## Approach

- Treat the **coder** (Codex, Cursor, or main-agent Claude) and the **Step 2b drafter** as the only dynamic-archetype producers on `/implement` and `/design`.
- Preserve the existing Step 5 consumer contract:
  - eligibility marker exists (`step2-external-scout-eligible.txt`)
  - `SCOUT_CODER_STATUS=ok`
  - `$IMPLEMENT_TMPDIR/scout-coder-manifest.json`
- **Valid empty manifests are success**: `{"archetypes":[]}` with `SCOUT_CODER_STATUS=ok` means static-only review, not producer failure.
- **Filtered-to-zero is not valid empty**: when raw input had one or more archetype entries but `filter-manifest --mode review` removes all of them (reserved slugs, static duplicates, etc.), treat as `missing-or-invalid`, not `ok`; do not write the eligibility marker; Step 5 must not forward as `pre-scouted-empty`.
- For invalid, absent, or malformed producer output on `/implement`:
  - write a canonical empty manifest
  - do not launch a separate scout on `/implement` or `/design`
  - run static reviewers only
  - print a bold stderr warning
  - append **at most one** persisted `Warnings` entry per run (owned by `dispatch_panel` after diff classification)
  - show a dedicated final-summary line
- **Warning ownership and timing**:
  - `normalize-coder-scout` writes manifest, status env, and eligibility marker only; it may print bold stderr but does **not** append `execution-issues.md` `Warnings`.
  - `review_and_fix` Step 5 preflight does **not** append producer-failure warnings.
  - `dispatch_panel` appends the single persisted producer-failure warning **after** diff classification, only when the round status is `producer-missing` or `producer-invalid`, never for `skipped-docs-only` / `skipped-test-only` / `skipped-generated-only`, `pre-scouted-empty`, or valid non-empty `pre-scouted` success.
  - Use a per-run sentinel (`$IMPLEMENT_TMPDIR/.producer-scout-warning-logged`) so duplicate append cannot occur.
- **Canonical pre-scouted empty status**: when `--pre-scouted-manifest` normalizes successfully under `--mode review` and archetype count is zero **because raw input was intentionally empty** (producer `SCOUT_CODER_STATUS=ok`), set `SCOUT_STATUS=pre-scouted-empty`; write the round manifest; skip `_synthesize_dynamic_slots`; do **not** set `parse-failed` or `pre_scouted_manifest_validation`. Document this token in `step2-dispatch.md`, `final_report.py`, and tests.
- **Implement normalization mode**: all implement-path manifest filtering must call `scout filter-manifest --mode review` (never default plan-review mode). Default plan-review mode applies `PLAN_RESERVED` and can strip valid code-review slugs (for example `arch`) before Step 5.
- **Producer input paths differ by producer**:
  - **External coders** (Codex/Cursor on `STATUS=complete`): `--input` is `DispatchState.launch_scout_manifest` (Codex: `$IMPLEMENT_TMPDIR/codex-step2-out/scout-coder-manifest.json`; Cursor: tmpdir-local launch path). Never hardcode `scout-coder-manifest.raw.json` for external normalization.
  - **Main agent** (`claude_fallback`, `--emergency`, explicit `--coder claude`): orchestrator writes raw JSON to `$IMPLEMENT_TMPDIR/scout-coder-manifest.raw.json`; normalize fence passes that path as `--input` with `--producer main-agent`.
- Keep `/review` standalone unchanged in behavior: it still uses the existing separate dynamic scout. Fix site defaulting so ambient `IMPLEMENT_TMPDIR` cannot suppress that scout.
- `_clear_external_scout_state` on `claude_fallback` must clear **all** coder scout artifacts so stale `SCOUT_CODER_STATUS=ok` cannot leak into `final_report`.

- External normalization must use tool-specific `launch_scout_manifest`; hardcoding `.raw.json` breaks Codex/Cursor complete paths.

## Failure modes

- Malformed JSON → canonical empty manifest, static-only, `producer-invalid` after classification.
- Wrong `filter-manifest` mode (plan-review default) → valid implement slugs stripped; prevented by always passing `--mode review` on implement paths.
- Raw non-empty manifest filtered to zero → `missing-or-invalid` at normalization; `producer-invalid` at Step 5; avoids silent downgrade to static-only success.
- Unconditional eligibility marker write → reserved-slug manifests appear eligible; prevented by marker write only on `ok`.
- Warning append failure → bold stderr still prints; run continues.
- Final-summary derivation cannot read status files → `Dynamic archetypes: unknown`.
- `SCOUT_CODER_STATUS=ok` without readable manifest/marker → summary reports `static-only, producer missing-or-invalid`.
- Generated implementer prompt drift → regenerate; existing generated-agent checks catch it.
- Unclosed Step 2.4 fence in SKILL.md → `make lint` / fence-shape harness failure; prevented by closing the fence immediately after the one-line command and keeping absent-input guidance as prose outside the fence.
- Step 2 anti-halt skipping normalize fence → separate Step 5 scout relaunch (#4954); prevented by main-agent carve-out before Step 3 breadcrumb.
