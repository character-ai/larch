Reviewing the branch diff and commit history for OOS pipeline integration risks.
### In-Scope Findings
- **risk-integration** `skills/shared/scripts/oos-serialize.sh:101-118` — The rewritten serializer only starts blocks on `^###[[:space:]]+FINDING_[0-9]+:`; it never splits or emits `### OOS_<n>:` headings that `tally-code-votes.sh` can write into `oos.md` for direct-OOS ballots. That was tolerable when `emit-tally.sh` always re-serialized from `oos.md`, but this branch adds a fail-closed desync-rebuild path (`emit-tally.sh:168-183`) that depends on `oos-serialize.sh` to repopulate `$REVIEW_TMPDIR/oos-accepted-review.md` whenever `OOS_ACCEPTED_COUNT > 0` and the sink block count disagrees. If the tally-normalized sink is empty or partial while `oos.md` holds only accepted `### OOS_N:` blocks, rebuild yields too few blocks and emit-tally exits 1, stalling review/ship instead of recovering. **Suggested fix:** Teach `oos-serialize.sh` to treat `^###[[:space:]]+OOS_[0-9]+:` as a block starter (with the same security/`Result=accepted` filters), or on the rebuild branch re-run tally’s normalization helper over `oos.md` instead of relying on serialize-only FINDING parsing.

- **risk-integration** `skills/review/scripts/emit-tally.sh:168-183` — The desync-rebuild branch can also not recover scope-drift accepted OOS: `tally-code-votes.sh` writes those into the accepted sink as normalized bare `### OOS_<seq>:` blocks, but leaves the source `oos.md` copy as an untagged `### FINDING_N:` block. `oos-serialize.sh` only marks a FINDING block as OOS when `[OUT_OF_SCOPE]`/`[OOS]` appears in the line (`oos-serialize.sh:107-108`), so rebuild from `oos.md` undercounts relative to `OOS_ACCEPTED_COUNT` and emit-tally exits 1. The happy path is protected by the preserve branch (`emit-tally.sh:161-167`), but any sink loss between tally and emit (crash, manual tmpdir edit, partial write) turns a previously silent overwrite into a hard stop with no serialize fallback. **Suggested fix:** Either include scope-drift blocks in `oos.md` with an explicit OOS tag for serialize fallback, or make the rebuild branch re-read the accepted sink from the parent mirror `$(dirname "$SESSION_ENV_PATH")/oos-accepted-review.md` before failing when `oos.md` cannot reproduce scope-drift blocks.

This predates #3550; the branch fixes tally→emit overwrite and header normalization but does not close the accumulated-vs-mirror split.

Pre-existing; not introduced by the normalization changes.
