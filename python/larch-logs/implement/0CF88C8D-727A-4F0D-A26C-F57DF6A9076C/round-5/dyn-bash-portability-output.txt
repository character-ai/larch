### In-Scope Findings
- **code-quality** `skills/shared/scripts/oos-serialize.sh:25-69` — The branch replaces a self-contained awk serializer with a bash loop that shells out to an inline Python security classifier on every OOS block. The prior implementation classified security purely in awk, so the serialize fallback path (`emit-tally.sh` when `OOS_ACCEPTED_COUNT == 0`) no longer runs on hosts where `python3` is missing or broken; `emit-tally.sh` now propagates that failure because it removed the old `|| true` guard on `oos-serialize.sh`. That is a portability regression for the standalone/legacy serialize path, not just an implementation detail. **Suggested fix:** Either restore an awk/BSD-safe security classifier for `oos-serialize.sh`, or source/reuse `scripts/lib-vote-tally.sh:is_security_block` and document `python3` as a hard prerequisite in `oos-serialize.md`; keep `emit-tally.sh` fail-closed only when the dependency is intentionally required.

- **code-quality** `skills/shared/scripts/oos-serialize.sh:41-68` — The duplicated Python classifier in `is_security_tagged_block` does not match the hardened contract in `scripts/lib-vote-tally.sh:64-71`: it calls `open(...)` without an `OSError` handler, so a read failure exits Python with status 1 instead of the library’s status 2. In `flush_block`, status 1 is treated as “not security,” so a transient I/O failure can serialize a security-tagged block into the public accepted-OOS sink. **Suggested fix:** Reuse `is_security_block` from `lib-vote-tally.sh` (or copy its `try`/`except OSError` → exit 2 path verbatim) and branch on `0/1/2` the same way `tally-code-votes.sh` and `review-and-fix.sh` already do.

- **code-quality** `skills/shared/scripts/oos-serialize.sh:72-90` — `flush_block` writes to `$OUTPUT_FILE` incrementally and calls `exit 2` on classifier failure instead of `return 2`. With `set -euo pipefail`, a mid-file failure after earlier accepted blocks leaves a partially written public sink; the new harness only covers total `python3` failure before any writes, not partial output after one or more successful flushes. **Suggested fix:** Write to a temp file under `$TMPDIR_OOS`, flush atomically to `$OUTPUT_FILE` only after the full input scan succeeds, and use `return 2` (with the caller deciding whether to exit) so failure modes stay localized and non-atomic output cannot leak.

### Out-of-Scope Observations
- **code-quality** `skills/shared/scripts/oos-serialize.sh:101-118` — Block detection still keys only on `^### FINDING_[0-9]+:`; direct `### OOS_N:` entries in `oos.md` are ignored on the rebuild path. That limitation predates this branch (the old awk serializer matched the same header shape); worth noting, but not introduced here.

- **code-quality** `skills/review-and-fix/scripts/review-and-fix.sh:1438-1443` — The skipped-findings loop calls `is_security_block` twice for non-security blocks (once in the `if`, again in the `else`). Behavior is correct because return `2` falls through to the abort path, but it doubles Python startup cost per skipped finding; this is inefficiency, not a Bash 3.2/BSD portability defect.

- **code-quality** `skills/review/scripts/tally-code-votes.sh:606-607` — Normalized blocks are written to `$REVIEW_TMPDIR/normalized-oos-${OOS_WRITE_SEQ}.md` and never deleted. Harmless for typical review rounds, but unrelated to the portability surface under review.
