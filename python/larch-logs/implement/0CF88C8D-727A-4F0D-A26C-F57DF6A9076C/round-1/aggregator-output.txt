### FINDING_1: Python and awk legacy OOS header matchers disagree
- **Reviewer(s)**: cursor-specialist-structure-output.txt, cursor-specialist-correctness-output.txt, cursor-specialist-testing-output.txt, cursor-specialist-edge-cases-output.txt, dyn-shell-portability-output.txt, dyn-counter-parity-output.txt
- **Severity**: important
- **Concern**: Bash/awk counts legacy `### FINDING_N:` headers with `[OUT_OF_SCOPE]` anywhere on the header line, while Python only counts when the tag appears immediately after the id. The same accepted-OOS artifact can therefore block in bash but pass in Python ship paths.
- **Suggested revisions (informational for voters; coder decides)**:
  - From cursor-specialist-structure-output.txt, cursor-specialist-correctness-output.txt, cursor-specialist-testing-output.txt, cursor-specialist-edge-cases-output.txt: Address the concern above.
  - From dyn-shell-portability-output.txt: Align Python with awk (e.g. match `^###\s+FINDING_\d+:` and require `[OUT_OF_SCOPE]` anywhere on that line, or share one test fixture with both counters and make the regexes identical), and add a regression case for a non-immediate tag placement.
  - From dyn-counter-parity-output.txt: Make Python mirror awk explicitly—e.g. treat a line as a legacy block start when it matches `^###\s+FINDING_\d+:` and contains the literal `[OUT_OF_SCOPE]` anywhere on that line (same for the file guard)—or narrow awk to the Python rule if that stricter shape is the only supported legacy format; add a paired fixture with the tag after title text and assert identical counts from both counters.
