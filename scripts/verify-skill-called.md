# scripts/verify-skill-called.sh — contract

Also documents the `git count-commits` Python CLI used by commit-delta mode and `scripts/test-verify-skill-called.sh` (regression harness).

`scripts/verify-skill-called.sh` is a generic mechanical post-invocation verifier for `Skill` tool calls (closes #160). Three mutually-exclusive modes: `--sentinel-file <path>` (file exists, is a regular file, and is non-empty), `--stdout-line <regex> --stdout-file <path>` (captured stdout contains a line matching the POSIX ERE, matched via `LC_ALL=C grep -E -q -- …` to pin locale and block option injection; empty regex rejected as an argument error; grep exit 2 is treated as an internal fault per the fail-closed contract), and `--commit-delta <expected> --before-count <N>` (commit count ahead of main increased by exactly the expected amount). Emits `VERIFIED=true|false` and `REASON=<token>` on stdout; exit 0 for pass/fail, exit 1 for argument errors and internal faults (fail-closed). Intended as a defense-in-depth gate for `Skill` calls whose child skills have no dedicated domain-specific verifier. Commit counting is implemented by `python3 "$PLUGIN_ROOT/python/cli.py" git count-commits`, using raw integer stdout plus the `ok` / `missing_main_ref` / `git_error` file-based side channel (`COUNT_COMMITS_STATUS_FILE`). The harness covers all three statuses through the CLI, wired into `make lint` via the `test-verify-skill-called` target.
