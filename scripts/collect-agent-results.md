# scripts/collect-agent-results.sh — contract

`scripts/collect-agent-results.sh` collects, validates, and optionally retries external reviewer outputs from `scripts/run-external-agent.sh`. It wraps `scripts/wait-for-reviewers.sh` for sentinel polling, validates each output (non-empty + retry on empty via `.meta` files), optionally invokes `scripts/validate-research-output.sh` on each `STATUS=OK` entry under `--substantive-validation` (Phase 3 of umbrella #413, closes #416), and emits structured `STATUS=OK|TIMED_OUT|FAILED|EMPTY_OUTPUT|SENTINEL_TIMEOUT|NOT_SUBSTANTIVE` results plus per-tool health monotonicity. Used by `/research` (Step 1.4 + Step 2.4 — `skills/research/references/research-phase.md` + `validation-phase.md`), `/review`, `/design` Step 2a.3 + Step 3 + Step 2a.5 dialectic + judge phases, and `/implement` Step 5 quick-mode reviewer collection. Runs `set -uo pipefail` but deliberately **omits `set -e`** so non-zero exits from reviewer subprocesses and the validator are informational rather than aborting. The script sources `scripts/external-tool-registry.sh` fail-closed via the `LARCH_EXTERNAL_TOOL_REGISTRY_LOADED` sentinel before deriving tool names. Tool derivation prefers `<output>.meta`'s `TOOL=` key when it exactly matches a registered `LARCH_EXTERNAL_TOOLS` entry, then falls back to filename inference by scanning the basename for registered tool tokens; `unknown` remains the intentional observational classification for partial or malformed launches whose metadata and basename do not identify a registered tool. Wait stdout is correlated by the indexed grammar from `scripts/wait-for-reviewers.sh`: `OUTPUT_FILES[$i]` maps to wait record index `i+1`, and basenames are informational only. Retry preserves both capture modes (`--capture-stdout` and `--capture-stdout-only`) from metadata. Retry metadata normally uses `CMD_JSON=`: the collector validates a top-level non-empty JSON array whose every element is a string, deserializes through base64 records into a Bash array, asserts decoded length, swaps only standalone argv elements equal to `OUTPUT_FILE`, and launches retry via direct array expansion. For Cursor review outputs whose `.meta` includes any `OUTER_LAUNCHER*` key, the collector validates `TIMEOUT=` first and then branches to the outer-launcher retry path before inspecting `CMD_JSON`; this ordering is load-bearing because Cursor's post-processing lives in `scripts/launch-cursor-review.sh`, not in the inner `cursor agent` command captured by `CMD_JSON`. The outer branch requires all three keys together, canonicalizes `OUTER_LAUNCHER` to exactly `scripts/launch-cursor-review.sh`, rejects `..` in the launcher, prompt-file, and workdir fields, pins `OUTER_LAUNCHER_PROMPT_FILE` to `${ORIG_OUTPUT}.prompt` as a readable regular non-symlink file, validates `OUTER_LAUNCHER_WORKDIR` as an existing directory, then spawns the launcher from that workdir with `--prompt-file`. A sidecar carrying valid `OUTER_LAUNCHER*` metadata does not fall back to `CMD_JSON`, even if `CMD_JSON` is present and well-formed; replay is byte-stable from the prompt sidecar rather than re-rendering specialist prompts. Missing or malformed `CMD_JSON`, missing or malformed `TIMEOUT`, decode length mismatch, post-decode empty arrays, or malformed outer-launcher metadata fail closed immediately by rewriting the original result to `STATUS=EMPTY_OUTPUT|HEALTHY=false` and calling `set_tool_unhealthy`. Missing `TIMEOUT=` no longer defaults to 120s; it is invalid retry metadata under the D2 resolution for #1219. The standalone-output-path invariant is shared with `scripts/run-external-agent.md`: callers that need retry retargeting pass output paths as standalone argv elements (`--output X`), not embedded (`--output=X`) and not only inside prompt text. **Bash 3.2 portability invariant at the validator call site:** when a caller passes `--substantive-validation` without `--validation-mode` (e.g., `/research` Step 1.4), `VAL_ARGS=()` is empty; on bash 3.2 (macOS default `/bin/bash`) the bare `"${VAL_ARGS[@]}"` expansion under `set -u` raises `unbound variable` and silently misclassifies every reviewer file as `STATUS=NOT_SUBSTANTIVE`. The validator invocation MUST therefore use the `"${VAL_ARGS[@]+"${VAL_ARGS[@]}"}"` idiom (precedented at `scripts/create-pr.sh:105` — `${GH_DRAFT_ARGS[@]+"${GH_DRAFT_ARGS[@]}"}`); a one-line WHY-comment at the call site documents the rationale so future readers do not "simplify" it back. Issue #511 was a regression of this invariant; `scripts/test-collect-agent-bash32.sh` (wired into `make lint` via `test-harnesses`) is the regression harness — Case 1 statically pins the idiom by regex near the validator call (Linux-CI backstop on every PR; bash 4.4+ does not exhibit the runtime hazard), Cases 2/3 exercise the actual collector under any `/bin/bash` whose version is `< 4.4` (bash 3.x or bash 4.0-4.3 — both still vulnerable; bash 4.4 was the fix release), and Case 4 proves duplicate output basenames are correlated by wait index rather than basename. Edits to the substantive-validation loop MUST keep the safe-expansion idiom at the validator call site; if the call-site shape changes, update the harness's Case 1 regex AND this contract together. The retry deserialization block uses a `while IFS= read -r ... <<< "$_b64_stream"` here-string loop because `mapfile` is Bash 4+ and unavailable on macOS `/bin/bash` 3.2, `done < <(...)` redirection-from-process-substitution has a similar 3.2 portability hazard in this loop shape, and `jq -r '.[]'` would corrupt argv elements containing embedded newlines. `scripts/test-collect-agent-retry.sh` covers valid replay, malformed JSON, stale `CMD=`, malformed/missing `TIMEOUT`, non-string arrays, newline-bearing argv, substring-preserving path swaps, outer-launcher retry and fail-closed gates, and the vulnerable-system-bash runtime path when available. The script's per-tool health is monotonic (any failure permanently flips a tool to unhealthy for the rest of the session — a later success does NOT flip it back); `--write-health <path>` reads prior state and merges monotonically when the file already exists, including `GEMINI_HEALTHY`. The health helper state and `--write-health` envelope intentionally remain explicit `CODEX_HEALTHY`, `CURSOR_HEALTHY`, and `GEMINI_HEALTHY` variables; extending those fields for a future registry entry requires a separate health-envelope change.

The `.meta` parser is intentionally line-oriented: each record is split on the first `=` and no escaping layer is applied while reading. On duplicate keys (`TIMEOUT=`, `CMD_JSON=`, etc.), the last assignment wins. This matches the existing parser convention; sidecars with internal contradictions are accepted as long as the final value satisfies validation. Keep this parser in sync with the writer-side `.meta sidecar grammar` contract in `scripts/run-external-agent.md`, which documents the per-field guarantees for `TOOL`, `TIMEOUT`, capture booleans, `OUTPUT_FILE`, and `CMD_JSON`.

Wait usage errors (for example, invalid `--timeout` from the caller) and other wait fatals (for example, `mktemp` failure in `scripts/wait-for-reviewers.sh`) on the **initial** `wait-for-reviewers.sh` invocation surface as collector exit 1 with the wait script's stderr message followed by a `collect-agent-results.sh: wait-for-reviewers.sh exited <N>` trailer line, rather than being silently masked into `SENTINEL_TIMEOUT` / `EMPTY_OUTPUT` reviewer records (closes #1188 / umbrella #1200). The **empty-output retry-phase** wait (later in the same script) deliberately keeps `>/dev/null 2>&1 || true` because retry outcomes are re-checked from sentinel state downstream; tightening that path could surface transient `mktemp` / IO failures as fatal collector exits in cases where the retry result still has a usable sentinel. On the initial-wait success path, wait's stderr (per-poll dot progress and per-minute status lines) is captured to a temp file under `${TMPDIR:-/tmp}` and removed via an `EXIT` trap (covering signal-driven exits as well as success and explicit-failure branches), preserving today's quiet-success orchestrator UX. Argument-presence validation for `--timeout` is owned by the collector itself (parameter-expansion `:?` at the option-parsing case arms in `scripts/collect-agent-results.sh` — readers should rely on the `case "$1" in --timeout) ... ;; --write-health) ... ;;` block rather than fixed line numbers); argument-value validation (positive-integer plus `10#` floor) is owned by wait. The collector treats wait's value-validation as authoritative rather than swallowing it. The regression harness `scripts/test-wait-for-reviewers.sh` pins both the wait-side rejection contract (R1-R8) and the collector-side passthrough (C1/C2).

**Retry-failure `EXIT_CODE` propagation (#1290).** On retry failure, the collector propagates the retry `.done` sentinel value as `EXIT_CODE=<RETRY_EXIT>` rather than masking non-zero exits as `EXIT_CODE=0`. All collector-side fail-closed rows that do not have a child-process sentinel value to propagate (pre-launch retry-metadata invalid and post-launch missing retry sentinel) emit `EXIT_CODE=99` for consistency. The retry success branch (`.done` is `0` AND retry output non-empty) continues to emit `STATUS=OK|EXIT_CODE=0`. Note: `EXIT_CODE=0` can still appear on a retry **failure** row when the sentinel is `0` but the retry output stayed empty (`STATUS=EMPTY_OUTPUT`); `EXIT_CODE=0` alone is therefore not a success signal — `STATUS=OK` (and an empty `FAILURE_REASON`) is. Both initial and retry sentinel read sites pass the sentinel bytes (after the `cat` command-substitution trailing-newline trim) through `normalize_exit_code_or_99`, which accepts only `^[0-9]{1,3}$` digit strings in the `0..255` range; invalid bytes stderr-log and force `99`. The length bound is load-bearing because Bash arithmetic is fixed-width and can otherwise accept oversized digit strings after overflow, so the guard also protects the pipe-delimited `RESULTS` invariant from newlines, `|`, control bytes, and oversized values in `.done` content. The companion `exit_code_was_coerced` returns `true|false` for a given raw sentinel; the initial-sentinel call site uses it to detect coercion (since `normalize_exit_code_or_99` runs in a `$(...)` subshell, any global it sets cannot propagate back). When coercion fired AND the output file is empty, the initial-sentinel branch routes to the retry path rather than to `STATUS=FAILED` — a corrupt or partially-written `.done` should not deny the one-shot empty-output recovery the retry path was designed for. Real (non-coerced) non-zero exits with empty output still route to `STATUS=FAILED` because the wrapper genuinely reported a failure. `build_missing_retry_sentinel_result` is the single source of truth for the missing-retry-sentinel result block and is exercised directly by `scripts/test-collect-agent-retry.sh` Case K; no executable-path override or other production retry seam is shipped.

**Empty-output retry deserializer prerequisites.** The inner `CMD_JSON` retry path requires `jq` (CMD_JSON validate + per-element decode via `jq -r '.[] | @base64'`) and `base64 -d` (the `-d` flag is portable across GNU coreutils, BSD/macOS, and BusyBox; `--decode` is rejected by BusyBox). The outer-launcher Cursor branch does not deserialize `CMD_JSON`, but it still requires `TIMEOUT=` and valid `OUTER_LAUNCHER*` path metadata before launch. `jq` is a hard repo prerequisite documented at the wrapper contract in `scripts/run-external-agent.md`; it is repeated here because the collector consumes that contract on a different code path. If either binary is unavailable at retry time, the inner retry path fails closed for that index — `mark_retry_metadata_invalid` flips the original result to `STATUS=EMPTY_OUTPUT|HEALTHY=false` and `set_tool_unhealthy` runs. Missing, non-digit, or zero/zero-padded `TIMEOUT=` also fails closed for that reviewer before any retry arithmetic or launch. The retry-phase wait timeout starts with a 30s safety floor and then rises to the maximum queued `TIMEOUT+60`, so short reviewers do not inherit a fixed 180s wait while long reviewers keep their full grace window. Other indices in the same collector invocation that have valid metadata still launch retries; the per-`j` `RETRY_LAUNCHED` array preserves their fail-closed `FAILURE_REASON` strings against the post-wait result-update loop, and a `_decode_failed` flag in the deserializer skips the empty-array branch so a base64-decode failure surfaces as `Retry metadata invalid: CMD_JSON decode failed` rather than the misleading `empty CMD_JSON array after decode`. Distinct missing-key messages — `missing CMD_JSON and TOOL`, `missing CMD_JSON`, `missing TOOL`, `TIMEOUT missing`, and the `OUTER_LAUNCHER*` field-specific messages — narrow each `FAILURE_REASON` to the field actually absent or invalid.
