# scripts/local-cleanup.sh — contract

`scripts/local-cleanup.sh` is the post-merge local-tidy-up step invoked by `/implement` Step 14 and `/release` Step 8: switch to `main`, fetch latest, fast-forward local `main` from `origin/main`, then delete the feature or release branch named via `--branch`. Treats branch deletion failure as non-fatal (the branch may already be gone, e.g. if the operator manually deleted it). Refuses to run with `--branch main` for safety. Outputs `CLEANUP_SUCCESS=true|false`, `CURRENT_BRANCH=<name>`, `BRANCH_DELETED=true|false` so callers can report partial-success warnings without interrupting their post-merge flow.

After fetching and before pulling, the script checks whether local `main` is ahead of `origin/main` only by prior larch-log flush commits. The cleanup is deliberately narrow: every ahead commit subject must begin with the `chore(larch-logs): flush` prefix and the aggregate diff must stay under `larch-logs/`. The diff for that second predicate is evaluated against the pre-fetch `origin/main` tip (captured immediately before `git fetch origin main`) so a just-landed squash-merge cannot contaminate the check with the PR's code files on the updated remote. When both predicates pass, the script warns on stderr and resets local `main` to `origin/main` so stale prior-run flush commits do not block the pull. Non-flush ahead work is left untouched.

The pull is always `git pull --ff-only origin main`: cleanup may advance local `main` to a newer remote tip, but it never creates a merge commit or reconciles divergence. When the fast-forward pull fails, the local tree may be on `main` without the just-merged remote release/feature commit, and the branch named by `--branch` is intentionally preserved. Callers must warn operators to manually reconcile local `main` with `origin/main` before relying on the local tree, then delete the preserved branch after reconciliation. When local `main` is ahead of `origin/main`, stderr also reports the ahead count and tells the operator to push or reconcile local `main` before retrying; the stdout failure envelope and exit-zero behavior are unchanged.

Usage and safety errors, including missing `--branch` or `--branch main`, exit 1 before the output trap is installed and emit no stdout keys. After argument validation succeeds, the EXIT trap always emits the three keys on exit 0, including partial-failure cases such as checkout, fetch, fast-forward pull, or branch-delete failures.
