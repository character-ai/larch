# scripts/lint-literal-counts.py - contract

`scripts/lint-literal-counts.py` is a repo-wide markdown policy lint (closes #1245) that flags drift-prone literal item-count lines matching the single module constant regex `^\s*\d+\s+(assertions|rules|bullets|rows|reviewers|agents|specialists|cases|fields|sections)\b`; the regex uses `re.ASCII`, so `\d` means ASCII digits only. The numeric span is intentionally unbounded, so year-prefix lines such as `2024 sections ...` are an accepted false-positive class and should be allow-listed inline if they appear. The only allow-list form is the same-line pragma `<!-- lint-literal-counts: allow <reason> -->`: the reason is required, the `allow` token is case-sensitive lowercase, and the HTML-comment body constraint means reasons cannot contain `--` or `-->`. Pragma scope is same-line only, and the leading-position regex means at most one violation can be matched per line. Leading horizontal whitespace is in scope, so indented summaries that begin with counts are checked. Lines inside fenced code blocks are exempt with a length-aware state machine: the opener length is recorded, and the closer must have the same indentation and `len(closer) >= len(opener)`, so nested 3-tick fences inside a 4-tick wrapper remain exempt; `skills/implement/references/anchor-comment-template.md:35-129` is the canonical nested-fence example. Files are read as UTF-8 with UTF-8 BOM stripped and CRLF normalized to LF. Exit codes are `0` clean, `1` violations, and `2` internal errors; exit 2 takes priority when internal errors and violations occur together. Messages use `lint-literal-counts: <repo-relative-path>:<1-based-line-number>:`; "absolute" line references mean the 1-based line index inside the file, never a filesystem-absolute path. Glob scope is `git ls-files --cached --others --exclude-standard -z -- '*.md'` when `--root` is a git worktree, so both tracked and untracked-non-ignored markdown is scanned (gitignored trees such as `.agents/` are still skipped); the `--others --exclude-standard` flags are load-bearing because the hook runs with `pass_filenames: false` + `always_run: true`, so a freshly-added untracked `.md` would otherwise slip past the lint until it was staged. Otherwise (non-git worktree, e.g. mktemp harness fixtures), the fallback walks `*.md` with `os.walk(root, followlinks=False)` while excluding `.git/`, `node_modules/`, `.venv/`, and `.agents/` defensively, and the final list is sorted so order does not depend on filesystem walk semantics. Symlinks are never followed. `--root` is a contract token for harness isolation, and argparse accepts only `--root`, rejecting positional arguments; this is load-bearing under the pre-commit `pass_filenames: false` contract. The lint is registered as local pre-commit hook id `lint-literal-counts` with `language: python`, `pass_filenames: false`, `always_run: true`, and no third-party dependencies. `scripts/test-lint-literal-counts.sh` is the regression harness, wired through Makefile target `test-lint-literal-counts` in shard 2; `agent-lint.toml` excludes only `scripts/test-lint-literal-counts.sh`, mirroring the `test-lint-skill-invocations.sh` precedent. `scripts/test-references-headers.md` is orthogonal: it guards the narrow `references/*.md` Contract header shape, while this lint guards repo-wide prose drift.
