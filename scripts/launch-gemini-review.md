# launch-gemini-review.sh

**Purpose**: Launch Gemini as a generic-only code reviewer and normalize the Gemini CLI JSON envelope into the plain-text reviewer output consumed by `collect-agent-results.sh`.

**Invocation**: `gemini -m "$GEMINI_MODEL" -p "$PROMPT" -o json --skip-trust --approval-mode yolo`, where `$GEMINI_MODEL` is resolved by `scripts/lib-gemini-model-resolver.sh` using set-aware precedence: `LARCH_GEMINI_MODEL`, then `CLAUDE_PLUGIN_OPTION_GEMINI_MODEL`, then `gemini-2.5-pro`. Blank, whitespace-only, and POSIX `[[:cntrl:]]` values fail closed through the standard `fail_closed 2` sidecar envelope; internal spaces are allowed. The same resolver is applied by `scripts/check-reviewers.sh` for the Gemini health probe so probe and reviewer use the same model. The probe deliberately stays at `--approval-mode plan` (least privilege) — it sends a fixed `"Respond with OK"` prompt and never invokes a tool. Reviewer launches append `--admin-policy "$SCRIPT_DIR/gemini-reviewer-policy.toml"` to load the plugin-shipped reviewer write-deny policy.

## Invariants

- Generic-only v1: accepts `--output`, `--timeout`, and `--prompt`; rejects specialist flags.
- `--timeout` must be a positive integer; `0`, empty, non-digit strings, and zero-valued multi-digit strings (`00`, `000`, ...) are rejected at argv-validation time with exit 2 (parallel to `scripts/run-external-agent.sh` and the `launch-*-implement.sh` family — closes #1115, #1167). Valid leading-zero positive values like `010` are accepted and interpreted as base-10 (`010` → 10s).
- Timeout is clamped to 600 seconds before launching Gemini.
- Uses `run-external-agent.sh --capture-stdout-only` so Gemini stdout JSON is written to `<output>.raw` while stderr remains diagnostic-only.
- Requires `jq`; missing `jq` fails closed with `MISSING_JQ`, empty output, non-zero `.done`, and a diagnostic.
- Parses `.response` as the only successful output field. `.error`, missing `.response`, or empty `.response` fail closed.
- Writes normalized plain text to `--output` atomically, then writes `<output>.done` last.
- Process exit code matches `.done` for the exit codes used by this launcher: 0 on success, 1 on Gemini `.error` / missing or empty `.response` / snapshot-guard-triggered revert / `UNRECOVERABLE_DELTA`, 99 on snapshot-guard infrastructure failure (cannot capture pre or post snapshot), 127 on missing `jq`, plus the upstream `run-external-agent.sh` exit on transport failures. On any non-zero `.done`, `$OUTPUT` is empty — `fail_closed` and the post-success snapshot-guard branch both call `write_empty_output` before persisting the failure, so consumers MAY treat `.done != 0` as authoritative even without re-reading `$OUTPUT`. These codes are within POSIX's portable 0-255 range.
- Writes `<output>.meta` with `TOOL=gemini` and `CMD_JSON=` pointing at the redacted launcher invocation, so retry paths replay JSON normalization rather than raw `gemini`. Only the on-disk encoding changed: the retry replay model remains "launcher argv with the prompt body replaced by a sha256 prefix + byte length."
- Loads `scripts/gemini-reviewer-policy.toml` via `--admin-policy` so an admin-tier priority 5999 rule denies `write_file`, `replace`, `edit`, `edit_file`, and `delete_file` in reviewer mode while `--approval-mode yolo` continues to allow shell. This is an off-label reliance on gemini-cli honoring `--admin-policy` from arbitrary file paths, and the guarantee depends on gemini-cli keeping these write-tool names stable.
- Prepends a fixed hardening preamble to the caller-provided prompt before passing it to Gemini. The preamble explicitly bans shell writes, file-writing tools, and git/index/ref mutation; call sites still keep the shared `Do NOT modify files. Do NOT commit. Do NOT push.` language for parity with Cursor and Codex reviewer prompts.
- Before launching, removes stale `${OUTPUT}.dirty-tree` / `${OUTPUT}.untracked-baseline` sidecars and captures a NUL-delimited untracked baseline via `scripts/snapshot-untracked.sh`. On exit, writes `${OUTPUT}.dirty-tree` via `check-mid-run-dirty-tree.sh --mode baseline` so `/review` Step 5 sidecar consultation has Cursor/Codex-equivalent coverage when Gemini reviewer call sites are reintroduced (issue #1487; matches the contract introduced for Cursor/Codex by #1437). The dirty-tree sidecar emission is independent of the repo-root snapshot guard below — both run, and they cover overlapping but not identical surfaces (the snapshot guard captures and reverts tracked-file content + index state under the repo root; the dirty-tree sidecar reports on the untracked-file delta against the pre-launch baseline).
- On the early-short-circuit fail_closed paths (`MISSING_JQ`, model-resolve failure, snapshot-guard setup failure), no agent ran, so the launcher writes `${OUTPUT}.dirty-tree` with `STATUS=unknown`, `MODE=baseline`, `UNTRACKED_BASELINE=present|missing`, and `REASON=fail-closed-no-agent-ran`. The EXIT trap (`_publish_dirty_tree_on_exit`) emits the same `STATUS=unknown` / `MODE=baseline` shape with `REASON=exit-trap-no-agent-ran` for asynchronous exits (SIGINT / SIGTERM, or any `set -e` propagation) that leave the launcher before `AGENT_RAN=true`. STATUS=unknown routes consumers through the same recovery-safe path as a real detector failure rather than letting them treat a present sidecar with STATUS=clean as "launcher proved the tree clean." Pre-launch tracked or staged dirt could otherwise be silently masked under a false STATUS=clean. Consumers should branch on `STATUS=unknown` rather than the specific `REASON=` token.
- Snapshot guard captures the current `HEAD` SHA, sha256 records for tracked and untracked files, and the index-vs-`HEAD` diff name set under the current git repo root after stale launcher artifacts are removed and before Gemini launches. It captures again after JSON normalization, excluding the launcher's own `$OUTPUT*` / `$RAW_OUTPUT*` artifacts, and treats any delta as a reviewer mutation. Index-state capture closes the case where a reviewer runs `git add` against an already-modified tracked file — the on-disk content hash is unchanged but the index has new entries vs `HEAD`, and the `I\t-\t<path>` records make that delta visible to the comparison.
- Snapshot temp resources (`SNAPSHOT_PRE`, `SNAPSHOT_POST`, `SNAPSHOT_BACKUP` under `${IMPLEMENT_TMPDIR:-${TMPDIR:-/tmp}}`) are removed by an `EXIT` trap registered after `mktemp` in `setup_snapshot_guard`. The trap is idempotent and tolerates partial state — a setup-stage capture failure still unlinks the temp files. Operators inspecting failed runs should preserve the `${OUTPUT}.diag` content and the `${IMPLEMENT_TMPDIR:-${TMPDIR:-/tmp}}` parent before re-running.
- The EXIT trap is composed with one best-effort `timing-ledger.sh record-vendor-task` emission. `TIMING_START_S` is captured after argv validation and before snapshot guard / `run-external-agent.sh`; `--timing-task-kind <kind>` defaults to `gemini-review`. Timing failures are silent and never affect stdout, `.done`, or launcher exit behavior. **Validation**: when `--timing-task-kind` is supplied via the CLI, the value must be non-empty and must not begin with `--`; otherwise the launcher exits 2 with `--timing-task-kind requires a non-empty, non-flag-like value` on stderr (issue #1480 defense-in-depth against argv-shape collapse from a broken env-var-prefix expansion in the caller).
- Before spawning Gemini, the wrapper rehydrates token context from `IMPLEMENT_TMPDIR` when present: `$IMPLEMENT_TMPDIR/session-id` overwrites any stale `LARCH_TOKEN_SESSION_ID`, and `$IMPLEMENT_TMPDIR/claude-source.env` becomes `LARCH_CLAUDE_SOURCE_FILE`. Gemini review does not record vendor tokens today; this keeps parity with Codex and Cursor launchers.
- On a snapshot delta, the guard restores modified tracked files, deleted tracked files, and new untracked files to their pre-launch state where possible, writes `SNAPSHOT_GUARD_TRIGGERED:` with the repo-relative path list to `<output>.diag`, writes non-zero `.done`, and exits 1. If the guard cannot capture or restore consistently, it writes `SNAPSHOT_GUARD_FAILED:` or `UNRECOVERABLE_DELTA:` and exits non-zero.
- The guard is fail-open when the launcher is not run from inside a git working tree or the repo has no `HEAD`; it writes `snapshot guard skipped: not inside a git working tree` to `<output>.diag` and relies only on the Gemini policy file in that mode.
- Snapshot generation is bounded by `LARCH_GEMINI_SNAPSHOT_TIMEOUT` seconds, default `30`. The value must be a positive base-10 integer; non-digit, empty, and non-positive values (`0`, `00`, `000`, ...) silently fall back to the default. Leading-zero values like `010` are interpreted as `10` seconds, not octal `8`. There is no "disable timeout" sentinel — a non-positive override is treated as misconfiguration and replaced with the default rather than disabling the cap. On timeout, the guard writes `SNAPSHOT_GUARD_TIMEOUT:` to `<output>.diag`, skips comparison for that run, and falls through to the existing policy-only behavior.
- On the missing-`jq` fail-closed path, `write_meta()` deliberately omits `CMD_JSON` instead of failing before `write_done()`. The collector treats missing `CMD_JSON` as invalid retry metadata, skips retry, and marks the result/tool unhealthy.
- Rejects empty `--output` values and paths containing bytes outside `[A-Za-z0-9._/-]` before stale-file cleanup or raw wrapper launch. The same byte string is used on disk, in `OUTPUT_FILE=`, and as a standalone argv element in `CMD_JSON` that collector retry substitution rewrites, so unsafe paths fail fast instead of being transformed.
- Rejects Gemini model values that are blank, whitespace-only, or contain POSIX `[[:cntrl:]]` bytes before the raw wrapper launch; the rejection writes empty output, `.done=2`, `.diag` with the resolver diagnostic, and `.meta`.
- Output filenames must carry a `gemini-` prefix when consumed by `collect-agent-results.sh` unless `.meta` is guaranteed present.

## Policy contract

`scripts/gemini-reviewer-policy.toml` lives beside this launcher and is passed as an absolute path derived from `SCRIPT_DIR`. Its single `[[rule]]` denies the five known Gemini file-writing tool names at admin priority 5999, which overrides `--approval-mode yolo`'s default-allow posture while leaving read tools and shell available for live-repo review. The policy is intentionally reviewer-only; `scripts/launch-gemini-implement.sh` keeps yolo with write tools for the implementer slot.

The policy contract is narrower than a general sandbox. If gemini-cli removes arbitrary-path support for `--admin-policy`, the launcher should fail closed on Gemini argv parsing. If gemini-cli renames write tools or adds a new write-capable tool outside the deny list, the policy can silently stop covering that write surface until the deny list is updated. The snapshot guard is the load-bearing backstop for write surfaces the toolName-filtered policy cannot cover, including shell redirects, `tee`, mutating shell commands, and future renamed write tools.

## Prompt contract

Gemini runs with live repository access, matching the Cursor and Codex reviewer posture. Callers pass the same review prompt shape used for those reviewers: ask Gemini to run `git diff main...HEAD`, `git log main...HEAD --oneline`, and read changed files for context in diff mode, or read the description-mode scope file before inspecting files. Reviewer prompts must explicitly say: `Do NOT modify files. Do NOT commit. Do NOT push.` The launcher prepends the stronger anti-shell-write preamble at runtime so the detailed Gemini-specific hardening language has one source of truth.

## Test harness

`scripts/test-launch-gemini-review.sh` stubs `gemini` and exercises the real `run-external-agent.sh` path to cover timeout clamping, JSON normalization, fail-closed `.error`, `MISSING_JQ`, launcher-specific `--output` rejection before side effects, Gemini model rejection through the sidecar envelope, `CMD_JSON` sidecar emission, `--timeout 0` rejection at argv-validation time, prompt-hardening preamble injection, snapshot detection/revert for new untracked files, snapshot detection/revert for modified and deleted tracked files, and the non-git fail-open diagnostic.
