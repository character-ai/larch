# lib-cursor-launcher-common.sh

Sourced-only helper for the shared Cursor launcher mechanics in `scripts/launch-review.sh --tool cursor`, `scripts/launch-cursor-ci.sh`, and `scripts/launch-cursor-implement.sh`; the primary launcher contracts remain in those sibling docs. Exposes `cursor_launcher_load_model_args` (hydrates fixed global `MODEL_ARGS` from `scripts/agent-model-args.sh --tool cursor --with-effort`), `cursor_launcher_setup_auth_argv` (sources `scripts/lib-cursor-auth.sh`, returns `cursor_auth_preflight`'s status, pre-reads the macOS `cursor-access-token` service into `CURSOR_API_KEY` when possible, and hydrates fixed global `CURSOR_AUTH_ARGS` on success), `cursor_launcher_append_outer_meta`, `cursor_launcher_promote_inner_done`, `cursor_launcher_setup_private_config_dir`, `cursor_launcher_cleanup_private_config_dir`, and `cursor_launcher_run_stall_monitor` (used by `launch-cursor-ci.sh` only today: polls while a `run-external-agent.sh` PID is alive; `stdout` / `file:<path>` / `tree:<root>` channel modes; the `stdout` channel advances the last-progress timestamp only on capture-file byte-size changes — a missing file or steady zero-byte size does not refresh it; Bash 3.2-safe; on stall appends diagnostics — `ps` for the wrapper and its direct children without argv columns — then SIGTERM/SIGKILLs inner child PIDs first when `pgrep -P` is available, then the wrapper PID). When `IMPLEMENT_TMPDIR` resolves to a run-log `round-*` directory (or `jq` is unavailable), the monitor may also write `cursor-ci-stall-*.json` sidecars; see `scripts/launch-cursor-ci.md`. The `CURSOR_CONFIG_DIR` helpers handle per-invocation isolation (issue #2022): `setup` creates a fresh `mktemp -d` directory, seeds it from `~/.cursor/cli-config.json` when present, and exports `CURSOR_CONFIG_DIR`; `cleanup` removes the directory and unsets the variables. Call `setup` immediately before the auth-retry loop and `cleanup` immediately after the loop (or in the EXIT trap). The `cursor_launcher_append_outer_meta` and `cursor_launcher_promote_inner_done` functions are thin wrappers; their canonical bodies live in `scripts/lib-external-launcher-common.sh` (issue #1502 dedup), which this file sources. Keep this stub in sync with `.claude/rules/script-md-siblings.md` and the primary contracts when shared Cursor launcher behavior changes.
