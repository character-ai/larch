# scripts/test-collect-agent-bash32.sh — contract

`scripts/test-collect-agent-bash32.sh` is the regression harness for the bash 3.2 portability hazard at the validator call site in `scripts/collect-agent-results.sh` (issue #511) plus always-on collector wait-correlation and validator-status fixtures. Cases: (1) static grep that pins the safe-expansion idiom `"${VAL_ARGS[@]+"${VAL_ARGS[@]}"}"` at the validator call site — runs on every bash version and is the Linux-CI regression backstop because bash 4.4+ no longer exhibits the empty-array nounset hazard at runtime; (2) dynamic empty-`VAL_ARGS` exercise of the actual collector under `/bin/bash` 3.x (≥200-word substantive fixture, pre-created `.done` sentinel containing `0`, basename containing `cursor` so `derive_tool` attributes correctly) asserting `STATUS=OK` AND clean stderr — skip-with-loud-message on bash 4+; (3) dynamic `--validation-mode` forwarding pin under `/bin/bash` 3.x using a literal `NO_ISSUES_FOUND` fixture with both a positive assertion (`--validation-mode` present → `STATUS=OK`) and a negative control (`--validation-mode` absent → `STATUS=NOT_SUBSTANTIVE`) — skip-with-loud-message on bash 4+; (4) duplicate-basename collector regression — two output files named `same.txt` under different directories, only the first with a `.done` sentinel, asserting argv-index correlation leaves the first `STATUS=OK` and the second `STATUS=SENTINEL_TIMEOUT`; (5) `CURSOR_EMPTY_RESPONSE` mapping from validator exit 5; (6) empty `.diag` fallback — a failed reviewer with a zero-byte diagnostic sidecar still reports the status-derived `FAILURE_REASON` instead of an empty reason. Wired into `make lint` via the `test-collect-agent-bash32` target and the `test-harnesses` aggregator. The test script is added to `agent-lint.toml`'s exclude array because it is a Makefile-only harness (referenced only from `Makefile`, not from any SKILL.md or other runtime path) — same shape as `scripts/test-validate-research-output.sh`. Edits to the substantive-validation block MUST keep the safe-expansion idiom at the validator call site or Case 1 will fail; if the call-site shape changes (e.g., introducing a helper function or splitting the loop), update the Case 1 grep regex AND the `scripts/collect-agent-results.md` invariant in the same PR. Edits to wait stdout grammar or collector timeout correlation must keep Case 4 and `scripts/wait-for-reviewers.md` aligned.
