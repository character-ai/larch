# launch-cursor-ci.sh

Launches Cursor for `/implement` CI-related subwork from `scripts/ship-pr.sh`.

## Interface

```text
launch-cursor-ci.sh --role fix|resolve-conflict|bump-classify|changelog-draft --output PATH --run-id ID --repo OWNER/REPO [--plan-file PATH] [--conflict-files CSV] [--failure-log PATH] [--timeout SECONDS]
```

`--output` must be an absolute path using the same narrowed safe alphabet as `run-external-agent.sh`.
`--plan-file`, when present, must be an absolute path; if the file exists, its content is inserted into the vendor prompt as design-plan context.
`--conflict-files`, when present with `--role resolve-conflict`, must be a comma-separated list of repo-relative paths (no `..` segments, no absolute paths, each segment must match `^[A-Za-z0-9._/-]+$`); the launcher validates the CSV then injects it into the vendor prompt inside `<<<CONFLICT_PATHS>>>` / `<<<END_CONFLICT_PATHS>>>` delimiters.
`--failure-log`, when present, must be an absolute path to an **existing** regular file under `$IMPLEMENT_TMPDIR` (the environment variable must be set). A capped, `redact-secrets.sh`-filtered excerpt is injected into the prompt inside `<<<FAILURE_LOG_EXCERPT>>>` / `<<<END_FAILURE_LOG>>>` delimiters. The `fix` role prompt also carries the **local reproduction invariant** (re-run the same failing commands or harness after fixing).

## Behavior

The launcher builds a fixed prompt containing only trusted path and identifier values, wraps it through `cursor-wrap-prompt.sh`, and runs Cursor through `run-external-agent.sh --capture-stdout-only`. It writes retry metadata via `lib-cursor-launcher-common.sh`, emits timing with `--timing-task-kind cursor-ci-fix`, and writes a best-effort `${OUTPUT}.token-record` sidecar from Cursor JSON usage. Cursor auth setup is shared with `launch-review.sh --tool cursor`: after the Darwin preflight, the helper best-effort pre-reads the `cursor-user` / `cursor-access-token` keychain service into `CURSOR_API_KEY` so the Cursor child receives `--api-key` when the service is readable. The spawn site also uses `lib-external-launcher-common.sh`'s per-tool Darwin serial lock and outer auth retry wrapper; auth detection reads `${OUTPUT}.diag`, where `run-external-agent.sh --capture-stdout-only` routes Cursor stderr. Before the auth-retry loop the launcher calls `cursor_launcher_setup_private_config_dir` to export a fresh private `CURSOR_CONFIG_DIR` (seeded from `~/.cursor/cli-config.json` when present), eliminating the `cli-config.json` rename race when multiple CI-fix invocations run in parallel; cleanup runs inline after the loop via `cursor_launcher_cleanup_private_config_dir`.

### Stall detection

Per-role output progress is monitored while `run-external-agent.sh` runs in the background. `STALL_CHANNEL` is `stdout` for roles `fix`, `bump-classify`, and `changelog-draft` (monitors growth of the JSON output file). For `resolve-conflict` it is `tree:$PWD` (any working-tree change outside `.git`). The stall budget defaults to **180** wall seconds and is overridden by `LARCH_CURSOR_CI_STALL_THRESHOLD` (integer seconds; invalid or empty values fall back to 180). Polling uses the same cadence as `run-external-agent.sh`: `RUN_EXTERNAL_AGENT_POLL_INTERVAL` (default 10s). When a stall fires, the launcher appends a `Stall detected:` diagnostic block to `${OUTPUT}.diag` (including `channel=` and `time_since_last_progress=`), then `cursor_launcher_run_stall_monitor` in `lib-cursor-launcher-common.sh` terminates direct children of the wrapper first (SIGTERM, brief wait, SIGKILL) when `pgrep -P` is available, and only then signals the `run-external-agent.sh` wrapper PID the same way — matching the ordering used elsewhere for Cursor/Codex launchers so `SIGKILL` on the wrapper cannot leave a long-lived agent child orphaned. The launcher treats the outcome like any other non-zero launcher exit. That path still runs `append_launch_failure` when `IMPLEMENT_TMPDIR` is set (same as other failures), so `execution-issues.md` records the `cursor-ci` tool failure alongside the diag excerpt.

**Stall JSON sidecar** (when `jq(1)` is available and a run-log `round-*` directory is resolved): after `SIGTERM` is sent to the wrapper and its direct children, the monitor writes `round-N/cursor-ci-stall-<unix_ts>-<pid>-<rand>.json` next to the implement run log (unique basename and `mktemp` for the jq staging file to avoid same-second collisions). **Capture phase:** the first `Stall detected:` block appended to `${OUTPUT}.diag` (including the inline `ps` snapshot there) is written **before** those signals. The merged stdout/stderr transcript snapshot behind `last_transcript_lines` is taken **before** `SIGTERM` as well (`transcript_tail_capture_phase: "pre_sigterm"`). The JSON sidecar’s `ps`, `lsof`, and `git_state` fields are gathered **after** `SIGTERM` (`capture_phase: "post_sigterm"`); `diag_capture_note` documents the split. Sidecar assembly runs in parallel with the brief SIGTERM grace window so heavy `jq`/redaction/git work does not postpone SIGKILL escalation. Treat `.diag` as the immediate pre-kill view; diffing it against post-signal `ps`/`lsof` in the JSON is expected. **Sidecar directory resolution:** walk up from `${OUTPUT}`'s directory for the nearest `round-N/` ancestor; if none is found but `$IMPLEMENT_TMPDIR` is set, use `$IMPLEMENT_TMPDIR/round-1` (created if missing). The JSON object includes `channel`, `pid`, `time_since_last_progress`, `ps` (target + children + capped uid-scoped cursor argv snapshot; `scripts/redact-secrets.sh` under an 8s `timeout`/`gtimeout` envelope when the redactor is executable and a wall-clock wrapper exists; otherwise omission markers), `lsof` (capped `lsof -nP -p <pid>` when `lsof` and `timeout`/`gtimeout` exist), `git_state` (`status_porcelain` from capped `git status --porcelain` when `timeout`/`gtimeout` exist, then the same bounded redaction envelope as other blobs; `rebase_patch_excerpt` only while a rebase is in progress in the resolved git worktree), `transcript_tail_contract` (documents non-interleaved stdout-then-stderr tail blocks), and `last_transcript_lines` (from the pre-SIGTERM merged tail file, capped). If `jq` assembly fails after a stall, a one-line `cursor-ci-stall-json: jq assembly failed …` marker is appended to `${OUTPUT}.diag` so audits can tell “stalled but no parseable sidecar” from “no stall.” If the assembled JSON cannot be moved into place (`mv` to the final path fails), a one-line `cursor-ci-stall-json: write failed …` marker is appended. Omitting `jq` or an unwritable run-log directory skips the sidecar without affecting stall termination. Residual risk: argv snapshots are defense-in-depth redacted, not a full privacy boundary on hostile or unusual process listings.

When the auth-retry loop finishes with a non-zero `LAUNCHER_EXIT` and `IMPLEMENT_TMPDIR` is set, the launcher best-effort appends `${OUTPUT}.diag` to `$IMPLEMENT_TMPDIR/execution-issues.md` through `scripts/append-tool-failure.sh --redact` under `Tool Failures`, including an auth verdict and the final auth-loop attempt count.

## Harness

`scripts/test-launch-cursor-ci.sh` covers argv validation, output path validation, role validation, token-record normalization shape, and stall-detection fixtures (PATH stub for `cursor`, short `LARCH_CURSOR_CI_STALL_THRESHOLD`, fast `RUN_EXTERNAL_AGENT_POLL_INTERVAL`). Stall JSON contract assertions run only when `jq(1)` is installed; **GitHub Actions / `CI=true` runners must install `jq`** so those branches are not silently skipped.
