# hook-bg-poll-guard.sh

## Purpose

PreToolUse guard that blocks progress-observation probes (and Monitor / TaskOutput calls) while an immediate-background wait marker is live. Covers both `/design` and `/implement` bg-wait fences.

## Primary callers

- `hooks/hooks.json` via the `PreToolUse` matcher `Read|Bash|Monitor|TaskOutput`.

## Invariants

- Fails open on malformed hook input, missing `jq`, unreadable or malformed markers, telemetry write failure, and unexpected runtime errors.
- Allows Claude subprocess tool calls when `LARCH_CLAUDE_SUBPROCESS_HOOK_EXEMPT=1` is inherited from larch's `claude --print` launcher. This child-process boundary lets spawned Claude review, vote, and scout subprocesses read their assigned files while the parent orchestrator has a live immediate-background wait marker. Larch sets the signal only on spawned Claude children, so the parent orchestrator remains blocked by live markers unless the existing `LARCH_BG_POLL_GUARD_DISABLE=1` escape hatch is set.
- Scopes live markers by their session tmpdir under `~/.cache/larch/sessions/` (or the allowed `${TMPDIR}` design/implement/larch parents) plus `kill -0` PID-liveness and marker age, not by `CLAUDE_PID` matching (#5684). The old `CLAUDE_PID` equality check rejected every marker in production because the hook's `PPID`/input never matched the stored value, so no probe was ever denied. The marker still records `CLAUDE_PID` as debug metadata but the hook no longer reads it.
- The `$TMPDIR` branch of `marker_candidates` scans only `larch-*`, `claude-design-*`, and `claude-implement-*`
  prefixed dirs under `$TMPDIR` (maxdepth 2 within each), not the full TMPDIR tree. This
  avoids the macOS per-user `$TMPDIR` timeout issue (#5868): the full tree can reach 77k+
  dirs and exceed the hook's timeout under concurrent load. The `~/.cache/larch/sessions`
  branch is unaffected. The matched dirs are collected and passed to a single `find`
  invocation (multiple start-paths) rather than spawning one `find` subprocess per dir
  (#5943 recurrence of #5868): with the accumulated `larch-*`/`claude-design-*`/`claude-implement-*`
  dir count unbounded, per-dir subprocess spawn overhead alone could exceed the hook's
  timeout even though each individual `find` was already depth-scoped.
- Drops known-foreign live markers during collection before any deny loop sees them. A marker is known-foreign when its marker-local `CLONE_PATH` stamp, or fallback sibling `.larch-keepalive` `CLONE_PATH`, canonically differs from the hook input `cwd`; exact clone-root matches and subdirectory cwd matches count as same clone. The marker-local stamp wins when present and canonical so hook decisions use the identity captured at marker creation time. Empty `cwd`, missing identity, unreadable identity files, malformed `CLONE_PATH`, or uncanonical paths keep the marker, preserving conservative behavior when identity is unknown.
- Denies Monitor and TaskOutput tool calls while a retained bg-wait marker owned by this repo clone is live (design or implement). This is the primary defense against the BC8DDA64 Monitor-arming amplifier. Known-foreign markers are filtered before this path, so a live wait in another clone cannot block this session's Monitor/TaskOutput calls or receive this session's denial telemetry.
- Denies progress-observation probes aimed at the live tmpdir (design or implement), result env files, reviewer output files, or `plan-review` artifacts. A `Read` of `tasks/*.output` is allowed during a live wait because it is the write-once classification artifact after `<task-notification>`; this lets the orchestrator classify missing or whitespace-only output bytes as spurious and yield. During live same-clone `design-step*` waits only, repeated classification Reads of the same `tasks/<id>.output` are clamped after `LARCH_BG_POLL_GUARD_TASK_OUTPUT_READ_THRESHOLD` unchanged or whitespace-only Reads (default 2). The per-task sidecar is `bg-poll-guard-task-output-read.<id>.count`; it resets on non-whitespace content changes and on marker release via `reset_task_output_read_state`. On denial, the clamp also writes `no-progress-task-output-clamped` and arms `no-progress-circuit-breaker-armed` so the Stop hook can block task-notification re-entry immediately instead of waiting for the generic no-progress threshold. The clamp is a successful-Read clamp for `/design` notification recovery, not a general task-output polling policy, and it does not apply to `implement-step*` or unknown `STEP` values. Bash probes of `tasks/*.output` and the `TaskOutput` tool remain denied, with Bash `tasks/*.output` text matches still checked by `bash_probe_target_dir_plausible` for defense in depth. Known-foreign markers are filtered during collection.
- Scopes the generic bare `$DESIGN_TMPDIR`/`$IMPLEMENT_TMPDIR`/`$SESSION_TMPDIR` literal-text match in `bash_has_probe_target` to dirs the command plausibly targets. `bash_probe_target_dir_plausible` uses the same marker-local `CLONE_PATH` first, `.larch-keepalive` fallback second identity resolver as `marker_foreign_clone`, so same-clone probes from repo subdirectories still deny and known-foreign markers do not. When clone identity is unknown, it falls back to the older embedded repo-clone tag heuristic: the call's own `cwd` equals that dir, or the dir's `claude-<skill>-<clone-tag>-<suffix>` tag matches the tag derived from `cwd`'s basename. Two repo clones sharing an identical directory basename still collide only under this fallback, the same known limitation #5684 already accepts for marker liveness.
- Allows wrapper-routed calls through `design-run-*.sh` so `/design` can launch or resume the background work.
- Denies the Step 3 background sleep-loop recovery waiter matched by `bash_is_step3_recovery_waiter`, evaluated at the same tier as `bash_is_strict_wrapper_only` and before the generic filetest-sleep denials (#4725; this waiter was previously allowed at this tier). The waiter is itself a zero-output background task that amplifies premature `<task-notification>` events, so it is blocked in favor of the foreground terminal-sentinel probe below.
- The `bash_is_step3_recovery_waiter` matcher recognizes the exact `.completed/step-3-terminal` waiter shape — including an optional single leading `DESIGN_TMPDIR=<abs>;` assignment and the braced `${DESIGN_TMPDIR}` form (#4489) — so all of those bare-waiter forms are denied for retained same-clone markers. Known-foreign markers are filtered before this deny loop. Appended probes and compound command tails fall through to the generic deny loop; `.step3-review-result.env` waiters were already denied.
- Splits Step 3 sentinels. `.completed/step-3` remains the pause and Gate B milestone. `.completed/step-3-terminal` is the hook-release and recovery target written after `.step3-review-result.env` persists. `design-step3-review.sh` clears stale `.completed/step-3-terminal` and `.step3-terminal-persisted-this-run` at wrapper launch. `plan-review step3-state` clears them on direct re-entry and auto-continuation. Step 1e re-entry (`python/cli.py design step1e-reentry`) clears the same terminal sentinel pair alongside downstream phase markers.
- Releases live design markers once their terminal completion sentinel exists: `design-step3-review` on `.completed/step-3-terminal` plus readable `.step3-terminal-persisted-this-run`, `design-step4-tail` on `.completed/step-4`, `design-step5c` on `.completed/step-5c-terminal`, and `design-step-final-summary` on `.completed/step-final-summary`. Releases implement markers on their terminal sentinels: `implement-step3-checks` on `.completed/step-3-terminal`, `implement-step5-review` on `.completed/step-5-terminal`, `implement-step5-resume` on `.completed/step-5-resume-terminal`, `implement-step5-self-review` on `.completed/step-5-self-review-terminal`, `implement-step6-checks` on `.completed/step-6-terminal`, `implement-step7a` on `.completed/step-7a-terminal`, and `implement-step8-ship` on the root-level `.step-8-ship-handoff.rc` sidecar. All release sentinels must be regular files, not symlinks. Sentinel release is the intended fast path for same-turn result reads after `<task-notification>`; prompt guidance owns bounded foreground recovery when notification delivery and sentinel visibility transiently disagree.
- Allows `.bg-wait-active` marker-file reads for diagnosis. The `Read` tool is allowed when the target basename is exactly `.bg-wait-active`. Bash allows narrow marker-only diagnosis commands using common read/probe verbs (`cat`, `stat`, `ls`, `wc`, `head`, `sed`, `awk`) and still denies mixed commands that also reference task outputs, result files, `.completed/*`, `plan-review/`, Step 8 handoff files, control operators, or mutation/redirection shapes. `.completed/*` sentinels remain guarded.
- Denies a Bash command whose effective shell text is only the retained live marker directory, including quoted paths and `/private` path aliases on macOS. Known-foreign markers are filtered before this bare-dir classifier runs.
- Allows a foreground terminal completion-sentinel probe after `/design` premature notification recovery. The allowance is syntax-based for `test -f …` or `[ -f … ]`, with an optional exact echo-only `&& echo DONE || echo WAIT` tail, and it allows the absent-sentinel `WAIT` case. It targets only the terminal sentinel that matches the live design marker: `.completed/step-3-terminal`, `.completed/step-4`, `.completed/step-5c-terminal`, or `.completed/step-final-summary`. When live markers exist, the probe must bind `DESIGN_TMPDIR` to the live marker directory (explicit assignment matching a live dir, or exactly one retained live dir when unset); known-foreign sole live markers are filtered before clamp selection and cannot receive probe-clamp telemetry. If the probed sentinel exists as a symlink at evaluation time, the guard denies it. Denies Bash commands that create or truncate terminal sentinel paths while a marker is live.
- Allows a narrow `/implement` Step 3/5 foreground terminal-sentinel probe only for exact non-compound `test -f "$IMPLEMENT_TMPDIR/.completed/step-3-terminal"` and `test -f "$IMPLEMENT_TMPDIR/.completed/step-5-terminal"` shapes, including braced `${IMPLEMENT_TMPDIR}` and an optional leading `IMPLEMENT_TMPDIR=<abs>;` assignment. The probed sentinel binds to the matching live marker step (`implement-step3-checks` or `implement-step5-review`) and is clamped while absent. Bracket tests, appended reads, task-output probes, loops, sleeps, and nonmatching implement steps still deny.
- Denies foreground probes of non-terminal sentinels, result envs, task outputs, progress artifacts, sleep loops, watcher loops, `plan-review/` artifacts, and appended `cat` / `ls` / `stat` / `jq` style probes. The foreground terminal probe is not a substitute for wrapper completion on the initial launch.
- Clamps repeated foreground terminal-sentinel probes (#5478). The sanctioned recovery pattern is one foreground probe per real `<task-notification>`; spurious empty-output notifications (#5240) can drive the orchestrator to probe every turn while the sentinel stays absent. The hook counts consecutive foreground probes per sentinel while the sentinel is absent and denies once the count exceeds `LARCH_BG_POLL_GUARD_PROBE_THRESHOLD` (default 2). The counter is keyed per sentinel basename, so Step 3 (`step-3-terminal`), Step 4 (`step-4`), Step 5c (`step-5c-terminal`), implement Step 5 (`step-5-terminal`), Final summary (`step-final-summary`), and Step 8 (`step-8-ship-handoff.rc`) waits in one tmpdir cannot contaminate each other. Step 8's clamp checks root-level `$IMPLEMENT_TMPDIR/.step-8-ship-handoff.rc`; terminal-sentinel clamps check `$dir/.completed/$name`. Counters clear when the corresponding non-symlink sentinel appears. The deny clears on its own once the sentinel appears. Denying a probe never blocks completion detection, which depends on marker release, not the probe. Fails open (allows) when the per-sentinel counter cannot be written.
- Allows the Step 8 rc probe carve-out only for the exact foreground `test -f "$IMPLEMENT_TMPDIR/.step-8-ship-handoff.rc"` shape, including the braced `${IMPLEMENT_TMPDIR}` form, an optional `IMPLEMENT_TMPDIR=<abs>;` prefix, and the pointer-reader prefix documented in `skills/implement/SKILL.md`. Multi-live-marker resolution binds the probe to the live dir whose marker has `STEP=implement-step8-ship`, not to unrelated live waits. All other `$IMPLEMENT_TMPDIR` progress probes remain denied. Commands that forge `.step-8-ship-handoff.rc` via `touch`, truncation, redirects, `tee`, or similar mutation shapes are denied while a marker is live.
- Writes only best-effort counter sidecars under the retained same-clone marker tmpdir: `bg-poll-guard-denials.count` (aggregate denial telemetry), the per-sentinel `bg-poll-guard-probe-denials.<sentinel>.count` files that drive the #5478 foreground-probe clamp, and the per-task `bg-poll-guard-task-output-read.<id>.count` files that drive the `/design` classification-Read clamp. A denied classification Read also writes `no-progress-task-output-clamped` as the Stop-hook bridge for notification storms. Known-foreign markers skipped at collection time do not receive denial or clamp counters from this session.
- Includes the triggering marker path (`.../.bg-wait-active`), marker `STEP`, and hook plugin version in every deny reason. The metadata is intentionally diagnostic so an orchestrator or operator can distinguish same-clone waits from stale or version-skewed hooks. Hook fixes only affect Claude sessions started after a plugin upgrade because running sessions keep their pinned `CLAUDE_PLUGIN_ROOT`.
- Emits deny JSON with a static `printf` string, not `jq -cn`, once a deny branch is reached (#5610). `jq` is still required up front to parse the hook input (the hook fails open when `jq` is missing before parsing), but the final deny emission does not depend on `jq`, so a `jq` runtime failure at emit time cannot silently swallow the deny output.
