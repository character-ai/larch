# lib-external-launcher-common.sh

Exposes:

- `external_launcher_promote_inner_done <output_path>` — atomically renames `${output_path}.inner.done` to `${output_path}.done` when present, signaling that launcher-owned post-processing has completed.
- `external_launcher_append_outer_meta <meta_path> <outer_launcher_path> <prompt_file_sidecar> <workdir> [risk] [stderr_sink]` — appends `OUTER_LAUNCHER=…`, `OUTER_LAUNCHER_PROMPT_FILE=…`, `OUTER_LAUNCHER_WORKDIR=…`, and `OUTER_LAUNCHER_RISK=high|low` to an existing `.meta` sidecar so `collect-agent-results.sh` can replay empty-output retries through the originating launcher with the same risk-gated effort setting; no-op when the meta file does not yet exist. Missing or invalid risk values are recorded as `high` (fail-closed). When the optional 6th `stderr_sink` arg is non-empty, also appends `STDERR_SINK=<path>`; an empty 5th risk arg keeps the `${RISK:-high}` default.
- `external_launch_health_gate <tool>` — optional pre-launch health gate for `codex` and `cursor`. The gate is off unless a positive `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` resolves from, in order, the process environment, `$SESSION_ENV_PATH`, or `$IMPLEMENT_TMPDIR/session-env.sh` (the session files are read through `scripts/read-session-env-key.sh`, never sourced); an explicit numeric `0` at a higher-priority source opts out instead of falling through. Non-Codex/Cursor tools no-op. When enabled, it runs `scripts/check-reviewers.sh` with the other tool skipped and `LARCH_EXTERNAL_AUTH_RETRIES=1`; if `timeout` or `gtimeout` is on `PATH`, that wrapper applies the resolved outer timeout, otherwise the probe's internal timeout remains the bound. Exit `124` or `143` from the wrapper is unhealthy before any fail-open handling. A parseable `*_PRESENT=false` is unhealthy, `*_PRESENT=true` proceeds, and a non-timeout run with no parseable presence line fails open.
- `external_launcher_record_usage_from_events <plugin_root> <events_file> <sidecar_path> <raw_label> [token_record_path]` — best-effort Codex usage scraper shared by the Codex review / implement / CI launchers. It runs `scripts/parse-codex-usage.sh` against the JSONL events file, appends the parser's stderr diagnostic to `sidecar_path` on fail-closed parse errors, and otherwise emits one of two output modes:
  - when `token_record_path` is provided, writes a six-line sidecar (`TOOL=codex`, `INPUT=`, `OUTPUT=`, `CACHE_READ=`, `TOTAL=`, `RAW=`) for launcher-local consumers;
  - otherwise, records a `vendor=codex` row through `scripts/token-ledger.sh record-vendor` with `input=`, `cache_read=`, `output=`, `total=`, and `raw=`.
  Parse failure is silent to the caller aside from the sidecar append; no token sidecar or ledger row is written.
- `external_serial_lock_release_after <lock> <delay>` — schedules a disowned delayed `rmdir` for an acquired lock. Spawn sites pass `LARCH_EXTERNAL_SERIAL_LOCK_DELAY` (default 0.5) so the lock covers CLI startup without holding it for the whole run.
- `external_is_transient_infra_failure <tool> <exit_code> <elapsed_s> <output_file>` — returns 0 when a launcher exit looks like a transient infrastructure blip: exit code in the tool-specific allowlist (codex exits 5 or 7; cursor exits 4 or 8) and output file absent or 0 bytes (tool exited before producing any response). Returns 1 otherwise. Checks the output file rather than the sidecar because the sidecar always contains `run-external-agent.sh`'s failure message even on 0-output runs. The `elapsed_s` argument is accepted for call-site compatibility but is not part of the classification. Called by `launch-review.sh` before the auth-retry check so 0-output infra blips get up to 2 bounded retries with jittered backoff before falling through to the auth check or waterfall escalation. Set `LARCH_TRANSIENT_RETRY_DELAY=0` in tests to skip the sleep.
- `external_auth_verdict <tool> <sidecar> [sidecar...]` — prints `auth` when any readable sidecar matches the auth classifier, `non-auth` when at least one sidecar is readable but none match, and `unclassified` when no sidecar is readable. Cursor callers pass both the wrapper sidecar and `.diag` file because stderr can land in either place depending on capture mode.

- `external_classify_launch_failure <launcher_exit> <sidecar> <auth_verdict> <binary_present> <tool> <output_file>` — prints two stdout lines: `LAUNCHER_FAILURE_CLASS=` then `LAUNCHER_FAILURE_REASON=` using the canonical enums (`none` / `health` / `other` for class; `auth` / `binary-missing` / `health-probe` / `timeout` / `parse` / `refusal` / `unknown` / empty for `none`). Consumes the launcher exit code, primary sidecar path, one-line `external_auth_verdict` output, whether the CLI binary was present before launch (`1`/`true` vs anything else), tool id for `external_is_transient_infra_failure`, and the tool output file path. CI launchers (`launch-*-ci.sh`) call this after each run so `ship-pr.sh` can classify first-tier failures without parsing tool-specific logs ad hoc.

The library is sourced-only (no shebang, no `set -e`); callers own exit semantics. Loaded once per shell via the `LARCH_LIB_EXTERNAL_LAUNCHER_COMMON_LOADED` guard so the per-tool wrapper libs (`lib-codex-launcher-common.sh`, `lib-cursor-launcher-common.sh`) can both source it without double-defining functions.

The per-tool wrappers (`codex_launcher_promote_inner_done`, `codex_launcher_append_outer_meta`, `cursor_launcher_promote_inner_done`, `cursor_launcher_append_outer_meta`) are thin one-line aliases retained in their respective per-tool libs so existing call sites in `launch-review.sh --tool codex`, `launch-review.sh --tool cursor`, and `launch-cursor-implement.sh` continue to work unchanged.
