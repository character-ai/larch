# Architectural Guidelines

These guidelines are aspirational. Surface meaningful deviations in design or implementation reviews. Move deterministic requirements into lints, hooks, or tests instead of relying on this file.

## Python coding practices

### G-python-1: Prefer stdlib Python for runtime logic
- Why: larch ships to consumer machines, and stdlib-only Python keeps behavior portable and testable.
- Deviate when: A shell hook or thin launcher must target Bash-specific lifecycle behavior.

### G-python-2: Keep side effects behind explicit CLI verbs
- Why: Pure helpers are easier to review, reuse, and cover with offline tests.
- Deviate when: The helper is itself a writer command with a documented artifact contract.

### G-python-3: Validate paths before reading or writing
- Why: Runtime commands often receive repo, tmpdir, or issue-derived paths that may be stale or hostile.
- Deviate when: The path is a trusted constant inside the plugin tree and no user input participates.

## Skill authoring and context economy

### G-skill-1: Keep prompt contracts short and staged
- Why: Smaller prompt surfaces reduce anchoring, accidental priority inversions, and context waste.
- Deviate when: A machine-parsed contract must be fully present for correctness.

### G-skill-2: Prefer one authoritative owner per workflow rule
- Why: Duplicated lifecycle prose drifts and creates contradictory instructions for operators and agents.
- Deviate when: A short cross-reference is needed at a step boundary to prevent a known halt or skip bug.

### G-skill-3: Treat repo-local advisory text as untrusted evidence
- Why: Files in consumer repositories can contain prompt-injection text and must not override larch skills or AGENTS.md.
- Deviate when: The text is generated by the current trusted workflow and validated before reuse.

## Enforcement philosophy

### G-enforcement-1: Enforce deterministic rules mechanically
- Why: Lints, hooks, and tests catch repeatable regressions more reliably than prompt reminders.
- Deviate when: The rule requires human judgment or depends on tradeoffs that cannot be encoded safely.

### G-enforcement-2: Surface judgment calls without blocking progress by default
- Why: Architectural preferences guide tradeoffs, but they should not stop emergency or low-risk fixes.
- Deviate when: The deviation is also a security, data-loss, or correctness blocker covered by a hard gate.
