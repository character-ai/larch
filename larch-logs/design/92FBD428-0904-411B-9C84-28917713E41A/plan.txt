## Approach

Minimal-change strategy: remove one archetype from each panel's static list, absorb its
focus into adjacent archetypes, and scrub counts from documentation without updating them
to new numbers (future experiments won't require re-touching the same docs).

The `dispatch-panel.sh` list-iteration pattern already satisfies the "per-existing-archetype
basis" requirement for `/implement`/`/review`. For `/design`, the hardcoded loops in
`dispatch-plan-review-panel.sh` satisfy the spirit (each archetype is named once in the
loop; future changes touch the loop bodies) — operator confirmed the inline list approach.

## Edge cases

- `sketch_budget=3` must be added to `session_env.py` validation before running tests;
  `design-init-runparams.sh` passes it to `write-run-params`, so without validation
  the session setup would fail on the first HARD /design run.
- `test-dispatch-panel.sh` asserts specific output filenames and `STATIC_SLOT_COUNT=8`;
  both break immediately on the first test run if not updated.
- The topology.tsv must be edited before running `generate-topology-docs.sh`; the script
  is the authoritative regenerator for `docs/topology.md`.
- `check-focus-area-enum.sh` (CI) validates that `security` appears in focus-area
  enumerations — but this is the FINDING TAG `security`, not the archetype slot name.
  These are independent. No changes needed to the focus-area enum.

## Testing strategy

Run existing test suite after all changes:
- `make test-dispatch-panel` — validates panel manifest and slot counts.
- `make test-tally-code-votes` — validates tally with updated manifest.
- `make test-review-core` — validates core review loop.
- `make lint` or `bash scripts/relevant-checks.sh` — CI lint including `check-focus-area-enum.sh`.
- `bash scripts/test-render-specialist-prompt.sh` — ensures edge-cases agent still renders.
- `bash python/test_session_env.py` or `make py-test` — validates sketch_budget validation change.
