Normalized merge of the 12 reviewer inputs into **6** distinct findings (same behavioral risk merged; different fixes or code paths kept separate).

### FINDING_1: Scope rebuild helper to `--reason final` only
- **Reviewer(s)**: Cursor-Arch, Cursor-dyn-publish-risk-integration
- **Severity**: important
- **Concern**: The pre-push rebuild-on-default helper is not explicitly limited to `REASON=final`. If the same reset-and-overlay path runs for pause, it would reset the disposable branch onto freshly fetched `origin/<default>` instead of keeping worktree creation from `origin/larch-log-design-<RUN_ID>` and the pause `--force-with-lease` reuse contract. That can discard pause-branch history, break documented pause semantics, and regress pause empty-porcelain fail-closed paths and existing pause reuse tests.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: State in the helper contract that it runs only for `REASON=final`; leave the existing pause commit/push path unchanged.
  - From Cursor-dyn-publish-risk-integration: Scope the rebuild-and-overlay helper to `REASON==final` only. For pause, keep the current commit-on-log-branch-base plus force-with-lease path; at most fetch refreshed `origin/<default>` without the full reset-and-overlay sequence.

### FINDING_2: Final-mode push must handle existing/divergent remote log branch
- **Reviewer(s)**: Cursor-Innovation, Cursor-Requirements, Cursor-dyn-stale-base-correctness
- **Severity**: important
- **Concern**: The plan adds pre-push rebuild but leaves final-mode push as plain `git push -u` while pause uses `--force-with-lease`. After a stuck or incremental re-flush (#4241/#4244), `origin/larch-log-design-<RUN_ID>` often still exists with a divergent tip. A commit rebuilt on fresh default cannot fast-forward that remote ref; push is rejected, recovery repeats the stuck-PR pattern, and a newer final snapshot never reaches one mergeable PR. Existing harness expects `PUBLISH_OK=false` on non-fast-forward, which contradicts the intended incremental republish semantics.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: Add final-mode push rule: when origin/larch-log-design-<RUN_ID> exists use --force-with-lease (same family as pause); document in design-log-publish.md
  - From Cursor-Requirements: Specify final-mode push when REMOTE_BRANCH_EXISTS or push would be non-fast-forward: e.g. git push --force-with-lease after the rebuild, document the contract in design-log-publish.md, and flip the RUNBASE1 harness to assert PUBLISH_OK=true with branch-only sentinel absent from default
  - From Cursor-dyn-stale-base-correctness: Specify final-mode push when `REMOTE_BRANCH_EXISTS=true`: force-with-lease onto `larch-log-design-<RUN_ID>` (or delete the stale remote ref first), then reuse the open PR via existing `gh pr list` recovery

### FINDING_3: Rebuild overlay must delete snapshot-absent paths
- **Reviewer(s)**: Codex-Innovation, Cursor-Pragmatic, Codex-dyn-publish-risk-integration
- **Severity**: important
- **Concern**: The rebuild helper overlays the desired snapshot without deletion-aware sync. After reset to freshly fetched `origin/<default>`, files already present under `larch-logs/design/$RUN_ID` on default but absent from the new redacted snapshot can survive. A copy-only overlay leaves excluded or stale artifacts (e.g. `codex-primary-plan-arch-output.txt`, round `findings.md`) on the PR branch while the session snapshot omits them, so the PR is not the true final snapshot and can regress the existing stale-excluded cleanup contract.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Innovation: After resetting to origin default, replace the run directory or sync with delete semantics before copying the snapshot; preserve the default manifest only for the manifest-only comparison, then git add the whole run path so deletions are committed
  - From Cursor-Pragmatic: After reset and before the delta check, replace $WT_DIR/$rel with the snapshot tree (for example rm -rf then cp -a), or run design_publish_remove_stale_excluded on $WT_DIR/$rel and stage deletions with git add -A -- $rel
  - From Codex-dyn-publish-risk-integration: Make the rebuild step replace or rsync --delete $WT_DIR/$rel from the scrubbed snapshot, then run the existing stale-excluded cleanup before the porcelain check. Treat non-manifest deletions as real delta.

### FINDING_4: Caller `PUBLISH_OK=true` short-circuit skips late idempotency path
- **Reviewer(s)**: Cursor-Requirements, Codex-dyn-publish-risk-integration
- **Severity**: important
- **Concern**: The plan changes `design-log-publish.sh` but leaves `design-publish.sh`'s existing `PUBLISH_OK=true` short-circuit before invoking it. On Step 5c re-entry after an early successful publish, the caller skips `design-log-publish.sh` entirely, so final-only artifacts are never compared or published and Fix C can drop the final snapshot delta despite moving idempotency into `design-log-publish.sh`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Requirements: Narrow the caller skip so existing success only protects result-env overwrite and failed-publish reporting after a current publish attempt. Still render timing and invoke design-log-publish.sh, then let its no-delta path decide. Update design-publish.md and add a focused test-design-publish.sh case with existing PUBLISH_OK=true plus a changed snapshot that asserts design-log-publish.sh is called.
  - From Codex-dyn-publish-risk-integration: Include a minimal design-publish.sh change so prior PUBLISH_OK=true does not skip the publish call; let design-log-publish.sh perform the late no-delta check, while preserving the existing write-once fallback when a later publish attempt fails

### FINDING_5: Final-mode commit must be created only inside rebuild helper
- **Reviewer(s)**: Cursor-dyn-publish-risk-integration
- **Severity**: important
- **Concern**: The plan does not state that the current pre-push `git commit` is replaced by the rebuild commit. The live script commits staged content on the initial worktree base, then pushes that SHA. If the rebuild helper is inserted after that commit without superseding it, push can still send a stale-base commit while the rebuilt tree never ships.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-publish-risk-integration: Move final-mode commit creation into the rebuild helper only: stage and scrub to snapshot, rebuild on fetched `origin/<default>`, delta-check, then single commit immediately before push. Do not push a pre-rebuild commit

### FINDING_6: Harness `RUNIDEM1` contradicts incremental republish semantics
- **Reviewer(s)**: Cursor-dyn-publish-risk-integration
- **Severity**: important
- **Concern**: Existing harness case `final idempotent success after squash merge` seeds default with one `plan.txt` content, publishes a differing tmpdir snapshot, and asserts no `pr create`. Removing the early ls-tree skip and adding late delta detection requires a PR for that differing snapshot (the #4212 fix), so the test contradicts the planned behavior.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-publish-risk-integration: Retire or rewrite the RUNIDEM1 case to expect `gh pr create` when snapshot differs from default. Keep no-PR assertions only for byte-identical reruns such as `final no-delta succeeds idempotently` (`726-760`)
