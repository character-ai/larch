## Edge cases

- **Existing run directory on default:** publish only real new content. Do not skip a newer final snapshot.
- **Manifest-only churn:** skip as idempotent. Do not open a PR just to change timestamps.
- **Deleted artifacts:** remove paths absent from the desired scrubbed snapshot. Treat non-manifest deletions as real delta.
- **Default branch changes mid-publish:** fetch and rebuild immediately before final push.
- **Existing final remote log branch:** use `--force-with-lease` for the rebuilt final commit.
- **Remote log branch exists in final mode:** keep final mode based on refreshed default, not the old log branch.
- **Pause mode:** keep branch reuse, force-with-lease, and recovery behavior unchanged.
- **Prior wrapper success:** still invoke publish so final-only artifacts can be compared.
- **Fetch failure before push:** fail closed before creating a PR.
- **Push failure after rebuild:** preserve the local recovery branch.

## Failure modes

- If the snapshot copy into `$WT_PARENT` fails, emit `PUBLISH_OK=false` and exit before push.
- If the mandatory pre-push fetch fails, emit `PUBLISH_OK=false` and exit before push.
- If the delete-aware replacement cannot be completed, emit `PUBLISH_OK=false` and exit before push.
- If the rebuilt commit cannot be created, emit `PUBLISH_OK=false` and exit before push.
- If `git push` fails, keep the current recovery-branch behavior.
- If CI or merge fails after PR creation, keep the current `PUBLISH_OK=false` and recovery metadata behavior.
- If a later wrapper publish attempt fails after a prior success, preserve the prior success result according to the existing write-once contract.
