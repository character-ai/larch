### 1. Exit 3 shared matrix missing python `needs_user_reason` override (correctness)

The plan’s A1b Exit 3 bullet only adds a python override for `failed_run_id` from stdout JSON. The shared Exit 3 entry at ```1050:1050:skills/implement/SKILL.md``` still opens with “read `BAIL_REASON` from `ship-pr-state.sh`”, and A2/A2b pins only `failed_run_id`, not dispatch-token sourcing.

The L955 python-driver paragraph already says to dispatch on `needs_user_reason`, but the shared post-invoke matrix does not—creating a bash/python seam the plan asserts it is closing.

**Suggested revision:** In A1b Exit 3, add an explicit python-branch override: read `needs_user_reason` from stdout JSON instead of `BAIL_REASON` from `ship-pr-state.sh`; add a matching structural pin in `scripts/test-implement-structure.sh`.

### 2. Exit 6 stall promotion vs NEVER #11 and dual-path reads (architecture)

Plan A1b Exit 6 states that on the python path, 4th-transient stall promotion sets `STALL_TRACKING` in `finalize-state.sh`. Current Exit 6 prose at ```1065:1065:skills/implement/SKILL.md``` generically says “set `STALL_TRACKING=true` in the state file via a key-based rewrite” (bash targets `ship-pr-state.sh`, which includes seeded `STALL_TRACKING=false` at ```978:978:skills/implement/SKILL.md```).

NEVER #11 at ```52:52:skills/implement/SKILL.md``` forbids prompt-side orchestrator writes to `finalize-state.sh`; the only blessed writer before teardown is `restore-finalize-state.sh` at Step 18. Mid-Step-8 Exit 6 promotion is therefore not covered. Python gap-fill (`_persist_stall_metadata_if_needed`) runs inside `ship.py` on `Outcome.STALLED` returns, not on orchestrator-side Exit 6→Exit 4 promotion.

**Suggested revision (minimum-change):** Keep Exit 6 promotion writing `ship-pr-state.sh` on both paths (bash behavior unchanged) and extend Exit 4 python stall reads to consult `finalize-state.sh` first, then `ship-pr-state.sh` (not only JSON `detail` when finalize is absent). Alternatively, add a sanctioned one-key helper and a narrow NEVER #11 exception—avoid unsanctioned orchestrator finalize-state writes.

### 3. [OUT_OF_SCOPE] Restore preservation test omits seeded `STALL_TRACKING=false` (correctness)

The production clobber path described in the plan (approach line 25) is: orchestrator seeds `STALL_TRACKING=false` in `ship-pr-state.sh` (```978:978:skills/implement/SKILL.md```), python gap-fill writes `STALL_TRACKING=true` to `finalize-state.sh` (```360:361:python/finalize.py```), then `restore-finalize-state.sh` prefers ship-pr values when non-empty (```83:86:scripts/restore-finalize-state.sh```).

Existing harness `write_complete_state` already uses `STALL_TRACKING=false` in ship-pr (```127:128:scripts/test-restore-finalize-state.sh```) but does not pre-seed finalize with `STALL_TRACKING=true`.
