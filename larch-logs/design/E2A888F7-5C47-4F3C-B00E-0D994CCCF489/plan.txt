## Edge cases

- Preserve caller-supplied field and label order.
- Do not emit empty optional flags.
- Treat `limit=0` as supplied and emit `--limit 0`; only `None` omits the flag.
- Do not expose unsupported `gh issue list --paginate` behavior.
- Accept empty list output as an empty result.
- Reject JSON objects and scalar values where issue-list arrays are required.
- Keep arbitrary GitHub state, search, field, label, and limit values as caller data; do not introduce policy validation that could reject future valid `gh` values.
- Plain issue-view reads must remain plain output reads: do not add JSON fields or templates implicitly.
- Do not read or manage lifecycle for a caller-owned `--body-file` path.
- Do not combine new mutation retries with read retries.

## Failure modes

- A non-transient issue-list, plain-view, or templated-view read failure raises `ShipError`.
- Exhausted transient read failures raise `TransientNetworkError` with the final result attached through the existing retry path.
- Invalid or incorrectly shaped issue-list JSON raises `ShipError`.
- Close and caller-owned body-file edit failures remain inspectable through returned `CommandResult` values.
- Existing label helper retries remain unchanged.
- Incorrect argv order, missing optional flags, unsupported pagination flags, accidental body-file replacement, or accidental JSON/template flags on plain views are caught by exact runner-call assertions.
