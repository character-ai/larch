### UPDATED: `scripts/dispatch-with-waterfall.sh`
Add the `fallback_group` dedup mechanism with phase-aware ledger, group-serialized phase-2, ledger anchoring, TSV validation, and reused-slot bookkeeping. Concretely:

1. **Manifest parse (Bash 3.2 compatible)**: when parsing the slots NDJSON, populate parallel arrays `slot_names[]`, `slot_tools[]`, `slot_outputs[]`, `slot_prompt_files[]`, and a NEW `slot_fallback_groups[]`. Use `jq -r '.fallback_group // empty'` (or `jq -r 'if has("fallback_group") then .fallback_group else "" end'`) to extract per-row; empty string means "no group, legacy path".

2. **TSV-safety validation** (immediately after manifest parse): for each non-empty `slot_fallback_groups[i]` and `slot_names[i]` and `slot_outputs[i]`, REJECT any value containing tab (`$'\t'`), CR (`$'\r'`), or LF (`$'\n'`). On rejection, write a `STEP_FAILED=MANIFEST_VALIDATION` line to stdout, emit a diagnostic to stderr, and exit non-zero. Document the rejected character set in `dispatch-with-waterfall.md`.

3. **Ledger anchoring**: derive the per-call tmpdir from `dirname` of the resolved slots-file path passed via `--slots-file`, then create `<tmpdir>/waterfall-group-results.tsv` (touch on first ledger write). Do NOT read `RESEARCH_TMPDIR`/`DESIGN_TMPDIR`/`REVIEW_TMPDIR` env vars in the dispatcher — anchoring solely on slots-file dirname avoids cross-run leakage and env-var drift.

4. **Ledger schema (TSV, single-token status)**: rows are 5 tab-separated fields: `group<TAB>slot_name<TAB>tool<TAB>output_path<TAB>status`. The status field is a SINGLE token: `ok` for primary success or fresh fallback success; `reused` for a slot that copied another slot's result. (No comma-embedded `OK,reused` form — keeps grep/cut parsing simple.) Add `source_slot` as an OPTIONAL 6th column ONLY on `reused` rows so consumers can attribute the source. The ledger is append-only within a dispatcher call; concurrent writers within the same call are not possible (the dispatcher itself owns the file). Document strict 5-or-6-field tab parsing only in `dispatch-with-waterfall.md`.

5. **Phase-1 ledger writes**: in `collect_phase` (or wherever phase-1 collection settles), for every slot `i` whose `slot_fallback_groups[i]` is non-empty AND whose phase-1 `STATUS` is `OK` (or the configured success token — confirm against existing `STATUS` set during implementation), atomically append a ledger row `<group><TAB><slot_name><TAB><tool><TAB><output_path><TAB>ok`. Use `printf '%s\t%s\t%s\t%s\t%s\n' ... >>"$ledger"` — append is atomic on POSIX for small lines, but if more safety is needed use the `mktemp` + `cat ledger new >tmp && mv tmp ledger` pattern.

6. **Group-serialized phase-2 dispatch** (addresses the race): change phase-2 launch logic from the current "background all queued phase-2 slots, then wait once" to per-group serialization for grouped slots:
   - **Ungrouped slots** (`slot_fallback_groups[i]` empty): launch in parallel as today.
   - **Grouped slots**: for each unique `fallback_group` in the queued phase-2 set, iterate group members ONE AT A TIME within that group. Before launching each member:
     - Scan the ledger for an existing `ok` row matching `(fallback_group, fallback_tool)` where `fallback_tool` is the tool this phase-2 slot would have launched (typically `codex` when primary was cursor, or vice versa).
     - **Match found**: invoke the `reuse_slot_result(idx, source_row)` helper (item 7 below) instead of launching. No process is spawned for this slot.
     - **No match**: launch the slot normally, wait for completion, write the resulting ledger row (status `ok`), then proceed to the next group member.
   - Groups are processed serially relative to each other ONLY IF the implementation cannot easily run inter-group phase-2 in parallel; if inter-group parallelism is easy (different ledger keys), keep it. Within a group, members are strictly sequential.
   - Document this exact invariant ("within a fallback_group, phase-2 launches are sequential") in `dispatch-with-waterfall.md` and add a same-group two-slot test.

7. **Reused-slot bookkeeping helper** (`reuse_slot_result(idx, source_slot_name, source_output_path, source_tool)`):
   - Copy `source_output_path` content to `slot_outputs[idx]` via `cat src > dst` (or `cp src dst`). Preserve file permissions per existing pattern.
   - Write a sidecar file `${slot_outputs[idx]}.dedup` containing exactly the two lines `DEDUPE_REUSED_FROM=<source_slot_name>` and `DEDUPE_REUSED_TOOL=<source_tool>` (use `printf '%s\n%s\n' ...`, NOT `>>` so the file is freshly written each call).
   - Append a ledger row `<group><TAB><slot_name><TAB><source_tool><TAB><slot_outputs[idx]><TAB>reused<TAB><source_slot_name>` (the 6th column is the optional `source_slot`).
   - Emit a structured contract-stream KV breadcrumb: `DEDUPE_REUSED=true` and `DEDUPE_REUSED_FROM=<source_slot_name>` and `DEDUPE_REUSED_TOOL=<source_tool>` (use existing `emit_kv` / `emit` helper from `scripts/lib-quiet.md` if available; otherwise plain stderr lines).
   - Set `final_outputs[idx]="${slot_outputs[idx]}"` and `final_tools[idx]="$source_tool"` so this slot is considered SETTLED by all downstream phase aggregation (avoids the blank-`ALL_OUTPUT_FILES` failure mode from FINDING_10).
   - Mark `idx` as excluded from any subsequent phase collection (e.g. add to a `_reused_indices` newline-delimited file the phase-3 fallback loop reads to skip).

8. **Backward compatibility**: when `slot_fallback_groups[i]` is empty for ALL slots in the manifest (legacy case), skip ALL ledger logic (do not create the TSV file). The dispatcher behavior is byte-equivalent to the pre-change version. Verify via existing `scripts/test-dispatch-with-waterfall.sh` cases — they must continue to pass without modification.

## Approach

Three independent fixes share one PR. Sequencing within the PR is critical to avoid mid-merge CI breakage:

1. **Item A first** (prose-only, no executable impact): research-phase.md, validation-phase.md, BASH_AUTHORING.md prose updates.
2. **Item B next** in two steps:
   - Step 2a: Add the `unset LARCH_PAIRED_PID_FILE` lines to all five callers (`dispatch-plan-review-panel.sh`, `decompose-panel-dispatch.sh`, `decompose-aggregator.sh`, `aggregate-findings.sh`, `dispatch-panel.sh`) BEFORE turning on the new linter rules.
   - Step 2b: Extend `lint-foreground-markers.sh` with the parent-unset rule AND the post-fence contradiction rule, then add the regression coverage in `test-lint-foreground-markers.sh`. Order matters: turning on the lint after the `unset` lines are already in place means CI does not break on the intermediate state.
3. **Item C last** (largest behavioral change, most independent): add `fallback_group` parsing + ledger + group-serialized phase-2 + reused-slot bookkeeping + TSV validation to `dispatch-with-waterfall.sh`, document in `dispatch-with-waterfall.md`, wire `fallback_group` into the `decompose-panel-dispatch.sh` and `dispatch-plan-review-panel.sh` manifest builders, and add regression coverage in `test-dispatch-with-waterfall.sh` + `test-decompose-panel-dispatch.sh` (+ the plan-review panel manifest assertion).

The `fallback_group` field is additive on the manifest schema. Existing callers that do NOT set it (`decompose-aggregator.sh`, `aggregate-findings.sh`, and any third-party caller) skip ALL ledger logic — the dispatcher is byte-equivalent to pre-change for those callers. This makes the rollout incremental and reversible: a caller can opt into dedup by adding `fallback_group` to its jq manifest rows; it can opt out by removing the field.

The ledger anchoring uses `dirname` of the resolved `--slots-file` argument, NOT environment variables. This decouples the dispatcher from caller-specific tmpdir conventions and avoids the cross-run leakage risk (FINDING_5).

Phase-2 is restructured from "background all queued phase-2 slots in one batch, then `wait` once" to "for grouped slots, launch one per group at a time and copy the result to peers". This is the only known way the dedup invariant ("exactly one Codex launch per (group, tool) phase-2") can hold given existing dispatcher concurrency (FINDING_13/15/20/24/28/36/45). Ungrouped slots keep their existing parallel behavior to preserve performance for callers that did not opt in.

## Edge cases

- **`fallback_group` present on a single slot** (no peer with same group): ledger row is written but no peer ever reads it; behavior is identical to legacy. Test: single-slot group must not break.
- **First slot's Codex itself fails** (no `ok` row in ledger for the group): subsequent slots in the group launch their own Codex (independent failure path). Test: dedup must not propagate failure or silently mask it.
- **Phase-1 codex-primary OK + cursor-primary fail in same group** (the explicit issue body scenario for Item C): cursor's phase-2 detects the phase-1 ledger row and reuses. Test mandatory (FINDING_40).
- **Slot whose primary tool IS codex (not cursor)**: dedup applies symmetrically — if a codex-primary slot fails primary and its peer's cursor-primary succeeded, the codex-primary slot's phase-2 (which would launch cursor) reuses the peer's cursor result. The ledger TSV `tool` column captures the actual result tool, not the slot's primary.
- **Linter look-back boundary at file top**: if the invocation is in the first 5 lines (rare), treat missing `unset` the same as the normal case (violation, unless suppressed).
- **`unset` on a continuation line (`unset LARCH_PAIRED_PID_FILE \`)**: the linter must treat physical lines, not logical lines, when counting look-back distance. Continuation lines are extremely uncommon for `unset`, so this is documentation-only.
- **`dispatch-with-waterfall.sh` referenced inside a heredoc body or string literal**: the linter's invocation-shape check excludes lines where the basename appears only inside `--tool "..."` or quoted string arguments. Heredocs are not anchors.
- **TSV validation false-positive on legitimate group strings**: only tab, CR, LF are rejected; underscores, hyphens, slashes, dots, alphanumerics are all valid. The valid set covers all proposed group names (`plan-arch`, `plan-dyn-some-slug`, `decomp-arch`, etc.).
- **Two distinct dispatchers running in the same repo concurrently** (`/design` + `/implement`): each call has its own `--slots-file` so the ledger anchoring (per-call tmpdir) keeps them isolated.

## Failure modes

1. **Dedup race (within a group)** — if phase-2 group serialization is implemented incorrectly (e.g. accidentally launches two members of the same group in parallel), the ledger scan can miss the first launch's `ok` row. Early warning: `test-dispatch-with-waterfall.sh` "single-group two-slot phase-2 dedup hit" case assertion that exactly one Codex process was launched will fail. Mitigation: implement group serialization as a strict per-group sequential loop; review for accidental `&` after `launch_slot`.
2. **Linter false-positive on legitimate suppression cases** — if a Family B caller has a justified reason to skip `unset` (e.g. an outer trap already cleared the env), the linter blocks the change. Early warning: a regression test or CI run shows the new violation on an unrelated PR. Mitigation: the `# lint-foreground-markers: ok <reason>` inline suppression is the documented escape hatch; document the typical reasons explicitly in `lint-foreground-markers.md`.
3. **Post-fence contradiction regression** — if a future commit reintroduces a `Do NOT set run_in_background: true` line within 10 markdown lines after a background+monitor fence in any file under the markdown scan set, the new linter check catches it. The existing `fence_stale_foreground_markers` check only scanned fence-internal/pre-fence content; the new check fills the post-fence gap and the regression coverage in `test-lint-foreground-markers.sh` keeps it locked down.

Early warning: existing tests pass absolute paths; document the assumption in `dispatch-with-waterfall.md`. Mitigation: resolve `--slots-file` to absolute via `realpath` (or `readlink -f` fallback) before computing `dirname`.
