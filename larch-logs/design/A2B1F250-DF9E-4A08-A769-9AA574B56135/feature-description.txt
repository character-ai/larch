# [BUG] (URGENT) /design plan-processing defects: mechanical_churn integer silently bypassed + plan-review loop continues spuriously on empty tally

Two bugs observed in run FB9CAE3D-450F-444B-8642-E2D4B71E4983 (issue #4106 `/design`).

### Bug 1 — `mechanical_churn` integer silently bypassed (was #4119)

`lib-plan-optional-trailers.awk` only matches `^mechanical_churn: (true|false)$`. When the Codex drafter emits `mechanical_churn: 35`, the value defaults to `false` with no warning and the soft advisory (downgrading the diff gate from `diff_lines > 1500` to `diff_added > 2000`) is silently skipped. The operator discovered and fixed the invalid value manually before postplan.

**Expected behavior:** When `mechanical_churn:` is present but not `true`/`false`, at least one of: awk emits a stderr diagnostic; `check-plan-size.sh` emits `PLAN_SIZE_STATUS=invalid-mechanical-churn` with exit 2; `design-postplan-emit.sh` surfaces a defect.

**Fix direction:** In `lib-plan-optional-trailers.awk`, emit a stderr diagnostic when the value is not boolean. Alternatively, add a post-parse validation pass in `check-plan-size.sh` that detects `has_mech=1` with an invalid value and exits 2 with `PLAN_SIZE_STATUS=invalid-mechanical-churn`.

**Affected files:**
- `skills/design/scripts/lib-plan-optional-trailers.awk`
- `skills/design/scripts/check-plan-size.sh`
- `skills/design/scripts/test-check-plan-size.sh` (regression)

---

### Bug 2 — plan-review loop continues spuriously on empty tally output (was #4120)

Round 1 had `COLLECT_OK_COUNT=14`, `INSCOPE_REMAINING=30`, `TALLY_PLAN_REVIEW_STATUS=ok`, `ACCEPTED_COUNT=0`, but `findings-classification.tsv` was header-only (zero data rows). The continuation check saw `ACCEPTED_COUNT=0` and `DEGRADED_PANEL=0` and should have stopped, but the loop ran 5 rounds total, finding 22 accepted findings across rounds 2–5.

**Root issue:** The tally does not distinguish "empty ballot (`INSCOPE_REMAINING=0`)" from "non-empty ballot with zero classified output (`INSCOPE_REMAINING=30`, header-only TSV)." Both surface as `TALLY_PLAN_REVIEW_STATUS=ok` + `ACCEPTED_COUNT=0`. The second state is a degraded-panel condition warranting continuation, but the current logic treats both identically.

**Expected behavior:** When `INSCOPE_REMAINING > 0` but `findings-classification.tsv` has zero data rows and tally is ok, emit `DEGRADED_PANEL=1` (or a distinct status like `tally-empty-from-nonempty-ballot`) so `plan-review-continuation.sh` correctly continues with `REASON=ballot-items-lost`.

**Fix direction:** In `plan-review-loop.sh`, after the tally step, compare `INSCOPE_REMAINING` against the row count in `findings-classification.tsv`. When `INSCOPE_REMAINING > 0` and TSV is header-only, emit `DEGRADED_PANEL=1` in round-summary output. Additionally persist `INSCOPE_REMAINING` to `round-summary.env` for post-mortem audits.

**Affected files:**
- `skills/design/scripts/plan-review-loop.sh`
- `skills/design/scripts/plan-review-loop.md`
- `skills/design/scripts/test-plan-review-loop.sh` (regression: assert `DEGRADED_PANEL=1` when ballot non-empty and TSV header-only)
