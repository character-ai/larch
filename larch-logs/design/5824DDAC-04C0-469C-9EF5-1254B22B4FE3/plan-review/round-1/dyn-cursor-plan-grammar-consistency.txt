### 1. correctness — `python/tests/issue/test_learn_from_bugs.py` (plan UPDATED)

The regex narrowing in `learn_from_bugs._INVARIANT_ID_RE` to `I-[A-Za-z0-9-]+-\d+` correctly matches `architectural_guidelines._INVARIANT_HEADING_RE`’s ID capture group and drops the `(?:INV|I)` alternation without widening `_INVARIANT_HEADING_RE`. That is the minimum fix for the reported `INV-*` vs `I-*` mismatch.

The proposed tests cover the indexer side well (`### I-Test-1` indexed, `### INV-Test-1` not). No existing test asserts `INV-*` rejection on the reader path (`parse_invariant_entries` / `read_invariants` in `architectural_guidelines.py`).

The gap is deliverable enforcement. Plan failure modes call out indexer-only tests as insufficient, but the firm test bullets only require `coverage_index()` assertions. Cross-parser comparison is under “if clean,” and reader-side `INV-*` coverage is optional via `MAY_UPDATE` `test_architectural_guidelines.py`. An implementer can close the bug in the indexer while leaving the reader contract unproven, which is exactly the drift the issue files.

**Suggested revision:** Require exactly one of: (a) parametrized cross-parser test in `test_learn_from_bugs.py` comparing `coverage_index()` with `parse_invariant_entries()` on the same fixture, or (b) a focused `INV-*` rejection test next to `test_invariants_present_file_emits_normalized_entries`. For parity cases, use `#{2,4}` headings only so tests do not conflate the pre-existing `#{2,4}` vs `#{1,6}` depth asymmetry with ID-prefix grammar.
