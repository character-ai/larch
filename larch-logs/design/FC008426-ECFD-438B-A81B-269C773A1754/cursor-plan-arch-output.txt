**1. [correctness]** Transient rerun must not block the fix loop (`plan.txt:44`, `scripts/ship-pr.sh:2500-2521`)

The plan says that when `transient_retries < CI_MONITOR_TRANSIENT_RERUN_MAX`, `evaluate_failure` runs `rerun_failed` and returns `no-changes`. Bash only returns early when rerun submission succeeds. If `ci-rerun-failed.sh` fails, bash records the failure and continues into the capped vendor-fix loop. Unconditional `no-changes` would skip that loop after a failed rerun.

**Suggested revision:** Return `no-changes` only when a new rerun was submitted (and treat `already_running` per existing budget rules); otherwise proceed to the outer `run_ci_fix` loop.

**2. [risk-integration]** `--failure-log` needs a compliant filesystem path (`plan.txt:40-41`, `scripts/launch-cursor-ci.sh:87-93`)

The plan threads redacted logs as `LogCollectResult.text` and refers to a “redacted path” for `build_launch_argv`, but launchers require an absolute, existing file under `IMPLEMENT_TMPDIR`. In-memory text or a path outside tmpdir will fail launcher validation.

**Suggested revision:** Add an explicit step in `run_ci_fix`: persist redacted logs to a temp file under `output_dir` or `IMPLEMENT_TMPDIR`, pass that path to `build_launch_argv`, and assert path rules in tests.

**3. [correctness]** Transient-network bails should map to `TRANSIENT`, not `STALLED` (`plan.txt:45`, `scripts/ship-pr.sh:3564-3565`)

The plan routes all non-exit-3 `bail` outcomes to `STALLED`. Bash classifies signatures such as `no valid output 3 times` via `is_transient_net_signature` and exits through the transient-net path (exit 6). `python/retry.py` already ports that classifier and is listed as a dependency, but `monitor` does not use it for bail mapping.

**Suggested revision:** In `monitor`, when `Decision.action == "bail"` and `retry.is_transient_net_signature(bail_reason)`, return `Outcome.TRANSIENT`; keep `STALLED` for non-transient bails only.
