**1. [correctness]** `read_failed_jobs` must filter failed conclusions (`plan.txt:30`, `python/gh.py:530-536`, `scripts/ci-failed-jobs.sh:72-73`). The plan says to parse JSON on `rc==0` via `gh.failed_jobs_read`, but bash and `gh.failed_jobs` only keep `conclusion=="failure"`. Without that filter, successful or cancelled jobs enter `classify_failed_jobs` and can mis-route the waterfall.

**2. [correctness]** `poll_ci` three-strike bail (`plan.txt:26`, `scripts/ci-wait.sh:200-209`). Bash bails after three polls with **no parseable** `CI_STATUS` from `ci-status.sh`, not three `CI_STATUS=error` values. `error` is handled immediately by `ci-decide.sh:79-84`. Line 112’s “3 consecutive `error`” test spec would encode the wrong behavior.

**3. [correctness]** `first-fixer-non-health` has two bash paths (`scripts/ship-pr.sh:2115-2122` pre-verify short-circuit; `2140-2167` post-stage HEAD unchanged). The plan and acceptance (`plan.txt:40,89,130`) emphasize only (B), while tests (`plan.txt:118`) require (A). `run_ci_fix` should return `first-fixer-non-health` on `agents.run_waterfall` `short_circuited` **without** requiring `stage_and_push`.

**4. [correctness]** Transient rerun failure fallthrough (`plan.txt:44`, `scripts/ship-pr.sh:2500-2514`). Bash continues into the `_max_fix=3` loop after a failed `ci-rerun-failed.sh`; the plan only describes returning `no-changes` on success. A failed rerun must not end `evaluate_failure` early.

**5. [risk-integration]** Missing detached-HEAD guard (`plan.txt:44`, `scripts/ship-pr.sh:2525-2530`). Bash aborts each outer attempt on detached HEAD before log collection; the plan never specifies this check.

**6. [correctness]** Jobs `in_progress` deferral vs bash (`plan.txt:44,89`, `scripts/ship-pr.sh:2567-2621`). Deferring when `read_failed_jobs` is `in_progress` while logs are `ready` is stricter than bash (which may still call `run_ci_fix_vendor`). Either document as intentional or match bash deferral on `gh-run-logs` rc=3 only.

**7. [OUT_OF_SCOPE] [architecture]** `CI_FIX_REBASE_PENDING` staging shortcut (`scripts/ship-pr.sh:2540-2565`) is not in `evaluate_failure`; Phase 7 driver state may need an equivalent for post-rebase staging.
