**1. [correctness]** `poll_ci` three-strike rule vs `ci-wait.sh` (`scripts/ci-wait.sh:200-216`)

The plan (`plan.txt` line 23, testing line 96) says **3-consecutive empty/`error` statuses → bail**. Bash increments `ci_failures` only when `CI_STATUS` is **empty** after parsing `ci-status.sh` output; on failure it forces `pending` and still calls `ci-decide.sh` until the third strike. A valid `CI_STATUS=error` line resets `ci_failures` and `ci-decide.sh` bails immediately (`scripts/ci-decide.sh:79-84`), not after three polls.

**Suggested revision:** Document and implement three-strike only for missing/unparseable status output; route `error` through `decide()` on every poll.

---

**2. [correctness]** Transient rerun failure fallthrough vs `run_evaluate_failure` (`scripts/ship-pr.sh:2500-2514`)

The plan (`plan.txt` lines 40-41, edge case 74-76) says when `transient_retries < CI_MONITOR_TRANSIENT_RERUN_MAX`, call `rerun_failed` only and **return `no-changes`**. Bash returns early only when `RERUN_SUBMITTED=true` (lines 2505-2511); otherwise it `record_failure` and **enters** the `_max_fix=3` loop (line 2514 onward).

**Suggested revision:** Return `no-changes` only after a successful or `already_running` rerun; on rerun failure, fall through to the fix loop like bash.

---

**3. [correctness / architecture]** One-shot log/job collection vs per-attempt loop (`scripts/ship-pr.sh:2522-2573`)

`monitor` is specified to call `gh.failed_jobs`, `classify_failed_jobs`, and `collect_failed_logs` once, then `evaluate_failure(...)` (`plan.txt` line 41). Inside `run_evaluate_failure`, each `_fix_attempt` re-invokes `gh-run-logs.sh` (2533) and, when logs are ready, `ci-failed-jobs.sh` (2573). Edge case 80 requires **rc=3 defer per attempt** (2567-2568), not a single upfront empty log for all three attempts.

**Suggested revision:** Re-collect logs (and refresh failed-job classification) inside `evaluate_failure`'s fix loop; surface an in-progress/defer outcome and backoff without running the vendor waterfall.

---

**4. [correctness]** In-progress log contract vs `gh-run-logs.sh` (`scripts/gh-run-logs.sh:51-53`)

The plan says in-progress → **empty/deferred** (`plan.txt` lines 27, 98). Bash still runs `tail -100` on the captured output and exits **3**. Fixing finding 3 matters more than tail content; tests that require empty strings would not match the shell helper.

**Suggested revision:** Model defer via rc=3 (or a typed defer flag); treat tail content as optional parity, not required empty string.
