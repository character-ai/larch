**1. [correctness] `gather_status` missing `gh pr checks` text fallback** (`plan.txt:24`, `scripts/ci-status.sh:145-174`)

The plan ports only the JSON `gh pr checks --json name,state,bucket,link` path. Bash falls back to plain-text parsing when JSON is empty or not an array. Without that fallback, `gather_status` can report `pending` or `pass` while checks actually failed, mis-routing `decide()` and the driver.

**2. [correctness] `rebase_then_evaluate` inserts `poll_ci` before fix** (`plan.txt:44`, `scripts/ship-pr.sh:3547-3549`)

Bash runs `run_rebase_rebump` and `run_evaluate_failure` back-to-back in one `ci-wait` handler. The plan returns `goto_rebase` only; the next `monitor()` begins with `poll_ci`, which may `wait` on pending CI for the full poll budget while bash would already be in `evaluate_failure` (including rc=3 log deferral). This is the largest behavioral gap relative to current `ship-pr.sh`.

**3. [correctness] `evaluate_failure` missing detached-HEAD guard** (`plan.txt:44`, `scripts/ship-pr.sh:2526-2530`)

Bash stalls before the fix loop on detached HEAD. The proposed `evaluate_failure` has no equivalent guard.

**4. [risk-integration] Empty `failed_run_id` not handled** (`plan.txt:44`, `scripts/ship-pr.sh:2497-2498`)

Bash `exit_stall`s when `FAILED_RUN_ID` is empty. The plan does not require a check before `evaluate_failure(run_id=...)`, risking useless gh calls and outer-attempt churn when link parsing fails.

**5. [OUT_OF_SCOPE] `CI_FIX_REBASE_PENDING` branch omitted** (`plan.txt:44`, `scripts/ship-pr.sh:2540-2565`)

Bash can stage and push pending CI-fix work without running the vendor waterfall. The Phase 6 plan does not mention this path; track for Phase 7 driver/state wiring.
