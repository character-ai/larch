### UPDATED: python/larch/report/final_report.py

Update `_architectural_guidelines_section()`.

Planned flow (reordered per accepted finding; mirrors `test_architectural_guidelines_section_happy_path_wins_over_drop_marker` for HEAD-mismatch recovery):

1. Read `head_sha` as today.
2. If `head_sha` exists, check `note_consumable()` as today.
3. If consumable, keep the current `note_fingerprint_stale()` check.
4. If consumable and not stale, render the durable note as today via `_read_consumable_architectural_guidelines_section()`.
5. If no section rendered, `not consumable`, and `note_readable_any_head()`:
   - read and render the durable note via `_read_consumable_architectural_guidelines_section()`;
   - if the rendered section is non-empty, call `clear_dropped_note_notice(implement_tmpdir)`;
   - do **not** call `_persist_drop_notice_and_invalidate()` on this path.
6. If no section rendered, read a persisted drop notice via `read_dropped_note_notice()` and format it as today.
7. If no section rendered, compute `staged_present`, `durable_present`, and `has_guideline_artifacts` as today.
8. If `has_guideline_artifacts` and (`not consumable` or `stale`), call `_persist_drop_notice_and_invalidate()` as today.

This ordering ensures:

- A pre-seeded or previously persisted drop marker does not win over a readable durable note when the only non-consumability reason is HEAD mismatch (e.g. post-merge `git checkout main`).
- Stale-marker recovery runs: fallback renders the note, clears the artifact, and skips invalidate.
- Genuine stale-fingerprint invalidation still runs when the note was consumable but stale (step 4 does not render; step 5 fallback is gated on `not consumable`; step 8 persists drop and invalidates).

## Edge cases

- **No current HEAD**: keep current behavior and return no architectural-guideline section.
- **Symlinked durable artifacts**: `note_readable_any_head()` must return false; fallback does not run; existing drop/invalidate behavior applies where applicable.
- **Readable durable note (any head) plus persisted drop marker**: when `not consumable` and `note_readable_any_head()`, render the durable note and clear the stale drop marker **before** reading the persisted drop notice (same precedence as `happy_path_wins_over_drop_marker`).
- **Persisted drop marker only, no durable note**: unchanged; step 6 renders the persisted notice.
- **Consumable but stale note**: step 4 does not render; step 5 fallback is skipped because `consumable` is true; step 8 still persists the drop notice and invalidates artifacts.
- **Post-merge pin guard without durable metadata**: do not skip based on incomplete metadata; fall through to existing best-effort pin behavior.

## Failure modes

- If the durable note cannot be read during fallback, render nothing and allow existing invalidation logic to proceed where applicable.
- If clearing the stale drop marker fails, do not fail final-report rendering. The helper already treats clear failures as best effort.
- If post-merge detection fails in closeout, the existing pin path may still return `"skipped"` because the fingerprint check fails on `main`; final-report fallback still prevents the false final-summary drop notice.
