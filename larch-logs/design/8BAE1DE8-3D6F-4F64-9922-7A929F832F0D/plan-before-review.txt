## Approach

Implement the fix in `/implement` review-and-fix only.

`round_runner._run_round` should keep using the degraded banner as the entry point, but split the retry path:

1. Parse the initial `core` dict and `review-core-threshold.env`.
2. Treat the degradation as pure per-item under-quorum only when all are true:
   - `UNDER_QUORUM_COUNT > 0`
   - `PARSE_FAILED_COUNT == 0`
   - `FAILED_SLOTS == 0`
3. For pure under-quorum, use the existing `degraded-retry.flag`, `degraded-retry.done`, and `voting-tally-degraded-attempt-1.md` preservation.
4. Build a restricted ballot from `findings.md` containing only IDs from `UNDER_QUORUM_ITEMS`.
5. Dispatch voters on that restricted ballot only.
6. Merge each new voter output after the original voter output for the same slot. `parse_judge_vote` keeps the last matching vote line, so the new per-item vote overrides the old under-quorum line while untouched items still use the original vote.
7. Re-run the tally on the full original ballot with merged voter files, so the final `voting-tally.md`, accepted file, rejected file, OOS artifacts, classification TSV, and counts reflect the whole ballot.
8. Update the in-memory `core` dict from the new tally result and recompute the same round status fields that `_run_round` uses downstream.
9. If the degradation is not pure under-quorum, keep the existing fresh-panel retry unchanged.

Keep the `/design` plan-review pipeline out of scope.

## Edge cases

- `UNDER_QUORUM_ITEMS` names an item not present in `findings.md`: fall back to the existing full retry before replacing final artifacts.
- Re-vote output is missing for one voter slot: merge the original file for that slot and let the final full tally decide whether degradation remains.
- Final full retally still has an under-quorum banner: preserve attempt 2 when it differs from attempt 1 and proceed best-effort under the existing single retry cap.
- Existing reviewer-slot warnings from `dropped-reviewer-attempts.env` must still surface when those paths use the full retry branch.
- Zero-findings degraded banners must keep the current skip behavior.

## Failure modes

- A targeted retally that writes only restricted-ballot artifacts could drop unaffected findings. Avoid this by retallying the full original ballot with merged voter files.
- A targeted path that overwrites `voting-tally.md` before preserving attempt 1 would lose audit evidence. Copy attempt 1 first.
- A targeted path that ignores `PARSE_FAILED_COUNT` or `FAILED_SLOTS` could mask real panel degradation. Gate on all three pure-under-quorum conditions.
- A targeted path that omits voter tools can break three-slot tally behavior. Reuse `VOTER_N_TOOL` from `review-core-voters.env`.
