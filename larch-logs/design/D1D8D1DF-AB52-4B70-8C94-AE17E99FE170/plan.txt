- **Operator action after successful merge**: write the non-filing record before cleanup. Preserve the tmpdir or mark it for preservation if the run log cannot be committed.
- **Terminal plus ledger**: file or print one terminal report. Do not file a second escalation report.
- **Terminal plus fallback evidence**: file or print one terminal report and include fallback evidence.
- **Terminal plus record-failure marker**: file or print one terminal report and include the marker.
- **Success plus empty ledger and no fallback evidence**: file nothing.
- **Success plus generic Tool Failure only**: file nothing.
- **Success plus tagged record-escalation Tool Failure**: treat as escalation evidence.
- **Success plus ledger**: Step 18a.5 files or prints one escalation-success report only when the canonical normalized outcome is a success outcome.
- **Success with `force-merged-externally` plus ledger**: Step 18a.5 files or prints one escalation-success report.
- **`admin_merged` state**: shared outcome helper maps it exactly as `write-final-report.sh` does today.
- **Invented success label**: Step 18a.5 skips unless mapped by the shared final-report outcome helper.
- **Success plus ledger write failure marker**: Step 18a.5 treats the marker as escalation evidence and does not silently skip.
- **Recovered stall plus ledger**: Step 7 defers. Step 18a.5 is the only success-with-ledger owner.
- **Terminal sentinel exists**: Step 18a.5 skips.
- **Escalation-success sentinel exists**: Step 18a.5 skips.
- **Any `STALL_TRACKING` source active**: Step 18a.5 skips.
- **Run did not satisfy canonical success outcome allowlist**: Step 18a.5 skips.
- **Missing attempts file on escalation success**: initialize or render zero-attempt history.
- **Missing classification file on terminal report**: fail closed before composition and log a Tool Failure.
- **Missing Tier B prompt-state supplement**: fail closed before Tier B composition and log a Tool Failure.
- **Consumer repo**: print Tier B report. Do not include client branch, paths, PR URL, issue body, plan text, or log tail.
- **Forked larch run**: treat as Tier B.
- **Tier A dev clone**: bypass TSV allowlist and redact the full public issue input, including verbatim bail reason.
- **Dry run**: write local dry-run body/input only. Do not call `/larch:issue`.

## Failure modes

- **Ledger write fails**: continue the run, write fallback evidence or a record-failure marker, append a tagged Tool Failure, and do not hide the original repair path.
- **Fallback evidence write also fails**: append tagged Tool Failure when possible. Step 18a.5 treats only the marker or tagged record-escalation Tool Failure as escalation evidence.
- **Generic Tool Failure exists after success**: ignore it for escalation-success eligibility.
- **Root-cause verdict is `operator-action` by mistake**: no public issue is filed. Finding remains in execution issues, operator-action artifacts, and run logs when available.
- **Post-merge cleanup would delete the only operator-action record**: preserve the tmpdir or mark it for preservation.
- **Tier B narrative leaks client data**: validator catches sentinel path, URL, plan, feature-description, execution-issues, state-file, attempt, log, ledger, fallback, run-log pointer, prompt-state supplement, repo, branch, and PR patterns. `SECURITY.md` documents residual heuristic risk.
- **Tier B validator rejects valid larch prose**: allowlisted larch operational tokens bypass raw-evidence substring rejection.
- **Unsafe title input**: reject unsafe title text, use only a validated root-cause summary, or fail closed.
- **Wrapper captures child stdout incorrectly**: Step 5 routing can break. Preserve stdout byte-for-byte except unavoidable ledger diagnostics.
- **Step 5 MAV KV fields drift**: prompt-side recorders can miss handoffs. Tests pin exact `STEP5_REVIEW_LEDGER_*` names.
- **Lint-fix KV fields drift**: prompt-side recorders can miss handoffs. Tests pin exact `LINT_FIX_LEDGER_*` names.
- **Python ship JSON keys drift**: Step 8 routing can miss handoffs. Tests pin exact ledger-ready JSON keys.
- **Python ship stdout gains extra lines**: Step 8 routing can break. Tests require exactly one JSON stdout object.
- **Terminal report tries to reuse old issue env**: avoid stale issue env. Terminal report owns fresh issue input and sentinel.
- **Helper lint drift**: `stall-recovery-report.sh lint` fails on TSV/code/doc mismatches and bail-token union drift.
- **Final outcome drift**: shared helper parity tests fail when `write-final-report.sh` success outcomes change.
- **Duplicate escalation record**: tests assert one ledger entry per escalation path.
- **Bash ship-pr starts recovery before prompt-side recording**: tests require handoff return before recovery waterfall or CI edits.
- **Bash Step 6 handoff keeps stall tracking active**: Step 18a.5 skips incorrectly. Tests require stall tracking false before Step 8+ resumes.
