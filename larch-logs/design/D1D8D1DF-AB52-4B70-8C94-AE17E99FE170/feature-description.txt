# auto-error-reporting: rework /implement failure reporting: terminal-only filing, mandatory root-cause, two-tier content

Part 1 of 3 of the auto-error-reporting rework. Part 2: #3991 (always file in the upstream larch repo). Part 3: #3992 (/design port).

#### Context

`/implement` Step 18a stall recovery auto-files issues that carry no actionable information; closed #3975 is the canonical example. Current behavior:

- **Files at first detection** (`attempt_count==0`), before any retry, and only for recoverable classes (`transient-infra`, `test-failure`, `lint-failure`, `dispatch-failure`, `ci-fix-exhausted`). Terminal classes (`contract-failure`, `unrecoverable`) never file, which is inverted: the failures most needing attention get no issue.
- **Bodies are allowlist-redacted to near-zero signal** (`stall-recovery-report-allowlists.tsv`): enums, a hash, and two fixed prose templates keyed by failure class. The classifier recognizes ~19 dispatcher bail tokens, but the render allowlist (`safe_bail_reason_value`) holds a mostly disjoint set of 14, so most real causes render as `redacted`. No run linkage (tracking issue, RUN_ID, branch, PR) is published.
- **No root-cause effort**: "Inferred root cause" is a canned one-liner per class (`root_cause_template`); no investigation happens.
- **No lifecycle**: successful recovery neither comments on nor closes the filed issue; self-healed transient blips still leave open issues (6 of 8 historical auto-filed issues were `transient-infra` noise). The terminal `bug-comment` repeats the body verbatim plus an attempt table.
- **Expensive script-to-main-agent escalations leave no trace**: when a script-owned repair loop (review loop, lint-fix loop, ship-pr CI-fix loop) fails to fix the problem it encountered and hands the work to the main agent, and the main agent then recovers, nothing is filed at all, even though that handoff is the expensive path that most needs root cause and a fix.

Key files: `skills/implement/references/stall-recovery.md`, `skills/implement/scripts/stall-recovery-report.sh` plus its sibling `.md` contract, allowlists TSV, and harness `test-stall-recovery-report.sh`, and the `SECURITY.md` section "Stall recovery sanitization".

#### Requirements (scope: /implement only; filing target unchanged, see #3991 for cross-repo)

1. **Terminal filing, all classes.** File on the terminal-failure path: retry cap exhausted, failed same-cause alternate, or a cap-0 class. Delete first-detection filing and the separate `bug-comment` surface; the single filed body carries the full attempt history. A successful recovery files no run-failure issue (escalation events are covered by requirement 2).
2. **Escalation-event reporting: file even on successful runs.** Track every script-to-main-agent escalation in a durable per-run ledger: a script-owned repair loop failed to fix the problem it encountered and bailed to the main agent. Covered /implement surfaces (exact enumeration pinned during design): the Step 5 review loop (`run-step5-review.sh` / review-and-fix bail), `lint-fix-loop.sh` `failed` / `main-agent-required` at the step3 / step5-self-review / step6 sites, ship-pr fix loops (`ci-fix-exhausted` and ship-pr-internal lint-fix bail), and Step 18a recovery dispatches that perform inline main-agent repair (including `step2-impl` inline implementation after dispatcher failure, the most expensive escalation). At teardown, when the ledger is non-empty and the run otherwise succeeded, file an escalation issue under the same root-cause, verdict, and tier rules; the root cause targets why the script loop failed, not the run outcome (the run succeeded). A run files at most one issue: a terminal failure absorbs the ledger as evidence. Rationale: main-agent recovery is very expensive even when it works perfectly; these events need root cause and fixes ASAP.
3. **Mandatory root-cause before filing.** Main Claude investigates before composing: read the validated failure-detail log, state files, attempts history, and escalation ledger; cite the durable evidence used; distinguish observation from inference and state confidence. Delete `root_cause_template` and `mitigation_template`. The finding includes a verdict: `larch-defect | environment | operator-action`.
4. **Skip filing on `operator-action` verdict.** Record the verdict and finding in chat and in `$IMPLEMENT_TMPDIR/execution-issues.md` (and the run log); do not file.
5. **Two-tier content policy.**
   - **Tier A (larch dev clone, `FORKED_TARGET=false`)**: drop the field allowlist; the only filter is `scripts/redact-secrets.sh`. Include run linkage (tracking issue, RUN_ID, branch, PR URL), verbatim bail reason, full attempt table, escalation ledger, the failure-detail log (already capped at 64 KiB), larch and tool versions, a pointer to the committed run-log directory, and the root-cause finding.
   - **Tier B (consumer repos and `--forked` runs)**: machine-composed, allowlist-bounded body, expanded to all larch-operational fields: the full bail-token enum rendered verbatim, step/phase, attempt table, escalation ledger (site and trigger tokens only), exit codes, dispatcher identity (codex/cursor/claude), matched classifier pattern, larch version, RUN_ID. Excluded as client data: client repo name, branches, file paths, plan text, issue titles/bodies, PR URLs, and log tails. The root-cause finding appears as one clearly bounded section written under a larch-internal-terms-only instruction (operational detail about larch itself is OK; data about the client repo is not).
   - `is-larch-dev-clone` selects the tier, not whether to compose. In this part, Tier B output still lands via the existing consumer chat-print path; cross-repo filing is #3991.
6. **Root-caused titles.** Replace `[Bug] /implement stall: <class> at <step>` with a title synthesized from the finding, keeping class/step as a suffix, and distinguishing terminal-failure reports from escalation-on-success reports (exact grammar is a design decision).
7. **SECURITY.md rewrite in the same change.** Replace the "never publishes raw logs/branch names/paths" guarantee with the two-tier contract; keep TSV and lint parity machinery scoped to Tier B; add a residual-risk paragraph for the Tier B narrative section (prompt-composed prose published on a public repo).
8. **Structure for reuse.** Parameterize the rewritten helper (state-file names, step/phase vocabulary, evidence sources, escalation-ledger location) so /design can adopt it in #3992 without a fork. No /design wiring in this part.

#### Resolved decisions

- Operator-error/induced terminal failures: skip filing (record only).
- Tier B log content: excluded in v1.
- Tier B root-cause narrative: included, as a bounded instruction-constrained section.
- SECURITY.md: rewritten in the same change, not a follow-up.
- Script-to-main-agent escalations file even when the run succeeds (cost signal; root cause the loop failure, not the run).

#### Acceptance criteria

- A run with no escalation events that succeeds files nothing and leaves no orphan issue.
- A run that succeeds after one or more script-to-main-agent escalations files exactly one escalation issue (subject to the `operator-action` skip), with the ledger and a loop-failure root cause in the body.
- A terminal failure of any class files exactly one issue absorbing the escalation ledger in a dev clone (or prints the Tier B report in a consumer repo), except `operator-action` verdicts, which only record.
- `test-stall-recovery-report.sh` updated; `stall-recovery-report.sh lint` parity holds for the Tier B allowlist.
- Reference and contract docs updated in sync.
