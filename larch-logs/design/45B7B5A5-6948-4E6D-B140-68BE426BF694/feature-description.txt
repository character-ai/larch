### Item 1 — Add premature-notification recovery carve-out to orchestrator-never.md
- **Location**: `skills/shared/orchestrator-never.md` (NEVER #3 / #4)
- **Source**: #4280, #4294
- **Severity**: latent
- **Description**: `orchestrator-never.md` NEVER #3 lists Monitor waits and backgrounded watcher loops with no carve-out for the sanctioned premature-notification recovery exception. `/implement` NEVER #8 documents the recovery, but agents that treat the shared file as the complete contract may still avoid the sanctioned single `until`-waiter recovery, or read it as conflicting with NEVER #4. Fix: add a carve-out to NEVER #3 (or a new NEVER #5) clarifying that a single re-launched `Bash run_in_background` condition-exit task (`until <condition>; do sleep N; done`) is the sanctioned recovery for a prematurely fired empty `<task-notification>` and does NOT violate NEVER #4 (which bans continuous polling loops, not a single one-shot re-launch).
