# Eliminate operator questions in issue partitioning process

Today, when /design or /implement run finds the issue to be too large, it asks user to partition or override (which is fine).  However, it then proceeds to ask a bunch of questions with waits in between about the details of the partitioning, and I don't think the user will particularly care.  Therefore, let's change to the following process:

When you decide that partitioning would be optimal (i.e., right before you currently ask the user to approve partitioning or overrule), also come up with (main agent, no subs) the optimal partitioning scheme, prioritized to minimize risk, and propose it to user as concrete choice 1, e.g., something like this:

1. let me partition the issue for you into K pieces as follows:
   part a: ...
   part b: ...
   ...
2. override and keep as a whole, but note the WARNING: ...
3. type something else:
4. chat

Further, if the user opts to partition, make sure, after you create all the new issues, to express dependencies between them within their own set as well as between each of them and the already existing issues using /block-issue.  Further, make sure to migrate any dependency relations that involved the original issue being partitioned.

In the end, I want the user to have to answer exactly 1 question.
