This keeps the hot path small and avoids a larger migration of `/design` guideline logic.

## Edge cases

- Missing repo root: `read_guidelines()` returns `absent`; `present-note` emits nothing on both assessment modes.
- Symlink, directory, unreadable, or escaping path: emit the helper warning and skip assessment.
- Present guidelines with empty parsed content: still mark assessment required on `pending`, because the file is present and the orchestrator can decide no deviations.
- `--assessment clean` must not print the clean note when guidelines are absent or invalid.
- `clean` + `present` must not leak path, content block, or assessment marker stdout.
- Step 1d.7 runs before `plan.txt` exists; deviation assessment must target `design-outline.md` only.
- Existing callers of `architectural-guidelines read` must see byte-compatible output.

## Failure modes

1. The references or `SKILL.md` still tell the orchestrator to derive the clean note itself or call `read` for presentation.
   - Signal: grep finds the fixed clean string in reference files outside helper-output examples, or Gate C skip-approve still mentions `read`.
   - Mitigation: replace those bullets with helper-driven flow; promote `SKILL.md` Gate C skip-approve to `present-note` deferral.

2. Step 1d.7 reuses the Gate C assessment target.
   - Signal: `design-outline.md` mentions `plan.txt` or "final plan" for deviation assessment.
   - Mitigation: bind assessment explicitly to `$DESIGN_TMPDIR/design-outline.md`.

3. `present-note` omits the untrusted content block on `pending`.
   - Signal: the orchestrator has a marker but no parsed entries to assess.
   - Mitigation: mirror the `read_main` present output before printing the marker.

4. `clean` mode prints a clean note after an invalid read, or emits extra machine rows on `clean` + `present`.
   - Signal: invalid-path or clean-present unit tests fail.
   - Mitigation: branch on `read_guidelines().status` before emitting the clean string; assert stdout equals the constant only.
