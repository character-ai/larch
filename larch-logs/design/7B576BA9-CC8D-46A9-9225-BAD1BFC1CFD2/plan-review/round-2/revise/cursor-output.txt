- Add an orchestrator-side best-effort stale-handoff clear immediately before **every** Step 8+ `step-8-ship.sh` background launch fence (initial `ship`, post-driver `reship`, ci-fix re-entry, conflict-resolution re-invoke, and other documented Step 8+ re-invoke paths). Use `rm -f "$IMPLEMENT_TMPDIR/.step-8-ship-handoff.rc" "$IMPLEMENT_TMPDIR/.step-8-ship-handoff.json" 2>/dev/null || true` in the same Bash block that invokes the wrapper, before `run_in_background` starts.
- Keep the Post-ship durable handoff fail-closed rule unchanged: absent rc after notification still means premature notification and end turn; present rc still means continue to `route-exit` in the same turn.

Revise NEVER #8 scoped recovery wording.

- Replace the blanket sentence that foreground terminal-sentinel probing is design-only and `/implement` recovery is notification-only.
- New scoped rule: Steps 3 and 5 (`implement-step3-checks`, `implement-step5-review`) remain notification-only with **no** sentinel probes; Step 8 alone uses one foreground non-sleeping `test -f "$IMPLEMENT_TMPDIR/.step-8-ship-handoff.rc"` at notification time, hook-allowed only while `implement-step8-ship` is live and clamped when rc stays absent.

## Edge cases

- **Stale rc sidecar on relaunch:** remove stale rc/json at orchestrator pre-launch and again at wrapper entry before arming the marker, or a reship/ci-fix re-entry could satisfy the rc probe with the prior run's sidecars.
- **Stale probe counter:** clear `bg-poll-guard-probe-denials.step-8-ship-handoff.rc.count` at wrapper entry so same-tmpdir reruns do not inherit a prior absent-rc clamp.
- **Setup failure before ship driver:** EXIT trap still writes rc fail-open and removes marker last.
- **Handoff write failure under `set -e`:** fail-open rc/json writes so marker removal always runs.
- **Python guard rc 4:** marker cleanup must not prevent existing stalled JSON sidecar behavior.
- **Symlink sentinel:** hooks must not treat a symlinked rc sidecar as completion.
- **Forged rc sidecar:** mutation verbs targeting `.step-8-ship-handoff.rc` must deny while the Step 8 marker is live.
- **Multiple live waits:** the rc probe allowance must bind to the live `implement-step8-ship` marker dir, including when another session tmpdir still has a different live marker.
- **Repeated premature notifications:** first rc probe stays allowed; repeated absent-rc probes are clamped once `probe_sentinel_name` resolves the Step 8 counter key; clamp counter clears when root-level rc appears.
- **Wrong clamp path:** using `.completed/step-8-ship-handoff.rc` would never see completion and would permanently deny the sanctioned probe after threshold.
- **Marker write failure:** ship-pr must continue. The hooks fail open because no marker exists.

## Failure modes

- If marker cleanup fails, hooks will reap it after PID death or timeout.
- If marker write fails, this change provides no hook coverage for that run, but ship-pr still proceeds.
- If stale rc cleanup fails at either orchestrator pre-launch or wrapper entry, the hook could see false completion. Use best-effort removal at both sites and test the normal relaunch case.
- If `probe_sentinel_name` does not recognize Step 8 rc paths, the clamp fail-opens and absent-rc probe storms remain uncapped.
- If `step8_handoff_probe_clamp` checks `.completed/` instead of tmpdir root, the clamp counter never clears on completion and NEVER #8 recovery is denied while ship-pr is still running.
- If the rc probe matcher is too broad, it may weaken the poll guard. Keep the matcher exact.
- If the rc probe matcher is too narrow, NEVER #8 recovery will be denied by the generic `$IMPLEMENT_TMPDIR` probe rule.
- If multi-live-marker binding is wrong, a legal Step 8 recovery probe can be denied while another bg-wait marker is live.
- If NEVER #8 still says notification-only for all `/implement` recovery, operators may skip the sanctioned Step 8 rc probe on premature notifications.
