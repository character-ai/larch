# [DEDUP] centralize the duplicated settle-wrapper rc dispatch table (design references)

**Problem.** The settle-wrapper return-code dispatch table (rc `0`/`1`/`10`/`11`/`12`/`13` → continue / retry / validator-escalation / pause / hard-size-prompt / split-path) appears **verbatim in two files**: `skills/design/references/approval-gates.md` (§Shared post-apply pipeline step 8) and `skills/design/references/discussion-rounds.md` (Round-2 body).

**Why this is not md-to-py.** The rc values are already owned by Python (`design_lifecycle.py` emits `POSTPLAN_RC=`). Each branch legitimately leads to an orchestrator-only action (AskUserQuestion, pause-exit, panel-dispatch), so the branch itself correctly stays in prose. The defect is the cross-file duplication, not in-prose logic. Filed separately from the md-to-py-IV umbrella for that reason.

**Proposed change.** Centralize the rc dispatch table in one canonical location (a shared reference snippet) and have both sites point to it so the wording cannot drift between files.

**Acceptance.**
- The rc dispatch table appears once; both callers reference the single source.
- No behavioral change.

**Notes.** Doc-hygiene, not a Python migration. Surfaced during the md-to-py-IV analysis but excluded from that prefix because it moves no logic into Python.
