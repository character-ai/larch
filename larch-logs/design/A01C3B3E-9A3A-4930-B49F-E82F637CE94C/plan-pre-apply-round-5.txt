## Edge cases

- `POST_DISPATCH_NEXT=bail` with a valid `BRANCH=` still bails; `ship-seed-input.env` is still updated when branch read succeeds.
- Missing or duplicated `POST_DISPATCH_NEXT` fails closed as `main-branch-post-dispatch`.
- Omitted `--expected-branch` on post-dispatch argv fails closed (argparse or bail token).
- `PHANTOM_*` and `COMMIT_SHA=` may appear before a post-dispatch bail.
- External implementer path keeps commit no-op (`noop`) when `ship-seed-input.env` has non-empty `MANIFEST_PATH`, even though the composite reaches the Step 4 leg.
- Pure `claude_fallback` without external launch must have prelaunch baseline before Step 2.4 edits; missing prelaunch blocks pathspec derivation.
- Ordinary Claude fallback requires fresh postlaunch capture + non-empty `implementation-commit-paths.nul` before composite launch; repair-loop re-entry must refresh postlaunch, pathspec, and commit message with `--tmpdir` and absolute paths.
- `step2-postlaunch-porcelain.nul` may be absent after ordinary `claude_fallback`; orchestrator and composite hooks must capture live porcelain at wire time, not assume dispatcher wrote it.
- Recovery mode keeps pre-composite `scope-check` on `$RECOVERY_PATHS_FILE`; composite captures fresh postlaunch, runs `recovery-paths` with `--repo-root` and `--tmpdir` after checks pass and before commit; final scope-check must pass on `step2-recovery-paths-final.nul` with absolute plan path.
- Post-checks recovery scope-check failure emits `BAIL_REASON=recovery-out-of-scope` and routes to Step 12d, not generic Step 18 stall.
- `implement commit` failure after checks pass emits `NEXT_ACTION=stall` with `STALL_STEP=4` / `BAIL_REASON=implementation-commit-failed` and skips 4.r.
- Rebase conflict on 4.r returns non-zero but still emits exactly one `NEXT_ACTION=continue`; orchestrator parses `CHECKPOINT_NEXT` and loads rebase routing (Step 6 parity), not Step 18.
- Q/A `--answers` redispatch must not duplicate Step 2 token/timing ledger rows from wrapper or `step2-dispatch`.
- Concurrent first dispatches must not double-mark telemetry: sentinel write occurs only after `dispatch.lock` held.
- `--rebase-checkpoint-4r` must not double-print `NEXT_ACTION=continue` (4.r leg owns the emit; outer composite suppresses).

## Failure modes

- Step 4 commit semantics can drift if `step4` reuses `review-and-fix commit-fixes --stage-all`. Mitigate with dedicated `_run_step4_commit_leg` and a regression test that step4 never invokes `commit-fixes`.
- Step 4 commit can fail argv parse if plan pins nonexistent `--message-file`. Mitigate by reading message files in-process and using existing `--message`.
- `CommitRouteOutcome` without `noop` breaks external no-op typing and pyright. Mitigate by widening the union and updating outcome allow-lists.
- Step 4 stall misclassification if `implementation-commit-failed` is omitted from config allowlists or `_run_step4_commit_leg` reuses `review-fix-commit-failed`. Mitigate with pinned token, `stall_step="4"`, config append, and pytest on seeded ship state.
- Pathspec derivation can be empty or stale if postlaunch porcelain is missing on ordinary `claude_fallback`. Mitigate with `_capture_postlaunch_porcelain` before every `recovery-paths` call and orchestrator refresh after repair edits.
- Pathspec can include pre-existing dirt if claude-fallback skips prelaunch capture. Mitigate with `run_dispatch_main` prelaunch write and pytest excluding untouched pre-dirt.
- Recovery-paths argparse fails if `--tmpdir` or absolute paths are omitted. Mitigate by pinning full argv in SKILL, helpers, and `checks-repair-loop.md`.
- Recovery commits can use stale pathspecs if composite skips fresh postlaunch before `recovery-paths`. Mitigate with `_run_step4_recovery_recompute` capture-then-recompute contract.
- Out-of-scope recovery deltas can reach checks if pre-composite `RECOVERY_PATHS_FILE` scope-check is dropped. Mitigate by keeping Step 2.4 orchestrator scope-check before composite launch.
- Duplicate orchestrator recovery-paths prose can double-run recompute or conflict with composite Step 4. Mitigate by deleting post-checks orchestrator sentences from Step 2.4 recovery sub-branch.
- Post-checks recovery scope-check failure can misroute to Step 18 if unpinned. Mitigate with `BAIL_REASON=recovery-out-of-scope` and SKILL Step 12d mapping.
- Step 3 anti-halt blockquote drift can cause double-commit or skipped 4.r. Mitigate by rewriting to Step 6 parity and anti-halt structure tests.
- `checks-repair-loop.md` Step-3-only continue rule can relaunch checks without commit/4.r. Mitigate by folding Step 3 into section 4 and pinning full composite argv in section 2.
- Optional `--expected-branch` weakens branch assertion. Mitigate with `required=True` and missing-flag pytest.
- Retired `step-2-entry` literals can break `make lint-retired-scripts` or plan-fidelity calibration. Mitigate by deleting both `.sh` and `.md`, registry removal, fragment-built paths in `test_residual_bash.py`, migrated-scripts rows, and fixture updates in the same change.
- Composite routing can lose 4.r conflict handling if orchestrator treats non-zero exit as invalid before reading `NEXT_ACTION=continue`. Mitigate with Step 6-parity parsing and structure tests.
- Double `NEXT_ACTION=continue` breaks single-line envelope parse. Mitigate by suppressing outer emit on `--rebase-checkpoint-4r` and pytest asserting exactly one `NEXT_ACTION=` line.
- Step 2 telemetry hoisted without lock/sentinel guard duplicates ledger rows on Q/A cycles. Mitigate by removing dispatcher timing mark, lock-gated once-only wrapper marks, and pytest.
- `rebase-checkpoint-routing.md` / structure-test needle mismatch on direct-probe fences can fail CI after doc unification. Mitigate by updating both docs and `test-implement-structure.sh` / `test-implement-rebase-macro.sh` needles together.
- Timeout budget can be too small if the rebase leg is added without increasing the outer fence timeout. Use `15600000`.
