## Implementation Plan — Issue #2586 (revised post-review)

Replace `/relevant-checks` skill invocation in `/implement` (and peer skills/scripts) with a direct invocation of `scripts/relevant-checks.sh` (consumer-repo top-level). Hard cutover in one PR.

## Approach

The wrapper helper `scripts/run-relevant-checks-captured.sh` stays as the orchestration boundary; only its hardcoded `CHECK_SCRIPT` target moves. The check script itself migrates out of the skill directory to `scripts/relevant-checks.sh`, the skill is deleted, and every caller's stdout-parser site learns about a new `RELEVANT_CHECKS_SKIPPED=true SITE=<site>` terminal state that replaces the current `STATUS=fail FAILURE_REASON=missing-check-script` envelope.

**Skip vs structural-failure distinction (revised per FINDING_1)**: The wrapper distinguishes "consumer has not configured local checks" from "consumer's script is broken." Absent file → skip with exit 0 + structured `RELEVANT_CHECKS_SKIPPED=true SITE=<site>` line. Present file that is not executable OR not a regular file → structured failure envelope `STATUS=fail EXIT_CODE=126 FAILURE_REASON=check-script-not-executable`. This avoids silent acceptance of a broken migration.

## Edge cases

- **Missing `scripts/relevant-checks.sh` in larch itself**: the new script IS created in this PR; running `/implement` on larch must continue to perform checks. Verified by /implement own dogfooding.

- **Present but non-executable**: per FINDING_1, this is now distinct from "missing." The wrapper emits a structured failure envelope (exit 126); harness coverage for both branches.

- **`PWD != CLAUDE_PROJECT_DIR`**: the wrapper `cd`s to `REPO_ROOT` (per FINDING_9) before invoking the check script. The check script's internal `git rev-parse --show-toplevel` then resolves under the intended tree. Harness regression covers this scenario.

- **Mid-PR state**: between commits, the working tree may have the new `scripts/relevant-checks.sh` AND the old `.claude/skills/relevant-checks/`. The wrapper after step 2 of "Order of edits" looks at `scripts/relevant-checks.sh` only; the old skill files are dead-weight but harmless until step 5 deletes them. No race risk because each Bash invocation is independent.

- **Pre-commit hook racing**: `git commit` triggers `pre-commit run` on staged files. Commit test retargets in the same commit or earlier commit as the deletion (step 4 before step 5 of "Order of edits").

- **Skip path on green-line callers**: any caller that branches on `grep -q '^RELEVANT_CHECKS_OK=true '` (currently 4 in ship-pr.sh, 3 in /implement SKILL.md, 1 in /review SKILL.md) would treat a SKIPPED line as failure if not updated. Mitigated by the in-PR update sites enumerated above; the refined verification gate at the end catches any survivor.

- **Larger banner change**: the rewrite is permitted to change banner literals only if the wrapper's coverage classifier is updated in lockstep AND every fixture-emitting test harness updates in lockstep. Recommendation: keep banner literals byte-identical to avoid this entire risk class; the rewrite is for comments and structure only.

- **`make lint` ordering**: `make lint` runs structural linters that may flag a renamed skill. Run `make lint` after each milestone in "Order of edits" to catch drift early; the final pass before PR must be clean.

- **Sandboxed permission rows**: `.claude/settings.json` lines 6 and ~184 are narrowly scoped to the deleted skill. The cleanup deletes both rows. Confirm the rows are exactly `"Bash($PWD/.claude/skills/relevant-checks/scripts/*)"` and `"Skill(relevant-checks)"` before deleting.

## Failure modes

1. **False-stall in ship-pr.sh on skip path** — caller mid-step records the SKIPPED line as a failure because the parser was not updated. Earliest warning: the test-ship-pr.sh new fixture asserting the skip path fails. Mitigation: add the ship-pr.sh `is_relevant_checks_clean()` helper + the 4 grep-site replacements + new test fixtures in the same commit as the wrapper's skip-emission update.

2. **Banner-string regression silently flips coverage classification** — a small rewrite of the new `scripts/relevant-checks.sh` changes a banner string, the wrapper classifier no longer matches, and `COVERAGE=...` reports the wrong value (or `WARN=agent-lint-missing` is no longer detected). Earliest warning: `test-relevant-checks-validation.sh` coverage-classification assertions fail. Mitigation: preserve the three banner strings byte-identical (the simplest path); if the rewrite changes them, update the wrapper's classifier in lockstep + add a banner-anchor grep assertion to `test-relevant-checks-validation.sh`.

3. **Downstream-consumer breakage on first invocation post-merge** — a third-party repo using larch as a plugin has `.claude/skills/relevant-checks/` but no `scripts/relevant-checks.sh`. After this PR merges, every `/implement` run on that repo silently skips local checks. Earliest warning: post-merge feedback from the downstream operator (no automated signal in this repo); the wrapper emits a stderr breadcrumb + machine line per FINDING_15 wording so observability is preserved. Mitigation: CHANGELOG.md entry clearly describes the migration step; SECURITY.md (per FINDING_7) documents the trust implication; OOS_1 tracks the broader downstream communication follow-up.
