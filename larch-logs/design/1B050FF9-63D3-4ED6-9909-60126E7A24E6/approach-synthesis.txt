## Architectural concerns surfaced

- **Parser-site survey is the load-bearing risk**. Every place in the runtime that parses wrapper stdout must learn about the skip line. Codex flagged ship-pr.sh; my grep confirms 4 sites there plus 3 in `/implement` SKILL.md and 1 in `/review` SKILL.md. The plan must enumerate each, with the exact replacement text.

- **Banner literals preservation is load-bearing**. The wrapper greps for 3 banner strings to classify coverage. The script rewrite (Round 1 Decision 6) must preserve them byte-identical, or the wrapper classifier updates in lockstep. Sketches and my reading both agree preserving the banners is the simplest path.

- **No new check categories**. The new `scripts/relevant-checks.sh` runs the same pre-commit + agent-lint phases the existing `run-checks.sh` runs.

- **Anti-halt invariant preservation**: `skills/implement/scripts/test-implement-relevant-checks-anti-halt.sh` must continue to assert that the orchestrator continues after `run-relevant-checks-captured.sh` returns. Migration must not weaken this assertion; if anything, it should add an assertion for the new `RELEVANT_CHECKS_SKIPPED=true` continuation path.

## Pragmatism / regression risk

- **Highest-risk regression**: parser-site false-stall on skip (per Codex). Mitigation: enumerate all parser sites in the plan; update each in lockstep with the wrapper's skip emission.
- **Test fixture risk**: harness setups must synthesize the new path. Mitigation: enumerate test harnesses with their fixture-creation lines.
- **Doc-staleness risk**: 58 files matched the initial grep. Mitigation: doc sweep is its own plan section, with a `grep` verification step in the acceptance criteria (no surviving `\.claude/skills/relevant-checks` or bare `/relevant-checks` skill references in live docs after the change; CHANGELOG.md gets a migration note).
