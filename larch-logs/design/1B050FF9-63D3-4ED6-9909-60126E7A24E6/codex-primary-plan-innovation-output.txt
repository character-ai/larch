A stronger cutover is still possible without breaking consumers: resolve new path first, old path second with a deprecation warning, and fail if neither exists unless the repo explicitly opts out.

2. **[risk-integration]** The hook deletion is premature for a hard cutover. Even if larch’s own prompts stop mentioning the Skill, consumer repos can still have project-local `/relevant-checks`; the hook is the only active-session guard preventing accidental raw Skill invocation.

3. **[architecture]** The plan creates the new script in this repo but does not provide a migration mechanism for other repos. For a required top-level consumer file, docs are a weak delivery channel; add a setup/upgrade detector or helper so consumers get a concrete path to compliance.
