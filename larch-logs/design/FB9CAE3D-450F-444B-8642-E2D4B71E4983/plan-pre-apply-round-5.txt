## Plan

**Approach**

- Scope this to **`/combine-issues --oos`**.
- Keep the **standard combine flow** unchanged.
- Add CLI verbs so the skill orchestrates tested Python graph logic instead of reimplementing it in prose.
- Use **direct native GitHub dependency APIs** for inherited edges.
- Fail closed when dependency reads, classification, approvals, or inherited writes are unresolved.
- Deduplicate all planned writes as **`(client_issue, blocker_issue)`**.
- Skip **self-edges** after source-to-combined remapping.
- Require operator approval for:
  - Any inherited or audit edge where a non-OOS open issue would be blocked by a newly combined **`[OOS]`** issue.
  - Every **Tier-2 semantic audit** edge, even if it appears safe.
- Partition deferred source closure by **combined issue host**.

**Sequence**

1. OOS skill fetches and validates OOS items as today.
2. OOS skill applies each approved group with **deferred source closure**.
3. OOS skill records **`source_issue -> combined_issue`** from apply output.
4. OOS skill records each new combined issue number and title.
5. OOS skill fetches **blocked-by** and **blocking** edges for all source issues.
6. OOS skill fetches the full paginated open-issue metadata set.
7. OOS skill runs **`combine-issues plan-inherited`** to remap, dedupe, classify, and produce initial per-source eligibility.
8. OOS skill writes safe inherited edges.
9. OOS skill surfaces inherited exception edges for operator approval.
10. OOS skill writes only approved inherited exception edges.
11. OOS skill runs **`combine-issues close-eligible`** to compute final source closure partitions from the inherited plan, decisions, and write results.
12. OOS skill closes only eligible sources, partitioned by their mapped combined issue.
13. OOS skill refreshes the full paginated open-issue metadata set for audit.
14. OOS skill runs Tier-1 prose audit with a concrete existing-edge dedup file.
15. OOS skill records best-effort Tier-2 semantic audit candidates in the same audit-candidate schema.
16. OOS skill runs **`combine-issues plan-audit`** to merge, dedupe, classify, and decide which audit candidates need approval.
17. OOS skill asks before writing audit exception edges and all Tier-2 edges.
18. OOS skill writes Tier-1 safe audit edges and approved audit edges.
19. OOS skill prints dependency summary counts and any sources left open.

**Edge cases**

- A source issue has no dependencies.
  - Emit empty lists and continue.
- Two source issues have the same dependency.
  - Write one edge.
- A source issue depends on another source issue in the same combined group.
  - Remap to the same combined issue and skip as self-edge.
- A source issue depends on a source issue in another combined group.
  - Remap both endpoints to their combined issues.
- A source issue blocks a non-OOS issue.
  - Treat as an inherited exception if it would make the non-OOS issue blocked by a new **`[OOS]`** issue.
  - Prompt before source closure.
  - Write only if approved.
- Inherited edge metadata is missing.
  - Mark classification unknown.
  - Do not write the edge automatically.
  - Do not close contributing sources.
- GitHub dependency API is unavailable.
  - Warn and continue with audit where possible.
  - Mark affected dependency reads failed.
  - Do not close affected source issues.
- Blocking-direction read endpoint is unavailable.
  - Emit an operator-visible warning.
  - Treat affected sources as dependency-read failures.
  - Fail closed for source closure.
- A dependency write already exists.
  - Treat existing idempotent success from **`issue add-blocked-by`** as success.
- Source closure fails after dependency writes.
  - Warn and keep summary honest.
- Eligible sources span multiple combined issues.
  - Close them in separate **`close-sources`** calls by combined issue.
- Audit proposes an already inherited edge.
  - Deduplicate before writing.
- Audit proposes a Tier-1 safe edge.
  - Write it after audit approval-required decisions are resolved.
- Audit proposes a Tier-2 edge.
  - Surface it as a proposal.
  - Write only if approved.
- Open archival issues exist.
  - Include them in the audit open-issue set.
- Prose says **`Blocks #N`** instead of **`Blocked by #N`**.
  - Convert to **`(#N, current_issue)`** when **`#N`** is in scope and open.
- Prose appears only in a comment.
  - Parse it the same way as issue-body prose.

**Failure modes**

- Native dependency reads may fail per issue.
  - Keep partial results.
  - Mark affected sources as not close-eligible.
  - Include warnings in the final dependency summary.
- Deferred closure can leave source issues open if dependency or close steps fail.
  - This is safer than orphaning dependencies.
  - Emit the remaining open sources.
- Inherited classification can lack metadata.
  - Treat it as unresolved.
  - Keep affected sources open.
- Inherited exception approval can be cancelled.
  - Do not write unresolved exception edges.
  - Do not close affected sources.
- Inherited exception approval can reject an edge.
  - Do not write the edge.
  - Record the rejection as an explicit decision.
  - Include it in the summary.
- Prose parsing can miss implicit dependencies.
  - Tier-2 skill review covers obvious semantic pairs best-effort.
- Tier-2 reasoning can be speculative.
  - Require explicit approval before writing every Tier-2 edge.
- Prose parsing can find stale references.
  - Check open state before proposing an edge.
- Audit exception approval may be skipped by operator cancellation.
  - Do not write unresolved approval-required audit edges.
  - Continue with Tier-1 safe audit edges only.
- Audit edge writes may fail.
  - Warn and count failures.
