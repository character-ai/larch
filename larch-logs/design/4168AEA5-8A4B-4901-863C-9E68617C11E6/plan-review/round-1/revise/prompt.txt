## Edge cases
- Manifest lost/corrupt mid-run → `load_or_recover_manifest()` rebuilds from run-dir contents; a flush never crashes.
- Merge `mergeStateStatus` UNKNOWN/empty → bounded retries (4 initial / 3 post-push) before classifying `error`.
- Flush commits push HEAD ahead of the PR OID → recover only when the extra commits are exclusively `chore(larch-logs):` flushes; force-with-lease on the expected OID, then re-probe; abort recovery if any non-flush commit is present.
- Version race → re-check origin/main plugin.json both before and after the OID precondition to narrow the TOCTOU window → `version_already_published`.
- `--forked` → never merge, never auto-close; OOS items are reported, not filed.
- `repo_unavailable` → local-only: skip PR create, push, merge, and remote upserts.
- Mermaid with unclosed frontmatter → fail-closed `rejected`; do not embed.
- Tracking-issue title over 256 chars after the prefix → truncate the user tail, preserve the prefix.
- Outbound redaction helper failure → fail-closed; never write an unredacted gh body.

## Failure modes
1. Silent double-merge or double-PR if idempotency regresses. Earliest signal: idempotency tests for `ensure_pr` and `already_merged`. Mitigation: ground-truth probes (`gh.pr_for_branch`, mergeStateStatus) before any mutation; assert no-op on re-run.
2. Unredacted secret or path reaches a public gh body. Earliest signal: redaction unit tests plus reuse of the `_body_file_args` choke point. Mitigation: all outbound bodies file-backed through `redact.redact`; fail-closed.
3. `flush_logs` skipped at a push/merge boundary → lost token/timing/exec-issue logs. Earliest signal: unit test asserting `merge_pr` flushes pre and post. Mitigation: a single `flush_logs()` entrypoint at every boundary; manifest `steps_ran` records coverage.
