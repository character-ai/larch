## Proposed Design Outline

### Goals
- Prevent same-user symlink tricks from redirecting the predictable state-file write in `hook-anti-read-poll.sh` to another writable file.
- Guard the state-file read against symlink-poisoned content.

### Non-goals
- Changes to other hook scripts (siblings use PID-qualified paths or already guard with `[ ! -L ]`).
- Changing hook warning thresholds, state format, or observable behavior.
- Adding Python or `larch.io` helper paths (hook is Bash-only; state file has no wire contract).

### Approach sketch
- Before reading `$state_file`: skip the read if `[ -L "$state_file" ]` (symlink guard, fail open).
- Replace the direct `>"$state_file"` write with: `mktemp` in the same `$state_dir`, write to the temp file, then `mv -f tmp "$state_file"` (atomic rename; replaces any symlink entry without following it).
- Cleanup the temp file on write or rename failure; exit 0 (fail-open contract preserved).
- Add one test case to `test-hook-anti-read-poll.sh`: place a symlink at the state-file path; verify the hook exits 0 and does not write through the symlink.
