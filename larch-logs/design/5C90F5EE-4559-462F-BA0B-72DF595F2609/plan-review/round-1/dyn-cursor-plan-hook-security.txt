### 1. correctness — `scripts/test-hook-anti-read-poll.sh` (proposed symlink regression)

The planned symlink test covers both invariants in principle: no reminder proves poisoned prior state was not trusted via the symlink read at ```55:57:scripts/hook-anti-read-poll.sh```, and unchanged target content proves the write path did not truncate through the symlink (today’s ```66:67:scripts/hook-anti-read-poll.sh``` `printf … >"$state_file"` behavior).

The gap is seed semantics. The counter only increments when `prev_path`, `offset`, and the 30s window all match at ```61:64:scripts/hook-anti-read-poll.sh```. If the test seeds `prev_count=2` with a stale `prev_time`, a broken implementation that still follows the symlink read will reset to `count=1` and stay silent. The test would pass without proving the read guard.

The plan’s state-path helper (cwd + session `cksum`, matching ```15:29:scripts/hook-anti-read-poll.sh``` and ```52:53:scripts/hook-anti-read-poll.sh```) is necessary but not sufficient. Spell out that the poison TSV row must use `path_hash` (not raw `file_path`), matching `offset`, `prev_count=2`, and `prev_time` within 30 seconds of the hook’s `HOOK_ANTI_READ_POLL_NOW`.

### 2. correctness — `scripts/hook-anti-read-poll.sh:53-67` (proposed promote)

Read hardening aligns with the repo’s `[ -f "$entry" ] && [ ! -L "$entry" ]` pattern (e.g. ```73:73:scripts/hook-deny-run-in-background.sh```). Temp-and-promote matches the ship-state contract in `SECURITY.md` (exclusive same-directory temp, no truncate-through-symlink).

The plan’s edge-case bullet on directory-like destinations is not wired into the implementation bullets. A bare `mv "$tmp" "$state_file"` when `$state_file` is a symlink to a directory can move the temp into that directory on macOS/Linux. Add explicit pre-promote handling: `rm -f` for symlinks, skip promote when a non-symlink directory occupies the path.
