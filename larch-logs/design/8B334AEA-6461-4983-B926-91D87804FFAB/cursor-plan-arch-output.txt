**1. [correctness]** `run_ship_pr_3134` stub contract for `LAUNCHER_EXIT`

The plan tells the harness to put `LAUNCHER_EXIT=0` in the `--output` file. `run_ci_fix_vendor` parses it from the launcher’s redirected stdout/stderr (`fail_file`), not from `--output`:

```1883:1884:scripts/ship-pr.sh
        launcher_exit=$(awk -F= '/^LAUNCHER_EXIT=/ {print $2; exit}' "$fail_file")
        launcher_exit="${launcher_exit:-0}"
```

Existing tier-order cases print `LAUNCHER_EXIT=0` to stdout (e.g. `scripts/test-ship-pr.sh:4389`). The new case should do the same.

**2. [correctness]** Guard `_stage_and_push_ci_fixes` before HEAD comparison

The plan adds HEAD equality only “after `_stage_and_push_ci_fixes` returns successfully,” but `run_ci_fix_vendor` today ends with an unguarded call:

```1922:1923:scripts/ship-pr.sh
    _stage_and_push_ci_fixes "$phase" "${ci_fix_out_base}.${winning_tier}.token-record" "$checks_site"
}
```

If staging/push fails, HEAD often stays at `baseline_head`; without an explicit `rc` check, the new branch could set `first-fixer-non-health` and exit 3 for a push/stage failure instead of a no-op vendor.

**3. [risk-integration]** `agent-lint.toml` companion update

The plan wires Makefile targets only. New lint scripts must join the `exclude` list beside `lint-bare-grep-probe` (`agent-lint.toml:878-881`) or `agent-lint` will flag them as unreachable dead scripts in CI.

**4. [correctness]** Test must seed `TRANSIENT_RETRIES=1`

`run_evaluate_failure` calls `ci-rerun-failed.sh` while `TRANSIENT_RETRIES < 1` (`scripts/ship-pr.sh:2205-2218`). Fix-loop vendor tests set `TRANSIENT_RETRIES=1` via state `awk` (e.g. `scripts/test-ship-pr.sh:4418-4420`). The plan’s new case should include that step so it reaches `run_ci_fix_vendor` deterministically.
