## Files to modify/create

### NEW: `scripts/lint-awk-multibyte-regex.sh`
Static lint that scans repo-wide `*.sh` and `*.awk` files for multi-byte UTF-8 characters inside dynamic awk regex contexts. Mirrors the `lint-bare-grep-probe.sh` skeleton: `--root PATH` flag (defaults to the repo root via `cd .. && pwd`), git-ls-files enumeration with `find` fallback for non-git roots, exit codes `0` clean / `1` violations / `2` CLI errors. Detects two patterns:

- **Rule 1 — `awk -v VAR=<value>` with non-ASCII byte in value.** Detected by scanning each line for an awk-invocation token (`awk` as a command word) followed by one or more `-v NAME=VALUE` arguments whose VALUE contains any byte outside `[\x00-\x7F]`. The matcher handles single-token (`-v VAR=val`) and split-token (`-v VAR =val`) forms, plus the multi-arg form (`awk -v A=x -v B=y '...'`). Continuation lines (trailing `\\`) join into the logical command before matching.
- **Rule 2 — non-ASCII inside an awk body at a regex callsite.** Detected by tracking the `awk` body span — between an opening `awk ... '` and the matching closing `'` (or, for heredoc form `awk ... <<'AWK' ... AWK`, between the opener and the close-delimiter line) — and flagging any line within the span that contains BOTH a non-ASCII byte AND one of the regex-callsite tokens: `match(`, `gsub(`, `sub(`, `split(`, ` ~ `, ` !~ ` (whitespace around `~` / `!~` to reduce false positives on identifiers like `~root`).

Same-line pragma `# lint-awk-multibyte-regex: ok <reason>` suppresses the flag, where `<reason>` is non-empty (the pragma without a reason is rejected to preserve grep-ability of suppressions, matching the `lint-bare-grep-probe.sh` convention).

Output one violation per finding to stderr: `lint-awk-multibyte-regex: <relpath>:<line>: <rule-id>: <snippet>` where `<rule-id>` is `awk-v-nonascii` (Rule 1) or `awk-body-nonascii-regex` (Rule 2). The snippet is the line content trimmed to 120 bytes with non-printable characters replaced by `?` (the byte position of the first non-ASCII run is preserved in the snippet for operator orientation).

Excludes: `node_modules/`, `larch-logs/`, `.git/` prefixes; symlinks; binary files (detected via `file --mime` heuristic on the first 4 KB).

Regression harness. Fixture cases under a per-test `mktemp -d`:

- **Suppression pragma with reason**: `awk -v label='テスト' # lint-awk-multibyte-regex: ok display-only` → exit 0.
- **Suppression pragma without reason**: `awk -v label='テスト' # lint-awk-multibyte-regex: ok` → exit 1.
- **Excluded prefix fixtures under `node_modules/` and `larch-logs/`** → exit 0 (not scanned).
- **Standalone `.awk` file** with a non-ASCII regex literal at a `match(` line → exit 1.

Each case asserts the lint exit code AND a specific needle in stderr (rule-id + filename:line where applicable). Assertions use `command grep -F` to avoid awk in the harness itself.

## Approach

Keep each surface change surgical:

- The lint reuses the `lint-bare-grep-probe.sh` skeleton (enumeration, scope handling, pragma grammar, exit codes). The only new logic is the two-rule textual matcher; awk is not parsed structurally — Rule 1 keys off the `-v NAME=VALUE` token shape and a non-ASCII test on VALUE; Rule 2 keys off a non-ASCII test conjoined with a regex-callsite token on the same line within an `awk` body span.
- The lint is wired into ALL enforcement surfaces consistent with `lint-bare-grep-probe`: `Makefile` lint umbrella, `.pre-commit-config.yaml` hook, `docs/linting.md` row, and `agent-lint.toml` allowlist. `scripts/relevant-checks.sh` picks the new lint up automatically via pre-commit.
- The ship-pr change reuses the existing `BAIL_REASON=first-fixer-non-health` plumbing (already wired in the cursor-launcher-failure path at line 1903 and in the Exit 3 router at line 2332). The new branch adds a HEAD-equality check gated on `_stage_and_push_ci_fixes` success; no new state keys, no new caller contract.
- The HEAD check is bracketed by an `if _stage_and_push_ci_fixes ...; then ... fi` so a stage-and-push failure propagates as `return 1` without setting `first-fixer-non-health`. The success branch ends in an explicit `return 0` so the function does not return the negation of the equality test by accident.
- The regression test uses the existing fix-loop harness scaffolding (`make_repo`, `make_tmpdir`, stub patterns) and mirrors `vendor_verify_local_pass`'s precondition seeding (`TRANSIENT_RETRIES=1`, `FAILED_RUN_ID=run3134`, `LARCH_QUIET_BREADCRUMBS=1`).
- Existing tier-order happy-path tests get a one-line modification each so the winning launcher actually advances HEAD; without this, the new no-commit detection would reroute those tests through first-fixer-non-health and fail their `rc 0` assertions.

## Edge cases

- **Heredoc awk bodies**: `awk '...' <<'AWK' ... AWK` and `awk ... <<-AWK ... AWK`. Initial scope recognizes single-quoted `awk '...'` bodies and standalone `.awk` files. Heredoc form is conservatively scanned: when the line containing `<<` is preceded by `awk` as a command word, the heredoc body lines up to the close-delimiter line are treated as the awk body for Rule 2 purposes. Detached heredocs (where the redirection is on a separate line from the `awk` invocation) are not in scope; the same-line pragma is the escape.
- **`-v VAR=$(command_substitution)` or `-v VAR="$shell_var"`**: VALUE here is the literal shell token, which the lint scans byte-by-byte. If a shell variable expands to non-ASCII at runtime, the lint cannot see it. The same-line pragma is again the escape for legitimate cases; the bug class we are catching is the embedded-literal case.
- **Multi-byte inside an awk-body comment**: Rule 2 only triggers when the line ALSO contains a regex-callsite token. A pure comment line with non-ASCII (e.g., `# em-dash — example`) does not trigger.
- **HEAD-non-advance check when the lint-fix-loop made commits independently of the vendor**: the comparison uses `git rev-parse HEAD` after `_stage_and_push_ci_fixes` returns. If lint-fix-loop staged and committed anything, HEAD advanced; the new branch does not fire. The detection fires only when nothing — vendor work, lint-fix-loop work, post-success cleanup — produced a commit.
- **HEAD-non-advance check when `_stage_and_push_ci_fixes` fails**: the wrapping `if _stage_and_push_ci_fixes ...; then` returns 1 without consulting the HEAD comparison, so stage/push failures (lint-fix failure, push rejection, etc.) propagate as ordinary vendor failure rather than misclassifying as first-fixer-non-health.
- **`baseline_head=unknown` (defensive)**: the equality branch does not fire; the success branch returns 0. The detached-HEAD guard in `run_evaluate_failure` (line 2227) already runs before `run_ci_fix_vendor`, so this branch is unreachable on the documented path; the check exists only to avoid silent misclassification if a callsite is added later.

## Non-goals

- **Detect `[[:class:]]` POSIX character classes in dynamic awk regex.** The original #3134 hypothesis pointed at mawk POSIX-class portability, but PR #3144 confirmed the actual root cause was multi-byte UTF-8 chars (em-dash) in dynamic patterns — applying the POSIX-class fix did not resolve the CI failure. Any future mawk POSIX-class portability concerns are deferred to a follow-up issue. The lint name (`lint-awk-multibyte-regex`) reflects the actual scope.
- Re-fix the upstream `lint-readability-preamble.sh` em-dash pattern — PR #3144 owns that. The new lint will catch any future regression of the same byte pattern.
- Add a mawk-vs-gawk CI smoke test. The failure mode is multi-byte handling per awk build, not "mawk uses different regex syntax." The new lint catches the source pattern at commit time.
- Strengthen the fixer prompt with a local-reproduce-and-iterate loop. The existing `LOCAL_REPRO` invariant in `launch-{cursor,codex,claude}-ci.sh` stays.
- Touch `_verify_failed_jobs_locally` or `lint-bash32.sh` semantics.

## Failure modes

1. **False positives from the new lint blocking unrelated PRs.** Earliest signal: a green-on-`main` working tree fails the new lint locally. Mitigation: Rule 1 keys off the awk-invocation token, not arbitrary `-v` substrings; Rule 2 requires both non-ASCII AND a regex-callsite token on the same line. The same-line pragma (with required reason) is the escape for legitimately non-regex non-ASCII (display strings, format args). Test fixtures include the printf-format false-positive guard.
2. **HEAD-non-advance detection misfires.** Earliest signal: a CI run that legitimately had nothing to fix gets classified as `first-fixer-non-health`. Mitigation: the detection is reachable only after CI was observed failing in `run_evaluate_failure`; the vendor is dispatched specifically because CI is red. If the vendor decides there is nothing to do and exits 0, escalation to the autonomous main-agent fallback IS the correct outcome — that path can fetch richer context and decide whether to bail with `design-flaw` or continue. The branch does not fire when `baseline_head=unknown` or when `_stage_and_push_ci_fixes` returns non-zero.
3. **Existing happy-path vendor tests trip the new no-commit branch.** Earliest signal: `make test-ship-pr-fix-loop` fails on the existing `ci_fix_vendor_tier_order_*` cases that currently assert `rc=0` despite the stub Cursor not modifying the tree. Mitigation: the test plan explicitly enumerates the audit-and-update of these sibling cases as part of `### UPDATED: scripts/test-ship-pr.sh`; the implementer must update them in lockstep with the ship-pr.sh change. Without the lockstep update, the test suite is the canary.
