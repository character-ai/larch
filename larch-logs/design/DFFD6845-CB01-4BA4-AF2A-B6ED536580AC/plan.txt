## Plan

### Overview

Four scoped components plus accepted review hardening:

1. **C1** — Delegate `/design` Step 2b plan drafting to a configurable Claude subprocess via new `scripts/launch-claude-drafter.sh`. The subprocess may research the repo only with side-effect-free tools; the launcher owns all writes under `$DESIGN_TMPDIR`. The orchestration keeps today’s inline Step 2b drafting path intact as the fallback.
2. **C2** — Route the always-on Claude voter through `LARCH_VOTER_MODEL` in `scripts/launch-claude-review.sh`, defaulting to `claude-fable-5`.
3. **C3** — Replace two stale fallback-reviewer `--model claude-opus-4-7` pins with `claude-sonnet-4-6`, and update voter documentation.
4. **C4** — Document the new drafter subprocess, prompt/data boundaries, model env vars, and dirty-tree backstop in security/config docs.

Accepted review revisions incorporated:
- no duplicate `design-postplan-emit.sh` entry point;
- drafter launch rc captured with `set +e` before fallback gating;
- drafter prompt embeds artifacts as redacted untrusted blocks;
- prompt includes resolved `design_classification` and full readability-style content;
- no new shared Step 2b contract file; inline drafting prose remains intact;
- delimiter parsing is whole-line, single-pair, fail-closed;
- JSON `.result` promotion uses scratch files and never clobbers authoritative status KVs;
- `.dirty-tree` sidecar guarantee starts only after output path canonicalization;
- pre-existing dirty trees and prelaunch failures do not block inline fallback;
- large-plan previews prefer fresh `plan-summary.md` with a mechanical freshness rule;
- drafter format/postplan failures can re-enter clean inline fallback once only;
- preview/harness updates target the live `skills/design/scripts/` paths.

### Files to modify/create

### NEW: `scripts/launch-claude-drafter.sh`

Read-mostly subprocess launcher for `/design` Step 2b plan drafting.

Accepted flags:
- `--model MODEL`
- `--prompt-file FILE`
- `--output-file FILE`
- `--timeout SECONDS`
- `--design-tmpdir DIR`
- `--repo-root DIR`
- `--timing-task-kind KIND` defaulting to `claude-plan-draft`
- optional `--baseline-porcelain FILE`

Security and validation:
- `--prompt-file` must be under `$DESIGN_TMPDIR` or `$PLUGIN_ROOT`.
- `--output-file` must be under `$DESIGN_TMPDIR`.
- `--design-tmpdir` and `--repo-root` must exist as non-symlink directories and be canonicalized with `pwd -P`.
- `--model` must be one non-empty token with no whitespace/control characters.
- Do **not** pass larch wrapper-only flags such as `--read-tools` or `--read-tools-add-dir` to the raw `claude` CLI.
- Production direct Claude argv uses verified native CLI flags only. Do not hard-code the `--allowedTools` shape until the pre-merge CLI probe confirms it. Launcher `CMD_JSON`, docs, and harness expectations must then match the proven shape exactly.
- Permit only side-effect-free discovery tools: `Read`, `Glob`, `Grep`, `LS`, or the probe-equivalent native allowlist.
- Deny `Write`, `Edit`, `Bash`, and mutating tools by omission plus `--permission-mode plan`.

Output/sidecars:
- Install the `.dirty-tree` `EXIT` trap **only after** `OUTPUT_CANON` has been containment-validated. Earlier argv/output-path validation failures may exit without a sidecar; Step 2b treats absent sidecar on no-launch/prelaunch paths as fallback-eligible.
- After trap installation, every exit path writes `${OUTPUT_CANON}.dirty-tree`.
- If subprocess never started: `STATUS=unknown MODE=prelaunch REASON=<validation-token>`.
- If subprocess ran and `--baseline-porcelain` was supplied/readable:
  - no delta vs baseline → `STATUS=clean MODE=baseline-delta REASON=claude-drafter-no-new-mutations`
  - delta vs baseline → `STATUS=dirty MODE=baseline-delta REASON=claude-drafter-new-mutations`
  - git/status failure → `STATUS=unknown MODE=baseline-delta REASON=git-status-failed`
- If no usable baseline exists:
  - empty current porcelain may report `STATUS=clean MODE=absolute`
  - non-empty current porcelain reports `STATUS=unknown MODE=no-baseline`, not confirmed dirty.
- `CMD_JSON` in `${OUTPUT_CANON}.meta` records exact native argv.
- `${OUTPUT_CANON}` remains authoritative status KVs only; never overwrite it with promoted prose.
- `${OUTPUT_CANON}.stderr`, `.stderr-tail`, `.failure-diag`, `.done`, `.meta`, and `.dirty-tree` are contract sidecars.
- Any `${OUTPUT_CANON}.json` or promoted-result scratch file is transient and deleted after parse. Do not introduce a persistent `.result` sidecar.

JSON/delimiter handling:
- Parse `--output-format json` with parity to `launch-claude-subprocess.sh`.
- Fail closed on invalid JSON, `is_error`, missing/non-string/empty `.result`, or 0-byte promoted result with exit 0.
- On JSON-envelope failure, write a clear `CLAUDE_JSON_RESULT_INVALID` diagnostic, use exit code `99`, set status `STATUS=ERROR`, and skip token-ledger recording.
- Extract from scratch `.result` text using exact whole-line sentinels:
  - `^LARCH_PLAN_BEGIN$` / `^LARCH_PLAN_END$`
  - `^LARCH_SUMMARY_BEGIN$` / `^LARCH_SUMMARY_END$`
- Reject missing, duplicate, nested, reversed, or unbalanced plan sentinels.
- Allow the delimiter names inside plan prose when not on exact sentinel lines.
- Empty extracted plan body is an error.
- Atomically write `$DESIGN_TMPDIR/plan.txt`.
- Atomically write `$DESIGN_TMPDIR/plan-summary.md` only when summary sentinels are present and extracted body is non-empty.
- Validate final plan has a trailing `diff_lines: <N>` line before reporting structural success.

Status KVs in `${OUTPUT_CANON}` include at minimum:
- `STATUS=OK|ERROR`
- `PLAN_WRITTEN=true|false`
- `PLAN_LINES=<N>`
- `DIFF_LINES=<N>`
- `SUMMARY_WRITTEN=true|false`
- `DRAFTER_LAUNCHED=true|false`

Token/timing:
- Add launcher-local token provenance before `token-ledger.sh record-vendor`:
  ```bash
  case "$TIMING_TASK_KIND" in
      *draft*) TOKEN_RAW=claude_draft ;;
      *scout*) TOKEN_RAW=claude_scout ;;
      *voter*) TOKEN_RAW=claude_vote ;;
      *)       TOKEN_RAW=claude_review ;;
  esac
  ```
- Record tokens as `token-ledger.sh record-vendor claude_sub ... raw="$TOKEN_RAW"` only after JSON promotion and delimiter extraction succeed.
- Record timing as vendor `claude` with task kind `$TIMING_TASK_KIND`.
- Do not add token provenance logic to `timing-ledger.sh`.
- Emit `STATUS`, `OUTPUT_FILE`, and `ELAPSED` via `emit_kv`.

```bash

  _plan_mtime=$(stat -f '%m' "$design_tmpdir/plan.txt" 2>/dev/null || stat -c '%Y' "$design_tmpdir/plan.txt")

  fi
```

### Approach

- Keep the existing inline Step 2b drafting path intact to reduce scope and preserve known orchestration duties.
- Add a subprocess-first path that drafts `plan.txt` and optional `plan-summary.md`; fallback reuses today’s inline drafting.
- Build the drafter prompt from the existing Step 2b requirements plus full readability-style content, resolved tier, and redacted untrusted input blocks.
- Keep all filesystem writes launcher-owned and `$DESIGN_TMPDIR`-confined.
- Use probe-proven native Claude CLI argv only.
- Treat `.result` promotion as scratch parsing; `${OUTPUT_CANON}` remains status KVs.
- Use one postplan entry point. Drafter success proceeds to the retained terminal postplan fence rather than invoking it directly.
- Prefer generated `plan-summary.md` for all large-plan preview surfaces only when freshness is mechanically proven by mtime.
- Delete `plan-summary.md` on any inline fallback that will rewrite `plan.txt`.
- Use baseline-delta dirty-tree semantics: block only confirmed new mutations after drafter launch.
- Permit postplan-driven inline fallback at most once via `.step2b-postplan-inline-retry-done`.
- Apply the voter model change at one role-based launch point.
- Align fallback reviewer pins and docs with the cheap Sonnet fallback decision.
- Retarget preview work to the live `skills/design/scripts/` renderer and harness already called by Step 3 and Gate C.

### Edge cases

- **Prelaunch validation failure**: no sidecar may exist; inline fallback allowed.
- **Pre-existing dirty tree**: does not block fallback or success unless a new baseline-delta mutation is detected.
- **Baseline capture failure**: omit `--baseline-porcelain`; do not treat absolute dirt as confirmed drafter mutation.
- **Malformed JSON/result**: fail with `CLAUDE_JSON_RESULT_INVALID`, no token row, inline fallback if eligible.
- **Malformed delimiters**: fail closed; no partial plan success.
- **Plan mentions delimiter names in prose**: accepted unless they appear as exact whole-line sentinels.
- **Missing final `diff_lines:`**: structural failure or postplan failure; clean inline fallback if eligible and once-only guard permits.
- **Large plan without summary**: structural failure for drafter success; fallback inline if eligible.
- **Stale generated summary at Step 3/Gate C**: mtime older than `plan.txt` → ignore and use synthetic outline.
- **Inline fallback after drafter or postplan failure**: delete `plan-summary.md` before rewriting `plan.txt`.
- **Second postplan failure after inline retry**: sentinel blocks another inline fallback; route to existing validator-failure / abort path.
- **Pause requested**: every new drafter bash fence honors the pause prelude.

### Failure modes

1. **Drafter timeout/crash/spawn failure**: `_drafter_rc` captured; inline fallback when dirty-tree eligible.
2. **JSON envelope invalid or model rejection**: status error, diagnostics, no token row, inline fallback when eligible.
3. **Delimiter/format failure**: no structural success; inline fallback when eligible.
4. **Postplan validation failure from drafter plan**: one inline fallback when dirty-tree eligible and sentinel absent; sentinel write prevents infinite re-entry; second failure uses existing terminal postplan failure routing.
5. **Confirmed new mutations**: recovery prompt; no inline fallback until clean re-check.
6. **CLI allowlist syntax mismatch**: pre-merge probe updates launcher and tests to proven native syntax.
7. **Prompt artifact contains secrets/instructions**: artifacts are redacted and wrapped as untrusted blocks before entering subprocess prompt.
8. **Stale `plan-summary.md` after plan rewrite**: preview ignores stale summary via mtime rule; inline fallback deletes summary before rewrite.
