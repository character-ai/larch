## Work item 1. Append six guideline entries to `ARCHITECTURAL_GUIDELINES.md`

Append each entry immediately after the last existing entry in its family, so it sits with its siblings. Match the existing bullet shape exactly: a `- Why:` line, an optional `- Guidance:` line, and a `- Deviate when:` line. Every entry below has a real `Deviate when:` clause so it passes `python3 python/cli.py lint guideline-no-exception`. Do not change any existing entry.

### 1a. After `G-Wire-2`, append `G-Wire-3`

```markdown
### G-Wire-3: Sweep every consumer of shared machinery, not only the consumer that surfaced the bug
- Why: a feature or fix that changes a shared renderer, a shared status converter, or a shared committed-artifact writer was repeatedly completed for one consumer while a sibling consumer sharing the same machinery was left unswept, so the fix silently no-op'd or misbehaved on the unswept surface (#5940, #6578, #6668, #6632, #6027).
- Guidance: when a change touches a renderer, status converter, parser, or artifact writer that more than one consumer shares, enumerate the sibling consumers by grep in the same change, update each one, and add a regression test for at least one consumer other than the one that surfaced the bug.
- Deviate when: a sibling consumer is provably unreachable for this change because it is guarded behind a flag that is off; record that fact, with the sibling list, in the PR description.
```

### 1b. After `G-Ext-3`, append `G-Ext-4`

```markdown
### G-Ext-4: Run every postcondition guard on the external-CLI success path that you run on the failure path
- Why: an external tool that exited 0 with a self-reported complete status was accepted without the quota check that ran on its non-zero exits, and a toolless agent's self-reported verdict was trusted with no proof it read its evidence, so a success-path branch skipped a guard the failure path ran (#6826, #6671).
- Guidance: for every external-CLI invocation, list the postcondition guards run on the non-zero exit path and run the same guards on the zero-exit and self-reported-success path; treat a vendor self-reported terminal status as untrusted until re-verified.
- Deviate when: a guard is gated on a signal that cannot occur on the success path by construction, for example a check that only runs for non-zero exit codes; name that reason in a code comment.
```

### 1c. After `G-Md-2`, append `G-Md-3`

```markdown
### G-Md-3: Track fenced-code-block state when parsing Markdown headings from splitlines
- Why: a parser that matched heading regular expressions over Markdown splitlines, with no fence state, split items on `###` lines that appeared inside fenced code blocks, because heading-like text inside a fence was indistinguishable from a real heading (#6676).
- Guidance: any parser that matches a `^#{1,6}\s` heading regular expression over `text.splitlines()` first computes the set of line indices inside balanced fenced code blocks and skips heading matches on those lines; reuse the `_balanced_fence_line_indices` helper in `python/larch/issue/issue_create.py` rather than re-deriving fence state.
- Deviate when: the parser documents that it intentionally reads headings inside fenced code blocks, which no current parser does.
```

### 1d. After `G-CLI-2`, append `G-CLI-3`

Match the exact casing of the existing `G-CLI-1` and `G-CLI-2` headings (uppercase `CLI`).

```markdown
### G-CLI-3: Parameterize the reason and attribution of an abort or error verb
- Why: an abort verb hardcoded the single current caller's operator-facing banner and log attribution, so every other abort routed through it inherited the wrong reason and reported a healthy state as unhealthy (#6796).
- Guidance: an abort or error verb takes its operator-facing reason and its log tool or exit-code attribution as parameters, defaulting to today's values for backward compatibility, and never hardcodes the single current caller's message; callers that abort for a different reason pass their own.
- Deviate when: the verb has exactly one caller by design and the hardcoded message is the only possible reason; record that fact in the verb docstring.
```

### 1e. After `G-IO-2`, append `G-IO-3`

```markdown
### G-IO-3: Return an existing absolute path unchanged from a path-rebase helper
- Why: a path-rebase helper re-anchored a valid, existing absolute path from the system `$TMPDIR` into a non-existent path, which broke session-transcript capture on every run after the migration because a same-host absolute path was treated as foreign (#6263).
- Guidance: a path-rebase helper returns an existing absolute path unchanged instead of re-anchoring it under a different root; when the input is absolute and the file exists, or the input already lies under the real system `$TMPDIR`, return it as-is.
- Deviate when: the helper documents that it deliberately relocates paths into a sandbox root, and the relocation target is guaranteed to exist before the call.
```

### 1f. After `G-Obs-5`, append `G-Obs-6`

`G-Obs-4` is currently unused in the file. Do not reuse it. Append as `G-Obs-6`.

```markdown
### G-Obs-6: Compute report column widths and bar offsets from the global maximum, not a per-row constant
- Why: a report renderer that aligned rows started each bar at a fixed offset instead of the longest row label plus one, which misaligned every row in the chart (#5587, #5753).
- Guidance: a renderer that aligns multiple rows computes column widths, bar start offsets, and bar lengths from the maximum across all rows in the render pass, not from a per-row value or a hardcoded constant; compute the maximum in a first pass, then render.
- Deviate when: the renderer draws a single row, so there is no cross-row maximum to compute.
```

## Work item 2. Append the `I-Commit-1` invariant to `ARCHITECTURAL_INVARIANTS.md`

Append the entry under the `## Run-log integrity` section, immediately after `I-Flush-1`. Match the existing invariant shape: a heading, prose paragraphs, an `Evidence of violation:` sentence, and a `Mechanical backing:` sentence. Invariants have no `Deviate when:` clause. Do not change any existing invariant.

```markdown
### I-Commit-1: A committed run-log field embeds its content, never a pointer into a session-tmpdir file

A field written into a committed run-log artifact under `larch-logs/` either embeds the redacted content it needs downstream or omits the field. It never stores a path into the session or system tmpdir (for example `$TMPDIR`, `IMPLEMENT_TMPDIR`, or `/var/folders/...`). A reader of a committed run log must be able to adjudicate the run from the committed artifact alone, without reaching into a session tmpdir that no longer exists. Evidence of violation: rejected and neutral finding bodies were absent from committed logs and survived only as pointers into session-tmpdir files that were never staged, so post-hoc adjudication could not evaluate whether a rejection was sound (#6027). Mechanical backing: a commit-time scan of staged `larch-logs/` content for session- and system-tmpdir path prefixes, with a failing check that rejects the commit; extend the run-log flush path that already stages redacted bodies so every voted finding commits its body through the existing redaction pipeline.
```

## Work item 3. Scaffold three mechanical lints

Each lint is an independent scaffold. For each, mirror the structure of `python/larch/lint/lint_tempfile_dir.py` (module with a `SUPPRESSION` constant, a `main(argv) -> int` entrypoint, argparse with `prog="cli.py lint <name>"`, baseline regen support only if the lint is baseline-backed) and the test structure of `python/tests/lint/test_lint_tempfile_dir.py`. Register each lint in the dispatch table in `python/larch/cli.py` (the dict whose rows look like `("lint", "tempfile-dir"): ("larch.lint.lint_tempfile_dir", "main"),`). Add a `make lint-<name>` target, a `make test-lint-<name>` target, and wire the lint into `py-lint-checks-fast` and the pre-commit hook set, following `docs/linting.md`. Do not merge until `make py-lint` and `make lint` are green.

### 3a. Lint `markdown-heading-fence-state` (backs #6676; enforces G-Md-3)

- Module to create: `python/larch/lint/lint_markdown_heading_fence_state.py`.
- CLI: `python3 python/cli.py lint markdown-heading-fence-state`.
- Registration row to add to the dispatch table in `python/larch/cli.py`: `("lint", "markdown-heading-fence-state"): ("larch.lint.lint_markdown_heading_fence_state", "main"),`.
- Test to create: `python/tests/lint/test_lint_markdown_heading_fence_state.py`.
- Surface scanned: `python/**/*.py` production modules (skip tests, `conftest.py`, helper files, symlinks, cache, vendored, virtualenv, mirroring the scoping rule used by `lint_subprocess_via_runner`).
- What it flags: a module that compiles a regular expression matching `^#{1,6}\s` (a Markdown heading), and matches or searches it over the result of `.splitlines()` on text, without consulting a fenced-code-block line-index set in the same module. Treat a module as compliant if it imports or defines a fence-line-index helper (for example `_balanced_fence_line_indices`) and gates heading matches on it.
- False-positive risk: a parser that intentionally reads headings inside fenced code blocks. Expected to be none today.
- Suppression: same-line `# lint-markdown-heading-fence-state: ok <reason>` on the regex declaration.
- Baseline policy: run the lint once on the current tree. The known prior violator (`parse_issue_input` in `python/larch/issue/issue_create.py`) now tracks fence state via `_balanced_fence_line_indices`, so it should pass. If the scan finds zero violations, ship with no baseline (hard ban). If it finds any, add `python/markdown-heading-fence-state-baseline.json` with one reason-bearing row per violation and a `make regen-markdown-heading-fence-state-baseline` target, and the baseline must only shrink.

### 3b. Lint `self-disarmable-gate` (backs #6542; mechanically enforces invariant `I-Gate-1`)

- Module to create: `python/larch/lint/lint_self_disarmable_gate.py`.
- CLI: `python3 python/cli.py lint self-disarmable-gate`.
- Registration row to add: `("lint", "self-disarmable-gate"): ("larch.lint.lint_self_disarmable_gate", "main"),`.
- Test to create: `python/tests/lint/test_lint_self_disarmable_gate.py`.
- Surface scanned: the gate and hard-trigger surface, scoped to `python/larch/design/plan_quality.py` and any sibling module under `python/larch/design/` that emits a size or publish trigger. Keep the surface narrow to hold precision.
- What it flags: a gate or hard-trigger function that reads a plan-meta field authored by the drafting model (the set includes at least `diff_added` and `mechanical_churn`, and should be read from the plan-meta dataclass in `python/larch/design/`) to suppress, replace with precedence, or fully disarm a hard trigger condition. A gate that uses author-declared meta as an OR-combined input, never to suppress, is compliant.
- False-positive risk: a gate that legitimately reads author meta for a non-suppression purpose. Keep detection scoped to suppression and disarm patterns.
- Suppression: same-line `# lint-self-disarmable-gate: ok <reason>`, naming the gate owner.
- Baseline policy: issue #6542 is closed and its fix direction was to OR-combine the diff signals and demote `mechanical_churn` to a presentation softener. Run the lint on the current tree. If the legacy suppression channels are gone, ship with no baseline (hard ban on reintroduction). If any self-disarm channel remains, add `python/self-disarmable-gate-baseline.json` with one reason-bearing row per channel and a regen target, and the baseline must only shrink.
- Note: this lint is the mechanical backing that graduates `I-Gate-1` from a human-readable invariant to an enforced check. State that link in the module docstring.

### 3c. Lint `unreachable-branch` (backs #6153; lower priority)

- Module to create: `python/larch/lint/lint_unreachable_branch.py`.
- CLI: `python3 python/cli.py lint unreachable-branch`.
- Registration row to add: `("lint", "unreachable-branch"): ("larch.lint.lint_unreachable_branch", "main"),`.
- Test to create: `python/tests/lint/test_lint_unreachable_branch.py`.
- Surface scanned: `python/larch/**/*.py` production modules (same scoping rule as 3a).
- What it flags: an `if` or `elif` branch in a function whose condition was already made unreachable by an earlier unconditional `return` of the same value, or by an earlier branch that always returns, in the same function body. This is the shape of the dead second `if bundle.mechanical_verdict:` branch in `_final_verdict` that #6153 left behind.
- False-positive risk: low and structural. The lint may overlap general Python tooling such as pyright or pylint `unreachable`; if so, document the overlap in the module docstring and prefer the narrower AST check that targets the returned-value-equivalence shape.
- Suppression: same-line `# lint-unreachable-branch: ok <reason>`.
- Baseline policy: this lint likely finds existing dead code across the tree. Ship with `python/unreachable-branch-baseline.json` as a reason-bearing shrinking baseline and a `make regen-unreachable-branch-baseline` target. Do not hard-ban on first run.
