## Findings

### 1. correctness — `python/larch/implement/architectural_assessment.py:860-891`
The plan registers `implement.architectural_assessment` and calls `next_untried_tier`, but the coordinator CLI never reads tool presence. `external_defaults._available` and `next_untried_tier` need `codex_present` / `cursor_present` (see `python/larch/core/external_defaults.py:73-118`). Other implement paths source those from session env via `_binary_flag` in `python/larch/implement/checks_lint_fix.py:164-244`. Without that wiring, missing Codex/Cursor may not be skipped pre-launch, breaking the edge case that unavailable binaries must not consume another tool's attempt.

**Suggested revision:** Read `CODEX_BINARY_FOUND` / `CURSOR_BINARY_FOUND` from `$IMPLEMENT_TMPDIR/session-env.sh` (with the same `_binary_flag` fallback pattern) and pass them into lane selection before any launch.

### 2. correctness — `python/larch/agents/_review_launcher.py:823-831`, `python/larch/implement/architectural_assessment.py:741-816`
Reusing `launch-review` changes the wire shape. Today `run()` expects assessment JSON on subprocess stdout (`architectural_assessment.py:807-817`). Codex writes `--output-last-message` to a file; Cursor wraps prose in a JSON `.result` field (`_review_launcher.py:645-654`). Codex auth preflight can return process exit `0` while `launcher_exit` is non-zero (`_review_launcher.py:823-831`). The plan's fail-closed rule and single-attempt mode are insufficient unless per-lane adapters normalize vendor output into the existing `LaunchResult.stdout` contract and use `resolve_launcher_exit` (`python/larch/agents/_launch_failure.py:140-159`).

**Suggested revision:** Add an explicit per-lane adapter step: resolve launcher exit from output sidecars, extract assessment JSON text, then feed that string to `_parse_results_independently`; treat resolved non-zero launcher exit or empty extracted text as lane-unavailable.

### 3. risk-integration — `skills/implement/scripts/step-8-assessment.sh:11-12`, `python/larch/core/external_defaults.py:126-128`
Same-lane retry removal increases wall-clock need per attempt. Current `BUDGET_S=2100` matches one `_TIMEOUT_SECONDS`/`FIXER_LANE_TIMEOUT_SEC` lane (1800s) plus 300s overhead (`step-8-assessment.md:29-33`). A Cursor→Codex→Claude waterfall needs `len(order) * FIXER_LANE_TIMEOUT_SEC` (5400s for three lanes) before overhead. `fixer_lane_budget_sec` already encodes that formula (`external_defaults.py:126-128`; tested for other roles at `python/tests/core/test_external_role_defaults.py:227-238`). Under-budget bgjob timeout looks like tool exhaustion and can still force `architectural-assessment-unavailable` operator-bail after only one or two lanes.

**Suggested revision:** Pin `BUDGET_S` to `fixer_lane_budget_sec("implement.architectural_assessment") + <adapter overhead>` (shared constant), update `step-8-assessment.md` and `test-step-8-assessment.sh` pins together, and add the new role to `test_fixer_lane_budget_reserves_a_full_timeout_per_configured_tier`.

Per-kind pending-set semantics, mixed-response handling, violation/deviation stop, `re-author-required` non-advance, deferred `_persist_unavailable`, preserved `ASSESSMENT_RESULTS` grammar, and operator-bail via `dispatch_ship.py:343-397` are all aligned with the issue. The `[BUG]` replay is covered by the planned waterfall tests reproducing empty stdout advancing to the next lane.
