## Plan

## Approach

- Add one shared scoring module surface in `python/voting.py`: severity constants, attribution splitting, and `accepted_finding_points_from_severities`.
- Use **panel-assessed `vN_severity` only** (never `body_severity`).
- Define **one** two-tier in-scope rule and use it everywhere (helper, tally scoreboards, Top reviewers, docs, prompts, tests):

  **Severity input set:** For each finding, collect `vN_severity` only from voter slots where the paired `vN_vote` is `YES`. Ignore `NO`, `JUDGE_ERROR`, and empty votes. Ignore empty or invalid severity tokens (`_SEVERITY_VALUES` minus `uncertain`).

  **Points:**
  - `+2` when the finding is accepted in-scope **and** at least one valid YES-voter severity is high (`blocker`, `major`).
  - `+1` for all other accepted in-scope cases (all ordinary, all missing/invalid among YES voters, any `uncertain`, or high mixed with no valid high token after filtering).
  - `0` neutral/exonerated.
  - `-1` rejected in-scope.
  - OOS stays flat: accepted `+1`, neutral `0`, rejected `-1`.

- **Score column** sums weighted accepted in-scope points; **Accepted** and other count columns stay unweighted.
- **Pruning stays unweighted:** do not change `python/review_pipeline.py` accepted-minus-rejected count math or `PruneRoundCounts`.
- **`_write_yield_tsv`** stays on unweighted accepted/rejected counts.
- **Top reviewers:** prefer per-round `findings-classification.tsv` weighted aggregation for **both** `/design` and `/implement` when any completed round has classification data; use `review-findings-full.jsonl` flat accepted-count fallback only when no classification TSV exists.
- **Top reviewers in-scope filter:** exclude rows with `scope=oos` explicitly; when the `scope` column is absent, fall back to `finding_id.startswith("OOS_")`. Only attribute accepted rows with `scope=in_scope` or legacy in-scope ids (no `scope` column and non-`OOS_` id).
- **Code-review OOS:** do not infer in-scope weighting from `OOS_` prefix alone at read time. Emit an explicit `scope` column at classification write time using the same `is_oos` / kind logic as tally scoreboards; TSV scoring treats `scope=oos` as flat OOS.
- **Legacy no-scope TSVs:** when the `scope` column is absent, treat accepted rows as flat `+1` (do not severity-weight); keep `OOS_` prefix and `scope=oos` as explicit OOS signals.
- **Attribution split rules (critical):**
  - **Emitted TSV `reviewer_slots` column:** pipe-split via `column="reviewer_slots"`.
  - **Emitted TSV `finding_reviewers` column:** label-aware tokenization via shared `tokenize_finding_reviewers` (comma segments plus whitespace tokenization; same semantics as `review_pipeline._tokenize_plan_finding_reviewers`).
  - **Inline tally-time raw proposer strings** (comma-delimited ballots, not yet normalized to pipes): comma-split or `tokenize_finding_reviewers`; **never** pipe-split raw proposer cells. Reserve `column="reviewer_slots"` for cells produced by `_reviewer_slots_for_tsv` or read from TSV.
- **Human attribution label vocabulary (critical):** `tokenize_finding_reviewers` requires a non-empty set of **display labels** (e.g. `Cursor-Pragmatic`, `Codex-Arch`), not manifest output basenames (`cursor/plan-requirements`) or slot ids. Every design `finding_reviewers` call site must build labels from an explicit source before `split_classification_attribution`.
- **Implement display-label mapping (critical):** code-review `reviewer_slots` TSV cells contain manifest output basenames (e.g. `cursor-specialist-...`). After pipe-split, map each token through `_progress_label_map` / `_progress_derived_label` before summing Top reviewers points so implement reports match existing jsonl-path display labels. Design `finding_reviewers` keeps human-label tokenization only; do not apply basename label maps to design cells.
- **Schema docs stay aligned:** bump classification TSV column counts everywhere the wire schema is documented (`docs/voting-process.md`, `docs/run-logs.md`, `skills/shared/voting-protocol.md`) so committed run-log consumers see the trailing `scope` column contract.

## Edge cases

- **Missing severity ratings:** accepted in-scope → `+1`.
- **Single high YES severity:** accepted in-scope → `+2` (works in one-judge degraded panels).
- **Mixed high/ordinary among YES voters** (e.g., 2 `major` + 1 `minor`): `+2` when any valid YES high remains.
- **NO-voter severities:** excluded from weighting math entirely.
- **Invalid severity tokens:** ignored; if no valid high remains among YES votes → `+1`.
- **Accepted OOS with high panel severities:** flat `+1` via `scope=oos` / `OOS_` prefix.
- **Legacy code-review `FINDING_N` with `[OUT_OF_SCOPE]`:** compute `is_oos` before row emit → `scope=oos` → flat `+1`, never in-scope `+2`; Top reviewers skip via `scope=oos` even without `OOS_` id prefix.
- **`_scope_drift` rows:** `is_oos` before emit → `scope=oos`; excluded from Top reviewers.
- **`effective == 0` degraded panel:** same `is_oos` + `scope` append as main loop; no short rows.
- **Whitespace-separated design `finding_reviewers`:** requires non-empty human label vocabulary from prune label map / panel manifest / voter tool labels; `tokenize_finding_reviewers` credits each matched label.
- **Empty label vocabulary:** fallback to `plan_review_round._slot_human_label` on manifest slots; never use manifest output basename map for design tokenization.
- **Raw comma proposer at tally time:** comma/`finding_reviewers` split; pipe split only on TSV `reviewer_slots` or post-`_reviewer_slots_for_tsv` cells.
- **Top reviewers with jsonl + TSV:** TSV wins when any round has classification data.
- **Legacy TSV without `scope` column:** accepted rows flat `+1`; `OOS_` prefix still flat OOS and excluded from Top reviewers via prefix fallback.
- **Implement Top reviewers display labels:** pipe-split `reviewer_slots` basenames, then map each through `label_map` / `_progress_derived_label` before aggregation.
- **Stale schema docs:** run-log readers that still assume 21/22 columns without `scope` mishandle OOS rows and column alignment; keep `docs/run-logs.md`, `docs/voting-process.md`, and `voting-protocol.md` in sync with `python/voting.py` headers.

## Failure modes

- **Accidentally using `body_severity`:** tests include high `body_severity` with ordinary panel severities → `+1`.
- **Pruning changes by accident:** no weighted fields in `PruneRoundCounts` or `review_pipeline.py` count aggregation.
- **Inline scoreboard still flat:** `review_tally` stats loop must sum `accepted_weight`, not `row["accepted"]`.
- **Pipe-splitting raw proposers:** under-credits co-proposers; tests cover comma ballot vs TSV pipe cells separately.
- **OOS scope emit ordering:** `is_oos` after row write leaves `scope=in_scope`; tests cover `[OUT_OF_SCOPE]`, drift, and `effective == 0`.
- **Top reviewers OOS leak:** filtering only `OOS_` prefix lets `FINDING_N` + `scope=oos` rows inflate in-scope leaderboard; `_classification_row_in_scope` must check `scope` column first.
- **Implement raw basename labels:** omitting `_progress_label_map` normalization on `reviewer_slots` shows `cursor-specialist-...` in Top reviewers instead of `Cursor/...` display labels.
- **Standalone header drift:** `_CLASSIFICATION_HEADER` missing `scope` misaligns DictReader consumers.
- **CI harness stale field count:** `test-findings-classification.sh` hardcoded 21/22 columns fails after header bump.
- **Legacy no-scope over-scoring:** absent `scope` column must not apply severity weighting.
- **Tuple shape regressions:** update every `score_rows` consumer in `review_tally.py` and `plan_review_tally.py`.
- **Tokenizer divergence:** leaving `_tokenize_plan_finding_reviewers` in `review_pipeline.py` after adding `voting.tokenize_finding_reviewers` causes prune vs scoreboard attribution drift.
