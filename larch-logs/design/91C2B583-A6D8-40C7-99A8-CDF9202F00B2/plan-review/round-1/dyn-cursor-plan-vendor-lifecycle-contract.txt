## Findings

1. **correctness** (`python/larch/agents/_review_launcher.py:1251-1263`): Cursor read-only and workspace-write modes are not distinguished by sandbox flags alone. Production uses `--mode ask` for read-only review and `--force` for workspace-write paths. The plan should name those tokens explicitly and test both argv shapes.

2. **correctness** (`python/larch/agents/_review_launcher.py:1123-1144`, `1295-1302`): The planned `run_vendor_launch` order runs usage before postprocessing. Cursor records usage after postprocess normalizes the JSON envelope. Shared usage-before-postprocess would break that contract on migration.

3. **correctness** (`python/larch/agents/_claude_runner.py:375`, `python/larch/agents/_ci_launcher.py:1037-1047`): Claude read-only and workspace-write argv differ in invocation flag (`--print` vs `-p`), flag order, and `allowedTools` grants. The plan needs separate builders and full-list tests for each shape.

4. **architecture** (`python/larch/agents/agents.py:19-27`, `python/larch/agents/_claude_runner.py:61-63`): The import ban should also exclude the `agents.py` barrel and `_claude_runner.py`, with tests proving `_vendor.py` does not transitively load launcher modules.
