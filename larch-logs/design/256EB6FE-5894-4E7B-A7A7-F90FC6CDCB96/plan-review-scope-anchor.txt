# Wire voter calibration score to a consequence (close the calibration loop)

Phase IV follow-up to the reviewer point-competition overhaul. Phase III umbrella: #5459 (closed). Cornerstone of Phase III was #5461.

## Problem

Phase III's cornerstone #5461 shipped a voter **Calibration Score** but wired it to **no consequence**. It is diagnostic-only, so it cannot change voter behavior.

Evidence in `main` after #5461 (PR #5492):

- `calibration_score` is computed in `python/voting.py` (`compute_voter_severity_distribution`) and consumed **only** by the severity scoreboard render (`format_voter_severity_table`) and the `/voter-calibration` report.
- `grep "standing"` over `python/` returns nothing — "voter standing" is prose, not a mechanism.
- No reference to calibration in voter dispatch, voter prompts, panel selection, spawning/pruning (`python/review_pipeline.py`), token allocation, or reviewer/proposer points.
- #5461's own plan said so explicitly: *"Do not add token allocation, spawning changes, or persistent rewards."*

**Why this blocks the goal.** The voter panel is ephemeral LLM agents with no memory across runs. A score computed *after* they vote and shown on a scoreboard no agent reads cannot change voting behavior. So #5461's real acceptance criterion — *"Measurable drop in panel High Rate over the subsequent corpus"* — is structurally unreachable by what shipped. Phase III repeated Phase II's pattern: it measured and surfaced the signal but wired no consequence. The incentive loop the umbrella set out to close is still open.

## Goal

Turn the measured calibration signal into an actual incentive, so calibrated severity tagging becomes the behaviorally dominant strategy for the voter panel and panel `High Rate` measurably falls.

## Options for /design to evaluate

- **A. Prompt feedback (lowest risk).** Inject each voter tool's recent `High Rate` / `Calibration Score` into its voter prompt as calibration feedback ("your recent YES-severity distribution is N% blocker/major; reserve those tags for findings that truly gate"). This is the only option that reaches an ephemeral agent before it votes.
- **B. Panel weighting / outlier handling.** Down-weight or drop chronically-uncalibrated voter tools from panels. Caution: the code-review panel is fixed (`v1`=cursor-validity, `v2`=codex-plan-fidelity, `v3`=codex-pragmatism); dropping a slot degrades the panel and trips the degraded-panel tier. Any weighting must keep quorum semantics intact.
- **C. Allocation coupling.** Fold the voter calibration signal into a consequence once token allocation (#4771) unblocks. Gated behind the ground-truth GO; lowest near-term leverage.

## Acceptance

- A measurable drop in panel `High Rate` over the subsequent incentivized-era corpus, validated via `/voter-calibration`. This is the #5461 criterion that the display-only score cannot satisfy.
- `make lint && make py-lint && make py-test`.

## Guardrails

- Keep panel severity **judge-set**. Do not re-expose proposer-controlled `body_severity` (gameable).
- Keep the change surgical. Reuse `compute_voter_severity_distribution` / `severity_calibration_score`.
- Do not ship token allocation (#4771) before `docs/ground-truth-verdict.md` records a human GO. The verdict is currently NO-GO.

## Dependencies

Builds on #5461 (Calibration Score, landed). Relates to #4771 (token allocation, gated NO-GO) and the ground-truth verdict machinery from #5464. No live blocker.

## Proposed Design Outline

### Goals
- Add opt-in pre/post incentive-era segmentation to `/voter-calibration`, comparing panel `High Rate` and `Calibration Score` before vs after the incentive shipped.
- Make the #5461 acceptance signal (a post-incentive High Rate drop) directly readable from the tool.

### Non-goals
- No change to default (no-flag) output. Today's single report stays byte-identical and backward compatible.
- No change to agreement/severity math, reviewer/proposer points, spawning, thresholds, tokens, or live verdicts. The tool stays diagnostic-only.
- No hard GitHub dependency. Offline use stays first-class via `--era-since-date`.

### Approach sketch
- Add `--era {all,pre,post}` and `--era-since-date YYYY-MM-DD` to `voter-calibration.py`.
- Tag each discovered TSV with its run `manifest.json` `started_at` at discovery time; per-finding rows carry no date. Reuse `_ground_truth_run_started_at_strict` + `_ground_truth_run_dir`, or a thin `python/voting.py` helper.
- Resolve boundary: explicit `--era-since-date` wins; else best-effort `gh` auto-detect of the incentive close date; else a clear "boundary unavailable" fallback.
- Render pre vs post agreement + severity scoreboards side-by-side for `--era all`; filter to one corpus for `--era pre|post`.
- Update SKILL.md, the `voter-calibration.md` contract, and the test harness; document the acceptance readout path.

- `skills/voter-calibration/SKILL.md`
- `skills/voter-calibration/scripts/test-voter-calibration.sh`
- Optional thin era-tagging helper in `python/voting.py`
