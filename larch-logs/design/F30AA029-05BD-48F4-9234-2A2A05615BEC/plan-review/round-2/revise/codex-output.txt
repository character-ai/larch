```bash
  set -euo pipefail
  _lib_round_cap_usage() {
    printf 'usage: lib-implement-round-cap.sh --count-prior-degraded <IMPLEMENT_TMPDIR> <current_round>\n' >&2
    exit 2
  }
  case "${1:-}" in
    --count-prior-degraded)
      [ "$#" -eq 3 ] || _lib_round_cap_usage
      case "$3" in
        ''|*[!0-9]*) _lib_round_cap_usage ;;
      esac
      [ "$3" -ge 1 ] || _lib_round_cap_usage
      count_prior_degraded_rounds "$2" "$3"
      ;;
    *)
      _lib_round_cap_usage
      ;;
  esac
fi
```

### Approach

Keep scope narrow. Item 1 is fixed in the wrapper, not the Step 0 caller. Item 3 adds one output key plus harness/doc wiring. Item 4 avoids prompt-side shell reimplementation and avoids timing-rehydration count drift by folding banner computation and printing into the already-existing Step 5 invocation fence.

### Edge cases

- `CLAUDE_PLUGIN_ROOT` already set: wrapper leaves it unchanged.
- Wrapper derivation fails: empty value reaches the existing guard and aborts loudly.
- `USAGE=` appears only for usage failures, not I/O failures.
- Round `1` returns `0`; non-integer or non-positive rounds exit 2.
- Step 5 banner values are not prompt-side variables; the Bash fence prints the complete banner before launching the loop.
- Sourcing `lib-implement-round-cap.sh` remains inert.

### Failure modes

- If the wrapper forgets `export`, child bootstrap still cannot resolve plugin-rooted paths.
- If Step 5 banner math is placed in a separate Bash fence, computed variables are lost before prompt-side banner prose.
- If a new Step 5 fence adds another plugin-root guard or tmpdir export, `test-implement-timing-rehydration` may fail.
- If `USAGE=` is inserted before `ERROR=`, existing parsers expecting `ERROR=usage:` first may regress.
- If the new harness sibling `.md` files are not added or excluded, script-md-siblings or agent-lint can fail.
