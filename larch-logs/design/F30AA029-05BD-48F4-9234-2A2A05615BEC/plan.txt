### UPDATED: `scripts/lib-implement-round-cap.sh`
Item 4. Append a direct-execution block at the end, guarded so sourcing stays side-effect-free. Do **not** add top-level `set -euo pipefail`; keep the existing shebang and `count_prior_degraded_rounds` sourcing behavior byte-unchanged.

```bash
if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
  set -euo pipefail
  _lib_round_cap_usage() {
    printf 'usage: lib-implement-round-cap.sh --count-prior-degraded <IMPLEMENT_TMPDIR> <current_round>\n' >&2
    exit 2
  }
  case "${1:-}" in
    --count-prior-degraded)
      [ "$#" -eq 3 ] || _lib_round_cap_usage
      case "$3" in
        ''|*[!0-9]*) _lib_round_cap_usage ;;
      esac
      [ "$3" -ge 1 ] || _lib_round_cap_usage
      count_prior_degraded_rounds "$2" "$3"
      ;;
    *)
      _lib_round_cap_usage
      ;;
  esac
fi
```

`--count-prior-degraded <tmpdir> <round>` prints `count_prior_degraded_rounds` for that round (the Step 5 banner passes round **1** → 0 on a fresh run). `<round>` must be a positive integer, else usage error exit 2. Bash 3.2 compatible.

## Approach

Each item is the minimal edit the approved outline allows. Items 1 and 3 are in-place insertions that preserve existing output/guards. Item 4 moves a tested shell computation behind a CLI so the orchestrator stops re-authoring glob/loop bash in the prompt; the SKILL.md edit stays prose-only to avoid touching pinned Step 5 fence counts. Repo conventions: every touched `.sh` keeps a sibling `.md`; the new Makefile-only harness is registered in `agent-lint.toml`; the item-4 CLI argv and item-3 new flag-surface get same-PR harness coverage.

## Edge cases

- Item 1: `cd` failure → empty `CLAUDE_PLUGIN_ROOT` → unchanged `:?` abort (broken layout still fails loudly). An already-exported value is left untouched (`-z` guard).
- Item 3: `USAGE=` is added only on the `fail_usage` (exit 1) class; exit-2 I/O errors keep their existing two-line output.
- Item 4: round `0` and non-numeric round are usage errors (exit 2). Round `1` returns `0`. Sourcing the lib must remain inert.

## Failure modes

- **Item 1 over-broad derivation**: if the wrapper were ever invoked from outside the plugin tree, `dirname "$0"/..` could mis-resolve. Mitigation: derivation fires only when `CLAUDE_PLUGIN_ROOT` is unset, and the `:?` guard plus the child `"${CLAUDE_PLUGIN_ROOT}/scripts/implement-bootstrap.sh"` path surface a bad root immediately.
- **Item 3 parser regression**: a consumer parsing the first `ERROR=` line could mishandle the new `USAGE=` line. Mitigation: `USAGE=` is appended after `ERROR=` on its own key; the `ERROR=usage:` contract is unchanged. Warning signal: harness assertion on the three-line envelope.
- **Item 4 sourcing regression**: a malformed guard could run the CLI (and `exit 2`) at source time, breaking `run-step5-review.sh` / `review-and-fix.sh`. Mitigation: the `[[ "${BASH_SOURCE[0]}" == "${0}" ]]` guard plus the "sourcing stays inert" harness assertion. Warning signal: Step 5 loop aborts at source.
