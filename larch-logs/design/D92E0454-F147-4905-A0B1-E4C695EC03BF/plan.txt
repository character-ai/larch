### UPDATED: python/larch/lint/skill_closure_ledger.py

Change `_summarize` only.

Approach:
- Track the final revision snapshot values and final commit SHA inside the iteration loop, updating both on each revision.
- In the per-revision accumulator loop, skip the advance call for any target absent from `snapshot_values`; only targets present in the current snapshot advance.
- Keep the existing `reappearing_targets` detection and accumulator-reset behavior unchanged.
- After the revision loop, when at least one revision was visited, advance every accumulated target absent from `final_snapshot_values` to `0` using `final_commit_sha`. Skip the post-loop pass entirely when no revision was visited.

Edge cases:
- A target absent for one or more intermediate revisions, then reappearing, must not record a synthetic drop to `0`.
- A target absent from the final selected snapshot must still return `end=0` (post-loop handles this).
- A target first seen after a selection boundary with `previous=None` keeps current first-seen behavior.
- When the selected revision range is empty, return an empty tuple immediately without executing the post-loop pass.

Failure modes:
- Advancing absent targets inside the loop can still create synthetic summary deltas.
- Forgetting the post-loop final-removal pass will break the end=0 guarantee for permanently removed targets; `test_since_tag_summary_reflects_removed_target_in_final_snapshot` is the primary regression guard.
- Mutating the detailed ledger path would violate the non-goal.
