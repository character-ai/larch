## Edge cases

- If `.step3-review-result.env` is a symlink, do not overwrite it.
- If `mktemp` fails while writing the primary result env, still preserve the already emitted operational status when it reached stdout.
- If diagnostic `mktemp` fails, still emit the visible warning and keep the loop alive.
- If `python3` or `python/cli.py` is unavailable, skip failure logging and keep the handoff alive.
- If child stdout contains a valid `STEP3_REVIEW_LOOP_STATUS` and the result env is missing, propagate the stdout status.
- If only a valid recoverable legacy `LOOP_STATUS` exists, map it to `STEP3_REVIEW_LOOP_STATUS` instead of leaving the Step 3 status empty.
- If only `LOOP_STATUS=zero-findings-degraded-panel` exists, do not introduce a new `STEP3_REVIEW_LOOP_STATUS=complete` mapping in this PR.
- If neither `STEP3_REVIEW_LOOP_STATUS` nor a recoverable `LOOP_STATUS` exists, degrade to `panel-failed`.
- Keep all emitted KVs single-line.
- If fd 0 path probing is unavailable or empty in tests, skip the path equality assertion rather than failing on platform differences.

## Failure modes when non-trivial

- `append-failure` can fail. Treat it as non-fatal.
- The loop stdout capture can contain duplicate status KVs from earlier emissions. Do not add persist-failure status KVs that can become last-wins clobbers.
- The wrapper stdout merge can carry the only valid `STEP3_REVIEW_LOOP_STATUS`. Test that before adding the fallback guard.
- Redirecting stdin on the outer Cursor wrapper depends on the child inheriting stdin from `run-external-agent`. This is the current Cursor launch shape and avoids argv changes.
- Codex launch branches remain intentionally unchanged because `run-external-agent` already provides `stdin=subprocess.DEVNULL` for Codex.
- `dispatch-plan-voters.sh` remains intentionally unchanged because the accepted scope is `launch-review.sh`.
