# [BUG] design-step3-review.sh exits silently when phase_driver_write_result_env fails: STEP3_REVIEW_LOOP_STATUS never surfaced to orchestrator

## Summary

During a `/design` run on issue #4277, the `design-step3-review.sh` background task returned exit code 0 with only one line of output (`Reading additional input from stdin...`) and no result KV lines (`STEP3_REVIEW_LOOP_STATUS`, `LOOP_STATUS`, etc.). All external reviewer and voter subprocesses completed normally and their output files are present. The `.step3-review-result.env` file was never written. The orchestrator received no loop status and could not continue automatically, requiring manual tally + plan-revision recovery.

## Observable state after failure

- All cursor plan reviewer outputs present (`cursor-plan-{arch,innovation,pragmatic,requirements}-output.txt`)
- All external voter outputs present (`codex-vote-output.txt`, `cursor-vote-output.txt`, `claude-vote-output.txt`)
- `voting-tally.md` present but empty (0 bytes)
- `.step3-review-result.env` absent
- `.step3-round-1.phase` absent
- `plan-review/round-1/round-meta.json` absent
- `.completed/step-3` sentinel absent
- Background task output: exactly one line — `Reading additional input from stdin...`
- Task exit code: 0

## Root cause

`step3_loop_emit_envelope` in `review-design-step3-loop.sh` is called when the round body returns `LOOP_STATUS=main-agent-vote-required`. It calls `step3_loop_persist_envelope`, which calls `phase_driver_write_result_env` to write `.step3-review-result.env`. If `phase_driver_write_result_env` fails (symlink guard fires, `mktemp` fails, or a KV value contains `\n`/`\r`), it:

1. Calls `larch_err` — which goes to **FD 3** (the larch quiet channel), not to task stdout or stderr.
2. Returns 1.

`step3_loop_persist_envelope` catches the failure with `emit` (also FD 3 only) and returns without writing the file. This failure is completely invisible in the task output.

`design-step3-review.sh` then reads `.step3-review-result.env` via `read-result-env.sh`, finds nothing, and falls back to `_plan_review_stdout_file`. That file is also effectively empty for result KVs because `run-step3-review.sh` uses `emit_kv` (FD 3) not `printf` for its envelope output. All `[[ -n "${VAR:-}" ]]` guards in `design-step3-review.sh` lines 331-348 skip, producing no stdout. Task exits 0 with empty output.

The orchestrator receives no `STEP3_REVIEW_LOOP_STATUS` and cannot continue.

## Secondary observation

The aggregator (Cursor with `-p` flag) and other external CLI subprocesses are invoked without `</dev/null` stdin redirection. In a non-interactive background-task context they print `Reading additional input from stdin...` to stderr, which surfaces in the background task output. This is observable in many committed design run logs (e.g., `aggregator-output.txt.stderr-tail` in `larch-logs/design/*/`). While not the direct cause of the failure, it creates misleading noise in the task output that can mask the actual empty-envelope exit.

## Suggested fixes

**Primary (silent-failure surface):** In `step3_loop_persist_envelope`, if `phase_driver_write_result_env` fails, write the failure to `execution-issues.md` via `python3 python/cli.py run-log append-failure` (or at minimum `larch_err` with a message that reaches FD 2 / stderr, not only FD 3). Also emit `STEP3_REVIEW_LOOP_STATUS=panel-failed` to stdout when the result env write fails so `design-step3-review.sh` gets a fallback status via `_plan_review_stdout_file`.

**Secondary (stdin noise):** Add `</dev/null` to all external CLI invocations that don't need stdin — specifically `cursor agent`, `codex exec`, and `claude` subprocess calls in `launch-review.sh` and `dispatch-plan-voters.sh`. Prevents "Reading additional input from stdin..." from appearing in background task output.

**Observability guard:** In `design-step3-review.sh`, after `read-result-env.sh` and sourcing `_safe_step3_env`, if both `STEP3_REVIEW_LOOP_STATUS` and `LOOP_STATUS` are still empty, emit `**⚠ Step 3: result env missing or empty after loop exit; treating as panel-failed**` to stderr and set `STEP3_REVIEW_LOOP_STATUS=panel-failed` before the printf block. This prevents a silent no-op exit from masking the failure.
