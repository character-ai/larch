### Item 1 — Probe timeout exits are non-retryable, and health-gate latency is unbounded
- **Location**: `python/agents.py` — `_run_codex_probes` (def at 863; `EXIT_TIMEOUT` early return at 868), `_run_cursor_probes` (def at 887; `EXIT_TIMEOUT` early return at 896); `LARCH_PROBE_RETRIES` read at 632-633
- **Source**: #4722 Item 1 (orig #4654 item 1, orig #4624) — **folds in #4654 item 2 (orig #4643)**, a near-duplicate restating the same probe path with an added health-gate-latency angle
- **Severity**: latent (risk-integration)
- **Description**: `rc == config.EXIT_TIMEOUT` (exit code 124) returns immediately with no retry in both `_run_codex_probes` and `_run_cursor_probes`. The `LARCH_PROBE_RETRIES` budget (added in #4613) only covers non-auth `rc == 1`; the timeout branch (`return False, True`) is not retried. A cold-start Codex exec with `high` reasoning effort that grazes the 30s `LARCH_PROBE_TIMEOUT_SECONDS` still produces `probe-failed` with no retry. Verified present at combine time. Fix: consider raising `LARCH_PROBE_TIMEOUT_SECONDS`, giving timeout exits a small retry budget (same `LARCH_PROBE_RETRIES` flag or a new env var), or downgrading probe model effort to avoid cold-start timeouts. **Folded sub-concern (orig #4643):** when adding a timeout retry, also assess whether probe retries add unacceptable health-gate latency and pin a gate-latency budget. Close the latency angle as covered-by-this-item if no distinct latency defect is found.

### Item 2 — Voter failure diagnostics use unbounded read_bytes() before slicing

- **Severity**: latent (resource)
- **Description**: Both sites call `read_bytes()[:200]` / `[:500]` — the whole file is read into memory, then sliced. For a pathologically large voter output / `.diag` / launcher-stderr file this loads the entire file just to show a short prefix. **Re-confirmed present at combine time (this run):** `agent_voters.py:219` (`read_bytes()[:200]` of voter output), `:222` (`read_bytes()[:200]` of `.diag`), and `:225` (`read_bytes()[:500]` of launcher-stderr). ## Proposed Design Outline

### Goals
- Fix the four confirmed external-tool defects: probe-timeout retry (Item 1), bounded diagnostic reads (Item 2), Cursor keychain mutex (Item 3), panel-stderr redaction (Item 10).
- Align failure-diagnostic source selection and stderr-tail resolution (Items 6, 7) only where a concrete gap remains; add the missing pytest coverage (Items 8, 9).
- Sync the external-reviewer and degraded-tools docs (Item 5).

### Non-goals
- No change to default probe behavior or health-gate latency. The new timeout-retry budget defaults to 0.
- No edits to retired Bash launcher surfaces (`scripts/lib-cursor-auth.sh` and peers).
- No `/research` rework unless Item 4 confirms a concrete per-lane routing gap; otherwise drop with recorded evidence.

### Approach sketch
- `python/agents.py`: add `LARCH_PROBE_TIMEOUT_RETRIES` parsing (default 0); give `_run_codex_probes` / `_run_cursor_probes` an independent timeout retry budget; wrap Darwin Cursor keychain reads in the external-startup lock; route implement/review failure paths through `resolve_failure_diagnostic_source`.
- `python/agent_voters.py` + `python/voting.py`: replace whole-file `read_bytes()[:N]` with a bounded prefix read; preserve the 200/200/500 byte caps.
- `python/collect_results.py`: extend `resolve_collector_stderr_tail_file` phase / NS-retry / `.launch-stderr` candidates only where a real gap remains.
- `python/plan_review_panel.py`: redact `proc.stderr` before the waterfall-failure log write and stderr re-surface.
- Add focused pytest coverage in the matching `test_*.py`; sync `docs/external-reviewers.md`, `docs/configuration-and-permissions.md`, `SECURITY.md`.

### Surfaces in scope
