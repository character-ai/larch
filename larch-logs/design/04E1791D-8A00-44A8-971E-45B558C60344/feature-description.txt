### Item 1 — Probe timeout exits are non-retryable, and health-gate latency is unbounded
- **Location**: `python/agents.py` — `_run_codex_probes` (def at 863; `EXIT_TIMEOUT` early return at 868), `_run_cursor_probes` (def at 887; `EXIT_TIMEOUT` early return at 896); `LARCH_PROBE_RETRIES` read at 632-633
- **Source**: #4722 Item 1 (orig #4654 item 1, orig #4624) — **folds in #4654 item 2 (orig #4643)**, a near-duplicate restating the same probe path with an added health-gate-latency angle
- **Severity**: latent (risk-integration)
- **Description**: `rc == config.EXIT_TIMEOUT` (exit code 124) returns immediately with no retry in both `_run_codex_probes` and `_run_cursor_probes`. The `LARCH_PROBE_RETRIES` budget (added in #4613) only covers non-auth `rc == 1`; the timeout branch (`return False, True`) is not retried. A cold-start Codex exec with `high` reasoning effort that grazes the 30s `LARCH_PROBE_TIMEOUT_SECONDS` still produces `probe-failed` with no retry. Verified present at combine time. Fix: consider raising `LARCH_PROBE_TIMEOUT_SECONDS`, giving timeout exits a small retry budget (same `LARCH_PROBE_RETRIES` flag or a new env var), or downgrading probe model effort to avoid cold-start timeouts. **Folded sub-concern (orig #4643):** when adding a timeout retry, also assess whether probe retries add unacceptable health-gate latency and pin a gate-latency budget. Close the latency angle as covered-by-this-item if no distinct latency defect is found.

### Item 2 — Voter failure diagnostics use unbounded read_bytes() before slicing
- **Location**: `python/agent_voters.py:219,222,225` (`_append_voter1_failure`, def at 209), `python/voting.py:527`
- **Source**: #4722 Item 2 (orig #4614 item 2, orig #4582)
- **Severity**: latent (resource)
- **Description**: Both sites call `read_bytes()[:200]` / `[:500]` — the whole file is read into memory, then sliced. For a pathologically large voter output / `.diag` / launcher-stderr file this loads the entire file just to show a short prefix. **Re-confirmed present at combine time (this run):** `agent_voters.py:219` (`read_bytes()[:200]` of voter output), `:222` (`read_bytes()[:200]` of `.diag`), and `:225` (`read_bytes()[:500]` of launcher-stderr). Fix: read only the needed prefix (e.g. open the file and `handle.read(N)`), mirroring the bounded-copy pattern already used by `_make_bounded_context_copy`; consider extending the no-whole-file-read test to cover the diagnostics path.

## Edge cases

- A timeout followed by success must mark the tool present and leave the timed-out flag false.
- Default timeout retries must remain zero.
- Auth failures must not consume timeout retry budget.
- Transient `rc == 1` failures must not consume timeout retry budget.
- A usable `CURSOR_API_KEY` must skip Darwin keychain lock work.
- Empty diagnostic candidate files must be ignored.
- Redaction may over-redact waterfall stderr. That is acceptable.

- Bad `LARCH_PROBE_TIMEOUT_RETRIES` values may silently fall back to zero.
- Phase stderr-tail ordering can change visible diagnostics. Pin order in tests.
- If redaction raises in `plan_review_panel.py`, let the panel fail rather than write raw stderr.
- Lock release bugs can slow later external launches. Use immediate release for keychain-only sections.
