## Edge cases

- A timeout followed by success must mark the tool present and leave the timed-out flag false.
- Default timeout retries must remain zero.
- Auth failures must not consume timeout retry budget.
- Transient `rc == 1` failures must not consume timeout retry budget.
- A usable `CURSOR_API_KEY` must skip Darwin keychain lock work.
- Empty diagnostic candidate files must be ignored.
- A pre-existing generic `.failure-diag` from `run_external_agent` must not mask implement sidecar launcher stderr after compose-and-resolve.
- Redaction may over-redact waterfall stderr. That is acceptable.

## Failure modes

- Bad `LARCH_PROBE_TIMEOUT_RETRIES` values may silently fall back to zero.
- Phase stderr-tail ordering can change visible diagnostics. Pin order in tests.
- If redaction raises in `plan_review_panel.py`, let the panel fail rather than write raw stderr.
- Lock release bugs can slow later external launches. Use immediate release for keychain-only sections.
- Implement stderr-tail regeneration must not overwrite a tail already derived from the final resolved source.
