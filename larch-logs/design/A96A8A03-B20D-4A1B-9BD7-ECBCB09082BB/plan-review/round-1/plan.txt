## Approach
- Part A #1 is scanner-plus-array-entry; the helper keeps its `export` pin form. The awk split preserves strict same-line enforcement for the existing emitters (Round 1 hard constraint) and relaxes to export-or-same-line only for `record-round`, which only the round-timing helper uses.
- Part A #2 mirrors the design-helper so the two deferred round-timing writers share idempotency semantics.
- Part B sets the env at the single dispatch site (`run_codex`) — the minimum surface that fixes the misattribution without touching the shared launcher.

## Edge cases
- The existing 15 emitters use `mark` / `record-vendor-task` / `timing-report.sh` only, so adding `record-round` to the scanner does not newly flag them.
- The helper's `export` (line 109) precedes its `record-round` call (line 110) in file order, so the file-scoped `exported` flag is set before the check.
- The caller `review-implement-step5-loop.sh` already pins `LARCH_TIMING_SKILL=implement` same-line on the helper process and guards in-process re-emit (`STEP5_ROUND_N_TIMING_EMITTED`); the helper's full-tuple pre-check only matters across processes (resume / deferred MAV).
- No literal "15" count exists in the test; the emitter array is explicit, so no count constant needs bumping.

## Failure modes
1. **Resume / cross-process re-emit appends a second round row.** Under full-tuple, a re-emit for the same round with a different `end_s` (e.g., re-derived via `date +%s` on resume) no longer short-circuits and appends a new row. This matches the design-helper's existing behavior. Earliest signal: duplicate `round` rows for one round in `timing-ledger.tsv`. Mitigation: the caller persists `round-start-s` first-write-wins and guards in-process emit, so a normal run writes exactly one row; the cross-process case mirrors the accepted design-helper pattern. Overwrite-on-stale is a possible follow-up if reviewers prefer it.
2. **Over-broad export rule weakens same-line enforcement.** If the relaxation applied to all call kinds, an emitter could silently drop its same-line pin. Mitigation: the relaxation is scoped to `record-round`; `mark` / `record-vendor-task` / `timing-report.sh` keep the strict same-line rule.
3. **Part B pin omitted on a future new dispatch path.** A new coder dispatch in `lint-fix-loop.sh` that records a `LARCH_TIMING_SKILL`-derived timing row would not be covered by the single-site pin. Mitigation: the structural assertion locks the current Codex site; parity audit per `external-tool-launcher-parity.md` covers new paths.
