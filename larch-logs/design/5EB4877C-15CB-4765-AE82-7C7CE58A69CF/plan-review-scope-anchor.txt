## Deliverable A: new lint `lint_agent_tool_contract`

### Rule

Flag every agent definition file that satisfies ALL three conditions:

1. The YAML frontmatter has a `tools:` key whose value is an explicit list (inline flow form like `tools: [Read]` or block-sequence form with `- Name` lines).
2. That list is empty, or it does not contain `Read`.
3. The prompt body (all text after the closing frontmatter fence) contains an imperative read instruction (patterns below).

Everything else passes. In particular:

- No `tools:` key at all: PASS. The agent inherits the full tool set, so `Read` is available.
- `tools:` with a scalar wildcard value such as `*` or `all`: PASS. Treat any non-list scalar as unrestricted.
- Declared list contains `Read`: PASS.
- Empty or Read-less list with no read-intent language in the body: PASS. A toolless pure-reasoning agent is legitimate.

### Why

#6671: `.claude/agents/bug-fix-triage.md` declared `tools: []` while its prompt demanded strict JSONL verdicts about bundles it was told to read. With no tools and a mandatory output format, the model play-acted tool calls and fabricated well-formed verdicts. The instance fix (`tools: [Read]`) landed; nothing prevents the next agent definition from shipping with the same contradiction. This lint is the class fix.

### Scan surface

- `agents/*.md` (shipped agents)
- `.claude/agents/*.md` (dev-only agents)

Non-recursive; both directories relative to the repo root. Skip files with no frontmatter fence.

### Frontmatter parsing

Stdlib only (no pyyaml; `python/` is stdlib-only by policy). Parse manually:

- Frontmatter is the block between a leading `---` line and the next `---` line.
- Find the `tools:` key at the top level of that block.
- Inline flow form: `tools: [Read]`, `tools: [Read, Grep]`, `tools: []`. Split on commas inside the brackets; strip whitespace and quotes.
- Block-sequence form: `tools:` on its own line followed by indented `- Name` lines until the next non-list line.
- Scalar form: `tools: *` or `tools: all` or any other non-list value; treat as unrestricted (PASS).

Precedent: `python/larch/lint/lint_skill_description_length.py` and `python/larch/lint/lint_skill_invocations.py` already parse markdown frontmatter with stdlib code. Reuse their approach or helper if one is importable; otherwise write a small local parser with the semantics above.

### Read-intent detection (body scan)

Case-insensitive regex over the body. Starter pattern set:

- `\bread\s+(?:the|each|every|all|any|its|their|this|that)\b[^.\n]{0,60}\b(?:file|files|bundle|bundles|path|paths|diff|diffs|body|bodies|artifact|artifacts|markdown|log|logs)\b`
- `\bopen\s+(?:the|each|every)\s+(?:file|bundle)\b`
- `\buse\s+(?:the\s+)?Read\b`

These are a starting point, not a frozen contract. The binding requirements are: (a) zero findings on the current unmodified tree, and (b) the fixture test matrix below classifies correctly. Tune the pattern list inside that envelope. Keep the final list as module-level compiled constants with a short comment per pattern.

### Suppression

HTML-comment pragma anywhere in the agent file, reason required (G-Py-11):

```
<!-- lint-agent-tool-contract: ok <reason> -->
```

Match with a regex equivalent to: `<!--\s*lint-agent-tool-contract:\s*ok\s+(\S[^>]*?)\s*-->`. A pragma with no reason text does not match and does not suppress.

### Baseline policy

Hard ban; no baseline file. Verified on 2026-07-09: the current tree has zero violations (`bug-fix-triage` declares `tools: [Read]`; every other agent file either lists `Read`, lists no `tools:` key, or has no read-intent language). If your scan finds a genuine violation that cannot be fixed in this change, follow G-Enf-2: add a reason-bearing baseline JSON in the style of `python/lifecycle-prefix-literal-baseline.json` and make it shrink-only. Do not weaken the rule instead.

### Explicit non-goals for v1

- Do NOT implement the advisory second check discussed in the mining report (flagging machine-parsed-only output mandates that lack a fail-closed clause). It is a low-precision text heuristic. Mention it in the module docstring as a possible follow-up, nothing more.
- Do NOT lint skill files, hooks, or external-agent prompts. Agent definition files only.

Append exactly this text:

```markdown
## Agent contracts

### I-Agent-1: A machine-ingested agent verdict is backed by evidence the agent actually read

An agent whose output is machine-parsed (JSONL verdicts, vote rows, manifests)
must either read its evidence through its own tools or emit the designated
cannot-read outcome for that item. It must never emit well-formed output for
evidence it could not open. A dispatch that inlines evidence must fit the
worst case computed from the owning cap constants; when it cannot, it passes
paths and grants a Read tool. Evidence of violation: a toolless triage agent
play-acted tool calls and fabricated JSONL verdicts, and the dispatching
skill's inlining assumption failed at the configured caps (#6671). Mechanical
backing: `python3 python/cli.py lint agent-tool-contract` over agent
frontmatter, plus fail-closed prompt language in the triage agent definition.
```

## Deliverable C: append guideline G-Ext-3

File: `ARCHITECTURAL_GUIDELINES.md`.

Placement: inside the `## External tools` section, immediately after the `### G-Ext-2` entry and before the `## Documentation and Markdown` heading. Keep one blank line before the new `###` heading, matching the file's spacing.

Append exactly this text:

```markdown
### G-Ext-3: Treat GitHub search as a recall filter; re-apply the shared normalized predicate locally before consuming results
- Why: GitHub search tokenizes bracketed terms, so `[BUG] in:title` also matches any title containing "bug", and prefix-only local matching missed retitled `[DONE] [BUG]` issues; both directions corrupted bug-mining selection (#6604, #6618).
- Guidance: after any `gh` search or list call, filter the result set through `larch.issue.title_match`, or the surface's shared predicate, before spending tokens or verdicts on it; never treat the raw search result as the selection.
- Deviate when: the consumer tolerates recall noise by design and says so where the search is issued.
```

## Deliverable D: append guideline G-Orch-6

File: `ARCHITECTURAL_GUIDELINES.md`.

Placement: inside the `## Orchestration and panels` section, immediately after the `### G-Orch-5` entry and before the `## Observability and telemetry` heading. Keep one blank line before the new `###` heading, matching the file's spacing.

Append exactly this text:

```markdown
### G-Orch-6: Size inlined agent payloads from the owning cap constants, not from an observed run
- Why: an inlining design that worked on one small observed run failed at the configured worst case near 700KB per batch, and the toolless agent downstream fabricated verdicts instead of failing (#6671).
- Guidance: when a skill or dispatcher inlines payloads into an agent prompt, compute the worst case from the cap constants that own the payload (diff cap, body cap, batch size) and check that it fits the transport; when it cannot, pass paths and grant the agent a Read tool.
- Deviate when: the payload is bounded small by construction, such as a fixed-format single record; note the bound where the dispatch is defined.
```
