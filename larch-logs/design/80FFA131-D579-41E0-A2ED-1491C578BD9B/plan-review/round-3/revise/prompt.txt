## Edge cases

- **Env override scope:** `LARCH_DESIGN_DRAFTER` must not affect any other role.
- **Invalid drafter override:** Resolver returns `skip_reason`; `design_lifecycle` must not raise; inline drafting fallback must remain reachable.
- **Drafter vs waterfall:** `design.plan_drafter` must never route through `tool_order()` multi-tier attempts.
- **Unavailable tools:** Registry defaults must not bypass existing availability checks.
- **Voter shape:** Code-review voter 1 must not gain Codex fallback; Claude-absent path must still emit `claude-vote-output.txt`.
- **Plan voters isolation:** `design.plan_voters` must not be wired through `agent_voters.py`.
- **Panel no-fallback split:** Code-review panel `--no-fallback` remains round-1-only when both vendors present; plan-review panel must never inherit that rule.
- **Plan voter no-fallback:** Voters 2/3 waterfall keeps always-on `--no-fallback`, distinct from panel policy.
- **Plan revision:** Current live order is Cursor-first, not the stale issue table.
- **FIXER split:** CI and rebase roles can share values today but must be independently pinned.
- **Decompose both-absent:** Claude generic branch must survive registry refactor.
- **Decompose aggregator:** Must be a firm registry role, not optional prose.
- **Dynamic plan-review slots:** Must stay scout-manifest-driven; registry must not flatten per-archetype dual-vendor expansion.
- **Scout dual entrypoints:** Review and design scout roles must be independently pinned; CLI must accept `--role-id`.
- **Aggregator roles:** Both findings-aggregator roles must be registered and independently pinned.
- **Generic Codex model_role:** Registry slot metadata must preserve `model_role=default` where live code sets it.
- **VoterPolicyDefault completeness:** Must include `archetype` and `default_label` or prompt rendering regresses.
- **Brainstorm pragmatic:** Documented orchestrator behavior only; no registry row.
- **Prompt-only surfaces:** Brainstorm framing/scope defaults must not stay as untested prose-only literals.
- **Docs drift:** Docs table must fail tests when registry defaults change without docs updates.

## Failure modes

- Routing `design.plan_drafter` through `tool_order()` can turn single-vendor pick into multi-tier attempts and change Step 2b failure semantics.
- Raising on invalid `LARCH_DESIGN_DRAFTER` can abort Step 2b instead of soft-falling back to inline drafting.
- Wiring `design.plan_voters` through `agent_voters.py` leaves plan voter dispatch hardcoded and breaks Claude-first plan voter semantics.
- Calling `panel_dispatch_policy("review.panel")` from `plan_review_panel.py` can add forbidden panel-level `--no-fallback` to plan review.
- Omitting `design.plan_voters` voter dispatch metadata can drop always-on voter `--no-fallback` without CI failure.
- Moving plan-review dynamic slots into flat registry rows can break scout-manifest dual-vendor expansion.
- Dropping the decompose both-absent Claude branch can fail decompose when both externals are down.
