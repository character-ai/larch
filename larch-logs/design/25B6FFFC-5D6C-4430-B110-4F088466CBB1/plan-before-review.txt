## Approach

Treat each coverage or review snapshot as an artifact set with an expected root.

Add opt-in I/O helpers that:

- Reject symlinks, symlinked ancestors, non-regular files, and paths outside the expected root.
- Open trusted files with no-follow semantics and verify the opened descriptor is regular.
- Support unpredictable, exclusive atomic writes without changing `larch_io.atomic_write` defaults.
- Revalidate containment and file type after security-critical replacement.

Keep the existing pre-coder snapshot location policy. Harden the shared `/tmp/larch-pre-coder-snapshots/` path instead of adding a new persisted directory pointer or changing snapshot layout. Use random exclusive temporary names, reject unsafe ancestors and destinations, and validate every later read.

For plan coverage:

- Validate the JSON, env, untouched-path, todo, and disposition files as one contained artifact set.
- Reject partial artifact sets. Preserve the absence of the full set as the legacy no-coverage case.
- Validate embedded paths against the canonical paths under `tmpdir`.
- Check counts, bands, booleans, fingerprints, and companion-file contents against the parsed coverage data.
- When `repo_root` is available, recompute coverage and require the persisted semantic fields and fingerprint to match live inputs.
- Remove advisory fallback to stale persisted coverage when a live recomputation fails.
- Without `repo_root`, perform structural, containment, file-type, schema, internal-consistency, and coverage-to-disposition fingerprint checks.
- Preserve touched-path rules, thresholds, todo classification, and valid disposition behavior.

For review snapshots:

- Route pre-coder and self-review snapshot writes through the safe atomic path.
- Validate every snapshot file and diff before it affects cleanup, delta detection, or staging.
- Require the snapshot HEAD to match the expected cleanup base where that gate already applies.
- Fail closed when an expected snapshot is missing, malformed, unsafe, or inconsistent.
- Preserve the existing full and legacy `head_untracked` cleanup modes for valid artifacts.

## Edge cases

- No coverage files may still mean a legacy or non-applicable run. One or more files without the complete required set is corruption.
- An empty untouched or todo inventory is valid when its file exists and matches the JSON.
- A snapshot may contain zero tracked or untracked paths. Its inventory files must still be trusted regular files.
- Dangling symlinks must be rejected even when `exists()` is false.
- Resolve containment without accepting a symlinked root or ancestor.
- Treat a file replaced between validation and open as unsafe. Validate the opened descriptor, not only the pathname.
- Preserve the legacy `head_untracked` snapshot shape only where current code already supports it. Do not reinterpret an incomplete full snapshot as that legacy mode.
- Do not allow malformed coverage to silently select `closes`, `part-of`, or an empty final-report summary.

## Failure modes

- Raise `ShipError` or return the existing nonzero workflow result when an artifact is present but cannot be trusted.
- Fail ship and commit routing when live coverage recomputation fails. Do not fall back to persisted advisory data.
- Abort coder cleanup before mutation when snapshot validation fails.
- If a security-critical write cannot be revalidated, remove only the safe contained temporary file and leave no completion artifact.
- Keep diagnostics path-focused but avoid printing artifact payloads.
