# [OOS] [OUT_OF_SCOPE] Coverage snapshot validation and temporary-file handling are unsafe

## Out-of-Scope Observation

**Surfaced by**: cursor-specialist-correctness, codex-specialist-correctness, cursor-specialist-edge-cases, codex-specialist-edge-cases

**Phase**: implement

**Vote tally**: N/A


## Description

Coverage snapshots are not handled as trusted, validated artifacts throughout their lifecycle. When `repo_root` is omitted, consumption can succeed based only on HEAD equality without validating the covered fingerprint or snapshot against the live diff, allowing missing, symlinked, stale, or mismatched snapshots through final-report and legacy-reader paths. During creation, predictable temporary coverage paths are opened with `write_text` before replacement, allowing a same-user attacker to plant a symlink and redirect writes outside the repository.
- **Suggested revisions (informational for voters; coder decides)**:
  - Require live snapshot and covered-fingerprint validation for every consumption path, including calls without `repo_root`, final-report paths, and legacy readers.
  - Reject missing, symlinked, stale, mismatched, non-regular, or out-of-repository snapshot files.
  - Create temporary coverage files using unpredictable, exclusive, no-follow semantics, then revalidate containment and file type before use or replacement.
