## Plan

## Approach

Treat coverage and review snapshots as untrusted artifact sets that must be validated before any workflow decision, rendering, staging, restoration, cleanup, or mutation.

Add opt-in trusted-I/O primitives that:

- Reject symlinked roots, symlinked ancestors, symlinked leaf paths, non-regular files, and resolved paths outside the expected root.
- Open trusted files with no-follow semantics and verify the opened descriptor is a regular file.
- Read trusted inputs through validated descriptors rather than validating a pathname and then performing an ordinary path-based read.
- Support unpredictable, exclusive atomic writes without changing `larch_io.atomic_write` defaults.
- Create and validate artifact directories without following a planted symlink at the expected root or leaf.
- Create a missing artifact root exclusively, but safely reuse an existing deterministic artifact root only after validating it and its ancestors without following symlinks.
- Revalidate containment, file type, and expected ownership boundary after security-critical replacement.
- Remove only a verified safe, contained temporary file if a write cannot be published safely.

Keep the existing snapshot locations and layouts. Harden the existing shared `/tmp/larch-pre-coder-snapshots/` location and existing review-round directories rather than adding persisted directory pointers. Use exclusive directory creation when a snapshot root is absent; when the expected deterministic root already exists after an interrupted run, validate it and its ancestors, safely clear only validated contained artifacts, and republish the complete snapshot set. Use random exclusive temporary names, reject unsafe ancestors and destinations, validate every later read, and preserve the current read-only snapshot-permission pass after each trusted artifact replacement.

For coverage:

- Define the complete coverage artifact set as the coverage JSON, env file, untouched-path inventory, and todo inventory. Do **not** make `scope-disposition.json` mandatory for valid coverage-only, advisory, or middle flows.
- Make coverage loading three-state:
  - return `None` only when every required coverage artifact is wholly absent;
  - return trusted coverage only when the complete set is structurally and semantically valid;
  - raise the existing workflow error class for partial, malformed, unsafe, stale, mismatched, or otherwise invalid present artifacts.
- Validate the JSON, env, untouched-path, and todo files as one contained artifact set. Reject partial sets and reject dangling symlinks even when `exists()` is false.
- Validate embedded artifact paths against canonical expected paths under `tmpdir`; validate companion-file contents, counts, bands, booleans, derived fields, and fingerprints against parsed coverage data.
- Treat the manifest and `step2-baseline.txt` as trusted inputs during coverage creation and live recomputation: use contained no-follow regular-file reads, bind the result to the opened descriptor or immediate post-read revalidation, and reject unsafe replacement or redirection.
- Require live repository recomputation for every coverage consumer and every coverage-derived disposition writer. Callers must supply or derive `repo_root`; if the repository root or live inputs cannot be validated, fail closed rather than accepting structural-only persisted coverage.
- Recompute coverage from trusted current plan, manifest, baseline, HEAD, and working-tree inputs, and require persisted semantic fields and fingerprints to match live inputs.
- Remove advisory fallback to stale persisted coverage when a live recomputation fails.
- Validate `scope-disposition.json` separately when it is present or when a consumer needs it. Its absence remains distinct from an invalid present file; unsafe, malformed, incomplete, or coverage-fingerprint-mismatched disposition data must never default to `closes`.
- Make validated coverage/disposition loaders the only read authority for disposition link kinds and deferred inventories. Callers must pass a validated result forward or provide `repo_root` for a live trusted load; raw wrapper reads must not re-open a pathname after validation.
- Require `record_disposition` and its CLI action to resolve `repo_root`, live-validate coverage before computing or persisting its fingerprint, and publish `scope-disposition.json` through the trusted random exclusive no-follow write path with final-path validation.

For review snapshots:

- Bind all pre-coder, post-coder, self-review, cleanup, delta-comparison, and staging artifact access to a single trusted snapshot loader.
- Create missing snapshot roots with exclusive semantics; for an existing deterministic root, reject symlinked ancestors and roots, validate it as a real contained directory, safely clear only validated contained snapshot artifacts, and revalidate the root before writing replacement artifacts.
- Route pre-coder artifacts, self-review artifacts, cleanup-time inventory rewrites, and every `post-coder-head.txt` writer—including `round_runner.py` and `review_and_fix.py` mav-apply mode—through safe random exclusive no-follow atomic writes followed by final-path validation.
- Preserve the existing `chmod 0444` / `_harden_pre_coder_snapshot_perms` behavior immediately after each trusted replacement, including mav-apply `post-coder-head.txt`.
- Make the complete snapshot validator the sole cleanup-mode authority. It must validate heads, inventories, patches, expected artifact combinations, containment, regular-file type, patch validity, and HEAD consistency before returning a recognized mode.
- Pass the validator-returned mode into cleanup, restoration, stale-HEAD gating, comparison, delta detection, and stage-path collection, or require those operations to invoke only validator-backed APIs. Remove independent legacy `_snapshot_mode` heuristics from decision paths.
- Validate the complete snapshot artifact set before selecting `full` versus `head_untracked` cleanup mode. Do not classify a tracked-only, incomplete, or interrupted snapshot directory as `full`.
- Validate snapshot roots, inventory files, patch files, heads, and `post-coder-head.txt` before mode detection, stale-HEAD gating, comparison, restoration, cleanup, LOC escalation, delta detection, or stage-path collection.
- Reject symlinked directories and files, non-regular files, escaped paths, stale or inconsistent HEADs, invalid patch data, and incomplete full snapshots before they can affect repository state.
- Preserve the existing full and legacy `head_untracked` cleanup modes only for legitimate, complete artifacts in the formats already supported.

## Edge cases

- No coverage files may still mean a legacy or non-applicable run. One or more coverage files without the complete four-file set is corruption.
- A disposition file is not required for valid coverage-only flows. When present or required, it must be trusted, live-validated against trusted coverage, and match trusted coverage; invalid disposition must not default to `closes`.
- `record_disposition` cannot freeze a persisted coverage fingerprint unless the coverage artifact set and live repository inputs validate with `repo_root`.
- Every coverage consumer and every disposition-derived helper must resolve or receive `repo_root` and perform live validation, or receive already validated coverage/disposition data. If trusted live inputs are unavailable, fail closed instead of accepting a structurally valid persisted artifact.
- An empty untouched or todo inventory is valid when its trusted file exists and matches the JSON.
- A snapshot may contain zero tracked or untracked paths, but all files required by its recognized mode must still be trusted regular files.
- A tracked-only or otherwise incomplete directory is not a valid full snapshot and must not be reclassified as `head_untracked`.
- A missing snapshot root can be created exclusively. An existing deterministic root from an interrupted attempt may be reused only after trusted root-and-ancestor validation and safe contained clearing; symlinked or unsafe existing roots fail closed.
- Dangling symlinks must be rejected even when `exists()` is false.
- Resolve containment without accepting a symlinked root or ancestor.
- Treat a file replaced between validation and open as unsafe; validate the opened descriptor, not only the pathname.
- Preserve the legacy `head_untracked` snapshot shape only where current code already supports it. Do not reinterpret an incomplete full snapshot as that legacy mode.
- Do not allow malformed coverage or disposition to silently select `closes`, `part-of`, deferred inventory, an empty final-report summary, `disposition: none`, or a finalization shortcut.
- Preserve existing snapshot layouts and permissions for valid artifacts; the hardening must not create a new persisted snapshot-location contract.

## Failure modes

- Return `None` only for wholly absent legacy coverage. Raise `ShipError` or return the existing nonzero workflow result for partial, malformed, unsafe, stale, or inconsistent present coverage.
- Treat absent disposition separately from invalid present disposition. Fail consumers that require disposition validation; never default invalid disposition to `closes`, an empty deferred inventory, or `disposition: none`.
- Fail disposition recording and its CLI action when live coverage recomputation fails, trusted repository inputs cannot be validated, or existing coverage artifacts are partial, unsafe, stale, or inconsistent.
- Fail ship, commit routing, PR rendering/mutation, final reporting, and finalization when live coverage recomputation fails or trusted repository inputs cannot be validated.
- Abort coder cleanup, restoration, staging, delta comparison, and stale-HEAD gating before mutation when a required snapshot is missing, incomplete, malformed, unsafe, stale, inconsistent, or lacks a validator-recognized mode.
- Do not use a legacy snapshot-mode heuristic after trusted validation; the complete validator is the sole authority for recognized cleanup mode.
- If a security-critical write cannot be revalidated, remove only the safe contained temporary file and leave no completion artifact.
- Keep diagnostics path-focused but avoid printing artifact payloads.
