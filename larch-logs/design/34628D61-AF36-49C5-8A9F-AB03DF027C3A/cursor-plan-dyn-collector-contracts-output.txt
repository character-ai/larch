### 1. [correctness] Validation lane launch example drops `--output` and `--timeout`

The plan’s validation-phase swap (`plan.txt:77-79`) only specifies `--workdir`, `--add-dir`, `--prompt-file`, and `--usage-label`. The launcher contract requires an absolute `--output` (`plan.txt:25-26`, `plan.txt:41-43`), and the validation collector still waits on `$RESEARCH_TMPDIR/codex-validation-output.txt` (`skills/research/references/validation-phase.md:180`).

If implementers follow the plan literally, `launch-codex-exec.sh` rejects the invocation (exit **2**, no sidecars), the background job never publishes `.done`, and `collect-agent-results.sh` times out on the validation lane.

**Suggested revision:** Extend the validation fence to match the current output contract, e.g. `--output "$RESEARCH_TMPDIR/codex-validation-output.txt" --timeout 1800`, and replace the whole Codex launch block (including the inline `agent-model-args.sh` stanza) rather than only the `run-external-agent.sh` line.

### 2. [risk-integration] Skill fences omit `${CLAUDE_PLUGIN_ROOT}/` on the new launcher path

All four proposed markdown swaps (`plan.txt:73-75`, `77-79`, `81-83`, `85-87`) use bare `scripts/launch-codex-exec.sh`. Existing surfaces use the plugin-root-qualified form, e.g. `${CLAUDE_PLUGIN_ROOT}/scripts/run-external-agent.sh` in `skills/research/references/research-phase.md:162` and `skills/research/references/validation-phase.md:136`.

In consumer repositories, `scripts/launch-codex-exec.sh` resolves under the consumer tree (typically missing), so the background launch fails before any `.meta`/`.done` sidecars exist and collection hangs or falls through to runtime fallback.

**Suggested revision:** Prefix every skill-fence example with `${CLAUDE_PLUGIN_ROOT}/scripts/launch-codex-exec.sh`, matching the existing external-launcher convention.
