# Implementation Plan — Wire shared Codex env-key auth into uncovered `codex exec` paths (#3475)

## Approach

Six `codex exec` surfaces bypass the shared auth helpers (`external_prepare_codex_auth`, `external_codex_auth_config_args` in `scripts/lib-external-launcher-common.sh`), so `OPENAI_API_KEY` preference never applies to them:

1. `skills/research/references/research-phase.md` — 4 research-lane fences (full-auto)
2. `skills/research/references/validation-phase.md` — validation-lane fence (full-auto)
3. `skills/shared/voting-protocol.md` — generic Codex voter fence (read-only)
4. `skills/shared/dialectic-protocol.md` — Codex judge fence (full-auto)
5. `scripts/lint-fix-loop.sh` — `run_codex()` (full-auto, via `run-external-agent.sh`)
6. `scripts/run-negotiation-round.sh` — direct `codex exec` with stdin-piped prompt

Per the approved outline: add one new shared launcher, `scripts/launch-codex-exec.sh`, modeled on `scripts/launch-codex-ci.sh` mechanics (ephemeral `CODEX_HOME` via `mktemp -d` + EXIT trap, `external_prepare_codex_auth` with loud failure, `external_codex_auth_config_args` argv splice, trust-config `-c` arg, model args via `agent-model-args.sh`, serial lock, auth-retry loop, `--json` events capture, usage recording, timing ledger) but with a caller-supplied prompt. Route sites 1–5 through it. Site 6 keeps its stdin-pipe + `--json` event-stream shape (incompatible with `run-external-agent.sh`, which redirects Codex stdin to `/dev/null` per issue #2962), so it gets inline per-site wiring mirroring `scripts/check-reviewers.sh:214-242`.

Add a lint guard, `scripts/lint-codex-exec-auth.sh`, following the `scripts/lint-bare-grep-probe.sh` convention, so future raw `codex exec` call sites fail `make lint` / pre-commit unless wired or suppressed.

Key decisions and tradeoffs:

- **Launcher wraps `run-external-agent.sh`** so the markdown-fence consumers keep their existing background-launch + `collect-agent-results.sh` collection contract (`.meta`, `.diag`, `.done` sidecars keyed to `--output`).
- **Auth-prep and other pre-`run-external-agent` failures mirror `launch-review.sh:444-463`**, not the slimmer `launch-codex-ci.sh` auth branch: truncate `$OUTPUT`, write `${OUTPUT}.diag` (`STATUS=FAILED` + env-key-aware `FAILURE_REASON`), write stub `${OUTPUT}.meta` (`TOOL`/`TIMEOUT`/`OUTPUT_FILE`/`CMD_JSON=[]`), write `${OUTPUT}.done` with the prep RC, `emit_kv LAUNCHER_EXIT`, then **exit 0** so background collectors fail fast on the sentinel instead of stalling until timeout.
- **Stdout `LAUNCHER_EXIT` contract for foreground callers** (`lint-fix-loop.sh`): wrapper exits 0 on exec/auth failures like `launch-codex-ci.sh`; `run_codex()` captures launcher stdout, parses `LAUNCHER_EXIT`, and returns that RC so the Codex→Cursor waterfall still branches correctly.
- **Negotiation stays inline** rather than forcing it through the launcher: converting its stdin-piped prompt to argv risks ARG_MAX on large ballots and changes its event-stream plumbing. Inline wiring is ~15 lines and matches `check-reviewers.sh`.
- **Research/voter/judge lanes gain serial-lock spawn protection and `--json` usage recording** as side effects of routing through the launcher. Both are deliberate alignment with the covered family (today these fences have neither).
- **`lint-fix-loop.sh` gains standard model args** (`agent-model-args.sh`) as a side effect; today `run_codex()` passes none. Deliberate alignment, noted in its `.md`.
- **Collect-managed launcher calls always include `--add-dir`** (default `--add-dir "$workdir"` inside the launcher when the caller passes none) so `collect-agent-results.sh` retry validation (`cmd_has_token "--add-dir"`) accepts reconstructed `.meta` `CMD_JSON`.
- Covered sites (`launch-review.sh`, `launch-codex-ci.sh`, `launch-codex-implement.sh`, `check-reviewers.sh`, `review-and-fix.sh`) are untouched.

## Edge cases

- **`OPENAI_API_KEY` unset/empty/whitespace**: `external_prepare_codex_auth` symlinks `~/.codex/auth.json` into the ephemeral home and `external_codex_auth_config_args` appends nothing — login behavior preserved at every swept site.
- **No `~/.codex/auth.json` and no env key**: prepare succeeds (symlink branch is conditional); Codex itself fails auth downstream and the existing failure/diag paths report it — same as covered sites.
- **Auth-prep failure under background fences**: launcher mirrors `launch-review.sh:444-463` — truncate `$OUTPUT`, write `.diag` (`STATUS=FAILED`), stub `.meta` (`CMD_JSON=[]`), `.done` with prep RC, `emit_kv LAUNCHER_EXIT`, exit 0 — so `collect-agent-results.sh` observes the sentinel immediately with a FAILED diag instead of waiting out the timeout.
- **`lint-fix-loop` launcher exit vs RC**: wrapper always exits 0; `run_codex` parses stdout `LAUNCHER_EXIT` so auth/exec failures still trigger the Cursor/main-agent waterfall.
- **Collector retry loses `CODEX_HOME` env**: `collect-agent-results.sh` re-invokes `run-external-agent.sh` from `.meta` `CMD_JSON` without the launcher env. The `-c` provider args persist in argv, so env-key mode still pins the larch provider; login mode falls back to the real `~/.codex`. This matches the pre-existing covered-site limitation (e.g. `launch-review.sh`) — documented in `launch-codex-exec.md`, not fixed here.
- **Collector retry rejects missing `--add-dir`**: launcher defaults `--add-dir "$workdir"` when callers omit it; collect-managed fences also pass explicit `--add-dir "$PWD"` / `--workdir` so reconstructed `CMD_JSON` passes `cmd_has_token "--add-dir"`.
- **ARG_MAX**: prompts already travel as argv in every fence today; `--prompt-file` only relocates the `cat`. Negotiation keeps its stdin pipe, so the largest-prompt path is unchanged.
- **Parallel research lanes**: 4 concurrent launcher invocations each create independent ephemeral homes; the serial lock only serializes spawn windows (`LARCH_EXTERNAL_SERIAL_LOCK_DELAY`).
- **Lint false positives**: comment lines are stripped; `lib-external-launcher-common.sh`'s quota-message string passes via the file-scope helper-presence rule; harness fixtures live in excluded `test-*.sh` or use the pragma.
