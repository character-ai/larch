**1. [correctness]** `scripts/launch-review.sh:444-463` — The plan’s auth-prep failure path for `launch-codex-exec.sh` (plan line 30) stops at truncate + `.diag` + “exit non-zero,” but the cited `launch-review.sh` model also writes `${OUTPUT}.meta` and `${OUTPUT}.done` and exits **0**. Revise the launcher contract and `test-launch-codex-exec.sh` to match `launch-review.sh:444-463`, not `exit non-zero`.

**2. [correctness]** `scripts/test-lint-fix-loop.sh:14-15` — A top-level `grep` enforces `--stderr-sink "$codex_wrapper_log"` in `run_codex()`. That conflicts with the planned launcher routing and will fail `make test-lint-fix-loop` immediately. Replace this pin with a launch-codex-exec routing assertion.

**3. [correctness]** `scripts/test-lint-fix-loop.sh:88-117` and `563-651` — The harness fixture copies helper libs but not `launch-codex-exec.sh` / `run-external-agent.sh`, and Codex cases hard-code `codex.events.jsonl`, `codex.wrapper.log`, and `codex.sidecar` at the run-dir root. The launcher nests artifacts under the `codex.log.*` stem. The plan only calls out stderr-tail stem updates; it should enumerate fixture copies and path retargets for cases 0a–0b.

**5. [correctness]** Plan `test-launch-codex-exec.sh` (line 38) vs Failure modes §1 — Failure mode 1 mitigates collection breakage by asserting `.meta` after a stubbed launcher run, but the harness spec never lists that assertion. Add it so the mitigation is test-backed, not prose-only.
