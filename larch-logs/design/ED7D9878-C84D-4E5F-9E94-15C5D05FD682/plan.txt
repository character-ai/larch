## Approach

Implement the mirror in three layers.

1. **Core kind abstraction**
   - Keep `architectural_guidelines.py` as the architectural knowledge helper module.
   - Add a narrow private kind spec so duplicated behavior is shared, while public functions stay named and stable.
   - Keep the separate CLI namespace precedent from #6469. Do not add a shared `--kind` flag to public verbs.

2. **Blocking semantics**
   - Guidelines keep `clean` and `deviation`.
   - Invariants use `clean` and `violation`.
   - A present-but-empty invariants file is a clean/no-assessment no-op, so the blocking path stays dormant until real `I-*` entries land. Durable counters under `$DESIGN_TMPDIR` bound both the Step 1d.7 outline and Gate C remediation loops across pause/resume.
   - `/design` blocks before approval when a violation is found. It rewrites the outline or plan with the smallest fix, validates through the existing settle/postplan path, then reassesses. It stops only after bounded retry exhaustion.
   - `/implement` blocks through Step 8, invariant-first. The main agent authors the invariant assessment. A clean note lets shipping continue. A violation note routes to a dedicated `ci-fix` invariant-violation branch that runs before the `FAILED_RUN_ID` check, treats the violation detail as untrusted evidence, repairs the code, then relaunches Step 8 to reassess. `phase=invariants-assessment` guards resume, and PR-create, existing-PR refresh, and post-rebase refresh all gate invariants before guidelines.

3. **Consumer parity**
   - Every place that reads, presents, persists, surfaces, audits, retains, or analyzes guideline artifacts gets an invariant sibling.
   - Ordering is invariant first, then guideline.
   - Absent and invalid files stay independent. One file never gates the other.

Avoid broad renames. Keep guideline filenames, env keys, and prompt strings byte-compatible where callers parse them.

## Edge cases

- Blank or present-but-empty `ARCHITECTURAL_INVARIANTS.md`: reader status is `present` but parsed content is empty. Treat it as no parsed entries and a clean/no-assessment no-op: never emit the violation-assessment-required marker, never block compose or Gate C, and continue to guidelines.
- Invalid invariant file: warn and omit it fail-closed. Continue guideline handling.
- Invariant present, guideline absent: run invariant assessment only.
- Guideline present, invariant absent: current behavior remains.
- Both present: invariant assessment runs first.
- HEAD changes after invariant materialization: invariant write-compose fails and Step 8 rematerializes.
- Violation fix changes the diff: the `ci-fix` invariant-violation branch relaunches Step 8, which rematerializes and reassesses before PR compose.
- Open-PR rebase or existing-PR reuse with an invariant-only body change: the refresh predicate and post-rebase helper reassess invariants before guidelines so the remote invariant section never goes stale.
- Redaction failure: do not publish the note. Stall or drop using the same fail-closed paths as guidelines.
- Symlinked tmpdir artifacts: reject at read, write, invalidate, and final-summary consumption sites.
- Historical logs: missing invariant artifacts are informational, not failures.

## Failure modes

1. **Kind abstraction corrupts guideline behavior**
   - Warning signal: existing guideline tests fail or stdout env keys change.
   - Mitigation: keep public guideline wrappers and add invariant tests without changing expected guideline strings.

2. **Invariant violation loops forever, or a blank file blocks**
   - Warning signal: repeated Step 8 `ci-fix` or Gate C/outline remediation with the same violation, or a compose gate that blocks with an empty invariants file.
   - Mitigation: reuse existing `fix_attempts` for implement and bounded design remediation counters persisted under `$DESIGN_TMPDIR` (Gate C and outline). Gate on non-empty parsed content so a blank file is a clean no-op. On exhaustion, hard-stop with the violation detail.

3. **Autonomous violation repair never starts**
   - Warning signal: `architectural-invariants-violation` handoff routed to `ci-fix` stalls because the CI-log path needs a `FAILED_RUN_ID` that a pre-PR handoff lacks.
   - Mitigation: the dedicated `ship-pr-ci-fix.md` invariant-violation branch runs first (before the `FAILED_RUN_ID` check), repairs from `DETAIL` / `DETAIL_FILE` and the durable note as untrusted evidence, skips run-log capture, and relaunches Step 8; harness-pin the branch ordering.

4. **Invariant PR section goes stale, or audit/run-log consumers drift**
   - Warning signal: an open-PR body keeps an old or missing invariant section after an invariant-only change or a rebase; GC drops invariant artifacts, audit-runs/fluff-analysis miss them, or batch validation rejects current sidecars.
   - Mitigation: gate invariants before guidelines in pre-PR compose, existing-PR refresh (`pr.py`), and post-rebase refresh (`ship.py`); add run-log batch, GC, audit-runs (design + implement scans), final-report, and fluff-analysis tests in the same change.
