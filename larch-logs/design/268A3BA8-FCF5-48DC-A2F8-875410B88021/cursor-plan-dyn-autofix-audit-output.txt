**1. Session rehydration order (correctness)**  
The port text centers on an allowlist session-env parser. The bash wrapper binds orchestrator exports first, overlays `session-env.sh`, then derives vendor flags. A file-only read can drop `SUMMARY_OUTCOME` and break operator-cancel sentinel content, or miss `ISSUE_NUMBER`/`REPO` for pause-save.

**2. Escalation evidence link (correctness / audit semantics)**  
Failure statuses must record stall-recovery escalation without losing diagnostics. The current wrapper attaches `--failure-detail-log` for in-tmpdir validation logs. The plan does not require that passthrough, so ledger rows may lack `failure_detail_log`.

**3. Exit-code contract (correctness)**  
The harness expects wrapper exit `0` even when `AUTOFIX_STATUS` is `failed` or `exhausted`. The plan does not preserve that contract; a non-zero Python exit can short-circuit the shared validator-failure operator flow.

**4. Structural harness gap (risk-integration)**  
`scripts/test-design-structure.sh` has many assertions against scripts this plan deletes. The listed test-design-structure updates are too narrow; CI will fail unless those greps are removed or retargeted to Python authorities.

**5. Inner auto-fix KV capture (correctness)**  
"Call existing `plan auto-fix-commands`" is ambiguous for an in-process port. Without `LARCH_QUIET_DISABLE=1` subprocess capture (or an equivalent internal return API), helper `emit_kv` output may not reach the stdout the orchestrator parses.
