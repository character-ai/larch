## Findings

**1. correctness — `python/design_lifecycle.py` (shared wrapper / postplan helper)**  
Rehydration must land in `os.environ`, not only in a local dict, before in-process `postplan_emit_main` or `pause_save_main`. `design_postplan.py` reads `ISSUE_NUMBER` from `os.environ` for pause handling and copies `os.environ` for validate/check-size subprocesses.

**2. correctness — `python/design_lifecycle.py` (shared postplan body helper)**  
In-process `postplan_emit_main` prints KV rows via `print()` in `flush()`. The helper must capture that stdout and re-emit it after nonfatal arms. Otherwise drafter success can print `DRAFTER_STATUS=succeeded` with no `POSTPLAN_RC=` rows.

**3. risk-integration — `python/session_env.py:687-716`**  
`_design_run_launcher_text` always `exec`s `skills/design/scripts/$script`. The plan deletes those `.sh` files. Retired names need dedicated `case` arms that invoke `python/cli.py` **before** the generic exec fallback.

**4. correctness — `python/design_lifecycle.py` (`design step2b-drafter`)**  
Preserve bash order: repair `.completed/step-2a` → pre-launch pause (`POSTPLAN_RC=11` when applicable) → timing mark → vendor launch. `test-design-structure.sh` enforces this ordering.
