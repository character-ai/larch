## Approach

Fix the Step 5c publish-tail false positive at its root: the helper that resolves the consumer repo's git toplevel is copy-pasted in ~5-6 places, and `design_publish.py` is the one copy that was never written, so it passes the plugin root as `--repo-root`. Extract one shared helper, adopt it everywhere, and stop the drift that produced this recurrence (#4490 then #4847 then #4887).

- Add one shared, stdlib-only helper module `python/repo_roots.py` exposing `consumer_repo_root()`.
- Adopt it in every validator caller that needs the consumer repo's git toplevel; delete the duplicated local definitions and inline `git rev-parse --show-toplevel` calls.
- Fix the broken Step 5c publish-tail caller (`design_publish.py`): pass the consumer repo as `--repo-root` and keep `CLAUDE_PLUGIN_ROOT` pinned to the plugin cache, exactly as Step 2b postplan does.
- Preserve dual-root validation semantics in `plan_quality.py`: consumer repo first, plugin cache second. Do not change `_resolve_repo_script()`.
- Improve the Step 5c operator guidance so `missing-script` defects (often a root-resolution false positive) are called out separately from genuinely unsafe-token defects, and warn against deleting valid repo-local test commands to satisfy a false positive.
- Run a grep audit after the change to confirm no remaining caller passes the plugin root as `--repo-root` when a consumer repo is available.

This is the operator-approved full scope for issue #4887 (Step 1c decisions): single source of truth for consumer-repo resolution, harmonize all callers, and the operator-message improvement. The shared helper is the load-bearing fix; harmonizing the already-working callers removes the duplication that caused the bug rather than adding a sixth copy.

## Edge cases

- Cwd is not inside a git worktree: `consumer_repo_root()` returns `None`; callers fall back to the plugin root, preserving current plugin-only behavior and existing harness tests that run without `git init`.
- Consumer repo and plugin root are the same path: `_resolve_repo_script()` dual-root collapse is unchanged.
- Plugin-cache install: `--repo-root` points at the consumer repo; `CLAUDE_PLUGIN_ROOT` points at the cache.
- Missing `git` binary or git failure: return `None` and use the existing fallback.
- Truly absent script files: validation still fails with `missing-script`.
- Unsafe tokens: no behavior change; the operator message clarifies they differ from `missing-script`.
- Recording fake CLI without publish-tail stubs: publish would abort at redact (rc 5) before validate assertions; mitigated by basing `_write_recording_cli` on `_write_fake_cli`'s tail handlers.

## Failure modes

- Shared helper placed in a heavy or circular-import module regresses CLI startup. Mitigation: a new tiny stdlib-only module (`repo_roots.py`).
- `CLAUDE_PLUGIN_ROOT` not preserved in the Step 5c validate env turns plugin-only scripts into false `missing-script`. Mitigation: set it explicitly and assert it in the regression recorder.
- Harmonizing load-bearing callers (`plan_review.py`, `design_lifecycle.py`, `plan_quality.py`) risks regressions in the review loop and validation. Mitigation: mechanical import-swap only; run the existing `test_plan_review.py`, `test_plan_quality.py`, and `test_design_lifecycle.py` suites plus `make py-test`.
- Changing existing result-env keys breaks downstream callers. Mitigation: add `VALIDATE_MISSING_SCRIPT_COUNT` additively; rename or remove nothing.
