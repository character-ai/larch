- **Panel init failure:** compute action after zero-round promotion, not before.
- **In-loop zfdp:** persist rows + `NEXT_ACTION=step3b` with `status=""`, `write_terminal=False`; never write `.completed/step-3-terminal` while the loop may continue.
- **Terminal zfdp:** full persist with `write_terminal=True` + `step3_loop_write_completed_step3`; `status=""` never `status="complete"`.

- **postplan-operator vs gate-b:** never route `postplan-operator-required` to Gate B apply UX.
- **Dual routing authority:** prompt-side must not branch post-loop on raw `LOOP_STATUS` / `STEP3_REVIEW_LOOP_STATUS` / `TALLY_PLAN_REVIEW_STATUS` when `NEXT_ACTION` is present.
- **Cap reached:** post-loop route is `NEXT_ACTION=step3b-bypass`, not a prose-only direct Step 3b jump.
- **Zero-findings skip-voting:** in-process only; post-loop never enters Step 3.5 on that path.

## Failure modes

- If `NEXT_ACTION` is missing after normalization, treat it as a routing error in prose and do not infer from raw status prompt-side.
- If `NEXT_ACTION=step3b` or `step3b-bypass` arrives before both required sentinels, treat the notification as premature.
- If in-loop zfdp calls full `step3_loop_persist_envelope` with default terminal write, premature `.completed/step-3-terminal` can release bg-poll-guard and route before the loop finishes; treat as implementation defect.
- If `NEXT_ACTION=step3b-bypass` and `design-step3-gate-b-bypass.sh` fails or returns `STEP3_STATE=refused-partial-gate-b-bypass`, stop for repair.
- If `NEXT_ACTION=postplan-operator` and operator resume flags are wrong, stop for repair; do not fall through to Gate B.
- If `NEXT_ACTION` has an unknown value, stop as a Step 3 routing error and preserve `$DESIGN_TMPDIR`.
- If `PHASE_RESULT_ENV_ALLOW_KEYS` omits `NEXT_ACTION`, persist fails closed with `ValueError`.
- If zfdp persist passes `status="complete"`, persisted `LOOP_STATUS` becomes `complete` and routing breaks; treat as implementation defect.
- If `plan-review run --read-result-env` emits routing KVs without recompute, orchestrator handoff can use stale directives; treat as implementation defect.
- If MAV post emits `TALLY_PLAN_REVIEW_STATUS=tally-error` without `NEXT_ACTION=step3b-bypass`, prompt-side raw-status branching reappears; treat as implementation defect.
- If cap-entry-guard prose still says "jump to Step 3b" without `NEXT_ACTION=step3b-bypass` and gate-b-bypass, harness pins and orchestrator behavior diverge; treat as implementation defect.
