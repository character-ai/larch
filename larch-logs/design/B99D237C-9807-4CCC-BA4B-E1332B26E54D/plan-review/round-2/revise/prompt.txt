## Problem (ground truth from the code)

- In `python/ship.py`, `run_ship()` seeds `iteration`/`rebase_count`/`fix_attempts`/`transient_retries` to `0` (ship.py:532-535). On an exit-3 (`NEEDS_USER_INPUT`) or exit-6 (`TRANSIENT`) handback the orchestrator re-invokes `run_ship()` and the counters reset, so the session-wide 50/20/10/1 caps (`config.SHIP_MERGE_LOOP_MAX_ITERATIONS`=50, `CI_MONITOR_MAX_REBASES`=20, `CI_MONITOR_MAX_FIX_ATTEMPTS`=10, `CI_MONITOR_TRANSIENT_RERUN_MAX`=1) are evaluated per-process instead of per-session.
- `_write_ship_state()` already persists `REBASE_COUNT`/`FIX_ATTEMPTS`/`ITERATION`/`TRANSIENT_RETRIES` (ship.py:383-386); nothing ever reads them back on entry, and `_write_terminal_state()` (ship.py:339-345) calls `_write_ship_state(ctx, phase=phase)` with default counter args `0`, so terminal CI handbacks/stalls at ship.py:538, 568, and 592 overwrite restored counters with zeros before the next invocation.
- `run_ship()` always starts at `checks` and runs `checks → postbump → pr-create` top to bottom. On re-entry against an open or already-merged PR this re-runs lint/tests and postbump (bump + flush + push), causing redundant rebase/push/CI churn.

## Approach

Add a best-effort resume reconciliation at the top of `run_ship()`. The persisted state file is the floor for session-wide counters on `open-pr`/`merged` only; `fresh` always uses zero counters (FINDING_6). Ground-truth gh/git/manifest refines only the resume phase; failed ground-truth reads degrade to state-file signals (never a hard error). Keep `run_ship()` linear — gate early phases with the resume decision rather than restructuring into a bash-style phase-dispatch loop.

Resume targets (coarse, three values):

- `fresh` — no valid PR identity, failed open-pr validation, or branch/head mismatch ⇒ run full `checks → postbump → pr-create → CI loop` with counters **literal zero** (ignore stale state-file counter keys).
- `open-pr` — validated PR identity, PR not merged, and (when gh reachable) `gh.pr_view().state == "OPEN"` with `head_ref` matching `ctx.branch_name or ctx.branch`; when gh is skipped (`repo_unavailable` / `forked` / `forked_target`), require state-file `BRANCH_NAME` to match the current branch (same normalization as `_write_ship_state`) or classify `fresh`. Skip checks + postbump; **hydrate** `working = ctx.with_(pr_number=…, pr_url=…)` before any pr-create state write or gate (FINDING_3); run idempotent pr-create body, then CI loop with restored counters; skip `write_final_report_comment` on resume.
- `merged` — merged predicates hold ⇒ `run_postmerge_phase` with hydrated `pr_number`/`pr_url` and a non-empty `merge_result` defaulting to `config.MERGE_RESULT_DRIVER_ALREADY_MERGED` when state/gh/manifest/phase imply merged but `MERGE_RESULT` is absent or not in `config.POST_MERGE_MERGE_RESULTS` (FINDING_4).

**PR identity (FINDING_1):** Parse `PR_NUMBER` from state file (fallback `ctx.pr_number`) only when the value is a base-10 int (same tolerance rule as counters). Non-numeric, empty, or out-of-range identity ⇒ no identity ⇒ `fresh`.

**Open-pr branch match:** When gh is queried successfully, require `pr.state == "OPEN"` and `pr.head_ref == (ctx.branch_name or ctx.branch)`; otherwise `fresh` (do not skip checks on a wrong-branch or closed PR). When gh is not queried, require `run_logs.read_state_kv(state_file, "BRANCH_NAME")` to equal the current branch string; mismatch ⇒ `fresh`.

**Terminal counter preservation (FINDING_2):** Extend `_write_terminal_state` with optional `iteration` / `rebase_count` / `fix_attempts` / `transient_retries` kwargs (default `0` for pre-CI paths). Resume decision precedence (after counter restore rules above):

1. Valid PR identity from step above; else `fresh`.
2. Classify `merged` when any holds: gh `pr_view().state == "MERGED"` (when reachable); OR `run_logs.manifest_status(ctx) == config.MANIFEST_STATUS_DONE`; OR state `PR_CLOSED == "true"`; OR state `MERGE_RESULT` in `config.POST_MERGE_MERGE_RESULTS`; OR state `PHASE == "postmerge"`. Set `resume.merge_result` to persisted post-merge value when present, else `config.MERGE_RESULT_DRIVER_ALREADY_MERGED`; hydrate `pr_url` from gh when available.
3. Else attempt `open-pr` only if open + branch match rules pass; else `fresh`.
4. Ground-truth gh read is best-effort: skip when `ctx.repo_unavailable` or `ctx.forked`/`ctx.forked_target`; wrap `gh.pr_view` in `try/except` — failure means state-file signals decide merged vs open-pr vs fresh.
