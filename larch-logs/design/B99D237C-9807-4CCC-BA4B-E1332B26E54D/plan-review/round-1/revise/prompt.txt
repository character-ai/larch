# Implementation Plan — Python ship driver: persist CI-loop counters + idempotent phase resume (#3448)

SIMPLE tier. Bias toward the smallest change that achieves the goal. ## Problem (ground truth from the code)

- In `python/ship.py`, `run_ship()` seeds `iteration`/`rebase_count`/`fix_attempts`/`transient_retries` to `0` (ship.py:532-535). On an exit-3 (`NEEDS_USER_INPUT`) or exit-6 (`TRANSIENT`) handback the orchestrator re-invokes `run_ship()` and the counters reset, so the session-wide 50/20/10/1 caps (`config.SHIP_MERGE_LOOP_MAX_ITERATIONS`=50, `CI_MONITOR_MAX_REBASES`=20, `CI_MONITOR_MAX_FIX_ATTEMPTS`=10, `CI_MONITOR_TRANSIENT_RERUN_MAX`=1) are evaluated per-process instead of per-session.
- `_write_ship_state()` already persists `REBASE_COUNT`/`FIX_ATTEMPTS`/`ITERATION`/`TRANSIENT_RETRIES` (ship.py:383-386); nothing ever reads them back.
- `run_ship()` always starts at `checks` and runs `checks → postbump → pr-create` top to bottom. On re-entry against an open or already-merged PR this re-runs lint/tests and postbump (bump + flush + push), causing redundant rebase/push/CI churn.

## Approach

Add a best-effort resume reconciliation at the top of `run_ship()`. The persisted state file is the floor for session-wide counters; gh/git/run-log-manifest ground truth refines only the resume phase, and a failed ground-truth read degrades to the persisted state (never a hard error). Keep `run_ship()` linear — gate the early phases with the resume decision rather than restructuring into a bash-style phase-dispatch loop (minimum-change bias).

Resume targets (coarse, three values):
- `fresh` — no PR identity; run the full `checks → postbump → pr-create → CI loop` flow (counters from 0). Unchanged behavior.
- `open-pr` — a PR identity exists and is not merged; **skip checks + postbump**, run the pr-create body (compose body, materialize-OOS, security gate, OOS gate, `pr.ensure_pr` — all idempotent), then the CI loop seeded with the restored counters. Skip the `run_logs.write_final_report_comment` call on resume (it already posted on the original pr-create).
- `merged` — the PR is already merged; skip straight to `run_postmerge_phase` with the persisted `pr_number`/`pr_url`/`merge_result`.

Counters are always restored from the state file regardless of target (gh cannot know fix-attempt counts). Ground truth governs only the phase.

Resume decision inputs and precedence:
1. Restore counters from `ctx.state_file` via the new `run_logs.read_resume_counters` (defaults `0` on absent/garbage).
2. PR identity = state-file `PR_NUMBER` (fallback `ctx.pr_number`). No identity ⇒ `fresh` (even if `PHASE` looks advanced — without a PR there is no remote state to preserve; `PHASE=checks` + empty `PR_NUMBER` is an initial-state file, not a resume).
3. With a PR identity, classify `merged` when any holds: gh `pr_view().state == "MERGED"` (queried only when reachable — see below); OR `run_logs.manifest_status(ctx) == config.MANIFEST_STATUS_DONE`; OR state `PR_CLOSED == "true"`; OR state `MERGE_RESULT` in `config.POST_MERGE_MERGE_RESULTS`; OR state `PHASE == "postmerge"`. Otherwise `open-pr`.
4. Ground-truth gh read is **best-effort**: skip it entirely when `ctx.repo_unavailable` or `ctx.forked`/`ctx.forked_target` (no upstream-reachability assumption), and wrap `gh.pr_view` in `try/except` like `ci_monitor.gather_status` does — any failure means "ground truth unavailable", so the state-file signals in step 3 decide.

## Edge cases
- `ctx.state_file is None` ⇒ `fresh`, counters 0. Existing tests (no `state_file`, or a not-yet-written `state_file`) are unaffected.
- `PHASE=checks` + empty `PR_NUMBER` (initial state) ⇒ `fresh`, not a resume.
- `repo_unavailable` / `forked` / `forked_target` ⇒ gh never queried; state-file signals decide.
- gh reachable but PR `CLOSED` and not merged ⇒ classified `open-pr`; `ensure_pr`/OOS gate handle it or stall normally (no special path).
- manifest file absent or unparseable ⇒ `manifest_status` returns `""` (treated as not-merged).
- counters present on a merged resume ⇒ restored but unused by `run_postmerge_phase` (harmless).

## Failure modes
1. **gh ground-truth read hangs/errors on a slow or unauthenticated host.** Earliest signal: resume unit test with a `gh.pr_view` stub that raises. Mitigation: skip gh when `repo_unavailable`/`forked`; wrap the call in `try/except` and degrade to state-file signals; never block resume on gh.
2. **Corrupt/partial state file (non-int counter) crashes `run_ship`.** Signal: the `REBASE_COUNT=notanint` test. Mitigation: `read_resume_counters` catches `ValueError` per field and defaults to 0; it never raises.
3. **Resume misclassifies (open PR read as fresh → churn returns; fresh read as open → checks skipped on a real first run).** Signal: the per-branch resume tests. Mitigation: key on PR identity first (no PR ⇒ fresh), make gh authoritative only when reachable, and cover `fresh`/`open-pr`/`merged` with explicit tests.

## Testing strategy
- `make py-test` (pytest) and `make py-lint` (ruff/pylint/pyright) must pass. New tests use stub `RecordingRunner`/monkeypatch only — no real bash, gh, or network.
- All pre-existing `test_ship.py` / `test_ci_monitor.py` tests stay green (resume is additive; `fresh` reproduces today's behavior).
- New coverage: `run_logs.read_resume_counters` (absent/empty/garbage/valid) and `run_logs.manifest_status` (absent/DONE/partial) get direct unit tests in `test_run_logs.py` if that file exists, otherwise in `test_ship.py`.
