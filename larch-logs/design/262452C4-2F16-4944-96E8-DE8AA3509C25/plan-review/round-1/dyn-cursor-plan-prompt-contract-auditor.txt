### 1. [correctness] Optional pre-check must not mutate Step 5c-owned artifacts (`skills/design/references/finalize-step5.md:72-78`, `python/larch/design/design_publish.py:228-241`)

The plan correctly allows a silent optional sanitizer pre-check and states Step 5c stays authoritative, but it does not pin the runtime boundary that makes that true.

Today, `_sanitize_diagram_candidate` returns immediately when `.completed/step-5b.5` already exists:

```228:229:python/larch/design/design_publish.py
    sentinel = design_tmpdir / ".completed" / "step-5b.5"
    if sentinel.is_file():
        return True
```

The legacy `design-step3b-sanitize.sh` wrapper still writes that sentinel, promotes `architecture-diagram.candidate.md` to `architecture-diagram.md`, emits chat `**⚠ 5b.5:` warnings, and is documented as legacy-only with Step 5c owning normal execution (`skills/design/scripts/design-step3b-sanitize.md:5-21`). An agent following the issue’s “verify before Step 5c” pattern via that script or an equivalent promote-on-success pre-check would skip authoritative Step 5c sanitization, or lose the candidate and trigger a skip path.

**Suggested revision:** In the proposed `finalize-step5.md` Step 5b.5 section and `skills/design/SKILL.md` Step 5b.5 prose, add an explicit immutability contract: optional pre-check may only read/validate the candidate in place (e.g. `python/cli.py mermaid sanitize --input …` with stdout parsed silently); it must not invoke `design-step3b-sanitize.sh`; it must not write `.completed/step-5b.5`, `architecture-diagram.md`, or `architecture-diagram.skipped`; it must not move or delete `architecture-diagram.candidate.md`; it must not print validity recaps or `**⚠ 5b.5:` sanitizer warnings. Revise the candidate silently or proceed to Step 5c.
