Reviewing the codebase to verify the draft plan against accepted findings and produce an accurate revised plan.
## Plan

Implement graceful degradation at the shared waterfall boundary, opt-in only. Close five gaps the review panel flagged:

1. Downstream manifest readers crash on skipped non-dict rows after a successful degraded dispatch (findings 1, 3).
2. Invalid-slot sidecar write timing is not pinned before reviewer launches; a late write failure can leave external reviewers running (findings 4, 6).
3. `DEGRADED_PANEL_WARNING` stops at `panel-dispatch` and never reaches the production `/design` Step 3 boundary (finding 5).

**Confirmed scope (issue #4768 Q&A):** `--skip-invalid-slots` on the shared loader; only `dispatch_panel` passes it; structurally-invalid rows only (do not drop missing/unreadable `prompt_file` at load time).

- Add `--skip-invalid-slots` to `agent dispatch-waterfall`.
- Keep default `_load_slots` behavior unchanged.
- When the flag is set: collect structurally invalid slot rows, skip them, launch valid slots, fail closed if no valid slots remain.
- **Pre-launch ordering (findings 4, 6):** write the invalid-slot sidecar immediately after slot load and **before the first `_launch_slot` call**; on sidecar write failure raise `ValidationError` with no launches, no paths file, and no running reviewers. This is intentionally **not** the post-launch `DROPPED_SLOTS_FILE` pattern.
- Have `plan-review panel-dispatch` pass the new flag.
- Surface skipped rows as `DEGRADED_PANEL_WARNING` at `panel-dispatch`, copy into round `values` before `collect-results`, then propagate through round stdout → `plan_review.py` Step 3 loop envelope → `.step3-review-result.env` → `design-step3-review.sh` stdout replay (finding 5).
- Harden `plan_review_round` manifest readers with `logging_util.iter_jsonl_dicts` so non-dict rows in on-disk `plan-review-slots.ndjson` cannot crash collection after a successful degraded dispatch. **Do not rewrite the manifest** (findings 1, 3).

## Approach

**Waterfall (opt-in skip).** Extend the shared loader with `--skip-invalid-slots`. Only `dispatch_panel` passes it; voters, `/review`, aggregator, and decompose keep fail-closed defaults.

**Pre-launch ordering contract (findings 4, 6).** Today `resolved_paths_file` is computed only after phase launches complete (~line 740 in `dispatch_waterfall`). Refactor `dispatch_waterfall` so slot load, all-invalid check, paths-file path resolution, and invalid-slot sidecar write complete **before** `phase1_launches` is built and **before** any `_launch_slot` or `_collect_phase` call. Stdout KVs (`INVALID_SLOT_DROP_COUNT`, `INVALID_SLOT_DROPS_FILE`, `WARN=invalid-slots-dropped`) remain at successful completion after launches and paths-file write. `DROPPED_SLOTS_FILE` stays post-launch for no-fallback launch/result drops only; do not mix structurally invalid manifest rows into that file or relocate invalid-slot sidecar writes to `_write_drops`.

**Manifest tolerance (findings 1, 3).** With `--skip-invalid-slots`, the waterfall skips bad rows at load time but leaves `plan-review-slots.ndjson` unchanged. `execute_round` later re-reads that file in `_load_manifest_slots` and `_compose_findings_from_collector`. Both hand-rolled loops today call `row.get` on unchecked `json.loads` results and raise `AttributeError` on scalar/array rows. Replace both loops with a shared helper backed by `logging_util.iter_jsonl_dicts`. Do not rewrite the manifest to valid rows only; downstream readers must tolerate the original mixed file.

**Warning propagation (finding 5).** `DEGRADED_PANEL_WARNING` already exists for voter degradation but is not wired through the Step 3 production path for invalid-slot drops. Thread it end-to-end:

1. `plan_review_panel.dispatch_panel` emits `DEGRADED_PANEL_WARNING=...` when `INVALID_SLOT_DROP_COUNT > 0`.
2. `plan_review_round.execute_round` copies the key from `panel_kv` into `values` immediately after successful `panel-dispatch` KV parse (~line 369) and **before** `collect-results` (~line 391).
3. Round `_emit` stdout carries the key in `values`.
4. `plan_review.py` adds `DEGRADED_PANEL_WARNING` to `MERGE_KEYS`, persists it in `step3_loop_persist_envelope` rows (same pattern as `POSTPLAN_RC` / `DEDUP_RC`), and re-emits it in `step3_loop_emit_envelope`.
5. `design-step3-review.sh` allowlists, binds, and printf-replays the key alongside existing `DEGRADED_PANEL`.

## Edge cases

- **Bad JSON row before a valid row:** skip it only with `--skip-invalid-slots`.
- **Non-dict row (scalar or array):** skip it at waterfall load with the flag; downstream manifest readers skip it via `iter_jsonl_dicts` without rewriting the manifest.
- **All rows invalid:** fail closed even with the flag; no launches, no paths file.
- **Blank lines only:** keep the current no-slot-rows failure.
- **Output path contains newline:** treat as structurally invalid and droppable only with the flag.
- **Missing prompt file:** do not drop at load time.
- **Invalid-slot sidecar write failure:** fail closed before any `_launch_slot`; no paths file; no running reviewers (findings 4, 6).
- **Existing no-fallback result drops:** keep `DROPPED_SLOTS_FILE` separate from invalid manifest drops; post-launch only.
- **Panel succeeds with drops:** round completes; operator sees `DEGRADED_PANEL_WARNING` at Step 3 boundary via result env and wrapper stdout replay (finding 5).

## Failure modes

- If the invalid-slot sidecar cannot be written pre-launch, raise `ValidationError` before any `_launch_slot` call; partial panels from late sidecar failure are explicitly out of scope (findings 4, 6).
- If the panel cannot read the sidecar, still emit a generic `DEGRADED_PANEL_WARNING` using the count.
- If the waterfall exits non-zero, preserve current panel failure reporting instead of converting it to a degraded warning.
- If `execute_round` manifest readers regressed, a mixed manifest could still crash collection during `_compose_findings_from_collector`; the `iter_jsonl_dicts` guard is the mitigation (findings 1, 3).
- If `DEGRADED_PANEL_WARNING` is not copied into `values` before `collect-results`, the round may complete findings work but the operator still sees no degradation at the Step 3 boundary; the `execute_round` early-copy plus envelope/wrapper propagation closes that gap (finding 5).
