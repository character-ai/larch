1. **[security] Raw breadcrumb copy before redaction**  
   `scripts/larch-log.sh:487-490` copies the entire staged run directory into the repo. The plan adds sanitized breadcrumb output, but it does not state that this blanket copy must exclude raw `$RUN_DIR/breadcrumbs`. That is the critical integration point for the security claim.

2. **[architecture] Batch registry shape does not fit `breadcrumbs/`**  
   `scripts/larch-log-batches.sh` is a four-field file-batch table, and `scripts/lib-larch-log.sh:66-72` turns a batch slug plus extension into one file path. A directory with a command-style sanitizer needs a separate contract or a deliberate special case.

3. **[correctness] `ci-wait` cannot preserve stderr progress by switching directly to `emit_breadcrumb`**  
   In quiet mode, unset-stream `emit_breadcrumb` writes to redirected stdout/log, not original stderr, and always appends a newline. That breaks the existing dot progress and the plan's stated compatibility test.

4. **[correctness] Sourced Step 5 breadcrumbs are not categorized**  
   `review-and-fix.sh` sources `review-implement-step5-loop.sh`, whose breadcrumbs run under the same stream environment. The plan's `review-and-fix.sh` callsite count misses that file.

5. **[risk-integration] `RESEARCH_TMPDIR` is documented but rejected**  
   `breadcrumb-monitor.md` says `$RESEARCH_TMPDIR` is valid, and research references allocate streams there, but `breadcrumb-monitor.sh` validates only implement/design/review tmpdirs. The rollout should resolve that mismatch while adding path-scope tests.
