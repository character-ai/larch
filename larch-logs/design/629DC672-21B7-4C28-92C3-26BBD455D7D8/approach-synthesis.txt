# Approach Synthesis (Step 2a.4)

## Agreement between sketches

Both Cursor-Generic and Codex-Generic agree on the high-level shape: this is finishing one contract across three surfaces.

1. **Runtime completion coupling** — every Family B entrypoint writes breadcrumbs to `LARCH_BREADCRUMB_STREAM` and installs the PID-keyed done trap after its final EXIT trap. Item 1 (done-trap wiring in the 9 denylisted scripts) is already complete per audit; the contract holds.
2. **Streamed user-visible progress** — `emit_breadcrumb` calls in stream-relevant code paths must pass an explicit `--category=` matching the fixed vocabulary `{progress, warn, stall, retry, escalate, wait-ci, network-flake}`. `ci-wait.sh` is the highest-impact behavioral migration site (machine output stays on `emit_kv`, genuine errors stay on `larch_err`, wait/progress moves to `emit_breadcrumb --category=wait-ci`).
3. **Durable redacted logs** — the new `breadcrumbs/` per-run directory must be registered as a sanitizer-required batch in `scripts/larch-log-batches.sh`; `scripts/larch-log.sh` must walk it and pipe each file through `redact-secrets.sh --streaming --state-file <tmp>` before committing to `larch-logs/<run-id>/breadcrumbs/<basename>`. Fail-closed on redactor error.

Risk priorities both sketches flagged:
- Trap-ordering must come AFTER each script's final EXIT trap (FINDING_5 invariant).
- Byte-for-byte stdout/stderr compatibility must be pinned with regression tests before/after wrapper changes.
- Redaction MUST fail closed for breadcrumb stream content; PEM state must persist correctly across split-input lines.
