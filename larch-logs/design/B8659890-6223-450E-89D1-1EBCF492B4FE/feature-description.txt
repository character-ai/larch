# ASCII Gantt reviewer-timing charts in /design + /implement (final + progress)

## Summary

Replace the Mermaid `gantt` reviewer-timing charts with a **reusable Python ASCII Gantt renderer** drawn in a plain code fence, then wire it into both the **final report** and the **progress report** for **/design** and **/implement**. The renderer must be reusable by **/review**. It is **fully generic**: it renders a chart for any set of `(label, start_s, end_s)` rows and hard-codes no task labels, vendors, or sections. No rendering-logic duplication.

## Why

- Reviewer-timing charts are emitted today as `mermaid` `gantt` fenced blocks by `scripts/render-review-phase-detail.sh` (reviewer-timing charts section), shared by `/implement` (`skills/implement/scripts/write-final-report.sh`) and `/design` (`skills/design/scripts/render-final-summary.sh --skill design`).
- **Mermaid only renders in a JS engine** (GitHub web, mermaid.live). It does **not** render in the Claude Code terminal where the operator first reads the summary, nor in the committed `final-summary.md`, `gh issue view`, or diffs. There the operator sees raw Mermaid DSL. There is no `mmdc` locally either.
- An ASCII chart in a plain fence renders identically in terminal, committed file, GitHub, PR body, and `gh`.

## Deliverables

1. **Python library — fully generic.** One stdlib-only module (for example `python/gantt.py`, exposed via a `python3 python/cli.py ...` verb). Input: a chart window `(window_start_s, window_end_s)` and a list of `(label, start_s, end_s)` rows. Output: the ASCII chart string. Single source of rendering truth.
   - **Hard-codes NO labels or domain knowledge** — no task names, vendor names, archetypes, sections, phases, or `/design`-vs-`/implement` specifics. Labels are opaque caller-supplied strings. The renderer must draw a correct chart for **any** set of `(label, start_s, end_s)` rows. The call sites own all meaning; the library only measures, scales, and draws.
2. **Final report.** Replace the Mermaid emission in `render-review-phase-detail.sh` with a call to the library. One change covers both skills (both already route through this script): each review round renders an ASCII Gantt.
3. **Progress report.** `python/progress_report.py` (the `p` / `progress` prompt) renders an ASCII Gantt for **every completed review round**, for `/design` and `/implement`, by calling the same library.
4. **Reuse.** The same function backs final report, progress report, and `/review`. No duplicate bar/axis/box logic.

## Rendering spec (exact)

- **Data source (caller's job, not the library's).** The call site extracts rows from `timing-ledger.tsv` (`type=vendor` rows: `start_s`, `end_s`, label), windows them to each round via `type=round` rows, caps at 25 rows per round, and sorts by start then end, then passes the resulting opaque `(label, start_s, end_s)` rows to the generic library. Labels pass through **as-is** (see Out of scope).
- **Labels.** Full task label, left-justified, column width = longest label. **No truncation.** Lines may exceed 80 columns (acceptable; wide monitors).
- **Track.** Fixed width `W` cells (for example 56), scaled to the round window; `span = max relative end`.
- **Bars.** Continuous **whole-cell `█` only**. `start_col = round(start*W/span)`, `end_col = round(end*W/span)`, minimum 1 cell, clamp to `W`. **No partial/sub-cell block glyphs** (`▏▎▍▌▋▊▉`): they leave a background sliver mid-bar that reads as a vertical line inside the bar on dark terminals.
- **Box.** Top `┌` + `─`×`W` + `┐`, bottom `└` + `─`×`W` + `┘`. **Border interior must equal `W`** so the right border lines up with each row's right `│`. Flat: one group, no sections.
- **Axis.** A line above the box: left label `0:00` under the first track cell; right label = window end (`m:ss`) ending under the last track cell.
- **Row.** `<label> │<track>│ <duration>`, duration bare (`Ns`), right-justified, **no parentheses, no start-end range column**.
- **Fence.** Wrap in a plain fence, not a `mermaid` fence.

## Tests / self-checks (assert in the harness)

1. **Right edges aligned.** Every row's right `│` is at the same column as `┐` / `┘`.
2. **Left edges aligned.** Every left `│` / `┌` / `└` at the same column.
3. **Glyphs.** Track contains only space and `█` (no partial blocks).
4. **No interior gap.** The run of `█` in any bar has no embedded space.

## Out of scope (separate follow-up)

- **Task labels.** Some are wrong or uninformative today (`cursor/plan-requirements` is not the requirements reviewer; `unknown/aggregator`, `cursor/review`, `codex/review`). Root cause for the follow-up: `render-review-phase-detail.sh` derives labels from the output basename (`derive.awk` / slot-map), and `launch-review.sh` defaults unspecified kinds to `codex-review` / `cursor-review`. The fix will read the timing-ledger `task_kind` column. Defer until real ASCII charts across multiple rounds make it easy to debug.
- **Outlier handling** (for example `/implement` CI `.out` rows far right that compress real bars). Observe with real charts first.
