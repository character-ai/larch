## Findings

### 1. correctness — `scripts/lint-bare-grep-probe.sh:226-244`

The plan calls for scanning every grep-family **segment** and keeping segment-start bare `grep` reporting, but `is_bare_wrapper_grep()` is anchored to the **line** start. It always calls `skip_assignments(1)` and only recognizes a `{` group prefix, not a per-segment `(`. Right-hand bare grep such as `echo ok || grep -q PAT file` will not satisfy `i == idx`, so the wrapper trap is skipped even though the plan says segment-start bare `grep` should still be reported (except pipe-fed allowances).

**Suggested revision:** Pass a `segment_start` index into bare-wrapper detection and run the same prefix skips from that index only.

### 2. correctness — `scripts/lint-bare-grep-probe.sh:209-224`

Segment discovery after `||`, `&&`, `;`, `|`, and `|&` is necessary but not sufficient. The current first-candidate finder also skips env assignments, optional leading `if`/`!`, group openers, and `command` before testing `is_grep_family`. The plan’s segment-discovery bullet does not require repeating that chain at each boundary. Planned tests include `|| command grep ... ../root` but not env-prefixed right-hand candidates; without shared prefix normalization, `false || LC_ALL=C rg ... ../root` can be missed.

**Suggested revision:** Add one shared `advance_to_command_start(i)` helper used for the initial candidate and every post-boundary restart.

### 3. correctness — `scripts/lint-bare-grep-probe.sh:348-362`

Gap 2 (`-f` / `--file`) needs parent-ascent on the **pattern-file operand**, not only on post-pattern search roots. The duplicated walkers today treat `-f` / `--file` as pattern options and consume split values without calling `has_parent_ascent_segment` on them; equals forms keep the ascent inside the same token. The plan’s tests cover `rg -f ../patterns`, `rg --file ../patterns`, and equals forms, but the refactor step only says to share argv walking. That leaves room to implement post-pattern scanning only and still pass some cases while missing `-f=../patterns`.

**Suggested revision:** Pin the shared walker contract: on `-f` / `--file` (split or `=`), run `has_parent_ascent_segment` on the file operand during option scan.

### 4. correctness — `scripts/lint-bare-grep-probe.sh:285-316`

Gap 4 is specifically about **grep** split `--include` / `--exclude` letting a no-path probe slip through when the include value is parsed as a path operand (`grep --include ../dir PATTERN`). The plan says to normalize split include/exclude but does not scope it to `cmd == "grep"`. The existing `option_takes_value` already keeps those flags grep-only; the shared walker must preserve that split and should name the concrete bypass fixture in tests.

**Suggested revision:** Scope include/exclude consumption to grep in the shared helper and add `grep --include ../dir PATTERN` as a named no-path violation case.

### 5. [OUT_OF_SCOPE] correctness — `scripts/lint-bare-grep-probe.sh:252-256`

`then` is already an argv terminator in `is_command_boundary()` but not a multi-candidate segment boundary. Same-line `if true; then rg PATTERN` is not covered by the planned operator list and is already missed by `candidate_index()`. This is a pre-existing line-based limitation, not one of gaps 1–5.

---

**Pipe-fed stdin:** The plan’s contract (allow `cmd | rg PATTERN`, still flag `cmd | rg PATTERN ../root`, parent-ascent before `< /dev/null`) is sound. The main regression risk is implementing `pipe_fed` from the segment’s immediate `|` / `|&` boundary only, not from any earlier pipe on the line; the plan’s doc bullet already states that intent.

**Minimum-change:** Gaps 6–7 correctly stay limitations-only; optional `docs/linting.md` shard fix is appropriately `MAY_UPDATE`.
