## Approach

Implement the minimum linter extension for gaps 1-5.

- Keep the scanner line-based.
- Scan every grep-family command segment on a line, not only the first candidate.
- Preserve existing piped-stdin allowance for `cmd | rg PATTERN`.
- Still check parent-ascent operands on piped, fallback, chained, and semicolon-separated grep-family commands.
- Treat right-hand `||`, `&&`, `;`, `|`, `|&`, and `&` command starts as new candidate segments.
- At each segment boundary, restart candidate prefix peeling (skip assignments, optional `if`/`!`, `(`, `{`, `command`) relative to that boundary start; do not reuse the previous segment's index.
- Per-candidate evaluation order: bare wrapper (segment-relative) → parent-ascent (always) → if pipe-fed skip no-path and devnull checks → else devnull short-circuit then explicit-path check. A safe pass (pipe-fed no-path, devnull, explicit-path) does NOT stop the line; continue to the next candidate segment.
- Check `-f`/`--file` option values for `../` segments in both split (`-f VALUE`) and equals (`--file=VALUE`) forms. Run the same `has_parent_ascent_segment()` check on the consumed value before continuing; leave `-e`/`--regexp` values unchecked.
- Fix split-value `--include` / `--exclude` parsing for `grep` (not `rg`) so option values cannot hide a later path or shift pattern/path detection.
- Refactor the duplicated argv walkers into one shared helper used by explicit-path and parent-ascent checks.
- Document gaps 6 and 7 as limitations only.

## Edge cases

- Quoted operator-like patterns such as `rg '|' path/` must stay valid.
- `-e "../pattern"` must not become a false positive.
- `--include="../*.py"` for grep may remain allowed if treated as a glob option value, not a search root.
- `rg PATTERN < /dev/null` remains allowed.
- `rg PATTERN ../root < /dev/null` still fails because parent-ascent checks run before the stdin short-circuit.
- `false || grep PATTERN file.txt` must flag bare-wrapper even though the preceding `false ||` means it rarely executes.
- A line that has a safe first candidate (e.g., `command grep PATTERN .`) and an unsafe second candidate (e.g., `; rg PATTERN ../root`) must still fail.

## Failure modes

- Over-scanning pipe-fed probes could reintroduce false positives for existing safe `cmd | rg PATTERN` forms.
- Under-consuming split option values can shift pattern/path detection and either miss a real path or flag a pattern.
- Segment-restart index errors can cause the same candidate to be evaluated twice or skipped entirely.
- Refactoring the shared argv walker can change stdin behavior for `-` and `/dev/stdin`.
- Bare wrapper `grep` logic can become too broad if it flags pipe-fed grep forms that the current contract allows.
