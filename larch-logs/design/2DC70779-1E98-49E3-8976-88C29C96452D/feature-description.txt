# [OOS] lint-bare-grep-probe.sh parent-ascent guard: 8 OOS gaps from run 3A7C4943 (issue #6304)

These 8 gaps were surfaced as OOS candidates during the `/implement` review for issue #6304 (run 3A7C4943). They extend the parent-ascent linter added in that PR. Each item is a distinct limitation of `scripts/lint-bare-grep-probe.sh`.

**1. (important) Unsafe right-hand `||` fallback not checked**

Candidate selection only inspects the first grep-family command on a line. An unsafe search on the right-hand side of `||` can bypass the `../` guard entirely.

**2. (important) Pattern-file operands skip ascent checks**

The path guard does not inspect `-f` / `--file` operands. A parent-ascent path hidden in a pattern-file argument evades detection.

**3. (latent) Later pipeline or semicolon commands skipped**

Grep-family commands after a pipe or semicolon on the same line are never checked for `../` operands.

**4. (important) Split-value ripgrep options can bypass the guard**

Split-value forms for `--include` and `--exclude` can be misparsed, letting a parent-ascent operand slip past the no-path guard.

**5. (latent) Duplicated argv walkers can drift**

The explicit-path and parent-ascent checks use separate argv parsing loops. A future option-parser edit could update one but not the other, reintroducing missed `../` operands or stdin false positives.

**6. (latent) Continuation-line probes escape line-based scanning**

The line-based scan cannot see `../` on continuation lines, so multiline fenced probes can bypass parent-ascent detection.

**7. (latent) Absolute search roots remain unbounded**

The linter still allows unbounded absolute search roots. A probe can recurse through a huge tree without any `..` segments.

**8. (nit) Stale `test-lint-bare-grep-probe` docs row**

The documentation inventory row for `make test-lint-bare-grep-probe` points at an outdated shard name and no longer matches the current test setup.
