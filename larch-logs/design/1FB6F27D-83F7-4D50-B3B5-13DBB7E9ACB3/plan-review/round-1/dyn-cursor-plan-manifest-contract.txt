## Findings

**1. [completeness] `_update_manifest_v2` outside Manifest adoption scope** (`python/run_logs.py:402-418`, `python/run_logs.py:2052-2072`, `python/final_report.py:494-508`)

The plan replaces the dict round-trips and `_manifest_v2_merge` but does not cover `_update_manifest_v2`, which still reads and mutates a raw dict. That path serves `larch_log_manifest_main` (terminal manifest reconcile) and `_commit_run` pre-commit refresh. Acceptance calls for Manifest as the only representation. Either wire this path through `from_json` / `to_json` or document it as a deliberate exception with byte-parity tests.

**2. [correctness] v2 JSON key naming not pinned in plan** (`python/run_logs.py:716-726`, `python/run_logs.py:947-960`)

`_manifest_to_dict` emits v1-shaped keys (`version`, `created_at`). Committed v2 manifests use `schema_version` and `started_at`. The plan mandates byte compatibility but does not forbid copying `_manifest_to_dict` shape into `to_json`. Add an explicit v2 emission rule so implementers do not introduce legacy keys on the v2 write or fallback path.

**3. [risk-integration] Two constants, one purpose** (`python/run_logs.py:370-372`, `python/run_logs.py:733-751`, plan `run_logs.py` section)

The plan proposes one v2 reserved-key constant for `from_json` and `to_json`. Today `_MANIFEST_IMMUTABLE` (6 keys) guards CLI updates in `_update_manifest_v2`, while `v2_exclude` (17 keys) partitions parse/emit. Merging them risks blocking valid CLI updates or allowing reserved-field corruption. Keep both constants with distinct roles.

**4. [risk-integration] v2 merge depends on passing on-disk `existing`** (`python/run_logs.py:947-954`, plan `run_logs.py` section)

V2 metadata not mapped into `Manifest` core fields is preserved only when `_manifest_v2_merge` copies the on-disk dict first. The plan’s optional `reserved` bag is fine, but whichever approach is chosen, `_write_manifest` must pass read `existing` into `to_json` for v2 files. The proposed `update_manifest` immutability test should assert on-disk JSON bytes, not only in-memory `Manifest` fields.
