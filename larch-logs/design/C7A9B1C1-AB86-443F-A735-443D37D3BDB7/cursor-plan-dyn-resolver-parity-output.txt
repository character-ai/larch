### Finding 1
**correctness** — `python/session_env.py` (planned CLI stdout)

Bash emits the winner with `printf '%s'` and no newline (`skills/implement/scripts/lib-resolve-implement-tmpdir.sh:109`). Both hooks assign `IMPLEMENT_TMPDIR=$(...)`. If the new CLI uses `print(path)`, the captured value includes `\n`, so `[[ -f "$IMPLEMENT_TMPDIR/.run-cleaned-up" ]]` and post-/review sentinel checks miss the real directory and the hook fail-opens when it should block or advise.

**Suggested revision:** Pin stdout to `sys.stdout.write(resolved)` with no trailing newline; add a subprocess-based pytest asserting captured bytes equal the path exactly.

### Finding 2
**correctness** — `skills/implement/scripts/hook-stop-fail-close.sh`, `scripts/sessionstart-health.sh` (planned pre-check)

`cleanup_cache_sessions_root()` already maps unset `HOME` to `/tmp/.cache` (`python/session_env.py:180-187`), matching bash `${HOME:-/tmp}/.cache` (`skills/implement/scripts/lib-resolve-implement-tmpdir.sh:10`). The plan’s hook pre-check only says “scan the same three roots” without the `${HOME:-/tmp}` expansion. A literal `$HOME/.cache` pre-check can skip `python3` while eligible `claude-implement-*` dirs live only under `/tmp/.cache/larch/sessions`.

**Suggested revision:** Copy the exact bash root tuple into both hook pre-checks; add one harness case with unset `HOME` and a session rooted under `/tmp/.cache`.

### Finding 3
**correctness** — `python/test_session_env.py` (planned coverage)

Bash fail-closes TTL evaluation when `now` is 0 (`skills/implement/scripts/lib-resolve-implement-tmpdir.sh:90-91`; contract `skills/implement/scripts/lib-resolve-implement-tmpdir.md:43-44`). The plan states “Reject when `now <= 0`” but the pytest checklist does not include it. That gap could let a port accept stale candidates under broken clock probes.

**Suggested revision:** Add an explicit `now=0` regression test alongside the listed TTL cases.
