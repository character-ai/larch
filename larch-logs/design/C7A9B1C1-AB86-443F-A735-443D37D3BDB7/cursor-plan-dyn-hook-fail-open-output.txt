## Findings

### 1. SessionStart `set -e` needs an explicit fail-open capture pattern (blocking, correctness)

The plan says a non-zero CLI exit should resolve to an empty tmpdir, but it does not spell out the bash idiom required under `set -euo pipefail` in `scripts/sessionstart-health.sh`.

Today the sourced resolver uses an explicit guard:

```184:184:scripts/sessionstart-health.sh
        IMPLEMENT_TMPDIR=$(resolve_implement_tmpdir "$HOOK_CWD" 2>/dev/null) || IMPLEMENT_TMPDIR=""
```

Replacing that with a bare `IMPLEMENT_TMPDIR=$(python3 ...)` means any resolver exit `1` (import failure, argparse error, runtime error) aborts SessionStart before the final `exit 0`, breaking the documented invariant that SessionStart is always non-blocking (`scripts/sessionstart-health.md:5`).

**Suggested revision:** Require the same `|| IMPLEMENT_TMPDIR=""` pattern (or a `set +e`/`set -e` wrapper) in the `### UPDATED: scripts/sessionstart-health.sh` section and in `scripts/sessionstart-health.md`.

### 2. SessionStart harness gap for python failure when session dirs exist (important, risk-integration)

The plan adds one new regression case: failing `python3` stub plus no `claude-implement-*` dirs to prove the pre-check skips Python. That case never invokes the resolver, so it cannot catch finding 1.

Existing boundary cases (14–16) will need a real `python3` on `PATH` and therefore exercise only the success path. There is no planned case where session dirs exist and `python3` fails.

**Suggested revision:** Add a harness case with a populated `claude-implement-*` tmpdir and a `python3` stub that exits non-zero; assert exit code `0` and no boundary advisory (fail-open degrade).

### 3. Stop hook has no runtime fail-open / no-spawn tests (important, risk-integration)

`scripts/test-implement-anti-halt.sh` only adds structural `grep` checks that `hook-stop-fail-close.sh` mentions `session resolve-implement-tmpdir` and the `claude-implement-*` pre-check. There is no runtime harness for the Stop hook today, and the plan does not add one.

Stop is the hook that can block the user. Regressions such as dropping the pre-check, omitting `command -v python3`, or accidentally enabling `set -e` around the resolver call would not be caught before production.

**Suggested revision:** Add a small offline harness (for example `scripts/test-hook-stop-fail-close.sh`) with at least: (a) no session dirs + failing `python3` stub → exit `0`, no `decision:block` JSON; (b) empty/malformed stdin JSON → exit `0`; (c) optional positive case that still blocks when resolver returns a real tmpdir with `review-round-summary.md` and no `.review-boundary-passed`.
