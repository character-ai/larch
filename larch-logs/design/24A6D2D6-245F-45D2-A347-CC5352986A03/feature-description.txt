# md-to-py-IV: render the compact reviewer-status table in Python (design Step 3)

**Theme:** Part of the md-to-py-IV umbrella. Move residual prose-logic from `/design` SKILL.md into deterministic Python.

**Problem.** The orchestrator renders the compact `📊 Reviewers: | Cursor-Arch: ✅ 4m12s | …` status table by hand from a TSV, including a multi-key round-binding fallback (`FINAL_ROUND_NUM` → `STEP3_REVIEW_ROUND_NUM` → `ROUNDS_COMPLETED`, numeric-validated) when `latest-reviewer-status.tsv` is missing. This block is **duplicated verbatim** at the Step 3 launch and the Step 3 resume fences (`skills/design/SKILL.md` ~597-608 and ~667-678). There is no Python renderer for this table today (confirmed by grep).

**Proposed change.** Have `python/plan_review_round.py` write a pre-rendered `reviewer-status-table.txt` (one line) alongside the TSV it already writes. The orchestrator emits that line verbatim, the same proven pattern already used for `final-summary.md`. The multi-key round-binding fallback moves entirely into Python.

**Acceptance.**
- A Python verb/function renders the icon table (✅/⏳/❌/⊘ + elapsed) from `reviewer-status.tsv` / `latest-reviewer-status.tsv`.
- Both Step 3 SKILL.md sites collapse to "emit the rendered line"; the duplicated ~12-line fallback prose is removed from both.
- Round-binding fallback logic lives in Python, not prose.

**Notes.** Hot path. Highest-confidence design-side item. Verify the emit stays orchestrator-side (tool output is collapsible, so the rendered line must be printed as chat text).
