# contract-unification [FEATURE] In-process calls over cli.py self-reentry

​#### Problem

Python modules re-invoke `python3 cli.py` by subprocess to call siblings in their own package, minting a hand-built argv serializer plus a KV stdout parser per hop. Review: 59 re-invocation sites; the tally flag contract is built independently in `review_core_body.py:659-686` and `round_runner.py:609-658` and parsed a third time by argparse, and the tally KV output dict is hand-written three times inside one function (`review_tally.py:755-776, 829-851, 1100-1125`) with drifting key sets. Design: 103 sites; `design_publish.py:802-846` shells out to its own package's `log-publish` and re-parses stdout while `design_log_publish_flow.py:530,562,716,725` back-imports `design_publish` privates with `# noqa: SLF001` — proving no isolation boundary exists. State: 37 `_cli(...)` sites in `bootstrap.py` (a 20-flag argv to sibling `session_env.write_env_main`), plus two divergent ~25-line `_redact_text` wrappers (`bootstrap.py:1376` vs `_report.py:449`) that both shell out to reach pure functions in `core/redact.py`. Issue: ~9 hops (`oos_filer.py:87-88` and friends re-parse `issue_create.emit_kv` output produced in-package).

​#### Goal

In-process function calls returning dataclasses for intra-package hops; `*_main` wrappers remain for shell callers; subprocess stays only at the Bash-Python boundary and for `gh`. Where a CLI surface must remain, one `Args.to_argv()`/`add_to_parser()` pair per stage and one emit function per result type.

​#### Size

Net reduction 700+ lines of argv/KV glue; removes the machinery that mints new parser pairs and ~37 interpreter spawns from the bootstrap hot path.

​#### Dependencies

Land after the plan-review/code-review machinery merge (it restructures the same review modules).

## Proposed Design Outline

### Goals
- Add frozen dataclass result types and module-level typed callable entry points for all four report modules.
- Keep every `*_main` wrapper emitting identical KV-stdout.
- Add tests for the new typed callables and result types.

### Non-goals
- Changing KV-stdout output format of any existing CLI entry point.
- Modifying out-of-scope callers (e.g., `design_pause.py`, `finalize.py`, `final_report.py`) except where the return type change is backward-safe.
- Touching `timing.py` class internals beyond adding module-level wrappers.

### Approach sketch
- Add `@dataclass(frozen=True)` result types in each of the four source modules (no new files).
- `progress_file.py`: add `PersistedRunResult` dataclass and `resolve_persisted_run()` typed callable; existing `resolve_persisted_repo_root()` stays unchanged.
- `statusline_install.py`: replace `install_statusline` `bool` return with `StatuslineInstallResult`; out-of-scope callers either discard the result or call via subprocess.
- `tokens.py`: add `BudgetCheckResult`, `ClaudeSourceResult`, `PrLineCountResult` dataclasses; change `check_step_token_budget`, `token_claude_source`, and `compute_pr_line_counts` to return them; add `token_mark()` module-level typed callable; update internal callers and `*_main` wrappers in-file; note `final_report.py` as MAY_UPDATE.
- `timing.py`: add `TimingMarkResult`, `VendorTaskResult`, `RoundResult`, `TimingReportResult` dataclasses; add module-level typed entry points `mark()`, `record_vendor_task()`, `record_round()`, `render_report()`; update `*_main` wrappers to delegate to them.
