**1. [correctness] `wait-for-reviewers` timeout detection is a no-op in the proposed snippet**  
The plan’s `(( _wait_rc != 0 )) && larch_err …` branch cannot fire: [`wait-for-reviewers.sh`](scripts/wait-for-reviewers.sh) documents and implements **always exit 0** on timeouts (lines 15–16, 176), while machine-readable `TIMEOUT` records go to **stdout** (lines 12–14, 165). The proposed caller discards stdout (`>/dev/null`), so operators get neither the planned warning nor a reliable signal to raise `LARCH_VOTER_WAIT_TIMEOUT`. **Revision:** capture stdout and grep for `^TIMEOUT `, or add a `--quiet` consumer mode—without changing `wait-for-reviewers.sh` exit semantics if that remains a hard acceptance constraint.

**2. [correctness] Cursor sidecar marker line number points inside the retry loop**  
The plan cites “after `wait "$WRAPPER_PID"` (~932)”. That site sits inside the auth/transient `while` loop where `: > "$SIDECAR"` runs on retry (lines 947–955). A marker written there can be erased before a successful exit. **Revision:** write `cursor-status: ok …` only after the loop at ~958, adjacent to `_write_dirty_tree_sidecar` / `cursor_launcher_promote_inner_done` (1045–1046), mirroring the codex post-loop placement (~560–564).

**3. [correctness] Planned `.done` wait regression test does not exercise the real race**  
Test case 1 delays `.done` via a **Claude CLI stub**, but voter 1’s `.done` is written by [`launch-claude-review.sh`](scripts/launch-claude-review.sh) after the subprocess returns (180–182), not by the stub. The production race for voters B/C is the **waterfall background subshell** writing `.done` after `launch-review.sh` returns ([`dispatch-with-waterfall.sh`](scripts/dispatch-with-waterfall.sh) 270–271). **Revision:** delay `${VOTER_2_PATH}.done` / `${VOTER_3_PATH}.done` in a `launch-review.sh` test stub or harness hook, not `STUB_BIN/claude`.

**4. [architecture] STATUS is computed before the new barrier**  
[`dispatch-code-voters.sh`](scripts/dispatch-code-voters.sh) sets `VOTER_*_STATUS` from `-s "$VOTER_*_PATH"` (198–210) **before** the planned wait. A late `.txt` flush can leave `failed` locked in before parse-rate. **Revision:** wait first, then derive STATUS (or re-derive STATUS once after wait).

**5. [architecture / innovation] Stronger in-scope alternative to stdin-only detach**  
`< /dev/null` at the `run-external-agent.sh` spawn is the right minimal fix and matches Decision 3. If Codex still inherits a controlling TTY session in edge environments, **`setsid` / `nohup` on the background child** (or closing FD 0 in the spawn subshell) is a stronger detach without per-caller changes—worth a one-line fallback note in `run-external-agent.md` if stdin redirect alone flakes in CI.

**6. [risk-integration] Codex marker ordering after `record_usage_from_events` is correct**  
Keep the marker after [`codex_launcher_record_usage_from_events`](scripts/launch-review.sh) (560–562) so parse-failure diagnostics are not overwritten; only the empty-success case gets `codex-status:`.

**7. [nit] `VOTER_2_STATUS=skipped` in the wait list appears unreachable**  
Nothing in current `dispatch-code-voters.sh` assigns `skipped` (grep shows only guards). Harmless but misleading in the new comment block.

**8. [nit] Testing strategy gap for the shared spawn layer**  
The plan relies on `test-dispatch-code-voters.sh` for stdin probing; [`test-run-external-agent.sh`](scripts/test-run-external-agent.sh) still has no stdin assertion. A small `TOOL_NAME=codex` case there would lock the Decision 3 “single entry point” contract independently of voter wiring.
