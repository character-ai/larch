# architectural-knowledge-IV [BUG] /design never persists an architectural-invariant assessment; the persist-design-assessment verb has no caller

From the 2026-07-09 audit of the architectural-knowledge features.

**Problem.** The CLI verb exists: `python/larch/cli.py` line 175 maps `("architectural-invariants", "persist-design-assessment")` to `invariants_persist_design_assessment_main`. The artifact name and atomic writer exist: `INVARIANT_DESIGN_ASSESSMENT = "architectural-invariant-assessment.md"` (`python/larch/core/architectural_guidelines.py` line 34) and `_write_invariant_design_assessment_atomic` (line 526). But no skill or script calls the verb:

```text
$ rg "architectural-invariants persist" skills/ scripts/
(no matches)
```

`skills/design/references/approval-gates.md` instructs `architectural-invariants present-note` plus a violation remediation loop (lines 151-190 at fb6d61294), and gives explicit persist instructions only for guidelines (lines 187-189: clean, deviation, and absent-or-invalid branches).

**Measured effect.** 0 of 29 design runs started since invariants gained real entries (PR #6635, merged 2026-07-08T19:53Z) committed `architectural-invariant-assessment.md`. 25 of those 29 committed the guideline assessment. No committed artifact proves the invariant check ran on any design run. The invariant tier is the one whose violations must block approval, and it has no design-side audit trail.

**Required change.**

1. Add the persist step to Gate C in `approval-gates.md`, mirroring the guideline contract exactly:
   - Clean: run `python/cli.py architectural-invariants persist-design-assessment --repo-root "$REPO_ROOT" --design-tmpdir "$DESIGN_TMPDIR" --assessment clean` (match the verb's real flag names; adjust prose to the implementation).
   - Violations found and remediated: write the final short assessment to a sidecar file and persist via `--assessment-file`, matching the guideline deviation branch shape.
   - Absent, invalid, or present-but-empty invariants: call with no assessment flags so stale artifacts are removed, matching the guideline absent-or-invalid branch.
   - Order: invariant persist before guideline persist, matching the existing present-note order.
2. Confirm the design flush includes `architectural-invariant-assessment.md` (the guideline analog already flushes). Add it to the allowlist if needed.
3. Extend the fail-closed completeness validator from the companion issue ("Approved /design runs silently miss the architectural-guideline assessment") to invariants: invariants `present` with at least one parsed entry and run approved means the artifact is required. Implement this issue after that one.
4. Pin the new Gate C prose in `scripts/test-design-structure.sh`.

**Acceptance criteria.**

- The next approved design run with non-empty invariants commits `architectural-invariant-assessment.md`.
- `rg "architectural-invariants persist" skills/` matches the new Gate C instruction.
- Validator tests cover the invariant branch: present+non-empty+approved+missing artifact fails; empty invariants file passes with no artifact.
