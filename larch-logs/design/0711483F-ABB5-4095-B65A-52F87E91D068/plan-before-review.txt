## Approach

1. Start with docs and prompt contracts.
   - Update Gate C persistence instructions first.
   - Then update Step 5c refusal docs.
   - Pin both with `scripts/test-design-structure.sh`.

2. Add publish-time enforcement.
   - Mirror the guideline check in `design_publish.py`.
   - Keep a parallel helper for invariants.
   - Use the parsed invariant content guard, not raw file existence.
   - Refuse invariant missing before guideline missing.

3. Add Step 5c KV plumbing.
   - Add invariant allow keys.
   - Preserve byte-stable existing guideline keys.
   - Add one new `STEP5C_STATUS` value.

4. Add degraded direct-publish audit trail.
   - Mirror the guideline warning in `design_log_publish_flow.py`.
   - Add summary prefixing in `design_summary.py`.
   - Use distinct marker files so either warning can be recorded independently.

5. Add committed run-log completeness.
   - Add invariant required-artifact logic in `run_log_manifest.py`.
   - Let existing execution-issue waiver logic cover the warning case.
   - Confirm flush already carries `architectural-invariant-assessment.md`. Only edit flush if a real allowlist blocks it.

6. Add tests beside the guideline tests.
   - Prefer small mirrored unit tests.
   - Do not backfill historical run logs.

## Edge cases

- Both invariant and guideline artifacts missing: publish refuses invariant first. After Gate C persists invariants, the existing guideline refusal can still catch a missing guideline artifact.
- Present invariant file with no parsed `I-*` entries: no artifact is required.
- Invalid invariant file: no artifact is required, and stale artifacts should be removed by the no-flags persist call.
- Missing marker symlink: summary and log-publish code must not follow it.
- Direct log publish can continue, but it must record the missing invariant artifact as a committed warning.

## Failure modes

- Gate C prose may call the wrong CLI flag shape. Pin exact commands in the structure harness.
- Step 5c may drop new KVs if allowlists are incomplete. Add tests for result-env and status-env propagation.
- Run-log completeness may over-require artifacts for empty parsed invariants. Test that empty parsed invariants pass.
- A warning that stays only in tmpdir would violate the audit trail. Test committed execution-issue waiver behavior.
