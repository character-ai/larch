### FINDING_2: Python ancestor skip may seed walk from dead probe subshell
- **Reviewer(s)**: Codex-Arch, Cursor-Innovation, Codex-Innovation, Codex-Pragmatic, Codex-Requirements
- **Severity**: important
- **Concern**: The planned Python `_collect_ancestor_pids` integration keeps the `sh -c` printf probe that captures the ephemeral subshell's `$$`. That subshell exits before ancestor walking runs, so `ps -p <shell_pid>` can be blank or stale, the skip set omits live ancestors (for example the bash launcher or a grandparent wrapper with `IMPLEMENT_TMPDIR` in argv), and `kill_session_background_processes` may still SIGTERM them. Making PPID-chain collection optional worsens the gap and leaves the Python parity fix incomplete.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Arch: Make ancestor collection from the probed PPID mandatory, or use os.getpid/os.getppid, and keep the current shell PID path only as best-effort extra coverage
  - From Cursor-Innovation: Seed _collect_ancestor_pids from os.getpid() (and merge probe PPID only if distinct). Do not start the walk from the subshell $$ returned by the probe.
  - From Codex-Innovation: Make collection from the probed PPID or os.getpid required, and assert the live process PID is walked
  - From Codex-Pragmatic: Make PPID-chain collection mandatory from the probed PPID, or collect the chain inside the probe shell before it exits. Update the unit test so it fails if only the transient shell PID is walked.
  - From Codex-Requirements: Make the plan require walking from the captured PPID, or collect the chain inside the same shell before it exits. Update the Python test to model the transient shell PID returning no `ps` row while the PPID chain contains the grandparent.
