### Edge cases

- Head-only legacy snapshots: keep existing preservation behavior; do not upgrade to full snapshots here.
- Missing snapshot: never stage the whole tree; treat as unscoped.
- Empty `post-coder-head.txt`: do not fall back to whole-tree capture for `since_committed=True`.
- Pre-lint baseline dirt: do not commit unless a lint-fix iteration reports that path.
- Unreported lint edits: leave them dirty rather than sweeping them into the lint commit.
- Path order: keep sorted output where current helpers promise stable order.

### Failure modes

- A lint-fix tool may omit `LINT_FIX_DELTA_PATHS` → `_lint_fix_delta_paths` returns no paths; the loop should avoid committing unrelated dirty paths.
- A degraded coder snapshot may produce no stage paths → the round may return `no-changes`; acceptable, since the primary fix is to prevent unsafe staging.
- A partial cleanup-verification failure may leave repo state after finalization → the regression should assert the workflow stops and logs the path-specific detail.

### Testing strategy

- Focused: `python3 -m pytest python/test_review_and_fix.py -k 'collect_round_stage_paths or lint_fix_delta_paths or step5_lint_fix or cleanup_verification'`
- Required: `make py-lint`, `make py-test`, then `make lint`.
- Expected: new OOS_1 and OOS_2 tests fail before and pass after; OOS_3 regression passes if code already handles partial verification, otherwise fix only the exposed cleanup control-flow bug.
