## Findings

### 1. Panel-tier growth test gap (correctness)

The plan’s **Failure modes** section says to add a test that grows a panel file and expects lint failure. The **Required tests** list under `python/tests/lint/test_lint_skill_closure_growth.py` never includes that case. It only covers panel scan composition, metric sums, and fail-closed missing/empty fixtures.

Acceptance requires `lint skill-closure-growth` to fail on panel-tier growth. Without a required growth test, the main ratchet contract for the new target is not verifiable. `test_baseline_check_fails_when_closure_lines_grow` today only exercises `design` (```401:408:python/tests/lint/test_lint_skill_closure_growth.py```).

### 2. follow SECURITY.md regression not mandated (correctness)

Failure modes call for sentence-bounded `follow` extraction and regression around the existing OOS/security example. Required classifier tests do not list a `follow SECURITY.md` case. The existing guard is MANDATORY-read shaped:

```341:362:python/tests/lint/test_lint_skill_closure_growth.py
def test_oos_pipeline_line_671_does_not_harvest_security_md(tmp_path: Path) -> None:
    """Regression for implement SKILL.md line 671 oos-pipeline bullet."""
    ...
```

Implement still uses `follow SECURITY.md` on the oos-pipeline path (```672:672:skills/implement/SKILL.md```). A new `follow` matcher could pass old tests while re-introducing SECURITY.md into closure.

### 3. Panel-tier double-count via follow (architecture / minimum-change)

```378:378:skills/implement/SKILL.md
**Main-agent scout manifest contract**: ... For non-empty manifests, follow `agents/_implementer-base.md` scout selection rules: ...
```

The plan’s new `follow <path>.md` pattern can match this line. `agents/_implementer-base.md` is already part of panel-tier (`agents/*.md`). The implement real-scan tests only assert positive `includes` for the three named hidden-eager files, not that `agents/_implementer-base.md` stays out. Baseline regen would silently absorb a double-count.

This works against minimum-change: panel edits would trip both panel-tier and implement ratchets.

### 4. Conditional gate not wired into implementation bullets (correctness)

The plan’s edge cases warn about overcount from `use`/`follow` and say conditional detection must run first. The `lint_skill_closure_growth.py` implementation section lists new patterns but does not require they go through `_line_is_conditional` (```294:311:python/larch/lint/lint_skill_closure_growth.py```).

High-risk lines include design clarify `follow skills/implement/SKILL.md` (```138:138:skills/design/SKILL.md```) and cancel-route `follow final-summary-emit.md` (```135:135:skills/design/SKILL.md```). Without an explicit wiring requirement, a follow-only code path could bypass the ratchet’s conditional model.
