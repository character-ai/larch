### FINDING_1: wrapper_rc=2 misclassification — launcher exit 2 is pre-spawn die(), not post-run validation failure
- **Concern**: The plan treats `wrapper_rc == 2` as a post-launch validation failure (e.g., dirty tree after fix) and maps it to the new "other" classification so the policy fires on cursor. In reality, all three CI launchers (`launch-cursor-ci.sh`, `launch-codex-ci.sh`, `launch-claude-ci.sh`) use `exit 2` only in their `die()` / argv-validation path BEFORE the tool actually runs (e.g., `launch-cursor-ci.sh:33-36`); the normal CLI completion path ends with `exit 0` and emits `LAUNCHER_EXIT=<code>` to convey the inner tool's exit code. Because the new classifier KVs are emitted at the bottom of the launcher script (after the normal-path exit-0 emit-block), a pre-spawn `die()` will exit before any KV is emitted. Consequently the `LAUNCHER_FAILURE_CLASS` KV will be ABSENT on wrapper_rc=2, and Edge case #2 defaults the missing class to `health`, contradicting the plan's stated policy ("validation-failure is classified as other"). Surfaced by 9 reviewers (cursor-arch, cursor-innovation, cursor-pragmatic, cursor-requirements, codex-arch, codex-edge F1, codex-innovation F2, codex-pragmatic, codex-requirements F1).
- **Proposed resolution**: Either (a) redefine the policy guard to key off `LAUNCHER_EXIT` plus the classifier KVs only (drop the wrapper_rc=2 carve-out entirely — argv validation failures predate the fixer and aren't a "first fixer failed" event the user policy addresses); OR (b) change the launchers' validation-rejection path to a separate non-die exit code (e.g., exit 4) AND emit `LAUNCHER_FAILURE_CLASS=other LAUNCHER_FAILURE_REASON=validation` before exiting. Update Edge case #3 ("Validation failure (wrapper_rc == 2)") accordingly. The simpler resolution is (a): treat wrapper_rc=2 as a launcher-internal usage error, NOT a first-fixer failure; the user's "first fixer failed for non-health reasons" framing applies to the tool actually running and producing an unhelpful result, not to argv mismatches in the wrapper.

### FINDING_2: "no actionable change" / "refusal to act" cannot be classified at the launcher boundary
