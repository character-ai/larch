## Approach

Use the approved narrow fix.

- In `_bind_step0_route_issue_env`, only call `_gap_fill_resume_route_state_values` when both `ISSUE_NUMBER` and `REPO` are missing.
- This preserves resume-like recovery paths.
- This blocks stale `.design-step0-route-state.env` `REPO` from filling a fresh explicit issue run.
- Let `step0_route_main` call `resolve_repo()` when the explicit issue is present and `REPO` remains unset.

- Assert the final route-state file contains `ISSUE_NUMBER=77` and `REPO=new/repo`, not the stale values.

## Edge cases

- Fresh explicit positional issue with stale route-state `REPO`: must resolve the current repo.
- Fresh explicit `--issue-number` should follow the same path because `ISSUE_NUMBER` is set before the guard.
- Resume-like paths with neither `ISSUE_NUMBER` nor `REPO` still gap-fill from route state.
- Verbal positional without an issue must still fail before stale route-state can revive an old issue.

## Failure modes

- If the guard is changed too broadly, resume recovery may lose persisted `ISSUE_NUMBER` or `REPO`.
- If the regression test only checks stdout, it may miss the wrong repo being passed to `gh issue view`.
- If the test leaves `REPO` in source env, it will not exercise the stale gap-fill path.
