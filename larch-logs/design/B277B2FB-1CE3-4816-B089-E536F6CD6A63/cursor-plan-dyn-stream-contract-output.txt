## Findings

**1. [correctness]** `skills/design/SKILL.md:991` — The plan’s “soft advisory” FD3 discipline does not pin the second breadcrumb used when mechanical churn downgrades the diff gate but a plan-body hard trigger still fires. Standalone Step 2b.5 and `plan-review-loop.sh` both emit that extra line before the hard Split prompt; a merged driver that only emits the under-threshold advisory form would silently drop operator context on rc 12.

**2. [risk-integration]** `scripts/test-design-structure.sh:40-87` — `assert_thin_fence` currently guards only assessor env reads. The plan adds it for Step 2b without extending the helper to block `.design-postplan-emit-result.env` parsing or `<<<"${_postplan_out:-}"` KV merge. A half-migrated fence could pass structure tests while still double-printing WARN bodies or leaking `WARN=`/`KEY=VALUE` lines beside `echo "$out"`. The plan should also explicitly retire the existing pins at lines 515–517 that *require* fat postplan parsing.

**3. [architecture]** `skills/design/scripts/design-postplan-emit.md:28-41` — The proposed `--with-plan-size` result-env contract extends beyond today’s emit/validate keys but the plan never enumerates the plan-size verdict fields that must land in `.design-postplan-emit-result.env`.
