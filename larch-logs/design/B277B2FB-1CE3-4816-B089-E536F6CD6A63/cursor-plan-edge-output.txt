**1. correctness** · `skills/design/scripts/plan-review-loop.sh:600-623` — The proposed `plan-review-loop.sh` update adds a `partition_requested=true` → `LOOP_STATUS=plan-size-trigger` handoff when no hard trigger fires, but it does not require `check-plan-size.sh` exit 0. Standalone Step 2b.5 returns before partition/hard branches on rc 2/3 (warn, log, continue without routing). If the loop applies the new partition rule after a failed size check (`hard` defaults false, `partition_requested` still true), it can incorrectly short-circuit to the plan-size Split path even though thresholds were never evaluated. **Suggested revision:** return early from `_run_post_apply_pipeline` on rc 2/3 before reading `partition_requested`; only surface `plan-size-trigger` when rc=0 and `HARD_TRIGGER_FIRED=false`. Add a harness case: `partition_requested=true` with forced rc 2/3 must not emit `LOOP_STATUS=plan-size-trigger`.
