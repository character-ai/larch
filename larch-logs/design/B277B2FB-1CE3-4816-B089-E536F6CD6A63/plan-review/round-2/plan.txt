### Summary

Add an additive `--with-plan-size` mode to `design-postplan-emit.sh` that runs `check-plan-size.sh` after a successful emit/validation and maps the merged emit + validate + plan-size verdict to thin-fence action exit codes. Prompt-side emit fences collapse to one driver call plus `echo "$out"` plus `case rc`, while `check-plan-size.sh` remains standalone-callable for retained callers.

Clean merged paths must preserve the legacy completion-sentinel effects: the initial Step 2b clean branch writes both `.completed/step-2b` and `.completed/step-2b.5` before Step 3, and re-entry/review clean branches write the same Step 2b.5 completion sentinel their legacy standalone plan-size pass would have written before continuing.

Merged thin-fence invocations and pause-save `exec` arms must preserve existing repo threading with `${REPO:+--repo "$REPO"}`. Hard/partition Split paths that return via Refine must explicitly write/update `.completed/step-2b.5` before continuing, because they no longer enter the retained standalone Step 2b.5 procedure on the merged path.

### Approach

- In `--with-plan-size`, after existing emit → optional HARD snapshot → validate:
  - `VALIDATE_STATUS=defects-found` exits **10** and skips plan-size.
  - Otherwise run `${PLUGIN_ROOT}/skills/design/scripts/check-plan-size.sh`.
  - Map size verdicts:
    - hard trigger (`HARD_TRIGGER_FIRED=true`) → **12**.
    - partition route (`partition_requested=true` and no hard trigger) → **13**.
    - clean/under-threshold → **0**.
  - invoke the nested plan-size subprocess with `LARCH_QUIET_DISABLE=1` and stdout-only capture, matching the retained standalone Step 2b.5 capture contract, so verdict KVs/WARN text do not disappear into the quiet log when the parent has initialized quiet mode.
- `check-plan-size.sh` rc 2/3 is nonfatal but must preserve the standalone Step 2b.5 diagnostics contract:
  - capture output to `check-plan-size.validation.log`;
  - append the same warning through the existing `append-tool-failure.sh` / `execution-issues.md` path used by Step 2b.5;
  - emit a display `WARN`;
  - treat the plan as under-threshold and exit **0**.
- Output discipline:
  - `--with-plan-size` writes KVs to `.design-postplan-emit-result.env`;
  - user-facing status, WARN bodies, soft advisory, under-threshold breadcrumb, and hard/partition sections go through `emit` on FD 3;
  - no `KEY=VALUE` lines are mirrored to FD 3 in `--with-plan-size`.
- Preserve failure-specific rc1 messaging:
  - before exiting **1** in `--with-plan-size`, the driver emits the existing human-readable failure line for missing `diff_lines`, emit failure, snapshot failure, or validator infrastructure failure;
  - thin fences may keep a generic rc1 abort because the specific diagnostic has already been printed.
- Pause in `--with-plan-size` returns **11**; the orchestrator thin fence `exec`s `design-pause-save.sh`. Non-flag pause behavior remains unchanged.
- Without `--with-plan-size`, the driver contract remains unchanged: exit codes `{0,1,2}`, `defects-found` exits 0, KVs mirrored to FD 3, and legacy pause behavior.

### Exit-code contract by site

All merged callers dispatch the same driver rc values, but site-specific action arms preserve existing prompt semantics.

- All merged fence preludes and rc 11 pause-save `exec` arms thread `${REPO:+--repo "$REPO"}` consistently with the Step 3.6 driver shape.
- **Initial Step 2b** (`--with-plan-size --snapshot-original`)
  - rc 0: write `.completed/step-2b` and `.completed/step-2b.5`, then Step 3.
  - rc 10: validator failure body; Fix-and-retry re-enters the same initial `--with-plan-size --snapshot-original` fence and redispatches rc; Override writes `.completed/step-2b`, then runs retained standalone Step 2b.5 before continuing.
  - rc 12: initial hard Split/Cancel prompt.
  - rc 13: Split path.
  - rc 11: `exec` pause-save.
  - rc 2 / rc 1: abort with existing config/op-failure handling.
- **Gate B shared post-apply pipeline** (`--with-plan-size`)
  - rc 0: write/update the Step 2b.5 completion sentinel, then Step 3.6.
  - rc 12: Gate B hard Split / Override / Cancel prompt.
  - rc 13: Split path.
  - rc 10: validator failure body for `--site design Step 3.5 / Gate B`; Fix-and-retry re-enters the same Gate B `--with-plan-size` fence; Override runs retained standalone Step 2b.5 with Gate B prompt semantics.
  - rc 11 / 2 / 1 as above.
- **discussion-round2 re-emit** (`--with-plan-size --force-validate`)
  - rc 0: write/update the Step 2b.5 completion sentinel, then return to Gate A.
  - rc 12: discussion hard Split/Cancel prompt.
  - rc 13: Split path.
  - rc 10: validator failure body for `--site design discussion-round2`; Fix-and-retry re-enters the same round-2 `--with-plan-size --force-validate` fence; Override runs retained standalone Step 2b.5 before returning.
  - rc 11 / 2 / 1 as above.
- **Step 1e Gate A optional-trailer re-entry rewrite**
  - use the same `--with-plan-size` thin-fence shape and rc arms as the discussion-round2 re-entry path, and pin this structurally.

The standalone Step 2b.5 procedure remains for Override-after-defects, Step 3 `LOOP_STATUS=plan-size-trigger`, and `plan-review-loop.sh`. Its hard-size prompt must be site-aware: initial/discussion routes use Split/Cancel; Gate B and plan-review-loop routes use Split/Override/Cancel.

For every rc 12/rc 13 merged Split path, the Refine-return branch must write/update `.completed/step-2b.5` before returning to Gate A or continuing, preserving the sentinel previously owned by the standalone Step 2b.5 procedure.
