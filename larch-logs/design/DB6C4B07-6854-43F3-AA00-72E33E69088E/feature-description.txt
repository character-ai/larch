# [py-code-quality] Read env once into a typed Ctx at _main boundaries

**Problem.** Environment variables are the ambient parameter bus (bash heritage): 660 `os.environ` references tree-wide (463 via `os.environ.get`), no central typed accessor. Worse, env is mutated as cross-step communication (`python/design_lifecycle.py` writes `os.environ[...]` at ~21 sites; run_logs/session_env mutate env as a side effect of parsing). Data flow is non-local, order-dependent, and tests must set process env.

**Proposed change.** Introduce a read-once typed `Ctx`/`Env` dataclass populated at each `_main` boundary and passed down explicitly. Incremental: new and refactored functions take `ctx`; legacy paths keep working. Build on the existing `config.ENV_*` name constants. Hotspots first: `python/agents.py` (127 reads), `python/design_lifecycle.py` (65), `python/plan_quality.py` (50).

**Out of scope / don't-touch.** Keep per-entrypoint `os.environ` save/restore in `*_core` (required because `cli.py` runs multiple commands in one process). Keep the `.sh` env-file wire format.

**Acceptance.** A typed `Ctx` exists and is adopted at the hotspot `_main` boundaries; new code reads env via `Ctx`, not raw `os.environ`; units green.

**Effort / risk.** Medium / medium. Incremental; no big-bang.

**Dependencies.** Root (no blockers). Independent.
