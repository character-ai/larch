## Edge cases

- **Pipelines:** Keep `cmd | grep PATTERN` and `cmd | rg PATTERN` allowed. The stdin source is finite and not the first blocking command.
- **Producer-side pipes:** Reject `rg PATTERN | head`; truncate argv at `|` before path detection.
- **Suffix operators:** Reject `rg PATTERN || true`; truncate argv at `||` before path detection so `true` is not mistaken for a path.
- **Redirects:** Truncate at `>`, `>>`, `<`, etc. before path walks; allow `command grep -v PAT "$FILE" > tmp || true` when `$FILE` is a path operand before the redirect.
- **Explicit stdin:** Allow `< /dev/null`. Require a pragma for intentional stdin-search fixtures.
- **Subshells and command wraps:** Reject `( rg PATTERN )`, `( command grep PATTERN )`, and `{ rg PATTERN; }` without a path because they still read stdin in background mode.
- **Brace groups:** `{ command rg -n PATTERN; }` without a path is a violation.
- **Option values:** Do not count `--type py`, `-t py`, or similar option values as paths.
- **Indentation:** Match grep-family probes with leading whitespace inside fences (parity with existing indented bare `grep` case 17).
- **Existing bare grep:** Do not weaken the current wrapper-exit trap.
- **False positives:** Prefer a narrow, reviewable pragma over allowing ambiguous no-path forms.

## Failure modes

- The awk parser may miss complex multi-line shell constructs.
- A rare option not in the skip list may cause a false path or false violation.
- A line with unusual quoting may need a pragma.
- Unquoted terminators inside quoted strings could truncate argv incorrectly; acceptable given the line-based lint model.
- These are acceptable because the existing lint is already line-based and shape-based.
