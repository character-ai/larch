## Edge cases

- **Pipelines:** Keep `cmd | grep PATTERN` and `cmd | rg PATTERN` allowed. The stdin source is finite and not the first blocking command.
- **Producer-side pipes:** Reject `rg PATTERN | head`; truncate argv at `|` before path detection.
- **Suffix operators:** Reject `rg PATTERN || true`, `rg PATTERN && true`, `rg PATTERN; echo done`, and `rg PATTERN |& cat`; truncate argv at `||`, `&&`, `;`, `&`, and `|&` before path detection so suffix tokens are not mistaken for paths.
- **Background operator:** Reject `rg PATTERN &`; truncate argv at `&` (and `|&` when present) before path detection so a trailing background job token is not mistaken for a path.
- **Redirects:** Truncate at `>`, `>>`, and other redirects before path walks, but **not** at the stdin-safe `< /dev/null` form; evaluate unquoted `< /dev/null` on the candidate command segment before truncation. Allow `command grep -v PAT "$FILE" > tmp || true` when `$FILE` is a path operand before the redirect.
- **Explicit stdin:** Allow only unquoted `< /dev/null` on the candidate command via pre-truncation short-circuit. Reject lines where `< /dev/null` appears only inside quotes, inline comments, or after `;`. Require a pragma for intentional stdin-search fixtures.
- **Subshells and command wraps:** Reject `( rg PATTERN )`, `( ripgrep PATTERN )`, `( grep PATTERN )`, `( command grep PATTERN )`, and `{ rg PATTERN; }` without a path because they still read stdin in background mode.
- **Brace groups:** `{ command rg -n PATTERN; }`, `{ command ripgrep -n PATTERN; }`, `{ grep -n PATTERN; }`, and `{ command grep -q PATTERN; }` without a path are violations; grouped forms with explicit paths are allowed.
- **Option values:** Do not count `--type py`, `--type=py`, `-t py`, `-A3`, or similar option values as paths.
- **Indentation:** Match grep-family probes with leading whitespace inside fences for both `rg` and `ripgrep` (parity with existing indented bare `grep` case 17).
- **Env prefixes:** Leading assignments such as `LC_ALL=C` must not prevent path detection on later argv tokens; env-prefixed no-path probes remain violations.
- **Existing bare grep:** Do not weaken the current wrapper-exit trap.
- **False positives:** Prefer a narrow, reviewable pragma over allowing ambiguous no-path forms.

## Failure modes

- The awk parser may miss complex multi-line shell constructs.
- A rare option not in the skip list may cause a false path or false violation.
- A line with unusual quoting may need a pragma.
- Unquoted terminators inside quoted strings could truncate argv incorrectly; acceptable given the line-based lint model.
- A naive full-line `< /dev/null` substring match could false-allow no-path probes when the redirect appears only in a later quoted echo or inline comment; mitigated by requiring an unquoted redirect on the candidate command segment and rejecting comment-suffix forms.
- These are acceptable because the existing lint is already line-based and shape-based.
