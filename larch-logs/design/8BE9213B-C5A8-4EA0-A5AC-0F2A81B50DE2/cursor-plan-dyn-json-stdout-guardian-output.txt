## Findings

**1. [correctness] `skills/implement/scripts/step-8-ship.sh` — inline phantom pattern is unsafe here**

Plan bullet at `### UPDATED: skills/implement/scripts/step-8-ship.sh` (lines 108–116) says to run the probe before `ship pr` and redirect stdout to stderr. It does not say that the existing inline pattern in `step-2-post-dispatch.sh` is forbidden for this wrapper.

`step-2-post-dispatch.sh` calls `phantom_probe_with_warn` in-process (lines 30–30). That is fine there because that wrapper’s stdout is a KV contract (`BRANCH=`, `COMMIT_SHA=`, `PHANTOM_*`). `step-8-ship.sh` today emits only JSON on stdout (lines 72–73, 75–91). An unredirected inline call would let `emit_kv` write `PHANTOM_*` to stdout (`scripts/lib-quiet.sh:186-187`) and corrupt the JSON contract.

**Suggested revision:** State explicitly that `step-8-ship.sh` must not copy the inline `phantom_probe_with_warn` call; use a subprocess with `>&2`.

---

**2. [risk-integration] `skills/implement/scripts/test-step-8-ship.sh` — substring checks won’t catch stdout pollution**

Plan lines 124–131 add ordering and redirect assertions but still align with the current harness style (`assert_contains '"outcome":"OK"'` at `test-step-8-ship.sh:65`). That passes even when stdout is multiple lines (probe KV + JSON).

This feature introduces a new risk-bearing path: probe output on the same wrapper stream as ship JSON.

**Suggested revision:** Add behavioral tests with a stub phantom that prints `PHANTOM_STATUS=…` to stdout; assert those lines land on wrapper stderr, wrapper stdout is exactly one line, `jq -e .` succeeds, and no `^PHANTOM_` prefix on stdout. Cover both the success path and the stale-Python STALLED JSON path (lines 67–80).

---

**3. [correctness] `skills/implement/scripts/step-8-ship.sh` — redirect direction needs a concrete example**

“Redirect the probe stdout to stderr” does not pin shell semantics. `2>&1` on the probe call would funnel stderr into stdout and break parsing the same way an unredirected probe would.

**Suggested revision:** Show the exact pattern `… phantom-probe-with-warn.sh --step 8-pre-ship >&2` and note that `2>&1` must not be used on that invocation.
