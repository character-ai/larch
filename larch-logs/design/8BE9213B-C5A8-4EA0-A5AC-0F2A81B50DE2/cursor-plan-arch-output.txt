## Findings

### 1. Stall seed must keep `MERGE=false` / `DRAFT=false` overrides (correctness)

`skills/implement/references/step5-review-branches.md` today forces `MERGE=false` and `DRAFT=false` on the missing-state stall seed path. The plan replaces that block with `step-8-seed-initial.sh` stall flags only and session reads for merge/draft. That changes behavior for `--merge` / `--draft` runs that stall at Step 5.

### 2. `EXPECTED_SESSION_ID` must come from `session-id`, not `session-env.sh` (correctness)

Bootstrap writes `session-id` but does not put `EXPECTED_SESSION_ID` in `session-env.sh`. `step-8-ship.sh` already reads the id file for `--expected-session-id`. The seeder wrapper plan does not pin that same source, so seeded state can omit the session binding Step 18 cleanup relies on.

### 3. Pre-driver routing should be mechanical, not orchestrator judgment (risk-integration)

The pre-driver vs post-driver split is documented in `SKILL.md` but enforced only by orchestrator interpretation of `ship-pr-state.sh`. A misread on the `oos file` failure retry path skips `oos file`, which is a documented breakage mode. A thin route script or a single pre-driver wrapper would close that gap without expanding feature scope.
