1. **[risk-integration]** `docs/installation-and-setup.md:30-44` — The proposed **Upgrade / operator notice** says unset-env operators switch drivers on the “next plugin upgrade,” but the selector is prompt-side in `skills/implement/SKILL.md` and runs from the **cached** plugin tree. The same doc already requires restart when a new version is installed (`docs/installation-and-setup.md:38`) and explains that `/implement` keeps using the older cached copy until refresh (`docs/installation-and-setup.md:77-82`). Without tying those together, the notice can overstate how soon the flip lands. **Suggested revision:** State that the Python default applies on the first `/implement` after the upgraded plugin is actually loaded (restart when `/upgrade-larch` installs a new version), and that `LARCH_SHIP_PR_IMPL=bash` must be set in the environment before starting Claude Code to pin legacy shipping during rollout.
