## Edge cases

- Marker lines may contain horizontal whitespace already accepted by `issue_wire`.
- Marker text embedded within prose, a longer comment, or split across physical lines must not count.
- Marker recognition remains case-sensitive.
- Missing, reversed, or duplicate markers must not make `/design` report `already-planned`.
- Empty but valid named blocks count as present because `parse_named_block` returns an empty string rather than `None`.
- `/learn-from-bugs` must still cut at `## Plan`, `## Approach`, or file headings when no valid marker appears.

## Failure modes

- A consumer may accidentally retain its old literal or regex while adding the shared call. Use targeted tests and a final grep to catch residual bypasses.
- An implementation may use `\s*` in the public multiline regex, allowing a marker to span lines while internal line parsing rejects it. Keep whitespace horizontal and test the split-line negative case.
- `compose_named_block` normalizes trailing inner newlines, so attempting byte-for-byte preservation of the old manually composed placeholder would reintroduce marker ownership drift. Golden-pin the new canonical fenced output instead.
- Router code may test parsed inner text by truthiness. This would reject a valid empty block. Test presence with `is not None`.
- Broad changes to `design-pause` or plan grammar would exceed the approved scope.
