## Edge cases

- Marker lines may contain the whitespace already accepted by `issue_wire`.
- Marker text embedded within prose or a longer comment must not count.
- Marker recognition remains case-sensitive.
- Missing, reversed, or duplicate markers must not make `/design` report `already-planned`.
- `/learn-from-bugs` must still cut at `## Plan`, `## Approach`, or file headings when no valid marker appears.
- Empty but valid named blocks still count as present because `parse_named_block` returns an empty string rather than `None`.

## Failure modes

- A consumer may accidentally retain its old literal or regex while adding the shared call. Use targeted tests and a final grep to catch residual bypasses.
- `compose_named_block` integration may add or remove a newline around the fenced placeholder. Pin the rendered partition text.
- Router code may test the parsed inner text by truthiness. This would reject a valid empty block. Test presence with `is not None`.
- The new multiline regex may lose full-line anchoring if it is rebuilt separately. Reuse the existing marker expression.
- Broad changes to `design-pause` or plan grammar would exceed the approved scope.
