# Implementation Plan — #3420: thin Step 0b (cancel/resume into drivers)

## Goal

Move the non-LLM rendering of Step 0b's two consumption fences out of `SKILL.md` and into the phase drivers, so each driver emits a single STATUS + exit code and the orchestrator fences collapse to capture → emit driver output → branch into only the genuinely-LLM routes (proceed/tier, clarify loop, already-planned prompt, resume continuation). Behavior across all seven routing outcomes is preserved; only WHERE the rendering happens moves.

## Approach

Two phase drivers already own routing/init logic and emit a result-env + stdout KV contract via `lib-phase-driver.sh` (`emit_kv`, `phase_driver_write_result_env`, `larch_err`). This change extends each driver to also own the operator-facing rendering that currently lives inline in `SKILL.md` Step 0b, then thins the SKILL.md fences.

Key moves:
- `design-route.sh` gains ownership of: the `cancel-title-filter` / `cancel-reentry-guard` summary rendering (`render-final-summary.sh`), the reentry-guard banner composition (MARKER_REMAINING math + message), and the `resume@*` env refresh (`write-design-current-env.sh`).
- `design-init-runparams.sh` gains ownership of its two failure banners (contract-drift, env-refresh-failed) — it already sets `INIT_STATUS` and exits 1; it will additionally print the detailed operator message itself.
- `SKILL.md` Step 0b: both consumption fences shrink. The `case "$ROUTE"` keeps its branch labels (Check 24 ordering pin), but each cancel/resume branch body collapses to "emit driver output / final-summary.md verbatim, then propagate the exit". The init fence collapses to capture → read STATUS → propagate.

Banner text fidelity: equivalent rewording is allowed (Round 1 Decision 3); functional behavior (routing outcomes, exit codes, which artifacts written, which GitHub side effects fire) is preserved.

### Critical hazard — render-final-summary.sh stdout vs. the KV contract

`render-final-summary.sh --post-publish-only` does **print + upsert + file** (it prints the summary to stdout, upserts the GitHub summary comment, and writes `final-summary.md`). Today the inline cancel branches run it un-captured, so its print reaches chat. Inside `design-route.sh`, the driver's stdout IS the KV result-env contract consumed by `_route_out=$(...)`; an un-redirected summary print would pollute that stream. The driver MUST redirect `render-final-summary.sh` stdout away from the KV stream (e.g. to a log / `/dev/null`) while preserving the upsert + `final-summary.md` side effects, and the orchestrator emits `final-summary.md` verbatim for the chat "print" (it must do this anyway per the anti-halt verbatim-emit rule). Banners that must surface directly go to the driver's **stderr** (not captured by the stdout command substitution), matching today's `>&2` cancel banners.

### design-route.sh gains `--session-id`

`render-final-summary.sh` reads `SESSION_ID` (→ RUN_ID) from env. On the fresh-run cancel routes the route driver currently has no SESSION_ID (it only learns one from `design-pause-load.sh` on resume). Add a required `--session-id` arg to `design-route.sh` (symmetric with `design-init-runparams.sh`), threaded from the orchestrator's Step 0a `$SESSION_ID`. The resume env-refresh continues to use the pause-loaded SESSION_ID internally.

## Edge cases
- **render-final-summary stdout pollution**: covered above — driver must redirect its stdout; the KV result-env stream must stay clean so the orchestrator parse is unaffected.
- **Empty SESSION_ID on cancel routes**: `render-final-summary.sh` falls back to RUN_ID="unknown"; threading the real `--session-id` preserves today's run-id in the summary. If the orchestrator passes empty, behavior degrades gracefully (unchanged from today).
- **resume env-refresh failure**: must still abort before the resumed step with a clear message and a non-success signal; do not silently continue into the resumed step with a stale env.
- **Brainstorm-prefix banner**: stays orchestrator-side (it mutates the mental `brainstorm_requested` flag); do not move it into the driver.
- **cancel-pause-load**: no summary is rendered today (only a banner + exit 1); keep it that way — do not add a render-final-summary call.
- **Stale docs/prose**: grep `docs/`, `README.md`, `SECURITY.md` for prose referencing the inline Step 0b cancel/resume rendering or SKILL.md line numbers (drift-prone-prose rule); update or remove stale references.

## Failure modes
- **KV stream pollution → mis-parse**: if the driver fails to redirect render-final-summary stdout, the orchestrator could bind a wrong/extra key or mis-route. Earliest signal: harness assertion on a clean result-env, plus a manual cancel-title-filter dry-run showing the summary once (not duplicated/garbled). Mitigation: redirect at the call site; assert the result-env contains only allowlisted keys.
- **Lost GitHub upsert**: if the driver switches to `--pre-publish-only` (file-only) to avoid the print, the summary GitHub comment upsert is lost. Mitigation: keep `--post-publish-only` and redirect stdout, not switch the phase flag.
- **Exit-code contract drift**: changing the driver's `0/1/2` contract would ripple into FINDING_2/3/5/9 pins and the orchestrator branches. Mitigation: keep cancel routes as `ROUTE=cancel-*` (exit 0) with the orchestrator owning the exit-1 propagation; if resume-refresh failure needs a non-zero driver exit, document and pin it explicitly.
- **Pin under-coverage**: a moved banner with no relocated pin would let future drift go unnoticed. Mitigation: every moved string gets a driver-side pin; every removed SKILL.md pin is replaced, not deleted.
