## Edge cases

- Missing or invalid architecture files must leave the compliance and `arch` prompts usable without empty policy sections.
- TRIVIAL must still receive invariants but not guidelines.
- Dynamic plan-review prompts must not inherit policy merely by using an architecture focus area.
- Cache hits must not reuse a compliance prompt for another specialist.
- Absent vendors and round-two pruning must account for the new slot through existing per-slot machinery.

## Failure modes

- A broad renderer call could continue leaking policy into every reviewer.
- A stem or slug mismatch could create the slot but omit its policy context.
- Stale generated agents or pre-rendered bodies could preserve the removed carve-out.
- Unchanged fixed-count tests or docs could misstate the expanded panel.
- Missing scout reservations could duplicate compliance coverage and waste a panel slot.

## Testing strategy

- Run the focused rendering, role-default, review-pipeline, and plan-scout pytest files.
- Run `python3 python/cli.py generate pre-rendered-reviewer-prompts`, the affected reviewer generators, and `python3 python/cli.py generate topology-docs`.
- Run `python3 python/cli.py generate check`.

- Grep reviewer prompts and generated bodies to confirm the architectural carve-out remains only in the compliance specialist.
- Exercise rendered prompts at TRIVIAL and HARD tiers for the compliance specialist, an ordinary specialist, `/design` `arch`, and a non-Arch plan reviewer.
