## Approach Synthesis

Codex-Generic produced a substantive sketch; Cursor-Generic returned only self-narration (162 bytes, logged as a Warning in `execution-issues.md`). The orchestrator acts as the second perspective during synthesis. The two perspectives converge on the same overall shape, so contested decisions are limited.

### Convergent decisions (both perspectives agree)

1. **Centralized stall recovery gate in `skills/implement/SKILL.md`, entered before Step 18 teardown.** Every existing bail path that sets `STALL_TRACKING=true` and skips to Step 18 should instead route through a new "recovery gate" step that lives between stall detection and `implement-finalize.sh teardown`. The gate is the single ingress for the new flow.

2. **Classify the stall from durable state, not chat memory.** Inputs: `$IMPLEMENT_TMPDIR/ship-pr-state.sh` (`PHASE`, `STALL_STEP`, `BAIL_REASON`), `$IMPLEMENT_TMPDIR/execution-issues.md` (categorized failures), `FAILURE_DETAIL_LOG` captures from `ship-pr.sh` exit 4, and recent tool stdout. The classifier maps these inputs to a failure class (transient-infra, same-cause-repeat, test-failure, lint-failure, dispatch-failure, contract-failure, unrecoverable).

3. **Failure-class-dependent retry caps** (codify Round 1 decision 6):
   - `transient-infra` (gh API errors, network, rate-limit): up to 4 retries with ~5s delay between attempts.
   - `same-cause-repeat` (the same root signature recurs after a recovery attempt): one alternate-strategy retry (e.g., re-read `larch:plan` and restart the stalled step from scratch instead of resuming partial state), then fall through to `[STALLED]`.
   - `test-failure` / `lint-failure`: higher per-class cap; iterate until clean checks or cap reached.
   - `unrecoverable` (missing binary, auth failure, broken precondition): no retry — go straight to terminal-failure comment + `[STALLED]`. Manual takeover cannot fix missing tools.

4. **Environment-conditional issue filing** (codify Round 1 decision 2):
   - Detect larch-clone via the `check-stale-plugin.sh` marker (working-tree root contains `skills/implement/SKILL.md`). Factor the predicate into a tiny shared helper to avoid duplicating logic.
   - **Larch clone**: invoke `/larch:issue` to file a single bug issue in the larch repo on first stall detection; post a follow-up comment with retry outcomes on terminal failure.
   - **Consumer repo**: print a chat message to the operator with a pre-formatted concise generic description that the operator can paste into a manually-filed larch issue.

5. **Allowlisted sanitization, not post-hoc redaction.** The report builder constructs the bug report from an explicit allowlist of safe fields — failing larch script/skill, step number, `STALL_STEP`, failure class, error class, exit code, error pattern hash — never raw command stdout, raw file paths, or raw line content from the consumer repo. `redact-secrets.sh` remains the mechanical backstop for anything that does flow through.

6. **Reuse existing primitives.** No new state file: reuse `ship-pr-state.sh` keys (`PHASE`, `STALL_STEP`, `STALL_TRACKING`, etc.). No new issue API: use `/larch:issue`. No new sanitization: use `redact-secrets.sh`. The new code is glue + classifier + report builder.

7. **Helper placement**: a single new script `skills/implement/scripts/stall-recovery-report.sh` (with `.md` contract sibling) handles classification, RCA assembly, sanitized report build, larch-clone branch, and `/larch:issue` invocation contract. The SKILL.md orchestration contract calls into it.

8. **Resume from the stalled step** (codify Round 1 decision 5). After a successful recovery attempt, the orchestrator clears the in-memory `STALL_TRACKING` flag and re-enters the existing `/implement` flow at the appropriate step (Step 2 for impl, Step 5 for review, Step 6 for checks, Step 8 for ship-pr, etc.). The mapping is driven by `STALL_STEP` in `ship-pr-state.sh`.

9. **`[STALLED]` rename is now the late-failure path only.** On successful recovery, the issue eventually transitions to `[DONE]` via the normal lifecycle. `[STALLED]` only appears when recovery itself exhausted retries (codify Round 1 decision 4 and 8).

10. **Files to modify** (convergent):
    - `skills/implement/SKILL.md` — add the recovery-gate step before Step 18; route every existing `STALL_TRACKING=true` bail through it.
    - `skills/implement/scripts/stall-recovery-report.sh` (NEW) — classifier + report builder + clone detection + filing dispatch.
    - `skills/implement/scripts/stall-recovery-report.md` (NEW) — contract sibling.
    - Possibly `scripts/check-stale-plugin.sh` — factor a `is-larch-dev-clone` helper if shared use grows (or inline the marker check in the new script).
    - Tests: a new `skills/implement/scripts/test-stall-recovery-report.sh` (hermetic harness) covering classifier branches, larch-clone vs consumer-repo paths, allowlisted field generation.

### Risks (convergent)

- **Prompt-complexity risk**: SKILL.md is already very large. The recovery-gate prose must be tight and reuse existing breadcrumb/anti-halt patterns.
- **Contradictory hard-stop policy at Step 8 (`STALL_STEP=6` / `PHASE=checks`)**: the existing `ship-pr.sh` exit-4 path is currently documented as "no main-agent edits after lint-fix exhaustion" — the new feature deliberately overrides that for the recovery attempt. The orchestrator must rewrite that prose carefully without breaking the existing invariant on the `ship-pr.sh` side.
- **IP leakage**: prevent at design time by allowlisting fields, not by post-hoc scrubbing.
- **Retry cap calibration**: conservative defaults; if too aggressive, recovery loops chew tokens; if too restrictive, easy stalls trip terminal failure unnecessarily.

### Marginal contested decisions

There is no strong disagreement between the two perspectives. The only marginal contention is about whether `ship-pr.sh`'s exit-code table itself should be extended (Codex's framing) or whether the orchestrator-side recovery gate is enough (orchestrator framing). This is not a fundamental architectural split — both can coexist — so it is recorded as a single low-impact contested decision.
