### FINDING_1: Persist failure can leave stale result env and block fallback
- **Reviewer(s)**: Cursor-Innovation
- **Severity**: important
- **Concern**: If `phase_driver_write_result_env` fails after `.step3-review-result.env` already exists with only round-body keys, `read-result-env.sh` may treat that stale file as primary input and skip stdout fallback. The orchestrator can then miss `STEP3_REVIEW_LOOP_STATUS`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: In the `if ! phase_driver_write_result_env ...` branch, `rm -f "$result_env"` after emitting the warning so `design-step3-review.sh` falls back to captured stdout

### FINDING_2: Optional safe args need arity checks, not value checks
- **Reviewer(s)**: Cursor-dyn-caller-contract
- **Severity**: important
- **Concern**: The plan needs `$#`-based checks for optional sanitized arguments. Empty safe values are distinct from omitted arguments, and value-based checks can recompute from unsafe globals containing CR/LF.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-caller-contract: Specify and implement [[ $# -ge 5 ]] / [[ $# -ge 6 ]] (or equivalent shift-aware counting) before choosing passed safe values vs in-function recomputation; add a harness case with unsafe global CR/LF, empty safe arg at $5, and $#=6

### FINDING_3: Write-failure test does not reach the write-failure path
- **Reviewer(s)**: Cursor-dyn-test-harness-fidelity
- **Severity**: important
- **Concern**: The planned write-failure test calls `step3_loop_emit_envelope` without its required four arguments. Under `set -e`, that can fail before `phase_driver_write_result_env` runs, so the intended symlink write-failure behavior is not exercised.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-test-harness-fidelity: Use `step3_loop_emit_envelope complete 1 1 1` (or another valid terminal status) with `.step3-review-result.env` symlinked first
