# [BUG] (URGENT) step3_loop_persist_envelope silently drops result env on KV-newline; orchestrator blind to loop status

## Summary

During `/design #4110`, the plan-review loop completed a full round (10 reviewers, plan revised by Codex), but the design orchestrator could not determine the loop status (`main-agent-vote-required`). The run required manual main-agent adjudication and produced an empty background-task output file, leaving the orchestrator blind.

## Root Cause

`step3_loop_persist_envelope` in `skills/design/scripts/review-design-step3-loop.sh:135` silently ignores `phase_driver_write_result_env` failures:

```bash
phase_driver_write_result_env "$result_env" "${kvs[@]}" || true
```

`phase_driver_write_result_env` in `skills/design/scripts/lib-phase-driver.sh:77-82` rejects any KV value containing a newline or carriage return and returns 1:

```bash
case "$kv" in
    *$'\n'* | *$'\r'*)
        larch_err "lib-phase-driver: refusing to write result env value containing newline or carriage return"
        rm -f "$tmp"
        return 1
        ;;
esac
```

When this returns 1, the `|| true` swallows the failure. `.step3-review-result.env` is never written.

## Cascade

After `step3_loop_emit_envelope main-agent-vote-required ...` silently fails to write the result env, `run_design_step3_loop` calls `exit 0` (line 483), which terminates the entire shell process — including `run-step3-review.sh`. The KV-emit code in `run-step3-review.sh` (lines 379-413, which also write to `.step3-review-result.env`) **never executes**.

`design-step3-review.sh` then runs `read-result-env.sh` with:
- `--input "$DESIGN_TMPDIR/.step3-review-result.env"` (absent → fallback)
- `--fallback-input "$_plan_review_stdout_file"` (empty, since `run-step3-review.sh` writes `emit_kv` output to FD 3 / quiet channel, not stdout)

Both sources are empty. `read-result-env.sh` produces an empty parsed env. All loop status variables (`LOOP_STATUS`, `STEP3_REVIEW_LOOP_STATUS`) remain unset. The background task output file is empty.

## Impact (observed run)

- Design run for issue #4110 produced a ballot (`ballot.txt` = 3292 bytes) but `voting-tally.md` remained empty.
- Orchestrator had no way to detect `main-agent-vote-required` automatically.
- Required manual inline vote + re-tally (two failed tally attempts due to wrong voter file format).
- The second tally run cleared `ballot.txt` and `findings.md` (both zeroed at 12:04) — the exact mechanism is unclear but the effect is the ballot was lost.
- Two OOS items (OOS_1, OOS_2) voted YES by the main agent were not filed because `oos-accepted-design.md` was cleared by the tally.
- The session tmpdir was preserved (not cleaned up) because `.design-publish-result.env` was also never written.

## Steps to Reproduce

Any `/design` run where:
1. The plan-review tally returns `main-agent-vote-required` (0 external judges available), AND
2. Any value in `step3_loop_persist_envelope`'s `kvs` array contains a newline or carriage return.

The newline-containing value is most likely one of:
- `PLAN_REVIEW_CONTINUE_REASON` (set from reviewer output)
- `SCOPE_ANCHOR_FILE` (file path — unlikely on most systems but possible)
- Any other `emit_kv`-sourced variable set from external agent output

## Suggested Fixes

**Fix A (minimal — change `|| true` to fail-forward):**

In `skills/design/scripts/review-design-step3-loop.sh:135`, replace:
```bash
phase_driver_write_result_env "$result_env" "${kvs[@]}" || true
```
with:
```bash
if ! phase_driver_write_result_env "$result_env" "${kvs[@]}"; then
    emit "**⚠ step3_loop_persist_envelope: failed to write result env (${result_env##*/}); loop status may be unrecoverable**"
    emit_kv WARN "step3_loop_persist_envelope: phase_driver_write_result_env failed"
fi
```

This at least surfaces the failure via FD 3 (quiet channel) so it appears in execution issues.

**Fix B (robust — sanitize KV values before write):**

Before building `kvs` in `step3_loop_persist_envelope`, strip newlines from any value that could contain multi-line content:
```bash
PLAN_REVIEW_CONTINUE_REASON="${PLAN_REVIEW_CONTINUE_REASON//$'\n'/}"
SCOPE_ANCHOR_FILE="${SCOPE_ANCHOR_FILE//$'\n'/}"
```
Or add a shared `sanitize_for_kv_value` helper that replaces `\n` and `\r` with spaces.

**Fix C (defense-in-depth — detect empty result env in orchestrator):**

In `design-step3-review.sh`, after `read-result-env.sh` produces an empty result and all loop status variables are empty, emit a hard warning and default to `panel-failed` so the orchestrator always emits a non-empty task output:
```bash
# After lines 175-206 in design-step3-review.sh, add:
if [[ -z "${LOOP_STATUS:-}" &amp;&amp; -z "${STEP3_REVIEW_LOOP_STATUS:-}" ]]; then
  printf '%s\n' "**⚠ Step 3: result env absent AND stdout empty after run-step3-review.sh — possible phase_driver_write_result_env failure; treating as panel-failed**"
  LOOP_STATUS=panel-failed
fi
```

**Recommended**: Apply Fix B + Fix C together. Fix B prevents the failure at the source; Fix C makes the orchestrator resilient to any future env-write failure.
