**1. [correctness] Post-loop branch matrix points at the wrong result file** (`skills/design/SKILL.md:1000`)

The plan creates `.step3-review-result.env` as the orchestrator handoff, but the UPDATED SKILL.md bullet says to keep the post-loop branch matrix prose unchanged while Approach says the matrix should read the normalized file. The matrix header still says read `.step3-plan-review-result.env` first. That inner file is written by `plan-review-loop.sh` and lacks driver-level normalization (cap-reached KVs, round-count rollback, unknown-status coercion).

**2. [correctness] `set +e` wrapper changes HARD cursor failure from hard abort to soft continue** (`skills/design/SKILL.md:917-930`)

Cursor-advance failure uses `exit 1` before the loop. In today's inline fence that aborts Step 3 because it runs under default `set -e`. The proposed fence wraps the whole driver in `set +e` and only captures rc. The plan does not say to stop Step 3 when the driver exits non-zero before writing `.step3-review-result.env`.

**3. [correctness] SKILL.md driver invocation omits required argv** (plan `skills/design/SKILL.md` UPDATED section)

`run-step3-review.sh` is specified to take `--round-cap` and `--convergence-threshold` from the orchestrator and not re-read env. The SKILL.md update section names the script call but not those flags. Without an explicit fence, env expansion can drop out of the orchestrator boundary.
