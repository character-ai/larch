**Finding 1 — detail**

The plan (§ `### UPDATED: skills/review-and-fix/scripts/review-and-fix.sh`, Nit counter paragraph) says:

> "add a helper to count `**Nit**`-severity findings in a round's `findings.md` … Derive non-nit accepted = `accepted_count − nit_count`"

`findings.md` at `$IMPLEMENT_TMPDIR/round-N/findings.md` is the **pre-classifier** findings file: it contains every finding the panel surfaced, both accepted and rejected. `accepted_count` is the **post-classifier** count from `review-core.env:ACCEPTED_COUNT`. Subtracting the total nit count (all findings) from the accepted count (accepted findings only) underestimates `non_nit_accepted` whenever the classifier rejects any nit-severity finding.

The existing `count_high_severity_accepted` (lines 122–129) already demonstrates the correct pattern: it scans `accepted_file` (the accepted-findings.md passed explicitly) — not `findings.md`. The plan cross-references this function ("mirror … `count_high_severity_accepted`") but then prescribes `findings.md`, contradicting the function it cites.

The `/design` loop's analogous nit counter is unaffected: it correctly proposes `_count_nit_findings` on `accepted-plan-findings.md` — the same file `ACCEPTED_COUNT` and `IMPORTANT_ACCEPTED_COUNT` already use.

**Suggested fix**: replace the `findings.md` reference in the nit-count step with `accepted_file` (the variable already in scope, defaulting to `$round_dir/accepted-findings.md`). The `**Nit**` marker string is correct and requires no change; only the source file changes to align nit count and accepted count on the same population.
