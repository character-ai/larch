## Approach

- **Reuse, don't duplicate.** The deterministic drop/rebase/re-bump already lives in `run_rebase_rebump` + `_run_rebase_rebump_from_step3` + `_run_rebase_rebump_verify_plain_no_push`. Factor the shared body so the step8b path differs only in (a) `exit_stall` target (8b vs 10/12), (b) push deferral (force-push-gate owns the push), and (c) post-success continuation (force-push-gate vs `ci-wait`). This is the "safe consolidation" the operator approved and mirrors the existing 10/12 internalization.
- **Phase 1–4 stays prompt-side.** Non-bump conflicts emit `exit 5` (rc=5, `STALL_TRACKING=false`) with `CALLER_KIND=ship_pr_pre_push` and `RESUME_PHASE=ship-pr-rrr-phase14-postbump`; the `conflict-resolution.md` handoff runs Phase 1–4. Phase 4 exit 0 reads `RESUME_PHASE` from state and re-invokes `ship-pr.sh --resume-phase ship-pr-rrr-phase14-postbump` (not `ship-pr-rrr-phase14`), which resumes the force-push-gate without entering the CI phase guard.
- **Idempotent resume.** The force-push-gate resume re-enters `run_bump_phase`; classify-bump returns `NONE` on an already-bumped HEAD (no double bump), then postbump reads `.postbump-phase=force-push-gate` and force-pushes. This is the existing resume contract — preserve it.
- **CLONE_TAG_FULL** is a pure function of `${CLONE_TAG:-$(basename "$PWD")}`; ship-pr.sh runs in the clone cwd, so the derivation is local. Keep the explicit flag for override.

## Edge cases
- `--forked` target: `run_step8b_rebase` rebases onto `upstream/main` and returns 2 (bail) on conflict, NOT 1 — so the internal path is entered only for the non-forked `return 1` conflict. Preserve the forked bail.
- `repo_unavailable=true`: postbump returns 2 (bail); the internal path is not entered. Preserve.
- `SKIPPED_ALREADY_FRESH=true`: re-bump no-ops; force-push-gate still runs.
- `HAS_BUMP=false` (forked or no bump skill): classify yields `NONE`; the path rebases/force-pushes with no new bump commit (step8-family `HAS_BUMP=false` semantics). Preserve.
- Bump-only conflict (`plugin.json`/`CHANGELOG`): the deterministic pre-pass + `drop-bump-commit` removes the bump first, so these resolve without Phase 1–4. Preserve.
- `CLONE_TAG` visibility: if `/implement` sets `CLONE_TAG` as a non-exported shell var, ship-pr.sh (a subprocess) will not see it and would fall back to `basename "$PWD"`. Verify whether `CLONE_TAG` is exported at the call site; if it is meaningful and unexported, `export CLONE_TAG` in the SKILL.md Invoke block or keep passing the explicit flag when `CLONE_TAG` is set. Default `basename "$PWD"` matches the historical else-branch.

## Failure modes
- **Resume routes to a CI phase with no PR (highest risk).** If Phase 4 exit 0 re-invokes `ship-pr-rrr-phase14` instead of `ship-pr-rrr-phase14-postbump`, resume hits `die_usage "... requires PHASE ci-initial or ci-merge"` or re-enters CI logic with no PR. Earliest signal: that `die_usage`, or a crash in `run_ci_phase` pre-PR. Mitigation: the dedicated `ship-pr-rrr-phase14-postbump` arm is a separate dispatch path that never enters the `ci-initial|ci-merge` guard; `conflict-resolution.md` Phase 4 reads `RESUME_PHASE` from state rather than hard-coding `ship-pr-rrr-phase14`. Validated by `test-ship-pr-rebase-phase14.sh`.
- **Stale/double bump (Invariant #1).** If push deferral or the classify-NONE idempotency is mis-wired, the branch could force-push without a fresh bump or with a stale version. Earliest signal: `check-bump-version --mode post` `VERIFIED=false`/`BUMP_TYPE=NONE`, or a merged version behind `origin/main`. Mitigation: keep `_run_rebase_rebump_from_step3`'s STATUS-first Block β gating and version-regression correction inside the shared body; `defer_push=true` so force-push-gate owns the single push.
- **Failure-routing drift (Invariant #3).** If a degraded-git failure in the internal step8b path calls `exit_stall 10|12` instead of `8b`, it bails to a nonexistent CI loop / 12d pre-PR. Earliest signal: wrong stall step label or a crash. Mitigation: parameterize the `exit_stall` target by caller family; assert the 8b target in tests.
