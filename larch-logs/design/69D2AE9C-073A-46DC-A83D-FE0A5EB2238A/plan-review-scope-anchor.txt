## Symptom
The #5797 fix (PR #5804) put `NO_OPEN_BROWSER=1` inside `cursor_auth_export_env()`, and every lane enumerated in #5797 calls it pre-spawn. One lane was missed: /design plan auto-fix. During `plan auto-fix-commands` / `plan validator-autofix`, a Cursor.app GUI window can still pop up over the operator's screen.

## Root cause
`_dispatch_vendor_fix` (python/larch/design/plan_quality.py:1087-1119) spawns `cursor agent -p` through run-external-agent with a plain `ctx.subprocess_env()` copy; nothing in that process chain sets NO_OPEN_BROWSER. Repo-wide, only 4 files reference NO_OPEN_BROWSER and none is in this path. The comment at python/larch/agents/_auth.py:168 ("all cursor lanes call this pre-spawn") is inaccurate for this lane.

## Expected behavior
All larch Cursor spawns run headless: this lane exports NO_OPEN_BROWSER=1 (via `cursor_auth_export_env()` or equivalent) before spawning, restoring the accuracy of the _auth.py comment and #5797's stated criterion ("across ALL larch Cursor lanes").

## Suggested fix
1. In the cursor branch of `_dispatch_vendor_fix` (python/larch/design/plan_quality.py:1087-1119), call `cursor_auth_export_env()` before spawning, or inject `NO_OPEN_BROWSER=1` into the env handed to run-external-agent for that spawn.
2. Add a regression test mirroring python/tests/agents/test_agents.py:630-632 that asserts NO_OPEN_BROWSER=1 in this lane's spawn env.
3. Re-check the other `cursor agent -p` composition sites reachable without `cursor_auth_export_env()` (repo grep for `run-external-agent` cursor branches) so the `_auth.py:168` "all cursor lanes" comment becomes true, then keep the comment.
