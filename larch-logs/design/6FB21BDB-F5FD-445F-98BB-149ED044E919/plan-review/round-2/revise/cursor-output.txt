## Edge cases

- A command run from `$DESIGN_TMPDIR` with a relative result filename must remain denied.
- A probe with an absolute tmpdir path instead of `$DESIGN_TMPDIR` should stay denied unless the implementation can validate it safely without broadening the parser.
- A compound command like `[ -f "$DESIGN_TMPDIR/.completed/step-3" ] && cat "$DESIGN_TMPDIR/.step3-review-result.env"` must be denied.
- A loop that only tests the sentinel but includes `sleep` must be denied by the existing anti-polling rules.
- A foreground probe of `.completed/step-5c` must be denied even when that file exists early in `design-step5c.sh`.
- Existing wrapper-routed calls must still allow.
- Existing Step 3 recovery waiters must still allow.
- On `PLAN_WRITE_OK=false`, only `.completed/step-5c-terminal` exists as the Step 5c terminal sentinel; the foreground probe must allow that sentinel.
- A foreground probe that finds `.completed/step-5c-terminal` while the wrapper is still alive authorizes post-notification parsing guarded by that sentinel; it does not authorize reading `.design-publish-result.env` before the terminal sentinel exists.
- When a premature notification already fired and no second notification will arrive, recovery must not block on "wait for original notification"; the terminal-sentinel probe is the sanctioned completion check on killed-waiter paths.

## Failure modes

- If the sentinel-probe matcher is too broad, it can reopen the progress-polling hole.
- If the matcher runs after the generic probe-verb denial, `test -f` probes will still be blocked.
- If `marker_step_completed` is retargeted to `.completed/step-5c`, the guard can release while the wrapper PID is still running and allow premature tmpdir/result reads.
- If `.completed/step-5c` is whitelisted for foreground probes, a premature Step 5c notification can observe a non-terminal milestone and invite premature routing or repeated checks.
- If docs say the foreground probe can replace terminal sentinel requirements or authorize result-env reads before the terminal sentinel exists, `/design` may route forward while the wrapper is still alive.
- If recovery prose still requires waiting for a second `<task-notification>` after a premature one, recovery remains blocked or falls back to foreground `ps` polling.
- If `AGENTS.md` or `orchestrator-never.md` is not updated, orchestrators may still reject the new foreground probe as banned progress observation.
