## Findings

### 1. [architecture] Item 2 regional slicing is scope creep for a nit pin (`python/test_plan_review.py`)

Item #4602 asks for a `round-summary.env` / `COLLECT_FAILURE_COUNT` regression pin. The plan adds three function-body slices with a 40-line co-occurrence fallback. That is heavy for an OOS nit bundle. `test_embedded_plan_review_loop_uses_migrated_collector` already pins body-wide `NOT_SUBSTANTIVE` and `COLLECT_FAILURE_COUNT` strings.

**Suggested revision:** Add `test_embedded_plan_review_loop_not_substantive_count_emitted` with (a) exact `COLLECT_FAILURE_COUNT=0` in the embedded `plan-review-loop.sh` body and (b) one substring tying `round-summary.env` to a `COLLECT_FAILURE_COUNT` emit. Skip regional helper extraction unless a simpler pin fails.

### 2. [correctness] Item 4 must not port the inverted diag-matches branch (`python/legacy_review_shell/tally-code-votes.sh:463-481`)

Today `parse-rate-diag-matches` returns exit `0` when a matching diag exists, and tally treats that as **exclude**. `parse-rate-check` always exits `0` and prints `PARSE_RATE_STATUS=OK` or `NOT_SUBSTANTIVE`, where `OK` means **include**.

The plan states the right KV semantics but does not warn against reusing the old `if python3 ...; then exclude` skeleton. A mechanical port would invert exclusion and let narrative-only voters back into quorum.

**Suggested revision:** In the tally edit instructions, state explicitly: parse `PARSE_RATE_STATUS` from stdout; on `OK` append to `EFFECTIVE_VOTER_FILES` / set `EFFECTIVE_SLOT`; on `NOT_SUBSTANTIVE` increment `VOTER_PARSE_FAILED_COUNT`. Never branch on the Python exit code.

### 3. [OUT_OF_SCOPE] Dead bash helper after Item 4 (`python/legacy_review_shell/tally-code-votes.sh:21-29`)

`voter_parse_rate_diag_path()` is only used by the diag-matches calls being removed. Leaving it is dead code.

### 4. [OUT_OF_SCOPE] Item 4 test covers legacy path only (`python/test_review_tally.py`)

The new `test_tally_excludes_narrative_only_voter_parse_rate_check` intentionally omits `--voter-tools`, so it exercises the legacy branch only. Production `/review` tallies often use the three-slot path. Existing three-slot tests use well-formed votes, so they would not catch a three-slot-only `parse-rate-check` argv mistake. Optional hardening, not required for this nit issue.

### 5. [OUT_OF_SCOPE] Missing harness doc file in plan list (`scripts/test-prompt-template-invariants.md`)

Item 5 says to update the sibling `.md`, but **Files to modify/create** lists only the `.sh`. Add the `.md` entry for discoverability.
