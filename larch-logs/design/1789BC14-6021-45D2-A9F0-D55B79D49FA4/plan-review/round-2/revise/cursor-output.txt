## Edge cases

- A degraded prompt must win over Step 2 routing when `DEGRADED_PROMPT_REQUIRED=true`.
- Rebase conflict data must remain available after `BOOTSTRAP_NEXT=rebase-routing`.
- Absent or malformed post-continue-tail `ROUTE` maps to `rebase-routing` only when `DEGRADED_PROMPT_REQUIRED` is false, `continue_tail_attempted` is true, and `_step2_blockers(data)` is false; step2-blocker cases (`REPO_UNAVAILABLE`, missing `plan.txt` / `feature-description.txt`, empty `coder`, and related row-290 cases) remain `cleanup`.
- When the continue tail is skipped (`continue_tail_attempted=false`), bare absent `ROUTE` after merge must not route to `rebase-routing`.
- When the tail runs but pops `ROUTE` because blockers are present after the 1.r probe, `BOOTSTRAP_NEXT` must be `cleanup`, not `rebase-routing`.
- Missing plan artifacts must not reach Step 2.
- Emergency Preflight warnings may still appear before the final validated envelope.
- `TITLE` may contain spaces and `=`, but not newlines; orchestrator must still split at the first `=` only.
- `PLAN_PATH` and `ISSUE_JSON_PATH` must match the helper-owned tmpdir paths exactly.
- Extra envelope keys beyond the seven allowed keys are not rejected by Python validation.
- Symlinked or non-regular `bootstrap-routing.env` refusal paths must still emit `BOOTSTRAP_NEXT` on exit `0` stdout so Step 0 fail-closed parsing does not abort every such resume.

## Failure modes

- If `BOOTSTRAP_NEXT` is absent or outside the allowed set after a zero bootstrap exit, treat Step 0 as a malformed bootstrap envelope and abort rather than guessing from legacy keys.
- If bootstrap builds an exit-0 envelope without computing `BOOTSTRAP_NEXT` on a routing-file refusal branch, every such resume will always abort Step 0 even when routing is otherwise valid.
- If `_bootstrap_next` evaluates malformed/absent `ROUTE` before `_step2_blockers` cleanup, blocked runs (repo unavailable, missing plan artifacts, empty coder) can incorrectly enter `rebase-checkpoint-routing.md`.
- If Preflight validation fails, exit `2` and do not emit a partial success envelope.
- If a readability edit accidentally changes Bash fence shape, run the fence-shape lint and either restore the old shape or update the lint only if a deliberate fence change was required.
- If lint harness pins are not updated alongside SKILL prose shrink, `make lint` fails via `test-implement-structure.sh` or `test-plan-adequacy-audit.sh`.
