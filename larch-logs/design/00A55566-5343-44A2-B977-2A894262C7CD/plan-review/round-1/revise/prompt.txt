## Root cause analysis

Two contracts interact:

1. **Larch tail ordering guarantees the summary is never the turn-final message.**
   - `/design` (`skills/design/SKILL.md` Step 5c item 5, Step 5d, Step 6): emit the summary via the shared Read-always profile, print the machine footer as "the last human-visible Step 5 line", then "Continue to Step 6 IMMEDIATELY" (a Bash fence).    - `/implement` (`skills/implement/SKILL.md` NEVER #17, Step 17, Step 18): emit the marker body, write `$IMPLEMENT_TMPDIR/.step17-emitted` only after that emission (a tool call), then "Continue to Step 18. 2. **The new Claude Code harness renders only the final text message of a turn reliably.** Its guidance states that assistant text written between tool calls may not be shown and that deliverables must be in the final text message with no tool calls after it. The previous build rendered every interleaved text block as it streamed, which is why the identical ordering displayed for months.

Trigger: the platform upgrade, not a larch release. Confidence is high on the larch-side ordering (directly inspectable). The harness rendering behavior is inferred from the new build's documented guidance plus the observed hidden emission; harness internals are not inspectable from this repo.
