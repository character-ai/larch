## Findings

**1. risk-integration — No-stall skip breadcrumb may disappear (in_scope, important)**  
`plan.txt:77-78` moves `⏩ 18a: stall recovery — no stall detected` into gate-phase wrapper stdout only. Live `skills/implement/SKILL.md:860` prints it as orchestrator text. The plan relays teardown tail KVs from finalize stdout but does not require relaying this skip line. That is a user-visible regression risk.

**2. correctness — Marker print can block teardown (in_scope, important)**  
`plan.txt:93-110` runs marker body emission in the same `set -e` script as teardown. `step-16-17.sh` tolerates marker `cat` failure and still exits 0. Without the same guard, a bad `summary-final.md` read can skip closing marks and `implement-finalize teardown`, leaking tmpdirs.

**3. correctness — Memory layer resolution gap (in_scope, important)**  
`plan.txt:63-68` uses `_stall_layer_active` for the gate decision but leaves memory sourcing vague. `step-18a-gate.sh:65-68` only honors `true|false` for `--stall-tracking-memory`; other values fall through to `false`. That can disagree with the broader not-false-and-not-empty rule used elsewhere.

**4. [OUT_OF_SCOPE] harness awk update for Step 18 launcher (latent)**  
`scripts/test-render-cost-line-callsites.sh:61-65` awk-blocks the old step18b fence. The plan updates grep pins (`plan.txt:254-263`) but should also replace that awk selector when implementing. Worth tracking; not blocking the feature itself.
