**1. Stdlib `paths:` parser can false-pass harness k/j (blocking, correctness)**

The plan’s “quoted block-list” / “quoted flow-list” wording (`plan.txt:15-18`) does not say the parser must validate every flow token or reject scalar `paths:` values. That invites a quote-skimming implementation.

- **Harness k** (`scripts/test-check-topology-rule-paths.sh:232-236`): `paths: ["skills/foo.md", 3, null, true]` must fail with `must be a string`. Today `scripts/check-topology-rule-paths.py:123-125` type-checks each list element after `yaml.safe_load`. A parser that only collects quoted strings returns `{"skills/foo.md"}`, matches the TSV authority, and exits 0.
- **Harness j** (`scripts/test-check-topology-rule-paths.sh:226-230`): `paths: skills/foo.md` must fail with `paths must be a list`. Today `scripts/check-topology-rule-paths.py:121-122` rejects non-list values. Coercing the scalar into a one-element list would false-pass.

**Suggested revision:** In the NEW module and contract doc, pin accepted shapes and fail-closed rules: block `paths:` + `- "..."` lines only; inline `paths: ["...", ...]` with quote-aware comma splitting; reject any other bracket token; reject scalar `paths:` without `[` before subset compare.

**2. CRLF contract not pinned against normalize pattern (important, correctness)**

`plan.txt:267` says reject CRLF before parsing, but the plan does not warn against copying `python/lint_skill_invocations.py:25`, which normalizes CRLF away. The current topology checker rejects any `\r` in the frontmatter region (`scripts/check-topology-rule-paths.py:95-96`). Harness e2 (`scripts/test-check-topology-rule-paths.sh:164-168`) depends on that.

**Suggested revision:** Require byte-preserving CRLF rejection (same region as `extract_frontmatter`), and explicitly forbid `.replace("\r\n", "\n")` on this path.
