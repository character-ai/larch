- Add `--root` to `check_topology_rule_paths` (same contract shape as `lint_literal_counts`): optional `Path` defaulting to `Path(__file__).resolve().parents[1]`. All TSV/rule path resolution and symlink checks must anchor on the resolved `--root`, not a module-global fixed at import time.
- Preserve the `python/run_logs.py` subprocess and stderr-capture boundary. Remove the retired `_RENDER_TRANSCRIPT` script-path constant and `is_file()` availability guard. Invoke `capture_transcript_main` with `sys.executable`, absolute `str(_REPO_ROOT / "python/cli.py")`, `run-log`, `render-session-transcript`, and the same `--input` / `--output` flags. Keep separate `render_err` capture and redaction. Update unavailable and non-zero fallback messages without embedding retired path literals.
- De-yaml topology parsing before moving it:
  - Remove `import yaml`.
  - Replace `yaml.safe_load` with a stdlib frontmatter parser that preserves the existing `paths: list[str]` contract for all harness-exercised shapes and production rule usage.
  - Supported grammar (pin in module and contract doc):
    - Block list: `paths:` followed by indented `- "..."` or indented `- bare-path-token` (unquoted string entry).
    - Inline flow list: `paths: ["...", ...]` only, with quote-aware comma splitting; every bracket token must be a double-quoted string.
  - Rejection rules (must match current harness diagnostics):
    - Scalar `paths: skills/foo.md` without list syntax → `paths must be a list`.
    - Flow list containing `3`, `null`, `true`, or other non-quoted tokens → fail on first non-string entry with `must be a string`; do not partially accept valid prefixes.
    - Missing `paths`, non-list `paths`, non-string entries, CRLF, and missing frontmatter → same outcomes as today.
  - Do not add general YAML support (anchors, aliases, merge keys, or arbitrary mappings).
- **Py-lint adaptation (strict pyright under `python/`)**: After each module lands in `python/`, it is scanned by `make py-lint` via `cd python && pyright` with `typeCheckingMode: strict` (`python/pyrightconfig.json`). The retired `scripts/*.py` bodies were not subject to this gate. During port, make only behavior-preserving py-lint cleanups required for acceptance:
  - Annotate JSON/frontmatter helpers and record shapes with `dict[str, object]`, `list[object]`, and narrow `cast(...)` only after `isinstance` guards.
  - Add explicit return types to generators and helpers (for example `Iterator[dict[str, object]]` for JSONL parsers).
  - Assign intentionally discarded call results to `_` where `reportUnusedCallResult` fires.
  - Guard `__doc__` before `.splitlines()` for argparse descriptions (use `( __doc__ or "").splitlines()[0]` consistently).
  - Do not change runtime behavior, CLI contracts, stderr messages, or exit codes to satisfy typing.
  - Verify each moved module with `cd python && pyright <module>.py` before deleting the retired script; final gate remains `make py-lint`.
- Keep the three existing bash harnesses. Repoint their subject commands to the new `python3 python/cli.py` verbs. Do not port them to pytest in this issue.
- Harness preflight: all three harnesses must drop retired `scripts/*.py` existence probes. Bind `CLI="$REPO_ROOT/python/cli.py"` (or equivalent) and gate startup on `python3` plus `cli.py` presence, not on deleted utility paths.
- Topology harness fixture isolation: drop the copy-into-temp-tree `scripts/check-topology-rule-paths.py` pattern. Fixture cases invoke `python3 "$REPO_ROOT/python/cli.py" lint topology-rule-paths --root "$dir"` from fixture cwds so isolated TSV/rule edits are exercised against the temp tree. Real-registry and non-root-cwd smokes invoke the same CLI without `--root` so they validate the live checkout.
- Delete only the six retired `scripts/*.py` utilities and six sibling `scripts/*.md` contracts after parity.
- Add only those twelve deleted paths to `python/migrated-scripts.tsv` with `#4974`. Do not list retained harness `.sh` or harness `.md` paths.
- Avoid retired path literals in new tracked files, harness headers, harness contract intros, and updated docs. If a compatibility diagnostic must print an old path, compose that string at runtime so `make lint-retired-scripts` stays clean.
- Do not add new behavior coverage for `cleanup-implement-logs`, `render-session-transcript`, or `retro-v3-sweep` beyond CLI registration smoke if needed.

### Edge cases

- `check_topology_rule_paths` must reject CRLF in rule frontmatter before parsing.
- The stdlib parser must not silently accept arbitrary YAML or partially valid flow lists.
- Scalar `paths:` without list syntax must fail with `paths must be a list` before subset compare.
- Flow-list parsing must reject non-quoted bracket tokens with `must be a string`, not return a filtered subset.
- Block-list parsing must accept both quoted and unquoted string entries.
- Topology CLI delegation must work when `sys.argv` still contains `python/cli.py`, domain, and verb.
- Topology `--root` must override `__file__`-anchored defaults so fixture trees under `$TMP_ROOT` are validated in isolation.
- The linter modules must keep `--root` defaults anchored to repo root after relocation.
- Git-worktree lint enumeration must still include untracked non-ignored markdown for `lint literal-counts`.
- `run_logs.py` must still treat renderer failures as subprocess failures with captured stderr.
- `capture_transcript_main` must not regress when cwd is outside repo root; subprocess must use absolute `_REPO_ROOT / "python/cli.py"`.
- Literal-counts and S041 harnesses must not gate on deleted `scripts/*.py` paths; preflight must target `python/cli.py` only.
- `cleanup_implement_logs` and `retro_v3_sweep` still write files when their existing flags request writes. Do not make them in-process helpers.
- Retained bash harness shellcheck entries must stay in `.pre-commit-config.yaml` while those harness files remain tracked.
- `agent-lint.toml` must not keep an exclude for the deleted `scripts/lint-no-raw-stderr-after-quiet-init.md` after the Python contract replaces it.
- Harness `.sh` headers and `.md` contract intros must not embed full retired script paths after cutover.
- Py-lint typing fixes must not alter JSONL filter semantics, frontmatter rejection messages, or argparse CLI surfaces.

### Failure modes

- `make lint-retired-scripts` can fail if new docs, tests, harness headers, or module docstrings include retired path literals.
- `make test-lint-literal-counts` / `make test-lint-no-raw-stderr-after-quiet-init` can fail at harness startup if the `LINT` preflight still probes deleted `scripts/*.py` paths.
- `python/test_stdlib_only.py` can fail if any moved module still imports PyYAML.
- Pre-commit can fail if moved hooks use `language: python` with stale script entries.
- Topology stdlib parsing can drift from harness expectations if scalar or partial flow-list cases are handled loosely.
- Topology fixture cases can false-pass or false-fail against production data if `--root` is omitted or the copy-into-temp-tree script pattern is retained after the CLI move.
- `run_logs.py` capture can regress if the render command is converted to an in-process call, if the retired `is_file()` guard remains after script deletion, or if a relative `python/cli.py` path is used under non-root cwd.
- Accidentally listing retained harness paths in `python/migrated-scripts.tsv` will cause false `lint-retired-scripts` failures against pre-commit shellcheck `files` patterns.
- `make lint` agent-lint dead-script checks can flag `python/lint_no_raw_stderr_after_quiet_init.md` as orphan if the exclude entry is not repointed from the deleted scripts contract.
- `docs/run-logs.md` can leave operators without a schema contract pointer if the cross-link still targets deleted `scripts/render-session-transcript.md`.
- `make py-lint` can fail after relocation if moved modules keep untyped JSON helpers, unknown `dict`/`list` values, unguarded `__doc__.splitlines()`, or unused call results that strict pyright reports under `python/pyrightconfig.json`.
