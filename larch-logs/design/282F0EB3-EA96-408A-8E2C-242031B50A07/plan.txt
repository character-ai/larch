## Implementation Plan — Issue #2590 (/design and /implement PR title labels overhaul)

### Goal

Switch the tracking-issue title-prefix state machine from the current 5-state set (`[IN PROGRESS]`, `[DONE]`, `[STALLED]`, `[PLANNED]`) to a 5-state set (`[DESIGNING]`, `[DESIGNED]`, `[IMPLEMENTING]`, `[DONE]`, `[STALLED]`). Add a `[DESIGNED]` precondition check at `/implement` Preflight admission so issues without a completed `/design` run hard-fail before allocating session state. Audit and update every `[IN PROGRESS]` / `[PLANNED]` reference in the active runtime surface (skills/, scripts/, agents/, .claude/, SECURITY.md, docs/, tests). Leave historical artifacts (CHANGELOG.md, larch-logs/**) unchanged.

### State machine summary

| Stage | Old prefix | New prefix | Writer |
|---|---|---|---|
| /design start | (none) | `[DESIGNING]` | scripts/tracking-issue-write.sh rename --state designing (new) |
| /design complete | `[PLANNED]` | `[DESIGNED]` | scripts/tracking-issue-write.sh rename --state designed (renamed) |
| /implement start | `[IN PROGRESS]` | `[IMPLEMENTING]` | scripts/tracking-issue-write.sh rename --state implementing (renamed) |
| /implement success | `[DONE]` | `[DONE]` | unchanged |
| /implement failure | `[STALLED]` | `[STALLED]` | unchanged |

Legacy `[IN PROGRESS]` and `[PLANNED]` prefixes are stripped (so rename remains idempotent for in-flight issues), but neither is accepted as a `--state` argument value and `[PLANNED]` no longer satisfies the `/implement` admission precondition.

### Approach

- **Single-PR strategy**: ship every change together because the rename helper, admission gate, callers, and test fixtures cross-cut and would otherwise reference each other's stale strings between PRs.
- **Migration posture**: legacy `[IN PROGRESS]` and `[PLANNED]` titles are tolerated by `strip_lifecycle_prefix` (so re-running /design on a `[PLANNED]` issue cleanly migrates to `[DESIGNING]` → `[DESIGNED]`), but rejected by admission and not accepted as `--state` argv values. Operators with stuck legacy-prefix issues either re-run `/design` or manually rename the title.
- **Admission precondition placement**: the new `missing-designed-prefix` check fires AFTER managed-prefix / report-prefix / audit-label / blockers — the precondition is the last gate before PASS so existing rejection reasons remain dominant in the operator-facing diagnostic. Exit code reuses 5 (same class as managed-prefix); `ADMISSION_RESULT` differentiates via the new value `missing-designed-prefix`.
- **Forked-mode and resume carve-outs**: preserved. The resume sentinel branch in admission already bypasses managed-prefix checks; it bypasses the new precondition for the same reason (the run was already approved at the prior /implement invocation).
- **/design Step 0 rename placement**: insert AFTER routers (clarify-loop, already-planned) have committed to proceeding rather than at the very start of Step 0a. This prevents the "cancel-from-already-planned" edge case from leaving the title at `[DESIGNING]` after a no-op /design exit.

### Edge cases

- **Issue already in `[PLANNED]` mid-migration**: /implement admission rejects it. Operator re-runs `/design`; the new Step 0 rename strips `[PLANNED]` and prepends `[DESIGNING]`. After completion, title becomes `[DESIGNED]` and /implement admission passes.
- **Issue already in `[IN PROGRESS]` mid-migration with no surviving `$IMPLEMENT_TMPDIR`**: /implement admission rejects (managed-prefix). Operator manually edits the title or accepts that the prior run is abandoned. Matches the current `[IN PROGRESS]` recovery posture.
- **Concurrent /design and /implement on the same issue**: /design renames to `[DESIGNING]` while /implement admission races. /implement admission sees `[DESIGNING]` (managed-prefix) and rejects. Expected behavior — the issue is in active design.
- **/design cancel from already-planned router**: title was NOT pre-renamed in this design (the rename happens after router commit), so the title stays at its pre-/design state on cancel. No misleading-state regression.
- **Round-trip marker preservation**: `tracking-issue-write.sh` already preserves the optional `[ROUND-TRIP]` marker after lifecycle strip; behavior carries over unchanged because the new prefix set uses the same strip-then-prepend mechanic.
- **Title length 256-char limit**: `truncate_title_with_prefixes_to_256` slices the user-tail. The new prefixes are slightly different lengths (`[DESIGNING] ` = 13 chars, `[DESIGNED] ` = 12 chars, `[IMPLEMENTING] ` = 16 chars vs old `[IN PROGRESS] ` = 14 chars, `[PLANNED] ` = 10 chars). The slicing logic is prefix-length-aware so no further change is needed; harness should add a long-title fixture for `[IMPLEMENTING] ` (the longest new prefix) to confirm slicing remains stable.

### Failure modes

1. **Stale prefix references**: a missed `[IN PROGRESS]` / `[PLANNED]` literal in some skill or script. **Earliest warning**: agent-lint or pre-commit catches via grep-based path scans, OR a CI test harness assertion fails. **Mitigation**: explicit final grep pass `git grep -nE '\[(IN PROGRESS|PLANNED)\]' -- ':!CHANGELOG.md' ':!larch-logs/'` after edits, with documented exclusions verified non-empty.

2. **Admission precondition rejecting valid resumed runs**: if the resume sentinel branch ordering or RUN_ID match condition fails, the new `missing-designed-prefix` check fires on a resumed run whose title was already renamed past `[DESIGNED]`. **Earliest warning**: existing resume test fixtures in `test-implement-admission.sh` would fail. **Mitigation**: the new precondition check is inserted AFTER the resume branch (which exits 0 with `RESUME=true` before reaching the new check); existing test ordering verifies this remains true.

3. **Combine-issues regression**: the jq filter regex change in `fetch-combinable-issues.sh` is the only callsite outside the prefix-set audit. A typo in the alternation would silently start including/excluding the wrong prefix set. **Earliest warning**: a manual `/combine-issues` dry-run would either omit new-state issues (false negative) or include them (false positive). **Mitigation**: add a test fixture for `fetch-combinable-issues.sh` (a hermetic jq pipeline test) if one does not already exist, or add a smoke test that pipes synthetic issue JSON through the filter and asserts the expected exclusions.

### Testing strategy

- **Updated harnesses**: run `make test-tracking-issue-write`, `make test-implement-admission`, `make test-lib-title-markers`, and the audit-runs test suite. Each must pass with the new fixtures.
- **New harness coverage**: (a) admission PASS on `[DESIGNED]`, (b) admission REJECT (missing-designed-prefix) on no-prefix and on `[PLANNED]`, (c) admission REJECT (managed-prefix) on `[DESIGNING]`, (d) rename round-trip from legacy `[PLANNED]` to new `[DESIGNED]` via single `tracking-issue-write.sh` call, (e) FALSE-POSITIVE marker insertion against a `[DESIGNING]` title.
- **Cross-skill consistency check**: a grep-based audit script (or pre-commit step) that fails if any file under `skills/`, `scripts/`, `agents/`, `.claude/`, `SECURITY.md`, `AGENTS.md`, or `docs/` contains `[IN PROGRESS]` or `[PLANNED]` outside an explicit allow-list. Optional but cheap to add and prevents drift.
- **Lint**: `bash scripts/relevant-checks.sh` after all edits.
