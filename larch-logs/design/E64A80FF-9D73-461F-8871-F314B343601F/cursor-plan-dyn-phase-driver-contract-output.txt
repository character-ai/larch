[correctness]** `plan.txt:28-47` / proposed `skills/design/scripts/design-postplan-emit.sh` — The approach pairs `set -euo pipefail` with a guarantee that the driver always writes `.design-postplan-emit-result.env` before exiting on success or failure paths, but it never requires `set +e` around `design-driver.sh` (EMIT_PLAN), `snapshot-plan-round.sh`, or `invoke-plan-validator.sh`. Sibling `design-publish.sh` already uses that pattern so a failed helper does not abort before result-env emission:

```159:162:skills/design/scripts/design-publish.sh
    set +e
    action_out=$(run_action "$action" "${action_args[@]+"${action_args[@]}"}")
    rc=$?
    set -e
```

Without the same guard, any non-zero helper rc exits the driver early and breaks the planned orchestration contract for `missing-diff-lines` (repair via `EMIT_PLAN_STATUS`), `snapshot-failed` (abort before Step 3), and `validate-driver-failed` (infra failure distinct from `defects-found` exit 0).

**Suggested revision:** Add an explicit mechanical rule in the Approach and `design-postplan-emit.md`: capture each helper under `set +e`, parse stdout KVs, set `POSTPLAN_EMIT_STATUS`, call `phase_driver_write_result_env`, mirror KVs to stdout, then `exit` with the documented code.
