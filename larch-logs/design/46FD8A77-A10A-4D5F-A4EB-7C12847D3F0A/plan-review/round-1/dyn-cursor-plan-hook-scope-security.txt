### 1. correctness — `skills/research/references/research-phase.md:65-100`

The plan updates `skills/research/SKILL.md` with “abort path” sentinel cleanup prose, but the only `/research` abort fences that call `session cleanup-tmpdir` live in `skills/research/references/research-phase.md`, not in `SKILL.md`.

```65:68:skills/research/references/research-phase.md
    abort)
      echo "**⚠ /research: aborted by operator at Step 1.1.c.**"
      python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" session cleanup-tmpdir --dir "$RESEARCH_TMPDIR"
      exit 0
```

Similar cleanup-only exits appear at lines 92-94 and 98-100. Step 0 creates the activation sentinel after session setup (per plan), so these mid-run aborts can leave a fresh sentinel in `${XDG_CACHE_HOME:-$HOME/.cache}/larch/deny-edit-write-active/` while the harness may still route `deny-edit-write.sh` to unrelated skills. That partially reintroduces the reported leak (deny without an active read-only skill), bounded by the 360-minute TTL in the plan’s approach section.

**Suggested revision:** Add `### UPDATED: skills/research/references/research-phase.md` and remove the activation sentinel in each `cleanup-tmpdir` abort branch before exit.

### 3. risk-integration — planned `scripts/deny-edit-write.sh` activation gate; `scripts/hook-bg-poll-guard.sh:600-605`

The plan’s minimum-change defense is sound on axis separation: activation ambiguity fail-opens (fixing leaked unconditional deny at `scripts/deny-edit-write.sh:64-150`), while active path resolution stays fail-closed (`scripts/deny-edit-write.sh:25-26`, `81-86`). Inactive-gate tests with isolated cache and stale-mtime cases address stale sentinel and missing-`jq` when inactive.

The weak link is PID coupling. The plan creates `skill-$PPID` sentinels from orchestrator Bash and has `activation_is_live()` match hook `$PPID`. The plan’s failure-modes section flags parent-PID skew but proposes no mitigation. Repo precedent from #5684 states production PreToolUse hooks did not align with session-stored PID metadata:

```600:605:scripts/hook-bg-poll-guard.sh
  # #5684: liveness is NOT scoped by CLAUDE_PID. In production the hook's PPID and
  # input never match the marker's stored CLAUDE_PID (hook input carries no claude_pid,
  # LARCH_BG_POLL_GUARD_SESSION_PID is unset outside tests), so the old equality check
  # rejected every marker and the guard never fired.
```

If hook `$PPID` differs from the Bash-tool `$PPID` used at sentinel creation, `activation_is_live()` returns false, the gate exits 0 at the planned pre-`jq` branch, and repo `Write`/`Edit` calls proceed during a live `/research` or `/bug` run — the opposite of the read-only guarantee the issue needs while those skills execute.

**Suggested revision:** Add one production-shaped harness case (parent/child subshells sharing a parent PID) or fail setup loudly when a post-write probe hook still sees inactive activation. Do not broaden scope beyond validating the PID contract.
