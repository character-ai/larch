## Summary

Fix two compounding defects so a merged `LARCH_SPARSE_DIRS` addition reaches existing installs through the documented `/release` + `/upgrade-larch` path, plus add a proactive drift warning.

- **RC2 (blocker)**: `/upgrade-larch` must reconcile a drifted sparse cone on an already-latest install instead of early-exiting.
- **RC1 (immediate)**: `/release` must run the working-tree upgrade script against the real installed/cache root so the just-released allowlist applies in the same release cycle.
- **Drift warning**: SessionStart hook warns (warn-only) when the marketplace cone drifts from the expected allowlist.
- **Release restart**: `/release` Step 8 must require a Claude restart after a same-version sparse-cone reconcile, not only after a version bump.

The fix is generic to any future allowlist dir. `python` is the first instance, not the subject.

## Approach

Reuse existing reconciliation. `refresh_larch_marketplace()` already removes and sparse re-adds the marketplace, repairing both git sparse cone and `known_marketplaces.json`. RC2 makes that path reachable on the idempotent branch by gating early-exit on `marketplace_sparse_cone_matches`.

RC1 runs the working-tree upgrade script against the real installed/cache root. This avoids stale Skill-tool logic while preserving cache/stamp/prune context through `CLAUDE_PLUGIN_ROOT`. The sparse allowlist comes from the executing script’s `SCRIPT_ROOT`, not from the installed root.

Release Step 7 resolves the **active** installed/cache root before prepare-time `CURRENT_VERSION` so prune/stamp context cannot target a stale cache dir while the operator session runs another version. Step 8 treats cone-only reconcile like a version install for restart purposes.

SessionStart only warns. It reads the same sourced-only allowlist lib but must resolve that lib through `SCRIPT_DIR` or a locally bound plugin root before any later `PLUGIN_ROOT` assignment. Missing lib/function/tool/input means silent skip.

## Edge cases

- **Version differs**: normal upgrade path unchanged.
- **RC1 with stale cache root missing `lib-sparse-dirs.sh`**: allowlist still comes from working-tree `SCRIPT_ROOT`.
- **RC1 when `CURRENT_VERSION` cache dir is absent but another installed root exists**: release resolves the actual installed/cache root and still runs the working-tree script.
- **RC1 when prepare `CURRENT_VERSION` differs from installed metadata**: prefer installed version / valid session `CLAUDE_PLUGIN_ROOT`; use `CURRENT_VERSION` cache dir only on match or documented fallback; never prune against a non-active root.
- **Release cache fallback with 0 or 2+ version dirs**: no arbitrary pick; warn and Skill-tool / no-install fallback.
- **Release same-version cone reconcile**: Step 8 still mandates restart even though `NEW_VERSION == CURRENT_VERSION`.
- **True dev clone / no marketplace install**: release falls back to existing Skill-tool path or warns, preserving current behavior.
- **Legacy full clone** (`larch-logs/` present): treated as drift and repaired by remove + sparse re-add.
- **`gh` unavailable**: existing unconditional-upgrade behavior remains.
- **Hook under stripped environment**: empty `HOME`, missing lib, undefined `normalize_sparse_dirs`, missing git, or empty compare inputs all skip silently.
- **Prune during RC1**: explicit installed root lets prune protect the running and target versions.

## Failure modes

1. **RC1 root conflation**: using installed root as allowlist source would repeat stale cone behavior. Mitigation: source sparse lib only from `SCRIPT_ROOT`; test with older fake cache missing the lib.
2. **Release binds wrong cache root**: preferring prepare `CURRENT_VERSION` over installed metadata can prune/remove the live active cache. Mitigation: metadata-first resolution order; accept `CURRENT_VERSION` only on match; ambiguous multi-version cache → no pick.
3. **Release fallback runs stale Skill implementation**: missing installed root could otherwise call stale `/upgrade-larch`. Mitigation: resolve actual installed/cache root before fallback; reserve Skill fallback for true no-install.
4. **Same-version cone repair without restart**: operator keeps stale in-memory plugin after release Step 7 reconcile. Mitigation: Step 7 `CONE_RECONCILED` flag + Step 8 restart when set.
3. **False-negative cone comparison**: already-latest installs reinstall every run. Mitigation: shared normalization plus match/drift harness cases.
4. **SessionStart fail-open violation**: undefined `PLUGIN_ROOT` or `normalize_sparse_dirs` could abort under `set -u`/`set -e`. Mitigation: local path binding, `declare -F` guard, best-effort isolation, and explicit tests.
5. **Future allowlist edit misses release/docs/tests**: mitigation through edit-in-sync docs and intentional dual-update literal guard.
