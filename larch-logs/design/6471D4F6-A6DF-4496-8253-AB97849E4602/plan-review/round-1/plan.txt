# Implementation Plan — Sparse-allowlist additions must reach existing installs (#3461)

## Summary

Fix two compounding defects so a merged `LARCH_SPARSE_DIRS` addition reaches existing installs through the documented `/release` + `/upgrade-larch` path, plus add a proactive drift warning.

- **RC2 (blocker)**: `/upgrade-larch` must reconcile a drifted sparse cone on an already-latest install instead of early-exiting.
- **RC1 (immediate)**: `/release` must apply the just-released allowlist within its own release cycle.
- **Drift warning**: SessionStart hook warns (warn-only) when the marketplace cone drifts from the expected allowlist.

The fix is generic to any future allowlist dir. `python` is the first instance, not the subject.

## Approach

Reuse, don't reinvent. The cone reconciliation already exists in `refresh_larch_marketplace()` (remove + sparse re-add, which also repairs `known_marketplaces.json`). RC2 just makes that path reachable on the idempotent branch by gating the early-exit on `marketplace_sparse_cone_matches`. The new `already_latest_and_cone_ok()` helper exists so the decision is unit-testable.

RC1 reuses the existing version-changed path: by running the just-released working-tree script with an explicit `CLAUDE_PLUGIN_ROOT` (the installed cache dir), the new allowlist drives `refresh_larch_marketplace` in a single install, with no second reinstall and both versions protected from prune.

Single source of truth: extracting `LARCH_SPARSE_DIRS` + `normalize_sparse_dirs` to `scripts/lib-sparse-dirs.sh` lets the hook and the upgrade script agree without a duplicate-and-lint. **Script-root vs installed-root**: `upgrade-larch.sh` sources the lib from `SCRIPT_ROOT` (the tree of the script file being executed) while `PLUGIN_ROOT` / `CLAUDE_PLUGIN_ROOT` govern cache derivation and prune only — this is what makes RC1 safe when Step 7 overrides `CLAUDE_PLUGIN_ROOT` to the pre-release cache. Sourcing `upgrade-larch.sh` itself into the hook is rejected because its top-level `larch_quiet_init` / `exec 1>&3` / `trap recover ERR` would corrupt the hook's stdout/error handling.

## Edge cases

- **Version differs**: `&&` short-circuits before `marketplace_sparse_cone_matches`, so the normal upgrade path is unchanged (no behavior change for the common case).
- **RC1 with stale cache root missing `lib-sparse-dirs.sh`**: allowlist still comes from the working-tree `SCRIPT_ROOT`; cone refresh uses the just-released `LARCH_SPARSE_DIRS`, not the old cache copy.
- **Legacy full clone** (`larch-logs/` present): `marketplace_sparse_cone_matches` already returns false → falls through to remove + sparse re-add (existing migration), now also reachable on the idempotent path.
- **`gh` unavailable**: `LATEST_STABLE` empty → `already_latest_and_cone_ok` is false → existing unconditional-upgrade path runs (unchanged).
- **Hook under stripped PATH / missing lib / missing git**: drift probe is fully best-effort; missing lib or tools → skip silently, hook still exits 0.
- **`/release` on a pure dev clone** (no `CUR_ROOT`): falls back to the existing Skill-tool invocation.
- **Prune during RC1**: explicit `CLAUDE_PLUGIN_ROOT=CUR_ROOT` makes `INSTALLED_VERSION=CURRENT_VERSION`, so prune retains both running and target versions.

## Failure modes

1. **RC1 `CLAUDE_PLUGIN_ROOT` mis-set or conflated with allowlist source** → `LARCH_CACHE_DIR` / prune mis-derive, or (if allowlist were sourced from `PLUGIN_ROOT`) RC1 reapplies a stale/missing lib from the pre-release cache. Earliest signal: prune log names unexpected versions, repeated wrong cone, or missing-lib failure under the cache root. Mitigation: compute `CUR_ROOT` from `CURRENT_VERSION`, guard `[ -d "$CUR_ROOT" ]`, source `lib-sparse-dirs.sh` only from `SCRIPT_ROOT`, use `CLAUDE_PLUGIN_ROOT` solely for cache/installed-version/prune; fall back to the Skill-tool path when `CUR_ROOT` is absent.
2. **Idempotent reconcile reinstalls on every run due to a false-negative cone match** (normalization mismatch between the lib and `git sparse-checkout list`) → repeated reinstalls. Earliest signal: `/upgrade-larch` always reinstalls when already-latest. Mitigation: both sides use the shared `normalize_sparse_dirs`; harness asserts match equality on identical lists.
3. **SessionStart probe latency or breakage** (slow/hanging `git` on the marketplace clone, or a sourced-lib error) → slower session start or a broken hook. Earliest signal: session-start delay or missing advisories. Mitigation: warn-only, best-effort guards, local-only git command, always exit 0; never source `upgrade-larch.sh`.
