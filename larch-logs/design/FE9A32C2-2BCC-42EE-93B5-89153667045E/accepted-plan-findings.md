### FINDING_1: Impure-attestation lines may leak into `findings.md`
- **Concern**: The cleanup as planned removes the only file-rewriting path that dropped impure-attestation lines. The OLD `_attempt_attestation_repair` function unconditionally called `drop_impure_empty_merge_attestation_lines` at function entry and wrote the cleaned text to `$cand_repaired_tmp`, so the downstream strip step (and the `mv` to `$agg_dest`) operated on already-cleaned bytes. After deletion, `drop_impure_empty_merge_attestation_lines` runs only inside the validator's `main()` and only against in-memory text — the file `$cand` still contains impure-token variants. The inline strip Python heredoc matches only the EXACT attestation token (`line.strip() == EMPTY_MERGE_ATTESTATION`), so variants like `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED suffix-junk` survive into `$merged_tmp` and thus into the merged `findings.md`. This is realized only when the model emits valid FINDING blocks alongside impure attestation variants (a rare prompt violation), but the existing harness stanza `zero_findings_impure_attest` exists specifically to guard against attestation-suffix leakage.
- **Proposed resolution**: extend the inline strip Python heredoc inside `_agg_pipeline_for_candidate` to also filter lines matching the `line_has_impure_empty_merge_attestation` predicate. The strip step then becomes: skip lines whose `.strip()` equals the exact token OR whose `.strip()` begins with the token but is not exactly the token. This preserves the OLD code's invariant that impure variants never reach `findings.md`.

### FINDING_2: Self-move `mv` becomes a no-op
- **Concern**: The plan calls for replacing `mv -f "$cand_repaired_tmp" "$agg_dest"` with `mv -f "$cand" "$agg_dest"` on the success path. However, `$cand` is derived from the dispatch's `ALL_OUTPUT_FILES`, which is the slot's `output:` path (i.e., `$out_path`). The pipeline invocation passes `_agg_pipeline_for_candidate "$cand" "$out_path"`, so `$agg_dest == $cand`. Self-move is a harmless no-op on Linux `mv` (GNU coreutils) but BSD `mv` (macOS default in some shells, FreeBSD) rejects it with "mv: rename ...: Invalid argument". The script runs under `set -euo pipefail`, so a non-zero `mv` exit would cascade.
- **Proposed resolution**: drop the `mv -f "$cand" "$agg_dest"` line entirely on the success path. Since `$cand` is already at `$agg_dest`, no move is needed. Only `mv -f "$merged_tmp" "$FINDINGS_FILE"` remains on the success path.
