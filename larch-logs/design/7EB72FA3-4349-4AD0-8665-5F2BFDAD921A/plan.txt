# Implementation Plan — Absorb /implement Step 5 review round-loop into review-and-fix.sh

## Goal

Collapse the prose-owned Step 5 round loop in `skills/implement/SKILL.md` into a single foreground Bash call. The new wrapper internalizes the round loop, post-round `run-relevant-checks-captured.sh`, post-checks `lint-fix-loop.sh`, the substantiality + bulk-skip-ratio gates, and the next-round decision. The main agent sees Step 5 as one bash call, parses a final summary KV envelope, and proceeds to Step 6 or Step 16. Cost reduction expected: 80%+ of current Step 5 Claude cost across observed runs (#2231 $37.52 → ~$3-6, #2253 $13.41 → ~$1-2, etc.).

   - Add new `run_implement_loop` function (placement: next to `run_implement_round` in the script):
     - Initialize `round_num` from `--starting-round N` (default 1). Validate per FINDING_3 above.
     - Compute `effective_round_cap = ROUND_CAP + count_prior_degraded_rounds(IMPLEMENT_TMPDIR, $round_num)` using the shared `lib-implement-round-cap.sh` helper. ROUND_CAP comes from `--round-cap` (loop mode requires base value, NOT pre-inflated — per FINDING_10).
     - Emit per-round breadcrumb via existing `emit_breadcrumb` path: `→ Step 5 round ${round_num}/${effective_round_cap}`.
     - For each iteration:
       - Call `_implement_round_body` for `round_num`. Capture round exit_code and parsed status keys (in-process, not via stdout — per FINDING_25).
       - **Status matrix branching** (per FINDING_4, FINDING_12, FINDING_18, FINDING_19 row in original list):
         - `REVIEW_AND_FIX_STATUS=main-agent-vote-required`: exit loop with `STEP5_REVIEW_STATUS=main-agent-vote-required`, `FINAL_ROUND_NUM=$round_num`, round artifacts intact under `round-${N}/`.
         - `REVIEW_AND_FIX_STATUS=panel-failed`: exit loop with `STEP5_REVIEW_STATUS=stall STALL_TRACKING=true STALL_REASON=panel-failed`.
         - `REVIEW_AND_FIX_STATUS=coder-failed`: check `CODER_STATUS` first. If `CODER_STATUS=submodule-violation`, exit with `STALL_REASON=submodule-violation`. Otherwise exit with `STALL_REASON=coder-failed`.
         - `REVIEW_AND_FIX_STATUS=converged-small-changes` or `no-changes` or `no-findings` or `in-scope-filtered-out`: exit loop with `STEP5_REVIEW_STATUS=complete` directly. **Do NOT run post-round checks/lint-fix/gates** — these statuses indicate no coder edits or filtered-out state.
         - `REVIEW_AND_FIX_STATUS=fix-applied`: continue to post-round helper dispatch below.
         - Any other / unknown `REVIEW_AND_FIX_STATUS`: exit with `STEP5_REVIEW_STATUS=stall STALL_REASON=round-failed-${REVIEW_AND_FIX_STATUS:-unknown}` (catch-all).
       - Post-round helper dispatch (only for `fix-applied`):
         - Dispatch `run-relevant-checks-captured.sh --tmpdir "$IMPLEMENT_TMPDIR" --site step5-review-fixes`. **Parse with token-aware splitter** (per FINDING_22): each line may carry multiple `KEY=value` tokens; tokenize by whitespace and extract each `KEY=value` independently. Recognize `STATUS`, `RELEVANT_CHECKS_OK`, `RELEVANT_CHECKS_SKIPPED`, `REDACTED_LOG_FILE`, `FAILURE_REASON`.
         - **Structural failure routing** (per FINDING_5): if `STATUS=fail` AND `REDACTED_LOG_FILE` is empty/absent, treat as structural stall: exit loop with `STEP5_REVIEW_STATUS=stall STALL_REASON=relevant-checks-${FAILURE_REASON:-unknown}`. Do NOT dispatch lint-fix-loop without a redacted log.
         - If `STATUS=fail` AND `REDACTED_LOG_FILE` is non-empty:
           - Initialize `lint_fix_attempts=0`, `lint_fix_max=${LARCH_STEP5_LINT_FIX_MAX_ATTEMPTS:-3}` (per FINDING_11).
           - Loop:
             - Dispatch `lint-fix-loop.sh --tmpdir "$IMPLEMENT_TMPDIR" --site step5 --checks-log "$REDACTED_LOG_FILE"`. Parse `LINT_FIX_STATUS`.
             - On `applied`: increment `lint_fix_attempts`. If `lint_fix_attempts >= lint_fix_max`, exit loop with `STEP5_REVIEW_STATUS=stall STALL_REASON=lint-fix-attempt-cap`. Otherwise re-dispatch `run-relevant-checks-captured.sh`; if pass, break to substantiality gate; if fail, repeat.
             - On `main-agent-required`: exit loop with `STEP5_REVIEW_STATUS=stall STALL_REASON=lint-fix-main-agent-required`.
             - On `failed`: exit loop with `STEP5_REVIEW_STATUS=stall STALL_REASON=lint-fix-failed`.
             - On `no-changes`: re-invoke checks once; if still failing, treat as `failed` stall.
         - On checks `RELEVANT_CHECKS_OK=true` or `RELEVANT_CHECKS_SKIPPED=true`, apply the re-review gate.
       - Re-review gate (substantiality + bulk-skip-ratio):
         - Re-read `DEGRADED_ROUND` from `round-${N}/review-and-fix.env`; if `true`, increment `effective_round_cap` once for the current iteration.
         - Substantiality classification: substantial = (`HIGH_SEVERITY_COUNT >= 2`) OR (`structural_loc >= 100`) OR (`FIX_COUNT >= 8`). `structural_loc` = `git diff --numstat $(cat round-${N}/pre-coder-head.txt) $(cat round-${N}/post-coder-head.txt) | awk '{a+=$1; b+=$2} END {print a+b}'`. On numstat failure, structural_loc=0; log Warnings entry; fall through to other criteria.
         - If non-substantial: log `Step 5 — review loop stopped after round $round_num because accepted findings were not substantial`, defer continuation/exit to bulk-skip-ratio gate.
         - Bulk-skip-ratio gate (regardless of substantiality): if `FIX_COUNT > 0`, compute `skip_ratio = SKIPPED_FINDING_COUNT / FIX_COUNT`; threshold default 0.5 (overridable via `LARCH_SKIP_RATIO_THRESHOLD`; same validation as today — invalid decimal logs Warnings and uses 0.5).
           - If `skip_ratio >= threshold` AND `round_num < effective_round_cap`: log loop-trigger to Warnings, increment `round_num`, continue iteration.
           - If `skip_ratio >= threshold` AND `round_num == effective_round_cap`: exit loop with `STEP5_REVIEW_STATUS=stall STALL_TRACKING=true STALL_REASON=bulk-skip-ratio-cap`.
         - If substantial AND `round_num < effective_round_cap`: increment `round_num`, continue iteration.
         - If substantial AND `round_num == effective_round_cap` AND bulk-skip-ratio gate did not stall: exit loop with `STEP5_REVIEW_STATUS=cap-hit`. Main agent prints `**⚠ 5: code review hit $EFFECTIVE_ROUND_CAP-round cap without converging. Proceeding.**`.
         - If non-substantial AND bulk-skip-ratio gate did not loop: exit loop with `STEP5_REVIEW_STATUS=complete`.
     - On loop exit, emit a final summary KV envelope as the LAST lines of stdout (last-line discipline). Envelope fields with restricted enums (per FINDING_23):
       - `STEP5_REVIEW_STATUS` ∈ {`complete`, `stall`, `cap-hit`, `main-agent-vote-required`, `mav-resume-past-cap`}
       - `STALL_TRACKING` ∈ {`true`, `false`}
       - `STALL_REASON` ∈ {`coder-failed`, `panel-failed`, `submodule-violation`, `lint-fix-failed`, `lint-fix-main-agent-required`, `lint-fix-attempt-cap`, `bulk-skip-ratio-cap`, `relevant-checks-<reason>`, `starting-round-invalid`, `round-failed-<status>`, `classifier-failed`, `env-write-failed`, ``} (empty when STALL_TRACKING=false)
       - `ROUNDS_COMPLETED=N` (count of rounds executed in this invocation)
       - `FINAL_ROUND_NUM=N` (the round at which the loop exited)
       - `FINAL_REVIEW_AND_FIX_STATUS=<last per-round status>`
       - `CODER_STATUS=<last per-round CODER_STATUS, or empty>` (per FINDING_12, to disambiguate submodule-violation)
       - `FILES_CHANGED_HINT=<best-effort concat of CODER_COMMIT_SHA values or count>`
       - `EFFECTIVE_ROUND_CAP=N` (the cap at exit, for parity with the SKILL.md banner)
     - **Exit code contract** (per FINDING_15): wrapper exits 0 for `complete`, `cap-hit`, `main-agent-vote-required`, `mav-resume-past-cap`; exits 2 for `stall` (any reason). Pin in tests.
     - **`flush_review_batches` cadence** (per FINDING_24): each `_implement_round_body` call ends with `flush_review_batches` as today, gated on `exit_code == 0`. Additionally, after the loop exits on stall paths (where the latest round body may have aborted before its flush), call `flush_review_batches` once with best-effort flag so stall paths still produce partial batches. The per-round flush stays for crash-safety.
   - Add new `run_implement_mav_apply` function (per FINDING_9): accepts `--findings-file`, `--implement-tmpdir`, `--round-num N`. Performs the same commit/artifact contract as an ordinary review round: writes `round-N/pre-coder-head.txt`, dispatches coder, writes `round-N/post-coder-head.txt` on success, flushes batches. Returns commit status to caller.

## Approach

The dispatch architecture preserves `run_implement_round` as the per-round primitive (single source of truth for round logic). The new `run_implement_loop` calls a refactored `_implement_round_body` iteratively without exiting, applies the post-round helper dispatch (relevant-checks → lint-fix-loop) inline with token-aware parsing and an attempt cap, applies the substantiality + bulk-skip-ratio gates inline with deterministic disk-derived inputs, and emits a final summary KV envelope with restricted enums. The launcher `scripts/run-step5-review.sh` defaults to `--mode loop` going forward; cap math is owned by the wrapper in loop mode and by the launcher in single mode. The main agent's role in Step 5 collapses to: print one banner, call one bash, parse one envelope, route. The MAV path uses an explicit `--mode mav-apply` to preserve commit semantics, and re-invokes the wrapper with `--starting-round N+1` for resume.

### Key decisions

1. **Co-locate the loop with the round primitive** — `run_implement_loop` lives next to `run_implement_round` in `review-and-fix.sh`. Per Step 2a.5 dialectic-resolution: synthesis stands (fallback-to-synthesis). FINDING_26 (child-process loop alternative) was exonerated by the voting panel; the in-process refactor proceeds with the explicit exit audit per FINDING_16.

2. **Preserve single-round CLI** — `review-and-fix.sh --mode diff --round-num N` continues to work without input changes for `test-review-and-fix.sh` and per-round debugging. The new `--mode loop` is additive.

3. **`--starting-round N` for restart from MAV** — the main agent re-enters with the next round number; `count_prior_degraded_rounds` (now from shared library) reads from disk so cap math survives the bail.

4. **Substantiality with deterministic inputs**:
   - `HIGH_SEVERITY_COUNT`: scanned from `round-N/accepted-findings.md` via `important_findings_present` regex family; persisted to `round-N/review-and-fix.env`.
   - `structural_loc`: `git diff --numstat $(round-N/pre-coder-head.txt) $(round-N/post-coder-head.txt)` summed across files; threshold 100.
   - `FIX_COUNT`: persisted to `round-N/review-and-fix.env`.
   First cut keeps it simple — no comment-filtering or file-path filtering (OOS_3 follow-up).

5. **Cap-math ownership**: shared library `lib-implement-round-cap.sh`. Loop mode wrapper inflates internally from BASE cap; launcher single mode pre-inflates as today. No double-inflation possible.

6. **Per-round `flush_review_batches` preserved** — each `_implement_round_body` call still ends with `flush_review_batches`. Crash-safety unchanged. Additionally, stall-path exit calls `flush_review_batches` once with best-effort flag (per FINDING_24) so audit trail parity holds.

7. **Per-round live breadcrumbs** — uses the existing `emit_breadcrumb` path. Operators see real-time round transitions.

8. **Stall vocabulary as fixed enum** — `STALL_REASON` restricted to documented tokens at emit time; no raw subprocess output interpolation. Full subprocess details go to round logs.

9. **Exit code contract**: 0 for success states (complete, cap-hit, MAV, mav-resume-past-cap); 2 for stall (any reason). Orchestrator parses envelope BEFORE branching on `$?` defensively, but exit code is the primary signal.

10. **Source-safe testing**: `main "$@"` guard at script bottom; tests can `source` the script without triggering top-level dispatch, then stub `_implement_round_body` and `run_implement_mav_apply` for state-machine testing.

11. **Remove duplicate tally prose** — verified at `review-and-fix.sh:542-690` that `flush_review_batches` writes both `code-review-tally` and `review-findings-full` batches per round with full content. The SKILL.md prose at lines ~1245-1281 is dead duplication. Removing it eliminates a source of drift.

12. **`--issue 0` as the authoritative contract for in-process compose** (per FINDING_13 + OOS_5). `compose_review_findings_output` passes `--issue 0`; downstream consumers (run-log miners, audit tools) join records by RUN_ID rather than issue number. Documented in `scripts/larch-log-batches.md`.

### Tradeoffs

- **Pro**: 80%+ Claude $ reduction at Step 5 (the dominant cost driver). Cleaner state machine. No drift between SKILL.md prose and runtime stall conditions.
- **Pro**: Source-safe testing seam unlocks stubbed-function state-machine tests.
- **Pro**: Shared cap-math library eliminates a long-standing drift risk between launcher and wrapper.
- **Con**: The substantiality logic moves from main-agent judgment to bash with deterministic proxies. The "≥100 LOC structural" criterion is an approximation; subjective judgment is replaced by a threshold.
- **Con**: Per-round artifact set grows (pre-coder-head.txt, post-coder-head.txt, HIGH_SEVERITY_COUNT in env). Modest disk + complexity cost.
- **Con**: Exit-audit work is non-trivial (3 confirmed body-reachable `exit 2` sites + helpers). Each conversion needs a regression test.

## Edge cases

- **Restart at round N>1 with no prior round artifacts**: validate at wrapper entry that `round-${N-1}/review-and-fix.env` exists; on missing artifact, exit with `STALL_REASON=starting-round-invalid` (per FINDING_3 + FINDING_18 catch-all).
- **Degraded round inflation across wrapper invocations**: shared `count_prior_degraded_rounds` reads from disk; degraded-flag inflation accumulates correctly across MAV-resume re-invocations.
- **`run-relevant-checks-captured.sh` returns `RELEVANT_CHECKS_SKIPPED=true`** (e.g., no check script applicable): treat as pass; proceed to substantiality gate. Same as today.
- **MAV occurs at round 5 (cap)**: wrapper exits MAV-required; main agent resolves; re-invokes with `--starting-round 6`. Loop enters, sees `round_num > effective_round_cap`, exits `STEP5_REVIEW_STATUS=mav-resume-past-cap` (distinct token per FINDING_27). Main agent prints `**ℹ 5: MAV resume past cap; no additional review round executed.**` and continues.
- **Coder commits no changes after `fix-applied`** (pathological): `pre-coder-head == post-coder-head`, so `structural_loc=0`; substantiality falls back to `HIGH_SEVERITY_COUNT` and `FIX_COUNT` criteria.
- **`LARCH_SKIP_RATIO_THRESHOLD` invalid decimal**: same validation as today — log Warnings entry, use default 0.5.
- **`git diff --numstat` fails** (e.g., HEAD detached unexpectedly): `structural_loc=0`, log Warnings entry. Substantial only if other criteria say so.
- **`run-relevant-checks-captured.sh` emits multi-KV-per-line**: token-aware parser handles this correctly (per FINDING_22).
- **`STATUS=fail` with no `REDACTED_LOG_FILE`** (log-dir-create-failed, log-allocation, etc.): treated as structural stall, no lint-fix attempted (per FINDING_5).
- **`lint-fix-loop.sh` returns `applied` repeatedly**: capped at `LARCH_STEP5_LINT_FIX_MAX_ATTEMPTS` (default 3); stall with `lint-fix-attempt-cap` (per FINDING_11).
- **Unknown `REVIEW_AND_FIX_STATUS`**: catch-all `STALL_REASON=round-failed-<status>` (per FINDING_18).
- **`run_implement_round` legacy CLI re-entry**: existing `--mode diff --round-num N` still works (no `main "$@"` triggering when sourced for tests; when invoked as a script with `--mode diff`, the new `main` dispatches to `run_implement_round` exactly as before).

## Failure modes (top 3)

1. **Contract drift between absorbed loop's KV envelope and SKILL.md parser.**
   - **Earliest warning**: structure test asserting that SKILL.md's parser case-branches cover every value `STEP5_REVIEW_STATUS` can emit (including `mav-resume-past-cap`). CI fails when a new wrapper status is added without updating SKILL.md.
   - **Simplest mitigation**: pin the envelope shape in `test-review-and-fix.sh` — every loop-exit path asserts the EXACT KV set (names, allowed enum values) — and the SKILL.md structure assertion.

2. **Exit-audit miss leaves an uncaught `exit 2` inside the loop body.**
   - **Earliest warning**: each formerly-exit-2 path has a regression test that simulates the failure condition and asserts the final envelope is emitted (the process did NOT die mid-loop).
   - **Simplest mitigation**: enumerate confirmed sites (review-and-fix.sh:199, :1131, :1238) in the plan + grep CI assertion that no new `exit 2` calls exist in functions called from `_implement_round_body` without a corresponding regression test.

3. **Substantiality `HIGH_SEVERITY_COUNT` scanner false-positive/negative.**
   - **Earliest warning**: a unit test that pins the regex output against a corpus of known-tagged accepted findings.
   - **Simplest mitigation**: reuse the existing `important_findings_present` regex family (already validated); document the regex as load-bearing in `review-and-fix.md`. Subsequent OOS-3 follow-up may refine.
