Main tradeoff: the obvious script loop saves money but moves more policy into bash, so the danger is silent drift from the review skill’s proportionality/substantiality semantics. I’d avoid “~100 LOC structural fix” as a fuzzy Bash judgment unless there is already a changed-LOC helper; use deterministic proxies first: high severity count from accepted findings, accepted count `>=8`, and a computed non-comment diff line threshold from `git diff --numstat` before/after each round. Crazy but plausible: instead of running full checks after every round, run a cheap “dirty sanity” plus targeted changed-file lint between rounds and defer full `relevant-checks` to Step 6, cutting wall time as well as Claude turns. Riskier but interesting: have the loop spawn all remaining re-review rounds speculatively only when fixes touched isolated files, then cancel later rounds if an earlier round converges; probably too complex for first cut, but it points at the real boundary: make Step 5 a durable state machine, not a transcript-driven conversation.
