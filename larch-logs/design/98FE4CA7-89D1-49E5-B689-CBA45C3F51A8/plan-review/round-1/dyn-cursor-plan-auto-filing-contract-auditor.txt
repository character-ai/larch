### 1. [code-quality] Generic `###` batch boundaries (`skills/issue/SKILL.md:113`)

The `/issue` generic batch parser treats any unfenced line starting with `### ` as a new item boundary. The plan requires filed bodies to include complete invariant and guideline text that uses repo-native headings such as `### I-Gate-1:` and `### G-Fix-1:` (`ARCHITECTURAL_INVARIANTS.md`, `ARCHITECTURAL_GUIDELINES.md`). Those lines will split one intended issue into several batch items or yield malformed entries. OOS-shaped `### OOS_N:` lines are absorbed in generic bodies (`python/tests/issue/test_issue_create.py` issue #132), but invariant and guideline IDs are not.

### 2. [correctness] Step 5 / `--file` exclusivity (`skills/learn-from-bugs/SKILL.md:136-139`)

Current Step 5 opens with unconditional approval-gated follow-ups. The plan adds a `--file` branch after the marker commit but does not guard Step 5 entry. Without an explicit `FILE_MODE` branch, `--file` runs can still hit the default apply gates and violate the no-apply contract.

### 3. [architecture] Hook proposals missing from `--file` residuals (`skills/learn-from-bugs/SKILL.md:81-84`, `:144`)

The report already proposes hook-shaped preventions and default Step 5 can update hook contracts. The planned `--file` category list omits hooks, so hook residuals would remain report-only even in auto-file mode.

### 4. [correctness] `-s` alias dropped vs binding scope (`skills/learn-from-bugs/SKILL.md:28-39`)

The scope anchor requires `--file/-s`. The plan adds `-f`, rejects `-s`, and does not document the deviation in the planned doc updates. That is a completeness gap against the stated feature.

### 5. [risk-integration] Partial child failure under-reporting (planned `--file` `/issue` handoff)

Research and decompose filing paths treat `ISSUES_FAILED>0`, sentinel verification, and stdout parsing as mechanical contracts. The plan’s edge case prose is not enough; the SKILL needs explicit fail-closed steps so `--file` does not claim full filing after dedup drops, dep-link orphans, or parse-input failure.

### [OUT_OF_SCOPE] Optional `--dry-run` preview before batch create

A pre-filing `issue parse-input` or `/issue --dry-run` gate would catch boundary mistakes early. Useful, but not required for the feature to function once finding 1 is fixed.
