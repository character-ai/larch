**1. [correctness]** `scripts/implement-admission.sh:207-210` — Early rename before `post-tracking-issue.sh` collides with admission on deferred-metadata recovery.

The plan moves `rename_to_implementing` to immediately after Branch 2 eligibility checks and accepts `[IMPLEMENTING]` when `POSTED=false` defers (`plan.txt` edge cases). Today, that defer path leaves no `parent-issue.md` and removes any stale sentinel (`scripts/implement-bootstrap.sh:671-674`). Preflight admission rejects `[IMPLEMENTING]` titles via `has_managed_prefix` unless a matching sentinel grants `RESUME=true` (`scripts/implement-admission.sh:161-210`).

Before the change, `POSTED=false` left the title `[DESIGNED]`, so a later fresh `/implement` could pass admission. After the change, a deferred-metadata run that does not finish in one session (or any operator who retries without the preserved tmpdir / `--resume-plan-tail`) hits exit **5** even though `DEFERRED=true` was intended to allow continuation. Dirty-tree recovery within one session is unaffected because SKILL re-enters bootstrap with `--resume-plan-tail` without re-running admission (`skills/implement/SKILL.md:478-510`); the gap is cross-session re-entry.

**Suggested revision:** Add a required plan step—either a narrow admission exception for this recovery surface, or explicit operator guidance that fresh `/implement` is unsupported after `POSTED=false` defer unless the title is manually reverted.

**2. [risk-integration]** `skills/implement/SKILL.md:701-702` — Canonical Step 0 table contradicts the proposed ordering.

Row 701 still lists `larch-log.sh init` → `post-tracking-issue.sh` → rename; row 702 still says `POSTED=false` implies “no rename.” Both become false after relocation. The plan lists stale docs as failure mode #1 but defers fixes to optional lint (`plan.txt:133-134, 143`), and structure tests do not enforce these strings.

**Suggested revision:** Require updating those two table rows in the same PR (minimal prose; no new helpers).

[OUT_OF_SCOPE] `scripts/implement-admission.sh` — A full `managed-prefix` carve-out for `[IMPLEMENTING]` + `larch:plan` without a sentinel is the durable fix for finding 1 but exceeds the stated ~25-line SIMPLE scope; track as a follow-up if product wants frictionless cross-session retry after metadata defer.
