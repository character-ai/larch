1. **[correctness] `skills/review/scripts/aggregate-findings.sh:28-40`**  
   Existing boolean-style arguments, including `--codex-present` and `--cursor-present`, consume the next positional with `${2:?}` and `shift 2`; there is no `--flag=value` case. The plan’s proposed parse arm matches that split-argv grammar, but the new error hint and docs repeatedly tell users to pass `--allow-findings-outside-tmpdir=true`. That exact spelling will be rejected as an unknown option. Revise the hint/docs to use `--allow-findings-outside-tmpdir true`, or deliberately support both forms in the parser.

2. **[correctness] `skills/review/scripts/aggregate-findings.sh:50-69`**  
   The new flag is proposed for validation after the existing boolean block, but the containment gate would use it before that point. With `--allow-findings-outside-tmpdir maybe` and an outside file, the script would emit the containment rejection instead of the promised `must be true or false` validation error. Add an early validation for this new flag before the containment `case`, and test invalid values against an outside-tmpdir file.

3. **[security] `AGENTS.md:15-19`, `SECURITY.md:61-90`**  
   The plan calls this a trust-boundary knob and allows an opt-in in-place rewrite of a file outside `--review-tmpdir`, but explicitly says not to update `SECURITY.md`. That conflicts with the repo rule to update `SECURITY.md` for security-relevant behavior changes. Add a short trust-model note documenting the opt-in, non-symlink guard, input-only relaxation, strict output containment, and rewrite risk.

4. **[code-quality] `skills/review/scripts/test-aggregate-findings.sh:12-13`**  
   The harness currently cleans only `$TMP`. The plan creates `$TMP_OUTSIDE` with `mktemp -d` but does not extend cleanup, so the new tests will leak temp directories. Extend the trap to include `${TMP_OUTSIDE:-}` or otherwise clean the sibling directory explicitly.
