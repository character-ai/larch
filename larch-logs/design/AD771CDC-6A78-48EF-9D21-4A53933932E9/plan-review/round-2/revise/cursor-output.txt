### NEW: `scripts/lib-failed-agent-stderr-tail.sh`
Sourced-only library (no shebang; `set` left to caller) holding the shared, dependency-free primitives. Renders to stdout / writes files only — it performs NO raw `>&2` itself, so it is safe to source from both quiet-init callers (`collect-agent-results.sh`, `launch-claude-review.sh`) and non-quiet `run-external-agent.sh` without tripping `lint-no-raw-stderr-after-quiet-init`.
Functions:
- `failed_agent_stderr_tail_lines()` — echo the resolved tail-line count from `LARCH_FAILED_AGENT_STDERR_TAIL_LINES` (default **`50`**; non-numeric → `50`; `0` is valid and means disabled).
- `failed_agent_stderr_byte_cap()` — echo the byte ceiling (fixed `5120`; internal constant, not user-tunable in this change).
- `render_failed_agent_stderr_tail <source_file>` — if disabled (`0`) or `source_file` is missing/empty, print nothing and return non-zero. Else: spool `tail -n <N> "$source_file"` through `scripts/redact-secrets.sh` into a temp file (mktemp + mv), then apply the byte cap with `head -c 5120` on that file using the repo’s inherited-pipefail pattern from `scripts/lib-cursor-launcher-common.sh` (`set +o pipefail` around `head -c`, e.g. lines 281–294) so SIGPIPE from early truncation cannot make `render_*` / `write_*` fail under callers with `set -o pipefail` + `set -e`. Print capped content to STDOUT. Resolve `redact-secrets.sh` via the lib’s own `SCRIPT_DIR`. **Do not** use a bare `tail | redact | head -c` pipeline under inherited pipefail.
- `write_failed_agent_stderr_tail <source_file> <output_file>` — capture `render_failed_agent_stderr_tail` and, when non-empty, write it atomically to `${output_file}.stderr-tail` (mktemp + mv). When disabled/empty, `rm -f` any pre-existing `${output_file}.stderr-tail` so stale tails cannot survive a later success or empty failure. Must return success when content was written even if the source exceeded the byte cap (regression for #3119 large tails).
- `failed_agent_stderr_signature <tail_file>` — emit a best-effort root-cause fingerprint: normalize volatile tokens via `sed -E` (digit runs `[0-9]+`→`#`, `0x[0-9a-fA-F]+`→`0x#`, absolute tmpdir/session paths under `/tmp`, `/var/folders`, and `~/.cache/larch/sessions` →`<path>`, the literal output basename →`<out>`), then `cksum | awk '{print $1}'`. Documented explicitly as a heuristic, NOT semantic understanding.
- `emit_failed_agent_stderr_tail_raw <output_file>` — for non-quiet callers: if `${output_file}.stderr-tail` exists and is non-empty, print a bounded fenced block to FD 2 via plain `printf >&2` (header `--- <basename> stderr tail (last N lines, redacted) ---`, body, `--- end stderr tail ---`). Used only by `run-external-agent.sh` (foreground paths where launcher stderr is not discarded).
- `resolve_failed_agent_stderr_source <output_file> <capture_stdout> <capture_stdout_only>` — helper returning the first existing non-empty path for the active capture mode (see `run-external-agent.sh` below); keeps selection logic in one place for harnessing.
Bash 3.2-safe throughout (no associative arrays, no `mapfile`, no `${var^^}`).

## Approach
- One shared lib owns tail+redact+cap+signature+source resolution so call sites stay tiny and logic has a single isolated harness.
- Byte cap uses spool-then-`head -c` with `set +o pipefail`, not a failing pipeline — largest tails must still produce `.stderr-tail` under `set -e` callers.
- Capture happens where the exit is observed (`run-external-agent.sh` for codex/cursor, `launch-claude-subprocess.sh` for claude agent failures); the redacted tail is persisted to `${OUTPUT}.stderr-tail` for cross-process handoff.
- Surface to chat on FD 2: `emit_*` from `run-external-agent.sh` when launcher stderr is not discarded; **`collect-findings.sh` tees** collector `larch_err` dedup output to the parent FD 2 on successful `/review` collection; background implement/panel lanes still depend on collector dedup after `wait-for-reviewers`.
- Dedup lives only in the collector; stale `${ORIG}.stderr-tail` is removed when retry/NS upgrades a slot to OK so publish cannot pair OK with a first-pass failure artifact.
- Default **50** lines matches issue #3202 acceptance criteria; env var remains the tuning knob.
- The `.stderr-tail` sidecar is intentionally NOT added to `design-log-publish.sh`'s exclusion glob.

## Edge cases
- Disabled (`LARCH_FAILED_AGENT_STDERR_TAIL_LINES=0`) → no sidecar, no emission, fully quiet.
- Empty/missing stderr source → no sidecar, no emission.
- Success (exit 0), including exit-0-but-empty-output → no tail (failure-only).
- Transient retry or NS-retry success → `rm -f "${ORIG_OUTPUT}.stderr-tail"` even when `REVIEWER_FILE` points at `*-retry.txt` or `*-ns-retry.txt`.
- Stale `${OUTPUT}.stderr-tail` from a prior run → pre-launch `rm -f` and disabled/empty `write_*`.
- Single pathological multi-KB line → byte cap truncates after redaction; pipefail must not block write.
- Non-numeric env value → falls back to **50**.
- `--capture-stdout` failure → tail prefers merged `OUTPUT_FILE`, not wrapper-only `.diag`.
- `--capture-stdout-only` failure → tail prefers `.diag` (agent stderr), not stdout file.
- Pipe/`KEY=value`-looking lines inside stderr → harmless on FD 2 only.
- Redaction idempotency → publishing already-redacted `.stderr-tail` re-runs redact as a no-op.
- Bash 3.2: collector dedup uses temp-file map + `command grep -F`.
- Retry failure: dedup reads `*-retry.txt.stderr-tail` when present.
- Inline `/review` + `dispatch-with-waterfall.sh`: launcher stderr discarded; chat surfacing is collector tee + `.stderr-tail` sidecars, not `emit_*` at dispatch.

## Failure modes
1. Parser corruption if the tail leaked into stdout. Mitigation: tail strictly FD 2; harness asserts stdout RESULTS unchanged when `.stderr-tail` exists.
2. Secret leak if redaction is skipped. Mitigation: redaction inside `render_*`; harness feeds a fake token.
3. Over-suppression via signature collision. Mitigation: conservative normalization; first full tail always prints; harness pins distinct-cause → distinct signature.
4. Pre-retry or stale-tail surfacing. Mitigation: dedup after §3.7; pre-launch `rm -f`; retry-path tail resolution; `rm -f` on retry/NS OK; claude tail before `.done`.
5. SIGPIPE abort under pipefail on large tails. Mitigation: spool + `set +o pipefail` around `head -c`; harness with pipefail caller and oversized stderr.
6. `/review` success hides tails in log-only collector stderr. Mitigation: `collect-findings.sh` tee to FD 2; `test-collect-findings.sh` asserts fenced tails visible on wrapper stderr when collection succeeds.
