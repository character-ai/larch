# Implementation Plan — Surface failed agent stderr tail to chat (#3202)

Goal: on every non-zero codex/cursor/claude subprocess exit in review/collector batches — and
other `run-external-agent.sh` invocations where stderr resolves via the planned source order —
surface the last N (default 30)
redacted stderr lines to chat, bounded to 5 KB, so reviewer-failure root causes survive
publish-exclusion and tmpdir cleanup. Within one collector batch, suppress duplicate
same-root-cause failures down to one line each. Additive only: the existing verdict line,
`.diag`, and the `collect-agent-results.sh` single-line `FAILURE_REASON` contract are unchanged.

**Out of scope (SIMPLE tier):** lint-fix-loop (`codex.wrapper.log`) and implement launchers
(`--sidecar-log` paths) lack `${OUTPUT}.sidecar` at the choke point; do not claim foreground
chat surfacing for those lanes without a follow-up stderr-source hook.

SIMPLE tier: smallest change that covers all lanes via the shared choke points
(`run-external-agent.sh` + `collect-agent-results.sh`) plus the claude launcher that bypasses
the runner. No bespoke per-`launch-*-*.sh` edits.

## Files to modify/create

### NEW: `scripts/lib-failed-agent-stderr-tail.sh`
Sourced-only library (no shebang; `set` left to caller) holding the shared, dependency-free
primitives. Renders to stdout / writes files only — it performs NO raw `>&2` itself, so it is
safe to source from both quiet-init callers (`collect-agent-results.sh`, `launch-claude-review.sh`)
and non-quiet `run-external-agent.sh` without tripping `lint-no-raw-stderr-after-quiet-init`.
Functions:
- `failed_agent_stderr_tail_lines()` — echo the resolved tail-line count from
  `LARCH_FAILED_AGENT_STDERR_TAIL_LINES` (default `30`; non-numeric → `30`; `0` is valid and
  means disabled).
- `failed_agent_stderr_byte_cap()` — echo the byte ceiling (fixed `5120`; internal constant,
  not user-tunable in this change).
- `render_failed_agent_stderr_tail <source_file>` — if disabled (`0`) or `source_file` is
  missing/empty, print nothing and return non-zero. Else `tail -n <N> "$source_file"` piped
  through `scripts/redact-secrets.sh` then truncated to the byte cap (`head -c 5120`), printed
  to STDOUT. Resolve `redact-secrets.sh` via the lib's own `SCRIPT_DIR`.
- `write_failed_agent_stderr_tail <source_file> <output_file>` — capture
  `render_failed_agent_stderr_tail` and, when non-empty, write it atomically to
  `${output_file}.stderr-tail` (mktemp + mv). When disabled/empty, `rm -f` any pre-existing
  `${output_file}.stderr-tail` so stale tails cannot survive a later success or empty failure.
- `failed_agent_stderr_signature <tail_file>` — emit a best-effort root-cause fingerprint:
  normalize volatile tokens via `sed -E` (digit runs `[0-9]+`→`#`, `0x[0-9a-fA-F]+`→`0x#`,
  absolute tmpdir/session paths under `/tmp`, `/var/folders`, and `~/.cache/larch/sessions`
  →`<path>`, the literal output basename →`<out>`), then `cksum | awk '{print $1}'`. Documented
  explicitly as a heuristic (volatile-token normalization), NOT semantic understanding.
- `emit_failed_agent_stderr_tail_raw <output_file>` — for non-quiet callers: if
  `${output_file}.stderr-tail` exists and is non-empty, print a bounded fenced block to FD 2 via
  plain `printf >&2` (header `--- <basename> stderr tail (last N lines, redacted) ---`, body,
  `--- end stderr tail ---`). Used only by `run-external-agent.sh`.
Bash 3.2-safe throughout (no associative arrays, no `mapfile`, no `${var^^}`).

## Approach
- One shared lib owns tail+redact+cap+signature so the three call sites stay tiny and the logic
  has a single isolated harness.
- Capture happens where the exit is observed (`run-external-agent.sh` for codex/cursor,
  `launch-claude-review.sh` for claude); the redacted tail is persisted to `${OUTPUT}.stderr-tail`
  for cross-process handoff.
- Capture for claude agent failures happens in `launch-claude-subprocess.sh` before `.done`; parent
  `launch-claude-review.sh` covers pre-subprocess validation failures only.
- Surface to chat on FD 2: directly from `run-external-agent.sh` for review runs with a resolvable
  stderr source, and re-surfaced by `collect-agent-results.sh` for background review/panel lanes
  — the #3119 case. Lint-fix/implement lanes are explicitly out of scope for SIMPLE tier.
- Dedup lives only in the collector because that is the single point that sees a whole batch of
  slots at once; it is the exact surface where the flood occurred.
- The `.stderr-tail` sidecar is intentionally NOT added to `design-log-publish.sh`'s exclusion
  glob: letting the redacted, bounded, failure-only tail publish into `larch-logs/` is bonus
  post-hoc recoverability aligned with the issue's intent, and keeps the change inside the
  user-approved 3-script centralization.

## Edge cases
- Disabled (`LARCH_FAILED_AGENT_STDERR_TAIL_LINES=0`) → no sidecar, no emission, fully quiet.
- Empty/missing stderr source → no sidecar, no emission (foreground 0-byte case stays quiet).
- Success (exit 0), including exit-0-but-empty-output → no tail (failure-only).
- Stale `${OUTPUT}.stderr-tail` from a prior run → removed on pre-launch `rm -f` and on
  disabled/empty `write_failed_agent_stderr_tail`.
- Single pathological multi-KB line → byte cap truncates to 5 KB after redaction.
- Non-numeric env value → falls back to 30 (no crash under `set -u`/`set -e`).
- Pipe/`KEY=value`-looking lines inside stderr → harmless: tail is FD 2 only, never the stdout KV
  plane, so the orchestrator parser cannot ingest it.
- Redaction idempotency → publishing already-redacted `.stderr-tail` re-runs redact at publish as
  a no-op.
- Bash 3.2: collector dedup uses a temp-file map + `command grep -F`, not associative arrays.
- Retry failure: dedup reads `*-retry.txt.stderr-tail` when present so tail aligns with
  `FAILURE_REASON` for the retry attempt.

## Failure modes
1. Parser corruption if the tail leaked into stdout. Earliest signal: collector consumers misread
   `STATUS`/`FAILURE_REASON`. Mitigation: tail is strictly FD 2 (`larch_err` / raw `>&2`); add a
   harness assertion that stdout RESULTS lines are unchanged when a `.stderr-tail` exists.
2. Secret leak to chat/committed log if redaction is skipped. Earliest signal: a token appears in
   a `.stderr-tail` test fixture. Mitigation: redaction is inside `render_*` (single path); harness
   feeds a fake token and asserts redaction.
3. Over-suppression: a genuinely different failure hashed to the same signature and got collapsed.
   Earliest signal: a real distinct cause shown as "identical". Mitigation: conservative
   normalization (only clearly-volatile tokens); the first full tail always prints; harness pins
   distinct-cause → distinct-signature.
4. Pre-retry or stale-tail surfacing. Earliest signal: FD-2 tail for a slot later upgraded to OK,
   or a success run showing an old tail. Mitigation: dedup only after §3.7 / pre-§4; pre-launch
   `rm -f` of `.stderr-tail`; retry-path tail resolution; claude tail before `.done`.

- Extend `scripts/test-run-external-agent.sh`: failed stub run writes `.stderr-tail` and emits the
  fenced block to stderr; success run writes nothing; `0`-disable writes nothing.

  first full tail + one suppression line on FD 2; distinct causes → two full tails; stdout RESULTS
  KV contract byte-unchanged; retry failure prefers `*-retry.txt.stderr-tail` over stale
  `${ORIG_OUTPUT}.stderr-tail`.

  `.done` on agent failure; collector pass does not run until final `RESULTS[]` (post-retry).

  writes none; existing full re-emit still present.

- Run `bash scripts/relevant-checks.sh` (covers shellcheck, bash32, raw-stderr, bare-grep, md
  siblings) plus the new and extended harness targets.
