Reviewing launcher code to align the revised plan with current per-family ordering and contracts.
## Plan

Treat this as a behavior-preserving refactor. Preserve every `KEY=value` stdout line, every public sidecar path string, and collector IPC ordering. Keep the inner sentinel override in `run_external_agent`, startup locks, magic exit-code handling, argv grammar, and `USER or "larch"` behavior untouched.

## Approach

- Introduce `LauncherPaths` as the single owner of stable output-rooted sidecar paths.
- Extract shared **primitives** (`_record_launch_timing`, existing `_promote_inner_done`) and a thin `_finalize_launch` **coordinator** that runs caller-supplied hooks in caller-owned order. Do **not** bake one global timing → meta → promote → failure → emit sequence into the helper.
- Document and test **per-family epilogue order** against current `python/agents.py` tails before migrating each launcher.
- Roll out `_finalize_launch` first to **CI** and **implement** families where tails are structurally similar. Leave **review** launchers on duplicated tails plus `LauncherPaths` until pre-promote hooks are spelled out; do not fold review-only steps into a CI-shaped epilogue in this PR.
- Keep implement stderr/failure IPC on explicit `sidecar_log` (`tmpdir/{tool}-impl.log`), never on `LauncherPaths.sidecar`.
- Replace open-coded `CODEX_HOME` / `CURSOR_CONFIG_DIR` save-restore with `_temporary_env` where the diff stays small.
- Keep `_review_record_timing` and `_record_implement_timing` as thin delegates to `_record_launch_timing`; do not remove those names in this PR.

### Per-family epilogue order (normative; callers must preserve)

**Codex CI** (`launch_codex_ci_main`, current ~3562–3594):

1. Post-run events/quota work (empty-events guard, `_mirror_codex_quota_from_events`).
2. `record-vendor-task` (timing).
3. Token record from events; emit `TOKEN_RECORD` before launcher-result KVs when file exists.
4. Append `.meta`.
5. On timeout: write `.stall.json` (always overwrite on timeout).
6. `_promote_inner_done`.
7. `_append_ci_failure`.
8. `_emit_ci_launcher_result`.

**Cursor CI** (`launch_cursor_ci_main`, current ~3683–3715):

1. Append `.meta` **before** timing.
2. `record-vendor-task`.
3. `_record_cursor_usage_from_output` (includes `record-vendor-sidecar`).
4. Emit `TOKEN_RECORD` when file exists.
5. On timeout: write `.stall.json` **only if** `not paths.stall_json.is_file()` (idempotent guard must stay Cursor-specific).
6. `_promote_inner_done`.
7. `_append_ci_failure`.
8. `_emit_ci_launcher_result`.

**Codex implement** (`launch_codex_implement_main`, current ~5114–5121):

1. Post-run events/quota work.
2. `_record_implement_timing`.
3. `_record_usage_from_events` (uses `sidecar_log`, not `paths.sidecar`).
4. Append `.meta`.
5. On nonzero exit: `_append_implement_launch_failure(..., sidecar_log, ...)` **before** promote.
6. `_promote_inner_done`.
7. `_emit_implement_launcher_envelope`.

**Cursor implement** (`launch_cursor_implement_main`, current ~5222–5228):

1. Append `.meta` **before** timing.
2. `_record_implement_timing`.
3. `_record_cursor_implement_usage`.
4. On nonzero exit: `_append_implement_launch_failure(..., sidecar_log, ...)` **before** promote.
5. `_promote_inner_done`.
6. `_emit_implement_launcher_envelope`.

**Review Codex / Cursor** (`_review_launch_codex`, `_review_launch_cursor`): **out of `_finalize_launch` scope for this PR.** Migrate path construction to `LauncherPaths` only. Keep existing relative order, including all pre-promote steps:

- Review Codex: failure append / sidecar ok line → outer meta → timing → token + `record-vendor-sidecar` → dirty-tree → promote → emit.
- Review Cursor: failure sink or append failure → outer meta → test-trap → postprocess (exit 0) → dirty-tree from baseline → timing → promote → emit. Failure sink for brainstorm must remain **before** `_promote_inner_done`.

`_finalize_launch` must not reorder review meta, dirty-tree, postprocess, token sidecar, or failure-sink writes relative to `.done`.

Design rules:

- Callers pass an ordered `hooks` list (or inline equivalent) that encodes the per-family table above.
- Do **not** hardcode timing/meta/promote/failure/emit order inside `_finalize_launch`.
- CI adopters pass hooks for timing, token stdout, meta, stall (family-specific callback), promote, failure append, emit.
- Implement adopters pass hooks with failure append **before** promote; failure callbacks close over `sidecar_log: Path`, not `paths.sidecar`.
- Cursor CI stall hook must preserve `not paths.stall_json.is_file()` guard; Codex CI stall hook keeps unconditional timeout write.
- Token stdout: callers responsible for emitting `TOKEN_RECORD` before launcher-result KVs; coordinator does not reorder stdout.

## Edge cases

- `run_external_agent` must not hardcode public `.done` while `RUN_EXTERNAL_AGENT_INNER_SENTINEL_SUFFIX` is set.
- `_promote_inner_done` must still rename `.inner.done` to `.done`.
- Review Cursor failure sink (`--stderr-sink`) must be written before `_promote_inner_done`.
- Review Cursor postprocess and dirty-tree writes must complete before `_promote_inner_done`.
- Cursor config dirs must be deleted even if launch or model parsing fails.
- Env vars must restore when the old value was unset and when set to empty string.
- Implement failure diagnostics must read `args.sidecar_log`, not `LauncherPaths(output).sidecar`.
- Token records must keep existing stdout position relative to launcher result lines per family.
- Cursor CI stall sidecar must not appear when file already exists on timeout; Codex CI behavior unchanged.

## Failure modes

- A wrong suffix silently breaks IPC.
- A changed stdout or sidecar write order breaks parsers and `collect_results` wait-on-`.done` contracts.
- Promoting `.done` before failure-diag, stderr-tail, postprocess, or failure-sink completion exposes incomplete artifacts.
- Routing implement failure through `paths.sidecar` drops real stderr from `{tool}-impl.log`.
- A shared stall step without Cursor's idempotent guard changes stall presence across tools.
- Removing `_review_record_timing` / `_record_implement_timing` breaks monkeypatched tests.
- Over-generalizing `_finalize_launch` hides launcher-specific failure handling.
