# [OOS] rebase-checkpoint-probe: auto-resolve trivial larch-log conflicts during early_rebase so orchestrator intervention is not needed

[OOS] rebase-checkpoint-probe: auto-resolve trivial larch-log conflicts during early_rebase so orchestrator intervention is not needed

## Context

Surfaced during `/implement` run 6F97279C-AE10-4AD9-B8A6-ABF45CDF3DA2 (sh-to-py C3b, issue #3681). After the implementation commit (4.r rebase checkpoint), `rebase-push.sh --keep-on-conflict` encountered conflicts in auto-generated run-log files and left them for the orchestrator to resolve manually.

## Root Cause

`rebase-checkpoint-probe.sh` uses `rebase-push.sh --keep-on-conflict`, which intentionally leaves all conflicts for the orchestrator. There is no pre-pass that auto-resolves trivial auto-generated files like `larch-logs/`.

During 4.r, `larch-logs/implement/run-1/manifest.json` conflicted across 4 consecutive rebase hops (each `--continue` re-conflicted the same file). Each hop required the orchestrator to:
1. Classify via `git-conflict-files.sh`
2. Apply `git checkout --ours` (take upstream main version)
3. `git-stage.sh` and re-continue

Since larch-log files are unconditionally auto-generated, the upstream (main) version is always correct and no semantic judgment is needed.

## Impact

- ~4 extra orchestrator loops burned on trivial auto-generated file conflicts
- Main Claude must correctly identify and resolve the same file repeatedly across multi-hop rebases
- Wasted ~2–3 extra minutes per impl run that has log-file overlap with main

## Suggested Fix

Add a trivial-file pre-pass inside `rebase-push.sh` (or `rebase-checkpoint-probe.sh`) before surfacing conflicts to the orchestrator:

1. After detecting conflicts (`git diff --name-only --diff-filter=U`), check each conflicting file against a trivial-file list:
   - `larch-logs/**` — always take upstream (main) version (`git checkout --ours`)
2. After auto-resolving trivial files, re-`git add` them and attempt `git rebase --continue` before returning exit 1.
3. Only surface the remaining (non-trivial) conflicts to the orchestrator.

This eliminates multi-hop noise for auto-generated files and reduces the per-conflict loop count from N to 1 for larch-log–only conflicts.

## Note

The second conflict set in this run (`.claude/rules/*.md`, `agent-lint.toml`, `python/stall_recovery.py`, etc.) was a legitimate content conflict requiring orchestrator judgment — Option A above would not auto-resolve those, and that behavior is correct.
