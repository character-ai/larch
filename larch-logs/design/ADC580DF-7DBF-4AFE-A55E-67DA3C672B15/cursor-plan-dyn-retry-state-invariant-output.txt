## Findings

### 1. [correctness] Parse-fail abort blocks rc 4 stdout-fallback (`skills/design/SKILL.md:1515-1517`)

The plan’s retry hygiene (`rm -f .design-publish-result.env` before each attempt) and driver contract (exit 4 with best-effort env write; stdout always carries `VALIDATE_*`) align with the existing rc 3 pattern at lines 1474-1476 and 1515. The plan does not update the parse-fail guard, which today aborts whenever `_publish_parse_ok` is false and `_publish_rc` is not 3.

After a successful `rm`, a defects-found run whose result-env write fails matches the harness case in `plan.txt` line 88 but still trips `exit 1` in the fence. That prevents the shared **Fix / Override / Cancel** loop and contradicts the non-fatal stdout-fallback note in `plan.txt` line 12.

**Suggested revision:** Extend the guard to `-ne 3` **and** `-ne 4` (or require populated `VALIDATE_STATUS` from `_publish_out` before aborting on rc 4). Pin the exemption in `scripts/test-design-structure.sh` alongside the planned rc-4 pins (~lines 93-94).

### 2. [correctness] Driver exit 4 is not visible to the orchestrator (`skills/design/SKILL.md:1459-1518`)

The plan correctly widens the unexpected-rc check to `{0,1,3,4}` and gates items 3-5 / Step 5d on the **latest** `_publish_rc` (plan lines 33-34, 42-46). The fenced capture stores `_publish_rc=$?` only inside the Bash subshell; the script does not print `_publish_out` or exit with the driver code, so the Bash tool typically returns **0** even when the driver returns **4**.

Orchestrator steps that say `_publish_rc == 4` therefore lack a mechanical binding unless the implementer infers rc 4 from `VALIDATE_STATUS=defects-found` after a separate Read of `.design-publish-result.env` — which the plan does not state. That weakens the anti-halt carve-out (“no items 3-5 while rc is 4”) if a prior `final-summary.md` exists.

**Suggested revision:** Add `exit "$_publish_rc"` at the end of the Step 5c fence for rc ∈ {0,1,3,4} on non-abort paths (matching how rc 2 still aborts the fence with `exit 1`), **or** explicitly define orchestrator binding: after parse, set `_publish_rc=4` when `VALIDATE_STATUS=defects-found` from the latest attempt’s file/stdout merge.
