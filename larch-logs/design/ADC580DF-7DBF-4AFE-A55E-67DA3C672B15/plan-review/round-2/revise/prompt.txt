### Approach
- **Fold (Step 5c).** `design-publish.sh` becomes the single mechanical tail: validate `composed-plan.md` (Tier 2 only via the existing `invoke-plan-validator.sh` -> `design-driver.sh` -> `validate-plan.sh` chain), redact to `composed-plan.redacted.md`, then run the unchanged publish tail. For plan.txt sites (Step 2b, Gate B, Step 3 `plan-review-loop`, discussion-round2), retain today's Fix / Override / Cancel semantics. For Step 5c, `design-publish.sh` exits 4 before any redaction/publish side effect; the outer Step 5c loop asks the shared prompt, then either retries normally after a user-approved fix, retries with `--skip-validate` on Override/Accept, or cancels while preserving `$DESIGN_TMPDIR`. Every retry replaces `_publish_out`, `_publish_rc`, and parsed result-env state before final summary, sentinel, footer, or cleanup decisions.

### Edge cases
- `composed-plan.md` present but empty -> exit 2 (precondition).
- `--skip-validate` with latent defects -> publishes anyway (operator accepted); redaction still runs.
- `redact-secrets.sh` returns nonzero -> exit 2; no publish/rename/marker.
- `redact-secrets.sh` yields an empty file -> exit 2 sanity guard (never publish an empty body).
- Validator infra failure (chain broke) -> exit 2 abort, kept distinct from `defects-found` (exit 4).
- Repeated Step 5c defects after a user-approved fix -> re-enters the same prompt-mediated rc4 path; no silent loop or artifact mutation.
- `run-params.json` from a legacy in-flight run still carrying `review_budget` -> ignored (no reader remains); no default needed.

### Failure modes
- **Exit-4 not threaded through every caller.** Adding exit 4 without updating the SKILL.md `{0,1,3}` guard makes a defects-found finalize abort as "unexpected rc". Signal: clean validation path fine, defect path aborts. Mitigation: widen the guard to `{0,1,3,4}`, route rc 4 before items 5-7, and pin it in `test-design-structure.sh`.
- **Stale retry state after Override/Fix.** If Step 5c reruns publish but keeps the original rc/output/result-env variables, final summary/sentinel/cleanup can reflect the failed attempt. Signal: rc4 path publishes on retry but still aborts or emits stale `VALIDATE_STATUS=defects-found`. Mitigation: require the retry loop to replace `_publish_out`, `_publish_rc`, and parsed result env before continuing.
- **Unvalidated publish.** If the folded internal validate is mis-wired or skipped, a hallucinated command could publish. Signal: published `larch:plan` contains a bad command. Mitigation: validation is unconditional (no `review_budget` gate); the `defects-found -> exit 4` case is harness-covered, and only user Override uses `--skip-validate`.
- **Raw shell exit from validator/redactor.** `set -e` or pipeline failures could bypass the documented exit contract. Signal: defects or redaction errors exit with arbitrary rc/no result env. Mitigation: `set +e` capture for validator and explicit `if ! ...; then fail` around redaction, both harness-covered.

Round II of /design refactor, Phase 3: fold validate+redact into publish (5c)

**Context.** Part of Round II of the `/design` refactor (rationale in Phase 1).

**Problem.** Step 5c runs three sequential Bash turns with no LLM judgment between them on the happy path: composed-plan validation (`invoke-plan-validator.sh`, `SKILL.md:1446-1466`), redaction (`redact-secrets.sh`, item 3 near line 1470), then publish (`design-publish.sh`, `SKILL.md:1476-1536`). `design-publish.md` already *requires* `composed-plan.redacted.md` as a precondition, so validate+redact are mandatory pre-steps. **Why.** ~2 turns saved on every finalize; large per-turn byte reduction; the validate/redact glue becomes lintable `.sh` and Python-portable.

**Scope / acceptance.** `design-publish.{sh,md}` updated (now owns validate+redact, keeps the defects-found hand-back); SKILL.md Step 5c items 2-4 thinned; `test-design-publish.sh` + `test-design-structure.sh` updated; the foreground-required invariant preserved; harnesses + `make lint` green.
