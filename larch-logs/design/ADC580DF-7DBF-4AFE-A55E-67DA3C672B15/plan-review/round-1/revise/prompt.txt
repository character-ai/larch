### Approach
- **Fold (Step 5c).** `design-publish.sh` becomes the single mechanical tail: validate `composed-plan.md` (Tier 2 only via the existing `invoke-plan-validator.sh` -> `design-driver.sh` -> `validate-plan.sh` chain), redact to `composed-plan.redacted.md`, then run the unchanged publish tail. The orchestrator only composes `composed-plan.md` then calls the driver once. The one hand-back is `exit 4` (`VALIDATE_STATUS=defects-found`), which routes to the shared handler.
- **Unconditional validation.** `review_budget` is always `full` today (both SIMPLE and HARD), so its `quick` branch and `--force-validate` are dead. Remove the field end-to-end and delete the skip branch in `design-postplan-emit.sh` so the validator always runs. `design_classification` (SIMPLE/HARD) is untouched.
- **Self-healing handler.** On `defects-found`, read `VALIDATE_LOG_FILE`, diagnose the root cause (offending command, flag, defect kind), and auto-fix the offending artifact: `plan.txt` for Step 2b / Gate B / discussion-round2, `composed-plan.md` for Step 5c. Re-validate by re-running the surfacing driver (`design-postplan-emit.sh` for plan.txt sites; `design-publish.sh` for Step 5c, which self-gates and only publishes when validation passes). Cap auto-repair at 2 attempts. On success, continue the surrounding path and log a `Warnings` note of the fix — no prompt. If still failing after 2 attempts, or the agent judges the defect a likely false positive it should not silently accept, fire `AskUserQuestion` that explains the root cause and offers context-specific options: apply the proposed fix, accept (false positive / proceed anyway), edit myself, or cancel. **Accept** at Step 5c re-invokes `design-publish.sh --skip-validate` (+ Warnings); **Accept** at plan.txt sites logs Warnings and continues (defects-found is non-blocking there, as today's Override). **Cancel** keeps today's semantics.

### Edge cases
- `composed-plan.md` present but empty -> exit 2 (precondition).
- `--skip-validate` with latent defects -> publishes anyway (operator accepted); redaction still runs.
- `redact-secrets.sh` yields an empty file -> exit 2 sanity guard (never publish an empty body).
- Validator infra failure (chain broke) -> exit 2 abort, kept distinct from `defects-found` (exit 4).
- Auto-repair introduces a new defect -> caught on re-validate; the 2-attempt cap stops loops.
- `run-params.json` from a legacy in-flight run still carrying `review_budget` -> ignored (no reader remains); no default needed.

### Failure modes
- **Exit-4 not threaded through every caller.** Adding exit 4 without updating the SKILL.md `{0,1,3}` guard makes a defects-found finalize abort as "unexpected rc". Signal: clean validation path fine, defect path aborts. Mitigation: widen the guard to `{0,1,3,4}` and pin it in `test-design-structure.sh`.
- **Unvalidated publish.** If the folded internal validate is mis-wired or skipped, a hallucinated command could publish. Signal: published `larch:plan` contains a bad command. Mitigation: validation is unconditional (no `review_budget` gate); the `defects-found -> exit 4` case is harness-covered.
- **Auto-repair runaway or destructive edit.** Signal: repeated re-validate with no convergence, or lost plan content. Mitigation: 2-attempt cap, escalate to the user, and edit only the offending command line.
