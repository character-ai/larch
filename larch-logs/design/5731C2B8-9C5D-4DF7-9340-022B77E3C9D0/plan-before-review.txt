## Approach

Replace Step 8 prompt-side assessment authorship with the existing blocking `step-8-assessment.sh` adapter.

The main agent will invoke one foreground fence through the implement-run launcher. The adapter owns bgjob start, repeated `python/cli.py bgjob wait --max-wait-s 270` calls, terminal validation, retry, persistence, deterministic filtering, and timeout-to-unavailable behavior. If the Bash tool times out, the main agent will repeat the identical adapter fence so it rejoins live work.

After the adapter returns, require:

- `BGJOB_RC=0`
- `STEP=implement-step8-assessment`
- a non-empty `ASSESSMENT_COVERED_FINGERPRINT`
- `ASSESSMENT_REQUESTED_KINDS` matching the routed request
- `ASSESSMENT_STATUS=complete`
- complete result coverage for the requested kinds

Reject missing, malformed, stale, mismatched, or fail-closed results. Relaunch `step-8-ship.sh` exactly once only after all requested results persist and validate.

Keep `invariants-assessment` and `guidelines-assessment` as dormant compatibility aliases. Each alias will normalize its handoff into the same combined adapter contract. Do not restore per-kind writers or inline fallback.

Preserve the Piece 1 through Piece 3 implementation. Do not change `step-8-assessment.sh`, `step-8-assessment.md`, Python assessment drivers, route tokens, result states, kind tokens, or the deterministic pre-filter.

## Edge cases

- The routed kind list contains one kind, both kinds, reordered kinds, duplicates, empty tokens, or unknown tokens.
- The compatibility route arrives with a legacy reason while the adapter requires the combined `NEXT_ACTION=assessments` handoff shape.
- The Bash tool times out while the adapter’s bgjob remains live. Repeating the same fence must rejoin rather than start duplicate work.
- The adapter returns success text but its result env is absent, incomplete, stale, or for different kinds.
- The result fingerprint does not match the request identity.
- An assessment times out and persists a validated unavailable outcome.
- A docs-only change reuses valid coverage without another model call.
- A later code change enters a previously untouched architectural scope and triggers the existing scoped reassessment.
- An invariant violation persists and must block ship despite the new delegation route.
- Both assessment kinds complete, but only one result is present. Do not relaunch ship.
- Assessment succeeds, but the ship relaunch fails. Do not rerun assessment unless existing identity and scope rules require it.

## Failure modes

- Prompt prose accidentally keeps an inline authorship escape hatch.
- The main agent uses an explicit bgjob wait fence even though the adapter owns the wait loop.
- A Bash-tool timeout starts a second assessment instead of rejoining.
- Validation trusts `DONE` or process exit alone without checking result identity and completeness.
- A stale result causes ship to continue against a different diff.
- The combined route relaunches ship once per kind instead of once after all results persist.
- A legacy alias bypasses the adapter or reaches an unsupported adapter handoff.
- Reference docs disagree with SKILL.md about route ownership.
- Security prose exposes raw assessor diagnostics or implies trusted model output.
- Fence-shape expectations drift from the changed SKILL.md Bash blocks.
