Five important out-of-scope observations surfaced during code review of the /implement run for issue #6375 (implement guideline-note drop tracking). None were accepted for inline fixing; all require design attention.

## Finding 1: ship outcome classifier infers guidelines_status from note emptiness

`_classify_ship_outcome` guesses `guidelines_status` from whether the note is empty when compose metadata is absent. A present-guidelines terminal result where the note string is empty (e.g. redaction returned an empty string) gets classified as `guidelines_status=absent` or `guidelines_status=clean` instead of `dropped`. This undercounts the drop rate in committed artifacts and in the audit scan.

**Affected files**: `python/larch/implement/ship_guidelines.py` (`_classify_ship_outcome` / `GuidelinesShipOutcome` construction)

**Fix**: thread `guidelines_status` from `prepare_compose_assessment` / `read_guidelines` into the outcome dataclass and classify using that field, not by checking whether the note string is non-empty. The plan already states this: "always sourced from materialized compose metadata."

## Finding 2: implement_step8_reachable does not thread PR bail evidence

`implement_step8_reachable` (extracted from `_scan_required`) does not thread PR-level bail evidence through the reachability check. Edge cases where a run bailed before Step 8 but after creating the PR can report step8 as informational-unreachable even though artifact absence should fail. Both the audit scan and fluff-analysis use this helper.

**Affected files**: `python/larch/issue/audit_runs.py` (`implement_step8_reachable`)

**Fix**: thread the bail-signal and PR evidence through the helper so stale bail-before-Step-8 runs correctly resolve as step8-ineligible rather than informational.

## Finding 3 (Round 2): ship outcome classification fails open on missing metadata

Same surface as Finding 1, confirmed in a second review round. `_classify_ship_outcome` infers `guidelines_status` from note emptiness when compose metadata is missing, misclassifying present-guideline drop paths as clean or absent. Drop rate in committed run logs is systematically undercounted.

**Affected files**: `python/larch/implement/ship_guidelines.py`

**Fix**: same as Finding 1 — use materialized metadata fields, not note emptiness.

## Finding 4: empty git HEAD serialized as clean outcome with blank head_sha

An empty `git rev-parse HEAD` output (detached HEAD with no commits, or a failure path) can produce `head_sha=""` in the committed `architectural-guideline-outcome.json`. The audit scan validates `head_sha` presence but not emptiness. A blank `head_sha` leaves the committed artifact unverifiable for audit linkage.

**Affected files**: `python/larch/implement/ship_guidelines.py` (sidecar write path), `python/larch/issue/audit_runs.py` (`_guideline_ship_outcome_scan_obj`)

**Fix**: treat `head_sha=""` as a validation failure in both the sidecar writer (stall before PR creation in normal mode) and the audit scan handler.

## Finding 5: broken symlink committed artifact bypasses gc-slimmed exemption

A committed symlink artifact at the `architectural-guideline-outcome.json` path passes the `path.exists()` check (symlink exists) but fails `path.is_file()`. The gc-slimmed exemption only checks for artifact absence (not-exists), so a committed symlink is treated as informational instead of failing. This weakens audit rejection.

**Affected files**: `python/larch/issue/audit_runs.py` (`_guideline_ship_outcome_scan_obj`)

**Fix**: check `not path.is_file() or path.is_symlink()` instead of absence-only for the fail path. The gc-slimmed exemption should cover only truly absent artifacts, not broken or symlinked ones.

## Proposed Design Outline

### Goals
- Fix `_classify_ship_outcome` so `guidelines_status` comes from materialized metadata, not note-emptiness inference (Findings 1 & 3).
- Add `pr: int = 0` to `implement_step8_reachable` and thread it to `_manifest_bail_signal` so bail-with-PR evidence resolves correctly (Finding 2).
- Guard `write_guideline_ship_outcome` against empty `head_sha` and validate `head_sha` non-emptiness in `validate_guideline_ship_outcome_record` (Finding 4).
- Fix gc-slimmed exemption to reject broken or regular symlinks, not only truly absent artifacts (Finding 5).

### Non-goals
- No changes to other audit scan handlers or ship-pr orchestration beyond the targeted surfaces.
- No migration or back-fill of existing committed run-log artifacts.
- No changes to forked-target paths beyond what the `head_sha` guard naturally covers.

### Approach sketch
- `_classify_ship_outcome`: remove the note-emptiness fallback; when `guidelines_status` is not in `{"present","absent","invalid"}`, treat it as `"absent"` directly rather than inferring from `result.note`.
- `write_guideline_ship_outcome`: add an early return when `head_sha` is empty, logging a warning via `_log_guidelines_ship_warning`.
- `implement_step8_reachable`: add `pr: int = 0` parameter; forward it to all `_manifest_bail_signal` calls inside the function.
- `_guideline_ship_outcome_scan_obj`: pass `pr` to `implement_step8_reachable`; tighten the gc-slimmed exemption to use `not path.exists() and not path.is_symlink()` (artifact truly absent).
- `validate_guideline_ship_outcome_record`: add a `not head_sha` check alongside the existing `base_ref` check.
