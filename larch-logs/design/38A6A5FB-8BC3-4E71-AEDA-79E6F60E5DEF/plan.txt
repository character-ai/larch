## Plan

Implement the smallest fail-closed path:

1. Add `panel-init-failed` as the zero-reviewer status.
2. Materialize and validate `plan-review-scope-anchor.txt` before Step 3 launches via a registered CLI verb, with secrets redaction per `SECURITY.md`.
3. Normalize any pre-dispatch zero-round `panel-failed` shape to `panel-init-failed` in **`design-step3-review.sh`** (authoritative shell path), including `monitor-mode-unavailable` and legacy loop output.
4. Update embedded legacy loop assets so entry-time redacted anchors are never overwritten or duplicated.
5. Stop `/design` before Gate C and Step 5 when zero reviewers ran, with full terminal handoff (`design-stage-terminal-state.sh`, `SUMMARY_OUTCOME=failed-panel-init`, Final summary).
6. Add `review_status:` and `rounds_completed:` to new `larch:plan` blocks.
7. Refuse `/implement` only when explicit plan provenance says review was skipped or zero rounds ran.
8. Parse provenance from the leading header only, never from plan body prose.
9. Keep legacy plans without provenance valid, per the non-goal.

## Approach

- **Scope anchor**: binding anchor is issue narrative (`larch:plan` stripped) plus approved outline only. Brainstorm stays on the existing optional `plan-review-feature-context.txt` path and is never read by the materialization helper. Composed anchor text is piped through `python/cli.py redact secrets` before write.
- **CLI surface**: shell entry scripts call `python/cli.py plan-review materialize-scope-anchor` only; no ad-hoc `python -c` imports.
- **Zero-round failures**: any Step 3 path that exits before `plan-review/round-1/` exists emits `panel-init-failed`, not Gate-B-bypass `panel-failed`. Terminal contract mirrors `postplan-failed`: stage terminal state, print `SUMMARY_OUTCOME=failed-panel-init`, exit non-zero; orchestrator runs Final summary.
- **Shared terminal helper**: extract `_step3_review_terminal_panel_init_failed` in `design-step3-review.sh` as the single owner of zero-round terminal handoff (normalize KVs when needed, invoke `design-stage-terminal-state.sh` with required `--exit-code`, print `SUMMARY_OUTCOME=failed-panel-init`, `exit 1`). Call it from `_step3_review_write_prelaunch_failure`, the missing-anchor prelaunch guard, and the post-loop normalization path. Prelaunch failures must not return bare `panel-init-failed` KVs without staging and `SUMMARY_OUTCOME`.
- **Terminal staging contract**: every `design-stage-terminal-state.sh` invocation from `_step3_review_terminal_panel_init_failed` (and the Step 3 entry-time failure path) must pass `--exit-code 1` (or the real wrapper rc) plus `--summary-outcome failed-panel-init`, mirroring `stage_design_terminal_state` in `design-publish.sh`. Empty `--exit-code` causes `STAGED=false`, stall-recovery validation failure, and `compose-status-missing` reporter fallback.
- **Normalization ownership**: do **not** rely on `plan_review.py` `run_main` for zero-round rewrite. `run_main` delegates to `run_step3_review` → embedded `run-step3-review.sh` and does not parse `--mode loop`. Add `_step3_review_normalize_zero_round_status` in `design-step3-review.sh` as the authoritative zero-round rewrite (not `run_main`).
- **Normalization ground truth**: treat `$DESIGN_TMPDIR/plan-review/round-1/` directory presence as the sole disk predicate for zero-round classification. Rewrite `panel-failed` → `panel-init-failed` only when `round-1/` is absent. Do **not** key normalization on `REVIEW_ROUND_COUNT=0` or `ROUNDS_COMPLETED=0` alone when `round-1/` exists (stale counters must not terminalize a degraded but real review run).
- **Normalization ordering (Bug 3 fix)**: in `design-step3-review.sh`, enforce this sequence after result-env load and stdout KV hydration, **before** empty/invalid status coercion to `panel-failed` (today ~473–506), stdout KV emit (~507–525), and escalation evidence (~526–533):
  1. Load `.step3-review-result.env` / stdout fallback into shell variables.
  2. Call `_step3_review_normalize_zero_round_status` (uses `round-1/` absence; may rewrite `panel-failed`, missing, or invalid statuses when no round launched).
  3. When normalization yields `panel-init-failed`, call `_step3_review_terminal_panel_init_failed` and `exit 1` immediately.
  4. Only then run `LOOP_STATUS` → `STEP3_REVIEW_LOOP_STATUS` derivation for still-empty values, with coercion branches updated so missing/invalid status + absent `round-1/` coerces to `panel-init-failed` (not `panel-failed`).
  5. Run allowlist validation, stdout KV emit, and `panel-failed` escalation evidence only for true degraded `panel-failed` where `round-1/` exists.
- **Terminal handoff ordering**: `_step3_review_terminal_panel_init_failed` runs **before** the `panel-failed` escalation-evidence `case` block (today ~526–533). `panel-init-failed` must never record degraded `panel-failed` escalation or exit `0`.
- **Embedded loop contract**: regenerate `_LEGACY_ASSETS` blobs for `plan-review-loop.sh` and `review-design-step3-loop.sh`. When `$DESIGN_TMPDIR/plan-review-scope-anchor.txt` exists and is a non-empty regular file, skip in-loop strip/compose/append; never overwrite entry-time redacted anchor. If recreation is required (file absent), call `python/cli.py plan-review materialize-scope-anchor` instead of duplicating strip logic.
- **Entry-time failures**: when `materialize-scope-anchor` fails in `design-step3-entry-state.sh`, orchestrator stages terminal state (with `--exit-code 1`) and runs Final summary without launching `design-step3-review.sh`.
- **Drafter metadata grammar**: the default Step 2b path launches `design-step2b-drafter.sh`; boolean-only `mechanical_churn:` rules must live in the drafter prompt and contract, not only `SKILL.md` inline fallback. Numeric churn belongs in `diff_lines:`, `diff_added:`, or `diff_deleted:`.
- **Feature description guard**: `design-step0-init.sh` writes `feature-description.txt` on proceed and already-planned replace; `design-step0c.sh` fail-closes when the file is absent or empty before Step 1c so resume and missed-init paths cannot reach Step 2b/3 silently.
- **Provenance**: Step 5c prepends a two-line header; publish and `/implement` Preflight share one Python parser that reads only lines before the first blank line.
- **Publish fail-closed**: Step 5c refuses when review env says zero rounds **or** when `plan-review/round-1/` is absent, unless `review_status` is an explicitly allowed degraded path **and** round artifacts exist on disk. Do not trust `ROUNDS_COMPLETED` / `REVIEW_ROUND_COUNT` alone (covers #4168 stale-env case).
- **Gate C degraded acknowledgment**: when review env shows degraded `panel-failed` and `plan-review/round-1/` exists, `--skip-approve` must **not** auto-approve Gate C. Force the normal Gate C prompt with the mandatory degraded-review warning so partial-review runs cannot silently reach Step 5c.
- **Stall-recovery tokens**: extend `stall-recovery-report.sh` allowlists so `failed-panel-init` / `panel-init-failed` / bail tokens validate before `design-stage-terminal-state.sh` writes.
- **Already-planned replace**: Step 0b writes a durable replace sentinel and runs init before Step 0c so `feature-description.txt` exists on that path.

## Edge cases

- **Legacy designed issues**: no `review_status:` header means `/implement` continues to allow the plan.
- **Cap hit after real rounds**: `review_status: cap-hit` with `rounds_completed>0` and `round-1/` present is allowed.
- **Cap hit with zero rounds**: fail closed because no reviewers ran (`round-1/` absent).
- **Stale env #4168**: `ROUNDS_COMPLETED=1` without `plan-review/round-1/` still blocks Step 5c publish.
- **Stale counters with real rounds**: `REVIEW_ROUND_COUNT=0` or `ROUNDS_COMPLETED=0` with `round-1/` present must **not** normalize to `panel-init-failed`.
- **Malformed prior plan block in issue body**: Step 3 entry fails before background launch with terminal `failed-panel-init`.
- **Placeholder plan-only issue body**: stripped scope can be empty; fail early with a clear diagnostic.
- **Numeric mechanical churn**: accept numeric input for resilience in `plan_quality.py`, but drafter prompt must still forbid numeric `mechanical_churn:`; canonical output remains boolean.
- **Stale log worktree**: clean only script-owned or missing worktrees; do not remove arbitrary user worktrees.
- **Provenance false positives**: plan body examples mentioning `rounds_completed: 0` must not block `/implement`.
- **Monitor mode unavailable**: zero-round prelaunch failure calls `_step3_review_terminal_panel_init_failed` with `--exit-code 1`, exits `1`, emits `SUMMARY_OUTCOME=failed-panel-init`, not Gate B bypass.
- **Legacy loop overwrite**: entry-time redacted anchor must survive loop start when file already valid.
- **Already-planned replace**: init and `feature-description.txt` run before Step 0c via `.already-planned-replace`; Step 0c still fail-closes if the file is missing on resume.
- **Stall-recovery token validation**: terminal staging for `failed-panel-init` must pass `validate-token` with `EXIT_CODE=1` before `design-failure-terminal-state.env` is written.
- **Scope-anchor secrets**: redaction failure blocks anchor write and triggers entry-time terminal path.
- **Normalization ordering**: zero-round rewrite must complete before `panel-failed` coercion, stdout emit, and escalation evidence; terminal helper must run for prelaunch and post-loop paths alike.
- **Gate C skip-approve + degraded panel-failed**: even with `--skip-approve`, operator must see mandatory degraded-review warning when `round-1/` exists.

## Failure modes

- If scope-anchor creation fails, `/design` exits before Step 3 review launch, stages terminal state with `--exit-code 1`, runs Final summary, and preserves tmpdir.
- If the loop fails before dispatch and returns a legacy `panel-failed` with absent `round-1/`, `design-step3-review.sh` normalization rewrites to `panel-init-failed` and `_step3_review_terminal_panel_init_failed` runs before any degraded escalation path.
- If normalization runs after `panel-failed` coercion, init failures stay on the Gate B bypass path and Bug 3 recurs.
- If normalization keys on stale counters instead of `round-1/`, a degraded but real review run can be terminalized incorrectly.
- If `_step3_review_terminal_panel_init_failed` omits `--exit-code`, staging emits `STAGED=false`, tokens fail validation, and `design-failure-report.sh` falls back to `compose-status-missing`.
- If process-group isolation is unavailable, Step 3 never launches reviewers; `_step3_review_terminal_panel_init_failed` returns full terminal contract (exit `1`, `SUMMARY_OUTCOME=failed-panel-init`).
- If prelaunch paths emit `panel-init-failed` without the shared terminal helper, orchestrator may miss Final summary and hard-stop routing (regression guarded by harness).
- If embedded loop regen is missed, loop may still overwrite or duplicate anchors; legacy blob regen is required in the same change.
- If stall-recovery allowlists are stale, `design-stage-terminal-state.sh` validation fails and failure reporter may fall back to `compose-status-missing`; allowlist updates are required for reliable auto-reporting.
- If Step 5c trusts env counters without `round-1/` check, stale `ROUNDS_COMPLETED` can still publish; round-artifact guard closes this hole.
- If `/design` proceeds past Step 0 without `feature-description.txt`, Step 0c fail-closed guard blocks silent Step 2b/3 input loss.
- If drafter prompt omits boolean-only `mechanical_churn:` rule, Codex may keep emitting numeric trailers despite validator tolerance.
- If `/implement` sees explicit skipped or zero-round provenance in the header, it exits preflight `2`.
- If `--skip-approve` auto-approves Gate C after degraded `panel-failed`, operator may approve a partially reviewed plan without acknowledgment.
- If stale worktree cleanup is unsafe, log publish keeps the existing recovery-branch failure path.
