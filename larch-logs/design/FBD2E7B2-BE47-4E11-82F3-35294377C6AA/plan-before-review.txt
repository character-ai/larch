# Lint-fix waterfall hardening

## Approach

- Treat the shared Piece 1 contracts as prerequisites. Use `config.FIXER_LANE_TIMEOUT_SEC`, `external_defaults.fixer_lane_budget_sec("implement.lint_fix_coder")`, and `external_defaults.next_untried_tier()` instead of local timeout and tier-loop constants.
- Track attempted tiers explicitly. Give each selected tier its full lane timeout while enforcing a total budget large enough for the complete configured waterfall.
- Inspect repository state after every dispatched tier, including non-zero and timeout exits. Continue to the next tier only when that attempt produced no useful delta.
- When an attempt produces useful edits, stop dispatching and return the edits to the existing checks loop. Let that loop rerun checks before deciding whether another repair iteration is needed.
- Apply existing forbidden-path, branch, HEAD, and redaction guards before accepting a tier's edits. Structural or integrity failures remain terminal and fail-closed.
- Record one bounded ledger row per attempted tier. Include the tier, outcome class, exit status, elapsed time, and whether it produced a useful delta. Preserve available tool logs and append execution-issue records for timeout, authentication, missing-binary, launcher, and similar anomalous failures.
- Remove exhaustion and stale-no-change promotion to `NEXT_ACTION=main-agent-edit`. Keep that action only for explicit `main-agent-required` structural cases. Route completed waterfall exhaustion to `NEXT_ACTION=stall`.
- Do not change Step 8 CI orchestration, waterfall membership, or tier order.

## Edge cases

- Some configured tools may be absent. Do not mark an unavailable tier as attempted, but terminate as exhausted or unavailable when no selectable tier remains.
- A launcher may time out or fail after editing files. Inspect and validate the delta before deciding to advance.
- A tier may create only forbidden or structurally unsafe edits. Revert or reject them through the existing guard and stop fail-closed.
- A tier may commit, modify tracked files, add untracked files, or combine these forms. Detect all supported delta shapes.
- Pre-existing dirty paths must not count as a tier's useful delta.
- A successful tier may make no changes. Record the no-op and continue without rerunning checks.
- The total budget must not cut off the final configured tier before it receives its full timeout.
- Redacted log validation failures must never enter another tier or leak raw check output into ledgers or execution issues.

## Failure modes

- If tier-selection state is invalid, fail loudly rather than silently restarting or skipping a tier.
- If repository state cannot be captured or verified after dispatch, return a structural failure and do not accept the edits.
- If per-tier evidence cannot be written, record the failure through the existing execution-issue path where possible. Do not convert an unsafe result into success.
- If all tiers are unavailable or attempted without useful edits, emit the explicit exhausted or stalled state. Never fall through to `NEXT_ACTION=main-agent-edit`.
- Preserve existing argument-validation and callback `OSError` stall envelopes.
