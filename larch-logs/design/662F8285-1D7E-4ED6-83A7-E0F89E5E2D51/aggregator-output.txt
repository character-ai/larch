### FINDING_1: `set -e`-unsafe post-wrapper `jq -e` can abort the Step 2 dispatcher
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation
- **Severity**: important
- **Concern**: The planned refactor of `normalize_coder_scout_manifest` in `step2-implement.sh` (lines 488–552) adds post-wrapper output-shape validation with bare `jq -e`. The script runs under `set -euo pipefail`, so a standalone failing `jq -e` can terminate the dispatcher before `normalize_coder_scout_manifest` returns non-zero and before `materialize_external_coder_scout` writes the canonical empty manifest and emits `SCOUT_CODER_STATUS=missing-or-invalid`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Wrap validation as `if ! jq -e '.archetypes | type == "array"' "$output"; then return 1; fi` (or equivalent) and keep all normalize failure exits as `return 1` only
  - From Cursor-Innovation: Wire validation like `launch-codex-drafter.sh`: gate on `SCOUT_STATUS` first, then use `if ! jq -e '.archetypes | type == "array"' "$output" >/dev/null 2>&1; then return 1; fi` (or fold jq into the same if test chain)

### FINDING_2: Shape-only `jq` acceptance can treat `SCOUT_STATUS=parse-failed` as success
- **Reviewer(s)**: Cursor-Innovation
- **Severity**: important
- **Concern**: `scout-plan-archetypes-wrapper.sh --filter-manifest` writes `{"archetypes":[]}` and emits `SCOUT_STATUS=parse-failed` for invalid JSON or non-array input. If `normalize_coder_scout_manifest` checks only output shape with `jq -e` and ignores wrapper status, corrupt sidecars would be accepted as normalized success instead of falling through to `SCOUT_CODER_STATUS=missing-or-invalid`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: Reject `parse-failed`, `missing`, `empty`, and `unknown` `SCOUT_STATUS` before any success-path jq check; only `SCOUT_STATUS=ok` or `empty` may return zero
