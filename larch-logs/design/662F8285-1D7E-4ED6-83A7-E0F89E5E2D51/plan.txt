## Edge cases

- **Wrapper parse failure**: keep `SCOUT_CODER_STATUS=missing-or-invalid` and write `{"archetypes":[]}`.
- **All rows filtered**: keep `SCOUT_CODER_STATUS=ok` because the sidecar was parseable and normalized to an empty archetype list.
- **Wrapper missing or non-executable**: capture safely, detect missing or invalid `SCOUT_STATUS`, return non-zero, and use the existing empty-manifest fallback.
- **Missing or unexpected status**: treat as normalization failure.
- **Malformed output after non-parse-failed status**: treat as normalization failure.
- **Same input and output path**: rely on wrapper atomic temp output before final move.
- **Dispatcher stdout**: prevent wrapper `WARN`, `SCOUT_STATUS`, `SCOUT_MANIFEST`, and `SCOUT_ARCHETYPE_COUNT` lines from joining the Step 2 dispatcher envelope.

## Failure modes

- If the wrapper path is missing or exits unexpectedly, normalization should fail closed to the existing empty-manifest fallback.
- If the wrapper emits `SCOUT_STATUS=parse-failed`, normalization should fail closed.
- If the wrapper emits `SCOUT_STATUS=ok` or `SCOUT_STATUS=empty`, normalization should still validate that `$output` is readable JSON with `.archetypes` as an array.
- If the wrapper emits no `SCOUT_STATUS` or an unknown status, normalization should fail closed.
- Do not accept output based on a loose “clearly valid” heuristic.
