## Approach

- Keep the top-level publish gate as a denylist; do not rewrite to an allowlist.
- Exclusion-only: add deny patterns and fix one dead round-N pattern; never add a file to the publish set. Flushed design-log bytes strictly decrease.
- Anchor every deny arm on a real producer (`launch-review.sh`, `launch-claude-subprocess.sh`, `dispatch-with-waterfall.sh`, `collect-agent-results.sh`); omit suffixes no producer emits.
- Distinguish manifest slot names (`codex-plan-*`, `dyn-codex-plan-*`, …) from output basenames (`codex-primary-plan-*-output.txt`); collector failure logs follow slot names.
- Use `*-output*.txt` so phased waterfall outputs like `-output-phase2.txt` remain covered.
- Keep implementation, tests, sibling docs, and `SECURITY.md` in sync.

## Edge cases

- Phased fallback transcripts are excluded by `*-output*.txt`.
- `claude-plan-assessor-round-N.txt` does not match `claude-plan-*-output*.txt` and remains out of scope.
- Vote outputs are not touched.
- Cursor `.json` sidecars are excluded; codex `.json` is intentionally not added (no producer).
- Cursor/Codex `.stderr` and `.stderr-tail` are intentionally NOT excluded: no producer emits them (only the Claude subprocess writes `${OUTPUT}.stderr` / `.stderr-tail`). Excluding them would be new dead patterns.
- Existing committed run logs are forensic records and must not be edited.
- Collector failure logs use slot slugs (`codex-plan-arch-collector.failure.log`), not output basenames (`codex-primary-plan-arch-output.txt`); do not deny `codex-primary-plan-*-collector.failure.log` (no producer).
- `plan-review-collector.stderr` can contain failed-agent stderr tails and launcher diagnostics.
- Dropped-slot diagnostics and collector failure logs can contain transcript/stderr snippets, so they are excluded even though they are not transcript files themselves.

## Failure modes

- Over-broad glob excludes canonical artifacts. Mitigation: patterns are anchored to plan-review transcript/diagnostic names; tests keep canonical artifacts (`findings.md`, `voting-tally.md`, etc.) published.
- Flushed bytes increase. Mitigation: the change is exclusion-only — it only adds deny patterns and removes a dead pattern, so it cannot add a file to the publish set; deny assertions prove the targeted files are absent while canonical-present assertions prove nothing canonical was lost.
- Missed sidecar or aggregate stderr leaves raw output publishable. Mitigation: tests cover every new deny arm, including Claude `.meta`/`.stderr`/`.stderr-tail`, slot-derived collector failures, `plan-review-collector.stderr`, dropped slots, and generic prompt.
- Dead pattern reintroduced. Mitigation: every deny arm is verified against a real producer; Cursor/Codex `.stderr`/`.stderr-tail` are deliberately omitted because no producer emits them. Fixtures use real names only.
- Documentation drift. Mitigation: update `.sh`, sibling `.md`, tests, and `SECURITY.md` in the same change.
