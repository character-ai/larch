## Findings

1. **correctness** (`skills/design/scripts/design-clarify.sh:167-206`): The thin wrapper must not run `design pause-save` before the same `--phase` / `--issue` validation the current script performs. Otherwise pause can run with bad argv and error semantics change.

2. **correctness** (`python/clarify.py:37-49`): `--claude-pid` must feed trusted session-env loading. Without it, symlinked `source-env.sh` can load as empty and break `DESIGN_TMPDIR` / `REPO` resolution on the normal launcher path.

3. **risk-integration** (`python/clarify.py:26-33`): **[SCOPE-REDUCTION]** Reuse `design_lifecycle.py` helpers instead of reimplementing env parsing, result-env reads, pause exit, and failure append/staging. That keeps the port smaller and aligned with existing tests.

4. **risk-integration** (`python/clarify.py:26-33`): Result env writes need the bash driver's atomic, symlink-safe contract. In-place writes risk partial env files on crash.

5. **correctness** (`python/clarify.py:74-102`): Publish route-state failures must stay non-terminal. Only fetch failures should call `design-stage-terminal-state.sh`.

6. **correctness** (`python/clarify.py:74-90`): Add `REQUEST_ID` positive-integer validation on publish before `clarify_comment_post`.

7. **correctness** (`python/clarify.py:90-94`): Keep the `SESSION_ID missing` warning on publish skip for harness and operator parity.
