## Findings

**1. [risk-integration] Empty `SESSION_ID` warning dropped from contract** (`skills/design/scripts/test-design-clarify.sh:198`, proposed `python/test_clarify.py`)

The live harness asserts publish stdout includes `SESSION_ID missing`. Bash emits a visible skip warning. The plan migrates publish tests to Python but never carries that warning forward, and the revised shell harness no longer covers publish behavior.

**Suggested revision:** Add the warning string to the Python publish spec and tests before removing the shell assertion.

**2. [correctness] Session env merge order unspecified** (proposed `python/clarify.py`, plan lines 56–63)

Wrapper sourcing plus trusted `_load_source_env` interact. Without merging allowlisted `os.environ` values before session-file overrides, the driver can reject a valid tmpdir on the symlink-without-`--claude-pid` path the plan itself tests.

**Suggested revision:** Document and implement `_base_env` + `_load_source_env` merge, then `_require_design_tmpdir`.

**3. [correctness] `-read-failed` fetch tokens lack a direct-call mapping** (proposed `python/clarify.py` fetch section, proposed `python/test_clarify.py`)

Eliminating subprocess stdout parsing removes the only Bash paths that produced `state-read-failed` and `fetch-read-failed`, yet tests still require all six failure tokens.

**Suggested revision:** Define explicit emission rules per token, or shrink the contract and tests if those tokens are retired.

**4. [architecture] Publish request-state read not bound to safe helper** (proposed `python/clarify.py` publish section)

Request-state loading needs the same allowlist and symlink refusal as route-state reads. The helper is named in the file list but not wired into the publish procedure.

**Suggested revision:** Mandate `_read_result_env` / `phase_driver_read_result_env` for `.design-clarify-request.env` with the Bash allowlist.
