## Edge cases

- `DESIGN_TMPDIR` missing, relative, nonexistent, or not a directory.
- `--issue` or `--claude-pid` is not a positive integer (wrapper and Python, exit 2).
- `--phase` missing or not `fetch|publish` (wrapper and Python, exit 2).
- `REPO` is malformed in env, route state, or request state.
- `.design-step0-route-state.env` is a symlink, unreadable, malformed, or absent.
- Route-state read failure on fetch vs publish (staging vs no staging).
- `.design-clarify-request.env` is absent, symlinked, unreadable, malformed, has mismatched `ISSUE_NUMBER`, or has missing/invalid `REQUEST_ID` (invalid `REQUEST_ID`: exit 2, no publish result env).
- `PLAN_FILE` or `RESPONSE_FILE` is empty, unreadable, missing, or symlinked.
- Redaction raises or returns empty output.
- `SESSION_ID` is empty.
- Log publish returns zero without `PUBLISH_OK=true`.
- Rename fails after response post and label removal.
- Pause is requested before either phase, after route-state resolution (must terminate before clarify work).
- Wrapper argv parsing consumes `"$@"`; delegation must use saved/rebuilt args.

## Failure modes

- Fetch failures are terminal clarify failures and should stage failed clarify.
- Publish route-state read failure is non-staging (`route-state-read-failed` only).
- Publish plan write, redaction, and artifact failures should fail closed before response post (exit 1, write publish result env).
- Invalid `REQUEST_ID` must fail closed before redaction or plan write (exit 2, **omit** publish result env; Bash `fail()` parity).
- Log publish failure is warning-only and should not block response post or label removal.
- Rename failure is warning-only and should not change the successful publish result.
- Pause-save must terminate the driver; clarify primitives must not run after pause.
- Direct Python exceptions should be redacted before entering result env rows or logs.
