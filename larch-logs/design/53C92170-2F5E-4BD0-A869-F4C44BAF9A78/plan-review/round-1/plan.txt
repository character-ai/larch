## Approach

Port the three soak-proven patches verbatim in intent (#3 drop `--json`, #5 OID poll, #7 remove
pre-merge flush) and add the unpatched fixes (#1 set-e, #4 error contract, #6 breadcrumbs). Layer
the two operator scope expansions on top: O1 makes in-loop flushes commit only on substantive
change without leaving a dirty index (FINDING_2), and Decision 1 lowers the runtime floor to 3.11
across packaging, lint/type pins, docs, CI matrix, implement + report-tokens guards. Every behavioral change gets a
regression test; the merge-convergence test is the gate for #7 + O1.

## Edge cases
- `gh pr create` stdout with a trailing newline or multiple URLs → `_recover_pr_from_conflict_text`
  takes the last match.
- `pr_for_branch` transiently fails right after a successful create → URL-parse fallback; if both
  fail, `ShipError` → JSON STALLED (#4), not a crash.
- OID poll: genuine (non-lag) mismatch exhausts the cap and returns `MERGE_RESULT_ERROR` (current
  behavior, just after polling) — it must not loop forever.
- Volatile-only flush skip: the first flush with real content still commits; a later flush whose
  only delta is timestamp/elapsed churn skips — substantive paths always force a commit.
- Volatile-only skip after publish: porcelain under the run path must be empty (classify-before-add
  or `git reset HEAD --` cleanup) so a later force-push does not see staged refresh JSON.
- Selector: `python3` == 3.11 passes; < 3.11 fails loudly; a 3.12 `python3` still passes.
- `/report-tokens`: `run-analysis.sh` probe matches docs/pyproject (≥ 3.11).
- parse-bootstrap: file-first pre-populates keys, then the stdout-fallback loop runs with all keys
  set → must still source cleanly under `set -e`.

## Failure modes
1. **Run-log completeness regression from removing the pre-merge flush.** If the removed flush was
   the only commit point for some volatile logs on a clean green path, they could be missing from
   `main`. Earliest signal: run-log-completeness checks / missing token-timing batches. Mitigation:
   logs are already committed at earlier implement steps and pre-rebase; the convergence test plus
   existing run-log verification guard this.
2. **OID poll masks a real mismatch or hangs.** A too-long/uncapped poll could hang, or an
   over-eager early return could merge a mismatched head. Signal: merge stalls or merges wrong OID.
   Mitigation: cap at `MERGE_PR_POST_PUSH_UNKNOWN_RETRIES` × 5s and return ERROR on exhaustion;
   early-return only on exact `head_ref_oid == local_head`.
3. **Volatile-only classifier drops substantive logs.** Too-broad volatile matching could skip a
   real log commit or leave a dirty tree. Signal: missing execution-issues batches in `larch-logs/`
   or `dirty worktree before force-push`. Mitigation: explicit basename allowlist (FINDING_4);
   classify-before-add or reset on skip (FINDING_2); commit whenever any non-allowlisted path changed; test both directions plus clean porcelain.
