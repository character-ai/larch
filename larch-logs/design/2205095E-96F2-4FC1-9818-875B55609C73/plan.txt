### UPDATED: python/rendering.py

- Add `--archetype` to `render voter`.
- Keep the default empty value so existing plan-review and MAV call sites keep their current prompt.
- Add three code-review voter archetype definitions with distinct lens behavior (each still applies the full acceptance rubric):
  - **`validity-correctness`**: "Is it real?" lens. Read cited `file:line` and the claimed failing scenario. Vote YES only when the defect is real and triggerable (logic errors, off-by-one, nil/None handling, type mismatches, races, exception/cleanup paths, security and boundary correctness). Default NO when the cited code does not exhibit the claimed defect or the scenario is not triggerable.
  - **`plan-fidelity-completeness`**: "Is it in scope and necessary?" lens. Vote YES when the feature would be incomplete, broken, unverifiable, or regressed without the finding against the implementation plan or stated intent (plan-to-implementation traceability, missing required artifacts/tests, stale replacement surfaces, partial/inverted planned requirements). Default NO for real-but-out-of-scope findings; those belong in OOS, not in-scope acceptance.
  - **`pragmatism-cost`**: "Is the fix worth it?" lens. Vote NO when value does not justify added complexity or maintenance (speculative robustness, cleaner/idiomatic/best-practice churn, premature configurability, unrequested refactors, micro-optimizations, portability speculation). Vote YES when the finding is necessary or the fix is clearly proportionate. Hard constraint: never trade away real correctness or security defects for simplicity; defer to lens 1 on correctness/security.
- **`plan-fidelity-completeness` no-plan fallback**: when `--verification-context code` and no plan context is staged for the render call (no `--plan-file` forwarded to `render voter`, which is the normal `/review --diff` and other paths where `dispatch-code-voters.sh` omits bounded `plan-context.txt`), inject an explicit fallback block after the archetype lens and before output-format instructions:

  - Treat missing plan as absence of a formal plan anchor, not automatic NO.
  - Do not require implementation-plan traceability that was never supplied; still default NO for real-but-out-of-scope findings.
- When bounded plan context **is** staged (`--plan-file` present on the render call), keep the existing "use the ballot path and any provided diff/plan context files" behavior; do not inject the no-plan fallback.

## Edge cases

- **Cursor unavailable:** run one Claude voter via `launch-claude-review`. Do not run Codex. Do not route Claude through `dispatch-waterfall`. Do not revert to the legacy 3-vendor panel.
- **Cursor available but one archetype fails:** keep the remaining Cursor voters. Let the existing threshold table handle the reduced effective quorum. `DISPATCH_OK` stays `true` even when `cursor-validity` (Voter 1) fails if at least one other slot survives.
- **Cursor available but all three fail:** `effective_judges=0`; set `DISPATCH_OK=false`; tally sees zero effective voters and uses the existing main-agent-vote-required path.
- **Claude floor fails:** `DISPATCH_OK=false`; audit heuristics treat this as floor failure.
- **No staged plan on code-review paths:** `plan-fidelity-completeness` uses the no-plan fallback (diff + ballot scope); do not treat missing plan as automatic NO or require unstaged implementation-plan traceability.
- **All manifest rows `tool=cursor`:** slot identity comes from predetermined paths and labels, never from `ALL_OUTPUT_TOOLS` tool-name deduplication.
- **Parse-rate retry:** retry the same archetype slot with the same archetype prompt plus the structured-vote prefix; `launch_voter_retry` must accept `cursor-*` labels.
- **Parse-rate filtering:** compact `EFFECTIVE_VOTER_FILES` and `EFFECTIVE_VOTER_LABELS` together so TSV `vN_tool` attribution matches surviving slots.
- **Same-tool mapping:** do not map waterfall outputs by tool name. All normal slots are Cursor, so slot identity must come from deterministic paths and emitted labels.
- **Attribution:** use per-archetype labels, not bare `cursor`, wherever voter labels are emitted or written to classification TSV rows.
- **TSV row shape:** every row (including 0-judge placeholders) must emit 21 cells matching the header; six cells per voter slot including `vN_tool`.
- **review-core label guards:** `voter_labels` must be built under the same predicates as `voter_files`, not inferred from filenames.

## Failure modes

- A partial Cursor outage may produce a degraded 1/3 or 2/3 panel without flipping `DISPATCH_OK`.
- All-three-failed Cursor rounds must flip `DISPATCH_OK=false`; leaving it `true` with `effective_judges=0` breaks audit heuristics and misreports dispatch health.
- Routing the Claude floor through `dispatch-waterfall` will exit 2 or never launch because manifest tools are limited to `codex`/`cursor`.
- Reusing `ALL_OUTPUT_TOOLS` tool-name mapping when all slots are Cursor would collapse archetype outputs onto one slot or drop paths.
- Setting `DISPATCH_OK=false` on Voter 1 failure alone in the 3-Cursor path would false-alarm audit heuristics when other archetype slots survive.
- A bad archetype prompt could correlate all three voters too tightly. The implementation keeps labels and per-slot logs so later analysis can measure this.
- Missing no-plan fallback on `plan-fidelity-completeness` may default NO on legitimate in-scope findings on `/review --diff` and shift 2-of-3 outcomes.
- A mismatched `--voter-labels` list could corrupt TSV attribution. Validate and fail fast.
- Header-only `vN_tool` updates without six-cell row emission would produce ragged TSV rows and break `csv.DictReader` / fluff-analysis header lookup.
- Building `voter_labels` outside the `voter_files` guard predicates could mis-attribute `v2_tool`/`v3_tool` after a middle-slot failure.
- Parse-rate compaction that drops files but not labels would leave ratings under `v2_*` while `v2_tool` names a different surviving slot.
- Stale `expected_voters_for_round` logic could emit spurious degraded warnings. Align with dispatch `expected_judges`.
- A stale test stub that assumes Codex voter paths may hide regressions. Update stubs to read the manifest and emit predetermined paths.
- **`parse_impl_tsv` index drift:** if left on hardcoded positions, adding `vN_tool` columns shifts v2/v3 severity cells and silently corrupts `/fluff-analysis` voter-severity reports on new implement run logs. Header-name parsing is the mitigation.
- **Stale #3704 harness probe:** leaving the Claude+waterfall parallelism test in place after dispatch retires the Claude lane will fail CI or give false confidence. Replace with a 3-Cursor waterfall concurrency assertion.
- **Docs-sync anchor drop:** removing `3-judge panel on every round` from any of the five POS targets (`skills/implement/SKILL.md`, `step-5-review.sh`, `README.md`, `docs/review-agents.md`, `docs/skills.md`) fails `test-quick-mode-docs-sync.sh`; update only the vendor wording and keep the anchor.
- **Stale public consumer docs:** leaving `README.md`, `docs/review-agents.md`, `docs/skills.md`, or `docs/voting-process.md` on the legacy `Claude opus + Codex + Cursor` / `Claude + Codex + Cursor` code-review voter wording lands a PR whose canonical docs contradict the shipped 3-Cursor panel.
- **voting-protocol drift:** partial rewrites that leave legacy Claude+Codex+Cursor prose in Launching Voters, availability, or wait-reviewers sections contradict operator-facing SKILL/banner text and invite regressions.
- **Sibling contract drift:** updating `test-dispatch-code-voters.sh` without `test-dispatch-code-voters.md` will misdocument shard inventory and confuse future harness edits.
