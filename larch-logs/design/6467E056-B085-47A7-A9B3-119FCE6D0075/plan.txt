## Edge cases

- **Older paused sessions**: keep `design-step5.sh` present as a compatibility surface unless tests show it is safe to delete.
- **Compatibility argv**: do not delegate with empty consumed argv. Reconstruct `--session-env-path` and `--claude-pid`, or preserve env sourcing before delegation.
- **Empty summary file**: emit no markers. The orchestrator fallback gate still checks the file.
- **Render helper prints stdout**: wrappers that call `render-final-summary.sh` directly must capture helper stdout before emitting marked output.
- **Publish rc 3**: parse stdout fallback as today, then emit markers from the written summary file.
- **Publish rc 1**: emit the marked failed-plan-write summary before the plan-write failure warning.
- **Publish rc 2 / unexpected rc**: emit the marked failed-publish-tail summary before sidecars and before the required abort.
- **Validator rc 4**: do not emit stale summary markers from Step 5c. The cancellation Final summary block owns that terminal summary.
- **Step 0 title-filter / re-entry cancel**: leave existing behavior unchanged. This plan does not modify Step 0 route marker handoff.
- **Route stdout capture**: leave existing route KV parsing unchanged.

## Failure modes

- **Markers missing**: SKILL falls back to reading the non-empty summary file.
- **Only one marker present**: treat marker extraction as invalid and use the file fallback.
- **Summary body contains marker-like text**: use dedicated whole-line markers and the first balanced pair.
- **Sidecars exist**: keep `REPORT_GATE_SIDECARS_FILE` as a path handoff. Do not convert sidecars to markers.
- **Final summary render fails**: emit no markers when no non-empty summary file exists, then abort as today.
