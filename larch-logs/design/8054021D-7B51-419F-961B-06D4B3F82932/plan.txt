## Edge cases

- **Missing plan or missing `diff_lines`:** `plan check-size` returns rc=2 and stdout KVs. The wrapper logs them, echoes them, and returns rc=2.
- **Usage or validation error:** `plan check-size` may return rc=3 and write diagnostics to stderr. The wrapper logs stderr too and returns rc=3.
- **Append failure fails:** `_append_failure` already suppresses command stdout and stderr. The wrapper should not change the rc or block the caller.
- **Pause requested:** `step2b5_main` must return the pause-save rc without running or logging check-size.
- **Successful check:** No failure log or execution issue should be written.

## Failure modes

1. **KV stdout changes**
   - Warning signal: Step 2b.5 prompt-side parsing no longer sees `PLAN_SIZE_STATUS` or size KVs.
   - Mitigation: Echo exactly the captured stdout and keep stderr out of launcher stdout.

2. **Duplicate execution issue rows**
   - Warning signal: tests or manual runs show two Step 2b.5 Warnings entries for one check-size failure.
   - Mitigation: Remove prompt-side `run-log append-failure` prose for Step 2b.5 rc=2 and other-rc branches.

3. **Lost stderr diagnostics**
   - Warning signal: rc=3 log lacks the argparse or validation diagnostic.
   - Mitigation: Capture stderr into the validation log for all non-zero check-size returns.
