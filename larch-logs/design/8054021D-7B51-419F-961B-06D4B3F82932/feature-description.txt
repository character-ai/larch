# md-to-py-IV: let failing design verbs self-log to execution-issues.md instead of prose run-log append-failure

**Theme:** Part of the md-to-py-IV umbrella. Move residual prose-logic from `/design` SKILL.md into deterministic Python.

**Problem.** Multiple `/design` failure branches instruct the orchestrator to write a capture file and then call `run-log append-failure --site … --tool … --exit-code … --category Warnings` by hand. The canonical example is Step 2b.5 rc=2 and the "any other rc" branch (`skills/design/SKILL.md` ~515-516), but the pattern recurs (Step 5b OOS prepare/annotate failure paths, validator-failure paths). The verb already knows it failed and holds the capture.

**Proposed change.** Have the failing Python verb append its own capture to `execution-issues.md` (it already spawns sibling `cli.py` subprocesses, so it can call `run-log append-failure` internally) before returning. The orchestrator's job shrinks to "on nonzero rc, print the warning breadcrumb and continue."

**Acceptance.**
- At least the Step 2b.5 rc=2 / other-rc branches self-log inside Python.
- The `run-log append-failure` invocation prose is removed from those orchestrator branches.
- Establish the self-logging pattern for the other design failure branches to follow.

**Notes.** Hot path. Scope this issue to the Step 2b.5 branches plus a documented pattern; sibling failure branches can adopt it incrementally.
