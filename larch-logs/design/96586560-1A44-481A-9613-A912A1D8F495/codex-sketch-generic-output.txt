The main tradeoff is strictness versus resume compatibility. Existing docs and tests allow empty `ISSUE_NUMBER` / `RUN_ID` in sentinel mode for partial or older files, while `/implement` later treats malformed sentinels as unusable and falls through. The safest change is to reject malformed non-empty values without changing absent-key behavior. Error messages should not echo malformed sentinel values, especially values containing newlines, because stdout is itself parsed as KEY=VALUE.
