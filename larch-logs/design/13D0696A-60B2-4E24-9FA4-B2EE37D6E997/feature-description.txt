# Fix vendor token pricing and consolidate the pricing machinery into one authority

**One job**: correct every wrong rate constant, eliminate all duplication of pricing constants and pricing code (at most one implementation per language; constants live in exactly one place), and close the ledger-completeness gap found during the investigation.

## Root cause (investigated 2026-06-11)

The reported dollars are arithmetically exact applications of wrong rate constants. Two independent errors, opposite directions:

1. **Codex underpriced ~9-12x per bucket.** Shipped defaults ($0.44 / $0.04 / $3.50 per M) are the GPT-5.3-Codex credit-table row (43.75 / 4.375 / 350 credits per 1M) converted at $0.01/credit. A Codex credit costs **$0.04** (cross-checked against GPT-5.5 API list price). Worse: larch's default Codex model is `gpt-5.5` (`scripts/agent-model-args.sh:157`, predates the 2026-05-22 rate "verification" in #2622 Bug 3), priced at 125 / 12.5 / 750 credits per 1M, which is **$5.00 / $0.50 / $30.00 per M**. The table was wrong from day one: wrong model row times wrong credit conversion.
2. **Cursor overpriced ~1.5x blended.** Shipped defaults ($1.25 / $0.25 / $6.00 per M) are Cursor **Auto-mode** rates, but larch pins `composer-2.5` (`scripts/agent-model-args.sh:151`), which costs **$0.50 / $0.20 / $2.50 per M** per cursor.com/docs/models-and-pricing.

Repricing the example run below (4B3C1A5A, ledger token counts unchanged) with correct rates: **Codex ≈ $75.69, Cursor ≈ $22.88** versus the reported $6.76 / $34.81. The report inverts reality. Across the last 6 design runs, Codex is actually 2.2-3.8x more expensive than Cursor; cache reads dominate (~92% of tokens) and composer-2.5 cache reads ($0.20/M) are only 2.5x cheaper than gpt-5.5 cached input ($0.50/M), so the true gap is ~3x, not 10x.

**Claude lane rates are correct** for Opus 4.7/4.8 ($5.00 / $0.50 / $6.25 / $10.00 / $25.00). Limitation to document: a Fable 5 main agent bills 2x that ($10 / $1.00 / $12.50 / $20.00 / $50.00); see Out of scope.

**Secondary ledger bug**: the `/design` Step 2b drafter sidecar (`RAW=codex_plan_draft`, ~800k tokens in the example run) is written by `launch-codex-exec.sh` but never ingested into the run ledger. `ship-pr.sh` ingests its codex-exec sidecars (`ship-pr.sh:1475`, `:2779`); `/design` has no equivalent call.

## Duplication inventory (what the overhaul removes)

- `python/report_tokens_cost.py:16-29` `DEFAULT_*` constants, plus `display_rates()` (~line 63) and `env_rate()` (~line 42). This copy is the live authority; all runtime imports use it.
- `python/report_tokens_models.py:145-183` **duplicate** `env_rate()` and **duplicate** `display_rates()` with the same numbers re-hardcoded inline. Used only by `python/test_report_tokens_models.py`.
- Blended fallback constants (`0.80 / 2.00 / 1.50` per M) are a second independently-maintained constant family in the same files.
- `docs/configuration-and-permissions.md` "Per-vendor rates" section documents pre-#2629 blended defaults (`6.00 / 10.00 / 10.00`) that no longer exist anywhere in code, and omits the per-bucket env vars.
- Pinned dollar expectations are spread across `python/test_report_tokens_cost.py`, `python/fixtures/report_tokens_design_golden.md` and `python/fixtures/report_tokens_implement_golden.md` (including the rendered "Rates used for display/fallback" legend), `scripts/test-render-run-summary-format.sh`, and `scripts/test-render-run-summary.sh`.
- Bash status: `scripts/token-cost.sh` / `scripts/token-report.sh` are already retired (#3671). `scripts/render-run-summary.sh` computes no rates; it shells out to `python3 python/cli.py token cost` and only formats the cost line. After this job, bash holds **zero** rate constants and **zero** cost computation. The one acceptable per-language pair is the cost-line *formatter* (bash `larch_emit_cost_line` and the Python `token render-cost-line` main), which the format-equality harness already pins.

## Plan

### 1. Single pricing authority

- `python/report_tokens_cost.py` becomes the **only** module holding rate constants, `env_rate()`, and `display_rates()`. Keep the module docstring claim ("Shared token pricing and display-rate authority") true.
- Express the constants as a table keyed by `(vendor, model)` plus a `DEFAULT_VENDOR_MODEL` map (`codex: gpt-5.5`, `cursor: composer-2.5`, `claude: claude-opus-4-8`). `display_rates()` resolves the default-model rows, so the `DisplayRates` surface, env-var ladder, and all call sites stay unchanged.
- Annotate the table with source URLs and a "verified as of YYYY-MM-DD" comment (same convention #2622 introduced). Re-verify the numbers below against the live pages at implementation time; the official OpenAI rate-card page rejected automated fetch during the investigation, so the Codex numbers rest on developers.openai.com/codex/pricing credits at $0.04/credit, corroborated by GPT-5.5 API list pricing.
- Delete `env_rate()` and `display_rates()` from `python/report_tokens_models.py`. `report_tokens_models.py` keeps only the `DisplayRates` dataclass and other typed models. Move or repoint the 4 tests in `python/test_report_tokens_models.py` that exercise the deleted copies.
- Derive the blended fallback rates from the per-bucket constants at a documented canonical bucket mix instead of hardcoding a second family. Measured fleet mix across recent design runs is roughly 7% uncached input, 92% cache read, 1% output; document the chosen mix as a constant next to the table. Resulting blended defaults land near $1.10/M (codex), $0.25/M (cursor). Keep the existing blended env overrides working.

### 2. Correct the defaults

| Bucket | Old | New | Basis |
|---|---|---|---|
| codex input | 0.44 | **5.00** | gpt-5.5, 125 credits/1M at $0.04 |
| codex cached input | 0.04 | **0.50** | 12.5 credits/1M |
| codex output | 3.50 | **30.00** | 750 credits/1M |
| cursor input | 1.25 | **0.50** | composer-2.5 row |
| cursor cache read | 0.25 | **0.20** | composer-2.5 row |
| cursor output | 6.00 | **2.50** | composer-2.5 row |
| claude (all five buckets) | unchanged | unchanged | Opus 4.8 list, still correct |

No data migration: committed run logs store raw token counts, and `/report-tokens` reprices historical runs at render time (`priced_by_token_cost` path), so corrected dollars apply retroactively. Numbers frozen in old issue comments stay as posted; acceptable.

### 3. Model-basis drift guard

This bug recurred because the rate table and the configured default models drifted independently. Prevent recurrence:

- Record the model in new vendor token records: launchers already resolve the model via `agent-model-args.sh`; pass it through `token record-vendor` / the `.token-record` sidecar as an optional `model=` field. Readers tolerate its absence (historical records).
- Add a consistency test that fails when `DEFAULT_VENDOR_MODEL` in the pricing authority disagrees with the defaults emitted by `scripts/agent-model-args.sh --tool codex` / `--tool cursor`.

### 4. Ledger completeness

- Ingest the Step 2b drafter sidecar in `/design`: after the drafter launch completes, call `python3 python/cli.py token append-record --input "$OUTPUT.token-record" --tmpdir "$DESIGN_TMPDIR"` (mirror the `ship-pr.sh` pattern, warn-not-fail on error).
- Audit every `launch-codex-exec.sh` / `launch-*-ci.sh` call site for `.token-record` sidecars that are written but never appended; route each through the same single ingestion helper exactly once. The review/vote panel path (which records via `token record-vendor` directly) is already ingested; do not double-count it.

### 5. Docs

- Rewrite the "Per-vendor rates" subsection of `docs/configuration-and-permissions.md`: remove the stale `6.00 / 10.00 / 10.00` blended text, document the per-bucket env vars and new defaults, name the model basis per vendor (gpt-5.5, composer-2.5, Opus 4.8), and note the Fable 5 limitation and the estimates-not-invoices caveat (subscription plans may make marginal cost lower than API-equivalent rates).
- Update the constants provenance comment and the `.md` sibling of any touched script per repo convention.

### 6. Tests and fixtures

- `python/test_report_tokens_cost.py`: convert rate-arithmetic tests to inject explicit rates via `environ` so they stop re-pinning shipped defaults; keep **one** snapshot test that pins the shipped default table (the single allowed restatement of the constants).
- `python/test_report_tokens_models.py`: drop or repoint the tests of the deleted duplicate functions.
- Regenerate `python/fixtures/report_tokens_design_golden.md` and `python/fixtures/report_tokens_implement_golden.md` (dollar columns plus the rates legend lines).
- Update pinned dollar strings in `scripts/test-render-run-summary-format.sh` and `scripts/test-render-run-summary.sh`.
- New: model-basis consistency test (section 3); drafter-sidecar ingestion test with an offline fixture asserting a `codex_plan_draft` row lands in the ledger exactly once.
- Run `bash scripts/relevant-checks.sh` and `make py-lint py-test`.

## Acceptance criteria

- Repricing the 4B3C1A5A ledger with shipped defaults yields Codex ≈ $75.7 and Cursor ≈ $22.9.
- Grep for any per-M rate literal finds it in exactly one runtime module, one test snapshot, and docs prose. `report_tokens_models.py` contains no rate numbers and no `env_rate`/`display_rates`.
- Bash contains no rate constants and no cost computation (formatter-only, format-equality harness still green).
- A `/design` run's ledger contains the `codex_plan_draft` record.
- Existing env-var overrides keep working unchanged (per-bucket beats blended beats defaults).

## Out of scope (file separately if wanted)

- Per-record model-keyed pricing (pricing each ledger row by its recorded model rather than the vendor default row). This is what would price a Fable 5 main lane at Fable rates and old gpt-5.3 runs at gpt-5.3 rates. Section 3's model field makes this possible later without another wire change.
- Distinct `raw` labels for aggregator/judge Codex calls (currently lumped with `codex_review`).
