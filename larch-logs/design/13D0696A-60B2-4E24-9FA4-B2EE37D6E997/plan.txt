## Approach

- Treat `NO_SKETCHES_CLASSIFIED_SIMPLE` as authoritative.
- Draft from direct inspection, not sketch agreement.
- Keep scope to pricing authority, rate defaults, tested ledger-completeness gaps, and sidecar model metadata needed by those gaps.
- Do not migrate run logs.
- Reprice existing token counts at render time.
- Preserve override order:
  - per-bucket env vars win when bucketed counts are available
  - blended env vars remain compatibility fallbacks for aggregate-only counts
  - derived defaults apply last
- Treat `.token-record` sidecars as best-effort accounting input.
- Clear stable sidecars before launch.
- Ingest each fresh sidecar exactly once.
- Keep launchers sidecar-only unless they already record directly into the active ledger.
- Route sidecar ingestion through one parser and one active-ledger helper.
- Capture `model` only where this change needs sidecar provenance or an existing helper contract requires it.
- Do not price by per-record model in this change.
- Do not create or edit `scope-files.txt`; it is not a repo file.
- Keep implementation scope metadata outside the repo file list.
- Defer prompt-only research, validation, voting, and dialectic retry-sidecar matrices to follow-up issues unless a script-owned call site can be tested now.
- Keep `Makefile` in scope because the new Step 2b harness has Makefile wiring.

## Failure modes

- A duplicate pricing helper can reintroduce stale constants. Guard with grep and tests.
- A drift between `DEFAULT_VENDOR_MODEL` and `agent-model-args.sh` can silently misprice reports. Guard with a sanitized-env model-basis test.
- The 4B3C1A5A repricing can regress if no test uses the real bucket mix. Guard with a default-rate repricing regression.
- A model-basis test can parse the wrong token if it assumes a single output token. Parse argv-token lines and extract values after `-m` or `--model`.
- User model override env vars can break the drift test if not sanitized.
- `launch-codex-ci.sh` can write false model metadata if it hardcodes `gpt-5.5`. Write the resolved model instead.
- `launch-codex-ci.sh` can expose stale usage after model/auth preflight failure if cleanup runs after preflight. Clear immediately after `OUTPUT` validation.
- Python CI and rebase tiers can omit Codex or Cursor costs if sidecars are not ingested after each launcher return.
- Python sidecar ingestion can be skipped by rollback, retry, or success branches unless it runs before those branches.
- Ship-pr recovery waterfall can omit Codex or Cursor CI costs if `${output}.token-record` is not ingested before retry `continue` or successful `return 0`.
- Bash `_stage_and_push_ci_fixes` can omit live `/implement` cost lines if it only appends NDJSON and does not record into the active ledger.
- Ship-pr recovery waterfall can double-count if both a tier-local ingestion hook and `_stage_and_push_ci_fixes` consume the same sidecar. De-duplicate by sidecar path.
- Step 2b can double-count if both launcher and wrapper append the same sidecar to the active ledger. Keep launcher sidecar-only and wrapper ingest-only.
- Step 2b can re-ingest stale usage if the stable sidecar is not cleaned before launch.
- Step 2b can still miss committed run-log accounting if tests check only active ledger rows. Assert the `$DESIGN_TMPDIR/token-report.ndjson` row too.
- Drafter failure paths can drop usage if the raw sidecar is copied after cleanup. Copy it immediately after the exec launcher returns.
- Plan-autofix can omit Codex costs if its sidecar is not ingested after launch.
- Plan-autofix can lose ledger mutations if ingestion runs inside the tmpdir guard. Ingest after the guard and restore block.
- Lint-fix can omit failed Codex costs if ingestion remains gated on `parsed_exit == 0`.
- Lint-fix can silently no-op active-ledger recording if `IMPLEMENT_TMPDIR` is not exported into the helper subprocess.
- `TOKEN_RECORD` can point at stale usage after preflight failures. Clear the sidecar before any stdout envelope can be emitted.
- NDJSON-only append can miss live `/design` or `/implement` cost lines. Record sidecars into the active token ledger too.
- A malformed `MODEL=` value can break CLI parsing if treated as numeric. Parse it as opaque text.
- Golden fixtures can mask default changes. Keep only one default-rate snapshot and use explicit env maps or scrubbed legends elsewhere.
- A new shell harness can drift from repo conventions if it lacks a sibling `.md` contract or relevant-check wiring.
- The new Makefile target can be missed if `Makefile` is not in the declared implementation scope.
- A non-existent `scope-files.txt` entry can send implementation work to a bogus repo file. Do not create it.
