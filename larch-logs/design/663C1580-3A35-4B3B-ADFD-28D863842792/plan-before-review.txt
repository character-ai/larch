## Approach

Adopt the approved nine-field schema. Require six fields when loading committed baselines, allow three optional fields, and reject old or unknown shapes. Preserve the existing four-field live-record writer behavior for Piece 2. The one-time baseline migration is performed by a dedicated migration function exposed via a new `--migrate` CLI flag; the implementer runs it once as part of the PR.

## Edge cases

- Reject booleans where integer fields are expected.
- Accept an empty `history` list for grandfathered entries, but reject malformed history elements.
- Preserve absent optional fields without serializing `null`.
- Reject optional metadata with empty strings or partial nested objects.
- Keep live ruff records serializable even though they lack the two committed-only required fields.

## Failure modes

- A partial migration causes `load_baseline` and the lint command to fail closed.
- Reconstructing records without optional fields would silently discard operator metadata. Round-trip tests must catch this.
- Changing `_run_write` in this piece would cross the partition boundary and may conflict with Piece 2.
- Accidental identity or metric edits would weaken or tighten the existing ratchet. Verify projections before accepting the migration.

## Testing strategy

- Run `cd python && python3 -m pytest tests/lint/test_lint_complexity_baseline.py`.
- Run `python3 python/cli.py lint complexity-baseline`.
- Run changed-file Python lint and type checks.
- Run `make lint` as required by acceptance.
- Inspect the baseline diff or a projection comparison to confirm only `added_at` and `history` were added.
