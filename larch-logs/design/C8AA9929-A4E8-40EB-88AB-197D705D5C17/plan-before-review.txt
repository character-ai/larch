## Approach

Replace the `origin/main` assumption with a typed base-resolution result.

1. Read `FORKED_TARGET` from trusted run state. Prefer `session-env.sh`, with `ship-pr-state.sh` as the later lifecycle source.
2. Select `origin` for normal runs and `upstream` for forked-target runs.
3. Resolve `refs/remotes/<remote>/HEAD` with `git symbolic-ref --short`.
4. Validate that the result belongs to the selected remote and is safe for Git argv.
5. Compute the live merge base from the resolved remote branch and `HEAD`.
6. Fall back to `step2-baseline.txt` only when the remote default branch or merge base cannot be resolved. Emit a clear diagnostic naming the failed remote and the conservative fallback.
7. Mark the resolution source internally. Do not change persisted coverage wire formats.
8. When using the live merge base, attribute committed and working-tree plan paths as today.
9. When using the frozen fallback, do not count committed `baseline..HEAD` paths as coverage. Count only current working-tree paths. This fail-closed rule prevents upstream commits from satisfying plan coverage when their provenance cannot be separated from this run.

Keep plan-path filtering and fingerprint construction unchanged after path attribution. This preserves disposition stability and avoids trusting implementer-authored manifest claims as gate evidence.

## Edge cases

- `refs/remotes/origin/HEAD` may be absent in shallow clones or test fixtures.
- Forked flows may have only `upstream/HEAD`, or neither remote HEAD.
- The symbolic ref may point to a deleted branch or return an unexpected remote prefix.
- A remote default branch may contain slashes.
- The selected remote branch may exist while no merge base is available because history is shallow.
- The worktree may contain rename or copy records with two paths.
- Coverage may be recomputed after dispatcher commits or run-log flush commits. Live-base attribution must remain stable, while fallback must remain conservative.
- Run state may be present only in `session-env.sh` during early coverage computation and in both state files later.

## Failure modes

- Do not silently treat an unresolved default branch as `main`.
- Do not pass unvalidated run-state or symbolic-ref text into Git argv.
- Do not let a stale frozen baseline grant coverage from committed paths.
- Do not fail open when the remote HEAD exists but merge-base computation fails.
- Do not change coverage artifact schemas merely to expose internal baseline provenance.
- Do not suppress the fallback diagnostic. Operators need to know why coverage became conservative.
