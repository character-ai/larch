1. [correctness] `scripts/dispatch-with-waterfall.sh:197-202`

The proposed test setup pre-seeds `waterfall-group-results.tsv`, but this script immediately truncates that file at startup for any grouped manifest. That means the stale ledger row described in the plan will not be present when `find_group_ok_for_tool` runs, so the test does not actually cover the failing `cp` branch. With the current test assertions, the scenario could still pass on the old buggy implementation because Codex would simply launch normally for the first grouped slot.

Suggested revision: make the stale row survive ledger initialization, or create the stale condition during the dispatcher run after an `ok` row is appended. Also tighten the counter assertion so it proves the stale-row reuse attempt fell through to relaunch, instead of only checking that Codex launched at least once.
