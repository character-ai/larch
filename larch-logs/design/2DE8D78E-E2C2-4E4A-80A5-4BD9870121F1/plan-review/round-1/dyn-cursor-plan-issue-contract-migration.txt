### 1. correctness — `python/larch/issue/audit_runs.py:710-716`

Preflight concurrency is a **degraded-read** callsite, not a hard-fail one. Today a failed list at line 712 yields `arr=[]`, so the probe does not block and preflight still prints `PREFLIGHT_OK=true`. The plan’s global “catch `ShipError` at command boundaries” guidance is easy to misapply here. Add an explicit preflight-only rule: catch `ShipError`, treat it as `[]`, and preserve current concurrency semantics.

### 2. correctness — `python/larch/issue/analyze_bugs.py:379-401`

The plan replaces the paginated API read but does not call out cleaning `_issue_from_raw`. That helper still filters `pull_request` and accepts API snake_case (`closed_at`, `html_url`, `state_reason`). After migration those branches are obsolete and can mask missing camelCase fields in tests. Drop them and rely on the explicit `gh.issue_list_read` field set.
