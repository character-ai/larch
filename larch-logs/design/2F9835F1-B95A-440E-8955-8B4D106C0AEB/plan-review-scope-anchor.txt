#### Problem

The funnel's input universe is filed `[BUG]` issues, so it answers "were the filed bugs fixed" and is blind by construction to bugs on main that nobody filed. Operator experience during the 2026-07 wave: `/analyze-bugs` reports all bugs fixed, and ten new bugs are filed within hours, discovered only by live runs.

#### Required design

1. New flag `--sweep` with `--sweep-max N` (default 20). Sweep state persists in `sweep-state.json` (fields: `last_sweep_sha`, `last_sweep_at`, `schema_version`) next to `ledger.jsonl` in the analyze-bugs cache root; first run defaults to the last 48 hours of main.
2. Merge enumeration: first-parent commits on `origin/main` since `last_sweep_sha`, excluding subjects matching `^chore\(larch-logs\)` and `^Release v`, and excluding commits whose diff touches only `larch-logs/`.
3. Per-merge sweep bundle: capped diff, touched files, consumers-of-changed-symbols (reuse the blast-radius scan from the sibling verdict-depth issue once landed; a minimal inline scan is acceptable if this lands first), and the merge's chronic-zone tag from the analytics issue.
4. New agent `.claude/agents/sweep-bug-finder.md` (model sonnet; tools Read, Grep, Glob), adversarial prompt: assume this merge planted a bug that bites within 48 hours; find it against the synced checkout, or return none. Strict JSONL: `{"merge_sha": str, "findings": [{"file": str, "symbol": str, "description": str, "severity": "high|medium|low", "confidence": "high|medium|low"}]}`.
5. Verification pass: each finding goes to a second agent invocation prompted to refute it. Findings surviving refutation land in a `Sweep candidates` report section and in a follow-up body file behind the existing approval-gated `/issue` filing. File sweep follow-ups with dedup ON (a live-run bug report may already exist).
6. Prioritization and budget: chronic-zone merges first, then largest diffs; stop at `--sweep-max` and log the skipped count. Print the cost estimate line for the sweep stage.
7. Update `sweep-state.json` only after a completed sweep (fail-closed on partial runs).

#### Expectation setting (include in SKILL docs)

A static sweep catches contract breaks, wrong field or key names, and logic errors. It does not catch timing, vendor-CLI drift, or GitHub-state bugs; those need harnesses (see the runtime-tier and close-criteria siblings). Document this limit so a clean sweep is not read as "main is bug-free".

#### Tests

Merge-enumeration tests (exclusion rules, first-parent, marker window); sweep-state round-trip and fail-closed partial-run test; JSONL contract parse tests; prioritization and cap tests with skipped-count logging; report fixture.

#### Non-goals

No auto-filing without the gate; no branches other than main; no runtime execution.

#### Acceptance criteria

1. On a fixture history with a flush commit, a release commit, and two real merges, only the real merges are swept.
2. A planted fixture defect (wrong dict key in a consumer) is found by the finder prompt contract and survives the refuter in the golden transcript fixture.
3. Skipped-count logging appears when merges exceed `--sweep-max`.
4. `.claude/skills/analyze-bugs/SKILL.md` documents the flag, the state file, and the expectation-setting paragraph.

#### Backing evidence

31 of 38 recently classified bugs were discovered by live runs, hours after merge; the merges that planted them were reviewable statically (#6946 is a one-line field-name contract break). Part of the `bug-treadmill` umbrella; blocked by the chronic-zone analytics issue.

## Proposed Design Outline

### Goals
- Add `--sweep` / `--sweep-max N` flag to `/analyze-bugs` to find unfiled bugs in recent main merges.
- Run adversarial finder + refuter agents per merge, emit surviving findings in a new report section, and gate filing behind the existing approval prompt.
- Persist sweep state fail-closed so partial runs do not corrupt progress.

### Non-goals
- No auto-filing without explicit approval gate.
- No branches other than `origin/main`; no runtime execution checks.
- No blast-radius scan from the sibling verdict-depth issue (minimal inline consumer scan acceptable).

### Approach sketch
- New `sweep_state` read/write helpers in `analyze_bugs.py` alongside `_cache_root`; state file at `<cache_root>/sweep-state.json`.
- New `sweep_main` / `sweep_enumeration` / `sweep_run` functions in `analyze_bugs.py`; new `("analyze-bugs", "sweep")` CLI verb in `python/larch/cli.py`.
- New agent `.claude/agents/sweep-bug-finder.md` (sonnet, Read/Grep/Glob); adversarial prompt returns strict JSONL.
- SKILL.md gains `--sweep` / `--sweep-max` flag docs, new sweep stages (Stage S0 state-load, S1 enumeration, S2 finder+refuter dispatch, S3 sweep report), and expectation-setting paragraph.
- Tests in `tests/issue/test_analyze_bugs.py` cover enumeration exclusion rules, sweep-state round-trip, fail-closed partial-run, JSONL parse, prioritization, cap/skip-count.

### Surfaces in scope
- `python/larch/issue/analyze_bugs.py`

- `.claude/agents/sweep-bug-finder.md` (new agent)
