## Design gaps to fold into the next plan

A prior plan-review surfaced these two gaps. One reviewer's findings were dropped on a parse error, so they were never voted on; capturing them here so the next `/design` run accounts for them.

1. **Keep straggler-dropped slots out of the code-review failure-threshold gate.** The plan adds `straggler-dropped` slots to `DROPPED_SLOTS_FILE`. In `/review` and `/implement`, `check_reviewer_failure_threshold` (`python/review_pipeline.py:1391`, wired around `python/review_pipeline.py:1922-1924` via `DROPPED_SLOTS_FILE`) counts that file toward the >50% panel-fail gate. Intentional straggler drops could flip `THRESHOLD_OK=false` even when enough reviewers actually succeeded. The reaper change must exclude straggler drops from that failure math (for example via a separate KV the threshold logic ignores), or the gate will misfire once the cutoff is active for code-review panels.

2. **Do not let an exit-0-but-empty-output launch anchor the quorum.** The reaper counts `rc==0` launches toward the success quorum, but substantive validation runs later (collector-side). An exit-0 launch with empty or unparseable output would still count and could anchor the deadline on a non-substantive fast exit. The "fastest = exited successfully, not a fast crash" intent covers non-zero crashes, not "fast empty success." Either defer arming until a collector-validated success, or document that exit-0 alone is the anchor and accept early cuts. This failure mode is real: a recent run's Codex voter exited 0 with empty output.

## Plan

> **Draft snapshot from an interrupted `/design` run.** Plan review did NOT run. `/design` was stopped to fix a `/design` bug first. The Round 1 Q&A decisions below are folded into the plan. Re-run `/design 4658` after the fix (it will offer to replace this draft).

### Design decisions (Round 1 Q&A)

1. **Scope**: cover all three reviewer panels — `/design` plan-review, `/implement` review, `/review` code-review. They all funnel through `agent dispatch-waterfall` (`python/agent_waterfall.py`), so one reaper change covers them.
2. **Cutoff policy**: adaptive. The time cap is a function of the **fastest completed reviewer** in the round (issue-specific, not a fixed average, because issues differ hugely in size). Deadline is about **3X** the fastest reviewer's elapsed time (2.5X acceptable). Do not always cut off; only reviewers that exceed the multiple are cut.
3. **Timed-out stragglers**: killed and dropped. **Waterfall fallback is DISABLED** for them — no codex->cursor->claude cascade. The round proceeds with the reviews already collected.
4. **Safety bounds**: deadline = clamp(multiple x fastest, floor, ceiling). Multiple default 3 (`LARCH_REVIEWER_STRAGGLER_MULTIPLE`; `0` disables and restores today's wait-for-all). Floor default 300s (`LARCH_REVIEWER_STRAGGLER_FLOOR_SECONDS`). Ceiling = existing per-reviewer `--timeout` (1860/1800). "Fastest" = the fastest reviewer that exited successfully, not a fast crash.

### Files to modify

**`python/agent_waterfall.py`** (core change)
- Add `import time` and two env readers (`_straggler_multiple()` default 3, `_straggler_floor()` default 300), mirroring the existing `LARCH_FALLBACK_CLAUDE_WARN_THRESHOLD` pattern.
- Rewrite `_reap_phase` from a per-launch blocking `process.wait()` into one concurrent poll loop, signature `_reap_phase(launches, opts) -> set[int]` returning straggler-dropped indexes:
  - Capture `start = time.monotonic()`; poll all launches with `process.poll()` on the existing 0.05s cadence; on each finish write `.done`, close stderr, drop from `_ACTIVE_LAUNCHES` / `_DISPATCH_LAUNCHES`.
  - Track `first_success_elapsed` = elapsed of the first launch exiting `0` (a fast crash does NOT anchor).
  - When set and multiple `> 0`: `deadline = min(ceiling, max(multiple * first_success_elapsed, floor))`, ceiling = `int(opts.timeout)`.
  - At the deadline, `_terminate_launch(...)` each remaining launch (existing process-group + descendant SIGTERM), write their `.done`, return their indexes.
  - Multiple `0` or no success ever: never set a deadline; wait for all (each self-terminates at its own `--timeout`). Identical to today.
- `_collect_phase`: pass `opts` to `_reap_phase`; for returned straggler indexes set `drops[idx] = DropState("straggler-dropped", ...)` and `continue` so they are **never** appended to `failed` and `final_outputs[idx]` stays empty. This is what DISABLES fallback for timed-out reviewers: only `failed` indexes feed phase2/phase3, so straggler-dropped slots skip both the other-tool and claude fallback, in both `--no-fallback` and fallback-active modes.
- Output assembly + `_write_paths_file`: skip empty `final_outputs` unconditionally (today gated on `opts.no_fallback`); in fallback mode only straggler-dropped slots are empty, so this just excludes them from `ALL_OUTPUT_FILES` / paths file.
- Observability: emit `STRAGGLER_DROPPED_COUNT` and, when `> 0`, `WARN=reviewer-straggler-dropped`; include straggler-dropped slots in the existing `DROPPED_SLOTS_FILE` sidecar.

**`python/test_agent_waterfall.py`** (tests)

- Straggler-dropped index absent from the fallback queue (no phase2/phase3 launch), in both fallback-active and `--no-fallback` modes.
- `LARCH_REVIEWER_STRAGGLER_MULTIPLE=0` disables the cutoff (wait-for-all preserved).
- Floor enforced; fast non-zero-exit does NOT anchor; ceiling clamp holds; `STRAGGLER_DROPPED_COUNT` / `WARN` emitted only when a straggler is dropped.

### Edge cases / failure modes

- `multiple=0` -> disabled; no success ever -> wait to ceiling; single-slot phase -> nothing to cut; all finish before deadline -> none cut.
- `floor > ceiling` misconfig -> clamp keeps `deadline <= ceiling`.
- Orphaned processes after kill -> reuse `_terminate_launch` (process group + descendants); existing atexit/SIGTERM cleanup unchanged.
- Over-aggressive cutoff -> mitigated by floor + 3x headroom + success-only anchor; signal is rising `STRAGGLER_DROPPED_COUNT`; mitigation is raising multiple/floor via env.
