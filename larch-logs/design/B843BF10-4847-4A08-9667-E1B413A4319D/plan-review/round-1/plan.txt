# Implementation Plan — sh-to-py F1: cli.py dispatcher, direct-call convention, migration playbook (#3667)

## Context

F1 is the root of the sh-to-py DAG (umbrella #3692). It lands the keystone conventions: one argparse dispatcher (`python/cli.py`), the direct-call convention (`python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" <domain> <verb> ...`, no .sh shims), the migration playbook, and a retired-scripts manifest + lint. Per Round 1 decisions: adopt `ship` and `report-tokens` as the first real domains, implement the lint in Python as a cli.py subcommand, scan all tracked files minus exclusions, and fully retire the `run-analysis.sh` wrapper + its harness. Plan-review revisions applied (rounds 1-2): full-path-only lint matching (live `.claude/skills/analyze-issues/scripts/` files share the retired basenames), six additional doc surfaces in the cutover sweep, harness fixture rewrite, report-tokens quiet-env subprocess test, quiet-safe lint diagnostics, and module `__main__` blocks retained as compatibility pass-throughs.

## Files to modify/create

### NEW: `python/cli.py`

- Argparse-based dispatcher. Grammar: `cli.py <domain> <verb> [args...]`.
- Static registry dict: `(domain, verb) -> (module_name, attr, help_one_liner)`. Initial entries: `("ship", "pr") -> ("ship", "main")`, `("report-tokens", "analyze") -> ("report_tokens_cli", "main")`, `("lint", "retired-scripts") -> ("migration_lint", "main")`.
- Lazy dispatch: `importlib.import_module` only for the requested domain, after registry validation. Top-level imports limited to `argparse`, `importlib`, `sys` so startup stays cheap and `--help` never imports domain modules.
- In-driver guard: exit with a clear stderr message when `sys.version_info < (3, 11)`, before any domain import. Keep top-of-file syntax parseable by older python3 (no 3.10+ syntax at module level; `from __future__ import annotations`).
- Help: `cli.py --help` lists domains and verbs from the registry. `cli.py <domain>` with a missing or `-h`/`--help` verb lists that domain's verbs and exits 2 (0 for explicit help). `cli.py <domain> <verb> --help` delegates to the target parser.
- Exit-code passthrough: `return int(target_main(rest_argv))`; `raise SystemExit(main())` in cli.py's own `__main__` block. A `SystemExit` raised inside a delegated parser propagates unchanged. Unknown domain or verb: message to stderr, exit 2 (argparse usage convention).
- Quiet-neutral when delegating: cli.py does NOT call `quiet_init()` itself. Adopted mains own their stream setup (`ship.main` self-initializes quiet conditionally; `report_tokens_cli.main` prints to plain stdout). New subcommands like the lint call `logging_util.quiet_init()` + `contract_stream()` themselves.

### NEW: `python/migration_lint.py`

- `main(argv) -> int` with argparse: `--manifest PATH` (default `python/migrated-scripts.tsv` relative to repo root) and `--root DIR` (default: cwd; tests point it at fixture repos). Parse args (and reject usage/manifest errors) BEFORE `quiet_init()` so argparse messages reach the caller normally.
- Reads the manifest (TSV: `path<TAB>retired_by`; `#` comment lines skipped). Empty manifest: exit 0 with `RETIRED_PATHS=0`.
- Enumerates tracked files via `git ls-files -z` through the `proc.py` runner seam (injectable for tests).
- Exclusions: any path containing a `larch-logs/` segment (nested `python/larch-logs/` is tracked), `CHANGELOG.md`, and the manifest file itself. Skip binary files (NUL byte in first 8 KiB); read text with `errors="replace"`.
- Matching rule: flag any occurrence of a retired **full repo-relative path** string in scanned content. Do NOT match bare basenames — live unrelated files legitimately share basenames with retired paths (`.claude/skills/analyze-issues/scripts/run-analysis.sh` vs the retired report-tokens wrapper), so basename matching would fail `make lint-retired-scripts` on a clean tree.
- Diagnostics are quiet-safe: after `quiet_init()`, emit human-readable `file:line` findings through `logging_util.BreadcrumbWriter().emit()` (fd-4 / `larch_err` parity — never bare `print(..., file=sys.stderr)`, which lands in the quiet log when quiet is active).
- Invariant: a manifest path that still exists in the tree is itself an error ("retired path still present").
- Contract output via `logging_util.quiet_init()` + `emit_kv`: `LINT_STATUS=ok|fail`, `RETIRED_PATHS=<n>`, `RETIRED_REFS=<n>`. Exit 0 clean, 1 on findings, 2 on usage/manifest errors.

## Approach

- **Dispatcher first, domains delegate.** cli.py validates `(domain, verb)` against a static registry, then lazily imports and calls the target `main(rest_argv)`. No behavior changes inside `ship.main` / `report_tokens_cli.main` — their argv surfaces are stable, so consumer cutover is a pure invocation-string swap.
- **Quiet ownership stays with subcommands.** `ship.main` conditionally self-initializes quiet (tmpdir-gated); unconditional dispatcher-level `quiet_init` would change that behavior. The lint demonstrates the blessed pattern for new code: `quiet_init()` + `emit_kv` on the contract stream, `BreadcrumbWriter().emit()` for post-quiet human diagnostics.
- **The lint proves itself in this PR.** The manifest seeds with four really-retired paths; every stale full-path reference left behind fails `make lint-retired-scripts` during implementation, forcing the full sweep the playbook prescribes.
- **Tier-3 surfaces in sync.** SKILL.md fence edits and `test-implement-structure.sh` pins move in the same commit; `make test-implement-structure` (shard member) plus `make lint` gate drift.
- **Order of work**: logging_util helpers → cli.py + tests → migration_lint + manifest + tests → Makefile/pre-commit wiring → consumer cutovers (implement, report-tokens) → deletions → docs (playbook, linting, installation, configuration, workflow, SECURITY, rules, READMEs, AGENTS) → full lint/test pass.

## Edge cases

- `cli.py ship --help` / missing verb: list `ship` verbs, exit 2 (explicit `--help` exits 0); never swallow into REMAINDER.
- Flag-like first token (`cli.py --version`): argparse usage error, exit 2 — only `--help` is a top-level flag.
- Older python3 invoking cli.py: version guard fires before any domain import; module-level syntax stays parse-safe for the guard to run.
- `emit_kv` value containing newline: ValueError → lint maps to exit 2 (lib-quiet parity).
- Manifest with trailing blank lines / comments: skipped; malformed row (no tab) → exit 2 with row number (reported before `quiet_init`).
- A live tracked file sharing a retired path's basename (analyze-issues collision): not flagged — matching is full-path-only.
- Retired full path appearing inside an excluded path (`larch-logs/`, `CHANGELOG.md`): not flagged.
- Lint run from a subdirectory: `git ls-files` runs under `--root` (default cwd) — Makefile/pre-commit always run from repo root; pytest subprocesses resolve cli.py via `Path(__file__)`, not cwd.
- Fresh clone with no python3.11: `make lint` fails loud at the guard with a clear message (matches `py-lint` behavior), not silently green.

## Failure modes

1. **Live /implement Step 8+ breaks at dispatch** (wrong argv mapping after the fence cutover). Earliest signal: `test-implement-structure.sh` pin failures in CI; first `/implement` run erroring at the selector. Mitigation: argv after `ship pr` is byte-identical to today's flags; cli.py delegates verbatim to `ship.main`; harness pins for every edited sentence updated in the same commit.
2. **Lint false positives block CI** (a legitimate doc needs to mention a retired full path). Earliest signal: `lint-retired-scripts` failing on files untouched by this PR. Mitigation: full-path-only matching (basenames never flag); segment-based exclusions (`larch-logs/`, `CHANGELOG.md`, manifest); the no-retired-literal authoring rule for tracked sources; run the lint locally before pushing; diagnostics print `file:line` for fast triage.
3. **/report-tokens output visibility regresses** (wrapper's stream-restore dance removed). Earliest signal: ported pytest quiet/fd-3 cases fail; `/report-tokens` prints nothing in an orchestrator session. Mitigation: direct invocation has no quiet redirection to undo (the wrapper only restored what it itself initialized); subprocess pytest cases pin stdout visibility under staged quiet env for both the lint and `report-tokens analyze`, plus stderr visibility of lint diagnostics.

## Testing strategy

- New pytest: `python/test_cli.py` (dispatch, lazy import, exit passthrough, fd-3 contract subprocess case, report-tokens quiet subprocess case, ported wrapper cases), `python/test_migration_lint.py` (11 cases above), extended `python/test_logging_util.py` (emit/emit_kv).

- Manual: `python3 python/cli.py --help`; `python3 python/cli.py report-tokens analyze --skill design --no-issue --no-plot`; confirm `cli.py ship pr --help` reaches ship's parser.
