Part of the sh-to-py bash-to-Python migration (umbrella tracking issue links all parts; DAG, waves, and global strategy live there).

**Goal**: Establish the keystone conventions every subsequent sh-to-py issue builds on: a single argparse-based subcommand dispatcher `python/cli.py`, the direct-call convention (consumers invoke `python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" <domain> <verb> ...` directly — no .sh shim files, ever), and the written migration playbook.

**Deliverables**:
- `python/cli.py`: subcommand registry (domain subparsers registered lazily so startup stays cheap); stdout/stderr/fd-3 contract wired through `logging_util.quiet_init()` / `contract_stream()` so CLI subcommands can speak the `lib-quiet` KV contract that .md orchestrators parse today (`scripts/lib-quiet.md` is the spec); exit-code passthrough conventions.
- `docs/python-migration.md`: the per-domain recipe — port functions, register CLI subcommands, write colocated pytest (porting harness semantics), cut ALL consumers (.md skill files and not-yet-migrated bash) over to direct CLI calls, run retargetable black-box test-*.sh harnesses once against the CLI as a parity gate, delete bash script + harness, stale-reference sweep per the drift rule.
- A migrated-scripts manifest + lint that fails CI when a retired script path is still referenced anywhere (skills/**/*.md, docs/, scripts/, Makefile, .github/workflows/).
- Decision log recorded in the playbook: no shims; hard cutover (no LARCH_*_IMPL-style selectors); hooks stay bash pending a separate overhaul; flat python/ layout retained; stdlib-only, Python >= 3.11.

**Dependencies**: none (root of the DAG).

**Definition of done**: cli.py has pytest coverage including the fd-3 contract; playbook lands; manifest lint wired into make lint; make py-lint / py-test green.
