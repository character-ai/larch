# Implementation Plan — Issue #2638

## Summary

When the Cursor aggregator produces a self-contradicting output (zero structural `### FINDING_N:` blocks while preamble or body contains the literal substring `### FINDING_`, with or without an attestation token), the existing single-shot dispatch + repair + validate sequence in `aggregate-findings.sh` can silently destroy the input findings. The fix wraps the existing dispatch + repair + validate sequence in a **3-phase validation-driven waterfall** (Cursor → Codex → Claude). The waterfall trigger is **narrow**: it fires only on the NEW "zero blocks + `### FINDING_` substring" rejection — pre-existing validation-failure paths continue to exit on first failure unchanged (resolving the trigger-rule contradiction per FINDING_12). After all 3 phases fail the new check, emit a distinct `REASON=validation-exhausted` that `review-core.sh` short-circuits on, mirroring the existing `panel-failed` envelope (FINDING_2), surfacing as `STALL_REASON=aggregator-validation-exhausted` in `/implement` Step 5.

## Approach

### 1. `aggregate-findings.sh` — narrow-trigger 3-phase waterfall

**Narrow trigger (FINDING_12 resolution)**: the per-phase waterfall fires ONLY when the new substring-rejection rule fires (zero blocks AND `### FINDING_` substring in output). Pre-existing validation-failure paths (missing attestation, impure attestation, unknown reviewer slot, etc.) continue to exit on first failure with `REASON=validation-failed` exactly as today — no behavioral change for those paths, no test churn.

**Internal helper refactor (FINDING_13)**: extract the existing dispatch + repair + validate sequence into an internal `_attempt_aggregation_phase()` helper that returns a structured result (`phase_reason`, `phase_failure_log`, `phase_cand_file`) without calling `append_warning`. The outer per-phase loop only calls `append_warning` on terminal failure (validation-exhausted), passing a single consolidated warning that names all phases attempted.

**Outer phase list construction (FINDING_7 resolution)**: build the outer phase list from truthful availability (CODEX_PRESENT/CURSOR_PRESENT passed into aggregate-findings.sh). The phase order is `(cursor codex claude)` with each external phase included only when its tool is present:

```
phase_list=()
[[ "$CURSOR_PRESENT" == "true" ]] && phase_list+=(cursor)
[[ "$CODEX_PRESENT"  == "true" ]] && phase_list+=(codex)
phase_list+=(claude)  # always available as final fallback
```

After each phase dispatch, inspect `ALL_OUTPUT_TOOLS` emitted by `dispatch-with-waterfall.sh`. If the dispatcher's internal waterfall fell back to a different tool (e.g., outer Phase 1 = Cursor but `ALL_OUTPUT_TOOLS` reports `claude`), treat the outer phase as failed and move to the next outer phase. This prevents the outer loop from miscounting a Claude fallback as a successful "Cursor phase".

**Per-phase dispatch invocation**: build a single-slot NDJSON manifest per phase. Force the intended tool via presence flags scoped per call (not truthfully reflecting session state — this is acceptable because the outer-loop tool-mismatch detection above catches the case where the dispatcher silently falls back). Set the outer-phase output path explicitly via the manifest's `output` field. Use the dispatcher's own emitted `ALL_OUTPUT_FILES` to locate the candidate file (FINDING_1 resolution: do NOT construct `.phaseN` filenames; read them from the dispatcher).

**Substring rejection check (FINDING_8 resolution — applied in TWO places)**:

(a) In `_attempt_attestation_repair()` BEFORE the synthesis branch: add the same zero-blocks + `### FINDING_` substring check that the validator's `main()` will run. When triggered, emit `AGGREGATOR_SYNTHESIS_SUPPRESSED=preamble_finding_substring` to `aggregator-repair.stderr` (parallel to existing `nonconforming_finding_heading_markers` suppression). The repair function then returns `(raw_text, synthesized=False, ...)` so the outer validation runs against the unrepaired output and fails — which then triggers the outer per-phase loop.

(b) In `main()` validation: same zero-blocks + `### FINDING_` substring check. Emits a clear stderr message and returns 1. This is the rejection signal the outer loop watches for.

The check is intentionally duplicated rather than centralized because the two call sites have different roles: (a) suppresses incorrect recovery, (b) signals outer-loop progression.

**Outer-loop trigger discrimination**: the outer loop watches for the SPECIFIC substring-rejection failure signal (not generic `validation-failed`). The validator's `main()` writes a distinct stderr line `AGGREGATOR_VALIDATION_FAILED=preamble_finding_substring` when the substring rule fires; other validation failures continue to emit their existing stderr messages. The outer loop greps the validator stderr for the specific token to decide whether to progress. Any other validation failure exits early with `REASON=validation-failed` as today (FINDING_12 resolution).

**stdout contract extension via `emit_result` (FINDING_6 resolution)**: extend `emit_result()` to optionally emit `PHASES_ATTEMPTED` (only when more than one phase ran, keeping single-phase happy-path stdout unchanged) and accept the new `REASON=validation-exhausted` value:

```bash
emit_result() {
    emit_kv AGGREGATED "$AGGREGATED"
    emit_kv INPUT_COUNT "$INPUT_COUNT"
    emit_kv MERGED_COUNT "$MERGED_COUNT"
    emit_kv REASON "$REASON"
    [[ -n "$FAILURE_LOG" ]] && emit_kv FAILURE_LOG "$FAILURE_LOG"
    [[ -n "$PHASES_ATTEMPTED" ]] && emit_kv PHASES_ATTEMPTED "$PHASES_ATTEMPTED"
}
```

REASON values: existing `disabled` / `insufficient-input` / `dispatch-failed` / `validation-failed` / `ok` plus new `validation-exhausted`.

**Per-phase output file paths (FINDING_1 resolution)**: use `dispatch-with-waterfall.sh`'s native `output_for_phase` naming, driven by `ALL_OUTPUT_FILES`. The outer loop sets a different base output path per outer phase via the slot manifest's `output` field, e.g.:
- Outer phase 1 → manifest `output=$REVIEW_TMPDIR/aggregator-output.txt`
- Outer phase 2 → manifest `output=$REVIEW_TMPDIR/aggregator-output-phase2-of-2.txt`
- Outer phase 3 → manifest `output=$REVIEW_TMPDIR/aggregator-output-phase3-of-3.txt`

The dispatcher then emits these paths verbatim in `ALL_OUTPUT_FILES`. (Distinct names per outer phase prevent any concurrency confusion with the dispatcher's own internal `-phase2.txt`/`-phase3.txt` naming used when internal fallback fires.) The final canonical `aggregator-output.txt` is overwritten only on the successful outer phase, by copying that phase's validated/repaired candidate.

### 3. `test-aggregate-findings.sh` — new test cases (FINDING_3, FINDING_9, FINDING_14 resolutions)

The existing single-call stub mechanism (`write_stub_dispatch`, controlled by `AGGREGATE_STUB_MERGE_KIND`) cannot exercise multi-phase paths. Extend with a per-call counter file using **heredoc substitution to bake the absolute counter path into the generated stub** (FINDING_11 resolution):

```bash
write_stub_dispatch_multiphase() {
    local stub="$TMP/stub-dispatch.sh"
    cat > "$stub" <<STUB_EOF
#!/usr/bin/env bash
set -euo pipefail
counter_file='$TMP/aggregate-stub-call-count'
[[ -f "\$counter_file" ]] || printf '0' > "\$counter_file"
n=\$(cat "\$counter_file")
n=\$((n + 1))
printf '%s' "\$n" > "\$counter_file"
# Use AGGREGATE_STUB_MERGE_KIND_PHASE\${n} if set, else fall back to AGGREGATE_STUB_MERGE_KIND
kind=\$(eval echo "\\\${AGGREGATE_STUB_MERGE_KIND_PHASE\${n}:-\$AGGREGATE_STUB_MERGE_KIND}")
# ... existing stub-dispatch logic gated by \$kind ...
STUB_EOF
    chmod +x "$stub"
}
```

New stub kinds:
- **`zero_findings_preamble_contradiction`** (single-call): emits short preamble like `Aggregating reviewer outputs into merged findings. We have multiple ### FINDING_N: blocks.` with zero structural blocks and no attestation token. The test runs aggregate-findings.sh ONCE and asserts: phase 1 validation rejects via the new rule (stderr contains `AGGREGATOR_VALIDATION_FAILED=preamble_finding_substring`). The test does NOT assert the final `REASON` — instead it inspects per-phase stderr.

New end-to-end multi-phase tests:
- **`waterfall_exhausted`** (3 phases): each phase's stub returns `zero_findings_preamble_contradiction`. Asserts:
  - `REASON=validation-exhausted` on stdout (FINDING_3 resolution: explicit terminal expectation).
  - `PHASES_ATTEMPTED=cursor,codex,claude` on stdout.
  - All 3 outer-phase output artifacts exist in REVIEW_TMPDIR.
  - Original `findings.md` unchanged (input findings survive).
  - Execution-issues.md gets exactly ONE warning entry (consolidated), not three (FINDING_13 resolution).
- **`waterfall_recover_on_phase2`** (2 phases): phase 1 emits `zero_findings_preamble_contradiction`; phase 2 emits valid merged output. Asserts:
  - `REASON=ok` on stdout.
  - `PHASES_ATTEMPTED=cursor,codex` on stdout.
  - `findings.md` replaced with merged output (1+ FINDING blocks).
  - No execution-issues.md warning entry (recoverable failure suppressed per FINDING_13).
- **`waterfall_skip_unavailable_external`** (FINDING_7 resolution): when CODEX_PRESENT=false, the outer phase list is `(cursor claude)` (codex skipped). Asserts:
  - `PHASES_ATTEMPTED=cursor,claude` after Cursor phase fails.
  - Outer-phase accounting matches the actual tool that ran.

New negative-prose regression test (FINDING_14 resolution):
- **`empty_merge_negative_finding_prose`** (single-call): emits prose like `No \`### FINDING_\` blocks were emitted because all inputs were duplicates.` followed by `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED`. The substring `### FINDING_` IS present in the output. Document the chosen behavior: this case CURRENTLY falls under the rule's broad reading (substring present → reject). The test asserts whichever behavior is implemented; if the breadth is accepted, the test documents it and operators can rephrase. If a polarity-aware exception is added later (separate change), the test is updated. **For this PR, accept the broad rule** — the proportionality argument from FINDING_14's voters supports keeping it simple.

Existing tests (`zero_findings_no_attest`, `zero_findings_impure_attest`, `zero_findings_nonconforming_heading`, `zero_findings_nospace_pseudo_heading`, `zero_findings_prose_finding_ids`, `empty_merge_existing_token_passthrough`, `zero_findings_padded_attest`, `merge_plus_spurious_attest`) continue to pass unchanged because the narrow trigger (FINDING_12 resolution) doesn't affect them.

### 4. `review-core.sh` — short-circuit mirroring full panel-failed envelope (FINDING_2 resolution)

After the existing `aggregate-findings.sh` invocation (current lines 504-512), parse `REASON` from `$aggregate_out`. When `REASON=validation-exhausted`, mirror the full `panel-failed` short-circuit at lines 386-429:

```bash
aggregate_reason=$(kv_get "$aggregate_out" REASON)
if [[ "$aggregate_reason" == "validation-exhausted" ]]; then
    agg_exhausted_tally="$REVIEW_TMPDIR/review-core-aggregator-exhausted-tally.env"
    agg_exhausted_emit_out="$REVIEW_TMPDIR/review-core-aggregator-exhausted-emit.env"
    : > "$REVIEW_TMPDIR/accepted-findings.md"
    : > "$REVIEW_TMPDIR/rejected-findings.md"
    : > "$REVIEW_TMPDIR/oos-accepted-review.md"
    cat > "$agg_exhausted_tally" <<EOF
ACCEPTED_COUNT=0
REJECTED_COUNT=0
EXONERATED_COUNT=0
NEUTRAL_COUNT=0
EOF
    agg_exhausted_emit_args=(
        --tally-file "$agg_exhausted_tally"
        --accepted-findings-file "$REVIEW_TMPDIR/accepted-findings.md"
        --oos-file "$REVIEW_TMPDIR/oos.md"
        --review-tmpdir "$REVIEW_TMPDIR"
        --round "$ROUND_NUM"
        --mode "$MODE"
        --scout-status "$scout_status"
        --dynamic-slots "$dynamic_slots"
        --static-slot-count "$static_slot_count"
    )
    [[ -n "$SESSION_ENV_PATH" ]] && agg_exhausted_emit_args+=(--session-env-path "$SESSION_ENV_PATH")
    [[ -n "${IMPLEMENT_TMPDIR:-}" ]] && agg_exhausted_emit_args+=(--implement-tmpdir "$IMPLEMENT_TMPDIR")
    if emit_tally_with_failure_isolation "5" "aggregator-validation-exhausted" "$agg_exhausted_emit_out" "${agg_exhausted_emit_args[@]}"; then
        copy_to_parent "$REVIEW_TMPDIR/rejected-findings.md" rejected-findings.md
        copy_to_parent "$REVIEW_TMPDIR/oos-accepted-review.md" oos-accepted-review.md
    fi
    flush_round_log
    emit_kv REVIEW_CORE_STATUS aggregator-validation-exhausted
    emit_kv ROUND_NUM "$ROUND_NUM"
    emit_kv ACCEPTED_COUNT 0
    emit_kv REJECTED_COUNT 0
    emit_kv EXONERATED_COUNT 0
    emit_kv NEUTRAL_COUNT 0
    emit_kv OUT_OF_SCOPE_DRIFT_COUNT 0
    emit_kv FINDINGS_FILE "$REVIEW_TMPDIR/findings.md"
    emit_kv ACCEPTED_FINDINGS_FILE "$REVIEW_TMPDIR/accepted-findings.md"
    emit_kv REJECTED_FINDINGS_FILE "$REVIEW_TMPDIR/rejected-findings.md"
    emit_kv PANEL_MODE "$panel_mode"
    emit_kv PANEL_SHAPE "$panel_shape"
    exit 2
fi
```

This is byte-faithful to the existing `panel-failed` envelope except for the failure label (`aggregator-validation-exhausted` instead of `panel-failed`) and the `REVIEW_CORE_STATUS` value.

## Edge cases

- **Phase 1 succeeds (common path)**: behaves exactly like today. Single dispatch, single validation, exit 0 with `REASON=ok`. `PHASES_ATTEMPTED` key NOT emitted (single-phase happy path keeps stdout shape stable).
- **Phase 1 fails the new substring-rejection rule, phase 2 succeeds**: `REASON=ok`, `PHASES_ATTEMPTED=cursor,codex`. No execution-issues.md warning (recoverable).
- **All 3 phases fail the substring-rejection rule**: `REASON=validation-exhausted`, `PHASES_ATTEMPTED=cursor,codex,claude`. ONE consolidated execution-issues.md warning. findings.md unchanged. review-core.sh short-circuits with the panel-failed-shaped envelope.
- **Phase 1 fails for a DIFFERENT reason (not substring-rejection)**: exit immediately with `REASON=validation-failed` (or `dispatch-failed`, etc.) as today. Waterfall does NOT fire. This is the narrow-trigger contract from FINDING_12.
- **CODEX_PRESENT=false**: outer phase list is `(cursor claude)`. `PHASES_ATTEMPTED=cursor,claude` after both fail.
- **CURSOR_PRESENT=false and CODEX_PRESENT=false**: outer phase list is `(claude)`. Single Claude attempt. No waterfall.
- **Dispatcher internal Claude fallback during outer Cursor phase**: `ALL_OUTPUT_TOOLS` reports `claude` instead of `cursor` → outer loop treats Cursor phase as failed, moves to outer Codex phase. Outer-phase accounting stays truthful.
- **`LARCH_AGGREGATOR_DISABLED=1`**: unchanged — pass-through with `REASON=disabled`.
- **`INPUT_COUNT < 2`**: unchanged — pass-through with `REASON=insufficient-input`.

## Failure modes

1. **Per-phase loop exceeds 3 iterations**: literal phase list `(cursor codex claude)` capped at length 3. Mitigated by construction.
2. **`ALL_OUTPUT_TOOLS` inspection detects internal fallback on every outer phase**: outer loop exits with `validation-exhausted` after trying all 3 outer phases. Diagnostic clarity preserved via `PHASES_ATTEMPTED` and per-phase output files.
3. **review-core.sh short-circuit skipped due to stdout parse error**: `kv_get` returning empty would fall through into voting on the unchanged findings.md (current behavior). The 28 raw findings would still go to voting — tolerable degradation, not silent destruction.
4. **Substring rule false-positive on negative prose**: documented breadth (FINDING_14); operators can rephrase aggregator-prompt output if it becomes recurrent. Future polarity-aware narrowing tracked separately.
