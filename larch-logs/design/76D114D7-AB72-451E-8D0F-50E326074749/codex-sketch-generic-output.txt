I’d keep the new behavior owned by [aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.sh). Today it dispatches one Cursor aggregation attempt, then runs the embedded Python validator/attestation repair. The implementation should wrap that dispatch-plus-repair-plus-validation sequence in a phase loop: `cursor`, then `codex`, then `claude`, stopping on the first validated candidate. `dispatch-with-waterfall.sh` should stay unchanged; the aggregator can build a one-slot manifest per attempt and force the intended phase using the existing dispatcher API. The Claude phase needs care because the slot schema only accepts `cursor|codex`, so it likely has to be expressed by causing the single slot to reach the existing phase3 fallback path rather than adding `tool=claude`.

Files to modify would be [aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.sh), [aggregate-findings.md](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.md), [test-aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/test-aggregate-findings.sh), [review-core.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/review-core.sh), [review-implement-step5-loop.sh](<OPERATOR_REPO_PATH>/skills/review-and-fix/scripts/review-implement-step5-loop.sh), and [SKILL.md](<OPERATOR_REPO_PATH>/skills/implement/SKILL.md). `aggregate-findings.sh` gets `PHASES_ATTEMPTED`, the raw `### FINDING_` substring rejection when `output_blocks()==0`, and the exhausted token. `review-core.sh` needs to treat that token as a hard round failure instead of continuing into voting with a stale/unmerged ballot. `review-implement-step5-loop.sh` should route the resulting review-and-fix status to `STALL_REASON=aggregator-validation-exhausted`, and the implement skill docs need the new stall row/category.

Main risks are preserving the current empty-merge repair behavior and not accidentally making clean zero-finding outputs fail. The new substring rule is intentionally broad, so it must run only when there are zero structural output blocks and raw output contains literal `### FINDING_`; existing cases like `zero_findings_no_attest`, padded/existing attestation, and `### FINDING_ids` need to keep passing. The waterfall loop also needs clean per-phase output paths/logs so diagnostics do not overwrite each other, while keeping the existing stdout contract additive only. I did not modify files.
