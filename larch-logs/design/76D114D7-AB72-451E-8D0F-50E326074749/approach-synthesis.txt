## Approach Synthesis

Both Cursor-Generic and Codex-Generic sketches converged on the same architecture without contested points.

### Shared agreements (both sketches)

- **Locus**: retry logic stays inside `aggregate-findings.sh`. The script wraps its existing dispatch+repair+validation sequence in a per-phase loop. `dispatch-with-waterfall.sh` stays unchanged.
- **Files to modify**: `aggregate-findings.sh`, `aggregate-findings.md` (sibling contract), `test-aggregate-findings.sh`, `skills/review/scripts/review-core.sh`, `skills/review-and-fix/scripts/review-and-fix.sh`, `skills/review-and-fix/scripts/review-implement-step5-loop.sh`, `skills/implement/SKILL.md` (Step 5 stall-reason table).
- **review-core.sh short-circuit is required**: today it ignores `aggregate_rc` (only breadcrumbs to execution-issues.md) and continues into voting regardless. For the exhausted-aggregator path to surface as a distinct STALL_REASON, review-core.sh must actively detect the exhausted signal and short-circuit (mirroring its existing `panel-failed` short-circuit at line 416).
- **review-and-fix.sh exit_code=2 path**: mirror `panel-failed` — a new case in the `core_status` switch sets `status=$core_status`, `exit_code=2`.
- **New validator check**: when `output_blocks() == 0` AND raw output text contains the substring `### FINDING_` anywhere (raw bytes, not just heading position), reject. The zero-blocks guard prevents false positives on legitimate merged outputs.
- **Don't break existing tests**: `zero_findings_no_attest` (#2563), `zero_findings_impure_attest`, `zero_findings_nonconforming_heading`, `zero_findings_nospace_pseudo_heading`, `zero_findings_prose_finding_ids`, `empty_merge_existing_token_passthrough`, `zero_findings_padded_attest` (#2536), and `merge_plus_spurious_attest` must continue to pass.

### Mechanism for forcing single-phase dispatch per call

Codex-Generic raised the question: dispatch-with-waterfall.sh's slot manifest only accepts `tool=cursor|codex`, so "Claude phase 3" must be expressed by manipulating presence flags. Resolution:

- **Phase 1 (Cursor)**: slot `tool=cursor`, `--cursor-present true --codex-present false` → dispatch fires Cursor only (phase 1 of the dispatcher's own internal waterfall).
- **Phase 2 (Codex)**: slot `tool=codex`, `--cursor-present false --codex-present true` → dispatch fires Codex only.
- **Phase 3 (Claude)**: slot `tool=cursor`, `--cursor-present false --codex-present false` → dispatch falls through to its phase3 Claude subprocess fallback.

Each invocation of dispatch-with-waterfall.sh produces exactly one phase of the aggregator's validation-driven waterfall.

### Stdout contract changes

- New REASON value: `validation-exhausted` (joins existing values `disabled` | `insufficient-input` | `dispatch-failed` | `validation-failed` | `ok`).
- New additive key: `PHASES_ATTEMPTED=<comma-list>` (e.g., `PHASES_ATTEMPTED=cursor,codex,claude`). Emitted when more than one phase ran.
- Existing keys (AGGREGATED, INPUT_COUNT, MERGED_COUNT, FAILURE_LOG) unchanged.

### Per-phase output preservation

Keep `aggregator-output.txt.phase1` / `.phase2` / `.phase3` in REVIEW_TMPDIR for investigation (this naming is already produced by dispatch-with-waterfall.sh's `output_for_phase` helper). The final `aggregator-output.txt` reflects the last-attempted phase's output so existing tests that read this file continue to work. On a successful merge in phase N, copy the validated/repaired candidate back into `aggregator-output.txt` (this matches existing behavior).

### Risks called out

- **Substring rule false positives**: rule must be guarded by `output_blocks() == 0` AND substring check must look for `### FINDING_` (with the `_` underscore) rather than just `FINDING_`. Prose like `### FINDING_ids` (no digit) must continue to NOT suppress synthesis on the existing `zero_findings_prose_finding_ids` test path.
- **Token cost**: 3× aggregator invocations on full waterfall exhaustion (Cursor + Codex + Claude). Acceptable per the user's confirmation; no opt-out env var.
- **Diagnostic clarity**: per-phase output files plus PHASES_ATTEMPTED stdout key keep operator investigation straightforward.

No contested decisions — both sketches agreed on all architectural points.
