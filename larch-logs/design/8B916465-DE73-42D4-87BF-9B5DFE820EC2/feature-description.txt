# /design and /implement final-summary Gantt charts dropped: marker body emitted via tool call instead of plain chat text

## Context

`/design` and `/implement` both extract the final-summary block from the background task output using `LARCH_FINAL_SUMMARY_BEGIN` / `LARCH_FINAL_SUMMARY_END` markers and are required to **emit that body verbatim as plain chat markdown**. The `## Review Phase Detail` section — including the round-by-round acceptance table and the per-round ASCII Gantt charts — lives inside those markers.

## Symptoms

In the session that produced run `6C2A7323-AFCF-420C-9B83-37FA68DE131D`, the user saw only the top-level bullet list:

```
- **Duration**: 08:17:15
- **Cost**: ...
- **Plan review**: 17 accepted ...
- **OOS filed**: ...
```

The `## Review Phase Detail` section (round table + five Gantt charts) was absent from the visible output. The user explicitly asked "why were these not printed as part of the final report?", confirming the omission was user-visible.

## Root cause

The SKILL.md instruction is:

> "Extract the final-summary body from the completed `design-step5c.sh` task output using the first balanced `LARCH_FINAL_SUMMARY_BEGIN` / `LARCH_FINAL_SUMMARY_END` whole-line marker pair and emit that body verbatim as plain chat markdown."

The orchestrator violated this by:

1. Running a `python3 -` Bash tool call to extract the content between the markers and print it — this puts the content in **tool output** (collapsible, not always visible to the user).
2. Then writing a **separate condensed text message** that only reproduced the top-level bullets, omitting the entire `## Review Phase Detail` section.

The phrase "emit that body verbatim as plain chat markdown" means the extracted content must appear in the orchestrator's **text output** — not in a tool call's stdout. Tool output is rendered in a separate collapsible block in the Claude Code UI, so users who do not expand tool results miss all content inside it.

The same failure mode applies to `/implement`, which has an identical marker-extraction + emit contract for its final summary (shipped via `render-final-summary.sh` inside the implement wrapper).

## Reproduction

Run `/design` or `/implement` on any issue. After the Step 5c / Step 18b background task completes, observe whether the full `## Review Phase Detail` section (round table + Gantt charts) appears in visible chat text or only inside a collapsed tool result.

The failure is latent whenever the orchestrator uses a Bash or Python tool call to extract and print the marker-delimited body instead of reading it inline and writing it as chat text.

## Suggested fix

### 1. Strengthen the SKILL.md instruction (both `/design` and `/implement`)

Add an explicit prohibition alongside the existing "emit verbatim as plain chat markdown" instruction:

> **Do NOT use a Bash tool call, Python script, or any other tool invocation to print the final-summary body. Use the Read tool to read the task output file, locate the markers in the returned text, and write the extracted body directly as orchestrator text output.**

This makes the delivery channel unambiguous. "plain chat markdown" is not self-evident about tool calls; the prohibition must be explicit.

### 2. Add a structural pin in `test-design-structure.sh` and `test-implement-structure.sh`

Add an assertion that `LARCH_FINAL_SUMMARY_BEGIN` does not appear inside any `bash` fence in `skills/design/SKILL.md` or `skills/implement/SKILL.md`. If the orchestrator were to correctly emit via text, the marker names would never appear in a bash fence — they are grep targets for text-side extraction, not shell commands.

### 3. Clarify the Read-tool fallback

The current fallback path says: "fall back to reading `${FINAL_SUMMARY_PATH:-$DESIGN_TMPDIR/final-summary.md}` when the file is non-empty." This is also a tool call (Read tool), but the Read tool result appears inline in the session context and can be directly echoed as text. Clarify that the Read fallback result must still be written as orchestrator text, not re-entered into another tool call.

## Affected files

- `skills/design/SKILL.md` — Step 5c item 5 emit instruction; Final summary block section
- `skills/implement/SKILL.md` — final-summary emit instruction (equivalent section)
- `scripts/test-design-structure.sh` — add LARCH_FINAL_SUMMARY_BEGIN bash-fence absence pin
- `skills/implement/scripts/test-implement-structure.sh` (if it exists) — same pin

## Acceptance

- After the fix, a `/design` run's final output in chat text contains the full `## Review Phase Detail` section with the round table and Gantt charts — not just the top-level bullets.
- After the fix, a `/implement` run's final output contains the full review phase detail (if applicable to that skill's final summary).
- `make test-design-structure` fails when a `LARCH_FINAL_SUMMARY_BEGIN` bash-fence appears in `SKILL.md`.
