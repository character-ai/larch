1. **[correctness]** `skills/upgrade-larch/scripts/upgrade-larch.sh` (prune retained-set build, plan steps 5 and Failure modes #4): The plan seeds `$ACTUAL_VERSION` then fills to `KEEP_VERSIONS=8`, but it never requires skipping versions already in the retained set. Failure mode #4 only warns against seeding *after* picking eight. If `$ACTUAL_VERSION` is already in the newest eight, a naive loop can retain nine directories. **Suggested revision:** Require dedupe while filling; extend `test-upgrade-larch-prune.sh` with a case where the install target is already in the top eight and the post-prune count is exactly eight.

2. **[correctness]** `skills/cleanup/scripts/cleanup.sh` (age scan, plan `/cleanup` steps 3–4): Newest activity is derived from `find "$entry" -mindepth 1 -maxdepth 5` plus `stat_mtime`, with no behavior when `find` fails or returns a partial tree (permissions, I/O errors). The plan’s edge cases assume a full shallow scan; on failure only the entry’s own mtime counts, so a stale root with fresh `larch-logs/implement/<RUN_ID>/round-1/findings.md` can still be deleted. **Suggested revision:** Fail closed (keep the entry) on `find` non-zero or document and test that policy; add a harness case where a fresh depth-5 artifact must preserve the parent even when `find` is forced to fail.

3. **[risk-integration]** `skills/cleanup/scripts/cleanup.sh:19-31`, `skills/cleanup/SKILL.md`: The plan drops the singleton *abort* but only says `SESSION_COUNT` “may still be emitted.” Removing `pgrep` entirely would silently emit `SESSION_COUNT=0` while the skill still tells the operator to parse it. **Suggested revision:** Keep `pgrep -x claude` solely for `emit_kv SESSION_COUNT`; delete only the `exit 1` branch; mirror that split in `cleanup.md` and `test-cleanup.sh`.
