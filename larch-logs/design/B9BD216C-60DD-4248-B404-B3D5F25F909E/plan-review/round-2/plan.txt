# Implementation Plan — #3174: age-based retention + simplified /cleanup, max-8 install-stamp prune

SIMPLE-tier design. Bias: smallest change that fixes the bug. Remove fragile machinery; do not add config or layers the issue did not ask for.

## Resolved direction (Round 1)

- `/upgrade-larch` keeps the **8 most-recently-installed** version dirs and deletes the rest. **8 is a hard maximum**, not a floor. Ordering uses a per-version install-stamp file; legacy un-stamped dirs fall back to dir mtime.
- The just-installed target is always retained. The currently-running version is retained only if it is among the 8 newest-installed (matches "fewer than 8 releases since my job started → my version survives"; a "release" = a new distinct version dir, since re-installing the same stable is idempotent and creates no new dir).
- The 7-day window applies to `/cleanup` session dirs **only** — it never deletes a top-8 version dir.
- Remove the entire active-protection apparatus: `collect_active_session_versions`, session-scan/fallback-root pins, `KEEP_LIMIT` eviction loop, Stage A (delete-newer-than-stable), and the `lib-larch-cache-touch.sh` mtime touch.
- Slim `.larch-keepalive` to an identity record (`CLONE_PATH`, `SESSION_ID` only); **keep the filename for this PR** (defer any rename to a follow-up). Drop cleanup's sentinel skip; `lib-resolve-implement-tmpdir.sh` keeps reading `.larch-keepalive`. `current-design-env-*.sh` stays untouched.

## Approach

### /upgrade-larch prune (the core fix)
1. After a verified stable install, write `$LARCH_CACHE_DIR/$ACTUAL_VERSION/.larch-installed-at` containing `date +%s` (epoch seconds). Best-effort; a write failure logs a warning but does not abort. On the already-latest path: bind the prune target explicitly (`ACTUAL_VERSION="${CURRENT_INSTALLED_VERSION:-$INSTALLED_VERSION}"`) **before** calling the shared prune helper; best-effort stamp that version; then prune without reinstalling.
2. Replace `list_cached_versions_by_mtime` with `list_cached_versions_by_install_stamp`: for each version dir, timestamp = install-stamp epoch if the stamp file is present and numeric, else dir mtime (reuse the existing dual-`stat` `stat_mtime` helper), else `0`. Sort by **stamp presence first** (stamped dirs before un-stamped fallback dirs), then timestamp **descending**, then version-string tiebreak — newest stamped installs outrank legacy un-stamped dirs whose mtimes were bumped by the removed touch helper.
3. New prune body: build the retained set by seeding `$ACTUAL_VERSION` first, then add newest entries from `list_cached_versions_by_install_stamp` until the set size is exactly `KEEP_VERSIONS=8` or the cache is exhausted; `rm -rf` the rest. This preserves the hard max of 8 while retaining the just-installed/already-current target even if the stamp write failed or fallback ordering would put it outside the first 8.
4. Delete now-unused helpers: `collect_active_session_versions`, `warn_preserved_active_version_once`, the `WARNED_ACTIVE_SESSION_VERSIONS` array, `version_gt`, `sort_versions`, the `LARCH_SESSIONS_DIR` pin usage, and `LARCH_UPGRADE_FALLBACK_SESSION_ROOTS`. Keep `is_safe_version`, `stat_mtime`, `get_stable_releases`, `get_installed_larch_version`, `list_cached_versions_*`.
5. `8` stays a plain constant (`KEEP_VERSIONS=8`); the issue requested an env override only for the age window, not the cap. Do not add a cap env var.
6. Keep the prune callable from both the verified-install path and the already-latest path so an over-cap cache is corrected even when no files are downloaded.

### /cleanup (make it runnable any time)
1. Drop the `pgrep -x claude` singleton abort entirely. With age-based reaping, a live or recently-active session has a fresh timestamp and survives, so the abort is unnecessary.
2. Drop the `.larch-keepalive` / `.larch-session` skip — deletion no longer keys on a sentinel.
3. Delete a `~/.cache/larch/sessions/*` directory (and matching `/tmp` glob dirs) when its **newest-activity** timestamp is older than `LARCH_CLEANUP_RETENTION_DAYS` (default 7). Newest-activity = `max(mtime of the dir and every file/dir under it via a bounded shallow scan: find "$entry" -mindepth 1 -maxdepth 2`, each path measured with the dual-`stat` `stat_mtime` helper) so nested live writes under `design-export/`, `larch-logs/`, `breadcrumbs/`, etc. refresh retention (APFS does not bump parent-dir mtime on child content edits). Validate the env var as a positive integer; fall back to 7 with a warning on invalid input.
4. Reap **dangling** top-level `current-design-env-*.sh` symlinks (`-L` and `! -e`). Leave live symlinks. Leave the `current-design-env` mechanism itself untouched.
5. Preserve the `emit_kv` output contract; keep a count of removed entries. `SESSION_COUNT` may still be emitted for visibility but no longer gates anything.

### Identity record slim-down (filename unchanged)
1. In `session-setup.sh`, rename `write_keepalive_sentinel` → `write_session_identity`; still write `$SESSION_TMPDIR/.larch-keepalive` with a one-line header comment plus exactly `CLONE_PATH=` and `SESSION_ID=` (drop `PID`/`PPID`/`PREFIX`/`CREATED`/`NOTE` — nothing reads them).
2. Refresh adjacent comments in `lib-resolve-implement-tmpdir.sh`, `hook-stop-fail-close.sh`, and `sessionstart-health.sh` to describe `.larch-keepalive` as a slim session-identity record (not a cleanup-protection sentinel). **No resolver read-path or fallback logic changes** — filename stays `.larch-keepalive` for this PR.
3. Update test fixtures that write the sentinel directly to the slim two-field shape.

### Touch removal
Remove the `source lib-larch-cache-touch.sh` + `larch_touch_executing_cache_root ...` pair from `session-setup.sh`, `write-session-env.sh`, and `write-design-current-env.sh`. Delete `scripts/lib-larch-cache-touch.sh` and its `.md` sibling. Retention no longer keys on mtime, so the touch has no consumer.

## Edge cases

- Cache with fewer than 8 version dirs: keep all, delete none.
- Exactly 8: keep all.
- More than 8 all stamped: keep the 8 newest by stamp.
- More than 8 where `$ACTUAL_VERSION` would otherwise sort outside the first 8: keep `$ACTUAL_VERSION` plus the newest remaining entries until exactly 8 remain.
- Mixed stamped / un-stamped: **all stamped dirs sort before any un-stamped dir** regardless of mtime; within each tier sort by timestamp descending; unreadable timestamp sorts as `0` (least protected).
- Just-installed stamp write fails: still retained via the explicit seeded-`$ACTUAL_VERSION` invariant, without increasing retained count above 8.
- Already-latest install path with cache over cap: bind `ACTUAL_VERSION` from installed metadata first; no reinstall, but prune still runs and leaves at most 8 dirs with the current version seeded.
- `/cleanup` active session: a freshly-written child file keeps newest-activity inside the window → dir kept.
- `/cleanup` APFS dir whose own mtime is stale but a child or depth-2 grandchild (e.g. under `design-export/`) was just edited: kept (bounded recursive newest-activity keying).
- `/cleanup` dangling `current-design-env-*.sh` symlink reaped; live symlink kept.
- `/cleanup` with multiple `claude` processes: runs normally (abort removed).
- Invalid `LARCH_CLEANUP_RETENTION_DAYS`: fall back to 7 with a warning.

## Failure modes

1. **Identity-record shape desync.** If `session-setup.sh` slims fields but resolver parsing assumptions drift, `/implement` Stop/SessionStart hooks stop binding. Earliest signal: `test-keepalive-sentinel` / sessionstart-health harness failures. Mitigation: writer + comment refresh + all sentinel-writing test fixtures in the same PR; **no filename change** this PR to avoid compatibility churn.
2. **Self-deletion of the running version.** If `/upgrade-larch` runs from a version outside the 8-newest-installed, that dir is pruned; concurrent jobs on it lose their dir. Signal: a "version blown away" report for a very old running version. Mitigation: just-installed always kept; running version kept iff in the newest-8 (matches the user's "<8 releases" expectation); `rm` of an open inode does not kill the running process, and the user restarts post-upgrade. Documented tradeoff, accepted in Round 1.
3. **Legacy-dir mtime mis-ordering during migration.** Pre-feature dirs whose mtime was bumped by the now-removed touch may briefly sort high among un-stamped dirs. Signal: a touched old un-stamped version consuming an un-stamped slot. Mitigation: stamp-presence-first sort ensures stamped installs always outrank un-stamped legacy dirs; every `/upgrade-larch` install writes a stamp; mtime fallback only affects un-stamped legacy dirs, which age out. Low impact.
4. **Retained-set off-by-one.** Seeding `$ACTUAL_VERSION` after selecting the first 8 can leave 9 dirs. Mitigation: seed first, then fill to `KEEP_VERSIONS`, and assert exactly 8 remain in the target-outside-top-8/stamp-failure test.
5. **Already-latest prune with unset target.** If the already-latest path calls prune before binding the installed version, the current version may not be seeded. Mitigation: assign `ACTUAL_VERSION` from `CURRENT_INSTALLED_VERSION` immediately before the shared prune call; cover in prune harness.
