### FINDING_1: maxdepth-4 cleanup scan misses depth-5 round artifacts
- **Reviewer(s)**: Cursor-Arch, Codex-Arch, Cursor-Edge, Cursor-Pragmatic, Codex-Edge, Cursor-Innovation, Codex-Innovation, Codex-Pragmatic, Cursor-Requirements, Codex-Requirements, Cursor-dyn-caller-inventory, Codex-dyn-caller-inventory, Cursor-dyn-depth-alignment, Codex-dyn-depth-alignment
- **Severity**: important
- **Concern**: The planned cleanup activity scan uses `find -maxdepth 4`, but run-log round artifacts such as `larch-logs/implement/<RUN_ID>/round-<N>/findings.md` are depth 5 from the session root. If only those round files are refreshed during a long-running `/implement` session, especially on APFS where parent directory mtimes may not update on child edits, cleanup can misclassify an active session as stale and delete it. The plan and proposed tests also appear to claim depth-5 round artifacts are protected while allowing shallower depth-4 manifest coverage, which could miss the boundary failure.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Raise the bounded scan to maxdepth 5 (or document manifest-only retention and drop the round-<N>/findings.md harness/edge-case). Reconcile the depth rationale in the plan and cleanup.md with docs/run-logs.md path shapes.
  - From Codex-Arch: Use maxdepth 5 for the session activity scan and make the cleanup harness assert a fresh round-1/findings.md case, not only manifest.json
  - From Cursor-Edge, Cursor-Pragmatic: Raise the bounded scan to `-maxdepth 5` (or document that retention relies on tmpdir-root `round-<N>/` writes and drop the `larch-logs/.../round-*` test claim). Align failure-mode #6 and edge-case bullets with the chosen depth.
  - From Codex-Edge: Use maxdepth 5 or otherwise explicitly include larch-logs/*/*/round-*/* in newest-activity, and make test-cleanup.sh assert a stale ancestor plus fresh larch-logs/implement/<RUN_ID>/round-1/findings.md case rather than only manifest.json.
  - From Cursor-Innovation, Codex-Innovation: Change the cleanup scan to maxdepth 5 or add a targeted round-* file scan, and update the plan/tests to match.
  - From Codex-Pragmatic: Raise the cleanup scan/test contract to maxdepth 5 or explicitly include the round artifact path depth, and keep the manifest case as separate depth-4 coverage
  - From Cursor-Requirements, Codex-Requirements: Change the cleanup scan and tests to maxdepth 5, or narrow the acceptance criteria to only paths reachable at maxdepth 4 such as larch-logs/implement/<RUN_ID>/manifest.json
  - From Cursor-dyn-caller-inventory, Codex-dyn-caller-inventory: Use maxdepth 5 if round-<N> files are part of the retention contract, or narrow the contract/tests to depth-4 manifest.json only
  - From Cursor-dyn-depth-alignment, Codex-dyn-depth-alignment: Use maxdepth 5 if round files must be protected, and require test-cleanup.sh to set freshness only on larch-logs/implement/<RUN_ID>/round-1/findings.md for the boundary case. Alternatively keep maxdepth 4 but remove the round-<N>/findings.md protection claim.
