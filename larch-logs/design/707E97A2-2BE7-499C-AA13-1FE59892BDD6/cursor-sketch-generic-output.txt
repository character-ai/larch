# Cursor-Generic slot — filled by Claude subagent fallback after Cursor returned only narrative-only stubs twice in a row (logged under Warnings).

**1. Key architectural decisions and approach.** The pause flag propagates via two equally-authoritative file sentinels written by `/larch:pause`: `$DESIGN_TMPDIR/.pause-requested` (preferred, located via `~/.cache/larch/sessions/current-design-env-$PPID.sh` so the skill can `source` it and read `DESIGN_TMPDIR`) and a parallel `~/.cache/larch/sessions/pause-requested-<ISSUE>.flag` (machine-wide fallback when the env symlink is stale). Each contains a single timestamp line — no payload, since all real state goes to GitHub. `/design`'s SKILL.md gains an "**Anti-halt continuation reminder**"-adjacent **Pause-check** rule: a single shell oneliner `[ -f "$DESIGN_TMPDIR/.pause-requested" ] && exec "$CLAUDE_PLUGIN_ROOT/scripts/design-pause-save.sh" --design-tmpdir "$DESIGN_TMPDIR" --issue "$ISSUE" --reason user` is appended to the canonical Bash-block prelude so it fires on *every* between-Bash boundary from Step 1c onward without altering any step body. `design-pause-save.sh` (a) `touch $DESIGN_TMPDIR/.pause-in-progress` (used by `.pause-requested` consumers to ignore double-fires), (b) writes a tiny `pause-state.txt` into `$DESIGN_TMPDIR` containing `STEP=<derived>`, `SESSION_ID`, `RUN_ID`, `TIER` (read from `run-params.json`), `BRAINSTORM_DONE=<bool>`, `BODY_HASH=<sha256 of current issue body>`, `PAUSED_AT=<ISO8601>` — where `STEP` is computed by reading the highest-named completed sentinel under `$DESIGN_TMPDIR/.completed/` and mapping it through `step-name-registry.tsv` to the *next* unfinished step ID, (c) invokes `design-log-publish.sh --reason pause` (new flag) which differs from end-of-design only in commit subject (`chore(larch-logs): pause design run ${RUN_ID} [skip ci]`), an extra `paused=true` field appended to `manifest.json`, and an idempotent overwrite of an already-published `RUN_ID` (publish-on-pause is a *snapshot*, not a finalize), (d) writes a redacted `pause-state.txt` (piped through `scripts/redact-secrets.sh` first, mandatory) through a **new** `scripts/named-block-write.sh --marker design-pause` against the issue, and (e) leaves the tracking-issue title at `[DESIGNING]` (no `rename` call). `named-block-write.sh` is factored from `plan-block-write.sh` by parameterizing the four module-level constants (`MARK_START`/`MARK_END`/`CANON_START`/`CANON_END`) on a `--marker NAME` flag and renaming `plan_block_classify_current()`/`PB_*` vars to `block_classify_current()`/`NB_*`; the original `plan-block-write.sh` is rewritten as a 5-line thin wrapper that just calls `named-block-write.sh --marker plan "$@"` so the existing CLI surface and `BODY_BYTES`/`MARKERS_PRESENT`/`MODE` stdout contract are preserved bit-for-bit. `design-driver.sh`'s `--resume-from` already supports the four ACTION names; the change adds a parallel `step_id`-keyed branch keying off `normalize_step` of step IDs like `1c`/`1d`/`2a`/`3.5`/`4b`, by treating any value matching `^[0-9]+[a-z]?(\.[0-9]+)?$` as a step-id and consulting `.completed/$step_id` sentinels written by a new convention (Step Nc start emits `: > "$DESIGN_TMPDIR/.completed/step-1c-entered"` etc., already partially in place via `.brainstorm-done`/`.step3-entry-plan-printed`). `/larch:pause` is `~30` lines: `source` the PID-keyed env symlink, fail-fast if no live session, `touch` the two sentinels, print a single-line breadcrumb. Resume detection lives in `/design`'s Step 0b: after `session-setup.sh` allocates the *fresh* `$DESIGN_TMPDIR`, a new sub-step calls `scripts/design-pause-load.sh --issue $ISSUE` which reads the issue body via `gh`, greps for `<!-- larch:design-pause:start -->`, on hit (a) verifies `BODY_HASH` against the body with the marker block stripped — mismatch emits `WARN=body-drift` but still proceeds (per constraint #8 the marker wins), (b) fetches the latest `larch-logs/design/<RUN_ID>/` tree via `git fetch origin` + `git show origin/<default>:larch-logs/design/<RUN_ID>/*` into the freshly allocated `$DESIGN_TMPDIR`, (c) atomically removes the marker block (via `named-block-write.sh --marker design-pause --content-file /dev/null` — the new script treats empty content + `present` classification as **delete**, returning `MODE=removed`), (d) exports `LARCH_DESIGN_RESUME_FROM=$STEP` and routes `/design` to call `design-driver.sh --resume-from "$STEP"`.

**3. Top 3 risks with mitigations.**
- **Risk A — partial-state from a crash between `design-log-publish.sh --reason pause` and the issue-body marker write.** Mitigation: write order is **publish first, then issue-body marker** (publish is idempotent on the same `RUN_ID`; the marker is the atomic commit point). If the marker write fails, the published log branch is harmless — Step 0b's resume detection keys only on the issue marker, so a missing marker means "no pause occurred". `design-pause-save.sh` emits `PAUSE_OK=false` and routes failure through `append-tool-failure.sh` so the user sees it, and the in-progress `.pause-in-progress` sentinel is removed only on full success — its presence on next run is a hint to the user that the previous pause was incomplete.
- **Risk B — `design-log-publish.sh` PR-merge being blocked (e.g., admin merge disabled, branch protection drift) prevents a clean pause snapshot.** Mitigation: reuse the existing `RECOVERY_BRANCH=` emission already in `design-log-publish.sh`; on pause-save, if `PUBLISH_OK=false` but `RECOVERY_BRANCH` is set, still write the issue marker but record `LOG_RECOVERY_BRANCH=<name>` *inside* the marker block so `design-pause-load.sh` can fetch from the recovery branch instead of `origin/<default>`. This degrades gracefully without blocking the pause itself.
- **Risk C — in-flight Bash tools that don't honor the sentinel between exit and next Bash call (long-running externals, parallel Family A collectors, dialectic launches).** Mitigation: accept this as the documented "worst-case one step of lost work" per constraint #3 — the sentinel check runs only at Bash-tool boundaries, not mid-tool. To minimize blast radius, treat the externally-launched lanes per constraint #5 (abandon and re-launch on resume); document in the new pause SKILL.md that pause requested during a 20-minute reviewer wave will fire only when that wave's collector returns. Additionally, `design-pause-save.sh` records the step-of-pause as the *step that was about to start* (next unfinished sentinel), not the in-flight step, so resume restarts that step cleanly rather than trying to mid-resume an abandoned external. A secondary minor risk — `BODY_HASH` mismatch causing user confusion — is mitigated by emitting a clear `**⚠ Issue body changed since pause — resuming anyway**` breadcrumb (per constraint #8) rather than failing.
