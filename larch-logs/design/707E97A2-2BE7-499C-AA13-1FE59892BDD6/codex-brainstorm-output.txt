1. **Lean: Pause Snapshot Only**
This scope persists a pause record only when the user explicitly interrupts `/design` and says “pause.” The record captures run identity, current phase/step, run parameters, issue metadata, and a redacted bundle of only the artifacts needed to resume at the nearest safe boundary. It gains a smaller persistence surface and avoids continuously publishing intermediate state, but it costs precision for “pause anywhere” because mid-step work may be replayed or discarded. It explicitly excludes streaming every artifact write, strict mid-command continuation, and reuse by `/implement` or `/review` beyond shaping the helper names generically.

2. **Checkpointed Anywhere Resume**
This scope treats pause as available anywhere, but resume lands at the last completed checkpoint rather than the exact interrupted instruction. `/design` writes or refreshes issue-backed checkpoints at major step boundaries and on explicit pause; in-flight external reviewers are abandoned and relaunched from the last coherent checkpoint. It gains practical reliability while satisfying user-initiated pause from any visible point, but it may repeat expensive reviewer/sketch work after interruption. It explicitly excludes exact restoration of subprocess state, live external reviewer continuation, and per-artifact durability between checkpoints.

3. **Issue Body + Comment Artifact Bundle**
This scope stores a compact resume marker in the issue body and spills larger redacted artifacts into one or more structured issue comments. The body marker remains the auto-detect entrypoint for `/design <N>`, while comments carry versioned artifact manifests and chunked content when the 65 KB body limit is risky. It gains full GitHub-native cross-session restore without requiring branches, gists, or local disk, but it costs more machinery around comment discovery, updates, chunking, and stale comment handling. It explicitly excludes using `larch-logs/design/...` as the source of truth and excludes publishing every transient temp file unless it is part of the pause manifest.

4. **Log-Branch Backed Restore**
This scope uses the issue body as the authoritative resume pointer, but stores the redacted tempdir snapshot under the existing `larch-logs/design/<RUN_ID>/` publishing path. Resume reconstructs `$DESIGN_TMPDIR` from that committed artifact bundle, then lets `design-driver.sh --resume-from` or a broader equivalent continue. It gains room for large artifacts and aligns with existing log publishing behavior, but it costs more coupling to git worktree/publish mechanics and makes “state lives in the issue” true only by pointer, not by full payload. It explicitly excludes issue-comment chunk storage and excludes making local tempdir retention part of correctness.

5. **Generic Save/Restore Helper, Design-Only Adoption**
This scope builds a shared pause helper API with named block read/write, redaction, manifesting, artifact packing, and restore primitives, but wires only `/design` to it in this issue. The helper is shaped so `/implement` and `/review` can adopt later, including stable marker names, schema versioning, and conflict warnings, but no behavior changes ship for those workflows now. It gains future reuse without expanding the current acceptance surface, but it costs some upfront abstraction work before there is a second adopter. It explicitly excludes implementing `/implement` or `/review` pause/resume, and excludes a full lifecycle SDK with callbacks for every workflow phase.

6. **Strict Full-Fidelity Restore**
This scope persists enough state to rebuild the temp directory and resume with minimal re-derivation across unbounded pause/resume cycles, including artifact manifests, run params, token ledger, review outputs, synthesis files, and explicit invalidation rules for abandoned externals. Auto-detect resume reads the issue marker, warns on concurrent edits, reconstructs the run, and continues from a precise recorded state machine location where possible. It gains the strongest user experience and the least repeated work, but it costs the most schema design, storage management, validation, migration, and edge-case handling. It explicitly excludes continuing already-running external reviewers after pause, and still excludes guaranteeing byte-for-byte restoration of live shell/process state.
