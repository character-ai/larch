## Findings

1. **[correctness]** `plan.txt:80` — Edge case claims `named-block-write.sh` inherits `gh issue edit` retry logic from `plan-block-write.sh`, but the current writer has a single attempt (`scripts/plan-block-write.sh:213-216`) with no retry loop. Operators may expect transient rate-limit recovery that does not exist.

2. **[correctness]** `plan.txt:11,48` vs `scripts/plan-block-write.sh:169-197` — “Bit-for-bit” preservation of the stdout contract is undermined if `named-block-write.sh` implements `MODE=removed` for `/dev/null` (or “empty” content) when markers are present: today that path produces `MODE=replaced` with an empty inner block, not deletion. The thin `exec` wrapper would forward `/dev/null` and change observable `MODE=` for any caller that ever uses it on `plan-block-write.sh`.

3. **[correctness]** `plan.txt:23,26` — Delete semantics say “`--content-file` is empty **or** `/dev/null`” without defining whether a zero-byte regular file counts. Treating any empty file as delete would make Step 5c (`composed-plan.redacted.md` accidentally empty) delete the `larch:plan` block instead of writing an empty block; the plan should pin delete to `/dev/null` only (or an explicit flag).

4. **[correctness]** `plan.txt:26` — Contract doc says “four malformed exit conditions”; `plan-block-write.sh` emits **five** tokens (`multiple-start`, `multiple-end`, `start-without-end`, `end-without-start`, `end-before-start` at `scripts/plan-block-write.sh:90-110`). `scripts/test-plan-block.sh` exercises all five; under-documenting risks dropping `end-before-start` in the extraction.

5. **[security]** `plan.txt:21-23` — `--marker NAME` is interpolated into `grep -E` patterns (`scripts/plan-block-write.sh:20-21` style) with no stated allowlist. Values containing regex metacharacters (`.`, `+`, etc.) could mis-classify bodies or match wrong lines; restrict markers to `^[a-z0-9][a-z0-9-]*$` (covers `plan` and `design-pause`).

6. **[architecture]** `plan.txt:33-34` vs `scripts/plan-block-read.sh:20-21` — `design-pause-load.sh` will hand-parse `<!-- larch:design-pause:… -->` via `gh issue view` instead of reusing shared classify/extract logic. Marker-boundary drift vs `named-block-write.sh` (whitespace-tolerant regex) can cause `BODY_HASH` mismatch or failed resume; consider `named-block-read.sh --marker design-pause` or shared classify sourced from the write primitive.

7. **[risk-integration]** `plan.txt:92` — Testing strategy says the pause harness is “Registered in `Makefile`”, but `### Files to modify/create` has no `Makefile` entry. Without a `test-design-pause-resume` target on a `test-harnesses-N` shard, CI will not run cases (c)–(f) including `/dev/null` → `MODE=removed`.

8. **[nit]** `plan.txt:48` — After `exec` to `named-block-write.sh`, stderr/usage strings will say `named-block-write.sh` instead of `plan-block-write.sh` (`scripts/plan-block-write.sh:123,133-137`). Callers/tests only grep stdout KV lines today; still a debugging ergonomics change worth noting in `scripts/plan-block-write.md`.
