# Claude pragmatic-lens brainstorm — smallest-viable shippable slices

Each slice below honors all 9 Round-1 user-resolved decisions, then asks: what is the leanest thing that ships? Each slice names the risk if we cut too far.

## Slice A — "Pointer block + log-publish branch as the durable store"

Pause writes only a small `larch:design-pause` marker block to the issue body containing: step pointer (e.g., `STEP=2a:waiting-for-cursor-sketch`), `SESSION_ID`, current `[DESIGNING]` rename guard, and a content-hash of the issue body at pause time (for the warn-but-proceed concurrent-edits check). Bulk artifacts (sketches, plan.txt, reviewer outputs, run-params.json) are pushed to a dedicated branch `larch-logs/design/<RUN_ID>/` via the **already-existing** `design-log-publish.sh` (currently only run at end of design). Resume reads the issue marker, fetches the branch, restores `$DESIGN_TMPDIR` from it, re-enters the named step. Why it's lean: reuses existing `larch:plan` block grammar and `design-log-publish.sh`. Risk if cut too far: if a user denies push permission or `larch-logs` workflow is disabled, the feature dies. Mitigation: graceful fallback to in-body chunked storage when push fails.

## Slice B — "Re-derive expensive artifacts; only persist user-decided state"

Pause persists only: `run-params.json`, `feature-description.txt`, `discussion-round1.md`, `brainstorm.md` (when complete), `accepted-plan-findings.md` (when complete), `discussion-round2.md` (when complete), the current `plan.txt` (when written), and the operator's Gate A / Gate B / Gate C choices. Everything else (sketches, dialectic, reviewer outputs, voting tallies) is re-derived on resume. The body marker is `larch:design-pause` containing a step pointer plus base64-gzipped tar of just the small "decision" files (kilobytes, not megabytes). Why it's lean: avoids the ~65 KB body limit for most plans; honors "resume from any machine" because the issue is self-sufficient. Risk if cut too far: re-deriving sketches and 10-reviewer panel costs $5-20 per resume; users who pause mid-review get hit with the full review cost again. Mitigation: surface this cost prominently in the resume confirmation prompt.

## Slice C — "Pause at any Bash-tool boundary; mid-Bash is best-effort kill"

Pause request is recorded in a sentinel file `$DESIGN_TMPDIR/.pause-requested`. After **every** Bash tool call returns (and at the top of every step), the orchestrator checks for this sentinel; if present, the pause snapshot runs and the run exits. Mid-Bash-tool-call pause is handled by Claude Code's Esc semantics: when user hits Esc, the in-flight Bash is killed by the harness; the orchestrator never gets to write the snapshot, so on next `/design <N>` the resume detects the missing snapshot and re-enters from the last completed step. Why it's lean: no signal handler in /design itself; we lean on Claude Code's native Esc behavior and just check a sentinel between calls. Risk if cut too far: user's pause is not honored if Esc happens mid-Bash and the orchestrator hasn't written *any* snapshot yet for the current step — they lose the partial work of that step (e.g., a half-finished sketch). Mitigation: snapshot at the END of each step (post-Bash) so worst case is one step of lost work.

## Slice D — "Two-marker protocol: pause-marker + state-blob, redact secrets"

Pause writes two named blocks to issue body: `<!-- larch:design-pause -->` (small pointer with step name, session id, edit-content hash) and `<!-- larch:design-state -->` (base64-gzipped opaque tar of artifacts, passed through `redact-secrets.sh` before zipping). Resume parses both. Concurrent-edit detection compares the edit-content hash. Why it's lean: a single helper `scripts/design-pause-save.sh` (mirror of `plan-block-write.sh`) handles both blocks; `scripts/design-pause-load.sh` reads them. The shared helper for `/implement` and `/review` is just these two scripts plus the marker grammar. Risk if cut too far: a few-MB artifact set (full plan-review reviewer outputs) won't fit in the 65 KB body. Mitigation: when artifact size exceeds threshold, error out at pause with "your run is too big to pause; complete or cancel"; document the threshold.

## Slice E — "Pause is just a 'kill the run; mark state' button. No 'in-flight' nuance."

Esc → user types "pause" → orchestrator immediately writes the pause marker and exits cleanly. There is **no** attempt to wait for in-flight Bash tools or externals; they are killed by Claude Code's harness when Claude exits. Any partial output is discarded (matches Decision 5: abandon in-flight externals). Resume re-launches from the last completed step boundary. Why it's lean: zero coordination logic — pause is just "write marker, exit". Risk if cut too far: even non-external mid-step work (e.g., the orchestrator was halfway through synthesizing sketches into approach-synthesis.txt) is lost. Mitigation: write the synthesis output ATOMICALLY (tmp + rename) so it's either complete-on-disk or absent; resume re-runs whichever steps are absent.

## Slice F — "Pause is a `Skill` invocation, not a flag"

The user-facing pause is a dedicated skill `/larch:pause` that operates on the running session via the env file (`~/.cache/larch/sessions/current-design-env-$PPID.sh` already gives us a stable handle). The skill writes the pause marker and exits. The `/design` orchestrator on the next turn detects the marker and unwinds cleanly. Why it's lean: zero coupling to `/design`'s argv parsing; `/larch:pause` is a tiny skill that just calls a `pause-now.sh` helper. The same `/larch:pause` works for `/implement` and `/review` later (Decision 4 generalization). Risk if cut too far: requires the user to know about `/larch:pause` (a new skill name); doesn't auto-detect "I pressed Esc and typed 'pause' in chat" — they must use the slash command. Mitigation: document `/larch:pause` in the README pause section; the SKILL.md anti-halt rule for `/design` is unchanged.
