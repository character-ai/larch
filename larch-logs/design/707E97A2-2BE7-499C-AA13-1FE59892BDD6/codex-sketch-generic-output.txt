Implement this as a thin checkpoint layer around the existing `/design` state model, not as a second workflow engine. `/larch:pause` should source `~/.cache/larch/sessions/current-design-env-$PPID.sh`, require `DESIGN_TMPDIR` and `ISSUE_NUMBER`, then write both `$DESIGN_TMPDIR/.pause-requested` and `~/.cache/larch/sessions/pause-requested-${ISSUE_NUMBER}.flag`. `/design` adds a prompt-side sentinel check after every Bash boundary: if `.pause-requested` exists, run `scripts/design-pause-save.sh --design-tmpdir "$DESIGN_TMPDIR" --issue "$ISSUE_NUMBER" --step <next-resumable-step> --tier ...`, then exit cleanly with the issue still `[DESIGNING]`. `design-pause-save.sh` should call `design-log-publish.sh --reason pause`; that path should reuse the current redacted staging, disposable worktree, PR, squash merge, and `larch-logs/design/<RUN_ID>/` layout, differing only in reason metadata, commit/PR wording, and no Step 5 finalization semantics. It should then write a tiny `larch:design-pause` issue-body block containing `STEP`, `SESSION_ID`, `RUN_ID`, `TIER`, `BRAINSTORM_DONE`, `BODY_HASH`, and `PAUSED_AT`. Extract `scripts/named-block-write.sh` from `plan-block-write.sh` by parameterizing marker name, canonical start/end generation, classify/replace/append/delete behavior, redaction, and issue edit; keep `plan-block-write.sh` as a wrapper for `--name larch:plan`. Resume detection belongs early in Step 0b after argv parse, issue binding, and issue-body fetch, before clarify/already-planned/tier routing: plain `/design <N>` sees `larch:design-pause`, runs `design-pause-load.sh` to fetch the committed log snapshot into the fresh Step 0a `$DESIGN_TMPDIR`, refreshes `source-env.sh` with the restored `SESSION_ID` / `ISSUE_NUMBER`, removes the pause marker atomically, warns on `BODY_HASH` mismatch, then continues via `design-driver.sh --resume-from "$STEP"`. Extend the driver’s resume enum from ACTION names to the full design step IDs in `step-name-registry.tsv`; for prompt-owned steps, the driver should primarily validate/normalize the step and emit skip/continue KVs, while existing ACTION replay remains for `EMIT_PLAN`, `VALIDATE_PLAN_COMMANDS`, `TALLY`, and `FINALIZE`.

Files to create or modify: `skills/pause/SKILL.md` for the tiny user-facing pause command; `scripts/design-pause-save.sh` to publish logs and write the pointer block; `scripts/design-pause-load.sh` to parse the pointer, restore `larch-logs/design/<RUN_ID>/`, compare body hash, and remove the marker; `scripts/named-block-write.sh` for shared named issue-block editing; `scripts/plan-block-write.sh` to delegate to that helper; `scripts/design-log-publish.sh` to add `--reason pause|final` while preserving current default behavior; `skills/design/SKILL.md` to add the post-Bash sentinel checks and Step 0b auto-resume branch; `skills/design/scripts/design-driver.sh` to accept normalized step IDs like `1d.5`, `2a`, `3.5`, `4b`; `skills/design/scripts/test-design-driver.sh` for the expanded resume enum; and one new pause harness, likely `scripts/test-design-pause.sh`, covering marker write/load/delete, hash warning, repeated pause cycles, and publish failure behavior. Add or update sibling `.md` contracts where this repo already keeps script docs, and register the harness in `Makefile` / lint config if that is the local pattern.

The main risks are operational, not architectural. First, pause-save can partially succeed: log publish may merge but marker write may fail, or the marker may write after a failed publish. Mitigate by ordering publish first, only writing the marker on `PUBLISH_OK=true`, logging failures with `append-tool-failure.sh`, and leaving the local tmpdir intact so the operator can retry `/larch:pause`. Second, `design-log-publish.sh` depends on PR creation/`--admin` merge and can be blocked by auth, branch protection, or stale branch state; mitigate by preserving the existing `PUBLISH_OK=false` / `RECOVERY_BRANCH` behavior and treating pause as not durable until the marker is written. Third, “pause anywhere” is only guaranteed at Bash boundaries: an interrupted external sketch/reviewer may leave incomplete artifacts. Mitigate by storing the next major resumable step, abandoning in-flight externals, and relaunching that step fresh on resume while preserving completed sentinels like `.brainstorm-done`, `.step3-entry-plan-printed`, and dirty-tree prompt markers from the restored tmpdir.
