**1. [important] [correctness]** [`skills/design/SKILL.md`](skills/design/SKILL.md) — Sub-step **0b.6** is specified *after* the lifecycle title filter (lines 186–191). Paused issues intentionally keep `[DESIGNING]` (plan Approach). That prefix is in `LARCH_TITLE_LIFECYCLE_REJECT_REGEX` (`scripts/lib-title-eligibility.sh:12`), so resume never reaches `design-pause-load.sh`. **Revision:** Run resume detection right after issue fetch and **before** sub-step 2.5, or exempt `[DESIGNING]` when the `design-pause` marker is present.

**2. [important] [correctness]** Proposed [`scripts/design-pause-load.sh`](scripts/design-pause-load.sh) — `git archive … larch-logs/design/<RUN_ID> | tar -x -C "$DESIGN_TMPDIR"` leaves a nested tree (`docs/run-logs.md` documents depth-1 artifacts under that path). The skill expects `plan.txt`, `run-params.json`, etc. at `$DESIGN_TMPDIR` root. **Revision:** Flatten published run files into the tmpdir after extract.

**3. [important] [correctness]** Plan omits a mandatory **`write-design-current-env.sh`** call after successful load. Step **0a** always allocates a new `SESSION_ID` (`skills/design/SKILL.md:117–176`); without rebinding, publish and pause-save can target the wrong run. **Revision:** Refresh `source-env.sh` and the PID symlink from marker `SESSION_ID`/`RUN_ID` before routing.

**4. [important] [risk-integration]** [`scripts/design-log-publish.sh`](scripts/design-log-publish.sh) lines 159–162 — Stale worktree checkout blocks republish; the plan’s pause idempotent branch only addresses an existing **local branch** (lines 164–169). Repeated pause snapshots for the same `RUN_ID` can fail with `PUBLISH_OK=false` and no marker. **Revision:** Teardown stale worktrees for `larch-log-design-${RUN_ID}` on `--reason pause`.

**5. [important] [risk-integration]** Proposed load path uses **`git archive --remote`**, which is unsupported or unreliable on many GitHub HTTPS setups; the repo has no prior `git archive` usage. **Revision:** `git fetch` then local `git archive <ref> …`.

**6. [important] [correctness]** `BODY_HASH` has no normative definition in the proposed contracts. **Revision:** Shared helper + identical strip rules on save and load.

**7. [important] [correctness]** Resume is placed before the **clarify loop** (Step 0b.3) without interaction rules. A paused issue that later receives `needs-design-clarification` could resume past clarify. **Revision:** Gate resume on label state or run clarify before step routing.

**8. [important] [architecture]** Step **0b.6** only says “route directly to that step” — no jump table for substeps (tier gate, `write-run-params`, `1d.5`, etc.). **Revision:** Explicit skip list per `STEP` aligned with `step-name-registry.tsv`.

**9. [latent] [correctness]** Lexicographic-min step selection can diverge from registry workflow order if new step IDs are added. **Revision:** Use TSV row order.

**10. [latent] [risk-integration]** `pause-requested-${ISSUE}.flag` is never cleared. **Revision:** Remove on successful `design-pause-save.sh`.

**11. [nit] [architecture]** Testing strategy requires a **Makefile** target but the plan’s Files section does not list `Makefile`. **Revision:** Add `test-design-pause-resume` to the file list.

**12. [nit] [correctness]** `named-block-write.sh` delete semantics are only defined when the block is **present**; `/dev/null` with absent block is unspecified. **Revision:** Document no-op or `MODE=absent`.

**13. [important] [correctness]** Failure mode 1 + retry `/larch:pause` — without a marker, retry still waits for the next Bash boundary; the plan should state that explicitly for operators mid–long-running tool work.
