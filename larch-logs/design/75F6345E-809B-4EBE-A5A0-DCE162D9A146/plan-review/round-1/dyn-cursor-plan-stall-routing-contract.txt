### 1. Correctness — stale ledger log on partial-fix exhaustion (`checks_lint_fix.py`)

The plan generalizes `_populate_no_changes_stale_ledger` to accept `exhausted` while still passing `args.checks_log` from `checks_repair_loop_main`:

```417:421:python/larch/implement/checks_lint_fix.py
    action = _repair_loop_action(
        loop=loop,
        lint_site=lint_site,
        checks_log=args.checks_log,
        allowed_tmpdir=canonical_tmp,
```

That matches today's `no-changes-stale` behavior (see `test_checks_repair_loop_main_step6_no_changes_stale_falls_back_to_main_agent`), but the two statuses differ. In dispatch-first mode, an exhausted loop updates `redacted_log_for_dispatch` after each failed recheck:

```1689:1701:python/larch/implement/checks_lint_fix.py
            redacted_path = _redacted_log_for_dispatch(
                checks,
                allowed_tmpdir=canonical_tmp,
            )
            ...
            redacted_log_for_dispatch = redacted_path
```

After partial helper edits, the remaining failures live in that latest redacted file, not the original `--checks-log`. Pointing `LINT_FIX_LEDGER_FAILURE_DETAIL_LOG` at the argv log can send the main agent at errors the helpers already fixed.
