The implementation centers on three changes in `scripts/launch-claude-review.sh`, plus a sibling docs update and a same-PR harness extension in `scripts/test-launch-claude-review.sh`. The core architectural decision is to make `--context-files <path>` behave **differently** from the four existing implicit context flags (`--diff-file`, `--scope-files`, `--plan-file`, `--feature-file`): those flags silent-skip via `append_context_file()`'s `[[ -n "$path" && -f "$path" ]] || return 0` guard (line 97), but `--context-files` is an explicit user contract and must hard-error with exit 2 when its argument is missing or non-existent — matching the Step 1c clarification. The new flag is repeatable (each occurrence appends one path), parsed via a dedicated case-arm that collects into a Bash array. It forwards verbatim to `launch-claude-subprocess.sh`'s already-existing `--context-files` interface (line 33), so all canonicalization, allow-root containment, symlink rejection, 1 MB cap, and 20-file cap remain authoritative in the subprocess. The launcher does only what the subprocess cannot: it (a) hard-errors empty/missing user-supplied paths early, (b) deduplicates by canonical path across all five context flag sources, and (c) emits `--allow-root <dirname>` for each unique parent directory so containment passes downstream.

File-level edits land in **`scripts/launch-claude-review.sh`**: add a new `EXPLICIT_CONTEXT_FILES=()` array near the existing scalars (around line 28), add a case-arm `--context-files) EXPLICIT_CONTEXT_FILES+=("${2:?--context-files requires a value}"); shift 2 ;;` to the parser at lines 32-46 (repeatable single-value form, since the launcher's existing case uses fixed `shift 2` two-token consumption), refactor `append_context_file()` (line 95) to accept a `strict` second argument controlling whether missing/empty hard-errors with `larch_err` + `exit 2` versus silent-skip, and to dedupe by canonical path. The simplest dedupe shape is to track a `:`-separated `seen_canonical_paths` string keyed off `realpath` (or `cd … && pwd -P`-of-dirname + basename, matching `canonical_existing_file()` in the subprocess), parallel to the existing `seen_allow_roots` mechanism on lines 100-103. The four existing `append_context_file` calls (lines 105-108) keep silent-skip semantics; a new loop iterates `EXPLICIT_CONTEXT_FILES[@]` with strict=1. Update **`scripts/launch-claude-review.md`** to document `--context-files` in the flag list, note it is repeatable, hard-errors on missing paths (contrasting with the implicit flags), is role-orthogonal across reviewer and voter, deduplicates against the other four context flags by canonical path, and that the subprocess 20-file cap remains the global ceiling so combined input from all five sources counts toward that cap. The **harness** at `scripts/test-launch-claude-review.sh` gains: (1) accept-test asserting two distinct `--context-files` paths pass through to a stub claude invocation under `--role reviewer`; (2) accept-test under `--role voter` proving role-orthogonality; (3) reject-test that omitting the value (`--context-files` followed by another flag) trips Bash's `${2:?…}` and exits 2; (4) reject-test for a non-existent path producing the new `larch_err` message and exit 2; (5) dedup-test verifying that passing the same file via `--diff-file` and `--context-files` results in a single `--context-files` argument to the subprocess (assertable by stubbing `launch-claude-subprocess.sh` itself or via subprocess `STDERR_CAPTURE` log inspection); (6) containment-test where a `--context-files` path outside `PLUGIN_ROOT`/`SESSION_ROOT` is rejected by the subprocess and the message propagates via the existing tempfile-stderr capture (lines 129-134 of the launcher).

The main tradeoffs and risks: (i) **Asymmetric strict vs. silent-skip semantics** in `append_context_file` is a behavioral split worth flagging in a code comment — silent-skip exists because implicit flags are conditionally populated by callers (`launch-review.sh`, `dispatch-code-voters.sh`) that may legitimately pass empty strings when a phase has no plan/feature/scope, whereas `--context-files` is operator-typed and an empty value almost certainly indicates a caller bug. (ii) **Dedup canonicalization cost**: each path requires a `dirname` + `cd … && pwd -P` round-trip; for the 20-file cap this is bounded and cheap, but the subprocess will re-canonicalize, so we tolerate the duplication rather than threading canonical paths through an argv contract change. (iii) **Caller-surface ripple**: existing callers (`launch-review.sh`, `dispatch-code-voters.sh`, any specialist-prompt orchestrators in `skills/`) must not be touched per the additive-flag constraint; greps against the launcher's caller surface should confirm no incidental forwarding of `--context-files` already exists. (iv) **Pre-check vs. authoritative cap**: a launcher-side pre-check of `combined_count <= 20` is permissible per the Step 1d binding but adds drift risk if the subprocess cap ever changes; the safer minimum is to skip the pre-check and let the subprocess emit the cap error, which still propagates via the existing tempfile-stderr capture. (v) **Markdownlint MD038** on the docs update — when listing repeatable flag syntax, write `--context-files <path>` (no inner whitespace at code-span boundaries) and put the "repeatable" qualifier in prose, not inside the span.
