# Implementation Plan — Context-file launcher surface (issue #2867)

## Approach

Expose a public, repeatable `--context-files <path>` argv flag on `scripts/launch-claude-review.sh` that forwards verbatim to `scripts/launch-claude-subprocess.sh`'s existing `--context-files` interface. The launcher does only what the subprocess cannot — early hard-error on missing/empty/unreadable operator-supplied paths via explicit arity validation (NOT Bash `${parameter:?...}` expansion, whose exit-1 status would violate the documented exit-2 contract), and canonical-path dedup across all five context-flag sources (implicit `--diff-file/--scope-files/--plan-file/--feature-file` plus the new explicit flag) — while the subprocess retains authority over canonicalization, symlink rejection, allow-root containment, the 1 MB per-file size cap, and the 20-file global cap. The asymmetric validation (hard-error for explicit, silent-skip for implicit) is intentional: implicit-flag callers (`launch-review.sh`, `dispatch-code-voters.sh`) legitimately pass empty strings when a phase has no plan/feature/scope, but explicit operator-typed `--context-files` should fail fast on typos.

**Containment-test contract decision** (resolving review-finding theme B): the launcher's existing `--allow-root` propagation for context-file dirnames is the intentional contract — operator-supplied `--context-files` paths are AUTHORIZED via widened allow-roots, matching the existing implicit-flag behavior. The test harness verifies this propagation positively (explicit context succeeds via widened roots) and uses an orthogonal rejection vector (symlink path) to verify the subprocess-stderr-propagation contract. No symmetry break with the subprocess containment model: the subprocess remains authoritative for what counts as "inside" allowed roots; the launcher only widens the set.

No changes to the subprocess. No new callers added.

### UPDATED: `scripts/launch-claude-review.sh`

Argv + plumbing change:

- Add `EXPLICIT_CONTEXT_FILES=()` initialization near the existing scalars (around line 28, before the `while [[ $# -gt 0 ]]` parser).
- Insert a new case-arm in the argv parser (between the existing `--feature-file` line 43 and `--timeout` line 44) using **explicit arity validation** so the contract-mandated exit 2 fires correctly:
  ```bash
  --context-files)
      [[ $# -ge 2 && -n "${2:-}" && "$2" != --* ]] || {
          larch_err "launch-claude-review.sh: --context-files requires a value"
          exit 2
      }
      EXPLICIT_CONTEXT_FILES+=("$2")
      shift 2
      ;;
  ```
  Do NOT use `${2:?...}` parameter expansion — its exit-1 failure status violates the documented exit-2 contract on trailing/missing values (review finding theme A).
- Update the `usage()` larch_err string (line 12) to include `[--context-files <file>...]` in the context-flags suffix.
- Refactor `append_context_file()` (line 95) to accept a second positional `strict` argument and to dedup by canonical path:
  - Signature: `append_context_file <path> <strict>` where `strict` is `0` (silent-skip on missing/empty/unreadable) or `1` (hard-error). Use `local strict="${2:-0}"` so single-argument call sites remain valid during the refactor window.
  - Compute canonical path: `local canonical; canonical="$(cd "$(dirname "$path")" 2>/dev/null && printf '%s/%s' "$(pwd -P)" "$(basename "$path")")" || canonical=""`.
  - When `strict=1`: if `path` is empty, `! -f "$path"`, `! -r "$path"` (NEW — readability check addresses review-finding theme D), or `canonical` empty → `larch_err "launch-claude-review.sh: --context-files path missing or unreadable: $path"; exit 2`. The fixed wording is required for the harness assertion.
  - When `strict=0`: preserve the existing `[[ -n "$path" && -f "$path" ]] || return 0` silent-skip behavior (DO NOT add the `-r` check here — implicit callers may pass non-readable placeholders by design).
  - Track a new `:`-separated string `seen_canonical_paths` (parallel to `seen_allow_roots`). After computing `canonical`, branch on `case ":$seen_canonical_paths:" in *":$canonical:"*) return 0 ;; ...` — return 0 silently if already seen; otherwise append to `ctx_args` as `--context-files "$path"` (operator-supplied form, NOT `$canonical`; the subprocess re-canonicalizes), append `$canonical` to `seen_canonical_paths`, and add the canonical dirname to `allow_root_args` via the existing `seen_allow_roots` dedup logic.
- Update the four existing call sites (lines 105-108) to pass `0` as the second argument explicitly:
  `append_context_file "$DIFF_FILE" 0`, `append_context_file "$SCOPE_FILES" 0`, `append_context_file "$PLAN_FILE" 0`, `append_context_file "$FEATURE_FILE" 0`.
- Add a new loop after the four existing calls iterating `EXPLICIT_CONTEXT_FILES[@]` with `strict=1`:
  ```bash
  for ctx_path in ${EXPLICIT_CONTEXT_FILES[@]+"${EXPLICIT_CONTEXT_FILES[@]}"}; do
      append_context_file "$ctx_path" 1
  done
  ```
  The `${array[@]+"${array[@]}"}` expansion is required under `set -u` for empty arrays.
- No changes to the subprocess invocation (lines 113-117); `ctx_args` and `allow_root_args` are already passed through.
- Add a single one-line comment above the refactored `append_context_file()` body: `# strict=1: --context-files hard-errors on missing/empty/unreadable; strict=0: implicit flags silent-skip (callers may pass empty).` This is a load-bearing WHY comment.
- Bash 3.2 compatibility: no associative arrays, no `mapfile`/`readarray`, no `${var,,}` parameter case conversion; only `case` matching and `+=` array append.

## Edge cases

- **Repeated identical `--context-files <path>`**: dedup by canonical path collapses to one forwarded entry. No error.
- **`--context-files` shares canonical path with an implicit flag**: same dedup; first occurrence wins (order: implicit four processed in lines 105-108, then `EXPLICIT_CONTEXT_FILES` loop). Explicit duplicate is silently dropped.
- **Empty `EXPLICIT_CONTEXT_FILES` array under `set -u`**: guarded via `${EXPLICIT_CONTEXT_FILES[@]+"${EXPLICIT_CONTEXT_FILES[@]}"}` expansion.
- **Path with embedded spaces**: Bash array expansion preserves spaces; parser arm captures `"$2"` correctly with explicit arity check.
- **Relative path**: `cd "$(dirname "$path")" && pwd -P` resolves to absolute. Subprocess re-canonicalizes.
- **Symlink path**: launcher's canonical-path dedup uses `pwd -P` of dirname so the symlink TARGET is the dedup key; the subprocess `canonical_existing_file` then rejects the symlink at validation time. Stderr propagates via the existing tempfile capture (test case 7 covers this).
- **Path beyond combined 20-file cap**: launcher does not pre-check; the 21st file is rejected by the subprocess with `--context-files is capped at 20 files` (line 90), surfacing via tempfile-stderr capture.
- **Unreadable file (chmod 000)**: launcher's strict mode (`-r` check) hard-errors with exit 2 before forking the subprocess (test case 8).
- **Trailing `--context-files` (no value) and `--context-files --timeout 5` (flag-like next token)**: both rejected by the parser's explicit arity check with exit 2 + the fixed wording (test case 3 covers both).
- **Context file in a directory OUTSIDE PLUGIN_ROOT/SESSION_ROOT**: launcher widens `--allow-root` so the subprocess accepts (test case 6 covers this — positive propagation test).

## Failure modes

1. **Backward-compat regression on the existing 4 implicit `append_context_file` call sites**: the helper's new `strict` parameter changes its signature. Earliest warning: every existing test case in `test-launch-claude-review.sh` that exercises `--diff-file`/`--plan-file` etc. fails. Mitigation: default `strict="${2:-0}"` inside the function, AND explicitly pass `0` at all four call sites (lines 105-108). Same-PR diff must show both edits to prevent silent drift on future call-site additions.
2. **Dedup canonicalization mismatch with subprocess**: launcher's `cd … && pwd -P` may resolve symlinked parent directories differently from subprocess's `canonical_existing_file`, causing the same logical file to bypass dedup OR collapse distinct files. Earliest warning: test case 5 fails when run under a symlinked `$TMPROOT` (some CI runners). Mitigation: ensure the launcher's canonicalization shape matches the subprocess's exactly (no `readlink -f` divergence); document the canonicalization mechanism in the inline WHY comment.
3. **`make lint` regression from stale validator-harness expectations**: the existing `test-validate-plan-commands.sh` lines 104-107 still expect `--context-files` to be reported as `unknown-flag`. Once the launcher's `usage()` lists the new flag, this assertion fires. Earliest warning: `make lint` fails on the first commit that updates `launch-claude-review.sh` without the same-PR harness flip. Mitigation: revise the harness assertion (and possibly the validator's allowlist) in the SAME commit that updates the launcher.
4. **Unreadable-file test flakiness as root**: the chmod-000 test case is skipped under `EUID == 0`. CI workflows running as a non-root user honor the case; container-based runners may sometimes run as root and silently skip. Mitigation: document the skip condition in a one-line comment; the case is a regression backstop, not a primary contract assertion.
5. **`scripts/test-launch-claude-review.md` sibling drift**: the `.claude/rules/script-md-siblings.md` rule expects the `.md` sibling to evolve with the `.sh`. Earliest warning: `make lint` fails the script-md-siblings check. Mitigation: extend the Covers line as part of the same PR (UPDATED entry above).
