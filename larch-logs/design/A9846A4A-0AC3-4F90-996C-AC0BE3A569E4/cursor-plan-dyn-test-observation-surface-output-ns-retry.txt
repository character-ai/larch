2. **[correctness]** `plan.txt:57` / `scripts/launch-claude-review.sh:112-118` — Case 5’s `PATH` subprocess stub and `LARCH_LAUNCH_CLAUDE_SUBPROCESS_OVERRIDE` are not viable: the launcher invokes `"$SCRIPT_DIR/launch-claude-subprocess.sh"` (absolute path, not `PATH`), and no such override exists in `scripts/`. **Revision:** Either extend the plan to add an override env var read at the subprocess invocation site, or drop subprocess-argv capture and use stdin inspection in the `claude` stub (finding 1).

3. **[correctness]** `plan.txt:56-57` / `scripts/launch-claude-review.sh:95-103` — Case 6 (containment: stderr `context file outside allowed roots`) cannot fire for paths that pass `append_context_file`, because every accepted context file appends `--allow-root "$(dirname "$path")"` (proposed plan preserves this). `SESSION_ROOT` is the canonical dirname of `--output`, which the harness places under `$TMPROOT`, so a context file under `$TMPROOT` is already allowed even without `--allow-root`. **Revision:** Remove case 6 from `test-launch-claude-review.sh` (containment is already covered in `scripts/test-launch-claude-subprocess.sh:69-80`) or redesign it to call `launch-claude-subprocess.sh` directly without the launcher’s `--allow-root` widening.

4. **[correctness]** `plan.txt:55` / `scripts/launch-claude-review.sh:32-47` (proposed `--context-files` arm) — Case 3 asserts exit `2`, but a trailing `--context-files` with no value trips `${2:?--context-files requires a value}`, which aborts with Bash exit `1`, not the launcher’s explicit `exit 2` used elsewhere (cf. `scripts/test-wait-for-reviewers.sh:40-41` expects `1` for the same `${2:?}` pattern). **Revision:** Assert `rc -eq 1`, or validate missing values in the case arm with an explicit `larch_err` + `exit 2` (matching timeout/role tests in the same harness).

5. **[architecture]** `plan.txt:55` — Test case 3 text still leads with `--context-files --timeout 5`; that invocation binds `--timeout` as the path (`${2:?}` does not reject flag-like tokens) and would fail later with `path missing or unreadable: --timeout`, not `--context-files requires a value`. The plan self-corrects to trailing `--context-files`, but the contradictory lead sentence risks a wrong harness implementation. **Revision:** Describe only the trailing-flag invocation in the test spec; optionally add a separate latent test or parser guard for flag-like values.
