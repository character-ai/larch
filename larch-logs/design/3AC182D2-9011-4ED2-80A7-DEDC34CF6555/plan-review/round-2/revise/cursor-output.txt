## Plan

### Approach

Add a new `/rejected-analysis --n DAYS` skill that recovers only rejected code-review findings that are verified real, not already fixed, and not already filed.

Keep the split simple:

1. **Prompt-side skill** parses the single `--n DAYS` argument, creates a temp work dir, calls the Python prepare step, **parses and retains machine KV rows from every wrapper fence** (Bash does not preserve shell state), dispatches bounded **mechanically read-only** verification via the existing external launcher, delegates confirmed non-security clusters to `/issue`, then **always** calls the Python record step (even when `/issue` is skipped or partially fails).
2. **Python core** owns all deterministic work: per-skill-root log discovery and parsing, ballot-id normalization, vote joins via `python/voting.py`, cheap pre-filtering, cap accounting, ledger reads/writes (including pre-verification drops), clustering, issue-batch rendering, issue-output parsing, cluster-to-hash mapping artifacts, and voter-verdict sidecar output.
3. **Agent verification** stays narrow and read-only. Each verification task is launched through `python/cli.py agent launch-review` with `--sandbox read-only` (Cursor `--mode ask` / Codex read-only sandbox) and a prepare-rendered prompt file. Dirty-tree checkpoint before/after each launch is a **backstop**: reject verdicts and ledger-dismiss when `STATUS=dirty` or `STATUS=unknown`. Each agent returns one JSON verdict: `confirmed`, `stale`, or `already-fixed`, with **required** non-empty `current_location` and `evidence` fields.
4. **Issue filing** delegates to `/issue --input-file ... --sentinel-file ...` so existing redaction, semantic dedup, dependency wiring, and post-call sentinel checks remain the authority. **Security-sensitive confirmed findings never reach `/issue`**; they are ledger-dismissed locally with an operator-visible warning per `SECURITY.md` and the `/bug` security gate pattern.
5. **Idempotency** comes from a committed TSV ledger at `larch-logs/rejected-analysis-ledger.tsv`, keyed by a **frozen** `finding_hash` (see below). **Every triage outcome** (dismissed pre-filter, cap-exceeded, verification-failed, stale, already-fixed, filed, deduped) is ledgered so reruns do not repeat expensive work. Ledger updates use **read-merge-`os.replace`** (mirror `review_pipeline.ensure_reviewer_prune_ledger`), not append-only writes.

Honor the discussion constraints:

- Keep rejected findings with **at least one YES vote**.
- Drop 0-YES findings.
- Treat `major` and `blocker` voter severities as priority only, not inclusion.
- Sort high-severity candidates before lower severity.
- Cap verification at **100 findings** by default.
- Log every drop reason and every cap drop; **also ledger deterministic pre-verification drops**.
- Collect from both `larch-logs/implement/` and `larch-logs/review/` using **skill-root-specific artifact layouts** (mirror `python/analyze_issues._ground_truth_discover_classifiers`).
- Keep `/design` plan-review rejections out of v1.
- **Exclude already-OOS-deferred findings**: accept only in-scope code-review rows (`scope` empty or `in_scope`, canonical `FINDING_*` ids); drop `scope=oos` / `out_of_scope` and `OOS_*` ids with `dismissed:oos-deferred`.

#### Frozen `finding_hash` contract

Idempotency depends on a stable hash over normalized identity and concern, **not** synthetic JSONL ids or raw prose whitespace.

- Algorithm: `sha256` over UTF-8 newline-joined sorted `key=value` lines (keys sorted lexicographically).
- Fields (all normalized before hashing):
  - `source_skill` — `implement` or `review`
  - `run_id`
  - `round_num` — decimal string
  - `canonical_finding_id` — post-normalization ballot id (`FINDING_N`), never `REJ_*`
  - `file_path` — repo-relative, slash-normalized, no leading `./`
  - `line_hint` — decimal string or empty
  - `concern` — whitespace-collapsed concern text (strip, collapse internal runs of whitespace)
- Synthetic JSONL `id`, voter slot labels, and trailing/leading prose whitespace **do not** participate.
- `concern_hash` ledger column stores `sha256(concern_normalized)` for diagnostics; `finding_hash` is the ledger primary key.

### Edge cases

- Implement run has JSONL but no matching classification TSV for that round: drop with logged reason and ledger `dismissed:unjoinable`.
- Review run has `review-findings.ndjson` but no matching `review-findings-classification-round-N.tsv`: same.
- JSONL `id` is synthetic while TSV uses `FINDING_N`: resolve via prose header and token mapping before join and hashing.
- `round_num` missing on multi-round implement JSONL: drop as ambiguous; do not guess.
- Review NDJSON without `round_num`: bind round only from classification filename; drop if multiple rounds share `finding_id` without round isolation.
- Unsupported classification TSV schema: drop after `classification_tsv_schema_supported` returns false.
- `scope=oos` or `OOS_*` id: drop with `dismissed:oos-deferred`.
- Schema v2 with no body severity: use per-voter severity from classification TSV only.
- Finding cites no file path: keep only if concern clearly names a repo surface; else drop and ledger.
- Cited file no longer exists: verify only if cheap path inference possible; else `stale`.
- Open issue snapshot fails: abort before Agent verification and filing.
- Security-tagged confirmed finding: ledger `dismissed:security-sensitive`; print operator warning; never `/issue`.
- `/issue` deduplicates: `record` resolves `ISSUE_<i>_DUPLICATE_OF_NUMBER` / `_URL` via `issue-cluster-map.json` batch index.
- `/issue` fails partially: `record` commits safe rows, withholds unmapped `filed-as` rows, sets `UNMAPPED_CONFIRMED=true`, exits non-zero; surface created issue numbers for operator repair.
- Stale sentinel in reused workdir: `rm -f` parsed `ISSUE_SENTINEL` before each `/issue` attempt.
- `VERIFY_COUNT=0`: skip agent launches only; `finalize` no-op merge; `record` commits prepare ledger-pending.
- Dismissed-only finalize (`stale`/`already-fixed`/`verification-failed` only): skip `/issue`; `record` still appends ledger.
- Cap-exceeded and other pre-verification drops: ledgered during prepare; second run skips them.
- Ledger duplicate hashes: keep first row, warn, do not append duplicate.
- Ledger atomic replace fails after successful `/issue`: fatal exit; operator repairs ledger manually using surfaced issue numbers and cluster map.
- Dirty-tree during verification: reject verdict, ledger `dismissed:dirty-tree`; do not retry indefinitely.

### Failure modes

- **Bad argument**: exit non-zero with usage; do not run collection.
- **Malformed logs**: skip malformed rows with counts; abort only if date window metadata unreadable for every run.
- **Issue snapshot unavailable**: fail closed before verification.
- **Malformed Agent JSON or missing location/evidence**: `verification-failed`; ledger dismissed; do not file.
- **Repo mutated during verification**: dirty-tree checkpoint rejects verdict; ledger `dismissed:dirty-tree`; do not file.
- **All candidates dropped by cap**: log counts; `finalize` + `record` commit cap-drop ledger rows; exit successfully with no `/issue`.
- **Partial `/issue` failure**: `record` commits safe rows; exit non-zero with `UNMAPPED_CONFIRMED=true`; surface created numbers.
- **Sentinel verification fails**: `record` still runs; withhold unmapped filed rows; exit non-zero.
- **Ledger merge/readback fails**: fatal; do not claim success.

### Testing strategy

Run focused tests first:

- `python3 -m pytest python/test_rejected_analysis.py`
- `python3 python/cli.py rejected-analysis prepare --days 7 --log-root <fixture> --work-dir <tmp>`
- `bash skills/rejected-analysis/scripts/test-rejected-analysis.sh`

Then repository-required checks:

- `make py-lint`
- `make py-test`
- `make lint`

Fixture tests must prove:

- First run files one coherent issue batch from confirmed non-security findings.
- Second run over same window emits no new verification prompts or issue batch.
- `stale`, `already-fixed`, and `verification-failed` ledgered and never filed.
- Cap-exceeded and 0-YES drops ledgered; second prepare skips them.
- **`VERIFY_COUNT=0` run**: `finalize` + `record` commit prepare ledger-pending without agent launches; second prepare skips hashed drops.
- Dismissed-only run still calls `record` and commits ledger.
- `/issue` dedup stdout (`DUPLICATE_OF_*`) maps to ledger issue numbers via `issue-cluster-map.json`.
- `ISSUES_FAILED>0` commits safe rows only; unmapped confirmed hashes not filed; exit non-zero.
- Implement and review layouts both collect rejected 1-YES in-scope rows.
- Ballot id normalization joins `REJ_*` JSONL to `FINDING_*` TSV; hash stable across ids.
- High-severity 1-YES sorts before lower severity under cap.
- Security-tagged and OOS-deferred confirmed findings never produce `issue-batch.md`.
- Batch items include `Dissenting voter(s):` provenance.
