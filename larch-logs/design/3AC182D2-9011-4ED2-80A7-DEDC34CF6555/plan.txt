## Plan

### Approach

Add a new `/rejected-analysis --n DAYS` skill that recovers only rejected code-review findings that are verified real, not already fixed, and not already filed.

Keep the split simple:

1. **Prompt-side skill** parses the single `--n DAYS` argument, creates a temp work dir, calls the Python prepare step, **parses and retains machine KV rows from every wrapper fence** (Bash does not preserve shell state), dispatches bounded **mechanically read-only** verification via the existing external launcher, delegates per-candidate verdict ingestion to Python, delegates confirmed non-security clusters to `/issue`, then **always** calls the Python record step (even when `/issue` is skipped or partially fails).
2. **Python core** owns all deterministic work: per-skill-root log discovery and parsing, ballot-id normalization, vote joins via `python/voting.py`, cheap pre-filtering, cap accounting, ledger reads/writes (including pre-verification drops), clustering, issue-batch rendering, issue-output parsing, cluster-to-hash mapping artifacts, verdict ingestion/extraction, location binding, field sanitization, and voter-verdict sidecar output.
3. **Agent verification** stays narrow and read-only. Each verification task is launched through `python/cli.py agent launch-review` with **only supported flags** (`--tool`, `--output`, `--timeout`, `--prompt-file`, `--timing-task-kind`, optional `--stderr-sink`, `--site`). **`launch-review` does not accept `--sandbox`**; read-only enforcement is launcher-owned (Codex `codex exec --sandbox read-only`; Cursor `cursor agent --mode ask` plus dirty-tree baseline). Parse launcher stdout for `OUTPUT=` and `LAUNCHER_EXIT=`; never `json.loads` the output file directly in prompt-side orchestration. After each launch, read `${OUTPUT}.dirty-tree` (launcher-written sidecar); treat `STATUS=dirty` or `STATUS=unknown` as reject and ledger `dismissed:dirty-tree`. Delegate body extraction, JSON validation, location binding, and sanitization to `python/cli.py rejected-analysis ingest-verdict`, which applies the same Cursor/Codex postprocessing rules as `agents.py` (`_review_cursor_postprocess`, fence stripping, launcher failure sentinels).
4. **Issue filing** delegates to `/issue --input-file ... --sentinel-file ...` so existing redaction, semantic dedup, dependency wiring, and post-call sentinel checks remain the authority. **Security-sensitive confirmed findings never reach `/issue`**; they are ledger-dismissed locally with an operator-visible warning per `SECURITY.md` and the `/bug` security gate pattern. Security classification runs in **both** `prepare` (pre-verify exclusion) and `finalize` (confirmed-survivor re-filter).
5. **Idempotency** comes from a committed TSV ledger at `larch-logs/rejected-analysis-ledger.tsv`, keyed by a **frozen** `finding_hash` (see below). **Every terminal triage outcome** (dismissed pre-filter, cap-exceeded, verification-failed after successful launch, stale, already-fixed, dirty-tree, near-duplicate collapse, filed, deduped) is ledgered so reruns do not repeat expensive work. **Launcher/infra failures** (`LAUNCHER_EXIT!=0`, missing binary, auth preflight) are **not** ledgered; the skill exits non-zero before durable success is claimed so operators can rerun. Ledger updates use **read-merge-`os.replace`** (mirror `review_pipeline.ensure_reviewer_prune_ledger`), not append-only writes.

Honor the discussion constraints:

- Keep rejected findings with **at least one YES vote**.
- Drop 0-YES findings.
- Treat `major` and `blocker` voter severities as priority only, not inclusion.
- Sort high-severity candidates before lower severity.
- Cap verification at **100 findings** by default.
- Log every drop reason and every cap drop; **also ledger deterministic pre-verification drops**.
- Collect from both `larch-logs/implement/` and `larch-logs/review/` using **skill-root-specific artifact layouts** (mirror `python/analyze_issues._ground_truth_discover_classifiers`).
- Keep `/design` plan-review rejections out of v1.
- **Exclude already-OOS-deferred findings**: accept only in-scope code-review rows (`scope` empty or `in_scope`, canonical `FINDING_*` ids); drop `scope=oos` / `out_of_scope` and `OOS_*` ids with `dismissed:oos-deferred`.

#### Frozen `finding_hash` contract

Idempotency depends on a stable hash over **run-independent identity**, not ballot numbering, run metadata, synthetic JSONL ids, line-range formatting, raw prose whitespace, or **mutable repo filesystem state**.

- Algorithm: `sha256` over UTF-8 newline-joined sorted `key=value` lines (keys sorted lexicographically).
- **Hash inputs** (all normalized before hashing):
  - `file_path` — repo-relative, slash-normalized, no leading `./`, no trailing slash on file paths (see `extract_target_path` below)
  - `concern` — whitespace-collapsed concern text from `extract_concern` (below)
- **Ledger columns only** (do **not** participate in `finding_hash`): `canonical_finding_id`, `line_hint`, `concern_hash`, `source_skill`, `run_id`, `round_num`, synthetic JSONL `id`, voter slot labels, dissenting slots, trailing/leading prose whitespace.
- **Rationale**: `canonical_finding_id` (`FINDING_N`) is per-run ballot numbering; the same unresolved defect in implement vs review logs or across runs must share one `finding_hash` when `file_path` and normalized `concern` match. `line_hint` is diagnostic/provenance only; range syntax variants (`path:12` vs `path:12-14`) must not fork identity.

#### Normative identity extractors (single helpers; unit-tested)

Implement three frozen helpers used by join, dedup, hashing, verification prompts, and ledger writes. **Do not consult live file existence when selecting the hash path**; existence checks are reserved for stale detection, demotion, and verifier binding only.

**`extract_concern(prose_body, tsv_row)`**

1. If `prose_body` contains a `### FINDING_N:` heading, use the heading title text after the colon (strip markdown decoration).
2. Else if prose contains a bulletized concern leader, strip the leading list marker and bold wrapper, then take the value:
   - `- **Concern**:` (case-insensitive leader after bullet/bold strip)
   - `Concern:` (case-insensitive leader on its own line)
   - `what:` (case-insensitive leader)
3. Else if the classification TSV row has a non-empty `concern` column, use it (whitespace-collapsed).
4. Else use empty string.
5. Apply whitespace collapse (strip; collapse internal runs of whitespace to single spaces).

**`extract_target_path(prose_body, tsv_row, repo_root)`**

`repo_root` is accepted for API symmetry but **must not** be used for hash-path tie-breaking via filesystem probes.

1. If classification TSV row has a non-empty `file` or `location` column with a repo-relative path token, normalize and use it (strip backticks; strip bullet/bold prefixes when present; take path portion before first `:` when `path:line` form; accept plain repo-relative paths and directory paths without a `:line` suffix).
2. Else collect candidate paths from prose in **stable document order**:
   - bulletized `- **Location**:` / `- **File**:` leaders (strip list marker and `**...**:` prefix before parsing)
   - backtick-wrapped `path` or `path:line` / `path:line-line` tokens
   - `**File**:` / `File:` leaders
   - bare `path:line` citations on their own line
   - bare repo-relative path tokens on their own line (no line suffix)
3. Normalize each candidate: repo-relative, forward slashes, no leading `./`, no trailing slash for file paths; preserve directory paths without forcing a file suffix.
4. **Tie-break when multiple paths** (hash-stable; no `os.path.exists` / `stat`):
   - prefer the first normalized path from the TSV `file`/`location` column when present
   - else prefer the first normalized path in prose collection order
   - when still tied after normalization, prefer lexicographically smallest path
5. Return empty string when no path is extractable.

**`extract_line_hint(prose_body, tsv_row, chosen_path)`**

1. When `chosen_path` came from a `path:line` or `path:start-end` citation (TSV or prose), use the **first decimal line number** in the range (`12-14` → `12`; lone `12` → `12`).
2. Else when TSV `location` column carries a parseable line for `chosen_path`, use its first decimal line.
3. Else return empty string.
4. **Ledger/diagnostic only** — not a `finding_hash` input. Unit-test that `12`, `12-14`, and equivalent citations yield identical `line_hint` for the same path.

**`compute_finding_hash(finding: RejectedFinding) -> str`**

- Hash only normalized `file_path` and `concern` from the extractors above.
- `concern_hash` ledger column stores `sha256(concern_normalized)` for diagnostics and prepare-time near-dedup grouping; `finding_hash` is the ledger primary key.

**Near-duplicate collapse (prepare)**

- Group survivors by `(normalized file_path, concern_hash)` before verify cap.
- Choose one survivor (highest severity sort key, then newest).
- **Ledger every suppressed sibling** immediately in `ledger-pending.tsv` with `dismissed:near-duplicate` and `alias_of=<survivor finding_hash>` (or equivalent `superseded_by` column) so reruns cannot resurrect collapsed siblings from another run's `FINDING_N`.

#### Per-candidate ingest status staging (durable)

Every verification candidate gets a durable ingest-status row on **every** orchestrator ingest attempt, not only successful verdict JSON. `prepare` writes empty `ingest-status.jsonl`; each `ingest-verdict` call appends exactly one JSON line keyed by `candidate_id`:

```json
{"candidate_id":"...","finding_hash":"...","status":"ingested|launch-failed|dirty-tree|parse-failed|location-mismatch","disposition":"optional","launcher_exit":0,"output_path":"..."}
```

`finalize` and `record` read `ingest-status.jsonl` as the authoritative per-candidate outcome map. They **must not** infer `dismissed:verification-failed` for candidates whose durable status is `launch-failed`; those hashes remain unledgered and retryable. Only candidates with a successful launch (`launcher_exit=0`) and no terminal ingested verdict (`parse-failed`, `location-mismatch`, or missing parsed verdict after launch success) may receive `dismissed:verification-failed`.

#### Verification prompt template

`prepare` renders one prompt per surviving candidate under the work dir using `issue_wire.emit_untrusted_content_block(tag="rejected_finding_candidate", text=...)` with explicit data-not-instructions preamble and read-only launcher instructions. Pin the candidate's normalized `file_path` and `line_hint` in the prompt and require the verifier to re-check **that surface**. **Pin machine output contract in every prompt**:

- Return **one JSON object only** (no markdown fences, no TSV, no prose wrapper).
- Required keys: `status` (`confirmed` | `stale` | `already-fixed`), `current_location` (non-empty string referencing the same repo-relative file as the candidate), `evidence` (non-empty string).
- Unit-test that rendered prompts contain the schema contract and pinned candidate path.

CLI verbs:

- `prepare --days DAYS [--log-root larch-logs] [--work-dir DIR] [--verify-cap 100]`
  - Accept `--days` (wrapper translates public `--n`).
  - Validate days and cap.
  - Create or use a work dir; emit `REPO_ROOT` for orchestrator context.
  - Scan implement and review run roots within the `manifest.json` / `run-manifest.json` `started_at` window.
  - Apply skill-root adapters, in-scope/OOS filter, and round-isolation rules:
    - Multi-round implement: if JSONL `round_num` absent and the same `finding_id` appears in more than one round TSV, drop as ambiguous (do not guess).
    - Review: always bind round from classification filename; drop when round cannot be determined uniquely.
  - Drop rows with 0 YES votes.
  - Drop security-tagged findings from the auto-file candidate set via `is_security_sensitive_candidate`; ledger as `dismissed:security-sensitive` with operator-visible summary (no `/issue`).
  - Sort `major`/`blocker` YES voters first, then not-demoted, then newest.
  - Deduplicate near matches by normalized `file_path` plus `concern_hash`; **ledger every suppressed sibling** with `dismissed:near-duplicate` and survivor reference.
  - Read committed ledger; drop already-triaged hashes (first row wins on duplicate hash; warn).
  - Query open issues once through injectable `gh` seam. **Fail closed** before Agent verification if snapshot fails.
  - Drop findings already covered by open issues via deterministic title/body token overlap; `/issue` remains fuzzy backstop.
  - Demote (do not drop) candidates whose target file was touched after run start (`git log --since <started_at> -- <path>` via `proc.Runner`).
  - Apply verify cap; log cap drops.
  - **Append ledger-pending rows** for all deterministic pre-verification drops (0-YES, schema-unsupported TSV, ambiguous round, oos-deferred, open-issue-overlap, ledger-duplicate, near-duplicate, cap-exceeded, security-sensitive) with dispositions like `dismissed:zero-yes`, `dismissed:cap-exceeded`, `dismissed:oos-deferred`, `dismissed:near-duplicate`, etc.
  - Write `candidates.json`, `drops.jsonl`, `ledger-pending.tsv` (pre-verification drops), empty `verdicts.jsonl`, and empty `ingest-status.jsonl`.
  - Emit KEY=value lines: `WORK_DIR`, `VERIFY_COUNT`, `VERDICTS_FILE`, `INGEST_STATUS_FILE`, `LEDGER_PENDING_FILE`, `ISSUE_SENTINEL`, `REPO_ROOT`, per-candidate `VERIFY_PROMPT_<id>=<path>`.
- `ingest-verdict --work-dir DIR --candidate-id ID --output PATH --launcher-exit N [--dirty-sidecar PATH]`
  - **Always** append one `IngestStatusRow` to `ingest-status.jsonl` before returning.
  - When `launcher-exit != 0`: return `INGEST_STATUS=launch-failed` (no verdict append; no ledger write here).
  - When launcher exit 0: read `${output}.dirty-tree` unless `--dirty-sidecar` overrides; on `STATUS=dirty|unknown`, append a dirty-tree disposition stub to `verdicts.jsonl` ingest staging and return `INGEST_STATUS=dirty-tree`.
  - Otherwise read postprocessed agent body from `--output` using shared extraction helpers mirroring `agents.py` (Cursor JSON `result` unwrap, fence strip, `CURSOR_EMPTY_RESPONSE` / `CURSOR_DEGRADED_RESPONSE` sentinels, Codex last-message text).
  - Parse exactly one JSON object; validate `status`, non-empty `current_location`, non-empty `evidence`.
  - Sanitize string fields via `_sanitize_verdict_field`.
  - Run `bind_verifier_location`; on failure return `INGEST_STATUS=location-mismatch` (no `confirmed` ingest).
  - On success append sanitized verdict to `verdicts.jsonl` and return `INGEST_STATUS=ingested`.
  - On parse/schema failure return `INGEST_STATUS=parse-failed`.
- `finalize --work-dir DIR`
  - Load candidates, ingested verdicts, and `ingest-status.jsonl`.
  - For each candidate in `candidates.json`, resolve outcome from durable ingest status:
    - `launch-failed`: **exclude** from ledger pending (remain retryable).
    - `dirty-tree`: add `dismissed:dirty-tree`.
    - `parse-failed` / `location-mismatch`: add `dismissed:verification-failed`.
    - `ingested` with parsed verdict: map `confirmed` / `stale` / `already-fixed`.
    - successful launch (`launcher_exit=0`) with no ingest row and no terminal status: add `dismissed:verification-failed` (defensive only; normal runs always write ingest-status rows).
  - Validate verdict JSON strictly on ingested rows:
    - Allowed `status`: `confirmed`, `stale`, `already-fixed` only on successful ingest.
    - Require non-empty sanitized `current_location` and `evidence`; re-run `bind_verifier_location`; otherwise `verification-failed`.
  - **Security re-filter (mandatory)**: before clustering or `issue-batch.md`, re-run `is_security_sensitive_candidate` on each `confirmed` survivor (use original finding metadata plus verifier evidence text); ledger `dismissed:security-sensitive`, exclude from batch, emit operator-visible warning summary (mirror prepare).
  - Keep only `confirmed` non-security candidates for issue clustering.
  - Mark `stale`, `already-fixed`, `verification-failed`, `dirty-tree`, and post-finalize `security-sensitive` as dismissed ledger entries in `ledger-pending`.
  - Cluster confirmed findings by subsystem/file area (deterministic; no LLM).
  - Per-issue size cap (e.g. 5 findings per issue).
  - Render `issue-batch.md` in `/issue` generic batch format with full provenance per item (all string fields sanitized):
    - run id, source skill, round, finding id, vote split, **Dissenting voter(s): `<slot list>`**, verification verdict, re-checked location, `finding_hash`, ledger hash.
  - Write machine-readable `issue-cluster-map.json`:
    ```json
    {"schema_version": 1, "clusters": [{"batch_index": 1, "finding_hashes": ["..."]}, ...]}
    ```
    Batch index matches `### <title>` item order in `issue-batch.md` (1-based).
  - When `VERIFY_COUNT=0` or no confirmed survivors: emit empty `issue-batch.md`, `CONFIRMED_COUNT=0`, empty cluster map with `"clusters": []`, refresh `ledger-pending.tsv` paths only.
  - Emit `CONFIRMED_COUNT`, `ISSUE_BATCH_FILE`, `ISSUE_CLUSTER_MAP_FILE`, `ISSUE_SENTINEL`, `LEDGER_PENDING_FILE`, `INGEST_STATUS_FILE`, `ISSUE_OUTPUT_STUB`, `LAUNCH_FAILURES` (count of `launch-failed` rows in ingest status).
- `record --work-dir DIR [--issue-output FILE] [--issue-verified true|false] [--issues-failed N] [--launch-failures N]`
  - `--issue-output` optional.
  - Load `issue-cluster-map.json` as the **authoritative** hash↔batch-index map (do not infer cluster membership from issue body prose).
  - Re-read `ingest-status.jsonl` to ensure no `launch-failed` hash receives a terminal ledger row.
  - When `--issue-output` provided and non-empty: parse `/issue` stdout for created and deduplicated shapes (`ISSUE_<i>_NUMBER`, `ISSUE_<i>_URL`, `ISSUE_<i>_DUPLICATE=true`, `ISSUE_<i>_DUPLICATE_OF_NUMBER`, `ISSUE_<i>_DUPLICATE_OF_URL`, `ISSUES_FAILED`).
  - **Partial-failure contract** (single normative behavior):
    - **Always** commit safe ledger rows via read-merge-atomic write:
      - all pre-verification / dismissed / stale / already-fixed / verification-failed / dirty-tree / oos-deferred / cap-exceeded / near-duplicate / security-sensitive rows from `ledger-pending.tsv`;
      - `filed-as #N` rows **only** for `finding_hash` values whose cluster batch index resolved to `ISSUE_<i>_NUMBER` or `ISSUE_<i>_DUPLICATE_OF_*`;
    - **Never** write `filed-as` for confirmed hashes in clusters lacking resolved mapping when `ISSUES_FAILED>0` or `issue-verified=false`.
    - **Never** write any ledger row for `launch-failed` candidates.
    - Set `UNMAPPED_CONFIRMED=true` and exit non-zero when any confirmed cluster lacks mapping; still persist safe rows first.
    - Exit non-zero when `issues-failed>0`, `issue-verified=false` (after `/issue`), or `launch-failures>0`; still persist safe rows first.
    - When `issues-failed=0`, mapping complete, `issue-verified=true`, and `launch-failures=0`: commit all rows; exit 0.
  - Merge `ledger-pending` and finalize dispositions; dedupe by `finding_hash` (first committed row wins; warn on duplicates).
  - **Fatal** on ledger write/readback failure after atomic replace; do not emit success counters until durable.
  - Write/append voter-verdict sidecar rows for `/voter-calibration` (sanitized cells).
  - Emit `LEDGER_APPENDED`, `ISSUES_CREATED`, `ISSUES_DEDUPLICATED`, `DISMISSED_COUNT`, `UNMAPPED_CONFIRMED`, `RECORD_EXIT_RC`.

Helper behavior:

- Use `larch_io.atomic_write` (read full ledger → merge rows in memory → temp + `os.replace`) for committed ledger updates; mirror `review_pipeline.ensure_reviewer_prune_ledger` / `write_prune_decision_env` durability posture.
- Use `proc.Runner` for `gh`/`git` probes.

### Edge cases

- Implement run has JSONL but no matching classification TSV for that round: drop with logged reason and ledger `dismissed:unjoinable`.
- Review run has `review-findings.ndjson` but no matching `review-findings-classification-round-N.tsv`: same.
- JSONL `id` is synthetic while TSV uses `FINDING_N`: resolve via prose header and token mapping before join; `finding_hash` ignores ballot id.
- Prose cites multiple paths: `extract_target_path` tie-break is deterministic from TSV precedence then prose order; does not fork `finding_hash` across equivalent reruns or unrelated file creation/deletion.
- Bulletized `- **Location**:` / `- **Concern**:` without backticks: normalize to repo-relative `file_path` and collapsed `concern`.
- `path:12` vs `path:12-14`: identical `line_hint` (`12`); `finding_hash` unchanged (line_hint not hashed).
- `round_num` missing on multi-round implement JSONL: drop as ambiguous; do not guess.
- Review NDJSON without `round_num`: bind round only from classification filename; drop if multiple rounds share `finding_id` without round isolation.
- Unsupported classification TSV schema: drop after `classification_tsv_schema_supported` returns false.
- `scope=oos` or `OOS_*` id: drop with `dismissed:oos-deferred`.
- Schema v2 with no body severity: use per-voter severity from classification TSV only.
- Finding cites no file path: keep only if concern clearly names a repo surface; else drop and ledger.
- Cited file no longer exists: verify only if cheap path inference possible; else `stale` (existence used here, not in hash).
- Open issue snapshot fails: abort before Agent verification and filing.
- Security-tagged confirmed finding missed at prepare: `finalize` re-filter ledgers `dismissed:security-sensitive`; print operator warning; never `/issue`.
- Verifier returns parseable JSON for wrong file: `location-mismatch` → `verification-failed`; never filed.
- Verifier evidence contains tabs/newlines: sanitized before ledger/sidecar/batch.
- `/issue` deduplicates: `record` resolves `ISSUE_<i>_DUPLICATE_OF_NUMBER` / `_URL` via `issue-cluster-map.json` batch index.
- `/issue` fails partially: `record` commits safe rows, withholds unmapped `filed-as` rows, sets `UNMAPPED_CONFIRMED=true`, exits non-zero; surface created issue numbers for operator repair.
- Sentinel verification fails: `record` still runs; withhold unmapped filed rows; skill exits non-zero after `record`.
- Stale sentinel in reused workdir: `rm -f` parsed `ISSUE_SENTINEL` before each `/issue` attempt.
- `VERIFY_COUNT=0`: skip agent launches only; `finalize` no-op merge; `record` commits prepare ledger-pending.
- Dismissed-only finalize (`stale`/`already-fixed`/`verification-failed` only): skip `/issue`; `record` still appends ledger.
- Cap-exceeded and other pre-verification drops: ledgered during prepare; second run skips them.
- Near-duplicate siblings: all suppressed hashes ledgered; second run skips entire equivalence class.
- Ledger duplicate hashes: keep first row, warn, do not append duplicate.
- Ledger atomic replace fails after successful `/issue`: fatal exit; operator repairs ledger manually using surfaced issue numbers and cluster map.
- Dirty-tree during verification: reject verdict via `${OUTPUT}.dirty-tree`; ledger `dismissed:dirty-tree`; do not retry indefinitely in one run.
- `LAUNCHER_EXIT!=0` or auth/binary preflight failure: durable `launch-failed` ingest-status row; do not ledger candidate; skill exits non-zero after `record` commits only safe rows; next run retries verification.
- `parse-failed` / `location-mismatch`: durable ingest-status row; `finalize` ledgers `dismissed:verification-failed`; never conflated with `launch-failed`.
- Successful launch with empty/malformed agent body: `ingest-verdict` → `parse-failed`; durable status row; `finalize` ledgers `dismissed:verification-failed`.
- Same logical finding in implement and review logs: identical `finding_hash`; second sighting skipped via ledger.

### Failure modes

- **Bad argument**: exit non-zero with usage; do not run collection.
- **Malformed logs**: skip malformed rows with counts; abort only if date window metadata unreadable for every run.
- **Issue snapshot unavailable**: fail closed before verification.
- **Launcher/infra failure**: durable `launch-failed` ingest-status row; no candidate ledger row; `record` may still commit pre-verification drops; skill exits non-zero (`LAUNCH_FAILURES>0`).
- **Malformed Agent JSON or missing location/evidence after successful launch**: `parse-failed` → `verification-failed`; ledger dismissed; do not file.
- **Verifier location drift/wrong file**: `location-mismatch` → `verification-failed`; do not file.
- **Repo mutated during verification**: `${OUTPUT}.dirty-tree` rejects verdict; ledger `dismissed:dirty-tree`; do not file.
- **Security classifier miss at prepare**: `finalize` re-filter prevents public filing.
- **All candidates dropped by cap**: log counts; `finalize` + `record` commit cap-drop ledger rows; exit successfully with no `/issue`.
- **Partial `/issue` failure**: `record` commits safe rows; exit non-zero with `UNMAPPED_CONFIRMED=true` and/or `ISSUES_FAILED>0`; surface created numbers.
- **Sentinel verification fails**: `record` still runs; withhold unmapped filed rows; skill exits non-zero (`ISSUE_VERIFIED=false`).
- **Ledger merge/readback fails**: fatal; do not claim success.
