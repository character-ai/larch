# Root cause: /implement #3688 PR creation failure — Makefile rebase conflict…

## Summary

Two conflicts resolved manually: `Makefile` (take feature-branch side — removes retired bash harness targets, adds Python-based targets) and `python/migrated-scripts.tsv` (keep-both — upstream adds 8 rows for #3923, feature adds 56 rows for #3688).

3. **Python ship driver invoked** — `python3 python/cli.py ship pr` entered the `pr-prep` phase and attempted a rebase onto the new `origin/main` HEAD (`e98052f8c`).
4. **Rebase failed** — commit `e98052f8c` modifies `Makefile` lines for `test-clarify-comment` and `test-clarify-state` (migrating them from bash harnesses to `pytest test_clarify.py`). The feature branch's Makefile also modifies the same `test-harnesses-*` section for sh-to-py P3. Result: conflict; ship driver exits with `STALL_STEP=rebase-failed`, `EXIT_CODE=4`, no PR created.
5. **Stall classification** — Step 18a reads `STALL_STEP=rebase-failed` from `finalize-state.sh`. The classifier sanitizes `rebase-failed` to `STALL_STEP=unknown` (not in the closed step enum). With `STALL_STEP=unknown`, `PHASE=unknown`, and `BAIL_REASON=` (empty), the classifier produces `FAILURE_CLASS=transient-infra`, `RESUME_HINT=none`. `RESUME_HINT=none` skips all dispatch and takes the terminal-failure path.

## Specific Makefile Conflict

Commit `e98052f8c` (Fixes #3924, #3977) changed:

```diff
 test-clarify-comment:
-	bash scripts/harness-timer.sh $@ bash scripts/test-clarify-comment.sh
+	cd python && $(PYTHON) -m pytest test_clarify.py

 test-clarify-state:
-	bash scripts/harness-timer.sh $@ bash scripts/test-clarify-state.sh
+	cd python && $(PYTHON) -m pytest test_clarify.py
```

The feature branch's Makefile (from the 7.r rebase resolution) had already removed several retired bash harness targets and added new Python-based targets in the same region, creating a three-way conflict that the ship driver cannot resolve automatically.

## Classification Gap

`rebase-failed` is not a recognized `STALL_STEP` enum value, so the classify subcommand sanitizes it to `unknown`. A rebase conflict at ship-pr (before PR creation) would ideally classify with `RESUME_HINT=step8-shippr` so a retry can be dispatched after the conflict is resolved. Instead, the unknown step/phase/bail-reason combination falls through to `transient-infra` with `RESUME_HINT=none`, which terminates the run without attempting recovery.
