## Findings

### 1. [risk-integration] `skills/design/SKILL.md:97` — stale Step 0a lifecycle prose (major)

The plan removes `--skip-branch-check` from `design_step0.py:166` but leaves `skills/design/SKILL.md` as **MAY_UPDATE**. Line 97 still instructs orchestrators that `/design` "calls `design step0-session` with `--skip-branch-check`" and that it "does not check a feature branch."

After the code change, `/design` will enforce `main` through shared `admission.preflight_main()` (`session_env.py:1614-1617`). Stale runtime prompt prose is a direct contract conflict and matches the plan's own failure mode about reintroducing the skip.

**Suggested revision:** Promote to **UPDATED**; replace line 97 with clean-main entry requirements (main, clean tree, empty stash) and drop all `--skip-branch-check` guidance.

### 2. [correctness] `docs/clean-main-contract.md:17-21` — incomplete `/design` subsection (minor)

The plan says to remove the stale "design does not check branch" claim but does not explicitly rewrite the Standalone `/design` block. That block still says design "still requires a clean working tree" only, with no `main` or stash requirements.

**Suggested revision:** Rewrite lines 17-21 to mirror the updated default gate: on `main`, clean working tree, empty stash, fetch/sync pass; no `<USER_PREFIX>/*` continuation for `/design`.

### 3. [correctness] `docs/clean-main-contract.md:5-15` — stash missing from contract enumeration (minor)

Section **(a)** lists dirty tree and wrong branch but not stash. Section **(d)** remediation paths (line 13-15) omit non-empty stash. The plan's doc bullets add stash to the default definition but do not call out updating **(d)**'s three-path summary.

**Suggested revision:** Add empty stash to **(a)**; add stash pop/drop to **(d)**; extend line 15 to cover stash failures.

### 4. [risk-integration] `docs/clean-main-contract.md:7-8` — USER_PREFIX "gate bypassed" overstates scope (minor)

Section **(b)** says the entire gate is bypassed on `<USER_PREFIX>/*`. Code today only skips branch/sync/rebase via `--skip-branch-check` (`admission.py:231-237`, `253-272`; `bootstrap.py:431-432`). Working-tree checks always run (`admission.py:238-247`). After the plan, stash checks run in the same block and are not skipped by `--skip-branch-check`.

**Suggested revision:** Clarify in **(b)** and the plan's "unchanged" language that USER_PREFIX bypass is branch-position only; dirty-tree and stash checks remain enforced.

### 5. [correctness] `python/larch/state/bootstrap.py:1332` — normalized message needs stash disambiguation (minor)

The plan updates bootstrap text but only says to "mention both dirty working trees and non-empty stash." Current option **(c)** uses "commit or stash" as a verb for uncommitted changes (`bootstrap.py:1332`, `docs/clean-main-contract.md:13`), which conflicts with the new failure mode where `git stash list` must be empty (`admission.py` proposed messages in plan).

**Suggested revision:** Spell out in the plan that **(c)** must distinguish uncommitted changes from clearing an existing stash stack; add explicit `git stash pop` / `git stash drop` guidance.
