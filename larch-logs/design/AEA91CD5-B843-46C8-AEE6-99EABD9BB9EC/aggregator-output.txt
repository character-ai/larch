### FINDING_1: `max_transient_retries` must honor unset env and health-gate suppression
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation, Cursor-Pragmatic
- **Severity**: important
- **Concern**: Global `max_transient_retries` resolution cannot rely on `_env_int` alone. When `LARCH_PROBE_RETRIES` is unset and `max_auth_retries == 1` (launch-time health gate with `LARCH_EXTERNAL_AUTH_RETRIES=1`), transient retries must be `0` for fast-fail. A single `_env_int("LARCH_PROBE_RETRIES", 2)` call treats unset as `2` and skips that suppression. Explicit overrides require `os.environ` membership (or equivalent) before reading the value. Invalid or empty present values (`LARCH_PROBE_RETRIES=""` or non-integer) must fall back like unset (`0` when `max_auth_retries == 1`, else `2`), not force `max_transient_retries=2` and regress health-gate latency or rate-limit exposure.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Add explicit check_reviewers binding, e.g. if "LARCH_PROBE_RETRIES" in os.environ: max_transient_retries = _env_int("LARCH_PROBE_RETRIES", 2) elif max_auth_retries == 1: max_transient_retries = 0 else: max_transient_retries = 2; document that _env_int cannot implement unset-vs-set by itself
  - From Cursor-Innovation: Document and implement a three-branch resolver: if LARCH_PROBE_RETRIES in os.environ then _env_int(..., 2); elif max_auth_retries==1 then 0; else 2
  - From Cursor-Pragmatic: Only honor explicit override when the value parses as a non-negative integer. On invalid/empty present values, apply the same fallback as unset: `0` when `max_auth_retries == 1`, else `2`. Document that behavior in `docs/configuration-and-permissions.md`.

### FINDING_2: Cursor preflight auth failure needs per-call zero transient budget
- **Reviewer(s)**: Cursor-Innovation
- **Severity**: important
- **Concern**: When `cursor_auth_preflight` returns auth failure (`rc == 2`), only the Cursor probe path must use `max_transient_retries=0` while Codex keeps the global transient budget. If the global `max_transient_retries` is passed to `_run_cursor_probes` without a preflight branch, a probe `rc==1` after preflight `rc==2` can still run up to three transient attempts even though auth is already known bad.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: At the Cursor call site compute cursor_transient = 0 when preflight.rc == _CURSOR_PREFLIGHT_AUTH_RC else max_transient_retries; pass cursor_transient only to _run_cursor_probes; keep the global max_transient_retries for Codex

### FINDING_3: Missing regression test for Cursor preflight one-shot on transient rc==1
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: `test_check_reviewers_cursor_preflight_rc2_one_shot` covers probe `rc==2` only. Without a test where preflight `rc==2` and the fake probe returns `rc==1`, an implementer can wire only the global health-gate rule and omit call-site `max_transient_retries=0`, allowing a misclassified or transient probe `rc==1` to run three attempts (default `LARCH_PROBE_RETRIES=2`) and break the definite-auth one-shot contract.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: Add a test mirroring preflight rc `2` with fake probe returning `1` and assert exactly one probe call with default env (no explicit `LARCH_PROBE_RETRIES`).
