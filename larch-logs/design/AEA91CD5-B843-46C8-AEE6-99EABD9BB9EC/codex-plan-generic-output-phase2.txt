### Findings

1. **correctness** (`python/agents.py:854-884`): Auth and transient budgets use different counting semantics, but the plan does not pin auth behavior to the current attempt-cap loop. `LARCH_EXTERNAL_AUTH_RETRIES` today caps total probe invocations (`range(1, max(max_retries, 1) + 1)`; value 5 → five probes on all-auth failure). `LARCH_PROBE_RETRIES=2` is specified as two extra attempts after the first failure (three total on all `rc==1`). Reimplementing both with symmetric retry counters can yield six auth probes for `LARCH_EXTERNAL_AUTH_RETRIES=5`, breaking `test_check_reviewers_expired_stamp_misses_and_auth_retry` and changing launcher auth semantics. **Suggested revision:** In `_run_codex_probes` / `_run_cursor_probes`, preserve today's auth path as an attempt cap identical to the existing loop, and apply `max_transient_retries` only for `rc==1`. State explicitly in the plan that auth keeps attempt-cap semantics while transient uses retry-after-first-failure semantics.

2. **correctness** (`python/agents.py:886-922`): Health-gate transient suppression requires distinguishing unset from defaulted `LARCH_PROBE_RETRIES`. The plan forces `max_transient_retries=0` when the variable is unset and `max_auth_retries==1`, but also says to read it via `_env_int("LARCH_PROBE_RETRIES", 2)`. `_env_int` substitutes the default before parsing, so it cannot detect unset. Unconditional use would always yield `2` and skip health-gate suppression. **Suggested revision:** In `check_reviewers`, branch on `"LARCH_PROBE_RETRIES" in os.environ` inside the active `_temporary_environ` overlay: if present, parse with `_env_int`; if absent and `max_auth_retries==1`, set `0`; if absent otherwise, set `2`. The plan's explicit-env override test already covers this; wire the implementation bullet to match.
