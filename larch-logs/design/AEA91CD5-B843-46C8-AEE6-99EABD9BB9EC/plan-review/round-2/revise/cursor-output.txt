## Plan

## Basis

- `approach-synthesis.txt` is `NO_SKETCHES`; draft from direct code and doc inspection.
- `discussion-round1.md` sets `LARCH_PROBE_RETRIES`, default `2`, as the retry API.
- Approved outline limits scope to `python/agents.py`, `python/test_agents.py`, and `docs/configuration-and-permissions.md`.
- Do not change negative caching, probe timeout, model effort, or caller scripts.

## Approach

- Add a separate transient retry budget for non-auth probe failures.
- Keep auth retry behavior separate from transient retry behavior.
- **Preserve distinct counting semantics** (FINDING_2): auth and transient budgets must not share a `for attempt in range(...)` bound or symmetric counter.
- Treat `LARCH_PROBE_RETRIES=0` as "no transient retry".
- Keep invalid or empty `LARCH_PROBE_RETRIES` values falling back to `2`.
- Preserve fast failure for definite auth preflight failures, deterministic setup failures, and health-gate one-shot probes.
- Do not change the public `agent check-reviewers` key-value output.

An explicit `LARCH_PROBE_RETRIES` in the environment overrides this health-gate suppression, including `0`.

- Change `_run_codex_probes` signature to accept both retry budgets:

  - `max_auth_retries`
  - `max_transient_retries`
  - `timeout`

- Change `_run_cursor_probes` the same way.
- Update call sites in `check_reviewers` to pass both budgets. For Cursor preflight auth failure (`preflight.rc == _CURSOR_PREFLIGHT_AUTH_RC`), keep `max_auth_retries = 1` and pass `max_transient_retries = 0`.

- **Replace the shared `for attempt in range(1, max(max_auth_retries, 1) + 1)` loop** in `_run_codex_probes` and `_run_cursor_probes` with a **`while True` loop and independent counters**. Do not extend the auth `range` bound by `max_transient_retries`, and do not model transient retries as `range(1, max_transient_retries + 1)`.

  **Semantic contract (must match today's auth tests and new transient tests):**

  - **Auth (`rc == _AUTH_RETRY_RC`) — attempt-cap semantics (unchanged):** `LARCH_EXTERNAL_AUTH_RETRIES=N` caps **total probe invocations** on an all-auth-failure path to **N** (today's `range(1, max(N, 1) + 1)`). Example: `N=5` with five consecutive auth failures → five probe calls; `N=2` with auth then success → two probe calls (`test_check_reviewers_expired_stamp_misses_and_auth_retry`).
  - **Transient (`rc == 1`) — retry-after-first-failure semantics (new):** `LARCH_PROBE_RETRIES=N` allows **N additional attempts after the first transient failure**, for **N+1** total probe calls on an all-`rc==1` path. Example: `N=2` → three probe calls; `N=0` → one probe call.
  - Auth and transient budgets are **independent**: mixed auth-then-transient (or transient-then-auth) sequences consume only the budget for the failure class of each probe result.

  **Suggested loop shape (equivalent logic acceptable if counters match):**

  ```python
  auth_failures = 0
  transient_retries_used = 0
  while True:
      rc = _run_one_*_probe(timeout)
      if rc == 0:
          return True, False
      if rc == config.EXIT_TIMEOUT:
          return False, True
      if rc == _PROBE_NO_RETRY_RC:
          return False, False
      if rc == _AUTH_RETRY_RC:
          auth_failures += 1
          if auth_failures >= max(max_auth_retries, 1):
              return False, False
          continue
      if rc == 1:
          if transient_retries_used >= max_transient_retries:
              return False, False
          transient_retries_used += 1
          continue
      return False, False
  ```

  **Anti-patterns to avoid:**

  - Reusing one loop bound for both budgets (e.g. `range(1, max(max_auth_retries, max_transient_retries) + 1)`).
  - Treating `max_transient_retries` as a total attempt cap (would break `LARCH_PROBE_RETRIES=2` → three-call expectation).
  - Inflating auth probes (e.g. six calls when `LARCH_EXTERNAL_AUTH_RETRIES=5` on all-auth failure).

- **Mandatory** deterministic no-retry path in `_run_one_codex_probe`:

  - When `_prepare_codex_home` returns non-zero, return `_PROBE_NO_RETRY_RC` instead of `1`.
  - Do not map prep/setup failures to transient-retryable `rc == 1`.

- Cursor setup fast-fail remains unchanged: `_cursor_probe_setup_chain()` returning `None` exits before the retry loop (no probe calls). No transient budget is consumed.

- Keep stamp read/write behavior unchanged.
- Keep negative stamp TTL behavior unchanged.

## Edge cases

- Cached positive stamps should still skip probing and therefore skip retry logic.
- Cached negative stamps should still be ignored by default because negative TTL remains `0`.
- Timeout should still return `*_PROBE_TIMED_OUT=true` immediately.
- Cursor preflight auth failure should still run at most one probe attempt with zero transient retries.
- `_prepare_codex_home` failure must remain one-shot even with default `LARCH_PROBE_RETRIES=2`.
- `LARCH_PROBE_RETRIES=0` should preserve old one-shot behavior for non-auth failures.
- Health-gate callers (`LARCH_EXTERNAL_AUTH_RETRIES=1`, `LARCH_PROBE_RETRIES` unset) must remain one-shot for transient failures.
- Explicit `LARCH_PROBE_RETRIES` in the environment overrides health-gate transient suppression.
- Invalid retry env values should not crash `check-reviewers`.
- Mixed auth and transient failure sequences must decrement only the budget for each probe's failure class; neither budget may borrow from the other.

## Failure modes

- More attempts may slightly increase Step 0 latency when a tool is truly unavailable.
- Retrying all `rc == 1` failures can waste attempts on deterministic failures if setup failures are not kept on `_PROBE_NO_RETRY_RC` (mandated above).
- Rapid repeated probes can still aggravate provider rate limits. The retry budget should remain small.
- Health-gate latency could regress if transient suppression is omitted when `LARCH_EXTERNAL_AUTH_RETRIES=1`.
- A naive shared `for`-loop bound can under-retry transient failures, over-retry auth failures, or break `test_check_reviewers_expired_stamp_misses_and_auth_retry`.
