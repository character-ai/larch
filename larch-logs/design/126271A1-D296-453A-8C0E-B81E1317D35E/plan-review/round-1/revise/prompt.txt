# [FEATURE] Add lint_monkeypatch_facade_binding (follow-up to #6494)

Source: `/larch:learn-from-bugs -n 25` run, 2026-07-08. Report section 4, rule L1, and section 7, item I2.

#### Problem

#6494: two `flush_logs_pre` tests in `test_run_logs.py` patched `run_logs._commit_run` and `run_logs._write_final_report` on the `run_logs` facade module after a refactor moved the live binding into `run_log_flush`, which imports those names directly (`from larch.report.run_log_commit import _commit_run`). `monkeypatch.setattr` on the facade rebinds only `run_logs.&lt;attr&gt;`; the code under test kept the real functions, the mocks silently no-oped, and both tests passed by accident. #6494's suggested fix names this lint as the follow-up; no open issue tracks it.

#### Rule

Flag any `monkeypatch.setattr(M, "name", ...)` call in a test file where all of the following hold:

- the first argument resolves to an imported module `M` whose source file lives in this repo;
- the second argument is a string literal naming the attribute;
- `M`'s module source binds that name only by import (`from x import name` or `import x as name`), and not by a module-level `def name`, `class name`, `name = ...`, or `name: T = ...`.

Also flag the dotted-string form `monkeypatch.setattr("pkg.mod.name", ...)` under the same only-imported condition for `pkg.mod`.

Skip silently: non-literal attribute names, first arguments that do not resolve to a repo module (objects, instances, third-party modules), and modules whose source cannot be located.

The report line must name the file and line, the patched facade module, the defining module seen in the import, and the suggested fix: patch the defining module, or patch the consuming module's own binding.

#### Known false positive

Patching the facade is correct when the code under test performs late attribute access through the facade (for example `import run_logs` followed by `run_logs._commit_run(...)` at call time). Version 1 does not attempt to detect that pattern; affected lines use the suppression comment with a reason.

#### Suppression and baseline

- Inline suppression: `# lint-monkeypatch-binding: ok &lt;reason&gt;` on the flagged line. A reason is required (G-Py-11).
- Grandfather existing violations in a reason-bearing baseline that only shrinks (G-Enf-2), following the baseline pattern of sibling lints such as `lint_tempfile_dir`. Add a `regen-monkeypatch-facade-binding-baseline` Makefile target mirroring the existing `regen-*-baseline` targets.

#### Wiring (follow existing conventions exactly)

1. Module: `python/larch/lint/lint_monkeypatch_facade_binding.py` with a module-level `main(argv) -&gt; int` returning a typed exit code (G-CLI-1). Mirror the structure of `lint_tempfile_dir.py`.
2. Registry: add `("lint", "monkeypatch-facade-binding"): ("larch.lint.lint_monkeypatch_facade_binding", "main")` to the dispatch table in `python/larch/cli.py`.
3. Makefile: add a `$(PYTHON) python/cli.py lint monkeypatch-facade-binding` line to the `py-lint-checks-fast` recipe, plus the regen baseline target and its `.PHONY` entry.
4. Scan surface: `python/tests/**/test_*.py` and `python/test_*.py`.
5. Tests: `python/tests/lint/test_lint_monkeypatch_facade_binding.py` covering: a facade re-export patch is flagged (reproduce the #6494 shape); a patch of the defining module is not flagged; a patch of a module that defines the name with `def` is not flagged; the dotted-string form is flagged; a suppressed line is not flagged; baseline entries are honored.
