Architecturally, make this a validator semantics change, not a dispatcher change. The dispatcher already admits either `### FINDING_N:` or a full-line `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED` candidate, and `_agg_pipeline_for_candidate` already maps validator narrow-trigger failures to `MERGE_PIPELINE_RC=1`. The clean fix is inside the embedded `aggregate-validate.py` in [aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.sh:502): in the `if not blocks:` branch, keep rejecting preamble contradictions first, keep rejecting missing attestation, but when `has_attest_line` is true and no preamble contradiction exists, return `0` instead of emitting `AGGREGATOR_VALIDATION_FAILED=empty_merge_from_nonempty_input`. That preserves the fail-closed behavior for narration that looks like malformed findings while allowing the explicit “all inputs duplicate, no merged findings” contract.

The main files to modify would be [skills/review/scripts/aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.sh:536), [skills/review/scripts/test-aggregate-findings.sh](<OPERATOR_REPO_PATH>/skills/review/scripts/test-aggregate-findings.sh:693), and likely [skills/review/scripts/aggregate-findings.md](<OPERATOR_REPO_PATH>/skills/review/scripts/aggregate-findings.md:26). The existing `zero_findings_input_nonempty rejected` test currently asserts `AGGREGATED=false`, `REASON=validation-exhausted`, unchanged input, and the `empty_merge_from_nonempty_input` diagnostic; that should flip to `AGGREGATED=true`, `REASON=ok`, `MERGED_COUNT=0`, and no surviving attestation token in the persisted ballot. The “pattern gate accepts full-line attestation and reaches validator” case should likewise assert it reaches the successful validator/strip path, not the narrow-trigger failure path. The docs need updating because they currently describe exact-attestation-on-nonempty-input as a validation-exhausted path.

The main tradeoff is that this changes a deliberately conservative validation rule: a bad aggregator can now erase a nonempty ballot if it emits the attestation token. The mitigating guard is that the token is an explicit machine contract already required by the prompt/pattern gate, and preamble contradiction detection should still reject outputs that reference finding IDs without producing valid blocks. The riskiest edge cases are benign narrative plus attestation versus malformed “almost findings” prose, padded attestation lines, and impure attestation suffixes; the regression tests should cover exact token, whitespace-padded token, no-token empty output, preamble contradiction, and merged blocks plus spurious token.
