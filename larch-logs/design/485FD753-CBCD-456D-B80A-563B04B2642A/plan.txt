# Plan — Fix attestation-only duplicate-merge to yield REASON=ok (#2939)

## Approach

The bug is a validator-semantics defect inside the embedded `aggregate-validate.py` heredoc in `skills/review/scripts/aggregate-findings.sh`. When aggregator output contains the `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED` line (possibly preceded by allowed narrative) and zero `### FINDING_<digits>:` blocks while input had structured findings, the validator's `if not blocks:` branch falls through to the `empty_merge_from_nonempty_input` narrow-trigger, which surfaces as `REASON=validation-exhausted`. The contract documented in `agents/orchestrator-aggregator.md` (lines 47-49) explicitly permits "brief narrative explaining the empty merge (optional)" before the attestation line. The plan for #2881 stated this case should yield `MERGE_PIPELINE_RC=0 → REASON=ok` with `MERGED_COUNT=0`.

The fix has three coordinated pieces:

1. **Validator (Python heredoc)**: in the `if not blocks:` branch, replace the unconditional `empty_merge_from_nonempty_input` return-1 path with a structural success predicate. The new ordering inside the branch is: (a) preamble-contradiction check (unchanged); (b) **new** nonconforming-heading-with-attestation rejection so malformed pseudo-headings like `### FINDING_1 not-a-valid-heading` combined with attestation cannot be accepted; (c) no-attestation rejection (unchanged); (d) attestation-only success path → `return 0` with an auditable stderr diagnostic. The orchestrator-aggregator prompt at `agents/orchestrator-aggregator.md:47-49` explicitly allows narrative before the attestation line, so the validator must accept narrative+attestation; downstream cleanup is handled by the strip path (piece 2).

2. **Strip path (shell wrapper)**: change the zero-block fallback in `_agg_pipeline_for_candidate` so the persisted `findings.md` is **always whitespace-only** when the success path produces zero merged blocks. Replace the current conditional `[[ -s "$merged_tmp" ]] || printf '\n' >"$merged_tmp"` (which only writes `\n` when the strip emptied merged_tmp) with an unconditional `printf '\n' >"$merged_tmp"` inside the `count_finding_blocks "$cand" -eq 0` branch. This guarantees no allowed-narrative prose leaks into the persisted ballot regardless of what the validator accepted. The unconditional overwrite is bounded by the `count_finding_blocks "$cand" -eq 0` guard, so the existing `merge_plus_impure_attest` success path (1 block + impure attestation suffix) is unaffected.

3. **Tests, docs, security, CHANGELOG**: flip in-place every test currently asserting `REASON=validation-exhausted` for the now-accepted scenarios (`zero_findings` #2536, `zero_findings_input_nonempty` #2782, `zero_findings_padded_attest_rejected` #2536) to expect `REASON=ok`, `AGGREGATED=true`, `MERGED_COUNT=0`, and a whitespace-only persisted `findings.md`. Add three new tests: a canonical round-trip success (pure attestation only), a pseudo-heading-with-attestation rejection (FINDING_3 regression), and a narrative-with-attestation success that asserts the persisted ballot is whitespace-only (FINDING_2 regression). Update `aggregate-findings.md`, sibling `test-aggregate-findings.md`, `SECURITY.md`, and add a `CHANGELOG.md` entry.

The downstream consumer surface (`review-core.sh:542-543`) branches only on `REASON=validation-exhausted`; all other reasons fall through to the normal voting flow, where `tally-code-votes.sh:128-130` uses `shopt -s nullglob` to handle a zero-block ballot cleanly (no accepted findings, no rejected findings, no crash). The voter dispatch step still launches 3 voters with an empty ballot — that wasted-token inefficiency is filed as OOS_2 (Cursor-Pragmatic) and is out of scope for this PR.

## Edge cases

- **Exact-line attestation only with nonempty input** → RC=0 (new success). Strip path's Change C unconditionally writes `\n`; FINDINGS_FILE = `\n`. Downstream voters see an empty ballot and produce no findings.
- **Narrative + attestation line (orchestrator-aggregator template-compliant output)** → RC=0 (new success). Narrative survives the strip (it doesn't start with the attestation token), but Change C unconditionally overwrites merged_tmp with `\n`, so FINDINGS_FILE = `\n`. No narrative leakage.
- **Whitespace-padded attestation line** (leading or trailing spaces only around the exact token) → `line.strip() == EMPTY_MERGE_ATTESTATION` so `line_has_impure_empty_merge_attestation` returns False; `drop_impure_empty_merge_attestation_lines` keeps the line; `has_attest_line` is True. Falls into the new success branch → RC=0 / REASON=ok. (Corrects the original plan's misclassification per FINDING_7.)
- **Impure attestation** (suffix or adjacent junk, e.g., `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED junk-suffix` or `LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTEDjunk`) → `drop_impure_empty_merge_attestation_lines` removes the impure line. With no other attestation line, `has_attest_line` is False → path-3 no-attestation rejection (REASON=validation-failed) unchanged.
- **Attestation + preamble contradiction** (attestation + prose like `### FINDING_24:` or `(FINDING_24-28)`) → path-1 preamble rejection fires first; unchanged behavior.
- **Attestation + nonconforming pseudo-heading** (e.g., `### FINDING_1 not-a-valid-heading` + attestation, or `###FINDING_1:` + attestation) → path-2 NEW rejection with `nonconforming_heading_with_attestation` → REASON=validation-exhausted. Addresses FINDING_3.
- **Attestation + spurious FINDING blocks** (e.g., 1 valid block + attestation line) → already rejected at line 532-538 by the existing `blocks and has_attest_line` early branch ("empty-merge attestation %r must not appear when merged FINDING blocks exist"). Unchanged.
- **No attestation + zero blocks + nonempty input** → path-3 no-attestation rejection. Unchanged.
- **No attestation + zero blocks + nonconforming heading** → path-3 no-attestation rejection (the nonconforming check at path-2 is gated on `has_attest_line`, so a no-attest fixture still gets the more informative no-attestation diagnostic). Existing tests at lines 660 and 675 continue to pass unchanged.
- **Empty input + zero blocks + attestation** → input_slot_set is empty → "no input reviewer labels" rejection at line 526-527 fires first. Unchanged.
- **All-OOS input + attestation-only output** → `non_oos_input_slots` is empty, `oos_only_slots` non-empty. The `if not blocks:` branch enters the new success path; the `oos_only_slots` check at line 595-603 only fires when `blocks` is non-empty. Validates correctly.
- **Findings.md pre-existing content** → the wrapper's `mv -f "$merged_tmp" "$FINDINGS_FILE"` at line 674 overwrites unconditionally. Whitespace-only findings.md is the intended end state.

## Failure modes

1. **Loosened validator drops narrative findings if a bad aggregator emits the attestation token without doing real dedup work**. Mitigations: (a) the attestation token is required by the orchestrator-aggregator prompt and the `--require-result-pattern` pattern gate, both of which are exercised in CI; (b) preamble-contradiction detection still rejects outputs that mention real FINDING IDs in prose; (c) the new path-2 nonconforming-heading rejection catches malformed pseudo-headings; (d) downstream voters see an empty ballot and exit cleanly — there is no "silent data corruption" beyond the missing findings, which is itself the contract semantic ("all findings were duplicates"). Earliest warning signal: a run with `REASON=ok` and `MERGED_COUNT=0` while reviewer outputs in `$REVIEW_TMPDIR/aggregator-input.md` clearly had distinct concerns. The three new tests pin the canonical valid case and the two new rejection variants.

2. **Test-assertion flip lands but adjacent tests are not updated, causing CI to fail in unexpected ways**. Mitigation: after edits, `grep -n 'validation-exhausted' skills/review/scripts/test-aggregate-findings.sh` to confirm every remaining hit is for a preamble or nonconforming-with-attestation rejection (not for an attestation-only case). Run `bash skills/review/scripts/test-aggregate-findings.sh` locally before pushing.

3. **SECURITY.md and aggregate-findings.md drift from validator behavior**. Mitigation: update SECURITY.md, aggregate-findings.md, sibling test-aggregate-findings.md, and CHANGELOG.md in the same commit as the script change. Cite #2939 in all four touch points.

4. **`empty_merge_from_nonempty_input` token references remain elsewhere in the codebase**. Mitigation: after the change, `grep -rn 'empty_merge_from_nonempty_input' --include='*.sh' --include='*.py' --include='*.md' .` and confirm no surviving references except possibly historic comments or PR descriptions. (Pre-existing larch-logs snapshots contain stale references and are intentionally not edited per repo convention.)
