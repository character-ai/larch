### FINDING_1: `write_tally_stub` would write to a non-existent directory on ballot/voter-unreadable branches
- **Reviewer**: Claude (quick mode)
- focus-area = correctness
- **Concern**: The plan adds `write_tally_stub` calls on three `exit 2` paths of `skills/design/scripts/tally-plan-review.sh`: the ballot-file-unreadable branch (current lines 58–61), the voter-file-unreadable branch (current lines 62–66), and the `split_ballot_to_blocks` branch (current lines 77–80). But `mkdir -p "$DESIGN_TMPDIR"` is currently at line 68 — AFTER the ballot/voter readability checks. So the stub-write on those two branches would target a directory that has not yet been created, and would fail (or write into a non-existent parent) when the operator passed a `$DESIGN_TMPDIR` that did not pre-exist. The `split_ballot_to_blocks` branch is fine (it runs after line 68).
- **Proposed resolution**: In `tally-plan-review.sh`, hoist `mkdir -p "$DESIGN_TMPDIR"` to immediately after the missing-required-args check (current line 57), BEFORE the ballot-file-unreadable check at line 58. The hoisted `mkdir -p` is semantically equivalent on the success path (DESIGN_TMPDIR is created earlier rather than later), and unlocks safe stub-writes on all three target failure branches. Update the plan's `UPDATED: tally-plan-review.sh` bullet to make this hoist explicit alongside the `tally_file` hoist, and add a one-line note in `tally-plan-review.md` under **Invariants** that "`mkdir -p $DESIGN_TMPDIR` runs as the first action after argv validation so all subsequent exit paths can write to it."
