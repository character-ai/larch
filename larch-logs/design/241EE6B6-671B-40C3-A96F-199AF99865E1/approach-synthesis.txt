## Approach Synthesis

Note: the actual Cursor sketch slot returned a 358-byte narration-only output — exactly the bug this design fixes (`outputTokens=6767`, `result_bytes=357`). The Cursor lane was recovered via a Claude Agent-tool fallback; the substantive synthesis below uses Cursor-via-Claude + Codex.

### Agreement (both sketches converge)

1. **Root-cause primary fix**: change `--mode plan` → `--mode ask` at `scripts/launch-review.sh:924` (the single production callsite). Both modes are documented read-only in `cursor agent --help`, so the read-only safety property is preserved; the `CURSOR_SANDBOX_ENFORCEMENT_LINE` and the surrounding comment block at lines 828-846 must be updated together with the argv flag so the prompt-level preamble matches actual CLI behavior. Five test assertions at `scripts/test-launch-review.sh` lines 1827/1838/1887/1890/1960 must flip from `--mode plan` to `--mode ask` in the same change.

2. **Secondary length-vs-tokens backstop**: add a heuristic at the `.result` extraction site (`scripts/launch-review.sh:1022-1040`). When `usage.outputTokens > 1000` AND extracted `.result` < 500 bytes, write the literal sentinel `CURSOR_DEGRADED_RESPONSE` to the output file — exactly the same write pattern as the existing `CURSOR_EMPTY_RESPONSE` sentinel at line 1040. Thresholds verbatim from Round 1 Decision 3.

3. **Telemetry routing — aliased**: route the new `CURSOR_DEGRADED_RESPONSE` literal through the existing validator + collector machinery so no new STATUS code is introduced (Round 1 Decision 7). `scripts/validate-research-output.sh:411-424` maps the new literal to validator exit 5 the same way it already maps `CURSOR_EMPTY_RESPONSE`; the orchestrator-visible STATUS remains `CURSOR_EMPTY_RESPONSE`. Waterfall fallback in `dispatch-with-waterfall.sh` fires automatically because STATUS != OK.

4. **Tertiary `--require-result-pattern` extension — plan-review only**: add the gate to `skills/design/scripts/dispatch-plan-review-panel.sh` with `--require-result-pattern '^[[:space:]]*(schema_version|\{"no_issues_found)'`. Sketch dispatchers stay opt-out (primary + secondary cover the sketch surface). Plan-review reviewer output reliably starts with the TSV header `schema_version` or the single-line JSON sentinel `{"no_issues_found": true}`, so the pattern gate has near-zero false-positive risk (Round 1 Decision 6).

5. **Task 2 — `normalize_rcc_max_iter` coverage**: wrap the three unguarded sites — `scripts/ship-pr.sh:2013`, `scripts/ship-pr.sh:2118`, and three stub bodies in `scripts/test-ship-pr.sh` (3786/3830/3876) — via `_RCC_MAX_ITER=$(normalize_rcc_max_iter "${LARCH_CI_LOCAL_FIX_ITER:-6}")`. Function definition at `scripts/ship-pr.sh:162` already exists. Also remove the `vendor-verify-sweep.sh` helper-stub block (lines 3647-3658) and replace its invocation with a direct `ship-pr.sh` integration call gated by `STUB_LINT_FIX_STATUS=main-agent-required`. Acceptance criterion: `vendor_verify_sweep_regression` still asserts exit 4 + `STALL_STEP=10-max-retries` + zero pushes (Round 1 Decision 9).

6. **Files modified** (seven, each touched only at cited ranges): `scripts/launch-review.sh`, `scripts/test-launch-review.sh`, `scripts/validate-research-output.sh`, `skills/design/scripts/dispatch-plan-review-panel.sh`, `scripts/ship-pr.sh`, `scripts/test-ship-pr.sh`. (Note: `scripts/collect-agent-results.sh` is reachable but no edit is needed under the aliasing approach — the existing exit-5 → `STATUS=CURSOR_EMPTY_RESPONSE` line at 1208 covers both literals.)

### Divergence (minor, resolved)

**Vendor-verify-sweep helper rewrite shape** — Codex follows the issue's verbatim patch (remove the helper, direct `ship-pr.sh` invocation). Cursor-via-Claude flags a safer-path mitigation: *"keep the helper file shape but route its body through the real `run_evaluate_failure ci-initial` entry rather than rewriting from scratch."* Round 1 Decision 9 already pinned the verbatim-removal path AND the passing-test acceptance criterion, so this design follows the verbatim patch. If the test fails during `/implement`, the implementer may retreat to Cursor-via-Claude's preserve-helper variant — record this as a fallback in the plan's Risks section, not as the primary direction.

### Innovation worth preserving

- Cursor-via-Claude explicitly notes **Bash 3.2 portability** per `BASH_AUTHORING.md §3` applies throughout the launcher edits, and **per-anchor breadcrumb markers** from §4 do NOT apply (no Family B denylisted scripts touched). Carry this CI-awareness note into the plan's Testing strategy.
- Codex's observation that "`dispatch-with-waterfall.sh` already treats any non-`OK` summary status as a failed slot" confirms aliasing is sufficient — no new dispatcher case needed.

### Edge / failure-mode awareness

- `--mode ask` sandbox property: documented read-only; mitigated by unchanged hardening preamble + dirty-tree sidecar.
- Heuristic false positives: a legitimately terse response after high token use (e.g., `NO_ISSUES_FOUND` sentinel) could trigger the backstop. Mitigation: `validate-research-output.sh` already short-circuits the `NO_ISSUES_FOUND` / `no_issues_found: true` sentinels before the body length check, so the `CURSOR_DEGRADED_RESPONSE` literal only ever appears in output files that already lack the sentinels; the validator path is untouched by this issue.
- `vendor_verify_sweep_regression` test rewrite: highest-effort piece because direct `ship-pr.sh` integration must reproduce the helper-stub's environment.
