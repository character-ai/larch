## Findings

### 1. `python/test_agents.py` — bash harness cleanup (correctness)

The plan says to replace Bash parity tests, but it does not name the `_bash_classify` / `_bash_startup_lock_acquire` helpers at lines 24–59 that `source` `scripts/lib-external-launcher-common.sh`. Deleting that lib without removing these callers breaks `make py-test` or leaves dead skip paths.

**Suggested revision:** Add an explicit `### UPDATED: python/test_agents.py` bullet to delete the `LIB_COMMON` subprocess helpers and any tests that still source retired libs.

### 2. `python/agents.py:1333` — redaction order (correctness)

`_compose_failure_diag` currently applies `redact_tmpdir_paths(redact_secrets_only(...))`. The plan and Bash `append_vendor_failure_diagnostics` require **tmpdir-paths then secrets**. The port must fix this existing helper, not only the new canonical stderr-tail helpers.

### 3. `python/test_agents.py:795-803` — stale section-order test (correctness)

`test_compose_failure_diag_orders_failure_carriers` pins sink → sidecar → diag order. The plan ports Bash `write_failure_diag` order (sidecar.history, events.history, sink, sidecar, diag, …). Leaving this test unchanged gives false confidence or a merge-time failure.

### 4. Retired-path sweep scope (risk-integration)

The plan’s rg command (lines 539–540) targets `agent-lint.toml`, `python/checks.py`, flush scripts, and docs, but not `python/test_agents.py` or `python/test_collect_results.py`, which still reference deleted libs. Line 18 calls for a repo-wide sweep; the narrower command is easy to follow literally and miss test literals before `migrated-scripts.tsv` append.

**Suggested revision:** Add `python/test_*.py` to the documented rg sweep and to the Testing strategy checklist.

### 5. [OUT_OF_SCOPE] `LARCH_VENDOR_FAILURE_DIAG_BYTES` (architecture)

Bash uses a fixed 16384-byte cap. Python `_append_vendor_failure_diagnostics` honors `LARCH_VENDOR_FAILURE_DIAG_BYTES` with default 20000 **characters**. The plan fixes the default to 16384 bytes but keeps the env knob. That is a small behavioral divergence worth a follow-up issue, not a blocker for this port.
