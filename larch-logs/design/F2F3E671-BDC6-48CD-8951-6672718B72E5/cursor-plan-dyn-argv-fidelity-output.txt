Reviewing the plan and tracing Codex/Claude drafter argv paths against the repo.
## Findings

**1. Codex drafter in-process `launch-codex-exec` must return `launcher_exit`, not wrapper process rc**  
`launch_codex_exec_main` always exits `0` after emitting `LAUNCHER_EXIT` on the contract stream (`python/agents.py:2498-2500`). The retired bash drafter treats wrapper rc and parsed `LAUNCHER_EXIT` separately (`scripts/launch-codex-drafter.sh:214-215,225`). The plan says “quiet internal callable” and “capture launcher_exit” but does not forbid calling `launch_codex_exec_main` directly. That would misclassify Codex failures as success.

**2. `checks.py` Cursor auth port omits `cursor_preread_service_token()`**  
Bash loads keychain tokens via `cursor_launcher_setup_auth_argv` → preflight → **preread** → export (`scripts/lib-cursor-launcher-common.sh:34-44`). The plan lists only `cursor_auth_preflight` and `cursor_auth_export_env` for `python/checks.py`. Other Python launchers call preread (`python/agents.py:2793,3797,4293`; `python/review_and_fix.py:1292`). Skipping preread breaks Darwin keychain-only Cursor lint-fix auth while still omitting `--api-key`.

**3. Claude drafter path validation omits bash control-char / `..` rules**  
`launch-claude-drafter.sh` rejects control characters and `..` in paths via `canonical_*` / `under_root` (`scripts/launch-claude-drafter.sh:48-83,184-199`). The plan’s validation bullets do not require parity. A Python port using only “file exists / under root” checks would accept paths the bash launcher rejects.

**4. Claude argv must not reuse `launch_claude_subprocess_main`**  
The drafter requires `claude --model <model> --print --output-format json --add-dir … --allowedTools Read,Glob,Grep,LS --permission-mode plan` with prompt on stdin (`scripts/launch-claude-drafter.sh:234-236`). `launch_claude_subprocess_main` builds `["claude", "--print", "--output-format", "json", "--model", …]` without `--add-dir` / `--permission-mode plan` unless `--read-tools` (`python/agents.py:4832-4834`). The plan states the exact argv but does not forbid delegating to the subprocess launcher; that would drift permission mode and flag order.

**5. [OUT_OF_SCOPE] `agent-lint.toml` S030 pins not listed for repoint**  
Deleted scripts remain allowlisted at `agent-lint.toml:327-337,521,609`. The plan sweeps docs and `checks.py` tables but not this file. Worth a follow-up issue so `make lint` / agent-lint stays aligned after deletion.
