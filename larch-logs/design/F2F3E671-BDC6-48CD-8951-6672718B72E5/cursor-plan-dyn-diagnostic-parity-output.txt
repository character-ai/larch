## Findings

### 1. Missing ns-retry tail resolution in `collect_results` (correctness)

Bash resolves tails in order: retry → **ns-retry** → launch-stderr → `.stderr-tail` (`scripts/lib-failed-agent-stderr-tail.sh:160-187`). Python `resolve_collector_stderr_tail_file` checks retry then jumps straight to the candidate loop (`python/collect_results.py:756-775`). The plan lists the full order under `### UPDATED: python/collect_results.py` but does not name the missing branch, so an implementer can “preserve order” in prose while leaving the ns-retry gap.

### 2. Split stderr-tail authority (architecture / risk-integration)

Three implementations coexist today:

- `agents._tail_redacted` uses character slicing `[:5120]` (`python/agents.py:1299-1303`)
- `review_dispatch.render_failed_agent_stderr_tail` uses UTF-8 byte truncation (`python/review_dispatch.py:373-391`)
- `checks.py` will still call bash until ported (`python/checks.py:1629-1648`)

The plan fixes `_tail_redacted` bytes but allows `checks.py` to use “`agents.py` or `review_dispatch`”, and `collect_results` re-renders through `review_dispatch` while launchers use `_write_stderr_tail`. That invites post-port drift on caps, env disable, and multibyte edges.

### 3. Claude drafter generic failure `.failure-diag` compose omitted (correctness)

On non-zero exit, bash writes stderr-tail and, when `.failure-diag` is empty, calls `write_failure_diag` with `--sink` pointing at `.stderr` (`scripts/launch-claude-drafter.sh:324-330`). Plan failure bullets (`plan.txt` lines 71-76) cover Codex exec/empty/delimiter paths and JSON invalid, not this generic Claude failure carrier path.

### 4. Codex drafter raw sidecar precedence for stderr-tail omitted (correctness)

Codex drafter failures tail from `_codex_raw.sidecar` before `OUTPUT_CANON.stderr` (`scripts/launch-codex-drafter.sh:228-236`). Quota mirroring lands on the raw sidecar via `launch-codex-exec`. The plan mentions `CODEX_EXEC_FAILED` and token-record copy but not this source order for stderr-tail.

### 5. `LARCH_FAILED_AGENT_STDERR_TAIL_LINES=0` not on collector path (risk-integration)

Bash honors env-driven line count and disable (`scripts/lib-failed-agent-stderr-tail.sh:43-49`). `review_dispatch` hardcodes 30 lines and remains in the collector re-render path (`python/collect_results.py:825`). Plan mentions “exact line count env handling” under agents helpers but does not require wiring it through `review_dispatch` / `collect_results`.
