/cleanup: top-level-mtime age-delete; drop depth-5 activity scan (fix hangs)

## Background

`/cleanup` (`skills/cleanup/scripts/cleanup.sh`) garbage-collects stale larch session temp dirs by age (`LARCH_CLEANUP_RETENTION_DAYS`, default 7), across two roots plus a symlink reap:

- **`~/.cache/larch/sessions/`** — larch's *owned* canonical root (`scripts/session-setup.sh:235`). Home for `/implement` `SESSION_TMPDIR`, `/design` `DESIGN_TMPDIR`, `source-env.sh`, the `current-design-env-*.sh` pointer symlinks, and reentry-guard markers. Per-user, survives reboot. larch owns the whole subtree, so deleting by age is unambiguous.
- **`/tmp`** — shared system temp where larch is a *guest*, not owner. Still actively written today: `scripts/wait-for-reviewers.sh:78` hardcodes `/tmp/wait-reviewers-*`; `scripts/session-setup.sh:265,270` falls back to `/tmp/claude-implement-*` when the cache `mktemp` fails; `scripts/lib-design-tmpdir.sh:171` allowlists `/tmp`. Because `/tmp` is shared, cleanup must match larch's specific name patterns there — never delete bare `/tmp` entries.
- **Dangling `current-design-env-*.sh` symlinks** — per-Claude-PID pointers (`ln -sfn` by `scripts/write-design-current-env.sh`) that every `/design` Bash block sources to rehydrate session state; they go dangling when their target session dir is removed.

The script emits a four-key stdout contract — `SESSION_COUNT`, `CACHE_REMOVED`, `TMP_REMOVED`, `SYMLINKS_REMOVED` — which the skill's Step 2 currently verifies.

## Motivation (incident)

A routine `/cleanup` ran for **~23 minutes** to do trivial work: removed 225 cache entries, **0** `/tmp` entries, 153 dangling symlinks, exit 0. Diagnosis:

- The workload was tiny: 656 cache entries / ~7,295 descendants; `/tmp` matched **0** of the real patterns.
- `sample` showed the process **CPU-bound in bash internals** (no syscall leaf) for the whole window — spinning, not blocked on I/O.
- Root cause: `newest_activity_mtime()` measures age by running `find -maxdepth 5` over each entry and **forking one `stat` per descendant path**, iterating a giant here-string in bash — an O(entries × descendants) fork/expansion storm, aggravated by 19 separate glob expansions over a 16,440-entry `/tmp`.

Two behaviors were *latently* trying to avoid deleting active runs, but are unnecessary:
- the depth-5 "newest activity" scan (keep a dir if any deep file is recent), and
- `SESSION_COUNT` via `pgrep -x claude` — **computed, emitted, then never used to gate deletion** (a vestige).

Both are obviated by the retention window: **no larch run lives anywhere near 7 days**, so age-since-last-touch alone fully captures "neither actively running nor useful for immediate debugging."

## Agreed decisions

1. **Goal (good, unchanged):** GC larch session temp dirs once old enough (default 7 days) that they're neither running nor useful for debugging.
2. **age = top-level mtime.** Accept that a directory's mtime doesn't bump on deep-only writes — harmless over a 7-day window since nothing larch creates stays alive that long.
3. **Scope to larch's own dirs only** — `~/.cache/larch/sessions/*` + larch *name-pattern* entries in `/tmp`; never bare `/tmp`.
4. **Keep both roots** (cache + `/tmp`) — `/tmp` is not dead (`wait-reviewers-*` always; `claude-implement-*` on fallback).
5. **Keep the dangling-symlink reap, age-independent** — a recently-orphaned pointer is younger than 7 days, so only the dangling-check catches it; safe because `write-design-current-env.sh` always creates the target before the symlink, so "dangling" reliably means "session gone," never "about to appear."
6. **Skill body = thin wrapper.** All logic (passes, counting, key emission, summary, contract enforcement) lives in `cleanup.sh`; `SKILL.md` just runs it and relays output.

## Fix plan

Replace the per-descendant scan with three flat passes — no descendant walk, no per-file `stat` fork, no repeated globbing:

```bash
RET="${LARCH_CLEANUP_RETENTION_DAYS:-7}"      # validated; fallback 7 with warning
SESSIONS="${XDG_CACHE_HOME:-$HOME/.cache}/larch/sessions"
TMP_ROOT="${LARCH_TEST_TMP_ROOT:-/tmp}"        # test hook preserved

emit_kv SESSION_COUNT "$(pgrep -x claude | wc -l)"   # informational only

# 1) cache: top-level entries older than RET days; never through a symlink
find "$SESSIONS" -mindepth 1 -maxdepth 1 ! -type l -mtime +"$RET" -print0  -> rm -rf, count CACHE_REMOVED

# 2) /tmp: same, scoped to larch's existing name patterns (never bare /tmp)
find "$TMP_ROOT" -mindepth 1 -maxdepth 1 ! -type l -mtime +"$RET" \
     \( -name 'larch-*' -o -name 'claude-implement-*' -o -name 'wait-reviewers-*' -o ... \) -print0  -> rm -rf, count TMP_REMOVED

# 3) reap dangling current-design-env-*.sh symlinks regardless of age (skip if target exists)
find "$SESSIONS" -maxdepth 1 -name 'current-design-env-*.sh' -type l -print0  -> for each: [ -e "$l" ] || { rm -f "$l"; count SYMLINKS_REMOVED; }

emit_kv CACHE_REMOVED / TMP_REMOVED / SYMLINKS_REMOVED ; print human summary
```

`find -mtime +N` reads the entry's own mtime (= top-level) and `+N` means strictly older than N×24h. Reuse the existing `TMP_PATTERNS` list verbatim.

## Remove

- `newest_activity_mtime()`, the descendant scan in `should_remove_by_age()`, and `stat_mtime()` (no longer needed).
- The `NOW`/epoch-`CUTOFF` arithmetic (replaced by `find -mtime`).
- `SESSION_COUNT` *gating intent* — keep it only as an emitted informational count.

## Preserve

- The four-key stdout contract; `LARCH_CLEANUP_RETENTION_DAYS` validation; `LARCH_TEST_TMP_ROOT` test hook; symlink-safety (never delete through a symlink); the dangling-symlink reap.

## In-sync updates (repo rules)

- `skills/cleanup/SKILL.md` — slim to a thin wrapper (run script, relay summary, surface non-zero exit).
- `skills/cleanup/scripts/cleanup.md` — sibling contract.
- `skills/cleanup/scripts/test-cleanup.sh` — drop depth-5 activity-scan tests; add "top-level mtime", "completes fast on a large `/tmp`", and "scoped patterns only" assertions; keep the symlink-reject / dangling-reap / retention-parse / multi-claude-info tests.
- Docs wording that mentions "depth 5 / newest activity": `README.md`, `docs/skills.md`, `docs/workflow-lifecycle.md`, `docs/linting.md` (the `make test-cleanup` row).

## Acceptance criteria

- Completes in well under a second even with a 16k-entry `/tmp`.
- Deletes only larch entries with top-level mtime older than the retention window; never deletes through a symlink; never touches non-larch `/tmp` entries.
- Reaps dangling `current-design-env-*.sh` symlinks regardless of age; never removes a live one.
- Emits all four keys; exit 0.
- `SKILL.md` contains no cleanup logic beyond invoking the script and relaying its output.
- `make test-cleanup` (updated) passes; `bash scripts/relevant-checks.sh` clean.
