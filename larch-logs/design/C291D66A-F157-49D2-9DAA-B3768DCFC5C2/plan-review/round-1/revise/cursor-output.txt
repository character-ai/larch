# Implementation Plan — #3212 /cleanup top-level-mtime age-delete

## Summary
Replace the O(entries × descendants) depth-5 activity scan in `cleanup.sh` with three flat passes that delete larch session temp entries by their own (top-level) mtime via `find -mtime`. This removes the per-file `stat` fork storm and the 19 repeated `/tmp` glob expansions that made a trivial `/cleanup` run for ~23 minutes. Preserve the four-key stdout contract, retention parsing, the `LARCH_TEST_TMP_ROOT` hook, symlink-safety, and the age-independent dangling-symlink reap. Wire `make test-cleanup` into the Makefile and `test-harnesses-12` so acceptance gates and `make lint` actually run the harness. Update `SECURITY.md` trust-boundary prose for the new enumeration and retention semantics. Update the skill prose, sibling contracts, regression harness, and docs that carry depth-5 wording.

This is a SIMPLE-tier change: surgical, no opportunistic refactors.

## Approach
- `find -mtime +N` reads the entry's OWN mtime and `+N` means strictly older than N×24h — semantically equal to the old `newest < NOW - N*86400` test but without scanning descendants. Decision #2 accepts the one behavior change: a dir touched only deep-down keeps its old top-level mtime and is GC'd at the window — harmless because no larch run lives anywhere near 7 days.
- One combined `/tmp` `find` with an `-name` OR clause replaces the 19 separate glob expansions, fixing the second aggravator on a 16k-entry `/tmp`.
- Top-level entry counts are small, so the per-entry delete loop has no fork storm; the storm came only from the removed depth-5 `stat`-per-descendant scan.
- Makefile wiring closes the gap between documented `make test-cleanup` acceptance and CI: `.PHONY` already named the target but no recipe existed and `test-harnesses-12` only ran `test-cleanup-tmpdir`.

## Edge cases
- `/tmp` symlinks matching a pattern: now skipped by `! -type l` (old code could `rm -f` a symlink-to-file). This strengthens "never delete through a symlink".
- `/tmp` plain files (`larch4-review.diff`, `commit-msg-*-review.txt`, ...): still deleted by age — `! -type l` matches regular files and `rm -rf` removes them; `stale-tmp-file-removed` still passes.
- Empty match set: the `while read` loop runs zero times; counts stay 0.
- `TMP_PATTERNS` is always non-empty, so `\( "${_find_name_args[@]}" \)` never expands to nothing (bash 3.2 `set -u` array-expansion safety).
- `(( CACHE_REMOVED++ )) || true` is retained: the first post-increment returns the pre-value 0 (exit status 1) and would trip `set -e` without the guard.
- Missing `CACHE_DIR` / `TMP_ROOT`: guarded by `[[ -d ... ]]`; `find`'s `2>/dev/null` and the loop `|| true` swallow transient races.

## Failure modes
- `find` rejects the `-mtime` / `! -type l` / `\(...\)` `-name` grouping on this platform → all deletions silently no-op (counts 0). Earliest signal: `stale-dir-removed` / `stale-tmp-dir-removed` start asserting 0. Mitigation: the existing cache `find -mindepth 1 -maxdepth 1` already runs on macOS BSD find; probe the new predicate locally per the verify-external-tool-invocations rule; the harness removal/keep cases catch a broken predicate.
- Over-deletion if `! -type l` is dropped or `-mtime` is AND-ed with only the first `-name` (mis-parented group) → unintended `/tmp` entries match. Earliest signal: `nonlarch-tmp-untouched` and `symlinked-session-dir-skipped` fail. Mitigation: keep the explicit `\( ... \)` group and `! -type l`.
- A genuinely deep-active but top-level-stale session dir is deleted earlier than an operator expects mid-debug. Signal: operator surprise. Mitigation: accepted by decision #2 (7-day window); documented in `SKILL.md` / `cleanup.md` / `SECURITY.md`.
- `make test-cleanup` invoked before Makefile wiring → "No rule to make target". Mitigation: this PR adds the recipe and `test-harnesses-12` prerequisite.
