## Findings

1. **architecture — `skills/implement/references/step2-dispatch.md:32`**: The canonical Step 2 contract still says external launchers must not emit the Step 2 token mark. The plan inverts that without listing this reference file. Update the contract and any text-pinning harness in the same change.

2. **correctness — `python/larch/agents/_ci_launcher.py:709-918`**: The proposed launcher helper needs the same once-only semantics the dispatcher already has. Without skipping on `--answers-file` and/or an existing ledger mark, Q/A resume and the `step2-dispatch` launcher retry path can write multiple Step 2 token marks in one run.

3. **risk-integration — `python/larch/report/tokens.py:2739-2740`**: Mark visibility cannot rely on nonzero exit codes alone. A missing ledger is currently a silent no-op with rc 0. Treat unresolved or unwritten ledgers as a warning path, not an optional check.

4. **correctness — `python/larch/report/tokens.py:1007-1016`**: The raw-label fallback is only safe if misclassified rows are removed from their enclosing Step 0 slice before the synthetic Step 2 row is added. The plan names the risk but should pin that subtraction in the `_per_step_json` procedure and test Step 0 totals, not only Step 2 presence.
