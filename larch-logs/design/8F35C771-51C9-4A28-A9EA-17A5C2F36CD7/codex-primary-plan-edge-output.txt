1. **[correctness] `scripts/ci-wait.sh:67-71` / `scripts/ci-wait.sh:171`**  
The plan says to add `larch_quiet_write_paired_pid_file` after the existing `larch_quiet_init` + `larch_quiet_append_done_trap` pair, but `ci-wait.sh` later installs its own `EXIT` trap at line 171. That overwrites the lib-quiet done trap, so a paired monitor would still never see `LARCH_DONE_SENTINEL` become non-empty. Revise the plan so `ci-wait.sh` chains both traps, preferably by installing `larch_quiet_append_done_trap` after the custom output trap is defined.

2. **[correctness] `scripts/dispatch-with-waterfall.sh:177-221`**  
The monitor will signal only the top-level PID written by the paired script. That is insufficient for Family B scripts that launch child processes and wait on them. `dispatch-with-waterfall.sh` starts per-slot subshells and launcher processes in the background; killing only the dispatcher can leave those launchers running. Add process-tree cleanup, process-group signaling, or explicit TERM traps in child-spawning Family B scripts.

3. **[security] `scripts/lib-quiet.sh:204-207`**  
The proposed helper writes to `$LARCH_PAIRED_PID_FILE` after only absolute-path / `..` validation, while the monitor contract requires session tmpdir scope and symlink rejection. That creates an arbitrary file overwrite surface through inherited environment. Make the helper enforce the same canonical session-root and symlink checks as `breadcrumb-monitor.sh`.

4. **[risk-integration] `scripts/lint-foreground-markers.sh:345-349`**  
The planned lint token `export LARCH_PAIRED_PID_FILE` is too broad. It permits a fence that merely exports an inherited or stale value, which undermines the “fresh per-launch PID file” invariant. Tighten the lint rule to require a same-fence `mktemp` allocation under the session tmpdir, and test that a bare export fails.
