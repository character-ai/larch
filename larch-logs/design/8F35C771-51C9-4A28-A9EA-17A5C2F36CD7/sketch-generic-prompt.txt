ISSUE #2848: Breadcrumb publish pipeline duplication and monitor exit gap

## Problem (paraphrased from issue body)

(1) `scripts/design-log-publish.sh` and `scripts/larch-log.sh` previously duplicated breadcrumb staging/redaction/atomic-mv logic between `design_publish_breadcrumbs` and `larch_log_publish_breadcrumbs`. Confirm no residual copy-paste remains between the two scripts (manifest writers, file enumerators, error reporters, etc.) and consolidate any genuine remaining duplication in this PR.

(2) `scripts/breadcrumb-monitor.sh:163-168` exits with code 4 after a 30-minute (1800s) timeout without signaling or stopping the paired background script. Plan-review collectors use `--timeout 1860` (31 minutes) which is LONGER than the monitor's timeout — so when monitor exits, the background script continues running with no breadcrumb consumer, leaking processes. Add cleanup so the monitor signals the paired background process on timeout exit.

## User-resolved scope (Round 1 decisions)

1. **Item (1) scope**: Audit + close any residual duplication via a quiet side-by-side sweep of `design-log-publish.sh` vs `larch-log.sh` / `lib-larch-log.sh`. Consolidate any genuine remaining duplication in this PR's diff (no separate audit report).

2. **Pairing mechanism (item 2)**: Add a `--paired-pid-file <PATH>` flag to `breadcrumb-monitor.sh`. Callers allocate `$LARCH_PAIRED_PID_FILE` (mktemp under `$DESIGN_TMPDIR/breadcrumbs/` and analogous tmpdirs), export it before the background launch, and pass `--paired-pid-file` pointing at the same path to the monitor. Long-running scripts write their own `$$` to that file at startup when `LARCH_PAIRED_PID_FILE` is set in the environment. Backward-compatible (opt-in: if no flag, no signaling).

3. **Signal strategy**: On monitor timeout — send SIGTERM to the paired PID, wait 5 seconds grace, then SIGKILL if still alive. Standard graceful-shutdown pattern.

4. **Adoption scope**: Update ALL current paired callsites in one PR. This means: (a) every Family B long-running script (`collect-agent-results.sh`, `ship-pr.sh`, `run-step5-review.sh`, `ci-wait.sh`, etc.) writes `$$` to `$LARCH_PAIRED_PID_FILE` at startup; (b) every SKILL.md fenced block that pairs a background launch with `breadcrumb-monitor.sh` allocates the env var and passes `--paired-pid-file` to the monitor.

5. **Lint enforcement**: Update `scripts/lint-foreground-markers.sh` (and its test harness) to enforce the new contract — every Family B fenced block must allocate `LARCH_PAIRED_PID_FILE` and pass `--paired-pid-file` to the paired monitor. Hard contract going forward (CI-blocking).

6. **Missing pid-file fallback**: When the monitor times out and `--paired-pid-file` was provided but the file is missing/empty/malformed, log a `WARN paired-pid-file-missing` breadcrumb and proceed with the current exit code 4 (no escalation, no kill attempt). Most defensive.

7. **Audit shape**: Quiet sweep folded into the PR diff. No separate audit report file.
