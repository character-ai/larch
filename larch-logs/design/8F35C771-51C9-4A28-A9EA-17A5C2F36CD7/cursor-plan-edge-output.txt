**1. [correctness] `scripts/breadcrumb-monitor.sh:5-10`** — The proposed `larch_bm_signal_paired_pid` runs under `set -euo pipefail`. Any `kill`/`kill -0` against a stale or already-exited PID returns non-zero and can abort the monitor before `exit 4`, leaving the Family B background process running and defeating the orphan fix. **Suggested revision:** guard all kill/poll calls with `|| true` (or a local `set +e` block) and always proceed to `exit 4`; add a harness case for ESRCH/stale PID.

**2. [correctness] `scripts/test-breadcrumb-monitor.sh:88` (plan)** — The plan references both `LARCH_TEST_OVERRIDE_TIMEOUT` and `LARCH_BM_TEST_TIMEOUT_SECONDS` for the same hook. **Suggested revision:** standardize on one test-only env var end-to-end in code, docs, and the plan.

**3. [risk-integration] `skills/design/SKILL.md:470`** — Sketch-phase fences use Bash `timeout: 1260000` (21 minutes) while the monitor waits 1800 seconds (30 minutes). The host typically SIGKILLs the foreground monitor first, so the new paired-pid signaling path never runs and `collect-agent-results.sh` can remain orphaned. **Suggested revision:** align Bash timeout with monitor budget (or lower monitor timeout for sketch fences) and document the coupling in `BASH_AUTHORING.md`.

[correctness] `scripts/breadcrumb-monitor.sh:117-130`** — The plan’s WARN breadcrumb shape (`category=warn msg=…`) does not match `larch_bm_emit_line`, which parses `c=` fields and drops non-conforming lines. **Suggested revision:** use `larch_err`/`printf 'WARN …'` like existing monitor warnings, or emit `larch:bc … c=warn text=paired-pid-file-missing`; pin stdout in tests.
