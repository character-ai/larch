## Summary

The `/learn-from-bugs` digest parser recognizes only `##` and `###` Markdown headings. A structured bug body that uses `####` headings finds no sections, falls to the `_freeform` fallback, and is truncated at `FREEFORM_CAP`. The truncation drops exactly the root-cause and suggested-fix content the synthesis step needs. A second, related weakness: the section splitter ignores fenced-code state, so a heading-shaped line inside a code fence can act as a phantom section boundary. This issue is distinct from closed #6618, which fixed search over-selection; #6618 appears here only as the live body that exposed the parser gap.

## Original report

Operator request, verbatim: `--no-dedup I1, and /issue --no-dedup L1 + L2`.

Item I1 from the `/learn-from-bugs -n 10` report of 2026-07-11: "learn-from-bugs digester silently degrades sectioned bug bodies to truncated freeform. `_HEADING_RE` in `learn_from_bugs` matches only `##` and `###` headings. Bug bodies that use `####` headings fall through `_pick_sections` to the `_freeform` fallback and are truncated at `FREEFORM_CAP`, dropping exactly the root-cause and suggested-fix content the synthesis needs. `_split_sections` also ignores fenced-code state, so a `##` line inside a fenced block becomes a phantom section boundary; G-Md-3 names this exact hazard for Markdown heading parsers."

## Reproduction scenario

1. Run `python3 python/cli.py learn-from-bugs prepare --state closed --limit 10 --out <run-dir> --root <repo>` in a checkout whose closed bugs include #6618.
2. Read the `digest.jsonl` record for #6618.
3. The record shows `"structured": false` with a `_freeform` section truncated mid-sentence, although the issue body carries `#### Problem`, `#### Evidence`, and `#### Root cause` sections.

Observed live on the 2026-07-11 run (larch 52.5.33). No mutation is involved; the reproduction is read-only.

## Expected behavior

A bug body with recognizable section headings at common levels (h2 through h4) yields a structured digest: `"structured": true` with `root cause` (and, when present, `suggested fix`) sections kept under their per-section caps. Freeform truncation is reserved for genuinely unstructured bodies.

## Observed behavior

The #6618 digest record is `_freeform`, truncated at `FREEFORM_CAP` mid-sentence (the text stops inside "`BUG_TITLE_LIFECYCLE_PREFIXES`"). Its `#### Root cause` content is partially lost and its suggested-fix content never reaches the synthesis. The clustering step therefore reads less evidence than the issue actually contains, on exactly the issues that follow a sectioned layout at h4.

## Root cause analysis

Two causes, one observed and one inferred:

1. Observed: `_HEADING_RE` is `re.compile(r"^#{2,3}\s+(.+?)\s*$", re.MULTILINE)` (`python/larch/issue/learn_from_bugs.py:62`). It matches only h2 and h3. For an h4-sectioned body, `_split_sections` (`learn_from_bugs.py:252`) returns no named sections, `_pick_sections` (`learn_from_bugs.py:268`) picks nothing, and the body falls to `{"_freeform": _squeeze(prefix, FREEFORM_CAP)}` (`learn_from_bugs.py:282`). `WANT_SECTIONS` (`learn_from_bugs.py:46`) already lists `root cause`, so #6618's `#### Root cause` section would map today if the regex saw the heading.
2. Inferred, not yet observed in a live record: `_split_sections` runs the heading regex over the whole diagnostic prefix without tracking fenced-code state. A `##`-prefixed line inside a fenced block would register as a section boundary and swallow or split real sections. Guideline G-Md-3 names this hazard class for Markdown heading parsers, and the repo already carries `lint_markdown_heading_fence_state` for it.

## Evidence

- Live digest record from the 2026-07-11 run: `{"number": 6618, ..., "structured": false, "prefix_chars": 3413, "sections": {"_freeform": "... (`_bug_title`, `BUG_TITLE_LIFECYCLE_PREFIXES…"}}` (truncated mid-sentence at the freeform cap).
- Issue #6618's body is sectioned with `#### Problem`, `#### Evidence`, and `#### Root cause` headings.
- `python/larch/issue/learn_from_bugs.py:62`: `_HEADING_RE` restricted to `#{2,3}`.
- `python/larch/issue/learn_from_bugs.py:46-51`: `WANT_SECTIONS` includes `root cause`, so the miss is the heading level, not the section name.
- `python/larch/issue/learn_from_bugs.py:252-260`: `_split_sections` has no fence-state tracking.
- Contrast: #6604's body uses h2/h3-compatible headings and digested as `"structured": true` in the same run, which isolates the failure to heading level.

## Affected files

- `python/larch/issue/learn_from_bugs.py`: owns `_HEADING_RE`, `_split_sections`, and `_pick_sections`; both defects live here.
- `python/tests/issue/test_learn_from_bugs.py`: needs new fixtures for h4-sectioned bodies and for headings inside fences.

## Suggested fix(es)

1. Widen `_HEADING_RE` to heading levels 2 through 4 (`#{2,4}`). Keep the existing first-word dedup in `_pick_sections` so `root cause` still maps to a single section.
2. Track fenced-code state in `_split_sections` and ignore heading matches inside fences, per G-Md-3.
3. Add unit tests: an h4-sectioned body digests as `structured=true` with its `root cause` section; a heading-shaped line inside a fence does not create a section; existing h2/h3 fixtures stay byte-identical.
4. Acceptance sweep: re-run `learn-from-bugs prepare` over a selection containing #6618 and confirm its record becomes `structured=true` with the root-cause section retained.

Optional, larger recall follow-up (may be out of scope): map near-miss section names such as `Problem` onto `summary`. Flagged under Open questions rather than proposed here.

## Open questions

- Should near-miss heading names (`Problem`, `Evidence`) map onto the canonical sections, or stay unmapped? Mapping raises recall but risks misclassifying prose.
- Should h5 and deeper headings match too? Levels 2 through 4 cover every body observed in the 2026-07-11 run.

## Approved direction (outline)

## Proposed Design Outline

### Goals
- Recognize h2-h4 (`#{2,4}`) section headings in `/learn-from-bugs` bug-body digests.
- Ignore heading-shaped lines inside fenced code blocks when splitting sections.

### Non-goals
- Near-miss heading-name mapping (`Problem`->`summary`, etc.).
- h5 and deeper heading support.

### Approach sketch
- Widen `_HEADING_RE` in `python/larch/issue/learn_from_bugs.py` from `#{2,3}` to `#{2,4}`.
- Add fenced-code state tracking to `_split_sections` so heading matches inside fences are skipped, per G-Md-3.
- Preserve the existing first-word dedup in `_pick_sections` so `root cause` maps to one section.

### Surfaces in scope
- `python/larch/issue/learn_from_bugs.py`
- `python/tests/issue/test_learn_from_bugs.py`
