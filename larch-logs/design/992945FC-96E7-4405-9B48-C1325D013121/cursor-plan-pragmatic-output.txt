## 1. `review-core.sh` must always pass three canonical slots (blocking)

That is the exact compaction bug the plan describes. The fix belongs in `review-core.sh`, not only in `tally-code-votes.sh`.

## 2. Tally preamble and 0-judge branch need the same tiered logic (blocking)

The plan’s fixed `for slot in 0 1 2` loop is specified for the main ballot pass, but lines 421–448 still derive quorum from `${#VOTER_FILES[@]}` and compact into `EFFECTIVE_VOTER_FILES`. On Claude fallback (one real file plus two empty placeholders), that inflates thresholds to 2-of-3. The early 0-judge exit also writes rows without `vN_tool` / `body_severity` while the three-slot header expects 22 columns.

With three `tool=cursor` rows, that mapping is wrong, and the parallel Claude launch violates the settled “pure 3-Cursor when available” panel. The plan describes the target composition but should make this control-flow split explicit in `agent_voters.py`.
