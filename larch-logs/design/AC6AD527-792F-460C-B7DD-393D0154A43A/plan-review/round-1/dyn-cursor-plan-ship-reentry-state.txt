## Review summary

The plan places de-terminalization at the right point: after `_resume_plan` and `_blocked_resume_result`, and before any branch can call `flush_logs_pre` (including `reconcile_committed_stalled_summary_if_recovered` on the `merged` path at `ship.py:1315-1321`). It preserves resume inputs by deriving the target phase from `ResumePlan.start`, not from stale `PHASE=stalled`. It keeps prompt-side writers untouched and does not relax `_flush_guideline_outcome_before_pr` / `_flush_invariant_outcome_before_pr` fail-closed allowlists (`ship.py:273-284`).

### Finding 1 (major): `RunContext.stall_tracking` must be cleared for Fix 2

The plan says `STALL_TRACKING=false` but does not require clearing `RunContext` before `_write_ship_state`. That is required on the live reship path because `dispatch_ship._ship_pre_fix_context` seeds `stall_tracking` from the stalled state file.

### Finding 2 (minor): symlink `finalize-state.sh` must fail closed

The plan’s symlink edge case is correct on security grounds, but refusal alone is incomplete: `_read_state_file` still reads symlink targets (`_tokens.py:177-184`), so `_stall_signal_is_terminal` can remain true (`_normalize.py:184-188`). The helper should stall when finalize cannot be removed as a regular file.

### Finding 3 (minor): classifier routing needs a concrete rule

Fix 3 and acceptance criterion 5 require `_classify.py` updates. The plan lists the file but not the matching rule. A narrow matcher for the new reason (preserving `transient-infra` / `step8-shippr` for the pre-PR refresh deadlock shape) avoids observability regressions if state reset is partial.

### What the plan gets right

- **Timing**: Insertion at `run_ship` after `ship.py:1305-1308` is before `fresh` postbump flush (`1391`), guideline refresh (`_flush_guideline_outcome_before_pr`), and merged reconcile flush.
- **Phase mapping**: `fresh` → `pr-prep`, `pre-pr-compose`/`open-pr` → `assessments` (`config.SHIP_ROUTE_ACTION_ASSESSMENTS`), `merged` → `postmerge` matches existing writers (`ship.py:1324-1331`, `1457-1464`).
- **Pre-terminal guard**: New reason mirrored into `REFRESH_SKIP_MERGE_OK` like `REFRESH_SKIP_COMMIT_FAILED` preserves existing merge-refresh semantics; guideline/invariant flush sites still stall on any non-allowlisted skip (`ship.py:273-284`). `_check_preterminal_outcome_label` / forbidden labels stay unchanged per plan.
- **Post-merge / done resumes**: De-terminalize only when `PHASE=stalled`; `done` and blocked starts return before flush; merged reconcile runs only after the reset point.
- **Commit retry**: Factoring `git add` → `diff --cached --quiet` → `git commit` from `_commit_run` (`run_log_commit.py:497-506`) with a single retry matches the failure mode analysis (copy/scrub before tail).
