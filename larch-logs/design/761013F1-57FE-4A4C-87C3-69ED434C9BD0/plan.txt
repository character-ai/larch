Implement two repo-local lint ratchets under the existing `python/larch/lint/` pattern. Use direct codebase inspection because `approach-synthesis.txt` is `NO_SKETCHES`.

## Approach

- Mirror `lint_lifecycle_prefix_literal.py` and `lint_tempfile_dir.py` for the renderer lint.
- Mirror `lint_shared_convention_regex.py` for the guidelines-note bypass lint.
- Keep both lints read-only, stdlib-only, and registered through `python/cli.py`.
- Add both names to the `py-lint-checks-fast` loop. Do not add a CI job.
- Document both under `docs/linting.md`.
- Add focused tests under `python/tests/lint/`.
- For renderer test-reference coverage, match whole identifiers only. Do not use bare substring search; a name like `_vendor_rows` must not be satisfied by `_progress_vendor_rows` in test text.

### NEW: python/larch/lint/lint_renderer_golden_tests.py

Implement `cli.py lint renderer-golden-tests`.

Behavior:

- Scan only top-level `FunctionDef` and `AsyncFunctionDef` nodes in `python/larch/report/*.py`.
- Match function names where `name.startswith("_render_") or name.endswith("_rows")`.
- Treat a function as covered when any file under `python/tests/report/*.py` contains the function name as a whole identifier.
- Whole-identifier matching rules:
  - Compile one boundary-safe pattern per candidate name, for example `re.search(r"(?<![A-Za-z0-9_])" + re.escape(name) + r"(?![A-Za-z0-9_])", text)`.
  - Do not use bare `name in text`.
  - Apply the same boundary rule across all test files read for coverage.
- Skip symlinks and non-files.
- Validate parse/read failures as tool failures, exit `2`.
- Support same-line suppression only:
  - `# lint-renderer-golden-tests: ok <reason>`
  - Empty or missing reasons do not suppress.
- Use baseline file `python/renderer-golden-tests-baseline.json`.
- Baseline row schema:
  - `file`
  - `function_name`
  - `reason`
- Normalize `file` relative to `python/`, for example `larch/report/progress_report.py`.
- Reject malformed baseline rows, extra keys, missing reasons, duplicates, invalid paths, and stale baseline rows.
- Exit behavior:
  - `0` when no unbaselined live findings exist and no stale baseline rows exist.
  - `1` when new unbaselined renderers or stale baseline rows exist.
  - `2` for malformed baseline, bad args, parse/read failures, or duplicate live identities.
- `--write` should preserve reasons for still-live rows and fail closed when a live finding has no preserved reason and no `--initial-reason`.
- `--initial-reason` must be non-empty when supplied.
- Emit diagnostics that name the file, function, and missing test reference.

Important identity choice:

- Use `(file, function_name)` only.
- Do not include line numbers.

## Edge cases

- A helper named `*_rows` may not render user-facing output. Keep it baselined, not excluded, because round 1 resolved the broad predicate.
- A longer identifier that contains a shorter candidate name as a substring must not count as coverage. Example: `_progress_vendor_rows` must not satisfy `_vendor_rows`.
- A test may reference a function name in a comment. This is accepted by design when the comment contains the whole identifier. The lint is a presence ratchet, not a fixture-quality verifier.
- Renaming a renderer may create one stale baseline row and one new finding. This is useful. It forces either a test reference or a reason-preserving baseline update.
- Suppression comments in string literals must not suppress findings. Use `tokenize` comments, as existing lints do.
- The guidelines lint should not flag the owner helper in `ship_guidelines.py`; that file owns the legacy helper and wrapper sequence.
- Do not scan tests for guidelines bypass calls. Tests may need direct fixture calls.

## Failure modes

- `py-lint-checks-fast` can fail on the current tree if the renderer baseline is not seeded from the same predicate and identifier-matching rules used by the lint.
- Substring-style test matching would let unreferenced `*_rows` helpers such as `_vendor_rows` pass while only a longer sibling name appears in tests. Whole-identifier matching closes that hole.
- A stale baseline implementation that silently drops missing live rows would weaken the ratchet. Make stale rows an exit `1`.
- A broad AST search could flag definitions instead of calls. Limit the bypass lint to `ast.Call`.
- A raw text search for `_invalidate_guidelines_note(` would risk false positives in strings and comments. Use AST for the bypass lint.
- If `--write` assigns a generic reason to new rows during routine regen, the baseline can grow silently. Preserve reasons and fail closed unless `--initial-reason` is explicitly supplied.
