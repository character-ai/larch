1. [correctness] `scripts/ship-pr.sh:1229-1234`: the plan uses shell `rc` from the launcher call to decide tier success. The CI launchers document and implement a wrapper contract where runtime failure is reported as `LAUNCHER_EXIT=<int>` on stdout while the wrapper exits 0 for non-validation failures. The new waterfall would silently stop after Cursor even when Cursor timed out or auth failed. Revise the plan to capture launcher stdout separately from diagnostics, parse `LAUNCHER_EXIT`, and drive tier fallback from that value.

2. [risk-integration] `scripts/gh-run-logs.sh:41-53`: the proposed `[ -s "$gh_logs_fail_file" ]` guard is not enough. `gh-run-logs.sh` writes the GitHub Actions URL header before it knows whether logs are available, so rc=3 still leaves a nonempty file. Pass the `gh-run-logs.sh` rc or a boolean alongside the path, and only inject `--failure-log` on rc=0.

3. [code-quality] `scripts/ship-pr.sh:1220-1246`: the plan keeps one `output` path for all tiers, then appends `${output}.token-record` after the first tier that appears successful. A failed tier can leave stale sidecars under that shared basename. Use per-tier output paths or clear sidecars before every tier attempt.

4. [architecture] `scripts/ship-pr.sh:50-55`: path-only dirty snapshots are not enough for rollback. The conceptual `git restore --staged` plus `git checkout` rollback can destroy tracked edits that existed before the failed tier. Either restore from a content/index snapshot or refuse to run tier rollback when tracked dirt exists at function entry.

5. [security] `scripts/launch-cursor-ci.sh:94-120`: `--failure-log` will carry untrusted CI output into the agent prompt. The plan should require delimiter-based prompt construction and explicit “untrusted log data” handling in the launchers, not just argv forwarding from `ship-pr.sh`.
