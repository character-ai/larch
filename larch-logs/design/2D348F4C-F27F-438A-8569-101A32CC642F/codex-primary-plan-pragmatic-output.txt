1. **[correctness] `scripts/ship-pr.sh:1227-1239`**
The plan’s tier success/failure decision is based on `$?` from `launch-*-ci.sh`, but the existing Cursor and Codex CI launchers emit `LAUNCHER_EXIT=<n>` and then `exit 0` for tool runtime failures. That means a failed Cursor tier will look successful to `run_ci_fix_vendor`, preventing Codex/Claude fallback and allowing post-success handling to run.

Suggested revision: capture launcher stdout into the existing failure log, parse `LAUNCHER_EXIT`, and make tier status depend on that value when wrapper rc is 0. Keep wrapper rc 2 as validation failure. Add a regression where the launcher exits wrapper 0 with `LAUNCHER_EXIT=124` or `1`, and assert the next tier runs.

2. **[safety] `scripts/ship-pr.sh:50-55`**
The rollback plan relies on path-only dirty/untracked snapshots. That is safe for newly-created untracked files, but not for tracked files that were already dirty at function entry. If a failed tier edits one of those paths, a path-delta rollback cannot restore the original dirty content; excluding it leaks failed-tier changes into the next tier, while `git checkout --` would discard the operator’s pre-existing work.

Suggested revision: either fail/stall before the waterfall when tracked dirty baseline is non-empty, or snapshot exact pre-tier tracked content and restore to that baseline after a failed tier. Add a regression for “pre-existing tracked dirty file modified by failed tier is preserved exactly before the next tier starts.”
