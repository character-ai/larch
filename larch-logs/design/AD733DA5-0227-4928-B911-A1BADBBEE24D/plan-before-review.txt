## Approach

Implement the approved combined Step 8 assessment round with minimal routing churn.

Use `architectural-assessments` as the Python `needs_user_reason`. Map it to `NEXT_ACTION=assessments`. Put the requested kinds in `ShipResult.detail` as `invariants`, `guidelines`, or `invariants,guidelines`.

In `ship.py`, add a small private helper for compose-time gates. It should:

- Snapshot `HEAD` and the compose base once per pass, then run invariant and guideline gates against that same snapshot.
- Run invariants first.
- Still evaluate guidelines when invariants need assessment, so both materialized inputs exist before one combined pause.
- Return the old invariant-violation path unchanged.
- Return `ShipResult(Outcome.NEEDS_USER_INPUT, needs_user_reason="architectural-assessments", detail=<kinds>)` when any assessment is needed.
- Preserve absent, invalid, dropped, redaction, and outcome-sidecar behavior per gate.
- Preserve both durable notes, write wrappers, outcome JSON sidecars, and PR-body sections.

Replace the current pre-PR compose two-phase state writes with one `_write_ship_state(..., phase="assessments", ...)` before the combined gate pass. Apply the same combined assessment return path in `_refresh_guidelines_gate_after_rebase`.

Keep back-compat for runs already paused on old tokens:

- Keep dispatch mappings for `architectural-invariants-assessment` and `architectural-guidelines-assessment`.
- Keep old `invariants-assessment` and `guidelines-assessment` SKILL branches for one release.
- Add the new `assessments` branch before them.

## Edge cases

- Both files present and both notes stale: one pause, `DETAIL=invariants,guidelines`.
- One file absent or invalid: the other file can still request assessment through the combined action.
- Invariant violation: keep old `architectural-invariants-violation` behavior.
- Old paused run: old per-kind `NEXT_ACTION` still completes.
- `HEAD` changes after materialization: existing write wrappers still fail and force Step 8 rematerialization.
- Outcome sidecar write or dropped outcome failure: keep fail-closed stall behavior before PR compose.

## Failure modes

- If `DETAIL` is missing or malformed for `assessments`, the SKILL handler should fail closed as Tool Failure rather than guessing kinds.
- If one writer fails, do not run later writers or relaunch Step 8 with a partial stale note.
- If both writers succeed, relaunch Step 8 once. Do not relaunch after the first writer.
- If route-exit emits an old per-kind action, run the old handler and do not require `DETAIL`.
