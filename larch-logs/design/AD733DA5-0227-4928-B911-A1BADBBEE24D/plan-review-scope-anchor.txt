From the 2026-07-09 audit of the architectural-knowledge features.

**Current behavior.** `python/larch/implement/ship.py` runs two separate compose-time assessment phases: `phase="invariants-assessment"` (line 1367 at fb6d61294) and `phase="guidelines-assessment"` (line 1399), pausing Step 8 with `NEEDS_USER_REASON=architectural-invariants-assessment` and `...=architectural-guidelines-assessment` respectively. `skills/implement/SKILL.md` lines 679-680 handle each `NEXT_ACTION` separately: read the reference file, author the draft from the materialized diff, run the write wrapper, relaunch `step-8-ship.sh` through the Step 8 bgjob start/wait pair. Invariants run first. In a repo with both files present (every larch run), Step 8 executes three times: initial run, post-invariant relaunch, post-guideline relaunch.

Both assessments consume the same final diff (merge-base to HEAD, `larch-logs/` excluded), materialized twice into `architectural-invariant-materialized-diff.txt` and `architectural-guideline-materialized-diff.txt` with separate env sidecars.

**Required change.** One combined assessment round.

1. When Step 8 needs any compose-time assessment, `ship.py` materializes all needed inputs (invariant and guideline) in a single exit with one combined `NEXT_ACTION` (for example `architectural-assessments`), listing which kinds need authoring.
2. The orchestrator handler authors all needed drafts in one turn (invariants first), runs each existing write wrapper (`step-architectural-invariants-write-compose.sh`, then `step-architectural-guidelines-write-compose.sh`), then relaunches Step 8 once.
3. Preserve unchanged: the two separate durable notes and meta sidecars, the two outcome JSON sidecars and their schemas, the validators in `architectural_guidelines.py`, independent absent-or-invalid handling per file (one file may be absent while the other is present), HEAD-drift rematerialization semantics, and the PR-body sections (`## Architectural invariants`, `## Architectural guidelines`).
4. Single-kind runs (only one file needs authoring) go through the same combined action with one kind listed.
5. Back-compat: a run paused mid-flight on an old per-kind `NEXT_ACTION` must still complete. Either keep accepting the old actions for one release or document the migration in the exit matrix.
6. Update: `skills/implement/SKILL.md` lines 679-680 (collapse to one handler), `skills/implement/references/architectural-invariants-present.md` and `architectural-guidelines-present.md` (merge or cross-link into one combined contract), `skills/implement/references/ship-pr-exit-matrix.md`.
7. Tests: `python/tests/implement/test_ship.py` route-exit coverage for the combined action; `scripts/test-implement-structure.sh`; `skills/implement/scripts/test-architectural-guidelines-step.sh`.

**Benefit.** One fewer full Step 8 relaunch per `/implement` run (bgjob round-trip plus orchestrator turn), on every run.

**Acceptance criteria.**

- A run needing both assessments pauses exactly once for them.
- The merged PR body still contains both sections; sidecar schemas byte-compatible with existing readers.
- A resumed run paused on the old per-kind action completes.

## Proposed Design Outline

### Goals
- Reduce Step 8 relaunch count by one: when both assessments are needed, exit once with a combined reason instead of twice.
- Keep all artifact schemas, PR-body sections, and outcome sidecars byte-compatible.
- Preserve back-compat for runs paused on the old per-kind `NEXT_ACTION` tokens.

### Non-goals
- Do not merge the two durable-note schemas or write wrappers.
- Do not change Phase A staging, conflict-fix paths, or CI-fix no-rerun constraints.
- Do not create a new merged reference file; cross-link only.

### Approach sketch
- In `ship.py` (`_refresh_guidelines_gate_after_rebase` and `run_ship` compose block): run both gates before any early exit; if either needs assessment, return one `ShipResult(needs_user_reason="architectural-assessments", detail=<comma-separated kinds>)` with a single `_write_ship_state(phase="assessments")` call.
- In `dispatch_ship.py`: add `"architectural-assessments"` → `"assessments"` mapping; keep old per-kind mappings.
- In `ship_resume.py`: add `"assessments"` to the pre-PR-compose resume set.
- In `SKILL.md` lines 679-680: add `assessments` handler before the old back-compat handlers.
- In `ship-pr-exit-matrix.md` and the two present-reference files: document the combined token and cross-link.
