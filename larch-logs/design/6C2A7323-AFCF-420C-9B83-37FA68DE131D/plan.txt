## Edge cases

- Brainstorm requested but no external slots launch: do not call `--mode collect`; synthesize from parent-written or Claude-only outputs, then call `--mode complete` on terminal.
- External launch attempted but failed before usable output exists: still call `--mode collect` with the intended canonical output path so the wrapper can ingest the launcher-owned stderr sink.
- Collect called for only one vendor: ingest only that vendor's launch failure sink and ignore any stale sink for the other vendor.
- Brainstorm skipped on resume: `--mode entry` must write `.completed/step-1d.5` exactly once and must not require the top-level complete fence.
- Active brainstorm resume with a pause request pending: `--mode entry` must pause before external launches or collection.
- `jq` absent: run-params parsing must still detect `"brainstorm_requested": true`.
- Collector exits non-zero: `--mode collect` must still log collector failure, parse any stdout records, inspect sidecars, run the checkpoint, and exit 0.
- Collector exits 0 with a failed per-slot status: log each non-OK result and continue synthesis from readable outputs.
- Collector failure after one external succeeds: log the collector failure, preserve available output, parse any stdout records, and let the parent synthesize from readable outputs.
- Launch failure before usable output exists: `launch-review.sh --stderr-sink` must create the canonical launch failure log that collect scans.
- Prompt-side launch handling must not append launch failures directly. Otherwise collect can duplicate the same issue.
- `launch-review.sh --stderr-sink` must skip direct `append_launch_failure` for brainstorm launches while preserving no-sink behavior.
- Dirty-tree sidecar reports dirty or unknown: write `dirty-tree-detected.env` with `STAGE=brainstorm-collection` and `RECOVERY_REQUIRED=true` before synthesis.
- Dirty-tree checkpoint fails, reports dirty, or reports unknown: merge checkpoint evidence into the same recovery env and warn.
- Dirty-tree recovery prompt already fired for this boundary: do not fire it again on resume.
- Step 2b.5 wrapper returns Bash rc 0 with `PLAN_SIZE_HANDLED=true`: caller must not treat this as a successful plan size rc 0.
- Step 2b.5 wrapper must print preserved stdout plus `PLAN_SIZE_RC=` before callers depend on it.
- Validator auto-fix status missing or unknown: normalize to `failed`, log a warning, and fall through to the operator prompt.
- Validator Override logging must preserve the call-site site value, validation log evidence, and boolean redaction flag.
- Validator Override logging must not pass valued redact args to `run-log append-failure`.

## Failure modes

- If `design-step1d5.sh --mode collect` is invoked with zero paths, exit 2. This catches prompt drift.
- If collector stdout parsing sees malformed blocks, log only well-formed non-OK records and preserve the full collector output for inspection.
- If warning append fails, suppress that append failure with `|| true` to preserve current degraded behavior.
- If dirty-tree evidence exists, do not continue to synthesis while `RECOVERY_REQUIRED=true`.
- If `plan check-size` emits stderr noise, do not mix it into parseable stdout. Store it only in the validation log.
- If Step 2b.5 cannot find `PLAN_SIZE_RC=` in wrapper stdout and `PLAN_SIZE_HANDLED=true` is absent, treat it as wrapper drift rather than falling back to the Bash tool rc.
- If `--record-override` is called without `--site`, exit 2 rather than recording an unattributed warning.
- If `--record-override` receives a valued `--redact` argument, exit 2 rather than forwarding unsupported argv.
- If `--record-override` cannot find the validation log file, record with the requested path and preserve current degraded behavior rather than dropping site attribution.
- If `launch-review.sh --stderr-sink` cannot write its sink, preserve the original launch failure output and rc.
- If the structural lint flags documentation examples that are not orchestrator-facing, narrow scope rather than adding broad suppressions.
