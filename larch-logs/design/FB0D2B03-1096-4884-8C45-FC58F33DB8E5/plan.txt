**Fix B: Gate post-notification complete routing on `.completed/step-3`.** Add the accepted reviewer finding to the Step 3 routing contract. After `<task-notification>`, do not route `STEP3_REVIEW_LOOP_STATUS=complete` or a loop-mode synthesized `LOOP_STATUS=complete` to Step 3b unless `$DESIGN_TMPDIR/.completed/step-3` exists. **Fix C: Clear stale per-round state before automatic continuation.** Clear `.step3-review-result.env` before automatic round-2 continuation starts in `run_design_step3_loop()`. This removes the stale per-round file so any remaining incorrect waiter cannot fire on round-1 state. Because `review-design-step3-loop.sh` is in `_RETIRE_DESIGN_SKIPS`, regenerate the gzip-embedded `_LEGACY_ASSETS` entry in `python/plan_review.py` from the edited source so `plan-review run --mode loop` materializes the fix at runtime.

**Hook allowlist: Permit only the sanctioned terminal waiter.** Add a dedicated `bash_is_step3_recovery_waiter` predicate checked immediately after `bash_is_strict_wrapper_only` and before the live-marker deny loop. The sanctioned orchestrator waiter is not wrapper-routed, so putting the allowlist in `bash_segment_is_wrapper_routed` cannot work. The new predicate must match the full command as an atomic `until [ -f "$DESIGN_TMPDIR/.completed/step-3" ]; do sleep N; done` loop with no probe verbs, no trailing `&&` / `||` / `;` commands after the loop, and no `.step3-review-result.env` sentinel. **Verify-only: No Step 6 mutation.** Do not add `kill-background-processes` before `session cleanup-tmpdir` in `design-step6-cleanup.sh`. Fix A, Fix B, and Fix C address the stale-sentinel root cause. Document existing behavior instead: `design-step3-review.sh`'s EXIT trap already calls `session kill-background-processes` after `wait "$_loop_pid"` returns; `python/finalize.py` kills before tmpdir deletion on the finalize path. `session_env.cleanup_tmpdir_main` remains a plain rmtree helper.

## Edge cases

- **Spurious task notification**: do not route `complete` unless `.completed/step-3` exists. Use the sanctioned one-time waiter when the sentinel is absent.
- **Zero accepted findings**: the continuation path is not taken; no env clearing is needed.
- **Continuation helper failure**: preserve the existing failure envelope; `rm -f` runs only on the `PLAN_REVIEW_CONTINUE=true` branch.
- **MainAgent or operator handoff**: the handoff exits before the continuation branch; `.step3-review-result.env` is preserved for prompt-side routing.
- **Symlinked result env**: `rm -f` unlinks the symlink path, not its target.
- **Embedded blob drift**: if `plan_review.py` blob is not regenerated after source edit, integration tests and the new drift harness fail.
- **Hook allowlist too broad**: require exact `.completed/step-3` suffix and reject probe verbs or trailing commands.
- **Hook PID mismatch**: if the `.bg-wait-active` marker is absent or stale, the hook exits 0 regardless of the waiter pattern; the new predicate is defense-in-depth when the marker is live.
- **Legacy single-mode harnesses**: keep legacy mapping behavior separate from loop-mode post-notification fallback. The new terminal gate applies to loop-mode complete routing after the background Step 3 fence.

## Failure modes

- **Missing terminal gate**: a stale `.step3-review-result.env` with `LOOP_STATUS=complete` can still advance the orchestrator into cleanup while round 2 is running.
- **Hook predicate in wrong tier**: placing the allowlist in `bash_segment_is_wrapper_routed` leaves bare orchestrator waiters denied.
- **`bash_first_sync_segment` truncation**: a segment-based matcher can truncate at the first semicolon and miss the full loop. The dedicated predicate must evaluate the full command string.
- **Clearing too early**: if `.step3-review-result.env` is removed before `step3_loop_run_continuation` reads it, `plan-review-continuation.sh` loses required input. The `rm -f` runs after `step3_loop_run_continuation` returns.
- **SKILL.md anti-polling count**: adding a third exact `NEVER poll .step3-review-result.env` literal breaks the count assertion.
- **Fix C not shipped**: editing only the on-disk `.sh` without regenerating `_LEGACY_ASSETS` leaves the live CLI on stale behavior.
