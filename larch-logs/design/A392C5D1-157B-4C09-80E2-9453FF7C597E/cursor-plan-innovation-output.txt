### 1. architecture — `scripts/reviewer-prune.sh:59-297`
**[SCOPE-REDUCTION]** The plan describes porting `reviewer-prune.sh` (~296 lines) as bash, but the file is already a thin wrapper around ~240 lines of inline Python. Re-porting from bash risks behavioral drift. Minimum change: lift the heredoc into `review_pipeline.py` and port only `lib-prune-decision.sh` (~100 lines of real bash).

### 2. risk-integration — `python/plan_review.py:802-836`
Step 4 correctly mirrors the waterfall `_decode_legacy_asset` pattern for embedded prune cutover. The plan must forbid re-encoding gzip blobs from `legacy_asset_bytes()` output (post-substitution). Prior `/design` work established that raw retired markers must survive in `_LEGACY_ASSETS`; prune edits should use decode-time substitution first, raw-blob regeneration second.

### 3. correctness — `python/legacy_review_shell/review-core.sh:83-85`
Today's `review-core.sh` defaults gather/dispatch/collect/check to sibling scripts under `python/legacy_review_shell/`, which step 6 deletes. The plan should explicitly require native `review_core` to call the ported Python functions in-process. Retained `aggregate-findings.sh` / tally / emit paths can still flow through `review_legacy` or `cli.py review …` façades.

### 4. risk-integration — `Makefile:845-846`
The plan retargets `test-reviewer-prune` and `test-lib-prune-decision` but omits `test-check-reviewer-failure-threshold`, whose `-k` filter still includes `run_legacy_relays`. After `run_legacy` leaves `review_pipeline.py`, that target needs an explicit pytest retarget or relay tests silently disappear from the shard.

### [OUT_OF_SCOPE] 5. architecture — `python/review_legacy.py` (proposed)
A separate `review_legacy.py` is reasonable but not required. Keeping a small façade-only relay in `review_pipeline.py` until aggregate/tally/compose port would reduce file surface without changing runtime behavior. Worth a tracked follow-up only if the team wants fewer modules, not a blocker for G1.
