## Findings

### 1. architecture — `python/larch/issue/_ground_truth.py:377-391`

The issue scope lists four dual-manifest loops in `_ground_truth.py` (lines 263, 277, 293, 378). The plan migrates started_at and larch_version only. `_ground_truth_run_ended_at` remains a copied dual-name loop. The planned `lint run-log-walkers` ratchet rejects that pattern outside `run_log_corpus.py`, so `ground_truth.py` would fail the new lint unless the plan adds a shared `run_ended_at` helper or narrows the ratchet.

**Suggested revision:** Add `run_ended_at` (or shared dual-manifest ended/completed/updated_at reads) to `run_log_corpus.py`, repoint `_ground_truth_run_ended_at`, and test precedence/fallback alongside `run_started_at`.

### 2. architecture — planned `run_log_corpus.discover_classifications`

`discover_classifications` is described as a log-root triple-glob. Callers use two shapes today: log-root discovery (`_ground_truth.py:231-241`, `_voting_calibration.py:546-558`) and per-run TSV discovery with **numeric** round sorting in `difficulty_calibration.py:255-266` versus **lexicographic** `sorted(glob)` in rejected_analysis and ground_truth. Unifying without two entry points or an explicit sort policy would change round processing order (e.g. round-10 before round-2 lexicographically).

**Suggested revision:** Add a per-run `classification_tsv_paths(skill, run_dir, *, round_sort=...)` API plus log-root `discover_classifications(log_root)`; pin sort policy per caller in the plan and tests.

### 3. correctness — planned `run_started_at`

Non-strict callers (`_ground_truth.py:262-273`, `_voting_calibration.py:529-540`) return on the first JSON object manifest even when both `started_at` and `updated_at` are absent. They do not fall through to `run-manifest.json`. The plan covers malformed-json fallback and strict `started_at`-only mode but not this empty-field short-circuit.

**Suggested revision:** Specify and test that `run_started_at` advances to the alternate filename only when the preferred candidate is missing, symlink, unreadable, malformed, or non-object—not when timestamp fields are simply empty.

### 4. correctness — `skills/fluff-analysis/scripts/fluff-analysis.py:95-109`

`manifest_started` reads only `manifest.json` / `started_at`. `manifest_larch_version` reads only `manifest.json`. That is narrower than `rejected_analysis._run_started_at`, which also accepts `updated_at` and `run-manifest.json`. Replacing with shared helpers using default dual-name/`updated_at` behavior would change cutoff and version filtering despite the plan’s “unchanged fixture counts” goal.

**Suggested revision:** Pin fluff-specific flags (`allow_updated_at=False`, manifest.json-only if required) at each call site and add a regression fixture.

### 5. correctness — `python/larch/calibration/difficulty_calibration.py:223-227`

The difficulty scanner distinguishes `missing_skill_roots` (resolve failure) from `unreadable_skill_roots` (`glob` OSError). The shared `_safe_child_run_dirs` only handles resolve failures. Adopting it verbatim can turn a counted skip into an uncaught exception.

**Suggested revision:** Map `glob` OSError to `unreadable_skill_roots` in the walker or adapter, with a unit test.
