## Edge cases

- A review artifact may have only `run-manifest.json`; metadata helpers must still read it.
- If both manifest names exist, `manifest.json` must win.
- `load_run_manifest` must continue rejecting a run that has only `run-manifest.json`.
- A malformed preferred manifest may require checking the alternate candidate, matching current dual-loop callers.
- Strict ground-truth verdict filtering must not accept `updated_at` when `started_at` is absent.
- Review classification files still need caller-owned schema validation.
- GC must scan safely even when a run lacks an accepted manifest, because it can recover the date from Git.
- JSONL fallback sources are caller-specific and must not disappear when TSV discovery moves to the shared helper.
- The lint must not classify run-log writers, fixed artifact lookups, or session-local paths as corpus walkers.
- The lint exemption must remain limited to the three files scheduled for deletion by #7008.

## Failure modes

- A helper return-type change could alter date comparisons, panel labels, or round identities.
- Applying manifest acceptance to review artifacts could silently drop valid `run-manifest.json` data.
- Replacing GC enumeration with manifest-filtered `run_dirs` could hide malformed runs from retention.
- Overbroad lint matching could block legitimate artifact code. Narrow tests must cover negative cases.
- Underbroad lint matching could allow another copied walker. Positive fixtures must cover each forbidden traversal shape.
- The skill scripts can fail outside the checkout if imports bypass their existing plugin-root bootstrap.
