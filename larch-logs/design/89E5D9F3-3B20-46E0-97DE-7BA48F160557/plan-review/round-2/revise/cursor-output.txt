## Plan

## Approach

Implement count-only prompt-size instrumentation in Python with one centralized artifact router, opt-in panel gating, explicit panel-env producers at every panel dispatch entrypoint, and locked concurrent appends.

- Add helpers in `python/larch/report/tokens.py`.
- Log one TSV row per launched panel slot.
- Store only counts and safe identifiers:
  - skill or site.
  - round number when known.
  - slot kind: `specialist`, `plan-review`, `voter`, `aggregator`, `implementer`.
  - slot/tool/output basename.
  - prompt bytes and estimated tokens.
  - agent-file repo path, bytes, and estimated tokens when an agent file exists.
- Never store rendered prompt text.
- Keep logging best-effort. Catch read/write/lock errors and continue dispatch.
- Use the same `(len(text) + 3) // 4` estimate used by skill-closure metrics.
- Reuse the existing `TokenLedger` `fcntl` flock pattern (`TOKEN_LOCK_TIMEOUT_S`, skip-on-timeout) for header creation and row appends so parallel panel dispatch cannot corrupt a shared TSV.

**Single artifact authority**

All writes route through `append_panel_prompt_size(...)` plus `panel_prompt_size_artifact_for_output(...)`. Launchers must not hardcode `Path(args.output).parent / "panel-prompt-sizes.tsv"`.

`panel_prompt_size_artifact_for_output()` resolution order:

1. `LARCH_PANEL_ARTIFACT_DIR` when set and valid: `<dir>/panel-prompt-sizes.tsv`.
2. Parsed `plan-review/round-<N>` from `LARCH_PANEL_ROUND_DIR` or an output path under that tree.
3. For implement/review round-local outputs already under `round-<N>/`, use that round directory.
4. Fall back to `output.parent` only when steps 1–3 do not apply.

Design plan-review rows must land only under `plan-review/round-<N>/panel-prompt-sizes.tsv`. Do not commit a top-level `$DESIGN_TMPDIR/panel-prompt-sizes.tsv`.

**Opt-in panel gating**

Prompt-size logging runs only when `LARCH_PANEL_SLOT` is non-empty and classified `slot_kind` is one of: `specialist`, `plan-review`, `voter`, `aggregator`, `implementer`. Unknown or missing panel context skips logging. This excludes non-panel `agent launch-review` / `agent launch-claude-review` callers such as `plan_scout`, plan-autofix (`plan_quality`), and `decompose`.

Panel dispatch producers must set the env block (or pass `--panel-artifact-dir` into `dispatch-waterfall`) before any panel child launch. Do not infer panel logging from default `site` alone inside `agent_waterfall`; that would risk instrumenting out-of-scope waterfall callers.

**Shared producer helper**

Add `build_panel_dispatch_env(...)` in `tokens.py` returning a child-env dict merged with `os.environ`. All panel producers call this helper so artifact dir, site, round keys, and per-slot `LARCH_PANEL_SLOT` stay consistent across design plan-review, `/implement` Step 5, and `/review`.

**Env contract** (set by panel dispatchers, forwarded through `agent_waterfall` `Popen` and direct voter launches):

- `LARCH_PANEL_SLOT`
- `LARCH_PANEL_PHASE`
- `LARCH_PANEL_PRIMARY_TOOL`
- `LARCH_PANEL_SITE`
- `LARCH_PANEL_ROUND_NUM` (when known)
- `LARCH_PANEL_ROUND_DIR` (design plan-review round directory or implement/review `round-<N>` when applicable)
- `LARCH_PANEL_ARTIFACT_DIR` (preferred TSV parent; usually equals `round_dir` for design and implement round-local paths)
- `LARCH_PANEL_SOURCE_AGENT_FILE` (repo-relative agent path for prompt_file-backed slots such as aggregator)

Use `env={**os.environ, ...}` for subprocess launches.

**Artifact basename:** `panel-prompt-sizes.tsv`

**Committed paths:**

- `/implement` Step 5: `larch-logs/implement/<RUN_ID>/round-<N>/panel-prompt-sizes.tsv`.
- `/review`: `larch-logs/review/<RUN_ID>/panel-prompt-sizes.tsv` when tmpdir is run-root; `larch-logs/review/<RUN_ID>/round-<N>/panel-prompt-sizes.tsv` when dispatch uses a round directory.
- `/design`: `larch-logs/design/<RUN_ID>/plan-review/round-<N>/panel-prompt-sizes.tsv` only.

Add `python3 python/cli.py token measure-panel-cost`.

- Scan committed `panel-prompt-sizes.tsv` files under design `plan-review/round-*`, implement `round-*`, and review run logs.
- Ignore design top-level `panel-prompt-sizes.tsv` if present from legacy runs.
- Aggregate by `agent_file` when present.
- Also include generated/no-agent buckets so voters and generated plan-review prompts are not dropped.
- Output TSV sorted by realized bytes descending.
- Include dispatch count, runs observed, loads per run, prompt bytes/tokens, agent bytes/tokens, and total realized bytes/tokens.

## Edge cases

- Missing prompt file: skip logging for that slot.
- Missing agent file: log prompt bytes and leave agent fields blank or zero.
- Prompt render failure: no row is required because no rendered prompt exists.
- Missing `LARCH_PANEL_SLOT`: skip logging (decompose, scout, plan-autofix).
- Missing producer panel env: skip logging; producers must set env or `--panel-artifact-dir` explicitly.
- Waterfall fallback: log the actual launched tier, not every possible tier, when launcher-side context is available.
- Multiple rounds: append rows to the same round-scoped TSV with `round_num`.
- Design top-level exclusions: keep `panel-prompt-sizes.tsv` in `plan-review/round-N/` only; voter/aggregator rows must not remain at `$DESIGN_TMPDIR` root.
- Implement/review round dirs: when `review_tmpdir` is already `round-N`, artifact dir is that directory; otherwise use run-root tmpdir or `round-N` subdirectory per dispatch conventions.
- Fix-coder implementer: local panel context in `apply_findings_with_coder` must not depend on unrelated parent env and must not instrument `/implement` Step 2 feature coder.
- Code-review aggregator: code mode must set `LARCH_PANEL_SOURCE_AGENT_FILE=agents/orchestrator-aggregator.md` like plan mode.
- Concurrent appends: flock timeout skips the row best-effort; dispatch continues.
- Lock unavailable (non-Unix): degrade to unlocked append with warning, matching `TokenLedger` import fallback.

## Failure modes

- Logging write or lock fails: dispatch still proceeds.
- Aggregation sees old logs without the TSV: skip them.
- TSV row is malformed: skip that row.
- No panel prompt logs exist: command writes header-only TSV and exits 0.
- A future prompt source is generated, not file-backed: aggregate it in a generated bucket so frequency is still visible.
- Stray top-level design TSV from pre-fix runs: aggregation ignores it; publish flow does not commit it.
- Panel env omitted at a producer: that path produces no rows; tests on `review_dispatch_panel`, `agent_voters`, `coder_runner`, and code-mode `review_aggregate` guard against silent omission.
