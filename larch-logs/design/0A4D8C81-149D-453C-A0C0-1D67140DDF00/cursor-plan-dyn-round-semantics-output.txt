**1. [correctness]** Design `oos` count source (`plan.txt` §`plan-review-loop.sh`, proposed `_emit_round_timing_row`)

The plan requires accepted OOS and points at `voting-tally.md` so security-accepted OOS that never reach `oos-accepted-design.md` are included. The proposed counter is `grep -cE '^\| OOS_[0-9]+ \|'`, which matches every OOS row in the Findings table:

```470:479:skills/design/scripts/tally-plan-review.sh
    printf '## Findings\n\n'
    printf '| Item | YES | NO | Exon | JERR | Result |\n'
    ...
        printf '| %s | %s | %s | %s | %s | %s |\n' "$id" "$TALLY_YES" "$TALLY_NO" "$TALLY_EXONERATE" "$TALLY_JUDGE_ERROR" "$result"
```

Rejected OOS (e.g. tests at `skills/design/scripts/test-tally-plan-review.sh:204`) still appear in that table. **Suggested revision:** count rows where Item matches `OOS_<n>` and Result is `accepted` (awk/`grep` on the Result column), and update the planned `test-timing-report.sh` design fixture accordingly.

**2. [correctness]** Design timing emit on snapshot-failed terminals after successful post-apply (`plan-review-loop.sh:1506-1526`)

The plan’s late-emit rule is tied to `_run_post_apply_pipeline` returning (lines 60-63 in `plan.txt`). After a successful post-apply, `_snapshot_round_dir` can still fail and exit via convergence/cap-hit (1517-1521) or `panel-failed`/`snapshot-failed` (1525-1526). Those `_terminal_exit` paths are not listed in the plan’s emit checklist. **Suggested revision:** name those branches explicitly and require `_emit_round_timing_row` immediately before each terminal `_snapshot_*` / `_terminal_exit` there, using the same artifact greps as other late emits.
