## Implementation Plan — per-review-round timing in timing-report.json (#3488)

SIMPLE tier: smallest change that adds a per-round `rounds` sub-array to the
Step 5 (implement code review) and Step 3 (design plan review) `per_step`
entries in `timing-report.json`, with per-round `duration_seconds`,
`accepted`, and `rejected` for both skills, plus accepted `oos` for design.

### Goal (binding scope, from Round 1)
- Per-round `duration_seconds` AND `accepted`/`rejected` counts are mandatory for both skills (hard-required).
- `/design` rounds additionally carry an accepted-OOS `oos` count.
- JSON + run-log flush + tests only. No markdown `## Per-Step Durations` change; no `/report-tokens` or other analysis-tool change; no new flush site; no backfill.
- `rounds` is purely additive; no existing field renamed/removed.

### Architecture (key facts established by codebase research)
- `timing-report.json` is rendered from the session timing-ledger TSV by `scripts/timing-report.sh` (`refresh-run-logs.sh:78` runs `timing-report.sh --full --format json`, then `larch-log.sh --batch timing-report` commits it). So per-round data must live in the **ledger** to reach the committed batch. No new flush site is needed.
- Ledger rows are fixed at **13 tab-columns**; `timing-report.sh row_ok()` skips any row with `NF != 13` and dispatches by column 2 (`mark`/`vendor`/`workflow`). A new `round` row kind must be exactly 13 columns and is naturally ignored by the markdown path.
- The implement Step 5 round loop is `run_implement_loop` in `review-implement-step5-loop.sh` (sourced by `review-and-fix.sh`); it calls `_implement_round_body` once per round. `_implement_round_body` already computes `accepted_count`/`rejected_count` (from review-core `ACCEPTED_COUNT`/`REJECTED_COUNT`).
- The design Step 3 round loop is `while (( round_num <= ROUND_CAP ))` in `plan-review-loop.sh`; `_run_plan_review_round` is the round body. Per-round accepted/rejected counts come from `$DESIGN_TMPDIR/accepted-plan-findings.md` and `rejected-findings.md` (same greps as ~1456–1457). Per-round **accepted OOS** counts come from `voting-tally.md` Findings rows (`grep -cE '^\| OOS_[0-9]+ \|'` with `[[ -f ... ]]` guard) so security-accepted OOS that never land in `oos.md` are included; do **not** count `oos.md` (rejected-OOS prose) for `--oos`.
- The OOS count must filter `voting-tally.md` by Result = `accepted`, not merely by `OOS_N` item id. Use awk/pipe-field parsing with trimming (or an equivalent anchored regex that requires the Result column to be `accepted`) so rejected/exonerated OOS rows are excluded while security-accepted OOS rows still count.
- Parent step marks: implement `Step 5 — code review` (existing Step 5 mark before `run-step5-review.sh`; timing-only re-mark when `--starting-round` > 1 — see below); design `design Step 3 — plan review`. JSON attachment requires **skill + recorded `round_step` label + interval**: `emit_round_array(skill, step, s, e)` keeps a row only when `round_skill == skill`, `round_step == step`, and `round_start ∈ [s,e)`. Prevents resumed Step 5 rounds or Step 7 intervals from stealing rows. Gate-C re-entry still yields distinct parent-mark intervals per pass.
- `design-publish.sh` calls `design-log-publish.sh` before `render-final-summary.sh`, which today renders `$DESIGN_TMPDIR/timing-report-final.json` post-publish; publish copies top-level tmpdir files, so Gate-C must render fresh timing JSON **immediately before** `design-log-publish.sh` when `SESSION_ID` is set. Remove stale timing-report-final artifacts first (or render to a fresh temp and move only on success), then run `LARCH_TIMING_SKILL=design timing-report.sh --full --format json --output …/timing-report-final.json`; warn on non-zero or empty output. `render-final-summary.sh --post-publish-only` remains for chat/summary only.
- Main-agent handoff paths are special for both skills: do **not** append a preliminary round row with fallback `0/0` counts. **Implement**: both `main-agent-vote-required` and `coder-main-agent-required` persist the original round start in the round directory, exit the loop without emitting, and defer exactly one `record-round` until the Step 5 orchestrator finishes prompt-side adjudication/apply, relevant checks, lint repair, and commit — immediately before re-invoking `run-step5-review.sh --starting-round`. Counts come from post-handoff round artifacts (`review-tally.env` or accepted/rejected finding greps), never from loop-exit `IRF_LAST_*`. **`run_implement_mav_apply` stays coder-apply-only** (no timing row). **Design**: `main-agent-vote-required` persists start, skips loop emission, and emits one row from `skills/design/SKILL.md` after inline re-tally (existing plan).
- Backward compat verified: timing-report batch validation is `none`; `measure-realized-cost.sh` and `python/report_tokens_scan.py` read timing-report.json via `.get()` and tolerate the additive field.

## Approach
Place per-round timing+counts in the ledger as a new 13-column `round` row kind, emitted once per round when final counts and wall time are known. `timing-report.sh` attaches by skill + recorded step label + each mark's own interval; nested child steps use per-child bounds, not outer implement filters. Implement loop rows use `IRF_LAST_*` only on in-loop terminal paths; **`main-agent-vote-required` and `coder-main-agent-required` defer** until `skills/implement/SKILL.md` finishes prompt-side handoff work and calls `record-implement-review-round-timing.sh` with post-tally artifact counts. Design loop rows use the shared helper with zero-safe greps; design MAV defers to `skills/design/SKILL.md`. Implement resumes re-mark Step 5 timing-only when `--starting-round` > 1. Gate-C renders fresh `timing-report-final.json` before publish. Emission is strictly best-effort (`|| true`).

## Edge cases
- `end_s < start_s` (clock skew): clamp `duration_s` to 0 in `record-round` (mirrors vendor rows).
- No round rows for a step: `emit_round_array` prints nothing, so the per_step entry is byte-identical to today (backward compatible).
- Parent step mark absent: round rows match no interval and are silently omitted from JSON (they still exist in the ledger). The emitters use the canonical parent labels and interval matching to minimize this.
- Gate-C re-entry: distinct parent-mark intervals; pre-publish timing render picks up all ledger rows through Step 5c.
- Step label mismatch / wrong interval: triple-match drops orphan round rows rather than attaching to Step 7 or another skill interval.
- Resumed implement Step 5 (`--starting-round` > 1): without a timing-only re-mark + `round_step`, round 2+ could fall outside any Step 5 interval or into Step 7's interval — mitigated by `run-step5-review.sh` timing mark + `emit_round_array` step equality.
- Implement round rows never carry `oos`; the report omits the field for them.

## Failure modes
1. **Round row attached to wrong `per_step`** (skill-only interval match) → Step 5 rounds appear under Step 7 or another interval. Signal: `rounds` on unexpected step. Mitigation: `round_step` column + `emit_round_array(skill, step, …)`; implement resume re-mark; fixture with Step 5 / Step 7 / Step 5.
2. **Count drift** (artifact heading format changes or OOS result parsing wrong) → wrong accepted/rejected/oos. Signal: per-round counts disagree with `voting-tally.md` / `review-tally.env`. Mitigation: accepted/rejected greps + accepted-only OOS Result-column parsing; tests assert accepted, rejected, and exonerated OOS cases.
3. **Round duration under-count** → `rounds[].duration_seconds` misses checks/lint or revise/post-apply time. Signal: round duration much smaller than wall-clock review work. Mitigation: late `_round_end` immediately before each terminal/continue path after post-round work.
4. **Stale or missing handoff counts** → implement MAV/coder-main rows record loop-exit `0/0` or wrong totals. Signal: ledger row predates re-tally / prompt-side apply. Mitigation: persist start, defer emission to `skills/implement/SKILL.md`, read `review-tally.env`/round artifacts in `record-implement-review-round-timing.sh`; forbid `IRF_LAST_*` and loop-body emission for both handoff statuses.
5. **Handoff duration under-count** → deferred row emitted from `mav-apply` or loop exit before prompt-side checks/lint/commit. Signal: round duration excludes post-handoff wall time. Mitigation: emit immediately before `--starting-round` re-invoke only.
6. **Stale timing JSON in published design logs** → committed `timing-report-final.json` missing late Step 4/5 marks and round rows. Signal: publish artifact predates final ledger or survives a failed render. Mitigation: remove stale output/fresh-temp render before `design-log-publish.sh`, warn on missing/empty output.
7. **Telemetry failure aborts the loop** → would break `/implement` or `/design` mid-review. Mitigation: `|| true` on every `record-round` and timing-report render; never gate loop control flow on telemetry.
