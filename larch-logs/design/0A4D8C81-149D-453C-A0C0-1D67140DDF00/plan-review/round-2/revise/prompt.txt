## Approach
Place per-round timing+counts in the ledger as a new 13-column `round` row kind, emitted once per round by the two existing review loops at the points where counts are already available. `timing-report.sh` attaches by skill + recorded step label + interval; implement resumes re-mark Step 5 when `--starting-round` > 1. ## Edge cases
- `end_s < start_s` (clock skew): clamp `duration_s` to 0 in `record-round` (mirrors vendor rows).
- No round rows for a step: `emit_round_array` prints nothing, so the per_step entry is byte-identical to today (backward compatible).
- Parent step mark absent: round rows match no interval and are silently omitted from JSON (they still exist in the ledger). The emitters use the canonical parent labels and interval matching to minimize this.
- Gate-C re-entry: distinct parent-mark intervals; pre-publish timing render picks up all ledger rows through Step 5c.
- Step label mismatch / wrong interval: triple-match drops orphan round rows rather than attaching to Step 7 or another skill interval.
- Resumed implement Step 5 (`--starting-round` > 1): without re-mark + `round_step`, round 2+ could fall into Step 7's interval — mitigated by `run-step5-review.sh` mark + `emit_round_array` step equality.
- Implement round rows never carry `oos`; the report omits the field for them.
- Design timing emit must not run before revise on paths that will revise (under-counts wall time); early emit only on skip-revise branches.
- Design `_emit_round_timing_row` must not grep bare artifact basenames or `oos.md` for accepted OOS; use `voting-tally.md` with `[[ -f ... ]]` guards.
- Markdown / `--summary` / `--terse` unaffected: `round` rows are not `mark`/`vendor`/`workflow`, so those code paths ignore them.

## Failure modes
1. **Round row attached to wrong `per_step`** (skill-only interval match) → Step 5 rounds appear under Step 7 or another interval. Signal: `rounds` on unexpected step. Mitigation: `round_step` column + `emit_round_array(skill, step, …)`; implement resume re-mark; fixture with Step 5 / Step 7 / Step 5.
2. **Count drift** (artifact heading format changes) → wrong accepted/rejected/oos. Signal: per-round counts disagree with `voting-tally.md` / `review-tally.env`. Mitigation: accepted/rejected greps + OOS from `| OOS_N |` tally rows; tests assert counts.
3. **Design duration under-count** → sum of `rounds[].duration_seconds` < parent Step 3 duration. Signal: rounds emitted before revise/post-apply. Mitigation: late `_round_end` on revise paths only.
4. **Stale timing JSON in published design logs** → committed `timing-report-final.json` missing late Step 4/5 marks and round rows. Signal: publish artifact predates final ledger. Mitigation: pre-publish render in `design-publish.sh`.
5. **Telemetry failure aborts the loop** → would break `/implement` or `/design` mid-review. Mitigation: `|| true` on every `record-round` and timing-report render; never gate loop control flow on telemetry.
