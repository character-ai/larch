**1. [correctness]** `record-implement-review-round-timing.sh` rejected fallback vs `emit-tally.sh` output shape

The plan’s fallback is `^FINDING_[0-9]+_OUTCOME=rejected$` on `rejected-findings.md`. Today `emit-tally.sh` builds that file with `grep -n`, so lines look like `2:FINDING_1_OUTCOME=rejected` (see `skills/review/scripts/emit-tally.sh:105-112` and `larch-logs/implement/.../round-1/rejected-findings.md`). The anchored pattern never matches when `review-tally.env` is missing—the case the plan’s harness explicitly covers.

**2. [correctness]** `timing-report.sh` must thread step intervals into `emit_round_array`

Round attachment is keyed on `round_start ∈ [step_start, step_end)` (`plan.txt` lines 27-31). `emit_json_step` today closes the object in one printf (`scripts/timing-report.sh:368-370`) and callers in `emit_json_report` / `emit_json_child_steps` (`385-410`) never pass `s`/`e`. Without a signature/call-site change, `emit_round_array` cannot implement the contract (especially nested design child steps called out at plan line 36).

**3. [correctness]** Design MAV `round-start-s` vs snapshot pruning

On `main-agent-vote-required`, `plan-review-loop.sh` calls `_snapshot_terminal_exit_preserving_status` → `_snapshot_round_dir` (`403-410`, `319-400`). That loop deletes every file under `plan-review/round-N/` except `revise/` (`380-384`) before repopulating from session-root allowlist artifacts. Persisting only to `plan-review/round-$round_num/round-start-s` (plan lines 100-103) is erased before `skills/design/SKILL.md` deferred timing (lines 111-116). The plan’s allowlist fix (`lib-design-round-artifacts.sh`) is necessary but conflicts with the “persist under plan-review/round-N/” wording unless the start file is also written at an allowlisted session-root path before snapshot.
