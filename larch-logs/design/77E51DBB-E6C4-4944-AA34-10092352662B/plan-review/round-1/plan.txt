# Implementation Plan — /design plan-size gate: split add/delete thresholds, relax mechanical churn (#3175)

## Summary

Make the `/design` Step 2b.5 hard plan-size gate key on estimated ADDED lines instead of total churn. Deletions never trip it. A self-declared `mechanical_churn: true` trailer downgrades the diff gate to a soft advisory. The change is additive and backward compatible: the required final `diff_lines: <N>` trailer and its ~41 consumers are untouched, and plans without the new trailers reproduce today's behavior byte-for-byte.

Settled directions (Step 1c/1d):
- New OPTIONAL trailers `diff_added: <N>`, `diff_deleted: <N>`, `mechanical_churn: true`, placed in the final contiguous metadata block immediately ABOVE the still-required last-line `diff_lines: <N>`.
- Hard diff trigger fires on `diff_added > 2000` (strict `>`) when `diff_added` is present; otherwise legacy `diff_lines > 1500`.
- Deletions (`diff_deleted`) are informational only — never a trigger, no cap.
- `mechanical_churn: true` suppresses the diff hard trigger and emits a SOFT advisory instead (no Split/Cancel).
- `plan_lines > 800` plan-body hard trigger is UNCHANGED and is NOT affected by `mechanical_churn` or deletions (out of scope per Round 1).

Core threshold logic. After the existing `diff_lines:` last-line validation (unchanged), add a full-file scan for the three optional trailers and recompute the diff trigger.

- Keep lines 1-90 (argv, `larch_design_tmpdir_validate`, plan/last-line/`diff_lines:` trailer validation, `plan_lines` computation) exactly as today. Exit codes 2/3 and `PLAN_SIZE_STATUS` paths unchanged.
- Parse optional trailers only from the final contiguous metadata block immediately above the required final `diff_lines:` line. The block consists only of strict trailer lines for `diff_added`, `diff_deleted`, or `mechanical_churn`; scanning stops at the first non-trailer line above `diff_lines:`. Within that block, last full-line match wins for duplicate keys, same strict grammar as `diff_lines` (literal token, exactly one ASCII space, then the value to end-of-line):
  - `diff_added` from lines matching `^diff_added: [0-9]+$` (digits). Empty when absent or malformed.
  - `diff_deleted` from lines matching `^diff_deleted: [0-9]+$` (digits). Empty when absent or malformed. INFORMATIONAL ONLY.
  - `mechanical_churn` from lines matching `^mechanical_churn: (true|false)$`. Normalize to `true` only on an explicit final `true`; otherwise `false` (covers absent and explicit `false`).
  Tabs / multiple spaces / non-digit values fail the anchored regex and are treated as absent; prose or code-block lines earlier in the plan do not count — mirror `emit-plan.sh` strictness (harness case 12 analog).
- Recompute triggers:
  - `hard_plan = (plan_lines > 800)` — UNCHANGED.
  - Raw diff hardness + reason basis: if `diff_added` non-empty → `hard_diff_raw = (diff_added > 2000)`, `diff_basis="diff-added"`; else → `hard_diff_raw = (diff_lines > 1500)`, `diff_basis="diff-lines"`.
  - Mechanical downgrade: if `mechanical_churn == true` → `soft_advisory = hard_diff_raw`, `hard_diff = 0`; else → `soft_advisory = 0`, `hard_diff = hard_diff_raw`.
  - `hard_trigger = hard_plan OR hard_diff`.
- `TRIGGER_REASONS` priority order: `plan-body-lines` (when `hard_plan`), then `$diff_basis` (when `hard_diff`). When `mechanical_churn` downgraded the diff trigger, no diff reason is added (only the advisory). Empty string when no hard crossing.
- Emit keys (exit 0): keep `HARD_TRIGGER_FIRED`, `TRIGGER_REASONS`, `PLAN_LINES`, `DIFF_LINES` (all as today). ADD always-emitted keys: `DIFF_ADDED` (integer or empty), `DIFF_DELETED` (integer or empty), `MECHANICAL_CHURN` (`true`/`false`), `SOFT_ADVISORY` (`true`/`false`).
- HIDDEN CONSTRAINT: do NOT name the advisory key `SOFT_TRIGGER_FIRED` and do NOT reintroduce `FILES_COUNT`. The harness string-splits both as retired keys and asserts their absence; use `SOFT_ADVISORY`. Keep `> 800` / `> 1500` / `> 2000` strict (equality does not trip).

## Approach

- Additive, backward-compatible contract: the final `diff_lines: <N>` line stays required and last, so `emit-plan.sh` (reads only the last non-empty line) and `design-driver.sh` (`ACTION=EMIT_PLAN` dispatch) need NO change. Verified: `design-driver.sh` never parses `diff_lines`; `diff-lines.txt` and `composed-plan.md` (Step 5c) keep using the total estimate.
- `plan-review-loop.sh` consumes only `HARD_TRIGGER_FIRED` (awk, line ~640) for the `plan-size-trigger` `LOOP_STATUS`. The mechanical/deletion downgrades yield `HARD_TRIGGER_FIRED=false`, which correctly avoids forcing a split mid-review-loop. No change needed there; cover with a spot-check.
- All threshold logic lives in `check-plan-size.sh`; the orchestrator (SKILL.md Step 2b.5) only learns to parse the new keys and print the advisory.
- Revision flows that rewrite `plan.txt` must preserve or recompute the optional trailers so a mechanical/deletion-heavy plan does not regress to legacy total-churn gating after Gate B or waterfall revisions.

## Edge cases

- `diff_deleted` present without `diff_added`: deletions are informational, so the gate uses the legacy `diff_lines` fallback; `diff_deleted` never affects the trigger.
- `diff_added` present, `diff_deleted` absent: fine — additions-keyed trigger applies; `DIFF_DELETED=` emitted empty.
- `mechanical_churn: true` with the diff already under threshold: `soft_advisory=0` (nothing to downgrade); advisory line not printed.
- `mechanical_churn: true` + `plan_lines > 800`: plan-body hard trigger still fires; the diff side may also set `SOFT_ADVISORY=true`. Both surfaces are coherent (hard prompt + advisory line that explicitly says the plan-body gate still requires Split/Cancel, not “proceeding”).
- Malformed optional trailer (`diff_added: 12x`, tab, double space): rejected by the anchored regex, treated as absent → legacy fallback. No exit-code change.
- Optional trailer text in prose/code blocks: ignored unless it appears in the final contiguous metadata block immediately above `diff_lines:`.
- Multiple `diff_added:` lines inside the final metadata block: last full-line match wins, mirroring the `diff_lines` last-line robustness (harness case 11 analog).

## Failure modes

1. **Silent gate bypass via stale parser.** If SKILL.md Step 2b.5 is not updated to parse `SOFT_ADVISORY`/`DIFF_ADDED`, the advisory is computed but never surfaced, so operators lose the signal. Earliest signal: advisory never prints on a known mechanical-churn plan. Mitigation: update Step 2b.5 parse + advisory print in the same change; `test-design-structure.sh` keeps the EMIT_PLAN→check-plan-size ordering honest.
2. **Backward-compat regression for the ~41 `diff_lines` consumers.** A grammar/last-line change would break `emit-plan.sh` and legacy plans. Earliest signal: `test-check-plan-size.sh` cases 1-13 or `test-emit-plan.sh` fail. Mitigation: keep `diff_lines:` last-line-required and lines 1-90 byte-stable; legacy cases stay green; do not touch `emit-plan.sh`.
3. **Retired-key collision.** Reintroducing `SOFT_TRIGGER_FIRED`/`FILES_COUNT` would clash with the harness retired-key asserts (and any drift lint). Earliest signal: `assert_no_key` failures. Mitigation: use `SOFT_ADVISORY`; leave the retired-key asserts in place.
4. **Revision-flow trailer loss.** Gate B or waterfall revision rewrites can preserve only `diff_lines:` and drop the optional trailers, converting a deletion/mechanical plan back into a legacy hard trigger. Earliest signal: a revised `mechanical_churn: true` plan returns `plan-size-trigger`. Mitigation: update revision prompts/contracts and add a focused preservation regression or spot-check.
5. **Plan-body spoofing.** Prose or code samples containing `mechanical_churn: true` could suppress the diff gate if the parser scans the whole file. Earliest signal: spoof-resistance regression fails. Mitigation: parse only the final contiguous metadata block above `diff_lines:`.
