# [BUG] Claude cost always priced at Opus 4.8 rates regardless of actual main-agent model

## Summary

When the Claude main agent runs on Sonnet 4.6 (or any model other than Opus 4.8), the cost reported in the PR body and `/report-tokens` is incorrect. `display_rates()` in `python/report_tokens_cost.py` always prices Claude tokens at Opus 4.8 list rates regardless of which model was actually used. Since the manifest already captures `model_roster.main` correctly (since #5099), the information to price accurately is available but never consulted during cost calculation.

## Original report

The user noted that they alternate between Opus 4.8 and Sonnet 4.6 as the main agent model. The cost reporting does not correctly take into account which model was used. Investigation confirmed that:

- `manifest.model_roster.main` is populated correctly from the session transcript (since #5099).
- `display_rates()` has no model parameter and always calls `_default_row("claude")`, which resolves to `DEFAULT_VENDOR_MODEL["claude"]` = `"claude-opus-4-8"`.
- `DEFAULT_RATE_TABLE_PER_M` has exactly one Claude entry: `("claude", "claude-opus-4-8")`.
- No Sonnet 4.6 (or other Claude model) entry exists in the rate table.
- No call site passes the manifest model to `display_rates()`.

Opus 4.8 runs are priced correctly by coincidence. Sonnet 4.6 runs are over-reported at Opus rates.

## Reproduction scenario

1. Start an `/implement` or `/design` run with the Claude main agent set to Sonnet 4.6.
2. Let the run complete and merge the PR.
3. Inspect the PR body "Run summary" section: `- **Main agent model**: claude-sonnet-4-6` is displayed correctly.
4. Inspect the reported cost: it is priced at Opus 4.8 rates ($5.00/$25.00 per M input/output) rather than Sonnet 4.6 rates.

Could not run an exact dollar-difference reproduction inline, but the code path is unambiguous.

## Expected behavior

Cost for the "claude" lane is calculated using the rate row matching `manifest.model_roster.main`. A Sonnet 4.6 run should use Sonnet 4.6 pricing; an Opus 4.8 run should use Opus 4.8 pricing.

## Observed behavior

All Claude main-agent tokens are priced at Opus 4.8 list rates regardless of the actual model. `display_rates()` always returns Opus 4.8 rates for the "claude" lane.

## Root cause analysis

Two independent gaps combine to produce the bug:

1. **Missing rate table entries.** `DEFAULT_RATE_TABLE_PER_M` in `python/report_tokens_cost.py` contains only one Claude model row: `("claude", "claude-opus-4-8")`. There are no rows for `claude-sonnet-4-6`, `claude-haiku-4-5`, `claude-fable-5`, or any other Claude model. `rate_row("claude", model="claude-sonnet-4-6")` therefore falls back to the Opus default (line 76).

2. **Model not threaded to `display_rates()`.** `display_rates()` (line 118) accepts only an `environ` parameter; it has no `model` parameter. It calls `_default_row("claude")` unconditionally. The manifest's `model_roster.main` is captured in `Manifest.synthesize_v2` (run_logs.py:210–211) and displayed in the PR body via `render_run_summary` (pr_body.py:445), but it is never passed to `display_rates()` or to `_pricing_from_counts()` at any call site.
