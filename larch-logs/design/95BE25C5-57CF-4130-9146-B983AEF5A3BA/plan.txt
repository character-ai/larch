## Approach

- Treat `NO_SKETCHES` as authoritative.
- Implement the approved Python-first routing change with the smallest viable surface.
- Add one deterministic ship exit router (`ship route-exit`) that consumes the durable Step 8 handoff sidecar (rc + validated driver JSON) and emits exactly one routing `NEXT_ACTION=` line on stdout.
- Add one deterministic OOS checkpoint router (`implement step-8-oos-checkpoint`) that runs disposition-checkpoint, owns success bookkeeping on rc 0, and emits exactly one `NEXT_ACTION=` on every path.
- Keep these prose-owned branches only:
  - `NEXT_ACTION=oos-pipeline`: run `/issue` pipeline, then checkpoint.
  - `NEXT_ACTION=ci-fix`: autonomous CI-fix edits (after escalation recording when `ledger_ready=true`, and only when `FORKED_TARGET` / `REPO_UNAVAILABLE` are false).
  - `NEXT_ACTION=operator-bail`: `AskUserQuestion`, then existing Step 12d path.
- Pin one durable post-ship handoff: `step-8-ship.sh` tees wrapper stdout to a capture file and an EXIT trap persists `.step-8-ship-handoff.rc` on every termination plus `.step-8-ship-handoff.json` only when the capture contains a parseable driver/guard JSON object; `ship route-exit` reads those sidecars, not immediate-background notification stdout.
- Narrow setup-failure contract: pre-`ship pr` paths that emit no schema JSON (`require_value` rc 2, `clone-tag` failure, etc.) persist rc only; SKILL halts with Tool Failures before `route-exit` when `.json` is absent. Guard rc 4 and `ship pr` paths must still land JSON in the capture so `route-exit` can emit post-driver `NEXT_ACTION=stall`.
- **Stale-json hygiene:** when the EXIT trap finds no parseable schema JSON in the current capture, unlink any existing `$IMPLEMENT_TMPDIR/.step-8-ship-handoff.json` before persisting rc-only sidecars so a fresh setup failure cannot pair a new `.rc` with driver JSON from a prior attempt.
- **Synchronous capture drain:** parse sidecar JSON only after the tee/capture pipeline is fully closed and drained. Do not rely on an EXIT trap that races `exec > >(tee …)` flush. Prefer explicit capture pipelines around guard and `ship pr` with `PIPESTATUS` (or equivalent) so the final guard/`ship pr` JSON line is on disk before extraction.
- Keep `/issue` invocation in prose. Move transient retry counter, exit-6 sleep, and retry-cap stall seeding into `ship route-exit` as the **sole** post-driver transient retry authority; gate the in-driver fourth-`TRANSIENT`→`STALLED` cap in `python/ship.py` on orchestrated runs so exit 6 reaches `ship route-exit`.
- Pin orchestration detection for the in-driver cap bypass: skip `_PYTHON_TRANSIENT_STALL_ATTEMPT` only when `ctx.expected_session_id` is non-empty (`step-8-ship.sh` always passes `--expected-session-id` from `$IMPLEMENT_TMPDIR/session-id`). Direct/cron `ship pr` callers without that signal keep in-driver `STALLED`/exit 4 on the fourth `TRANSIENT`.
- Split stall semantics explicitly:
  - **Pre-driver** `NEXT_ACTION=stall|halt-seed|halt-oos` from `ship pre-driver` (unchanged tokens).
  - **Post-driver** `NEXT_ACTION=stall` from `ship route-exit` → Step 16 default (with `ship_pr_pre_push` conflict-resolution sub-branch), then Step 18.
  - **OOS-checkpoint** `NEXT_ACTION=stall` → halt Step 8+ (no stats, no `OOS_PENDING=false`); **do not** reuse the post-driver Step 16 stall table row.
  - **Post-driver** `NEXT_ACTION=tool-failure` for exit 1 `INTERNAL_ERROR` → Tool Failures hard stop; no `[STALLED]` rename, no Step 18 stall recovery.
- Pin `ship route-exit` **process exit-code contract** (aligned with `checks repair-loop` parse-before-rc semantics): exit **0** whenever JSON validates, the handoff sidecar writes successfully, and `NEXT_ACTION=` is emitted; exit **non-zero** only when `NEXT_ACTION` is absent (malformed/missing JSON, missing required fields, missing rc sidecar, missing json sidecar when invoked, handoff sidecar write failure). Driver exit codes 1/3/4/6 are **inputs**, not propagated as `route-exit` process rc when routing succeeds.
- Pin `implement step-8-oos-checkpoint` **process exit-code contract**: exit **0** whenever `NEXT_ACTION=` is emitted (including bookkeeping-failure stall paths); exit **non-zero** only when `NEXT_ACTION` is absent (true parse/validation/invoke failures). - **Boolean KV normalization:** serialize handoff booleans as lowercase `true` / `false` in `.ship-route-exit-handoff.env` (at minimum `ledger_ready`); prose gates escalation only on `ledger_ready=true`.
- On OOS checkpoint disposition rc 0 with successful bookkeeping tail: mirror `oos_filer._after_checkpoint` success path: `_write_run_statistics` → `_stamp_manifest(..., value=True)` → merge-clear `OOS_PENDING=false` via allowed-key patch helper → emit `OOS_CHECKPOINT_RC=0` and `NEXT_ACTION=reship`.
- On OOS checkpoint disposition rc 0 bookkeeping failure: best-effort `_stamp_manifest(tmpdir, run_id, value=False)` before stall emission, matching `_after_checkpoint` failure hygiene.

## Edge cases

- Exit 0 with `outcome=OK` maps to `complete`; do not leave success outside the router.
- Malformed or missing driver JSON / handoff json sidecar when `route-exit` is invoked must fail closed; never infer continuation from `ship-pr-state.sh` or notification stdout.
- Setup failures without schema JSON: `.rc` only; unlink stale `.json` from prior attempts; SKILL Tool Failures before `route-exit`; do not invent driver JSON.
- Guard rc 4 `STALLED` JSON must be tee-captured with drain complete before extraction; EXIT trap alone cannot recover bytes not yet flushed.
- Exit 1 `INTERNAL_ERROR` maps to `tool-failure`, not `stall`; no Step 18 stall recovery rename.
- `ship route-exit` returns process rc 0 for driver exits 1/3/4/6 when classification succeeds; orchestrator gates on missing `NEXT_ACTION`, not driver rc.
- Rc sidecar is authoritative over notification memory / stale `--exit-code` argv.
- Exit 6 retry counting: absent `ship-pr-net-retries-python.count` means 0 before increment; **persist incremented value before reship**; fourth failure seeds `--stall-step transient-retry-cap --phase ci-initial` in route-exit; in-driver cap bypass requires non-empty `expected_session_id`.
- `ci-local-unfixable:*` matches by prefix; exact `local-unfixable` routes to `ci-fix`, not `operator-bail`.
- `NEXT_ACTION=reship` must not clear active `ship_pr_pre_push` conflict handoff keys until Phase 4 completes.
- Orchestrator must not sleep again when `RESHIP_DELAY_SECONDS=30` is present in sidecar.
- Pre-driver, post-driver, and OOS-checkpoint `stall` tokens share names but **different** SKILL routing.
- OOS checkpoint: disposition rc 1 remains disposition gap → `NEXT_ACTION=stall`, wrapper exit 0, no stats, no state clear.
- OOS checkpoint disposition rc 0 bookkeeping failure → best-effort `step9a1=false` stamp, `OOS_CHECKPOINT_RC` non-zero, `NEXT_ACTION=stall`, `OOS_PENDING` unchanged; never `OOS_CHECKPOINT_RC=0`.
- OOS checkpoint rc 2 / 126 / 127 / other non-zero disposition → `NEXT_ACTION=stall`, wrapper exit 0; child-written stderr log preserved when capture is empty.
- Empty OOS batches still write run-statistics with count 0 and stamp `step9a1=true` when full success tail completes.
- `filed_count` must use `larch-logs/implement/<RUN_ID>/oos-issues.ndjson`, not tmpdir-root ndjson.
- Multiline `detail` must land in `DETAIL_FILE`, not raw `DETAIL=` in `.env`.
- `ledger_ready` handoff values are lowercase `true`/`false`; prose compares `ledger_ready=true` only.
- `FORKED_TARGET=true` or `REPO_UNAVAILABLE=true` blocks autonomous ci-fix even when route-exit emitted `ci-fix`.
- `OOS_PENDING=false` must use `_patch_ship_state_keys`; never `_write_ship_state` `extra_fields` or single-key wipe.

- Legacy SKILL exit-code routing paragraphs and stale NEVER #14/#15 orchestrator contracts must not coexist with `ship route-exit` / checkpoint verb ownership.

## Failure modes

- Route-exit cannot read valid handoff sidecars or JSON / required fields → stderr diagnostic, non-zero exit, no `NEXT_ACTION`, orchestrator Tool Failures hard stop.
- Route-exit handoff sidecar write failure → fail closed same as parse failure.
- Missing `.json` after setup failure (or after stale-json unlink) → SKILL Tool Failures before route-exit (expected path, not route-exit failure).
- Stale `.json` retained across rc-only retry → mis-bucketed routing; prevented by EXIT unlink.
- Tee drain race → false rc-only sidecar on valid guard/ship JSON; prevented by synchronous capture drain.
- OOS checkpoint disposition rc 0 with stats write, manifest stamp, or `ship-pr-state.sh` patch failure → best-effort `step9a1=false`, `OOS_CHECKPOINT_RC` non-zero, `NEXT_ACTION=stall`, `OOS_PENDING` unchanged, process exit 0.
- OOS checkpoint wrapper propagating disposition rc → SKILL Tool Failures instead of OOS-checkpoint stall; prevented by Python-rc-only wrapper exit.
- OOS checkpoint wrapper erasing child-written validation stderr log → empty diagnostics on rc 2; prevented by preserve-nonempty-log contract.
- OOS checkpoint true invoke/validation failure (no `NEXT_ACTION`) → non-zero process exit, orchestrator Tool Failures.
- Transient retry counter not persisted → infinite exit-6 reship loop at retry 1; prevented by atomic count write before sleep/reship.
- Transient retry-cap stall seed failure → surface diagnostic, still emit `NEXT_ACTION=stall` after best-effort seed attempt logged.
- In-driver transient cap still converting fourth `TRANSIENT` to `STALLED` on orchestrated runs → bypasses route-exit retry-4 seed; prevented by `expected_session_id` gate in `python/ship.py`.
- `_write_ship_state` `extra_fields` for `OOS_PENDING` → `ShipError`, bookkeeping-failure stall always wins; prevented by `_patch_ship_state_keys`.
- `ledger_ready=True` stringification → skipped escalation; prevented by lowercase boolean KV contract.
