Outcome semantics:

- `ok`: a commit was created and the helper considers the commit phase successful.
- `noop`: clean-tree `--stage-all` no-op, with `COMMITTED=false`, `SHA=`, and `ERROR=`.
- `failed`: usage, invalid message, missing `IMPLEMENT_TMPDIR`, no review delta paths, git commit failure, or `--stage-all` commit success that still leaves porcelain dirty.

For the `--stage-all` success path:

- Probe `_git_status_porcelain()` after the commit.
- If porcelain is non-empty, emit `COMMIT_OUTCOME=failed`, keep `COMMITTED=true`, keep `SHA=<head>`, emit a concise `ERROR=dirty tree after review fix commit`, and return `1`.
- If porcelain is empty, emit `COMMIT_OUTCOME=ok` and return `0`.

For non-`--stage-all` commits:

- Do not add a post-commit porcelain probe.
- Map existing successful commit to `ok`.
- Map existing non-zero commit result to `failed`.

Orchestrator routing (all `commit-fixes --stage-all` sites):

- Continue only when `COMMIT_OUTCOME=ok` or `COMMIT_OUTCOME=noop`.
- Treat absent or malformed `COMMIT_OUTCOME` as failure (fail-closed).
- Keep `ERROR=` for logging only; do not use it as the primary continuation predicate.
- Step 7: stall on any `COMMIT_OUTCOME` not in `{ok, noop}` after `commit-fixes --stage-all`.
- Self-review Step 5 item 7: same allowlist and stall setup as Step 7 (`review-fix-commit-failed`).

Step 5 resume orchestrator routing (after `--ready-to-commit` fence):

- **Review-loop envelope owns Step 6.** Normal Step 6 continuation requires a present `STEP5_REVIEW_STATUS`. `COMMIT_OUTCOME=ok|noop` alone is never sufficient to advance to Step 6.
- When stdout contains `STEP5_REVIEW_STATUS=`, branch on that envelope per the Step 5 status table only. Do not re-check `COMMIT_OUTCOME` on this path. Do not map a normal Step 5 loop stall (`STEP5_REVIEW_STATUS=stall`, etc.) or other envelope outcomes to `resume-handoff-commit-failed` solely because the wrapper exited non-zero or because `COMMIT_OUTCOME` is absent, malformed, or `failed`.
- When stdout lacks `STEP5_REVIEW_STATUS=`:
  - Route to `resume-handoff-commit-failed` when relayed `COMMIT_OUTCOME` is not exactly `ok` or `noop` (including absent, malformed, or `failed`).
  - Route `COMMIT_OUTCOME=ok` or `COMMIT_OUTCOME=noop` with no `STEP5_REVIEW_STATUS=` to the existing Step 5 preflight/resume failure path (log to `Warnings`, `STALL_TRACKING=true`, `STALL_STEP=5`, skip to Step 18). This is **not** success and **not** Step 6 continuation.
  - Also apply the existing rule: wrapper exit non-zero with no `STEP5_REVIEW_STATUS=` is a Step 5 preflight failure to Step 18.
- Remove prompt-side porcelain probes and multi-condition commit predicates.

Wrapper gate (`step-5-resume.sh`):

- After capturing `commit_output` and `commit_rc`, parse `COMMIT_OUTCOME` from `commit_output` internally (before any stdout relay).
- Exit before `review-and-fix step5` unless parsed `COMMIT_OUTCOME` is exactly `ok` or `noop` (fail-closed on absent or malformed values, not only on `COMMIT_OUTCOME=failed` or non-zero `commit_rc`). On allowlist failure, relay `COMMITTED=`, `ERROR=`, `SHA=`, and `COMMIT_OUTCOME=` from `commit_output` on wrapper stdout, then exit non-zero.
- Run the existing `git status --porcelain` probe as the second dirty-tree guard.
- On porcelain failure, relay failure KVs on wrapper stdout (`COMMIT_OUTCOME=failed` when the parsed commit phase was otherwise `ok` or `noop`; preserve underlying `COMMITTED` / `SHA` / `ERROR=` from `commit_output` when present), then exit non-zero before `review-and-fix step5`.
- **Defer relaying successful commit KVs** (`COMMIT_OUTCOME=ok|noop` plus matching `COMMITTED` / `SHA` / `ERROR=`) to wrapper stdout until **after** both the internal `COMMIT_OUTCOME` allowlist and the porcelain probe pass. Do not emit `COMMIT_OUTCOME=ok|noop` before the porcelain gate completes.
- After both gates pass, relay the successful commit KVs once, then invoke `review-and-fix step5`.
- Do not add `git add -A` or broaden pathspec behavior.

## Edge cases

- A clean `--stage-all` tree must stay a no-op (`COMMIT_OUTCOME=noop`), not a failure.
- A partial pathspec commit that leaves unrelated dirty paths must become `COMMIT_OUTCOME=failed`.
- A normal Step 5 loop stall with `STEP5_REVIEW_STATUS=stall` must not become `resume-handoff-commit-failed`, even when `COMMIT_OUTCOME` is absent, malformed, or `failed`.
- Missing or malformed `COMMIT_OUTCOME` must not be treated as success at any `commit-fixes --stage-all` caller.
- When `commit-fixes` exits `0` but omits or malforms `COMMIT_OUTCOME`, `step-5-resume.sh` must exit before `step5` without relaying `COMMIT_OUTCOME=ok|noop`.
- When internal commit phase is `ok|noop` but porcelain is non-empty, `step-5-resume.sh` must relay failure KVs (not `COMMIT_OUTCOME=ok|noop`) and exit before `step5`.
- When `commit-fixes` exits non-zero with `COMMIT_OUTCOME=failed` but porcelain is clean, `step-5-resume.sh` must relay failure KVs and exit before `step5`.
- When wrapper stdout carries `COMMIT_OUTCOME=ok|noop` but lacks `STEP5_REVIEW_STATUS=`, the orchestrator must route to Step 18 preflight/resume failure, not Step 6.
- When wrapper stdout carries `STEP5_REVIEW_STATUS=complete` or `STEP5_REVIEW_STATUS=stall`, the orchestrator must follow the envelope table and must not route to `resume-handoff-commit-failed` based on `COMMIT_OUTCOME`.
- Self-review mode must not continue to Step 6 when dirty-after-success returns `COMMIT_OUTCOME=failed` and exit `1`.

## Failure modes

- If `COMMIT_OUTCOME` is omitted on one helper branch, callers may fall through incorrectly. Centralized emission reduces that risk.
- If the wrapper relays `COMMIT_OUTCOME=ok|noop` before the porcelain probe, a later porcelain failure can leave misleading success tokens on stdout and confuse orchestrator routing.
- If the orchestrator treats `COMMIT_OUTCOME=ok|noop` without `STEP5_REVIEW_STATUS=` as resume success, Step 6 can run without a completed review loop.
- If SKILL.md nests lacks-envelope `COMMIT_OUTCOME` rules under the present-`STEP5_REVIEW_STATUS` branch, implementers may skip fail-closed routing or misroute envelope outcomes such as `stall` or `complete` to `resume-handoff-commit-failed`.
- If tests keep a static dirty porcelain monkeypatch after a successful `--stage-all` commit, they will now fail correctly because the new post-commit probe sees the tree as dirty.
- If `scripts/test-implement-structure.sh` lines 333-334 and wrapper gate needles pin only `COMMIT_OUTCOME=failed` instead of the full allowlist, deferred-relay contract, and two-branch SKILL routing, `make lint` can fail on stale literal assertions.
