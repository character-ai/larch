## Findings

### 1. correctness — `python/review_pipeline.py:995-1013`

The plan’s **ok-empty producer** edge case does not reach the Step 5 consumer. Today, when `--pre-scouted-manifest` is forwarded with `SCOUT_CODER_STATUS=ok` and `{"archetypes":[]}`, the branch still requires `_scout_archetypes(scout_manifest)` to be truthy:

```995:1013:python/review_pipeline.py
        if scout_status == "na" and pre_scouted:
            if _normalize_scout_manifest(Path(pre_scouted), scout_manifest, dynamic_max) and _scout_archetypes(scout_manifest):
                scout_status = "pre-scouted"
                ...
            else:
                _write_empty_scout_manifest(scout_manifest)
                scout_status = "parse-failed"
                scout_fail_reason = "pre_scouted_manifest_validation"
```

That mislabels intentional static-only review as a parse failure. The implement gate that disables separate scouting does not fix this path because a manifest is still forwarded.

**Suggested revision:** Accept empty normalized pre-scouted manifests as success with zero dynamic slots; add regression coverage.

---

### 2. risk-integration — plan `python/implement_dispatch.py` + `python/review_and_fix.py`

The plan assigns **two writers** for the same producer failure:

- Normalize helper: append `Warnings` + bold warning when status is not `ok`.
- Step 5 preflight: append `Warnings` once per run when producer status is non-ok.

For main-agent `--emergency` runs that never produce a manifest, both Step 2 normalization and Step 5 preflight can record the same failure. That breaks the review emphasis on **warning de-duplication** and inflates the final-summary `Warnings` count without changing behavior.

**Suggested revision:** Single durable warning owner at Step 2; Step 5 stays loud on stderr only unless no Step 2 entry exists.

---

### 3. completeness — `python/design_lifecycle.py` inline fallback

The plan’s **loud-but-nonblocking** contract is wired for drafter subprocess output, not inline fallback. On drafter failure the launcher clears scout manifests and falls back to inline drafting without any scout-absent warning:

```3414:3418:python/design_lifecycle.py
    with contextlib.suppress(FileNotFoundError):
        (design_tmpdir / "plan-summary.md").unlink()
    _clear_scout_manifests(design_tmpdir)
    _write_text(design_tmpdir / ".step2b-plan-source", "inline\n")
    print(f"**⚠ 2b: drafter subprocess failed — falling back to inline drafting (vendor={vendor})**")
```

The plan’s “align inline fallback contract” note is not a concrete step. Inline `/design` can finish with static-only plan review and no operator-visible producer-failure signal.

**Suggested revision:** After inline plan materialization, if `scout-plan-manifest.json` is still absent, emit the same warning + final-summary line as drafter-absent.
