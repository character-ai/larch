## Risks surfaced
- **R2 prose pin**: any helper that rewrites the post-force-push error wording breaks sub-test R2 (`scripts/test-merge-pr.sh:619`). Mitigation: the call site composes the error string itself after calling the helper; the helper doesn't print or compose the error.
- **Bash 3.2 portability**: arithmetic-evaluation loop constructs (`for ((i=0; i<N; i++))`) work in Bash 3.2 but are stylistically inconsistent with the existing `for _retry in 1 2 3;` loop. Use a positional `while` loop to stay Bash 3.2-safe and stylistically aligned with the rest of `scripts/merge-pr.sh` (no associative arrays / namerefs / mapfile anywhere in this script).
- **Downstream parsers**: Codex confirmed `scripts/ship-pr.sh` parses `MERGE_RESULT` only and keys textual exceptions on OID mismatch + "Base branch was modified" — the new initial-check error wording does not collide.
- **CHANGELOG / docs**: Codex found no parser dependency on the existing error text outside the test harness. The `error` row of `scripts/merge-pr.md`'s MERGE_RESULT enum table already documents empty/UNKNOWN coverage, so the enum table need not change. `CHANGELOG.md` is updated only if the repo's release process expects every user-visible fix to log there (we'll leave a single short entry consistent with recent style).
