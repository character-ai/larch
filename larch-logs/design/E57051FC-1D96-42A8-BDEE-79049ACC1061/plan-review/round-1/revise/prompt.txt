# save degraded voting-tally.md before panel retry to enable root cause analysis

saving votnig-tally.md as per above to aid in similar debugging

## Background

When a review panel round is degraded (banner triggered in `voting-tally.md`), `review_and_fix.py` retries with a fresh panel. The retry overwrites the degraded `voting-tally.md` in place, so the first attempt's tally — which contained the `"⚠ Degraded code-review panel"` banner and the specific condition that fired — is gone.

## Proposed fix

Before overwriting `voting-tally.md` with the retry's results, copy it to a sibling artifact, e.g. `voting-tally-degraded-attempt-1.md` (or using the retry cycle counter). This artifact should be committed to the run log alongside the successful tally so post-run analysis (e.g. `/audit-runs`) can identify the root cause of the degradation.

## Relevant code

`python/review_and_fix.py` around line 2464–2474: the degraded-panel detection and retry loop.

## Acceptance

- Degraded `voting-tally.md` is preserved as a sibling artifact before the retry.
- The artifact is committed to `larch-logs/implement/&lt;RUN_ID&gt;/round-N/`.
- Post-retry, if the retry also degrades, a second sibling artifact is written (e.g. `voting-tally-degraded-attempt-2.md`).
