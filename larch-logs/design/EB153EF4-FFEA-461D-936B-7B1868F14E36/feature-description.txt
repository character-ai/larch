# /implement Step 0: fold degraded-tools gate and 1.r rebase checkpoint into the bootstrap continue path

**Problem.** Step 0 on the continue path is three consecutive Bash calls: `skills/implement/scripts/step-0-bootstrap.sh`, then `skills/implement/scripts/step-0-degraded-gate.sh`, then `scripts/rebase-checkpoint-probe.sh` for checkpoint 1.r. The bootstrap already computes the continue route and owns the presence keys the gate consumes, so the two follow-up calls are mechanical on the common path.

**Proposal.**

- On the continue route (empty bail reason, no stall, readable plan, non-empty coder), the bootstrap tail runs the degraded-tools gate and the 1.r rebase checkpoint internally and folds their KVs into the routing envelope.
- The only prompt-side bounce is a `DEGRADED_PROMPT_REQUIRED=true` envelope row (interactive run with both external tools down) for the AskUserQuestion fork. The `.degraded-tools-gate-prompted` sentinel semantics stay as today, including resume re-entry protection.
- The relayed 1.r outcome uses the `ROUTE=` token from the runtime-reads issue so the routing reference loads only on conflict or bail.

**Acceptance.**

- A non-degraded run reaches Step 2 after one Step 0 Bash call.
- The routing table gains the `DEGRADED_PROMPT_REQUIRED` row; dirty-tree recovery and resume-tail behavior unchanged; bootstrap harnesses extended to cover the absorbed gate and checkpoint.
