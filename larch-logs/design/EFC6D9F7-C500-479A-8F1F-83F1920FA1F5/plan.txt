## Plan

## Approach

- Treat **dynamic reviewer output basenames** as first-class panel slots in threshold accounting, matching static collector records, output files, and dropped rows.
- Pass the **full panel slot count** (`SLOT_COUNT` = static + dynamic) into `check-reviewer-failure-threshold` as `--intended-slots` and `--launched-slots`; do not keep a static-only denominator.
- **Preserve static straggler threshold exemption** (#5047): static `straggler-dropped` rows remain excused from the >50% failure gate and from static coverage failure; only **dynamic** dropped/straggler slots count as threshold failures.
- **Complete dropped-row accounting via `count_once` only**, with **collector-first precedence across all sources** (#FINDING_7):
  - Process collector records first; build `statuses` and a **`counted_slot_tools: set[tuple[str, str]]`** index by reverse-mapping each collector basename through `panel-manifest.ndjson` (`output` basename → `slot` + `tool`) when manifest is available.
  - For dropped rows: resolve basename via `_dropped_reviewer_output_base`; call `count_once(base=..., status="ERROR")` only when the resolved basename is **not already in `statuses`** (collector wins; dropped ERROR must not downgrade OK/cap_hit).
  - **Skip `--reviewer-output-files` counting** for any basename already present in `statuses` from collector records so a later output-file probe cannot flip OK/cap_hit to ERROR (#FINDING_7). `count_once` must never downgrade a collector success.
  - Increment `dropped_slots` for resolved-basename drops; increment `dynamic_dropped_slots` from **`dyn-*` slot prefix on every non-static-straggler dropped row**, even when basename resolution returns `None`.
  - **Synthetic fallback only when slot/tool is unseen** (#FINDING_3): when basename is `None` for a `dyn-*` drop, call `count_once(base=_synthetic_dynamic_drop_key(slot=slot, tool=tool), status="ERROR")` **only if** `(slot, tool) ∉ counted_slot_tools` and the synthetic key is not already in `statuses`. If collector already recorded that slot/tool under its real basename, skip synthetic counting entirely (slot-prefix `dynamic_dropped_slots` still increments for threshold KVs, but do not double-count `FAILED_SLOTS` / `COUNTED_SLOTS`).
  - **Delete** the parallel manual `failed += 1` / `statuses[base] = "ERROR"` path.
  - Drive `never_launched` subtraction from resolved-basename `dropped_slots`; static `straggler-dropped` rows stay out of that counter.
- **Pin backward-compat KV semantics**:
  - `DROPPED_STATIC_SLOTS` = static **non-straggler** drops only (existing contract: `0` for static straggler rows, `1` for static collector-failure drops).
  - `DROPPED_SLOTS` = total dropped rows that resolve to a basename (dynamic included).
  - Emit new **dynamic-only** threshold KVs: `DYNAMIC_FAILED_SLOTS` and `DYNAMIC_DROPPED_SLOTS` (derived from dynamic basenames and/or `dyn-*` slot prefixes) so warning and test paths do not key off aggregate totals.
- Resolve dropped-slot output basenames from **`panel-manifest.ndjson`** (`slot` + `tool` → `output` basename), with documented fallbacks for `dyn-*` / `dyn-dyn-*` scout names and `-codex` twin slots.
- **Register `--panel-manifest`** on `check_reviewer_failure_threshold` (`usage` string and `_parse_args` options set); load manifest inside threshold for `_dropped_reviewer_output_base` and collector basename → slot/tool reverse index.
- **Forward waterfall straggler metadata through dispatch without clobbering prune warnings** (#FINDING_4 dispatch half): `dispatch_panel` emits `STRAGGLER_DROPPED_COUNT` and forwards waterfall warning text via a **dedicated `WATERFALL_WARN` key** (not plain `WARN`), preserving dispatch-owned `WARN` from prune filtering and dispatch-rc handling. In `agent_waterfall`, **merge** multiple waterfall warning tokens (cost-fallback, straggler, invalid-slots) into one semicolon-separated `WARN` emission so `_kv_parse` does not drop earlier waterfall warnings before dispatch reads them.
- **Threshold-env merge from dispatch, not threshold stdout** (#FINDING_6): after `threshold_result.stdout` is written to `review-core-threshold.env`, **append** `STRAGGLER_DROPPED_COUNT` and `WATERFALL_WARN` from the parsed **`dispatch` dict** (values forwarded by `dispatch_panel`). Do not expect the threshold CLI to emit these keys. Keep `DYNAMIC_*` / `DROPPED_SLOTS` from threshold parse only.
- **One canonical dropped-slots ledger** (no duplicate staging): waterfall already writes `{launch_manifest}.output-files.dropped-slots` under `review_tmpdir`. **Do not** copy or symlink a second `*.dropped-slots` ledger; `run_logs.py` allowlists `*.dropped-slots` so `write-round` commits the waterfall artifact. `progress_report` reads that committed basename via glob; dedupe duplicate ledger files if more than one `*.dropped-slots` matches (prefer the manifest-adjacent waterfall path).
- **Post-threshold round finalization in review core** (every `_run_round` exit path after threshold parse): invoke a shared helper (e.g. `_finalize_dropped_reviewer_round`) that **only** stages bounded `dropped-*-*.txt` diagnostic carriers when present. **Do not** surface warnings here; threshold path writes `DYNAMIC_*` KVs and appends dispatch straggler metadata into `review-core-threshold.env` only.
- **Warning surfacing in `review_and_fix.py` after degraded-retry settles** (#5334/#5345 cadence; #FINDING_5): add `_surface_dropped_reviewer_warning(...)` beside `_surface_under_quorum_warning` / `_surface_parse_failed_warning`. **Accumulate dynamic-drop evidence across retry attempts** (#FINDING_5): after each `review_core_capture` (including the first attempt before retry), merge that attempt's `review-core-threshold.env` dynamic counters (`DYNAMIC_FAILED_SLOTS`, `DYNAMIC_DROPPED_SLOTS`) and dynamic-qualified straggler evidence into a per-round accumulator file (e.g. `round-{N}/dropped-reviewer-attempts.env` with monotonic max-or-sum semantics documented in code). Call `_surface_dropped_reviewer_warning` **once per settled round** from `_run_round` **after** the degraded-retry loop completes, reading the **merged accumulator** plus final `core` / threshold env. Never call `review_tally.surface_warning` from review core at threshold time; Step 5 degraded retries must not duplicate warnings, but a successful retry must still surface warnings when the first attempt dropped a dynamic reviewer.
- **`STRAGGLER_DROPPED_COUNT` backstop is dynamic-qualified only**: warn from dispatch `STRAGGLER_DROPPED_COUNT` **only when** dropped-slots TSV rows and/or `panel-manifest.ndjson` contain a `dyn-*` slot or dynamic output basename. **Never** warn from aggregate `STRAGGLER_DROPPED_COUNT` alone when merged `DYNAMIC_*` counters are zero.
- **`cap_hit` is success everywhere collector failures are labeled** (#FINDING_4): match `check_reviewer_failure_threshold` `status_success` (`OK`, `cap_hit`) in `progress_report` collector merging; do not treat `cap_hit` as a `Reviewer slot failures` row.
- **Commit** waterfall `*.dropped-slots` and curated `dropped-*-*.txt` via narrow allow globs so post-teardown `progress_report` can label drops with no collector record.
- Preserve **bounded dropped-slot diagnostics** in the round source dir before teardown (`agent_waterfall`), using destination names that pass deny globs and exclude raw reviewer output (no `.json`, no raw `.meta`).
- Keep scout selection, launch shape, adaptive straggler cutoff timing, and static archetype coverage gate semantics unchanged.

## Edge cases

- **Dynamic Codex names**: handle `dyn-name-output.txt` and `dyn-name-codex-output.txt`; manifest lookup wins over heuristics.
- **Double `dyn-` prefix**: scout may emit `dyn-dyn-lint-escalation`; mapping must normalize without producing `dyn-dyn-dyn-*` basenames. Primary tests anchor on this shape.
- **Phase and retry suffixes**: normalize `-phase2`, `-phase3`, and `-retry` before counting and labeling.
- **Static vs dynamic straggler policy**: static `straggler-dropped` → no threshold failure, no warning; dynamic `straggler-dropped` → failed + counted + warned.
- **Duplicate records**: preserve `count_once` behavior with **collector-first precedence** across dropped rows and output-file probes; dropped-row ERROR and output-file ERROR ignored when collector already recorded that basename (#FINDING_7).
- **Synthetic key with prior collector record** (#FINDING_3): `dyn-*` drop with basename miss but collector already counted `(slot, tool)` → skip synthetic `count_once`; increment `DYNAMIC_DROPPED_SLOTS` only.
- **Dropped-only dynamics with basename miss and no collector**: synthetic `dyn-slot:{slot}:{tool}` drives `FAILED_SLOTS` and `COUNTED_SLOTS`.
- **THRESHOLD_OK=true with dynamic drop**: warning surfaces once after retry settles in `review_and_fix` from merged accumulator; ledger commits via waterfall sidecar only.
- **Successful degraded retry after dynamic drop** (#FINDING_5): first-attempt dynamic counters preserved in `dropped-reviewer-attempts.env`; warning still fires.
- **STRAGGLER_DROPPED_COUNT backstop**: requires `dyn-*` evidence in dropped TSV or manifest; never aggregate count alone; read merged accumulator + dispatch-appended threshold env (#FINDING_6).
- **Static-only straggler**: no warning despite `STRAGGLER_DROPPED_COUNT=1` when only static rows dropped.
- **Plain dynamic collector failure** (no drop row): `DYNAMIC_FAILED_SLOTS` triggers warning without `DROPPED_SLOTS`.
- **`cap_hit` collector rows**: substantive success in threshold and `progress_report` labeling (#FINDING_4).
- **Malformed dropped rows**: skip; do not crash threshold.
- **Zero slots**: keep threshold success for `--intended-slots 0`.
- **Diagnostic deny globs**: destination basenames must not end with denied suffixes.
- **Symlink staging**: do not symlink dropped-slots ledger (`write-round` skips symlinks).
- **Degraded Step 5 retry**: warning emitted only after final settled round via merged accumulator, not per attempt.
- **WARN clobbering**: prune `WARN` and waterfall warnings must coexist via `WATERFALL_WARN` forwarding; agent_waterfall merges its own multi-condition `WARN` before single emit.

## Failure modes

- If `SLOT_COUNT` is missing or non-numeric, review core computes `STATIC_SLOT_COUNT + DYNAMIC_SLOTS` safely.
- If manifest lookup fails for a dynamic drop, slot-prefix `DYNAMIC_DROPPED_SLOTS` still increments; synthetic `count_once` runs only when `(slot, tool)` unseen (#FINDING_3).
- If diagnostic copy fails, dispatch completes and dropped slot still counts.
- If warnings fire at threshold time in review core, degraded retries duplicate `execution-issues.md` entries; `review_and_fix` post-retry surfacing with per-attempt merge prevents that (#FINDING_5).
- If warnings key off aggregate `DROPPED_SLOTS` or undifferentiated `STRAGGLER_DROPPED_COUNT`, static behavior regresses; dynamic-only counters and TSV/manifest qualification prevent that.
- If `DROPPED_STATIC_SLOTS` mirrors combined totals, existing straggler tests break; static-only semantics are pinned.
- If integration test keeps the hardcoded threshold stub, dynamic accounting regressions go undetected.
- If `_failed_reviewers` drops `round-meta.json`, uses wrong `parent.parent` collector probe, or treats `cap_hit` as failure (#FINDING_4), static failure labels inflate.
- If duplicate ledger staging is added, `write-round` may commit two `*.dropped-slots` files and double-count failures.
- If `--panel-manifest` is not registered, threshold hard-fails rc=2 before any accounting runs.
- If unresolved `dyn-*` drops skip `count_once` when slot/tool unseen, threshold reports `FAILED_SLOTS=0` despite dropped dynamic slot (#5499 regression).
- If output-file loop re-counts collector OK basenames, threshold can false-trip (#FINDING_7).
- If `STRAGGLER_DROPPED_COUNT` / `WATERFALL_WARN` are not appended from `dispatch` after threshold write (#FINDING_6), dynamic-qualified backstop cannot fire when `DYNAMIC_*` stay zero.
- If waterfall `WARN` overwrites prune `WARN` via plain-key forwarding, operator loses prune warning in summary.
