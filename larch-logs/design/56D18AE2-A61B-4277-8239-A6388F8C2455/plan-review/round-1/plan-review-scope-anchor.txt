Conditional spawning of review agents in /design, /implement, /review based on accepted-finding performance in the last 2 rounds

Performance-based conditional spawning of review agents, to cut wasted review tokens. (Originally #3463.)

> **Scope change (2026-06-07):** Part A (review-round counter unification + cap normalization) has been split out to **#3662**. The counter unification that #3484 targeted already shipped (single-pass review via #3243 / #3512 / #3628), so this issue no longer depends on it — build directly on the existing single-pass / single-counter model. **This issue is now Part B only.**

## Problem

We are currently likely wasting tokens by unconditionally spawning every review agent on every round. This applies to code review in `/implement` and plan review in `/design` and `/review`.

## Proposed optimization

On the first 2 rounds, spawn all review agents unconditionally. Starting with the third round, and on each subsequent round, drop (do NOT launch) any agent — a combination of a particular tool (e.g. Cursor) and a particular profile/archetype (e.g. Security) — that did not produce any accepted suggestion in either of the last 2 rounds.

Example (archetype names illustrative): if on the first 2 rounds the only combos that produced ACCEPTED suggestions were Cursor/Architect and Codex/Security, then from round 3 only those 2 combos are spawned. If Cursor/Architect's last accepted suggestion was on round 1 and it produces none on round 3, it is dropped from round 4 onward. This automatically discriminates against combos that don't produce accepted suggestions.

## Notes / design considerations

- **Data foundation already exists.** The reviewer competition scoreboard already attributes accepted findings per `{Tool}-{Archetype}` combo (e.g. `Cursor-Arch`, `Codex-Security`), scoring +1 per voted-in finding. "Accepted suggestion" = a voted-in finding.
- **"Round" semantics differ per skill** and both must be handled: in `/design` a round is a Gate C re-entry (one panel pass each); in `/implement` it is a Step 5 review round. Both are single counters today.
- **No-redemption ratchet:** a combo pruned at round 3 never returns. Decide whether that is desired, or whether an occasional re-probe is warranted (a lens quiet for 2 rounds may still catch a regression introduced by a later fix round).
- **Measurement:** the token savings from dropping Claude reviewer/voter combos are now visible thanks to #3637 (spawned-process Claude tokens are recorded under the `claude_sub` cost lane), so this issue's benefit is measurable via `/report-tokens`. #3637 is a measurement enabler, not a hard dependency.

## Proposed Design Outline

### Goals
- Cut wasted review tokens: from round 3, skip tool×archetype combos with zero accepted findings in their last 2 launched rounds.
- Cover all three review surfaces: `/design` plan review, `/implement` Step 5 code review, `/review` diff mode.
- Round 5 (the cap) always re-probes with the full panel; rounds 1-2 always run full.

### Non-goals
- No review-round-cap edits — #3662 landed the flat cap of 5; this builds on it.
- No pruning for `/review` description mode (single-pass) or for rounds 1-2.
- No cross-run memory — the prune ledger is per-run only.

### Approach sketch
- Refresh the prior reviewed plan: one shared helper `scripts/reviewer-prune.sh` with `record` (post-tally ledger rows per launched slot) and `filter` (pre-launch manifest rewrite) subcommands.
- Hook `filter` at the single point in each dispatcher where the slot manifest is complete; the filtered manifest becomes authoritative for everything downstream.
- Launched rounds are strike rounds; "accepted" = voted-in rows in the round's findings-classification TSV, attributed by exact normalized token match.
- Pruned-empty rounds advance the round counter (`prune-skipped`), never converge or count as degraded.
- `LARCH_REVIEWER_PRUNE=off` kill switch; fail open on missing/corrupt ledger.

### Surfaces in scope
- `scripts/reviewer-prune.sh` (new, + contract md + offline harness + Makefile target).
- `skills/review/scripts/` — `dispatch-panel.sh`, `review-core.sh` (+ md, tests).
- `skills/review-and-fix/scripts/` — `review-and-fix.sh`, `review-implement-step5-loop.sh` (+ md, tests).
- `skills/design/scripts/` — `run-step3-review.sh`, `dispatch-plan-review-panel.sh`, `plan-review-loop.sh` (+ md, tests); `scripts/lib-design-round-artifacts.sh`.
- Prose/docs: `skills/review/SKILL.md`, `skills/review/references/heavy-worker.md`, `skills/design/SKILL.md`, `skills/implement/SKILL.md`, `skills/design/references/plan-review.md`, `docs/configuration-and-permissions.md`, `docs/point-competition.md`, `docs/linting.md`.
