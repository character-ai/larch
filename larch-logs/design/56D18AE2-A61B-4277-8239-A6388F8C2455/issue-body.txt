Performance-based conditional spawning of review agents, to cut wasted review tokens. (Originally #3463.)

> **Scope change (2026-06-07):** Part A (review-round counter unification + cap normalization) has been split out to **#3662**. The counter unification that #3484 targeted already shipped (single-pass review via #3243 / #3512 / #3628), so this issue no longer depends on it — build directly on the existing single-pass / single-counter model. **This issue is now Part B only.**

## Problem

We are currently likely wasting tokens by unconditionally spawning every review agent on every round. This applies to code review in `/implement` and plan review in `/design` and `/review`.

## Proposed optimization

On the first 2 rounds, spawn all review agents unconditionally. Starting with the third round, and on each subsequent round, drop (do NOT launch) any agent — a combination of a particular tool (e.g. Cursor) and a particular profile/archetype (e.g. Security) — that did not produce any accepted suggestion in either of the last 2 rounds.

Example (archetype names illustrative): if on the first 2 rounds the only combos that produced ACCEPTED suggestions were Cursor/Architect and Codex/Security, then from round 3 only those 2 combos are spawned. If Cursor/Architect's last accepted suggestion was on round 1 and it produces none on round 3, it is dropped from round 4 onward. This automatically discriminates against combos that don't produce accepted suggestions.

## Notes / design considerations

- **Data foundation already exists.** The reviewer competition scoreboard already attributes accepted findings per `{Tool}-{Archetype}` combo (e.g. `Cursor-Arch`, `Codex-Security`), scoring +1 per voted-in finding. "Accepted suggestion" = a voted-in finding.
- **"Round" semantics differ per skill** and both must be handled: in `/design` a round is a Gate C re-entry (one panel pass each); in `/implement` it is a Step 5 review round. Both are single counters today.
- **No-redemption ratchet:** a combo pruned at round 3 never returns. Decide whether that is desired, or whether an occasional re-probe is warranted (a lens quiet for 2 rounds may still catch a regression introduced by a later fix round).
- **Measurement:** the token savings from dropping Claude reviewer/voter combos are now visible thanks to #3637 (spawned-process Claude tokens are recorded under the `claude_sub` cost lane), so this issue's benefit is measurable via `/report-tokens`. #3637 is a measurement enabler, not a hard dependency.

## Dependencies

- No longer blocked by Part A (#3662) — the single-round model it targeted already exists.
- Original combine preserved a native blocked-by edge on #3482 (now closed). No open blockers remain.

## Plan

# Implementation Plan — Issue #3619: Conditional spawning of review agents (Part B)

## Goal

Cut wasted review tokens. From round 3 on, do not launch reviewer combos (tool × archetype slot) that produced zero accepted items in their last 2 launched rounds. Round 5 re-probes with the full panel. Applies to `/design` plan review, `/implement` Step 5 code review, and `/review` diff mode.

**Depends on #3662 (native blocked-by edge)**: #3662 flattens the review-round cap to a uniform 5 across `/design` (both tiers) and `/implement` (hard ceiling — entry inflation and post-round bump removed, `lib-implement-round-cap.sh` deleted, Step 5 telemetry fence reports `ROUND_CAP=5`). This plan builds on that end state and makes **no cap edits of its own** (operator-approved post-Gate-C amendment; the cap scope originally in this plan moved out as #3662 duplication).

## Approach

One new shared helper, `scripts/reviewer-prune.sh`, with two subcommands:

- `record` — after a round's tally, write one row per launched slot to a run-stable ledger TSV. Inputs: `--ledger FILE --round N --manifest FILE --classification FILE [--collector-results FILE] [--label-map FILE]`. Ledger columns: `round`, `tool`, `slot`, `label`, `collected`, `accepted_count`. `record` is **idempotent per round**: it rewrites the ledger as (rows where round != N) + the new rows (atomic temp + `mv`), so a retried round attempt replaces the discarded attempt's rows instead of stacking duplicates.
- `filter` — before a round's launch, rewrite the panel manifest to eligible slots only. Inputs: `--ledger FILE --round N --manifest FILE --out FILE`. Emits KVs: `PRUNE_ACTIVE`, `ELIGIBLE_COUNT`, `PRUNED_COUNT`, `PRUNED_COMBOS` (comma list), `PANEL_PRUNED_EMPTY`.

Combo identity is the manifest pair `tool:slot`. Both dispatchers already build a complete NDJSON slot manifest before launch (`panel-manifest.ndjson` for code review; `plan-review-slots.ndjson` for plan review), so `filter` hooks in at exactly one point per dispatcher: after the manifest is fully built (static + dynamic), before the waterfall launch. **The filtered manifest becomes the authoritative manifest for everything downstream**: each dispatcher emits its `PANEL_MANIFEST` KV pointing at the filtered file, and all post-dispatch consumers (slot counts, output-to-slot mapping, label-map generation, coverage gate, threshold denominators, `record`) read the filtered manifest, never the pre-filter one. The pre-filter file is kept on disk for forensics only.

Eligibility rule in `filter`:

- `LARCH_REVIEWER_PRUNE=off` (exact match) → all slots eligible; `PRUNE_ACTIVE=false`.
- Round N ≤ 2 or N ≥ 5 → all eligible (rounds 1-2 baseline; round 5 full re-probe; N > 5 defensive — rounds are hard-capped at 5 per #3662).
- Otherwise (N = 3 or 4): take the combo's ledger rows with `round < N`; dedupe per round keeping max `accepted_count`. Fewer than 2 such rounds → eligible (clean slate). Both of the 2 most recent such rounds have `accepted_count=0` → pruned. Else eligible.
- Missing or unparsable ledger → all eligible plus a warning KV (fail open).

**Launched rounds are strike rounds** (accepted FINDING_13, scope reduction): every row in the filtered manifest that the round actually launched counts in the strike window with its measured `accepted_count`, including slots whose output came back empty, NOT_SUBSTANTIVE, or dropped under `--no-fallback`. The `collected` column is recorded for diagnostics only and never gates the window. Slots never launched in a round (pruned, outage-skipped at dispatch, or not yet scouted) have no row for that round, so they keep their clean slate. Rounds that are rolled back or never settle write no rows at all (see `record` call sites below).

"Accepted" means `voting_result=accepted` rows in the round's findings-classification TSV, including accepted OOS rows (anything that scores +1 in the point competition). A slot's `accepted_count` is the number of accepted rows whose attribution cell contains the slot's label under **exact normalized token equality** (accepted FINDING_11): split code-review `reviewer_slots` cells on `|` and plan-review `finding_reviewers` cells on `,`, trim surrounding whitespace from each token, then require token == label. No substring or prefix matching. Labels:

- Code review: label = output basename (e.g. `cursor-specialist-security-output.txt`), matching `reviewer_slots` cells after `normalize_reviewer_label` (waterfall phase2/phase3 retries already normalize back to the slot's basename, so attribution follows the slot).
- Plan review: the caller supplies `--label-map` (TSV `slot<TAB>label`) generated with the loop's existing `plan_slot_human_label` (e.g. `cursor-plan-arch` → `Cursor-Arch`), matching `finding_reviewers` cells. No mapping duplication.

The diagnostic `collected` column: a slot is `collected=true` when the collector results show status OK for its output after normalizing collector `REVIEWER_FILE` basenames with the same phase2/phase3/retry suffix-stripping loop as `normalize_reviewer_label` (accepted FINDING_12), so phase2/phase3/retry success paths join back to the manifest output. When no collector row exists for a launched slot (e.g. Claude fallback outputs that bypass the collector), fall back to "output file exists and is non-empty" so fallback slots stay visible in diagnostics (accepted FINDING_3; with launched-row strikes, fallback slots are pruned or retained on equal terms either way).

**Round-number source** (accepted FINDING_5): the prune round is the skill's review-round counter, not an artifact index. For `/design`, `run-step3-review.sh` threads the pending Gate C review round (`STEP3_REVIEW_ROUND_NUM`, the value it persists to `review-round-count.txt`) into `plan-review-loop.sh` as a new `--prune-round-num`; the loop forwards it to the dispatcher's `filter` and to `record`. The existing `--round-num` keeps its artifact-path role (`plan-review/round-N/` forensics) unchanged — on SIMPLE it stays 1 across Gate C re-entries while the prune round advances 1 → 2 → 3. For `/implement` and `/review`, the existing `--round-num` already is the loop round and serves both purposes.

`record` call sites: only settled rounds that produced a final classification TSV (`complete` / zero-findings paths). Rolled-back `/design` rounds (`tally-error`, `degraded-empty-collector`), `panel-failed`, and MAV-deferred rounds are not recorded — their absence fails open. For `/implement`, a degraded tally that `review-and-fix.sh` retries in-round is harmless even if recorded: the retry's `record` replaces that round's rows via the per-round idempotent rewrite (accepted FINDING_9), so pruning never keys on a discarded attempt.

**Pruned-empty rounds advance, not converge** (accepted FINDING_1). When `filter` leaves zero slots (`PANEL_PRUNED_EMPTY=true`), nothing spawns and the round consumes its counter slot, but the loops must keep the round-5 full re-probe reachable instead of terminating early:

- Code review dispatch short-circuits before the waterfall with success KVs; `review-core.sh` returns a distinct `REVIEW_CORE_STATUS=prune-skipped` (zero findings, empty artifacts, `PANEL_PRUNED_EMPTY=true` passed through) instead of plain `ok`.
- `/implement`: `review-and-fix.sh` maps `prune-skipped` to a non-terminal round outcome; `review-implement-step5-loop.sh` increments `round_num` and continues (no convergence, no degraded classification) while `round_num < ROUND_CAP`; at the cap the loop ends normally.
- `/review` standalone: Step 3f treats `prune-skipped` as "continue to next round" (not convergence) while under the cap.
- `/design`: the dispatcher's `PANEL_PRUNED_EMPTY=true` short-circuit is handled in `plan-review-loop.sh` BEFORE the degraded-empty handling: empty artifacts + "round skipped: all reviewer combos pruned" note, `LOOP_STATUS=complete`, `DEGRADED_PANEL=false`, `WARN=` breadcrumb. Control returns to Gate C as usual (each /design round is operator-triggered), and the consumed counter keeps round numbering advancing toward 5 on HARD.

Cap-removal scope (accepted FINDING_4, FINDING_6) is **owned by #3662** and excluded here: the `/implement` entry/resume inflation, the post-round `effective_round_cap` increment, `lib-implement-round-cap.sh`, and the Step 5 telemetry fence/banner all become fixed-cap-5 surfaces when #3662 lands. This plan touches `review-implement-step5-loop.sh` only to add the `prune-skipped` round advancement.

## Edge cases

- <2 launched prior rounds → eligible (fresh dynamic archetypes, outage-skipped slots, new runs).
- Launched-but-failed slots (empty output, NOT_SUBSTANTIVE, `--no-fallback` drop) → strike rows with `accepted_count=0`; `collected=false` recorded for diagnostics only.
- MAV-deferred tallies and rolled-back rounds → no ledger row; retried `/implement` rounds → per-round replace-rewrite keeps only the final attempt.
- Re-scouted dynamic archetype → same slot name → history accrues (intended).
- Both vendors down: code review Claude-fallback rows keep `cursor:*` keys and strike normally; /design Claude-generic path bypasses pruning.
- `/review` description mode is single-pass → never prunes.
- Empty/header-only ledger → all eligible.
- /design SIMPLE: with #3662's flat cap of 5 on both tiers, the prune round advances 1 → 5 across Gate C entries (artifact round may stay 1); rounds 3-4 prune, round 5 re-probes with the full panel on both tiers. This also moots panel-rejected FINDING_8's tier-cap-bypass alternative.

## Failure modes

1. **Pruned round misread as degraded** → wrong rollbacks/convergence. Signal: `DEGRADED_ROUND=true`, degraded classification, or convergence on a round-3+ skip. Mitigation: explicit `PANEL_PRUNED_EMPTY` KV, distinct `prune-skipped` status, harness assertions that degraded flags stay false and loops advance.
2. **Label-mapping drift** → accepted_count always 0 → over-pruning to empty panels. Signal: all-zero ledger while voting-tally shows accepted findings. Mitigation: raw basenames + exact token equality for code; reuse of `plan_slot_human_label` via `--label-map` for design; shared-prefix fixtures from real artifacts.
3. **Pre/post-filter manifest divergence** → counts, coverage, attribution, or record keyed to slots that never launched. Signal: `STATIC_SLOT_COUNT` disagreeing with launched outputs; ledger rows for pruned slots. Mitigation: filtered `PANEL_MANIFEST` is the single downstream source in both dispatchers; harness pins.

## Testing strategy

New offline `scripts/test-reviewer-prune.sh` plus extended harnesses listed above; all fixture-based. `make lint` + `bash scripts/relevant-checks.sh`; same-PR launcher-harness updates per `.claude/rules/launcher-argv-test-coverage.md`.
