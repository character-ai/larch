[OOS] design-log-ship: follow-up correctness and architecture cleanups (poll_ci required-filter, transient-rerun dedup, quiet_init TMPDIR, stderr bridge, rerun_failed guard)

Five [OOS] design-review findings for the `design-log-ship` feature, all low-severity (nit/latent), touching `python/design_log_ship.py`, `python/ci_monitor.py`, and `scripts/design-log-publish.sh`.

---

### 1. `poll_ci` classifies all PR checks; optional failures can block log-only merges
- **Description**: Adopting `poll_ci` drops the current `--required` filter on the completion watch. Scenario: `gh pr checks --required --watch` ignores optional checks; `ci_monitor` classifies all PR checks, so optional pending/failing checks can block log-only merges that today proceed when required checks are green.
- **Reviewer**: Cursor-Arch
- **Severity**: latent
- **Focus area**: risk-integration
- **Location**: `python/ci_monitor.py:179-197`

---

### 2. Transient-rerun duplicates `ci_monitor.evaluate_failure()` upfront block
- **Description**: Transient-rerun classification duplicates the upfront block already in `ci_monitor.evaluate_failure()` instead of calling a shared helper. Scenario: Two copies of `collect_failed_logs` + `retry.is_transient_net_signature` + `rerun_failed` semantics will drift from ship-pr over time.
- **Reviewer**: Cursor-Arch
- **Severity**: latent
- **Focus area**: architecture
- **Location**: `python/design_log_ship.py:28-90`

---

### 3. `quiet_init` in child process uses IMPLEMENT_TMPDIR not DESIGN_TMPDIR
- **Description**: Python child `quiet_init` only consults `IMPLEMENT_TMPDIR`, while parent `larch_quiet_init` prefers `DESIGN_TMPDIR` for log placement. Scenario: Design-log publish diagnostics split across two quiet-log files (parent under `$DESIGN_TMPDIR`, child under `$TMPDIR`), adding operator toil when debugging a parked log PR.
- **Reviewer**: Cursor-Arch
- **Severity**: nit
- **Focus area**: risk-integration
- **Location**: `scripts/design-log-publish.sh:173-197`

---

### 4. Bridge captures stderr via 2>&1 despite quiet-only stdout contract
- **Description**: Python bridge captures stderr via 2>&1 despite quiet-only stdout contract. Scenario: Stray stderr lines could complicate PUBLISH_OK parsing in edge cases.
- **Reviewer**: Cursor-Innovation
- **Severity**: nit
- **Focus area**: correctness
- **Location**: `scripts/design-log-publish.sh:189-195`

---

### 5. `rerun_failed` submitted when failed logs lack transient network signature
- **Description**: Log-only path submits one `rerun_failed` even when failed logs are ready but lack a transient network signature, broader than the issue's "classify transient-vs-real" wording and ship's `evaluate_failure` transient-only rerun. Scenario: A genuine required-check failure still consumes one extra CI cycle before parking recovery — operational cost, not a merge-on-red safety hole.
- **Reviewer**: Cursor-Pragmatic
- **Severity**: latent
- **Focus area**: correctness
- **Location**: `python/design_log_ship.py:72-75`
