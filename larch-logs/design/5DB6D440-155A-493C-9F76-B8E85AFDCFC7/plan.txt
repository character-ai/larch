## Edge cases

- A same-run OOS sink can contain aggregate-promoted items while the round tally still says `OOS_ACCEPTED_COUNT=0`.
- A sink with fewer blocks than `OOS_ACCEPTED_COUNT` remains unsafe and must fail.
- Security OOS blocks must not enter public filing pools on either design or review paths.
- A reviewer can produce prose no-findings that passes substantive validation but cannot produce structured records.
- A reviewer can produce valid structured TSV/JSONL that now needs lazy sidecar materialization in the design path.
- Retry sentinel behavior must not loop when annotate keeps returning empty issue stdout.

## Failure modes

- Preserving every non-empty OOS sink could mask stale or partial sinks. Guard with `sink_count >= OOS_ACCEPTED_COUNT`, not only `sink_count > 0`.
- Removing structured collector validation without lazy sidecar generation would drop real plan-review findings. Add the sidecar materialization test.
- Changing `collect-results` globally could alter `/implement` Step 5. Keep the fix in `plan_review_round.py`.
- Security classification must use `artifact_text` after `_artifact_text_for_item`, not raw `block_text`. Classification before attribution restoration misses security tags in restored reviewer context.
- Any read or decode failure in the security classifier must raise, not return `False`. Silently returning non-security routes tagged OOS into public pools.
- The shell harness must clean up temporary dirs on both pass and fail paths as much as current style allows.
