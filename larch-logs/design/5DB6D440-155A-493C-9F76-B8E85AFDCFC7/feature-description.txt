### Item 1 — emit_tally guard rejects post-promotion state (important)

**File**: `python/larch/review/review_tally.py`

`emit_tally` has a pre-promotion sink guard that aborts when the accepted sink is non-empty. After aggregate-trigger promotion appends items to `oos-accepted-review.md`, a same-run re-entry of `emit_tally` sees a non-empty sink and aborts before the serialize step, blocking the intended promotion retry path.

---

### Item 2 — Dead annotate-skipped-empty-stdout branch after status grammar change (nit) — CONFIRMED LIVE

**Files**: `python/larch/design/design_step5b.py`, `python/larch/design/design_oos.py`

The old empty-stdout warning branch (handling `annotate-skipped-empty-stdout` on exit 0) in `step5b_annotate_main` / `design_oos.py` appears unreachable after the status grammar changed to `annotate-failed-empty-stdout`. `design_oos.py` emits only `annotate-failed-empty-stdout` (line ~217), yet `design_step5b.py` still branches on `annotate-skipped-empty-stdout` (line ~295). The branch is dead code unless the status vocabulary is re-aligned.

**Fix**: remove the `annotate-skipped-empty-stdout` branch, or re-wire it if the status is still meant to be emitted on the exit-0 path.

### Item 3 — Duplicate security classifier can drift between design and review paths (latent)

**Files**: `python/larch/review/plan_review_tally.py`, `python/larch/review/review_tally.py`

`/design` and the `/implement` review path route security classification through separate entry points (`plan_review_tally._is_security` → `voting.is_security_block`; `review_tally` uses both `voting.is_security_block` and `voting.is_security_block_text`). If the path/text classifiers drift, security-classed items can leak into the public filing pool on one path but not the other.

**Fix**: consolidate onto a single shared classifier so the path- and text-based checks cannot diverge.

---

### Item 4 — Redundant weak empty-stdout annotate test remains (nit)

**File**: `python/tests/design/test_design_oos.py`

The older empty-stdout annotate test is redundant because the newer `NEXT_ACTION` coverage exercises the same behavior. The weak test adds noise without coverage value.

**Fix**: remove the redundant test.

---

### Item 5 — Missing review_core_body session-env integration test (nit)

**Files**: `python/larch/review/review_core_body.py`, `python/tests/review/test_review_tally.py`

Direct `emit_tally` unit tests do not cover the `review_core_body.py` session-env path that threads `--session-env-path` through to `emit_tally`. The integration path is untested.

**Fix**: add an integration test that drives `review_core_body` with a `--session-env-path` and asserts the tally/sink copy-to-parent behavior.

---

### Item 6 — Gate C reentry pool reset lacks regression test (latent)

**File**: `skills/design/scripts/design-step3-entry.sh`

The `design-step3-entry.sh` `--reentry` path resets `oos-aggregate-pool.md` alongside stale review artifacts. There is no automated regression test, so stale pool state could re-trigger promotion after review re-entry without detection.

**Fix**: add a regression test that asserts `oos-aggregate-pool.md` is reset on the `--reentry` path.

---

### Item 7 — Once-only retry sentinel lacks end-to-end harness (latent)

**Files**: `skills/design/references/finalize-step5.md`, `python/larch/design/design_oos.py`

The `.oos-issue-retry-used` sentinel governing the Bug A annotate retry is prompt-orchestrator-owned with no end-to-end harness. A double-retry or silent Step 5b advance past the sentinel would only surface in a live `/design` run.

**Fix**: add an end-to-end harness that exercises the once-only retry sentinel path.

---

### Item 8 — /design still runs --structured-reviewer-validation after substantive validation (from #6316) — CONFIRMED LIVE

**Files**: `python/larch/review/plan_review_round.py` (structured-reviewer-validation wiring)

**Surfaced by**: Cursor-Arch (design phase).

`/design` still runs `--structured-reviewer-validation` after substantive validation. Scenario: `/implement` Step 5 uses validation-mode only, but `/design` plan review also passes `--structured-reviewer-validation`. A prose no-findings result without JSON or `NO_ISSUES_FOUND` can still be demoted `NOT_SUBSTANTIVE` on the structured path even after the prior fix.

**Fix**: on the `/design` plan-review path, do not apply structured-reviewer-validation demotion to prose no-findings once substantive validation has passed.
