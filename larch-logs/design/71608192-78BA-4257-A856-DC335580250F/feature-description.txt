# Model policy refresh: GPT-5.6 difficulty routing, panels, voters, and fixers

## Summary

Adopt the GPT-5.6 family (released 2026-07-09) across larch's Codex surfaces, make model choice difficulty-conditional for the /implement coder, the Step 5 reviewer panels, and the finding voters, and refresh the three fixer waterfalls (CI recovery, review-fix, plan revision). Reasoning effort stays `high` everywhere it is set today.

Policy matrix (the reviewer sets below are COMPLETE per tier; spawn nothing else):

| Tier | Step 2 coder | Reviewer set, per static and per dynamic archetype | Codex voter model |
|---|---|---|---|
| TRIVIAL | Codex `gpt-5.6-terra` | one Cursor `auto` reviewer (no Codex rows) | `gpt-5.6-luna` |
| MODERATE | Codex `gpt-5.6-sol` | pair: Cursor `auto` + Codex `gpt-5.6-luna` | `gpt-5.6-terra` |
| HARD | Codex `gpt-5.6-sol` | pair: Cursor `auto` + Codex `gpt-5.6-terra` | `gpt-5.6-terra` |

Fixer waterfalls (first available wins; effort unchanged):

| Task | New waterfall |
|---|---|
| CI fixes (`implement.ci_recovery_fixer`) | Codex `gpt-5.6-terra` -> Cursor `auto` -> Claude `claude-sonnet-4-6[1m]` |
| Apply accepted review findings (`review.fix_coder`) | Codex `gpt-5.6-terra` -> Cursor `auto` -> Claude `claude-sonnet-4-6[1m]` |
| Plan revision in /design (`design.plan_revision`) | Codex `gpt-5.6-terra` -> Cursor `composer-2.5` -> Claude `claude-sonnet-4-6[1m]` |

Non-difficulty role defaults: `CODEX_DEFAULT_MODEL` becomes `gpt-5.6-sol` (brainstorm, negotiations, health probe, other default-role launches). The review role default becomes `gpt-5.6-luna` (non-panel review-role sites, findings aggregator). The fix role default becomes `gpt-5.6-terra`. The vote role default becomes `gpt-5.6-terra`.

Exact model ids and list prices per 1M tokens (verified 2026-07-09 at developers.openai.com):

| Model id | Input | Cached input | Output |
|---|---|---|---|
| `gpt-5.6-sol` | $5.00 | $0.50 | $30.00 |
| `gpt-5.6-terra` | $2.50 | $0.25 | $15.00 |
| `gpt-5.6-luna` | $1.00 | $0.10 | $6.00 |

Current rows for comparison: `gpt-5.5` is $5.00 / $0.50 / $30.00 and `gpt-5.4-mini` is $0.75 / $0.075 / $4.50. Claude Sonnet 4.6 is $3.00 input / $0.30 cache read / $15.00 output per 1M and already has a rate-table row; `claude-sonnet-4-6[1m]` is the Claude Code CLI model syntax that pins the 1M-context variant of the same model id.

Codex row models resolve tier-to-role via `codex_review_model_role_for_archetype` (`difficulty.py:163-168`): non-HARD rows use the `review` role (`gpt-5.4-mini`); HARD rows use per-archetype overrides `DIFFICULTY_CODEX_MODEL_ROLE_OVERRIDES["review.panel"]` (`config.py:274-277`), so `correctness` and `edge-cases` escalate to the `default` role, which is `gpt-5.5`. **Answer to the operator note: MODERATE panels spawn no `gpt-5.5` reviewer today; HARD panels spawn two (`correctness`, `edge-cases`). The new spec removes them.** A `generalist` Codex slot with `model_role="default"` exists in the table (`config.py:404`) but is not emitted per the role's doc_fallback; delete it as part of this change.
- **Voters today.** `review.voters` (`config.py:451-463`) and `design.plan_voters` (`config.py:464-476`) run three voters, each a Codex-primary waterfall (codex, cursor, claude). Codex voter slots resolve the `vote` role, so `gpt-5.4-mini` flat, env `LARCH_CODEX_VOTE_MODEL`.
- **Fixer waterfalls today.** CI recovery (`implement.ci_recovery_fixer`, `config.py:369`) runs Claude first (`CLAUDE_CI_FIX_MODEL = claude-opus-4-8`, `config.py:535`, via `launch-claude-ci`), then Codex at the DEFAULT role (`launch_codex_ci_main` passes no `codex_role`, `_ci_launcher.py:253`, so `gpt-5.5`), then Cursor `composer-2.5` (`_ci_launcher.py:341`). Review-fix (`review.fix_coder`, `config.py:371`) runs Codex fix role (`gpt-5.4-mini`), then Cursor `composer-2.5`, then Claude `claude-sonnet-4-6` (`claude_review_fix`, `config.py:543`). Plan revision (`design.plan_revision`, `config.py:374`) runs Cursor `composer-2.5`, then Codex fix role via `--model-role fix` (`python/larch/design/plan_quality.py:1243`), then Claude via `launch-claude-review` (`plan_quality.py:1245`).
- **Pricing coupling 1.** `rate_row()` resolves the vendor-default row via `DEFAULT_VENDOR_MODEL["codex"] = config.CODEX_DEFAULT_MODEL` (`python/larch/report/report_tokens_cost.py:17-21,110-121`). Changing the constant without a matching rate row raises `KeyError` in every cost report.
- **Pricing coupling 2.** `CODEX_MINI_MODEL = config.CODEX_REVIEW_MODEL_DEFAULT` (`report_tokens_cost.py:102`) is the by-model split key for the mini display bucket. Flipping the role constant without fixing the split sends historical `gpt-5.4-mini` run-log rows to the default bucket at Sol rates (about 6.7x) during /report-tokens re-analysis.
- **Pricing coupling 3.** Claude by-model accounting exact-matches `CLAUDE_SONNET_4_6_MODEL` (`CLAUDE_SUB_MODEL_FLAG_PREFIXES`, `report_tokens_cost.py:103-107`) and `rate_row("claude", model=...)` falls back to Opus 4.8 rates for unknown ids. If the literal string `claude-sonnet-4-6[1m]` leaks into vendor ledger rows, those rows misprice at Opus rates and miss the sonnet sub-model split.
