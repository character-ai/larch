# Implementation Plan — sh-to-py F2: session/state module (`session_env.py`)

## Scope summary

Port **13 invoke-style** session/state scripts into one stdlib-only `python/session_env.py`, register `session` verbs in `cli.py`, hard-cut every `.md`/`.sh` call site to direct CLI calls, run the retargeted bash harnesses once as a parity gate, then delete the bash + harness + `.md` siblings.

## Formal F2 scope change (defer 4 sourced-only libs) — user-approved

This plan **formally re-scopes #3668** from "delete all 17 in the same change" to **13 ported now + 4 sourced-only libs deferred**. This re-scope is operator-approved (not a unilateral narrowing). Each deferred lib is `source`d by surviving bash owned by later phases; bash cannot `source` a Python function, so deleting them in F2 breaks out-of-phase survivors:
- `scripts/lib-design-tmpdir.sh` — `source`d by ~35 design-machinery scripts (C3a–c, #3679–3682).
- `scripts/lib-validate-meta-path.sh` — `source`d by external-agent launchers incl. `check-mid-run-dirty-tree.sh` (B4, #3673).
- `skills/implement/scripts/lib-resolve-implement-tmpdir.sh` — `source`d by a bash hook (`hook-stop-fail-close.sh`; hooks stay bash) + `sessionstart-health.sh`.
- `scripts/lib-finalize-state-keys.sh` — `source`d by `ship-pr.sh` (retired in E1, #3690).

**Required follow-up**: before updating #3668's scope note, file a concrete follow-up issue for the 4 deferred libs via `/larch:issue` and wire it via `/block-issue` blocked-by the phases owning their last sourcers (B4 #3673; C3a–c #3679/#3680/#3681/#3682; E1 #3690; `lib-resolve-implement-tmpdir.sh` waits on the bash-hook overhaul). Record the issue number in #3668's scope note and in `docs/python-migration.md`.

## Files to modify/create

### NEW: `python/session_env.py`
Stdlib-only module owning session/state lifecycle. One `*_main(argv) -> int` entry per CLI verb, internal helpers, the NEVER #14 writer-guard, and frozen dataclasses for structured results. Repo idiom: `from __future__ import annotations`; `proc.Runner` for subprocess; `quiet_init`/`contract_stream`/`emit_kv` for fd-3 contract output; `logging_util.BreadcrumbWriter().emit(..., quiet=False)` for post-`quiet_init` diagnostics; `config.py` for tunables; atomic temp + `os.replace` writes with `O_EXCL`/`O_NOFOLLOW` + symlink refusal (mirror `finalize._write_finalize_text_safely`).

**Three distinct path predicates** — do not conflate:
1. `is_allowed_session_tmpdir(path)` — the **broad cleanup removal** allowlist matching `scripts/cleanup-tmpdir.sh` (root under `/tmp`, `/private/tmp`, `/var/folders`, or the cache sessions root). Used ONLY by the `cleanup-tmpdir` verb.
2. **Writer-target validator** (stricter, for NEVER #14): cache-sessions-root or `/tmp`-family root membership **plus** a basename under `claude-*-` (all `session-setup --prefix` values: `claude-implement`, `claude-design`, `claude-review`, `claude-research`). Session-env content writes (`write-env`/`write-design-env` content file/`persist-run-flags`/`restore-finalize-state`) must pass this — NOT the broad cleanup allowlist (else approved writers could write payloads outside real larch session dirs, weakening NEVER #14). Enumerate the accepted prefixes in `test_session_env.py`.
3. finalize's RunContext/session-id-gated `_cleanup_target_ok` stays in `finalize.py` for ship teardown only.

**Design-tmpdir validator**: inline `larch_design_tmpdir_validate` (the 8-step allowlist/ancestor-tail algorithm from `scripts/lib-design-tmpdir.sh`) as an internal stdlib helper; `write-design-env` calls it before any write. Never source the deferred bash lib.

**NEVER #14 runtime writer-guard (scoped + carve-outs)**: governs session-env content-file writes via the stricter writer-target validator (predicate 2) + a per-writer key allowlist + a **value validator that rejects CR/LF bytes** in every persisted value before rendering (a newline would inject extra KEY=VALUE lines and bypass the key allowlist — match finalize's existing newline rejection), before any bytes are written. **Carve-outs**: skip the path allowlist when `--output` is `/dev/null`; for `write-env --plugin-root-only`, validate only the plugin-root value grammar + parent-dir writability (mirror `emit_plugin_root_env`), NOT session-tmpdir membership. The **design current-env symlink** uses a dedicated symlink validator permitting the hardcoded `Path.home()/".cache"/"larch"/"sessions"/current-design-env-$PPID.sh` location, so an XDG-aware check never rejects it.

**Per-writer key allowlists (explicit constants)**:
- `write-env` — the `write-session-env.sh` parse-only output key set (incl. `CODEX_*`/`CURSOR_*` alias peers, `LARCH_*` token/ledger/run-id keys).
- `write-design-env` — the exact sourceable source-env key set: `DESIGN_TMPDIR`, `SESSION_TMPDIR`, `SESSION_ID`, optional `REPO` + `ISSUE_NUMBER`, the CODEX/CURSOR presence/available/binary keys, `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT`, and `CLAUDE_PLUGIN_ROOT` when present. Do NOT add `CLAUDE_PID` to the content (it is only the `--claude-pid` symlink-name argument; the source-env format does not change).
- `persist-run-flags` — the `run-flags.sh` keys (`NO_ISSUES`, `EMERGENCY_REQUESTED`, `SELF_REVIEW_REQUESTED`, `QUICK_MODE`).
- `restore-finalize-state` — the verbatim 20-key bash allowlist from `lib-finalize-state-keys.sh` (see verb below).

### Per-verb emitter routing
Match each verb's stdout/quiet behavior to its retired bash script — no global fd-3 routing:
- fd-3 contract stream (`quiet_init` + `emit`/`emit_kv`): `setup`, `write-run-params` (`RUN_PARAMS_WRITTEN`), `read-key` (value only, no `KEY=` prefix), `entry-gate` (success two-line KV).
- plain stdout KV: `read-classification` (`SIMPLE`/`HARD`); `persist-run-flags` (`RUN_FLAGS_PERSISTED=true`).
- always-emit stdout KV via EXIT trap: `local-cleanup`.
- file-only, silent success (no stdout): `write-env`, `write-design-env`, `write-id`, `restore-finalize-state`.
**Diagnostics routing (caller-visibility)**: parse usage errors BEFORE `quiet_init` where possible; for user-visible diagnostics AFTER `quiet_init`, use `BreadcrumbWriter` default routing (or a `larch_err`-style helper writing to caller-visible stderr/fd 4 + the quiet log), NOT `emit(..., quiet=False)` which would land only in the redirected quiet log — preserving bash `larch_err` caller visibility. Reserve `quiet=False` for intentionally log-only messages.
Authoritative bash references: `persist-implement-run-flags.sh`, `read-design-classification.sh`, `read-session-env-key.sh`, `local-cleanup.sh`, `restore-finalize-state.sh`, `session-entry-gate.sh`.

## Edge cases
- `read-key` `=`-values; all four default rules incl. present-but-empty + `--default`; fd-3 emit (not raw stdout).
- `write-design-env` source-safe quoting round-trip; `~/.cache` (non-XDG) symlink even when `XDG_CACHE_HOME` set; legacy-name warning; refresh-preservation.
- `setup --caller-env`: reject unsafe `LARCH_TIMING_LEDGER` roots; never inherit `SESSION_TMPDIR`; `PREV_IMPLEMENT_TMPDIR` copy-only; write `session-id` + `.larch-keepalive`; warn-only `check-stale-plugin`.
- `write-id` idempotency on non-empty `--output`.
- `persist-run-flags` `--no-issues` required.
- `cleanup-tmpdir` empty/out-of-root ⇒ refuse (exit 1); audit-log append best-effort.
- `local-cleanup` local-main-ahead-by-flush-commits ⇒ reset before ff-only pull.
- Writer-guard `/dev/null` + `--plugin-root-only` carve-outs; design-env symlink under hardcoded `~/.cache` not rejected by the XDG-aware check.
- `persist-run-flags`/`entry-gate`/`write-run-params` preserve exit-2/exit-4 semantics relied on by `implement-bootstrap`.
- Shell call sites with `CLAUDE_PLUGIN_ROOT` unset (hook/standalone) resolve the CLI via SCRIPT_DIR/fallback.

## Failure modes
1. **Source-safe parity drift** in `write-design-env`: a quoting or path (XDG vs `~/.cache`) difference silently breaks every `.md` prelude that `source`s the design env. Mitigation: `bash source` round-trip + `~/.cache`-under-XDG pytest. Highest-risk surface.
2. **Resume-tail plugin-root gap**: deleting `write-session-env.sh` without `write-env --plugin-root-only` breaks `implement-bootstrap.sh --resume-plan-tail`. Mitigation: ship the carve-out surface, repoint bootstrap, assert B7 parity before deletion.
3. **Writer-guard mis-scoping**: too broad (cleanup allowlist) weakens NEVER #14; too strict rejects the `~/.cache` design-env symlink or `/dev/null`/plugin-root writes. Mitigation: stricter session-content validator + explicit carve-outs + dedicated symlink validator; cover each in pytest.
4. **Silent ship-behavior change**: unifying `local-cleanup` with finalize's divergent `_local_cleanup`, or expanding `restore-finalize-state` keys, would change ship/postmerge behavior and break parity harnesses. Mitigation: port `local-cleanup` standalone; keep `restore-finalize-state` 20-key; leave finalize untouched.
