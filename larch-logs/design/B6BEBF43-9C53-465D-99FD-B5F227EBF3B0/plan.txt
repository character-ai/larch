# Implementation Plan — Delete 6 larch skills

## Scope summary

Delete 6 larch skills (skill-evolver, simplify-skill, show-skill, compress-skill, create-skill, umbrella) including their directories, tests, and documentation. Update runtime references so no live consumer of the deleted skills remains. Leave CHANGELOG.md entries and `larch-logs/` run records intact as historical artifacts. Replace `/review` description-mode auto-issue-filing (which went through `/umbrella`) with no-op + manual /issue follow-up (drop the auto-filing path entirely).

Two scope decisions from Round 1 frame this plan:
- **Decision 1 (Runtime refs only)**: scrub references in runtime files; leave CHANGELOG.md and `larch-logs/` untouched.
- **Decision 2 (Scrub umbrella broadly)**: remove `/umbrella` prose from SECURITY.md and /issue scripts; keep `/issue`'s `--blocked-by-issue` flag (caller-agnostic) but remove `/umbrella`-specific prose.

## Edge cases

- **Makefile shard balance**: removing ~12 test targets from various shards may unevenly distribute remaining harnesses across shards. `test-harness-shards-coverage` only checks that every target lives in exactly one shard (not balance). The CI matrix can still pass with an uneven distribution; rebalancing is optional polish.
- **`/review` description mode behavior change**: removing the `/umbrella`-driven auto-issue-filing changes default behavior — OOS findings in `oos.md` are no longer auto-filed as GitHub issues. Users follow up with `/issue` manually. This is the explicit consequence of the "scrub umbrella refs broadly" decision.
- **`/issue --blocked-by-issue` flag**: kept (caller-agnostic per the user's Decision 2 framing). The `/umbrella` consumer is gone, but other callers (operators, future skills) may still supply the flag.
- **Plugin permission caching**: `.claude/settings.json` changes take effect on the next session. Existing in-progress sessions hold cached permissions; this is a known property of the plugin lifecycle and does not affect this PR.
- **`/im` skill survival**: `/im` remains. Its public-facing caller `/create-skill` is being deleted, but `/im` is still useful for standalone use and is invoked via the Skill tool from `/alias`. KEEP.
- **`/alias` skill survival**: KEEP — `/alias` is for general delegation aliases. Its create-skill cross-reference is updated inline in `resolve-target.md`.

## Failure modes (3 most likely)

1. **Missed reference → broken doc cross-link or stale agent-lint allow-list path**. *Signal*: `make markdownlint` finds a broken `skills/<deleted>/...` link, OR `make agent-lint` reports an allowed-list path that no longer exists. *Mitigation*: comprehensive grep before commit (`grep -rE 'skill-evolver|simplify-skill|show-skill|compress-skill|create-skill|/umbrella|skill:umbrella|larch:umbrella' ...`) plus the Phase 6 `make lint` gate.
2. **Makefile shard imbalance breaks `test-harness-shards-coverage`**. *Signal*: `make test-harness-shards-coverage` reports "umbrella missing shard targets" or "umbrella has unexpected prerequisites". *Mitigation*: after each `.PHONY` / shard edit, re-run the coverage check; adjust until clean.
3. **`/review` description-mode runtime failure if SKILL.md is half-updated**. *Signal*: a `/review` description-mode run would invoke `/umbrella` via the Skill tool, find no `/umbrella` skill, and stall or error. *Mitigation*: update `skills/review/SKILL.md` in the same commit as the `skills/umbrella/` deletion; never land a half-state. CI does not run `/review` end-to-end, so this is caught only by `make test-review-structure` (which the Phase 5 edits to `scripts/test-review-structure.sh` should keep clean) plus manual smoke-test.
