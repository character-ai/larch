**`is_security_tagged(block_text: str) -> bool`**
- Port the classifier logic from `skills/shared/scripts/oos-serialize.sh` exactly.
- Remove fenced code globally:
  - `re.sub(r"```.*?```", "", text, flags=re.DOTALL)`
- Build `text_no_backtick` only for the canonical-token check:
  - `re.sub(r"`[^`\n]*`", "", text_no_fence)`
- Match canonical token:
  - `focus-area\s*=\s*security`, ignorecase.
- Match explicit security only on the first line:
  - Allow both `[OUT_OF_SCOPE]` and `[OOS]` prefixes.
  - Allow backtick-wrapped `[security]` and `<security>`.
  - Keep the retired regex shape:
    - `^###\s+(?:OOS_\d+:|FINDING_\d+:)\s*(?:\[(?:OUT_OF_SCOPE|OOS)\]\s*)?`...
- Match focus-area field lines after per-line normalization:
  - `normalized = line.replace("`", "").replace("*", "").strip()`
  - Then apply the retired `field_value` regex.

**`oos_serialize(findings_file: Path, output_file: Path, session_env_path: Path | None = None) -> tuple[int, int]`**
- Return `(oos_accepted, oos_held_security)`.
- Ignore `session_env_path`; keep it for CLI compatibility.
- Create `output_file.parent` with `parents=True, exist_ok=True` before writing.
- Truncate `output_file` to empty on entry.
- Scan only `### FINDING_N:` blocks from `findings_file`.
- A block starts at `^###\s+FINDING_\d+:` and ends at the next such header or EOF.
- A block is OOS when the header or any body line contains `[OUT_OF_SCOPE]` or `[OOS]`.
- Skip non-OOS blocks silently.
- Classify every OOS block before applying the accepted-whitelist serialization rule.
  - Security blocks increment `held_security`.
  - Security blocks are not written, even when rejected or neutral.
  - This preserves the retired behavior where rejected security-tagged OOS blocks still count as held.
- Apply the accepted-whitelist Vote tally rule only to non-security OOS blocks:
  - Inspect only lines beginning `Vote tally: `.
  - Treat a Vote tally result as present only when that line matches `(^|[ \t])Result=`.
  - Do not treat substrings such as `NotResult=rejected` or `NoResult=rejected` as present results.
  - If no Vote tally line has a present Result token, the block remains eligible.
  - If at least one Vote tally line has a present Result token, serialize only when some such line also matches `(^|[ \t])Result=accepted([ \t]|$)`.
  - Do not accept `Result=accepted-extra` or other values that fail the retired whitespace/end boundary.
  - Skip every present non-accepted result, including `Result=rejected` and `Result=neutral`.
  - Prose mentions of `Result=rejected` outside a `Vote tally: ` line do not skip the block.
  - Port the retired awk condition:
    - `line starts with "Vote tally: " and /(^|[[:space:]])Result=/`
    - acceptance requires `/(^|[[:space:]])Result=accepted([[:space:]]|$)/` on that same line.
- Non-security eligible blocks are normalized with `normalize_oos_block_header(seq, text)`.
- Increment OOS output sequence only for serialized non-security blocks.
- Append one blank line after each serialized block, matching the retired helper.
- Build serialized output in memory and write it only after the full scan succeeds.
- On classifier exception or non-boolean classifier result:
  - Raise a module-local classification error.
  - Leave `output_file` empty.
  - Do not write partial accepted blocks.

## Edge cases

- A `Vote tally: ... Result=neutral` non-security OOS block must be skipped.
- A `Vote tally: ... Result=rejected` non-security OOS block must be skipped.
- A `Vote tally: ... NotResult=rejected` non-security OOS block must remain eligible when no true Result token exists.
- A `Vote tally: ... NoResult=rejected` non-security OOS block must remain eligible when no true Result token exists.
- A `Vote tally: ... Result=accepted-extra` line must not satisfy the accepted boundary.
- A rejected or neutral security-tagged OOS block must be counted as held and not serialized.
- A block with no `Vote tally: ... Result=` token line remains eligible when it is non-security.
- A prose `Result=rejected` mention remains eligible.
- `[OOS]` plus first-line `[security]` or `<security>` must be held.
- Backtick or bold `focus-area: security-hardening` fields must be held.
- Body-cited security headings must not trigger the header classifier.
- Serializer output parent directories must be created before truncation.
- Classifier failures must fail closed and leave no partial public sink.
- Normalize-header stdin mode and exit-2 validation must match the retired helper.
- Normalize-header success payload must be emitted on stdout so shell redirection captures it.
