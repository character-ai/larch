## Plan

Ship a standalone library script `skills/design/scripts/revise-plan-with-waterfall.sh` that drives a fixed Codex → Cursor → Claude waterfall for between-round plan revisions. Each tier renders a prompt from `plan.txt` + accepted findings + feature context, launches the configured launcher with the composed prompt as `--prompt-file`, validates the emitted patch against the canonical plan path, applies it atomically with revert on failure, and re-runs `ACTION=EMIT_PLAN` to refresh `diff-lines.txt`. The script is a pure library — Piece 5 (#2871) owns integration into `skills/design/scripts/plan-review-loop.sh`. A fully-mocked offline harness at `scripts/test-revise-plan-with-waterfall.sh` covers waterfall promotion, patch validator, apply/revert, and the emit-plan gate via env-var launcher stubs and deterministic plan fixtures.

The waterfall always exits 0; logical outcomes are surfaced via the lib-quiet contract stream (`REVISE_STATUS`, `REVISE_TIER`, `REVISE_PATCH_PATH`, `REVISE_PLAN_HASH_BEFORE`, `REVISE_PLAN_HASH_AFTER`, per-tier `REVISE_TIER_<N>_STATUS`). The per-tier ordinal mapping is part of the contract: `REVISE_TIER_1_STATUS` corresponds to codex, `REVISE_TIER_2_STATUS` to cursor, `REVISE_TIER_3_STATUS` to claude. Every KV is emitted unconditionally on every invocation (failure paths explicitly emit `REVISE_TIER=""` and `REVISE_PATCH_PATH=""` so presence-aware callers always see `KEY=`). Bash 3.2 portable; no associative arrays, no namerefs, no `mapfile`. Plan grammar is preserved end-to-end: the `### NEW:/UPDATED:/REWRITTEN:` headings and the final `diff_lines: <N>` trailer must survive validation.

### NEW: `skills/design/scripts/revise-plan-with-waterfall.sh`

Bash 3.2 library script. Argv:

- `--design-tmpdir <dir>` (required): session tmpdir; output files land under `<dir>/plan-review/round-<N>/revise/`; `<dir>/plan.txt` is the canonical plan file the script reads/writes (see preflight rule 2 below).
- `--plan-file <path>` (required): the in-place `plan.txt` to revise. **Preflight invariant**: the canonical resolution (`cd "$(dirname "$path")" && pwd -P`/basename) MUST equal `$design_tmpdir/plan.txt`; argv mismatch → `larch_err` + `exit 2`. This keeps the standalone-callable interface (any caller can pass the path explicitly) while ensuring the file revised, validated, and reported on is the same file `ACTION=EMIT_PLAN` reads.
- `--findings-file <path>` (required): accepted in-scope plan-review findings (one round's `accepted-plan-findings.md`).
- `--feature-file <path>` (required): the canonical feature description (read-only context).
- `--round-num <N>` (required): integer round identifier; used in per-tier output paths.
- `--codex-present <true|false>` (required): availability snapshot for Codex tier.
- `--cursor-present <true|false>` (required): availability snapshot for Cursor tier.
- `--timeout <secs>` (default `1800`): per-tier launcher timeout. Forwarded as `--timeout "$timeout"` to every launcher (Codex/Cursor/Claude); without it `launch-review.sh` exits 2.
- `--patch-format <unified-diff|file-replacement>` (default `unified-diff`): how the LLM is asked to emit the patch and how the validator interprets the output. `unified-diff` is the smallest-change default because `git apply` already enforces structural validity; the `file-replacement` knob exists (per Step 3 vote, exonerated) so Piece 5 can switch without further argv churn if unified-diff proves brittle in practice.
- `--help`: usage + exit 0.

Source `scripts/lib-quiet.sh`; call `larch_quiet_init`. Use `emit_kv` for every machine line.

Behavior — pre-flight:

1. Validate argv (required flags non-empty, files readable, integers numeric, booleans `true`/`false`). Argv defects → `larch_err` + `exit 2` (caller bug; not a logical failure).
2. Canonicalize `--plan-file` and `--design-tmpdir`; require `canonical(plan_file) == canonical(design_tmpdir)/plan.txt`. Mismatch → `larch_err` describing both paths + `exit 2`. This is the same invariant Piece 5 (#2871) is expected to satisfy when it calls this script (`SKILL.md` Step 3 uses `$DESIGN_TMPDIR/plan.txt` throughout).
3. Resolve launcher paths via env-var overrides for harness substitution: `LARCH_TEST_LAUNCH_CODEX_REVIEW` → defaults to `${CLAUDE_PLUGIN_ROOT}/scripts/launch-review.sh`; `LARCH_TEST_LAUNCH_CURSOR_REVIEW` → same default; `LARCH_TEST_LAUNCH_CLAUDE_REVIEW` → defaults to `${CLAUDE_PLUGIN_ROOT}/scripts/launch-claude-review.sh`; `LARCH_TEST_DESIGN_DRIVER` → defaults to `${CLAUDE_PLUGIN_ROOT}/skills/design/scripts/design-driver.sh`.
4. Compute `REVISE_PLAN_HASH_BEFORE` via `shasum -a 256 "$plan_file" | awk '{print $1}'`.
5. Record whether the original plan contained any `### NEW:`, `### UPDATED:`, or `### REWRITTEN:` headings (parseable by the heading grammar — at least one ASCII whitespace after `###`, optional whitespace before `:`) by counting them once via `grep -E '^###[[:space:]]+(NEW|UPDATED|REWRITTEN)[[:space:]]*:'`. Store the count in `_orig_file_heading_count` for the post-apply check (FINDING_5).
6. Snapshot the plan: `cp "$plan_file" "$plan_file.before-revise"`. On script exit (success OR failure), remove `.before-revise` only on `REVISE_STATUS=ok` or after a successful revert; otherwise leave it for the caller to inspect.
7. Compose the prompt file once at `<round-dir>/revise/prompt.txt`. Body:
   - One-line role banner ("You are revising an /design implementation plan based on accepted reviewer findings.").
   - Patch-format directive (unified-diff: "Emit ONLY a single unified diff in your final response, with no prose, no fences, no narration. Use the canonical form `--- a/plan.txt` / `+++ b/plan.txt` (relative paths, no directory prefix beyond `a/` / `b/`)." / file-replacement: "Emit ONLY the complete replacement plan in your final response, beginning with `## Plan` and ending with `diff_lines: <N>`.").
   - Hard rule: the revised plan must end with `diff_lines: <N>` (validator enforces). When the original plan had `### NEW:/UPDATED:/REWRITTEN:` headings, the revision must preserve at least one such heading (validator enforces — see FINDING_5 post-candidate check).
   - `<plan>…</plan>`, `<findings>…</findings>`, `<feature>…</feature>` reference blocks, content from the three input files.

Behavior — waterfall:

For each tier in fixed order `(codex, cursor, claude)` with ordinal `<N>` ∈ `{1, 2, 3}` respectively:

a. **Skip predicate**: if the tier is `codex` and `--codex-present` is `false`, emit `REVISE_TIER_1_STATUS=skipped-not-present` and continue. Same for `cursor` (`REVISE_TIER_2_STATUS=skipped-not-present`). The Claude tier is always attempted (no presence flag — Claude is the in-session fallback).
b. **Launch**: route through the resolved launcher with mode `description` and `--prompt-file "$prompt_path"` as the prompt source. Codex/Cursor go via `launch-review.sh --tool codex|cursor --output <round-dir>/revise/<tier>-output.txt --prompt-file "$prompt_path" --mode description --timeout "$timeout" --plan-file "$plan_file" --feature-file "$feature_file" --scope-files "$findings_file"`. Claude goes via `launch-claude-review.sh --output <round-dir>/revise/claude-output.txt --prompt-file "$prompt_path" --mode description --timeout "$timeout" --plan-file "$plan_file" --feature-file "$feature_file" --scope-files "$findings_file"`. Do NOT pass `--description-text` (the `--prompt-file` IS the prompt source; mixing both is a launcher-config defect). Capture exit code into per-tier `_tier_rc` without aborting the surrounding waterfall.
c. **Extract patch**: read `<round-dir>/revise/<tier>-output.txt`. Patch is the entire file body when `--patch-format=unified-diff` (strip a single fenced ```diff … ``` wrapper if present; nothing else accepted) or the complete file content when `--patch-format=file-replacement`. Empty / unreadable output → `REVISE_TIER_<N>_STATUS=no-patch`.
d. **Validate** (see "Patch validator" section in the sibling `.md` for full grammar; summary here):
   - **Unified-diff mode**: parse every `diff --git` / `--- ` / `+++ ` header in the patch; require every old/new path to be exactly `a/plan.txt` or `b/plan.txt` (no directory prefix beyond `a/` / `b/`); reject otherwise. Then `cd "$(dirname "$plan_file")"` and run `git apply --check --whitespace=nowarn "$patch_file"` (NOT `--unsafe-paths`; the working directory provides the basename context). Reject any patch that touches files other than `plan.txt` via the header check above — the `cd dirname` + canonical `a/plan.txt`/`b/plan.txt` form is the single allowlist mechanism.
   - **File-replacement mode**: file is non-empty and ends with `diff_lines: <N>` (numeric).
   - On any failure set `REVISE_TIER_<N>_STATUS=invalid-patch` and continue waterfall.
e. **Apply**:
   - **Unified-diff mode**: with the same `cd "$(dirname "$plan_file")"` working directory, run `git apply --whitespace=nowarn "$patch_file"`. The header validation in step d means the apply touches only `plan.txt`; the working directory means we do not need `--unsafe-paths`. If the session tmpdir is not a git worktree (common case — `$DESIGN_TMPDIR` is `mktemp -d`), `git apply` still works because it operates on the working tree without consulting `.git/`. The harness fixtures and the sibling `.md` both pin this canonical form (FINDING_6).
   - **File-replacement mode**: `mv -f` of the candidate file onto `<plan-file>`.
   - Apply failure → restore from `.before-revise` and set `REVISE_TIER_<N>_STATUS=apply-failed`; continue waterfall.
f. **Post-apply heading check** (FINDING_5): when `_orig_file_heading_count > 0`, count `### NEW:/UPDATED:/REWRITTEN:` headings in the post-apply plan via the same `grep -E` rule from preflight step 5. If the post-apply count is `0`, the revision dropped all file-scope headings → restore from `.before-revise`, set `REVISE_TIER_<N>_STATUS=invalid-patch` (treating it as a validator failure rather than apply failure since the apply itself succeeded), and continue waterfall.
g. **Emit-plan gate**: pipe `printf 'ACTION=EMIT_PLAN\n' | "$design_driver" --design-tmpdir "$design_tmpdir"`. Parse `EMIT_PLAN_STATUS` from stdout. On `EMIT_PLAN_STATUS=ok` set `REVISE_TIER_<N>_STATUS=ok` and break out of the waterfall (this tier won). On any other status restore from `.before-revise`, set `REVISE_TIER_<N>_STATUS=emit-plan-failed`, and continue.

Behavior — finalize:

After the loop, decide the overall status and emit every KV unconditionally on the lib-quiet stream (one record per invocation):

- Any tier with `REVISE_TIER_<N>_STATUS=ok` →
  - `emit_kv REVISE_STATUS ok`
  - `emit_kv REVISE_TIER "$winner"` (one of `codex`, `cursor`, `claude`)
  - `emit_kv REVISE_PATCH_PATH "$round_dir/revise/${winner}-output.txt"`
  - `emit_kv REVISE_PLAN_HASH_BEFORE "$_hash_before"`
  - `emit_kv REVISE_PLAN_HASH_AFTER "$_hash_after"` (freshly computed post-apply)
  - Remove `.before-revise`; exit 0.
- All tiers exhausted with no `ok`:
  - Pick `REVISE_STATUS` precedence based on which failure modes were seen across the three tiers:
    - If every tier emitted `no-patch` or `skipped-not-present` → `REVISE_STATUS=failed-no-patch`.
    - Else if at least one tier reached the validator and failed it (`invalid-patch`) → `REVISE_STATUS=failed-validation`.
    - Else if at least one tier reached apply or emit-plan and failed (`apply-failed` / `emit-plan-failed`) → `REVISE_STATUS=failed-apply`.
  - `emit_kv REVISE_STATUS "$_status"`
  - `emit_kv REVISE_TIER ""` (explicit empty value, per FINDING_8 — never omit the key)
  - `emit_kv REVISE_PATCH_PATH ""` (explicit empty value, per FINDING_8)
  - `emit_kv REVISE_PLAN_HASH_BEFORE "$_hash_before"`
  - `emit_kv REVISE_PLAN_HASH_AFTER "$_hash_before"` (plan is reverted; before == after)
  - Snapshot `.before-revise` is left in place for caller debugging; exit 0.
- In all branches, the three per-tier KVs (`REVISE_TIER_1_STATUS`, `REVISE_TIER_2_STATUS`, `REVISE_TIER_3_STATUS`) are emitted exactly once each, in ordinal order, before the summary block. Tiers that never executed because an earlier tier won emit `REVISE_TIER_<N>_STATUS=not-attempted`.

## Approach

- **Standalone library shape with canonical-plan invariant**: pure argv-driven Bash 3.2 script with the `lib-quiet.sh` contract stream. The `--plan-file` flag is kept (so callers always pass the path explicitly) but a preflight requires it to canonically resolve to `$design_tmpdir/plan.txt`. This is the minimum-friction reconciliation between "standalone library" (explicit argv) and "no skew between revised file and validated file" (the file `ACTION=EMIT_PLAN` reads is the same file `git apply` modifies).
- **Fixed waterfall order**: Codex → Cursor → Claude. Order is hard-coded (no `--order` flag) — the issue and parent plan explicitly specify this ordering. Adding configurability would be over-engineering on SIMPLE tier.
- **Prompt source via `--prompt-file`**: every tier receives the composed prompt as `--prompt-file "$prompt_path"`; `--description-text` is NOT passed. The launchers (real Codex/Cursor/Claude) require exactly one prompt source; mixing both is a defect.
- **No `--unsafe-paths`**: the script `cd "$(dirname "$plan_file")"` before `git apply --check` / `git apply`, requiring the diff to use the canonical `a/plan.txt` / `b/plan.txt` form. The cd-then-relative-path pattern is the single allowlist mechanism — there is no `--unsafe-paths` widening the trust boundary. Diffs touching any other path are rejected by the header check before `git apply` runs.
- **Patch format default unified-diff**: unified diff is the obvious mainline. The `--patch-format file-replacement` knob exists (per Step 3 vote — reviewers wanted to drop it; voters exonerated the scope) so the integration (#2871) can switch without further argv churn if rounds reveal unified-diff brittleness.
- **Validator scope**: smallest checks that prevent corruption — patch headers reference only `plan.txt`, `git apply --check` passes, post-apply file has at least one `### NEW:/UPDATED:/REWRITTEN:` heading when the original had any, ends with a numeric `diff_lines: <N>` trailer, and `ACTION=EMIT_PLAN` accepts it. Anything beyond this belongs in `check-plan-size.sh` and the plan-review panel.
- **Snapshot revert with file-level `cp`**: a peer-file snapshot is simpler than git-stash or git-checkout and lets the script work in non-git scratch dirs (the harness uses `$TMPROOT/case_dir` which is not a git worktree). On overall failure we leave the snapshot for caller inspection so they can diff what each tier emitted vs the original. `git apply` does not require a git worktree — it operates on the working tree without consulting `.git/` — so we do NOT `git init` the session tmpdir.
- **Tier launchers via env-overrides**: the harness substitutes stub scripts via `LARCH_TEST_LAUNCH_*` env vars. Production callers don't set them and the real launchers run.
- **Unconditional KV emission**: every key the script's contract declares is emitted on every invocation. Failure paths explicitly emit `REVISE_TIER=""` and `REVISE_PATCH_PATH=""` rather than omitting the keys, so presence-aware callers always see `KEY=`. Per-tier statuses are emitted in fixed ordinal order (1=codex, 2=cursor, 3=claude); tiers that didn't run emit `not-attempted` rather than being absent.

## Edge cases

- **Empty plan file** at start: preflight canonicalization succeeds; first tier launches; emit-plan gate (or the diff_lines: trailer check in file-replacement mode) fails because the source plan had no `diff_lines:` trailer → surface `REVISE_TIER_<N>_STATUS=emit-plan-failed` and continue. End state: `REVISE_STATUS=failed-apply` (per the precedence rule). Sibling `.md` documents this as caller-responsibility.
- **`plan.txt` already missing `diff_lines:` trailer**: same as above — emit-plan gate fails for every tier, plan reverts to its (already malformed) original; `REVISE_PLAN_HASH_AFTER=REVISE_PLAN_HASH_BEFORE`.
- **Diff that touches files other than `plan.txt`**: header check rejects before `git apply --check` runs → `REVISE_TIER_<N>_STATUS=invalid-patch`. Test case #3 covers this.
- **Diff that uses non-`a/plan.txt` header form** (e.g. `--- plan.txt` without the `a/` prefix, or `--- /abs/path/plan.txt`): header check rejects → `invalid-patch`. The canonical form is documented in the prompt directive and pinned in the harness fixtures (FINDING_6).
- **`$DESIGN_TMPDIR` is not a git worktree**: `git apply` still works because it does not require `.git/` for the apply itself (it only needs working-tree access). No `git init` is performed.
- **Launcher returns non-zero exit**: treated as `no-patch` regardless of file content (per `dispatch-with-waterfall.sh` precedent — a non-zero exit is a launcher-level failure, not a patch we can trust).
- **`--codex-present false AND --cursor-present false`**: both external tiers skip (`REVISE_TIER_1_STATUS=skipped-not-present`, `REVISE_TIER_2_STATUS=skipped-not-present`); only Claude runs. If Claude wins → `REVISE_STATUS=ok REVISE_TIER=claude`. If Claude also fails → `REVISE_STATUS=failed-*` per precedence.
- **Concurrent invocations on the same `$DESIGN_TMPDIR/plan-review/round-<N>/`**: not supported. The caller (Piece 5) is single-runner inside one `/design` session per the single-runner invariant. Document this as a caller invariant — do not add file locking.
- **`.before-revise` from a prior failed run already exists**: overwrite without warning. Snapshot is per-invocation, not append-only.
- **Per-tier output path collision across reruns**: same directory, same filename; later writes overwrite. Acceptable — callers retry per-round, not in-place.
- **Heading-only revision** (FINDING_5 corner): a revision that removes the last `### NEW:/UPDATED:/REWRITTEN:` heading but otherwise applies cleanly reverts via the post-apply heading check. If the original plan had zero such headings, the heading check is a no-op (don't penalize plans that legitimately have no file-scope sections).

## Failure modes

1. **All three tiers emit unparseable output (LLM regression)**. Earliest warning signal: `REVISE_TIER_1_STATUS=no-patch` or `=invalid-patch` on a tier that historically succeeded. Mitigation: caller (Piece 5) treats `REVISE_STATUS=failed-*` as a degraded round; the multi-round loop in #2871 already plans to handle this via the convergence/quorum gate. This script just surfaces the failure cleanly.
2. **`git apply` corrupts `plan.txt` despite returning success** (extremely unlikely but possible with whitespace-only diffs). Earliest signal: emit-plan gate rejects the post-apply file. Mitigation: the emit-plan gate + post-apply heading check are the strict structural validators; on failure we revert from `.before-revise`. The snapshot is taken before any tier runs, so the revert always brings the plan back to its pre-invocation state.
3. **`design-driver.sh ACTION=EMIT_PLAN` itself regresses or moves**. Earliest signal: harness case "Codex wins" fails because the stub driver returns no `EMIT_PLAN_STATUS=ok`. Mitigation: pin the driver path via env var (`LARCH_TEST_DESIGN_DRIVER`) so the harness exercises the wiring; the sibling `.md` enumerates the env var so production callers can override on emergency.

## Testing strategy

- **Primary**: `scripts/test-revise-plan-with-waterfall.sh` (eleven cases listed above — eight original + three from FINDING_2 / FINDING_5 / canonical-plan invariant) — fully offline, no network, no Codex/Cursor/Claude binary required. Hermetic via `LARCH_QUIET_DISABLE=1` + per-test `mktemp -d` + trap cleanup. Stub launchers assert `--prompt-file` is the sole prompt source.
- **CI wiring**: `make test-revise-plan-with-waterfall` runs the harness directly; `make test-harnesses-9` includes it in the existing parallel bucket. `make lint-bash32` automatically covers the new `.sh` (no explicit registration needed).
- **Sibling-md check**: `agent-lint` (already runs in CI) verifies every `.sh` has a sibling `.md`; the four new files satisfy that.
- **No live LLM tests**: per Step 1c Decision 2, the harness is fully mocked. Drift between stubs and real launchers is acceptable risk — the integration piece (#2871) already plans live multi-round runs in `scripts/test-design-multi-round-integration.sh` that will exercise the real launchers end-to-end.
- **Manual smoke**: optional follow-up — operator can run `bash skills/design/scripts/revise-plan-with-waterfall.sh --design-tmpdir /tmp/foo --plan-file /tmp/foo/plan.txt --findings-file /tmp/foo/findings.md --feature-file /tmp/foo/feature.txt --round-num 1 --codex-present true --cursor-present true` against a hand-crafted fixture and inspect outputs.
