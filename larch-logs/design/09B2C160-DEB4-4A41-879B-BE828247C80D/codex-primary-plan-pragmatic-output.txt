[risk-integration] `scripts/launch-review.sh:196-206` and `scripts/launch-claude-review.sh:65-69`: the proposed launch step says to pass `--mode description` with `--description-text` set to the composed prompt, but both launchers require exactly one prompt source (`--prompt`, `--prompt-file`, or `--agent-file`). `--description-text` is only context for rendering an agent-file prompt, not a prompt source. Revise the plan to launch with `--prompt-file "$prompt_file"` or `--prompt "$(cat "$prompt_file")"`.

2. [correctness] `skills/design/scripts/emit-plan.sh:43-57`: `ACTION=EMIT_PLAN` always validates `$DESIGN_TMPDIR/plan.txt`, while the new script accepts an arbitrary `--plan-file`. If those differ, the apply path and validation gate operate on different files. For the minimum fix, require `--plan-file` to canonicalize to `$design_tmpdir/plan.txt`, or remove the arbitrary-file contract.

[security] `skills/design/scripts/revise-plan-with-waterfall.sh` (planned): the plan relies on a “plan.txt allowlist” around `git apply --unsafe-paths`, but `git apply` does not provide such a per-file allowlist.
