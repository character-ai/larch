## Findings

### 1. Correctness — `python/larch/cli.py:618-621`

The plan’s AST rule is intentionally broad (“every expression context”, list **and** tuple). That matches the adoption goal for call-site argv like `proc.run(["gh", ...])` and `_gh_read(["gh", ...])`, which the narrower subprocess gh scan in `lint_subprocess_via_runner.py:170-182` misses today.

It also matches non-argv registry keys:

```618:621:python/larch/cli.py
    ("gh", "resolve-repo"): ("larch.git.gh", "resolve_repo_main"),
    ("gh", "remote-repo"): ("larch.git.gh", "remote_repo_main"),
    ("gh", "run-logs"): ("larch.git.gh", "run_logs_main"),
    ("gh", "workflow-path"): ("larch.git.gh", "workflow_path_main"),
```

Those tuples are CLI namespace keys, not executable argv. They should survive repoint. The plan’s “expect no findings after repoint” check cannot succeed unless the rule or exemptions are adjusted, or four permanent pragmas are added without being planned.

### 2. Risk-integration — `.pre-commit-config.yaml` (planned hook)

Integration coverage is otherwise sound:

- CLI registration is correctly aimed at `python/larch/cli.py` (where `("lint", "subprocess-via-runner")` already lives at line 468).
- `Makefile:58` `py-lint-checks-fast` is the CI fast-lint path (`python-lint` shard 1 via `Makefile:624`).
- `Makefile:276-277` `lint-only` → pre-commit is the `lint-local` CI path (`.github/workflows/ci.yaml:137`).

The remaining integration gap is hook trigger semantics. The plan names `pass_filenames: false` and cites the always-run convention, but does not require `always_run: true` in the firm `.pre-commit-config.yaml` edit. Spell it out so the hook cannot be wired like `lint-run-log-walkers` (`.pre-commit-config.yaml:312-317`), which only fires when staged paths match.

### 3. Verified plan strengths (no finding)

- **Detection scope**: list/tuple, first-element `"gh"` literal, every AST context, with `larch/git/` and standard test exemptions, matches the issue anchor and existing `python/larch/**/*.py` lint patterns (`lint_lifecycle_prefix_literal.py:148-161`).
- **Suppression**: same-line, reason-bearing `# lint-gh-argv-literal: ok <reason>` via tokenized comments matches `lint_guidelines_note_wrapper_bypass.py:58-70`; planned tests cover empty reason, other-line pragma, and pragma-like string content (same pattern as `test_lint_guidelines_note_wrapper_bypass.py:136-148`).
- **Failure handling**: exit `2` on unreadable/non-UTF-8/parse failures is stricter than today’s gh helper path in `lint_subprocess_via_runner.py:281-288`, which silently returns `[]`.
- **subprocess-via-runner preservation**: explicitly frozen per plan; overlap is real but intentional for this PR.

### [OUT_OF_SCOPE] Architecture — `python/larch/lint/lint_subprocess_via_runner.py`

After adoption, gh argv will be governed by both the new baseline-free lint and the existing gh sub-ratchet with `subprocess-via-runner-gh-baseline.json`. Retiring the older gh scan is reasonable follow-up work, not required to ship this feature once repoint is complete.
