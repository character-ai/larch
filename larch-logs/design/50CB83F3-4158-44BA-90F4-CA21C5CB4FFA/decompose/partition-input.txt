**Original feature context (excerpt)**:

# contract-unification [FEATURE] adoption lint: hard-ban "gh" argv literals outside larch/git/

​#### Problem

Once the wrappers exist and every caller is repointed, nothing prevents new raw `["gh", ...]` argv from reintroducing divergent pagination/error grammars and skipping `_retry_read`. Adoption decays without enforcement.

​#### Goal

Add an adoption lint that **hard-bans** `"gh"` argv literals anywhere outside `python/larch/git/`. Test fixtures are suppressed via an explicit pragma/allowlist. The lint fails CI on **any** violation — no grandfathered baseline — so the tree must be 100% repointed first.

​#### Scope

- New lint script (Python, behind `python3 python/cli.py`) + Makefile/CI wiring.
- Test-fixture suppression mechanism (pragma or allowlist).
- `docs/linting.md` entry.

​#### Dependencies

Blocked by ALL repoint issues (listing + `_json_documents` deletion, issue view/edit/close, repo-resolution) and the wrapper-add issue. The hard ban only passes once every in-scope site is clean, so this lands last.
