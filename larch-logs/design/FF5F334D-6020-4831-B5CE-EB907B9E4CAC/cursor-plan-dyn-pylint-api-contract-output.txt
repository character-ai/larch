Reviewing the plan and pylint duplicate-code integration in the codebase.
## Findings

### 1. **correctness** — Threshold guard tests misstate Pylint 4.0.5 semantics
**Location:** `plan.txt:106-108` (proposed `python/test_duplicate_code.py`)

Pylint 4.0.5 reports duplicates only when effective common lines are **strictly greater than** `min-similarity-lines`, not when equal. In `pylint/checkers/symilar.py`, `_find_common` yields only when `eff_cmn_nb > self.namespace.min_similarity_lines` (line 539). Verified: with `min-similarity-lines=8`, two files with exactly 8 identical stripped lines produce **zero** findings; 9 lines produce a finding.

The plan’s “block at `min-similarity-lines` fails” case would encode `>=` semantics and can pass a broken runner or fail a correct one.

**Suggested revision:** Document strict-`>` parity. Threshold tests: `min-1` passes; exactly `min` passes; `min+1` fails.

---

### 2. **correctness** — Pin `pylint.checkers.symilar`; call `Symilar._find_common`, don’t copy the loop
**Location:** `plan.txt:40-44` (proposed `python/duplicate_code.py`)

`pylint.checkers.similar` does not exist in 4.0.5; the module is `pylint.checkers.symilar`. Pair-level comparison already exists as `Symilar._find_common`, with helpers `hash_lineset`, `remove_successive`, and `filter_noncode_lines` at module scope.

The plan’s “copy the minimal pair comparison loop” fallback invites a broad, drift-prone fork of ~80 lines of internal logic.

**Suggested revision:** Import from `pylint.checkers.symilar` only. Instantiate `Symilar(min_lines=..., ignore_*=...)` from parsed `[SIMILARITIES]` and call `_find_common(lineset_a, lineset_b)` per shard. Reserve copying for import failure only (exit `2`). Add a module comment: `# pylint==4.0.5 internal API; see pylint/checkers/symilar.py`.

---

### 3. **correctness** — `[SIMILARITIES]` flags use `yn` (`yes`/`no`), not Python booleans
**Location:** `plan.txt:26-30`, `python/.pylintrc:528-537`

`.pylintrc` uses `ignore-comments=yes` style values. Pylint’s checker defaults treat unset flags as `True` (`symilar.py:767-800`), while `Symilar.__init__` defaults them to `False` (`symilar.py:341-344`). A naive parser that reads booleans or falls back to `Symilar()` defaults will change normalization vs today’s `pylint -j 1` run.

**Suggested revision:** Parse `yes`/`no` like Pylint’s `yn` option type. Pass all four flags explicitly into `LineSet` / `Symilar`; never rely on `Symilar()` constructor defaults alone.

---

### 4. **risk-integration** — `ignore-paths` must be resolved relative to `--root`, not repo root
**Location:** `plan.txt:31-36`, `python/.pylintrc:55`

Today’s job runs `cd python && pylint ... .`, so `ignore-paths=.venv/,.mypy_cache/` applies under `python/`. The proposed CLI runs from repo root with `--root python`. If discovery emits `python/foo.py` while patterns stay `.venv/`, `python/.venv/` may not be excluded and file sets can diverge from Pylint.

**Suggested revision:** Walk under `--root` with paths relative to that root (same basis as `cd python && pylint .`). Match `ignore-paths` against those relative paths, matching Pylint’s cwd semantics.

---

### 5. **[OUT_OF_SCOPE]** — `line_enabled_callback` / per-line `# pylint: disable=duplicate-code`
**Location:** `plan.txt:40-44` (`LineSet` construction)

Pylint passes `line_enabled_callback=self.linter._is_one_message_enabled` into `LineSet` (`symilar.py:384-388`, `632-635`). The plan omits this. No `disable=duplicate-code` / `R0801` usages exist under `python/` today, so parity is not required for this issue’s correctness gate.

---

### 6. **[OUT_OF_SCOPE]** — Reuse Pylint’s config loader instead of a custom `[SIMILARITIES]` parser
**Location:** `plan.txt:25-31`

`PyLinter` / `arguments_manager` can load `python/.pylintrc` and expose typed options, reducing hand-rolled INI parsing. Worth a follow-up issue; not blocking if the custom parser handles `yn` and paths correctly.
