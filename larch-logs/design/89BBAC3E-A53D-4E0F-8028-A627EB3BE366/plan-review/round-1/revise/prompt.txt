## Edge cases

- **Repo cannot resolve**: abort before temp proposal work.
- **`origin/main` cannot resolve**: abort REGULAR refresh instead of comparing against stale local code.
- **Issue changes group after fetch**: apply skips that issue and warns.
- **Issue closes after fetch**: apply skips it and warns.
- **Existing dependency edge**: skip as duplicate.
- **Proposed edge cycle**: skip and warn.
- **Both endpoints in-flight**: write nothing and emit a loud warning.
- **Fully stale REGULAR issue**: propose close only, never close before approval.
- **Partly stale REGULAR issue**: edit body in place, preserving uncertain content.
- **Large backlog**: honor pair cap and report skipped semantic pairs.

- GitHub dependency endpoints may be unavailable.
  - Fetch emits warnings.
  - Plan can still proceed with issue body analysis.

- `gh issue edit` can fail.
  - Continue other approved mutations.
  - Redact stderr and include the issue number in the final summary.
- `block-issue` can fail.
  - Continue other approved edges.
  - Count failed edges separately.
- Prompt-side semantic inference can be uncertain.
  - Default keep issue text.
  - Do not write low-confidence edges unless the operator approves the grouped plan.
