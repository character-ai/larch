## Findings

**1. [in_scope | important | correctness]** `python/plan_review_round.py:257-336`

The `/design` cap plan keys `oos_counts_by_slot` from `slot_name = slot_by_output.get(rf, Path(rf).stem.replace("-output", ""))` (plan `### UPDATED: python/plan_review_round.py`, bullets 132-136). That matches current code at ```257:257:python/plan_review_round.py``` but not how Step 3 already maps collector files to manifest slots. `write_reviewer_status_tsv` uses `voting.normalize_reviewer_basename` to join `-retry`/`-phase2`/`-phase3` paths back to phase-1 manifest outputs (```375:397:python/plan_review_round.py```; covered in `test_plan_review_round.py:831-907`).

Without the same join, retry-path OK records get a fallback slot like `cursor-plan-arch-retry` instead of manifest slot `cursor-plan-arch`. The common single-record case still caps at 3, but it violates the plan’s slot-identity contract and can allow >3 OOS if two OK collector records exist for the same logical reviewer.

**Suggested revision:** Build a normalized-basename→slot map from the manifest and resolve `slot_name` before cap checks; add a retry-path unit test.

**2. [OUT_OF_SCOPE | important | risk-integration]** `python/test_review_pipeline.py` (planned section)

Plan `### UPDATED: python/test_review_pipeline.py` (lines 171-181) tests only Claude prose with `### Out-of-Scope Observations`. External reviewers use `_parse_output_tsv` first (```1505:1509:python/review_pipeline.py```), which is the main `/implement` Step 5 path. The planned test would not catch cap regressions on structured TSV output.

**3. [OUT_OF_SCOPE | latent | correctness]** `python/test_plan_review_round.py` (planned section)

Plan `Edge cases` (line 221) requires in-scope rows after capped OOS overflow, but the proposed test (plan lines 159-169) only covers multi-reviewer OOS suppression. A bug that drops post-overflow in-scope rows or leaves numbering gaps could slip through.
