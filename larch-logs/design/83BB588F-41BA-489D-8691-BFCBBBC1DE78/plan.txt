# Implementation Plan — Issue #2790 (breadcrumb propagation rollout, core slice)

This plan lands **items 1, 2, 3, 5, 6** from issue #2790 (the "core" rollout from PR #2786). Items **4, 7, 8, 9** are explicitly out of scope and will be filed as blocked-by-2790 follow-up issues by the Step 5b OOS pipeline. Plan was revised after Gate B Apply-all to address 56 reviewer findings spanning 10 underlying defects.

## Approach

The rollout splits along three contracts:

1. **Producer-side done-trap wiring** (items 1, 2). Nine denylisted long-running scripts append `larch_quiet_append_done_trap` after their final script-owned `EXIT` trap. **CRITICAL: the existing `larch_quiet__exit_combo` at `scripts/lib-quiet.sh:149-156` is broken** — it writes the done sentinel and status BEFORE evaluating the saved prior EXIT trap, AND does not preserve `$?` for the prior trap. This plan fixes `lib-quiet.sh` to run the saved trap FIRST (with original `$?` primed), then write status/sentinel. Two of the nine scripts (`scripts/run-step5-review.sh`, `skills/implement/scripts/run-step2-dispatch.sh`) currently do not source `lib-quiet.sh` — they source the helper but **do NOT call `larch_quiet_init`** (which actively redirects stdout/stderr to a quiet log and would silently break the relay-wrapper KV contract) and instead call `larch_quiet_append_done_trap` directly. Item 2's `ci-wait.sh` progress conversion is bundled with item 1's done-trap edit on the same script; per issue #2790 item 2 the progress lines map to `--category=wait-ci` (not `progress`).

2. **Stream-category migration** (item 3). Eighteen caller files (17 from the original audit plus `.claude/skills/bump-version/scripts/apply-bump.sh` which inherits the stream when invoked from `ship-pr.sh`) receive explicit `--category=` per the fixed vocabulary in `scripts/lib-quiet.sh:222-225`. Per Step 1c Q2, the migration uses per-call judgment with a `progress` default. **FD-contract preservation**: `larch_errf` writes restored stderr (`>&4` after quiet init); `emit_breadcrumb` without `LARCH_BREADCRUMB_STREAM` falls through to stdout (the quiet log). To avoid changing the FD contract on direct/test invocations of `ci-wait.sh`, this plan adds a new `emit_breadcrumb_stderr` helper to `lib-quiet.sh` that mirrors `larch_errf`'s stderr semantics in the non-stream fallback path; `ci-wait.sh` migrations use this helper for stderr-visible progress lines. The 21+ other caller files migrate to plain `emit_breadcrumb` because their callsites already write to stdout/quiet log.

3. **Persistence-side committed log breadcrumbs batch** (items 5, 6). The new `breadcrumbs` batch is registered in `scripts/larch-log-batches.sh` with sanitizer **`none`** (NOT a new `breadcrumb-streaming` sanitizer arm — the existing `case` dispatch in `scripts/lib-larch-log.sh:103-167` is unchanged; per-file validation lives in the new directory-walk branch of `larch-log.sh`). The extension column uses **`.dir`** to mark directory-batch semantics, and `larch_log_batch_path` gains a directory-batch branch. `scripts/larch-log.sh` adds `--input-dir` parsing and a new branch that: (a) accepts `--session-tmpdir <path>` for path-scope validation and execution-issues.md routing, (b) filters input files to basename pattern `*.ndjson` (so `.done`, `.status`, `.quiet`, `.surfaced` control files are NEVER committed), (c) redacts each file via `redact-secrets.sh --streaming --state-file <tmp>` to a per-file `mktemp` temp under `larch-logs/<run-id>/breadcrumbs/`, (d) atomically `mv` to the final basename on redactor success, (e) on per-file failure: deletes the partial temp, captures redactor stderr to a per-file failure log, calls `append-tool-failure.sh --log "$session_tmpdir/execution-issues.md" --category Warnings --output-file <failure-log> --redact` (best-effort — continue past append non-zero), and proceeds to the next file. Per user Q4 ("skip + warn + continue"), the writer aggregates: returns 0 when at least one file succeeded OR the input directory was empty; returns 1 only when at least one file failed AND zero succeeded (caller decides whether to treat as fatal). **Publisher wiring**: `scripts/design-log-publish.sh` calls the new writer for `$DESIGN_TMPDIR/breadcrumbs` before commit; `scripts/refresh-run-logs.sh` and `scripts/larch-log-flush.sh` call it for `$IMPLEMENT_TMPDIR/breadcrumbs`. Without these caller updates the batch machinery is dead code. The two helpers PR #2786 left undocumented (`scripts/breadcrumb-monitor.sh`, `scripts/lib-redact-streaming.sh`) get sibling `.md` files authored from observed script behavior (see per-file sections for actual exit codes / argv).

### UPDATED: `scripts/lib-quiet.sh`

The single critical fix that unblocks items 1 and 2:

- **Fix `larch_quiet__exit_combo` ordering and exit-status propagation** (lines 149-156). New body:
  ```bash
  larch_quiet__exit_combo() {
      local _ec=$?
      if [ -n "${LARCH_QUIET_PREV_EXIT_TRAP:-}" ]; then
          # Re-prime $? to the original exit code before evaling prior trap.
          (exit "$_ec"); eval "$LARCH_QUIET_PREV_EXIT_TRAP" || true
      fi
      larch_quiet__exit_write_done "$_ec"
      return "$_ec"
  }
  ```
  The prior trap runs FIRST with `$?` primed to the original exit code (so `ci-wait.sh:170`'s `EXIT_STATUS=$?` sees the script's exit, not the helper's). Then the done sentinel and status file are written. The monitor cannot observe `LARCH_DONE_SENTINEL` content until after the prior trap finishes its cleanup/`.done`-writer.
- **Guard `larch_quiet_append_done_trap` against double-install in nested wrapper/child invocations**. Add an early-return when `LARCH_DONE_OWNER_PID` is already set and is NOT equal to `$$`:
  ```bash
  larch_quiet_append_done_trap() {
      if [ -z "${LARCH_DONE_SENTINEL:-}" ] || [ -z "${LARCH_STATUS_FILE:-}" ]; then
          return 0
      fi
      if [ -n "${LARCH_DONE_OWNER_PID:-}" ] && [ "${LARCH_DONE_OWNER_PID}" != "$$" ]; then
          return 0
      fi
      export LARCH_DONE_OWNER_PID=$$
      # ... existing trap-capture + chain installation ...
  }
  ```
  This makes the call safe to invoke in BOTH wrapper and inner scripts (e.g., `run-step5-review.sh` outer + `review-and-fix.sh` inner): only the outermost top-level PID that first exported `LARCH_DONE_OWNER_PID` installs the chain; child invocations no-op.


### NEW: `scripts/breadcrumb-monitor.md`

Sibling docs for `scripts/breadcrumb-monitor.sh` per `.claude/rules/script-md-siblings.md`, authored from observed script behavior (NOT from the original PR #2786 architecture prose):

- **Purpose**: foreground breadcrumb tailer paired with backgrounded denylisted scripts to surface live progress.
- **Argv**: `--stream PATH`, `--done-sentinel PATH`, `--status-file PATH`, `--quiet-log PATH`, `--surfaced-sentinel PATH` (all required), plus optional `--poll-interval=SEC`, `--rate-cap=N`, `--final-tail-lines=N`, `--mode=tail|monitor`.
- **Env-var interaction table**: `LARCH_BREADCRUMB_STREAM`, `LARCH_DONE_SENTINEL`, `LARCH_STATUS_FILE`, `LARCH_QUIET_LOG_FILE`, `LARCH_BREADCRUMBS_SURFACED_FILE`, `LARCH_QUIET_DISABLE` — semantics + argv precedence.
- **Mode-selection logic**: tail-mode (default — live tail until DONE sentinel content present) vs. monitor-mode; surfaced-sentinel pre-existing → silent exit (idempotent re-invocation).
- **Exit codes (per observed script behavior)**:
  - `0` — clean exit (normal termination or silent-exit on pre-existing surfaced sentinel)
  - `2` — argv/setup error OR path-scope rejection (path validation via `larch_bm_validate_path`)
  - `4` — monitor timeout
  - Per-line redactor failure does NOT cause process exit; emits a `WARN redact-drop-line` and continues (drop semantics).
- **Redaction failure semantics**: per-line streaming redactor failures drop that line from the surface (no process exit); the final tail (`tail -n "$FINAL_TAIL_LINES" "$QUIET_LOG" | lib-redact-streaming.sh`) tolerates `|| true` and emits redacted bytes only.
- **Foreground-duplication guard**: surfaced-sentinel write-once semantics; second invocation in the same logical boundary observes the pre-existing sentinel and exits 0 silently (per line 88-91).
- **Primary callers**: the 9 Family-B denylisted scripts (cross-reference each script's `.md` sibling and the SKILL.md prose under BASH_AUTHORING.md §4).

### NEW: `scripts/lib-redact-streaming.md`

Sibling docs for `scripts/lib-redact-streaming.sh` per `.claude/rules/script-md-siblings.md`, authored from observed script behavior:

- **Purpose**: line-oriented wrapper around `redact-secrets.sh --streaming`, used by `breadcrumb-monitor.sh` and `larch-log.sh` to redact PEM-bearing streams with state preserved across lines.
- **Argv**: `--state-file=PATH` or `--state-file PATH` (required). Reads stdin, writes stdout.
- **API**: NOT a function library — it is a CLI wrapper that loops over stdin lines and pipes each through `redact-secrets.sh --streaming --state-file=<path>`. There are no `larch_redact_stream_*` function entry points.
- **Env-var interaction table**: none required; the `--state-file` argv is the sole input.
- **Exit codes (per observed script behavior)**:
  - `0` — all lines redacted successfully
  - `1` — redactor non-zero on any line (exits immediately, breaking the input loop)
  - `2` — missing or unknown argv (`--state-file` is required; unknown options error)
- **Redaction failure semantics**: fail-fast on the first line where `redact-secrets.sh --streaming` returns non-zero; callers (breadcrumb-monitor, larch-log breadcrumbs branch) interpret exit 1 as "drop this file/chunk" per their own fail-closed contracts.
- **Primary callers**: `scripts/breadcrumb-monitor.sh:137,212`, `scripts/larch-log.sh` (breadcrumbs batch directory-walk branch).

## Edge cases

1. **`run-step5-review.sh` and `run-step2-dispatch.sh` source `lib-quiet.sh` for the FIRST TIME**. Per findings F17/F25/F31/F43/F45 the `larch_quiet_init` call would actively redirect stdout/stderr to a quiet log and break the wrapper KV-relay contract. Solution: source `lib-quiet.sh` but **do NOT call `larch_quiet_init`**. Call `larch_quiet_append_done_trap` directly; it early-returns when sentinels are unset (no-op in test/manual invocations). Byte-identical stdout/stderr is preserved by construction.
2. **`larch_quiet_append_done_trap` is a no-op when `LARCH_DONE_SENTINEL`/`LARCH_STATUS_FILE` are unset OR when `LARCH_DONE_OWNER_PID` is already set to another PID**. The new nesting guard (added in `lib-quiet.sh` above) means calling the function unconditionally in all 9 scripts is safe — wrapper+inner pairs no longer double-install the chain.
3. **`larch_quiet__exit_combo` ordering after the fix**: prior trap runs FIRST with `$?` primed to the original exit code, then `LARCH_STATUS_FILE` and `LARCH_DONE_SENTINEL` are written with the same code. Monitor cannot observe the done sentinel before the prior trap finishes.
4. **`ci-wait.sh` line 248 bare `"\n"` cosmetic separator stays on `larch_errf` unchanged**. It is the only intentional `larch_errf` progress-adjacent line; the spot-check grep allowlist exempts it. Do NOT migrate this line.
5. **`larch-log.sh` breadcrumbs batch directory may not exist** (zero-breadcrumb run). The writer returns 0 with no output; the destination `larch-logs/<run-id>/breadcrumbs/` directory is created lazily only when at least one file is successfully redacted.
6. **Symlink handling: SINGLE RULE** — skip files whose `[ -L "$file" ]` is true, AND reject when the input directory itself is a symlink (`[ -L "$input_dir" ]`). Apply `realpath` containment check only to non-symlink files (each entry's realpath must remain under the canonical input directory's realpath). Do NOT follow symlinks via `readlink`. This unifies the prior plan-level contradiction (per findings F7, F56).
7. **`emit_breadcrumb` argv parsing accepts `--category=NAME` and `--category NAME`**. Use the `--category=NAME` form for consistency.
8. **Non-breadcrumb files under the input directory** (`.done`, `.status`, `.quiet`, `.surfaced`, redactor state) are filtered by basename pattern. Only `*.ndjson` files reach the redactor. This prevents accidentally committing control artifacts or larger quiet-log files (per finding F15).
9. **Atomic write**: redactor output writes to a per-file `mktemp` temp under the destination directory (NOT a separate tmpdir — same filesystem ensures `mv` atomicity). On redactor success, `mv $temp $dest_dir/$basename`. On failure, `rm -f $temp`. A partial file never appears under the committed destination (per finding F20).
10. **`emit_breadcrumb_stderr` is a new lib-quiet helper**. Used by ci-wait progress migrations to preserve byte-shape stderr in non-stream contexts (per finding F6). Other migrations use plain `emit_breadcrumb` because their callsites already write to stdout/quiet log.

## Failure modes

1. **Trap-chain breakage from a missed prior-trap registration**. The fixed `larch_quiet__exit_combo` evaluates the saved prior body before writing the done sentinel. If the implementer places `larch_quiet_append_done_trap` BEFORE the script's `trap ... EXIT` registration (instead of after), the prior-trap chain captures EMPTY (the trap wasn't registered yet), and the script's cleanup never runs. **Earliest warning signal**: `.done` sidecar file missing or empty after `ci-wait.sh` exits, or `$WAIT_STDERR` temp file left under tmpdir after `collect-agent-results.sh`. **Mitigation**: place `larch_quiet_append_done_trap` AFTER the very last `trap ... EXIT` registration (verify via `grep -n 'trap.*EXIT' <file>` and re-grep after edit). For scripts with no prior trap (ship-pr.sh, dispatch-plan-voters.sh, dispatch-with-waterfall.sh, run-step5-review.sh, run-step2-dispatch.sh), placement immediately after `larch_quiet_init` (or after `source lib-quiet.sh` for the non-init wrappers) is correct.

2. **`emit_breadcrumb` category typo drops the record from the stream**. Per `lib-quiet.sh:225` an unknown category logs `WARN unknown-category=<cat> (dropped from stream)` and returns 0. **Earliest warning signal**: operator sees `WARN unknown-category=` lines in stderr but no chat-side breadcrumbs from the affected callsite. **Mitigation**: enforce the fixed vocabulary mechanically — when implementing the migration, cross-check each new `--category=NAME` against `lib-quiet.sh:222-225` before saving each edit. The follow-up test harness (item 4, out of scope here) will add an offline test asserting all in-tree categories are in the vocabulary.

3. **`larch-log.sh` partial-publish from streaming-redactor failure silently drops a breadcrumb file**. Per user Q4 (skip + warn + continue), a corrupt breadcrumb file disappears from the committed log while `PUBLISH_OK=true` still reports. **Earliest warning signal**: a missing file under `larch-logs/<run-id>/breadcrumbs/` despite the per-run `breadcrumbs/` having entries; corresponding `Warnings` entry in `execution-issues.md` with site `larch-log breadcrumbs batch`. **Mitigation**: the `Warnings` entry is the audit trail; the `flush-execution-issues.sh` step converts it to NDJSON committed under `execution-issues.ndjson`. Downstream consumers (audit-runs skill, post-merge audits) grep `Warnings` for `larch-log breadcrumbs batch` to find affected runs.
