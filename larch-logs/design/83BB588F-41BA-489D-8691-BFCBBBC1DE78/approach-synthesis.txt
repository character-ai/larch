### Architectural decisions from Codex

Codex proposed a three-contract rollout — **script producers**, **foreground monitor consumers**, and **committed log persistence**:

1. **Done-trap append-after pattern**: `larch_quiet_append_done_trap` runs AFTER each script's final script-owned `EXIT` trap. This preserves existing cleanup/status behavior (e.g. `ci-wait.sh:170` writes `${OUTPUT_FILE}.done`; `collect-agent-results.sh:307` removes `$WAIT_STDERR`; `step2-implement.sh:402` removes `$LAUNCHER_TMP`). The existing `larch_quiet_append_done_trap` implementation at `scripts/lib-quiet.sh:159-178` already wraps the existing EXIT trap via `LARCH_QUIET_PREV_EXIT_TRAP` + `larch_quiet__exit_combo`, so the wiring is one `larch_quiet_append_done_trap` call after the script's last `trap ... EXIT` line.
2. **Wrapper scripts adopt lib-quiet.sh**: `scripts/run-step5-review.sh` and `skills/implement/scripts/run-step2-dispatch.sh` currently don't source `lib-quiet.sh` — they need the source line + `larch_quiet_init` at the top before any `larch_quiet_append_done_trap` call. The acceptance prose calls for byte-identical stdout/stderr regression tests for these two; those tests are **deferred to follow-up item 4** per user Q1.
3. **`ci-wait.sh` progress conversion**: Move progress-tier `larch_errf` calls to `emit_breadcrumb --category=wait-ci`, keeping real diagnostics on `larch_err`/`larch_errf`. The grep audit of `scripts/ci-wait.sh` distinguishes the two: anything informational (waiting, polling, retry status) → breadcrumb; anything error-tier (failed gh call, abort condition) → stays on larch_err*.
4. **`emit_breadcrumb` category migration**: 21 caller files, ~120 callsites, currently 0 with explicit `--category=`. Without categories, `lib-quiet.sh:222` warns + drops the record from the stream. Migration makes the stream-enforcement an invariant rather than best-effort. Per user Q2, use per-call judgment with default `progress`; valid vocabulary is `{progress, warn, stall, retry, escalate, wait-ci, network-flake}` per `lib-quiet.sh`.
5. **Sibling `.md` files for new helpers**: Create `scripts/breadcrumb-monitor.md` and `scripts/lib-redact-streaming.md` per `.claude/rules/script-md-siblings.md`. Each documents argv, env-var interaction, mode-selection, exit codes, redaction failure semantics, and the foreground-duplication guard via the surfaced-sentinel file.
6. **`larch-log` breadcrumbs batch**: Register the per-run `breadcrumbs/` directory in `scripts/larch-log-batches.sh` (and sibling `.md`) as a sanitizer-required batch. Make `scripts/larch-log.sh` walk the directory and pipe each file through `redact-secrets.sh --streaming --state-file <tmp>` before placing the redacted output in `larch-logs/<run-id>/breadcrumbs/<basename>`. Per user Q4, on streaming-redactor non-zero exit: **skip that file + warn + continue** (do not abort the entire publish).

### Risk surface

- **Trap ordering**: adding the done-trap before or instead of existing traps would silently break cleanup or legacy sentinel files (e.g., `${OUTPUT_FILE}.done` for `ci-wait.sh`). Mitigation: `larch_quiet_append_done_trap` already saves and re-invokes the prior trap via `larch_quiet__exit_combo` — so as long as it's called AFTER the script's last `trap ... EXIT` registration, ordering is preserved.
- **Observability drift**: missing categories are currently dropped from the stream path. Migration must be comprehensive enough that no critical callsite stays uncategorized after this PR — otherwise some breadcrumb output silently disappears.
- **Fail-closed brittleness for committed logs**: per-file skip+warn (user Q4) is looser than abort-everything. This avoids one bad breadcrumb file killing a whole publish, at the cost of partial publishes. The Warnings entry in `execution-issues.md` is the audit trail.
