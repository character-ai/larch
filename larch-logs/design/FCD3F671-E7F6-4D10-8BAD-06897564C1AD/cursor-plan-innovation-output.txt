1. [risk-integration] `skills/design/scripts/revise-plan-with-waterfall.sh:365-371`

Concern: The plan names fallback outputs as `<tool>-fallback-output.txt`, but `finalize()` derives `REVISE_PATCH_PATH` from only `winner`. A tier-4 Codex success would emit `revise/codex-output.txt`, not `revise/codex-fallback-output.txt`.

Suggested revision: Track the actual output path when `attempt_tier` succeeds, or add the smallest conditional in `finalize()` for `winner_is_fallback`.

2. [correctness] `skills/design/scripts/revise-plan-with-waterfall.sh:150-166,377-383`

Concern: The proposed tier-4 chain stores three fallback attempts in one `tier4_status`. Later failures can overwrite earlier, more informative failures.

Scenario: tiers 1-3 all return `no-patch`; tier-4 Codex returns `invalid-patch`; tier-4 Cursor and Claude return `no-patch`. The final aggregation sees only `no-patch` for tier 4 and reports `failed-no-patch`, contrary to the plan’s stated failure mapping.

Suggested revision: For ordinal 4, preserve the highest-priority failure status (`invalid-patch`, then apply/emit failures, then no-patch/skipped) unless a later attempt succeeds.
