1. **[correctness] `skills/design/scripts/revise-plan-with-waterfall.sh:365-371`**
Concern: fallback success would emit a stale `REVISE_PATCH_PATH`.
Scenario: tier 4 calls `attempt_tier 4 codex "$REVISE_DIR/codex-fallback-output.txt"`, but `finalize()` still reconstructs `REVISE_PATCH_PATH` as `"$REVISE_DIR/$winner-output.txt"`. For `REVISE_STATUS=ok-fallback`, that can point to the earlier failed `codex-output.txt` instead of the winning fallback output.
Suggested revision: add a `winner_output_path` variable, set it in `attempt_tier()` on success from the actual `output` argument, and emit that path in `finalize()`.

2. **[risk-integration] `scripts/design-log-publish.sh:372-380`; `scripts/lib-design-round-artifacts.sh:39-47`**
Concern: the proposed tier-4 files are outside the plan-review artifact allowlist.
Scenario: the plan writes `prompt-unified-diff.txt` and `<tool>-fallback-output.txt` under `plan-review/round-N/revise/`. `design-log-publish.sh` rejects any file there unless `design_round_revise_artifact_included()` allows it, so a fallback run can later fail log publishing.
Suggested revision: either avoid new artifact filenames, or update `scripts/lib-design-round-artifacts.sh` plus its sibling doc/tests to allow `prompt-unified-diff.txt` and `*-fallback-output.txt`.
