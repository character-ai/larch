# Cursor-Generic sketch (Claude Agent fallback — Cursor unavailable)

**(1) Key architectural decisions and approach.** I propose a two-layer design built around a single new primitive: a *breadcrumb stream file* per script invocation, distinct from the existing quiet log. Layer one (script side) extends `lib-quiet.sh` so that whenever `LARCH_QUIET_BREADCRUMBS=1` is set, `emit_breadcrumb` writes a structured one-line record (`larch:bc <ISO8601> <DEPTH> <SCRIPT_PID> <CATEGORY> <TEXT>`) atomically (single `printf` ≤ PIPE_BUF) to `${LARCH_BREADCRUMB_STREAM}` — a path the parent SKILL preallocates under `$IMPLEMENT_TMPDIR/breadcrumbs/${calling_skill}.${PPID}.ndjson` — *in addition to* the existing quiet log. Crucially, nested scripts inherit `LARCH_BREADCRUMB_STREAM` through the environment, so any depth of helper writes to the same shared stream; `DEPTH` is derived by the helper from a counter in the env var `LARCH_BC_DEPTH` (incremented per `larch_quiet_init`), giving the model a sense of nesting without forcing recursion-aware code. Layer two (SKILL side) flips the 9 denylisted scripts to `run_in_background: true`, but standardizes a single follow-up Bash call — the *consumption call* — that the skill makes immediately after launching the background job. That foreground call invokes a new helper `scripts/breadcrumb-tail.sh` which (a) blocks on the background task's `<task-notification>` via `wait`-like semantics on the task id (passed in by the skill), (b) periodically (every ~30s) prints the *new* lines from the stream file to stdout under a fenced `### larch breadcrumbs (<script>)` header, redacted by piping through `lib-redact.sh`, and (c) on script exit prints a final block containing `STATUS=<exit_code>`, the last 30 lines of the quiet log via `tail -n 30`, and a `larch:reactive` directive (e.g. `RETRY_OK=1`, `STALL_DETECTED=1`) parseable by the model. Because this consumption call is itself foreground, the harness streams its stdout in real time exactly the way it would have streamed the original script — but the orchestrator no longer has to fight the harness over backgrounding the actual long-running work. Monitor and ScheduleWakeup are intentionally avoided: Monitor stays endorsed for external-log tailing in other contexts but is too coupled to the harness UI to be the primary path here, and the user has explicitly rejected ScheduleWakeup as flaky. The breadcrumb-tail helper uses a plain bounded `until [ -f "$DONE_SENTINEL" ]; do sleep 30; ... done` loop with a hard ceiling (e.g. 30 min) and the sentinel is touched by a one-line `trap 'touch "$DONE_SENTINEL"' EXIT` injected into each denylisted script's tail by way of a small `larch_quiet_install_done_sentinel` function added to `lib-quiet.sh`. To prevent the foreground-duplication problem (constraint 4), `lib-quiet.sh` writes breadcrumbs to the stream file *only* when `LARCH_BREADCRUMB_STREAM` is set — and that env var is set by the skill **only** in the always-background path; if the legacy foreground path is still chosen by a skill author, the stream var is unset and the existing behavior (FD-3 or FD specified by `LARCH_QUIET_BREADCRUMB_FD`) is unchanged. The reactive surface is a small fixed vocabulary documented in `scripts/lib-quiet.md`: `larch:bc category=...` where category ∈ {`progress`, `warn`, `stall`, `retry`, `escalate`, `wait-ci`, `network-flake`}, allowing the orchestrator to recognize, for example, `category=stall` + ≥ 2 consecutive heartbeats with no new progress lines and decide to cancel/retry without parsing prose.

**(2) Files and modules to modify.** Core: `scripts/lib-quiet.sh` gains a third emission target (the stream file) inside `emit_breadcrumb`, the `larch_quiet_install_done_sentinel` helper, and depth-aware initialization; `scripts/lib-quiet.md` documents the stream contract, the depth model, and the reactive vocabulary. New: `scripts/breadcrumb-tail.sh` + sibling `.md` (the consumption helper — ~80 lines, Bash 3.2-safe, sources `lib-redact.sh` for piping output through `redact-secrets.sh`); `scripts/test-breadcrumb-tail.sh` + `.md` for offline harness coverage. Each of the 9 denylisted scripts (`ship-pr.sh`, `ci-wait.sh`, `collect-agent-results.sh`, `dispatch-plan-voters.sh`, `dispatch-with-waterfall.sh`, `run-step5-review.sh`, `run-step2-dispatch.sh`, `skills/implement/scripts/step2-implement.sh`, `skills/review-and-fix/scripts/review-and-fix.sh`) gets a single-line addition near the top, after `larch_quiet_init`, calling `larch_quiet_install_done_sentinel`; no other behavior changes. Skill prompts that currently embed the `**⚠ Foreground required…**` banner + `# Foreground required: see BASH_AUTHORING.md §4` comment for these 9 scripts are rewritten to the new pattern — a paired *background launch* + *foreground breadcrumb-tail* block — in `skills/implement/SKILL.md`, `skills/design/SKILL.md`, `skills/design/references/sketch-launch.md` (where applicable), `skills/design/references/plan-review.md`, `skills/design/references/dialectic-execution.md`, `skills/shared/dialectic-protocol.md`, `skills/shared/voting-protocol.md`, `skills/review/references/heavy-worker.md`, and `skills/review-and-fix/SKILL.md`. Lint changes: `scripts/lint-foreground-markers.sh` is *repurposed* (not deleted) into `lint-background-pairs.sh` (or kept under the same filename with new semantics, documented in `scripts/lint-foreground-markers.md`) which now *requires* that any invocation of a denylisted script in a fenced block has `run_in_background: true` and is immediately followed by a `breadcrumb-tail.sh --task-id` consumption block within N lines; banner text is rewritten to `**⚠ Background required — must be paired with breadcrumb-tail.sh.**`. `BASH_AUTHORING.md §4` is rewritten to describe the new contract. `AGENTS.md` Conventions bullets referring to NEVER #9 / NEVER #16 are updated, and `skills/implement/SKILL.md` NEVER list is amended (likely replacing NEVER #16 with the inverse: "NEVER call denylisted scripts in foreground"). `orchestrator-never.md` and `skills/research/SKILL.md` get pointer updates. Run-log flushing (`docs/run-logs.md`) gains a note that the breadcrumb stream files are committed alongside the quiet logs.

**(3) Tradeoffs and risks.** The biggest tradeoff is that we *trade* one harness-quirk problem (random backgrounding of foreground-required scripts) for *deterministic* dependence on the harness's `<task-notification>` arrival inside a foreground `wait` loop — but this is on stronger ground, because the foreground consumer is short-stdout, never long-blocking on real work, and we now *want* the background task; harness behavior aligns with intent rather than fighting it. The main risk is **dual-runner ordering**: if the orchestrator forgets to immediately follow the background launch with the `breadcrumb-tail.sh` consumption call, completion may be lost; mitigation is the rewritten `lint-foreground-markers.sh` enforcing the pairing as a structural invariant, plus a small `scripts/test-background-pair-lint.sh` harness exercising the rewrite. A secondary risk is **breadcrumb-file unbounded growth on long runs** — bounded by a soft 10 MB cap in `breadcrumb-tail.sh` (warn + truncate-front) and by the fact that emit-breadcrumb call sites are already restrained (~20 across the 9 scripts). **Concurrency safety**: writes are line-atomic only up to PIPE_BUF (≈ 4 KiB on macOS); breadcrumb messages are short and we never interleave fields across writes, but the contract in `lib-quiet.md` will explicitly cap message length at 1 KiB. **Redaction overhead**: piping each batch through `redact-secrets.sh` is a per-30s `grep`/`sed` pass over at most a few KiB; negligible. **Bash 3.2 portability**: the helper uses only `while read`, `tail -n +N`, `wc -l`, `printf`, `trap EXIT`, and `until … sleep`, all 3.2-safe. **Backwards compatibility**: skills that don't opt into the new env var keep working unchanged (legacy FD-3 / `LARCH_QUIET_BREADCRUMB_FD` paths preserved); a deprecation note in `lib-quiet.md` flags the FG-only path. **Subagent surface**: `/review --subagent` and `/design` heavy workers run inside Agent-tool sandboxes that do not receive task notifications from outside; for those, the background script and the breadcrumb-tail must both live inside the subagent, which is naturally satisfied because the helper scripts are repo-local. **Lint-regression risk**: rewriting `lint-foreground-markers.sh` (and renaming the banner phrase) touches every reference in `BASH_AUTHORING.md §4` and many SKILL.md files — high refactor surface, but mechanically uniform, mitigated by a one-shot rewrite plus the existing pre-commit hook catching anything missed. Finally, the chat-bound output adds visible token cost — each 30s batch surfaces ~5-15 redacted lines — but this is bounded (most scripts complete in <30 min), strictly *user-visible* (so the user can interrupt early), and gated by the same `LARCH_QUIET_BREADCRUMBS=1` env var that already governs visibility today.
