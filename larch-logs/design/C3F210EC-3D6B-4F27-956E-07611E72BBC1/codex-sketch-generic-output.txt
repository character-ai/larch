I’d make breadcrumb propagation a first-class `lib-quiet` feature, not a per-skill polling convention. Add a shared append-only, chat-bound breadcrumb stream, e.g. `LARCH_QUIET_BREADCRUMB_FILE`, that `emit_breadcrumb` writes to in addition to the existing quiet log path, while preserving FD 3 `emit` / `emit_kv` exactly as-is in [scripts/lib-quiet.sh](<OPERATOR_REPO_PATH>/scripts/lib-quiet.sh:70). A new wrapper, likely `scripts/run-with-breadcrumbs.sh`, would launch long-running helpers with `run_in_background:true`, set the shared breadcrumb file for all descendants, expose a completion sentinel / exit-code file, and arrange for Monitor to tail only the redacted breadcrumb display file. That avoids foreground duplication because breadcrumbs no longer need to be surfaced on child stdout, and nested scripts bubble up naturally through inherited env vars; [review-and-fix.sh](<OPERATOR_REPO_PATH>/skills/review-and-fix/scripts/review-and-fix.sh:12) already has the right idea with inherited breadcrumb FD setup, but the destination should become file-based for background-safe streaming.

The main edit surface is: [scripts/lib-quiet.sh](<OPERATOR_REPO_PATH>/scripts/lib-quiet.sh:114) and [scripts/lib-quiet.md](<OPERATOR_REPO_PATH>/scripts/lib-quiet.md:14) for the new stream contract; `scripts/test-lib-quiet.sh` for nested/background/redaction coverage; a new runner/propagator helper modeled on [scripts/run-external-agent.sh](<OPERATOR_REPO_PATH>/scripts/run-external-agent.sh:143), which already owns sentinels, metadata, timeout, and progress; [scripts/redact-secrets.sh](<OPERATOR_REPO_PATH>/scripts/redact-secrets.sh:4) as the mandatory outbound filter for chat-bound breadcrumb/tail text; and the orchestrator docs in `/implement` and `/design` where foreground calls are currently hard-coded, such as [skills/implement/SKILL.md](<OPERATOR_REPO_PATH>/skills/implement/SKILL.md:1018), [skills/implement/SKILL.md](<OPERATOR_REPO_PATH>/skills/implement/SKILL.md:1205), and [skills/implement/SKILL.md](<OPERATOR_REPO_PATH>/skills/implement/SKILL.md:1563). The foreground linter should be retired or repurposed: [BASH_AUTHORING.md](<OPERATOR_REPO_PATH>/BASH_AUTHORING.md:50) and [scripts/lint-foreground-markers.sh](<OPERATOR_REPO_PATH>/scripts/lint-foreground-markers.sh:18) currently enforce the exact opposite contract for the nine named scripts, so they need to become “background + breadcrumb propagation required” checks instead.

The big tradeoff is between harness-native Monitor streaming and script-side periodic polling. I’d prefer Monitor for the visible inline stream because the repo already forbids Monitor only as a completion-wait mechanism, while allowing it for logs/events, and completion can still come from the background Bash task/sentinel. The risks are real: Monitor behavior must be verified in Claude Code, chat-bound redaction must fail closed, stdout KV parsing must not be polluted by breadcrumb text, and background completion must not reintroduce the old “model ended the turn before result handling” halt. Keeping the wrapper responsible for offsets, final redacted `exit_code + tail 20-40 lines`, and a model-actionable breadcrumb prefix like `larch:breadcrumb script=ship-pr phase=ci-watch severity=info ...` should contain most of that risk without replacing the FD-3 contract.
