### DECISION_1: Chat-bound display loop mechanism (Monitor tool vs foreground polling loop)
- **Chosen**: Monitor tool for near-real-time per-line streaming of the redacted breadcrumb file; completion still arrives via the background Bash `<task-notification>`. Sketches the user's title constraint ("ideally, instantly") more directly.
- **Alternative**: Foreground bash `until [ -f DONE_SENTINEL ]; sleep 30; emit-new-lines; done` polling loop installed as a paired post-launch Bash call, driven by a `trap EXIT` sentinel installed in each script via a new `larch_quiet_install_done_sentinel` helper in `lib-quiet.sh`.
- **Tension**: Monitor is endorsed by AGENTS.md for "logs, external polling, or event streams" but is less verified for this exact use case (per-line streaming of a file actively appended by a backgrounded script). The polling loop is simpler and more predictable but introduces a ~30s display lag and occupies a foreground Bash slot for the script's entire duration. The user has explicitly disliked ScheduleWakeup-based timers ("flaky"), but the polling-loop variant uses an in-process `sleep` inside a single Bash invocation — different runtime model from ScheduleWakeup.
- **Impact**: High
- **Affected files**: scripts/lib-quiet.sh (new emission target), new scripts/breadcrumb-tail.sh OR scripts/monitor-breadcrumbs.sh, all 9 denylisted scripts (consumption-call pattern), SKILL.md orchestrator launch patterns across /implement and /design, scripts/lint-foreground-markers.sh (repurposed enforcement target), AGENTS.md ("Don't spawn a Monitor or polling loop" bullet — may need carve-out)

### DECISION_2: Wrapper shape — explicit foreground pairing vs single wrapper script
- **Chosen**: Explicit pairing — skill issues `run_in_background:true` for the long script, then immediately issues a foreground consumption call (breadcrumb-tail OR Monitor depending on DECISION_1) in the same message. Enforced as a structural invariant by the repurposed lint.
- **Alternative**: Single `scripts/run-with-breadcrumbs.sh` wrapper that the skill always calls foreground; the wrapper internally backgrounds the long script, exposes a sentinel/exit-code file, and streams the redacted breadcrumb file out on its own stdout. From the SKILL.md author's perspective, the call looks foreground but the actual work is background.
- **Tension**: Explicit pairing makes the contract visible at the orchestrator (SKILL.md) level and easier to lint, but doubles the per-callsite boilerplate (background launch + paired consumption call). The single-wrapper approach hides complexity behind one call but obscures the bg/fg topology from a SKILL.md reader and makes the lint harder to express (it has to look for the wrapper, not the underlying script).
- **Impact**: Medium
- **Affected files**: new wrapper script + sibling .md, all 9 denylisted scripts' invocation sites in SKILL.md files (~6-10 sites), scripts/lint-foreground-markers.sh (repurposed)
