## Findings

1. **[correctness]** `skills/design/SKILL.md` (proposed Step 0b route fence, plan lines 249–258) — The Step 3–shaped handoff is incomplete for `WARN`/`ERROR` on the file-first path. Live Step 3 already handles `WARN` during the result-env read:

```864:871:skills/design/SKILL.md
    while IFS= read -r _line || [[ -n "$_line" ]]; do
      _key="${_line%%=*}"; _value="${_line#*=}"
      case "$_key" in
        LOOP_STATUS|ACCEPTED_COUNT|IMPORTANT_ACCEPTED_COUNT|DEGRADED_PANEL|ROUNDS_COMPLETED|TALLY_PLAN_REVIEW_STATUS|AGGREGATOR_STATUS|VOTING_TALLY_FILE|STEP3_REVIEW_CAP_REACHED|STEP3_REVIEW_ROUND_NUM|ROUND_NUM|REVIEW_ROUND_COUNT)
          printf -v "$_key" '%s' "$_value" ;;
        WARN) printf '%s\n' "WARN=$_value" ;;
      esac
    done <"$DESIGN_TMPDIR/.step3-review-result.env"
```

The plan’s route fence excludes `WARN`/`ERROR` from file-first handling, relies on `_route_out` merge plus an undefined “re-emit non-empty WARN/ERROR” step, and never adds an `ERROR)` case (needed for `design-pause-load.sh` `emit_kv ERROR`, e.g. `scripts/design-pause-load.sh:29-30`). **Suggested revision:** Add `WARN|ERROR)` to the file-first loop and `ERROR)` to the stdout merge loop (same `printf '%s\n' "${_key}=${_value}"` shape as Step 3 `WARN`); remove the redundant second re-emit unless you explicitly dedupe file vs stdout.

2. **[correctness]** `skills/design/scripts/design-init-runparams.sh` (proposed lines 210–214) — Relocated jq/run-params warnings call `emit` with markdown prose. Under the quiet contract, `emit` is contract-stream output on FD 3, not operator stderr (`scripts/lib-quiet.md:18-19`; `scripts/lib-quiet.sh:158-163`). The init orchestrator only documents KV merge for `WARN` among diagnostics, so those lines stay inside `_init_out` and are not printed—unlike today’s orchestrator `printf` at `skills/design/SKILL.md:357-360`. **Suggested revision:** Use `emit_kv WARN "…"` for both strings (same channel as rename failure at plan line 193).
