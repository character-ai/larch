# Implementation Plan — Extract /design Step 0b router into phase drivers (#3245)

## Approach

Extract the `/design` SKILL.md Step 0b deterministic spine into two phase-driver
scripts that reuse the rank-1 convention (`run-step3-review.sh` +
`lib-phase-driver.sh`, landed via #3244). Split around the in-region
`AskUserQuestion` gates, which stay in the orchestrator:

- `design-route.sh` (pre-gate): resume-detect → title-eligibility → reentry-guard
  → emit one `ROUTE=` verdict + parsed resume KVs.
- `design-init-runparams.sh` (post-gate): tier-resolve → env-refresh →
  `[DESIGNING]` rename → `write-run-params.sh` → router-flag merge.

SKILL.md Step 0b collapses to: fetch issue → call `design-route.sh` → apply
`BRAINSTORM_PREFIX` (before `ROUTE` branching) → orchestrator handles clarify /
already-planned / cancel gates → on `ROUTE=proceed` → issue-bound env refresh
(5.5-bis window) → `feature-description.txt` → call `design-init-runparams.sh`.
Both drivers source `lib-phase-driver.sh`, write a result `.env` (atomic,
symlink-refusing), emit `emit_kv` stdout, and use exit codes 0=ok / 1=op-failure /
2=config error. Land both `.sh` files **executable** (`chmod +x`).

Observable behavior is preserved. Round 1 Decision 1 is **revised per FINDING_1**:
collapse today's duplicate sub-step-6 refresh into the init driver, but **reorder**
that single in-driver refresh to run **before** `[DESIGNING]` rename (not after),
and **restore** the proceed-path issue-bound refresh as an orchestrator Bash fence
(relocated 5.5-bis) after gates clear and **before** `feature-description.txt` /
the init-driver fence so `source-env.sh`, the prelude's `$ISSUE_NUMBER` pause-check,
and `/larch:pause` see issue-bound env during orchestrator work. Writer
re-invocation is idempotent when both fire on the proceed path.

Per Round 1 Decision 2: ship the driver `.sh` + mandatory `.md` siblings, write
NO new driver test harnesses, and make the minimal edits to the two existing
harnesses that pin the inline Step 0b shape so CI stays green.

The clarify-loop gate, the already-planned `AskUserQuestion`, the verbal-create
`/larch:issue` call, all cancel banners, the Final summary block, and the
contract-drift abort stay in the orchestrator (issue "Must not").

## Files to modify/create

### NEW: `skills/design/scripts/design-route.sh`
Pre-gate phase driver. Header: `#!/usr/bin/env bash`, `set -euo pipefail`, source
`lib-phase-driver.sh`, `larch_quiet_init`, `fail()` → `larch_err` + exit 2.
Resolve `DESIGN_TMPDIR` (`cd … && pwd -P`), `SESSION_ENV_PATH`, `PLUGIN_ROOT` via
`phase_driver_resolve_plugin_root`. **File mode: executable.**

Argv: `--design-tmpdir PATH` (req), `--issue N` (req), `--issue-title STR` (req),
`--issue-body-file PATH` (req — orchestrator writes the fetched body here; the
driver makes no extra `gh` fetch for the body), `--has-clarify-label true|false`
(req — orchestrator passes the parsed label presence), `--claude-pid N` (req),
`--repo OWNER/REPO` (opt). Validate body-file is a readable regular file (not a
symlink); reject embedded newline/CR in scalar args.

Responsibilities, in strict order:
1. Resume detection: if the body file contains `<!-- larch:design-pause:start -->`,
   run `$PLUGIN_ROOT/scripts/design-pause-load.sh --design-tmpdir … --issue …
   ${REPO:+--repo …}` and parse `LOAD_OK`. On `LOAD_OK=true`, emit
   `ROUTE=resume@<STEP>` plus `RESUME_STEP`, `SESSION_ID`, `RUN_ID`, `TIER`,
   `BRAINSTORM_DONE`, and any `WARN=` lines; return. On `LOAD_OK=false`, write
   through any `WARN=` / `ERROR=` from pause-load stdout into the result env,
   **then fall through** to steps 2–4 (do **not** short-circuit to
   `ROUTE=proceed` — clarify / already-planned verdict logic must still run).
2. Title-eligibility: source `$PLUGIN_ROOT/scripts/lib-title-eligibility.sh`.
   Predicate order (a) `title_has_lifecycle_reject_prefix` → `ROUTE=cancel-title-filter`
   + `TITLE_FILTER_REASON=lifecycle` + `TITLE_FILTER_MARKER=<token>`; (b)
   `title_has_archival_report_prefix` → `ROUTE=cancel-title-filter` +
   `TITLE_FILTER_REASON=archival`; (c) `title_starts_with_brainstorm` → set and
   emit `BRAINSTORM_PREFIX=true`, do NOT route. Earlier matches short-circuit.
3. Re-entry guard: source `$PLUGIN_ROOT/scripts/lib-design-reentry-guard.sh`. Call
   `design_reentry_marker_hit "$ISSUE" "$CLAUDE_PID"`. On `MARKER_HIT=true`, emit
   `ROUTE=cancel-reentry-guard` + `MARKER_AGE`, `MARKER_TTL`, and
   `DESIGN_REENTRY_MARKER_PATH` (via `design_reentry_marker_path`). On miss or
   helper return 2, continue.
4. Verdict: `--has-clarify-label true` → `ROUTE=clarify`; else body contains a
   `larch:plan` block → `ROUTE=already-planned`; else `ROUTE=proceed`. Always carry
   forward `BRAINSTORM_PREFIX` and any pause-load `WARN`/`ERROR` breadcrumbs from
   step 1.

Output: result env `$DESIGN_TMPDIR/.design-route-result.env` via
`phase_driver_write_result_env` + `emit_kv` stdout. Allowlist: `ROUTE`,
`BRAINSTORM_PREFIX`, `TITLE_FILTER_REASON`, `TITLE_FILTER_MARKER`, `MARKER_AGE`,
`MARKER_TTL`, `DESIGN_REENTRY_MARKER_PATH`, `RESUME_STEP`, `SESSION_ID`, `RUN_ID`,
`TIER`, `BRAINSTORM_DONE`, `WARN`, `ERROR`. Exit 0 for any verdict (cancel routes are
verdicts, not failures); 2 for argv/config error. The driver never prompts the
user, never creates issues, and never prints user-facing cancel banners — the
orchestrator owns those.

### NEW: `skills/design/scripts/design-init-runparams.sh`
Post-gate phase driver, same header convention. **File mode: executable.** Runs only
after the orchestrator clears the gates on `ROUTE=proceed` (and after the
orchestrator proceed-path env refresh).

Argv: `--design-tmpdir PATH` (req), `--issue N` (req), `--session-id STR` (req),
`--claude-pid N` (req), `--classification SIMPLE|HARD` (req),
`--partition-requested true|false`, `--brainstorm-requested true|false`,
`--manual-requested true|false`, `--repo OWNER/REPO` (opt).

Responsibilities (**reordered per FINDING_1**):
1. Tier-derived params (replaces the SKILL.md `if/elif`): SIMPLE → reason "default
   tier: SIMPLE (no --hard)", `sketch_budget=0`, `review_budget=full`,
   `workflow_path=SIMPLE`; HARD → reason "argv tier: --hard", `sketch_budget=4`,
   `review_budget=full`, `workflow_path=HARD`. `source=caller-forwarded`.
2. **Env refresh (collapsed sub-step 6, before rename)**: one
   `$PLUGIN_ROOT/scripts/write-design-current-env.sh --output
   "$DESIGN_TMPDIR/source-env.sh" --design-tmpdir … --session-id … --issue-number …
   --claude-pid …` call, adding `--manual-requested true` only when manual. Runs
   **before** rename so issue-bound env is persisted for pause during rename and
   run-params writes. Idempotent with the orchestrator's proceed-path 5.5-bis
   refresh.
3. `[DESIGNING]` rename: `$PLUGIN_ROOT/scripts/tracking-issue-write.sh rename
   --issue … --state designing ${REPO:+--repo …}`. Best-effort; `RENAMED=false`
   is idempotent success; non-zero → emit `WARN=` (orchestrator logs it).
4. `write-run-params.sh` with all tier-derived + flag args → `run-params.json`.
   Non-zero exit → emit `INIT_STATUS=contract-drift` and exit 1.
5. Router-flag jq-merge: the canonical filter
   `.partition_requested = (.partition_requested == true or $merge_p) |
   .brainstorm_requested = (.brainstorm_requested == true or $merge_b) |
   .manual_gate_b = $merge_m`, run only when ≥1 flag true AND `jq` present AND
   `run-params.json` exists; missing-file → emit the refusing-to-recreate warning;
   jq-unavailable → emit the jq-unavailable warning. (This is the #3008-pinned
   filter, relocated here verbatim.)

Note: `feature-description.txt` stays in the orchestrator (it owns the title+body
and the verbal-path text). Output: result env
`$DESIGN_TMPDIR/.design-init-runparams-result.env` + `emit_kv` stdout. Allowlist:
`INIT_STATUS` (ok | contract-drift), `RENAMED`, `RUN_PARAMS_PATH`,
`DESIGN_CLASSIFICATION`, `WARN`. Exit 0=ok, 1=write-run-params contract drift
(orchestrator prints the existing contract-drift banner + exits), 2=argv/config.

## Edge cases
- Resume `STEP=0c`: orchestrator still runs clarify-then-continue (control-flow
  stays out of the driver); other steps jump directly.
- Brainstorm title prefix: driver emits `BRAINSTORM_PREFIX=true` without routing;
  orchestrator sets `brainstorm_requested=true` and prints the info banner **before**
  `ROUTE` branching so `already-planned` ad-hoc Q&A + Step 1d.5 still work.
- Verbal-create: `/larch:issue` runs first (orchestrator), then fetch, then
  `design-route.sh`; title-eligibility still applies to the created issue.
- Re-entry helper return 2 (caller error): continue (not a hard block), matching
  today.
- `design-pause-load.sh` `LOAD_OK=false`: driver writes through `WARN`/`ERROR`, then
  runs title → reentry → clarify/already-planned/proceed verdict (no early
  `ROUTE=proceed`).
- Body-file is a symlink / unreadable: driver exits 2 (config error) before any
  routing.
- `jq` unavailable or missing `run-params.json` after write: driver emits the
  existing warnings; flag persistence degrades exactly as today.
- Proceed path: orchestrator 5.5-bis refresh + init-driver pre-rename refresh are
  both idempotent writer re-invocations; prelude `$ISSUE_NUMBER` is satisfied after
  the orchestrator fence.
- Resume `@`: env refresh honors restored `manual_gate_b=true` via conditional
  `--manual-requested true` (orchestrator-owned, not init driver).

## Failure modes
1. KV-contract drift between driver and orchestrator (ROUTE/KV names mismatch, or
   `ERROR` dropped from allowlist) → orchestrator mis-routes or hides pause-load
   failures. Earliest signal: re-pointed `test-design-structure.sh` checks fail.
   Mitigation: pin ROUTE enum + result-env allowlist (including `ERROR`) in both
   `.md` siblings and the harness; parse via `phase_driver_read_result_env`.
2. Harness under-update → green-locally / red-on-CI. Earliest signal: `make lint`
   structure tests. Mitigation: run both updated harnesses + `relevant-checks.sh`
   before commit; include executable-bit pins for both new drivers.
3. Routing-order regression (title-filter must precede reentry-guard must precede
   clarify) → wrong cancel/clarify outcome. Earliest signal: re-pointed Check 24
   ordering assertion. Mitigation: preserve predicate order in `design-route.sh`
   and keep the ordering assertion.
4. ISSUE_NUMBER / prelude gap on proceed → pause-save or `set -u` failure before
   init driver. Earliest signal: manual smoke or FINDING_13 re-pointed ordering
   checks. Mitigation: proceed-path orchestrator refresh before init work; init
   driver refresh before rename.
