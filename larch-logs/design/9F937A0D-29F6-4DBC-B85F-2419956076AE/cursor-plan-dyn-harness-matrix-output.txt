1. **[correctness]** Planned pre-gate failure logging (`plan.txt:48-60`, `138-139`) must write diagnostics to a real file before calling `append-tool-failure.sh`. The gate path captures stderr to `<implement-tmpdir>/oos-disposition-gate.stderr.log` (`plan.txt:53-54`), but pre-gate exits (ambiguous ndjson at `SKILL.md:1223-1224`, ndjson precondition at `1247-1248`) never invoke the gate. `scripts/append-tool-failure.sh:100-104` refuses to run when `--output-file` is absent, so Decision 2 “log all non-zero exits” can fail on those paths unless the helper creates a checkpoint-specific capture file first.

2. **[correctness]** The planned “gate-exit-2 → checkpoint exit 2” harness case (`plan.txt:104`) is underspecified relative to checkpoint behavior. The gate harness uses an explicit invalid range (`test-oos-disposition-gate.sh:202-213`, `HEAD~99..HEAD`), but the checkpoint port auto-derives range from the invoking work tree (`SKILL.md:1201-1210`, `plan.txt:34-36`). Seeding only a fake implement-tmpdir does not force exit 2; the test needs a stated CWD strategy (e.g. run outside any git work tree, matching gate `count_inline_triage` failure) rather than “tmpdir whose repo lacks the range.”

3. **[risk-integration]** The planned logging snippet (`plan.txt:56-59`) should keep the inline `|| true` guard on `append-tool-failure.sh` (`SKILL.md:1280`). Without it, `set -euo pipefail` in the new helper can turn a logging-side failure into an unexpected exit and blur the 0/1/2 contract the orchestrator will branch on (`plan.txt:11-14`, `83-87`).
