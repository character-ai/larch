## Approach

Add an optional result-env sink to the ship result contract. Reuse the redacted JSON payload so stdout, journaling, and result-env values cannot drift. Keep JSON stdout byte-compatible for callers that omit the new flag.

Validate the result-env path under the owned implementation tmpdir. Refuse unsafe files and symlinked path components. Write the complete env atomically and fail closed on errors.

Confidence: high.

### UPDATED: python/larch/implement/ship_result.py

- Extend `emit_result()` with an optional result-env path.
- Convert ship payload fields to uppercase `KEY=value` rows with stable scalar formatting for strings, integers, booleans, and null values.
- Include `CI_ERRORS_FILE`, `CI_ERRORS_DISTILL_CLASS`, and `FAILED_JOBS_COUNT` in the result-env contract, including empty or zero values needed by downstream routing.
- Sanitize CR and LF bytes for the line-oriented format without changing the existing JSON representation.
- Validate that the destination is an absolute regular-file path beneath `ctx.tmpdir`, with no symlinked destination or parent.
- Use the shared atomic I/O helper with restrictive permissions.
- Write the result env before publishing the JSON contract so a failed required write cannot appear successful.
- Preserve the existing JSON stdout and best-effort journal behavior when no path is supplied.

## Edge cases

- Preserve empty values that distinguish an unavailable CI digest from an omitted result.
- Render `None` as an empty value and booleans as lowercase wire tokens.
- Do not let multiline detail or redacted diagnostic text forge extra KVs.
- Do not create missing or unsafe parent directories outside the validated bgjob path.

## Failure modes

- Reject an invalid result-env path before emitting a successful JSON result.
- Propagate result-env write failures so bgjob transport records a failed child instead of consuming a partial file.
- Keep journal append failures best-effort after both primary contracts succeed.
