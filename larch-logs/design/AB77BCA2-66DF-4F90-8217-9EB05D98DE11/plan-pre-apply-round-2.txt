## Approach

Add an optional, required-once-supplied result-env sink to the ship contract. Derive its KVs from the same redacted result payload used for JSON, while preserving JSON stdout exactly for callers without the flag.

Prevalidate a supplied path before `run_ship` or any other ship mutation. Require the tmpdir allowed-root gate, reuse the bgjob merge-env validator, and publish with trusted atomic I/O. A required result-env failure must not publish a successful JSON contract.

Confidence: high.

### UPDATED: python/larch/implement/ship_result.py

- Extend `emit_result()` with an optional, prevalidated result-env path.
- Build result-env rows from the redacted JSON payload using stable uppercase `KEY=value` scalar rendering: strings as text, integers as decimal, booleans as lowercase tokens, and `None` as empty.
- Sanitize CR/LF only in result-env values so multiline or diagnostic content cannot forge rows; leave JSON payload rendering unchanged.
- Emit all outcome, ledger, repair, and CI fields needed by downstream routing.
- Mirror `dispatch_ship` CI pairing rules: always emit `CI_ERRORS_FILE` and `FAILED_JOBS_COUNT`; emit `CI_ERRORS_DISTILL_CLASS` only when `CI_ERRORS_FILE` is empty.
- On a supplied sink, require `_tmpdir_under_allowed_root(ctx.tmpdir)`, revalidate/canonicalize with `bgjob.model.validate_merge_result_env()`, and write with `larch.io.format_kvs()` plus `trusted_atomic_write(..., root=ctx.tmpdir, mode=0o600)`.
- Write the result env before JSON stdout; propagate validation or write failures without a successful JSON result.
- Retain existing JSON stdout and best-effort journaling behavior when no sink is supplied; journal only after both primary contracts succeed.

## Edge cases

- Preserve empty values that distinguish unavailable CI evidence from omitted output.
- Render `None` as empty and booleans as lowercase wire tokens.
- Do not emit contradictory CI digest and distillation-class keys.
- Do not follow symlinked path components or create missing parent directories.

## Failure modes

- Reject invalid result-env configuration before ship work begins.
- Fail required result-env writes closed so bgjob transport records a failed child rather than consuming a partial result.
- Keep journal append failures best-effort only after result-env and JSON publication succeed.
