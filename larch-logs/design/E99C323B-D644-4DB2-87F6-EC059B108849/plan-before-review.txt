## Approach

Use the existing run-log commit path as the enforcement point. Validate the staged run directory before it is copied and committed. Do not backfill old logs.

Add a small completeness model:

- Required artifacts are derived from current run evidence, not hardcoded as a flat filename list.
- Required implement artifacts:
  - `session-transcript.jsonl` once Step 7a-level evidence exists.
  - `final-summary.md` once terminal summary evidence exists or Step 8-level evidence exists.
  - `review-findings-full.jsonl` when code review voting ran.
- Required design artifacts:
  - `final-summary.md` for design log publish.
  - `session-transcript.jsonl`, unless transcript capture recorded an execution issue.
  - `review-findings-full.jsonl` when plan-review voting ran.
- Optional telemetry, including token and timing reports, stays fail-soft.

For each missing required artifact, accept only a committed execution-issues record that names the missing artifact or its canonical slug. Accept `execution-issues.ndjson` for implement logs and `execution-issues.md` for design logs. Do not accept session-local status strings such as `SESSION_TRANSCRIPT_STATUS=write-failed` unless they were rendered into a committed execution-issues artifact.

Return a distinct run-log incompleteness exit code from `run-log commit`. Preserve `run-log refresh` as an envelope-producing command, but report a distinct skip reason and error text when the commit gate rejects the run.

## Edge cases

- A missing artifact with an execution issue that does not name the artifact must fail.
- Empty or malformed execution-issues files must not satisfy the check.
- Prior committed logs are not scanned or backfilled.
- Optional token/timing telemetry must not become required by accident.
- Design logs may use `execution-issues.md`; implement logs should prefer `execution-issues.ndjson`.

## Failure modes

- Import cycles can occur if `run_log_commit.py` calls helpers that import `run_logs.py`. Keep shared logic below both callers.
- Over-broad required-artifact detection can block legitimate early bailouts. Gate artifacts only when existing run evidence says the corresponding phase ran.
- Over-loose omission matching can turn a status string into a false pass. Require a category-keyed execution issue and artifact-specific text.
- Changing `run-log refresh` exit behavior can break callers that parse its stdout envelope. Prefer a new reason over a new refresh process rc unless tests prove safety.

## Testing strategy

Run focused tests only:

- `python3 -m pytest python/tests/report/test_run_log_flush.py`
- `python3 -m pytest python/tests/report/test_run_logs.py -k verify_completeness`

Then run changed-file lint if Python lint is available:

- `make py-lint`

Do not run broad harnesses unless the implementation touches shell or skill prompts.
