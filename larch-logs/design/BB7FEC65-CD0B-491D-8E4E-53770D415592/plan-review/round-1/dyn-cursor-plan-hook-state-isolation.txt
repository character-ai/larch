The misfire half is under-specified. The plan says to verify “session-beta does not inherit session-alpha count,” but the only interleaved beta action described is a **different-path** read. Under the current cwd-only key (`scripts/hook-anti-read-poll.sh:356`, `374-377`), a different-path beta read already resets the shared counter; beta staying silent does not prove misfire prevention. The bug report’s misfire case requires both sessions to read the **same** path: after alpha reaches count 2 on `X@offset0`, beta’s first read of `X@offset0` would bump the shared file to count 3 and can emit a spurious reminder (`scripts/hook-anti-read-poll.sh:389`) even though beta has only polled once.

**Suggested revision:** Extend the planned regression with an explicit same-path step (alpha ×2 on `X`, beta ×1 on `X` with `assert_silent`, then continue with the different-path interleave and alpha’s third read). The plan’s own Failure modes section already flags this risk; the test design should match it.
