## Edge cases

- A referenced marker and heuristic phrase occur together. The referenced regression wins.
- A bare `regression` has no trustworthy issue number. Emit `ref: null` and omit it from the chain list while counting it in the regression ratio.
- Several referenced markers occur. Use the first match in the stable title-then-root-cause input order rather than inventing a multi-parent schema.
- Marker text appears only in an appended `/design` plan. Ignore it because origin extraction uses the diagnostic prefix and retained digest sections.
- A digest has no structured root-cause section. Check its normalized title and retained fallback section, then default to unknown.
- There are no selected bugs. Render zero counts, no chains, and a `0/0` or `n/a` regression ratio as specified by the skill, without dividing by zero.
- Percentages do not sum to exactly 100 after rounding. Preserve raw counts and state the denominator.
- A regression has `ref` equal to its own issue number. Keep the classification but flag the self-chain as suspect evidence rather than presenting it as a valid chain.
- `--zones` contains whitespace around names. Trim it.
- `--zones` is empty, contains an empty comma element, or is combined with verbal search text. Stop with a clear argument error before preparation.
- Zone text contains shell metacharacters. Keep it quoted as data and pass the final query through the existing argv array.

## Failure modes

- Over-broad regexes may classify ordinary uses of “introduced” or “after” as regressions. Anchor patterns to the required phrases and issue-number syntax.
- Heuristic prose may produce false positives. Keep the phrase list small, document it as best-effort, and retain `unknown` as the default.
- Prompt-only report requirements can drift. Pin the key report grammar and ordering in the structural harness.
- Reversing chain direction would misstate causality. Tests and skill prose must define the earlier referenced issue as the left side and the current digest issue as the right side.
- Treating percentages as the source of truth can hide rounding errors. Always render counts and the total denominator.
- A guideline may be accompanied by vague mechanical prose to avoid the warning. Require a named lint, hook, or invariant test, or an explicit acceptance that none exists.

# bug-treadmill [FEATURE] learn-from-bugs: origin mining + regression-ratio headline

#### Problem

`/learn-from-bugs` clusters root causes but has no origin view: it cannot say what fraction of bugs are residuals of earlier fixes versus first-exercise failures of new code versus spec gaps. A manual classification of 38 recent bugs found 24% fix-residual chains and 39% new-code-latent; that distribution is the single most decision-relevant fact about the 2026-07 wave, and no tool computes it. Separately, the skill proposes guideline entries as preventions even though prose demonstrably regresses here: #6746 measured a prompt-side fix moving the assessment miss rate from ~12% to 20% because "nothing mechanical checks the artifact afterward".

#### Required design

1. Digester (`learn-from-bugs prepare` path in `python/larch/issue/learn_from_bugs.py`): extract origin markers from the title and the root-cause digest sections with regexes for `introduced by #N` / `introduced by PR #N`, `incomplete fix of #N`, `persists after #N`, `residual of #N`, and bare `regression`. Each digest record gains `origin`: `{"kind": "regression|new-code|spec-gap|unknown", "ref": &lt;int or null&gt;}`. Kind heuristics: an extracted reference implies `regression`; body language like "never designed", "was never told", "no handling for" implies `spec-gap`; "first time this path ran", "newly added" implies `new-code`; default `unknown`. Heuristics are best-effort and documented; do not overfit.
2. Report Step 4 section 2 (root-cause clusters) gains a headline block first: origin distribution with counts and percentages, the chain list as `#X -&gt; #Y` pairs, and the regression ratio. When a chain's mechanism is a duplicated contract (two parsers, hand-copied field names), name single-sourcing as the class fix.
3. Prose-only warning: in the proposals sections, any cluster whose only residual proposal is a guideline entry is marked `prose-only prevention: unlikely to stick`, citing #6746 and #6747, with a required one-line statement of the nearest mechanical alternative (lint, hook, invariant test) or an explicit acceptance that none exists.
4. Zone scoping: a new `--zones "a,b"` flag translating zone names into the gh search expression through the existing verbal-description path. This is the documented handoff from the analyze-bugs chronic-zones report line.

#### Tests

Marker-extraction unit tests (each regex family plus a no-marker body); origin-kind heuristic tests; report fixture asserting the headline block, a chain pair, and a prose-only marker; `--zones` translation test.

#### Non-goals

No automatic coupling that runs this skill from analyze-bugs; no change to filing behavior or to the `--file` contract; no re-classification of already-scanned history.

#### Acceptance criteria

1. On a digest fixture containing a `persists after #N` body, the report headline shows a regression entry and the `#X -&gt; #Y` chain.
2. A cluster with only a guideline proposal renders the prose-only marker with a mechanical alternative line.
3. `--zones` produces the expected search expression; SKILL.md documents flag and headline.

#### Backing evidence

The origin distribution is what distinguishes "old code decaying" (1 of 38) from "the pipeline refilling its own queue" (24% residuals); without it every run of this skill reads as a fresh list of unrelated clusters. Part of the `bug-treadmill` umbrella; implementable independently of the analyze-bugs issues.
