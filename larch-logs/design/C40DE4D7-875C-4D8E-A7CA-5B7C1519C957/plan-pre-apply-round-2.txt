Cover these scenarios:

1. `bgjob start` prints exactly one line:
   `BGJOB_STATUS=STARTED STEP=<name> PGID=<n>`
2. Owner death:
   - start a live owner process
   - start a long child with `--owner-pid <owner-pid>`
   - kill the owner
   - wait for `BGJOB_RC=orphaned`
3. Budget expiry:
   - start a long child with `--budget-s 1`
   - wait for `BGJOB_RC=timeout`
4. External daemon kill:
   - start a long child
   - read the daemon PID from the registry row
   - kill only the daemon
   - assert `bgjob wait` reports `BGJOB_STATUS=DEAD` within one short wait interval

   - create a registry row with valid tmpdir, log_dir, stdout, stderr, and result-env paths
   - set `START_EPOCH` old enough or `BUDGET_S` small enough that `entry_expired` is true before `bgjob reap` runs
   - ensure no result env exists (or result env absent/unlinked)
   - set daemon liveness dead (`DAEMON_PID` absent or identity-invalid)
   - point `CHILD_PID` at a live recycled process with mismatched recorded child identity fields
   - run `bgjob reap`
   - assert the row is removed
   - assert the live recycled PID still exists (reap must not signal the PID's new owner)
6. Bad step names:
   - assert names with `..`, `/`, and `\` reject with rc 2 and `BGJOB_ERROR`

Harness details:

- Use a private `mktemp -d` root.
- Set `LARCH_BGJOB_REGISTRY_ROOT` under that root.
- Set the new test-only timing env vars only inside this script.
- Use cleanup traps to kill any live child, owner, or leftover process group that the test started.

## Edge cases

- `ps` may be blocked or non-standard in a sandbox. The harness must skip loudly, not fail with confusing process-identity errors.
- A killed daemon can leave the child process alive. The harness cleanup must terminate only processes it started.
- PID reuse tests must not signal the live recycled PID. Scenario 5 requires an expired row with dead daemon and mismatched live child identity; validate by keeping the live process alive after reap.
- Owner death depends on consecutive identity failures. Use both grace and poll overrides to keep the test fast.
- Registry rows must use valid tmpdir, log_dir, stdout, stderr, and result-env paths or `read_entry` will discard them before the test reaches reap logic.
- `reap_main` case 2 and harness scenario 5 target different branches: pytest case 2 hits terminate-validated on expired rows; harness scenario 5 proves no signal to a live recycled PID under the same expired terminate path.

## Failure modes

- A malformed registry fixture can produce a false pass by making `reap` treat the row as invalid or take the both-dead unlink shortcut. Build fixtures with real valid paths, force expiry, set daemon dead + child live with corrupted identity, and only then corrupt identity fields.
- A too-small timeout can make CI flaky on busy runners. Use bounded loops with clear diagnostics and a small but nonzero slack.
- Invalid override parsing could make production daemon startup fail if an operator accidentally exports the test env var. Fail closed with an explicit error at daemon startup when override env is set but invalid.
- Import-time caching of timing overrides would break existing monkeypatched orphan tests while new parser tests still pass. Helpers must read env/config on each call.
- Baseline regen without lint pragmas at new read sites fails closed and blocks ship. Record reasons before `make regen-env-via-config-constant-baseline`.
- If the Bash harness uses Bash 4 features, macOS contributors will fail. Keep arrays simple and avoid associative arrays, `mapfile`, namerefs, and case conversion.
- Updating PR #6706 body without preserving existing content would drop audit context. Use body-preserving fetch-merge-edit flow.
