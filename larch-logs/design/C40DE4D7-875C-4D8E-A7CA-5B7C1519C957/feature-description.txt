# Ship the real-process bgjob harness and close #6524/#6516 acceptance leftovers

## Problem

A 2026-07-09 audit of the bgjob migration drive (#6514, #6524 with chunks #6530-#6540, #6516) found the drive complete except three leftovers. All drive issues are closed, so this issue captures the unfinished items.

1. `scripts/test-bgjob.sh` only re-runs `python/tests/bgjob` under pytest. #6524 acceptance criterion 8 and #6530 criterion 1 required real-process coverage instead. Owner death, budget expiry, and external kill are covered only by monkeypatched unit tests. `bgjob reap` (`reap_main` in `python/larch/bgjob/cli.py`) has no tests at all, yet `scripts/cleanup-sessionstart.sh` runs it at every session start.
2. PR #6706 closed #6516 without the Section E KEEP/REPOINT/DELETE decision table required by its acceptance criterion 5.
3. `python/env-via-config-constant-baseline.json` still carries an entry for `_bg_wait_marker_context`, a symbol PR #6706 deleted. The #6516 plan listed this baseline for update; the PR deferred it.

Real-process coverage matters here. The production orphan-bug family (#6580, #6590, #6591, #6595, #6612) fired at ~123s, right at `BGJOB_OWNER_GRACE_S = 120` plus poll slack: the exact zone owner-death tests target.

## Work items

### A. Real-process `scripts/test-bgjob.sh` harness

Replace the pytest-wrapper body with real-process coverage, per #6524 item 35:

- daemon start prints exactly one `BGJOB_STATUS=STARTED STEP=<name> PGID=<n>` line
- owner death: kill the owning process; the daemon self-terminates within grace and writes `BGJOB_RC=orphaned`
- budget expiry (`--budget-s 1`): the daemon kills the group and writes `BGJOB_RC=timeout`
- external daemon kill: `bgjob wait` returns `DEAD` within one poll interval
- `bgjob reap` removes a synthetic stale registry row with a recycled PID without signaling the PID's new owner
- step names with `..` or path separators are rejected

Keep the harness fast. `BGJOB_OWNER_GRACE_S` is a hardcoded `Final = 120` in `python/larch/core/config.py`; a naive owner-death test waits two minutes. Add a test-only override (env var routed through a config constant, production default unchanged, baseline reason recorded per the env-via-config-constant lint). Same option for `BGJOB_DAEMON_POLL_INTERVAL_S` if needed.

The Makefile `test-bgjob` target already runs `bash scripts/test-bgjob.sh` inside `test-harnesses-4`; no rewiring needed unless runtime grows (then re-shard per `docs/linting.md`). Skip loudly where the sandbox blocks `ps` process-identity probes. Keep `python/tests/bgjob` in `py-test`; do not duplicate it as the only bgjob harness.

### B. `bgjob reap` unit tests

Add pytest coverage for `reap_main`: a stale dead row is removed, an identity-mismatched (recycled) PID is left unsignaled, and a live identity-valid row is preserved.
