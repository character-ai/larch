# [OOS] CI bail-token normalization & stall-recovery improvements — 5 items

## Out-of-Scope Observations — CI bail-token normalization & stall-recovery improvements

Combined from issues #4086, #4055, and #4039 (partial).

### Item 1 — LAUNCHER_EXIT missing on non-zero exit treated as success

- **Location**: python/agents.py
- **Description**: `make_conflict_launch_fn` (and `launch_*_ci_main` callers) parse `LAUNCHER_EXIT` only from FD-3 stdout. When a CI launcher tier exits non-zero before emitting its `LAUNCHER_EXIT` line, the waterfall treats the missing value as 0 (success) and can misclassify a failed tier as successful before moving to the next fix attempt. The same parsing gap exists in CI monitor. Suggested fix: treat a missing or non-integer `LAUNCHER_EXIT` on a non-zero process exit as a launch failure, not a success.

### Item 2 — ci-wait.sh still emits prose BAIL_REASON instead of normalized tokens

- **Location**: scripts/ci-wait.sh
- **Description**: `scripts/ci-wait.sh` still emits prose `BAIL_REASON` values (e.g., "Poll budget exhausted", "ci-wait.sh exited unexpectedly", "No CI checks observed") instead of normalized tokens. The mixed prose/token surface persists in the CI wait stack after `ci-decide.sh` normalization, so downstream classifiers see inconsistent bail formats.

### Item 3 — stall-recovery-report.sh residual legacy API surface and env encoding

- **Location**: skills/implement/scripts/stall-recovery-report.sh
- **Description**: Two residual issues: (1) legacy `bug-body`, `bug-comment`, and issue-input renderers remain callable entry points — a stale caller will silently use them without error; (2) `env` value encoding has pending fixes for multi-line values that pass through the KV grammar incorrectly.

### Item 4 — Stale stall-tracking layers can block escalation-success reporting

- **Location**: skills/implement/scripts/stall-recovery-report.sh, finalize-state.sh, session-env.sh, ship-pr-state.sh
- **Description**: `normalize-outcome` reads stall state from up to four ambient or non-cleared layers (`STALL_TRACKING` in `finalize-state.sh`, `ship-pr-state.sh`, `session-env.sh`, and stall-recovery-report's own state). Stale data in any layer can block the escalation-success path from reporting correctly.

### Item 5 — Tier B bail-token union spans four authority sources with only test sync

- **Location**: skills/implement/scripts/stall-recovery-report.sh:543-554
- **Description**: The Tier B bail-token union is required by the issue spec but spans four authority sources with only test sync to keep them aligned. High drift risk on every new dispatcher token addition. Suggested fix: consolidate the union into a single canonical source and derive the others from it.
