1. **correctness** — `skills/design/scripts/validate-plan-commands.md:[planned-contract]` — Tier 2 bullet (Approach) treats flags missing from `--help` as `DEFECT kind=unknown-flag`, while Edge cases (lines 52–53) mandates `SKIPPED_FLAG_CHECK reason=flag-not-in-help` and continuation; these cannot both hold. **Suggested revision:** pick one contract and align Approach, Edge cases, and the validator sibling doc.

2. **risk_integration** — `skills/design/references/approval-gates.md:86-87` — Gate B explicitly re-runs `ACTION=EMIT_PLAN` after revising `plan.txt`, but the plan only adds `VALIDATE_PLAN_COMMANDS` after the initial Step 2 emit and before Step 5c `composed-plan.md`. There is no validation pass tied to the post-review plan revision, so defective commands can persist through Step 3b–4–4b until late Step 5c (or never when `review_budget=quick` skips both gates). **Suggested revision:** run the same validation immediately after each post–Gate B `EMIT_PLAN`, or document the residual risk window and acceptable abort behavior.

3. **correctness** — `skills/design/SKILL.md:496-504` — Today’s EMIT_PLAN failure flow requires repairing `plan.txt` before Step 3; a parallel “Fix-and-retry” for command defects will edit `plan.txt` without a stated obligation to re-run `ACTION=EMIT_PLAN`, leaving `diff_lines.txt` / `diff_lines:` potentially stale vs the repaired body. **Suggested revision:** whenever `plan.txt` is edited to fix validator defects, re-emit `ACTION=EMIT_PLAN` before the next `VALIDATE_PLAN_COMMANDS` attempt.

4. **architecture** — `skills/design/scripts/validate-plan.sh` (planned) — Step 5c must validate `composed-plan.md` while Step 2b validates `plan.txt`; the plan relies on narrative (“when invoked from Step 5c”) but does not pin the driver `ACTION=… ARGS=…` contract or `validate-plan.sh` CLI flags in the Files-to-create list. **Suggested revision:** specify `ACTION=VALIDATE_PLAN_COMMANDS ARGS=…` (or env) in `design-driver.md` / `validate-plan.md` and thread the same argv from both SKILL call sites.

5. **code-quality** — `skills/design/SKILL.md:805-814` — The canonical “Plan helper contracts” footer lists emit/tally/finalize/file-oos/plan-block-write/etc., but the plan’s Files-to-update section never adds the new parser, validator, wrapper, or `scripts/dry-runnable-scripts.tsv`, breaking the repo’s discoverability pattern enforced elsewhere. **Suggested revision:** extend that bullet list (and any `test-design-structure.sh` pins if they assert helper completeness).

6. **security** — `SECURITY.md` — Tier 3 literally executes commands parsed from plans (even with `LARCH_DRY_RUN=1` / timeouts), and failure mode 2 adds override forensics; AGENTS.md expects `SECURITY.md` updates when security-relevant behavior changes, but the plan’s file list omits it. **Suggested revision:** add a short section documenting dry-run registry expectations, blast-radius limits, and override logging boundaries.
