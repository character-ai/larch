### Agreement (load-bearing, both sketches + user Round-1 decisions)

- **Two-helper architecture**: deterministic `skills/design/scripts/parse-plan-commands.sh` (markdown-state-aware fenced-block extractor; side-effect-free TSV output) + execution-facing `skills/design/scripts/validate-plan-commands.sh` (consumes TSV; runs Tier 2 + Tier 3). Both helpers live under `skills/design/scripts/` per `.claude/rules/script-md-siblings.md` with `.md` siblings.
- **Driver integration**: route the validator through `skills/design/scripts/design-driver.sh` as a new re-runnable `ACTION=VALIDATE_PLAN_COMMANDS`, mirroring `ACTION=EMIT_PLAN` / `ACTION=TALLY` / `ACTION=FINALIZE`. Caller passes the plan file path on stdin or as flag; driver shells out to parser → validator and emits KV status.
- **Invocation points**: Step 2b — immediately AFTER the existing `ACTION=EMIT_PLAN` block (so `diff-lines.txt` is written and `plan.txt` is final for this turn); Step 5c — BEFORE `redact-secrets.sh` pipes `composed-plan.md` through and `plan-block-write.sh` writes to GitHub (so defects cannot reach the issue body).
- **Parser scope** (Round 1 Q4): fenced ` ```bash ` / ` ```sh ` blocks only; split each command line on `|`, `&&`, `||`, `;`; suppress heredoc bodies (`<<EOF ... EOF` and `<<'EOF' ... EOF`); join backslash continuations; identify the script path as the first non-flag token after env-var assignments; extract named long flags (`--foo` / `--foo=bar` / `--foo bar`); emit TSV `block_line_start<TAB>script_path<TAB>flag1<TAB>flag2<TAB>…`. Conservatively skip subshells `$(...)` and process substitution `<(...)` with a `PARSE_NOTE skipped=<kind> line=<N>` row.
- **Validator scope** (Round 1 Q2): only commands whose script path matches `scripts/`, `skills/*/scripts/`, or `.claude/skills/*/scripts/`. System commands (gh, jq, awk, sed, grep, find, printf, sort, etc.) are dropped silently at TSV-consumption time.
- **NEW / UPDATED parsing** (Step 1c Q2): `### NEW: <path>` headings exclude that path from validation entirely. `### UPDATED: <path>` headings + a structured `- Adds flag: --newflag` bullet under the heading allow that single new flag on that script silently. Other UPDATED-script flags still validate normally.
- **Tier 2 graceful-skip** (Round 1 Q1): when a script lacks a `--help` arm (helper run with `--help` exits non-zero, produces empty stdout, or times out), skip flag-check; log `SKIPPED_FLAG_CHECK script=<path> reason=no-help` to `$DESIGN_TMPDIR/validate-plan-commands.log`. Existence check still fires.
- **Tier 3 contract**: opt-in via top-level `scripts/dry-runnable-scripts.tsv` (sibling `.md` documents the dry-run convention each script honors — `LARCH_DRY_RUN=1` env var or `--validate-only` flag, per the script's choice). Runs AFTER Tier 2 passes for that script (Round 1 Q3 — both must succeed). Bounded timeout (10s default). Defects emit `DEFECT kind=dry-run-failed script=<path> exit=<N>` with captured stdout/stderr appended.
- **Tier-gating** (Step 1c Q1): validator is no-op on `--trivial`. Gate is mechanical: read `review_budget` from `$DESIGN_TMPDIR/run-params.json` (`full` ⇒ validate; `quick` ⇒ skip), matching the existing Step 3 gating mechanism. /implement Preflight gating is out of scope (Step 1c Q3).
- **Failure flow**: when the driver returns defect rows (non-zero exit OR a `DEFECTS_FOUND=true` KV), the orchestrator presents `AskUserQuestion` with **Fix-and-retry / Override / Cancel**. Fix-and-retry: operator edits `$DESIGN_TMPDIR/plan.txt` (or the `composed-plan.md` for Step 5c) and the driver re-runs. Override: decision logs to `$DESIGN_TMPDIR/execution-issues.md` under `Warnings` via `append-tool-failure.sh` and the run continues. Cancel: in Step 2b it returns to Gate A (no plan published yet); in Step 5c it preserves `$DESIGN_TMPDIR` (mirrors plan-block-write failure path) — do NOT run cleanup.
- **Defect-row schema**: parser emits `PARSE_NOTE` rows for skipped constructs; validator emits `DEFECT script=<path> kind=<missing-script|unknown-flag|dry-run-failed> [flag=<flag>] [exit=<N>] [message=<one-line>]` rows. Both files (`$DESIGN_TMPDIR/parse-plan-commands.tsv` + `$DESIGN_TMPDIR/validate-plan-commands.log`) are surfaced to the operator when the failure-flow prompt fires.
- **Companion artifacts**: harnesses `skills/design/scripts/test-parse-plan-commands.sh` + `skills/design/scripts/test-validate-plan-commands.sh` with `.md` siblings; Makefile targets `test-parse-plan-commands` and `test-validate-plan-commands` wired into `make lint`; `skills/design/references/flags.md` documents the tier rule and AskUserQuestion options; `agent-lint.toml` exclusions if any introspection patterns mis-flag the new helpers; topology row in `skills/shared/topology.tsv` documenting the new validator phase.

### Out-of-scope (v1)

- Subshells `$(...)`, process substitution `<(...)`, embedded `eval` and complex quoting interpolation — parser emits `PARSE_NOTE skipped=<kind>` rather than guessing.
- `/implement` Preflight validator gating (Step 1c Q3 — explicit out of scope; can be filed as a follow-up).
- Auto-overhauling existing scripts to add `--help` arms — already filed as separate issue #2679.

### Tradeoffs and Risks

- **Parser precision vs. complexity**: a Bash/awk parser handles the specified command shapes (pipes, chains, heredoc suppression) without an AST dependency. The cost is well-known blind spots; `PARSE_NOTE` makes those visible rather than silent.
- **Tier 2 coverage**: with 394 of 501 .sh scripts lacking `--help`, graceful-skip means many invented flags will still slip through v1. Mitigated by the parallel overhaul issue #2679 and by Tier 3 catching opted-in scripts comprehensively.
- **Tier 3 execution risk**: dry-run executes literal plan commands, so any script that mis-honors `LARCH_DRY_RUN=1` could have side effects. Mitigated by the explicit opt-in registry + sibling-doc requirement + timeout cap.
- **Re-run cost on Fix-and-retry loops**: each iteration re-runs the full parser + validator pipeline (~seconds, not minutes). Acceptable for an interactive defect-fix loop.
