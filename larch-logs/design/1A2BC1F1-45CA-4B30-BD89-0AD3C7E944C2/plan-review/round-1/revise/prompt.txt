# Plan: "Override and proceed" option for /design oversized-feature gates

Add a third option — **Override and proceed (advised against)** — to the two `/design`
prompts that gate an oversized feature: the Step 2b.5 plan-size **Hard branch** and the
Step 1c/1d **semantic-sprawl** heuristic. The option carries a prominent anti-recommendation,
sits **next-to-last** (Split / Override / Cancel), proceeds without a second confirmation, and
writes a Warnings audit entry to the run log. Thresholds and the `--partition` flow do not change.

## Approach

The override behaves exactly like the existing **No-trigger branch**: it logs an audit note and
**returns to the caller**. The caller's existing routing then decides where to go next:

- Initial Step 2b -> Step 2b.5 hard override -> return -> Step 3 (plan review).
- Gate B re-emit -> Step 2b.5 hard override -> return -> Step 3b (per Gate B flow).
- Step 3 `LOOP_STATUS=plan-size-trigger` -> hard handler override -> return -> the existing
  "short-circuit to Step 3b".
- Step 1c/1d sprawl override -> return -> the normal pre-plan flow (no split, no cancel).

Reusing "return to caller" keeps the change small and uniform: the override sets no
`SUMMARY_OUTCOME` and never exits, so no new cancellation outcome is introduced and
`render-final-summary.sh` (and its test) stay untouched.

Each override appends a `### Warnings` entry to `$DESIGN_TMPDIR/execution-issues.md` through
`append-tool-failure.sh` (`--category Warnings --exit-code 0 --redact`), so the committed run
log records that the operator bypassed the gate. The audit write is best-effort (`|| true`) and
never blocks the operator's chosen action.

The new option is always shown when the prompt fires; the prominent warning is the only
guardrail (no flag, no second confirmation). `--partition` still cannot auto-downgrade a hard
trigger — the override is an explicit, loudly-discouraged operator escape hatch, a different
thing from a `--partition` downgrade.

Both prompts use the same label and a context-appropriate description.

- Hard-branch description: `STRONGLY DISCOURAGED. Proceeding with this oversized plan is quite
  likely to SEVERELY degrade the quality of the reviews and the resulting design. We advise

  quite likely to SEVERELY degrade the quality of the reviews and the resulting design. We
  advise against it. Pick this only if you knowingly accept that risk; splitting is almost
  always better. The override is recorded in the run log.`

Option order on both prompts (next-to-last placement): Split / Override / Cancel. The Split and
Cancel labels and their existing on-select behavior are preserved verbatim.

## Summary

Add an **"override and proceed"** option to the `/design` Step 2b.5 hard-trigger `AskUserQuestion` (in `skills/design/SKILL.md`).

## Current behavior

When `HARD_TRIGGER_FIRED=true` — plan-body line count **> 800**, or `diff_added` **> 2000** (legacy `diff_lines` **> 1500**) — the Step 2b.5 **hard branch** fires an `AskUserQuestion` with **exactly two** options:

1. "Let my panel of agents split this feature for you"
2. "Cancel"

This is deliberate: SKILL.md notes "(no **Continue** option — hard triggers are never downgradeable by `--partition`)". There is intentionally no escape hatch to proceed with an oversized plan.

## Requested change

Add a **third** option that lets the operator override the hard trigger and proceed straight to plan review (Step 3) with the current oversized plan. Requirements:

1. **Prominent anti-recommendation.** The new option's label/description must very prominently state that overriding is **quite likely to severely degrade the quality of the reviews and the resulting plan**, and that we **advise against it**.
2. **Position: next-to-last.** It must be shown as the next-to-last choice — i.e. **between** the Split option and Cancel. Final option order:
   - "Let my panel of agents split this feature for you"
   - **Override and proceed (advised against — likely severe quality degradation)**
   - "Cancel"

## Motivating example

> "As I flagged: `HARD_TRIGGER_FIRED=true` (reason diff-added: 2700 > 2000). Plan body is only 238 lines (under the 800 plan-body trigger), so this is purely the diff-size trigger — driven by the full-surface scope you chose in Round 1."

In cases like this the operator may knowingly accept the risk and want to proceed rather than split or cancel.

## Scope

The larch `/design` skill itself:

- Primary: `skills/design/SKILL.md` Step 2b.5 **Hard branch** (the `AskUserQuestion` option list and the on-Override routing to Step 3).
- Any structure-test pins that assert the current "exactly two options" wording (e.g. `scripts/test-design-structure.sh`).
- Possibly `skills/design/references/flags.md` / `references/approval-gates.md` cross-references that describe the hard branch as having no Continue/override option.

## Out of scope

- The partition (`--partition` / `-p`) flow and soft-advisory (`mechanical_churn`) behavior are unchanged.
- The hard-trigger thresholds themselves are unchanged.
