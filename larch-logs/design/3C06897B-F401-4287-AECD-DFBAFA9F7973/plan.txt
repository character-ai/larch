## Approach

`phase_plan_materialize` follows `phase_tracking`'s established idiom (local-scoped helper variables, `kv_value_from_block` parsing, `$SCRIPT_DIR` for sibling scripts, `larch_err`/`emit_kv`/`emit_breadcrumb` channel discipline, `return 0` after setting bail reason). The function body order matches the current SKILL.md L645–810 byte-for-byte: **snapshot → token/timing marks → cp plan → gh-compose → workflow-path → persist-run-flags → dirty-tree → slug+branch (conditional) → git-current-branch → plan-log → plan-review-tally → larch:plan-summary**.

The new `--preflight-tmpdir` argv flag delivers the Preflight artifact location explicitly (validated as required when `--up-to-phase ∈ {plan,coder,all}`). A new `should_run_phase_plan_materialize` predicate is permissive on `DEFERRED=true` (FORKED_TARGET-skip, POSTED=false-deferred) — only hard bails (closed/PR/init-failed/STALL_TRACKING/REPO_UNAVAILABLE) skip the phase — so forked-target runs still get `feature-description.txt` and `plan.txt` materialized for Step 2 dispatch. `phase_coder_select` (Phase 4) continues to use the stricter `should_run_post_tracking_phase`.

Three new tail keys (`BRANCH_NAME`, `BRANCH_ACTION`, `PLAN_FILE`) replace empty placeholders in `emit_final_tail`. Two guarded breadcrumbs match the documented `LARCH_QUIET_BREADCRUMBS`-truthy pattern (no stdout pollution under `LARCH_QUIET_DISABLE=1`). All composed log inputs (goal text, plan-review-tally body, larch:plan summary body) pipe through `redact-secrets.sh` + `redact-tmpdir-paths.sh` before write — preserves the SKILL.md L632–634 compose-time-sanitization invariant.

SKILL.md changes are surgical: change `--up-to-phase tracking` → `--up-to-phase plan` (+ `--preflight-tmpdir`), add three KV case arms, add two exit-2 handler branches, add a `dirty-tree` routing branch in the Step 0 bail guard, and remove ~150 lines of now-redundant prompt-side prose between L645–795 + L658–685.

## Edge cases

1. **Empty `feature-description.txt` first line**: `head -1` on a malformed file returns empty; `slug` becomes empty; `branch_name_derived` becomes `${USER_PREFIX}/-${ISSUE_NUMBER_RESOLVED}` (leading dash after prefix). Same behavior as current SKILL.md pipeline — not regression. Tested implicitly via B5-plan-green iter 1 (uppercase non-empty title). Explicit empty-title hardening deferred to a follow-up issue.
2. **`PREFLIGHT_TMPDIR/plan-from-issue.txt` missing or empty**: `cp` fails; `STEP_FAILED=copy-plan` + `exit 2` (B11-plan-copy-plan-failure). SKILL.md exit-2 handler surfaces the captured stderr.
3. **`tracking-issue-summary.sh` rate-limited / network failure**: best-effort path; non-zero rc logged via `append-tool-failure.sh` to `Warnings`. Skipped entirely for forked-target (FORKED_TARGET=true gate).
4. **`gh issue view` exits non-zero (auth/network)**: captured rc → `STEP_FAILED=gh-issue-view` + `exit 2` (B12-plan-gh-issue-view-failure). SKILL.md exit-2 handler surfaces captured stderr.
5. **`IS_USER_BRANCH` not yet populated**: `phase_infra` always populates this global via early `create-branch.sh --check`; defensive `${IS_USER_BRANCH:-false}` handles the unset case as belt-and-suspenders.
6. **`dirty_status` is empty (parse failure)**: defaults to neither `dirty` nor `unknown` so phase proceeds. Acceptable — `check-mid-run-dirty-tree.sh` is designed to be permissive; a hard parse failure should not block plan materialization.
7. **Forked-target with empty `UPSTREAM_REPO_OPT`**: `main()`'s existing validation requires `--upstream-repo` when `--forked-target true` is set with `--issue-number`; defensive empty-arg handling in `gh_repo_args` composition produces `""` which `gh` interprets as no `--repo` (fallback to hub default). Document this in `implement-bootstrap.md` as a known degraded mode.

## Failure modes

1. **Order-of-operations drift from SKILL.md** (architectural): if the absorbed sequence reorders operations (e.g., gh-compose before cp), downstream consumers may read inconsistent state. **Warning signal**: B5-plan-green's ordered-invoke-log assertion fails (FINDING_47). **Mitigation**: function body order matches current SKILL.md L645–810 byte-for-byte (snapshot → token/timing → cp → gh → workflow-path → persist → dirty → slug+branch → git-current-branch → plan-log → plan-review-tally → larch:plan-summary). B5-plan-green asserts the ordered invoke-log sequence; reordering fails the harness.

2. **F7 guard regression** (systemic): if the new permissive `should_run_phase_plan_materialize` predicate accidentally allows phase entry on hard bails, existing `B2-plan` / `B4-plan` tests fail and start asserting Phase 3 bail reasons overwriting `adopted-issue-closed`. **Warning signal**: B2-plan/B4-plan assertions newly added in this PR (`assert_not_contains "IMPLEMENT_BAIL_REASON=run-flags-persist-failed"` etc.) fail. **Mitigation**: keep the predicate's hard-bail conditions identical to `should_run_post_tracking_phase`'s; only the `DEFERRED` check is relaxed. `phase_coder_select` continues to use `should_run_post_tracking_phase` unchanged.

3. **Slug pipeline drift** (correctness): if the `tr | sed | cut` pipeline drifts even one character from current SKILL.md, branch names change for downstream consumers. **Warning signal**: B5-plan-green's three iter slug-assertions fail (uppercase, special chars, 40+ chars), and the invoke-log asserts the exact `create-branch --branch <expected>` string. **Mitigation**: copy-paste the pipeline byte-identically from SKILL.md L757–761; B5-plan-green exercises each pipeline component (`tr lower`, `tr -c`, `sed --*`/`^-`/`-$`, `cut -c1-40`, trailing `sed -*$`) via the three parameterized titles.
