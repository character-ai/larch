The plan updates `skills/shared/design-background-wait.md` and `AGENTS.md` but not the inline `/design` skill contract. Anti-pattern #5 and the Step 3 routing table still describe only empty-output / prefix-identical / probe ordering, with no post-notification `Read` of `tasks/*.output` and no `STEP3_REVIEW_KEEPALIVE=waiting` handling. The orchestrator treats `skills/design/SKILL.md` as authoritative; without aligned edits, Fix A and Fix C docs will not bind Step 3 behavior.

**2. [risk-integration] Missing `skills/shared/orchestrator-never.md` update (line 9)**

NEVER #3 still forbids reading task outputs before notification and does not document the Fix A carve-out after notification. The hook cannot enforce “read only after notification,” so this file is the cross-skill enforcement layer. Omitting it leaves a documentation gap on the primary recovery path the bug report describes.

**3. [correctness] Keepalive teardown must survive the trap swap at `design-step3-review.sh:634`**

The plan correctly says to stop keepalive after `wait` and in cleanup, but the success path swaps the EXIT trap at line 634 before `normalize-status`. Cleanup will not run on normal completion. Implementation must call a shared stop helper inline between `wait` (line 617) and trap replacement (line 634), not rely on `_step3_review_cleanup` alone.

**4. [correctness] Keepalive scope limited to primary launch path (`design-step3-review.sh:609-617` vs reattach `479-528`)**

Keepalive is only specified after `_loop_pid=$!` on the main Python launch path. Reattach/detach flows use different wait semantics and can still leave wrapper stdout silent for long periods. Fix A covers deadlock there, but Fix C’s upstream notification mitigation may not apply on those paths unless explicitly scoped in the plan.
