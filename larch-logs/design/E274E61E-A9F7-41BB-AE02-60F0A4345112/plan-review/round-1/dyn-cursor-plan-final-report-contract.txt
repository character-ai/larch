## Findings

### 1. **correctness** — `python/larch/report/final_report.py:533-587`

Manifest-only stalled reconciliation updates the heading but **deletes** the Outcome line (`del lines[outcome_idx]` at 584) instead of writing `- **Outcome**: DONE` for recovered success outcomes like `merged`. That conflicts with the issue requirement that success summaries always lead with Outcome `DONE`.

The plan only broadens `_summary_stalled_outcome_index` matching; it does not change rewrite semantics. Existing tests (`python/tests/report/test_run_logs.py:1054-1056`, `1081-1084`) check that lowercase `stalled` is gone, not that `DONE` appears.

**Suggested revision:** Replace the bullet with `_map_outcome_display(recovered_outcome)` rather than deleting it, and assert `- **Outcome**: DONE` in reconciliation success tests (including the new `STALLED` input case).

### 2. **correctness** — `python/larch/design/design_summary.py:644-648`

`/design` primary rendering goes through `invoke_render` → `render run-summary` → `pr_body.render_run_summary`, which the plan updates. The **degraded fallback** path still writes raw `- **Outcome**: {outcome}` when the main renderer fails. That path can emit `approved` or `stalled` instead of `DONE` or `STALLED`.

The plan’s file list does not include `design_summary.py`.

**Suggested revision:** Add `### UPDATED: python/larch/design/design_summary.py` and route the fallback Outcome line through the same display mapper.

### 3. **risk-integration** — `python/larch/report/final_report.py:586-587`

The reconciliation failure guard only checks for leftover `- **Outcome**: stalled`. Once new summaries emit `STALLED`, a partial rewrite that leaves the display bullet unchanged would not trip this guard.

**Suggested revision:** Reject any remaining stalled outcome bullet using the same matcher used for detection (or an explicit `stalled|STALLED` alternation).
