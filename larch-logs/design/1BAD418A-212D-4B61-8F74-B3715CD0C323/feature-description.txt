# auto-error-reporting: always file failure reports in the upstream larch repo (cross-repo filing + signature dedup)

Part 2 of 3 of the auto-error-reporting rework. Part 1: #3988 (content, timing, root-cause, and escalation-event rework of /implement failure reporting). Part 3: #3992 (/design port, chained behind this issue).

#### Context

After #3988, terminal-failure and escalation reports are composed in two tiers: Tier A (full info, larch dev clones) and Tier B (larch-operational fields only; consumer and forked repos). Filing mechanics are unchanged by #3988: dev clones file via `/larch:issue` in the current repo, while consumer repos only print an "Action required" report in chat. This part makes every report land as an issue in the upstream larch repo, regardless of which repo the skill ran in.

#### Requirements

1. **Always file in the upstream larch repo.** Consumer and `--forked` runs file their Tier B report cross-repo. Larch dev clones keep filing in the current repo (which is larch). `is-larch-dev-clone` keeps selecting the content tier only, never whether to file.
2. **Canonical larch repo resolution** is a design decision: resolve from plugin/marketplace metadata vs a pinned constant. Document the choice and its failure mode.
3. **Filing path** is a design decision: extend `/larch:issue` with a cross-repo target (its dedup and dependency analysis currently read the current repo), or add a thinner direct `gh issue create -R` path reserved for failure reports.
4. **Signature dedup pre-pass.** Before filing, exact-match the `larch-stall:signature` marker against open larch-repo issues. On match, comment "+1 occurrence" with the new attempt table, escalation ledger, and root-cause finding instead of filing a duplicate. This becomes load-bearing once consumer fleets can file: one larch regression must not produce N identical issues.
5. **Filing-failure fallback.** When cross-repo filing fails (auth, network), print the composed report in chat for manual filing (today's consumer behavior).
6. **Docs and SECURITY.md.** Document that consumer runs file under the consumer's GitHub identity on the public larch repo, and that Tier B content rules are the safety boundary for that path.

#### Dependencies

Blocked by #3988: Tier B composition must exist before cross-repo publication is safe.
