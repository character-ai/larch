# [OOS] Runtime bug + test-coverage gaps: scout, Step 2 dispatch, ship-pr — 5 items

Combined from #4206, #4207, #4173, #4161, #4159 by `/combine-issues --oos`. Two runtime bugs plus three test-coverage gaps in the dynamic scout, Step 2 dispatch, and ship-pr paths.

### Item 1 — [BUG] plan_scout.py: scout_dynamic_archetypes does not clear .raw.cap-hit before each tier
- **Location**: `python/plan_scout.py:455-506` (guard at `python/plan_scout.py:344-346`)
- **Source**: #4206
- **Description**: `scout_dynamic_archetypes` does not unlink `Path(str(raw) + ".cap-hit")` before launching each tier. `_raw_is_scout_json()` rejects any raw file with a `.cap-hit` sibling. If Cursor hits a cap the `.cap-hit` marker remains; Claude can then write valid JSON to the same `.raw`, but the code still falls through to write an empty manifest with `SCOUT_STATUS=empty`. Fix: unlink `Path(str(raw) + ".cap-hit")` before launching Cursor and before launching Claude, matching the deleted shell helper's per-tier cleanup.

### Item 2 — [COVERAGE] python/test_plan_scout.py: missing E2E cases for diff-mode dynamic scout
- **Location**: `python/test_plan_scout.py`, `python/test_rendering.py`
- **Source**: #4207
- **Description**: The new pytest does not replace several important cases from the deleted 873-line `scripts/test-scout-dynamic-archetypes.sh` harness. Missing: diff-mode happy path with `--read-tools` assertions; fenced JSON salvage through `scout_dynamic_archetypes`; over-cap (max_archetypes=0) with Claude fallback paths. Also missing: plan-listed scope-anchor boundary cases in `python/test_rendering.py` — symlink rejection, zero-byte rejection, >65536-byte rejection, and CR/LF-in-path rejection against `_scope_anchor_common_shape_ok` guards.

### Item 3 — [COVERAGE] Cursor same-path scout normalization untested in Step 2 harness
- **Location**: `skills/implement/scripts/test-step2-dispatch.sh`
- **Source**: #4173
- **Description**: Test 13a covers only the Codex path where `LAUNCH_SCOUT_MANIFEST_PATH != SCOUT_CODER_MANIFEST`. The Cursor same-path case (input and output both `$TMPDIR/scout-coder-manifest.json`) has no dispatcher-level test. Suggested fix: add a Cursor-stub variant to Test 13a that writes the sidecar to `$TMPDIR/scout-coder-manifest.json` and asserts filtered output at the same path plus `no_wrapper_stdout_lines`.

### Item 4 — [BUG] Bash ship-pr.sh still defaults missing LAUNCHER_EXIT to 0 on non-zero wrapper exit
- **Location**: `scripts/ship-pr.sh` (~lines 2493-2494, 1720-1721, 2876-2877)
- **Source**: #4161
- **Description**: Bash CI/conflict launcher paths default a missing `LAUNCHER_EXIT` KV line to `0` via `${launcher_exit:-0}` even when the launcher wrapper exits non-zero without emitting that line. Python paths now fail closed through `agents.resolve_launcher_exit`. When `LARCH_SHIP_PR_IMPL=bash`, mirror `resolve_launcher_exit` semantics: prefer `.done` sidecar, then parsed stdout, then `max(wrapper_rc, 1)` on non-zero exit without valid LAUNCHER_EXIT.

### Item 5 — [COVERAGE] ship-pr runtime tests skip run_checks_with_lint_fix_loop wrapper path
- **Location**: `scripts/test-ship-pr-rebase.sh`
- **Source**: #4159
- **Description**: New runtime lint-handoff tests source `ship-pr.sh` and exercise `run_captured_cmd_then_fix_loop` plus `_rcc_handle_fix_status` but duplicate the ledger handoff block inline instead of calling `run_checks_with_lint_fix_loop`; a regression that removes or reorders the handoff in that wrapper could still pass. Suggested fix: add a test case that stubs only `run_lint_fix_loop_capture` / `failure_capture_path` and drives `run_checks_with_lint_fix_loop` end-to-end, asserting all `SHIP_PR_LEDGER_*` KV fields after the wrapper returns `main-agent-required`.
