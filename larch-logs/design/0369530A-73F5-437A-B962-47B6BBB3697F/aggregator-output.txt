### FINDING_1: ship-pr plan omits per-site `ship_pr_resolve_launcher_exit` contracts for CI-fix and conflict paths
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation, Cursor-Requirements
- **Severity**: important
- **Concern**: The plan documents an explicit `ship_pr_resolve_launcher_exit` invocation only for the recovery waterfall (~2493). CI-fix (~1720) and conflict-resolution (~2876) still use `fail_file` plus `tier_out`/`conflict_out` with `2>&1` capture (not `launcher_stdout`/`output`), and may keep `${launcher_exit:-0}`. Python launchers write `${output}.done` beside `tier_out`/`conflict_out` while stdout goes to `fail_file`. An implementer can fix only the documented recovery call, pass wrong output bindings, or leave defaults in place, so `LARCH_SHIP_PR_IMPL=bash` can still report false success when `LAUNCHER_EXIT` is missing despite a non-zero wrapper exit.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Add per-site call contracts to the plan: ~1720 ship_pr_resolve_launcher_exit "$fail_file" "$tier_out" "$wrapper_rc"; ~2876 ship_pr_resolve_launcher_exit "$fail_file" "$conflict_out" "$rc"; keep the existing ~2493 shape; require all three replacements and removal of every ${launcher_exit:-0} default at those sites
  - From Cursor-Innovation: Document and implement per-site calls: ship_pr_resolve_launcher_exit "$fail_file" "$tier_out" "$wrapper_rc" at ~1720 and ship_pr_resolve_launcher_exit "$fail_file" "$conflict_out" "$rc" at ~2876; keep the existing recovery-waterfall "$launcher_stdout" "$output" "$tier_rc" call before rm -f
  - From Cursor-Requirements: Spell per-site bindings in the plan: CI-fix ~1720 uses `ship_pr_resolve_launcher_exit "$fail_file" "$tier_out" "$wrapper_rc"`; recovery ~2493 uses `"$launcher_stdout" "$output" "$tier_rc"`; conflict ~2876 uses `"$fail_file" "$conflict_out" "$rc"`.
