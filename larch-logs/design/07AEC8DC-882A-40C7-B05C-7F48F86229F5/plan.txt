# Implementation Plan — Issue #2654

## Summary

Fix `set -e` violation in `step5_parse_checks_capture_file` and
`step5_parse_lint_capture_file` (skills/review-and-fix/scripts/review-implement-step5-loop.sh)
by making `step5_parse_kv_tokens` total (always exit 0). Add wrapper-level
diagnostics that surface malformed capture files clearly: a stderr line for
operator visibility, plus — for the checks wrapper specifically — a
fail-closed global override (`STEP5_CHK_STATUS=fail` /
`STEP5_CHK_FAILURE_REASON=malformed-capture`) so `run_implement_loop` emits a
`stall` envelope instead of silently completing. Add a focused regression
test that sources the loop file and exercises both wrappers under `set -e`,
and wire the new test section into the sharded CI Makefile so the regression
runs under `make lint` / `test-harnesses-*`.

## Approach

The bug has a single root cause (`step5_parse_kv_tokens` returns 1 + bash
`var=$(cmd)` propagates exit codes + `set -e`). Fixing it centrally in the
helper is one line, instead of `|| true` at six call sites. The function
becomes total — there is no longer an "error" mode in the helper, only
"matched" (non-empty stdout) and "not matched" (empty stdout). Callers
already discriminate via `[[ -n "$v" ]]`, so semantics at every call site
are byte-identical to before. The diff is the smallest that achieves the
goal (KARPATHY §2 Simplicity First).

Wrapper-level diagnostics surface malformed capture files in run logs.
Stderr is the visibility channel; the fail-closed STATUS override on the
checks side hardens the loop against silent fall-through past the
`STATUS=fail` branch in `run_implement_loop`. The lint side does not
need a fail-closed override because the existing `case` on
`STEP5_LINT_STATUS` already maps unrecognized (including empty) values to
the `*` default arm, which stalls. Treating the two wrappers symmetrically
would either over-engineer the lint side or under-protect the checks side.

Required-field definition per wrapper (single source of truth — see
test-review-and-fix.sh parser bullets above):
- `step5_parse_checks_capture_file`: at least one of `STATUS`,
  `RELEVANT_CHECKS_OK`, or `RELEVANT_CHECKS_SKIPPED` must be populated.
  All three are real producer discriminators emitted by
  `scripts/run-relevant-checks-captured.sh`. `RELEVANT_CHECKS_SKIPPED=true`
  is the clean envelope in consumer repos lacking `scripts/relevant-checks.sh`;
  treating it as missing would emit spurious diagnostics on every
  legitimate run.
- `step5_parse_lint_capture_file`: `LINT_FIX_STATUS` must be populated.
  Producer emits one of `applied`, `main-agent-required`, `failed`,
  `no-changes`.

CI safety: wiring the new `parsers` section into the sharded Makefile is
load-bearing — `make lint` only runs the section targets, not the full
`test-review-and-fix.sh`. Without `test-review-and-fix-parsers` on a
shard, the regression test could silently stop running.

## Edge cases

- **Empty line in capture file**: already handled by the existing
  `[[ -z "$line" ]] && continue` guards. No change needed.
- **Multiple lines, key on one of them**: existing for-loop sets the
  global on the matching line, leaves it set across subsequent
  non-matching lines (because the inner `[[ -n "$v" ]] && STEP5_CHK_X="$v"`
  only assigns when the helper produced a non-empty value). Unchanged.
- **Multiple lines with same key on more than one**: last occurrence
  wins — same as current behavior. Unchanged.
- **`RELEVANT_CHECKS_SKIPPED=true` capture**: legitimate clean envelope
  from consumer repos without `scripts/relevant-checks.sh`. Treated as
  well-formed (satisfies the three-way discriminator). Wrapper emits
  no stderr; `run_implement_loop` normalizes `STATUS=pass` via the
  existing `if [[ "$STEP5_CHK_RELEVANT_CHECKS_SKIPPED" == "true" ]]`
  branch.
- **`KEY=` with empty value**: the helper now prints empty stdout and
  returns 0 for any tokenization, including `KEY=` with no value. The
  wrapper's `[[ -n "$v" ]] && X="$v"` skips the assignment, the global
  stays empty, and the discriminator gate treats it as if the key was
  absent. This matches the conservative interpretation (an empty value
  is not a valid discriminator) without further code. Test coverage
  for this exact edge is out of scope for this PR.
- **Bash 3.2 portability**: no new constructs (no `mapfile`, no
  associative arrays, no `${var,,}`). Plain `printf >&2`, `[[ -z ... ]]`,
  and direct global assignments.
- **`&&` list under `set -e`**: empirically verified that the existing
  per-iteration `[[ -n "$v" ]] && STEP5_CHK_X="$v"` pattern is exempt
  from `set -e` exit per the bash manual; the post-loop required-field
  check is reached normally after the helper fix.
- **Quiet-mode FD interactions**: the stderr writes do not go through
  the `emit`/`emit_kv` quiet-mode helpers — they are direct
  `printf >&2` so they show up in run logs whether or not quiet mode
  is active.

## Failure modes

1. **Future caller adds a key not in the current set with a typo**. With
   the helper always returning 0, a typo (e.g.
   `step5_parse_kv_tokens "$line" RELEVENT_CHECKS_OK`) would never get a
   non-zero exit. Mitigation: the wrapper-level required-field check
   surfaces malformed reads at the wrapper boundary — a typo would
   manifest as "required field missing" stderr at the wrapper that
   owns it. The parsers regression test pins the contract for both
   wrappers.

2. **Wrapper stderr line gets line-wrapped or rate-limited by a future
   logging layer**. The line is intentionally single-line and short.
   Mitigation: regression test asserts on the literal substring
   `required field missing`, which is the load-bearing diagnostic
   token.

3. **Producer evolution breaks the discriminator contract**.
   `scripts/run-relevant-checks-captured.sh` currently emits one of
   `STATUS`, `RELEVANT_CHECKS_OK`, or `RELEVANT_CHECKS_SKIPPED` on
   every success path; `scripts/lint-fix-loop.sh` emits `LINT_FIX_STATUS`
   from its four-value enum. If a future producer change introduces a
   new discriminator field on the success path without updating the
   wrapper, the wrapper would emit `required field missing` on
   legitimate captures. Mitigation: the wrapper-level diagnostic is
   stderr-only on the lint side (no behavior change) and fail-closed
   on the checks side (stall envelope — but with a clear reason
   `relevant-checks-malformed-capture` operators can root-cause).
   Test coverage in `test-review-and-fix-parsers` would catch the
   contract break in CI when the producer adds a new discriminator
   without updating the wrapper.
