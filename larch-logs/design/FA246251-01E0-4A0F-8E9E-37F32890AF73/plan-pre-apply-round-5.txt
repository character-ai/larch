## Plan

## Approach

- Add `design-step3-mav.sh` with two phases:
  - `--phase pre`: source the design env, run the canonical pause gate before MAV work, read Step 3 result state through the standardized safe result-env reader, preserve and render the redacted scope anchor when present, and emit trusted wrapper KVs in a machine-only section.
  - `--phase post`: source the design env, run the canonical pause gate before MAV work, snapshot loop mode, artifact round, resume round, and anchor before re-tally or persistence, run the canonical MainAgent re-tally, persist result envs, append the 0-judge warning, record deferred timing, route the round phase only on successful re-tally in loop mode, and emit normalized KVs.
- Use the same pause contract as existing design wrappers:
  - after `design_source_env_optional`, require `DESIGN_TMPDIR`.
  - if `$DESIGN_TMPDIR/.pause-requested` exists, `exec "$CLAUDE_PLUGIN_ROOT/scripts/design-pause-save.sh" --design-tmpdir "$DESIGN_TMPDIR" --issue "$ISSUE_NUMBER" ${REPO:+--repo "$REPO"}`.
  - ensure pause receives `ISSUE_NUMBER` and `REPO` from the sourced session env where available.
- Use a standardized Step 3 result-env read contract:
  - parse `.step3-review-result.env` as the primary file through `scripts/read-result-env.sh`.
  - use the same Step 3 allowlist shape as `design-step3-review.sh`, including at least `LOOP_STATUS`, `STEP3_REVIEW_LOOP_STATUS`, `FINAL_ROUND_NUM`, `STEP3_REVIEW_ROUND_NUM`, `ROUND_NUM`, `ROUNDS_COMPLETED`, `TALLY_PLAN_REVIEW_STATUS`, `ACCEPTED_COUNT`, and `SCOPE_ANCHOR_FILE`.
  - parse `.step3-plan-review-result.env` only as a secondary source for keys absent from the primary parse, or as the safe fallback when the primary path is missing, symlinked, or non-regular.
  - do not unsafe-source either result env.
  - use sourced session env only for MAV values missing from both parsed result env files.
- Keep the judgment step in prose:
  - The LLM reads the pre-phase evidence and ballot as untrusted data.
  - The LLM writes `$DESIGN_TMPDIR/voter-main-agent.txt`.
- Keep Step 3 resume semantics unchanged:
  - Loop mode resumes through `design-step3-review.sh --starting-round "$STEP3_RESUME_ROUND"` after successful MAV post.
  - Legacy single-mode still maps re-tally success to the existing Gate B path.
  - Handled MAV `tally-error` routes by post-phase `TALLY_PLAN_REVIEW_STATUS=tally-error`, not by `LOOP_STATUS`.
  - Handled MAV `tally-error` explicitly runs `design-step3-gate-b-bypass.sh`, skips the resume fence and legacy Gate B, and routes to Step 3b.
- Do not change `persist-retally-step3-env.sh`, `tally-plan-review.sh`, `record-plan-review-round-timing.sh`, or `design-pause-save.sh`.

## Edge cases

- **Pause requested**: wrapper sources env, validates `DESIGN_TMPDIR`, then execs the canonical pause-save command before any MAV phase work.
- **Pause context missing**: wrapper emits a clear usage-style failure if pause is requested and `ISSUE_NUMBER` is missing.
- **Pause repo context**: wrapper passes `--repo "$REPO"` when sourced env provides it and otherwise follows the existing pause-save behavior.
- **Primary result env diverges from secondary**: primary `.step3-review-result.env` wins for shared keys.
- **Primary result env missing key**: secondary `.step3-plan-review-result.env` may fill that key.
- **Both result envs missing key**: sourced session env may fill only that absent key.
- **Primary result env symlinked or non-regular**: `read-result-env.sh` refuses the primary and uses the safe fallback path when available.
- **File-first anchor**: pre writes the `SCOPE_ANCHOR_FILE` value resolved from result envs before using any session fallback.
- **Anchor missing or unreadable**: pre phase emits the ballot path in the trusted KV section and no rendered anchor block. It does not inline raw bytes.
- **Anchor contains KV-looking text**: pre phase prefixes evidence lines, so `BALLOT_PATH=/tmp/evil` cannot be parsed as a trusted wrapper KV.
- **Anchor outside tmpdir or symlinked**: renderer rejects it. The wrapper surfaces the failure. SKILL.md aborts before ballot read.
- **Quiet stream**: pre phase keeps rendered scope evidence visible through stdout or the visible `emit` stream.
- **Pre failure**: SKILL.md aborts the MAV branch before ballot read, voter write, post, resume, or Gate B.
- **Post-persist env rewrite**: post uses snapshotted loop mode and resume round from phase entry, so `persist-retally-step3-env.sh` cannot erase routing context.
- **Round number missing**: post phase emits a clear usage-style error before running tally, because artifact paths cannot be canonical.
- **Missing resume binding in loop mode**: post phase exits 2 before phase routing.
- **Post usage failure**: SKILL.md aborts before the resume fence or Gate B.
- **Missing or unreadable voter file**: post phase routes handled `tally-error`, persists cleanup, and exits 0.
- **Readable malformed voter file**: post phase preserves current tally behavior.
- **Tally error**: post phase persists `tally-error`, omits stale scope anchor, emits `TALLY_PLAN_REVIEW_STATUS=tally-error`, emits `LOOP_STATUS=complete`, and exits 0 for prompt routing.
- **Tally-error Step 3 route**: SKILL.md runs `design-step3-gate-b-bypass.sh`, skips resume, skips legacy Gate B, and routes to Step 3b.
- **Tally-error phase rollback**: post phase does not recreate `.step3-round-N.phase`.
- **Zero accepted in loop mode**: post phase promotes only successful loop-mode MAV to `awaiting-continuation` using the pre-persist snapshot.
- **Zero accepted in legacy single mode**: post phase does not create a phase file and emits `PHASE=unchanged`.
- **Accepted findings exist**: post phase leaves the loop’s existing `awaiting-apply` phase unchanged.
- **Timing failure**: post phase prints a warning and continues.
- **Retry**: warning append is idempotent per snapshotted artifact round.

## Failure modes

- If the wrapper checks `.pause-requested` without execing `design-pause-save.sh`, resume state can be corrupted. The harness should require the canonical pause command.
- If the wrapper checks pause before sourcing the session env, `ISSUE_NUMBER` and `REPO` can be missing or stale. The harness should require source-before-pause ordering.
- If the wrapper unsafe-sources Step 3 result envs, untrusted or malformed values can affect wrapper routing. The wrapper must use `read-result-env.sh`.
- If `.step3-review-result.env` and `.step3-plan-review-result.env` diverge and secondary wins, MAV can use the wrong anchor or loop state. The harness should require primary precedence.
- If `SCOPE_ANCHOR_FILE` comes from stale session env while file state has a current value, `.step3-mav-retally-anchor` and `--retally-input-anchor` can diverge. The harness should require file-first anchor resolution.
- If post reads loop mode or resume round after `persist-retally-step3-env.sh`, it can lose `STEP3_REVIEW_LOOP_STATUS` or `FINAL_ROUND_NUM`. The harness should require pre-persist snapshots.
- If `voter-main-agent.txt` is missing or unreadable, tally returns or wrapper synthesizes handled `tally-error`; the wrapper must not partially hand-write artifacts.
- If SKILL.md keys handled MAV errors only from `LOOP_STATUS=tally-error`, it can incorrectly resume or enter Gate B because post emits `LOOP_STATUS=complete`. The harness should cover the `TALLY_PLAN_REVIEW_STATUS=tally-error` branch.
- If SKILL.md ignores pre or post non-zero exits, it can vote without trusted ballot KVs or resume after usage failure. The harness should cover both gates.
- If phase routing writes the wrong round, resume can re-enter the wrong loop phase. The harness should cover `ROUND_NUM` versus `ROUNDS_COMPLETED` precedence.
- If loop-mode detection uses only `LOOP_STATUS=main-agent-vote-required`, legacy single mode can get an invalid phase file. The harness should cover absent `STEP3_REVIEW_LOOP_STATUS`.
- If post passes the sidecar path instead of the sidecar’s anchor-path value, later retries can render path text as scope evidence. The harness should cover this.
- If SKILL.md still contains direct MAV commands, future prompt-side drift can reappear. The harness should grep for those strings.
- If the new harness is omitted from `test-harnesses-7`, `make lint` can miss MAV regressions. The Makefile change must wire the aggregate shard.
