Reviewing the codebase to align the revised plan with existing paths and patterns.
## Plan

## Goal

Prevent `/implement` from declaring success when firm plan work remains undone.

Use the existing Step 2 untouched-firm-heading probe as the source of truth. Add `todos_left` as an independent trigger. Keep the gate mechanical: counts, thresholds, and recorded disposition only.

Coverage and disposition must apply on every implementation path (external complete, main-agent `claude_fallback`, recovery commits, and post-disposition edits). Ship and PR mutation must fail closed when required disposition is missing, stale, or invalidated.

## Approach

1. Add threshold constants in `python/larch/core/config.py`.

   - Middle band: untouched firm headings >= 20% of firm headings OR >= 10 headings.
   - High band: untouched firm headings >= 50% of firm headings OR >= 30 headings.
   - Add comments with the incident rationale.
   - Keep `### MAY_UPDATE:` excluded.

2. Add a scope-disposition Python module.

   - Define frozen dataclasses for:
     - plan coverage summary
     - disposition requirement
     - recorded disposition
   - Store tmpdir wire files through `larch.io`:
     - `plan-coverage.env`
     - `plan-coverage-untouched.txt`
     - `plan-coverage-todos-left.md`
     - `scope-disposition.env`
     - `scope-disposition.md`
   - Reject embedded newlines in KV values.
   - Redact content before any GitHub or run-log surface.
   - Compute a coverage fingerprint from firm-heading totals, untouched paths, `todos_left` count/text, and band flags.
   - Expose one shared entry point, for example `compute_and_write_coverage(...)`, used by all call sites below.

3. Upgrade Step 2 coverage output on external complete.

   - In `dispatch_step2.py`, replace the advisory-only uncovered count with the shared coverage summary call before emitting `STATUS=complete`.
   - Compute:
     - total firm heading paths
     - touched firm heading paths
     - untouched firm heading paths
     - untouched percent
     - band: `advisory`, `middle`, `high`
     - `todos_left` count and bounded text
   - Persist `plan-coverage.env` and sidecars before emitting `STATUS=complete`.
   - Preserve existing warning KVs for compatibility.
   - Add new KVs only additively, such as:
     - `PLAN_COVERAGE_TOTAL`
     - `PLAN_COVERAGE_TOUCHED`
     - `PLAN_COVERAGE_UNTOUCHED`
     - `PLAN_COVERAGE_UNTOUCHED_PERCENT`
     - `PLAN_COVERAGE_BAND`
     - `PLAN_COVERAGE_DISPOSITION_REQUIRED`
     - `PLAN_COVERAGE_FINGERPRINT`
     - `PLAN_FIDELITY_FORCED`
     - `PLAN_COVERAGE_FILE`
     - `PLAN_COVERAGE_UNTOUCHED_FILE`
     - `TODOS_LEFT_COUNT`
     - `TODOS_LEFT_FILE`
   - Treat non-empty `todos_left` on `STATUS=complete` as `PLAN_COVERAGE_DISPOSITION_REQUIRED=true` even with full file coverage.
   - Do not branch on advisory-only below-middle gaps.

4. Run the same coverage compute on every non-external-complete implementation path.

   - Add a shared launcher fence, for example `implement scope-disposition compute`, invoked from:
     - `dispatch_step2.py` on external `STATUS=complete` (step 3 above)
     - `dispatch_commit_route.py` / `checks-commit-route` after the Step 4 commit leg for `claude_fallback` and recovery commits
     - a post-2.4 fence after `normalize-coder-scout` and recovery-path capture on main-agent paths, before Step 3
   - Inputs:
     - Step 0 materialized `$IMPLEMENT_TMPDIR/plan.txt`
     - actual post-commit touched paths from the working-tree capture used by Step 2 / commit-route
     - `todos_left` from manifest when present; otherwise from main-agent scout/manifest sidecars when available
   - After recovery `scope-check` succeeds, run the same summary against recovered touched paths before continuing.
   - Emit the same additive KVs and write the same artifacts as the external-complete path.
   - On `claude_fallback`, recovery, and self-implement paths, disposition is required under the same middle/high/`todos_left` rules as external complete.

5. Fail closed when coverage cannot be computed reliably.

   - If Step 0 plan read/parse fails, firm-heading extraction fails, or touched-path capture is unavailable on a path that has already committed implementation work:
     - do not treat the gap as advisory-only
     - set `PLAN_COVERAGE_DISPOSITION_REQUIRED=true`
     - write a bounded `plan-coverage.env` with `PLAN_COVERAGE_STATUS=unavailable` and reason
     - block Step 3 continuation until disposition is recorded or the run bails
   - Ship pre-driver and shared ship validation must reject missing, malformed, or `unavailable` coverage artifacts when implementation has already committed.

6. Prompt for disposition in `/implement` Step 2 when required.

   - Update `skills/implement/SKILL.md` after implementation is committed on every path and before Step 3:
     - external complete: after post-dispatch envelope validation
     - `claude_fallback` / recovery / self-implement: after the post-2.4 scope-disposition compute fence
   - If `PLAN_COVERAGE_DISPOSITION_REQUIRED=true` and no valid `scope-disposition.env` exists, ask the operator:
     - `proceed-partial`
     - `bail-rescope`
   - Wait indefinitely.
   - If the platform returns a no-response fallback, re-ask the same prompt. Do not default.
   - Record only after a real answer.
   - After `step2-impl` or any post-disposition implementation edits, rerun scope-disposition compute before Step 3 continuation or before ship.
   - If the new fingerprint differs from the fingerprint recorded in `scope-disposition.env`, invalidate disposition, delete stale `scope-disposition.env`, and require a fresh operator choice.

7. Implement disposition recording with safe follow-up ordering.

   - `proceed-partial`:
     - File the follow-up issue first via `/issue` or `python/cli.py issue create`, including untouched inventory and `todos_left`.
     - Cross-link both issues in comments.
     - Dependency rule: make the current tracking issue blocked by the follow-up issue, or omit a blocking edge until the parent can close. Do not make the deferred follow-up blocked by the still-open parent tracking issue.
     - Use `python/cli.py issue add-blocked-by --client-issue <TRACKING_NUM> --blocker-issue <FOLLOWUP_NUM>` when the native edge is available.
     - Write `scope-disposition.env` and run-log batch only after follow-up issue creation and dependency linking succeed.
     - Record `FOLLOWUP_ISSUE_NUMBER` and URL in the disposition artifact.
   - `bail-rescope`:
     - Record the disposition.
     - Route through Step 12d with a new safe bail reason such as `plan-scope-disposition-bail-rescope`.
   - If follow-up filing or dependency linking fails, do not record `proceed-partial`; keep the run parked or route to stall/tool-failure.
   - Both successful paths write the tmpdir artifact and run-log batch.

8. Hard-gate ship and every PR mutation path.

   - Extract `validate_disposition_for_ship(...)` in `scope_disposition.py`.
   - Call it from:
     - `ship_pre_driver_main` before seed and OOS filing
     - `ship.py` immediately before every `pr.ensure_pr` / PR body refresh path, including pr-create and rebase refresh when `PR_NUMBER` is already set
     - `pr.ensure_pr` before `_push_existing_pr` and `push.push_branch`
   - Validation rules:
     - if high band or non-empty `todos_left` requires disposition and `scope-disposition.env` is missing, invalid, fingerprint-mismatched, or `plan-coverage.env` is missing/invalid/unavailable: refuse
     - emit `NEXT_ACTION=halt-scope-disposition`
     - return non-zero
     - do not seed PR state
     - do not create or update a PR
   - Reserve terminal Tool Failure for artifact tampering or fingerprint mismatch after a valid recorded disposition.
   - When `halt-scope-disposition` occurs because disposition is merely absent while `plan-coverage.env` requires it, route back to the Step 2 disposition sub-step: read artifacts from disk, re-run `AskUserQuestion`, and call the recording CLI. Do not treat missing disposition as terminal failure.
   - Document the recovery branch in `skills/implement/SKILL.md` Step 8 and `skills/implement/references/ship-pr-exit-matrix.md`.

9. Force plan-fidelity finder on middle and high bands across all Step 5 modes.

   - Persist `PLAN_FIDELITY_FORCED=true` when the middle threshold trips.
   - In `review_dispatch_panel.py`, append a dedicated prune-exempt row, for example `plan-fidelity-forced`, using `agents/reviewer-plan-fidelity.md`.
   - Tool selection:
     - prefer Cursor when present
     - otherwise inject an equivalent Codex row from the same agent prompt
     - ensure every tier, including degraded and TRIVIAL codex-only panels, still carries the forced row
   - In `review_prune.py`, exempt the forced row from pruning.
   - Keep the existing additive Cursor/`auto` plan-fidelity lane, but ensure the forced finder exists even when ordinary tier pruning would drop rows.
   - For `--self-review` and `STEP5_REVIEW_STATUS=self-review-required`, extend `skills/implement/references/self-review.md` with a mandatory inline plan-fidelity pass when `plan-coverage.env` sets `PLAN_FIDELITY_FORCED=true`:
     - read full plan plus untouched inventory
     - review deferred scope explicitly before Step 6
   - Pin tests for TRIVIAL, MODERATE, HARD, Cursor-absent, degraded-panel, and self-review branches.

10. Project partial scope into completion surfaces.

    - PR body:
      - For `proceed-partial`, use `Part of #N` instead of `Closes #N`.
      - Add a bounded `## Deferred plan inventory` section with untouched headings, `todos_left`, and follow-up issue.
    - Final summary:
      - Add one line:
        - `- **Plan coverage**: <touched>/<total> firm headings; todos_left: <count>; disposition: <value>; follow-up #<N>`
      - Include bounded `todos_left` detail or an artifact reference when non-empty.
    - Tracking issue rename:
      - Suppress `[DONE]` when disposition is `proceed-partial`.
      - Do not close the tracking issue via closing keyword.
    - Existing success outcomes may remain `DONE` in run summary if the run completed, but the plan-coverage line and `Part of` footer must make partial scope visible.

11. Keep acceptance-gaming closed.

    - Coverage reads the Step 0 materialized plan file, not tests, allowlists, skip files, or implementation-authored acceptance artifacts.
    - Coverage compares firm heading paths to the actual working-tree touched paths captured before dispatcher commit or after the relevant commit-route leg.
    - Do not use manifest `files_touched` as the coverage source, except for displaying coder-declared context if useful.

## Edge cases

- Empty firm-heading list: no gate; keep advisory behavior.
- `todos_left` with non-string entries: count entries, render only safe string forms.
- Plan read failure or git probe failure after implementation commit: fail closed with `PLAN_COVERAGE_STATUS=unavailable` and require disposition or bail.
- Existing PR on resume: update footer from `Closes` to `Part of` if disposition is partial; refuse refresh when required disposition is missing.
- Follow-up issue filing fails: do not record `proceed-partial`; keep the run parked or route to stall.
- Follow-up dependency must not deadlock: tracking issue blocked by follow-up, not the reverse.
- `bail-rescope`: do not create a PR.
- Post-disposition edits change touched paths or `todos_left`: invalidate prior disposition and require a fresh operator choice.
- Repo unavailable or forked dry-run: fail closed for required disposition unless the existing flow cannot publish, then record a local-only disposition and surface it in final summary.
- `halt-scope-disposition` on resume: re-prompt operator from disk artifacts; hard-fail only on tampering or invalid coverage artifacts.

## Failure modes

- **Artifact tampering**: `validate_disposition_for_ship(...)` checks `scope-disposition.env` against current `plan-coverage.env` fingerprint and rejects mismatch with terminal failure.
- **Dropped `todos_left`**: Step 2 and commit-route coverage writes persist `todos_left` into coverage artifacts before sanitizing manifest output.
- **Non-complete path bypass**: shared compute runs on external complete, claude_fallback, recovery, and post-2.4 main-agent commits.
- **Reviewer pruning removes finder**: forced slot carries a prune-exempt marker, uses Codex fallback when Cursor is absent, and has unit coverage.
- **Self-review bypass**: `self-review.md` adds mandatory inline plan-fidelity when `PLAN_FIDELITY_FORCED=true`.
- **Closing keyword leak**: PR creation, update, and refresh all use the same disposition-aware linker and shared ship validation.
- **Silent `[DONE]` rename**: finalize reads the disposition artifact directly and skips done rename on partial scope.
- **Missing recovery routing**: Step 8 and ship exit matrix route absent disposition back to Step 2 instead of terminal tool failure.
