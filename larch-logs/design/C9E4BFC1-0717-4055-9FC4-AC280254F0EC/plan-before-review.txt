## Goal

Prevent `/implement` from declaring success when firm plan work remains undone.

Use the existing Step 2 untouched-firm-heading probe as the source of truth. Add `todos_left` as an independent trigger. Keep the gate mechanical: counts, thresholds, and recorded disposition only.

## Approach

1. Add threshold constants in `python/larch/core/config.py`.

   - Middle band: untouched firm headings >= 20% of firm headings OR >= 10 headings.
   - High band: untouched firm headings >= 50% of firm headings OR >= 30 headings.
   - Add comments with the incident rationale.
   - Keep `### MAY_UPDATE:` excluded.

2. Add a scope-disposition Python module.

   - Define frozen dataclasses for:
     - plan coverage summary
     - disposition requirement
     - recorded disposition
   - Store tmpdir wire files through `larch.io`:
     - `plan-coverage.env`
     - `plan-coverage-untouched.txt`
     - `plan-coverage-todos-left.md`
     - `scope-disposition.env`
     - `scope-disposition.md`
   - Reject embedded newlines in KV values.
   - Redact content before any GitHub or run-log surface.

3. Upgrade Step 2 coverage output.

   - In `dispatch_step2.py`, compute:
     - total firm heading paths
     - touched firm heading paths
     - untouched firm heading paths
     - untouched percent
     - band: `advisory`, `middle`, `high`
     - `todos_left` count and bounded text
   - Persist this before emitting `STATUS=complete`.
   - Preserve existing warning KVs for compatibility.
   - Add new KVs only additively, such as:
     - `PLAN_COVERAGE_TOTAL`
     - `PLAN_COVERAGE_TOUCHED`
     - `PLAN_COVERAGE_UNTOUCHED`
     - `PLAN_COVERAGE_UNTOUCHED_PERCENT`
     - `PLAN_COVERAGE_BAND`
     - `PLAN_COVERAGE_DISPOSITION_REQUIRED`
     - `PLAN_COVERAGE_FILE`
     - `PLAN_COVERAGE_UNTOUCHED_FILE`
     - `TODOS_LEFT_COUNT`
     - `TODOS_LEFT_FILE`
   - Treat non-empty `todos_left` on `STATUS=complete` as `PLAN_COVERAGE_DISPOSITION_REQUIRED=true` even with full file coverage.

4. Prompt for disposition in `/implement` Step 2 when required.

   - Update `skills/implement/SKILL.md` after Step 2 envelope validation and before Step 3.
   - If `PLAN_COVERAGE_DISPOSITION_REQUIRED=true`, ask the operator:
     - `proceed-partial`
     - `bail-rescope`
   - Wait indefinitely.
   - If the platform returns a no-response fallback, re-ask the same prompt. Do not default.
   - Record only after a real answer.

5. Implement disposition recording.

   - `proceed-partial`:
     - Create a follow-up issue with the untouched inventory and `todos_left`.
     - Cross-link the tracking issue.
     - Add a blocked-by relationship so the follow-up is blocked by the current tracking issue, or use the repo’s existing dependency helper if the direct relationship is unavailable.
     - Record `FOLLOWUP_ISSUE_NUMBER` and URL.
   - `bail-rescope`:
     - Record the disposition.
     - Route through Step 12d with a new safe bail reason such as `plan-scope-disposition-bail-rescope`.
   - Both paths write the tmpdir artifact and run-log batch.

6. Hard-gate ship.

   - In `ship pre-driver`, check disposition requirements before seed and OOS filing.
   - If high band or non-empty `todos_left` requires disposition and `scope-disposition.env` is missing or invalid:
     - emit `NEXT_ACTION=halt-scope-disposition`
     - return non-zero
     - do not seed PR state
     - do not create or update a PR
   - Update Step 8 SKILL routing for `halt-scope-disposition` as a Tool Failure unless Step 2 already asked the operator. This keeps resume and manual tampering fail-closed.

7. Force plan-fidelity finder on middle and high bands.

   - Add a durable flag, for example `PLAN_FIDELITY_FORCED=true`, when the middle threshold trips.
   - In Step 5 dispatch, inject `agents/reviewer-plan-fidelity.md` into every round when forced.
   - Exempt this slot from reviewer pruning.
   - Keep the existing additive Cursor/`auto` plan-fidelity lane, but ensure the forced finder exists even when ordinary tier pruning would drop rows.
   - Pin tests for TRIVIAL, MODERATE, and HARD.

8. Project partial scope into completion surfaces.

   - PR body:
     - For `proceed-partial`, use `Part of #N` instead of `Closes #N`.
     - Add a bounded `## Deferred plan inventory` section with untouched headings, `todos_left`, and follow-up issue.
   - Final summary:
     - Add one line:
       - `- **Plan coverage**: <touched>/<total> firm headings; disposition: <value>; follow-up #<N>`
   - Tracking issue rename:
     - Suppress `[DONE]` when disposition is `proceed-partial`.
     - Do not close the tracking issue via closing keyword.
   - Existing success outcomes may remain `DONE` in run summary if the run completed, but the plan-coverage line and `Part of` footer must make partial scope visible.

9. Keep acceptance-gaming closed.

   - Coverage reads the Step 0 materialized plan file, not tests, allowlists, skip files, or implementation-authored acceptance artifacts.
   - Coverage compares firm heading paths to the actual working-tree touched paths captured before dispatcher commit.
   - Do not use manifest `files_touched` as the coverage source, except for displaying coder-declared context if useful.

## Edge cases

- Empty firm-heading list: no gate; keep advisory behavior.
- `todos_left` with non-string entries: count entries, render only safe string forms.
- Plan read failure or git probe failure: keep existing warning-only suppression, because the gate lacks a reliable denominator.
- Existing PR on resume: update footer from `Closes` to `Part of` if disposition is partial.
- Follow-up issue filing fails: do not record `proceed-partial`; keep the run parked or route to stall.
- `bail-rescope`: do not create a PR.
- Repo unavailable or forked dry-run: fail closed for required disposition unless the existing flow cannot publish, then record a local-only disposition and surface it in final summary.

## Failure modes

- **Artifact tampering**: ship pre-driver validates `scope-disposition.env` against current coverage artifact and rejects mismatch.
- **Dropped `todos_left`**: Step 2 writes `todos_left` into the coverage artifact before sanitizing manifest output.
- **Reviewer pruning removes finder**: forced slot carries a prune-exempt marker and has unit coverage.
- **Closing keyword leak**: PR creation and update both use the same disposition-aware linker.
- **Silent `[DONE]` rename**: finalize reads the disposition artifact directly and skips done rename on partial scope.
