## Findings

### 1. [correctness] Review path will not accrue telemetry

The plan targets both `larch-logs/implement/<RUN_ID>/checks-digest-sizes.tsv` and `larch-logs/review/<RUN_ID>/checks-digest-sizes.tsv`, and acceptance requires review accrual. Standalone `/review` runs `checks run-relevant` at Step 3e (`skills/review/SKILL.md` around lines 66–68) before Step 4 establishes `review_log_root` and writes batches (lines 77–79). Implement gets `run-log init` at Step 0 (`python/larch/state/bootstrap.py` around line 652); review does not.

Plan edge cases say to skip when no run-log directory exists or when resolution is ambiguous. During normal review, checks failures at Step 3e therefore skip telemetry every time. Implement-only failures can still accrue after bootstrap.

**Suggested revision:** Minimum-change fix is `[SCOPE-REDUCTION]`: drop review surfaces from this PR and measure implement-only, which matches the issue’s organic-failure source. If review must stay, create or resolve exactly one `larch-logs/review/<RUN_ID>/` before append (counts only), without waiting for Step 4 batch writes.

### 2. [correctness] Skill subdirectory selection is unspecified

`checks_run_relevant.py` validates tmpdir prefixes `claude-implement-` and `claude-review-` (lines 147–148) but has no `larch-logs` logic today. The plan names both implement and review paths without saying how the writer picks the skill segment under `canonical_tmp/larch-logs/`.

Without an explicit rule, a naive glob of `larch-logs/*/*` can mis-attribute rows or skip when multiple children exist.

**Suggested revision:** Map tmpdir basename prefix to `implement` or `review`, then require exactly one non-symlink child directory under that skill path (same uniqueness contract as the plan’s skip rules).

### 3. [latent / security] Stderr on telemetry failure may leak paths

The plan copies `panel-prompt-sizes.tsv` best-effort style. `append_panel_prompt_size` prints `write skipped: {exc}` on failure (`python/larch/report/tokens.py` lines 468–469). A copied handler could put absolute paths on stderr even when the TSV stays count-only.

This does not put log, digest, prompt, or command text into committed TSV or aggregator output. It is a secondary stderr leak, not a committed-report reconstruction path.

**Suggested revision:** Use a bounded, content-free stderr warning for checks-digest telemetry failures.

## Assessment (leak / minimum-change)

**Writer contract:** The plan’s field list (`site`, `attempt`, byte/token counts, `digest_truncated`) matches a content-free design. Existing digest assembly stores redacted `first_error` / `first_location` in the digest file only (`python/larch/implement/checks_run_relevant.py` lines 834–840, 1018–1037), not in the proposed TSV.

**Best-effort:** Skipping on missing/ambiguous run dirs, catching telemetry exceptions without altering `ChecksResult` / `DIGEST_FILE`, and flock-append with skip-on-lock-failure align with the panel pattern (`python/larch/report/tokens.py` lines 380–469).

**Committed reports:** `measure_checks_digest_savings()` as specified scans TSVs, skips symlinks (panel precedent at `python/tests/report/test_tokens.py` lines 1299–1314), and emits aggregates only. Counts alone cannot reconstruct raw failure lines. Commit-time `_scrub_run_tree` (`python/larch/report/run_log_commit.py` lines 159–186) adds a secondary secret scrub on copied trees.

**Minimum-change note:** The non-functional review path adds surface area without delivering acceptance. Implement-only telemetry is sufficient for the issue’s go/no-go measurement and matches where organic checks failures will occur first.
