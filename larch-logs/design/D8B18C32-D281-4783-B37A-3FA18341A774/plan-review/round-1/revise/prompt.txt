# Implementation Plan — #3568: stall-recovery bug-body unparseable by /issue --input-file

## Summary

`/implement` Step 18a first-detection filing pipes the heading-less `bug-body`
output straight into `/larch:issue --input-file`. The generic batch parser
(`skills/issue/scripts/parse-input.sh`) needs a `### <title>` item heading, so it
returns `ITEMS_TOTAL=0` and files nothing — silently.

The repo already ships the fix as a tested subcommand: `stall-recovery-report.sh
issue-input-file` synthesizes the `### [Bug] /implement stall: <class> at <step>`
heading from the classification env plus the `bug-body` output. It is simply
never called from `stall-recovery.md` step 4. The fix wires it in and pins the
wiring so it cannot silently re-break.

## Approach

Fix by reuse, not new code. The only live behavior change is the `stall-recovery.md`
step 4 prose the orchestrator follows; everything else is regression pinning. Two
complementary pins make the fix durable:
- `test-stall-recovery-report.sh` pins the *parser contract* — the generated input
  file is batch-parseable (`ITEMS_TOTAL=1`), the heading-less body is not (`=0`).
- `test-implement-structure.sh` pins the *wiring* — step 4 actually calls
  `issue-input-file`. The parser pin alone would still pass if step 4 reverted to
  `bug-body`, so the wiring pin is what prevents silent recurrence.

## Edge cases

- **Dry-run** (`LARCH_STALL_RECOVERY_DRY_RUN=1`): `issue-input-file` emits
  `DRY_RUN_DECISION=true` like `bug-body`; the compose is a local file write, so
  running it before the dry-run gate is safe and GitHub is still skipped. (test
  case 18 already covers dry-run `issue-input-file`.)
- **Consumer / `--forked` repo**: unchanged — prints the `bug-body` body
  verbatim; the `INPUT_FILE` is unused on that path.
- **Terminal classes / `attempt_count>0`**: step 4 still skipped; gate untouched.
- **Title synthesis**: `issue-input-file` derives the heading from
  `FAILURE_CLASS`/`STALL_STEP` via `safe_class_value`/`safe_step_value`; sanitized
  values keep the heading parser-safe and single-line.

## Failure modes

1. **Prose re-divergence** — a future edit reverts step 4 to `bug-body` +
   `--input-file`. Earliest signal: `test-implement-structure.sh` wiring grep
   fails. Mitigation: that assertion (this plan adds it).
2. **parse-input generic-mode drift** — a change to the `### <title>` heading
   contract silently makes the headed file unparseable again. Earliest signal:
   `test-stall-recovery-report.sh` `ITEMS_TOTAL=1` pin fails. Mitigation: that pin.
3. **issue-input-file output drift** — default output filename or `INPUT_FILE`
   key renamed. Earliest signal: the structure integration block + the new parse
   pin (both reference concrete paths/keys) fail. Mitigation: existing + added
   asserts surface it in CI.

## Testing strategy

- `make test-implement-structure` — new step-4 wiring assertion on

- `bash scripts/relevant-checks.sh` (or `make lint`) — markdownlint on the `.md`

## Defect

`/implement` Step 18a stall-recovery first-detection filing silently no-ops: `stall-recovery-report.sh bug-body` emits a report that starts with an HTML signature comment and `## ...` sections, with **no `### <title>` item heading** — but the procedure (`skills/implement/references/stall-recovery.md` step 4) files it via `/larch:issue --input-file <generated>`, whose generic batch parser requires `### <title>` item boundaries. `parse-input.sh` returns `ITEMS_TOTAL=0` (mode=generic) and the filing creates nothing, so the terminal `bug-comment` step later has no recovery-created issue to target.

Observed on plugin cache 47.0.70 during an `/implement` run for #3462 (ship driver stalled with `outer fix attempts exhausted`; recovery classified `transient-infra` from an evidence-starved `ship-pr-state.sh` — the state split-brain part is addressed by #3462 itself; this parser mismatch is not).

## Suggested fix (either)

1. `stall-recovery-report.sh bug-body` emits a leading `### <one-line sanitized title>` heading so the generated file parses as one batch item; or
2. `stall-recovery.md` step 4 switches the dev-clone filing to single mode: `/larch:issue --body-file <generated> "<explicit title>"`.

A regression pin in `test-stall-recovery-report.sh` asserting the bug-body output parses to `ITEMS_TOTAL=1` under `skills/issue/scripts/parse-input.sh` would close the loop.
