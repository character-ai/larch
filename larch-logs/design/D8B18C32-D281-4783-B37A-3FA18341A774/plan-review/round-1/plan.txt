# Implementation Plan — #3568: stall-recovery bug-body unparseable by /issue --input-file

## Summary

`/implement` Step 18a first-detection filing pipes the heading-less `bug-body`
output straight into `/larch:issue --input-file`. The generic batch parser
(`skills/issue/scripts/parse-input.sh`) needs a `### <title>` item heading, so it
returns `ITEMS_TOTAL=0` and files nothing — silently.

The repo already ships the fix as a tested subcommand: `stall-recovery-report.sh
issue-input-file` synthesizes the `### [Bug] /implement stall: <class> at <step>`
heading from the classification env plus the `bug-body` output. It is simply
never called from `stall-recovery.md` step 4. The fix wires it in and pins the
wiring so it cannot silently re-break.

Three reviewer findings are incorporated: (1) tighten the wiring pin to assert
the specific filename on `--input-file`, not just the `issue-input-file` token;
(2) normalize batch-mode indexed keys (`ISSUE_1_NUMBER`/`ISSUE_1_URL`) to
top-level keys (`ISSUE_NUMBER`/`ISSUE_URL`) in `stall-recovery-issue.env` so
later terminal-failure comment steps can target the recovery issue; (3) tighten
`safe_step_value` in `stall-recovery-report.sh` to reject unsafe trailing bytes
after the first character, and add a regression fixture for an `8a`-prefixed
unsafe value.

## Approach

Fix by reuse, not new code. The only live behavior changes are:
1. The `stall-recovery.md` step 4 prose the orchestrator follows (route through
   `issue-input-file` + normalize batch output keys).
2. The `safe_step_value` tightening in `stall-recovery-report.sh` (closes the
   sanitizer gap before it can propagate to a public issue title).

Everything else is regression pinning. Three complementary pins make the fix
durable:
- `test-stall-recovery-report.sh` pins the *parser contract* — the generated
  input file is batch-parseable (`ITEMS_TOTAL=1`), the heading-less body is not
  (`=0`).
- `test-stall-recovery-report.sh` also pins the *sanitizer contract* — an
  `8a`-prefixed unsafe value is stripped to a safe form.
- `test-implement-structure.sh` pins the *wiring* — step 4 names
  `stall-recovery-issue-input.md` on the `--input-file` line, not just the
  `issue-input-file` token. The parser pin alone would still pass if step 4
  reverted to `bug-body`; the filename-specific wiring pin prevents that.

## Edge cases

- **Dry-run** (`LARCH_STALL_RECOVERY_DRY_RUN=1`): `issue-input-file` emits
  `DRY_RUN_DECISION=true` like `bug-body`; the compose is a local file write, so
  running it before the dry-run gate is safe and GitHub is still skipped. The
  batch-key normalization step is also a local env-file write and runs safely
  before the gate. (Test case 18 already covers dry-run `issue-input-file`.)
- **Consumer / `--forked` repo**: unchanged — prints the `bug-body` body
  verbatim; the `INPUT_FILE` and the normalization step are unused on that path.
- **Terminal classes / `attempt_count>0`**: step 4 still skipped; gate untouched.
- **Title synthesis**: `issue-input-file` derives the heading from
  `FAILURE_CLASS`/`STALL_STEP` via `safe_class_value`/`safe_step_value`; the
  tightened `safe_step_value` keeps the heading parser-safe and single-line for
  all inputs including edge-case suffixed tokens.
- **Dedup path**: `/larch:issue --input-file` returns `ISSUE_1_DUPLICATE_OF_*`
  when dedup fires; the normalization step maps these to top-level keys so
  `bug-comment` can always read `ISSUE_NUMBER`/`ISSUE_URL` from
  `stall-recovery-issue.env`.

## Failure modes

1. **Prose re-divergence** — a future edit reverts step 4 to `bug-body` +
   `--input-file`. Earliest signal: `test-implement-structure.sh` filename
   grep fails (checks for `stall-recovery-issue-input.md` on the `--input-file`
   line). Mitigation: that assertion (this plan adds it).
2. **parse-input generic-mode drift** — a change to the `### <title>` heading
   contract silently makes the headed file unparseable again. Earliest signal:
   `test-stall-recovery-report.sh` `ITEMS_TOTAL=1` pin fails. Mitigation: that
   pin.
3. **issue-input-file output drift** — default output filename or `INPUT_FILE`
   key renamed. Earliest signal: the structure integration block + the new parse
   pin (both reference concrete paths/keys) fail. Mitigation: existing + added
   asserts surface it in CI.
4. **Batch-key normalization omitted** — a future refactor drops the
   `ISSUE_1_NUMBER` → `ISSUE_NUMBER` mapping. Earliest signal: the `bug-comment`
   step fails to find the recovery issue and surfaces a missing-env-key error
   (runtime). Mitigation: the normalization prose is explicit in step 4; a future
   test pin on `stall-recovery-issue.env` content would be stronger but is out
   of scope for this PR.
5. **Sanitizer re-loosened** — `safe_step_value` reverts to a glob. Earliest
   signal: the `8a`-unsafe-value regression fixture in `test-stall-recovery-report.sh`
   fails. Mitigation: that fixture (this plan adds it).
