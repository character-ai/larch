### 1. [correctness] `scripts/design-pause-load.sh` — WI2 loop wiring under `set -euo pipefail`

The plan’s WI2 algorithm (`plan.txt` lines 13–17) correctly chooses NUL-delimited `git ls-tree -z` plus `IFS= read -r -d ''`, which is Bash 3.2-safe per `BASH_AUTHORING.md` §3 and matches established repo usage (`scripts/scrub-log-secrets.sh:185`, `scripts/lint-bash32.sh:120`). The edge-case note at plan line 46 is accurate for path contents.

What the plan omits is how to feed the loop in a script that already runs with `set -euo pipefail`:

```4:4:scripts/design-pause-load.sh
set -euo pipefail
```

Piping `git ls-tree` into `while read` is risky here for two reasons:

1. **Subshell** — a piped `while` body runs in a subshell, so `emit_load_fail` (which `exit 0`s) would not stop the parent loader; the parent could proceed to artifact checks with a partially populated `$restore_tmp`.
2. **`pipefail` + EOF** — the final `read -d ''` returns non-zero at EOF; with `pipefail` the pipeline can fail under `set -e` before `missing-restored-artifact` runs, including when enumeration is empty (the plan’s intended empty-subtree path at lines 17 and 47).

The sibling publisher already avoids this by using process substitution:

```609:609:scripts/design-log-publish.sh
    done < <(find "$completed_root" -type f | LC_ALL=C sort)
```

**Suggested revision:** In WI2, mandate `while … done < <(git -C "$REPO_TOP" ls-tree …)` (not a pipe), per-iteration `if ! git show …; then emit_load_fail snapshot-extract-failed; fi`, and pin prefix stripping as `prefix="larch-logs/design/${RUN_ID}/"` / `rel="${path#"$prefix"}"` with `[[ "$rel" == "$path" ]] && emit_load_fail snapshot-extract-failed` so a prefix mismatch cannot silently recreate `larch-logs/design/…` under `$restore_tmp` instead of the flat staging root that `tar --strip-components=3` produced today (`scripts/design-pause-load.sh:233-234`).
