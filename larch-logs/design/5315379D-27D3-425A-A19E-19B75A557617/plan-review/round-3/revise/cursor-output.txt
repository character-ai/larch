### Edge cases

- `ISSUE_NUMBER` missing or `0`: refresh self-skips and checkpoint still routes `reship`.
- Staged architectural-guidelines files absent: pin helper returns skipped.
- Git `HEAD` or repo root cannot be resolved: pin helper skips or fails best-effort.
- `STALL_TRACKING` values like `true`, `1`, or arbitrary non-empty strings are active.
- Only empty string and exact `false` are inactive for the Step 18 active-stall gate.
- Empty `--stall-tracking-memory` must fall back to env `STALL_TRACKING`, not treat empty as inactive by itself.
- Explicit `--stall-tracking-memory=true|false` must override env regardless of env value.
- Step 18a.5 evidence must not treat generic Tool Failures as escalation evidence.
- Composite stdout may contain summary markers before `NEXT_ACTION=finalize-done`; marker extraction must still use the captured stdout.
- Composite may return non-zero while still emitting `NEXT_ACTION=finalize-done`; orchestrator must parse stdout before treating the fence as a hard stop.
- Finalize may delete `$IMPLEMENT_TMPDIR`; the orchestrator must not Read fallback files afterward.
- After stall recovery with `CLEARED=true`, prompt-side 18a.5 must still run before standalone finalize even though the composite already emitted `NEXT_ACTION=stall-recovery`.
- During active stall recovery (`STALL_RECOVERY_REQUIRED=true` before `CLEARED=true`), prompt-side 18a.5 and standalone finalize must not run.
- Orchestrator must not follow stale Step 18a gate-phase prose if composite `NEXT_ACTION` and `STALL_RECOVERY_REQUIRED` disagree; `NEXT_ACTION` wins for routing.

### Failure modes

- If the composite emits `NEXT_ACTION=stall-recovery`, prompt-side code must not run Step 18a.5 or finalize until stall recovery completes with `CLEARED=true`.
- If memory-layer parsing diverges from `step-18.sh` `run_gate`, composite may spuriously emit `stall-recovery` or miss a real stall before green-path finalize.
- If recovery succeeds with escalation evidence, skipping prompt-side 18a.5 before standalone finalize would miss escalation-success filing.
- If the composite emits `NEXT_ACTION=escalation-filing`, prompt-side code must not finalize before filing finishes.
- If finalize exits non-zero inside the composite, the composite should still have forwarded stdout and emitted `NEXT_ACTION=finalize-done`; the non-zero rc remains visible to the caller and marker extraction still runs from captured stdout.
- If `NEXT_ACTION` is missing from composite stdout, the SKILL should route to Tool Failures instead of guessing.
- If `normalize-outcome` is skipped inside the composite, escalation-filing eligibility is undefined and may file or skip incorrectly.
- If subprocess-via-runner baseline is not regen'd and no ok pragma is added, `make py-lint` fails on new `implement_dispatch.py` subprocess sites.
- If tests disagree on the fence count, trust the parser-observed count from `scripts/test-implement-fence-shape.sh`.
- If `test_cli.py` bumps the affected-registry `checked` count without adding a module to the `affected` set, CI fails on a false registry regression.
