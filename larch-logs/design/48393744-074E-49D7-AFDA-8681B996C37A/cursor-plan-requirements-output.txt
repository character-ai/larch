### Findings

**1. `$BUG_TMPDIR` must be created under `/tmp` (correctness)**  
The plan adds `deny-edit-write.sh` and `Write` for `bug-issue-body.md`, but Step 2 only says “setup `$BUG_TMPDIR`” without mandating a `/tmp` `mktemp`. The hook allows writes only under canonical `/tmp`. A tmpdir under `~/.cache` would block body composition.

**2. Hook path needs `${CLAUDE_PLUGIN_ROOT}` (correctness)**  
The plan specifies `scripts/deny-edit-write.sh`. The only in-repo precedent (`skills/research/SKILL.md`) uses `${CLAUDE_PLUGIN_ROOT}/scripts/deny-edit-write.sh`.

**3. Dedup stdout keys missing from verification spec (correctness)**  
Dedup success is required (approach step 32, edge case line 110, report step 37). `/issue` emits `ISSUE_1_DUPLICATE_OF_URL`, not `ISSUE_1_URL`. The SKILL.md section for step 6 should name those keys so the final URL report works on dedup.

**4. `/issue` invocation must use composed body, not raw description (completeness)**  
The feature requires investigation output in the filed issue. The plan separates investigation (`$ARGUMENTS`) from composition (`bug-issue-body.md`) but does not pin the Skill-tool argv shape. Without an explicit `--body-file` + title contract, an implementer could forward the raw bug text and skip RCA.

**5. [OUT_OF_SCOPE] Bash read-only is prompt-only**  
Investigation forbids repo edits in prose, but only `Write` is hook-gated. Same trade-off as `/research` for `Bash`. Not required for the stated feature.

**6. [OUT_OF_SCOPE] No docs catalog entry**  
Approved surfaces are `skills/bug/SKILL.md` and `test-anti-halt-banners.sh` only. Plugin export does not need README/docs updates for correctness.

### Coverage summary

The plan matches the approved outline well: no `/bug` flags, no `--no-dedup`, inline investigation, structured body for `/design`, `/issue` single mode with sentinel verification, anti-halt sync (`test-anti-halt-banners.sh` + `subskill-invocation.md`), and proportionate lint tests. Gaps are narrow contract pins for tmpdir placement, hook path, dedup stdout parsing, and explicit `/issue` Skill args.
