## Approach

`approach-synthesis.txt` is `NO_SKETCHES`, so draft from direct repo inspection.

Add `/bug` as a small stateful orchestrator:

1. Treat all `$ARGUMENTS` as the bug description.
   - Do not add `/bug` flags.
   - Do not expose or forward `--no-dedup`.
   - Abort on empty or whitespace-only input.

2. Investigate inline.
   - Use `Read`, `Grep`, `Glob`, and safe `Bash` discovery.
   - Do not edit repository files.
   - Do not dispatch external agents.
   - Prefer direct evidence: relevant files, call paths, tests, reproduction clues, and existing issue context when useful.

3. Compose a temp issue body.
   - Use `$BUG_TMPDIR/bug-issue-body.md`.
   - Include: summary, original report, reproduction scenario, expected behavior, observed behavior, root cause analysis, evidence, affected files, suggested fixes, and open questions.
   - If root cause remains uncertain after real investigation, say that plainly and include the strongest evidence and next investigative steps. Do not fabricate.

4. Invoke `/issue` via the Skill tool.
   - Use single mode with `--body-file`.
   - Pass a descriptive title derived from the bug report.
   - Pass `--sentinel-file "$BUG_TMPDIR/issue-completed.sentinel"`.
   - Do not pass `--no-dedup`; keep `/issue` duplicate detection and dependency analysis on.

5. Verify child completion.
   - Parse `/issue` stdout for `ISSUES_CREATED`, `ISSUES_FAILED`, `ISSUES_DEDUPLICATED`, and per-item issue URLs.
   - Run `python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" verify skill-called --sentinel-file "$BUG_TMPDIR/issue-completed.sentinel"`.
   - Treat created and deduplicated outcomes as successful when `ISSUES_FAILED=0` and `VERIFIED=true`.
   - Fail closed on `/issue` failure or `VERIFIED=false`.

6. Cleanup.
   - Remove the bug tmpdir at the end.
   - Report the created or deduplicated issue URL.

## Edge cases

- Empty bug description: abort before creating a tmpdir.
- Description starts with `--`: treat it as prose, not a flag.
- Root cause uncertain: file an honest issue with evidence and open questions rather than inventing certainty.
- `/issue` deduplicates the report: treat as success when the sentinel verifies and `ISSUES_FAILED=0`.
- `/issue` fails after partial work: surface the failure and do not claim an issue was filed.
- Missing `gh` auth or repo detection failure inside `/issue`: let `/issue` report the failure; `/bug` should surface it.
- Write hook denies non-`/tmp` writes: keep all prompt-side `Write` paths under `$BUG_TMPDIR`.

## Failure modes

- **False root cause confidence**: avoid by requiring evidence under `## Evidence` and hedging uncertain causal claims.
- **Silent child halt**: avoid with anti-halt banner, micro-reminder, stdout parsing, and sentinel verification.
- **Lint drift**: avoid by syncing `scripts/test-anti-halt-banners.sh` with `skills/shared/subskill-invocation.md`.
- **Issue body too vague for `/design`**: avoid with the fixed body template and affected-files section.
