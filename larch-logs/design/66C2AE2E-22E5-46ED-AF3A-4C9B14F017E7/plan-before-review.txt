## Edge cases

- Treat missing target files as assertion failures, not collection errors with incomplete context.
- Preserve literal and regex semantics from each Bash `grep` invocation. Do not accidentally convert fixed-string pins into regex pins.
- Count non-overlapping occurrences consistently and define empty-needle behavior as invalid configuration.
- For ordered checks, report whether the first anchor was missing, the second anchor was missing, or the order was reversed.
- For same-line checks, require all tokens on one physical line.
- For bounded cross-file checks, report both target files, the anchor, the required token, and the bound.
- Preserve checks for files that must not exist.
- Preserve exact proximity windows used by the implement harness.
- Keep named tests included in their skill’s focused Make selection.
- Avoid parameter IDs that collide after punctuation normalization.
- Do not let retired full-path literals survive in fixtures, comments, generated guidance, or docs.

## Failure modes

- A broad parameterization may weaken a specialized assertion. Keep such assertions as named tests.
- Focused Make selection may omit named tests. Add a collection-level assertion or explicit selection pattern that proves each skill target includes all of its cases.
- Updating only executable references will leave prose references that fail `lint-retired-scripts`.
- Adding pytest tests without matching IDs can make legacy assertion parity unauditable.
- Removing agent-lint exclusions before all stale comments are updated can produce confusing dead-reference findings.
- Fixture wording edits can alter plan-fidelity expectations. Run the owning calibration tests after each fixture update.
- The design classifier test executes Bash against temporary state. Keep it isolated and fail with captured output.
