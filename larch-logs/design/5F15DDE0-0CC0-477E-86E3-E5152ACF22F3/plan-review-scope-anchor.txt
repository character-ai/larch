## Proposed Design Outline

### Goals
- Print summary table (outcome, cost, key fields) last in `/design` and `/implement` final reports.
- Ensure review phase detail (Gantt chart, timing rows) appears before the summary table.
- Keep existing section content intact; only order changes.

### Non-goals
- No changes to the content or formatting of any section.
- No changes to failure/degraded-fallback rendering paths.
- No new configuration or flags for ordering preference.

### Approach sketch
- In `final_report.py` (`write_final_report`): compute `render_implement_review_detail` first, build body as review-detail → issue detail → arch knowledge → summary table (appended last).
- In `design_summary.py` (`_write_enriched_post_publish_summary`): read existing summary from `out_file`, build pre-summary body (review detail, issue detail), append summary last.
- Handle empty-body edge case: strip leading newlines from prefix sections before appending summary.
- Update one test in each test file to assert the new ordering (review detail precedes run-summary marker).
