## Approach

Create a standalone pre-`/design` skill. It will fetch untrusted issue content, inspect bounded primary evidence, run safe probes, compare related issues, and choose a verdict.

Keep model-led investigation in `skills/triage/SKILL.md`. Put deterministic GitHub mutation and verification behind a typed Python CLI helper. Use the existing untrusted-content, redaction, authorization, title-prefix, and blocked-by machinery.

Treat `--report-only` as a hard no-mutation path. Never edit repository files or author a `/design` plan.

## Edge cases

- The issue changes between fetch and apply.
- The issue is closed, deleted, transferred, or is a pull request.
- `--repo` points outside the current checkout, so local code cannot verify that repository.
- Cited logs exist only on an unmerged branch, are missing, truncated, or were never flushed.
- A cited line moved while its symbol still exists.
- Multiple plausible duplicates exist without one canonical match.
- A dependency is plausible but not near-certain.
- The body already matches the proposed rewrite or a prior triage comment exists.
- A lifecycle prefix is absent, repeated, or mixed with a bug prefix.
- The canonical duplicate equals the triaged issue.
- Redaction changes the proposed content.
- A GitHub mutation succeeds but its read-back does not confirm the postcondition.

## Failure modes

- Fail before mutation when validation, authorization, snapshot freshness, redaction, or security checks fail.
- Stop the mutation sequence after any failed command or failed read-back.
- Preserve the scratch directory for actionable mutation diagnostics, but disarm the Write hook.
- Do not claim design readiness when evidence is insufficient or a valid body rewrite cannot be verified.
- Do not close an issue when the verification comment, title restoration, or canonical duplicate check fails.
- Report missing evidence and residual uncertainty without inventing a root cause.
