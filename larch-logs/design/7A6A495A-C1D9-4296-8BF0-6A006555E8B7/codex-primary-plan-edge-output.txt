1. [correctness] `skills/design/scripts/decompose-file-issues.sh:97-104`  
Concern: the proposed `m_anchor` / `findall` block has no guard for `blocked-by` lines that contain zero valid `Piece N` tokens.  
Scenario: `- Dependencies: blocked-by Pieces 1, 2, 3` is explicitly called out in the plan as silently producing zero edges. That is a silent dependency drop, not a safe strict-grammar failure.  
Suggested revision: keep the “no plural support” decision, but reject it. If `m_anchor` is present and `blockers` is empty, emit a non-ok status and exit before writing `partition-input.txt` or `partition-deps.tsv`.

2. [risk-integration] `skills/design/scripts/decompose-prompts/_common-tail.txt:25-28`; `skills/design/scripts/decompose-aggregator.sh:93-96`  
Concern: the parser contract is widened, but both producer schemas still tell reviewers/aggregator to emit only `none | blocked-by Piece N`.  
Scenario: external proposals that need multiple blockers are still guided toward an underspecified singular field, while the helper docs say comma/and-separated repeated `Piece N` tokens are valid. This increases inconsistent output and makes future failures harder to classify.  
Suggested revision: update both prompt schemas to something like `none | blocked-by Piece N[, Piece M...]`, with one sentence requiring each blocker number to be preceded by `Piece` and forbidding `Pieces 1, 2, 3`.
