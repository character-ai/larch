m_anchor = re.search(r"blocked-by\b(.*)$", dep, re.I)
if m_anchor:
    segments = re.split(r",|\s+and\b", m_anchor.group(1), flags=re.I)
    blockers = []
    for seg in segments:
        seg = seg.strip()
        if not seg:
            continue
        m_seg = re.match(r"^Piece\s+(\d+)$", seg, re.I)
        if not m_seg:
            print("DECOMPOSE_PARTITION_STATUS=bad-dependency-ref", flush=True)
            sys.exit(2)
        blockers.append(int(m_seg.group(1)))
    if not blockers:
        print("DECOMPOSE_PARTITION_STATUS=bad-dependency-ref", flush=True)
        sys.exit(2)
    seen = set()
    for blocker in blockers:
        if blocker in seen:
            continue
        seen.add(blocker)
        if blocker not in index_by_num:
            print("DECOMPOSE_PARTITION_STATUS=bad-dependency-ref", flush=True)
            sys.exit(2)
        bi = index_by_num[blocker]
        edges.append((bi, i))

### UPDATED: `skills/design/scripts/decompose-file-issues.md`

Insert a short `**Edge-extraction rules**` paragraph immediately after the existing `**Purpose**` paragraph and before `**Primary caller**`. Suggested wording (~4 lines):

> **Edge-extraction rules**: `- Dependencies: blocked-by Piece N` lines emit one TSV edge per comma- or `and`-separated `Piece N` token (e.g., `blocked-by Piece 1, Piece 2, Piece 3` emits three edges; `blocked-by Piece 1 and Piece 2` emits two). Duplicate blocker numbers within a single line are deduped to one edge. The producer grammar is strict: any non-`Piece N` segment (incidental prose, the deferred plural shape `Pieces 1, 2, 3`, or an unknown blocker number) aborts the run with `DECOMPOSE_PARTITION_STATUS=bad-dependency-ref` exit 2 and emits no `partition-input.txt` / `partition-deps.tsv`.

## Approach

The bug is a single-match `re.search` on a multi-blocker dependency line. Replace it with a two-step parse: anchor on `blocked-by`, split the remainder on comma or `and`, then require each segment to match `^Piece\s+(\d+)$` exactly. This avoids the false-positive failure mode where prose-incidental `Piece N` mentions in the remainder (e.g., `blocked-by Piece 1 (see also Piece 2)`) would create spurious edges if the regex scanned the full tail with `findall`.

Per-blocker emit: append one `(blocker_index, current_piece_index)` tuple per accepted blocker, preserving the existing edge-append shape so downstream cycle detection / `indeg` accounting / TSV serialization are untouched.

Idempotency: dedupe blockers within a single dependency line via a `seen` set so `blocked-by Piece 1, Piece 1` emits a single edge. The set is rebuilt per piece, so duplicate edges across pieces are not affected by this dedupe.

Strict-reference rule, three sources of failure (all aborting with the same `DECOMPOSE_PARTITION_STATUS=bad-dependency-ref` exit 2):
1. Unknown blocker number (preserves the original strict-reference rule, now across all blockers in the list, not just the first).
2. Non-`Piece N` segment after splitting on `,` / `and` (e.g., narrative prose, the deferred plural `Pieces 1, 2, 3` shape).
3. Empty blocker list after segment parsing (catches the case where the anchor matched but no segment yielded a valid blocker — silently zero edges from a clearly intended `blocked-by` line is silent data corruption, exactly the failure class the original bug exposed).

Producer-schema parity: update `_common-tail.txt` and `decompose-aggregator.sh` so the prompts that TEACH models how to emit dependencies advertise the same `none | blocked-by Piece N[, Piece M ...]` grammar that the parser now accepts. Without this end-to-end consistency, the parser contract change would be silently undermined by stale producer prompts. The plural shape `Pieces 1, 2, 3` remains deferred (a future issue can broaden the regex if observed in the wild).

## Edge cases

- **Single-blocker shape** (`blocked-by Piece 1`): `m_anchor.group(1)` is ` Piece 1`; split yields `[" Piece 1"]`; segment `Piece 1` matches; one edge. Existing fixture `p1` continues to pass.
- **Comma multi-blocker** (`blocked-by Piece 1, Piece 2, Piece 3, Piece 4`): split yields four segments, each matches, four edges in declaration order.
- **`and` separator** (`blocked-by Piece 1 and Piece 2`): split on `\s+and\b` yields two segments, both match, two edges.
- **Mixed comma and `and`** (`blocked-by Piece 1, Piece 2 and Piece 3`): split yields three segments, three edges.
- **Out-of-order blockers** (`blocked-by Piece 2, Piece 1`): two segments, two edges emitted in declaration order. Cycle detection (Kahn's algorithm) is order-insensitive.
- **Duplicate blockers** (`blocked-by Piece 1, Piece 1`): `seen` set dedupes; one edge.
- **Mixed valid + invalid blocker numbers** (`blocked-by Piece 1, Piece 99` when Piece 99 missing): both segments match `^Piece\s+(\d+)$`; first iteration of the post-validation loop appends edge `(idx1, current)`; second iteration triggers `bad-dependency-ref` exit 2. Important: partial edges in the in-memory `edges` list are discarded because the process exits before any `edges` are serialized to disk (serialization happens only after all pieces parsed, in the later `topological_sort` / TSV-write block).
- **Empty dependencies / `none`**: `dep` starts with `none`; anchor regex does not match `blocked-by`; the entire `if m_anchor:` block is skipped; no edges appended. Existing path preserved.
- **Prose-incidental `Piece N`** (`blocked-by Piece 1 (see Piece 2 for context)`): split on `,` and `\s+and\b` yields one segment `Piece 1 (see Piece 2 for context)`; that does NOT match `^Piece\s+(\d+)$`; abort with `bad-dependency-ref` exit 2. **Behavior change**: stricter than the original single-match parser (which would have emitted one edge for `Piece 1` and ignored the prose). This is intentional — the producer prompts do not authorize prose in the dependency line, and silently extracting one blocker while ignoring incidental `Piece N` mentions is itself a silent-data-corruption risk.
- **Plural shape** (`blocked-by Pieces 1, 2, 3`): split on `,` yields `["Pieces 1", "2", "3"]`; first segment fails `^Piece\s+(\d+)$` (extra `s`); abort with `bad-dependency-ref` exit 2. **Behavior change**: the original single-match parser would have silently produced zero edges. This is intentional per Round 1 Decision 5 (out of scope) AND per FINDING_4 (silent zero-edges is bad). If the plural shape is observed in the wild, the follow-on issue should broaden the regex to `(?:Pieces?\s+)?(\d+)` AND update the producer schemas.

## Failure modes

1. **Silent under-counting** (the original bug): regression-tested by the new multi-blocker fixture (`p2c`) asserting exactly 4 edges via `wc -l` and individual `grep -Fq` per edge.
2. **Silent over-counting from prose-incidental `Piece N`**: the new fail-closed behavior catches this — a producer that emits `blocked-by Piece 1 (see Piece 2)` triggers `bad-dependency-ref` instead of silently emitting an extra edge. Coverage: the strictness is exercised by the bad-ref multi-list fixture (`p2d`) at the segment level; a dedicated prose fixture is not added because the segment-level reject is general (any non-`Piece N` segment aborts).
3. **Dedupe regression** (a regression that drops the `seen` set and emits one edge per blocker without dedupe): the new duplicate-blocker fixture (`p2f`) asserts exactly 1 edge for `blocked-by Piece 1, Piece 1`. A dedupe regression would emit 2 edges and fail this assertion immediately.
4. **Strict-reference weakened** (a regression that allows unknown blocker numbers to silently drop instead of aborting): the bad-ref fixture (`p2d`) asserts both the exit code (`_rc2d -eq 2`) AND the status string AND the absence of `partition-input.txt` / `partition-deps.tsv`. All four assertions must hold; a regression that emits the status string but exits 0 fails the `_rc2d -eq 2` assertion immediately.
