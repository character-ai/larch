# Implementation Plan — #2865 Cursor narration-only outputs bypass waterfall fallback

## Goal

Add a centralized result-pattern gate to `dispatch-with-waterfall.sh` so the existing 3-phase fallback machinery treats `STATUS=OK` outputs that fail a caller-supplied regex as failed slots. Opt the two decompose call-sites into the gate, swap the aggregator's primary tool from Cursor to Codex, and update `decompose-panel-dispatch.sh` so its per-slot panel-row generation consumes the dispatcher's `ALL_OUTPUT_FILES_PATH` resolved paths (otherwise the fallback recovers content but the panel never sees it).

## Files to modify/create

### UPDATED: `scripts/dispatch-with-waterfall.sh`

Add one optional flag, a one-shot prevalidation, and one extra check inside per-phase collection.

- Declare `REQUIRE_RESULT_PATTERN=""` near the other defaults (next to `WATERFALL_PATHS_FILE=""`).
- Extend the argv parse loop with `--require-result-pattern) REQUIRE_RESULT_PATTERN="${2:?--require-result-pattern requires a value}"; shift 2 ;;`.
- **Prevalidate the regex once** after argv parse and the existing jq guard, before any slot launches: run `printf '' | grep -E -- "$REQUIRE_RESULT_PATTERN" >/dev/null 2>&1`, capture rc; if rc>1 (grep ERE syntax error), `larch_err "dispatch-with-waterfall.sh: --require-result-pattern is not a valid ERE: $REQUIRE_RESULT_PATTERN"` and `exit 2`. Skip the prevalidation when `REQUIRE_RESULT_PATTERN` is empty.
- Inside `collect_phase`, modify the per-slot resolution at the `STATUS == OK || STATUS == cap_hit` branch:
  - When `STATUS == cap_hit`, **bypass** the pattern check entirely and continue settling the slot as today (preserves the existing token-budget skip contract from `launch-review.sh`).
  - When `STATUS == OK` and `REQUIRE_RESULT_PATTERN` is non-empty: run `grep -Eq -- "$REQUIRE_RESULT_PATTERN" "${rf:-$output}"`. **Branch on grep rc**: rc 0 → accept (fall through to the existing `final_outputs[$idx]` / `final_tools[$idx]` assignment); rc 1 (no match) → push `$idx` into `failed` and `continue` **before** setting `final_outputs` / `final_tools`. The prevalidation above guarantees rc>1 cannot occur at runtime for a syntactically valid pattern; if the resolved file is unreadable, grep emits rc 2 with stderr, which the dispatcher surfaces via the existing `set -euo pipefail` only when not wrapped — keep the per-slot grep wrapped in an `if` so the surrounding loop continues to the next slot, but emit a `larch_err` describing the unreadable path and treat the slot as failed.
  - When `STATUS == OK` and `REQUIRE_RESULT_PATTERN` is empty, behavior is identical to today.
- Default behavior (flag unset) is unchanged — additive and backward compatible.

Critical control-flow detail: do **NOT** assign `final_outputs[$idx]` / `final_tools[$idx]` on the pattern-miss branch. The `failed+=("$idx"); continue` must run before any assignment, so subsequent phases overwrite cleanly and the paths-file emit reflects the resolved phase-2/phase-3 path rather than a stale phase-1 narration entry.

Use `${rf:-$output}` (matching the existing OK branch's variable resolution) so retry-path REVIEWER_FILE rewrites (e.g. `<orig>-retry.txt`) are honored exactly like today's OK branch.

## Approach

Pick the **structural fix at the boundary** rather than per-caller post-grep duplication. The dispatcher already owns the `STATUS=OK`/`cap_hit` ↔ retry-path machinery; introducing the new check at that exact point reuses phase-1 → phase-2 → phase-3 fallback, the WARN threshold, the paths-file emit, dirty-tree sidecars, and the `DISPATCH_OK` semantics with zero contract churn elsewhere.

Make the flag **opt-in by default**: only the two decompose callers (aggregator and panel dispatch) need it, and they share the same regex (`^[[:space:]]*## Recommendation`) that their existing post-dispatch grep guards already encode. Sketch and plan-review collectors remain on today's semantics per the documented Non-adopters paragraph in `dispatch-with-waterfall.md`.

Make the **aggregator primary-tool swap (Fix 1)** orthogonal: it does not depend on Fix 2 to land, and the dispatcher continues to fall through to Cursor on phase 2 and Claude on phase 3 regardless of which external is primary.

**Preserve the token-budget skip contract** (Theme B): `STATUS=cap_hit` is the launcher's explicit "do not run; respect cost cap" sentinel. The pattern gate is `STATUS=OK`-only so cap_hit always settles the slot terminally; the existing token-budget guards keep their meaning.

**Fail loud on operator misconfiguration** (Theme C): an invalid ERE is a caller bug, not a runtime no-match. Prevalidate once at startup and exit 2 with `larch_err` so the operator sees the issue immediately instead of every slot silently burning all three phases.

**Honor the resolved-path contract** (Theme A): when the dispatcher's gate routes a slot through phase 2 / phase 3, the operator-facing panel must see the recovered content. The `ALL_OUTPUT_FILES_PATH` is the existing contract for that — `decompose-panel-dispatch.sh` becomes the second consumer of that contract (the first is `collect-agent-results.sh --paths-file` for plan review). The aggregator does not need a similar update because it consumes the dispatcher's single resolved path directly via `read -r final_out <"$ALL_OUTPUT_FILES_PATH"` already (see existing code at lines 138-141 in `decompose-aggregator.sh`).

**Why the inner-dispatch layer is the right home for this gate** (empirical confirmation from a prior session): a separate `/design` run observed `aggregate-findings.sh`'s outer-fallback path was itself unreliable — `MERGE_PIPELINE_RC=1` (`empty_merge_from_nonempty_input`) in round 1 should have continued to the Codex outer phase but didn't (round 2 did fire). That evidence strengthens the case for a content-aware gate at the inner `dispatch-with-waterfall.sh` boundary rather than reordering or hardening outer-phase fallback chains. Separately, Cursor's narration-only outputs were measured at `outputTokens=6086` with `~106-byte .result` — the model ran to completion and abstained at presentation time, not a zero-output launcher failure. That confirms the right layer is the dispatch-layer pattern check (this plan) and **NOT** a launcher-layer change like swapping `cursor agent --mode plan` to `--mode auto`. The latter would be an upstream Cursor behavior bet; the former is a defensive structural guard that works regardless of upstream model behavior.

## Edge cases

- **`STATUS=cap_hit` with `--require-result-pattern` set**: pattern check is bypassed; slot settles on the assigned tool just as today. The cap-hit harness case asserts no phase-2/phase-3 launch occurs.
- **`STATUS=OK` with `cap_hit` not in play, pattern matches**: fall through to the existing `final_outputs[$idx]` / `final_tools[$idx]` assignment.
- **`STATUS=OK` with pattern mismatch**: `failed+=("$idx"); continue` runs BEFORE any `final_outputs` / `final_tools` assignment. Subsequent phases overwrite cleanly; the paths-file emit reflects the resolved phase-2/phase-3 path.
- **`REVIEWER_FILE` rewrites on retry**: grep `${rf:-$output}` (matching the existing OK branch's variable resolution) so the retried file is what's pattern-checked.
- **Empty result file with `STATUS=OK`**: `grep -Eq` on an empty file returns 1 — slot correctly falls through. Same behavior as the existing OK path when the file is non-empty but pattern-mismatched.
- **Pattern is itself empty (`--require-result-pattern ''`)**: parse-loop `${2:?--require-result-pattern requires a value}` rejects empty values with a clear stderr message and exit 2.
- **Pattern is invalid ERE**: prevalidation runs once after argv parse and emits a clear `larch_err`; exit 2 before any slot launches.
- **Pattern that always matches (e.g. `.*`)**: behavior reduces to today's: every `STATUS=OK` output is accepted. Documented in the Flags section.
- **All N tools fail the pattern**: each slot fails phase-1, phase-2, then phase-3 falls back to Claude. If Claude's output also fails the pattern, the slot ends up in `phase3_failed[]` and the existing `DISPATCH_OK=false` + paths-file emission of the phase-3 path apply.
- **`ALL_OUTPUT_FILES_PATH` empty/missing in `decompose-panel-dispatch.sh`**: indicates a dispatcher contract regression. The loop emits a single `larch_err` warning and falls back to the manifest path so prior behavior is preserved; the linked dispatcher harness case asserts the paths-file is always written when slots run, so the warning is exceptional.
- **Resolved-paths array shorter than the manifest** (impossible per dispatcher contract — paths-file always has one line per slot): the `${_resolved_paths[$_i]:-$_outp}` fallback keeps the original behavior for any out-of-range index.
- **Tool stub backward compatibility in `test-dispatch-with-waterfall.sh`**: default env-var values match today's hardcoded strings (`cursor ok` / `codex ok`), so the existing 12+ test cases keep their byte-identical assertions.
- **Bash 3.2 portability**: panel-dispatch loop uses `while IFS= read -r line; do _resolved_paths+=("$line"); done < "$ALL_OUTPUT_FILES_PATH"`, not `mapfile` / `readarray` (per `BASH_AUTHORING.md` §3).

## Failure modes

1. **Caller threads an invalid ERE**: detected at prevalidation; dispatcher exits 2 with `larch_err` naming the bad pattern. No slot launches. Operator sees the failure immediately rather than silently across all phases.
2. **Pattern accidentally rejects all legitimate outputs**: every slot fast-fails to Claude on phase-3, `WARN=cost-fallback-exceeded-threshold` fires when `FALLBACK_COUNT > 3`, and the operator sees the existing breadcrumb. Earliest signal: the WARN line in the dispatcher output; deeper signal: `DISPATCH_OK=false` followed by absent `## Recommendation` in the merged output. Mitigation: callers' patterns are short and grep-tested in the harness.
3. **Dispatcher contract regression where `ALL_OUTPUT_FILES_PATH` is empty**: panel-dispatch falls back to manifest paths with a single `larch_err` warning. Linked dispatcher harness asserts paths-file is always written when slots run, so the warning is an audit trail rather than a silent regression.
