## Plan

## Approach

- Add shared `python/exec_issue_detail.py` as the single fence-aware parser, counter, and renderer for exec-issue and warning detail.
- Keep parsing read-only. Do not change how `execution-issues.md` or `execution-issues.ndjson` are written.
- Parse only existing final-summary inputs:
  - `execution-issues.md` when present and non-empty.
  - `larch-logs/implement/<run_id>/execution-issues.ndjson` as implement fallback when markdown is missing or empty.
- Use the same category split as existing counters:
  - Exec Issues: `Tool Failures`, `External Reviewer Issues`.
  - Warnings: `Warnings`.
- **Single load, single count source**: both integration sites call `load_issue_detail_groups` once per final-summary pass, derive totals only via `count_load_result(load_result)`, and pass the same `LoadResult` into rendering. No caller-passed totals that can diverge from parsed or legacy-degraded totals.
- **Fence-aware walking**: ignore fenced code blocks for section boundaries, bullet detection, and label extraction (fixes design `_issue_counts` gap vs implement `_count_issue_sections`).
- **Event text extraction** (per bullet, outside fences only):
  - Bold bullets like `- **lint**: drift` or `- **Step 2b.5**: plan-size check failed`: extract normalized bold label plus same-line trailing text after the closing `**` (strip leading colon/whitespace from suffix). Render as one bounded display line, e.g. `lint: drift` or `Step 2b.5: plan-size check failed`.
  - Plain bullets like `- degraded-tools-gate` or `- a` (existing producer shapes from `run-log append-entry`, `stall_recovery.py`, `implement_dispatch.py`, etc.): derive display text from the trimmed bullet body (truncated). No bold label required.
  - NDJSON structured rows: parse each row `body` as markdown section body under `category`; apply the same bullet rules per row body.
  - Do not include multiline fenced diagnostic bodies or continuation lines in rendered rows.
- **Dedupe/collapse**: collapse identical normalized `dedupe_key` values while preserving first-seen order. For bold bullets, `dedupe_key` is normalized full `display_text` (label plus suffix), not label alone, so `lint: drift` and `lint: timeout` remain distinct. For plain bullets, `dedupe_key` is normalized trimmed first-line body. When duplicates collapse, increment `IssueDetail.count` and render `×N` on the display line.
- **Count semantics**:
  - Non-degraded: `count_issue_groups(groups)` returns `(sum(d.count for d in exec_issues), sum(d.count for d in warnings))`.
  - Degraded legacy NDJSON string-count fallback: `LoadResult` carries `degraded_totals: tuple[int, int]`; public `count_load_result(load_result)` returns those totals when `listing_degraded` is true.
  - Header totals always come from `count_load_result`; rendered numbered rows are collapsed `IssueDetail` entries; `len(rows)` may be less than the header total when `×N` is shown.
- **Legacy NDJSON fallback** (port `final_report._refresh_issue_counts` lines 373–396):
  - When all NDJSON lines parse as dicts: structured per-row path (existing plan).
  - When not all lines are dicts: concatenate valid dict `body` fields into synthetic markdown; if `^### (Tool Failures|External Reviewer Issues|Warnings)$` headings appear, run fence-aware markdown aggregator on concatenated text (`listing_degraded=False`).
  - Else: category-string count fallback for totals only via `legacy_category_string_totals(body_text)`; return `LoadResult(empty groups, listing_degraded=True, degraded_totals=(exec_n, warn_n))`. Detail listing emits category headers with correct totals and no fabricated rows.
- **Assessment**: one Claude Haiku call per non-empty category with redacted `display_text` and `count` only (never raw fenced captures, full row bodies, or unredacted suffixes). Fail closed to rows without assessment lines on timeout, invalid JSON, subprocess failure, or missing `claude`.
- **Redaction**: run `redact.redact_outbound` on each `display_text` before building the assessment prompt; run `redact.redact_outbound` on the full rendered detail block before return (same pattern as `review_phase_detail._invoke_renderer`).
- Append the detail block after run-summary render and before `review_phase_detail.append_review_phase_detail` so it stays near the top-level run summary.
- **Design `phase == "pre"`**: load and count before `invoke_render` for both phases so run-summary bullets match parsed totals; append exec/warnings detail only after the `if phase == "pre": return 0` guard, inside the existing post-`pre` try block alongside `review_phase_detail`.

- Frozen dataclasses:

  - `IssueDetail(label: str, description: str, display_text: str, count: int)` (post-collapse).
  - `IssueDetailGroups(exec_issues: tuple[IssueDetail, ...], warnings: tuple[IssueDetail, ...])`.
  - `LoadResult(groups: IssueDetailGroups, listing_degraded: bool, degraded_totals: tuple[int, int] | None = None)`.
    - `degraded_totals` is set only when `listing_degraded=True` and legacy string-count fallback supplies non-parseable totals.
    - Validate in `__post_init__` or factory: when `listing_degraded` and `degraded_totals` is not `None`, `groups` exec/warn tuples are empty.
- Category constants shared with design/implement summary counters (`EXEC_CATEGORIES`, `WARN_CATEGORY`).
- Constants: `MAX_DISPLAY_LEN` (e.g. 200) for display and assessment prompt text; `ASSESSMENT_TIMEOUT_SECONDS` (short, e.g. 10–15s).
- **Fence-aware markdown walker** (`_walk_issue_sections(text) -> iterable of (category, line)` or section-batched lines):
  - Track `### ` section headings into exec / warn / other buckets.
  - Toggle fence state on lines whose stripped form starts with ` ``` `.
  - Ignore bullets and headings inside fences.
- **Bullet parser** (`_parse_bullet_line(line) -> IssueEvent | None`):
  - Match `- ` bullets only.
  - Bold form: `^- \*\*([^*]+)\*\*:?(.*)$` → `label` = trimmed label with optional trailing colon stripped from label token; `description` = trimmed suffix after bold span; `display_text` = `f"{label}: {description}"` when suffix non-empty else `label`; `dedupe_key` = normalized `display_text`.
  - Plain form: `^- (.+)$` when bold regex does not match → `label` = `""`; `description` = trimmed body; `display_text` = truncated body; `dedupe_key` = normalized plain text.
  - Return `None` for empty bodies.
- **Markdown aggregator** (`parse_markdown_execution_issues(text: str) -> IssueDetailGroups`):
  - Walk sections fence-aware.
  - Parse in-scope bullets, collapse by `dedupe_key`, preserve first-seen order, sum counts into `IssueDetail.count`.
- **NDJSON structured aggregator** (`_parse_ndjson_structured_rows(rows: list[dict]) -> IssueDetailGroups`):
  - One JSON object per line; use `category`; parse `body` through markdown bullet rules scoped to that category.
  - Ignore malformed rows.
  - For body with zero parsed bullets, count once using plain first-line fallback (mirrors `max(1, _count_markdown_bullets_outside_fences(...))` semantics) with `display_text` from trimmed first line.
- **Legacy string-count helper** (`legacy_category_string_totals(body_text: str) -> tuple[int, int]`):
  - `exec_n = body_text.count('"category":"Tool Failures"') + body_text.count('"category":"External Reviewer Issues"')`
  - `warn_n = body_text.count('"category":"Warnings"')`
  - Port of today's `_refresh_issue_counts` else branch.
- **NDJSON legacy fallback** (`_parse_ndjson_legacy(path: Path) -> LoadResult`):
  - Read all lines; if every non-empty line is a dict, delegate to structured path → `LoadResult(groups, listing_degraded=False)`.
  - Else concatenate dict `body` values; when synthetic markdown has `### Tool Failures|External Reviewer Issues|Warnings` headings, return `LoadResult(parse_markdown_execution_issues(body_text), listing_degraded=False)`.
  - Else compute `degraded_totals = legacy_category_string_totals(body_text)`; return `LoadResult(empty groups, listing_degraded=True, degraded_totals=degraded_totals)`.
- **Tmpdir loader** (`load_issue_detail_groups(tmpdir: Path, *, run_dir: Path | None) -> LoadResult`):
  - Prefer `tmpdir / "execution-issues.md"` when non-empty → `LoadResult(parse_markdown_execution_issues(text), False)`.
  - Else when `run_dir` provided and `run_dir / "execution-issues.ndjson"` exists → `_parse_ndjson_legacy(...)`.
  - Else `LoadResult(empty groups, listing_degraded=False)`.
- **Count helpers**:
  - `count_issue_groups(groups: IssueDetailGroups) -> tuple[int, int]`: internal/non-degraded only; `(sum(d.count for d in groups.exec_issues), sum(d.count for d in groups.warnings))`.
  - `count_load_result(load_result: LoadResult) -> tuple[int, int]`: **sole public total API for call sites**. When `load_result.listing_degraded` and `load_result.degraded_totals` is not `None`, return `degraded_totals`; else return `count_issue_groups(load_result.groups)`.
- **Assessment helper** (`assess_issue_details(category: str, details: tuple[IssueDetail, ...]) -> dict[str, str]`):
  - Build prompt from `[{display_text: redact.redact_outbound(d.display_text), count: d.count}, ...]`.
  - `subprocess.run` with `claude --print --output-format json --model <haiku-model>`.
  - Model override via `LARCH_EXEC_ISSUE_ASSESSMENT_MODEL`.
  - Return `{}` on all failures.
  - Map assessments back by redacted `display_text` or stable index ids.
- **Rendering helper** (`render_issue_detail_block(load_result: LoadResult, *, assess: bool = True) -> str`):
  - Derive `exec_total, warning_total = count_load_result(load_result)` internally (no external total parameters).
  - Return `""` when both totals are zero and both group tuples are empty.
  - When `listing_degraded` and totals are non-zero with empty group tuples: render header-only block (`## Exec Issues and Warnings`, `Exec Issues ({exec_total}):`, `Warnings ({warning_total}):`) with no numbered rows and no fabricated assessments.
  - Otherwise:
    - `## Exec Issues and Warnings`
    - `Exec Issues ({exec_total}):`
    - Numbered `display_text` rows with optional ` ×N` when `count > 1`.
    - Optional indented assessment line per row when present.
    - `Warnings ({warning_total}):`
  - For zero totals in a category, render `Exec Issues (0)` or `Warnings (0)` with no list.
  - Apply `redact.redact_outbound` to the full rendered block before return.
- **Public convenience** (`build_issue_detail_section(load_result: LoadResult) -> str`):
  - Thin wrapper: `render_issue_detail_block(load_result, assess=True)`.
  - Callers that already loaded pass the same `LoadResult` instance used for `count_load_result`.

## Edge cases

- Missing `execution-issues.md`: implement uses NDJSON fallback; design returns empty groups.
- Empty `execution-issues.md`: implement uses NDJSON fallback when available.
- Malformed NDJSON: ignore bad rows; continue with valid rows; fall through to legacy concatenation when not all-dict.
- Legacy string-count-only NDJSON: `degraded_totals` non-zero, empty detail tuples, `listing_degraded=True`; headers match totals, no fabricated list rows; run-summary and detail block use same `count_load_result`.
- Bold label with trailing colon inside bold token: strip for display and dedupe.
- Same normalized label, different suffixes: distinct `dedupe_key` values (do not collapse).
- Same `display_text` with different fenced bodies: collapse by `dedupe_key`; do not surface fenced text.
- Very long labels or suffixes: truncate before redact and assessment prompt.
- Unlabeled bullets on implement and design paths: must appear in detail list as plain truncated text and increment counts.
- Claude unavailable: render rows with no assessment lines; degraded header-only path skips assessment entirely.
- Duplicate bullets: one collapsed row, header total equals sum of `IssueDetail.count`.
- Design `phase == "pre"`: counts in run summary; no detail section appended.

## Failure modes

- Assessment timeout can slow final summary.
  - Mitigation: short timeout; fail closed to rows without assessment lines.
- Assessment prompt could leak diagnostics if built from raw rows.
  - Mitigation: redact each `display_text` before prompt assembly; test absence of raw secrets in prompt and rendered output.
- Refactoring counters could change historic totals.
  - Mitigation: port full `_refresh_issue_counts` fallback chain including `degraded_totals`; lock with existing `test_pr_body.py` fixtures plus new cross-parser and degraded-header tests.
- Redaction skipped on new block could re-expose tmp paths or tokens in suffix text.
  - Mitigation: mandatory `redact.redact_outbound` on assessment inputs and rendered block; regression tests on design and implement final-summary paths.
- Dual total sources could recreate `Warnings (N)` with fewer rows.
  - Mitigation: single `load_issue_detail_groups` per site; totals always from `count_load_result(load_result)`; renderer consumes the same `LoadResult`; no caller override parameters.
- Passing `LoadResult` to `count_issue_groups` by mistake would yield `(0, 0)` on degraded paths.
  - Mitigation: `count_load_result` is the only documented call-site counter; tests assert degraded fixtures never use `count_issue_groups` alone.
