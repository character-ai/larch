## Plan

## Approach

- Add shared `python/exec_issue_detail.py` as the single fence-aware parser, counter, and renderer for exec-issue and warning detail.
- Keep parsing read-only. Do not change how `execution-issues.md` or `execution-issues.ndjson` are written.
- Parse only existing final-summary inputs:
  - `execution-issues.md` when present and non-empty.
  - `larch-logs/implement/<run_id>/execution-issues.ndjson` as implement fallback when markdown is missing or empty.
- Use the same category split as existing counters:
  - Exec Issues: `Tool Failures`, `External Reviewer Issues`.
  - Warnings: `Warnings`.
- **Single load, single count source**: both integration sites call `load_issue_detail_groups` once per final-summary pass, derive totals only via `count_load_result(load_result)`, and pass the same `LoadResult` into rendering. No caller-passed totals that can diverge from parsed or legacy-degraded totals.
- **Section-boundary semantics** (match `final_report._count_issue_sections`):
  - On `### Tool Failures`, `### External Reviewer Issues`, or `### Warnings`: switch active section bucket and **clear `in_fence=False`** even when the heading appears inside an open fence (unclosed fence before `### Warnings` must still start the warnings bucket).
  - On any other `### ` heading: set section to none and clear `in_fence=False`.
  - Toggle fence state only on lines whose stripped form starts with ` ``` `.
  - Collect section body lines (including fence delimiter lines) into per-section buffers; apply fence-aware bullet parsing only within the active exec/warn section buffer via `_count_markdown_bullets_outside_fences`-equivalent logic.
- **Event text extraction** (per bullet, outside fences only):
  - Bold bullets like `- **lint**: drift` or `- **Step 2b.5**: plan-size check failed`: extract normalized bold label plus same-line trailing text after the closing `**` (strip leading colon/whitespace from suffix). Render as one bounded display line, e.g. `lint: drift` or `Step 2b.5: plan-size check failed`.
  - Plain bullets like `- degraded-tools-gate` or `- a` (existing producer shapes from `run-log append-entry`, `stall_recovery.py`, `implement_dispatch.py`, etc.): derive display text from the trimmed bullet body (truncated). No bold label required.
  - NDJSON structured rows: parse each row `body` as markdown section body under `category`; apply the same bullet rules per row body.
  - Do not include multiline fenced diagnostic bodies or continuation lines in rendered rows.
- **Dedupe/collapse**: collapse identical normalized `dedupe_key` values while preserving first-seen order. For bold bullets, `dedupe_key` is normalized full `display_text` (label plus suffix), not label alone, so `lint: drift` and `lint: timeout` remain distinct. For plain bullets, `dedupe_key` is normalized trimmed first-line body. When duplicates collapse, increment `IssueDetail.count` and render `×N` on the display line.
- **Count semantics**:
  - Non-degraded: `count_issue_groups(groups)` returns `(sum(d.count for d in exec_issues), sum(d.count for d in warnings))`.
  - Degraded legacy NDJSON string-count fallback: `LoadResult` carries `degraded_totals: tuple[int, int]`; public `count_load_result(load_result)` returns those totals when `listing_degraded` is true.
  - Header totals always come from `count_load_result`; rendered numbered rows are collapsed `IssueDetail` entries; `len(rows)` may be less than the header total when `×N` is shown.
- **Legacy NDJSON fallback** (port `final_report._refresh_issue_counts` lines 373–396):
  - When all NDJSON lines parse as dicts: structured per-row path (existing plan).
  - When not all lines are dicts: concatenate valid dict `body` fields into synthetic markdown; if `^### (Tool Failures|External Reviewer Issues|Warnings)$` headings appear, run fence-aware markdown aggregator on concatenated text (`listing_degraded=False`).
  - Else: category-string count fallback for totals only via `legacy_category_string_totals(body_text)`; return `LoadResult(empty groups, listing_degraded=True, degraded_totals=(exec_n, warn_n))`. Detail listing emits category headers with correct totals and no fabricated rows.
- **Assessment**: one Claude Haiku call per non-empty category with redacted `display_text` and `count` only (never raw fenced captures, full row bodies, or unredacted suffixes). Fail closed to rows without assessment lines on timeout, invalid JSON, subprocess failure, missing `claude`, envelope error, or schema mismatch.
- **Claude subprocess contract** (match `agents.py` `launch-claude-subprocess` / `launch-claude-ci` envelope handling): `claude --print --output-format json` returns a wrapper object; assessments live in the string `result` field after a second `json.loads`, not at stdout top level.
- **Model resolution**: pin a documented default Haiku slug when `LARCH_EXEC_ISSUE_ASSESSMENT_MODEL` is unset (same env-override pattern as `LARCH_VOTER_MODEL` / `LARCH_DESIGN_PLAN_MODEL`); always pass an explicit `--model` to subprocess.
- **Redaction**: run `redact.redact_outbound` on each `display_text` before building the assessment prompt; run `redact.redact_outbound` on the full rendered detail block before return (same pattern as `review_phase_detail._invoke_renderer`).
- Append the detail block after run-summary render and before `review_phase_detail.append_review_phase_detail` so it stays near the top-level run summary.
- **Design `phase == "pre"`**: load and count before `invoke_render` for both phases so run-summary bullets match parsed totals; append exec/warnings detail only after the `if phase == "pre": return 0` guard, inside the existing post-`pre` try block alongside `review_phase_detail`.

## Edge cases

- Missing `execution-issues.md`: implement uses NDJSON fallback; design returns empty groups.
- Empty `execution-issues.md`: implement uses NDJSON fallback when available.
- Malformed NDJSON: ignore bad rows; continue with valid rows; fall through to legacy concatenation when not all-dict.
- Legacy string-count-only NDJSON: `degraded_totals` non-zero, empty detail tuples, `listing_degraded=True`; headers match totals, no fabricated list rows; run-summary and detail block use same `count_load_result`.
- Bold label with trailing colon inside bold token: strip for display and dedupe.
- Same normalized label, different suffixes: distinct `dedupe_key` values (do not collapse).
- Same `display_text` with different fenced bodies: collapse by `dedupe_key`; do not surface fenced text.
- `### Warnings` inside an open fence: section boundary clears fence and starts warnings bucket (must match historic `(1, 1)` fixture).
- Very long labels or suffixes: truncate before redact and assessment prompt.
- Unlabeled bullets on implement and design paths: must appear in detail list as plain truncated text and increment counts.
- Claude unavailable or bad assessment JSON: render rows with no assessment lines; degraded header-only path skips assessment entirely.
- Claude returns success envelope but `is_error=true` or empty `result`: treat as assessment failure; rows render without assessment lines.
- Claude returns success envelope with string `result` that is not valid assessments JSON: fail closed; no assessment lines.
- `LARCH_EXEC_ISSUE_ASSESSMENT_MODEL` unset or whitespace-only: use pinned `claude-haiku-4-5` default so behavior is deterministic across environments.
- Duplicate bullets: one collapsed row, header total equals sum of `IssueDetail.count`.
- Design `phase == "pre"`: counts in run summary; no detail section appended.

## Failure modes

- Assessment timeout can slow final summary.
  - Mitigation: short timeout; fail closed to rows without assessment lines.
- Assessment prompt could leak diagnostics if built from raw rows.
  - Mitigation: redact each `display_text` before prompt assembly; test absence of raw secrets in prompt and rendered output.
- Assessment response shape drift could silently drop all assessment lines.
  - Mitigation: fixed JSON schema in prompt; unwrap Claude envelope before inner parse; strict `assessments` validation; tests for envelope success, `is_error`, empty `result`, partial ids, and invalid inner shape.
- Parsing stdout as top-level `assessments` would fail every real `claude --print --output-format json` call.
  - Mitigation: `_unwrap_claude_json_result` plus inner `_parse_assessments_payload`; envelope-shaped mocked stdout test (not bare assessments JSON at stdout root).
- Unpinned assessment model could inherit operator-specific Claude defaults or fail when env unset.
  - Mitigation: `config.EXEC_ISSUE_ASSESSMENT_MODEL_DEFAULT` plus env override; tests for env-set and env-unset `--model` argv.
- Refactoring counters could change historic totals.
  - Mitigation: port full `_count_issue_sections` boundary semantics (heading clears fence); port full `_refresh_issue_counts` fallback chain including `degraded_totals`; lock with existing `test_pr_body.py` fixtures plus new cross-parser and degraded-header tests.
- Redaction skipped on new block could re-expose tmp paths or tokens in suffix text.
  - Mitigation: mandatory `redact.redact_outbound` on assessment inputs and rendered block; regression tests on design and implement final-summary paths.
- Dual total sources could recreate `Warnings (N)` with fewer rows.
  - Mitigation: single `load_issue_detail_groups` per site; totals always from `count_load_result(load_result)`; renderer consumes the same `LoadResult`; no caller override parameters.
- Passing `LoadResult` to `count_issue_groups` by mistake would yield `(0, 0)` on degraded paths.
  - Mitigation: `count_load_result` is the only documented call-site counter; tests assert degraded fixtures never use `count_issue_groups` alone.
- `_refresh_issue_counts` wrapper returning `None` would break `pr_body` and parity tests.
  - Mitigation: explicit `return exec_issue_detail.count_load_result(result)` in delegation body.
