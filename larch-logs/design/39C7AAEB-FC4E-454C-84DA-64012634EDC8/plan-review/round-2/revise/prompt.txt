# Introduce ARCHITECTURAL_GUIDELINES.md: operator-curated architectural goals /design + /implement consult

## Summary

Add an optional, hand-maintained `ARCHITECTURAL_GUIDELINES.md` at a repo's root. `/design` and `/implement` read it when present and treat its entries as **aspirational goals**, not hard rules. The agent may deviate with judgment; **all deviations are surfaced** to the operator. Absent the file, both skills behave exactly as today.

This is a **generic** larch feature: it reads whatever repo larch operates on. larch ships its own seeded copy as the first consumer.

## Motivation

- larch enforces some rules mechanically (linters, hooks, structural tests) and many more in scattered prose (`AGENTS.md`, `.claude/rules/`, skill NEVER lists). There is no single, design-altitude home for **judgment-level architectural goals that cannot be deterministically enforced**.
- These goals should bias `/design` and `/implement` the way the existing **Design Mindset** questions already do, but repo-specific and operator-curated.

## Decisions (settled in design discussion)

1. **Guidelines, not invariants.** Aspirational; not necessarily ever 100% true.
2. **Scope = only non-deterministically-enforceable goals.** Anything a linter, hook, or structural test can catch belongs there, not here.
3. **All deviations are surfaced.** `/design` raises them at the **proposal-approval** and **final-plan-approval** gates. `/implement` emits **warnings** only.
4. **Hand-maintained file.** `/design` and `/implement` never auto-edit it. Deviation rationale lives in the plan or PR, not in the file.
5. **Generic mechanism + larch seeds its own.** Discovered at the operating repo's root (git toplevel / `CLAUDE_PROJECT_DIR`); absent → behave as today.
6. **Granularity rule.** Because all deviations are surfaced, each guideline is pitched coarse enough that a deviation is a **notable event**, and carries an inline "does not count as a deviation" carve-out.
7. **Register.** "KARPATHY for this repo's architecture": each entry is **goal; why; deviate-when**. Architecture-specific only; does not duplicate KARPATHY's generic guidance.

## Mechanism (scope of this issue)

## Seeded guideline set (larch's own)

### Python coding practices

- **G-Py-1: Pass composite data as frozen dataclasses**, not bare tuples or dicts. Why: immutability plus named, refactor-safe fields across boundaries. Deviate when: scalar returns; genuine builders; an external dict/JSON parsed into a frozen dataclass at the edge. Aspirational today (`frozen=True` in a minority of files).
- **G-Py-2: Annotate types beyond signatures, including locals.** Why: documents intent and catches what inference will not demand. Deviate when: the type is obvious from the right-hand side (`count = 0`, loop targets). Note: ruff `ANN` is currently ignored, so annotation presence is unenforced; enabling `ANN001`/`ANN201` would mechanize signatures, leaving local-variable annotation as the judgment residue.
- **G-Py-3: Prefer domain types over stringly-typed primitives** (`Enum`, `NewType`, typed outcomes/errors). Includes the **boolean-trap** case: a bool that *selects behavior* becomes an enum (`do(*, mode=Mode.DELETE)`, not `do(True)`); a bool that *is data* stays bool. Why: illegal states unrepresentable; self-documenting call sites. Deviate when: one-call-site private helper; signature fixed by an external API/protocol. Note: ruff `FBT001`/`FBT003` already flag this and are widely `# noqa`'d today.
- **G-Py-4: Fail loudly and fail closed; never silently swallow.** Why: auditability and the codebase's fail-closed parity. Deviate when: a documented, narrow degraded path the caller explicitly handles.
- **G-Py-5: Isolate side effects behind injectable seams** (cf. `proc.py`, `RecordingRunner`). Why: keeps logic unit-testable offline. Deviate when: thin CLI dispatch glue with nothing to test.
- **G-Py-6: Pythonic judgment (PEP 20) is the scope; PEP 8 mechanics are not.** The deterministic style layer is owned by ruff + pylint + pyright. This is what "adhere to official Python guidelines" reduces to once the linters take their half.

### Skill authoring &amp; context economy

- **G-Skill-1: Load phase-local skill content lazily, at the point of need.** Conditional or later-phase blocks live in `references/` and are Read right before the phase that uses them (review rules before review; conflict handling on conflict). The eager prompt keeps the **pointer plus trigger condition** so content is never silently skipped. Why: lean active prompt; instructions adjacent to use. Deviate when: cross-cutting safety/NEVER constraints and Step-0-governing rules load eagerly; blocks too small to justify a separate Read.
- **G-Skill-2: Logic lives in Python behind `cli.py`; SKILL.md and Bash stay thin.** The judgment residue is "is this logic that belongs in Python?". Mechanical parts (no consecutive Bash blocks; residual-bash allowlist) are lints, not this guideline.

### Enforcement philosophy

- **G-Enf-1: Prefer mechanical enforcement.** When a judgment call recurs, promote it to a lint, hook, or structural test. Governs this file too: entries graduate to lints over time.
