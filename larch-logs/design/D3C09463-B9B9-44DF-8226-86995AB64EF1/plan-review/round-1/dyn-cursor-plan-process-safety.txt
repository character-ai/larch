## Findings

### 1. Owner-token propagation is contradictory (correctness / risk-integration)

The plan’s bootstrap and dispatch_leg sections disagree on how the owner token reaches the JSON publisher.

```167:177:python/larch/state/bootstrap.py
_larch_cleanup_active_leg() {
  python3 "$CLAUDE_PLUGIN_ROOT/python/cli.py" implement kill-active-leg --implement-tmpdir "$IMPLEMENT_TMPDIR" 2>/dev/null || true
}

case "$script" in
  *.py)
    trap _larch_cleanup_active_leg EXIT INT TERM
    python3 "$CLAUDE_PLUGIN_ROOT/$script" "$@"
```

Bootstrap requires generating a token and passing it only to cleanup, while `dispatch_leg` must store `owner_token` from the environment when publishing after `Popen` (today’s publisher is `_publish_active_leg_pgid` at ```86:93:python/larch/implement/dispatch_leg.py```). If the child never receives the token, bystander no-ops and owner matching cannot work.

**Suggested revision:** Export the config-named env var before the `python3` target line and pass the same value to `--owner-token` on cleanup.

### 2. `kill_active_leg_main` omits required `--owner-token` handling (completeness)

Bootstrap/tests are pinned to forward `--owner-token`, but the `dispatch_leg` UPDATED list never requires argparse, mandatory presence, or match logic in `kill_active_leg_main` (```142:157:python/larch/implement/dispatch_leg.py``` still reads only `--implement-tmpdir`, unlinks, then signals without validation).

**Suggested revision:** Add explicit required changes for `--owner-token` parsing, fail-closed behavior when missing, owner match before consume/kill, and no unlink on live owner mismatch.

### 3. Step 3 Python teardown lacks an identity-validation contract (correctness)

The plan fixes the post-`wait` recycle bug (```421:427:skills/design/scripts/design-step3-review.sh``` still tears down after `wait`), but the replacement Python helper has no wire contract for how “recorded identity” is obtained or compared at trap time.

**Suggested revision:** Name the CLI verb and document validation inputs, expected command signature rules, `ps` fail-closed behavior, and the same no-SIGKILL-after-failed-validation rule as the shared helper.
