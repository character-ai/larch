## Approach

Complete the trusted-artifact contract without changing artifact locations or I/O primitives.

For PR mutations and disposition-only consumers, centralize declared-context resolution and invalid-present artifact handling in `scope_disposition.py`. A non-`None` `tmpdir`, non-empty `IMPLEMENT_TMPDIR`, or explicit `manifest_path` declares implement context. An explicit manifest without a valid effective tmpdir fails closed before artifact access or mutation; the implementation must not infer a trusted artifact root from an arbitrary manifest parent. Preserve standalone behavior only when no context signal exists.

For coder snapshots, replace heuristic mode classification in every production decision path with a complete validator that distinguishes a wholly absent snapshot from a complete valid snapshot and a present-invalid snapshot. Snapshot creation may occur only after the validator reports wholly absent state. Return an immutable validated snapshot record containing the mode, pre-coder HEAD, trusted root identity, and validated artifact inventory; thread or revalidate that record before attempt capture, cleanup, diff-base, and staging decisions. Reject changed, partial, unsafe, or malformed snapshots before repository mutation.

Finish production consumer hardening and the regression coverage promised by #6852. Reuse existing fixtures and trusted artifact writers where possible.

## Edge cases

- `tmpdir=None` with no `IMPLEMENT_TMPDIR` and no explicit manifest remains a standalone no-op.
- An empty `IMPLEMENT_TMPDIR` does not declare a context.
- An explicit tmpdir argument declares context even when the environment is unset.
- An explicit manifest declares context; if neither the explicit tmpdir nor `IMPLEMENT_TMPDIR` yields a valid effective tmpdir, the call fails closed.
- A dangling symlink or regular file at the declared tmpdir path is invalid context.
- An explicit manifest cannot make an invalid declared tmpdir safe and cannot establish a trusted artifact root by parent-directory inference.
- A snapshot directory that exists with only some required files is invalid, not missing.
- A snapshot root with a symlink, unsafe ancestor, non-regular artifact, or unexpected existing artifact is invalid, not eligible for replacement.
- A tracked-path inventory with zero entries may be valid, but required inventory files must still exist.
- Duplicate tracked paths or different paths that map to the same patch filename are invalid.
- Snapshot artifact changes after initial validation require rejection before the next cleanup, diff-base, attempt-capture, or staging decision.
- Validation failures must occur before external coder launch or repository cleanup.

## Failure modes

- Over-broad context detection could break legitimate standalone ship operations. Tests must cover no-context, declared-tmpdir, manifest-only-invalid, and valid tmpdir-plus-manifest paths.
- Permissive snapshot classification could rewrite or trust partial artifacts. The validator must distinguish wholly absent from present-invalid before any write.
- Validating only at coder startup could allow changed artifacts to influence cleanup or staging. Thread the validated record or revalidate immediately before every downstream consumer decision.
- Duplicated context logic could leave disposition-only consumers permissive. Use one shared declared-context and invalid-present boundary for mutation, link, deferred-inventory, finalize, and report consumers.
- Consumer tests may accidentally use raw fixture writes that no longer form trusted artifact sets. Build fixtures through existing trusted writers where practical.
- A protocol-only signature mismatch may evade runtime tests. Include type and lint checks for `gh.py`.
- Removing `_snapshot_mode` from `coder_runner.py` without updating all monkeypatching test modules will break collection or runtime tests.
