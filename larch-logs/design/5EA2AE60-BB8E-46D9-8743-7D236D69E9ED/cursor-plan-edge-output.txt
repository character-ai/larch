**1. [correctness] Missing Phase-B verification in `_verify_failed_jobs_locally`** (`scripts/ship-pr.sh:2006-2017`)

The plan’s helper runs `_run_per_job_command_once` before each job’s fix loop and moves on when a job already passes, but it never re-runs all fixable jobs after later jobs may have changed the tree. `run_per_job_local_fix_loop` explicitly performs that second sweep and returns `4` on regression (`ci_per_job_verify_regression` depends on this). A vendor fix that passes an early job check but breaks a later-listed job can still be pushed.

**2. [correctness] Vendor `ci-local-unfixable` must `exit 3`, not retry** (`scripts/ship-pr.sh:2066-2149`)

`run_per_job_local_fix_loop` calls `exit 3` at line 2033. The proposed vendor path only returns `1` and the `run_evaluate_failure` `case` handles `0` and `2` only. The outer loop clears `BAIL_REASON` every iteration (line 2066), so a failed verify loses the bail token and burns up to three full vendor+verify cycles before stalling at `10-max-retries` (exit `4`) instead of exit `3` as `vendor_verify_local_exhausts` requires.

**3. [correctness] `max_iter` clamp is documented but not scheduled** (`scripts/ship-pr.sh:174-181`)

Failure modes #2 correctly identifies invalid `LARCH_CI_LOCAL_FIX_ITER` values; the five implementation bullets never add the clamp. Without it, the new `for ((attempt=1; attempt<=max_iter; attempt++))` loop is fragile under bad env input.

**4. [risk-integration] Do not branch on `$?` after `_verify`** (proposed `run_ci_fix_vendor` ~1870)

Use an explicit `verify_rc=` capture before `case`, especially for the `rc=2` head-changed chain called out as the highest-severity regression.
