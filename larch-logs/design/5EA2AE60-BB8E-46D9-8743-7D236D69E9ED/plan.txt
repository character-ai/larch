# Plan — Fixes #2963: ship-pr.sh CI-fix loop must re-run failed CI jobs locally before pushing

## Approach

When `run_evaluate_failure` (scripts/ship-pr.sh:2038) handles a CI failure today, it has two paths to push a fix:

1. **Per-job path** (engaged when `gh_logs_rc=0` AND `ci-failed-jobs.sh` rc=0 AND `FAILED_JOBS_COUNT>0` AND TSV non-empty): `run_per_job_local_fix_loop` runs each fixable job's local command, fix-loops until each passes, runs a final cross-job verification sweep, and pushes via `_stage_and_push_ci_fixes`. This path correctly validates fixes locally.

2. **Vendor fallback path** (engaged on any of: per-job loop returns rc=1 main-agent-required/dispatch-failed/exhausted, `ci_failed_rc != 0`, `FAILED_JOBS_COUNT=0`, TSV empty, or `gh_logs_rc != 0`): `run_ci_fix_vendor` dispatches Cursor→Codex→Claude fixer with the failure-log, then calls `_stage_and_push_ci_fixes`. `_stage_and_push_ci_fixes` runs `run_checks_with_lint_fix_loop` (scripts/ship-pr.sh:1724-1728) — which only invokes `relevant-checks.sh` (pre-commit hooks + agent-lint), **NOT** the actually-failed CI jobs. The vendor-fixed code is then pushed. If the fix touches a job not covered by `relevant-checks.sh` (test-harnesses, smoke-dialectic, agnix, agent-sync), the original CI job will fail again. The fix loop repeats — multiple consecutive CI failures.

This plan inserts a **pre-push per-job verification gate inside the vendor path**, so any fix dispatched by `run_ci_fix_vendor` is re-validated locally against the originally-failed fixable jobs before `_stage_and_push_ci_fixes` is allowed to push. Mechanism:

- Plumb the failed-jobs TSV (`$ci_failed_tsv`) from `run_evaluate_failure` (scripts/ship-pr.sh:2085) into `run_ci_fix_vendor` as a new optional positional argument.
- Introduce `_verify_failed_jobs_locally <phase> <failed_jobs_tsv>`. It iterates fixable rows from the TSV (re-using `_per_job_argv` at scripts/ship-pr.sh:1877), runs each command via `_run_per_job_command_once`, and on failure re-enters `run_captured_cmd_then_fix_loop` (scripts/ship-pr.sh:162) with `_RCC_SITE=ship-pr-ci-per-job`. After all per-job repairs succeed, **the helper runs a final cross-job verification sweep** (mirroring `run_per_job_local_fix_loop`'s Phase B at scripts/ship-pr.sh:2006-2017): re-runs every locally-passed job once more in a clean pass. Returns 0 (all pass + sweep clean), 2 (head-changed-after-dispatch — matches `run_per_job_local_fix_loop`), 4 (sweep regression — matches `run_per_job_local_fix_loop`). On consolidated unfixables it calls `state_set_many BAIL_REASON=ci-local-unfixable:<list>` and **`exit 3` directly** — same pattern as `run_per_job_local_fix_loop` at scripts/ship-pr.sh:2024-2033. This mirrors the per-job exit-3 contract precisely; **`run_evaluate_failure` does not need a new `ci-local-unfixable:*` branch** because the helper exits the process directly. (Addresses FINDING_1, FINDING_2, FINDING_8.)
- Call `_verify_failed_jobs_locally` between the winning-tier break and `_stage_and_push_ci_fixes` in `run_ci_fix_vendor` at scripts/ship-pr.sh:1870.
- `run_ci_fix_vendor` captures the helper's return code (only 0, 2, or 4 since `exit 3` short-circuits the process before return). It propagates rc=2 (head-changed) and rc=4 (sweep regression) to its caller as distinguishable return codes. `run_evaluate_failure` keys on them identically to the existing per-job branches at scripts/ship-pr.sh:2113-2120 (rc=2 → `exit_stall 10-head-changed`/`12-head-changed`; rc=4 → `per_job_verification_retry=true` for outer retry without pushing). This preserves the #2909/PR #2941 head-changed routing chain.
- Empty-TSV path: when the TSV is absent or empty (because `ci_failed_count=0`, TSV empty, or vendor path entered via `gh_logs_rc != 0`), `_verify_failed_jobs_locally` is a no-op-with-warning that delegates to `relevant-checks.sh` only — explicitly preserving today's behavior so the vendor path still progresses when no per-job info is available.

**Inner budget expansion**. The hardcoded `for attempt in 1 2 3` at scripts/ship-pr.sh:180 is the **real** ceiling today — `_RCC_MAX_ITER` at line 174 has no effect above 3 because the `for` list is fixed. Replace `for attempt in 1 2 3; do` with `for ((attempt=1; attempt<=max_iter; attempt++)); do` so `_RCC_MAX_ITER` becomes the actual ceiling. Remove the now-redundant `[ "$attempt" -le "$max_iter" ] || break` guard at scripts/ship-pr.sh:181 (numeric for-loop already enforces the bound). Add an explicit numeric/zero clamp `case "$max_iter" in ''|*[!0-9]*|0) max_iter=3 ;; esac` immediately after the `max_iter=${_RCC_MAX_ITER:-3}` assignment at line 174 so non-numeric/empty/zero env values fall back to the safe default of 3. (Addresses FINDING_3.) Set `_RCC_MAX_ITER=${LARCH_CI_LOCAL_FIX_ITER:-6}` at the per-job-loop call site (scripts/ship-pr.sh:1986) AND in the new `_verify_failed_jobs_locally` helper, so each per-job fix dispatch gets up to 6 inner attempts (was effectively 3). Outer `_max_fix=3` at scripts/ship-pr.sh:2063 stays unchanged.

**Why this approach over alternatives** (sketch convergence):
- "Widen verification beyond originally-failed jobs": rejected — amplifies wall-clock by N× without addressing the actual gap.
- "Pre-push hook inside `_stage_and_push_ci_fixes`": rejected — `_stage_and_push_ci_fixes` doesn't have the TSV in its signature.
- "Replace `run_ci_fix_vendor` entirely with `run_per_job_local_fix_loop`": rejected — the vendor path is a useful fallback for cases the per-job classifier doesn't cover.

## Edge cases

- **Vendor fixer commits the fix** (head-changed): preserved end-to-end. `_verify_failed_jobs_locally` returns 2 → `run_ci_fix_vendor` returns 2 → `run_evaluate_failure` captures vendor_rc=2 and calls `exit_stall 10-head-changed` (or `12-head-changed`). Matches the existing `run_per_job_local_fix_loop` rc=2 contract.
- **Vendor verification sweep regression**: Phase B re-runs every Phase-A-passed job. If any fails on the sweep, `_verify_failed_jobs_locally` returns 4 → vendor returns 4 → `run_evaluate_failure` sets `per_job_verification_retry=true` → outer retry without push. Mirrors per-job `run_per_job_local_fix_loop` rc=4 handling at scripts/ship-pr.sh:2117-2119.
- **Fixable job has no `_per_job_argv` mapping**: row goes to `unfixable[]`. Helper still attempts other fixable rows. If `unfixable[]` non-empty at end, consolidated `ci-local-unfixable:<list>` bail + `exit 3`. Consistent with `run_per_job_local_fix_loop` handling at lines 1962-1964.
- **Vendor fixer makes no changes** (`_RCC_STATUS=no-changes-stale`): job goes to `unfixable[]` rather than aborting all jobs — operator sees consolidated bail.
- **Empty TSV from `gh_logs_rc != 0` path**: explicit no-op-with-warning. Vendor proceeds with `relevant-checks.sh`-only gate (today's behavior). The warning surfaces the gap.
- **Bad env values for `LARCH_CI_LOCAL_FIX_ITER`** (empty, "0", non-numeric): the explicit clamp `case "$max_iter" in ''|*[!0-9]*|0) max_iter=3 ;; esac` in edit #1 forces fallback to 3. No infinite loop, no zero-attempt skip.
- **Multiple originally-failed fixable jobs, one fixes others as side effect**: `_run_per_job_command_once` runs FIRST for each job before fix loop engages — if already passing, no inner-budget iterations are burned.
- **Wall-clock cost**: bounded by classifier (8 fixable job kinds). Worst case `LARCH_CI_LOCAL_FIX_ITER=6` × 3 outer × N fixable jobs. Mitigated by (a) most CI runs fail 1-2 jobs, (b) early-exit on head-changed, (c) outer `_max_fix=3` unchanged.

## Failure modes (3 most likely)

1. **Head-changed routing regression** (most severe): if the new helper accidentally collapses rc=2 to rc=1 or any inserted command clobbers `$?` before capture, CI fixes committed by external coders would be silently dropped — exactly the #2909 bug. Earliest signal: regression of existing `ci_per_job_head_changed` test plus new `vendor_verify_head_changed` and `vendor_verify_rc2_on_gh_logs_failed_branch` tests. Mitigation: capture `verify_rc=$?` immediately after `_verify_failed_jobs_locally`; capture `vendor_rc=$?` immediately after `run_ci_fix_vendor` in BOTH call sites (lines 2127 and 2131); explicit `case 0|2|4|1|*` branching at every propagation boundary.

2. **rc=4 sweep regression contract gap**: if `_verify_failed_jobs_locally` returns 4 but `run_ci_fix_vendor` or `run_evaluate_failure` doesn't route it correctly (e.g., collapsed into rc=1), pushes proceed despite regression. Earliest signal: `vendor_verify_sweep_regression` test would fail. Mitigation: explicit `4) per_job_verification_retry=true ;;` arm at both vendor call sites.

3. **`_per_job_argv` map drift**: a new GitHub Actions job classified as `fixable` by `ci-failed-jobs.sh` but unmapped by `_per_job_argv` will silently drop into `unfixable[]`, causing `BAIL_REASON=ci-local-unfixable:<new-job-name>` + exit 3 on every CI failure for that job. Earliest signal: operator sees `ci-local-unfixable:<new-job-name>` in run logs. Mitigation: the existing `per-job argv dispatch table stays aligned with workflow jobs` test at scripts/test-ship-pr.sh:~3050 already guards against this (it checks `_per_job_argv` against the GitHub Actions workflows). Keep that test untouched.
