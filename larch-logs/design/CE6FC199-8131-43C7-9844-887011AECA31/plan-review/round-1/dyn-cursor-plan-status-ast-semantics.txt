## Findings

### 1. [major / correctness] Suppression token must use the `lint-` prefix

The plan binds both `rule_id` and `suppression_token` to `status-routing-truthiness`, while the scope anchor and planned `docs/linting.md` entry document `# lint-status-routing-truthiness: ok <reason>`. In this repo, CLI names drop the prefix (`unreachable-branch`) but `LintRule.suppression_token` keeps it (`lint-unreachable-branch` in `unreachable_branch_detector.py` and `lint_unreachable_branch.py`). The shared engine builds pragma regexes from `suppression_token` only (`engine.py`). If the new rule omits `lint-`, inline suppressions never match and grandfathering cannot work as specified.

### 2. [major / correctness] Engine-managed suppression needs an explicit contract

The plan correctly wants engine-managed suppression and occurrence assignment before suppression, but it does not pin how that differs from `lint_unreachable_branch`, which sets `allow_inline_suppression=False` and skips suppressed sites inside the detector. That sibling behavior contradicts `docs/linting.md` (“occurrence numbers are assigned before baseline or pragma suppression”). For this rule, the plan should require the engine-default path: `detect()` emits every bare site with a stable pre-suppression occurrence index, and the engine applies same-line filtering afterward. A regression test mirroring `test_occurrence_is_assigned_before_pragma_suppression` is the right guard.

### 3. [major / correctness] Pin `normalized_condition` to `ast.dump`

Occurrence baselines key on `normalized_condition` / `pattern_name`. The plan says “one stable AST representation” but does not point at the existing `normalize_expr` in `unreachable_branch_detector.py`, which uses `ast.dump(..., annotate_fields=False)`. Without that pin, two implementers could produce incompatible baseline identities for the same source.

### 4. [minor / correctness] Pin remaining `LintRule` baseline knobs

The approach section lists occurrence baseline and `normalized_condition`, but not `require_baseline=True` or `stale_baseline_on_clean_scan=False`. `lint_unreachable_branch.py` pins both. Adding them keeps fail-closed behavior aligned with neighboring occurrence ratchets.

### [OUT_OF_SCOPE] Ordering-comparison test gap

The scope says ordering comparisons must pass, but the planned test list does not name that case. Because bare-truthiness detection targets `if`/`while`/BoolOp/`not`/`bool()` nodes rather than `Compare` operands, this is unlikely to break acceptance. A dedicated negative test is optional polish, not a plan blocker.
