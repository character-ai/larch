# contract-unification [FEATURE] pytest wire-fixture factories + session builders

​#### Problem

Only 44 of 198 test files import the shared support modules (verified); the rest re-inline infrastructure below the R0801 8-line radar. Wire literals: finding blocks appear 726 times across 29 files, vote lines 220 across 15, panel-manifest slot JSON 170 across 13, plan bodies written 383 times across 32 files. Session plumbing: 33 files hand-write `session-env.sh` with divergent baseline envs; `test_implement_dispatch.py` calls its private `_session` builder 148 times; plugin-root derivation via `parents[N]` appears 215 times across 67 files. Fakes: 822 inline `CommandResult(...)` constructions across 59 files, 603 inline `CompletedProcess`, ~36 local Fake/Stub classes re-solving RecordingRunner. Plus 990 asserts pinning exact human-facing prose across 119 files and 243 redundant `LARCH_QUIET_DISABLE` re-sets that the root conftest already owns.

​#### Goal

A wire-fixture factory module (make_finding, vote_lines, slot_manifest, plan_body, result-env writers) plus session/design-dir builders and 2-3 RecordingRunner variants with `ok()`/`completed()` one-line factories, hosted in `test_support.py`/a sibling (respecting lint_flat_tests). Migrate the big-5 files mechanically; adopt a convention of asserting stable tokens rather than prose. A wire-format change becomes a 1-file edit instead of ~29.

​#### Size

Net reduction 4,000-6,000 lines; the drift-resistance gain matters more than the line count.

## Proposed Design Outline

### Goals
- Adopt `test_support.RecordingRunner`, `ok()`, and `completed()` across the five high-churn test files.
- Strip redundant per-test `LARCH_QUIET_DISABLE` sets covered by root conftest.
- Convert mechanical prose asserts to stable machine tokens in touched hunks only.

### Non-goals
- Replacing the keyed dict-based `RecordingRunner` in `test_ci_monitor.py` (keep it local).
- Replacing `StubRunner` in `test_checks.py` (calls-structure differs; would require broad assertion surgery).
- Changing any test behavior or assertions beyond the token-stabilization scope.
- Touching files outside the five targets and `docs/linting.md`.

### Approach sketch
- `test_review_and_fix.py`: add `from test_support import ok`; replace `proc.CommandResult(tuple(argv), 0, "...", "", 0.0)` with `ok(argv, "...")`; strip all redundant `LARCH_QUIET_DISABLE` monkeypatch calls.
- `test_agents.py`: add `from test_support import ok`; replace `CommandResult(tuple(argv), 0, "", "", 0.0)` lambdas with `ok(argv)`; preserve the one intentional `delenv` call.
- `test_ship.py`: already imports `RecordingRunner`; add `ok` to imports; replace inline `CommandResult(...)` lambdas with `ok(...)` where the argv is known.
- `test_checks.py`: keep `StubRunner` and `_ok()`; convert mechanical prose asserts to stable tokens in touched hunks only.
- `test_ci_monitor.py`: keep keyed `RecordingRunner`; add `from test_support import ok`; replace `_cr(argv, 0)` calls with `ok(argv)` where appropriate.
- `docs/linting.md`: add a short convention note: assert stable machine tokens, not full warning strings.
