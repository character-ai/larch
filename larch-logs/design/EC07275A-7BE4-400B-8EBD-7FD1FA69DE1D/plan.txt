## Implementation Plan

Zero-turn typed-keyword progress hook (`p`/`progress`): UserPromptSubmit shim → skill/step-aware `progress_report.py` engine.

---

### Design-time verification (items 13a, 13b from issue)

**13a — Block-reason display fidelity and length limit.** `UserPromptSubmit` with `decision=block` displays the `reason` field as plain text in the Claude Code terminal. The harness prints it to the terminal; no protocol-level truncation exists. At ~50-80 plain-text lines the report scrolls naturally. Use no ANSI escape codes. No truncation strategy needed for v1.

**13b — Delivery timing.** `UserPromptSubmit` fires at prompt-delivery time. During an active model turn the report appears when the turn ends (user types during the turn). The common case — idle orchestrator awaiting a task-notification — has no delay. No mitigation needed.

### Files to modify/create

### NEW: `scripts/hook-progress-report.sh`

Thin Bash shim registered under `UserPromptSubmit` in `hooks/hooks.json`. Responsibilities:

1. Read stdin with one `jq` invocation: parse `prompt`, `cwd`.
2. Trim prompt (strip leading/trailing whitespace). Exit 0 silently if `jq` is absent or stdin read fails.
3. Exact-match (case-sensitive, anchored): trimmed prompt equals `p` OR `progress`. No match → exit 0 silently (fast path, ~a few ms).
4. On match: invoke `python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" progress report --cwd "$cwd"`. Capture stdout into `_report`.
5. If `_report` is non-empty → output `{"decision": "block", "reason": "$_report"}` with exit 0. Prompt is blocked and displayed; model is never invoked.
6. If `_report` is empty (no live run) → exit 0 silently.
7. Any internal error at any step → `exit 0` silently (fail-open invariant from issue).

Bash 3.2-compatible. No `set -e` (hooks must never abort). Uses `command grep` not bare `grep` in any probe-style calls. Shellcheck-clean.

### NEW: `python/progress_report.py`

Stdlib-only module; `report_main(argv: list[str]) -> int` entry point.

**CLI**: `--cwd DIR` (required). Outputs the progress report to stdout. Returns 0 on success (including "no live run" → empty output), non-zero on usage/internal error.

**Live-run discovery** — scans `~/.cache/larch/sessions/`:

- Design pointers: files matching `current-design-env-*.sh` that are symlinks. For each: check symlink target exists and is a file (skip stale). Read the target file for `DESIGN_TMPDIR=`. Read `$DESIGN_TMPDIR/.larch-keepalive` for `CLONE_PATH=`. If `CLONE_PATH` == `cwd` → match.
- Implement pointers: files matching `current-implement-env-*.sh` that are regular files. For each: read `IMPLEMENT_TMPDIR=`, `REPO_CWD=`. If `IMPLEMENT_TMPDIR` dir exists and `REPO_CWD` == `cwd` → match.
- No match → return empty string (hook exits 0).
- Multiple matches → prefer the newest by file mtime; implements the "fallback to newest whose tmpdir still exists" rule.

**Step determination** (implement):

1. Read latest `mark` row from `$IMPLEMENT_TMPDIR/timing-ledger.tsv` (tab-separated; column indices: 0=`v1`, 1=type, 2=timestamp, 3=skill, 4=label). Latest mark = last row where column 1 is `mark`.
2. Read `$IMPLEMENT_TMPDIR/ship-pr-state.sh` with a simple `KEY=value` reader for `PHASE=`, `PR_NUMBER=`, `PR_URL=`. If file absent → PHASE empty.
3. Check `$IMPLEMENT_TMPDIR/progress/done` exists (Step 5 done marker).

**Step determination** (design):

1. Read latest `mark` row from `$DESIGN_TMPDIR/timing-ledger.tsv` same way.
2. Read `$DESIGN_TMPDIR/run-params.json` for `design_classification`.

**v1 renderer dispatch** (implement):

- **Step 5 active** (latest timing mark contains `"Step 5"` AND `progress/done` absent AND PHASE not `pr-create`/`merge`/`done`): call `_render_step5(implement_tmpdir, run_id)`.
- **Step 8+ active** (PHASE non-empty and not empty/implementation/checks, OR latest mark contains `"Step 8"`/`"Step 9"`/`"Step 10"`): call `_render_ship_pr(implement_tmpdir)`.
- **Otherwise** (any other step): call `_render_generic("implement", step_label, start_s)`.

**`_render_step5(implement_tmpdir, run_id)`**: resolves `run_id` (same lookup chain as `run-step5-review.sh`: session-env.sh `RUN_ID`, then single manifest under `larch-logs/implement/`). Shells out to `scripts/render-review-phase-detail.sh --rounds-root "$implement_tmpdir/larch-logs/implement/$run_id" [--timing-ledger T] [--token-ledger L] --skill implement`. Prepends a liveness header: `Step 5 code review — round N in progress` + elapsed since round start + `panel-manifest.ndjson` reviewer count derived from `$implement_tmpdir/round-N/panel-manifest.ndjson`. Captures stdout. Returns the combined header + table.

**`_render_ship_pr(implement_tmpdir)`**: reads `$implement_tmpdir/ship-pr-state.sh` for `PHASE=`, `PR_NUMBER=`, `PR_URL=`. Returns: `Ship-PR phase: {PHASE}\nPR: #{PR_NUMBER} {PR_URL}` (omit PR fields when absent).

**`_render_generic(skill, step_label, start_s)`**: returns `{skill}: {step_label} — started {elapsed} ago\nlast artifact: {mtime of most-recently-modified file in tmpdir}`.

**`_render_generic` for design**: analogous but keyed off design pointer.

**Error handling**: any subprocess failure or missing file → fall back to generic renderer or return empty string. Never raise; always return a string.

### UPDATED: `python/session_env.py`

Add two new verb implementations and register them in the CLI dispatch via `cli.py`.

**`write_implement_env_main(argv)`**:
- Accepts `--claude-pid PID --implement-tmpdir DIR --cwd CWD`.
- Validates: PID matches `^[1-9][0-9]{0,6}$`; DIR is an absolute path under allowed session root, exists; CWD is an absolute path.
- Writes `~/.cache/larch/sessions/current-implement-env-{PID}.sh` (regular file, NOT a symlink) with content:
  ```
  IMPLEMENT_TMPDIR=/abs/path/to/tmpdir
  REPO_CWD=/abs/path/to/repo
  SKILL_KIND=implement
  ```
  Atomic write (mktemp + mv, same pattern as other writers). Fails if target path is a symlink or ancestor is a symlink.
- Returns 0 on success; 1 on error (logs to stderr).

**`clear_implement_pointer_main(argv)`**:
- Accepts `--claude-pid PID`.
- Deletes `~/.cache/larch/sessions/current-implement-env-{PID}.sh` if present. Does not error if absent. Returns 0.
- Refuses to delete if the path resolves outside `~/.cache/larch/sessions/`.

Register both in `cli.py`:
```python
("session", "write-implement-env"): ("session_env", "write_implement_env_main"),
("session", "clear-implement-pointer"): ("session_env", "clear_implement_pointer_main"),
```

### UPDATED: `SECURITY.md`

Add a new section describing the `UserPromptSubmit` hook surface: it fires on every prompt submission in every repo where the plugin is loaded. The shim reads `prompt` and `cwd` from the harness-provided JSON. It is fail-open (any error → exit 0). No secrets are written; progress data is read-only from session tmpdir artifacts. No network calls.

---

### Approach

The hook shim is Bash, fail-open by design: any unexpected branch → exit 0. The Python engine is stdlib-only for runtime portability. Discovery enumerates stable pointer files rather than scanning all tmpdirs. The pointer file for implement is a real file (not a symlink) so it can be atomically deleted at teardown without leaving dangling symlinks. `progress/done` is a single empty marker file so the #3878 Monitor watcher can `inotifywait`/poll for its creation.

---

### Edge cases

- **Concurrent sessions in the same repo**: the single-runner invariant means at most one implement and one design pointer exist per repo cwd at any time.
- **Stale pointer (run crashed)**: `IMPLEMENT_TMPDIR` dir is gone → pointer skipped silently. `/cleanup` reaps these.
- **Multiple repos, same Claude session**: cwd matching selects the correct pointer; other-repo pointers are skipped.
- **Hook fires during model turn**: `UserPromptSubmit` fires at delivery. Common case (idle orchestrator) is unaffected. Narrow window during active turn → report appears after turn completes (acceptable).
- **`jq` absent**: first jq call in shim fails → exit 0 immediately (fail-open).

---

### Failure modes

1. **Pointer write fails in bootstrap** (network/permissions on `~/.cache/larch`): logged to `execution-issues.md`, run continues. Typing `p` shows "no live run" (silent exit 0), which is acceptable degradation.
2. **`render-review-phase-detail.sh` fails or returns empty** during `_render_step5`: fall back to `_render_generic` with whatever timing data is available.
3. **Hook times out** (10 s budget exceeded by slow Python startup): harness kills the hook process. The next `p` invocation attempts again; no permanent state written.

---

### Testing strategy

- `scripts/test-hook-progress-report.sh`: offline fixture tests for the Bash shim (match/no-match/no-run/fail-open). Register as `test-hook-progress-report` in Makefile.
- `python/test_progress_report.py`: pytest unit tests using `tmp_path` fixture; mock the subprocess call in `_render_step5` to avoid external dependency. Covered by `make py-test`.
- `python/test_stdlib_only.py`: auto-picks up `progress_report.py`; will fail if a non-stdlib import is added.
- `make py-lint`: covers type annotations and import validity.
- Bash 3.2 compatibility of `hook-progress-report.sh`: `make lint-bash32` and `make shellcheck`.
