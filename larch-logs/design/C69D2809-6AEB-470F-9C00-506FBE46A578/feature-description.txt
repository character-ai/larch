# architectural-knowledge-IV [FEATURE] Add guideline G-Root-1: resolve repo roots from run state, never ambient cwd

From the 2026-07-09 audit of the architectural-knowledge features.

**Motivation.** A recurring defect class has no guideline entry:

- #4490: the `/design` postplan validator required the repo root and ran from plugin-cache cwd; closed, then recurred via #4509.
- #4509: the plan-review loop runs from plugin-cache cwd, breaking the dirty-tree check.
- #6049: skill-closure and complexity baselines computed differently under plugin-cache `cli.py` versus the working repo, producing a false-pass loop.

The class: code that derives the repository root, or a search root, from the ambient working directory breaks when a step executes from the plugin cache, a sibling clone, or a session tmpdir. An in-repo example of the hazard boundary: `_resolve_repo_root` in `python/larch/core/architectural_guidelines.py` (lines 243-254) prefers `CLAUDE_PROJECT_DIR` and falls back to cwd only as a last resort.

**Required change.** Add one entry to `ARCHITECTURAL_GUIDELINES.md`. Proposed text, ready to adapt:

```markdown
## Execution roots

### G-Root-1: Resolve the repository root from persisted run state, never from ambient cwd
- Why: skill steps execute from varying working directories (the plugin cache, sibling clones, session tmpdirs), so code that derives the repo root or a search root from the process cwd breaks away from the operator clone; the postplan validator and plan-review loop failed from plugin-cache cwd (#4490, #4509), and baseline computations differed between plugin-cache and working-repo invocations (#6049).
- Guidance: read the root from the run's source env (`REPO_ROOT`), an explicit `--repo-root` flag, or `CLAUDE_PROJECT_DIR` resolved once at the trust boundary; treat any cwd fallback as a last resort that logs its use; never compose repo-relative paths from cwd in prompt-side Bash.
- Deviate when: an interactive, user-invoked helper documented to operate on the repo the operator is standing in, or a test that controls its own cwd.
```

Notes for the designer:

1. Section placement: a new `## Execution roots` section (proposed above, near `## CLI surface`) or an existing section; designer's call.
2. The ID must match `GUIDELINE_HEADING_RE` (`^###\s+(G-[A-Za-z0-9-]+-\d+):`); `G-Root-1` matches.
3. This is a guideline, not an invariant: legitimate cwd uses exist (interactive helpers, tests).

**Acceptance criteria.**

- `python3 python/cli.py architectural-guidelines read` includes G-Root-1 with its Why and Deviate bullets.
- The entry cites only the three verified evidence issues above.
