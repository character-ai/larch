### 1. correctness — Occurrence baseline field name mismatch (`python/larch/lint/engine.py:872-874`)

The plan requires full `run_rule` baseline delegation while preserving the legacy JSON schema with `normalized_condition` (`python/larch/lint/lint_unreachable_branch.py:40-42`). The shipped engine occurrence codec only accepts and serializes `pattern_name` (`python/larch/lint/engine.py:872-874`, `1113-1120`). The Approach preflight gate is right to stop if that gap remains, but the plan lists no firm fix while forbidding both `engine.py` changes and rule-local baseline plumbing. `test_baseline_schema_and_stale` and any non-empty baseline write cannot pass as written.

**Suggested revision:** Name an explicit upstream deliverable (firm `engine.py` update or dependency slice) that round-trips `normalized_condition` with stable key order, or narrow acceptance if the JSON field is intentionally renamed.

### 2. correctness — Scan scope not pinned to `python/larch/**` (`python/larch/lint/lint_unreachable_branch.py:805-807`)

Production today scans only `root/python/larch` (`python/larch/lint/lint_unreachable_branch.py:805-807`, `iter_source_files` at `93-103`). The plan mentions pathspecs but does not lock them to the larch subtree. Reusing markdown’s `python/**/*.py` pathspecs would widen detection and can change findings relative to the legacy detector and equivalence goldens.

**Suggested revision:** Pin `LintRule.pathspecs` to `python/larch/**/*.py` (or equivalent) and document that production scope must stay larch-only.

### 3. correctness — Suppression vs occurrence identity (`python/larch/lint/lint_unreachable_branch.py:479-494`)

The plan moves suppression to the engine, but legacy occurrence numbers are assigned only for non-suppressed hits and then renumbered per function (`479-494`, `545-554`). Engine post-detect suppression can leave occurrence gaps and break `(file, qualified_symbol, occurrence, normalized_condition)` identities. The markdown port keeps suppression in the detector and sets `allow_inline_suppression=False` (`python/larch/lint/lint_markdown_heading_fence_state.py:62`).

**Suggested revision:** Keep detector-side suppression and empty-reason failures, set `allow_inline_suppression=False`, and finalize occurrence numbering after suppressed hits are removed.

### 4. risk-integration — Missing LintRule and main() contract pins (`python/larch/lint/lint_markdown_heading_fence_state.py:119`)

Legacy always fails on stale baseline rows and parse errors with exit `2`. The plan does not pin `syntax_policy="raise"`, `occurrence_baseline=True`, or `strict_stale=not write` on check like the markdown port (`python/larch/lint/lint_markdown_heading_fence_state.py:111-120`). Default engine behavior can turn stale rows into warnings-only and syntax errors into exit `1`.

**Suggested revision:** Add explicit LintRule and `main()` wiring matching the markdown port for syntax, occurrence baseline, and strict stale handling.
