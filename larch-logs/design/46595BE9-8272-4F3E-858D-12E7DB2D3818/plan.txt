**5. `scripts/design-log-publish.sh`** (new)
Interface:
```
design-log-publish.sh --design-tmpdir PATH --run-id ID --issue N --repo OWNER/REPO [--dry-run]
```
Behavior (in order):
1. Validate `--run-id` with `larch_log_validate_slug run-id "$RUN_ID"` (F13)
2. Resolve `REPO_ROOT` via `git -C "$(dirname "$DESIGN_TMPDIR")" rev-parse --show-toplevel` (or `git rev-parse --show-toplevel`)
3. Refuse on default branch: call `current_branch_is_default` logic from `scripts/lib-larch-log.sh` — match `main`, `master`, and `origin/HEAD` (F6 was neutral/rejected, but this is still correct practice)
4. Resolve the integration base: `ORIGIN_DEFAULT=$(git symbolic-ref refs/remotes/origin/HEAD 2>/dev/null | sed 's#refs/remotes/origin/##' || echo main)`
5. Create a git worktree on a new branch from `origin/$ORIGIN_DEFAULT`:
   ```bash
   WORKTREE=$(mktemp -d)
   git -C "$REPO_ROOT" worktree add -b "larch-log-design-$RUN_ID" "$WORKTREE" "origin/$ORIGIN_DEFAULT"
   ```
   This keeps the original working tree untouched (F2). The log PR uses only the worktree branch.
6. Create target dir: `$WORKTREE/larch-logs/design/$RUN_ID/`
7. Create manifest.json using `larch-log.sh init`:
   ```bash
   "$CLAUDE_PLUGIN_ROOT/scripts/larch-log.sh" init \
     --log-root "$WORKTREE" \
     --skill design \
     --run-id "$RUN_ID" \
     --issue "$ISSUE_NUMBER"
   ```
   This produces a full schema-2 manifest with operator_cwd, larch_version, model_roster, steps_ran, etc. (F11)
8. Copy DESIGN_TMPDIR artifacts to `$WORKTREE/larch-logs/design/$RUN_ID/` with:
   a. Sidecar trimming (F3): for each `.meta` file, strip `CMD_JSON=...` lines; for each `*-output*.json` file, remove top-level `.result` field via `jq 'del(.result)'`; for each `.diag` file, copy as-is (no trimming needed)
   b. Redaction pipeline: `redact-tmpdir-paths.sh | redact-secrets.sh`
   c. Atomic copy: write to temp then `mv`
   d. Skip symlinks
   e. Depth-1 files + explicit recursion into `render-cache/` subdirectory (any other subdirs are skipped with a note in script output)
9. `git -C "$WORKTREE" add larch-logs/design/$RUN_ID/`
10. `git -C "$WORKTREE" commit -m "chore(larch-logs): flush design run $RUN_ID [skip ci]"`
11. `git -C "$WORKTREE" push origin "larch-log-design-$RUN_ID"`
12. Write PR body to a temp file
13. Run `"${CLAUDE_PLUGIN_ROOT}/scripts/create-pr.sh" --title "chore(larch-logs): design run $RUN_ID" --body-file "$tmpbody" --repo "$REPO" --base "$ORIGIN_DEFAULT"` (called from `$REPO_ROOT` — `create-pr.sh` uses CWD's git context, but we need the worktree branch, so cd into worktree or pass explicit branch hint)
    **Note**: `create-pr.sh` reads branch from `git rev-parse --abbrev-ref HEAD`. Since it's called from `$REPO_ROOT` (original branch), not the worktree, we need to pass `--base "$ORIGIN_DEFAULT"` and the head branch `larch-log-design-$RUN_ID`. Use `gh pr create` directly here since `create-pr.sh` doesn't support `--head`:
    ```bash
    PR_JSON=$(gh pr create --repo "$REPO" \
      --head "larch-log-design-$RUN_ID" \
      --base "$ORIGIN_DEFAULT" \
      --title "chore(larch-logs): design run $RUN_ID" \
      --body "Design run logs for issue #$ISSUE_NUMBER" \
      --json number,url)
    ```
14. Parse `PR_NUMBER` and `PR_URL` from JSON
15. `gh pr merge "$PR_NUMBER" --repo "$REPO" --squash --admin --delete-branch`
16. `git -C "$REPO_ROOT" worktree remove "$WORKTREE" --force`
17. Emit on stdout: `PUBLISH_OK=true`, `PR_NUMBER=N`, `PR_URL=url`
- On failure: emit `PUBLISH_OK=false`, `PUBLISH_ERROR=<token>`, exit non-zero
- `--dry-run`: skip git/gh ops, emit `PUBLISH_OK=true PUBLISH_DRY_RUN=true`

Bash 3.2-compatible. `set -euo pipefail`.

### Approach

**`[PLANNED]` prefix**: five-location edit in `tracking-issue-write.sh` + one in `lib-title-markers.sh`. All Bash 3.2-compatible. Update sibling docs `tracking-issue-write.md` and `lib-title-markers.md`. Add `[PLANNED]` to `find-lock-issue.sh`'s `has_managed_lifecycle_prefix` so /fix-issue treats [PLANNED] issues as machine-managed (excluded from /fix-issue targeting, consistent with [IN PROGRESS], [DONE], [STALLED]).

**Design log publish**: `scripts/design-log-publish.sh` creates an isolated git worktree on a fresh `larch-log-design-$RUN_ID` branch forked from `origin/HEAD`. It uses `larch-log.sh init` to produce a full schema-2 manifest, then copies DESIGN_TMPDIR artifacts with sidecar trimming (CMD_JSON / .result) followed by redaction. The git commit on the worktree carries `[skip ci]`. The PR is created via `gh pr create` with explicit `--head` pointing at the log-only branch. After `gh pr merge --squash --admin --delete-branch`, the worktree is removed. The original working tree's branch is never touched.

**SESSION_ID**: parsed from `session-setup.sh` output in Step 0b alongside `SESSION_TMPDIR`. Threaded to `design-log-publish.sh` as `--run-id`.

**REPO**: resolved in Step 5 via `gh repo view --json nameWithOwner` before rename/publish helpers are called.

**Clarify-loop coverage**: the clarify-loop exit path in Step 0b also calls the `[PLANNED]` rename and `design-log-publish` (same snippet as Step 5b) before exiting, ensuring designs completed via clarification get the same lifecycle treatment.

### Edge cases
- **Default-branch guard**: worktree branch check (`current_branch_is_default`) is bypassed because the worktree is on a new branch, not the default. The guard on the working tree ensures `design-log-publish.sh` is not called when on default (should not happen since `/design` creates a user branch, but defensive).
- **PR already exists for log branch**: rare (only if same run-id used twice); `create-pr.sh` / `gh pr create` returns an existing PR — proceed with merge.
- **Worktree cleanup failure**: if merge fails or the script is interrupted, `git worktree list` will show the dangling worktree. The operator can remove it with `git worktree remove --force`.
- **Sidecar trim failure** (jq absent or file corrupt): fail closed — do not copy the file and emit `PUBLISH_OK=false PUBLISH_ERROR=sidecar-trim-failed`.
- **SESSION_ID empty**: `design-log-publish.sh` guard `[ -n "${SESSION_ID:-}" ]` in SKILL.md skips publish with a warning rather than passing empty `--run-id`.

### Failure modes
1. **`gh pr merge --admin` fails** (`policy_denied`): emit `PUBLISH_OK=false`, print warning; logs are already committed locally on the log branch. Operator can manually push/merge.
2. **Redaction failure** (tmpdir-paths.sh or redact-secrets.sh unavailable): fail closed, no commit.
3. **`larch-log.sh init` fails**: emit `PUBLISH_OK=false`, abort without creating worktree content.

### Testing strategy
- `scripts/test-tracking-issue-write.sh`: `planned` state + idempotency
- `scripts/test-design-log-publish.sh`: happy path, default-branch guard, dry-run, sidecar trimming, slug validation, failure handling
- Manual smoke test: run `/design <issue>` end-to-end; confirm `[PLANNED]` on issue title and `larch-logs/design/<run-id>/` in remote main
