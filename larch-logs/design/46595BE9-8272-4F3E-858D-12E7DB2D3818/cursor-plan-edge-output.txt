1. **[risk-integration]** [scripts/session-setup.sh:306-340](scripts/session-setup.sh) — `/design` invokes `session-setup.sh` with `--skip-repo-check`, which skips the entire REPO derivation block, so `REPO` is usually never emitted on stdout. The plan’s Step 5 snippet threads `--repo "$REPO"` into `tracking-issue-write.sh`, `design-log-publish.sh`, and `gh pr merge`, leaving `REPO` unset in the documented parse contract. **Suggested revision:** derive repo the same way as `plan-block-write.sh` (`resolve_repo` / omit `--repo` when unknown), or stop skipping repo check for design, or extend Step 0 text to require parsing `REPO` when `emit_kv` prints it.

2. **[correctness]** [skills/design/SKILL.md:167-168](skills/design/SKILL.md) — Step 0 explicitly tells the orchestrator to parse `SESSION_TMPDIR` and reviewer availability lines, not `SESSION_ID`. The plan relies on `"$SESSION_ID"` for `--run-id` without adding a binding step. **Suggested revision:** parse `SESSION_ID` from `session-setup` output in Step 0, or read `"$DESIGN_TMPDIR/session-id"` (written by `session-setup.sh` around [scripts/session-setup.sh:279-283](scripts/session-setup.sh)) in Step 5 and reference that in the plan.

3. **[correctness]** [scripts/larch-log.sh:124-137](scripts/larch-log.sh) vs plan “default branch guard” — `larch-log.sh commit` refuses any **default** branch via `current_branch_is_default` (matches `main`, `master`, or `origin/HEAD` target), not merely `main`. If `design-log-publish.sh` only checks `main`, behavior diverges from the stated “mirror larch-log” claim. **Suggested revision:** share or copy the full `current_branch_is_default` logic, not a single hard-coded branch name.

4. **[architecture]** [docs/run-logs.md:71-75](docs/run-logs.md), [scripts/larch-log.sh:169-188](scripts/larch-log.sh) — The plan proposes a minimal `manifest.json` (`schema_version`, `skill`, `run_id`, `issue_number`, `status=done`) written ad hoc instead of `larch-log.sh init`, which normally materializes the full schema-2 envelope (`operator_cwd`, `larch_version`, `steps_ran`, etc.). **Suggested revision:** either generate a full-compatible manifest (init + `manifest` updates) or explicitly document a **separate** manifest profile for `larch-logs/design/` so downstream tooling does not assume implement-shaped JSON.

5. **[correctness]** [plan.txt](plan.txt) `design-log-publish.sh` copy rules — “non-recursive depth-1 for files; recurse one level into `render-cache/`” drops any other subdirectory trees under `DESIGN_TMPDIR` without surfacing an error, which is silent log loss if future steps stash artifacts in nested folders. **Suggested revision:** recurse with explicit include/exclude rules aligned with how design artifacts are laid out, or fail closed when unexpected directories exist.

6. **[code-quality]** [scripts/tracking-issue-write.sh:31-40](scripts/tracking-issue-write.sh), [scripts/tracking-issue-write.md:8-9](scripts/tracking-issue-write.md) — Top-of-file rename semantics and the markdown usage table still enumerate only `in-progress|done|stalled`. **Suggested revision:** extend both to include `planned` / `[PLANNED]` so the shipped contract matches behavior.

8. **[correctness]** [plan.txt](plan.txt) SKILL snippet — `tracking-issue-write.sh rename ... 2>/dev/null` hides stderr from `gh`, so operators only see the generic grep-based warning. **Suggested revision:** capture stderr to a file and surface `ERROR=` when `FAILED=true`.
