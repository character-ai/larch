### FINDING_1: SESSION_ID not parsed in Step 0
- **Concern**: The plan's Step 5 snippet uses `--run-id "$SESSION_ID"` but `/design` Step 0 only instructs parsing `SESSION_TMPDIR` and reviewer flags from `session-setup.sh` output — not `SESSION_ID`. The run-id passed to `design-log-publish.sh` would be empty or unset. [6 of 10 reviewers, important, correctness]
- **Suggested revision**: Extend Step 0 parsing to bind `SESSION_ID` from `session-setup.sh` emit_kv output (see `scripts/session-setup.sh:282-283`), or document reading `$DESIGN_TMPDIR/session-id`.

### FINDING_2: Current branch PR can merge unrelated commits
- **Concern**: `design-log-publish.sh` plans to push `$CURRENT_BRANCH` and call `create-pr.sh`, which returns any existing open PR for that branch. Calling `gh pr merge --squash --admin` on that PR merges the full branch delta, not just log files. `--delete-branch` then removes the remote feature branch. When the operator ran `/design` on an existing user feature branch with prior commits or an open PR, all that work gets squash-merged to main. [9 of 10 reviewers, important, risk-integration]
- **Suggested revision**: Use an ephemeral dedicated log-only branch forked from the default branch for the PR, containing only the `larch-logs/design/<run-id>/` commit. Never create/merge the PR from the user's feature branch.

### FINDING_3: Sidecar trimming missing before committing design logs
- **Concern**: The plan copies all DESIGN_TMPDIR files using only `redact-tmpdir-paths.sh` + `redact-secrets.sh`. Existing larch-log publication (`larch-log.sh write-round`) deliberately strips `CMD_JSON=...` from `.meta` sidecars and removes top-level `.result` from `*-output.txt.json` tool-envelope sidecars before committing, because those fields can contain full prompts, retry argv, or raw model output not intended for public logs. The generic redaction pipeline does not cover these. [6 of 10 reviewers, important, security]
- **Suggested revision**: Either use an explicit allowlist of artifact names (mirroring `larch-log.sh write-round`'s allow-list), or apply the same `CMD_JSON` / `.result` sidecar-specific trimmers from `scripts/lib-redact.sh` before redaction, failing closed on trim errors.

### FINDING_4: $REPO undefined in /design (--skip-repo-check skips derivation)
- **Concern**: `/design` calls `session-setup.sh --skip-repo-check`, which skips the `REPO` derivation block. The plan's Step 5 snippet passes `--repo "$REPO"` to `tracking-issue-write.sh`, `design-log-publish.sh`, and `gh pr merge`, but `$REPO` has no defined source in the skill text. The calls fail closed or target the wrong repo. [3 of 10 reviewers, important, correctness]
- **Suggested revision**: Add an explicit `REPO=$(scripts/resolve-repo.sh ...)` or equivalent `gh repo view --json nameWithOwner` call in Step 5 (before rename/publish) and thread it through all helpers.

### FINDING_5: Missing ${CLAUDE_PLUGIN_ROOT} prefix on new script invocations
- **Concern**: Plan's Step 5 snippets invoke `scripts/design-log-publish.sh` as a relative path. All existing Step 5 helpers use `${CLAUDE_PLUGIN_ROOT}/scripts/...` because the consumer working directory is the target repo, not the plugin checkout. A relative call fails with "command not found" in installed-plugin mode. [6 of 10 reviewers, important, correctness]
- **Suggested revision**: Use `"${CLAUDE_PLUGIN_ROOT}/scripts/design-log-publish.sh"` and `"${CLAUDE_PLUGIN_ROOT}/scripts/tracking-issue-write.sh"` matching existing Step 5 invocations.

### FINDING_6: Default-branch guard must use current_branch_is_default, not just "main"
- **Concern**: Plan says `design-log-publish.sh` refuses to run on main, "mirroring larch-log.sh commit". But `larch-log.sh commit` uses `current_branch_is_default` which matches `main`, `master`, and `origin/HEAD` default branch — not just `main`. A repo where the default branch is `develop` or `master` would bypass the guard if the script only checks for `main`. [5 of 10 reviewers, important, correctness]
- **Suggested revision**: Implement the guard using the same `current_branch_is_default` logic from `scripts/larch-log.sh:124-137` (or factor a shared helper), and align the edge-case prose.

### FINDING_10: find-lock-issue.sh has_managed_lifecycle_prefix doesn't include [PLANNED]
- **Concern**: `skills/fix-issue/scripts/find-lock-issue.sh:137-149` gates `/fix-issue` eligibility using `has_managed_lifecycle_prefix` which only knows `[IN PROGRESS]`, `[DONE]`, `[STALLED]`. After this change, `[PLANNED]` titles may remain eligible for `/fix-issue` targeting, or the exclusion behavior may be surprising. [2 of 10 reviewers, latent, correctness]

### FINDING_11: Partial manifest.json schema diverges from larch-log.sh init
- **Concern**: The plan hand-writes a minimal `manifest.json` (schema_version=2, skill, run_id, issue_number, status). `larch-log.sh init` produces a full schema-2 manifest with `operator_cwd`, `larch_version`, `model_roster`, `steps_ran`, `parent_skill`, `attempt`, `flags`, etc. Design run manifests advertise schema_version=2 but omit expected fields, causing schema drift for any consumer that reads these. [4 of 10 reviewers, latent, architecture]
- **Suggested revision**: Use `larch-log.sh init` and `larch-log.sh manifest` for manifest creation, adding a `--commit-message-suffix` extension or equivalent to get `[skip ci]` in the commit message.

### FINDING_12: `print` is not a Bash 3.2 builtin in SKILL.md snippet
- **Concern**: Plan's Step 5b snippet uses `print "**⚠ ...**"` for warnings, but `print` is not a Bash builtin (it's a zsh built-in); in Bash 3.2 this is a command not found error that can swallow the failure signal if the script ignores the exit code. [1 reviewer, nit, code-quality]
- **Suggested revision**: Use `printf '%s\n' "..."` in all bash code snippets.

### FINDING_13: RUN_ID not validated before path construction in design-log-publish.sh
- **Concern**: `design-log-publish.sh --run-id` should validate the value with `larch_log_validate_slug` (same as larch-log.sh does) before constructing paths. A malformed run-id (e.g., `../x`) could write outside `larch-logs/design/`. [2 of 10 reviewers, latent, security]
- **Suggested revision**: Call `larch_log_validate_slug run-id "$RUN_ID"` early in the script.

### FINDING_14: Non-recursive depth-1 copy silently drops nested DESIGN_TMPDIR subdirs
- **Concern**: Plan says "non-recursive depth-1 for files; recurse one level into render-cache/". Other nested directories (e.g., future step artifacts) are silently dropped with no error. [1 reviewer, important, correctness]
- **Suggested revision**: Either document the explicit include list (and that unknown subdirs are intentionally dropped), or fail closed when unexpected directories exist, so log incompleteness is surfaced rather than silenced.
