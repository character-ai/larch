1. **[risk-integration] `plan.txt:34-38`; `scripts/create-pr.sh:117-157`**  
Concern: the plan says to push `$BRANCH`, call `create-pr.sh`, then `gh pr merge --delete-branch`. `create-pr.sh` first returns an existing open PR for the current branch, so this is not guaranteed to be a standalone branch-scoped log PR. In nested `/implement` use, it could merge/delete the implementation branch before implementation proceeds.  
Suggested revision: create an isolated log branch from the default branch, pass it explicitly as the PR head, and only merge/delete that log branch. Test existing-PR and nested-session cases.
