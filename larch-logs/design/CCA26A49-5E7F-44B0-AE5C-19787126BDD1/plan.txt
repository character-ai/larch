# Implementation Plan — Issue #2899 (close-as-stale with two adjacent-doc wording fixes)

## Background

Issue #2899 is a combine-issues consolidation of #2858, #2859, #2860. Those three source OOS issues were closed as `COMPLETED` on 2026-05-26 by the combine-issues workflow when their content was consolidated into this issue — not by any PR fix.

Separately and coincidentally on the same day, PR #2892 (commit `fdfacb21`, `Fixes #2852: Fix ship-pr.sh stall when CHANGELOG.md is in bump commit`) landed and, in fixing the underlying runtime bug, also rewrote the docs at the three locations cited by OOS items A/B/C:

- `scripts/implement-finalize.sh:780-781` — the call at line 758 was changed from `git-amend-add.sh` to `commit-changelog.sh --version`; failure strings at 780-781 say `remained dirty after commit` (no "amend" wording).
- `scripts/drop-bump-commit.md` — documents `--allow-changelog-only` flag and walking-back drop mechanism explicitly; no "amended bump+CHANGELOG commit only" claims remain.
- `.claude/skills/bump-version/scripts/apply-bump.md:40-41` — rewritten in `fdfacb21` to say `drop-bump-commit.sh` "walks back from HEAD and drops the most recent matching bump commit" and "skips that [CHANGELOG] subject while walking back to the bump."

`grep -i amend` returns **zero matches** in all three cited files.

An adjacent-docs grep across the bump+drop-bump+CHANGELOG edit-in-sync graph then surfaced two residual stale-wording sites that still imply an "amend"-into-bump-commit pathway. This plan cleans up those two sites and closes #2899.

## Approach

Strict-minimum doc-only cleanup. The change is two single-phrase Edit-tool replacements, one per file. No script edits, no test changes, no behavior change. The phrase-replacement tactic preserves all other text in both files byte-identically — this minimises the diff and avoids triggering markdownlint MD038/MD037 false-positives on adjacent code spans.

Both edits live on the same `*.md` contract line that already covers the post-#2852 separate-CHANGELOG-commit behavior elsewhere on the line; the fix is exactly the in-phrase qualifier that remained stale.

After the doc edits, `/implement` proceeds through its normal flow: branch creation, the two Edit-tool replacements, version bump (PATCH per docs-only classification), CHANGELOG entry, run-log flush, CI, ship. The standard `/implement`-generated artifacts (`.claude-plugin/plugin.json` version bump, `CHANGELOG.md` entry, `larch-logs/implement/<RUN_ID>/` directory) are expected and not in tension with the "no other files modified" framing — see the Acceptance section for the precise scope statement.

After the resulting PR merges, post a short close comment on issue #2899 and close it. The comment template (with placeholder for the merged PR number):


## Edge cases

- **Markdownlint MD038/MD037 (no inner whitespace in code spans)**: both edits leave existing backticked tokens (`` `CHANGELOG` ``) intact and only modify outer non-code-span words. No new code spans introduced. Safe.
- **Edit-in-sync chains**: `scripts/git-commit.md` and `scripts/test-implement-finalize.md` are both sibling `.md` files for shell scripts under `scripts/`. Per `.claude/rules/script-md-siblings.md`, the contract update happens in the same PR, but only the `.md` files are touched here — the corresponding `.sh` scripts are not behaviorally affected, so no sibling-update obligation fires beyond these two files.
- **Idempotency**: re-running `grep -i amend` against the two edited files after merge must yield zero matches. This is the primary acceptance check.
- **Adjacent stale dead-code stub**: `scripts/test-implement-finalize.sh:275-281` defines a `git-amend-add.sh` stub gated on `STUB_AMEND_FAIL=true` (never set). This is dead code but the surrounding `git-amend-add.sh` script is intentionally retained per `scripts/git-amend-add.md:3` ("retained for future amend use cases"). Surface as OOS observation only — not in this plan's scope.
- **Historical CHANGELOG entries**: `CHANGELOG.md:1379` and `CHANGELOG.md:5692,6241` mention `git-amend-add.sh` in past-tense changelog entries. These are immutable historical entries — do NOT edit.
- **Close-comment placeholder substitution**: the close-comment template contains a `<MERGED_PR_NUMBER>` placeholder. The operator or `/implement` must substitute the real integer PR number before `gh issue comment`. The Acceptance section enforces this with a literal-text check on the posted body.

## Failure modes

1. **Edit collides with a concurrent in-flight branch on the same lines.** `scripts/git-commit.md` and `scripts/test-implement-finalize.md` were last touched at different commit eras; collision risk is low. Earliest warning: rebase conflict during `/implement` Step 8b. Mitigation: standard Phase 1 trivial-files auto-resolve does NOT cover `.md` files, so conflict-resolution.md normal classification applies. The two edits are single-phrase replacements on isolated lines; resolution is straightforward.
2. **Markdownlint regression on edited lines.** Both edits are mid-paragraph phrase deletions; markdownlint is unlikely to flag them, but stale wrapping rules in the long paragraph could surface MD013 line-length issues. Earliest warning: `make lint-only` step in `relevant-checks.sh`. Mitigation: the lines were already very long pre-edit; removing 2-4 words does not change wrap behavior.
3. **Posted close-comment contains an unsubstituted placeholder.** If `/implement` (or the operator) posts the comment body verbatim without substituting `<MERGED_PR_NUMBER>`, issue #2899 will be closed with a literal `<MERGED_PR_NUMBER>` token in its citation. Earliest warning: visible immediately in the posted comment body on GitHub. Mitigation: the Acceptance section's literal-text check below explicitly rejects the placeholder string from the posted body.
