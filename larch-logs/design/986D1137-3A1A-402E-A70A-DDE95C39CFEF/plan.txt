## Edge cases

- Codex absent design-panel behavior already has coverage. Do not widen this issue unless the new helper reuses that path accidentally.
- Round 3 requires both HARD cap and recorded escalation authorization. A HARD tier alone must still stop at 2.
- Escalation-trigger findings must be new. Avoid stale applied-finding ledgers in the test tmpdir.
- Bash stubs must fail closed when a supposedly blocked round launches.
- Seeded difficulty records must be resolution-persisted; otherwise `resolve_plan_review_tier` re-audits and clobbers the seed before the assertion runs.

## Failure modes

- A stub that emits fixed `PANEL_SHAPE` can mask a propagation bug. Derive the emitted value from parsed inputs (the captured `--tier`) or use a unique sentinel per case; keep `PANEL_SHAPE` (`singles`/`pairs`) distinct from the `--panel` threshold token (`simple`/`hard`).
- Asserting `PANEL_SHAPE`/cap KVs on step-5 wrapper stdout gives a false failure: those KVs live only in `review-core.env`. Assert against the capture path, not the wrapper.
- A non-persisted difficulty seed is silently re-resolved by the driver, so a "HARD" cap test can pass for the wrong reason. Persist the record (`build_record`/`write_record` or persistence markers) before `run_driver`.
- Reusing one tmpdir across tier cases can leak difficulty records or counters.
- Asserting exact full argv order can be brittle. Assert stable flag/value pairs.
- If any added test needs production changes, stop and correct the test plan.
