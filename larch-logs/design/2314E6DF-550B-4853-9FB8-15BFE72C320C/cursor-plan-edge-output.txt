**1. [correctness] Already-fresh must not enter the conflict loop**  
Steps 3–4 run sequentially: ancestor short-circuit skips `git rebase`, but step 4 always runs `_resolve_conflicts`, which calls `rebase --continue`. With no in-progress rebase, that matches `rebase-push.sh`’s `--continue` guard and fails. Bash on `SKIPPED_ALREADY_FRESH` (`rebase_rc=0`) skips conflict handling and goes to `_run_rebase_rebump_from_step3` (`scripts/ship-pr.sh` ~3431). **Revision:** branch orchestration so step 4 runs only when a rebase is in progress (or `_resolve_conflicts` no-ops without calling continue).

**2. [correctness] Missing classify/apply failure → `Stalled`**  
Step 5 lists `classify_bump`, regression guard, and `apply_bump` but not failure escalation. Bash stalls on classify/apply failure (`scripts/ship-pr.sh` ~3025–3082). Python `classify_bump` can raise `ShipError`; `apply_bump` returns `ApplyResult(applied=False, ...)`. **Revision:** document `Stalled` for classify failure and for `not apply_result.applied` before changelog tail and force-push.

**3. [correctness] Step 3 should distinguish conflict vs non-conflict rebase failure**  
Step 3 only spells out abort+`Stalled` when `unmerged_paths` is empty. Conflict failures (non-zero rebase, paths still `U`) must keep the rebase in progress and enter step 4—matching `rebase-push.sh --keep-on-conflict`. **Revision:** add an explicit branch in step 3 orchestration.

**[OUT_OF_SCOPE]** `run_rebase_rebump` pre-drop `refresh-run-logs.sh` and `ship_pr_pre_rebase_larch_logs_fixup` (`scripts/ship-pr.sh` ~3196–3236) are omitted; locked decision #239 defers larch-logs fixup to the future `ship.py` driver. Without equivalent pre-drop hygiene, `drop_bump_commit` can still hit Guard-1 `dropped=False` and `Stalled` where bash often recovers—track for Phase 7 driver wiring, not Phase 3 module scope.
