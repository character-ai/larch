> Part of the **ship-pr.sh → Python** rework. **Full plan, research findings, and cross-phase context: #3132.**

## Shared context (applies to every phase)

**Why this exists.** `scripts/ship-pr.sh` (~3,400 lines) is the `/implement` post-review state machine (rebase → checks → bump → PR → CI → merge → post-merge). Its high failure rate is the motivation for a typed, unit-tested Python rewrite under a new flat `python/` directory shared by all larch skills.

**Locked architecture decisions:**
1. **Single idempotent process** — recovery via gh/git **ground truth**, NOT a persisted state file. No `ship-pr-state.sh`, no `--resume-phase`.
2. **Strangler-fig cutover** — zero change to the live `/implement` path until Phase 7.
3. **Reimplement logic in Python** — shell out only to `git`, `gh`, agent CLIs, and the consumer test runner.

**Runtime vs. dev dependencies.** Runtime imports **stdlib only** (Python ≥ 3.12). `ruff`/`pylint`/`pyright`/`pytest` are **dev/CI-only**.

**Conventions:** flat `python/` (no subdirs); tests colocated `python/test_<module>.py`; constants in `config.py`; immutable frozen dataclasses; injectable `proc.run` seam; outbound text through `redact.py`.

**Quality bars:** pass **Python Lint** + **Python Tests**; **bash-parity test** per ported component; do not delete a shared `.sh` until a caller grep is zero.

**This phase is worked by `/design`**, then `/implement`.

## Phase 3 — Rebase component

A large, stateful unit: bring the feature branch up to date on `origin/main` and recover from conflicts autonomously. This is the first step of the top-level flow (and the `GOTO Rebase` target of the CI-monitor loop).

### Module to create
- **`rebase.py`**
  - rebase the branch onto `origin/main`;
  - **deterministic auto-resolve** of trivial / bump-only / CHANGELOG / auto-generated conflicts (uses `changelog.py` from Phase 2);
  - **drop the stale bump commit** (and its companion `Update CHANGELOG …` commit) before replay;
  - for **non-trivial conflicts**, invoke the **fixer-agent waterfall** in-process to resolve them — replacing today's bounce out to the LLM orchestrator via `conflict-resolution.md`;
  - **re-classify / re-bump** after a successful rebase (uses `version_bump.py`);
  - **force-push-with-lease**;
  - a **cap** on rebase attempts (escalate to `Stalled`/`NeedsUserInput` on exhaustion).

### `.sh` to port / read
`rebase-push.sh`, the `run_rebase_rebump` function in `ship-pr.sh`, `auto-resolve-changelog.sh` (shared with Phase 2), and the `conflict-resolution.md` procedure (the parts that are deterministic vs. the parts now handled by the in-process fixer).

### Acceptance criteria
- Parity vs `rebase-push.sh` for the deterministic paths.
- Conflict-fixer path exercised with a **stub agent waterfall** (no real `cursor`/`codex`/`claude`).
- Drop-bump / drop-changelog replay correctness; attempt-cap enforcement.
