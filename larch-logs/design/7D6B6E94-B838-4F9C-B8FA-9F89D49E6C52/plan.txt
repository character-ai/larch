## Edge cases

- `push force` must still emit `BRANCH=` before dirty-worktree failure when a branch exists.
- `push force --expected-remote-oid` must keep the same lease target as the deleted helper.
- `push branch` must preserve final non-zero push exit codes after all retries fail.
- `git rebase-abort` must still exit 0 when no rebase is in progress.
- `git snapshot-untracked` must still fail open and remove stale output on probe failures.
- `git check-remote-branch` must distinguish present, absent, and transport error.
- `git show-stage` stdout is raw file content. Do not route it through quiet logging.
- `git phantom-probe` in `step-8-ship.sh` must not contaminate the ship driver JSON stdout.

## Failure modes

- Retired path literals in tests or docs will break `make lint-retired-scripts`.
- Repointing `git-force-push.sh` to the wrong domain would fail because the existing CLI owner is `push force`, not `git force-push`.
- Deleting `lib-phantom-probe.sh` would break `rebase-checkpoint-probe.sh`; keep it unless a separate slice retires that script.
- Removing bash harness targets before pytest parity exists can lose regression coverage.

## Testing strategy

- Run focused pytest first:
  - `python3 -m pytest python/test_git.py python/test_phantom.py python/test_push.py -q`
  - `python3 -m pytest python/test_admission.py python/test_bootstrap.py python/test_implement_dispatch.py python/test_review_and_fix.py -q`
- Run script/structure tests touched by consumer rewrites:
  - `bash scripts/test-rebase-checkpoint-probe.sh`
  - `bash scripts/test-implement-fence-shape.sh`
  - `bash scripts/test-implement-structure.sh`
  - `bash skills/implement/scripts/test-step-8-ship.sh`
- Run migration and lint gates:
  - `make lint-retired-scripts`
  - `make py-lint`
  - `make py-test`
  - `make lint`
