## Findings

### 1. architecture — `python/larch/design/design_step5c.py:55`

`step2b5_main` is defined in `design_step5c.py`, not `design_step2b.py`. The plan groups step2b verbs under `design_step2b` and does not call out `step2b5` separately. A literal read routes `design step2b5` to the wrong module and dispatch fails at import/lookup time.

### 2. completeness — `python/tests/design/test_design_cli_ports.py:8-30`

The firm file list covers only `python/tests/test_cli.py`, but `test_design_cli_ports.py` pins eight repointed design verbs to `larch.design.design_lifecycle` (for example `step2b-drafter`, `step2b5`, `step5c`). That test will fail after the registry change and is the main automated guard for the acceptance rule that no registry row uses `design_lifecycle`.

### 3. correctness — `python/tests/design/test_design_step_log.py:16` (and related)

The 3-tuple registry shape breaks strict 2-tuple equality in `test_design_step_log.py`, `test_design_gate_render.py`, and `test_implement_dispatch.py`. The plan updates tuple handling only in `test_cli.py`, so CI can still fail on unrelated registry rows.
