## Plan

### sh-to-py P3: small user skills

Port the small shipped skill script surfaces to stdlib-only Python. The migrated surfaces are `/issue`, `/block-issue`, `/alias`, `/cleanup`, `/upgrade-larch`, and `/set-up-forked-open-source-repo`.

Direct callers must invoke:

`python3 "${CLAUDE_PLUGIN_ROOT}/python/cli.py" <domain> <verb> [args...]`

No shell shims are added.

Shared sourced libraries `scripts/lib-larch-dev-clone.sh` and `scripts/lib-sparse-dirs.sh` are retained in this PR. Their logic is ported into Python for `/upgrade-larch`, but the bash files stay on disk because `scripts/check-stale-plugin.sh`, `skills/implement/scripts/stall-recovery-report.sh`, `scripts/sessionstart-health.sh`, and their harnesses still source them.

### Approach

Create six Python modules and register their entrypoints in `python/cli.py`.

- `python/issue_create.py`: ports the `/issue` REST/helper scripts.
- `python/issue_block.py`: ports `/block-issue` GraphQL `addBlockedBy`.
- `python/alias_skill.py`: ports alias generation and target resolution.
- `python/cleanup_skill.py`: ports `/cleanup`.
- `python/upgrade_larch.py`: ports `/upgrade-larch` and release root resolution.
- `python/forked_repo.py`: ports forked repo setup and remote helpers.

Update `python/redact.py` before wiring `issue_create.py` to it. Preserve outbound redaction parity with `scripts/redact-secrets.sh`, including Cursor CLI `crsr_` key coverage.

Replace absorbed bash harness coverage with pytest. Update every live direct call site before deleting bash files. Append retired paths to `python/migrated-scripts.tsv`.

Run a tracked-file stale-reference sweep after `python/migrated-scripts.tsv` is updated. Replace full repo-relative references to deleted scripts with the Python CLI path or neutral historical prose before running `make lint-retired-scripts`.

### Stdout and stderr contracts

#### `issue parse-input`

Emit:

- `ITEMS_TOTAL=N`
- `ITEM_<i>_TITLE=...`
- `ITEM_<i>_BODY_FILE=...` only when the item body is non-empty
- `ITEM_<i>_REVIEWER=...` only when non-empty
- `ITEM_<i>_PHASE=...` only when non-empty
- `ITEM_<i>_VOTE_TALLY=...` only when non-empty
- `ITEM_<i>_MALFORMED=true` when malformed

Do not emit empty OOS field lines.

Preserve issue #138 behavior: malformed items with a non-empty body emit both `BODY_FILE` and `MALFORMED`. Title-only malformed items emit `TITLE` and `MALFORMED` only.

#### `issue create-one`

Preserve the full `create-one.sh` schema and exit codes.

Use `python/redact.py` for outbound issue-title, body, and captured-error redaction only after adding parity for the shell redaction families, including `crsr_` Cursor CLI keys.

On success emit:

- `ISSUE_NUMBER=N`
- `ISSUE_URL=url`
- `ISSUE_ID=id`
- `ISSUE_TITLE=title`

On failure emit:

- `ISSUE_FAILED=true`
- `ISSUE_ERROR=msg`

On `--dry-run` success emit:

- `DRY_RUN=true`
- `DRY_RUN_TITLE=title`
- `ISSUE_TITLE=title`
- `DRY_RUN_LABELS=L1,L2` when labels are present
- `DRY_RUN_BODY_PREVIEW=...` when preview output is present

Preserve exit codes `0`, `1`, `2`, and `3`.

Redaction failure is exit `3` and emits `ISSUE_FAILED=true` plus `ISSUE_ERROR=redaction:...`.

#### `issue add-blocked-by`

This is the `/issue` REST dependency helper. It must not emit the `/block-issue` GraphQL schema.

On success emit to stdout contract stream:

- `BLOCKED_BY_ADDED=true`
- `CLIENT=N`
- `BLOCKER=M`

On failure emit to stdout contract stream:

- `BLOCKED_BY_FAILED=true`
- `CLIENT=N`
- `BLOCKER=M`
- `ERROR=msg`

Preserve exit codes `0`, `1`, `2`, and `3`.

Preserve retry semantics:

- 3 attempts.
- Sleeps of 10 seconds then 30 seconds.
- 422 messages matching `already exists`, `already tracked`, `already added`, or `duplicate dependency`, case-insensitive, are idempotent success.
- 404 on the dependencies sub-resource is immediate no-retry feature-unavailable.
- Other 422s retry.

#### `block-issue add-blocked-by`

This is the `/block-issue` GraphQL helper. It must not emit the `/issue` REST schema.

Arguments:

`ISSUE_A ISSUE_B [--repo owner/name]`

Behavior:

- Resolve node IDs through `gh api graphql`.
- Invoke the native `addBlockedBy` mutation.
- Verify blocked-by membership after mutation.
- On lookup or mutation failure, emit `ERROR=msg` to stderr and exit `1`.
- On membership verification mismatch after a successful mutation, preserve current warn-only behavior: emit `WARNING=msg` to stderr, then still emit success stdout and exit `0`.
- On success emit `SUCCESS=true` and the confirmation line `✓ #A is now blocked by #B` on stdout.

Only share neutral helper code with the `/issue` REST path. Do not delegate `/block-issue` to the REST dependency POST implementation.

#### `issue allocate-candidates`

Emit exactly:

`CANDIDATES=<comma-separated>`

Always exit `0` except usage errors, which exit `1`.

Preserve union-credit semantics. A candidate already in the union still grants floor credit to every nominating item.

#### `issue list-issues`

Always exit `0`.

On success emit:

- `LIST_STATUS=ok`
- TSV rows: `<number>\t<title>\t<state>\t<url>`

On failure emit:

- `LIST_STATUS=failed`

Failure mode emits no TSV rows. Warnings go to stderr.

Port the `DEDUP_SKIP_PREFIX_FILTER` behavior from `scripts/lib-title-eligibility.sh`. Exclude archival and research-prefixed titles from the TSV. Sanitize titles by stripping tabs and newlines.

#### `issue fetch-issue-details`

Emit:

`FETCH_STATUS_<N>=ok|failed`

Exit `0` for per-issue partial fetch failures.

Exit `1` for usage and validation errors, including:

- missing or empty `--numbers`
- missing or empty `--output`
- unknown flags
- invalid `--max-comments`
- invalid `--max-body-chars`

#### `issue write-sentinel`

This helper is the exception to the contract-stream rule.

- On success, emit exactly `WROTE=true` to stderr.
- On skipped dry-run, emit exactly `WROTE=false REASON=dry_run` to stderr.
- On skipped failures, emit exactly `WROTE=false REASON=failures` to stderr.
- Emit `ERROR=msg` to stderr on arg errors.
- Never emit to stdout.
- Never emit through contract stream.
- Write sentinel atomically with mktemp plus rename.
- Exit `0` except arg errors, which exit `1`.

#### `issue cleanup-failed`

Emit:

- `CLOSED=true|false`
- `ISSUE=N`
- `ERROR=msg` when applicable

Always exit `0`.

#### `cleanup run`

Emit through contract stream:

- `SESSION_COUNT=N`
- `CACHE_REMOVED=N`
- `TMP_REMOVED=N`
- `SYMLINKS_REMOVED=N`
- `IMPLEMENT_POINTERS_REMOVED=N`

#### `upgrade-larch run`

Preserve quiet behavior:

- Initialize quiet mode like `quiet_init`.
- Restore stdout after quiet init, equivalent to `exec 1>&3`, so operator-visible plugin output remains visible.
- Machine-readable status keys go to stderr.

Stderr machine keys:

- `LARCH_RESTART_REQUIRED=true` when install or reconciliation requires restart.
- `LARCH_CONE_RECONCILED=true|false` after sparse-dir reconciliation.
- `LARCH_NEW_VERSION_INSTALLED=true` after a version upgrade completes.

Installed-version and operator-facing plugin lines go to restored stdout.

#### `upgrade-larch release-step7-root`

Emit:

`RESOLVED_ROOT=<path>`

This ports the cache-root resolution behavior from `release-step7-root.sh`.

#### `forked-repo setup`

Preserve the same stdout and stderr contract as `setup-forked-open-source-repo.sh`.
