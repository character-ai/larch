### 1. Harness fetch path duplication (risk-integration)

The live script still walks successful runs and calls `_collect_log_rows` per run:

```416:439:.claude/skills/rebalance-test-harnesses/scripts/rebalance.py
    # ------------------------------------------------------------------
    # Step 2: Fetch baseline timing
    # ------------------------------------------------------------------
    print(
        f"\n[2/9] Fetching timing from last {args.n_runs} successful CI runs "
        f"on {args.baseline_branch!r} …"
    )
    baseline_runs = gh.run_list_successful(
        _RUNNER,
        repo=repo,
        branch=args.baseline_branch,
        workflow=args.workflow,
        limit=args.n_runs,
    )
    ...
    for run in baseline_runs:
        print(f"  Fetching log for run {run.database_id} …")
        rows = _collect_log_rows(_RUNNER, run.database_id, repo=repo)
```

The plan adds a harness pre-write gate and extracts `ci_timing_fetch`, but it does not say to delete this loop. That is unnecessary duplication and a drift risk against the shared fetch helper.

### 2. Python packing contract gap (correctness)

`pack()` returns shard → target lists:

```10:11:python/harness_shard_packer.py
- ``pack(medians, n_shards, *, guard, extras)`` → ``{shard_n: [target, ...]}``
```

The assignments file needs the inverse (`nodeid → shard_id`). The plan states the target shape but not the invert step. Wrong JSON fails closed at collection, but the PR would still be broken until fixed.

### 3–5. Out-of-scope / scope-reduction

- **Golden CI log fixture**: real-format validation is valuable but not required for the rename + harness path; route to OOS.
- **Jobs-API Python verification**: outline explicitly chose asymmetric semantics; duration-only verification is weaker but in-bounds for v1.
- **Pack helper wording**: a single `_pack_nodeids` helper is simpler than conditional reuse prose.
