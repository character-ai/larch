- Treat `NO_SKETCHES` as binding. This plan comes from direct repo inspection.
- Honor the approved outline and Round 1 decisions as binding scope: hard rename, default `--kind all`, asymmetric verification, `--n-python-shards` mismatch aborts before writes.

- **Mirror the proven harness model with minimal duplication.** Add `python/pytest_ci_timing.py` for pytest-specific parsing and aggregation. Extract only the shared `gh.run_list_successful` + `gh.run_log_read` fetch loop into `python/ci_timing_fetch.py` so `harness_ci_timing.py` and `pytest_ci_timing.py` do not trip pylint `duplicate-code` (`min-similarity-lines=8`; CI runs `make py-lint-duplicate-code` separately from `make py-lint`). Keep attempt-boundary logic separate per format.
- **Baseline pytest packing must dedupe retried matrix attempts.** Before `compute_medians` in the Python rebalance path, filter parsed rows to the **latest attempt only** per `(run_id, shard)` via `_split_pytest_shard_attempts` (same rule as `shard_totals_per_run` / verification). Packing and LPT assignment must never double-count retried `python-tests` duration sections.
- **Safety first for test selection.** The assignment map can never reduce coverage. Malformed JSON raises at load (pytest collection fails loud). JSON booleans must never be accepted as shard ids (`isinstance(True, int)` is true in Python). A map whose `max(shard_id) != shard_count` is ignored in favor of full collection-index round-robin. Unassigned nodeids always round-robin by `(i % shard_count) + 1`.
- **Minimal `main()` change in `rebalance.py`.** Keep the harness packer, Makefile IO, partition validation, and warning-only verification unchanged. Add a `--kind` dispatch and extract only the branch/commit/push/PR and verification-trigger orchestration into shared helpers so both legs share one branch, commit, and PR.
- **Unified pre-write gate (no partial artifacts).** Before the first filesystem mutation, branch creation, or PR for any selected kind, run every applicable readiness check and in-memory packing. For `--kind all`, both harness and Python gates must pass before `write_shards`, assignments JSON write, branch checkout, or `git add`. On any gate failure, exit non-zero with no branch, no PR, and no partial writes.
- **Path-scoped artifact cleanliness gate (before first write).** After in-memory packing succeeds and before the no-op check or any disk write, require every kind-selected output path to be clean in git. Use `git.status_porcelain_paths(_RUNNER, path, cwd=_REPO_ROOT)` for each path that this run may mutate: `Makefile` when harness or `all`; `python/shard-assignments.json` when python or `all`. When porcelain output is non-empty for any required path, print an error naming the dirty path(s) and exit non-zero with no writes, no branch, and no PR. This prevents `_revert_written_paths` from resetting operator edits that existed before the run started.
- **Harness pre-write packing must match today's script.** When harness or `all` is selected, the gate phase must run the same measured-workload selection, LPT pack, and warning-only feasibility preflight as the current harness path: `measured = _select_packed_workload(medians, all_shard_targets)`, `new_shards = pack(measured, n_shards, guard=_GUARD)`, then `_check_feasibility(new_shards, medians, balance_threshold)` before any `write_shards`. Orphan baseline medians must not influence packing; the feasibility warning must not disappear.
- **Post-validate write failures roll back all touched paths.** After harness partition validation succeeds under `--kind all`, any failure writing `python/shard-assignments.json` must call `_revert_written_paths` for every path already written this run (at minimum `Makefile`) before returning non-zero. Do not leave a harness-only Makefile mutation without a matching assignments map.
- **Assignments JSON writes are atomic.** Serialize assignments to a temp file beside the target (`python/shard-assignments.json.<pid>.tmp`), then `os.replace` into `python/shard-assignments.json` only after serialization succeeds. Never leave a truncated or half-written checked-in map on disk. On any writer exception before replace, delete the temp file and leave the prior on-disk bytes unchanged.
- **Shared post-PR verification dispatch for every selected leg.** After PR creation, run the shared `n_verify_runs` `workflow_dispatch` + `_trigger_and_wait` loop whenever **any** selected leg needs post-PR verification (`harness`, `python`, or both under `--kind all`). Do not gate dispatch on the harness leg only. Leg-specific collection and fail-closed Python checks run only **after** those verification runs complete.
- **Preserve test seams.** Keep `_select_packed_workload`, `_check_feasibility`, `_report_wall_clock_balance`, `_collect_wall_clock`, `pack`, `_RUNNER`, `gh`, `ShipError` importable with current signatures so existing `python/test_rebalance_script.py` tests pass.
- **Default `--n-python-shards 4`** to match the active `python-tests` matrix in `.github/workflows/ci.yaml` (`shard: [1, 2, 3, 4]`, `PYTEST_SHARD_COUNT: "4"`). Reject a value that differs from the shard count observed in fetched `python-tests` rows. Never open a PR for a shard count CI does not run.

### NEW: python/pytest_ci_timing.py

- Stdlib-only parser for pytest duration rows in combined `gh run view --log` output. Mirror the runner seam of `python/harness_ci_timing.py` but use `ci_timing_fetch` for downloads.
- Frozen dataclass `PytestTimingRow(run_id: int, shard: int, shard_total: int | None, nodeid: str, seconds: float, attempt: int)`:
  - `shard_total` carries the `N` from `shard X of N` when present; `None` when only the job-name fallback supplied shard id.
  - `attempt` is the 0-based duration-section index within the `(run_id, shard)` log slice (see `parse_log`).
- `parse_log(log: str, run_id: int) -> list[PytestTimingRow]`:
  - Consider only lines whose job column (before the first tab) starts with `python-tests`.
  - Extract shard and total: prefer `shard (\d+) of (\d+)` anywhere on the line (`shard` = first group, `shard_total` = second group); else fall back to the final integer inside the parenthesized job name (`python-tests (3.11, 1)` -> shard `1`, `shard_total=None`).
  - Track attempt boundaries with pytest's duration report banner, not opening-nodeid repeats. Increment `attempt` on each new `slowest durations` section header line (match case-insensitive `slowest` + `durations` on the post-tab payload, e.g. `=== ... slowest durations ... ===`). Reset `attempt` to `0` at the start of each `(run_id, shard)` job slice when scanning the combined log.
  - After the second tab, strip an optional leading timestamp, then match a duration row `^(\d+(?:\.\d+)?)s\s+(setup|call|teardown)\s+(\S.*)$`.
  - Keep only `call` rows. Preserve the raw nodeid string verbatim. Ignore setup/teardown, malformed seconds, non-`python-tests` jobs, and non-duration lines.
- `fetch_timing_rows(runner, *, n_runs=5, workflow="ci.yaml", branch="main", repo) -> list[PytestTimingRow]`: delegate to `ci_timing_fetch.fetch_parsed_timing_rows`.
- `compute_medians(rows) -> dict[str, float]`: `{nodeid: median_seconds}` across the supplied row list (callers that need attempt dedup must filter first).
- `rows_latest_attempt_per_shard(rows: Sequence[PytestTimingRow]) -> list[PytestTimingRow]`:
  - Group by `(run_id, shard)`; within each group, keep rows from the attempt slice with the maximum `attempt` value (reuse `_split_pytest_shard_attempts`).
  - Return the concatenation of latest-attempt rows only. Used by baseline packing before `compute_medians` and documented as the packing input contract.
- `observed_shard_count(rows) -> int | None`:
  - Collect every non-`None` `shard_total` from parsed rows; when exactly one distinct total exists, return it (authoritative even when max shard id is lower because a shard had no `call` rows).
  - When multiple conflicting totals appear, return `None` (callers treat as hard failure with a conflict message).
  - When no `shard_total` was parsed, fall back to `max(row.shard)` across rows, or `None` when empty.
- `_split_pytest_shard_attempts(shard_rows: Sequence[PytestTimingRow]) -> list[list[PytestTimingRow]]`:
  - **Do not** port the harness opening-target splitter. Pytest `--durations=0` rows are sorted by measured duration, so a retried shard's second attempt can start with a different nodeid.
  - Group consecutive rows sharing the same `attempt` field (assigned during `parse_log` from duration-section banners). Each distinct `attempt` value is one job attempt for that shard.
- `shard_totals_per_run(rows) -> dict[int, dict[int, float]]`: group by `(run_id, shard)`, apply `_split_pytest_shard_attempts`, sum `call` seconds from the **latest attempt only** per shard.
- `median_shard_totals(rows) -> dict[int, float]`: median of per-run shard totals (built on deduped totals).

## Edge cases

- **No Python duration rows in baseline**: abort the Python leg in the pre-write gate before writing, naming `python-tests` and `--durations=0`.
- **Retried `python-tests` matrix job in baseline**: `rows_latest_attempt_per_shard` keeps only the latest duration-section attempt per `(run_id, shard)` before `compute_medians`; stale attempt timings must not influence packing.
- **Skipped or new tests**: tests absent from the map shard by collection index `(i % shard_count) + 1`, same as today.
- **Removed tests**: the next rebalance writes only measured nodeids, dropping stale keys.
- **Runtime shard-count mismatch**: pytest ignores a non-empty map when `max(shard_id) != PYTEST_SHARD_COUNT` (covers too-few and too-many ids), falling back to full round-robin.
- **Rebalance-time `--n-python-shards` mismatch**: abort in pre-write gate before writes, naming the observed CI shard count (or conflicting-totals error).
- **Shard 4 has no `call` rows but logs say `of 4`**: `observed_shard_count` returns `4` from parsed totals; rebalance proceeds when `--n-python-shards 4`.
- **Empty map `{}`**: `select_shard_nodeids` skips the `max()` guard and round-robins every index. CI behavior is byte-identical to today.
- **Malformed assignments JSON**: `load_shard_assignments` raises `ValueError`; pytest collection fails loud instead of silently dropping tests.
- **JSON boolean shard ids (`true`/`false`)**: rejected in `load_shard_assignments` via explicit `isinstance(v, bool)` guard and `type(v) is int` acceptance; a map like `{"pkg/test_foo.py::test_bar": true}` must not silently map to shard 1.
- **Timestamped or parametrized log lines**: the parser strips the timestamp and preserves the nodeid verbatim.
- **Orphan harness medians**: `_select_packed_workload` filters to `all_shard_targets` before `pack`; orphan baseline rows do not affect packing or feasibility totals.
- **Dirty kind-selected artifact before write**: cleanliness gate aborts with named path(s); no write, branch, or PR; operator local edits are preserved.
- **`--kind all` partition-validation failure**: revert `Makefile` only via `_revert_written_paths`; the checked-in assignments file is never written or modified.
- **`--kind all` assignments JSON write failure after partition validate**: revert every path written this run (at minimum `Makefile`); atomic write ensures assignments bytes stay at the prior `{}` or last-good map; no partial JSON.
- **`--kind python` assignments write failure**: temp file deleted; target file bytes unchanged.
- **`--kind all` Python pre-write failure**: no `Makefile` write, no assignments write, no branch, no PR.
- **`--kind python` with no harness leg**: post-PR `workflow_dispatch` still runs before Python verification collection.
- **Python verification with partial coverage**: for example only shards 1 to 3 present when `n=4`; hard failure listing the missing ids.
- **Retried `python-tests` matrix job with different opening nodeid on retry**: duration-section `attempt` tracking splits attempts; verification totals use latest attempt only.

## Failure modes when non-trivial

- **CI log format drift**: the Python parser may find no rows. Abort in pre-write gate with a clear message; zero rows after PR creation also fails closed with the PR URL.
- **Conflicting `shard X of N` totals in one run**: `observed_shard_count` returns `None`; abort before writes with a conflict message.
- **Baseline packing on undeduped retried rows**: prevented by `rows_latest_attempt_per_shard` before `compute_medians`; without it, assignments could be optimized on stale timings and fail Python verification.
- **Missing verification dispatch for `--kind python`**: prevented by kind-aware `_trigger_verification_runs`; Python fail-closed checks must not run against stale pre-PR logs.
- **GitHub CLI failure**: keep current explicit errors for run list, log read, workflow dispatch, PR creation, and verification.
- **Python verification spread over threshold or empty/incomplete timing**: leave the PR open, print the PR URL, exit non-zero (distinct from harness warning-only semantics).
- **Harness verification spread over threshold**: print the existing warning and tables; exit 0 (unchanged contract).
- **Harness feasibility over threshold pre-write**: print the existing warning-only `_check_feasibility` message; continue (unchanged contract).
- **Partial artifact commit under `--kind all`**: prevented by kind-aware staging that adds every changed selected path before commit, and by the unified pre-write gate.
- **Partial artifact write under `--kind all`**: prevented by `_revert_written_paths` on partition failure, atomic assignments write, and Makefile rollback on assignments failure after partition success.
- **Truncated assignments JSON on write failure**: prevented by atomic temp-file replace; pytest collection must never see a half-written map.
- **Rollback erasing pre-existing local edits**: prevented by path-scoped cleanliness gate before first write; `_revert_written_paths` only runs on paths the script wrote after a clean start.
- **Rollback after `git.add` or commit-hook failure**: `_revert_written_paths` restores staged index then working tree; paths are not left staged dirty.
- **Pylint duplicate-code on mirrored timing modules**: mitigated by `ci_timing_fetch.py` shared fetch loop; run `make py-lint-duplicate-code` before merge.
- **Stale map in a PR**: `make py-test` fails at collection (malformed or bool shard ids) or safely round-robins (mismatched count); coverage never silently shrinks.
