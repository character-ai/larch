### FINDING_1: `--kind all` lacks unified pre-write fail-closed gate
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation, Cursor-Pragmatic, Cursor-Requirements, Cursor-dyn-kind-all-write-ordering
- **Severity**: important
- **Concern**: Under default `--kind all`, harness and Python preflight checks are documented separately but not bound to run before the first filesystem mutation. If harness packing and `Makefile` write/partition validation run before Python baseline fetch, row-count, shard-count, and `untimed_targets` gates, a later Python-leg failure can leave a harness-only `Makefile` change on disk (or a partial PR) while rollback only reverts `python/shard-assignments.json` on partition failure, violating the requirement that Python abort conditions exit before writes and that operators never get a single-leg PR under `--kind all`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: In `rebalance.py` `main()`, add an explicit precondition phase for every selected kind: harness untimed gate plus Python row/shard-count checks must all pass before the first disk write; on any failure exit non-zero without creating a branch/PR
  - From Cursor-Innovation: State explicitly: for any kind that includes `python` (`python` or `all`), run Python baseline fetch, row-count check, and shard-count check before writing `Makefile` or `python/shard-assignments.json`; on failure exit non-zero with no branch/PR and no partial artifacts
  - From Cursor-Pragmatic: Run shared Python readiness checks (non-empty rows, observed shard count match) before any write/branch/PR for all; abort the whole invocation exit non-zero with no partial artifacts
  - From Cursor-Requirements: State explicitly in rebalance.py main() and rebalance.md: for --kind all, Python pre-write failures return non-zero before Makefile/JSON writes and before branch/PR creation; never stage a single-leg PR
  - From Cursor-dyn-kind-all-write-ordering: Add an explicit `--kind all` pre-write gate subsection before plan.txt:49-53: finish baseline fetch + medians + harness `untimed_targets` / no-row checks + python `observed_shard_count` / zero-row checks + in-memory packing for both legs; exit non-zero before any `write_shards` or assignments write when any gate fails.


### FINDING_2: Rollback after commit/push failure may leave paths staged
- **Reviewer(s)**: Codex-dyn-kind-all-write-ordering
- **Severity**: important
- **Concern**: Plan rollback relies on `git.checkout_paths` after staging, but `checkout_paths` runs `git checkout -- path` and does not unstage an already-added path. After `git.add` and a commit-hook failure, `Makefile` and `python/shard-assignments.json` can remain staged/dirty instead of fully reverted.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-dyn-kind-all-write-ordering: Add an explicit rollback helper for written paths that calls git.restore_staged before one git.checkout_paths call per path after git.add failures, and preserve original-branch restoration for post-commit push failures; cover this helper in python/test_rebalance_script.py


### FINDING_3: Shard-count validation ignores parsed `of N` total
- **Reviewer(s)**: Codex-Arch
- **Severity**: important
- **Concern**: Shard-count validation discards the parsed `of N` total and uses only the maximum parsed shard id. A valid 4-shard `python-tests` run can be rejected when shard 4 has no parseable `call` duration rows while shards 1–3 still report `shard X of 4`, causing `/rebalance-tests --kind python/all` to abort before writes even though CI runs 4 shards.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Arch: Carry the total from `shard X of N` into `PytestTimingRow` or a helper; have `observed_shard_count` prefer the unique parsed `N`, fail on conflicting totals, and use max shard id only as fallback

### FINDING_5: Pytest verification totals omit retry-attempt dedup

- **Severity**: important
- **Concern**: Pytest shard totals deliberately skip retry-attempt dedup, while the existing harness parser handles successful `gh run view --log` output that may include retried matrix job attempts.   - From Codex-Innovation: Mirror the harness latest-attempt handling for pytest rows before shard_totals_per_run sums a run/shard; keep only the latest attempt.
  - From Cursor-Pragmatic: Reuse or minimally port _split_shard_attempts into shard_totals_per_run/median_shard_totals, or document and test the accepted false-failure risk

### FINDING_6: Pytest retry dedup may double-count across attempts

- **Severity**: important
- **Concern**: Pytest retry dedup copies the harness opening-label splitter even though pytest duration rows are sorted by measured duration. A retried `python-tests` shard whose later attempt has a different first call row will not open a new attempt, so `shard_totals_per_run` can sum both attempts and fail a valid PR.

### FINDING_1: Bool JSON values accepted as shard IDs
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: `load_shard_assignments` JSON validation is underspecified for boolean shard values. The plan intends to reject non-integer shard ids, but `json.loads` maps `true`/`false` to `bool`, and `isinstance(True, int)` is `True` in Python. A map like `{"pkg/test_foo.py::test_bar": true}` can be accepted as shard 1 and silently mis-shard tests.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: Specify rejection with type(v) is int (or explicit isinstance(v, bool) guard per plan_scout.py) and add a test_pytest_sharding case for bool values


### FINDING_3: Rollback can destroy pre-existing local edits
- **Reviewer(s)**: Codex-Generic
- **Severity**: important
- **Concern**: Rollback can erase pre-existing local edits to selected artifacts. The plan writes and later rolls back `Makefile` and `python/shard-assignments.json` via `git.restore_staged` plus `git.checkout_paths`, but does not require those paths to be clean before the first write. If an operator has local edits, a partition, assignments-write, add, commit, or push failure can reset their edits to HEAD while cleaning up rebalancer output.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Generic: Add a path-scoped pre-write cleanliness gate for every kind-selected artifact before any write, or snapshot exact pre-run bytes and restore those bytes on rollback. Keep the rollback helper otherwise unchanged.
