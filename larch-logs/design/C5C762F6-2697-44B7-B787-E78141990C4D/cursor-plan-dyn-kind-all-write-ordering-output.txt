### Findings

1. **correctness** — `.claude/skills/rebalance-tests/scripts/rebalance.py` (plan § Write ordering `--kind all`, plan.txt:49-53). The plan correctly orders Makefile write → `_validate_partition()` → assignments JSON, and partition failure reverts only `Makefile` (plan.txt:51-52; matches rebalance.py:494-497). It does not contractually require that **all** pre-write abort gates for **both** legs complete before the first write. Python mismatch / zero-row aborts (plan.txt:58-59,159-163) and harness `untimed_targets` / empty-baseline gates (rebalance.py:441-474) live outside the write-ordering block. During the planned `--kind` dispatch refactor, an implementer could write the Makefile and then discover a Python-leg abort, leaving a dirty Makefile without the assignments file — the opposite of the intended partition-failure story.

2. **risk-integration** — `.claude/skills/rebalance-tests/scripts/rebalance.py` (plan § Failure rollback, plan.txt:53-54,68-69). The plan's `paths_to_stage` rollback matches `git.checkout_paths`'s single-path API (python/git.py:608-609) and extends rollback to post-assignments branch/commit/push failures for `--kind all`. It does not pin rollback to the active branch before returning to `original_branch`. The existing early-failure pattern already does Makefile `checkout_paths` then optional `original_branch` restore (rebalance.py:510-512); commit/push failures today skip `checkout_paths` entirely (rebalance.py:521-530). A shared helper must preserve the early pattern and apply the same per-path revert on the feature branch before switching back, or `--kind all` can strand partial artifacts.
