# [BUG] (URGENT) Compact reviewer status table rule fires for all immediate-background waits but…

## Symptoms

During a `/design` run, after the user approves Gate C and `/design` reaches Step 5c (the plan-write/publish step), the orchestrator prints:

```
📊 Reviewers: | design-step5c: ⏳ |
```

This reviewer-status-table format normally shows named reviewer slots (e.g. `Cursor-Arch`, `Codex-Innovation`) during Step 3 plan review. Seeing it in Step 5c — after all reviews are done and the user has approved — is confusing and implies reviews are still in progress when they are not.

## Context

The `/design` SKILL.md Progress Reporting section states:

> **Compact reviewer status table**: Use the twice-per-wait reviewer status cadence. Print a compact table exactly twice for **each immediate-background wait**.

Step 5c (`design-step5c.sh`) is launched with `run_in_background: true`, making it an immediate-background fence. The rule therefore fires.

However, the slot content and post-notification parsing are defined **only for Step 3 reviewer panels**:
- Slot names come from `$DESIGN_TMPDIR/latest-reviewer-status.tsv` — a Step 3 artifact.
- Post-notification says to parse `.step3-review-result.env` — also a Step 3 artifact.
- For Step 5c and the Final summary block, neither of these files contains anything meaningful.

## Root cause

The compact reviewer status table rule is scoped universally (`each immediate-background wait`) but its content semantics — slot names, TSV parsing, `.step3-review-result.env` parsing — are only defined for Step 3. When the rule fires for a non-Step-3 background fence, the slot content is **undefined by the skill**. The orchestrator fills the gap by inventing a slot name (`design-step5c: ⏳`), which is confusing and gives the wrong impression to the user.

The immediate-background fences affected (beyond Step 3 and its resume fence) include:
- Step 5c (`design-step5c.sh`)
- The Final summary block (`design-step-final-summary.sh`)

## Suggested fix

Option A (narrow): Scope the compact reviewer status table rule explicitly to Step 3 and its resume fence only. For all other immediate-background fences, replace the table with a plain progress breadcrumb such as `⏳ 5c: writing plan to GitHub…`.

Option B (general): Add an explicit clause: "When there are no known reviewer slots (i.e. outside Step 3 and its resume fence), skip the table and print only the standard step breadcrumb."

Option A is preferred — it is smaller and eliminates the ambiguity at the source rather than adding a conditional clause.
