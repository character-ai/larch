# bug-treadmill [FEATURE] analyze-bugs: blast-radius and class-completeness verdicts

#### Problem

Two recurring failure modes pass today's funnel by construction:

- Blast radius. The regression scan watches only the fix's own touched files (`later commits touching those files` plus a revert grep). #6931's verdict said "No later commits touch the file" while its sibling consumer crashed the same afternoon: #6946, `scripts/step-8-ci-fixer.sh` reading `TierSelectResult` field names that the Python side had changed. Cross-file and cross-language contract breaks are invisible.
- Class completeness. A fix that fully addresses the described instance gets `FIXED_CLEAR`, honestly, while sibling sites keep the class alive: #6610 to #6668, #6632 to #6672, #6882 to #6955. The funnel never asks whether the pattern survives elsewhere.

#### Required design

1. Bundle builder (`build_bundle_record` in `python/larch/issue/analyze_bugs.py`): extract changed symbol names from the fix diff (function and method defs, dataclass field names, and string-literal dict keys touched by changed hunks; regex extraction is acceptable, `ast` on the post-fix file version where cheap). Grep the repo for references to those symbols outside the touched files. Add a `## Consumers of changed symbols` bundle section listing `path:line` references, with non-Python consumers (`scripts/*.sh`, `skills/**/*.md`, hooks) explicitly tagged `cross-language`.
2. Widen the later-history and revert scans from touched files to touched-plus-consumer files. This changes `later_history_hash` inputs, so existing cache entries invalidate once; document that in the SKILL preflight notes.
3. Agent contracts:
   - `.claude/agents/bug-fix-triage.md`: add required JSONL field `introduced_risk` (string): the most plausible new defect this diff introduces in the listed consumers, or `none found`. Keep the strict-schema and evidence-token rules.
   - `.claude/agents/bug-fix-verifier.md`: add required JSONL fields `introduced_risk` (same contract, but verified with Grep against the checkout), `class_complete` (bool), and `sibling_sites` (list of `path:symbol` strings). The verifier must run at least one targeted grep for the fixed pattern outside the fix before setting `class_complete=true`.
4. Ledger ingest: accept the new fields with strict-key validation for rows produced by this version; rows missing the new fields are marked `legacy_schema=true` rather than rejected, so `--refresh` is not forced.
5. Report additions: an `Introduced risk` section (rows where risk is not `none found`, with the agent's evidence sentence) and an `Instance fixed, class open` section (rows with `class_complete=false` and their sibling sites). Class-open rows are appended to the follow-up body file behind the existing approval-gated `/issue` filing.

Consumer-scan unit tests including a cross-language fixture (a Python symbol referenced from a fixture shell script and a fixture SKILL.md); hash-widening test; strict-key ingest tests for new and legacy rows; report golden fixture with one introduced-risk row and one class-open row.

No runtime execution, no automatic filing, no sweep of unfiled bugs. Chronic-zone routing lives in the sibling analytics issue.
