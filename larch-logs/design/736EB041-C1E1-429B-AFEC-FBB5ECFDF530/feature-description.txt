Extend repeat-fingerprint silent-yield rule: Tier-1 probe prose, ambiguous contract, missing contract tests, and anti-pattern title

OOS items from PR #6332 (issue #6309):

1. Tier-1 probe rules still miss the repeat carve-out. The Tier-1 probe prose in AGENTS.md, orchestrator-never, and the Step 3 / Step 5c routing text still lacks a byte-identical repeat carve-out, so readers can keep following the old probe-on-non-empty rule instead of the silent-yield path.

2. Fingerprint matching contract is ambiguous. The rule says "byte-identical" repeats but fingerprints only the first 200 chars, so prefix-only matches can be misclassified as either new notifications or repeats.

3. Contract tests do not pin repeat-fingerprint literals. The acceptance harnesses only pin the empty-output and Step 3 terminal literals, so later prose edits could remove the repeat-fingerprint carve-out without failing CI.

4. Anti-pattern #5 title still implies empty-output only. The title still reads like an empty-output-only rule even though the body now covers repeat notifications, so a reader scanning the heading could miss the byte-identical repeat case.
