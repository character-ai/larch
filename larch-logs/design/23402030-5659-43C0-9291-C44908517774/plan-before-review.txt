## Approach

Create a shared, typed per-item adjudication engine over `voting.py`. The engine will own item iteration, outcome policy, score-row construction, classification-row collection, and OOS routing. Family hooks will supply vote inputs and render family-specific schemas and artifact formats.

Preserve all CLI entry points, status KVs, headers, paths, and caller contracts. Require a net line reduction.

## Drift-convergence review

Call out these intentional convergence changes in the implementation and PR:

- Both families compute neutral rescue, OOS fileability, score kind, and score result once in the shared engine.
- Both families use the same reroute-marker definition.
- Both families derive score and OOS-pool eligibility from the same adjudication result.
- Both families use the canonical `review_types.parse_blocks` FINDING/OOS parser through their existing ballot split and artifact paths.

Preserve these intentional differences:

- Classification TSV headers and family-specific columns.
- Vote-source adapters and degraded-panel behavior.
- Artifact filenames, accepted/rejected wrappers, OOS numbering, and final scoreboard presentation.
- Code-review scope-drift reclassification, which has no plan-review equivalent.

## Edge cases

- Empty ballots and zero effective voters must retain their current family-specific status and header-only outputs.
- Missing middle voter slots must keep column and severity alignment.
- Main-agent fallback must not be scored as an external panel.
- Neutral high-severity findings must route to OOS without becoming fileable unless the shared voting policy permits it.
- Rejected or non-fileable OOS items must never enter the aggregate public pool.
- Security OOS items must reach only the private sidecar.
- Neutralized ballots must retain restored proposer attribution and fail closed when the sidecar is missing or stale.
- Co-proposers and unique-finder bonuses must retain current attribution and weighting.

## Failure modes

- Abort before publishing partial public OOS artifacts when proposer restoration or security classification fails.
- Do not write a classification row from a partially built item result.
- Keep family-specific CLI error codes, diagnostics, and status KVs unchanged.
- Treat byte differences in TSV rows, scoreboards, tally-env rows, or Markdown artifacts as regressions unless listed as an explicit convergence change.
- Reject an extraction that increases total production lines or leaves parallel policy branches in both family modules.
