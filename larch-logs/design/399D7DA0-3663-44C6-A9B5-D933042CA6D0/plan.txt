## Edge cases

- `--repo` omitted for `plan-inherited`: preserve existing behavior. Missing blockers stay unknown.
- `--repo` provided but repo cannot resolve: skip enrichment and append a warning. Missing blockers stay unknown.
- Closed client issue: keep unknown or non-open client behavior unchanged. The scoped fix is closed blockers.
- Blocker lookup returns malformed JSON: leave absent, warn, and classify unknown.
- Blocker lookup returns `OPEN`: classify through existing safe or exception gates.
- Blocker lookup returns neither `open` nor `closed`: classify unknown.
- Source contributes to multiple combined hosts: existing multi-host closure block remains.
- Repeated source mapping fragments: promote to sorted unique arrays instead of overwriting.
- `satisfied_edges` in old plans absent: `close-eligible` treats missing field as empty.
- `close-stale --reason` invalid: fail before closing anything.
- `close-stale --comment-file` missing: fail before closing anything.
- `close-stale` partial success: return like `close-sources`, emit `PARTIAL=true`, and surface warnings.
- All fetched OOS items stale: require approval, run stale closure, report tally, and stop without creating combined issues.
- Mixed run with some fully stale sources and some actual items: close fully stale sources only after approval, then continue with approved combination work.

## Failure modes

- GitHub read failures during enrichment can leave sources ineligible. This is intentional fail-closed behavior.
- GitHub close failures in `close-stale` can leave stale issues open. Surface redacted warnings and `PARTIAL=true`.
- Invalid close reasons can otherwise make every stale close fail. Validate locally before mutation.
- Bad prompt-side accumulation of mapping fragments can still corrupt state. The new fragment and explicit merge rule reduce manual entry but do not replace validation by later JSON parsers.
- Stale closure approval can be denied. In that case, leave stale-only sources open and report them as not closed.
