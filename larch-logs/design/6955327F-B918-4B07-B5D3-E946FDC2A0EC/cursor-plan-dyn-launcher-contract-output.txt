**Findings**

1. **[correctness]** `scripts/launch-review.sh:502-504,928-933` — The plan states Codex/Cursor tiers run agentically with `--add-dir` over the output directory so they read context by path (`plan.txt` lines 12 and 59). Flag parsing accepts `--mode`, `--timing-task-kind`, `--diff-file`, `--scope-files`, and `--plan-file` (outer passthrough at `42-49`; inner handlers at `118-127` / `618-627`). `scout-dynamic-archetypes` is not rejected by `launch-review.sh` (only non-empty / non-flag-like check at `127`). `timing-ledger.sh` warns on unknown kinds (`208-209`) but does not block them.

   Codex review does pass `--add-dir "$CANON_OUTPUT_DIR"` (`502-504`), which matches session-scoped diff paths when output lives under the same tmpdir. Cursor review does not: it runs `cursor agent ... --workspace "$PWD"` (`928-933`) and `collect-agent-results.sh` forbids `--add-dir` on Cursor retry argv. After the path-only prompt change, a Cursor tier cannot read files under `REVIEW_TMPDIR` / `DESIGN_TMPDIR` outside the repo workspace, so the tier will usually produce non-JSON output, fail the unchanged `jq` gate, and fall through—defeating the intended Codex→Cursor→Claude waterfall for the common case.

2. **[security]** `.claude/settings.json:186`, proposed `scripts/launch-claude-subprocess.sh` `--read-tools` — The plan adds `claude --print --add-dir "$SESSION_ROOT" --allowedTools "Read Grep Glob"` and calls that allowlist “stronger than today's prompt-only preamble” (`plan.txt` line 19). Project settings set `"defaultMode": "bypassPermissions"`, and `docs/configuration-and-permissions.md` documents that `-p` children honor that mode. The plan leaves `--permission-mode` optional (“verified at impl time”). Without a pinned restrictive mode, the scout subprocess may still get write-capable tools despite the allowlist.
