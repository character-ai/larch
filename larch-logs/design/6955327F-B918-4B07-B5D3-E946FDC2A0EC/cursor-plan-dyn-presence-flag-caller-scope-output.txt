### 1. [correctness] `plan.txt:19` — cap-hit sibling path typo

The plan’s `tier_raw_is_scout_json` helper lists two cap-hit locations: `${raw_path%.raw}.cap-hit` and `${raw}.cap-hit`. For the scout waterfall, Codex is invoked with `--output` set to the tier raw path (today `raw_output="${OUTPUT}.raw"` in `scripts/scout-dynamic-archetypes.sh` around line 247). `launch-review.sh` writes the cap-hit sidecar as `${OUTPUT}.cap-hit` (see `scripts/launch-review.sh` around lines 185–186), so the real file is `*.raw.cap-hit`, not `*.cap-hit` with `.raw` stripped.

An implementer who follows the stripped form will never see the sidecar. Parse-gating on JSON still usually prevents a false win, but the documented fast-path is wrong and weakens the FINDING_1 guard against prose/`cap_hit` wins.

**Suggested revision:** In the plan and helper, check only `"${raw_path}.cap-hit"` (optionally also `head -1` == `STATUS=cap_hit` on `"$raw_path"`).
