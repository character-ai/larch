## Approach

1. Add a run-aware `progress deactivate` command around the existing hardened pointer removal.
   - Require lifecycle callers to supply their run ID.
   - Clear `current` only when it still names that run.
   - Keep SessionStart reset able to clear the active pointer after its own liveness check.
   - Preserve run directories and breadcrumb logs.

2. Remove the stale window at new-job entry.
   - Clear the prior pointer before design or implement setup can block on preflight or reviewer probes.
   - Separate reviewer probing from session creation where needed.
   - Activate the new session or requested run ID as soon as it is known, before reviewer probes.
   - Re-activate the persisted run ID on `--resume-plan-tail`.

3. Scope statusline liveness to the active run.
   - Read the active run ID once and use it for rendering and bgjob matching.
   - Treat only a live, in-budget registry entry with the same clone and `entry.run_id` as active work.
   - Apply that predicate to SessionStart reset, stale marking, and the one-hour hide.
   - Add `resume` and `compact` to reset sources.
   - Preserve `current` when the active run itself still owns live work.

4. Stop cross-run breadcrumb contamination.
   - Resolve a writer's run ID from its explicit command input or persisted process/session state.
   - Route asynchronous review, CI, ship, and timing writes through `append_breadcrumb_for_run`.
   - Do not fall back to `current` in daemon-capable paths.
   - Keep missing or invalid identity best-effort and fail-silent, matching existing progress telemetry behavior.

5. Deactivate at terminal lifecycle boundaries.
   - Design: successful pause-save, terminal failure staging, Step 0 abort, and Step 6 completion or terminal preservation.
   - Implement: teardown and standalone cleanup, including success and bail/stall outcomes.
   - Run deactivation only after required terminal state or pause artifacts succeed.
   - Use compare-and-clear semantics so a late old-run cleanup cannot clear a newer run.

## Edge cases

- `current` is absent, malformed, symlinked, non-regular, or changes between read and removal.
- A new run activates while an old run is entering teardown.
- A registry row matches the clone but not the active run.
- A matching row is alive but over budget, or the daemon is alive after its child exits.
- SessionStart receives malformed JSON, no source, no repository, or statusline opt-out.
- Step 0 fails before a session ID exists.
- A custom run ID differs from the session ID.
- `--resume-plan-tail` has missing or invalid persisted run identity.
- Pause publication or marker creation fails.
- Design Step 6 preserves artifacts but has no live work.
- Progress identity is missing in a telemetry-only writer. The primary operation must continue.
- A daemon writes after its run has been deactivated. Its old log may receive the row, but the row must not render unless that run is active again.

## Failure modes

- Do not clear a pointer merely because a lifecycle process believes it owns the clone. Require an exact run-ID match.
- Do not treat unrelated same-clone bgjobs as evidence that the active run is alive.
- Do not hide the active run when its own live, in-budget work remains.
- Do not make progress telemetry failures fail review, CI, ship, timing, pause publication, or terminal cleanup.
- Do not delete run logs during deactivation.
- Do not weaken existing fd-relative and symlink protections.
- Do not reintroduce reviewer probe results after activation in an order that changes degraded-tools routing.
- Do not let lifecycle deactivation happen before required pause or terminal artifacts verify.
