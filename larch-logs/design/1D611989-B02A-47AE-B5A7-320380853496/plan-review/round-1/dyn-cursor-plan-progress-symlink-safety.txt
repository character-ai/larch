## Findings

### 1. (correctness) Default append clone open must not mkdir — `python/larch/report/progress_file.py:181-198`, `:230-241`, `:336-350`

The plan’s edge cases say a missing clone progress directory makes default append return `False`. The shape it points at (`append_breadcrumb_for_run`) starts with `_ensure_directory_fd`, which creates missing directories (`python/larch/report/progress_file.py:181-198`). `_open_verified_dir` (`python/larch/report/progress_file.py:230-241`) opens only existing verified dirs.

If the implementer copies the for_run wrapper verbatim, append without a prior `activate_run` can mkdir an empty clone hash dir and then return `False` when `current` is absent. That satisfies “return False” but violates the no-side-effect fail-silent contract and leaves clutter under `progress_root()`.

**Suggested revision:** In the `append_breadcrumb` section, require `_open_verified_dir(clone_dir)` (catch `OSError` → return `False`) before `_read_active_run_id_from_dirfd`; reserve `_open_or_create_subdir` for the validated active run directory only.

### 2. (risk-integration) Stale flat-path TOCTOU test — `python/tests/report/test_progress_statusline.py:51-66`

`test_append_breadcrumb_rechecks_after_mkdir` asserts the current flat writer calls `larch_io.assert_no_symlink_path_or_ancestors` twice around `_ensure_directory` on `progress_path(repo_root)` (`python/larch/report/progress_file.py:121-128`). The plan’s fd-anchored default writer drops that path-based double-check in favor of `_open_verified_dir` / `_read_active_run_id_from_dirfd` / `_append_line_in_dir`.

The plan lists many test updates but not this one. After the flip, the test will fail or falsely imply flat-path recheck coverage still applies to production default writes.

**Suggested revision:** Add an explicit test-plan bullet to update or replace `test_append_breadcrumb_rechecks_after_mkdir`, mirroring `test_append_breadcrumb_for_run_pins_run_dir_after_fd_acquisition` (`python/tests/report/test_progress_statusline.py:348-376`) for default `append_breadcrumb` after `activate_run`.

**Review note:** The planned statusline helper using path-based `_read_active_run_id` (`python/larch/report/progress_file.py:369-385`) while append uses `_read_active_run_id_from_dirfd` (`python/larch/report/progress_file.py:388-410`) is an intentional asymmetry in the plan; `_tail_breadcrumbs` (`python/larch/report/statusline.py:63-75`) remains the log safety gate. Legacy flat reads go away when `render_statusline` stops calling `progress_path` (`python/larch/report/statusline.py:122`). Acceptance coverage for run isolation, missing/invalid `current`, legacy flat ignore, active mtime, and symlink fail-silent is otherwise aligned with landed helpers and Piece 3 activation (`python/larch/state/bootstrap.py:502-503`, `python/larch/design/design_step0.py:199-211`).
