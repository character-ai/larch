Reviewing the codebase to align the revised plan with existing helpers and tests.
## Plan

Implement the final production flip for run-scoped progress breadcrumbs. Keep the existing call-site API unchanged.

Use the already-landed run layout:

`~/.cache/larch/progress/<clone-hash>/current`
`~/.cache/larch/progress/<clone-hash>/<run-id>/breadcrumbs.log`

Treat `current` as required for default writes and reads. Missing, invalid, unreadable, symlinked, or corrupt state must fail silent.

Do not change `activate_run`, cleanup, retention, or `progress note --run-id`.

## Approach

Flip `append_breadcrumb` and `render_statusline` from flat clone-level `progress_path` to the active-run pointer and run-scoped `breadcrumbs.log`.

Default writers and readers both resolve the clone directory through the existing fd-safe helpers, then read `current` through `_read_active_run_id_from_dirfd` on the verified clone dir fd. Do not use path-based `_read_active_run_id` in production reader code.

Expose a small public active-run reader in `progress_file.py` so `statusline.py` does not import private helpers or need lint suppressions.

Leave `append_breadcrumb_for_run` as the explicit override path for `progress note --run-id`.

### UPDATED: docs/progress-reporting.md

Document the final per-run contract.

Update the prose to say:

- Breadcrumbs are scoped by clone and active run ID.
- The active pointer is `~/.cache/larch/progress/<clone-hash>/current`.
- The active breadcrumb log is `~/.cache/larch/progress/<clone-hash>/<run-id>/breadcrumbs.log`.
- Default writers require a valid `current` pointer and no-op fail silent when it is missing or invalid.
- The reader follows `current` via fd-safe clone-dir open and tails only the active run log.
- Legacy flat `<clone-hash>.log` files are ignored by the reader.
- A fresh run starts empty because `activate_run` points at a new run directory.
- Larch assumes one active larch run per clone. Do not add concurrency semantics.
- Staleness uses the active run log mtime; live clone bgjobs still suppress stale text.

## Edge cases

- Missing clone progress directory: default append returns `False`; statusline renders empty.
- Missing `current`: default append returns `False`; statusline renders empty.
- Invalid `current`: default append returns `False`; statusline renders empty.
- Missing active run log: statusline renders empty.
- Legacy flat log exists: statusline ignores it.
- Prior run log exists with newer or older mtime: statusline ignores it unless `current` points to that run.
- Symlinked pointer, clone dir, run dir, log, or ancestor: fail silent and do not write outside the progress root.
- Corrupt log content: `_tail_breadcrumbs` keeps filtering to valid breadcrumb rows.
- TOCTOU swap of run dir after fd acquisition: default append must not write outside the intended cache tree (fd-pinning test).

## Failure modes

- If `append_breadcrumb` still calls `progress_path`, fresh runs can show stale prior-run rows. Tests must assert no flat log is created.
- If the reader falls back to flat logs when `current` is missing, old rows can reappear. Tests must pin empty output.
- If `_age_suffix` uses the wrong path, stale text can follow an old run. Tests must pin active-run mtime.
- If the default writer uses path-based open instead of fd-safe helpers, symlink swaps can escape the intended cache tree. Keep the fd helper path.
- If tests only cover `append_breadcrumb_for_run`, the production default may remain unflipped. Add direct default-writer tests.
- If `test_append_breadcrumb_rechecks_after_mkdir` is left unchanged, the targeted pytest run fails or passes vacuously without exercising fd-anchored default-append guards.
- If `statusline` reads `current` path-based or imports `_read_active_run_id`, symlink races or Ruff/pyright private-usage violations can slip through.
