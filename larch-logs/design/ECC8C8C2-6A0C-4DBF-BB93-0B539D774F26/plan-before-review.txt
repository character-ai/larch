## Edge cases

- `mkdir -p` succeeds but `state_dir` is swapped to a symlink before `chmod`: the new post-`mkdir` guard exits 0 before `chmod`.
- `state_dir` passes the pre-read guard, then is swapped before `mktemp`: the new pre-`mktemp` guard exits 0 before temp creation.
- A symlink swap happens after `mktemp`: existing pre-write and pre-promotion checks still remove `tmp_state` when possible and exit 0.
- A leaf `state_file` symlink exists: existing tests and guards keep replacing it with a regular state file without following it for reads or writes.
- `jq`, `cksum`, `date`, `mktemp`, or filesystem operations fail: preserve current exit-0 hook behavior.

## Failure modes when non-trivial

- The test variant could remove the new pre-`mktemp` guard by accident, making the positive check meaningless. Avoid this by constructing the deep-guardless variant with a specific protected occurrence next to `mktemp`.
- The fully guardless negative control could fail if later guards still block promotion. Its assertions should accept either a temp file or a state file in the redirect, but it must prove attacker-controlled storage received hook output.
- `chmod` on a symlinked directory may affect the redirect target in the guardless variant. Keep the redirect under the harness temp dir and clean it with the existing trap.
- Bash 3.2 compatibility matters. Use POSIX-style shell constructs already present in the harness. Avoid arrays, `mapfile`, namerefs, and case-conversion expansions.
