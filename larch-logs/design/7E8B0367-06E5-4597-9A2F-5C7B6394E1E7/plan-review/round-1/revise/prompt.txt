# Implementation Plan: Stop the /design scope-creep ratchet (#3512)

Two coupled loop-level changes, plus the operator-chosen full removal of the `--manual` surface.

## Approach

Three threads, all in the `/design` Step 3 review path:

1. **Remove inter-round auto-apply → single review pass.** `plan-review-loop.sh`'s multi-round path revises `plan.txt` between rounds via `revise-plan-with-waterfall.sh` and re-reviews the bloated result (loop body lines ~1728-1887). Delete the revise / post-apply / loop-again machinery so each Step 3 entry runs exactly one review round and never revises the plan. Gate B (Step 3.5) becomes the sole apply point. Keep the richer single-round error handling (`panel-failed`, `tally-error`, `degraded-empty-collector`, zero-findings, `main-agent-vote-required`).

2. **Add a cumulative drift guard at Step 2b.5.** Capture a tier-agnostic baseline (plan body lines + diff estimate) once at the initial Step 2b. On later Step 2b.5 runs (after each Gate B apply, after discussion-round2), compare the current plan against that baseline. When growth exceeds a multiple (`LARCH_DESIGN_DRIFT_MULTIPLE`, default `2`), surface it to the operator with an `AskUserQuestion` (Continue / Cancel) and block silent auto-continue. The drift guard backstops the residual ratchet across Gate-C "Re-run review panel" loops.

3. **Remove `--manual` / `-m` / `manual_gate_b` entirely** (operator decision). With no auto-apply on either tier, the `manual_gate_b=false` auto-apply branch is deleted; Gate B always presents accepted findings for explicit operator choice.

Reuse decisions (keep the change minimal):
- Drift logic lives in the existing `check-plan-size.sh` + Step 2b.5 plumbing, not a new helper.
- Baseline is written by `design-postplan-emit.sh --snapshot-original` (already the initial-Step-2b-only call) on **both** tiers — fixing the SIMPLE gap where `plan.txt-original` is HARD-only today (`design-postplan-emit.sh:457`).
- Drift-cancel reuses `SUMMARY_OUTCOME=cancelled-sprawl` (drift is sprawl) — no new render-final-summary outcome.
- The **outer** Gate-C re-review counter (`review-round-count.txt`, tier cap SIMPLE=3 / HARD=5) is unchanged — only the **inner** auto-apply loop is retired.

Coordination: the issue-anchoring sibling also edits `plan-review-loop.sh` but in the scope-anchor materialization region (lines ~140-200); this change edits the loop body (revise/convergence, lines ~1728-1887). No logical overlap, but expect a textual merge.

## Edge cases

- **Baseline missing** (resumed pre-upgrade run, or `drift-baseline.env` unreadable): `check-plan-size.sh` emits `DRIFT_TRIGGER_FIRED=false`; Step 2b.5 skips the drift branch. No crash.
- **Initial Step 2b.5**: baseline just written, current == baseline, ratio = 1 → no drift trigger.
- **Both hard size trigger and drift fire**: hard size trigger wins (Split / Cancel, no Continue). Drift branch only fires when `HARD_TRIGGER_FIRED=false`.
- **`--manual` on argv after removal**: rejected as an unrecognized flag by `parse-design-argv.sh` (hard error before Step 0), matching the documented allowlist behavior.
- **`manual_gate_b` present in a stale `run-params.json`** (resumed run): harmless — all readers are removed; Gate B always prompts.
- **Single-pass zero-findings**: empty `accepted-plan-findings.md` → Gate B zero-findings short-circuit (unchanged) → Step 3.6 (HARD) → Step 3b.
- **`LARCH_DESIGN_DRIFT_MULTIPLE` invalid** (non-numeric / ≤0 / leading zero): fall back to default `2` with no error (mirror the `LARCH_DESIGN_PLAN_SUMMARY_THRESHOLD` coercion pattern).

## Failure modes

- **Branch-matrix drift between SKILL.md and the reduced `LOOP_STATUS` enum.** Earliest signal: `test-design-structure.sh` / `test-step3-orchestrator-fence.sh` fail on the status regex. Mitigation: update the enum regex and the branch matrix in the same commit; the harness pins both.
- **Step 0-pre KV-count desync.** Removing `MANUAL_REQUESTED` without flipping `8 → 7` aborts every `/design` run at Step 0-pre ("success output was incomplete"). Earliest signal: `test-parse-design-argv.sh` + a live argv parse. Mitigation: edit `parse-design-argv.sh`, the SKILL.md Step 0-pre block, and `test-step0b-router-flag-recovery.sh` together.
- **Drift baseline written on the wrong call.** If the baseline is (re)written on a non-initial emit, drift always reads 1× and never fires. Mitigation: gate the write strictly on `--snapshot-original`; add a `test-design-postplan-emit.sh` assertion that re-emit without `--snapshot-original` does not touch `drift-baseline.env`.

# /design review: stop the scope-creep ratchet (no auto-apply + drift guard)

## Context

Motivated by the `/design` run on issue #3482 (SIMPLE ~85-line reorder auto-expanded to a 396-line refactor across 5 review rounds). Sibling of the issue-anchoring issue and the assessor-on-SIMPLE issue. Even with reviewers/voters anchored to the issue, two **loop-level** mechanisms let the plan ratchet upward.

## Problem

- **Auto-apply re-baselining.** With `manual_gate_b=false` (the SIMPLE default), `plan-review-loop.sh` writes each round's accepted findings into `plan.txt`, and the **next** round reviews the bloated result — never re-anchoring to the issue. In #3482 round 1's tiny "admission" footer seed became round 2's `ADMISSION_READY` machinery, which became rounds 3–5's `--scrub-only` / `RENAME_NOOP` elaborations. Each round's findings were locally valid against the prior round's plan.
- **Drift-blind convergence.** The loop's convergence rule halts on "few important findings **this round**," never on "the plan has ballooned vs the issue." In #3482 it never converged (accepted counts 3 → 6 → 6 → 10 → 5) and ran to the 5-round cap, because every round honestly found important *internal-consistency* gaps in the growing machinery.

## Proposed change (candidate directions — `/design` will choose)

- **Remove auto-apply re-baselining entirely — no auto-apply, ever, on both tiers.** Accepted findings are surfaced at Gate B and applied only by explicit operator choice (or a single review pass with no inter-round auto-revision). This is a deliberate operator decision, not a per-tier default.
- **Add a cumulative drift guard.** Halt or flag the loop (and block any auto-continue) when the plan body or diff estimate grows beyond a threshold multiple of the issue's initial Step-2b estimate, surfacing the drift to the operator instead of silently accreting.

## Scope / acceptance

- `plan-review-loop.sh` no longer auto-applies accepted findings between rounds; Gate B (`SKILL.md` Step 3.5) becomes the sole apply point; `run-step3-review.sh` / the Step 3 post-loop branch matrix and `approval-gates.md` updated to match.
- A run whose plan grows past the drift threshold halts/flags instead of silently accreting (new regression coverage).
- Existing harnesses (`test-plan-review-loop.sh`, `test-step3-review-cap.sh`, etc.) updated; `make lint` green.

## Dependencies

- **Blocked by** the issue-anchoring issue (operates on the issue-anchored review signal; both touch `plan-review-loop.sh` in different regions — coordinate to avoid self-conflict).
- The assessor-on-SIMPLE issue is **blocked by** this one (they should share the `plan.txt-original` baseline, and the assessor's round-comparison premise changes once auto-apply is removed).
- Shares the `test-design-structure.sh` merge surface with the Round II `/design` refactor (#3420 / #3421 / #3422); no hard logical conflict.
