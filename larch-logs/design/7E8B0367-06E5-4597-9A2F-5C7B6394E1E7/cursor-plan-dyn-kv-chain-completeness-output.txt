**1. [correctness] `drift-baseline.env` write keys unspecified** (`skills/design/scripts/design-postplan-emit.sh`)

The read side is explicit: `check-plan-size.sh` will load `BASELINE_PLAN_LINES` and `BASELINE_DIFF_LINES` from `$DESIGN_TMPDIR/drift-baseline.env`. The write side only says to persist baseline “after `PLAN_LINES` / `DIFF_LINES` are populated” and does not name the on-disk keys. That mismatch can make drift permanently inert with no error.

**2. [correctness] Standalone Step 2b.5 parse chain incomplete** (`skills/design/SKILL.md:995-1002`)

Merged paths are covered (parse `DRIFT_*` / `BASELINE_*` from `.design-postplan-emit-result.env` on `_postplan_rc=14`). Retained standalone Step 2b.5 still reads `check-plan-size.sh` stdout directly, but step 3’s explicit parse list stops at `SOFT_ADVISORY` and never adds `DRIFT_TRIGGER_FIRED` or sibling keys. The drift branch prose references `DRIFT_TRIGGER_FIRED` without wiring how it is bound from `_plan_size_out`.

**3. [risk-integration] Structure harness will not enforce rc `14`** (`scripts/test-design-structure.sh:329-331`)

`assert_postplan_thin_fence` hard-codes case arms `0 10 11 12 13 2 1`. The plan updates SKILL / approval-gates / discussion-rounds prose for `_postplan_rc=14` but does not call out updating this harness loop (or the `exit 12` / `exit 13` contains checks). CI can stay green while a fence omits the drift arm.
