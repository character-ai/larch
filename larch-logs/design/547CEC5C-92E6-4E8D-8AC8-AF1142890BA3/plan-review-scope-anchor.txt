## Context

PR #6522 (closed #6514) landed part 1 of the bgjob migration: the `python3 python/cli.py bgjob {start,wait,status,reap}` transport (`python/larch/bgjob/`), the PreToolUse deny hook `scripts/hook-deny-run-in-background.sh`, the inverse `lint bg-wait-coverage` with the reason-bearing allowlist `python/larch/lint/bg_wait_allowlist.txt`, the shared wait contract `skills/shared/bgjob-wait.md`, and session-start reaping in `scripts/cleanup-sessionstart.sh`.

Part 1 deliberately did not convert the call sites. Every long-running larch step still launches via Bash `run_in_background: true` and waits on `<task-notification>`. The 13 allowlist entries carry that legacy prose, and the legacy marker/notification machinery is still live in 11 Python modules. This issue converts all of it to `bgjob start` plus chunked `bgjob wait`.

Issue #6516 (delete the spurious-task-notification defense stack) assumes this migration is complete ("nothing in larch launches Bash `run_in_background` tasks"). #6516 must stay blocked on this issue. Part 1 left the defense stack functional but inert so this PR and #6516 stay independently revertable; this issue must also leave it functional.

## Binding contract per migrated site

`skills/shared/bgjob-wait.md` is the single normative wait contract. Apply it uniformly:

- Wrapper bodies keep their names, rehydrate and arm step preconditions, then `exec` the real work under `bgjob start --step <name> --tmpdir "$TMPDIR" --budget-s <n> -- <command...>`. Harness-visible wrapper stdout is exactly the one `BGJOB_STATUS=STARTED STEP=<name> PGID=<n>` line. Banners and breadcrumbs move to orchestrator prose or daemon logs.
- Orchestrator prose replaces every "immediate-background + wait for `<task-notification>`" instruction with: foreground `bgjob start`, then loop `bgjob wait --max-wait-s 270` with tool timeout `330000`. On `WAIT`, the next action is another identical `bgjob wait` with no prose, `Read`, `TaskOutput`, `Monitor`, or sleep between waits. On `DEAD`, route through the step's existing failure or stall handling. On `DONE`, continue only when `BGJOB_RC=0` and the step's required KVs are present; `BGJOB_RC=timeout`, `BGJOB_RC=orphaned`, any other non-zero value, or missing required KVs route through the step's existing failure or stall handling.
- Each step's existing result KV block merges into `$TMPDIR/bgjob/<step>.result.env` (the `--merge-result-env` input to `bgjob start`), and the result env is the completion source of truth.
- Existing terminal sentinels keep being written during this issue (`.completed/step-3-terminal`, `.completed/step-5-terminal`, `.completed/step-5c-terminal`, `.completed/step-4`, `.completed/step-final-summary`, `.completed/step-7a-terminal`, `.step-8-ship-handoff.rc` / `.json`). Routing contracts stay byte-compatible; sentinel retirement belongs to #6516.

## Acceptance criteria

1. `git grep -l "run_in_background" skills/` returns only lint-allowlisted files and historical run logs, and `python/larch/lint/bg_wait_allowlist.txt` contains at most the `skills/shared/orchestrator-never.md` compatibility entry; `python3 python/cli.py lint bg-wait-coverage` enforces this in `make lint`.
2. Every migrated wrapper's harness-visible foreground stdout is exactly the one `BGJOB_STATUS=STARTED` line (harness-asserted per wrapper).
3. `DONE` continuation is gated on `BGJOB_RC=0` plus required step KVs at every migrated orchestrator branch; prompt-shape harnesses assert the gate text.
4. Step 6 does not treat Step 5c as idle while a live identity-valid `design-step5c` registry row exists and `.completed/step-5c-terminal` is absent (pinned in `test_design_lifecycle.py`).
5. Stall recovery classifies abandoned `implement-step3-checks` and `implement-step5-self-review` legs from dead bgjob registry rows, not `.bg-wait-active` (pinned in `test_stall_recovery.py`).
6. End-to-end: one full `/design` run and one full `/implement --merge` run on a MODERATE issue complete with zero `<task-notification>` entries in the session transcript and no notification-recovery turns in the committed run log.
7. `make py-lint`, `make py-test`, and all affected `test-harnesses` shards pass, including pylint (CI-only) and the pytest unique-basename constraint for any new test files.
8. `scripts/test-bgjob.sh` passes in its `test-harnesses` shard against real processes: owner death yields `BGJOB_RC=orphaned` within grace, budget expiry yields `BGJOB_RC=timeout`, an externally killed daemon yields `DEAD` within one poll interval, and reap leaves a recycled PID's new owner unharmed (closes #6514 acceptance criterion 2, which part 1 covered only with monkeypatched unit tests).
9. #6516 remains blocked on this issue until all of the above hold.

- Migrate in small mechanical passes, one surface group per commit: /design, /implement, /review, /research, state classifiers, shared docs, then lints and harnesses.

- Orchestrator prose swaps every task-notification wait for a foreground `bgjob wait --max-wait-s 270` loop gated on `BGJOB_RC=0` plus required step KVs.
- Terminal sentinels keep being written; legacy hooks stay functional and inert.
- Update prompt-shape harnesses and Python tests in the same PR as their surfaces.
