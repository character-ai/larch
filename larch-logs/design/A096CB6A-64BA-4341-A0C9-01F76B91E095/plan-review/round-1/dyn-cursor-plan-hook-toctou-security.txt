## Findings

### 1. correctness — `scripts/hook-anti-read-poll.sh:18-28` (plan parse/event gap)

The plan’s event shape does not carry over the full session-key chain the Bash hook uses today:

```18:28:scripts/hook-anti-read-poll.sh
session_id=$(printf '%s' "$INPUT" | jq -r '.session_id // ""' 2>/dev/null) || session_id=""
if [ -z "$session_id" ]; then
    session_id=$(printf '%s' "$INPUT" | jq -r '.conversation_id // ""' 2>/dev/null) || session_id=""
fi
if [ -n "$session_id" ]; then
    session_key="$session_id"
elif [ -n "${HOOK_ANTI_READ_POLL_DISCRIMINATOR:-}" ]; then
    session_key="nosession-${HOOK_ANTI_READ_POLL_DISCRIMINATOR}"
else
    session_key="nosession"
fi
```

Without explicit plan text for `conversation_id` and `HOOK_ANTI_READ_POLL_DISCRIMINATOR`, the Python helper can silently merge counters across sessions that today stay isolated.

### 2. security — plan Approach vs `python/larch/report/progress_file.py:181-218`

The plan’s fd-bound contract is right for chmod, temp create, read, unlink, and replace once a verified `state_dir_fd` exists. It does not pin how that fd is obtained. The repo already solves this with ancestor checks plus per-component opens:

`larch_io.assert_no_symlink_path_or_ancestors` at `python/larch/io.py:26-35` is the companion guard. Opening `${TMPDIR}` in one shot does not give the same guarantee.

### 3. correctness — `scripts/hook-anti-read-poll.sh:74-89`, `scripts/test-hook-anti-read-poll.sh:241-251`

Current production behavior replaces a symlinked leaf with a regular state file. The plan’s “if cheap, unlink” wording is weaker than what ships and what the harness already verifies after the leaf-poison case.

### 4. correctness — `scripts/test-hook-anti-read-poll.sh:213-251`

When Bash guardless variants are removed, the black-box harness must keep the poison-row semantics (matching `path_hash`, offset, `prev_count=2`, fresh `prev_time`). Silence alone does not prove the fd-bound read path skipped untrusted symlink content.
