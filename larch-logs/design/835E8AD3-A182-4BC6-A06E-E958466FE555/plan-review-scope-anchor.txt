On the installed `codex-cli 0.142.5`, `codex exec -c model=gpt-5.6-sol` printed `warning: Model metadata for gpt-5.6-sol not found. Please upgrade to the latest app or CLI and try again."` The gate was mid-rollout during the runs: `sol` passed for one run and failed for the other at 04:13Z; `terra` still worked at 06:11Z and was gated by late evening PT. After `npm install -g @openai/codex@latest` (0.144.1), `sol`, `terra`, and `luna` all pass. The operator toolchain is already upgraded; no local breakage remains.

**Durable larch gaps** (this recurs on every vendor model rotation):

1. The Step 0 probe validated codex without the role models, so session-env permitted codex while every launch failed. The run silently degraded to `claude_fallback`; only a Warnings line surfaced, and the run paid Claude cost and quality drift with no operator prompt.
2. The drift message reports the vague CLI warning plus `exit 99`. 99 is the larch invalid-exit sentinel (`python/larch/agents/collect_results.py:282`; `python/larch/implement/dispatch_step2.py:606` defaults `LAUNCHER_EXIT` to `99`), not a real exit code. The actionable server message never reaches the operator.

**Proposed fix**:

- Detect the two signals in codex probe and launch stderr: `Model metadata for <model> not found` and `requires a newer version of Codex`. Map them to an operator-facing message: "codex CLI too old for <model>; run `npm install -g @openai/codex@latest`". Surface it in the Step 2 drift warning and in `/larch:status`.
- Consider probing with the resolved role model, or checking `codex --version` against a version floor stored next to the model pins in `python/larch/core/config.py`.

## Proposed Design Outline

### Goals
- Surface an actionable "upgrade Codex CLI" message when OpenAI's per-model version gate trips, replacing the opaque `exit 99` + vague CLI warning.
- Switch the Step 0 codex probe to exercise `gpt-5.6-luna` (cheapest, highest-volume review model) instead of `gpt-5.6-sol`.
- Route the detected gate signal to `/implement`'s Step 2 drift warning and to `/larch:status`.

### Non-goals
- No `codex --version` version-floor constant or check.
- No probing of sol/terra in Step 0 (single luna probe only).
- No change to the 60s probe cache TTL, the exit-99 launcher sentinel, or the degraded-tools gate stdout contract.

### Approach sketch
- Add one shared detector that matches `Model metadata for <model> not found` and `requires a newer version of Codex` in stderr/sidecar text and returns the gated model plus upgrade hint.
- Probe path (`_auth.py`): switch probe model to luna; when the detector fires, mark codex unavailable with a gate-specific reason feeding the status state/phrase.
- Launch path: classify the gate signal into an actionable failure reason surfaced through the codex `claude_fallback` drift warning.
- `/larch:status` and the shared degraded explanation: render the upgrade hint when the probe hit the gate.

### Surfaces in scope
- `python/larch/agents/_auth.py` (probe model, status state/phrase).
- `python/larch/agents/_run_external.py` and/or `collect_results.py` (shared detector + launch classification).
- `python/larch/implement/dispatch_step2.py` (emit hint on codex fallback).
- `skills/implement/SKILL.md` and `skills/status/SKILL.md` (message rendering).
- Tests under `python/tests/agents/` and `python/tests/implement/`.
