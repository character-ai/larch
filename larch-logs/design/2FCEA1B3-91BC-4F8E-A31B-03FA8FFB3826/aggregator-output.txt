Checking the proposed test harness and Step 6 guards to normalize the two reviewer findings accurately.
Two distinct correctness gaps in the proposed `test-design-step6.sh` harness: one is missing conjunctive-guard coverage, the other mis-targets the assertion stream.

### FINDING_1: Missing marker-plus-sidecar regression test
- **Reviewer(s)**: Cursor-dyn-race-guard
- **Severity**: important
- **Concern**: The functional harness only exercises absent-sidecar cases (tests 1–3). It does not cover the case where both `.design-step5c-status.env` and `.bg-wait-active` exist. The plan requires ignoring `.bg-wait-active` when the status sidecar is present. A marker-only guard (`-f .bg-wait-active` without conjunctive `! -f .design-step5c-status.env`) would pass tests 1–3 but fail in production when Step 5c has written the sidecar but a stale marker remains, blocking normal Step 6 completion with exit 1.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-race-guard: Add test case 4: create both `.design-step5c-status.env` (minimal allowlisted body, e.g. `PLAN_WRITE_OK=false`) and `.bg-wait-active`; run prelude and cleanup; assert exit 0, output lacks `appears still in-flight`, and normal skip/preserve status lines still emit.

### FINDING_2: In-flight assertions grep stdout but guards print to stderr
- **Reviewer(s)**: Cursor-dyn-harness-fit
- **Severity**: important
- **Concern**: Planned in-flight test assertions say "Assert output contains" but the in-flight guards are specified to print diagnostics to stderr (`>&2`). Grepping captured stdout alone yields false failures even when prelude/cleanup correctly exit 1 with the in-flight diagnostic on stderr.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-harness-fit: Capture stdout and stderr separately; assert `appears still in-flight` against stderr (or `stdout+stderr`), and keep KV negatives (`STEP6_PRELUDE_STATUS=skipped`, `CLEANUP_STATUS=preserved`) on stdout only.
