### FINDING_1: Snapshot failures route to an undefined hard-fail status
- **Reviewer(s)**: Codex-Arch
- **Severity**: important
- **Concern**: HARD snapshot failures after successful postplan emission are planned to use a status that is not included in the loop envelope enum or SKILL branch matrix, leaving no closed status for the loop to emit or for callers to parse.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Arch: Map snapshot failures to a defined hard-fail status such as postplan-failed with a SNAPSHOT_RC/SNAPSHOT_STATUS key, or add snapshot-failed to the enum, SKILL branch matrix, and harness assertions.

### FINDING_2: Round phase markers are not durably written before apply or continuation work
- **Reviewer(s)**: Codex-Edge
- **Severity**: important
- **Concern**: After a review/tally result settles, the plan does not require writing the round phase marker before subsequent apply or continuation work. An interrupt can leave a settled round without `.step3-round-N.phase`, causing `--starting-round N` resume rejection or unintended advancement to the next round.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Edge: Write awaiting-apply atomically for ACCEPTED_COUNT>0 and awaiting-continuation for ACCEPTED_COUNT=0 immediately after the review/tally result is settled and before any apply/continuation work; then promote phases as later steps complete.

### FINDING_3: `approve_requested` is not sourced or passed through consistently
- **Reviewer(s)**: Codex-Innovation
- **Severity**: important
- **Concern**: The loop depends on `approve_requested`, but the plan does not add a script-side source/pass-through for the persisted value and omits `plan-review-continuation.sh`’s required `--approve-requested` argument. This can either bypass the Gate B per-round approval prompt or fail/misroute continuation.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Innovation: Read approve_requested from run-params.json in run-step3-review.sh or review-design-step3-loop.sh using the current jq/sed fallback pattern, pass it into run_design_step3_loop, use it for the per-round-approval-required branch, and call plan-review-continuation.sh --approve-requested "$APPROVE_REQUESTED"; add true/false harness coverage

### FINDING_4: Per-round approval resume lacks a durable filtered-findings handoff
- **Reviewer(s)**: Codex-Requirements
- **Severity**: important
- **Concern**: The per-round approval bail-out does not define the exact wire format or path for the user-filtered findings set. If “Go through each” skips a finding but the resumed loop still consumes the original `accepted-plan-findings.md`, skipped findings can still be applied.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Requirements: Define the durable decision wire format and exact findings path the loop consumes, or require the main-agent branch to replace accepted-plan-findings.md with the filtered set before resume; add the corresponding resume assertion to test-review-design-step3-loop.sh

### FINDING_5: Per-round timing is only recorded on the continue path
- **Reviewer(s)**: Codex-Requirements
- **Severity**: important
- **Concern**: The plan specifies per-round timing, but the detailed loop only records timing when `PLAN_REVIEW_CONTINUE=true`. Terminal complete, cap/degraded exits, and bail-out/resume paths can lose the required timing row, including common one-round completion.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Requirements: Record or defer record-plan-review-round-timing.sh for every settled round, including terminal and resumed bail-out paths; persist round-start-s before each bail-out and cover terminal plus resume timing in the new loop harness

### FINDING_6: MAV re-tally tally-error lacks direct tally-error rollback and phase cleanup
- **Reviewer(s)**: Codex-dyn-state-machine-coherence
- **Severity**: important
- **Concern**: A `main-agent-vote-required` round can persist `review-round-count.txt` and an apply phase before main-agent re-tally. If that re-tally returns `tally-error`, the plan does not restore the prior round count or clear stale phase/pre-apply/approval state, so a failed tally can consume a cap slot and leave incorrect resume state.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-dyn-state-machine-coherence: Add an explicit MAV re-tally error branch: before emitting or routing tally-error, atomically restore review-round-count.txt to N-1, clear the round-N phase/pre-apply/approval state, persist tally-error envs, then take the same Step 3b skip path; cover this in the new loop harness.

### FINDING_7: Apply-required bail-outs can leave missing or stale phase state after failed apply/restore
- **Reviewer(s)**: Codex-dyn-state-machine-coherence
- **Severity**: important
- **Concern**: The auto-apply path can emit `main-agent-apply-required` without an `awaiting-apply` phase marker, or after a restore with a stale `awaiting-post-apply` phase. A later `--starting-round` resume can rerun the review pass or skip directly to post-apply/continuation even though the accepted findings are not in `plan.txt`.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-dyn-state-machine-coherence: Write awaiting-apply before the auto-apply attempt and, after any restore that leads to main-agent-apply-required, atomically leave or demote the phase to awaiting-apply before the envelope. Have the SKILL main-agent apply body overwrite it to awaiting-continuation only after the full Gate B pipeline and snapshots settle.
