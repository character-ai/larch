# Implementation Plan — script-internal /design Step 3 review loop (#3771)

## Goal

Move the `/design` Step 3 multi-round review loop out of the orchestrator and into a script. One `run-step3-review.sh --mode loop` Bash call runs every round and returns only on a stop/cap/hard-fail terminal or one of the enumerated bail-outs. This brings `/design` Step 3 to parity with `/implement` Step 5 and removes the per-round-return fragility that the heavy Step-3 anti-halt prose exists to mitigate.

## Approach

Mirror the `/implement` Step 5 topology, with one adaptation: `/implement` applies code fixes via the external coder waterfall; `/design` applies plan revisions via `revise-plan-with-waterfall.sh` (prior art from #2870, never wired in). The main agent re-enters only when that waterfall is exhausted or an operator/LLM decision is required, and resumes the **same round** at the correct intra-round phase so the expensive review pass never re-runs and accepted findings apply exactly once.

PPID-prelude boundary (FINDING_2): the canonical two-line `source ~/.cache/larch/sessions/current-design-env-$PPID.sh` + `.pause-requested` prelude stays in the **SKILL.md** Bash fences before each `run-step3-review.sh --mode loop` invocation (initial and every resume), because `$PPID` inside the nested loop script would name an intermediate launcher shell, not the root Claude PID. The loop script honors pause from `$DESIGN_TMPDIR/.pause-requested` using **inherited env** (exported by the SKILL.md fence) or the tmpdir-local `$DESIGN_TMPDIR/source-env.sh`; it never sources the PPID-keyed env file itself.

Key structural decision — **shared round-body function** (true `/implement` parity, no duplication): extract today's single-pass body of `run-step3-review.sh` `--no-preview` (cap guard, round-cursor advance, slot cleanup, `plan-review-loop.sh` launch, result-env normalization, `review-round-count.txt` persist/rollback, scope-anchor handoff) into one sourced function. Both the single-pass mode and the new loop call it. This mirrors `review-and-fix.sh`, where `_implement_round_body` is defined once and used by both `--mode diff` (single) and `run_implement_loop` (loop). It keeps `run-step3-review.sh` (including its sourced loop, same process) the **sole writer** of `review-round-count.txt`.

Deliberate divergence from the issue's literal "loop calls `plan-review-loop.sh` directly": the loop calls the **shared round-body function** instead, reusing cap / round-count / round-cursor / slot-cleanup / result-normalization / scope-anchor logic. Net behavior is identical (the round body calls `plan-review-loop.sh`), but there is one implementation. Flag for plan review.

Patch format (Round 1 decision): the in-loop reviser runs `--patch-format file-replacement`. Revert safety comes from a **loop-owned** pre-apply snapshot (the reviser deletes its own `plan.txt.before-revise` on success, so the loop cannot rely on it); HARD runs keep `plan-after-round-N.txt` and `plan.txt-original`. No new git mechanism (Round 1 decision dropped the git-commit ask).

## STEP3_REVIEW_LOOP_STATUS envelope

Enum: `complete`, `cap-hit`, `main-agent-vote-required`, `main-agent-apply-required`, `per-round-approval-required`, `postplan-operator-required`, `postplan-failed`, `panel-failed`, `tally-error`, `degraded-empty-collector`. Carry-through: `ROUNDS_COMPLETED`, `FINAL_ROUND_NUM`, `ACCEPTED_COUNT`, `DEGRADED_PANEL`, `SCOPE_ANCHOR_FILE`, `PLAN_REVIEW_CONTINUE_REASON`, and for apply/postplan bail-outs `POSTPLAN_RC` / `DEDUP_RC` plus postplan keys via `.design-postplan-emit-result.env`. `.step3-review-result.env` / `.step3-plan-review-result.env` stay the durable handoff. rc 11 (pause) is not a status (loop exec's `design-pause-save.sh`). `postplan-failed` (rc 1/2/unexpected) is a **hard-fail terminal**: SKILL.md aborts for repair (preserve `$DESIGN_TMPDIR`), NOT a Step 3b transition (FINDING_5).

## Resume-phase model (intra-round)

One concrete durable marker per round: `$DESIGN_TMPDIR/.step3-round-<N>.phase`, written atomically (mktemp + mv), holding one of `awaiting-apply`, `awaiting-post-apply`, `awaiting-continuation`. Plus the loop-owned pre-apply snapshot `$DESIGN_TMPDIR/plan-pre-apply-round-<N>.txt` and the reused `.gate-b-postapply-ready-<N>` marker (written only after dedup succeeds).

Phase meaning and resume routing:
- **no `.phase` for round N** → run the review pass for round N.
- **`awaiting-apply`** (review/tally complete, `ACCEPTED_COUNT>0`, not yet applied — set before `per-round-approval-required`; reached after `main-agent-vote-required` re-tally) → resume at apply. For per-round-approval, consume the durable filtered approval decision (FINDING_1) before applying. After MAV, recompute `ACCEPTED_COUNT`; if 0, promote directly to `awaiting-continuation` (FINDING_8).
- **`awaiting-post-apply`** → resume re-runs mechanical dedup → postplan → snapshot (the apply is not repeated; the loop pre-apply snapshot is still the restore source for a dedup failure).
- **`awaiting-continuation`** → resume runs only `plan-review-continuation.sh`; the postplan fence is NOT re-run.

Phase transition timing (FINDING_5): write `awaiting-post-apply` **immediately after a successful reviser apply, before dedup/postplan** (so an interrupt cannot rerun apply); an in-loop `design-postplan-emit.sh` rc 11 keeps the phase at `awaiting-post-apply` (resume reruns dedup/postplan without reapplying — FINDING_1/5); promote to `awaiting-continuation` only after dedup succeeds **and** postplan settles rc 0 (or a non-plan-changing operator Override/Continue) **and** HARD snapshots complete; demote back to `awaiting-post-apply` for a plan-changing Fix-and-retry/autofix.

Round N is settled only after `plan-review-continuation.sh`; the loop launches round N+1 only when `PLAN_REVIEW_CONTINUE=true`.

`--starting-round` validation (FINDING_4): `review-round-count.txt` records the **last consumed** round. Omitted `--starting-round` means a fresh start at `count+1`. Allow `start==count+1` with no `.phase` marker (fresh round). `start<=count` requires a matching `.step3-round-<start>.phase` (bail-out resume). Reject only `start>count+1`, or `start<=count` without the required phase evidence. `design-step3-state.sh` clears settled lower-round `.phase` / `plan-pre-apply-round-*.txt` on `--direct-review-entry` and after continuation settles, so stale markers cannot mis-route a fresh entry.

## Per-round body (mechanical, no main-agent turn)

For round N inside the `while`:
1. Pause/prelude: honor `$DESIGN_TMPDIR/.pause-requested` (`design-pause-save.sh`) using inherited env / `$DESIGN_TMPDIR/source-env.sh` — NOT `current-design-env-$PPID.sh`, which stays in the SKILL.md fence (FINDING_2). On resume, branch to the round-N phase.
2. Timing mark; capture `round_start_s`.
3. Run the shared round-body (review pass). Parse `LOOP_STATUS`, `TALLY_PLAN_REVIEW_STATUS`, `ACCEPTED_COUNT`, `DEGRADED_PANEL`, `SCOPE_ANCHOR_FILE`.
4. Route on `LOOP_STATUS`:
   - `main-agent-vote-required` → write phase `awaiting-apply`; bail-out (exit 0).
   - `cap-reached` → terminal `cap-hit`.
   - `tally-error` / `degraded-empty-collector` → terminal degraded; the shared round-body rolled back `review-round-count.txt`. `panel-failed` → terminal degraded; the round-count is **persisted** (FINDING_2). All three route to Step 3b skipping Gate B.
   - `complete` / `zero-findings-degraded-panel`:
     - `ACCEPTED_COUNT=0` → no apply → continuation (step 6).
     - `ACCEPTED_COUNT>0`: if `approve_requested=true` → write phase `awaiting-apply`, bail-out `per-round-approval-required` (exit 0) before apply; else auto-apply (step 5).
5. Auto-apply: take the loop-owned pre-apply snapshot `plan-pre-apply-round-<N>.txt`; run `revise-plan-with-waterfall.sh --patch-format file-replacement --findings-file accepted-plan-findings.md ...`. On `REVISE_STATUS=failed-*` → bail-out `main-agent-apply-required` (reviser already auto-reverted). On `{ok, ok-fallback}`: write phase `awaiting-post-apply` immediately (FINDING_5), then run `gate-b-dedup-plan.sh --snapshot-trailers` then `--dedup` under `set +e`; on either nonzero rc, restore `plan.txt` from the loop snapshot and bail-out `main-agent-apply-required` with `DEDUP_RC` (FINDING_1/3). On dedup success, write `.gate-b-postapply-ready-<N>`, then run `design-postplan-emit.sh --with-plan-size` under `set +e`; route rc — 0 → for HARD run `snapshot-plan-round.sh write-after --design-tmpdir "$DESIGN_TMPDIR" --round "$N"` then `snapshot-plan-round.sh write-cursor --design-tmpdir "$DESIGN_TMPDIR" --value "$((N + 1))"` (nonzero rc → repair-required) (FINDING_6), promote phase `awaiting-continuation`, continue to step 6; 11 → exec `design-pause-save.sh` (phase stays `awaiting-post-apply`); 10/12/13/14 → terminal `postplan-operator-required` with `POSTPLAN_RC`; 1/2/unexpected → terminal `postplan-failed` with `POSTPLAN_RC` (hard fail).
6. Continuation: run `plan-review-continuation.sh`. `false` → terminal `complete`. Else record timing, advance round, `continue`.

## Bail-out events (the only mid-loop returns to the main agent)

Every bail-out resumes with `run-step3-review.sh --design-tmpdir "$DESIGN_TMPDIR" --mode loop --starting-round "$N"`; the loop re-enters round N at the recorded phase.
1. `main-agent-vote-required` — 0-judge panel; main agent votes + re-tallies, recomputes `ACCEPTED_COUNT`; resume at `awaiting-apply` (or `awaiting-continuation` if 0 accepted — FINDING_8).
2. `main-agent-apply-required` — reviser/dedup exhausted (`DEDUP_RC` when from dedup); main agent runs the full Gate B Apply-all + Shared post-apply pipeline, writes phase `awaiting-continuation`; resume runs continuation only (FINDING_3).
3. `per-round-approval-required` — `--per-round-approval` only; emitted post-review with `ACCEPTED_COUNT>0` before apply; main agent fires Gate B's prompt and writes a durable approval decision (FINDING_1): **Apply all** → resume applies the full `accepted-plan-findings.md`; **Go through each** → main agent stages a **filtered** findings file (the kept set) plus the rejected-set update before resume, and the loop applies only the filtered set; **Switch to discussion** → exit to Gate A without applying. Resume at `awaiting-apply` consumes the decision exactly once.
4. `postplan-operator-required` — `design-postplan-emit.sh` brakes keyed by `POSTPLAN_RC`: rc 10 (validator → autofix then Fix/Override/Cancel), 12 (plan-size HARD → Split/Override/Cancel), 13 (partition → Split-path), 14 (drift → Continue/Cancel). Override/Continue/non-exiting-Split persist the decision and resume at `awaiting-continuation` past the fence; plan-changing Fix-and-retry/autofix re-enters the fence (FINDING_6). rc 11 is in-loop pause-save.

Terminal: `panel-failed`, `tally-error`, `degraded-empty-collector`, `cap-hit`, `complete` → Step 3b (with `.completed/step-3` written first — FINDING_7). `postplan-failed` → hard-fail abort for repair (FINDING_5).

## Edge cases

- Cap reached (6th entry) → `cap-hit`; Gate B skipped; Step 3b → completion boundary → Step 4 → Gate C.
- Reviser canonical-plan invariant: `--plan-file` resolves to `$DESIGN_TMPDIR/plan.txt`.
- The reviser deletes `plan.txt.before-revise` on success, so the loop's own `plan-pre-apply-round-<N>.txt` is the dedup-failure restore source (FINDING_1).
- `.gate-b-postapply-ready-<N>` is written only after dedup succeeds, so a crash before dedup does not falsely signal apply complete (FINDING_1).
- Resume never re-runs the review pass for an already-reviewed round; findings apply exactly once; round N+1 launches only after continuation true.
- MAV re-tally with 0 accepted → continuation, not apply (FINDING_8).
- file-replacement reviser output keeps optional trailers; `--dedup` requires the `--snapshot-trailers` snapshot first (exit 3 if missing); both run under `set +e`.
- A pause requested mid-loop, and an in-loop postplan rc 11, both route to pause-save; resume skips re-applying findings.

## Failure modes

1. **`review-round-count.txt` sole-writer violation / wrong rollback set.** Double-write desyncs the cap; rolling back `panel-failed` lets failed launches dodge the cap. Mitigation: one shared round-body owns all writes; rollback only `tally-error`/`degraded-empty-collector`, persist `panel-failed` (FINDING_2). Signal: `test-step3-review-cap.sh`.
2. **Apply not exactly-once / lost plan on resume or dedup failure.** Reviser deletes its snapshot; a stale `.gate-b-postapply-ready` re-applies or skips. Mitigation: loop-owned pre-apply snapshot + marker-after-dedup + the `.phase` marker (FINDING_1/3/9). Signal: `test-review-design-step3-loop.sh` resume-phase + dedup-failure assertions.
3. **Envelope escape or invalid-plan continuation.** A non-bail-out returns to the main agent; dedup/postplan aborts under `set -e` with no status; or postplan rc 1/2 continues to Gate C with a malformed plan. Mitigation: closed enum; `set +e` capture of dedup + postplan with every rc mapped; `postplan-failed` is a hard-fail abort, not a Step 3b transition (FINDING_5); operator-brake resume cannot re-loop the fence (FINDING_6). Signal: `test-review-design-step3-loop.sh` + `test-step3-orchestrator-fence.sh`.
