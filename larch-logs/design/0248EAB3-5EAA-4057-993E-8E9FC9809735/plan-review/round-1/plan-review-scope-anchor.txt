# Refactor /design Step 3 review into a script-internal multi-round loop

## Summary

`/design` Step 3 plan review currently runs its **multi-round loop in the orchestrator (main agent)**: each review round returns control to the main agent, which then re-invokes the review driver for the next round. This diverges from `/implement` Step 5, whose multi-round review loop is **script-internal** — a single Bash call runs every round and returns only on completion or a genuine bail-out.

**Goal:** refactor `/design` Step 3 so the entire multi-round review loop runs as **one script call**, exiting on success only after all review rounds have completed (stop decision or cap reached), and returning to the main agent **only on enumerated bail-out events**. This brings `/design` Step 3 to architectural parity with `/implement` Step 5.

This divergence is recent (see "When this diverged") and is the root cause of the mid-loop halt fragility that the heavy "Anti-halt continuation reminder" prose in `skills/design/SKILL.md` exists to mitigate. Moving the loop into a script removes the class of failure where the main agent ends the turn between rounds instead of continuing.

## Current architecture (precise)

### /implement Step 5 — the target shape (script-internal loop)

- `skills/implement/SKILL.md` Step 5 states it outright: "Step 5 invokes **one** foreground `run-step5-review.sh` Bash tool call that **internalizes the entire round loop** … never a background or polling launch."
- `scripts/run-step5-review.sh` makes exactly ONE call to `skills/review-and-fix/scripts/review-and-fix.sh --mode loop`, which sources `skills/review-and-fix/scripts/review-implement-step5-loop.sh` and calls `run_implement_loop()`.
- `run_implement_loop()` contains a `while true` loop. Each iteration runs `_implement_round_body` (one review-and-fix round, which dispatches the **Codex→Cursor coder waterfall** to APPLY accepted fixes as a subprocess), then routes on the round status. It increments `round_num` internally and only emits a final envelope (via `step5_emit_final_envelope`) at a terminal or bail-out outcome.
- The envelope key is `STEP5_REVIEW_STATUS ∈ {complete, cap-hit, stall, main-agent-vote-required, coder-main-agent-required, mav-resume-past-cap}`.
- The main agent regains control mid-loop ONLY on bail-outs that genuinely need LLM/operator action:
  - `main-agent-vote-required` — 0-judge panel; the main agent casts the ballot, re-tallies, then re-invokes the wrapper with `--starting-round`.
  - `coder-main-agent-required` — Cursor→Codex both exhausted this round; the **main agent applies the accepted fixes via Edit/Write** (the Claude tier of the coder waterfall), then re-invokes the wrapper with `--starting-round`.

### /design Step 3 — the current shape (orchestrator-driven loop)

- `skills/design/scripts/plan-review-loop.sh` "always runs one pass and never invokes the revision waterfall" (`plan-review-loop.md`). `skills/design/scripts/run-step3-review.sh` wraps it for one cap-guard + one pass + result normalization. **Neither contains a round loop.**
- The multi-round loop is **prose** in `skills/design/SKILL.md` under the "**Heuristic multi-round continuation check**" (Step 3.5). On a continue decision the main agent: re-runs the Step 3 prelude (source session-env, honor `.pause-requested`, timing mark) and **re-invokes `run-step3-review.sh --no-preview`**, then processes `LOOP_STATUS` per the Step 3 branch matrix, then runs **Gate B**, then re-evaluates the continuation check.
- The continuation decision is computed by `skills/design/scripts/plan-review-continuation.sh` (`PLAN_REVIEW_CONTINUE=true|false` + reason). The cap is 5 (`review-round-count.txt`); rounds 3-4 may be reviewer-pruned; round 5 re-probes the full panel.

## The core obstacle (why a naive "move the loop into a script" fails)

In `/implement`, per-round fix application is delegated to the **external coder subprocess** (Cursor/Codex) inside `review-and-fix.sh`. That is what lets the loop stay inside a script — the main agent is needed only when the coder waterfall is exhausted (`coder-main-agent-required`).

In `/design`, the per-round apply is **Gate B**, and Gate B's default auto-apply **revises `plan.txt` using the main agent's Write tool** — a semantic LLM operation (read `accepted-plan-findings.md`, rewrite the plan prose). See `skills/design/references/approval-gates.md` "Gate B" → "### Apply-all body" → "### Shared post-apply pipeline". **This main-agent Write is precisely why each round returns to the orchestrator.** The continuation predicates fire exactly when there ARE significant accepted findings (any High/Important, more than five non-nit, or a first-round structural/large change) — i.e. the *continuing* rounds are the ones that need an apply — so "apply per round" is inherent to the continuing case and cannot simply be deferred to the end.

Therefore, to make the loop script-internal, **the per-round plan-apply must be delegated to a subprocess**, exactly as `/implement` delegates code fixes to its coder waterfall. The main agent should be invoked only when that apply subprocess is exhausted (a new `main-agent-apply-required` bail-out, the design analogue of `coder-main-agent-required`).

## Prior art already exists — use it

`skills/design/scripts/revise-plan-with-waterfall.sh` is a **complete, harnessed, standalone Codex→Cursor→Claude plan-revision waterfall** (added in #2870, commit `8b9a0d7ae`). Its own contract (`revise-plan-with-waterfall.md`) states verbatim: *"Planned caller: `skills/design/scripts/plan-review-loop.sh` in the next integration piece."* That integration was never completed — Gate B (main-agent apply) was adopted instead, and the #3700 multi-round loop was layered on top in the orchestrator.

This script is the design analogue of the `/implement` coder waterfall:
- Argv: `--design-tmpdir`, `--plan-file` (must canonically resolve to `$DESIGN_TMPDIR/plan.txt`), `--findings-file`, `--feature-file`, `--round-num`, `--codex-present`, `--cursor-present`, optional `--timeout`, optional `--patch-format`.
- KV contract: `REVISE_TIER_{1..4}_STATUS`, `REVISE_STATUS ∈ {ok, ok-fallback, failed-no-patch, failed-validation, failed-apply}`, `REVISE_WINNING_TIER`, `REVISE_PATCH_PATH`, `REVISE_PLAN_HASH_{BEFORE,AFTER}`.
- Applies findings as a **validated patch** (`git apply --check`, NEW/UPDATED/REWRITTEN heading check, optional-trailer preservation, `ACTION=EMIT_PLAN` gate), snapshots `plan.txt` and reverts on any failure. This is mechanically validated — strictly more robust than the main-agent Write.
- Harness: `scripts/test-revise-plan-with-waterfall.sh` (`make test-revise-plan-with-waterfall`).

**Recommended approach: wire `revise-plan-with-waterfall.sh` into a new script-internal Step 3 loop controller, completing the originally-planned integration. On waterfall exhaustion (`REVISE_STATUS=failed-*`), bail out with `main-agent-apply-required` so the main agent applies the accepted findings via Write (today's Gate B "### Apply-all body"), then resumes the loop with `--starting-round`.**

## Prescriptive implementation plan

| `_implement_round_body` (review round + coder apply) | per-round body: `plan-review-loop.sh` (review) + `revise-plan-with-waterfall.sh` (apply) + `gate-b-dedup-plan.sh` + `design-postplan-emit.sh --with-plan-size` + `snapshot-plan-round.sh write-after`/`write-cursor` |

| `record-implement-review-round-timing.sh` per round | `record-plan-review-round-timing.sh` per round (already exists) |

### Per-round body (inside the new loop `while`, mechanical — no main-agent turn)

For round N:
1. **Pause/prelude**: honor `$DESIGN_TMPDIR/.pause-requested` (call `design-pause-save.sh`) and source `~/.cache/larch/sessions/current-design-env-$PPID.sh` if present — relocate today's Step 3 prelude into the loop body.
2. Timing mark + capture `round_start_s`.
3. Run `plan-review-loop.sh` (review pass; unchanged). Parse `LOOP_STATUS`, `TALLY_PLAN_REVIEW_STATUS`, `ACCEPTED_COUNT`, `DEGRADED_PANEL`, `SCOPE_ANCHOR_FILE`, etc.
4. Route on `LOOP_STATUS`:
   - `complete` / `zero-findings-degraded-panel` **with** accepted findings → **apply** via `revise-plan-with-waterfall.sh --findings-file "$DESIGN_TMPDIR/accepted-plan-findings.md" …`:
     - `REVISE_STATUS ∈ {ok, ok-fallback}` → run `gate-b-dedup-plan.sh --dedup`, then `design-postplan-emit.sh --with-plan-size`; route its rc (see bail-outs); on rc=0 run HARD `snapshot-plan-round.sh write-after` + `write-cursor`.
     - `REVISE_STATUS=failed-*` → **bail-out** `main-agent-apply-required` (persist `round-start-s`, emit envelope, exit 0).
   - `complete` / `zero-findings-degraded-panel` with **zero** accepted findings → no apply (Gate B zero-findings short-circuit), proceed to continuation.
   - `main-agent-vote-required` → **bail-out** `main-agent-vote-required` (exit 0).
   - `cap-reached` → terminal `cap-hit` (exit 0).
   - `tally-error` / `degraded-empty-collector` / `panel-failed` → terminal degraded envelope; roll back `review-round-count.txt` per existing `run-step3-review.sh` persist/rollback semantics; exit (these already route to Step 3b, skipping Gate B).
5. **Continuation**: run `plan-review-continuation.sh`. If `PLAN_REVIEW_CONTINUE=false` → terminal `complete` (exit 0). Else record timing row, advance `round_num`, `continue`.
6. If `approve_requested=true` (`--per-round-approval`): **bail-out** `per-round-approval-required` BEFORE apply each round (this mode is intentionally operator-interactive; the main agent fires the Gate B `AskUserQuestion`, then resumes with `--starting-round`).

### Envelope (new — mirror `STEP5_REVIEW_STATUS`)

`STEP3_REVIEW_LOOP_STATUS ∈ {complete, cap-hit, main-agent-vote-required, main-agent-apply-required, per-round-approval-required, panel-failed, tally-error, degraded-empty-collector}`, plus carry-through keys: `ROUNDS_COMPLETED`, `FINAL_ROUND_NUM`, `ACCEPTED_COUNT`, `DEGRADED_PANEL`, `SCOPE_ANCHOR_FILE`, `PLAN_REVIEW_CONTINUE_REASON`, and the existing `.step3-review-result.env` fields. Keep `.step3-review-result.env` / `.step3-plan-review-result.env` as the durable cross-fence handoff.

### Bail-out events (the ONLY mid-loop returns to the main agent)

1. `main-agent-vote-required` — 0-judge panel; main agent votes + re-tallies (existing SKILL.md MAV block + `render-main-agent-scope-anchor.sh` + `persist-retally-step3-env.sh`), then re-invokes the loop with `--starting-round`.
2. `main-agent-apply-required` — `revise-plan-with-waterfall.sh` exhausted; main agent applies accepted findings via Write (today's "### Apply-all body" + shared post-apply pipeline), then re-invokes the loop with `--starting-round`.
3. `per-round-approval-required` — only when `--per-round-approval`; main agent fires Gate B's Apply all / Go through each / Switch to discussion `AskUserQuestion`, then re-invokes the loop with `--starting-round` (or exits to Gate A on "switch to discussion mode").
4. `design-postplan-emit.sh` operator brakes inside the in-loop apply pipeline: rc=12 (plan-size HARD → Split/Override/Cancel), rc=10 (validator defects → Fix/Override/Cancel), rc=14 (drift → Continue/Cancel). Each is a bail-out; on the non-cancel choice the main agent re-invokes the loop with `--starting-round`.

All other outcomes (`panel-failed`, `tally-error`, `degraded-empty-collector`, `cap-hit`, and the `complete` stop) END the loop and route to Step 3b exactly as today.

### SKILL.md changes

- Replace the Step 3 / Step 3.5 orchestrator-loop prose with: one `run-step3-review.sh --mode loop` Bash call, then a branch on `STEP3_REVIEW_LOOP_STATUS` (mirroring Step 5's branch on `STEP5_REVIEW_STATUS`), including a resume-with-`--starting-round` handler for each bail-out class.
- Keep in SKILL.md (legitimate LLM/operator-boundary work, same split as Step 5): the MAV adjudication block; the `main-agent-apply-required` apply body (= today's "### Apply-all body"); the Gate B `--per-round-approval` `AskUserQuestion`; and the `design-postplan-emit.sh` operator prompts (Split/Override/Cancel, Fix/Override/Cancel, Continue/Cancel).
- Reduce the Step-3 portion of the "Anti-halt continuation reminder" to the bail-out-resume boundaries only — it no longer needs to guard per-round re-invocation.

### Preserve (do not regress)

- Review-round cap of 5; reviewer pruning in rounds 3-4 (`reviewer-prune.sh`, already inside `plan-review-loop.sh`); round-5 full-panel re-probe; pruned-empty continuation toward the round-5 re-probe.
- `review-round-count.txt` persist/rollback semantics (the driver stays the sole writer; `plan-review-loop.sh` must not read/write it).
- Cumulative `accepted-plan-findings-all.md` and `oos-accepted-design.md`; scope-anchor handoff (`SCOPE_ANCHOR_FILE` dual gate).
- Gate B remains the sole `plan.txt` apply point (now reached via the in-loop waterfall on the happy path, or via the `main-agent-apply-required` bail-out body).
- Pause/resume across rounds; single-`/design`-per-repo and single-runner invariants; HARD plan snapshots per applied round.

## Open decisions for /design

- **Apply delegation vs. main-agent-apply-every-round.** Recommended: wire `revise-plan-with-waterfall.sh` so the common path is fully in-loop. Alternative (rejected): treat every accepted-findings apply as a `main-agent-apply-required` bail-out — this returns to the orchestrator on every *continuing* round, which does NOT meet the goal. Confirm the recommended path during `/design`.
- **Launcher shape:** extend `run-step3-review.sh` with `--mode loop` (parity with `run-step5-review.sh`'s `--mode`) vs. add a sibling `run-step3-review-loop.sh`.
- **Patch format:** whether the in-loop reviser uses `--patch-format unified-diff` (default, with tier-4 file-replacement fallback) or `file-replacement` directly, given plan rewrites are often large.

## Approved direction (outline)

## Proposed Design Outline

### Goals
- Run `/design` Step 3's full multi-round review as **one** script-internal Bash call that returns only on stop/cap or an enumerated bail-out — architectural parity with `/implement` Step 5.
- Apply per-round plan revisions in-loop via `revise-plan-with-waterfall.sh`; the main agent re-enters only on bail-outs and resumes with `--starting-round`.
- Shrink the Step-3 "Anti-halt continuation reminder" prose to the bail-out/resume boundaries only.

### Non-goals
- No change to review-panel composition, voting, scope-anchor handoff, or the cap-of-5 / reviewer-pruning / round-5 re-probe semantics.
- No change to `/implement` Step 5.
- No new git mechanism for revert — keep the reviser's `.before-revise` auto-revert plus existing snapshots.

### Approach sketch
- Extend `run-step3-review.sh` with `--mode loop` (mirrors `run-step5-review.sh`'s `--mode`).
- Add `review-design-step3-loop.sh` exposing `run_design_step3_loop()` `while true`, mirroring `review-implement-step5-loop.sh`.
- Per-round body (mechanical): `plan-review-loop.sh` → `revise-plan-with-waterfall.sh --patch-format file-replacement` → `gate-b-dedup-plan.sh` → `design-postplan-emit.sh --with-plan-size` → `snapshot-plan-round.sh` → `plan-review-continuation.sh`.
- Emit a `STEP3_REVIEW_LOOP_STATUS` envelope; bail-outs: `main-agent-vote-required`, `main-agent-apply-required`, `per-round-approval-required`, and `design-postplan-emit.sh` operator brakes.

### Surfaces in scope
- `skills/design/scripts/{run-step3-review, review-design-step3-loop (NEW), plan-review-loop, revise-plan-with-waterfall, plan-review-continuation, snapshot-plan-round}.sh`
- `skills/design/SKILL.md` Step 3 / 3.5; `skills/design/references/{plan-review, approval-gates}.md`; `docs/workflow-lifecycle.md`; `skills/shared/topology.tsv`.
- Harnesses: extend `test-run-step3-review.sh`, `test-plan-review-loop.sh`, `test-step3-review-cap.sh`, `test-design-pause-resume.sh`, `test-step3-orchestrator-fence.sh`; add `test-review-design-step3-loop.sh`; wire into `make lint` + `docs/linting.md`.

### Open questions
- None. The three open decisions are resolved (in-loop reviser; `--mode loop`; `--patch-format file-replacement`); git-per-round-commit dropped.
