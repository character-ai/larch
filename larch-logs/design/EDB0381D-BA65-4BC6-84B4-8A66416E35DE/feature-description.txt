# Add linter enforcing no 2 consecutive Bash() tool calls in skill .md files

Mechanizes the "no consecutive prompt-side Bash blocks" item (criterion-2 routing from #4659; relates to G-Skill-2, orchestrator thinness).

## Goal

A lint that flags two adjacent `bash` tool-call fences in an orchestrator-facing skill `.md` with no intervening non-Bash step. Consecutive Bash blocks usually signal logic that should be a single `cli.py` call.

## Detection (needs care)

A naive "two ```bash fences in a row" grep over-counts. The lint must exclude:

- **illustrative fence pairs** (e.g. the `WRONG` / `CORRECT` example blocks in design SKILL.md anti-patterns);
- `sh` / `text` / other non-tool example blocks;
- **intentional separate boundaries** required by the pause/resume design: pause-check fences, foreground recovery-probe fences, and `<task-notification>` wait fences. These are deliberately distinct Bash boundaries and must not be flagged.

So this is a lint **with documented carve-outs**, likely an AST / markdown-fence parse rather than a regex.

## Why

Keeps the orchestrator thin (G-Skill-2). Consecutive prompt-side Bash blocks are a smell for logic that belongs in one Python verb.

## Open question for /design

Confirm whether "consecutive" means adjacent fences in source, or two Bash tool calls with no intervening different tool at runtime. The carve-out list differs slightly between the two readings.

## Approach

1. Build the fence-aware checker (reuse markdown-fence parsing from other skill linters if available).
2. Encode carve-outs; allow an inline suppression comment with a reason for legitimate exceptions.
3. Wire into `make lint` + pre-commit per repo convention.
4. Fix or suppress-with-reason existing violations surfaced by the first run.

## Related

## Acceptance

Lint active in `make lint` + pre-commit; carve-outs covered by a small test; existing skill `.md` files pass or carry justified suppressions.
