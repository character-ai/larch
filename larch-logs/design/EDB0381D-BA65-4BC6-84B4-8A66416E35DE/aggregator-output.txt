### FINDING_1: Suppression pairing semantics unspecified
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: Suppression pairing semantics are unspecified. A valid `# lint-consecutive-bash: ok <reason>` on only one fence of an adjacent pair may still be reported if the implementer requires both fences to carry a pragma. In triple-chain gaps (A–B–C), fence B may need duplicate suppressions unless middle-fence behavior is defined.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: State explicitly that one valid suppression on either fence suppresses that adjacent pair, and a suppression on the middle fence of a short-gap chain suppresses both pairs it participates in

### FINDING_2: Scan scope omits `skills/shared/*.md`
- **Reviewer(s)**: Codex-Generic
- **Severity**: important
- **Concern**: The planned scan scope omits `skills/shared/*.md`, an orchestrator-facing shared skill prompt surface. The existing bare-grep lint treats shared Markdown as orchestrator-facing, and shared files such as `skills/shared/external-reviewers.md` contain Bash tool-call fences used by multiple skills. A consecutive Bash pair added to a shared prompt fragment could pass `make lint` and the pre-commit hook, so the new lint would not fully enforce the no-consecutive-prompt-side-Bash rule across orchestrator-facing skill Markdown.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Generic: Add `skills/shared/*.md` to the scoped patterns, git and non-git enumeration, pre-commit `files:` filter, docs, and first-run remediation/test coverage.
