1. **correctness** (`plan.txt:40-41`): The plan tells implementers they may pass `STATIC_SLOT_COUNT` through as `--intended-slots`. That KV is the launched static row count already wired to `--launched-slots`. When Codex is present but some `codex-specialist-*` launches never run, intended must stay 8 while launched may be 6; the threshold script only counts the gap when `INTENDED_SLOTS > LAUNCHED_SLOTS` (`check-reviewer-failure-threshold.sh:104-109`). Drop the STATIC_SLOT_COUNT shortcut and derive intended only from availability (or a dedicated dispatcher KV).

2. **correctness** (`plan.txt:40-41`): The proposed `4 * (cursor_available + codex_available)` must not be implemented as arithmetic on the literal strings `true`/`false`. Mirror the dispatch-panel availability gates: count vendors with `[[ ... == true ]]`, floor to 1 when both are down, then multiply by 4 before passing `--intended-slots`.
