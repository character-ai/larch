### 1. [correctness] Dual `INTENDED_SLOTS` sources risk phantom never-launched failures (`plan.txt:40-41`, `review-core.sh:451-452`)

The four availability states and `>50%` cutoffs in the plan match the existing threshold implementation when `INTENDED_SLOTS` is set correctly:

| Vendors | Emitted static rows | `INTENDED_SLOTS` | `HALF_PLUS_ONE_MIN` (`/2+1`) | Hard-stop when |
|---------|---------------------|------------------|------------------------------|----------------|
| Both up | 8 | 8 | 5 | `FAILED_SLOTS >= 5` (>4) |
| Cursor-only / Codex-only | 4 | 4 | 3 | `FAILED_SLOTS >= 3` (>2) |
| Both down (4 Claude-fallback rows) | 4 | 4 (floor) | 3 | `FAILED_SLOTS >= 3` (>2) |

That follows `HALF_PLUS_ONE_MIN=$(( INTENDED_SLOTS / 2 + 1 ))` and `FAILED_SLOTS >= HALF_PLUS_ONE_MIN` in ```112:118:skills/review/scripts/check-reviewer-failure-threshold.sh```.

Today `review-core.sh` only passes `--launched-slots "$static_slot_count"` and never `--intended-slots`; the threshold script hardcodes `INTENDED_SLOTS=6` (```39:40:skills/review/scripts/check-reviewer-failure-threshold.sh```), which is the #2449 mismatch the plan targets.

The plan’s availability math is right, but Step `review-core.sh` lists **either** recomputing `4 * (cursor_available + codex_available)` **or** using `STATIC_SLOT_COUNT`. A second derivation can disagree with dispatch (the plan’s own failure mode #1). When `INTENDED_SLOTS > LAUNCHED_SLOTS`, ```107:109:skills/review/scripts/check-reviewer-failure-threshold.sh``` adds `NEVER_LAUNCHED` into `FAILED_SLOTS`, which can false-trigger `panel-failed`.

**Suggested revision:** Treat `STATIC_SLOT_COUNT` from `dispatch-panel.sh` as the single denominator; pass the same value for `--intended-slots` and `--launched-slots` so `NEVER_LAUNCHED` stays 0 in normal runs.

### 2. [risk-integration] Planned `test-review-core` coverage may not exercise threshold wiring (`plan.txt:121-122`, `test-review-core.sh:239-244`)

The plan calls for asserting `--intended-slots` “derivation from availability,” but the harness replaces the threshold script with a stub that always prints `INTENDED_SLOTS=12` and does not read argv (```239:244:skills/review/scripts/test-review-core.sh```). The dispatch stub also omits `STATIC_SLOT_COUNT` (```40-93:skills/review/scripts/test-review-core.sh```), so `static_slot_count` defaults to 0 in production `review-core` parsing.

**Suggested revision:** Extend the plan’s test step to require real-script (or argv-capturing stub) cases for 4-slot and 8-slot panels, asserting `review-core` forwards matching `--intended-slots` / `--launched-slots` from dispatch output—not a recomputed availability formula in isolation.
