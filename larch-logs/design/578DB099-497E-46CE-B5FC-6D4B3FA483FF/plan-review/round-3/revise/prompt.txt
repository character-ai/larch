## Edge cases
- **Both vendors unavailable**: every archetype still emits one Cursor-primary row that waterfalls to Claude; `INTENDED_SLOTS` = emitted count (4). No archetype is silently dropped.
- **Single vendor (e.g. Codex down)**: only the available vendor's row is emitted per archetype (4 static); `INTENDED_SLOTS=4`; threshold fails at >2. No duplicate "cursor-row-falls-to-codex" inflation because emission is availability-gated.
- **Scout returns 0 dynamics**: no dynamic rows for either vendor; static-only panel unaffected.
- **Dynamic name collides with a static slug**: reserved-slug lists still reserve the 4 survivors, so the scout cannot duplicate a static archetype as a dynamic.
- **Dynamic name collides with a folded slug**: reserved-slug lists also keep `structure` and `plan-fidelity`, so folded lenses cannot reappear as dynamic archetypes.
- **Cursor row fails while Codex is available**: the Codex peer row has already been launched for that archetype, so the Cursor row must not trigger a second Codex fallback run.

Code-review panel: collapse 6 static archetypes → 4 + spawn Codex dynamics (cost/latency reduction)

## Problem
The `/review` + `/implement` code-review panel runs **6 static specialist archetypes** — structure, correctness, testing, security, edge-cases, plan-fidelity (`cursor_specialists=(...)` in `skills/review/scripts/dispatch-panel.sh:106`) — and its **dynamic** scout slots are **Cursor-only** (`dispatch-panel.sh:181` hardcodes `tool:"cursor"`). 1. Collapse the 6 static archetypes → **4** by merging roles.
2. Spawn **Codex dynamics** in addition to Cursor (mirror `/design`'s both-vendor dynamic dispatch at `dispatch-plan-review-panel.sh:214-227`) — hit harder upfront, then prune aggressively (see conditional-spawning issue #3463).
