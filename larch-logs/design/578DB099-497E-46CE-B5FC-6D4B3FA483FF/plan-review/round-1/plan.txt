## Implementation Plan

Collapse the `/review` + `/implement` code-review panel from 6 static archetypes to 4, and run both vendors (Cursor + Codex) on every static slot and every dynamic scout slot, mirroring `/design`'s `dispatch-plan-review-panel.sh`. SIMPLE tier — bias toward the smallest change that achieves the goal; most of the line count is mechanical count/phrase sync, not new logic.

### Decisions (from Round 1)
- 4 archetypes, **keep anchor slugs**: `security` (standalone), `correctness` (standalone), `edge-cases` (primary; folds `structure` as secondary scan), `testing` (primary; folds `plan-fidelity` as secondary scan).
- **Both-vendor** on static AND dynamic slots (user choice), gated on availability. Cost reduction comes from collapsing 6→4 distinct lenses; the second vendor offsets raw slot count. Net is "hit harder upfront", with pruning deferred to #3463.

### Honest divergences from the issue's assumed surface (confirmed by codebase read)
1. The merged specialists are **hand-maintained** `agents/reviewer-edge-cases.md` / `agents/reviewer-testing.md` (header: "specialist variant, hand-maintained"), NOT generated from `reviewer-templates.md`. The 4 generators target different agents (code-reviewer, code-robustness, plan-fidelity, security-structure-tests). So the fold edits land in the agent files; `reviewer-templates.md` is touched only for stale enumerating prose, and no new generator is added. `agent-sync` is unaffected.
2. The reserved-slug lists in `dispatch-panel.sh` and `scout-dynamic-archetypes.sh` already reserve the 4 surviving slugs (they are a subset of today's 6). No functional change is required; optional cleanup only. Keeping `structure`/`plan-fidelity` reserved prevents the scout from resurrecting them as dynamics while their agent files still exist.
3. `tally-code-votes.sh` already parses `codex-specialist-*-output.txt` (write_archetype_map) and the 4 surviving slugs keep their existing focus-area mappings, so attribution needs no functional change for both-vendor static — only optional dead-case cleanup.
4. This **reverses #2449**, which deliberately removed Codex from this panel (`codex_present_for_waterfall="false"`; comment in `check-reviewer-failure-threshold.sh`). See Failure modes.

## Approach
- **Canonical replacement phrase**: define ONE literal to replace "6 Cursor specialists" everywhere (proposal: `4 specialists per vendor (Cursor + Codex)`). Use the exact same string across README/docs/topology/diagram and the `test-quick-mode-docs-sync.sh` required-phrase list so the doc-sync harness passes. Pick the final wording during implementation and apply it atomically.
- **Mirror `/design`**: copy the both-vendor emission shape from `dispatch-plan-review-panel.sh` (one `tool:cursor` row + one `tool:codex` row per archetype, each gated on availability) rather than inventing a new shape.
- **Minimal-logic principle**: most files are count/phrase sync. The only real logic changes are in `dispatch-panel.sh` (both-vendor static/dynamic emission, dynamic row accounting, and gate flip), `check-reviewer-failure-threshold.sh` (availability-derived denominator), `review-core.sh` (pass `--intended-slots`), `larch-log.sh` (exclude Codex specialist raw outputs), and the two agent-prompt folds.
- Keep `--panel simple|hard` behavior identical for the static set (both already select the same specialists today; both select the same 4 after the change).

## Edge cases
- **Both vendors unavailable**: every archetype still emits one Cursor-primary row that waterfalls to Claude; `INTENDED_SLOTS` = emitted count (4). No archetype is silently dropped.
- **Single vendor (e.g. Codex down)**: only the available vendor's row is emitted per archetype (4 static); `INTENDED_SLOTS=4`; threshold fails at >2. No duplicate "cursor-row-falls-to-codex" inflation because emission is availability-gated.
- **Scout returns 0 dynamics**: no dynamic rows for either vendor; static-only panel unaffected.
- **Dynamic name collides with a static slug**: reserved-slug lists still reserve the 4 survivors, so the scout cannot duplicate a static archetype as a dynamic.
- **Dynamic name collides with a folded slug**: reserved-slug lists also keep `structure` and `plan-fidelity`, so folded lenses cannot reappear as dynamic archetypes.
- **plan-fidelity coverage after fold**: the testing lane keeps the `--plan-file` requirement and the plan is appended by `render-specialist-prompt.sh`, so critical plan-conformance gaps are still flagged.
- **Codex absent at runtime**: identical to today (Cursor-primary + Claude fallback); the change degrades gracefully.

## Failure modes
1. **Threshold denominator mismatch** — if `INTENDED_SLOTS` does not track vendor availability, the >50% hard-stop misfires (too strict when only Cursor runs against an 8-intended denominator; too lenient otherwise). Earliest signal: review-core hard-stops on healthy panels, or fails to stop on mostly-failed panels. Mitigation: availability-derived `--intended-slots`; cover 4-slot and 8-slot cases in tests.
2. **Reversing #2449 (Codex re-enablement)** — Codex was deliberately removed from this panel; if the original reason was poor code-review signal or cost, re-enabling degrades signal-to-noise or inflates spend. Earliest signal: post-change run-log mining shows Codex static/dynamic findings mostly rejected, or a cost spike. Mitigation: emission is gated on `CODEX_PRESENT` (absent → today's behavior); the deferred #3463 pruner is the planned cost control; validate by re-mining run logs after ~1 week (issue's stated validation step).
3. **Count/phrase drift** — a missed "6 Cursor specialists" site fails `test-quick-mode-docs-sync.sh`, the topology projection, or the `test-dispatch-panel.sh` breadcrumb assertion. Mitigation: one canonical phrase applied to every enumerated site + the harness phrase lists in the same change; run `make lint` and the doc-sync + dispatch-panel harnesses before finalizing.
4. **Raw Codex specialist outputs leak into committed run logs** — adding `codex-specialist-*` outputs without extending `larch-log.sh` exclusions could commit large raw reviewer transcripts. Mitigation: update the filter and add larch-log regression coverage.
5. **Prompt source/runtime drift** — editing hand-maintained reviewer agents without regenerating `agents/pre-rendered/*` leaves runtime prompts stale. Mitigation: regenerate the two pre-rendered bodies and manifest, and run prompt-generation checks.
