## Decision 2: Aggregator Codex model_role
- **Question**: When `review.findings_aggregator` and `design.plan_findings_aggregator` flip their single slot's primary tool from `cursor` to `codex`, which Codex `model_role` gets gpt-5.4-mini (the model the issue names)?
- **Resolution**: `model_role="review"` (CODEX_REVIEW_MODEL_DEFAULT = "gpt-5.4-mini"). Verified in `_launch_failure.py`: an empty/`"default"` model_role resolves to CODEX_DEFAULT_MODEL = "gpt-5.5" instead, which would silently miss the issue's named model. `"review"` and `"fix"` both resolve to gpt-5.4-mini today; `"review"` is the closer semantic fit since aggregation is a review-pipeline mechanical-merge step, not a coder-fix step.
- **Source**: codebase (`python/larch/agents/_launch_failure.py` role_defaults mapping; `python/larch/core/config.py` CODEX_*_MODEL_DEFAULT constants)

## Decision 4: Mechanics of "plan revision runs inline in the main agent"
- **Question**: How does the Step 3 automatic loop hand plan revision to the interactive main agent instead of an external tool, without changing today's default silent-auto-apply UX (no added prompts)?
- **Resolution**: `python/larch/review/plan_review.py`'s loop currently has two paths for applying accepted findings: (a) the happy path, which silently shells out to `plan revise-waterfall` (external Cursor→Codex→headless-Claude dispatch) with zero orchestrator involvement, and (b) a bail-out to prompt-side Gate B (`main-agent-apply-required` / `per-round-approval-required`) whose existing `### Apply-all body` already applies findings inline via the Write tool — this is exactly the target behavior, already built, just reached only on failure or `--per-round-approval` today. The fix: remove path (a) entirely and make the loop always take path (b) for every round with accepted findings, regardless of `approve_requested`. `approve_requested` continues to gate only whether Gate B fires the interactive AskUserQuestion (`per-round-approval-required`) versus applying silently with a print-only notice (today's default auto-apply message) — that distinction is orthogonal to who performs the edit and is unchanged by this issue.
- **Source**: codebase (`python/larch/review/plan_review.py` `_run_apply`/phase state machine; `skills/design/references/approval-gates.md` Gate B `### Apply-all body` / `### Shared post-apply pipeline`)
