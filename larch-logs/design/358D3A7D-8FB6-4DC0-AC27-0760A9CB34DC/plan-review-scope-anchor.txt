**What:** Port `skills/implement/scripts/materialize-manifest-oos.sh` (~233 lines) to Python and call it in-process instead of via subprocess.

**Why:** Security-sensitive. It does jq manifest parsing plus `sed`-based PII/secret redaction (internal-URL, email, SSN, phone regexes) plus security-signal routing. Fragile regex redaction is exactly the code that should not live in Bash. It already calls `python/cli.py redact secrets` and then layers additional hand-written `sed` redaction on top. Overlooked by the migration (absent from all manifests).

**Evidence:** Invoked from `python/implement_dispatch.py:1125` via `subprocess` — the Python runtime is shelling out to this Bash script. Also referenced by `python/file_oos.py:361`.

**Scope:**
- Port manifest parsing, title/description normalization, dedup-by-title, security routing (`security-oos-observations.md`), and the public-text sanitizer into Python.
- Reuse `python/cli.py redact secrets` rather than re-implementing `sed` redaction.
- Call the new code in-process from `implement_dispatch.py` / `file_oos.py` (remove the subprocess hop).
- Preserve the `--count-only` path.
- Migrate `test-materialize-manifest-oos.sh` to pytest.
- Delete the `.sh`; record in the manifest.

**Acceptance:** Redaction parity (or stronger) verified by tests covering each PII family; security-routing parity; `--count-only` preserved; `make lint-retired-scripts` clean.

**Note:** Touches redaction behavior — run a security review and update `SECURITY.md` if covered families change.
