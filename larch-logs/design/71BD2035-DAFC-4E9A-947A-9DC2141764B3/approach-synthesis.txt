## Divergence resolution

- Cursor flagged that emitting exact-match `BAIL_REASON=fix-attempts-exhausted` from `ci-decide.sh` will flip the FIX_ATTEMPTS >= 10 cap path from exit 4 → exit 3. **Resolution**: this flip is intentional per Round 1 Decision 4. The two paths remain distinct:
  - `ci-decide.sh` FIX_ATTEMPTS >= 10 cap → `bail` envelope with magic token → ship-pr `needs_user_bail_reason` returns true → **exit 3** (user-input bail, `/implement` Step 16 contract).
  - `run_evaluate_failure` outer `_max_fix=3` attempts all fail → `exit_stall "10-max-retries"` → **exit 4** (stall).
  The existing exit-3 stub test at `test-ship-pr.sh:1042-1047` continues to pass via direct stub injection; the new test in (3) above covers the orthogonal exit-4 path.

## Risks and mitigations

- **Prompt-fragment drift**: a launcher omits the include. Mitigation: add a small assertion in `scripts/test-launch-cursor-ci.sh` / `test-launch-codex-ci.sh` / `test-launch-claude-ci.sh` (or whichever harness covers each launcher) that the rendered `$PROMPT_FILE` contains a sentinel substring from the fragment file.

- **Collapsing the two ship-pr exit paths**: the FIX_ATTEMPTS cap (exit 3 user-input) and the vendor-loop exhaustion (exit 4 stall) MUST remain distinct. Mitigation: keep the existing exit-3 stub test passing AND add the new exit-4 stub test; the test pair pins the contract.

- **Post-merge `larch-log.sh write` policy**: `refresh-run-logs.sh` already short-circuits after merge outcomes (`merged|admin_merged|already_merged`), so adding the `final-bail-reason` publish there is safe — it cannot fire post-merge. No new commit mechanism needed.

- **Bash 3.2 portability**: all touched scripts are already 3.2-compatible; no new constructs introduced.

- **Foreground markers**: no new fenced bash blocks in SKILL.md surface — the CI-fix knowledge is a runtime concern, not an orchestrator directive.
