## Approach

Implement the Gate C ladder independently for invariants and guidelines.

Each plan edit must run the existing settle and postplan validation path before a fresh `larch:arch-assessor` spawn. Persist tier counters so pause, resume, and re-entry cannot reset the bounds.

Treat a guideline assessment file as publishable only when it is the canonical clean note or carries a valid, unfenced exception block. Keep the existing fail-closed persistence and publish checks.

## Edge cases

- Invariants and guidelines may both be adverse. Process them independently in canonical order.
- A tier-1 no-progress or bail still consumes that kind’s tier-1 round.
- A failed settle or postplan validation stops before reassessment.
- Pause or repeated Gate C entry must not reset counters or reuse a verdict from an older plan.
- An exception-looking line inside a Markdown fence has no authority.
- A valid exception cannot waive an invariant violation.
- A bare deviation remains non-publishable after ladder exhaustion.

## Failure modes

1. **A stale assessment approves a revised plan.** Re-run settle/postplan, then spawn a fresh assessor against the current `plan.txt`.
2. **Re-entry repeats a tier indefinitely.** Persist per-kind counters and fail closed when their bounds are exhausted.
3. **A prose example bypasses the exception gate.** Use a fence-aware parser at both persistence and publication boundaries.
