## Findings

### 1. Decompose default argv construction (blocking)

The plan’s `waterfall_argv = [env] if env else [...]` pattern does not match how `decompose.py` builds commands today. Both `dispatch_panel` and `aggregate_partition` use `os.environ.get(..., default_path)` and always get a truthy string, so a literal translation never selects the new CLI verb default.

### 2. Teardown ordering (important)

Bash teardown is specific about process-group kill before descendant sweep (`kill -- -$pid` after optional `set -m`). The plan should pin that ordering so the Python port does not regress orphan vendor processes.

### 3. [OUT_OF_SCOPE] Diagnostic string renames

`dispatch-code-voters.sh` and `decompose.py` failure logging still name `dispatch-with-waterfall.sh`. Worth fixing during cutover, but not required for parity or CI green.
