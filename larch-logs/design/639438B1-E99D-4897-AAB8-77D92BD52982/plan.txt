## Edge cases

- Empty / absent `ADOPTED` value remains valid (exit 0, `ADOPTED=` line emitted). Case (c) "absent" and case (d) "explicit empty" must continue to pass — the validation block is only entered when `[[ -n "$ADOPTED_VAL" ]]`.
- Duplicate `ADOPTED=` lines (case (k)) still resolve via first-match-wins from `grep -m1`. No change.
- CRLF line endings (case (l)) and leading BOM (case (m)) continue to work because they are handled before the validation block runs.
- The fixed-token literal `ADOPTED: 'malformed-value-omitted'` uses the same single-quoted form as `ISSUE_NUMBER: 'malformed-value-omitted'` and `RUN_ID: 'malformed-value-omitted'` — verify by grep that the new string appears alongside the existing two.
- `assert_equal_stdout` for cases (e)/(f)/(g)/(h) pins exactly two lines (`FAILED=true\nERROR=...`). Any extra KV line, trailing whitespace, or appended payload in stdout breaks the assertion — this is the load-bearing protection against future KV-injection regressions even if the fixed-token error is preserved.
- The negative `assert_not_contains` needles must NOT use bare digits (`"1"`) or bare lowercase words (`"yes"`) — `FAILED=true` already contains `true`, the legitimate `ADOPTED=true` line contains `true`, and small substrings could spuriously match. Use the quoted form (`"'1'"`, `"'true '"`) and/or the raw-token form (`"ADOPTED=1"`, `"ADOPTED=true "`).

## Failure modes

1. **Test assertion drift** — if any of cases (e)/(f)/(g)/(h) misses a sub-edit (especially the `assert_equal_stdout` line switch), CI fails loudly on byte-mismatched assertions. Earliest signal: `make test-tracking-issue-read-sentinel`. Mitigation: read each of the four blocks side-by-side with the existing fixed-token cases (p)/(q)/(t)/(u)/(v)/(w) to confirm the shape matches.
2. **`.md` sibling drift** — script changes without matching `.md` contract updates trigger the `script-md-siblings` rule violation in CI. Earliest signal: pre-commit hook. Mitigation: update `scripts/tracking-issue-read.md` and `scripts/test-tracking-issue-read-sentinel.md` in the same commit; verify by grep that `'malformed-value-omitted'` appears next to `ADOPTED` in both `.md` files after the edit.
3. **Stale in-script header / inline contract comments** — if the line-291-294 runtime edit ships without the matching header (lines ~33-47) and inline-comment (lines ~250-256) edits, the source-level contract documentation contradicts the runtime behavior, and a future maintainer could re-introduce the verbatim echo by following the stale comment. Earliest signal: code review (no test catches comment drift directly). Mitigation: grep the file post-edit for the literal substring `'<v>'` — it should not appear anywhere in the file.
4. **SECURITY.md drift** — if SECURITY.md is not updated, the AGENTS.md rule is violated even though the runtime behavior is correct. Earliest signal: PR review by a maintainer following the security-update rule. Mitigation: grep SECURITY.md post-edit for `ADOPTED` adjacent to `malformed-value-omitted`.
5. **Inaccurate clarifying comment in get-issue-context.sh** — the original draft incorrectly named `clarify-comment-post.sh` and `clarify-state.sh` as accepting `0`. Both scripts actually reject `0` via an explicit secondary check. If the comment ships with the wrong attribution, it encodes false integration guidance and could mislead a future hardening pass into "fixing" a non-bug. Mitigation: verify the comment's cited peers by inspecting the actual validation block of each named script before committing.
