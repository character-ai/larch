**1. Idempotent sentinel path needs materialization before checkpoint** (`python/oos_filer.py:483-488`, correctness)

The `prior_sentinel and not blocks` branch writes ndjson from sentinel URLs and stamps `step9a1=true` without a checkpoint today. After the plan adds `disposition-checkpoint`, `disposition_gate` fails when ndjson lists filed URLs but no accepted input files exist on disk (`python/file_oos.py:468-475`). The plan describes materialization for sentinel-only recovery tests, but it should name this early-return branch explicitly so `test_idempotency_sentinel_skips_create_loop` does not regress.

**2. Retry matching must not reuse `_sentinel_urls()` titles** (`python/oos_filer.py:142-148`, correctness)

`_sentinel_urls()` assigns every recovered issue the placeholder title `Recovered OOS disposition`. Title-only matching against accepted `### OOS_N:` blocks will miss, so checkpoint-failed retries can re-file the same batch. Parse real titles from the sentinel markdown table and ndjson `Title` metadata (and prefer URL correlation where available).

**3. `verify-completeness` has extra ndjson success paths** (`python/run_logs.py:2512-2532`, risk-integration)

The plan updates `_step9a1_heuristic` and names `verify-completeness`, but the verifier still treats ndjson alone as completion in its final OR return (`2528-2529`) and in bail-signal branches (`2516-2517`). Without aligning all three sites, provisional ndjson after a failed checkpoint can still read as Step 9a.1 complete outside the heuristic.
