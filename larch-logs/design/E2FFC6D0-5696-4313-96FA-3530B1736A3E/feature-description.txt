# md-to-py-VII: dedup /design Step 3 / Gate prose: settle-rc fallback tables, Gate-B-bypass restatement, the two Step 3 entry fences, External Reviewer Setup; emit STEP4_MODE directive

**Lever:** context (always-loaded + conditional) + python (non-determinism). **Surface:** `skills/design/SKILL.md` Step 3 / Gate region (520–699), `skills/design/references/settle-rc-dispatch.md`, `approval-gates.md`.

**Problem.** Five overlapping redundancies on the design review/gate path:
- `settle-rc-dispatch.md`'s wrapper-rc table (42–52) + site-variant table (54–59) re-derive routing the always-emitted `SETTLE_NEXT_ACTION` already encodes (`design-step35-settle.md:50` calls the process rc "the compatibility fallback for older prompt-side dispatch").
- The Gate-B-bypass contract is restated 4–5× (586 routing row, 631/633 status elaborations, 635 sentinel restatement, 637–643 fence); 631/633 split carries no distinct behavior, every step3b-bypass status runs the same helper and skips Gate B.
- The two Step 3 entry fences (524–526 first-time, 530–532 Gate A/C re-entry) are one parameterized call differing only by a caller-set `--reentry` flag.
- Step 3.5 post-apply prose (659–664) pre-states the optional-trailer guard + settle wrapper + resume idempotency already normative in `approval-gates.md` (MANDATORY-read at 657); External Reviewer Setup (546–551) restates a loop-owned plan-existence check + reviewer-prompt focus-area content.
- Step 4 debate-mode is bound from a 3-condition self-compute plus an optional `dialectic-gatec --probe-only` foreground turn.

**Mechanism.**
- Collapse the two settle fallback tables to one line ("token absent → stop for repair"); keep only the primary `SETTLE_NEXT_ACTION` table.
- Dedup Gate-B-bypass to the 586 routing row + the single fence; delete 631/633/635.
- Show one parameterized Step 3 entry fence (`design-step3-entry.sh ${STEP3_REENTRY_FLAG}`) with a one-line caller note; keep the reentry-vs-first-time routing explicit (no auto-detect, reentry clears downstream sentinels).
- Slim 659–664 and External Reviewer Setup to delegation pointers.
- Have `design-step3b-entry.sh --mode finalize` emit `STEP4_MODE=foreground|background`; Step 4 reads it and picks the `run_in_background` flag, deletes the 3-condition prose and the optional probe turn.

**Savings.** ~25–35 always-loaded lines + ~18 conditional lines + non-determinism + avoids the optional probe turn.

**Risk.** Med. Verify no `test-design-structure` marker pins the inlined settle / gate-b / `design-step35-settle.sh` literals before cutting; the finalize-computed fingerprint validity must hold through Step 4 entry (no apply occurs between them). Run `make test-design-structure`.

## Edge cases

- **Missing `SETTLE_NEXT_ACTION`**: prompt-side prose must stop for repair, even if wrapper rc is known.
- **Action / rc disagreement**: preserve the existing stop-for-repair rule.
- **Step 3 re-entry**: caller must still set `--reentry`; no helper should infer it from disk state.
- **Gate-B-bypass partial sentinels**: keep `design-step3-gate-b-bypass.sh` refusal behavior and repair instruction.
- **`STEP4_MODE` probe failure**: fail closed before Step 4 tail launch.
- **`--skip-approve`**: probe-only should naturally return foreground when debate is suppressed by run params.
- **Cached dialectic digest**: probe-only should return foreground when no new debate is required.

## Failure modes

- Structural tests may fail if old fallback-table literals remain pinned.
- Step 4 can choose the wrong execution mode if `STEP4_MODE` is not parsed from the Step 3b finalize wrapper output.
- Removing too much Gate-B-bypass prose can hide the sentinel repair path; keep the single fence and parse rule.
- Removing too much settle prose can obscure wrapper rc diagnostics; preserve rc documentation in `design-step35-settle.md`, not as dispatch fallback.
