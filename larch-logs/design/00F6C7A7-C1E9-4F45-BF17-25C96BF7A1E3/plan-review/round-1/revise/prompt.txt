# Plan — Harden /implement stall reporting (issue #3563)

## Summary

Improve the auto-filed `/implement` stall report so future occurrences are actionable. Two reporting-only changes, no dispatch or classifier-behavior change:

1. Render an uncaptured exit code as `unknown` instead of the misleading `0`.
2. Surface the already-sanitized `bail_reason` in the report body so dispatch-failures name the failing envelope check (`orchestrator-envelope-invalid` / `wrapper-validation-failure`).

All work is in the `stall-recovery-report.sh` helper plus its allowlist TSV, doc sibling, and offline harness. The classifier branches (`FAILURE_CLASS`, `RESUME_HINT`, retry caps) and the sanitization boundary are untouched.

## Background (why this is safe)

- The machine `EXIT_CODE` emitted by `classify` flows only into `stall-recovery-classification.env`, which is consumed solely by `bug-body` / `bug-comment` composition. No code branches numerically on the stall-recovery `EXIT_CODE` (grep across `skills/implement/`, `scripts/` found no such consumer; `stall-recovery.md` steps 4-8 branch on `FAILURE_CLASS` / `RESUME_HINT` / `attempt_count` only). So emitting `unknown` for an uncaptured code is backward-safe.
- `chat-print` is not a separate render path: consumer repos print the composed `bug-body` / `bug-comment` verbatim (`stall-recovery.md` steps 4 and 8). Fixing `compose_body_content` therefore fixes the filed body, the filed comment, and the chat print at once.
- `bail_reason` is already a sanitized closed enum produced by `safe_bail_reason_value` and emitted by `classify` into the classification file — it is available to `compose_body_content` today; it is simply not rendered.
- `cmd_lint` (and harness case 14) enforce that the allowlist set of `(surface, field_key)` pairs is identical across the TSV, the in-code `code_allowlist_lines` heredoc, and the doc `<!-- stall-recovery-allowlist:begin -->` table. The `transform` column is documentary and NOT linted.

## Approach

- **Reuse the established `safe_*_value` pattern.** Exit-code handling becomes a one-line helper call at both the `classify` emission site and the `compose_body_content` render site, identical in spirit to step/phase sanitization. The distinction "captured 0 vs uncaptured" is preserved from `classify` onward because `classify` stops collapsing empty/non-numeric to `0`.
- **Render `bail_reason`, do not re-derive it.** The renderer re-applies `safe_bail_reason_value` to the loaded value (defense-in-depth, consistent with how `compose_body_content` already re-sanitizes step/phase/class/signature), then maps empty to `none` for a clean, always-present cell.
- **Lockstep allowlist edit.** TSV, `code_allowlist_lines`, and the doc table change together so `cmd_lint` stays green; the harness already asserts this.
- **Trade-off — `unknown` in the machine `EXIT_CODE` KV.** Emitting non-numeric `unknown` is simpler and needs no second "captured?" KV. It is safe because no consumer reads the stall-recovery `EXIT_CODE` numerically (verified by grep). The alternative (keep `EXIT_CODE` numeric, add a separate captured-flag) is rejected as more surface for no benefit.

## Edge cases

- Real `EXIT_CODE=0` (a genuine captured zero) still renders `0` — only empty/non-numeric becomes `unknown`.
- `seed-terminal-state` writes `EXIT_CODE=4`; numeric pass-through keeps `4`. No regression for terminal-seeded stalls.
- `bail_reason` empty renders `none`; a non-allowlisted value renders `redacted`; an allowlisted token renders verbatim.
- Idempotency: `classify` emits `unknown`, `compose_body_content` re-applies `safe_exit_code_value("unknown")` → still `unknown`.
- Markdownlint MD038: no empty code spans — `bail_reason` always resolves to a non-empty token before backticking.

## Failure modes

1. **Allowlist drift** (TSV / code / doc out of sync) → `cmd_lint` and harness case 14 fail closed. Earliest signal: `bash skills/implement/scripts/test-stall-recovery-report.sh` or `stall-recovery-report.sh lint`. Mitigation: edit all three in one change; lint is the backstop.
2. **A hidden numeric consumer of the stall-recovery `EXIT_CODE`** would break on `unknown`. Earliest signal: an `/implement` Step 18a run mis-handling the classification file. Mitigation: grep confirmed none; `unknown` is emitted only when the source is empty/non-numeric (numeric values pass through unchanged), so any real captured code is unaffected.
3. **Unsanitized `bail_reason` leaking into a public issue.** Earliest signal: a non-enum token appearing in a filed body. Mitigation: renderer re-applies `safe_bail_reason_value` (closed allowlist → `redacted`), and every body/comment is still piped through `redact-secrets.sh`.

## Testing strategy

- Extend `test-stall-recovery-report.sh` with the assertions above (classify `unknown` vs real `0`; body `Exit code` unknown/zero; body `Bail reason` token/none/redacted). Keep the existing classify, lint (case 14), and byte-stability (case 15) cases green.
- Run `bash skills/implement/scripts/test-stall-recovery-report.sh` and `skills/implement/scripts/stall-recovery-report.sh lint`.
- Run `bash scripts/relevant-checks.sh` for repo-wide lint (markdownlint MD038 on the new `Bail reason` cell, shell strict-mode, bash 3.2 portability of the new helper).
