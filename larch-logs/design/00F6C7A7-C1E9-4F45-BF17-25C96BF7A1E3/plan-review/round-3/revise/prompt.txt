# Plan — Harden /implement stall reporting (issue #3563)

## Summary

Improve the auto-filed `/implement` stall report so future occurrences are actionable. Two reporting-only changes, no dispatch or classifier-behavior change:

1. Render an uncaptured exit code as `unknown` instead of the misleading `0`.
2. Surface the already-sanitized `bail_reason` in the report body so dispatch-failures name the failing envelope check (`orchestrator-envelope-invalid` / `wrapper-validation-failure`).
3. Wire the existing Step-2 hard-bail reason through the in-memory `IMPLEMENT_BAIL_REASON` / `FINAL_BAIL_REASON` handoff into Step 18a `classify --bail-reason`, using a behavior-stable split so routing (`FAILURE_CLASS`, `RESUME_HINT`, retry caps) is unchanged while the rendered `Bail reason` row is populated.

All work spans the Step-2-to-Step-18a orchestration prose (`skills/implement/SKILL.md`, `skills/implement/references/stall-recovery.md`), the `stall-recovery-report.sh` helper plus its allowlist TSV, doc sibling, SECURITY.md, offline harnesses (`test-stall-recovery-report.sh`, `test-implement-structure.sh`). Classifier branch tables (`retry_cap_for`, `resume_hint_for` dispatch rules) and the sanitization boundary are untouched; `classify_from_evidence` inputs stay behavior-stable per the split below.

## Background (why this is safe)

- The machine `EXIT_CODE` emitted by `classify` flows only into `stall-recovery-classification.env`, which is consumed solely by `bug-body` / `bug-comment` composition. No code branches numerically on the stall-recovery `EXIT_CODE` (grep across `skills/implement/`, `scripts/` found no such consumer; `stall-recovery.md` steps 4-8 branch on `FAILURE_CLASS` / `RESUME_HINT` / `attempt_count` only). So emitting `unknown` for an uncaptured code is backward-safe.
- `chat-print` is not a separate render path: consumer repos print the composed `bug-body` / `bug-comment` verbatim (`stall-recovery.md` steps 4 and 8). Fixing `compose_body_content` therefore fixes the filed body, the filed comment, and the chat print at once.
- `bail_reason` is already a sanitized closed enum produced by `safe_bail_reason_value` and emitted by `classify` into the classification file — it is available to `compose_body_content` today; it is simply not rendered. Today Step 18a passes `--bail-reason "${IMPLEMENT_BAIL_REASON:-}"` but Step-2 hard-bails set only `FINAL_BAIL_REASON`, so the #3550 path classifies/renders with an empty bail token even when `execution-issues.md` names `orchestrator-envelope-invalid`.
- `classify_from_evidence` already accepts `bail` as an input, but widening that input for reporting must not reroute stalls that already classified correctly from evidence alone (#3550: `dispatch-failure` at step 2). The plan therefore splits **classification bail** (state/session only, unchanged precedence) from **report bail** (`--bail-reason` argv coalesced after `failure_class` is decided).
- `cmd_lint` (and harness case 14) enforce that the allowlist set of `(surface, field_key)` pairs is identical across the TSV, the in-code `code_allowlist_lines` heredoc, and the doc `<!-- stall-recovery-allowlist:begin -->` table. The `transform` column is documentary and NOT linted.
