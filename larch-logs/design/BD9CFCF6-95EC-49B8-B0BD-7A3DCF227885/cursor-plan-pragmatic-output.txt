## Findings

**1. [risk-integration / blocking]** `skills/implement/scripts/step-5-resume.sh:85-90`

The plan drops `|| true` from `commit-fixes --stage-all` but keeps `set -euo pipefail`. Today `commit_fixes` calls `git-commit.sh -m` after `git add -A` with no `--only` and no empty-tree short-circuit. On a clean handoff tree that commit exits non-zero, so the wrapper dies before KV relay or `review-and-fix step5`. The edge case ("`COMMITTED=false` on a clean tree is not failure") is stated but not wired to survive `set -e`.

**Suggested revision:** Capture rc without triggering `set -e`, then branch on `COMMITTED=` plus porcelain; or teach `commit_fixes --stage-all` to exit 0 when porcelain is empty after add.

**2. [correctness / important]** `python/review_and_fix.py` (proposed `_lint_fix_snapshot_paths`)

Gap #3 needs in-place edits on pre-dirty tracked files via `git diff --name-only <pre_lint_head>`. The extra porcelain bullet is ambiguous. A literal reading can union every porcelain change since loop entry and commit unrelated pre-existing dirty paths, defeating "never unrelated pre-existing dirty hunks."

**Suggested revision:** Commit set = `delta_paths ∪ names from pre_lint_head diff`; exclude paths whose porcelain line matches the entry snapshot; add a test where a pre-dirty untouched file must not be staged.

**3. [OUT_OF_SCOPE / latent]** `python/review_and_fix.py:2325-2335`

Step 7 `--stage-all` still uses `git add -A` and a non-`--only` commit. That is a pre-existing widening vs path-scoped Step 7; worth a follow-up once Step 5 stall gates are in place, not required for this issue's three gaps.
