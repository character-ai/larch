**1. [correctness] `python/review_and_fix.py` (~144–149, proposed `_lint_fix_snapshot_paths`)** — The plan’s snapshot commit helper names `pre_lint_porcelain` and `git diff --name-only <pre_lint_head>` but does not define how to exclude paths that were already dirty at loop entry and unchanged by lint-fix. `git diff` against loop-start HEAD will still include pre-existing dirty hunks on those paths. The repo already solves this for coder rounds via per-path patch snapshots in `_path_matches_pre_coder_snapshot` / `_round_coder_delta_paths` (`python/review_and_fix.py:453–479`). Reuse that pattern at lint-loop entry; do not rely on a vague porcelain-diff rule.

**2. [risk-integration] `python/review_and_fix.py:2325–2327` + `skills/implement/SKILL.md:694–696`** — Step 7 is widened to `commit-fixes --stage-all`, but `commit_fixes` still runs `git add -A` then a bare `git-commit.sh -m` with no `--only --pathspec-from-file`. That conflicts with the lint-fix pathspec-only discipline the plan adds elsewhere and can commit unrelated staged or dirty files left on the tree. Narrow `--stage-all` to stage only review-loop delta paths (same pathspec-file shape as `_stage_and_commit_round`), or add a dedicated flag.

CI still escalates via `first-fixer-non-health` today. Defer self-heal to a follow-up unless recurrence data justifies it.

**4.
