## Edge cases

- **Already-fixed CI failures**: helpers no-op and fall back to the delegated fixer path.
- **Non-incident legacy-prefix path**: never auto-expand `ALLOW=`; delegate to Claude or manual review.
- **Partition variants**: do not infer arbitrary `-k` fixes; only the known `cleanup_target_ok` overlap on `test-implement-cleanup-script`.
- **Dual CI failures in one log**: both mechanical helpers may run before a single verify pass.
- **Lint-fix on clean baseline**: `run_lint_fix` commits inline; post-loop delta commit is a no-op.
- **Lint-fix on dirty baseline**: commit only unioned `delta_paths`, never unrelated pre-existing dirty paths.
- **Lint-fix no-op**: do not create an empty review-fix commit.
- **Commit failure**: stall at Step 5 (`lint-fix-commit-failed`) or fail-closed in `step-5-resume.sh` rather than reaching ship dirty-tree push failure.

## Failure modes

- If CI logs are truncated and lack known signatures, the agentic CI fixer uses the existing Claude delegate path.
- If mechanical self-heal edits fail local verification, the existing rollback path restores the baseline and returns the current failure status.
- If Step 5 lint-fix delta commits fail, the run stalls with `lint-fix-commit-failed` instead of `push.assert_clean_worktree` at Step 8.
- If `step-5-resume.sh` handoff commit fails, the wrapper exits non-zero before re-entering the review loop.
