## Findings

**1. `step-5-resume.sh` fail-closed vs clean tree (blocking, correctness)**  
The plan drops `|| true` from `commit-fixes --stage-all` but the script keeps `set -euo pipefail`. `commit_fixes` always attempts `git commit` and returns non-zero when there is nothing to commit. On a clean tree the wrapper would exit before `review-and-fix step5`, even though the plan’s edge cases require resume to continue. The script needs explicit rc capture, KV relay, and a porcelain-empty proceed branch.

**2. `_lint_fix_snapshot_paths` porcelain rule (important, correctness)**  
Gap #3 needs precise path selection. The plan’s porcelain leg (“paths lint-fix may have touched”) conflicts with the stated rule to never commit unrelated pre-existing dirty hunks. Pin candidates to the intersection of lint-fix deltas and `git diff` against the pre-lint HEAD snapshot.

**3. `ci_agentic_fix` mechanical fast-path integration (important, risk-integration)**  
The mechanical branch should reuse the same post-verify tail as the delegate path (`forbidden` guard, `_delta_paths`, `stage_and_push`). Without an explicit shared-helper requirement, partial duplication can skip rollback or push guards.

**4. [OUT_OF_SCOPE] Step 7 `--stage-all` (latent, architecture)**  
Widening Step 7 to `git add -A` is broader than the pathspec-only lint-fix commit the plan adds elsewhere. Prefer explicit pathspecs unless orchestrator prose truly cannot name changed files; not required to close #4712 if the lint-fix commit path works.
