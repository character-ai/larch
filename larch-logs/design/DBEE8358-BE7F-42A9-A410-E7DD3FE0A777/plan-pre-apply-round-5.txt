## Edge cases

- If a file move also changes the function name, callee, env name, access kind, or occurrence number, treat it as new debt.
- If two old rows could explain one live finding (baseline relocation-key count greater than 1), treat it as ambiguous and fail closed before `--initial-reason`.
- If one old row could explain two live findings (live relocation-key count greater than 1), treat it as ambiguous and fail closed before `--initial-reason`.
- Partial regen with stale flat path plus new package path for the same relocation key must fail closed, not last-win a reason.
- For env lint, many distinct `IMPLEMENT_TMPDIR` `get` rows in `agents.py` across different `qualified_symbol` values must remain distinct relocation keys; omitting `Path(file).name`, `qualified_symbol`, or `occurrence` would collapse them and block package-move `--write`.
- If the baseline file is absent, keep the current `--initial-reason` bootstrap behavior.

## Failure modes

- A too-broad relocation key could mask new subprocess or env debt.
  - Avoid this with basename plus full semantic identity (including `qualified_symbol` and `occurrence` for env) and per-side uniqueness checks.
- A too-narrow key could leave package moves unrecoverable.
  - Preserve basename-only path movement for the observed flat-to-package move.
- Ambiguity handled after `--initial-reason` could silently bootstrap colliding rows.
  - Hard-stop ambiguous relocation matches before any `--initial-reason` consideration.
- Env relocation key missing `Path(file).name`, `qualified_symbol`, or `occurrence` would falsely flag ambiguity on real `agents.py` baselines and leave the packaging-move failure unfixed.
  - Align env relocation identity with subprocess granularity using all six fields.
