## Findings

### 1. Manifest token storage bypasses proof-of-read (security / correctness)

The plan correctly keeps `evidence_token` out of `triage-batch-*.jsonl` and `triage-pending-*.jsonl` (current batch rows only carry `issue`, `cache_key`, `bundle_path` at ```637:637:python/larch/issue/analyze_bugs.py``` and ```818:818:python/larch/issue/analyze_bugs.py```). Batch-only exclusion is not enough.

The plan also says to **store the token in the manifest record** and compare ingest rows against that manifest value. Prefetch writes the full manifest with `asdict(manifest)` at ```682:682:python/larch/issue/analyze_bugs.py```, and Stage 0 exposes `MANIFEST_PATH` at ```704:704:python/larch/issue/analyze_bugs.py```. Any Read-capable agent in the same run directory can harvest all tokens from `manifest.json` without opening any `bundle_path` file, then emit schema-valid JSONL that ingest accepts.

**Suggested revision:** Treat bundle markdown as the sole token source. Embed the coordinator token in each bundle file, parse it from disk during `ledger_ingest`, and do **not** serialize `evidence_token` into `manifest.json` `issues[]` (ingest-only lookup from bundle file is enough).

### 2. Skill prompt still allows orchestrator-side token smuggling (risk-integration)

The planned SKILL.md changes replace infeasible inlining with path-only dispatch and document ingest rejection for bad tokens. Current orchestrator `allowed-tools` include `Read` at ```5:5:.claude/skills/analyze-bugs/SKILL.md```.

The plan’s failure-mode note covers accidental **bundle** inlining (plan Approach §6) but not orchestrator reads of `manifest.json` or explicit token pasting into the Task prompt. That path satisfies ingest without the triage agent reading bundle files.

**Suggested revision:** Add hard Stage 1 prohibitions: no `MANIFEST_PATH`, no pre-extracted `evidence_token` values, and no inlined bundle bodies in Task input; only the batch path plus read instructions.

### 3. Empty `triage-pending` disables the active-batch guard (correctness)

Ingest only checks active batches when `expected_issues` is non-empty:

```1096:1099:python/larch/issue/analyze_bugs.py
        if expected_issues and parsed.issue not in expected_issues:
            print(f"WARN: rejected line {lineno}: issue not in active {stage or 'ingest'} batch", file=sys.stderr)
            rejected += 1
            continue
```

If `triage-pending-*.jsonl` is missing or empty, this guard is skipped entirely. Combined with a token source, schema-valid rows for any manifest issue can reach the ledger outside a dispatched batch. The plan does not address this path.

**Suggested revision:** Fail closed when triage ingest has rows but `expected_issues` is empty, or bind ingest to the specific batch file that was dispatched.

### 4. [OUT_OF_SCOPE] Cross-batch ingest is looser than dispatch

`_stage_issue_numbers` unions issues from **all** `triage-pending-*.jsonl` files (```875:899:python/larch/issue/analyze_bugs.py```). A single `triage-results-N.jsonl` can ingest rows for issues assigned to a different pending batch if tokens are obtainable. This is pre-existing laxity, not introduced by the token plan; fixing it needs batch-scoped ingest wiring beyond minimum-change scope.

## What the plan gets right

- Batch JSONL at ```637:637:python/larch/issue/analyze_bugs.py``` / ```818:818:python/larch/issue/analyze_bugs.py``` does not leak enough to satisfy ingest without bundle content; only paths and `cache_key` are present, and `cache_key` is a hash unrelated to a random token (plan keeps cache-key logic unchanged).
- Replacing toolless agent + infeasible inlining with Read-capable path dispatch matches current caps (`DEFAULT_DIFF_CAP` / `DEFAULT_BODY_CAP` at ```35:36:python/larch/issue/analyze_bugs.py```).
- Strict `_strict_keys` ingest at ```998:1000:python/larch/issue/analyze_bugs.py``` is the right place to add `evidence_token`; tests in the plan cover missing/wrong token and old manifests.
- Old-manifest fail-closed behavior and preserving deep-ingest’s three-field contract are appropriately scoped.

**Minimum-change recommendation:** Keep batch path dispatch and bundle-embedded tokens; drop manifest serialization of tokens; have ingest parse expected tokens from bundle files; add two SKILL.md prohibitions (no manifest, no token smuggling). That closes the main fabrication class without batch resizing or cross-batch ingest refactors.
