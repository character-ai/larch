## Approach

1. Make the agent capable of reading evidence.
2. Make the skill dispatch contract executable at current bundle caps by passing paths, not inline bundle content.
3. Add a coordinator-authored proof-of-read token inside each bundle.
4. Require that token at ingest.
5. Keep the token out of the batch file so a path-only or batch-only agent cannot satisfy the gate.
6. Keep the change local to `/analyze-bugs`. Do not resize batches unless a later performance issue requires it.

## Edge cases

- Old manifests without `evidence_token` should not accept new triage rows. Fail closed and route the operator toward rerunning prefetch.
- `NEEDS_DEEP` rows still need the correct token. An unreadable bundle row without a token must be rejected, not trusted.
- Duplicate issue rows should still be rejected before or after token validation with clear warnings.
- Deep verifier ingest must remain compatible with its existing three-field JSONL contract.
- Existing ledger rows should remain readable so old reports do not break.

## Failure modes

- If the triage agent cannot read a bundle, it may emit `NEEDS_DEEP`, but ingest will reject it unless it read enough bundle content to echo the token. That is intentional. It prevents an unread agent from authoring data that disarms the gate.
- If an orchestrator accidentally inlines bundle content including the token, the token gate cannot prove tool use. The skill prompt must therefore forbid inlining and require path-only dispatch.
- If token generation is deterministic from fields visible in the batch JSONL, a model could infer it. Use a random high-entropy token.
