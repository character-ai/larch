Main risk is first-run migration: if no history file exists, the script cannot truly know which old cache dirs were installed versus merely available. For safety, first run should seed history with known facts only: the currently installed version from Claude metadata, the executing cached version, active-session versions, and the newly verified target. A more conservative option is to skip retention-cap pruning when history is absent and only remove versions newer than verified stable; that leaves extra cache dirs once, but avoids destroying rollback candidates. The tradeoff is disk cleanup versus preserving user intent, and for this bug I would bias toward preservation.
