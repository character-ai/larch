1. **correctness** — `plan.txt:120-121` / [`skills/upgrade-larch/scripts/test-upgrade-larch-prune.sh:107-121`](skills/upgrade-larch/scripts/test-upgrade-larch-prune.sh): The `stat-fallback-mtime-zero` case says to stub `stat` so both `stat -f` and `stat -c` fail for one version, but the plan does not add a `write_stub_stat` helper analogous to `write_stub_rm`, and line 121 incorrectly says to reuse `write_stub_*` as-is. **Revision:** Specify `write_stub_stat` following the `RM_FAIL_VERSION` / `target="${*: -1}"` pattern; fail only mtime-style `-f`/`-c` invocations for the configured version; delegate all other calls to `/usr/bin/stat`.

2. **risk-integration** — [`skills/upgrade-larch/scripts/test-upgrade-larch-prune.sh:140-208`](skills/upgrade-larch/scripts/test-upgrade-larch-prune.sh): `run_case` already prepends `$bin` for `claude`, `gh`, and `rm` stubs but the plan never requires a `$bin/stat` install or `STAT_FAIL_VERSION` export. **Revision:** Wire the stat stub into `run_case` the same way as `write_stub_rm` / `RM_FAIL_VERSION`.

3. **correctness** — `plan.txt:120`: Relying on `chmod 000` on a cache directory is not a sound alternative to a stat stub for this test. On owner-owned dirs, `stat` usually still returns mtime, so the case would not force the `stat_mtime` → `0` path. **Revision:** Use the PATH stub; do not document chmod-based failure injection for cache dirs.

4. **latent** — `plan.txt:119` / proposed `list_cached_versions_by_mtime` (`sort -k1,1n`): The tiebreaker case acknowledges unstable BSD `sort` but still proposes a deterministic eviction assertion. **Revision:** Stabilize sorting (`sort -s` where available), weaken assertions, or skip on non-GNU sort.

**Stub feasibility (directive):** A PATH-injected stub can intercept the proposed `stat_mtime()` calls (`stat -f '%m' -- "$file"` then `stat -c '%Y' -- "$file"`). It is more complex than `write_stub_rm` because it must distinguish `-f` vs `-c` mtime extraction from other `stat` uses, but it remains straightforward (~15–20 lines) and matches existing harness conventions. The case is **implementable** as described once `write_stub_stat` and `run_case` wiring are added; it is **not** implementable as written if the plan is taken literally (“reuse … as-is” with no stub spec). **chmod 000** does not replace the stub for this contract.
