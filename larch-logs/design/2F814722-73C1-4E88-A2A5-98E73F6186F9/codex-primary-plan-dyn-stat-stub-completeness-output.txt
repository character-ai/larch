The plan says `stat-fallback-mtime-zero` should “stub `stat` to return non-zero for one specific version,” but the plan does not add a `write_stub_stat` analogue to the existing `write_stub_rm`, and the current harness only writes stubs for `claude`, `gh`, and `rm`.

A PATH-injected `stat` stub can realistically intercept both proposed calls from `stat_mtime()` (`stat -f '%m' -- "$file"` and `stat -c '%Y' -- "$file"`), but it must be explicit: inspect the last argv target, fail for `*/$STAT_FAIL_VERSION`, and route all other calls to the real binary without recursing through `$PATH`.

Do not replace this with `chmod 000` on the cache directory itself. `stat` of the final path’s metadata generally does not require read permission on that directory, and removing execute permission from a parent would likely cause the prune loop’s `[ -d "$dir" ]` guard to skip the entry before `stat_mtime()` is exercised. The test is therefore unimplementable as described unless the plan specifies and wires the stub.
