# Plan: Manifest-schema-drift hardening + dispatcher recovery (issue #2803)

## Goal

After a long Codex `/implement` run, Codex sometimes writes a malformed `manifest.json` (e.g. `{status, summary, checks}` missing `schema_version`, `commit_message`, `files_touched`, ...), the dispatcher bails with `manifest-schema-invalid`, and ~$5–6 of working-tree work is stashed and lost. Reduce both the **probability** of the drift (prompt-contract hardening) and the **cost when it happens** (dispatcher recovery path), without weakening the existing `ORCHESTRATOR_EDIT_AUTHORITY` trust boundary, the post-implementer mechanical safety rails, or the secrets-redaction surface for committed text.

## Approach

Three-layer defense in depth, scoped narrowly:

1. **Prevention — inline schema template** in the shared implementer base prompt so Codex/Cursor see the exact required JSON shape at the moment they write the manifest (proximity beats pointer in long contexts). The template is the **literal canonical JSON** covering every required field, not a prose enumeration.
2. **Prevention — `jq -e` self-validation** in the implementer base prompt before the atomic `mv manifest.json.tmp manifest.json`, mirroring the dispatcher's `complete`-branch predicate (including `files_touched | all(. | type == "object" and (.path | type == "string"))`). The `schema_version` check uses `(.schema_version | tostring) == "1"` so prompt-side jq accepts both numeric `1` and string `"1"` (matching the dispatcher's `jq -r` stringification — FINDING_34). For `needs_qa` manifests, also self-validate `<QA_PENDING_PATH>.tmp` requiring `.questions array length > 0` so prevention is not weaker than the dispatcher's `qa-pending-missing` branch (FINDING_35).
3. **Recovery — dispatcher fallback** in `step2-implement.sh`: when `manifest-schema-invalid` AND the prior `.status` was either `complete` or missing-with-a-valid-JSON-object-of-the-legacy-fingerprint (NOT `needs_qa`, `bailed`, or unparsable/truncated JSON) AND the post-launch working-tree delta (computed via NUL-safe set-difference against a prelaunch porcelain baseline) is non-empty AND no pre-launch staged content exists AND the post-implementer mechanical guards (branch unchanged, `.claude-plugin/plugin.json` baseline, submodule clean **including paths-under-submodule check**, Cursor HEAD-unchanged) all pass, emit the existing `STATUS=claude_fallback` + `ORCHESTRATOR_EDIT_AUTHORITY=allowed` envelope plus new `RECOVERY_FROM=manifest-schema-invalid`, `RECOVERY_PRIOR_TOOL=$TOOL_TAG`, and `RECOVERY_PATHS_FILE=$TMPDIR_ARG/step2-recovery-paths.txt` (NUL-delimited) KVs. The orchestrator's Step 2.4 branches on `RECOVERY_FROM` at entry — skipping the opportunistic Q&A and the full re-implement block — and runs only: (a) plan-scope alignment against the canonical `### NEW:/### UPDATED:/### REWRITTEN:` extraction from `## Files to modify/create`; (b) commit message synthesis piped through `scripts/redact-secrets.sh`; (c) recomputation of the recovery delta after Step 3 checks-repair so any lint-fix mutations are also committed-or-rejected together; (d) commit via Step 4 using the persisted `RECOVERY_PATHS_FILE` with `git commit --only -- <paths>` semantics so pre-existing index content is never swept in.

The pair invariant (`ORCHESTRATOR_EDIT_AUTHORITY=allowed` iff `STATUS=claude_fallback`) is preserved by construction — `RECOVERY_FROM` is an additive marker, not a new STATUS. Recovery `claude_fallback` is **commit-only**: it does **not** authorize re-implementation from the plan; the Step 2 entry matrix gains an explicit carve-out row for this distinction.

## Edge cases

- **Empty working tree on a needs_qa cycle**: implementer wrote `qa-pending.json` with a needs_qa manifest, dispatcher detects malformed needs_qa shape at line 534. Recovery MUST NOT activate (Test M2 + M6).
- **Implementer-declared bail with diff**: implementer wrote a `bailed` manifest but also left edits in the tree. Recovery MUST NOT activate (Test M3); the implementer chose to bail explicitly.
- **Untracked-only implementation**: prior implementer added new files but modified no tracked files. The recovery gate uses `git status --porcelain --untracked-files=all -z` which catches untracked entries (Test M7).
- **Pre-existing dirty user file before launch (no post-launch content change)**: the porcelain set-difference + content-snapshot overlap check excludes paths whose digest is unchanged from prelaunch (Test M14 sub-case).
- **Pre-existing dirty user file before launch (post-launch content changed)**: the content-snapshot comparison includes the path with reason `content-changed-pre-dirty-overlap` (Test M14 primary).
- **Pre-launch staged content**: any pre-launch `git diff --cached` non-empty sets `PRELAUNCH_INDEX_NONEMPTY=true` and excludes recovery entirely (Test M16). This prevents pre-staged content from being committed alongside synthesized recovery messages.
- **Path contains whitespace / rename / unusual characters**: NUL-safe porcelain `-z` + `git commit --pathspec-from-file --pathspec-file-nul` handles all valid POSIX paths (Test M13).
- **Protected-path / submodule (gitlink) / submodule (dirty content inside) / branch change in the recovered tree**: the `run_post_implementer_safety_gates` helper runs before the recovery emit; any failure bails with the matching reason and skips recovery (Tests M8, M9a, M9b, M10). Submodule guard token is **`submodule-dirty`** consistently with the existing dispatcher.
- **TMPDIR_ARG inside REPO_ROOT (e.g. scratch test fixtures)**: tmpdir-relative paths filtered from delta (Test M15). Dispatcher does NOT fail-close on this configuration — production runs use tmpdirs outside REPO_ROOT, and the test harness keeps tmpdirs under scratch repos to exercise this filter path explicitly.
- **Malformed JSON / truncated manifest**: `MANIFEST_PARSE_OK=false` excludes recovery (Test M12); a partial-edit run with a corrupted manifest never lands in `claude_fallback`.
- **Line 357 (corrupt resume counter)**: not a manifest validation failure; remains raw `emit_bailed` (Test M11).
- **Line 534 (needs_qa repair branch) / `qa-pending-missing` / `qa-pending-malformed`**: needs_qa-side failures keep existing behavior; recovery is gated to {empty-with-legacy-fingerprint, complete} only.
- **commit_message redaction**: synthesized recovery messages go through `scripts/redact-secrets.sh`; redaction is re-run after Step 3 checks-repair in case checks-repair mutates context the message references.
- **Step 3 checks-repair mutates files between Step 2.4 and Step 4**: the recovery delta is **recomputed** post-Step-3 (Test M18); the final recovery paths file is `step2-recovery-paths-final.nul`. Any newly out-of-scope path triggers `FINAL_BAIL_REASON=recovery-out-of-scope`.
- **manifest-raw.json publication**: quarantined to `manifest-raw.invalid.json`; `recovery-metadata.json` published in its place (Test M17). Committed run logs never carry an invalid manifest.
- **Multiple post-launch deltas spanning plan + out-of-plan files**: §2.4 recovery sub-branch fails closed (`FINAL_BAIL_REASON=recovery-out-of-scope`) rather than committing a partial subset.
- **schema_version numeric vs string**: prompt-side jq accepts both via `(.schema_version | tostring) == "1"` (FINDING_34); dispatcher gate at line 486-487 mirrors this via `jq -r` stringification — Test M19's inline template parse pins this.

## Failure modes

1. **Inline template drifts from canonical schema in `codex-manifest-schema.md`**. **Earliest signal**: a real `/implement` run fails because Codex follows the inline template (now wrong) and the dispatcher's `jq -e` validation against the canonical rejects it. **Mitigation**: the Edit-in-sync note in `codex-manifest-schema.md`, the inline-content presence test (Test M19), and per-implementer jq-parse + canonical-field-set assertions in `test-{codex,cursor}-implementer.sh` flag obvious omissions. The prompt-side jq predicate exactly mirrors the dispatcher predicate, with `schema_version` stringification handled on both sides.
2. **Recovery branch activates on legitimate implementer bails, accidental working-tree noise, pre-existing staged content, or out-of-scope edits**. **Earliest signal**: false-positive recoveries land bad commits or commit unrelated changes. **Mitigation**: the recovery gate is (manifest-schema-invalid) AND (manifest parses as object) AND (prior status in {empty-with-legacy-fingerprint, complete}) AND (prelaunch index empty) AND (non-empty post-launch NUL-safe set-difference with content-snapshot overlap handling) AND (all post-implementer safety gates pass including hardened submodule + paths-under-submodule check) AND (Step 2.4 plan-scope alignment passes) AND (post-Step-3 delta recomputed + re-aligned). Tests M2/M3/M6/M11/M12/M16/M8/M9a/M9b/M10/M15/M17/M18 pin every gate.
3. **Pair invariant broken by a sloppy edit to the recovery function**. **Earliest signal**: `test-step2-dispatch.sh` Tests 11a/11b/M5 fail in CI. **Mitigation**: existing Tests 11a/11b are pinned; Test M5 adds the recovery-specific pair-invariant assertion. The function emits each KV exactly once and exits 0.
4. **Recovery `claude_fallback` re-interpreted as ordinary fallback re-implementation**. **Earliest signal**: orchestrator runs `Edit`/`Write` over prior-implementer files, fights or duplicates their work. **Mitigation**: the §2 entry matrix carve-out row + the §2.4 entry branch on `RECOVERY_FROM` + the NEVER invariant under §2.4 recovery sub-branch. Pinned by Test M1's downstream assertion that no Edit/Write tool calls fire on the recovery path (offline stub).
5. **Submodule dirty file content slips through claude_fallback because the leading-status check misses it**. **Earliest signal**: a recovery commit lands edits inside a submodule worktree. **Mitigation**: hardened submodule guard runs both `git submodule status --recursive` leading-status check AND a paths-under-submodule rejection of every recovery delta path; both branches emit `submodule-dirty` consistently. Test M9b pins the dirty-file-inside-submodule case.
6. **NUL-unsafe path handling corrupts commit args for paths with whitespace / renames**. **Earliest signal**: a recovery commit stages the wrong path or fails after the synthesized message is composed. **Mitigation**: `git status --porcelain -z`, `commit-implementation.sh --pathspec-from-file --pathspec-file-nul`, and `git commit --only` flow end-to-end with NUL delimiters. Test M13 pins.
7. **`scripts/extract-plan-scope-paths.sh` diverges from `scout-plan-archetypes-wrapper.sh write_scope_files`**. **Earliest signal**: plan-scope alignment in §2.4 rejects valid recovery paths or accepts invalid ones. **Mitigation**: the design-side scout switches to the shared helper inline, and the scout harness's existing snapshot test ensures the helper's output equals the previous inline python output on a corpus of fixture plans.
