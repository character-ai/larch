**1. Test M9 bail token (`submodule-modified` vs `submodule-dirty`)**  
The plan’s recovery guard text and Test M9 use `submodule-modified`, but the live dispatcher and schema doc emit **`submodule-dirty`** at ```574:579:skills/implement/scripts/step2-implement.sh```. Tests and comments should follow the canonical token or the schema and harness diverge.

**2. Matrix vs recovery sub-branch**  
§2.4 recovery says the main agent must **not** re-implement when `RECOVERY_FROM` is set, yet the authoritative matrix still requires full Step 2.4 implementation for all `claude_fallback` rows (```937:943:skills/implement/SKILL.md```). Because the matrix explicitly overrides conflicting prose, the plan needs an explicit matrix carve-out, not only a recovery subsection.

**3. Plan-scope section naming**  
The scope gate names **"Files to modify"**, while `/design` and this plan use **`## Files to modify/create`** with `### NEW:` / `### UPDATED:` / `### REWRITTEN:` paths (```17:18:<TMPDIR>/plan.txt```, `skills/design/SKILL.md:585`). Without the scout heading regex, recovery will mis-classify in-scope work.

**4. Frozen delta vs Step 3**  
Recovery checks porcelain once in §2.4, then Step 3 may mutate the tree before Step 4’s narrow `commit-implementation.sh` call. The plan does not persist the dispatcher-approved path set, so commit scope can drift.

**5. Path normalization gap**  
Step 7a rejects bad manifest paths before external commit; recovery never runs that check on porcelain-derived paths, so forbidden path shapes could reach Step 4 if mechanical gates pass.

**6. Pre-launch porcelain timing**  
`step2-baseline.txt` is first-invocation-only (```286:288:skills/implement/scripts/step2-implement.sh```); the plan adds `step2-prelaunch-porcelain.txt` but does not say whether it is refreshed on each `--answers` launch. That choice changes what “post-launch delta” means on resume.

**7. [OUT_OF_SCOPE] Dispatcher auto-repair**  
A unconventional stronger path: synthesize a valid `status=complete` manifest from `git diff` + plan metadata inside `emit_manifest_invalid_or_recover`, stay on the existing dispatcher commit path, and reserve `claude_fallback` for cases repair cannot validate—lower cost than re-running the main agent.
