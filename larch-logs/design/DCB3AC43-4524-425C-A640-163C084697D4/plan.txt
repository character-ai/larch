## Edge cases

- **Invalid env value:** treat as off.
- **Zero or negative env value:** treat as off.
- **Co-proposed attribution:** no bonus when comma-split `reviewer_slots` length is greater than 1.
- **Neutralized ballots:** use restored proposer sidecar attribution before sole-finder detection.
- **Scope drift:** bonus gating runs only after `_scope_drift()` sets `is_oos` / `kind`; scope-drifted accepted rows stay flat OOS `+1` with zero uniqueness bonus.
- **High severity:** bonus is additive on top of `+2`, not a replacement.
- **Default compatibility:** no score or output note changes when the env var is unset or `0`.
- **Flattened `score_rows`:** never use post-aggregation `score_rows` alone to recover sole-finder status in either tally path.

## Failure modes

- Using pipe-split (`reviewer_slots` TSV format) for sole-finder detection in code review would misclassify comma-separated co-proposers as one slot and can award a sole-finder bonus on shared findings. Pin to comma-split credit-sharing contract.
- Inferring sole-finder from flattened `score_rows` after the item loop will be wrong for co-proposed accepted findings. Use per-item accumulators in `_render()` / the code-review item loop.
- Implementing sole-finder detection inside plan-review `_scoreboard()` per row would over-award every co-proposer. Detect in `_render()` and pass per-row bonus into aggregation.
- Adding a scoreboard column would break table consumers. Use a note instead.
- Applying the bonus before scope-drift classification would incorrectly reward OOS rows.
- Feeding the bonus into pruning would violate the design constraint.
