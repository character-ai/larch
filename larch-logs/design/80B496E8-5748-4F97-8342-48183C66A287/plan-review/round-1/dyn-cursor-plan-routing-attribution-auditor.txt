### 1. correctness — `python/larch/state/bootstrap.py:1113-1116`

The plan routes `_phase_coder` from `difficulty-prior.env` only. Step 2 dispatch already resolves the effective tier with operator override first:

```338:344:python/larch/implement/dispatch_step2.py
def _resolve_step2_difficulty(tmpdir: Path) -> str:
    override = larch_io.read_kv(path=tmpdir / "run-flags.sh", key="DIFFICULTY_OVERRIDE", default="", first_match=True, on_error_default=True)
    normalized_override = difficulty.normalize_tier(override)
    if normalized_override:
        return normalized_override
    prior = _read_design_difficulty_prior(tmpdir)
    return difficulty.normalize_tier(prior)
```

Bootstrap still uses a fixed Codex-first order from `external_defaults.tool_order("implement.step2_coder")` until the plan lands:

```1113:1116:python/larch/state/bootstrap.py

Reuse the same override-then-prior resolver (shared helper or equivalent logic) before `CODER_TOOL_ORDER_BY_DIFFICULTY` lookup, and add bootstrap tests for override vs prior.
