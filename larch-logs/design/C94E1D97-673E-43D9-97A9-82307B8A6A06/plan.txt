- Invalid webhook schemes must fail before transport is called.
- `urllib.request.urlopen` exceptions must map to `STATUS=failed`.
- Transport exceptions containing CR/LF must be whitespace-normalized before the 500-byte cap so CLI output stays one KV line per field.
- Invoking `python3 python/cli.py slack issue-announce` with no `--implement-tmpdir` must emit `STATUS=failed` and `ERROR=--implement-tmpdir is required` on stdout and exit `2`, not argparse usage text alone.
- Invoking with a nonexistent `--implement-tmpdir` must emit `STATUS=failed` and `ERROR=--implement-tmpdir not found` on stdout and exit `2`, not `STATUS=skipped` / `REASON=issue-not-set`.

## Failure modes

- `make lint-retired-scripts` can fail if deleted path strings remain in docs, Makefile commands, registry prose, or `agent-lint.toml` S030 pins.
- `make agent-lint` / `make lint` can fail if harness paths are removed from the tree but still pinned in `agent-lint.toml`.
- Pyright can fail if the urlopen fake has loose types. Keep helper classes simple and typed enough for the existing test style.
- The main function tests can become order-sensitive if `capsys.readouterr()` is not called after each CLI invocation.
- Unnormalized multiline transport errors can break downstream KV parsers that expect single-line `ERROR=` values.
- Leaving `--implement-tmpdir` as argparse-only `required=True` breaks closeout log parsers and any caller that expects STATUS envelope on argv errors after the shell deletion.
- Skipping the tmpdir `is_dir` guard lets a bad path fall through to `_read_kv` defaults and silently skip as `issue-not-set`, breaking closeout parity with the deleted shell.
