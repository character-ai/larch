## Findings

### 1. [testing] Design round-start-s test will not exercise production loop
**Location:** `skills/design/scripts/test-design-step3-review.sh:11-34`

The plan adds a `/design` regression via `test-design-step3-review.sh` using the existing fake Step 3 plugin. That plugin stubs `plan-review run` with `plan-review-loop-stub.sh` and never runs `review-design-step3-loop.sh` (the script that would get the new `step3_loop_persist_round_start_s` helper). Production runs the gzipped embedded loop via `plan_review._run_legacy`, not the wrapper fake path.

A post-wrapper assert on `plan-review/round-1/round-start-s` would not fail if persist logic is missing or gated wrong. Static blob string checks in `test_plan_review.py` only prove the helper text exists in the asset.

**Suggested revision:** Add a runtime test that sources the live loop (or materialized embedded copy), stubs only `run_step3_round_body`, invokes `run_design_step3_loop`, and asserts write-once `round-start-s` behavior. Keep `test_embedded_review_design_step3_loop_matches_live_script` as a companion check.

### 2. [correctness] Prior-round fallback needs explicit skill and round filters
**Location:** `python/progress_report.py:577-614`

The plan hardens `_render_inflight_gantt` with a prior-round-end fallback but does not pin the lookup contract. `scripts/render-review-phase-detail.sh` already filters `table_rrange` by `SKILL` while `gantt_rrange` does not (lines 246-262); the plan fixes that asymmetry for settled charts but omits the same constraint for the new Python prior-round helper.

Without filtering `v1 round` rows by skill and exact prior round index (`round_num - 1`), a same-number cross-skill row can skew the fallback lower bound.

**Suggested revision:** Document and implement: max `end_s` over rows where `$2=="round"`, `$4==skill`, and `$6==round_num-1` (matching `python/timing.py` / `render-review-phase-detail.sh` column layout). Pass `skill` from `_render_step5` (`implement`) and `_render_design_plan_review` (`design`).
