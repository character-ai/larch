4. **[risk-integration]** [scripts/dispatch-code-voters.sh](scripts/dispatch-code-voters.sh) `check_voter_parse_rate` (~L142–L163) — Ballot id enumeration uses `grep -cE '^### (FINDING_[0-9]+):'` and an awk pipeline that only strips `FINDING_` ids, so `### OOS_N:` headings never enter the denominator or per-id checks. That skews NOT_SUBSTANTIVE detection whenever OOS headings exist or dominate. **Suggested revision:** Extend both the count and the id-extraction loop to include `OOS_[0-9]+` in lockstep with `split_ballot_to_blocks` / `vote_for_id` contracts in [scripts/lib-vote-tally.sh](scripts/lib-vote-tally.sh).
