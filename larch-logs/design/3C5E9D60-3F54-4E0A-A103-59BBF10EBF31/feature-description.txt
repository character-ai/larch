# /design Step 0: fold degraded gate and issue fetch into session/route fences

**Problem.** The Step 0 happy path is up to six consecutive Bash calls with no model judgment between them: `design-step0-session.sh`, `design-step0-degraded.sh`, a prose-directed raw `gh issue view` plus `resolve-repo.sh` REPO resolution, `design-step0-route.sh`, a `read-result-env.sh` re-read of `.design-route-result.env`, and `design-step0-init.sh` after a prompt-side `feature-description.txt` write.

**Proposal.**

- `design-step0-session.sh` runs the degraded-tools gate internally on the common path and folds its KVs into the session envelope; the only prompt-side bounce is a `DEGRADED_PROMPT_REQUIRED=true` row for the interactive both-down `AskUserQuestion` fork. `.degraded-tools-gate-prompted` sentinel semantics unchanged, including re-entry protection.
- `design-step0-route.sh` absorbs the issue fetch (2x retry), the `issue-body.txt` write, and REPO resolution, emitting `ISSUE_TITLE`, `HAS_CLARIFY_LABEL`, and `REPO` KVs. It prints the allowlisted route-result KVs directly on stdout so the separate result-env read disappears on the proceed path.
- `design-step0-init.sh` composes `feature-description.txt` itself from the fetched title and body (the verbal path passes text through the existing argv binding).
- The verbal-path `/larch:issue` Skill call stays as the judgment boundary; cancel, clarify, already-planned, and resume route semantics unchanged.

**Acceptance.**

- Issue path reaches Step 0c after three Bash calls (session, route, init); no raw `gh` invocation remains in Step 0 prose.
- Degraded prompt, abort-cleanup, and all route branches behave exactly as today; route and parse harnesses extended.
