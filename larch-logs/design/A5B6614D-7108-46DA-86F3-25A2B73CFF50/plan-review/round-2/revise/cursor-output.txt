## Edge cases

- `ARCHITECTURAL_GUIDELINES.md` absent: prepare must not try to compute a diff; rc `0` with `STATUS=absent` continues to Step 8.
- `ARCHITECTURAL_GUIDELINES.md` invalid: prepare must emit the warning and skip diff; rc `0` with `STATUS=invalid` continues to Step 8.
- Repo root cannot be resolved for diff: present guidelines may still emit content, then diff materialization returns the existing absent or failed diff status.
- Stale Phase A artifacts survive invalidation: prepare must fail closed with rc `2`; orchestrator must stop Phase A and must not continue to Step 8.
- Prepare fence exits non-zero without `ARCHITECTURAL_GUIDELINES_STATUS=present` or `invalid`: orchestrator must not infer `absent` from missing status and must not continue to Step 8.
- Forked target state missing: wrapper must default to `false`, as the current materialize wrapper does.
- Empty implementation diff: still emit an `ok` diff status and fingerprint.
- Retired materialize wrapper left on disk: must not ship; harness negative checks and `residual-bash-paths.txt` removal both guard against dual Phase A materialization entrypoints.

## Failure modes

- If prepare returns `1` after a present read with `ARCHITECTURAL_GUIDELINES_DIFF_STATUS=failed`, the orchestrator logs the warning and continues to Step 8 without staged artifacts.
- If prepare returns `2` during invalidation (or any other non-zero exit without `STATUS=present`/`invalid`), treat it as a hard Phase A failure: append `ARCHITECTURAL_GUIDELINES_WARNING` to execution-issues and stop before Step 8. This matches the current `set -e` invalidation behavior in the read wrapper, but is now explicit for stdout-only parsers.
- If the materialize wrapper or sibling doc is not deleted, SKILL sibling-contract prose may still reference a second materialization path and operators can invoke the stale fence; explicit delete steps and harness existence checks prevent this.
- If output grammar drifts, `python/test_architectural_guidelines.py` and the shell harness should catch it.
