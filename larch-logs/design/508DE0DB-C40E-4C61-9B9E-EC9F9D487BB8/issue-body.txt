## Summary

`/upgrade-larch` deleted the **currently-running** plugin version directory (`47.0.34`) during a routine upgrade to `47.0.35`. Because the running version's directory holds the `lib-quiet.sh` redactor that the still-executing script sources, the prune deleted `scripts/redact-secrets.sh` out from under the live process, producing repeated `WARN larch_err-redaction-unavailable` lines for the rest of the run.

The deeper defect: cache retention ranks versions by **install-stamp presence first** (`-k1,1rn` on `has_stamp`). `47.0.34` had no `.larch-installed-at` stamp, so it sorted **below every stamped version** regardless of recency. With a keep-cap of 8 and 10 cached versions, the prune evicted the genuinely-oldest stamped version (`47.0.15`) **and** the unstamped-but-recent `47.0.34`, while keeping six versions *older* than `47.0.34` (`47.0.19/.20/.24/.27/.29/.31/.33`).

This is **not a regression from a new code edit**. The stamp-based ranking was introduced in #3174 (`f65e4d04e`, 2026-05-29) and the in-place marketplace refresh in #3231 (`e60c38be8`, 2026-05-30). The bug stayed dormant because every prior upgrade ran *from* a stamped version. It first triggered now because a rapid release burst (47.0.33→34→35 within ~45 min) produced an **unstamped current version** for the first time.

File: `skills/upgrade-larch/scripts/upgrade-larch.sh` (the only file with this logic — `/cleanup` does NOT share it).

## Observed incident

During `/release` (promote `v47.0.35` → run `/upgrade-larch`), the upgrade script printed:

```
Upgrading larch from 47.0.34 to 47.0.35...
...
Verified: larch 47.0.35 installed successfully.
Pruning old larch versions (keeping up to 8 most-recently-installed)...
  Removing old version: 47.0.15
  Removing old version: 47.0.34          <-- the version we were upgrading FROM (running tree)
WARN larch_err-redaction-unavailable
WARN larch_err-redaction-unavailable
Installed larch plugin version:
  ❯ larch@larch-local
    Version: 47.0.35
WARN larch_err-redaction-unavailable
WARN larch_err-redaction-unavailable
Upgrade complete. Restart Claude Code to apply the new version.
```

Two symptoms:
1. **`47.0.34` (and `47.0.15`) pruned** — but `47.0.34` was newer than 7 of the 8 retained versions. "Keep the 8 most recent" kept the wrong set.
2. **`WARN larch_err-redaction-unavailable` ×N** — emitted only *after* `Removing old version: 47.0.34`, because pruning the running tree deleted its sibling `scripts/redact-secrets.sh` (the redactor that `scripts/lib-quiet.sh` looks for at `$LARCH_LIB_QUIET_DIR/redact-secrets.sh`). The fail-open path then warned and printed each remaining log line unredacted.

### Evidence (verified on disk during the incident)

Cache after the prune (`~/.claude/plugins/cache/larch-local/larch/`): 8 dirs remain, all stamped, monotonic with version:

| Version | `.larch-installed-at` (local) |
|---|---|
| 47.0.19 | 08:17 |
| 47.0.20 | 10:17 |
| 47.0.24 | 11:44 |
| 47.0.27 | 12:56 |
| 47.0.29 | 13:19 |
| 47.0.31 | 15:27 |
| 47.0.33 | 16:51 |
| 47.0.35 | 19:00 |

Pre-prune there were 10 (the 8 above + `47.0.15` + `47.0.34`). The eviction set `{47.0.15, 47.0.34}` is exactly what the sort produces: 9 stamped (`15,19,20,24,27,29,31,33,35`) + 1 **unstamped** (`34`). Top-8 by `(has_stamp desc, ts desc, version desc)` = `{35,33,31,29,27,24,20,19}`; evicted = oldest-stamped `15` + unstamped `34`. `v47.0.34` is a normal stable release (`isPrerelease=false`), so this is not a prerelease artifact — its *local cache dir* simply never got stamped.

## Root cause

Three contributing defects; the first two must be fixed.

### Defect A — the currently-running version directory is not protected from prune
`prune_cached_versions()` seeds its retained set with only `target_version` (the just-installed version). It does **not** retain the version the script is *executing from* (`INSTALLED_VERSION`, the basename of `PLUGIN_ROOT`). When the running version ranks outside the top-8, it is deleted mid-run, removing `scripts/redact-secrets.sh` and `scripts/lib-quiet.sh` from under the live process. This is the direct cause of the `WARN larch_err-redaction-unavailable` spam and of losing the version you were running.

`skills/upgrade-larch/scripts/upgrade-larch.sh:228-230`:
```bash
    if [ -n "$target_version" ] && is_safe_version "$target_version" && [ -d "$LARCH_CACHE_DIR/$target_version" ]; then
        retained="$target_version"
    fi
```

### Defect B — a successful install is only stamped when it equals `LATEST_STABLE`
`write_install_stamp` runs only inside the `VERIFIED_TARGET=true` branch. When the marketplace HEAD installs a version that is not (yet) the promoted "latest stable" — e.g. during a release burst where the version bump has merged but its GitHub release isn't promoted yet — `ACTUAL_VERSION != LATEST_STABLE`, so `VERIFIED_TARGET=false` and **no stamp is written**. The directory persists permanently unstamped. Per Defect C's ranking, an unstamped dir sorts below *every* stamped version, so it is first in line for eviction even though it is recent. This is how `47.0.34`'s local dir ended up unstamped.

`skills/upgrade-larch/scripts/upgrade-larch.sh:363-369`:
```bash
# Prune old versions only after a verified stable install.
if [ "$VERIFIED_TARGET" = true ]; then
    write_install_stamp "$ACTUAL_VERSION"
    prune_cached_versions "$ACTUAL_VERSION"
else
    larch_err "Skipping prune because the expected stable version was not verified."
fi
```

How `LATEST_STABLE` and the installed version diverge: `LATEST_STABLE` = newest non-prerelease GitHub release (`get_stable_releases`, `gh api .../releases | select(.prerelease==false)`), while the installed version = whatever the in-place marketplace clone resolves to at HEAD (after #3231's `claude plugin marketplace update`). These can differ for the window between a version bump merging to `main` and its release being promoted.

### Defect C (design assumption, root of the mis-ranking) — `has_stamp` is the dominant sort key
`list_cached_versions_by_install_stamp()` sorts by `has_stamp` first, so all unstamped dirs rank below all stamped dirs unconditionally. The sibling doc states the intent: *"stamped directories sort before any still-unstamped legacy directories."* The assumption "unstamped ⇒ legacy/old" is false once an install lands unstamped via Defect B — an unstamped dir can be the most recent one.

`skills/upgrade-larch/scripts/upgrade-larch.sh:206-207`:
```bash
        printf '%s\t%s\t%s\n' "$has_stamp" "$ts" "$version"
    done | sort -t $'\t' -k1,1rn -k2,2rn -k3,3rn | cut -f3-
```

**Scoping decision:** Defect C's ranking is **left as-is** (do NOT change the `has_stamp` tiering). Fixing A + B makes the harmful case impossible: B prevents new unstamped dirs, and A protects the one dir whose deletion actually breaks the run. A pre-existing unstamped *non-running* dir being pruned early is harmless (it is a re-downloadable cache entry). Changing the ranking would re-litigate #3174's deliberate "trust stamps over mtime" design and is unnecessary. (An optional stamp-on-discovery backfill is noted under "Out of scope" for a future hardening pass — not part of this issue.)

### Why it "worked perfectly until now"
The retention logic has not changed since #3174 (2026-05-29). It worked because, until this session, every version you upgraded *from* had been installed via a clean verified path and was therefore stamped — a stamped→stamped upgrade never trips Defect A (running version stays in the top-8) and never self-deletes the redactor. Tonight's rapid 33→34→35 release cadence produced the first **unstamped running version** (`47.0.34`), which simultaneously exposed Defect A (wrong eviction + self-delete) and was enabled by Defect B (unstamped install). Latent bug newly *triggered*, not newly *introduced*.

## Implementation plan (precise)

All edits are in **`skills/upgrade-larch/scripts/upgrade-larch.sh`** plus its sibling doc **`skills/upgrade-larch/scripts/upgrade-larch.md`**. Shell must stay Bash 3.2-compatible (`set -euo pipefail` is already in effect; see `BASH_AUTHORING.md` §3). No new external deps.

### Change 1 — Protect the running version directory in `prune_cached_versions` (fixes Defect A)

In `prune_cached_versions()` add `_protected` to the locals, and replace the single-version seed with a loop that retains BOTH the target and the running version.

**1a.** At `upgrade-larch.sh:224`, change:
```bash
    local retained="" version version_dir removed=0
```
to:
```bash
    local retained="" version version_dir removed=0 _protected
```

**1b.** At `upgrade-larch.sh:228-230`, replace:
```bash
    if [ -n "$target_version" ] && is_safe_version "$target_version" && [ -d "$LARCH_CACHE_DIR/$target_version" ]; then
        retained="$target_version"
    fi
```
with:
```bash
    # Always retain (a) the just-installed target and (b) the version this
    # script is executing from (INSTALLED_VERSION = basename of PLUGIN_ROOT).
    # Deleting the running version's directory mid-run removes sibling helpers
    # it sources (scripts/lib-quiet.sh, scripts/redact-secrets.sh) out from
    # under the live process, which breaks outbound-log redaction and can fail
    # the remainder of the run. The just-installed target is retained for the
    # same reason it always was (it is the version operators will run next).
    for _protected in "$target_version" "$INSTALLED_VERSION"; do
        [ -n "$_protected" ] || continue
        is_safe_version "$_protected" || continue
        [ -d "$LARCH_CACHE_DIR/$_protected" ] || continue
        version_is_retained "$_protected" "$retained" && continue
        retained="${retained:+$retained }$_protected"
    done
```

Notes for the implementer:
- `INSTALLED_VERSION` is a global assigned at `upgrade-larch.sh:273` (`INSTALLED_VERSION="$(basename "$PLUGIN_ROOT")"`). Both `prune_cached_versions` call sites (the idempotent already-latest path ~line 320, and the post-upgrade path ~line 366) execute *after* line 273, so the global is set at call time. Confirm this ordering holds after editing.
- `version_is_retained` and `is_safe_version` already exist in the file; reuse them (do not reimplement).
- The keep-cap is preserved: the retention loop's `break` condition (`wc -w … -ge keep_versions`) still bounds the retained set to 8 total. Pre-seeding up to 2 protected versions just means the ranked loop fills the remaining ≤6 slots. When the running version is already in the natural top-8 (the common case), the `version_is_retained` guard makes this a no-op and behavior is unchanged.
- Do not change `keep_versions=8`.

### Change 2 — Stamp every successful install, not only verified ones (fixes Defect B)

Hoist the `ACTUAL_VERSION` resolution out of the `LATEST_STABLE` conditional so the just-installed version is stamped regardless of stable-verification, while keeping **prune** gated on verification (rollback safety unchanged).

**2a.** At `upgrade-larch.sh:343-361`, replace:
```bash
# Verify the installed version matches the expected stable release.
VERIFIED_TARGET=false
ACTUAL_VERSION=""
if [ -n "$LATEST_STABLE" ]; then
    ACTUAL_VERSION=$(get_installed_larch_version || true)
    if [ "$ACTUAL_VERSION" = "$LATEST_STABLE" ]; then
        VERIFIED_TARGET=true
        larch_err "Verified: larch ${LATEST_STABLE} installed successfully."
    else
        larch_err ""
        larch_err "Warning: expected version ${LATEST_STABLE} but found installed version ${ACTUAL_VERSION:-unknown}."
        larch_err "A pre-release or unexpected version may have been installed."
        larch_err "Re-run /upgrade-larch or install manually:"
        larch_err "  claude plugin marketplace remove larch-local"
        larch_err "  rm -rf '$MARKETPLACE_CLONE'"
        larch_err "  claude plugin marketplace add character-ai/larch --sparse $LARCH_SPARSE_DIRS"
        larch_err "  claude plugin install larch@larch-local"
    fi
fi
```
with:
```bash
# Resolve what we actually installed up front so we can stamp it regardless of
# stable verification (the stamp records WHEN the version was installed and
# drives cache-retention ranking — an unstamped directory sorts below every
# stamped version and would be pruned ahead of genuinely-older versions,
# including the directory this script runs from). Pruning itself stays gated
# on a verified stable install below to preserve rollback candidates.
VERIFIED_TARGET=false
ACTUAL_VERSION=$(get_installed_larch_version || true)
if is_safe_version "${ACTUAL_VERSION:-}"; then
    write_install_stamp "$ACTUAL_VERSION"
fi
if [ -n "$LATEST_STABLE" ]; then
    if [ "$ACTUAL_VERSION" = "$LATEST_STABLE" ]; then
        VERIFIED_TARGET=true
        larch_err "Verified: larch ${LATEST_STABLE} installed successfully."
    else
        larch_err ""
        larch_err "Warning: expected version ${LATEST_STABLE} but found installed version ${ACTUAL_VERSION:-unknown}."
        larch_err "A pre-release or unexpected version may have been installed."
        larch_err "Re-run /upgrade-larch or install manually:"
        larch_err "  claude plugin marketplace remove larch-local"
        larch_err "  rm -rf '$MARKETPLACE_CLONE'"
        larch_err "  claude plugin marketplace add character-ai/larch --sparse $LARCH_SPARSE_DIRS"
        larch_err "  claude plugin install larch@larch-local"
    fi
fi
```

**2b.** At `upgrade-larch.sh:363-369`, remove the now-duplicate stamp call inside the verified branch (prune stays gated). Replace:
```bash
# Prune old versions only after a verified stable install.
if [ "$VERIFIED_TARGET" = true ]; then
    write_install_stamp "$ACTUAL_VERSION"
    prune_cached_versions "$ACTUAL_VERSION"
else
    larch_err "Skipping prune because the expected stable version was not verified."
fi
```
with:
```bash
# Prune old versions only after a verified stable install (rollback safety).
# The install stamp was already written above, regardless of verification.
if [ "$VERIFIED_TARGET" = true ]; then
    prune_cached_versions "$ACTUAL_VERSION"
else
    larch_err "Skipping prune because the expected stable version was not verified."
fi
```

Notes for the implementer:
- `write_install_stamp` already no-ops safely when the version dir is absent (`[ -d "$version_dir" ] || return 0` at its top) and warns-but-continues if `date` fails — so calling it unconditionally is safe.
- The already-latest idempotent branch (~`upgrade-larch.sh:317-324`) already calls `write_install_stamp "$ACTUAL_VERSION"` then `prune_cached_versions`. Leave that branch as-is; it is unaffected (there `ACTUAL_VERSION == CURRENT_INSTALLED_VERSION == LATEST_STABLE`).
- After 2a, `ACTUAL_VERSION` is resolved even when `LATEST_STABLE` is empty (the `gh`-unavailable "upgrade unconditionally" path), so the install gets stamped there too. Verify no other code path relied on `ACTUAL_VERSION=""` as a sentinel (grep the file for `ACTUAL_VERSION`).

### Change 3 — Update the sibling contract doc

`skills/upgrade-larch/scripts/upgrade-larch.md` (per `.claude/rules/script-md-siblings.md`, the `.md` must be updated in the same PR as behavior changes). Update the retention/stamp description (currently around lines 12 and 19):
- State that the install stamp is now written for **any** successfully-installed version (verified or not), and that **pruning** remains gated on a verified stable install.
- State that prune always retains **both** the verified/just-installed target **and** the currently-running version directory (basename of `PLUGIN_ROOT`), and explain why (avoid deleting sibling helpers the live process sources).

## Testing / verification

There is currently **no** offline harness for `upgrade-larch.sh` (the prior harnesses were intentionally removed in #3231), and the script runs top-level code on source (not guarded by a `BASH_SOURCE == $0` block), so it cannot be sourced for unit testing without a refactor. Recommended verification (do not re-add a full harness unless a reviewer asks; if you do, follow the sibling `.md` + `make lint` Makefile-target contract):

1. **Static checks (required):** run `bash scripts/relevant-checks.sh` (or `make lint`). Confirm `make lint-bash32` passes (no Bash 4+ constructs introduced) and `shellcheck` is clean for the edited file.
2. **Manual retention check (required):** simulate the incident with a throwaway cache dir to prove the running version is retained and an unstamped dir no longer evicts a stamped-but-older one. Suggested shape (adapt; this is illustrative, run by hand):
   - Create a temp `LARCH_CACHE_DIR` with 10 fake version dirs, stamp 9 of them with increasing `.larch-installed-at` values, leave the "running" one unstamped.
   - Drive `prune_cached_versions "<target>"` with `INSTALLED_VERSION="<unstamped running version>"` and assert: (a) the unstamped running version dir still exists afterward; (b) exactly `keep_versions` are retained; (c) the oldest stamped dir is the one evicted.
   - Because the script is not source-safe, do this by copying the two functions (`list_cached_versions_by_install_stamp`, `prune_cached_versions`) and their small dependencies (`is_safe_version`, `read_install_stamp`, `stat_mtime`, `version_is_retained`, a stub `larch_err`/`warn_prune_failure`) into a scratch script for the assertion, or by temporarily adding a `BASH_SOURCE`/`$0` guard locally (do not commit the guard unless the team wants source-safety as a follow-up).
3. **Stamp-on-unverified check (required):** confirm that after `claude plugin install` resolves a version `!= LATEST_STABLE`, `.larch-installed-at` is now written for that version (Change 2). A focused read of the diff + the manual setup above is sufficient; no live release needed.
4. **Live sanity (optional, after merge):** on the next real `/upgrade-larch`, confirm no `WARN larch_err-redaction-unavailable` lines appear and the prior version remains in the cache.
