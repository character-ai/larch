Four follow-ups from issue #6108 / PR #6135 (bg-poll-guard cross-clone marker filtering). All four touch `scripts/hook-bg-poll-guard.sh` and/or its test file.

## 1. Add same-clone bare-path direct-probe test (from #6137)

The #6108 plan called for an explicit test: "Same-clone Bash direct dir probe denies." `scripts/test-hook-bg-poll-guard.sh` covers same-clone denial for Monitor, TaskOutput, `Read` under the live marker dir, `tasks/*.output` Bash and Read, and subdirectory-cwd probes. No case exercises the bare `*"$dir"*` match in `bash_has_probe_target` directly: a Bash command whose only content is the live marker directory path, with no wrapping verb.

Add a same-clone test that sends a bare `$dir`-only Bash command and asserts deny. Without it, a regression in the raw `*"$dir"*` branch, or in the result-path (`path_is_known_result`) coverage in `scripts/hook-bg-poll-guard.sh`, can land without failing CI.

**Files**: `scripts/test-hook-bg-poll-guard.sh`, `scripts/hook-bg-poll-guard.sh`.

## 2. Make assert_deny verify the marker's real STEP value (from #6140)

`assert_deny()` in `scripts/test-hook-bg-poll-guard.sh` asserts a deny reason contains `.bg-wait-active`, `STEP=...`, and `hook_version=...`. The `STEP=` check only confirms the token is present. It never compares the emitted value against the STEP the test wrote into the live marker file.

A stale constant, or a wrong value substituted into `deny_reason_with_marker()` in `scripts/hook-bg-poll-guard.sh`, would still pass every current assertion.

Strengthen `assert_deny` to accept an expected step value and compare it against the value the deny JSON actually reports.

**Files**: `scripts/test-hook-bg-poll-guard.sh`.

## 3. Track hardening idea: stamp clone identity at marker-creation time (from #6138)

`scripts/hook-bg-poll-guard.sh` filters foreign-clone `.bg-wait-active` markers using `.larch-keepalive`'s `CLONE_PATH`. When `cwd` is empty, or `.larch-keepalive` is missing, unreadable, or unparsable, the hook keeps the marker as a fail-safe. This is documented, intentional behavior from the #6108 plan's Edge Cases, not a bug: it favors false denials over false allows.

The residual risk is real: a cross-clone false positive, the original #6108 incident, can still recur whenever clone identity is unknown, until a stronger session-local identity signal exists.

Track this as a future hardening idea: have the hook wrapper stamp a durable, unambiguous clone identity at marker-creation time, instead of inferring it later from `cwd` or `.larch-keepalive`.

**Files**: `scripts/hook-bg-poll-guard.sh`.

## 4. Guard against clone-ownership helper drift across two hooks (from #6139)

`clone_paths_same()` and `marker_foreign_clone()` exist twice: once in `scripts/hook-no-progress-guard.sh` (added by #5927), once in `scripts/hook-bg-poll-guard.sh` (added by #6108). The #6108 plan chose duplication deliberately: AGENTS.md keeps contract-bearing hooks self-contained, and larch avoids a shared Bash library for hooks.

The tradeoff is real. A future fix to one copy's clone-matching logic, for example a new edge case in subdirectory-path comparison, can land in one hook and not the other. That reintroduces inconsistent cross-clone behavior between the two guards.

Consider one of:
- A short comment in each function pointing at its sibling, so an editor touching one remembers to check the other.
- A structural test that asserts the two implementations stay byte-identical, or behaviorally equivalent on a shared fixture set, so drift fails CI instead of surfacing as a future incident.

**Files**: `scripts/hook-bg-poll-guard.sh`, `scripts/hook-no-progress-guard.sh`.

## Proposed Design Outline

### Goals
- Close the bare `$dir`-only Bash probe gap in `hook-bg-poll-guard.sh` (currently allowed) and add a same-clone regression test asserting deny.
- Strengthen `assert_deny()` in `scripts/test-hook-bg-poll-guard.sh` to verify the actual marker STEP value at every existing call site.
- Stamp a durable clone identity into `.bg-wait-active` markers at creation time, and add a structural equivalence test guarding `clone_paths_same()`/`marker_foreign_clone()` drift between `hook-bg-poll-guard.sh` and `hook-no-progress-guard.sh`.

### Non-goals
- Eliminating the deliberate duplication between the two hooks (no shared Bash library for hooks).
- Extending the structural-equivalence test to the other duplicated helpers (`marker_value`, `canonical_dir`, `marker_candidates`, `marker_step_completed`/`is_step_completed`) beyond the two named clone-ownership functions.
- Changing existing sentinel-release logic or STEP-value semantics at marker-creation call sites.

### Approach sketch
- Add an unconditional bare-dir-match trigger in `hook-bg-poll-guard.sh`'s main deny loop (alongside the 7 existing gated triggers) so a command consisting only of the literal marker directory path also denies.
- Add an optional expected-step parameter to `assert_deny()`; thread the real expected STEP value through every existing call site plus the new bare-dir test.
- Add a `CLONE_PATH`-equivalent field written into `.bg-wait-active` at creation time (reusing the same canonicalization logic `.larch-keepalive` already uses); update `marker_foreign_clone()` in both hooks to prefer the embedded field, falling back to `.larch-keepalive` when absent.
- Add a new structural-equivalence test comparing the two hooks' copies of `clone_paths_same()`/`marker_foreign_clone()`.
- Update sibling `.md` docs for every behavior change (script-md-siblings rule).

### Surfaces in scope
- `scripts/hook-bg-poll-guard.sh`, `scripts/hook-bg-poll-guard.md`
- `scripts/test-hook-bg-poll-guard.sh`, `scripts/test-hook-bg-poll-guard.md`
- `scripts/hook-no-progress-guard.sh`, `scripts/hook-no-progress-guard.md`
