### 1. [risk-integration] `python/larch/review/review_and_fix.py:526-548` — Restage helper needs explicit fail-open exception handling

The plan correctly places difficulty re-staging in `_flush_review_batches_for_result` after the existing `flush_review_batches` try/except, calls it only from terminal flush sites (`_finish_step5_terminal_success`, `self-review-required`, `mav-resume-past-cap`, stall), and keeps it after `_resolve_step5_tier` (line 597) and in-loop `append_escalation` (lines 722-728). That ordering matches the issue root cause and the design-publish mirror in `python/larch/design/design_publish.py:873-881`.

The gap is exception safety. Today’s code-review flush path swallows all exceptions so Step 5 terminal status is unchanged (`review_and_fix.py:537-548`). The plan’s `### UPDATED: python/larch/review/review_and_fix.py` section only mandates warning on non-zero CLI exit. Without an explicit `except Exception` around restage, a raised error could hit the outer `step5` handler (`review_and_fix.py:777-781`) and flip a successful terminal path.

**Suggested revision:** Add to the plan that `_restage_difficulty_batch` (or its call site) uses the same fail-open exception envelope as the code-review flush, not only non-zero `run-log write` exit codes.
