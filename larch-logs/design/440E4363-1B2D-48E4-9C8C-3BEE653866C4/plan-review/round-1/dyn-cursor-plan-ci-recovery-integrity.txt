## Findings

1. **correctness** — `python/larch/implement/ci_fixer_lane.py:501-554`: The plan fixes foreign-run rejection in `_read_rounds`, but the global `attempts` set at lines 501–509 and the unscoped duplicate check at lines 553–554 still key only on attempt number. After lineage B reuses attempt `1`, those checks can still raise `LaneClosedError` even when column 3 differs. Duplicate detection must be scoped to `(run_id, attempt)` in both read and persist.

2. **correctness** — `skills/implement/scripts/step-8-ci-fixer.sh:138-169`: Tier selection reads attempted tiers from column 2 of `lineage-$LINEAGE_KEY.tsv`. Crash finalization is planned to append lineage rows from Python, but the plan does not pin the same six-column layout the success path uses at line 138. A mismatched crash row can skip tier advancement or inflate `ATTEMPT`.

3. **architecture** — `python/larch/cli.py:69`, `skills/implement/scripts/step-8-ci-fixer.sh:89-105`: The crashed-lane helper is specified inside `ci_fixer_lane.py`, yet the firm file set omits `python/larch/implement/ci.py` and `python/larch/cli.py`. The wrapper needs a registered CLI entry the shell can call on the non-zero path, matching how `--start` invokes `ci fixer-lane`.

4. **correctness** — `skills/implement/scripts/step-8-ci-fixer.sh:102-105`, `python/larch/bgjob/model.py:120-123`: Finalize currently gates on `$STEP.merge.env` (line 105). On non-zero bgjob exits the daemon writes `$STEP.result.env` with `BGJOB_RC` while merge env stays absent. The plan’s branch-after-result-envelope rule should name `.result.env` explicitly so implementers do not keep treating a missing merge env as `REASON=missing-result` on crash paths.

5. **correctness** — `python/larch/implement/ci_fixer_lane.py:282-288`, `python/larch/core/config.py:250`: The plan’s global cap near `BGJOB_LOG_TAIL_BYTES` conflicts with per-file tail reads of up to 4096 bytes each. Without a single composed-and-truncated payload, diagnostics can exceed the intended bound and weaken the committed-log egress contract in `SECURITY.md`.
