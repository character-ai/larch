## Approach

1. Fix the shared ledger contract first: retain all valid history, while scoping duplicate-attempt detection to a run ID.
2. Branch on the daemon-owned result envelope before requiring lane-owned success artifacts.
3. Keep crash handling in Python, where identity, repository safety, redaction, durable diagnostics, idempotency, and configured tier selection can be validated together.
4. On a non-zero daemon result, validate clean repository state and salvage-commit provenance before crashed-tier accounting; reship validated salvage work rather than retrying another tier.
5. Persist and verify one redacted bounded diagnostic before any retry-eligible lineage advancement.
6. Reuse existing tier selection, run-log writing, redaction, and byte-cap mechanisms. Do not add a second waterfall policy or diagnostic store.
7. Leave prompt hardening, complexity-baseline behavior, local-check scope, and bgjob daemon semantics unchanged.

## Edge cases

- Valid foreign-run rows remain in `fixer-rounds.tsv` and may reuse an attempt number.
- Duplicate attempts within one run ID and any malformed rounds or lineage row remain fatal.
- `BGJOB_RC=timeout`, `BGJOB_RC=orphaned`, and numeric non-zero exits use the same crash-finalization route.
- A stale status file from another lineage cannot affect a non-zero route.
- A successful bgjob with absent or mismatched lane artifacts remains an integrity failure.
- A crash after a validated clean lane-owned salvage commit returns `reship`, not `retry-next-tool`.
- Dirty worktree state, unknown `HEAD` provenance, or unexpected advanced commits fail closed rather than launching another tier.
- Missing stdout or stderr logs produce explicit unavailable sections without blocking available diagnostic sources.
- Re-entering finalize after a partial failure converges without duplicate lineage rows or committed warnings.
- Hostile control text, credentials, and absolute paths are treated only as redacted evidence; the final combined diagnostic remains bounded.

## Failure modes

1. **The ledger fix drops prior lineage history.**
   - Earliest signal: the cross-lineage test finds only the new row after `_persist`.
   - Mitigation: validate and render all rows, while scoping only duplicate detection by run ID.

2. **A crash retries despite a salvage commit or unsafe repository state.**
   - Earliest signal: `retry-next-tool` is emitted after `HEAD` advanced or with uncommitted drift.
   - Mitigation: validate `HEAD`, worktree cleanliness, and narrow lane-owned salvage provenance before crash accounting; emit `reship` only for the validated salvage case and otherwise fail closed.

3. **A crash advances the tier without durable accounting.**
   - Earliest signal: finalize emits `retry-next-tool` while the lineage row or execution issue is absent.
   - Mitigation: persist and verify the diagnostic and lineage state before retry; fail closed on either error.

4. **Crash diagnostics exceed the committed-log boundary or leak sensitive data.**
   - Earliest signal: oversized-tail fixtures exceed the total cap or retain a token or tmpdir path.
   - Mitigation: compose, redact, and truncate one combined payload; test total size and both secret/path redaction.
