## Approach

1. Fix the root ledger contract first. Keep all valid history rows, but scope duplicate detection to each run ID.
2. Add the crash route at finalize, where the daemon result and launch identity are available without violating the no-evidence-reads rule.
3. Put validation, redaction, diagnostic composition, idempotency, and tier selection in Python. Keep Bash limited to envelope discovery and routing.
4. Persist the diagnostic and crashed lineage row before returning a retry result.
5. Reuse the existing tier selector, execution-issue writer, redactor, and byte-cap constant. Do not add a second waterfall policy or diagnostic store.
6. Leave prompt hardening, complexity-baseline behavior, local-check scope, and bgjob daemon semantics unchanged.

## Edge cases

- Valid foreign-run rows remain in `fixer-rounds.tsv` and may reuse the same attempt number.
- Duplicate attempts within one run ID still fail closed.
- Any malformed rounds or lineage row remains fatal, even when it belongs to another run.
- A stale status file from the prior lineage must not affect a non-zero bgjob route.
- `BGJOB_RC=timeout`, `BGJOB_RC=orphaned`, and numeric non-zero exits follow the same crashed-attempt accounting.
- A successful bgjob with absent or mismatched lane artifacts remains an integrity failure.
- Missing stdout or stderr logs produce an explicit unavailable section without blocking the other diagnostic sources.
- Re-entering finalize after a partial failure must converge without duplicate rows or duplicate committed warnings.
- Diagnostic text may contain hostile control text, credentials, or absolute paths. Treat it only as redacted evidence.

## Failure modes

1. **The ledger fix drops prior lineage history.**
   - Earliest signal: the cross-lineage test finds only the new row after `_persist`.
   - Mitigation: validate all rows, preserve all rows when rendering, and scope only duplicate detection by run ID.

2. **A crash advances the tier without durable accounting.**
   - Earliest signal: finalize emits `retry-next-tool` while the lineage row or `execution-issues.md` entry is absent.
   - Mitigation: persist and verify the diagnostic and lineage row before emitting the retry result. Fail closed on either error.

3. **Crash diagnostics leak secrets or temporary paths into committed logs.**
   - Earliest signal: hostile diagnostic fixtures retain a token or fixture tmpdir after finalization.
   - Mitigation: use the shared redaction pipeline, cap the final redacted payload, test both secret and path fixtures, and block advancement if persistence cannot complete safely.
