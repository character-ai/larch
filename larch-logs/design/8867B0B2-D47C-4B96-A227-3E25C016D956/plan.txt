## Approach

Implement the narrow reset path from the approved outline.

- Add a best-effort `deactivate_run(repo_root)` helper in `progress_file.py`.
- Add a `progress session-reset` CLI path in `statusline.py`.
- Wire `scripts/sessionstart-statusline.sh` to run reset before install.
- Reset only for SessionStart payload `source` values `startup` and `clear`.
- Skip reset for `resume` and `compact`.
- Skip reset when `_clone_has_live_bgjob(repo_root)` reports a live bgjob for the clone.
- Delete only `~/.cache/larch/progress/<clone-hash>/current`.
- Keep run directories and `breadcrumbs.log` files untouched.
- Keep `activate_run`, `append_breadcrumb`, `progress note --run-id`, cleanup, retention, and staleness rendering unchanged.
- Keep the reset fail-silent so Claude startup is never blocked.

Security policy note: do not update `SECURITY.md` unless implementation broadens deletion beyond the single clone-local pointer. The planned change preserves the existing symlink-refusal posture and does not change the public security policy.

## Edge cases

- Missing or malformed SessionStart JSON must no-op.
- Payloads with no repo path must no-op.
- Relative repo paths must no-op through existing `_repo_from_payload` behavior.
- `source=resume` and `source=compact` must preserve `current`.
- A live bgjob in the same clone must preserve `current`, even when the source is `startup` or `clear`.
- Missing `current` must not create any progress files.
- Symlinked progress roots, clone dirs, pointer files, and non-regular pointer files must fail silent.
- Old run logs must remain available for retention cleanup.
- New runs must still become visible through the existing `progress activate` then breadcrumb path.

## Failure modes when non-trivial

- Reset runs on `resume` or `compact`: active breadcrumbs vanish during a real continuation.
- Reset ignores live bgjobs: a background larch run loses its visible progress during session start.
- Reset deletes a run directory: retention and audit evidence are corrupted.
- Reset follows a symlink: a same-user symlink swap can delete an arbitrary file.
- Hook reads stdin twice: the second Python call receives an empty payload and reset silently misses.
- Hook exits non-zero: Claude startup can be blocked by a cosmetic statusline feature.
- CLI is added to machine stdout keys: prompt-side callers may treat an empty reset command as a machine envelope.

## Testing strategy

Run only changed-file checks.

- `python3 -m pytest python/tests/report/test_progress_statusline.py -q`
- `bash scripts/test-sessionstart-statusline.sh`
- `python3 python/cli.py progress session-reset --help`
- `python3 python/cli.py progress statusline --help`
- If the changed-file check runner is available and the tree contains only these edits, run `python3 python/cli.py checks run-relevant`.

Manual smoke test:

1. Create a temp repo.
2. Activate an old run and append one breadcrumb.
3. Render statusline and confirm the old row appears.
4. Pipe `{"source":"startup","cwd":"<repo>"}` into `python3 python/cli.py progress session-reset`.
5. Render statusline again and confirm it is empty.
6. Activate a new run, append its first breadcrumb, and confirm only the new row appears.
