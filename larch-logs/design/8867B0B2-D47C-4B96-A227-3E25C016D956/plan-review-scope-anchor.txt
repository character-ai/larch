## Proposed Design Outline

### Goals
- Stop the leftover clone-scoped `current` progress pointer from rendering a stale breadcrumb at Claude session start.
- Make the first larch statusline entry the new run's first breadcrumb, not the previous run's leftover.

### Non-goals
- No changes to `activate_run`, `append_breadcrumb`, `progress note --run-id`, cleanup/retention, or the renderer's staleness math.
- No new "session" concept in the renderer; no deletion of run directories or `breadcrumbs.log` bodies.
- No change to statusline install, opt-out, or `refreshInterval` behavior.

### Approach sketch
- Add a fail-silent `deactivate_run(repo_root)` to `progress_file.py` that unlinks only the clone's `current` pointer (symlink-safe, fd-anchored, best-effort).
- Add a `progress session-reset` verb (in `statusline.py`, which already owns payload→repo-root and live-bgjob helpers) that parses the SessionStart payload, gates on `source ∈ {startup, clear}`, skips when a live bgjob exists, then calls `deactivate_run`.
- Wire the new verb into the existing `sessionstart-statusline.sh` SessionStart hook (one extra fail-silent pipe); honor `LARCH_STATUSLINE_DISABLE=1` like install.

### Surfaces in scope
- `python/larch/report/progress_file.py` (new `deactivate_run`)
- `python/larch/report/statusline.py` (new session-reset core + main)
- `python/larch/cli.py` (register `("progress", "session-reset")`)
- `scripts/sessionstart-statusline.sh` + `scripts/sessionstart-statusline.md` (wiring + contract)
- `docs/progress-reporting.md` (document the reset)
- Tests: `python/tests/report/test_progress_statusline.py`, `scripts/test-sessionstart-statusline.sh`
