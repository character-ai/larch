# /design: collapse per-fence boilerplate via a shared session launcher

**Problem.** Every Bash fence in `skills/design/SKILL.md` (about 40 today) repeats the same boilerplate: `--session-env-path "$HOME/.cache/larch/sessions/current-design-env-$PPID.sh" --claude-pid "$PPID"`. The repetition bloats the always-loaded skill body and invites copy drift between fences. It is the /design analog of the rehydration-prelude repetition #4011 removes from /implement.

**Proposal.**

- Share one launcher mechanism with #4011 rather than inventing a second pattern. #4011 is in flight; this issue MAY modify that implementation if needed (for example, generalize the `larch-run.sh` emission into a shared helper with per-skill anchors) so one mechanism serves both skills.
- /design anchor: Step 0a (`design-step0-session.sh`) writes an executable launcher keyed on the existing `$PPID` symlink convention (for example `~/.cache/larch/sessions/design-run-$PPID.sh`). The launcher bakes in the resolved `--session-env-path` and `--claude-pid` values and execs the named wrapper with the remaining argv.
- Post-Step-0a fences in SKILL.md and references collapse to one line each, for example `"$HOME/.cache/larch/sessions/design-run-$PPID.sh" design-step3-entry.sh`. `$PPID` still expands exactly once in the root Bash-tool shell, preserving the documented nesting-hazard semantics.
- Pre-Step-0a fences (parse/session) keep their current shape. Wrapper-internal source-env and pause-check contracts are unchanged (NEVER #7 unaffected).

**Acceptance.**

- Post-Step-0a fences are one line each; `scripts/test-design-structure.sh` pins the new shape and the pause-check invariant still passes.
- One shared launcher mechanism serves /implement and /design; Bash 3.2 portable; no behavior change to any wrapped script.

**Ordering.** Blocked by #4019 (HARD-flow removal deletes several fences this issue would otherwise rewrite) and #4011 (the shared mechanism lands there first; see Proposal for the permitted-modification carve-out).
