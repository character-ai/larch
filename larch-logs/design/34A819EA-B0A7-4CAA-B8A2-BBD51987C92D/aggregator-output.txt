### FINDING_1: `design-step-prelude.sh` remains listed as a launcher target
- **Reviewer(s)**: Cursor-Arch, Cursor-Pragmatic
- **Severity**: important
- **Concern**: The plan removes or changes post-Step-0a launcher fences, but still presents `design-step-prelude.sh` as a launcher example. That script only sources session state and pause-checks, so copying the example would create a no-op fence.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Remove `design-step-prelude.sh` from launcher examples; keep it only as retired prelude prose, or state explicitly it is not a valid launcher target.
  - From Cursor-Pragmatic: Omit `design-step-prelude.sh` from launcher examples; if the wrapper inventory still lists it, note it is not a launcher-routed fence target

### FINDING_2: `CLAUDE_PLUGIN_ROOT` validation can occur after session writes
- **Reviewer(s)**: Cursor-Innovation, Cursor-Pragmatic
- **Severity**: important
- **Concern**: `write_design_env_main` may write or refresh session artifacts before validating `CLAUDE_PLUGIN_ROOT` when `--claude-pid` is set. An invalid plugin root can leave a partially refreshed session without a usable launcher.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: In write_design_env_main, when args.claude_pid is set, validate non-empty CLAUDE_PLUGIN_ROOT via _validate_plugin_root_value before _atomic_write, symlink refresh, or _write_design_run_sh; on failure emit ERROR= and return 1 with no side effects
  - From Cursor-Pragmatic: When `args.claude_pid` is set, require a non-empty validated `CLAUDE_PLUGIN_ROOT` before `_atomic_write(out_path, …)` and before symlink/launcher writes; keep the planned nonzero `ERROR=` exit and no `design-run-<pid>.sh` on failure

### FINDING_3: Launcher path authority can drift from the design symlink path
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: The plan does not pin `design-run-$PPID.sh` to the same home-cache authority as `_design_symlink_path`. If launcher writes reuse broader writer-target logic or XDG cache paths, `write-design-env` can succeed for `source-env.sh` and the symlink while failing to place the launcher beside the current design env symlink.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: Define `_design_run_path(pid)` beside `_design_symlink_path` using the same `Path.home()/.cache/larch/sessions` parent; write the launcher with the symlink guard (`_assert_no_symlink_path_or_ancestors` / `_safe_output_parent`) and atomic `0o755` write, not `_writer_target_allowed`; extend `test_session_env.py` XDG case to assert `design-run-<pid>.sh` beside the home-cache symlink
