## Approach

Add a small durable run-log artifact for implement Step 8 guideline outcomes.

Use one JSON replace-mode batch `architectural-guideline-outcome.json` with schema version 1:

- `schema_version`: always `1`
- `phase`: `implement`
- `step`: `8`
- `outcome`: `pinned`, `clean`, or `dropped`
- `reason`: stable reason token
- `detail`: redacted bounded diagnostic, when useful
- `guidelines_status`: `present`, `absent`, or `invalid`
- `head_sha`
- `base_ref`
- `assessment_kind`: `clean`, `deviation`, or empty

**Classification rules:**
- `outcome=pinned`: guidelines_status=present and a redacted note is returned and passed to PR body.
- `outcome=clean`: guidelines_status=absent or invalid (missing/invalid guidelines), OR guidelines_status=present and the note is the CLEAN_PRESENTATION_NOTE.
- `outcome=dropped`: guidelines_status=present and note cannot be shipped (materialization, read, redaction, fingerprint, or stale artifact failure).
- `needs_assessment=True` with no prior outcome: skip sidecar write; no durable outcome until a terminal resolution.

Reserve `dropped` exclusively for guidelines_status=present failures. Absent or invalid guidelines map to `outcome=clean`, not `dropped`, so the drop rate is not inflated.

Write the outcome sidecar before the optional warning append. The sidecar write is best-effort; failure logs a warning but does not stall ship.

Flush the outcome sidecar in the same pre-PR log commit as the first full refresh, after `_guidelines_gate_before_pr` resolves. Both initial PR-create and the rebase-refresh path (`_refresh_guidelines_gate_after_rebase`) share this same flush contract through a single helper. Only one pre-PR flush occurs per compose attempt. If `flush_logs_pre` returns volatile-only (nothing new committed), verify the committed `architectural-guideline-outcome.json` exists and matches the tmpdir sidecar; a matching committed artifact is acceptable.

After a log-only flush advances HEAD (larch-logs changes only), the diff fingerprint is unchanged. Re-pin the durable note metadata (`HEAD_SHA`/`ASSESSED_HEAD_SHA`) to the post-flush HEAD when only larch-logs changed, or teach `note_consumable` to accept fingerprint-stable notes after larch-logs-only commits, so the outcome flush does not invalidate the just-composed note.

Keep the existing warning-append path for human-readable diagnostics in `execution-issues.ndjson`. Do not rely on warnings as the only durable signal.

Do not add `architectural-guideline-outcome.json` to the generic step8 condition in `docs/run-logs-required-files.tsv`. The version-aware dedicated scan handles pre-feature legacy runs gracefully; a generic step8 row would false-fail older runs.

## Edge cases

- A log-only flush advances HEAD before PR creation. Re-pin note metadata to post-flush HEAD when only larch-logs changed, or teach note_consumable to trust fingerprint-stable notes across larch-logs-only commits.
- `--no-logs-commit` cannot satisfy committed-log coverage. Write sidecar to tmpdir only; do not stall.
- Existing historical runs lack the artifact. The scan treats them as informational; fluff-analysis tracks them as missing-legacy.
- Redaction failures must not write raw note text or raw exception data into the JSON artifact.
- A dropped outcome and a warning entry may both exist; they dedupe independently.
- `needs_assessment=True` without a terminal resolution: skip sidecar write; do not emit an incomplete outcome.
- Volatile-only refresh: accept if committed artifact already exists for the run.
- Absent or invalid guidelines: `outcome=clean`, not `dropped`. Drop rate not inflated.

## Failure modes

- If the pre-PR flush fails, stall before PR creation (except no-logs-commit mode).
- If the sidecar is malformed, the run-log flush should fail closed through the JSON sanitizer.
- If audit cannot infer Step 8, report informational rather than fail for legacy runs.
- If fluff-analysis sees malformed outcome JSON, count the run as missing or invalid; report in coverage section; do not crash.
- If GC slimming runs before the keep-set update ships, affected runs lose the outcome. Audits treat gc-slimmed absent artifact as informational.
