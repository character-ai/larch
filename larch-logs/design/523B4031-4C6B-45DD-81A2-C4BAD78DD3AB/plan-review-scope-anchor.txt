- Survivor scripts must call `python3 "$SCRIPT_DIR/../python/cli.py" ...`, not `${CLAUDE_PLUGIN_ROOT}/python/cli.py`, so they do not fail under `set -u` when `CLAUDE_PLUGIN_ROOT` is unset (direct checkout or copied-harness execution). Skill fences and Python modules may keep the `${CLAUDE_PLUGIN_ROOT}` form.

## Decisions to carry into design

1. **Parity-gap handling.** If a `cli.py` verb is not a complete replacement (flags, exit codes, stdout/stderr), fix it in `python/git.py` / `push.py` / `phantom.py` in this slice so every helper deletes atomically in one PR.
2. **Test-coverage bar.** Before deleting a Bash harness, confirm `python/test_git.py` / `test_push.py` / `test_phantom.py` cover its behavior. Add pytest cases for gaps. No silent coverage loss.
3. **Legacy stderr prefixes** such as `git-commit.sh:` inside `python/git.py` / `push.py` and in pytest assertions are intentional parity output. Keep them; do not remove them to satisfy reference lint.
4. **Argument-error parity.** Some helpers intentionally exit 0 on parse errors (for example `snapshot-untracked.sh`, `check-remote-branch.sh`). Preserve that behavior where callers rely on fail-open.
