## Findings

### 1. code-quality / correctness — Failure recording contract (`python/larch/issue/execution_issues.py:151-152`, `skills/implement/scripts/test-flush-execution-issues.sh:254-255`)

The Bash harness records failure in `execution-issues.md` with substrings `run-log failed` and `simulated larch-log failure`. The real flush path uses `_append_failure` with site `flush-execution-issues` and message `run-log exited {proc.returncode}`; failed append stderr lands in `APPEND_LOG_FILE` only (`execution_issues.py:146-152`).

Because `make test-flush-execution-issues` runs only `pytest -k flush` (`Makefile:931-932`), those Bash strings were never CI-gated. New pytest must follow `_append_failure`, not the stale Bash expectations.

### 2. correctness — Idempotent wrapper KV and batch line count (`python/tests/issue/test_execution_issues.py:73-85`, `skills/implement/scripts/test-flush-execution-issues.sh:205-208`)

Bash idempotent rerun asserts `RECORDS=0` on wrapper stdout and unchanged NDJSON batch line count. Preserved `test_flush_execution_issues_idempotent_when_sentinel_matches` calls `flush_execution_issues` directly, checks `already-flushed`, and omits `records == 0` and batch line-count checks.

Plan text “preserve existing idempotency … tests” conflicts with “cover every behavioral assertion removed from Bash” unless those tests are extended via `flush_execution_issues_main`.

### 3. correctness — Per-section batch idempotency (`python/tests/issue/test_execution_issues.py:88-110`, `skills/implement/scripts/test-flush-execution-issues.sh:228-235`)

Per-section-probe rerun after sentinel removal asserts `RECORDS=0` and `before == after` on batch lines. `test_flush_execution_issues_already_flushed_when_batch_contains_normalized_sections` hits the same `batch_matches` branch but does not assert main stdout `RECORDS=0` or NDJSON line-count stability.

### 4. correctness — `APPEND_LOG_FILE` KV on success (`python/larch/issue/execution_issues.py:238-239`, `skills/implement/scripts/test-flush-execution-issues.sh:158-159`)

Plan lists readable `APPEND_LOG_FILE` for the success case. Bash parsed `APPEND_LOG_FILE=` from wrapper stdout via `kv_value`. New pytest should parse that KV from `flush_execution_issues_main` stdout, not infer append success only from batch file presence.
