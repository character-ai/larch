1. [correctness] `skills/design/scripts/tally-plan-review.sh:79-314`

Concern: the proposed always-emit `tally-error` fallback does not actually cover the named early exits if it only extends the current `cleanup` trap at line 314. Several `exit 2` paths happen before that trap exists. Also, a literal "add at the end of cleanup" implementation will run `rm -rf "$WORKDIR"` before testing `$?`, which can clobber the original failing exit code.

Suggested revision: register the trap before any nonzero exit path and capture `rc=$?` as the first line of `cleanup`. Use a blank-safe `WORKDIR=""` initialization so early cleanup does not trip `set -u`.

2. [risk-integration] `scripts/dispatch-plan-voters.sh:224-236`

Concern: the proposed `voter_coverage_emit_voter_kvs(index, path, tool, status, parse_rate_status)` abstraction conflicts with the plan’s byte-identical stdout requirement. The current block emits `VOTER_2_PATH`, then `VOTER_3_PATH`, then `VOTER_PATHS_FILE`, then the remaining Voter 2/3 fields. A sequential per-voter helper would change that order.

Suggested revision: either keep the KV block inline, or make the helper own the whole existing emit sequence so it can preserve the exact order and `VOTER_PATHS_FILE` placement.
