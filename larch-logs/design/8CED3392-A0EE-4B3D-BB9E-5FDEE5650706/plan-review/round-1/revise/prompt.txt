### NEW: `scripts/test-step0b-router-flag-recovery.sh`

New harness that exercises the SKILL.md Step 0b recovery jq-merge against the same
`write-run-params.sh` output the runtime produces. The harness reproduces the canonical
shell snippet from `skills/design/SKILL.md` Step 0b (the merge expression matches the
substring pinned by the new `contains` check in (1) above so drift between SKILL.md
and the harness is caught at the SKILL.md side).

Structure:

```bash
#!/usr/bin/env bash
# Regression harness for SKILL.md Step 0b router-flag jq-merge recovery.
# Verifies that partition_requested / brainstorm_requested OR-merge and
# manual_gate_b OVERWRITES from the current argv-derived value.
set -euo pipefail
export LARCH_QUIET_DISABLE=1

REPO_ROOT=$(cd "$(dirname "$0")/.." && pwd -P)
WRITER="$REPO_ROOT/scripts/write-run-params.sh"

fail() { echo "FAIL: $1" >&2; exit 1; }
TMPROOT=$(mktemp -d "${TMPDIR:-/tmp}/larch-step0b-recovery.XXXXXX")
trap 'rm -rf "$TMPROOT"' EXIT

# merge_run_params replicates the SKILL.md Step 0b jq-merge snippet verbatim
# (modulo $DESIGN_TMPDIR pointer indirection). Update both this function and
# SKILL.md together; CI pins the SKILL.md side via test-design-structure.sh.
merge_run_params() {
  local out="$1" partition_requested="$2" brainstorm_requested="$3" manual_requested="$4"
  local _rp_merge _rp_err
  _rp_merge=$(mktemp "${TMPDIR:-/tmp}/larch-router-flags-merge.XXXXXX")
  _rp_err=$(mktemp "${TMPDIR:-/tmp}/larch-router-flags-merge-err.XXXXXX")
  jq -c \
    --argjson merge_p "$([[ "$partition_requested" == true ]] && echo true || echo false)" \
    --argjson merge_b "$([[ "$brainstorm_requested" == true ]] && echo true || echo false)" \
    --argjson merge_m "$([[ "$manual_requested" == true ]] && echo true || echo false)" \
    '.partition_requested = (.partition_requested == true or $merge_p) | .brainstorm_requested = (.brainstorm_requested == true or $merge_b) | .manual_gate_b = $merge_m' \
    "$out" >"$_rp_merge" 2>"$_rp_err" || { cat "$_rp_err" >&2; rm -f "$_rp_merge" "$_rp_err"; return 1; }
  mv -f "$_rp_merge" "$out"
  rm -f "$_rp_err"
}

# Case 1: all stored false; manual-only argv => manual=true, partition/brainstorm stay false.
# Matches the FINDING_9 scenario ("--manual-only argv followed by jq-merge").
OUT1="$TMPROOT/case1.json"
"$WRITER" --classification SIMPLE --partition-requested false --brainstorm-requested false --manual-gate-b false --output "$OUT1" >/dev/null
merge_run_params "$OUT1" false false true
jq -e '.partition_requested == false and .brainstorm_requested == false and .manual_gate_b == true' "$OUT1" >/dev/null \
  || fail "case1: manual-only argv merge produced $(cat "$OUT1")"

# Case 2: stored manual=true; argv manual=false => manual=false (OVERWRITE semantic).
# This is the asymmetry: partition/brainstorm OR-merge, manual is overwritten so omitting
# --manual clears stale persisted manual mode (SKILL.md Step 0b rationale).
OUT2="$TMPROOT/case2.json"
"$WRITER" --classification SIMPLE --partition-requested false --brainstorm-requested false --manual-gate-b true --output "$OUT2" >/dev/null
merge_run_params "$OUT2" false false false
jq -e '.manual_gate_b == false' "$OUT2" >/dev/null \
  || fail "case2: manual_gate_b overwrite did not clear stored true; got $(cat "$OUT2")"

# Case 3: stored partition=true; argv partition=false => partition=true (OR-merge preserves).
OUT3="$TMPROOT/case3.json"
"$WRITER" --classification SIMPLE --partition-requested true --brainstorm-requested false --manual-gate-b false --output "$OUT3" >/dev/null
merge_run_params "$OUT3" false true false
jq -e '.partition_requested == true and .brainstorm_requested == true and .manual_gate_b == false' "$OUT3" >/dev/null \
  || fail "case3: partition OR-merge regressed; got $(cat "$OUT3")"

# Case 4: stored brainstorm=true; argv brainstorm=false => brainstorm=true (OR-merge preserves).
OUT4="$TMPROOT/case4.json"
"$WRITER" --classification SIMPLE --partition-requested false --brainstorm-requested true --manual-gate-b false --output "$OUT4" >/dev/null
merge_run_params "$OUT4" false false false
jq -e '.brainstorm_requested == true and .partition_requested == false and .manual_gate_b == false' "$OUT4" >/dev/null \
  || fail "case4: brainstorm OR-merge regressed; got $(cat "$OUT4")"

echo "PASS: test-step0b-router-flag-recovery.sh"
```

Cases cover: (1) FINDING_9 manual-only argv scenario, (2) manual overwrite-clears-stale,
(3) partition true-only OR-merge, (4) brainstorm true-only OR-merge. Four cases total —
minimum needed to lock the asymmetric merge semantic FINDING_8/9 flagged as untested.

## Approach

- Three concrete add-ons. No new helpers, no abstraction, no shared library.
- Stale-prose lint reuses the existing `absent` / `contains` helpers in
  `test-design-structure.sh` (fixed-string matchers per `.claude/rules/` regex-injection
  guidance).
- Recovery harness uses the same `mktemp -d` + `trap` cleanup pattern as
  `test-write-run-params.sh` and a verbatim copy of the SKILL.md jq expression so the
  CI-pinned substring keeps both sides in sync.
- Failure-path tests reuse `assert_rejected_with` (already present in
  `test-write-run-params.sh`).

## Edge cases

- **Stale-prose false positive**: phrases like "no auto-apply" are unambiguous about
  Gate B contradiction. If a future legitimate use needs the phrase, it can carry an
  inline waiver comment or the lint can be narrowed. The chosen set deliberately leaves
  "always prompts" alone in non-Gate-B contexts (Gate A always prompts on re-entry, so
  the lint targets the specific "Gate B always prompts" composite phrase).
- **Bash 3.2 portability**: the new harness uses only POSIX-safe constructs
  (`mktemp`, `trap`, plain `local`, `[[ ... ]]`); no `declare -A`, no `mapfile`. Per
  `BASH_AUTHORING.md` §3.
- **jq availability**: existing harnesses already require jq; the new harness inherits
  the same assumption (CI runs install jq).
- **Drift between SKILL.md and harness**: the new `contains` check in
  `test-design-structure.sh` pins the canonical jq substring; any SKILL.md edit that
  removes or rewords the merge expression breaks CI immediately.
- **Empty-value vs missing-value**: `${2:?...}` in write-run-params.sh fires on both
  unset and null. The two new `assert_rejected_with` cases cover both shapes
  (empty string + missing token at end of argv).

## Failure modes

- **Stale-prose lint over-matches in unrelated docs**: if `docs/workflow-lifecycle.md`
  or `docs/configuration-and-permissions.md` later legitimately quote the stale phrase
  in a historical-context section, the lint fails. Mitigation: the lint targets only
  `$APPROVAL_MD` and `$SKILL_MD` (Gate B's authoritative surfaces); other docs are
  intentionally not in the lint scope, so historical mentions elsewhere stay free.
  Warning signal: a CI failure on a PR that did not touch Gate B prose.
- **Recovery harness silently drifts from SKILL.md**: the harness embeds the merge
  expression as a local shell function. If SKILL.md edits the jq expression without
  updating the harness, the harness still passes against its own copy. Mitigation:
  the positive `contains` pin in `test-design-structure.sh` locks the SKILL.md
  substring; any rewording invalidates the pin and CI fails before the harness can
  go stale. Warning signal: `test-design-structure.sh` failing on a SKILL.md edit.
- **Makefile shard imbalance after add**: adding the new harness to `test-harnesses-6`
  marginally lengthens that shard. Mitigation: pick a shorter shard if review reveals
  imbalance — this is a cosmetic CI scheduling concern, not a correctness one.
