## Plan

## Goal

Stop the `/design` plan-review loop from ratcheting an over-scoped plan upward. Feed the originating issue into the scout, reviewers, voters, and MainAgent fallback as the scope anchor; give reviewers the pre-review plan as a drift baseline; preserve scope-cut markers through dedup/aggregation; and let a legitimate scope-reduction finding win in the tally even when additive findings would normally outvote it. Both tiers, uniform. No Gate B / convergence / assessor-on-SIMPLE changes.

## Key design decisions

- **Scope anchor means the originating issue, not brainstorm-merged context.** Capture the original feature/issue file before any brainstorm merge and pass that path to the new scout/reviewer/voter/MainAgent scope-anchor paths. Existing merged context may remain available as optional context, but it must not become the binding scope anchor.
- **Scope-cut marker = leading in-band literal tag, not a new enum.** Reviewers prefix a scope-reduction finding’s `what`/Concern text with `[SCOPE-REDUCTION]`. The TSV `scope` field stays `in_scope`.
- **Detector is narrow.** `is_scope_reduction_block` matches only a leading `[SCOPE-REDUCTION]` marker in the normalized finding problem field, e.g. `- **Concern**: [SCOPE-REDUCTION] ...`, `what: [SCOPE-REDUCTION] ...`, or an aggregated finding heading that begins with the marker. Strip fenced and inline code before matching. Non-leading prose mentions do not count.
- **Protected tally rule is design-only.** Shared edits stay additive/backward-compatible. The threshold override lives in `tally-plan-review.sh`.
- **Acceptance rule for scope-reduction blocks:** promote only normal `rejected` or `neutral` results to `accepted` when `YES >= 1` and `YES >= NO`. Never promote an already `exonerated` result.
- **MainAgent fallback is covered.** The 0-judge path receives the same issue-anchor and problem-first scope-cut rubric. If a MainAgent YES accepts a tagged scope cut, `findings-classification.tsv` records that accepted result instead of forcing it back to rejected.
- **Marker preservation is enforced before tally.** Plan-review dedup must not drop a leading scope-reduction marker. Plan-mode aggregation must preserve at least one leading marker when tagged inputs are merged, or fail/fallback to the unmerged tagged findings.
- **Baseline plan captured per-run by the loop.** `plan-review-loop.sh` snapshots its own round-1 entry plan to `plan-review-baseline.txt` for both tiers and passes it to reviewers. The reviewer baseline block is skipped when `cmp -s baseline current` reports identical content.

## Approach

1. **Scope anchor source:** capture the original issue before brainstorm merge and pass that as the binding scope file everywhere new scope logic is added.
2. **Scout:** derive archetypes from issue scope first, not plan bloat.
3. **Reviewers:** receive issue + baseline and tag scope-reduction concerns with a leading `[SCOPE-REDUCTION]`.
4. **Dedup:** preserve tagged scope-cut blocks before aggregation.
5. **Aggregator:** preserve leading markers in plan mode and fallback if a tagged input would lose all tags.
6. **Voters/MainAgent:** read the issue anchor and judge scope cuts problem-first.
7. **Tally:** narrowly detect leading markers and apply the protected design-only acceptance threshold.

## Edge cases

- **Round 1, no drift:** baseline file is a copy of current plan, but `cmp -s` suppresses the baseline drift block.
- **SIMPLE tier:** loop-written baseline exists even without `plan.txt-original`.
- **Brainstorm additions:** remain optional context only; they do not redefine issue scope.
- **Aggregator or dedup marker loss:** validation/fallback keeps tagged findings available to tally.
- **Non-leading tag mentions:** do not trigger protected acceptance.
- **EXONERATE majority:** not promoted to accepted.
- **0-judge MainAgent path:** gets the same scope-anchor rubric; accepted tagged scope cuts are consistently reflected in accepted artifacts and classification TSV.
- **Other consumers:** no new flags passed, so `/research`, `/review`, and `/implement` voter/tally behavior remains unchanged.

## Failure modes

- **Shared-script regression:** guarded by byte-equality default-path tests.
- **Marker false positive:** guarded by leading-only detector and non-leading/fenced tests.
- **Marker loss before tally:** guarded by dedup preservation and aggregation fallback tests.
- **Scope anchor drift via brainstorm:** guarded by original-vs-merged context tests.
- **MainAgent artifact mismatch:** guarded by classification TSV tests.
- **Over-protection:** mitigated by `YES>=NO`, no exonerated promotion, and problem-first voter instructions.

## Testing strategy

- New `test-plan-review-scope-anchor.sh` for end-to-end marker preservation, prompt anchoring, and protected acceptance.
- Extend existing prompt, dispatch, tally, and lib tests listed above.
- Run `make lint` / relevant harness shard after implementation.

## Acceptance

- Scout, reviewers, voters, and MainAgent fallback receive the originating issue as scope anchor.
- Reviewers receive the pre-review baseline and suppress identical-baseline noise.
- Scope-reduction findings use a narrow leading marker and survive dedup/aggregation.
- A legitimate tagged scope cut can win on `YES=1, NO=1`; untagged or exonerated findings cannot.
- MainAgent accepted scope cuts are consistent across accepted artifacts and classification TSV.
- Shared voter/tally consumers remain backward-compatible.
- Harnesses updated and `make lint` green.
