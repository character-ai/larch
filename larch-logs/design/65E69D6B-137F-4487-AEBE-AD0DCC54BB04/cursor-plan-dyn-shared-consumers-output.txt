### 1. [correctness] `skills/design/SKILL.md:1094` — MainAgent path missing scope-cut voter contract

The plan correctly keeps shared-script changes additive: `render-voter-prompt.sh` gates `--scope-anchor-file`, `lib-vote-tally.sh` only adds `is_scope_reduction_block`, `aggregate-findings.sh` gates on `--input-mode plan`, and `/review` stays on `dispatch-code-voters.sh` + default `code` aggregation (`review-core.sh` never passes `--input-mode plan`).

The protected tally override in `tally-plan-review.sh` is also correctly design-only; `tally-code-votes.sh` will keep using unmodified `classify_result`.

The gap is the **0-judge MainAgent path**. When all external voters fail, `tally-plan-review.sh:452-459` emits `main-agent-vote-required` before any scope-reduction override can run with external YES votes. The orchestrator then votes per `skills/design/SKILL.md:1094` using the generic proportionality rubric — without reading the issue scope file or applying the `[SCOPE-REDUCTION]` problem-first rule that `--scope-anchor-file` adds to `render-voter-prompt.sh:51-61`.

Because the override requires `TALLY_YES >= 1`, a sole MainAgent **EXONERATE** on a scope-cut finding (`YES=0`) leaves the finding exonerated/rejected even though the plan documents that a single advocate should win. External-voter panels are covered; degraded 0-judge panels are not.

### 2. [architecture] `skills/design/scripts/plan-review-loop.sh:119-134` — Scope anchor may include brainstorm, not issue-only

The plan states voters receive the "originating issue" as scope anchor, but the proposed wiring passes `$FEATURE_FILE`, which the loop already rewrites to `plan-review-feature-context.txt` when `brainstorm.md` is present. That is consistent with scout/panel `--description-file` / `--feature-file` usage today, but it widens the anchor beyond the bare issue and can dilute scope-reduction findings when brainstorm content expanded scope.

[OUT_OF_SCOPE] `skills/design/references/plan-review.md` — Plan does not list this doc in **Files to modify/create**, yet it is the normative Step 3 voter contract (`test-design-structure.sh:1292-1309` pins phrases there). After `render-voter-prompt.sh` gains `--scope-anchor-file` and `tally-plan-review.sh` gains protected acceptance, plan-review.md and the MainAgent SKILL prose should document the exception to the "2+ YES" tier or drift guards will not catch behavioral regressions for operators.
