**1. `larch:plan` strip needs a named canonical contract**

The plan correctly requires stripping prior `larch:plan` content before writing `plan-review-scope-anchor.txt`. The repo already centralizes marker regexes in `scripts/plan-block-read.sh` and `skills/design/scripts/design-route.sh`, but the plan does not require reusing them or handling malformed marker pairs. For a SIMPLE fix, a small shared strip helper (or explicit “call the same awk as plan-block-read inverse”) is lower risk than inline logic in `plan-review-loop.sh`.

**2. Anchor source must be captured before brainstorm merge**

Today `plan-review-loop.sh` overwrites `FEATURE_FILE` with the brainstorm merge at lines 124–133. The plan’s intent is clear (“pre-brainstorm issue/feature text”), but the implementation step should name a concrete variable/path captured before that block. Otherwise the primary regression this issue targets can slip back in.

**3. Post-dedup parity fallback needs a concrete artifact**

The parity gate is sound, but “fall back to the pre-dedup in-scope stream” is ambiguous because `findings-in-scope.md` is produced only after dedup. Without naming the fallback file and whether dedup is skipped or tagged blocks are re-injected, aggregation may still run on marker-stripped input.

**4. [OUT_OF_SCOPE] HARD assessors**

Step 3.6 (`assess-plan-round.sh` / `dispatch-plan-assessors.sh`) still use `--feature-file` from the design tmpdir and are outside this plan’s file list. That is acceptable for a SIMPLE plan-review fix, but HARD redesigns could still see merged brainstorm context at assessor time.
