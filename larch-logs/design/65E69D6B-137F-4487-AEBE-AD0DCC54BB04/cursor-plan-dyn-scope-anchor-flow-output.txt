### 1. [correctness] Round-1 baseline degrade will not behave as documented

The plan’s edge case says round 1 degrades when baseline equals the current plan via **path equality** (`plan.txt:115-116`). The proposed loop wiring always snapshots to `$DESIGN_TMPDIR/plan-review-baseline.txt` and passes that as `--baseline-plan-file` while `--plan-file` stays `plan.txt`, so paths are never equal and the drift-compare prompt block fires on every first review even when contents match. Add a **content** short-circuit in the proposed `render-plan-review-prompt.sh` (e.g. `cmp -s`) and fix the edge-case wording.

### 2. [correctness] Dedup can eliminate scope-cut findings before protected tally

`plan-review-loop.sh` runs Jaccard dedup on Concern/Description text before aggregation (`plan-review-loop.sh:1110-1185`). Opposing scope-cut and scope-addition findings about the same area can collapse to one block; the dropped finding never reaches voters/tally, undermining the protected `[SCOPE-REDUCTION]` acceptance path. Exempt tagged blocks from cross-merge or skip dedup between tagged and untagged pairs.

### 3. [risk-integration] Missing panel-dispatch regression coverage

`test-dispatch-plan-review-panel.sh` already guards `--feature-file` waterfall forwarding but is absent from the plan’s test surface list. New `--baseline-plan-file` threading into static, dynamic, generic-fallback, and `append_shared_prompt_tail` renders needs similar assertions to avoid silent prompt wiring regressions.
