## Architectural Concern Both Sketches Missed

The Round 1 Decision 4 mandates adding new `coder-codex.events.jsonl`-named files to `round_artifact_included`. **However**, the existing `case` statement at `scripts/larch-log.sh:70` ALREADY has a blanket exclusion `*.events.jsonl` that returns 1 (excludes). This is checked **before** the include alternation at line 89, so Bash case ordering means the include line won't override the exclusion match.

Two resolution paths:

**Path 1 — rename the new artifacts to bypass the wildcard**: use a name that does NOT end in `.events.jsonl`, e.g., `coder-codex-events.jsonl` (hyphen, not dot, before `events`). The existing `*.events.jsonl` glob requires a literal `.` before `events`, so `coder-codex-events.jsonl` would not match. Minimal-touch — no edit to existing exclusion patterns.

**Path 2 — add specific includes before the exclusion**: move the new events.jsonl include lines ABOVE the `*.events.jsonl` exclusion line so Bash case order grants them. Requires restructuring the case statement (the current exclusion-then-include layout is a readable convention).

**Recommended**: **Path 1** (rename) — minimal disruption to the existing case-statement convention; preserves the original intent that launcher-generated events.jsonl files remain excluded.

## Pragmatism / Safety Warnings

- Item B's primary regression risk is **wrapper.log shape changes**: today `2>&1` consolidates stdout+stderr into wrapper.log. After Item B, stdout goes to `events.jsonl`, so wrapper.log will only contain stderr (and any messages emitted by the `run-external-agent.sh` wrapper itself). Downstream forensic-analysis consumers reading wrapper.log may have to adapt. Mitigation: per-site regression assertions on wrapper.log content shape.
- Item C carries effectively zero regression risk (additive allowlist entry).
- Item A carries zero regression risk for callers (envelope contract preserved per Round 1 Decision 6).
