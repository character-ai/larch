## Approach

Extend the existing codec instead of adding another parser. Preserve each caller’s current first-wins, last-wins, trimming, CR, empty-value, and error behavior through explicit policy arguments.

Use the existing `kv get` command for Bash. Keep `env_file.py`, `parse_allowlisted_env_line`, and `design read-result-env` unchanged.

Delete redundant emit wrappers in the approved surfaces. Route output through `logging_util.emit_kv`, with conversion or sanitization kept at each call site where required.

Add a reason-bearing lint baseline. The baseline may only shrink and must not hide new parser sites.

## Edge cases

- Preserve values containing additional `=` characters.
- Preserve each caller’s duplicate ordering and empty-value fallback.
- Do not treat `export KEY='v'` as the raw codec grammar.
- Do not weaken allowlist, shell-token, symlink, CR, or newline checks.
- Keep bootstrap readers that cannot locate `cli.py` grandfathered with reasons.
- Do not convert unrelated command-line option or tab-field splitting.

## Failure modes

- A wrong duplicate policy can silently change routing state. Pin each migrated caller with duplicate fixtures.
- Broad lint matching can flag ordinary string parsing. Require loop and env-pattern evidence.
- Emitter conversion can change boolean case or permit forged rows. Normalize before the newline check and test exact stdout.
- Hook migration can fail before plugin-root discovery. Keep unavoidable bootstrap reads outside the funnel and baseline them.

## Testing strategy

- Run focused codec, CLI, logging, session-env, agents, design, git, CI, preflight, and lint pytest modules.
- Run the affected hook and skill harnesses for SessionStart, background denial, design Step 3, bootstrap, tracking comments, execution-issue refresh, and Step 18.
- Run `python3 python/cli.py lint kv-codec`.
- Run `make py-lint-checks-fast` and relevant changed-file checks.
- Confirm the baseline shrinks for every migrated parser and fails when a new fixture adds an unbaselined parser.
