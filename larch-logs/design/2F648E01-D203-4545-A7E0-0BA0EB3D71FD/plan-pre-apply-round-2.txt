## Edge cases

- Both external voter tools down must still avoid launching voters 2 and 3; only voter-1 runs via the dedicated Claude floor path.
- Codex down with Cursor up should still run all three design voter slots through Cursor fallback in one waterfall manifest.
- HARD row overrides must not create duplicate Codex rows for the same archetype.
- Row-level `model_role` must override the waterfall fallback role; `resolved_model` must follow the resolved role.
- TRIVIAL code review with both externals present and a non-empty scout manifest must still emit `dyn-cursor` and must not emit `dyn-codex`.
- Existing committed design classification TSVs with old labels must remain parseable.

## Failure modes

- Leaving the Claude-first `dispatch_voters` happy path in place would negate config changes and break semantic `VOTER_N_TOOL` / tally attribution.
- A tier-wide `--model-role default` could accidentally upshift all HARD Codex rows if row-level overrides are missing.
- Renaming plan voter output files can break status parsing if every `VOTER_N_PATH` emitter is not updated.
- Calibration may split old and new labels unless fallback and parser tests cover both shapes.
- TRIVIAL `dyn-cursor` suppression when Codex is up would leave TRIVIAL review without dynamic rows.
- Docs can drift from manifests unless tests assert row-level `model_role` and `resolved_model`.
