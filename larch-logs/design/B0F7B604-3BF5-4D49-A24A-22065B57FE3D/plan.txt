## Approach

Fix the command that the hook captures.

The hook is already correct:

- it matches only exact `p` or `progress`
- it runs `python/cli.py progress report --cwd ...`
- it blocks only when captured stdout is non-empty
- it fails open on empty output or errors

The bug is that `report_main` initializes lib-quiet before printing the report. That redirects FD 1 to the quiet log. The shell capture receives empty stdout and lets the prompt fall through.

Use the minimum change:

- remove quiet routing from `report_main`
- leave plain `print(report)` as the command deliverable
- keep the command quiet by design through fail-open behavior, not FD redirection

Perform the sibling audit before implementation or during it:

- Search `cli.py`-registered `*_main` functions that call `quiet_init` and emit via plain `print` or `sys.stdout.write`.
- Fix inline only if another command has the same unambiguous captured-stdout deliverable bug.
- Otherwise do not expand scope. Record ambiguous cases as out of scope if needed.

Expected result: only `python/progress_report.py` changes inline.

## Edge cases

- No live run: still exits `0` with empty stdout.
- Internal render exception: still exits `0` with empty stdout.
- Parser error: argparse may write to stderr. The hook redirects stderr to `/dev/null`.
- Existing quiet env from a parent process: `progress report` still writes the report to real stdout.
- `LARCH_QUIET_DISABLE=1`: behavior remains stdout as before.
- `/implement` and `/design` both recover because both use the same hook and CLI command.

## Failure modes

- If a future edit re-adds `quiet_init` to `report_main`, the new subprocess test fails because stdout is empty and the quiet log contains the report.
- If the test calls `report_main` directly instead of a subprocess, FD redirection can pollute the pytest process. Use subprocess coverage.
- If the test omits quiet env vars, it will not cover the regression.

- `make py-test`

Targeted checks:

- Existing progress-report tests continue to cover live-run discovery and dynamic render output.
- Existing `scripts/test-hook-progress-report.sh` should still pass because the hook contract is unchanged.
