1. [correctness] `scripts/create-pr.sh:27,201-203`

The plan’s canonical call shape is unsafe for the many target scripts that use `set -euo pipefail`. A non-zero `with_transient_retry` return will abort the script before the existing branch reads `_WTR_RC` and emits its current diagnostics or fallback behavior.

Suggested revision: make the plan require a guarded call shape for `set -e` scripts, such as an `if with_transient_retry ...; then :; else :; fi` block followed by `rc=$_WTR_RC`, or define the shared helper to always return 0 and use `_WTR_RC` as the sole status channel.

2. [risk-integration] `scripts/ship-pr.sh:2385-2391,3067-3088`

The proposed `ship_pr_with_transient_retry` wrapper preserves non-zero transient exhaustion, but not rc=0 envelope exhaustion. `ci-wait.sh` and `merge-pr.sh` intentionally return 0 while reporting transient failures in stdout keys. With the proposed wrapper, the third transient envelope attempt leaves `_WTR_RC=0`, hits `[ "$rc" -eq 0 ] && return 0`, and ship-pr continues on a failed envelope.

Suggested revision: have `ship_pr_with_transient_retry` inspect the final envelope with the predicate before returning success, then call `exit_transient_net` when that predicate still matches.
