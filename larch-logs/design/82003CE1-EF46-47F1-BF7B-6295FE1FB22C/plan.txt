## Approach

The smallest change that achieves the goal is to move the existing helper one file over, add 2-second / 4-second sleeps, and re-run the predicate at exhaustion in the ship-pr wrapper so envelope-error responses still terminal-exit. The lifted helper is byte-equivalent to the current helper for ship-pr's existing 7 callsites because the thin `ship_pr_with_transient_retry` wrapper preserves `exit_transient_net` terminal semantics for both rc != 0 + transient-signature and rc == 0 + predicate-transient exhaustion. Every new gap callsite uses the canonical pattern: `mktemp` a per-call `fail_file`, call `with_transient_retry transient_envelope_predicate_none "$fail_file" <verb> <args>`, and immediately copy `_WTR_OUT` and `_WTR_RC` into named locals before the next wrapper runs.

**Wrapper-call shape (set -e safety).** Every gap callsite in this plan runs in a script that uses `set -e` somewhere in its environment. To prevent the helper's non-zero return from tripping errexit before the caller can read `_WTR_RC` and `_WTR_OUT`, every callsite uses one of two shapes:

```bash
# Shape A — conditional
if with_transient_retry transient_envelope_predicate_none "$fail_file" "$@"; then
    : # success path uses _WTR_OUT
else
    rc=$_WTR_RC
    # failure path uses _WTR_OUT / _WTR_RC / "$fail_file"
fi

# Shape B — set +e capture
set +e
with_transient_retry transient_envelope_predicate_none "$fail_file" "$@"
rc=$_WTR_RC
out=$_WTR_OUT
set -e
```

Both shapes read the globals immediately, before any other command runs, so a later `: ; ` or unrelated invocation cannot overwrite `$?`.

For `design-log-publish.sh`, the cleanup-on-PR-create-fail branch is the load-bearing fix from today's incident: when retries are exhausted AND the recovery `gh pr list` confirms no PR exists, the script cleans up the pushed remote branch so a caller-driven retry can re-push cleanly. The cleanup is guarded by `create_rc != 0` plus a recovery-empty probe so a successful server-side create whose response was lost does NOT lose its PR's remote branch. `git push origin --delete` is best-effort; failures are silenced because the operator already has a recovery branch ref.

For `gh issue create` and `git clone`, retry is unsafe because the operations are not idempotent (Finding 4 / Finding 6): a server-side create + lost response would re-create on retry, and a partial clone directory would block the next attempt. Those callsites stay bare; the surrounding scripts continue to run them as single-shot.

## Edge cases

- `lib-net.sh` is sourced into many call chains. The `LARCH_LIB_NET_LOADED` sentinel already prevents duplicate sourcing; the new exports inherit this guard at no extra cost.
- `with_transient_retry` is invoked from scripts that may run under `set -e`. The helper itself does not use `set -e`; every gap callsite uses the conditional (Shape A) or `set +e` capture (Shape B) pattern above so `_WTR_RC` / `_WTR_OUT` are read before any other command overwrites `$?`.
- A `fail_file` is truncated at the start of every attempt (`: > "$ff"`) — every callsite uses its own `mktemp`-allocated `fail_file` per wrapped call so successive wrappers within the same script do not stomp each other's capture.
- For `gh issue close` rollback callsites (`create-one.sh:335`, `apply-combination.sh:100`, `decompose-file-issues.sh:355`, `audit-close-priors.sh:100`), the retry must not block the rollback path forever; the 3-attempt cap with 6 seconds of total backoff keeps the worst-case rollback wall-time bounded.
- `local-cleanup.sh:74` is a soft-fail callsite that prints `(continuing)`; the wrap preserves that behavior on exhaustion because the caller still ignores `_WTR_RC`.
- `gh issue create` and `git clone` callsites are intentionally left bare per Findings 4 and 6; both operations are non-idempotent under the retry semantics defined here. Operators retry them at a higher level when failures occur.
- `git push origin --delete` in `design-log-publish.sh`'s cleanup branch may itself hit a transient. Leave it bare with `|| true`; wrapping it would deepen the cleanup latency without buying recovery, and the script already preserves a local recovery branch.

## Failure modes

1. **Nested-retry latency blowup on `rebase-push.sh:274`.** The inner push wrap pairs with the existing 3-attempt lease-race outer loop, so a sustained transient outage could cost up to 9 push attempts plus jittered + 2s/4s backoff (~30 seconds wall-time). Earliest signal: rebase-push timing breadcrumbs grow. Mitigation: documented in the plan and accepted per Round 1; rebase-push callers (Step 12c, postbump) already have their own timeout envelopes.
2. **`exit_transient_net` semantics regression in ship-pr.** If the thin wrapper drops the predicate-on-rc=0 path used by `transient_envelope_predicate_merge_pr` / `_ci_wait`, ship-pr would silently accept envelope-failure responses. Earliest signal: ship-pr merges that should have retried on `MERGE_RESULT=error` succeed without retrying. Mitigation: `ship_pr_with_transient_retry` re-runs the supplied predicate against the final `fail_file` content after the lifted helper returns and calls `exit_transient_net` whenever the predicate still flags transient — regardless of rc — and the new `scripts/test-lib-net.sh` exercises the envelope-error exhaustion path explicitly.
3. **`design-log-publish.sh` cleanup races with successful-create-but-lost-response.** If `gh pr create` succeeds server-side but the response is lost, the script's recovery probe (`gh pr list --head $WT_BRANCH`) may return the PR. The cleanup branch is now gated on `create_rc != 0` AND a recovery-empty probe so the delete fires only when no PR exists; a successful create with lost response preserves the remote branch under `RECOVERY_BRANCH` for the operator. Earliest signal: a follow-up `gh pr list` returns the open PR.
