## Findings

### 1. **correctness** — Stub PLUGIN_ROOT cases still shell the retired script (`scripts/test-dispatch-code-voters.sh:144-148`, `606-633`)

The bash harness builds fake plugin roots that symlink `scripts/dispatch-code-voters.sh`, then calls that path directly for voter-1 delayed `.done`, missing `.done`, and wait-timeout scenarios. The plan ports happy-path coverage and lists those branches, but it never states that pytest must drop the script symlink and enter through `python/cli.py agent dispatch-voters`.

After deletion, those cases cannot run as written. Voter-1 sentinel arbitration is the highest-risk slice; it can regress while simpler CLI smoke tests stay green.

**Suggested revision:** In `### NEW: python/test_agent_voters.py`, require fake `CLAUDE_PLUGIN_ROOT` trees to invoke `agent dispatch-voters` via repo `python/cli.py` (or a delegating stub), not `scripts/dispatch-code-voters.sh`.

### 2. **risk-integration** — Eight-way Makefile shard mapping is unspecified (`Makefile:849-871`)

The plan retargets eight `test-dispatch-code-voters-*` targets to pytest with “matching `-k` filters” but does not pin the section names from `scripts/test-dispatch-code-voters.sh:12-21` (`happy`, `edge-and-r3-claude`, `retry-claude`, etc.) to concrete `-k` expressions.

Without a fixed table, CI shards can drift: run zero tests, the wrong slice, or the whole module. That breaks the timing contract that motivated the eight-way split.

**Suggested revision:** In `### UPDATED: Makefile`, document the exact `pytest -k` selector per target and use the same `timing harness-mark` + `python3 -m pytest -q python/test_agent_voters.py -k '...'` shape as `test-dispatch-with-waterfall`.
