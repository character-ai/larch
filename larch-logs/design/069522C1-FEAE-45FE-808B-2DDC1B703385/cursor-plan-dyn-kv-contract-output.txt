**1. Bounded context not forwarded to Claude launch or waterfall**

The plan copies diff/plan into the review tmpdir but the `agent launch-claude-review` and `agent dispatch-waterfall` bullets do not say to pass those paths. The bash script forwards `ctx_args` to both:

```115:149:scripts/dispatch-code-voters.sh
python3 "$CLI" agent launch-claude-review \
    --output "$VOTER_1_PATH" \
    ...
    "${ctx_args[@]+"${ctx_args[@]}"}" >/dev/null 2> "${VOTER_1_PATH}.launcher-stderr" &
...
waterfall_output=$(python3 "$CLI" agent dispatch-waterfall \
    ...
    "${ctx_args[@]+"${ctx_args[@]}"}")
```

Without that, symlink-diff and 2MB-diff parity cases in the harness can fail or silently change behavior.

**2. Code-review KV order is underspecified**

`review-core.sh` uses `kv_get`, so key order is not parsed today. The plan still claims byte-compatible `VOTER_*` output. The plan-review helper `voter_status_block_main` uses a different order (`VOTER_PATHS_FILE` before `VOTER_2_TOOL`):

```867:886:python/voting.py
    rows = [
        ("VOTER_1_PATH", voter_1_path),
        ...
        ("VOTER_2_PATH", voter_2_path),
        ("VOTER_3_PATH", voter_3_path),
    ]
    if Path(plan_voter_paths_file).is_file() ...
        rows.append(("VOTER_PATHS_FILE", plan_voter_paths_file))
    rows.extend([("VOTER_2_TOOL", ...), ...])
```

The retired bash order is sequential per slot, then `VOTER_PATHS_FILE`, then `DISPATCH_OK` (`scripts/dispatch-code-voters.sh:354-382`). The plan should pin that sequence and add an order test like `python/test_plan_review_panel.py:264-304`, but with the code-review key list.

**3. Harness suppression path token**

`is_harness_review_path` only matches `test-dispatch-code-voters.` among voter harness names (`python/voting.py:466-476`). The bash harness relies on tmpdirs like `test-dispatch-code-voters.XXXXXX` for env-isolation (`scripts/test-dispatch-code-voters.sh:1008-1049`). Moving tests to `python/test_agent_voters.py` without that path shape or a pattern update can leak parse-rate warnings into a parent `execution-issues.md`.

**4. DEGRADED_PANEL_WARNING must use code-review wording**

Bash emits:

```348:351:scripts/dispatch-code-voters.sh
    _warn_msg="**⚠ Degraded code-review panel: ${effective_judges}/${expected_judges} effective judges produced output.**"
    larch_err "$_warn_msg"
    emit_kv DEGRADED_PANEL_WARNING "$_warn_msg"
```

`degraded_warning_main` uses plan-review text ("substantive vote output"). The harness asserts exact code-review strings. Reusing the plan helper would break parity.

**5. Diagnostic site strings after label cutover**

Parse-rate failures log `--site "{dispatch_label} {voter_tool}"` (`python/voting.py:558-559`). The default label changes to `agent dispatch-voters`. The harness still greps `dispatch-code-voters.sh claude/codex/voter1` in execution-issues. The plan does not say whether ported tests should expect the new site strings or preserve legacy ones for audit continuity.
