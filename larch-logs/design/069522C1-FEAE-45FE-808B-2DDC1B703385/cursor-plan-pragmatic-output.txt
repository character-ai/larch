## Findings

### 1. Prelaunch prompt gate must cover all three voters before any launch

**Focus:** correctness

Retired bash always finishes `make_voter_prompt_file` for claude, codex, and cursor before it backgrounds Claude:

```107:123:scripts/dispatch-code-voters.sh
claude_prompt=$(make_voter_prompt_file claude)
codex_prompt=$(make_voter_prompt_file codex)
cursor_prompt=$(make_voter_prompt_file cursor)
...
python3 "$CLI" agent launch-claude-review \
    ...
    "${ctx_args[@]+"${ctx_args[@]}"}" >/dev/null 2> "${VOTER_1_PATH}.launcher-stderr" &
```

The plan’s fail-closed `render voter` rule is right, but it does not state that **all three** prompts must succeed before **any** voter starts. A sequential port can orphan a Claude child and still corrupt the panel.

**Suggested revision:** Add one explicit prelaunch block in `python/agent_voters.py`: render and validate claude, codex, and cursor prompts; exit `2` on any failure; only then launch voters.

### 2. Pin `{label}-vote-prompt.txt` artifact names

**Focus:** correctness

The plan names `claude-vote-output.txt` and `code-voter-slots.ndjson`, but not prompt paths. The harness checks prompt files by fixed basename under the review tmpdir (`scripts/test-dispatch-code-voters.sh:383-397`). `voting.parse_rate_retry` also keys retry prompt naming off the prompt basename.

**Suggested revision:** Document and implement `$REVIEW_TMPDIR/{claude,codex,cursor}-vote-prompt.txt` explicitly in `agent_voters.py` and the pytest port checklist.

### 3. [OUT_OF_SCOPE] Drop unnecessary `docs/review-agents.md` edit

**Focus:** architecture

The plan lists `docs/review-agents.md` as UPDATED, but that file has no `dispatch-code-voters` references today. Its shrink-not-backfill wording already matches live behavior. Editing it adds diff without helping cutover or `lint retired-scripts`.

**Suggested revision:** Remove that file from scope unless the stale-reference sweep finds a literal to fix.
