### Divergence + reasoned synthesis call

1. **Implicit waterfall order — Cursor→Codex→Claude (issue) vs Codex→Cursor→Claude (current repo).** All four sketches independently surfaced this contradiction. The issue body text and the issue's example warning `**⚠ Cursor unavailable — falling back to Codex implementer.**` are internally consistent ONLY with Cursor-first; that text would be incoherent under Codex-first. Synthesis call: **adopt the issue body's Cursor → Codex → Claude order**; bundle the cross-file updates required for repo consistency (SECURITY.md L104, `scripts/test-implement-step2-routing.sh` L31-32). Listed as DECISION_1 for dialectic because the Cursor-Arch sketch explicitly argued for verbatim preservation of existing repo order (treating the change as a separate product decision).
2. **DEFERRED phase guard.** Cursor-Edge: today `should_run_post_tracking_phase` skips when `DEFERRED=true`; after Phase 4 deletes the prompt-side waterfall, deferred-but-implementing paths (`POSTED=false` metadata defer; fork mode with plan materialized) emit empty `coder=` which silently breaks Step 2 dispatch. Cursor-Arch implicitly accepted current behavior (DEFERRED skips coder). Synthesis call: **widen `should_run_post_tracking_phase` to be permissive (like `should_run_phase_plan_materialize`: no bail / no stall / no `REPO_UNAVAILABLE`)** — DEFERRED is no longer a coder-skip trigger. Listed as DECISION_2 for dialectic.
3. **Dirty-tree resume invocation.** Cursor-Arch and Cursor-Edge both note SKILL.md L478 recovery still re-enters at `--up-to-phase plan --resume-plan-tail`. Synthesis call: bump to `--up-to-phase coder --resume-plan-tail` so the recovery path also runs `phase_coder_select` and the final KV tail contains `coder=`. Unanimous — not contested; folded into plan deliverable.
4. **`test-implement-step2-routing.sh` migration.** Cursor-Arch and Cursor-Edge flagged that this harness pins `### Implementer waterfall` heading and `Codex → Cursor → Claude` — both deleted/changed by Phase 4. Synthesis call: update pins in same PR (retarget heading anchors to the equivalent `implement-bootstrap.md` sections; update order to Cursor-first). Unanimous — not contested.
5. **Warning helper extraction.** Cursor-Arch: small local helper; Codex-Pragmatic: tiny local helper or `case`. Synthesis call: small in-file helpers (one `case` block per fallback transition; no separate file). Unanimous-leaning — not contested.

### Architecture/Standards highlights (from Cursor-Arch)

- Clean separation across three surfaces: `scripts/implement-bootstrap.sh` (mechanical), `scripts/implement-bootstrap.md` (contract), `skills/implement/SKILL.md` (orchestration).
- Bail/stall guards (`should_run_post_tracking_phase`, `IMPLEMENT_BAIL_REASON` short-circuit) keep DEFERRED → still-skipped, REPO_UNAVAILABLE → still-skipped after the widening above (only DEFERRED gets reclassified).
- Bootstrap stdout discipline preserved; documenting the bail-table row + breadcrumb #5 in `implement-bootstrap.md` keeps a single canonical contract per `AGENTS.md` `script-md-siblings` convention.

### Pragmatism/Safety warnings (from Codex-Pragmatic, Cursor-Edge)

- Behavioral regression risk: changing waterfall order from Codex-first to Cursor-first changes the operator-visible default implementer when `--coder` is omitted. Mitigation: keep the change paired with SECURITY.md / step2-routing pin updates; do not split across PRs.
- Stub-overwrite class regression (the F7 class from #2732 prior phases): keep `should_run_*` guards; never set `IMPLEMENT_BAIL_REASON` inside a phase that was skipped by guard.
- Plan-only resume path still skips coder; the bump to `--up-to-phase coder --resume-plan-tail` is required to maintain "no regression in existing harnesses" acceptance.

### Edge-case / failure modes (from Cursor-Edge)

- **Tri-state explicit-coder failure** — `CODEX_BINARY_FOUND` or `CURSOR_BINARY_FOUND` absent from `session-env.sh` means "Step 0 may have failed" and produces the undeterminable warning + STALL — never silently fall through to implicit waterfall.
- **Breadcrumb-count regression** — `→ step0: branch ` (with trailing space) and `→ step0: larch:plan posted` are emitted conditionally on success. The deterministic happy-path scenario for the "exactly 5 lines" assertion must guarantee all four prior breadcrumbs fire, plus the new coder breadcrumb.
- **`coder_fallback=true` scope creep** — set only on implicit → claude (both externals down). Cursor-fallback path under Codex-first (the OLD order) explicitly does NOT set `coder_fallback`. Under Cursor-first (new order), the analogous rule: only implicit → claude sets the flag; intermediate Cursor → Codex fallback does not.
- **REPO_UNAVAILABLE coupling** — if plan phase was skipped due to `REPO_UNAVAILABLE`, coder phase should also skip (same guard predicate applied across both phases) — synthesis preserves this.
- **`refresh-execution-issues.sh` default** — line 79 falls back to `coder="claude"` when SESSION_ENV CODER is empty. After Phase 4, that fallback survives uneventfully because `phase_coder_select` populates SESSION_ENV (or KV tail) on every happy path; verify the harness still reads `CODER` from the right source.
