## High-level implementation approach (architecture review)

### 1. Key architectural decisions

Phase 4 should finish the same consolidation pattern Phases 1–3 established: **mechanical Step 0 work lives in `scripts/implement-bootstrap.sh`; `skills/implement/SKILL.md` keeps orchestration contract only** (one foreground bootstrap invocation, KV parse/export, bail routing table, dirty-tree recovery carve-out). `phase_coder_select` replaces the stub at ```911:914:scripts/implement-bootstrap.sh``` and plugs into existing guards (`should_run_post_tracking_phase`, bail/`STALL_TRACKING` short-circuit before later phases) so DEFERRED paths still skip coder selection while permissive plan materialization remains unchanged.

Reuse existing infrastructure rather than new libraries: **`lib-quiet.sh`** (`emit_kv`, `emit_breadcrumb`, `larch_err`) for the five-breadcrumb happy path and KV-only stdout; **`read-session-env-key.sh`** for the four probe keys (resume already rehydrates them in `phase_infra` at ```342:345:scripts/implement-bootstrap.sh```); **`codex_available` / `cursor_available`** already derived in `phase_infra` (```479:488:scripts/implement-bootstrap.sh```) — `phase_coder_select` should consume those globals after a session-env re-read for parity, not reimplement probe logic. For explicit `--coder` failures, a small internal helper (e.g. `coder_unavailable_class` → `binary_missing` | `undeterminable` | `runtime_failed`) keeps the six verbatim SKILL strings maintainable without a cross-repo abstraction. Wire results into `emit_final_tail`’s existing `coder` / `coder_fallback` slots (```964:965:scripts/implement-bootstrap.sh```), set `IMPLEMENT_BAIL_REASON=coder-unavailable` + `STALL_TRACKING=true` on explicit mismatch, and use `larch-log.sh manifest --field coder_fallback=true` only on implicit Claude fallback — matching today’s ```742:774:skills/implement/SKILL.md``` behavior.

**Alignment note:** the approved outline mentions an implicit **Cursor → Codex → Claude** waterfall, but the repo’s canonical order is **Codex → Cursor → Claude** (`SECURITY.md`, `scripts/test-implement-step2-routing.sh`, current SKILL prose). Phase 4 should port existing semantics verbatim; changing order is a separate product decision that would require updating those pins.

Orchestrator boundary stays clean per non-goals: **`--coder` argv parsing and `coder_explicit` remain in the SKILL flag section**; bootstrap receives `--coder <value>` when explicit. Warnings for implicit fallback belong on stderr via `larch_err`/`emit`; execution-issue bullets can use `append-tool-failure.sh` (Warnings category) like other Step 0 phases.

### 3. Tradeoffs (maintainability vs convenience)

**SKILL collapse vs debuggability** — Moving ~576 lines into script + `.md` sharply reduces prompt drift and duplicate rehydration blocks, but operators lose inline prose; compensate by keeping exit-2 routing and dirty-tree recovery in SKILL while pushing waterfall tables to `implement-bootstrap.md` (single canonical doc per `AGENTS.md` conventions).

**Inline `case` vs shared warning helper** — Verbatim strings resist refactoring; a 30-line helper per tool (cursor/codex) trades a bit of indirection for one place to update when probe messaging changes. Avoid extracting to `scripts/` unless a second caller appears — YAGNI within the bootstrap file.

**Structural pins vs agility** — Extending the existing awk block (```466:489:scripts/test-implement-structure.sh```) from `plan` to `coder` prevents re-absorption of deleted helpers but requires coordinated updates whenever Step 0 argv shape legitimately changes; document the pin intent in the sibling `.md`.

**Test surface split** — Bootstrap harness owns behavior; structure harness owns shape; step2-routing must move or shrink — three test files touching one feature is intentional insurance against the #2732 regression class, at the cost of coordinated edits each phase.

**Resume / single-Bash acceptance** — “Exactly one Bash call” on clean main is compatible with a second resume-only call on dirty-tree; ensure acceptance criteria and structural pins both allow the resume exception while forbidding reintroduced inline `snapshot-untracked` / `gh issue view` blocks in Step 0 fences.
