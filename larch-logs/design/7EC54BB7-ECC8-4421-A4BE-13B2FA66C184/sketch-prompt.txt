/design Step 3 plan-review: orchestrator-side env-file persistence of `ALL_OUTPUT_FILES` (space-separated paths) crashes the next Bash block

## Symptom

During `/design --simple 2632` Step 3 (plan review), after `dispatch-with-waterfall.sh` returned 10 reviewer output paths in `ALL_OUTPUT_FILES`, the orchestrator wrote them to a small env file (`$DESIGN_TMPDIR/dispatch-state.env`) intending to source them into the subsequent `collect-agent-results.sh` Bash block (because the Claude Code Bash tool does not preserve in-process shell variables between calls).

The next Bash block sourced that env file and immediately failed:

```
$DESIGN_TMPDIR/dispatch-state.env: line 1: $DESIGN_TMPDIR/codex-primary-plan-arch-output.txt: Permission denied
error: unexpected argument 'codex' found
collect-agent-results.sh: at least one output file is required
```

The `read -r -a _all_output_files <<< "$ALL_OUTPUT_FILES"` step then produced an empty array because `ALL_OUTPUT_FILES` was set to only the first path. Calling `collect-agent-results.sh` with zero positional arguments hit anti-pattern rule #4 in `skills/design/SKILL.md` ("NEVER call `collect-agent-results.sh` with zero positional arguments").

## Exact Bash that broke it

```bash
# In the dispatch Bash block — wrote env file without quoting the value:
printf 'ALL_OUTPUT_FILES=%s\nALL_OUTPUT_TOOLS=%s\nDISPATCH_OK=%s\n' \
  "$ALL_OUTPUT_FILES" "$ALL_OUTPUT_TOOLS" "$DISPATCH_OK" > "$DESIGN_TMPDIR/dispatch-state.env"

# In the next Bash block — sourced that file:
source "$DESIGN_TMPDIR/dispatch-state.env"
read -r -a _all_output_files <<< "$ALL_OUTPUT_FILES"
"$CLAUDE_PLUGIN_ROOT/scripts/collect-agent-results.sh" ... "${_all_output_files[@]}"
```

The env-file line was literally:

```
ALL_OUTPUT_FILES=/path1.txt /path2.txt /path3.txt /path4.txt /path5.txt /path6.txt /path7.txt /path8.txt /path9.txt /path10.txt
```

unquoted. Bash interprets `VAR=value cmd args` as "set VAR=value for the next command, then exec cmd args". So `source` executed `/path2.txt` with `/path3.txt /path4.txt …` as arguments → "Permission denied" because the file is a non-executable `-rw-` regular file. The `codex` argument error came later when bash kept walking the trailing paths and one of them began with content containing `codex`.

## Root cause

Two layers:

1. **Orchestrator mistake (immediate cause)**. The persistence write used unquoted bash KV format. The fix on the orchestrator side is one of:
   - `printf 'ALL_OUTPUT_FILES="%s"\n' "$ALL_OUTPUT_FILES" > "$envfile"` (quoted value)
   - Write paths one per line into a dedicated file (`printf '%s\n' "$path" >> "$listfile"`) and `mapfile`/`while read` it back (Bash 3.2: while read).
   - Do dispatch + collect in a single Bash block (no env-file round-trip).

2. **Skill ergonomics gap (root cause)**. `skills/design/SKILL.md` Step 3 splits the dispatch and the collect into two visually-separate Bash code blocks: dispatch parses `ALL_OUTPUT_FILES` into a shell variable, and the collect block (whose contract lives in `references/plan-review.md`) starts with `read -r -a _all_output_files <<< "$ALL_OUTPUT_FILES"`. This is internally inconsistent with the SKILL's own foundational invariant — quoted from SKILL.md line ~120:

   > The Claude Code Bash tool does NOT preserve shell state between calls. Step 0a writes `$DESIGN_TMPDIR/source-env.sh` containing … so those values survive into the new subshell.

   `source-env.sh` is the documented persistence path for session-wide values (`DESIGN_TMPDIR`, `SESSION_ID`, reviewer presence). There is no documented persistence pattern for `ALL_OUTPUT_FILES` between the dispatch Bash block and the next Bash block. An orchestrator that does dispatch + collect across two Bash calls (which is natural — the dispatcher already blocks for ~20 minutes; bundling collect into the same block doubles the timeout footprint and means a single Bash failure loses both phases) must improvise persistence, and that's where this bug landed.

## Reproduction

1. `/design --simple <ISSUE>` (or `--hard`); reach Step 3 plan review.
2. Let `dispatch-with-waterfall.sh` complete normally with 10 external reviewer outputs.
3. In the dispatch Bash block, capture `ALL_OUTPUT_FILES` parsed value but use `printf 'KEY=%s\n' "$val"` (unquoted) to persist it.
4. In a subsequent Bash block, `source` that env file.
5. → "Permission denied" + `collect-agent-results.sh: at least one output file is required`.

The bug ONLY surfaces when:
- Multiple reviewer paths are returned (i.e., normal Step 3 plan review with `review_budget=full`); and
- The orchestrator persists across Bash calls via an env-file (rather than bundling dispatch + collect in one block).

## Suggested fix (in order of preference)

A) **SKILL.md tightening** — `skills/design/SKILL.md` Step 3 should either:
   - Bundle the dispatch Bash block and the collect Bash block into a single block (preferred — fewer cross-subshell hazards), with the caveat that the combined `timeout` covers both phases.
   - OR explicitly document the cross-subshell persistence pattern: write `ALL_OUTPUT_FILES` paths one-per-line to `$DESIGN_TMPDIR/all-output-files.txt` (no shell quoting required) and reload via `while IFS= read -r p; do _all_output_files+=("$p"); done < "$file"` (Bash 3.2 compatible — no `mapfile`).

B) **`dispatch-with-waterfall.sh` change (defense in depth)** — have the dispatcher write `ALL_OUTPUT_FILES` paths one-per-line to a deterministic file under `$DESIGN_TMPDIR` (e.g., `$DESIGN_TMPDIR/<slot-set>-output-files.txt`) in addition to printing the space-separated string. Orchestrators that already work today don't break; new orchestrators have a documented cross-subshell handoff.

C) **`collect-agent-results.sh` ergonomic** — accept `--paths-file <file>` (one path per line) as an alternative to positional arguments. This eliminates the shell-array hazard entirely for callers that produced a multi-line manifest.

D) **CI/lint coverage** — add a `scripts/test-design-structure.sh` (or similar) assertion that catches Bash blocks in `skills/design/SKILL.md` that read a multi-value shell variable across subshells without a documented persistence mechanism. This is fuzzier than (A)-(C); only worth doing if other inline cross-subshell hazards exist.

## Impact / observed cost

On the affected `/design --simple 2632` run, the failure was recoverable: re-running `collect-agent-results.sh` with the explicit 10-path positional list (re-derived from the dispatcher's printed stdout, which the orchestrator had already shown to the user) skipped the broken env-file round-trip. No external tokens were re-spent — all 10 outputs already existed under `$DESIGN_TMPDIR`. But the recovery required user attention (manual interrupt + reformulation), so the cost is in human-loop time, not API tokens.

## Severity / focus / location

- Severity: medium (recoverable, but breaks the documented Step 3 flow under common orchestrator implementations).
- Focus: orchestration ergonomics / skill-prompt clarity.
- Location: `skills/design/SKILL.md` Step 3 (External Reviewer Dispatch via Waterfall section); `skills/design/references/plan-review.md` "Collecting External Reviewer Results" section.
