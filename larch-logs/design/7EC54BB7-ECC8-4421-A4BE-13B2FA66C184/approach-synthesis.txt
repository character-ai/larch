## Approach Synthesis

### Agreement

Both sketches (Codex substantive, Cursor exploratory) converge on:
1. **Strictly additive**: keep existing emit_kv KVs unchanged; add a new emission for the paths-file.
2. **Paths-file format**: one path per line, Bash 3.2-compatible `while IFS= read -r path; do ...; done` consumer.
3. **Cross-subshell handoff**: orchestrators read the new paths-file across Bash-tool blocks instead of persisting a shell variable.
4. **Test coverage**: extend existing harnesses (`test-dispatch-with-waterfall.sh`, `test-dispatch-plan-voters.sh`, `test-dispatch-code-voters.sh`, plus a new test for `collect-agent-results.sh --paths-file`).

### Divergence

- **Cursor (partial)**: "pass an explicit manifest path from callers" — implies caller supplies the destination path.
- **Codex**: dispatcher derives the path deterministically from the slots-file basename (e.g., `${slots_file_basename}-output-files.txt`) and emits the chosen location as a new KV `ALL_OUTPUT_FILES_PATH=<path>`.

**Synthesis pick**: deterministic-default with explicit override.

- The dispatcher accepts an optional `--paths-file <path>` flag. When passed, write there.
- When omitted, derive deterministic default from the slots-file path: `${slots-file}.output-files` (sibling with `.output-files` suffix — safer than `${basename}-output-files.txt` because it avoids any `.txt` collision with reviewer outputs and keeps the file alongside the slots manifest the caller already manages).
- Always emit a new `ALL_OUTPUT_FILES_PATH=<path>` KV via `emit_kv` so the caller can read the chosen location regardless of whether they passed the flag. Existing `ALL_OUTPUT_FILES` / `ALL_OUTPUT_TOOLS` stdout emissions are preserved unchanged.
- This serves both audiences: zero caller change (Codex direction) AND explicit per-caller control (Cursor direction).

### Voter-dispatcher scope nuance

Codebase audit reveals: `dispatch-plan-voters.sh` and `dispatch-code-voters.sh` emit only single-path KVs (`VOTER_1_PATH`, `VOTER_2_PATH`, `VOTER_3_PATH`), not multi-path lists. Single-path KVs do NOT exhibit the multi-word RHS hazard from the issue (e.g., `VAR=/single/path` is harmless when sourced unquoted; `VAR=/p1 /p2 /p3` is the bug shape). They only internally consume `ALL_OUTPUT_FILES` from the waterfall dispatcher inside their own script process (safe — single subshell).

User's Round 1 decision was "all three dispatchers" for uniform symmetry. To respect that while being honest about scope: voter dispatchers will get a `VOTER_PATHS_FILE=<path>` emission listing their voter output paths one-per-line. This is symmetric documentation, not a hazard fix. The dispatcher mode where the actual multi-path hazard lives is exclusively `dispatch-with-waterfall.sh`.

### Tradeoffs and risks

- **Risk**: filename collisions if `${slots-file}.output-files` ever collides with a real reviewer output. Mitigation: pick a suffix that can't appear elsewhere (`.output-files` doesn't end in `.txt`); test asserts the path is absent before write.
- **Risk**: empty paths-file silently passes the "never collect zero files" anti-pattern-#4 guard. Mitigation: `collect-agent-results.sh --paths-file` fails closed when the file is empty, preserving the invariant.
- **Risk**: orchestrators that fork `plan-review.md` continue to use the old pattern. Mitigation: the existing `ALL_OUTPUT_FILES` stdout KV is preserved unchanged, so forked snippets keep working.
- **Risk**: Test churn surface — three dispatcher harnesses + new collector test. Mitigation: tests are additive (existing assertions preserved); new assertions follow the existing test patterns.

### Failure modes

1. **Paths-file write race**: two `/design` runs share `$DESIGN_TMPDIR` — impossible because session-setup.sh creates a unique per-PID directory; but if a future caller passes the same explicit `--paths-file`, the second write clobbers the first. Mitigation: dispatcher writes atomically (`mv` from temp), and the explicit-flag path is opt-in.
2. **Stale paths-file from prior run**: if a deterministic-default path file exists from a previous run in the same `$DESIGN_TMPDIR`, the new content overwrites it. Acceptable — `$DESIGN_TMPDIR` is per-session.
3. **Backward-compat regression**: an external caller depends on `ALL_OUTPUT_FILES` stdout KV format. Mitigation: harness assertion preserves the exact emit line; CI catches a regression.
