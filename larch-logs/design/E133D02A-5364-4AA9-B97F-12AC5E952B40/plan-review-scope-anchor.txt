#### Problem

The reviewer-findings block grammar (headings of the form `### FINDING_N:` / `### OOS_n:`, security tags, focus-area fields) is split and matched by 15+ hand-written parsers with live drift. The canonical `review_types.parse_findings` has zero plan-review consumers. Independent regexes: `batch_report.py:28-30` and `review_and_fix.py:129-138` (identical trio, both files also import the canonical parser), `plan_review_accepted_audit.py:17` (wider ID character class), `plan_review_tally.py:982`, `review_tally.py:34-35`, `review_aggregate.py:27`, `voting.py:126,1084`, `plan_review_common.py:286`, `plan_review_findings.py:14`. Security-tag classification is copied from `voting.py:823 is_security_block_text` into `issue/oos.py:49`, `design/design_oos.py:109`, `issue/file_oos.py:88-113`, `issue/oos_disposition.py:42-68`, with differing focus-area character classes. `rejected_analysis.py:89` accepts any heading depth where the others require exactly three hashes. Segmentation also recurs in `issue/_oos.py:29`, `issue/audit_runs.py:1091`, `report/review_phase_detail.py:19`, `state/dirty_tree.py:253`, and `skills/fluff-analysis/scripts/fluff-analysis.py:240`.

#### Goal

One grammar module (block segmentation, heading/ID parse, is_security, non-security counting, dedup identity) — either grown in `review_types.py` with an OOS surface or a sibling `oos_grammar.py` both packages import. Delete the copies; add an adoption-ratchet lint banning `FINDING_`/`OOS_` heading regex literals outside the owner.

#### Size

~350 duplicated lines to ~120 shared; net reduction 200-250 lines and one answer to "is this block security-tagged".

## Proposed Design Outline

### Goals
- Single FINDING/OOS block-grammar owner in `larch/review/review_types.py`.
- All 15+ independent regex copies deleted; callers import from the owner.
- Adoption-ratchet lint bans new FINDING/OOS heading regex literals outside the owner.

### Non-goals
- Changing the wire format (heading syntax, field names, security tags).
- Touching non-Python parsers (shell scripts, fluff-analysis skill script exempt from the Python lint ratchet).
- Rewriting `_finding_dedup_key` logic; only move it to the owner.

### Approach sketch
- Extend `review_types.py` with: `parse_blocks()` (handles both FINDING and OOS IDs), `is_security_block_text()`, `count_non_security_blocks()`, `finding_dedup_key()`.
- Delete copies in `issue/oos.py`, `design/design_oos.py`, `issue/file_oos.py`, `issue/oos_disposition.py`, `review_aggregate.py`, `review_and_fix.py`, `batch_report.py`, `voting.py`, `state/dirty_tree.py`, `report/review_phase_detail.py`, `plan_review_findings.py`, `plan_review_tally.py`, `plan_review_common.py`.
- Update `lint_shared_convention_regex.py` to detect FINDING/OOS heading regex literals, with `review_types.py` on the allowlist.
- Add tests for the new grammar surface to `test_review_types.py`.
