## Approach

- **Primary fix: merge-eligible post-`ensure_pr` flush + push.** On `--merge` runs only (`working.merge` true; not draft, forked, forked-target, or repo-unavailable), add one `run_logs.flush_logs_pre` immediately after `ensure_pr`, `_write_ship_state` with `PR_NUMBER` / `PR_URL`, and **before** CI/merge loop entry. Use `working.with_(state_file=None)` like existing flush sites. This is the minimum change that puts PR-evidence state into a commit that can ride into the squash-merge tree on the common straight-merge path (`goto_rebase=false`). NEVER #16 unchanged: no post-merge commit.
- **Scope: merge-eligible only.** Do **not** flush on non-merge, draft, fork, or repo-unavailable early-return paths. Place the new flush **after** the early-return guard (`not working.merge or working.draft or ...`, lines ~1433–1449). Non-merge runs are out of scope for this bug; a local-only post-PR commit there would diverge from the remote PR branch without a guaranteed publish path.
- **Push is required after post-ensure flush (blocking on merge paths).** A local `flush_logs_pre` commit alone does not fix the regression: squash-merge uses the **remote** PR branch. After a successful post-`ensure_pr` flush on merge-eligible paths, **push the feature branch** before `ci_monitor.monitor` (reuse `push.push_branch` or a thin wrapper with the same contract as `finalize.postbump`'s force-push gate; do **not** re-run full postbump rebase). Stall on push failure the same way postbump stalls. Without push, the remote still carries the stale pre-PR `pr-prep` `bailed` snapshot.
- **Post-ensure flush is blocking on merge paths for critical skip reasons.** The post-`ensure_pr` flush is the authoritative pre-squash writer; warn-only parity with pre-`ensure_pr` `pr-prep` / `REFRESH_SKIP_MERGE_OK` is **not** sufficient on merge paths for `commit-failed` or `manifest-recovery-failed`. Treat those as **stalling** before CI loop entry. Preserve intentional `no-logs-commit` skips and other benign skips (`volatile-only`, missing run-id, etc.) as non-blocking via a dedicated `REFRESH_SKIP_POST_ENSURE_PR_OK` set.
- **Strict flush gates on local artifact success only, not tracking upsert.** For the post-ensure merge path, propagate `final-summary.md` write failure or `_reconcile_manifest_for_terminal_report` failure as `manifest-recovery-failed` (stalling). **Decouple tracking upsert from strict success:** when `flush_logs_pre(strict_final_report=True)` calls `write_final_report`, pass `skip_tracking_upsert=True` so local write + reconcile success returns `rc=0` even if `tracking-issue upsert-summary` fails afterward. Log upsert failure as a warn breadcrumb / execution-issues entry; do **not** map it to `REFRESH_SKIP_RECOVERY_FAILED`. Default `skip_tracking_upsert=False` everywhere else; `--comment-only` behavior unchanged.
- **Outcome cascade companion (required, not sufficient alone).** In `normalized_outcome_values`, add a gated PR-evidence branch: when `_has_pr_evidence(...)`, empty `MERGE_RESULT`, `_is_healthy_pre_terminal_pr_snapshot(...)`, and no higher-precedence terminal branch matched, emit `pr-created` or `pr-created-draft` **regardless of `MERGE`**. Remove the `not _truthy(merge)` gate on the old `pr_number` branch. **Gate out terminal failures after PR creation:** do not emit `pr-created` when `BAIL_REASON` / `IMPLEMENT_BAIL_REASON` is non-empty, `PHASE=stalled`, or `EXIT_CODE` is present and non-zero (e.g. `ci-fix-exhausted` with empty `MERGE_RESULT` must stay `stalled` / `bailed`, not success-classed). Without flush + push + this gated branch, merge runs still misrecord at flush time or never publish corrected logs.
- **Drop no-PR-imminent inference.** Do not infer `pr-created` from `PHASE=pr-create` / `pr-prep` without PR evidence. Remove `PRE_POSTBUMP_FLUSH` wiring from this PR.
- **Manifest reconciliation companion.** Reorder `write_final_report` so `run_dir/final-summary.md` is written **before** reconcile; replace `_stamp_skipped_steps_for_terminal_report` with `_reconcile_manifest_for_terminal_report` that sets `steps_ran.step8=true` when `final-summary.md` (or `version-bump-reasoning.md`) exists, and sets manifest `status` to `in-progress` for success-classified non-terminal outcomes (`pr-created`, `pr-created-draft`). Do not set `in-progress` for `bailed`, `bailed-needs-user-input`, or `stalled`.
- **`flush_logs_pre` reload companion.** After `_stage_pre_commit(..., mode="refresh")`, reload manifest via `load_or_recover_manifest_checked` and merge only the `step9a1` heuristic delta so a stale pre-render `steps_ran` snapshot cannot clobber reconciled `step8=true`.
- **Do not write `merged` pre-squash** in this PR.
- **Audit tolerance companion (#4): reinterpret stale committed bail dirs with PR evidence.** The writer fix only corrects new runs; historical dirs already on `main` keep the old `bailed` / `partial` snapshot. Make the committed-log classifiers (`audit-runs scan-run`, `run-log verify-completeness`) treat a run dir as non-bail when its `final-summary.md` heading bails but the manifest carries `pr_number` evidence. Offline and deterministic: no GitHub calls. Do not backfill or rewrite committed dirs; corrupt manifests stay strict.

## Edge cases

- **Draft / fork / repo-unavailable / non-merge**: no post-ensure flush or push; behavior unchanged on early return.
- **Draft PRs on merge path**: if merge-eligible with draft, early-return guard already exits; no post-ensure flush.
- **Already merged / design-only / forked-dry-run**: precedence unchanged.
- **Pre-`ensure_pr` snapshot**: `pr-prep` flush may still write `bailed`; post-`ensure_pr` flush + push is the last pre-squash publisher on straight happy paths.
- **Post-ensure flush or push failure on merge**: stall before merge; operator gets stalled run rather than squash-merging stale `bailed` snapshot.
- **`--no-logs-commit`**: post-ensure skip remains non-blocking.
- **Rebase / CI-fix paths**: existing pre-rebase flushes remain; post-`ensure_pr` flush+push runs once before first monitor, not inside `goto_rebase` loops.
- **Post-PR terminal failure (e.g. `ci-fix-exhausted`)**: gated cascade preserves `stalled` / `bailed`; does not misclassify as `pr-created`.
- **Tracking-issue comment on post-ensure path**: skipped via `skip_tracking_upsert=True`; fresh-path `write_final_report_comment` (~1430) and `--comment-only` post-merge refresh remain unchanged.
- **True pre-PR failures**: remain `bailed` / `bailed-needs-user-input`.
- **Historical committed dirs**: not rewritten; `audit-runs` / `verify-completeness` reinterpret them as non-bail when `pr_number` evidence is present (#4).
- **Corrupt manifest under audit tolerance**: never treated as PR evidence; corrupt dirs stay strict failures.

## Failure modes

- **Flush without push** leaves remote PR branch on stale pre-PR `bailed` commit; squash-merge preserves the bug. Mitigate with mandatory push after post-ensure flush.
- **Flush without outcome fix** still records `bailed` at flush time. Both ship sequencing and gated PR-evidence cascade required.
- **Outcome fix without flush+push** never reaches merged tree on straight path. All three required.
- **Unbounded PR-evidence branch** misrecords `ci-fix-exhausted` / stalled post-PR runs as `pr-created`. Mitigate with `_is_healthy_pre_terminal_pr_snapshot` gates on `BAIL_REASON`, `PHASE`, `EXIT_CODE`.
- **Strict flush treating upsert as local failure** blocks merge on transient `gh` outage despite correct committed artifacts. Mitigate with `skip_tracking_upsert=True` on post-ensure path.
- **Warn-only post-ensure on merge** for `commit-failed` / `manifest-recovery-failed` allows squash-merge of stale snapshot. Mitigate with merge-path blocking.
- **Suppressed `_write_final_report` errors** allow merge with corrupt manifest. Mitigate with `strict_final_report` on post-ensure path.
- **Non-merge post-ensure flush** would create unpushed local commits ahead of PR. Mitigate by merge-eligible-only scope.
- **Harness `step8=false` expectation** breaks CI after reconcile reorder. Mitigate with `test-write-final-report.sh` update.
- **Audit-tolerance false positive** could hide a genuinely incomplete bail that happens to carry a `pr_number`. Mitigate by requiring explicit `pr_number` evidence, keeping corrupt manifests strict, and only suppressing the bail-skip shortcut: tolerance never fabricates completeness, so missing required files still fail the scan.
- **Post-merge regression**: no post-merge commit path or bypass env var.
