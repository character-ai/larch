## Findings

### 1. **correctness** — `python/stall_recovery.py:671-674` (plan `### UPDATED: python/stall_recovery.py`, Failure modes)

The plan adds a healthy pre-terminal branch for `MERGE=true` and `PHASE in {"pr-prep", "pr-create"}` when no `PR_NUMBER` exists yet. That matches the reported pre-PR flush at `python/ship.py:1350`.

It does not change the existing `PR_NUMBER` branch at `python/stall_recovery.py:671`, which still requires `not _truthy(merge)`.

Later `flush_logs_pre` calls run after the PR exists with `MERGE=true` and `PHASE` values such as `rebase` or `ci-initial` (`python/ship.py:1675`, `python/ship.py:1776`, `python/ci_monitor.py:1196`). On those paths the new branch does not match, the `PR_NUMBER` branch is skipped because `merge` is true, and the cascade still lands on `bailed`.

Each of those flushes rewrites `final-summary.md` via `python/run_logs.py:1173` before commit. A merge run that rebases or CI-fix flushes once can squash-merge a committed tree that again says `bailed`, even after a correct pr-prep snapshot.

**Suggested revision:** In the same plan section, also drop the `not _truthy(merge)` guard on the existing `PR_NUMBER` branch so `--merge` runs with PR evidence get `pr-created` / `pr-created-draft`. Keep `merge_downgraded` on `not _truthy(merge)` at `python/stall_recovery.py:678-684`. Add a test for `MERGE=true`, `PR_NUMBER` set, `PHASE=rebase`.

**Precedence check:** Stall (`any_stall` at `python/stall_recovery.py:659-660`), fork, design-only, merged, and `force-merged-externally` branches all sit above both PR branches. The plan’s `BAIL_NEEDS_USER_INPUT` gate and stall-first ordering preserve those precedences. The gap is under-coverage, not reordering.

### 2. **[OUT_OF_SCOPE]** **architecture** — `python/audit_runs.py:511-537`, `python/run_logs.py:2491-2597` (plan Approach item 7)

The plan adds stale-bail tolerance in audit and verify tooling. The binding issue lists that as optional defense-in-depth (suggested fix item 4). New runs are fixed by the `stall_recovery` and `final_report` changes alone.

Historical dirs without `manifest.pr_number` or a parseable PR line in `final-summary.md` still will not benefit. `verify-completeness` already treats `manifest_pr_number` as step8 evidence at `python/run_logs.py:2562`.

**Suggested revision:** Drop `### UPDATED: python/audit_runs.py` and `### UPDATED: python/run_logs.py` from this PR unless historical audit scans are an explicit deliverable.
