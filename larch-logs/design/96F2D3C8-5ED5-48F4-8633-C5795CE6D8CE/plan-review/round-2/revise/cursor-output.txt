## Approach

- **Primary fix: post-`ensure_pr` committed flush.** Add one `run_logs.flush_logs_pre` in `python/ship.py` immediately after `ensure_pr` and the `_write_ship_state` that persists `PR_NUMBER` / `PR_URL`, using `working.with_(state_file=None)` like existing flush sites. Run it for **all** paths that proceed past PR create (merge runs before the CI/merge loop; non-merge runs before the early `Outcome.OK` return). This is the minimum change that puts PR-evidence state into the last pre-squash commit on the common first-pass CI-then-merge path (no `goto_rebase`). NEVER #16 unchanged: no post-merge commit.
- **Outcome cascade companion (required, not sufficient alone).** In `normalized_outcome_values`, add a PR-evidence branch: when `PR_NUMBER` or `PR_URL` is present, `MERGE_RESULT` is empty, and no higher-precedence terminal branch matched, emit `pr-created` or `pr-created-draft` **regardless of `MERGE`**. Remove the existing `not _truthy(merge)` gate on the `pr_number` branch by folding it into this branch. Without both the post-`ensure_pr` flush and this branch, `--merge` runs with `PR_NUMBER` set still fall through to `bailed` at flush time.
- **Drop the no-PR-imminent inference branch.** With the post-`ensure_pr` flush as the authoritative pre-merge writer carrying PR evidence, do **not** infer `pr-created` from `PHASE=pr-create` / `pr-prep` without `PR_NUMBER`. Remove `PRE_POSTBUMP_FLUSH` sentinel wiring from this PR; the pre-`ensure_pr` `pr-prep` flush may still record `bailed`, but the post-`ensure_pr` flush supersedes it on the branch that squash-merges.
- **Manifest reconciliation companion.** Reorder `write_final_report` so `final-summary.md` is written to `run_dir` before reconciliation; replace `_stamp_skipped_steps_for_terminal_report` with `_reconcile_manifest_for_terminal_report` that sets `steps_ran.step8=true` when `final-summary.md` (or `version-bump-reasoning.md`) exists, and sets manifest `status` to `in-progress` for success-classified non-terminal outcomes (`pr-created`, `pr-created-draft`). Do not set `in-progress` for `bailed`, `bailed-needs-user-input`, or `stalled`.
- **`flush_logs_pre` reload companion.** After `_stage_pre_commit(..., mode="refresh")`, reload manifest via `load_or_recover_manifest_checked` and merge only the `step9a1` heuristic delta so a stale pre-render `steps_ran` snapshot cannot clobber reconciled `step8=true`.
- **Do not write `merged` pre-squash** and **do not add audit/verify stale-bail tolerance** in this PR. Historical dirs stay as-is; reinterpret separately if needed.

## Edge cases

- **Draft PRs**: preserve `pr-created-draft` on the PR-evidence branch.
- **Forked dry runs**: `forked-dry-run` precedence unchanged.
- **Design-only**: `design-only` precedence unchanged.
- **Already merged**: `force-merged-externally` unchanged.
- **Pre-`ensure_pr` snapshot**: the `pr-prep` flush may still write `bailed`; the post-`ensure_pr` flush is the last pre-squash writer on straight happy paths.
- **Rebase / CI-fix paths**: existing pre-rebase flushes remain; post-`ensure_pr` flush must not regress ordering with `goto_rebase` loops.
- **Non-merge runs**: post-`ensure_pr` flush before early return fixes the same committed-artifact gap.
- **True pre-PR failures**: remain `bailed` / `bailed-needs-user-input`.
- **Stalled paths**: `STALL_TRACKING=true` still wins over neutral inference.
- **Outcome downgrade protection**: post-`ensure_pr` flushes with PR evidence must not downgrade to `bailed` (PR-evidence branch + multi-flush test).
- **Historical committed dirs**: not rewritten in this PR.

## Failure modes

- **Flush without outcome fix** still records `bailed` for `--merge` runs at flush time. Both ship flush placement and PR-evidence cascade are required.
- **Outcome fix without post-`ensure_pr` flush** never reaches committed tree on straight merge path (inference runs only inside `write_final_report` during flush). Both are required.
- **Over-broad PR-imminent inference** can hide real post-PR bails. Keep `BAIL_NEEDS_USER_INPUT` and stall precedence; only infer when PR evidence exists.
- **Manifest status drift** confuses analyzers. Restrict `in-progress` to success-classified non-terminal outcomes only.
- **`flush_logs_pre` clobber** can undo `step8` reconciliation. Mitigate by reloading manifest post-`_stage_pre_commit`.
- **Post-merge regression** remains high risk. No post-merge commit path or bypass env var.
