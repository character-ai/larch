### 1. [correctness] `scripts/lib-external-launcher-common.sh:25-30`

The plan adds `[[ -n "$stderr_sink" ]] && printf 'STDERR_SINK=%s\n' "$stderr_sink"` after the `OUTER_LAUNCHER_RISK=` line inside the existing `{ … } >> "$meta_path"` block, and justifies `&&` because the sourced lib has no `set -e`. That misses caller semantics: `external_launcher_append_outer_meta` ends with that compound command, so when `stderr_sink` is empty (the default for all current four-arg call sites and for any run without `--stderr-sink`) the `{ … }` group’s exit status is 1.

Callers are all `set -e` scripts — `launch-review.sh:4`, `launch-cursor-ci.sh:10`, `launch-cursor-implement.sh:44` — and invoke append without guarding the return code (`launch-review.sh:594`, `1010`). The no-sink path would terminate before exit, breaking every normal review launch. The plan’s `if`-form choice for `run-external-agent.sh:193-200` is correct for the same reason; the lib helper needs the same pattern (or an unconditional final command in the group).

**Suggested revision:** Replace the proposed `&& printf` with `if [[ -n "$stderr_sink" ]]; then printf 'STDERR_SINK=%s\n' "$stderr_sink"; fi`, matching the `run-external-agent.sh` writer.
