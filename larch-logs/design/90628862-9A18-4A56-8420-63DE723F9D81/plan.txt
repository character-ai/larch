# Implementation Plan — `--skill=<name>` for `/audit-runs` and `/report-tokens`

## Approach

Add a **required** `--skill=<name>` argument to both skills with a closed enum `{design, implement}`. Plumb the value through the existing helper scripts so all `larch-logs/implement` literals become `larch-logs/$SKILL`. Report titles gain a skill-prefix (`[Implement|Design Run Logs Audit ...]`, `[Implement|Design Analysis Report]`). The prior-report search regex for `--skill=implement` accepts BOTH the legacy and the new prefixed shape so historical reports remain discoverable; design starts clean.

The change is parameterization, not redesign. Helper scripts that currently accept `--log-root` or `--scans-tsv` are extended to also accept a `--skill` flag with the closed enum so SKILL.md can pass a single source of truth; design-specific code branches (PR title regex, design-only artifact filenames) live behind that `--skill` flag rather than ad-hoc directory probing.

## Edge cases

- **Missing flag**: both skills reject invocation with a clear error before any side effect (no GitHub call, no tmpdir).
- **Out-of-enum**: `--skill=foo` is rejected with the same shape of error and the allowed values listed.
- **Empty `larch-logs/<skill>/` directory**: same "no run logs found" path that already exists for implement. The error message names the resolved `LOG_BASE`.
- **No prior reports for `--skill=design`**: `since last audit` errors cleanly (existing behavior, same error shape).
- **Mixed-title legacy implement audit reports**: dual-regex prior-report search via the centralized title-matcher covers this for `--skill=implement`.
- **A chore PR titled like a design flush but pointing at a non-existent run dir**: `audit-map-runs.sh` emits the same TSV row with empty `run_id` (same as the existing missing-directory path for implement).
- **`--plot-from <N>` against a legacy `[Analysis Report]` issue under `--skill=design`**: title fetch detects the mismatch and rejects with a clear message before parsing.
- **`--plot-from <N>` against an `[Implement Analysis Report]` under `--skill=design`**: same title-mismatch rejection.
- **Design run dir missing `token-report-final.json`** (incomplete or paused run): same "skip with warning" path that implement uses for missing `token-report.json` (`larch_err "Warning: ..."`).

## Failure modes

- **Wrong skill scan applied to wrong run dir** — `scans-implement.tsv` against a `larch-logs/design/<RUN_ID>/` run dir would emit `result=error` NDJSON rows. Earliest signal: `audit-scan-run.sh` NDJSON `result=error` flood. Mitigation: SKILL.md derives the scans path from `$SKILL` mechanically and passes it; `audit-scan-run.sh` enum-validates `--skill` so the path mismatch is caught at preflight. Test harness verifies the wiring.
- **Title-matcher regex matches the wrong audit-report across skills** — the implement regex must NOT match `[Design Run Logs Audit ...]` and vice versa. Earliest signal: prior-report frontmatter parse fails or `audited_pr_range.last` references an unknown PR. Mitigation: anchor each regex with `^\[` and pin the skill literal in the alternation; assert boundary cases in `test-audit-runs.sh`.
- **`--plot-from` legacy-design rejection regression** — an operator running `/report-tokens --skill=design --plot-from <legacy-implement-issue>` should be rejected, not silently plot from cross-skill data. Earliest signal: visible error message before any parse. Mitigation: title fetch and prefix validation happen before any body parsing; explicit test fixture for the design + legacy-implement-issue case.
