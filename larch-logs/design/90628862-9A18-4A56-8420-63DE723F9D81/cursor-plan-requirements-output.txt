1. **[correctness]** `skills/report-tokens/scripts/run-analysis.sh:118-122`

Concern: the plan addresses the base directory for `--skill=design`, but not the design token report filename. Current scan code requires `token-report.json`; the committed design logs I checked have `token-report-final.json` and no `token-report.json`.

Scenario: `/report-tokens --skill=design` would walk `larch-logs/design/*`, skip every run at the token-report existence gate, and report no parseable design token data.

Suggested revision: make the token report path skill-aware. Keep `token-report.json` for implement and read `token-report-final.json` for design. Update the proposed design fixtures and tests to use `token-report-final.json`.

2. **[correctness]** `skills/report-tokens/scripts/run-analysis.sh:1088-1096,1134-1138`

Concern: the plan requires `--skill=design --plot-from <N>` to reject legacy `[Analysis Report]` issues, but it assigns that to the issue-body parser. The current flow fetches only `.body`, then passes only a body file to Python, so there is no title available to validate.

Scenario: a legacy implement analysis issue with a valid raw-data block can be accepted under `--skill=design`, which breaks the skill-scoping contract.

Suggested revision: fetch `title,body` for `--plot-from` and validate title shape before plotting, or write/read an explicit skill marker in the report body. Add a focused test for design rejecting legacy `[Analysis Report]` and implement accepting both legacy and `[Implement Analysis Report]`.
