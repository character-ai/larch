**1. [correctness] `python/ship.py:477-484` — Trigger-C pre-postbump refresh must be best-effort**

Bash always continues to postbump after `refresh-run-logs.sh`, even when refresh fails (`|| true` at `scripts/ship-pr.sh:1119-1121`). The plan moves refresh out of `finalize.postbump` into `ship.py` but does not require the same non-fatal contract. Without it, a `flush_logs_pre` skip (including future `recovery_ok=false`) can stall bump while bash proceeds.

**Suggested revision:** Specify that pre-postbump refresh logs warnings and never blocks postbump; add a ship test that refresh failure still invokes postbump with `log_write_status=skipped`.

**2. [correctness] `python/ci_monitor.py:865-890` — CI-fix plan omits post-rebase verify and pre-push refresh**

The cited bash range includes `_run_post_rebase_verify_gates` and `refresh-run-logs.sh || true` before the force-push/plain-push branch (`scripts/ship-pr.sh:1685-1699`). Plan prose only mentions defer-rebase and push semantics. An implementer could add rebase + force-push without re-verify, lint re-check, optional post-rebase commit, or log refresh.

**Suggested revision:** Explicitly port post-rebase verify gates, the failed-jobs-TSV-empty defer-rebase skip, and best-effort pre-push refresh; thread the inputs `stage_and_push` needs and test them.

**3. [correctness] `python/ship.py:431-435` — Postmerge flush skip must not stall**

Current code returns `Outcome.STALLED` on any `flush_logs_post` skip. Bash records warnings and always advances to `done` (`scripts/ship-pr.sh:3141-3178`). The plan’s warning-only OK rule is limited to recovery/manifest/report failure and does not say to remove the existing stall branch.

**Suggested revision:** Treat all postmerge flush/manifest/report failures as warning-only; remove the stall return; test OK advance with failed flush.
