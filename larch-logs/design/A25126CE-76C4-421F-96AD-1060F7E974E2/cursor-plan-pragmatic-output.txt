### 1. [architecture] `plan.txt:46-52` — `RunContext` file omitted

The plan adds `ci_fix_rebase_pending` on `RunContext`, hydrates it from env/state, and serializes it in `_write_ship_state`, but `python/run_context.py` is not in **Files to modify/create**. Without that file, the field cannot exist or round-trip through `ship-pr-state.sh`, breaking persisted CI-fix rebase retry parity with `scripts/ship-pr.sh:59-78`.

**Suggested revision:** Add `### UPDATED: python/run_context.py` with the field, `from_env` / state-file hydration via `run_logs.read_state_kv`, and a unit test pin.

### 2. [correctness] `plan.txt:54-56` — CI-fix pending not plumbable through current monitor APIs

`evaluate_failure`, `run_ci_fix`, and `stage_and_push` take `run_id`/`repo`/`cwd` only — no `state_file`, `tmpdir`, or `ci_fix_rebase_pending`. Bash `_stage_and_push_ci_fixes` reads the global hydrated at `ship-pr.sh:1617-1620` and sets pending at `1710`. Python cannot reproduce push-only retries or the tests listed in `test_ci_monitor.py` without explicit API threading.

**Suggested revision:** Name new parameters on `monitor` → `evaluate_failure` → `run_ci_fix` → `stage_and_push`, document ship-loop updates to `working` and `_write_ship_state` after each fix attempt.

### 3. [risk-integration] `plan.txt:46-48` — Missing ship-layer postbump residue clear

Bash `run_bump_phase` always runs `_clear_phase1_postbump_residue` (`rm` of `.postbump-phase`) before refresh and `implement-finalize.sh postbump` (`ship-pr.sh:1111-1125`). The plan ports checkpoint handling only inside `finalize.postbump`. A stale symlink checkpoint is removed by bash before finalize runs; Python can still hit `postbump-state-corrupt`.

**Suggested revision:** In `ship.py` postbump layering (before Trigger-C refresh), mirror `_clear_phase1_postbump_residue` at minimum `rm -f "$tmpdir/.postbump-phase"`.
