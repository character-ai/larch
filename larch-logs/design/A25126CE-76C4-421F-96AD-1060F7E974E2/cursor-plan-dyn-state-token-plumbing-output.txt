**1. [correctness] `python/ship.py:352-392`, `python/ship.py:658-659` — `CI_FIX_REBASE_PENDING` lifecycle incomplete in ship driver**

The plan adds `RunContext.ci_fix_rebase_pending` and serializes it in `_write_ship_state`, but Python never loads the flag from `ctx.state_file` at `run_ship` entry (bash `_ci_fix_pending_hydrate` at `scripts/ship-pr.sh:3248`), `_write_ship_state` currently omits `CI_FIX_REBASE_PENDING`, and the CI loop does not write back pending state after monitor/fix attempts.

**Suggested revision:** Add a startup hydration step from `ctx.state_file`, include `CI_FIX_REBASE_PENDING` in `_write_ship_state`, and after each monitor/fix path that sets or clears pending, update `working` and persist before the next iteration.

**2. [correctness] `python/ci_monitor.py:865-891` vs `scripts/ship-pr.sh:1708-1719` — missing `verify_passed` gate before persisting pending rebase**

Bash sets `CI_FIX_REBASE_PENDING` only when post-rebase verify gates passed and force-push fails (`verify_passed=true`). The plan’s `ci_monitor.py` section does not mention this gate.

**Suggested revision:** In the `stage_and_push` port, set pending only when `verify_passed` is true; otherwise record failure and return without persisting pending.

**3. [correctness] `python/ship.py:476-478` vs `scripts/ship-pr.sh:1119-1121` — Trigger-C bump refresh must stay best-effort**

Bash runs `refresh-run-logs.sh` with `|| true` before postbump. Moving refresh to `ship.py` without the same rule would stall bump on benign refresh skips that bash ignores.

**Suggested revision:** Make pre-postbump refresh warning-only for merge/post-merge skip reasons; keep fail-closed `recovery_ok` gating for recovery/manifest paths only.

**4. [architecture] `python/ci_monitor.py:1059-1138`, `python/ship.py:554-566` — `evaluate_failure` pending-retry wiring underspecified**

When `CI_FIX_REBASE_PENDING` is true, bash `run_evaluate_failure` skips vendor dispatch and calls `_stage_and_push_ci_fixes` directly (`scripts/ship-pr.sh:2231-2233`). The plan threads the flag through `FixResult` but does not require `monitor()`/`evaluate_failure()` to accept it or `run_ship` to pass `working.ci_fix_rebase_pending` each iteration.

**Suggested revision:** Extend `monitor`/`evaluate_failure`/`stage_and_push` with `ci_fix_rebase_pending`; branch to push-only `stage_and_push` at the top of the evaluate_failure loop when pending; return updated pending in `FixResult`; have `run_ship` pass and apply it each loop turn.
