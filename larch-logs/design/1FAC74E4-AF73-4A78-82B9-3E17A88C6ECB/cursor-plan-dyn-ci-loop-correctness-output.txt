## Findings

### 1. Outer `evaluate_failure` loop can multiply the 20-cycle budget (blocking)

**Plan bullet:** Retire `CI_MONITOR_FIX_WATERFALL_MAX_ATTEMPTS` for ship-pr CI fixes; replace role=`fix` with `ci agentic-fix` delegate.

**Repo:** `evaluate_failure` still runs `CI_MONITOR_FIX_WATERFALL_MAX_ATTEMPTS` (currently 3) outer iterations at ```1486:1607:python/ci_monitor.py```.

**Concern:** One agentic subprocess already owns up to 20 cycles. Nesting it inside the existing outer loop allows up to 60 fix cycles and defeats the budget constraint.

**Suggested revision:** Collapse `evaluate_failure` to a single agentic delegate per evaluation (plus pre-delegation transient rerun / in-progress wait).

---

### 2. `CI_FIX_REBASE_PENDING` push-only retry path is unspecified (important)

**Plan bullets:** Map `rebase-required` to a successful fix result; do not agentically resolve conflicts in the CI loop.

**Repo:** ```1492:1527:python/ci_monitor.py``` calls `run_ci_fix(..., ci_fix_rebase_pending=True)`, which only re-attempts `stage_and_push` without launching a fixer.

**Concern:** Removing `run_ci_fix` without a replacement pending branch either re-runs the full agentic loop on a deferred push or drops the pending fast path.

**Suggested revision:** Preserve a pending-only `stage_and_push` retry in `evaluate_failure`; map agentic `rebase-required` to `ci_fix_rebase_pending=true` with the same monitor semantics as today's `waterfall-failed` + pending path (```1776:1782:python/ci_monitor.py```).

---

### 3. `monitor()` does not handle agentic success/failure status tokens (important)

**Plan bullets:** Emit `STATUS=passed|rebase-required|ci-fix-exhausted|...`; map to `FixResult`.

**Repo:** `monitor()` branches only on `pushed`, `fix-exhausted`, `local-unfixable`, etc. at ```1730:1788:python/ci_monitor.py```.

**Concern:** New KV statuses that become `FixResult.status` values not in that switch fall through to `Outcome.STALLED`.

**Suggested revision:** Add explicit `monitor()` branches or pin the mapper to existing `FixResult.status` values and document the contract.

---

### 4. `local-unfixable` → `fix-exhausted` upgrade conflicts with plan mapping (important)

**Plan bullet:** `local-unfixable` maps to `NEEDS_USER_INPUT`.

**Repo:** ```1566:1572:python/ci_monitor.py``` upgrades `local-unfixable` to `fix-exhausted` when `code_fix_attempted_on_ready_log` is set.

**Concern:** Operators get `ci-fix-exhausted` stall routing instead of direct `local-unfixable` handling.

**Suggested revision:** Skip that conversion on the agentic path.

---

### 5. Passive `ci wait` argv contract is incomplete (important)

**Plan bullet:** After push, call `python3 python/cli.py ci wait` as one blocking subprocess.

**Repo:** `wait_main` requires `--pr`, `--repo`, and optional `--iteration`, `--rebase-count`, `--fix-attempts` for `poll_ci` → `decide()` at ```172:182:python/ci.py``` and ```133:162:python/ci_monitor.py```.

**Concern:** Omitted counter args can skew `decide()` and break parsing `FAILED_RUN_ID` for the next agentic cycle.

**Suggested revision:** List the full `ci wait` invocation in the plan and thread live ship counters into the agentic driver.

---

### 6. `ci-fix-exhausted` detail must preserve stall-recovery shape (important)

**Plan bullet:** Bail with `ci-fix-exhausted` after 20 cycles.

**Repo:** `_fix_exhausted_detail` at ```1402:1421:python/ci_monitor.py``` adds job names and redacted log tail; `stall_recovery.py` uses a valid detail log for `step8-shippr` resume at ```210:215:python/stall_recovery.py```.

**Concern:** A minimal `DETAIL=ci-fix-exhausted` string regresses inline resume to `unrecoverable`.

**Suggested revision:** Reuse `_fix_exhausted_detail` (or equivalent) when emitting exhaustion KV output.
