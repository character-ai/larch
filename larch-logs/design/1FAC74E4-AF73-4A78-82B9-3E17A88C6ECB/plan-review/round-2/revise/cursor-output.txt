## Plan

### Approach

- `approach-synthesis.txt` is `NO_SKETCHES`.
- Use the approved outline as binding scope.
- Keep the change narrow:
  - Ship-pr CI fixes use a dedicated agentic subprocess with a single delegate per failure evaluation.
  - Conflict resolution uses an explicit per-tier loop in `_resolve_conflicts` (not stock `run_waterfall`), with write-capable tiers and post-tier unmerged-path verification.
  - Pre-ship lint-fix gets order/model changes, a dedicated Claude lint-fix launcher, and a corrected availability gate.
  - Ship-pr version-bump conflict special cases and their prose are removed everywhere they still ship.

### Core behavior

- Set the shared fixer order to `("claude", "codex", "cursor")`.
- Set the Claude fixer model default to `claude-opus-4-8`.
- Keep Codex at `gpt-5.5` with effort `high`.
- Keep Cursor at `composer-2.5`.
- For `role=fix`, stop using Codex and Cursor in ship-pr CI recovery.
- For `role=resolve-conflict`, keep the reordered single-shot waterfall semantics via an explicit per-tier loop with post-tier unmerged-path verification.
- Upgrade `launch-claude-ci` to a write-capable agent mode (repo-scoped Edit/Write), matching Codex/Cursor CI launchers; do not use `claude --print` for fix or conflict roles.
- Add a dedicated write-capable `launch-claude-lint-fix` launcher for pre-ship lint-fix; do not route routine lint failures through CI-role `--failure-log` / `--plan-file` prompts.
- Add a 20-cycle CI-fix subprocess owned by `ci agentic-fix`:
  - collect current failed jobs and logs
  - launch write-capable Claude/Opus for focused working-tree edits
  - mechanically compare HEAD to the pre-cycle baseline; roll back and fail closed on model-authored commits
  - scan/revert forbidden paths and submodule paths before verify/push
  - run local verification for the failed fixable jobs
  - push only after guards and verification pass
  - run passive CI wait as one blocking subprocess call
  - continue on new CI failure
  - bail with `ci-fix-exhausted` after 20 cycles
- `evaluate_failure` delegates to the agentic fixer exactly once per failure evaluation; no outer `CI_MONITOR_FIX_WATERFALL_MAX_ATTEMPTS` loop for `role=fix`.
- Do not add an upfront ship-pr local checks gate.

### Edge cases

- Claude binary missing:
  - CI fix returns `first-fixer-non-health` or a clear agentic failure.
  - It must not fall through to Codex/Cursor for CI fixes.
  - Local lint-fix may continue to Codex/Cursor after Claude is unavailable or fails.
- Claude read-only or no-op conflict tier:
  - Explicit per-tier loop in `_resolve_conflicts` continues to Codex/Cursor when unmerged paths remain.
- CI run still in progress:
  - Wait before collecting logs when needed.
  - Use passive blocking wait after every push.
- CI failure changes after a push:
  - Start the next agentic cycle from the new failed run id.
- Local verification fails:
  - Roll back that cycle's edits.
  - Do not push.
  - Continue until the 20-cycle cap.
- Branch falls behind main or push hits rebase blockers:
  - Emit `rebase-required` with `CI_FIX_REBASE_PENDING=true`.
  - Let existing rebase/handoff paths handle conflict resolution.
  - Do not put merge-conflict resolution inside the agentic CI loop.
- No local equivalent job:
  - Return `local-unfixable`.
- Empty or malformed agentic subprocess output:
  - Fail closed as `waterfall-failed`.
- Model-authored commit despite prompt:
  - HEAD gate rolls back and fails the cycle closed.
- Forbidden or submodule path touched:
  - Revert and fail the cycle without push.
- Dirty baseline:
  - Preserve existing dirty-tree safeguards before staging and pushing.
- Version-file conflict:
  - Treat it like any other conflict.
  - Do not checkout ours.
  - Do not suppress handoff because it is a version file.
- Agentic exhaustion after 20 cycles:
  - Map to `fix-exhausted` and operator bail via Step 12d; do not route to main-agent CI-fix.
- Codex/Cursor absent but Claude present:
  - Lint-fix must still dispatch Claude first; never short-circuit to `main-agent-required` before the Claude attempt.

### Failure modes

- Agentic loop exhausts 20 cycles:
  - Return `FixResult(status="fix-exhausted", detail beginning with ci-fix-exhausted)`.
- Passive CI wait times out:
  - Count the cycle as not green.
  - Continue if cycles remain.
  - Exhaust to `ci-fix-exhausted`.
- Claude exits nonzero for auth, quota, or health on conflict resolution:
  - Continue waterfall to Codex/Cursor via explicit per-tier loop.
- Claude exits nonzero for non-health reasons as first fixer on CI fix:
  - Do not try Codex/Cursor for ship-pr CI.
  - Surface through existing launcher classification.
- Push fails:
  - Return `ci-fix-exhausted` or a precise push failure detail when unsafe to continue.
  - Do not loop blindly if the branch state is unsafe.
- Rebase conflict occurs during push preparation:
  - Emit `rebase-required`.
  - Use existing `PrePushConflictHandoff` / `goto_rebase` behavior in the parent process.
- Outer `evaluate_failure` re-invocation:
  - Must not multiply agentic cycles beyond the single delegate's 20-cycle cap.
