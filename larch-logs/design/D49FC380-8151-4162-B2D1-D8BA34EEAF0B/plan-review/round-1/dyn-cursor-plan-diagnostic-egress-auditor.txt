## Findings

### 1. Security — Tier A egress for failure-detail stderr (major)

The plan builds `design-publish-tail.failure.log` from captured stderr and uses it as `FAILURE_DETAIL_LOG` for terminal staging. On the design reporting path, eligible runs file Tier A issues whose body includes that file:

```292:296:python/larch/state/_report.py
    if detail_valid:
        body.append("\n## Validated failure-detail log\n\n" + detail_content + "\n")
    body.append(_append_file_section(label="Run-log pointer", path=tmpdir / "run-log-pointer.txt"))
```

Redaction before filing is secrets-only:

```413:420:python/larch/state/_report.py
def _redact_text(text: str) -> str | None:
    ...
    completed = subprocess.run([sys.executable, str(redactor), "redact", "secrets"], ...)
```

Approach item 3 says public output stays behind “existing sensitive-corpus and redaction checks,” but Tier A does not run tmpdir-paths scrub or sensitive-corpus rejection on the full body. Embedding stderr tails in the failure-detail log reintroduces operator path and traceback egress on the same path as the bug report.

### 2. Correctness — Terminal-state URL keys vs rawish gate (major)

The plan extends terminal state with issue, branch, and PR fields. Validation applies `_reject_rawish_terminal_value` to every key except `FAILURE_DETAIL_LOG`:

```319:323:python/larch/state/_tokens.py
def _reject_rawish_terminal_value(value: str) -> bool:
    ...
    return any(token in lower for token in ("http://", "https://", "github.com", "/users/", "/home/", " larch ", "```"))
```

Any staged `PR_URL=https://github.com/...` fails before the new per-key validators run, so extended progress state cannot validate and reporting falls back.

### 3. Correctness — `design-rename-log-flush` hint never reaches classification (major)

Design failure reporting classifies with `profile=generic`. That path hardcodes the resume hint:

```351:371:python/larch/state/_classify.py
    resume_hint = "none"
    ...
        "RESUME_HINT": resume_hint,
```

The implement profile discards the classifier hint tuple and uses `_resume_hint_for`, which returns `none` for generic step `publish` (lines 97–112). The plan’s recoverable / `design-rename-log-flush` classifier cannot affect filed reports without explicit hint wiring in both paths.

### 4. Risk integration — Tail capture ordering and symlink rejection (minor)

Temp captures are removed in `finally` today:

```675:679:python/larch/design/design_step5c.py
        finally:
            with contextlib.suppress(FileNotFoundError):
                publish_stdout_file.unlink()
            with contextlib.suppress(FileNotFoundError):

```

The plan adds durable tail files but should pin copy-before-unlink and the same nofollow / non-symlink containment used by `design_write_merge_env` and `_detail_log.py`, or the original diagnostic loss returns.

Log flush uses tmpdir-paths + secrets scrub (`design_log_publish_flow.py:199-238`). The plan’s fresh result-env initialization, checkpoint writes, and fail-closed redaction failure modes address the original stale-env and silent-loss defects.
