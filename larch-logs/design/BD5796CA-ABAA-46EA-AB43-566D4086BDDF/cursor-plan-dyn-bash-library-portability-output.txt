1. **[correctness]** `scripts/lib-design-reentry-guard.sh` (proposed, plan L51): The plan names both `stat -f %m` and `stat -c %Y` but not how to choose at runtime. Repository precedent in `scripts/lib-external-launcher-common.sh:96-106` uses try-fallback with `^[0-9]+$` validation because GNU `stat -f` on Linux is not a format flag. Without that in the plan, implementers can pick a single flag or wrong order and break Linux mtime reads or arithmetic.

2. **[correctness]** `scripts/lib-design-reentry-guard.sh` (proposed, plan L50): `design_reentry_marker_write` is only described as `touch` the marker path. Edge cases cover permission failures (plan L110) but not a missing parent directory. `scripts/write-design-current-env.sh:139` already does `mkdir -p` before writing under the same `~/.cache/larch/sessions` tree; the write path should do the same so failures surface as `MARKER_WRITE_FAILED` rather than a raw `touch` error.

3. **[risk-integration]** `scripts/lib-design-reentry-guard.sh` (proposed, plan L51): The proposed flow is “checks if the marker exists” then “compares stat…”. That invites a separate `[[ -f ]]` before `stat`. A race-deleted marker or failed `stat` can emit stderr into the operator Bash transcript while Step 0b expects clean contract KV output. Specify stat-first (both flags redirected) and treat non-numeric or empty mtime as `MARKER_HIT=false` with return 1 and no stderr, following `scripts/check-reviewers.sh:89-98`.

4. **[architecture]** `scripts/lib-design-reentry-guard.sh` (proposed, plan L41, L49): Plan L41 says marker creation reuses a directory `session-setup.sh` already manages, but `session-setup.sh:234-236` resolves `${XDG_CACHE_HOME:-${HOME:-/tmp}/.cache}/larch/sessions` while the proposed marker path is `${HOME}/.cache/larch/sessions/...`. On Linux with custom `XDG_CACHE_HOME`, sessions and markers land in different trees; the guard silently fails open. Either align the path with `session_cache_root()` or document an explicit HOME-only contract (matching `write-design-current-env.sh:132-139`) and remove the session-setup claim.

5. **[code-quality]** `Makefile` (proposed, plan L100-101): The new `test-design-reentry-guard` target should use `scripts/harness-timer.sh` like `test-design-structure` at `Makefile:365-366` for consistent CI harness behavior.

6. **[correctness]** `scripts/test-design-reentry-guard.sh` (proposed, plan L62-68): F3 requires a marker older than TTL but does not say how to set mtime portably across BSD/GNU `touch`, risking a harness that passes on one OS only.

[OUT_OF_SCOPE] Broader alignment of `write-design-current-env.sh:132-139` and `skills/design/SKILL.md` prelude paths with `XDG_CACHE_HOME` (same HOME-only pattern as the proposed marker); worth a follow-up if markers move to the XDG-aware root.
