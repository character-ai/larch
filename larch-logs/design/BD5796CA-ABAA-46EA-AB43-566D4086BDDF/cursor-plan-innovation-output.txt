1. **[important] [risk-integration]** [`Makefile`](Makefile) — The plan says to add `test-design-reentry-guard` to the `lint:` target, but `lint` only depends on the aggregate `test-harnesses` target (shards 1–20). A standalone target that is never listed on any `test-harnesses-N` line will not run under `make lint`. Wire the target into a shard (e.g. `test-harnesses-14` beside `test-design-structure`) and use the `harness-timer.sh` wrapper like other `test-design-*` targets.

2. **[important] [correctness]** [`scripts/test-design-structure.sh`](scripts/test-design-structure.sh):758-767 — New checks 21–22 only grep for `design_reentry_marker_hit` / `design_reentry_marker_write`. Check 20 still asserts `2 → 2.5 → 3` only, so CI would not catch placing sub-step 2.6 after the clarify loop or already-planned router. Extend the ordering assertion to `2 → 2.5 → 2.6 → 3`.

3. **[important] [architecture]** [`skills/design/SKILL.md`](skills/design/SKILL.md):199-203 — Sub-step 2.6 runs before sub-step 4 (already-planned). After a completed design, an operator who reverts `[DESIGNED]` and retries within the TTL is refused at the session-cache guard and never reaches the replace/ad-hoc/cancel prompt—only marker deletion or waiting. If that friction is intentional, state it explicitly in Step 0b; otherwise run the guard after sub-step 4 or only when `larch:plan` exists and the operator did not choose replace.

4. **[important] [correctness]** [`skills/design/SKILL.md`](skills/design/SKILL.md):973-975 — Item 11 ties marker write to the same `SESSION_ID` / `PUBLISH_OK` gate as the `[DESIGNED]` rename. When plan-block-write succeeds but publish fails (`PUBLISH_OK=false`), there is no marker and no lifecycle title—exactly the “rename failed but plan succeeded” gap the plan motivates, but only partially closed. Stronger alternative: write the marker when step 4 succeeds (or `PLAN_WRITE_OK=true`) regardless of publish/rename outcome.

5. **[important] [correctness]** `scripts/lib-design-reentry-guard.sh` (proposed) — `design_reentry_marker_write` plans a bare `touch` without `mkdir -p` on `~/.cache/larch/sessions/`. `write-design-current-env.sh` does `mkdir -p` on that directory; a marker write before session-setup or on a fresh `HOME` in tests can fail silently into Warnings and leave the guard unarmed.
