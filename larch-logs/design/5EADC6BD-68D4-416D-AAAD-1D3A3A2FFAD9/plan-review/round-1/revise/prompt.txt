## Edge cases

- An empty live result may make every baseline row stale. Warn by default and fail only under strict stale.
- An empty write produces `[]` while dropping old rows.
- Metric changes preserve the reason because symbol identity excludes the metric.
- A baseline may change between initial load and publication. The guarded write and read-back checks must fail closed on unsafe state.
- A valid JSON array with duplicate identities is invalid even when duplicate rows are byte-identical.
- A filtered check may use a baseline, but filtered regeneration must not erase rows outside the selected paths.

## Failure modes

- Invalid flags, unsafe paths, malformed JSON, invalid schemas, duplicate identities, and missing reasons return `2`.
- Strict stale failures return `2` without writing.
- Atomic publication or read-back failure returns `2` and reports the baseline path on stderr.
- New or increased findings return `1` only after the full scan and baseline comparison validate.
