### 1. [correctness] Write-mode baseline targets must allow absent files (`python/larch/lint/engine.py:216-219`)

The plan calls for guarded `--write-baseline` bootstrap and tests that a successful write creates a new regular file. The existing `_normalize_repo_relative_path` helper rejects any path that does not already exist as a regular file. If baseline-path validation reuses that helper, first-time writes fail with exit `2` before `trusted_atomic_write` can create the file (which already supports absent destinations at `python/larch/io.py:208-210`).

**Suggested revision:** Add a write-specific destination validator that uses `larch.io` parent-chain checks, permits a missing destination file, and still rejects directory targets, symlink parents, escapes, and non-regular existing files.

### 2. [correctness] `--strict-stale` exit precedence with new findings is unspecified (`python/larch/lint/engine.py:472-515`)

The plan assigns exit `1` to new or regressed rows and exit `2` to strict stale, and the test section requires precedence when both are present, but the Approach never states which wins. That leaves a real fork: a run with new findings plus strict-stale rows could return `1` and violate the strict-stale acceptance criteria.

**Suggested revision:** Document that `strict_stale` forces exit `2` whenever any stale identity remains, even if stdout also carries new findings; pin this in Approach and the stale-precedence tests.

### 3. [correctness] Live Finding-to-baseline projection kind is undefined (`python/larch/lint/engine.py:46-55`)

Two baseline schemas are defined, and mixed baseline row shapes are rejected, but the plan does not say how a `Finding` maps to generic vs symbol-metric projection or when optional fields are incoherent. One `run_rule` call could produce mixed projected rows, making write-mode serialization fail read-back validation or compare the wrong identity keys.

**Suggested revision:** Add explicit projection rules and require a homogeneous projected live set per run (exit `2` on mixed projections).

### 4. [correctness] Filtered check stale detection scope is undefined (`python/larch/lint/engine.py:251-273`)

Write mode correctly refuses filtered regeneration, but check mode may pass `paths=` while loading a full baseline. Without scoping stale detection to the selected paths, baseline rows for unscanned files appear stale. That breaks filtered check semantics and can turn `--strict-stale` into a false exit `2`.

**Suggested revision:** Either exclude out-of-filter baseline identities from stale detection during filtered check, or require filtered check to use a baseline scoped to the same paths; test the chosen behavior.

### 5. [risk-integration] `larch.io` failures are outside the `ScanError` exit-2 contract (`python/larch/lint/engine.py:507-509`)

This piece introduces trusted baseline I/O, but `run_rule` only catches `ScanError`. `read_trusted_text` and `trusted_atomic_write` raise `OSError` on symlink parents, escapes, non-regular targets, root TOCTOU (`python/larch/io.py:195-201`, `235-240`), and publication failures. Those bypass the documented `0/1/2` contract and the plan's fail-before-mutation buffering on error paths.

**Suggested revision:** Convert trusted I/O failures into `ScanError` before they reach the orchestrator boundary.
