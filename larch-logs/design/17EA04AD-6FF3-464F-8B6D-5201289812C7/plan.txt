## Edge cases

- **Missing summary file:** keep current behavior. Emit no readiness markers and no summary path from the helper.
- **Empty summary file:** keep current behavior. Emit no readiness markers and no summary path from the helper.
- **No trailing newline:** no longer relevant to contract-stream body emission. Keep a test that ensures the disk body remains untouched.
- **Step 5c publish rows:** if Step 5c already emits `FINAL_SUMMARY_PATH`, duplicate identical rows are acceptable only if existing KV consumers tolerate them. Prefer avoiding a duplicate in Step 5c only if inspection shows the helper call would create confusing repeated rows. Otherwise favor the smallest helper-only change.
- **Sidecars:** preserve current `REPORT_GATE_SIDECARS_FILE` behavior. Sidecars are separate from the final-summary body.
- **Stale orchestrator prose:** any callsite still directing marker-body extraction yields empty chat after Python stops emitting bodies; `finalize-step5.md`, SKILL.md Final summary block lines, and harness greps must all move together.

## Failure modes

- If the orchestrator prose still tries to extract a marker body, chat output will be empty. The shared profile, SKILL.md, `finalize-step5.md`, and harness updates must close this gap.
- If `FINAL_SUMMARY_PATH` is omitted on cancellation paths, the summary may not display. Emitting the path inside `_emit_final_summary_marked_from_disk` covers those paths.
- If tests only check markers, the Gantt corruption regression can return. Add a body-omission assertion for a large Gantt-like summary.
- If harness greps still require marker-first language, CI will fail even when runtime behavior is correct.
