1. **[correctness]** `plan.txt:36-37,175-176` — The proposed `classify_bump` idempotency walk describes transparent commits by subject prefix only. Bash also requires file-set validation (`CHANGELOG.md`-only or `larch-logs/**` only) and caps the walk at three commits. Without both, a spoofed `Update CHANGELOG for …` commit above real skill changes can be misclassified as `NONE` instead of a real bump (see `.claude/skills/bump-version/scripts/test-classify-bump.sh` test 5). **Suggested revision:** Spec and implement the `idempotency_commit_is_transparent` guards and `IDEMPOTENCY_DEPTH < 3` loop from `classify-bump.sh:89-126`.

2. **[correctness]** `plan.txt:43-44` — Mapping unmerged paths to `Stalled` conflicts with `apply-bump.sh:124-129` (exit **4**, `APPLIED=false`) and with `config.py` where `EXIT_BAIL=4` and `EXIT_STALL=6`. **Suggested revision:** Return `ApplyResult(applied=False, error=…)` for unmerged/dirty-tree failures; use `Stalled` only for `bump_branch_guard` (ship-pr stall semantics).

3. **[correctness]** `plan.txt:105-109,214-217` — `verify_bump_commit_count` is specified with fail-closed status handling but the test plan lists bash parity only for classify/apply/drop-bump, not `scripts/check-bump-version.sh` / `lib-count-commits.sh`. **Suggested revision:** Add one `@pytest.mark.skipif` post-mode parity test against `check-bump-version.sh` on a shared fixture (including `missing_main_ref` / `git_error` paths).

4. **[correctness]** `plan.txt:58-62,147-148` — `ENV_LARCH_BUMP_FILES` is added to `config.py`, but `drop_bump_commit` is only described with a `bump_files` parameter. Shell drop logic is env-driven with replacement semantics (`drop-bump-commit.sh:130-185`). **Suggested revision:** State that `bump_files=None` reads `LARCH_BUMP_FILES` from the environment; add tests aligned with `scripts/test-drop-bump-commit.sh` custom-path cases.

5. **[risk-integration]** `plan.txt:108-109,164-166` — Bash classify always prints `REASONING_FILE=`; the plan moves reasoning into `BumpClassification.reasoning` and tells callers not to write `IMPLEMENT_TMPDIR`. Parity text “matches classify-bump.sh output” is underspecified and risks either flaky tests or reintroducing file side effects. **Suggested revision:** Limit bash-parity to version fields (`CURRENT_VERSION`, `NEW_VERSION`, `BUMP_TYPE`); test `reasoning` content independently.
