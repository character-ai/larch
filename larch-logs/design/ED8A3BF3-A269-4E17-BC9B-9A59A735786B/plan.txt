### NEW: python/oos_filer.py

New module; entry point is `cmd_file(argv)`.

**CLI**: `python3 python/cli.py oos file --implement-tmpdir PATH [--repo REPO] [--issue-number N] [--codex-timeout SECS]`

**Behavior**:

1. Parse args; read `FORKED_TARGET`, `REPO_UNAVAILABLE`, `RUN_ID`, `REPO` from `ship-pr-state.sh` (and argv overrides).
2. **Defense-in-depth security check**: if `$IMPLEMENT_TMPDIR/security-oos-observations.md` is non-empty, log Tool Failures and return non-zero (ship should already have stalled; this guards direct CLI misuse).
3. Resolve accepted OOS inputs (same order as `oos-pipeline.md` / disposition checkpoint):
   - `$IMPLEMENT_TMPDIR/oos-accepted-main-agent.md`
   - design OOS: `design-export/oos-accepted-design.md`, fallback `oos-accepted-design.md`
   - `$IMPLEMENT_TMPDIR/oos-accepted-review.md`
4. Build working batch: parse `### OOS_N:` blocks; deduplicate by normalized title (`file_oos._normalize_title`); exclude security-routed blocks (focus-area predicate from `file_oos`); skip blocks with existing `- **Filed URL**:` (count those URLs as already-filed evidence).
5. **Idempotency sentinel** (`$IMPLEMENT_TMPDIR/oos-issues-created.md`): if present with GitHub URLs, skip Codex + `/issue` create loop; reconstruct evidence from sentinel. Still write `run-statistics.md` and refresh `oos-issues.ndjson` evidence rows.
6. **Codex combine** (only when working batch has >1 item **and** Codex is available):
   - Write batch to `$IMPLEMENT_TMPDIR/oos-combine-input.md`.
   - Call `python3 python/cli.py agent launch-codex-exec --output $IMPLEMENT_TMPDIR/oos-combine-codex-output.md --timeout <codex_timeout> --prompt-file <prompt_file> --sandbox read-only --workdir <repo_root>`.
   - Prompt: aggressively merge unless clearly unrelated; valid `### OOS_N:` markdown; do not increase item count.
   - On success with valid output and non-increasing item count: replace working batch.
   - On Codex non-zero exit, invalid markdown, or item-count increase: **fall back to pre-combine working batch** (log warning under `Warnings`; do not abort entire filing).
   - When Codex is unavailable and batch size >1: skip combine; proceed with pre-combine batch.
7. Write combined markdown to `$IMPLEMENT_TMPDIR/oos-combined.md`.
8. Run cap pre-pass: `file_oos.issue_cap(...)` (or `python/cli.py oos issue-cap`).
9. Run file-conflict pre-pass: `file_oos.file_conflict_deps(...)`; on non-zero, degraded-continue without intra-batch deps (match `oos-pipeline.md` step 3.5).
10. **Carve-outs**:
    - `FORKED_TARGET=true`: skip `/issue` create; write skipped-evidence rows to `oos-issues.ndjson`; write `run-statistics.md`; stamp manifest; return 0.
    - `REPO_UNAVAILABLE=true`: same skip behavior.
11. **File via `/issue` batch machinery** (not bare `gh`):
    - Implement `_run_issue_batch(...)` in `oos_filer.py` (or thin wrapper in `issue_create.py`) mirroring `oos-pipeline.md` step 4:
      - `python/cli.py issue parse-input --input-file "$IMPLEMENT_TMPDIR/oos-combined.md" --output-dir <bodies_dir>`
      - `python/cli.py issue allocate-candidates --total-items N` (fail-open on non-zero per `/issue` contract)
      - Topological create loop: for each item, wrap OOS bodies per `/issue` OOS template, then `python/cli.py issue create-one --title ... --title-prefix "[OOS]" --body-file ... --repo <repo>`; honor `--blocked-by-issue` via existing `issue add-blocked-by` when parent issue set; forward intra-batch deps TSV when present.
      - Parse `ISSUES_CREATED`, `ISSUES_FAILED`, `ISSUES_DEDUPLICATED`, `ISSUE_<i>_URL=`, `ISSUE_<i>_DUPLICATE_OF_URL=`; treat created and duplicate-of URLs as disposition evidence.
      - **Sanitize every title/body** with `file_oos._sanitize_public_text` before writing temp body files passed to `issue create-one` (fail closed if sanitization would truncate critical content the same way `pr_body` redaction checks do).
    - If `/issue` batch exits non-zero or `ISSUES_FAILED>0`: do not write `oos-issues-created.md`; return non-zero.
12. Write sentinel `$IMPLEMENT_TMPDIR/oos-issues-created.md` (existing table format; include deduplicated URLs).
13. Write `$IMPLEMENT_TMPDIR/larch-logs/implement/$RUN_ID/oos-issues.ndjson` (accepted-disposition row per filed/deduped issue; sanitize NDJSON bodies per `execution-issues-tracking.md`).
14. Write `$IMPLEMENT_TMPDIR/larch-logs/implement/$RUN_ID/run-statistics.md` unconditionally: `Run $RUN_ID: <N> OOS issue(s) filed.` (or `0` for empty/skip).
15. **Manifest stamping**: call `python/cli.py run-log manifest` (or `run_logs.update_manifest`) to set `steps_ran.step9a1=true` when filing completed (including idempotent/skip carve-outs that still wrote evidence); on empty-input success with no filing gate, set `step9a1=false` explicitly.
16. Emit compact JSON stdout: `status`, `accepted_count`, `filed_count`, `deduplicated_count`, `urls`, `run_statistics_written`, `step9a1_stamped`.
17. Return 0 on success.

## Edge cases

- **No OOS files**: `oos file` writes `run-statistics.md` with 0 count, stamps `step9a1=false`, exits 0; ship proceeds.
- **Pre-ship timing + merge**: OOS batches committed by `flush_logs_pre` ride into squash-merge tree; audit sees `run-statistics.md` / `oos-issues.ndjson`.
- **Sentinel from prior session**: skip Codex + `/issue`; still refresh statistics + manifest `step9a1=true`.
- **`/issue` partial failure**: all-or-nothing sentinel; non-zero; orchestrator stops before ship.
- **Codex down with 2+ items**: file pre-combine batch (degraded combine warning).
- **Security sidecar**: ship stalls pre-PR; `oos file` also fails closed if invoked directly.

## Failure modes

1. **`/issue` batch failure**: `oos file` non-zero; orchestrator stops before ship; no PR with undisclosed accepted OOS.
2. **Codex combine invalid + fallback batch also fails cap/gate**: non-zero; no sentinel.
3. **Run-log/manifest write failure**: non-zero; no durable evidence without manifest stamp.
4. **Security sidecar present**: ship `NEEDS_USER_INPUT` before PR create; operator must clear per SECURITY.md before resume.
