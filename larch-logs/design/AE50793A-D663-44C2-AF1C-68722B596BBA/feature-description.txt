# [BUG] (URGENT) /design: stop orchestrator busy-wait polling during immediate-background waits

## Incident

- Run `1890FD62-0DA8-4259-B652-BE9FFD962A76` (issue #4102, effort max, 5 review rounds, larch 50.0.2, main model claude-sonnet-4-6) cost **$237.94 total, $213.50 main agent**, vs ~$50 typical for /design.
- Orchestrator transcript analysis (transcripts are not committed; numbers preserved here): **1043 of 1496 assistant turns were filesystem polling** of `$DESIGN_TMPDIR` while `design-step3-review.sh` ran as an immediate-background task.
- Dominant shapes: 621 x `ls -la "$DESIGN_TMPDIR" | sort -k9 | tail`, 164 x `ls -la "$DESIGN_TMPDIR"/*-output.txt | awk '$5 > 0' | wc -l`, 85 x vote-output checks, plus one backgrounded `while [ ! -f .step3-review-result.env ]; do sleep 5; done` watcher and six staggered `sleep N && ls` background probes (hand-rolled ScheduleWakeup equivalents, N = 30/45/60/90/120/150).
- Polling turns consumed **359M of 485M cache-read tokens (74%)**: roughly **$110-145** of the main-agent spend at Sonnet 4.6 rates, plus permanent context bloat (each poll result makes every later turn more expensive).
- The orchestrator launched Step 3 once and **never consumed a `<task-notification>`**. Notifications deliver at turn boundaries; the orchestrator never yielded, so it side-channel-read `.step3-review-result.env` and `.step3-round-N.phase` mid-flight instead of the prescribed launch -> notify -> resume protocol.
- The model recited the rule before breaking it: "Waiting for the review panel to complete (task br3jollow). Not polling - the notification will arrive." followed 0.7 s later by the first foreground `ls` poll.

## Root cause (4 strands)

1. **Contradictory instruction (the motive).** `skills/design/SKILL.md`, Verbosity Control section, "Compact reviewer status table" block: "maintain a mental tracker of each agent's status. Print a compact table after EACH status change". After Step 3 moved scout/dispatch/collection/voting inside one opaque background script, the orchestrator receives zero per-reviewer events. The only way to observe a "status change" is to poll the tmpdir. The model obeyed the instruction: it printed 25 boards fed by poll output (e.g. "Reviewers: 4/8 output files have content").
2. **Yield-is-a-halt trap (the mechanism).** The Anti-halt continuation reminder forbids ending the turn on "a Bash result, a status message" and whitelists turn-yield only for the Step 1d.5/1d.7 discussion lanes. The Immediate-background fences say "wait for `<task-notification>`" but never state that ENDING THE TURN is the required wait. Caught between "never halt" and "wait", the model busy-waited turn after turn.
3. **Shape-pinned guardrails (failed defenses).** `skills/shared/orchestrator-never.md` #3 bans re-reading "the task output file" per turn; #4 and the Step 3 fence prose ban a "sleep loop" on `.step3-review-result.env`. The polls used different paths (`plan-review/round-N/`, `*-output.txt`, whole-tmpdir listings) and no sleep, slipping every literal. The one literal violation (the backgrounded while/sleep watcher) had no enforcement.
4. **Advisory-only instrumentation.** `scripts/hook-anti-read-poll.sh` is PostToolUse and matches only `tasks/<id>.output` references with read verbs (cat/tail/head/less/more/sed -n). `ls` of `$DESIGN_TMPDIR` never matches; even on match it merely injects a reminder. The harness launch ack ("To check interim output, use Read on that file path") actively invites interim reads.

## Proposed fix (defense in depth, 4 layers)

**Layer 1: remove the motive.** Rewrite the Compact reviewer status table contract in `skills/design/SKILL.md`: print exactly twice per background wait (once post-launch, all pending; once post-notification with final statuses). Delete "after EACH status change" and "maintain a mental tracker". Have the Step 3 driver/loop write a small per-slot status+elapsed summary artifact (launcher `.meta` sidecars and `record-plan-review-round-timing.sh` already capture the data) that the orchestrator renders once after the notification.

**Layer 2: affirm the yield.** In the Anti-halt continuation reminder and at all four `Immediate-background required` fences (Step 3 launch, Step 3 resume, Final summary block, Step 5c publish): after the "Command running in background" acknowledgment, print the permitted breadcrumb/board line, then END THE TURN with zero further tool calls. State explicitly: yielding on an in-flight immediate-background fence is NOT a halt; it is the only correct wait; the `<task-notification>` is the only resume trigger; ignore the launch ack's "check interim output" suggestion.

**Layer 3: generalize the NEVER.** Rewrite `skills/shared/orchestrator-never.md` #3 (or add #5) intent-based: between a background launch and its `<task-notification>`, the orchestrator makes ZERO progress-observation tool calls of ANY shape. Non-exhaustive shape list: Bash probes (ls/cat/wc/stat/find/head/tail/test/grep) of the session tmpdir or task outputs, Read of those paths, TaskOutput on the running task, backgrounded `sleep N && probe` staggered probes (ScheduleWakeup equivalents), backgrounded watcher loops, Monitor waits. Name the banned intent, cite this incident alongside #3175, add CI pins in the existing `scripts/test-design-structure.sh` style.

**Layer 4: mechanical enforcement (deny, not advise).**

- Wait-marker protocol: wrappers hosting immediate-background fences (`design-step3-review.sh`, `design-step-final-summary.sh`, `design-publish.sh`; /implement equivalents may follow as a second pass) write `$DESIGN_TMPDIR/.bg-wait-active` (writer PID, start epoch, step id) on entry and remove it in an EXIT trap.
- New PreToolUse hook registered in `hooks/hooks.json` for `Bash|Read`: when a live marker exists (writer PID alive, age under the fence timeout) and the tool call is a tmpdir/task-output probe not routed through the `design-run-$PPID.sh` launcher, emit `permissionDecision: deny` with a reason that cites the NEVER rule and instructs: end the turn; wait for `<task-notification>`.
- Safety: fail-open on any hook error; ignore and reap stale markers (dead PID or age over timeout); `LARCH_BG_POLL_GUARD_DISABLE=1` escape hatch; never deny wrapper-routed launcher calls so the pause flow stays live; bash 3.2 compatible per BASH_AUTHORING.md.
- Telemetry: count denials in a `$DESIGN_TMPDIR` sidecar; surface a `Warnings` entry in `execution-issues.md` and a final-summary line ("N blocked polling attempts") so regressions stay visible in committed run logs and `/audit-runs`.

## Acceptance criteria

- With the marker live, any `ls`/`cat`/Read probe of `$DESIGN_TMPDIR` is denied with the educational message; wrapper-routed calls and post-notification reads pass.
- `skills/design/SKILL.md` carries the twice-per-wait status-table cadence and the affirmative END THE TURN directive at all four immediate-background fences; structure tests pin both literals.
- `orchestrator-never.md` covers shape-independent observation, sleep-probe wakeups, and TaskOutput; CI pin updated.
- Run-log surface shows the denial count; clean runs show zero.
- `make lint` and the design structure harnesses pass.
