## Edge cases

- **Result env write fails:** `write_result_env_and_emit` emits stdout first. The block still exits `4`, preserving the stdout fallback path used by `design-step5c.sh`.
- **Stale success result env exists:** exit `4` already forces stdout authority in `design-step5c.sh`, so stale success should not mask the current defect.
- **Empty file exists:** handle it the same as a missing file because `[[ ! -s ... ]]` covers both.
- **Pause requested:** keep current ordering. This plan does not move the pause checkpoint.
- **Fix-and-retry after skipped composition:** recompose `$DESIGN_TMPDIR/composed-plan.md` before retrying. Re-running only `design-step5c.sh` can repeat the same defect.
- **Override after skipped composition:** do not offer Override. If invoked manually, the missing-or-empty file precondition still returns exit `4`, even with `--skip-validate`.
- **Auto-repair after skipped composition:** do not run auto-repair. It can bypass Step 5c item 1 and synthesize or publish the wrong plan surface.
- **`--skip-validate` ordering regression:** the new test must fail if `--skip-validate` is evaluated before the missing-or-empty `composed-plan.md` precondition.
- **`--skip-validate` stale artifacts:** use a fresh tmpdir and fresh stub logs for the missing-composed-plan regression so prior happy-path outputs cannot make absence or no-side-effect assertions unreliable.

## Failure modes

- If `VALIDATE_LOG_FILE` is empty, the shared validator-failure flow has weaker evidence. Set it before calling `write_result_env_and_emit`.
- If `PLAN_WRITE_OK` is left unset, Step 5c parsing can become ambiguous. Set it to `false`.
- If the path still uses `fail`, `design-step5c.sh` will keep treating it as unexpected exit `5` and abort.
- If SKILL.md Fix-and-retry text only re-runs `design-step5c.sh`, the orchestrator can skip Step 5c item 1 again and loop on the same missing-file defect.
- If shared auto-repair runs for the missing-composed-plan diagnostic, it can bypass the required Step 5c item 1 composition contract.
- If Override is offered for the missing-composed-plan diagnostic, it can fail again or imply an unsupported recovery path.
- If tests do not cover `--skip-validate` with missing or empty `composed-plan.md`, a reorder can bypass the recoverable exit `4` path.
- If the `--skip-validate` missing-composed-plan test reuses the happy-path `$D_SKIP` tmpdir, stale `composed-plan.redacted.md`, result env, or call logs can hide the ordering regression or produce misleading failures.
