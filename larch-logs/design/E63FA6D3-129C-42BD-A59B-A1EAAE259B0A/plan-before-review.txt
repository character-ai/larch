## Approach

Publish the durable state marker through one shared branch, PR, and merge sequence. Use it in both default and filing modes. Keep report generation, issue filing, and `write-state` rollback behavior unchanged.

#### Edge cases

- Reject detached HEADs, invalid state paths, branch collisions, malformed PR output, or a missing PR number before attempting a merge.
- Run repository-sensitive Git and PR commands against `ANALYSIS_ROOT`, not the caller’s ambient directory.
- Treat an existing open PR returned by `cli.py pr create` as valid only when its parsed status and identity are complete.
- Do not roll back a committed marker after a PR exists. The PR becomes the durable recovery surface.
- Do not rerun `/issue` when filing succeeded but marker publication needs manual completion.

#### Failure modes

- A branch, commit, push, or PR creation failure stops the workflow and reports the exact stage.
- An admin merge failure does not claim success or discard the PR. It produces a manual merge request.
- Unrelated dirty files remain outside the marker commit. The PR helper’s clean-worktree guard must still pass after the isolated commit.
