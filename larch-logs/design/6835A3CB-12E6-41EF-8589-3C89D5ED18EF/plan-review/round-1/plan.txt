# Implementation Plan — Issue #3619: Conditional spawning of review agents (Part B)

## Goal

Cut wasted review tokens. From round 3 on, do not launch reviewer combos (tool × archetype slot) that produced zero accepted items in their last 2 launched rounds. Round 5 re-probes with the full panel. Applies to `/design` plan review, `/implement` Step 5 code review, and `/review` diff mode.

## Approach

One new shared helper, `scripts/reviewer-prune.sh`, with two subcommands:

- `record` — after a round's tally, append one row per launched slot to a run-stable ledger TSV. Inputs: `--ledger FILE --round N --manifest FILE --classification FILE [--collector-results FILE] [--label-map FILE]`. Ledger columns: `round`, `tool`, `slot`, `label`, `collected`, `accepted_count`.
- `filter` — before a round's launch, rewrite the panel manifest to eligible slots only. Inputs: `--ledger FILE --round N --manifest FILE --out FILE`. Emits KVs: `PRUNE_ACTIVE`, `ELIGIBLE_COUNT`, `PRUNED_COUNT`, `PRUNED_COMBOS` (comma list), `PANEL_PRUNED_EMPTY`.

Combo identity is the manifest pair `tool:slot`. Both dispatchers already build a complete NDJSON slot manifest before launch (`panel-manifest.ndjson` for code review; `plan-review-slots.ndjson` for plan review), so `filter` hooks in at exactly one point per dispatcher: after the manifest is fully built (static + dynamic), before the waterfall launch.

Eligibility rule in `filter`:

- `LARCH_REVIEWER_PRUNE=off` (exact match) → all slots eligible; `PRUNE_ACTIVE=false`.
- Round N ≤ 2 or N ≥ 5 → all eligible (rounds 1-2 baseline; round 5 full re-probe; N > 5 defensive — rounds are hard-capped at 5 after this change).
- Otherwise (N = 3 or 4): take the combo's ledger rows with `collected=true` and `round < N`; dedupe per round keeping max `accepted_count`. Fewer than 2 such rounds → eligible (clean slate). Both of the 2 most recent such rounds have `accepted_count=0` → pruned. Else eligible.
- Missing or unparsable ledger → all eligible plus a warning KV (fail open).

"Accepted" means `voting_result=accepted` rows in the round's findings-classification TSV, including accepted OOS rows (anything that scores +1 in the point competition). A slot's `accepted_count` is the number of accepted rows whose reviewer attribution contains the slot's label. Labels:

- Code review: label = output basename (e.g. `cursor-specialist-security-output.txt`), matching `reviewer_slots` cells after `normalize_reviewer_label` (waterfall phase2/phase3 retries already normalize back to the slot's basename, so attribution follows the slot).
- Plan review: the caller supplies `--label-map` (TSV `slot<TAB>label`) generated with the loop's existing `plan_slot_human_label` (e.g. `cursor-plan-arch` → `Cursor-Arch`), matching `finding_reviewers` cells. No mapping duplication.

`collected=true` requires collector status OK for the slot's output (key `STATUS` or `COLLECTOR_STATUS` in the collector-results records); when no collector file is supplied, fall back to "output file exists and is non-empty". Rows with `collected=false` never count toward the 2-strike window (user decision: combos that never got a chance keep a clean slate).

`record` is called only for settled rounds that produced a final classification TSV (`complete` / zero-findings paths). Rolled-back rounds (`tally-error`, `degraded-empty-collector`), `panel-failed`, and MAV-deferred rounds are not recorded — their absence fails open.

When `filter` leaves zero slots (`PANEL_PRUNED_EMPTY=true`), the round is skipped cleanly (user decision): the dispatcher short-circuits before the waterfall with success KVs, and the caller treats it as a clean zero-findings round — NOT a degraded panel. The round still consumes the round counter (so round 5's full probe stays reachable).

Separately (user decision): hard-cap `/implement` Step 5 rounds at 5 by removing the degraded-round cap inflation (`ROUND_CAP_INFLATED = ROUND_CAP_BASE + DEGRADED_ROUNDS`).

## Files to modify/create

### NEW: `scripts/reviewer-prune.sh`

The shared helper described above. Bash 3.2-safe: `jq` for NDJSON manifests, `awk` for ledger/classification TSV processing; no associative arrays. `set -euo pipefail`. Sources `lib-quiet.sh` and emits machine KVs via `emit_kv`. `record` appends atomically (temp file + `mv` is unnecessary for append; use a single `>>` write of all rows at once) and writes a header line when creating the ledger. `filter` writes the filtered manifest to `--out`, prints one operator-visible stderr line via `larch_err` when it prunes (`→ review prune: round N drops <combos>`), and never edits the input manifest in place.

## Edge cases

- Fewer than 2 launched-and-collected prior rounds (fresh dynamic archetypes, first rounds, outage-skipped slots) → eligible.
- Collector non-OK, waterfall-dropped (`--no-fallback`) slots → `collected=false`; round does not count against the combo.
- MAV-deferred tallies (both skills) and rolled-back /design rounds → no ledger row; fail open.
- Same dynamic archetype re-scouted in a later round → same slot name → history accrues across rounds (intended).
- Both vendors down: code review's 4 Claude-fallback rows keep `cursor:*` keys (attribution already normalizes to the slot basename); /design's combined Claude-generic path bypasses pruning entirely.
- `/review` description mode is single-pass (round 1) → never prunes.
- Duplicate ledger rows for one round (defensive) → dedupe keeping max accepted_count.
- Empty ledger file or header-only → all eligible.

## Failure modes

1. Pruned round misread as degraded → wrong rollbacks/degraded handling. Earliest signal: `DEGRADED_ROUND=true` or round-count rollback on a round-3+ skip. Mitigation: explicit `PANEL_PRUNED_EMPTY` KV, `LOOP_STATUS=complete`, and harness assertions that degraded flags stay false.
2. Label-mapping drift between record and tally attribution → accepted_count always 0 → over-pruning to empty panels by round 4. Earliest signal: ledger rows all zero while `voting-tally.md` shows accepted findings. Mitigation: code style uses raw basenames; design style reuses `plan_slot_human_label` via `--label-map`; harness fixtures copied from real artifacts.
3. Escape hatch ignored at one call site → pruning impossible to disable in the field. Earliest signal: `PRUNE_ACTIVE=true` with `LARCH_REVIEWER_PRUNE=off` in any KV stream. Mitigation: the env check lives in exactly one place (`reviewer-prune.sh filter`); harness case pins it.

## Acceptance

- Rounds 1-2: byte-identical panel behavior with an empty/missing ledger.
- Round 3-4: a combo with zero accepted items in its last 2 launched-and-collected rounds is not launched; combos with <2 rounds of history launch.
- Round 5: full panel always.
- All-pruned round: nothing spawns; clean convergence statuses (`REVIEW_CORE_STATUS=ok` / `LOOP_STATUS=complete`); round counter consumed; no degraded flags.
- `LARCH_REVIEWER_PRUNE=off`: today's behavior everywhere.
- `/implement` Step 5 cap is a fixed 5 (no degraded inflation); resume/mav-resume math uses the base cap.
- New + updated harnesses green; `make lint` green.
