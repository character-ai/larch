#### UPDATED: `scripts/check-contains-pins.sh`
- **Escape-aware closing-quote scan for double-quoted literals.** The current code uses `literal_end = index(rest, quote)` to find the closing quote, which truncates literals containing escaped `\"`. Replace the double-quoted-literal branch in `parse_contains` with a char-by-char scanner that walks `rest` one character at a time, tracking `\\` escapes; the literal ends at the first UNESCAPED `"`. Single-quoted-literal scanning stays as-is (no escapes inside single quotes in bash).
- **Bare-dollar detection on ORIGINAL source.** While the char scanner walks the double-quoted source, set a flag `bare_dollar` when a `$` is encountered that is NOT preceded by `\`. The flag captures bash semantics: `\$` is a literal `$` (no interpolation), bare `$` is a real variable interpolation. After capturing the closing-quote position, apply the unescape pass (`\$`→`$`, `\"`→`"`, `\\`→`\`) only to the body slice between the opening `"$VAR"` argument and the closing unescaped `"`.
- **CHECK vs SKIP decision.** If `bare_dollar` is set on the ORIGINAL source, emit `SKIP` (true variable interpolation cannot be verified verbatim). Otherwise emit `CHECK` with the UNESCAPED literal as the payload. Literals containing only `\$` escapes are CHECKable because bash unescapes them to literal `$` at runtime — exactly what the target file is expected to contain.
- **Trailing backslash handling.** If the char scanner consumes a backslash at the end of input without a following char, treat it as unterminated → emit `SKIP`.
- **Non-recognized escape sequences.** A `\` followed by any char OTHER than `$" \` leaves both chars in the literal (matches bash double-quote semantics: `\n` inside double quotes is literally `\` + `n`).
- Bash 3.2 portability preserved (awk implementation only; no Bash arrays for the new logic).

### Approach

**A1** — The awk parser's `parse_contains` function gets two narrow changes for double-quoted literals: (1) replace `index(rest, quote)` with a char-by-char scanner that respects `\\` escapes, and (2) detect bare unescaped `$` on the ORIGINAL source (before unescape). Bash double-quote semantics dictate the escape rules: `\$`, `\"`, `\\` are recognized; everything else preserves the backslash. The CHECK/SKIP decision uses the original-source bare-`$` flag, not a post-unescape rescan.

**A2** — `relevant-checks.sh` keeps `test-design-structure` design-scoped. Two new case blocks: one for verifier/harness/canonical-pin-source edits (routes to `test-check-contains-pins`), and one broader for cross-skill `skills/*/SKILL.md|skills/*/references/*.md` (routes to `test-check-contains-pins` only). The verifier's `--changed-files` scoping inside the script handles work expansion.

Documented as an informational smoke check; `make lint-bash32` + Section 4's forbidden-token assertions remain the authoritative portability gate (per Round 1 Decision 2 and FINDING_11's framing).

**A4** — Switch sketch variant from `grep -Foc '<READABILITY_STYLE>'` (counts substring occurrences) to `grep -Fc "$sketch_style_line"` (counts matching LINES; `sketch_style_line='Style requirements: <READABILITY_STYLE>.'` without backticks). Each sketch bullet contains the substring exactly once; count stays 4 on the real repo. Extra mentions of `<READABILITY_STYLE>` without the `Style requirements:` prefix no longer satisfy.

**B5** — Per-step placement is enforced for `orchestrator-inline` rows with non-empty `step_markers`. Implementation is awk-based: for each step ID, find the `<!-- step:<id>` marker line, treat lines between that marker and the next `<!-- step:` line (or EOF) as the step body, count `orchestrator_style_re` matches inside. Each named step requires ≥1 directive.

**B6** — Shared TSV at `scripts/lint-readability-preamble.tsv` (root `scripts/`, sibling to its consumers). Sibling `.md` documents the canonical reader contract. The test harness derives fixture paths and expected counts from the parsed manifest, proving consumption.

### Edge cases

- **Empty `step_markers` field**: skipped; only the file-level count is enforced (matches all rows except SKILL.md).
- **TSV comment lines** (`#` prefix) and **blank lines**: skipped via the awk filter `NF >= 1 && $1 !~ /^#/ && $0 != ""`.
- **TSV last line without trailing newline**: awk handles it naturally.
- **A1 trailing backslash** (`\` at end of literal): emits SKIP (cannot be unambiguously unescaped).
- **A1 `\` followed by char other than `$" \``**: leave as-is (literal backslash + char). Matches bash double-quote semantics: `\n` is two chars `\` + `n`.
- **A1 escaped quote at end of literal** (`"foo \""`): the char scanner ends at the SECOND `"` (the unescaped one). The captured body is `foo \"`. Unescape produces `foo "`. CHECK against target.
- **A1 mixed escaped + bare `$`**: the original-source scan sets `bare_dollar=1`; emits SKIP. Covered by the new `escape-with-bare-dollar` fixture.
- **B5 step-marker not present in file**: emit a clear error `<file>: step "<id>" referenced in TSV but <!-- step:<id> marker not found`. Surfaces stale TSV rows when a step is renamed/removed.
- **B5 step-marker present but next-marker missing** (last step in file): treat EOF as the closing bound. Awk's natural END handler covers this.
- **B6 awk-based TSV reader under set -u**: awk is its own process; the outer Bash `set -u` does not interact with awk variables. Empty middle fields from awk are real empty strings; `$5` is `""` not unset.
- **B6 TSV reader applied to malformed line**: invalid `expected_count` triggers exit 2 before consumer logic runs.
- **A4 sketch line containing the substring twice**: counts as 1 line (`-Fc` semantics). Today no sketch line has it twice; if a future sketch does, the count drops by 1 and the lint warns — intentional.
- **F8 step bodies in fixtures**: the `write_skill_md_with_steps` helper places one or more directives between each `<!-- step:N -->` and the next; the placement check sees real step bodies.

### Failure modes

The three most likely architectural/systemic failure paths and their mitigations:

1. **A1 escape-aware scanner regressing the canonical no-`$` double-quoted literal path**: the new char scanner replaces a working `index(rest, quote)` call. A bug in the new scanner (e.g., wrong escape state transition) could silently truncate literals that were parsed correctly before. **Earliest signal**: existing Section 1 happy-path tests for double-quoted literals (`double-quoted`, `double-quoted-backticks`) fail. **Mitigation**: existing Section 1 fixtures must continue to pass post-change; add explicit `escape-quote-inside-literal` to Section 5 that exercises the new scanner against the in-the-middle escape case.

2. **B5 step-marker proximity false positives during SKILL.md refactors**: a future refactor that renames step IDs would leave the manifest's `step_markers` stale, and lint would fail with `step "<id>": ... marker not found`. **Earliest signal**: pre-commit lint failure naming the missing step ID and TSV path. **Mitigation**: the error message names the exact step ID and TSV row; `scripts/lint-readability-preamble.tsv.md` documents the edit-in-sync rule with SKILL.md. The error fails closed — operators can't accidentally ship a stale manifest.

3. **B6 TSV reader divergence between lint and test**: if lint and test implement the awk parser slightly differently (e.g., different `NF` filter, different comment-skip rule), the test harness can pass on a TSV that lint rejects (or vice versa). **Earliest signal**: the extended FINDING_12 case `tsv-extended-source-of-truth` fails because the synthetic extra row is enumerated by one consumer but not the other. **Mitigation**: identical awk filter (`NF >= 1 && $1 !~ /^#/ && $0 != ""`) and identical field extraction; `scripts/lint-readability-preamble.tsv.md` documents the canonical contract; the test harness explicitly asserts row-count match between its enumeration and lint's iteration.
