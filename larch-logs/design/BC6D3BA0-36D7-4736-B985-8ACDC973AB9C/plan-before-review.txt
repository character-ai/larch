## Approach

Add a coordinator-only runtime stage after the existing static report. Select the newest eligible fix commits by `fix_time`, up to `--runtime-max`.

For each selected fix:

- Discover added or modified `python/tests/` files from the fix commit.
- Run the discovered files together with `python3 -m pytest`, using a timeout and option-safe argv.
- Resolve touched orchestration paths against a declarative prefix-to-make-target map.
- Run each deduplicated mapped target with `make` and a timeout.
- Persist bounded pass, fail, timeout, or absent evidence in `runtime-results.jsonl`.

Bind every result to the manifest issue, cache key, and fix SHA. The report must reject or ignore stale rows whose identity no longer matches the current bundle.

A passing runtime execution promotes the existing static verdict to tier `RUNTIME`. Any test or harness failure produces verdict `SUSPECT` with a bounded, single-line output tail. Absence does not crash the run or claim runtime verification. Unmapped orchestration zones remain at their static tier and appear in a harness coverage-gap section. A fix may retain a coverage-gap annotation even when another runtime source passes.

After runtime verification, rerun the report command so the final rendered report and snapshot include runtime evidence. `--runtime-max 0` disables the stage.

## Edge cases

- A fix has no resolved SHA or no runtime-relevant files.
- A discovered test was later deleted from `main`.
- Several touched paths resolve to the same make target.
- A fix touches both mapped and unmapped orchestration zones.
- Runtime output contains newlines, pipes, control characters, or excessive text.
- A prior runtime artifact belongs to another manifest or an older fix SHA.
- The budget exceeds eligible fixes or is zero.

## Failure modes

- Git discovery or runtime artifact corruption fails loudly because the coordinator cannot trust the evidence.
- Pytest failures, harness failures, missing tests, and timeouts become recorded evidence rather than coordinator errors.
- A report never grants `RUNTIME` from absent checks, stale rows, or a skipped fix.
- Runtime verification performs no GitHub or vendor-CLI calls.
