Prefer importing and reusing `progress_report._read_env_file` if that avoids drift without widening cleanup scope; otherwise duplicate the same algorithm locally. Do not reuse implement-pointer bare-line parsing (`line.startswith("IMPLEMENT_TMPDIR=")`).

### Edge cases

- **Early design run:** no timing-ledger row exists yet. `_run_activity_mtime()` falls back to pointer mtime.
- **Active design Step 3:** newest activity may be a legacy `design/round` row, not a v1 row. Ranking must use that row.
- **Dangling design symlink:** cleanup still removes it.
- **Resolved target with missing tmpdir:** cleanup removes only the design symlink after reading `export DESIGN_TMPDIR=...` / `export SESSION_TMPDIR=...`.
- **`SESSION_TMPDIR` only:** progress and cleanup both honor it.
- **Malformed ledger rows:** existing parsing ignores them and falls back when no valid activity exists.
- **Quoted env paths:** cleanup must accept `export DESIGN_TMPDIR='...'` the same way progress discovery does.

### Failure modes

- If legacy round parsing is too broad, unrelated non-v1 ledger lines could skew ranking.
  - Restrict to `cols[2] == "design"` and `cols[3] == "round"` only.
- If cleanup still uses bare-line env parsing, live design pointers with `export`-prefixed env files are misread as missing tmpdir and unlinked while `/progress` still works.
  - Require `_read_design_tmpdir` to mirror `_read_env_file` rules in the Files section, not only as a failure-mode note.
- If cleanup removes non-symlink files matching `current-design-env-*.sh`, it may exceed scope.
  - Keep the design reaper symlink-only.
- If design ranking tests use only v1 mark or v1 round rows, they may not prove #4954 parity against production Step 3 activity.
  - Use the legacy `record_plan_review_round_timing` row shape in the active-run regression.
