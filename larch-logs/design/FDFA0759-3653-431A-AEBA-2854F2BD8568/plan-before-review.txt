## Edge cases

- `gh repo view` can fail while the `origin` remote still identifies a valid GitHub repository. In-scope callers must now accept that canonical fallback.
- `gh.resolve_repo` may return `None` for missing, malformed, or non-GitHub remotes. Each caller must retain its current empty-result or exception contract.
- Explicit repository arguments must continue to outrank ambient discovery.
- Callers that validate explicit slugs must not weaken that validation.
- Repository resolution with a caller-provided `cwd` must pass that directory through unchanged.
- Offline analysis must continue when repository enrichment is optional.
- Removing `_resolve_repo_for_fetch` must not break monkeypatch seams or external imports. Keep it if a targeted search finds a live consumer.

## Failure modes

- A caller may accidentally expose `None` where its public contract expects `""`.
- Replacing `subprocess.run` may bypass an existing test double and cause tests to invoke the real `gh` executable.
- Adding Git remote fallback may change a former failure into success. Tests must distinguish this intended canonical behavior from error-contract regressions.
- Removing a wrapper that is patched by tests or imported elsewhere may break a stable seam. Search all repository references before deletion.
- Unused imports or suppressions may remain after deleting direct subprocess and JSON parsing code.
