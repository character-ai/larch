# /design: script-own sentinel, phase, and marker writes

**Problem.** Raw `: >`, `mkdir -p`, `rm`, and KV-env writes are scattered across `skills/design/SKILL.md`, `references/approval-gates.md`, `references/discussion-rounds.md`, and `references/decompose-panel.md`: `.step3-reentry` (Gate A Ready-for-review, Gate C Re-run review panel), `.step3-round-N.phase` values, `.postplan-operator-continue-N`, `.gate-b-per-round-approval-round-N.env` (`FINDINGS_FILE=` KV), `.completed/step-2b` and `.completed/step-2b.5` on Override and Split returns, and the `.step3-entry-plan-printed` clear. Prompt-side state-file composition is the error class /implement NEVER #11 and #12 exist to prevent.

**Proposal.**

- Prefer riding an existing wrapper call over adding one: `design-step3-entry.sh --reentry` writes `.step3-reentry` itself; the Step 3 resume fence accepts `--findings-file` and `--phase` so the per-round-approval env file and phase writes ride the resume call; postplan Override and Split returns get their completion markers from the postplan wrapper rc contract.
- Remaining standalone sites route through `design-step3-state.sh` modes (it already owns `--direct-review-entry`, `--gate-b-bypass`, `--auto-continuation-entry`).
- Update the references to name the wrapper flags instead of raw write commands.

**Acceptance.**

- No raw marker, phase, or env-write instruction remains in /design prose; every write has a script owner.
- Pause/resume semantics for each sentinel unchanged; `test-design-step3-state.sh` and the pause-resume harnesses extended.
