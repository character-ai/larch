### FINDING_1: Preserve render helper subprocess and terminal-format behavior
- **Reviewer(s)**: Cursor-Arch
- **Severity**: important
- **Concern**: The shared `_call_render_phase_detail_script` extraction may omit existing subprocess safety and Markdown stripping behavior. If it drops the 6s timeout, non-checking capture, failure fallback, or `_strip_md_for_terminal()`, the hook can exceed the `UserPromptSubmit` budget or emit raw Markdown table syntax.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Specify in the plan that `_call_render_phase_detail_script` is a byte-for-behavior extraction of current `_render_review_detail` tail: same 6s timeout, non-checking capture, empty string on failure, and markdown stripping before return; add one regression asserting the helper still strips headings or preserves the existing strip test via the refactor.

### FINDING_2: Root-live freshness rejects the current plan-review manifest
- **Reviewer(s)**: Codex-Arch, Codex-Pragmatic, Codex-dyn-label-contract, Codex-dyn-freshness-floor
- **Severity**: important
- **Concern**: The planned root-live freshness logic compares `plan-review-slots.ndjson` against mutable mtimes such as the round directory or late-written `round-start-s` file. Current dispatch can write the root manifest before creating or touching round-local files. That can reject the live active-round manifest and fall back to generic Step 3 progress or wrong reviewer counts.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Arch: Use the parsed round-start-s epoch content, not the marker file mtime, as the root-live manifest and output freshness floor; keep step_start and round-dir fallback for missing or invalid markers
  - From Codex-Pragmatic: Base freshness on stable round-start epoch data, such as round-start-s contents or the Step 3 timing mark, not directory or marker file mtime. Add a regression where a current root manifest is older than a later round-local write or late round-start-s file but current reviewer outputs still render.
  - From Codex-dyn-label-contract: Revise the freshness rule and regression fixture to model current order: accept a root manifest newer than the Step 3 mark when the round dir has current dispatch evidence such as prune-decision.env, or otherwise do not compare root manifest mtime against round directory mtime for that live path
  - From Codex-dyn-freshness-floor: Do not use whole round directory mtime as the no-round-start freshness barrier after child sidecars can be created. Use a stable current-round marker, or accept root-live by Step 3 mark plus a dispatch marker that proves the current round has rewritten the manifest. Update regression 8 to model a child file created after the manifest.

### FINDING_3: Planned freshness-floor test fixture cannot reach its assertion
- **Reviewer(s)**: Cursor-dyn-freshness-floor
- **Severity**: important
- **Concern**: The proposed Test 18 fixture sets the root manifest mtime older than `round-start-s` mtime while the planned acceptance rule requires the manifest to be at least as new as that marker. The manifest is rejected before the output freshness-floor behavior is exercised, so the test can fall through to generic progress instead of proving returned-reviewer counting.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-dyn-freshness-floor: Raise root manifest mtime to at least `300` (matching or exceeding `round-start-s`), or drop `round-start-s` from this case and drive the floor via `step_start_s` in a dedicated `_design_output_freshness_floor` unit test. Keep the mtime-`250` / mtime-`400` output pair and the root-live `source_kind`.

### FINDING_4: Design current-round selection treats settled rounds as active
- **Reviewer(s)**: Cursor-Innovation
- **Severity**: important
- **Concern**: Reusing `_current_round_dir` still keys settlement on `review-and-fix.env`, which design does not write. After a plan-review round finishes and `round-summary.env` exists, the renderer can keep reporting that stale round as in progress until the next round starts.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: Add a design-specific current-round selector: prefer review-round-count.txt when readable, else the highest round-N dir without round-summary.env; return empty when the selected round already has round-summary.env and no newer active round exists

### FINDING_5: Per-round elapsed time falls back to phase-wide Step 3 timing
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: When `round-start-s` is absent, planned design elapsed logic falls back to the Step 3 phase start. Normal multi-round runs may not persist `round-start-s`, so round 2 and later can show the whole phase duration beside the current round.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: In _design_elapsed, prefer round-start-s, else int(round_dir.stat().st_mtime); use step_start_s only if the round dir is missing. Add a round-2 regression where step_start_s is much older than round_dir mtime.
