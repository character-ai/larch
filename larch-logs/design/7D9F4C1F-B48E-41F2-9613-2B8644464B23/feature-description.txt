# md-to-py-IX: compress skill description frontmatter (Tier-1) + length-cap lint

Tighten the **Tier-1 autoload** that rounds V–VIII never touched: the skill `description:` fields render into the skill registry **every conversation**, regardless of which skill runs.

#### Goal

- Compress the 28 skill `description:` fields (~6,348 chars, roughly 1,587 tokens, paid every conversation). The 8 longest are 200–250 chars (`fluff-analysis` 249, `bug` 243, `set-up-forked-open-source-repo` 237, `issue` 224, `design` 219, `voter-calibration` 215, `alias` 214, `gc-run-logs` 203).
- Add a `description:` **length-cap lint** (for example 200 chars) to hold the gain.

#### Hard constraint

Each `description:` MUST keep its trigger clause. `agent-lint` `S017/desc-no-trigger` requires a `Use when …` / `Trigger when …` form. Compression is surgical rewording, not blunt truncation, and the cap lint must not conflict with S017.

#### Scope

`description:` fields in `skills/*/SKILL.md` and dev-only `.claude/skills/*/SKILL.md`; the new cap lint.

#### Out of scope

- The `@`-import chain prose (sibling child A2).
- `SKILL.md` bodies (children B1/B2).

Part of the md-to-py orchestrator-slimming program (round V #5278, VI #5409, VII #5569, VIII #5696). Round IX pivots from md-to-py migration and fold/relocate to Tier-1 autoload + in-place prose density, fronted by a CI closure-size ratchet. Designed independently.
