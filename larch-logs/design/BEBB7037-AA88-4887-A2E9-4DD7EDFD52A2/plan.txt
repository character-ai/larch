## Plan

PATCH tier: port the run-log B3 shell surface into Python, preserve the existing wire contracts, cut over every direct/runtime call site, relocate contract docs, then delete retired scripts and harnesses.

### Approach

Python receives the full committed-run-log surface with parity-first behavior:

- `python/run_logs.py` absorbs: `larch-log.sh`, `lib-larch-log.sh`, `larch-log-batches.sh`, `larch-log-flush.sh`, `refresh-run-logs.sh`, `capture-session-transcript.sh`, `verify-run-log-completeness.sh`, `append-tool-failure.sh`, and `append-execution-issue.sh`.
- `python/redact.py` absorbs CLI cutover for: `redact-secrets.sh`, `redact-tmpdir-paths.sh`, `scrub-log-secrets.sh`, `scrub-submodule-paths.sh`.
- `python/verify_skill.py` absorbs: `verify-skill-called.sh` and `lib-count-commits.sh`.

Register 19 CLI verbs:

- `run-log`: `init`, `write`, `write-round`, `append`, `exists`, `commit`, `manifest`, `flush`, `refresh`, `capture-transcript`, `verify-completeness`, `append-failure`, `append-entry`, `publish-breadcrumbs`.
- `redact`: `secrets`, `tmpdir-paths`, `scrub-log-secrets`, `scrub-submodule-paths`.
- `verify`: `skill-called`.

Key invariants:

- Preserve existing `larch-log.sh` success stdout envelope for run-log lifecycle verbs: `LOG_WRITTEN`, `LOG_PATH`, `BYTES`, `SHA256`, `COMMIT_SHA`, `UNCHANGED`; add only compatible extra keys such as `SECRET_SCRUB_VIOLATIONS` on commit paths only, not flush.
- Preserve existing `larch-log.sh` failure envelope where it exists: `LOG_WRITTEN=false`, empty `LOG_PATH`, `SHA256`, and `COMMIT_SHA`, `BYTES=0`, `UNCHANGED=false`, `ERROR=<message>`, and current exit tiers 1/2/3.
- Preserve existing stderr-only refusal paths for post-merge and default-branch commit guards. Do not convert those refusals into a stdout envelope unless the current script already does.
- Preserve `exists` probe semantics: after successful argv, log-root, slug, and batch validation, exit 0 and emit the existing envelope with `LOG_WRITTEN=false`; set `UNCHANGED=true` when the batch path exists and `UNCHANGED=false` when absent. Validation and usage failures use `larch_log_fail` exit 1/2/3, not exit 0.
- Preserve `append-execution-issue.sh` as a first-class contract via `run-log append-entry`, not folded into tool-failure-only logic.
- Preserve `append-tool-failure.sh` behavior via `run-log append-failure`, including optional metadata flags.
- Expose breadcrumb staging as a non-committing `run-log publish-breadcrumbs` surface; `design-log-publish.sh` must call it instead of `run-log commit`. Design publish keeps its custom commit flow.
- Resolve commit target repo from the caller/consumer worktree with `git -C <invocation cwd> rev-parse --show-toplevel`, including subdirectory cwd. Fail only when cwd is outside a git worktree.
- Replace all internal Python commit paths that still target the plugin checkout with the same consumer-root resolver.
- Preserve volatile-only refresh detection in `_commit_run`: port `_VOLATILE_REFRESH_BASENAMES`, volatile path detection/cleanup, and the internal `larch-log-volatile-only` signal; map `flush_logs_pre` volatile-only skips to `config.REFRESH_SKIP_VOLATILE_ONLY`.
- Route all manifest reads/writes through schema v2 helpers shared with `larch_log_manifest_main`; do not write legacy v1 `Manifest` shapes on recovery or internal update paths.
- Keep `flush_logs_pre` and `flush_logs_post` separate. Only pre-flush may commit. Post-flush remains post-merge tmpdir-only and must not call `run-log refresh` or `_commit_run`.
- Keep `scripts/run-log-terminal-outcomes.inc.bash` as a surviving sourced include for bash consumers; duplicate/import the same constants in Python completeness logic and keep the two in sync.
- Use existing `scripts/render-session-transcript.py` for transcript rendering; do not reference a nonexistent `.sh` renderer.
- Avoid `redact` ↔ `run_logs` circular imports: `redact.py` owns scrub-log directory walking; `run_logs.py` calls into `redact`, never the reverse.
- Delete retired helpers only after a grep-driven stale-reference gate proves all runtime, config, policy, and prose references are cut over. Keep `make lint-retired-scripts` path-precise per `docs/linting.md`; run a migration-local bare-basename sweep separately.

### NEW: `python/verify_skill.py`

Implement `verify skill-called` with parity modes:

- `--sentinel-file P`:
  - missing path → `VERIFIED=false REASON=missing_path`
  - non-regular path → `VERIFIED=false REASON=not_regular_file`
  - regular but empty file → `VERIFIED=false REASON=empty_file`
  - regular non-empty file → `VERIFIED=true REASON=ok`
- `--stdout-line RE --stdout-file P`:
  - reject empty regex before file I/O
  - missing/non-regular stdout file → `VERIFIED=false REASON=missing_stdout_file`
  - preserve `LC_ALL=C grep -E -q -- "$RE" "$P"` semantics, either by subprocess or an equivalent POSIX ERE path
  - handle leading-dash patterns safely
  - grep exit 0 → `VERIFIED=true REASON=ok`
  - grep exit 1 → `VERIFIED=false REASON=no_match`
  - grep exit 2 or malformed regex: exit 1, stderr diagnostic only, emit no `VERIFIED=` / `REASON=` envelope
- `--commit-delta N --before-count N`:
  - use existing Python git count-commits path
  - preserve exact delta equality semantics, not threshold semantics
  - delta mismatch → `VERIFIED=false REASON=commit_delta_mismatch`
  - preserve `missing_main_ref` / `git_error` fail-closed behavior as exit-0 false results

Emit `VERIFIED=true|false`, `REASON=<token>` on normal pass/fail paths; exit 0 for pass/fail and exit 1 for argument/internal faults.
