## Agreement (overwhelming majority)

Both sketches converge on the same high-level shape:

1. **A new helper script** is introduced for failed-job extraction. Cursor proposes `scripts/jobs-ci-fix-dispatch.sh`; Codex proposes `scripts/ci-failed-jobs.sh`. Both keep this orthogonal to `gh-run-logs.sh` (Cursor mentions an optional extension; Codex keeps it strictly separate — the synthesis picks the separate-helper form because gh-run-logs.sh has a stable, single-responsibility contract that is widely consumed and should not be widened just for this feature).
2. **Failed-job extraction** uses `gh run view <RUN_ID> --repo <OWNER/REPO> --json jobs` and emits normalized job names plus a class (`fixable` / `no-local-equivalent`). `gh run view --help` confirms `jobs` is a valid JSON field (Codex spot-checked this).
3. **Mapping table** keys on the GitHub Actions job name and maps to one local command per job. Coverage: `lint`, `lint-mermaid`, `shellcheck`, `test-harnesses`, `agent-lint`, `agnix`, `smoke-dialectic`, `agent-sync`. `gitleaks`, `trufflehog`, and runner-env-specific failures are tagged `no-local-equivalent`.
4. **Per-job inner loop**: for each fixable failed job — run mapped local command; on non-zero, dispatch the existing 3-tier (Cursor/Codex/Claude) waterfall with the captured local log as `--failure-log`; re-run only that job's command; repeat up to **3 inner attempts** mirroring the existing `_max_fix=3` outer cap shape.
5. **Push gate**: re-push only when every fixable failed job passes locally. Outer `_max_fix=3` cap in `run_evaluate_failure` continues to bound the total invocations.
6. **Bail-on-unfixable**: jobs in the `no-local-equivalent` class OR jobs whose per-job inner loop exhausts the cap accumulate into an unfixable set. After processing every fixable job, if the set is non-empty, `state_set_many BAIL_REASON "ci-local-unfixable: <comma-list>"` and exit 3 (this matches the existing `BAIL_REASON` envelope pattern and stays compatible with `needs_user_bail_reason` triage in ship-pr.sh).
7. **No new launchers, no new sub-skill, no top-level orchestration script** — strictly extend `scripts/ship-pr.sh` plus the small new helper and its mandatory sibling .md + regression harness. The launch-{cursor,codex,claude}-ci.sh families are reused unchanged via the existing `run_ci_fix_vendor` path.

## Divergence (contested decisions surfaced for dialectic)

See `contested-decisions.md`. The five contested decisions worth a dialectic pass are:
- **D1 — Fix-dispatch path**: reuse `run_ci_fix_vendor` waterfall directly vs. wrap `lint-fix-loop.sh` with a widened `--site` enum.
- **D2 — Helper-refactor scope**: factor a reusable `run_captured_cmd_then_fix_loop` helper vs. inline the new per-job loop alongside the existing `run_checks_with_lint_fix_loop`.
- **D3 — Matrix shard handling**: normalize shard suffixes (`test-harnesses (7)` → `make test-harnesses-7`) vs. always run the full local matrix on any shard failure.
- **D4 — Mapping-table drift detection**: structural test that cross-validates the mapping against `ci.yaml` job names vs. documented best-effort sync.
- **D5 — Failed-job extraction location**: separate sibling script (`scripts/ci-failed-jobs.sh`) vs. extending `scripts/gh-run-logs.sh` to emit `FAILED_JOBS=…` alongside the log excerpt.

## Integration choices being incorporated into the plan
- New script name: `scripts/ci-failed-jobs.sh` (Codex's name; clearer single responsibility than Cursor's `jobs-ci-fix-dispatch.sh`).
- Sibling docs: `scripts/ci-failed-jobs.md` (mandatory per script-md-siblings.md) + extend `scripts/ship-pr.md` to document the new CI-failure recovery contract (Codex's stronger position).
- Regression harness: `scripts/test-ci-failed-jobs.sh` exercising the parser, mapping lookup, error paths, and unfixable-set classification.
- Wiring point inside `run_evaluate_failure`: after `gh-run-logs.sh` returns rc=0 (skip on rc=3 in-progress as today), before the existing `run_ci_fix_vendor` call. The new helper produces a `$IMPLEMENT_TMPDIR/ci-failed-jobs-<phase>.tsv`-style artifact consumed by the next phase.
- Per-job inner loop and unfixable-set assembly live in `ship-pr.sh` (new functions, e.g., `run_per_job_local_fix_loop` and `assemble_unfixable_bail`), not in the helper — the helper is strictly the parse-and-map primitive.

## Resolved-by-synthesis decisions (NOT contested; one sketch raised them and the other did not disagree)

These three concerns were raised by exactly one of the two sketches and absorbed into the synthesis without disagreement. They are NOT debated in Step 2a.5; they are recorded here for plan traceability.

### Resolved-1: Matrix shard handling (raised by Codex only)
Normalize matrix shard suffixes in the helper parser. Map `test-harnesses (N)` → `make test-harnesses-N` when the per-shard Make target exists; otherwise collapse to `make test-harnesses`. `test-harnesses` is the only matrix job in `.github/workflows/ci.yaml`. Cursor's fallback did not raise matrix handling; Codex's mention sets the bar.

### Resolved-2: Mapping-table drift detection vs ci.yaml (raised by Cursor's Claude fallback only)
Add a structural test that grep-extracts job names from `.github/workflows/ci.yaml` and cross-validates against the mapping table in `scripts/ci-failed-jobs.sh`. Drift between ci.yaml and the mapping table is otherwise silent (degraded recovery). Codex did not raise this; Cursor's fallback's mention sets the bar.

### Resolved-3: Failed-job extraction location (raised by both, very weak Cursor pushback)
Use a separate sibling script `scripts/ci-failed-jobs.sh`. `scripts/gh-run-logs.sh` stays untouched. Cursor's fallback only "optionally" suggested extending gh-run-logs.sh; Codex explicitly kept them separate. Both effectively agree on the separate-helper direction.
