1. **[security]** `scripts/ci-failed-jobs.sh` (planned), `scripts/ship-pr.sh` (planned TSV consumer): Tab-separated rows with unescaped `JOB_NAME`/`SHARD`/`LOCAL_CMD` let a single logical field split into multiple columns under `IFS=$'\t' read`, mis-binding `CLASS` to `LOCAL_CMD`. Suggested revision: forbid or escape `\t`/`\n` in emitted fields (or switch off TSV), and add `test-ci-failed-jobs.sh` coverage for an embedded tab in `.name`.

2. **[security]** `scripts/ship-pr.sh` (planned `run_per_job_local_fix_loop`): The plan’s `eval "$LOCAL_CMD"` makes any future data/plumbing bug a shell-injection hazard; the `case` catch-all alone cannot compensate once a row is misclassified `fixable`. Suggested revision: replace `eval` with structured dispatch (`make …` only after validating numeric shard, fixed literals per mapping arm).

3. **[correctness]** `scripts/ci-failed-jobs.sh` (planned shard normalization): Parenthesized suffix handling is illustrated but not constrained to a digit-only matrix idiom, so adversarial or malformed names are not explicitly rejected before building `make test-harnesses-${SHARD}`. Suggested revision: require `^[0-9]+$` for shard capture and fall back to `no-local-equivalent` or full-suite fallback only on valid parses.

4. **[correctness]** `scripts/ci-failed-jobs.sh` (planned jq): Filtering strictly `conclusion=="failure"` can omit other failed outcomes GitHub reports separately (notably `timed_out`). Suggested revision: expand the `select` or document and test the intentional omission and downstream `run_ci_fix_vendor` coverage.

5. **[risk-integration]** `scripts/ci-failed-jobs.sh` (planned TSV schema): The plan does not pin whether `LOCAL_CMD` for `no-local-equivalent` rows is always empty/non-executable, which matters if `CLASS` parsing drifts. Suggested revision: specify empty `LOCAL_CMD` for non-fixable rows and assert it in the offline harness.

**Catchall note (plan vs. exploit path):** The written plan’s `case` default to `no-local-equivalent` does ensure unknown **base** job names are not mapped to a fixable `make …` command in the intended design, but that property alone does not prove no string reaches `LOCAL_CMD` or `eval`—TSV integrity, shard validation, and avoiding `eval` are the binding controls; the plan under-specifies the first three relative to the proposed `eval` site.

[OUT_OF_SCOPE] **latent** `scripts/ci-failed-jobs.sh` (planned gh JSON path): Compromised or replaced `gh` binaries returning synthetic JSON are out of scope for this plan review, but any parser that `eval`s derived strings would amplify such a compromise; same file region as the planned `gh run view … --json jobs` integration (plan.txt gh invocation lines).
