1. **correctness** — [`plan.txt`](file:///Users/zhupanov/.cache/larch/sessions/claude-design-larch9-LWwpEQ/plan.txt) change 4 (lines 82–83) adds `ci-failed-jobs.sh` immediately after `gh-run-logs.sh` but does not require a capture path separate from `gh_logs_capture`. Reusing the same `fail_file` with a truncating `>` would wipe the log that [`scripts/ship-pr.sh`](scripts/ship-pr.sh) later passes to `run_ci_fix_vendor` as `gh_logs_capture` (assignment at 1533; consumer at 1358–1360). Suggested revision: require a disjoint sink (or `$(...)` so `gh_logs_capture` is never overwritten) and state that invariant explicitly in the plan and `ship-pr.md` wiring.

2. **correctness** — The plan says to emit and parse `FAILED_JOBS_COUNT` via FD-3 / `emit_kv` ([`plan.txt`](file:///Users/zhupanov/.cache/larch/sessions/claude-design-larch9-LWwpEQ/plan.txt) lines 38–42, 82–83) without binding that to one of the two valid caller contracts implied by [`scripts/lib-quiet.sh`](scripts/lib-quiet.sh) lines 70–75 and 105–111. After `larch_quiet_init`, contract lines go to FD 3, which is a dup of whatever FD 1 was **before** the quiet redirect; mixing a `$(...)` capture with an extra child-level `>` on stdout before init yields an empty substitution buffer and a false zero or empty count, skipping `run_per_job_local_fix_loop` when it should run. Suggested revision: mandate either the [`scripts/ship-pr.sh`](scripts/ship-pr.sh) `ci-rerun-failed` pattern (1500: `rerun_out=$(... 2>"$fail_file")` + `kv_value` on `rerun_out`) or a dedicated file redirect where parsing reads that same file, and add a harness assertion for non-empty KV when failures exist.

3. **risk-integration** — [`scripts/ship-pr.sh`](scripts/ship-pr.sh) uses two different capture idioms in the same function: command substitution for structured `ci-rerun-failed.sh` output (1500) versus full stdout/stderr redirect for human `gh-run-logs.sh` (1530). The new `ci-failed-jobs.sh` matches the quiet-helper family, not `gh-run-logs.sh`; the plan never states which idiom to mirror, so an implementer can pick the wrong one and silently drop `FAILED_JOBS_COUNT`. Suggested revision: name `ci-rerun-failed.sh` as the canonical analogue in the plan’s `run_evaluate_failure` bullet and in the proposed `ci-failed-jobs.md` “callers” section.

4. **architecture** — [`plan.txt`](file:///Users/zhupanov/.cache/larch/sessions/claude-design-larch9-LWwpEQ/plan.txt) line 21 (“default stdout via FD-3 emit”) blurs POSIX stdout with the post-init contract stream described in [`scripts/lib-quiet.md`](scripts/lib-quiet.md) lines 14–19. Suggested revision: align wording with “caller-visible stream preserved at FD 3” to reduce mis-wiring.
