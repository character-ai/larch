# Approach Synthesis (sketch_budget=2 / Cursor-Generic + Codex-Generic)

Both sketches converge on the same architectural shape. Cursor produced a brief exploration note (the
`design-log-publish.sh` depth-1 staging concern); Codex produced a substantive 3-paragraph plan that
matches the structure below. No divergence between the two.

## Architecture

1. Rating capture lives at the **tally boundary**, not the orchestrator. `plan-review-loop.sh` already
   owns round number / ballot / voter dispatch / tally call. Extend tally with TSV emission rather than
   teaching the main agent how to assemble rows.

2. Shared parser at `scripts/parse-judge-vote-and-rating.sh` (+ sibling `.md`) implementing the contract
   that issue #2675 (Lesson 6) pins as a hard dependency on this issue:
   - Positional invocation `<voter_file> <ballot_id>`
   - Stdout KV via `lib-quiet.sh` `emit_kv` (`PARSED_VOTE`, `PARSED_CORRECTNESS`, `PARSED_SEVERITY`,
     `PARSED_QUALITY`, `PARSED_UNCERTAIN`)
   - Exit 0 on recognized vote OR missing line; non-zero only on hard failure (set-e safe in callers)
   - Position-agnostic axis tokens (`CORRECTNESS=` / `SEVERITY=` / `QUALITY=` / `UNCERTAIN=`)
   - Vote token immediately after `<ID>:` (preserves the anchored parse in `lib-vote-tally.sh:12-29`)
   - Any missing/unrecognized axis becomes empty string; `PARSED_UNCERTAIN` defaults to `true` when any
     axis was missing or unrecognized

3. Voter prompt extension in `skills/shared/scripts/render-voter-prompt.sh` (the shared renderer used
   by `dispatch-plan-voters.sh` for the three plan-review judges and later by `dispatch-code-voters.sh`).
   Extension is **unconditional** (not gated by `--verification-context plan|diff-plan`): the extra
   suffix tokens are silently ignored by current `lib-vote-tally.sh` anchored parsing, so adding them
   globally is harmless during the L6 (#2675) pre-implementation window.

4. Retry prose in `scripts/lib-voter-parse-rate.sh` updated so empty-output retries describe the new
   line shape; otherwise retries would reinforce the old shorter format and degrade parse rate.

5. `skills/design/scripts/tally-plan-review.sh` emits `findings-classification.tsv` covering every
   ballot row (`FINDING_N` + `OOS_N`; accepted / rejected / neutral / exonerated). `plan-review-loop.sh`
   passes an explicit round-aware output path (`--findings-classification-out`) so tally never has to
   infer round state.

6. vN slot identity (Decision 3 — alphabetical per row): v1=Claude, v2=Codex, v3=Cursor. Independent of
   the dispatch order in `dispatch-plan-voters.sh`. The tally writes rows by alphabetically sorting the
   available voter outputs by their tool name and assigning them to v1/v2/v3 in that order.

7. `scripts/design-log-publish.sh` currently uses `find ... -maxdepth 1`. This issue adds the
   `plan-review/round-<N>/findings-classification.tsv` path to its staging allowlist as a targeted
   extension. Full recursive staging is OOS — that belongs to #2667.

8. `docs/run-logs.md` documents the new TSV in the design-log layout. Coordinate the wording with
   #2667 (which already touches `docs/run-logs.md`).

9. Harness `skills/design/scripts/test-findings-classification.sh` (+ sibling `.md`) plus a `Makefile`
   lint target covering:
   - 3 complete-rating judges produce a populated TSV row
   - Degraded round (one judge missing) → empty vN_* columns for that slot, other slots populated
   - 0-judge fallback (Decision 1) → row written with voting_result populated, all vN_* empty
   - 0-findings round (Decision 2) → header-only TSV (no data rows)
   - OOS ballot rows rated alongside FINDING rows
   - Re-run case (Decision 4) → second tally overwrites round-1/findings-classification.tsv
   - Position-agnostic axis tokens in voter output

## Risks
- Prompt/parser drift between L2 and L6 — mitigated because trailing tokens are silently ignored by
  the existing anchored vote parser.
- Missing-judge vs incomplete-judge: missing → empty vN columns; present-but-omitted → axis empty,
  PARSED_UNCERTAIN=true. The parser emptiness contract distinguishes them at the TSV row level.
- Publish depth coupling: only the single new nested path is allowlisted; broader recursion deferred
  to #2667 to keep this issue small.
