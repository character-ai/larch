# Plan: ship-pr.sh — rebase + rebump + lint inside the CI-fix path before pushing

Re-sequence the `/implement` CI-fix path so a fix is pushed already-rebased,
re-bumped, and lint-clean in one shot. Reuse existing helpers only; no new
rebase / rebump / behind-count / lint-fix / push implementations (issue #3210
hard constraint). Decisions from Round 1: guard-only (no ci-decide rework),
rotate the vendor start tier per attempt, cover both fix-push paths via one
shared helper.

## Files to modify/create

### NEW: `scripts/ci-behind-count.sh`
Extract the behind-count computation that currently lives inline at
`ci-status.sh:177` (`git rev-list "HEAD..$BASE_TARGET" --count`) into a small,
reusable script so both `ci-status.sh` and `ship-pr.sh` call one source (no
duplicated `git rev-list HEAD..<base> --count`).
- Args: `--base-remote` (default `origin`), `--base-ref` (default `main`),
  `--no-fetch` (skip the `git fetch`; caller already fetched).
- Behavior: optional `git fetch "$BASE_REMOTE" "$BASE_REF" --quiet`, then
  `git rev-list "HEAD..${BASE_REMOTE}/${BASE_REF}" --count`.
- Output (FD-3/stdout KV via `lib-quiet.sh`): `BEHIND_COUNT=<n>`. Same input
  validation regex on `--base-remote`/`--base-ref` as `ci-status.sh:64`.
- Exit 0 on success; non-zero on argv error. On a failed `git rev-list`, emit
  `BEHIND_COUNT=0` (fail-open: never block a push on a count error) and a
  Warnings-class diagnostic on stderr.

## Approach

The fix-push order becomes: **commit fix → check behind (against the same base
the rebase will use) → (if behind) rebase + rebump with push deferred →
re-verify failed jobs + lint on the rebased tree → push (force-with-lease if
rebased, else plain).** This matches the issue's required order (rebase →
rebump → lint → push) while reusing `run_rebase_rebump` wholesale; the only
changes to the rebase machinery are a `defer_push` flag that suppresses its
terminal force-push so the caller can re-verify first, and `base_remote` /
`base_ref` plumbing so forks rebase onto `upstream/main`.

Guard-only reconciliation (Round 1 Decision 1): `ci-decide.sh` / `run_ci_phase`
routing is untouched. After the post-fix path rebases, the next `ci-wait` poll
computes `BEHIND_COUNT=0`, so `ci-decide.sh` returns `wait`/`evaluate_failure`
rather than `rebase` — the deferred-rebase path is a natural no-op fallback, not
a double rebase.

Both fix-push paths are covered because the logic lives in the shared
`_stage_and_push_ci_fixes` (Round 1 Decision 3); the vendor path and the per-job
local-fix path both call it.

## Edge cases

- **Not behind:** behind-check returns 0 → no rebase, plain `git-push.sh`
  (today's behavior, unchanged).
- **Fork target:** base resolves to `upstream/main`; the `base_remote`/`base_ref`
  args are threaded into both the behind-check and `run_rebase_rebump` →
  `rebase-push.sh` so the rebase targets the same base. `run_rebase_rebump` did
  **not** previously support a non-`origin` base (the fork `ACTION=rebase` branch
  at 3142-3151 is a separate `rebase-push.sh --base-remote upstream` call); this
  plan adds that base plumbing (FINDING_3).
- **Rebase conflict:** reuses `run_rebase_rebump`'s vendor conflict-resolution
  (launch-*-ci.sh `--role resolve-conflict`, Phase 1-4) and its `exit_stall`
  behavior — no new conflict path.
- **Lint delta after rebase:** staged from **re-captured** post-rebase dirty-path
  snapshots (FINDING_6), then committed before the force-push.
- **Claude tier unavailable / Codex down (current degraded run):** the rotated
  waterfall keeps the same per-tier availability guards (1869) and waterfall
  fallbacks; rotation only changes the starting index.
- **`HAS_BUMP=false` repos:** `_run_rebase_rebump_from_step3` already skips the
  rebump when `HAS_BUMP=false`; deferred-push mode preserves that.

## Failure modes

1. **Re-verify fails after a deferred rebase (unpushed local rebase).** The
   branch is rebased+rebumped locally but not pushed; `_verify_failed_jobs_locally`
   may `exit 3` (propagates), return 2 (head-changed), or return 4 (retry).
   Mitigation: set `CI_FIX_REBASE_PENDING=true` **only** on a failed post-rebase
   verify path so a later retry push uses `git-force-push.sh` (avoids a
   non-fast-forward rejection from a plain push against the diverged remote), and
   never set it before re-verify so an `exit 3` cannot leave the flag set without
   a verify gate (FINDING_2). Map `rc=2`→`exit_stall`, `rc=4`→`return 4`; never
   push an unverified tree (FINDING_5). Earliest signal: a plain-push
   non-fast-forward error in CI logs.
2. **False `first-fixer-non-health` bail after a deferred rebase.** The no-commit
   bail in `run_ci_fix_vendor` (1933-1948) compares `baseline_head` to
   `LAST_STAGE_AND_PUSH_PRE_REFRESH_HEAD`; a deferred rebase rewrites `HEAD` and
   would falsely trip the bail (#3134 class). Mitigation: refresh
   `LAST_STAGE_AND_PUSH_PRE_REFRESH_HEAD` after the rebase (FINDING_4). Signal: a
   spurious `first-fixer-non-health` exit 3 on a behind branch.
3. **Double-rebase regression with `ci-decide.sh`.** Signal: `REBASE_COUNT`
   climbing without CI converging. Mitigation: the post-fix path leaves the
   branch up to date, so the next poll sees `BEHIND_COUNT=0`; covered by a
   regression test asserting no second rebase when already current.

  `BEHIND_COUNT` for behind/ahead/equal, `--no-fetch`, fork base, and fail-open
  on an invalid ref.
- `scripts/test-ship-pr.sh --section fix-loop` (extend): (a) behind>0 →
  `run_rebase_rebump` invoked with deferred push + correct base, re-verify runs,
  push uses force-with-lease; (b) behind=0 → no rebase, plain push; (c) re-verify
  failure after rebase → no push, `CI_FIX_REBASE_PENDING` set, retry push uses
  force-with-lease; (d) `BEHIND_COUNT` parsed via `kv_value` (assert a
  multi-line/quiet helper output does not corrupt the comparison); (e) fork base
  threaded into the rebase; (f) `HEAD`-snapshot refresh suppresses the false
  no-commit bail; (g) post-rebase verify `rc=2`→`exit_stall`, `rc=4`→retry; (h)
  vendor start-tier rotation across `_fix_attempt` (rotated order +
  first-fixer-non-health keyed on first iteration); (i) no second rebase when
  already current. Use the existing stubbed-binary / state-file harness pattern.
- `scripts/test-ci-status.sh`: confirm `BEHIND_COUNT` parsing still works after
  delegating to `ci-behind-count.sh`.
- Run `bash scripts/relevant-checks.sh` (lint/shellcheck/bash32) on all touched
  scripts; `make test-harness-shards-coverage` after the Makefile edit.
