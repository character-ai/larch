## Plan: ship-pr.sh — rebase + rebump + lint inside the CI-fix path before pushing

Re-sequence the `/implement` CI-fix path so a fix is pushed already-rebased,
re-bumped, and lint-clean in one shot. Reuse existing helpers only; no new
rebase / rebump / behind-count / lint-fix / push implementations (issue #3210
hard constraint). Decisions from Round 1: guard-only (no ci-decide rework),
rotate the vendor start tier per attempt, cover both fix-push paths via one
shared helper. Round 2 revisions address quiet-contract parsing, fork base
alignment, deferred-rebase verify/push gating, return-code propagation,
first-fixer-non-health false positives, and post-rebase stage-path refresh.

## Approach

The fix-push order becomes: **commit fix → check behind (parse KV) → (if
behind) rebase + rebump with push deferred onto the correct base → re-verify
failed jobs + lint on the rebased tree (re-capture stage paths) → push
(force-with-lease if rebased this call, else plain; pending flag only for
failed-verify retry paths).** This matches the issue's required order (rebase →
rebump → lint → push) while reusing `run_rebase_rebump` wholesale; the changes
to the rebase machinery are a `defer_push` flag, fork-aware base threading, and
caller-side verify/lint gating before push.

Guard-only reconciliation (Round 1 Decision 1): `ci-decide.sh` /
`run_ci_phase` routing is untouched. After the post-fix path rebases onto the
correct base, the next `ci-wait` poll computes `BEHIND_COUNT=0`, so
`ci-decide.sh` returns `wait`/`evaluate_failure` rather than `rebase` — the
deferred-rebase path is a natural no-op fallback, not a double rebase.

Both fix-push paths are covered because the logic lives in the shared
`_stage_and_push_ci_fixes` (Round 1 Decision 3); the vendor path and the
per-job local-fix path both call it with the same return-code propagation.

## Edge cases

- **Not behind:** behind-check returns 0 → no rebase, plain `git-push.sh`
  (today's behavior, unchanged).
- **Fork target:** behind-check and deferred rebase both use `upstream/main`
  via threaded `--base-remote upstream --base-ref main` into `run_rebase_rebump`
  / `rebase-push.sh`; do not rely on the separate fork-only `ACTION=rebase`
  branch (3142-3151) for the CI-fix path.
- **Rebase conflict:** reuses `run_rebase_rebump`'s vendor conflict-resolution
  (launch-*-ci.sh `--role resolve-conflict`, Phase 1-4) and its `exit_stall`
  behavior — no new conflict path.
- **Lint delta after rebase:** committed with a **fresh** post-rebase
  `collect_ci_stage_paths` snapshot (not pre-rebase files).
- **Claude tier unavailable / Codex down (current degraded run):** the rotated
  waterfall keeps the same per-tier availability guards (1869) and waterfall
  fallbacks; rotation only changes the starting index.
- **`HAS_BUMP=false` repos:** `_run_rebase_rebump_from_step3` already skips the
  rebump when `HAS_BUMP=false`; deferred-push mode preserves that.
- **Post-rebase verify exit 3 (`ci-local-unfixable`):** `_verify_failed_jobs_locally`
  may `exit 3` (not a return code). `CI_FIX_REBASE_PENDING` must **not** be set
  on this path; the unpushed rebased tree is handled by existing exit-3 bail
  semantics, not a later force-with-lease retry via the pending flag.

## Failure modes

1. **Re-verify fails after a deferred rebase (unpushed local rebase).** The
   branch is rebased+rebumped locally but not pushed. Mitigation: on verify
   `rc=4` or lint failure, set `CI_FIX_REBASE_PENDING=true` and return without
   pushing; a later successful retry uses `git-force-push.sh`. On verify `rc=2`,
   return `2` → caller `exit_stall`. On verify `rc=3` (exit 3), do not set the
   pending flag. Success-path force push uses `rebased_this_call=true`, not the
   pending flag.
2. **Double-rebase regression with `ci-decide.sh`.** If the post-fix rebase and
   the next-poll `ACTION=rebase` both fire, churn returns. Signal: `REBASE_COUNT`
   climbing without CI converging. Mitigation: the post-fix path leaves the
   branch up to date against the correct base, so the next poll sees
   `BEHIND_COUNT=0`; covered by a regression test asserting no second rebase
   when already current.
3. **`REBASE_COUNT` undercount on the bail-before-push path.** A rebase that
   bails before `_run_rebase_rebump_from_step3`'s counter bump is not counted,
   weakening the max-rebases storm guard. Signal: more than `_max_rebases`
   effective rebases. Mitigation: increment the counter when the deferred rebase
   completes, independent of the deferred push.
4. **False first-fixer-non-health after deferred rebase (#3134 class).** Deferred
   rebase rewrites `HEAD` after `LAST_STAGE_AND_PUSH_PRE_REFRESH_HEAD` was
   recorded pre-rebase; vendor exit 0 with no new fix commit could falsely
   trigger the no-commit bail. Mitigation: refresh `LAST_STAGE_AND_PUSH_PRE_REFRESH_HEAD`
   after successful post-rebase verify+lint, and/or skip the bail when rebase
   occurred this call.
5. **Fork behind-check vs rebase base mismatch.** Behind-check sees
   `upstream/main` but rebase defaults to `origin/main`. Mitigation: thread base
   args through `run_rebase_rebump` into every `rebase-push.sh` call (FINDING_3).
