## 1. Corpus-prep hook before per-file detect is unspecified (architecture)

`run_rule` discovers tracked files and invokes `rule.detect(source)` once per `SourceFile` (`engine.py:1255-1296`). It has no hook for a corpus-wide preparation step.

The plan requires resolving `OptionalMetadata` once from the full prepared in-memory corpus, but `REWRITTEN` only says to call `run_rule`. Today’s `main()` resolves metadata once, then scans every design module (`lint_self_disarmable_gate.py:525-539`). A per-file `detect()` that re-resolves from disk or lazily on first call violates “exactly once” and “no second discovery pass.”

**Suggested revision:** In `REWRITTEN`, document the production sequence: discover all sources → Piece 1 prep API → capture `meta_fields` → `run_rule` with a `detect` closure that reads the prepared metadata. Do not call filesystem `resolve_optional_metadata(design_dir)` on the production path.

## 2. Piece 1 corpus-preparation API has no pinned symbol (risk-integration)

The plan’s fail-closed dependency check cannot be implemented without a named import target. The original #6967 Piece 1 (`engine.py`) is already present and contains no corpus-preparation API.

**Suggested revision:** Pin the exact Piece 1 symbol (module, function, argument types, return values) and the import-time probe that stops the port when it is absent.

## 3. LintRule discovery contract is not pinned (correctness, scope-reduction)

Legacy scope is `design_dir.glob("*.py")` with `test_*` skipped (`lint_self_disarmable_gate.py:188-197`). The unreachable-branch port pins `pathspecs` and `source_filter` in its `REWRITTEN` section; this plan does not.

**Suggested revision:** Pin `pathspecs=("python/larch/design/*.py",)`, `syntax_policy="raise"`, and `allow_inline_suppression=False` in `REWRITTEN`, matching the unreachable-branch template.

## 4. Detector must use `engine.ScanError` (correctness)

Legacy `ScanError(RuntimeError)` (`lint_self_disarmable_gate.py:45-46`) is not `engine.ScanError`. `_scan_source` wraps non-engine exceptions (`engine.py:641-646`), which would change exit-code-2 diagnostics for suppression-owner and empty-reason failures on the `run_rule` path.

**Suggested revision:** Raise `larch.lint.engine.ScanError` from the detector and re-export it from the wrapper.
