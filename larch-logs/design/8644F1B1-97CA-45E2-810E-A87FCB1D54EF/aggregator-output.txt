### FINDING_1: Keepalive ownership must follow the repo checkout
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation
- **Severity**: important
- **Concern**: Keepalive-backed same-clone markers can be misclassified as foreign when hook input is rooted at the session tmpdir, and the planned regressions need to mirror the production repo-checkout cwd contract.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Before CLONE_PATH comparison, return not-foreign when cwd_canon equals the marker dir or is under it (same rule bash_probe_target_dir_plausible already uses via cwd_canon = dir). Document this edge case and add a regression where keepalive CLONE_PATH is the repo but hook cwd is the marker tmpdir.
  - From Cursor-Arch: In planned sections 2, 4, and 5, require same-clone payloads to set cwd to the matching repo checkout whenever .larch-keepalive is present; reserve tmpdir cwd for unknown-identity fail-safe cases only.
  - From Cursor-Innovation: Document the production contract in the test plan (mirror the existing #5925 comment at lines 859-864): when `.larch-keepalive` is present, set payload `cwd` to the owning repo clone path equal to `CLONE_PATH` (or a subdirectory of it). Keep no-keepalive cases on tmpdir cwd only for fail-safe coverage. Add an explicit regression that a keepalive-backed same-clone marker with repo cwd still denies Monitor while the same marker with tmpdir cwd is filtered out and allows.

### FINDING_3: Basename plausibility must not override clone ownership
- **Reviewer(s)**: Codex-Innovation, Codex-dyn-Hook Scope Risk
- **Severity**: important
- **Concern**: Even after collection-time clone filtering, the downstream basename-only plausibility gate can still let retained same-clone probes and clamps through, especially for repo subdirectories.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Codex-Innovation: Collection-time filtering leaves the old basename plausibility gate on same-clone paths. Scenario: The plan says subdirectory cwd is same-clone and same-clone Monitor, TaskOutput, tasks output, and bare tmpdir probes must still deny. With cwd=/repo/docs and marker CLONE_PATH=/repo, collection keeps the marker, but bash_probe_target_dir_plausible still derives cwd_tag=docs and lets those same-clone probes through.
  - From Codex-Innovation: After foreign markers are filtered at collection time, remove the old plausibility gate from post-collection deny decisions or replace it with the .larch-keepalive CLONE_PATH comparison that treats repo subdirectories as same clone.
  - From Codex-dyn-Hook Scope Risk: Collection-time filtering leaves the old basename-only plausibility gate on retained same-clone markers. Scenario: A same-clone wait with cwd in a repo subdirectory passes clone_paths_same during collection, but later Monitor, TaskOutput, tasks/*.output, or bare $IMPLEMENT_TMPDIR checks can still allow because bash_probe_target_dir_plausible compares only the cwd basename to the marker tag.
  - From Codex-dyn-Hook Scope Risk: Update the plan to replace or bypass the downstream basename heuristic for retained markers. Use the .larch-keepalive same-clone result consistently after collection, and add a subdirectory-cwd same-clone regression for one gated task-output or Monitor path.
