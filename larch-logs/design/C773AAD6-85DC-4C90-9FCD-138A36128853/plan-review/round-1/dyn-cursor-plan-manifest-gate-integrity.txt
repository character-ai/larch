### 1. [correctness] Legacy `host_decision` has no seed allowlist (`python/larch/lint/lint_module_manifest.py`, planned)

The plan lists “Legacy rows must not become a backdoor for newly added modules” under edge cases, but the `lint_module_manifest.py` bullets only exempt legacy from justification checks. Nothing rejects a brand-new `lint_*.py` filed with `host_decision: "legacy"` and `source_issue: 0`. That pair satisfies missing-entry and justification rules while bypassing the commissioning gate.

Add a frozen seed allowlist (for example `LEGACY_SEED_MODULES`) containing only basenames seeded in the initial manifest, and fail any other legacy row. Add a test: new on-disk module + legacy manifest row → exit 1 with a policy finding.

### 2. [correctness] `source_issue` must reject JSON booleans (`python/larch/lint/lint_module_manifest.py`, planned)

The plan’s boolean edge case is correct, but Python treats `bool` as `int`. Repo lints already guard with `isinstance(v, int) and not isinstance(v, bool)` (for example `python/larch/lint/lint_lifecycle_prefix_literal.py:528`). Without that, `"source_issue": true` can pass a positive-integer check.

Spell out the bool guard in the implementation bullets and add a test case.

### 3. [correctness] Filesystem inventory vs `run_rule` discovery (`python/larch/lint/engine.py:177-194`, planned `lint_module_manifest.py`)

The plan says compare against regular non-symlink `lint_*.py` files, yet also mandates `run_rule`, which discovers only `git ls-files --cached` paths. That misses untracked modules and cannot detect stale manifest rows for deleted files.

Follow the wire-artifact inventory style (`python/larch/lint/lint_wire_artifact_pairing.py:164-165`) or `lint_common.git_ls_files_z` (`python/larch/lint/lint_common.py:50-57`) for the inventory set; treat `run_rule` as optional for per-file work, not the sole enumerator.

### 4. [architecture] Stale rows and schema validation need an explicit phase (planned `lint_module_manifest.py`)

Stale entries and malformed JSON are manifest-global operations. `run_rule` only walks existing sources (`python/larch/lint/engine.py:472-515`) and cannot alone enforce “deleted lint module leaves stale entry until row removed.”

Split the plan into: (1) manifest schema validation → exit 2, (2) inventory diff for missing/stale/policy findings → exit 1, (3) optional `run_rule` pass. Preserve engine exit classes and finding stdout (`engine.py:480-482`).

### 5. [correctness] Legacy rows should require `source_issue: 0` only (planned manifest schema)

Seeded legacy uses `source_issue: 0`, but the plan does not reject legacy rows with a positive `source_issue`, which weakens the legacy vs `new-module-justified` distinction.

Require `source_issue == 0` for legacy rows (with the bool guard). Test legacy + positive issue → contract error or policy finding.

### 6. [correctness] Self-entry must be covered by inventory-sync test (`python/tests/lint/test_lint_module_manifest.py`, planned)

The self-entry edge case is stated, but the test plan only says verify committed manifest matches live inventory. That can pass if `lint_module_manifest.py` is missing from the manifest while counts match for other modules.

Assert the committed manifest includes `lint_module_manifest.py` as `new-module-justified` with non-empty justification and a positive commissioning `source_issue`.
