## Edge cases

- The manifest lint must include its own new module.
- JSON booleans must not count as positive integer issue numbers.
- Basenames must not contain separators or traversal segments.
- Legacy rows must not become a backdoor for newly added modules.
- A deleted lint module must leave a stale-entry finding until its manifest row is removed.

## Failure modes

- Fail with the tool-error exit for malformed or unreadable manifest data.
- Fail with findings for validly parsed policy violations.
- Do not silently skip missing manifests, unsafe filesystem entries, or duplicate records.
- Keep proposal filing blocked until every applicable cost field is complete.

## Testing strategy

- Run `make test-learn-from-bugs-structure`.
- Run `make test-lint-module-manifest`.
- Run `make lint-module-manifest`.
- Run focused pytest for both changed test modules.
- Run `make py-lint` and `make lint` for acceptance coverage.
