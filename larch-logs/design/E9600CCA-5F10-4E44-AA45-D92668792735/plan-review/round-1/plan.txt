## Implementation Plan

Fix #3334: `ship-pr` retries CI on deterministic failures without attempting a fix.

The CI monitor blind-reruns a failed run (no code change) before the fix loop, gated only on a retry counter — never on whether the failure is transient. With `rebase_then_evaluate`'s rebase + re-bump, a deterministic test/lint/compile failure churns until `10/12-max-retries`, never invoking the fixer. Same shape in the Bash live path and the Python migration tree.

## Approach

Add ONE transient-vs-deterministic gate in the CI-failure caller, in both implementations:

1. **Classify before retry-vs-fix.** Before the blind rerun, fetch the failure log and classify it with the existing `is_transient_net_signature` (network/infra). Treat every CI **check** failure as **deterministic** unless the log shows a network/infra signature (Round 1 Decision 1: "assume CI issues are never transient; a network issue is another matter").
   - Transient (network signature) AND under the rerun cap → rerun without a fix (today's behavior, now gated).
   - Deterministic, or rerun cap reached, or log unreadable → skip the blind rerun and go straight to the fix loop.
2. **Keep one rebase-to-main, then fix (Round 1 Decision 2).** `rebase_then_evaluate` still rebases once when behind, then evaluates. The gate above breaks the rebase→re-bump→blind-rerun churn: a persisting deterministic failure now reaches the fixer instead of re-running. No separate mechanism is needed — gating the blind rerun is what stops the churn.
3. **Wire true fixer exhaustion into the autonomous CI-fix path (Round 1 Decision 3).** When the in-script vendor/per-job fix waterfall exhausts its attempts **after at least one dispatch against a ready failure log** (`gh-run-logs` rc=0 / Python `logs.state == "ready"`), route to the orchestrator's autonomous main-agent CI-fix (exit 3, `BAIL_REASON=ci-fix-exhausted`) instead of a plain stall (exit 4). Outer-loop exhaustion with logs still in progress, no ready log ever obtained, push/launcher failures, or no-tier dispatch must **remain** on the existing stall path (`exit_stall` / `Outcome.STALLED`). The autonomous sub-procedure is already capped at 3 attempts, so this adds no unbounded loop. The rebase-storm exhaustion (`REBASE_COUNT >= 20`) stays a plain stall — it is "main too active", not a code-fix case.

**Resolved design decision (outline open question):** the gate lives in the CALLER (`run_evaluate_failure` / `evaluate_failure`), NOT in `ci-decide.sh` / the `decide` port. The decision matrix only sees `pass|fail|pending|merged` + counters; classification needs the failure-log text, which only the caller holds. `ci-decide.sh` and `decide` are unchanged.

## Edge cases
- **Log not yet available** (`gh-run-logs` rc=3 / Python `logs.state == "in_progress"` or `"error"`): cannot classify → treat as deterministic (no blind rerun); the existing in-progress backoff in the fix loop handles waiting. If the outer cap exhausts with only in-progress deferrals and no ready-log fix dispatch, terminal path stays exit 4 stall — not `ci-fix-exhausted`.
- **Bash/Python log-readiness parity**: Bash blind-rerun classification requires `gh_logs_rc == 0` before `is_transient_net_signature`; non-zero fetch skips rerun (same as Python requiring `logs.state == "ready"`).
- **Network failure inside a job** (e.g. a test hitting the network): the failure log carries a `is_transient_net_signature` match → still allowed one gated rerun (honors "a network issue is another matter").
- **Tail window**: `gh-run-logs` shows the last `CI_MONITOR_LOG_TAIL_LINES` (100). A network signature buried above the tail is missed and treated as deterministic — acceptable; deterministic-default is the safe bias.
- **Budget interaction**: `TRANSIENT_RETRIES` now caps only transient reruns; `FIX_ATTEMPTS` (cap 10) and the per-invocation waterfall cap (3) are unchanged, so fix-first cannot loop unbounded.
- **Rebase storm**: `REBASE_COUNT >= 20` still stalls (exit 4); not routed to autonomous fix.

## Failure modes
- **Mis-routing a genuine infra/transient failure to a code fix.** Signal: fixer makes no-op or wrong edits on a flaky/network failure. Mitigation: classify the failure log with the existing network signature set before fix-first; reserve rerun for that set.
- **Routing pending or non-code-fix exhaustion to autonomous main-agent CI fix.** Signal: `ci-fix-exhausted` fires with no usable failure log or after push/launcher failure. Mitigation: gate exit 3 on `_fix_dispatched_on_ready_log` / `fix_dispatched_on_ready_log`; preserve stall for in-progress-only and non-dispatch exhaustion.
- **Autonomous fix loop pressure at exhaustion.** Routing `ci-fix-exhausted` to exit 3 hands more failures to the main-agent fixer. Signal: repeated main-agent CI-fix attempts. Mitigation: the orchestrator's existing 3-attempt sentinel/counter cap bounds it, then falls through to user-bail.
- **Bash/Python drift.** The bug reappears when `LARCH_SHIP_PR_IMPL=python` goes live if only one side changes. Mitigation: mirror the gate + exhaustion routing in both; add parity tests in `test_ci_monitor.py`.
