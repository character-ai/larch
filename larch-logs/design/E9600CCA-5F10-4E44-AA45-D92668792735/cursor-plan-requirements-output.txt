### 1. [correctness] `plan.txt:28-33` vs `plan.txt:62-63` — substantive-attempt predicate drift (Python)

The plan’s **single contract** says Bash sets `_code_fix_attempted_on_ready_log` when `run_per_job_local_fix_loop` is **entered** with `ci_failed_count > 0` (plus vendor `vendor_rc == 4`). The **`python/ci_monitor.py`** bullet narrows this to flagging only when `run_ci_fix` returns `verify-failed` / verification-retry (or vague “per-job equivalent”). Python’s `run_ci_fix` runs the vendor waterfall before local per-job verify (`python/ci_monitor.py:909-948`), so following only the Files bullet can under-set the flag versus Bash per-job entry. That breaks Decision 3 parity: substantive outer exhaustion routes to autonomous exit 3 in Bash but can still stall in Python.

**Suggested revision:** Point the Python section at the unified predicate and define an explicit Python mapping (substantive dispatch, not defer-only outers); extend tests so ready-log/ready-job exhaustion after real fix dispatch asserts `fix-exhausted` / `ci-fix-exhausted`, not only `verify-failed` tails.
