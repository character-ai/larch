# review-points-overhaul-II Make panel severity informative (rubric + majority-YES aggregation)

Phase II cornerstone. Fixes the value-weighting signal that Phase I #4773 shipped but that is currently inert.

**Problem (measured).** On the panel severity that #4773 uses for points, **~98% of accepted in-scope findings are rated `major`/`blocker` by a YES voter** (implement: major=281, blocker=12, minor=3; design: major=802, blocker=158, minor=29). So the +2 tier is near-universal and value-weighting collapses to a near-flat "+2 for accepted." Root cause: `accepted_finding_points_from_severities` (`python/voting.py`) returns +2 if **any** YES voter rates `blocker`/`major` — the most inflation-prone rule possible — and voters have no incentive to calibrate severity (their tag sets the proposer's points, not their own).

**Change (two parts; must ship together).**
- (a) Anchor the labels: add an explicit severity rubric to the voter prompt with concrete per-level examples (reserve `blocker` for data-loss/security; `major` for blocks-merge / wrong-behavior; everything else `minor`/`nit`). There is an accept/reject necessity gate today but no severity anchor.
- (b) Change the aggregation in the single function `accepted_finding_points_from_severities` from "any YES voter high" to "majority of YES voters rate high." This one edit propagates to all three live callers (`review_tally.py`, `plan_review_tally.py`, and `progress_report.py` via `accepted_points_from_classification_row`) and the replay path.

**Do NOT revert to reviewer `body_severity`.** #4773 deliberately moved off proposer-set severity so reviewers cannot set their own points. Reverting reintroduces gameable, proposer-controlled scoring. Keep panel (judge) severity; calibrate the judges instead.

**Honest caveat.** (b) alone does nothing while labels stay inflated; (a) alone leaves the gameable "any" rule. They are a pair. This step fixes the advisory scoreboard now; it does not change any live decision until item #4 lands.

**Verify.** Re-score the committed corpus; success = the +2 share among accepted findings develops real, stable spread (variance well above ~0), not a target number. There is no ground truth yet (see item #5).

**Risk.** Medium. Touches scoring math + generated prompts. Tests: `python/test_voting.py`, `python/test_review_tally.py`, `python/test_plan_review.py`.

**Dependencies.** None (cornerstone). Blocks the measurement and load-bearing items below.
