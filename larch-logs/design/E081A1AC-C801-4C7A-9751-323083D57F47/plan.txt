# Plan — Stop shrinking judge panel; all 3 judges run on every round

## Goal

Make the code-review voter panel unconditionally 3-judge (Claude + Codex + Cursor) on every round in both `/implement` Step 5 and standalone `/review`. Today, round 1 runs the full 3-judge panel and rounds 2+ omit the Codex voter, leaving a 2-judge panel (Claude + Cursor). That round-1-only gating (originally introduced by closed issue #2419) is removed; the existing waterfall continues to handle Codex unavailability via Claude replacement.

Scope (per Step 1c clarification): apply uniformly across both `/implement` Step 5 and `/review` standalone — they share `scripts/dispatch-code-voters.sh`, so a single fix point covers both.

## Approach

- The behavior is centralized in `scripts/dispatch-code-voters.sh`; making the panel composition unconditional there fixes both call sites (`/implement` Step 5 via `review-and-fix.sh` → `review-core.sh`, and `/review` standalone via `review-core.sh` directly).
- Use the existing round-1 branch as the unconditional shape — it's already the well-tested code path that produces the 3-judge panel.
- Keep `--round-num` validated and threaded through, since downstream artifact paths, retry diagnostics, and `expected_judges` warnings still need it (`expected_judges` now stays at 3 regardless, but the warning machinery is the same).
- The Codex voter's runtime unavailability is already covered by the existing waterfall (Codex → Cursor → Claude per slot); no new fallback logic is needed for "what if Codex is down on round 4".
- Tests: existing `test-dispatch-code-voters.sh` round-2 section flips polarity (now asserts the same panel shape as round 1, not a shrunk shape). `test-quick-mode-docs-sync.sh` learns the new positive marker, and the self-test fixtures it uses are updated to match.

### Trade-offs

- **Cost**: keeping the Codex voter on every round restores Codex usage that issue #2419 deliberately capped. The user has accepted this cost in exchange for consistent panel composition across rounds.
- **No env-var escape hatch**: the change does not add a `LARCH_*` env var to restore the old shrinking behavior. The user's framing ("stop shrinking ... should run on every round") is unconditional, and adding a knob for a behavior we are explicitly removing would be premature configurability.

## Edge cases

- **Codex unavailable session-wide** (`CODEX_AVAILABLE=false`): on every round, the Codex slot waterfalls to Claude (already-supported path; same as today's round-1 behavior). `VOTER_2_TOOL=claude`, `VOTER_2_STATUS=fallback`.
- **Codex transiently unhealthy mid-run** (Codex returns empty output on round 3 after passing rounds 1-2): the existing per-slot waterfall in `dispatch-with-waterfall.sh` triggers a Claude replacement for that round; `VOTER_2_STATUS=fallback`, no degraded-panel warning.
- **All externals down**: both Codex and Cursor slots waterfall to Claude. `expected_judges=3`, `effective_judges=3` (all Claude). Same as standalone-Claude behavior in any round today.
- **`--round-num` validation failures** (zero, non-integer): unchanged — still hard-fail with the existing usage error.
- **Higher round numbers** (e.g., round 5, the cap): no special-case behavior; the same 3-judge panel runs.

## Failure modes

- **Tests skipped due to incomplete update**: if `test-dispatch-code-voters.sh`'s round-2 section is updated but `test-quick-mode-docs-sync.sh`'s positive marker is not, CI will fail because the old `3-judge panel on round 1` literal disappears from the public docs but the harness still requires it. Earliest warning: `test-quick-mode-docs-sync.sh` fails locally in `make lint` before push. Mitigation: update both harnesses (and the embedded self-test fixtures) in the same commit as the doc edits.
- **Stale prose left somewhere**: a doc or comment that still says "Codex voter is omitted on rounds 2+" will silently misinform readers and may resurface as an OOS observation later. Earliest warning: post-fix grep for the canonical stale phrases (`omit Codex`, `2-judge panel on rounds 2+`, `rounds 2+ use a 2-judge`, `Codex voter omitted`) returning hits. Mitigation: run such a grep across `docs/`, `skills/`, `scripts/`, `README.md` before declaring done.
- **dispatch-with-waterfall.sh edge case**: changing `codex_present_for_waterfall` to always equal `CODEX_AVAILABLE` regardless of round must keep producing valid manifests for the waterfall. Earliest warning: `test-dispatch-code-voters.sh` round-2 section failing on `DISPATCH_OK=true` or on the manifest-shape assertions. Mitigation: keep the existing round-1 manifest-write block as the template for the new unconditional code path; do not invent a new shape.
