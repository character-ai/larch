**(1) Architectural decisions and approach.** Adopt a prompt-only prohibition, grounded entirely in `agents/_implementer-base.md` and the inline prompt in `scripts/launch-codex-ci.sh`. The fix is a normative "Hard guards"-style clause that prohibits Codex from spawning persistent interactive subprocess sessions (`exec_command` without `tty=true`, paired `write_stdin` / `read_stdout` polling, kept-alive child shells), paired with positive guidance: when subprocess input is required, pass it via heredocs (`cmd <<'EOF' ... EOF`), pipes (`printf '...' | cmd`), input files (`cmd < /tmp/in`), or single-shot command lines — never an interactive session. Frame the rule by failure mode ("stdin is closed for this session") rather than by tool name, so it survives Codex CLI tool renames. Keep it Codex-specific via a parenthetical annotation in the shared base, since `agents/_implementer-base.md` flows into both `codex-implementer.md` (via `scripts/generate-codex-implementer.sh`) and `cursor-implementer.md`; Cursor lacks the tool surface, so a "(Codex-specific)" note is harmless and avoids splitting the base. This honors the "minimum code that solves the problem" bias and stays inside Option 2 (no recovery branch in `step2-implement.sh`, no setsid/PTY wrapper).

**(2) Files to modify and why.** Three sources, two regenerated artifacts, three sibling `.md` updates, two harness touches. (a) `agents/_implementer-base.md` — add the new clause to "Hard guards" (or a sibling "Subprocess-tool discipline" subsection just below the Hard guards), so both implementer prompts inherit it; this is the single canonical edit per the auto-gen contract. (b) Run `bash scripts/generate-codex-implementer.sh` to regenerate `agents/codex-implementer.md`; `scripts/generate-cursor-implementer.sh` for `agents/cursor-implementer.md` per external-tool-launcher-parity. (c) `scripts/launch-codex-ci.sh` — append the same prohibition to the inline `PROMPT=` heredoc at line 138 (likely as a new context block alongside `$LARCH_PATTERNS` / `$LOCAL_REPRO`, or directly in the trailing paragraph at line 150). (d) Update sibling docs per `script-md-siblings.md`: `scripts/launch-codex-ci.md`, `scripts/generate-codex-implementer.md`, `scripts/generate-cursor-implementer.md`. (e) Per `launcher-argv-test-coverage.md`, no argv surface changes — but the implementer-base diff flows into `agents/codex-implementer.md`, which `skills/implement/scripts/test-codex-implementer.sh` may pin substrings of; verify and extend assertions in the same PR if it does. Optionally add a one-line regression pin in `skills/implement/scripts/test-codex-implementer.sh` asserting the new clause string appears in the regenerated agent file. Finally, `make lint` (which runs `generate-codex-implementer.sh --check` and the Cursor equivalent).

**(3) Tradeoffs and risks.** The main tradeoff is verification weakness: prompt-level guidance is advisory, not enforceable — Codex may still ignore the rule under long-context drift. Mitigation: phrase the clause inside the existing Hard guards block (numbered alongside `git reset --hard`, `git add`, etc.) so it inherits the "MUST abort with `status=bailed`" framing rather than reading as a soft suggestion. Secondary risks: (a) cross-talk with #2973 — the `< /dev/null` fix in `run-external-agent.sh` addresses parent-shell stdin closure, not Codex's child-shell stdin closure, so the two fixes are complementary and we should land #2973 first to avoid confounding any incidental Codex behavior change; (b) auto-gen drift if a contributor edits `agents/codex-implementer.md` directly (mitigated by the existing `--check` mode in CI); (c) risk of the new clause being too broad and accidentally discouraging legitimate single-shot `bash -c` calls — keeping the rule scoped to persistent sessions (heredocs/pipes explicitly endorsed) is the surgical phrasing. No production code paths, sandboxing semantics, or launcher argv surfaces change, which keeps the blast radius limited to two regenerated agent files and one `.md` sibling group.
