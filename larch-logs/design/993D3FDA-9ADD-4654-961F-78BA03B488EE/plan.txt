# Plan: Prohibit persistent interactive subprocess sessions in Codex implementer + CI fixer prompts (issue #2991, blocked by #2973)

## Summary

Codex's `write_stdin` tool against an `exec_command` session without `tty=true` fails with `stdin is closed for this session`, killing the implementer mid-run, leaving 600+ uncommitted lines and no manifest (the failure mode reported in #2991). This design adds a prompt-level prohibition against persistent interactive subprocess patterns to the Codex implementer prompt (via the shared base file with a Cursor-strip in the Cursor generator) and to the inline Codex CI fixer prompt; regenerates the auto-generated agent artifacts; adds the new stable bail token to the manifest schema; and pins the clause via two grep-style harness assertions plus one absence-pin in the Cursor harness.

This is a prompt-only fix per Round 1 Decision 1 (Option 2). It does NOT add a recovery branch in `step2-implement.sh`, does NOT add a setsid/PTY launcher wrapper, and does NOT change any launcher argv. #2991 is recorded as **blocked by #2973** in GitHub (native blocked-by relationship). #2973 lands first and addresses a different failure class (parent-shell stdin closure on background Codex spawns) via `< /dev/null` redirects in `scripts/run-external-agent.sh:206-213`; #2991 lands afterward and addresses Codex's own use of `exec_command`/`write_stdin` against child subprocesses.

### UPDATED: `agents/_implementer-base.md`

Add a new Hard guard #9 to the existing numbered list inside `## Hard guards` (the section ends after rule #8 today; the new rule extends the existing numbered list and inherits the section's "MUST cause you to abort with `status=bailed`" framing). The clause is Codex-flavored in the base — the Cursor generator strips it (see `scripts/generate-cursor-implementer.sh` UPDATE below) so the Cursor artifact does not inherit a Codex-specific abort instruction. The clause text:

```
9. **NEVER spawn or maintain persistent interactive subprocess sessions.** Do NOT use `exec_command` to hold a child shell open for later input, do NOT call `write_stdin` against a held child, and do NOT poll with `read_stdout`. The stdin-is-closed-for-this-session error class kills the implementer mid-run, leaving uncommitted edits in the working tree and no manifest (issue #2991). When a command needs input, pass it up front via a heredoc (e.g. ``cmd <<'EOF' ... EOF``), a pipe (e.g. ``printf '...' | cmd``), an input file (e.g. ``cmd < /tmp/input``), or a single-shot shell command. If the work genuinely requires an interactive subprocess pattern, set `status=bailed`, `bail_reason="interactive-subprocess-unsupported"`, and return.
```

Place the new rule directly after the existing rule #8 (which ends with `... contaminates the PR diff and makes OOS contamination harder to review.`). Maintain one blank line between rule #8 and rule #9, and another blank line between rule #9 and the following `## How to declare completion` H2. Do NOT modify rules #1-#8.

Rationale for placement inside the Hard guards numbered list (rather than a new section):
- Inherits the section's strongest framing ("non-negotiable", "MUST abort with status=bailed") without restating it.
- Keeps the prompt scannable — implementers see a single numbered list of hard rules.
- Matches the existing pattern of rule #2 (vendor-flavored phrasing differs between Cursor base and Codex sed-substituted artifact).

## Approach

The implementer makes the canonical edit in `agents/_implementer-base.md` first (adding Hard guard #9), then extends `scripts/generate-cursor-implementer.sh` with the sed deletion that strips rule #9 from the Cursor artifact. Then run BOTH generator scripts (`bash scripts/generate-codex-implementer.sh` and `bash scripts/generate-cursor-implementer.sh`) to update the two implementer artifacts. After that, edit `scripts/launch-codex-ci.sh` inline prompt, update the three `.md` siblings (one for the CI launcher, two for the generator-side test harnesses), add the bail token to the two manifest-schema files, add the new helpers in `test-codex-implementer.sh` (presence) and `test-cursor-implementer.sh` (absence), and add the rendered-prompt assertion in `test-launch-codex-ci.sh`.

Final validation: explicitly run `bash scripts/check-generators.sh` (or `make agent-sync`, which invokes the walker via line 949 of the Makefile) to confirm both implementer artifacts match the base. The walker `scripts/check-generators.sh` takes no flags; it invokes each registered generator in `--check` mode (see `scripts/check-generators.sh:2` and the per-generator `--check` mode entry points at `scripts/generate-codex-implementer.sh:22-28` and `scripts/generate-cursor-implementer.sh:22-28`). `make lint` does NOT transitively invoke `check-generators.sh` (no pre-commit hook covers it), so the implementer must run it explicitly. Then run the three harness scripts (`test-codex-implementer.sh`, `test-cursor-implementer.sh`, `test-launch-codex-ci.sh`) and `make lint`.

Key constraint: rule #9 must use phrasing the implementer can recognize as a behavior contract, not just a tool-name ban. The clause centers the failure mode (the stdin-is-closed-for-this-session class, persistent interactive subprocess sessions) and provides explicit positive alternatives (heredoc, pipe, input file, single-shot command), so it survives Codex CLI tool renames and does not over-restrict legitimate single-shot `bash -c` invocations.

## Edge cases

- **Generator regenerates only when invoked**: `scripts/check-generators.sh` is the explicit drift gate; `make lint` does not currently run it (no pre-commit hook references it). The implementer MUST invoke it explicitly after editing the base or either generator.
- **Cursor generator sed deletion robustness**: the deletion pattern `/^9\. \*\*NEVER spawn or maintain persistent interactive subprocess sessions\*\*/,/^$/d` deletes from the rule line through the first following blank line. The base file MUST place a blank line immediately after rule #9 (between #9 and `## How to declare completion`) for the pattern to terminate correctly. Tested via `bash scripts/check-generators.sh` after both edits land — if the blank line is missing, the sed deletion eats into the next section and the regenerated Cursor artifact fails `--check`.
- **Auto-generated comment on hand edits**: the `<!-- AUTO-GENERATED -->` marker is a documentation hint. Drift is mechanically caught by `bash scripts/check-generators.sh`; the existing CI harness `test-check-generators.sh` covers the walker itself.
- **`test-codex-implementer.sh` helper separation**: the new `assert_subprocess_guard_present` is a separate helper with its own failure message — FINDING_2's concern (misleading manifest-template error) is resolved by NOT folding the check into the existing helper.
- **`test-cursor-implementer.sh` absence-pin**: the absence-pin is a positive-test-for-negative-property — it passes when the rule is NOT present. If a future contributor reverts the sed deletion, the test fails with a clear message attributing the regression to the Cursor generator.
- **`test-launch-codex-ci.sh` rendered-prompt assertion**: the new assertion lives inside the existing stub-launch block at lines 73-82, so it relies on the stub `codex` having already been invoked and `${OUT_FIX}.prompt` having been written. Placing the assertion outside that block would race the stub setup.
- **Inline-prompt quote hygiene**: the `PROMPT="..."` body is double-quoted shell. Any unescaped `"` inside terminates the assignment early. The new paragraph uses no inner double quotes (FINDING_3 fix); the phrase `the stdin-is-closed-for-this-session failure class` is recognizable without quote marks.
- **Bail-reason token additions to schema vs digest**: the full schema lists bail-reason tokens with full descriptions, the digest lists them tersely. Both files must be updated in the same PR (the digest's contract is "keep in sync with the corresponding sections above" per `codex-manifest-schema.md:154`).
- **#2973 ordering**: #2973's `< /dev/null` fix in `scripts/run-external-agent.sh` lands first. This design's edits do NOT touch `run-external-agent.sh` and do NOT conflict with that PR. The blocking relationship is recorded natively via `/larch:block-issue` (already established before this plan was written).

## Failure modes

1. **The implementer forgets to run `bash scripts/check-generators.sh`.** Symptom: a future PR's CI catches the drift (if drift is caught at all), or worse, the regenerated artifact ships with stale content. Earliest signal: a CI harness run of `test-check-generators.sh` or an explicit `make agent-sync` discovers the mismatch. Mitigation: the plan's "Approach" section explicitly names both `bash scripts/check-generators.sh` and the two per-generator commands; the plan does NOT claim `make lint` covers this.

2. **A future PR weakens the clause phrasing in the base or in the inline prompt.** A subtle edit could drop the positive guidance, or replace `persistent interactive subprocess` with a narrower phrase. The grep pins use the literal signature phrase, so weakening edits that drop "persistent" or "interactive" would break the pin. Earliest signal: harness failure in `test-codex-implementer.sh` or `test-launch-codex-ci.sh`.

3. **Codex CLI tool surface changes (renames `write_stdin` or removes `exec_command`).** A future Codex CLI version could rename or remove the tools the clause references. The clause references the failure surface (the stdin-is-closed-for-this-session class), the tool names (`exec_command`, `write_stdin`, `read_stdout`), AND the architectural pattern (persistent interactive sessions). If only the names change, the architectural-pattern phrasing still applies; the implementer reading the prompt will recognize the failure class even if the tool name is unfamiliar. If the pattern itself disappears (CLI loses the interactive-session tool family), the clause becomes a harmless no-op until cleanup. Mitigation: track Codex CLI release notes for tool renames; refresh the clause text via a follow-up OOS issue when needed.
