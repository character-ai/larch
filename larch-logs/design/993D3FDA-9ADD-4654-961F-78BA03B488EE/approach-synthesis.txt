## Approach Synthesis

Both sketches (Cursor-Generic Claude-fallback and Codex-Generic) converge on the same prompt-only approach with no contested architectural decisions.

### Where the sketches agree
- **Single canonical edit point**: extend the existing `## Hard guards` numbered list in `agents/_implementer-base.md` with a new rule against persistent interactive subprocess sessions. Placing the new clause inside the numbered Hard guards (rather than a separate section) lets it inherit the section's existing "MUST abort with `status=bailed`" framing, which is the strongest framing available in a prompt-level fix.
- **Codex-specific scoping via parenthetical**: since `agents/_implementer-base.md` is shared and regenerates both `agents/codex-implementer.md` and `agents/cursor-implementer.md`, the new clause needs a `(Codex-specific; Cursor's tool surface does not expose these tools)` annotation. This is an intentional benign asymmetry — splitting the base file would cost more than the annotation does.
- **Phrase by failure mode, not tool name**: the clause should reference the failure surface ("persistent interactive subprocess sessions", "kept-alive `exec_command` sessions", "`write_stdin` against a held child", "paired `read_stdout` polling") rather than only the single literal tool name `write_stdin`. This survives Codex CLI tool renames and matches the user's Round 1 Decision 4 (broader scope).
- **Positive guidance**: the clause must explicitly endorse the alternatives — heredocs (`cmd <<'EOF' ... EOF`), pipes (`printf '...' | cmd`), input files (`cmd < /tmp/in`), one-shot shell commands. Without the positive side, the prompt looks restrictive without showing the implementer what to do instead.
- **Regenerate both implementer artifacts**: after editing the base, run `bash scripts/generate-codex-implementer.sh` to refresh `agents/codex-implementer.md` and `bash scripts/generate-cursor-implementer.sh` to refresh `agents/cursor-implementer.md`. Both regenerated files are in `scripts/generators.tsv`, so `make lint` `--check` mode will fail if either is stale.
- **Codex CI fixer prompt**: the same prohibition belongs in `scripts/launch-codex-ci.sh` (inline `PROMPT=` body starting at line 138). The CI fixer is a different launch site that uses a different prompt source but the same Codex CLI tool surface, so it has the same write_stdin failure risk. Update the sibling `scripts/launch-codex-ci.md` to document the new prompt context per `.claude/rules/script-md-siblings.md`.
- **Lightweight harness pins**: both sketches recommend adding grep-style assertions to confirm the new clause text appears in the regenerated agent file and in the launch-codex-ci.sh inline prompt. Existing test files: `skills/implement/scripts/test-codex-implementer.sh` (covers `agents/codex-implementer.md`), `scripts/test-launch-codex-ci.sh` (covers `scripts/launch-codex-ci.sh`).

### Minor divergences (resolved in favor of the broader scope)
- Cursor-Claude proposed an *optional* harness pin in `test-codex-implementer.sh` only. Codex-Generic proposed pins in *both* `test-codex-implementer.sh` and `test-launch-codex-ci.sh`. Resolution: include both pins — they are cheap (one grep assertion each) and they protect against future prompt-revision drift, matching the repo's existing grep-style prompt-contract tests.
- Cursor-Claude suggested updating `scripts/generate-codex-implementer.md` and `scripts/generate-cursor-implementer.md` siblings. Codex-Generic did not. Resolution: NO — the generator scripts themselves are not changing semantically (only their input base file changes), so their sibling `.md` contracts are accurate as-is. Updating them would be noise.

### Validation hook chain
After all edits, the implementer should run `make lint`. The relevant `--check` passes are:
- `scripts/check-generators.sh` walks `scripts/generators.tsv` and re-invokes each generator in `--check` mode. If the implementer edits `_implementer-base.md` but forgets to regenerate `codex-implementer.md` or `cursor-implementer.md`, this fails.
- Standard markdownlint, shellcheck, bash32 portability, and sibling-md checks via `scripts/relevant-checks.sh`.
- The new harness assertions in `test-codex-implementer.sh` and `test-launch-codex-ci.sh` confirm the prompt clause survives all regenerations.

### Failure modes and risks (highlighted from sketches)
1. **Prompt-level guidance is advisory, not enforceable.** Codex may still ignore the rule under long-context drift. The Hard guards framing ("MUST abort with status=bailed") and placement in the existing numbered list is the strongest mitigation prompt-level engineering offers.
2. **#2973 ordering**: #2973's `< /dev/null` fix in `scripts/run-external-agent.sh` and #2991's prompt-level fix address *different* failure surfaces (Codex's own stdin closure vs. Codex's child-process stdin via `write_stdin`). They are complementary; #2991 should land after #2973 (blocked-by recorded via `/larch:block-issue`).
3. **Auto-gen drift**: a future contributor could hand-edit `agents/codex-implementer.md` and bypass the canonical edit point. Mitigated by the existing `--check` mode in CI (re-run on every commit).
4. **Over-broad phrasing**: a too-restrictive clause could accidentally discourage legitimate single-shot `bash -c` calls. The positive guidance (heredocs, pipes, input files) is the surgical phrasing that scopes the prohibition to persistent sessions, not to all subprocess invocation.
