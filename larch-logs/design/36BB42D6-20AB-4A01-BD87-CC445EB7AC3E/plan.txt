- `design-stage-terminal-state.sh`
- `design-failure-report.sh`
- `design-step-final-summary.sh`

Use full in-process Python ports. Do not add thin wrappers or shims.

Preserve existing contracts:

- `LARCH_FINAL_SUMMARY_BEGIN`
- `LARCH_FINAL_SUMMARY_END`
- `REPORT_GATE_SIDECARS_FILE=`
- `design-failure-terminal-state.env`
- terminal and escalation sentinels
- fallback chat artifacts
- existing run-log tool labels unless tests prove they are private

Cut Python callers to imports and direct function calls. Use launcher mappings only for prompt-side `.sh` basenames that must remain in `skills/design/SKILL.md`.

## Edge cases

- Existing terminal state with a different outcome, site, or trigger must preserve the old state and emit `STAGED=false`.
- Existing terminal state that is a symlink or non-regular file must fail.
- `--failure-detail-log` must stay under `DESIGN_TMPDIR`.
- `--failure-detail-log` must be regular, readable, and not a symlink.
- `--evidence-ref` must reject unsafe tokens, absolute paths, URLs, spaces, backticks, and traversal.
- Missing terminal state for terminal-failure outcomes must produce fallback chat.
- Cancellation outcomes must produce operator-action skip artifacts.
- Final-summary output must preserve marker shape and newline behavior.
- `.completed/step-final-summary` must be written after marked output and sidecar handoff.
- The hook-bg-poll-guard step name `design-step-final-summary` must remain unchanged.

## Failure modes

- In-process ports may leak helper stdout. Capture helper output where the shell version wrote logs or env files.
- A partial caller cutover may leave deleted helper paths dangling in prompt or tests.
- Calling `cli.py` from Python callers may violate the no-shell-out route. Use direct imports for Python-to-Python calls.
- Changing historical tool labels may break run-log audits. Keep labels stable unless tests require a change.
- Removing shell files before adding launcher mappings may break prompt-side final-summary fences.
