### FINDING_3: In-process `step_final_summary_main` risks breaking the stdout/stderr/marker split

- **Severity:** important  
- **Plan section:** `### UPDATED: python/design_lifecycle.py` — `step_final_summary_main` (“call `design_summary.render_final_summary_main` in-process”, then emit markers + sidecars)  
- **Concern:** Today `design-step-final-summary.sh` **captures** render stdout to a log and emits markers/sidecars separately on wrapper stdout:

```113:145:skills/design/scripts/design-step-final-summary.sh
  python3 ... design render-final-summary ... >"$DESIGN_TMPDIR/render-final-summary.stdout.log"
...
emit_final_summary_marked_from_disk
emit_report_gate_sidecars_from_disk
...
: >"$DESIGN_TMPDIR/.completed/step-final-summary"
```

`render_final_summary_main` also writes the summary body to stdout and may print `REPORT_GATE_SIDECARS_FILE=` (`python/design_summary.py` lines 372–389). An in-process call without an explicit capture/suppress contract can duplicate the summary body, leak `REPORT_GATE` into the wrong stream, or break orchestrator marker extraction. The plan does not specify a capture layer equivalent to the bash redirect.  
- **Same pattern on Step 5c success path:** `design-step5c.sh` lines 327–334 redirect render; markers on wrapper stdout.

### FINDING_5: Quiet-mode KV registration incomplete for failure-report stdout

- **Severity:** important  
- **Plan section:** `### UPDATED: python/cli.py` — add verbs to `_DESIGN_LIFECYCLE_STDOUT_KEYS`  
- **Concern:** `design-failure-report.sh` emits orchestrator-parsed KVs (`DESIGN_FAILURE_REPORT_DECISION`, `DESIGN_FAILURE_REPORT_REASON`, `DESIGN_FAILURE_REPORT_ARTIFACT`) on the contract stream. The plan registers the verb but does not list these keys. Under quiet wrappers, unstated keys can be swallowed (plan’s own failure mode: “Missing `_MACHINE_STDOUT_KEYS` entries silently swallow KV stdout”). `STAGED` / `PRESERVED` / `TERMINAL_STATE_FILE` need the same explicit treatment for `design stage-terminal-state`.  
- **Evidence:** Current registry at `python/cli.py` lines 470–503 has no `stage-terminal-state`, `failure-report`, or `step-final-summary`.

## Recommendations (plan edits only; no implementation)

1. Add a **`### NEW: python/test_design_failure_report.py`** (or an explicit subsection) that maps **each** `test-design-failure-report.sh` case to a named pytest (decision, reason, artifact paths).  
2. In `step_final_summary_main` / `failure_report_main` design notes, require a **`_capture_contract_stdout` helper** (or `io.StringIO` + log files) mirroring bash `>render-final-summary.stdout.log` and `design-failure-report.*.log`.  
3. Extend `python/test_design_summary.py` with a **non-mocked** test: seed sidecar files → assert `REPORT_GATE_SIDECARS_FILE=` and no summary duplication when called from wrapper context.  
4. Register **all emitted KV keys** for the three new verbs in `_DESIGN_LIFECYCLE_STDOUT_KEYS` / `_MACHINE_STDOUT_KEYS` (document the key list in the plan).  
5. Add explicit pytest for **`STAGED=false` + exit 0** and Step 5c/clarify append-failure with `--exit-code 0`.  
6. Do **not** delete `test-design-failure-report.sh` / `test-design-stage-terminal-state.sh` until the matrix above is green in pytest (plan acceptance criterion).
