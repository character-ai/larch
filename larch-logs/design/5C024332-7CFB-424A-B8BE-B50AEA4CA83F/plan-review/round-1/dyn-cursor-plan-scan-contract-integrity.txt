## Findings

### 1. architecture — `python/larch/lint/engine.py` (planned)

The plan draws a clear boundary for lazy AST parsing (Approach 6-7) and says the frozen `SourceFile` model must not be weakened, but it never says how to cache inside a frozen dataclass. In this repo, `python/pyrightconfig.json` uses `"typeCheckingMode": "strict"`, and there is no existing lazy-cache-on-frozen pattern to copy. Without an explicit slot/holder design, implementation is likely to hit `FrozenInstanceError` or lean on untyped workarounds.

**Suggested revision:** Specify the mutable-slot pattern in the `engine.py` plan bullets and keep the existing lazy-AST tests.

### 2. correctness — `python/tests/lint/test_lint_engine.py` (planned)

Path containment and filtering boundaries are otherwise well staged (git discovery first, then validate/filter, then load). The gap is operator-supplied `paths` that are syntactically valid but match nothing in the tracked set after filtering. The test list names this case; the approach does not.

**Suggested revision:** Document exit `2` vs clean `0` for unmatched requested paths and encode it in tests.

### 3. correctness — `python/larch/lint/engine.py` (planned)

Buffered output and “errors win over findings” (Approach 11-12, Failure modes) align with existing lint exit semantics (`0` / `1` / `2`) seen in modules like `lint_common.py` and tests such as `test_lint_agent_tool_contract.py` (findings on stdout, empty stderr on exit `1`). The duplicate-finding edge case is the remaining determinism hole.

**Suggested revision:** Close the dedupe vs sort-only decision in Approach before implementation.

## Assessment (boundaries the plan gets right)

- **Discovery vs containment vs load:** Steps 2-5 separate injected `git ls-files --cached` discovery, path normalization/containment, and strict UTF-8 loading. That matches `Runner` / `CommandResult` in `python/larch/core/proc.py` (lines 14-35) and G-Py-7 injection.
- **Lazy AST vs syntax policy vs detect:** Parse-on-access, `fail`/`skip`, then detector validation before suppression, is a coherent pipeline order.
- **Partial stdout / repo writes:** Buffer-then-emit plus explicit tests for no partial stdout on later validation failure and no repository mutation match the scan-only contract and NEVER-style side-effect isolation.
- **Runner test fake:** A recording fake with argv/cwd capture matches patterns in `python/tests/implement/test_ci_monitor.py` (lines 46-80); the protocol surface is `run(argv, *, cwd, env, check, ...)` → `CommandResult`.
- **Minimum-change scope:** Two new files, no CLI registration, no baseline/write mode, and no edits to existing lint entry points keep piece 1 appropriately narrow versus the parent #6988 vision.
