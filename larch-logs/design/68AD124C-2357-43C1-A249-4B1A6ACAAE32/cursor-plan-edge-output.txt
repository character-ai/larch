1. **[correctness]** [`skills/design/references/approval-gates.md:86-87`](skills/design/references/approval-gates.md), [`skills/design/references/approval-gates.md:104`](skills/design/references/approval-gates.md), [`skills/design/SKILL.md:786`](skills/design/SKILL.md) — Gate B settled paths still say “proceed to Step 3b” after Step 2b.5; the plan only adds a forward-reference for Step 3.6, not replacements on the Apply all / Go through each / zero-findings branches. **Concern:** On every normal HARD run, the orchestrator can skip the assessor entirely. **Revision:** Replace “proceed to Step 3b” with “proceed to Step 3.6 (HARD-only; skip on non-HARD), then Step 3b” on Gate B terminal paths, SKILL.md line 786, and Step 2b.5 callable prose at line 644.

2. **[correctness]** [`skills/design/SKILL.md:158`](skills/design/SKILL.md) vs [`skills/design/scripts/render-final-summary.sh:43-48`](skills/design/scripts/render-final-summary.sh) — The plan says `render-final-summary.sh` needs no change, but the script rejects unknown `--outcome` values. **Concern:** Stop on assessor WORSE runs the Final summary block with `SUMMARY_OUTCOME=cancelled-assessor-worse` and exits 2 (“outcome not in enumeration”), so cancellation UX breaks. **Revision:** Add `cancelled-assessor-worse` to the `case` allowlist, extend `test-render-final-summary.sh`’s outcome loop, and drop the “no script change” claim.

3. **[correctness]** [`skills/design/scripts/assess-plan-round.sh`](skills/design/scripts/assess-plan-round.sh) (planned steps 4–5) — On `dispatch-plan-assessors.sh` non-zero exit, step 4 sets `ASSESSOR_VERDICT=not-worse` / `degraded-default-open`, but step 5 still calls `tally-plan-assessor.sh`. **Concern:** Stale or partial assessor output files can be tallied into a false `worse-majority` after a failed dispatch. **Revision:** On dispatch failure, skip tally, omit `assessor-verdict-round-<N>.txt` (or write only after a successful dispatch), and emit the degraded KV block directly.

4. **[risk-integration]** [`skills/design/SKILL.md:266`](skills/design/SKILL.md) — The Final summary block orchestrator contract omits `cancelled-assessor-worse` even though Step 3.6 Stop exports it. **Concern:** Prompt-side agents may treat the new outcome as invalid and skip or mishandle the Final summary fence. **Revision:** Add `cancelled-assessor-worse` to the line-266 enumeration alongside other `cancelled-*` tokens.

5. **[architecture]** [`skills/design/SKILL.md:30`](skills/design/SKILL.md) — Anti-halt sub-step chain is still `3→3.5→3b` with no `3.6`. **Concern:** Models can halt after Gate B or treat 3b as the immediate successor, especially on re-entry from Gate C(c). **Revision:** Update the chain to `3→3.5→3.6→3b` and list Gate C(c) re-entry as returning to Step 3 (then 3.5 → 3.6 → 3b).

6. **[correctness]** Plan edge cases §203 (`0-0-3 → WORSE`) vs tally rule (lines 85–89, 204) — Three parseable `TIE` votes yield `worse_count=0`, so the strict rule yields `NOT_WORSE`, not WORSE. **Concern:** Harness/docs will encode the wrong boundary and mislead operators. **Revision:** Change the edge-case bullet to `0-0-3 (three TIE) → NOT_WORSE` and add an explicit `test-tally-plan-assessor.sh` case.

7. **[risk-integration]** Planned `assess-plan-round.sh` — Step 3 passes `--feature-file "${IMPLEMENT_TMPDIR:-$DESIGN_TMPDIR}/feature-description.txt"` to `plan-review-loop.sh` ([`skills/design/SKILL.md:731`](skills/design/SKILL.md)), but the orchestrator argv contract does not specify the same resolution for assessors. **Concern:** Nested `/implement` shells can leave assessors with a missing or wrong feature frame while review still works. **Revision:** Document and implement the same `IMPLEMENT_TMPDIR` fallback when calling `render-assessor-prompt.sh` / `dispatch-plan-assessors.sh`.

8. **[latent]** [`skills/design/SKILL.md:143-156`](skills/design/SKILL.md) (planned Step 3.6) — Step 3.6 prose says “invoke `assess-plan-round.sh`” and parse KV, but unlike Step 3 there is no fenced Bash block with `read-cursor`, KV parsing, and Continue/Stop branching. **Concern:** Inconsistent orchestrator wiring risks silent skips or wrong `AskUserQuestion` gating. **Revision:** Add a Step 3.6 fenced block mirroring the Step 3 `_plan_review_out` parse pattern (including `ROUND_CURSOR` from `read-cursor` for `write-after --round`).
