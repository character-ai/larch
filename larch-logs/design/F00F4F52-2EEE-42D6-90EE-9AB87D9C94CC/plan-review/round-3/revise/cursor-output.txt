## Edge cases

- **Codex unavailable**: still emit the generic Codex slot in rounds 1–2; waterfall falls back through existing phases. Test both rounds 1 and 2 on the unavailable path in each dispatcher so a round-specific gate cannot hide behind round-1-only coverage.
- **Round 3+**: do not emit the generic slot; audit fails only generic Codex rows (`generalist` / `codex-plan-generic`), not specialist or dynamic Codex rows.
- **Global model role**: specialist Codex rows receive `review`; generic Codex row receives `default`.
- **Design prompt path**: generic design slot must use `prompt_file` from `render plan-review` so plan/feature context and TSV contract are injected; bare `agent` + `mode=description` lacks plan scope.
- **Static vs dynamic counts**: generic design row lives in `_static_slot_rows`; bump static/total manifest counts, not `DYNAMIC_SLOT_COUNT`.
- **No fallback round 1**: preserve existing `--no-fallback` policy when both vendors present and `round_num < 2`; failed generic Codex handled like other dropped peer rows.
- **Collector parsing**: design consumes structured JSONL from rendered plan-review prompts; implement maps `codex-generalist-output.txt` to `generic`.
- **Multi-round Step 5**: round 3+ may still carry specialist/dynamic Codex rows; the narrowed audit must not treat those as violations.

## Failure modes

- If `_launch_slot` ignores per-slot `model_role`, the generic reviewer uses the review model instead of GPT 5.5.
- If the design generic row uses bare `agent` instead of `prompt_file`, the slot prompts without plan scope and yields `NOT_SUBSTANTIVE` or empty findings.
- If the generic row is gated on `codex_present` / `codex_available`, `/design` and `/implement` lose parity and violate unconditional rounds 1–2 contract.
- If round gating uses `< 2` instead of `<= 2`, round 2 misses the generic reviewer.
- If availability gating is applied only in round 1 tests, a round-2-only `codex_present` / `codex_available` guard can ship while round-1 unavailable tests still pass.
- If audit fails **any** `tool=codex` row in round 3+, compliant multi-round manifests with specialist/dynamic Codex keep failing even when generic gating is correct; the scan must flag only generic slots in round ≥ 3.
- If tests bump `DYNAMIC_SLOT_COUNT` instead of static/total counts, a missing static generic row can slip through.
- If only `test_panel_dispatch_static_slot_matrix` is updated, stale totals in `test_panel_dispatch_dynamic_rows_render_full_scaffold` (12 → 13) and `test_dispatch_panel_pre_scouted_valid_dynamic_slots` (`SLOT_COUNT` 10 → 11) leave the PR unverifiable.
- Round-1-only generic tests miss a `< 2` round gate that drops round 2 on the design path.
- Round-1-only unavailable-Codex tests miss a round-2-only availability gate that drops the generic reviewer when Codex is absent.
