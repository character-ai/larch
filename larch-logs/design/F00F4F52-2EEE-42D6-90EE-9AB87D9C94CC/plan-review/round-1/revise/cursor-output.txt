## Edge cases

- **Codex unavailable**: still emit the generic Codex slot in rounds 1–2; waterfall falls back through existing phases.
- **Round 3+**: do not emit the generic slot; audit fails any Codex row.
- **Global model role**: specialist Codex rows receive `review`; generic Codex row receives `default`.
- **Design prompt path**: generic design slot must use `prompt_file` from `render plan-review` so plan/feature context and TSV contract are injected; bare `agent` + `mode=description` lacks plan scope.
- **Static vs dynamic counts**: generic design row lives in `_static_slot_rows`; bump static/total manifest counts, not `DYNAMIC_SLOT_COUNT`.
- **No fallback round 1**: preserve existing `--no-fallback` policy when both vendors present and `round_num < 2`; failed generic Codex handled like other dropped peer rows.
- **Collector parsing**: design consumes structured JSONL from rendered plan-review prompts; implement maps `codex-generalist-output.txt` to `generic`.

## Failure modes

- If `_launch_slot` ignores per-slot `model_role`, the generic reviewer uses the review model instead of GPT 5.5.
- If the design generic row uses bare `agent` instead of `prompt_file`, the slot prompts without plan scope and yields `NOT_SUBSTANTIVE` or empty findings.
- If the generic row is gated on `codex_present` / `codex_available`, `/design` and `/implement` lose parity and violate unconditional rounds 1–2 contract.
- If round gating uses `< 2` instead of `<= 2`, round 2 misses the generic reviewer.
- If audit only exempts the generic row but still fails round-2 specialist Codex, compliant manifests keep failing (or naive exemptions hide round-3 regressions); the scan must allow all Codex in rounds 1–2 and fail only round ≥ 3.
- If tests bump `DYNAMIC_SLOT_COUNT` instead of static/total counts, a missing static generic row can slip through.
