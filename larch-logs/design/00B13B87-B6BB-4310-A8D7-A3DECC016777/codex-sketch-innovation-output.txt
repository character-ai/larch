I would make `plan-review-loop.sh` a small state machine, not a bigger linear script. Keep the current single-pass body as `run_one_round(round_num)`, then add a loop that tracks `round_num`, `convergence_streak`, `accepted_count`, `important_accepted_count`, `degraded`, and plan hashes. After each tally, snapshot the round artifacts into `plan-review/round-N/`, compute counts from `accepted-plan-findings.md`, and either stop or call `revise-plan-with-waterfall.sh`. A useful twist: make each round transactional. Write active artifacts top-level for compatibility, but immediately copy a distilled, immutable round bundle plus `round-summary.env` before any revision mutates `plan.txt`.

Extend `test-plan-review-loop.sh`, then add `scripts/test-design-multi-round-integration.sh` for cap, convergence, revision failure, final artifact promotion, and publish allowlist behavior.

The main tradeoff is where to put state. The obvious path keeps top-level files as the active workspace and copies them into round folders; it is low risk and matches current consumers. The cleaner path runs each round inside its own `round-N/` workdir, then promotes the final artifacts to top level; that reduces accidental cross-round leakage but may force more argv plumbing. A crazy but plausible option: keep a machine-readable `round-ledger.ndjson` as the primary contract, then derive `review-round-count.txt`, final KVs, and publish manifests from it. That would make pause/resume and forensic publishing easier later, but it is probably too much schema for this piece unless the tests start fighting shell state.
