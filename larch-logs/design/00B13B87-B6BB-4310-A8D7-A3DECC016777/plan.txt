# Implementation Plan — Multi-round plan-review loop integration and publishing (#2871)

## Approach

Convert today's orchestrator-driven multi-round flow (SKILL.md Gate-C re-runs of single-pass `plan-review-loop.sh`) into a script-managed inner loop **inside** `plan-review-loop.sh`. One Step 3 entry now runs N internal rounds via the script; the outer Gate-C "Re-run review panel" remains the only way to start a fresh loop. Multi-round mode is gated on explicit `--round-cap` argv (`ROUND_CAP_ARG_SEEN=1`); without it, the script preserves today's legacy single-pass behavior including `LOOP_STATUS=complete` and no auto-apply.

When multi-round mode is active and `manual_gate_b=false`, all accepted in-scope findings auto-apply via `revise-plan-with-waterfall.sh` (Piece 4) every round including the final/convergence round. When `manual_gate_b=true`, the loop runs single-pass per round and defers all auto-apply to Gate B (preserving the manual user-choice contract).

The "assessor" concept is deferred to #2953 and out of scope here.

### UPDATED: `skills/design/scripts/plan-review-loop.sh`

Refactor the existing single-pass body (current lines 189-710) into a private function `_run_plan_review_round(round_num)`. Wrap that function in an outer `while` loop driven by new argv and inner state. The function moves `_dedup_failed=0` to its first line (FINDING_12 — per-round reset).

New argv (extending current set):

- `--round-cap N` — default value when omitted: `${LARCH_DESIGN_ROUND_CAP:-5}`. Maximum round number the loop will run. **When `--round-cap` is OMITTED on argv, set `ROUND_CAP_ARG_SEEN=0` and run LEGACY single-pass mode**: NO multi-round behavior, NO auto-apply via revise, NO `converged`/`cap-hit`/`revision-failed` emissions, preserve current `LOOP_STATUS=complete` semantics, write `round-$ROUND_NUM/findings-classification.tsv` and exit after the single tally (FINDING_5).
- `--convergence-threshold N` — default `${LARCH_DESIGN_CONVERGENCE_THRESHOLD:-3}`. Only consulted in multi-round mode.
- `--round-num N` (existing) — STARTING round; default 1. Backward-compat preserved.

New inner state (function-local; initialized at outer loop entry, NOT global):

- `round_num`, `convergence_streak`, `collect_ok_count`, `collect_failure_count`, `loop_status_override`, `revise_status`, `revise_winning_tier`.

New per-round helpers:

- `_count_important_findings <path>` — counts `### FINDING_N:` blocks whose body contains `- **Severity**: important`. Counts ONLY blocks inside `accepted-plan-findings.md`. Uses awk/grep — no Python.
- `_count_collector_evidence` — populates `collect_ok_count` and `collect_failure_count` by parsing the collector's structured output (`STATUS=OK` entries). Used by the zero-findings gate (FINDING_13).
- `_snapshot_round_dir(round_num)` — copies session-root artifacts into `$DESIGN_TMPDIR/plan-review/round-N/` using `design_round_artifact_included` from the shared lib. Symlink-safe: each source is checked with `[ -L ]`; if any source is a symlink, refuse the snapshot and emit `WARN=`. **Rmdir safety (FINDING_7 echo)**: before the cleanup at Step 3 entry that purges stale `plan-review/round-*/`, validate that `plan-review` is a real directory (not a symlink) under the session root via `cd "$DESIGN_TMPDIR/plan-review" && pwd -P`; only then delete validated child directories matching `round-[0-9]+`.
- `_write_round_summary(round_num)` — writes `$DESIGN_TMPDIR/plan-review/round-N/round-summary.env` AFTER all final-state mutations for the round are known. Schema (FINDING_8):
  - `ROUND_NUM`, `LOOP_STATUS` (set on terminal rounds only; empty on non-terminal), `REASON` (`zero-findings`/`streak`/`cap-hit`/`revision-failed`/empty), `CONVERGENCE_STREAK`, `ACCEPTED_COUNT`, `IMPORTANT_ACCEPTED_COUNT`, `DEGRADED_PANEL`, `TALLY_PLAN_REVIEW_STATUS`, `AGGREGATOR_STATUS`, `REVISE_STATUS`, `REVISE_WINNING_TIER`, `PLAN_HASH_BEFORE_REVISE`, `PLAN_HASH_AFTER_REVISE`, `COLLECT_OK_COUNT`, `COLLECT_FAILURE_COUNT`.
  - Move `DEGRADED_PANEL=1` BEFORE `_write_round_summary` on the revision-failed branch (FINDING_8).
- `_clear_session_root_review_artifacts` — at the START of each round (FINDING_10), truncate session-root `findings.md`, `findings-in-scope.md`, `findings-oos.md`, `accepted-plan-findings.md`, `rejected-findings.md`, `oos.md`, `oos-this-round.md`, `ballot.txt`, `voting-tally.md` so a tally-error mid-round cannot leak stale findings into the next round.
- `_accumulate_round_oos(round_num)` — after each round's tally, copy the round's `oos.md` to `$DESIGN_TMPDIR/plan-review/round-N/oos.md`, then union into the cumulative `$DESIGN_TMPDIR/oos-accepted-design.md` with dedup on the OOS block's `**Description**:` text (case-insensitive substring match; first occurrence wins) (FINDING_3). Step 5b reads this cumulative file.
- `_run_revise_with_status_parse(round_num)` — invokes `revise-plan-with-waterfall.sh` and PARSES stdout for `REVISE_STATUS=` (FINDING_1). The helper validates: rc=0 AND `REVISE_STATUS=ok` → success; rc=0 AND `REVISE_STATUS=failed-*` → treat as revision-failed; rc!=0 → revision-failed. Status values per `revise-plan-with-waterfall.md:48`: `ok`, `failed-no-patch`, `failed-validation`, `failed-apply`.

Outer loop pseudocode (multi-round mode only; legacy single-pass mode skips the loop and emits `LOOP_STATUS=complete` after one pass):

```
if ROUND_CAP_ARG_SEEN == 0:
    # LEGACY SINGLE-PASS MODE — preserve existing contract verbatim
    _run_plan_review_round(ROUND_NUM)
    emit_loop_kvs complete ... (existing behavior; no auto-apply, no converged/cap-hit)
    exit 0

# MULTI-ROUND MODE
round_num = ROUND_NUM
convergence_streak = 0
manual_mode = read manual_gate_b from $DESIGN_TMPDIR/run-params.json (jq, false on missing)
while round_num <= ROUND_CAP:
    _clear_session_root_review_artifacts
    _run_plan_review_round(round_num)        # _dedup_failed reset inside this function
    # Branch order is load-bearing: each check below must short-circuit before later checks
    if loop_status_override == "main-agent-vote-required":
        _write_round_summary(round_num, LOOP_STATUS=main-agent-vote-required)
        write_step3_result_env LOOP_STATUS=main-agent-vote-required ROUNDS_COMPLETED=round_num
        emit_loop_kvs main-agent-vote-required ...
        exit 0
    if _paths_readable == 0:
        write_step3_result_env LOOP_STATUS=panel-failed ROUNDS_COMPLETED=round_num
        emit_loop_kvs panel-failed ...
        exit 1
    if TALLY_PLAN_REVIEW_STATUS == "tally-error":              # FINDING_10
        _snapshot_round_dir(round_num)
        _write_round_summary(round_num, LOOP_STATUS=tally-error, REVISE_STATUS=skipped)
        write_step3_result_env LOOP_STATUS=tally-error ROUNDS_COMPLETED=round_num
        emit_loop_kvs tally-error ...
        exit 0
    _accumulate_round_oos(round_num)                            # FINDING_3
    _count_collector_evidence                                    # FINDING_13
    ACCEPTED_COUNT = grep -c '^### FINDING_' accepted-plan-findings.md
    IMPORTANT_ACCEPTED_COUNT = _count_important_findings accepted-plan-findings.md
    PLAN_HASH_BEFORE_REVISE = git hash-object --no-filters plan.txt
    if ACCEPTED_COUNT == 0:
        if collect_ok_count == 0:
            # zero findings + zero collector evidence = false-positive convergence
            _snapshot_round_dir(round_num)
            _write_round_summary(round_num, LOOP_STATUS=degraded-empty-collector, REVISE_STATUS=skipped)
            DEGRADED_PANEL = 1
            write_step3_result_env LOOP_STATUS=degraded-empty-collector ROUNDS_COMPLETED=round_num
            emit_loop_kvs degraded-empty-collector ...
            exit 0
        # legitimate zero-findings convergence
        _snapshot_round_dir(round_num)
        _write_round_summary(round_num, LOOP_STATUS=converged, REASON=zero-findings, REVISE_STATUS=skipped)
        write_step3_result_env LOOP_STATUS=converged REASON=zero-findings ROUNDS_COMPLETED=round_num
        emit_loop_kvs converged ... REASON=zero-findings
        exit 0
    if manual_mode == true:                                      # FINDING_9
        # Manual Gate B: no inner auto-apply; do not run revise
        # Treat the loop as one round and exit so manual Gate B applies findings.
        _snapshot_round_dir(round_num)
        _write_round_summary(round_num, LOOP_STATUS=complete, REASON=manual-gate-b, REVISE_STATUS=skipped)
        write_step3_result_env LOOP_STATUS=complete REASON=manual-gate-b ROUNDS_COMPLETED=round_num
        emit_loop_kvs complete ... REASON=manual-gate-b
        exit 0
    _run_revise_with_status_parse(round_num)                     # FINDING_1
    PLAN_HASH_AFTER_REVISE = git hash-object --no-filters plan.txt
    if revise_status != "ok":
        DEGRADED_PANEL = 1                                        # FINDING_8: before _write_round_summary
        _snapshot_round_dir(round_num)
        _write_round_summary(round_num, LOOP_STATUS=revision-failed, REVISE_STATUS=revise_status)
        write_step3_result_env LOOP_STATUS=revision-failed ROUNDS_COMPLETED=round_num REVISE_STATUS=revise_status
        emit_loop_kvs revision-failed ...
        exit 0
    _run_post_apply_pipeline(round_num)                          # FINDING_4 — dedup sweep + EMIT_PLAN + validator + Step 2b.5
    # post-apply may NOT exit the loop; if Step 2b.5 chose Split-path it exits the skill upstream
    _snapshot_round_dir(round_num)
    if DEGRADED_PANEL == 1:
        convergence_streak = 0
    elif ACCEPTED_COUNT <= CONVERGENCE_THRESHOLD and IMPORTANT_ACCEPTED_COUNT == 0:
        convergence_streak += 1
        if convergence_streak >= 2:
            _write_round_summary(round_num, LOOP_STATUS=converged, REASON=streak, REVISE_STATUS=ok)
            write_step3_result_env LOOP_STATUS=converged REASON=streak ROUNDS_COMPLETED=round_num
            emit_loop_kvs converged ... REASON=streak
            exit 0
    else:
        convergence_streak = 0
    if round_num == ROUND_CAP:
        _write_round_summary(round_num, LOOP_STATUS=cap-hit, REVISE_STATUS=ok)
        write_step3_result_env LOOP_STATUS=cap-hit ROUNDS_COMPLETED=round_num
        emit_loop_kvs cap-hit ...
        exit 0
    _write_round_summary(round_num, LOOP_STATUS="", REVISE_STATUS=ok)   # non-terminal
    round_num += 1
```

- `_run_post_apply_pipeline(round_num)` (FINDING_4) is a NEW helper that mirrors approval-gates.md "Shared post-apply pipeline" steps 1-7: dedup-sweep the freshly revised plan.txt; print `dedup-sweep: removed <N> duplicate line(s) from plan.txt`; run `ACTION=EMIT_PLAN` via `design-driver.sh`; run `invoke-plan-validator.sh "$DESIGN_TMPDIR/plan.txt"`; run Step 2b.5 (`check-plan-size.sh`). If Step 2b.5 reports hard trigger / partition request, the loop ABORTS and exits with `LOOP_STATUS=plan-size-trigger ROUNDS_COMPLETED=round_num`; SKILL.md handles the Split/Cancel `AskUserQuestion` upstream after Step 3 returns. Dedup sweep is performed by the loop helper itself via the same prompt-side reasoning as Gate B today (no separate dedup script needed); for the loop, since it runs inside a bash script, the dedup sweep is best-effort using regex-based duplicate-line detection. (Note: this is a divergence from Gate B's LLM-driven dedup; document the trade-off in plan-review.md.)
- `write_step3_result_env` (FINDING_15) writes `$DESIGN_TMPDIR/.step3-plan-review-result.env` with normalized KVs (`LOOP_STATUS`, `ACCEPTED_COUNT`, `IMPORTANT_ACCEPTED_COUNT`, `DEGRADED_PANEL`, `ROUNDS_COMPLETED`, `REASON`, `REVISE_STATUS`, `CONVERGENCE_STREAK`, `AGGREGATOR_STATUS`, `TALLY_PLAN_REVIEW_STATUS`, `VOTING_TALLY_FILE`, `VOTER_1_PARSE_RATE_STATUS`, `COLLECT_OK_COUNT`, `COLLECT_FAILURE_COUNT`). Single canonical file consumed by SKILL.md Step 3.5 and Gate B prose.

## Edge cases

- **Legacy single-pass back-compat is gated on argv presence, not value** (FINDING_5). `--round-cap 1` is NOT legacy mode; it's multi-round mode with a 1-round cap (auto-apply still runs). `--round-cap` OMITTED is legacy. Make this explicit in the argv parser via an `ARG_SEEN` flag set when the case match fires; the env var fallback `${LARCH_DESIGN_ROUND_CAP:-5}` does not flip the flag.
- **REVISE_STATUS values are not exhaustive** (FINDING_1). Per `revise-plan-with-waterfall.md:48`, valid values are `ok`, `failed-no-patch`, `failed-validation`, `failed-apply`. If a future Piece adds a new failed-* value, the loop's "any non-ok = revision-failed" check still works. If a future Piece changes `ok` to e.g. `success`, the loop will treat success as failure — document the coupling clearly in both sibling docs.
- **Manual mode with multi-round flag** (FINDING_9). The loop exits after one round when `manual_gate_b=true`, even if `--round-cap 5` is set. This is intentional — the user's `--manual` flag overrides the multi-round behavior. Tests cover this exit. Document that `--manual` + `--round-cap` is supported (no error), but multi-round semantics are skipped.
- **Post-apply pipeline failure inside the loop** (FINDING_4). If `invoke-plan-validator.sh` reports `defects-found` mid-loop, the validator's defect-found AskUserQuestion fires INSIDE Step 3 (mid-loop). This is a UX wrinkle — the user gets prompted during what was meant to be an autonomous loop. Mitigation: on `defects-found` inside the loop's post-apply pipeline, exit the loop with `LOOP_STATUS=plan-validator-defects` and let SKILL.md Step 3 raise the AskUserQuestion at the normal post-Step-3 boundary. Cleaner; preserves loop autonomy.
- **Step 2b.5 hard-trigger mid-loop** (FINDING_4). If the auto-applied plan exceeds 800 lines or 1500 diff lines mid-loop, Step 2b.5 fires. The loop must NOT fire `AskUserQuestion` inside itself; exit with `LOOP_STATUS=plan-size-trigger`, let SKILL.md Step 3 handle the Split/Cancel prompt at the post-Step-3 boundary. (Already in the pseudocode.)
- **OOS dedup heuristic** (FINDING_3). Simple substring match on `**Description**:` may over-collapse different OOS items with similar phrasing. Trade-off: simple and predictable vs precise. Document the heuristic; refine later if false positives are observed.
- **Symlink safety in cleanup** (FINDING_7 echo). The Step 3 entry cleanup of `plan-review/round-*/` validates via `cd "$DESIGN_TMPDIR/plan-review" && pwd -P` and only deletes resolved children matching `round-[0-9]+`. If `plan-review` itself is a symlink, refuse cleanup and emit a warning; design-log-publish.sh's existing symlink rejection will catch any pollution.
- **`.step3-plan-review-result.env` corruption** (FINDING_15). If the loop crashes after partial writes to the result env, SKILL.md must treat malformed/missing keys as `LOOP_STATUS=panel-failed` and route accordingly. Defensive parsing in SKILL.md Step 3.
- **Allowlist drift detection** (FINDING_16). The `test-lib-design-round-artifacts.sh` harness asserts include/exclude decisions for every basename emitted by `_run_plan_review_round`. Test fixtures derived from a live run prevent silent additions to the loop's output from going un-allowlisted at publish time.

## Failure modes

1. **Auto-apply writes a plan that fails the next round's review** — the waterfall introduces a regression no reviewer catches before convergence. *Earliest signal*: `IMPORTANT_ACCEPTED_COUNT` rising across rounds despite convergence intent. *Mitigation*: `round-summary.env` records `PLAN_HASH_BEFORE_REVISE`/`PLAN_HASH_AFTER_REVISE` so the user can diff via Gate C. Defer aggressive validation to #2953.
2. **Allowlist drift between loop snapshot and publish** (FINDING_16). The shared lib + drift test mitigate. Concrete example: if a future Piece adds `findings-classification-v2.tsv` and updates only the loop's snapshot, the publish would fail closed and the integration harness would catch it.
3. **`.step3-plan-review-result.env` parser ambiguity** (FINDING_15). If a value contains an `=` or newline, naive `key=value` parsing breaks. Mitigation: the writer escapes newlines as `\n` literals and forbids `=` in values by design (no user content goes into this file; only enum keys/values from a controlled vocabulary). Document in the sibling .md.
