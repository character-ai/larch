1. **correctness** — `skills/design/scripts/revise-plan-with-waterfall.sh:348-386`

The proposed loop checks `revise_rc != 0`, but the existing helper exits `0` even when it emits `REVISE_STATUS=failed-no-patch`, `failed-validation`, or `failed-apply`. That makes the planned `revision-failed` branch mostly unreachable.

Suggested revision: parse the helper stdout and require `REVISE_STATUS=ok`. Treat any other status as `LOOP_STATUS=revision-failed`.

2. **risk-integration** — `skills/design/scripts/revise-plan-with-waterfall.sh:104-108`, `scripts/design-log-publish.sh:352-367`

The plan says to disallow `plan-review/round-N/revise/`, but the current revise helper writes all revise artifacts there. Publishing will fail closed once the loop auto-applies anything.

Suggested revision: either move revise artifacts to `$DESIGN_TMPDIR/revise/round-N/` in the helper, or explicitly allow a constrained nested `revise/` subtree in publishing.

3. **correctness** — `skills/design/scripts/plan-review-loop.sh:661-676`, `skills/design/scripts/tally-plan-review.sh:121-133`

The pseudocode does not stop on `TALLY_PLAN_REVIEW_STATUS=tally-error`. Some tally errors happen before `accepted-plan-findings.md` is truncated, so a later count can see stale findings.

Suggested revision: branch on `tally-error` before counting, revising, snapshotting as success, or checking convergence.

4. **risk-integration** — `skills/design/SKILL.md:1037`, `skills/design/scripts/tally-plan-review.sh:103-105`

The unchanged main-agent vote path reruns tally without `--findings-classification-out`, so tally defaults to `round-1`. That breaks internal round numbering.

Suggested revision: pass the current completed round into the main-agent tally rerun and write classification into that round’s directory.

5. **architecture** — `skills/design/scripts/plan-review-loop.md:12-20`, `skills/design/scripts/plan-review-loop.sh:699-705`

The compatibility story is internally inconsistent. The plan says `complete` and single-pass behavior remain, but the pseudocode exits as `converged` or `cap-hit`.

Suggested revision: define an explicit legacy single-pass mode, or update contracts/tests to accept the new statuses and side effects.

6. **code-quality** — `Makefile:4-5`

The new integration harness is not paired with a Makefile update in the plan.

Suggested revision: add `Makefile` to the plan, wire the new target into a shard, and update lint docs if target documentation is expected.

7. **correctness** — `skills/design/scripts/plan-review-loop.sh:22`, `skills/design/scripts/plan-review-loop.sh:681-686`
