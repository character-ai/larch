# /design clarify loop: two-phase design-clarify.sh wrapper

**Problem.** The clarify branch (Step 0b sub-step 3) is roughly eight prose-directed raw commands around one judgment point: `clarify state`, request-comment fetch, `redact secrets`, `named-block write --marker plan`, REPO resolution, a `set +e` publish capture of `design-log-publish.sh` with `PUBLISH_OK` parsing and failure appends, `clarify comment-post --kind response`, `clarify label --action remove`, and a guarded `tracking-issue-write.sh rename --state designing`. Prompt-side composition of this sequence is the error class the /implement seeder issue #4016 exists to prevent.

**Proposal.**

- New `skills/design/scripts/design-clarify.sh` with two phases. `--phase fetch`: clarify state plus request-comment fetch; emits the request body path and state KVs. `--phase publish`: everything after the operator-composed response file exists (redact, plan write, publish with `PUBLISH_OK` parse and Warnings append on failure, comment-post, label removal, conditional rename, `SUMMARY_OUTCOME=cancelled-clarify` handoff), preserving the existing guards: stop before publish on plan-write failure per implement Preflight semantics; rename only when `SESSION_ID` is non-empty and `PUBLISH_OK=true`; never emit `--state designed` here.
- The LLM keeps `AskUserQuestion` and composing the clarify response content file via the Write tool.

**Acceptance.**

- Clarify branch: two Bash calls plus the existing Final summary fence; byte-compatible comment, label, and rename behavior and exit-0 semantics.
- Offline harness covers plan-write failure, publish failure, empty `SESSION_ID`, and the happy path.
