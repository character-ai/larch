- **Missing launcher issue:** Wrapper falls back to sourced `ISSUE_NUMBER`; if neither exists, it fails before clarify commands.
- **Step 0a source-env timing:** `skills/design/SKILL.md` passes `--issue "$ISSUE_NUMBER"` because `source-env.sh` may not yet carry `ISSUE_NUMBER` on `ROUTE=clarify`.
- **Route-state repo timing:** On `ROUTE=clarify`, Step 0 init may not have populated session `REPO`, so the wrapper falls back to `$DESIGN_TMPDIR/.design-step0-route-state.env`.
- **Missing plugin root:** Wrapper resolves from `CLAUDE_PLUGIN_ROOT` or phase-driver helper and fails clearly if no plugin root can be resolved.
- **Missing durable request id:** Publish fails before redaction and plan write.
- **Secret redaction failure:** Publish fails before plan write and before GitHub clarify mutations.
- **Plan write failure:** Stop before publish and before GitHub clarify mutations.
- **Publish failure:** Keep the successful plan write. Force `PUBLISH_OK=false` on non-zero publish exit. Append warning details on a best-effort basis. Continue response comment and label removal. Skip rename unless `PUBLISH_OK=true`. Still allow Final summary when cleanup succeeds.
- **Non-zero publish with `PUBLISH_OK=true`:** Treat as failed publish. Force `PUBLISH_OK=false`, skip rename, continue cleanup, and allow Final summary when cleanup succeeds.
- **Missing `PUBLISH_OK`:** Treat as a publish warning. Continue response comment and label removal. Skip rename. Still allow Final summary when cleanup succeeds.
- **Append-failure failure:** Do not abort clarify cleanup.
- **Empty `SESSION_ID`:** Skip publish and rename. Continue comment-post and label removal. Still allow Final summary when cleanup succeeds.
- **Repo unset:** Use existing repo resolution in Python clarify verbs. The wrapper passes `--repo` only when it has one.
- **Repo bound by Step 0b:** Thread `${REPO:+--repo "$REPO"}` through both launcher fences.
- **Secret-shaped plan content:** Redact `clarify-plan.md` before plan write using stdin/stdout redirects.
- **Secret-shaped response content:** `clarify comment-post` performs its own redaction for the response comment.
- **Cleanup failure:** Surface failed response comment or label removal with a non-zero wrapper exit. Do not rename after failed cleanup. Do not emit `SUMMARY_OUTCOME=cancelled-clarify`. Do not run Final summary.

## Failure modes

- `--issue` is missing and sourced `ISSUE_NUMBER` is unavailable: wrapper exits before any clarify command.
- `ISSUE` is invalid: wrapper exits before any clarify command.
- Plugin root cannot be resolved: wrapper exits before phase work.
- Route-state repo cannot be read: wrapper continues only if `--repo`, sourced `REPO`, or Python repo resolution can cover the call.
- `clarify state` fails: fetch phase emits failure status and exits before `AskUserQuestion`.
- `STATE` is not `awaiting-response`: fetch phase fails before operator composition.
- `comment-fetch` cannot find exactly one request body: fetch phase fails before operator composition.
- Fetch launcher exits non-zero or emits `FETCH_STATUS=failed`: `skills/design/SKILL.md` surfaces the error and terminates before `AskUserQuestion`.
- Fetch result env is missing, symlinked, malformed, or stale: publish phase fails before redaction.
- `clarify-plan.md` or `clarify-response.md` is missing: publish phase fails before redaction.
- `redact secrets` fails for `clarify-plan.md`: publish phase records failure and fails before plan write.
- `named-block write` fails: publish phase records `PLAN_WRITE_OK=false` and runs no later side effects.
- `design-log-publish.sh` exits non-zero, emits `PUBLISH_OK=false`, or omits `PUBLISH_OK`: publish phase records warning metadata and continues to clarify response cleanup.
- `design-log-publish.sh` exits non-zero after emitting `PUBLISH_OK=true`: publish phase forces `PUBLISH_OK=false`, skips rename, records warning metadata, and continues to clarify response cleanup.
- `run-log append-failure` fails: publish phase continues to clarify response cleanup.
- `clarify comment-post` fails: publish phase records `POSTED=false`, skips label removal and rename, omits `SUMMARY_OUTCOME=cancelled-clarify`, and exits non-zero.
- `clarify label --action remove` fails: publish phase records `CHANGED=false`, skips rename, omits `SUMMARY_OUTCOME=cancelled-clarify`, and exits non-zero.
- `tracking-issue rename` fails: publish phase records `RENAMED=false` and does not roll back.
