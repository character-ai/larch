From the 2026-07-09 audit of the architectural-knowledge features.

**Motivation.** `/learn-from-bugs` (added in PR #6465) mines closed bugs into prevention proposals: lint rules, invariants, guideline entries. It seeded the recent invariant and guideline extensions. Nothing triggers it: it writes no durable last-run marker (checked `skills/learn-from-bugs/SKILL.md` and `python/larch/issue/learn_from_bugs.py` on 2026-07-09), so mining happens only when the operator remembers. The invariant set grows from evidence only if the mining actually runs.

**Required change.**

1. A durable last-run marker committed by `/learn-from-bugs` runs: for example `larch-logs/shared/learn-from-bugs-state.json` holding the run date and the highest closed-issue number scanned. Additive, versioned schema per G-Wire-2 (readers tolerate prior shapes; no backfill).
2. An advisory nudge from an existing periodic surface. Proposed host: `/audit-runs` (it already runs on an operator cadence and has the `test-audit-runs` harness). During its run, count closed `[BUG]` issues newer than the marker; when the count exceeds a threshold, print one suggestion line naming the count and the `/learn-from-bugs` command. Never auto-run the skill; cost stays operator-controlled.
3. Threshold as a `Final` in `config.py` per G-Cfg-1 (proposed: `LEARN_FROM_BUGS_NUDGE_THRESHOLD = 25`).
4. Missing marker (feature never ran): nudge with "never run" wording instead of a count.
5. Bug selection must reuse the shared normalized predicate per G-Ext-3, verbatim guidance from `ARCHITECTURAL_GUIDELINES.md`:

```text
after any `gh` search or list call, filter the result set through `larch.issue.title_match`, or the surface's shared predicate, before spending tokens or verdicts on it; never treat the raw search result as the selection.
```

6. Tests: marker write and read (including the never-ran case), threshold boundary, and the audit-runs suggestion line.

**Acceptance criteria.**

- A `/learn-from-bugs` run updates the committed marker.
- `/audit-runs` prints the nudge when the backlog exceeds the threshold and stays silent below it.
- The threshold lives in `config.py`; selection goes through the shared title predicate.

## Proposed Design Outline

### Goals
- Commit a durable `larch-logs/shared/learn-from-bugs-state.json` marker after each `/learn-from-bugs` run.
- Print one advisory suggestion line in `/audit-runs` when closed `[BUG]` backlog exceeds threshold.
- Expose `LEARN_FROM_BUGS_NUDGE_THRESHOLD = 25` in `config.py`.

### Non-goals
- Auto-run `/learn-from-bugs` at any point.
- Modify existing audit-run scan logic, counters, or the filed report body.
- Change the `/learn-from-bugs` Step 5 operator approval gates.

### Approach sketch
- Add `write-state` and `read-state` verbs to `learn_from_bugs.py` (marker read/write + CLI registration).
- Call `write-state` automatically at the end of `/learn-from-bugs` Step 4 (auto-commit, no operator approval).
- Add `bugs-backlog-nudge` verb to `audit_runs.py` that reads the marker, counts closed `[BUG]` issues via `gh`, applies `bug_title_match` filter, and emits a suggestion line when count exceeds threshold.
- Wire `bugs-backlog-nudge` into the `/audit-runs` orchestrator flow (after scan, before report filing).
