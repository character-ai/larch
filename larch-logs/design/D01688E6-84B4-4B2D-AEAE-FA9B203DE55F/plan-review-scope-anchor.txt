## Operator request (verbatim)

> switch all uses of Cursor/auto in larch to Cursor/Composer 2.5.  There should be no more Cursor/auto mentioned anywhere, including pricing table, as we will no longer ever use it for any reason.  The switch effects exclusively Cursor/auto, with upcoming Cursor/Grok 4.5 staying uneffected.

## Goal

Remove the Cursor `auto` model from larch entirely. Every lane that launches Cursor with `--model auto` moves to `composer-2.5` (the existing `CURSOR_DEFAULT_MODEL`). The `("cursor", "auto")` pricing row, the auto display rates, the `CURSOR_AUTO_MODEL` constant, and all "Cursor auto" prose in docs, skills, and doc_fallback strings are deleted. The Grok 4.5 work in #6825 is untouched.

## History and relationships

- #6553 (closed) added one experimental Cursor/auto reviewer lane to compare auto vs Composer 2.5.
- #6721 (closed 2026-07-09) then moved ALL Cursor reviewer lanes to auto and removed the #6553 lane. Its rationale: auto avoided the $0.25/M Teams Token Rate that pinned Composer 2.5 paid at the time.
- This issue reverses #6721 and goes further: it also flips the two fixer lanes that hardcode auto, and deletes the auto pricing surface. Reason: per Cursor docs and staff confirmation (2026-07-10), first-party models (Composer 2.5, Grok 4.5) are now exempt from the Token Rate, so auto lost its pricing advantage; Composer 2.5 base rates beat auto on every component.
- **Blocked by #6825** (Grok 4.5 coder switch): both issues edit the same regions of `python/larch/core/config.py` (cursor model constants, `ROLE_DEFAULTS`) and `python/larch/report/report_tokens_cost.py` (rate table, `display_rates()`). Land #6825 first, then rebase this work on it.

## Proposed Design Outline

### Goals
- Remove the Cursor `auto` model from larch entirely. Every Cursor lane launches `--model composer-2.5` and panel manifests record `resolved_model=composer-2.5`.
- Delete the `("cursor", "auto")` rate row, the `CURSOR_AUTO_MODEL` constant, and all "Cursor auto" prose across code, docs, skills, and generated projections.
- Excise the downstream `cursor_auto_cost` schema and render surface (PR body, final report, `/report-tokens`), per the full-removal decision.

### Non-goals
- Do not relitigate the composer-2.5 Token Rate surcharge values (0.75/0.45/2.75); keep them.
- Do not run `retro_fix_cursor` over committed run logs; legacy cost text stays as written.
- Do not remove the generic per-slot `cursor_model` plumbing from #6553; only auto producers go. Codex and Claude lanes are untouched.

### Approach sketch
- Producer removal first: drop `cursor_model=CURSOR_AUTO_MODEL` overrides so Cursor reviewer slots resolve through the standard chain (`LARCH_CURSOR_MODEL` -> `CLAUDE_PLUGIN_OPTION_CURSOR_MODEL` -> `CURSOR_DEFAULT_MODEL`).
- Replace the two hardcoded fixer lanes (CI recovery, review-and-fix coder) with the standard `resolve_model_args("cursor", with_effort=True)` resolution.
- Rate layer: delete the auto rate row, the `cursor_auto` DisplayRates rate fields, and the `model == CURSOR_AUTO_MODEL` cost special case. Legacy `model="auto"` ledger rows fall back to `DEFAULT_VENDOR_MODEL["cursor"] = "composer-2.5"`.
- Full cost-record removal: drop `cursor_auto_cost` from the RunCost/RunRecord schemas, the "Cursor Auto" render row, and the PR-body "(Composer, Grok, Auto)" segment.
- Delete `CURSOR_AUTO_MODEL`; update doc_fallback strings, the Step 5 banner prose, topology.tsv, regenerate topology.md, and the pinned tests.
