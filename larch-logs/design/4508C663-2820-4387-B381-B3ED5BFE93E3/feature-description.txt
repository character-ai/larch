# Sweep stale SECURITY.md file pointers and add a doc-pointer-paths lint

#### Summary

`SECURITY.md` cites files that no longer exist on main, so a security review that trusts it reaches wrong conclusions about which controls exist. `/learn-from-bugs` (2026-07-14, 174 closed bugs mined) verified 24 dead backticked file pointers in `SECURITY.md` and 0 in `AGENTS.md`. Sweep the stale rows and add a lint so the class cannot regrow. This is one deliverable: the sweep makes the lint land clean with no baseline.

#### Root cause analysis (independently verified 2026-07-14)

The packaging migration moved flat `python/*.py` modules under `python/larch/`, and the subagent overhaul (#7192, #7193) deleted scripts and lanes. Doc sweeps were piecemeal: #7126 fixed four dead `AGENTS.md` pointers, #7218 fixed three stale `SECURITY.md` rows, and #6020 fixed six earlier passages. No mechanical check exists for path-shaped pointers in Tier-1 docs, so identical stale rows survive each sweep. A fence-aware scan on main found 24 dead pointers in `SECURITY.md`, dominated by pre-migration flat names such as `python/ship.py`, `python/plan_review.py`, `python/review_pipeline.py`, `python/rendering.py`, `python/test_stall_recovery.py`, plus deleted scripts such as `skills/design/scripts/assess-plan-round.sh`. Guidelines `G-Md-1` and `G-Md-2` state the rule as prose only; `G-Enf-1` prefers mechanical enforcement.

Backing issues: #7126, #7218, #6020.

#### Scope

- Part 1: re-point or delete every dead file pointer in `SECURITY.md`.
- Part 2: new lint `doc-pointer-paths` scanning `AGENTS.md` and `SECURITY.md`.
- Out of scope: widening the lint to `docs/` (a later issue may do that once the false-positive rate is proven near zero).

#### Enumeration procedure (Part 1 and test fixtures)

Run from the repo root. This is the same rule the lint implements:

```python
import re
from pathlib import Path

prefixes = ("python/", "skills/", "scripts/", "docs/", "hooks/", "agents/", ".claude/", ".claude-plugin/", ".github/")
token_re = re.compile(r"`([^`\n]+)`")
for doc in ("AGENTS.md", "SECURITY.md"):
    in_fence = False
    for lineno, line in enumerate(Path(doc).read_text(encoding="utf-8").splitlines(), 1):
        if line.lstrip().startswith("```"):
            in_fence = not in_fence
            continue
        if in_fence:
            continue
        for tok in token_re.findall(line):
            if any(ch in tok for ch in "<>*${}? ") or "/" not in tok or not tok.startswith(prefixes):
                continue
            probe = tok.split("::", 1)[0].split("#", 1)[0]
            if not Path(probe).exists():
                print(f"{doc}:{lineno}: {tok}")
```

#### Implementation instructions

1. Part 1 sweep. For each dead pointer: when the module moved, update to the current `python/larch/**` path (locate with `git log --follow` or by grepping for the referenced symbol); when the machinery was deleted, delete or rewrite the row to describe the current posture, mirroring how #7218 handled the CI-fixer rows.
2. Part 2 lint, module `python/larch/lint/lint_doc_pointer_paths.py`:
   - Scan `AGENTS.md` and `SECURITY.md` line by line; toggle fenced-code state on lines whose stripped form starts with three backticks; skip fenced lines (the `G-Md-3` rule; see `lint_markdown_heading_fence_state` for the shape).
   - Extract inline-backtick tokens; keep tokens that start with one of the prefixes above, contain `/`, and contain none of `<`, `>`, `*`, `$`, `{`, `}`, `?`, or whitespace.
   - Strip one trailing `::<symbol>` or `#<fragment>` suffix, then require the path to exist under the repo root.
   - Skip tokens starting with `larch-logs/` (run-generated).
   - Same-line suppression: `<!-- lint-doc-pointer-paths: ok <reason> -->` with a required non-empty reason; a suppression without a reason is itself a violation.
   - Report one violation per file, line, and token; exit non-zero on any violation, matching sibling lints.
3. Register per `G-CLI-1` in `python/larch/cli.py`: `("lint", "doc-pointer-paths"): ("larch.lint.lint_doc_pointer_paths", "main")`.
4. Wire the verb into the same lint battery that runs `lint markdown-heading-fence-state` (Makefile and CI), with parity to sibling lints.
5. Baseline policy: none. Part 1 lands in the same PR, so the lint introduces clean and stays a hard ban.

#### Acceptance criteria

1. `python3 python/cli.py lint doc-pointer-paths` exits 0 on the swept tree.
2. The enumeration procedure above prints nothing for `SECURITY.md` and `AGENTS.md`.
3. A fixture with a dead pointer fails the lint and names the file, line, and token.
4. Fenced examples, placeholder tokens, `larch-logs/` paths, and reason-bearing suppressed lines are not flagged.
5. A `::symbol` or `#fragment` suffix checks only the file part.
6. A suppression comment without a reason fails.
7. Every edited `SECURITY.md` row points at an existing path or carries a deletion rationale in the PR description.

#### Tests

New `python/tests/lint/test_lint_doc_pointer_paths.py` covering: dead pointer flagged; live pointer passes; fenced-block skip; placeholder skip; `larch-logs/` skip; suffix stripping; suppression with reason passes; suppression without reason fails. Run: `python3 -m pytest python/tests/lint/test_lint_doc_pointer_paths.py`.
