The panel threshold check in `review-core.env` emits `THRESHOLD_REASON=no successful static reviewer for archetype(s): edge-cases`, causing `REVIEW_CORE_STATUS=panel-failed`.

Evidence: `round-1/collector-results.env`, `round-1/review-core.env`.

The defect is that the TRIVIAL-tier panel threshold requires a substantive edge-cases response even when the diff contains only Markdown prose additions. A doc-only 4-line diff to `docs/workflow-lifecycle.md` and `skills/implement/references/step5-review-branches.md` has no code edge cases, so the reviewer correctly finds none, but the body length check rejects the response as non-substantive rather than treating it as a valid "no edge cases" result. This causes repeated `panel-failed` regardless of how many times the review is retried.
