## Problem

The current review-process telemetry only measures **over-acceptance** (fluff). `/fluff-analysis` reports acceptance / OOS / reject rates and low-value accepts; its recommendations are all "reject more / faster." `/voter-calibration` measures agreement and severity calibration but explicitly excludes realized outcomes. Nothing tracks the **inverse risk**: the gate rejecting or dropping findings that were actually real.

This matters because the necessity gate is being tightened over time. Per analysis #5640, in the recent window findings/run fell from 39.4 to 11.2, OOS rose from 34% to 51%, and the **important-severity reject rate jumped from 20.8% to 49.4%**. There is currently no standing metric that would flag if tightening has started discarding necessary findings.

## Proposed direction

Add a tracked **false-negative / under-acceptance** view, segmented pre/post each rubric change, so the gate can be tuned against both failure modes rather than just fluff:

- **Neutral-rate**: count and rate of `neutral` (1-YES) findings per run, by severity tier. A rising high-severity neutral-rate is an early false-negative signal.
- **Important-reject-rate over time**: the 0-YES rejection rate of reviewer-claimed-important findings, with the pre/post split already supported by `--cutoff` / `--since-version`.
- **Realized-outcome tie-in (best-effort)**: reuse the `analyze-issues` ground-truth matcher (rejected/deferred finding later resurfaces as a filed bug) as a periodic diagnostic, acknowledging its conservative undercount (`docs/ground-truth-verdict.md`).

Keep it diagnostic-only (no effect on live spawning, thresholds, tokens, or scores), consistent with `/voter-calibration`.

## Affected surfaces

- `skills/fluff-analysis/scripts/fluff-analysis.py` (add neutral-rate and important-reject-rate sections; data already flows through the classification TSVs)
- `skills/voter-calibration/scripts/voter-calibration.py` (or a new diagnostic) for the per-voter neutral/false-negative view
- `.claude/skills/analyze-issues` ground-truth voter calibration (already does realized-outcome matching; surface it on a cadence)
- tests: the existing offline harnesses for each analyzer

## Acceptance criteria

- A report cut shows high-severity `neutral`-rate and important-severity reject-rate, segmented pre/post a chosen cutoff or version.
- The metric is reproducible offline from committed `larch-logs/` with no live `gh` dependency for the core numbers.
- Documented as diagnostic-only.

## Rationale

From #5640: the team currently optimizes one side of the gate (fluff). A symmetric false-negative metric makes gate-tightening safe by catching over-rejection of necessary findings before it shows up as shipped bugs.

Refs #5640.

## Proposed Design Outline

### Goals
- Add neutral-rate (1-YES) and important-reject-rate (0-YES on reviewer-claimed-important findings) to `fluff-analysis.py`, segmented pre/post a cutoff.
- Add per-voter false-negative view to `voter-calibration.py`: fraction of each voter's YES votes that end on neutral/rejected findings.
- Add optional realized-outcome tie-in to `voter-calibration.py` as a degraded section that skips when GitHub is unavailable.

### Non-goals
- No changes to live review spawning, thresholds, tokens, or proposer scores.
- No changes to `voting.py` or existing baseline tables (neutral stays lumped in the rej% column for backward compat).
- No structural changes to classification TSV formats.

### Approach sketch
- In `fluff-analysis.py`: add `_section_false_negatives()` that reads `outcome` and `body_severity` from existing records. Render neutral-rate by severity tier + important-reject-rate. Gate pre/post sub-tables on existing `cutoff`/`since_version` logic.
- In `voter-calibration.py`: add a `_per_voter_false_negative()` helper that reads TSV rows directly (without the agreement-row path which skips neutral) and counts YES-on-(neutral|rejected) per voter.
- In `voter-calibration.py`: add optional realized-outcome section using `ground_truth_voter_calibration` from `analyze_issues.py`. Wrap in try/except with logged note on failure.
- Update both test harnesses with synthetic fixture rows covering neutral and important-rejected cases.
