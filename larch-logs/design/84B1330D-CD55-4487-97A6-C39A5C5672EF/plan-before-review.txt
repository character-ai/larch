## Approach

Add a small mechanical completeness layer around the existing design publish path.

1. Reuse `larch.core.architectural_guidelines.read_guidelines()` and `DESIGN_ASSESSMENT`.
2. Add a helper that checks this condition:
   - outcome is approved
   - guidelines status is `present`
   - `$DESIGN_TMPDIR/architectural-guideline-assessment.md` is a regular, non-symlink file
3. Call the helper in normal `publish_core()` before redaction, issue plan-block write, rename, diagram upsert, and log-publish.
4. On normal Step 5c absence:
   - emit machine KVs naming the missing artifact
   - set `PUBLISH_REFUSE_REASON=missing-guideline-assessment`
   - write `.design-publish-result.env`
   - return the existing recoverable refusal rc used for publish precondition failures
   - print an operator-visible Gate C re-entry message
5. Add a degraded direct log-publish path for noninteractive or resume-style publishing:
   - append a `Warnings` execution issue that names `architectural-guideline-assessment.md`
   - write a small marker file for summary stamping
   - render `final-summary.md` with a visible warning before copying the run tree
6. Emit machine lines from `architectural-guidelines persist-design-assessment` so audits can distinguish helper not called from helper failed.
7. Extend design run-log completeness verification so approved design logs in repos with present guidelines require the assessment artifact unless a committed execution issue names the omission.

## Edge cases

- Guidelines `absent` or `invalid`: no artifact is required. Stale artifact cleanup remains helper-owned.
- Missing artifact in normal Step 5c: fail before plan-block write, rename, diagram upsert, final summary publish, or run-log commit.
- Missing artifact in degraded direct log-publish: never silent. Record an execution issue and stamp the summary.
- Symlink or non-regular assessment file: treat as missing for completeness.
- Existing execution issue waiver must name `architectural-guideline-assessment.md`.
- Companion invariant assessment is out of scope.

## Failure modes

- If guideline status cannot be read, rely on `read_guidelines()` status. `invalid` means no artifact is expected.
- If result env writing fails after a refusal, keep existing rc/result-env fallback behavior.
- If degraded warning append fails, summary stamping should still attempt to show the warning.
- If summary rendering fails, fallback summary still shows the warning marker.
