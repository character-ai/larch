**History and root cause.** #6374 (closed DONE 2026-07-05) targeted this gap with prose changes to the `--skip-approve` carve-out in `skills/design/references/approval-gates.md`. The miss rate went from ~12% (measured 2026-07-04) to 20% (measured 2026-07-09). The persistence step is prompt-side only: Gate C prose instructs `architectural-guidelines present-note` then `persist-design-assessment` (approval-gates.md lines 165-198 at fb6d61294). The model-tier split above shows weaker main agents skip the call. Nothing mechanical checks the artifact afterward: the design flush commits whatever files exist, and the publish succeeds without the assessment.

This violates the repo's own invariant I-Flush-1, quoted from `ARCHITECTURAL_INVARIANTS.md`:

```markdown
### I-Flush-1: A missing required run-log artifact is a recorded execution issue, never a silent status string

Every run-log flush must either commit the run's required artifact set (session
transcript, voted-finding bodies, final report) or record the omission as a
category-keyed execution issue that flushes into the committed run log.
```

**Required change.** Mechanical fail-closed enforcement, not another prose patch.

1. At design finalize/publish (the step that renders `final-summary.md` and stages the run-log commit), add a completeness check: when `read_guidelines(repo_root).status == "present"` and the run outcome is approved, `architectural-guideline-assessment.md` must exist in `$DESIGN_TMPDIR`.
2. On absence in an interactive path: hard-fail the publish with an operator-visible error naming the missing artifact and directing Gate C re-entry.
3. On absence in a non-interactive or resume path where Gate C cannot re-run: record a category-keyed execution issue that flushes into the committed run log, and stamp `final-summary.md` with a visible warning line. Silence is the defect; pick loud failure first, recorded degradation second.
4. When guidelines are `absent` or `invalid`, no artifact is expected and the check passes.
5. Emit machine lines for the persist attempt and result so audits can distinguish "helper failed" from "never called".
6. Check whether a design-side run-log completeness verifier already exists (an implement-side completeness harness exists; see `test-verify-run-log-completeness` in the Makefile). Extend it if so; add one if not.
7. Scope this issue to the guideline assessment. A companion issue in this batch ("/design never persists an architectural-invariant assessment") extends the same validator to invariants and should land after this one.

**Acceptance criteria.**

- A test seeds a finalized design tmpdir with guidelines present and no assessment artifact: publish fails (or records the execution issue on the degraded path). With the artifact present, publish succeeds.
- New approved design runs always carry the artifact or a recorded execution issue; re-running the audit query above on the next 30 runs yields 0 silent misses.
- `scripts/test-design-structure.sh` pins any changed Gate C prose.

## Proposed Design Outline

### Goals
- Add a mechanical fail-closed completeness check in the design publish path: when guidelines are `present` and the run outcome is approved, `architectural-guideline-assessment.md` must exist.
- Hard-fail publish on the interactive path when the artifact is missing; record a category-keyed execution issue and stamp final-summary on non-interactive/resume paths.
- Emit machine lines for the persist attempt and result so future audits can distinguish "helper failed" from "never called."

### Non-goals
- Architectural invariant assessment (companion issue for a later PR).
- Changing Gate C prose as the primary fix (mechanical check is the fix; prose is a secondary note at most).
- Affecting runs where guidelines are `absent` or `invalid` (check passes automatically).

### Approach sketch
- Locate the publish/step5c entrypoint in `python/design_publish.py` or `python/design_lifecycle.py` and identify the earliest point after the outcome is known and before run-log commit staging.
- Add a `check_guideline_assessment_completeness(design_tmpdir, repo_root, interactive)` function: reads guidelines status; if `present` and outcome is approved, checks for `architectural-guideline-assessment.md`; returns `ok` or `missing`.
- Interactive path (`missing`): raise a typed `PublishError` / return a non-zero exit so Step 5c aborts with operator-visible error pointing to Gate C re-entry.
- Non-interactive/resume path (`missing`): call `record_execution_issue` to append to `execution-issues.md`; write a warning line to `final-summary.md`.
- Extend (or add) the design-side run-log completeness verifier after checking `test-verify-run-log-completeness` in the Makefile.

### Surfaces in scope
- `python/design_publish.py` and/or `python/design_lifecycle.py` (publish entrypoint; precise file to be confirmed by code inspection)
- `python/design_summary.py` (final-summary stamping on degraded path)
- `python/test_design_publish.py` or `python/test_design_lifecycle.py` (unit test: seed tmpdir with guidelines present + no artifact; assert fail/record; with artifact, assert pass)
- `Makefile` / `scripts/test-verify-run-log-completeness` (extend or add completeness verifier)
- `skills/design/references/approval-gates.md` and `scripts/test-design-structure.sh` (pin any Gate C prose change, only if prose is updated)
