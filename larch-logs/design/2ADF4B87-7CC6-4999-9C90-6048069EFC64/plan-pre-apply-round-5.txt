## Failure modes

1. **Validation failure**:
   - Exit `1`.
   - Emit exact bash-compatible stdout KVs only for validations that used stdout in the retired verb.
   - Preserve stderr-only validation behavior for `clarify state` invalid `--issue`.
   - Preserve stderr-only validation behavior for `clarify label` invalid `--issue`.
   - Validate `clarify label --issue` before repo resolution or gh I/O.
   - Validate `clarify comment-post --issue`, `--kind`, `--id`, and `--content-file` before repo resolution or gh I/O.

2. **Repo resolution failure**:
   - Print `FAILED=true`.
   - Print `ERROR=could not determine repo`.
   - Exit `2`.

3. **gh API failure in `clarify_state`**:
   - Raise `ShipError`.
   - CLI prints `FAILED=true` and redacted `ERROR=...`.
   - Exit `2`.

4. **Transient gh failure in `clarify_comment_post`**:
   - Retry through `issue_comment_with_retry`.
   - On exhaustion, raise `ShipError`.
   - CLI exits `2`.

5. **Posted comment URL parse miss**:
   - Strip stdout first.
   - If stripped stdout does not contain a parseable `issuecomment-N` suffix, do not raise.
   - Return success with `POSTED=true`, `COMMENT_ID=`, and `COMMENT_URL=`.

6. **Label create race**:
   - If output contains `already exists` or `already been taken`, case-insensitive, continue to add the issue label.
   - Otherwise raise `ShipError`.

7. **Label add/remove failure**:
   - Check the add/remove `CommandResult`.
   - On nonzero return, raise `ShipError`.
   - CLI prints `FAILED=true` and redacted `ERROR=...`.
   - Exit `2`.

8. **Redaction truncation**:
   - Raise `ShipError`.
   - Do not post the comment.

9. **Quiet-output routing failure**:
   - Treat missing parseable machine KVs in quiet mode as a test failure.
   - Do not fall back to ad hoc stdout printing in clarify mains.
