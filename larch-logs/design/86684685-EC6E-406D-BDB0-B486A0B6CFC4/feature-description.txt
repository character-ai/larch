# [OOS] Token-record sidecar ingestion & token-env hygiene — 6 items

Combined from #4164 and #4153 by `/combine-issues --oos`. Token-record sidecar ingestion and token-env hygiene gaps across the research, validation, drafter, ship, and lint-fix paths.

### Item 1 — Bash lint-fix token env handling gaps: stale ledger vars and warning relay
- **Location**: `scripts/lint-fix-loop.sh` (~lines 442-451), `python/checks.py`
- **Source**: #4164
- **Description**: `scripts/lint-fix-loop.sh` has two related token ingestion gaps on the Bash lint-fix path (~lines 442-451). First, the `IMPLEMENT_TMPDIR=...` env prefix for token subprocesses does not clear inherited token-ledger vars (original text truncated at filing). Second, a warning-relay gap on the same path.

### Item 2 — Research Codex sidecar ingestion lacks mechanical enforcement or harness coverage
- **Location**: `skills/research/references/research-phase.md`
- **Source**: #4164
- **Description**: `skills/research/references/research-phase.md` documents research Codex sidecar ingestion instructions, but ingestion is prompt-side only with no script-level hook or structural harness. If the prompt drifts, sidecar token records are silently dropped.

### Item 3 — Codex drafter TOKEN_RECORD points at missing stable path on copy failure
- **Location**: `scripts/launch-codex-drafter.sh`, `skills/design/scripts/design-step2b-drafter.sh`, `scripts/relevant-checks.sh`
- **Source**: #4164
- **Description**: `scripts/launch-codex-drafter.sh` warns via `larch_err` when the token-record `cp` to the stable path fails, but all exit paths still emit `TOKEN_RECORD=${OUTPUT_CANON}.token-record` even when that stable path was never written.

### Item 4 — Python ship driver lacks Bash recovery sidecar ingestion parity
- **Location**: `python/ship.py`, `docs/run-log-cli.md` (parity target: `scripts/ship-pr.sh`)
- **Source**: #4164
- **Description**: Bash `ship-pr.sh` recovery ingestion for CI-fix sidecars is unavailable on the default Python ship driver (`python/ship.py`). CI-fix recovery on `LARCH_SHIP_PR_IMPL=python` paths may still drop sidecar token records.

### Item 5 — Validation-phase Codex lanes lack sidecar ingestion step
- **Location**: `skills/research/references/validation-phase.md` (~lines 129-190)
- **Source**: #4153
- **Description**: Validation-phase Codex lanes (e.g. `codex-validation-output.txt`, which also gets `${OUTPUT}.token-record`) write token-record sidecars without a ledger ingestion step; only `research-phase.md` was updated. Validation still collects Codex outputs via `collect-agent-results.sh` without ingesting their token sidecars. (Deduplicated from 3 near-identical copies in #4153.)

### Item 6 — Research/validation ingestion `env -u` omits LARCH_TOKEN_SESSION_ID
- **Location**: `python/tokens.py:324-330`, `skills/research/references/research-phase.md:165`
- **Source**: #4153
- **Description**: Research ingestion `env -u` omits `LARCH_TOKEN_SESSION_ID`, which `resolve_session_id` reads before any tmpdir `session-id` file. With the planned unsets for `LARCH_TOKEN_*`, the session id can still leak in from the parent environment and mis-attribute ingested rows.
