## Approach

- Treat `NO_SKETCHES` as binding. Draft from direct repo inspection and the approved outline.
- Use the approved outline and discussion constraints:
  - Default ON.
  - Disable with one env kill-switch.
  - Read the last 100 committed run-log directories by default.
  - Make the window env-tunable.
  - Roll up by base voter tool: `claude`, `codex`, `cursor`.
  - Omit the prompt block when a tool has no usable data.
  - Cover both code-review and plan-review voter dispatch.
  - Do not change weighting, spawning, pruning, token allocation, quorum, thresholds, or proposer-controlled severity.
- Correct the outline path `python/config.py` to the real config module: `python/larch/core/config.py`.
- **Render-time tool attribution must match the launching tool.** Do not pass a single pre-branch `--voter-tool` for voter 1, and do not key voter 2/3 or plan-review waterfall slots to primary-tool-only renders when fallback may substitute vendors at launch.
- **Per-base-tool rollup requires voter-label rewrite before scoring.** Setting `panel=global` alone is insufficient; rewrite each nested `voters[].voter` through the base-tool normalizer before `compute_voter_severity_distribution`.
- **Snapshot freshness.** Delete any pre-existing snapshot path in the tmpdir before running the snapshot CLI, or write to a unique temp file and pass it onward only after a successful write. Never reuse a stale `voter-calibration-stats.tsv` after a failed snapshot step.

## Edge cases

- **Cold start:** no committed logs, unsupported logs, or no valid YES severities must produce no prompt block.
- **Legacy schemas:** use existing TSV schema helpers so compact and tool-column schemas keep working; map compact `v1`/`v2`/`v3` before rollup instead of skipping them.
- **Mixed panels:** code-review and plan-review rows aggregate by base tool, not panel, after voter-label rewrite to `panel=global`.
- **Fallback tools:** labels such as `cursor-plan-fidelity`, `cursor-pragmatism`, `Claude`, `Codex`, and `Cursor` map to their actual base tool via case-insensitive normalization.
- **Malformed env window:** fallback to 100.
- **Kill-switch:** `LARCH_VOTER_CALIBRATION_FEEDBACK=0` skips snapshot computation and render flags entirely.
- **Snapshot failure:** dispatch continues without feedback; stale tmpdir snapshots must not be passed through.
- **Ambiguous waterfall tool:** omit calibration for that slot rather than inject another tool's stats.
- **Prompt stability:** no stats must mean byte-stable render output for existing callers.

## Failure modes

- **Run-log parse drift:** avoid by reusing `voter_agreement_rows_from_tsv` and schema support checks.
- **Performance regression:** compute one snapshot per dispatch, not once per voter.
- **Prompt overreach:** keep feedback advisory. Do not alter parser, ballot, tally, or quorum behavior.
- **Bad committed logs:** skip bad files for this incentive path rather than blocking live voting.
- **Tool misattribution:** centralize base-tool normalization, pre-launch tool resolution, and per-tool prompt selection; test cursor-only, claude fallback, and waterfall substitution paths.
- **Stale snapshot reuse:** avoid by deleting or uniquifying the snapshot path before each fresh snapshot attempt.
