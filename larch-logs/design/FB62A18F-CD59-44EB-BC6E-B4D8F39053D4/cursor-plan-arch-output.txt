**Finding 1 — Generated design wrapper prelude (architecture)**

The plan patches individual scripts such as `design-step3-review.sh` and `design-step-validator-autofix.sh`, but every generated `/design` wrapper duplicates the same header from `design-step-prelude.sh`:

```24:29:skills/design/scripts/design-step-prelude.sh
CODEX_PRESENT="${CODEX_PRESENT:-false}"
CURSOR_PRESENT="${CURSOR_PRESENT:-false}"
CODEX_AVAILABLE="${CODEX_AVAILABLE:-$CODEX_PRESENT}"
CURSOR_AVAILABLE="${CURSOR_AVAILABLE:-$CURSOR_PRESENT}"
CODEX_BINARY_FOUND="${CODEX_BINARY_FOUND:-false}"
CURSOR_BINARY_FOUND="${CURSOR_BINARY_FOUND:-false}"
```

Defaults are applied before `design_source_env_optional` sources session env. After durable env stops writing probe-health keys, `CODEX_BINARY_FOUND` can be `true` while `CODEX_AVAILABLE` remains `false`. That reintroduces the exact skip behavior the issue targets across brainstorm, Step 3, revise-waterfall, and other lanes not individually listed.

**Finding 2 — Implement both-down hard-fail envelope (risk-integration)**

Design gets an explicit `STEP0_STATUS=degraded-both-down-hard-fail` in `design-step0-session.sh`. Implement has no `STEP0_STATUS` consumer. Bootstrap `_run_absorbed_continue_tail` still auto-proceeds on non-interactive both-down and silently passes when a stale sentinel exists on interactive both-down. The plan’s edge cases forbid that, but bootstrap changes do not name the stdout KV or SKILL routing row that forces abort before checkpoint `1.r`.

**Finding 3 — Resume degraded gate inputs (correctness)**

Bootstrap resume reads `CODEX_PRESENT` / `CURSOR_PRESENT` from the routing envelope populated from stripped `session-env.sh`. The plan’s failure-mode list flags this, but the bootstrap section only says “rerun private check-reviewers” without making that probe mandatory before `agent degraded-tools-gate`. Without it, resume can mis-gate or emit `PRESENCE_INPUT_EMPTY` after health keys are removed from durable env.

**Finding 4 — [OUT_OF_SCOPE] Shell health gate scope**

`external_launch_health_gate` in `lib-external-launcher-common.sh` is not on the production launch path (`run_external_agent` uses Python `_external_health_gate`, which the plan removes). Plan language to “keep retry behavior for executable binaries that run and return probe or launcher failures” risks preserving per-launch `check-reviewers` probes in dead shell code. Worth a tracked follow-up to shrink scope, not a blocker if Python gate removal ships.
