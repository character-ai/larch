### 1. [correctness] Env-key auth-prep failure case is unreachable as specified

The plan’s item 4 (plan.txt:56-60) reuses the login-mode mv prep-failure trick while `OPENAI_API_KEY` is set. On the env-key branch, `external_prepare_codex_auth` never propagates strip/mv failures:

```694:699:scripts/lib-external-launcher-common.sh
    if external_codex_env_key_enabled; then
        if [[ -f "$home_dir/config.toml" ]]; then
            external_strip_codex_larch_env_provider "$home_dir/config.toml" || true
            external_strip_codex_literal_credentials "$home_dir/config.toml" || true
        fi
        return 0
```

`review-and-fix.sh` only sets `codex_auth_setup_failed` when that helper returns non-zero (lines 284-286), and the env-key breadcrumb requires `codex_auth_setup_failed=true` (lines 326-329). After `mktemp -d` creates `codex_home`, `mkdir -p` inside the helper cannot fail. The same plan explicitly leaves implementer env-key auth-prep breadcrumb untested as unreachable (plan.txt:77). Item 4 conflicts with that and cannot be made to pass without production changes.

**Suggested revision:** Remove item 4 or fold env-key coverage into item 5’s dispatch-failure path only.

### 2. [correctness] Cleanup snapshots need an exported case TMPDIR

Item 2 (plan.txt:51-52) and item 5 (plan.txt:67) snapshot `find "$TMPDIR" … 'larch-codex-review-fix-home.*'`, but homes are created with `mktemp -d "${TMPDIR:-/tmp}/larch-codex-review-fix-home.XXXXXX"` (review-and-fix.sh:277) while `run_review_and_fix` never sets `TMPDIR` (test-review-and-fix.sh:308-318). Default placement is `/tmp`, not the case scratch dir the plan describes.

**Suggested revision:** `export TMPDIR="$case_dir"` (under `$SCRATCH/...`) on each auth-prep/cleanup case before `run_review_and_fix`.

### 3. [risk-integration] Implementer mv stub must not be copied verbatim

Implementer test 4h uses a blanket failing `mv`:

```445:448:skills/implement/scripts/test-codex-implementer.sh
cat > "$AUTH_PREP_BIN/mv" <<'EOF'
#!/usr/bin/env bash
exit 99
EOF
```

That works only because Codex never spawns afterward. Review-and-fix auth-prep failure still runs Cursor fallback and later `mv -f` for composed output (review-and-fix.sh:814, 1143). The plan’s delegate-to-`/bin/mv` rule (plan.txt:47, 86-87) is correct; the “mirroring implementer” wording (plan.txt:46) is misleading and risks a false-green or broken harness if followed literally.

**Suggested revision:** Document the conditional dest-path predicate explicitly and treat implementer as a login-only, no-fallback analogue—not a byte-copy source.

### 4. [risk-integration] PATH stub teardown should appear in the subshell contract

Plan subshell examples unset `OPENAI_API_KEY` and set `HOME` but do not show `PATH="$auth_prep_bin:…"` (plan.txt:49-50, 57-58). Implementer scopes stub PATH to a single command subshell (test-codex-implementer.sh:455-456). Without the same scoping, a leaked `PATH` stub would affect later dispatch cases in the shared harness process.

**Suggested revision:** Include `PATH="$case_auth_prep_bin:/usr/bin:/bin"` in the same subshell that enables the mv stub.
