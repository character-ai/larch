## Approach

- Tests and fixtures only; no production-script changes. All four harnesses are already wired into the Makefile and CI shards (`test-harnesses-4/5/8/10` + the `test-review-and-fix-dispatch` section target); extending the files in place needs no wiring edits.
- Reuse each harness's existing conventions: `pass`/`fail` helpers and fixture style in `test-lib-external-launcher-common.sh`; `run_cr` + per-test `TMPDIR` + `assert_line` in `test-check-reviewers.sh`; `make_work_repo` + `run_review_and_fix` + `TEST_AGENT_*` stub env in `test-review-and-fix.sh`; `STUB_*` capture files and numbered `fail N` labels in `test-codex-implementer.sh`.
- Forcing auth-prep failure uses the proven read-only `config.toml` mechanism (`chmod a-w` on a fixture `HOME` copy source; `cp` preserves the read-only mode on the destination, and `external_strip_codex_larch_env_provider` fails its `-w` precheck). No function shims are needed in the two harnesses that exec their target as a child process.
- Bash 3.2 compatible: plain arrays, `grep -F` needles, `find`/`ls` snapshots; no `mapfile`, no associative arrays (`BASH_AUTHORING.md` §3).
- Trade-off: the `/tmp` snapshot diff in `test-codex-implementer.sh` tolerates pre-existing third-party `larch-codex-home-*` dirs by asserting only on **new** survivors, at the cost of a small race window if a concurrent launcher run creates homes mid-test. CI shards run harnesses sequentially, so the window is acceptable.

## Edge cases

- `grep -c` exits 1 on zero matches while still printing `0`; guard count probes with `|| true` and compare the captured count (BASH_AUTHORING.md §1).
- The read-only `config.toml` fixture must be `chmod u+w`-restored after each failure-path case so the scratch `trap 'rm -rf'` cleanup does not fail on Linux runners.
- macOS vs Linux `stat`/`touch` differences are already handled by existing stamp tests; new stamp assertions only check file existence and first-line content, which is portable.
- The login-mode reverse stamp case must keep `LARCH_LIB_CURSOR_AUTH_TEST_MODE=1` and a cursor stub exiting 127 like sibling cases, so only the codex lane is exercised.
- The review-and-fix login-fallback case must not assume the developer machine has `~/.codex/auth.json`: the fixture `HOME` fully controls both `config.toml` and `auth.json`.
- The multiline `'''` fixture must be written with a quoted heredoc delimiter so the test file itself stays parseable (BASH_AUTHORING.md §2).

## Failure modes

1. **False-green count assertions.** A `grep -Fxc` needle that drifts from the fixture byte-for-byte (quoting, spacing) counts 0 and may still satisfy a `-eq 0` comparison written for the wrong expectation. Warning signal: a new assertion passes both before and after reverting the fixture. Mitigation: during implementation, flip each new assertion's expectation once locally to confirm it can fail (mutation sanity check), mirroring the audit finding that motivated this plan (line 162).
2. **Shared-`/tmp` flakiness in the snapshot diff.** A concurrent local `launch-codex-implement.sh` run could add `larch-codex-home-*` dirs between snapshots, failing the cleanup assertion spuriously. Warning signal: failures only on developer machines with parallel larch sessions, never in CI. Mitigation: compare sorted before/after lists and fail only on entries absent from the before-snapshot; document the single-runner expectation in the test comment.
3. **Fixture-permission cleanup breakage.** A failing assertion between `chmod a-w` and the restoring `chmod u+w` leaves a read-only file that breaks `rm -rf` scratch cleanup on some filesystems. Warning signal: harness reports pass/fail correctly but leaves `larch-test-*` litter. Mitigation: perform `chmod u+w` immediately after the `run_review_and_fix` invocation returns, before any assertions (the existing t7a/4h cases already follow this order).
