### 1. correctness — `plan.txt:14-16` (login-home `model_provider` count)

The plan asks for exactly one retained `model_provider = "openai-larch-env"` on `login-home/config.toml` after `external_prepare_codex_auth` on the copied login fixture. That conflicts with login-path semantics: the harness already expects **no** top-level selector via `assert_top_level_not_line` at ```121:122:scripts/test-lib-external-launcher-common.sh```, and after strip the only surviving text is the multiline example line (`example model_provider = ...`), which does not match a whole-line `grep -Fxc 'model_provider = "openai-larch-env"'` count of 1.

**Suggested revision:** Assert count **0** for that pattern on the login-home fixture (alongside zero `env_key`), matching existing removal assertions.

### 2. correctness — `plan.txt:41-44` (stamp-isolation login subcase)

The decoy env-key-stamp / unset-`OPENAI_API_KEY` subcase only requires argv to lack env-key overrides “and/or” show login auth material. Login-path prep does not fail closed when `auth.json` is absent (`external_prepare_codex_auth` returns 0 at ```705:707:scripts/lib-external-launcher-common.sh```), so Codex can be probed without ever creating a login symlink—making the login-path wiring assertion vacuous.

**Suggested revision:** Bind `HOME` to a fixture with `.codex/auth.json` (and strippable `config.toml`), unset `OPENAI_API_KEY`, ensure no fresh `codex-login` stamp, then assert symlink target plus absent env-key `-c` overrides in the argv capture.

### 3. architecture — `plan.txt:29-31` (trusted-project adjacency scope)

Adjacency checking is planned only for `t10-env-key-false` in `test-check-reviewers.sh`, while production launchers use the same `-c "$trust_config_arg"` pattern in `check-reviewers.sh`, `review-and-fix.sh`, and `launch-review.sh`. This is acceptable minimum scope for #3476, but it is a deliberate parity gap.

**Suggested revision:** Document as intentional probe-only coverage, or mirror the adjacent `-c` pairing assertion in review-and-fix dispatch argv captures when touching that harness anyway.
