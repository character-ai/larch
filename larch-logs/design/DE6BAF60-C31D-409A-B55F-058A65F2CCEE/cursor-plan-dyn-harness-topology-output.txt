## Findings

### 1. risk-integration — `skills/review-and-fix/scripts/test-review-and-fix.sh:63-192`
Plan item 1 names `run-external-agent-stub.sh` as the edit target. The dispatch harness only materializes that script as a heredoc at lines 63-192 inside `test-review-and-fix.sh`; there is no standalone file on disk. Implementing against the named path would miss CI (`test-review-and-fix-dispatch` / `test-harnesses-5`).

**Suggested revision:** Add `TEST_AGENT_CODEX_AUTH_LINK_FILE` beside the existing `TEST_AGENT_CODEX_*_FILE` hooks in the heredoc stub (mirror `skills/implement/scripts/test-codex-implementer.sh:239-240`).

### 2. correctness — `skills/review-and-fix/scripts/test-review-and-fix.sh:308-318`
New dispatch cases (auth-prep failure, login fallback) depend on fixture `HOME/.codex/{config.toml,auth.json}`, but `run_review_and_fix` only `cd`s into the work repo and never sets `HOME`. No existing dispatch test sets `HOME` either. Without an explicit `HOME=<fixture>` prefix, `review-and-fix.sh:280-281` reads the developer machine’s `~/.codex`, making the new cases flaky and non-hermetic.

**Suggested revision:** Document and implement `HOME="$fixture_home"` on each new `run_review_and_fix` invocation (login fallback must also ship fixture `auth.json`, as the plan already implies at Edge cases).

### 3. correctness — `skills/review-and-fix/scripts/review-and-fix.sh:280-285` / `scripts/check-reviewers.sh:212`
The Approach section says `chmod a-w` + `cp` preserves read-only on the destination so `external_strip_codex_larch_env_provider` fails its `-w` precheck (`lib-external-launcher-common.sh:539`). Both production copy sites use plain `cp` into a new temp directory, which creates a writable destination. `test-check-reviewers.sh` t7a (lines 280-286) has the same shape: read-only source, no `auth.json`, so login-mode prep fails at the symlink step, not strip. `test-codex-implementer.sh` case 4h actually forces strip failure via an `mv` shim (lines 445-449), not chmod alone.

**Suggested revision:** For review-and-fix case 2, either (a) state clearly that the fixture omits `auth.json` and the test pins symlink-time prep failure, or (b) use the mv-shim technique from 4h. Do not add fixture `auth.json` while assuming chmod alone blocks prep.
