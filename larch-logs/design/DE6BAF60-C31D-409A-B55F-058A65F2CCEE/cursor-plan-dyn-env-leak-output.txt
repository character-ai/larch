## Findings

**1. [correctness] Review-and-fix login auth-prep cleanup targets the wrong TMPDIR namespace**

The plan (Step 2, line 51) snapshots `find "$TMPDIR" -maxdepth 1 -name 'larch-codex-review-fix-home.*'`, and Edge cases (line 97) call that a “private-`TMPDIR`” snapshot. The harness only sets `TMP=$(mktemp -d …)` and never exports it:

```26:27:skills/review-and-fix/scripts/test-review-and-fix.sh
TMP=$(mktemp -d "${TMPDIR:-/tmp}/test-review-and-fix.XXXXXX")
trap 'rm -rf "$TMP"' EXIT
```

Codex temp homes are created under the inherited `${TMPDIR:-/tmp}`, not under `$TMP`:

```277:277:skills/review-and-fix/scripts/review-and-fix.sh
    codex_home=$(mktemp -d "${TMPDIR:-/tmp}/larch-codex-review-fix-home.XXXXXX") || codex_rc=1
```

So the proposed assertion is not case-private and can see debris from earlier dispatch cases (e.g. the existing codex-telemetry case) or unrelated `/tmp` traffic. The env-key dispatch-failure case correctly pins cleanup via `TEST_AGENT_CODEX_HOME_FILE` (plan line 63); login auth-prep should use the same discipline—per-case `TMPDIR` export in the subshell, or an implementer-style `/tmp` survivor diff.

**2. [correctness] Stamp-isolation login-path case must forbid `run_cr_with_env`**

`run_cr` unsets `OPENAI_API_KEY`; `run_cr_with_env` does not:

```28:39:scripts/test-check-reviewers.sh
run_cr() {
    local tmp="$1"
    shift
    mkdir -p "$tmp"
    ( cd "$REPO_ROOT" && TMPDIR="$tmp" LARCH_QUIET_DISABLE=1 env -u OPENAI_API_KEY "$@" )
}

run_cr_with_env() {
    local tmp="$1"
    shift
    mkdir -p "$tmp"
    ( cd "$REPO_ROOT" && TMPDIR="$tmp" LARCH_QUIET_DISABLE=1 "$@" )
}
```

Plan stamp-isolation item 3 (lines 35–38) requires exercising the login path with no `OPENAI_API_KEY`, but only login-mode review-and-fix cases (plan line 49) get an explicit `unset`. If the check-reviewers isolation case uses `run_cr_with_env` without setting the key, a parent-exported `OPENAI_API_KEY` keeps env-key mode active and breaks isolated-run semantics. Mandate `run_cr` (or subshell `unset`) for that subcase; reserve `run_cr_with_env` for legacy-strip and live env-key probes.

**Exonerated (no finding):** Existing `t10-env-key` / `t10-env-key-false` invocations already run inside command-substitution subshells, so `OPENAI_API_KEY=<REDACTED-TOKEN>` does not escape. `t7a` `HOME="$SCRATCH/t7a-home"` is scoped inside `run_cr`’s subshell. Check-reviewers `assert_no_probe_homes` on each case’s `run_cr` TMPDIR matches production (`mktemp` under case TMPDIR at `check-reviewers.sh:208`). Implementer `/tmp` snapshot tolerates pre-existing dirs. Env-key review-and-fix cases can follow the existing `out=$(OPENAI_API_KEY=… run_review_and_fix …)` pattern at `test-review-and-fix.sh:783-790`.
