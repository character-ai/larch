1. [correctness] The plan says “HEAD moved on the same branch,” but the proposed test is only “current_head is non-empty and differs.” `git rev-parse HEAD` still succeeds in detached HEAD, and it also succeeds after checkout to another branch or after an amend/rewrite. Capture and compare the symbolic branch, and require `baseline_head` to be an ancestor of `current_head`.

2. [security] The new committed forbidden-path pseudocode loses the current prefix semantics from `post_dispatch_forbidden_revert`. Exact awk membership catches `.gitmodules` and a submodule directory path itself, but not `submodule_path/file`. That is the boundary case the new test should exercise.

3. [security] Skipping the whole `post_dispatch_forbidden_revert` / delta block on the HEAD-changed path leaves uncommitted forbidden edits unchecked. The commit may be clean while the worktree is not. Run the forbidden dirty-tree check before `applied`.

4. [correctness] The `baseline_clean=false` acceptance is too broad. Existing code intentionally avoids helper-owned commits in that state; accepting an external commit can silently package pre-existing user work into the CI-fix commit. Keep the new “coder commit is the fix” path limited to clean baselines unless the implementation can prove no baseline-dirty path entered the commit.
