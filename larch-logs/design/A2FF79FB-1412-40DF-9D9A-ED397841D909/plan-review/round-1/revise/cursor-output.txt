## Edge cases

- A file with only blank lines should produce zero content tokens.
- A file without a trailing newline should still get stable content-token output.
- Non-ASCII text should follow the existing estimator unless the implementation deliberately changes `_estimated_tokens()`. Avoid changing that estimator in this child.
- `--skill` must reject unknown skill names with exit `2`.
- `--skill` combined with `--write` must exit `2` before any baseline write.

## Failure modes

- If baseline JSON is stale after adding fields, lint exits `2` or freshness tests fail.
- If `scripts/test-design-structure.sh` calls the all-skill ratchet instead of `--skill design`, implement-only growth may fail the design harness. Avoid that coupling.
- If `scripts/test-design-structure.sh` uses `CLI_PY` (`python/larch/cli.py`) for the ratchet call, the script can exit `0` without running the linter. Use `python/cli.py` for that invocation only.
- If `--write` honors `--skill` and writes a one-row baseline, `load_baseline()` fails closed on the next default lint run until manual repair. Reject the combination at argparse time.
- If blank-line-normalization removes indentation-only code fences, it is acceptable for this metric because it is a ratchet signal only, not rendered content.
