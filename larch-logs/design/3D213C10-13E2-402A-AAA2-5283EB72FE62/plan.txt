# Implementation Plan — #3348: fast-fail health gate for external-agent launchers

This is a SIMPLE-tier design. The core behavior change is small (one helper + one call
site + chokepoint timeout resolution). The breadth (all three named surfaces + Python parity)
is user-directed; each individual change stays minimal.

## Problem restated

`check-reviewers.sh` already provides a bounded (`LARCH_PROBE_TIMEOUT_SECONDS`=30s), cached
(`LARCH_PROBE_TTL_SECONDS`=60s, per-USER stamp files) real health probe at session start.
The residual gap: a tool healthy at session start can degrade mid-run (quota exhaustion,
network blip, token expiry). Dispatchers still launch it via `run-external-agent.sh`, which
then waits the full `--timeout` (20-30 min) before the waterfall falls to Claude.

Fix (Round 1 Decision 1): add a launch-time health gate at the shared `run-external-agent.sh`
chokepoint that reuses the existing `check-reviewers.sh` probe + stamp cache. On unhealthy,
skip the real launch and emit a health-class failure so the existing per-tool waterfall
degrades to Claude immediately.

## Files to modify/create

### UPDATED: `scripts/lib-external-launcher-common.sh`
- Add `external_launch_health_gate <tool>` (sourced-only helper, Bash-3.2-safe, no `set -e`).
- Timeout resolution (Plan review FINDING_1 — the gate, not a session-env export, is the single
  activation point; `session-env.sh` is NOT sourceable, only key-readable):
  1. Use `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` from the process env when it is a positive integer.
  2. Else, when unset/`0`/non-numeric, resolve it from a session-env file via
     `"$SCRIPT_DIR/read-session-env-key.sh"` — first `$SESSION_ENV_PATH` (when set), then
     `$IMPLEMENT_TMPDIR/session-env.sh` (when set). Use the read value when the key is present and
     a positive integer.
  3. Else gate is OFF — return `0` (proceed, current behavior). No implicit default-on without a
     session-env opt-in, so tests with neither the env var nor a session-env file stay unaffected.
- Behavior once a positive timeout `N` resolves:
  - Return `0` (proceed) when `<tool>` is not `codex` or `cursor` (external-tool only).
  - Invoke `"$SCRIPT_DIR/check-reviewers.sh" --skip-<other>-probe` with `LARCH_EXTERNAL_AUTH_RETRIES=1`,
    wrapped in `timeout`/`gtimeout N` when a wall-clock wrapper exists; without one, run unwrapped
    and rely on `check-reviewers.sh`'s internal `LARCH_PROBE_TIMEOUT_SECONDS` bound. The fresh-stamp
    fast path returns in well under 1s. Capture the wrapper exit `rc`.
  - Decision order (Plan review FINDING_2 — timeout must fail unhealthy BEFORE the missing-line
    fail-open):
    1. `rc` is `124` or `143` (outer-timeout kill / SIGTERM, often with no `*_PRESENT` line) →
       return non-zero (unhealthy → skip launch). A hung real probe is positive unhealth evidence.
    2. Parsed `<TOOL>_PRESENT=false` → return non-zero (unhealthy → skip launch).
    3. Parsed `<TOOL>_PRESENT=true` → return `0` (healthy → proceed).
    4. No parseable `<TOOL>_PRESENT` line and `rc` not `124`/`143` → fail OPEN (return `0`, proceed).
       Only a broken gate (not a timeout) fails open; never block a launch because the gate broke.
- The helper is tool-symmetric (Codex and Cursor share the path), satisfying
  `.claude/rules/external-tool-launcher-parity.md` by construction.

## Approach

- Reuse over rebuild: the gate consults `check-reviewers.sh`, which already owns the probe, stamp
  cache, serial lock, and auth-retry logic. The first launch against a degraded tool pays one
  bounded probe; `check-reviewers.sh` writes a fresh `false` stamp, so subsequent launches and the
  `launch-review.sh` retry cycles within the 60s TTL fast-fail instantly. Worst-case added latency
  is ~one probe per 60s window instead of one 20-30 min hang.
- Activation (Decisions 2 + Plan review FINDING_1/3/4): the gate resolves its timeout from the
  process env, then `SESSION_ENV_PATH`, then `IMPLEMENT_TMPDIR/session-env.sh`. `/design` sets the
  env directly through the sourceable `source-env.sh` export; `/implement` (and nested `/review`)
  rely on the persisted `session-env.sh` key plus the chokepoint read. This delivers "on in
  production, off in test/CI" with zero test-harness churn — tests set neither the env var nor a
  session-env file. Standalone `/review` / `/research` are a documented L1 gap (env-var opt-in;
  `/research` tracked by the accepted OOS issue).
  - Considered alternative: default-on inside `run-external-agent.sh` with a `=0` opt-out. Rejected
    for L1 because every stub harness that drives `run-external-agent.sh --tool codex|cursor` would
    fast-fail in CI where no real binary exists, forcing an opt-out edit in each.
- Waterfall integration without classifier changes: codex `7` / cursor `8` + empty output is the
  existing `health`/`health-probe` path. CI family falls through (health is not `other`, so
  `run_waterfall` does not short-circuit); review family retries (cheaply, cached) then falls
  through. Both reach Claude.

## Edge cases

- Gate enabled but `timeout`/`gtimeout` absent (macOS Bash 3.2 without coreutils): run
  `check-reviewers.sh` unwrapped; its internal `LARCH_PROBE_TIMEOUT_SECONDS` still bounds the probe.
- Outer-timeout kill yields exit `124`/`143` with no `*_PRESENT` line → unhealthy (FINDING_2), not
  fail-open.
- Fresh `false` stamp from session start: gate fast-fails instantly with no new probe.
- Fresh `true` stamp: gate proceeds with no new probe (~0 added latency on the healthy path).
- `--tool` other than codex/cursor (e.g. claude): gate is a no-op.
- Parallel panel launches: `check-reviewers.sh` already uses atomic stamp writes + a Darwin serial
  lock, so concurrent gate calls are safe.
- Gate-infra failure (missing/broken `check-reviewers.sh`, rc not 124/143): fail OPEN (proceed).

## Failure modes

1. False-positive on a healthy-but-slow tool (transient network slows the probe past the bound) →
   needless Claude fallback. Earliest signal: a rise in `health-probe fast-fail` diag lines /
   Claude-tier usage. Mitigation: generous `30s` default; the `false` stamp expires in 60s so the
   next window can recover; unset/`0` opt-out.
2. Accidental gate activation in tests/CI → stub launches fast-fail. Earliest signal: harness
   failures citing exit `7`/`8` or `health-probe fast-fail`. Mitigation: gate OFF unless the env var
   OR a session-env file supplies a positive timeout; production-only wiring; gate tests stub
   `check-reviewers.sh`.
3. Probe cost/latency creep (a small `Respond with OK` call per 60s window) → marginal token spend.
   Earliest signal: extra codex/cursor probe rows in the token ledger. Mitigation: stamp cache
   (≤1 probe / 60s), `LARCH_EXTERNAL_AUTH_RETRIES=1` for the gate, internal probe-timeout bound.
