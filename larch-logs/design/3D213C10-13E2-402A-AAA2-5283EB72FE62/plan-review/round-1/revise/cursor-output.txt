# Implementation Plan — #3348: fast-fail health gate for external-agent launchers

This is a SIMPLE-tier design. The core behavior change is small (one helper family + one call site + env wiring). The breadth (all three named surfaces + Python parity) is user-directed; each individual change stays minimal.

**Reviewer round incorporated:** FINDING_1 (session-env persistence ≠ process-env activation on `/implement`), FINDING_2 (wrapper timeout exit before fail-open), FINDING_4 (standalone `/review` and `/research` never run `write-session-env`).

## Problem restated

`check-reviewers.sh` already provides a bounded (`LARCH_PROBE_TIMEOUT_SECONDS`=30s), cached (`LARCH_PROBE_TTL_SECONDS`=60s, per-USER stamp files) real health probe at session start. The residual gap: a tool healthy at session start can degrade mid-run (quota exhaustion, network blip, token expiry). Dispatchers still launch it via `run-external-agent.sh`, which then waits the full `--timeout` (20–30 min) before the waterfall falls to Claude.

Fix (Round 1 Decision 1): add a launch-time health gate at the shared `run-external-agent.sh` chokepoint that reuses the existing `check-reviewers.sh` probe + stamp cache. On unhealthy, skip the real launch and emit a health-class failure so the existing per-tool waterfall degrades to Claude immediately.

Fix (reviewer round): production activation must not rely on persisting the key in `session-env.sh` alone — that file is not sourced; `/implement` and nested launch paths only parse allowlisted keys into the process environment. Resolve `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` at the chokepoint from the process environment first, then from durable session-env files via `read-session-env-key.sh` when unset.

## Production scope (FINDING_4)

| Entry path | Gate ON in production? | Mechanism |
|---|---|---|
| `/design` | Yes | `write-design-current-env.sh` exports `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT`; Step 1c+ prelude sources `current-design-env-$PPID.sh` into the Bash subshell |
| `/implement` (Step 2, Step 5, ship-pr CI tiers, plan-review under implement) | Yes | `write-session-env.sh` persists the key; `run-external-agent.sh` reads it from `$IMPLEMENT_TMPDIR/session-env.sh` (and `$SESSION_ENV_PATH` when set) at the chokepoint |
| Nested `/review` under `/implement` | Yes | Same chokepoint read via `$IMPLEMENT_TMPDIR` / `--session-env-path` |
| Standalone `/review` | **No (documented out of scope)** | Step 0 `session-setup.sh` has no `--write-session-env`; no `session-env.sh` exists on `$REVIEW_TMPDIR` |
| Standalone `/research` | **No (documented out of scope)** | Same as standalone `/review` |

Standalone `/review` and `/research` are explicitly deferred: enabling them requires adding `--write-session-env "$<SKILL>_TMPDIR/session-env.sh"` to their Step 0 `session-setup.sh` invocations plus the same chokepoint read (already tries `$REVIEW_TMPDIR/session-env.sh` when set). That expansion is not part of this SIMPLE-tier issue; document the boundary in `docs/configuration-and-permissions.md` and `scripts/lib-external-launcher-common.md`.

### UPDATED: `scripts/lib-external-launcher-common.sh`
- Add `external_launch_health_gate_effective_timeout` (sourced-only, Bash-3.2-safe, no `set -e`):
  - If `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` is already a positive integer in the process environment, print it on stdout and return `0`.
  - Otherwise, for each readable candidate file in order — `"${IMPLEMENT_TMPDIR:-}/session-env.sh"`, `"${SESSION_ENV_PATH:-}"`, `"${REVIEW_TMPDIR:-}/session-env.sh"` (skip empty paths) — call `"$SCRIPT_DIR/read-session-env-key.sh" --file "$path" --key LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` **without** `--default`. Use the first non-empty value that passes the positive-integer check.
  - If still unset/invalid, print nothing and return `0` (gate OFF at script level).
  - Do not invent a `30` default during the session-env read path; the writer default applies only when the key is actually persisted (new runs) or when `/design` exports it.
- Add `external_launch_health_gate <tool>` (sourced-only helper):
  - Resolve timeout via `external_launch_health_gate_effective_timeout`; return `0` (proceed) immediately when resolution yields empty, `0`, or non-numeric (gate OFF).
  - Return `0` (proceed) when `<tool>` is not `codex` or `cursor` (gate is external-tool only).
  - Otherwise invoke `"$SCRIPT_DIR/check-reviewers.sh" --skip-<other>-probe` with `LARCH_EXTERNAL_AUTH_RETRIES=1`, wrapped in `timeout`/`gtimeout "$resolved_timeout"` when a wall-clock wrapper exists; when neither exists, run unwrapped and rely on `check-reviewers.sh`'s internal `LARCH_PROBE_TIMEOUT_SECONDS` bound. Capture wrapper exit status separately from probe output.
  - **FINDING_2 ordering:** if the wrapper exit is `124` or `143`, return non-zero (unhealthy → skip launch) **before** any fail-open branch.
  - Parse `<TOOL>_PRESENT` from probe output; return non-zero when `<TOOL>_PRESENT=false`.
  - Fail OPEN (return `0`, proceed) only on gate-infrastructure errors: `check-reviewers.sh` missing/non-executable, or no parseable `<TOOL>_PRESENT` line **after** the wrapper-timeout check above. Only skip on positive unhealth / timeout evidence; never block a launch because the gate itself broke.
- Tool-symmetric (Codex and Cursor share the path), satisfying `.claude/rules/external-tool-launcher-parity.md` by construction.
