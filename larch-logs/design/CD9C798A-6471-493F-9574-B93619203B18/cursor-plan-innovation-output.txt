### 1. [correctness] `skills/review-and-fix/scripts/test-review-and-fix.sh:512-519` — carryover grant-root assertion

The plan correctly requires `cd` into each work repo before `pre_coder_snapshot_dir` and fixture seeding (lines 51–52), so the `$PWD` relocation branch will run for `…/implement/round-1` layouts. It does not say to refresh `_repo_root_cg`, which is still taken from the harness CWD before that `cd` (lines 513, 559).

After relocation, `snap_dir` lives under `${TMPDIR}/larch-pre-coder-snapshots/…`, so the existing `case "$snap_dir" in "$_repo_root_cg"/*` check still passes even when it no longer means “outside the work repo Codex `--add-dir "$PWD"` root.” A regression that leaves snapshots at `$work/implement/.pre-coder-snapshots/` (inside the grant) would not trip this assertion; the new in-repo relocation unit case would catch it, but the carryover guards would give a false sense of coverage.

**Suggested revision:** After `cd "$work_carryover_guard"` / `cd "$work_index_carryover_guard"`, recompute `_repo_root_cg` from that repo (or assert `snap_dir` is outside `"$PWD"` / `"$PWD"/*` directly), matching the plan’s stated “outside `$PWD`” intent.

### 2. [OUT_OF_SCOPE] [risk-integration] `skills/review-and-fix/scripts/test-review-and-fix.sh:3012-3049` — `relocated-structural-loc` layout

The plan updates `mav-apply-relocated-pre-head` to in-repo `IMPLEMENT_TMPDIR="$PWD/implement"` but does not touch `relocated-structural-loc`, which still sets `IMPLEMENT_TMPDIR="$case_dir/impl"` while `cd "$case_dir/work"`. That keeps the default snapshot path and does not exercise relocated `pre_coder_snapshot_dir` inside `run_implement_loop` telemetry. Not a production gap given the dedicated in-repo relocation tests; worth tracking so the case name and coverage stay aligned.
