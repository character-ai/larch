## Description

Five related latent/important hardening gaps surfaced during review of #3288:
  (a) `FINDING_6` — if `IMPLEMENT_TMPDIR` is under the repository root, the relocated pre-coder snapshots land inside the Codex `--add-dir "$PWD"` grant and remain coder-writable. Affects non-standard deployments; production sessions use `~/.cache/larch/sessions/` (outside the repo).
  (b) `FINDING_9` (sandbox confinement) — the relocation trusts that `codex exec --full-auto` confines writes to declared `--add-dir` / workspace roots; if the sandbox is more permissive, relocation alone is insufficient and read-only protection or sandbox hardening would be needed.
  (c) `FINDING_11` — some harness layouts keep `IMPLEMENT_TMPDIR` under the work tree, so they don't exercise the production trust-boundary assumption (snapshots outside repo/Codex grant).
  (d) `FINDING_13` — `post-coder-head.txt` remains in coder-writable `round_dir` and feeds `structural_loc`/bulk-skip telemetry. Does not affect the carryover commit guard but could skew loop telemetry if tampered with.
  (e) `FINDING_17` — `scripts/launch-codex-implement.sh` grants the entire session tmpdir via `--add-dir "$SESSION_TMPDIR"`, wider than the Step 5 grant (`--add-dir "$round_dir"`); pre-existing and outside the #3288 diff.
  Suggested work: (a) document in `review-and-fix.md` that callers must ensure `IMPLEMENT_TMPDIR` is outside the repo root; consider a runtime assertion in the snapshot writer. (b) Verify `codex exec --full-auto` sandbox confinement in CI or docs; add `chmod 0444` to snapshot files as defense-in-depth. (c) Update harness to use an out-of-repo tmpdir for the trust-boundary test fixture. (d) Optionally relocate `post-coder-head.txt` to the snapshot dir, or `chmod 0444` it. (e) Evaluate narrowing the `--add-dir "$SESSION_TMPDIR"` grant in `launch-codex-implement.sh` or scoping it to `round_dir` only.

### Discovered bug (fix first)

- The doc claims that when the round parent is inside `$PWD`, the helper relocates pre-coder snapshots under `${TMPDIR:-/tmp}/larch-pre-coder-snapshots/<hash>/$(basename "$round_dir")`, outside the repo-root `--add-dir "$PWD"` grant.

- Impact: when `IMPLEMENT_TMPDIR` / `round_dir` is under the repo root (FINDING_6 / FINDING_11 non-standard deployments and in-repo test fixtures), pre-coder snapshots land inside the coder-writable `--add-dir "$PWD"` grant. The documented snapshot-integrity invariant is violated, and the doc asserts a security mitigation that does not exist.

Fix direction (Decision 1): implement the relocation branch so the code matches its documented contract.
