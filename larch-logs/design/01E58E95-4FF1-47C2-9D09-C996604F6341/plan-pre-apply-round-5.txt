## Edge cases

- **Quiet mode**: machine stdout must still use fd 3 after `quiet_init`.
- **Help and usage**: parse help and usage before `quiet_init` so usage remains operator-visible.
- **Citation validator fail-soft**: per-claim failures must not become process failures.
- **Citation reason tokens**: keep existing tokens for redirects, timeout, 404/410, 403/405/501, git-root-unavailable, DNS/network failure, and invalid-argument degraded sidecars.
- **Citation global budget**: budget exhaustion must cancel or kill in-flight fetches, backfill `UNKNOWN(timeout)`, exit `0`, and leave no orphan work.
- **Subprocess-backed fetches**: any worker PID exposed by the fetch seam must be terminated or killed on budget expiry.
- **Final summary contract**: no contract-stream output may appear after `SUMMARY=...`.
- **Sidecar identity**: byte-identical reruns depend on preserving the validator label unless the contract is intentionally bumped.
- **Network safety**: Python HTTP code must not use environment proxies or follow non-DOI redirects.
- **DNS rebinding**: resolved private IPs must fail before fetch, and fetch should use the checked IP when possible.
- **TLS pinning**: pinned fetches must preserve original hostname verification, SNI, and `Host`.
- **DNS timeout**: slow resolution must remain bounded by per-fetch timeout or global budget.
- **DOI redirect**: `doi.org` 3xx remains a valid DOI signal.
- **File-line containment**: realpath escape outside the git root must not pass.
- **Planner edit loop**: Step 1.1.c must revalidate operator edits through the Python CLI, not the deleted shell script.
- **Planner delimiter**: any `||` in retained planner lines must fail before count gates.
- **Planner exit codes**: validation failures exit `1`; missing args and bad paths exit `2`.
- **Findings renderer**: fenced markdown and body lines starting with `### ` must not corrupt issue batch parsing.
- **Findings report path**: missing paths and non-regular files both exit `2` with the old error wording.
- **Rendering reuse**: findings batch logic must route through `python/rendering.py` so B6 remains the shared authority.
- **Banner fallback matching**: only `RESEARCH_*_STATUS=fallback_...` triggers a banner; `RESEARCH_*_REASON` text must not.
- **Banner drift**: `BANNER_TEMPLATE` must stay byte-equal to the research-phase banner literal.
- **Structured reviewer output**: JSONL, TSV, and no-findings sentinels must keep existing collector behavior.
- **Validation-mode call-sites**: no deleted-script `-x` guard may suppress the Python validator.
- **Validation-mode threshold**: default to 30 words in validation mode unless `--min-words` overrides it.
- **Collector validator command**: store the Python validator as an argv array, never as a scalar command string.
- **Eval-set structure**: preserve header triplet, adversarial note shapes, and Anthropic attribution pin.
- **Eval harness tooling**: jq and awk must not remain required; full runs still require `claude`.
- **Eval harness issue safety**: full eval prompts must include `--no-issue`.
- **Eval harness**: `--smoke-test` must never require `claude`.
- **Retired paths**: tests must not embed retired path literals after the manifest update.
- **Harness telemetry**: migrated Makefile pytest recipes must keep `timing harness-mark` markers.
- **Shard 8 budget target**: keep `test-validate-citations-budget` as a pytest-backed alias unless all shard references are removed together.

## Failure modes

- **Stale call-site remains**: `make lint-retired-scripts` fails after manifest entries are added.
- **Edit-loop stale planner**: Step 1.1.c breaks interactive subquestion edits by calling the deleted planner script.
- **Scalar validator command**: collector validation fails because `python3 ... cli.py eval validate-research-output` cannot fit in one executable path variable.
- **Deleted-script guard remains**: legitimate short Cursor review payloads may be misclassified without invoking the Python validator.
- **Wrong harness path**: `make test-synthesis-subagent` may keep asserting the deleted banner helper.
- **Wrong exit code**: collectors or planner callers may misclassify validator and planner failures.
- **Planner exit-code drift**: mapping all planner failures to exit `2` breaks the old harness contract.
- **Wrong stdout stream**: orchestrator parsing may miss `COUNT=`, `REASON=`, or `SUMMARY=`.
- **Post-summary chatter**: citation advisory counts may break if anything follows `SUMMARY=...`.
- **Reason-token drift**: existing sidecar consumers may fail if HTTP, git-root, timeout, DNS, network, or invalid-argument tokens change.
- **Budget backfill gap**: claims still in flight at budget expiry may be omitted instead of recorded as `UNKNOWN(timeout)`.
- **Orphan fetch work**: canceled URL or DOI workers may survive after the validator exits.
- **Thread-only timeout bug**: unkillable in-thread HTTP work can survive global budget expiry even when the sidecar looks correct.
- **Network proxy leak**: citation validation may reintroduce SSRF risk.
- **TLS verification regression**: pinned fetches may fail public HTTPS or weaken verification if SNI or hostname checks are wrong.
- **Unbounded DNS**: slow resolution may block fail-soft completion.
- **Rendering fork**: duplicating B6 helpers in `research.py` can drift from shared issue rendering behavior.
- **Report path drift**: accepting directories or non-regular files can corrupt downstream issue batch parsing.
- **Banner false positive**: matching `fallback_` inside `RESEARCH_*_REASON` can emit the fallback banner incorrectly.
- **Banner literal drift**: changing the Python banner without updating docs can desync synthesis output.
- **False deleted bash docs**: `citation-validation-phase.md` may keep advertising curl or setsid requirements after the Python cutover.
- **Missing tool mismatch**: preserving jq or awk checks can make smoke tests fail with exit `3`.
- **Issue creation regression**: dropping `--no-issue` can create user-facing research issues during eval runs.
- **Validation-mode false negative**: keeping a 200-word default in validation mode can mark concise valid review findings as `NOT_SUBSTANTIVE`.
- **Eval-set structure regression**: dropping the old structure checks can lose adversarial notes, headers, or attribution pins.
- **Lost harness timing**: bare pytest Makefile recipes can drop harness telemetry.
- **Shard 8 breakage**: deleting `test-validate-citations-budget` without updating shard 8 breaks `make lint`.
- **Bash 3.2 static pin drift**: old grep expectations can fail after the correct Python CLI cutover.
- **Over-broad docs rewrite**: retired literal paths may remain in prose and fail migration lint.
- **Harness alias overuse**: keeping old Makefile target names as aliases can hide that bash harnesses were deleted. Prefer direct pytest target recipes, except keep `test-validate-citations-budget` stable if shard topology still requires it.
