# [DEDUP] centralize the repeated final-summary marker-extraction instruction (design SKILL.md)

**Problem.** The final-summary marker-extraction instruction is repeated **near-verbatim ~4 times** in `skills/design/SKILL.md` (Step 0b cancel-route path, the Final summary block, and Step 5c items 5 / abort path). Each copy says: extract the body between `LARCH_FINAL_SUMMARY_BEGIN` / `LARCH_FINAL_SUMMARY_END`, else Read-tool fallback on `${FINAL_SUMMARY_PATH:-$DESIGN_TMPDIR/final-summary.md}`, emit verbatim as plain chat text, do not paraphrase / reorder / add prose, and the `REPORT_GATE_SIDECARS_FILE` follow-on.

**Why this is not md-to-py.** The emit itself must stay orchestrator-side: tool output lands in a collapsible block, so the body must be printed as the orchestrator's own chat text. The defect is the repetition across sites, not in-prose logic. Filed separately from the md-to-py-IV umbrella for that reason.

**Proposed change.** Factor the marker-extraction + Read-fallback + verbatim-emit + sidecar instruction into one shared reference (e.g. `skills/shared/final-summary-emit.md` or a single named section) and have the Step 0b, Final summary block, and Step 5c sites point to it.

**Acceptance.**
- The instruction appears once; the ~4 sites reference the single source.
- No behavioral change.

**Notes.** Doc-hygiene / readability, not a Python migration. Surfaced during the md-to-py-IV analysis but excluded from that prefix because it moves no logic into Python.
