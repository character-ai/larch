## Summary

37 `tempfile.mkstemp` / `mkdtemp` / `NamedTemporaryFile` / `TemporaryDirectory` call sites in `python/larch/` (AST-confirmed at HEAD `9db723ca2`, tests excluded) pass no `dir=`, so they stage files in the ambient `$TMPDIR`. #6259 proved the ambient `$TMPDIR` can be malformed inside live `/implement` Step 5 processes, making creation itself fail with `ENOENT`; that fix added `dir=` at one site (`voting.py`) and left the rest of the class untouched. Non-context-managed sites also leak scratch files (#5923/#5973 class). No lint prevents new sites.

## Original report

Run-scoped tempfile calls without `dir=` remain across `python/larch` (post-#5923/#5973 residual), staging files in the ambient `$TMPDIR`; #6259 proved the ambient `$TMPDIR` can be malformed in live `/implement` Step 5 processes, so these are correctness exposure (`ENOENT` on create) plus scratch-file leak hygiene, and no lint prevents new sites. Prior related closed work: #5923 (four leak buckets, threaded `review_tmpdir`), #5973 (5 residual sites + cleanup), #6259 (write-tally `NamedTemporaryFile` with no `dir=` raised `ENOENT` under malformed `$TMPDIR`; run-root `code-review-tally.json` never landed), #3381 (macOS `mktemp -t` vs `TMPDIR` guard), #1957 (`is_tmp_path` rejects `/var/folders`). Surfaced by `/learn-from-bugs` mining (report issue #6470, section 7 item 2 and section 4 item 2). Suggested work items: (1) thread an explicit run-scoped `dir=` into each confirmed site where a tmpdir is in scope, mirroring the #6259 fix; (2) add a new AST-based Python lint (line greps miss continuation lines) flagging the tempfile calls without `dir=`, with a shrinking reason-bearing baseline per G-Enf-2 for deliberate system-tmp sites.

## Reproduction scenario

The #6259 shape reproduces the class: in a live `/implement` Step 5 process whose `$TMPDIR` resolves to a malformed, nonexistent path, any of the 37 sites below raises `FileNotFoundError` at create time and its caller's contract silently degrades (in #6259, the run-root `code-review-tally.json` was never written). For the leak half: run any flow through a `delete=False` / bare `mkstemp` site whose cleanup path is skipped on error; the scratch file persists in the system `$TMPDIR` (#5923 observed unbounded accumulation). Not reproduced live in this run; the site list below is static AST evidence.

## Expected behavior

Tempfile staging inside larch run flows lands under an explicit run-scoped directory (implement/design/review tmpdir, or the `--log-root`), so creation cannot depend on ambient `$TMPDIR` health and scratch files are swept with the session. Deliberate system-tmp uses are explicit and baselined.

## Observed behavior

All 37 sites depend on ambient `$TMPDIR`. One member of the class already failed in production (#6259). The rest remain exposed, including `run_log_flush.py:883-884` in the transcript-capture path that #6263 diagnosed (its `mkstemp(prefix="session-transcript.", ...)` landing in system `$TMPDIR` was a precondition of that bug's path corruption).

## Root cause analysis

Class-level cause: `dir=` threading was applied incident-by-incident (#5923 threaded `review_tmpdir` into four buckets; #6259 fixed one `NamedTemporaryFile`), never as a sweep, and there is no mechanical rule to stop new no-`dir=` sites. Observation, not inference: the class fix pattern already exists in-tree (post-#6259 `voting.py:1512` passes `dir=` on a continuation line, which is exactly why line-grep audits keep missing the survivors; only an AST pass sees them). A minority of sites are plausibly intentional system-tmp staging (for example `gh.py` `--body-file` staging that is written, consumed by `gh`, and deleted); the class still shares the malformed-`$TMPDIR` creation failure, so intentional sites belong in a reason-bearing baseline rather than an exemption by silence.

## Suggested fix(es)

1. Thread an explicit run-scoped `dir=` (implement/design/review tmpdir or `--log-root`) into each site where a run directory is in scope, mirroring the #6259 `voting.py` fix; prefer the enclosing function's existing tmpdir parameter over new plumbing (the #5923 pattern).
2. Add an AST-based lint (for example `lint_tempfile_dir`) flagging `tempfile.mkstemp` / `mkdtemp` / `NamedTemporaryFile` / `TemporaryDirectory` calls in `python/larch/` without a `dir=` keyword. Grep-based checks are insufficient: the in-tree fixed sites carry `dir=` on continuation lines. Grandfather deliberate system-tmp sites in a shrinking reason-bearing baseline per G-Enf-2 (one line per site with the reason, for example "gh --body-file staging, deleted in finally").
3. Optional hardening from #6259's alternative direction: a shared helper that validates or repairs `$TMPDIR` before any system-tmp staging, for baselined sites that legitimately stay ambient.

## Open questions

1. Which of the 37 sites are deliberately system-tmp (baseline) versus run-scoped (fix)? The `gh.py` body-file staging and the context-managed `TemporaryDirectory` sites look deliberate; the review/report/design clusters look like fix targets.
2. Should `TemporaryDirectory` (context-managed, auto-cleaned) be in the lint's scope? It cannot leak, but it shares the malformed-`$TMPDIR` creation failure; leaning include, with baseline entries.
3. Does any site run before a session tmpdir exists (bootstrap paths like `design_step0.py`)? Those may need the #6259 "validate and repair `$TMPDIR`" fallback instead of `dir=`.

## Proposed Design Outline

### Goals
- Thread `dir=<run-scoped-tmpdir>` into the 15 fixable sites where a session tmpdir is in scope, eliminating ambient `$TMPDIR` dependency for those calls.
- Add an AST-based lint (`lint_tempfile_dir.py`) that flags new no-`dir=` tempfile calls, with a reason-bearing JSON baseline for the 22 intentional or un-fixable sites.
- Wire the lint into `py-lint-checks-fast` with a `regen-tempfile-dir-baseline` Makefile target.

### Non-goals
- The "validate and repair `$TMPDIR`" helper (optional hardening from #6259 direction) is out of scope.
- Fixing sites in `python/tests/` (excluded by issue scope and lint scope).
- Fixing sites in Bash scripts.

### Approach sketch
- **Site sweep**: for each of the 15 fixable sites, thread or read the enclosing run-scoped tmpdir (`design_tmpdir`, `review_tmpdir` env var, `log_root.parent`, or `canonical_tmp`). Minimal surgical changes; no new cross-module plumbing beyond param threading.
- **Baseline**: write `python/tempfile-dir-baseline.json` with one entry per baseline site; each entry carries a short reason string per G-Enf-2 / G-Py-11.
- **Lint module**: `python/larch/lint/lint_tempfile_dir.py` walks AST nodes for `tempfile.mkstemp`, `mkdtemp`, `NamedTemporaryFile`, `TemporaryDirectory` calls lacking a `dir=` keyword argument, checks against the baseline, and exits non-zero on new violations.
- **Makefile + CLI**: one `py-lint-checks-fast` entry and a `regen-tempfile-dir-baseline` target; CLI verb `lint tempfile-dir`.
- **Tests**: `python/tests/lint/test_lint_tempfile_dir.py` covers clean code, violation detection, baseline suppression, and baseline shrink-only enforcement.

### Surfaces in scope
- `python/larch/lint/lint_tempfile_dir.py` (new)
- `python/tests/lint/test_lint_tempfile_dir.py` (new)
- `python/tempfile-dir-baseline.json` (new)
- `Makefile` (lint entry + regen target)
- `python/larch/cli.py` (new verb registration)
- 15 fixable source files (surgical `dir=` threading only)
