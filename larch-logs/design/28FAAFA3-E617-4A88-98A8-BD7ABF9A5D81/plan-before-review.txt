## Approach

Add a side-effect-free `larch.design.plan_grammar` module.

The module will:

- Define the four heading kinds: `NEW`, `UPDATED`, `REWRITTEN`, and `MAY_UPDATE`.
- Accept the current union of heading forms: level-two or level-three headings, colon headings, and bracket headings.
- Track fenced code blocks so heading-like text inside fences is not treated as a plan section.
- Define the complete trailer key registry: `review_status`, `rounds_completed`, `difficulty`, `diff_added`, `diff_deleted`, `mechanical_churn`, `oversize_override`, and terminal `diff_lines`.
- Export compiled whole-line regexes and typed helpers for trailer recognition.
- Parse the contiguous final trailer block into a frozen dataclass.
- Preserve current validation details, including duplicate handling, accepted leading zeroes, rejection of `08` and `09` where existing size-gate parsing rejects them, strict boolean values, and `oversize_override: operator`.
- Compose trailer lines in canonical order without treating model-authored metadata as trusted gate authority.
- Iterate plan sections without owning `larch:plan` markers.

Repoint consumers to these APIs. Keep `issue_wire` as the sole marker owner. Remove local regexes and key tuples only after their behavior is covered by shared compatibility tests.

## Edge cases

- Preserve both `##` and `###` heading levels.
- Preserve colon and bracket heading forms for all four heading kinds.
- Do not parse headings inside fenced code blocks.
- Require whole-line trailer matches.
- Treat only the final contiguous metadata block as trailers.
- Preserve older plans that omit optional trailers.
- Keep `diff_lines` mandatory and terminal where the current consumer requires it.
- Preserve consumer-specific handling of duplicate and malformed metadata.
- Do not grant authority to a model-authored `oversize_override`.
- Do not move or normalize `larch:plan` marker handling.

## Failure modes

- A stricter shared regex could reject a previously accepted plan. Prevent this with union fixtures before deleting local regexes.
- A permissive shared parser could weaken size gates. Keep strict typed accessors for gate inputs and retain trusted override verification outside the grammar module.
- Import cycles could form if the grammar module imports consumer policy. Keep it dependent only on the standard library and leaf constants that do not import design modules.
- A shared section iterator could parse fenced examples as real scope. Track fence state explicitly.
- Provenance insertion or bootstrap stripping could reorder or drop optional trailers. Test the complete block through both paths.
- Compatibility wrappers could leave two effective owners. Remove local key lists and regexes once each consumer is migrated.
