## Findings

### 1. `design_lifecycle.py` import surface omitted (correctness)

`design_lifecycle.py` still imports private Step 5c trailer helpers (`_AUTO_COMPOSE_OPTIONAL_TRAILER_RE`, `_split_plan_body_and_trailers`, peel/sidecar builders) from `design_step5c.py`:

```218:229:python/larch/design/design_lifecycle.py

    STEP5C_STATUS_ALLOW_KEYS,
    STEP6_INFO_ICON,
    _AUTO_COMPOSE_OPTIONAL_TRAILER_RE,
    _auto_compose_plan_md,
    _build_acceptance_section,
    _build_trailer_lines_from_sidecars,
    _optional_trailer_lines_from_values_file,
    _peel_trailing_optional_trailers,
    _read_diff_lines_sidecar,
    _split_plan_body_and_trailers,
```

The plan updates `design_step5c.py` but not `design_lifecycle.py`. Removing those privates from Step 5c without a lifecycle repoint breaks compose paths that `test_design_lifecycle.py` already covers.

**Suggested revision:** Add `### UPDATED: python/larch/design/design_lifecycle.py` to import the shared compose/split/peel APIs from `plan_grammar` (or thin public wrappers), not from `design_step5c` privates.

### 2. Gate B trailer owner left out of migration (architecture)

Gate B still owns a separate four-key set and a whole-file scanner:

```66:66:python/larch/review/plan_review_common.py
OPTIONAL_TRAILER_KEYS = {"diff_added", "diff_deleted", "mechanical_churn", "oversize_override"}
```

```349:355:python/larch/review/plan_review_loop.py
def _trailer_map(text: str) -> dict[str, str]:
    values: dict[str, str] = {}
    for line in text.splitlines():
        match = re.match(r"^([a-z_]+):\s*(.*?)\s*$", line)
        if match and match.group(1) in OPTIONAL_TRAILER_KEYS:
            values[match.group(1)] = match.group(2)
    return values
```

That conflicts with the stated goal of one registry owning trailer-key recognition and with the post-migration grep cleanup. Importing the full eight-key registry here would also widen gate-b snapshots to provenance keys the current contract excludes.

**Suggested revision:** Add updates for `plan_review_common.py` and `plan_review_loop.py`; import a documented size-only subset from `plan_grammar`, not the full registry.

### 3. `issue_wire.extract_scope_paths` heading grammar not unified (correctness)

Scope extraction still accepts only `###` colon headings:

```375:375:python/larch/issue/issue_wire.py
        match = re.match(r"^###\s+(NEW|UPDATED|REWRITTEN|MAY_UPDATE)\s*:\s*(.+)$", line)
```

The plan promises `##`/`###` and bracket forms everywhere headings matter. Even after `plan_quality.py` switches heading counts to shared helpers, `dispatch_step2.py`, `dirty_tree.py`, and `scope_disposition.py` still call `issue_wire.extract_scope_paths` directly, so accepted alternate heading forms would not drive coverage or scope checks.

**Suggested revision:** Add `### UPDATED: python/larch/issue/issue_wire.py` to delegate heading detection to `plan_grammar` inside `extract_scope_paths` (markers stay in `issue_wire`).

### 4. Preflight blank-line tolerance vs contiguous trailer parsing (correctness)

Preflight walks backward from `diff_lines:` and skips blank lines when extending the metadata window:

```451:457:python/larch/implement/preflight.py
    for index in range(diff_idx - 1, -1, -1):
        line = lines[index]
        if line.startswith(allowed):
            start = index
            continue
        if not line.strip():
            continue
        break
```

Shared optional-metadata parsing stops at the first non-trailer line, including blanks:

```216:222:python/larch/design/plan_quality.py
    for idx in range(trailer_nr - 2, -1, -1):
        line = lines[idx]
        kind = _metadata_block_line_kind(line)
        if not kind:
            break
```

The plan says to replace preflight’s local scan with shared trailer parsing. That would change behavior for plans where provenance and size trailers are separated by blank lines.

**Suggested revision:** In the preflight update, keep policy-local lenient final-region lookup (blank-tolerant) for `review_status` / `rounds_completed` / `difficulty`, and use the shared parser only where contiguous-block semantics are intended.

### 5. Gate B whole-file trailer scan vs contiguous-block contract (risk-integration)

Gate B’s `_trailer_map` collects optional size keys from any line in the plan, not only the terminal contiguous block (see finding 2). The plan’s edge cases require contiguous final metadata. Naively switching gate-b to the shared contiguous parser would stop treating body-embedded `diff_added:` / `mechanical_churn:` lines as present for snapshot/dedup, changing behavior that `test_plan_review.py` exercises today.

**Suggested revision:** When repointing gate-b, either preserve explicit whole-file collection for the size-only subset or document and test the intentional shift to contiguous-block-only semantics.
