[correctness]** [`skills/implement/scripts/generate-code-flow-diagram.sh:102`](skills/implement/scripts/generate-code-flow-diagram.sh) — The plan states there are no public output contract changes, but the proposed awk changes `SKIP_REASON` for real sanitizer output. Today `awk -F=` prints only the second `=`-delimited field (`pipe-in-node-label fence`); after the change the value is the full remainder (`pipe-in-node-label fence=mermaid line=7`). That is an observable KV change on every sanitizer rejection, not only the synthetic `pipe-in-node-label=foo` case. **Suggested revision:** Add a regression case with the production log line shape, document the enrichment in the `.md` sibling, and correct the Approach wording.

**2. [correctness]** [`scripts/test-ci-failed-jobs.sh`](scripts/test-ci-failed-jobs.sh) (proposed T8) — The plan’s embedded-newline test compares counts of input stderr lines vs `larch_err` lines, but `while IFS= read -r line` already splits `tmp_stderr` on physical newlines, so `$line` cannot contain `\n` when sourced from the file. The test may pass without validating `sanitize_diagnostic_line`. The actual multi-line-`larch_err` failure requires `\n` inside `$line` before `printf '%s\n'`. **Suggested revision:** Test BEL/ESC on one fixture line via `GH_FAIL_STDERR_FILE`, and separately invoke `sanitize_diagnostic_line` (or a one-iteration harness) with `$'foo\nbar'` to assert a single logical diagnostic line.
