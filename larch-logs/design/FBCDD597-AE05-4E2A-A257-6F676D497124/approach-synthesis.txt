# Approach Synthesis

**Sketch availability**: Codex-Generic returned a substantive sketch. Cursor-Generic returned only chain-of-thought preamble (logged as degraded under External Reviewer Issues in `execution-issues.md`). Synthesis below is built from the Codex sketch reinforced by direct codebase inspection.

## Agreement

The Codex sketch and the Step 1c/1d-resolved constraints agree on all key design choices:

1. **Two narrow, scope-bounded changes** — keep both items as isolated shell hardening fixes with no public output contract changes. Item A modifies one awk line in `generate-code-flow-diagram.sh`; Item B modifies one `larch_err` call site in `ci-failed-jobs.sh` plus a small new helper.

2. **Item A fix shape** — replace the `awk -F=` extraction with portable awk that matches `^REASON_TOKEN=`, strips only that prefix, and prints the remainder intact (including additional `=` characters). The fix must keep the existing fallback `|| printf 'sanitizer-rejected'` meaningful by ensuring the awk command exits non-zero when no `REASON_TOKEN=` line is present.

3. **Item B fix shape** — add a small permissive diagnostic sanitizer (e.g., `sanitize_diagnostic_line()`) defined near the existing `sanitize_list()` in `ci-failed-jobs.sh`. The new helper removes control bytes and newlines while preserving printable ASCII, spaces, and standard diagnostic punctuation. Apply it inline at the `larch_err "$line"` call inside the existing per-line `while IFS= read -r line` loop. Do not collapse the loop; do not weaken or reuse the existing strict `sanitize_list`.

4. **Audit scope confirmed** — Codex's audit pass and codebase inspection both confirm the only emit sites in `scripts/ci-failed-jobs.sh` that handle untrusted input are: (a) the line-80 `larch_err "$line"` stderr passthrough loop; (b) the KV emits at lines 145-147 which already use `sanitize_list`. The two `larch_err` calls at lines 16 and 20 in `usage()` and `die()` take internal literal strings and need no sanitization. (Note: Codex referenced lines 79/125/128 as audit anchors; the authoritative current-tree line is 80 for the stderr passthrough and 145-147 for the KV emits — confirmed by direct `grep` in Step 0c.)

5. **Test extension shape** — extend the existing harnesses:
   - `skills/implement/scripts/test-generate-code-flow-diagram.sh`: add a sanitizer-stub case that emits `REASON_TOKEN=pipe-in-node-label=foo` and assert `SKIP_REASON=pipe-in-node-label=foo` (full value preserved past second `=`).
   - `scripts/test-ci-failed-jobs.sh`: add a failing-`gh` stub stderr fixture containing printable diagnostic prose plus control bytes and embedded newlines. Assert the resulting `larch_err` output preserves the readable prose, strips control bytes, and does not let a crafted newline create extra logical log lines.

6. **Separate sanitizers per data class** — the existing strict `sanitize_list` is the correct policy for KV-emitted job names (machine-consumed); the new `sanitize_diagnostic_line` is the correct policy for human diagnostic stderr. Do not merge the two policies; they have different consumers and different threat models.

## Incorporated ideas

From the Codex sketch (folded into the plan):
- Portable awk shape (`match` + `substr` or `sub` + `print`) — adopt portable form so we do not require gawk.
- The `sanitize_diagnostic_line` helper name and locality (defined next to `sanitize_list`).
- Inline application at the existing loop without restructuring the loop.
- Test-case names and assertion shapes.

From codebase inspection (added beyond Codex):
- The exact `tr` argument string for the permissive whitelist must be chosen carefully to remain Bash 3.2 / macOS-portable per `BASH_AUTHORING.md §3`. `tr -d '[:cntrl:]'` is the most portable single-pass form that strips all control bytes (including `\n`, `\r`, `\t`) — but stripping `\t` may impede some diagnostic alignment. A two-step pipe `tr -d '[:cntrl:]'` is acceptable; alternatives like `LC_ALL=C tr -d '\0-\037\177'` give the same result with explicit byte range.
- The new helper must respect the same `set -euo pipefail` semantics as the rest of `ci-failed-jobs.sh` and must not break the loop when the input line is fully sanitized away (i.e., it can emit an empty line via `larch_err ""` — that's the safer behavior than skipping).
