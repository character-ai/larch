1. [security] [important] [in_scope] `scripts/ci-failed-jobs.sh:79-81`
Concern: the planned `larch_err "$(printf '%s' "$line" | sanitize_diagnostic_line)"` call is too late to address newline injection. The `while IFS= read -r line` loop has already consumed `\n` as a record boundary, so the helper can strip BEL/ESC/CR from each line but cannot stop a malicious newline in `gh` stderr from creating extra diagnostic records.

Suggested revision: sanitize or normalize `$tmp_stderr` before line splitting, or explicitly read/collapse the raw diagnostic stream before emitting through `larch_err`. The regression test should assert the actual protected contract: a fixture containing an injected newline in one crafted diagnostic does not increase the number of emitted `larch_err` records.
