### 1. correctness — `skills/implement/scripts/generate-code-flow-diagram.sh:102`

The proposed awk prints everything after `REASON_TOKEN=`, but production sanitizer output is documented as `REASON_TOKEN=<short-token> fence=<N> line=<N>` ([`scripts/sanitize-mermaid-fragment.md:44`](scripts/sanitize-mermaid-fragment.md)). That means the fix silently changes live `SKIP_REASON` values (e.g. from `pipe-in-node-label fence` today to `pipe-in-node-label fence=1 line=5` tomorrow) while the plan claims no public contract change.

**Suggested revision:** After stripping the prefix, truncate at the first space so only the short token is emitted while embedded `=` inside the token is preserved. Add a regression fixture using the real log-line shape, not only `pipe-in-node-label=foo`.

### 2. correctness — `scripts/ci-failed-jobs.sh:79-81`

The stated newline-injection mitigation cannot work on the current read path: `while IFS= read -r line` splits `tmp_stderr` before `sanitize_diagnostic_line` runs, so `$line` never contains `\n`. Control-byte stripping within a line is still useful; newline protection is not.

**Suggested revision:** Either slurp and sanitize the whole stderr blob before splitting, or narrow the contract and tests to intra-line C0/DEL bytes only and drop the embedded-newline assertions.

### 3. risk-integration — `skills/implement/scripts/test-generate-code-flow-diagram.sh:35-60`

The Item A test sketch references helpers (`write_sanitize_stub`, `run_subject_skip_path`, `assert_file_contains`) that do not exist. The harness today uses an inline `SANITIZE_REJECT` stub and `assert_contains`.

**Suggested revision:** Rewrite the sketch against the existing harness structure so implementation does not invent parallel scaffolding.

### 4. correctness — plan test sketch / `scripts/sanitize-mermaid-fragment.sh:201`

The regression example `REASON_TOKEN=pipe-in-node-label=foo` does not match how the sanitizer actually emits reject lines (space-separated `fence=` / `line=` metadata). A test built only on the synthetic form can pass while production-shaped output still regresses.

**Suggested revision:** Drive the test from a fixture that mirrors sanitizer output and assert the intended short-token value.

### 5. [OUT_OF_SCOPE] architecture — `scripts/sanitize-mermaid-fragment.sh:283`

The same class of untrusted `REASON_TOKEN` parsing appears in the sanitizer’s warnings-log token aggregation. If tokens ever include `=`, generator and warnings paths will diverge.

**Suggested revision:** Track a follow-up to share one portable token extractor.

### 6. [OUT_OF_SCOPE] architecture — `scripts/lib-quiet.sh:97-103`

Local `sanitize_diagnostic_line` hardens one call site but leaves every other `larch_err "$external"` passthrough to opt in manually. Centralizing C0/DEL stripping in `larch_err` (opt-in or default) would be a stronger systemic fix than a single-file helper.

**Suggested revision:** Add an explicit fallback regression case.
