# bash-to-py-mop-up: Thin design-step3-review.sh: move status normalization into cli.py

**What:** Extract the portable status-normalization state machine and result-env synthesis out of `skills/design/scripts/design-step3-review.sh` (~734 lines) into a `python/cli.py plan-review` verb. Keep the Bash process-group launcher.

**Why:** The migration docs deliberately keep this file as "the process-group wrapper for Step 3" because it needs Bash job control (`set -m`, `kill -- -$pid`). But roughly 200 lines of `LOOP_STATUS` <-> `STEP3_REVIEW_LOOP_STATUS` mapping, terminal-status synthesis, and result-env normalization (the back half of the file) are pure logic that does not need a shell. This is a partial thinning, not a full migration.

**Scope:**
- Add a `cli.py plan-review normalize-status` (or similar) verb that ingests the result-env plus plan-review stdout and emits the canonical `STEP3_REVIEW_LOOP_STATUS` / `LOOP_STATUS` / KV envelope.
- The wrapper keeps only argv parse, monitor-mode setup, background launch, EXIT-trap sentinel writes, and a call to the new verb.
- Preserve the `.completed/step-3` and `.completed/step-3-terminal` sentinel contracts and the `--read-result-env` recovery path exactly.

**Acceptance:** Step 3 sentinel and status contracts unchanged; existing design Step 3 harnesses pass; the wrapper shrinks materially while retaining job control.

**Note:** The shell stays for process-group isolation; do not remove the launcher.
