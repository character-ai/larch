1. [security] `scripts/lib-design-tmpdir.sh:1`

Concern: the proposed parent-resolve + basename algorithm misses the final path component when it is already a symlink.

Scenario: `/tmp/design-session` points to `/var/target`. The helper canonicalizes `/tmp`, appends `design-session`, sees an allowed `/tmp/...` path, then callers write through the symlink outside the allowlist.

Suggested revision: reject `-L "$resolved"` before returning success, or canonicalize an existing final directory and re-check that leaf path against the same normalized allowlist. Add a test for a final-component symlink, not only a parent symlink.

2. [integration] `skills/design/scripts/emit-design-plan-preview.sh:6`

Concern: the plan adds `lib-design-tmpdir.sh` to this script, but the script currently does not source `lib-quiet.sh`. The new helper’s diagnostics use `larch_err`.

Scenario: an invalid `--design-tmpdir` path in this script can fail as `larch_err: command not found`, which weakens the hardening path and makes the failure harder to recover from.

Suggested revision: source `scripts/lib-quiet.sh` before the helper in `emit-design-plan-preview.sh`, or make `lib-design-tmpdir.sh` fall back to `printf ... >&2` when `larch_err` is not defined.
