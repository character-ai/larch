# Regression coverage for the chronic recurring bug families (notification/sentinel, Gantt, aggregator, lint-fix)

## Problem

**69% of bugs in the last-100-design-run window (54/78) are recurrences of ~12 defect families**, and 17/78 carry literal "again/still/regression" language. See analysis #5640. The same surfaces keep re-breaking after they are "fixed."

Diff-scoped, necessity-gated code review is the wrong tool for "this whole surface is fragile": it sees one PR's diff, not the class invariant. The highest-leverage prevention is upstream of voting, in regression tests and contract assertions on the chronic surfaces.

## Proposed direction

For the top families, add regression coverage that asserts the **class invariant**, not just the one-off fix:

- **findings-aggregator**: contract tests for the validation / merge path (missing-reviewer-attribution, dedup fallback, semantic-validation rejection rate).
- **lint-fix / checks loop**: assertions for fast-fail and relevant-checks rule-table completeness.

- `scripts/test-*.sh` and `python/test_*.py` regression harnesses for each family's owning module
- the renderers under `python/` for report/Gantt output; `python/larch/review/review_aggregate.py` for the aggregator

- New tests run in CI.

## Rationale

From #5640: review prevented ~3-9% of these bugs at most, and tuning voting does nothing for recurrences. Regression coverage on the chronic families would prevent far more of the actual bug stream than any voting change.
