### NEW: python/collect_results.py

Implement the collector library and CLI.

Core objects:

- `CollectorOptions`: parsed flags and output paths.
- `CollectorRecord`: structured in-memory row with serializer for the existing stdout grammar.
- `RetryMeta`: parsed `.meta` sidecar.
- `RetryPlan`: prepared retry argv and sentinel paths.

Main flow:

1. Parse:
   - `--timeout <seconds>`
   - `--substantive-validation`
   - `--validation-mode`
   - `--structured-reviewer-validation`
   - `--summary-only`
   - `--paths-file <file>`
   - positional output paths
2. Enforce existing argument errors:
   - missing `--timeout`
   - no paths
   - `--paths-file` plus positional paths
   - unreadable, non-regular, or empty paths file
3. Derive sentinels by appending `.done`.
4. Call `review_dispatch.wait_reviewers()` with captured emit lines.
5. If the wait helper returns non-zero, relay sanitized diagnostics and exit `1`.
6. Build initial records in argv order, not basename order.
7. Preserve the current status mapping:
   - `OK`
   - `TIMED_OUT`
   - `FAILED`
   - `EMPTY_OUTPUT`
   - `SENTINEL_TIMEOUT`
   - `NOT_SUBSTANTIVE`
   - `CURSOR_EMPTY_RESPONSE`
   - `cap_hit`
8. Preserve invalid `.done` coercion to `EXIT_CODE=99`.
9. Keep `CURSOR_EMPTY_RESPONSE` and `CURSOR_DEGRADED_RESPONSE` first-line classification.
10. Run one empty-output or transient-diagnostic retry from valid `.meta` data.
11. Run substantive and structured validation only for `STATUS=OK` records.
12. Run one non-substantive retry when current bash behavior does.
13. Emit failed-agent stderr tails after retries and validation settle.
14. Emit stdout records with blank lines between reviewers.

Retry details:

- Parse `.meta` as key-value lines.
- Validate `TOOL`, `TIMEOUT`, `CMD_JSON`, `OUTPUT_FILE`, capture mode, `STDERR_SINK`, and outer-launcher keys.
- Use Python `json` instead of `jq`; keep malformed JSON fail-closed.
- Preserve raw `CMD_JSON` shape checks for Codex and Cursor.
- Preserve outer launcher replay:
  - review retry via `python3 python/cli.py agent launch-review`
  - Codex exec retry via `python3 python/cli.py agent launch-codex-exec`
- Preserve `--stderr-sink` forwarding for review retry metadata when present.
- Retarget retry output paths by replacing the original output path element.
- Wait for retry sentinels with the same `max(30, timeout + 60)` style bound.
- Keep missing retry sentinel as `STATUS=EMPTY_OUTPUT|EXIT_CODE=99`.

Validation details:

- Use `python3 python/cli.py eval validate-research-output`.
- Add `--validation-mode` only when requested with `--substantive-validation`.
- Add `--structured-reviewer-mode --write-structured <sidecar>` for structured validation.
- Preserve validator-exit mapping for `NOT_SUBSTANTIVE`.
- Preserve structured sidecar emission only when validation succeeds.

## Edge cases

- Preserve argv-index correlation when two output files share a basename.
- Treat `STATUS=OK` plus empty `FAILURE_REASON` as success. Do not use `EXIT_CODE=0` alone.
- Keep `cap_hit` terminal under waterfall phase collection.
- Keep `CURSOR_DEGRADED_RESPONSE` equivalent to `CURSOR_EMPTY_RESPONSE`.
- Keep retry metadata fail-closed for malformed JSON, missing timeout, bad tool, bad launcher kind, bad sandbox, missing prompt file, or bad add-dir JSON.
- Keep summary-only output small and free of `FAILURE_REASON` and `STRUCTURED_SIDECAR`.
- Keep stderr-tail dedup after all retries and validation settle.
- Do not require `jq`; Python JSON replaces it.
- Do not preserve Bash 3.2-specific implementation tests. Replace them with behavior tests.

## Failure modes

- If initial wait setup fails, exit `1` and emit no reviewer records.
- If a reviewer times out, emit `SENTINEL_TIMEOUT`.
- If retry metadata is invalid before launch, emit `EMPTY_OUTPUT` with `EXIT_CODE=99`.
- If retry launches but no retry sentinel appears, emit `EMPTY_OUTPUT` with `EXIT_CODE=99`.
- If retry exits non-zero, propagate the retry sentinel exit code.
- If substantive validation fails and non-substantive retry also fails, keep `NOT_SUBSTANTIVE`.
- If structured validation succeeds but sidecar publish fails, keep the row non-OK or omit the sidecar per current bash behavior.
