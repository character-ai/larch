## Plan

## Approach

Make a hard cutover to `python3 python/cli.py agent collect-results`.

Keep the observable collector contract stable:

- stdout record grammar stays unchanged.
- record order stays argv order.
- wait timeout correlation stays index-based.
- retry metadata remains fail-closed.
- `LARCH_QUIET_DISABLE=1` and fd-3 behavior stay compatible with `logging_util.quiet_init()`.
- no shim remains at `scripts/collect-agent-results.sh`.

**Exit contract (process vs per-reviewer):** the collector CLI returns **0** after emitting all argv-indexed reviewer record blocks, even when individual rows carry `STATUS!=OK` (`FAILED`, `TIMED_OUT`, `NOT_SUBSTANTIVE`, etc.). Per-reviewer failure is expressed only via `STATUS` / `FAILURE_REASON` / `EXIT_CODE` fields. Reserve **non-zero** process exit for pre-emit failures only: missing/invalid args, non-positive `--timeout` (pre-wait validation), initial wait fatals, and any other path that emits **no** `REVIEWER_FILE=` blocks. `collect-findings.sh` exits on non-zero `collector_rc`, and `dispatch-with-waterfall.sh` runs the collector inside command substitution under `set -e`; exiting `1` on per-reviewer failures would abort `/review` collection and waterfall phase settlement.

**Stderr prefix contract (operator diagnostics vs run-log labels):**

- **Stdout KV grammar** is unchanged.
- **Operator-visible stderr diagnostics** (timeout/argv validation after `quiet_init`, transient-retry notices, NS-retry notices, outer-launcher validation errors, initial-wait fatal relay, legacy wait trailer) keep the **`collect-agent-results.sh:`** prefix so quiet-session FD routing and harness parity (`C_T1`, `C_T4`, etc.) remain stable.
- Reserve **`agent collect-results`** for **run-log / failure-append tool labels only** (`append_review_failure`, `run-log append-failure --tool`, human-readable labels in `design-step1d5.sh`, `collect-findings.sh` failure logging). Do **not** retarget operator stderr diagnostic prefixes to `agent collect-results`.

Use existing Python surfaces where they already own behavior:

- `review_dispatch.wait_reviewers()` for sentinel waits (with caller-controlled emit/diagnostic sinks).
- `review_dispatch._validate_positive_int()` (same rules as `wait_reviewers_main`) for positive-timeout validation on the initial wait.
- `review_dispatch.render_failed_agent_stderr_tail()` for redacted stderr tails.
- `retry.is_transient_net_signature()` for transient diagnostics.
- `logging_util.quiet_init()`, `emit()`, and `diagnostic()` for contract output and diagnostics.
- `agents._COLLECTOR_NS_STRONG_HEADER` for non-substantive retry prompt strengthening.
- `python/cli.py agent external-tool-registry --kind external-tools` (or equivalent helper) for `.meta` `TOOL=` allowlist parity with `scripts/external-tool-registry.sh`.
- `python/cli.py` subprocess verbs for launcher replay and validation.

Port failed-agent stderr tail resolution from `scripts/lib-failed-agent-stderr-tail.sh` (`resolve_collector_stderr_tail_file`, `collector_stderr_tail_candidates`, `failed_agent_stderr_signature`) into `python/collect_results.py` or a small shared Python helper colocated with `review_dispatch.py`. Treat that shell library as normative for suffix preference, phase-candidate walk, temp tail materialization from `.launch-stderr`, and signature-based dedup.

Use subprocess seams in the new module so tests can monkeypatch launch, wait, validation, filesystem, and cwd without invoking the deleted shell script.

**CLI entry quiet routing:** call `logging_util.quiet_init(argv0="collect-agent-results.sh")` as step 0 of `collect_results_main`, before flag parsing, matching `scripts/collect-agent-results.sh:189` (`larch_quiet_init` before the arg loop). This ensures `emit()` routes `REVIEWER_FILE` blocks through fd 3 when a parent uses command substitution without `LARCH_QUIET_DISABLE` (for example `scripts/dispatch-with-waterfall.sh:344`). Honor `LARCH_QUIET_DISABLE=1` via existing `quiet_init` no-op behavior.

**Post-`quiet_init` validation diagnostics (finding 1):** after `quiet_init`, timeout and argv validation failures must **not** rely on raw `print(..., file=sys.stderr)` from `review_dispatch._validate_positive_int` or similar helpers (quiet mode routes stderr to the quiet log, not FD 4 or a caller `2>` capture such as `design-step1d5.sh` or `collect-findings.sh` stderr replay). Wrap validation: call `_validate_positive_int` (or equivalent), and on failure emit the same message text through `logging_util.diagnostic()` with **`collect-agent-results.sh:`** prefixes; exit `1` with no `REVIEWER_FILE=` / `STATUS=` stdout.

**Initial wait (shell parity):**

- Before any polling, reject non-positive `--timeout` using `_validate_positive_int` rules; on failure emit via `diagnostic()` with `collect-agent-results.sh:` prefix, exit `1`, **no** `REVIEWER_FILE=` / `STATUS=` stdout, **no** `wait-for-reviewers.sh exited` trailer (pre-wait path; intentional change from subprocess wait passthrough).
- Do not call in-process `wait_reviewers(timeout=0)`; `wait_max_polls` floors at 1 and would break bad-timeout parity.
- Run the initial wait through buffered in-process `wait_reviewers()`: pass captured `emit_fn` and `diagnostic_fn` wrappers that accumulate lines into memory for parsing only.
- On success (`wait_reviewers` returns `0`): consume buffered `TIMEOUT` indices internally; do **not** relay `DONE`/`TIMEOUT` lines or poll progress dots onto the collector contract stream.
- On failure (`wait_reviewers` returns non-zero **after** a valid positive `--timeout`): relay sanitized buffered diagnostics via `larch_err` / `diagnostic()` with `collect-agent-results.sh:` prefixes, then emit the legacy trailer **`collect-agent-results.sh: wait-for-reviewers.sh exited <rc>`** via `diagnostic()` (matching `scripts/collect-agent-results.sh:315-318` and `scripts/collect-agent-results.md`); exit `1` with no reviewer records (issue #1188 relay parity). **Do not** emit this trailer on the pre-wait non-positive `--timeout` path.
- Parse wait output by `TIMEOUT <idx> <basename>` and correlate by 1-based argv index.

**Retry-phase waits:** use no-op `emit_fn` / `diagnostic_fn` sinks (equivalent to `>/dev/null 2>&1 || true`); swallow non-zero wait exit; derive outcomes from sentinel files afterward.

**Retry child stdout/stderr suppression:** every non-blocking retry launch (CMD_JSON via `agent run-external-agent`, outer `agent launch-review`, outer `agent launch-codex-exec`) must use `stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL` (or an equivalent seam) matching shell `>/dev/null 2>&1 &` at `scripts/collect-agent-results.sh:823`, `:833`, `:926`, `:1173`. Do not inherit the collector parent's stdout/stderr fds. Launcher noise must not leak into quiet-session routing or the orchestrator terminal. Stderr tails remain recoverable only through the existing `.stderr-tail` / `.launch-stderr` materialization paths, not from retry child process streams.

**Outer-launcher replay cwd:** match `scripts/collect-agent-results.sh:810-833`: launch each outer retry in an isolated child context with `subprocess.Popen(..., cwd=validated_workdir)` (or a dedicated subprocess wrapper). **Never** call `os.chdir()` on the collector process; parallel retries with different workdirs must stay isolated and later argv-indexed rows must keep correct relative `.meta`/output and stderr-tail paths.

## Edge cases

- Duplicate basenames must remain correlated by argv index.
- `STATUS=OK` plus empty `FAILURE_REASON` is success.
- `EXIT_CODE=0` alone is not success.
- `cap_hit` remains terminal for waterfall phase collection.
- `CURSOR_DEGRADED_RESPONSE` remains equivalent to `CURSOR_EMPTY_RESPONSE`.
- Invalid initial `.done` values coerce to `EXIT_CODE=99`.
- Non-positive `--timeout` exits `1` via pre-wait `diagnostic()`; no reviewer records; **no** `wait-for-reviewers.sh exited` trailer.
- Initial wait fatal (valid positive timeout) relays diagnostics **and** legacy `wait-for-reviewers.sh exited <rc>` trailer via `diagnostic()`.
- Initial wait success must not stream `DONE`/`TIMEOUT` or poll progress onto collector stdout.
- `collect_results_main` must call `quiet_init(argv0="collect-agent-results.sh")` before arg parsing.
- Post-`quiet_init` validation failures must use `diagnostic()`, not raw stderr print.
- Operator stderr diagnostics keep `collect-agent-results.sh:` prefix; run-log tool labels use `agent collect-results`.
- Collector process exits **0** after emitting all records even when rows are `FAILED` / `TIMED_OUT` / `NOT_SUBSTANTIVE`.
- All non-blocking retry launches use `stdout=DEVNULL, stderr=DEVNULL`.
- Transient retry requires `${output}.diag`, eligible status, matching `is_transient_net_signature()`, and valid `.meta`.
- Outer replay uses per-launch `cwd=`; no global `os.chdir()`.
- All retries in a class launch in parallel before single batch `wait_reviewers`.
- `derive_ns_retry_reason` exit-code table is fixed per shell.
- `NS_RETRY_REASON` appended to `*-ns-retry.txt.meta` best-effort after NS-retry wait.
- `--summary-only` suppresses `FAILURE_REASON` and `STRUCTURED_SIDECAR`.
- `collect-findings.sh` keeps subshell `unset LARCH_QUIET_*` + `LARCH_QUIET_DISABLE=1`.
- `# Pin:` comment in `collect-findings.sh` must name `agent collect-results --timeout 1860 --substantive-validation --validation-mode`.

## Failure modes

- Non-positive `--timeout` exits `1` with `diagnostic()` validation text; no reviewer records; no wait trailer.
- Initial wait setup or validation exits `1` via `diagnostic()`; no reviewer records.
- Initial wait fatal relays buffered diagnostics plus `collect-agent-results.sh: wait-for-reviewers.sh exited <rc>`; no partial records.
- Raw stderr print after `quiet_init` would route validation errors to quiet log instead of caller `2>` capture.
- Per-reviewer `FAILED`/`TIMED_OUT` must **not** cause process exit non-zero (would break `set -e` callers).
- Retry children inheriting collector stdout/stderr would leak launcher noise.
- Sequential per-reviewer retry waits would inflate runtime and risk upstream timeouts.
- Global `os.chdir()` during outer replay would poison later argv-indexed paths.
- Stale Makefile shard entries for deleted harnesses would break `make lint`.
- Stale `# Pin:` comment would break `make test-review-structure` pin 13.
