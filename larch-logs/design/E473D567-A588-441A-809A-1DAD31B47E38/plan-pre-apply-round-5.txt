## Plan

## Approach

Make a hard cutover to `python3 python/cli.py agent collect-results`.

Keep the observable collector contract stable:

- stdout record grammar stays unchanged.
- record order stays argv order.
- wait timeout correlation stays index-based.
- retry metadata remains fail-closed.
- `LARCH_QUIET_DISABLE=1` and fd-3 behavior stay compatible with `logging_util.quiet_init()`.
- no shim remains at `scripts/collect-agent-results.sh`.

Use existing Python surfaces where they already own behavior:

- `review_dispatch.wait_reviewers()` for sentinel waits (with caller-controlled emit/diagnostic sinks).
- `review_dispatch._validate_positive_int()` (same path as `wait_reviewers_main`) for positive-timeout validation on the initial wait.
- `review_dispatch.render_failed_agent_stderr_tail()` for redacted stderr tails.
- `retry.is_transient_net_signature()` for transient diagnostics.
- `logging_util.quiet_init()`, `emit()`, and `diagnostic()` for contract output and diagnostics.
- `agents._COLLECTOR_NS_STRONG_HEADER` for non-substantive retry prompt strengthening.
- `python/cli.py agent external-tool-registry --kind external-tools` (or equivalent helper) for `.meta` `TOOL=` allowlist parity with `scripts/external-tool-registry.sh`.
- `python/cli.py` subprocess verbs for launcher replay and validation.

Port failed-agent stderr tail resolution from `scripts/lib-failed-agent-stderr-tail.sh` (`resolve_collector_stderr_tail_file`, `collector_stderr_tail_candidates`, `failed_agent_stderr_signature`) into `python/collect_results.py` or a small shared Python helper colocated with `review_dispatch.py`. Treat that shell library as normative for suffix preference, phase-candidate walk, temp tail materialization from `.launch-stderr`, and signature-based dedup.

Use subprocess seams in the new module so tests can monkeypatch launch, wait, validation, filesystem, and cwd without invoking the deleted shell script.

**CLI entry quiet routing (finding 4):** call `logging_util.quiet_init(argv0="collect-agent-results.sh")` as step 0 of `collect_results_main`, before flag parsing, matching `scripts/collect-agent-results.sh:189` (`larch_quiet_init` before the arg loop). This ensures `emit()` routes `REVIEWER_FILE` blocks through fd 3 when a parent uses command substitution without `LARCH_QUIET_DISABLE` (for example `scripts/dispatch-with-waterfall.sh:344`). Honor `LARCH_QUIET_DISABLE=1` via existing `quiet_init` no-op behavior.

**Initial wait (shell parity; findings 2 and 4):**

- Before any polling, reject non-positive `--timeout` using the same `_validate_positive_int` rules as `wait_reviewers_main` (`--timeout 0` or non-digit → exit `1`, no `REVIEWER_FILE=` / `STATUS=` stdout, wait error text on stderr). Do not call in-process `wait_reviewers(timeout=0)`; `wait_max_polls` floors at 1 and would break bad-timeout parity.
- Run the initial wait through buffered in-process `wait_reviewers()` (or an equivalent helper that shares validation): pass captured `emit_fn` and `diagnostic_fn` wrappers that accumulate lines into memory for parsing only.
- On success (`wait_reviewers` returns `0`): consume buffered `TIMEOUT` indices internally; do **not** relay `DONE`/`TIMEOUT` lines or poll progress dots onto the collector contract stream.
- On failure (`wait_reviewers` returns non-zero): relay sanitized buffered diagnostics via `larch_err` / `diagnostic()`, then exit `1` with no reviewer records (issue #1188 relay parity).
- Parse wait output by `TIMEOUT <idx> <basename>` and correlate by 1-based argv index.

**Retry-phase waits:** use no-op `emit_fn` / `diagnostic_fn` sinks (equivalent to `>/dev/null 2>&1 || true`); swallow non-zero wait exit; derive outcomes from sentinel files afterward.

**Retry child stdout/stderr suppression (finding 3):** every non-blocking retry launch (CMD_JSON via `agent run-external-agent`, outer `agent launch-review`, outer `agent launch-codex-exec`) must use `stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL` (or an equivalent seam) matching shell `>/dev/null 2>&1 &` at `scripts/collect-agent-results.sh:823`, `:833`, `:926`, `:1173`. Do not inherit the collector parent's stdout/stderr fds. Launcher noise must not leak into quiet-session routing or the orchestrator terminal. Stderr tails remain recoverable only through the existing `.stderr-tail` / `.launch-stderr` materialization paths, not from retry child process streams.

**Outer-launcher replay cwd (finding 1):** match `scripts/collect-agent-results.sh:810-833`: launch each outer retry in an isolated child context with `subprocess.Popen(..., cwd=validated_workdir)` (or a dedicated subprocess wrapper). **Never** call `os.chdir()` on the collector process; parallel retries with different workdirs must stay isolated and later argv-indexed rows must keep correct relative `.meta`/output and stderr-tail paths.

## Edge cases

- Duplicate basenames must remain correlated by argv index.
- `STATUS=OK` plus empty `FAILURE_REASON` is success.
- `EXIT_CODE=0` alone is not success.
- `cap_hit` remains terminal for waterfall phase collection.
- `CURSOR_DEGRADED_RESPONSE` remains equivalent to `CURSOR_EMPTY_RESPONSE`.
- Invalid initial `.done` values coerce to `EXIT_CODE=99`.
- Invalid `.done` plus empty output still gets one retry attempt when `.meta` is valid.
- `.meta` `TOOL=` is authoritative only when it passes the external-tool registry allowlist.
- Non-positive `--timeout` on initial wait exits `1` before polling; no reviewer records emitted.
- Initial wait success must not stream `DONE`/`TIMEOUT` or poll progress onto collector stdout; only final record blocks appear.
- `collect_results_main` must call `quiet_init(argv0="collect-agent-results.sh")` before arg parsing so inherited quiet-session parents get fd-3 record routing without `LARCH_QUIET_DISABLE`.
- All non-blocking retry launches must use `stdout=DEVNULL, stderr=DEVNULL`; stderr tails come only from `.stderr-tail` / `.launch-stderr` paths, not retry child streams.
- Transient retry requires `${output}.diag`, eligible status (`FAILED` / `TIMED_OUT` / `SENTINEL_TIMEOUT`), matching `is_transient_net_signature()`, and valid `.meta`; may remap to `EMPTY_OUTPUT` before queueing.
- Retry metadata fails closed for malformed JSON, missing timeout, unknown tool, bad launcher kind, bad sandbox, missing prompt file, bad workdir, bad add-dir JSON, review-shaped `CMD_JSON` without outer metadata, or present `${output}.prompt` without outer metadata.
- When any outer metadata field is set, outer replay takes precedence over `CMD_JSON` validation and routing.
- Outer replay must use per-launch `cwd=` on background subprocesses; collector process cwd must remain unchanged across the argv loop.
- All retries in a class launch in parallel (background / `Popen`) before the single batch `wait_reviewers`; never sequential launch-wait per reviewer within a class.
- Retry-phase `wait-reviewers` non-zero exit is swallowed; no-op sinks suppress wait chatter; sentinel inspection decides outcomes.
- `derive_ns_retry_reason` exit-code table is fixed: substantive `2|3` → `NO_ISSUES_FOUND_TOO_THIN`, `4` → `OUTPUT_EMPTY`, structured `5` → `JSON_PARSE_FAIL`, else `UNKNOWN`.
- `NS_RETRY_REASON` is recorded at classification and appended to `*-ns-retry.txt.meta` best-effort after NS-retry wait.
- `--summary-only` must suppress `FAILURE_REASON` and `STRUCTURED_SIDECAR`.
- Structured NS retry must publish sidecar beside original output and may downgrade to `CURSOR_EMPTY_RESPONSE` after publish.
- Stderr-tail dedup runs after retries and validation settle, using phase-candidate walk and signature normalization.
- `collect-findings.sh` must keep subshell `unset LARCH_QUIET_*` + `LARCH_QUIET_DISABLE=1` so quiet-session FD-4 routing does not swallow collector diagnostics.
- Python JSON replaces `jq`.
- Bash 3.2-specific implementation coverage is deleted, not recreated.
- `make lint` must not reference deleted `test-collect-agent-bash32` or `test-collect-agent-retry` harness targets after Makefile shard cleanup.

## Failure modes

- Non-positive `--timeout` on initial wait exits `1` with wait error text and emits no reviewer records (does not poll once with floored `wait_max_polls`).
- Initial wait setup or wait value validation exits `1` and emits no reviewer records.
- Initial wait fatal exit relays buffered diagnostics only; no partial reviewer records.
- Streaming wait progress or `DONE`/`TIMEOUT` lines onto collector stdout on initial-wait success would violate the contract stream.
- Omitting `quiet_init` at CLI entry would emit reviewer records on the wrong stream under inherited quiet-session state.
- Retry children that inherit collector stdout/stderr would leak launcher noise into quiet-session routing or parent capture files and corrupt failure diagnostics.
- A reviewer wait timeout emits `SENTINEL_TIMEOUT`.
- A process exit `124` emits `TIMED_OUT`.
- A non-zero process exit emits `FAILED`.
- Empty output without usable retry remains `EMPTY_OUTPUT`.
- Invalid retry metadata emits `EMPTY_OUTPUT` with `EXIT_CODE=99`.
- Retry launch without a retry sentinel emits `EMPTY_OUTPUT` with `EXIT_CODE=99`.
- Retry non-zero exit propagates the retry sentinel exit code.
- Transient retry without `.diag` does not queue retry (status stays `SENTINEL_TIMEOUT` / `TIMED_OUT` / `FAILED`).
- Sequential per-reviewer retry waits would inflate total runtime and risk upstream collector timeouts; parallel queue-then-batch-wait prevents that regression.
- Global `os.chdir()` during outer replay would poison relative paths for later argv-indexed rows in parallel retry batches.
- Substantive validation failure stays `NOT_SUBSTANTIVE` if non-substantive retry fails.
- Structured validation or structured NS retry success without a publishable sidecar must not emit a false successful sidecar path.
- Retry-phase wait fatals must not abort the collector when retry sentinels remain inspectable.
- Stale `test-collect-agent-bash32` / `test-collect-agent-retry` Makefile shard entries would break `make lint` after harness deletion.
