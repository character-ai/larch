## Edge cases

- If the remote log branch was deleted after a squash merge, final-mode idempotency still works only when the current final artifacts match the default branch after staging.
- If the default branch contains only pause-era artifacts, final mode must stage and publish the current final artifacts.
- If the default-branch fetch or tracking ref is stale, idempotent no-delta detection may miss and the script can fall through to normal publish behavior.
- If a stale result-env lock remains from a crashed process, the writer must not perform an unlocked clobber. It either skips because existing success is visible or returns a write failure after stdout KVs.
- If the failed-summary render lock cannot be acquired, the driver must not render `failed-publish` unlocked.
- If a current run fails validation or plan writing after a prior success, stale `PUBLISH_OK=true` must not be preserved.
- If a publish retry reaches the publish tail before the first invocation records success, normal failure handling can still run. The locked pre-render check prevents a false failed-publish render after success appears.

## Failure modes

- A stale or failed `origin/<default>` fetch can delay idempotent no-delta success detection until a later retry.
- The lock cannot protect writes if callers bypass `write_result_env_and_emit`; this change keeps all driver result-env writes on that helper path.
- The lock cannot protect summaries if callers render `failed-publish` outside the guarded helper; this change routes failed-publish rendering through the guarded path.
- If stdout capture is missing on exit `1`, `3`, or `4`, `design-step5c.sh` will still fail closed rather than read stale primary success.
