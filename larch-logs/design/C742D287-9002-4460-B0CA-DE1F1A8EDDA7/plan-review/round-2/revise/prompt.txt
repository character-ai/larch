## Edge cases

- **Unset, zero, invalid, negative, or non-finite env value:** `unique_finder_bonus_from_env` returns `0.0`; replay output stays unchanged.
- **OOS accepted rows:** keep base OOS scoring only. Do not add the unique-finder bonus.
- **Legacy TSV without `scope`:** keep existing `_classification_row_is_oos` / `_classification_row_in_scope` fallback based on `OOS_` id prefixes.
- **Multi-reviewer accepted rows:** keep shared base credit. Do not add the unique-finder bonus, even when `--reviewer-labels` or human-label filtering leaves only one matching reviewer.
- **Label-filtered scoreboard labels:** bonus eligibility must use raw attribution arity; the scoring loop remains filtered to requested labels.
- **Unknown reviewer labels in `voting scoreboard`:** keep existing behavior. Only labels present in the requested scoreboard receive points.
- **Fractional scores:** use `format_score` in both scoreboard output and `render_phase_detail` Top reviewers to avoid `3.0` output while allowing `3.25`.

## Failure modes

- Adding the bonus inside the per-reviewer loop without a sole-reviewer guard can reward every reviewer on a deduplicated finding.
- Using label-filtered reviewer list length for sole-finder eligibility can over-award when a second raw attribution label is omitted from `--reviewer-labels`.
- Reusing `accepted_points_from_classification_row` alone is insufficient because that helper intentionally returns `1` for accepted OOS rows.
- Reading the env var in each row can make tests harder to reason about and violates the planned replay-surface boundary.
- Keeping `int` annotations in progress Top reviewers or omitting `format_score` in `render_phase_detail` can hide fractional-score display bugs.
