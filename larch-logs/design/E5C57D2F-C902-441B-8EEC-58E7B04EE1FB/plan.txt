## Implementation Plan

Fix the undocumented `ship-pr.sh` exit 2 by removing the `set -e` state leak that lets a failing local CI harness abort the script with its raw exit code, and harden the harness rc-capture so a future leak cannot reproduce the crash. SIMPLE tier: smallest change that fixes the root cause; no routing changes.

## Root cause

- `scripts/ship-pr.sh` runs `set -uo pipefail` by design (lines 4-7: "Intentionally no `set -e`"). Every helper call captures `rc` explicitly.
- `run_pr_prep_phase` and its helper `run_oos_disposition_gate_if_required_before_oos_pending_false` wrap their OOS-gate calls in `set +e` … `set -e`, but the trailing `set -e` is **unconditional** at lines **1052**, **1557**, and **1567**. Unlike the correct save/restore idiom at lines **139-147** (`run_lint_fix_loop_capture`), these sites enable errexit even though the script baseline is `set +e`, and `set` options are global, so errexit leaks out of `run_pr_prep_phase`.
- `run_pr_prep_phase` runs before the CI phases. With errexit leaked on, `run_evaluate_failure` → `run_per_job_local_fix_loop` → `run_captured_cmd_then_fix_loop` → `_run_per_job_command_capture` (lines **2262-2267**) runs the local harness via the set-e-fragile pattern `"${_PJA_ARGV[@]}" > "$_RCC_RAW_LOG_PATH" 2>&1` immediately followed by `_RCC_CMD_RC=$?`. A failing harness (e.g. `make test-harnesses-12` exiting non-zero) trips errexit at the harness line and aborts the whole script with the raw harness code (2) **before** `_RCC_CMD_RC=$?` runs.
- Result matches the incident exactly: `⚠ ship-pr: running local CI job test-harnesses-12` (printed at line 2263) immediately followed by `SHIP_PR_EXIT=2`, with `BAIL_REASON` empty (cleared at line 2518) and `STALL_TRACKING=false` (no stall reached). Exit 2 is not in the documented orchestrator exit table (0, 3, 4, 5, 6).
- The issue's proposed fix (translate the code in `run_evaluate_failure`) cannot work alone: errexit aborts the script at the harness invocation before any translation logic is reached.

   ```
       "${_PJA_ARGV[@]}" > "$_RCC_RAW_LOG_PATH" 2>&1
       _RCC_CMD_RC=$?
   ```

   with

   ```
       _RCC_CMD_RC=0
       "${_PJA_ARGV[@]}" > "$_RCC_RAW_LOG_PATH" 2>&1 || _RCC_CMD_RC=$?

The `||` makes the harness command a tested command, so errexit never fires on it.

Leave `run_evaluate_failure`'s helper captures (`gh-run-logs.sh` ~2527, `ci-failed-jobs.sh` ~2567, `ci-rerun-failed.sh` ~2496) unchanged: they are protected by the leak fix above; hardening them is out of scope for this fix.

## Approach

- Treat this as an errexit-invariant restoration, not an exit-code translation. The documented exits already cover the confirmed-failure outcomes once the crash is removed: an unfixable local job exits 3 with `BAIL_REASON=ci-local-unfixable:<jobs>` (lines 2384/2484), and a fixable-but-exhausted job stalls at exit 4 (`…-max-retries`). No change to `run_evaluate_failure` routing or to `needs_user_bail_reason` / `is_autonomous_exit3_bail_reason`.
- Reuse the in-repo save/restore idiom (lines 139-147) verbatim in shape so the fix is consistent and review-obvious.
- Keep the change surgical: only the three toggle sites and the one harness-capture site are touched in `ship-pr.sh`.

## Edge cases

- **Errexit genuinely on at a toggle site.** The conditional restore re-enables errexit only when it was on before the `set +e`, so callers that legitimately run under errexit keep their state. With the current `set +e` baseline this is a no-op, which is the intended outcome.
- **Harness exits 0.** `_RCC_CMD_RC=0` initializer plus `|| _RCC_CMD_RC=$?` leaves `_RCC_CMD_RC=0`; the `_RCC_CMD_RC -eq 0` success branch (lines 280/304) is unchanged.
- **Harness exits with a documented orchestrator code (e.g. 2 from a nested helper).** The raw code is now captured into `_RCC_CMD_RC` and flows through the normal fix-loop / unfixable / stall logic instead of escaping as the process exit code.
- **`pipefail` interaction.** The hardened line is a simple redirected command, not a pipeline, so `pipefail` is irrelevant to it; behavior is unchanged.
- **Bash 3.2.** `case $- in *e*)`, `local`, and `|| var=$?` are all 3.2-safe; no Bash 4+ constructs are introduced.

## Failure modes

- **Incomplete leak fix.** If only the harness capture is hardened but any toggle site (helper or either `run_pr_prep_phase` outer wrapper at 1557/1567) still force-enables errexit, a different unguarded `cmd; rc=$?` site (e.g. `gh-run-logs.sh` capture) could abort instead. Mitigation: fix all three toggle sites; earliest signal: any new undocumented non-{0,3,4,5,6} exit from `ship-pr.sh`. The regression suite's baseline-off leak assertions (helper + both pr-prep outers) guard this.
- **Over-broad restore.** Force-enabling errexit elsewhere (wrong "fix") would re-introduce the class of bug. Mitigation: only restore prior state conditionally; never add an unconditional `set -e`. Signal: `make test-harnesses` / `test-ship-pr.sh` failures.
- **Contract drift with `_RCC_CMD_RC` consumers.** If the initializer is omitted, a success could leave a stale non-zero value. Mitigation: keep `_RCC_CMD_RC=0` before the `||` capture; the harness test asserts both success (0) and failure (real rc) values.

## Testing strategy

- New regression assertions in `scripts/test-ship-pr.sh` (above): with `set +e`, all three toggle surfaces leave `$-` without `e`; with `set -e`, restore-when-on subtests keep `e`; `_run_per_job_command_capture` is errexit-safe and records the real rc.
- Run the existing suite to confirm no regressions: `make test-harnesses` (or the targeted shard) and `bash scripts/test-ship-pr.sh`.
- Run `bash scripts/relevant-checks.sh` (lint, shellcheck, bash32) after the edits.
