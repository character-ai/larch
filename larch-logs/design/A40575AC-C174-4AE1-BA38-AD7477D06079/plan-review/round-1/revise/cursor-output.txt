## Plan

Fix the OOS disposition gate silently dropping accepted out-of-scope review findings (#3550). Root cause is a format-contract mismatch: producers write legacy `### FINDING_N: [OUT_OF_SCOPE]` headers (and scope-drift reclassifications keep bare `### FINDING_N:` headers), while counters and the filing parser key on `### OOS_N:`. On the production review path, `tally-code-votes.sh` writes accepted OOS into `oos-accepted-review.md`, but `emit-tally.sh` unconditionally invokes `oos-serialize.sh` on `oos.md` and **overwrites** that sink — dropping scope-drift blocks entirely and preserving legacy `FINDING_` headers for tagged OOS.

Fix = producer normalization in tally (primary) + **preserve tally output in emit-tally** when tally already wrote accepted OOS (production overwrite chain) + reader hardening (defense-in-depth) + regression tests spanning tally-only, emit-tally, review-core integration, and both bash/Python gates.

SIMPLE-tier: minimum change at each site. No gate-disposition math, vote-tally logic, `/issue` filing schema, or design-path OOS producer changes.

## Approach

Three layers, per Round 1 + accepted review findings:

1. **Producer normalization (`tally-code-votes.sh`)** — canonical `### OOS_<seq>:` on every accepted non-security block before write. Makes counter, gate, Step 9a.1 batch builder, and `parse-input.sh` see the canonical schema. Dual-sink writes reuse one normalized string; mirror only when paths differ.
2. **Emit-tally preservation (`emit-tally.sh`)** — when `OOS_ACCEPTED_COUNT > 0`, skip `oos-serialize.sh` so production `review-core` → `tally-code-votes` → `emit-tally` → `copy_to_parent` does not overwrite tally's normalized accepted file. This closes the scope-drift drop (bare `FINDING_N:` blocks never survive `oos-serialize` today).
3. **Reader hardening (awk + python)** — defense-in-depth for any surviving legacy tagged header; awk/python updated in lockstep.

`oos.md` / `oos-serialize.sh` left unchanged on the tally-wrote path; serialize remains the fallback when tally wrote zero accepted OOS.

## Edge cases

- Scope-drift bare `### FINDING_N:`: normalized by tally producer; reader backstop intentionally does **not** match (requires tag) — avoids miscounting in-scope findings in mixed files.
- Security-tagged OOS: never written to accepted-OOS file; producer change in non-security branch only.
- `OOS_ACCEPTED_OUT == OOS_ACCEPTED_FILE` (no `SESSION_ENV_PATH`): single append only — prevents doubled blocks and false gate failures.
- `OOS_ACCEPTED_COUNT > 0` but `oos.md` also present: emit-tally skips serialize; tally output wins.
- `OOS_ACCEPTED_COUNT == 0`: emit-tally still runs serialize/truncate — unchanged standalone behavior.
- 0-judge main-agent path: inherits tally + emit-tally fixes on re-tally.
- Header rewrite preserves title verbatim; only `### <ID>:` token replaced.
- Renumber-all for genuine `### OOS_N:` ids: safe — consumers key on ordinals.
- Bash 3.2 / BSD portability: awk `sub()`, not GNU sed.

## Failure modes

1. **emit-tally still overwrites tally output** — mitigated by `OOS_ACCEPTED_COUNT > 0` skip guard + review-core integration test. Earliest signal: parent `oos-accepted-review.md` contains `### FINDING_` after full review round.
2. **Dual-sink duplication** — mitigated by equality guard + standalone harness asserting awk count `== 1`. Earliest signal: gate false-fails with `non_security` 2× expected.
3. **Reader over-counts in-scope findings** — mitigated by requiring `[OUT_OF_SCOPE]` in reader match. Earliest signal: gate `non_security` higher than accepted OOS count.
4. **awk/python parity drift** — edit both in lockstep; shared test fixtures for legacy-header + security exclusion.
