## Plan

Fix the OOS disposition gate silently dropping accepted out-of-scope review findings (#3550). Root cause is a format-contract mismatch: producers write legacy `### FINDING_N: [OUT_OF_SCOPE]` headers (and scope-drift reclassifications keep bare `### FINDING_N:` headers), while counters and the filing parser key on `### OOS_N:`. On the production review path, `tally-code-votes.sh` writes accepted OOS into `oos-accepted-review.md`, but `emit-tally.sh` unconditionally invokes `oos-serialize.sh` on `oos.md` and **overwrites** that sink — dropping scope-drift blocks entirely and preserving legacy `FINDING_` headers for tagged OOS. A second bypass: `review-and-fix.sh` appends coder-`SKIPPED` blocks to `accumulated-oos.md` with bare `### FINDING_N:` headers, which reader backstop intentionally ignores.

Fix = shared header-normalization helper + producer normalization in tally and review-and-fix (primary) + **preserve tally output in emit-tally** when tally already wrote accepted OOS, guarding **both** serialize and truncate branches (production overwrite chain) + reader hardening (defense-in-depth) + regression tests spanning tally-only, emit-tally, review-and-fix skipped routing, and both bash/Python gates.

SIMPLE-tier: minimum change at each site. No gate-disposition math, vote-tally logic, `/issue` filing schema, or design-path OOS producer changes.

## Approach

Four layers, per Round 1 + accepted review findings:

1. **Shared normalization (`normalize-oos-block-header.sh`)** — single portable awk rewrite used by all accepted-OOS producers touched in this fix.
2. **Producer normalization (`tally-code-votes.sh` + `review-and-fix.sh`)** — canonical `### OOS_<seq>:` on every accepted non-security block before write. Tally covers voted OOS and scope-drift; review-and-fix covers coder-`SKIPPED` routing that bypassed tally. Dual-sink writes reuse one normalized string; mirror only when paths differ. Skipped-path seq continues from existing `accumulated-oos.md` block count across rounds.
3. **Emit-tally preservation (`emit-tally.sh`)** — when `OOS_ACCEPTED_COUNT > 0`, no-op preserve (neither serialize nor truncate). Closes the scope-drift drop and the missing-`oos.md` wipe that could clear tally output before `copy_to_parent`.
4. **Reader hardening (awk + python)** — defense-in-depth for any surviving legacy **tagged** `FINDING` header; intentionally does **not** count bare `FINDING` (normalization is the fix for dedicated OOS sinks).

`oos.md` / `oos-serialize.sh` left unchanged on the tally-wrote path; serialize remains the fallback when tally wrote zero accepted OOS.

## Edge cases

- Scope-drift bare `### FINDING_N:`: normalized by tally producer; reader backstop intentionally does **not** match (requires tag) — avoids miscounting in-scope findings in mixed files.
- Coder-skipped bare `### FINDING_N:`: normalized by review-and-fix producer at append — not deferred to reader extension.
- Security-tagged OOS: never written to accepted-OOS file; producer change in non-security branches only.
- `OOS_ACCEPTED_OUT == OOS_ACCEPTED_FILE` (no `SESSION_ENV_PATH`): single append only — prevents doubled blocks and false gate failures.
- `OOS_ACCEPTED_COUNT > 0` but `oos.md` missing: emit-tally preserve branch — no `:>` truncate.
- `OOS_ACCEPTED_COUNT > 0` but `oos.md` also present: emit-tally skips serialize; tally output wins.
- `OOS_ACCEPTED_COUNT == 0`: emit-tally still runs serialize/truncate — unchanged standalone behavior.
- Multi-round skipped OOS: seq monotonic across rounds via pre-append count on `accumulated-oos.md`.
- 0-judge main-agent path: inherits tally + emit-tally fixes on re-tally.
- Header rewrite preserves title verbatim; only `### <ID>:` token replaced.
- `test-review-core.sh` out of scope: harness stubs `REVIEW_CORE_TALLY_VOTES_SH` / `REVIEW_CORE_EMIT_TALLY_SH` to `$TMP/tally.sh` and `$TMP/emit.sh` (stub emit overwrites `oos-accepted-review.md` with placeholder content), so extending that harness cannot exercise the production tally→emit overwrite chain; FINDING_1 coverage stays in `test-tally-code-votes.sh` + `test-emit-tally.sh`.
- Renumber-all for genuine `### OOS_N:` ids: safe — consumers key on ordinals.
- Bash 3.2 / BSD portability: awk `sub()`, not GNU sed.

## Failure modes

1. **emit-tally still overwrites or truncates tally output** — mitigated by top-level `OOS_ACCEPTED_COUNT > 0` preserve guard covering **both** serialize and truncate branches + `test-emit-tally.sh` (pre-seeded tally output preserved with and without `oos.md`). Earliest signal: parent `oos-accepted-review.md` contains `### FINDING_` or is empty after full review round despite tally `OOS_ACCEPTED_COUNT > 0`.
2. **Dual-sink duplication** — mitigated by equality guard + standalone harness asserting awk count `== 1`. Earliest signal: gate false-fails with `non_security` 2× expected.
3. **Coder-skipped OOS bypasses normalization** — mitigated by review-and-fix append-path rewrite + `test-review-and-fix.sh` awk count assertion. Earliest signal: `oos-accepted-review.md` has bare `### FINDING_` after SKIPPED routing; disposition checkpoint count `0` with unfilled items.
4. **Reader over-counts in-scope findings** — mitigated by requiring `[OUT_OF_SCOPE]` in reader match for `FINDING` headers. Earliest signal: gate `non_security` higher than accepted OOS count in mixed accepted-findings files.
5. **awk/python parity drift** — edit both in lockstep; shared test fixtures for legacy-header + security exclusion.
