### FINDING_1: Extend `resolve_ledger_path` (not just `resolve_session_id`) for DESIGN_TMPDIR
- **Concern**: Plan item 7 extends only `resolve_session_id` to fall back to `$DESIGN_TMPDIR/session-id`. But `scripts/token-ledger.sh` also has a `resolve_ledger_path` function that determines the per-run ledger ROOT directory, and it does NOT currently consider `DESIGN_TMPDIR`. Standalone `/design` would get a session-id alignment but the actual JSONL ledger file might still land outside `$DESIGN_TMPDIR` (or trigger the "no per-run ledger root" warning seen during launch-review record-vendor calls). `scripts/timing-ledger.sh` already recognizes `DESIGN_TMPDIR` as a ledger root.
- **Reviewers**: Cursor-Arch, Cursor-Edge (×2 — duplicated), Cursor-Innovation, Cursor-Pragmatic, Cursor-Requirements, Codex-Arch, Codex-Edge, Codex-Pragmatic (8 reviewers, several with multi-finding emphasis)
- **Proposed resolution**: Add a `DESIGN_TMPDIR` directory branch to `resolve_ledger_path` mirroring `timing-ledger.sh:77-78` precedence, in addition to the `resolve_session_id` fallback. Extend the precedence narrative in plan items 7 + 8 to cover both functions. Update `scripts/test-token-ledger.sh` to assert ledger-root selection precedence.

### FINDING_2: Add an early token-ledger mark in /design (Step 0)
- **Concern**: `token-report.sh:376-380` requires at least one ledger mark to render totals; it errors "no step marks in ledger" otherwise. The plan emits a cost line on Step 0b fast-exit paths (clarify branch, already-planned cancel, tier-gate cancel), but these paths exit before Step 3 (which is the earliest current `token-ledger.sh mark` call). On those paths, `token-report.sh` would fail and the cost line would be suppressed even when the user actually has Claude orchestrator usage to report.
- **Reviewers**: Codex-Arch, Codex-Edge, Codex-Innovation, Codex-Pragmatic, Codex-Requirements (5 reviewers, all Codex)
- **Proposed resolution**: Add a `token-ledger.sh mark "design Step 0 — session setup"` call in `/design` Step 0 (after `session-setup.sh` succeeds and `DESIGN_TMPDIR` is bound). The mark seeds the ledger so token-report.sh works on any subsequent exit path. Note in plan item 13 that the Step 0a session-setup-failure path STILL has no DESIGN_TMPDIR and is the only true pre-ledger exit (skip emission there is correct; document explicitly).

The plan should explicitly acknowledge that the cost-line emission applies to standalone /design (which is the only supported invocation path going forward), and the nested-artifact-only contract no longer constrains this work. Add a one-sentence note to plan items 13/14 stating this. The cleanup of nested-/design references in /implement is OOS (user direction).

### FINDING_5: Structure test grep on `exit 0\b` / `exit 1\b` literals is brittle
- **Concern**: Plan item 14's structure assertion proposes grepping for `exit 0\b`, `exit 1\b`, and `**ℹ /design cancelled` to enumerate exit paths. SKILL.md uses Markdown prose like "exit **0**" and inline code-span "exit 0" — word-boundary grep on shell literals misses prose; the real `exit 1` shell call in Step 0a is the only shell-literal exit. The test would give false confidence.
- **Reviewers**: Cursor-Arch, Cursor-Requirements, plus implicitly Cursor-Edge
- **Proposed resolution**: Anchor the structure test on stable markers instead of `exit` literals: (a) presence of `render-cost-line.sh` invocation near every emission point; (b) `**ℹ /design cancelled` markers; (c) the terminal machine footer ➡️ string. Or: parse only fenced bash blocks for shell exits.

### FINDING_6: All-N/A test case in test-render-run-summary.sh breaks after defaults
- **Concern**: Plan changes token-cost.sh so unset rates yield default dollars instead of N/A. `scripts/test-render-run-summary.sh` lines 54-82 specifically asserts the "all N/A" output shape — that test loses its meaning and the harness intent silently breaks.
- **Reviewers**: Cursor-Arch, Cursor-Requirements, Cursor-Edge (latent)
- **Proposed resolution**: Replace the all-N/A test case with either (a) an explicit "force unknown rates" test hook (e.g., new env `LARCH_RATES_DISABLED=1` that opts out of defaults — but this expands scope), or (b) drop the all-N/A case and replace with a "all defaulted" assertion verifying the new dollar-shape output. Option (b) is preferred; document the rationale.

### FINDING_7: New test harnesses need Makefile + agent-lint.toml + docs/linting.md wiring

- **Reviewers**: Cursor-Arch, Cursor-Requirements, Codex-Innovation, Codex-Pragmatic, Codex-Requirements (5 reviewers, including 3 Codex)
- **Proposed resolution**: Add an explicit "Wiring" subsection to the plan listing: Makefile shard registration (mirror `test-render-run-summary` pattern), agent-lint.toml path allowlist entries, docs/linting.md harness inventory rows, and sibling `.md` stubs for every new test. ### FINDING_11: render-cost-line.sh and render-run-summary.sh duplicate fmt_usd / cost display
- **Concern**: New helper duplicates `fmt_usd` and cost-formatting logic from `render-run-summary.sh:127-136`. Drift risk over time.
- **Reviewers**: Cursor-Arch, Codex-Arch (latent)
- **Proposed resolution**: Two options: (a) share a sourced fragment `scripts/lib-cost-fmt.sh` consumed by both helpers; (b) have `render-cost-line.sh` consume only `token-cost.sh` `KEY=value` lines with a single in-house formatter (since token-cost.sh already does the math). ### FINDING_12: Plan assumes $DESIGN_TMPDIR/token-report.json exists but no plan step renders it
- **Concern**: Plan item 13 reads token counts from `$DESIGN_TMPDIR/token-report.json` "if rendered, else direct token-report.sh ... invocation". But no plan step currently INVOKES `token-report.sh --output $DESIGN_TMPDIR/token-report.json`; the file would never exist for the read path.
- **Reviewers**: Cursor-Edge
- **Proposed resolution**: Make the plan explicit: the emission step ALWAYS invokes `token-report.sh --full --format json --output $DESIGN_TMPDIR/token-report.json` first (with `--quiet-on-empty` or unavailable-detection downstream), then reads the rendered JSON. Remove the "if rendered, else" branch — it's misleading.

### FINDING_13: token-ledger.sh `pwd|sha256` third-tier fallback omitted from plan precedence
- **Concern**: Plan's three-tier precedence narrative (LARCH_TOKEN_SESSION_ID → IMPLEMENT_TMPDIR → DESIGN_TMPDIR) omits the existing fourth fallback in `token-ledger.sh:30-39` that hashes `pwd -P` as a last resort. Plan should either preserve it after DESIGN_TMPDIR or document its removal.
- **Reviewers**: Cursor-Edge
- **Proposed resolution**: Document the full precedence: `LARCH_TOKEN_SESSION_ID` → `IMPLEMENT_TMPDIR/session-id` → `DESIGN_TMPDIR/session-id` → `pwd-hash`. The pwd-hash fallback is preserved untouched.

### FINDING_14: token-cost.sh doesn't validate rate env strings — malformed values bypass defaults
- **Concern**: `scripts/token-cost.sh:14-31` `rate_or_na` accepts any non-empty string as a numeric rate. Malformed strings (e.g., `LARCH_CLAUDE_RATE_PER_M=abc`) would bypass defaults and reach awk math, producing zero costs without warning. With defaults shipping, malformed input would silently produce $0 instead of using the default.
- **Reviewers**: Codex-Edge, Codex-Innovation (latent)
- **Proposed resolution**: Add numeric validation (`^[0-9]+(\\.[0-9]+)?$` regex) on rate env vars. Malformed → fall through to default. Document in `scripts/token-cost.md`. Update tests to cover malformed input.

### FINDING_15: TOTAL_COST aggregation semantics change once N/A → defaults
- **Concern**: Currently `TOTAL_COST` sums only numeric vendor costs (skipping N/A). With defaults, all three vendors are always numeric, so `TOTAL_COST` ALWAYS sums all three. Behavior change isn't documented; downstream consumers expecting N/A propagation may behave differently.
- **Reviewers**: Cursor-Innovation (latent)
- **Proposed resolution**: Document the semantic change in `scripts/token-cost.md`: with defaults, all per-vendor costs are numeric, so `TOTAL_COST` always sums all three. Add a test asserting the new behavior. No downstream consumer breakage expected (render-run-summary.sh `cost_bullet` already handles N/A or numeric).

### FINDING_16: Default USD displayed without "not invoice grade" disclaimer
- **Concern**: Default dollar values become operator-visible. Without disclaimer, operators may misread them as actual billing truth. Latent UX / honesty concern (multiple reviewers framed it as security/latent).
- **Reviewers**: Cursor-Arch, Cursor-Edge, Cursor-Innovation, Cursor-Requirements
- **Proposed resolution**: Add a prominent "These are conservative estimates, not invoice-grade" line in `docs/configuration-and-permissions.md` near the rate env-var section. Also include in `scripts/token-cost.md`. The `💰 Cost:` line itself stays compact (no inline disclaimer — that would be noisy); the docs section bears the disclosure.

### FINDING_17: check-step-token-budget.sh documents IMPLEMENT_TMPDIR-only derivation
- **Concern**: `scripts/check-step-token-budget.sh:49-53` documents IMPLEMENT_TMPDIR-only `LARCH_TOKEN_SESSION_ID` derivation. After the plan, /design has its own session-id; budget-cap docs are stale.
- **Reviewers**: Cursor-Innovation
- **Proposed resolution**: Add `scripts/check-step-token-budget.sh` (or just its `.md`) to the plan's docs-update list noting the DESIGN_TMPDIR fallback now applies. No code change needed if `token-ledger.sh resolve_session_id` is the single source of truth (which it should be after FINDING_1).
