## Approach Synthesis

### Agreement (both Cursor-Generic and Codex-Generic)

1. **Root cause of "no cost report"**: `scripts/token-cost.sh` has no built-in default rates and `LARCH_*_RATE_PER_M` env vars are not set anywhere in the repo. With unset rates, `token-cost.sh` returns `N/A` for every vendor; `render-run-summary.sh` faithfully renders `**Cost**: TOTAL N/A — Claude N/A, Codex N/A, Cursor N/A` (verified in larch-logs/implement/E5A49BDA-… and 4F448A92-… final-summary.md). User perceives this as "no cost report".

2. **Fix location**: ship sensible default per-vendor rates baked into `scripts/token-cost.sh`. Env vars `LARCH_CLAUDE_RATE_PER_M`, `LARCH_CODEX_RATE_PER_M`, `LARCH_CURSOR_RATE_PER_M`, and `LARCH_TOKEN_RATE_PER_M` continue to take precedence when explicitly set. Keep stdout flat `KEY=value` lines. (Codex called this out; Cursor implicitly agrees by listing token-cost.sh as the affected file.)

3. **/design summary line**: emit the exact single-line format `💰 Cost: TOTAL ~$X — Claude $A, Codex $B, Cursor $C  |  Tokens: <T>k` BEFORE the terminal machine footer `➡️ 5: cleanup — plan written to issue #<N>; NEXT REQUIRED: continue`. Cursor: "new human-visible line ordered before the machine footer, with SKILL updates for every early-exit branch". Codex confirms the same ordering invariant.

4. **All /design exit paths**: cost+token line must be emitted on success (Step 5), Step 0 cancel, Gate A/B/C cancels, clarify branch, and error paths. Codex: "route cleanup exits through the same final-emission contract so the cost line appears before whatever terminal machine footer or terminal failure line exists for that path".

5. **/implement does NOT need new bullets** — the **Cost** bullet already exists in `render-run-summary.sh` and `final-summary.md`. The fix is to make the existing bullet show actual dollar amounts (by shipping defaults), not to add a new structure.

6. **Files**: 
   - `scripts/token-cost.sh` and `scripts/token-cost.md` — ship defaults + doc them
   - `docs/configuration-and-permissions.md` — expose the numeric default values
   - `skills/design/SKILL.md` Step 5 + Gate A/B/C cancel paths + Step 0 clarify branch — emit cost line before existing terminal footer
   - `skills/design/scripts/` — likely a small helper (e.g., `emit-cost-summary.sh`) to keep the formatter single-source
   - Tests: `scripts/test-token-cost.sh` (or its equivalent), `scripts/test-render-run-summary.sh` updates if any flag changes (none expected). Codex explicitly recommends regression cover via test-render-run-summary.sh and test-write-final-report.sh.

### Decision call: build a dedicated formatter helper vs. reuse render-run-summary.sh

Cursor implicitly endorses **a new helper for /design** ("requires a new human-visible line"). Codex hints at **a small formatting helper or mode around existing cost data** (could be either). Choosing: **a small helper script `scripts/render-cost-line.sh`** that ingests vendor token counts and emits the exact `💰 Cost: TOTAL ~$X — Claude $A, Codex $B, Cursor $C  |  Tokens: <T>k` line (one line, no trailing newline before next line). Reuses `token-cost.sh` for cost computation. Tokens line in /implement run summary remains in `render-run-summary.sh`; the new helper is /design-only. **Why a new helper**: render-run-summary.sh emits a full multi-bullet markdown block with a `<!-- larch:run-summary v=1 -->` sentinel — that's overkill for /design which wants ONE line; reusing it would force /design to either accept the full block or take on conditional rendering logic. A small dedicated helper keeps both surfaces simple.

### Codex's secondary observation: write-final-report.sh stale-data risk

Codex flagged that `skills/implement/scripts/write-final-report.sh` reads `$run_dir/token-report.json` FIRST and falls back to `$IMPLEMENT_TMPDIR/token-report-rendered.json` SECOND. Both files exist on most runs (Step 7a writes the committed run-dir version, later refreshes update tmpdir). Spot-check of `write-final-report.sh:165` confirms the iteration order. **Decision**: this is not the proximate cause of the user's "no cost report" complaint (that's the N/A from unset rates, fully explaining the observed behavior). Leave the read-order alone in scope of this issue; if reviewers raise it, treat as OOS or per-finding accept.

### Defaults values — concrete proposal

Use round, conservative ballpark numbers based on public list pricing for medium-tier blends (per 1M total tokens):
- `LARCH_CLAUDE_RATE_PER_M` default: **$6.00** (mid-blend between Sonnet input/output prices, account for cache discounts in practice).
- `LARCH_CODEX_RATE_PER_M` default: **$10.00** (OpenAI o-series mid-blend).
- `LARCH_CURSOR_RATE_PER_M` default: **$10.00** (Cursor billing approximation).

These are deliberately documented as "rough estimates" — users with real billing visibility will set their own rates. Document the rationale in `scripts/token-cost.md` and the numeric defaults in `docs/configuration-and-permissions.md` under the existing rate-env-vars subsection.

### Hard constraints preserved (re-listed)

1. `render-run-summary.sh` CLI flags and markdown block schema — no break.
2. `<!-- larch:run-summary v=1 -->` sentinel — unchanged.
3. `token-cost.sh` stdout `KEY=value` schema — preserved (defaults computed inside the same machinery).
4. Env-var precedence: explicit `LARCH_*_RATE_PER_M` overrides defaults.
5. `/design` terminal machine footer remains the LAST output line on the happy path.
6. Existing tests under `scripts/test-token-cost.sh` (or equivalent) must continue to pass; new tests cover defaults.
7. No new dependencies; bash + awk only.
