# Implementation Plan: Issue #2594 — dollar-cost summary for /implement and /design

## Goal

Make both `/implement` and `/design` display a per-vendor dollar-cost summary at the end of each run. `/implement` currently emits a `**Cost**: TOTAL N/A — Claude N/A, Codex N/A, Cursor N/A` bullet because no default rates ship and `LARCH_*_RATE_PER_M` env vars are unset; `/design` emits no cost or token summary at all. Two workstreams: (1) ship sensible per-vendor default rates so the existing /implement bullet shows real dollars by default; (2) add a single-line cost+tokens summary at the end of /design (and on every /design exit path) — this also requires extending the existing token-tracking plumbing to recognize standalone `/design` sessions.

**Standalone-only scope**: per explicit user direction, "/design can NEVER be called from /implement; a separate design session is in flight to clean up nested-/design remnants in /implement — do not file OOS for it." The plan therefore treats the standalone /design path as the only supported invocation. The Anti-pattern #7 nested-artifact-only contract (`skills/design/SKILL.md:103-104`) does not constrain this change. Nested-/design code-path cleanup is OUT OF SCOPE.

## Approach

**Centralize the rate-default knowledge in `token-cost.sh`** (Codex sketch's recommendation). Every cost consumer downstream — `render-run-summary.sh` for /implement, the new `render-cost-line.sh` for /design — calls `token-cost.sh` and gets numeric values without needing its own default knowledge. This keeps the schema flat: KEY=value lines stay the same; only the values change from `N/A` to dollars.

**For /design's token tracking**, extend BOTH `token-ledger.sh resolve_session_id` AND `resolve_ledger_path` to recognize `DESIGN_TMPDIR` as a fallback after the existing `IMPLEMENT_TMPDIR` check. This brings token-ledger to parity with `timing-ledger.sh` (which already recognizes DESIGN_TMPDIR). The pwd-hash fourth-tier fallback in `resolve_session_id` is preserved unchanged. Also extend `launch-review.sh` to derive `LARCH_TOKEN_SESSION_ID` from `$DESIGN_TMPDIR/session-id` when `IMPLEMENT_TMPDIR` is unset. With these extensions, external reviewer launches (Cursor/Codex sketches and plan-review reviewers) record their token counts to the design-session-keyed ledger; Claude orchestrator tokens come from `token-claude-source.sh` resolving the transcript independent of session-id (already works).

**Early token-ledger mark in /design Step 0**: `token-report.sh` requires at least one ledger mark to render totals. Step 0 (after session-setup.sh succeeds) is the earliest point at which `DESIGN_TMPDIR` is available. Add a `token-ledger.sh mark "design Step 0 — session setup"` call there so any subsequent exit path (Step 0b cancels, Step 5 happy path) has a populated ledger to read from.

**For /design's cost line**, a new tiny helper `scripts/render-cost-line.sh` produces the exact terminal-friendly format. It is NOT a substitute for `render-run-summary.sh` — that produces a full markdown bullet block with a `<!-- larch:run-summary v=1 -->` sentinel for tracking-issue comments and committed run logs; this new helper produces ONE terminal line with no sentinel and no markdown bullets, designed for end-of-run terminal output.

**Default rate values** (per 1M total tokens, blended across input/output/cache):
- Claude: `$6.00` — mid-blend matching typical Sonnet-class mix.
- Codex: `$10.00` — rough OpenAI o-series mid-blend.
- Cursor: `$10.00` — rough Cursor billing approximation.

These are deliberately documented as estimates with a "not invoice-grade" disclaimer. Users with billing visibility set their own rates via env vars.

**Malformed-rate handling**: `token-cost.sh` now strictly validates rate env vars with `^[0-9]+(\.[0-9]+)?$`. Empty, zero, or non-numeric → fall through to the default. This prevents silently producing $0 when a user typoed their env var.

**No back-compat shim**: changing N/A to defaulted dollars is a user-visible improvement, not a regression. Existing tests asserting N/A output (only `scripts/test-render-run-summary.sh`'s all-N/A case) are explicitly updated as part of FINDING_6 / test harness wiring.

## Edge cases

- **Zero token counts for a vendor**: `cost_for "$tokens" "$rate"` with `tokens=0` and a numeric default rate yields `$0.00` (consistent with "vendor didn't run"). The line still emits showing real $0 for that vendor.

- **All three vendors zero tokens** (very early /design exit before any ledger mark beyond Step 0 was recorded): `--quiet-on-empty` flag on `render-cost-line.sh` suppresses the line when ALL three counts are zero.

- **Token-report.sh transcript not resolvable** (no Claude Code session or transcripts gated): `token-report.sh` exits 0 with `Token report unavailable: …`. The emission falls back to zero token counts; `--quiet-on-empty` suppresses output. Print `**⚠ /design: token report unavailable; cost line suppressed**` before the machine footer in this case.

- **Malformed rate env var (e.g., `LARCH_CLAUDE_RATE_PER_M=abc`)**: strict regex validation in `token-cost.sh rate_or_default` catches this and falls through to default. Tests cover this path explicitly.

- **`LARCH_TOKEN_RATE_PER_M` set, others unset**: Claude rate falls back to `LARCH_TOKEN_RATE_PER_M` (existing behavior). Codex and Cursor use new per-vendor defaults. TOTAL_COST sums all three numerically.

- **Env var explicitly set to `0`**: existing `rate_or_na` treated `0` as N/A. With new defaults, `0` is also treated as "use default" — consistent. To force `$0` cost display for a vendor, the user would need to use a tiny rate like `0.01` (out of scope to add an explicit opt-out env var).

- **/design clarify branch fast-exit**: clarify-loop exits early after `plan-block-write.sh` success but before any external reviewers run. Token counts are mostly Claude orchestrator tokens. With the Step 0 token-ledger mark in place, `token-report.sh` returns a populated ledger and the cost line emits with real values.

- **Step 0a session-setup-failure and tier-flag mutual-exclusion abort** (pre-DESIGN_TMPDIR exits): no `DESIGN_TMPDIR` exists, no ledger, no transcript reachable through the rendering path. Skip emission entirely. Document this single-policy contract in plan item 14 (no `--quiet-on-empty` alternative).

## Failure modes

1. **`token-cost.sh` default-rate change breaks downstream consumers asserting N/A output**: `scripts/test-render-run-summary.sh`'s all-N/A case is the known affected harness. **Earliest signal**: `make lint` fails. **Mitigation**: FINDING_6 + plan item 23 explicitly replace that test case with an all-defaulted assertion in the same PR.

2. **Token-ledger session-id resolution change collides with an unintended caller**: extending `resolve_session_id` and `resolve_ledger_path` to check `DESIGN_TMPDIR` could surprise callers that set DESIGN_TMPDIR unexpectedly. **Earliest signal**: a /design ledger entry appears where none was expected. **Mitigation**: the fallback fires only when neither `LARCH_TOKEN_SESSION_ID` nor `IMPLEMENT_TMPDIR/session-id` is available — so explicit overrides win. Plan item 12 adds tests for the full precedence.

3. **/design SKILL.md exit-path emission misses a branch**: hard to detect statically. **Earliest signal**: user reports "cost line on the happy path but not when I bailed". **Mitigation**: FINDING_5 / plan item 22 anchors the structure test on `**ℹ /design cancelled` and `render-cost-line.sh` literals (not on brittle `exit N\b` greps), pairing every exit marker with an emission within N lines OR a whitelist entry for pre-DESIGN_TMPDIR exits.
