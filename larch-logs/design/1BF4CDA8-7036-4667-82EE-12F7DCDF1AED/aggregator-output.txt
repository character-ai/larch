### FINDING_2: Ruff audit subprocess must treat exit code 1 as violations-present success
- **Reviewer(s)**: Cursor-Arch, Cursor-Pragmatic
- **Severity**: blocking
- **Concern**: The plan omits explicit handling for ruff's non-zero exit during the audit-config scan. Production modules still emit complexity diagnostics, so `ruff check` exits 1 while printing valid violation JSON. Treating any non-zero ruff exit as a hard failure aborts before baseline comparison and keeps `make py-lint-main` / `python/cli.py lint complexity-baseline` red on the unchanged tree.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Document and implement: always parse `--output-format json` stdout for the five selected rules; treat ruff exit 0 and 1 as success paths when JSON parses; reserve exit 2 for missing ruff, empty/unparseable JSON, or unexpected ruff exit codes
  - From Cursor-Pragmatic: Run ruff with `check=False`; accept rc 0 (no records) and rc 1 (parse stdout JSON); reserve exit 2 for rc >= 2, empty/unparseable JSON, or spawn failures. Document the same semantics for the manual baseline-derivation command (rc 1 is expected when violations exist).

### FINDING_3: Normalize ruff filename paths before baseline indexing
- **Reviewer(s)**: Cursor-Pragmatic
- **Severity**: important
- **Concern**: Audit runs with `cwd=python/`, so ruff JSON may report `ship.py` or `./ship.py` (or mix `python/` prefixes). If baseline generation writes one form but later comparison keeps another, indexing reports spurious new identities and CI false-fails until manual rebaseline.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Pragmatic: Centralize filepath normalization in `parse_violation_record` (strip leading `./` and optional `python/`; use forward-slash repo-relative paths under `python/`) and reuse it for per-file-ignore grouping during baseline generation.
