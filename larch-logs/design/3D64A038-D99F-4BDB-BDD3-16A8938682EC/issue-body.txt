Preserve vendor-agent error diagnostics in committed run logs (audit all sites)

## Context

Design run `6835A3CB-12E6-41EF-8589-3C89D5ED18EF` (issue #3619, flushed in PR #3697), Step 3 plan review, round 1: the Codex scout leg (`scout-dynamic-archetypes`) failed with exit 7 after 5 launch attempts (`auth-retries=1, transient-retries=5`), burning 377s of the round's critical path before the Claude fallback produced the manifest in 55s. Post-hoc root-cause analysis of WHY codex failed was impossible: no codex stderr or diagnostics survived into the committed run log.

## Symptoms

- `larch-logs/design/6835A3CB-12E6-41EF-8589-3C89D5ED18EF/execution-issues.md` records the failure header — `codex-review failed (exit 7 — non-auth — auth-retries=1, transient-retries=5)` — but its error code block is **empty**.
- The committed `scout-plan-manifest.json.raw.stderr` (0 bytes) is NOT codex's stderr — it belongs to the Claude fallback tier, which reused the same `$OUTPUT` path (`.raw.meta` was likewise overwritten to `TOOL=claude TIMEOUT=180`).
- No `*.sidecar`, `*.diag`, or `*.events.jsonl` files exist anywhere in the committed run dir.
- The live session tmpdir (`~/.cache/larch/sessions/claude-design-*`) was already cleaned by the time of analysis, so the evidence is unrecoverable.

## Root cause analysis (four stacked layers)

1. **Codex stderr goes to a `.sidecar`, not `.stderr`** — `scripts/launch-review.sh` sets `SIDECAR="${OUTPUT}.sidecar"` (~line 556); the codex event stream goes to `${OUTPUT}.events.jsonl`; `run-external-agent.sh` failure summaries append to `${OUTPUT}.diag`. Anyone inspecting the committed log looks at `.stderr` and finds the wrong (fallback-tier) file.
2. **Retry hygiene truncates the sidecar between attempts** — `: > "$SIDECAR"` before each retry `continue` (`scripts/launch-review.sh` ~631/636 codex-side; ~1071/1083/1089 cursor-side). This is deliberate (per-attempt auth/quota classification must not read stale markers from a prior attempt) but it destroys attempts 1..N-1 stderr with no archived copy.
3. **The final attempt's failure path can produce no stderr at all** — the pre-launch health-gate fast-fail in `scripts/run-external-agent.sh` (~lines 207-224) writes `health-probe fast-fail: <tool> unhealthy before launch` plus probe diagnostics to `${OUTPUT}.diag` only, then exits (7 codex / 8 cursor) without touching stderr. The sidecar ends empty, and `append-tool-failure.sh` faithfully copies an empty block into `execution-issues.md`.
4. **Publish-time exclusion** — `scripts/design-log-publish.sh` `design_artifact_excluded()` (~line 304) drops `*.sidecar`, `*.diag`, `*.events.jsonl` from the committed run log (#3534 policy). The `.diag` file — append-only across retries and the one artifact holding all 5 attempts' failure lines — never reaches git. The implement-side batch table (`scripts/larch-log-batches.sh`) likewise has no slug for these diagnostic sidecars.

Net effect: the only stderr-derived artifact designed to survive into git is the redacted excerpt inside `execution-issues.md`, and it captures whatever the sidecar holds at give-up time — which on this failure shape is nothing.

## Suggested fix (this incident's surface)

1. `append_launch_failure` in `scripts/launch-review.sh`: when the sidecar is empty at failure-capture time, fall back to `${OUTPUT}.diag` (and/or a bounded tail of `${OUTPUT}.events.jsonl`) as the diagnostic source for `execution-issues.md`.
2. Preserve per-attempt stderr instead of discarding it: before each `: > "$SIDECAR"` truncation, append the outgoing content (with an attempt header) to `${OUTPUT}.sidecar.history`. Classification semantics stay intact — the live sidecar still holds only the current attempt.
3. Health-gate fast-fail in `scripts/run-external-agent.sh`: also echo the one-line diagnosis to stderr (not only `.diag`) so the sidecar is never empty on that path.
4. Publish: include failure diagnostics in the flush — allow `*.diag` (small, failure-only) and `*.sidecar.history` for failed launches in `design-log-publish.sh`, and add corresponding implement-side batch slugs in `larch-log-batches.sh`. Pipe newly published diagnostics through `redact-secrets.sh` at publish time. Keep #3534's intent by NOT publishing bulky raw transcripts for successful runs.

## General requirement: audit ALL vendor-agent call sites

Audit every call site that launches a vendor agent — codex, cursor, AND claude-as-subprocess (`scripts/launch-claude-subprocess.sh`) — including at least: `scripts/launch-review.sh`, `scripts/run-external-agent.sh`, `scripts/scout-dynamic-archetypes.sh`, `scripts/launch-codex-implement.sh`, `scripts/launch-cursor-implement.sh`, `scripts/launch-cursor-ci.sh`, `skills/review/scripts/dispatch-panel.sh`, `skills/review-and-fix/scripts/review-and-fix.sh`, the design/implement voter and aggregator launches, and any other `run-external-agent.sh` / launcher consumers.

For each site, verify and enforce all three properties:

1. **Saved**: on error, the agent's stderr AND tool-native diagnostic streams (codex `events.jsonl`, cursor JSON result/stderr, claude subprocess stderr) are written to files that survive the run — not truncated by retry loops, not deleted by cleanup before publish.
2. **Logged**: the failure lands in `execution-issues.md` (or the equivalent run log) with non-empty diagnostics whenever any diagnostic stream had content.
3. **Flushed**: those diagnostic files are included in the run-log flush that gets merged into git (`design-log-publish.sh` inclusion rules; `larch-log-batches.sh` slugs for `/implement`), redacted via `redact-secrets.sh`.

## Acceptance criteria

- A failed vendor launch at ANY site leaves enough committed diagnostics to distinguish, at minimum: health-gate fast-fail vs mid-run crash vs timeout (exit 124) vs auth vs quota.
- `execution-issues.md` error blocks are never empty when any diagnostic stream had content.
- An audit table (call site × {saved, logged, flushed}) is recorded in the PR description or a doc under `docs/`.
- Regression coverage per repo conventions (script-md siblings, `make lint` harnesses).
