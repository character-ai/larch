# Implementation Plan — Preserve vendor-agent error diagnostics in committed run logs (#3713)

SIMPLE tier. **Centralize**: `run-external-agent.sh` is the single composed-carrier producer so every vendor launch inherits the fix; launchers archive per-attempt history and do site-aware logging. Fix the incident's 4 stacked layers; classify every site in an audit table; add regression coverage. Sites not directly fixed are `inherits-via-run-external-agent.sh` or residual-OOS.

## Root cause (code-confirmed)

1. `scripts/append-tool-failure.sh:152` `cat`s `--output-file` verbatim; line 100 only checks existence → empty fenced block when the source is empty/zero-byte at give-up.
2. `scripts/launch-review.sh:644/1102` pass the live `$SIDECAR` as `--output-file`; retries truncate it first with no archive → empty at give-up. **`launch-review.sh` does NOT `source lib-failed-agent-stderr-tail.sh`** today.
3. `scripts/run-external-agent.sh:207-224` health-gate fast-fail writes only `${OUTPUT}.diag` and `: > "$OUTPUT_FILE"`; never touches the sidecar.
4. `scripts/design-log-publish.sh:304` excludes `*.sidecar`/`*.diag`/`*.events.jsonl`; `scripts/larch-log-batches.sh` has no failure slug.

## Central carrier — composed, final-failure-only

`${OUTPUT}.failure-diag` is the single committed failure carrier: a bounded **composed** artifact with labeled sections for every non-empty diagnostic stream needed for the failure.

**Producer + retry-then-success guard (F2/F1)**: `run-external-agent.sh` clears `${OUTPUT}.failure-diag` at ENTRY (before each attempt). It composes the carrier inside the existing `_write_sentinel_on_exit` EXIT trap when `EXIT_CODE != 0`, **before** writing `${OUTPUT}.done`, so a visible `.done` always implies the carrier already exists for failures (round-4 F1; no separate trap). A retry that later SUCCEEDS clears the prior carrier at the success-attempt entry and writes none on exit 0 → retry-then-success commits nothing. No-retry / single-attempt / direct-consumer failures still write it. Launcher give-up backstops cover early launcher exits that never reach a final wrapper attempt.

**Carrier source list (composed sections)**: `.sidecar.history`, a bounded filtered events history (archived before every events `rm`/reset — round-4 F5), final sink/sidecar, `.diag`, filtered `.events.jsonl` tail, `${OUTPUT}.stderr` (claude subprocess), `${OUTPUT}.launch-stderr`, `${OUTPUT}.launcher-stderr` (voters), and — for `--capture-stdout` — the base output file as a bounded source (round-4 F10). `--sink`/`--history`/`--events` cover caller-specific paths.

**Redaction boundary (round-3 F14)**: `write_failure_diag` folds only error/quota/`turn.failed` event lines (reuse `external_is_quota_failure` / type filter), strips top-level `.result` from wrapper/JSON sections (per `lib-redact.sh`) or bounds to stderr-only, keeps byte caps. Apply the same filter before `append_vendor_failure_diagnostics` / `append-tool-failure.sh --redact`.

**Publish**: only `*.failure-diag` is committed (design staging redacts at `design_publish_stage_file:420`; implement via the batch). Keep `*.sidecar`, `*.diag`, `*.events.jsonl`, AND `*.sidecar.history` excluded (explicit `*.sidecar.history` deny arm — round-3 F15).

## Approach

1. **Compose helper** `write_failure_diag OUTPUT [--sink] [--history] [--events]`: bounded labeled carrier with the redaction-boundary filter; append-with-header when the carrier exists. Bash 3.2-safe.
2. **Resolver** `resolve_failure_diagnostic_source OUTPUT [--sink] [--history] [--events]`: carrier-preferred, else first non-empty across the source list. Returns 1 when all empty.
3. **Never-empty log**: site-aware callers pass the resolved carrier to `append-tool-failure.sh`, which gains a fail-closed backstop — missing/zero-byte `--output-file` → synthesize `no diagnostics captured (exit N)`.
4. **Archive per-attempt** `external_stream_reset TARGET HISTORY LABEL` (any truncated/removed stream): archive then truncate. Wire at every sidecar, `.diag`, AND codex events truncation/removal site, including `run-external-agent.sh` entry cleanup (archive prior non-empty `.diag`/events before `rm`/clear — round-4 F5).
5. **Verdict ordering**: compute `external_failure_verdict` from the live sidecar/`.diag` (codex parity: pass `.diag` + events tail) BEFORE any reset; never read the just-truncated sidecar.
6. **Give-up ordering (round-4 F3)**: (A) preflight/no-wrapper exits → `write_failure_diag` then `resolve_failure_diagnostic_source` then log/flush; (B) post-wrapper give-up → carrier already exists, resolve + log only (no re-compose, no duplicate sections).
7. **Health-gate fast-fail** echoes its diagnosis to stderr in addition to `.diag`.
8. **Implement durable path (round-4 F14)**: one canonical `$IMPLEMENT_TMPDIR/vendor-failure-diagnostics.txt` batch is the single durable implement flush path; `append_vendor_failure_diagnostics RECORD_FILE OUTPUT SITE [--sink] [--history] [--events]` redacts + atomically appends (temp + `flock` / per-slot staging — F6) to avoid interleaving. A flush helper (sentinel / clear-after-success) runs from `step-7a.sh`, `larch-log-flush.sh`, and `refresh-run-logs.sh` so pre/post-Step-7a bails still commit it via `larch-log.sh append --batch vendor-failure-diagnostics --record-file` (inherits `larch_log_redact_file`). Per-output `*.failure-diag` write-round allowlisting is reserved only for paths that cannot reach the batch — avoid double-committing the same failure (round-4 F14).
9. **Log-location resolution (round-4 F4)**: shared resolver precedence `LARCH_EXECUTION_ISSUES_LOG` → `dirname(SESSION_ENV_PATH)` → IMPLEMENT_TMPDIR → DESIGN_TMPDIR → REVIEW_TMPDIR (explicit override first).
10. **Site-aware logging only in site-aware callers**: generic `launch-claude-subprocess.sh` calls `write_failure_diag` only; execution-issues + batch appends live in the wrappers that know the tmpdir + site.
11. **Audit + tests**; classify every site directly-fixed | inherits-via-`run-external-agent.sh` | residual-OOS, naming residual {saved, logged, flushed} gaps.

## Edge cases
- Retry-then-success: entry-clear + exit-0 → no carrier (F2).
- `.done` visible ⇒ carrier present for failures (sentinel-trap ordering, F1).
- Single-attempt / health-gate / auth-setup / model-args preflight: carrier still composed before exit (F8).
- Codex events removed between attempts: filtered events history archived first (F5).
- `--capture-stdout`: base output file is a bounded carrier source (F10).
- Scout tier reuse: tier-specific stems prevent entry-clear erasure (F15).
- Voter `.launcher-stderr`, dropped no-fallback slots: source list + `VOTER_*_BASE`/`DROPPED_SLOTS_FILE` (F8/F12).
- Sensitive JSON/tool content: error/quota-line filter + `.result` strip; same filter before execution-issues append (round-3 F14).
- Implement double-commit avoided: batch is durable; per-output allowlist only for batch-unreachable paths (F14).
- `/dev/null` sidecar no-op; redaction on every committed copy; Bash 3.2 (temp files + `while read`).

## Failure modes
- **Classification corruption.** Reset before verdict could misclassify auth/quota. Signal: `test-launch-review.sh` classification. Mitigation: verdict before reset (codex+cursor parity); history/carrier never read by classifiers.
- **Publish leak / balloon.** Stale carrier on retry-success, raw JSON, double-commit, or secrets could leak/bloat. Signal: `test-design-log-publish.sh` retry-then-success + redaction-boundary; `test-larch-log.sh` scoped allowlist. Mitigation: entry-clear, final-failure carrier, error-line filter + `.result` strip, batch-as-durable-path, line-420 / `larch_log_redact_file` redaction, byte caps.
- **Site-coverage drift.** A site marked "inherits" without a real carrier path stays broken. Signal: audit table + per-site harnesses. Mitigation: central carrier in `run-external-agent.sh`; audit names residual {saved,logged,flushed} gaps.
