## Findings

**1. [security] `python/plan_review.py:1003-1006` — result-env writes need bash-parity symlink refusal**

The plan calls for “atomic writes that reject symlink targets,” but the only in-tree atomic helper today is `_write_atomic`, which does not check whether the destination is a symlink. The bash contract embedded at `python/plan_review.py:942-947` refuses writes when the target path is a symlink. A native loop that reuses `_write_atomic` for `.step3-review-result.env` / `.step3-plan-review-result.env` can reintroduce a symlink-follow write.

**Suggested revision:** implement `phase_driver_write_result_env` in `python/design_lifecycle.py` (mktemp + mv, refuse `-L` targets) and route all Step 3 result-env persistence through it.

**2. [risk-integration] `python/design_lifecycle.py:27-48` — reads should stay on the canonical allowlist reader**

The plan adds new “safe result-env read/write” helpers inside `plan_review.py`, but `phase_driver_read_result_env` and `python/cli.py design read-result-env` already enforce symlink refusal, CR/LF rejection, and allowlist filtering (`python/test_design_lifecycle.py`).

**Suggested revision:** call the existing reader from the ported loop/MAV paths instead of adding a second parser in `plan_review.py`.

**3. [correctness] `skills/design/scripts/review-design-step3-loop.sh:130-137` — preserve postplan sidecar KV allowlist**

When relaying `.design-postplan-emit-result.env` during `step3_loop_emit_envelope`, bash only forwards a fixed set of `POSTPLAN_*`, `PLAN_SIZE_*`, and `DRIFT_*` keys. The plan ports loop mechanics but does not mention this filter.

**Suggested revision:** carry the same allowlist into the native `step3_loop_emit_envelope` port so stdout/postplan routing stays byte-stable.

**4. [correctness] `python/plan_review.py:1064-1065` — `persist_retally` must use scope-anchor retally-handoff**

`persist_retally_step3_env` is still legacy bash. The plan lists porting it, and `python/test_plan_review.py` already expects tally-error to drop `SCOPE_ANCHOR_FILE` while ok paths persist only validated anchors. The plan does not name `scope-anchor retally-handoff` (`python/rendering.py:608-630`).

**Suggested revision:** call `scope_anchor_retally_handoff_main` before writing `SCOPE_ANCHOR_FILE` into result-env files.

**5. [security] `skills/design/scripts/test-design-step3-mav.sh:173-201` — port symlink/outside-anchor MAV regressions to pytest**

The plan deletes `test-design-step3-mav.sh` after moving MAV into Python. That harness is the current guard for symlinked/broken `.step3-review-result.env` refusal and outside-tmpdir `SCOPE_ANCHOR_FILE` render failure.

**Suggested revision:** add explicit pytest coverage for those cases under “MAV pre/post phases” before removing the shell harness.
