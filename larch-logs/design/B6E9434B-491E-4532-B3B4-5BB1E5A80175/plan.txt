## Plan

Port `blocker-helpers.sh`, `parse-prose-blockers.sh`, `get-issue-state.sh`, `get-issue-info.sh`, and `get-issue-context.sh` to Python. Expose CLI verbs `blocker all-open` and `issue state|info|context`. Cut over only the scoped bash consumers and delete retired helpers and harnesses.

## Approach

Add two modules:

- `python/blocker.py`: native blocker resolution plus prose blocker parsing.
- `python/issue_query.py`: issue state, field, and context reads.

Add `gh` read wrappers and one public paginated JSON helper in `python/gh.py`.

Register four CLI entries in `python/cli.py`.

**KV output contract (quiet mode).** Every new CLI uses `logging_util.quiet_init` and must emit all machine-readable KV lines through `logging_util.emit_kv` (same pattern as `python/clarify.py`). Never use bare `print()` or `sys.stdout.write()` for `BLOCKERS=`, `STATE=`, `URL=`, `IS_PR=`, `VALUE=`, `TITLE_FILE=`, `BODY_FILE=`, `FAILED=`, or `ERROR=`. After `quiet_init`, FD 1 is redirected to the quiet log; contract output must go through `emit_kv` on FD 3 so `implement-admission.sh`, `implement-bootstrap.sh`, and `implement-finalize.sh` command substitution captures the KV block.

Cut over consumers:

- `scripts/implement-admission.sh`: replace `source blocker-helpers.sh` plus `all_open_blockers` with `python3 cli.py blocker all-open`.
- `scripts/implement-bootstrap.sh`: replace `get-issue-context.sh` and `get-issue-state.sh` call sites only; route through existing `$PY_CLI`.
- `scripts/implement-finalize.sh`: replace `get-issue-info.sh` call sites only; route through existing `$PY_CLI`.

Output contracts for new CLI verbs mirror their bash predecessors so existing `kv_value_from_block` and `kv_value` parsers remain unchanged.

Keep `STEP_FAILED=get-issue-state` in bootstrap failure output. Only the underlying command changes.

When `issue state` or `issue info` omits `--repo`, call `gh.resolve_repo`. If it returns `None`, pass `repo=None` to the issue-view wrappers and omit `--repo` on the `gh issue view` command. This preserves the old empty-repo fallback.

## Edge cases

- Native dependency API returns lowercase `open`: blocker is included.
- Native dependency API returns uppercase `OPEN`: blocker is included.
- Native dependency API returns 404 or unsupported feature error: return `[]`.
- Paginated native dependency payload: parse concatenated arrays through public `gh.loads_json_paginated_list`.
- Paginated comment payload: parse concatenated arrays through public `gh.loads_json_paginated_list`.
- Prose parser receives comments: parse each comment `.body` string, not raw JSON.
- Prose parser sees keyword and issue number split across lines: no match.
- Prose parser sees inline backticks spanning a newline: do not strip across the newline.
- Prose parser sees issue number followed by another digit: no match.
- Prose parser sees `Depends on [#150](url)`: no match.
- Prose parser sees `[Depends on #150](url)`: match.
- Prose parser sees self-reference: drop it before state lookup.
- `issue state` or `issue info` omits `--repo`: resolve repo with `gh.resolve_repo`.
- `gh.resolve_repo` returns `None` for `issue state` or `issue info`: omit `--repo` from `gh issue view`.
- `issue state` gets non-numeric `--issue`: emit `FAILED=true`, emit `ERROR=--issue must be numeric`, exit 1.
- `issue state` gets flag-looking value after `--issue` or `--repo`: emit `FAILED=true`, emit matching value-required `ERROR=`, exit 1.
- `issue state` emits `IS_PR=true` or `IS_PR=false` in lowercase only.
- `issue state` gh failure: emit separate `FAILED=true` and `ERROR=gh issue view failed: ...` lines via `emit_kv`, exit 1.
- `issue info` invalid field: emit `VALUE=` via `emit_kv` and exit 0.
- `issue info` missing `--issue` or `--field` after parse: emit `VALUE=` via `emit_kv` and exit 0.
- `issue info` `--issue`, `--field`, or `--repo` without a following value: exit 1 with no `VALUE=`.
- `issue context` missing required args or unknown flag after parse: exit 2 with no KV envelope.
- `issue context` `--issue`, `--repo`, or `--tmpdir` without a following value: exit 1 with no `TITLE_FILE`/`BODY_FILE`.
- `issue context` gh, parse, mkdir, or write failure: exit 1.
- `issue context` tmpdir does not exist: create it before writing.
- All CLI KV output after `quiet_init`: must use `logging_util.emit_kv`, never bare stdout.
- Empty issue body or no comments: prose blocker parsing returns no refs.
- Admission harness uses absolute `python/cli.py` path: stub still intercepts.
- Bootstrap harness context fetch: invoke-log coverage is preserved through the dispatcher.

## Failure modes

1. **Python unavailable on PATH**

   Admission emits `ADMISSION_ERROR="blocker all-open failed"` and exits 2. Bootstrap and finalize fail according to their existing command handling.

2. **`gh api` rate limit or auth failure during blocker lookup**

   Blocker lookup fails open and emits no blockers.

3. **KV emitted to stdout instead of contract stream after `quiet_init`**

   Bootstrap state probes and finalize rename see empty KV blocks despite successful gh reads. Mitigation: all CLI mains route success and failure envelopes through `logging_util.emit_kv`.

4. **`issue state` returns non-JSON**

   `issue state` emits `FAILED=true` and `ERROR=<single-line message>` on separate `emit_kv` lines, then exits 1. Bootstrap keeps existing `STEP_FAILED=get-issue-state` handling.

5. **`issue context` receives invalid arguments**

   Missing required args or unknown flags exit 2. Missing flag values exit 1 with no KV envelope. Runtime failures exit 1.

6. **`issue info` receives a flag without a value**

   Exits 1 with no `VALUE=` envelope, matching the retired helper.

7. **Harness misses a new Python call**

   The updated admission, bootstrap, and finalize harnesses must intercept `cli.py blocker all-open` and `cli.py issue state|context|info` so offline tests do not hit real GitHub or deleted helper paths.

8. **Retired `.md` contracts omitted from `migrated-scripts.tsv`**

   Retired-script lint cannot catch references to deleted contract docs. Mitigation: append every Deleted-block path, including `.md` files.
