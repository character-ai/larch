# Approach Synthesis

**Sketch inputs**: 1 substantive (Codex-Generic), 1 empty stub (Cursor-Generic, 175 bytes — see `execution-issues.md`). Synthesis derived from Codex with no divergence-resolution needed.

## Agreement (single-sketch baseline)

The implementation is a **contract collapse**, not a compatibility layer. Specifically:

1. **`design_classification` is the sole tier input** everywhere. The single enum `SIMPLE | HARD` controls Step 2a (sketch presence), Step 2a.5 (dialectic presence), Step 3 (always full panel review for both tiers), Step 3 reviewer prompts (per-tier emphasis), Step 2b plan-writer self-direction (per-tier emphasis), Gate C cap (3 vs 5), and the tier-gate `AskUserQuestion` description text.

2. **No translation layer**. `quick_mode`, `review_budget`, `workflow_path`, `sketch_budget`, `design_classification_source`, `design_classification_reason` are **deleted** from `run-params.json` schema (v2). They are not preserved as derived/computed fields — downstream readers (timing-ledger, render-final-summary, plan-review-loop, etc.) switch to reading `design_classification`.

3. **`--trivial` argv → hard error** in Pre-Step-0, before `session-setup.sh`. No deprecation shim, no silent upgrade.

4. **Step 2a SIMPLE branch** writes sentinel stubs using the renamed `NO_SKETCHES_CLASSIFIED_SIMPLE` token. Step 2a HARD branch launches the 4 personality sketches unchanged.

5. **Step 3 always invokes `plan-review-loop.sh`** (full panel). The `read-design-review-budget.sh` gate is deleted. The validator gate `invoke-plan-validator-if-not-quick.sh` is renamed to `invoke-plan-validator.sh` and runs unconditionally.

6. **Per-tier emphasis injection** at three surfaces:
   - (a) Step 2b plan-writer prose in `SKILL.md` — designer-side instruction ("smallest change…" for SIMPLE; "thoroughness…" for HARD).
   - (b) Step 3 reviewer prompt template via `render-plan-review-prompt.sh` and `references/plan-review.md` — reviewer-side instruction ("flag scope creep, prefer EXONERATE on nits…" for SIMPLE; "flag missed considerations, engage seriously…" for HARD).
   - (c) Tier-gate `AskUserQuestion` option descriptions in Step 0b — operator-facing.

7. **Gate C cap requires state**. The cap is per-tier (SIMPLE=3, HARD=5) and lives across Gate B/C iterations, so the orchestrator must persist a review-round counter in `$DESIGN_TMPDIR` (e.g., `$DESIGN_TMPDIR/review-round-count.txt`) — incremented before each Step 3 entry, read by Gate C to decide whether to hide the "Re-run review panel" option. Passing `--round-num` to `plan-review-loop.sh` is the existing pattern (already used internally); the orchestrator-side counter can drive it.

8. **Harness updates are part of the feature, not follow-up**. `scripts/test-design-structure.sh`, `skills/design/scripts/test-design-driver.sh`, `scripts/test-write-run-params.sh`, `skills/design/scripts/test-read-design-review-budget-invoke.sh` (delete entirely), and `skills/design/scripts/test-render-final-summary.sh` all pin the old three-tier / budget model. Update or delete in the same PR.

## Tradeoffs and risks

- **SIMPLE is heavier than old TRIVIAL in runtime** (full review panel + validator always run). The tier-gate description must make this clear: SIMPLE optimizes for minimal *change*, not minimal *runtime*. Operators picking SIMPLE expecting Claude-only fast review will be surprised by the 10-22 external reviewer panel.
- **Structural test churn is the biggest risk**. Old pins assert literal `--trivial` prose in SKILL.md and `TRIVIAL_DOC_ONLY` enum values. Forgetting any breaks CI.
- **Downstream readers of `workflow_path` / `quick_mode`** (timing-ledger.sh, render-final-summary.sh, run-analysis.sh in report-tokens, topology.tsv) need to switch to `design_classification`. Each touch is small but the file count is wider than just `skills/design/`.
- **No backward compat anywhere** means existing run-params.json files from in-flight `/design` runs (across other clones) become unreadable after the schema bump. This is acceptable per the no-compat directive but should be noted.
