### Decisions chosen by synthesis (not from sketches; reasoned from Round 1 + codebase)

- **`-p`/`--partition` semantics**: when set, the post-Step-2b check is bypassed and the soft-trigger AskUserQuestion fires unconditionally on every plan write. Mutually exclusive with `--trivial`; error before Step 0 if both appear.
- **Step 1c/1d sprawl heuristic placement**: a one-paragraph addition to `discussion-rounds.md` Step 1c body — the orchestrator may proactively fire an extra `AskUserQuestion` offering the partition path before Step 2a launches sketches, when answers suggest several distinct sub-features or cross-cutting infrastructure changes. The hard-fail "panel in development" path applies here too on selection. No mechanical assertion.
- **Helper exit code**: helper itself returns 0 in all detection cases (triggers don't cause exit codes — they're reported via KV). Non-zero only on input validation failure (missing `plan.txt`, malformed `diff_lines: <N>` trailer).
- **`TRIGGER_REASONS` format**: comma-separated tokens (`plan-body-lines`, `diff-lines`, `files-count`, `partition-flag`, `semantic-guesstimate`). Diagnostic counts emitted as separate KV lines.

### Risks surfaced

- **Helper false positives** if Step 2b plan format isn't fully migrated to headings (a plan with only bulleted Files-to-modify would never trip files-count). Mitigation: migrate Step 2b prose **and** reviewer-prompt rendering in the same change, plus harness coverage that includes both old-format (skipping) and new-format (counting) inputs.
- **Reviewer-prompt rendering churn**: changing the prompt template format might break the existing test-render harness. Mitigation: list all render-fixture test files in the plan's Files-to-modify section so reviewers see the full footprint.
- **Cursor-Generic empty-sketch anomaly**: noted in execution-issues; not a planning risk for this design.
- **L3 comment-post failure**: best-effort at end of Step 5; failure non-fatal but logged to Warnings.
