### Approach

Introduce a `BOTH_DOWN` sentinel that makes the single-tool-down vs both-down distinction explicit at the detector level. This lets all four callers and `external-reviewers.md` use a single conditional instead of re-deriving the logic from `CODEX_STATE`/`CURSOR_STATE` themselves.

The explanation-block text change in `degraded-tools-gate.sh` ensures that the block the caller prints already says the right thing regardless of whether the caller uses it as a notice or as a question preamble.

### Edge cases

- `BOTH_DOWN` is always `false` when `DEGRADED=false` (trivially, nothing to branch on). Callers only consult `BOTH_DOWN` when `DEGRADED=true`.
- The `.degraded-tools-gate-prompted` sentinel continues to fire in both sub-branches so re-entry on the same run does not re-warn or re-ask.
- Autonomous/non-interactive behavior is unchanged: the existing `On a non-interactive run, log and proceed` branch stays as-is; `BOTH_DOWN` is irrelevant on that path.
- Test harness: existing cases that assert explanation-block presence remain valid; the two new Cases (13/14) pin the last-line text divergence.

### Failure modes

- If a caller does not parse `BOTH_DOWN` from the gate output, `BOTH_DOWN` is unset and the caller defaults to the old "ask always" behavior — no regression.
- If `degraded-tools-gate.sh` emits `BOTH_DOWN` before callers are updated (partial deploy), callers silently ignore the new KV and behave as before — safe rollout order.

### Testing strategy

- `test-degraded-tools-gate.sh`: add `BOTH_DOWN` assertions to existing Cases 2–4; add Cases 13–14 for explanation text divergence. Run: `bash scripts/test-degraded-tools-gate.sh`.
- No new integration test needed: `make lint` already wires `test-degraded-tools-gate` into the pre-commit check.
