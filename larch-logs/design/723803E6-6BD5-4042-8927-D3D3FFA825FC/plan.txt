## Summary

Move the `[DESIGNING]`→`[DESIGNED]` title rename in `design-publish.sh` to right after the architecture-diagram upsert, and drop its `PUBLISH_OK==true` gate. This admits the issue to `/implement` as soon as the plan + diagram are posted, without waiting on the design-log PR. A later log-publish failure can no longer block or delay `/implement`. The `design_reentry_marker_write` guard stays where it is (after publish, still gated on `PUBLISH_OK==true`), per operator decision.

SIMPLE-tier reorder inside one script, plus its contract, two test harnesses, and stale prose in three docs (SKILL.md Step 5c, `implement-admission.md`, `approval-gates.md`). No `/implement`, security, or publish-model change. No new flags, modes, or result-env keys.

## Approach

The change is a pure reorder plus one gate removal. The rename block already returns `RENAMED` into the result env via `write_result_env_and_emit`; moving the block earlier does not change what it emits, only when it runs and under which condition. Splitting the old combined block keeps each concern with its own gate: rename → `SESSION_ID` only; marker → `SESSION_ID` + `PUBLISH_OK`. The `lib-design-reentry-guard.sh` source stays bundled with the marker because only the marker needs it.

`/implement` is untouched: it admits on the `[DESIGNED]` title, which now appears earlier. No new flags, no new files, no new result-env keys, no signature changes. The two doc edits are pure prose-accuracy fixes for the new timing.

## Edge cases

- **`SESSION_ID` empty** (defensive path; never hit in real runs since Step 0a guarantees a UUID): rename still skipped, because the new block keeps the `SESSION_ID` guard. Marker still skipped. Matches today.
- **Publish fails after a successful rename**: issue is already `[DESIGNED]` with a `larch:plan` block; `RENAMED=true` in the result env; `SUMMARY_OUTCOME=failed-publish` and the "log publish incomplete" footer still fire. `/implement` can proceed. This is the intended new behavior.
- **Rename fails** (best-effort): warn is emitted and the run continues to publish exactly as before; only the warn text changed.
- **Spurious `/design` re-invocation after a publish failure**: no reentry marker is written (still publish-gated), but the already-`[DESIGNED]` title routes a re-invocation to the already-planned path, so there is no protection gap.

## Failure modes

1. **A test silently keeps the old order green** — if the structure-test pin or the harness ordering assertion is mis-edited, a future refactor could move the rename back without detection. Mitigation: the new `upsert < rename < publish_log` structure pin plus the flipped harness assertions both fail loudly if the rename drifts back behind publish. Earliest signal: `bash scripts/test-design-structure.sh` and `bash skills/design/scripts/test-design-publish.sh`.
2. **Result-env regex drift** — the rename-failure warn text feeds `grep 'WARN=.*\[DESIGNED\].*rename failed'`. Mitigation: keep `[DESIGNED]` and `rename failed` literally in the new string. Earliest signal: the "rename failure" harness case.
3. **SKILL.md structure-pin breakage** — editing Step 5c item 6 could disturb the pinned `step-5c` sentinel substring. Mitigation: edit only the trailing rename/cleanup clause; re-run `scripts/test-design-structure.sh`. Earliest signal: a `(15b)` / `(25)` structure-test failure.
