# Move [DESIGNING]→[DESIGNED] rename to right after the architecture-diagram upsert (drop PUBLISH_OK gate)

Source: GitHub issue #3482 — "Move renaming issue title prefix from [DESIGNING] to [DESIGNED] in /design to right after diagram is posted to issue"

## Current order (inside design-publish.sh, Step 5c)

1. Post the plan to the issue — `plan-block-write.sh` writes the `larch:plan` block into the issue body. Sets `PLAN_WRITE_OK=true`.
2. Upsert the architecture-diagram comment.
3. Create + merge the logs-flush PR — `design-log-publish.sh` (disposable worktree → push → `gh pr create` → wait for required CI → `gh pr merge --squash --admin --delete-branch`). It emits `PUBLISH_OK=true` only after the squash `--admin` merge completes.
4. Render the final summary.
5. Rename `[DESIGNING]` → `[DESIGNED]` — `tracking-issue-write.sh rename --state designed`, but gated on `PUBLISH_OK == true` (`if [ -n "$SESSION_ID" ] && [ "$PUBLISH_OK" == true ]`).

## TODO

Move (5) to right after (2), dropping the gating on `PUBLISH_OK == true` — publish now happens in a subsequent step rather than earlier, so the rename no longer needs to wait for it.

## Operator clarification (binding)

The operator explicitly accepts and *wants* the consequence that the design-log PR will NOT yet be published/merged when an `/implement` run could pick up this issue. That earlier admission of `[DESIGNED]` is the entire point of the optimization. The rename must therefore happen before (and independent of) the `design-log-publish.sh` publish step, and must no longer be gated on `PUBLISH_OK`.

Additionally (binding): log flushing, **even if it fails**, must not prevent or affect in any way `/implement`'s ability to proceed. Because the `[DESIGNED]` rename is the admission gate `/implement` reads, performing the rename *before* publish means a later `design-log-publish.sh` failure (or a never-merged logs PR) leaves the issue at `[DESIGNED]` and `/implement` is wholly unaffected. The rename must not be rolled back, re-gated, or reverted on publish failure.
