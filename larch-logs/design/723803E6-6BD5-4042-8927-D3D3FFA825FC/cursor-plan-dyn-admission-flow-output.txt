## Findings

### 1. (correctness) `render-final-summary.sh` cannot read `RENAMED` from result env at render time

The plan tells `append_failed_publish_notes` to qualify `/implement` guidance using `RENAMED` from `.design-publish-result.env` when present (`plan.txt` lines 87–89). In `design-publish.sh`, `render-final-summary.sh` runs **before** `write_result_env_and_emit`:

```319:330:skills/design/scripts/design-publish.sh
SUMMARY_OUTCOME=approved
if [[ -n "$SESSION_ID" ]] && [[ "${PUBLISH_OK:-}" != true ]]; then
    SUMMARY_OUTCOME=failed-publish
fi
export DESIGN_LOG_PR_NUMBER="${PR_NUMBER:-}"
export DESIGN_LOG_PR_URL="${PR_URL:-}"
export DESIGN_LOG_RECOVERY_BRANCH="${RECOVERY_BRANCH:-}"
"${PLUGIN_ROOT}/skills/design/scripts/render-final-summary.sh" \
    --outcome "$SUMMARY_OUTCOME" \
    ...
```

The result env is written only at the end (lines 367–369). Recovery metadata already uses shell exports into `render-final-summary.sh`; `RENAMED` should follow that pattern. After the reorder, `RENAMED` will be set before render, but only an `export` (or a new render flag) makes it visible to `append_failed_publish_notes`.

**Suggested revision:** In the `design-publish.sh` section, require `export RENAMED="${RENAMED:-}"` (and optionally `SCRUB_OK`) immediately before `render-final-summary.sh`. Update `append_failed_publish_notes` / `render-final-summary.md` to read env first; use `.design-publish-result.env` only as a harness fallback.

### 2. (risk-integration) Step 5d footer must be qualified, not only the summary notes

Step 5c item 5 emits `final-summary.md` verbatim before Step 5d (`skills/design/SKILL.md` lines 1525, 1544). The plan’s Step 5d extension (plan.txt lines 76–77) is the right place to fix operator guidance when `PUBLISH_OK=false` but early rename succeeded.

Today’s footer at lines 1550–1552 is unconditional (“log publish incomplete; NEXT REQUIRED: continue”). Without the planned qualification, operators can treat a failed log flush as blocking `/implement` even when `implement-admission.sh` would pass on a live `[DESIGNED]` title (`scripts/implement-admission.sh` lines 239–246).

**Suggested revision:** Keep the Step 5d edit explicit in the plan’s `SKILL.md` section (branch on parsed `RENAMED` / title), not only in `render-final-summary.sh`.
