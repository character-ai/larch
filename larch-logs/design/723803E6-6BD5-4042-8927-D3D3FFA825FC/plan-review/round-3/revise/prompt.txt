## Approach

The change is a reorder plus gate swap: rename moves before full publish and drops the `PUBLISH_OK` gate, but picks up the same fail-closed scrub gate via `--scrub-only` so early admission cannot bypass a scrub refusal. Factor `--scrub-only` from the existing publish staging+scrub block rather than duplicating scrub logic in `design-publish.sh`. The rename block already returns `RENAMED` into the result env via `write_result_env_and_emit`; moving it earlier does not change what it emits, only when it runs and under which conditions. Splitting the old combined block keeps each concern with its own gate: scrub preflight → `SESSION_ID`; rename → `SESSION_ID` + `SCRUB_OK=true`; marker → `SESSION_ID` + `PUBLISH_OK`. The `lib-design-reentry-guard.sh` source stays bundled with the marker because only the marker needs it.

`/implement` is untouched: it admits on the `[DESIGNED]` title, which now appears earlier. No new flags, no new files, no signature changes.

## Edge cases

- **`SESSION_ID` empty** (defensive path; never hit in real runs since Step 0a guarantees a UUID): rename still skipped, because the new block keeps the `SESSION_ID` guard. Marker still skipped. Matches today.
- **Scrub preflight fails closed** (`SCRUB_OK=false`): rename skipped; title stays `[DESIGNING]`; `/implement` blocked until exposure is fixed and `/design` Step 5c retried. Full publish may still run and fail; admission must not be promised in footers.
- **Publish fails after a successful rename**: issue is already `[DESIGNED]` with a `larch:plan` block; `RENAMED=true` in the result env; `SUMMARY_OUTCOME=failed-publish` and the "log publish incomplete" footer still fire. `/implement` can proceed. This is the intended new behavior.
- **Rename fails after successful scrub** (`RENAMED=false`): footers and `append_failed_publish_notes` must **not** claim `/implement` is ready; operators must fix the title first.
- **Operator reads only the Step 5d footer or `failed-publish` summary**: footer and `append_failed_publish_notes` must qualify on `RENAMED=true` / title already `[DESIGNED]` before stating log flush failure does not block `/implement`.
- **Rename fails** (best-effort): warn is emitted and the run continues to publish exactly as before; only the warn text changed.
- **Spurious `/design` re-invocation after a publish failure**: no reentry marker is written (still publish-gated). `design-route.sh` applies lifecycle title-filter **before** the plan-block verdict; an already-`[DESIGNED]` title hits `cancel-title-filter` (not `already-planned`). Recovery is manual title edit (drop the `[DESIGNED]` prefix) or accept that a fresh full `/design` requires a non-lifecycle title — not "re-run already-planned."
