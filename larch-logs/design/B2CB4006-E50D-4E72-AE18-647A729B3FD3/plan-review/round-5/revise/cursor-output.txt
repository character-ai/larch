### Target retirement contract

Retiring a target means **all** of the following:

1. **Delete the entire `test-<name>:` recipe block** from the Makefile (not only `.PHONY` / shard prereq removal).
2. Remove the name from `.PHONY`.
3. Remove the name from every `test-harnesses-N:` prerequisite line.
4. Keep each `test-harnesses-N:` rule on one physical line.
5. Keep aggregate `test-harnesses:` prereqs in parity with declared shard rules.

A target removed from shards but left as a recipe still counts toward partition coverage and can still be invoked directly.

## Edge cases

- `pytest -k` matches module names. Do not use tokens equal to file stems as the sole selector.
- Broad `-k` expressions can overlap. Validate with the guard, not visual inspection.
- Parametrized tests count as multiple node IDs. The guard compares collected node IDs; use its output as source of truth.
- A single full-file target is allowed only when all duplicate full-file targets for that file were retired.
- `test-verify-run-log-completeness` differs by environment; preserve `env -u LARCH_VERIFY_MANIFEST` on its sliced recipe.
- `extract_pytest()` ignores pytest file arguments after `files[0]`; multi-file recipes are unsafe for `ENFORCED` sign-off.
- `test-classify-bump` may keep `python/test_version_bump.py` full-file as the sole harness owner for that module; removing `python/test_release.py` from the recipe is the required fix, not narrowing version_bump coverage.
- `python/test_design_summary.py` has three test families but only two Makefile targets; both targets must remain with disjoint slices, and both must appear in `checks.py` for `design_summary.py` edits.
- The guard ignores files not yet in `ENFORCED`; Bucket-1 validation requires the `ENFORCED` edit before the guard run, not after.
- `test-design-driver` must own four lifecycle tests (not one) because `python/checks.py` routes `plan_quality.py` and `design_lifecycle.py` edits there alongside the separate `test-step0b-router-flag-recovery` target for `design_route`; both modules need **both** targets in `_DIRECT_TARGET_RULES` to preserve former full-file breadth.
- Sliced-in-place targets shrink run-relevant coverage unless `_DIRECT_TARGET_RULES` lists every surviving partition target for that source file.

## Failure modes

- **Hidden fifth payment**: `test-classify-bump` or another target still runs full `python/test_release.py` while `ENFORCED` reports a clean partition for dedicated release targets.
- **Overlap on verify target**: `test-verify-run-log-completeness` stays full-file after siblings are sliced; guard reports overlap and blocks merge.
- **Uncovered capture_transcript**: `test-capture-session-transcript` stays full-file while siblings are sliced; guard reports overlap or the target keeps paying full-file CI runtime.
- **Uncovered verify_main**: `test-release-finish` slices only `release_finish` and omits six `test_verify_main_*` tests; guard blocks merge.
- **Uncovered design_summary families**: retiring or mis-slicing `test-render-final-summary-bash32` leaves `issue_counts` / `plan_review_line` tests uncovered.
- **Zombie recipes**: target removed from shards/`.PHONY` but recipe block remains; guard still counts it or `make <target>` still runs an old full-file selection.
- **`checks.py` breakage**: a `python/checks.py` relevant rule points at a deleted target name.
- **`checks.py` coverage shrink**: sliced targets run fewer node IDs but `_DIRECT_TARGET_RULES` still lists only the old single full-file target; `/implement` run-relevant misses `design_route`, `issue_counts`, `plan_review_line`, or panel-dispatch tests.
- **`plan_quality` `design_route` gap**: `test-design-driver` partitioned but the `plan_quality.py` rule still lists only `test-design-driver`; `plan_quality.py` edits no longer run `test_design_route_merges_flags_for_already_planned`.
- **Mislabeled lifecycle slices**: `-k reentry` or `-k step0b` on `python/test_design_lifecycle.py` leaves tests uncovered or fails the guard.
- **`plan_quality` coverage shrink**: `test-design-driver` narrowed to `-k design_driver` drops four lifecycle tests from `/implement` relevant-checks for `plan_quality.py` edits.
- **Uncovered phase_driver after retirement**: `test-lib-phase-driver` retired without assigning its two `phase_driver` tests to `test-design-driver`; guard reports uncovered node IDs.
- **Premature guard green**: running the guard before the nine paths are in `ENFORCED` validates only the prior 15-file list and misses Bucket-1 regressions.
- **Version-bump coverage regression**: narrowing `test-classify-bump` to `-k classify` drops non-classify `python/test_version_bump.py` tests from `make lint` harness coverage.
- **Shard coverage drift**: `.PHONY` or `test-harnesses-N` membership not updated after retirement.
- **Lost rebalance follow-up**: PR merges without a tracked issue; deferred `/rebalance-tests --kind harness` work is never scheduled.
- **Temporary shard imbalance**: accepted in this PR; handled by the tracked post-merge rebalance issue.
