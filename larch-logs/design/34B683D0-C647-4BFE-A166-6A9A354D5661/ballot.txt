### FINDING_1:
- **Reviewer(s)**: Cursor-Arch Phase2
- **Severity**: important
- **Focus area**: architecture
- **Location**: python/logging_util.py:55-100; python/plan_review.py:206-239; python/clarify.py:836-865; python/design_summary.py:210-249
- **Concern**: Planned in-process callers would call CLI-style mains without isolating quiet_init fd side effects. Scenario: logging_util.quiet_init duplicates and redirects process file descriptors. A contextlib or proc-style stdout capture around stage_terminal_state_main or failure_report_main can miss KV output because emit_kv writes via fd 3, and the caller process can keep stdout and stderr redirected after the imported call. This regresses the existing subprocess log contracts such as step3-stage-terminal-state.stdout.log, design-clarify-stage.stdout.log, and design-failure-report.stdout.log.
- **Proposed resolution**: Split pure implementation helpers from CLI entrypoints. Run quiet_init only in the direct CLI path after tmpdir validation. Have Python callers invoke pure helpers with explicit stdout/stderr or artifact paths, or use a fd-level capture-and-restore wrapper that proves parent stdout and stderr remain unchanged.
