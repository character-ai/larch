## Approach

1. Add `python3 python/cli.py bgjob {start,wait,status,reap}` as the new long-running job transport.
   - `start` double-forks, calls `setsid`, redirects daemon stdout/stderr to log files, writes an identity-checked registry entry, and prints only `BGJOB_STATUS=STARTED STEP=<name> PGID=<n>`.
   - The daemon writes `$TMPDIR/bgjob/<step>.result.env` atomically with `BGJOB_RC`, `BGJOB_ELAPSED_S`, and the step's existing result KVs.
   - The daemon also writes each step's existing terminal sentinel before result completion routing changes.
   - Budget expiry kills the process group and writes `BGJOB_RC=timeout`.
   - Owner death kills the process group after grace and writes `BGJOB_RC=orphaned`.
   - `wait` polls result files in 1 to 2 second intervals, emits `DONE`, `WAIT`, or `DEAD`, and uses `SIGALRM` at `--max-wait-s + 30`.
   - `status` reports live registry entries and identity verdicts.
   - `reap` cleans identity-verified stale jobs without killing recycled PIDs.

2. Use existing process identity helpers instead of bare PIDs.
   - Extend or wrap `larch.core.process_identity` for PID, PGID, start time, and command signature checks.
   - Use `larch.io.atomic_write`, `read_kvs`, and `format_kvs` for registry and result envs.
   - Define shared wire literals and timeouts in `larch.core.config`.

3. Replace prompt-side immediate-background instructions with a single foreground wait contract.
   - Add `skills/shared/bgjob-wait.md`.
   - Each migrated site launches the step with `bgjob start`, then loops `bgjob wait --max-wait-s 270` with tool timeout `330000`.
   - On `WAIT`, the next action is another `bgjob wait`, with no prose, `Read`, `TaskOutput`, `Monitor`, or sleep.
   - On `DONE`, parse the result KVs and continue existing branch handling.
   - On `DEAD`, route through the step's existing failure or stall path.

4. Migrate call sites in small mechanical passes.
   - Keep wrapper names when they are part of the skill surface.
   - Convert wrapper bodies to rehydrate, arm preconditions, and delegate real work to `bgjob start`.
   - Move banners and breadcrumbs to orchestrator prose or daemon logs.
   - Ensure harness-visible wrapper stdout is exactly the `BGJOB_STATUS=STARTED` line.
   - Fold Step 3 and Step 5 detach/reattach loop identity into bgjob registry ownership rather than retaining a second daemon model.

5. Add regression enforcement.
   - Add a PreToolUse hook that denies Bash tool input containing `run_in_background: true` while a larch run is active in the same clone.
   - Repurpose `lint bg-wait-coverage` into an inverse lint that rejects `run_in_background` in `skills/` unless listed in a reason-bearing allowlist.
   - Keep old bg-wait hooks and docs functional, but inert when no call sites use `run_in_background`.

6. Update operator docs only after migration wiring is complete.
   - Document `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` as optional for dedicated runner sessions.
   - State that it disables background subagents and Ctrl+B.

## Edge cases

- Recycled PID or PGID must never be killed. Treat identity mismatch as stale and report it.
- Daemon leader exits before children. Reap must validate process-group members before signaling.
- Result file appears while registry entry still exists. Prefer result `DONE`, then clean registry.
- Registry entry exists but daemon is gone and result is absent. Return `DEAD` within one poll interval.
- Owner PID is reused. Owner identity must include start time, not PID only.
- `bgjob wait` receives a too-large `--max-wait-s`. Clamp or reject so tool auto-background cannot happen.
- A result env value contains newline or carriage return. Reject or escape before writing.
- `CLAUDE_PLUGIN_ROOT`, `DESIGN_TMPDIR`, `IMPLEMENT_TMPDIR`, or `RESEARCH_TMPDIR` is missing. Fail with `BGJOB_ERROR` or the existing step error path, not a silent wait.
- Legacy hooks may see stale `.bg-wait-active` from an interrupted old run. New bgjob hooks must not depend on that marker.
- Research has parallel external lanes. Start each lane separately, then wait each launched bgjob without using TaskOutput or Monitor.
- Step 8 must preserve handoff rc/json so existing route-exit logic still works.

## Failure modes when non-trivial

- A daemon writes partial result env. Use temp file plus atomic rename and parse only regular non-symlink files.
- A `WAIT` loop emits prose or uses another tool between waits. The shared prompt and tests must pin this.
- A migrated wrapper leaks banner text before `BGJOB_STATUS=STARTED`. Harness must assert exact stdout.
- The new hook blocks unrelated clones. Use clone identity from cwd and keepalive/session data; fail open when identity cannot be proven.
- The inverse lint blocks retained issue-2 docs. Use a reason-bearing allowlist.
- Step 5 detach/reattach removal loses resume behavior. Pin owner-death, orphaned, and re-entry tests before deleting bespoke sidecars.
- Ship-pr route-exit misses handoff files. Keep `.step-8-ship-handoff.rc` and `.json` as compatibility sidecars.
