## Edge cases

- Lifecycle constants include trailing spaces. The lint should detect literals with or without that trailing space.
- Case variants should match, including `[Bug]`.
- Tuple, list, and set operands to `in` and `not in` can contain both valid constants and bad literals.
- Chained comparisons can hide literals in non-obvious comparator positions.
- Regex strings can contain escaped brackets. For this lint, simple normalization that recognizes escaped bracket forms is enough.
- Docstrings are AST string literals. Skip them explicitly.
- Inline suppression should suppress only the finding on that line or the immediately following line for standalone comments.
- Occurrence numbers should remain stable when a prior finding is suppressed.

## Failure modes

- Importing the wrong bug-prefix source can create an import cycle. Keep the import to `larch.issue.title_match.BUG_PREFIX`, which already depends only on `larch.core.config`.
- Over-scanning display strings can make the baseline noisy. Limit findings to the named AST contexts.
- Hardcoding token text would recreate the drift this lint prevents. Build the token map from constants only.
- A baseline identity that includes line numbers would churn on unrelated edits. Exclude line numbers from identity.
- If the shared normalizer moves after this lands, update only the allowlist and import source in this lint.

# [FEATURE] Add lint_lifecycle_prefix_literal (title-prefix constants)

Source: `/larch:learn-from-bugs -n 25` run, 2026-07-08. Report section 4, rule L2.

#### Problem

#6604: `/analyze-bugs` selected bug titles with a hand-written, case-sensitive `[BUG]` prefix test while the retitle convention had grown lifecycle prefixes (`[DONE] `, `[DESIGNED] `, `[IMPLEMENTING] `, `[STALLED] `, defined in `config.TRACKING_ISSUE_PREFIX_BY_STATE` in `python/larch/core/config.py`) and case variants such as `[Bug]`. The audit silently skipped most of its population. The fix introduced a normalizer, but nothing stops the next selector from re-deriving these tokens by hand.

#### Rule

Flag lifecycle and bug title-prefix string literals used in comparison or match positions in `python/larch` non-test sources.

- Token set: build at lint runtime from `config.TRACKING_ISSUE_PREFIX_BY_STATE.values()` plus the bug-title prefix constant (`BUG_PREFIX`, currently in `python/larch/issue/analyze_bugs.py`; the learn-from-bugs over-selection issue filed in this same batch hoists it into a shared module). Match tokens with trailing spaces stripped and case-insensitively, so `[DONE]`, `[done] `, and `[Bug]` all count. Do not hardcode the token list inside the lint; build it from the existing constants (G-Cfg-1).
- Comparison and match positions: operands of `==`, `!=`, and `in`; arguments to `.startswith`, `.endswith`, `.removeprefix`, and `.lstrip`; string-literal patterns passed to `re.compile`, `re.search`, `re.match`, or `re.fullmatch` whose pattern contains one of the tokens.
- Allowlist: `python/larch/core/config.py` (the definitions), the shared normalizer module produced by the hoist, and all test files.
- Not flagged: literals in display strings, f-string display output, log messages, docstrings, and comments. Only comparison and match positions count.

The report line must name the file, line, matched token, and the constant the code should consume instead.

#### Suppression and baseline

- Inline suppression: `# lint-lifecycle-prefix: ok &lt;reason&gt;`.
- Shrinking reason-bearing baseline per G-Enf-2, seeded from the initial scan; regen target `regen-lifecycle-prefix-literal-baseline`.

#### Wiring

Same conventions as sibling lints: module `python/larch/lint/lint_lifecycle_prefix_literal.py` with module-level `main(argv) -&gt; int` (G-CLI-1); registry entry `("lint", "lifecycle-prefix-literal")` in `python/larch/cli.py`; a `$(PYTHON) python/cli.py lint lifecycle-prefix-literal` line in the `py-lint-checks-fast` recipe plus the regen baseline target and `.PHONY` entry; tests at `python/tests/lint/test_lint_lifecycle_prefix_literal.py` (flag a `.startswith("[DONE]")` fixture; do not flag the config.py definitions, display f-strings, or suppressed lines; baseline honored).

#### Sequencing

This lint references the shared normalizer module created by the learn-from-bugs over-selection issue filed in this same batch. If this lint lands first, allowlist `python/larch/issue/analyze_bugs.py` temporarily and move that allowlist entry to the shared module when the hoist lands.
