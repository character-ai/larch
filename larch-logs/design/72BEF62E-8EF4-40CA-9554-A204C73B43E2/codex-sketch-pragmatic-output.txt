**Approach**

Use `plan-review-loop.sh` as a thin single-pass coordinator, not a new review framework. It should wrap the current full-budget Step 3 mechanics in the same order: scout archetypes, dispatch panel, collect reviewer outputs, aggregate/fallback, write `ballot.txt`, call `dispatch-plan-voters.sh`, then call existing `tally-plan-review.sh` or `design-driver.sh ACTION=TALLY`. Keep quick/trivial entirely in `SKILL.md`: `review_budget=quick` continues to load `plan-review-quick.md`; only `review_budget=full` invokes the new script. I would avoid importing `review-core.sh` wholesale because it is code-review-shaped and adds unrelated round/log/convergence behavior. The new script should accept `--round-num N` with default `1`, emit `LOOP_STATUS`, `ACCEPTED_COUNT`, `DEGRADED_PANEL`, and `ROUNDS_COMPLETED=$round_num`, and write only the existing session-root artifacts.

**Risks**

The biggest behavior risk is aggregator absorption. Calling `skills/review/scripts/aggregate-findings.sh` is not “no behavior change” in a strict sense: it can merge, renumber, or reshape ballot rows, and its current validation expects code-review-style structure such as severity lines. That risk is worth accepting only if the issue defines “no behavior change” as preserving the final artifact names/semantics, not byte-identical ballots. The clear acceptance test should be: run `plan-review-loop.sh` with stubbed panel outputs and a pass-through aggregator, then byte-compare the six session-root artifacts against a fixture produced by the old flow; separately test aggregator failure/non-substantive output falls back to the unaggregated ballot and still produces the same artifact set. Add one duplicate-finding fixture to prove aggregation changes only dedup shape, not accepted/rejected/OOS classification.

For Bash 3.2, do not inherit Bash 4-only conveniences. `review-core.sh` mostly uses portable indexed arrays and process substitution, but the new script must avoid associative arrays, namerefs, `mapfile/readarray`, `${var^^}`/`${var,,}`, `&>>`, and `coproc`. Use newline temp files plus `while IFS= read -r`, `awk` KV parsing, and indexed arrays only. The 0-judge fallback is another risk: once Voter 1 moves into `dispatch-plan-voters.sh`, `plan-review-loop.sh` should consume `VOTER_PATHS_FILE` or explicit status KVs and call `tally-plan-review.sh` with only non-failed voter files; if none exist, preserve the existing `main-agent-vote-required` path without hand-writing artifacts.
