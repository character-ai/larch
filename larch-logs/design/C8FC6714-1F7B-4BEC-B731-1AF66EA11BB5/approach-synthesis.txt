## Approach Synthesis

**Convergence**: Both sketches (Cursor-Generic, Codex-Generic) converge on Option A from the issue — the caller-contract fix. Capture the backgrounded Family B writer's PID with `family_b_pid=$!` immediately after `&`, run `breadcrumb-monitor.sh` in the foreground (preserving live streaming), then `wait "$family_b_pid" 2>/dev/null || true` before the wrapper Bash script exits. The monitor still exits early when the done sentinel fires; the `wait` couples the parent shell to the real child exit, so the orchestrator's task-notification only arrives after the Family B writer has truly terminated.

**Why caller-contract, not monitor-side**: Modifying `breadcrumb-monitor.sh` to do the wait internally would require the monitor to know the writer's PID, which would mean either (a) reading `LARCH_PAIRED_PID_FILE` (which `breadcrumb-monitor.sh` already does but only on timeout, to signal the writer) and adding a `wait` post-loop — but the monitor is invoked in a different subshell than the wrapper that spawned the writer, so it can't `wait` for a PID that isn't its child — or (b) having the writer self-monitor, losing the foreground breadcrumb stream. Both sketches reject these in favor of keeping the change at the caller boundary. Option C from the issue (exec replacement) is also rejected because it would lose live breadcrumb streaming.

**Scope (top-level Family B writers, per AGENTS.md)**: AGENTS.md lists 5 top-level Family B writers that own `LARCH_PAIRED_PID_FILE`. All 5 exist in the tree (one is at a sub-path under `skills/`):
- `scripts/ship-pr.sh`
- `scripts/run-step5-review.sh`
- `scripts/collect-agent-results.sh`
- `scripts/dispatch-plan-voters.sh`
- `skills/implement/scripts/run-step2-dispatch.sh`

`lint-foreground-markers.sh` already treats all 5 as `family_b_pid_writer_required` (line 44). The fix applies to all 5.

**Files to modify**:
- `BASH_AUTHORING.md` §4 — add the `wait $!` discipline as normative prose for the background+monitor pair; document the PID-capture-then-wait pattern with a minimal example.
- All SKILL.md and references/*.md fenced bash blocks that invoke a Family B top-level writer in the background+monitor pair — sweep all matches and add the `family_b_pid=$!` capture + `wait` line.
- `scripts/lint-foreground-markers.sh` — extend the per-anchor checks so each Family B top-level writer anchor in a fence requires (a) PID capture via `<var>=$!` on the same fenced line OR within the next 3 lines, and (b) a later `wait "$<var>"` invocation in the same fence, **after** the `breadcrumb-monitor.sh` call. Mirror the existing `family_b_pid_writer_required` gating so nested-only children are not constrained.
- `scripts/test-lint-foreground-markers.sh` — add positive (passing) and negative (missing-wait → violation) fixtures for the new invariant.
- New harness `scripts/test-background-monitor-wait.sh` (+ sibling `.md`) — a focused offline test that simulates the orphan scenario: spawn a slow background process, run a fast fake-monitor that exits early (writes done sentinel), and verify the parent wrapper shell does not exit until the slow process truly terminates. Must be Bash 3.2-portable (per `.claude/rules/shell-strict-mode.md` + BASH_AUTHORING.md §3) and registered via the Makefile so `make lint` picks it up.

**Tradeoffs and risks**:
- **Verbosity**: SKILL.md fences become a few lines longer (PID-capture and wait). Mitigated by the lint rule that ensures consistency.
- **Linter false positives**: PID-variable detection needs to be lenient enough to allow stylistic variation (`family_b_pid`, `ship_pr_pid`, `_pid`) but strict enough to catch missing waits. Use a regex that matches `^[A-Za-z_][A-Za-z0-9_]*=\$!` anywhere within the fence after the anchor, paired with `wait\s+"?\$(?:[A-Za-z_][A-Za-z0-9_]*|\{[A-Za-z_][A-Za-z0-9_]*\})` later in the same fence.
- **Wait can hang**: if a Family B writer enters an unbounded loop, `wait` blocks indefinitely. The monitor's `--paired-pid-file` already enforces a 1800-second hard timeout (signals SIGTERM then SIGKILL on the writer); after that, the writer exits and `wait` returns. No additional timeout needed in the wrapper.
- **Wait return code**: `wait "$pid" 2>/dev/null || true` discards the writer's exit code at the wrapper boundary. This is intentional — the wrapper communicates status via `LARCH_STATUS_FILE`, not via wrapper exit code. Existing orchestrator code already reads `STATUS_FILE`.
- **Non–Family B background launches** (sketch launch wrappers, plan-review launchers) are unchanged. Out of scope.

**Failure modes preserved by this approach**:
- Single-runner invariant: `LARCH_PAIRED_PID_FILE` + `kill -0` checks on re-invocation are unaffected.
- Live breadcrumb streaming: monitor runs in foreground; stdout is captured by the Bash tool wrapper as before.
- Bash 3.2 portability: `wait "$pid"` and `pid=$!` are POSIX-compatible.
