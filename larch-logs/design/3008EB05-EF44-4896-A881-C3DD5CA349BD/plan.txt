## Approach

The issue asks for structural-test coverage of two literal anchors that are currently emitted by `emit-design-plan-preview.sh` (lines 103 / 116) but documented in `SKILL.md` Step 3 prose and `approval-gates.md` Gate C prose. The user picked **section-scoped** granularity (Step 1c clarification), so use the existing two-step pattern already used by `FINDING_21` for Step 2b: (a) extract the section block with `awk` keyed on the literal `<!-- step:N -->` / `## Gate X` boundary markers, (b) `grep -Fq` for the literal header inside the captured block. This guarantees that moving the header text out of Step 3 / Gate C — even into adjacent prose — fails the assertion.

Numbering: continue the natural sequence (`Check 18`) rather than minting a new `FINDING_N` because issue #2702 is itself an OOS spin-off, not a vote-accepted finding from a /design run. This matches Checks 1–17.

## Edge cases

- **Step boundary regex precision**: `^<!-- step:3 ` (note trailing space) deliberately excludes `<!-- step:3.5 ` because Step 3.5's marker is `<!-- step:3.5 — Post-Review Chooser (Gate B) -->`. The awk range terminator `^<!-- step:3.5 ` is also literally distinct from `^<!-- step:3 `, so the captured block is exactly Step 3.
- **Gate C terminator**: `^## State invariants` (the next top-level heading after Gate C in `approval-gates.md`) bounds the captured block. If a future commit renames that section, the range becomes open-ended (matches to EOF); the assertion still passes when the Gate C anchor is present, and fails the same way when it isn't.
- **Section moved/renamed**: if either header is moved out of its respective block (or removed), the assertion fails — which is the intended structural protection.
- **Block not found** (e.g., `<!-- step:3 ` marker is also deleted): the `awk` range captures nothing and the `grep -Fq` fails as a single combined failure, with the `(18)` prefix in the fail message pointing the operator to the right check.

## Failure modes

1. **Awk range mis-extraction** if the marker tokens drift. Earliest signal: `make lint` regression fails on the existing FINDING_21 Step 2b extraction too, since it uses the same anchor convention. Mitigation: reuse the FINDING_21 pattern verbatim rather than inventing a new one.
2. **Block-level false negative if Gate C section is renamed**. Earliest signal: the new Check 18 fails immediately on a structural rename. Mitigation: failure message says `Gate C block missing '## Final Design Plan'` so the operator sees exactly which header / file is in question.
3. **Sibling `.md` drift**. Earliest signal: existing `.claude/rules/script-md-siblings.md` enforcement notices the doc was edited without the script (or vice-versa) on the next `make lint` pass. Mitigation: update both files in the same commit.
