# Approach Synthesis — `--brainstorm` flag for /design

## Decision summary

Add a new public boolean flag `--brainstorm` to `/design`. When set, run a new step (Step 1d.5, between Round 1 discussion and Gate A) that dispatches a 3-agent ideation panel (Cursor + Codex + Claude) writing brainstorm.md, then enters a free-form discussion loop with the user before continuing to Gate A. Existing tier flows are byte-identical when the flag is OFF.

## How the 3-agent panel runs

Mirror the Step 2a sketch parallel-launch pattern exactly:

- **Cursor — Brainstorm** (if `cursor_available`): `launch-review.sh --tool cursor --output "$DESIGN_TMPDIR/cursor-brainstorm-output.txt" --timeout 1200 --timing-task-kind cursor-brainstorm --prompt-file "$DESIGN_TMPDIR/brainstorm-prompt-cursor.txt"`. Run via Bash tool with `run_in_background: true`, `timeout: 1260000`.
- **Codex — Brainstorm** (if `codex_available`): same shape with `--tool codex`, `cursor-brainstorm` → `codex-brainstorm`.
- **Claude — Brainstorm (always)**: Agent tool with `general-purpose` subagent; prompt is `<BRAINSTORM_PRAGMATIC_PROMPT>` (default Claude slot role); subagent writes its output to `$DESIGN_TMPDIR/claude-brainstorm-output.txt`. Run with `run_in_background: true`.
- **Fallback for Cursor when `cursor_available=false`**: Claude Agent-tool subagent with `<BRAINSTORM_FRAMING_PROMPT>` (Cursor's role).
- **Fallback for Codex when `codex_available=false`**: Claude Agent-tool subagent with `<BRAINSTORM_SCOPE_PROMPT>` (Codex's role).
- **All-Claude path (both externals unavailable)**: 3 Claude Agent-tool subagents in parallel, each with one of the three distinct prompts. Diversity preserved.

Issue all launches in a single message for parallel execution. Collection: `scripts/collect-agent-results.sh --timeout 1260` for any external slots actually launched; omit slot paths replaced by Agent-tool fallbacks (Agent return text is captured directly by the parent session; the orchestrator writes it to the corresponding `*-brainstorm-output.txt` for uniform downstream reading). Preserve anti-pattern #4: never call `collect-agent-results.sh` with zero entries — when ALL three slots are Agent-tool (all-Claude path), do not call the collector at all.

## Free-form discussion loop

Mechanics:

1. Main agent reads the three brainstorm outputs.
2. Main agent synthesizes, deduplicates, and orders the ideas into `$DESIGN_TMPDIR/brainstorm.md` using the schema:
   ```markdown
   ## Brainstorm Synthesis

   ### Idea 1: <short title>
   - **Source**: Cursor | Codex | Claude-Framing | Claude-Scope | Claude-Pragmatic (or Claude-Fallback-{role} for fallback slots)
   - **Summary**: <1-3 sentences>
   - **Rationale**: <why it's worth considering>
   ```
3. Main agent prints the synthesis under the same `## Brainstorm Synthesis` header in chat.
4. Main agent ends its turn (this is an explicit non-sequential control-flow directive that overrides the global anti-halt continuation rule for the brainstorm loop only; precedent: Gate A's "Show latest design proposal" branch already yields turns).
5. User replies in free-form chat — reactions, additions, overrides of ordering, requests to drop ideas, etc.
6. Main agent reads the user's message, mutates `brainstorm.md` via the Write tool, re-prints the updated synthesis, ends turn again.
7. Loop repeats until the user signals termination. Recognized vocabulary (guidance, not strict): `ready`, `ready to proceed`, `proceed`, `looks good`, `next`, `go to sketches`, `/ready`, or similar. Main agent uses semantic understanding to detect termination intent.
8. On termination: write `$DESIGN_TMPDIR/.brainstorm-done` (zero-byte marker), continue to Step 1e Gate A.

## Sentinel placement

`$DESIGN_TMPDIR/.brainstorm-done` is created by the brainstorm loop on termination. Checked at:
- Step 1d.5 entry: if `brainstorm_requested=true` AND sentinel exists, skip (already done in this invocation).
- Gate A "Discuss more" re-entry: ignored (Discuss more re-enters Step 1c/1d only, not 1d.5).
- Gate B(c) and Gate C(b) post-plan re-entries to Gate A: ignored for the same reason.
- Already-planned router's "replace via full flow" and "ad-hoc Q&A" branches: new invocation = fresh `$DESIGN_TMPDIR` = sentinel naturally absent on first entry; this matches user decision #6 (brainstorm fires unconditionally when --brainstorm is on argv, on both replace and ad-hoc Q&A paths within the same invocation but only ONCE per invocation).

## Anti-halt override

Add a single bold-italic sentence at the top of brainstorm.md prose:

> **The brainstorm free-form discussion loop is an explicit non-sequential control-flow directive that overrides the global anti-halt continuation reminder in SKILL.md for the duration of the loop. After each `## Brainstorm Synthesis` print, end the turn and await the user's next free-text message. The override lifts the moment the user signals termination and `$DESIGN_TMPDIR/.brainstorm-done` is written.**

Cite this override in the SKILL.md Step 1d.5 section's MANDATORY pointer line so reviewers reading SKILL.md don't miss the override.

## Backward-compat

When `--brainstorm` is NOT on argv:
- `brainstorm_requested=false` is persisted in `run-params.json` (new schema-additive field).
- Step 1d.5 is silently skipped (`⏩ 1d.5: brainstorm — skipped (--brainstorm not set)` breadcrumb).
- Existing test fixtures need no edits (additive JSON field is ignored by readers via named-field selection in `jq` / Python).
- No `brainstorm.md` file is created; downstream `if exists` reads remain no-ops.

## Failure modes and mitigations

- **External timeout**: collect-agent-results.sh returns STATUS!=OK for the failed external. Orchestrator skips that slot's content but proceeds with whatever other slots produced output. brainstorm.md is still written.
- **Both externals timeout in single-external-degraded launch**: 2 of 3 slots fail. Orchestrator writes a partial brainstorm.md with whatever Claude slot returned. Warning logged.
- **All-Claude failure (rare)**: brainstorm.md is empty/missing. Print warning, skip discussion loop, write sentinel anyway, proceed to Gate A. Downstream readers' "if exists and non-empty" guards prevent breakage.
- **User says "cancel" in discussion loop**: not currently a defined exit; if needed, surface a Gate-A-like prompt at the start of the discussion loop ("Continue to discussion / Cancel /design") — but this is an enhancement beyond user's spec. Defer.
