### DECISION_1: Step position relative to Gate A
- **Chosen**: Step 1d.5 — insert AFTER Step 1d (Round 1 discussion) and BEFORE Step 1e Gate A. Brainstorm output becomes part of the context Gate A's "Ready for review" / "Discuss more" approval considers. The user's `Discuss more` re-entry naturally lets them open another sub-round if brainstorm raised new scope questions before approving readiness.
- **Alternative**: Step 1f — insert AFTER Step 1e Gate A's first-time "Ready" exit and BEFORE Step 2a. Brainstorm fires only after the user has approved leaving the clarification phase. Gate A is treated as the canonical "done with clarification" gate; brainstorm is post-approval ideation that the user has explicitly opted in to by saying "Ready for review".
- **Tension**: Both interpretations satisfy the user's natural-language spec ("after all clarifying questions, before any design proposals"). Codex (sketch source 1) advocates 1d.5; Cursor (sketch source 2) advocates 1f. The semantic question is whether Gate A is "asking clarifying questions" (it isn't — it's an approval gate with a Discuss-more option) and whether the user wants brainstorm output to BE part of Gate A's context (Codex) or to fire only AFTER the user has dismissed Gate A's clarification loop (Cursor). The interaction with the global anti-halt continuation rule is the same in both placements (a turn-yielding free-form loop). The re-entry semantics differ: with 1d.5, the user discovering issues in brainstorm can re-enter 1c/1d via Gate A's Discuss-more; with 1f, the user has no clean re-entry path because Gate A has already been approved and Gate A's Discuss-more re-entry is post-plan (re-entered from Gate B/C, with Shape 2 prompt) rather than pre-plan. With 1f, brainstorm-raised scope questions would have to wait for Gate B/C re-entry — a strictly worse UX, unless we argue Gate A approval implies "no more scope questions" and brainstorm is purely about ideation framings (not scope).
