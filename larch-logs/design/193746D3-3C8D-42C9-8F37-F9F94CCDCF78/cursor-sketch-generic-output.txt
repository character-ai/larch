(a) Key architectural decisions and approach

The `--brainstorm` flag is best treated as an additive modifier that materializes a brand-new Step 1f sandwiched between Step 1e Gate A and Step 2a — explicitly, Gate A still fires after Step 1d as today, the user picks "Ready for review", and *only then* does Step 1f run. This keeps `--brainstorm` invisible to every existing tier flow when the flag is absent (a single `BRAINSTORM_REQUESTED=true` guard around the entire Step 1f block makes the OFF path byte-equivalent), preserves Gate A's `discussion-round1.md` as a strictly scope/requirements artifact that brainstorm can consume, and satisfies decision #2 ("after 1c/1d, before Gate A approval considers brainstorm") if we interpret "before Gate A approval" as *before any post-brainstorm re-prompt* — Gate A's "Discuss more" re-entry semantics already provide that naturally: after Step 1f writes `brainstorm.md` and updates the synthesis, Gate A is re-fired (Shape 1) so the user can pick "Discuss more" (loop back into 1c-style discussion + brainstorm context) or "Ready for review" (proceed to Step 2a). The brainstorm step body itself lives in a new `skills/design/references/brainstorm.md` (loaded via a `MANDATORY — READ ENTIRE FILE` directive in SKILL.md Step 1f, mirroring the discussion-rounds.md / approval-gates.md pattern), with prompt placeholder tokens (`<BRAINSTORM_GENERIC_PROMPT>`, `<BRAINSTORM_CONTRARIAN_PROMPT>`, `<BRAINSTORM_PRAGMATIC_PROMPT>`, `<BRAINSTORM_EXPLORER_PROMPT>`) substituted by a new lightweight `skills/design/references/brainstorm-prompts.md` companion — exactly parallel to the sketch-launch.md / sketch-prompts.md pair so contributors recognize the convention. The 3-agent panel dispatches via the existing `scripts/launch-review.sh --tool {cursor,codex}` wrappers in parallel exactly like Step 2a.2 (single-message launch, `run_in_background: true`, `timeout: 1260000`), then collected through `scripts/collect-agent-results.sh --timeout 1260` — no dedicated launcher is needed; the panel shape is just Cursor-Brainstorm + Codex-Brainstorm + Claude-Brainstorm-Generic (the third slot is *always* a Claude subagent via the Agent tool, not an external, which is why issue #98's attribution-leak concern does not apply here — brainstorm is collaborative ideation, not adversarial debate, and the user explicitly designed in a Claude slot from the start). When Cursor or Codex falls back to Claude, the assigned slot uses the same `<BRAINSTORM_*_PROMPT>` body via Agent tool (one prompt per slot); when **both** externals are unavailable, all three Claude subagents launch in parallel with **distinct** prompts drawn from the four-prompt menu (contrarian / pragmatic / explorer — picking three by deterministic priority order, with the always-Claude slot keeping `<BRAINSTORM_GENERIC_PROMPT>`) so diversity survives the zero-externals path. Synthesis is main-agent inline (read the three output files, dedupe, sort by main-agent judgment) and writes `$DESIGN_TMPDIR/brainstorm.md` to a stable schema (`## Brainstorm Synthesis` + numbered idea blocks with `**Source**: Cursor|Codex|Claude-Generic|Claude-Contrarian|...`). The open free-form discussion loop is mechanically structured as: main agent prints the synthesis under `## Brainstorm Synthesis` → ends its turn (Claude's natural turn boundary is the user's free-text prompt cue — this is *not* a halt, it's the conversational handoff that `AskUserQuestion` would normally fake) → user reacts in free-form chat → main agent reads the user's message, mutates `brainstorm.md` with a Write tool call, re-prints the synthesis → ends turn again. Termination is signaled by the user typing one of a recognized vocabulary ("ready", "ready to proceed", "proceed", "looks good", "next", "go to sketches", "/ready", or similar — documented in brainstorm.md prose as guidance, but the main agent uses semantic understanding to detect it). Once detected, the orchestrator writes the one-shot sentinel `$DESIGN_TMPDIR/.brainstorm-done` (a zero-byte marker, checked by Gate B / Gate C / re-entries via `[ -f "$DESIGN_TMPDIR/.brainstorm-done" ]`) and continues to Gate A. The free-form loop is the **only** intentional turn-yielding boundary in `/design` outside `AskUserQuestion`; SKILL.md prose must mark Step 1f's per-iteration synthesis-print as an explicit allowed pause (modeled exactly on the "Show latest design proposal" branch in Gate A, which already yields a turn and re-fires).

(c) Main tradeoffs and risks

Backward-compat byte-identity is delivered by gating *all* new behavior on `BRAINSTORM_REQUESTED=true` — Step 1f executes nothing when the flag is OFF (not even a skip breadcrumb, to avoid altering the existing breadcrumb stream that downstream audit tooling like `audit-runs` keys on); the only OFF-path side effect is the new `brainstorm_requested: false` field in `run-params.json`, which is a schema additive change that existing readers (`check-plan-size.sh`, `read-design-review-budget.sh`, Step 2b.5's `partition_requested` reader) ignore because they each select named fields. The `--trivial` + `--brainstorm` interactive collision is the trickiest piece because Pre-Step-0's shell block today *prints + exits 1* for `--trivial` + `--partition` — adding an `AskUserQuestion` there is impossible since shell scripts can't fire prompts and the existing collision code intentionally runs *before* Step 0a creates `$DESIGN_TMPDIR`. The clean resolution: move the `--brainstorm`-specific collision check *out of* the shell Pre-Step-0 gate and into prompt-side prose at the top of Pre-Step-0 (a small `AskUserQuestion` block in SKILL.md that fires when the orchestrator detects both flags during its initial argv scan, exactly the same scan that already exists for the partition collision — the orchestrator already reads `$ARGUMENTS` once before the Pre-Step-0 shell block per the "scan the start of `$ARGUMENTS` for tier flags" instruction). This keeps the existing `--trivial` + `--partition` non-interactive hard-error path untouched (no shell change at all to that branch) and adds a parallel prose-side branch for the new interactive collision. On "Upgrade to --simple" the orchestrator sets the in-memory tier flag without rewriting argv (so downstream "Step 0b parses argv" reads `--simple` from the orchestrator's mental state, not from `$ARGUMENTS`); on "Cancel" no `session-setup.sh` runs, no `DESIGN_TMPDIR` is created, just like the existing collision. The open free-form discussion loop is the highest-risk interaction with the anti-halt continuation rule: SKILL.md's global "do NOT halt on user-visible output" reminder explicitly forbids ending a turn on a deliverable-looking output, yet the brainstorm loop *needs* to yield turns to receive free-text user input. The mitigation is precedent-following: Gate A's "Show latest design proposal" branch already prints `## Latest Design Plan`, ends its turn, and waits for an `AskUserQuestion` answer — and the anti-halt rule is explicitly subordinate to "explicit non-sequential control-flow directives in THIS file" (per the SKILL.md anti-halt paragraph, which whitelists Gate A re-entry transitions). Step 1f must therefore include a *named, explicit* turn-yield directive in brainstorm.md prose ("after printing the updated `## Brainstorm Synthesis`, end the turn and await the user's next free-text message — this is an explicit non-sequential control-flow directive that overrides the anti-halt continuation reminder for the duration of the brainstorm loop only; the override lifts the moment the user signals termination and `.brainstorm-done` is written"), and the SKILL.md Step 1f section must cite this override in the same sentence that loads brainstorm.md (so reviewers reading SKILL.md don't think the override is hidden). The downstream-consumer risk is contained: Step 2a/2a.5/2b currently read `approach-synthesis.txt`, `discussion-round1.md`, `dialectic-resolutions.md` (and `contested-decisions.md` for 2a.5), and brainstorm.md becomes a strictly *additive* input — never load-bearing, never mutating existing artifact schemas, never required — so existing offline harnesses (`test-emit-design-plan-preview.sh`, `test-tally-plan-review.sh`, `test-validate-plan-commands.sh`, `test-render-final-summary.sh`) need no edits because their fixtures don't include `brainstorm.md` and the Step 2b prose change ("read brainstorm.md if it exists and is non-empty") fails open. The publish path is similarly untouched: `larch:plan` writes via `plan-block-write.sh --content-file "$DESIGN_TMPDIR/composed-plan.redacted.md"`, and `composed-plan.md` composition logic does not currently embed brainstorm content — keeping it that way avoids leaking brainstorm prose into the public issue body (Round 1 decision #3: "GitHub issue body is NOT mutated by brainstorm"). Re-fire policy is enforced by the `.brainstorm-done` sentinel checked at three sites: Gate A's "Discuss more" re-entry (skip Step 1f, go straight to discussion sub-round), Gate B(c) / Gate C(b) post-plan re-entries (already skip 1f because they jump to Gate A, but the sentinel makes it explicit), and the already-planned-router's "replace via full flow" branch (the sentinel is per-invocation, scoped to `$DESIGN_TMPDIR` which is created fresh per invocation, so a *new* invocation correctly re-fires brainstorm while an in-progress invocation never double-fires — this matches Round 1 decision #6 exactly). Rollout/test story: (1) offline harness coverage via the extended `test-write-run-params.sh` (round-trip the new flag through JSON) plus the new `test-brainstorm-prompts.sh` (pin the four prompt-body literals); (2) structural CI coverage via `scripts/test-design-structure.sh` extensions (Step 1f marker presence, registry row, brainstorm.md / brainstorm-prompts.md existence, public-argv allowlist pin); (3) end-to-end smoke via a one-shot interactive invocation `claude '/design --brainstorm --simple 9999'` against a throwaway issue, exercising both the externals-available path (Cursor + Codex + Claude triple) and the zero-externals path (3-Claude DISTINCT prompts — easily forced via `LARCH_FORCE_NO_EXTERNALS=1` or by pointing `which cursor` / `which codex` at a stub that exits 1); (4) verify the `agent-lint.toml` suppress block does not need new entries by running `make lint` post-change; (5) verify the `lint-foreground-markers` hook passes because the brainstorm collector call carries the standard Family B banner + per-anchor comment that every existing `collect-agent-results.sh` callsite in SKILL.md already carries.
