## Approach Synthesis

**Both sketches converge on the same high-level approach** — evolve the existing `write_initial_state()` in `scripts/ship-pr.sh:239` rather than adding a parallel writer. No substantive divergence on the architectural direction.

### Where the sketches agree

1. **Extend the existing writer, not parallel.** Both Cursor and Codex recommend evolving `write_initial_state()` into a single canonical initializer rather than adding a second function. This avoids schema drift between two writers.
2. **Two new control flags**: `--init-state-from-argv` (sketches imply this, though the issue's prose suggests it could be implicit — see contested decision below) plus `--force-init-state`. Both agents endorse the force flag.
3. **Resume precedence**: existing on-disk state wins unless `--force-init-state` is passed. Argv-init flags ignored on resume.
4. **Value sanitization**: reject CR/LF in values (Codex explicit). Keep `=` allowed in values (existing state stays compatible).
5. **Atomic write**: same `STATE_FILE.tmp.$$ && mv` pattern as today.
6. **Same files to touch**: `scripts/ship-pr.sh` (argv parser + writer), `scripts/ship-pr.md` (interface + precedence contract), `skills/implement/SKILL.md` (Step 8+ replace heredoc + drop "write before invoking" directive), `scripts/test-ship-pr.sh` (fresh-init + resume + force cases).
7. **Bash 3.2 portability concern (Codex)**: use explicit per-key variables + `case` parsing, not associative arrays.
8. **Schema drift risk (Cursor + Codex)**: ensure the argv-init key set matches the orchestrator's 38-key heredoc spec (the 3 keys missing from current `write_initial_state` — BAIL_FAILURE_DETAIL_LOG, NO_LOGS_COMMIT, IMPLEMENT_TMPDIR — must be added).

### Implementation strategy emerging from both sketches

1. Add per-key argv flags: `--branch-name`, `--issue-number`, `--run-id`, `--manifest-path`, `--tool-label`, `--expected-session-id`, `--expected-tmpdir-basename-prefix`, plus the control flag `--force-init-state`.
2. Each new flag has a corresponding `INIT_<KEY>` variable inside ship-pr.sh; `write_initial_state()` writes the flag's value when set, else falls back to the current auto-derivation (BRANCH_NAME from `git rev-parse --abbrev-ref HEAD`; RUN_ID from env or basename; etc.).
3. Validation: reject CR/LF in any `INIT_*` value (Round 1 hard constraint that values must produce a clean `KEY=value` line). The state file syntax check already enforces `^[A-Z_][A-Z0-9_]*=.*$` per `validate_state_syntax`.
4. Resume path: when `STATE_FILE` exists, `--init-state-from-argv` flags are silently ignored (current behaviour); `--force-init-state` overrides and re-writes.
5. SKILL.md Step 8+ Bash block adds the new flags between `--repo` and the closing line; the "Before invoking the script, write..." prose at L1550-1559 is dropped; the key list converts to an informational appendix noting "ship-pr.sh's argv-init mode populates these keys".
6. Test harness gets three new cases: fresh-init (no existing state file → argv writes it byte-identical to the heredoc), resume-precedence (existing state wins despite conflicting argv), force-init (`--force-init-state` overrides).
7. `scripts/ship-pr.md` documents the new flags and precedence contract.

### Risks both sketches flagged

- **Schema drift** — single source of truth needed for the key set.
- **Resume clobbering** — must verify resume-precedence harness case.
- **Value encoding** — newlines/CR rejected; `=` in values acceptable.

The synthesis chosen for Step 2b:

- Follow Codex's slightly more detailed parsing strategy (explicit `INIT_*` variables, `case` dispatcher).
- Single ordered key-list constant inside `ship-pr.sh` shared by `write_initial_state()` and `require_key` validation.
- Match the 38-key SKILL.md spec exactly; add BAIL_FAILURE_DETAIL_LOG, NO_LOGS_COMMIT, IMPLEMENT_TMPDIR to `write_initial_state()`.
- Tests extend the existing `scripts/test-ship-pr.sh` (per Round 1 decision).
