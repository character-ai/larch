## Approach

- Use **Gate C** as the default surfacing point for post-review forks.
- Reason:
  - Step 2b can detect forks cheaply while drafting.
  - Gate C already has operator approval.
  - Post-review surfacing avoids adding a pre-draft pause.
- Bind auto candidates to the **plan fingerprint** and clear them on every post-Step-2b `plan.txt` rewrite at documented choke points (**settle after dedup/postplan**, **plan_review after full apply+dedup**, **postplan hash change**) so Gate C never debates obsolete forks.
- Keep debate **cheap and inert by default**.
  - No fingerprint-valid candidates means no debate and no output.
  - Detection is self-declaration from the drafter (plus optional inline-fallback write), not a separate classifier pass.
  - Debate runs only for 1-2 fingerprint-valid candidates.
  - `--skip-approve` suppresses auto debate launches entirely.
- Use **Claude subprocesses** through existing launcher infrastructure with an explicit clarifier time budget and mandatory child terminate/kill on fail-open.
- Keep dialectic **advisory**.
  - It never rewrites `plan.txt`.
  - Approve publishes the current plan; panel lean is recommendation only.
  - **Discuss further** owns plan revision when the operator disagrees.
  - CHOSEN follows `drafter_pick`; Option A/B labels stay neutral in digest text.
- Defer `dialectic-clarifier.md` load until fingerprint-valid contested artifacts or a manual request exists.
- Consolidate Gate C mechanical emit in **`design-step3b-tail.sh`**; retire `design-step4b-preview.sh` references.
- Gate C manual debate uses **`--request-file` only** at the orchestrator callsite to avoid shell metacharacter injection.

## Edge cases

- **No fork detected**: no candidate file, no reference load, no Gate C digest, no added cost beyond a cheap fingerprint check.
- **Over-eager drafter**: candidate validator enforces two concrete options, material tradeoff text, valid `drafter_pick`, and cap 2.
- **Plan changes after Step 2b**: `dialectic-clear-stale` at settle/postplan/plan_review choke points drops auto candidates and cached auto digest; `dialectic-gatec` no-ops unless manual debate is requested.
- **Dedup after apply**: clear-stale runs only after dedup succeeds, not immediately after `revise-waterfall` when dedup will still rewrite `plan.txt`.
- **`--skip-approve`**: no auto debate subprocesses; optional fingerprint-valid cached digest print only; preview and auto-approve proceed.
- **Manual request is vague**: return a short instruction asking for `decision: option A vs option B` or `debate <candidate-id>`, then re-fire Gate C.
- **Manual `debate <id>` with stale fingerprint**: reject with shape help; no debate; operator must rewrite plan and re-declare or use explicit A vs B text.
- **Claude unavailable or fails / budget exceeded**: terminate tracked children, print warning, append `execution-issues.md`, continue Gate C; late child writes ignored.
- **Malformed optional dialectic JSON in drafter output**: valid plan kept; no candidate file; diagnostics only.
- **Stale candidates file on disk**: deferred-load guard and `dialectic-gatec` no-op; no `dialectic-clarifier.md` load overhead.

## Failure modes

1. **Dialectic spam**
   - Warning signal: many ordinary implementation choices appear as Gate C debates.
   - Mitigation: strict validator plus cap 2; require two named options and a real tradeoff.

2. **Hidden decider regression**
   - Warning signal: `plan.txt` changes based on dialectic output before operator approval.
   - Mitigation: dialectic runner writes digest artifacts only; Gate C **Discuss further** owns any plan revision; Approve semantics explicitly keep current plan.

3. **Cost creep**
   - Warning signal: no-fork or skip-approve runs launch Claude subprocesses.
   - Mitigation: no-op-first `dialectic-gatec`; fingerprint stale no-op; skip-approve gate before auto debate; clarifier wall-clock budget with fail-open and child kill; tests assert no launches on absent/stale candidates and on skip-approve.

4. **Stale fork debate**
   - Warning signal: digest discusses options the current plan already resolved.
   - Mitigation: plan fingerprint on candidates and digest status; clear-stale at all rewrite choke points (settle post-dedup/postplan, plan_review post-apply+dedup, postplan hash change); manual id lookup requires fingerprint match.

5. **Orphan subprocess corruption**
   - Warning signal: digest/status changes after Gate C continued or during cleanup.
   - Mitigation: terminate/kill tracked children on budget exceed; generation token ignores late writes; test asserts post-timeout immutability.

6. **Shell injection via Gate C Other**
   - Warning signal: operator quotes/metacharacters break the manual debate fence.
   - Mitigation: Write-tool request file + `--request-file` only at Gate C; `--request` reserved for tests/internal callers.
