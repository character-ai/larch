## Findings

### 1. Gate C `Other` debate vs full-plan contract (`approval-gates.md:223`) — important, correctness

The plan adds manual debate via Gate C `Other` in `### UPDATED: skills/design/SKILL.md` and prompt text in `### UPDATED: skills/design/references/approval-gates.md`. The normative Gate C contract at `skills/design/references/approval-gates.md:223` still treats **every** `Other` response as a full-plan request. Without an explicit dispatch table and precedence rules, the on-demand debate affordance from the issue scope will not run reliably.

### 2. `--skip-approve` auto-debate cost (`plan.txt` Edge cases) — important, risk-integration

The plan places `dialectic-gatec` in `### UPDATED: skills/design/scripts/design-step3b-tail.sh` before the existing Gate C preview and `SKIP_APPROVE_REQUESTED_GATEC` row. Edge-case text only allows digest printing. That means flagged runs with `--skip-approve` can still launch the full cheap-debate subprocess fanout while skipping the operator gate, which conflicts with the issue’s hard cost-discipline constraint.

### 3. Unconditional `dialectic-clarifier.md` load (`skills/design/SKILL.md` plan section) — important, architecture

`### UPDATED: skills/design/SKILL.md` requires loading `references/dialectic-clarifier.md` before every Gate C handling pass. The issue requires near-zero overhead on no-fork runs and deferring large reference loads until a contested decision is confirmed. Mechanical no-op in `dialectic-gatec` does not remove orchestrator context cost from loading the reference on the common path.

### 4. Adjudication contract gap (`python/design_dialectic.py` plan section) — blocking, correctness

`### NEW: python/design_dialectic.py` claims reuse of `skills/shared/dialectic-protocol.md` threshold rules with Claude-only judges, but the clarifier candidate schema (`option_a`/`option_b`/`drafter_pick`) does not match protocol `{CHOSEN}`/`{ALTERNATIVE}` synthesis semantics, cheap debaters have no specified structured output, and the protocol’s 3-judge threshold table fails closed below two eligible judges. Without a dedicated slim clarifier adjudication profile, panel lean in the digest can be wrong or empty while still presenting as advisory guidance at Gate C.
