## Summary

PR #6885 (issue #6882) replaced the exact-match assessment-note classifiers with tolerant prose classification. That unblocked verbose clean notes, but the gate now leans open:

- A note is a violation only when it names a specific `I-*`/`G-*` id and does not lead with the clean sentence (`_invariant_assessment_kind` in `python/larch/core/architectural_guidelines.py`; the same shape twice in `python/larch/implement/ship_guidelines.py`).
- A real violation note that describes the problem without naming an id classifies as clean and ships.
- The classifier logic is triplicated across the two modules. The shared regexes reduce drift but do not remove it.

## Proposal

Make the outcome explicit at persist time; stop inferring it from prose.

- The /design persist verb already accepts an explicit assessment flag (`persist-design-assessment --assessment clean`). Mirror that for the /implement assessment wrappers: the author passes an explicit outcome, and `architectural-invariant-outcome.json` and the guideline outcome carry that field.
- Demote prose classification to a consistency cross-check: an explicit clean outcome plus a note that names `I-*`/`G-*` ids without the clean lead fails closed with a re-author request.
- Collapse the three classifier copies into one shared helper.

## Acceptance

- Outcome JSON carries an author-supplied outcome field.
- Prose-only inference no longer decides ship routing.
- Mismatch between explicit outcome and note structure fails closed.
- One shared classifier implementation. Regression tests cover clean-with-rationale, id-free violation notes, and mismatch.

## Proposed Design Outline

### Goals
- Make the /implement architectural-assessment outcome author-supplied at persist time, so an explicit outcome (not prose) decides ship routing.
- Fail closed when a note declares `clean` but names an `I-*`/`G-*` id without the clean lead (one-way cross-check).
- Collapse the three tolerant-prose classifiers into one shared helper.

### Non-goals
- Do not change the tolerant-prose classifier logic; relocate it into one helper and demote it to a cross-check.
- Do not touch the /design `persist-design-assessment` path (already explicit).
- No symmetric cross-check: an explicit `violation`/`deviation` paired with a clean-shaped note is honored, not re-author-forced.

### Approach sketch
- Add one shared classifier helper in `architectural_guidelines.py` (serving both `clean|deviation` and `clean|violation` vocab); import it from `ship_guidelines.py`; delete the 3 copies.
- Add a required `--outcome` flag to the /implement `write-compose-assessment` (and `write-staged-assessment`) verbs; record it as the authoritative `ASSESSMENT_KIND` in note metadata / outcome sidecar.
- On present invariants/guidelines, an omitted `--outcome` fails closed with a re-author request; prose never routes.
- Cross-check at write time: declared `clean` + classifier says violation/deviation, fail closed.

### Surfaces in scope
- `python/larch/core/architectural_guidelines.py`; `python/larch/implement/ship_guidelines.py`
- `skills/implement/scripts/step-architectural-{invariants,guidelines}-write-compose.sh`; `...-write-staged.sh`
- Tests: `python/tests/core/test_architectural_guidelines.py`; `python/tests/implement/test_ship.py`

### Open questions
- None. Both scope forks (hard cutover, one-way cross-check) resolved in Round 1.
