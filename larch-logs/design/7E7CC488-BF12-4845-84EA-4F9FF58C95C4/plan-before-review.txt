## Approach

1. Define the two assessment vocabularies and a distinct re-author-required exit code in shared config.
2. Move the tolerant note classifier into one helper in `python/larch/core/architectural_guidelines.py`. Preserve its current first-line clean-lead and identifier-search behavior.
3. Require an explicit outcome on compose and staged assessment writers. Validate `clean|violation` for invariants and `clean|deviation` for guidelines.
4. Before writing artifacts, run the one-way cross-check. Reject declared `clean` when the shared classifier finds an identifier without the clean lead. Do not reject explicit `violation` or `deviation`.
5. Persist the supplied value as `ASSESSMENT_KIND` in the existing HEAD and diff-fingerprint-pinned metadata. Keep outcome sidecars at `schema_version == "1"`.
6. Pass the validated outcome through the live Step 8 coordinator and shell wrappers in the same change.
7. Remove prose inference from ship routing. Authored present notes without a valid persisted outcome must request re-authoring rather than route as clean. Deterministic-clean, unavailable, absent, invalid, and empty-invariant paths retain their existing system-derived behavior.

## Edge cases

- A canonical clean first line followed by rationale naming `I-*` or `G-*` remains clean.
- An identifier-free note declared `violation` or `deviation` remains blocking.
- A clean-shaped note declared `violation` or `deviation` remains blocking.
- A note declared `clean` with a matching identifier and no canonical clean lead is rejected before persistence.
- Guideline outcomes cannot use `violation`; invariant outcomes cannot use `deviation`.
- Missing outcomes fail closed only on authored present-assessment paths. System-derived absent, invalid, unavailable, deterministic-clean, and invariant-empty paths remain valid.
- HEAD drift or diff-fingerprint drift continues to invalidate the note and sidecar regardless of the explicit outcome.
- Legacy authored metadata without `ASSESSMENT_KIND` cannot regain authority through prose inference.

## Failure modes

- If a producer is not updated atomically, the required flag can stall valid Step 8 runs. Update the coordinator and all retained wrappers with the CLI gate.
- If routing retains any `assessment_kind or classify(note)` fallback, prose can still decide shipping. Remove these fallbacks and test missing metadata directly.
- If the mismatch check runs after writing, a failed authoring attempt can leave a consumable clean artifact. Validate before all writes and assert artifact absence on failure.
- If the shared helper merges vocabularies, guideline and invariant sidecars may accept invalid values. Keep separate constant sets and tests.
- If mismatch errors collapse into the generic internal-error or unavailable path, callers cannot request re-authoring. Preserve the distinct exit and status through wrappers and coordinator handling.
