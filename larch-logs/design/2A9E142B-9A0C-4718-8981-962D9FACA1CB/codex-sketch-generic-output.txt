The main risk is contract drift between “8 reviewer invocations” and “4 raw proposals”: I would make the artifact model explicit by grouping the two vendor outputs per archetype into one user option, without silently synthesizing them unless the user chooses the aggregator. The other sharp edge is dependencies: `/issue --no-dedup` currently conflicts with `--intra-batch-deps-file`, so this feature either should not use `--no-dedup` when filing dependent batches, or L1/L3 must deliberately change `/issue` semantics for that combination. Finally, closing the original issue is high-impact and should be idempotent: write a sentinel in `$DESIGN_TMPDIR`, parse `ISSUE_*` stdout by key, only close after all required partition issues and blocker edges are confirmed, and surface partial failures without pretending the partition completed.
