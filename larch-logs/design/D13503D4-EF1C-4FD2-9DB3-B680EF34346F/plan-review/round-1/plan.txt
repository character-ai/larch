# Round II of /design refactor, Phase 2: move Step 3 preview ownership into review driver

## Summary

Move Step 3 plan-candidate preview ownership into `run-step3-review.sh`, but
retain a live preview-only Bash fence before the captured review driver call.
This preserves the pre-voting `## Plan Candidate for Review` display and the
large-plan "show full plan" interrupt point; command substitution would
otherwise buffer the preview until after the long review. The separate direct
`emit-design-plan-preview.sh --variant step3` orchestrator fence is removed;
the orchestrator calls `run-step3-review.sh --preview-only` for the live
preview, then captures `run-step3-review.sh --no-preview` for review KVs.

Collapse the Step 3 result-env consumption fence in `SKILL.md` to the Phase 1
thin-fence shape. Review panel / cap guard / branch matrix / SIMPLE-HARD
semantics are unchanged. The original per-Step-3-entry turn-reduction goal is
deferred because accepted review requires preserving the preview yield.

Tier: SIMPLE. Phase 2 of 7; only the Step 3 surface is touched. Phases 3-7 are
separate issues.

## Key mechanics

- `larch_quiet_init` inside a command substitution duplicates the substitution
  pipe into FD 3, so `emit` output from a captured driver call is still
  buffered. Therefore the preview must be rendered by an uncaptured
  `run-step3-review.sh --preview-only` invocation before the long review call.
- The driver MUST keep emitting machine KVs on FD 3: `test-run-step3-review.sh`
  pins them as the symlink-outer fallback (when `phase_driver_write_result_env`
  refuses a symlinked `.step3-review-result.env` and exits 1, the orchestrator
  recovers KVs from stdout). The captured review stream must remain preview-free
  and KV-oriented; non-KV WARN/display lines may still be echoed by the thin
  fence.
- If no safe non-symlink result env was loaded, stdout fallback KVs are parsed
  in order and later allowlisted values overwrite earlier values so terminal
  driver KVs win over any earlier diagnostic-looking lines. A safely read
  result env keeps file-first precedence.
- `assert_thin_fence` (added in Phase 1) forbids the literal
  `is a symlink; refusing to source` in the scoped region and requires the
  region's entry pause guard to thread `${REPO:+--repo "$REPO"}`. The thin Step
  3 fence therefore guards the result-env read with `! -L` (no message) and
  threads `${REPO:+--repo "$REPO"}` into the Step 3 pause guard.
- Sentinel ownership moves to the driver preview mode:
  `emit-design-plan-preview.sh --variant step3` becomes a pure renderer;
  `run-step3-review.sh --preview-only` checks and touches
  `.step3-entry-plan-printed`.

## Edge cases

- **Re-entry** (Gate C re-run, Gate B(c)/Gate C(b) -> Gate A -> Step 3): the
  sentinel exists, so `--preview-only` renders no preview. Preserved.
- **Symlinked `.step3-review-result.env`**: file read skipped via `! -L`; the
  orchestrator recovers KVs from the driver's stdout fallback. Same net outcome
  as today (symlink -> stdout fallback), now without the forbidden
  `refusing to source` message.
- **Missing/empty `plan.txt` at Step 3**: the renderer prints its warning and
  exits 0; `--preview-only` touches the sentinel for this documented path and
  the subsequent `--no-preview` call proceeds to review.
- **Allowlist-invalid or missing/invalid tmpdir preview warning**: preview mode
  emits the warning but does not create `.step3-entry-plan-printed`, so a later
  valid Step 3 entry can still show the preview.
- **`LARCH_QUIET_DISABLE` (tests)**: `emit` routes to FD 1. In preview mode it
  is live stdout; in review mode it is captured for KV fallback.
- **Large-plan summary mode**: handled inside `emit-design-plan-preview.sh`
  (`LARCH_DESIGN_PLAN_SUMMARY_THRESHOLD`); unchanged. The separate preview-only
  fence preserves the "show full plan" interrupt.
- **Plan body line resembling an allowlisted `KEY=value`**: theoretical
  mis-parse is avoided for preview text because preview is not in the captured
  review stream; fallback parsing also lets later terminal KVs win when no safe
  result env was loaded.

## Failure modes

- **Buffered preview regression** — rendering the preview from the captured
  `--no-preview` review call delays it until after review. Earliest signal:
  `test-run-step3-review.sh` no-preview-has-no-plan assertion fails or chat-order
  structure pins fail. Mitigation: keep preview in the uncaptured
  `--preview-only` fence.
- **Display / KV bleed** — echoing KV lines as display dumps `LOOP_STATUS=...`
  noise to chat, or parsing early diagnostics as terminal state corrupts branch
  state. Signal: `test-step3-orchestrator-fence.sh` display-vs-parse and
  later-KV-wins assertions. Mitigation: allowlist-keyed parse; echo only non-KV
  lines; terminal stdout KVs overwrite earlier fallback values when no safe env
  was loaded.
- **Sentinel split-ownership** — sentinel logic left in both the script and the
  driver renders the preview twice or never. Signal:
  `test-run-step3-review.sh` idempotency case. Mitigation: single owner (driver).
- **Sentinel over-eager touch** — allowlist-invalid or missing-tmpdir preview
  warnings create `.step3-entry-plan-printed` and suppress later valid previews.
  Signal: `test-run-step3-review.sh` disallowed-tmpdir no-sentinel case.
  Mitigation: touch only on rendered header or verified missing/empty-plan path.
- **`assert_thin_fence` regression** — the Step 3 pause guard omits
  `${REPO:+--repo "$REPO"}` or the region keeps `refusing to source`. Signal:
  `scripts/test-design-structure.sh` Step 3 thin-fence assertion. Mitigation:
  thread REPO; `! -L` guard with no forbidden string.
