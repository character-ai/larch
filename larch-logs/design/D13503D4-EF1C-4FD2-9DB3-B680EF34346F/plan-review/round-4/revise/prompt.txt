## Edge cases

- **Preview-only before validation**: missing `--round-cap` or failed tmpdir
  `cd` must not block the live preview fence; only `--no-preview` enforces those
  checks.
- **Omitted mode flags**: direct harness/CLI callers without
  `--preview-only`/`--no-preview` behave as `--no-preview`; `SKILL.md` uses
  explicit flags.
- **Missing `.step3-review-result.env`**: `-f && ! -L` guard skips file read so
  `set -e` does not abort before stdout KV fallback.
- **Re-entry** (Gate C re-run, Gate B(c)/Gate C(b) -> Gate A -> Step 3): when
  tmpdir validates and the sentinel exists, `--preview-only` renders no preview.
  Preserved.
- **Stale sentinel on invalid tmpdir**: sentinel present but tmpdir fails
  `larch_design_tmpdir_validate` — still invoke the renderer so allowlist warnings
  are not suppressed; do not touch the sentinel.
- **Symlinked `.step3-review-result.env`**: file read skipped via `! -L`; the
  orchestrator recovers KVs from the driver's stdout fallback. Same net outcome
  as today (symlink -> stdout fallback), now without the forbidden
  `refusing to source` message.
- **Missing/empty `plan.txt` at Step 3**: the renderer prints its warning and
  exits 0; `--preview-only` touches the sentinel only when that exact warning
  string appears in captured stdout **and** tmpdir validates (not via filesystem
  `! -s` alone); the
  subsequent `--no-preview` call proceeds to review.
- **Allowlist-invalid or missing/invalid tmpdir preview warning**: preview mode
  emits the warning but does not create `.step3-entry-plan-printed`, so a later
  valid Step 3 entry can still show the preview.
- **`LARCH_QUIET_DISABLE` (tests)**: `emit` routes to FD 1. In preview mode it
  is live stdout; in review mode it is captured for KV fallback.
- **Large-plan summary mode**: handled inside `emit-design-plan-preview.sh`
  (`LARCH_DESIGN_PLAN_SUMMARY_THRESHOLD`); unchanged. The separate preview-only
  fence preserves the "show full plan" interrupt.
- **Plan body line resembling an allowlisted `KEY=value`**: preview is not in the
  captured review stream; stdout fallback uses the pinned 12-key allowlist only
  and later terminal KVs win when no safe result env was loaded (harness case
  with early fake `LOOP_STATUS` line).

## Failure modes

- **Buffered preview regression** — rendering the preview from the captured
  `--no-preview` review call delays it until after review. Earliest signal:
  `test-run-step3-review.sh` no-preview-has-no-plan assertion fails or chat-order
  structure pins fail. Mitigation: keep preview in the uncaptured
  `--preview-only` fence.
- **Preview blocked by review validation** — `--preview-only` runs after
  `--round-cap` / `cd` checks and exits before rendering. Signal:
  `test-run-step3-review.sh` preview-without-round-cap / disallowed-tmpdir cases.
  Mitigation: parse mode before validation; raw tmpdir to renderer on preview path.
- **Mode-flag compatibility break** — requiring an explicit mode flag breaks
  `test-run-step3-review.sh` / `test-design-multi-round-integration.sh` direct
  callers. Signal: integration or driver harness fails before review logic runs.
  Mitigation: default omitted mode to `--no-preview`; SKILL.md uses explicit flags.
- **Display / KV bleed** — echoing KV lines as display dumps `LOOP_STATUS=...`
  noise to chat, or parsing early diagnostics as terminal state corrupts branch
  state. Signal: `test-step3-orchestrator-fence.sh` display-vs-parse and
  later-KV-wins assertions. Mitigation: allowlist-keyed parse; echo only non-KV
  lines; terminal stdout KVs overwrite earlier fallback values when no safe env
  was loaded.
- **Sentinel split-ownership** — sentinel logic left in both the script and the
  driver renders the preview twice or never. Signal:
  `test-run-step3-review.sh` idempotency case. Mitigation: single owner (driver).
- **Sentinel over-eager touch or stale suppress** — allowlist-invalid tmpdir
  warnings create `.step3-entry-plan-printed`, or a stale sentinel hides later
  allowlist warnings. Signal: `test-run-step3-review.sh` disallowed-tmpdir /
  stale-sentinel-invalid-tmpdir cases. Mitigation: validate before sentinel
  read/write/touch; touch only on header/warning strings when tmpdir validates.
- **`assert_thin_fence` / REPO regression** — any Step 3 pause guard omits
  `${REPO:+--repo "$REPO"}` or the region keeps `refusing to source`. Signal:
  `scripts/test-design-structure.sh` Step 3 thin-fence / all-pause-save REPO pins.
  Mitigation: thread REPO on every pause-save in the region; `-f && ! -L`
  result-env guard with no forbidden string.
- **Normative doc drift** — `docs/issue-anchored-plan.md` still describes the old
  direct renderer fence. Signal: manual drift review or structure/doc pins.
  Mitigation: include `docs/issue-anchored-plan.md` in the file list and update
  lines 189-194.
