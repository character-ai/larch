### 1. [correctness] `skills/design/SKILL.md` (thin-fence `rc=2` block, ~1097–1103 today)

The plan correctly moves exit-2 handling before `LOOP_STATUS` normalization, but it still only `printf`s the configuration-error banner. Peer steps (0b, 2b, 3.6, 5c) use `exit 1` after an exit-2 banner. Here the fence can still load a safe `.step3-review-result.env` first, leaving `LOOP_STATUS=complete` (or similar) set when `_plan_review_rc==2`. Skipping normalization does not stop the orchestrator from following the **Post-loop branch matrix**, which branches on `LOOP_STATUS`, not `_plan_review_rc`. That is a real mis-route after mutual-exclusion or other driver exit 2.

**Suggested revision:** Add `exit 1` immediately after the banner (and a structure pin), consistent with Step 3.6.

### 2. [correctness] `skills/design/scripts/run-step3-review.sh` (proposed `--preview-only` branch)

Mode-before-validation is right, but the plan never requires an explicit `exit 0` at the end of `--preview-only`. If implementation uses a preview `if` without stopping the script, a successful preview falls through into the existing `--round-cap` / `cd` gate. The SKILL preview fence does not pass `--round-cap`, so operators get a live plan preview followed by a spurious configuration exit 2—not a second review, but still a broken Step 3 entry.

**Suggested revision:** Document and implement `exit 0` after preview emit/sentinel touch; extend `test-run-step3-review.sh` to assert no review side effects (no result env, no round-count mutation).
