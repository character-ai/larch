## Summary

`WARN_PLAN_FILES_UNTOUCHED` fires a false-positive advisory when a plan scope heading (`### UPDATED:`) lists a file whose plan prose body explicitly marks the change as conditional ("only change if…"). The dispatcher's coverage check reads headings but not prose conditions, so it warns even when the implementer correctly skipped the file per the plan's own instructions.

## Original report

During run 2A177850-CE78-4DCA-BF63-D5EDFFFBF631 (PR #4896, issue #4865), the dispatcher emitted `WARN_PLAN_FILES_UNTOUCHED=true` / `WARN_PLAN_FILES_UNTOUCHED_COUNT=1`. The untouched file was `python/run_logs.py`. The plan's scope heading declared `### UPDATED: python/run_logs.py`, but the prose body for that section read: "Only change this file if the audit finds a genuine soft-fail scrub path." Codex correctly skipped the file — no soft-fail scrub path was found — but the advisory still fired.

## Reproduction scenario

1. Author a `/design` plan that includes a `### UPDATED: <file>` scope heading where the prose body says "Only change if…" (a conditional update).
2. Run `/implement` with Codex or Cursor as the coder.
3. The implementer correctly skips the file based on the conditional prose.
4. Observe `WARN_PLAN_FILES_UNTOUCHED=true` in dispatcher stdout even though the skip was intentional and plan-directed.

## Expected behavior

`WARN_PLAN_FILES_UNTOUCHED` should not fire for a file whose plan scope heading or prose body explicitly marks the change as conditional. Either:
- The plan format should provide a heading variant that signals "optional" (e.g., `### MAY_UPDATE:`) and the coverage check should exclude it; or
- The coverage check should suppress the warning when it can detect a conditional marker in the prose immediately following the file heading.

## Observed behavior

`WARN_PLAN_FILES_UNTOUCHED=true` is emitted with `WARN_PLAN_FILES_UNTOUCHED_COUNT=1`, attributing `python/run_logs.py` as an uncovered path even though Codex's decision to skip it was correct and plan-sanctioned.

## Root cause analysis

`_plan_coverage_uncovered_paths` in `python/implement_dispatch.py` (line 1287) calls `issue_wire.extract_scope_paths` to collect all paths from `### NEW:` / `### UPDATED:` / `### REWRITTEN:` headings, then compares against the pre-commit working-tree delta. It reads headings only and has no access to the prose that follows each heading. Because the plan format does not currently distinguish "unconditional update" from "conditional update" at the heading level, every `### UPDATED:` path is treated as a firm coverage expectation.

## Evidence

- `python/implement_dispatch.py:1283–1298`: `_explicit_plan_scope_paths` calls `issue_wire.extract_scope_paths(plan_text, use_fallback=False)` with no conditionality awareness.
- `python/implement_dispatch.py:1528–1531`: `_plan_coverage_uncovered_paths` returns all heading-listed paths absent from the pre-commit working tree without inspecting prose content.
- Plan scope heading for `python/run_logs.py` (issue #4865 body): `### UPDATED: python/run_logs.py` followed by "Only change this file if the audit finds a genuine soft-fail scrub path."
- `git show d27702d09 -- python/run_logs.py` produces no output: the file was not touched in the squash-merge commit.
- `python/test_run_logs.py` was changed (+25 lines) — new parity tests were added — confirming the implementation around `run_logs.py` was otherwise complete.

## Affected files

- `python/implement_dispatch.py` — `_explicit_plan_scope_paths` and `_plan_coverage_uncovered_paths` (lines 1283–1298): add conditionality awareness or accept a new heading variant.
- `python/issue_wire.py` — `extract_scope_paths`: may need a flag or separate extractor for optional headings.
- `docs/issue-anchored-plan.md` — plan heading format docs: clarify that `### UPDATED:` implies a firm coverage commitment; document a new `### MAY_UPDATE:` variant if one is added.
- `/design` skill prompt — scope-heading authoring guidance: instruct `/design` not to use `### UPDATED:` for conditional changes.

## Suggested fix(es)

**Option A (preferred): add `### MAY_UPDATE:` heading variant.**
- Define `### MAY_UPDATE: <path>` as a new scope heading for optional changes.
- `issue_wire.extract_scope_paths` excludes `MAY_UPDATE` paths from the coverage-check list.
- Update `/design` authoring guidance to use `MAY_UPDATE` when prose says "only if…".
- Update `docs/issue-anchored-plan.md`.

**Option B: prose-suffix annotation.**
- Allow `### UPDATED: <path> (conditional)` as a decorated heading.
- `_explicit_plan_scope_paths` strips the annotation and returns the path, but tags it so `_plan_coverage_uncovered_paths` can skip tagged paths from the warning.

Both options are non-breaking. Either one eliminates false-positive warnings without loosening coverage checks for unconditionally-declared paths.

## Approved direction (outline)

## Proposed Design Outline

### Goals
- Stop `WARN_PLAN_FILES_UNTOUCHED` firing for plan files the plan itself marks optional.
- Add a `### MAY_UPDATE: <path>` scope heading recognized across the plan-grammar consumers.
- Keep the warning firm for unconditional `### NEW: / ### UPDATED: / ### REWRITTEN:` paths.

### Non-goals
- No change to gating; the coverage diagnostic stays warn-only.
- No retroactive re-flagging of old run logs or existing `### UPDATED:` conditional plans.
- No new dirty-tree or `plan scope-paths` behavior beyond recognizing the keyword.

### Approach sketch
- Teach `issue_wire.extract_scope_paths` to recognize `MAY_UPDATE`, gated by a new `include_optional` param (default: include).
- `implement_dispatch._explicit_plan_scope_paths` calls it with optional excluded, so coverage skips MAY_UPDATE paths.
- Add `MAY_UPDATE` to the `plan_quality.py` plan-size heading counter so optional files still count.
- Update /design authoring (`design_lifecycle.py`), reviewer grammar note (`rendering.py`), and `docs/issue-anchored-plan.md`.
