## Approach

Use an additive heading variant.

- Do not infer conditionality from prose.
- Do not decorate existing headings with suffixes.
- Keep old plans valid.
- Keep old conditional `### UPDATED:` plans warning as before.
- Make `MAY_UPDATE` opt-in for new plans.

The key split is:

- `include_optional=True`: normal scope extraction.
- `include_optional=False`: coverage commitments only.

Gate B revise-waterfall must preserve optional heading type so review revisions do not upgrade `MAY_UPDATE` into firm headings and reintroduce false positives.

Step 3b must recognize `MAY_UPDATE` as a real file heading so docs-only optional plans keep the existing no-architectural-change skip behavior.

Defer `parse_plan_commands` / `- Adds flag:` parity unless a real plan needs it.

This keeps the fix narrow and avoids changing dirty-tree recovery semantics.

## Edge cases

- **No `## Files to modify/create` section**: coverage still sees no explicit scope when `use_fallback=False`.
- **Empty explicit section**: fallback still applies only for default CLI scope extraction.
- **Mixed firm and optional duplicate path**: de-duplicate by path. If any firm heading names the path, coverage should still expect it.
- **Optional-only plan**: no untouched warning should fire.
- **MAY_UPDATE-only docs plan at Step 3b**: classifier must not treat the plan as heading-free; docs-only optional paths should skip diagram generation.
- **Gate B revise on optional headings**: revised plan must keep `### MAY_UPDATE:`; conversion to firm headings is invalid.
- **Legacy path syntax**: keep backticks and parenthetical stripping behavior unchanged.
- **Malformed headings**: keep the ASCII-space requirement after `###`.
- **Deferred**: `MAY_UPDATE` with `- Adds flag:` rows is out of scope for this change.

## Failure modes

1. **Optional paths vanish from scope consumers**
   - Signal: `plan scope-paths` omits `MAY_UPDATE`.
   - Mitigation: default `include_optional=True` and add CLI coverage.

2. **Coverage gets too loose**
   - Signal: untouched firm `### UPDATED:` path no longer warns.
   - Mitigation: mixed-heading dispatcher regression with a firm untouched path.

3. **Gate B upgrades optional headings to firm**
   - Signal: post-review plan rewrites `### MAY_UPDATE:` as `### UPDATED:` and coverage warns on intentional skip.
   - Mitigation: explicit revise-prompt hard rule forbidding optional-to-firm conversion.

4. **Step 3b misclassifies optional-only docs plans**
   - Signal: a docs-only plan with only `### MAY_UPDATE:` headings forces `DIAGRAM_REQUIRED=true`.
   - Mitigation: extend the Step 3b heading regex and add structure-harness classifier cases.

5. **Docs and drafter guidance drift**
   - Signal: `/design` still emits conditional `### UPDATED:` headings.
   - Mitigation: update Step 2b prompt, Skill guidance, reviewer grammar text, readability contract, and issue-format docs in the same change.
