# Phase 2: phase_tracking — Implementation Plan

## Scope (issue #2736, umbrella #2732)

Replace the `phase_tracking` stub in `scripts/implement-bootstrap.sh` with a full state machine that absorbs `skills/implement/SKILL.md` Step 0 calls #6-#9 (sentinel/tracking-issue-read → get-issue-state → larch-log.sh init → post-tracking-issue → tracking-issue-write rename). Phase 1 (#2735) is DONE; this work extends the existing `phase_infra` body. Phase 3 (plan materialization) and Phase 4 (waterfall) stay out of scope.

## Dialectic-binding decisions

- **DECISION_1 voted (3-0 THESIS → CHOSEN)**: `post-tracking-issue.sh POSTED=false` → set `DEFERRED=true`, **continue** (no sentinel, no rename); plan materialization happens in Phase 3, so `phase_tracking` returns 0 with the deferred flag set.
- **DECISION_2 voted (2-1 ANTI_THESIS → ALTERNATIVE)**: `get-issue-state.sh FAILED=true` → `emit_kv STEP_FAILED get-issue-state` + `exit 2` (treat as infra failure, matches Phase 1's `phase_infra` exit-2 pattern). Do NOT route to `tracking-init-failed` / `STALL_TRACKING` — that bail is reserved for `larch-log.sh init` failures and RUN_ID derivation failures.

**`phase_tracking` body — state machine** (replace stub):

```
phase_tracking() {
    local forked_flag="${FORKED_TARGET:-false}"
    local target_issue="${ISSUE_NUMBER_OPT:-}"

    # Carve-out 1: repo_unavailable (read from REPO_UNAVAILABLE set by phase_infra)
    if [ "$REPO_UNAVAILABLE" = "true" ]; then
        BRANCH_SELECTED=repo-unavailable-skip
        DEFERRED=true
        emit_skip_breadcrumb_if_enabled "repo-unavailable"
        return 0
    fi

    # Carve-out 2: forked_target
    if [ "$forked_flag" = "true" ]; then
        BRANCH_SELECTED=forked-target-skip
        DEFERRED=true
        if [ -n "$UPSTREAM_REPO_OPT" ] && [ -n "$target_issue" ]; then
            # F4 binding doc delta: best-effort context fetch; failures are logged-only, not fatal.
            "$SCRIPT_DIR/get-issue-context.sh" \
                --issue "$target_issue" \
                --repo "$UPSTREAM_REPO_OPT" \
                --tmpdir "$IMPLEMENT_TMPDIR" \
                >"$IMPLEMENT_TMPDIR/upstream-context.log" 2>&1 || true
        fi
        emit_skip_breadcrumb_if_enabled "forked-target"
        return 0
    fi

    # Branch 1: sentinel exists (fail-closed per F2/F8/F19)
    if [ -f "$IMPLEMENT_TMPDIR/parent-issue.md" ]; then
        local _b1_out _b1_rc=0 _sent_failed _sent_issue _sent_runid _sent_adopted _sent_error
        _b1_out=$("$SCRIPT_DIR/tracking-issue-read.sh" --sentinel "$IMPLEMENT_TMPDIR/parent-issue.md" 2>"$IMPLEMENT_TMPDIR/tracking-issue-read.stderr.log") || _b1_rc=$?
        _sent_failed=$(printf '%s\n' "$_b1_out" | grep -m1 '^FAILED=' | awk -F= 'NF{print $2}')
        _sent_issue=$(printf '%s\n' "$_b1_out" | grep -m1 '^ISSUE_NUMBER=' | awk -F= 'NF{print $2}')
        _sent_runid=$(printf '%s\n' "$_b1_out" | grep -m1 '^RUN_ID=' | awk -F= 'NF{print $2}')
        _sent_adopted=$(printf '%s\n' "$_b1_out" | grep -m1 '^ADOPTED=' | awk -F= 'NF{print $2}')
        _sent_error=$(printf '%s\n' "$_b1_out" | awk -F= 'BEGIN{e=""} /^ERROR=/{e=substr($0,index($0,"=")+1); exit} END{print e}')  # F19

        # Strict guard (F2): rc=0 AND not FAILED=true AND ADOPTED=true AND non-empty ISSUE_NUMBER AND non-empty RUN_ID
        local _sentinel_usable=true
        [ "$_b1_rc" -eq 0 ] || _sentinel_usable=false
        [ "$_sent_failed" != "true" ] || _sentinel_usable=false
        [ "$_sent_adopted" = "true" ] || _sentinel_usable=false
        [ -n "$_sent_issue" ] || _sentinel_usable=false
        [ -n "$_sent_runid" ] || _sentinel_usable=false

        if [ "$_sentinel_usable" = "true" ] && [ -n "$target_issue" ] && [ "$_sent_issue" != "$target_issue" ]; then
            # Mismatch — clear sentinel, preserve larch-logs/, fall through to Branch 2
            larch_err "**⚠ Step 0 tracking: sentinel mismatch (sentinel has #$_sent_issue, argv requested #$target_issue). Clearing sentinel and re-adopting.**"
            rm -f "$IMPLEMENT_TMPDIR/parent-issue.md"
        elif [ "$_sentinel_usable" = "false" ]; then
            # Malformed / unusable sentinel — clear it and fall through to Branch 2 (F2)
            larch_err "**⚠ Step 0 tracking: sentinel unusable (rc=$_b1_rc FAILED=$_sent_failed ADOPTED=$_sent_adopted ISSUE_NUMBER=$_sent_issue RUN_ID=$_sent_runid ERROR=${_sent_error:-none}). Clearing sentinel.**"
            rm -f "$IMPLEMENT_TMPDIR/parent-issue.md"
        else
            # Resume path
            ISSUE_NUMBER_RESOLVED="$_sent_issue"
            RUN_ID="$_sent_runid"
            BRANCH_SELECTED=branch-1-resume

            # Idempotent manifest init — F8: capture stderr; on non-zero, route to tracking-init-failed
            if ! "$SCRIPT_DIR/larch-log.sh" init \
                --log-root "$IMPLEMENT_TMPDIR/larch-logs" \
                --skill implement \
                --run-id "$RUN_ID" \
                --issue "$ISSUE_NUMBER_RESOLVED" >"$IMPLEMENT_TMPDIR/larch-log-init.log" 2>&1; then
                larch_err "**⚠ Step 0 tracking: Branch 1 larch-log init failed; see $IMPLEMENT_TMPDIR/larch-log-init.log. Routing to tracking-init-failed.**"
                IMPLEMENT_BAIL_REASON=tracking-init-failed
                STALL_TRACKING=true
                emit_tracking_breadcrumb_if_enabled
                return 0
            fi

            rename_to_implementing "$ISSUE_NUMBER_RESOLVED" "Branch 1 resume"
            emit_tracking_breadcrumb_if_enabled
            return 0
        fi
    fi

    # Branch 2: fresh adopt
    [ -n "$target_issue" ] || {
        # Standalone --up-to-phase tracking without --issue-number is a no-op
        return 0
    }

    local _state_out _state_rc _state _is_pr _state_err
    _state_out=$("$SCRIPT_DIR/get-issue-state.sh" --issue "$target_issue" 2>"$IMPLEMENT_TMPDIR/get-issue-state.stderr.log")
    _state_rc=$?

    # DECISION_2 ALTERNATIVE: FAILED=true OR non-zero rc → STEP_FAILED=get-issue-state + exit 2
    if printf '%s\n' "$_state_out" | grep -q '^FAILED=true$' || [ "$_state_rc" -ne 0 ]; then
        _state_err=$(printf '%s\n' "$_state_out" | awk -F= 'BEGIN{e=""} /^ERROR=/{e=substr($0,index($0,"=")+1); exit} END{print e}')  # F19
        larch_err "**⚠ Step 0 tracking: get-issue-state failed: ${_state_err:-unknown}. Aborting.**"
        emit_kv STEP_FAILED get-issue-state
        exit 2
    fi
    _state=$(printf '%s\n' "$_state_out" | grep -m1 '^STATE=' | awk -F= 'NF{print $2}')
    _is_pr=$(printf '%s\n' "$_state_out" | grep -m1 '^IS_PR=' | awk -F= 'NF{print $2}')

    if [ "$_is_pr" = "true" ]; then
        larch_err "**⚠ Step 0 tracking: #$target_issue is a pull request, not an issue. Aborting.**"
        IMPLEMENT_BAIL_REASON=adopted-issue-is-pr
        BRANCH_SELECTED=branch-2-adopt
        return 0
    fi
    if [ "$_state" = "CLOSED" ]; then
        larch_err "**⚠ Step 0 tracking: adopted issue #$target_issue is CLOSED. Aborting.**"
        IMPLEMENT_BAIL_REASON=adopted-issue-closed
        BRANCH_SELECTED=branch-2-adopt
        return 0
    fi

    # OPEN — adopt. RUN_ID precedence: --run-id (F5) > session-id > LARCH_TOKEN_SESSION_ID
    if [ -n "$RUN_ID_OPT" ]; then
        RUN_ID="$RUN_ID_OPT"
    else
        RUN_ID=$(tr -d '\r\n' <"$IMPLEMENT_TMPDIR/session-id" 2>/dev/null || true)
        [ -n "$RUN_ID" ] || RUN_ID="$LARCH_TOKEN_SESSION_ID"
    fi
    if [ -z "$RUN_ID" ]; then
        larch_err "**⚠ Step 0 tracking: cannot derive RUN_ID. Aborting.**"
        IMPLEMENT_BAIL_REASON=tracking-init-failed
        STALL_TRACKING=true
        BRANCH_SELECTED=branch-2-adopt
        return 0
    fi

    if ! "$SCRIPT_DIR/larch-log.sh" init \
        --log-root "$IMPLEMENT_TMPDIR/larch-logs" \
        --skill implement \
        --run-id "$RUN_ID" \
        --issue "$target_issue" >"$IMPLEMENT_TMPDIR/larch-log-init.log" 2>&1; then
        larch_err "**⚠ Step 0 tracking: larch-log.sh init failed; see $IMPLEMENT_TMPDIR/larch-log-init.log. Routing to tracking-init-failed.**"
        IMPLEMENT_BAIL_REASON=tracking-init-failed
        STALL_TRACKING=true
        BRANCH_SELECTED=branch-2-adopt
        return 0
    fi

    # post-tracking-issue.sh writes parent-issue.md on success.
    # F5: pass --run-id so the sentinel records the chosen RUN_ID (matches post-tracking-issue.sh extension below).
    local _post_out _post_rc=0 _posted _post_err
    _post_out=$("$SCRIPT_DIR/../skills/implement/scripts/post-tracking-issue.sh" \
        --implement-tmpdir "$IMPLEMENT_TMPDIR" \
        --issue-number "$target_issue" \
        --run-id "$RUN_ID" \
        --adopted true 2>"$IMPLEMENT_TMPDIR/post-tracking-issue.stderr.log") || _post_rc=$?
    _posted=$(printf '%s\n' "$_post_out" | grep -m1 '^POSTED=' | awk -F= 'NF{print $2}')
    if [ "$_posted" != "true" ]; then
        # DECISION_1 binding: DEFERRED=true, continue. No sentinel (post-tracking-issue.sh writes it only on success).
        _post_err=$(printf '%s\n' "$_post_out" | awk -F= 'BEGIN{e=""} /^ERROR=/{e=substr($0,index($0,"=")+1); exit} END{print e}')  # F19
        larch_err "**⚠ Step 0 tracking: post-tracking-issue.sh metadata upsert failed (POSTED=$_posted ERROR=${_post_err:-unknown}). Continuing with DEFERRED=true.**"
        DEFERRED=true
        ISSUE_NUMBER_RESOLVED="$target_issue"
        BRANCH_SELECTED=branch-2-adopt
        # No rename on POSTED=false — preserve the operator's ability to investigate
        emit_tracking_breadcrumb_if_enabled
        return 0
    fi

    ISSUE_NUMBER_RESOLVED="$target_issue"
    BRANCH_SELECTED=branch-2-adopt
    rename_to_implementing "$target_issue" "Branch 2 adopt"
    emit_tracking_breadcrumb_if_enabled
    return 0
}
```

**`emit_final_tail` extension** (replace existing function):

```
emit_final_tail() {
    emit_infra_kv_block
    # F1: branch-aware ISSUE_NUMBER — empty on fork/skip carve-outs regardless of argv
    case "$BRANCH_SELECTED" in
        forked-target-skip|repo-unavailable-skip)
            emit_kv ISSUE_NUMBER "" ;;
        branch-1-resume|branch-2-adopt)
            emit_kv ISSUE_NUMBER "${ISSUE_NUMBER_RESOLVED:-}" ;;
        *)
            # No phase_tracking branch reached (--up-to-phase infra or standalone tracking
            # without --issue-number); pass-through OPT for Phase 1 parser stability.
            emit_kv ISSUE_NUMBER "${ISSUE_NUMBER_RESOLVED:-${ISSUE_NUMBER_OPT:-}}" ;;
    esac
    emit_kv RUN_ID "${RUN_ID:-}"
    emit_kv BRANCH_SELECTED "${BRANCH_SELECTED:-}"
    # F16: always emit explicit booleans
    emit_kv DEFERRED "${DEFERRED:-false}"
    emit_kv STALL_TRACKING "${STALL_TRACKING:-false}"
    emit_kv BRANCH_NAME ""        # Phase 4 fills
    emit_kv PLAN_FILE ""          # Phase 3 fills
    emit_kv coder ""               # Phase 4 fills
    emit_kv coder_fallback ""      # Phase 4 fills
    emit_kv IMPLEMENT_BAIL_REASON "${IMPLEMENT_BAIL_REASON:-}"
}
```

## Approach

`phase_tracking` runs after `phase_infra` in a single bootstrap invocation (`--up-to-phase tracking`). It reads only `phase_infra` globals (`REPO_UNAVAILABLE`, `IMPLEMENT_TMPDIR`, `SCRIPT_DIR`, `LARCH_TOKEN_SESSION_ID`) plus the four new argv globals (`FORKED_TARGET`, `UPSTREAM_REPO_OPT`, `RUN_ID_OPT`, `ISSUE_NUMBER_OPT`). All other state is local-scoped (Bash 3.2 portable).

State-machine ordering: carve-outs first (cheapest), then Branch 1 (fs check + script call), then Branch 2 (network + log + comment). Once a branch settles, `phase_tracking` returns 0; `main()`'s guard then skips Phase 3/4 stubs if a bail token or `STALL_TRACKING=true` was set, falls through to `emit_final_tail` (which emits the uniform KV block on every path).

`get-issue-state.sh FAILED=true` is the **only** hard exit-2 path inside `phase_tracking` (DECISION_2). All other failures (sentinel mismatch, sentinel malformed, larch-log init, RUN_ID derivation, post-tracking-issue, rename) are non-fatal — they set `IMPLEMENT_BAIL_REASON` / `STALL_TRACKING` / `DEFERRED` and return 0.

The post-tracking-issue.sh integration relies on the script's contract: it writes `parent-issue.md` only on POSTED=true. `phase_tracking` does not duplicate that write, so DECISION_1's "no sentinel on POSTED=false" invariant is enforced by construction.

`--forked-target` flows through `phase_infra` → `write-session-env.sh` (F6) → `session-env.sh` so Step 2 fork-detection picks it up after the bootstrap returns. `--run-id` flows through `phase_tracking` → `post-tracking-issue.sh` `--run-id` (F5) so the sentinel records the chosen identifier.

All error-parsing uses `awk -F= 'BEGIN{e=""} /^KEY=/{e=substr($0,index($0,"=")+1); exit} END{print e}'` (F19) so messages containing `=` are not truncated. Single-key reads use `grep -m1 '^KEY=' | awk -F= 'NF{print $2}'` for tokens that cannot contain `=`.

## Edge cases

- **`--up-to-phase tracking` with no `--issue-number`**: Branch 2 returns 0 early without GitHub calls; `BRANCH_SELECTED=` (empty); `DEFERRED=false` / `STALL_TRACKING=false` per F16 defaults.
- **Sentinel exists, no argv issue**: treat as resume when sentinel is usable (mismatch guard skipped because both values would be needed to compare).
- **Sentinel `FAILED=true` OR `ADOPTED=false` OR empty IDs** (F2): rm sentinel, fall through to Branch 2. Always log the unusable-sentinel warning to stderr.
- **`RUN_ID_OPT` validation**: rejected via `die_usage` when non-alphanumeric (no path-traversal characters reach the log root).
- **`--forked-target` true with no `--upstream-repo`**: still emit `BRANCH_SELECTED=forked-target-skip` + `DEFERRED=true`; skip the context fetch (no upstream target).
- **`--forked-target true` with `--upstream-repo` set but no `--issue-number`**: skip the context fetch (no issue), still emit forked-target-skip.
- **`tracking-issue-read.sh --sentinel` reports valid ADOPTED=true but ISSUE_NUMBER empty**: treat as unusable per F2; clear and fall through.
- **`larch-log init UNCHANGED=true`** (F15): Branch 1 idempotent re-init; treat as success, no STALL_TRACKING.
- **`--run-id` matches existing sentinel RUN_ID**: Branch 1 still fires (sentinel match wins); the supplied `--run-id` is ignored on the resume path (sentinel is authoritative).
- **`post-tracking-issue.sh POSTED=false`** (DECISION_1): `DEFERRED=true`, no sentinel, no rename, exit 0. Next `/implement <same-issue>` retries Branch 2 from scratch.
- **Concurrent runs**: out of scope (single-runner invariant at the `/implement` level).
- **Bash 3.2 portability**: all parsing uses `grep -m1 ... | awk -F= 'NF{print $2}'` or `awk 'index($0,"=")>0 {...}'` patterns; no `mapfile`, no `${var^^}`, no `declare -A`, no `local -n`.

## Failure modes

1. **`get-issue-state.sh FAILED=true`** (DECISION_2) — sharp infra exit (`STEP_FAILED=get-issue-state` + exit 2). Earliest signal: stderr `**⚠ Step 0 tracking: get-issue-state failed: $ERROR. Aborting.**`. Mitigation: orchestrator routes `STEP_FAILED=` via the standard infra-error table; user retries.
2. **`post-tracking-issue.sh POSTED=false`** (DECISION_1) — soft continue (`DEFERRED=true`, no sentinel). Earliest signal: stderr POSTED=false warning. Mitigation: next run re-attempts Branch 2.
3. **Branch 1 corrupt sentinel** — `rm -f` removes the sentinel atomically, preserves `larch-logs/`, prints warning, falls through to Branch 2 (F2). Mitigation: next run starts cleanly.
4. **larch-log init failure (Branch 1 or Branch 2)** — `IMPLEMENT_BAIL_REASON=tracking-init-failed` + `STALL_TRACKING=true`, return 0. Step 18 renames to `[STALLED]`. Mitigation: operator inspects `$IMPLEMENT_TMPDIR/larch-log-init.log`.
5. **rename failure** — best-effort, logged to `execution-issues.md` Tool Failures via `append-tool-failure.sh` (F9). No bail. Mitigation: visual indicator on GitHub may be stale; correctness unaffected.
