Foundation piece of the #6997 partition (bgjob step-adapter unification). Child of umbrella #7014. Land this first: the adapter conversions and the step-8 grammar unification all build on this verb.

#### Problem

Nine live step scripts hand-implement the same bgjob adapter protocol: the `--bgjob-child` / `--merge-result-env` arg loop, `rehydrate_plugin_root` (9 copies, 2 divergent variants), a registry-liveness Python heredoc, stale-entry clearing, atomic merge-env writers, and `bgjob start ... -- bash "$0" --bgjob-child` self-reexec. The liveness policy has already drifted: step-5-review.sh:75 waits only while `child_liveness and daemon_liveness`, step-6-entry.sh:75 is byte-identical but uses `or`.

#### Goal

Add one `python3 python/cli.py bgjob adapt --step X --budget-s N -- <child argv>` (start-or-wait) verb that owns registry probe, one liveness policy, stale-clear, identity, merge-env, and fail-closed writes. Additive: no consumer converts in this piece.

#### Scope

- New verb `bgjob adapt` (or `start-or-wait`) in `python/larch/bgjob/cli.py`, reusing `python/larch/bgjob/{registry,wait,daemon,model}.py`.
- One start-or-wait protocol module (~400 lines).
- Resolve the `and` vs `or` liveness drift into ONE policy, chosen from the registry child-vs-daemon process model, documented in code.
- Unit tests under `python/tests/bgjob/` for start, re-attach/wait, stale-clear, merge-env, and the liveness policy.

#### Non-goals

Converting any step script, and moving the assessment or ship token vocabularies. Those are later pieces.

#### Acceptance

- `bgjob adapt` starts a child, re-attaches on a second call, merges the result env, and fails closed on a dead registry entry.
- One documented liveness policy; no `and`/`or` fork in the new module.
- `make py-lint` and `make py-test` green.

Run /design on this issue before /implement.

## Proposed Design Outline

### Goals
- Add `python3 python/cli.py bgjob adapt` as a start-or-re-attach verb that encapsulates the adapter protocol shared by nine step scripts.
- Establish one documented liveness policy (`child OR daemon`) in a new module, eliminating the `and`/`or` drift.
- Ship unit tests for start, re-attach, stale-clear, merge-env, and liveness policy.

### Non-goals
- Converting any existing step script to use the new verb.
- Moving assessment or ship token vocabularies.
- Fixing `step-5-review.sh:75` `and` bug in-place (that is a consumer conversion, deferred).

### Approach sketch
- New `python/larch/bgjob/adapt.py` module: registry probe → liveness check → branch (start / re-attach / dead-fail-closed / done-early).
- New `adapt_main()` in `python/larch/bgjob/cli.py`; register it under `bgjob adapt` in `python/cli.py`.
- Liveness policy: `child_liveness(entry).live OR daemon_liveness(entry).live`; policy comment references daemon model.
- Stale-clear: unlink a dead entry and re-issue a fresh start.
- Re-attach path: emit `BGJOB_STATUS=STARTED STEP=<step> PGID=<pgid>` matching `bgjob start` contract so callers use `bgjob wait` unchanged.

### Surfaces in scope
- `python/larch/bgjob/adapt.py` (new)
- `python/larch/bgjob/cli.py` (new `adapt_main`)
- `python/cli.py` (register `bgjob adapt`)
- `python/tests/bgjob/test_bgjob_adapt.py` (new tests)
