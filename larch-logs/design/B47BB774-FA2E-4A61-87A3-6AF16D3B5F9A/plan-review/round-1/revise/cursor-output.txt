## Edge cases

- Empty `findings.md` **and** empty `oos.md`: both gates retain current fail-closed behavior (`panel-failed` when collector success is zero or coverage fails).
- Primary `>50%` slot failure threshold: unchanged; still `panel-failed`.
- Dispatch failure before consolidation: unchanged; still early `panel-failed`.
- OOS-only with `FINDINGS_COUNT > 0`: completes via aggregation/tally; OOS handoff artifacts (`oos-accepted-review.md`, etc.) must remain on the normal path, not `zero-findings`.
- Downgrade warning does not fire for explicit PR-only runs (`MERGE=false` in seed and ship state).
- `collector-slot-status.env` must not expose raw collector diagnostics even if `collector-results.env` contains them in tmpdir.

## Failure modes

- If `review-core-threshold.env` or `collector-slot-status.env` cannot be written, existing shell `set -e` behavior should still fail closed.
- If `execution-issues.md` is absent, downgrade detection defaults to `IMPLEMENT_MERGE_DOWNGRADED=false`.
- If run-log flushing fails, existing `append_round_log_write_failure` behavior remains unchanged.
- Bypass must not mask true primary-threshold failures (`THRESHOLD_OK=false` from `check-reviewer-failure-threshold.sh`).
