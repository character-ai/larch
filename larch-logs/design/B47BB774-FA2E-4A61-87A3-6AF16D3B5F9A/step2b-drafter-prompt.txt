# [BUG] /implement Step 5 review panel-failed despite completed reviewers; stalls run…

## Summary

`/implement` Step 5 code review can return `panel-failed` and hard-stall the run even though all reviewers complete and produce parseable output. Observed on plugin **v51.1.0**, run `3C3F080B-365B-4B00-A891-F1CD01DE9B96` (issue #4547): the 10-slot panel (6 static + 4 dynamic) all ran to completion, "consolidating findings" printed, then `STEP5_REVIEW_STATUS=stall STALL_REASON=panel-failed` with a 0/0/0 tally. The committed run log shows the panel produced 7 parseable findings and `Reviewer slot failures: 0`, so the panel did not actually lose its reviewers — the consolidation/threshold gate reported zero successful slots anyway. Step 18a stall recovery then classified the stall `transient-infra` and dispatched `step8-shippr`, creating a non-merged PR (#4603) and silently downgrading the operator's `--merge` to `pr-created`.

review panel failure

## Reproduction scenario

Not deterministically reproducible (panel/collector outcome depends on reviewer output shape and stochastic format adherence). Observed scenario:

## Root cause analysis

Two `panel-failed` exits exist in `python/legacy_review_shell/review-core.sh`:

- Line ~737: dispatch failed (zero reviewers launched). Fires **before** "consolidating findings".
- Lines ~902–932: the reviewer-failure **threshold gate** returned `THRESHOLD_OK=false`. Fires **after** "consolidating findings".

This run printed "consolidating findings", so it took the **threshold-gate** path. `THRESHOLD_OK` can be set false by three sub-conditions:

1. `FAILED_SLOTS &gt;= 50%+1` of intended static slots (`check-reviewer-failure-threshold.sh:245-251`; `NOT_SUBSTANTIVE` slots count as failed).
2. `launched_success_count == 0` — "no successful launched reviewer output" (`review-core.sh:876-888`, derived from `collector_success_count` over `collector-results.env`).
3. static archetype coverage gate failed (`review-core.sh:889-901`).

**Inference (not proven from committed artifacts):** sub-condition 2 is the most likely trigger here. `round-meta.json` records `"collector": ""` (empty collector record) and `final-summary.md` reports `Reviewer slot failures: 0` — together suggesting the collector did not surface any successful per-slot record (`collector_success_count == 0`), which trips the "no successful launched reviewer output" gate even though the reviewers ran and 7 OOS findings were later aggregated and filed (issue #4602). A plausible contributing factor: the static reviewers emitted only out-of-scope observations / no in-scope structured findings, and that output shape is treated as non-substantive/unsuccessful per slot.

This is in the same subsystem that issue #4547 is changing (the reviewer **collector** + failure-threshold), but it is a distinct defect: #4547 reworks `NOT_SUBSTANTIVE` retry/tally handling, whereas this is a consolidation-accounting failure where the panel is declared failed despite completed reviewers and parseable output. `NOT_SUBSTANTIVE` slots will still count toward the &gt;50% threshold after #4547, so #4547 does not obviously fix this.

Separately, the stall classifier mapping `panel-failed` → `transient-infra` → `step8-shippr` is a deliberate degraded path, but its side effect — silently turning `--merge` into a non-merged PR — is surprising for the operator.
