## Scope

Implement one PR for the approved targets only:

- `review_core`
- `_shared_step2b_postplan_body`
- `run_ship` (narrow helper extraction only; merge loop stays inline)

Do not refactor `failure_report_core`, `_run_round`, or `run_external_agent`.

**Ship scope cap (accepted scope-reduction findings):** defer full `_ship_merge_loop` extraction. This PR limits `run_ship` work to Flush+Push rebase dedup (`_ship_rebase_phase`), optional phase14 helper at the existing loop head, and postmerge tail extraction (`_ship_postmerge_phase`). Keep the merge loop, dual iteration-cap checks, `ci_fix_rebase_pending_head` persistence, and monitor-head refresh inline in `run_ship`.

## Approach

- Preserve the existing wire grammar:
  - Same `KEY=value` keys.
  - Same row order where callers may observe it.
  - Same JSON shapes.
  - Same exit codes.
- Keep CLI wrappers and `*_main` seams intact.
- Use frozen dataclasses for new result objects.
- Keep side effects in existing runtime paths; pure deciders return metadata only.
- Add direct unit tests for new decision/result helpers so tests do not need stdout scraping.
- Split pure decision from emission and from filesystem apply for postplan.
- For ship, keep `phase14` as a distinct loop-head path; deduplicate only the shared Flush+Push rebase pair. Do not extract the merge loop.
- **Stdout parity rule:** batch emission must mirror **per-branch** row order from today's code, not a single global segment template. Use per-branch append recipes (or golden captures) and lock full line order in smoke tests.
- **Review scout-prefix invariant:** after successful dispatch parsing, build a named `dispatch_scout_rows` tuple once from today's full post-dispatch stdout prefix (through the unconditional `PANEL_PRUNED_EMPTY` row) and prepend it into every downstream `ReviewCoreResult` except `description-empty` and `dispatch-failure`. No post-dispatch early return may omit this prefix.
- **Postplan path resolution:** `_postplan_decide` receives `design_tmpdir` (or a small frozen `PostplanPaths` value derived from it) so `touches`, `writes`, and `unlinks` are absolute `Path` values under the tmpdir without globals or cwd-relative ambiguity.
- **Postplan stdout assembly:** executor builds `PostplanResult.stdout_lines` from captured emit buffer plus `PostplanDecision.rows` using today's `StringIO` ordering: preserve trailing newlines on the captured buffer; append each decision row segment exactly once with no extra separators between segments.

## Failure modes

- A missed `_emit_kv` conversion can leave `review_core` partially batch-emitting and partially streaming.
- Applying a single global segment template will reorder keys and break `review_core_capture` / `review-and-fix` parsers.
- Building `dispatch_scout_rows` from only three scout keys drops `PRUNED_COMBOS` / `PANEL_PRUNED_EMPTY` and breaks prune-skipped consumers.
- Dropping `dispatch_scout_rows` on a post-dispatch early return mis-orders `THRESHOLD_REASON` and breaks scout-dependent consumers.
- Collapsing validation-exhausted tally-fail with post-voter tally-fail spuriously emits `VOTER_*` rows.
- Dropping duplicate post-common `FINDINGS_CLASSIFICATION_TSV_FILE` rows changes last-wins consumer behavior.
- Merging `_zero_findings_branch` incorrectly at only one call site drops classification/common/`VOTING_TALLY_FILE` on the other path.
- Using dispatch-derived `panel_mode` / `panel_shape` on description-empty or dispatch-failure breaks early-exit stdout contracts.
- Row order drift can break shell callers and `review_core_capture`.
- Putting filesystem mutations inside `_postplan_decide` breaks purity and confuses tests.
- Omitting rc `0`/`12`/`13` rows from `_postplan_decide` passes decide tests while breaking drafter wrapper and Gate B parsers.
- Leaving rc `0`/`12`/`13` touches only in the executor body leaves the ok path untestable and violates pure-decider acceptance.
- Omitting rc `10` non-KV rows from assembled `stdout_lines` passes touch-based tests while breaking orchestrator-visible output.
- Wrong `stdout_lines` join semantics (extra separators or dropped captured trailing newlines) breaks drafter wrapper and Gate B parsers.
- Omitting rc `10` inline-retry gating artifacts from `PostplanDecision` passes row tests while breaking orchestrator retry semantics.
- Omitting `design_tmpdir` / `PostplanPaths` from `_postplan_decide` forces globals or wrong-cwd touches.
- Running `postplan_emit_main` before pre-emit pause check changes pause semantics.
- Omitting non-`step2b` preamble scout clearing changes Gate B behavior.
- Collapsing postplan pause or print paths changes orchestrator-visible stdout or exit semantics.
- Folding `phase14` into Flush+Push rebase can add a stall point or wrong counter/handoff during conflict resume.
- Dropping phase14 success `phase="ci-initial"` write loses durable resume counters and breaks `test_phase14_flag_rebase_success_clears_handoff_and_conflict_files`.
- Moving `iteration += 1` into `_ship_rebase_phase` for `goto_rebase` can double-increment or break wait-only cap semantics.
- Returning from `_ship_rebase_phase` without a terminal result on stall lets the merge loop continue after a pre-rebase flush skip.
- Omitting `main_advanced` `phase="rebase"` pre-write diverges stall/resume metadata from today's code.
- Absorbing merge-loop extraction into this PR adds high-risk mechanical churn without pure KEY=value test seams for ship.
- Dropping caller-owned `phase="postmerge"` write on resume merged path loses durable state before postmerge breadcrumb.
- Adding monitor-head fields to main_advanced ci-initial write changes resume/grace behavior.
- `_ship_postmerge_phase` absorbing merge-result branches changes stall timing or drops durable `phase=merge` writes.
