**Problem.** The largest functions interleave pure decisions with `KEY=value` stdout emission, so the state machines and tallies cannot be unit-tested without scraping stdout.

**Evidence.**
- `python/ship.py:run_ship` (~749-line span), `python/review_pipeline.py:review_core` (~350), `python/design_lifecycle.py:failure_report_core` (~355, ~15 nested closures), `python/review_and_fix.py:_run_round` (~212), `python/agents.py:run_external_agent` (~191).
- Postplan deciders emit via `io.StringIO().write("POSTPLAN_RC=...")` interleaved with sentinel side effects (`python/design_lifecycle.py:3011`), so the decision can't be tested in isolation.

**Proposed change.** Per god-function, extract a pure core `(inputs) -> Result(rows, status, ...)` and a thin emit layer that prints `KEY=value`. Start with `run_ship`, `review_core`, and the design postplan deciders. Pairs with the typed-domain item so the cores return typed results.

**Out of scope / don't-touch.** Keep the `*_main`/`*_core` testability seam and the wire grammar. Refactor structure behind existing parity tests; do not change behavior.

**Acceptance.** Pure cores for the named functions are unit-tested without stdout scraping; emit layers are thin; parity/units green.

**Effort / risk.** Medium / medium. Incremental, one function at a time.

**Dependencies.** Blocked by the typed-domain-objects item (the review-path split consumes the `Finding` type). Wired via `/block-issue`.

## Proposed Design Outline

### Goals
- Split `review_core` into a pure `ReviewCoreResult` dataclass + thin emit layer so tests skip stdout scraping.
- Split `_shared_step2b_postplan_body` (postplan deciders) into a pure decision function + thin side-effect/emit layer.
- Decompose `run_ship` (777 lines) into focused helper sub-functions without changing `ShipResult` or `emit_result`.

### Non-goals
- Do not change wire grammar (KEY=value keys, JSON shapes, exit codes).
- Do not refactor `failure_report_core`, `_run_round`, or `run_external_agent` in this PR.
- Do not add new public CLI verbs or change behavior.

### Approach sketch
- `review_pipeline.py`: extract `_review_core_body()` returning a frozen `ReviewCoreResult`; move all `_emit_kv` calls to a thin `_emit_review_core_result()` wrapper at the end of `review_core`.
- `design_lifecycle.py`: extract `_postplan_decide()` returning `(rc, status, rows, sentinels)` tuple; thin `_shared_step2b_postplan_body` executes sentinels and prints rows.
- `ship.py`: extract `_ship_rebase_phase`, `_ship_merge_loop`, `_ship_postmerge_phase` sub-functions from `run_ship`; no emit changes since `emit_result` is already separate.
- Add unit tests for each pure core (no stdout capture needed).

### Surfaces in scope
- `python/review_pipeline.py` (`review_core`, new `ReviewCoreResult` dataclass)
- `python/design_lifecycle.py` (`_shared_step2b_postplan_body`, new pure-decision helper)
- `python/ship.py` (`run_ship` decomposed into phase helpers)
- `python/test_review_pipeline.py`, `python/test_design_lifecycle.py`, `python/test_ship.py` (new pure-core unit tests)
