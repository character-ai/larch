# [py-code-quality] Split pure logic from KEY=value emission in god-functions

**Problem.** The largest functions interleave pure decisions with `KEY=value` stdout emission, so the state machines and tallies cannot be unit-tested without scraping stdout.

**Evidence.**
- `python/ship.py:run_ship` (~749-line span), `python/review_pipeline.py:review_core` (~350), `python/design_lifecycle.py:failure_report_core` (~355, ~15 nested closures), `python/review_and_fix.py:_run_round` (~212), `python/agents.py:run_external_agent` (~191).
- Postplan deciders emit via `io.StringIO().write("POSTPLAN_RC=...")` interleaved with sentinel side effects (`python/design_lifecycle.py:3011`), so the decision can't be tested in isolation.

**Proposed change.** Per god-function, extract a pure core `(inputs) -> Result(rows, status, ...)` and a thin emit layer that prints `KEY=value`. Start with `run_ship`, `review_core`, and the design postplan deciders. Pairs with the typed-domain item so the cores return typed results.

**Out of scope / don't-touch.** Keep the `*_main`/`*_core` testability seam and the wire grammar. Refactor structure behind existing parity tests; do not change behavior.

**Acceptance.** Pure cores for the named functions are unit-tested without stdout scraping; emit layers are thin; parity/units green.

**Effort / risk.** Medium / medium. Incremental, one function at a time.

**Dependencies.** Blocked by the typed-domain-objects item (the review-path split consumes the `Finding` type). Wired via `/block-issue`.
