### FINDING_6: `_ship_rebase_phase` lacks pinned stall/return and caller-owned state contract
- **Reviewer(s)**: Cursor-Innovation, Codex-Generic
- **Severity**: important
- **Concern**: `_ship_rebase_phase` stall/return contract is unspecified. When pre-rebase `flush_logs_pre` is skipped for a disallowed reason, today's code writes terminal stall state, publishes snapshot, and returns `ShipResult(Outcome.STALLED, ...)`. Without a pinned helper return/raise contract, the merge loop can continue after a stall. Both current rebase branches increment `rebase_count` before later state writes; a helper that only mutates a local counter or writes terminal state can persist stale `REBASE_COUNT` or continue after a stall instead of returning terminal results before iteration/state writes.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Innovation: Specify `_ship_rebase_phase` returns a small result (for example `Outcome.OK | STALLED` plus detail) or re-raises/returns `ShipResult`; caller must immediately return on stall and must not bump `iteration` or write ci-initial state
  - From Codex-Generic: Require the helper to return a small result carrying updated `rebase_count` plus an optional terminal `ShipResult`/action, and require callers to assign the count and return terminal results before iteration/state writes; otherwise keep the block inline
