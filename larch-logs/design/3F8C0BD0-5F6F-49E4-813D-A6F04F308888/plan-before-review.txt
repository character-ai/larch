## Edge cases

- No coverage artifact remains a normal empty coverage summary.
- Valid `"proceed-partial"` disposition still produces `"part-of"` and skips the done rename.
- A stale artifact during teardown defaults to `"closes"` so the terminal rename is not lost.
- A stale artifact during final-report rendering removes only the optional coverage line.
- Stall teardown continues to use the stalled rename path without consulting coverage.
- Runs with `done_rename_applied` continue to skip disposition lookup.
- Catch only `ShipError`. Unexpected programming errors must still surface.

## Failure modes

- Catching too broadly could hide malformed state or coding defects. Use the named `ShipError` exception and narrow the guarded expressions.
- Moving disposition lookup outside its current predicates could validate coverage for runs that do not need a rename. Keep the lookup behind the existing eligibility checks.
- Returning an empty report line for errors outside `load_live_coverage(...)` could weaken trusted-artifact validation. Limit the report fallback to that call.
- Omitting the breadcrumb would make degraded teardown hard to audit. Verify the warning in the regression test.
