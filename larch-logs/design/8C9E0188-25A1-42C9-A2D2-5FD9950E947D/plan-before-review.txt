## Edge cases

- An override must replace a baseline key exactly once.
- Builders must preserve trailing newlines and deterministic ordering.
- Tests for missing keys must not receive those keys from canonical defaults.
- Tests for malformed, duplicate, injected, or symlinked wire files must continue constructing raw fixtures.
- Repeated parameterized tests must receive isolated directories and dictionaries.
- Paths containing spaces must remain valid test values.
- Piece 1 rebase conflicts must be resolved through its shared support API, without expanding this piece into CLI or runner migration.

## Failure modes

- Over-broad migration could make negative tests pass against unintended defaults.
- Divergent plugin-root keys could hide differences between design and implement consumers.
- Importing `tests.support.session` without the package marker could resolve an unrelated installed `tests` package.
- A helper that appends instead of replacing overrides could change first-match `KEY=value` behavior.
- A stale run-params shape could drift from production schema v3.
