- **Reviewer(s)**: Cursor-Arch

- **Concern**: Replacing bootstrap setup with `make_implement_tmpdir` can place seeded files under `tmp_path/impl` while tests still read `tmp_path`.

### FINDING_2: Session writer semantics for baseline, additive, and sparse keys are undefined
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation, Cursor-Pragmatic, Cursor-Requirements
- **Severity**: major
- **Concern**: A production-writer-only allowlist or default-merging implementation can reject required fixture keys such as `CURSOR_PRESENT`, `MODE`, and `REPO`, or inject baseline values into sparse fixtures such as `_write_minimal_state`, changing their inputs and coverage.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Document that implement `write_session_env` accepts any `_KEY_RE`-valid key for overrides (value hygiene only), while `write_design_source_env` stays restricted to `WRITE_DESIGN_ENV_KEYS`; for minimal fixtures, require omitting every implement baseline key before writing sparse overrides such as `REPO`+`MODE` only
  - From Cursor-Innovation: Define an explicit implement allowlist (at minimum WRITE_ENV_KEYS plus fixture-only keys such as CURSOR_PRESENT used by migrated tests) and document which keys are production-writer vs fixture-only.
  - From Cursor-Pragmatic: Keep _write_minimal_state as a raw two-line session-env write, or add an explicit carve-out: omit every implement baseline key and allow only non-writer test keys such as MODE via a documented sparse-fixture path. Do not route _write_minimal_state through the canonical default baseline.
  - From Cursor-Requirements: Require _write_minimal_state (and similar sparse fixtures) to pass omit= for every implement baseline key or keep them as raw session-env writes exempt from the shared writer refactor
  - From Cursor-Requirements: Document that overrides may add any safe KEY=value pair not in the baseline (including REPO MODE WORKFLOW_PATH LARCH_RUN_ID) and that invalid-key rejection targets malformed names or unsafe values, not production-writer allowlist exclusivity

### FINDING_3: Seed helper defaults must preserve dispatch bytes
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation, Cursor-Pragmatic
- **Severity**: minor
- **Concern**: Unspecified seed defaults can silently change dispatch or bootstrap inputs during mechanical migration.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Pin defaults in `session.py` to `## Plan\n` and `feature\n`, add optional `content=` to both seed helpers, and assert the literals in `test_foundation.py`
  - From Cursor-Innovation: Pin defaults to the current _session bytes: plan.txt is "## Plan\n" and feature-description.txt is "feature\n"; assert them in test_foundation.py.
  - From Cursor-Pragmatic: Pin defaults to ## Plan\n and feature\n for make_implement_tmpdir to match dispatch _session, and state that bootstrap sites with other bytes must call seed_plan or seed_feature_description with explicit content after tmpdir creation.

### FINDING_4: Design environment wire format must match production
- **Reviewer(s)**: Cursor-Arch, Cursor-Innovation
- **Severity**: minor
- **Concern**: The design environment helper does not specify production-compatible quoting and wire structure, risking divergence for spaced paths or production-writer tests.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Make `write_design_source_env` use the same `export` + `shlex.quote` emission as `session_env._export_line`, and cover a spaced `REPO_ROOT` in `test_foundation.py`
  - From Cursor-Innovation: Require the same wire shape as write_design_env_main: shebang, generator comment line, and export KEY=shlex.quote(value) rows in stable key order.
