# Step 8 bgjob cutover and inline-fallback removal

## Difficulty assessment

Confidence: high. The required lane and result protocol already exist. Direct inspection identified the active Agent path, obsolete constants, cutover point, and test surfaces.

This is HARD because it changes the Step 8 prompt contract, bgjob lifecycle, persisted-result validation, retry routing, and the only sanctioned inline recovery exception.

## Approach

1. Replace the default Step 8 Agent-tool procedure with `step-8-ci-fixer.sh`.
2. Start one identity-bound bgjob for the selected waterfall tier. While it runs, issue only identical documented `bgjob wait` calls.
3. After `DONE`, require `BGJOB_RC=0`, then consume the wrapper’s compact validated result envelope. Do not read CI logs, failure digests, fixer transcripts, or repository changes in the main-agent path.
4. Route `RESULT=reship` back through the Step 8 ship bgjob. Route `RESULT=retry-next-tool` to a fresh wrapper invocation, which selects the next untried tier. Route full waterfall exhaustion to `ci-fix-exhausted`.
5. Materialize architectural-invariant violation evidence at the canonical tmpdir path and bind it to the live run ID, `HEAD`, and input fingerprint before the lane receives it.
6. Delete the Agent-tool spawn flow, default-path `ci distill-log` flow, fixer-spawn sentinel, post-bail 10-attempt inline loop, and `fallback-attempts.count` routing.
7. Preserve the `LARCH_CI_FIXER=0` inline procedure and its 30-attempt budget without weakening its existing gates.

## Edge cases

- The ship handoff has no failed run ID.
- A default-branch failure uses a run ID distinct from the PR run.
- The selected vendor is unavailable before launch.
- A tier returns `retry-next-tool` after changing `HEAD`.
- A prior rounds file belongs to another run ID, `HEAD`, or input fingerprint.
- The bgjob registry is missing, dead, or stale.
- The merge result exists but disagrees with `fixer-status.env`.
- A result names the wrong tier or attempt.
- All configured tiers are exhausted.
- Invariant evidence is absent, unsafe, stale, malformed, or replaced by a symlink.
- The kill switch is enabled after delegated sidecars already exist.
- Fork and repository-unavailable handoffs must never enter either repair path.

## Failure modes

- Treat malformed or stale identity as operator-bail or tool failure. Never reuse the result.
- Treat nonzero bgjob completion as closed failure. Do not reinterpret it as a retryable typed result.
- Treat a missing compact result envelope as failure, even if repository changes or green CI suggest success.
- Do not fall back to main-agent edits when tier selection, evidence capture, launcher execution, or result validation fails.
- Do not route full waterfall exhaustion into stall recovery or the removed fallback counter.
- Keep the kill-switch inline budget independent from delegated tier attempts.
