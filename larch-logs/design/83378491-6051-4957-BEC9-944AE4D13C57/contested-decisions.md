### DECISION_1: Internal reuse pattern between rebase-checkpoint-probe.sh and phantom-probe-with-warn.sh
- **Chosen**: Library-based reuse via new `scripts/lib-phantom-probe.sh` (synthesis compromise) — both wrappers `source` the library and call a `phantom_probe_with_warn` shell function; each wrapper still emits exactly one `emit_breadcrumb` at its own entry; library function emits phantom KVs through the wrapper's already-initialized FD 3 stream.
- **Alternative**: Inline duplication of the phantom probe + warn + append-failure logic in both wrappers (Cursor sketch implicit choice); OR `rebase-checkpoint-probe.sh` invokes `phantom-probe-with-warn.sh` as a subprocess and merges its stdout KVs (Codex sketch explicit choice).
- **Tension**: Cursor's prose embeds phantom probe + warn logic directly inside `rebase-checkpoint-probe.sh` (no shared library, no subprocess call); Codex explicitly proposes `rebase-checkpoint-probe.sh` calls `phantom-probe-with-warn.sh` internally to "avoid duplicating append logic." Both extremes have downsides: duplication = two places to bug-fix; subprocess delegation = nested breadcrumb collision (or `--no-breadcrumb` flag) + extra fork/exec per macro site. Library pattern resolves both.
- **Impact**: Medium (correctness across two scripts; affects testability and how reviewer findings on phantom-probe behavior propagate).
- **Affected files**: scripts/rebase-checkpoint-probe.sh, scripts/phantom-probe-with-warn.sh, scripts/lib-phantom-probe.sh (new under synthesis call), scripts/test-rebase-checkpoint-probe.sh, scripts/test-phantom-probe-with-warn.sh.
