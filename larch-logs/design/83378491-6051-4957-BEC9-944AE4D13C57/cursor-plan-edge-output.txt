1. **[correctness]** [`scripts/rebase-push.sh:220-227`](scripts/rebase-push.sh) — The plan (`plan.txt` ~L43–44, L108, L269) tells the combined wrapper and offline harness to treat `REBASE_ERROR` as **stderr** on non-conflict failure; production `rebase-push.sh` emits `REBASE_ERROR` with `emit_kv` on the **quiet contract stream** (FD3), same as skip markers. Parsing only stderr yields empty errors and weak Step-18 bail copy. **Suggested revision:** Parse the captured rebase-push **contract output** (the same temp file used for `SKIPPED_*` / `CONFLICT_FILES`), update `test-rebase-checkpoint-probe.sh` case 6 stubs accordingly, and fix the SKILL pointer prose that still says “stderr” for exit 3.

2. **[correctness]** [`scripts/append-execution-issue.sh:85-88`](scripts/append-execution-issue.sh) — The plan’s append-failure path (`plan.txt` ~L15–16) assumes **`stderr`** carries the failure text for `PHANTOM_APPEND_WARN_ERROR`. This script surfaces failures with **`emit_kv FAILED` / `emit_kv ERROR`** (quiet contract), so stderr is often empty and the planned KV can be blank. **Suggested revision:** Parse append’s contract stream on non-zero exit, or merge captured stderr with parsed `ERROR=` from the child contract.

3. **[risk-integration]** [`Makefile:4-40`](Makefile:4-40) [`docs/linting.md:38-42`](docs/linting.md) — The plan (`plan.txt` ~L243–256) only defines `make test-rebase-checkpoint-probe` / `make test-phantom-probe-with-warn` and vaguely “wire into aggregate `test`”. This repo runs harnesses through **`test-harnesses-N` shards**, a partition guard, and a single long **`.PHONY`** inventory; targets not added there never run under `make lint` / CI. **Suggested revision:** Extend the mammoth `.PHONY` line and assign each new harness to exactly one `test-harnesses-*` prerequisite list per `docs/linting.md`.

4. **[correctness]** `plan.txt:36-43` `plan.txt:279-280` — Defensive `CONFLICT_FILES` fallback is specified when the line is missing, but not when **`git diff --diff-filter=U` is also empty** (half-open rebase edge, tooling regression). The wrapper could still exit **1** with an empty list and send a weak conflict payload. **Suggested revision:** Document a deterministic branch (treat as non-conflict failure with `REBASE_ERROR`, or hard-abort with explicit message) when the derived list is empty.

5. **[architecture]** [`lib-quiet.sh:105-111`](lib-quiet.sh:105-111) `plan.txt:49-63` — The plan repeatedly says parse `REBASE_OUTCOME` / `PHANTOM_*` from the wrapper’s **stdout**; after `larch_quiet_init`, machine-readable output is **`emit_kv` to FD3**, which only coincides with captured “stdout” when the capture sink was wired as FD1 at child init. **Suggested revision:** Align wording with existing SKILL guidance (“token-aware” contract stream / subshell capture) so implementers do not tee the wrong file descriptor.

6. **[security]** `plan.txt:15-16` `plan.txt:61-62` — `PHANTOM_APPEND_WARN_ERROR` is echoed into another `emit_kv` value without **newline or spoofing hygiene**; hostile or noisy subprocess text can break line-oriented KV parsing or inject token-looking lines. **Suggested revision:** Collapse internal newlines and strip leading `KEY=` patterns before emitting the secondary KV.

7. **[code-quality]** `plan.txt:171-184` — The Region-1 SKILL example nests a **```bash** fence inside an outer **```** block, which is invalid Markdown and risks a broken `SKILL.md` if pasted literally. **Suggested revision:** Use a single fenced `bash` block per call site (or prose + one fence) consistent with surrounding SKILL style.

8. **[code-quality]** `plan.txt:215-220` — DENYLIST edit claims “alphabetical-ish” order but lists **`rebase-checkpoint-probe.sh` before `phantom-probe-with-warn.sh`**, opposite strict basename order. **Suggested revision:** Reorder the two lines or relax the comment to avoid misleading reviewers.
