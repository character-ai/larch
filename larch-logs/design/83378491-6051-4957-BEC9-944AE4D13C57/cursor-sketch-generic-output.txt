After the probe, embed the same `append-execution-issue.sh` branches the SKILL currently shows for `STATUS=phantom` / `unknown`, including the secondary warning on append failure. At the top: `source` [`scripts/lib-quiet.sh`](scripts/lib-quiet.sh), `larch_quiet_init`, exactly one `emit_breadcrumb` of the form `→ rebase-probe: <step-prefix> <short-name>`, and a **terminal** block of `emit_kv` lines so the orchestrator can replace “parse `rebase-push` stdout then separately parse phantom output” with one parse pass. Preserve conflict semantics by emitting `REBASE_OUTCOME=conflict` and `CONFLICT_FILES=…` (from captured stdout, with the same defensive `git diff --name-only --diff-filter=U` fallback the macro documents) before any phantom work, and use an exit status aligned with today’s macro (so the Conflict Resolution Procedure and Step-18 bail paths stay behaviorally identical). The sibling `phantom-probe-with-warn.sh` is the same probe + warn + append-failure handling without `rebase-push`, for `2-post-dispatch` and `8-pre-bump` only.

**Tradeoffs and risks.** The main behavioral change is **always** probing after `1.r`; that is a deliberate uniformity trade (one extra sub-second dirty-tree check) against one wrapper shape everywhere. Centralizing M1–M3 + phantom in one script reduces Bash call count but concentrates failure modes: any bug in KV ordering (e.g. `SKIPPED_ALREADY_PUSHED` vs `SKIPPED_ALREADY_FRESH` precedence) or in exit-code mapping could regress skip semantics or conflict routing—harness cases listed in your acceptance criteria should lock those down. Bash 3.2 means avoiding modern bashisms in the new scripts while staying consistent with existing helpers (`check-phantom-dirty.sh` already uses `[[` and similar patterns). Finally, foreground-marker lint will apply to every new fence: missing banner/comment on any call site will fail CI even if the shell logic is correct.
