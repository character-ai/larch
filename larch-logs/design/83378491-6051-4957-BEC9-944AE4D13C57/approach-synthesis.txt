## Approach Synthesis

Cursor-Generic and Codex-Generic converge on the same orchestration shape; one implementation-internal tradeoff remains contested.

### Agreement (high confidence)

- **Two scripts**: `scripts/rebase-checkpoint-probe.sh` + `scripts/phantom-probe-with-warn.sh`, each with a sibling `.md` per the script-md-siblings rule.
- **`rebase-checkpoint-probe.sh` shape**: `lib-quiet.sh` at top → `larch_quiet_init` → exactly one `emit_breadcrumb '→ rebase-probe: <step-prefix> <short-name>'` → rebase via `scripts/rebase-push.sh --no-push --skip-if-pushed --keep-on-conflict [--base-remote $r --base-ref $b]` → branch on rc → on non-conflict success, run the phantom probe → terminal `emit_kv` tail. Optional `--base-remote <r>` / `--base-ref <b>` argv pass-through (forwarded to `rebase-push.sh` when present); caller passes them conditionally on `forked_target=true`.
- **KV grammar (terminal block)**: `REBASE_OUTCOME=ok|skipped|conflict|failed`, plus `SKIPPED_ALREADY_FRESH`, `SKIPPED_ALREADY_PUSHED`, `REBASE_ERROR`, `CONFLICT_FILES`, `PHANTOM_STATUS`, `PHANTOM_COUNT`, `PHANTOM_REASON`. The orchestrator parses once.
- **Conflict path unchanged**: emit `REBASE_OUTCOME=conflict` + `CONFLICT_FILES=<comma-list>` (from `rebase-push.sh` stdout; defensive fallback `git diff --name-only --diff-filter=U` for empty list); exit non-zero in a way the orchestrator's existing parse continues to route to the Conflict Resolution Procedure with `caller_kind=early_rebase`. No phantom probe runs on the conflict path.
- **`phantom-probe-with-warn.sh` shape**: `lib-quiet.sh` + `larch_quiet_init` + one `emit_breadcrumb '→ phantom-probe: <step>'` + `check-phantom-dirty.sh` invocation + conditional `append-execution-issue.sh` on `STATUS=phantom|unknown` (with secondary warning KV on append failure) + terminal `emit_kv` tail (`PHANTOM_STATUS`, `PHANTOM_COUNT`, `PHANTOM_REASON`, plus append-failure surfacing).
- **`1.r` uniformity**: the new wrapper always runs the phantom probe (sub-second cost) — the 1.r site gets a new `--step 1.r-post-rebase` probe; 4.r/7.r/7a.r reuse their existing step tokens.
- **SKILL.md surgery**: replace L119-156 Rebase Checkpoint Macro body with a thin pointer; replace the 4 macro call-site fences with single foreground-marked `rebase-checkpoint-probe.sh` invocations; replace 2 standalone phantom probe sites (`2-post-dispatch`, `8-pre-bump`) with `phantom-probe-with-warn.sh` invocations. The orchestrator-side M2 conflict banner + `caller_kind=early_rebase` bail + `STALL_TRACKING=true` non-conflict-fail prose stays in SKILL.md next to the new "parse KV" instruction (preserves user-visible behavior and Step-18 bail wiring).
- **Foreground markers**: both new scripts get DENYLIST entries in `scripts/lint-foreground-markers.sh`; every new SKILL.md fence carries the banner and per-anchor comment per `BASH_AUTHORING.md` §4.
- **Bash 3.2 portability**: no `declare -A`, no namerefs, no `mapfile`, no `${var^^}`/`${var,,}`, no `&>>`; positional args + `case`/`tr` for any case conversion.
- **Two test harnesses** (per Decision 2 of round 1): `scripts/test-rebase-checkpoint-probe.sh` + sibling `.md` and `scripts/test-phantom-probe-with-warn.sh` + sibling `.md`. Each Makefile target wired; `docs/linting.md` updated.
- **`scripts/test-implement-rebase-macro.sh` pivot**: today's literal-string `rebase-push.sh --no-push --skip-if-pushed --keep-on-conflict` assertion inside the macro section must move — after consolidation that string lives only in the wrapper (and possibly the sibling `.md`). Test must instead assert four canonical `rebase-checkpoint-probe.sh <step-prefix> <short-name>` invocations tied to `1.r`/`4.r`/`7.r`/`7a.r`, plus the two `phantom-probe-with-warn.sh` invocations at `2-post-dispatch`/`8-pre-bump`. Retain invariants (A)(B)(C)(E) and cross-doc pin (I).

### Contested decision

**Internal reuse pattern between the two wrappers** — `rebase-checkpoint-probe.sh` runs the same phantom probe + warn sequence that `phantom-probe-with-warn.sh` owns. How should that overlap be implemented?

- **Cursor (inline duplication)**: embed the `check-phantom-dirty.sh` invocation and `append-execution-issue.sh` branches directly inside `rebase-checkpoint-probe.sh`. `phantom-probe-with-warn.sh` repeats the same logic. Two places to fix bugs; two places to test.
- **Codex (subprocess delegation)**: `rebase-checkpoint-probe.sh` invokes `phantom-probe-with-warn.sh` as a subprocess on the non-conflict success path; parses its stdout KVs; merges them into the combined wrapper's KV tail. Single source of phantom-probe+warn logic; trivially testable in isolation. Subprocess overhead is negligible (mid-run, ~4 invocations).

**Synthesis call**: **Library-based reuse via `scripts/lib-phantom-probe.sh`** (compromise that resolves the tension cleanly). A new helper library exposes a `phantom_probe_with_warn` shell function. Both `rebase-checkpoint-probe.sh` and `phantom-probe-with-warn.sh` `source` the library and call the function. Benefits:
- Single source of phantom-probe + warn + append-failure logic (DRY satisfied).
- No subprocess overhead and no nested `emit_breadcrumb` collision (each wrapper still emits exactly one breadcrumb at its own entry).
- Library function emits its phantom KVs via `emit_kv` to the calling wrapper's already-initialized FD 3 stream; wrapper appends its own rebase KVs.
- Test isolation: harness can dot-source `lib-phantom-probe.sh` directly to unit-test the function without driving full wrapper paths.

Files newly affected by the synthesis call (beyond what's listed in the issue body):
- `scripts/lib-phantom-probe.sh` (new) + sibling `.md`.

### Risks and tradeoffs

- **KV ordering precedence** is the most error-prone surface: `SKIPPED_ALREADY_PUSHED` must be checked **before** `SKIPPED_ALREADY_FRESH` (per existing macro M3 prose — `rebase-push.sh` exits early on already-pushed before fetch). Wrapper must preserve that precedence in its KV emission.
- **Step-18 bail routing** depends on `STALL_TRACKING=true` being set by the orchestrator on `REBASE_OUTCOME=failed` and on M2 hard-failure paths in the Conflict Resolution Procedure. Wrapper does NOT set this — the orchestrator parses `REBASE_OUTCOME` and sets `STALL_TRACKING` itself. SKILL.md prose updates need to reflect that.
- **`1.r` added probe** is a deliberate behavior delta (uniformity vs. minimum-touch). User chose uniformity; tradeoff already booked.
- **Foreground-marker lint** fires on every new SKILL.md fence: banner + per-anchor comment must be added at all 6 new call sites (4 rebase-checkpoint-probe + 2 phantom-probe-with-warn).
- **Concentration of failure modes** — a wrapper bug regresses 4-6 sites simultaneously. Mitigation: the two new harnesses must cover every documented branch (acceptance criteria already enumerate these).
- **`lib-phantom-probe.sh` shellcheck** must pass without leaking `set -e` semantics to callers; functions must be defensive about already-initialized FD 3.
