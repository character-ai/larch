## Dialectic Resolutions

### DECISION_1: Internal reuse pattern between rebase-checkpoint-probe.sh and phantom-probe-with-warn.sh
**Resolution**: Library-based reuse via new `scripts/lib-phantom-probe.sh` — both wrappers source the library and call a shared `phantom_probe_with_warn` shell function; each wrapper still emits exactly one `emit_breadcrumb` at its own entry; library function emits phantom KVs through the wrapper's already-initialized FD 3 stream.
**Disposition**: voted
**Vote tally**: THESIS=2, ANTI_THESIS=1
**Thesis summary**: A sourced library fits the established `scripts/lib-*.sh` pattern (idempotent `LARCH_LIB_*_LOADED` guard, in-process FD 3 emit), keeps one quiet session and one breadcrumb per wrapper, and avoids subprocess/KV-merge plumbing that would otherwise be needed to reuse `phantom-probe-with-warn.sh` from inside `rebase-checkpoint-probe.sh`.
**Antithesis summary**: The remaining work after `check-phantom-dirty.sh` is narrow parse-and-append glue; ~30 lines duplicated across two wrappers is smaller than the maintenance burden of a new sourced helper with caller-owned `set -e`, quiet-FD, return semantics, and KV-naming contracts — focused harness assertions can catch drift.
**Why thesis prevails**: Two of three judges (Claude + Codex) voted THESIS; their rationale converges on the concrete `lib-quiet.sh` FD-3 / `LARCH_QUIET_PID` coupling argument — a sourced function inherits the parent wrapper's quiet session without spawning a second `larch_quiet_init` boundary or a duplicate breadcrumb. The Cursor judge's ANTI_THESIS vote on proportionality is acknowledged: yes, the warn-glue is small, but the same goal (avoid drift) is achieved with the library at lower marginal cost than the harness-only mitigation Defense B proposes, because library reuse mechanically prevents drift instead of detecting it after the fact. The plan therefore engages the antithesis directly: the library will be intentionally minimal (`phantom_probe_with_warn` function + `LARCH_LIB_PHANTOM_PROBE_LOADED` guard, sub-100 LOC), keeps phantom KV emission identical across both wrappers, and the new `test-rebase-checkpoint-probe.sh` / `test-phantom-probe-with-warn.sh` harnesses will independently exercise both wrapper entry points so the proportionality concern is bounded by tests rather than by sharing logic informally.
