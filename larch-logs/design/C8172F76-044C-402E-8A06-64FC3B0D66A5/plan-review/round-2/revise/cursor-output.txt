Reviewing the ship driver and related code so the revised plan reflects the accepted findings accurately.
## Plan

Implement the minimum fix in three layers: effective finalize normalization, writer-side backstop, and ship-driver committing reconciliation for recovery paths that skip intermediate flushes. Reconciliation runs on every terminal ship success path (PR-created, PR-created-draft, and pre-merge), and a failed correction push blocks success instead of leaving remote logs stalled.

## Approach

1. **Primary normalization fix (effective finalize everywhere).**
   - In `python/larch/state/_normalize.py`, add a helper that detects stale finalize-stall overlays after recovery.
   - Treat `finalize-state.sh` terminal stall fields as stale only when live `ship-pr-state.sh` shows later clean ship evidence:
     - PR number or PR URL is present, or merge result is terminal.
     - ship `PHASE` is not `stalled`.
     - ship-side `BAIL_REASON`, `IMPLEMENT_BAIL_REASON`, and non-zero `EXIT_CODE` are absent.
   - When that helper matches, build `fin_eff` by clearing only stale finalize terminal fields used for outcome choice: `STALL_TRACKING`, `STALL_STEP`, `PHASE=stalled`, `BAIL_REASON`, `IMPLEMENT_BAIL_REASON`, `EXIT_CODE`, and `BAIL_NEEDS_USER_INPUT`.
   - Keep raw `fin` solely for diagnostic emit keys such as `IMPLEMENT_FINALIZE_STALL_TRACKING`.
   - Wire stale detection before stall gating. Derive `effective_any_stall` from memory, ship, and session stall flags plus non-stale finalize contribution only. Do not let raw `fin_stall` force `any_stall=true` when the overlay is stale.
   - Inside `normalized_outcome_values` only, pass `fin_eff` (not raw `fin`) into every outcome predicate: `_stall_signal_is_terminal`, `_has_failure_signals`, `_phase_counts_as_stalled`, and `_is_healthy_pre_terminal_pr_snapshot`. Keep `_has_failure_signals` unchanged for other callers.
   - Keep `_finalize_phase_is_stale_stall_overlay` behavior for in-flight ship phases, but ensure it cooperates with the new recovery overlay helper rather than returning false whenever raw `any_stall` is true.

2. **Ship-time re-flush behavior.**
   - Keep `_publish_post_pr_terminal_snapshot` as the main pre-push correction path when a terminal snapshot is published.
   - Ensure it passes a context whose current PR fields are available to `flush_logs_pre(..., strict_final_report=True)`.
   - Do not add a second post-ensure PR log flush on the normal fresh PR path. `ship_merge.py` documents that this would move HEAD and re-trigger CI (#5217).
   - Do not change genuine terminal stall publishing when active ship failure signals remain.

3. **Committing reconciliation (recovery gap) with fail-closed push.**
   - Normalization and flush backstop only help when `flush_logs_pre` runs. After a stall snapshot commits `Outcome: stalled`, open-pr resume can reach success with zero intervening committing flush when CI returns merge on the first poll, or when a non-merge or draft PR path returns OK without entering the merge loop. `flush_logs_post` rewrites tmpdir only and never git-commits.
   - Add a narrow shared helper in `python/larch/implement/ship_pr.py` (or a small shared ship module) that centralizes:
     - committed-summary stalled-heading detection;
     - live recovery via `normalized_outcome_values` (`pr-created`, `pr-created-draft`, or `merged`) with no active ship failure signal;
     - one guarded `flush_logs_pre(..., strict_final_report=True)` plus push through existing push helpers, reusing the backstop and corrected normalization.
   - Gate strictly so fresh non-stale PR creation keeps the push-only `_post_ensure_flush_and_push` invariant. Run only when the committed run-dir summary is stalled and current ship/finalize evidence normalizes away from stall.
   - **Push failure is terminal for reconciliation.** Mirror `_post_ensure_flush_and_push` in `ship_merge.py`: treat `ShipError` from `push.push_branch` and any push result whose `status` is not exactly `"pushed"` as a stalled recovery outcome. Do not return `Outcome.OK` and do not call `merge.merge_pr` when the corrected summary commit did not reach the remote.
   - On strict flush skip/failure, preserve existing stall/terminal behavior rather than claiming a corrected committed log.
   - Invoke the helper from **both** success exit points that can leave a git-tracked stalled summary behind:
     - **Early PR-created / draft success:** immediately before the `ShipResult(Outcome.OK, ...)` return when `not working.merge or working.draft or ...` (the post-`ensure_pr` branch that never enters the merge loop).
     - **Pre-merge merge loop:** immediately before `merge.merge_pr(..., post_flush=False)` when monitor action is `merge` or `already_merged`.
   - If the helper returns a terminal `ShipResult`, propagate it instead of claiming PR-created or merged success.

4. **Run-log backstop.**
   - Add a narrow writer-side reconciliation helper in `python/larch/report/run_log_flush.py`, with optional heading/outcome rewrite helper in `python/larch/report/final_report.py`.
   - Run only during flush paths that already touch a run dir.
   - When tmpdir ship/finalize state exists, prefer full re-render through existing `write_final_report` / `normalized_outcome_values`.
   - When only committed manifest evidence is available, stay conservative:
     - allow `status=done` plus `pr_number` to reconcile toward `merged`;
     - avoid rewriting PR-only `status=partial` or `status=in_progress` stalled summaries unless ship state also has no active failure signal.
   - For manifest-only backstop, do not do heading-only rewrite. Either skip when tmpdir state is unavailable, or atomically update both the first non-empty heading line and the first matching `- **Outcome**: stalled` line so the committed summary is internally consistent. Assert rewritten summaries no longer contain stalled outcome text.
   - Fail closed in `strict_final_report=True` if reconciliation cannot write the required summary.

5. **Do not repair historical logs.**
   - Do not add a migration over existing `larch-logs/`.
   - The change affects future flushes and touched run dirs only.

## Edge cases

- **Finalize has stale `EXIT_CODE=4`.** Ignore it in `fin_eff` only when clean ship evidence proves later recovery.
- **PR exists but ship is actively failed.** Keep `stalled` or `bailed`; reconciliation must not run on early-return or pre-merge paths.
- **Merge result exists.** Prefer `merged` or existing force-merge labels over stall.
- **No PR or merge evidence.** Keep genuine terminal stall behavior unchanged.
- **Draft PR.** Preserve `pr-created-draft`; reconciliation must run on the early draft success return when committed summary is still stalled.
- **Non-merge PR-created success.** Same reconciliation hook as draft; do not rely on pre-merge-only placement.
- **Forked dry run and design-only.** Do not change their ordering unless existing tests require it.
- **Committed summary stalled but normalization already correct before success return.** Reconciliation should still fix the committed git copy once; tmpdir-only postmerge refresh is insufficient.
- **Reconciliation push fails after local commit.** Fail closed: return stalled recovery, do not claim PR-created/merged success, do not merge with remote still showing `Outcome: stalled`.
- **Manifest-only rewrite.** If heading and outcome bullet cannot both be made consistent, skip rather than leave mixed stall/non-stall text.

## Failure modes

- If final-summary rewrite fails during strict ship-time or reconciliation flush, return the existing recovery-failed skip so ship does not claim a corrected committed log.
- If reconciliation push fails (exception or non-`pushed` status), return terminal stalled recovery before any OK return or `merge.merge_pr`; remote must not merge ahead of a still-stalled run log.
- If manifest-only evidence is ambiguous, do not rewrite. A false `stalled` is bad, but a false `merged` is worse.
- If state files are malformed or missing, keep current fallback behavior.
- If reconciliation would reintroduce the fresh-run double-flush pattern, the guard must refuse and preserve #5217 behavior.
