## Numbered findings

1. **correctness** — `python/larch/lint/engine.py:648-658`, `python/larch/lint/lint_markdown_heading_fence_state.py:32-68`  
   The plan requires unchanged `python/markdown-heading-fence-state-baseline.json` bytes and delegating baseline I/O to `run_rule`, but the engine only parses generic or symbol-metric rows. Legacy rows use `file`, `pattern_name`, and `occurrence`. Those contracts cannot both hold on the current engine API. Revise the plan to add an occurrence-key baseline shape in Piece 1, or keep a minimal local baseline bridge and limit `run_rule` to scan/discovery.

2. **correctness** — `docs/linting.md:122`, `python/larch/lint/engine.py:546-547`  
   Occurrence ratchets intentionally omit line numbers. Engine generic baselines key on `(path, line, rule_id, message)`. Moving code without changing occurrence would keep legacy rows valid but stale generic rows or create false new findings. The plan must preserve occurrence-key identity, not generic line-key projection.

3. **correctness** — `python/tests/lint/test_lint_engine_equivalence.py:271-326`, `python/larch/lint/engine.py:195-224`  
   Replacing the equivalence adapter with engine-backed discovery will scan zero files unless fixtures are git-tracked or a `RecordingRunner` stubs `git ls-files`. The plan’s `MAY_UPDATE` equivalence section does not mention this harness change.

4. **correctness** — `python/larch/lint/lint_markdown_heading_fence_state.py:578-579`, `python/larch/lint/engine.py:496-507`, `python/tests/lint/test_lint_markdown_heading_fence_state.py:283-285`  
   Legacy malformed Python exits **2** via `ScanError`. Default `syntax_policy="fail"` yields a syntax finding and exit **1**. The plan says to preserve exit codes but does not specify how to keep exit **2** for parse failures.

5. **correctness** — `docs/linting.md:22`, `python/larch/lint/engine.py:461-486`  
   Suppression belongs on the regex declaration line. Engine inline suppression only inspects `finding.line` (the `.match`/`.search` call). `detect()` must keep legacy declaration-line pragma handling; empty-reason failures should remain `ScanError` from detect, not engine pragma handling alone.
