# [BUG] /implement Step 5 loop skips code-review batch flush on complete and cap-hit…

## Summary

The absorbed `/implement` Step 5 review loop skips the code-review batch flush on its two most common terminal paths, `complete` and `cap-hit`. As a result, run-root `code-review-tally.json` and `review-findings-full.jsonl` are never written for normal converged or capped panel runs. Every implement final summary and PR body since roughly larch v52.2.4 renders `Code review: N/A`, and every downstream analyzer that reads those two run-root files silently degrades.

## Original report

`/implement` Step 5 loop skips the code-review batch flush on its two most common terminal paths (`complete` and `cap-hit`), so run-root `code-review-tally.json` and `review-findings-full.jsonl` are never written. Every implement final summary and PR body since about v52.2.4 renders `Code review: N/A`, and downstream run-log analyzers lose the per-run acceptance signal. The regression came in with the Step 5 loop absorption in PR #6042 (issue #6024); the difficulty-tiers umbrella #5993 children built on the absorbed loop, so every difficulty-era run is affected and the #5992 calibration corpus loses its per-run accepted-count fallback source.

## Reproduction scenario

1. Run any `/implement` whose Step 5 panel converges normally or hits the round cap (the overwhelmingly common outcomes; 92% of runs complete in one round).
2. After the run-log flush lands, inspect the committed run directory `larch-logs/implement/<run-id>/`.
3. Observe that `round-1/` (and `round-2/`) artifacts exist, but run-root `code-review-tally.json` and `review-findings-full.jsonl` are absent.
4. Observe the final summary comment and PR body render `- **Code review**: N/A` instead of the accepted-count line.

A concrete committed example is `larch-logs/implement/1FA74504-BB66-41A8-86CB-731D2870A139/` (the #5992 run, larch v52.3.0, merged cleanly after 2 review rounds): it has full `round-1/` and `round-2/` artifacts and no run-root tally or findings JSONL.

## Expected behavior

Every Step 5 loop exit that ends the review phase flushes the code-review batches, so `larch-logs/implement/<run-id>/code-review-tally.json` and `review-findings-full.jsonl` exist for converged and cap-hit runs, and final summaries and PR bodies render lines like `Code review: 1/2 accepted`, as they did at larch v52.2.3.

## Observed behavior

- All 20 implement runs flushed on 2026-07-03 (larch v52.2.8 and v52.3.0) render `Code review: N/A`; runs flushed on 2026-07-02 at v52.2.3 render real values (`1/1 accepted`, `2/2 accepted`, `1/2 accepted`).
- Post-regression committed run dirs lack both run-root files while containing complete per-round artifacts.
- No warning or execution issue surfaces, because the flush wrapper swallows all exceptions and the two terminal paths never call it at all.

## Root cause analysis

In `python/larch/review/review_and_fix.py`, the step5 loop calls `_flush_review_batches_for_result` on the stall path (line 733), the unknown-status round-failed path (line 730), the `self-review-required` path (line 642), and the past-cap resume paths (lines 600 and 619). The `complete` terminal path (line 738) and the `cap-hit` terminal path (lines 735-737) emit the step5 envelope and `return 0` without flushing. Those two are the normal success exits, so virtually all healthy panel runs skip the flush.

The regression arrived with the Step 5 loop absorption in PR #6042 (issue #6024), which introduced `_flush_review_batches_for_result` and the loop-terminal branches; the pre-absorption flow flushed through a different call chain. The difficulty-tiers PRs #6064, #6122, and #6150 (umbrella #5993) built on the absorbed loop and inherited the gap rather than causing it.

Two aggravating factors:

- `_flush_review_batches_for_result` (line 524) wraps the flush in `contextlib.suppress(Exception)`, so even a reachable-but-failing flush would be invisible.
- `final_report.py:686` derives the Code review line from ship-handoff key `CODE_REVIEW_LINE`, which has no producer anywhere in the repo, with fallback to run-root `code-review-tally.json`; with the fallback file missing, the line is always `N/A`.

## Evidence

- `python/larch/review/review_and_fix.py:730-739` at HEAD `44cc1e1fb`: `stall` and round-failed branches flush; `cap-hit` (735-737) and `complete` (738) do not.
- Flush call sites confirmed by grep: lines 600, 619, 642, 730, 733 only.
- Empirical bisect from committed run logs: `larch-logs/implement/EA8219BE-7FA8-4610-B810-F9CA3A152B23` (v52.2.3, `1/1 accepted`), `A8EB5F44-C628-444B-9A28-72CC056C2F9C` (v52.2.3, `2/2 accepted`), `DA337AAF-4727-47E0-9727-731154C779F2` (v52.2.3, `1/2 accepted`) all have both run-root files; `1FA74504-BB66-41A8-86CB-731D2870A139` (v52.3.0) and `008C3B6D-D2EC-40BA-9651-CBCD2B9A4F74` (v52.2.8) render `N/A` and lack both files. All 20 implement final summaries committed 2026-07-03 show `N/A`.
- The flush machinery itself is healthy, verified by local replay against a copy of the committed run dir `1FA74504-BB66-41A8-86CB-731D2870A139`: `python3 python/cli.py review compose-findings --implement-tmpdir <copy> --issue 0 --output <copy>/review-findings-full.jsonl` returned `COMPOSED=true`, `FINDINGS_TOTAL=4`, `MODE=jsonl` against the new round-scoped layout, and calling `larch.review.batch_report.flush_review_batches(impl_tmpdir=<copy>, run_id=..., rounds=2, ...)` wrote `larch-logs/implement/<run-id>/code-review-tally.json` and `review-findings-full.jsonl` correctly.
- `command grep -rn 'CODE_REVIEW_LINE' python/ skills/ scripts/` shows only the consumer at `final_report.py:686`; no producer exists.
- `--self-review` runs are unaffected: `write_self_review_tally` (`review_and_fix.py:1005`) writes the tally through a separate path, and its own warning text at `review_and_fix.py:1074` ("final report may fall back to Code review: N/A") confirms the run-root tally is the intended contract.

## Affected files

- `python/larch/review/review_and_fix.py` — the step5 loop with the two non-flushing terminal paths (`complete`, `cap-hit`) and the exception-swallowing wrapper.
- `python/larch/review/batch_report.py` — `flush_review_batches` / `_compose_review_findings_output`; healthy, but its soft-skip return paths deserve a surfaced warning.
- `python/larch/report/final_report.py` — consumer whose `Code review` line falls back to the missing run-root tally (line 686).
- `python/larch/git/pr_body.py` — renders the same line into PR bodies.
- Degraded downstream consumers of the missing run-root files: `python/larch/issue/audit_runs.py` (lines 586 and 661: step5 validation and tally read), `python/larch/issue/rejected_analysis.py`, `python/larch/issue/_ground_truth.py`, `python/larch/report/review_phase_detail.py`, `python/larch/report/gc_run_logs.py`, `python/larch/calibration/calibration_replay.py`, and `python/larch/calibration/difficulty_calibration.py` (the #5992 analyzer's implement JSONL fallback source). The last one matters most: it starves the difficulty-tiers umbrella #5993 calibration corpus of per-run accepted-count signal for exactly the tiered runs it needs, though `round-*/findings-classification.tsv` still covers the analyzer's primary path.
- `python/tests/review/test_review_and_fix.py` — home for the missing regression coverage.

## Suggested fix(es)

1. Call `_flush_review_batches_for_result` on the `cap-hit` and `complete` terminal paths in the step5 loop (`review_and_fix.py:735-739`), before the envelope emission, mirroring the stall path.
2. Replace the blanket `contextlib.suppress(Exception)` in `_flush_review_batches_for_result` with a logged warning (or an execution-issue append) so future flush failures surface instead of vanishing.
3. Add a regression test in `python/tests/review/test_review_and_fix.py` asserting that a converged (`complete`) loop exit and a `cap-hit` loop exit leave `larch-logs/implement/<run-id>/code-review-tally.json` and `review-findings-full.jsonl` populated.
4. Optional cleanup: either produce `CODE_REVIEW_LINE` in the ship handoff or drop the dead `_read_kv` branch at `final_report.py:686` so the derivation path is the single documented source.
