## Goal

Prevent tests, fixtures, development probes, and reporter simulations from creating or mutating real GitHub issues without explicit live-run authorization.

Cover both known filing choke points:

- `python3 python/cli.py issue create-one`
- `scripts/file-failure-report-cross-repo.sh`, including create, comment, and reconciliation mutations

Keep dry-run and local report composition available without authorization.

## Approach

1. Define one authorization contract for GitHub issue mutations.
   - Use config-owned wire literals and refusal statuses.
   - Require explicit evidence from the invoking live driver. Do not infer authorization from the current directory, repository shape, run ID alone, or the presence of GitHub credentials.
   - Support session-backed authorization for `/design` and `/implement`.
   - Support an explicit operator-invoked context for `/issue` and the dev-only audit flow.
   - Make refusal distinct from GitHub, redaction, validation, and network failures.

2. Persist the live-run authorization key through the guarded session writers.
   - Add the key to both `/implement` `session-env.sh` and `/design` `source-env.sh`.
   - Preserve it on legitimate refresh and resume paths.
   - Validate it as a strict boolean.
   - Do not accept an arbitrary ambient value as sufficient evidence. Mutation callers must explicitly identify their context file or operator-invoked route.

3. Gate `issue create-one` immediately before its first mutation-capable path.
   - Parse the authorization input with the existing CLI arguments.
   - Keep `--dry-run` usable without authorization.
   - Refuse before repository lookup, label lookup, temporary body creation, or `gh issue create` when a non-dry-run call lacks valid authorization.
   - Emit stable refusal KVs and a distinct non-zero exit code.
   - Apply the same gate to the legacy `--json` fallback create path and orphan rollback close path because they share one authorized invocation.

4. Gate the cross-repository stall-report helper before any GitHub operation.
   - Require the live mutation context for create, duplicate-comment, dedup lookup, and reconciliation-related calls.
   - Emit a designated refusal status and reason without calling `gh`.
   - Keep `--dry-run` validation offline.
   - Thread the context explicitly from `/design` and `/implement` reporter code rather than relying on inherited process state.

5. Update every legitimate caller of the guarded boundaries.
   - `/design` terminal and salvage reporting passes its guarded `source-env.sh`.
   - `/implement` stall recovery passes its guarded `session-env.sh`.
   - OOS and scope-disposition filing pass the active `/implement` context.
   - `/issue` and the dev-only audit skill mark their direct, operator-requested filing calls explicitly.
   - Inventory all repository call sites for both choke points. Do not leave a caller that silently degrades to an unauthorized create attempt.

6. Make the Python test environment deny real issue mutations by default.
   - Set the test-only denial control in the autouse isolation fixture.
   - Ensure denial wins over inherited live-session state. This protects test runs launched from inside an active `/design` or `/implement`.
   - Tests of successful filing must use injected runners, monkeypatches, or stubbed `gh` processes and opt into only the narrow simulated mutation under test.
   - Add a subprocess regression so the protection does not depend only on an in-process monkeypatch.

7. Document the outbound mutation boundary and refusal contract in the security policy and helper contract.

## Edge cases

- A valid `LARCH_RUN_ID` without the authorization key must refuse.
- An authorization key inherited through ambient environment without the explicit context argument must refuse.
- A context file outside the expected session root, a symlink, a non-regular file, a malformed boolean, or a mismatched run identity must refuse.
- Test denial must override a valid parent session context.
- `--dry-run` must not require authorization and must make no `gh` calls.
- Dedup matches must not post comments without authorization.
- Create success followed by ID lookup failure may run rollback close only because the original invocation was already authorized.
- Reporter refusal must produce a local fallback artifact and must not retry through another mutation route.
- Resume and environment refresh must retain authorization only through the trusted writer path.
- Operator-invoked authorization must be explicit at the direct skill command, not inferred from TTY state or credentials.

## Failure modes

- If a legitimate caller omits authorization, fail before GitHub access and emit the designated refusal fields.
- If session evidence cannot be read or validated, treat it as unauthorized.
- If a helper returns the refusal status, preserve that reason through reporter normalization and fallback output.
- If the test isolation fixture is absent from a subprocess, the boundary-level authorization check must still refuse.
- Do not convert refusal into a fail-open dedup result or a generic create retry.
- Do not let fixture-authored state alone suppress the test default-deny guard.

## Testing strategy

Run only the focused changed-file tests and harnesses:

- `python3 -m pytest python/tests/core/test_config.py`
- `python3 -m pytest python/tests/state/test_session_env.py`
- `python3 -m pytest python/tests/issue/test_issue_create.py`
- `python3 -m pytest python/tests/design/test_design_lifecycle.py`
- `python3 -m pytest python/tests/state/test_stall_recovery.py`
- `bash scripts/test-file-failure-report-cross-repo.sh`

Also run changed-file lint and type checks through the repository’s documented focused Python lint path. Verify the shell helper with the Bash 3.2 and shell lint targets applicable to that file.

The key regression assertion is process-level: invoke each filing boundary without authorization while a real-looking repository and inherited live session are present, then prove the stub log contains no `gh` invocation.
