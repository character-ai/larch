Remove FILES_COUNT from /design plan-size soft-trigger detection

In `/design` plan-size soft-trigger detection (Step 2b.5, `skills/design/scripts/check-plan-size.sh`), `FILES_COUNT` is currently one of three metrics that can fire the soft trigger, alongside `PLAN_LINES` and `DIFF_LINES`:

```
Plan Size — Soft Trigger

┌─────────────┬───────┬────────────┐
│   Metric    │ Value │ Threshold  │
├─────────────┼───────┼────────────┤
│ PLAN_LINES  │ 119   │ soft > 250 │
│ DIFF_LINES  │ 280   │ soft > 600 │
│ FILES_COUNT │ 9     │ soft > 8   │
└─────────────┴───────┴────────────┘
```

Remove `FILES_COUNT` completely as a consideration — it is irrelevant and causing false positives. A plan touching 9 small files is not architecturally "large"; what matters is the actual line counts of the plan and projected diff.

## Scope

- Remove `FILES_COUNT` from the soft-trigger evaluation in `check-plan-size.sh`.
- Remove `FILES_COUNT` from the displayed soft/hard trigger tables in `/design` Step 2b.5 output.
- Update related tests / harness assertions if any pin the metric.
- Keep `PLAN_LINES` and `DIFF_LINES` thresholds unchanged.
- Hard-trigger logic: remove `FILES_COUNT` from hard-trigger evaluation too if it is part of it, on the same rationale.

## Out of scope

- Threshold tuning for `PLAN_LINES` / `DIFF_LINES`.
- Adding new metrics.
