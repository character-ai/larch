## Approach

Add a shared **YES-vote severity distribution** path next to the existing voter agreement path.

- Reuse `HIGH_SEVERITIES = frozenset({JudgeSeverity.blocker.value, JudgeSeverity.major.value})`.
- Carry optional severity data in voter rows with a **fixed positional contract** (see below).
- Count only `YES` votes for severity distribution.
- Count valid severities by enum value: `blocker`, `major`, `minor`, `nit`, `uncertain`.
- Treat `uncertain` as a **valid non-high** bucket included in `valid_yes_severity_count` (same spirit as points logic: it is a real judge signal, not absence of severity).
- Map empty strings, invalid tokens, and absent severity on YES votes to **Missing Severity**, excluded from `valid_yes_severity_count`.
- Compute `high_rate = (blocker + major) / valid_yes_severity_count`.
- Set `uncalibrated = true` only when `high_rate > high_severity_threshold` (strict `>`).
- Return `high_rate = None` and `uncalibrated = false` when no valid YES severity exists.
- Append severity scoreboards immediately after **every** agreement scoreboard render site (main tally loops and degraded/zero early-return paths).
- Mirror agreement global rollup: panel table from raw rows; global table from `_global_rows(rows)`.
- Do not change voting decisions, quorum, point awards, TSV schemas, or existing agreement table columns.

### Positional severity contract

`voter_severities[i]` must align with `voter_votes[i]` **before** label filtering:

- Live tallies and TSV ingestion both pass a **three-element** severity list for slots 1..3.
- Use `""` for absent/dead slots; never pass variable-length lists from `_votes_and_severities_for_item`.
- In `voter_agreement_row_from_panel`, when building each voter dict from `(label, vote)` at index `i`, attach `"severity": voter_severities[i]` when `voter_severities` is provided.
- `voter_agreement_rows_from_tsv` always supplies `voter_severities=[row.get(f"v{pos}_severity") or "" for pos in (1,2,3)]` alongside the existing three-slot `voter_votes` list.
- When `voter_votes` is empty (MainAgent adjudication with `tally_voter_file` set), omit `voter_severities` or pass `None`; never pass a three-element list against an empty `voter_votes` list.

## Edge cases

- **Neutral panels:** stay excluded because existing agreement row eligibility excludes them.
- **Single parseable voter:** stays excluded from rows because agreement is undefined.
- **YES without severity:** count as missing severity, not high or low; excluded from `valid_yes_severity_count`.
- **YES with `uncertain`:** count as valid non-high bucket; included in denominator.
- **NO with severity:** ignore for severity distribution entirely.
- **Invalid severity token:** count as missing severity on YES votes.
- **No valid YES severities:** render `n/a` high rate and `uncalibrated = false`.
- **Threshold equality:** do not flag at exactly `0.90`; flag only above it (e.g. 9 blocker + 1 uncertain → 90.0% → not flagged).
- **Degraded slot alignment:** empty middle slots keep `""` severity at index 2; never compress lists.
- **Legacy code-review path (no `--voter-tools`):** when `cells` has fewer than three entries, pad `voter_severities` to three elements with the same index rule as `voter_votes` (`cells[pos - 1][2] if pos - 1 < len(cells) else ""`); never pass `len(cells)`-length severity lists into `voter_agreement_row_from_panel`.
- **MainAgent plan-review path (`tally_voter_file` set):** `voter_votes` stays `[]`; omit `voter_severities` (or pass `None`) so the length guard does not fire.
- **Zero/degraded tally paths:** still emit paired severity scoreboards (empty tables acceptable).

## Failure modes

- Live tally can diverge from committed TSV analysis if severity is collected with variable-length lists or wrong index alignment. Mitigate via the three-slot positional contract in both live tallies and TSV ingestion, and via explicit `three_slot` vs legacy padding branches in `review_tally.py`.
- Legacy `review_tally.py` using `[cell[2] for cell in cells]` when `cells` is shorter than three entries triggers `ValueError` on the length guard or misaligns severities versus padded `v1`/`v2`/`v3` TSV columns. Mitigate by mirroring the existing `voter_votes` padding branch for `voter_severities`.
- `plan_review_tally.py` passing a three-element `voter_severities` when `voter_votes=[]` on the MainAgent path triggers `ValueError` and breaks degraded adjudication. Mitigate by gating severity collection and kwarg passing on the same `eligible > 0 and not tally_voter_file` guard as `voter_votes`.
- `write-tally` can reject the new code-review heading unless `_ALLOWED_CODE_REVIEW_HEADERS` is updated.
- Forgetting `plan_review_round.py`, zero-judge code-review paths, or zero-judge tests leaves acceptance gaps where `voting-tally.md` lacks severity sections or regressions go undetected.
- Global severity table can mislead if it aggregates per-panel rows instead of `_global_rows` rollup.
- Offline harness using a single `grep -Fq '## Voter Severity Scoreboard'` can pass when only the panel section remains and global rollup is dropped. Mitigate by requiring count `>= 2` plus anchored greps after `## Agreement Table` and `## Global Voter Agreement`.
- A low-sample voter can be flagged from a small number of YES votes. Acceptable for this phase unless a later design adds a minimum severity vote threshold.
