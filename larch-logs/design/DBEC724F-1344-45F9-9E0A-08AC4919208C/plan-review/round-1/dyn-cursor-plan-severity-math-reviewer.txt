## Findings

### 1. `correctness` — `python/plan_review_tally.py:662-679`

**Concern:** The plan allows reusing `_votes_and_severities_for_item` for severity passed into agreement rows. That helper skips dead voter slots, while `voter_votes` in `_render` always emits three fixed slots. On degraded two-judge panels, severity indices will not match vote indices.

**Suggested revision:** Build per-voter severity in the same three-position loop as `voter_votes` (lines 665-668). Do not pass `_votes_and_severities_for_item` output into `voter_agreement_row_from_panel`.

### 2. `correctness` — `plan.txt:10-11`, `python/review_types.py:56-61`

**Concern:** Valid calibration buckets are listed as four levels only. `uncertain` is a real `JudgeSeverity` value accepted by `valid_panel_severity`, but it is absent from the plan's bucket list and edge cases.

**Suggested revision:** Treat only `blocker`, `major`, `minor`, and `nit` as valid calibration buckets. Count `uncertain` as Missing Severity and exclude it from the `high_rate` denominator. Add a unit test.

### 3. `risk-integration` — `skills/voter-calibration/scripts/voter-calibration.py:102-103`

**Concern:** The global severity table must use the same `_global_rows(rows)` preprocessing as global agreement. The plan does not state this explicitly.

**Suggested revision:** Mirror the agreement render path: `compute_voter_severity_distribution(_global_rows(rows), ...)`.

### 4. `architecture` — `python/voting.py:129-159`

**Concern:** The plan does not define how `voter_severities` aligns with `voter_votes` when optional severity is added to row builders.

**Suggested revision:** Fix the contract as index-parallel to `voter_votes` (length 3 for positional TSV slots). TSV ingestion should always supply three severities from `v{pos}_severity`.

## What the plan gets right

- **YES-only counting** (plan.txt:9, 86-88, 117-118) matches the existing points helper pattern in `accepted_finding_points_from_severities` (`python/voting.py:506-513`), which skips non-YES votes before severity math.
- **`HIGH_SEVERITIES`** reuse (plan.txt:7-8, 34) matches `python/voting.py:80`.
- **Missing/invalid severity** excluded from `high_rate` denominator (plan.txt:11-14, 117-120) prevents empty or bad tokens from inflating high rate.
- **`review_tally.py`** wiring via existing `cells` tuples (plan.txt:63-64) is aligned; severity is already at index 2 in the tally loop (`python/review_tally.py:686-696`).
- **Parity test strategy** (plan.txt:98-111) mirrors existing agreement tests in `python/test_review_tally.py:540-550` and `python/test_plan_review.py:1411-1422`.
