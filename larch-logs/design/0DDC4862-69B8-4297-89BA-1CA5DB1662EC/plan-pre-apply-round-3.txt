## Approach

Implement the approved narrow fix.

- Treat `voting write-tally` nonzero exits as observable warnings, not Step 5 blockers.
- Persist `stderr` and `stdout` for the tally subprocess to `code-review-tally.flush.err`.
- Stage the same sidecar into the run-root tree so it ships with committed run logs. Create the run-root directory first, and point the Warnings text at the run-root path.
- Keep observability fail-open: a sidecar or Warnings write error must not turn a tolerated tally failure into a Step 5 exit.
- Remove stale tally sidecars after a later successful tally write.
- Keep the root-cause mechanism out of scope until a live run captures the error.
- Derive `Code review` from `review-findings-full.jsonl` when `code-review-tally.json` is absent, reusing one shared counting core rather than a second copy.
- Keep the self-review path recoverable: emit `phase: code-review` records so the fallback can reconstruct real self-review counts.

## Edge cases

- Nonzero `write-tally` with empty stderr and stdout still writes a sidecar with the rc.
- Stale `code-review-tally.flush.err` files are removed after a successful tally write.
- Malformed JSONL lines in `review-findings-full.jsonl` are ignored, matching the shared counting core.
- The fallback only applies to `code-review-tally.json`.
- Self-review emits one JSONL row per accepted or rejected finding, so the derived ratio matches the markdown counts exactly.
- A present-but-empty `review-findings-full.jsonl` renders `N/A`, not `0 findings`, because it cannot prove a review ran. Self-review runs emit `phase: code-review` records to preserve nonzero counts; genuinely zero-finding self-review runs with an absent tally fall back to `N/A`.

## Failure modes

- If run-root sidecar writing fails, the tmpdir sidecar and execution-issues entry may still capture the failure.
- Observability writes are fail-open: a sidecar or `execution-issues.md` append error is suppressed so a tolerated tally failure never becomes a Step 5 exit.
- If the live root cause is before the Python subprocess returns, this change still captures the rc and any wrapper output.
