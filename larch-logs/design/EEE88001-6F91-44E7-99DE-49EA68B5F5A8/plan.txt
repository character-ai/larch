## Approach

Each item is a surgical change touching a single primary surface. Item A is a harness-only assertion strengthening (~10 LOC). Item B is a function extraction + one new caller — extraction is a structural-only refactor for the existing zero-findings site (~62 LOC moved into a function body), and the new caller adds ~10 LOC of branch-and-call. Item C is a single-line doc edit plus a brief note on `aggregator-empty-merge.stderr`. The `agg-zero` test rewrite is ~15 LOC swapped in place plus a small dispatch-voters tracking stub change (~5 LOC).

Item B's extract-then-add-caller pattern was chosen over inline-duplication because the body is ~62 lines (well over the "three similar lines" rule-of-thumb) and the two call sites differ in zero parameters (both emit `REVIEW_CORE_STATUS=zero-findings`). It was chosen over a post-aggregator-only short-circuit reorganization because deferring the pre-aggregator branch behind aggregator would force aggregator to run on zero-findings rounds — wasting work and changing existing semantics. The extraction preserves the pre-aggregator efficient path verbatim.

Reusing `REVIEW_CORE_STATUS=zero-findings` (instead of a new `aggregator-empty-merge` value) keeps downstream wrappers in `skills/review-and-fix/` and `/implement` Step 5 unchanged — both already recognize `zero-findings` as a clean terminal status. The cost is a small loss of telemetry resolution (operators cannot distinguish "no findings emitted by panel" from "panel emitted findings but aggregator merged to zero"). That distinction is recoverable from `voting-tally.md` and `aggregator-dispatch.env` if needed for diagnostics.

No production logic in `dispatch-plan-review-panel.sh`, `dispatch-code-voters.sh`, or `aggregate-findings.sh` is touched. Item A's harness already covers the wiring contract; Item B's skip is upstream of the dispatcher; Item C is doc-only.

## Edge cases

- **Aggregator returns `REASON=ok` with `MERGED_COUNT>0`**: existing path unchanged (proceeds to voter dispatch + tally).
- **Aggregator returns `REASON=ok` but `MERGED_COUNT` key is absent from KV stream** (older aggregator binary, override, schema drift): the new branch's strict `"$aggregate_merged_count_raw" == "0"` test fails because the captured value is the empty string, so behavior falls through to the existing voter dispatch path (graceful degrade to pre-fix).
- **Aggregator returns `REASON=ok` with `MERGED_COUNT="0"` but `findings.md` is missing or non-empty without an attestation line**: routes to the empty-merge branch (the branch keys off `REASON` + `MERGED_COUNT` only, not file content). This matches the aggregator contract — `REASON=ok && MERGED_COUNT=0` is the attestation-only success case per the validator. If a future aggregator change emits `ok && 0` without writing attestation, the symptom would be an empty voting-tally with no actual review — visible but not catastrophic.
- **`aggregate_reason` is `validation-exhausted`**: the existing branch at line 543 still wins (it precedes the new branch). No interaction.
- **Pre-aggregator zero-findings path** (line 453, `findings_count == 0`): after extraction, behavior is byte-for-byte identical; the function call site is `emit_zero_findings_branch` with no argument.
- **Item A harness assertion**: when the production code is correct, both `cursor-plan-${a}` and `codex-plan-${a}` rows are present and carry `fallback_group=plan-${a}`. The `jq -s -e` form slurps the ndjson into an array, collects matching rows, and requires `length == 2` AND `all(.[]; .fallback_group == $fg)`. An empty selector match-set (slot rename or missing row) trips `length == 2` and fails the assertion. A mismatched `fallback_group` value trips the `all()` predicate and fails.

## Failure modes

1. **Function-extraction subtle behavior drift in `review-core.sh`** — extracting 62 lines into a function exposes shell-variable scope issues (e.g., `panel_manifest`, `collector_results_file`, `not_substantive_slots`, `scout_status`, `dynamic_slots`, `static_slot_count`, `panel_mode`, `panel_shape`, `ROUND_NUM`, `MODE`, `SESSION_ENV_PATH`, `IMPLEMENT_TMPDIR`, `CURSOR_AVAILABLE`, `CODEX_AVAILABLE`, `TALLY_VOTES_SH`, `REVIEW_TMPDIR`, `flush_round_log` invocation, `record_findings_classification_round`, `copy_to_parent`, `emit_tally_with_failure_isolation`). All of these are read by the existing body but defined in the outer script. Earliest warning signal: `test-review-core.sh` zero-findings tests fail with shell unbound-variable errors under `set -euo pipefail`. Mitigation: extract as a regular bash function (not subshell) so all outer-script variables remain in scope; do NOT introduce `( ... )` subshell isolation.

2. **`MERGED_COUNT` parsing fails on present-but-malformed value** — `kv_get` is the canonical KV parser used elsewhere in the file and returns the raw string after `=`. Trailing whitespace or unusual formatting would make `"0"` comparison fail and route to voter dispatch. This is the safe failure direction (no skip when uncertain). Earliest warning signal: the new test's empty-merge assertion still launches voters in spite of the stub emitting `MERGED_COUNT=0`. Mitigation: re-use `kv_get` (already imported) without any default-coalescing on the captured value.

3. **`test-dispatch-plan-review-panel.sh` slurped `jq -s -e` consumes large ndjson** — for the standard 10-row static manifest the slurp cost is trivial. For potential future scaling (more archetypes), slurping is still cheap. Earliest warning signal: harness runtime grows visibly. Mitigation: none needed at current scale; the strengthened assertion is required for correctness per FINDING_3.
