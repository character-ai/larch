### In-Scope Findings

1. **Important** correctness, `larch-logs/design/091F33CE-13BA-4445-90A9-7366AD354D25/plan.txt:75-85` and `python/agents.py:947-956`: the plan says to pass the **health-gate timeout** into `check_reviewers(...)`, but it does not explicitly require `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT=0` to short-circuit before that call. The target `check_reviewers` path treats a `0` timeout as falsy and falls back to `LARCH_PROBE_TIMEOUT_SECONDS`, whose `zero_allowed=False` behavior maps zero to `30`, matching the probe knob but violating the health knob’s documented zero opt-out in `docs/configuration-and-permissions.md:246-250`. If an implementer wires the resolver through as `probe_timeout_seconds=0`, setting `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT=0` can still run a 30-second probe and fast-fail a launch. Fix the plan under `### UPDATED: python/agents.py` to require: resolve health timeout separately, return proceed/disabled when it is exactly `0`, and pass only positive values to `check_reviewers`.
