# Increase health-check probe timeout default from 30s to 60s

## Summary

Raise the default per-attempt vendor health-check probe timeout (Codex, Cursor) from **30s to 60s**.

## Relationship to #4756

This issue is **blocked by #4756** (`[DESIGNING] External-tool health probes... 10 items`). That issue's **Item 1** covers the same root cause (a cold-start probe grazing the 30s `LARCH_PROBE_TIMEOUT_SECONDS` emits a false `probe-failed`) and lists "raise `LARCH_PROBE_TIMEOUT_SECONDS`" as a candidate fix. However, #4756's current plan **deliberately keeps the 30s default** and instead adds a timeout-retry budget (`LARCH_PROBE_TIMEOUT_RETRIES`, default `0`). This issue tracks the distinct default bump (30s → 60s) that #4756 set aside. Land #4756 first, then revisit whether the retry budget alone suffices or the default should also rise.

## Motivation

The Step 0 operator-safety health check (`agent check-reviewers`) probes each vendor CLI by spawning a real `codex exec` / `cursor agent` call and waiting for a reply. The per-attempt wall-clock timeout defaults to 30s.

On slow networks or cold-start vendor CLIs, a healthy vendor can exceed 30s, hit the timeout, and be misclassified as `probe-failed`. That trips the degraded-tools gate: operator confirmation when one vendor is down, hard-fail when both are down. A 60s default gives slow-but-healthy vendors more headroom and reduces false-negative degraded gates.

## Current behavior

- `LARCH_PROBE_TIMEOUT_SECONDS` controls the per-attempt probe timeout. Default **30** (non-numeric / empty / `0` falls back to 30).
- Defined in `python/agents.py`, `check_reviewers` (~line 936): `timeout = probe_timeout_seconds or _env_int("LARCH_PROBE_TIMEOUT_SECONDS", 30, zero_allowed=False)`.
- The timeout is **per attempt**, not total. With retries the wall-clock can already be a multiple of it.
- On timeout the probe returns `EXIT_TIMEOUT` (124) and is **not** retried; the vendor is marked not-present for the session.
- Documented in `docs/configuration-and-permissions.md` (the `LARCH_PROBE_TIMEOUT_SECONDS` entry).

## Proposed change

- Change the default from `30` to `60` in `python/agents.py` (`check_reviewers`).
- Update the `LARCH_PROBE_TIMEOUT_SECONDS` default in `docs/configuration-and-permissions.md`.
- Update any tests that pin the 30s default (e.g. `python/test_agents.py`).
- Run `make py-lint` and `make py-test`.

## Open question: sibling launch-time gate

There is a second, related 30s timeout: `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` (default 30), the launch-time health gate applied before each `agent run-external-agent` Codex/Cursor launch (`python/session_env.py` `_external_timeout`; documented in `docs/configuration-and-permissions.md`). Decide whether to:

- (a) raise only the Step 0 probe timeout (`LARCH_PROBE_TIMEOUT_SECONDS`), or
- (b) also raise `LARCH_EXTERNAL_HEALTH_CHECK_TIMEOUT` to 60s for consistency.

Recommend (a) as the minimal change unless operators also report launch-time false-fails. Note the launcher-parity rule (`.claude/rules/external-tool-launcher-parity.md`) lists the health-probe surface as shared between Codex and Cursor.

## Acceptance criteria

- Default probe timeout is 60s when `LARCH_PROBE_TIMEOUT_SECONDS` is unset.
- Override semantics unchanged: non-numeric / empty / `0` falls back to the new 60 default.
- Docs and tests reflect 60s.
