## Edge cases

- `MAIN_ADVANCED` can come from merge-state lag, admin failure with conflict signal, version/main advancement, or post-force-push recovery. All should force one rebase pass before another merge attempt.
- `CI_NOT_READY` should still wait or continue as before. Do not rebase only because checks are not ready.
- Rebase sidecar fallback must not ingest stale `${output}.token-record` content from a previous attempt.
- Research sidecar ingestion warnings must report the real failing command rc, not `0`.
- Progress filtering should exclude CI/probe rows by both task kind and output basename, because older ledgers may have incomplete or drifted kinds.

## Failure modes

- If pre-rebase flush skips for a non-allowed reason after `MAIN_ADVANCED`, return the same `STALLED` shape as the existing `goto_rebase` path.
- If conflict-fix sidecar pre-clear fails due to permissions or an unsafe path, let the exception fail closed before launch.
- If `timing` import from `progress_report.py` causes a cycle, keep the helper local and add a parity assertion instead of widening imports.
- If a research ingestion command fails and writes stderr, keep the warning plus stderr suffix.
