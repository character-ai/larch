### FINDING_1: Symlink or non-directory dest not refused before tree replace
- **Reviewer(s)**: Cursor-Arch, Cursor-Pragmatic
- **Severity**: important
- **Concern**: Planned tree-publish hardening routes existing destinations through `_replace_tree_with_backup` only when `dest.exists()` and `dest.is_dir()` and not `dest.is_symlink()`. There is no explicit refuse path for symlink or plain-file destinations in `_copy_tree_to_repo` (and related callers such as `publish_breadcrumbs_main`). If `dest.exists()` is true for a symlink (including symlink-to-directory) or a non-directory file, a naive `else` branch can still call `staged.replace(dest)` / `tmp_dest.replace(dest)`, replacing the symlink or file instead of raising before any rename. That contradicts the documented edge-case requirement to refuse symlink/non-directory destinations.
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Add an explicit branch: when dest.exists() and not (dest.is_dir() and not dest.is_symlink()), raise ValueError before any rename; call _replace_tree_with_backup only for a normal directory dest; use tmp_dest.replace(dest) only when dest is missing.
  - From Cursor-Pragmatic: Add an explicit refuse branch in both callers before any staged.replace(dest): if dest.is_symlink() or (dest.exists() and not dest.is_dir()), raise ValueError (or always route existing dest through the helper, which already refuses symlink/non-directory).

### FINDING_2: Narrowed exception tuples omit Unicode decode failures on manifest/commit/flush IO
- **Reviewer(s)**: Cursor-Arch, Cursor-Pragmatic
- **Severity**: important
- **Concern**: The plan replaces broad `suppress(Exception)` around commit/manifest/flush IO with narrow `try/except` tuples (OSError, json.JSONDecodeError, TypeError, ValueError) and promises warn-then-continue behavior. Several UTF-8 reads in this path use `path.read_text(encoding="utf-8")` without `errors=replace`: `_read_manifest_v2` (used by `_update_manifest_v2` at `python/run_logs.py:1874`), `_render_execution_issues_batch` (execution-issues.md at lines 1012 and 1016, reachable via `_stage_pre_commit` inside the flush wrapper at `python/run_logs.py:2207`), and related manifest reads. `UnicodeDecodeError` is not a subclass of `OSError` and is absent from the planned catch lists. Today `suppress(Exception)` swallows these and flush/commit continue (flush still returns 0); after narrowing, decode failures propagate and abort instead of emitting the planned stderr warning and continuing, breaking the warn-and-continue contract (including `larch_log_flush_main` returning 0).
- **Suggested revisions (informational for voters; coder decides)**:
  - From Cursor-Arch: Add UnicodeError to the manifest, breadcrumb, and flush catch tuples (or use errors=replace on those reads if silent degradation is intended), and add a test that corrupt UTF-8 in manifest or execution-issues emits a stderr warning without aborting flush.
  - From Cursor-Pragmatic: Add UnicodeDecodeError to the manifest-update catch tuple (consistent with python/run_logs.py:1688) and emit the same stderr warning before continuing.
