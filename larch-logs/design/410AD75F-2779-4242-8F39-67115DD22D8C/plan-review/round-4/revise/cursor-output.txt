## Failure modes

- Stale references to the deleted shell path can make `make lint-retired-scripts` fail.
- Moving the markdown without updating `_doc_allowlist_lines()` or `_doc_retry_policy_lines()` can break `stall-recovery lint`.
- Leaving `helper.exists()` guard in `plan_review.py` causes silent Step 3 escalation no-op after shell deletion.
- Omitting `exit_code` on the hand-built Namespace raises `AttributeError` before ledger write; only `OSError` is caught today.
- **Collapsing record-escalation validation failures into the non-writable degraded path returns `0`, touches Step 3 sentinels incorrectly, and changes verb semantics.**
- **Omitting `_write_record_escalation_tool_failure` leaves `compose_report` escalation-success without degraded record-escalation evidence after shell deletion.**
- **Skipping primary `ship-pr-state.sh` syntax validation lets malformed state files reach classification and breaks case21-malformed exit `3` contract.**
- **Omitting `--profile` on classify subparser blocks generic-profile harness cutover (case25) even when `classify()` routing exists.**
- **Unconditional same-cause-repeat promotion misclassifies `contract-failure` and `unrecoverable` repeats (case20b), producing wrong retry hints for step-6 contract stalls.**
- **Deleting bash harness 1 without porting case7g–7k6 drops submodule/dispatch bail-precedence coverage; stale transient notes can win over allowlisted bail tokens.**
- **Wrong CLI verb ordering (`stall-recovery --profile ... populate-sensitive-corpus`) fails argparse before any stall-recovery logic runs, breaking design failure-report harness conversion.**
- **Skipping classify field sanitization lets raw bail tokens, dispatchers, and exit codes persist into classification artifacts and downstream Tier A/Tier B reports after shell deletion.**
- **Omitting classify state-file validation allows symlinked or out-of-tmpdir state reads and breaks bash exit `3`/`1` contracts.**
- **Dropping `CLAUDE_PROJECT_DIR="$consumer"` on design failure-report harness cutover makes sensitive-corpus leak tests false-pass against the real dev clone.**
- Retiring legacy `bug-body` tests without replacing their redaction assertions can weaken coverage.
- Deleting bash harnesses before porting case21/22 durability, case7g–7k6, case20b, split ledger branches, classify sanitization, and case24 Tier A dedup non-dry drops atomic-failure and dedup coverage.
- Rebalancing Makefile shards incorrectly leaves tests uncovered in CI (`lint-harness-pytest-partition.py` failure).
- Direct `plan_review.py` calls can lose stdout/stderr logs unless output is redirected around `stall_recovery.record_escalation()`.
- Fake-plugin harnesses can fail if they symlink only `python/*` files but not enough repo context for `python/cli.py` imports.
- **`test-ci-decide.sh` using undefined `$ROOT` aborts under `set -u` before classify assertions run.**
- Replacing `test-ci-decide.sh` classify checks with `validate-token` breaks token acceptance semantics.
