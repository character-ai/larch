## Findings

### 1. `record_attempt()` parity missing from plan (blocking, correctness)

The plan’s `python/stall_recovery.py` section details `record_escalation()` and `classify()` bash parity but never requires fixing `record_attempt()`.

Today Python clobbers the attempts file:

```303:308:python/stall_recovery.py
def record_attempt(args: argparse.Namespace) -> int:
    path = Path(args.attempts_file or Path(args.implement_tmpdir) / "stall-recovery-attempts.env")
    count = int(read_kv(path, "attempt_count", "0") or 0) + 1
    values = {"version": 1, "created_utc": read_kv(path, "created_utc", datetime.now(UTC).isoformat()), "attempt_count": count, "last_class": args.failure_class, "last_signature": args.signature, "last_resume_hint": args.resume_hint, "last_outcome": args.outcome}
    write_kvs(path, values)
    return 0
```

`compose_report()` builds the attempts table only from `attempt.{idx}.*`:

```1435:1441:python/stall_recovery.py
    lines.extend(
            f"| `{idx}` | `{_safe_class_value(read_kv(attempts_file, f'attempt.{idx}.class', ''))}` | "
            ...
            for idx in range(1, attempt_count + 1)
        )
```

Bash `cmd_record_attempt` appends `attempt.N.*` rows. Deleting the shell without porting this leaves reports with `attempt_count>0` but empty attempt rows.

**Suggested revision:** Add explicit `record_attempt()` work (append semantics, tmpdir confinement, harness case11/13/21 ports) to the plan’s `python/stall_recovery.py` section.

### 2. Same-cause-repeat contract mismatch (important, correctness)

Plan lines 67–70 bind promotion to `last_signature` and `last_outcome=failed`. Bash uses `latest_attempt_signature()` on `attempt.${attempt_count}.signature` and excludes only `contract-failure` / `unrecoverable` (stall-recovery-report.sh:1244–1250). Case7/case20b harness flows use bash `record-attempt` then `classify`.

**Suggested revision:** Tie same-cause-repeat to `latest_attempt_signature` parity after `record_attempt` is fixed; port case7 and case20b explicitly.

### 3. Incomplete harness-to-pytest inventory (important, risk-integration)

The plan lists many pytest targets but omits several harness cases that block safe deletion: case7, case11, case13, case21. Without an explicit checklist, implementers may delete bash harnesses while coverage gaps remain.

**Suggested revision:** Add a named port table mapping each harness case to a pytest function before `REWRITTEN: test-stall-recovery-report-*.sh` deletion.
