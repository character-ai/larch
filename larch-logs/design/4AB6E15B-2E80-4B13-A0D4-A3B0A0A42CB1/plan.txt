# Plan: reconcile link_pr_closes with ship-pr Closes #N composition (#3326)

Reconcile the Python rework tree's two `Closes #N` composers into one source of
truth, fix the canonical helper's prefix-collision bug, and drop dead surface.
`tracking_issue.link_pr_closes` becomes the single canonical helper (string +
idempotency); `pr_body.compose_pr_body` delegates to it instead of inlining
`f"Closes #{issue_number}"`. Delete the unused `PrBodyParts` dataclass. No bash
changes, no fork/no-issue placeholder parity, no new `pr.ensure_pr` wiring.

This is a SIMPLE-tier, python/-only cleanup (dev/CI tree, not wired to the live
`/implement` path until Phase 7).

## Files to modify/create

### UPDATED: `python/pr_body.py`
- Add `import tracking_issue` to the import block (alphabetical with the other
  bare-module imports). Verified no circular import: `tracking_issue.py` imports
  only `config`, `gh`, `redact`, `errors`, `proc` — not `pr_body`.
- Delete the dead `PrBodyParts` dataclass (the `@dataclass(frozen=True)` block

- In `compose_pr_body`, build the body from `parts` first, then append `Closes #N`

  - Old: `if issue_number is not None: parts.extend(["", f"Closes #{issue_number}"])`
    before `body = "\n".join(parts) + "\n"`.
  - New: `body = "\n".join(parts) + "\n"`, then
    `if issue_number is not None: body = tracking_issue.link_pr_closes(body, issue_number)`.
  - Keep the existing post-build order intact: the `sanitize_fragment(body,
    from_md=True)` check and `redact.redact(...)` fail-closed pass still run on

### UPDATED: `python/tracking_issue.py`
- Fix the `link_pr_closes` idempotency check to be prefix-collision-safe. Replace
  the substring test `if needle in body:` with a digit-boundary regex so a longer
  issue number cannot mask a shorter one:
  - Old: `needle = f"Closes #{issue_number}"` then `if needle in body: return body`.
  - New: keep `needle = f"Closes #{issue_number}"` for the append; change the guard

  - This addresses the plan-review finding (Cursor-Edge): substring `needle in
    body` skips appending `Closes #4` when the body already contains `Closes #42`.
    The fix benefits both new caller `compose_pr_body` and the existing
    `pr.ensure_pr` caller.

## Approach
- One owner for the `Closes #N` string and its idempotency:
  `tracking_issue.link_pr_closes`, now collision-safe. Both `compose_pr_body` and
  `pr.ensure_pr` route through it.
- `pr.py:ensure_pr` keeps its call sites unchanged and inherits the correctness
  fix transitively.
- Round 1 framing said `tracking_issue.py` would be unchanged in behavior; that is
  superseded by the plan-review finding the operator accepted at Gate B — the
  helper gains a small, well-tested correctness fix.
- Trade-off (Round 1 Q2): the helper stays in `tracking_issue.py` rather than
  moving to `pr_body.py`, keeping churn minimal at the cost of leaving the
  bash-vs-Python module-placement difference in place.

## Edge cases
- `issue_number is None`: `compose_pr_body` adds no `Closes` line and does not call
  `link_pr_closes`. Unchanged behavior.
- Body already contains an exact `Closes #N` (digit-boundary): `link_pr_closes` is
  a no-op (idempotent), so no duplicate.
- Prefix collision (tracking `#4`, body already has `Closes #42`; or `#42` vs
  `Closes #421`): FIXED — the digit-boundary guard `Closes #{n}(?!\d)` does not
  treat the longer number as a match, so the correct `Closes #N` is appended. The
  leading side is already safe: the literal `Closes #` prefix prevents `Closes
  #142` from matching `Closes #42`.
- Blank-line layout shifts from two blank lines to one before `Closes #N` (the
  `link_pr_closes` rstrip + `\n\n` form). Matches bash `ship-pr.sh` better; no
  existing test pins the old two-blank-line layout.
- Mermaid sanitization and redaction still run on the final body (with `Closes`
  appended); the fail-closed ordering is preserved.

## Failure modes
1. Future circular import — if `tracking_issue` later imports `pr_body`, the new
   `import tracking_issue` in `pr_body.py` would cycle. Earliest signal:
   `ImportError` on `import pr_body` in any test. Mitigation: keep
   `link_pr_closes` free of `pr_body` dependencies (it already is).
2. A future caller depends on the removed `PrBodyParts`. Earliest signal:
   `AttributeError: module 'pr_body' has no attribute 'PrBodyParts'`. Mitigation:
   verified zero current and planned uses; reviewers re-grep before merge.
3. The digit-boundary regex changes idempotency for an unforeseen body shape.
   Earliest signal: a `test_link_pr_closes_*` failure. Mitigation: the change only
   narrows "already present" detection (it never produces duplicate lines — it can
   only append in more cases); the three regression tests lock both the append and
   no-append paths.

## Testing strategy
- Add the three tests above (`test_compose_pr_body_appends_closes`,

- Run `make py-lint` and `make py-test`; both must stay green.
- No bash harness changes (no bash files touched).
