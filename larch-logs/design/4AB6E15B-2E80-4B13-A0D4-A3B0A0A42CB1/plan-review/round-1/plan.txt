# Plan: reconcile link_pr_closes with ship-pr Closes #N composition (#3326)

Reconcile the Python rework tree's two `Closes #N` composers into one source of
truth and drop dead surface. `tracking_issue.link_pr_closes` becomes the single
canonical helper (string + idempotency); `pr_body.compose_pr_body` delegates to
it instead of inlining `f"Closes #{issue_number}"`. Delete the unused
`PrBodyParts` dataclass. No bash changes, no fork/no-issue placeholder parity, no
new `pr.ensure_pr` wiring.

This is a SIMPLE-tier, python/-only cleanup (dev/CI tree, not wired to the live
`/implement` path until Phase 7).

## Files to modify/create

### UPDATED: `python/pr_body.py`
- Add `import tracking_issue` to the import block (alphabetical with the other
  bare-module imports). Verified no circular import: `tracking_issue.py` imports
  only `config`, `gh`, `redact`, `errors`, `proc` — not `pr_body`.
- Delete the dead `PrBodyParts` dataclass (the `@dataclass(frozen=True)` block
  with fields `summary`, `mermaid_block`, `test_plan`, `closes_line`). It is
  never instantiated anywhere in `python/` and is referenced by no other open
  issue or committed plan. Keep `from dataclasses import dataclass` — it is still
  used by `MermaidResult`.
- In `compose_pr_body`, replace the inline closes block. Build the body from
  `parts` first, then append `Closes #N` through the canonical helper:
  - Old: `if issue_number is not None: parts.extend(["", f"Closes #{issue_number}"])`
    before `body = "\n".join(parts) + "\n"`.
  - New: `body = "\n".join(parts) + "\n"`, then
    `if issue_number is not None: body = tracking_issue.link_pr_closes(body, issue_number)`.
  - Keep the existing post-build order intact: the `sanitize_fragment(body,
    from_md=True)` check and `redact.redact(...)` fail-closed pass still run on
    the final body (now with `Closes #N` appended).

### UPDATED: `python/test_pr_body.py`
- Add `test_compose_pr_body_appends_closes`: call `compose_pr_body(summary="- x",
  issue_number=42)` and assert `"Closes #42"` appears exactly once in the result.
  This is the missing positive coverage that locks the consolidated behavior.

### UPDATED: `python/test_tracking_issue.py`
- Keep `test_link_pr_closes_appends`.
- Add `test_link_pr_closes_idempotent`: call `link_pr_closes` on a body that
  already contains `Closes #42` and assert the result is unchanged (no duplicate
  needle). This locks the single-source-of-truth idempotency invariant.

## Approach
- One owner for the `Closes #N` string and its idempotency:
  `tracking_issue.link_pr_closes`. Both `compose_pr_body` and `pr.ensure_pr` route
  through it.
- `pr.py:ensure_pr` is unchanged — it already calls
  `tracking_issue.link_pr_closes` on both the existing-PR and new-PR paths.
- `tracking_issue.py` is unchanged in behavior — it only gains a new caller and a
  new test.
- Trade-off accepted (Round 1): the helper stays in `tracking_issue.py` rather
  than moving to `pr_body.py`. This keeps churn minimal at the cost of leaving the
  bash-vs-Python module-placement difference in place (bash composes `closes`
  inside `ship-pr.sh` PR-body assembly). The user chose this in clarification.

## Edge cases
- `issue_number is None`: `compose_pr_body` adds no `Closes` line and does not call
  `link_pr_closes`. Unchanged behavior.
- Body already contains `Closes #N`: `link_pr_closes` is a no-op, so no duplicate
  even if a future caller pre-seeds the needle.
- Blank-line layout shifts from two blank lines to one before `Closes #N` (the
  `link_pr_closes` rstrip + `\n\n` form). This matches bash `ship-pr.sh` better.
  No existing test pins the old two-blank-line layout.
- Mermaid sanitization and redaction still run on the final body (with `Closes`
  appended); the fail-closed ordering is preserved.

## Failure modes
1. Future circular import — if `tracking_issue` later imports `pr_body`, the new
   `import tracking_issue` in `pr_body.py` would cycle. Earliest signal:
   `ImportError` on `import pr_body` in any test. Mitigation: keep
   `link_pr_closes` free of `pr_body` dependencies (it already is); note the
   constraint in review.
2. A future caller depends on the removed `PrBodyParts`. Earliest signal:
   `AttributeError: module 'pr_body' has no attribute 'PrBodyParts'`. Mitigation:
   verified zero current and planned uses (grep + issue/doc search); reviewers
   re-grep before merge.
3. A downstream consumer string-matches the old two-blank-line body. Earliest
   signal: a PR-body assertion diff in CI. Mitigation: no such consumer exists
   today — `compose_pr_body` is not yet wired into `ensure_pr`; the new positive
   test locks the consolidated layout.

## Testing strategy
- Add the two tests above (`test_compose_pr_body_appends_closes`,
  `test_link_pr_closes_idempotent`).
- Run `make py-lint` and `make py-test`; both must stay green.
- No bash harness changes (no bash files touched).
