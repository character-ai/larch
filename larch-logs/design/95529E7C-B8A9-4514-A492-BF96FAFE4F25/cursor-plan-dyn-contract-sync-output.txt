### 1. [correctness] `scripts/design-pause-save.sh:175-178` — broadened publish gate breaks exit-1 recovery

The plan mirrors FINDING_17 in `design-publish.sh` by changing the pause path from `publish_rc -ne 0 && -z PUBLISH_OK` to `publish_rc -ne 0` and immediately calling `emit_fail "publish-failed"`. That differs from `design-publish.sh`, which still continues after forcing `PUBLISH_OK=false` on non-zero exit.

`design-log-publish.sh` intentionally exits **1** (not 0) on post-push operational failures while emitting `PUBLISH_OK=false` and often `RECOVERY_BRANCH`:

```14:16:scripts/design-log-publish.sh
# Expected operational failures emit PUBLISH_OK=false on stdout. Pre-validation and
# pre-push failures exit 0 so callers can parse stdout. Post-push failures (git push,
# gh pr create after push, gh pr merge) exit 1 while preserving PUBLISH_OK=false.
```

Pause-save’s recovery contract depends on reaching the second branch when publish fails but a recovery ref exists:

```180:191:scripts/design-pause-save.sh
if [[ "$PUBLISH_OK" != "true" ]]; then
    log_failure "design-log-publish.sh" "$publish_err"
    if [[ -n "$RECOVERY_BRANCH" ]]; then
        if [[ "$RECOVERY_BRANCH" == "larch-log-design-$RUN_ID" || "$RECOVERY_BRANCH" == "larch-log-design-recovery-$RUN_ID" ]]; then
            printf 'LOG_RECOVERY_BRANCH=%s\n' "$RECOVERY_BRANCH" >> "$state_tmp"
        else
            ...
```

Under the proposed gate, a real post-push failure (`publish_rc=1`, `PUBLISH_OK=false`, `RECOVERY_BRANCH` set) would hit `emit_fail "publish-failed"` first and never write a resumable pause marker with recovery metadata — a regression against `scripts/design-pause-save.md:32-38`.

The plan’s edge-case note (“recovery paths still require `PUBLISH_OK=false` on exit 0”) misreads the publish contract: recovery in production commonly pairs **exit 1** with a failure envelope. The planned `rc-ok-false` harness case (stdout `PUBLISH_OK=true`, non-zero exit) would not detect this because existing recovery tests use a stub that exits 0 (`test-design-pause-resume.sh:127-131`).

**Suggested revision:** Gate only the contradictory case — non-zero exit when stdout claims success or omits `PUBLISH_OK` — e.g. `if [[ "$publish_rc" -ne 0 && ( -z "$PUBLISH_OK" || "$PUBLISH_OK" == "true" ) ]]`. Add a pause-resume stub mode that exits 1 with `PUBLISH_OK=false` + `RECOVERY_BRANCH` and assert `PAUSE_OK=true` / marker write still succeeds.
