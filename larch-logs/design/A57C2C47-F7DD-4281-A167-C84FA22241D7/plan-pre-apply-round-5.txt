## Plan

## Approach

Create one stdlib-only module `python/voting.py` that absorbs 12 bash scripts. Each absorbed surface becomes an importable function plus a `*_main(argv)` verb registered in `python/cli.py`. Consumers call `python3 "$PLUGIN_ROOT/python/cli.py" voting <verb>` directly. No shims. This is a hard cutover per `docs/python-migration.md`.

Behavior spec stays `docs/voting-process.md` and `docs/point-competition.md`. Thresholds, ballot grammar, parse-rate suppression, retry exit behavior, degraded-panel KV payloads, and scoring semantics do not change.

Sequence:

1. Port functions into `python/voting.py`; register verbs in `python/cli.py`.
2. Write `python/test_voting.py` porting all 6 deleted bash harness assertion sets; `make py-lint py-test` green.
3. Cut over all consumers, surviving harnesses, Makefile, `agent-lint.toml`, `SECURITY.md`, and docs.
4. Parity gate: run the retargeted consumer harnesses once: `test-tally-code-votes`, `test-tally-plan-review`, `test-dispatch-code-voters-*`, `test-dispatch-plan-voters`, `test-findings-classification`, `test-review-findings-classification`, `test-plan-review-scope-anchor`, `test-implement-bootstrap`, `test-review-and-fix`, `test-review-structure`, `test-implement-structure`.
5. Delete the 36 retired files; append rows to `python/migrated-scripts.tsv`; `make lint` green.

### Diagnostic route

Do not mix warning prose into machine stdout.

- `parse-rate-check` stdout remains `PARSE_RATE_STATUS=...`.
- `parse-rate-retry` stdout remains the bare captured status token only.
- `parse-rate-check` and `parse-rate-retry` exit 0 whenever they emit `OK` or `NOT_SUBSTANTIVE`.
- Retry launcher failure or empty retry output cleans retry temp files, keeps original diag, prints `NOT_SUBSTANTIVE`, and exits 0.
- `degraded-warning` stdout remains the single `DEGRADED_PANEL_WARNING=` KV line only.
- `degraded-warning` keeps the full existing banner string in the KV value for parity.
- Warning prose from `parse-rate-*` and `degraded-warning` must be written to an explicit operator-visible diagnostic stream.
- **Quiet-mode routing (plain-stdout verbs)**: diagnostic helpers must mirror `scripts/lib-quiet.sh` / `logging_util.BreadcrumbWriter` behavior. When `LARCH_QUIET_ACTIVE` is set and the Python child has **not** called `quiet_init()`, write sanitized prose with `os.write(4, ...)` to the inherited original stderr (fd 4); fall back to `sys.stderr` only when fd 4 is unavailable. When quiet is inactive, write to inherited stderr. Machine tokens stay on stdout (or fd 3 after parent quiet init) only; never route warning prose there.
- When a parent shell script is quiet-mode aware, capture diagnostic prose separately and re-emit it through the existing human diagnostic helper or stream used by that script.
- When Python emits diagnostics directly, route them through the fd-4 path above without clobbering fd 3 contract output.
- Add pytest and dispatch harness assertions that captured stdout for `parse-rate-retry` is exactly `OK`, `NOT_SUBSTANTIVE`, or the existing final status token, with no `=` prefix and no warning text.
- Add pytest cases that with `LARCH_QUIET_ACTIVE=1` and `LARCH_QUIET_PID` set (parent quiet, child did not `quiet_init`), diagnostic prose lands on fd 4 / inherited stderr and not on stdout.
- Add a plan dispatch harness assertion that degraded-panel warning prose remains visible while the KV order and `DEGRADED_PANEL_WARNING` value stay byte-compatible.

### Module design rules

- **Stream routing**: `parse-judge-vote`, `write-tally`, and `compose-tally-record` call `logging_util.quiet_init()` and emit through `emit_kv` / `contract_stream`. All other verbs print machine output plainly to stdout and route warning prose through the diagnostic route above (fd 4 when parent quiet active, else stderr).
- **Subprocess seams**: use `proc.run` for retry launchers, `scripts/append-tool-failure.sh`, and `scripts/larch-log.sh`.
- **Path resolution**: resolve subprocess seams from `--plugin-root` when given. Otherwise resolve from `Path(__file__).parent.parent`.
- **Env overrides**: keep `LARCH_WRITE_TALLY_LOGGER`. Drop `LARCH_WRITE_TALLY_COMPOSER`.
- **Retry env fallbacks**: keep reading optional `LARCH_EXECUTION_ISSUES_LOG`, `SESSION_ENV_PATH`, and `IMPLEMENT_TMPDIR`.
- **Harness suppression**: port `is_harness_review_path` and `should_suppress_parse_rate_issue_append`. Apply suppression before calling `append-tool-failure.sh` in both `parse-rate-check` and `parse-rate-retry`, so harness-shaped review paths do not pollute parent execution issue logs.
- **Do not port `is_scope_reduction_block`**. It only delegates to `scripts/check-scope-reduction-marker.sh`.
- **Parity details**: preserve the `>= 0.8` `JUDGE_ERROR` ratio threshold; diag sidecar field order; first-200-bytes capture; `-parse-rate-diag.txt`, `-parse-retry`, and `-first-pass` names; `.done` sentinel handling; code and plan retry preamble texts; retry failure exit behavior; code-review header allowlist validation in `write-tally`; body-file symlink rejection; `emit_kv` newline rejection.
- **Plan voter coverage**: preserve effective-judge gating and `VOTER_PATHS_FILE` conditional emission exactly.
- **Code-review body files**: `write-tally` and `compose-tally-record` validate `--body-file` for code-review mode but never include body content in `code-review-tally.json`.
- **Scoreboard quoting**: implement bash `printf '%q'` compatible quoting for `SCOREBOARD_FILE`. Do not use `shlex.quote` for this migration.
- **Hashing**: replace `shasum` with `hashlib.sha256`.

## Edge cases

- **Subprocess cost in tally loops**: per-finding CLI calls add roughly 30 to 50 ms each. Accepted for this part.
- **No-trailing-newline verbs**: `reviewer-for-block`, `classify-result`, and `panel-tier` keep byte parity with bash `printf '%s'`.
- **Parse-rate stdout**: `parse-rate-retry` prints only a bare status token. `parse-rate-check` keeps the existing KV form.
- **Parse-rate exit codes**: `OK` and `NOT_SUBSTANTIVE` are successful statuses and exit 0, including retry-launcher failure fallback.
- **Parse-rate ID grammar**: use `finding-only|finding-oos`; both dispatchers pass `finding-oos` so `OOS_N` IDs keep participating in parse-rate accounting.
- **Parse-rate skipped slots**: failed slot 1 and failed/skipped slots 2/3 keep `SKIPPED` parse-rate status; Python retry must not run for guarded-off slots.
- **Parse-rate harness suppression**: harness-shaped review paths must not append parse-rate warnings into parent issue logs.
- **Diagnostic visibility**: warning prose from parse-rate and degraded-panel paths must not vanish into quiet logs or pollute captured stdout; when parent quiet is active, route to fd 4 (fallback stderr).
- **Degraded warning KV**: keep the banner in the `DEGRADED_PANEL_WARNING` value. Forbid extra non-KV stdout lines.
- **Plan voter coverage**: all-failed and empty-output voters do not count as effective judges. Empty voter paths file does not emit `VOTER_PATHS_FILE`.
- **parse-judge-vote no-match**: exit 0 with empty vote and axis fields; invalid vote token same as no match.
- **parse-judge-vote duplicates**: last matching anchored ID line wins; axis fields reset per match.
- **parse-judge-vote axes**: parse only before ` -- `; `PARSED_UNCERTAIN=true` unless all four axes valid and explicit `UNCERTAIN=false`.
- **ERE to `re` translation**: translate `[[:space:]]` classes and case-insensitive matching carefully. Pin with pytest.
- **Last-match-wins semantics**: preserve for `vote-for-id`, `parse-judge-vote`, and `tally-vote`.
- **Empty/missing inputs**: empty voter file or zero ballot IDs gives `PARSE_RATE_STATUS=OK`; missing voter file in `tally-vote` is skipped; missing tally file in `scoreboard` gives all-zero scores; `eligible <= 0` rejects and reports `main-agent-required`.
- **Empty optional retry context**: omit optional code-dispatch `--ctx` pairs when `bounded_diff` or `bounded_plan` is empty.
- **Code-review parser fallback**: tally-code-votes keeps the fd 3 warning and synthetic `PARSED_*` JUDGE_ERROR block on parser failure (rc 2), distinct from no-match rc 0.
- **Code-review body file**: validate `--body-file`, reject symlinks as today, and do not include body content in the JSON tally record.
- **review-and-fix tally flush**: `2>&1` capture around `WRITE_TALLY_CMD` prevents larch-log KV leakage to stdout; failure output goes to `larch_err` only.
- **Scoreboard quoting**: keep bash `printf '%q'` compatible output. Do not switch to `shlex.quote`.
- **fd-3 inheritance**: quiet verbs route KV to the contract stream; callers capturing with `$()` see identical bytes.
- **`split-ballot` partial writes**: detect duplicates before writing. Fail closed.
- **`--neutral N`**: keep accepting and ignoring the deprecated argv in `write-tally` and `compose-tally-record`.
- **Regex fetch failures**: validator scripts must not continue with empty regex variables. Checked helpers fail closed.
- **Command-array seams**: multi-word Python defaults must use arrays, not scalar executable paths.
- **Unset variables**: every updated shell caller must define `CLI`, `DISPATCH_LABEL`, `LAUNCH_MODE`, and root variables before use under `set -u`.

## Failure modes

- **Missed consumer reference**: `make lint-retired-scripts` fails CI.
- **Stale structure-test comment**: `scripts/test-review-structure.sh` can fail retired-script lint if its nearby comment still names the retired `is_security_block` path.
- **Stale file-line-regex docs**: `skills/implement/scripts/test-oos-file-conflict-deps.md` can fail retired-script lint if it still names the retired regex lib.
- **Parse-rate ID regression**: OOS-only outputs stop counting if `finding-oos` is not wired. Pytest and dispatch harnesses pin this for code and plan.
- **Parse-rate skipped-slot regression**: invoking retry for skipped/failed slots changes `VOTER_N_PARSE_RATE_STATUS` defaults and effective-judge counts.
- **Parse-rate stdout regression**: `parse-rate-retry` status capture fails if stdout contains KV prefixes or warnings. Pytest and dispatch harnesses pin the bare token contract.
- **Parse-rate exit regression**: dispatch command substitution can abort under `set -e` if retry failure returns nonzero instead of printing `NOT_SUBSTANTIVE` and exiting 0.
- **Parse-rate suppression regression**: harness runs can pollute parent execution issue logs if suppression helpers are omitted.
- **Parse-rate argv regression**: `python/test_voting.py` covers explicit flag mappings and option-shaped `--ctx` values.
- **Parse-rate retry regression**: `test-dispatch-code-voters-retry-claude`, `test-dispatch-code-voters-retry-cursor`, and regression harnesses exercise real `voting parse-rate-*` verbs through sandbox CLI.
- **Hidden warning regression**: degraded-panel and parse-rate diagnostics must remain visible through the fd-4 diagnostic route while machine stdout stays parseable.
- **Quiet fd-4 regression**: routing diagnostics to raw stderr when parent quiet is active hides operator-visible messages in quiet logs.
- **Degraded warning payload drift**: downstream parsers can break if `DEGRADED_PANEL_WARNING` stops carrying the full banner string.
- **parse-judge-vote contract drift**: no-match rc 0 vs parser-failure rc 2 confusion can change vote counts; axis-after-delimiter parsing can false-positive axes.
- **Plan coverage drift**: failed, non-substantive, empty-path, missing-file, or empty-file voters can be counted incorrectly. Tests pin exclusion.
- **Regex command failure**: validator helpers fail through existing error paths instead of binding empty grep patterns.
- **Code-review parser fallback drift**: parser rc 2 can change vote counts if the synthetic `JUDGE_ERROR` block is dropped.
- **Code-review tally schema drift**: body-file content must not enter the JSON tally record. Pytest pins absence.
- **review-and-fix stdout leak**: dropping `2>&1` tally capture can inject larch-log KV lines into review-and-fix stdout contract stream.
- **Scoreboard quoting drift**: `%q` differences for paths with spaces or shell metacharacters can break byte parity. Pytest pins compatibility.
- **Plan-review KV order drift**: `test-dispatch-plan-voters.sh` pins interleaved status-block order.
- **`/implement` Step-0 tally break**: `test-implement-bootstrap.sh` covers `write-tally` CLI ordering; `test-review-and-fix.sh` covers the preserved override env and `2>&1` capture path.
- **Sandbox harnesses missing `python/`**: dispatch harnesses fail fast; fixture copy or execv shim fixes this.
- **Unset variable aborts**: scripts running under `set -u` can fail before invoking Python if `CLI`, `DISPATCH_LABEL`, `LAUNCH_MODE`, `PLUGIN_ROOT`, or `PY_CLI` are not defined.
