### In-Scope Findings

- **correctness (implementation missing)** `python/agent_waterfall.py:412-427` — Issue #4658 plan (`Files to modify → python/agent_waterfall.py`) requires a concurrent poll `_reap_phase`, env readers (`LARCH_REVIEWER_STRAGGLER_MULTIPLE`, `LARCH_REVIEWER_STRAGGLER_FLOOR_SECONDS`), and straggler return handling. On `main`, `_reap_phase` still blocks per launch with `process.wait()` and returns `None`; there is no `time` import, no straggler env plumbing, and no `STRAGGLER_DROPPED_COUNT` / `WARN=reviewer-straggler-dropped`. **Suggested fix:** Implement the plan’s `_reap_phase(launches, opts) -> set[int]` rewrite and wire it through `_collect_phase` before claiming acceptance.

- **correctness (straggler-dropped → phase2/phase3)** `python/agent_waterfall.py:560-566,682-702` — Plan section **Design decisions (Round 1 Q&A) #3** and **`_collect_phase` bullet** require straggler-dropped slots to skip fallback. Today any phase-1 reviewer that exits non-zero (including per-reviewer `--timeout` kills) gets `drops[idx] = DropState("collector-failure", …)` and `failed.append(idx)`, and `phase2_queue = [*phase1_queue, *phase1_failed]` queues it for the other-tool phase; `phase3_queue` repeats the pattern for phase-2 failures. Slow reviewers therefore **do** enter phase2/phase3 today. **Suggested fix:** After `_reap_phase`, mark straggler indexes with `DropState("straggler-dropped", …)`, `continue` without appending to `failed`, so they never reach `phase2_queue` / `phase3_queue`.

- **correctness (filtered collection mapping)** `python/agent_waterfall.py:509-519` — Plan **`_collect_phase` bullet** says straggler indexes get a drop and `continue` so they are never treated as failures. The loop always maps `blocks[pos]` to `launches[pos]` after `collect-results` runs on **all** outputs. If the straggler check runs after parsing collector status, a SIGTERM’d slot (non-zero `.done`) becomes `collector-failure` and lands in `failed` unless the straggler guard runs first. The plan does not pin guard order or exclude straggler paths from the `collect-results` argv. **Suggested fix:** Pass only non-straggler outputs to `collect-results`, or check `idx in straggler_dropped` at the top of the per-launch loop before any status-based `failed.append`.

- **correctness (deadline arming / quorum math)** Plan section **Safety bounds** — `deadline = min(ceiling, max(multiple * first_success_elapsed, floor))` with arming on first exit code `0`. The plan does not say whether arming uses `time.monotonic() - start` at reap time or relies on a stored finish timestamp; a fast exit-0 with empty output (later `EMPTY_OUTPUT` / gate failure) can still anchor the deadline before any substantive review completes, contradicting **Design decisions #2** (“not a fast crash”). **Suggested fix:** Arm only after first exit `0` **and** either defer arming until post-collector `OK`/`cap_hit`, or document that exit-0 alone is the anchor and accept false early cuts.

- **correctness (no-quorum / fast-failure)** Plan **Edge cases / failure modes** — `multiple=0` must preserve wait-for-all; “no success ever” must wait to per-reviewer ceiling. That matches intent, but the plan does not say straggler-dropped `.done` exit codes must differ from natural-timeout failures so `_collect_phase` can distinguish “adaptive cut” from “genuine crash still eligible for fallback.” Today both are non-zero exits. **Suggested fix:** Write a distinct non-zero exit (or a sidecar marker) on adaptive SIGTERM, and teach the straggler guard to key off that marker rather than collector `FAILED`/`TIMED_OUT`.

- **correctness (floor/ceiling output assembly)** `python/agent_waterfall.py:753-757,623-626,760-761` — Plan **`Output assembly + _write_paths_file`** requires skipping empty `final_outputs` unconditionally. Today empty paths are skipped only when `opts.no_fallback`; in fallback-active `/design` plan-review (`python/plan_review_panel.py:304-322`, no `--no-fallback`), empty strings are appended to `ALL_OUTPUT_FILES` and written as blank lines in the paths file. **`DROPPED_SLOTS_FILE`** is emitted only when `opts.no_fallback` (`760-761`), while the plan says straggler-dropped slots belong in the dropped sidecar for observability. **Suggested fix:** Unconditionally skip empty outputs in paths/KV assembly; emit `DROPPED_SLOTS_FILE` whenever any slot (including stragglers in fallback mode) has an empty `final_outputs[idx]`.

- **risk-integration (downstream threshold)** `python/review_pipeline.py:1460-1468,1922-1924` — Plan **Acceptance** (“round proceeds with reviews already collected”) does not cover `/review` / `/implement` `check_reviewer_failure_threshold`, which reads `--dropped-slots-file` and counts every dropped static slot as `failed`/`ERROR` toward the >50% panel-fail gate. If stragglers are added to `DROPPED_SLOTS_FILE` under `--no-fallback` (`python/review_pipeline.py:~1085`), several intentional straggler drops can flip `THRESHOLD_OK=false` even when enough reviewers succeeded. **Suggested fix:** Extend the plan (and implementation) so `straggler-dropped` rows are excluded from threshold failure math, or add a separate KV consumed by threshold logic.

- **testing** `python/test_agent_waterfall.py` — Plan **`python/test_agent_waterfall.py` (tests)** lists straggler kill, no phase2/phase3 queueing, `multiple=0`, floor/ceiling, and KV emission cases. No straggler tests exist on `main`. **Suggested fix:** Add the plan’s pytest cases before merge; include a mixed-phase scenario (OK + straggler-dropped + genuine failure) to prove only the failure index enters `phase2_queue`.
