## Global behavior changes (issues)

### FINDING_1: STRICT read-only preamble is unconditional in `launch-review`

**Plan/doc:** `docs/configuration-and-permissions.md` § `LARCH_CURSOR_MODEL` describes risk-gated max-mode; `skills/design/references/plan-review.md` § Competition notice describes panel-scoped scoring injection. Neither describes voters/decompose/aggregator getting launcher hardening.

**Issue:** Every `agent launch-review` invocation prepends `_CURSOR_REVIEW_STRICT_PREAMBLE` / injects `_CODEX_REVIEW_STRICT_PREAMBLE` with no caller opt-in flag:

```4581:4582:python/agents.py
    prompt = f"{_CURSOR_REVIEW_STRICT_PREAMBLE}\n\n{original_prompt}"
    wrapped = f" /max-mode on. Prompt: {prompt}"
```

```4342:4343:python/agents.py
        instr_path = Path(home) / "trusted-instructions.txt"
        instr_path.write_text(_CODEX_REVIEW_STRICT_PREAMBLE, encoding="utf-8")
```

Voters, decompose, and aggregation all reach `launch-review` via `dispatch-waterfall`, so they inherit this preamble and `/max-mode on` even though their dispatchers pass no opt-in flag. That is broader than “panels only.”

### FINDING_2: `--risk low` is documented but not wired at any caller surface

**Plan/doc:** `docs/configuration-and-permissions.md` § `LARCH_CURSOR_MODEL` (line 187): low risk from `classify-diff` should suppress max-mode; Codex should omit `--with-effort`.

**Issue:** No dispatcher passes `--risk` to `launch-review` (grep shows only `collect_results.py` retry replay at line 552). Launch always uses `resolve_model_args(..., with_effort=True)` and always wraps Cursor with `/max-mode on` (`agents.py` 4355, 4548, 4582). Docs describe opt-in low-risk behavior; implementation is globally high-effort/max-mode for all `launch-review` callers.

### FINDING_3: Plan-review panel missing competition-notice parity with code-review

**Plan section:** `skills/design/references/plan-review.md` § Competition notice (lines 28–32, 97).

**Issue:** Code-review achieves competition notice via the opt-in launch flag chain. Plan-review panel does not pass `--competition-notice` on waterfall (Finding above) and `render plan-review` does not embed the block. If the intended contract is “panels pass the flag,” plan-review fails; if the intended contract is “panels inject competition text,” plan-review also fails on the native Python render path.

## Summary

- **Confirmed correct:** Code-review panel passes `--competition-notice` when `competition-notice.md` exists; voting, decompose, and aggregation omit it.
- **Not confirmed:** Plan-review panel does not pass `--competition-notice` on waterfall, and rendered plan-review prompts lack the competition block.
- **Accidental globals:** STRICT CONSTRAINTS preamble + `/max-mode on` + Codex `with_effort=True` apply to every `launch-review` caller (including voters, decompose, aggregator), not only reviewer panels. Documented `--risk low` suppression is not implemented at any caller surface.
