## Edge cases

- **Malformed `code-review-tally.json`:** Callers return no fallback rows before the helper runs; the helper is not invoked on unreadable JSON.
- **Malformed individual counts:** Each count coerces to `0` independently; a valid sibling count still expands (e.g. `accepted_count="bad"`, `rejected_count=2` → two rejected rows).
- **Malformed review JSONL:** Do not fall back to tally rows.
- **Direct fluff execution:** `python3 skills/fluff-analysis/scripts/fluff-analysis.py ...` must still work; bootstrap must use `parents[3]` so `<repo>/python` resolves, not `skills/python`.
- **Successful secret scrub:** Commit/publish proceeds and warns to rotate.
- **Scrub command failure:** Publish aborts with non-zero log-publish exit and fatal design-publish rc **5**. Do not silently treat this as an ordinary log PR failure.
- **Residual secret after scrub:** Abort before writing or committing the affected artifact.
- **Run-log commit scrub failure:** Treat as `SecretScrubFailure` even when pre-copy scrubbing succeeded; do not return recoverable `PUBLISH_OK=false` / exit **0**.
- **Run-log commit non-scrub failure:** No commit produced, git status/add errors, or default-branch refusal remain recoverable `PUBLISH_OK=false` / exit **0**.
- **Symlink during tree copy:** Still skip or return `(False, 0)` without `SecretScrubFailure`; must not become fatal rc **5**.
- **Push/PR failure after successful scrub:** Remains recoverable (`PUBLISH_OK=false`, design publish rc **0**, `RECOVERY_BRANCH` when applicable).
- **Worktree/init or preflight publish miss:** Remains recoverable (`publish.returncode == 0`, `PUBLISH_OK=false`, no `RECOVERY_BRANCH`, design publish rc **0**); must not be misclassified as scrub-fatal rc **5** or drop `PUBLISH_OK=false` from the result env.
- **Log-publish crash or partial stdout:** `design publish` must branch on `publish.returncode != 0` without `RECOVERY_BRANCH` even when `PUBLISH_OK` is absent from parsed KVs; must not fall through to `return 0`.

## Failure modes

- **Import bootstrap wrong in fluff script:** Using `parents[2]` inserts `skills/python` and direct script invocation fails. Pin `parents[3]` and test from the script path with a harness path-resolution assert.
- **Helper changes row shape or per-count semantics:** Audit or fluff reports drift. Keep caller-owned record construction and canonical `int(str(value))` coercion.
- **Scrub failure mapped to rc 1 or left at rc 0:** Step 5c may treat publish as success while logs are uncommitted or partially scrubbed. Pin rc **5** and test `failed-publish-tail`.
- **`publish.returncode` ignored in `design_publish`:** Even after log-publish learns non-zero scrub exits, the current tail always returns **0**. Branch on returncode immediately after the subprocess; do not require `PUBLISH_OK=false` in stdout.
- **Missing recoverable branch for exit 0 without `RECOVERY_BRANCH`:** Worktree/init and other non-scrub misses already exit log-publish with `PUBLISH_OK=false` and no recovery branch. Without an explicit branch, implementers may mis-route these to scrub-fatal rc **5** or omit `PUBLISH_OK=false` from the result env while still returning **0**.
- **Over-broad fail-closed change:** Symlink skips, worktree/init failures, or PR push/create recovery may become hard-fail. Keep `SecretScrubFailure` limited to explicit scrub faults; regression-test push/PR/symlink and worktree/init paths stay exit **0**.
- **Run-log commit scrub miss:** Second scrub gate in `run-log commit` can fail after successful pre-copy scrub; without explicit classification, design publish returns **0**. Add targeted subprocess-path test.
- **Rotation warning removed by mistake:** Existing warning tests should catch this.
