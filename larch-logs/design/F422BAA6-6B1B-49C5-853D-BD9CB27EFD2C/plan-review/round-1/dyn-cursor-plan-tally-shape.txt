## Findings

**1. correctness / architecture** — `plan.txt:51-56` vs `python/test_audit_runs.py:646-663`

The plan says the helper returns `[]` for **malformed counts** or **absent counts**, while line 54 also says invalid values become `0`. Current callers coerce **each count independently**: `accepted_count="bad"` with `rejected_count=2` still yields two rejected rows (`test_scan_run_absent_review_findings_self_review_tally_populates_blank_stats` expects `blank == 2`). A helper that returns `[]` when any count is malformed would change fallback behavior, not just deduplicate constants.

**Suggested revision:** Reserve `[]` for non-dict input, non-`self-review` mode, or unreadable tally JSON (caller-side). Coerce each count independently: invalid/missing → `0`, negative → no rows for that side, valid sibling count still expands.

**2. [OUT_OF_SCOPE] correctness / latent** — `plan.txt:54`; `python/audit_runs.py:586-590`; `skills/fluff-analysis/scripts/fluff-analysis.py:216-220`

The plan says coercion should match “current callers,” but audit uses `int(str(value))` and fluff uses `int(value)`. Float values like `2.5` would diverge (audit → `0`, fluff → `2`). No test covers this; `write_self_review_tally` likely emits integers only.

**Suggested revision (if ever unified):** Pin `int(str(value))` in the helper and add a one-line test only if float input is plausible.
