Foreground-by-default for blocking script calls from skill orchestrators

## Problem

Skill orchestrators (notably `/implement`, `/design`) sometimes invoke single-call blocking scripts with `run_in_background: true`. Confirmed offenders include `review-and-fix.sh` and `ship-pr.sh`; a repo-wide audit will refine the set.

**Verified behavior**: when Claude uses the Bash tool with `run_in_background: true`, the tool returns immediately with a task ID and stdout/stderr are NOT delivered to the conversation or UI until the command completes (or Claude polls via `BashOutput` / `Monitor`). Breadcrumbs emitted by scripts on FD 1/2 and via `lib-quiet.sh` on FD 3 are invisible to the user in real time.

**Two failure modes**:
1. **Bad UX** — operator loses progress visibility during multi-minute blocking calls.
2. **Turn-boundary risk** — the task-completion notification fires asynchronously and can land after the orchestrator has ended its turn, requiring user intervention to recover (see issue #2454 and `skills/implement/SKILL.md` NEVER #16, both motivated by exactly this failure for `ship-pr.sh`).

## Current state (grep-confirmed)

Two-family pattern is already in use today, but not normative:

- **Family A (background OK)** — parallel agent launches (`launch-review.sh` / `launch-codex-implement.sh` / `launch-cursor-implement.sh`) awaited by `collect-agent-results.sh`. `run_in_background: true` is correct here and explicitly documented at each call site (`sketch-launch.md`, `dialectic-execution.md`, `research-phase.md`, `validation-phase.md`, `voting-protocol.md`, `dialectic-protocol.md`).
- **Family B (foreground required)** — single blocking calls. Some sites have explicit "Do NOT set `run_in_background: true`" prose (`ship-pr.sh` NEVER #16, `ci-wait.sh` in `rebase-rebump-subprocedure.md:184`, `run-step5-review.sh` at `SKILL.md:1202`, every `collect-agent-results.sh` site), but the guidance is scattered and reactive (added per-incident, not preemptive).

The Bash tool's own description biases Claude toward background for long-running commands: *"Only use this if you don't need the result immediately and are OK being notified when the command completes later."* Without a global override + per-site reminders, Claude inconsistently chooses background — especially after context compression in long `/implement` runs.

No lint/CI enforcement catches drift.

## Goal

- Foreground is the **default** for blocking script calls from skill orchestrators.
- Background is allowed only for: (a) parallel agent launches awaited by a single foreground collector; (b) scripts explicitly designed for `Monitor`-based tailing.
- Apply the rule uniformly across all skills.

## Binding decisions (resolved with operator before formalization)

- **Inline marker style** at every Family B Bash block site: BOTH a ⚠ banner above the fence (`**⚠ Foreground required — do NOT set \`run_in_background: true\`.**`) AND an inline `# Foreground required: see BASH_AUTHORING.md §4` comment inside the fence.
- **Denylist style**: by script basename (not full path). False-positive risk is low in larch because wrappers (e.g., `launch-review.sh`) have distinct names from the scripts they invoke.
- **Audit scope**: repo-wide across all skills (`implement`, `design`, `research`, `review`, `review-and-fix`, `ship-pr`, `loop`, `bump-version`, `issue`, plus `skills/shared/*` and any other skill `SKILL.md` / `references/*.md`). Grep already shows mixed usage in `/research` and `/review`.

## Known Family B basenames (starting set; audit will refine)

`ship-pr.sh`, `ci-wait.sh`, `run-step5-review.sh`, `review-and-fix.sh`, `run-step2-dispatch.sh`, `step2-implement.sh`, `collect-agent-results.sh`, `dispatch-with-waterfall.sh`, `dispatch-plan-voters.sh`.

## Hard constraints

- MUST NOT regress Family A invocations (parallel sketch / reviewer / debater / judge / voter launches keep `run_in_background: true`).
- MUST NOT change semantics of any existing skill step; only ADD markers + ADD rule + ADD lint.
- Bash 3.2 portable per `BASH_AUTHORING.md` §3.
- Marker insertion is the work; do not refactor invocation patterns.

## Out of scope

- Inverse lint (catching a Family A allowlist script invoked without `run_in_background: true`). Deferred until a concrete drift case appears.
- Per-skill rewrites beyond marker insertion.

## Acceptance

- `BASH_AUTHORING.md` gains §4 "Foreground Default for Blocking Script Calls" with: (a) the rule, (b) the WHY (breadcrumb visibility + turn-boundary safety, citing issue #2454 / NEVER #16), (c) the exception list (Family A, Monitor-tailed).
- `AGENTS.md` "Conventions" cross-references §4 in one line.
- Every Family B invocation in `skills/**/SKILL.md` and `skills/**/references/*.md` has BOTH the ⚠ banner AND the `# Foreground required` inline comment within ±20 lines of the invocation.
- Lint target (`make lint-foreground` or extension of `scripts/test-design-structure.sh` / `scripts/test-implement-structure.sh`) exists and asserts both markers for every denylisted-basename invocation site. Fails CI on drift.
- `make lint` regression-clean; existing structure tests regression-clean.
