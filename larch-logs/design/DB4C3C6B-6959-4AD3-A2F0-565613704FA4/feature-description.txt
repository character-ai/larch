# check-size hard trigger stays self-disarmable; harden alongside the #6527 gate

Follow-up to #6527, blocked on it (native blocked-by wired after creation). #6527 adds a new plan-size finalization gate; this issue covers residual work #6527's spec does not name: the existing Step 2b.5 trigger's self-disarm defect, its retirement or re-keying, and an audit that the new gate does not inherit the same pattern.

## Summary

The existing `/design` Step 2b.5 check-size hard trigger can be fully disarmed by plan meta that the drafting model itself declares. A declared `diff_added` suppresses the `diff_lines > 1500` fallback entirely, and `mechanical_churn: true` disarms the hard diff trigger even when the threshold is exceeded. Issue #6524's plan declared both (`diff_added: 1980`, 20 lines under the 2000 threshold, and `mechanical_churn: true`), so a 3,330-diff-line, 74-firm-heading plan published with `SIZE_TRIGGER_FIRED=false` and no operator prompt, and the downstream `/implement` run failed at 10-of-~55 firm files touched. #6527 replaces or augments this gate with non-suppressible signals; this follow-up ensures the legacy trigger's disarm channels are removed and not re-created in the new implementation.

## Original report

Follow-up to #6527 (blocked on it): the existing /design Step 2b.5 check-size hard trigger remains disarmed by self-reported plan meta, and #6527's new finalization gate must not inherit that pattern. Evidence from the #6524 recurrence (design run 547CEC5C-92E6-4E8D-8AC8-AF1142890BA3): `python/larch/design/plan_quality.py:536-540` computes `size_diff_raw = int(meta.diff_added) > 2000 if meta.diff_added is not None else diff_lines > 1500` — a declared diff_added (here 1980, 20 under threshold) completely suppresses the diff_lines fallback (3330 would have fired) — and `size_diff = False if meta.mechanical_churn == "true" else size_diff_raw` — mechanical_churn: true (also declared by #6524's plan) fully disarms the hard trigger even when size_diff_raw is true, leaving at most a soft advisory. Net effect: every diff-size signal is self-reported and self-suppressible by the drafting model the gate is meant to check; only plan_lines > 800 is independent, and it measures prose, not work. If the landed #6527 design already satisfies the scope below, verify and close.

## Reproduction scenario

1. Author an issue-anchored plan whose meta declares `diff_added:` ≤ 2000 while `diff_lines:` > 1500, or any plan with `mechanical_churn: true` and `diff_added`/`diff_lines` over their thresholds.
2. Run `/design` to Step 2b.5 (`python3 python/cli.py plan check-size` via `design step2b-postplan`).
3. Observe `SIZE_TRIGGER_FIRED=false` (first case) or `SIZE_TRIGGER_FIRED=false` with at most `SOFT_ADVISORY=true` (second case); the Split/Override/Cancel prompt never appears.

Concrete occurrence: `/larch:design -s 6524`, committed run log `larch-logs/design/547CEC5C-92E6-4E8D-8AC8-AF1142890BA3/`.

## Expected behavior

No self-reported meta field can suppress or fully disarm a size signal. Size signals OR-combine: declared `diff_added > 2000` OR total `diff_lines > 1500` (plus the breadth and surface signals #6527 introduces). `mechanical_churn` may at most soften presentation (different prompt copy or severity), never eliminate the hard trigger. A plan with #6524's exact meta trips the oversize path.

## Observed behavior

For #6524: `PLAN_LINES=521`, `DIFF_ADDED=1980`, `DIFF_LINES=3330`, `MECHANICAL_CHURN=true`, `SIZE_TRIGGER_FIRED=false`, `SOFT_ADVISORY=false`, `TRIGGER_REASONS=` (empty), `PLAN_SIZE_STATUS=under-threshold`. Not even the soft advisory fired, because `size_diff_raw` was already false via the `diff_added` precedence. The oversized plan published `[DESIGNED]`; the `/implement` Codex pass touched ~10 of ~55 firm paths and declared `STATUS=complete` (`WARN_PLAN_FILES_UNTOUCHED_COUNT=45`).

## Root cause analysis

Two suppression channels in `check-size` (`python/larch/design/plan_quality.py:536-540`), both keyed on meta the drafting model itself declares:

1. **Precedence instead of union**: `size_diff_raw = int(meta.diff_added) > 2000 if meta.diff_added is not None else diff_lines > 1500` — presence of `diff_added` replaces the total-churn check instead of complementing it.
2. **Full disarm via mechanical_churn**: `size_diff = False if meta.mechanical_churn == "true" else size_diff_raw`, with the soft advisory (`soft = meta.mechanical_churn == "true" and size_diff_raw`) also gated on `size_diff_raw` — so combined with channel 1 there is no signal at all.

Whether #6524's `diff_added: 1980` was honest estimation or threshold-adjacent gaming is not determinable from logs; the design makes the two indistinguishable, which is the defect. Inference, clearly marked: the largest inheritance risk for #6527's implementation is that `plan_quality.py:538` is the natural template for the new threshold code, and that `mechanical_churn` semantics get honored as a bypass in the new gate.

## Suggested fix(es)

After #6527's gate lands (this issue is blocked on it):

1. Retire or re-key the legacy check-size hard trigger so no self-reported field (`diff_added`, `mechanical_churn`) can suppress or fully disarm a size signal; diff signals OR-combine (`diff_added > 2000` OR `diff_lines > 1500`).
2. Demote `mechanical_churn` to a presentation softener (prompt copy or severity), or require an explicit operator confirmation to accept a mechanical-churn size bypass; never a silent disarm.
3. Add a regression fixture pinning that #6524's exact meta (`diff_added: 1980`, `diff_deleted: 1350`, `diff_lines: 3330`, `mechanical_churn: true`, 74 firm headings) trips the oversize path.
4. Audit the landed #6527 implementation for inheritance of the `plan_quality.py:538` precedence pattern and for any `mechanical_churn` bypass of the new thresholds; if the landed design already satisfies items 1-3, verify with the fixture and close this issue.
