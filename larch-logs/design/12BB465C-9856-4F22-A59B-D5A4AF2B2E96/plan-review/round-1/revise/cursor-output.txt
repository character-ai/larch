## Approach

`approach-synthesis.txt` is `NO_SKETCHES`, so draft from direct repo inspection only.

Implement the minimum shared fixes:

1. **No-issues salvage**
   - Parse structured JSONL/TSV records first.
   - If records exist, return them unchanged.
   - If no records exist, salvage a clean pass when there is **exactly one** standalone no-issues sentinel line among all non-blank lines (narration/prose on other lines is allowed).
   - Accept a standalone line that is either `NO_ISSUES_FOUND` or a JSON object whose `no_issues_found` value is `true`.
   - Emit a non-failure warning when that accepted sentinel was not the first non-blank line.
   - Keep findings output strict.

2. **Cursor parity**
   - Keep the existing `schema_version` guard in `_review_cursor_normalize_no_issues`.
   - Preserve current first-line inline normalization behavior for existing tests.
   - Add standalone-line detection so prose followed by `{"no_issues_found": true}` collapses to the canonical one-line sentinel.

3. **Launch-failure site labels**
   - Add `--site` to `agent launch-review`, defaulting to `review Step 2`.
   - Validate and thread it into `_review_append_launch_failure`.
   - Thread it through `agent dispatch-waterfall` and `agent dispatch-voters`.
   - Pass `design Step 3` from plan-review panel and voter dispatch.
   - Pass or derive `implement Step 5` for review-and-fix Step 5 review core and voter dispatch.
   - Normalize `_append_implement_launch_failure` from site `2` to `implement Step 2`.
   - Persist the validated site in launch-review `.meta` and replay it on collect-results outer retries.

4. **Review collection sentinel guard (no early drop)**
   - Do **not** short-circuit markdown parsing when a standalone JSON sentinel appears alongside real findings.
   - Treat prose-plus-trailing-sentinel as clean only in the collect fallback path after TSV and markdown parsing both return zero rows.

## Edge cases

- **Valid findings plus sentinel:** keep findings. Structured salvage never fires when records exist; review collection must parse markdown/TSV first and only then treat a trailing sentinel as clean when zero rows were parsed.
- **Multiple sentinels:** do not salvage.
- **Inline JSON in narration:** only Cursor's existing first-line compatibility path may normalize it. The shared validator and review-pipeline standalone helper require a standalone line.
- **`schema_version` output:** Cursor normalizer must not collapse findings-shaped output.
- **Site labels with spaces:** allow spaces. Reject control characters.
- **Default callers:** callers that do not pass `--site` keep `review Step 2`.
- **Retry without meta site:** collect-results retry omits `--site` and launch-review falls back to its default.

## Failure modes

- If the warning is emitted on stderr, collectors must treat it as informational on validator exit 0.
- If `--site` is missing from a `_parse_args` allowlist, downstream argv fails with `unknown option: --site` and site threading silently stops.
- If review collection reintroduces an early sentinel short-circuit in `_parse_output`, clean-pass detection can drop real markdown findings.
- If voter dispatch or retry meta omits site, launch failures may still log under `review Step 2`.
