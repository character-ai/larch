Bash derives two windows per round from `timing-ledger.tsv`: table Time/Cost/token attribution use skill-filtered `type=round` rows (`$4==SKILL`); Gantt uses the wider skill-agnostic overlap window. Tests 11–12 lock this. The plan says "Preserve Gantt" and "token ledger windows" but never splits table vs Gantt derivation. A single-window port regresses #4537-sensitive output.

**2. correctness — design loop `-x` guard (`skills/design/scripts/review-design-step3-loop.sh:542-545`)**

The plan updates the default writer to `python/cli.py progress write-design-round-meta` but leaves `[[ -x "$_rmd_sh" ]]`. After deleting the `.sh`, that guard fails silently and post-revise metadata stops refreshing.

**3. correctness — settled Gantt status filter (`python/progress_report.py:538-559`)**

Existing `_progress_vendor_rows()` skips vendor rows unless status is `complete|OK`. Bash settled Gantt awk has no status gate. Reusing the inflight helper for final-report Gantt would drop valid rows.

**4. correctness — singular `reviewer` fallback (`scripts/render-review-phase-detail.sh:305-310`)**

Top-N attribution must accept legacy JSONL with `reviewer` only. The plan covers top reviewers generally but not this fallback tested in harness Test 6.

**5. correctness — Cost `$0.00` vs em dash (`scripts/render-review-phase-detail.sh:171-208`)**

Missing ledger → em dash; ledger present with zero in-window vendor tokens → `$0.00`. The plan does not pin this distinction, which affects per-round and Total cost rows.
