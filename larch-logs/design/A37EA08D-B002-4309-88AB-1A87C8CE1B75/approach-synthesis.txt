## Approach Synthesis

Both sketches (Cursor-Generic via Claude fallback, Codex-Generic) converge strongly on a near-identical architecture. There are **no contested decisions**.

### Agreement (both sketches)

- **Persistence mechanism**: `manual_gate_b` is a new boolean in `$DESIGN_TMPDIR/run-params.json`, modeled exactly on `partition_requested` / `brainstorm_requested`. Default value `false` (i.e., auto-apply is default). Written by `scripts/write-run-params.sh` via a new `--manual-gate-b true|false` flag using the same `require_enum ... true false` pattern.
- **Argv parsing**: `--manual` / `-m` is parsed in `skills/design/SKILL.md` Step 0b argv parser alongside existing flags. The flag value is forwarded to `write-run-params.sh` so it appears in `run-params.json`. Whole-run sticky (no mid-run toggle).
- **Gate B behavioral edit (single normative source)**: `skills/design/references/approval-gates.md` is the load-bearing edit. The Gate B Prompt section gains a leading branch:
  - When `manual_gate_b == true` (or absent → coerce to `false` → auto-apply): execute the existing **Apply all** body verbatim, but preceded by the compact findings list and an explicit auto-apply breadcrumb. No `AskUserQuestion` fires.
  - When `manual_gate_b == true`: the existing 3-option `AskUserQuestion` (Apply all / Go through each / Switch to discussion mode) fires unchanged.
- **Invariant rewrite**: State Invariant #4 ("No-auto-apply contract") in `approval-gates.md` is revised to describe the new dual-mode contract: auto-apply default plus `--manual` opt-out. Gate A and Gate C remain free of auto-revision. The tally script still writes artifact files only (no plan.txt mutation).
- **Pipeline reuse**: the auto-apply branch funnels into the SAME downstream pipeline the existing "Apply all" branch already uses — dedup-sweep → `dedup-sweep:` breadcrumb → `ACTION=EMIT_PLAN` → `invoke-plan-validator-if-not-quick.sh` (when `review_budget=full`) → Step 2b.5 plan-size check → Step 3b. This preserves every existing invariant by construction.
- **Visibility**: print a compact findings list (FINDING_N, severity, reviewer, concern excerpt) and a `🔶 /design 3.5: gate B (auto-apply N findings)` breadcrumb on the auto-apply path so operators see what is being applied.
- **flags.md**: full per-flag entry for `--manual` / `-m` documenting scope (Gate B only), default behavior change, whole-run sticky semantics, and the run-params.json key name.
- **Fallback recovery**: every Gate B reader uses `jq -r '.manual_gate_b // false'` so a missing key (older run-params.json, upgrade mid-flight, jq merge failure path) safely coerces to `false` = auto-apply default.
- **Tests**: `scripts/test-write-run-params.sh` (and any other tests asserting on run-params.json schema) get a `manual_gate_b: false` default-case update.
- **Coordination with #2667**: this issue lands first; #2667 is marked blocked-by this issue via native GitHub Issue Dependencies API. Per #2667's existing plan it will reconcile its multi-round Gate B presentation rebase on top of the new default once both are merged.

### File-by-file impact (consolidated from both sketches)

1. **`scripts/write-run-params.sh`** — add `--manual-gate-b` flag (`require_enum ... true false`), `MANUAL_GATE_B` variable, `--arg manual_gate_b "${MANUAL_GATE_B:-false}"` jq binding, and `manual_gate_b: ($manual_gate_b == "true")` in the emitted JSON. Mirror the existing `partition_requested` / `brainstorm_requested` pattern. Update sibling `scripts/write-run-params.md` to describe the new field.
2. **`skills/design/SKILL.md`** — argv parser recognizes `--manual` / `-m`; sets internal `manual_requested=true|false`; forwards as `--manual-gate-b $manual_requested` to `write-run-params.sh`; flag-table row added; jq-merge recovery path on write failure also persists the new field; SKILL.md Step 3.5 prose updated to delegate Gate B mode handling to `approval-gates.md` (one-sentence pointer).
3. **`skills/design/references/approval-gates.md`** — Gate B Prompt section gains the `manual_gate_b` leading branch; auto-apply path adds compact findings list + breadcrumb; State Invariant #4 rewritten; "Cross-tier invariant" prose updated to note the auto-apply default applies uniformly across all tiers; per-tier behavior unchanged for `--trivial`/`--simple`/`--hard` other than that mode flip.
4. **`skills/design/references/flags.md`** — full per-flag entry for `--manual` / `-m`; mutual-exclusion section left unchanged (`--manual` is independent of all tier/partition/brainstorm flags); persisted field name (`manual_gate_b`) documented.
5. **`scripts/test-write-run-params.sh`** — extend to cover `manual_gate_b: true` and `manual_gate_b: false` paths; also assert the default-absent → `false` shape if the test framework exercises that.

### Highlight: tradeoffs and risks (both sketches)

- **SKILL.md ↔ approval-gates.md drift**: the behavioral edit lives only in `approval-gates.md`; SKILL.md adds a one-sentence pointer and argv plumbing. As long as that delegation is enforced, drift stays bounded.
- **run-params.json fallback recovery**: defensive `jq -r '.manual_gate_b // false'` idiom at every read site keeps the upgrade-mid-flight / jq-write-failure paths sane.
- **Step 3 re-entry from Gate C(c) Re-run review panel**: the flag is whole-run sticky via `run-params.json`, so re-entries Just Work — there's no mid-run mode-switch UI by design (declined in Round 1 Decision 6).
- **Pre-prompt visibility**: the compact findings list adds output even on the silent auto-apply path; operators might confuse the list with a coming prompt. The breadcrumb wording (`🔶 /design 3.5: gate B (auto-apply N findings)`) and the absence of an `AskUserQuestion` resolve the ambiguity.
- **Coordination with #2667**: addressed by GitHub blocker dependency; no shared-branch overhead.

### Conclusion

There are no contested decisions. Both sketches arrived at the same architectural choice independently. The implementation plan can proceed directly from the synthesis.
