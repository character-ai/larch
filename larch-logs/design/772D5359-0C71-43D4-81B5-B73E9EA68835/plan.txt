## Edge cases

- **No rejected findings**: emit nothing. Do not print a heading.
- **All rejected findings filtered by applied-key ledger**: emit nothing. Do not print a heading.
- **Ledger missing**: emit the raw rejected body, framed only when `--report-framing` is passed.
- **Unrecognized rejected body with ledger present**: preserve current fail-closed empty emit and warning behavior.
- **CLI failure in tail wrapper**: fallback still frames the raw file so the operator does not see the stale "unimplemented" label.
- **Manual Step 3 re-run from Gate C**: reviewers get the current `plan.txt` through the existing `--plan-file` path. No new state is needed.
- **Premature empty notification**: yield or probe `.completed/step-3-terminal` first; print the post-notification table only after confirmed completion, using the unified sequence above.
- **`latest-reviewer-status.tsv` missing at print time**: bind round from notification stdout KVs first; if still unbound, read only round-binding keys from `.step3-review-result.env`; then use the per-round fallback file. Do not default silently to round 1 without binding.
- **Compact table item vs wait rules**: both must describe the same post-notification sequence (table before full env parse; minimal round-binding read allowed only inside the missing-latest fallback branch).
- **Audit finds no `/implement` hits**: document "no `/implement` change needed" explicitly in the PR audit section; do not add drive-by `/implement` edits.
- **Step 4 orchestrator adds prose**: avoid by making wrapper marker body the sole operator-visible rejected output; no readability-style compose step.
- **Lint manifest drift**: if Step 4 readability directive is removed from `SKILL.md` without updating `lint-readability-preamble.tsv`, `make lint` fails; update the manifest in the same PR.

## Failure modes

- If the SKILL Step 4 text still adds its own heading, the operator may see a duplicate heading. Avoid this by making the wrapper body authoritative and removing orchestrator-side heading composition.
- If fallback `cat` omits framing, failures can reintroduce stale wording. Frame fallback output too.
- If the prompt text is added only to static roles, dynamic scout reviewers can still re-raise already-covered concerns. Add the instruction to the shared scaffold.
- If post-notification table printing stays only in the Compact reviewer status table nested list and not in both wait rules, strict orchestrators may skip the table entirely. Relocate the print into both wait rules with the same sequence text.
- If the Compact table item still says "parse `.step3-review-result.env` for round binding, then show table" while wait rules say "print table before parsing env", strict orchestrators will follow conflicting instructions and may show the wrong round or skip the table. Use one shared three-step sequence in both places.
- If "between the two permitted prints" language survives the cadence edit, orchestrators may treat mid-wait churn as allowed and reintroduce stale pre-launch-style tables. Use single-print-only guidance.
- If per-round fallback runs without round binding when `latest-reviewer-status.tsv` is absent, the table can default to round 1 and misrepresent the panel. Require notification stdout or minimal env key scan first.
- If the #4838 audit is skipped, the umbrella issue stays open. Record grep output and the `/implement` no-change conclusion in the PR body.
- If `lint-readability-preamble.tsv` is not updated when Step 4 readability directive is removed, `make lint` fails on `readability-preamble` verification.
- If a plan example fence is left unclosed inside `### UPDATED:` sections, later file targets may render as example text instead of actionable steps. Close every example fence before the next `### UPDATED:` heading.
