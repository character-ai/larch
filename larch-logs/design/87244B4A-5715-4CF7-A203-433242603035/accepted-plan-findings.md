### FINDING_1: New Step 0b sub-step should be numbered 2.5, not 3.0
- **Concern**: The plan names the new title-filter sub-step "3.0", but the existing Step 0b decimal-numbering pattern uses N.M form (1, 2, 3, 4, 5, 5.5, 6 today). Renumbering disrupts existing references in `scripts/test-design-structure.sh` and operator-facing prose.
- **Proposed resolution**: Rename the new sub-step to **2.5** throughout the plan. This mirrors the existing 5.5 pattern (inserts a decimal sub-step between two integer sub-steps without renumbering downstream items).

### FINDING_2: Reject-exit must call the Final summary block with a new SUMMARY_OUTCOME enum value
- **Concern**: All existing /design Step 0b early-exit paths (clarify cancel, already-planned cancel, tier-gate cancel) export a `SUMMARY_OUTCOME=cancelled-*` value and run the `### Final summary block` fenced bash block before `exit 0`. The plan currently says "prints the banner and exits 1" without this hygiene, which violates SKILL.md's explicit enum contract (`cancelled-clarify | cancelled-already-planned | cancelled-tier-gate | cancelled-sprawl | cancelled-plan-size-hard | cancelled-decompose | approved | approved-partition | failed-plan-write`) and skips the post-Step-0a summary that operators rely on.
- **Proposed resolution**: (a) Extend the SKILL.md enum list with `cancelled-title-filter` (or `refused-title-prefix` — pick one in plan revision). (b) Before `exit 1` on the lifecycle-reject and archival-report-reject branches of the new sub-step 2.5, export the new enum value and run the `### Final summary block` fence (same as the cancel sub-steps above). (c) Preserve `$DESIGN_TMPDIR` (Step 6 cleanup is already skipped on non-`approved` outcomes per the existing pattern). Exit code stays 1 (distinct from `exit 0` of cancel paths) so CI/`make` consumers can distinguish "operator cancelled" from "title-filter blocked".

### FINDING_3: list-issues.sh source-path resolution needs a verified precedent
- **Concern**: The plan proposes `${BASH_SOURCE%/*}/../../../scripts/lib-title-eligibility.sh` from `skills/issue/scripts/list-issues.sh` without anchoring to an existing pattern. If the established convention in the codebase uses a different form (e.g. `$(cd "$(dirname "$0")/../../.." && pwd)/scripts/lib-...sh`, or `${LARCH_PLUGIN_ROOT}/scripts/...`, or sourcing through a wrapper), inventing a new form increases divergence risk.
- **Proposed resolution**: At implementation time, run `grep -rn 'source.*scripts/lib-' skills/*/scripts/*.sh` (and equivalents for `\. \"`) to enumerate existing cross-tree sourcing patterns. Adopt the dominant pattern verbatim and pin it in `lib-title-eligibility.md`'s "Primary callers" section. If no precedent exists, prefer the `CLAUDE_PLUGIN_ROOT`-based form for consistency with SKILL.md Bash blocks.

### FINDING_4: Document filter ordering rule explicitly in the new sub-step
- **Concern**: A title like `[DESIGNING] Brainstorm: foo` matches both lifecycle-reject AND brainstorm. The plan implicitly assumes lifecycle-reject runs first (short-circuits before brainstorm), but doesn't say so. A future edit could reorder the three predicate calls and silently change behavior (brainstorm-with-[DESIGNING] would then auto-enable brainstorm AND immediately reject, which is incoherent).
- **Proposed resolution**: Add one sentence to the new sub-step 2.5 prose stating: "Predicate ordering is mandatory: (a) `title_has_lifecycle_reject_prefix` (exit on match), (b) `title_has_archival_report_prefix` (exit on match), (c) `title_starts_with_brainstorm` (set flag and continue on match). Earlier matches short-circuit; only the brainstorm predicate is non-exiting." Add a single anchor line in `scripts/test-design-structure.sh` pinning the order.
