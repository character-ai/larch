# Implementation Plan — Issue #2395 (ship-pr.sh subagent escalation) — Revised

**This is the FINAL implementation plan** — post Step 3 plan-review (29 of 32 in-scope findings accepted unanimously, 2 exonerated, 1 rejected, 1 OOS accepted). ## Goal

Reduce main-agent bail interruptions out of `scripts/ship-pr.sh` by absorbing recoverable exits into in-script logic with a uniform 3-tier waterfall (Cursor → Codex → Claude, ONE try each) plus a bounded transient-network retry. Waterfall hooks into 4 stall sites (with the additional earlier `exit_stall 6` site for `resolve_checks_log_path` failure); 3 `exit 5` resume-paths become in-script mechanical; 6 transient-net sites get a 3-attempt jittered-backoff helper that is **envelope-aware** (also classifies rc=0 `MERGE_RESULT=error|admin_failed` / `ACTION=bail BAIL_REASON=...transient...` envelopes). CI-fix work (existing `run_ci_fix_vendor` AND new waterfall paths) must reproduce the failed job locally — enforced via vendor-prompt text + the existing post-launch `run_checks_with_lint_fix_loop`. Out-of-scope: bump-branch-guard, classify/apply-bump errors, CI watch exits, `exit_stall 12d`, `exit 3` user-input bails. UX-driven goal (fewer bails), not a cost-reduction promise.

## Detail (revised) — ship-pr.sh additions

### run_recovery_waterfall <phase> <fail_file> [--conflict-files CSV]

Private function placed near `run_ci_fix_vendor` (~line 1216). Inputs:
- `phase` ∈ `checks` / `pr-prep` / `pr-create` / `rebase-nonbump`. Drives BOTH the vendor `--role` (mapped below) AND the post-tier verifier selection.
- `fail_file` (failure-log path captured by calling phase function).
- `--conflict-files CSV` (optional; only set for `rebase-nonbump`).

Vendor role mapping (resolves FINDING_15/F20/F32 — unified across all CI launchers):
- `checks` / `pr-prep` / `pr-create` → vendor launchers use `--role fix`.
- `rebase-nonbump` → vendor launchers use `--role resolve-conflict --conflict-files <CSV>`.

Per-phase post-tier verifier (resolves FINDING_27, FINDING_29):
- `checks` / `pr-prep`: `run-relevant-checks-captured.sh --site step6 --tmpdir "$IMPLEMENT_TMPDIR"`. Pass = `RELEVANT_CHECKS_OK=true` or `RELEVANT_CHECKS_SKIPPED=true`.
- `pr-create`: re-run the actual failing helper that triggered the waterfall (`write-final-report.sh --implement-tmpdir ...` for line-1104 site; `create-pr.sh --title ... --body-file ...` for line-1138 site). Pass = the helper returns 0 with parseable envelope. The caller stores the helper invocation as a `verify_cmd_array` before calling the waterfall.
- `rebase-nonbump`: after each tier emits its fix, run `GIT_EDITOR=true git rebase --continue`; if successful, verify via `_run_rebase_rebump_verify_plain_no_push`. Pass = both succeed.

Sequence (3 tiers, ONE attempt each, NO retries within a tier):

**Tier availability** (resolves FINDING_2/F10/F20): use `command -v cursor`, `command -v codex`, `command -v claude` (matches existing pattern in `run_ci_fix_vendor:1227-1234`). Do NOT introduce new session-env-based gating that diverges from existing behavior; existing `command -v` is the canonical truth.

**Pre-tier baseline capture** (per tier): under `$IMPLEMENT_TMPDIR/recovery-waterfall/<phase>/<tier>/`, write:
- `baseline-head.txt` from `git rev-parse HEAD`.
- `baseline-tracked.txt` from `git diff --name-only HEAD` (includes both unstaged AND staged-vs-HEAD changes — confirmed by inspection).
- `baseline-untracked.txt` from `git ls-files --others --exclude-standard`.
- `baseline-staged.txt` from `git diff --cached --name-only` (FINDING_26 — explicitly track staged-vs-index delta).

**Per-tier dispatch** with `--failure-log` injection (FINDING_21/F28):
- Tier 1 — Cursor: `launch-cursor-ci.sh --role <vendor_role> --output ... --run-id ... --repo ... [--plan-file ...] [--conflict-files ...] --failure-log "$fail_file" --timeout 1800`.
- Tier 2 — Codex: same argv shape with `launch-codex-ci.sh`.
- Tier 3 — Claude: same argv shape with `launch-claude-ci.sh`.

**Post-tier HEAD assertion**: `git rev-parse HEAD == baseline_head`. If a tier silently committed, hard-fail with `head-changed-after-dispatch` (mirrors `lint-fix-loop.sh:273-275`). Append diagnostic to `$fail_file` via `record_failure`.

**Post-tier verify**: per-phase verifier above. On pass, proceed to commit-and-push (for `checks` / `rebase-nonbump` phases that produce working-tree edits); skip commit/push for `pr-prep` / `pr-create` phases (verify-as-rerun already validated the helper's outcome, no edits to commit).

**Tier rollback on verify-fail** (resolves FINDING_14/F23, FINDING_7, FINDING_26 — Bash 3.2 safe, quoted-path discipline):
```bash
# Tracked delta: paths now-tracked-dirty minus baseline-tracked-dirty.
# Use newline-delimited temp files (Bash 3.2 — no associative arrays).
post_tier_tracked=$(mktemp)
git diff --name-only HEAD > "$post_tier_tracked"
comm -23 <(LC_ALL=C sort -u "$post_tier_tracked") <(LC_ALL=C sort -u "$DESIGN_TMPDIR/.../baseline-tracked.txt") > "$tracked_delta"

# Reset staged delta first (FINDING_26).
while IFS= read -r path || [[ -n "$path" ]]; do
    [[ -n "$path" ]] || continue
    git restore --staged -- "$path" 2>>"$fail_file" || true
done < "$staged_delta"

# Then revert working-tree changes via `--` sentinel + quoted argument (FINDING_14/F23).
while IFS= read -r path || [[ -n "$path" ]]; do
    [[ -n "$path" ]] || continue
    git checkout -- "$path" 2>>"$fail_file" || true
done < "$tracked_delta"

# Remove untracked-delta files (FINDING_14/F23).
while IFS= read -r path || [[ -n "$path" ]]; do
    [[ -n "$path" ]] || continue
    rm -f -- "$path" 2>>"$fail_file" || true
done < "$untracked_delta"

# Forbidden-path/submodule safety (FINDING_7): if `.gitmodules` exists at HEAD and the
# delta paths touch any registered submodule, delegate to lint-fix-loop's
# `post_dispatch_forbidden_revert` helper (sourced or invoked via the equivalent
# shell snippet) rather than the raw paths above.
if [[ -f .gitmodules ]] && grep -F -x -f <(git config --file .gitmodules --get-regexp 'submodule\..*\.path$' | awk '{print $2}') "$tracked_delta" >/dev/null 2>&1; then
    # Fall through to forbidden-revert helper extracted from lint-fix-loop:99-135
    _run_recovery_waterfall_submodule_safe_revert "$tracked_delta" "$untracked_delta" "$fail_file"
fi
```

Rollback failure logged as a Warning but does NOT block next tier (next tier captures its own baseline against post-rollback state).

**Tier success path**: commit + push via existing flow when working-tree edits exist (use the full sequence from `run_ci_fix_vendor:1244-1306` — `collect_ci_stage_paths` + `git add` + `git-commit.sh` + `append-token-record.sh` + `refresh-run-logs.sh` + `git-push.sh`). For `pr-prep` / `pr-create` phases, no commit (verify-as-rerun is the success signal).

**Return contract**: returns 0 on tier success (caller advances phase); returns 1 with `WATERFALL_EXHAUSTED=true` written to `$fail_file` if all tiers fail (caller `exit_stall`s as today).

### with_transient_retry <out_var> <fail_file> <transient_envelope_predicate> <cmd...>

Private function placed near `exit_transient_net` (~line 653). 3 attempts with jittered exponential backoff:
- base = `2 * 2 ** (attempt - 1)` (2, 4, 8)
- jitter = `RANDOM % (base / 2 + 1)`
- sleep = `base + jitter - base / 4`, minimum 1s
- Reuses the math at `scripts/ship-pr.sh:1352-1360`.

**Envelope-aware classification** (resolves FINDING_1/F19/F11): after each attempt, the helper classifies as transient if EITHER:
- (a) exit code is non-zero AND `is_transient_net_signature "$(cat $fail_file)"` returns true (existing behavior — `fail_file` carries combined stderr+stdout per `capture_command_output`, resolving FINDING_5/F30); OR
- (b) the per-callsite `transient_envelope_predicate` returns true. Predicate is a function name; ship-pr.sh defines two predicates:
  - `transient_envelope_predicate_merge_pr`: returns 0 (transient) when stdout shows `MERGE_RESULT=error` or `MERGE_RESULT=admin_failed` AND `is_transient_net_signature "$ERROR_field"` is true.
  - `transient_envelope_predicate_ci_wait`: returns 0 (transient) when stdout shows `ACTION=bail` AND `BAIL_REASON` matches `is_transient_net_signature`.
  - For the other 4 sites (write-final-report×2, create-pr, rebase-push), pass `transient_envelope_predicate_none` (always returns 1 — falls back to exit-code-only classification, which works because those helpers return non-zero on transient failure).

After each attempt: if NOT transient, set `$out_var` and return the captured exit code immediately. Only retry when transient.

On exhaustion (3 attempts all transient): fall through to existing `exit_transient_net` (preserves backward-compat for unrecoverable-transient case).

Bash 3.2 safe: `printf -v "$out_var"` (existing pattern at line 86-87), no `local -n`.

## Edge cases

- Tier produces a silent commit → `git rev-parse HEAD == baseline_head` assertion fails → `head-changed-after-dispatch`. Logged as Tool Failures.
- All three tiers unavailable → Warning per skipped tier; waterfall returns `WATERFALL_EXHAUSTED=true` → caller exit_stalls.
- Tier rollback fails on a per-file basis (e.g., `git checkout` of a deleted file fails) → log Warning per failure but continue; the loop is best-effort, not all-or-nothing.
- Non-transient failure on attempt 1 of retry helper → immediate fall-through, no backoff delay.
- Step 8 mechanical: counter reaches 2 → `exit_stall 8` (FINDING_4 persisted counter).
- Force-push-gate mechanical: `implement-finalize.sh postbump --resume-phase force-push-gate` returns `STATUS=conflict` again → `exit_stall 8b`.
- Legacy state load (FINDING_8/F13/F16): pre-upgrade state file carries `RESUME_PHASE=bump CALLER_KIND=step8_apply_bump_same_version` → handler advances to `bump` phase; new mechanical path takes over.
- Legacy state load: pre-upgrade state file carries `RESUME_PHASE=ship-pr-rrr-phase14` + `ship-pr-rrr-after-phase14.flag` → handler runs `run_rebase_rebump` (now waterfall-backed). Flag-clearing semantics retained.
- PR-create dry-run probe alternative ABANDONED per FINDING_29 — re-run actual failing helper (write-final-report.sh / create-pr.sh) as verify.
- Concurrent rebase mid-waterfall: per-tier detached-HEAD probe (mirroring `run_evaluate_failure:1341-1346`) catches; hard-fail that tier; next tier captures fresh baseline.
- Submodule paths in delta (FINDING_7): rollback delegates to `lint-fix-loop.sh`'s forbidden-revert pattern for safety.
- Path with leading dash in delta (FINDING_14/F23): `git checkout -- "$path"` and `rm -f -- "$path"` use `--` sentinel + quotes.
- Path with spaces in delta (FINDING_14/F23): `while IFS= read -r path` preserves whitespace; quoted-arg avoids word-splitting.
- Staged-only changes after tier (FINDING_26): rollback runs `git restore --staged -- "$path"` BEFORE `git checkout -- "$path"`.
- `--failure-log` file is missing when waterfall fires (e.g., the failing helper didn't write a fail file): launchers receive `--failure-log` absent; prompt falls back to generic role text (FINDING_21/F28). Test `failure_log_argv_optional` verifies this.
- Failure-log content >4KB: launcher truncates to 4KB and notes `... [truncated]` in the prompt.
- Failure-log content contains secrets: launcher pipes through `redact-secrets.sh` before injection.
- Bash 3.2 traps: arithmetic-expansion only, `printf -v` not `local -n`, no `mapfile`, no `&>>`. `make lint-bash32` passes.
