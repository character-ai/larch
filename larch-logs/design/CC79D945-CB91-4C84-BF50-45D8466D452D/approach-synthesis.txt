# Approach Synthesis — Issue #2395 (ship-pr.sh subagent escalation)

## Strong Agreements (all 4 sketches)

1. **Additive to ship-pr.sh, not a new orchestration layer.** Add private functions inside ship-pr.sh (`run_recovery_waterfall`, `with_transient_retry`) rather than a new top-level script. The existing helper surface (lib-quiet.sh, lib-net.sh, record_failure, failure_capture_path, capture_command_output, is_transient_net_signature) is the right primitive set; the new waterfall is a thin orchestrator over them.

2. **Uniform waterfall shape**: Cursor → Codex → Claude subagent, ONE attempt per tier, then bail (fall through to existing exit_stall). Vendor tiers reuse launch-cursor-ci.sh / launch-codex-ci.sh with new `--role` tokens per site (`checks-recover`, `pr-prep-recover`, `pr-create-recover`, plus existing `resolve-conflict` for rebase non-bump conflicts).

3. **Transient-net retry primitive**: small helper `with_transient_retry` (3 attempts with jittered exponential backoff 2s/4s/8s ±25%) wrapping the 6 sites that today call exit_transient_net. Reuse the math already in run_evaluate_failure:1352-1360.

4. **Out-of-scope hard boundaries hold**: bump-branch-guard, classify/apply-bump failures, CI watch exits (run_evaluate_failure max-retries, ci-wait failures), exit_stall 12d (merge admin/policy/error), and all exit 3 user-input bails stay intact. run_ci_fix_vendor's 3-vendor cycle is NOT restructured.

5. **Per-tier rollback is required** — without it, tier-N inherits tier-(N-1)'s half-fix and the post-tier run-relevant-checks-captured.sh measures a chimera. Capture pre-tier dirty-tree baseline (capture_tracked_dirty_paths / capture_untracked_dirty_paths), revert via `git checkout -- <tracked>` + `rm <untracked>` on tier verification failure. Mirrors lint-fix-loop.sh's pattern.

6. **exit 5 absorption mechanical**: (3a) step8_apply_bump_same_version → in-script `git-sync-local-main.sh` + re-classify + apply retry; (3b) force-push-gate → direct call to implement-finalize.sh postbump with phase flag; (3c) ship-pr-rrr-phase14 → folded into the rebase-rebump waterfall. Legacy RESUME_PHASE / CALLER_KIND keys retained as parseable no-ops (backward state-file compat).

7. **Sibling-md + harness coverage** required per script-md-siblings rule: ship-pr.md updated in same PR; test-ship-pr.sh gains assertions per converted path. New launcher (if added) gets its own .md sibling and test-launch-*.sh coverage.

8. **Bash 3.2 compatible throughout** — no associative arrays, no namerefs, no mapfile. Reuse proven `$((... * 2 ** N))` / `$((RANDOM % ...))` backoff math. Run `make lint-bash32` after edits.

## Personality-Specific Highlights

### Architecture/Standards (Claude fallback)
Argues for a SINGLE Claude launcher (extend launch-claude-subprocess.sh with `MODE=writer` flag) to keep one redaction/auth/timing path. Flags blast-radius widening of the documented read-only review launcher. Notes that dispatch-with-waterfall.sh is reviewer-oriented and NOT reusable here. Strong on maintainability/single-responsibility framing.

### Pragmatism/Safety (Codex)
Preserves all hard boundaries explicitly. Recommends prompt-level local-reproduction enforcement + post-launch validation; keeps state syntax stable with old RESUME_PHASE / CALLER_KIND as parseable no-ops. **Strongly prefers a NEW narrow scripts/launch-claude-ci.sh** rather than extending launch-claude-subprocess.sh (avoids blast-radius widening on the documented read-only review launcher).

### Edge-cases/Failure-modes (Claude fallback)
Most defensive proposal. Requires per-tier dirty-tree baselines under `$IMPLEMENT_TMPDIR/recovery-waterfall/<phase>/`, mandatory post-tier verify, rollback on verify failure, AND crash-recovery state keys (RECOVERY_TIER, RECOVERY_PHASE, RECOVERY_ATTEMPT_COUNT). Best risk taxonomy across all four:
- state-file corruption mid-recovery
- partial commits during tier transitions (mitigated via `git rev-parse HEAD == $baseline_head` assertion post-tier)
- subagent producing changes that fail relevant-checks → rollback + next tier
- dirty tree between waterfall tiers (capture baselines per tier)
- race with concurrent CI runs (detached-HEAD probe per tier)
- secret leakage in retry failure logs (every new tier launch flows through `record_failure --redact`; also pipe BAIL_REASON through redact-secrets.sh)
- Bash 3.2 traps (no `local -n` aliasing for tier-result out-vars; use `printf -v` or temp files)
- asymmetric local-reproduction across phases (checks-site has run-relevant-checks-captured.sh as authoritative; pr-create 9b has no failed-CI log to reproduce against — must use dry-run probes like `git push --dry-run` + `gh pr view --json state`)

### Innovation/Exploration (Codex)
Proposes machine-readable proof of local reproduction via KV envelope from the vendor: REPRO_CMD=..., REPRO_FAILED_BEFORE=true, VERIFY_CMD=..., VERIFY_PASSED_AFTER=true — ship-pr.sh rejects tier output without these. Also proposes a "waterfall ledger" TSV under $IMPLEMENT_TMPDIR recording tier/role/rc/proof-file/chosen-output per attempt for postmortems. Crazy-but-might-work alternative: tier produces a patch file, ship-pr.sh applies + verifies + commits + pushes (centralized mutation, no vendor half-edits).

## Synthesis Decisions (to be ratified by dialectic for the contested ones)

A. **Architecture**: private functions inside ship-pr.sh (`run_recovery_waterfall`, `with_transient_retry`, plus per-phase tier helpers). Apply Edge's tier-rollback pattern. (uncontested.)

B. **Claude tier delivery**: prefer NEW `scripts/launch-claude-ci.sh` next to launch-cursor-ci.sh / launch-codex-ci.sh — three siblings, cleaner read-only/write boundary on launch-claude-subprocess.sh. (contested — DECISION_1)

C. **Local-reproduction verification**: script-level mandatory post-tier `run-relevant-checks-captured.sh` for checks-class phases; for pr-create 9b use `git push --dry-run` + `gh pr view --json state` probes; prompt-level guidance reinforces the contract for vendor tiers. (contested — DECISION_2)

D. **Enforce local-repro on EXISTING run_ci_fix_vendor**: yes — constraint A applies to all CI fix paths. Implementation is prompt + post-launch verify additions to run_ci_fix_vendor (which already does run_checks_with_lint_fix_loop after vendor); not a restructure. (contested — DECISION_3)

E. **Per-tier rollback**: dirty-tree-baseline + `git checkout -- <tracked>` / `rm <untracked>` mirroring lint-fix-loop. (contested — DECISION_4, alternative is Innovation's patch-file idea)

F. **Mid-waterfall crash recovery**: NO new state keys; mid-waterfall crash restarts recovery from Cursor. Accept wall-time cost; bound complexity. (contested — DECISION_5, Edge dissents)

G. **out-of-scope unchanged**: bump-branch-guard, classify/apply-bump errors, CI watch exits, 12d, exit 3 user-input bails, run_ci_fix_vendor's 3-attempt cycle structure. (uncontested.)

H. **Bonus from Innovation**: defer the machine-readable REPRO_*/VERIFY_* KV envelope and the waterfall-ledger TSV as follow-ups unless trivial to add inside the same PR.
