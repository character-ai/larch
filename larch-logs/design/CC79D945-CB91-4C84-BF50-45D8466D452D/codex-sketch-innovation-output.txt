I would avoid rewriting `ship-pr.sh`; add two small primitives and route only the scoped bails through them. First, a Bash 3.2-safe `retry_transient_helper()` wrapper for the six transient sites, with persisted attempt context only if needed for logs, not state schema churn. Second, a `run_recovery_waterfall()` adapter with roles like `checks-fix`, `pr-prep-fix`, `pr-create-fix`, and `resolve-conflict`, always Cursor -> Codex -> Claude, one attempt each. The non-obvious part is Claude: a true Agent-tool subagent cannot be launched from inside Bash, so either define “Claude tier” as a new `scripts/launch-claude-ci.sh` subprocess wrapper, or keep a tiny prompt-side escape hatch. I would push for the subprocess wrapper if the UX goal is fewer bails, but document that this is Claude CLI subprocess semantics, not interactive Agent-tool semantics.

Modify mainly `scripts/ship-pr.sh`, `scripts/ship-pr.md`, and `scripts/test-ship-pr.sh`. Optionally add `scripts/launch-claude-ci.sh` plus sibling md/harness if Claude CLI subprocess is accepted. In `ship-pr.sh`, replace the targeted `exit 5`/`exit_stall` sites: bump same-version/version-regression becomes direct `git-sync-local-main.sh -> classify/apply retry`; `force-push-gate` re-enters postbump internally; `ship-pr-rrr-phase14` flag/resume disappears; PR create/prep/checks and non-bump conflict failure call the waterfall before stalling. I would also update the existing Cursor/Codex CI prompts to require a machine-readable proof of local reproduction: `REPRO_CMD`, `REPRO_FAILED_BEFORE=true`, `VERIFY_CMD`, `VERIFY_PASSED_AFTER=true`. `ship-pr.sh` should reject a CI-fix commit/push if that proof is absent, because prompt text alone will drift.

Tradeoff: centralizing recovery reduces operator stalls but makes `ship-pr.sh` a stronger orchestrator, so tests need to pin “no side effects when sourced” and every new launcher must be stub-friendly. The crazy-but-might-work alternative is to make all recovery tiers produce a patch file instead of directly mutating the repo, then have `ship-pr.sh` apply, verify, commit, and push. That would make local-repro enforcement cleaner and prevent vendor half-edits, but it is probably too much for this issue. A smaller unconventional compromise: use a single “waterfall ledger” TSV under `$IMPLEMENT_TMPDIR` to record tier, role, rc, proof file, and chosen output. It preserves backward-compatible state while making postmortems much easier.
