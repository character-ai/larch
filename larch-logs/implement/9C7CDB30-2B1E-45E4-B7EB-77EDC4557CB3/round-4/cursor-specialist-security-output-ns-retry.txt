### In-Scope Findings

1. - **security** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:206-208` — On `oos-category-mangle` jq failure, up to 400 bytes of raw `jq` stderr are copied into `detail` and emitted in NDJSON, so parse errors can leak snippets of the JSONL (or filesystem paths jq mentions) into scan output that may be archived, pasted, or committed. **Suggested fix:** Avoid echoing raw stderr: emit a fixed opaque token (for example `jq_parse_error`) plus optional sanitized line/column if parsed from stderr, or run `jq` with `-e` and map known patterns to short codes without forwarding stderr verbatim.

2. - **security** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:442-451` — The `category-stats` mangled-count path repeats the same pattern: `mj_err` from `head -c 400` on jq stderr is folded into `category_stats_detail` and then into emitted NDJSON via `jstr`, creating the same information-disclosure channel for the second jq invocation. **Suggested fix:** Apply the same redaction policy as above so `category-stats` never embeds raw jq diagnostics in machine-readable output.
