### In-Scope Findings
- **security** `python/session_env.py:197-202` — The cleanup allowlist treats the allowlist roots themselves as removable because `_under()` returns true when `resolved == resolved_root`. As a result, `session cleanup-tmpdir --dir /tmp`, `/private/tmp`, `/var/folders`, `/private/var/folders`, or the cache sessions root passes validation and reaches `shutil.rmtree()` at `python/session_env.py:919-931`; the retired bash only allowed `root/*`, not `root`. **Suggested fix:** Make the cleanup predicate child-only, e.g. require `resolved_root in resolved.parents` for removal targets and explicitly reject equality with every allowlist root.

- **security** `python/session_env.py:700-884` — The new writer-target guard is not consistently applied to public session writer verbs: `write-id` creates/overwrites `--output` without any allowed-root check (`python/session_env.py:700-720`), `persist-run-flags` accepts any existing `--implement-tmpdir` and writes `run-flags.sh` there (`python/session_env.py:733-750`), `write-run-params` writes to any absolute path with an existing parent (`python/session_env.py:785-817`), and `restore-finalize-state` writes `finalize-state.sh` / `final-bail-reason.txt` under any existing directory (`python/session_env.py:856-884`). This bypasses the branch’s new NEVER #14 boundary for approved `session write-*` / state writers. **Suggested fix:** Route every session state/content write target through the writer-target validator before writing, or introduce verb-specific validators that require the target file or containing tmpdir to be under the allowed session roots, while keeping documented carve-outs such as `/dev/null` and `--plugin-root-only`.
