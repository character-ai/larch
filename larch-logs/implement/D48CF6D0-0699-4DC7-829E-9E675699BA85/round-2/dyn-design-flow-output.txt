Reviewing the branch diff and commit history for architecture issues in the /design control-flow changes.
### In-Scope Findings

- **architecture** `skills/design/scripts/assess-plan-round.sh:152-156` — With default auto-apply, the first HARD review round applies all accepted findings at Gate B with no operator prompt, but Step 3.6 still skips assessor dispatch when `ROUND_NUM < 2` (“no previous plan”). On the common single-round path (Step 3 → auto-apply Gate B → Gate C), the only post-apply halts are size brakes and validator escalation—there is no assessor quality gate despite the issue’s stated HARD contract that the assessor is the quality halt after auto-apply. Auto-apply removes the old Gate B human checkpoint without adding a round-1 assessor substitute. **Suggested fix:** Either run a round-1 assessor against `plan.txt-original` vs post-apply `plan.txt` (coordinating with #3513’s anchor work), or document and test that round 1 is intentionally assessor-exempt and keep an explicit operator halt (e.g. require `--approve` on first round, or a lightweight round-1 confirmation) until #3513 lands.

- **architecture** `skills/design/SKILL.md:1739-1764` — The shared validator handler writes a durable per-site sentinel (`.plan-command-autofix-<site>.attempted`) before calling `auto-fix-plan-commands.sh`. That sentinel is never cleared between Gate C “Re-run review panel” cycles, so the second and later Gate B auto-apply passes hit `AUTOFIX_STATUS=skipped-cycle-cap` and fall straight to the operator prompt without spawning vendors. That conflicts with the acceptance criterion that validator defects are auto-corrected cross-vendor whenever possible, and it is introduced by Component D in this branch. **Suggested fix:** Scope the sentinel to a single Gate B settlement (delete or rotate it at the start of each Step 3.5 entry, or key it by review round / `review-round-count.txt`), while keeping the within-site loop cap for Fix-and-retry re-entries in the same pass.

- **architecture** `skills/design/SKILL.md:1343-1375`, `skills/design/scripts/snapshot-plan-round.sh:146-174` — The Revert path restores `plan.txt`, review artifacts, cursor, and `review-round-count.txt`, but it does not clear post-apply completion state such as `.completed/step-2b.5`, optional-trailer snapshots (`.gate-b-optional-trailer-keys*`), or stale `.design-postplan-emit-result.env`. After Revert, the orchestrator still proceeds to Step 3b with `step-3.6` written while `step-2b.5` reflects the pre-revert apply/validation pass. That leaves contradictory settled-state markers if the operator pauses/resumes or later re-enters Gate B without a full Step 3 re-run. **Suggested fix:** Extend `revert-round` (or the Step 3.6 Revert fence) to remove or downgrade post-apply sentinels and trailer snapshots tied to the reverted round, and optionally re-run a lightweight `design-postplan-emit.sh --with-plan-size` validation pass on the restored plan before Step 3b.

- **architecture** `skills/design/SKILL.md:1247` — The Step 3.5 prose still tells operators to reach Round 2 discussion via Gate B’s “Switch to discussion mode,” but under default auto-apply (`approve_requested=false`) that branch is unreachable; discussion is only via Gate C “Discuss further” or `--approve`. This is a control-flow documentation mismatch introduced by the auto-apply default and can misroute orchestrator behavior on resume. **Suggested fix:** Update the Step 3.5 paragraph to state that Round 2 discussion is reached via Gate C “Discuss further” (or Gate B only with `--approve`), matching `skills/design/references/flags.md` and `approval-gates.md`.
