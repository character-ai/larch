Reviewing the branch diff and commit history, then examining the auto-fix helper and its integration points.
### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:1775` — On `AUTOFIX_STATUS=ok`, the shared handler re-enters `design-postplan-emit.sh --with-plan-size` directly and skips the Shared post-apply pipeline’s `gate-b-dedup-plan.sh --snapshot-trailers` / `--dedup` steps. An external vendor can satisfy command validation while corrupting or dropping the optional `diff_added:` / `diff_deleted:` / `mechanical_churn:` trailers that `check-plan-size.sh` and the drift guard rely on, so size brakes can run on stale metadata after a silent auto-fix on the default auto-apply path. **Suggested fix:** After a successful auto-fix (and before re-entering `design-postplan-emit.sh`), run the same optional-trailer snapshot + dedup guard used in Gate B’s Shared post-apply pipeline, or mechanically re-validate trailer keys against the pre-fix snapshot and fail closed into the operator prompt when they drift.

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:196-210` — The Cursor dispatch uses write-enabled `cursor agent -p --trust --workspace "$DESIGN_TMPDIR"`, but unlike sketch, dialectic, and plan-review collection boundaries in `skills/design/SKILL.md`, neither `auto-fix-plan-commands.sh` nor the shared handler consults `${OUTPUT}.dirty-tree` sidecars or runs `check-mid-run-dirty-tree.sh --mode checkpoint` after the external returns. `SECURITY.md` documents that Cursor `--trust` can still write via absolute paths outside `--workspace`; with default auto-apply increasing how often this lane runs, undetected consumer-repo mutations are a real integration gap. **Suggested fix:** Mirror the plan-review post-collection pattern: after each auto-fix dispatch, consult launcher dirty-tree sidecars and run `check-mid-run-dirty-tree.sh`; on `STATUS=dirty|unknown`, write `$DESIGN_TMPDIR/dirty-tree-detected.env` and route through the existing dirty-tree recovery prompt before continuing the success path.

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:135-147` — `revalidate()` silences validator stderr (`2>/dev/null`) and treats any non-`ok` `VALIDATE_STATUS` (including infrastructure `error`) the same as “still defective,” without appending validator diagnostics to `$DESIGN_TMPDIR/execution-issues.md`. On the default auto-apply path, transient Tier-3 probe failures or parser errors during auto-fix therefore surface only as `AUTOFIX_STATUS=exhausted` after up to two 1800s vendor attempts, with no durable failure capture beyond stderr breadcrumbs. **Suggested fix:** Capture validator stderr to `$WORK_DIR/revalidate-attempt-N.log`, append it via `append-tool-failure.sh` when `VALIDATE_STATUS` is `error` or the wrapper exit is non-zero, and short-circuit the vendor loop immediately on infrastructure failure instead of burning the full alternation budget.

- **risk-integration** `skills/design/SKILL.md:1748-1754` — The shared handler invokes `auto-fix-plan-commands.sh` without the `env LARCH_QUIET_DISABLE=1` wrapper used by every other KV-capturing design driver fence (`design-postplan-emit.sh`, `check-plan-size.sh`, Gate B in `approval-gates.md`). Contract output depends on `lib-quiet.sh` routing `emit_kv` to FD 3 inside command substitution; that works in the common case but is inconsistent with the established capture pattern and is not structurally pinned in `scripts/test-design-structure.sh` (unlike postplan/plan-size). **Suggested fix:** Wrap the invocation as `_autofix_out=$(env LARCH_QUIET_DISABLE=1 "$CLAUDE_PLUGIN_ROOT/skills/design/scripts/auto-fix-plan-commands.sh" …)` and add a structure-test pin matching the postplan emit fence so future edits cannot regress KV capture.
