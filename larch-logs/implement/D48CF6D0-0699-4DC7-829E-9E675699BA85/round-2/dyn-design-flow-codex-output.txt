### In-Scope Findings
- **architecture** `skills/design/SKILL.md:1342-1375` — The new assessor Revert path restores `plan.txt` and immediately proceeds to Step 3b without re-establishing the post-plan state. That leaves derived artifacts like `diff-lines.txt` and validator/size status from the rejected applied plan; for round 1 it can also restore `plan.txt-original`, which `skills/design/scripts/design-postplan-emit.sh:506-538` snapshots before validation/autofix, so a Step 2b validator fix can leave the revert baseline stale/invalid. This can publish a reverted plan with stale diff metadata or command defects while bypassing validator and size brakes. **Suggested fix:** After successful revert, rerun the merged post-plan pipeline against the restored plan before Step 3b, or snapshot/restore the full validated post-plan checkpoint (`plan.txt`, `diff-lines.txt`, validator status). Also ensure `plan.txt-original` represents the first validated/autofixed Step 2b plan, not the pre-validation draft.

- **architecture** `skills/design/scripts/auto-fix-plan-commands.sh:223-254` — Auto-fix attempts let external agents edit the target file in place, but when all attempts are exhausted the helper emits `AUTOFIX_STATUS=exhausted` without restoring the pre-autofix file. The subsequent operator prompt therefore operates on partially failed, unapproved external edits; choosing Override could proceed with those edits even though validation still failed. **Suggested fix:** Snapshot the target plan/composed-plan before the first vendor attempt and restore it on any non-`ok` terminal status (`exhausted`, `failed`, or malformed result), or emit an explicit “mutated but still invalid” state that forces operator review of the diff before Override can continue.

- **architecture** `skills/design/SKILL.md:1203` — The Step 3 post-loop contract still says “Gate B is always explicit,” contradicting the new default auto-apply mode documented later in Step 3.5. Because `/design` is prompt-driven, this stale control-flow instruction can cause the default path to keep prompting despite `approve_requested=false`. **Suggested fix:** Replace this sentence with the mode-dependent contract: Gate B auto-applies by default and prompts only when `approve_requested=true`; add a structure test that rejects remaining “Gate B always explicit” wording.
