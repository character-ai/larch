Reviewing the branch diff and commit history, with emphasis on the validator auto-fix path and vendor dispatch integration.
### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:1759-1765` and `skills/design/scripts/auto-fix-plan-commands.sh:164-184` — The shared validator handler passes `--repo-root "$CLAUDE_PLUGIN_ROOT"`, and the helper’s dirty-tree guard snapshots `git status` only for that directory. `/design` normally runs in the consumer clone’s working tree, while Codex/Cursor auto-fix runs with write/`--trust` posture and can mutate paths outside `$DESIGN_TMPDIR`. Those consumer-repo changes are invisible to the guard, so auto-fix can return `AUTOFIX_STATUS=ok` and the orchestrator can continue even though the operator’s active repo was modified. **Suggested fix:** Pass the same filesystem repo root used for the initial validator pass (typically `git rev-parse --show-toplevel` from the active design session cwd, not the plugin install path), snapshot dirty-tree state for that root before dispatch, and fail the attempt (or the whole auto-fix cycle) when any delta appears outside `$DESIGN_TMPDIR`.

- **risk-integration** `skills/design/SKILL.md:1763-1764` and `skills/design/scripts/auto-fix-plan-commands.sh:94-97` — Auto-fix vendor selection keys off `CODEX_PRESENT` / `CURSOR_PRESENT`, not the Step 0 availability flags (`CODEX_AVAILABLE` / `CURSOR_AVAILABLE`) that the degraded-tools gate and #3207 panel logic use to skip unavailable externals. After a degraded continue, auto-fix can still dispatch a vendor the rest of `/design` already treats as down, wasting bounded attempts and widening the write-enabled external surface without adding recovery value. **Suggested fix:** Thread `codex_available` / `cursor_available` (or the `*_AVAILABLE` session-env keys) into `auto-fix-plan-commands.sh` and build `VENDOR_ORDER` from those flags; keep `unavailable` semantics when neither is available.

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:353-360` — On tmpdir-guard or repo-dirty failure, the helper sets `dispatch_rc` and `continue`s without rolling back edits to the target plan file. A vendor can partially rewrite `plan.txt`/`composed-plan.md`, trip the guard, and leave the plan in an intermediate state that never gets revalidated in that attempt; the loop may end `exhausted` while the plan content has already drifted from the pre-auto-fix baseline. **Suggested fix:** Snapshot the target file before each dispatch (alongside the non-target backup), restore it whenever `dispatch_rc` is 90/91, and only treat an attempt as successful after a passing `revalidate()` on the restored-or-final target.

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:127-136,353-355` — The tmpdir mutation guard only inventories regular files (`find . -type f`) and restores failures are swallowed with `|| true`. New symlinks or other non-regular entries under `$DESIGN_TMPDIR` are outside the manifest and are not removed on rollback; a failed restore also does not abort the loop or emit a durable warning, so later attempts or operator escalation can proceed with corrupted session artifacts. **Suggested fix:** Extend the guard to cover symlinks/new paths (or reject any post-dispatch `find` delta outside `plan-autofix/**` and the target file), treat restore failure as a hard attempt failure with logging to `execution-issues.md`, and do not continue to `revalidate()` after a failed rollback.

- **risk-integration** `skills/design/scripts/test-auto-fix-plan-commands.sh:1-200` — The offline harness covers vendor alternation, tmpdir mutation restore, redaction fail-closed behavior, and validator infra failure, but has no case for repo dirty-tree detection or for target-file rollback after guard failure. Those are the main integrity controls called out in `SECURITY.md` for this new write-enabled lane; without regression coverage they can drift silently. **Suggested fix:** Add harness cases that simulate a dispatch stub touching `REPO_ROOT`, assert `dispatch-rc=90`/`AUTOFIX_STATUS=exhausted`, and simulate guard failure after target mutation while asserting the plan file is restored to its pre-attempt contents.

### Out-of-Scope Observations

- `validate-plan.sh` already defaults `--repo-root` to the plugin tree via `git -C "$SCRIPT_DIR/../../..."` when callers omit it (`skills/design/scripts/validate-plan.sh:53-55`). Auto-fix mirrors that by passing `$CLAUDE_PLUGIN_ROOT`; fixing consumer-repo Tier 3 resolution is broader than this branch’s auto-fix integration, though the dirty-tree guard issue above is amplified here because write-enabled vendors are new.

- The branch otherwise aligns well with the stated contract: bounded cross-vendor alternation with `MAX_ATTEMPTS` clamped to vendor count, original validator evidence preserved before revalidation, redaction fail-closed for the validator log in prompts, per-site `.plan-command-autofix-*.attempted` cycle cap, assessor revert clearing those sentinels (`skills/design/scripts/snapshot-plan-round.sh:97`), and explicit operator escalation on `exhausted`/`unavailable`/`failed`/`skipped-cycle-cap`.
