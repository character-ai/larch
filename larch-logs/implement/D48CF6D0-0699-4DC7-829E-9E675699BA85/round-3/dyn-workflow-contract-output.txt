Reviewing the branch diff and commit history against the documented `/design` workflow contract.
### In-Scope Findings

- **architecture** `skills/design/SKILL.md:1193` — The Step 3 post-loop branch matrix still calls Gate B the “sole **operator-approved** apply point,” which is leftover #3512 wording. On the default path (`approve_requested=false`), Gate B auto-applies with no operator prompt, so this line contradicts the new contract in Step 3.5, `approval-gates.md` §Gate B, and the acceptance criterion that default runs auto-apply. An orchestrator reading the branch matrix can wrongly expect a Gate B prompt every round. **Suggested fix:** Reword to “sole apply point” and note that default auto-applies while `--approve` restores explicit operator approval.

- **architecture** `skills/design/SKILL.md:29,636,1107` and `skills/design/references/approval-gates.md:23-47,204` — Gate A re-entry is still documented as reachable from “Gate B(c) → Step 1e” without stating that Gate B(c) exists only when `--approve` is set. Elsewhere the branch already documents this correctly (`approval-gates.md:91,167`; `SKILL.md:1247-1248`). Under default auto-apply, the only post-review discussion entry is Gate C “Discuss further”; treating Gate B(c) as always available misroutes operators and agents toward a prompt path that default runs never expose. **Suggested fix:** Qualify every Gate B(c) mention with “(`--approve` / `approve_requested=true` only)” and point default runs to Gate C “Discuss further” for the same discussion loop.

- **architecture** `skills/design/SKILL.md:1343-1375` and `skills/design/references/assessor.md:38` — On assessor WORSE, choosing **Revert** but hitting a `snapshot-plan-round.sh revert-round` failure (missing snapshot, copy error, bad round anchor) silently keeps the auto-applied plan and continues to Step 3b with Continue semantics. That conflicts with the acceptance criterion that Revert restores the pre-round plan and with operator intent after an explicit Revert choice; the run can proceed to Step 3b / Gate C with a plan the operator believed was rolled back. **Suggested fix:** Fail closed on Revert helper failure (retry, abort with preserved tmpdir, or re-prompt) instead of falling through to Continue; align `assessor.md` and add harness coverage for the orchestrator Revert branch, not only the helper.

- **architecture** `skills/design/SKILL.md:1762` and `skills/design/scripts/auto-fix-plan-commands.md:17,37` — The shared validator auto-fix fence always passes `--repo-root "$CLAUDE_PLUGIN_ROOT"`, while the helper contract says callers should pass the same repo root used for the initial validation and uses that root for dirty-tree delta checks. For `/design` in a consumer clone (plugin cache ≠ consumer repo), vendor activity confined to `$DESIGN_TMPDIR` may not be reflected in plugin-root `git status`, weakening the new cross-vendor auto-fix safety boundary documented in `SECURITY.md`. **Suggested fix:** Thread the consumer repo root (same source as plan-command validation / session setup) into the auto-fix invocation, or document and test why plugin-root monitoring is sufficient when the workspace is tmpdir-scoped.
