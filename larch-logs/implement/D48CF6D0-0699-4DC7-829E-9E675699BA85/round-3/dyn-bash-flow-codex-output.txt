### In-Scope Findings
- **architecture** `skills/design/scripts/auto-fix-plan-commands.sh:343-385` — The auto-fix loop is not transactional around the target plan file: the target is excluded from the tmpdir guard, there is no target backup/restore on failed attempts, and there is no post-dispatch revalidation that the target is still a regular non-symlink file. As a result, a vendor that exits non-zero, mutates another tmpdir file, trips repo-dirty detection, fails trailer dedup, or hits validator infrastructure failure can still leave `plan.txt` / `composed-plan.md` changed before `AUTOFIX_STATUS=exhausted` falls back to the operator prompt in `skills/design/SKILL.md:1786-1789`; a vendor could also replace the target with a symlink and have later dedup/revalidation follow it. **Suggested fix:** Snapshot the target file and its lstat/canonical parent before each attempt; after dispatch, reject symlink/non-regular/out-of-tmpdir target state, restore the target on every non-`ok` attempt path, and only keep the edited target after validator success plus trailer/dirtiness checks. Treat detected repo dirty deltas as fail-closed cleanup/abort, not as an ordinary validator prompt fallback.
