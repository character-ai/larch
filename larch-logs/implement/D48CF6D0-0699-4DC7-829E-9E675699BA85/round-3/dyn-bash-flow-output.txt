### In-Scope Findings

- **architecture** `scripts/design-pause-save.sh:177-178`, `skills/design/SKILL.md:1190`, `skills/design/SKILL.md:2163-2190`, `skills/design/references/approval-gates.md:88-91` — Gate B auto-apply is prompt-side work that can span many orchestrator turns, but `.completed/step-3.5` is only written at the Step 3.6 entry fence (`SKILL.md:1254`), while `.completed/step-3` is written at the Step 3.5 prelude (`SKILL.md:1222`). `design-pause-save.sh` maps `step-3` present + `step-3.5` absent → `STEP=3.5`, so a pause during auto-apply resumes back into Gate B with `approve_requested=false` and re-runs `### Apply-all body` with no idempotency guard. That can silently double-apply the same accepted findings. Default auto-apply amplifies a pre-existing sentinel gap that explicit `--approve` only partially mitigates. **Suggested fix:** Write `step-3.5` (or a round-scoped `.gate-b-applied-round-<N>` sentinel) immediately after the shared post-apply pipeline succeeds, before Step 3.6; or teach `design-pause-save.sh` / resume routing to detect an in-progress Gate B apply and resume at Step 3.6 or 3b instead of re-entering Gate B. Add a pause/resume harness that seeds `step-3` only, asserts no second apply on reload.

- **architecture** `skills/design/scripts/snapshot-plan-round.sh:89-106`, `skills/design/SKILL.md:1343-1373` — `revert-round` rolls back `plan.txt`, review artifacts, and downstream sentinels via `clear_post_revert_state`, but it does not clear `.completed/step-2b.5`, which Gate B’s merged `design-postplan-emit.sh` path writes on successful apply (`approval-gates.md:156`). After a WORSE-majority **Revert**, the plan is back to the pre-round snapshot while `step-2b.5` still claims the post-apply size/validation fence completed for the undone round. That leaves inconsistent pause/resume state if the operator pauses before Step 3b or later re-enters plan-size handling. **Suggested fix:** Extend `clear_post_revert_state` to `rm -f "$DESIGN_TMPDIR/.completed/step-2b.5"` (and document that Revert invalidates the Gate B post-apply settlement), with harness coverage in `test-snapshot-plan-round.sh`.

- **risk-integration** `skills/design/SKILL.md:1759-1765`, `skills/design/scripts/auto-fix-plan-commands.sh:164-184` — The shared validator auto-fix handler passes `--repo-root "$CLAUDE_PLUGIN_ROOT"`, and `check_repo_dirty_delta` only snapshots `git -C "$REPO_ROOT" status`. `/design` runs in the consumer clone, while auto-fix vendors are scoped to `$DESIGN_TMPDIR`; any escape that dirties the consumer worktree would not be detected. Revalidation also uses that repo root for Tier 3 command resolution (`auto-fix-plan-commands.sh:229`), which can disagree with paths in a consumer-anchored plan. **Suggested fix:** Thread the consumer repo root from session setup (same root `design-postplan-emit.sh` / `validate-plan.sh` use on the initial failing pass) into `auto-fix-plan-commands.sh --repo-root`, and add harness coverage for dirty-tree detection on the consumer root.

- **correctness** `skills/design/SKILL.md:1193` — The Step 3 post-loop branch matrix still says Gate B is “the sole operator-approved apply point for accepted findings,” which contradicts the new default auto-apply contract documented elsewhere in the same change (`approval-gates.md:88-91`, `SKILL.md:1244`). An orchestrator following stale matrix text could skip auto-apply or treat Gate B as prompt-only on resume/re-entry. **Suggested fix:** Reword that bullet to match the auto-apply default / `--approve` opt-in semantics used in the Gate B sections.
