### In-Scope Findings
- **architecture** `skills/design/scripts/snapshot-plan-round.sh:121-128` — Revert restores `plan.txt` from `plan-after-round-<N-1>.txt` / `plan.txt-original`, but later review rounds can start from a newer user-revised plan: Gate C “Discuss further” re-enters Gate A and can revise `plan.txt` before Step 3 (`skills/design/references/approval-gates.md:181`, `skills/design/SKILL.md:640-642`). In that path, “Revert this round’s findings” discards legitimate discussion edits made before the review round, not just the findings applied at Gate B. **Suggested fix:** Capture a true pre-review/pre-Gate-B baseline for each Step 3 round after any Gate A/Gate C re-entry edits, e.g. `plan-before-round-<N>.txt`, and make both the assessor comparison/revert target use that baseline.

- **architecture** `skills/design/scripts/snapshot-plan-round.sh:127-138` — Successful Revert updates `plan.txt` and counters but leaves `$DESIGN_TMPDIR/diff-lines.txt` from the applied plan. Step 5c later composes the published `larch:plan` using `diff-lines.txt` (`skills/design/SKILL.md:1576`), so a reverted design can publish stale `diff_lines` metadata from the rejected applied round. **Suggested fix:** After restoring `plan.txt`, refresh the sidecar from the restored plan via `emit-plan.sh --design-tmpdir "$DESIGN_TMPDIR"` or an equivalent atomic parse/write, and add regression coverage for reverted `diff-lines.txt`.

- **architecture** `skills/design/references/approval-gates.md:105-109` — The new mode section says default Gate B auto-applies with no prompt, but the Step 3 outcome matrix still says `complete` / `zero-findings-degraded-panel` “uses the full explicit prompt,” and `skills/design/SKILL.md:1203` still says “Gate B is always explicit.” These stale control-flow statements can cause the prompt-side executor to stop for the old Gate B prompt despite `approve_requested=false`, violating the default auto-apply acceptance criterion. **Suggested fix:** Rewrite these remaining “always explicit/full prompt” statements to route through the `approve_requested` mode branch, with zero-findings still short-circuiting before either mode.
