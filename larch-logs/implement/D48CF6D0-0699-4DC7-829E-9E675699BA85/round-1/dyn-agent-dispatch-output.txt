Reviewing the branch diff and commit history, then tracing the auto-fix plan-command integration path.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:73,116-118` and `skills/design/SKILL.md:1727-1732` — Re-validation inside `auto-fix-plan-commands.sh` resolves `--repo-root` from the plan file’s directory (session tmpdir, usually outside git) and falls back to `pwd`, while the upstream failure came from `validate-plan.sh` invoked without `--repo-root`, which defaults to the plugin script tree (`git -C "$SCRIPT_DIR/../../.." …`). On a consumer repo with a git-based plugin install, auto-fix can report `AUTOFIX_STATUS=ok` against a different root than `design-postplan-emit.sh` / `design-publish.sh` use on re-entry, producing false success or a repeat `rc=10` loop with no orchestrator cycle cap. **Suggested fix:** Thread an explicit consumer repo root through the shared handler (e.g. `git rev-parse --show-toplevel` from the design session cwd, or a persisted key in `source-env.sh`), pass `--repo-root` into both `auto-fix-plan-commands.sh` and the initial validator path so every validate/revalidate call shares one root; add a harness case that stubs mismatched roots and asserts `AUTOFIX_STATUS` cannot diverge from `design-postplan-emit.sh`.

- **risk-integration** `skills/design/SKILL.md:1742-1743,1045,1655` — After `AUTOFIX_STATUS=ok`, the handler re-enters `design-postplan-emit.sh` or `design-publish.sh`, and those sites route `_postplan_rc=10` / `_publish_rc=4` back into the same shared auto-fix block with no per-site attempt budget. A root mismatch or partial vendor fix can spin: auto-fix → ok → postplan validate fail → auto-fix again, burning external calls and wall time while default auto-apply keeps the operator out of Gate B. **Suggested fix:** Add a durable counter in `$DESIGN_TMPDIR` (e.g. `.plan-autofix-orchestrator-cycles`) incremented on each auto-fix invocation; after a small cap (1–2), skip further vendor dispatch and fall through to the Fix-and-retry / Override / Cancel prompt with a mandatory `Warnings` entry, even if the helper alone would retry.

- **risk-integration** `skills/design/SKILL.md:1726-1743` — The orchestrator captures `_autofix_rc` but branches only on `_autofix_status`; it never handles helper exit `2` (bad/missing `--codex-present` / `--cursor-present` after env rehydration) or empty KV output. That skips the required “defects occurred” `Warnings` log (operator decision 6) and can jump straight to Fix-and-retry/Override/Cancel without recording that auto-fix never ran. **Suggested fix:** Treat `_autofix_rc != 0` or empty `_autofix_status` as a failed auto-fix attempt: append a `Warnings`/`Tool Failures` entry with captured stderr, then escalate to the operator prompt; optionally read `CODEX_PRESENT` / `CURSOR_PRESENT` from `$DESIGN_TMPDIR/source-env.sh` in the fence instead of relying on unstale shell exports.

- **risk-integration** `skills/design/scripts/auto-fix-plan-commands.sh:205-213,116-128` — Vendor dispatch failures are only echoed via `larch_err`; they are not appended to `$DESIGN_TMPDIR/execution-issues.md`, and `revalidate()` redirects validator stderr to `/dev/null`. A launcher timeout, auth failure, or validator crash therefore consumes an attempt with little durable telemetry, which makes degraded-mode triage harder and conflicts with the “always log when defects occurred” contract when auto-fix exhausts. **Suggested fix:** On non-zero `dispatch_rc` or `FINAL_VALIDATE_STATUS=error`, call `append-tool-failure.sh` (or `append-execution-issue.sh`) with the vendor log/sidecar paths; stop swallowing validator stderr in `revalidate()`—capture it to `$DESIGN_TMPDIR/plan-autofix/attempt-*/validate.stderr` and reference that in the warning.

### Out-of-Scope Observations

- **risk-integration** `skills/design/scripts/validate-plan.sh:53-55` — The pre-existing default `REPO_ROOT` (plugin tree vs consumer cwd) affects all plan-command validation, not only auto-fix; fixing it holistically (consumer root everywhere) is broader than this branch but would reduce the auto-fix integration risk above.

- **architecture** `skills/design/scripts/test-auto-fix-plan-commands.sh` — Offline coverage exercises dispatch/validate seams only; it does not test live Codex/Cursor launcher exit parsing, `--repo-root` parity with caller sites, or orchestrator cycle limits (documented as manual/CI in `auto-fix-plan-commands.md`).
