### In-Scope Findings
- **risk-integration** `python/ruff.toml:1` — The branch lowers the supported/runtime Python floor to 3.11 in `.github/workflows/ci.yaml:426-445`, `python/pyproject.toml:1-4`, `python/pyrightconfig.json:1-3`, and `python/.pylintrc:88-90`, but Ruff is still configured with `target-version = "py312"`. That leaves one Python lint lane validating against a newer language target than CI/runtime, so Ruff can miss or even encourage 3.12-only modernization while the package now advertises and tests 3.11 support. **Suggested fix:** Change `python/ruff.toml:1` to `target-version = "py311"` and add/update a small guard in the existing Python tooling/version tests so future floor changes keep Ruff, Pyright, Pylint, pyproject, docs, and CI in sync.
- **risk-integration** `.github/workflows/ci.yaml:49-58` — The lint and shellcheck jobs now run under Python 3.11, but their pre-commit cache key remains only `pre-commit-${{ hashFiles('.pre-commit-config.yaml') }}`; `.github/workflows/ci.yaml:150-159` has the same pattern. Because the key did not change with the interpreter, PRs can restore an exact pre-commit cache produced under the previous Python 3.12 environment and then never save the newly-created 3.11 hook envs, making every run reinstall Python hook environments and risking timeout/flaky CI after this runtime switch. **Suggested fix:** Include the configured/setup Python version in the pre-commit cache key for both jobs, e.g. add an `id` to `actions/setup-python` and key on `pre-commit-${{ steps.setup-python.outputs.python-version }}-${{ hashFiles('.pre-commit-config.yaml') }}` with matching restore prefixes.
