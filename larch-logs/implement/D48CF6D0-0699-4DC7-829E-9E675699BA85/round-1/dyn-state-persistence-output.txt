### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:1342-1359` — The Revert fence calls `snapshot-plan-round.sh revert-round --round "$ASSESSOR_ROUND_NUM"`, but `ASSESSOR_ROUND_NUM` is only emitted to the prior Step 3.6 Bash stdout for orchestrator parsing; it is not written to `source-env.sh`, exported, or assigned inside the revert subshell. Because Bash tool calls start fresh subshells, an empty `--round` makes `revert-round` exit 2, which silently falls through to Continue semantics (applied plan kept) even when the operator chose Revert. The driver already persists `ROUND_NUM` in `$DESIGN_TMPDIR/.step3.6-assessor.env` before rc=10 (see `design-plan-quality-assessor.sh:487-492`), but the revert fence never reads it. **Suggested fix:** In the Revert fence, parse `ROUND_NUM` from `.step3.6-assessor.env` (refuse symlinks, validate positive integer) before calling `revert-round`, or pass the parsed value as a literal `--round` argument in the same block; add a handoff harness case that simulates the full WORSE → Revert path and asserts `REVERT_STATUS=ok` plus plan/cursor/count rollback.

- **risk-integration** `skills/design/SKILL.md:1340-1361` — Successful Revert restores `plan.txt` and rolls back `review-round-count.txt` / `plan-review-round-cursor.txt`, but leaves `accepted-plan-findings.md`, `voting-tally.md`, and related Step 3 artifacts untouched. If the operator proceeds to Step 3b → Gate C → Approve without a Gate C re-review, the committed design log can still record accepted findings that no longer appear in the published plan, creating an audit/state mismatch. **Suggested fix:** On `REVERT_STATUS=ok`, clear or rewrite review-round apply artifacts (`accepted-plan-findings.md`, `rejected-findings.md`, `oos.md`, `voting-tally.md`, and optionally stale `assessor-verdict-round-<N>.*`) to match the reverted plan, or document and enforce that Revert must be followed by a Gate C re-run before publish.

- **risk-integration** `scripts/test-step0b-router-flag-recovery.sh:16-42` — The harness’s local `merge_run_params` / `recovery_merge_if_needed` helpers still mirror only `partition_requested` and `brainstorm_requested`; they omit the production `approve_requested` OR-merge arm added in `design-init-runparams.sh:231-239`. Cases 1–7 therefore cannot catch regressions where a stored `approve_requested=true` must be preserved when argv re-enters merge via another router flag. **Suggested fix:** Extend the replicated jq filter and recovery guard to include `$merge_a` / `approve_requested`, and add a case mirroring case 8a for stored-approve + argv-partition merge preservation.

- **risk-integration** `skills/design/scripts/test-design-plan-quality-assessor.sh:197-277` — Acceptance criteria call for Revert regression coverage, but the Step 3.6 handoff harness exercises WORSE rc=10 trailer parsing only; it never invokes the Revert fence or asserts post-revert `plan.txt` / cursor / counter state. ### Out-of-Scope Observations
