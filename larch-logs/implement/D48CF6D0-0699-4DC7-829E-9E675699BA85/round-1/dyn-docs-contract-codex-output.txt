### In-Scope Findings
- **architecture** `skills/design/scripts/assess-plan-round.sh:151-160` — HARD default auto-apply is not actually assessor-gated on the first review round: `assess-plan-round.sh` skips `ROUND_NUM < 2`, while the new Gate B docs promise that after default auto-apply “the HARD Step 3.6 assessor remains the quality gate” (`skills/design/references/approval-gates.md:90-103`, `docs/workflow-lifecycle.md:79`). With the Gate B prompt removed by default, first-round accepted findings can be applied with no operator prompt and no assessor halt unless size/validator brakes fire. **Suggested fix:** make round 1 assess against `plan.txt-original` as the previous baseline (or materialize an equivalent round-0 snapshot), update `assess-plan-round.md`, and add regression coverage for a HARD first-round auto-apply producing an assessor verdict/Revert path.

- **architecture** `skills/design/references/approval-gates.md:105-117` — The Gate B contract still says `LOOP_STATUS=complete` / `zero-findings-degraded-panel` “uses the full explicit prompt” and that revision happens only after the operator chooses Apply all / Go through each, directly contradicting the new default auto-apply branch in the same file (`skills/design/references/approval-gates.md:88-103`). Prompt-side execution can follow the stale later branch and incorrectly restore the per-round prompt without `--approve`. **Suggested fix:** rewrite that Step 3 outcome bullet to say complete paths use the mode selected by `approve_requested`, with explicit prompt only when `approve_requested=true`.

- **architecture** `README.md:59-61` — The public `/design` usage signature omits `[--approve]` while the adjacent prose advertises it; `docs/skills.md:51-55` has the same mismatch, although `skills/design/SKILL.md:4` and `docs/workflow-lifecycle.md:79` include the flag. This makes the new public opt-out look unsupported in the main skill catalog. **Suggested fix:** add `[--approve]` to the README and `docs/skills.md` argument signatures.

- **architecture** `skills/design/scripts/auto-fix-plan-commands.sh:65-73` — The auto-fix helper validates `DESIGN_TMPDIR` but accepts any existing `--plan-file`, then tells a write-enabled external agent to edit that path in place (`skills/design/scripts/auto-fix-plan-commands.sh:96-104`). That violates the new SECURITY.md contract that the write grant is scoped to `$DESIGN_TMPDIR` and only targets session-internal `plan.txt` / `composed-plan.md` (`SECURITY.md:144`), especially for Cursor where `--trust` can write arbitrary absolute paths. **Suggested fix:** canonicalize `--plan-file`, reject symlinks and paths outside canonical `$DESIGN_TMPDIR`, and require basename `plan.txt` or `composed-plan.md` before launching any vendor.

- **architecture** `SECURITY.md:142` — The Step 3.6 assessor trust-boundary paragraph still describes only Continue/Stop, including fail-closed trailer validation “before Continue/Stop,” but the branch adds a Revert branch that also relies on the trusted `LARCH_ASSESSOR_ROUND_NUM` scalar. This leaves SECURITY.md inconsistent with `skills/design/SKILL.md:1338-1362` and `skills/design/references/assessor.md:35-42`. **Suggested fix:** update the paragraph to Continue/Revert/Stop and explicitly state that Revert uses the validated trusted round number to call `snapshot-plan-round.sh revert-round`.
