Reviewing the branch diff and the files flagged in the scout notes for robustness issues.
### In-Scope Findings

- **code-quality** `scripts/write-design-round-meta.sh:99-136` — The panel-manifest writer always `mv`s `panel-manifest.ndjson.tmp` onto the final path (`|| true`), even when the embedded Python exits non-zero and the `|| printf '0'` path forces `_panel_count=0`. A partial or empty tmp file can therefore replace a previously good manifest while `round-meta.json` records `total_slot_count: 0`, producing inconsistent Review Phase Detail (zero reviewers launched despite real slot artifacts). **Suggested fix:** Capture Python’s exit status separately; only `mv` when it is 0 and `_panel_count` is numeric; on failure `rm -f` the tmp and leave the existing manifest untouched (or skip the mv entirely).

- **code-quality** `scripts/write-design-round-meta.sh:136,194-197` — Both atomic renames swallow `mv` failures and never remove leftover `*.tmp` files. A failed rename leaves `panel-manifest.ndjson.tmp` / `round-meta.json.tmp` in the round directory and can leave stale final files if a prior run already wrote them, so metadata can be silently wrong or split across tmp/final pairs. **Suggested fix:** Check `mv` exit codes; on failure delete the tmp file and avoid overwriting the destination; optionally emit a stderr warning (still exit 0) so operators can see synthesis degradation.

- **code-quality** `scripts/write-design-round-meta.sh:132-136` — When `python3` is absent, the script truncates `panel-manifest.ndjson.tmp` and publishes an empty manifest even though `round-meta.json` is still emitted via `jq`, hard-coding `total_slot_count: 0`. That contradicts the plan’s jq/Python fallback story and can zero out panel attribution in environments with `jq` but no `python3`. **Suggested fix:** Add a `jq`-based NDJSON projection for `plan-review-slots.ndjson` (mirroring the Python loop) before falling back to an empty manifest, or skip rewriting `panel-manifest.ndjson` when no writer succeeded.

- **code-quality** `scripts/compose-review-findings.sh:371-487` — `_design_filtered` is created with `mktemp` but is not registered in the script’s `trap` (which only removes `TMP_OUT` and `DESIGN_REVIEWER_MAP`). If `parse_artifact` later calls `fail()` (e.g., redaction/`jq` failure in `emit_record`), the helper exits 2 without reaching `[ -z "$_design_filtered" ] || rm -f "$_design_filtered"`, leaking a temp accepted-findings file under `$TMPDIR`. **Suggested fix:** Extend the `trap` to remove `_design_filtered` when set, or wrap the design accepted path in a subshell/`trap` that always deletes the filter temp on exit.

- **risk-integration** `skills/design/scripts/dispatch-plan-review-panel.sh:185-190` — The new both-externals-absent manifest row is appended with bare `jq -nc` under `set -euo pipefail` and no `command -v jq` guard. On hosts without `jq`, dispatch aborts before emitting `PANEL_PATHS_FILE`, whereas the pre-change path could still complete with an empty manifest. That is a new hard dependency in the degraded generic-Claude path the feature relies on for non-zero panel counts. **Suggested fix:** Guard with `command -v jq` and fall back to a small Python NDJSON append (or printf a single known-safe JSON line) before exiting, matching the best-effort posture used elsewhere.
