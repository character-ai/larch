Reviewing the diff and the tally parser and Gate B skip-filter implementations.
### In-Scope Findings

- **correctness** `scripts/compose-review-findings.sh:462-467` — `filter_design_gate_b_skipped()` builds skip identity by stripping **every** line in an accepted block that contains the substring `rejected by user during one-by-one review`, not only the Gate B reason line. Any accepted `FINDING_*` whose concern or scenario text legitimately quotes that phrase loses that line before comparison and in the composed JSONL, so Review Phase Detail can show truncated finding bodies or, if a rejected block normalizes to the same truncated text, incorrectly drop a finding that was not Gate-B-skipped. **Suggested fix:** Match skipped findings by `FINDING_*` ID (or strip only lines matching a structured reason pattern such as `^- \*\*Reason(?: not implemented)?\*\*:.*rejected by user during one-by-one review`), and compare normalized bodies without substring-based line deletion from accepted blocks.

- **correctness** `scripts/compose-review-findings.sh:462-467` — Gate B exclusion relies on exact normalized full-block equality between `accepted-plan-findings-all.md` and `rejected-findings.md`, with normalization limited to `rstrip()` per line. `accepted-plan-findings-all.md` is cumulative across rounds while rejected copies are written at Gate B time; any drift in reviewer labels, blank lines, or field ordering between the two files prevents a skip match, so a Gate-B-skipped finding can remain in the composed `review-findings-full.jsonl` as `outcome=accepted` while the per-round table counts come from `round-meta.json`, producing inconsistent Review Phase Detail (table vs top-reviewer attribution). **Suggested fix:** Key the filter on finding ID (`FINDING_<n>`) for blocks whose rejected copy carries the one-by-one reason, then compare only the shared metadata fields or strip the reason line alone before equality.

- **correctness** `scripts/write-design-round-meta.sh:40-45` — `_parse_tally_md()` reads `Result` from `$(NF-1)` with `$(NF-2)` fallback, which is only correct when pipe rows end with a trailing `|` so awk’s final empty field shifts `Result` to `NF-1`. Canonical `tally-plan-review.sh` output does include that trailing delimiter, but rows without it misparse: `FINDING_*` rows read JERR (`0`) as the result and are silently not tallied, while `OOS_*` rows treat JERR as a non-`accepted` result and increment `OOS_REJECTED_COUNT`. Because the TSV fallback replaces MD counts only when MD parses to all zeros, partial MD miscounts are not corrected. **Suggested fix:** Parse the `Result` column by header name (or fixed index from the `| Item | YES | NO | JERR | Result |` schema) instead of `NF-1`, and add harness cases for both trailing-pipe and no-trailing-pipe rows.

### Out-of-Scope Observations

- The same Gate B `normalize()` substring-stripping logic already exists in `skills/design/scripts/render-final-summary.sh:280-285`; this branch amplifies the impact by feeding the compose path into `review-findings-full.jsonl` and Review Phase Detail, but the fragile pattern predates the new wiring.
- There is no dedicated `scripts/test-write-design-round-meta.sh`; tally parsing is only exercised indirectly through integration harnesses, so the `NF-1` edge case above is unlikely to be caught by CI if a non-canonical `voting-tally.md` snapshot appears.
