Reviewing the branch diff and the files flagged in the scout notes for correctness issues.
### In-Scope Findings

- **correctness** `scripts/write-design-round-meta.sh:122-178` — `_adjust_security_oos_counts()` uses `mktemp "${round_dir}/.oos-sec.XXXXXX"` inside the published round snapshot directory while the script runs with `set -euo pipefail` and no `trap`. A `mktemp` failure (disk full, unwritable round dir) aborts the whole script before `panel-manifest.ndjson` / `round-meta.json` are written, even though the documented contract is best-effort exit 0 and callers only log a WARN. That can leave a round with snapshotted tallies but no renderer metadata. **Suggested fix:** create security-scratch files under `"${TMPDIR:-/tmp}"` (as `compose-review-findings.sh` already does for Gate B filtering), or wrap each `mktemp` in `block_file="$(mktemp ...)" || continue` / `|| { rm -f ...; break; }` so a temp failure cannot abort metadata synthesis; add an `EXIT` trap to remove any in-round temps if you keep the current location.

- **correctness** `scripts/write-design-round-meta.sh:129-139` — The same loop only removes `.oos-sec.*` files with a bare `rm -f` after each iteration. If the process is killed between `mktemp` and `rm`, or if `set -e` aborts before `rm` (for example on `mktemp` failure mid-loop), hidden `.oos-sec.*` files remain under `plan-review/round-N/`. `design-log-publish.sh` enumerates all round files with `find "$pr_root" -type f`; those dotfiles are neither in `design_round_artifact_included()` nor `design_artifact_excluded()`, so publish fails with “unexpected file under plan-review” and the run log never lands. **Suggested fix:** never create temps inside the staged round tree; if you must, register an `EXIT`/`ERR` trap that `rm -f "${round_dir}"/.oos-sec.*` and also delete `panel-manifest.ndjson.tmp` / `round-meta.json.tmp` on all exit paths.

- **correctness** `scripts/compose-review-findings.sh:441-484` — `filter_design_gate_b_skipped()` returns 1 when `python3` is unavailable, but the caller only swaps in the filtered file when the helper exits 0; on failure it silently keeps the unfiltered `accepted-plan-findings-all.md`. That re-includes `FINDING_*` blocks the operator rejected during Gate B one-by-one review, so `review-findings-full.jsonl` can attribute suggestions/top reviewers to findings that should be excluded, while `round-meta.json` counts still come from the voting tally. Review Phase Detail then mixes stale JSONL attribution with round metadata. **Suggested fix:** on `filter_design_gate_b_skipped` non-zero exit, either fail compose (so `render-final-summary.sh` truncates JSONL) or skip accepted parsing entirely and emit WARN; do not fall through to unfiltered accepted input when the Gate B grep precondition was true.

- **correctness** `scripts/write-design-round-meta.sh:132-137` — Security OOS adjustment calls `is_security_block "$block_file" 2>/dev/null` inside a conditional, so return code `2` (Python/`is_security_block` unavailable per `scripts/lib-vote-tally.sh:61-64`) is treated as “not security” and the OOS row is left in `OOS_ACCEPTED_COUNT` / `OOS_REJECTED_COUNT`. Held-local security OOS can therefore still appear as non-zero OOS columns in Review Phase Detail whenever block extraction succeeded but classification did not. **Suggested fix:** treat `is_security_block` rc `2` as “unknown” and skip subtracting only when rc `0`; optionally log and leave counts unchanged, or conservatively subtract only on rc `0` and document that rc `2` preserves tallies without falsely excluding non-security OOS.

This is a performance concern, not a functional regression introduced by the branch.
