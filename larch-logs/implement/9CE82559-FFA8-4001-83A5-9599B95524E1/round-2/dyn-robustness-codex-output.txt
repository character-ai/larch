### In-Scope Findings
- **correctness** `scripts/write-design-round-meta.sh:156-173` — The TSV fallback security adjustment never sees the vote result: the awk producer emits only `id<TAB>result`, but the loop reads `id _ result _rest`, so `result` is empty and line 160 always skips. When `voting-tally.md` is absent/unparseable and counts fall back to `findings-classification.tsv`, security-tagged accepted OOS blocks stay in `OOS_ACCEPTED_COUNT` even though `skills/design/scripts/tally-plan-review.sh:503-512` keeps accepted security OOS out of public OOS outputs. **Suggested fix:** Read two fields in the TSV loop (`read -r id result`) or emit a dummy middle field, and add a fallback-TSV fixture with accepted security OOS to pin the subtraction.
- **correctness** `scripts/write-design-round-meta.sh:129-311` — The helper creates scratch files directly in the published round directory (`.oos-sec.*`, `panel-manifest.ndjson.tmp`, `round-meta.json.tmp`) and only removes/moves them on normal completion. If synthesis is interrupted after temp creation, those leftovers remain under `plan-review/round-N`, and `scripts/design-log-publish.sh:582-599` rejects unexpected round files, so a later publish/retry can fail because of internal scratch artifacts. **Suggested fix:** Use a private `mktemp -d` under `${TMPDIR:-/tmp}` with cleanup trapping, then write only final `round-meta.json` / `panel-manifest.ndjson` into the round directory; alternatively also teach the publisher to ignore exact scratch patterns.
