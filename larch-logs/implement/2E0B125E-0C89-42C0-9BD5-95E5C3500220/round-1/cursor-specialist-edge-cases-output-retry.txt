Pre-change synthesis caused the `empty_merge_from_nonempty_input` token and waterfall retry; post-change the run stops after the first phase. The plan documents this as intentional, but it is a real recovery-surface reduction, not a no-op cleanup. **Suggested fix:** If cross-vendor recovery for “empty merge, no token” should remain, emit a dedicated narrow-trigger stderr token (without reintroducing synthesis) or map the missing-attestation branch to `MERGE_PIPELINE_RC=1`; add a multi-phase harness stanza (`zero_findings_no_attest` + waterfall counter) so the contract is tested rather than only single-phase `LARCH_AGGREGATE_MAX_OUTER_PHASES=1` cases.

- **correctness** `skills/review/scripts/test-aggregate-findings.sh:605-621` — The `zero_findings_impure_attest` stanza title implies the extended strip predicate is exercised, but validation fails before strip runs; `junk-suffix` not appearing in `findings.md` holds because `cmp -s` proves the ballot was never replaced, not because strip filtered the candidate file.
