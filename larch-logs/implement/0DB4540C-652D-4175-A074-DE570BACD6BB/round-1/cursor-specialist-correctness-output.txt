1. **Latent**, `correctness` ([scripts/merge-pr.sh](scripts/merge-pr.sh) ~158–171): Recoverable classification uses `git log --format='%s' "${PR_HEAD_OID}..HEAD"` plus subject filters but never checks that `PR_HEAD_OID` is an ancestor of `HEAD`. In a rare non-linear case (local `HEAD` not descended from the GitHub PR tip, yet `PR_HEAD_OID..HEAD` is non-empty and happens to be 1–5 subjects all matching `^chore(larch-logs): flush `), the script would call `git-force-push.sh` and can rewrite the remote branch in a way that drops commits that exist only on the PR side. **Suggested fix:** require `git merge-base --is-ancestor "$PR_HEAD_OID" HEAD` (or equivalent) before setting `_flush_recoverable=true`.

2. **Nit**, `code-quality` / **Completeness w.r.t. plan** (`requirements` + `plan`) ([scripts/merge-pr.md](scripts/merge-pr.md) ~26–30): The new “Flush-commit OID recovery” section says the script checks this “**Before** the OID precondition in step 1,” but the implementation runs only inside the branch where `LOCAL_HEAD` is empty or does not equal `PR_HEAD_OID`—i.e. when that precondition fails first, not “before” it. **Suggested fix:** Rephrase to “when local HEAD does not match `headRefOid` …” so the doc matches control flow.
