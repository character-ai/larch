### In-Scope Findings

1. **Nit** (`code-quality`, `plan`): [scripts/merge-pr.md:54](scripts/merge-pr.md) — The sentence “Before the OID precondition in step 1, the script checks…” contradicts the real control flow: recovery runs **after** the step‑1 equality check fails (`LOCAL_HEAD != PR_HEAD_OID`), not before it. **Scenario:** Someone maintaining the gate reads the doc and looks for logic *before* the OID check in `merge-pr.sh` and mis-traces the script. **Fix:** Reword to “When step 1 detects `HEAD` ≠ `headRefOid`, …” (or “On OID mismatch, …”).

2. **Nit** (`code-quality`, `plan`): [scripts/merge-pr.md:48](scripts/merge-pr.md) — Numbered step 4 still says “local/remote OID mismatch” always “fail closed via `MERGE_RESULT=error`”, which is no longer universally true once flush-only recovery can clear the OID mismatch. **Scenario:** Operators use step 4 as the authoritative list of hard failures and overlook the flush exception. **Fix:** Qualify OID mismatch (e.g. “non-recoverable OID mismatch; see Flush-commit OID recovery”) or move OID wording out of step 4 into the flush subsection.

3. **Nit** (`code-quality`, `plan`): [scripts/merge-pr.md:60-62](scripts/merge-pr.md) — “Batched discovery” still implies a single compound `gh pr view` covers the OID precondition without a later round-trip; flush recovery adds a **second** `gh pr view` on that path. **Scenario:** Someone optimizes or audits API usage assuming exactly one `pr view` before merge. **Fix:** Add one clause that flush recovery may issue an extra `gh pr view` to refresh `headRefOid`.

4. **Nit** (`code-quality`): [scripts/test-merge-pr.sh:121-124](scripts/test-merge-pr.sh) — The fake `git fetch` handler now succeeds for **any** `git fetch origin …`, not only `origin main`. **Scenario:** A future regression introduces an unintended `git fetch origin <branch>` during the merge-pr path; the harness would still report success. **Fix:** Match `origin` plus the expected ref (e.g. `main` or `$STUB_BRANCH_NAME`) if you want the stub to stay strict.

5. **Nit** (`risk-integration`): [scripts/merge-pr.sh:174](scripts/merge-pr.sh) — `git-force-push.sh` stderr is redirected to `/dev/null`, so real push/lease failures lose tool diagnostics in logs while the script only surfaces the synthesized `ERROR=…force-push failed` line. **Scenario:** Debugging a denied force-push requires re-running the helper manually. **Fix:** Consider teeing stderr to `larch_err` or dropping the suppression for that subprocess only (if acceptable for the quiet contract).
