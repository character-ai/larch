### Out-of-Scope Observations
- **correctness** `skills/design/scripts/design-postplan-emit.sh:185-192` — `_postplan_resolve_repo()` (and the mirrored `_postplan_resolve_issue()`) only strips surrounding quotes when the extracted value is wrapped in a matching pair of single or double quotes. An unquoted value that has a trailing inline comment — e.g. `export REPO=owner/name # written by X` — would propagate the comment text as part of the REPO value, producing `--repo "owner/name # written by X"` in the `exec` call. This is incorrect `--repo` propagation, not a code-execution risk, because `printf '%s\n'` does not interpret escape sequences and `"$_repo"` prevents word-splitting in the `exec` argument list. In practice `write-design-current-env.sh` is machine-generated and should not emit comments on value lines, so this is theoretical. The same edge case exists in the pre-existing `_postplan_resolve_issue()` function. **Suggested fix:** In both helpers, after the `sub()`-based prefix strip, additionally strip a trailing ` # ...` comment with a second `sub(/[[:space:]]+#.*$/, "", v)` applied before the quote-stripping check, or document that `source-env.sh` is machine-written and must not contain inline comments on `export` value lines.
