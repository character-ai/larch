### In-Scope Findings

- **risk-integration** `skills/design/scripts/test-design-postplan-emit.sh:622-638` — The new D2d_silent_nonzero test only covers the path where `read-design-classification.sh` exits non-zero with **empty** stderr (synthetic WARN fires). There is no negative test verifying that the synthetic WARN is **suppressed** when the script exits non-zero with non-empty stderr. The no-dup guard `[[ "${#WARN_LINES[@]}" -eq "$_classification_warn_count_before" ]]` in `design-postplan-emit.sh:113` is new code introduced by this diff whose complementary invariant — "don't fire synthetic WARN when real stderr was captured" — has no coverage. A regression that inverts or removes the guard would not be caught. **Suggested fix:** Add a test case that stubs `read-design-classification.sh` to exit 9 while emitting one stderr line (e.g. `printf 'real warn\n' >&2; exit 9`), then asserts the stdout contains the real WARN but does NOT contain the synthetic `"exited 9"` WARN — using the existing `assert_not_contains` helper that was introduced in this same diff.

- **risk-integration** `skills/design/scripts/test-design-postplan-emit.sh:631` — Test D2d_silent_nonzero runs with `LARCH_QUIET_DISABLE=1` inherited from `export LARCH_QUIET_DISABLE=1` set at the end of D2d_invalid_warn (line ~618). It does not re-run with `env -u LARCH_QUIET_DISABLE` the way the comparable D2d_warn and D2d_invalid_warn tests do. The plan and `.md` contract both state classification warnings are "operator-visible under default quiet mode." If a future change made the synthetic WARN quiet-mode-invisible (e.g. by accidentally routing it through a non-WARN emit path), the test would still pass because it runs in verbose mode. The existing D2d_warn and D2d_invalid_warn tests establish this pattern explicitly. **Suggested fix:** Run D2d_silent_nonzero with `env -u LARCH_QUIET_DISABLE CALL_LOG="$CALL_LOG" CLAUDE_PLUGIN_ROOT="$FAKE_PLUGIN" bash "$SUBJECT" ...` instead of `run_subject`, mirroring the D2d_warn / D2d_invalid_warn pattern, so the quiet-mode path is explicitly exercised.
