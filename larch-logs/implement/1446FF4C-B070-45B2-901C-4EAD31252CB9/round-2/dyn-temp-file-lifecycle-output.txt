Reviewing temp-file lifecycle in the branch diff: reading the diff and tracing cleanup paths in the scout script.
### In-Scope Findings
- **code-quality** `scripts/scout-dynamic-archetypes.sh:161-165` — In `tier_raw_is_scout_json`, when `raw_path` is not valid JSON the function allocates `fenced_tmp`, `extract_valid_fenced_json` returns without I/O error (`rc != 2`), and `fenced_tmp` is empty, the `else` branch runs `cp "$raw_path" "$probe_tmp"`. On `cp` failure the error handler removes only `probe_tmp` and returns 1 before the unconditional `rm -f "$fenced_tmp"` at line 166, so each failed `cp` leaves a `${raw_path}.fenced-probe.*` file in the session directory. The waterfall can call this helper twice per scout run (Codex then Claude), so repeated probe misses on that path can accumulate uniquely suffixed temp files under `$SESSION_ROOT` even though `cleanup_temps` (lines 488–493) never references probe/fenced-probe paths. **Suggested fix:** On the empty-`fenced_tmp` `cp` failure path, remove both temps in the handler (e.g. `{ rm -f "$probe_tmp" "$fenced_tmp"; return 1; }`), matching the `cp "$fenced_tmp" "$probe_tmp"` branch at line 162; optionally add a single `rm -f "$fenced_tmp"` immediately before that `return 1` so every exit from the fenced branch clears `fenced_tmp`.

### Out-of-Scope Observations
- **`STAGED_DIR` (`$SESSION_ROOT/staged-context/`)** is created at lines 291–292 and not removed by the scout; staged files are intentionally left for tool-capable tiers and are normally bounded by session/`IMPLEMENT_TMPDIR` lifecycle rather than per-invocation teardown.
- **`${OUTPUT}.codex.launch.env` and `${OUTPUT}.claude.launch.env`** are truncated on each tier via `>"$launch_stdout"` (lines 391, 422); they persist across scout runs but do not grow append-only.
- **`cleanup_temps` EXIT trap** (lines 488–493) is registered only after the waterfall; it still covers only `fenced_json_tmp` and `validated_tmp`, not staged context or probe artifacts—consistent with pre-change behavior and acceptable given session cleanup, except for the leak path above.
