Reviewing the branch diff and the argv-materialization paths called out in the scout notes.
### In-Scope Findings

- **correctness** `scripts/scout-dynamic-archetypes.sh:384-386` — In `run_codex_tier`, staged or inline description is passed to `launch-review.sh` as `--description-text "$(head -c "$MAX_CONTEXT_BYTES" "$STAGED_DESC")"` or `--description-text "$DESCRIPTION_TEXT"`, materializing up to 262 144 bytes into a single argv element. On Linux, `MAX_ARG_STRLEN` is typically 131 072 bytes per string; values above that make `exec` of `launch-review.sh` fail with `E2BIG` before Codex runs. Staged descriptions between ~128 KiB and 1 MiB (allowed by `MAX_STAGED_BYTES`) and inline `--description-text` near the 256 KiB cap are affected when `--codex-present true`. The `description-too-large` harness (~270 KiB `--description-file`) only exercises the Claude stub, so this path is untested. **Suggested fix:** Stop passing `--description-text` from `run_codex_tier` when using `--prompt-file` (description is already in the scout prompt via staged-path Read instructions or inline embed, and `launch-review.sh` does not merge `DESCRIPTION_TEXT` into the Codex prompt on the `--prompt-file` path). If a launcher ever needs file-backed description, pass a path flag (e.g. `--description-file "$STAGED_DESC"`) and teach `launch-review.sh` to use it without argv materialization, or cap materialization at `min(MAX_CONTEXT_BYTES, 131072)`.

- **correctness** `scripts/scout-dynamic-archetypes.sh:384` — `$(head -c "$MAX_CONTEXT_BYTES" "$STAGED_DESC")` runs through command substitution, which strips all trailing newlines from `head` output. Any description whose semantics depend on a terminal newline (or trailing blank lines) is altered before being placed on argv. Combined with the point above, this materialization is also unused by Codex when `--prompt-file` is set (`launch-review.sh` only applies `--description-text` during `--agent-file` rendering), so the corruption is latent today but will bite if the argv path is kept. **Suggested fix:** Prefer `--description-file "$STAGED_DESC"` (no substitution) or drop the argument entirely and rely on the prompt’s staged-path Read instruction plus Codex `--add-dir "$CANON_OUTPUT_DIR"`.

- **correctness** `scripts/scout-dynamic-archetypes.sh:384` — `head -c` truncates on byte count, not UTF-8 code-point boundaries, so a cut at 262 144 bytes can leave a trailing partial multibyte sequence in the materialized `--description-text` value. **Suggested fix:** Same as above: avoid byte-oriented `head -c` into argv; let Codex read the staged file by path (already referenced in the scout prompt under `$SESSION_ROOT/staged-context/description.txt`).

- **correctness** `scripts/scout-dynamic-archetypes.sh:383-387` — For description mode with `--description-file`, the Codex tier forwards materialized `--description-text` to `launch-review.sh`, but on the `--prompt-file` code path `DESCRIPTION_TEXT` is never merged into the Codex prompt (`launch-review.sh` only adds it when `--agent-file` is set). Codex context for staged descriptions depends solely on the scout prompt’s “Read the file at …” line and `--add-dir` on the session output directory; the `head -c` argv is dead weight that still risks `E2BIG`. `/design` plan review with `--codex-present true` can therefore run Codex without the description body in the executed prompt while still paying argv cost. **Suggested fix:** Remove the `codex_args+=(--description-text …)` branches in `run_codex_tier` for `--prompt-file` launches; ensure `CANON_OUTPUT_DIR` (already `dirname` of `${OUTPUT}.raw`) covers `$SESSION_ROOT/staged-context/` so Codex can read staged files named in the prompt.
