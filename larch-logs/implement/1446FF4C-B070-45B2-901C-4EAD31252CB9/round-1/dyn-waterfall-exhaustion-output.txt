### Out-of-Scope Observations

Traced the no-winner terminal block in `scripts/scout-dynamic-archetypes.sh` (roughly 354–470) against the plan and `scripts/scout-dynamic-archetypes.md`. The behavior called out in the scout notes is intentional, not a regression.

**`had_probe_miss` is sticky, not per-tier.** It is initialized once at line 356 and only ever set to `1` inside `run_codex_tier` / `run_claude_tier` when a tier exits 0 with non-empty raw that fails `tier_raw_is_scout_json` (lines 402, 432). It is never cleared between tiers. That is required so a Codex probe miss still counts after Claude runs.

**Multi-tier no-winner priority (lines 445–460).** When `CODEX_PRESENT=true` and there is no winner, `(( had_probe_miss ))` is checked before `$last_scout_status`. So Codex launch failure + Claude probe miss yields `SCOUT_STATUS=empty`, not launcher failure — matching the contract: probe exhaustion wins if any tier had exit-0 non-empty output that failed the probe. The same applies to Codex probe miss + Claude launch failure (`empty`, not `claude-failed`/`timeout`).

**Launcher-failure path still exists.** When `had_probe_miss=0` and `CODEX_PRESENT=true`, the script emits `$last_scout_status` (lines 455–459), e.g. both tiers fail launch, or Codex times out and Claude returns empty raw without a probe miss. `last_scout_status` is updated only on non-zero launcher exit (lines 390–395, 420–425).

**Single-tier Claude-only is isolated.** With `CODEX_PRESENT=false`, the block at 446–454 is skipped. Launcher failure exits early at 462–468; exit-0 empty or unparseable raw falls through to `raw_output` and the unchanged `emit_parse_failed_result` path (from line 472), so `SCOUT_STATUS=parse-failed` is preserved for single-tier probe/validation failures.

**Harness alignment.** `scripts/test-scout-dynamic-archetypes.sh` covers multi-tier probe exhaustion (`waterfall-exhausted`) and Codex→Claude fallthrough; `skills/review/scripts/test-dispatch-panel.sh` retargets `dynamic-parse-failed*` / `dynamic-fail` to `--codex-available false` so they do not rely on multi-tier exhaustion semantics.

**Coverage gap (pre-existing / non-blocking).** There is no dedicated harness for (a) multi-tier all-launcher-failure with `had_probe_miss=0` asserting `$last_scout_status`, or (b) Codex launch-fail + Claude probe-miss asserting `SCOUT_STATUS=empty`. Behavior matches the written contract; tests would only lock it in.
