### In-Scope Findings

- **risk-integration** `skills/design/scripts/test-design-pause-resume.sh:240-249` — The new empty-state Gate-B-bypass case documents a save/load round-trip in `skills/design/scripts/test-design-pause-resume.md:15` and in the issue acceptance criteria, but the harness only invokes `design-pause-save.sh` and never `design-pause-load.sh`. `STEP=3b` encoding in the pause marker and the `design-pause-load.sh` HARD legacy rewrite (`STEP=3b` without `step-3.6` → `STEP=3.6` at `scripts/design-pause-load.sh:256-258`) are therefore untested on the path this branch adds. **Suggested fix:** After a successful save, run load into a fresh restore tmpdir (mirror the `design-36` pattern at `skills/design/scripts/test-design-pause-resume.sh:237-238`) and assert `LOAD_OK=true` and `STEP=3b`.

- **risk-integration** `skills/design/scripts/test-step3-orchestrator-fence.sh:6-18` and `skills/design/SKILL.md:1136` — `apply_gate_b_bypass_sentinels` refuses to run if any of `step-3`, `step-3.5`, or `step-3.6` already exist, and the empty-state pause test starts with none of them. Production bypass routing is two-phase: the Step 3 success boundary always writes `step-3` before Gate B, and bypass paths then add `step-3.5` and `step-3.6` before Step 3b. A faithful bypass run should usually have `step-3` before supplemental writes; the helper cannot model that layout and CI never exercises “`step-3` present, `step-3.5`/`step-3.6` absent → write supplementals → pause at 3b,” which is the realistic failure mode if an orchestrator follows only the second half of `1136`. **Suggested fix:** Split the helper into a supplemental writer (`! -f step-3.5` / `! -f step-3.6`, optionally requiring pre-existing `step-3`) and add a pause/resume case that seeds only `step-3` before invoking it; keep the all-empty helper only as an additional negative or isolation test.

- **risk-integration** `scripts/test-design-structure.sh:89-109` — Structural triple-sentinel coverage is scoped only to the `LOOP_STATUS=plan-size-trigger` bullet (awk region ending at `plan-validator-defects`). Other Gate-B-bypass statuses called out in `skills/design/SKILL.md:1132-1134` (`cap-reached`, `skipped-cap-reached`, `tally-error`, `degraded-empty-collector`, `panel-failed`, etc.) carry the same pause/resume contract in `scripts/design-pause-save.sh:82-83` but have no per-branch structural pin. Drift on those bullets would not fail CI while `plan-size-trigger` prose stays correct, and the new empty-state behavioral test would still pass via the shared helper. **Suggested fix:** Extend `assert_gate_b_bypass_branch_sentinels` (or add parallel assertions) for at least `panel-failed` and `cap-reached`, or factor a shared markdown excerpt and assert all bypass bullets reference it.
