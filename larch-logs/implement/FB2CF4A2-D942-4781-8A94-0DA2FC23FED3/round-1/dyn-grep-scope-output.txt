### In-Scope Findings

- **code-quality** `scripts/test-design-structure.sh:51-86` — Region-scoped `assert_thin_fence` writes the extracted slice to an `mktemp` file but only removes it on the success path (`[[ "$subject" == "$file" ]] || rm -f "$subject"`). Any `fail` call after scoping (missing marker, anti-shape violation, missing REPO on entry guard) exits without deleting the temp file, so a failing assertion can leave debris under `${TMPDIR:-/tmp}` and makes repeated local failures noisier. **Suggested fix:** Use a `trap` on the scoped path (`trap 'rm -f "$subject"' RETURN` or an ERR trap) so cleanup runs on every exit from the function, or wrap scoped checks in a subshell whose temp file is always removed.

- **code-quality** `scripts/test-design-structure.sh:72-78` — The file-first `.step3.6-assessor.env` anti-shape awk clears `in_read_loop` on any line containing `done`, not only a terminating `done <…assessor.env` redirect. A comment or string inside the `while read` body that contains the word `done` (for example `# not done yet`) resets the state machine before the real `done <"$DESIGN_TMPDIR/.step3.6-assessor.env"` line is evaluated, so the harness can miss a banned read-loop shape (false negative). **Suggested fix:** Only clear `in_read_loop` when `done` is a statement terminator (e.g. match `^[[:space:]]*done([[:space:]]|$)`), or require the redirect match on the same `done` line and drop the generic `done` reset rule.

- **code-quality** `scripts/test-design-structure.sh:56-57` — The scoped thin-fence positives still grep the whole extracted region for any `set +e` and any `$?`, not the assessor handoff block specifically. Because the Step 3.6 region also includes long markdown prose after the closing fence, a future edit could add documentation mentioning `$?` or `set +e` while removing the real `_assessor_rc=$?` capture in the bash fence, and the pin would still pass. **Suggested fix:** Narrow the positive checks to the first fenced bash block (extract lines between the opening and closing ` ```bash ` pair inside the region) or anchor greps near `_assessor_out` / `_assessor_rc`.

- **code-quality** `skills/design/scripts/test-step3-orchestrator-fence.sh:6-18` and `scripts/test-design-structure.sh:89-109` — Gate-B bypass coverage is split across two hand-maintained copies: `apply_gate_b_bypass_sentinels` (used by pause/resume tests) and `assert_gate_b_bypass_branch_sentinels` (markdown substring grep on the `plan-size-trigger` bullet).
