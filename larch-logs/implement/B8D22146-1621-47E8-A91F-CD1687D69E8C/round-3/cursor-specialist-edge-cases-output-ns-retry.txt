### FINDING_1: Parse-rate diag keyed by `voter_tool` collides across slots and disagrees with tally’s per-file diag map
- **Severity:** **Important**
- **Focus:** `correctness` / `risk-integration`
- **Location:** [scripts/dispatch-code-voters.sh](scripts/dispatch-code-voters.sh) `voter_parse_rate_diag_path` (lines 99–103) and all `check_voter_parse_rate` / `check_and_retry_voter_parse_rate` callers (e.g. 124–188, 230–266); contrast [skills/review/scripts/tally-code-votes.sh](skills/review/scripts/tally-code-votes.sh) `voter_parse_rate_diag_path` (198–207).
- **Issue:** When `voter_tool` is set, the diag path is always `$REVIEW_TMPDIR/${voter_tool}-parse-rate-diag.txt`, ignoring the voter **output basename**. Waterfall can run Claude for slot 2/3 while keeping paths `codex-vote-output.txt` / `cursor-vote-output.txt` with `VOTER_2_TOOL`/`VOTER_3_TOOL`=`claude`. Then slot 2 and slot 1 both read/write **`claude-parse-rate-diag.txt`**. A later slot that is parse-OK runs `rm -f "$diag_file"` on that same path and can **delete another slot’s NOT_SUBSTANTIVE evidence**. Separately, for `codex-vote-output.txt` + tool `claude`, tally still looks for **`codex-parse-rate-diag.txt`** (basename `codex-*`), so it **never sees** the parse-rate failure recorded under `claude-parse-rate-diag.txt`.
- **Scenario / breakage:** Codex/Cursor absent → both external slots fall back to Claude. Voter 1 stays NOT_SUBSTANTIVE (narrative); voter 2 on `codex-vote-output.txt` is structured OK. Voter 2’s OK branch removes `claude-parse-rate-diag.txt`, wiping voter 1’s diag. `tally-code-votes.sh` still counts voter 1’s narrative file in the quorum (no `claude-parse-rate-diag.txt`), while `dispatch-code-voters.sh` KV may still treat slot 1 as NOT_SUBSTANTIVE — **panel quorum / banners / vote math diverge** from filesystem truth.
- **Suggested fix:** Key diag paths off **stable output basename** (e.g. `${voter_path%.txt}-parse-rate-diag.txt` or slot-aware names), or drop the `voter_tool` fast-path and align dispatch with tally’s basename rules; only remove diag files that belong to the same output path.

### FINDING_2: `VOTER_COUNT` / `ELIGIBLE_VOTER_COUNT` contract change without repo-wide consumer audit beyond tally
- **Severity:** **Latent**
- **Focus:** `risk-integration`
- **Location:** [skills/review/scripts/tally-code-votes.sh](skills/review/scripts/tally-code-votes.sh) (emit lines ~582–583 per diff), [skills/review/scripts/tally-code-votes.md](skills/review/scripts/tally-code-votes.md).
- **Issue:** `VOTER_COUNT` now means effective quorum after parse-rate drops; new `ELIGIBLE_VOTER_COUNT` holds the raw count. In-repo grep shows only tally tests/docs referencing these keys today.
- **Scenario / breakage:** External automation or forked scripts that parsed `VOTER_COUNT` as “number of voter files passed” could mis-read panel tier after upgrade.
- **Suggested fix:** Call out the rename/meaning shift in release notes or keep backward-compatible alias key if external contracts matter.
