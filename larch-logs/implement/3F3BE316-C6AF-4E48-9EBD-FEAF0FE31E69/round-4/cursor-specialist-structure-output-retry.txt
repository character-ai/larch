### In-Scope Findings

1. **Important** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:559-714` — Public markdown is built by hardcoded `compose_body_content`, while the committed TSV and a third `code_allowlist_lines` heredoc exist only for `lint` key-name parity; the plan called for the helper to load the TSV at startup and compose `bug-body` from the allowlist. A maintainer can add a TSV/doc field, pass `lint`, and still ship output that never emits it. **Suggested fix:** Drive composition from `stall-recovery-report-allowlists.tsv` (or generate the heredoc from the TSV at build/lint time) and extend `lint` to assert every allowlisted field is emitted with the documented transform.

2. **Important** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:104-190` — Three near-copy validators (`validate_failure_detail_log`, `validate_tmpdir_local_file`, `validate_tmpdir_write_file`) repeat absolute-path, canonical-dir, symlink, tmpdir-prefix, and regular-file checks (~85 lines). The repo already has canonical-path helpers in [`scripts/lib-larch-log.sh`](scripts/lib-larch-log.sh) and [`scripts/lib-timing-paths.sh`](scripts/lib-timing-paths.sh). **Suggested fix:** Extract one shared `validate_path_under_tmpdir(mode=read|write|optional)` helper and call it from all three sites; keep distinct error messages via a `flag_name` parameter.

3. **Latent** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:253-269` — Retry caps/delays live in `retry_cap_for` / `retry_delay_for` while [`stall-recovery-report.md`](skills/implement/scripts/stall-recovery-report.md) claims to be the single normative source; `lint` does not compare code to that table. Harness case 7 only spot-checks transient/same-cause/unrecoverable caps. **Suggested fix:** Add a `lint` or harness assertion that parses the markdown retry table (or TSV-ify caps) and diffs against `retry-policy` output for every `FAILURE_CLASS`.

4. **Latent** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:340-347` — When no validated `--failure-detail-log` is present, `classify` concatenates entire `ship-pr-state.sh` and `session-env.sh` into classifier evidence with no size bound (detail logs are capped at 64 KiB). A bloated session env could slow or skew pattern matching. **Suggested fix:** Cap evidence ingestion (truncate with a marker, or read only allowlisted keys via `read-session-env-key.sh`) before `classify_from_evidence`.

5. **Nit** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:617-632` — `bug-body` / `bug-comment` require `--classification-file` but do not confine it under `$IMPLEMENT_TMPDIR`, unlike `--body-file`, `--attempts-file`, and `--failure-detail-log`. **Suggested fix:** Reuse the shared tmpdir validator for `--classification-file` (read-only mode) for a consistent input surface.

6. **Nit** `code-quality` `skills/implement/scripts/stall-recovery-report.sh:56-71` — Local `kv_get` duplicates parsing already centralized in [`scripts/read-session-env-key.sh`](scripts/read-session-env-key.sh). **Suggested fix:** Call the existing helper where feasible, or extract a tiny shared `lib-session-env-kv.sh` if subprocess cost matters.
