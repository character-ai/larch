### In-Scope Findings

- **security** `skills/implement/scripts/stall-recovery-report.sh:617-656` — **Latent:** `bug-body` / `bug-comment` accept `--classification-file` with only a readability check—no tmpdir prefix, symlink rejection, or regular-file guard—unlike `--body-file` and `--attempts-file` writes. A same-UID writer could point the orchestrator at a symlinked sensitive KV file; public output is mostly sanitized via `safe_*`, but this weakens defense-in-depth versus the documented four-surface allowlist model. **Suggested fix:** Reuse `validate_tmpdir_local_file` (or a read-only variant) for `--classification-file` when it lives under `$IMPLEMENT_TMPDIR`, and reject symlinks/non-regular files before `kv_get`.

- **security** `skills/implement/scripts/stall-recovery-report.sh:582-604` — **Latent:** `bug-comment` reads `--attempts-file` without the tmpdir/symlink containment enforced by `init-attempts` / `record-attempt` (`validate_tmpdir_write_file`). A mis-pointed path could pull another session’s attempt metadata into the terminal comment (signatures/classes only, but still cross-session bleed under shared `/tmp`). **Suggested fix:** Apply the same `validate_tmpdir_local_file` check to `--attempts-file` on read paths in `bug-comment` (and optionally `classify --attempts-file`).

- **security** `skills/implement/scripts/stall-recovery-report.sh:334-337` — **Latent:** `--failure-detail-log` is validated then `cat`’d without an open-time re-check; a same-UID TOCTOU could swap a validated regular file for a symlink between checks and read, pulling up to 64 KiB of out-of-tmpdir content into classifier evidence (evidence is not published directly, but could influence mis-routing). **Suggested fix:** Open the log with `O_NOFOLLOW` semantics (e.g., `python -c` / `read` builtin on a verified fd) or re-validate inode/device immediately before read, matching patterns used elsewhere in the repo.

- **security** `skills/implement/scripts/stall-recovery-report.sh:636-650` — **Nit:** Optional `--output-file` (and the transient `"$out_file.raw.$$"` sibling) can target any user-writable absolute path, not only `$IMPLEMENT_TMPDIR`. Within larch’s operator-trust model this is orchestrator-controlled, but it is an avoidable footgun if prompt-side args are ever wrong. **Suggested fix:** When `--implement-tmpdir` is set, require `--output-file` to pass the same tmpdir prefix/symlink checks as `--body-file`, or default exclusively under tmpdir.
