### In-Scope Findings

1. **Important** `risk-integration` `skills/implement/references/stall-recovery.md:11-13` — Step 18a classification tells the orchestrator to pass `--failure-detail-log` only after manual validation, but never says to read `BAIL_FAILURE_DETAIL_LOG` from `ship-pr-state.sh`. `ship-pr.sh` already sets that key to tmpdir-local capture files on several stall paths (e.g. `ci-local-unfixable`, `failure_capture_path`). **Scenario:** A Step 8+ stall with a populated `BAIL_FAILURE_DETAIL_LOG` runs recovery without forwarding that path; `classify` falls back to concatenated `ship-pr-state.sh` / `session-env.sh`, so stale `NOTE=` / `BAIL_REASON` lines can override the intended primary evidence and mis-route retries (plan failure mode 2). **Suggested fix:** In `stall-recovery.md` step 3 (and Step 18a SKILL cross-ref), require: read `BAIL_FAILURE_DETAIL_LOG` via `read-session-env-key.sh`, run the existing validator, pass `--failure-detail-log` when valid; optionally add a harness fixture with state pointing at a detail log.

2. **Important** `architecture` `skills/implement/references/stall-recovery.md:34-34` — Terminal-failure handling depends on prose-only seeding/rewriting of `ship-pr-state.sh` when it was never created (early bail before Step 8). There is no helper subcommand and no harness case for that seed path (case 19 covers success clear only). **Scenario:** Recovery exhausts on `tracking-init-failed` with in-memory `STALL_TRACKING=true` but no `ship-pr-state.sh`; Step 18b skips `restore-finalize-state.sh`, `implement-finalize.sh` reads `finalize-state.sh` with default/non-stalled `STALL_TRACKING`, and Branch A `[STALLED]` never runs despite SKILL promising disk-gated rename. **Suggested fix:** Add a small script (e.g. `stall-recovery-persist-stall.sh`) that atomically writes the canonical minimal Step-8-shape state under `$IMPLEMENT_TMPDIR`, call it from the reference, and add harness case asserting `restore-finalize-state` + `STALL_TRACKING=true` before teardown.

3. **Latent** `architecture` `skills/implement/references/stall-recovery.md:22-22` — Per-class retry caps are exposed via `retry-policy` but never enforced in shell; the retry loop is entirely orchestrator prose. **Scenario:** A mis-counting or halt-resuming agent issues nine `test-failure` dispatches without hitting a mechanical stop. **Suggested fix:** Add `should-retry --attempts-file … --class …` (or fold into `record-attempt`) that compares `attempt_count` to `MAX_ATTEMPTS` and exits non-zero when exhausted, and call it from the reference before each dispatch.

4. **Latent** `risk-integration` `skills/implement/SKILL.md:1754-1754` — Anti-halt text says “after issue filing or dry-run print, continue to dispatch” on every recovery iteration, while `stall-recovery.md` step 4 limits issue filing to `attempt_count==0`. **Scenario:** On retry 2+ the agent re-runs `/larch:issue`, creating duplicate or semantically-deduped noise. **Suggested fix:** Tighten SKILL anti-halt to “after first-detection issue filing when `attempt_count==0`, otherwise skip to dispatch.”

5. **Latent** `correctness` `skills/implement/scripts/stall-recovery-report.sh:46-53` — `FAILURE_SIGNATURE` hashes via `shasum`/`sha256sum`, but falls back to `cksum` when neither exists. **Scenario:** On a host without SHA-256, signature collisions/dedup behavior diverge from CI and from `/larch:issue` semantic dedup expectations. **Suggested fix:** Fail closed (exit 2) if no SHA-256 hasher is available, or document and test the fallback separately.

6. **Nit** `correctness` `skills/implement/scripts/stall-recovery-report.sh:357-363` — `classify --attempts-file` reads the attempts file with no tmpdir-prefix validation (unlike `init-attempts` / `record-attempt`). **Scenario:** A mistyped absolute path outside `$IMPLEMENT_TMPDIR` is read for signature comparison (no write). **Suggested fix:** Reuse `validate_tmpdir_local_file` (read-only mode) before `latest_attempt_signature`.
