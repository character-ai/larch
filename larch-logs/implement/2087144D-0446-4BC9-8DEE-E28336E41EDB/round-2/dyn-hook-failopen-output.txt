### Out-of-Scope Observations

- **risk-integration** `skills/upgrade-larch/scripts/upgrade-larch.sh:437-438` — `LARCH_CONE_RECONCILED=true` is printed whenever `MARKETPLACE_CONE_WILL_RECONCILE` was set before the reinstall path, including when the run later exits **1** because `VERIFIED_TARGET` is false (lines 460–462). `/release` Step 7 parsing that signal could treat a failed upgrade as a successful same-version cone reconcile and drive an unnecessary restart. **Suggested fix:** Emit `LARCH_CONE_RECONCILED=true` only after post-install `marketplace_sparse_cone_matches` succeeds (and same-version reconcile was the reason for the path).

- **risk-integration** (residual, plan-intentional) `scripts/sessionstart-health.sh:66-70` — When `lib-sparse-dirs.sh` is absent from the installed `SCRIPT_DIR` tree (case 4e in `scripts/test-sessionstart-health.sh`), a drifted marketplace clone produces no advisory. That matches the fail-open contract but leaves the pre-fix cohort (broken cone, no new lib on disk) without SessionStart visibility until `/upgrade-larch` or manual repair runs; the hook cannot warn until the library file exists in the active plugin checkout.

- **architecture** (pre-existing, documented in `SECURITY.md:151-153`) — The sparse probe runs only inside the `JQ_AVAILABLE && GIT_AVAILABLE` gate (line 92). When `jq` is missing, the emission path uses fixed JSON literals and never surfaces dynamic `MSG` content, so sparse drift is not warned in jq-stripped environments even if `git` is available. This is consistent with the jq-missing hardening model, not a regression from the new probe logic.
