Reviewing the branch diff and key upgrade/release paths for cache-root resolution and prune protection.
### In-Scope Findings

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:73-77,457-463` — `already_latest_and_cone_ok()` gates the idempotent early-exit on `get_installed_larch_version()` (metadata) equaling `LATEST_STABLE` plus a marketplace sparse-cone match, but it never compares that metadata version to `INSTALLED_VERSION` (`basename "$PLUGIN_ROOT"`). `/release` Step 7 deliberately runs the working-tree script with `CLAUDE_PLUGIN_ROOT="$RESOLVED_ROOT"` on the **active** cache root while installed metadata can already name a newer version (documented in `.claude/skills/release/SKILL.md:150-151,217`). In that state, if the marketplace cone already matches (manual repair, partial upgrade, or in-place `marketplace update`), the script prints `No upgrade needed.` and exits without reinstalling, so the active cache directory can still lack newly allowlisted paths (e.g. `python/`) even though metadata says latest. **Suggested fix:** When `PLUGIN_ROOT` is cache-shaped, require `CURRENT_INSTALLED_VERSION = INSTALLED_VERSION` before the early-exit (or treat `INSTALLED_VERSION != CURRENT_INSTALLED_VERSION` like cone drift and fall through to uninstall/reinstall). Add a harness case: active `.../larch/1.0.0`, metadata `2.0.0`, matching marketplace cone, `LATEST_STABLE=2.0.0` — must not early-exit.

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:518-523` — `LARCH_CONE_RECONCILED=true` is emitted whenever `MARKETPLACE_CONE_WILL_RECONCILE` was set at the start of the run, even when the post-reinstall `marketplace_sparse_cone_matches` check still fails (only a warning is printed at lines 519-520). `/release` Step 7 treats that line as authoritative for `CONE_RECONCILED` and Step 8 restart policy (`.claude/skills/release/SKILL.md:180-192,272`). A failed cone repair can therefore be reported as reconciled and trigger a restart without fixing the underlying drift. **Suggested fix:** Emit `LARCH_CONE_RECONCILED=true` only when `marketplace_sparse_cone_matches` succeeds after reinstall; otherwise emit a distinct failure signal or omit the reconcile flag so release automation does not assert success.

### Out-of-Scope Observations

- **correctness** `skills/upgrade-larch/scripts/release-step7-root.sh:89-95` — When installed metadata resolves to a version but `$cache_parent/$installed_version` is missing, `resolve_release_step7_root` returns failure immediately and does not fall through to the `CURRENT_VERSION` / sole-cache fallbacks in items 3–4 of the release contract. The harness encodes this as intentional (`test-upgrade-larch-retention.sh:268-273`), but it means `/release` Step 7 can skip the working-tree upgrade and fall back to the stale installed Skill when metadata and on-disk cache are out of sync.
