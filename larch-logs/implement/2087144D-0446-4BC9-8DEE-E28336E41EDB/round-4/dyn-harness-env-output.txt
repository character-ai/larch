### In-Scope Findings

- **risk-integration** `skills/upgrade-larch/scripts/release-step7-root.sh` — The committed harness and release Step 7 both `source` this helper (`test-upgrade-larch-retention.sh:12`, `test-upgrade-larch-retention.sh:128-130`, `.claude/skills/release/SKILL.md:167-168`), but the file is **not in `HEAD`** (`git show HEAD:skills/upgrade-larch/scripts/release-step7-root.sh` fails) and does not appear in the branch diff as a new file. On a clean checkout or CI, root-resolution cases and `make test-upgrade-larch-retention` will fail at `source` even though a developer machine with an untracked copy can look green. **Suggested fix:** Add `skills/upgrade-larch/scripts/release-step7-root.sh` (and its `release-step7-root.md` contract sibling per repo script rules) to the branch, or drop/guard the `source` until the helper is actually shipped.

- **risk-integration** `skills/upgrade-larch/scripts/test-upgrade-larch-retention.sh:329-492` — The three “production” integration cases prepend a stub `bin_dir` to `PATH` and only restore it after all assertions succeed (`PATH="$old_path"` at lines 386, 440, 492). With `set -euo pipefail`, a mid-block failure leaves stub `gh`/`claude` ahead of real tools for later cases, so failures can cascade or mask the real defect. **Suggested fix:** Wrap each production block in a subshell, or use `trap 'PATH=$old_path' RETURN` / explicit `PATH="$old_path"` in an `EXIT` trap for that block so `PATH` is always restored.

- **risk-integration** `scripts/test-sessionstart-health.sh:260` — Sparse “matching cone” coverage (`case 4c`) uses a hard-coded `EXPECTED_SPARSE_DIRS` array, while `skills/upgrade-larch/scripts/test-upgrade-larch-retention.sh:13,187` guards `scripts/lib-sparse-dirs.sh` with a separate literal. There is no cross-harness check tying the SessionStart array to the library, so an allowlist edit can update the lib + retention guard but leave `4c` building a stale cone (false pass) or an over-full cone (false fail). **Suggested fix:** Source `scripts/lib-sparse-dirs.sh` in the SessionStart harness and build the matching fixture from `normalize_sparse_dirs` / `LARCH_SPARSE_DIRS`, or add a small shared test helper that both harnesses use for the expected set.
