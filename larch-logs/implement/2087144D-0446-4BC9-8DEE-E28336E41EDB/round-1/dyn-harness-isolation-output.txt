### In-Scope Findings

- **correctness** `skills/upgrade-larch/scripts/test-upgrade-larch-retention.sh:293-310` — The “cone-reconcile detection” and “captured `2>&1` upgrade invocation” cases exercise a local stub (`$TMP/upgrade-stub.sh`) and helper functions, not `bash "$UPGRADE_SCRIPT"` against a drifted marketplace fixture. - **correctness** `skills/upgrade-larch/scripts/test-upgrade-larch-retention.sh:132-173` — `resolve_release_step7_root_for_test` mirrors release Step 7 ordering in prompt-only `.claude/skills/release/SKILL.md:146-153`, but there is no Makefile harness for release Step 7 and no negative case where `CURRENT_VERSION` disagrees with parsed installed metadata while multiple cache dirs exist (e.g. installed `2.0.0` with only `3.0.0` on disk falls through to the sole-cache branch at lines 167-170). The acceptance criterion “probe does not depend on later `PLUGIN_ROOT`” is therefore not exercised. **Suggested fix:** Add a case inside a real git worktree (stdin `cwd` in-repo) with isolated `HOME` drift fixture and a deliberately wrong `CLAUDE_PLUGIN_ROOT` (e.g. empty or non-marketplace path); assert the sparse advisory still follows `$HOME/.claude/plugins/marketplaces/larch-local`, not `PLUGIN_ROOT`.

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:429-436` — `LARCH_CONE_RECONCILED=true` is emitted only when `VERIFIED_TARGET=true` after reinstall.
