Reviewing the branch diff and key files for sparse-allowlist architecture issues.
### In-Scope Findings

- **architecture** `.claude/skills/release/SKILL.md:148-166` — Release Step 7 defines a four-tier `RESOLVED_ROOT` contract and a captured working-tree upgrade invocation, but the shipped bash fence stops at `# Resolve RESOLVED_ROOT using the ordering above before this point.` with no canonical resolver script. The only executable mirror is `resolve_release_step7_root_for_test()` in `skills/upgrade-larch/scripts/test-upgrade-larch-retention.sh:132-173`, which `/release` does not call. Production behavior therefore depends on prompt-side reimplementation that can drift from the harness (wrong cache root → prune/stamp against a non-active tree), which is the same class of failure the plan calls out for RC1. **Suggested fix:** Extract `resolve_release_step7_root()` (and optionally `detect_cone_reconcile_from_output()`) into a sourced library under `scripts/` or `skills/upgrade-larch/scripts/`, source it from both the release Step 7 fence and the retention harness, and replace the SKILL placeholder comment with a single documented invocation.

- **architecture** `scripts/lib-sparse-dirs.md:3-15` — The contract claims `scripts/lib-sparse-dirs.sh` is the “single source of truth” and lists edit-in-sync obligations for prose docs plus `test-upgrade-larch-retention.sh`, but it does not mention `scripts/test-sessionstart-health.sh:260`, which hardcodes a third copy as `EXPECTED_SPARSE_DIRS=(.claude .claude-plugin …)`. A future allowlist edit can update the lib and retention literal guard while SessionStart fixtures still assert the old cone, so the warn-only surface and upgrade/reconcile surface diverge without failing `make test-upgrade-larch-retention`. **Suggested fix:** Extend the edit-in-sync list to include `scripts/test-sessionstart-health.sh`, or have that harness source `lib-sparse-dirs.sh` and derive expected dirs via `normalize_sparse_dirs` (same pattern as production `sessionstart-health.sh`), keeping at most one intentional literal guard.

- **architecture** `scripts/sessionstart-health.sh:45-77`, `skills/upgrade-larch/scripts/upgrade-larch.sh:52-64` — The sparse-cone contract is split across surfaces: allowlist data lives in `lib-sparse-dirs.sh`, but drift detection rules (`git sparse-checkout list` normalization, `larch-logs/` exclusion, empty-configured guard, marketplace path binding) are duplicated in the SessionStart probe and in `marketplace_sparse_cone_matches()`. `lib-sparse-dirs.md` documents data-only SSOT, not comparison SSOT, so a rule change (e.g. also checking `known_marketplaces.json` `sparsePaths`, or treating legacy full clones differently) can make SessionStart warn while `/upgrade-larch` early-exits, or vice versa. **Suggested fix:** Move a shared `marketplace_sparse_cone_matches()` (or `sparse_cone_drifts_from_allowlist()`) into `scripts/lib-sparse-dirs.sh` with no side effects, and call it from both `upgrade-larch.sh` and `probe_sparse_cone_drift()` so warn-only and reconcile paths share one comparison implementation.

- **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:434-436`, `.claude/skills/release/SKILL.md:175-179` — Cross-step signaling treats `LARCH_CONE_RECONCILED=true` as the primary machine line for Step 8 restart, but the script emits it only inside the `VERIFIED_TARGET=true` block after `gh`-backed stable verification. Same-version cone reconciliation still runs when `NEEDS_CONE_RECONCILE=true`, but if verification fails (or `LATEST_STABLE` is unset), the reconcile fragment may appear without `LARCH_CONE_RECONCILED=true`, forcing release to rely on substring matching and risking a missed restart after a successful cone repair. **Suggested fix:** Emit `LARCH_CONE_RECONCILED=true` whenever `NEEDS_CONE_RECONCILE=true` and `refresh_larch_marketplace` + install complete successfully, independent of `VERIFIED_TARGET`, or document and test that release must treat successful exit + reconcile fragment as sufficient even when verification fails.
