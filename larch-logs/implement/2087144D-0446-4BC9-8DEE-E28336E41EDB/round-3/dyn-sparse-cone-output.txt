Reviewing the branch diff and commit history for sparse-checkout architecture issues.
### In-Scope Findings

- **architecture** `.claude/skills/release/SKILL.md:167-168` — Step 7 `source`s the full `skills/upgrade-larch/scripts/upgrade-larch.sh`, but the script’s top-level preamble (lines 7–17 and 399–401 in `upgrade-larch.sh`) runs before the sourced early-return at 404–406: it loads `lib-quiet.sh` from `PLUGIN_ROOT`, calls `larch_quiet_init`, partially restores stdout with `exec 1>&3`, and sets `LARCH_CACHE_DIR` / `INSTALLED_VERSION` in the **parent** orchestrator shell. Release does not set `LARCH_QUIET_DISABLE=1`, so a `/release` Step 7 fence can redirect the orchestrator’s stderr to a quiet log (fd 2 is not restored), export `LARCH_QUIET_*`, and leave misleading cache globals—undermining the captured `2>&1` contract and later Step 7/8 output. **Suggested fix:** Move `resolve_release_step7_root` (and any other source-only helpers) into a small sourced library (e.g. `scripts/lib-upgrade-larch-release.sh`) with no quiet init, no `exit`, and no cache globals; or gate all preamble side effects behind `[[ "${BASH_SOURCE[0]}" == "${0}" ]]` before `larch_quiet_init`, and document `export LARCH_QUIET_DISABLE=1` in the release Step 7 fence before sourcing.

- **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:9-11` — The missing-allowlist check uses `exit 1` before the sourced-return guard (404–406). If anything ever `source`s the script when `SCRIPT_ROOT/scripts/lib-sparse-dirs.sh` is absent, `exit 1` terminates the **caller** shell (e.g. a partial release checkout), not just the source. **Suggested fix:** Use `return 1` when `BASH_SOURCE[0] != $0`, reserve `exit 1` for direct execution, or relocate the check into the executable-only block after the source guard.

- **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:516-518` + `.claude/skills/release/SKILL.md:179-180` — `LARCH_CONE_RECONCILED=true` is emitted only when `MARKETPLACE_CONE_WILL_RECONCILE=true` **and** `marketplace_sparse_cone_matches` succeeds after reinstall; release Step 8 restart coupling keys solely off that machine line (no prose fallback in the skill, and tests explicitly reject the reconcile banner as a signal). If reinstall succeeds but the post-install cone comparison still fails (format drift, partial marketplace repair, or comparison false negative), Step 7 leaves `CONE_RECONCILED=false` even though the operator was told the cone was being repaired—same stale in-memory plugin failure mode RC1/Step 8 were meant to close. **Suggested fix:** Emit `LARCH_CONE_RECONCILED=true` when a same-version reconcile path was entered (`NEEDS_CONE_RECONCILE=true` / `MARKETPLACE_CONE_WILL_RECONCILE=true`) and the upgrade exits 0 after `claude plugin install`, or add the planned substring fallback in release Step 7 parsing when install succeeded but the machine line is absent.

- **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:7-14` — Allowlist correctly comes from `SCRIPT_ROOT`, but `lib-quiet.sh` still loads from `PLUGIN_ROOT` (`CLAUDE_PLUGIN_ROOT` / active cache). On the transitional release that introduces `lib-sparse-dirs.sh`, an older cache root may ship a different `lib-quiet.sh` while sparse policy is read from the working tree—splitting operational vs policy sources across install trees. **Suggested fix:** For direct execution, source `lib-quiet.sh` from `SCRIPT_ROOT` as well (with `PLUGIN_ROOT` reserved for cache/stamp/prune paths only), or document that release Step 7 must run with a cache root new enough to carry a compatible quiet helper.
