Reviewing the branch diff and key Bash runtime paths for correctness issues.
### In-Scope Findings

- **correctness** `.claude/skills/release/SKILL.md:167-190` — Step 7 `source`s `upgrade-larch.sh` in the same shell that later prints operator messages. Sourcing runs `larch_quiet_init` and `exec 1>&3` (`skills/upgrade-larch/scripts/upgrade-larch.sh:15-17`), which redirects FD 2 to the quiet log while only restoring stdout. Plain `echo`/`echo "Warning:..."` in that fence then goes to the quiet log, not the operator’s terminal, so release-time warnings can disappear even when the child `bash …/upgrade-larch.sh` run succeeds. **Suggested fix:** Resolve the root in an isolated subshell (e.g. `RESOLVED_ROOT=$(LARCH_QUIET_DISABLE=1 bash -c 'source …; resolve_release_step7_root "$1"' _ "${CURRENT_VERSION:-}")`), or set `LARCH_QUIET_DISABLE=1` before the `source`, or move `resolve_release_step7_root` into a small sourced-only helper that does not call `larch_quiet_init`.

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:398-405` — The source early-return is placed *after* `LARCH_CACHE_DIR="$(dirname "$PLUGIN_ROOT")"` and `INSTALLED_VERSION="$(basename "$PLUGIN_ROOT")"`, so `/release` Step 7’s `source` still mutates the parent shell with cache globals derived from `PLUGIN_ROOT`/`SCRIPT_ROOT` before returning. That can skew any later logic in the same Step 7 fence that assumes a clean environment. **Suggested fix:** Move the `BASH_SOURCE`/`return` guard (and ideally only function definitions plus sparse-lib sourcing) above the `LARCH_CACHE_DIR` / `INSTALLED_VERSION` assignments, or resolve roots from a subshell that never exports those globals into the release driver.

- **correctness** `.claude/skills/release/SKILL.md:178-187` — `CONE_RECONCILED` / `RESTART_REQUIRED` are parsed only when `upgrade_rc -eq 0`, but `upgrade-larch.sh` emits `LARCH_CONE_RECONCILED=true` (`skills/upgrade-larch/scripts/upgrade-larch.sh:516-518`) *before* the verification gate that can `exit 1` (`skills/upgrade-larch/scripts/upgrade-larch.sh:541-543`). A run can repair the marketplace cone, print the machine line, and still exit non-zero if stable verification fails; Step 7 then writes `CONE_RECONCILED=false`, and Step 8 will not mandate restart despite a cone-only repair (failure mode called out in the plan). **Suggested fix:** Parse `LARCH_CONE_RECONCILED=true`, `LARCH_NEW_VERSION_INSTALLED=true`, and `LARCH_RESTART_REQUIRED=true` from captured output regardless of exit code (treat non-zero as failure for messaging, not for dropping reconcile signals), or emit `LARCH_RESTART_REQUIRED=true` whenever `LARCH_CONE_RECONCILED=true` is emitted and document that contract.

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:516-525` — After a successful same-version cone repair (`MARKETPLACE_CONE_WILL_RECONCILE` + post-refresh `marketplace_sparse_cone_matches`), the script emits `LARCH_CONE_RECONCILED=true` but does **not** emit `LARCH_RESTART_REQUIRED=true` unless `LATEST_STABLE` is empty. `/release` Step 8 also keys off `RESTART_REQUIRED` from `release-step7.env`; it works when `CONE_RECONCILED=true` is parsed on `upgrade_rc=0`, but any consumer that only watches `LARCH_RESTART_REQUIRED=true` will miss the restart requirement on the primary happy path. **Suggested fix:** On the cone-reconciled branch, also emit `LARCH_RESTART_REQUIRED=true` (or document and enforce a single canonical line) so all automation paths agree.
