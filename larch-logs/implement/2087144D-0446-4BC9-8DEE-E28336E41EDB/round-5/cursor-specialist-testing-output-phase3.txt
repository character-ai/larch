The test harness references `RELEASE_STEP7_ROOT_SCRIPT="$SCRIPT_DIR/release-step7-root.sh"` and sources it in `resolve_release_step7_root_for_test`; every root-resolution test case (`root-active`, `root-metadata`, `root-metadata-missing`, `root-current-matches-metadata`, `root-current-sole`, `root-zero`, `root-ambiguous`) depends on it and will fail with "No such file or directory" on a clean checkout. Without this file committed, `make test-upgrade-larch-retention` fails and the release skill is broken for any operator pulling a clean checkout of this branch. **Suggested fix:** Stage and commit `skills/upgrade-larch/scripts/release-step7-root.sh` as part of this PR.

- **risk-integration** `skills/upgrade-larch/scripts/` (whole directory) — **Important** `release-step7-root.sh` is a new script under `skills/upgrade-larch/scripts/` but has no sibling `release-step7-root.md` contract, violating the project invariant in `.claude/rules/script-md-siblings.md` that every `.sh` file must have a co-located `.md`. The `agent-lint.toml` diff adds excludes for `lib-sparse-dirs.sh` and `lib-sparse-dirs.md` but does not add any entry for `release-step7-root.sh`. If `make lint` runs `agent-lint` on this file as a dead/uninvoked script (it has a shebang and is executable, but is intended to be sourced), the lint will fail; and the missing sibling `.md` will trip the `script-md-siblings` lint separately. **Suggested fix:** Add `skills/upgrade-larch/scripts/release-step7-root.md` as a sibling contract doc. If agent-lint flags it as a dead script, also add an exclude entry in `agent-lint.toml` with a sourced-only comment.

- **risk-integration** `skills/upgrade-larch/scripts/upgrade-larch.sh:521-530` — **Latent** `LARCH_RESTART_REQUIRED=true` is emitted twice when both `MARKETPLACE_CONE_WILL_RECONCILE=true` and `LATEST_STABLE=""` — once in the `elif [ -z "$LATEST_STABLE" ] || [ "$VERIFIED_TARGET" = true ]` branch of the cone-reconcile block (line 526), and again in the unconditional `if [ -z "$LATEST_STABLE" ]` block (line 530). The production test cases do not exercise this combination (the `production-drift` test has `gh` available; the `production-unverified-reinstall` test has a matching cone so `MARKETPLACE_CONE_WILL_RECONCILE=false`), so the double-emission is undetected. Release Step 7 parsing uses substring matching and is unaffected today, but any future consumer that counts or dedupletes the signal tokens would silently see two. **Suggested fix:** Guard the `[ -z "$LATEST_STABLE" ]` block at line 529 with `[ "$MARKETPLACE_CONE_WILL_RECONCILE" != true ]` (or an equivalent single-emission flag) so `LARCH_RESTART_REQUIRED=true` is emitted exactly once per run.

- **code-quality** `scripts/sessionstart-health.sh:46-90` — **Nit** `probe_sparse_cone_drift` restores `set -e`/`set -u` with an identical two-line block immediately before each of the three early `return 0` statements. If a future maintainer adds a new early-exit path and omits the restore, `errexit`/`nounset` could remain disabled for the rest of the hook. **Suggested fix:** Move the restore into a `trap ... RETURN` set at function entry, or extract a single helper function (`restore_shell_opts`) called by all exit paths.
