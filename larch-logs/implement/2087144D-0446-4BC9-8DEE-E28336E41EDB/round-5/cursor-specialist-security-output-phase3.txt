- **correctness** `.claude/skills/release/SKILL.md` Step 7 bash fence (diff line +93) and Step 8 bash fence (diff line +145) — `printf 'RESOLVED_ROOT=%s\n' "$RESOLVED_ROOT"` writes the value with `=` as a delimiter; Step 8 reads it with `awk -F= '$1=="RESOLVED_ROOT"{print $2; exit}'`. If `RESOLVED_ROOT` itself contains a literal `=` (possible for users whose `$HOME` path includes one, e.g. `<OPERATOR_REPO_PATH>, `awk` returns only the substring after the first `=` and before the next, silently corrupting the stored path. `RESOLVED_ROOT` is not used for control flow in Step 8 (only `CONE_RECONCILED`/`RESTART_REQUIRED` drive restart decisions), so this is a diagnostic corruption rather than a security hole, but it could confuse debugging. **Suggested fix:** Either strip `RESOLVED_ROOT` from the state file (it is not consumed in Step 8), or use a delimiter that cannot appear in a filesystem path (`|`, `\t`) or write/read it as the last field taking the rest of the line with `awk -F= 'NR==FNR && $1=="RESOLVED_ROOT"{print substr($0, index($0,"=")+1); exit}'`.

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh` (resolve_release_step7_root last-resort block, diff lines around `sole_root=$(single_larch_cache_version_dir...)` at the end of `resolve_release_step7_root`) — When `CLAUDE_PLUGIN_ROOT` is unset, installed metadata is unavailable (`get_installed_larch_version` returns nothing), and `current_version` is either not provided or doesn't match an existing dir, the function falls through to `single_larch_cache_version_dir` and returns whatever single directory it finds **without verifying it matches `current_version`**. This means a release where `CURRENT_VERSION` is e.g. `47.0.72` but the only cached dir is `47.0.70` would bind `RESOLVED_ROOT` to the old dir, then prune and stamp against it. The plan documents this as an intentional "last resort" fallback, but the code diverges from the plan's wording ("when (2) is unavailable and `CURRENT_VERSION` is the sole defensible cache target") by not checking that `current_version` matches the sole dir. **Suggested fix:** Gate the final fallback on `[ "$sole_root" = "$cache_parent/${current_version}" ]` (or at minimum only return it when `current_version` is non-empty), so a stale sole-cache-dir is not silently selected as the prune/stamp context for a different release.
