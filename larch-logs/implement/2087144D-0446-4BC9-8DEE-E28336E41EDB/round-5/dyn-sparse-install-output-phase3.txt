- **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:197-235` and `skills/upgrade-larch/scripts/release-step7-root.sh:77-115` — `resolve_release_step7_root` and its three helpers (`is_cache_shaped_larch_root`, `single_larch_cache_version_dir`, `get_installed_larch_version`) are duplicated in both files with diverging implementations: `upgrade-larch.sh` binds `cache_parent` directly from `$HOME`, while `release-step7-root.sh` routes through `release_step7_cache_parent()`. - **architecture** `skills/upgrade-larch/scripts/upgrade-larch.sh:508-512` — Inside the version-mismatch warning block, `marketplace_clone=$(marketplace_clone_path 2>/dev/null || true)` is called and the result expanded inline into a `larch_err` line via `$(shell_quote "$marketplace_clone")`. `shell_quote` uses `printf '%q'`, which is a Bash built-in `printf` extension not available in the Bash 3.2 environment mandated by `BASH_AUTHORING.md`. On macOS Bash 3.2.57 `printf '%q'` silently emits nothing, leaving the recovery line as `rm -rf ` with no path. This only affects the human-readable error message (not script correctness), but it is still a Bash 3.2 compatibility violation. **Suggested fix:** Replace `shell_quote` with a portable single-quote escaping idiom: `sq() { printf "'%s'" "$(printf '%s' "$1" | sed "s/'/'\\''/g")"; }`, or simply emit the literal `~/.claude/plugins/marketplaces/larch-local` in the warning (acceptable because `marketplace_clone_path` always returns that fixed path).

### Out-of-Scope Observations

- **architecture** `scripts/sessionstart-health.sh:44-90` — The `probe_sparse_cone_drift` function saves and restores `errexit`/`nounset` flags via `case $-` on entry and `[[ "$restore_*" == "true" ]] && set -e / set -u` on each return path. Bash's `case $-` is evaluated at function-entry time, not deferred; if a future caller invokes this function under `set -e` without having the function itself bracketed by `set +e`, the restoration branches are reached only if the function body itself doesn't abort. This is fine as currently written (all abort paths call return 0), but the pattern is fragile: any future `set -e`-sensitive addition inside the function that exits before the restoration lines will permanently disable errexit for the parent shell. A cleaner idiom is `local -` (bash 4.4+) or wrapping the whole body in a subshell for pure-read work.
