Reviewing the branch diff and shell failure-handling around FINALIZE and SIMPLE sentinel writes.
### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:827-838` — The Step 2a.5 SIMPLE repair fence only writes `.completed` markers when sentinel artifacts are missing (full rewrite branch) or when `.completed/step-2a` exists but `.completed/step-2a.5` does not (`elif` branch). If a SIMPLE resume reaches Step 2a.5 with all three sentinel files already present but **both** completion markers absent—a plausible corrupt or hand-edited tmpdir—the repair block is a no-op, the SIMPLE dialectic skip still runs, and only the later Step 2a.5 success-boundary prose (line 875) would write `.completed/step-2a.5`, never `.completed/step-2a`. That leaves pause/resume and `2a.2`’s “full package” checks in an inconsistent state (artifacts OK, `step-2a` missing). **Suggested fix:** Add a third branch for `_simple_artifacts_ok=true` that writes whichever of `.completed/step-2a` / `.completed/step-2a.5` are missing (without re-writing artifacts), or collapse marker repair into one `mkdir -p` + conditional `: >` block covering all absent-marker cases.

- **risk-integration** `skills/design/SKILL.md:663-671` — `set -e` is scoped only to the inner `_simple_artifacts_ok != true` artifact-write block; when artifacts already exist, the unconditional `.completed/step-2a` / `.completed/step-2a.5` writes at lines 669–671 run without errexit and the fence has no top-level `set -euo pipefail`. A silent `mkdir` or redirection failure on that idempotent path would not halt the subshell, so the orchestrator can continue while one or both completion markers are missing even though Step 2a.2 prose assumes the full marker pair exists. **Suggested fix:** Wrap the entire SIMPLE branch (after conflict checks) in `set -e`, or add explicit `|| exit 1` on every `mkdir` / `: >` marker write so fail-fast applies equally on fresh-write and verify-only paths.

- **risk-integration** `skills/design/SKILL.md:649,813` — Both the Step 2a entry and Step 2a.5 repair fences invoke `read-design-classification.sh` with `2>/dev/null`, which suppresses the script’s stderr warning when it defaults unreadable/invalid `run-params.json` to `HARD`. On a SIMPLE-tier session with a transiently bad params file, the entry fence skips sentinel/marker writes and the flow can fall into the HARD sketch path without an operator-visible tier downgrade signal—exactly when the folded entry fence is now the sole SIMPLE write site. **Suggested fix:** Drop `2>/dev/null` on those calls (let warnings reach execution-issues/terminal), or fail closed with `exit 1` when classification cannot be resolved to the tier already recorded in restored `run-params.json`.

### Out-of-Scope Observations

- `skills/design/scripts/test-design-pause-resume.sh:486-503` — The Step 3b FINALIZE-failure fixture asserts non-zero exit and the repair warning but does not assert that `.completed/step-3b` remains absent when FINALIZE fails (FM6 ordering). The harness uses a tmpdir that already has `step-3b` from `complete_design_steps`, so it cannot catch a regression that writes `step-3b` before checking `_finalize_rc`.

- `skills/design/scripts/design-driver.sh:141-143,178` — Pre-existing behavior: when `.completed/finalize` already exists, `ACTION=FINALIZE` returns exit 0 with `STEP_SKIPPED` without re-validating or recreating `rejected-findings.md` et al. The Step 3b boundary treats that as success and still writes `step-3b`; Step 4’s compatibility guard also skips FINALIZE when the finalize sentinel exists. This branch did not change `design-driver.sh`, but the earlier FINALIZE fold makes stale-sentinel exposure slightly more likely on re-entry at Step 3b.
