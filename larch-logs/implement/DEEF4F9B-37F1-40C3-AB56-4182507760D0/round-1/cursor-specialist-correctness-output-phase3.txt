### In-Scope Findings

1. **correctness** `scripts/test-design-structure.sh:226` — `IGNORECASE=1` inside the `awk` block of `assert_no_direct_step3b_step4_routes` is a gawk extension; macOS ships BSD awk, which silently treats it as a regular variable assignment and leaves pattern matching fully case-sensitive. The routing-verb arm `/(continue|proceed|auto-continue|route|jump|enter|go)/` is therefore case-sensitive on the macOS CI runner. A line like `"Continue to Step 3b then Step 4 via ..."` (capitalised C, no "completion boundary" text) would pass the guard unchallenged. The failing scenario: any of the six scanned surfaces gains a capitalised routing verb in a direct Step 3b→Step 4 chain — the harness silently misses it because `IGNORECASE` never fired. **Suggested fix:** replace `BEGIN { IGNORECASE=1 }` with a portable tolower approach — e.g. `{ line = tolower($0) }` and then test `line` against lower-cased patterns — or use `awk 'BEGIN{...}' "$tmp"` with gawk forced via `gawk` binary, but the portable rewrite is simpler and keeps macOS/Linux parity.

2. **code-quality** `scripts/test-design-structure.sh:233-234` — In `assert_no_direct_step3b_step4_routes`, when the `[[ -z "$bad" ]] || fail ...` line calls `fail` (which calls `exit 1`), the cleanup `rm -f "$tmp"` on the very next line is never reached. For the scoped variant (`scoped=true`), the temp file created by `mktemp` leaks every time an assertion fires. Not a functional correctness issue, but can accumulate stale files under `${TMPDIR:-/tmp}` across repeated CI runs. **Suggested fix:** register a `trap 'rm -f "$tmp"' EXIT` at the top of the function body so the file is cleaned on any exit path, or move the cleanup before the `fail` call.

3. **correctness** `scripts/test-design-structure.sh:156-163` — `assert_step2a_entry_simple_guard` checks that the SIMPLE guard line appears before the first artifact write (via line-number comparison), but does not check that `set -e` appears **after** the guard line (i.e. inside the `if` block). If `set -e` were moved to before the `if`, the harness would still pass while `set -e` would now be active for HARD runs, potentially aborting the fence on any non-zero exit in the shared entry code. The concrete risk is low because the current prelude commands are already guarded (`|| true`, `|| printf`), but the harness does not pin the invariant the plan requires ("run the guarded write block under `set -e`" = `set -e` must be inside the SIMPLE branch, not outside it). **Suggested fix:** add an ordering assertion `(( guard_line < set_e_line ))` analogous to the existing `guard_line < first_artifact_line` check.
