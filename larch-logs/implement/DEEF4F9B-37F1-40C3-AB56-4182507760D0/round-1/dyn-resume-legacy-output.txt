Reviewing legacy pause/resume compatibility paths in the branch diff and related source files.
### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:796-805` — The legacy SIMPLE Step 2a.5 compatibility guard only backfills `.completed/step-2a.5` and explicitly avoids touching sentinel artifacts (“do not re-write SIMPLE artifacts”). On `resume@2a.5`, the Step 2a entry fence does not run, so a restored snapshot with `.completed/step-2a` but missing `approach-synthesis.txt`, `contested-decisions.md`, or `dialectic-resolutions.md` (corrupt restore, manual marker edits, or incomplete tmpdir copy) proceeds to Step 2b with no repair path. Pre-PR sessions usually had sentinels from the old SIMPLE-branch fence, but the branch removes that second write site and makes resume depend solely on marker repair. **Suggested fix:** Extend the compatibility guard to idempotently create any missing SIMPLE sentinel files (same three writes as the entry fence) when classification is SIMPLE and `.completed/step-2a` exists, not only when `.completed/step-2a.5` is absent; keep completion-marker writes separate so marker-only repair remains cheap when artifacts are already present.

- **risk-integration** `skills/design/scripts/test-design-pause-resume.sh:144-152,242-251` — The new legacy fixtures validate pause save/load routing (`STEP=2a.5` / `STEP=4`) but never execute the Step 4 entry FINALIZE compatibility guard or assert `.completed/finalize` / `rejected-findings.md` creation. The legacy-finalize fixture is built from `make_design_tmpdir`, which supplies minimal `plan.txt` but no `diff-lines.txt`; a real resume@4 replay would hit `finalize-plan.sh`’s required-artifact check and hard-exit before Step 4 reads. CI therefore green-lights routing while leaving the primary legacy recovery path (FINALIZE at Step 4 entry) unverified. **Suggested fix:** Populate legacy fixtures with the artifacts `finalize-plan.sh` requires (`diff-lines.txt` at minimum), add a harness block that sources/runs the Step 4 entry fence (or invokes `design-driver.sh` with `ACTION=FINALIZE` when `.completed/finalize` is absent), and assert `FINALIZE_PLAN_STATUS=ok`, `.completed/finalize`, and empty-file creation for may-be-empty artifacts.

- **risk-integration** `skills/design/SKILL.md:801-805` — The Step 2a.5 compatibility guard gates marker repair on `read-design-classification.sh` returning exactly `SIMPLE`, but that helper defaults to `HARD` when `design_classification` is missing or invalid (`scripts/read-design-classification.sh:52-53`). A legacy snapshot can still carry `TIER=SIMPLE` in pause metadata while the guard skips `.completed/step-2a.5` repair; the session then advances via the SIMPLE skip prose with a missing Step 2a.5 sentinel, breaking registry-ordered pause/resume on the next pause. **Suggested fix:** In the compatibility guard, treat pause-restored tier as a fallback (e.g., read `TIER` from `$DESIGN_TMPDIR/pause-state.txt` or `run-params.json` when classification read returns HARD) before deciding whether to write `.completed/step-2a.5`, or fail closed with an operator-visible error when pause tier and classification disagree.

### Out-of-Scope Observations

That concentration is by design and matches the plan; harness text pins guard presence but not runtime resume ordering. Worth noting for future edits, not a defect in this branch.

Pre-existing structural ambiguity, not introduced by the compatibility guards themselves.
