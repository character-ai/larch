1. - **risk-integration** `scripts/test-design-structure.sh:226` — `BEGIN { IGNORECASE=1 }` in the new `assert_no_direct_step3b_step4_routes()` awk block is a GNU awk (gawk) extension. macOS ships BSD awk, which treats `IGNORECASE` as an ordinary user variable with no effect; all pattern matching remains case-sensitive. The routing-verb pattern `/(continue|proceed|auto-continue|route|jump|enter|go)/` would silently miss an uppercase or mixed-case variant (e.g. `Continue` or `PROCEED`) on developer machines running macOS, producing a false-green from a guard intended to be case-insensitive. Since the monitored docs currently use lowercase consistently the guard passes today, but provides weaker-than-intended protection against future edits. **Suggested fix:** replace `BEGIN { IGNORECASE=1 }` with a per-line `tolower()` call, e.g. `{ lower=tolower($0) }` and test `lower` instead of `$0` for the verb and arrow patterns; this is portable to both gawk and BSD awk.

2. - **correctness** `scripts/test-design-structure.sh:165,234` — `rm -f "$tmp"` in `assert_step2a_entry_simple_guard` (line 165) and the scoped-cleanup path in `assert_no_direct_step3b_step4_routes` (line 234) are only reached if no `fail()` call fires. Because `fail()` calls `exit 1`, any assertion failure orphans the temp file under `${TMPDIR:-/tmp}`. With `set -euo pipefail` active, even an unrelated non-zero exit before `rm -f` would leave orphan files. This is a nit for a short-lived CI harness, but repeated failures accumulate stale files. **Suggested fix:** use a `trap 'rm -f "$tmp"' EXIT` immediately after `tmp=$(mktemp ...)` in each function so cleanup fires on any exit.
