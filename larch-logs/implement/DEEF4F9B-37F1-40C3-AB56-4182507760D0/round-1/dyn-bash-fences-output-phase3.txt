### In-Scope Findings

- **correctness** `scripts/test-design-structure.sh:113-130` — `assert_no_direct_step3b_step4_routes` opens its awk script with `BEGIN { IGNORECASE=1 }`. `IGNORECASE` is a `gawk`-only extension; on macOS the system `/usr/bin/awk` is BSD awk, which treats `IGNORECASE` as an ordinary user variable and silently ignores it. As a result the final routing-verb pattern `/(continue|proceed|auto-continue|route|jump|enter|go)/ && /Step 3b/ && /Step 4/` is case-sensitive only. Any routing prose that uses a capitalized form — "Continue to Step 3b, then Step 4", "Proceed from Step 3b to Step 4" — passes the guard without triggering a failure. The arrow/comma/slash shorthand patterns above it don't need `IGNORECASE`, so those patterns still fire correctly; only the verb catch is broken. **Suggested fix:** Replace `BEGIN { IGNORECASE=1 }` with a separate lowercase-transformation step, or use `tolower()` on `$0` at the start of each rule: change the last clause to `{ line=tolower($0) } /step 3b completion boundary/ { next } line ~ /(continue|proceed|auto-continue|route|jump|enter|go)/ && line ~ /step 3b/ && line ~ /step 4/ { print; next }`. The fixed-literal shorthand patterns already match case-exactly and need no change.

- **correctness** `skills/design/SKILL.md` (Step 2a entry fence) — `set -e` is activated inside the `if [ "$_design_classification" = SIMPLE ]; then` body rather than at the top of the fence. In bash, `set -e` takes effect globally once executed, not just within the enclosing block. On a SIMPLE run the flag is set and persists beyond `fi`; if Claude Code's Bash tool re-uses the same shell session across fence invocations the next fence inherits `errexit`, potentially causing unrelated commands (like a `|| true`-less timing call) to abort unexpectedly. On a HARD run the flag is never set, which is correct. The fail-fast intent (no completion-marker writes after a failed artifact write) is sound, but the scoping is fragile. **Suggested fix:** Move `set -e` to the top of the fence (before the `if` block) and add explicit `set +e` at the end, or use an explicit `if ! { printf ...; printf ...; : >; }` failure block inside the SIMPLE guard so `set -e` never escapes the intended scope.

### Out-of-Scope Observations

- **correctness** `scripts/test-design-structure.sh` (`assert_step2a_entry_simple_guard`) — temp file created with `mktemp` is only removed at the end of the function; if any `fail` call fires first, `exit 1` is called and the temp file is leaked. This is consistent with the pre-existing harness pattern but will accumulate stale files in `/tmp` on repeated test failures.
