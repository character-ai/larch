### In-Scope Findings

1. **Latent** `correctness` `scripts/test-design-structure.sh:141` — `IGNORECASE=1` is a gawk-only extension; the macOS system `awk` (BSD nawk 20200816, confirmed above) silently ignores it, so `/(continue|proceed|auto-continue|route|jump|enter|go)/` in `assert_no_direct_step3b_step4_routes` matches only lowercase on this platform. The plan explicitly requires case-insensitive matching of routing verbs. A future commit that adds routing prose with a capitalized verb (e.g., "Proceed to Step 3b → Step 4") would pass on macOS but fail in gawk-based CI, making the guard unreliable as a local development check. **Suggested fix:** replace `BEGIN { IGNORECASE=1 }` with a `tolower`-based pattern: `tolower($0) ~ /(continue|proceed|auto-continue|route|jump|enter|go)/ && /Step 3b/ && /Step 4/` and likewise lower-case the `/Step 3b completion boundary/` guard line. This is POSIX portable and produces consistent behaviour across awk implementations.
