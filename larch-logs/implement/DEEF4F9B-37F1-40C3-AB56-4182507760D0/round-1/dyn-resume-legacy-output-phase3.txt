### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:801` — The resume compatibility fence that writes `.completed/step-2a.5` for old SIMPLE paused sessions (where `step-2a` exists but `step-2a.5` is absent) is placed **after** the "If `design_classification == SIMPLE`, print … and proceed directly to Step 2b" prose. An LLM orchestrator following the skill sequentially would likely trigger the "proceed" jump on first reading that line, skipping the bash fence below it. This leaves `.completed/step-2a.5` unwritten for old paused SIMPLE sessions, causing the pause-save machinery to re-route to Step 2a.5 on every subsequent pause (since `step-2a` is present but `step-2a.5` never gets written). Fresh runs are unaffected; the risk is confined to sessions paused in the narrow window between the old pre-PR Step 2a completion and Step 2a.5 skip, but on those runs the loop never self-heals without the sentinel write. **Suggested fix:** Move the compatibility fence (or merge its condition into the first timing fence at Step 2a.5 entry) so it executes *before* the "proceed to Step 2b" routing instruction, matching the explicit ordering contract used in the Step 3b completion boundary (FINALIZE + `step-3b` write *before* Step 4). Alternatively, restructure the Step 2a.5 skip prose as: "If SIMPLE, first run the compatibility fence below, then print the skip breadcrumb and proceed to Step 2b," so the routing instruction is unambiguously deferred until after the fence.

- **code-quality** `scripts/test-design-structure.sh:assert_no_direct_step3b_step4_routes` — `BEGIN { IGNORECASE=1 }` in the embedded `awk` block is a GNU awk extension not available in macOS BSD awk (the system default on macOS). `IGNORECASE` is silently ignored on BSD awk, making the routing-verb regex `/(continue|proceed|auto-continue|route|jump|enter|go)/` case-sensitive instead of case-insensitive as intended by the plan. On macOS developer boxes the guard silently passes for lines containing `Continue`, `Proceed`, `Jump`, etc. at the start of a sentence — violating the BASH_AUTHORING.md portability requirement for shell scripts. CI (Linux/gawk) is unaffected, but the local lint path diverges. **Suggested fix:** Replace `BEGIN { IGNORECASE=1 }` with a preprocessing step (`tolower($0)` on the comparison field), or explicitly double each alternation (e.g., `/(continue|Continue|proceed|Proceed|route|Route|jump|Jump|enter|Enter|go|Go)/`), or pipe the file through `tr '[:upper:]' '[:lower:]'` before passing to `awk` so the routing guard is portable across all awk implementations used in this repo.
