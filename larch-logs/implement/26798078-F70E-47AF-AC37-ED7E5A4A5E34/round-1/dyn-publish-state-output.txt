### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:1471-1496` — Step 5c uses file-first parsing of `.design-publish-result.env` when `_publish_rc ≠ 3`, then merges stdout with `[[ -n "${!_key:-}" ]] || printf -v` so **file values never get overwritten by fresher stdout**. The fence requires `rm -f .design-publish-result.env` before each attempt, but the driver does not clear or rotate that file on entry. If a retry omits `rm` (common on prompt-side orchestration), a prior exit **1** can leave `PLAN_WRITE_OK=false` in the env file while the new run exits **0** with `PLAN_WRITE_OK=true` on stdout only — items 3–5 then treat the run as a plan-write failure (wrong warning, no `step-5c` sentinel, wrong Step 5d footer) even though `plan-block-write.sh` and publish may have succeeded. The same pattern can leave stale `VALIDATE_STATUS=ok` / `PLAN_WRITE_OK=true` on a subsequent exit **4**, polluting handler inputs if anything branches on parsed KVs before the `_publish_rc == 4` check. **Suggested fix:** Have `design-publish.sh` remove or truncate `.design-publish-result.env` at driver start (before validation), and/or change the orchestrator merge to **stdout-wins for the latest attempt** when `_publish_rc ∈ {0,1,3,4}`; add a harness case: seed env with `PLAN_WRITE_OK=false`, run successful publish without `rm`, assert parsed `PLAN_WRITE_OK=true`.

- **risk-integration** `skills/design/SKILL.md:1513-1539` — Step **5d** gates the machine footer on `PLAN_WRITE_OK` but not explicitly on `latest _publish_rc ∈ {0,1,3}`. Items 3–5 are rc-gated; 5d is reachable only after them in the happy path, but the global anti-halt rule pushes “continue to the next step” across all boundaries. An orchestrator that advances from the Step 5c Bash fence to 5d while `_publish_rc` is still **4** (skipping the shared handler block at `skills/design/SKILL.md:1503`) could emit the success footer (`PLAN_WRITE_OK=true` … `NEXT REQUIRED: continue`) and write `.completed/step-5d` without a settled publish, especially combined with stale env state above. **Suggested fix:** Add an explicit guard at the top of §5d: proceed only when `latest _publish_rc ∈ {0,1,3}`; pin that prose in `scripts/test-design-structure.sh`.

- **risk-integration** `skills/design/scripts/design-publish.sh:225-241` — `--skip-validate` (Step 5c **Accept / proceed-anyway**) skips composed-plan validation but still redacts and runs the full publish tail (`plan-block-write.sh`, rename when `PUBLISH_OK=true`, reentry marker).
