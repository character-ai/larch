### In-Scope Findings

- **correctness** `skills/design/scripts/design-publish.sh:238-240` — After the `defects-found` early exit, the only gate before redaction/publish is `_validate_rc -ne 0`, empty `VALIDATE_STATUS`, or `VALIDATE_STATUS == not-run`. A validator that exits **0** with any other status string (for example a reintroduced `skipped-quick`, a typo, or a partial contract) is treated as success and the publish tail runs. Today `validate-plan-commands.sh` only emits `ok` or `defects-found`, so this is latent, but the folded driver is the last mechanical gate before `plan-block-write.sh`. **Suggested fix:** After the `defects-found` branch, require an explicit allowlist before redaction, e.g. `VALIDATE_STATUS=ok`, or `VALIDATE_STATUS=skipped` when `--skip-validate`; otherwise `fail` with exit 2 (same as infra failure).

- **correctness** `skills/design/scripts/design-publish.sh:228-232` — Validator output is captured with `2>&1` into `_validate_out` and parsed line-by-line via `parse_kv_from_output`, which assigns any `KEY=value` line and uses **last match wins** for `VALIDATE_STATUS`. That is fine for the quiet `emit_kv` contract stream, but if stderr ever carries a spurious `VALIDATE_STATUS=ok` after a real `VALIDATE_STATUS=defects-found` on stdout (or vice versa), the final parsed status can be wrong and bypass exit 4. **Suggested fix:** Capture validator stdout and stderr separately (stdout-only into `_validate_out`, stderr to a failure log), or parse only lines from the known `emit_kv` contract and ignore `STEP_FAILED` / diagnostic lines; keep `defects-found` checked before the infra-failure branch.
