Reviewing upfront stash scope in the branch diff and tracing `evaluate_failure` in Bash and Python.
Checking tests for cap-exceeded stash behavior and Bash vs Python parity.
### In-Scope Findings

- **correctness** `python/ci_monitor.py:1014-1044` — `upfront_ready_stash` is assigned only inside `if transient_retries < config.CI_MONITOR_TRANSIENT_RERUN_MAX` (`elif upfront_logs.state == "ready"` at 1030–1031). When the transient rerun budget is already exhausted (`transient_retries >= 1`), the function still calls `collect_failed_logs` up front (1014) but never stashes a ready result; fix-loop attempt 1 always re-collects (1043–1044). That contradicts FINDING_2 / `scripts/ship-pr.md:129` (“when the blind rerun is skipped but upfront logs were ready, iteration 1 reuses that capture”) for the cap-exceeded skip case, and it can change behavior: if the first collect returns `ready` and the second returns `in_progress` or `error`, attempt 1 defers without dispatch even though actionable logs were already available. Bash avoids this by not fetching upfront at all when `TRANSIENT_RETRIES >= 1` (`scripts/ship-pr.sh:2505-2527`), so only one log read occurs on that path. **Suggested fix:** Decouple stash from the rerun cap—e.g. after the rerun block, set `upfront_ready_stash = upfront_logs` when `upfront_logs.state == "ready"` and no transient blind rerun was submitted (preserve FINDING_6: do not stash after a rerun attempt, including failed rerun); alternatively skip the upfront collect entirely when `transient_retries >= CI_MONITOR_TRANSIENT_RERUN_MAX` for Bash parity. Add a unit test with `transient_retries=1`, a single mocked ready log response, and assert only one `gh run view … --log-failed` (or that attempt 1 uses the stash).

### Out-of-Scope Observations

- Non-ready upfront logs are not stashed (`elif` requires `state == "ready"`); when upfront is not ready, attempt 1 correctly calls `collect_failed_logs` fresh—FINDING_2 behavior for in-progress/error upfront capture is sound.
- No Bash defect on the same axis: cap exhaustion skips the whole upfront block, so there is no “discard ready stash” path (only a possible doc ambiguity that reuse prose applies only when upfront was actually fetched).
- Tests such as `test_evaluate_failure_exhausted_routes_needs_user_input` use `transient_retries=1` with identical mock responses on every collect, so they would not catch the redundant re-fetch / ready-discard regression.
