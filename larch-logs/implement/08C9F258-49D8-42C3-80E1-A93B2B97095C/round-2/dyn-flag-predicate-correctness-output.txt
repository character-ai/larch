### In-Scope Findings

- **correctness** `python/ci_monitor.py:911-934` — `code_fix_attempted` is initialized from `bool(classified.fixable)` before the launcher waterfall, and the `waterfall.winning_tier is None` / `"all tiers failed"` return propagates that value as `code_fix_attempted_on_ready_log` without ever entering the per-job loop at `937-954`. That breaks the unified predicate (“substantive” only after ready logs **and** ready jobs **and** per-job machinery or verify-retry consumption): a fixable job list with 100% launcher failure is treated as substantive exhaustion even though no local/per-job fix ran. `test_evaluate_failure_per_job_exhausted_routes_needs_user_input` encodes this (`wrapper_rc=1`, `make py-lint` never reached) and diverges from Bash, which only sets `_code_fix_attempted_on_ready_log` after entering `run_per_job_local_fix_loop` (`scripts/ship-pr.sh:2606-2609`) before vendor dispatch. **Suggested fix:** Move `code_fix_attempted = True` to after a winning tier and entry into the `for job in classified.fixable` loop (or reorder to run per-job local fixes before the vendor waterfall, matching Bash); return `code_fix_attempted_on_ready_log=False` on `"all tiers failed"` when only launchers were attempted; update the per-job-exhausted test to require actual per-job execution (or launcher `verify-failed` / verification-retry) before expecting `fix-exhausted`.

If persisted state still has `CI_FIX_REBASE_PENDING=true` when `run_evaluate_failure` runs again (new CI failure, ship-pr restart, or prior exhaustion), the next call can set the substantive flag and route to autonomous `ci-fix-exhausted` without ready logs/jobs or fix machinery in the current evaluation—violating the same-attempt predicate the scout checklist describes. **Suggested fix:** Clear `CI_FIX_REBASE_PENDING` at the start of `run_evaluate_failure` (or on all terminal exhaustion paths), and only set `_code_fix_attempted_on_ready_log` in the pending branch if it was already true earlier in the same invocation or after a fresh ready-log/ready-job fetch confirms readiness.
