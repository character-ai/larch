### In-Scope Findings

1. **`Important` · `security` · [`scripts/redact-tmpdir-paths.sh:20-21`](scripts/redact-tmpdir-paths.sh)** — Operator-repo path redaction was tightened from `[^/"[:space:]]+` segments to `[[:alnum:]_.-]+` per path component. **Problem:** Any username or repo directory segment that contains characters outside that class (for example `+` as in `my+repo`, or other punctuation the old pattern treated as part of a segment) no longer matches the full segment. **Scenario:** Input like `<OPERATOR_REPO_PATH>/repo/file.txt` can match only up to `foo`, treat `+` as the punctuation capture, and emit something like `…<OPERATOR_REPO_PATH>+bar/repo/file.txt`, which both **fails to redact the tail** and **corrupts the line** for downstream consumers. **Suggested fix:** Restore segment expressiveness for the operator-repo expressions (or add a second, stricter pass only where safe), and add regression cases for `+` and other common POSIX filename bytes that must not leak.

2. **`Latent` · `correctness` · [`scripts/ship-pr.sh:1238-1241`](scripts/ship-pr.sh)** — The regression guard calls `semver_lt "$new_version" "$_origin_ver"` only after validating `_origin_ver` with a strict semver regex, but **`new_version` is not validated the same way** before numeric `[[ … -lt … ]]` comparisons inside `semver_lt`. **Scenario:** A malformed or surprising `NEW_VERSION` string from `classify-bump.sh` (empty field, non-numeric token, leading-zero octal edge cases) can yield **silent wrong ordering** or brittle failures under `set -e`. **Suggested fix:** Require the same `^[0-9]+\.[0-9]+\.[0-9]+$` guard on `new_version` before calling `semver_lt`, or fold validation into `semver_lt` and fail closed.

3. **`Latent` · `architecture` · [`scripts/ship-pr.sh:385-395`](scripts/ship-pr.sh) vs [`.claude/skills/bump-version/scripts/apply-bump.sh:42-50`](.claude/skills/bump-version/scripts/apply-bump.sh)** — This branch introduces a second copy of `semver_lt` in `ship-pr.sh` while `apply-bump.sh` already defines an identical helper. **Scenario:** A future semver rule change updates one copy and not the other, so **rebase-rebump correction disagrees with apply-bump’s guard** in subtle edge cases. **Suggested fix:** Source a single shared implementation (for example a tiny `scripts/lib-semver.sh`) or call the bump-version helper in a controlled way so one definition owns the ordering contract.

4. **`Nit` · `code-quality` · [`scripts/larch-log.sh:430-432`](scripts/larch-log.sh)** — The new comment attributes the hardening to **`LARCH_LOG_REPO_ROOT` and `REPO_ROOT` diverging through symlink resolution**, but in this script both roots are populated from the same `git -C "$PWD" rev-parse --show-toplevel` pattern at load, so they are ordinarily **identical strings**; the practical hazard is safer to describe as **path-prefix / pathspec construction** (and future refactors), not two independently resolved roots. **Suggested fix:** Rephrase the comment to match the actual invariant and the failure mode you are preventing.
