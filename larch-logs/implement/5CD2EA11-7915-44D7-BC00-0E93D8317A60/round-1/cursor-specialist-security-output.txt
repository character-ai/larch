That overstates the contract: post-merge / recovery flows can set other values in the tmpdir manifest (for example `status=partial` in [`scripts/ship-pr.sh:1480`](scripts/ship-pr.sh) per `run_postmerge_phase`), and a later `larch-log.sh commit` could theoretically persist a non–`in-progress` value if the log root still held that manifest when flushed. **Concrete impact:** Readers treat committed `status` as a definitive lifecycle signal and misjudge recovery or partial runs, or wrongly dismiss `partial` / other values as impossible. **Suggested fix:** Replace “always” with a precise rule (for example: normal flush commits occur before `status=done`, so `done` is not what appears in git; list allowed committed values or point to `scripts/larch-log.md` for the exact state machine).
