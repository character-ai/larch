### In-Scope Findings

- **architecture** `.claude/skills/bump-version/scripts/classify-bump.md:5-12` — The contract documents `--base <ref>` for `/release`, but the implementation also accepts `--head <ref>` (used by `release-prepare.sh` as `--head origin/main` to classify `BASELINE_TAG..origin/main` instead of `BASE..HEAD`). `release-prepare.md` documents the pair; `classify-bump.md` and `-h|--help` do not. Callers outside `/release` cannot rely on a documented, stable `--head` surface. **Suggested fix:** Add an `## Optional --head <ref>` section to `classify-bump.md` (resolve via `git rev-parse`, set diff/compare ref, default `HEAD`; required companion to `--base` when the bump window must be anchored on `origin/main`), update the script header comment and help string to `Usage: classify-bump.sh [--base <ref>] [--head <ref>]`, and add a `test-classify-bump.sh` case that passes `--head` explicitly.

- **architecture** `.claude/skills/release/scripts/release-finish.md:1-64` — `release-finish.sh` exposes three harness-only env overrides (`LARCH_RELEASE_FINISH_PROMOTE_SCRIPT`, `LARCH_RELEASE_FINISH_ORIGIN_REPO`, `LARCH_RELEASE_FINISH_AT_VERSION` at lines 8 and 110–151) used by `test-release-finish.sh`, but the sibling contract does not mention them. That leaves the script’s real dependency-injection and version-check bypass paths undocumented for anyone extending the harness or auditing safety boundaries. **Suggested fix:** Add a short “Test-only environment overrides” subsection listing each variable, its effect, and that production `/release` must not set them (version bypass skips the `TARGET_OID` `plugin.json` read).

- **architecture** `.claude/skills/bump-version/scripts/classify-bump.sh:68-71,94-99,212` — With `--head origin/main`, the public-surface diff is `BASE..HEAD_COMPARE`, but `CURRENT_VERSION` / `NEW_VERSION` arithmetic always come from the **working-tree** `$PWD/.claude-plugin/plugin.json`, not from `origin/main`. `release-prepare.md` says “at classify time” without stating that invariant. Under SKILL’s `--dry-run` dirty-tree carve-out, or if prepare is invoked off `main`, preview bump math can disagree with the `origin/main` diff. **Suggested fix:** Document in `classify-bump.md` and `release-prepare.md` that `/release` depends on a clean checkout on `main` (or teach `classify-bump.sh` to read `.version` from `HEAD_COMPARE` when `--head` is set, and optionally compare it to the worktree in prepare).

- **architecture** `.claude/skills/release/scripts/release-prepare.sh:15-22` vs `.claude/skills/release/scripts/release-finish.sh:143-217` — Machine-readable failures use different channels: `release-prepare.sh` emits `ERROR=<token>` on **stdout** (see `emit_error`), while `release-finish.sh` emits `ERROR=merge-commit-missing` and other tokens on **stderr** only. `SKILL.md` Step 2 tells the orchestrator to parse prepare stdout; Step 6 does not document stderr parsing for finish. **Suggested fix:** Normalize (prefer stdout `ERROR=` KV for both scripts, per prepare) or document the split in `release-finish.md` and `SKILL.md` Step 6 so operators and automation parse the right stream.

- **architecture** `.claude/skills/release/SKILL.md:33-36` vs `.claude/skills/release/scripts/release-prepare.sh:1-252` — “Must be on `main`” and “working tree clean” are enforced only in skill prose, not in `release-prepare.sh` (no `git symbolic-ref`, no `git status --porcelain`). Prepare only checks that the `main` **ref** matches `origin/main`, not that **HEAD** is `main`. A direct script invocation from another branch can still get PR metadata and a bump proposal from `origin/main` while reading `plugin.json` from the current branch. **Suggested fix:** Either add mechanical guards to `release-prepare.sh` (and document them in `release-prepare.md`) or narrow SKILL language to “orchestrator MUST enforce before calling prepare” and treat script-only invocation as unsupported.

- **architecture** `.claude/skills/release/SKILL.md:48` vs `.claude/skills/release/scripts/release-prepare.md:47-50` — Step 2 lists a subset of prepare `ERROR=` tokens; the contract also defines `release-cut-in-progress`, `release-already-cut`, `origin-repo-mismatch`, `classify-bump-failed`, and `LATEST_COUNT`, which the orchestrator is not steered to parse. **Suggested fix:** Align `SKILL.md` Step 2 with the full error table in `release-prepare.md` (or link to the contract as authoritative) so failure routing is consistent across prompt and scripts.
