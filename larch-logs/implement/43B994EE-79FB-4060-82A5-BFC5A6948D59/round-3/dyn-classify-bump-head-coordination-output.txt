Reviewing classify-bump `--base`/`--head` coordination and release-prepare integration.
### In-Scope Findings

- **architecture** `.claude/skills/bump-version/scripts/classify-bump.sh:68-99,115-122,189` — `--head` only retargets the public-surface diff (`git diff "$BASE" "$HEAD_COMPARE"`); `CURRENT_VERSION` / `NEW_VERSION` still come from the worktree `$PWD/.claude-plugin/plugin.json`. With `--base`, idempotency is correctly skipped (`SKIP_IDEMPOTENCY=true` at lines 79 and 170–185), so `BUMP_TYPE=NONE` cannot be emitted on the `/release` path, but version arithmetic can still disagree with the commit being classified when the checkout is not exactly `origin/main` (e.g. on a `release/v*` branch while `main^{commit}` == `origin/main^{commit}`, or a dirty / dry-run worktree). `release-prepare.sh` enforces `main` vs `origin/main` but not `HEAD` vs `origin/main` (lines 136–140), so the helper can diverge from the SKILL’s “on `main`, clean tree” contract if called directly. **Suggested fix:** When `--head` is set, read `.version` from `git show "$HEAD_COMPARE:.claude-plugin/plugin.json"` (fail closed on mismatch with the worktree file), and have `release-prepare.sh` also require `HEAD^{commit}` == `origin/main^{commit}` (or run prepare only from a documented `git checkout main` wrapper).

- **architecture** `.claude/skills/bump-version/scripts/classify-bump.sh:94-99,159-185` — `--head` without `--base` is an unsafe combination: idempotency still walks the local `HEAD` chain (`IDEMPOTENCY_REF` starting at `HEAD`, lines 159–169) and can return `BUMP_TYPE=NONE` before the `--head`-scoped diff runs, even though the diff range is `BASE..HEAD_COMPARE`. `/release` always passes both flags (`.claude/skills/release/scripts/release-prepare.sh:227`), but the script’s CLI presents the axes as independent. **Suggested fix:** Document that `--head` requires `--base` for aggregate release use, or auto-set `SKIP_IDEMPOTENCY=true` whenever `--head` is set (and add a harness case for `--head` alone vs `--base`+`--head`).

- **architecture** `.claude/skills/bump-version/scripts/classify-bump.sh:115-122` — The reasoning log records only the base commit; it never records `HEAD_COMPARE` / `--head`, so release debugging can imply classification used local `HEAD` when it did not. This is observability for the new head/base coordination, not a functional bug on the guarded `/release` happy path. **Suggested fix:** Add a “Compare commit” line using `HEAD_COMPARE` (short OID + subject) when `--head` is set.

### Out-of-Scope Observations

- **architecture** `.claude/skills/release/scripts/release-prepare.sh:234-236` — The `awk -F= … substr($0,index($0,"=")+1)` KV parser correctly preserves values containing `=`; `REASONING_FILE` is not parsed here, so the scout’s `REASONING_FILE` concern does not apply to current callers.

- For the scoped `/release` invocation (`--base "$BASELINE_TAG" --head origin/main`), `SKIP_IDEMPOTENCY` and `HEAD_COMPARE` are functionally orthogonal for suppressing `BUMP_TYPE=NONE`; the idempotency walk on local `HEAD` (lines 159–169) is dead work once `--base` is set, not a correctness defect.

- No harness covers `classify-bump.sh --base … --head origin/main` together (`test-classify-bump.sh` Test 6 uses `--base` only; `test-release-prepare.sh` fakes `git` but delegates real `git diff` to the host repo), so head/base coordination regressions would mostly surface in live operator runs rather than offline tests.
