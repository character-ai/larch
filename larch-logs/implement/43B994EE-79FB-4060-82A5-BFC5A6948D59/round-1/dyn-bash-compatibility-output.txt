Reviewing the branch diff and bash scripts for Bash 3.2 compatibility and related code-quality issues.
Auditing shell scripts for Bash 3.2 issues, bare `grep`, and related patterns.
### In-Scope Findings

- **code-quality** `.claude/skills/release/SKILL.md:40-45` — Step 2’s bash fence assigns the script path to `PREPARE_OUT` and leaves `--repo`, `--bump`, and `--out-dir` as separate shell words, so the block never runs `release-prepare.sh` (the next token after the assignment is treated as a command name). An orchestrator following the skill verbatim will fail before prepare. **Suggested fix:** Use command substitution, e.g. `PREPARE_OUT=$("$PWD/.claude/skills/release/scripts/release-prepare.sh" --repo "$REPO" ${BUMP_FLAG:+--bump "$BUMP_OVERRIDE"} --out-dir "$(mktemp -d)")`, and parse KV lines from that capture.

- **code-quality** `.claude/skills/release/scripts/release-prepare.sh:172-176` — The `--bump` override path uses `IFS='.' read` plus bare `$((maj + 1))` / `$((min + 1))` / `$((pat + 1))`. On macOS Bash 3.2, components with leading zeros (still allowed by `^[0-9]+\.[0-9]+\.[0-9]+$`, e.g. `1.08.0`) trigger invalid octal arithmetic and can abort under `set -e`. Elsewhere in this repo, decimal forcing uses the `10#` prefix (e.g. `scripts/lib-external-launcher-common.sh`). **Suggested fix:** After `read`, increment with `10#`-prefixed arithmetic, e.g. `NEW_VERSION="$((10#maj + 1)).0.0"`, or reuse the same helper pattern as `classify-bump.sh` after adding `10#` there too.

- **code-quality** `.claude/skills/release/scripts/release-set-version.sh:12-21` — `semver_lt` compares version components with `[[ $a_min -lt $b_min ]]` (and siblings) after `IFS='.' read`, which has the same Bash 3.2 leading-zero / octal parsing hazard as the prepare override block. **Suggested fix:** Compare with decimal-forced arithmetic, e.g. `(( 10#a_min < 10#b_min ))`, for all three components in both operands.

### Out-of-Scope Observations

- **Bash 3.2 portability otherwise looks sound on this branch:** no `declare -A`/`declare -n`, `${var^^}`, `&>>`, or `${var//…/$replacement}` in new/modified release scripts; `REPO_ARGS=()` + `"${REPO_ARGS[@]}"` in `scripts/promote-release.sh` matches existing helpers (`scripts/create-pr.sh`); harness `grep` usage is piped (`printf … | grep`), which is safe per `BASH_AUTHORING.md`.
- **`for pr in $pr_numbers` in `release-prepare.sh:134`** is unquoted word-splitting, but PR IDs are digits-only from `sed`, so globbing risk is negligible and the pattern matches other repo scripts.
- **Leading-zero semver arithmetic in `classify-bump.sh:292-296`** predates this branch’s logic; `release-prepare.sh` duplicates it for `--bump` override only. A shared `10#` bump helper would fix both.
- **Plan gap (not bash):** no offline harness for `release-finish.sh` yet; tag/Release idempotency is documented for manual verification only.
