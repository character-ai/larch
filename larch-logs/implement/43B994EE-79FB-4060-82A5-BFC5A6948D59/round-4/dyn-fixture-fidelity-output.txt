Reviewing fixture fidelity in the release test harnesses: reading the diff and tracing fake `git`/`gh` stubs against callers.
Verifying whether the fake-git stubs handle all caller invocations, including `HEAD` and `merge-base`.
### In-Scope Findings

- **correctness** `.claude/skills/release/scripts/test-release-prepare.sh:74-93` — The fake `git` `rev-parse` branch handles `main`, `origin/main`, and `GIT_BASELINE_TAG`, but not `HEAD`. `release-prepare.sh:138-144` always runs `git rev-parse "HEAD^{commit}"` and compares it to `origin/main` after the stale-main check, so any path that reaches that line hits `unexpected git: rev-parse HEAD^{commit}` (exit **9**) instead of emitting success KVs or domain errors like `ERROR=pr-metadata-incomplete`. Running the harness here yields **3/11** passes (only cases that exit before line 138: zero/multiple Latest, stale-local-main, fetch-fail); cases 1, 5, 6, and 8–11 fail with `rc=9` and empty stdout, so they do not actually exercise PR extraction, `--bump`, or open-PR guards. **Suggested fix:** In the fake `rev-parse` handler, treat `HEAD` (after stripping `^{commit}`) like `main`/`origin/main` when `GIT_MAIN_OID` equals `GIT_ORIGIN_MAIN_OID`, or add an explicit `GIT_HEAD_OID` env defaulting to `GIT_ORIGIN_MAIN_OID`, and document that prepare tests must set it when simulating a detached or mismatched checkout.

- **correctness** `.claude/skills/release/scripts/test-release-finish.sh:58-114` — The fake `git` stub has no `merge-base` case; `release-finish.sh:196-197,211,226-227` calls `git merge-base --is-ancestor "$TARGET_OID" origin/main`. Every call falls through to `exit 9`, but the subject wraps those calls in `||` with an OID-equality shortcut (`rev-parse` of `TARGET_OID^{commit}` vs `origin/main^{commit}`). All seven harness cases set the same `GIT_TARGET_OID` and `GIT_ORIGIN_MAIN_OID`, so tests pass without ever validating ancestor semantics (e.g. squash-merge commit strictly behind `origin/main` but still on history). **Suggested fix:** Add a `merge-base)` branch that returns **0** when `GIT_MERGE_BASE_IS_ANCESTOR=1` (or when `GIT_TARGET_OID` equals `GIT_ORIGIN_MAIN_OID`), returns **1** when `GIT_MERGE_BASE_IS_ANCESTOR=0`, and add at least one case where `TARGET_OID` ≠ `origin/main` tip but should still be accepted only via `--is-ancestor`.

- **correctness** `.claude/skills/release/scripts/test-release-prepare.sh:94-99` — The `log` handler matches only the exact two-argument form `"${GIT_BASELINE_TAG}..origin/main"` plus `--format=%s`, which matches `release-prepare.sh:167-168,175-176`. On any mismatch it `exec "$REAL_GIT"`, so a typo in `GIT_BASELINE_TAG` vs fixture `tag_name` silently switches to the real repo’s history and makes PR count / `release-already-cut` behavior machine-dependent. **Suggested fix:** On mismatch, `exit 1` with a clear “unexpected git log” message (or require an explicit `GIT_LOG_FORCE_REAL=1`) instead of delegating to `$REAL_GIT` inside offline tests.
