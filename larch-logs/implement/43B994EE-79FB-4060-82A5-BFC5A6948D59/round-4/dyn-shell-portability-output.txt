Reviewing the branch diff and shell scripts for Bash 3.2 portability and correctness.
### In-Scope Findings

- **correctness** `.claude/skills/release/scripts/release-prepare.sh:104-115` — Baseline selection uses `gh api /repos/.../releases` and filters on `.is_latest == true`, but the REST release objects returned by `gh api` do not include `is_latest` (verified live: that filter matches 0 releases, while `gh release list --json tagName,isLatest` finds exactly one Latest). Every real `/release` prepare will emit `ERROR=no-unique-latest-release` with `LATEST_COUNT=0`. **Suggested fix:** Resolve baseline the same way as `promote-latest-release.sh` / `scripts/promote-release.sh`: `gh release list --repo "$REPO" --json tagName,isLatest` (paginate/limit as needed), require exactly one `isLatest`, and bind `BASELINE_TAG` from that; drop the nonexistent `is_latest` field from fixtures/docs too.

- **correctness** `.claude/skills/release/scripts/release-prepare.sh:138-143` + `.claude/skills/release/scripts/test-release-prepare.sh:74-92` — Prepare now requires `HEAD^{commit}` to equal `origin/main^{commit}`, but the offline fake `git` only implements `rev-parse` for `main`, `origin/main`, and the baseline tag—not `HEAD`. With `PATH` pointing at the fake, `git rev-parse HEAD^{commit}` falls through to `unexpected git` (exit 9); locally `make test-release-prepare` fails 8/11 cases on the success paths. **Suggested fix:** Extend the fake `git` `rev-parse` branch to treat `HEAD` like `origin/main` (e.g. echo `"${GIT_HEAD_OID:-${GIT_ORIGIN_MAIN_OID}}"`).

- **correctness** `.claude/skills/release/scripts/test-release-set-version.sh:28-39` + `.claude/skills/release/scripts/release-set-version.sh:6-8` — The harness `cd`s into a temp tree with its own `plugin.json`, but `release-set-version.sh` always writes `$REPO_ROOT/.claude-plugin/plugin.json` derived from the script path (the real larch checkout). Assertions read the temp file while the subject mutates the live plugin tree; on a checkout above `1.1.0` the subject correctly refuses a downgrade and the harness dies under `set -e` with no summary line. **Suggested fix:** Either add a test-only `PLUGIN_JSON` override (or optional path argv) and point tests at the temp file, or stop using a temp repo and instead snapshot/restore the real `plugin.json` around each case.

- **correctness** `.claude/skills/release/scripts/release-prepare.sh:253-257` — `--bump` override recomputes `NEW_VERSION` with `10#` arithmetic but concatenates raw `ver_maj` / `ver_min` from `IFS='.' read` (no `10#` normalization). A `CURRENT_VERSION` with leading-zero components (allowed by `[0-9]+\.[0-9]+\.[0-9]+$`) can yield non-canonical output (e.g. `01.2.3` → `01.3.0`) or, on the classify-bump path, octal pitfalls where `10#` is not used. **Suggested fix:** After `read`, normalize with `10#` for all three components when building `NEW_VERSION`, matching the semver compare block at lines 162–166.
