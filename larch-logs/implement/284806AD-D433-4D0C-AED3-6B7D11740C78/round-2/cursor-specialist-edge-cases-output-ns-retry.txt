### In-Scope Findings

### FINDING_1: Non-executable append helper drops warnings with no fallback
- **severity:** **Nit**
- **focus_area:** risk-integration
- **location:** [skills/review/scripts/dispatch-panel.sh](skills/review/scripts/dispatch-panel.sh):267-269
- **issue:** `append_scout_parse_issue` returns early when `append-execution-issue.sh` is not executable (`[[ -x ... ]]`), so `SCOUT_STATUS=parse-failed` produces neither an execution-issues entry nor a `WARN=` line.
- **scenario_or_breakage:** Unusual installs, tight permissions, or broken file modes hide the new warning path entirely with no signal.
- **suggested_fix:** Treat non-executable like a failed append (emit `WARN=`) or drop the `-x` gate and rely on invoking the script via `bash` with an explicit path.

### FINDING_2: Stale cached `parse-failed` sidecar triggers a misleading execution warning
- **severity:** **Latent**
- **focus_area:** risk-integration
- **location:** [skills/review/scripts/dispatch-panel.sh](skills/review/scripts/dispatch-panel.sh):336-365 (reuse path) with harness [skills/review/scripts/test-dispatch-panel.sh](skills/review/scripts/test-dispatch-panel.sh):294-312 (`reuse-empty-with-status`)
- **issue:** `append_scout_parse_issue` keys only off `SCOUT_STATUS=parse-failed`, including the reuse branch that **does not reconcile** a valid empty manifest with a stale `parse-failed` status file and often leaves `SCOUT_FAIL_REASON` empty.
- **scenario_or_breakage:** A round directory can contain a valid `{"archetypes":[]}` manifest while `scout-roundN-status.env` still says `parse-failed` (the harness encodes this). After this change, the dispatcher appends a Warnings execution issue with `reason=unknown`, implying a fresh scout parse failure for that round even when no scout subprocess ran or failed in this invocation.
- **suggested_fix:** Before appending, detect reuse inconsistency (e.g. valid empty manifest + `parse-failed` without a fresh scout run) and either normalize status/`SCOUT_FAIL_REASON`, skip the append, or log a distinct reason such as `stale_scout_status_sidecar`.
