### In-Scope Findings

- **correctness** `Makefile:955-959` — The new multi-target rule merges `test-compose-pr-summary` and `test-compute-pr-line-counts` into one recipe that runs `bash scripts/test-compose-pr-summary test-compute-pr-line-counts.sh`. That path is wrong in two ways: it drops the `.sh` suffix on `test-compose-pr-summary`, and it treats `test-compute-pr-line-counts.sh` as an argument instead of a separate script. Only `scripts/test-compose-pr-summary.sh` exists, so `make test-compose-pr-summary` (and shard `test-harnesses-4`, which lists that target) will fail at runtime. A second standalone rule for `test-compute-pr-line-counts` at lines 958–959 overrides the broken recipe for that target only, so `make test-compute-pr-line-counts` works while `test-compose-pr-summary` stays broken. **Suggested fix:** Split into two independent rules, mirroring neighboring harness targets: `test-compose-pr-summary` → `bash scripts/harness-timer.sh $@ bash scripts/test-compose-pr-summary.sh`; `test-compute-pr-line-counts` → `bash scripts/harness-timer.sh $@ bash scripts/test-compute-pr-line-counts.sh`. Remove the erroneous combined rule.

- **correctness** `Makefile:81` — `test-harnesses-4` lists `test-compute-pr-line-counts` twice (`… test-compose-pr-summary test-compute-pr-line-counts test-compute-pr-line-counts test-ci-status …`). GNU Make deduplicates prerequisites, so this does not double-run the harness, but it is an accidental duplicate introduced by this branch and can confuse shard-balance maintenance and drift-detection reviews. **Suggested fix:** Keep a single `test-compute-pr-line-counts` entry on the `test-harnesses-4` line.

- **correctness** `scripts/render-run-summary.sh:216-219` — `lines_disp` uses OR (`-n` on any of the four flags) rather than the documented contract (“all four empty → N/A; else format”). If a caller passes only a subset of the four flags (e.g. `--code-added 10` only), the renderer emits a malformed bullet such as `code +10/-, larch-logs +/-` instead of `N/A`. `write-final-report.sh` gates on all four integers before forwarding flags, so the primary `/implement` path is safe, but the shared renderer contract is incorrect for partial input. **Suggested fix:** Require all four counters to be non-empty integers before building the formatted string; otherwise keep `lines_disp="N/A"`, matching `write-final-report.sh`’s `LINES_DATA_OK` logic and the sibling `.md` contract.
