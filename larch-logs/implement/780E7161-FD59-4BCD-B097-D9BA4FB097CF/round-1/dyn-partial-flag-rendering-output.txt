### In-Scope Findings

- **correctness** `scripts/render-run-summary.sh:216-218` — `lines_disp` uses OR logic (`-n "$CODE_ADDED" || …`) but always interpolates all four variables into the format string. A caller that passes only a subset of `--code-added` / `--code-deleted` / `--logs-added` / `--logs-deleted` gets a malformed bullet (e.g. only `--code-added 107` renders `- **Lines (PR diff)**: code +107/-, larch-logs +/-/`). `write-final-report.sh:127-147` gates on all four integers before forwarding flags, so the production path is safe today, but the shared renderer has no equivalent guard and `scripts/render-run-summary.md:77-81` documents “all four empty → N/A; otherwise format” without requiring all four to be present — so partial input is silently treated as valid. **Suggested fix:** Change the renderer condition to require all four non-empty integer values (mirror `LINES_DATA_OK` in `skills/implement/scripts/write-final-report.sh:127-147`), update `scripts/render-run-summary.md` to state all-or-nothing explicitly, and add a harness case in `scripts/test-render-run-summary.sh` that passes a partial flag set and expects `N/A`.

- **correctness** `Makefile:955-956` — The combined target `test-compose-pr-summary test-compute-pr-line-counts` runs `bash scripts/harness-timer.sh $@ bash scripts/test-compose-pr-summary test-compute-pr-line-counts.sh`, which omits the `.sh` suffix on `test-compose-pr-summary` and passes `test-compute-pr-line-counts.sh` as a stray argument. `make test-compose-pr-summary` (including via `test-harnesses-4` at `Makefile:81`) will fail even though a correct standalone recipe exists at `Makefile:958-959`. **Suggested fix:** Restore separate single-target recipes (`test-compose-pr-summary` → `scripts/test-compose-pr-summary.sh`; `test-compute-pr-line-counts` → `scripts/test-compute-pr-line-counts.sh`), delete the broken combined target, and remove the duplicate `test-compute-pr-line-counts` prerequisite on `Makefile:81`.
