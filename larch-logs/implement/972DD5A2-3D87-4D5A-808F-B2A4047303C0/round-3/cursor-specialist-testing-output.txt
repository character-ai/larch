### In-Scope Findings

1. **`risk-integration` — Important — [`scripts/test-harness-timer.sh`](scripts/test-harness-timer.sh):44-60**  
   The feature text and implementation plan call for regex acceptance on the timing token (`^0\.[4-6][0-9]s$` for `sleep 0.5`, `^[12]\.[0-9]{2}s$` for `sleep 2`). The harness only checks `^[0-9]+\.[0-9]{2}s$` plus wide numeric windows (`0.40`–`1.20` and `1.90`–`4.99`). A broken timer that reports e.g. `3.50s` after `sleep 2` still passes, so the suite does not enforce the stated contract and can miss major regressions the requirements were meant to catch. Tighten with explicit `grep -Eq` / `[[ =~ ]]` on those regexes (and/or narrow ranges) so failures align with the spec.

2. **`correctness` — Important — [`scripts/test-harness-timer.md`](scripts/test-harness-timer.md):8 vs [`scripts/test-harness-timer.sh`](scripts/test-harness-timer.sh):47-50**  
   The sibling doc says `sleep 0.5` is asserted within `0.40s-0.79s`, but the script uses `0.40s-1.20s`. Someone debugging a failure from the `.md` will misread whether the harness is wrong. Align the documented bounds with the script or change the script to match the documented (and plan-narrower) window.

3. **`correctness` — Nit — [`scripts/test-harness-timer.md`](scripts/test-harness-timer.md):6-10 vs [`scripts/test-harness-timer.sh`](scripts/test-harness-timer.sh):76-108**  
   The markdown lists three cases only; the script adds a fourth (backward-clock clamp via a `PATH`-shadowed `python3`). The stub doc should mention that test so the sibling contract matches what CI runs.

4. **`risk-integration` — Latent — [`scripts/test-harness-timer.sh`](scripts/test-harness-timer.sh):76-96 and [`scripts/harness-timer.sh`](scripts/harness-timer.sh):8-11**  
   The backward-clock mock only intercepts `python3` when `$1` is `-c` and `$2` exactly matches `import time; print(time.time())`. If `harness-timer.sh` rewrites those invocations (quoting, whitespace, or a helper), the stub stops simulating backward time and the test can pass without exercising the clamp. After edits to the timer’s Python snippets, revisit the stub’s match logic or assert the mock ran (e.g. counter file state).
