2. **Latent** (`risk-integration`) — [scripts/test-harness-timer.sh](scripts/test-harness-timer.sh):44-60 vs feature request — The issue text asked explicit regex gates (`^0\.[4-6][0-9]s$`, `^[12]\.[0-9]{2}s$`). The implementation uses wide numeric bands (`0.40`–`1.20`, `1.90`–`4.99`) plus a fixed-decimal format check. That improves CI flake tolerance but no longer pins the stated acceptance shape; some wrong-but-in-range timings could still pass. **Suggested fix:** Either document the relaxed bands as the canonical contract or add a second assertion that also matches the tighter regex when the environment allows (or split fast/slow CI profiles).

3. **Latent** (`correctness`) — [scripts/harness-timer.sh](scripts/harness-timer.sh):8-13 — If `python3` is absent or errors during any of the three `-c` probes, `start`/`end`/`elapsed` substitutions can be empty; `printf` can still emit a `LARCH_HARNESS_TIMING` line with a broken third column while `exit "$rc"` still mirrors the inner command. Downstream parsers may see a row that looks structurally present but carries garbage timing. **Suggested fix:** After each Python probe (or once before `printf`), validate non-empty numeric `elapsed` and bail with a non-zero exit and/or stderr distinct from the sentinel line.

4. **Nit** (`architecture`) — [scripts/test-harness-timer.md](scripts/test-harness-timer.md):6-10 vs [scripts/test-harness-timer.sh](scripts/test-harness-timer.sh):76-108 — The regression harness implements a fourth case (backward clock / `0.00s` clamp) that is not listed under “## Tests” in the sibling `.md`. **Suggested fix:** Add Test 4 to `scripts/test-harness-timer.md` so Makefile-only discoverability stays paired with accurate coverage description.

5. **Nit** (`correctness`) — [scripts/test-harness-timer.sh](scripts/test-harness-timer.sh):78-99 — The fake `python3` only intercepts an exact `-c` payload string; a trivial harness change (spacing, alternate quoting, or a different clock probe) silently falls through to the real interpreter, so the “backward clock” assertion may stop exercising the clamp without failing. **Suggested fix:** Document this coupling next to the stub or assert the stub ran (e.g. counter file reached expected count) before accepting pass.

6. **Nit** (`code-quality`) — [scripts/test-harness-timer.sh](scripts/test-harness-timer.sh):9-20 — The helper function is named `fail` while a counter variable is also named `fail`.
