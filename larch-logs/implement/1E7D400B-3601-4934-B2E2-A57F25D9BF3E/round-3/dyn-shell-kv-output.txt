### In-Scope Findings

- **code-quality** `skills/implement/scripts/test-stall-recovery-report.sh:663-672` — The new “unsafe step-value” fixture uses `STALL_STEP=8a<script>`, but the pre-change `safe_step_value` prefix glob (`8[[:alnum:]-]*`) already rejects that full string because `<` is outside `[[:alnum:]-]`, so this case passes on both old and new sanitizer logic. The branch therefore does not mechanically pin the tightened full-string matcher against a regression back to the old glob; an alnum-only suffix the old matcher accepted (e.g. `8aevil`) would fail only under the new regex. **Suggested fix:** Add a harness case with `STALL_STEP=8aevil` (or similar) asserting the `issue-input-file` title is `… at unknown` and that `8aevil` is absent from the heading line, alongside the existing `8a<script>` case.

- **correctness** `skills/implement/scripts/stall-recovery-report.sh:1130-1145` — On the dedup fallback path, when `ISSUE_1_DUPLICATE=true` and `ISSUE_1_DUPLICATE_OF_NUMBER` is set, the code unconditionally assigns `issue_url=$duplicate_url` even if `ISSUE_1_DUPLICATE_OF_URL` is empty while `ISSUE_1_URL` is present and valid. That yields `issue-url-missing` and drops a usable create URL from corrupt/partial stdout instead of falling back to `ISSUE_1_URL` when the duplicate-of URL is missing. `/issue`’s dedup contract normally omits create fields, so this is an edge case, but the precedence is stricter than the plan’s “fallback to duplicate-of when create fields absent” wording. **Suggested fix:** Only override `issue_url` when `issue_value_is_url "$duplicate_url"` succeeds; otherwise keep a valid `ISSUE_1_URL` if present, or fail closed if neither URL is valid.
