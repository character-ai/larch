### In-Scope Findings

1. **Important** `correctness` `scripts/check-reviewers.sh:210,236,267` — `larch_write_bool_stamp` is called without a `|| true` guard in three places (after `cursor_auth_preflight` short-circuit, after the Cursor probe loop, and after the Codex probe loop). `larch_write_bool_stamp` does `mktemp -p … || return 1`; under `set -euo pipefail`, a non-zero return propagates up and aborts `check-reviewers.sh` entirely — a `/tmp` full or permission failure turns a TTL-cache write (an optimization) into a hard session-setup error. **Suggested fix:** Add `|| true` at every call site: `larch_write_bool_stamp "$(larch_stamp_path_cursor)" "$CURSOR_PRESENT" || true` (same for the Codex call at line ~267).

2. **Latent** `architecture` `scripts/session-setup.sh:112-148` — The diff's comment block declares `CODEX_BINARY_FOUND, CURSOR_BINARY_FOUND` as recognized `--caller-env` keys, but the actual `case` statement (lines 135-146, which was not changed) has no arms for those keys: they fall through to `*)  ;;` and are silently dropped. In the passthrough branch (`CHECK_REVIEWERS=false`), `FINAL_CODEX_BINARY_FOUND=""` is hardcoded to empty and never forwarded to `write-session-env.sh`. Concrete failing scenario: a second `/implement` run that inherits a prior `session-env.sh` via `--caller-env` loses the binary-vs-probe distinction; downstream SKILL.md reads `CODEX_BINARY_FOUND` as absent/empty and shows "probe failed / timed out" instead of "binary not found", silently degrading the diagnostic signal. **Suggested fix:** Add `CODEX_BINARY_FOUND) CALLER_CODEX_BINARY_FOUND="$value" ;; CURSOR_BINARY_FOUND) CALLER_CURSOR_BINARY_FOUND="$value" ;;` to the caller-env parsing `case`, initialize the variables, and propagate them into `FINAL_CODEX_BINARY_FOUND` / `FINAL_CURSOR_BINARY_FOUND` in the passthrough branch.

3. **Latent** `correctness` `scripts/check-reviewers.sh:115-123,156-165` — In both `larch_run_one_cursor_probe` and `larch_run_one_codex_probe`, `probe_out` (and `probe_side`) are allocated via `mktemp` before `external_serial_lock_acquire`. If the lock function exits non-zero, `set -euo pipefail` propagates the error up before the `rm -f "$probe_out"` cleanup at the bottom of each function, leaking those temp files. The cursor probe also has `cursor_launcher_cleanup_private_config_dir` in the main script body that won't be reached if the function aborts abnormally. In long-lived CI environments or machines with constrained `/tmp`, repeated probe failures could accumulate uncleaned files. **Suggested fix:** Add a `trap 'rm -f "$probe_out" "$probe_side"' RETURN` immediately after the mktemp calls (Bash 3.2-compatible with local trap scoping via a helper, or just guard `external_serial_lock_acquire` with `|| { rm -f "$probe_out"; return 1; }`).

4. **Latent** `architecture` `docs/configuration-and-permissions.md:27,41` — Both the `LARCH_CURSOR_MODEL` and `LARCH_CODEX_MODEL` sections were updated to say the variable applies to "Step 0 `check-reviewers.sh` probes", but the actual probe code uses no model argv: the Cursor probe skips `cursor_launcher_load_model_args` and emits bare `cursor agent …` with no `--model`; the Codex probe uses `codex exec … -- "Respond with OK"` with no `-m`. `check-reviewers.md` (also updated in this PR) correctly documents "no model args". The `configuration-and-permissions.md` description is therefore incorrect and creates a false user expectation that `LARCH_CURSOR_MODEL` can reduce probe cost or route to a specific model. **Suggested fix:** Change both model-variable `When set:` bullet lines to replace "Step 0 `check-reviewers.sh` probes" with the literal set of callers where the model actually applies (reviews, sketches, voting, negotiations, and `--coder=cursor|codex` implement), matching the accurate language in `check-reviewers.md`.

5. **Nit** `correctness` `skills/implement/scripts/test-step2-dispatch.sh:1499` — The Test 3e assertion `[[ -z "$ERR" ]]` will silently break this test if any future diagnostic message is added to `step2-implement.sh`, the sourced cursor launcher libs, or the auth library under `LARCH_QUIET_DISABLE=1`. **Suggested fix:** Either document in a comment exactly what the zero-stderr invariant is pinning, or relax to `[[ "$ERR" != *"ERROR"* ]]` / `[[ "$ERR" != *"FATAL"* ]]` to tolerate informational stderr.
