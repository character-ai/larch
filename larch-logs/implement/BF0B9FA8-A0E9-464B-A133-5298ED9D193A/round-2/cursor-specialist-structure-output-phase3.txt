### In-Scope Findings

1. - **code-quality** `scripts/check-reviewers.sh:60-68` — `larch_stamp_path_cursor` and `larch_stamp_path_codex` are byte-identical functions that differ only in the literal `cursor`/`codex` in the stamp filename. Each is called exactly twice (lines 205/212/238 and 250/269), so the body duplication is four-fold if the naming scheme ever changes. **Suggested fix:** Replace both with a single `larch_stamp_path <tool>` function: `printf '%s' "${TMPDIR:-/tmp}/larch-${1}-present-${_u:-larch}.stamp"`.

2. - **code-quality** `scripts/check-reviewers.sh:127-139, 170-182` — The poll/timeout/wait/`probe_rc` block inside `larch_run_one_cursor_probe` and `larch_run_one_codex_probe` is verbatim identical (~13 lines). The real tool-specific asymmetry — Cursor uses a single merged output file; Codex redirects stdout to `/dev/null` and captures stderr in a sidecar — applies only to the spawn line and the auth-check call sites, not the poll loop. **Suggested fix:** Extract the poll loop into a `larch_poll_probe_pid <pid> <timeout>` helper that returns `probe_rc` via a `local -` trick or prints it to stdout; call it from both probe functions.

3. - **code-quality** `scripts/check-reviewers.sh:147, 189` — Both `larch_run_one_cursor_probe` and `larch_run_one_codex_probe` read the global `AUTH_ATTEMPT` variable to decide whether to return 2 (signal auth retry) without declaring it `local` or accepting it as a parameter. The dependency on the caller's loop counter is invisible from the function signatures. If either function is copy-adapted elsewhere, the implicit coupling will cause confusing behaviour. **Suggested fix:** Accept `AUTH_ATTEMPT` as a positional parameter (`local attempt="$1"`) and update callers accordingly, or document the global dependency with a comment at the function definition.

4. - **code-quality** `scripts/check-reviewers.sh:249` — The Codex stamp-hit variable is named `_CACHED_C` while the Cursor equivalent is `_CACHED`. The asymmetry makes the two parallel sections harder to scan side-by-side and creates a small inconsistency with the naming convention. **Suggested fix:** Use `_CODEX_CACHED` / `_CURSOR_CACHED` (or just reuse `_CACHED` in the Codex block — both are local to separate `else` branches and do not overlap).

5. - **correctness** `skills/implement/scripts/test-step2-dispatch.sh:1596` — Test 3e uses `! grep -Eiq 'error|fatal|failed' <<<"$ERR"` to assert a clean stderr. The pattern `failed` (case-insensitive) matches benign library log messages such as "token lookup failed, retrying" or "service token resolution failed, proceeding without auth" that Cursor's launcher infrastructure may emit normally. A match silently fails the test in any environment where those messages appear. The impact is a flaky, hard-to-diagnose CI failure. **Suggested fix:** Either assert only that the expected output keys are present on stdout (which the test already does), or narrow the negative grep to a specific unambiguous error string such as `'FATAL\|unhandled exception'` rather than the generic `'failed'`.

6. - **code-quality** `scripts/test-check-reviewers.sh:228-236` (Test t12) — The Codex `--skip-codex-probe` test asserts only `CODEX_PRESENT=false` but does not assert `CODEX_BINARY_FOUND=true`. The corresponding Cursor-side skip test (t0c, lines ~913-917) correctly pins both `CODEX_PRESENT=false` and `CODEX_BINARY_FOUND=true`, documenting the invariant that skip flags do not suppress the `command -v` result. The Codex-skip path in t12 is a partial gap for this same contract. **Suggested fix:** Add `assert_line "skip codex bin found" "CODEX_BINARY_FOUND=true" "$out"` to test t12 (SB12 has a `codex` stub on PATH, so `CODEX_BINARY_FOUND=true` is deterministic).
