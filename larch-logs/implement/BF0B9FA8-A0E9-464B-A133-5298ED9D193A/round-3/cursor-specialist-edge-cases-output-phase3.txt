### In-Scope Findings

1. **Important** `correctness` `scripts/check-reviewers.sh:121` — `larch_write_bool_stamp` uses `mktemp -p "${TMPDIR:-/tmp}" "larch-probe-stamp.XXXXXX"`. The `-p DIR` flag is GNU coreutils-specific; macOS/BSD `mktemp` does not support it and returns a non-zero exit. The function is called with `|| true`, so the failure is silent — on macOS (which is this project's primary development platform), the stamp is never written and TTL caching is permanently silently disabled. Every session-setup re-probes from scratch, defeating the feature entirely. Confirmed by grepping the repo: every other `mktemp` call uses the portable template-path form `"${TMPDIR:-/tmp}/name.XXXXXX"`. **Suggested fix:** Change line 121 to `stamp_tmp=$(mktemp "${TMPDIR:-/tmp}/larch-probe-stamp.XXXXXX") || return 1`, matching the same portable pattern used by `larch_run_one_cursor_probe` (line 149) and `larch_run_one_codex_probe` (line 179).

2. **Latent** `correctness` `scripts/check-reviewers.sh:226-250` — `cursor_launcher_cleanup_private_config_dir` (line 250) is called unconditionally regardless of whether the setup block succeeded. The compound condition `if ! { cursor_preread_service_token && cursor_auth_argv && cursor_launcher_setup_private_config_dir }` short-circuits on the first failure, so if `cursor_preread_service_token` or `cursor_auth_argv` fails, `cursor_launcher_setup_private_config_dir` is never called. Yet cleanup still runs against potentially uninitialized global state (e.g., a `CURSOR_PRIVATE_CONFIG_DIR` that was never set). If the cleanup function is not idempotent for this partially-initialized state — for example, if it resolves a default or fallback path and removes a wrong directory — it could corrupt the user's Cursor config. **Suggested fix:** Gate the cleanup call on whether setup completed: track a boolean flag `_setup_ok=false` before the compound `if`, set it to `true` in the `else` branch (after setup succeeded), and only call `cursor_launcher_cleanup_private_config_dir` when `_setup_ok=true`.

3. **Latent** `risk-integration` `scripts/check-reviewers.sh:38-71` — The EXIT trap (`larch_probe_exit_cleanup`, line 71) is established *after* the two libs are sourced (lines 38–41), which is correct for source-time traps. However, the lib functions called later during the probe — specifically `cursor_auth_preflight` (line 220), `cursor_preread_service_token` (line 227), and `cursor_launcher_setup_private_config_dir` (line 229) — may themselves set EXIT traps internally (a common idiom in auth/config-dir helpers for local cleanup). Any such internal trap would replace `larch_probe_exit_cleanup`, leaving `PROBE_TMPFILES` and `PROBE_PIDS` uncleared on an unexpected exit mid-probe. If a probe PID is still running when the trap fires, it survives as an orphan. **Suggested fix:** Either verify (and document) that the three lib functions never set EXIT traps, or save/restore the trap around their calls with `_prev_trap=$(trap -p EXIT)` and `eval "$_prev_trap"` after each call.

4. **Nit** `code-quality` `scripts/check-reviewers.sh:154` — The `# shellcheck disable=SC2086` comment on line 154 is targeted at an array conditional-expansion line (`${CURSOR_AUTH_ARGS[@]+"${CURSOR_AUTH_ARGS[@]}"}`). SC2086 is the *scalar* unquoted-variable warning; the correct suppression here would be SC2068 (double-quoting array expansion) or no disable at all (the inner expansion is already properly quoted). The mismatch silently suppresses a different warning than the one that might fire, and will mislead future shellcheck runs. **Suggested fix:** Remove the `# shellcheck disable=SC2086` or replace it with `# shellcheck disable=SC2068` (if shellcheck still flags the outer conditional form).
