### In-Scope Findings

- **risk-integration** `scripts/session-setup.sh:414-439` — The passthrough branch (`CHECK_REVIEWERS=false`) emits `CODEX_BINARY_FOUND` / `CURSOR_BINARY_FOUND` only when `CALLER_CODEX_BINARY_FOUND` / `CALLER_CURSOR_BINARY_FOUND` are non-empty (lines 424-429). When a caller-env supplies `CODEX_PRESENT=true` without `CODEX_BINARY_FOUND` (pre-feature session-env, manually constructed caller-env, or any sub-skill invocation that pre-dates this branch), `FINAL_CODEX_BINARY_FOUND=""` (line 438), the `--codex-binary-found` flag is omitted from `WSE_ARGS`, and the key is absent from the written session-env. Downstream skills using `external-reviewers.md`'s new two-tier logic (`codex_available=true` only when **both** `CODEX_BINARY_FOUND=true` and `CODEX_PRESENT=true`) will read an absent key as non-`true`, derive `codex_available=false`, and fall back to Claude unnecessarily — even when Codex was already verified healthy. For the normal `/implement`-Step-0 → sub-skill flow this is safe because Step 0 always runs `--check-reviewers` and therefore always writes both keys. However, any sub-skill invoked with a `--session-env` file from a session that predates this branch, or any CI harness that manually writes a minimal caller-env with only `CODEX_PRESENT=true`, will trigger the silent misclassification. **Suggested fix:** In the passthrough branch, when `CALLER_CODEX_BINARY_FOUND` is empty but `CALLER_CODEX_PRESENT` is non-empty, synthesize `FINAL_CODEX_BINARY_FOUND="$CALLER_CODEX_PRESENT"` (the binary must have been present for the old probe to have written `PRESENT=true`; a `false` carries through correctly). Symmetric fix for `CURSOR_BINARY_FOUND`. Concretely, replace lines 438-439 with: `FINAL_CODEX_BINARY_FOUND="${CALLER_CODEX_BINARY_FOUND:-${CALLER_CODEX_PRESENT:-}}"` and `FINAL_CURSOR_BINARY_FOUND="${CALLER_CURSOR_BINARY_FOUND:-${CALLER_CURSOR_PRESENT:-}}"`.

- **risk-integration** `skills/implement/SKILL.md:1077-1081` — The Option A bail bullets (the four new explicit-coder-unavailable cases under `When coder_explicit=true`) each test for `cursor_available=false AND CURSOR_BINARY_FOUND=false` or `cursor_available=false AND CURSOR_BINARY_FOUND=true`. If `CURSOR_BINARY_FOUND` is absent from session-env (the same passthrough-path gap above), `read-session-env-key.sh --default ""` returns `""`. An absent key is not `false` and not `true`, so neither bullet matches. The SKILL.md has no explicit `absent` arm, leaving the orchestrator with no instruction for that case. In practice the "both must be true" guidance still sets `cursor_available=false`, but neither bail bullet is selected, creating an instruction gap that could lead to an explicit coder proceeding despite being unchecked. **Suggested fix:** Add a fifth bullet (or generalise the `CURSOR_BINARY_FOUND=false` bullet) to cover the absent/empty case: "If the explicit coder is `cursor` AND `cursor_available=false` AND `CURSOR_BINARY_FOUND` is absent or empty, treat it as `CURSOR_BINARY_FOUND=false` and print the binary-not-found message." Symmetric for codex.
