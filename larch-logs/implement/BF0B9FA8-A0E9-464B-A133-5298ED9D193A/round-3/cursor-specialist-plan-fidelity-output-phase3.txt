2. - **risk-integration** `scripts/check-reviewers.sh:227-235` — `PROBE_PIDS` accumulates every background PID without removing entries after `larch_poll_probe_pid` calls `wait "$probe_pid"`. The exit trap then calls `kill` on those reaped PIDs; if the OS reuses a PID between `wait` and the EXIT trap, the signal lands on an unrelated process. The plan specifies no cleanup semantics for completed probe PIDs, making this a latent risk introduced by the new cleanup pattern. **Suggested fix:** After `larch_poll_probe_pid` returns in each `larch_run_one_*_probe` function, remove the completed PID from `PROBE_PIDS` (or replace the kill-all loop with a guard that checks whether the process is still a child of this shell via `kill -0` before the kill).
