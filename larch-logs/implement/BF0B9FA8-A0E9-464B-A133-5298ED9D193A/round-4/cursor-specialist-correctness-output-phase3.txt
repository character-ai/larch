### In-Scope Findings

1. **correctness** `scripts/test-check-reviewers.sh:193,210,233,250` — Codex matrix tests t6–t12 do not set `LARCH_LIB_CURSOR_AUTH_TEST_MODE=1 LIB_CURSOR_AUTH_TEST_UNAME=Linux`. Each of these tests puts a cursor stub that exits 127 on `$PATH`, so `CURSOR_BINARY_FOUND=true` and `check-reviewers.sh` enters the full Cursor probe path — including `cursor_auth_preflight` — before the stub's exit-127 ends the attempt. Without the test-mode env vars, `cursor_auth_preflight` on macOS attempts Darwin Keychain access; on headless macOS CI this causes a prompt or immediate failure, making the Codex matrix tests non-deterministic. The plan explicitly states "Tests set `LARCH_LIB_CURSOR_AUTH_TEST_MODE=1 LIB_CURSOR_AUTH_TEST_UNAME=Linux` for Cursor paths so Darwin keychain preflight is skipped deterministically." The Codex tests also run the Cursor path and must carry those vars. **Suggested fix:** Add `LARCH_LIB_CURSOR_AUTH_TEST_MODE=1 LIB_CURSOR_AUTH_TEST_UNAME=Linux` to each `run_cr` invocation in tests t6–t12 (same pattern as t0, t0c, t0d, t1, t2, t3, t4, t5).

2. **latent** `scripts/session-setup.sh:428-431` — In the passthrough branch (no `--check-reviewers`), when `CALLER_CODEX_BINARY_FOUND` is absent from caller-env but `CALLER_CODEX_PRESENT=false` is present, the code infers `_passthrough_codex_bin="$CALLER_CODEX_PRESENT"` — emitting `CODEX_BINARY_FOUND=false`. This is wrong when `CODEX_PRESENT=false` was written because the runtime probe failed (binary is on `$PATH` but probe timed out or auth-failed). SKILL.md Option A reads this inferred key and prints "Codex binary not found" instead of "runtime probe failed / auth error." **Scenario**: A session generated on the current branch stores `CODEX_PRESENT=false` (probe failed, binary present); a follow-up `/implement` invocation passes that session-env as `--caller-env` without `--check-reviewers`; SKILL.md sees `CODEX_BINARY_FOUND=false` and bails with a misleading "binary not found" diagnostic when `--coder=codex` is requested. **Suggested fix:** In the passthrough branch emit `CODEX_BINARY_FOUND` only when it is explicitly present in caller-env (i.e., drop the `PRESENT` → `BINARY_FOUND` inference fallback), or document the approximation with a comment acknowledging the false-negative case.

3. **nit** `scripts/check-reviewers.sh:226-250` — `cursor_launcher_cleanup_private_config_dir` (line 250) is called unconditionally after the compound `if ! { cursor_preread_service_token && cursor_auth_argv && cursor_launcher_setup_private_config_dir }` block. When `cursor_preread_service_token` or `cursor_auth_argv` fails, `cursor_launcher_setup_private_config_dir` is never called, yet cleanup is invoked. If the cleanup function is not idempotent for never-set-up state it could behave incorrectly. **Suggested fix:** Verify that `cursor_launcher_cleanup_private_config_dir` is idempotent when called without a prior `cursor_launcher_setup_private_config_dir` call, and add a comment asserting this invariant, or restructure so cleanup is only called when setup was attempted.

4. **nit** `scripts/check-reviewers.sh:131` — `SECONDS=0` in `larch_poll_probe_pid` resets the shell-global `SECONDS` builtin, not a local copy. Between the Cursor poll return and the Codex probe launch, any intervening code that relies on `SECONDS` as an accumulated elapsed-time counter would see a value near 0 instead of actual elapsed time. Currently no such code exists between the two probes, but this is a fragile global side-effect. **Suggested fix:** Replace `SECONDS=0; while ... ; if (( SECONDS >= ... ))` with `local _start=$SECONDS; while ... ; if (( SECONDS - _start >= ... ))`, preserving the accumulated global without resetting it.
