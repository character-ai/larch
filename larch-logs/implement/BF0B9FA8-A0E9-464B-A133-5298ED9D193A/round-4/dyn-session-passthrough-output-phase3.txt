### In-Scope Findings

- **correctness** `scripts/session-setup.sh:428-431,440-443` — The passthrough branch (the `else` block when `CHECK_REVIEWERS != "true"`) falls back to inferring `_passthrough_codex_bin="$CALLER_CODEX_PRESENT"` when `CALLER_CODEX_BINARY_FOUND` is absent or invalid. This conflates probe-failed (`PRESENT=false` with the binary on PATH) with binary-absent (`PRESENT=false` because `command -v` found nothing). When a caller-env file from a probe-failed session (e.g. `CODEX_PRESENT=false` because auth timed out, but binary was found) lacks `CODEX_BINARY_FOUND`, the inference emits `CODEX_BINARY_FOUND=false` and writes it forward through `FINAL_CODEX_BINARY_FOUND` → `write-session-env.sh --codex-binary-found false` → the nested session-env. `SKILL.md` lines 1083–1088 explicitly distinguish `BINARY_FOUND=false` ("binary not found" bail message) from `BINARY_FOUND=true + PRESENT=false` ("runtime probe failed / auth error" bail message); the incorrect explicit `false` causes the wrong user-facing bail message for Option A explicit `--coder=codex|cursor` invocations. In practice the impact is limited to old/pre-PR caller-env files that lack `CODEX_BINARY_FOUND`, because new files always carry it; SKILL.md's absent-key treatment (lines 1084, 1087: absent → treat as `false`, print binary-not-found message) produces the same wrong outcome, so the inference doesn't change today's behavior — but it does propagate an incorrect explicit `false` into downstream session-envs, which could matter if future code distinguishes absent from explicit false. The same defect is symmetric for Cursor at lines 440–443. **Suggested fix:** Remove the fallback inference block (lines 428–431 for Codex, 440–443 for Cursor) so that when `CALLER_CODEX_BINARY_FOUND` is absent, `_passthrough_codex_bin` remains `""`, no `CODEX_BINARY_FOUND` line is emitted on passthrough, and SKILL.md's documented absent-key semantics apply cleanly rather than being preempted by a semantically incorrect explicit value.
