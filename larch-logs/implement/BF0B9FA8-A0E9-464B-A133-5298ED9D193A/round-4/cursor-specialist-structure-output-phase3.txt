### In-Scope Findings

1. - **correctness** `scripts/session-setup.sh:428-431` — In the passthrough branch (when `CHECK_REVIEWERS=false`), if `CALLER_CODEX_BINARY_FOUND` is absent from the caller-env but `CALLER_CODEX_PRESENT` is known, the code falls back to using `CALLER_CODEX_PRESENT` as the proxy value for `CODEX_BINARY_FOUND`. This conflates "binary missing" (`PRESENT=false` because the binary is absent) with "probe failed" (`PRESENT=false` because auth timed out or the probe returned non-zero). A legacy session-env that carries `CODEX_PRESENT=false` from a probe failure will cause `CODEX_BINARY_FOUND=false` to be emitted into the new session, and SKILL.md Option A will then print "Codex binary not found" instead of "Codex runtime probe failed / auth error" — wrong diagnostic message for a working-binary scenario. The behavioral outcome (stall to Step 18) is identical, but the user message is misleading. **Suggested fix:** When `CALLER_CODEX_BINARY_FOUND` is absent, do not infer from `PRESENT`; simply leave `_passthrough_codex_bin=""` so no `CODEX_BINARY_FOUND` key is emitted. SKILL.md's own absent-key rule (treat absent as `false`) already handles the fallback conservatively, and the diagnostic text for absent-vs-false is the same, so no SKILL.md change is needed.

2. - **code-quality** `scripts/check-reviewers.sh:167-171,199-203` — `larch_run_one_cursor_probe` and `larch_run_one_codex_probe` both read the outer-scope globals `AUTH_ATTEMPT` and `MAX_AUTH_RETRIES` without declaring them as parameters or documenting the dependency. The functions appear self-contained (only `local` vars declared) but silently depend on the caller's loop counter to decide whether to return 2 (auth-retry) or 1 (permanent failure). This makes the probe helpers harder to reason about in isolation and impossible to call correctly without understanding the outer retry loop's state. **Suggested fix:** Add a brief comment to each function noting the globals it reads (`# Reads: AUTH_ATTEMPT MAX_AUTH_RETRIES`), or pass the values as positional parameters so the dependency is visible at the call site.

3. - **correctness** `scripts/check-reviewers.sh:131` — `larch_poll_probe_pid` resets the global `SECONDS` shell builtin (`SECONDS=0`) to implement the per-probe timeout. Since `SECONDS` is a process-global counter, each probe invocation silently corrupts the script-wide elapsed-time baseline. If `lib-cursor-launcher-common.sh` or `lib-cursor-auth.sh` (sourced at lines 39-41) or any future caller uses `$SECONDS` for elapsed-time computation after the first probe call, the reset produces wrong values. **Suggested fix:** Capture start time with `_t0=$(date +%s)` as a local variable and compute elapsed as `$(( $(date +%s) - _t0 ))` inside the loop; this leaves the global `$SECONDS` undisturbed.

4. - **code-quality** `scripts/test-check-reviewers.sh:28-33` — `run_cr` executes `cd "$REPO_ROOT"` in the function body without a subshell. Because there is no `( ... )` wrapper, each call permanently changes the outer script's current working directory. This works only because all existing `run_cr` calls target the same directory; if a future test ever sets a different CWD between calls (e.g., to test behavior from a non-repo path), `run_cr`'s side-effect `cd` would silently undo it. **Suggested fix:** Wrap the function body in a subshell: `run_cr() { local tmp="$1"; shift; mkdir -p "$tmp"; ( cd "$REPO_ROOT" && TMPDIR="$tmp" LARCH_QUIET_DISABLE=1 "$@" ); }`.
