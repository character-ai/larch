### In-Scope Findings

- **correctness** `python/rebase.py:97-105` — `_is_bump_path` treats `CHANGELOG.md`, `CHANGELOG.rst`, and `CHANGELOG` as bump files via `_CHANGELOG_BASENAMES`, but `scripts/ship-pr.sh:2609-2648` (`ship_pr_vendor_conflict_csv_is_non_bump_only` on `main`) does not mention any CHANGELOG basename; only `.claude-plugin/plugin.json`, `version.go`, `go.sum`, and env-listed paths count. After the same deterministic prepass, CHANGELOG-only waterfall exhaustion therefore raises plain `Stalled` in Python while bash classifies the set as non-bump-only, enters `run_recovery_waterfall`, and can emit the exit-4 handoff (`scripts/ship-pr.sh:2870-2892`). **Suggested fix:** Drop the CHANGELOG basename rule from `_is_bump_path` (and from `test_bump_only_waterfall_exhaustion_stalls_without_handoff_flag`, which currently encodes the wrong parity), or add an explicit bash-parity test that sources the shell helper and asserts identical results for representative CSVs including CHANGELOG-only sets.

- **correctness** `python/rebase.py:92-105` — `_larch_bump_files()` reads only `LARCH_BUMP_FILES` split on `os.pathsep`, while bash prefers `LARCH_VERSION_FILES` with `:`-separated segments and uses `LARCH_BUMP_FILES` only as a deprecated fallback when the primary var is unset (`scripts/ship-pr.sh:2613-2616`, `docs/configuration-and-permissions.md:308-325`). A consumer that sets only `LARCH_VERSION_FILES` (the documented name) will have custom version paths treated as non-bump in Python, so site-1 exhaustion can raise `PrePushConflictHandoff` when bash would return “not non-bump-only” and skip the handoff path. **Suggested fix:** Mirror bash precedence in `_larch_bump_files()` (read `LARCH_VERSION_FILES` first, fall back to `LARCH_BUMP_FILES`, split on `:` not `os.pathsep`), add `ENV_LARCH_VERSION_FILES` to `python/config.py`, and extend `test_mixed_bump_waterfall_exhaustion_stalls_without_handoff_flag` to cover the primary env var.

- **correctness** `python/test_rebase.py:657-683` — `test_bump_only_waterfall_exhaustion_stalls_without_handoff_flag` asserts that a lone `CHANGELOG.md` conflict must stall without handoff, which locks in the CHANGELOG-as-bump behavior above and will fail if `_is_bump_path` is aligned to current bash. **Suggested fix:** Replace that fixture with a conflict path bash actually classifies as bump-only (e.g. unresolved `.claude-plugin/plugin.json`, `version.go`, or a path from `LARCH_VERSION_FILES`), and add a separate test that CHANGELOG-only exhaustion yields `PrePushConflictHandoff` once classification matches `ship_pr_vendor_conflict_csv_is_non_bump_only`.
