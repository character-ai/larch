### In-Scope Findings

- **architecture** `python/rebase.py:92-105` — `_larch_bump_files()` reads only `LARCH_BUMP_FILES`, but bash `ship_pr_vendor_conflict_csv_is_non_bump_only` in `scripts/ship-pr.sh:2609-2626` and `docs/configuration-and-permissions.md:310-325` treat `LARCH_VERSION_FILES` as primary and fall back to deprecated `LARCH_BUMP_FILES` only when the former is unset. Repos configured with only `LARCH_VERSION_FILES` will misclassify custom version-file conflicts as non-bump-only, write the handoff flag, and raise `PrePushConflictHandoff` when bash would take the bump/version path and stall without handoff. **Suggested fix:** mirror bash precedence in `_larch_bump_files()` (read `LARCH_VERSION_FILES` first, deprecated alias second), add `ENV_LARCH_VERSION_FILES` to `python/config.py`, split on `:` per documented contract, and add parity tests for both env vars.

- **architecture** `python/rebase.py:97-100` — `_is_bump_path()` treats `CHANGELOG.md` / `CHANGELOG.rst` / `CHANGELOG` as bump/version paths, but bash `ship_pr_vendor_conflict_csv_is_non_bump_only` (`scripts/ship-pr.sh:2630-2645`) and its deterministic prepass (`scripts/ship-pr.sh:2816-2837`) do not. CHANGELOG-only waterfall exhaustion therefore raises plain `Stalled` in Python while bash routes through the recovery waterfall and, on exhaustion, emits exit-4 handoff with `CONFLICT_FILES` — contradicting the branch’s stated bash-fidelity rule 2. **Suggested fix:** drop the `_CHANGELOG_BASENAMES` gate from `_is_bump_path()` (or gate handoff through a helper tested against the bash function), and add a parity test for CHANGELOG-only conflict CSV.

- **risk-integration** `python/rebase.py:228-236`, `python/ship.py:88-94`, `python/finalize.py:40-45` — this branch replaces waterfall-exhaustion `NeedsUserInput` with `PrePushConflictHandoff(Stalled)`, but existing drivers still map any `Stalled` subclass to undifferentiated `Outcome.STALLED` without reading `conflict_files`, `resume_phase`, `caller_kind`, or `conflict_csv`. The library exception carries enough for Phase 7 translation, yet `rebase.rebase_and_push()` is already called from `ship.py` and `finalize.py` today, so handoff metadata and the former exit-3 (`NeedsUserInput`) distinction are lost at the driver boundary while exit code becomes 4 with no `CONFLICT_FILES` emission. **Suggested fix:** add a shared mapper that handles `PrePushConflictHandoff` before generic `Stalled` (preserving fields on `ShipResult`/`FinalizeResult` or a dedicated payload), even if full state-file writes and CLI exit wiring remain Phase 7.
