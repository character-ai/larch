Reviewing the branch diff against bash pre-push conflict handoff semantics.
Comparing the bash reference implementation with the Python changes.
### In-Scope Findings

- **risk-integration** `python/rebase.py:92-105` — The non-bump-only gate reads only `LARCH_BUMP_FILES` via `config.ENV_LARCH_BUMP_FILES`, but bash `ship_pr_vendor_conflict_csv_is_non_bump_only` in `scripts/ship-pr.sh:2613-2617` treats `LARCH_VERSION_FILES` as canonical and uses `LARCH_BUMP_FILES` only as a deprecated fallback when the former is unset (documented in `docs/configuration-and-permissions.md:308-325`). Repos configured with the current variable will classify version-file conflicts differently in Python vs bash: Python may raise `PrePushConflictHandoff` and write the resume flag where bash would take the bump-only stall path with no exit-4 handoff. **Suggested fix:** Mirror bash precedence in `_larch_bump_files()` (read `LARCH_VERSION_FILES` first, fall back to `LARCH_BUMP_FILES`, split on `:`), add `ENV_LARCH_VERSION_FILES` to `python/config.py`, and add parity tests for both env vars.

- **risk-integration** `python/rebase.py:97-100` — `_is_bump_path()` treats `CHANGELOG.md`, `CHANGELOG.rst`, and `CHANGELOG` as bump/version paths, so CHANGELOG-only waterfall exhaustion raises plain `Stalled` with no handoff flag. Bash `ship_pr_vendor_conflict_csv_is_non_bump_only` (`scripts/ship-pr.sh:2609-2648`) does not treat CHANGELOG basenames as version files; CHANGELOG-only conflicts there pass the non-bump gate and trigger exit-4 / `ship_pr_pre_push` handoff with `CONFLICT_FILES` and `ship-pr-rrr-after-phase14.flag`. Phase 7 would stall operator recovery for CHANGELOG-only pre-push conflicts on the Python path while bash still dispatches `conflict-resolution.md`. **Suggested fix:** Drop the `_CHANGELOG_BASENAMES` check unless bash gains the same rule; add a bash-sourced parity test (CHANGELOG-only CSV → handoff eligible) so the gate stays aligned with `scripts/ship-pr.sh`.

- **risk-integration** `python/rebase.py:108-109` — There is no bash-sourced parity harness for `_conflicts_are_non_bump_only` / `_is_bump_path` against `ship_pr_vendor_conflict_csv_is_non_bump_only`, unlike other ship-parity surfaces (`python/test_checks_bash_parity.py`, `python/test_redact.py`). The two env-var and CHANGELOG mismatches above would not be caught by unit tests alone (`python/test_rebase.py:313-340` asserts Python behavior against the plan, not bash). **Suggested fix:** Add `test_rebase_bash_parity.py` (or extend an existing parity module) that sources the bash helper and asserts matching true/false for representative CSV inputs: plugin.json, version.go, `LARCH_VERSION_FILES` entries, deprecated `LARCH_BUMP_FILES`, mixed/non-bump, and CHANGELOG-only.

### Out-of-Scope Observations

- **risk-integration** `python/ship.py:88-94`, `python/finalize.py:40-45` — This branch adds `PrePushConflictHandoff` in `python/rebase.py` but does not update the Python ship driver. Both modules map any `Stalled` subclass (including `PrePushConflictHandoff`) to generic `Outcome.STALLED` without preserving `conflict_files`, `resume_phase`, or `caller_kind`.
