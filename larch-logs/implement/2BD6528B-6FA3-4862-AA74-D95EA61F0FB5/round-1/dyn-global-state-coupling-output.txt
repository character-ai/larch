### In-Scope Findings

- **architecture** [`scripts/ship-pr.sh:1700-1720`](scripts/ship-pr.sh) — Phase B iterates the full `fixable_jobs[]` list without checking whether Phase A returned `_RCC_STATUS=ok` for that job. The plan says the verification sweep runs only after each fixable job’s per-job loop succeeds; as written, jobs already pushed into `unfixable[]` at lines 1694–1697 still get `_run_per_job_command_once` and may run another `run_captured_cmd_then_fix_loop`, spending extra fix budget on jobs the plan already treated as exhausted. **Suggested fix:** Track Phase-A outcomes (e.g. a parallel `phase_a_ok[]` bitset or skip `fixable_jobs[$i]` when the job token is already in `unfixable`) and restrict the Phase B loop to jobs that completed Phase A with `_RCC_STATUS=ok`.

- **architecture** [`scripts/ship-pr.sh:1694-1734`](scripts/ship-pr.sh) — `unfixable` is append-only across both phases. If Phase A marks a job unfixable (`*) unfixable+=("$job_token")` at 1696) but Phase B’s verify-fix path later sets `_RCC_STATUS=ok` (1717–1718), the job token is never removed from `unfixable`, so the tail at 1726–1734 can `exit 3` with `BAIL_REASON=ci-local-unfixable:…` even though every mapped command now passes locally. **Suggested fix:** On Phase B success, delete the job token from `unfixable` (or rebuild `unfixable` from Phase-B failures only), and only bail when the final set is non-empty after both phases complete.

- **architecture** [`scripts/ship-pr.sh:1694-1696`](scripts/ship-pr.sh) — `run_captured_cmd_then_fix_loop` exposes `_RCC_STATUS=head-changed` (163:165) for `FAILURE_REASON=head-changed-after-dispatch`, but the Phase A/Phase B call sites collapse every non-`ok` status into `unfixable+=("$job_token")` and eventually `exit 3`. The plan calls for the same `exit_stall` path used elsewhere when HEAD moves during dispatch; routing `head-changed` through the unfixable bail changes operator recovery semantics. **Suggested fix:** Branch on `_RCC_STATUS=head-changed` at the call site (both 1694 and 1718) and invoke the existing stall/exit_stall helper with the phase-appropriate step code instead of adding the job to `unfixable`.

- **architecture** [`scripts/ship-pr.sh:119-177`](scripts/ship-pr.sh) — `run_captured_cmd_then_fix_loop` resets `_RCC_DELTA_PATHS_FILE` to a fresh `rcc-delta-paths-$$-$RANDOM.txt` on every entry (125–126) and only merges into the process-global `ALL_LINT_FIX_DELTA_PATHS_FILE` (158). That avoids stale per-helper delta files between jobs/phases; duplicate path lines are deduped by `append_unique_paths_file` (72–80). No defect here—call sites correctly re-set `_RCC_RERUN_FN`, `_RCC_SITE`, `_RCC_TARGET_CMD_ARGS_FILE`, `_RCC_MAX_ITER`, `_PJL_LOG_PATH`, and `_PJL_JOB_TOKEN` before each invocation (1688–1692, 1711–1716), and `_run_per_job_command_capture` overwrites `_RCC_CMD_RC` each iteration (1631–1633).
