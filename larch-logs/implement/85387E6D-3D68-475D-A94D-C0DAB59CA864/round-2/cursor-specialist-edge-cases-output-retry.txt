### In-Scope Findings

1. **Important** — **architecture** `scripts/upsert-diagrams-comment.sh:215` — Stable-marker discovery uses exact first-line equality (`$2 == marker`) with no BOM or trailing-`\r` normalization, while `scripts/tracking-issue-read.sh:423-425` already strips a UTF-8 BOM before marker matching. If GitHub returns a comment whose first line is `<!-- larch:diagrams v1 -->\r` or BOM-prefixed, the helper treats the comment as missing, creates a second stable-marker comment, and splits Architecture/Code Flow across two comments. **Suggested fix:** Normalize list-tab first lines the same way as `tracking-issue-read.sh` (strip BOM and `${line%$'\r'}`) before comparing to `MARKER`; add a harness case with CRLF/BOM first lines.

2. **Latent** — **correctness** `scripts/upsert-diagrams-comment.sh:94-125` — The section splitter only tracks ```mermaid fences; any plain ``` block before the real `## Code Flow Diagram` / `## Architecture Diagram` boundary, or an unclosed ```mermaid fence, leaves `in_fence` wrong so a literal `## … Diagram` line inside prose/code can be treated as a section boundary and the next upsert can drop the other section silently. **Suggested fix:** Extend the fence state machine (or reject invalid diagrams at generation time) and add a regression where a non-mermaid fence or unclosed mermaid fence precedes the opposite section heading.

3. **Latent** — **risk-integration** `skills/design/SKILL.md:974` — FINDING_8 `--clear-architecture` only updates the stable `<!-- larch:diagrams v1 -->` comment; legacy `<!-- larch:diagrams v1 runid=… -->` orphans are never matched, so re-running `/design` on a non-architectural plan after an old `/implement` run leaves a stale Architecture block on the legacy comment even though 5c.5 reports `ARCHITECTURE_SOURCE=cleared`. **Suggested fix:** Document this migration limitation prominently in Step 5c.5/3b operator text, or add an optional one-time legacy cleanup path (out of scope unless product wants it).

4. **Nit** — **architecture** `scripts/upsert-diagrams-comment.sh:266-272` — When `--clear-architecture` runs but no stable comment exists, the helper exits `UPSERT_STATUS=no-op` while still emitting `ARCHITECTURE_SOURCE=cleared`, which implies GitHub state changed when nothing was updated (legacy orphans remain). **Suggested fix:** Emit `ARCHITECTURE_SOURCE=absent` (or a distinct `no-op`) when `comment_id` is empty after a clear request.

### Out-of-Scope Observations

1. **Latent** — **correctness** `scripts/tracking-issue-summary.sh:71` — The same exact first-line marker match (no CRLF/BOM normalization) exists in the pre-existing summary upsert path; the new stable-marker workflow amplifies the impact but the underlying pattern predates this branch. **Suggested fix:** Fix once in a shared helper used by both scripts.
