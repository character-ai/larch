Reviewing branch changes with focus on bash exit semantics in `design-publish.sh`.
### In-Scope Findings

- **correctness** `skills/design/scripts/design-publish.sh:194-317` — After `design_reentry_marker_write`, the script runs `set +e` (line 194) and never restores `set -e` for the rest of the success tail (upsert, publish capture, post-publish render, rename, and final `write_result_env_and_emit`). That disables errexit for ~120 lines, so any later command that fails without an explicit `if`/`||` guard will not abort and the driver can still reach `exit 0` with a partially applied publish tail. The plan and former inline SKILL pattern scoped `set +e`/`set -e` only around subshell captures (`upsert-diagrams-comment.sh`, `design-log-publish.sh`); the marker block only needs a short `set +e` … `set -e` around the marker call itself. **Suggested fix:** After the marker failure-handling block (after line 206), add `set -e`, then wrap upsert and publish captures in their own `set +e` / `_rc=$?` / `set -e` pairs (matching `design-publish.md` ordering prose), leaving the remainder of the script under `set -euo pipefail`.

- **risk-integration** `skills/design/SKILL.md:1315-1320` — The Step 5c driver handoff uses three separate `if` statements: exit `3` prints the “result-env write failed … continuing” WARN (lines 1315–1317), but the next check (`_publish_rc` ≠ 0 and ≠ 1, lines 1318–1320) is still true for `_publish_rc=3`, so the orchestrator immediately prints “design-publish.sh failed (exit 3); aborting /design” and `exit 1`. That contradicts the documented `{0,1,3}` contract in the same section (line 1362) and nullifies `design-publish.sh`’s `exit 3` path (lines 317–318), which is meant to allow stdout fallback after a completed publish tail when `.design-publish-result.env` cannot be written. **Suggested fix:** Exclude `3` from the unexpected-rc guard, e.g. `if [[ "${_publish_rc:-0}" -ne 0 && "${_publish_rc:-0}" -ne 1 && "${_publish_rc:-0}" -ne 3 ]]; then`, or restructure as an `if/elif` chain (`2` → abort, `3` → warn+continue, `0|1` → parse, else → abort). Add a `test-design-structure.sh` pin on that fence so the prose contract cannot drift again.
