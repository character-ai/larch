### In-Scope Findings

- **correctness** `skills/design/scripts/design-publish.sh:187-305` — After `PLAN_WRITE_OK=true`, the success tail still runs under `set -euo pipefail` without a blanket `set +e` or ERR trap. Any hard failure after a successful `plan-block-write.sh` (e.g. `source "$PLUGIN_ROOT/scripts/lib-design-reentry-guard.sh"`, `printf` to `diagrams-architecture-upsert.stdout`, or `phase_driver_write_result_env` failing after emit) aborts the driver with exit status **1** and usually **no** `.design-publish-result.env`. The contract reserves exit `1` for plan-block-write failure (`PLAN_WRITE_OK=false` in the result env); the SKILL Step 5c block treats `_publish_rc=1` as that path. The orchestrator will not print the plan-write failure warning unless `PLAN_WRITE_OK=false` is parsed (item 7), but the run can stop with the plan already on GitHub, publish/rename/summary steps incomplete, and no machine keys for operators. **Suggested fix:** After plan-block-write succeeds, either (a) disable `set -e` for the remainder and handle each helper’s rc explicitly (matching publish/upsert/marker), or (b) add an ERR trap that writes `.design-publish-result.env` with `PLAN_WRITE_OK=true` plus a `WARN=` and exits with a dedicated code outside `{0,1}` (e.g. `3`), and teach the SKILL exit-code contract to abort on that code.
