### In-Scope Findings

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:171-175` — The `skipped-not-present:*|*:skipped-not-present` arm assigns `tier4_status=skipped-not-present` whenever `new` is `skipped-not-present`, even when the stored value is more severe (`invalid-patch`, `no-patch`, `apply-failed`, `emit-plan-failed`). In the tier-4 mini-waterfall (Codex → Cursor → Claude), a common sequence is Codex `invalid-patch` then Cursor `skipped-not-present` when `--cursor-present false`; merge downgrades to `skipped-not-present`, contradicting the documented precedence in `revise-plan-with-waterfall.md:65` (`invalid-patch` > `no-patch` > `skipped-not-present`). **Suggested fix:** Drop the `*:skipped-not-present` reverse pattern (or only accept `new=skipped-not-present` when `tier4_status` is `not-attempted` / empty / already `skipped-not-present`); prefer a rank table and `tier4_status=$(max_severity "$tier4_status" "$new")` so the worse status always wins.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:177-181` — The `no-patch:*|*:no-patch` arm has the same asymmetry: `invalid-patch:no-patch` matches `*:no-patch` and sets `tier4_status=no-patch`, downgrading from `invalid-patch`. That pair is reachable when tier-4 Codex rejects a file-replacement candidate as `invalid-patch` and tier-4 Cursor returns empty/`no-patch`. **Suggested fix:** Same as above—either left-anchor merges only (`no-patch:*` without `*:no-patch`) with explicit “keep worse” rules, or numeric severity comparison; never assign a less-severe `new` over a more-severe stored status.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:189-199` — Cross-severity reverse matches also downgrade: `apply-failed:emit-plan-failed` hits `*:apply-failed` and sets `emit-plan-failed` (less severe than `apply-failed`), and `emit-plan-failed:apply-failed` hits `*:emit-plan-failed` and keeps `emit-plan-failed` instead of promoting to `apply-failed`. Both violate the stated `emit-plan-failed > apply-failed` ordering. **Suggested fix:** Replace the symmetric `*|*:` outer cases with a single severity-rank helper; early `ok` / empty guards can stay, but all non-ok pairs should resolve to `max(rank(old), rank(new))`.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:165-201` — Several valid status pairs fall through the outer `case` with no assignment (implicit no-op), so the result depends on match order rather than a total ordering; examples include unlisted cross-pairs if a future caller passes an unexpected status string, and `not-attempted:not-attempted` (harmless today because `attempt_tier` never emits `not-attempted`, but the inner `not-attempted:*|*:not-attempted` arm deliberately omits `not-attempted` from its inner list). The matrix is incomplete as a specification of merge semantics. **Suggested fix:** Implement merge as total function over the seven known statuses (documented enum only) with explicit default/error for unknown values, rather than a partial `case` grid.
