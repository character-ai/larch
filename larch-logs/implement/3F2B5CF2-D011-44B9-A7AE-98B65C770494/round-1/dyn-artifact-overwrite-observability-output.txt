Reviewing branch changes for tier-4 artifact overwrite and integration risks.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:457-489`, `skills/design/scripts/plan-review-loop.sh:377-399`, `scripts/lib-design-round-artifacts.sh:38-48` — Tier-4 reuses allowlisted `revise/` filenames and overwrites `prompt.txt` plus any `<tool>-output.txt` / `<tool>-candidate.patch` touched in the tier-4 mini-waterfall, but `plan-review-loop.sh` only parses `REVISE_STATUS` (and `REVISE_WINNING_TIER`, which revise does not emit) from revise stdout and never writes allowlisted `revise.env`. The full revise KV contract (`REVISE_TIER_1/2/3/4_STATUS`, `REVISE_PATCH_PATH`, `REVISE_TIER`) exists only on ephemeral stdout while `design-log-publish.sh` / `_snapshot_round_dir` copy the post-overwrite files into committed `larch-logs/design/`. After `REVISE_STATUS=ok-fallback`, published forensics can show file-replacement bodies under `*-candidate.patch` with no retained corrupt unified-diff artifacts or per-tier statuses, so audit/post-mortem workflows cannot reconstruct the #3146 failure mode from committed round data alone. **Suggested fix:** Before tier 4 runs, snapshot allowlisted sidecars (e.g. copy `prompt.txt` → `prompt-unified-diff.txt` and failed `*-candidate.patch` files) or write all revise stdout KVs to `revise.env`; extend `round-summary.env` / `design_round_revise_artifact_included` if new sidecar names are added.

- **risk-integration** `skills/design/scripts/revise-plan-with-waterfall.sh:360-367`, `skills/design/scripts/revise-plan-with-waterfall.sh:477-487` — Tier-4 `attempt_tier` reuses the same `<tool>-output.txt` paths but returns `no-patch` when `launch_tier` fails without truncating a file already written by tier 1–3. A later tier-4 winner can then leave non-winning tools’ `*-output.txt` (and their `*-candidate.patch` if tier 4 never re-ran that tool) showing unified-diff-era content while `prompt.txt` already reflects file-replacement instructions, producing an internally inconsistent published `revise/` bundle. **Suggested fix:** At the start of each tier-4 `attempt_tier`, remove or truncate the target `<tool>-output.txt` (and optionally refresh `<tool>-candidate.patch`), or use distinct allowlisted tier-4 basenames until `finalize()` copies the winner into the canonical names.

- **risk-integration** `scripts/test-revise-plan-with-waterfall.sh` — Acceptance calls for `REVISE_TIER_4_STATUS` on every harness case and a tier-4 `ok-fallback` success path, but the harness has no `REVISE_TIER_4_STATUS`, `ok-fallback`, or tier-4-success assertions (and `skills/design/scripts/test-plan-review-loop.sh` stubs only emit `REVISE_STATUS=ok`). The primary integration fix (tier-4 success + `ok-fallback` propagation + artifact contract) therefore has no automated guard against regressions in overwrite behavior or consumer handling. **Suggested fix:** Add a dedicated harness case where tiers 1–3 return `invalid-patch`, tier 4 file-replacement wins, assert `REVISE_STATUS=ok-fallback` / `REVISE_TIER_4_STATUS=ok` / `REVISE_PATCH_PATH` points at the overwritten winner file, and extend `test-plan-review-loop.sh` with a stub emitting `ok-fallback` to verify `round-summary.env` retention.
