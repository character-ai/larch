### In-Scope Findings

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:239-257` — After `started=1`, the awk only suppresses a line that is exactly `` ``` ``; any narration after a closing fence (e.g. `` ```diff\n--- a/plan.txt\n...\n```\nApplied successfully.``) is copied into the candidate patch. That trailing prose is not valid unified-diff content and will fail `git apply --check`, but it is a real post-extraction corruption path distinct from the leading-preamble case #3146 fixed. **Suggested fix:** Once `started=1`, stop copying at the first standalone `` ``` `` (and optionally treat a second `` ```diff `` as a hard stop), or trim from the last hunk/context line backward instead of streaming the remainder of the file.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:244-250` — The pre-start gate arms on the first line matching `^--- `, `^\+\+\+ `, `^@@ `, or `^diff --git ` anywhere in the file. Illustrative diff headers in markdown before the real patch (e.g. a “canonical form” example block using `--- a/plan.txt` / `+++ b/plan.txt`) will flip `started=1` too early and emit example lines plus later prose into the candidate; `main`’s `cp`-whole-output path failed differently on prose-only preambles but did not false-start on mid-file example headers. **Suggested fix:** Prefer requiring a paired `--- a/plan.txt` then `+++ b/plan.txt` (or `diff --git a/plan.txt b/plan.txt`) before arming, or skip lines until the first `` ```diff `` / `` ``` `` block and only then hunt for headers inside the following slice.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:245-252` — Only the opening `` ```diff `` is consumed in the `!started` branch; once `started=1`, a later `` ```diff `` line is printed as patch body and interior `` ``` `` closers are dropped. Multi-fence outputs (prose, then `` ```diff ``, then a second fenced diff) therefore produce structurally invalid patches instead of selecting the last fenced block. **Suggested fix:** Detect fenced regions explicitly (track fence depth / `` ```diff `` open-close pairs) and run header detection only inside the last closed fence, or reset `started` when a new `` ```diff `` opener appears after a closing `` ``` ``.
