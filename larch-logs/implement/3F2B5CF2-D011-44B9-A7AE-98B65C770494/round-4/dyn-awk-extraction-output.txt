### In-Scope Findings

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:359-380` — `extract_file_replacement_candidate` treats `^## Plan$` as a block opener but never copies that line into `block[]`; `capture_candidate` only emits `block[1..trailer_idx]`, so a well-formed model response like `## Plan` + body + `diff_lines: N` is written to `plan.txt` without the required `## Plan` heading. `validate_file_replacement()` and the test harness stub `design-driver.sh` only check the `diff_lines:` trailer, so tier-4 file-replacement can return `REVISE_STATUS=ok-fallback` while producing a structurally invalid plan (case3 in `scripts/test-revise-plan-with-waterfall.sh` asserts `fallback win` but not `## Plan`). **Suggested fix:** On `^## Plan$`, append the header to the block (`block[++block_len] = $0` after `reset_block()`), or prepend `## Plan` inside `capture_candidate` before copying lines; add a harness assertion that `plan.txt` still begins with `## Plan` after tier-4 success.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:246-252` — `is_patch_line()` ends with `[-+]`, so any post-hunk line starting with `-` or `+` is treated as part of the patch. Unfenced model output often adds markdown bullets or “summary” lines after the diff; those lines are greedily included, which can recreate the original `git apply --check` failures (corrupt patch / misaligned hunks) even after preamble stripping. The harness only covers trailing prose that does not start with `-`/`+` (case2b). **Suggested fix:** Tighten termination: after the first `@@` hunk header, only accept lines matching unified-diff hunk bodies (`^ `, `^-`, `^\+`, or `^\` No newline at end of file`), and stop the greedy scan on the first non-matching line instead of using the broad `[-+]` alternative for the whole candidate.

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:237-270` — `is_candidate_start()` fires on every in-patch `---`/`+++` pair as well as on `diff --git`, so one physical patch yields overlapping candidates (full patch from `diff --git`, then a second candidate starting at the embedded `---`). `attempt_tier` tries `candidate-*.patch` in glob order; depending on numbering, a partial inner candidate can be validated before a complete outer one, or extra invalid candidates can burn tiers before the good patch is reached. **Suggested fix:** Only start a new candidate at `diff --git`, or at the first `---`/`+++` pair that is not already inside an emitted range (track `last_end` and skip starts with `idx < last_end`).

- **correctness** `skills/design/scripts/revise-plan-with-waterfall.sh:313-317` — When any fenced ` ```diff ` block produces at least one extracted candidate, `found_file` is set and the full-response fallback (`extract_unified_diff_candidates_from_source "$output"`) is skipped. A valid unfenced `--- a/plan.txt` patch after a fenced wrong-path diff is never extracted for tiers 1–3; recovery depends entirely on tier-4 file-replacement. **Suggested fix:** Always run the unfenced full-output pass and merge/dedupe candidates, or only set `found_file` after a candidate passes `validate_unified_headers` + `check_git_apply`, not merely after awk extraction.
