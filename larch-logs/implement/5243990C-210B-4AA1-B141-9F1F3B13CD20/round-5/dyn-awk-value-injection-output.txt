### In-Scope Findings

- **security** `skills/implement/scripts/stall-recovery-report.sh:135-171` — `rewrite_ship_pr_state_keys` passes every replacement value through gawk `-v "v$i=${vals[$i]}"`, and gawk interprets backslash escapes in `-v` assignments (`\n`, `\t`, `\\`, etc.), so an unsanitized value could be silently altered before `print key "=" u[key]` writes `ship-pr-state.sh`. On this branch the only callers are `cmd_clear_stall` (literals `false` / empty `STALL_STEP` only; `skills/implement/scripts/stall-recovery-report.sh:217`) and `cmd_seed_terminal_state` rewrite (only `STALL_TRACKING=true` plus `STALL_STEP` / `PHASE` after `safe_step_value` / `safe_phase_value`; `skills/implement/scripts/stall-recovery-report.sh:265-275`). Disk-sourced fields such as `BAIL_FAILURE_DETAIL_LOG` (paths may contain `\` on Windows or escaped segments) are not passed through `-v`; they are copied unchanged via the awk `print` pass-through branch (`skills/implement/scripts/stall-recovery-report.sh:152-163`), so the scout’s backslash scenario does not affect those keys today. `safe_phase_value` / `safe_step_value` (`skills/implement/scripts/stall-recovery-report.sh:726-743`) whitelist tokens and collapse everything else to `unknown`, which blocks `\` in the only disk-derived values currently fed to `-v`. There is no present remote-code path, but the helper is a reusable footgun if a future caller passes `kv_get` output for an unsanitized key. **Suggested fix:** centralize awk-safe encoding in `rewrite_ship_pr_state_keys` (e.g. double backslashes before building `awk_v`, or pass values via `ENVIRON` / a temp file instead of `-v`), document the invariant in `stall-recovery-report.md`, and add a harness case that writes a backslash-heavy value into a rewritten key and asserts the on-disk line is byte-identical.
