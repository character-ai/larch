Reviewing the branch diff and stall-recovery KV emission paths for the post-mv re-read pattern.
### In-Scope Findings

- **correctness** `skills/implement/scripts/stall-recovery-report.sh:230-235,313-318` — The post-`mv` destination re-read uses `if tracking=$(read-session-env-key.sh ...); then ... fi` instead of the temp-read `|| emit_*_false_exit` pattern. Under `set -euo pipefail`, a non-zero exit from `read-session-env-key.sh` makes the `if` test false, skips the value check, and falls through to `emit_kv CLEARED true` / `emit_kv SEEDED true` without emitting the promised false KV or a non-zero exit. That breaks the documented contract that operational failures on destination re-read emit `CLEARED=false` / `SEEDED=false` before exit (`stall-recovery-report.md` lines 37–38). After a successful `mv`, a transient unreadable `ship-pr-state.sh` or a tool failure could be reported as cleared/seeded while disk state is unverified, and the orchestrator may clear in-memory `STALL_TRACKING` on `CLEARED=true`. **Suggested fix:** Mirror the temp-read chain: `tracking=$(read-session-env-key.sh --file "$state" ...) || emit_cleared_false_exit 1` (and the seed analogue), then `if [ "$tracking" != false ]` / `!= true`; remove the outer `if ...; then` wrapper. Add harness cases that stub `read-session-env-key.sh` to exit 1 on the destination call only (distinct from `noop-mv`, which exercises a stale/wrong value with exit 0).

### Out-of-Scope Observations

- The `case22-clear-dest-assert-fail` / `case22-seed-dest-assert-fail` tests in `skills/implement/scripts/test-stall-recovery-report.sh:806-861` use a no-op `mv` to leave disk stale and assert via value mismatch; they do not cover `read-session-env-key.sh` exiting non-zero on the destination re-read, so the regression above would not be caught by the current matrix.
