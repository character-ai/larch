Reviewing branch changes with focus on Bash 3.2 array portability in `rewrite_ship_pr_state_keys`.
### In-Scope Findings

- **correctness** `skills/implement/scripts/stall-recovery-report.sh:138-171` — The new `rewrite_ship_pr_state_keys` helper uses a compound declaration `local -a keys=() vals=() awk_v=()`. GNU Bash 3.2 (macOS `/bin/bash`) only applied array attributes to the **first** name in a multi-variable `declare`/`local -a` statement; that was fixed in Bash 4.0 (see Bash 4.0 `NEWS`). Here, `vals` and `awk_v` are therefore initialized as empty-string scalars from `=()`, not as indexed arrays. Current `clear-stall` / `seed-terminal-state` call sites still behave correctly because `vals+=` / `awk_v+=` run before any `${vals[$i]}` or `"${awk_v[@]}"` use and Bash 3.2 promotes those scalars to arrays on first `+=`, but the helper depends on that implicit promotion rather than explicit array setup. That is a latent portability footgun on the determinism-critical stall-state rewrite path (wrong/missing `-v` args or subscript reads if promotion order ever changes). **Suggested fix:** Split into three declarations on separate lines (`local -a keys=()` / `local -a vals=()` / `local -a awk_v=()`), matching `BASH_AUTHORING.md` §3 style; optionally harden the final call with the repo’s Bash 3.2 empty-array idiom `"${awk_v[@]+"${awk_v[@]}"}"` (see `scripts/test-render-final-summary-bash32.sh` / issue #3039) if `n` can ever be zero.

### Out-of-Scope Observations

- **`awk_begin+="..."`**, C-style `for ((i = 0; i < n; i++))`, and `${vals[$i]}` after the `while`/`+=` loop are Bash 3.2–safe; no issue there.
- **`scripts/lint-bash32.sh`** only flags Bash 4+ constructs (`declare -A`, `mapfile`, `${var^^}`, namerefs, `&>>`, coprocs, etc.); it would **not** catch compound `local -a` initialization or unsafe empty `"${awk_v[@]}"` under `set -u`. **`scripts/test-lint-bash32.sh`** (Makefile `test-lint-bash32`, `test-harnesses-13`) regression-tests the **linter**, not per-script Bash 3.2 runtime behavior of `stall-recovery-report.sh`.
- Pre-existing precedent: `skills/review-and-fix/scripts/review-and-fix.sh:812` uses the same two-name pattern `local -a round_summary_files=() round_summary_glob=()`.
- Round 2 review on this branch already noted `local -a keys=() vals=()` as acceptable OOS; this review extends that to the three-name form introduced for `awk_v`.
- **`test-stall-recovery-report.sh`** exercises `clear-stall` / `seed-terminal-state` on the branch’s default CI bash (typically 4.x/5.x), so it would not catch macOS 3.2-only declaration quirks unless run under `/bin/bash` 3.2 explicitly (contrast `scripts/test-render-final-summary-bash32.sh` / `scripts/test-collect-agent-bash32.sh`).
