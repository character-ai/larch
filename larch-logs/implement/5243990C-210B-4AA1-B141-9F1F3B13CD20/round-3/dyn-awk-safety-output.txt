### In-Scope Findings

- **security** `skills/implement/scripts/stall-recovery-report.sh:135-169,260-268` — `rewrite_ship_pr_state_keys` builds an awk program by interpolating `${vals[$i]}` into double-quoted awk string literals (`u["…"]="…"`). `cmd_clear_stall` only passes fixed literals (`false`, `""`) and is safe. In `cmd_seed_terminal_state`’s rewrite path, when `--stall-step` / `--phase` are omitted, `$step` and `$phase` come straight from `kv_get "$state" STALL_STEP` / `PHASE` with no `safe_step_value` / `safe_phase_value` pass. `check_ship_pr_state_syntax` only requires `^[A-Z][A-Z0-9_]*=.*$`, so values may contain `"`, `\`, `;`, and other awk metacharacters (e.g. `PHASE=x"; system("id"); #`). That can break out of the interpolated string and run arbitrary awk when `seed-terminal-state` rewrites an existing `ship-pr-state.sh`. Elsewhere in the same file, `compose_body_content` already sanitizes disk-backed step/phase before use (`799-800`, `917`). **Suggested fix:** Always normalize disk-backed values before embedding: `step=$(safe_step_value "$(kv_get "$state" STALL_STEP "8")")` and `phase=$(safe_phase_value "$(kv_get "$state" PHASE "ci-initial")")`, then apply CLI overrides; prefer refactoring `rewrite_ship_pr_state_keys` to pass updates via `awk -v` (as in `cmd_record_attempt` at `656-659`) or a dedicated escaper so values are never spliced into program text.
