### In-Scope Findings

- **code-quality** `skills/implement/scripts/stall-recovery-report.sh:129-162` — `rewrite_ship_pr_state_keys` builds an inline awk program by interpolating `${vals[$i]}` into double-quoted bash strings (`u["KEY"]="VALUE"`). On the `seed-terminal-state` rewrite path (`skills/implement/scripts/stall-recovery-report.sh:249-257`), `STALL_STEP` and `PHASE` are taken from `kv_get` and passed through unchanged when `--stall-step` / `--phase` are omitted, so any value that satisfies `check_ship_pr_state_format` (only `KEY=…` shape, not value charset) can reach awk unescaped. Values containing `"`, `\`, or newlines can break the generated awk program or yield a corrupt `ship-pr-state.sh` while `set -euo pipefail` is active. `clear-stall` is less exposed (literals `false` and `""`), but the helper is shared. **Suggested fix:** Before every rewrite, normalize disk-sourced `step` / `phase` with `safe_step_value` / `safe_phase_value` (or map unknowns to the same defaults used on the seed-fresh path), and escape awk string literals in the builder (e.g., `gsub`/`awk -v` per key instead of bash string concatenation into the program text).

- **code-quality** `skills/implement/scripts/step-18b-final-report.sh:61-70` — `token_rc` is assigned in the token-report failure branch but never read or emitted; the contract documents only `EMIT_BODY`, `WFR_RC`, and `STEP17_EMITTED_PRESENT`. That is harmless on bash 3.2 but adds noise for reviewers and future edits (someone may assume a KV exists). **Suggested fix:** Drop `token_rc` and the assignment, or emit a documented KV (e.g. `TOKEN_REPORT_RC`) if orchestration should distinguish token-report failure from write-final-report failure.
