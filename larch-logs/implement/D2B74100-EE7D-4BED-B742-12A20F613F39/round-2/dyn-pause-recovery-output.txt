Reviewing pause/recovery changes: reading the diff and inspecting the key scripts.
### In-Scope Findings

- **correctness** `skills/design/scripts/design-postplan-emit.sh:215` — On the internal pause path, `_postplan_pause_checkpoint` calls `validate_repo "$_repo"` before writing `POSTPLAN_EMIT_STATUS=paused` and before `exec` into `design-pause-save.sh`. Because `validate_repo` invokes `fail` (exit **2**), a malformed `REPO` read from `source-env.sh` aborts Step 2b with the orchestrator’s “configuration error (exit 2)” path instead of handing off to pause-save, which already validates argv/`REPO` and returns `PAUSE_OK=false` / `ERROR=invalid-repo` without aborting `/design`. `.pause-requested` stays armed, no pause marker is written, and the operator gets a postplan failure rather than a structured pause failure. **Suggested fix:** Drop the pre-exec `validate_repo` in `_postplan_pause_checkpoint` (or replace it with a non-fatal check that omits `--repo` when invalid) so malformed repo handling is delegated to `design-pause-save.sh` after `POSTPLAN_EMIT_STATUS=paused` is written; add a `test-design-postplan-emit.sh` case with bad `export REPO=…` in `source-env.sh` and `.pause-requested` to assert `exec` still occurs and pause-save’s envelope is returned.

- **correctness** `scripts/design-pause-save.sh:198-200` — The new contradictory-envelope branch (`publish_rc ≠ 0` and stdout `PUBLISH_OK=true`) calls `log_failure` with only `$publish_err`, but the misleading success line lives on `$publish_out`. Stubs and some real failures can leave stderr empty while stdout carries `PUBLISH_OK=true`, so `execution-issues.md` may record an empty Tool Failures capture even though publish was normalized to failure—hurting diagnosis without blocking `rc-false-recovery`. **Suggested fix:** When forcing `PUBLISH_OK=false`, log `$publish_out` (or a merged out+err capture) via `append-tool-failure.sh`, and extend `test-design-pause-resume.sh` `rc-ok-false` to assert the failure log contains the stdout envelope.

### Out-of-Scope Observations

- **Pre-existing:** `scripts/design-pause-save.sh:194-197` still returns `ERROR=publish-failed` on non-zero publish exit with a missing `PUBLISH_OK` line and never inspects `RECOVERY_BRANCH`. Current `design-log-publish.sh` always emits `PUBLISH_OK=false` before operational exit **1**, so legitimate recovery (`rc-false-recovery`, `local-recovery`) is covered by tests and behaves correctly; the gap is only theoretical for catastrophic exits with no envelope.

- **Pre-existing:** The failed-publish recovery path at `scripts/design-pause-save.sh:203-204` always appends a Tool Failures entry even when a valid `RECOVERY_BRANCH` yields `PAUSE_OK=true`; that can look like a hard failure in logs despite a resumable pause marker.

- **Test gap (not a code defect):** `test-design-pause-resume.sh` covers exit **1** + `PUBLISH_OK=false` + remote recovery (`rc-false-recovery`) but not the same shape with `larch-log-design-recovery-<RUN_ID>` (local push-failure recovery with exit **1**); code at `206-207` should handle it, but the path is untested.
