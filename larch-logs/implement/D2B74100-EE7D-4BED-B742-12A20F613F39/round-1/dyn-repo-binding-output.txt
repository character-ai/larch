Reviewing branch changes for security around `--repo` binding and validation. Reading the precomputed diff and commit history.
### In-Scope Findings

- **security** `scripts/design-pause-save.sh:82-125` — The branch persists `REPO` into `$DESIGN_TMPDIR/source-env.sh` via `design-init-runparams.sh` → `write-design-current-env.sh` (see `skills/design/scripts/design-init-runparams.sh:177`), but `design-pause-save.sh` still **sources** that file before the post-source `validate_repo` at lines 125–127. That diverges from `design-postplan-emit.sh`, which deliberately uses awk-only `export REPO=` extraction and documents that sourcing `source-env.sh` runs arbitrary shell (`skills/design/scripts/design-postplan-emit.sh:200-207`). Under the documented same-UID session-tmpdir trust model, a writer who controls `source-env.sh` can execute code at source time and still supply a syntactically valid `OWNER/REPO` that passes `validate_repo`, redirecting `gh issue view`, `design-log-publish.sh`, and pause-marker writes (`named-block-write.sh` at `scripts/design-pause-save.sh:223-229`) within the operator token’s scopes. **Suggested fix:** Stop sourcing `source-env.sh` for binding fields; mirror `_postplan_resolve_repo` / `_postplan_resolve_issue` (awk-only reads of `export REPO=` and `export SESSION_ID=`) and only then call `validate_repo` before any `gh` or publish work, or split session env into a non-executable KV file that all pause/publish paths read consistently.

- **security** `skills/design/SKILL.md:321` — Step 0b still fetches the issue with `gh issue view "$ISSUE_NUMBER"` **before** `REPO` is resolved in the same sub-step, and without `${REPO:+--repo "$REPO"}`. Later sub-steps (route driver, clarify publish, pause checks, Step 5c) now thread `--repo` heavily, so a hub-default mismatch can load the wrong issue body into `$DESIGN_TMPDIR/issue-body.txt` while subsequent mutations target another repository once `REPO` is bound. That is a cross-repo data-integrity risk the branch amplifies rather than introduces. **Suggested fix:** Resolve and validate `REPO` first (same rules as `validate_repo`), persist it via `write-design-current-env.sh`, then run the initial `gh issue view` with explicit `--repo "$REPO"` (or fail closed if `REPO` cannot be resolved).
