### In-Scope Findings

- **correctness** `skills/design/SKILL.md:463-466` — Step 0b clarify publishes in one Bash subshell (sub-step 3), but sub-step 6 runs the shared Final summary fence in a **new** subshell that only does `export DESIGN_LOG_PR_NUMBER="${DESIGN_LOG_PR_NUMBER:-}"` (and siblings). Values parsed from `_publish_out` in sub-step 3 are not written to `$DESIGN_TMPDIR` (unlike Gate C, where `design-publish.sh` exports `DESIGN_LOG_*` in-process before calling `render-final-summary.sh`). On `SUMMARY_OUTCOME=failed-publish`, clarify summaries can omit recovery PR/branch notes even when publish stdout carried `PR_NUMBER` / `RECOVERY_BRANCH`. **Suggested fix:** Persist publish metadata in sub-step 3 (e.g. append to `$DESIGN_TMPDIR/.design-publish-result.env` or a small `design-log-publish-meta.env`), and have the Final summary fence source that file before `render-final-summary.sh`, mirroring the Step 5c driver contract.

- **correctness** `skills/design/SKILL.md:1549-1555` — After FINDING_4, `design-publish.sh` renders `publish-skipped` when `SESSION_ID` is empty, but Step 5d still uses the **success** footer (`plan written to issue #<N>; NEXT REQUIRED: continue`) whenever `SESSION_ID` is empty or `PUBLISH_OK=true`. Failed publish correctly gets a distinct “log publish incomplete” footer. Empty `SESSION_ID` therefore yields an honest `publish-skipped` summary plus a success-class footer and allowed Step 6 cleanup, which misaligns terminal signals. **Suggested fix:** Add a third footer branch for `publish-skipped` (empty `SESSION_ID` after plan write), e.g. “plan written; design log publish skipped (no SESSION_ID)”, and gate cleanup/footer text on that outcome the same way failed publish is gated.
