Reviewing the branch diff and summary-rendering contracts between the render scripts.
### In-Scope Findings

- **architecture** `skills/design/scripts/design-publish.sh:299-360` — On a non-zero `design-log-publish.sh` exit, the new fail-closed branch clears `PR_NUMBER`, `PR_URL`, and `RECOVERY_BRANCH` whenever stdout already said `PUBLISH_OK=true`, then exports empty `DESIGN_LOG_*` into `render-final-summary.sh`. That breaks the `failed-publish` summary contract: `append_failed_publish_notes` in `render-final-summary.sh` (lines 322–337) can only emit recovery bullets when those env vars survive, and the harness only checks recovery forwarding for honest `PUBLISH_OK=false` (`test-design-publish.sh:331-350`), not for the contradictory-envelope case (`387-412`). Operators can get a `failed-publish` summary with generic recovery prose but no flush PR / recovery branch even though publish stdout may have carried real recovery metadata. **Suggested fix:** On non-zero exit with stdout `PUBLISH_OK=true`, force `PUBLISH_OK=false` and log the failure, but keep parsed `PR_*` / `RECOVERY_BRANCH` (after `sanitize_publish_metadata`) unless you have evidence the stdout envelope is untrusted; add a harness assertion that `DESIGN_LOG_RECOVERY_BRANCH` / flush PR lines appear in `final-summary.md` for that stub mode.

- **architecture** `skills/design/SKILL.md:466` vs `skills/design/scripts/design-publish.sh:352-354` — `publish-skipped` and the explicit “Publish skipped” note are wired only on the Gate C `design-publish.sh` path when `SESSION_ID` is empty. Step 0b clarify sub-step 6 still routes empty `SESSION_ID` to `cancelled-clarify`, so the same “publish never ran” condition produces different outcomes and notes depending on exit path (`cancelled-clarify` has no skip note; `publish-skipped` does in `render-final-summary.sh:357-358`). That splits the shared `render-final-summary.sh` / `render-run-summary.sh` contract across callers and weakens FINDING_4’s “honest skip” goal for clarify-only exits. **Suggested fix:** Either use `publish-skipped` (and the skip note) whenever publish was skipped with empty `SESSION_ID`, including clarify sub-step 6, or document clarify as intentionally different and add a clarify-specific note branch in `render-final-summary.sh` for `cancelled-clarify` when publish was skipped.

- **architecture** `skills/design/scripts/design-publish.md:24-27,52` vs `skills/design/scripts/design-publish.sh` — The branch updates publish/summary behavior in code and adds a “fail-closed / publish-skipped” note in `design-publish.md`, but the normative ordering still requires `render-final-summary.sh --pre-publish-only` before publish while the driver only invokes `--post-publish-only` and `test-design-publish.sh` explicitly forbids a pre-publish render on the happy path. That leaves two competing contracts for the design ↔ shared-renderer boundary (two-phase pre/post vs single post-outcome render). **Suggested fix:** Align `design-publish.md` and `render-final-summary.md` “Publish-tail render behavior” with the single post-publish invocation in `design-publish.sh`, or restore the pre-publish call if the two-phase model is still required (e.g. cost preservation in `render_or_fallback`).

### Out-of-Scope Observations

- **architecture** `scripts/design-pause-save.sh:223-226` — The pause path applies the same “non-zero exit + stdout `PUBLISH_OK=true` ⇒ clear `RECOVERY_BRANCH`” rule, which is stricter than the summary-only issue and can block resumable pause when recovery metadata was only on stdout; worth aligning with whatever fix you choose for `design-publish.sh`.

- **architecture** `skills/implement/scripts/write-final-report.sh:462` and `skills/implement/scripts/write-final-report.md:5` — Implement’s degraded fallback still documents/emits Outcome bullets only for `failed-*`, not `publish-skipped`; harmless today because `/implement` does not use that outcome, but the shared `render-run-summary.sh` enum is now wider than the implement fallback mirror.

- The dual `RUN_LOGS_PATH` guards in `render-final-summary.sh:295-298` and `render-run-summary.sh:221-224` correctly suppress synthetic `larch-logs/design/unknown/` and fake paths on `failed-publish` / `publish-skipped`; primary and degraded design paths are covered in `test-render-final-summary.sh` and `test-render-run-summary.sh`. No regression found for approved real run ids still synthesizing log paths when `--run-logs-path N/A`.
