Reviewing branch changes with a security focus on `--repo` handling and related validation paths.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/design-publish.sh:218-231` — Step 5c resolves `REPO` (from `--repo`, `resolve-repo.sh`, or `gh repo view`) and then uses it for `design-log-publish.sh`, `upsert-diagrams-comment.sh`, `tracking-issue-write.sh`, and `render-final-summary.sh`, but the `plan-block-write.sh` call on line 231 omits `${REPO:+--repo "$REPO"}`. When the design session targets a non-default repository (fork/upstream split, consumer clone with a different `gh` default), `named-block-write.sh` falls back to `gh repo view` in the cwd and can write `larch:plan` to the wrong repo’s issue with the same numeric id. This branch amplifies exposure by persisting `REPO` in `source-env` and threading it across Step 0b/clarify/pause while leaving the Gate C plan write unbound. **Suggested fix:** Forward `${REPO:+--repo "$REPO"}` on the `plan-block-write.sh` invocation (and add a harness case where `REPO=other/owner` proves the plan block lands on that repo, not the hub default).

- **security** `scripts/design-log-publish.sh:82-88` — FINDING_11 adds `validate_repo` here, but it is weaker than `scripts/design-pause-save.sh:18-24` (no rejection of `--*` prefixes or backslashes). A value like `--attacker/org` matches the log-publish regex and reaches `gh --repo "$REPO"`; pause-save would reject the same argv early. The branch introduces both validators together, so the mismatch is a new inconsistent trust boundary across publish entrypoints. **Suggested fix:** Extract one shared `validate_repo` (or copy the pause-save `case` arms verbatim into `design-log-publish.sh`, `design-publish.sh`, `design-postplan-emit.sh`, and `write-design-current-env.sh`) so every `--repo` path rejects the same malformed shapes before any `gh` call.

- **security** `scripts/write-design-current-env.sh:114-117` with `skills/design/scripts/design-init-runparams.sh:177` — PLAN_FINDING_5 now persists `REPO` into `source-env.sh` / `current-design-env`, but the writer only checks the `OWNER/REPO` regex (no newline/`..`/`/*`/`--` guards). Values such as `../repo` can be written to session env; stricter readers (`design-pause-save.sh`) reject them on load, but weaker consumers (e.g. `render-final-summary.sh` `issue_url_from_repo`, which only tests `*/`) can still synthesize misleading `https://github.com/...` links. **Suggested fix:** Use the same strict `validate_repo` before `build_export REPO` in `write-design-current-env.sh`, and reject invalid values at init time in `design-init-runparams.sh` before persistence.

### Out-of-Scope Observations

- `scripts/named-block-write.sh:27-40` does not validate `--repo` format before `gh issue view` / `gh issue edit`; that predates this branch. Clarify flow in `skills/design/SKILL.md` now passes `--repo` explicitly; Gate C `design-publish.sh` does not.

- Positive: `sanitize_publish_metadata` in `design-publish.sh` (PR number/URL/recovery-branch validation), awk-only `REPO` reads in `design-postplan-emit.sh` (no `source` of untrusted `source-env.sh`), argv-before-source validation in `design-pause-save.sh`, and the structural `(27c)` scan for pause-check `${REPO:+--repo "$REPO"}` forwarding are sound hardening aligned with the plan.
