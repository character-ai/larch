Reviewing pause/resume recovery changes: reading the diff and key implementation files.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/design-postplan-emit.sh:210-222` — Internal pause during Step 2b (and other post-plan re-emits) calls `validate_repo` on the resolved `_repo` before `design-pause-save.sh`, but `validate_repo` ends in `fail` (exit **2**). A malformed `export REPO=...` in `source-env.sh` therefore aborts `design-postplan-emit.sh` without exec’ing pause-save, without writing `POSTPLAN_EMIT_STATUS=paused`, and without clearing `$DESIGN_TMPDIR/.pause-requested`. The operator’s pause request stays armed and the run hits a hard configuration error instead of the structured `PAUSE_OK=false` / `ERROR=invalid-repo` path that direct pause-save provides. **Suggested fix:** On invalid resolved repo at the pause checkpoint, either call `design-pause-save.sh` (so it can `emit_fail invalid-repo`), or remove `.pause-requested`, emit a clear `WARN`, and write a failed postplan result env—do not `exit 2` while the sentinel remains.

- **risk-integration** `scripts/design-pause-save.sh:561-564` — The new contradictory-envelope guard (`publish_rc ≠ 0` and stdout `PUBLISH_OK=true`) forces `PUBLISH_OK=false` but also blanks `RECOVERY_BRANCH=""` before the failed-publish handler. The plan text says to fall through to the existing recovery branch logic; clearing `RECOVERY_BRANCH` is stricter than the `rc-false-recovery` path (`PUBLISH_OK=false` + valid `RECOVERY_BRANCH` ⇒ resumable marker). Today’s `design-log-publish.sh` should not emit that combination, but any future stdout/exit mismatch that includes a valid recovery branch would lose the only resumable hint and end at `publish-and-recovery-failed` with no issue marker—opposite of the recovery-preservation goal. **Suggested fix:** On contradictory envelope, set `PUBLISH_OK=false` only; keep `RECOVERY_BRANCH` and run the same slug validation branch used when `PUBLISH_OK=false` (mirror `skills/design/scripts/design-publish.sh:299-306` if you change both call sites).

### Out-of-Scope Observations

- **risk-integration** `scripts/design-pause-save.sh:557-568` — `log_failure` only attaches `publish_err`, not `publish_out`, so stdout lines such as `RECOVERY_BRANCH=` may be missing from `execution-issues.md` during failed pause publishes; recovery metadata still lands in the issue marker when the slug matches. Pre-existing pattern, not introduced by the contradictory-envelope block alone.

- **correctness** `skills/design/scripts/design-postplan-emit.sh:20-25` vs `scripts/design-pause-save.sh:18-23` — `validate_repo` in postplan does not reject backslashes; pause-save does. Unlikely in practice but slightly inconsistent across pause entry points.

- Recoverable publish failures with `PUBLISH_OK=false` and a valid `RECOVERY_BRANCH` still reach `PAUSE_OK=true`, `WARN=recovery-branch-only`, and a marker with `LOG_RECOVERY_BRANCH` (`test-design-pause-resume.sh` `rc-false-recovery`; `design-pause-load.sh:180-214`). Contradictory `rc-ok-false` correctly blocks markers. Repo forwarding in `SKILL.md`, `design-init-runparams.sh`, and postplan pause tests (`D11`/`D11a`/`D11b`) matches the intended non-default-repo binding.
