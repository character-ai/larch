Reviewing the branch diff and tracing publish/pause/clarify state transitions for correctness issues.
### In-Scope Findings

- **correctness** `skills/design/SKILL.md:463-466` — Step 0b clarify sub-step 3 tells the orchestrator to set `DESIGN_LOG_PR_NUMBER`, `DESIGN_LOG_PR_URL`, and `DESIGN_LOG_RECOVERY_BRANCH` from publish stdout, and sub-step 6 runs the shared Final summary fence (`skills/design/SKILL.md:552-560`), which only re-exports `${DESIGN_LOG_*:-}` from the **current** Bash subshell. Claude Code does not preserve shell variables across separate Bash tool calls, and clarify does not use `design-publish.sh` (which exports those vars in-process before calling `render-final-summary.sh`). On a clarify path with non-empty `SESSION_ID` and failed publish, `SUMMARY_OUTCOME=failed-publish` can render without PR/recovery bullets even though sub-step 3 parsed them. **Suggested fix:** In the clarify publish Bash block, persist recovery fields to a tmpdir artifact (for example `$DESIGN_TMPDIR/design-log-recovery.env` or `export` lines appended to `source-env.sh`) and have the Final summary fence source that file before calling `render-final-summary.sh`, mirroring the Gate C driver contract.

- **correctness** `skills/design/SKILL.md:71` (canonical prelude, repeated at many Step boundaries) — The pause prelude uses `exec design-pause-save.sh` when `.pause-requested` exists. On failure paths such as `ERROR=invalid-repo`, `design-pause-save.sh` exits 0 with `PAUSE_OK=false` and does **not** remove `.pause-requested` (`scripts/design-pause-save.sh:266` runs only after success). Every later Bash block hits the same prelude again, so a bad persisted `REPO` (now rejected by new `validate_repo` in `design-pause-save.sh:91-114`) traps the run in a repeat pause attempt with no SKILL guidance to abort or clear the sentinel. **Suggested fix:** Either stop using bare `exec` and parse `PAUSE_OK`/`ERROR` to halt `/design` and surface the error, or remove `.pause-requested` on terminal pause-save failures, or add explicit orchestrator handling for `invalid-repo` / `publish-failed` after a non-success pause-save exit.

- **correctness** `skills/design/scripts/design-postplan-emit.sh:219-230` — On internal pause with a malformed resolved repo, the driver writes `POSTPLAN_EMIT_STATUS=paused` into `.design-postplan-emit-result.env` via `_postplan_write_result_and_emit` while leaving `VALIDATE_STATUS` empty, then emits `PAUSE_OK=false` / `ERROR=invalid-repo` on stdout without calling `design-pause-save.sh`. `skills/design/SKILL.md:939-943` treats an empty `VALIDATE_STATUS` as a hard abort (“result env missing/unreadable”), which misreports the failure if this path is reached with `.pause-requested` still set (for example direct/harness invocation or a future call site without the prelude). **Suggested fix:** Do not write `POSTPLAN_EMIT_STATUS=paused` when repo validation fails; use a distinct status such as `pause-failed` with populated mandatory keys, or skip the result-env write and emit only structured stdout errors.

### Out-of-Scope Observations

- **correctness** `skills/design/scripts/design-publish.sh:348-352` and `skills/design/SKILL.md:1529` — Writing `.completed/step-5c` when `SESSION_ID` is empty (`publish-skipped`) is intentional per the plan, but it means resume will not return to Step 5c publish if `SESSION_ID` was empty once and is later fixed in session env; only relevant if empty `SESSION_ID` was accidental.

- **risk-integration** `scripts/design-pause-save.sh:223-226` — Forcing `PUBLISH_OK=false` and clearing `RECOVERY_BRANCH` on non-zero exit with stdout `PUBLISH_OK=true` is fail-closed; if a buggy publisher ever emitted both, recovery metadata would be discarded (narrow; post-push failures normally emit `PUBLISH_OK=false` with `RECOVERY_BRANCH`).

The Gate C publish path (`design-publish.sh:301-356`, `skills/design/SKILL.md:1529-1530`) correctly fail-closes non-zero publish exits, withholds `step-5c` on failed publish, maps empty `SESSION_ID` to `publish-skipped`, and preserves recovery metadata in the driver-mediated summary path. Tests in `test-design-publish.sh`, `test-design-pause-resume.sh`, and `test-render-final-summary.sh` cover those behaviors for the scripted paths.
