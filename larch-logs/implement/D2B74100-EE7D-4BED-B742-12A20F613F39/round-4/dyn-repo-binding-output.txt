### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:885-887` — Step 2b still invokes `design-postplan-emit.sh` without `${REPO:+--repo "$REPO"}` even though the prelude pause-check on the line above uses shell `REPO` from `current-design-env-$PPID.sh`. The driver only learns repo from its `--repo` argv or an awk read of `$DESIGN_TMPDIR/source-env.sh` (`skills/design/scripts/design-postplan-emit.sh:200-207`), not from the exported shell variable. If `source-env.sh` is missing or stale while the session already resolved a non-default repo for issue fetch, an internal `.pause-requested` pause during Step 2b can call `design-pause-save.sh` / `design-log-publish.sh` against the hub-default repo while the rest of the run targets another repository. **Suggested fix:** Forward `${REPO:+--repo "$REPO"}` on every `design-postplan-emit.sh` invocation in `skills/design/SKILL.md` (Step 2b, Gate B, Gate A re-entry, `references/approval-gates.md`), matching Step 5c and the pause-check prelude.

- **risk-integration** `scripts/clarify-state.sh:26-38`, `scripts/clarify-comment-post.sh:28-40`, `scripts/clarify-label.sh:28-40` — This branch tightens `--repo` validation on `design-log-publish.sh`, `design-pause-save.sh`, and `named-block-write.sh`, and expands clarify routing in `skills/design/SKILL.md` to thread `${REPO:+--repo "$REPO"}` through clarify helpers. Those clarify scripts still pass caller `--repo` straight through `resolve_repo()` with no `OWNER/REPO` grammar check before `gh issue view`, `gh issue comment`, or `gh api repos/${REPO}/issues/...`. A malformed repo string therefore still reaches GitHub on the clarify path even though publish/pause paths now fail closed. **Suggested fix:** Add the same `validate_repo` guard used in `design-pause-save.sh` to `clarify-state.sh`, `clarify-comment-post.sh`, and `clarify-label.sh` immediately after argv parse (fail before any `gh` call), or route clarify through a shared validated resolver.

- **risk-integration** `scripts/design-pause-load.sh:78-107` — `design-pause-load.sh` accepts `--repo` but does not validate argv before the first `gh issue view "$ISSUE" "${gh_repo_args[@]}"` (line 107). Validation only happens later for `MARKER_REPO` from the pause payload (`scripts/design-pause-load.sh:142-147`). The branch adds stricter repo validation elsewhere and documents pause binding in `SECURITY.md`, which makes this loader gap more visible: a direct or future caller with a malformed `--repo` can hit the wrong or failing `gh` target before marker comparison. **Suggested fix:** Validate `--repo` at entry with the same `OWNER/REPO` rules as `design-pause-save.sh`, and only build `gh_repo_args` after validation succeeds.

If a buggy publisher ever emitted both `PUBLISH_OK=true` and a valid `RECOVERY_BRANCH` on exit 1, pause-save would drop resumable log-recovery state instead of normalizing only `PUBLISH_OK`.
