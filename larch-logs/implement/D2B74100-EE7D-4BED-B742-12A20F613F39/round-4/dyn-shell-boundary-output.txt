### In-Scope Findings

- **security** `scripts/design-pause-save.sh:101-117` — Replacing `source "$DESIGN_TMPDIR/source-env.sh"` with `source_env_get` removes arbitrary-code execution from a tampered env file, but `SESSION_ID` / `RUN_ID` taken from that file are not validated before they are written into `pause-state.txt` and passed to `design-log-publish.sh` (`--run-id "$RUN_ID"`). A writable or attacker-controlled `source-env.sh` can supply values containing newlines or other delimiter-breaking characters; those values are emitted with bare `printf 'SESSION_ID=%s\n'` / `printf 'RUN_ID=%s\n'` into pause state (lines 183–187) before `redact-secrets.sh`. `design-pause-load.sh` rejects malformed run ids on resume, but a poisoned `larch:design-pause` block can still land on the GitHub issue and confuse operators or tooling. **Suggested fix:** After merging `SESSION_ID` from `source_env_get`, enforce the same constraints as `write-design-current-env.sh` / `design-pause-load.sh`: reject embedded newlines/CR (`validate_plain_value`-style), then require `larch_log_slug_is_valid "$RUN_ID"` (and optionally the `^[A-Za-z0-9_.-]{1,128}$` bound) before any `printf` into `state_tmp` or publish argv construction.
