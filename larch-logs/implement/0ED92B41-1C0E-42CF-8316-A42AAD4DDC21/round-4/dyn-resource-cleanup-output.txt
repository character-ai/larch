### In-Scope Findings

- **correctness** `python/checks.py:312-316` — `_allocate_log_file` opens `log_fd` with `os.open`, then `runner.run([...])` runs **before** the `try`/`os.fdopen` block. If `runner.run` raises anything other than returning a `CommandResult` (e.g. `RuntimeError` from a test stub, timeout wrapper, or future `check=True` caller), the exception bypasses the `except OSError` handler at `python/checks.py:343-345` and the descriptor is never closed. Bash avoids this by truncating the log file with `: >` (close immediately) and only redirecting check output afterward in `scripts/run-relevant-checks-captured.sh:171-188`. **Suggested fix:** Wrap allocation through log write in `try`/`finally` (or move `runner.run` before `os.open` and write via `Path.write_text`/`open()` like bash). Ensure `os.close(log_fd)` runs on every exit path when `fdopen` has not taken ownership, e.g. `finally: contextlib.suppress(OSError); os.close(log_fd)` guarded by a flag set once `fdopen` succeeds.

- **correctness** `python/checks.py:1371-1378` — `_redacted_log_for_dispatch` writes the fallback `*.redacted` file and then `chmod(0o600)`. On any `OSError` (including `chmod` failing after a successful `write_text`), it returns `None` but leaves the partially created file on disk. Bash explicitly removes a failed redaction artifact (`rm -f "$REDACTED_LOG_FILE"` in `scripts/run-relevant-checks-captured.sh:229-231`). The same write-then-chmod-without-cleanup pattern exists in `run_relevant_checks` at `python/checks.py:382-397`. **Suggested fix:** In the `except OSError` branch, `unlink(missing_ok=True)` the redacted path before returning; optionally defer `write_text` until after path validation, or write to a temp name and atomically rename after `chmod`.
