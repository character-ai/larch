### Out-of-Scope Observations

The Phase 4 `bash -c` call sites in `python/checks.py` follow the repo’s preferred pattern from `BASH_AUTHORING.md` §2: the script body is a fixed string, and every dynamic value is passed as a separate argv element after the `bash` name argument, so expansion uses quoted positional references (`"$1"`, `"$2"`, `"$@"`) rather than interpolation into the script text.

**`_run_with_serial_lock` (`python/checks.py:566-587`)** — `tool` is only ever `"codex"` or `"cursor"` from callers. `LARCH_EXTERNAL_SERIAL_LOCK_DELAY` is validated with `re.fullmatch(r"[0-9]+(?:\.[0-9]+)?", delay)` before it becomes `$3`, which is stricter than `scripts/lint-fix-loop.sh:242,283` (unvalidated `${LARCH_EXTERNAL_SERIAL_LOCK_DELAY:-0.5}` passed into `sleep "$delay"`). `shift 3` before `exec "$@"` correctly separates lock setup from the nested inner `bash -c` argv.

**`_run_codex` / `_run_cursor` redirect wrappers (`python/checks.py:711-718`, `839-846`)** — `codex_events`, `codex_wrapper_log`, and `cursor_wrapper_log` are fixed filenames under a `tempfile.mkdtemp` directory whose parent is the validated session `lint-fix-loop` dir; `site` is whitelisted via `_is_known_site` before `mkdtemp`. Paths reach the shell only as argv, not embedded in the `-c` string.

**`_load_cursor_launch_argv` (`python/checks.py:628-644`)** — `preflight_log` is passed as `$2` and used only in `2>>"$2"`; a path containing spaces, quotes, or newlines stays a single argv word and does not break out of quoting.

**`_run_cursor` prompt wrap (`python/checks.py:803-812`)** — `prompt_body` (redacted checks log) is `$2` to `cursor-wrap-prompt.sh`, which prints it with `printf '...%s' "$1"` (`scripts/cursor-wrap-prompt.sh:36-39`); no eval or unquoted expansion.

**Non-`bash -c` subprocess usage** — `proc.run` uses `subprocess.Popen` with a list argv and `shell=False` (default). Git/forbidden-path operations use `["git", …, "--", path]` / `["rm", "-f", "--", path]`, which avoids shell metacharacter issues on repo-relative paths from `git diff`.

**Residual (not shell-embedding)** — `run_lint_fix` validates `checks_log` with `is_symlink()` once at entry but does not confine the path to the validated tmpdir; a TOCTOU symlink swap between check and `_compose_prompt` read could leak arbitrary file content into the fixer prompt (information disclosure, not command injection). That class of issue also exists in the bash orchestration model and is outside the scout’s shell-argv focus.
