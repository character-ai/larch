### FINDING_22: **architecture** `python/ship.py:730-755` — `_seed_last_monitored_head` falls through to `return current` whenever `LAST_MONITORED_HEAD` is missing or equals the checkout HEAD, even when `FIX_ATTEMPTS > 0`. On cold resume after a CI-fix push, that seeds `last_monitored_head` to the post-fix SHA, so `post_push_grace` is 0 on the first monitor poll and the driver can still poll “pending” for the full budget instead of using the bounded empty-checks window. This matters for in-flight or pre-migration `ship-pr-state.sh` files that have `FIX_ATTEMPTS` but never got `LAST_MONITORED_HEAD` written (initial seed at `python/ship.py:134-173` omits it; pre-#4867 runs; crash after push but before the loop writes the field). **Suggested fix:** When `fix_attempts > 0` and `persisted` is empty or equals `current`, treat the head as post-push: return `""`, or derive the prior head from `CI_FIX_REBASE_PENDING_HEAD` / branch run-list metadata, instead of `return current`. Add a resume test with `FIX_ATTEMPTS=1`, no `LAST_MONITORED_HEAD`, and `HEAD` at the fix SHA.

### FINDING_23: **architecture** `python/ship.py:1565-1629` — After each monitor call, `last_monitored_head` is updated in memory (`last_monitored_head = current_head`) but terminal bail paths (`_write_terminal_state` at `python/ship.py:418-451`, e.g. `no-ci-checks-observed` at `1619`) never pass `last_monitored_head`, so durable state keeps only the iteration-start value from the `1483-1494` write. That is correct for the common post-push stall (pre-push head in state, post-push HEAD in git). It breaks when the iteration-start write already synced `LAST_MONITORED_HEAD` to the current HEAD (`persisted == current` with `fix_attempts > 0`), because `_seed_last_monitored_head` then returns `current` and disables grace on the next resume. **Suggested fix:** On terminal outcomes that mean “no CI observed for this head” (`CI_WAIT_BAIL_NO_CHECKS_OBSERVED`, and optionally poll-budget exhaustion after post-push grace), persist an explicit pre-monitor head: pass `last_monitored_head=(prior persisted value or pre-push SHA)` into `_write_terminal_state` / `_write_ship_state`, or write `LAST_MONITORED_HEAD` to the head that was current before the monitor poll when grace was non-zero.

### FINDING_29: **correctness** `python/ship.py:730-755` — `_seed_last_monitored_head` has a third branch (`fix_attempts > 0 and persisted and current and persisted != current`) that is unreachable: the first branch uses the same conjuncts and returns first, so the third branch never runs. The real resume gap is the opposite case: after a CI-fix push, state is updated with `LAST_MONITORED_HEAD` equal to the current HEAD (loop writes at `python/ship.py:1493`, monitor updates at `python/ship.py:1565`, continue-path write at `python/ship.py:1720`). On cold resume with `FIX_ATTEMPTS>0`, `LAST_MONITORED_HEAD=h1`, and `HEAD=h1`, seed falls through to `return current`, so `post_push_grace` is 0 at `python/ship.py:1544-1547` and zero-check heads again classify as `pending` for the full poll budget.
