**`set -e` / `emit_kv` path (workstream A)** — The new enumeration paths match the planned fail-safe contract:

- **Guarded `mktemp`**: `if _cache_list=$(mktemp …); then` / `if _tmp_list=$(mktemp …); then` prevents `set -e` from aborting on allocation failure; the `mktemp-allocation-failure-warns` case covers unwritable `TMPDIR` and still expects both removal KVs.

- **Read loops**: `done < "$_list" || true` is required even for an empty enumeration (first `read` returns 1); without it, a successful `find` with zero entries could trip `errexit` before `emit_kv`.
- **Loop body**: `(( … )) || true` on counters is unchanged; `rm -rf` / `rm -f` in the body share the same `set -e` behavior as the pre-change process-substitution loops (not introduced by this diff).

**Temp lifecycle** — On every path where `mktemp` succeeds, `rm -f "$_cache_list"` / `rm -f "$_tmp_list"` runs once at the end of that pass (success, `find` failure, or after the read loop). Allocation-failure branches never create a list file. There is no early `exit` between allocation and `rm -f` in these blocks.

**`mktemp` template** — `${TMPDIR:-/tmp}/larch-cleanup-*.XXXXXX` is Bash 3.2–safe (external `mktemp`, no Bash 4+ features). The trailing six `X` characters satisfy BSD and GNU `mktemp`; the literal `*` is part of the filename prefix, not a glob. This matches the plan and is exercised on Darwin in CI via `test-cleanup.sh`.
