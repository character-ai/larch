### FINDING_8: PATH_PREFIX can leak across test-cleanup.sh cases after assert failure
- **Reviewer(s)**: dyn-test-env-isolation-output.txt
- **Severity**: latent
- **Concern**: In `test-cleanup.sh`, `assert_eq`, `assert_contains`, and `kv_get` call `fail` → `exit 1`, so a failed assertion aborts the harness before trailing `unset PATH_PREFIX` in the new enumeration cases. `enumeration-failure-warns-tmp` sets `PATH_PREFIX` immediately before `mktemp-allocation-failure-warns`, which never sets `PATH_PREFIX`; `run_cleanup` prefers a leaked shell `PATH_PREFIX` over per-case `$work/bin`. If `enumeration-failure-warns-tmp` fails after setting `PATH_PREFIX` but before `unset`, the next case can run `cleanup.sh` with the enumeration-failure stub still on `PATH`, causing wrong failures/flakes.
- **Suggested revisions (informational for voters; coder decides)**:
  - From dyn-test-env-isolation-output.txt: Move `unset PATH_PREFIX` to immediately after each `run_cleanup` (before any assertion), or wrap each stubbed case in a subshell / `trap 'unset PATH_PREFIX' RETURN` so teardown runs even when `fail` exits. The `mktemp-allocation-failure-warns` block already does the right thing for `TMPDIR`/`chmod` (lines 244–245 run before assertion failures at 246+).
