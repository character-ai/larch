### In-Scope Findings

- **correctness** `python/changelog.py:24-25,317-318,416-417,550-551,609-618` — Changelog heading dates use `datetime.now(tz=UTC).date()`, while `lib-changelog.sh`, `commit-changelog.sh`, and `apply-bump.sh` use `date +%Y-%m-%d` (the process local timezone). On a machine where local date ≠ UTC date, Python writes `## [X.Y.Z] - YYYY-MM-DD` / `Version X.Y.Z (YYYY-MM-DD)` with a different calendar day than bash for the same run, so byte-level parity with the shell scripts fails and Phase 7 could emit different CHANGELOG headings than the live path. **Suggested fix:** Match bash by using local date (e.g. `datetime.now().astimezone().date().isoformat()`), or inject a shared `today` callable in tests and document that CI assumes UTC if you intentionally standardize on UTC everywhere.

- **correctness** `python/changelog.py:512-527` — For extensionless conflict paths, `auto_resolve` picks Markdown vs RST via `detect_format(ours_result.stdout, path=conflict_path)`, which only inspects the `:2:` (ours) side. `auto-resolve-changelog.sh` uses both stages: if either side has `## ` headings, it requires matching first headings or exits without merging; otherwise it uses RST. When ours has no `## ` but theirs does (or first headings differ), bash refuses; Python may still run `_auto_resolve_rst` on both bodies and can return `True` or `False` on a different code path than the awk script. **Suggested fix:** Port the extensionless branch from `auto-resolve-changelog.sh` (lines 182–195): consider both `:2:` and `:3:` for `md_has_any_l2_heading` / first-heading equality before choosing the merge mode.
