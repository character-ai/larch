Checking one more edge case: doc-title skip when the only other section is a release heading.
Tracing insert behavior against `RST_SAMPLE` to confirm structure.
### In-Scope Findings

- **correctness** `python/changelog.py:441-448` — `_insert_rst_after` always splices the new block at `anchor + 2` (immediately after the anchor section’s underline). `_write_rst_entry` uses `_rst_merge_first_index` as the anchor, which for `RST_SAMPLE` is `Unreleased` (line 3), not the first release block. On that fixture the insert lands between the `Unreleased` header and its body (`Changed` / `~~~~~` / `- Pending`), so the new `Version 1.1.0` section is placed inside what should still be the Unreleased section, ahead of the real release list. That diverges from Markdown `write_changelog_entry`, which inserts after the full Unreleased section (or before the first `## [semver]` heading). `test_rst_write_and_drop` only checks that `Version 1.1.0` appears somewhere and can be dropped, so it does not catch the broken structure. **Suggested fix:** Compute the insert index from the anchor section’s end (scan to the next `_rst_release_section_indices` entry, or the next `_rst_title_indices` title after `anchor + 2`), and splice there—before the first release section when the anchor is `Unreleased`/intro, and before the anchor title when inserting a newer release above an existing one. Add a unit test on `RST_SAMPLE` that `Changed` / `- Pending` remain directly under `Unreleased` and `Version 1.1.0` sits above `Version 1.0.0`.

- **correctness** `python/changelog.py:417-418,137-147` — `_write_rst_entry` builds new release underlines with `"=" * len(title)`, while `_rst_merge_first_index` treats any first `_rst_title_indices` entry whose underline is all `=` as a document title and, when `len(indices) >= 2`, moves the anchor to `indices[1]`. That matches `auto-resolve-changelog.sh`, but it conflicts with the writer’s own output: a changelog with no leading `====` document title whose first section is a Python-written release will have that release misclassified as a doc title on the next operation, so write/merge anchor on the wrong section (or `no anchor` when only one `=` section exists). **Suggested fix:** Use the same adornment as existing release sections (e.g. `-` in `RST_SAMPLE`) for new entries, and/or restrict doc-title skip to a known document title (e.g. title line `Changelog` or only when `indices[0]` is not a `_rst_release_section_indices` hit); add a fixture with no doc-title block and two `Version …` sections to lock anchor behavior.

### Out-of-Scope Observations

- `is_rst_adornment`, `_rst_title_indices`, `_rst_merge_first_index` (including single-section vs doc-title skip), `_auto_resolve_rst` (title+underline in output; merge window `fh2+2:end2` with `end2 == second2`), and `_drop_rst_section` (section boundary at the next release index) align with `scripts/auto-resolve-changelog.sh` for the cases checked; no separate defect found on underline length, leading-space underlines, or merge-window off-by-one.

- `test_rst_write_and_drop` does not assert document structure after insert; stronger ordering assertions would have caught the `_insert_rst_after` bug.
