Reviewing RST parsing in the branch diff and `changelog.py`, comparing slice boundaries and format-detection paths.
### In-Scope Findings

- **correctness** `python/changelog.py:454-461` — `_auto_resolve_rst` computes `end2 = second2 - 1` and slices `ours[fh2 + 2 : end2]`, which excludes the last body line before the next RST section. `_extract_rst_body` at `python/changelog.py:248-254` uses `end = idx` (next title index) and `lines[body_start:end]`, which includes that line. Bash `auto-resolve-changelog.sh` uses 1-based inclusive `end2 = sh2 - 1` with `for (i = fh2 + body_off; i <= end2; i++)` (`body_off = 2`), which maps to Python exclusive `end2 = second2`, matching the Markdown branch at `python/changelog.py:423-429` (`end2 = sh2`). The RST merge path therefore drops the final pre-heading line (often a trailing blank or last bullet) and can fail tail union when that line differs between stages. **Suggested fix:** Set `end2 = second2 if second2 > 0 else len(ours)` (and the same for `end3`), mirror the Markdown resolver, and add an RST `auto_resolve` unit test with a blank line before the second section title to lock parity with `scripts/auto-resolve-changelog.sh`.

- **correctness** `python/changelog.py:146-150` — `duplicate_version_heading_count` for `ChangelogFormat.RST` only increments when `line == version` or `line.startswith(f"## [{version}]")`. The `## [...]` branch is Markdown-only; it does not detect titles written by `_write_rst_entry` (`Version {version} ({date})` at `python/changelog.py:376-377`). `_write_rst_entry` at `python/changelog.py:386-390` relies on this for duplicate detection, so a second insert of the same version in standard RST layout can pass with count 0 while a section already exists. **Suggested fix:** Align RST duplicate detection with `_drop_rst_section` / `_extract_rst_body` title rules (e.g. `line.startswith(f"Version {version}")`, semver in brackets, bare semver title) and drop the Markdown `##` check from the RST branch; add a unit test on `RST_SAMPLE` in `python/test_changelog.py` that expects count ≥ 1 for `1.0.0`.

- **correctness** `python/changelog.py:191-214` — `_extract_rst_body` ends the section at the next index from `_rst_title_indices`, which treats every adornment-underlined line (including subsections like `Changed` / `Fixed` in `python/test_changelog.py:55-74`) as a section boundary. For `Version 1.0.0 (...)` the next index is often a subsection title, not the next release, so the extracted body is empty or truncated and `extract_version_body` returns `None` despite content under nested headings. `_drop_rst_section` at `python/changelog.py:239-259` has the same boundary logic, so drop can leave orphaned subsection lines. **Suggested fix:** Port bash `rst_second_title_index`’s `fh + 2` search start and/or restrict boundaries to same-level section titles (e.g. only `Version …` / semver release lines), matching how release sections are authored in `_write_rst_entry`; extend RST extract/drop tests to assert full release bodies including subsections.

- **correctness** `python/changelog.py:195-198` — `_extract_rst_body` locates sections with `lines[idx] == version` or `f"[{version}]" in lines[idx]`, but `_drop_rst_section` at `python/changelog.py:245-248` also matches `lines[i].startswith(f"Version {version}")`. Entries produced by `_write_rst_entry` use the `Version {version} (...)` title form, so extract/drop disagree on the same file. **Suggested fix:** Share one helper for RST version title matching and use it in extract, drop, duplicate count, and `first_version_heading` (which at `python/changelog.py:127-133` also omits `Version …` titles).

### Out-of-Scope Observations

- `scripts/lib-changelog.sh` only implements Markdown duplicate/extract helpers; RST duplicate/extract gaps are not a regression from deleted bash RST editors—RST editing is net-new in this branch.
- `python/test_changelog.py:232-278` has bash parity for Markdown `auto_resolve` only; there is no RST fixture parity test, so the `_auto_resolve_rst` off-by-one would not be caught by current CI parity tests even when bash is available.
- `is_rst_adornment` (`python/changelog.py:61-70`) and `_rst_title_indices` (`python/changelog.py:73-87`) match `scripts/auto-resolve-changelog.sh` for whitespace-skipped titles and underlines at least as long as the title; no defect found there relative to the bash port.
