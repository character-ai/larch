### In-Scope Findings

- **risk-integration** `skills/implement/scripts/write-final-report.sh:115-134` — PR line-count integration treats every helper failure mode (`LINES_STATUS=unavailable` from `gh-failed`, missing/non-executable `compute-pr-line-counts.sh`, empty/malformed KV stdout) identically as `LINES_DATA_OK=false` → `- **Lines (PR diff)**: N/A`, with no `execution-issues.md` breadcrumb. That contrasts with renderer failures in the same script (`append_render_warning` at ~565–575), so auth outages, plugin packaging regressions, and “no PR” all look the same in the final summary and committed run log, weakening post-run diagnosis. **Suggested fix:** After parsing `lines_blob`, when `LINES_STATUS` is not `ok` (or the helper exits non-zero / produces no `LINES_STATUS`), append a `Warnings` entry (and optionally mirror `REASON=` from the helper KV) via `append-execution-issue.sh`; keep rendering `N/A` but make the failure class auditable.

- **risk-integration** `scripts/compute-pr-line-counts.sh:49-56` — `gh api` stderr is redirected to `/dev/null`, so when the GitHub files API fails the helper emits only `LINES_STATUS=unavailable` / `REASON=gh-failed` on stdout while auth, rate-limit, 404, and network errors are discarded. Downstream integration (`write-final-report.sh`) never surfaces that signal, so operators debugging “PR exists but Lines is N/A” cannot distinguish transient API failure from legitimately missing data without re-running `gh` manually. **Suggested fix:** On non-zero `gh_rc`, capture stderr to a temp file and emit a single `larch_err` line with a redacted snippet (or forward stderr into the `Warnings` path from `write-final-report.sh` when `REASON=gh-failed`).

- **risk-integration** `scripts/compute-pr-line-counts.sh:33-42` — `PR_NUMBER` is interpolated into the REST path after only an empty/`0` check; there is no `^[0-9]+$` guard (unlike `ISSUE_NUMBER` validation in `write-final-report.sh:646`). Corrupt or hand-edited `ship-pr-state.sh` / `session-env.sh` values produce odd `gh api` paths that fail opaquely and degrade to `N/A`, with no distinct `REASON=invalid-pr` for integrators or tests to key on. **Suggested fix:** Reject non-digit `PR_NUMBER` before building `endpoint` (emit `LINES_STATUS=skipped` + `REASON=invalid-pr`, exit 0) and add a harness case; optionally mirror the check in `write-final-report.sh` before invoking the helper.
