### In-Scope Findings

- **architecture** `skills/implement/SKILL.md:343-356` — The new `/implement` fence always routes presence through `read-session-env-key.sh --default "false"` before calling the gate, and that helper treats a missing **or empty** durable value as the default (`scripts/read-session-env-key.sh:101-102`). The gate therefore receives `--codex-present false` (non-empty), so `PRESENCE_INPUT_EMPTY` never fires for corrupt `session-env.sh` rows—only for orchestrator flag assembly that still passes `""`. That narrows the new detector well below the acceptance text about “empty resolved values” and duplicates the plan-review concern that defaulting to `false` suppresses the bug-class signal. **Suggested fix:** Either omit `--default "false"` for the two presence keys (let empty values reach the gate), add a `read-session-env-key` mode that distinguishes absent vs empty vs explicit `false`, or document in `skills/implement/SKILL.md` / `scripts/degraded-tools-gate.md` that `PRESENCE_INPUT_EMPTY` is strictly an orchestrator-assembly guard, not durable-env validation.

- **architecture** `skills/design/SKILL.md:313-322` — The `/design` degraded-tools fence sources `. "$DESIGN_TMPDIR/source-env.sh"` but does not export `DESIGN_TMPDIR`, rehydrate via `plugin-root.env`, or use the canonical Step 0 prelude (`current-design-env-$PPID.sh`) that every Step 1c+ block requires (`skills/design/SKILL.md:67-71`). Unlike the `/implement` fence (`skills/implement/SKILL.md:335-341`), this block is not self-contained across a fresh Bash tool call: if the orchestrator only runs the fenced snippet without carrying `DESIGN_TMPDIR` in the subshell environment, sourcing fails or targets the wrong path—the same cross-call state loss class as #3514. **Suggested fix:** Align the design fence with implement: prepend `export DESIGN_TMPDIR=…` (or the canonical two-line prelude), then source `source-env.sh` or the symlink; update `scripts/test-design-structure.sh` to require that prelude, not only the permissive `source-env OR current-design-env` OR.

- **architecture** `skills/design/SKILL.md:313` — The paragraph still says “After the presence parse above,” but the presence parse lives in the Step 0a `session-setup.sh` bash block while the gate lives in a **separate** fenced bash block (`skills/design/SKILL.md:315-322`). That wording re-invites the original failure mode (trusting volatile parse variables instead of durable env) even though the fence correctly sources `source-env.sh`. **Suggested fix:** Replace “presence parse above” with explicit “in a separate Bash block from Step 0a, source durable design env written by `write-design-current-env.sh`” language mirroring `/implement`.

- **architecture** `skills/implement/SKILL.md:338-340` — The degraded-tools prelude rehydrates `CLAUDE_PLUGIN_ROOT` with `awk -F= '$1=="LARCH_CLAUDE_PLUGIN_ROOT"{print $2}'`, but the file’s own Bash-block prelude contract forbids inventing variants and mandates the prefix-safe `BEGIN{p="LARCH_CLAUDE_PLUGIN_ROOT="} index($0,p)==1{…}` pattern (`skills/implement/SKILL.md:110-113`). Values containing `=` or ordering quirks can diverge between this fence and the other 40 rehydration sites. **Suggested fix:** Copy the canonical one-line awk from the Bash block prelude section into the degraded-tools fence (or source `plugin-root.env` only, matching post-Step-0 guidance).

- **architecture** `skills/implement/SKILL.md:332-359`, `skills/shared/external-reviewers.md:35` — The branch adds `PRESENCE_INPUT_EMPTY=true` on stdout and `larch_err` diagnostics on stderr (`scripts/degraded-tools-gate.sh:73-79`, `125-127`), but skill orchestration still only instructs parsing `DEGRADED` / `CODEX_STATE` / `CURSOR_STATE` / `BOTH_DOWN`. Nothing requires the orchestrator to treat `PRESENCE_INPUT_EMPTY` as a hard warning, log it to `execution-issues.md`, or merge stderr into operator-visible output—so the new signal can be lost when only stdout is parsed. **Suggested fix:** Extend the Degraded-tools gate procedure in `skills/shared/external-reviewers.md` and both SKILL fences with a mandatory post-invocation branch: if stdout contains `PRESENCE_INPUT_EMPTY=true`, append a `Warnings` entry (and do not treat the run as a normal outage).
