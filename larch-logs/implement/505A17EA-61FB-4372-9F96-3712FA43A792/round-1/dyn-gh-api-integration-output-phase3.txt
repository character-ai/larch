### In-Scope Findings

- **risk-integration** `scripts/compute-pr-line-counts.sh:44-45` — When `REPO` is empty (resolve-repo failed upstream in Step 0b), `write-final-report.sh` passes `--repo ""` to the helper. The helper's `[ -n "$REPO" ]` guard falls through to `repos/{owner}/{repo}/pulls/${PR_NUMBER}/files`, which relies on `gh`'s implicit git-remote context detection. If the calling shell is not inside the implementation repository (e.g., running from a CI workspace where the CWD is not a git repo), `gh` will fail to expand `{owner}/{repo}` and return a non-zero exit code. The helper correctly maps this to `LINES_STATUS=unavailable` → N/A, so the report still completes. However, the `test-compute-pr-line-counts.sh` case labelled `empty --repo uses placeholder endpoint` only asserts that `gh` was called with the placeholder string — it does not assert that `gh` failure on context resolution produces `LINES_STATUS=unavailable`. This leaves the graceful-failure path of the `REPO=empty + gh-context-fails` scenario untested. **Suggested fix:** Add a test case to `scripts/test-compute-pr-line-counts.sh` that combines `--repo ''`, a non-zero PR number, and `GH_SHIM_FAIL=true`, and asserts `LINES_STATUS=unavailable` and `REASON=gh-failed`. This documents and exercises the exact failure mode rather than relying on the already-covered generic `gh-failed` case (which uses `--repo 'owner/repo'`).

- **risk-integration** `scripts/test-compute-pr-line-counts.sh:1-92` — The gh shim unconditionally returns five rows in a single response, so `gh api --paginate` is never called more than once per test. Multi-page accumulation — where `--paginate` triggers multiple `gh api` calls and appends each page's TSV output to `$tsv_tmp` — is not exercised. If a future `gh` version changes how `--paginate` interacts with `--jq` (e.g., wrapping all pages in an outer array before filtering rather than filtering page-by-page), the awk bucketing would silently break with no test signal. The production code itself is correct given `gh`'s documented `--paginate` + `--jq` semantics, but the test contract does not pin this boundary. **Suggested fix:** Add a shim variant that `gh` writes two batches on successive calls (using a call counter in `GH_SHIM_LOG` length or a dedicated counter file), and assert that the combined counts are summed correctly, documenting that multi-page accumulation is explicitly verified.
