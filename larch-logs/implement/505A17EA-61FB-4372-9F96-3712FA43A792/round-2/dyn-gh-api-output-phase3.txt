### In-Scope Findings

- **risk-integration** `scripts/compute-pr-line-counts.sh:37-43` — `--pr-number` is only skip-guarded for empty and the literal string `"0"`; any other non-integer value (e.g., `"N/A"` or `"false"` if a state-file write misbehaves) passes the guard, is interpolated directly into the API endpoint path (`repos/<REPO>/pulls/N/A/files`), and causes a `gh api` HTTP 422/404. The failure is returned safely as `LINES_STATUS=unavailable`, so there is no fatal regression — but a gratuitous authenticated network round-trip is made before the error is detected. The caller `write-final-report.sh` passes `${PR_NUMBER:-0}` which covers the empty case but not malformed strings from `ship-pr-state.sh`. **Suggested fix:** add a `case "$PR_NUMBER" in *[!0-9]*) printf 'LINES_STATUS=skipped\nREASON=no-pr\n'; exit 0 ;; esac` guard immediately after the empty/zero check (line 35) so non-integer values are rejected before the endpoint is constructed, matching the integer-validation pattern already used in `render-run-summary.sh` (`case "${CODE_ADDED}…" in *[!0-9]*)`).

- **risk-integration** `scripts/compute-pr-line-counts.sh:56` — `gh api --paginate "$endpoint" … 2>/dev/null` fully suppresses `gh` stderr, including authentication-failure messages (e.g., "To authenticate, please run: gh auth login"), scope-inadequacy errors, and rate-limit retry notices. When the call fails, the only observable signal is `LINES_STATUS=unavailable REASON=gh-failed` on stdout, which `write-final-report.sh` silently renders as `- **Lines (PR diff)**: N/A`. The authentication-or-scope failure is therefore completely invisible to the operator — no entry is made to `execution-issues.md` and no stderr diagnostic surfaces anywhere in the final report. For a run where `gh` auth is stale or misconfigured (a realistic condition post-token-rotation), the operator has no actionable information. **Suggested fix:** capture `gh` stderr to a temp variable (e.g., `gh api … 2>"$err_tmp"; gh_rc=$?`) and, on `gh_rc != 0`, forward the captured text to the calling script's stderr channel or emit it as part of the `REASON=` KV (e.g., `REASON=gh-failed` extended with a truncated diagnostic line), so `write-final-report.sh` can append it to `execution-issues.md` under `Warnings`.
