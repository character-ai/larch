### In-Scope Findings

1. **Important** | **correctness** | [`scripts/measure-md-cost.sh:95`](scripts/measure-md-cost.sh) — The Python string literal `fh.write("path\ttier\tbytes...")` parses as `path` + TAB + `ier` + TAB + `bytes`, so the emitted header’s second column is **`ier`**, not **`tier`**, mislabeling the TSV contract and breaking anything that keys off the column name `tier`. The committed [`larch-logs/measure-md-cost/2026-05-18.tsv`](larch-logs/measure-md-cost/2026-05-18.tsv) first line correctly contains `tier` (verified via raw bytes), so that artifact is **not** reproducible from the current script without fixing the literal (e.g. split concatenation `"path\t" + "tier\tbytes\ttokens\tlines\th2_count\n"` or use a raw tab between tokens).

2. **Important** | **risk-integration** | [`scripts/measure-realized-cost.sh:100-106`](scripts/measure-realized-cost.sh) — Skills that appear in timing data but have **no** matching `skills/<name>/SKILL.md` or `.claude/skills/<name>/SKILL.md` are **silently dropped** from the ranked TSV (`continue` with no stderr). A typo slug, renamed skill, or non-file-backed name yields a **plausibly complete-looking report that omits entire workloads** with no signal that data was lost.

3. **Latent** | **correctness** | [`scripts/measure-realized-cost.sh:52-87`](scripts/measure-realized-cost.sh) — `skills_in_run` is a **set**, so each skill is counted **at most once per run directory** even when `timing-report.json` `per_step` lists the same skill on many steps (common for `implement`). `realized_tokens = invocations * tokens_per_invocation` then measures “runs touching this skill × full SKILL size,” not “per-step loads,” which **understates** cost if the intended contract is per-step prompt loads; the sibling doc says timing “identify which skills appeared” but not this dedupe, so consumers can mis-budget.

4. **Latent** | **architecture** | [`scripts/measure-realized-cost.sh:52-54`](scripts/measure-realized-cost.sh) — The loop walks **every** `larch-logs/*/*` directory (not only `implement/`), so any future two-level subtree that happens to carry `manifest.json` / timing files will be folded into the same counters **without** distinguishing run type, which can **mix unrelated semantics** into one ranking if layouts evolve.

5. **Latent** | **risk-integration** | [`scripts/measure-realized-cost.sh:59-83`](scripts/measure-realized-cost.sh) — `except Exception: pass` around timing JSON and manifest fallbacks **swallows parse errors**; a corrupt or schema-shifted `timing-report.json` can yield empty `skills_in_run` and then a **quiet fallback** to manifest-only or nothing, producing thin output that still looks like a successful run.

6. **Nit** | **architecture** | [`scripts/measure-md-cost.sh:93-98`](scripts/measure-md-cost.sh) — If the process dies after `mkstemp` but before `os.replace`, a prefixed `.tmp.measure-md-cost.*` file can remain under `larch-logs/measure-md-cost/` until manual cleanup (low impact for a dev script).

7. **Nit** | **correctness** | [`scripts/measure-ngram-duplication.sh:25-27`](scripts/measure-ngram-duplication.sh) — `LARCH_MEASURE_NGRAM_SIZE` / `MIN_FILES` / `LIMIT` are parsed with `int()` and no floor validation; `ngram_size=0` or negative yields nonsensical ranges or `ValueError` on `ranked[:limit]` if limit negative, which is an avoidable footgun for ad-hoc env overrides.
