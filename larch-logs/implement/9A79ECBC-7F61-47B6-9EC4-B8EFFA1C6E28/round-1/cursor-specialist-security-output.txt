### In-Scope Findings

1. **Important** · **security** · `scripts/measure-md-cost.sh:8-10`, `scripts/measure-ngram-duplication.sh:8-10`, `scripts/measure-realized-cost.sh:8-10`, `scripts/measure-references-heatmap.sh:8-10` — `STAMP` comes from `LARCH_MEASURE_DATE` without validation and is concatenated into `OUT_FILE`, then passed to Python as the final output path. A value such as `../../../../tmp/evil` makes `OUT_FILE` resolve outside `larch-logs/<tool>/`, so `mkdir(..., parents=True)` and `os.replace` can create or overwrite files anywhere the operator can write (clobbering unrelated files if the path is chosen maliciously or by mistake). Restrict the stamp to a safe pattern (for example `^[0-9]{4}-[0-9]{2}-[0-9]{2}$`) or compute the output path in Python with `(out_dir / f"{date}.tsv").resolve()` and assert `out_dir.resolve()` is a prefix of the result.

2. **Important** · **security** · `scripts/measure-ngram-duplication.sh:33-47` — `claude_roots()` appends `@…` targets from `CLAUDE.md` when they end in `.md` and do not start with `/`, but it never rejects `..` segments. A line like `@../outside.md` makes `(repo / rel).is_file()` and `read_text()` follow a path **outside** the repo root, so anyone who can change `CLAUDE.md` on a branch (or a fork PR checkout) can point the script at arbitrary readable `.md` files on disk and pull their content into the n-gram corpus and output. Reject targets containing `..` or `/`, resolve under `repo` with `(repo / rel).resolve()` and require `resolved.is_relative_to(repo)` (or equivalent), or only allow simple basename imports.

3. **Important** · **security** · `scripts/measure-realized-cost.sh:34-42`, `scripts/measure-realized-cost.sh:89-104` — `normalize_skill` returns arbitrary strings from `timing-report.json` / `timing-report.md` / `manifest.json` without stripping path components. Those values are joined as `repo / "skills" / skill / "SKILL.md"` (and the `.claude/skills/…` variant). A committed log row with a skill like `../..` or `foo/../../../secret` makes `pathlib` resolve outside `skills/` or `.claude/skills/`, so tokenization reads unintended files (information disclosure) whenever such a path exists. Allow only a conservative charset (for example `^[a-z0-9-]+$`) or resolve the candidate and verify it stays under the expected skill roots.

4. **Latent** · **risk-integration** · `scripts/measure-realized-cost.sh:112-114`, `scripts/measure-references-heatmap.sh:87-90` — TSV rows embed `skill` and `rel` with `%s` / f-strings without escaping tabs or newlines. Crafted values in logs (or rare git paths) can inject extra columns or rows into the TSV and mislead downstream tooling that assumes one record per line. Sanitize or reject fields containing `\t`/`\r`/`\n`, or use a structured exporter.

5. **Nit** · **code-quality** · `scripts/measure-ngram-duplication.sh:29-30` — `git ls-files` is invoked without `stderr=subprocess.DEVNULL`; in a broken or partial checkout this may spam stderr compared to `measure-md-cost.sh`, which silences it. Align behavior if consistent UX matters.
