### In-Scope Findings

1. **`**Important**` · `risk-integration` · [larch-logs/measure-md-cost/2026-05-18.tsv](larch-logs/measure-md-cost/2026-05-18.tsv):1-1291** — A full date-stamped measurement snapshot is committed (~1.3k rows). That is generated output from the new script, not a contract fixture the plan described, and it balloons the PR diff. **Scenario:** two branches both add or refresh `2026-05-18.tsv`, or contributors repeatedly re-run the tool on the same calendar date, producing noisy merges and stale baselines because CI never regenerates or checks this file. **Fix:** keep `larch-logs/measure-md-cost/` out of version control (`.gitignore`), or commit only when deliberately baselining and document a single-owner refresh process.

2. **`**Latent**` · `risk-integration` · [scripts/measure-md-cost.sh](scripts/measure-md-cost.sh):1-101, [scripts/measure-ngram-duplication.sh](scripts/measure-ngram-duplication.sh):1-80, [scripts/measure-realized-cost.sh](scripts/measure-realized-cost.sh):1-118, [scripts/measure-references-heatmap.sh](scripts/measure-references-heatmap.sh):1-94** — None of the new tooling is exercised by CI: there is no `scripts/test-measure-*.sh`, Makefile target, or workflow step that runs them (only `shellcheck` via pre-commit applies to the thin bash wrappers). **Scenario:** a later edit breaks the embedded Python (JSON shape, glob assumptions, or `tiktoken` usage) and merges green because nothing executes the heredocs. **Fix:** add a minimal smoke harness (e.g. run with `LARCH_MEASURE_DATE` fixed to a temp dir or golden subset) wired into the existing test-harness job, or document explicit “non-CI, human-only” acceptance and accept the blind spot.

3. **`**Nit**` · `risk-integration` · [scripts/measure-realized-cost.sh](scripts/measure-realized-cost.sh):52-74** — The scanner uses `(repo / "larch-logs").glob("*/*")`, so every top-level log family with `manifest.json` / timing artifacts is included, not only `larch-logs/implement/*/` as in the original feature text. **Scenario:** a future `larch-logs/<other>/*/` layout with partial files could skew aggregates compared to reviewers’ mental model. **Fix:** narrow the glob to `larch-logs/implement/*/` if that is the intended corpus, or state explicitly in the sibling `.md` that all run families are intentionally included.

4. **`**Latent**` · `correctness` · [scripts/measure-ngram-duplication.sh](scripts/measure-ngram-duplication.sh):64-69** — Ranking uses `occurrences * ngram_size` (word-count multiplier), while the requirement phrase “occurrences×shingle_length” is ambiguous (character length of the shingle string vs token/word width). **Scenario:** if stakeholders expected character-length weighting, the top-50 list mis-orders long alphanumeric shingles relative to short ones. **Fix:** align the score with the documented definition (characters, words, or bytes) and add a one-line comment or test vector.

5. **`**Latent**` · `correctness` · [scripts/measure-references-heatmap.sh](scripts/measure-references-heatmap.sh):68-76** — `Read` tool names are matched case-sensitively (`tool.get("name") != "Read"`). **Scenario:** transcripts that emit `read` or namespaced variants would be dropped silently, under-counting reads. **Fix:** normalize with `.lower()` or accept a small allowlist after normalizing.
