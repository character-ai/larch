### In-Scope Findings

1. **Important** (`correctness`) [`scripts/measure-realized-cost.sh:56-65`](scripts/measure-realized-cost.sh) and [`scripts/measure-realized-cost.sh:84-85`](scripts/measure-realized-cost.sh): Skills seen in a run are stored in a **set** (`skills_in_run`), so each skill contributes **at most one invocation per run** even when `timing-report.json` `per_step` lists the same skill on many steps (e.g. multiple `implement` rows in real logs). `realized_tokens` then scales with **distinct skills per run**, not step-level skill usage, which understates cost if “invocation” means each step where the skill’s prompt could matter. **Fix:** Count invocations from `per_step` with a `Counter` (and merge MD parsing similarly) instead of deduplicating with a set, or document and implement explicitly as “runs touching skill”.
