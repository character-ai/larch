### In-Scope Findings
- **correctness** `skills/review/scripts/aggregate-findings.sh:282-283` — `normalize_slot` uses a single trailing match `\s*\([^)]*\)\s*$`, so any reviewer suffix whose parentheses are not one flat `(…)` group fails to strip: nested cases such as `cursor-a-output.txt (via C.2 (gap))` leave `)` unmatched at the end, so `re.sub` does nothing and the token still fails the `input_slot_set` membership check, causing false `validation-failed` even though the base slot is correct. **Suggested fix:** Either document this as an unsupported shape and keep tests only for the flat suffix, or normalize with a loop/repeated suffix strip, or use a safer rule (for example strip only known prefixes like ` (via …)` or repeatedly apply the suffix pattern until stable while guarding against infinite loops).

- **correctness** `skills/review/scripts/aggregate-findings.sh:282-283` — The same one-shot suffix removal means tokens with two stacked flat annotations, e.g. `file.txt (note1) (note2)`, normalize once to `file.txt (note1)`, which will not match an input key `file.txt`, so validation can still fail for plausible LLM output even though the doc claims stripping of a trailing parenthetical. **Suggested fix:** Apply `normalize_slot` in a `while` loop until the string stops changing (with a small iteration cap), or strip all trailing `\s*\([^)]*\)` segments in a bounded loop, and add a regression test for `slot (a) (b)` if that output is considered valid.
