### In-Scope Findings

- **correctness** `skills/review/scripts/aggregate-findings.sh:282-283` — `normalize_slot` uses `re.sub(r"\s*\([^)]*\)\s*$", "", sl)`, which strips **any** trailing parenthetical on the slot token, not only the production “`(via …)`” annotation called out in issue #2536; if a slot string were ever a literal path or label whose real basename legitimately ends with a space plus parentheses (for example a `… (x86)`-style segment embedded at the end of the token), normalization would silently truncate it and could false-accept against `input_slot_set` or collapse distinct reviewers. **Suggested fix:** Restrict stripping to suffix patterns you actually intend to support (for example only ` (via ` / known annotation prefixes), document any accepted forms in [skills/review/scripts/aggregate-findings.md](skills/review/scripts/aggregate-findings.md), and add a regression test if you must preserve literal trailing parentheses in slot names.

- **code-quality** `skills/review/scripts/aggregate-findings.sh:311-313` — In `main()`, `if not input_blocks(intext): return 0` sits **after** `if not input_slot_set: return 1`; whenever `input_slot_set` is non-empty, `input_blocks(intext)` must also be non-empty because slots are only collected from `input_blocks`.
