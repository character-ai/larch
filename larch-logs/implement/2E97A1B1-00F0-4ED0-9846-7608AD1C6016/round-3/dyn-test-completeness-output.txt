### In-Scope Findings
- **risk-integration** `skills/review/scripts/aggregate-findings.sh:380-383` — The Python validator treats a line as an empty-merge attestation when `line.strip() == "LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED"`, but the persistence step strips only lines where the raw line matches exactly (`grep -v -x 'LARCH_AGGREGATOR_EMPTY_MERGE_ATTESTED'`). A vendor line such as leading or trailing spaces around the token validates successfully yet survives into the rewritten ballot, so voting surfaces can still show the machine token while `REASON=ok`, and the harness never covers this because the `zero_findings` stub uses a bare attestation line. **Suggested fix:** Align stripping with validation (for example filter with `awk`/`python3 -c` that drops any line whose stripped text equals the token, or reuse the same small Python snippet for the strip path), and optionally add a stub line with padded attestation plus an assertion that the persisted file contains no substring equal to the stripped token.
