### In-Scope Findings

### FINDING_1: Early convergence can stop the loop after repeated coder no-ops on low accepted counts
- **Severity**: **Latent**
- **Focus**: `correctness`
- **Location**: [skills/review-and-fix/scripts/review-and-fix.sh](skills/review-and-fix/scripts/review-and-fix.sh) (approx. `convergence_candidate_status` ~139–145; Part A convergence ~1206–1236)
- **Issue**: `convergence_candidate_status` treats `no-changes` (and `in-scope-filtered-out`) like `complete` for the low-accept / two-round heuristic, so two consecutive rounds can each have small `ACCEPTED_COUNT` while reviewers still vote in accepted findings the coder never lands; the script can still emit `REVIEW_AND_FIX_STATUS=converged-small-changes` and `/implement` Step 5 is instructed to stop the re-review loop.
- **Suggested fix**: Narrow the candidate set (for example require `complete` or additionally require `ACCEPTED_COUNT==0` / “no actionable accepted in-scope findings” before converging), or gate convergence when the last coder outcome was `no-changes` with `ACCEPTED_COUNT>0`.

### FINDING_2: Churn warning compares to last non-degraded round, not literal round N-1
- **Severity**: **Nit**
- **Focus**: `risk-integration`
- **Location**: [skills/review-and-fix/scripts/review-and-fix.sh](skills/review-and-fix/scripts/review-and-fix.sh) (Part C block ~1241–1256)
- **Issue**: The implementation plan / feature text describe “round-(N-1) accepts,” but Part C uses `find_previous_non_degraded_round` so a degraded round N-1 shifts the baseline to an older round; warnings and operator intuition can diverge when a degraded slot sits between the two compared rounds.
- **Suggested fix**: Either document this as intentional in [skills/review-and-fix/scripts/review-and-fix.md](skills/review-and-fix/scripts/review-and-fix.md) or compare against the immediate prior round’s `review-core.env` when that round is non-degraded, else emit an explicit “skipped degraded baseline” note in the warning.

### FINDING_3: Two independent “effective cap” stories must stay aligned
- **Severity**: **Latent**
- **Focus**: `architecture`
- **Location**: [scripts/run-step5-review.sh](scripts/run-step5-review.sh) (`count_prior_degraded_rounds`, argv `--round-cap` inflation ~118–181); [skills/implement/SKILL.md](skills/implement/SKILL.md) (Step 5 gate / `effective_round_cap` narrative ~1324–1328)
- **Issue**: Mechanical argv inflation is implemented in `run-step5-review.sh`, while Step 5’s human-facing loop contract also asks the orchestrator to recompute `effective_round_cap` from `DEGRADED_ROUND` plus prior counts; any drift between those recipes (or partial SKILL compliance) yields either premature “hit cap” behavior or extra rounds versus the launcher.
- **Suggested fix**: Cross-link the formulas in `run-step5-review.md` and SKILL.md with a single normative sentence (“launcher argv is authoritative; prompt-side variables must mirror this function”) or add a tiny helper script both docs reference by name.
