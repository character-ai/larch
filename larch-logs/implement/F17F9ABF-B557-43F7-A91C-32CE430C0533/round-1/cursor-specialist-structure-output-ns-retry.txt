### In-Scope Findings

### FINDING_1: Convergence overwrites load-bearing `fix-applied` / vote / halt statuses
- **severity**: **Important**
- **focus-area**: `correctness`
- **location**: [skills/review-and-fix/scripts/review-and-fix.sh](skills/review-and-fix/scripts/review-and-fix.sh) (Part A block after the `case "$core_status"` status assignment, ~1112–1130)
- **issue**: Part A assigns `status="converged-small-changes"` whenever `exit_code==0`, the round is not degraded, `round_num_dec>=2`, and the two-round accept heuristic matches — **without** restricting to the `complete` (or equivalent) branch. Any earlier-assigned exit-0 status such as `fix-applied`, `main-agent-vote-required`, or `no-changes` can be overwritten.
- **scenario_or_breakage**: Round *N−1* and *N* both have `ACCEPTED_COUNT<=threshold` while round *N* still takes the `fix-required` path and ends as `fix-applied` (coder committed). Part A then emits `REVIEW_AND_FIX_STATUS=converged-small-changes`. Per [skills/implement/SKILL.md](skills/implement/SKILL.md) Step 5 (~1380–1382), only `fix-applied` triggers the `run-relevant-checks-captured.sh --site step5-review-fixes` path; `converged-small-changes` falls under “any other status,” so the orchestrator can **skip mandatory post-fix checks** after a real fix commit, or similarly mishandle `main-agent-vote-required` / `no-changes` semantics.
- **suggested_fix**: Gate Part A so it only runs when `status` is already `complete` (or explicitly list allowed source statuses), or set convergence only when the `case` branch left `status=complete` and optionally merge convergence into summary without clobbering `fix-applied`.

### FINDING_2: `DEGRADED_ROUND` contract is documented but no in-repo orchestrator consumes it for the round cap
- **severity**: **Important**
- **focus-area**: `risk-integration` (requirements)
- **location**: [skills/review-and-fix/scripts/review-and-fix.md](skills/review-and-fix/scripts/review-and-fix.md) (~95–105) vs [skills/implement/SKILL.md](skills/implement/SKILL.md) Step 5 scripted loop (~1366–1398); [scripts/run-step5-review.sh](scripts/run-step5-review.sh) (unchanged)
- **issue**: The contract states that when `DEGRADED_ROUND=true` the orchestrator should **not** count the round toward the review cap. The diff only emits the KV from [skills/review-and-fix/scripts/review-and-fix.sh](skills/review-and-fix/scripts/review-and-fix.sh); **`/implement` Step 5 in SKILL.md never parses `DEGRADED_ROUND`**, and `run-step5-review.sh` does not adjust `round_num` / cap accounting.
- **scenario_or_breakage**: A degraded panel at `round_num == round_cap` still advances the loop the same as a healthy round, so the run can hit the cap stall or exit path while a “free retry” round was required by the feature text (“don’t burn round cap”).
- **suggested_fix**: Extend Step 5’s stdout key parsing to branch on `DEGRADED_ROUND=true` (e.g. re-invoke `run-step5-review.sh` with the same `--round-num` without incrementing toward `round_cap`, and document the behavior next to the existing re-review / bulk-skip gates).

### FINDING_3: “Important findings” guard is a narrow line-anchored grep
- **severity**: **Latent**
- **focus-area**: `code-quality` (requirements)
- **location**: [skills/review-and-fix/scripts/review-and-fix.sh](skills/review-and-fix/scripts/review-and-fix.sh) ~1125–1127 (`grep -qE '^\*\*Important\*\*|\*\*Important \`' …)
- **issue**: Important severity is only detected when it appears at a line start in those two shapes; common templates that put severity on a separate line from a `### FINDING_N:` header, or different Markdown, won’t match.
- **scenario_or_breakage**: A real Important-class finding present only inside a finding block body could fail to block convergence, and early-termination would fire despite Important content — violating the stated skip rule.
- **suggested_fix**: Reuse the same structural markers the repo already uses for findings (e.g. scan within `### FINDING_` blocks for severity tags), or call an existing normalizer if one exists in `review-core` / tally scripts.
