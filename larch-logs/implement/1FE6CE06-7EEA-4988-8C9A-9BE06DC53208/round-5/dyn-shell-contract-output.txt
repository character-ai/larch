### In-Scope Findings

NO_ISSUES_FOUND

The merge-gate work in `scripts/design-log-publish.sh` matches the intended shell contract:

- Registration probes use `set +e` / `set -e` around `reg_checks_out=$(gh pr checks …)` and capture stderr to a temp file instead of folding it into stdout.
- `jq -e` probes redirect to `/dev/null`, so boolean output does not land on the `KEY=value` stdout stream.
- `with_transient_retry` for `gh pr view` runs under `if …; then` / `else`, so a non-zero `_WTR_RC` does not trip `set -e` in the caller.
- `merge_rc` is assigned on every path that reaches the final `if [[ "$merge_rc" -ne 0 ]]` (empty `PUSH_HEAD_SHA`, registration timeout, watch failure, merge failure, success); post-push failures that `exit 1` earlier skip that check by design.
- Sleep uses the same overridable `sleep-seconds.sh` fallback as `lib-net.sh`.
- `design-publish.sh` wraps `design-log-publish.sh` in `set +e`, keeps stderr in `design-log-publish.failure.log`, and parses stdout with `parse_kv_from_output` — consistent with quiet-mode routing (`emit` → FD 3, which command substitution still captures per `lib-quiet.sh`).

`skills/design/scripts/test-design-publish.sh` and `scripts/test-design-log-publish.sh` align with that behavior (including `--json` vs `--watch` stub split and registration probe counts).
