### In-Scope Findings

1. **correctness** `scripts/design-log-publish.sh:825-866` — `reg_view_fail_file` is not explicitly cleared at the start of each registration loop iteration, unlike `reg_checks_err_file` which receives `: >"$reg_checks_err_file"` on line 826. All other `with_transient_retry` call sites in this script use a unique per-operation tmpfile; this is the only case where the same tmpfile is passed across multiple loop iterations. If `with_transient_retry` appends to its capture file rather than truncating, `last_view_err` (line 851: `cat "$reg_view_fail_file"`) accumulates stale content from prior probes — for example, a transient "Could not resolve host" from probe 1 that later self-healed would appear as the terminal diagnostic in the registration-timeout `larch_err` on probe 31, misleading operators into treating a timing race as a persistent network failure. The merge decision is unaffected (it depends on `pr_head_oid == PUSH_HEAD_SHA`), but the operator-facing diagnostic is corrupted. **Suggested fix**: add `: >"$reg_view_fail_file"` immediately before the `with_transient_retry` call at line 844, mirroring the `reg_checks_err_file` pattern on line 826.

- **correctness** `scripts/test-design-log-publish.sh:128-143` — In the `pr checks --json` stub handler, the total-probe counter (`count_file`) and the `GH_STUB_CHECKS_JSON_EMPTY_FIRST` knob counter (`knob_count_file`) both resolve to `${GH_STUB_CHECKS_JSON_COUNT_FILE:-...}` as their primary. When a caller explicitly sets `GH_STUB_CHECKS_JSON_COUNT_FILE`, both counters use the same file; every `--json` call increments a shared value, so the knob threshold comparison `"$checks_knob_probe" -le "$GH_STUB_CHECKS_JSON_EMPTY_FIRST"` becomes invalid (the knob probe counter is contaminated by the total probe counter). An identical collapse exists for the `pr view` `headRefOid` pair (`GH_STUB_PR_HEAD_OID_COUNT_FILE` at lines 190-201). No current tests set these override env vars so the bug is latent, but `GH_STUB_CHECKS_JSON_COUNT_FILE` reads as an intended override surface. **Suggested fix**: use a separate hard-coded suffix for the knob counter that ignores the override, e.g. `"${GH_STUB_LOG:-/tmp/gh-stub}.checks-json-knob-count"` unconditionally, so it cannot collapse with the total-count file.

2. **code-quality** `scripts/test-design-log-publish.sh:1056-1057` — The `=== stale head checks wait until PR head matches pushed head ===` block unsets `GH_STUB_PR_HEAD_OID_MISMATCH_FIRST` and calls `rm -rf "$TMPSTALE"` without restoring `SLEEP_SCRIPT_DIR` to `$GLOBAL_SLEEP_STUB`. After cleanup, `SLEEP_SCRIPT_DIR` points to the deleted `$TMPSTALE/sleep`. The immediately following `=== stale head never aligns ===` block sets its own stub, so no current test fails, but any test inserted between the two blocks that reaches the registration loop's sleep path would fall back to `sleep "$REG_INTERVAL"` (10 real seconds per probe), making the never-registered case take ~5 minutes. **Suggested fix**: add `export SLEEP_SCRIPT_DIR="$GLOBAL_SLEEP_STUB"` before `rm -rf "$TMPSTALE"` on line 1057, matching the pattern used by the `=== registration pr view failure refuses merge ===` and `=== stale head never aligns ===` blocks.
