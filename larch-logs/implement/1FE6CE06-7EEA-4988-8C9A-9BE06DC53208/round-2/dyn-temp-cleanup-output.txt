### In-Scope Findings

- **code-quality** `skills/design/scripts/plan-review-loop.sh:841-882` — The new `_collect_err_tmp=$(mktemp …)` path removes the process-substitution `tee` collector, but the `return 1` at line 874 (collector failed with no parseable output) runs before the `rm -f "$_collect_err_tmp"` at line 882, so each panel-failed round leaves a `plan-review-collector.stderr.*` file in `$DESIGN_TMPDIR`. Those files accumulate across multi-round review and are only removed when the session tmpdir is torn down. **Suggested fix:** `rm -f "$_collect_err_tmp"` immediately before the `return 1` at 874 (and optionally guard `mktemp` with `|| { …; return 1; }` under `set +e`), or register a function-local `trap 'rm -f "$_collect_err_tmp"' RETURN` right after `mktemp`.

- **code-quality** `scripts/design-log-publish.sh:186-199,817-820` — `wt_cleanup` still only unlinks `push_fail_file`, `create_fail_file`, `merge_fail_file`, `list_fail_file`, and `view_fail_file`; the registration-phase temps `reg_checks_err_file` and `reg_view_fail_file` are removed only at line 864 on the happy path. If `reg_checks_err_file` is created and `reg_view_fail_file` `mktemp` fails (lines 817–820), `emit_publish_failure` exits with code 1 and the EXIT trap runs `wt_cleanup`, which does not delete the checks capture file, leaving an orphan under `${TMPDIR:-/tmp}`. The same gap applies if the script is interrupted during the up-to-300s registration loop (trap clears the worktree but not those temps). **Suggested fix:** add `"${reg_checks_err_file:-}"` and `"${reg_view_fail_file:-}"` to `wt_cleanup`, and on the `reg_view_fail_file` mktemp failure branch call `rm -f "$reg_checks_err_file"` before `exit 1` so partial allocation cannot leak even if the trap list is incomplete.

### Out-of-Scope Observations

- **code-quality** `scripts/design-log-publish.sh:687-690` — `push_fail_file` `mktemp` failure still uses `emit_publish_result false` + `exit 0` instead of `emit_publish_failure` + `exit 1` like the post-push capture paths added in the same change; `PR_BODY_TMP` is cleaned by the EXIT trap, but recovery semantics are inconsistent with the new `emit_publish_failure` helper (not introduced by the registration-loop temps themselves).
