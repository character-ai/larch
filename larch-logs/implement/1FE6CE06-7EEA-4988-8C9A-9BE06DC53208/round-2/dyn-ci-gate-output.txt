### In-Scope Findings

- **correctness** `scripts/design-log-publish.sh:831-838` — The registration probe treats any parseable non-array JSON as a hard failure (`checks_registration_fatal=true` and immediate break). `gh pr checks --required --json` can legitimately return the JSON literal `null` while checks are not yet available; `scripts/ci-status.sh` already guards with `[[ "$CHECKS_JSON" != "null" ]]` before parsing. Here, `null` fails `type == "array"` but satisfies `jq -e '.'`, so the script aborts after one probe with “non-array JSON” instead of sleeping through the registration budget. That can reproduce the original failure mode (flush PR left open) on a transient API shape, and it is not covered by the harness (which tests `[]` and `{"message":…}` but not `null`). **Suggested fix:** Treat `null`, empty stdout, and `[]` the same way (not registered; keep polling until `REG_MAX_PROBES`). Reserve the fatal branch for structured error objects you intend to fail closed on (e.g. `type == "object"` with a `message` field), or mirror `ci-status.sh`’s explicit `!= "null"` guard before the non-array fatal path.
