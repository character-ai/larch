Reviewing the branch diff and commit history, focusing on the design-publish tail architecture.
### In-Scope Findings

- **architecture** `skills/design/scripts/design-publish.sh:38-51,137-158,252-307` and `skills/design/scripts/render-final-summary.sh:331-332` — Re-enabling `design-log-publish.sh` restores a live flush PR on the happy path, but the publish tail still drops most of the publish envelope: `parse_kv_from_output` only binds `PUBLISH_OK`/`RENAMED`/`UPSERT_*`/`ARCHITECTURE_SOURCE`, and `write_result_env_and_emit` never persists `PR_NUMBER`, `PR_URL`, or `RECOVERY_BRANCH` even though `design-log-publish.sh` emits them on stdout. Post-publish rendering always calls `render-run-summary.sh` with `--pr-number 0` / `--pr-url "N/A"`, so the terminal summary and the `tracking-issue-summary.sh` upsert that follows cannot reflect the merged `larch-logs/design/<run-id>/` PR. During the #3378 disable window this mismatch was masked because no PR existed; with flush live again the `/design` lifecycle advertises a run-log path but omits the PR that actually landed those logs. **Suggested fix:** Extend `parse_kv_from_output` and `.design-publish-result.env` to carry `PR_NUMBER`/`PR_URL`/`RECOVERY_BRANCH`, pass parsed PR fields into `render-final-summary.sh` (or teach that helper to read them from env), and add a harness assertion that a stubbed successful publish surfaces the PR line in `final-summary.md`.

- **architecture** `skills/design/scripts/design-publish.sh:254-297` and `scripts/design-log-publish.sh:887-890` — On publish failure the tail’s operator-facing envelope is split across stdout and stderr in a way that breaks recovery guidance. `design-log-publish.sh` puts `RECOVERY_BRANCH` (and often `PR_NUMBER`) on stdout via `emit_kv`, but `design-publish.sh` redirects only stderr to `design-log-publish.failure.log` and feeds that file to `append-tool-failure.sh`; recovery refs never become `WARN=` lines or result-env keys. Step 6 intentionally preserves `$DESIGN_TMPDIR` when `PUBLISH_OK=false`, yet the structured summary the operator actually reads gives no durable branch/PR pointer unless they dig through raw Bash stdout. Re-enabling flush makes this path common again (registration timeout, CI fail, merge fail), not theoretical. **Suggested fix:** Parse `RECOVERY_BRANCH`/`PR_NUMBER`/`PR_URL` from `_publish_out`, persist them in `.design-publish-result.env`, and on failure emit an explicit `add_warn` (and/or a final-summary note line) naming the recovery branch and open PR so the post-publish render/upsert and Step 6 preservation contract compose with the recovery story documented in `scripts/design-log-publish.md`.
