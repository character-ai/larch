### In-Scope Findings

- **architecture** `scripts/read-design-classification.sh:52-53` + `skills/design/SKILL.md` (Step 2a entry fence) — Invalid or missing `design_classification` in `run-params.json` always resolves to `HARD` (with only a stderr warning), and the Step 2a SIMPLE sentinel fence keys off that value. A paused or retried run whose `run-params.json` is stale, partially written, or corrupted can therefore leave `design_classification` unset yet still pass the “readable file” gate, skip SIMPLE sentinel repair, and launch the full sketch panel on a run that was originally SIMPLE. **Suggested fix:** Fail closed for SIMPLE-tier resume: if `run-params.json` is readable but classification is missing/invalid, abort with an operator-visible repair message (or require an explicit `[DESIGNING]` + stored tier in pause state) instead of defaulting to HARD; only treat `HARD` as the fallback when the file itself is unreadable and argv `--hard` was not the source of truth.

- **architecture** `scripts/design-pause-save.sh:4387-4423` + `skills/design/scripts/design-publish.sh:7793-7846` — Pause publish and Step 5c terminal publish each embed a separate `render_fresh_timing_report_for_*` implementation (tempdir allocation, jq validation, failure logging, artifact cleanup). The two paths are already diverging (`design-log-publish.sh` pause exclusions vs publish staging), so timing-report behavior can drift between pause snapshots and final publish without a single contract owner. **Suggested fix:** Extract one shared helper (e.g. `scripts/render-design-timing-report-final.sh` or a sourced function) invoked by both pause-save and design-publish, with one validation schema and one set of failure/warn breadcrumbs.

- **architecture** `skills/design/scripts/design-route.sh:234-279` + `skills/design/SKILL.md` (Step 0b post-route fence) — Cancel routes now render `final-summary.md` inside `design-route.sh`, then the Step 0b bash fence `cat`s the same file and exits 1, while adjacent orchestrator prose also instructs a separate read-and-emit verbatim pass. That splits summary ownership across driver render, bash stdout, and orchestrator chat, making double emission or missing emission depend on which layer the agent treats as authoritative. **Suggested fix:** Pick one emission surface: either driver renders only and orchestrator Read+emit is mandatory (bash fence must not `cat`), or bash `cat` is the sole emission path and delete the duplicate orchestrator emit instruction; document the chosen contract in `design-route.md` and pin it in `scripts/test-design-structure.sh`.

- **architecture** `skills/design/SKILL.md` (Step 2a.2 SIMPLE fast-path vs Step 2a.3 HARD zero-sketch path) — HARD “both tools down” and SIMPLE both write identical sentinel bytes (`NO_SKETCHES_CLASSIFIED_SIMPLE`, `NO_CONTESTED_DECISIONS`, empty `dialectic-resolutions.md`), so routing depends entirely on `run-params.json` tier plus completion-marker presence, not artifact shape. If pause/resume restores sentinels without a trustworthy tier (or with only partial `.completed/step-2a* markers), the flow can land in Step 2a.5 repair, the SIMPLE fast-path, or regular sketch launch inconsistently. **Suggested fix:** Add an explicit tier marker in pause state (already partially present as `TIER=` in pause-save) and require Step 2a/2a.5 fences to prefer pause-bound tier over re-parsed `run-params.json` on resume; optionally write a distinct HARD-degraded sentinel token so artifact shape disambiguates without relying on marker completeness alone.

- **architecture** `python/run_logs.py:720-727` + `python/merge.py:1783-1802` — The plan called for a centralized postmerge finalization helper with fail-closed recovery gating, but `finalize_postmerge_logs()` is a one-line alias of `flush_logs_post()`, and `merge.py` still calls `flush_logs_post()` directly. There is no single enforcement point ensuring recovery → manifest `done`/`pr_number` → report ordering for all post-merge callers, so future edits can reintroduce divergent ordering between `ship.run_postmerge_phase` and merge post-flush. **Suggested fix:** Move the recovery/manifest/report sequence into `finalize_postmerge_logs()` (with `flush_logs_post()` delegating or becoming private), and route both `ship.py` and `merge.py` through that function only; add a unit test that merge and ship paths share the same skip reasons on `recovery_ok=false`.
