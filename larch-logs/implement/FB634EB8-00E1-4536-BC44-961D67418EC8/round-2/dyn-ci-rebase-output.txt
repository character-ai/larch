Reviewing the CI-fix rebase/push flow in the diff and related source files.
### In-Scope Findings

- **risk-integration** `python/ci_monitor.py:930-938` — On `CI_FIX_REBASE_PENDING` push-only retries, post-rebase verification is skipped: `_run_post_rebase_verify_gates` in `scripts/ship-pr.sh:1685-1693` runs for both `did_rebase` and `pending_retry`, but Python only verifies when `did_rebase and classified.fixable`. A pending retry can force-push without re-running failed-job local verification or the relevant-checks lint loop, so a transient push failure can be retried on a tree that no longer passes CI gates. **Suggested fix:** On the `ci_fix_rebase_pending` path, mirror bash by running the same verify gate (failed-job verify + optional checks-site lint loop / post-rebase delta commit) before `force_push_recovery`, using the persisted failed-jobs context from the prior fix attempt rather than skipping straight to push.

- **risk-integration** `python/ci_monitor.py:943-959` — `CI_FIX_REBASE_PENDING` persistence does not match bash’s `verify_passed` gate (`scripts/ship-pr.sh:1708-1710`): Python sets `pending=True` whenever `(did_rebase or ci_fix_rebase_pending) and not pushed`, including cases where verify never ran or failed (e.g. empty `origin/<branch>` at `943-945`). Bash only calls `_ci_fix_pending_set` after verify succeeded and force-push failed. Combined with `monitor()` returning `Outcome.OK` when `waterfall-failed` and `ci_fix_rebase_pending` (`python/ci_monitor.py:1483-1488`), this can spin the merge loop on unverified or unpushable state instead of stalling. **Suggested fix:** Track a `verify_passed` boolean through `stage_and_push` and set `ci_fix_rebase_pending` only when verify passed and force-push failed; return `pending=False` (terminal stall) for verify failures, missing remote OID, and dirty-tree/lease failures that bash would not persist.

- **risk-integration** `python/ci_monitor.py:915-929` — The defer-rebase branch behind `origin/main` uses a single `git.fetch` + raw `git.rebase` + `git rebase --abort` on conflict, instead of bash’s `run_rebase_rebump` / `rebase-push.sh --no-push` path (`scripts/ship-pr.sh:1676-1677`, `2694+`), which includes sync-local-main, transient fetch retries, pre-rebase larch-log fixup, conflict-fixer handoff, and stall semantics on conflict. Transient fetch failures or rebase conflicts will behave differently from production `ship-pr.sh` during CI-fix pushes. **Suggested fix:** Route defer-rebase through the existing `rebase` module’s no-push wrapper (with `with_transient_retry` on fetch) and map conflict / transient outcomes to the same stall vs pending tokens bash emits, rather than inline `git.rebase`.

- **risk-integration** `python/ship.py:476-480` — Resume hydration clears `ci_fix_rebase_pending` when `CI_FIX_REBASE_PENDING_HEAD` is absent or mismatched, but bash never writes that key (only `CI_FIX_REBASE_PENDING` in `scripts/ship-pr.sh:71-78`). A state file produced by bash with `CI_FIX_REBASE_PENDING=true` will have pending cleared on Python `run_ship` entry, dropping the push-only retry contract across the bash→Python boundary. **Suggested fix:** Treat missing `CI_FIX_REBASE_PENDING_HEAD` as “accept current HEAD” (seed HEAD into state on first pending set) rather than clearing pending; only clear when HEAD is present and differs, matching bash’s implicit “retry at current HEAD” semantics.

- **risk-integration** `python/test_ci_monitor.py:1238-1294` — The plan acceptance criteria call for unit coverage of plain push, defer-rebase, post-rebase force-push, and persisted `CI_FIX_REBASE_PENDING` retry in `test_ci_monitor.py`; the branch adds no such tests (only `test_ship.py:670-717` for HEAD-mismatch clearing). `test_monitor_push_failed_stalls` still documents #3405 “no CI_FIX_REBASE_PENDING retry” while the implementation now sets pending on the rebase/force-push path, so regressions in push-selection and pending lifecycle are unguarded before Phase 7 cutover. **Suggested fix:** Add focused `RecordingRunner` tests for `stage_and_push` / `evaluate_failure` covering plain push vs force-push selection, defer-rebase behind main, pending retry with verify gating, and monitor’s OK-vs-STALLED routing when pending is or is not set; update the stale #3405 docstring.

### Out-of-Scope Observations

- **code-quality** `python/test_ci_monitor.py:1239` — The `test_monitor_push_failed_stalls` docstring is stale relative to the new pending-retry behavior and should be refreshed when CI-fix tests are added.
