Reviewing the branch diff and commit history for risk-integration issues.
### In-Scope Findings

- **risk-integration** `python/finalize.py:104-121` — `_postbump_checkpoint_status` treats any legacy `.postbump-phase` token other than `force-push-gate` as corrupt and returns `postbump-state-corrupt`, but bash clears unknown lowercase legacy tokens (e.g. `bogus-phase`) and continues with a full rebase (`scripts/implement-finalize.sh:544-558`, pinned by `scripts/test-implement-finalize.sh:889-892`). Resuming a Python ship run with a stale checkpoint therefore stalls postbump where bash would recover. **Suggested fix:** Mirror bash: if the checkpoint text matches `^[a-z][a-z0-9-]*$` but is not `force-push-gate`, unlink it and return `ok`; reserve `postbump-state-corrupt` for symlink/oversize/malformed tokens only. Add a parity test for the `bogus-phase` case (bash subprocess + Python).

- **risk-integration** `python/run_logs.py:651-694` — `flush_logs_post` / `finalize_postmerge_logs` renders `write-final-report.sh` and token/timing batches before writing `status=done` / `pr_number` to `manifest.json`. Bash `run_postmerge_phase` does the opposite: it writes manifest `status=done` first and only re-renders the final summary when that manifest write succeeds (`scripts/ship-pr.sh:3146-3173`). On partial failure, Python can leave a merged-outcome summary without a coherent `done` manifest—the exact case bash skips report rendering for. **Suggested fix:** Reorder postmerge finalization to match bash: manifest `status=done` + `pr_number` write → final report re-render → ledger batches; skip report when manifest write fails. Gate `run_postmerge_phase` on the same ordering.

- **risk-integration** `python/ship.py:476-480` — `run_ship` clears `ci_fix_rebase_pending` when `CI_FIX_REBASE_PENDING_HEAD` does not match current `HEAD`, but bash has no HEAD pin (`scripts/ship-pr.sh:61-78` only hydrates the boolean). After a failed force-push, an operator may amend/rebase locally; bash retries push-only on the next loop iteration, while Python drops pending and re-enters the full CI-fix waterfall—divergent resume semantics for the same persisted state. **Suggested fix:** Either drop the HEAD mismatch clear and match bash hydration, or document and test the stricter behavior explicitly; if keeping HEAD validation, persist and compare it the same way on every monitor iteration without silent clearing at ship entry.

- **risk-integration** `python/test_finalize_bash_parity.py` — The rewritten module still has only a handful of cases (mostly monkeypatched Python unit checks plus one draft `postmerge` subprocess compare). It does not subprocess-test postbump checkpoint handling, force-push outcomes, teardown rename branches, or cleanup partial paths that the plan and `scripts/test-implement-finalize.sh` cover. `test_finalize_bash_parity_gate.py` only asserts the module-level `skipif` shape, so checkpoint parity bugs like the `bogus-phase` case above can slip through `make py-test` with bash present. **Suggested fix:** Expand `test_finalize_bash_parity.py` with side-by-side subprocess cases modeled on `python/test_merge_bash_parity.py` and `scripts/test-implement-finalize.sh`, starting with postbump checkpoint clear/corrupt, remote-check/force-push status KVs, and postmerge cleanup partial/success.
