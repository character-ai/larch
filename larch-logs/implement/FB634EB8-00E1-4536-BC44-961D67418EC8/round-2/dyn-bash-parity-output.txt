Reviewing the branch diff and commit history against bash-parity correctness.
### In-Scope Findings

- **correctness** `python/finalize.py:114-119` — `_postbump_checkpoint_status()` treats any valid lowercase legacy token other than `force-push-gate` as corrupt and returns `postbump-state-corrupt`, but `scripts/implement-finalize.sh:544-552` clears unknown legacy tokens matching `^[a-z][a-z0-9-]*$` and only stalls on truly malformed checkpoints. The initial port cleared all valid tokens; round 1 regressed this by adding the `text != "force-push-gate"` branch, so resumes with a legacy checkpoint (e.g. `not-a-valid-checkpoint`) incorrectly bail instead of clearing and continuing. **Suggested fix:** Mirror bash: if the trimmed token matches `^[a-z][a-z0-9-]*$`, `unlink` the file and return `"ok"`; reserve `"corrupt"` for symlink/oversize/malformed content only.

- **correctness** `python/ci_monitor.py:930-938` — On `CI_FIX_REBASE_PENDING` push retries, `stage_and_push()` only runs post-rebase local verification when `did_rebase and classified.fixable`, but `scripts/ship-pr.sh:1685-1693` runs `_run_post_rebase_verify_gates` whenever `did_rebase=true` **or** `pending_retry=true`. A pending-only retry therefore skips the verify gates bash still enforces before force-push. **Suggested fix:** Run the same verify block when `ci_fix_rebase_pending` is true (or whenever `did_rebase or ci_fix_rebase_pending`), matching bash’s `pending_retry` branch.

- **correctness** `python/ci_monitor.py:915-927` — The defer-rebase path uses a plain `git.rebase` and aborts on any failure, returning `did_rebase=False` and `ci_fix_rebase_pending=False`. Bash’s equivalent (`scripts/ship-pr.sh:1676-1677` → `run_rebase_rebump … defer-push`) sets `did_rebase=true` before rebase and calls `rebase-push.sh --no-push --keep-on-conflict`, leaving conflict resolution to the vendor/Phase-1–4 handoff instead of aborting immediately. Python therefore fails closed on rebase conflicts where bash continues the CI-fix pipeline. **Suggested fix:** Port the defer-push rebase wrapper (`--keep-on-conflict`, conflict handoff, and `did_rebase=true` semantics) rather than a bare rebase+abort.

- **correctness** `python/test_finalize.py:130-134` — `test_postbump_rejects_corrupt_checkpoint` asserts `postbump-state-corrupt` for `not-a-valid-checkpoint`, but that string matches bash’s “unknown legacy, clear and continue” regex; the test encodes the regression above and will fight a correct fix. **Suggested fix:** Change the test to use genuinely malformed content (uppercase, empty, invalid characters) for the corrupt case, and add a separate test that unknown legacy tokens like `legacy-phase` are cleared and postbump proceeds with `status=ok`.
