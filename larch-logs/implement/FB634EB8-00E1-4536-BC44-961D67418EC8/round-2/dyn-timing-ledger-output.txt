### In-Scope Findings

- **correctness** `skills/design/scripts/plan-review-loop.sh:442-449` vs `skills/design/scripts/plan-review-loop.sh:1471-1476` — Multi-round `main-agent-vote-required` exits through `_snapshot_terminal_exit_preserving_status`, which still calls `_emit_plan_round_timing_row` (end time = panel exit, counts = pre–main-agent adjudication). The legacy no-`--round-cap` path correctly persists `round-start-s` and skips emission. That conflicts with `plan-review-loop.md` (“defers emission to `skills/design/SKILL.md` after inline re-tally”) and with `/implement`, where `review-implement-step5-loop.sh:242-245` defers entirely. If the SKILL deferred emit fails or is skipped, the ledger keeps a short duration and stale tallies; if it succeeds, you rely on a second superseding row and last-wins dedup. **Suggested fix:** In `_snapshot_terminal_exit_preserving_status`, on `LOOP_STATUS=main-agent-vote-required` only call `_persist_plan_round_start` (mirror the legacy branch and implement MAV), and let `record-plan-review-round-timing.sh` run once from `skills/design/SKILL.md` after re-tally.

- **correctness** `scripts/timing-report.sh:381-384` vs `docs/run-logs.md:379` — `emit_round_array` attaches a `round` row when only `round_start` lies in the parent step’s `[start,end)`; it never checks `round_end`. The run-log contract requires the step interval to fully contain both round start and end. Deferred handoffs (persisted early `round-start-s`, late `end_s` after MAV/checks) can attach to Step 5 / design Step 3 even when wall time extends into the next step, so `rounds[].duration_seconds` may exceed the parent `per_step.duration_seconds` and rounds may sit on the wrong step row. **Suggested fix:** Require `round_start >= start && round_end < end` (consistent half-open bounds), drop non-conforming rows, and add a harness case with a round spanning the next step mark.

- **correctness** `skills/review-and-fix/scripts/record-implement-review-round-timing.sh:99-104` vs `skills/design/scripts/record-plan-review-round-timing.sh:90-96` — Implement idempotency is round-number-only (first row wins forever); design allows superseding rows when `start_s`/`end_s`/counts change. Design multi-round MAV depends on superseding; implement does not. That is mostly safe because implement defers MAV emission, but any future or alternate caller that records a round before deferred work completes cannot be corrected on retry (unlike design). **Suggested fix:** Either align implement with design (allow supersede when `start_s`/`end_s` differ, keep idempotency only on exact tuple match), or document and test that implement must never pre-emit before deferred paths.
