### In-Scope Findings

- **code-quality** `skills/review-and-fix/scripts/record-implement-review-round-timing.sh:99-104` — The idempotency pre-check exits 0 when *any* `round` row exists for the round number, without matching `start_s`, `end_s`, `accepted`, or `rejected`. If a prior write produced a partial or wrong row (for example `timing-ledger.sh record-round` succeeded once but the post-check at lines 118–122 failed), a retry is treated as success and never corrects the ledger. The design sibling (`record-plan-review-round-timing.sh:90-96`) fingerprints the full row before short-circuiting, so implement and design diverge on the same contract. **Suggested fix:** Align the implement pre-check with the design fingerprint (round + step + start + end + accepted + rejected), or drop the coarse pre-check and rely only on the post-write verification already at lines 118–122.

- **code-quality** `skills/review-and-fix/scripts/review-implement-step5-loop.sh:187-217` — `run_implement_loop` declares many loop locals (`round_num`, `post_accepted_count`, etc.) but assigns `round_start_s=$(step5_now_s)` without `local`. Because this file is sourced from `review-and-fix.sh`, that leaks a global `round_start_s` into the parent shell and can collide with other sourced helpers or a second Step 5 entry in the same process. **Suggested fix:** Add `round_start_s` to the existing `local` block at line 187–192 (or declare `local round_start_s` immediately before the `while` loop).

- **code-quality** `skills/design/scripts/design-route.sh:36-41,144,159` — `validate_session_id_arg` only rejects embedded newlines; unlike `--issue`, `--claude-pid`, and other argv scalars it allows an empty `--session-id` value once the flag is present. An empty ID can still flow into `write-design-current-env.sh` / `design-init-runparams.sh` via `SESSION_ID_ARG`, producing run-params and timing artifacts keyed on a blank session id. **Suggested fix:** Reject empty values in `validate_session_id_arg` (mirror `validate_plain_scalar`) or add `[[ -n "$SESSION_ID_ARG" ]] || fail '--session-id must be non-empty'` before calling it.
