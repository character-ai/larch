Reviewing the branch diff and timing-ledger integrations for architecture issues.
### In-Scope Findings

- **architecture** `skills/review-and-fix/scripts/record-implement-review-round-timing.sh:99-105` vs `skills/design/scripts/record-plan-review-round-timing.sh:90-97` — The two deferred round writers use incompatible idempotency contracts on the same `type=round` ledger schema. Design skips only when the full tuple `(round, start_s, end_s, accepted, rejected, oos)` already exists and allows a superseding row when `end_s` or counts change (`test-record-plan-review-round-timing.sh` expects two round-1 rows after a timing update). Implement skips on any existing row for `(skill, step, round)` regardless of timestamps (`test-record-implement-review-round-timing.sh:41-45` explicitly forbids updating round-4 timing). That asymmetry means implement cannot correct a prematurely emitted row, while design can extend deferred MAV wall time after orchestrator work. **Suggested fix:** Unify idempotency across both helpers (either round-keyed last-writer-wins matching `timing-report.sh`’s `emit_round_array` dedupe, or full-tuple skip with explicit supersede on changed `end_s`/counts) and document the single contract in `scripts/timing-ledger.md`; align harnesses so both workflows test deferred re-emit with updated duration.

- **architecture** `skills/review-and-fix/scripts/review-implement-step5-loop.sh:347-353` — The `lint-fix-main-agent-required` branch breaks the deferral architecture used for `main-agent-vote-required` / `coder-main-agent-required` (lines 242-254 persist `round-start-s` and defer emission). Here the loop both persists `round-start-s` and calls `_emit_implement_round_timing_row` before exiting `stall`, while `skills/implement/SKILL.md:782` still attempts a deferred `record-implement-review-round-timing.sh` when `round-start-s` exists. Because implement idempotency is round-keyed, the orchestrator emit is a no-op and duration is frozen at lint-handoff time; tests (`test-review-implement-step5-loop-timing.sh:25-34`, `89-90`) document defer-only handoff behavior for other paths but do not exercise this branch. **Suggested fix:** Treat `lint-fix-main-agent-required` like MAV/CMA: persist `round-start-s`, skip in-loop `_emit_implement_round_timing_row`, and let the orchestrator stall path emit exactly once after any prompt-side work; add a loop-level harness asserting no in-loop ledger row and a single deferred row with the extended `end_s`.

- **architecture** `scripts/run-step5-review.sh:239-241` — Step 5 resume emits a second `mark "Step 5 — code review"` whenever `--starting-round > 1`, while the initial mark lives in the orchestrator fence. `timing-report.sh` builds separate `per_step` JSON entries per implement mark interval (`scripts/timing-report.sh:443-448`), and round rows attach by `round_start` falling inside each sub-interval (`emit_round_array`, lines 381-384). Deferred MAV timing is ordered correctly today (orchestrator records round N before resume re-invocation), but the split-mark design makes round attribution fragile if any future path records a round row after the resume mark or if mark emission moves relative to deferred writers. **Suggested fix:** Either emit the Step 5 mark only once per session (update/resume sentinel instead of a second mark) or centralize round recording so all rows for a logical Step 5 session share one mark window; document the ordering invariant beside `review-implement-step5-loop.md` / `run-step5-review.md`.

### Out-of-Scope Observations

- **architecture** `skills/review-and-fix/scripts/record-implement-review-round-timing.sh:107-109` — Unlike `record-plan-review-round-timing.sh:87`, the implement helper does not `unset IMPLEMENT_TMPDIR`’s cross-skill siblings (`DESIGN_TMPDIR` / `REVIEW_TMPDIR`). Risk is low because both helpers pin `LARCH_TIMING_LEDGER`, and `design-publish.sh` / `render-final-summary.sh` now use `env -u IMPLEMENT_TMPDIR` for reports; implement final-report paths were not given symmetric `env -u DESIGN_TMPDIR` hardening in this branch. Consider mirroring the design isolation pattern on any implement-side `timing-report.sh` invocations that do not already pin ledger + tmpdir explicitly.
