### In-Scope Findings

- **risk-integration** `skills/design/scripts/record-plan-review-round-timing.sh:84-105` — The new deferred writer exports `LARCH_TIMING_LEDGER="$DESIGN_TMPDIR/timing-ledger.tsv"` but calls `timing-ledger.sh` without `env -u IMPLEMENT_TMPDIR`, unlike the hardened publish/render paths in `skills/design/scripts/design-publish.sh:255-257` and `skills/design/scripts/render-final-summary.sh:102-104`. `resolve_ledger_path` in `scripts/timing-ledger.sh:62-72` prefers a valid `LARCH_TIMING_LEDGER`, but on validation failure it falls through to `IMPLEMENT_TMPDIR` before `DESIGN_TMPDIR`. In a mixed design+implement session (or any shell where `IMPLEMENT_TMPDIR` leaked), a design `round` row can land in the implement ledger while the design tmpdir ledger stays empty, so published `timing-report-final.json` and run-log timing blocks miss Step 3 round data. **Suggested fix:** Wrap the `timing-ledger.sh record-round` invocation with `env -u IMPLEMENT_TMPDIR` (and keep the explicit `LARCH_TIMING_LEDGER` pin), matching `design-publish.sh`; add a harness case that sets a stale `IMPLEMENT_TMPDIR` and asserts the row is written under `$DESIGN_TMPDIR/timing-ledger.tsv`.

- **risk-integration** `skills/design/SKILL.md:1117` — Deferred plan-review timing after `main-agent-vote-required` is specified only in orchestrator prose (`record-plan-review-round-timing.sh` after re-tally); there is no mandatory Bash fence comparable to implement’s MAV handoff block at `skills/implement/SKILL.md:800-812`. `plan-review-loop.sh:444-445` and `1503-1509` intentionally persist `round-start-s` and skip in-loop emission, so a missed prose step (halt, pause, or orchestrator skip) leaves no `round` row while the mark row for `design Step 3 — plan review` exists. `scripts/design-pause-save.sh:112-114` then renders `timing-report-final.json` from an incomplete ledger with no fail-closed gate. **Suggested fix:** Add a design SKILL Bash fence (mirroring implement Step 5) that reads `plan-review/round-*/round-start-s`, calls `record-plan-review-round-timing.sh`, and runs before Gate B / pause publish; extend `skills/design/scripts/test-design-pause-resume.sh` with a MAV-deferred fixture asserting a `round` row exists before pause render.

- **risk-integration** `skills/review-and-fix/scripts/review-implement-step5-loop.sh:347-352` — On `lint-fix-main-agent-required`, the loop calls `step5_persist_round_start` and exits with `stall` without `_emit_implement_round_timing_row`, deferring emission to implement SKILL stall prose (`skills/implement/SKILL.md:782`). Unlike the MAV/coder handoff path, there is no paired Bash fence on the stall branch—only prose for stalls where `round-start-s` exists. A orchestrator that handles `stall` without the deferred helper drops lint-handoff wall time entirely. **Suggested fix:** Either emit the deferred row inside `review-implement-step5-loop.sh` before the `lint-fix-main-agent-required` exit (using persisted `round-start-s` and final tally counts), or add a stall-branch Bash fence in `skills/implement/SKILL.md` symmetric to lines 800-812 and pin it in `scripts/test-implement-structure.sh` / extend `skills/review-and-fix/scripts/test-review-implement-step5-loop-timing.sh` with a `lint-fix-main-agent-required` fixture.

- **risk-integration** `scripts/run-step5-review.sh:239-240` — Loop resume (`--starting-round > 1`) writes a timing-ledger mark for `Step 5 — code review` but no matching token-ledger mark (`scripts/run-step5-review.md:42` documents this as intentional). First Step 5 entry uses `scripts/step-telemetry-mark.sh`, which marks both ledgers (`scripts/step-telemetry-mark.sh:41-42`). After MAV/coder handoff resume, token and timing ledgers disagree on Step 5 segment boundaries, so token-cost reports and timing reports cannot be reconciled for the same run. **Suggested fix:** On resume, call `step-telemetry-mark.sh` (or a thin wrapper that marks both ledgers) instead of timing-only `timing-ledger.sh mark`, or document and enforce a single canonical boundary source in `write-final-report.sh` / run-log consumers so mixed resume runs do not silently diverge.

- **risk-integration** `skills/design/scripts/record-plan-review-round-timing.sh:89-105` — Idempotency skips only when round, start, end, accepted, rejected, and OOS all match an existing row; a second call with the same round/start/end but different post-MAV counts appends a second `round` row. `scripts/timing-report.sh:381-391` dedupes by round number within a mark interval (last row wins), so JSON output can look correct while the on-disk ledger has duplicates—downstream tooling that reads the raw TSV sees inconsistent history. **Suggested fix:** Align implement-style idempotency: skip when any `round` row exists for `(skill, step, round)` regardless of counts, or upsert/replace the row; add a test in `skills/design/scripts/test-record-plan-review-round-timing.sh` that two calls with identical timing but different counts leave exactly one row.
