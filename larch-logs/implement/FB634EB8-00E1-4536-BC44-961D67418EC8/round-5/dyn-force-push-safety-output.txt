Reviewing force-push paths in the diff and related source files.
### In-Scope Findings
- **security** `python/ci_monitor.py:943-951` — `verify_job_locally` before `git.force_push_recovery` runs only when `classified.fixable` is non-empty, so `ci_fix_rebase_pending` push-only retries (and any post-rebase path where job reload yields an empty fixable set) can reach a lease force-push with no local verification. Bash always runs `_run_post_rebase_verify_gates` whenever `did_rebase` or `CI_FIX_REBASE_PENDING` is true (`scripts/ship-pr.sh:1685-1693`), including a relevant-checks fallback when the failed-jobs TSV is empty (`scripts/ship-pr.sh:1566-1584`). `test_pending_retry_missing_local_remote_ref_uses_ls_remote_lease` (`python/test_ci_monitor.py:699-723`) encodes the skip-verify behavior. **Suggested fix:** On `did_rebase or ci_fix_rebase_pending`, always run post-rebase verification before `force_push_recovery`—reload failed jobs on pending retry when `classified` is empty, verify fixable jobs when present, and mirror bash’s relevant-checks fallback when fixable is still empty; refuse force-push unless verification passes.

- **security** `python/finalize.py:295-318` — After live `ls-remote` reports the remote branch is `present`, `postbump()` prefers `git.try_rev_parse(f"origin/{branch}")` for `expected_remote_oid` and only calls `ls-remote` again when that local tracking ref is missing. That uses a potentially stale cached ref for the `--force-with-lease` OID instead of the live remote tip (bash `run_force_push_gate` calls `git-force-push.sh` without a caller-supplied OID and relies on post-fetch tracking-ref semantics; `stage_and_push` at `python/ci_monitor.py:957-966` fetches first). Wrong stale OIDs usually fail closed, but they weaken lease correctness and can diverge from bash under ref races. **Suggested fix:** After `_remote_branch_state` returns `present`, resolve `expected_remote_oid` from live `git ls-remote --exit-code --heads origin <branch>` (or `git.fetch` then `rev-parse`); do not prefer a pre-fetch local `origin/<branch>` OID for the lease.

### Out-of-Scope Observations
- **security** `python/finalize.py:100-101` — `postbump_preflight` treats `symbolic-ref` exit 0 with empty stdout as on `ctx.branch_name` without a live HEAD branch check; `force_push_recovery` still compares HEAD to the passed branch, so this is a preflight looseness rather than a direct push bypass.
- **risk-integration** `python/ci_monitor.py:899-903` — `stage_and_push` derives the push branch from the current `HEAD` only and does not compare it to session `BRANCH_NAME`/`ctx.branch_name` the way bash `validate_postbump_state_branch(true)` does before postbump force-push; mitigated today because `force_push_recovery` requires `branch == head_branch`, but a future caller passing a mismatched `branch` argument could be dangerous.
