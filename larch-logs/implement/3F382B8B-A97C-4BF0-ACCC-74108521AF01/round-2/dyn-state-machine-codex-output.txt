### In-Scope Findings
- **risk-integration** `skills/design/scripts/run-step3-review.sh:237-302` — Automatic continuation can run multiple SIMPLE rounds, but the driver still resets `ROUND_NUM=1` for every non-HARD invocation and only advances the loop round label via the HARD-only snapshot cursor, while `review-round-count.txt` / `STEP3_REVIEW_ROUND_NUM` advances to 2..5. The new `/design` loop in `skills/design/SKILL.md:1276` therefore uses one counter for cap/continuation and another stale label for loop artifacts, `ROUNDS_COMPLETED`, timing, and MainAgent re-tally paths, causing SIMPLE round 2+ evidence to be recorded as round 1. **Suggested fix:** Use the shared `STEP3_REVIEW_ROUND_NUM` as the `--round-num` passed to `plan-review-loop.sh` for both tiers, and keep any HARD plan-snapshot cursor separate if still needed; add a regression that runs two SIMPLE review entries and asserts `ROUND_NUM/ROUNDS_COMPLETED` and `plan-review/round-2/` line up with `review-round-count.txt`.

- **risk-integration** `skills/design/SKILL.md:1242-1277` — Step 3.5 marks `.completed/step-3` before Gate B, but the new `PLAN_REVIEW_CONTINUE=true` path loops back to Step 3 while clearing only `.step3-entry-plan-printed` and explicitly not writing `.completed/step-3.5`. If the run pauses or fails after deciding to continue but before the next review round settles, durable state says Step 3 is complete and Step 3.5 is incomplete, so resume can land back in Gate B for the previous round instead of launching the intended next review. **Suggested fix:** Before auto-reinvoking Step 3, reset the downstream Step 3/3.5/3b/4/4b sentinels (or introduce an explicit auto-review-in-progress sentinel that resume honors) and clear prior Gate-B apply markers once the previous round is committed to continuation.

- **risk-integration** `skills/design/references/approval-gates.md:82-84` — The Gate B zero-findings short-circuit still instructs the executor to proceed directly to Step 3b, which conflicts with the new continuation contract in `skills/design/SKILL.md:1274-1279` and `skills/design/references/approval-gates.md:167-169` that a `zero-findings-degraded-panel` round should run the heuristic check and may auto-continue. Following the Gate B body literally skips degraded-panel continuation for the exact zero-finding degraded case added to the helper tests. **Suggested fix:** Rewrite the zero-findings short-circuit to return to the Step 3.5 continuation check before Step 3b, and add a structure/harness assertion that `zero-findings-degraded-panel` reaches `plan-review-continuation.sh`.
