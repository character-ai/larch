### In-Scope Findings

- **correctness** `skills/design/scripts/render-final-summary.sh:256-301` — The Plan review line still hard-requires `voting-tally.md` before it will count anything, but `run-step3-review.sh` deletes `voting-tally.md` on the `cap-reached` path while leaving the new cumulative `accepted-plan-findings-all.md` intact. After a multi-round automatic sequence, a later Step 3 entry at cap (e.g. Gate A “Ready for review” with `review-round-count.txt` already at 5) can therefore end with a non-empty cumulative findings file and no tally file, and the final summary will incorrectly print `- **Plan review**: 0 findings`. This regression is introduced by the cumulative-artifact work: before `accepted-plan-findings-all.md`, cap-reached also removed the per-round accepted file, so the tally gate and artifacts were consistent. **Suggested fix:** Drop the `voting-tally.md` existence gate for counting (count directly from `accepted-plan-findings-all.md` / `accepted-plan-findings.md` / `oos-accepted-design.md` as documented in `render-final-summary.md`), or treat a non-empty cumulative file as sufficient evidence that plan review ran; add a harness case with cumulative findings present and `voting-tally.md` absent.

- **correctness** `skills/design/scripts/plan-review-loop.sh:1567-1613` — Gate C manual “Re-run review panel” uses the same `_accumulate_round_accepted_all` path as automatic continuation: it snapshots prior `accepted-plan-findings-all.md` and appends the new round instead of resetting. `approval-gates.md` invariant #2 explicitly says manual Gate C(c) re-entry must overwrite `accepted-plan-findings-all.md`, and only automatic continuation should cumulate. After automatic rounds plus a manual re-run, `render-final-summary.sh` will prefer the cumulative file and over-report findings from earlier automatic rounds that are no longer part of the active review set. **Suggested fix:** Reset `accepted-plan-findings-all.md` (and the `.accepted-plan-findings-all.prev.md` snapshot) on manual Gate C re-entry before `run-step3-review.sh` / `plan-review-loop.sh` runs—e.g. via an orchestrator sentinel cleared only on Gate C(c), or by teaching `plan-review-loop.sh` to skip accumulation unless the caller marks an automatic-continuation round.

- **correctness** `skills/design/scripts/plan-review-loop.sh:598-613` — Cumulative in-scope findings are appended without any deduplication, while accepted OOS uses description-key dedup in the same file’s `_accumulate_round_oos`. If later rounds re-accept materially similar findings (common after Gate B rewrites), `accepted-plan-findings-all.md` can count the same concern multiple times across rounds with duplicate `### FINDING_N:` headers, inflating the Plan review total relative to distinct issues accepted. **Suggested fix:** Either document that the cumulative file is intentionally a per-round audit trail (and adjust summary wording), or add dedup compatible with the `### FINDING_N:` block schema (e.g. concern-text or stable finding id), with a regression test in `test-plan-review-loop.sh` covering two-round accumulation.
