Reviewing the branch diff and key scripts for artifact-state consistency across review rounds.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/persist-retally-step3-env.sh:162-196` — On a successful MainAgent re-tally (`TALLY_PLAN_REVIEW_STATUS=ok`), `_rewrite_env_file` updates `LOOP_STATUS` / `TALLY_PLAN_REVIEW_STATUS` / `SCOPE_ANCHOR_FILE` but leaves `ACCEPTED_COUNT`, `IMPORTANT_ACCEPTED_COUNT`, `NIT_ACCEPTED_COUNT`, and `NON_NIT_ACCEPTED_COUNT` copied from the pre-retally env unchanged; it only zeroes those keys on `tally-error`. After a real `main-agent-vote-required` round (0 eligible judges), `tally-plan-review.sh` truncates `accepted-plan-findings.md` before exit, so the loop writes `ACCEPTED_COUNT=0` even though retally may later populate that file and `_merge_retally_accepted_all` appends blocks into `accepted-plan-findings-all.md`. Gate B and `plan-review-continuation.sh` read disk counts, but `.step3-review-result.env` / `.step3-plan-review-result.env` can stay at zero while artifacts are non-empty—any consumer of the env KVs (logging, diagnostics, future tooling) sees stale state. The harness seeds `ACCEPTED_COUNT=0` before ok retally and never asserts count refresh (`test-persist-retally-step3-env.sh:51-88`). **Suggested fix:** After successful merge, recompute accepted / important / nit / non-nit counts from `accepted-plan-findings.md` (reuse the awk helpers from `plan-review-loop.sh`) and write them into both env files in `_rewrite_env_file`, mirroring the tally-error zeroing path.

- **risk-integration** `skills/design/scripts/plan-review-continuation.sh:60-177` and `skills/design/scripts/persist-retally-step3-env.sh:162-196` — `plan-review-continuation.sh` reads `DEGRADED_PANEL` from `.step3-review-result.env`, and `persist-retally-step3-env.sh` never clears it after successful MainAgent adjudication. A 0-judge round always sets `DEGRADED_PANEL=1` in `plan-review-loop.sh`; after retally settles to `LOOP_STATUS=complete` / `TALLY_PLAN_REVIEW_STATUS=ok`, that flag persists. The continuation helper checks `DEGRADED_PANEL` before `HIGH_ACCEPTED_COUNT` / small-clean logic, so `PLAN_REVIEW_CONTINUE_REASON=degraded-panel` fires even when post-retally `accepted-plan-findings.md` is empty (explicitly covered in `test-step3-review-cap.sh:285-293`). With the new automatic multi-round loop, that forces extra full panels until the cap, each round appending to `accepted-plan-findings-all.md` / `oos-accepted-design.md` via `_accumulate_round_*`, inflating final-summary totals and burning `review-round-count.txt` slots after an already-adjudicated degraded round. **Suggested fix:** Either have `persist-retally-step3-env.sh` set `DEGRADED_PANEL=0` (and refresh related KVs) on successful retally when adjudication completed, or teach `plan-review-continuation.sh` to ignore `DEGRADED_PANEL` once `TALLY_PLAN_REVIEW_STATUS=ok` and `LOOP_STATUS=complete`, using only disk-derived accepted counts for the continue/stop decision.

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:598-614` and `skills/design/scripts/render-final-summary.sh:254-336` — `_accumulate_round_accepted_all` blindly concatenates each round's `accepted-plan-findings.md` into `accepted-plan-findings-all.md`, while `_accumulate_round_oos` deduplicates by normalized Description (`plan-review-loop.sh:552-586`). OOS merge in `persist-retally-step3-env.sh` also deduplicates (`persist-retally-step3-env.sh:125-144`). Across automatic continuation rounds, re-accepted or reworded in-scope findings therefore accumulate as separate `### FINDING_N:` blocks; `render-final-summary.sh` counts every block in the cumulative file (minus Gate B one-by-one skips at render time only). Final-summary “Plan review” totals can over-report versus distinct issues, especially on degraded-panel-driven extra rounds above. **Suggested fix:** Add block-level dedup for in-scope findings in `_accumulate_round_accepted_all` and/or `_merge_retally_accepted_all` (e.g., normalized Concern text, matching the OOS Description-key approach), or renumber/dedup when writing cumulative artifacts so `render-final-summary.sh` counts unique findings.

That heuristic asymmetry predates this branch's artifact work and is not a regression in env/artifact consistency.
