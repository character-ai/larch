Reviewing the branch diff and commit history for architecture issues in the Step 3 multi-round loop.
### In-Scope Findings

- **architecture** `skills/design/scripts/plan-review-continuation.sh:178-180` — The automatic continuation predicate fires on any single Important/High accepted finding (`HIGH_ACCEPTED_COUNT > 0`), but `/implement` Step 5 only treats a round as “substantial” when `high_n >= 2` (or structural LOC ≥ 100, or fix count ≥ 8) in `skills/review-and-fix/scripts/review-implement-step5-loop.sh:410`. The issue plan (#3698) explicitly called for symmetry with “important-accepted ≥ 2”, and `SKILL.md` claims the predicates mirror `/implement`, yet a lone Important finding now forces another full panel while `/implement` would converge. That mismatch will add extra automatic rounds (cost/latency) and re-open the exact divergence this branch is meant to close. **Suggested fix:** Align the continue threshold with `/implement` (`HIGH_ACCEPTED_COUNT >= 2`, or share a single constants/helper), and add a harness case for “1 Important → stop” vs “2 Important → continue”.

- **architecture** `skills/design/scripts/run-step3-review.sh:212-228` + `skills/design/SKILL.md:1276` — Each automatic continuation re-enters Step 3 via `run-step3-review.sh`, which deletes every `plan-review/round-*` directory before launching the next panel. With the new multi-round loop this runs up to four extra times per design, so per-round forensics (`findings-classification.tsv`, `round-summary.env`, voting tallies) from prior automatic rounds are destroyed even though `plan-review.md` documents those paths as the canonical per-entry artifact store and #3619’s planned per-round pruning needs stable round-indexed history. Only `accepted-plan-findings-all.md` survives at the tmpdir root. **Suggested fix:** Stop wholesale `round-*` deletion on auto-continuation re-entry (delete only the active round slot, or archive completed rounds), and extend harness coverage to assert round-1 artifacts remain after an automatic round-2 entry.

- **architecture** `skills/design/scripts/run-step3-review.sh:247-282` + `skills/design/references/approval-gates.md:184` — Gate C prose says HARD runs advance the round cursor when `plan-after-round-<cursor>.txt` exists, but `snapshot-plan-round.sh write-after` has no production caller in the Gate B / `design-postplan-emit.sh` path (only `write-original` is invoked). Automatic multi-round loops therefore always pass `--round-num 1` into `plan-review-loop.sh` while `review-round-count.txt` increments separately, leaving two round-tracking schemes permanently desynced on the new hot path. **Suggested fix:** After each Gate B post-apply fence, call `snapshot-plan-round.sh write-after --round "$STEP3_REVIEW_ROUND_NUM"` (and advance `write-cursor`), or drop the dead cursor branch and key `plan-review-loop` off `review-round-count.txt` only.

- **architecture** `skills/design/scripts/plan-review-continuation.sh:125-187` — Continuation’s “structural/large-change” signal is inferred from static plan metadata (`plan_lines > 120`, `diff_lines > 500`, or HARD classification) rather than the post-apply delta `/implement` measures (`structural_loc` from `git diff --numstat` in `review-implement-step5-loop.sh:395-402`). A plan can shrink after Gate B apply while still triggering another automatic round, or miss continuation after large rewrites that do not cross those static thresholds. **Suggested fix:** Either snapshot pre/post Gate B plan bodies and compare line deltas for continuation, or document and test that `/design` intentionally uses a cheaper static proxy and accept the behavioral drift.

- **risk-integration** `skills/design/scripts/plan-review-continuation.sh:169-187` — There is no `/implement`-style churn guard (Step 5 “Part C”: warn/stop when round *N* accepts more than round *N−1*). A oscillating panel can burn the shared cap of 5 with ping-pong findings before Gate C ever fires, with no operator-visible churn signal. **Suggested fix:** Persist per-round `ACCEPTED_COUNT` in `plan-review/round-N/round-summary.env` (once round retention is fixed) and add a continuation veto or warning when accepted count increases without convergence, matching `review-and-fix.sh` Part C semantics.

### Out-of-Scope Observations

- `snapshot-plan-round.sh write-after` is documented as part of the Gate B / `design-postplan-emit.sh` surface in `skills/design/SKILL.md:1702`, but no shipped `.sh` caller invokes `write-after` outside tests — the HARD cursor-advance branch in `run-step3-review.sh` appears to be dead code predating this branch.

- `skills/design/scripts/test-step3-review-cap.sh:121` still stubs `LOOP_STATUS=converged`, which is not a valid `plan-review-loop.sh` terminal status (`complete`, `zero-findings-degraded-panel`, etc. per `plan-review.md:52`); the stub is misleading though not on the production path.
