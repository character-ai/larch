Reviewing the branch diff and commit history, then tracing artifact persistence across the plan-review loop scripts.
### In-Scope Findings

- **correctness** `skills/design/scripts/plan-review-loop.sh:1613-1625`, `skills/design/scripts/tally-plan-review.sh:376-379`, `skills/design/scripts/persist-retally-step3-env.sh:68-147` — On the `main-agent-vote-required` path, `_accumulate_round_oos` restores prior-round `oos-accepted-design.md` into the session root (or merges when the stub tally wrote OOS), but the follow-up MainAgent re-tally always truncates `oos-accepted-design.md` and rewrites only the current round’s accepted OOS (`tally-plan-review.sh` lines 376–379). `persist-retally-step3-env.sh` merges in-scope findings into `accepted-plan-findings-all.md` on successful re-tally but has no symmetric OOS merge. On multi-round automatic continuation, OOS accepted in earlier rounds is dropped from the session-root cumulative file, so `render-final-summary.sh` under-counts OOS and Step 5b OOS filing can miss earlier-round acceptances. **Suggested fix:** After successful MainAgent re-tally, merge `oos-accepted-design.md` into a cumulative OOS artifact the same way in-scope findings are handled (e.g., call `_accumulate_round_oos` with the saved `.oos-accepted-design.prev.md`, or add an OOS merge helper in `persist-retally-step3-env.sh` using the existing description-key dedup), and add a multi-round harness case with prior-round OOS plus a later-round `main-agent-vote-required` re-tally.

- **correctness** `skills/design/scripts/persist-retally-step3-env.sh:110-144` — On successful re-tally (`tally-plan-review-status ok`), `_rewrite_env_file` refreshes `LOOP_STATUS` / `TALLY_PLAN_REVIEW_STATUS` and merges accepted blocks into `accepted-plan-findings-all.md`, but it preserves stale `ACCEPTED_COUNT`, `IMPORTANT_ACCEPTED_COUNT`, `NIT_ACCEPTED_COUNT`, and `NON_NIT_ACCEPTED_COUNT` from the prior `main-agent-vote-required` exit (typically zero) instead of recomputing them from `accepted-plan-findings.md`. Gate B reads the markdown file, so apply still works, but `.step3-plan-review-result.env` / `.step3-review-result.env` disagree with disk until something else overwrites them, which can mislead any consumer that trusts env KVs over artifacts (logging, resume, operator breadcrumbs). **Suggested fix:** On the `ok` path, recompute the four accepted-count KVs from `accepted-plan-findings.md` (reuse the counting helpers from `plan-review-loop.sh` or mirror `plan-review-continuation.sh`’s Python block) before writing both result env files; extend `test-persist-retally-step3-env.sh` to assert non-zero counts after a successful merge.

- **correctness** `skills/design/scripts/plan-review-loop.sh:598-613`, `skills/design/scripts/persist-retally-step3-env.sh:87-100` — Cumulative in-scope findings use two incompatible merge strategies: `_accumulate_round_accepted_all` blindly concatenates prior and current round blocks (no dedup), while `_merge_retally_accepted_all` deduplicates exact byte blocks. The same finding can therefore appear twice in `accepted-plan-findings-all.md` when an automatic round appends it and MainAgent re-tally later merges an identical block, or when two rounds accept byte-identical blocks via concatenation alone; `render-final-summary.sh:317` counts every `### FINDING_N:` header, inflating the Plan review line. **Suggested fix:** Unify cumulation on one idempotent merge (description-key or exact-block dedup, matching the OOS path) in both `_accumulate_round_accepted_all` and `_merge_retally_accepted_all`, and add a loop harness where round 2 re-tally merges a block already present from round 1’s accumulation.
