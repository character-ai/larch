### In-Scope Findings

- **correctness** `skills/design/scripts/render-final-summary.sh:253-272` — Part B fixes header-based counting, but Part A’s automatic multi-round loop makes the Plan review line systematically under-report in-scope findings. `accepted-plan-findings.md` is overwritten on every Step 3 re-entry (`skills/design/references/approval-gates.md:204`), while `oos-accepted-design.md` is accumulated across rounds (`plan-review-loop.sh` `_accumulate_round_oos`). The renderer sums both files at finalize time, so a run like round 1 with four accepted Important findings followed by a clean round 2 still prints `- **Plan review**: 0 findings` (or only last-round + cumulative OOS), reproducing the original “0 findings” operator confusion for the dominant in-scope case. **Suggested fix:** Aggregate across `plan-review/round-*/accepted-plan-findings.md` (or a dedicated run-total counter written each round) for the summary total; keep per-bucket breakdown explicit or document that only the final round’s in-scope set is shown.

- **correctness** `skills/design/SKILL.md:1274-1281` — The new heuristic continuation check implements only `IMPORTANT_ACCEPTED_COUNT >= 2` and never the planned convergence/continuation symmetry with `/implement` (`review-implement-step5-loop.sh:405-410` also continues on `structural_loc >= 100` or `fix_count >= 8`; `review-and-fix.sh` stops on `converged-small-changes` when a non-degraded round has ≤5 non-nit accepted and no Important findings). `NON_NIT_ACCEPTED_COUNT` / `NIT_ACCEPTED_COUNT` are emitted by `plan-review-loop.sh` but are not parsed in Step 3’s KV allowlist (`SKILL.md:1178-1196`), so the orchestrator cannot apply the convergence rule even if prose were added. A round with eight accepted medium (non-important) findings will stop after one pass here while `/implement` would auto-continue. **Suggested fix:** Extend Step 3 parsing to include `NON_NIT_ACCEPTED_COUNT`, `NIT_ACCEPTED_COUNT`, and `DEGRADED_PANEL`; mirror `/implement`’s continue (`important >= 2 || structural_loc >= 100 || accepted_non_nit >= 8`) and converge (`!degraded && non_nit <= 5 && important == 0`) predicates before looping back to Step 3.

- **correctness** `skills/design/scripts/test-render-final-summary.sh:40-67` — Regression coverage proves non-zero totals only when every fixture block includes `- **Focus area**: <value>`. Production templates allow omitting Focus area (`plan-review.md:180-190`), and the new awk END fallback (`render-final-summary.sh:283-285`) assigns those blocks to the low bucket without any test exercising a header-only `### FINDING_N:` block. A regression that drops the END fallback or breaks `inf` state across block boundaries would not fail CI. **Suggested fix:** Add a fixture with a `### FINDING_1:` block lacking Focus area (and optionally one with Focus area after other fields) asserting a non-zero Plan review line and correct low-bucket attribution.

- **correctness** `skills/design/scripts/render-final-summary.sh:275` — Block detection uses `^### (FINDING_|OOS_)[0-9]`, which is looser than the canonical artifact grammar `^### FINDING_[0-9]+:` / `^### OOS_[0-9]+:` used elsewhere (`plan-review-loop.sh:1516`, `plan-review-loop.sh:557`). A malformed header such as `### FINDING_:` (no index) or `### FINDING_1note:` could be counted in the summary but ignored by tally/grep helpers, producing summary totals that disagree with `ACCEPTED_COUNT` from `.step3-review-result.env`. **Suggested fix:** Align the awk header regex with `^### (FINDING_|OOS_)[0-9]+:` to match production writers and tallies.
