Reviewing the branch diff and commit history, then tracing how cumulative finding artifacts interact across review rounds.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:598-614` — `_accumulate_round_accepted_all` blindly concatenates each round’s `accepted-plan-findings.md` into `accepted-plan-findings-all.md`, while `_accumulate_round_oos` (lines 543–586) deduplicates OOS blocks by normalized description text. On automatic multi-round runs, a later panel can re-accept the same concern under a new `### FINDING_N:` header after Gate B has already applied an earlier version; both blocks remain in the cumulative file. `render-final-summary.sh` (lines 256–266) prefers `accepted-plan-findings-all.md` when non-empty and counts every `### FINDING_N:` header, so the posted `- **Plan review**:` line can over-count versus what was actually unique across rounds (the Part B fix regressed from “always 0” to “can inflate”). **Suggested fix:** Give in-scope accumulation the same semantic dedup shape as OOS (description/concern key, or location+concern prefix), or replace-per-round in the cumulative file and only append net-new blocks after Gate B apply; add a two-round harness asserting one logical finding accepted twice renders count 1.

- **risk-integration** `skills/design/scripts/design-step3-state.sh:71-73` — Gate C / Gate A manual re-entry (`: > .step3-reentry` → `--direct-review-entry`) clears `accepted-plan-findings-all.md` but leaves `oos-accepted-design.md` on disk. The next `plan-review-loop.sh` entry copies that file into `.oos-accepted-design.prev.md` and merges new accepted OOS forward (lines 1569–1586, 543–586), so prior manual/automatic OOS survives into the “fresh” manual panel run. That contradicts `approval-gates.md` State Invariants (“overwritten by the new manual run”) and can inflate OOS counts in `render-final-summary.sh` (lines 260–266) after Gate C “Re-run review panel”. **Suggested fix:** On `direct-review-entry`, also remove `oos-accepted-design.md` and `.oos-accepted-design.prev.md` (mirror the accepted-all reset), or truncate OOS at manual re-entry before the loop’s accumulate path runs; extend `test-design-step3-state.sh` to assert both cumulative files are cleared.

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:1623-1632` — The new `tally-error` branch restores `accepted-plan-findings-all.md` from `.accepted-plan-findings-all.prev.md` (matching OOS rollback) but does not restore or clear `accepted-plan-findings.md`, and it zeroes `IMPORTANT_ACCEPTED_COUNT` / nit counts while leaving `ACCEPTED_COUNT` whatever the partial tally wrote inside `_run_plan_review_round` (lines 1541–1544). `.step3-review-result.env` can therefore report `LOOP_STATUS=tally-error` with a non-zero `ACCEPTED_COUNT` while the cumulative file was rolled back and `accepted-plan-findings.md` may still hold partial tally output. Gate B is bypassed, but any consumer that trusts env KVs over files (logging, operator breadcrumbs, future automation) sees inconsistent cross-artifact state after a failed round in a multi-round sequence. **Suggested fix:** On `tally-error`, also restore or truncate `accepted-plan-findings.md` from a round-start snapshot (or force `ACCEPTED_COUNT=0` in the env write), matching the OOS/`accepted-all` rollback symmetry; add a harness case with prior cumulative + partial tally output asserting all three surfaces agree.

- **risk-integration** `skills/design/scripts/plan-review-continuation.sh:174-176` — `DEGRADED_PANEL` is read from `.step3-review-result.env` and, when set, forces `PLAN_REVIEW_CONTINUE=true` even if `accepted-plan-findings.md` is empty (`test-step3-review-cap.sh` lines 222–230 encodes this). After Gate B’s zero-findings short-circuit, the orchestrator still runs the continuation check (`SKILL.md` ~1274). A degraded panel that accepts nothing can therefore schedule up to four additional full review rounds (until `REVIEW_ROUND_COUNT >= 5`), consuming the shared cap without Gate B ever applying fixes—unlike `/implement`, which ties continuation to accepted-finding substance (`review-implement-step5-loop.sh` lines 405–411: `high_n >= 2`, structural LOC, fix count). **Suggested fix:** Require at least one accepted in-scope finding *or* a failed collector/panel signal that still produced ballot items before degraded continuation; alternatively continue degraded only when `NON_NIT_ACCEPTED_COUNT > 0` or `COLLECT_FAILURE_COUNT > 0` with a non-empty ballot, and stop pure zero-finding degraded rounds after one retry.

- **risk-integration** `skills/design/scripts/run-step3-review.sh:212-228` — Every automatic continuation re-invocation deletes all `plan-review/round-*` directories before launching the next round, while session-root cumulative files (`accepted-plan-findings-all.md`, `oos-accepted-design.md`) persist. Per-round forensics (ballots, classification TSV, `round-summary.env`) from earlier automatic rounds are destroyed even though the final summary reports their accepted findings cumulatively. That complicates diagnosing which round produced which accepted item and breaks the documented MAV path that writes `findings-classification-out` under `plan-review/round-${ROUNDS_COMPLETED}` (`SKILL.md` ~1224) for earlier rounds after a continue loop. **Suggested fix:** Stop wholesale `rm -rf plan-review/round-*` on automatic continuation (only prune rounds older than cap or snapshot before delete), or archive round-N to a stable path before cleanup; at minimum document that auto-continue is forensic-lossy except for cumulative session-root artifacts.
