### In-Scope Findings

- **risk-integration** `skills/implement/SKILL.md:776-782` — The Step 5 telemetry fence resolves `dynamic_archetypes_cap` as process `LARCH_DYNAMIC_ARCHETYPES_MAX` before `$IMPLEMENT_TMPDIR/session-env.sh`, but `scripts/run-step5-review.sh:169,236` reads only session-env and forwards a non-empty value as `--dynamic-archetypes` CLI, which `review-and-fix.sh:1221-1232` treats as highest precedence. `scripts/test-run-step5-review.md:11-13` documents that session-env is meant to override ambient shell env. When both sources differ, the banner can report one cap (e.g. ambient `7`) while the loop runs another (e.g. session-env `2` via CLI); when session-env is valid but ambient is out of range, the fence exits 2 and can block code review even though `run-step5-review.sh` would forward the valid session value. **Suggested fix:** Reorder the fence to read `LARCH_DYNAMIC_ARCHETYPES_MAX` from session-env first (matching `run-step5-review.sh`), fall back to non-empty process env only when session-env is empty, then default to `6`; validate after resolution; add a harness case with conflicting session-env vs ambient values asserting banner matches forwarded CLI.

- **risk-integration** `skills/implement/SKILL.md:812` — The new preflight-failure instruction (“Treat a non-zero fence exit or non-integer `PRIOR_DEGRADED_ROUNDS` as a hard Step 5 preflight failure and log it to `Warnings`”) does not specify control flow (abort Step 5 vs still invoke `run-step5-review.sh`) and does not include a literal `append-execution-issue.sh` invocation, unlike Step 2’s branch-mismatch path at `skills/implement/SKILL.md:630`. Given the #3448 `--step` misuse on this helper, orchestrators may either skip mandated review on fence exit 2 or fail logging again. **Suggested fix:** State explicitly that a failed telemetry fence must not invoke `run-step5-review.sh` (or must set `STALL_TRACKING` and route to Step 18), and add one fenced example: `append-execution-issue.sh --log "$IMPLEMENT_TMPDIR/execution-issues.md" --category Warnings --entry "- **Step 5**: banner preflight failed: …"`.

- **risk-integration** `skills/implement/SKILL.md:776,812` — The fence’s first tier `${dynamic_archetypes_value:-}` is inert inside the Bash subprocess: Step 0 persists the cap into session-env via `implement-bootstrap.sh:692` and `parse-bootstrap-routing-envelope.sh` does not export `dynamic_archetypes_value` to later fences. Prose at line 812 still claims that tier is active “with the same precedence `review-and-fix.sh` uses,” but the fence never sees it, so operators may believe Step 0’s validated cap is honored separately from session-env when it is not. **Suggested fix:** Drop the dead `${dynamic_archetypes_value:-}` branch from the fence and align prose with the actual source order (session-env → ambient → default), or export a durable key into session-env only and read that single source in both the fence and `run-step5-review.sh`.
