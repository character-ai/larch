## Accepted Findings

### FINDING_9: **risk-integration** `python/review_and_fix.py:1257-1264` — `_coder_timing_env` only sets `IMPLEMENT_TMPDIR` or `REVIEW_TMPDIR` when those keys are already missing (`if not env.get(...)`). It always overwrites `LARCH_TIMING_LEDGER`, but `launch-codex-exec` records `codex-review-fix` via an internal `timing record-vendor-task` call that passes **no** `--ledger` and relies on `resolve_timing_ledger_path()` env fallback. If a stale `IMPLEMENT_TMPDIR` or `REVIEW_TMPDIR` from a prior `/implement` or `/review` session is still in `os.environ`, validation of the resolved ledger can fail (ledger path is not under the stale root), and resolution silently falls through to `IMPLEMENT_TMPDIR/timing-ledger.tsv` per `python/timing.py:316-329`. Codex apply bars can land on the wrong ledger or stay missing; Cursor apply is safer because `_record_coder_vendor_task` passes explicit `--ledger`. **Suggested fix:** In `_coder_timing_env`, always bind the tmpdir key from `round_dir` layout (`IMPLEMENT_TMPDIR = round_dir.parent` for `round-<N>`, else `REVIEW_TMPDIR = round_dir`), not only when absent; add a regression test that sets a stale `IMPLEMENT_TMPDIR` and asserts the Codex subprocess env forces the resolved ledger path.
