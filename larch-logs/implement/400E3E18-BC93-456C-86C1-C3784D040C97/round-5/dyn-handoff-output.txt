### In-Scope Findings

- **risk-integration** `skills/implement/SKILL.md:826` — The `mav-resume-past-cap` branch re-invokes `record-implement-review-round-timing.sh` whenever `round-$FINAL_ROUND_NUM/round-start-s` exists, but that file is intentionally left behind by every deferred MAV/coder handoff and is only cleared implicitly by continuing the run. On the happy path the handoff block at lines 800–809 already records the round **before** `commit-review-fixes.sh` (Step 7 mark); resume then adds a second Step 5 mark (`scripts/run-step5-review.sh:239-240`) and the wrapper immediately returns `mav-resume-past-cap`. The second call replaces the ledger row (`skills/review-and-fix/scripts/record-implement-review-round-timing.sh:101-110`) with a much later `end_s`, and `scripts/timing-report.sh:384` only attaches rows when `round_end <= step_end`. Because the replacement `end_s` falls after the Step 7 boundary, the row no longer matches the original Step 5 interval and disappears from `timing-report.json` even though a ledger line remains — the opposite of the plan’s “record before Step 7 mark” guarantee. **Suggested fix:** Drop deferred recording from the `mav-resume-past-cap` branch (timing is already finalized in the MAV/coder handoff block), or gate it on “no existing implement/`Step 5 — code review`/round-N row with the persisted `start_s`” so a second emit cannot clobber a valid pre-commit row; add a harness that simulates record → Step 7 mark → Step 5 re-mark → `mav-resume-past-cap` and asserts the round still appears in rendered JSON with unchanged duration.

- **risk-integration** `skills/implement/SKILL.md:798-812` — The handoff bash fence always runs `git add -A` and `commit-review-fixes.sh` immediately after the deferred timing helper, while the prose one line above says terminal lint/check stalls must emit timing and **skip** the commit/reinvoke block. Unlike the loop script (which mechanically defers emission), this split is prompt-enforced only; an orchestrator that executes the whole fence after a lint stall would commit review fixes while `STALL_TRACKING=true`, advancing the tree and emitting the Step 7 timing mark before the run is supposed to stall — and any subsequent `mav-resume-past-cap` timing rewrite would be even further past the Step 5 window. **Suggested fix:** Split the SKILL into two fences (timing-only vs commit+resume), or add an explicit `if [ "$HANDOFF_TERMINAL_STALL" != true ]` guard around lines 810–821 so the mechanical contract matches the stall/resume prose.
