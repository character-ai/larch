Reviewing the branch diff and design-publish timing artifact changes.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/design-publish.sh:238-252,458-467` — Pre-publish timing render hard-fails when `jq` is absent (or when temp-dir/`timing-report.sh` render fails) and quarantines all `timing-report-final.*` artifacts, yet `design-log-publish.sh` still runs on the success path with `PUBLISH_OK=true` and nothing to stage. Post-publish `render-final-summary.sh` (lines 101-106) calls `timing-report.sh` directly into `$DESIGN_TMPDIR` without the same `jq` gate, so a run can merge committed design logs with no `timing-report-final.json` while the session tmpdir later holds fresh timing JSON (including the new per-round `rounds` data). Operators see a warning and may still get a normal publish outcome, but the committed run log permanently lacks per-round timing—the main acceptance target of this branch. **Suggested fix:** Treat pre-publish timing render as part of the publish gate: retry once, or fail closed / defer merge when render fails; alternatively, if post-publish render succeeds, block completion until a timing-only amend is flushed, or hoist the pre-publish render helper so both paths share identical validation and neither can succeed alone after the other failed.

- **risk-integration** `skills/design/scripts/design-publish.sh:217-229` — On `mktemp` failure the handler writes `timing-report-final.failure.log`, logs via `append-tool-failure.sh`, then immediately deletes it with `rm -f "$DESIGN_TMPDIR"/timing-report-final.*`, removing the very sidecar an operator would inspect after a failed publish prep. Only `execution-issues.md` retains the failure text (best-effort), and publish still proceeds with no timing artifact. **Suggested fix:** Exclude `timing-report-final.failure.log` from the cleanup glob (mirror the publish deny-list in `scripts/design-log-publish.sh:304`), or write failure diagnostics outside the `timing-report-final.*` namespace; optionally skip `design-log-publish.sh` when pre-publish render cannot allocate temp space.

- **risk-integration** `skills/design/scripts/design-publish.sh:260` — Pre-publish validation accepts any syntactically valid JSON via `jq -e .`, not a timing-report shape check (no `per_step`, no Step 3 entry, no `rounds`). A regressed or partial `timing-report.sh` output could be moved into `$DESIGN_TMPDIR` and staged into committed run logs while appearing “validated,” undermining the per-round telemetry this change adds. **Suggested fix:** Validate with a stricter `jq` filter (e.g. require `.per_step`, a matching plan-review step label, and array-typed `.rounds[]` when ledger round rows exist) before `mv`; on mismatch, quarantine like a render failure and emit a loud warning.

### Out-of-Scope Observations

- `render_fresh_timing_report_for_publish` in `skills/design/scripts/design-publish.sh` and `render_fresh_timing_report_for_pause_publish` in `scripts/design-pause-save.sh` are near-duplicates; drift between pause and final publish paths is a long-term maintenance risk but not a new regression by itself.

- `skills/design/scripts/test-design-publish.sh:553-572` asserts quarantine and exit 0 on `TIMING_REPORT_FAIL` but does not check that `.design-publish-result.env` carries the timing WARN or that the publish stub received no `timing-report-final.json`, leaving the committed-log gap above untested.

- `skills/design/scripts/render-final-summary.sh:87-88` intentionally deletes and re-renders timing JSON after publish; this recreates `timing-report-final.stderr.log` in the tmpdir (see `test-render-final-summary.sh:117`) but does not republish sidecars because `design-log-publish.sh` already merged—behavior appears intentional, not a stale-publish leak.
