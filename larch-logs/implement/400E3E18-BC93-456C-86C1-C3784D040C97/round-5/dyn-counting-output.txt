Reviewing the branch diff and round-timing helper count logic.
### In-Scope Findings
- **correctness** `skills/design/scripts/record-plan-review-round-timing.sh:50-65` — The design OOS counter walks `voting-tally.md` and increments whenever `Item` matches `OOS_N` and `Result` is exactly `accepted`, but `tally-plan-review.sh` still writes those rows for security-tagged OOS while deliberately excluding them from `oos-accepted-design.md` and other public OOS surfaces (see `skills/design/scripts/tally-plan-review.sh:505-506` and `skills/design/scripts/test-tally-plan-review.sh:79-81`). Per-round `oos` in `timing-report.json` will therefore overcount relative to the accepted-OOS count the rest of `/design` treats as durable/fileable. **Suggested fix:** Align OOS counting with tally’s security carve-out (e.g., skip `OOS_N` rows whose block has an unfenced `focus-area = security`, or count from `oos-accepted-design.md` / round snapshot instead of raw `voting-tally.md`), and add a harness case mirroring `test-tally-plan-review.sh`’s security exclusion.

- **correctness** `skills/review-and-fix/scripts/record-implement-review-round-timing.sh:82-94` — Rejected-count fallback checks `review-summary.json` before the `rejected-findings.md` grep, which is the reverse of the plan’s precedence (`grep` compact `FINDING_N_OUTCOME=rejected` rows first, then JSON only if still ambiguous). That matters on deferred handoff paths: MAV re-tally rewrites `round-N/rejected-findings.md` to prose `### [rejected] FINDING_N` headings via `tally-code-votes.sh` and does not refresh `review-summary.json` (only `emit-tally.sh` writes that file). If `round-N/review-tally.env` is missing or unreadable, the helper will emit stale pre-MAV `rejected_count` from JSON and never reach a grep that could work on the compact pre-MAV artifact. **Suggested fix:** Swap the fallback order to grep `rejected-findings.md` first, then `review-summary.json`; optionally add a prose-heading fallback (`^### \[rejected\] FINDING_[0-9]+`) for post-MAV artifacts, and extend `test-record-implement-review-round-timing.sh` with a fixture where tally.env is absent, JSON is stale, and compact vs prose rejected files disagree.
