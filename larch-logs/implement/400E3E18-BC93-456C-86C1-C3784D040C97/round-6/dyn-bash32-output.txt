### In-Scope Findings

- **correctness** `skills/design/scripts/record-plan-review-round-timing.sh:42-55` — The helper switches `artifact_root` to `plan-review/round-N/` whenever that directory exists, even if it only contains `round-start-s` or a pre-MAV snapshot. On the deferred `main-agent-vote-required` path, `plan-review-loop.sh` snapshots round artifacts before the orchestrator re-runs `tally-plan-review.sh`, so session-root `accepted-plan-findings.md`, `rejected-findings.md`, and `voting-tally.md` reflect post-adjudication counts while the round directory still holds pre-MAV data. The helper then records stale accepted/rejected/OOS counts (often zeros when snapshot files are missing from the round dir). **Suggested fix:** Count from `$DESIGN_TMPDIR` session-root artifacts after tally for deferred MAV emission; reserve the round-directory override for cases where only snapshotted per-round copies exist and session-root files were cleared, or pass explicit counts into the helper from the orchestrator after re-tally.

- **code-quality** `skills/design/scripts/design-publish.sh:259-265` — Pre-publish validation requires a design Step 3 `per_step` entry with a `rounds` array. `timing-report.sh` omits `rounds` when no ledger rows match the step interval, so a valid report (Step 3 mark present, timing render succeeded, but round rows missing or misattached) fails validation and the publish path deletes all `timing-report-final.*` artifacts. That drops the entire timing report instead of publishing the base JSON. `design-pause-save.sh` uses the looser `jq -e .` gate, so pause and normal publish behave inconsistently. **Suggested fix:** Validate structural JSON only (`workflow_path`, `per_step` array, `total_seconds`, `total_hms`) and treat `rounds` as optional; or accept Step 3 entries with or without `rounds`, logging a warning when round telemetry is absent.

- **code-quality** `skills/review-and-fix/scripts/review-implement-step5-loop.sh:3289-3312` — `_emit_implement_round_timing_row` always forwards `IRF_LAST_*` counts to `record-implement-review-round-timing.sh`, which skips `review-tally.env` whenever either argument is non-empty (including `"0"`). That is fine for in-loop emission, but the same helper is reused for deferred handoffs where post-MAV/post-checks counts live in `round-N/review-tally.env`. The orchestrator path omits `--accepted`/`--rejected`, so it is safe today; the in-loop path hard-codes the bypass and will silently ignore a refreshed round-local tally if a future caller passes explicit zeros. **Suggested fix:** Only pass `--accepted`/`--rejected` when intentionally overriding tally lookup (e.g., add an explicit `--prefer-tally` flag, or pass counts only when `IRF_LAST_*` is known fresh and omit the flags otherwise so the helper reads `review-tally.env` first).

- **code-quality** `scripts/timing-report.sh:381-415` — `emit_round_array` uses `match_idx` and `round_match_pos` as undeclared global awk arrays (not listed in the function-local list). Cleanup runs only when `mc > 0`; an early `return` on `mc == 0` is safe today, but the globals make the renderer fragile if the function is extended or called reentrantly. **Suggested fix:** Add `match_idx` and `round_match_pos` to the awk function-local list (`function emit_round_array(..., i, j, ..., match_idx, round_match_pos)`) and clear them on every exit path.

### Out-of-Scope Observations

No Bash 4+ constructs (`declare -A`, `mapfile`, namerefs, `${var^^}`, `&>>`, coprocs) appear in the changed shell scripts; quoting, `set -e`/`pipefail` interaction with `|| true` on grep/telemetry paths, and nawk-compatible awk usage look consistent with macOS Bash 3.2 expectations. The duplicate timing-render blocks in `design-publish.sh` and `design-pause-save.sh` are a maintainability smell but not a runtime defect in this diff.
