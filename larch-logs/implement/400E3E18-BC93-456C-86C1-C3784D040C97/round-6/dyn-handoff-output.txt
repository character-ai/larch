### In-Scope Findings

- **risk-integration** `skills/design/scripts/record-plan-review-round-timing.sh:42-71` — On multi-round `/design` runs, `main-agent-vote-required` exits through `_snapshot_terminal_exit_preserving_status`, which snapshots the round directory **before** `skills/design/SKILL.md` performs inline MAV adjudication and re-runs `tally-plan-review.sh`. The deferred helper then prefers `plan-review/round-N/` whenever that directory exists, so it reads the pre-MAV snapshot copies of `accepted-plan-findings.md`, `rejected-findings.md`, and `voting-tally.md` instead of the post-MAV session-root tallies that re-tally just wrote. Per-round `accepted`, `rejected`, and `oos` in `timing-report.json` can therefore be frozen at 0-judge fallback values even though Gate B and later steps use corrected counts; legacy single-pass MAV avoids this because it never snapshots before deferred emit. **Suggested fix:** For deferred MAV emission, count from `$DESIGN_TMPDIR` session-root artifacts (or add a `--prefer-session-artifacts` flag / only use `plan-review/round-N` when session-root tally files are absent), and add a multi-round MAV harness that snapshots, re-tallies into session root with different counts, then asserts the ledger row matches the post-MAV tallies.

- **risk-integration** `skills/design/scripts/record-plan-review-round-timing.sh:81-87` — Idempotency is keyed only on `(skill, step, round)` and exits before writing when any matching ledger row exists, without comparing `start_s`/`end_s` or counts. Combined with the MAV snapshot ordering above, a first deferred emit can permanently lock in stale counts; a later correction path (or a `mav-resume-past-cap`-style retry) cannot replace the row. **Suggested fix:** Either prefer session-root artifacts so the first deferred emit is correct, or tighten idempotency to match the implement helper’s `(round, start_s, end_s)` tuple and allow a single superseding write when counts differ after post-MAV re-tally.
