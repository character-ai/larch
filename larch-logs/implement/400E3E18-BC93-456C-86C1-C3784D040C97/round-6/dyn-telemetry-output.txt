Reviewing the branch diff and commit history for telemetry architecture issues.
### In-Scope Findings

- **architecture** `skills/design/scripts/record-plan-review-round-timing.sh:42-72` — Deferred MAV timing is wired to read counts from `plan-review/round-N/` whenever that directory exists, but MAV defers emission until after `skills/design/SKILL.md` re-tallies into session-root artifacts. Multi-round MAV snapshots pre-adjudication tallies into `plan-review/round-N/` (`plan-review-loop.sh:440-446`); legacy MAV only creates `round-start-s` there (`plan-review-loop.sh:1428-1435`) with no tally files. In both cases the helper prefers the round directory over `$DESIGN_TMPDIR`, so post-MAV accepted/rejected/OOS counts are ignored (stale snapshot counts on multi-round MAV, often all zeros on legacy MAV). That breaks the hard-required per-round count contract and diverges from `/implement`, where MAV re-tallies into `round-$N/review-tally.env` before `record-implement-review-round-timing.sh` runs. **Suggested fix:** For deferred MAV, count from session-root post-re-tally artifacts (add a `--prefer-session-root` flag or only switch to `plan-review/round-N/` when tally files are present and newer than MAV), or re-snapshot/copy post-MAV `accepted-plan-findings.md`, `rejected-findings.md`, and `voting-tally.md` into the round directory before emitting.

- **architecture** `skills/design/scripts/design-publish.sh:259-265` — Pre-publish validation requires a `design Step 3 — plan review` `per_step` row with a `rounds` array, but `scripts/timing-report.sh` treats `rounds` as optional (no matching ledger rows → no `rounds` key) and `docs/run-logs.md:379` documents it as “may include.” Legitimate design paths still emit the Step 3 timing mark but never write round rows (review-round cap reached, panel/tally short-circuits, telemetry failure). Those runs fail validation, `timing-report-final.json` is quarantined, and committed design run logs lose timing telemetry despite a valid ledger. **Suggested fix:** Relax publish validation to require only well-formed top-level JSON (`jq -e .` / `per_step` array), matching `scripts/design-pause-save.sh:288`; treat `rounds` as optional unless round ledger rows exist.

- **architecture** `scripts/timing-report.sh:381-384` vs `docs/run-logs.md:379` — Round attachment checks only `round_start ∈ [step_start, step_end)` and never validates `round_end`. The run-log contract says the step interval must fully contain both start and end. A deferred row recorded late (but with an early persisted `round-start-s`) can attach to Step 5/Step 3 even when `end_s` falls in a later step interval, inflating per-step review duration and misplacing rounds in JSON. **Suggested fix:** In `emit_round_array`, require `round_start >= start && round_end < end` (or `round_end <= end` if half-open on both sides), drop non-conforming rows, and add a harness case for deferred handoff near the next step mark.

### Out-of-Scope Observations

- **architecture** Design timing JSON is rendered through three paths with different contracts: `design-publish.sh` (strict `rounds` gate), `design-pause-save.sh` (generic `jq -e .`), and `render-final-summary.sh` (no `rounds` validation). This branch adds the pause-save path without unifying validation, so pause vs normal publish can produce different `timing-report-final.json` outcomes from the same ledger.

- Downstream consumers (`scripts/measure-realized-cost.sh`, `python/report_tokens_scan.py`) read only top-level `per_step` fields and ignore `rounds`; additive JSON remains backward-compatible for those tools.
