**[FINDING_1]**  
**Severity:** Nit  
**Category:** Plan-Fidelity / Correctness  
**File:** `scripts/timing-report.sh`, lines 385–386, 413  
**Title:** `emit_round_array` uses `round_num[i] + 0` as AWK array subscript for `round_match_pos` — minor deviation from plan's "never use field values as subscripts" guidance

**Description:**  
The plan states that dedup in `emit_round_array` should be done by iterating and checking for duplicate `round_num` values, without using field values as array subscripts. The implementation uses `rkey = round_num[i] + 0` as a subscript in `round_match_pos[rkey]`:

```awk
rkey = round_num[i] + 0
if (!(rkey in round_match_pos)) {
    match_idx[++mc] = i
    round_match_pos[rkey] = mc
} else {
    match_idx[round_match_pos[rkey]] = i
}
```

This is a minor deviation. The `+ 0` coerces the value to a numeric integer, and round numbers are validated upstream (by `cmd_record_round()`) to be non-negative integers. So the subscript is a bounded, validated integer — not a raw field value. AWK arrays keyed by integer are safe, and the logic correctly deduplicates by round number (last-write-wins keeps most-recent row). The cleanup loop (line 413) also correctly deletes using the same `round_num[match_idx[i]] + 0` form. Behavior is correct; the deviation is stylistic relative to plan guidance.

**Recommendation:** No action required. Document the `+ 0` coercion rationale in a brief inline comment if plan guidance will be enforced strictly in future review rounds.

**[FINDING_4]**  
**Severity:** Nit  
**Category:** Plan-Fidelity (Single Terminal Hook Contract)  
**File:** `skills/design/scripts/plan-review-loop.sh`, lines 1470–1487  
**Title:** `panel-failed` path uses direct `_emit_plan_round_timing_row` + `_terminal_exit` instead of routing through `_snapshot_terminal_exit_preserving_status`

**Description:**  
The plan explicitly lists `panel-failed` as one of the terminal exit paths that should be consolidated under the `_snapshot_terminal_exit_preserving_status` hook. The implementation instead calls `_emit_plan_round_timing_row` + `_terminal_exit` directly in both the `snapshot-failed` sub-path (lines 1479–1483) and the main `panel-failed` path (lines 1485–1487):

```bash
if (( _round_rc != 0 )); then
    ...
    if ! _snapshot_round_dir "$round_num"; then
        ...
        _emit_plan_round_timing_row "$round_num" "${_round_start:-}" "$(_plan_round_now_s)"
        _write_round_summary "$round_num" panel-failed snapshot-failed skipped
        _terminal_exit 1 "$round_num"
    fi
    _emit_plan_round_timing_row "$round_num" "${_round_start:-}" "$(_plan_round_now_s)"
    _write_round_summary "$round_num" panel-failed panel-failed skipped
    _terminal_exit 1 "$round_num"
fi
```

The timing row IS correctly emitted in both sub-paths. The practical impact is zero — no round timing is lost. The deviation is that future changes to `_snapshot_terminal_exit_preserving_status` (e.g., adding a new side-effect) will not automatically apply to `panel-failed` exits. This is a maintainability concern, not a correctness bug.

**Recommendation:** Consider refactoring `panel-failed` to route through `_snapshot_terminal_exit_preserving_status` (with appropriate `revise_status=skipped` and `rc=1` plumbing) to honor the plan's single-hook invariant. Low urgency.
