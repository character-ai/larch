### In-Scope Findings
- **risk-integration** `skills/implement/SKILL.md:796-822` — The MAV/coder handoff path merges deferred `record-implement-review-round-timing.sh`, `git add -A`, `commit-review-fixes.sh` (which always writes a Step 7 timing mark), and loop resume into one unconditional bash fence, while prose at 796 only says to skip commit/resume on terminal stall after checks/lint. That gate is prompt-only; an orchestrator that runs the full fence after a terminal lint stall will still commit and re-invoke Step 5, breaking the plan’s record-before-Step-7 ordering and risking wrong resume behavior after a handoff that was meant to terminate. **Suggested fix:** Split the fence into separate blocks (record-only vs record+commit+resume), or add a mechanical guard (e.g. only run commit/resume when a success sentinel is set and stall paths invoke a record-only fence copied from 800-809).

- **risk-integration** `skills/implement/SKILL.md:781,826` — The generic `stall` and `mav-resume-past-cap` branches tell the orchestrator to read `round-$FINAL_ROUND_NUM/round-start-s` and pass `$round_start_s` into `record-implement-review-round-timing.sh`, but unlike the handoff fence at 800-809 they provide no fenced read. - **risk-integration** `skills/design/SKILL.md:1160` — Design MAV deferred timing is documented only “after successful re-tally”; if inline re-tally returns `tally-error`, the prose routes to the tally-error short-circuit with no `record-plan-review-round-timing.sh` call, even though `plan-review-loop.sh` already persisted `plan-review/round-N/round-start-s` and deferred emission. MAV adjudication wall time is then lost, unlike implement’s explicit stall emit for handoff paths. **Suggested fix:** Before the tally-error short-circuit on the MAV path, read preserved `round-start-s`, set a fresh `end_s`, invoke `record-plan-review-round-timing.sh` with best-effort counts from artifacts present (or zero counts), matching implement’s “terminal stall still emits deferred row” behavior.
