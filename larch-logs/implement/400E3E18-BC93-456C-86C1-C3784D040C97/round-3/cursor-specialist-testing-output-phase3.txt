4. **Latent** `risk-integration` `skills/review-and-fix/scripts/review-implement-step5-loop.sh:101-128` — The one-shot guard in `_emit_implement_round_timing_row` is set only when the post-write awk verify finds a row matching the exact `$7 == s && $8 == e` (start and end timestamps). If `timing-ledger.sh` exits 0 but the row is not immediately visible on the verify read (e.g., a write-visibility delay on tmpfs without flock, or the ledger path resolves differently in the env-prefixed invocation vs. the verify read), the guard is never set and a second call with a different `end_s` will write a duplicate row. The deferred helper (`record-implement-review-round-timing.sh`) uses a round-number-only idempotency check, so cross-path duplicates are safe, but two in-loop rows for the same round would produce inflated `duration_seconds` in the JSON. **Suggested fix:** switch the guard-set condition to check only round number (`$6 == r`) rather than pinning `$7` and `$8`.

The plan's plan requirement is "leave no top-level `timing-report-final.*`"; the test covers only two of three possible extensions. **Suggested fix:** add `[[ ! -f "$D_FAIL_TIMING/timing-report-final.failure.log" ]] || fail "failed render must remove timing-report-final.failure.log"` alongside the existing assertions.
