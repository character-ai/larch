### In-Scope Findings

- **code-quality** `skills/design/scripts/plan-review-loop.sh:429-431` — `_emit_plan_round_timing_row` sets the one-shot guard (`printf -v "$guard_var" '%s' true`) unconditionally before validating `start_s`/`end_s`. If `_round_start` is empty (e.g., `date +%s` fails), the guard fires permanently but no ledger row is written, silently dropping that round's timing data with no retry path. The implement-side peer `_emit_implement_round_timing_row` in `skills/review-and-fix/scripts/review-implement-step5-loop.sh:105-125` correctly validates first and only sets its guard after confirming the row was written to the ledger. **Suggested fix:** Move the `printf -v "$guard_var" '%s' true` line to after the `=~` validation guards and after the helper returns successfully (mirroring the implement-side pattern), or at minimum move it to after the `=~` checks so an invalid/empty `_round_start` does not permanently consume the guard.

- **code-quality** `skills/design/scripts/record-plan-review-round-timing.sh:56-60` — The AWK OOS tally uses `gsub(/^[[:space:]]+|[[:space:]]+$/, "", item)` and the same pattern on `result`. ERE alternation (`|`) in awk gsub is POSIX-compliant and supported by macOS awk ≥ 2007, but the macOS system awk (one-true-awk) has historically had edge cases with `|` inside `gsub` patterns in certain versions. If `|` is treated as a literal character, `item` and `result` retain their surrounding whitespace, `item ~ /^OOS_[0-9]+$/` never matches whitespace-padded field values, and OOS counts are always 0 for all design timing rows. The committed test `test-record-plan-review-round-timing.sh` asserts `$12 == 1` (OOS=1) and would fail on such a system, but CI on Linux with gawk/mawk would pass silently. **Suggested fix:** Replace each `gsub(/^[[:space:]]+|[[:space:]]+$/, "", x)` call with two separate calls: `gsub(/^[[:space:]]+/, "", x); gsub(/[[:space:]]+$/, "", x)`. This is unambiguously portable across all awk implementations.

- **risk-integration** `skills/review-and-fix/SKILL.md` — The updated harness reference list adds `${CLAUDE_PLUGIN_ROOT}/skills/review-and-fix/scripts/test-review-implement-step5-loop-timing.sh` as a contract path, but this file is untracked and not committed in this diff (visible as `?? skills/review-and-fix/scripts/test-review-implement-step5-loop-timing.sh` in the working tree). ### Out-of-Scope Observations

- **code-quality** `scripts/timing-report.sh` (existing) — The `emit_round_array` function uses `match_idx` and `round_match_pos` as global awk arrays without explicit `delete match_idx` across a `mc == 0` return (no entries were added, so no cleanup needed — this is correct). But since `match_idx` is not declared as a local array in awk, the sort loop uses indices `1..mc` which may collide across calls if a previous call with a larger `mc` didn't clean up fully. Inspection shows the cleanup loop `for (i = 1; i <= mc; i++) { delete match_idx[i] }` correctly removes exactly the entries that were added. This is safe but fragile — a future caller that adds `match_idx` entries outside the function would silently corrupt the sort.
