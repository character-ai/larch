Reviewing the branch diff and git history, focusing on design timing publish and artifact-handling risks.
### In-Scope Findings
- **risk-integration** `scripts/design-pause-save.sh:213-224` — The branch adds a pre-publish fresh render in `design-publish.sh` (`render_fresh_timing_report_for_publish`, lines 215–276, invoked at 459) so committed run logs get up-to-date `timing-report-final.json` with per-round `rounds`, but the pause publish path still calls `design-log-publish.sh` directly with no equivalent render or stale-artifact cleanup. A pause after Step 3 (or any `.pause-requested` exec from `design-postplan-emit.sh` / `SKILL.md`) can therefore flush either no `timing-report-final.json` or a pre-round JSON left in `$DESIGN_TMPDIR`, while `timing-ledger.tsv` already contains new `round` rows. That violates the acceptance goal that per-round timing live in the committed timing-report artifact, and it is worse than before because round detail now depends on a fresh JSON render rather than living only in the opaque Step 3 mark. **Suggested fix:** Extract `render_fresh_timing_report_for_publish` into a shared helper (for example `skills/design/scripts/render-design-timing-for-publish.sh`) and invoke it from both `design-publish.sh` and `design-pause-save.sh` immediately before every `design-log-publish.sh` call; add a pause-path harness asserting stale `timing-report-final.*` sidecars are removed and fresh JSON is present (or explicitly absent with a warning) before staging.

- **risk-integration** `scripts/design-log-publish.sh:303-306` — This branch adds explicit exclusions for `timing-report-final.stderr.log` and `timing-report-final.failure.log`, which is the right publish-surface hardening, but `scripts/test-design-log-publish.sh` has no coverage for those exclusions (grep finds no `timing-report-final` references). A later edit to the exclusion glob or staging loop could silently re-publish diagnostic sidecars into `larch-logs/design/<run-id>/`, which is exactly the leak class the design-publish changes were meant to close. **Suggested fix:** Extend `scripts/test-design-log-publish.sh` with fixtures that place `timing-report-final.stderr.log`, `timing-report-final.failure.log`, and valid `timing-report-final.json` under a design tmpdir and assert only the JSON is staged into the run-dest tree.

### Out-of-Scope Observations
- **risk-integration** `skills/design/scripts/design-publish.sh:217-229` — On `mktemp` failure the handler writes `timing-report-final.failure.log`, passes it to `append-tool-failure.sh`, then immediately deletes it via `rm -f "$DESIGN_TMPDIR"/timing-report-final.*`; publish safety is preserved, but the on-disk failure artifact is self-deleted before any later inspection.
- **correctness** `skills/design/scripts/record-plan-review-round-timing.sh:44-49` — Per-round accepted/rejected counts are taken from session-root tally files, not round-local snapshots, so multi-round JSON can attribute cumulative counts to individual rounds; that predates the publish changes and is outside the artifact-publish focus.
