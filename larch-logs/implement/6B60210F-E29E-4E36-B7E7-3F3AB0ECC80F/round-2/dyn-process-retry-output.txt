Reviewing the branch diff and git history, focusing on subprocess, retry, gh/git, and agent launcher correctness.
### In-Scope Findings

- **correctness** `python/gh.py:50-61,83-90` — `_retry_read` always funnels through `_ensure_success`, so after `with_transient_retry` exhausts on a transient signature the helper raises `ShipError` instead of returning the last `CommandResult`. The Phase 1 plan explicitly requires read-op exhaustion to return the last result for caller-side handling, and the live bash path (`ship_pr_with_transient_retry` in `scripts/ship-pr.sh:2653-2668`) treats exhausted transient retries as a distinct terminal outcome (`exit_transient_net`), not a generic command failure. **Suggested fix:** Have `_retry_read` return `retried.value` (or a small wrapper carrying `RetryResult` metadata) and let typed callers decide whether to parse JSON, raise, or map transient exhaustion to `Outcome.TRANSIENT`/`TransientNetworkError`; reserve `_ensure_success` for call sites that truly require fail-fast semantics.

- **correctness** `python/gh.py:130-166` — `pr_create` only deduplicates via a pre-flight `pr_for_branch` lookup and then performs a single non-retried `gh pr create`. It does not implement the bash recovery path in `scripts/create-pr.sh:192-229` (`recover_existing_pr_after_create_conflict`), which handles the documented race where `gh pr list --head` returns empty but `gh pr create` fails with “pull request for branch … already exists” (see `scripts/create-pr.md:74-83`). When Phase 7 wires this module in, that window becomes a hard failure or duplicate-create attempt instead of idempotent recovery. **Suggested fix:** After a non-zero create, inspect combined stdout/stderr for the conflict shape and re-query `pr_for_branch` (with the same retry policy as other reads) before surfacing failure; mirror the bash fallback URL/title extraction only if list recovery is inconclusive.

- **correctness** `python/gh.py:143-159` — `pr_create` passes the PR body via inline `--body`, while the live path in `scripts/create-pr.sh:268-275` uses `--body-file` after redaction. Large implement plans can exceed per-argument size limits or behave differently under `gh` than file-based submission, and this repo’s own `lint-gh-body-inline` rule exists because inline bodies are a known footgun. **Suggested fix:** Accept a filesystem path (or write body to a tmp file internally), invoke `gh pr create … --body-file <path>`, and align other create flags with `create-pr.sh` (`--base`, `--assignee @me`) so argv construction matches production behavior.

- **correctness** `python/test_gh.py:170-177` — The plan requires unit tests proving idempotent `gh` read helpers re-invoke on simulated transient signatures and do **not** retry mutating ops. Tests cover deduplication, JSON parsing, and a single-shot non-transient failure (`test_pr_view_raises_before_json_on_failure`), but there is no test that feeds two transient `CommandResult`s then a success and asserts multiple runner invocations for `pr_view`/`run_list`/etc., nor a test that transient exhaustion returns/behaves per policy rather than only raising on the first failure. **Suggested fix:** Add `RecordingRunner` scenarios: (1) two transient stderr blobs then success → assert three calls and parsed record; (2) three transient failures → assert call count == `config.TRANSIENT_RETRY_MAX_ATTEMPTS` and document expected exhaustion semantics once `_retry_read` is fixed.

### Out-of-Scope Observations

- **correctness** `python/retry.py:45-54` — The ordered substring checks for `EOF`/`during`, `git fetch`/`failed`, and `lookup`/`no such host` match bash `case` glob left-to-right semantics (verified against `scripts/test-lib-net.sh:95-99`); the parity vectors `"failed during EOF cleanup"` and `"failed after git fetch"` in `python/test_retry.py:55-56` correctly expect non-transient classification in both implementations.

- **architecture** `python/agents.py:123-166` — `launch_tier` invokes `scripts/launch-*-ci.sh` directly without a `bash` prefix; this mirrors ship-pr’s executable-script invocation and is acceptable when `cwd` is the repo root and scripts remain `+x`.
