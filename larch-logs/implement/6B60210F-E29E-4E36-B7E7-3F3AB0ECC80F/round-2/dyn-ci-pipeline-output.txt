Reviewing CI integration: reading the diff and key integration files.
### In-Scope Findings

- **risk-integration** `scripts/relevant-checks.sh:177` — The Python routing glob lists `python/*.py`, `pyproject.toml`, `ruff.toml`, `pyrightconfig.json`, and the requirements files, but not `python/.pylintrc`. A branch that only changes pylint configuration will not run `py-lint` or `py-test` during `/implement` relevant-checks, while CI `python-lint` still runs pylint over the full tree and can fail on config-only PRs the local gate never exercised. **Suggested fix:** Add `python/.pylintrc` to the same `case` pattern (and extend `scripts/test-relevant-checks.sh` with a `.pylintrc`-only fixture).

- **risk-integration** `scripts/relevant-checks.sh:177-179` — `maybe_append_py_lint_target` skips `py-lint` when `ruff`/`pylint`/`pyright` are missing, but `py-test` is always appended with no `pytest` probe. An implement session that touches `python/*.py` without `pytest` on `PATH` will fail relevant-checks (non-zero exit) even though the documented “graceful skip” path only covers lint tools; harness section 3k encodes this asymmetry as expected behavior. **Suggested fix:** Mirror the lint helper with a `maybe_append_py_test_target` that warns and skips when `pytest` is absent, or document that `pip install -r python/requirements-test.txt` is mandatory before any Python edit (and fail fast with an explicit install hint).

- **risk-integration** `scripts/test-ship-pr.sh:3454-3462` — `ship-pr.sh` maps `python-lint` → `make py-lint` and `python-tests` → `make py-test`, and `test-ci-failed-jobs.sh` now requires those workflow job IDs in the classifier, but the per-job argv regression stub still only asserts legacy jobs (`lint`, `shellcheck`, `test-harnesses`, etc.). A broken or missing `_per_job_argv` branch for the new jobs would not be caught by this harness despite the test name claiming alignment with workflow jobs. **Suggested fix:** Add `check_case python-lint "" "make py-lint"` and `check_case python-tests "" "make py-test"` to the stub (or generate cases from the workflow job list like `test-ci-failed-jobs.sh` does).

- **risk-integration** `scripts/ship-pr.sh:2166-2170` — When CI reports a failed `python-lint` job, ship-pr replays `make py-lint`, which runs `pyright` but does not run `actions/setup-node@v5` or `pip install -r python/requirements-dev.txt` the way `.github/workflows/ci.yaml:431-436` does. A fix loop can fail locally on pyright/Node or unpinned-tool drift while CI is green (or vice versa), unlike the explicit install steps in the dedicated CI job. **Suggested fix:** Either wrap replay in a small helper that installs `python/requirements-dev.txt` and documents/verifies Node (matching CI), or document in `python/README.md` and ship-pr breadcrumbs that per-job replay requires the same prereqs as `make py-lint` plus Node for pyright.

- **risk-integration** `Makefile:25-31` — `lint` now depends on `py-lint` and `py-test` before harnesses and pre-commit, but neither target installs deps; contributors following AGENTS.md (“run `make lint`”) without prior `pip install` of both requirements files will fail at the first Python step. CI never runs the umbrella `lint` target—it uses separate `python-lint` / `python-tests` jobs with installs—so this widens local-vs-CI drift for the common dev entrypoint. **Suggested fix:** Either remove `py-lint`/`py-test` from the `lint` prerequisite chain (keep them as explicit/CI-only targets), or add install/bootstrap steps or documented prerequisites in `docs/linting.md` and the `lint` comment block.

### Out-of-Scope Observations

- **risk-integration** `docs/linting.md:292` — The CI usage bullet still lists `shellcheck`, `agent-lint`, `gitleaks`, etc., but does not mention the new `python-lint` / `python-tests` jobs or their split requirements files; only the relevant-checks bullet was updated. Worth a doc pass so operators know PR CI now includes two additional gates.

- **risk-integration** `python/README.md:26-31` — Documents pip installs for Python tools but not that `pyright` (via `make py-lint`) needs a Node runtime on the host, which CI supplies via `setup-node` and local replay does not.
