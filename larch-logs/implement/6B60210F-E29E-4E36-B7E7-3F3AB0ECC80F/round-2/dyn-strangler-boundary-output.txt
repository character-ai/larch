### In-Scope Findings

- **risk-integration** `Makefile:25` — The branch prepends `py-lint` and `py-test` to the repo-wide `lint` target (`lint: py-lint py-test test-harnesses …`), but Phase 1 only promised standalone `make py-lint` / `make py-test` plus CI jobs. That folds the new Python dev toolchain (pip-installed `ruff`/`pylint`/`pyright`/`pytest`, plus Node for pyright) into the default contributor path documented as `make lint` in `AGENTS.md`, so a normal bash-only lint run now fails at the first Python prerequisite even when the diff never touches `python/`. **Suggested fix:** Drop `py-lint` and `py-test` from the `lint` prerequisite list; keep them as explicit/CI/relevant-checks-only targets so the strangler tree stays opt-in until Phase 7.

- **risk-integration** `scripts/ship-pr.sh:2166-2170` — Live `/implement` Step 8 CI replay now maps `python-lint` / `python-tests` to bare `make py-lint` / `make py-test`, but unlike the GitHub Actions jobs (`.github/workflows/ci.yaml:421-458`) neither `ship-pr.sh` nor `lint-fix-loop.sh` runs `pip install -r python/requirements-dev.txt` / `requirements-test.txt` or `setup-node` before replay. On typical agent hosts without those tools preinstalled, a failing Python CI job is classified fixable via `scripts/ci-failed-jobs.sh:31` yet local replay fails immediately, burning fixer iterations and often ending in `ci-local-unfixable` instead of a recoverable loop—the opposite of the allowlist’s intent. **Suggested fix:** Add a small replay wrapper (or extend `_per_job_argv`) that installs the pinned requirements (and documents Node for pyright) before invoking the Make targets, or gate replay with the same PATH checks used in `scripts/relevant-checks.sh:47-63` and fall back when tools are absent.

- **risk-integration** `scripts/relevant-checks.sh:177-179` — `/implement` and `/review` call `run-relevant-checks-captured.sh` → `relevant-checks.sh`; for `python/*.py` (and listed config files) the script always appends `py-test` while only `py-lint` is guarded by `maybe_append_py_lint_target` (`scripts/relevant-checks.sh:47-63`). A host with bash/pre-commit tooling but no `pytest` on PATH therefore hard-fails Step 3/5/6 when the run touches `python/`, even though lint tools are skipped with a warning—this is a new live-orchestration dependency on the Phase 1 tree beyond “CI job names only.” **Suggested fix:** Mirror the py-lint guard for `pytest` (warn-and-skip when missing, document required `pip install -r python/requirements-test.txt` in `docs/linting.md` / install docs), or treat missing pytest as exit 2 with an explicit install hint rather than an opaque `make py-test` failure.
