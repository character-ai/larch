Reviewing the redaction implementation and parity tests against the bash sources.
### In-Scope Findings

- **security** `python/test_redact.py:95-114` — Bash parity coverage is far below what Phase 1 acceptance and the plan’s testing strategy require. Only two single-vector checks exist (`test_parity_redact_secrets_sample`, `test_parity_redact_tmpdir_sample`), each comparing full `redact.redact()` to one isolated helper (`redact-secrets.sh` or `redact-tmpdir-paths.sh`). The plan calls for byte-identical output on the shared vector sets from `scripts/test-redact-secrets.sh` and `scripts/test-redact-tmpdir-paths.sh` (30+ tmpdir cases including E1–E7 JSONL `\n` boundaries, punctuation-terminated operator roots, nested `/var/folders`, multi-field JSON, and non-match preservation; secrets cases for all token families, idempotency, blockquote/indented PEM, and streaming split-PEM). None of those harness vectors are parametrized through a bash comparison, so regex drift in `python/redact.py:34-172` could ship without CI catching leakage or over-redaction. **Suggested fix:** Add a `_bash_redact_pipeline(text)` helper that pipes through `redact-tmpdir-paths.sh | redact-secrets.sh` (matching `scripts/design-log-publish.sh:74-75` and `scripts/tracking-issue-write.sh:71-72`), then parametrized parity tests over the bash harness vectors (or extracted shared fixtures) asserting `_parity_normalize(redact.redact(v)) == _parity_normalize(pipeline(v))` for every case.

- **security** `python/test_redact.py:56-68` — The unterminated-PEM fail-closed case is exercised only as a Python-side assertion (`test_unterminated_pem_fail_closed`); there is no bash byte-parity check even though acceptance explicitly requires it (“including the unterminated-PEM fail-closed case”). The implementation in `python/redact.py:200-203` matches the bash marker string, but without a parity assertion a future edit to `_redact_secrets_pem` could reintroduce tail leakage (the exact failure mode bash guards against in `scripts/test-redact-secrets.sh:311-323`). **Suggested fix:** Add a parity test that feeds the same `UNTERMINATED_BODY` fixture through `printf … | redact-tmpdir-paths.sh | redact-secrets.sh` and asserts identical stdout to `redact.redact()`, including absence of `tail-that-should-not-silently-survive` and presence of the truncation marker.

- **security** `python/test_redact.py:45-54` — Blockquote- and indent-prefixed PEM blocks are a documented bash edge case (`scripts/test-redact-secrets.sh:294-309`) and are supported in `python/redact.py:18-22` via `^[ \t>]*` on BEGIN/END, but `test_redact.py` only covers flush-left PEM. A regression in the `>` / whitespace prefix handling would not be caught before Phase 7 cutover. **Suggested fix:** Port the bash Section 4a `INDENTED_BODY` fixture into a parametrized parity test (Python vs `redact-secrets.sh` pipeline) asserting `<REDACTED-PRIVATE-KEY>`, no key material, and preserved prefix/suffix prose.

### Out-of-Scope Observations

- `python/redact.py:215-222` implements only batch `redact(text: str)`; bash `scripts/redact-secrets.sh:52-118` also exposes `--streaming` with a persisted `in_pem` state file for line-at-a-time callers. That gap is acceptable for Phase 1 (strangler-fig, not wired to live path) but will matter when `logging_util.py` or similar streams chunks — without a streaming API or caller-side state, PEM bodies split across writes could leak on the future Python path (raised in design review, not introduced as an active leak today).

- Live bash callers use inconsistent pipeline order: `scripts/design-log-publish.sh:75` and `scripts/lib-failed-agent-stderr-tail.sh:111` use `tmpdir | secrets`, while `scripts/implement-bootstrap.sh:1020` uses `secrets | tmpdir`. Python hard-codes tmpdir-then-secrets (`python/redact.py:264-265`, `python/test_redact.py:84-88`). That pre-existing inconsistency should be resolved at Phase 7 cutover so replacement of both orderings does not silently change scrubbing for path segments that embed token-shaped substrings.

- `skills/issue/scripts/create-one.sh:88-92` still redacts through `redact-secrets.sh` only (no tmpdir pass). That is pre-existing and outside this branch’s diff, but it means session tmpdir paths can still reach public GitHub issue bodies on the live path regardless of `python/redact.py` quality.
