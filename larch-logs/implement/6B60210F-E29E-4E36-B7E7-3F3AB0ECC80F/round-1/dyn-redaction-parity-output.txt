Verifying the pipeline-order leak with a concrete path pattern:
### In-Scope Findings

- **security** `python/redact.py:215-218` — `redact()` runs secret/PEM scrubbing before tmpdir/operator-path rewrite (`_redact_secrets_pem` then `_redact_tmpdir_paths`), but the production two-pass contract on outbound GitHub/diagnostic text is **tmpdir → secrets** (`scripts/tracking-issue-write.sh:200-203`, `scripts/design-log-publish.sh:74-75`, `scripts/lib-failed-agent-stderr-tail.sh:111`). The passes are not commutative: if a PAT- or `ghp_`-shaped substring appears inside a session directory token (e.g. `<TMPDIR>`), secrets-first replaces the token with `<REDACTED-TOKEN>` (breaking the session-suffix charset), so the tmpdir pass no longer matches and the output stays `/tmp/claude-implement-<REDACTED-TOKEN>` instead of `<TMPDIR>`. That leaks session layout and host path structure relative to the bash pipeline. **Suggested fix:** In `redact()`, apply `_redact_tmpdir_paths` first, then `_redact_secrets_pem` (matching `redact-tmpdir-paths.sh | redact-secrets.sh`). Add a combined-pipeline parity test that pipes both bash helpers and compares to `redact.redact()` on vectors where order matters (including secret-shaped session suffixes).

- **security** `python/test_redact.py:88-107` — Bash parity is limited to one secrets vector and one tmpdir vector (`test_parity_redact_secrets_sample`, `test_parity_redact_tmpdir_sample`), each compared against a **single** helper, not the chained `tmpdir | secrets` pipeline. The plan called for porting the regression vectors from `scripts/test-redact-secrets.sh` (PEM blockquote/indent, unterminated PEM, idempotency) and `scripts/test-redact-tmpdir-paths.sh` (E1–E7 literal-`\n` boundaries, JSON punctuation tails, nested `/var/folders`, plus-bearing repo names, multi-field JSONL). Those cases are mostly absent, so the branch does not mechanically guard against regex/ordering drift on security-critical paths before Phase 7 cutover. **Suggested fix:** Parametrize parity tests from the bash harness fixtures (or duplicate their inputs in pytest), assert byte-identical output against `printf '%s' "$v" | redact-tmpdir-paths.sh | redact-secrets.sh`, and keep the existing per-helper tests only as supplemental coverage.

### Out-of-Scope Observations

- The live `/implement` path still uses the bash helpers only (strangler-fig); this ordering gap affects the future `python/redact.py` consumer, not current production behavior.
- The bash tree itself is not fully consistent: some call sites use secrets→tmpdir (`scripts/implement-bootstrap.sh:220-230`, `skills/implement/SKILL.md:357`) while others use tmpdir→secrets; that predates this branch.
- `redact.py` does not port `redact-secrets.sh --streaming` (used by `scripts/lib-larch-log.sh`); that is a separate future parity item, not introduced as a regression by this diff alone.
- Unterminated PEM handling drops tail material and emits the stdout truncation marker correctly (`python/redact.py:200-203`, `python/test_redact.py:56-67`), but Python does not mirror bash’s stderr `WARN` lines (`scripts/redact-secrets.sh:167`); observability only, not a secret leak.
