### In-Scope Findings

- **risk-integration** `scripts/ship-pr.sh:2134-2169` — `ci-failed-jobs.sh` now classifies `python-lint` and `python-tests` as `fixable`, but `_per_job_argv` has no matching cases (only `lint`, `shellcheck`, `test-harnesses`, etc.). When either Python job fails on a PR, `run_per_job_local_fix_loop` / `_verify_failed_jobs_locally` treat the row as fixable in the TSV, `_per_job_argv` returns 1, the job is pushed into `unfixable[]`, and ship-pr exits 3 with `BAIL_REASON=ci-local-unfixable:python-lint` (or `python-tests`) instead of replaying `make py-lint` / `make py-test`. The allowlist change avoids `unknown-job-name`, but live `/implement` CI recovery for these new blocking jobs is still broken. **Suggested fix:** Add `python-lint)` → `_PJA_ARGV=(make py-lint)` and `python-tests)` → `_PJA_ARGV=(make py-test)` to `_per_job_argv`, and extend `scripts/test-ship-pr.sh` `ci_per_job_argv_table` (~3454–3462) with the same expectations so drift is caught in harnesses.

- **risk-integration** `scripts/test-ci-failed-jobs.sh:221-228` — The workflow-drift guard enumerates every job in `.github/workflows/ci.yaml` but its `case` arm still only allows the pre-Phase-1 set (`lint|…|smoke-dialectic`). With `python-lint` and `python-tests` added to the workflow, `make test-ci-failed-jobs` (and the CI `test-harnesses` shard that runs it) will fail with `workflow job missing from ci-failed-jobs mapping: python-lint` even though `scripts/ci-failed-jobs.sh:31` already maps those IDs. **Suggested fix:** Add `python-lint|python-tests` to the harness `case` list (alongside the existing fixable/gitleaks/trufflehog split), or derive the allowed set from the same source as `job_class()` so workflow, classifier, and harness cannot drift again.
