Reviewing the stdlib-boundary architecture: reading the diff, enforcement test, and runtime modules.
Checking whether nested imports are visited and whether the sibling set should match runtime modules only:
### In-Scope Findings

- **architecture** `python/test_stdlib_only.py:51-57` — The enforcement allowlist treats every `python/*.py` stem as a valid sibling import, including all `test_*` modules. A runtime module can therefore pass the guard with `import test_config` or `from test_redact import …` even though those modules import `pytest` and other dev-only packages, defeating the stated runtime/dev boundary at execution time while looking compliant in CI. **Suggested fix:** Restrict the sibling set to runtime modules only (e.g. `sibling = set(RUNTIME_MODULES)`), and add a negative test that a deliberate `import test_config` in a scratch runtime module fails the guard.

- **architecture** `python/test_stdlib_only.py:49-59` — The plan’s `test_stdlib_only.py` spec calls for discovering runtime modules, **importing each**, then AST-walking imports; the implementation only parses source and never executes `importlib.import_module` (or equivalent) for runtime modules. That misses import-time failures (syntax/initialization), circular-import breakage, and any dependency introduced via dynamic import paths (`importlib.import_module`, `__import__`, etc.) that never appear as `ast.Import` / `ast.ImportFrom` nodes. **Suggested fix:** After the AST pass, import each module in `RUNTIME_MODULES` under a controlled `sys.path` (only `python/`, no site-packages), and extend the guard with AST checks for constant-string dynamic imports (or a small denylist of `importlib` / `__import__` call patterns).

- **architecture** `python/test_stdlib_only.py:38-40` — `visit_ImportFrom` silently skips `ImportFrom` nodes with `module is None` (relative forms like `from . import x`). The flat tree has no package `__init__.py`, so this is unlikely today, but it is a hole in the “walk every import” contract: a future relative import in a mis-packaged runtime file would not be audited. **Suggested fix:** Treat `module is None` as a relative import, resolve it with `node.level` and the scanning module name (or fail closed if `level > 0` in a non-package layout), rather than returning without recording.
