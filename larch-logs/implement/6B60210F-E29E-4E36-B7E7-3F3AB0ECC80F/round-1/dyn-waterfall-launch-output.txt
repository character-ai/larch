Reviewing `agents.py` and its tests against the bash parity sources.
### In-Scope Findings

- **correctness** `python/agents.py:171-201` — `run_waterfall` always walks `tiers` in list order and gates first-fixer short-circuit on `idx == 0` plus `tier == first_tier`, but `run_ci_fix_vendor` in `scripts/ship-pr.sh` rotates with `offset=$(( start_attempt % 3 ))` and visits `tier=${tiers[$(((tier_idx + offset) % 3))]}`. A caller that passes `config.FIXER_TIER_ORDER` unchanged while only setting `first_tier` will run the wrong tier sequence and can miss or mis-apply the `first-fixer-non-health` bail when `start_attempt % 3 != 0`. **Suggested fix:** Rotate inside `run_waterfall` (e.g. `ordered = tiers[offset % len(tiers):] + tiers[:offset % len(tiers)]`, `first = ordered[0]`) or require and document that `tiers` is pre-rotated; add tests mirroring offset 1/2 from `scripts/ship-pr.sh:2032-2035`.

- **correctness** `python/agents.py:87-97` — `classify_launch_failure` scans both `sidecar` and `output_file` for refusal patterns, but `external_classify_launch_failure` in `scripts/lib-external-launcher-common.sh:255-273` only checks refusal on the sidecar; `output_file` gets parse-only checks. Refusal text only in the primary output file will classify as `other`/`refusal` in Python and `other`/`unknown` in bash, breaking planned bash-parity. **Suggested fix:** Match bash order: parse/refusal on sidecar first; on `output_file`, only run the parse regex (no refusal pass).

- **correctness** `python/agents.py:79-80` — `binary_present` uses Python truthiness (`if not binary_present`), while bash treats only `1|true|yes` as present (`scripts/lib-external-launcher-common.sh:228-234`). A shell bridge passing `"0"` is truthy in Python and will not emit `health`/`binary-missing`. **Suggested fix:** Normalize like bash (`binary_present in (1, True) or str(binary_present).lower() in {"1", "true", "yes"}`) before classifying.

- **correctness** `python/test_agents.py:48-56` — Bash-parity for classification is limited to the timeout case; the plan and `scripts/test-lib-external-launcher-common.sh:112-131` also cover binary-missing, auth, health-probe (cursor exit 8 + empty output), parse, and generic unknown. Gaps there won’t catch classification drift before Phase 7 wiring. **Suggested fix:** Add parametrized parity tests for every vector in `test-lib-external-launcher-common.sh` (skip when bash/lib is absent, same pattern as `test_parity_classify_timeout`).

- **correctness** `python/agents.py:191-201` — Short-circuit uses `idx == 0`, but bash uses `waterfall_iter == 0` after skips (`scripts/ship-pr.sh:2036-2041`, `2063-2067`, `2076-2084`). If a future `launch_fn` models a skipped first tier (e.g. claude script unavailable) while still leaving cursor→codex→claude in `tiers`, Python can treat the first *launched* tier as non-first and skip the bail; bash increments `waterfall_iter` on `continue` without launch. **Suggested fix:** Track an `attempt_index` incremented only when a tier is actually launched, and compare that to zero for short-circuit (or drop skipped tiers from `tiers` before calling `run_waterfall` and document that contract).

### Out-of-Scope Observations

- **risk-integration** `python/agents.py:122-139` — `build_launch_argv` uses repo-relative `scripts/launch-*.sh` paths; `run_ci_fix_vendor` invokes `"$SCRIPT_DIR/launch-*.sh"` absolutely (`scripts/ship-pr.sh:2044-2058`). This is fine if `proc.run` always uses `cwd=repo_root` (scripts are executable), but a wrong cwd will break launch; Phase 7 should pass absolute paths or `bash` + `SCRIPT_DIR` like bash does.

- **architecture** `run_waterfall` intentionally omits ship-pr rollback, verify, and `BAIL_REASON` handling (still in `scripts/ship-pr.sh`); that matches Phase 1 scope, but callers must not treat `WaterfallResult.short_circuited` alone as equivalent to setting `first-fixer-non-health` state.
