### FINDING_10: **correctness** `skills/design/scripts/design-step3-review.sh:340-342` — **Important:** `_step3_review_should_guarantee_step3` treats `main-agent-vote-required` as a Step 3 terminal status and the EXIT trap then mints `.completed/step-3`. The loop itself deliberately does not write `step-3` for `main-agent-vote-required` because this is a mid-loop handoff to the MainAgent vote path, not a Step 3b-ready terminal completion. Concrete failure: if a pause or recovery path runs after this handoff, `design_pause.py` sees `.completed/step-3` without `.completed/step-3.5` and resolves the session to Step 3.5 instead of resuming the required MainAgent vote flow. **Suggested fix:** Remove `main-agent-vote-required` from the trap’s step-3 guarantee list, and add a Step 3 wrapper regression test that a `main-agent-vote-required` result env gets `.completed/step-3-terminal` but not `.completed/step-3`.

The EXIT trap’s `_step3_review_should_guarantee_step3()` can still mint `.completed/step-3` from that stale env (statuses like `complete`) **without** requiring the current-pass sidecar, while `step-3-terminal` minting correctly requires `.step3-terminal-persisted-this-run`. ### FINDING_17: **security** `scripts/hook-bg-poll-guard.sh:326-334` — The new `bash_attempts_terminal_sentinel_mutation()` is meant to block orchestrator-side forgery of terminal sentinels while `.bg-wait-active` is live, and `scripts/hook-bg-poll-guard.md:20` documents that guarantee. The matcher only catches `touch`, `mkdir`, `: >`, and `echo … >`. It does not catch bare `> "$DESIGN_TMPDIR/.completed/step-3-terminal"`, `cp`, `mv`, hard-link `ln`, `tee`, `printf … >`, or `install`. Those commands are also outside `_PROBE_VERB_RE` (`scripts/hook-bg-poll-guard.sh:193`), so they fall through the generic probe-verb denials. A live-marker session can therefore mint regular (non-symlink) `.completed/step-5c-terminal` or `.completed/step-final-summary` files, or the Step 3 pair `.completed/step-3-terminal` plus `.step3-terminal-persisted-this-run` (`scripts/hook-bg-poll-guard.sh:83-86`), satisfy `marker_step_completed`, and unlock Read/Bash access to `.step3-review-result.env`, `.design-publish-result.env`, and `final-summary.md` before the background wrapper has actually persisted them. Tests only pin `touch` forgery (`scripts/test-hook-bg-poll-guard.sh:237-239`), not these alternate creation paths. **Suggested fix:** Fail closed on any live-marker Bash command that references terminal sentinel path tokens unless it is an already-whitelisted wrapper launch, recovery waiter, or foreground terminal probe. If you keep a dedicated mutation helper, extend it to cover bare `>`, `cp`, `mv`, `ln`, `tee`, `printf … >`, and `install`, and add regression cases for each; alternatively, invert the model so sentinel path literals deny by default and only the two explicit allowlist functions can pass.
