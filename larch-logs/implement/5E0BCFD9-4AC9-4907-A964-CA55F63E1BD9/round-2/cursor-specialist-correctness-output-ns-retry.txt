### In-Scope Findings

- **correctness** `scripts/clarify-state.sh:92-101` — Pagination merge is wrong for real `gh api --paginate --slurp` output: `--slurp` wraps each page in an outer JSON array, so the merged value is typically `[[…page1…],[…page2…]]`, but the script runs `jq -s 'add // []'` (which leaves that nested shape intact) and then `jq -r '.[] | (.body …)'`, which iterates **pages** (inner arrays), not comment objects. **Concrete scenario:** an issue with >100 comments (GitHub’s default page size) yields `MERGED` like `[[{…},{…}],[{…}]]`; the second `jq` errors (`Cannot index array with string "body"`) and the script exits under `set -e`, or if coercion ever succeeded, markers would be read in the wrong order / skipped. **Suggested fix:** After `gh api --paginate --slurp`, normalize to a flat comment list before extracting first lines (for example pipe through `jq 'add'` once or twice until the first element is an object with `.body`, or use `jq '[.[] | .[]]'` when the top-level is an array of pages of objects), and extend `scripts/test-clarify-state.sh` to feed a fixture matching the real nested `--slurp` shape, not only concatenated top-level arrays.
