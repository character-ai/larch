**[correctness]** [skills/review/scripts/collect-findings.sh:281-284](skills/review/scripts/collect-findings.sh) — The skip trigger is `/^##/`, which matches the first two `#` characters of *any* ATX heading with two or more hashes at column 1. In particular, `#### ...` (and `#####`, etc.) begins with `##`, so a legitimate `####` subheading after `### In-Scope Findings` runs `flush()`, sets `skip=1`, and `skip { next }` then drops subsequent list lines until another `### In-Scope Findings` / `### Out-of-Scope Observations` line. That can silently lose real findings. **Suggested fix:** Restrict the preamble matcher to true H2 lines only (e.g. require the third character not be `#`, and allow `##` end-of-line), such as `/^##([^#]|$)/` or `/^##([[:space:]]|$)/`, and add a regression fixture with `####` under in-scope bullets.

**[correctness]** [skills/review/scripts/collect-findings.sh:281-284](skills/review/scripts/collect-findings.sh) — For `MODE=diff`, [collect-findings.md](skills/review/scripts/collect-findings.md) still states that diff mode treats the whole output as in-scope when section headers are absent. After this change, any line matching `/^##/` starts a skip region until a canonical `### In-Scope Findings` or `### Out-of-Scope Observations` appears. A diff-style answer shaped as `## Summary` / `## Findings` with bullets and *no* `### In-Scope Findings` header would have all bullets after the first `##` skipped (only pre-`##` bullets would parse). That is a behavioral regression relative to the documented “entire output” contract, even if many templates always emit the `###` headers. **Suggested fix:** Tie the `##` skip to description mode, or to a narrow heading allowlist (e.g. commits/merge-base), or reset skip on bullet lines under diff mode—whichever matches the real output distribution; extend tests with a diff-mode fixture that uses `##` section titles without `### In-Scope Findings`.
