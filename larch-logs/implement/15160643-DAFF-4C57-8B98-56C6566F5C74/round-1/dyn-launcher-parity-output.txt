### In-Scope Findings

- **architecture** `scripts/test-launch-review.sh:1381-1384` — The codex suite’s “threading” check greps the whole `scripts/launch-review.sh` for `_RUN_EXTERNAL_SINK_ARGS+=(--stderr-sink "$STDERR_SINK")`, which also appears in `_launch_cursor` (~692–693). It does not assert that sink args are expanded on the codex `RUN_EXTERNAL` calls (~541, ~559). A regression that removed only those expansions while leaving cursor’s (~976) and both init blocks would still pass, so the harness does not guard codex lane wiring despite the plan’s parity requirement. **Suggested fix:** Assert codex-specific forwarding (e.g. two `"${_RUN_EXTERNAL_SINK_ARGS[@]+"${_RUN_EXTERNAL_SINK_ARGS[@]}"}"` expansions inside `_launch_codex`, or stub-capture `run-external-agent.sh` argv in the codex subshell) and mirror the same pattern for cursor (one expansion after `--capture-stdout-only`).

- **architecture** `scripts/test-launch-review.sh:2709-2741` — The cursor stderr-sink block accepts the flag and checks outer `.meta` but has no lane-specific inner-argv assertion, while the codex block adds the weak file-wide grep above. Per `.claude/rules/launcher-argv-test-coverage.md` and `.claude/rules/external-tool-launcher-parity.md`, that leaves cursor with weaker regression coverage for the same shared surface even though `scripts/launch-review.sh` implementation is symmetric (init/parse/validate at ~111–157 vs ~652–693, meta append at ~604 vs ~1028, `RUN_EXTERNAL` at ~541/559 vs ~976). **Suggested fix:** Extend the cursor subshell with the same lane-scoped argv contract as codex (prefer stub-based checks over whole-file greps).
