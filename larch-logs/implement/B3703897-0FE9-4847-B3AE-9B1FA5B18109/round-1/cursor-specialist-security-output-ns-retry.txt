### In-Scope Findings

1. **Important**
- **risk-integration** `scripts/design-log-publish.sh:86-88` and `scripts/design-log-publish.md:40-42` — `--dry-run` exits with `PUBLISH_OK=true` after only required argv presence, tmpdir existence, and basic `--issue`/`--run-id` shape checks; it does not run the non-mutating preconditions the real path needs (`command -v jq`, `git rev-parse --show-toplevel`, `git symbolic-ref refs/remotes/origin/HEAD`, `command -v gh`), while the contract claims dry-run validates “required tools” aside from `jq`. **Suggested fix:** Either run those read-only checks before emitting `PUBLISH_OK=true`, or rewrite the contract to state dry-run is argv plus “tmpdir exists” only so automation cannot treat `PUBLISH_OK=true` as “publish will succeed next invocation.”

2. **Nit**
- **correctness** `scripts/design-log-publish.sh:64-70` — The stderr text says “expected positive integer,” but the `case "$ISSUE"` pattern accepts `0`, so invalid GitHub issue `0` slips through until later `gh`/`larch-log.sh` failures. **Suggested fix:** Reject `0` explicitly (for example `[[ "$ISSUE" == "0" ]]`) with the same `emit_publish_result false` pattern used for other validation failures.

3. **Nit**
- **security** `scripts/design-log-publish.sh:194-205` — `find` is invoked without a `--` separator before the root path, so a `--design-tmpdir` value that begins with `-` can be parsed as find options instead of a path. **Suggested fix:** Use `find -- "$DESIGN_TMPDIR" ...` and `find -- "$DESIGN_TMPDIR/render-cache" ...` so the roots are always positional operands.
