### In-Scope Findings
- **correctness** `scripts/design-log-publish.sh:395-402` — After `gh pr merge`, the script runs `git -C "$REPO_ROOT" worktree remove --force "$WT_DIR"` and `rm -rf "${WT_PARENT:-}"` with errors sent to `/dev/null` or ignored via `|| true`, then clears `WT_DIR`/`WT_PARENT` and runs `trap - EXIT`, which removes the EXIT-time `wt_cleanup` safety net. If `worktree remove` fails (permissions, transient git error, stale lock), the failure is silent, the script can no longer retry removal using the recorded path, and the operator is not told to run `git worktree remove` manually. **Suggested fix:** Treat worktree removal as part of the success contract: surface non-zero status on stderr (do not discard stderr), avoid clearing `WT_DIR`/`WT_PARENT` or disabling the EXIT trap until removal succeeds (optionally retry once), and on persistent failure emit an explicit recovery line with the absolute worktree path and keep `trap` active so a normal `exit` still runs `wt_cleanup`.
