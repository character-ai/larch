- **correctness** `scripts/ship-pr.sh:1764-1785` — On a post-merge `write-final-report.sh` failure classified as transient, the new branch calls `exit_transient_net` (which `exit 6`s the whole script) before `advance_phase "done"` at lines 1784–1785, so `PHASE` can remain `postmerge` even though the PR is already merged and local cleanup has run. A non-transient failure on the same helper only `record_failure`s and still advances to `done`, so transient vs non-transient outcomes differ in whether the state machine reaches the terminal phase; operators relying on `PHASE=done` or a clean exit after merge may see an inconsistent contract unless every caller treats exit `6` from the post-merge tail as an explicit retry path. **Suggested fix:** Either document and enforce that exit `6` from `postmerge` must resume with `--resume-phase postmerge` (and verify that path is idempotent), or align semantics with the non-transient branch by recording the failure, still advancing `done`, and surfacing retry through a mechanism that does not strand `PHASE` short of `done` after a successful merge.
