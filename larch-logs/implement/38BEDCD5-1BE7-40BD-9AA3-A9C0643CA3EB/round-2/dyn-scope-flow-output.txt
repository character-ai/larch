Reviewing the branch diff and tracing `SCOPE_ANCHOR_FILE` through the plan-review pipeline for integration risks.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:1515-1517` — On the pre-dedup ballot renumber fallback path, a second renumber failure calls bare `exit 1` inside `_run_plan_review_round`, which bypasses `_terminal_exit` / `write_step3_result_env` / `emit_loop_kvs`. That means `SCOPE_ANCHOR_FILE` (and the rest of the Step 3 result contract) is never written for this failure mode even though `plan-review-scope-anchor.txt` was already materialized and scout/panel would have consumed it earlier in the same round. `run-step3-review.sh` then sees `rc=1` with no fresh inner env and may coerce `LOOP_STATUS=panel-failed`, losing the sanitized anchor handoff the MainAgent path depends on. **Suggested fix:** Replace the bare `exit 1` with `return 1` plus an explicit terminal status (`LOOP_STATUS=panel-failed` or a dedicated ballot-renumber token), or call `_terminal_exit` / `_snapshot_terminal_exit_preserving_status` before exiting so `SCOPE_ANCHOR_FILE` is always emitted on every loop termination path.

- **risk-integration** `skills/design/scripts/run-step3-review.sh:148-173` — `validate_scope_anchor_handoff` silently clears `SCOPE_ANCHOR_FILE` (WARN only) when the parsed path is missing, is a symlink, contains CR/LF, or canonicalizes outside `DESIGN_TMPDIR`. Voters already received the inlined anchor earlier in the same round, but the MainAgent 0-judge fallback reads scope only from refreshed Step 3 result state per `skills/design/SKILL.md`; clearing the key creates an intentional asymmetry where external judges were issue-anchored and the MainAgent adjudicates without the same binding scope evidence. **Suggested fix:** Fail closed with a dedicated `LOOP_STATUS` / `TALLY_PLAN_REVIEW_STATUS` when a non-empty handoff path cannot be validated, or fall back to the canonical staged file `$DESIGN_TMPDIR/plan-review-scope-anchor.txt` when it exists and is a regular file under the design tmpdir, instead of clearing the key.

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:171-179` — Brainstorm handling writes `plan-review-feature-context.txt` from unstripped `ORIGINAL_FEATURE_FILE` (which may still contain an embedded `larch:plan` block) plus brainstorm synthesis. Binding dispatch correctly uses `SCOPE_ANCHOR_FILE` / `plan-review-scope-anchor.txt`, but the sidecar file is a latent alternate “feature context” surface with stale-plan content and no consumer guard in the loop itself. A future mistaken `--feature-file` / `--description-file` wiring would reintroduce exactly the scope-creep failure mode this issue targets. **Suggested fix:** Either stop writing the sidecar until something actually consumes it, or build it from the same stripped anchor body (and keep brainstorm clearly non-binding) so no parallel feature narrative can become the accidental binding input.
