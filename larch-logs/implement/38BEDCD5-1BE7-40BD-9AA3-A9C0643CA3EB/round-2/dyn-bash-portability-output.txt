### In-Scope Findings

- **code-quality** `skills/review/scripts/aggregate-findings.sh:158-171` — Plan-mode scope-reduction splitting calls `check-scope-reduction-marker.sh` via `subprocess.run` and treats any non-zero exit other than `1` the same as “not tagged” (`returncode == 0` only). If the helper is missing, not executable, or `python3` fails inside it, tagged `[SCOPE-REDUCTION]` blocks are silently routed into the LLM aggregation input instead of the preserved tagged sidecar, which defeats the conservative aggregation contract. **Suggested fix:** Mirror the deduper’s `is_tagged()` handling in `plan-review-loop.sh`: distinguish exit `1` (false) from infrastructure failure (non-0/1), log a WARN, and on helper failure fall back to the untagged+tagged split using the original input (or abort aggregation with `AGGREGATED=false`) rather than misclassifying tagged blocks.

- **code-quality** `skills/design/scripts/plan-review-loop.sh:141-142` — Scope-anchor materialization runs `plan-block-strip-body.sh` with `2>/dev/null`, so strip failures that do not emit `MALFORMED=` on stdout surface only as a generic “failed to strip” error with no stderr context. Under `set -euo pipefail`, that makes production debugging harder and can hide quoting/path failures inside the strip helper. **Suggested fix:** Drop the stderr redirect (or tee stderr into `$DESIGN_TMPDIR/plan-strip.stderr` and append it to the `larch_err` message) while keeping stdout KV parsing unchanged.

- **code-quality** `scripts/plan-block-strip-body.sh:68-70` — After malformed-marker counting, line numbers are resolved with `grep -n … | head -1 | cut` under `set -o pipefail`. If `grep -n` fails unexpectedly (I/O error, race, encoding edge), the pipeline aborts the whole script instead of emitting a structured `MALFORMED=` token; callers then get a hard bash failure rather than the fail-closed contract shared with `plan-block-read.sh`. **Suggested fix:** Guard the pipeline with `set +e`, verify `start_line`/`end_line` are non-empty integers, and route empty/invalid results through `emit_malformed` (e.g. a dedicated token) instead of dying in the pipeline.

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:1233-1248` — The deduper’s `is_tagged()` writes each finding block to `tempfile.NamedTemporaryFile(..., delete=False)` under the default system temp directory and unlinks in `finally`, but a crash/kill between create and `os.unlink` leaves orphan files in `/tmp` (or `$TMPDIR`). The same pattern is duplicated in the parity gate and aggregation paths. **Suggested fix:** Create temp files under `$DESIGN_TMPDIR` (or pass `dir=os.environ["DESIGN_TMPDIR"]` when set), and/or register an `atexit` cleanup list so marker-detector temp files cannot accumulate across long multi-round runs.

- **code-quality** `scripts/lib-vote-tally.sh:76-80` — `is_scope_reduction_block` documents a `<block>` argument but passes it to `check-scope-reduction-marker.sh --file`, so the parameter must be a filesystem path, not inline markdown (same pattern as `is_security_block`). Harnesses comply, but the name invites misuse from future tally code that might pass heredoc content containing newlines or `###` prefixes, which will make `--file` fail under `set -e`. **Suggested fix:** Rename the parameter/doc to `block_file`, or write the block body to a `mktemp` under `$TMPDIR` and pass that path (with trap cleanup), matching how the Python deduper already invokes the helper.

- **code-quality** `scripts/compute-pr-line-counts.sh:97-99` — After printing the KV contract from `awk`, the script runs `trap - EXIT` and then `rm -f "$tsv_tmp"`. With `set -e`, an `rm` failure would exit non-zero after partial stdout was already emitted, yielding a truncated/mis-parsed KV stream for `write-final-report.sh`. **Suggested fix:** Keep the EXIT trap until process exit, or wrap the manual `rm` with `rm -f … || true` after successful emission so the helper always exits 0 once KVs are printed.
