Reviewing the branch diff and commit history, then inspecting the new and modified shell scripts for runtime issues.
### In-Scope Findings

- **code-quality** `skills/design/scripts/plan-review-loop.sh:136-177` — `_materialize_scope_anchor` installs a `RETURN` trap to remove `stripped_tmp`, `anchor_tmp`, and `strip_kv`, but every failure path calls `exit 2` from inside the function. In Bash, `exit` terminates the whole script without running a `RETURN` trap, so failed strip/empty-anchor/CR-LF checks can leave those temp files behind in `$DESIGN_TMPDIR` until session cleanup. **Suggested fix:** Add an `EXIT` trap (or a shared `cleanup` function invoked from both `RETURN` and error paths), or return an error code to the caller and let the top level `exit` after cleanup.

- **code-quality** `skills/design/scripts/plan-review-loop.sh:144` — Scope-anchor materialization redirects `plan-block-strip-body.sh` stderr to `/dev/null` while only parsing stdout for `MALFORMED=`. Any `larch_err` diagnostics from the strip helper are discarded, which makes malformed-marker debugging harder and can hide unexpected infrastructure failures that do not emit `MALFORMED`. **Suggested fix:** Capture stderr to a tmp file (same pattern as collector failures) and include it in the `larch_err` message when `strip_rc != 0`.

- **correctness** `skills/implement/scripts/write-final-report.sh:118-136` — PR line-count caching treats any non-empty `LINES_STATUS` in `ship-pr-state` as authoritative for the current `PR_NUMBER`, including `LINES_STATUS=unavailable` from a transient `gh api` failure. A later `write-final-report` invocation will reuse the cached unavailable result and never retry `compute-pr-line-counts.sh`, so the final summary can show `Lines (PR diff): N/A` permanently for that PR. **Suggested fix:** Cache only when `LINES_STATUS=ok`, or retry when cached status is `unavailable`/`skipped` (with optional backoff), and replace prior `LINES_*` keys instead of append-only growth.

- **code-quality** `scripts/check-scope-reduction-marker.sh:19-96` — The stdin and `--file` code paths duplicate the same ~40-line Python block. Dedup, aggregation, and parity already depend on this helper as the single canonical detector; drift between the two copies would produce inconsistent marker detection across invocation modes. **Suggested fix:** Factor the Python into one heredoc fed by either `sys.argv[1]` or `sys.stdin`, matching the pattern used elsewhere in `plan-review-loop.sh`.

- **code-quality** `scripts/lib-vote-tally.sh:76-80` — `is_scope_reduction_block` takes a parameter named `block` but passes it to `--file`, so callers must supply a filesystem path, not inline markdown. A mistaken caller passing heredoc text would make `check-scope-reduction-marker.sh` raise `FileNotFoundError`; Python exits **1**, which the helper treats as “not tagged” rather than “detector error,” silently misclassifying scope-reduction findings. **Suggested fix:** Rename the parameter/doc to `block_file`, assert `[[ -f "$block_file" ]]`, and propagate non-0/1 helper exit codes as failure instead of “false.”

### Out-of-Scope Observations

- **compute-pr-line-counts.sh** and **plan-block-strip-body.sh** otherwise follow existing repo conventions: `set -euo pipefail`, `mktemp` + `EXIT` traps, quiet `emit_kv` on the strip helper, and non-fatal KV output for `gh` failures.
- **dispatch-plan-voters.sh** / **render-voter-prompt.sh** correctly gate `--scope-anchor-file` to plan context, inline redacted anchor content, and preserve byte-identical default output when the flag is omitted.
- **plan-review-loop.sh** dedup/parity/ballot-renumber paths degrade safely (pre-dedup fallback, aggregation fallback, subprocess failures on marker helper `rc=2` abort dedup rather than silently dropping tags).
- **`is_scope_reduction_block` is not used on the production tally path**; that matches the plan’s “unchanged thresholds” requirement and is intentional, not a runtime defect.
