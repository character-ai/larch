### In-Scope Findings

- **risk-integration** `skills/design/scripts/plan-review-loop.sh:136-177` — `_materialize_scope_anchor` writes to a fixed path but never refuses a pre-existing symlink at `$DESIGN_TMPDIR/plan-review-scope-anchor.txt` (or `.scout.txt`). A redirect follows the symlink, so anchor bytes can land outside the session tmpdir. Downstream in-loop consumers only require readability (`-r`), not `-L` or tmpdir containment: `dispatch-plan-voters.sh:48-51`, `render-plan-review-prompt.sh:133`, `render-voter-prompt.sh:92`, `revise-plan-with-waterfall.sh` (via `emit_untrusted_file_block`). `run-step3-review.sh::validate_scope_anchor_handoff` rejects symlinks only after the loop finishes, so reviewers/voters/revise may already have inlined arbitrary file content. **Suggested fix:** Before materialization, fail closed if the destination (and scout sibling) exists and is a symlink; atomically create regular files under `$DESIGN_TMPDIR`. Reuse the same `validate_scope_anchor_handoff` checks (or a shared helper) in every in-loop reader before inlining anchor content.

- **risk-integration** `skills/design/scripts/render-main-agent-scope-anchor.sh:22-33` — The MainAgent renderer checks only `-r` on `--scope-anchor-file` and does not apply the symlink / `$DESIGN_TMPDIR` containment rules that `run-step3-review.sh:148-173` enforces on durable handoff. The existing `main-agent-vote-required preserved on non-zero rc` case stubs loop stdout without `SCOPE_ANCHOR_FILE` and without creating `plan-review-scope-anchor.txt`, which should trigger recovery failure and `panel-failed` under current logic—so the handoff contract and its tests are out of sync. **Suggested fix:** Extend `test-run-step3-review.sh` with cases for (a) valid inner-env `SCOPE_ANCHOR_FILE` preservation, (b) recovery from staged anchor when env key is missing, (c) symlink/outside-tmpdir clearing, and (d) downgrade to `panel-failed` when recovery fails; update the main-agent stub to emit a valid staged anchor or expect `panel-failed`.
