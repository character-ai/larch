### In-Scope Findings

- **security** `scripts/launch-claude-subprocess.sh:177-182` — The branch adds hardened, HTML-escaped scope-anchor blocks in `render-plan-review-prompt.sh`, `render-voter-prompt.sh`, `revise-plan-with-waterfall.sh`, and `render-main-agent-scope-anchor.sh`, but the Claude generic plan-review fallback still forwards the same staged anchor through `launch-claude-review.sh` as a raw `--feature-file` context attachment. `launch-claude-subprocess.sh` then `cat`s that file into `<context_file_N>…</context_file_N>` with no `redact-secrets.sh` or `&lt;`/`&gt;` escaping, so attacker-controlled issue text can break out of the wrapper (for example `</context_file_1>` or `</reviewer_feature_description>`) and reach the model as live instructions even though the main prompt already contains an escaped `<reviewer_feature_description encoding="literal-redacted">` block. This is introduced/amplified here because `dispatch-plan-review-panel.sh` now binds `--feature-file` to `$DESIGN_TMPDIR/plan-review-scope-anchor.txt` and passes it via `waterfall_extra` to `launch-claude-review.sh` while also inlining the escaped anchor in the rendered generic prompt. **Suggested fix:** For plan-review Claude launches, stop forwarding `--feature-file` when the prompt already inlines the escaped anchor, or route all context attachments through the same `redact_untrusted_stream` / `emit_untrusted_file_block` helper used by the renderers; add a regression in `scripts/test-launch-claude-review.sh` or `scripts/test-launch-claude-subprocess.sh` that plants a delimiter-breakout payload in the scope-anchor file and asserts the subprocess prompt contains only escaped markup.

- **security** `skills/design/scripts/dispatch-plan-review-panel.sh:99-128` — The degraded-tools path explicitly combines both defenses in one launch: `append_shared_prompt_tail` / `render_plan_review_prompt` emit the escaped binding scope anchor into `claude-plan-generic.prompt`, and the same launch also passes `--feature-file "$FEATURE_FILE"` (the unstaged-on-disk `plan-review-scope-anchor.txt`) into `launch-claude-review.sh`. That creates two inconsistent channels for the same untrusted evidence, and only the second channel preserves injectable delimiters. Codex/Cursor reviewers are not affected because `launch-review.sh` uses `--prompt-file` only and does not re-embed `--feature-file` when `--agent-file` is absent. **Suggested fix:** Drop `--feature-file` from the generic Claude fallback invocation once the rendered prompt carries the anchor, or pass a pre-escaped companion file (like `plan-review-scope-anchor.scout.txt`) if a separate attachment is still needed.
