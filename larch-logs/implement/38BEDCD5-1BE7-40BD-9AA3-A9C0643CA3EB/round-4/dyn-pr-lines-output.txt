- **correctness** `skills/design/SKILL.md:1119` — Step 3’s MainAgent fallback now requires `${CLAUDE_PLUGIN_ROOT}/skills/design/scripts/render-main-agent-scope-anchor.sh`, but that script is **not in `HEAD`** (only an untracked working-tree copy exists). On a degraded 0-judge panel with a readable `SCOPE_ANCHOR_FILE`, the orchestrator will invoke a missing helper and cannot render the scope anchor before voting. **Suggested fix:** Add `skills/design/scripts/render-main-agent-scope-anchor.sh` to the branch (with `agent-lint.toml` / harness coverage if needed), or change SKILL.md to inline the same redact+escape block without depending on an unshipped script.

- **correctness** `skills/implement/scripts/write-final-report.sh:118-142` — PR line-count caching appends new `LINES_PR_NUMBER` / `LINES_*` rows to `ship-pr-state.sh` but reload uses `END{print v}` for the PR number while `read_lines_kv` takes the **first** matching `CODE_ADDED` / `CODE_DELETED` / etc. from **all** historical rows. If the same session state ever records counts for more than one PR (or is rewritten and appended again), the summary can show the current PR number with line counts from an earlier PR. **Suggested fix:** Cache and read a single atomic block keyed by PR (e.g. only parse `LINES_*` lines after the last `LINES_PR_NUMBER=`, or replace prior line-count keys instead of appending duplicates).

- **correctness** `skills/design/scripts/plan-review-loop.sh:1436-1459` — The post-dedup scope-reduction parity gate bails out when `len(post_tag) < len(pre_tag)`. Legitimate Jaccard dedup can merge two tagged near-duplicates into one block; parity then treats that as marker loss, restores `findings-in-scope.pre-dedup.md`, and puts duplicate tagged findings back on the ballot. That does not drop markers, but it can reintroduce semantic duplicates and dilute voting on scope-cut items. **Suggested fix:** Match pre-dedup tagged blocks to post-dedup output by normalized problem text + reviewer overlap (same approach as aggregation’s parity), and only fall back when a tagged input has **no** represented tagged output, not merely when counts differ.
