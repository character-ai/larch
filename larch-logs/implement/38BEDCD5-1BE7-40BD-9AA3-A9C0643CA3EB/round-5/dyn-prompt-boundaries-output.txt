### In-Scope Findings

- **security** `skills/design/SKILL.md:1119` — Step 3’s MainAgent 0-judge path requires `${CLAUDE_PLUGIN_ROOT}/skills/design/scripts/render-main-agent-scope-anchor.sh` to emit a redacted, HTML-escaped scope block and explicitly forbids inlining raw anchor bytes, but that script is **not in HEAD** (it exists only as an untracked working-tree file). On a clean checkout the orchestrator cannot follow the hardened contract; a fallback that reads `plan-review-scope-anchor.txt` directly would bypass the same delimiter escaping tested for voters/reviewers. **Suggested fix:** Commit `render-main-agent-scope-anchor.sh`, register it in `Makefile` / `agent-lint.toml`, and add a harness mirroring `test-render-voter-prompt.sh` delimiter-breakout cases so the MainAgent path cannot ship without the hardened renderer.

- **security** `scripts/scout-dynamic-archetypes.sh:131-139,352-353` — Plan-review scout now receives the GitHub issue scope anchor via `--description-file`, but `stage_context_file` only `cp`s the file into `staged-context/`; scout is told to `Read` it as plain text. Unlike reviewers/voters/revise, there is no `encoding="literal-redacted"` wrapper or `&lt;`/`&gt;` escaping on that content—only upstream `redact-secrets.sh` at anchor materialization (`plan-review-loop.sh:172`). A malicious issue body can still embed instruction-like prose that the scout model may follow when choosing dynamic archetypes. **Suggested fix:** Stage the description through the same `redact-secrets.sh` + HTML-entity pipeline used in `render-voter-prompt.sh` / `render-plan-review-prompt.sh`, or inline it inside a hardened untrusted block in the scout prompt instead of path-only delivery.

- **risk-integration** `skills/design/scripts/dispatch-plan-review-panel.sh:82-87` — Dynamic reviewer prompts concatenate scout JSON `prompt_body` with raw `cat "$body_file"` before the shared tail that carries the escaped scope anchor. JQ validation blocks obvious tag breakouts (`scout-dynamic-archetypes.sh:539-580`), but soft instruction injection in `prompt_body` is not redacted or escaped. Because this branch re-anchors scouting on attacker-controlled issue text, a manipulated scout can propagate injection into dynamic reviewer focus directives. **Suggested fix:** Pipe `prompt_body` through `redact-secrets.sh` and the shared `emit_untrusted_file_block` helper (or equivalent) before appending it to dynamic prompts; extend panel dispatch tests to assert delimiter/instruction payloads are neutralized.
