### In-Scope Findings

- **code-quality** `skills/design/scripts/plan-review-loop.sh:141-176` — `_materialize_scope_anchor()` installs `trap 'rm -f "$stripped_tmp" "$anchor_tmp" "$strip_kv"' RETURN` but never clears it with `trap - RETURN`. In Bash, traps set inside a function persist for the rest of the shell; every later function return in this long-lived driver (`_run_plan_review_round`, `_run_revise_with_status_parse`, `_terminal_exit`, etc.) re-runs that trap. Today the locals are usually unset outside the materializer, so the trap mostly degrades to `rm -f ""`, but that is fragile trap hygiene on macOS Bash 3.2 and could delete unrelated temps if a later function reuses those names or if trap timing changes. **Suggested fix:** clear the trap before leaving the function (`trap - RETURN` on all exit paths), use a dedicated subshell for materialization, or switch to an `EXIT`-scoped cleanup with uniquely named temps and no function-scoped `RETURN` trap.

- **code-quality** `scripts/check-scope-reduction-marker.sh:19-97` — The canonical marker detector hard-depends on `python3` with no `command -v python3` preflight or actionable stderr. Under `set -euo pipefail`, a missing interpreter surfaces as exit 127 from nested `subprocess.run` calls in `plan-review-loop.sh` and `aggregate-findings.sh`, which are reported generically as “scope marker helper failed” rather than “python3 unavailable.” That makes local/CI diagnosis harder on minimal shells. **Suggested fix:** add an early `command -v python3` guard with a explicit error line, or document/python-gate the helper the same way other runtime scripts in this repo treat required interpreters.

- **code-quality** `skills/review/scripts/aggregate-findings.sh:158-188` — The plan-mode tagged/untagged split wraps a large inline `python3` heredoc in a bare `if python3 ...; then ... else ... fi`. Any non-zero exit — missing `python3`, syntax error, unreadable `MARKER_HELPER`, or helper rc 2 — is collapsed into the same warning: “scope marker helper failed during plan split.” That obscures the real failure mode during `set -e` debugging. **Suggested fix:** capture exit status and stderr from the split step and branch on `127`/“command not found” vs helper rc 2 vs validation failure, emitting distinct diagnostics before falling back to `AGGREGATED=false`.

- **code-quality** `scripts/compute-pr-line-counts.sh:54-99` — The script registers an `EXIT` trap for `tsv_tmp`, then disables it with `trap - EXIT` and manually `rm`s the file before a forced `exit 0`. That pattern is easy to get wrong under `set -e` if a future edit adds an early `return`/`exit` between the `awk` and `trap - EXIT`, and it bypasses the trap on the normal path for no clear benefit. **Suggested fix:** keep a single cleanup path — either let the `EXIT` trap always run and drop the manual `trap - EXIT`/`rm` pair, or use a `finally`-style function with one explicit cleanup call on all exits.
