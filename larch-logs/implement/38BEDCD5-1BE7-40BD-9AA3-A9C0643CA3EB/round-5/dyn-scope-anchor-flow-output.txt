Tracing the scope-anchor lifecycle across the diff and key integration points.
### In-Scope Findings

- **architecture** `skills/design/references/brainstorm.md:160` — The downstream consumer contract still says Step 3 merges brainstorm into the feature file passed to `dispatch-plan-review-panel.sh`, so reviewers see plan plus merged context. After this branch, `plan-review-loop.sh` stages `plan-review-scope-anchor.txt` (stripped issue ± approved outline) and passes that to scout/panel/voter/revise; brainstorm is written only to `plan-review-feature-context.txt`, which no production reader consumes. The new “Plan-review binding scope” section (lines 162–164) contradicts line 160, so maintainers can re-wire brainstorm back into the binding anchor and recreate the original scope-creep failure mode. **Suggested fix:** Replace the Step 3 bullet with the staged-anchor contract: binding path is `plan-review-scope-anchor.txt`; brainstorm stays in `plan-review-feature-context.txt` as optional, non-binding, and is not forwarded to panel dispatch.

- **architecture** `scripts/lib-design-round-artifacts.sh:5-35` — Per-round forensic snapshots (`plan-review/round-N/`) still use an allowlist that includes `plan.txt`, ballot, and findings, but not the new `plan-review-scope-anchor.txt` (or `findings-in-scope.pre-dedup.md`). Multi-round runs therefore cannot answer “what issue scope did round N reviewers/voters actually see?” from committed round artifacts, which undercuts debugging the scope-creep class this feature targets. **Suggested fix:** Extend `design_round_artifact_included` (and any publish/staging mirrors) to include `plan-review-scope-anchor.txt` and, if parity debugging matters, `findings-in-scope.pre-dedup.md`; add a harness assertion that round snapshots retain the anchor used for that round.

- **risk-integration** `skills/design/scripts/render-main-agent-scope-anchor.sh:1-33` — MainAgent 0-judge fallback now depends on this new renderer (invoked from `SKILL.md` Step 3) for redacted, HTML-escaped scope evidence, but the script is not registered in `Makefile`, has no offline harness, and is absent from `agent-lint.toml`. Voter/reviewer anchoring is heavily tested; the MainAgent path is prompt-only plus an untested helper, so regressions in redaction/escaping or prompt text can silently drop issue anchoring on the degraded panel path that motivated the feature. **Suggested fix:** Add `test-render-main-agent-scope-anchor.sh` (strip/redact/escape, unreadable-file failure) and register it in `Makefile`/lint shards; optionally pin a `test-design-structure.sh` reference from `SKILL.md` to the renderer.

- **architecture** `skills/shared/scripts/render-voter-prompt.sh:71-97` — With `--scope-anchor-file`, voters still receive finding-anchored proportionality first (“more complexity than **it** warrants” at lines 71–72), then a later override block (line 93) asking them to judge against issue scope. That mirrors the pre-change voter failure mode: early, concrete EXONERATE guidance can dominate later override text, so scope-reduction findings may still lose to addition findings even though the anchor is inlined. Reviewer prompts avoid this by baking issue scope into the anchor block up front; voters do not. **Suggested fix:** When `--scope-anchor-file` is set, omit or relocate the generic finding-anchored EXONERATE lines (71–72) so the first proportionality instruction is issue-anchored; keep the byte-identical no-flag path unchanged and extend `scripts/test-render-voter-prompt.sh` to assert ordering.
