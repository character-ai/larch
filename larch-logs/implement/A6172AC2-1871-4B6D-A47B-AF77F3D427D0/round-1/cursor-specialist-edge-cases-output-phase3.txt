### In-Scope Findings

1. **correctness** `python/logging_util.py:72-83` — **Important**: `quiet_init()` leaks fds 3 and 4 on partial failure. When `os.dup2(1, 3)` and `os.dup2(2, 4)` succeed but `os.open(path, os.O_WRONLY | os.O_APPEND)` then raises `OSError`, the `except OSError:` handler calls `_clear_quiet_env()` and returns — without closing fds 3 and 4. These fds (copies of original stdout and stderr) remain open for the process lifetime and are inherited by every child process spawned by `ship.py`. A child `ship.py` invocation or any tool that probes fd 3 for IPC will find it unexpectedly open, potentially confusing quiet-routing state in nested calls. **Suggested fix:** In the `except OSError:` block, before `_clear_quiet_env()`, close any fds that were successfully dup'd: `for _fd in (3, 4): \n    try: os.close(_fd) \n    except OSError: pass`.

2. **correctness** `python/ship.py:714-721` — **Latent**: `emit_result()` does not catch I/O errors from `print`/`flush` on the contract stream. If `print(json.dumps(payload, sort_keys=True), file=stream)` or `stream.flush()` raises `BrokenPipeError` or `OSError` (e.g., fd 3 closed by the parent's orchestrator between quiet init and emit, or stdout broken in non-quiet mode), the exception propagates through `emit_result`, bypasses `_persist_stall_metadata_if_needed` (already past), and exits `main()` entirely — leaving the caller with no contract JSON and a non-zero, non-JSON exit. The acceptance criterion "Contract JSON always reaches the caller-visible contract stream" is violated on a broken pipe. **Suggested fix:** Wrap the print+flush in `try/except OSError` (or `Exception`), log the failure to original stderr (fd 4 if quiet), and continue to return the exit code.

3. **risk-integration** `python/ship.py:887-888` — **Latent**: `_persist_stall_metadata_if_needed` and `emit_result` are called outside any exception envelope after the outer `try/except Exception`. Inside `_persist_stall_metadata_if_needed`, the `except (OSError, ShipError)` clause is narrower than the "best-effort" intent described in the plan. If the breadcrumb emit inside that except clause (`logging_util.BreadcrumbWriter().emit(...)`) raises a non-OSError exception (e.g., `ValueError: I/O operation on closed file` when `sys.stderr` is closed, or a `TypeError` from a corrupted stream), the exception propagates out of `_persist_stall_metadata_if_needed`, past `emit_result`, and out of `main()` — leaving the caller without contract JSON. Scenario: tests or environments where stderr has been closed before `main()` returns. **Suggested fix:** Widen the catch to `except Exception` in `_persist_stall_metadata_if_needed`, and/or wrap the two tail calls (`_persist_stall_metadata_if_needed` + `emit_result`) in a `try/except Exception` guard that ensures `emit_result` always runs.

### Out-of-Scope Observations

1. **correctness** `python/finalize.py:356` — `write_finalize_state` (the existing ctx-based writer) writes values like `PR_TITLE` and `PR_URL` without shell quoting (`f"{key}={value}\n"`). This is pre-existing behaviour replicated by the new `write_finalize_state_merged`. When bash scripts source the resulting `finalize-state.sh`, values with spaces or shell-special characters (e.g., a PR title `Fixes #123: add feature`) would be misinterpreted. Out of scope because the pattern predates this diff.
