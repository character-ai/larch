### In-Scope Findings

1. **`code-quality`** `python/test_support.py:27` — `_index: int = 0` is a regular dataclass field, so `RecordingRunner(_index=5)` is a valid (unintended) constructor call. A test accidentally passing `_index=` would silently skip the first N scripted responses without any error. **Suggested fix:** Declare it as `_index: int = field(default=0, init=False)` to prevent accidental construction with a non-zero index.

2. **`code-quality`** `python/test_run_logs.py:20-21` — `RecordingRunner` subclass is not decorated with `@dataclass`, so `git_commits: int = 0` is a class-level annotation, not a proper instance field. It happens to work via Python's attribute-shadowing-on-first-assignment, but the pattern is inconsistent with the parent's dataclass model and any static analysis or `__init__`-based initialization would not include it. **Suggested fix:** Decorate the subclass with `@dataclass` and use `field(default=0)`, or at minimum add a brief comment explaining the non-standard initialization.

3. **Latent** `correctness` `python/finalize.py:334,337` — `shlex.split(value, posix=True)` silently strips backslashes from single-token values (e.g., a bash-written `STALL_STEP=git\-rebase` reads back as `git-rebase`; `VALUE=a\b` reads as `ab`). The fallback `len(parsed) == 1 else value` only protects multi-token inputs. Since `write_finalize_state_merged` never writes backslashes, round-trip is clean for Python-written files, but external `finalize-state.sh` files written by bash scripts using backslash-continuation would silently corrupt on first Python read. **Suggested fix:** Replace shlex with a simple `value.strip("'\"")` parser that mirrors the unquoted-only write format, or at least document the posix-stripping caveat in the function docstring.

4. **Latent** `code-quality` `python/test_ship.py` — Two gap-fill regression cases required by the plan's acceptance criteria are absent: **(a)** plan item (2): pre-seed `STALL_TRACKING=true` and verify `_persist_stall_metadata_if_needed` returns early without clobbering; **(b)** plan item (7): monkeypatch `write_finalize_state_merged` to raise and assert STALLED JSON + exit-4 unchanged. Without (a), the no-clobber early-return path (`if _truthy(data.get("STALL_TRACKING", "")): return`) has no test; without (b), the best-effort wrapper's behavior under write failure is untested. **Suggested fix:** Add both regression tests as unit tests in `test_ship.py`.

5. **Latent** `code-quality` `python/logging_util.py:46-87` — `quiet_init()` has no unit tests for its core behaviors: formatted log path shape (`larch-quiet-ship.py-<pid>.log`), idempotency when called twice, degradation on unwritable log parent, and the `LARCH_QUIET_DISABLE` no-op path. The tests in `test_ship.py` monkeypatch `quiet_init` away entirely rather than exercising it. A regression to log-path formatting (e.g., an unformatted template literal) would be undetected by CI. **Suggested fix:** Add dedicated tests in `test_ship.py` or a new `test_logging_util.py` for at least the log-path-shape and degradation cases, as required by the plan.

6. **Nit** `code-quality` `python/logging_util.py:90-97` — `contract_stream()` calls `os.dup(3)` on every invocation, creating a unique fd each time. The caller (`emit_result`) correctly closes it via `_close_contract_stream`, but a future call site that forgets the close would silently leak a dup of fd 3. **Suggested fix:** Document in the function docstring that callers must close the returned stream when it is not `sys.stdout`, or cache the dup in a module-level variable after `quiet_init` succeeds (closed on process exit by the OS in any case).
