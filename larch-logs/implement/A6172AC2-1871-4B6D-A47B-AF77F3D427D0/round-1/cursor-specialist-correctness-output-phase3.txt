### In-Scope Findings

1. **correctness** `python/ship.py:774-782` — **[Latent]** `_first_present` returns `str(value)` for any `int` including `0`, so `_fill_if_empty(data, "PR_NUMBER", result.pr_number, ...)` writes `PR_NUMBER=0` to `finalize-state.sh` whenever `result.pr_number` is `0`. PR number `0` is used in `pr.py` as the repo-unavailable sentinel (`PrResult(number=0, url="", status="local-only")`). In practice `run_ship` converts it via `ensured.number or None`, but `_first_present` has no int-zero guard, leaving the path open if any caller ever passes `ShipResult(pr_number=0, ...)` directly. An orchestrator that reads `PR_NUMBER=0` from finalize-state and tries to act on it (e.g., `gh pr view 0`) gets a hard failure. **Suggested fix:** in `_first_present`, skip int zero: `if isinstance(value, int): return str(value) if value != 0 else ""`.

2. **correctness** `python/logging_util.py:46-87` — **[Latent]** `quiet_init` re-initializes when a parent process has set `LARCH_QUIET_ACTIVE=1` and `LARCH_QUIET_PID=<parent-pid>` (non-empty, != child's pid). The two early-return guards only cover "active but no PID" and "PID equals our own PID"; a parent-owned PID falls through to `os.dup2(1, 3)`. If the orchestrator has already redirected fd 1 to a quiet log before forking Python, the child's `dup2(1, 3)` saves the quiet log onto fd 3, so `contract_stream()` returns the quiet log rather than the original stdout capture target, and contract JSON is silently swallowed. **Suggested fix:** add an early return when `LARCH_QUIET_ACTIVE` is truthy and `active_pid` is non-empty (regardless of whether it matches our PID): `if _env_truthy(config.ENV_LARCH_QUIET_ACTIVE) and active_pid: return`.

3. **correctness** (completeness w.r.t. plan) `scripts/restore-finalize-state.sh`, `skills/implement/SKILL.md`, `skills/implement/scripts/stall-recovery-report.sh`, `skills/implement/references/stall-recovery.md`, `skills/implement/scripts/test-stall-recovery-report.sh`, `scripts/test-implement-structure.sh`, `scripts/test-implement-structure.md`, `docs/linting.md`, `python/test_restore_finalize_state.py` — **[Important]** All nine files named in the plan's "Files to modify/create" list for Round 1 are absent from the diff. The acceptance criteria require: `restore-finalize-state.sh` preservation of Python-written `STALL_TRACKING=true` over ship-pr `STALL_TRACKING=false` (FINDING_1/4); `stall-recovery-report.sh` four-layer classify with finalize-state fallback (FINDING_3); SKILL.md prose reconciled for exit-3/4/6 dual-path reads; `test-implement-structure.sh` routing contract pins; and `docs/linting.md` matrix prose. Without the `restore-finalize-state.sh` fix, the Python-written stall metadata can still be clobbered on recovery; without the classify fix, Step 18a misses finalize-only stalls. **Suggested fix:** implement the missing files per the plan before merging.

4. **code-quality** `python/run_context.py:135-139` — **[Nit]** `with_` silently overwrites the canonical `branch` field when both `branch_name` and `branch` are passed together: `changes["branch"] = changes.pop("branch_name")` executes first and replaces the explicit `branch=` value. `with_(branch_name="a", branch="b")` yields `branch="a"`, discarding `"b"` without any error. The current test only covers alias-only calls. **Suggested fix:** detect and raise when both alias and canonical are passed simultaneously, or process canonical first so that alias only applies when canonical is absent.

5. **code-quality** `python/test_run_logs.py:20-44` — **[Nit]** `RecordingRunner` subclass is not decorated with `@dataclass`, making `git_commits: int = 0` a class attribute rather than a per-instance dataclass field. Augmented assignment (`self.git_commits += 1`) creates an instance attribute on first write, so two instances accidentally share the class-level `0` until mutated. **Suggested fix:** add `@dataclass` and `git_commits: int = field(default=0, init=False)` to make it a proper per-instance attribute.

6. **correctness** `python/ship.py:11` — **[Nit]** `_version_supported` calls `tuple(version_info)` with `# type: ignore[arg-type]` when `sys.version_info` already supports direct tuple comparison: `sys.version_info >= (3, 11)` works without any cast or type ignore. **Suggested fix:** type the parameter as `tuple[int, ...]` (or just inline the guard in the call site as `sys.version_info >= (3, 11)`).
