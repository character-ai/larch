### In-Scope Findings

- **code-quality** `python/test_run_logs.py:20-21` — `RecordingRunner` subclass omits `@dataclass`, so `git_commits: int = 0` is a class-level attribute rather than a per-instance field initialized by `__init__`. The behaviour is incidentally correct because Python creates an instance shadow on first `+=1`, but the initial value is read from the class, not from `__init__`. If a future test ever checks `runner.git_commits` before any `git commit` call on a freshly-constructed instance, it reads the class attribute — correct today, but silent semantic drift from the original `@dataclass` version that initialised it per instance. There is also no `calls` reset guarantee: the inherited dataclass `__init__` still initialises `calls`/`responses`/`_index` correctly, but `git_commits` is excluded from `__eq__`, `__repr__`, and any `dataclasses.replace` use that a future caller might attempt. **Suggested fix:** Add `@dataclass` to the subclass and annotate `git_commits: int = field(default=0)` so it is a proper per-instance dataclass field, or explicitly assign `self.git_commits = 0` in an `__init__` override, matching the original class's semantics exactly.

- **code-quality** `python/test_gh.py:18-20`, `python/test_push.py:27-29` — Both files define a `@dataclass` subclass solely to change `strict`'s default to `True`. Python dataclass inheritance places the child's re-declared field in the `__init__` signature at the parent's original position, which works but is the least-obvious way to set a constructor default. More importantly, `@dataclass` on the child regenerates `__init__`, `__repr__`, and `__eq__` including the inherited `_index: int = 0` field, so `RecordingRunner(strict=True)` in a test call site becomes ambiguous (is `_index` also a param?). This also makes the subclass appear as a distinct type to type-checkers, silently widening the accepted-runner interface. **Suggested fix:** Remove both local subclasses and instead call the shared runner directly as `RecordingRunner(strict=True, responses=[...])`. The `strict` parameter is already on `test_support.RecordingRunner`, so no subclass is needed; the two files should import `RecordingRunner` directly rather than creating a local alias-with-override.

- **code-quality** `python/conftest.py:21-22` — The autouse fixture patches the module-level private variable `logging_util._self_initialized_quiet` by string name. If that private variable is renamed during a future refactor, `monkeypatch.setattr` will raise `AttributeError` at fixture setup, failing every test in the suite rather than producing a targeted error at the site of the rename. Additionally, the fixture sets `LARCH_QUIET_DISABLE=1` globally, which means the new quiet-aware code paths (`quiet_init`, `contract_stream`, fd-3/fd-4 routing added by this branch) are never exercised by any test in the diff — the plan's acceptance criteria explicitly requires fd-3 capture and fd-4 traceback tests, but no test in `test_ship.py` removes `LARCH_QUIET_DISABLE` to test actual quiet routing. **Suggested fix:** Add a documented public `_reset_quiet_state()` helper to `logging_util` (or expose via `quiet_init` reset path) so the fixture patches through the public surface; separately, add at least one test in `test_ship.py` that calls `monkeypatch.delenv(config.ENV_LARCH_QUIET_DISABLE)` and verifies that `contract_stream()` returns a wrapper over fd 3 and that breadcrumbs reach fd 4 after `quiet_init` succeeds — covering the acceptance criteria the plan explicitly requires.

### Out-of-Scope Observations

- **code-quality** `python/test_support.py:27` — `_index: int = 0` is a public dataclass field (leading underscore in Python does not make it private to `@dataclass`). It appears in `__init__`, `__repr__`, and `__eq__`, so `RecordingRunner() == RecordingRunner()` is true only if `_index` matches, and `repr(runner)` includes `_index=…`. This is pre-existing design but newly exported as a shared interface; callers in `test_gh.py` and others subclass from it, propagating the exposed `_index`. Consider using `field(init=False, repr=False, compare=False, default=0)` to hide it from the public interface.
