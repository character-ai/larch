### In-Scope Findings

- **correctness** `scripts/lib-design-reentry-guard.sh:619-622` — When the marker file exists but `_design_reentry_marker_mtime` cannot produce a usable timestamp (both `stat` forms fail or return non-numeric output, including the deliberate `!= "0"` rejection), `design_reentry_marker_hit` reports `REASON=absent` and admits the run without removing the file. A persistent unreadable marker therefore disables the guard for the full TTL window while leaving a misleading “absent” reason, which is fail-open relative to the stated goal of blocking same-session re-entry after a successful plan write. **Suggested fix:** On the `[ -f "$marker_path" ]` branch, if mtime resolution fails, best-effort `rm -f "$marker_path"` (or return a distinct `REASON=unreadable` and treat as hit) so a broken marker cannot silently neutralize the guard; add a harness fixture that creates a marker and forces both stat paths to fail (e.g., permission fixture where feasible).
