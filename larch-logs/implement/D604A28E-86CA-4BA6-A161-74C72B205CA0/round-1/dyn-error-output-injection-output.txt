### Out-of-Scope Observations

- **security** `scripts/tracking-issue-read.sh:291-294` — The new sentinel hardening correctly uses the fixed token `'malformed-value-omitted'` for invalid non-empty `ISSUE_NUMBER` and `RUN_ID` (lines 285–290) and static text for argv `--issue` via `fail_usage "--issue must be numeric"` (lines 230–233); `scripts/get-issue-state.sh:52-54` likewise emits only the static `ERROR=--issue must be numeric` string. The adjacent, pre-existing `ADOPTED` failure path still interpolates `$ADOPTED_VAL` into stdout (`ERROR=invalid ADOPTED value in sentinel: '$ADOPTED_VAL' ...`), so a corrupted sentinel can still inject attacker-controlled bytes (including newlines or `KEY=` tokens) into the KEY=VALUE stream on that path. **Suggested fix:** Apply the same fixed-token redaction pattern to the `ADOPTED` error envelope (or reject without echoing the raw value), and extend the sentinel harness with a no-echo assertion similar to cases (t)–(u).

- **security** `scripts/get-issue-state.sh:64-68` — On `gh` failure, `ERROR=gh issue view failed: $SAFE` still forwards scrubbed-but-untrusted `gh` stderr into stdout; this predates the branch and is outside the new validation paths, but it remains a stdout-injection surface if `gh` ever returns attacker-influenced text. **Suggested fix:** Route `gh` errors through the same redaction/truncation helper used in `tracking-issue-read.sh` (`redact_gh_error`) or cap to a generic token-free message.

- **correctness** `scripts/tracking-issue-read.sh:275-280` — Line-oriented `extract_sentinel_key` means embedded-newline sentinel values are not exposed to the post-extraction `case` validators; the branch documents this gap and does not add a newline-rejection harness case. Blast radius stays bounded to session-tmpdir sentinels, but the documented “no echo / no injection” guarantee is same-line–only for malformed values. **Suggested fix:** If newline rejection becomes a requirement, validate after extraction with an explicit newline probe (e.g. `case "$val" in *$'\n'*)`) or reject multi-line values before emit, and pin with a harness case.
