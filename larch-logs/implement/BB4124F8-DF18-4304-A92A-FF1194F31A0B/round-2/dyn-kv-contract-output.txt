### In-Scope Findings

- **correctness** `skills/design/scripts/design-plan-quality-assessor.sh:108` — `WORKFLOW_PATH` is resolved with `json_scalar_or_sed … SIMPLE`, so a missing, null, or unreadable `workflow_path` is treated as non-HARD and the driver settles with `ASSESSOR_STATUS=skipped` and exits 0. That diverges from `scripts/read-design-classification.sh:6-52`, which defaults missing/invalid `design_classification` to **HARD** with a warning. On a partially corrupted `run-params.json` (e.g. `design_classification: "HARD"` but `workflow_path` null/absent after manual edit or a bad merge), the rest of `/design` can still behave as HARD while Step 3.6 silently skips the quality gate with no `WARN=` about the mismatch. **Suggested fix:** When `workflow_path` is empty, fall back to `design_classification` (map `HARD` → HARD lane) or default `workflow_path` to HARD when classification is HARD; at minimum emit a `WARN=` when `design_classification` and `workflow_path` disagree so operators see assessor skip is not intentional.

- **correctness** `skills/design/scripts/design-plan-quality-assessor.sh:240-253` — `_assess_rc` is captured from `"$ASSESS_SH"` but never used; after any non-zero child exit the driver still runs `parse_kv_from_output` and backfills with `ASSESSOR_STATUS=skipped` / `ASSESSOR_VERDICT=skipped` before `_write_result_and_emit` and exit 0. Today `assess-plan-round.sh` mostly exits 0 on operational paths, so this is latent, but a future non-zero failure with partial/empty stdout would surface as a benign skip to the orchestrator instead of the Step 3.6 fail-closed path. **Suggested fix:** After the `set -e` block, if `_assess_rc -ne 0`, append a `WARN=`, set `ASSESSOR_STATUS` to a distinct settled status (or propagate failure via exit 2), and document the contract in `design-plan-quality-assessor.md`; mirror with a harness case.

- **correctness** `skills/design/SKILL.md:1051-1058` vs `skills/design/scripts/design-plan-quality-assessor.sh:108` — The orchestrator pre-read leaves `_wp` empty when `workflow_path` is absent (`jq`/`sed` yield `""`), so the skip breadcrumb prints `workflow_path=` with no value, while the driver records `WORKFLOW_PATH=SIMPLE` in `.step3.6-assessor.env`. Outcomes align (both skip), but telemetry diverges and can hide the SIMPLE default on corruption. **Suggested fix:** In the SKILL.md pre-read, apply the same default as the driver (`SIMPLE` when empty after parse) or print the parsed `WORKFLOW_PATH` from the driver result env after invoke; add a harness case for missing `workflow_path` with HARD `design_classification`.
