### In-Scope Findings

- **architecture** `.claude/skills/audit-runs/SKILL.md:136-146` — `audit-title.sh` prints a `TITLE=…` KV line (see `.claude/skills/audit-runs/scripts/audit-title.sh:47-66`), but **Title Format** only assigns `TITLE_OUT=$(bash … audit-title.sh …)` and illustrates the value as `[Run Logs Audit Report …]` without the `TITLE=` prefix, unlike `PACIFIC_TIMESTAMP` which is explicitly parsed with `sed -n 's/^PACIFIC_TIMESTAMP=//p'` (`.claude/skills/audit-runs/SKILL.md:139-140`). An orchestrator that passes `TITLE_OUT` straight into `create-one.sh --title` would file issues whose title literally starts with `TITLE=`, which is a silent contract break. **Suggested fix:** Document the same stripping pattern for titles (for example `sed -n 's/^TITLE=//p'` on `TITLE_OUT`, or state clearly that `--title` must use the substring after `TITLE=`), and align the comment example with the script’s actual stdout.

- **architecture** `.claude/skills/audit-runs/SKILL.md:210-219` — **Close Prior Reports** only tells the operator to expect `CLOSED_NUMBER=<N>` lines, while `.claude/skills/audit-runs/scripts/audit-close-priors.sh:37-64` also emits `ISSUE_LIST_FAILED=true` / `REASON=…` (with exit status `1`) when listing issues fails, and per-issue `CLOSE_FAILED=…` / `REASON=…` when comment or close fails while the script still exits `0`. None of that failure or partial-failure surface is named in `SKILL.md`, so the main skill contract is narrower than the script (and than `.claude/skills/audit-runs/scripts/audit-close-priors.md:5-14`), and an LLM can treat a half-failed close pass as success. **Suggested fix:** Extend **Close Prior Reports** (and optionally the **Scripts** bullet for `audit-close-priors.sh`) to list every stdout key and the exit-code rules: fail-fast on non-zero exit / `ISSUE_LIST_FAILED`, and on success still scan stdout for `CLOSE_FAILED=` and surface `REASON` to the user.

- **architecture** `.claude/skills/audit-runs/SKILL.md:242-258` — The **Revised Orchestrator Flow** summary under-documents the KV surface compared to the normative sections above: for example `audit-resolve-prs.sh` is reduced to `PR_LIST, PRIOR_REPORT_NUMBER, RESOLVED_ECHO` (`.claude/skills/audit-runs/SKILL.md:246`) even though **Verbal-Description Resolution** requires `PR_COUNT`, `IMPLICIT_SINCE_LAST_AUDIT`, and `ERROR` as well (`.claude/skills/audit-runs/SKILL.md:49`), and `audit-preflight.sh` (`.claude/skills/audit-runs/SKILL.md:245`) omits `REASON` even though **Pre-flight** documents it (`.claude/skills/audit-runs/SKILL.md:40`).
