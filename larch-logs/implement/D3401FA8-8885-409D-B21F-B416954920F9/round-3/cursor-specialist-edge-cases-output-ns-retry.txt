### In-Scope Findings

1. - **architecture** `.claude/skills/audit-runs/scripts/audit-preflight.md:12` and `.claude/skills/audit-runs/scripts/audit-preflight.sh:10-24` — The contract says the script always exits 0 and callers should read `PREFLIGHT_OK`, but unknown argv hits `exit 1` with only stderr text, so an orchestrator that ignores non-zero exits can treat a failed parse as an empty or stale stdout contract and continue. **Suggested fix:** Either document non-zero exits for usage errors in `audit-preflight.md` (and the script header) or fold bad argv into `PREFLIGHT_OK=false` with a `REASON` and keep exit 0 for all machine-readable outcomes.

2. - **architecture** `.claude/skills/audit-runs/scripts/audit-resolve-prs.md:16-19` and `.claude/skills/audit-runs/scripts/audit-resolve-prs.sh:19-33` — Same mismatch as preflight: `audit-resolve-prs.md` promises “Always exits 0” while malformed flags `exit 1`, so automated wrappers that only parse KV on success paths can mis-handle usage failures. **Suggested fix:** Align `audit-resolve-prs.md` and the `Exit codes` header with the real behavior, or emit `ERROR=…` / empty `PR_LIST` and exit 0 for argv errors to match the documented contract.

3. - **correctness** `.claude/skills/audit-runs/scripts/audit-resolve-prs.sh:52-78` — `fetch_merged_main_prs_json` stops after 100 pages (≤10k closed PRs per accumulation), then `since last audit`, `since <ISO>`, and `last N PRs` all filter only within that truncated universe; on a busy repo, PRs merged after the cutoff but not present in those pages never enter `PR_LIST`, producing an audit that looks complete but omits merges (worst case: `ERROR=no new PRs…` when newer PRs exist off the tail). **Suggested fix:** Paginate until empty batch, raise a hard cap with an explicit `ERROR` when the cap is hit, or switch to a targeted GitHub search/GraphQL query bounded by `mergedAt` instead of unbounded list materialization.

4. - **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:280-295` — `scan_changelog_rebase_conflicts` always emits `"result":"pass"` even when `count>0`, unlike other scans that use `fail` when the measured condition is non-zero; any consumer that keys off `result` (and ignores `count`) will silently skip changelog/rebase signals while `CHANGELOG_DELTA` still grows from `audit-compute-counters.sh`. **Suggested fix:** Emit `result:"fail"` when `count>0` (or introduce a neutral `result:"finding"` consistently documented in `audit-scan-run.md` and tests) so NDJSON semantics stay aligned with the cumulative counter path.

5. - **correctness** `.claude/skills/audit-runs/scripts/audit-map-runs.sh:78-97` — Fallback walks `"$LOG_ROOT"/*/parent-issue.md` in glob order and breaks on the first `ISSUE_NUMBER` match; if more than one run directory contains the same `ISSUE_NUMBER` (retries, superseded runs, copied trees), the chosen `RUN_ID` is filesystem-order dependent and can point the scanner at the wrong log set while still filling `closes_issue`. **Suggested fix:** After collecting all matches, pick the same “newest `started_at` from manifest.json” rule used for primary `pr_number` hits, or fail loud when multiple candidates tie without a strict total order.

6. - **risk-integration** `.claude/skills/audit-runs/scripts/test-audit-runs.sh:1933-1970` — New “preflight” coverage reimplements concurrency comparison and `normalize_repo` inline instead of invoking `audit-preflight.sh` (contrast with tests 31–35 that subprocess real scripts), so `audit-preflight.sh` can regress its real `jq`/date/gh integration while tests still pass. **Suggested fix:** Extend the hermetic stub pattern (as in test 32) to run `audit-preflight.sh` under a fake `PATH` for `gh`/`git`/`date` or assert on its stdout KV for representative branches.

7. - **correctness** `.claude/skills/audit-runs/scripts/audit-compute-counters.sh:46-71` — `parse_prior` plus `num_or_zero` turns any malformed prior counter string into `0`, so a corrupted prior report silently resets baselines and makes deltas look like first-time totals instead of surfacing a hard error. **Suggested fix:** If `parse_prior` returns non-empty but `num_or_zero` yields 0 while the raw token was non-empty, emit a distinct `ERROR`/`WARN` KV or exit non-zero so operators fix the prior issue body rather than publishing wrong cumulative history.
