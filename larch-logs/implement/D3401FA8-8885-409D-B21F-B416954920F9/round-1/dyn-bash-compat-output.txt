Verifying the preflight `RECENT` pipeline and `GH_REPO` normalization.

Confirmed: when `jq` exits 0 it prints `true` and the extra `echo "true"` makes `RECENT` two lines, so the strict equality check fails and the concurrency guard does not fire.

### In-Scope Findings

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-preflight.sh:82-86` — The `RECENT=$(gh … | jq -e … && echo "true" || echo "false")` construct captures **both** `jq`’s stdout (e.g. a literal `true` line) and the following `echo "true"`, so `RECENT` becomes a two-line value like `true`/`true`; `[ "$RECENT" = "true" ]` then never matches when a recent audit exists and the guard silently stays open, allowing overlapping audits despite the intended 5-minute window. **Suggested fix:** Drop the duplicate `echo` and either redirect `jq` stdout to `/dev/null` and emit a single sentinel (`echo true`/`echo false`) from exit status alone, or use `if gh … | jq -e … >/dev/null; then RECENT=true; else RECENT=false; fi` so the captured value is exactly one line.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-pacific-timestamp.sh:17-21` — The primary path formats with `date +"%Y-%m-%dT%H:%M%z"` and then forces `±HHMM → ±HH:MM` via a trailing `sed` that only matches a **four-digit** numeric offset at the end of the string; this matches common macOS/BSD `%-0700` style output, but if `date` ever emits an offset form that does not end in four digits (unusual `%z` behavior, unexpected trailing text, or a future colonized `%z` that interacts oddly with the pattern), `PACIFIC_TIMESTAMP` can miss the contract’s explicit `-07:00`/`-08:00` shape. **Suggested fix:** After formatting, validate with a strict pattern (e.g. `grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}[+-][0-9]{2}:[0-9]{2}$'`) and fall through to UTC or `get_pacific_manual` when validation fails, or normalize offsets with a small case split for `±HHMM` vs `±H:MM` vs `±HH:MM` instead of one brittle `sed`.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-pacific-timestamp.sh:28-64` — When the `TZ=America/Los_Angeles date …` path fails, `get_pacific_manual` derives “Pacific” time by subtracting a fixed 7/8 hours from **UTC wall-clock fields** with only a partial day rollback and an explicit non-handling of month/year rollover, so the emitted timestamp is not a faithful `America/Los_Angeles` conversion in edge windows (DST transitions, month boundaries) even though downstream SKILL text treats it like a real Pacific audit clock. **Suggested fix:** If the TZ path fails, skip this pseudo-Pacific path and go straight to the documented UTC fallback (or call a small helper that does real Olson-zone conversion), so operators never see a misleading “Pacific” label.

- **code-quality** `.claude/skills/audit-runs/scripts/audit-title.sh:59-62` — The `PR_REFS=$(… awk … | sed …)` pipeline is dead on arrival because the next line recomputes `PR_REFS` from the `while read` loop, which invites future edits to change the wrong branch and makes review harder. **Suggested fix:** Delete the unused `awk`/`sed` assignment and keep only the working join pipeline (or vice versa), leaving a single obvious implementation.
