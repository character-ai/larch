- **architecture** `.claude/skills/audit-runs/SKILL.md:193-199` — The `cumulative_counters` YAML example is out of sync with [`audit-compute-counters.sh`](.claude/skills/audit-runs/scripts/audit-compute-counters.sh) and [`audit-compute-counters.md:12-24`](.claude/skills/audit-runs/scripts/audit-compute-counters.md): it still documents `ns_retries_cursor_specialist_launches`, which the script neither parses from prior frontmatter nor prints as a KV line, while omitting `oos_categories_blank` and `changelog_rebase_conflicts` even though the script reads/writes those keys via `OOS_CATEGORIES_BLANK` / `CHANGELOG_REBASE_CONFLICTS` (see [`audit-compute-counters.sh:57-62`](.claude/skills/audit-runs/scripts/audit-compute-counters.sh), [`audit-compute-counters.sh:129-134`](.claude/skills/audit-runs/scripts/audit-compute-counters.sh)). Together with [`SKILL.md:179`](.claude/skills/audit-runs/SKILL.md) telling operators to populate frontmatter from script output, this breaks the end-to-end contract chain the scout notes describe. **Suggested fix:** Make the `cumulative_counters` block an exhaustive mirror of every counter the script emits and parses; either implement and document `ns_retries_cursor_specialist_launches` in the script or remove it from the schema until it exists.

- **architecture** `.claude/skills/audit-runs/SKILL.md:53` — The sentence “Adding a scan = adding a TSV row, no SKILL.md edit needed” contradicts the actual wiring: each registry row needs a matching arm in [`audit-scan-run.sh:304-317`](.claude/skills/audit-runs/scripts/audit-scan-run.sh), optional aggregation in [`audit-compute-counters.sh:84-112`](.claude/skills/audit-runs/scripts/audit-compute-counters.sh), coordinated updates per [`audit-compute-counters.md:27-29`](.claude/skills/audit-runs/scripts/audit-compute-counters.md), and often human-facing docs/tests. **Suggested fix:** Replace this claim with an explicit multi-artifact checklist so registry edits are not mistaken for single-file work.

- **architecture** `.claude/skills/audit-runs/SKILL.md:62-73` — The human “Scans” table does not list `changelog-rebase-conflicts` (new in [`scans.tsv:11`](.claude/skills/audit-runs/scans.tsv)) and still does not reflect the full `scans.tsv` set (e.g. `rej-category-blank` on [`scans.tsv:5`](.claude/skills/audit-runs/scans.tsv)), so the narrative registry and machine registry diverge. **Suggested fix:** Add a row per `scans.tsv` scan name or delete the partial table and point readers solely at `scans.tsv` / `audit-scan-run.md`.

- **architecture** `.claude/skills/audit-runs/scripts/test-audit-runs.sh:1-2080` — There are no tests referencing `changelog` or the new scan’s NDJSON / counter path (confirmed by searching the file), so the new `changelog-rebase-conflicts` row is not covered by the harness despite [`audit-scan-run.md:27-28`](.claude/skills/audit-runs/scripts/audit-scan-run.md) and [`audit-compute-counters.md:27-29`](.claude/skills/audit-runs/scripts/audit-compute-counters.md) calling for coordinated tests. **Suggested fix:** Add hermetic fixtures that assert the NDJSON shape for matching/non-matching `execution-issues.ndjson` bodies and that `CHANGELOG_*` KVs sum correctly with a synthetic `scan-results-*.ndjson` plus a small prior-frontmatter sample.

- **architecture** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:298-317` — The driver `case "$scan_name"` has no default branch, so any `scans.tsv` name without a matching arm produces no NDJSON record (silent drop), which is worse than a loud failure for registry drift detection. **Suggested fix:** Emit an explicit error NDJSON line (and non-zero exit) for unknown scan names so TSV and script cannot silently diverge.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:280-295` — `scan_changelog_rebase_conflicts` always emits `"result":"pass"` even when `count` is non-zero, unlike other counting scans that flip to `fail` when counts indicate problems; consumers that key off `result` for pass/fail tables can disagree with `count` and with [`audit-compute-counters.sh:109-112`](.claude/skills/audit-runs/scripts/audit-compute-counters.sh) which only sums `count`. **Suggested fix:** Set `"result":"fail"` when `count>0` (keeping `count` for deltas) or document that only `count` is authoritative and ensure all consumers follow that rule.
