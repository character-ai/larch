### In-Scope Findings

- **correctness** `.claude/skills/audit-runs/scripts/audit-preflight.sh:71-80` — Repo identity compares normalized `REMOTE_REPO` to `GH_REPO`, but `GH_REPO` is produced only by stripping the `https://github.com/` prefix while `REMOTE_REPO` uses a different normalization path; if GitHub’s `url` includes a `.git` suffix (or other shape divergence), you can get a false `PREFLIGHT_OK=false` even when the clone matches `--repo`, and the `REASON=... expected=%s` line prints `--repo` rather than the parsed GitHub identity, which can mislead debugging. **Suggested fix:** Normalize both sides with the same function (strip scheme, host, optional `.git`, trailing slashes) and include both parsed identities in `REASON` when they differ.

- **correctness** `.claude/skills/audit-runs/scripts/audit-pacific-timestamp.sh:7-73` — The header comments claim US DST transition rules, but the manual fallback applies a fixed “Apr–Oct = -07:00” month window, adjusts only the hour (and explicitly skips month/year rollover), and derives “Pacific” time from **UTC** date fields; when `TZ=America/Los_Angeles` is unavailable or returns empty, `PACIFIC_TIMESTAMP` can be the wrong Pacific wall clock and wrong calendar day near boundaries (including the stated Mar/Nov transition window). **Suggested fix:** Prefer failing closed into the documented UTC last-resort when `TZ` is unavailable, or implement a real zone conversion (or call `python`/`zdump`) instead of arithmetic on UTC clock fields.

- **architecture** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:298-317` — The `scans.tsv` driver loop dispatches with a `case` that has no default branch, so a newly added registry row with a typo or a scan implemented only in TSV will be **silently skipped** while the run still exits 0 after emitting other scans—easy “everything passed” false confidence. **Suggested fix:** Add a `*)` branch that emits an NDJSON `setup`/`registry` error (or `exit 1`) for unknown `scan_name` values.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:280-295` — `changelog-rebase-conflicts` increments `count` but always emits `"result":"pass"` even when `count>0`, unlike other counting scans that flip to `fail` when non-zero; consumers aggregating pass/fail from NDJSON can treat changelog hits as “passing.” **Suggested fix:** Emit `fail` when `count>0` (or introduce a neutral `result` like `info` and document it consistently across the skill + tests).

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-compute-counters.sh:94-98` and `.claude/skills/audit-runs/scripts/audit-scan-run.sh:320-329` — `audit-compute-counters.sh` sums `category-stats.canonical` / `.oos_blank`, but `audit-scan-run.sh` omits the entire `category-stats` object when `review-findings-full.jsonl` is missing; those deltas become **0** with no signal that data was absent, so cumulative clean/blank totals can be understated versus what a human would infer from “missing jsonl.” **Suggested fix:** Emit an explicit `category-stats` object with `result:"skip"` (or include a `data_missing:true` flag) and have `audit-compute-counters.sh` treat that as non-fatal but visibly separable from true zeros.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:170-184` — `codex-generalist-waste` selects `.steps[]` matches and pipes through `head -1`, so if multiple “round-1.*codex” steps exist, the script may evaluate the wrong duration (including picking a ≤120s step while another step exceeded 120s), yielding a false pass. **Suggested fix:** Aggregate with `max` across all matching steps (or sum, depending on the intended definition) instead of taking the first emitted line.

- **risk-integration** `.claude/skills/audit-runs/scripts/test-audit-runs.sh:1806-1836` — The “all 5 forms recognized” coverage re-implements dispatch regexes in `classify_verbal` rather than executing `audit-resolve-prs.sh`, so the unit tests can stay green while the real script’s parsing diverges after an edit. **Suggested fix:** Where offline `gh` is impossible, factor the dispatch into a tiny sourced shell fragment tested by both, or add a narrow `bash audit-resolve-prs.sh …` test behind recorded fixtures/stubs.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-close-priors.sh:38-40` — `ISSUE_LIST_FAILED=true` is printed to **stderr**, while the contract markdown describes stdout KV output; an orchestrator that only captures stdout will miss structured failure and may continue as if there were zero priors. **Suggested fix:** Emit the same KV shape on stdout (and keep stderr for human detail), matching `audit-close-priors.md`.
