### In-Scope Findings

- **architecture** `.claude/skills/audit-runs/scripts/audit-preflight.md:12` — The contract promises `Always exits 0; caller reads PREFLIGHT_OK`, but `audit-preflight.sh` exits `1` on unknown arguments after only a stderr message (`audit-preflight.sh:21-24`), producing **no** `PREFLIGHT_OK` / `REASON` stdout pair for that failure mode. **Suggested fix:** Align behavior with the contract by emitting `PREFLIGHT_OK=false` plus a `REASON=…` (or a dedicated `ERROR=…` key if you want symmetry with resolve) and exiting `0`, or change `audit-preflight.md` to document non-zero exits and absent KV for usage errors.

- **architecture** `.claude/skills/audit-runs/scripts/audit-resolve-prs.md:16` — The contract promises `Always exits 0` and full KV output, but `audit-resolve-prs.sh` exits `1` on unknown arguments with stderr only (`audit-resolve-prs.sh:30-33`), so none of `IMPLICIT_SINCE_LAST_AUDIT`, `PR_LIST`, `ERROR`, etc. are emitted. **Suggested fix:** Same as preflight: either emit a complete KV error surface and `exit 0`, or narrow the `.md` contract to match argv/exit semantics.

- **architecture** `.claude/skills/audit-runs/scripts/audit-close-priors.md:7-9` — The contract illustrates failure lines as `CLOSE_FAILED=<N>  REASON=<msg>` (space-delimited tokens), but `audit-close-priors.sh` prints `CLOSE_FAILED=<N>` then a **tab** before `REASON=…` (`audit-close-priors.sh:60-63`). **Suggested fix:** Make the delimiter match the contract (spaces only) or update `audit-close-priors.md` to document the actual TAB-separated field layout.

- **architecture** `.claude/skills/audit-runs/SKILL.md:193-199` — The `cumulative_counters` YAML example omits `oos_categories_blank` and `changelog_rebase_conflicts`, while `audit-compute-counters.md:12-24` and `audit-compute-counters.sh:595-606` define stdout KV including `OOS_CATEGORIES_BLANK`, `OOS_BLANK_DELTA`, `CHANGELOG_REBASE_CONFLICTS`, and `CHANGELOG_DELTA`; `audit-compute-counters.md:29` explicitly calls for syncing `SKILL.md` frontmatter keys in the same change. **Suggested fix:** Extend the SKILL frontmatter example (and any prose that lists counter inputs) so every counter emitted by `audit-compute-counters.sh` has a documented YAML home consistent with prior parsing in `audit-compute-counters.sh:529-534`.

- **architecture** `.claude/skills/audit-runs/scripts/audit-scan-run.md:23` — The contract states synthetic `category-stats` **and** `cross-cutting` objects are part of the output, but `audit-scan-run.sh:320-329` emits `category-stats` only when `review-findings-full.jsonl` exists, while `cross-cutting` is always emitted (`audit-scan-run.sh:331-345`). **Suggested fix:** Either always emit a `category-stats` line (zeros when the JSONL is absent) or revise `audit-scan-run.md` to say `category-stats` is conditional on that file.
