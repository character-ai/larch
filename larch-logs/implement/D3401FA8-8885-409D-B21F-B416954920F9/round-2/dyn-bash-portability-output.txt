### In-Scope Findings

- **code-quality** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:237-238` — `cache-freshness` uses `sort -V` for semver ordering; that flag is not guaranteed on every BSD/macOS `/usr/bin/sort` userspace the repo still targets next to Bash 3.2, and under `set -euo pipefail` a non-supporting `sort` exits non-zero and aborts the whole script before the rest of the scans and summary NDJSON run. **Suggested fix:** Avoid a hard dependency on `sort -V` (for example compare dotted version tuples in `awk`, use an explicit `jq` numeric compare on split segments, or feature-detect `sort -V` and fall back to a portable comparator) so cache comparison cannot take down the entire scan driver on older toolchains.

- **code-quality** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:157-167,247-256` — In `scan_codex_round1_adherence` and `scan_coder_tool`, loop-scratch assignments (`round_dir`, `round_num`, `tool`) are not `local`, unlike most other scan helpers in the same file, so each invocation mutates the global namespace and makes ordering/refactors brittle under `set -u` or future shared helpers. **Suggested fix:** Mark those temporaries as `local` (or assign into `local` variables) so each `scan_*` function stays side-effect free and consistent with the rest of the file.
