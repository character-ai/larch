### In-Scope Findings

- **risk-integration** `python/ship.py:13-32` — The Python 3.12 floor is enforced only when `ship.py` starts at `/implement` Step 8+, after implementation, review, and commits may already be done. With Python now the default driver (`LARCH_SHIP_PR_IMPL` defaulting to `python` in `docs/configuration-and-permissions.md` and `AGENTS.md`), a host whose `python3` is 3.11 or older can complete most of the run and then stall with `outcome=STALLED` and no PR. `scripts/session-setup.sh` and `scripts/implement-bootstrap.sh` do not probe the interpreter version, so there is no early fail-fast with the documented `LARCH_SHIP_PR_IMPL=bash` rollback hint from `docs/installation-and-setup.md`. **Suggested fix:** Add a Step 0 (or session-setup) version probe when the default Python ship path is active; fail loudly before Step 2 with the rollback instructions, mirroring the `ship.py` JSON contract.

- **risk-integration** `skills/design/SKILL.md:1213` — MainAgent re-tally `SCOPE_ANCHOR_FILE` refresh into `.step3-plan-review-result.env` and `.step3-review-result.env` is orchestrator prose only. `plan-review-loop.sh` and `run-step3-review.sh` mechanically gate handoffs via `scripts/lib-scope-anchor-handoff.sh`, and `larch_scope_anchor_retally_handoff_value` encodes the re-tally contract in `scripts/lib-scope-anchor-handoff.sh:103-119`, but no production script calls it during re-tally. `skills/design/scripts/test-step3-orchestrator-fence.sh:329-367` only grep-pins SKILL.md/approval-gates prose, unlike `test-plan-review-loop.sh` and `test-run-step3-review.sh`, which exercise stale-seed and tally-error omission mechanically. An orchestrator that reuses exported `SCOPE_ANCHOR_FILE` on re-tally `tally-error`, or skips dual-env refresh on `ok`, can leave stale anchor paths for Gate B / Step 3.6 — the exact failure mode the plan called FINDING_5/FINDING_12. **Suggested fix:** Wire re-tally through a small helper (or extend `tally-plan-review.sh` post-processing) that calls `larch_scope_anchor_retally_handoff_value` and rewrites both result env files, and add a stale-seed harness case parallel to the loop/run-step3 tests.

- **risk-integration** `Makefile:4` — CI dropped Python 3.11 from `.github/workflows/ci.yaml` (matrix is `3.12` only), but `make py-test` uses `$(PYTHON) -m pytest` with `PYTHON ?= python3` and no version floor. On a machine where `python3` is 3.11, `make py-test` can pass syntax checks or fail opaquely while `pyproject.toml` requires `>=3.12`; this diverges from CI and from the new production default. `scripts/relevant-checks.sh` gates `py-test` on 3.12+, but bare `make py-test` does not. **Suggested fix:** Have the Makefile target reject `python3` below 3.12 (same probe as `python/ship.py`) or document/require `PYTHON=python3.12` explicitly in `docs/linting.md` with a failing guard in the recipe.
