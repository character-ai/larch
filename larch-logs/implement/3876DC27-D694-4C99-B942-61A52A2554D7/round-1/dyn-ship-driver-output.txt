### In-Scope Findings

- **architecture** `skills/shared/scripts/render-voter-prompt.sh:28-39` — `validate_scope_anchor_file()` rejects any anchor not under `$REPO_ROOT`, `/tmp`, or `/var/folders`, but `/design` materializes `plan-review-scope-anchor.txt` under `$XDG_CACHE_HOME/larch/sessions/…` via `scripts/session-setup.sh:259-266`. `dispatch-plan-voters.sh:74-77` always forwards that staged path into `render-voter-prompt.sh`, so the normal cache-backed session layout fails closed with exit 2 and plan-review voter prompts never render. Harnesses pass because they use `mktemp` under `/tmp`. **Suggested fix:** Align containment with `render-main-agent-scope-anchor.sh:33-40` — accept `--design-tmpdir` (or derive it from the caller) and require the canonical anchor path to resolve under that tmpdir; alternatively extend the allowlist to the `session_cache_root` pattern from `session-setup.sh`.

- **architecture** `skills/review/scripts/aggregate-findings.sh:218-221` — The new plan-review scope-anchor append uses `redact-secrets.sh` only and inlines raw bytes into the aggregator prompt. Every other scope-anchor consumer on this branch (`render-voter-prompt.sh`, `revise-plan-with-waterfall.sh`, `launch-claude-subprocess.sh`) uses the literal-redacted escaped block contract documented in `SECURITY.md`. That splits the two-surface trust model inside one pipeline stage and leaves delimiter/instruction-breakout exposure in the LLM aggregation pass. **Suggested fix:** Reuse `emit_untrusted_file_block` (or the same redact + `&lt;`/`&gt;`/`&amp;` pipeline) for the aggregator scope section, and add a harness assertion in `skills/review/scripts/test-aggregate-findings.sh` mirroring the voter delimiter cases.

- **architecture** `skills/design/scripts/plan-review-loop.sh:554-576` vs `229-268` — Durable `SCOPE_ANCHOR_FILE` handoff is terminal-gated in `_scope_anchor_handoff_value()` / `write_step3_result_env()` / `emit_loop_kvs()`, but `_write_round_summary()` always writes `SCOPE_ANCHOR_FILE=${SCOPE_ANCHOR_FILE:-}` from the materialized module variable, including on `panel-failed` and `tally-error` exits (`1829-1833`, `_snapshot_terminal_exit_preserving_status`). `plan-review-loop.md:64-66` documents `SCOPE_ANCHOR_FILE` in `round-summary.env` without the same terminal gate, so forensic round artifacts can contradict the normalized handoff contract that `run-step3-review.sh` and `SECURITY.md` describe. **Suggested fix:** Route `round-summary.env` through `_scope_anchor_handoff_value()` (or omit the key when tally terminal is not `ok` / `main-agent-vote-required`), and document the gate in `plan-review-loop.md` so passive-summary readers do not treat error-round summaries as authoritative handoff state.

- **architecture** `skills/design/scripts/run-step3-review.sh:148-150` — `scope_anchor_relay_allowed()` permits relay when `TALLY_PLAN_REVIEW_STATUS=ok` regardless of `LOOP_STATUS`, while the inner loop gates on tally terminal only (`plan-review-loop.sh:231-234`) and the docs describe tally-terminal relay (`run-step3-review.md:42`, `SECURITY.md:232`). If file-first `.step3-plan-review-result.env` parsing ever leaves `TALLY_PLAN_REVIEW_STATUS=ok` paired with a failure `LOOP_STATUS` (partial/crashed write, manual repair), Step 3 would re-emit a scope anchor the inner loop intentionally withheld. **Suggested fix:** Mirror the loop gate exactly — require `TALLY_PLAN_REVIEW_STATUS` ∈ `{ok, main-agent-vote-required}` and reject relay when `LOOP_STATUS` is in the Gate-B-bypass / error set (`tally-error`, `panel-failed`, etc.), with a stale-seed harness case in `test-run-step3-review.sh`.

- **architecture** `skills/design/SKILL.md:4521` (re-tally block) — MainAgent re-tally `SCOPE_ANCHOR_FILE` refresh (`_RETALLY_SCOPE_ANCHOR_IN` / `_RETALLY_PARSED_SCOPE_ANCHOR_FILE`, dual env rewrite, tally-error omission) lives only in orchestrator prose, while loop and Step-3 relay logic is enforced in `plan-review-loop.sh` and `run-step3-review.sh`. `test-step3-orchestrator-fence.sh` pins substring presence but there is no executable contract for the re-tally path comparable to the loop harness stale-leak cases. **Suggested fix:** Extract re-tally parse/persist into a small sourced helper (parallel to `_scope_anchor_handoff_value`) invoked from a thin SKILL.md Bash fence, and add an offline harness that seeds stale exported `SCOPE_ANCHOR_FILE`, omits the KV on `tally-error`, and asserts both refreshed env files stay clean.
