Reviewing the branch diff and commit history for security issues in prompt-rendering changes.
### In-Scope Findings
- **security** `skills/review/scripts/aggregate-findings.sh:218-221` — This branch wires plan-review scope anchoring into the findings aggregator (`plan-review-loop.sh` now passes `--scope-anchor-file "$SCOPE_ANCHOR_FILE"`), but the new inline path only pipes the anchor through `redact-secrets.sh` and appends it as raw markdown. Unlike sibling consumers (`render-voter-prompt.sh`, `render-main-agent-scope-anchor.sh`, `revise-plan-with-waterfall.sh`), it omits `<>&` escaping, the `encoding="literal-redacted"` wrapper, and the tag-like-content framing prose. Issue-body text can therefore inject delimiter-like sequences (for example `</context_file_1>`, `### In-Scope Findings`, or instruction-like lines) into the Codex/Cursor aggregator prompt and weaken the untrusted-data boundary during LLM merge/dedupe. **Suggested fix:** Reuse the hardened pattern from `skills/design/scripts/render-main-agent-scope-anchor.sh:43-51` or `skills/shared/scripts/render-voter-prompt.sh:21-25`—validate the path, emit untrusted framing prose, then render via `emit_untrusted_file_block plan_review_scope_anchor` (or delegate to `render-main-agent-scope-anchor.sh`). Add a harness case in `skills/review/scripts/test-aggregate-findings.sh` that asserts escaped delimiter bytes and framing when `--scope-anchor-file` is set.

- **security** `skills/design/scripts/render-plan-review-prompt.sh:115-127` — The branch adds `validate_design_prompt_file()` for `--feature-file` (the staged scope anchor) with symlink rejection and a 64KiB cap, but unlike `revise-plan-with-waterfall.sh` and `render-main-agent-scope-anchor.sh` it never requires the canonical path to resolve under `DESIGN_TMPDIR`. A miswired or same-UID-swapped `--feature-file` can therefore still pull arbitrary readable host content into external scout/reviewer prompts even though content is redacted and XML-escaped afterward. **Suggested fix:** After `canon="$(canonical_path "$path")"`, require `canon` under `$(cd "$DESIGN_TMPDIR" && pwd -P)/` for `--feature-file`, mirroring `render-main-agent-scope-anchor.sh:33-40` and the new containment checks in `revise-plan-with-waterfall.sh`.

- **security** `SECURITY.md:85-90` — The new “Plan-review scope-anchor pipeline” section states that scope-anchor consumers must render staged anchor material as “literal-redacted escaped evidence with untrusted framing prose,” but the branch simultaneously adds aggregator consumption without meeting that contract and does not list the aggregator among inline consumers. That creates false assurance that all anchor inlining is delimiter-safe when the aggregator path is not. **Suggested fix:** Either harden `aggregate-findings.sh` to match the documented contract and explicitly list the aggregator under inline consumers, or qualify `SECURITY.md` to state that the aggregator is a legacy/raw inline surface until migrated.
