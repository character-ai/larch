### In-Scope Findings

- **correctness** `skills/shared/scripts/render-voter-prompt.sh:28-55` — `validate_scope_anchor_file()` only accepts anchors under `REPO_ROOT`, `/tmp`/`/var/folders`, or `~/.cache/.../larch/sessions/*`, but `scripts/lib-design-tmpdir.sh` also permits any canonical path under `${TMPDIR}/`. A design session rooted in a custom `TMPDIR` (allowed by `larch_design_tmpdir_validate`) will still materialize `plan-review-scope-anchor.txt` there, and `dispatch-plan-voters.sh` will pass that path to `render-voter-prompt.sh`, which now hard-fails with exit 2 instead of the pre-branch readability-only check. Default cache-backed sessions are fine; custom-`TMPDIR` design runs break at voter prompt render. **Suggested fix:** Align the allowlist with `lib-design-tmpdir.sh` (include resolved `${TMPDIR%/}/*`) or mirror `aggregate-findings.sh` by accepting any path under the caller’s design/review tmpdir; add a harness case with `TMPDIR` outside `/tmp` and `/var/folders`.

- **correctness** `skills/design/scripts/plan-review-loop.sh:560-583` — `_write_round_summary()` always writes `SCOPE_ANCHOR_FILE=${SCOPE_ANCHOR_FILE:-}` from the materialized anchor path, including on `panel-failed` / `tally-error` terminals, while `write_step3_result_env()` / `emit_loop_kvs()` now gate the key through `_scope_anchor_handoff_value()` to `ok` / `main-agent-vote-required` only. Round summaries on failed terminals can therefore still record an anchor path that normalized Step 3 handoff deliberately omits, creating divergent durable state in `plan-review/round-N/round-summary.env` vs `.step3-plan-review-result.env`. **Suggested fix:** Reuse `_scope_anchor_handoff_value()` (or omit the key when `TALLY_PLAN_REVIEW_STATUS` / `LOOP_STATUS` are non-terminal) before writing `round-summary.env`, and extend `test-plan-review-loop.sh` with a `tally-error` / `panel-failed` round-summary assertion.

- **correctness** `scripts/check-scope-reduction-marker.sh:57-58` — Consolidating the stdin/file detectors also changed detection from `norm(cand).startswith("[SCOPE-REDUCTION]")` to case-insensitive `re.match(r"^\[SCOPE-REDUCTION\]", norm(cand), re.I)`, so lowercase variants like `[scope-reduction]` now classify as scope-reduction markers. That is not covered by `scripts/test-check-scope-reduction-marker.sh` and diverges from the uppercase-only marker contract referenced in `skills/design/SKILL.md`. **Suggested fix:** Either restore case-sensitive matching to preserve prior semantics, or add explicit tests and SKILL/SECURITY prose if case-insensitive detection is intended.

### Out-of-Scope Observations

- **correctness** `skills/design/scripts/plan-review-loop.sh:1311-1346` — The branch broadened dedup `comparison_text()` from stripping only `[important|nit|latent]` once to stripping arbitrary `[A-Za-z0-9_-]+` prefixes in a loop. This predates the scope-anchor handoff work and is not mechanically tied to the new `SCOPE_ANCHOR_FILE` relay, but it is a behavior change worth watching in dedup parity regressions.
