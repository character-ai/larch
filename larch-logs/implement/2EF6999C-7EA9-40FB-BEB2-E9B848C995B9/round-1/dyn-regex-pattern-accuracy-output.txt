### In-Scope Findings

- **correctness** `skills/design/scripts/file-design-oos.sh:74-104` — Cross-session `recover_oos_accepted_from_sentinel_urls` walks URLs in `oos-issues-created.md` order and, on each step, injects `urls[ui]` into the first `### OOS_*` block that still lacks a `Filed URL` line. That list is produced in `cmd_annotate` by collecting URLs from stdout and then `sort -u` (`skills/design/scripts/file-design-oos.sh:329-331`), so order is lexicographic, not `oos-design-filing-order.txt` order and not aligned with `ISSUE_<i>_URL` indices. With multiple accepted OOS items, lexical order of GitHub URLs can disagree with OOS block order, so recovery can stamp the wrong issue URL onto the wrong OOS block while still emitting `FILE_DESIGN_OOS_STATUS=skip-sentinel`. **Suggested fix:** persist a deterministic mapping for recovery (for example extend the cached sentinel to `OOS_<n><TAB><url>` lines written alongside the sorted URL list, or drop `sort -u` for the cache copy only and preserve declaration order), and drive recovery with the same keyed logic as the annotate Python (`cmd_annotate` `skills/design/scripts/file-design-oos.sh:287-305`).

- **correctness** `scripts/oos-disposition-shared.inc.bash:47` — The strict-line ERE requires `\*\*:` immediately before the colon, whereas other helpers use `\*\*Filed URL\*\*\s*:` (`skills/design/scripts/file-design-oos.sh:38`, `skills/design/scripts/file-design-oos.sh:94`). A manually edited or tooling-emitted line such as `- **Filed URL** : https://…` (space before colon) would be ignored by `count_filed_url_field_lines`, under-counting `filed_urls` versus blocks that the rest of the pipeline already treats as filed. **Suggested fix:** align the strict prefix with the looser “optional whitespace before colon” convention, e.g. `\*\*Filed[[:space:]]URL\*\*[[:space:]]*:` in the `grep -E` pattern, or normalize accepted markdown before counting.
