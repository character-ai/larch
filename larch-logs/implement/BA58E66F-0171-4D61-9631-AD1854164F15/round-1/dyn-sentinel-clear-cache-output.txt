Reviewing the branch diff and related source for sentinel vs `--clear-cross-session-cache` ordering.
### In-Scope Findings

- **architecture** `skills/design/scripts/file-design-oos.sh:229-251` — The new `oos-issue-sentinel` idempotency probe runs unconditionally after `--clear-cross-session-cache` deletes only the cross-session cache (`~/.cache/larch/design-oos-filed/<ISSUE_NUMBER>.md`) and before the cache-recovery branch, so an operator who passes `--clear-cross-session-cache` expecting the documented “force a normal re-file” path (`file-design-oos.md:14`, `skills/design/SKILL.md:1532`) is still hard-stopped with `FILE_DESIGN_OOS_STATUS=skip-already-filed-sentinel` whenever the in-session `/issue` sentinel has `ISSUES_CREATED>0`. That is correct for the resume-after-interrupt scenario this branch targets, but it creates asymmetric idempotency layers: cross-session cache has an explicit escape hatch; in-session sentinel does not, and nothing in the docs states that `--clear-cross-session-cache` does not apply to `oos-issue-sentinel`. **Suggested fix:** Document the precedence explicitly in `file-design-oos.md` and `skills/design/SKILL.md` (cross-session clear does not remove or bypass `oos-issue-sentinel`; same-session recovery should run `annotate`, not re-`prepare`). If intentional force re-file in a persisted tmpdir is ever required, add a separate, loudly warned flag (e.g. `--clear-issue-sentinel`) rather than overloading `--clear-cross-session-cache`, and add harness case `S2` asserting `--clear-cross-session-cache` + present sentinel still yields `skip-already-filed-sentinel`.

- **architecture** `skills/design/SKILL.md:1544-1560` — `cmd_prepare` now emits a new terminal status `skip-already-filed-sentinel` (`file-design-oos.sh:245-248`), but Step 5b only branches on `skip-sentinel`, `skip-no-items`, `skip-all-security`, and `ready`. There is no orchestrator contract for the new status (no skip breadcrumb, no guidance to attempt `annotate` from retained `oos-issue.stdout.txt`, no `Warnings` entry for the `WARN=` line). An orchestrator that only follows the enumerated branches may fall through undefined behavior instead of deterministically skipping `/larch:issue` and continuing to Step 5c. **Suggested fix:** Add a Step 5b branch for `FILE_DESIGN_OOS_STATUS=skip-already-filed-sentinel` mirroring `skip-sentinel` (skip `/issue`, print an operator-visible `⏩` line, optionally attempt `annotate` when `oos-issue.stdout.txt` exists, append the prepare `WARN=` to `execution-issues.md`), and extend the harness or a skill-contract test to pin that routing.

That predates this branch’s A1/A2 harness additions but remains an orchestrator/skill contract gap alongside the new prepare status above.
