Reviewing threshold counting semantics: reading the branch diff and the threshold script plus its callers.
Branch commits (since `main`): `f8454e785` (panel collapse), `dbcc84e76` (run log), `19a4a36d6` / `05793677e` (review fixes). Round 2 correctly wires `external_array` into `static_archetype_coverage_ok` (previously only `claude_array`), which matters for both-vendor panels.

### In-Scope Findings

- **correctness** `skills/review/scripts/check-reviewer-failure-threshold.sh:117-164` — The collector-results pass always appends each static row’s normalized basename to `COUNTED_BASES_FILE` and increments `COUNTED_SLOTS` / `FAILED_SLOTS` without checking whether that basename was already counted, while the `--reviewer-output-files` pass (lines 167–184) skips duplicates via `grep -Fxq`. If `collector-results.env` ever contains two records for the same static stem (e.g. `cursor-specialist-security-output.txt` and `cursor-specialist-security-output-phase3.txt`, or a retry sidecar plus base), failures are double-counted toward the `>50%` gate even though phase suffixes are meant to collapse to one logical slot. **Suggested fix:** In the collector blank-line handler, compute `normalized_base` first and `continue` when `grep -Fxq "$normalized_base" "$COUNTED_BASES_FILE"` already succeeds—mirror the `--reviewer-output-files` loop—before incrementing counters.

- **correctness** `skills/review/scripts/check-reviewer-failure-threshold.sh:167-184` — `--reviewer-output-files` dedupe is “collector wins”: any basename already recorded from collector is skipped entirely, even when collector `STATUS` is `ERROR` / `NOT_SUBSTANTIVE` / `timeout` but the on-disk file is substantive (`output_file_is_success` would return true). `review-core.sh` passes the same `external_array` / `claude_array` paths to both `collect-findings.sh` (collector) and `--reviewer-output-files`, so this path is live. On a 4-slot panel with four collector failures and four substantive files, `FAILED_SLOTS=4` yields `THRESHOLD_OK=false` (fail at ≥3) before `static_archetype_coverage_ok` runs; the `external-files-only` harness in `test-review-core.sh` only passes because the threshold stub forces `TEST_THRESHOLD_OK=true`. **Suggested fix:** When a `--reviewer-output-files` path normalizes to a basename already in `COUNTED_BASES_FILE`, re-evaluate with `output_file_is_success` and, if true, adjust `FAILED_SLOTS`/`SUCCEEDED_SLOTS` (or treat collector non-OK + substantive file as success) so aggregate threshold and per-archetype coverage stay aligned.

- **correctness** `skills/review/scripts/check-reviewer-failure-threshold.sh:187-195` — Dropped-static rows from `--dropped-slots-file` always increment `FAILED_SLOTS` with no dedupe against `COUNTED_BASES_FILE` or prior drop lines. Duplicate TSV rows for the same static slot (or a drop row plus a collector failure for the same emitted output, if that can occur) inflate `FAILED_SLOTS` without a corresponding increase in `INTENDED_SLOTS`, which can push an 8-slot panel over the ≥5 failure threshold incorrectly. **Suggested fix:** Track dropped `(slot,tool)` or normalized output basenames in a set and count each logical static drop once; optionally skip a drop when that basename already contributed a collector failure.

### Out-of-Scope Observations

- **correctness** `skills/review/scripts/review-core.sh:608-613` — `review-core.sh` sets `--launched-slots` equal to `--intended-slots` (`static_slot_count`), so the `NEVER_LAUNCHED` padding path in `check-reviewer-failure-threshold.sh:198-205` is unused in production; only harnesses like `never_launched` exercise it. That matches “denominator = emitted static rows” but differs from the `--launched-slots` doc wording about vendor-unhealthy never-launched slots unless another caller passes a lower launched count.

- **code-quality** `skills/review/scripts/review-core.sh:629-640` — The per-archetype coverage gate runs only when `THRESHOLD_OK != false`, so a round that already fails the aggregate `>50%` check may exit with the threshold reason and never surface `COVERAGE_GATE_REASON` for a missing archetype; operationally fine, but operators debugging “silent lens loss” on a heavily degraded panel may need both artifacts.

Overall, the 4/8 denominator, dynamic `dyn-*` / `dyn-*-codex-*` exclusion, dropped-static counting with `UNACCOUNTED_NEVER_LAUNCHED`, and `STATIC_SLOT_COUNT`-only wiring in `review-core.sh` match the plan; the main gaps are asymmetric dedupe between collector vs file passes and dropped-row idempotency.
