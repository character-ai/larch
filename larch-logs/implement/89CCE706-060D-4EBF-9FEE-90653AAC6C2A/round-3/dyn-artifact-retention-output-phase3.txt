### In-Scope Findings

- **risk-integration** `scripts/larch-log.sh` — The deny-list adds `dyn-*-codex-output.txt|dyn-*-codex-output.txt.meta|dyn-*-codex-output.txt.json|dyn-*-codex-output.txt.cap-hit` to committed-log exclusions, directly contradicting the plan's acceptance criterion: "larch-log.sh excludes static codex-specialist-* raw outputs/meta **but not dyn-*-codex twins**." The effect is asymmetric retention: Cursor dynamic twin outputs (`dyn-*-output.txt`) pass through the broad `*-output.txt` allow, while Codex dynamic twin outputs for the same archetype are denied. Committed run logs from both-vendor runs will be missing one vendor's perspective for every dynamic archetype, silently breaking post-hoc forensics (e.g., diagnosing why a dynamic Codex reviewer flagged or missed something) and making the log record for dynamic rounds structurally unbalanced. The updated `scripts/larch-log.md` rationalizes the exclusion as "so committed logs do not retain raw Codex reviewer transcripts outside the aggregate artifacts," but that rationale applies equally to Cursor dynamic twins, which remain included; neither is gated by the plan's intent. **Suggested fix:** Remove `dyn-*-codex-output.txt|dyn-*-codex-output.txt.meta|dyn-*-codex-output.txt.json|dyn-*-codex-output.txt.cap-hit` from the deny arm in `round_artifact_included()` so dynamic Codex twins are included via the existing broad `*-output.txt` / `*-output.txt.meta` / `*-output.txt.json` / `*-output.txt.cap-hit` allows, matching Cursor dynamic twin behavior; update `scripts/larch-log.md` and `scripts/test-larch-log-write-round.sh` to assert dynamic Codex twin inclusion, not exclusion.

- **risk-integration** `scripts/test-larch-log-write-round.sh` — The test harness adds positive assertions that `dyn-api-contract-codex-output.txt`, its `.meta`, and its `.json` are excluded, but adds no corresponding positive assertion that the Cursor dynamic twin `dyn-api-contract-output.txt` is included. The broad `*-output.txt` wildcard in `round_artifact_included()` is currently the only thing protecting Cursor dynamic twin inclusion; a future edit that accidentally extended the deny list to cover `dyn-*-output.txt` would silently break Cursor dynamic retention without causing a test failure. **Suggested fix:** Add a `printf 'cursor dynamic raw body\n' > "$source_dir/dyn-api-contract-output.txt"` fixture line and an `assert_file "$round_dir/dyn-api-contract-output.txt" "cursor dynamic twin included"` assertion alongside the Codex denial checks.

- **risk-integration** `scripts/larch-log.sh` — The deny pattern for dynamic Codex outputs is `dyn-*-codex-output.txt` (and its unphased sidecars), but the analogous phased-fallback variants `dyn-*-codex-output-phase2.txt`, `dyn-*-codex-output-phase3.txt`, and `dyn-*-codex-output-retry.txt` are absent from the deny list. The broad `*-output-*.txt` allow below would commit phased Codex dynamic outputs if they were ever produced by the waterfall (e.g., if a Codex dynamic slot underwent a phase-2 retry). This creates a partial exclusion hole: unphased Codex dynamic outputs are denied but phase-fallback variants of the same slot are committed. The probability is low given the `--no-fallback` path, but the inconsistency means a waterfall degradation could unexpectedly commit Codex dynamic raw transcripts that the deny list intends to suppress. **Suggested fix:** Either extend the deny to include `dyn-*-codex-output-phase*.txt|dyn-*-codex-output-retry.txt`, or — preferably — address Finding 1 by removing the denial entirely so the behavior is symmetric with Cursor dynamic twins.
