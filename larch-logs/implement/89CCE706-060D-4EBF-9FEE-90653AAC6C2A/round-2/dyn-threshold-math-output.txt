**Threshold-math trace (why no in-scope issues):**

1. **Denominator** — `review-core.sh` passes `--intended-slots` and `--launched-slots` both from `STATIC_SLOT_COUNT` (emitted row count, 4 or 8), not from availability flags.

2. **>50% gate** — `HALF_PLUS_ONE_MIN = INTENDED_SLOTS/2 + 1` yields fail at ≥3/4 and ≥5/8; harness cases `fail_4`, `pass_8`, `fail_8`, and `one_drop_8` match.

3. **Dropped peers** — Static TSV rows (non-`dyn-*` slots) add to `FAILED_SLOTS`; `UNACCOUNTED_NEVER_LAUNCHED = (INTENDED - LAUNCHED) - DROPPED_STATIC_SLOTS` avoids double-counting drops as never-launched padding.

4. **Dynamics** — `is_dynamic_reviewer_basename` / `is_dynamic_slot_name` keep `dyn-*` and `dyn-*-codex-output*` out of the static denominator.

5. **Phase outputs** — `normalize_reviewer_output_base` plus `--reviewer-output-files` (final paths from dispatch, including `*-phase3.txt` on Claude fallback) count phase failures without double-counting when a collector row already exists (see `test-check-reviewer-failure-threshold.sh` “output-files” case).

6. **Per-archetype coverage** — After threshold passes, `static_archetype_coverage_ok` requires each of `security`, `correctness`, `edge-cases`, `testing` to have at least one `OK|cap_hit` collector row or substantive Claude static file. For an 8-slot panel, ≥5 static failures implies ≤3 successes, so at least one archetype lacks any successful peer; when threshold passes with ≤4/8 failures, each archetype can still have a surviving peer, so the coverage gate complements rather than contradicts the aggregate gate.
