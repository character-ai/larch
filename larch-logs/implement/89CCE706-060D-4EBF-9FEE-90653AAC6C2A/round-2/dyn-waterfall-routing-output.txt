Reviewing the branch diff and commit history, then inspecting key routing scripts for waterfall and dropped-slot behavior.
Checking whether collector parsing can double-count failures and whether coverage omits successful external outputs.
`### In-Scope Findings`

Branch commits (since `main`): `f8454e785` (panel collapse + both-vendor dispatch), `dbcc84e76` (run-log flush), `19a4a36d6` (round-1 review fixes: threshold `--reviewer-output-files`, coverage gate + Claude fallback accounting).

- **risk-integration** `skills/review/scripts/check-reviewer-failure-threshold.sh:117-165` — The collector-results loop appends every static record to `COUNTED_BASES_FILE` and increments `COUNTED_SLOTS` / `FAILED_SLOTS` without checking whether that normalized basename was already counted, while the later `--reviewer-output-files` pass explicitly dedupes with `grep -Fxq` (lines 174–176). If `collector-results.env` ever contains two records for the same static archetype (for example both `cursor-specialist-testing-output.txt` and `cursor-specialist-testing-output-phase3.txt` with failing statuses), `FAILED_SLOTS` can be inflated to 2 for one archetype and push an otherwise healthy 8-slot panel over the >50% gate. **Suggested fix:** Mirror the output-files dedupe in the collector loop: before incrementing counters, skip when `normalize_reviewer_output_base "$current_base"` is already in `COUNTED_BASES_FILE`, or merge statuses so one basename contributes at most one success/failure outcome.

- **risk-integration** `skills/review/scripts/review-core.sh:430-484,624-627` — `static_archetype_coverage_ok` only treats collector `STATUS=OK|cap_hit` and substantive Claude outputs as archetype success; it does not consider substantive files in `external_array`. Threshold math can credit those same files via `--reviewer-output-files`, so a round can pass the >50% gate yet fail coverage with `no successful static reviewer for archetype(s): …` when collector rows are missing or non-OK but on-disk external outputs are substantive (mis-sync or collector edge case). **Suggested fix:** When evaluating coverage, also walk `external_array` with the same `static_slug_for_reviewer_file` + substantive check used for Claude outputs, or reuse normalized results already computed for threshold.

- **architecture** `skills/review/scripts/check-reviewer-failure-threshold.md:8-16` — The contract documents `--intended-slots`, `--dropped-slots-file`, and collector parsing, but omits `--reviewer-output-files`, which round 2 added as the mechanism for counting phase-2/phase-3 Claude fallback static outputs that never appear in `collector-results.env` (see `test-check-reviewer-failure-threshold.sh` “reviewer output files count phase fallback static slots”). **Suggested fix:** Add a row for `--reviewer-output-files` (optional, deduped against collector bases; used for phase2/phase3/retry static basenames) and note that `review-core.sh` forwards `external_array` + `claude_array` after collection.

- **code-quality** `skills/review/scripts/review-core.sh:548-560` — `dispatch_ok` and `static_dispatch_ok` are still parsed from `dispatch-panel.sh` but no longer influence control flow after removal of the `STATIC_DISPATCH_OK=false` → `THRESHOLD_REASON=dispatch-failed` short-circuit (see diff removal at ~2587). Under both-vendor `--no-fallback`, `dispatch-with-waterfall.sh` still sets `STATIC_DISPATCH_OK=false` on any single static drop/failure even when the opposite-vendor peer succeeded; nothing in `review-core` consumes that signal anymore. **Suggested fix:** Either drop the unused variables, emit a narrower KV from the waterfall (per-archetype static health), or document in `review-core.md` / `dispatch-panel.md` that panel failure is determined solely by threshold + coverage gate, not `STATIC_DISPATCH_OK`.

**What looks correct on routing (no issue filed):** `dispatch-panel.sh` emits four static archetypes with per-vendor rows, gates `--no-fallback` on both vendors, sets `codex_present_for_waterfall="$CODEX_AVAILABLE"`, forwards `DROPPED_SLOTS_FILE`, and uses `STATIC_SLOT_COUNT` as the threshold denominator; harnesses cover 1/8 dropped-peer pass and 5/8 fail (`test-check-reviewer-failure-threshold.sh`), dropped-slot wiring and dirty-tree recovery (`test-review-core.sh`), and conditional `--no-fallback` / Codex presence (`test-dispatch-panel.sh`).
