With both vendors and conditional `--no-fallback`, partial peer drops are expected to be more common, so this gap is materially worse after the change. **Suggested fix:** Add `round-*-dropped-slots.tsv` to the `write-round` allowlist (and document it in `scripts/larch-log.md`), run the file through `larch_log_redact_file` before staging, and extend `test-larch-log-write-round.sh` with a fixture that proves the TSV lands in `round-<N>/` while `dropped-slot-diags/` stays excluded.
