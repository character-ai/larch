### In-Scope Findings

- **correctness** `skills/review/scripts/review-core.sh:430-486` — The new per-archetype coverage gate credits an archetype when `collector-results.env` has `STATUS=OK` or `STATUS=cap_hit`, but it does not apply the same substantive-output check that `check-reviewer-failure-threshold.sh` uses via `--reviewer-output-files` (`output_file_is_success` / `NOT_SUBSTANTIVE` grep). If `collect-agent-results.sh` records `OK` while the on-disk static transcript is empty or non-substantive, threshold math can count that slot as failed while `static_archetype_coverage_ok` still records the slug as covered, so the round can pass the coverage gate without a substantive static lens for that archetype. **Suggested fix:** When building `success_file`, treat collector `OK` like threshold does: only add the slug if the normalized output path is also substantive (reuse `claude_static_output_is_success` or share one helper), or derive coverage from the same normalized-base status map `count_static_status_once` builds after collector + output-file reconciliation.

- **correctness** `skills/review/scripts/review-core.sh:623-627` — Phase-2/phase-3 static failures are only visible to threshold when their paths appear in `EXTERNAL_OUTPUT_FILES` / `CLAUDE_OUTPUT_FILES` (final waterfall outputs). `dispatch-panel.sh` does not forward `PHASE2_SLOTS` / `PHASE3_SLOTS`, and `review-core.sh` does not pass intermediate phase paths to `--reviewer-output-files`. Today a failed phase-2 file is invisible if a later phase on the same slot succeeds (one outcome per manifest row), which matches the contract doc, but a failed final phase-3 path that is omitted from `ALL_OUTPUT_FILES` while siblings succeed could yield `THRESHOLD_OK=true` with only dropped-slot + aggregate math (≤50% failures) even though `STATIC_DISPATCH_OK=false` and an archetype has no substantive peer. **Suggested fix:** Either forward `PHASE2_SLOTS`/`PHASE3_SLOTS` (or all manifest output paths) into threshold for static basenames whose final collector status is non-OK, or document and assert in `dispatch-with-waterfall.sh` that every static slot with `STATIC_DISPATCH_OK=false` always has a final path in `ALL_OUTPUT_FILES` or a static row in `DROPPED_SLOTS_FILE`.
