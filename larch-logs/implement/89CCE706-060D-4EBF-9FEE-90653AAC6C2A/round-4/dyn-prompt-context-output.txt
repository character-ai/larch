### In-Scope Findings

- **security** `scripts/render-specialist-prompt.md:33-34`, `scripts/render-specialist-prompt.sh:298-308`, `skills/review/scripts/dispatch-panel.sh:101-103` — Shipped docs and dispatch errors say `reviewer-testing` injects the folded plan-fidelity scan via `<implementation_plan>` in every mode, but the renderer still embeds plan/feature files only when `MODE=diff` and `DIFF_MODE=generic`. Round-3 harnesses (`scripts/test-render-specialist-prompt.sh:375-387`) lock in the opposite: plan text must **not** appear for `reviewer-testing` on docs-only/test-only/generated-only diffs or in description mode. Meanwhile `agents/reviewer-testing.md:24-35` tells reviewers to verify against `<implementation_plan>` when present. That is a trust-boundary/documentation gap: `--plan-file` is mandatory, agent prose promises plan context, and external Codex/Cursor slots often never receive a redacted plan block. **Suggested fix:** Either implement the documented `reviewer-testing` basename exception (inject via `emit_untrusted_file_block` for all diff modes + description, with tests flipped to `assert_contains`), or narrow all docs/agent copy/dispatch errors to match the generic-only gate and drop the false “injects folded plan-fidelity” wording.

- **security** `skills/review/scripts/dispatch-panel.sh:168-173` — Scout `rationale` and `prompt_body` are written into `<scout_notes>` with no `redact-secrets.sh` pass and no angle-bracket escaping, while this branch adds `emit_untrusted_file_block` (redact + escape) for plan/feature files in `scripts/render-specialist-prompt.sh:224-236`. Validation blocks `</scout_notes>` and `</reviewer_*` but not strings like `<implementation_plan encoding="literal-redacted">` inside `prompt_body`. A compromised or jailbroken scout can plant delimiter-shaped markup inside the specialist body that is printed **after** any legitimately escaped plan block, undermining the new encoding contract. Codex dynamic twins reuse the same pre-rendered prompt, widening exposure. **Suggested fix:** Pipe scout fields through the same `redact_untrusted_stream` helper (or `escape_prompt_data`) before embedding in `synthesize_dynamic_slots`, extend `scout_manifest_is_valid` to reject plan/feature delimiter patterns, and add a harness with a malicious `prompt_body` proving escaped output.

- **security** `SECURITY.md:113` vs `scripts/render-specialist-prompt.md:33-34` — `SECURITY.md` accurately states plan/feature context is emitted only for generic diff reviews. `render-specialist-prompt.md` still documents a `reviewer-testing` exception that the script does not implement. Security readers get a different contract than skill/doc maintainers. **Suggested fix:** Align `SECURITY.md` with the chosen behavior (if the exception is implemented, document it; if not, remove the exception from `render-specialist-prompt.md` and acceptance text).

- **architecture** `agents/reviewer-testing.md:33-35`, `scripts/render-specialist-prompt.sh:298-308` — Folding `plan-fidelity` into `reviewer-testing` depends on plan context for the secondary scan, but narrowed diff modes (`dispatch-panel.sh:2217` sets `SCOUT_STATUS=skipped-*` and passes `--diff-mode` into dynamic renders) and static slots launched via `scripts/launch-review.sh:349-359` (no `--diff-mode`, but classifier may still yield docs-only/test-only) omit the plan. Plan-conformance checks silently weaken on common PR shapes despite mandatory `--plan-file`. **Suggested fix:** Implement targeted plan injection for `reviewer-testing` only, or stop requiring `--plan-file` when the classifier narrows mode and adjust the secondary-scan wording to diff-scoped checks only.
