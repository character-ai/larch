### In-Scope Findings

- **correctness** `skills/review/scripts/review-core.sh:421-465` — The new `static_archetype_coverage_ok` gate treats `collector-results.env` as the sole source of successful static peers, but `collect-findings.sh` only writes that file for external outputs via `collect-agent-results.sh` and for Claude outputs that are explicitly `NOT_SUBSTANTIVE`. Substantive Claude phase-2/phase-3 fallback successes (the normal both-down path, and single-vendor rescue when `--no-fallback` is omitted) never get an `STATUS=OK` record. After this branch, a round where all four archetypes are covered only by `cursor-specialist-*-output-phase3.txt` (or similar) still passes aggregate threshold math (`FAILED_SLOTS=0`) but fails the coverage gate with `no successful static reviewer for archetype(s): security,correctness,edge-cases,testing`, producing a false `panel-failed` stall on an otherwise healthy panel. **Suggested fix:** When computing coverage (and ideally threshold), union slug successes from substantive Claude fallback outputs—e.g. pass `claude_array` into `static_archetype_coverage_ok` and treat non-empty, non-`NOT_SUBSTANTIVE` `cursor-specialist-*` / `codex-specialist-*` basenames (after phase/retry normalization) as successful peers—or teach `collect-findings.sh` to append `STATUS=OK` collector rows for substantive Claude static reviewers the same way external collection does.

- **correctness** `skills/review/scripts/check-reviewer-failure-threshold.sh:71-138` — The plan called for counting phase-2/phase-3 static failures in threshold math, but the script still only inspects `collector-results.env`. Because `collect-findings.sh:268-311` never records substantive Claude fallback outputs, phase-3 rescues that succeed are invisible (under-counted successes), while phase-3 failures that never hit `record_claude_non_substantive` can be invisible too (under-counted failures). That leaves threshold and coverage using different evidence sets and lets `THRESHOLD_OK=true` coexist with a coverage failure on the same rescue-only round. **Suggested fix:** Either extend `collect-findings.sh` to emit collector records for all final static reviewer outputs (external and Claude, all phases), or have `check-reviewer-failure-threshold.sh` accept the dispatched output file list and classify static `*-phase2`/`*-phase3`/`*-retry` basenames directly, matching the coverage gate’s slug normalization.

- **correctness** `skills/review/scripts/check-reviewer-failure-threshold.sh:135-137` — Never-launched padding is suppressed whenever `DROPPED_STATIC_SLOTS > 0`, not when dropped rows already account for the `INTENDED_SLOTS - LAUNCHED_SLOTS` gap (as the plan specified). If a future caller passes `LAUNCHED_SLOTS < INTENDED_SLOTS` together with a partial dropped-slots file, unaccounted never-launched slots would not be added to `FAILED_SLOTS`, letting a partially dispatched panel slip under the >50% gate. **Suggested fix:** Replace the coarse `DROPPED_STATIC_SLOTS == 0` guard with explicit gap math, e.g. only skip padding for `min(DROPPED_STATIC_SLOTS, NEVER_LAUNCHED)` or pad `NEVER_LAUNCHED - DROPPED_STATIC_SLOTS` when positive.
