**F4 — Latent | Correctness**
**`check-reviewer-failure-threshold.sh:135` — never-launched padding suppressed by any drop, even an unrelated one**

```bash
NEVER_LAUNCHED=$(( INTENDED_SLOTS - LAUNCHED_SLOTS ))   # line 133
(( NEVER_LAUNCHED < 0 )) && NEVER_LAUNCHED=0            # line 134
if (( DROPPED_STATIC_SLOTS == 0 )); then                # line 135
    FAILED_SLOTS=$(( FAILED_SLOTS + NEVER_LAUNCHED ))
fi
```

The condition on line 135 suppresses all never-launched padding the moment `DROPPED_STATIC_SLOTS > 0`, regardless of whether the dropped slot is the same archetype as the never-launched one. If a caller ever passes `LAUNCHED_SLOTS < INTENDED_SLOTS` while also having an unrelated dropped slot, genuine never-launched failures escape the threshold.

In the primary call from `review-core.sh` this is a no-op: both `--intended-slots` and `--launched-slots` are set to `$static_slot_count`, so `NEVER_LAUNCHED` is always 0. But the logic is wrong as a standalone invariant, and a future caller or test that passes differing values (e.g., a manifest-emit failure that leaves `LAUNCHED < INTENDED`) would silently under-count failures. The correct condition should subtract what is already covered: `FAILED_SLOTS += max(0, NEVER_LAUNCHED - DROPPED_STATIC_SLOTS)`.

**F5 — Nit | Structure / performance**
**`collect_dropped_static_outputs` in `review-core.sh` re-reads `manifest_file` in full for every dropped slot**

The function uses a nested while loop: the outer loop iterates dropped slots, and the inner loop re-reads `manifest_file` from the start to find the matching manifest row. For a panel with D dropped slots and M manifest rows this is O(D×M) reads, plus 2 `jq` invocations per manifest row examined. For typical panels (D ≤ 4, M ≤ 24) this is harmless, but the pattern would slow visibly if the manifest grows (e.g., high dynamic-archetype counts). A single `jq` pass matching all dropped slots at once, or a grep of the manifest for the slot name before the inner loop, would be O(M) total.
