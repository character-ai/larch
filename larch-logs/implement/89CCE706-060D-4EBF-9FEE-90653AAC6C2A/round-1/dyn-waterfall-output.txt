### In-Scope Findings

- **risk-integration** `skills/review/scripts/review-core.sh:421-466` — `static_archetype_coverage_ok` only treats `STATUS=OK|cap_hit` rows in `collector-results.env` as successful static peers, but that file is populated exclusively for **external** outputs via `collect-agent-results.sh` in `collect-findings.sh` (lines 268–311); successful Claude phase-3 fallbacks land in `CLAUDE_OUTPUT_FILES` and are parsed for findings without ever writing `STATUS=OK` into `collector-results.env`. On the both-vendors-down path (four Cursor-primary rows that always fall through to Claude phase 3, per `dispatch-panel.sh:120-123` and `dispatch-with-waterfall.sh:470-476`), and on single-vendor paths where externals fail through to Claude, a round that actually produced findings will still fail the coverage gate with `no successful static reviewer for archetype(s): security,correctness,edge-cases,testing`, yielding `REVIEW_CORE_STATUS=panel-failed` even though the panel behaved as designed. **Suggested fix:** Teach the coverage gate to credit archetypes from successful Claude fallback outputs too — e.g. join `CLAUDE_OUTPUT_FILES` / manifest rows against the four static slugs (using the same basename normalization already in `normalize_reviewer_output_base`), or have `collect-findings.sh` append `STATUS=OK` collector records for substantive Claude static-fallback outputs before threshold/coverage run.

- **risk-integration** `skills/review/scripts/check-reviewer-failure-threshold.sh:71-147` — The plan called for counting phase-2/phase-3 static specialist failures so a relaxed `STATIC_DISPATCH_OK` path cannot report a partially failed Claude-fallback panel as clean; the shipped threshold script still only inspects `collector-results.env` plus optional dropped-slot TSV rows. That works for external phase-1/phase-2 finals collected by `collect-agent-results.sh`, but Claude phase-3 finals are outside that file, so their failures are invisible to `FAILED_SLOTS` unless they happen to be recorded as `NOT_SUBSTANTIVE` (the only Claude path that writes to `collector-results.env`). A both-down or single-vendor run can therefore pass the >50% gate with `FAILED_SLOTS=0` while several archetypes actually failed at phase 3, as long as `wait-for-reviewers.sh` succeeds. **Suggested fix:** Either fold Claude static-fallback outputs into the same collector-results stream with explicit `STATUS=` values before threshold, or extend `check-reviewer-failure-threshold.sh` to accept `--claude-output-files` / manifest context and count failed phase-3 static basenames the same way external failures are counted.

- **risk-integration** `skills/review/scripts/test-review-core.sh:254-259` — The `check-threshold.sh` stub hardcodes `INTENDED_SLOTS=12` and never asserts forwarded argv (`--intended-slots`, `--launched-slots`, `--dropped-slots-file`), so the new wiring from `review-core.sh:595-605` and the real threshold math at 4 vs 8 slots are not exercised in the main review-core harness; the collect stub also always fabricates four `codex-specialist-*` `STATUS=OK` rows (lines 113–124), which masks the Claude-fallback coverage bug above. **Suggested fix:** Replace the threshold stub with argv-logging that asserts `$STATIC_SLOT_COUNT`-derived denominators and dropped-file forwarding, add a both-down fixture where `CLAUDE_OUTPUT_FILES` holds `cursor-specialist-*-output-phase3.txt` paths and `collector-results.env` is empty/minimal, and assert the round succeeds (or fails only when peers truly fail).

- **risk-integration** `skills/review/scripts/test-dispatch-panel.sh` — Acceptance criteria require stub-log proof that global `--no-fallback` is present for both-vendor manifests and omitted for single-vendor and both-down cases (mirroring `skills/design/scripts/test-dispatch-plan-review-panel.sh`); the harness checks `STATIC_SLOT_COUNT=8`, Codex static breadcrumbs, and both-down phase-3 counts but never greps waterfall argv for `--no-fallback` or `DROPPED_SLOTS_FILE` forwarding. **Suggested fix:** Log waterfall argv in the stub (as design’s harness does) and add explicit greps: `--no-fallback` when both vendors are true, absent when only one vendor is available or both are false, plus a dropped-peer case that asserts `DROPPED_SLOTS_FILE` is re-emitted on dispatch-panel stdout.
