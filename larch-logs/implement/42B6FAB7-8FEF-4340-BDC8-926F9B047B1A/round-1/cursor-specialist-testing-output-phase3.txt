2. - **risk-integration** `skills/design/scripts/test-plan-review-loop.sh:316-338` — The three-reviewer regression test asserts OOS heading uniqueness in both `findings.md` and `ballot.txt` (lines 316–321), and FINDING heading monotonic-increase only in `findings.md` (lines 322–338). The plan acceptance criteria explicitly requires "`ballot.txt` exists, non-empty, with the same heading-uniqueness guarantees" for FINDING headings too. A future regression where the aggregator or disabled-aggregator path re-introduces duplicate FINDING blocks in `ballot.txt` would not be caught. **Suggested fix:** Extend the `ballot.txt` check to also assert (via the same Python monotonicity snippet or a simpler `grep -cF`/uniqueness loop) that each `### FINDING_N:` heading appears exactly once in `ballot.txt`.

3. - **code-quality** `scripts/test-implement-structure.sh:398-399` — `|| true` is appended to both `comm` invocations: `comm -23 … || true` and `comm -13 … || true`. With `set -euo pipefail` in effect, if a process substitution feeding `comm` silently produces empty output due to a parser regression or pipe error, `|| true` suppresses the failure and leaves `diff_ship_not_skill`/`diff_skill_not_ship` as empty strings — the drift guard then reports "no differences" and exits clean instead of surfacing the extraction failure. **Suggested fix:** Remove the `|| true` guards from the `comm` lines; `comm` exits 0 on success with sorted input, so they're redundant. Let process-substitution failures propagate to the test's `set -e` trap.
