### In-Scope Findings

- **risk-integration** `skills/design/SKILL.md:146` — The Step 0-pre invoke uses unquoted `<PUBLIC_ARGV_WORDS>` in `parse-design-argv.sh <PUBLIC_ARGV_WORDS>`. If the skill loader leaves that token unexpanded, Bash treats it as stdin redirection from a file named `PUBLIC_ARGV_WORDS`, not as script arguments. `parse-design-argv.sh` only reads `"$@"` and never stdin, so the parser runs with empty argv, exits **0**, and emits `POSITIONAL_KIND=none` with all flags false. That can silently drop a real invocation like `/design --hard 3249` into the “no positional” path instead of failing loudly. `CLAUDE_PLUGIN_ROOT` has an explicit unexpanded-literal guard (lines 135–137); argv has no symmetric runtime check—only prose in `parse-design-argv.md:9`. **Suggested fix:** Avoid `<…>` shell-redirection syntax for argv entirely—e.g. end the fence with `"$@"` and have the orchestrator run the block with public argv as trailing parameters (`bash … -- --hard 3249`), or substitute quoted tokens before Bash and add a pre-invoke guard that aborts if the rendered command still matches `<PUBLIC_*>` / has zero args when `$ARGUMENTS` was non-empty. Mirror the `CLAUDE_PLUGIN_ROOT` “unexpanded template literal” pattern for whatever substitution mechanism you keep.

- **risk-integration** `scripts/test-design-structure.sh:266-272` — The structural pin `grep -Fq '<PUBLIC_ARGV_WORDS>'` requires the placeholder to **remain** in the committed `SKILL.md` template. It does not prove loader substitution at runtime, nor does it require a fence-side expansion guard (unlike the pins for `unexpanded template literal` and `parse-design-argv.sh not executable`, which only cover `CLAUDE_PLUGIN_ROOT`). A regression where the orchestrator copies the template line verbatim into the Bash tool would still pass `make test-design-structure`. **Suggested fix:** Add a pin for an argv expansion guard in the `step0pre_block` (e.g. forbid a bare `<PUBLIC_ARGV_WORDS>` token on the invoke line in rendered fences, or require a documented post-substitution sentinel), and/or add a small harness that renders a sample fence and asserts the invoke line contains quoted argv tokens and no `<PUBLIC_ARGV_WORDS>` redirection.

- **risk-integration** `skills/design/SKILL.md:146-194` — When redirection fails because `PUBLIC_ARGV_WORDS` is missing, Bash typically fails the substitution with a non-zero RC and a “No such file or directory” message; the fence maps any non-3 failure to a generic `parse-design-argv.sh failed (exit …)` string without mentioning template substitution. When an empty `PUBLIC_ARGV_WORDS` file exists, the parser still succeeds with `POSITIONAL_KIND=none`, which is easy to confuse with an intentional bare `/design`. **Suggested fix:** After capture, if `_argv_rc` is non-zero and stderr/stdout mentions `PUBLIC_ARGV_WORDS`, print an explicit “skill loader did not expand `<PUBLIC_ARGV_WORDS>`” diagnostic; optionally treat `POSITIONAL_KIND=none` plus non-empty user `$ARGUMENTS` as a hard abort in orchestrator prose (even if the script correctly classifies empty argv).
