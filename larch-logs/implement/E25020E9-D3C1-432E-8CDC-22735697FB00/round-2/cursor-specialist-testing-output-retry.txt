### In-Scope Findings

- **risk-integration** `agent-lint.toml:889-1278` — The plan explicitly calls for updating `agent-lint` allowlists for the new harness, but `skills/design/scripts/test-design-pause-resume.sh` and its sibling `.md` are absent from the `exclude` list while peer harnesses like `test-design-driver.sh` are listed. `scripts/named-block-write.sh` is only reachable via Bash-to-Bash `exec`/caller edges (not a direct `SKILL.md` path), the same pattern that requires explicit exclusion for helpers like `scripts/larch-log-flush.sh`. **`make lint` / agent-lint can fail with G004 dead-script false positives on merge.** **Suggested fix:** Add `scripts/named-block-write.sh`, `scripts/named-block-write.md`, `skills/design/scripts/test-design-pause-resume.sh`, and `skills/design/scripts/test-design-pause-resume.md` to `agent-lint.toml` `exclude`, mirroring adjacent design harness entries and documenting the Bash-caller reachability rationale.

- **risk-integration** `scripts/test-design-log-publish.sh:283-736` — Acceptance criteria and the plan both require a `--reason pause` fixture that verifies **force-with-lease push reuses an existing remote branch** (FINDING_11). The new pause tests cover commit subject, `manifest.paused`, `.completed/` staging, no-op snapshot reuse, and recovery-branch soft-fail, but none assert that republish to an existing `larch-log-design-<RUN_ID>` remote issues `git push --force-with-lease` (or equivalent observable push behavior). **Scenario:** pause-save on the second cycle of the same `RUN_ID` could regress to `branch -D` / push-fail behavior without CI catching it. **Suggested fix:** Extend `test-design-log-publish.sh` with a git stub or push-arg log capture that seeds a remote branch, runs a second `--reason pause` publish, and asserts `--force-with-lease` (and successful reuse) on the push invocation.

- **risk-integration** `scripts/test-design-structure.sh:928-939` — `assert_bash_fences_have_pause_check` only requires the line after each env-source to match `/design-pause-save\.sh/`, not the full two-line prelude with the `.pause-requested` sentinel guard specified in the plan and Anti-pattern #7. **Scenario:** a future edit could replace the guard with unconditional `exec design-pause-save.sh` (or drop the sentinel check while keeping the script name on the next line) and CI would still pass, changing pause semantics for in-flight `/design` runs. **Suggested fix:** Tighten the awk assertion to require both `.pause-requested` and `design-pause-save.sh` on the immediately following line, matching the canonical prelude in `skills/design/SKILL.md:72-73`.

- **risk-integration** `skills/design/scripts/test-design-pause-resume.sh:157-164` — Plan test case **(m)** requires that with `.completed/{step-1c, step-2a}` present, save selects `STEP=1d` (registry-order walk skipping completed steps). The harness instead tests `step-1c` + `step-1d` complete → `STEP=1d.5`, which validates adjacent progression but not non-contiguous sentinel gaps. **Scenario:** a bug in registry-order walking that only handles consecutive completed prefixes could slip through while adjacent-step cases pass. **Suggested fix:** Add a fixture with `: > "$DESIGN_TMPDIR/.completed/step-1c"` and `: > "$DESIGN_TMPDIR/.completed/step-2a"` (and no intervening sentinels) and assert `STEP=1d` on save stdout.

- **risk-integration** `scripts/test-design-log-publish.sh:209-279` — `design-log-publish.sh` now stages `$DESIGN_TMPDIR/.completed/` whenever the directory exists, regardless of `--reason` (see `scripts/design-log-publish.sh:431-475`), but the existing happy-path fixture has no `.completed/` tree and no assertion about final-publish behavior with sentinels present. Real `/design` runs will accumulate `.completed/step-*` sentinels before the Step 5c final publish. **Scenario:** final flush commits could silently grow to include progress sentinels (or staging bugs could break final publish) without regression signal. **Suggested fix:** Add a `--reason final` (default) fixture with a populated `.completed/` directory and assert either expected staging (if intentional) or explicit absence (if final publish should omit them), documenting the chosen contract.

- **risk-integration** `skills/design/scripts/test-design-pause-resume.sh:1-280` — Several documented failure contracts have no harness coverage: `ERROR=marker-write-failed` (publish OK, gh edit fails), `ERROR=snapshot-not-found` (missing remote snapshot), and `ERROR=tmpdir-unset` on save. The harness covers many plan cases (a–l, partial m/n) plus valuable extras (issue/repo binding, delete-fail rollback, redaction), but these operator-retry paths from the plan's failure-mode section are untested. **Suggested fix:** Add stubbed cases: force `GH_EDIT_FAIL=1` after successful publish stub → `PAUSE_OK=false` + `ERROR=marker-write-failed`; empty/missing snapshot archive → `LOAD_OK=false` + `ERROR=snapshot-not-found`; invoke save without `--design-tmpdir` → `ERROR=tmpdir-unset`.
