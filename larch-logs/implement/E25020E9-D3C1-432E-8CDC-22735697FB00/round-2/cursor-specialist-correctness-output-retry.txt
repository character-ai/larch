### In-Scope Findings

- **correctness** `scripts/design-pause-load.sh:197-210` — **Plan-correctness (both):** After staging and artifact checks, the loader deletes the `larch:design-pause` marker and only then runs `cp -R` into `$DESIGN_TMPDIR`. The plan requires asserting restored artifacts **before** deleting the marker and treats marker removal as the atomic commit point of a successful resume. **Concrete scenario:** `named-block-write.sh --delete` succeeds, but `cp` fails (disk full, permissions, or path error). The issue body no longer has a pause marker (`LOAD_OK=false`, `ERROR=restore-install-failed`), while the fresh Step 0a tmpdir stays empty. The operator must recover manually from `larch-logs/design/<RUN_ID>/` on the remote branch. **Suggested fix:** Copy staged files into `$DESIGN_TMPDIR` first (or use a rename into place), re-assert required root files there, delete the marker only after install succeeds, then emit `LOAD_OK=true`.

- **correctness** `skills/design/SKILL.md:206-207` — **Plan-correctness (both):** On `LOAD_OK=true`, Step 0b sub-step 2.5-bis skips sub-steps 2.5 through 6, including the title-eligibility filter (2.5) and the `[DESIGNING]` rename (5.5). FINDING_1 only covers paused **`[DESIGNING]`** issues; it does not cover pause during Step 0b before 5.5 or issues that still carry `[IMPLEMENTING]` (or another lifecycle prefix). **Concrete scenario:** Issue title is `[IMPLEMENTING] feature`, operator pauses during Step 0b (via `/larch:pause`, which does not use the Step 1c+ prelude) before sub-step 5.5 runs, then resumes. Resume bypasses `title_has_lifecycle_reject_prefix` and never runs the 5.5 rename, so `/design` continues on an `[IMPLEMENTING]` issue and may never get a `[DESIGNING]` title. **Suggested fix:** On successful load, always run 2.5 (or at least lifecycle-reject) before skipping; and/or run a best-effort 5.5 rename when the title is not already `[DESIGNING]` (using restored `run-params.json`), even when other 0b sub-steps are skipped.

- **correctness** `skills/design/SKILL.md:206` — **Completeness w.r.t. plan (both):** The plan states that on resume, “all of those state mutations are already persisted in the restored tmpdir,” listing `[DESIGNING]` rename among them. The rename is a GitHub issue mutation, not a tmpdir artifact, and the resume path explicitly skips sub-step 5.5. **Concrete scenario:** Pause after Step 0b sub-step 4 (tier gate) but before 5.5; snapshot has `run-params.json` but the issue title is unchanged. Resume at `STEP=1c` never executes 5.5, so tracking/title state diverges from a normal fresh run. **Suggested fix:** Align SKILL.md and load behavior: either persist rename completion in `pause-state.txt` and run 5.5 on resume when absent, or narrow the plan claim to tmpdir-only state and document title handling.

- **correctness** `scripts/design-pause-save.sh:192-199` — **Plan-correctness (plan):** After `named-block-write.sh`, save only checks the subprocess exit code, not `WRITTEN=true` / `FAILED=` on stdout (unlike other larch `gh` helpers). **Concrete scenario:** A future regression returns exit 0 with `FAILED=true` and no body update; save emits `PAUSE_OK=true` while the issue has no marker, so the next `/design` starts fresh despite an published snapshot. **Suggested fix:** Parse stdout for `WRITTEN=true` (and treat `FAILED=true` as `ERROR=marker-write-failed`) before emitting `PAUSE_OK=true`.

- **correctness** `skills/pause/SKILL.md:45-46` — **Latent / plan (both):** `/larch:pause` still creates `.pause-requested` immediately before the synchronous `design-pause-save.sh` call. The plan de-emphasized flag-then-defer for FINDING_17 because save runs directly. **Concrete scenario:** Save fails after publish but before marker write (`PAUSE_OK=false`); `.pause-requested` remains. The operator continues the same `/design` turn; the next Step 1c+ prelude `exec`s save again, causing a second `--reason pause` publish while the operator already saw a failed `/larch:pause`. **Suggested fix:** Remove the sentinel write from `/larch:pause` on the synchronous path, or clear `.pause-requested` on any save failure.
