### In-Scope Findings

1. **Important** **correctness** `skills/pause/SKILL.md:45-56` — `/larch:pause` still creates `.pause-requested` before calling `design-pause-save.sh`, but the plan (FINDING_17) requires the skill to invoke the save helper **synchronously and directly** with no flag-then-defer primary path; the sentinel is only for the defensive Bash-prelude between `/design` boundaries. If the process is killed after `: > .pause-requested` but before save finishes, the orphaned-flag failure mode the plan removed can return; a successful save also leaves a redundant flag until save removes it. **Suggested fix:** Remove lines 45–46 from `skills/pause/SKILL.md` so the skill only runs `design-pause-save.sh` (with optional `--repo`); keep `.pause-requested` creation only in the `/design` prelude path for mid-run deferral.

2. **Important** **correctness** `scripts/design-pause-load.sh:197-210` — The plan requires asserting restored root artifacts **before deleting** the pause marker so a failed restore leaves the marker for retry. The loader deletes the marker via `named-block-write.sh --delete` and only then `cp`s into `$DESIGN_TMPDIR`; if `cp` fails (`ERROR=restore-install-failed`), the issue body no longer has `larch:design-pause` but the fresh tmpdir is still empty, so the next `/design` starts fresh with no automatic resume pointer despite a durable log snapshot. **Suggested fix:** Copy staged artifacts into `$DESIGN_TMPDIR` first, re-assert `plan.txt` / `run-params.json` / `pause-state.txt` at the tmpdir root, then delete the marker; align `scripts/design-pause-load.md` if the contract text should match the plan ordering.

3. **Important** **correctness** `skills/design/scripts/test-design-pause-resume.sh` (plan test case **(m)**) — The plan requires that with `.completed/step-1c` and `.completed/step-2a` present (and intermediate steps absent), save picks `STEP=1d` by registry file order, not lexicographic order. The harness only checks `step-1c` alone → `STEP=1d` and `step-1c`+`step-1d` → `STEP=1d.5`; it never creates `step-2a` without `1d`/`1e`/… and asserts `STEP=1d`. A regression that skips registry rows between completed sentinels would not fail CI. **Suggested fix:** Add a dedicated case: touch only `step-1c` and `step-2a`, run save, assert stdout contains `STEP=1d`.

4. **Latent** **risk-integration** `skills/design/SKILL.md:73,342-1138` — Plan FINDING_4 threads optional `--repo OWNER/REPO` through pause save/load from Step 0b’s `resolve-repo.sh`, and save persists `REPO=` in the marker for fail-closed load. Every Bash-prelude `exec design-pause-save.sh` line passes only `--issue "$ISSUE_NUMBER"` (no `${REPO:+--repo "$REPO"}`), while `/larch:pause` does pass `--repo` when resolved. A defensive prelude save on a hub issue in a non-default repo can write markers with one `REPO` binding while the prelude save uses `gh`’s default repo, causing `repo-mismatch` or wrong publish targets on resume. **Suggested fix:** Export `REPO` into session env after Step 0b resolution (or re-resolve in the prelude) and append `${REPO:+--repo "$REPO"}` to every prelude `design-pause-save.sh` invocation.

5. **Nit** **correctness** `docs/issue-anchored-plan.md:77-87` — Acceptance requires documenting the full KV payload schema, but the LIVE catalog example omits `ISSUE_NUMBER=` and `REPO=` even though `design-pause-save.sh` writes them and `design-pause-load.sh` fail-closes on mismatch (`scripts/design-pause-save.sh:131-134`, `design-pause-load.sh:121-131`). Operators reading only the wire-format doc will not know those binding fields are required for safe resume. **Suggested fix:** Add `ISSUE_NUMBER=` and optional `REPO=` to the documented marker block in `docs/issue-anchored-plan.md`.
