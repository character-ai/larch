### In-Scope Findings

1. **Important** (`risk-integration`, `plan`) — [`scripts/compose-review-findings.sh:127-145`](scripts/compose-review-findings.sh)  
   `code-review-rejected` now only recognizes `### [rejected] …`; the previous `### [Code Review] …` pattern is gone. For any round where `rejected-findings-full.md` is absent but legacy `rejected-findings.md` still uses `[Code Review]` headings, those lines hit the generic `###` branch (`flush_pending` + `continue`) and never populate `pending_body`, so rejected sections are dropped and `FINDINGS_TOTAL` / downstream consumers that depend on composed output can silently skew on older logs or partial flushes. Suggested fix: accept both header shapes (two regex branches or alternation) until migration is complete, and add a regression fixture for “full missing + legacy md”.

2. **Latent** (`risk-integration`, `plan`) — [`scripts/test-hook-anti-read-poll.sh:1-67`](scripts/test-hook-anti-read-poll.sh)  
   The plan’s edge list calls out a 30-second window, but the harness never advances time or injects `first_ts`, so behavior when `age > 30` (counter reset vs continued warnings) and repeated warnings after the threshold are unverified. Suggested fix: add a small helper hook point (e.g. optional `LARCH_READ_POLL_NOW` override for tests) or fixture-driven `state_file` to assert “no fire after window” and “fires again only after streak rebuilds”.

3. **Latent** (`risk-integration`, `plan`) — [`scripts/test-hook-anti-read-poll.sh:50-62`](scripts/test-hook-anti-read-poll.sh)  
   The “different path” case only checks two reads of `other.md` then one read of `different.md`; it does not exercise interleaved reads (e.g. `A,A,B,A,A,A`) to prove the counter fully resets per path after alternation, which is the usual failure mode for streak bugs. Suggested fix: extend the harness with an explicit interleave sequence.

4. **Nit** (`risk-integration`) — [`skills/implement/scripts/write-rejected-findings.sh:62-63`](skills/implement/scripts/write-rejected-findings.sh)  
   The quiet-line still reports `details=rejected-findings.md` even when the durable log copy came from `rejected-findings-full.md`, which can mislead anyone correlating transcript keys with log files. Suggested fix: mention “full artifact when present” or drop the hard-coded filename.
