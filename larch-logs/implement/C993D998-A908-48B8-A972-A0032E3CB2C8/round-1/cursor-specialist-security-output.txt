1. **Latent**, **risk-integration**, [`skills/implement/scripts/write-rejected-findings.sh:52-59`](skills/implement/scripts/write-rejected-findings.sh) — The new path prefers a verbatim `cp` of `rejected-findings-full.md` into durable run logs. That is a **larger sensitive-data footprint** than the previous bare ledger copy and **does not go through** the same `redact_field` / `redact-secrets` pipeline used when composing review output in [`scripts/compose-review-findings.sh:65-71`](scripts/compose-review-findings.sh). **Scenario:** a rejected finding quotes or pastes a token, credential, or customer data from the repo; it is written to `larch-logs/implement/<RUN_ID>/rejected-findings.md` and may be committed or copied off-machine. **Suggested fix:** run the full file through the existing redaction helpers (or reuse a single “sanitize for logs” primitive) before `cp`, or explicitly document that this artifact may contain unredacted secrets and must be treated as confidential / excluded from public mirrors.

2. **Latent**, **security**, [`scripts/hook-anti-read-poll.sh:28-48`](scripts/hook-anti-read-poll.sh) — State is stored as a TSV under `${TMPDIR:-/tmp}/larch-read-poll/` including the **full `file_path`**. Default umask often yields **world-readable** files in `/tmp`, so on a **shared local machine** another account could read `state-*.tsv` and infer which paths the agent is reading. **Suggested fix:** `chmod 600` the state file after write and/or use a user-private directory (for example under `$HOME/.cache/larch/...` or `$XDG_RUNTIME_DIR` when set).
