### In-Scope Findings

1. **Latent** (`correctness`, `plan`+`requirements`) — [`skills/implement/scripts/write-rejected-findings.sh:62-74`](skills/implement/scripts/write-rejected-findings.sh) — `count_rejected_findings` falls through to `printf '1\n'` when the chosen detail file is non-empty but matches neither the `### [(rejected|Code Review)]` header regex nor the ledger-line regex. **Concrete scenario:** `rejected-findings-full.md` contains only narrative text or an unexpected header shape (no `###` blocks, no `N:FINDING_*_OUTCOME=rejected` lines); the script still exits `STATUS=ok` with `REJECTED_COUNT=1`, misreporting cardinality to anything consuming the quiet stream. **Suggested fix:** Treat “no match” as `0` unless you can prove the file is a single synthetic block, or add a last-resort heuristic aligned with `emit-tally.sh` output.

2. **Nit** (`correctness`, `plan`) — [`skills/implement/scripts/write-rejected-findings.sh:43-77`](skills/implement/scripts/write-rejected-findings.sh) and [`skills/implement/scripts/write-rejected-findings.md:12-17`](skills/implement/scripts/write-rejected-findings.md) — The implementation plan explicitly said the count heuristic should still use `rejected-findings.md` while the log copy prefers `rejected-findings-full.md`; shipped code and doc instead derive `REJECTED_COUNT` from the same preferred `detail_file`. **Concrete scenario:** If bare ledger and full markdown ever disagree in count (partial write, tooling mismatch), transcript `REJECTED_COUNT` will follow the full artifact, not the bare ledger the plan called out. **Suggested fix:** Either restore bare-sourced counting to match the approved plan or record an explicit plan amendment (the current tests encode the unified behavior).

3. **Latent** (`risk-integration`, `requirements`) — [`scripts/hook-anti-read-poll.sh:13-17`](scripts/hook-anti-read-poll.sh) — The hook only inspects `tool_input.file_path`. If the host Claude Code payload uses a different key for the Read target (or nests paths differently), `file_path` is empty and the hook exits silently. **Concrete scenario:** Host upgrades change JSON shape; repeated identical reads never emit the anti-poll reminder while tests still pass (harness uses `file_path`). **Suggested fix:** Mirror other hooks’ defensive field fallbacks (e.g. try alternate documented keys) or add a contract test against a captured real hook payload.

4. **Latent** (`correctness`, `requirements`) — [`scripts/hook-anti-read-poll.sh:19-20`](scripts/hook-anti-read-poll.sh) and [`scripts/hook-anti-read-poll.sh:47-48`](scripts/hook-anti-read-poll.sh) — `offset` is kept as a string and compared to `last_offset` from the state file without numeric normalization. **Concrete scenario:** One invocation supplies offset `10` and a later one `010` for the same read; the hook treats them as different keys, resets the streak, and never fires on the third logical identical read. **Suggested fix:** Normalize both sides with a single arithmetic coercion (e.g. `10#` expansion or `awk`) before compare.

5. **Latent** (`correctness`, `requirements`) — [`scripts/hook-anti-read-poll.sh:40-61`](scripts/hook-anti-read-poll.sh) — State is read/modified/written without locking. **Concrete scenario:** Two `Read` PostToolUse hook processes for the same `cwd` overlap; interleaved writes to `state-*.tsv` can corrupt `last_path`/`count`/`first_ts` fields so the counter resets or jumps unpredictably. **Suggested fix:** Accept as rare and document, or use atomic write-rename or `flock` around the state update while preserving exit-0 non-blocking semantics.
