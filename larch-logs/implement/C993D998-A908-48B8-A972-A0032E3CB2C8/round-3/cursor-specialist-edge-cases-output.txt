### In-Scope Findings

1. **Important** (`risk-integration`) — [skills/implement/scripts/write-rejected-findings.sh](skills/implement/scripts/write-rejected-findings.sh):104-108 — On failure to copy redacted findings into `LOG_ROOT/implement/<RUN_ID>/rejected-findings.md`, the script sets `REJECTED_COUNT` to `0` together with `STATUS=failed`. A caller that treats `REJECTED_COUNT` as authoritative can conclude there were no rejections when the tmpdir actually contained findings, only persistence failed. Suggested fix: keep emitting the computed count (or add a separate `PERSIST_OK=false` / `COPY_FAILED=true` flag) while retaining `STATUS=failed` and the error string.

2. **Latent** (`correctness`) — [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):47-64 — `age` is computed as `$((now - first_ts))` with no guard for negative values. If the clock steps backward or `first_ts` in the state file is ahead of `now`, `age` is negative; `[ "$age" -le "$WINDOW_SECS" ]` stays true, so the “third read in window” branch can fire when the real elapsed wall time is not 30 seconds, and the `age -gt "$WINDOW_SECS"` reset path may never run until clocks realign. Suggested fix: treat `age < 0` like an expired window (reset streak) or ignore corrupted `first_ts`.

3. **Nit** (`correctness`) — [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):19-20 — Any `tool_input.offset` string that is not purely digits is coerced to `0`, so two distinct logical offsets that normalize to the same bucket could share one poll counter. Suggested fix: document as intentional or parse integers with `jq` more strictly if the tool ever emits non-decimal offsets.

4. **Latent** (`correctness`) — [skills/implement/scripts/write-rejected-findings.sh](skills/implement/scripts/write-rejected-findings.sh):62-74 — `count_rejected_findings` falls through to `printf '1\n'` when the file is non-empty but matches none of the heuristics, forcing a count of `1` and an `ok` status. A malformed or future-format artifact would be reported as exactly one rejection. Suggested fix: return `0` or a dedicated `unknown`/`STATUS` path instead of defaulting to `1`.

5. **Latent** (`risk-integration`) — [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh):127-132 — Rejected code-review blocks now bind `pending_reviewer` from the tally line (often a `FINDING_*` id). Downstream consumers of `review-findings-full.md` that assumed the second field was always a human reviewer name (as in legacy `### [Code Review] Name`) may mis-classify or mis-display rows. Suggested fix: document the emitted field semantics or split “display name” vs “finding id” in the template.
