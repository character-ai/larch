### In-Scope Findings

1. **Important** (`correctness`) — [Implementation plan](feature_description) Item P step 1: the plan requires the rejection **count heuristic to keep using** the bare [`skills/implement/scripts/write-rejected-findings.sh`](skills/implement/scripts/write-rejected-findings.sh) `rejected-findings.md` while the **log copy** prefers `rejected-findings-full.md` when non-empty. The branch implements `count="$(count_rejected_findings "$detail_file")"` so `REJECTED_COUNT` is derived from the same `detail_file` chosen for persistence (full when present), which contradicts that explicit split and can disagree with the summary ledger whenever the two artifacts diverge. Either compute the count from `summary_file`/`rejected-findings.md` per the plan, or treat the plan as superseded and keep today’s behavior (already reflected in [`skills/implement/scripts/write-rejected-findings.md`](skills/implement/scripts/write-rejected-findings.md) and [`CHANGELOG.md`](CHANGELOG.md) 29.3.12).

2. **Latent** (`risk-integration`) — [`skills/implement/scripts/write-rejected-findings.sh`](skills/implement/scripts/write-rejected-findings.sh) (persist block in diff): on `persist_detail_copy` failure the script emits `REJECTED_COUNT=0` with `STATUS=failed` before `exit 1`, which can mislead any consumer that keys only on `REJECTED_COUNT` even though rejections exist; the supplied plan did not specify this fail-closed envelope (prior behavior was a silent `cp … || true`). Prefer emitting the computed count with `STATUS=failed`, or document the contract if zeroing is intentional.

3. **Nit** (`architecture`) — Item Q state path: the plan text names a flat `${TMPDIR:-/tmp}/larch-read-poll-${CWD_HASH}.tsv`, while [`scripts/hook-anti-read-poll.sh`](scripts/hook-anti-read-poll.sh) uses `${TMPDIR:-/tmp}/larch-read-poll/state-${cwd_hash}.tsv` after `mkdir -p`/`chmod 700` on the directory. Behavior matches the intent (per-project isolation, mode-600 file) but is not path-faithful to the plan wording.
