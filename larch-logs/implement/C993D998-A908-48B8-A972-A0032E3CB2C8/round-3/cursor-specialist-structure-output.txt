### In-Scope Findings

1. **Nit** · `code-quality` · [scripts/compose-review-findings.md](scripts/compose-review-findings.md):5-8 — The contract still says code-review rejections are read from `$IMPLEMENT_TMPDIR/round-*/rejected-findings.md` (and parent `rejected-findings.md`), but [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh):163-176 prefers `rejected-findings-full.md` when it exists and is non-empty. Someone wiring artifacts from the doc alone can omit the full file and get different composition than the script. Extend the input bullets to state `rejected-findings-full.md` first, then the bare `.md` fallback (same for the parent tmpdir fallback).

2. **Latent** · `code-quality` (plan) · [skills/implement/scripts/write-rejected-findings.sh](skills/implement/scripts/write-rejected-findings.sh):43-51 — The implementation plan called for preferring `rejected-findings-full.md` when `--run-id` and `--log-root` are set; the script always sets `detail_file` from the full artifact whenever it is non-empty, so `REJECTED_COUNT` / `details=` also follow the full file even when no run log is written. That is likely desirable but is a broader semantic change than the plan text. Either gate `detail_file` on log args or document global preference explicitly (and align with [skills/implement/scripts/write-rejected-findings.md](skills/implement/scripts/write-rejected-findings.md):12-17).

3. **Latent** · `correctness` · [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):63-68 — `age=$(( now - first_ts ))` is not clamped; if `first_ts` is ever greater than `now` (clock skew, manual `HOOK_ANTI_READ_POLL_NOW` in tests, restored state), `age` is negative and `[ "$age" -le "$WINDOW_SECS" ]` stays true, so the third read can still emit a reminder even though real wall time between first and third read exceeded 30 seconds. Clamp to non-negative age or reset the streak when `now < first_ts`.

4. **Nit** · `code-quality` · [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):13-20 — The hook runs `jq` five times on the same JSON blob. A single `jq` extracting all needed fields would match common hook style and reduce fork overhead on every Read.

5. **Nit** · `risk-integration` · [scripts/test-hook-anti-read-poll.sh](scripts/test-hook-anti-read-poll.sh):76-84 — The “different path resets counter” case switches `cwd` to `/proj2`, which uses a different state file than the `/proj` streak above, so it does not prove same-`cwd_hash` state isolation for path changes (the production case). Prefer one fixed `cwd` and vary only `file_path` to match the hook’s real layout.
