### In-Scope Findings

1. **Latent** (`risk-integration`) — [`.agnix.toml:41`](.agnix.toml): `AS-014` is added to global `disabled_rules`, so **agnix no longer evaluates that rule anywhere in the tree**, not only for the GitHub URL regex in `github-remote-repo.sh`. **Concrete scenario:** a future edit in another script or skill that would have tripped `AS-014` for a pattern the rule is meant to catch (for example, a problematic `[[ =~ ]]` or path-like construct the rule models) can pass `make agent-lint` / strict agnix until caught by human review or other tooling. **Suggested fix:** after the `github[.]com` regex rewrites in [`scripts/github-remote-repo.sh:25-33`](scripts/github-remote-repo.sh), try removing `AS-014` from `disabled_rules`; keep the global disable only if agnix still reports a false positive with no narrower suppression option.

2. **Latent** (`security`) — [`scripts/hook-anti-read-poll.sh:60-61`](scripts/hook-anti-read-poll.sh): `file_path` from hook JSON is written as a TSV field with `printf '%s\t…\n'` and later parsed with `IFS=$'\t' read -r last_path …`. A path string containing a **literal TAB or newline** breaks the one-line TSV contract and desynchronizes `read`, so `last_path` / counters can be wrong and the anti-poll signal becomes unreliable. **Suggested fix:** reject or strip control characters in `file_path` before persistence, or store state as JSON via `jq` (no ambiguous delimiters).

3. **Nit** (`correctness`) — [`scripts/hook-anti-read-poll.sh:41-44`](scripts/hook-anti-read-poll.sh): `count` and `first_ts` from the state file are validated as all-digits, but **`last_offset` is not** normalized the same way as fresh `offset` (lines 19–20). **Concrete scenario:** a stale state line with `last_offset` `01` vs a new read with offset `1` fails the string equality check, resetting the streak and suppressing the reminder. **Suggested fix:** apply the same digit-only normalization to `last_offset` after `read`.

**Positive security notes (not findings):** [`scripts/github-remote-repo.sh:35-36`](scripts/github-remote-repo.sh) redacts userinfo in unparsed URLs before printing; the read-poll hook’s [`scripts/hook-anti-read-poll.sh:65-67`](scripts/hook-anti-read-poll.sh) reminder does not echo `file_path` (aligned with [`SECURITY.md`](SECURITY.md)); [`scripts/compose-review-findings.sh:68-71`](scripts/compose-review-findings.sh) and [`skills/implement/scripts/write-rejected-findings.sh:85-88`](skills/implement/scripts/write-rejected-findings.sh) keep redaction + escaping on persisted composed / log content.
