### In-Scope Findings

1. **Latent** `correctness` (source: **plan** for Q — deterministic harness; code: [`scripts/test-hook-anti-read-poll.sh`](scripts/test-hook-anti-read-poll.sh))  
   The suites at `scripts/test-hook-anti-read-poll.sh:31-48` and `scripts/test-hook-anti-read-poll.sh:50-63` invoke the hook with real wall-clock time (`mk_payload … | "$HOOK"`) and never pin `HOOK_ANTI_READ_POLL_NOW`, unlike the expired-window block at `scripts/test-hook-anti-read-poll.sh:79-93`.  
   **Concrete scenario:** CI or a loaded host pauses the process for more than 30 seconds between the first and third identical Read simulation; the hook resets the streak (`scripts/hook-anti-read-poll.sh:47-57`), so the third call returns no `additionalContext` and the harness fails intermittently.  
   **Suggested fix:** drive those cases through `run_hook` (or export a monotonic `HOOK_ANTI_READ_POLL_NOW` sequence with gaps ≤30 between the first three calls).

2. **Latent** `correctness` (source: **plan** — inner-heading guard for P; code: [`scripts/compose-review-findings.sh`](scripts/compose-review-findings.sh))  
   The new guard only folds lines matching `^###[[:space:]]+(FINDING_|OOS_)` into `pending_body` (`scripts/compose-review-findings.sh:135-139`). Any other markdown subsection inside a `### [rejected] …` block (e.g. `### Notes` or `### Evidence`) still falls through to the generic `###` handler (`scripts/compose-review-findings.sh:142-145`), which calls `flush_pending` and `continue`, so that heading line is dropped from the composed body.  
   **Concrete scenario:** a future or hand-edited `rejected-findings-full.md` includes a non-`FINDING_` / non-`OOS_` `###` line between the `[rejected]` header and the vote tally; the composed `review-findings-full` loses that subsection while splitting records early.  
   **Suggested fix:** broaden the in-body exception (e.g. treat any `###` that is not a new `[rejected]` / legacy `[Code Review]` opener as body while `pending_id` is set), or document that only `FINDING_`/`OOS_` subheadings are supported.

3. **Nit** `risk-integration` (source: **plan**; code + doc: [`scripts/hook-anti-read-poll.sh`](scripts/hook-anti-read-poll.sh), [`scripts/hook-anti-read-poll.md`](scripts/hook-anti-read-poll.md))
