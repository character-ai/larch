### In-Scope Findings

1. **Important** · `risk-integration` · [CHANGELOG.md](CHANGELOG.md):14-20 vs [.claude-plugin/plugin.json](.claude-plugin/plugin.json) — The shipped plugin version is **29.3.12**, but `CHANGELOG.md` has no **29.3.12** section and instead documents **29.3.11** for the AS-014 / GitHub-regex work. Anyone comparing the release tag to the changelog will see a missing version and a mismatched section title. **Suggested fix:** Rename or split the changelog section so the highest released version in `plugin.json` has a matching `## [29.3.12]` entry (or document why 29.3.11 is an unpublished intermediate).

2. **Latent** · `correctness` · [skills/implement/scripts/write-rejected-findings.sh](skills/implement/scripts/write-rejected-findings.sh):65-71 — The log write path runs `redact-tmpdir-paths` and `redact-secrets` with `> …/rejected-findings.md 2>/dev/null || true`. If either helper exits non-zero or the pipeline breaks mid-flight, the destination can end up empty or stale while the script still reports `STATUS=ok` and `details=rejected-findings-full.md`, so operators lose rejected detail without an error signal. **Suggested fix:** Detect empty/non-writable output (e.g. `wc -c` check or pipefail with controlled fallback to `cp`) and surface `STATUS=failed` or skip the silent `|| true` on the write path.

3. **Latent** · `architecture` · [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):170-199 — State is a single TSV file per `cwd` hash with read-modify-write on every Read. Two concurrent Read completions could interleave writes and corrupt `count`/`first_ts`, weakening or falsely triggering the warning under parallel tool use. **Suggested fix:** Document as best-effort only, or use atomic rename (`write temp; mv`) / flock if stronger guarantees are required.

4. **Latent** · `code-quality` · [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):193-198 — Once `count >= 3` inside the window, **every** additional identical Read emits another `additionalContext` payload until the window expires, which can spam the session during intentional tight loops. **Suggested fix:** Emit only on the transition to threshold (e.g. fire when `count == 3` only) or throttle repeats.

5. **Nit** · `code-quality` · [scripts/hook-anti-read-poll.sh](scripts/hook-anti-read-poll.sh):143-149 — The hook runs `jq` three times over the same stdin buffer via `printf '%s' "$INPUT" | jq …`. **Suggested fix:** Single `jq` invocation producing all needed fields to reduce fork/exec overhead on hot path.

6. **Nit** · `code-quality` · [scripts/test-hook-anti-read-poll.sh](scripts/test-hook-anti-read-poll.sh):96-104 — The “different path resets counter” scenario uses a **fresh** `cwd` (`/proj2`), which only proves isolation between projects, not path switching within the same `cwd` state file as the implementation plan described. **Suggested fix:** Add one case that keeps `cwd` fixed, does two reads on path A, switches to path B, then a third read on A and asserts no fire (or expected reset), matching the plan’s intent.
