### In-Scope Findings

1. **Important** (`risk-integration`, `plan`) — [`skills/implement/scripts/write-rejected-findings.sh`](skills/implement/scripts/write-rejected-findings.sh) (diff hunk ~2595–2627): When `rejected-findings-full.md` is non-empty, the run log is copied from `detail_file` (full), but `REJECTED_COUNT` is still computed from `summary_file` (`rejected-findings.md`) whenever that file is non-empty. A stale or placeholder bare ledger (e.g. grep lines or a single filler line) can disagree with the number of `### [rejected] …` blocks copied into `larch-logs/.../rejected-findings.md`, so orchestrators or batch tooling that compare `REJECTED_COUNT` to the saved file can mis-rank the run. The plan called out preferring the full file for the log copy but did not require tests for count alignment when both files exist; the new `full_dir` case in [`skills/implement/scripts/test-write-rejected-findings.sh`](skills/implement/scripts/test-write-rejected-findings.sh) never asserts `REJECTED_COUNT`. **Suggested fix:** Either derive the count from the same `detail_file` whenever it is selected for copy, or add a regression test (and doc) that locks the intended contract when both files are present.

2. **Latent** (`risk-integration`, `plan`) — [`scripts/test-hook-anti-read-poll.sh`](scripts/test-hook-anti-read-poll.sh) (diff ~2362–2374): The opening “first two calls do not fire / third fires” block drives three hook invocations with real wall-clock time and no `HOOK_ANTI_READ_POLL_POLL_NOW` override. The hook resets the streak when `(now - first_ts) > 30` ([`scripts/hook-anti-read-poll.sh`](scripts/hook-anti-read-poll.sh) diff ~2177–2181). On a heavily loaded CI host, gaps between subprocess spawns could exceed 30s, so the third call might stay silent and the harness would flake. **Suggested fix:** Use fixed `HOOK_ANTI_READ_POLL_NOW` values (e.g. 1, 2, 3) for those three calls, consistent with the “expired window” section in the same file.
