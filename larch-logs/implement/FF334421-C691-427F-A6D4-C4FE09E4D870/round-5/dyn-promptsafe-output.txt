Examining security-sensitive changes in state writes, scope anchoring, and prompt rendering.
### In-Scope Findings

- **security** `skills/design/scripts/render-plan-review-prompt.sh:115-173` — Plan-review reviewers inline the staged scope anchor (`--feature-file` → `$DESIGN_TMPDIR/plan-review-scope-anchor.txt`) with redaction and HTML entity escaping, but unlike the voter path there is no byte cap before inlining. A collaborator-controlled GitHub issue body (after `larch:plan` stripping) can be arbitrarily large and is materialized without size limits in `plan-review-loop.sh`, then copied into up to ten parallel external reviewer prompts. That enables context stuffing / run-cost amplification and increases residual prompt-injection surface even with escaping. **Suggested fix:** Apply the same hard bound used in `render-voter-prompt.sh` (`validate_scope_anchor_file`, 64 KiB fail-closed) to `--feature-file` in `render-plan-review-prompt.sh`, and optionally enforce the same limit when writing `plan-review-scope-anchor.txt` in `plan-review-loop.sh` so oversize anchors fail before dispatch.

- **security** `skills/design/scripts/render-main-agent-scope-anchor.sh:31-51` — Main-agent plan-review voting uses the same scope-anchor inlining pattern (redact + escape, untrusted framing) but also omits a size limit, while voters are capped at 64 KiB in `skills/shared/scripts/render-voter-prompt.sh:40-45`. A large issue body therefore hits the inline MainAgent fallback path with unbounded untrusted content. **Suggested fix:** Reuse the shared 64 KiB validation helper (or duplicate the exact `wc -c` / fail-closed check) before streaming the anchor block.

- **security** `python/ship.py:647-656,724-725` — The new merge-before-overwrite logic in `_write_ship_state` reads an existing `--state-file` before writing, but only refuses symlink destinations on write (`path.is_symlink()` at line 724). If `ship-pr-state.sh` is replaced with a symlink between orchestrator seeding and a Python refresh, `path.is_file()` + `read_text()` will follow the symlink and ingest arbitrary same-UID file contents into the merge map; validated keys can then be written back into the real state file on the next successful write. **Suggested fix:** Fail closed before read when `Path(ctx.state_file).is_symlink()` (or open with `O_NOFOLLOW`) and mirror the write-side symlink rejection in `SECURITY.md`.
