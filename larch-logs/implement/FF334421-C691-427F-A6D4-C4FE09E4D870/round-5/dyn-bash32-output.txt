### In-Scope Findings

- **correctness** `skills/implement/scripts/stall-recovery-report.sh:418-427` — `validate_optional_state_evidence_file` treats an oversize `ship-pr-state.sh` (>64KiB) as a hard `exit 3`, but only on the evidence-gathering path (`cmd_classify` lines 654–656). The earlier KV-read path for the same file (lines 609–617) has no size cap, so classification can partially succeed and then abort when no valid `--failure-detail-log` is present. That is asymmetric with the documented failure-detail contract (“invalid logs are ignored; classification continues from remaining evidence” in `stall-recovery-report.md`) and is a regression from the prior `[ -r "$state_file" ] && cat` behavior. **Suggested fix:** On oversize/non-regular optional evidence files, return 1 and skip that layer (same as missing file), reserving `exit 3` for `ship-pr-state.sh` symlink/syntax-invalid cases already handled at lines 605–612; or apply the 64KiB cap consistently on both KV-read and evidence paths.

- **correctness** `skills/implement/scripts/stall-recovery-report.sh:620-627` — The same helper hard-aborts `classify` with `exit 3` when `finalize-state.sh` or `session-env.sh` is oversize or symlinked, instead of skipping that layer. On the Python-default path, stall metadata often lives only in `finalize-state.sh`; a file slightly over 64KiB (or a symlink misconfiguration) now kills Step 18a classification entirely rather than falling back to other layers. The sibling contract still documents exit 3 only for `ship-pr-state.sh` problems (`stall-recovery-report.md:123`). **Suggested fix:** For `finalize-state.sh` / `session-env.sh`, treat validation failures like missing evidence (`return 1`); only emit `exit 3` for the dedicated `ship-pr-state.sh` guards already at lines 605–612.
