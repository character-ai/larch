Reviewing branch shell changes for Bash 3.2 compatibility, quoting, and parsing robustness.
### In-Scope Findings

- **code-quality** `scripts/test-implement-structure.sh:125-151` — The new awk-scoped pins for the Python selector and bash exit-matrix gate only grep for a few literal substrings inside extracted windows; they do not pin the Step 18 `_restore_finalize` conditional gate added in `skills/implement/SKILL.md:1352-1380` (`LARCH_SHIP_PR_IMPL:-python`, missing-finalize restore, or terminal-override detection), even though acceptance and `scripts/test-implement-structure.md:43-44` call that out. A regression that deletes or rewrites the restore gate while leaving the selector prose intact would still pass `make lint`. **Suggested fix:** Add awk- or grep-scoped assertions in the Step 18 bash-fence region for `_restore_finalize`, `[ "${LARCH_SHIP_PR_IMPL:-python}" = "bash" ]`, and at least one terminal-override predicate (`STALL_TRACKING=true`, `BAIL_NEEDS_USER_INPUT=true`, or differing `STALL_STEP`).

- **code-quality** `skills/implement/scripts/test-stall-recovery-report.sh:214-242` — The new finalize-only classify fixtures (`case_finalize_fallback`, `case8finalize`) assert `FAILURE_CLASS`, `STALL_TRACKING`, and `STALL_STEP`, but neither asserts `RESUME_HINT` is non-`none` (the harness contract in `skills/implement/scripts/test-stall-recovery-report.md:6890` explicitly requires that). A classify regression that reads finalize stall keys but maps `STALL_STEP=8` to `RESUME_HINT=none` would slip through. **Suggested fix:** Add `assert_eq step8-shippr "$(kv RESUME_HINT "$SANDBOX/case_finalize_fallback.out")"` (and the same for `case8finalize`) alongside the existing class/step assertions.

- **code-quality** `skills/implement/SKILL.md:1366-1371` — The new Step 18 restore gate compares `STALL_TRACKING` and `BAIL_NEEDS_USER_INPUT` with literal `= "true"` only, while Step 18a / `stall-recovery-report.sh` treat a wider truthy set (`1`, `TRUE`, `yes`, `on`, etc.). If any writer emits a non-lowercase truthy value, restore could be skipped and `implement-finalize.sh teardown` may run against a stale `finalize-state.sh`. **Suggested fix:** Reuse the same truthy predicate as `stall-recovery-report.sh` (small shared helper or duplicated `case` arm) before setting `_restore_finalize=true`.

- **code-quality** `scripts/test-implement-structure.sh:144-151` — The bash-matrix awk window ends at the first `Parse the process exit code and then read` line (`skills/implement/SKILL.md:1093`), so the pin verifies only the gate sentence plus that preamble, not that the Exit 0/3/4/6 bullets below stay bash-scoped. That is acceptable for Bash 3.2, but it is a weak boundary pin: editing the preamble without touching the gate still passes. **Suggested fix:** Extend the awk end anchor to a stable token inside the first matrix bullet (for example the Exit 0 heading) or add a separate `grep -Fq` that the Exit 0 bullet retains an explicit bash-only qualifier for `ship-pr.sh --resume-phase pr-create`.
