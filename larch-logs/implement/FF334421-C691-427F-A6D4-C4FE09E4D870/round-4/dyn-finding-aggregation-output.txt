### In-Scope Findings

- **correctness** `skills/design/scripts/plan-review-loop.sh:1322-1345` — Plan-review dedup merges `[SCOPE-REDUCTION]` tagged findings with untagged findings when Jaccard similarity exceeds 0.6, keeping the tagged body and only unioning reviewers. That runs before `aggregate-findings.sh` withholds tagged blocks, so a scope-cut finding can absorb a separate in-scope finding on the same topic and drop its distinct concern text from the ballot. **Suggested fix:** Never merge across the tagged/untagged boundary in `dedup()` (only dedupe within tagged or within untagged pools), or split scope-reduction blocks out before dedup and append them after dedup/aggregation, matching the aggregate withhold contract.

- **correctness** `skills/design/scripts/plan-review-loop.sh:1271-1286` and `skills/review/scripts/aggregate-findings.sh:774-788` — `check-scope-reduction-marker.sh` accepts plain `- Concern:` and `what:` markers, but dedup `problem_text()` / `comparison_text()` and aggregate parity `problem_text()` only parse bold `- **Concern**:` / `- **Description**:` lines. Plain-Concern and what-only scope findings are tagged for withholding but their marker text is omitted from Jaccard/parity comparisons, which breaks the end-to-end path (the harness expects `AGGREGATED=false` for plain Concern and preserves the raw file via fail-open rollback rather than withhold→merge→append). **Suggested fix:** Share one normalization helper with the marker script (heading, bold/plain Concern, Description, and `what:`) and use it in dedup, aggregate split, and parity checks.

- **correctness** `skills/review/scripts/aggregate-findings.sh:791-795` — Parity matching in plan-mode aggregation reads reviewers only from bold `- **Reviewer(s)**:` / `- **Reviewers**:` lines, while the validator accepts additional reviewer-line shapes. Scope-reduction findings with non-bold reviewer attribution can fail parity (exit 1) even when the LLM merge and tagged append are correct, rolling back a good aggregation. **Suggested fix:** Reuse the validator’s `reviewer_line_slots()` patterns (or call into the same Python module) for parity reviewer overlap instead of the narrower inline regex.

- **correctness** `skills/review/scripts/aggregate-findings.sh:183-187` — When the plan-mode scope-marker split helper exits non-zero, the script emits `REASON=validation-failed` and exits 0 without calling `append_warning()`, unlike dispatch/merge failure paths. Operators may see `AGGREGATED=false` with no execution-issues breadcrumb while findings stay unaggregated. **Suggested fix:** On split helper failure, append a warning to the execution-issues log (same pattern as other aggregator failures) before `emit_result`.
