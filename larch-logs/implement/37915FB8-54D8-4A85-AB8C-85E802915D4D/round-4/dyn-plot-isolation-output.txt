### In-Scope Findings

- **architecture** `python/test_plot_cost_over_time.py:14-23` — The optional real-subprocess smoke test exercises `plot-cost-over-time.py` directly without setting `MPLCONFIGDIR`, even though `plot-cost-over-time.md:24-26` and `python/report_tokens_plot.py:63-68` define that variable as part of the isolation contract, and the plan called for validating persistent PNG lifetime after the child returns. When matplotlib is present, CI/dev runs therefore bypass the documented config-dir isolation and never assert that returned paths still exist on disk after subprocess exit; only the fake-Runner unit test in `python/test_report_tokens_plot.py:57-61` checks file presence. **Suggested fix:** Drive the smoke test through the same spawn shape as production (or at minimum set `MPLCONFIGDIR` under a temp output root), parse the JSON path list, and assert each PNG still exists after the child exits; keep the matplotlib-missing skip on exit code 3.

- **architecture** `python/test_report_tokens_plot.py:57-78`, `python/test_plot_cost_over_time.py:14-49`, `skills/report-tokens/scripts/plot-cost-over-time.md:7-19` — Producer and consumer sides of the plot JSON contract are tested with separate inline payloads rather than a shared committed fixture, despite the plan’s D1 mitigation (“shared fixture tests on both sides”) and the explicit drift risk called out in the plan’s failure modes. `_series()` in `python/report_tokens_plot.py:29-45` and `_validate_series()` in `skills/report-tokens/scripts/plot-cost-over-time.py:38-67` can diverge (field names, series count/order, date formatting, version handling) while both test files still pass. **Suggested fix:** Add one canonical plot-input JSON fixture (for implement and design) under `python/fixtures/` or similar, have `test_report_tokens_plot.py` assert the producer-written file matches it, and have `test_plot_cost_over_time.py` feed the same fixture to the child script.

### Out-of-Scope Observations

- **architecture** `python/report_tokens_plot.py:101` — `LARCH_REPORT_TOKENS_NO_OPEN` uses raw env truthiness (`not os.environ.get(...)`) while `LARCH_REPORT_TOKENS_NO_PLOT` uses `_env_flag_enabled()` at `python/report_tokens_plot.py:57`; values like `0`/`false` behave differently between the two flags. Docs only mention `NO_OPEN=1`, so impact is low.

- Matplotlib isolation itself looks sound on this branch: no `matplotlib` imports under `python/report_tokens_*`, the only import is in `skills/report-tokens/scripts/plot-cost-over-time.py`, spawning goes through `proc.Runner` + `sys.executable`, child failures surface on stderr and degrade to “No plots generated”, returned paths are constrained to the persistent plot temp dir, and `test_stdlib_only.py` still enforces the stdlib-only `python/` runtime surface.
