Reviewing token-pricing correctness in the migration: reading the diff and key pricing modules.
### In-Scope Findings
- **correctness** `python/report_tokens_models.py:96-107` — `safe_int` is narrower than the embedded helper it replaced in the old `run-analysis.sh`, and that helper feeds every token count passed to `scripts/token-cost.sh` via `report_tokens_cost.token_cost_argv` / `aggregate_vendor_tokens` and scan inclusion checks in `report_tokens_scan._has_numeric_tokens`. The new version only accepts digit-only strings and integer-valued floats; it no longer strips commas (`"1,000,000"`) or truncates non-integer floats (`1000.9` → `0` instead of `1000`). Those values can drive `_bucket_total` to zero, flip a vendor from per-bucket to blended argv, or skip a run as having no numeric tokens, so headline costs can diverge from what the bash path produced on the same JSON. **Suggested fix:** Port the legacy `safe_int` behavior (comma stripping, `int(float(s))` for strings, guarded float truncation) into `report_tokens_models.safe_int`, and add tests for comma-formatted strings and fractional floats in `python/test_report_tokens_models.py` plus a cost-argv regression in `python/test_report_tokens_cost.py`.

- **correctness** `python/report_tokens_render.py:172-181` — The cost-reduction suggestions block always states that `` `scripts/token-cost.sh` remains the pricing authority used for headline totals ``, but `_summary` already admits runs priced via Python blended fallback (`priced_by_token_cost=False`) and `_top_runs` labels those rows `(fallback)` while still folding their dollars into “Tracked total estimated cost.” When `token-cost.sh` is missing, fails, or returns incomplete KV output, the headline total is partly or wholly from `_fallback_cost` in `report_tokens_cost.py`, so the suggestions line overstates shell authority and can mislead cost triage. **Suggested fix:** Make the suggestions text conditional on whether any priced record has `priced_by_token_cost=False` (e.g., say shell is authoritative when used, and note that fallback blended rates filled gaps), or move the authority disclaimer next to the existing fallback warning in `_summary` and drop the unconditional claim here.

### Out-of-Scope Observations
- Per-vendor mixed bucket vs blended argv (new) vs the old all-three-`BUCKETS_*`-dicts gate (main) is an intentional plan change and aligns with `token-cost.sh`’s independent `CLAUDE_BUCKET` / `CODEX_BUCKET` / `CURSOR_BUCKET` flags; it can change totals vs historical reports when only some vendors have buckets, but that is not a shell-contract bug.
- Plot/trend date axes still use `closed_at` for graphs and `started_at` for per-day tables; the plan documents that mismatch as a preserved quirk.
- For `--skill=design`, runs with `workflow=unknown` still appear in aggregate/vendor headline tables but are excluded from SIMPLE/HARD trend/plot groupings via `_workflow_groups`; that affects grouping, not per-run pricing math.
