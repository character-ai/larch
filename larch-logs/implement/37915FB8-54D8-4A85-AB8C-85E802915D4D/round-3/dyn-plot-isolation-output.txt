Reviewing plot-isolation architecture: reading the diff and key plot-related files.
### In-Scope Findings

- **architecture** `skills/report-tokens/scripts/plot-cost-over-time.py:37-84` — The normative contract in `skills/report-tokens/scripts/plot-cost-over-time.md` requires `version`, per-skill series shape (implement: exactly one `All runs` series; design: `SIMPLE` and `HARD`), and typed `points`, but the child only checks that `series` is a list. Non-dict series entries and series with non-list `points` are skipped with `continue`, and extra/mislabeled series still produce PNGs with exit code 0. Parent/child contract drift therefore fails silently instead of surfacing a schema error on stderr. **Suggested fix:** Add explicit validation after `_load()` (require `version == 1`, validate `skill`, enforce series count and labels per skill, reject empty `written` when input was non-empty) and return exit code 2 with a clear stderr message; mirror the rules in `python/test_plot_cost_over_time.py` and add a parent-side test that reads the `plot-input.json` `report_tokens_plot.py` writes for both skills.

- **architecture** `skills/report-tokens/scripts/plot-cost-over-time.py:41-84` — The input document includes a `version` field for forward-compatible schema evolution, but the renderer never reads it, so a bumped `version` with a changed shape would still be accepted and partially rendered. That undermines the isolation boundary’s documented evolution story and keeps regression risk on the parent writer alone. **Suggested fix:** Fail closed on unknown `version` values (accept only `1` for now) and document that policy in `plot-cost-over-time.md`; when bumping the schema, teach the child to accept both versions or reject old callers explicitly.

- **risk-integration** `python/report_tokens_plot.py:69` — The matplotlib child is spawned through `runner.run(...)` with no `timeout`, while other subprocess-heavy `python/` paths use bounded waits via `config`. A hung or pathological matplotlib run can block the entire `/report-tokens` CLI with no recovery path. **Suggested fix:** Pass a dedicated plot timeout (for example reusing `SUBPROCESS_DEFAULT_TIMEOUT_SEC` or a smaller report-tokens-specific constant) into `runner.run`, treat timeout like other non-zero exits (stderr skip line, return `[]`), and add a fake-`Runner` or harness test that asserts timeout handling.

- **architecture** `python/test_report_tokens_plot.py:57-71` — Tests exercise the runner seam and `MPLCONFIGDIR`, but they never assert the subprocess argv contract (`sys.executable`, script path, input/output dirs) or the JSON payload `_series()` emits (implement vs design series labels/count). The optional smoke in `python/test_plot_cost_over_time.py` only covers a minimal implement fixture and does not assert returned PNG paths still exist after the child exits, which the plan called out as part of persistent output lifetime. **Suggested fix:** Extend `test_plot_contract_and_mplconfig` (or add sibling tests) to inspect `runner.calls[0]` and the written `plot-input.json` under `plot_dir`; extend the optional smoke to `assert Path(p).is_file()` for each path in the JSON list after `subprocess.run` completes.

### Out-of-Scope Observations

- Plot date axis uses `closed_at` while per-day tables use `started_at`; that mismatch is called out in the plan as a preserved, pre-existing quirk rather than something this branch introduced.
- `python/report_tokens_plot.py:101-103` invokes `open` via the runner without checking the result; that is a minor operational gap but not central to matplotlib subprocess isolation.
