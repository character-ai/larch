Reviewing the pricing pipeline: reading the diff and key cost/render modules.
### In-Scope Findings

- **correctness** `python/report_tokens_scan.py:124-131`, `python/report_tokens_cost.py:35-43,64-87` — Scan admission and pricing use different definitions of “has bucket data.” `_has_numeric_tokens` accepts a run when *any* value in `BUCKETS_*` is positive, but `token_cost_argv` only treats a vendor as bucket-priced when `_bucket_total` over schema-specific keys is positive. A report can pass scan with something like `BUCKETS_claude: {"total": 5_000_000}` while `claude.totals.total` stays 0 and named bucket keys are empty; pricing then takes the blended branch with `--claude-tokens 0`, so headline totals can be effectively zero with no skip warning. That breaks the plan’s “never silently zero-cost” rule for malformed-but-nonempty bucket objects. **Suggested fix:** Align validation with pricing: require either a positive `_bucket_total` for at least one vendor or a positive `VendorTotals.total`, and skip with the existing stderr warning when only non-schema bucket keys have counts.

- **correctness** `python/report_tokens_cost.py:45-56` — For Claude’s blended fallback (`--claude-tokens`), `_aggregate_tokens` sums `input`, `cache_read`, `cache_create_5m`, `cache_create_1h`, and `output` but not `VendorTotals.cache_create`. If `claude.totals` has material `cache_create` with `cache_create_5m`/`cache_create_1h` still zero (possible in token-report totals before split fields are fully populated), `component_total > 0` makes the function return a partial sum instead of `totals.total`, underfeeding `token-cost.sh` relative to the committed report. **Suggested fix:** Include `totals.cache_create` in the Claude component sum (and mirror the same key set in `_bucket_total` if undivided `cache_create` can appear in `BUCKETS_claude`), or when components don’t reconcile with `totals.total`, prefer `totals.total` for blended argv the way `scripts/render-run-summary.sh` does via aggregate token variables.

### Out-of-Scope Observations

- Per-vendor mixed bucket/blended argv in `report_tokens_cost.py` matches the plan and is an improvement over the removed bash “all three `BUCKETS_*` dicts or blended for everyone” gate; headline tables and plots correctly use `RunRecord.*_cost` / `total_cost` from `token-cost.sh` KV output, not display-rate math in `report_tokens_render.py`.
- `_cost_env()` forwarding of `LARCH_RATE_*` / legacy aliases into the `token-cost.sh` child environment matches the documented contract; fallback paths warn on stderr when `token-cost.sh` is missing, fails, or returns incomplete KV lines.
- Pre-existing semantic quirks called out in the plan remain: plot series use `closed_at` while per-day tables use `started_at`, and design-mode summary totals can include `unknown`-workflow runs that SIMPLE/HARD trend tables and plots omit.
