Reviewing the token-pricing path: reading the diff and key modules.
### In-Scope Findings

- **correctness** `python/report_tokens_cost.py:41-63` — Per-vendor bucket mode is chosen with `if bucket:` (any non-empty `BUCKETS_<vendor>` object), but `scripts/token-cost.sh` only prices from the lane flags (`--codex-input-tokens`, `--codex-cached-input-tokens`, `--codex-output-tokens`, etc.); it never reads `BUCKETS_* .total`. Committed design reports often have `BUCKETS_codex` with `total > 0` while `input`, `cached_input`, and `output` are all zero (for example `larch-logs/design/62CB09DA-4657-45BE-B085-2D2E1BED1054/token-report-final.json` lines 88–92, with `codex.totals.total` also 963050). Scan accepts those runs (`report_tokens_scan.py:112-118`), but `token_cost_argv` sends all-zero lane flags, so `token-cost.sh` returns `CODEX_COST=0.00` while still exiting 0; `price_run` marks `priced_by_token_cost=True` and `report_tokens_render.py` uses those KV costs for headline totals, vendor breakdown, and per-day tables. That materially under-reports Codex spend on a common log shape even though pricing technically went through `token-cost.sh`. **Suggested fix:** Gate bucket mode on non-zero pricing lanes (same fields passed to `token-cost.sh`), e.g. a per-vendor helper that sums only `input`/`output`/`cache_read`/`cached_input`/`cache_create_5m`/`cache_create_1h`; if the sum is 0, pass `--{vendor}-tokens` with `VendorTotals.total` instead. Add a `test_report_tokens_cost.py` fixture mirroring the design log shape and assert argv uses `--codex-tokens` with the aggregate total; optionally add a post-pricing sanity check when `totals.total > 0` but parsed vendor cost is 0.
