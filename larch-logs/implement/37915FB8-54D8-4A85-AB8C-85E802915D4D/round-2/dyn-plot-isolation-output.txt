Reviewing plot-isolation architecture: reading the diff and key plot modules.
### In-Scope Findings

- **architecture** `skills/report-tokens/scripts/plot-cost-over-time.py:27-67` — The normative contract in `skills/report-tokens/scripts/plot-cost-over-time.md` requires `version: 1`, exactly one `"All runs"` series for `implement`, and `SIMPLE` + `HARD` for `design`, but the child only checks that `series` is a list and then plots every dict it can parse. Extra series, wrong labels, or a missing `version` all succeed with exit 0, so argv/JSON drift between `python/report_tokens_plot.py` and the matplotlib helper will not fail fast and can produce the wrong number of PNGs without tripping tests that mock the child. **Suggested fix:** Validate `version`, `skill`, and series cardinality/labels in `plot-cost-over-time.py` (non-zero exit + stderr) before plotting; add subprocess tests that feed minimal invalid payloads and expect failure, plus golden `plot-input.json` fixtures for both skills.

- **architecture** `skills/report-tokens/scripts/plot-cost-over-time.py:40-46` — Malformed series entries are skipped with `continue`, and an empty `written` list still exits 0 and prints `[]`. `python/report_tokens_plot.py:75-100` treats that as a successful child run and returns `[]`, and `python/report_tokens_cli.py:90-95` prints the same stdout line `No plots generated.` as the `--no-plot` path, without a stderr reason—so contract violations or partial child bugs degrade to “no plots” rather than a visible plot failure. **Suggested fix:** Treat “zero PNGs after validation” as an error (non-zero exit from the child, or a dedicated stderr line from `plot()` when stdout is `[]` after exit 0); fail closed on any skipped series once schema validation exists.

- **architecture** `python/report_tokens_plot.py:85-100` — After the child returns, the parent only checks that each path exists and stays under `plot_dir`; it never checks skill-specific expectations (one PNG for `implement`, two for `design`). A regressed child that emits a single PNG for `design` still passes path checks and is advertised under `Plots written to:` in `python/report_tokens_cli.py:90-93`, which is easy to miss in review. **Suggested fix:** After parsing the JSON path list, assert `len(paths)` matches the skill (`1` vs `2`) and optionally basename patterns (`all-runs`, `simple`, `hard`); on mismatch, emit the same stderr “plot child failed” pattern and return `[]`.

### Out-of-Scope Observations

- **architecture** `python/test_report_tokens_plot.py` and `python/test_plot_cost_over_time.py` — Unit tests use a fake `Runner` that never executes `plot-cost-over-time.py`; the optional smoke test only covers an `implement` payload and skips entirely when matplotlib is missing (`returncode == 3`). CI can stay green while the real subprocess contract (especially `design` dual-series + `MPLCONFIGDIR`) drifts; this amplifies the validation gap above rather than replacing child-side checks.

- **correctness** `python/report_tokens_plot.py:101` — `LARCH_REPORT_TOKENS_NO_OPEN` is read with `not os.environ.get(...)`, so values like `0` or `false` do not suppress macOS `open`, unlike `LARCH_REPORT_TOKENS_NO_PLOT` which uses `_env_flag_enabled` / CLI merging in `python/report_tokens_cli.py:55`.

- Plot date axis uses `closed_at` in `python/report_tokens_plot.py:37-40` while per-day tables in render use `started_at` (called out in the plan as a preserved quirk, not introduced for isolation).

- Matplotlib isolation itself looks sound: no `matplotlib` import in scanned `python/*.py` (`python/test_stdlib_only.py`), `MPLCONFIGDIR` is set under the persistent `larch-report-tokens-plot.*` directory (`python/report_tokens_plot.py:62-68`), and child output paths are constrained to that directory (`python/report_tokens_plot.py:97-99`).
