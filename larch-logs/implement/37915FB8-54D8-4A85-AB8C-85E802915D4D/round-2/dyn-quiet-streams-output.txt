Reviewing quiet-stream integration in the report-tokens wrapper and related code.
### In-Scope Findings

- **risk-integration** `skills/report-tokens/scripts/test-run-analysis-quiet.sh:27-39` — The new quiet harness only exercises the success path (`--no-issue --no-plot` with a valid fixture tree) and asserts `Scanning ` on stderr plus analysis on stdout. It does not run wrapper failure modes under inherited quiet (`LARCH_QUIET_ACTIVE=1` + foreign `LARCH_QUIET_PID`), such as `--plot-from`, missing/invalid `--skill`, missing `python3`, or a scan that emits repo-resolution errors before `exec`. Acceptance #8 and the plan’s quiet contract depend on `larch_err` reaching the caller’s real stderr before FD restore and on `exec 1>&3 2>&4` before Python; those paths are unguarded in CI and could regress back to “exit 1 with no explanation” without failing the harness. **Suggested fix:** Extend `test-run-analysis-quiet.sh` with at least two extra cases: (1) `--plot-from 1` (or missing `--skill`) and assert the `ERROR:` line lands in the captured stderr file, not only in `larch-quiet-*.log`; (2) a fixture where `gh repo view` fails and issue posting is enabled, asserting the friendly repo-resolution message is on captured stderr while stdout stays contract-shaped or empty.

- **risk-integration** `python/report_tokens_cli.py:109-110` — On issue-post failure, `main()` catches `ShipError` and returns `EXIT_BAIL` without printing `exc`, relying on every `post_issue()` path having already written to stderr. That matches the old silent-failure class this branch is meant to eliminate: any future `ShipError` raised without a preceding `print(..., file=sys.stderr)` (refactor, new helper, or `gh.issue_create` path change) would again yield a bare non-zero exit under quiet orchestration even though the wrapper restored FDs. **Suggested fix:** Mirror the scan path (`except ShipError as exc: print(str(exc), file=sys.stderr); return EXIT_BAIL`) or re-raise after logging so issue-post failures are always fail-loud on stderr.

### Out-of-Scope Observations

On `main`, the monolithic `run-analysis.sh` restored only stdout (`exec 1>&3` at ~line 1169) immediately before `python3`, not stderr; the new wrapper’s `exec 1>&3 2>&4` is a deliberate improvement for Python-phase diagnostics. Repo-resolution fail-soft behavior is covered in `python/test_report_tokens_scan.py` but not end-to-end through the bash wrapper under quiet mode.
