### In-Scope Findings

- **correctness** `python/report_tokens_cost.py:72-73` — For Claude on the blended path (no usable `BUCKETS_claude`, or bucket sum is zero), `token_cost_argv` passes `--claude-tokens` from `VendorTotals.total` only. The removed embedded Python in `run-analysis.sh` instead passed the sum of `input + cache_read + cache_create + output` from `claude.totals`. In `token-report.sh`, `totals.total` is `sumfield(rows; "total")` while the component columns are separate sumfields, so those values can diverge on real reports. Headline Claude dollars from `token-cost.sh` can therefore shift vs the previous `/report-tokens` implementation even when `token-cost.sh` itself is unchanged. **Suggested fix:** For the Claude blended branch only, pass `max(totals.total, input + cache_read + cache_create + cache_create_5m + cache_create_1h + output)` (or restore the legacy component sum exactly and document which field is authoritative), and add a fixture test where `claude.totals.total` ≠ that component sum.
