### In-Scope Findings

- **security** `scripts/test-check-reviewers.sh:254-264` — The new `t6e` case runs a live env-key Codex probe with `OPENAI_API_KEY=<REDACTED-TOKEN>` but does not apply the same post-probe secret-containment checks added for the sibling `t10-env-key-false` fixture at `454-457`. Unlike `t10-env-key-false`, `t6e` has no recursive `grep -Fr '<REDACTED-TOKEN>' "$SCRATCH/t6e"` scan and no `assert_no_probe_homes` call, so a regression that leaves the sentinel in probe sidecars, `larch-codex-probe-home.*` temp configs, or other TMPDIR debris would not fail this harness even though the probe actually ran. **Suggested fix:** Mirror the `t10-env-key-false` tail: after the stamp assertions, add `if grep -Fr '<REDACTED-TOKEN>' "$SCRATCH/t6e" 2>/dev/null; then fail ...; fi` and `assert_no_probe_homes "codex env-key login-decoy cleanup" "$SCRATCH/t6e"`.

- **security** `scripts/test-check-reviewers.sh:591-593` — The legacy env-key strip leak guard only recursively scans the case TMPDIR (`$SCRATCH/t-legacy-strip`), while the sentinel also lives under the isolated HOME fixture at `$SCRATCH/t-legacy-strip-home/.codex/config.toml` and `check-reviewers.sh` copies `~/.codex/config.toml` from that overridden HOME during probe setup. `assert_no_probe_homes` is correctly TMPDIR-scoped because probe homes are created under `${TMPDIR}/larch-codex-probe-home.*`, but a bug that wrote the stripped credential into a *new* file under HOME (outside the fixture path) would not be caught; the test only proves the fixture file is unchanged via `cmp`, not that no other HOME path contains the sentinel. **Suggested fix:** Add a targeted HOME scan that excludes the known fixture, e.g. `find "$SCRATCH/t-legacy-strip-home" -type f ! -path "$_legacy_fixture" -print0 | xargs -0 grep -Fl '<REDACTED-TOKEN>'` and fail on any hit, or recursively grep the parent `$SCRATCH` while excluding the fixture copy path.
