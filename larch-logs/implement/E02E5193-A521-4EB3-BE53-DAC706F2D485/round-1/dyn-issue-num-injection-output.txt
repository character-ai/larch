### In-Scope Findings
- **security** `scripts/ship-pr.sh:951-952` — `issue_num` from `read_state ISSUE_NUMBER` is concatenated into the PR title and later persisted as `PR_TITLE` without checking that it is a plain GitHub issue id (for example digits-only). That does not bypass the quoting chain into `gh`, but a malformed or hand-edited state value yields a misleading `Fixes #…` title and weakens the guarantee that the prefix refers to a real issue the way operators expect. The new test in `scripts/test-ship-pr.sh:132-140` only covers a numeric issue and does not exercise rejection or stripping of invalid values. **Suggested fix:** Before applying the prefix, require a safe pattern (for example `case "$issue_num" in ''|*[!0-9]*) ;; *) title="Fixes #${issue_num}: ${title}";; esac`) or reuse a single small validator shared with other `ISSUE_NUMBER` uses, and optionally add a regression test for a non-numeric value so the prefix is skipped and a warning is logged.
