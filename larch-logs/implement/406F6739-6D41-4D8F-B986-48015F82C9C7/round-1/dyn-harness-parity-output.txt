### In-Scope Findings

- **code-quality** `skills/design/scripts/test-run-step3-review.sh:163-173` — The new regression harness only asserts `LOOP_STATUS` and `REVIEW_ROUND_COUNT` in `.step3-review-result.env`, while `run-step3-review.md:34-36` and the plan’s acceptance criteria call for the full normalized KV set (`TALLY_PLAN_REVIEW_STATUS`, `STEP3_REVIEW_CAP_REACHED`, `ACCEPTED_COUNT`, etc.). A partial write or dropped keys would still pass CI. **Suggested fix:** Add an `assert_file_contains` loop (or one golden-file check) over all documented keys after the `panel-failed` / `complete` cases, mirroring how `test-run-step2-dispatch.sh` documents coverage in its sibling `.md`.

- **code-quality** `skills/design/scripts/test-lib-phase-driver.sh:62-80` — `phase_driver_resolve_plugin_root` is documented as `CLAUDE_PLUGIN_ROOT` → session-env → tree-walk (`lib-phase-driver.md:24`), but the unit harness only exercises session-env and tree-walk fallback. A regression that ignores a set `CLAUDE_PLUGIN_ROOT` would not be caught. **Suggested fix:** Add a case that exports `CLAUDE_PLUGIN_ROOT=/tmp/other` (with a dummy session file pointing at `$REPO_ROOT`) and asserts the env value wins.

- **correctness** `skills/design/scripts/test-run-step3-review.sh:1-181` — No case exercises file-first parsing of `.step3-plan-review-result.env` (stdout vs file precedence, or symlink ignore + stdout fallback), even though that logic moved out of `SKILL.md` into `run-step3-review.sh:208-233` and is only string-pinned in `scripts/test-design-structure.sh:68-69`. **Suggested fix:** Add scenarios that write a real inner `.env`, a symlinked inner `.env`, and a stub loop whose stdout disagrees; assert the driver’s emitted/normalized `LOOP_STATUS` and result env match the contract.

- **correctness** `skills/design/scripts/test-run-step3-review.sh:116-127` — Rollback is only asserted when `TALLY_PLAN_REVIEW_STATUS=tally-error` while `LOOP_STATUS=complete`; `run-step3-review.sh:244-247` also rolls back on `LOOP_STATUS=tally-error` alone. That branch is untested in both new harnesses. **Suggested fix:** Add a stub emitting `LOOP_STATUS=tally-error` with a non-error tally status and assert `review-round-count.txt` reverts to the prior value.

- **code-quality** `skills/design/scripts/test-step3-review-cap.sh:57-91` — `write_snapshot_stub` installs `snapshot-plan-round.sh` under each tmpdir’s `skills/design/scripts/`, but `run_driver` always sets `CLAUDE_PLUGIN_ROOT="$ROOT"` (`test-step3-review-cap.sh:95-96`), so those fixtures are never invoked; HARD cursor coverage depends on the real repo script instead.
