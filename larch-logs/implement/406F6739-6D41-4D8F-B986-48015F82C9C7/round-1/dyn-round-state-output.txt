### In-Scope Findings

- **risk-integration** `skills/design/scripts/run-step3-review.sh:119-122` — On the cap-reached entry path (`_round_count >= _round_cap`), the driver sets `LOOP_STATUS=cap-reached` and skips the entire `else` block, so it never runs the `plan-review/round-*` forensics cleanup that lived in the old second Step 3 fence *before* the cap check. Pre-refactor, stale round directories were always cleared on every Step 3 entry, including cap short-circuits; now they persist across cap-reached re-entries (Gate C / Gate A loops), leaving stale artifacts that downstream steps may treat as current-round evidence. **Suggested fix:** Move the symlink-safe `plan-review/round-*` cleanup above the cap-reached branch (or run it unconditionally before the cap decision), matching pre-refactor ordering; add a harness case in `test-step3-review-cap.sh` that pre-seeds stale `plan-review/round-*` dirs and asserts removal on cap-reached.

- **risk-integration** `skills/design/SKILL.md:849-868` — The orchestrator fence wraps `run-step3-review.sh` in `set +e`, captures `_plan_review_out` and `_plan_review_rc`, but only sources `.step3-review-result.env` and never parses stdout KVs or checks return code. Prose at line 874 promises “driver stdout KVs are fallback only,” yet `_plan_review_out` is dead. If the driver exits non-zero before writing the result env (HARD cursor advance failure at `run-step3-review.sh:171-174`, exit 2 for argv/executable errors, or `phase_driver_write_result_env` refusal on a symlink target), the orchestrator continues with unset `LOOP_STATUS` and may fall through the branch matrix into Gate B or other paths without normalized cap/rollback state. Pre-refactor, cursor advance failure called `exit 1` inside the fence and aborted Step 3. **Suggested fix:** After the driver call, fail closed on `_plan_review_rc -ne 0` (at minimum for exit 1 cursor-abort and exit 2 launcher errors), and add stdout KV parsing as fallback when `.step3-review-result.env` is missing or symlink-refused, mirroring the old inner-loop parse loop.

- **risk-integration** `skills/design/SKILL.md:856-868` — File-based handoff now depends entirely on sourcing `.step3-review-result.env`, but the fence has no fallback when that file is a symlink (it prints a refusal warning and leaves all KVs unset). The driver’s `emit_kv` breadcrumbs on FD 3 are captured into `_plan_review_out` under command substitution and would provide recoverable state, yet the orchestrator ignores them. A symlink on the result env path therefore breaks cap-reached routing, round-count visibility (`REVIEW_ROUND_COUNT`), and Gate B bypass logic even if the driver completed successfully. **Suggested fix:** When sourcing is refused or the file is absent, parse allowlisted keys from `_plan_review_out` before entering the branch matrix; optionally have the driver treat a pre-existing result-env symlink as fatal only after emitting KVs, or unlink-and-write atomically when safe.
