### In-Scope Findings

- **correctness** `skills/design/scripts/run-step3-review.sh:120-122` — On the cap-reached short-circuit (`STEP3_REVIEW_CAP_REACHED=true`), the driver jumps straight to result emission and never runs the `plan-review/round-[0-9]*` cleanup in the `else` branch at lines 124–140. On `main`, the plan-review fence always cleared stale round forensics first, then sourced `.step3-review-cap.env` and skipped the loop when cap was already reached. Gate C / Gate A re-entries at cap can therefore leave prior `plan-review/round-*` directories on disk when they would previously have been removed. **Suggested fix:** Run the same symlink-safe `plan-review/round-*` cleanup before the cap-reached branch (or hoist cleanup above the `if [[ "$STEP3_REVIEW_CAP_REACHED" == true ]]` split) so cap-skipped entries match pre-refactor hygiene; add a harness case under `test-run-step3-review.sh` or `test-step3-review-cap.sh` that seeds `plan-review/round-1/` and asserts removal on cap-reached.

- **correctness** `skills/design/scripts/run-step3-review.sh:257-259` — When `plan-review-loop.sh` exits non-zero with a `LOOP_STATUS` other than `panel-failed` or `main-agent-vote-required`, the driver now **overwrites** `LOOP_STATUS` to `panel-failed` (added in `2a8f4e0ac`). Inline `SKILL.md` on `main` only printed a warning and left the loop-reported status intact, so statuses like `revision-failed`, `emit-plan-failed`, or `plan-size-trigger` paired with an unexpected exit code could follow different Step 3 branch-matrix / Gate B routing after the extract. **Suggested fix:** Either restore warn-only parity with `main`’s fence, or document and test the intentional coercion (and align `run-step3-review.md` + acceptance criteria); if coercion is kept, consider aligning `TALLY_PLAN_REVIEW_STATUS` when forcing `panel-failed`.

### Out-of-Scope Observations

- **Scout focus (two-phase cap guard at 142–150):** Re-sourcing `$CAP_ENV` after the top-of-script write is redundant in this single-process driver; the inner `STEP3_REVIEW_CAP_REACHED=true` block at 147–150 is unreachable when the lines 99–116 write succeeded. With `set -euo pipefail`, a failed `cat >"$CAP_ENV"` aborts before re-source, so this is not a silent partial-write masker in practice—only **code-quality** dead/duplicate logic.

- **`_step3_prior_round_count`:** Initialized to `0` at line 152 and set to `STEP3_REVIEW_ROUND_NUM - 1` only when the round num matches `^[0-9]+$`, matching `main`’s inline fence (`git show main:skills/design/SKILL.md` ~908–910 / 984–988). Rollback at 265–266 updates both `review-round-count.txt` and in-memory `REVIEW_ROUND_COUNT`; parity with pre-refactor behavior. A `:-0` rollback when `STEP3_REVIEW_ROUND_NUM` is corrupt is the same latent edge case as before, not introduced here.

- **`LOOP_STATUS` allow-list vs `plan-review-loop.md`:** The driver regex at line 253 matches the removed `SKILL.md` inline list (includes `optional-trailer-dedup-loss`). `plan-review-loop.md:44` omits `optional-trailer-dedup-loss` even though `plan-review-loop.sh` emits it—pre-existing doc drift; the driver aligns with the loop implementation, not the stale `.md` bullet list.

- **Harness gap:** `test-run-step3-review.sh` asserts file rollback for tally/degraded paths but does not assert `REVIEW_ROUND_COUNT=` in stdout/`.step3-review-result.env` on rollback (file checks are sufficient for the core contract).
