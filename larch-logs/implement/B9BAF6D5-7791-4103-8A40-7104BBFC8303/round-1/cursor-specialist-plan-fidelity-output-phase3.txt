### In-Scope Findings

**FINDING 1 — Nit — Correct deviation from plan print spec**  
`skills/review/scripts/aggregate-findings.sh` (diff line ~4806)

The plan specifies a single combined `print()` call:
```python
print(
    "AGGREGATOR_VALIDATION_FAILED=empty_merge_from_nonempty_input "
    "input had %d FINDING blocks; merged output has zero "
    "(attestation present is not sufficient when inputs were nonempty)"
    % (input_finding_count,),
    file=sys.stderr,
)
```
This would emit `AGGREGATOR_VALIDATION_FAILED=empty_merge_from_nonempty_input input had N FINDING blocks...` as a **single line** with trailing text.

The implementation splits into two `print()` calls — token alone on one line, human explanation on the next.

**Why the split is required**: The plan also specifies the outer waterfall grep as `grep -Eq '^AGGREGATOR_VALIDATION_FAILED=(preamble_finding_substring|empty_merge_from_nonempty_input)$'` — `$`-end-anchored. The combined print would fail this grep (trailing text after the token). The plan contains an internal inconsistency; the implementation resolves it correctly. No change needed.

**FINDING 2 — Nit — Waterfall stub helper differs from plan sketch**  
`skills/review/scripts/test-aggregate-findings.sh` (diff line ~4909, ~5229)

The plan says: *"if the existing test harness does not already have a per-phase stub helper, inline a minimal one... that selects `AGGREGATE_STUB_MERGE_KIND` based on a `STUB_PHASE_COUNTER` env var."*

The implementation instead adds a new `zero_findings_waterfall_ctr` case arm to the dispatch stub's existing `case` block, using a file-based counter at `$LARCH_AGGREGATE_WATERFALL_CTR`. The waterfall test then sets `AGGREGATE_STUB_MERGE_KIND=zero_findings_waterfall_ctr` and `LARCH_AGGREGATE_WATERFALL_CTR="$ZWF/ctr"` directly — no separate helper function.

**Assessment**: Functionally equivalent. The file-counter approach is actually cleaner than the env-var-counter the plan sketched because it avoids state leakage between parallel test sections. The plan explicitly left the helper implementation open ("reuse it" / "keep the helper local"). No change needed.
