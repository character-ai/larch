### In-Scope Findings

1. **Latent** (`risk-integration`) — [`scripts/ship-pr.sh`](scripts/ship-pr.sh):1493-1499 — In the `policy_denied|admin_failed|error` arm, `[ "$rc" -ne 0 ] || record_failure ci-merge "merge-pr.sh envelope" …` runs **before** the new OID branch. When `merge-pr.sh` exits `0` with `MERGE_RESULT=error` (how [`scripts/merge-pr.sh`](scripts/merge-pr.sh) emits OID failures), `record_failure` always runs and appends a tool-failure row via `append-tool-failure.sh`. **Scenario:** A recoverable OID mismatch is fixed by `run_rebase_rebump`, the run finishes with `PHASE=done` and exit `0`, but `execution-issues.md` (or equivalent capture) still shows a merge-pr “envelope” failure for that same attempt, which reads like a hard failure despite success. **Suggested fix:** Skip the envelope `record_failure` when `is_head_divergence_recoverable` will apply (or add a follow-up “superseded by rebase+rebump” note in the same append path).

2. **Latent** (`correctness`) — [`scripts/ship-pr.sh`](scripts/ship-pr.sh):1202-1207 and [`scripts/merge-pr.sh`](scripts/merge-pr.sh):205-208 — `is_head_divergence_recoverable` matches any `ERROR` containing `local HEAD` … `does not match PR head OID`, including merge-pr’s **“after force-push recovery”** string, not only `; refusing to evaluate same-version gate`. **Scenario:** After merge-pr’s flush/force-push path runs, GitHub’s `headRefOid` can still disagree with `git rev-parse HEAD`; merge-pr returns `MERGE_RESULT=error` with the “after force-push recovery” suffix. `ship-pr` will now run `run_rebase_rebump` instead of stalling at `12d`. That may be exactly what you want (extra automation) or may be broader than the narrative in the feature text (“same gate” wording). **Suggested fix:** If only the “refusing to evaluate same-version gate” class should auto-rebase, tighten the `case` pattern (or key off a dedicated marker from `merge-pr.sh`); if both classes should rebase, document that explicitly in [`scripts/ship-pr.md`](scripts/ship-pr.md) next to the exception.

3. **Nit** (`code-quality`) — [`scripts/test-ship-pr.sh`](scripts/test-ship-pr.sh):1361-1379 — The implementation plan called for `_make_rebase_stubs`; the test instead inlines minimal `exit 0` stubs for `drop-bump-commit.sh`, `git-sync-local-main.sh`, `git-force-push.sh`, and `refresh-run-logs.sh`. Behavior is likely fine because `write_stubs` already provides a generic [`scripts/rebase-push.sh`](scripts/rebase-push.sh) stub, but duplicating stub patterns increases drift if `_make_rebase_stubs` gains required behavior later. **Suggested fix:** Reuse `_make_rebase_stubs` (or extract shared helpers) so the regression test tracks the same stub surface as other rebase tests.
