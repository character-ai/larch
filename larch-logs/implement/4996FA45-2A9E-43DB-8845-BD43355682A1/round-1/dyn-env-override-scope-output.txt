Checking how `MANIFEST` is used and whether CI/Makefile/hooks set or sanitize `LARCH_VERIFY_MANIFEST`.

### In-Scope Findings

- **security** `scripts/verify-run-log-completeness.sh:9-10` — `LARCH_VERIFY_MANIFEST` is honored whenever set in the process environment, with no guard tying it to harness-only use; `scripts/test-verify-run-log-completeness.sh` never unsets it at startup and [`Makefile`](Makefile) `test-verify-run-log-completeness` target (lines 661–662) does not wrap the harness in `env -u LARCH_VERIFY_MANIFEST`, so a developer or CI job that **exports** this variable globally (shell profile, reusable workflow env, shared runner image defaults) can silently switch verification away from [`docs/run-logs-required-files.tsv`](docs/run-logs-required-files.tsv) without touching the tree—an integrity bypass for the same checkout that dirty-tree checks will not surface. **Suggested fix:** `unset LARCH_VERIFY_MANIFEST` near the top of [`scripts/test-verify-run-log-completeness.sh`](scripts/test-verify-run-log-completeness.sh) (after `set -euo pipefail`), keep per-test overrides as `VAR=value "$VERIFY" …` only where intended, and consider `env -u LARCH_VERIFY_MANIFEST` on Makefile targets that are meant to enforce the canonical manifest; extend [`scripts/verify-run-log-completeness.md`](scripts/verify-run-log-completeness.md) to warn explicitly against exporting it in interactive shells used for real verification.

- **correctness** `scripts/verify-run-log-completeness.md:49-51` — The new “Testing override” section describes the value as an “absolute or **repo-relative** path,” but [`scripts/verify-run-log-completeness.sh`](scripts/verify-run-log-completeness.sh) uses `MANIFEST` unmodified (lines 9–10, 97, 150), so a relative path is resolved against the **current working directory**, not `REPO_ROOT`, which can mislead operators about where a path is interpreted (especially if the verifier is launched outside the repo root). **Suggested fix:** Rephrase to “absolute path or path relative to the verifier’s current working directory” and recommend absolute paths for harness fixtures (as test 14 already does via `$bad_manifest` under `$TMP`).
