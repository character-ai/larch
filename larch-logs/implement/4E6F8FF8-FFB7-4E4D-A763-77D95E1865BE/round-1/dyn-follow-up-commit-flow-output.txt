### In-Scope Findings

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:467-480` — On the round-mode follow-up path, a failed `git add -A` / `git-commit.sh` emits `leaving residue for the ship-pr Option A backstop`, but when tracked porcelain is still non-empty the very next check returns exit **2** with `CODER_STATUS=failed` and no `CODER_COMMIT_SHA`. `review-and-fix.md` documents that exit **2** is blocking for `/implement` Step 5, while Option A only runs later inside `ship-pr.sh` `run_rebase_rebump`; in the persistent-hook failure class the workflow stops at Step 5, so the backstop message describes a recovery path that does not run in that failure mode and can mislead operators or automation into expecting a later rebase fixup. **Suggested fix:** Reword or gate the Option A warning so it only logs when execution can actually reach `run_rebase_rebump` (e.g. findings mode / warn-and-continue), or drop it on the fail-closed branch and rely on the second `left tracked changes uncommitted after follow-up` message; align `review-and-fix.md` with whichever contract you keep.

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:467-495` — If the follow-up `if git add -A && git-commit.sh` branch fails but `git status --porcelain --untracked-files=no` is unexpectedly empty afterward, control falls through to the success epilogue: `CODER_STATUS=applied`, exit **0**, and `CODER_COMMIT_SHA` stays at the **primary** round commit SHA even though the follow-up commit never landed. That is a narrow edge case (e.g. commit hook interaction), but it violates the documented “one follow-up, then fail if still dirty” contract and can make Step 5 report success while the tree state does not match `CODER_COMMIT_SHA`. **Suggested fix:** Treat follow-up `else` as failure unless you explicitly verify the residue that triggered the block is gone (e.g. return **2** or at minimum avoid emitting `applied` / refresh `commit_sha` only when follow-up succeeded).

- **risk-integration** `scripts/ship-pr.sh:2856-2870` / `skills/review-and-fix/scripts/review-and-fix.sh:438-465` — Option A’s pre-rebase fixup uses `git add -u` (tracked only), while round-mode primary and follow-up commits use `git add -A`. Both paths gate on tracked-only porcelain (`--untracked-files=no`), but when tracked dirt and new untracked files coexist (e.g. a hook or coder artifact), Step 5 follow-up can sweep untracked into the follow-up commit while Option A may leave untracked residue and still hit `drop-bump-commit.sh` Guard 1 on a later full-tree check. **Suggested fix:** Document the intentional asymmetry and add a harness case with coexisting tracked hook residue plus untracked files, or align staging (`-A` vs `-u`) with the documented “match primary round commit” contract if full staging is required at rebase.
