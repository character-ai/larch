Reviewing branch changes for commit-ordering integration risks. Reading the diff and relevant files.
### In-Scope Findings

- **risk-integration** `skills/review-and-fix/scripts/review-and-fix.sh:461-481` — The round-mode follow-up path documents fail-closed behavior when “the follow-up commit fails **or** tracked porcelain is still non-empty” (`review-and-fix.md:56`), but the implementation only returns `2` with `CODER_STATUS=failed` when porcelain remains after the attempt. If `git add -A` and `git-commit.sh` fail in the `else` branch (lines 467–468) yet the tracked tree is clean—for example a hook or commit helper rejects the commit without leaving staged changes—execution falls through to the success epilogue and emits `CODER_STATUS=applied` with `CODER_COMMIT_SHA` still pointing at the **primary** round commit (lines 484–494). That can let Step 5 advance while a failed follow-up was only logged to stderr, and it diverges from the persistent-hook test (which relies on leftover porcelain) without covering “commit failed, tree clean.” **Suggested fix:** In the follow-up `else` branch, write the same `result_file` (`CODER_STATUS=failed`, `CODER_TOOL`, etc.) and `return 2` immediately; keep the existing porcelain re-check as a second guard for the success path.

- **risk-integration** `scripts/ship-pr.sh:2857-2872` — Block 0b performs a single `git add -u -- larch-logs/` + fixup commit and does not re-check tracked porcelain afterward, unlike `review-and-fix.sh`’s one-shot follow-up loop. A pre-commit hook that mutates an already-staged `larch-logs/` file during `git-commit.sh` can leave hook-only changes out of the fixup commit object but still on disk; `drop-bump-commit.sh` Guard 1 then sees dirty tracked porcelain, returns `DROPPED=false`, and `run_rebase_rebump` can stall (lines 2886–2895) even though Step 5 may have already cleaned hook residue via a follow-up commit. `rebump_dirty_tracked_fixup_idempotent_hook` does **not** short-circuit before `drop-bump-commit.sh` (it copies the real script after `_make_rebase_stubs`, lines 2608–2611) and runs the full `ship-pr.sh` rebump path; it asserts both hook and manual residue appear **inside** the fixup commit blob, which depends on hook mutations being captured in that one commit rather than on a second fixup pass. **Suggested fix:** After a successful fixup commit, mirror review-and-fix: if `git status --porcelain --untracked-files=no` is still non-empty within `larch-logs/`, run one more `git add -u -- larch-logs/` + fixup (or `git add -A` scoped to allowlisted paths) before calling `drop-bump-commit.sh`; alternatively document that Step 5 follow-up must always leave the tree clean and add a harness case where hook residue remains only in the working tree after fixup to pin stall vs. second commit behavior.
