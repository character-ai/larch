### FINDING_9: `/tmp` cleanup — missing descendant freshness guard (cache/tmp asymmetry)
- **Reviewer(s)**: cursor-specialist-edge-cases-output.txt, dyn-cleanup-tmp-descendant-protection-output.txt
- **Severity**: important
- **Concern**: The `/tmp` pass deletes top-level matches by `-mtime +N` without calling `cache_entry_has_fresh_descendant` (or equivalent), while the cache pass skips removal when descendants were touched inside the retention window. `session-setup.sh` still falls back to `/tmp/claude-implement-*` when the cache root is unavailable; parent-directory mtimes are not reliably bumped when nested session files are written (APFS). A long-running `/implement` under `/tmp` can be `rm -rf`'d while still active, even though the same layout under `~/.cache/larch/sessions/` would be kept — a behavioral regression versus the pre-#3212 depth-5 activity scan that applied to both roots.
- **Suggested revisions (informational for voters; coder decides)**:
  - From cursor-specialist-edge-cases-output.txt: Apply cache-style fresh-descendant skip (or subtree mtime) for `/tmp` directory matches; add regression test under `LARCH_TEST_TMP_ROOT`.
  - From dyn-cleanup-tmp-descendant-protection-output.txt: Reuse the same descendant freshness probe for `/tmp` directory candidates (shared helper, not cache-only naming), or if `/tmp` is intentionally legacy/best-effort, touch the session root on active writes and document that operators must not rely on `/tmp` for multi-day runs; add a harness case under `LARCH_TEST_TMP_ROOT` mirroring `stale-toplevel-with-fresh-deep-child-kept`.
