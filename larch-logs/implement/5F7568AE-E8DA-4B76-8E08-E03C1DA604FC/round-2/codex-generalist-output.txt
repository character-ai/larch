### In-Scope Findings

1. **Important** `risk-integration` `skills/implement/SKILL.md:1674`  
   Step 7a still commits the run log without first writing `final-summary.md`, and line 1679 now explicitly says not to call `write-final-report.sh` there. In a successful merge, the later Step 17/18 final-summary write happens after `ship-pr.sh` has created the post-merge sentinel, so the new `larch:final-summary` file is not included in the pre-merge log commit. Add the `write-final-report.sh` call before the `larch-log.sh commit` block, or add a log-only pre-merge mode if PR URL availability is the concern.

2. **Important** `correctness` `skills/review/scripts/review-core.sh:356`  
   Zero-finding review rounds still bypass `emit-tally.sh`, so they do not write `review-summary.json` with `schema_version=2` or the new `panel` fields. Concrete scenario: a clean review with `SCOUT_STATUS=ok` and dynamic slots exits through lines 356-392, flushes the round log, and the committed round lacks the new observability fields entirely. Route the zero-findings path through `emit-tally.sh` with a zero-count tally file and the same `--scout-status`, `--dynamic-slots`, and `--static-slot-count` arguments before `flush_round_log`.

3. **Important** `risk-integration` `skills/review-and-fix/scripts/review-and-fix.sh:637`  
   The rejected-findings fallback is no longer backward-compatible: compact `round-N/rejected-findings.md` files are treated as aggregate inputs and wrapped under `## Round N`, so the fallback copy at lines 675-678 is skipped whenever any compact round file exists. Concrete scenario: an older run with only `round-1/rejected-findings.md` now produces a full-detail-shaped root file instead of copying the latest bare ledger as documented in `skills/review-and-fix/scripts/review-and-fix.md:98`. Make the aggregate two-pass: first detect non-empty `rejected-findings-full.md` files; if none exist, copy the latest compact fallback unchanged.
