### In-Scope Findings

### FINDING_1: Post-create `git-push` widens failure surface beyond the observability brief
- **severity:** **Important**
- **focus_area:** `risk-integration`
- **location:** [`scripts/ship-pr.sh`](scripts/ship-pr.sh) (new block after `larch-log.sh commit` in `run_pr_create_phase`, ~lines 1003–1015 in current tree)
- **issue:** The branch adds a mandatory `git-push.sh` immediately after the post–PR-create `larch-log.sh commit`, with transient classification and `exit_stall 9b` on non-transient failure. This is substantial orchestration change not called out in the three-part observability plan and introduces new stall/transient-exit outcomes on push alone.
- **scenario_or_breakage:** A run that previously reached `ci-initial` with a local-only log commit can now stall at `9b` or take a transient-net exit if this early push fails, even when PR creation and log writes succeeded.
- **suggested_fix:** If the only goal is “remote PR tip includes `final-summary`,” rely on the next existing push boundary (or gate this push behind a flag) and record failures via the same `append-tool-failure` patterns used elsewhere instead of adding a hard-required mid-phase push.

### FINDING_2: Part B diverges from the written Step 7a plan while meeting the underlying intent another way
- **severity:** **Latent**
- **focus_area:** `code-quality` (source: `plan`)
- **location:** [`skills/implement/SKILL.md`](skills/implement/SKILL.md) Step 7a prose (~lines 808–812) vs [`scripts/ship-pr.sh`](scripts/ship-pr.sh) `run_pr_create_phase` and [`scripts/refresh-run-logs.sh`](scripts/refresh-run-logs.sh)
- **issue:** The pasted implementation_plan specified adding `write-final-report.sh` before Step 7a’s `larch-log.sh commit`; the diff instead forbids Step 7a invocation and wires `write-final-report.sh` after `PR_URL` is persisted in `ship-pr` / refresh paths.
- **scenario_or_breakage:** Anyone executing against the literal plan text will edit the wrong lifecycle point or remove the new ship-pr/refresh wiring by mistake, even though the alternate design is arguably sounder (needs `PR_URL` in `ship-pr-state.sh`).
- **suggested_fix:** Reconcile docs: either update the tracking issue/plan artifact to match the ship-pr–centric design or implement the Step 7a hook and delete the contradictory prohibition.

### FINDING_3: Duplicated round-discovery pipeline in `write_rejected_findings_aggregate`
- **severity:** **Nit**
- **focus_area:** `code-quality`
- **location:** [`skills/review-and-fix/scripts/review-and-fix.sh`](skills/review-and-fix/scripts/review-and-fix.sh) (`write_rejected_findings_aggregate`: two identical `find … | awk … | sort` process substitutions)
- **issue:** The same sorted round list is built twice (probe for any full file, then full emit pass), increasing maintenance cost and drift risk if round sorting rules change.
- **suggested_fix:** Capture the sorted `round_num<TAB>round_dir` list once (temp file or array) and reuse for both passes.

### FINDING_4: `write-final-report` errors swallowed in ship-pr / refresh paths
- **severity:** **Nit**
- **focus_area:** `risk-integration`
- **location:** [`scripts/ship-pr.sh`](scripts/ship-pr.sh) (`write-final-report.sh` … `>/dev/null 2>&1 || true`); [`scripts/refresh-run-logs.sh`](scripts/refresh-run-logs.sh) (`2>/dev/null || true`)
- **issue:** Failures are fully silenced, unlike the Step 7a guidance that discourages bare `|| true` without adjacent failure capture for load-bearing tooling.
- **scenario_or_breakage:** Operators lose stderr signals when final-summary rendering breaks; the run continues and downstream only notices missing or stale `final-summary.md` indirectly.
- **suggested_fix:** Route stderr to the existing `failure_capture_path` / `append-tool-failure.sh` pattern (or at least tee to a pre-bump flush log) instead of discarding entirely.
