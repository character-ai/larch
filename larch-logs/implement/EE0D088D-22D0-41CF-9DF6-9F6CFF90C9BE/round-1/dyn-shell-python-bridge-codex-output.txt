### In-Scope Findings
- **risk-integration** `python/ci_monitor.py:380-398` — The new Python completion gate ignores `gh pr checks --json` stdout whenever `gh` exits non-zero, and `_read_pr_checks_text()` also drops text output on non-zero rc. That breaks the design-log rerun path for the exact non-pass states it is meant to handle: if required checks fail or are pending with parseable output, `checks_status(required=True)` can degrade to `"pending"` instead of `"fail"` with a run id, so `python/design_log_ship.py:217-251` never reruns the failed run and eventually times out. The shell registration path already treats non-zero rc with JSON as useful (`scripts/design-log-publish.sh:1041-1048`), so completion should do the same. **Suggested fix:** Parse JSON stdout whenever it is a valid array regardless of return code, and for text fallback classify captured stdout/stderr even on non-zero rc; add tests where required JSON/text returns rc 1/8 with fail/pending rows.

- **risk-integration** `python/test_design_log_ship.py:307-345` — The quiet-mode bridge required by the plan is not actually covered: these `main()` tests call real `logging_util.quiet_init()` in-process and assert via `capsys`, while `emit_kv()` writes to fd 3 after quiet init; meanwhile `scripts/test-design-log-publish.sh:6` globally exports `LARCH_QUIET_DISABLE=1`, so the shell bridge never exercises inherited quiet mode either. This leaves `_dlship_out=$(python3 ... 2>&1)` unvalidated for the fd3-vs-stdout contract that the integration depends on. **Suggested fix:** Add a subprocess or `capfd` test with inherited `LARCH_QUIET_ACTIVE`/`LARCH_QUIET_PID` proving `PUBLISH_OK=` is captured on stdout, and either monkeypatch `quiet_init` or avoid `capsys` for in-process `main()` tests.
