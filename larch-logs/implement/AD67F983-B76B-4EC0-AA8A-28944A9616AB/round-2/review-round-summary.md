### FINDING_15: **security** `skills/design/scripts/review-design-step3-loop.sh:89-93` — `step3_loop_persist_round_start_s` uses a check-then-write pattern (`[[ -L "$start_file" || -e "$start_file" ]]` then `printf … >"$start_file"`) that is vulnerable to TOCTOU symlink replacement: a concurrent writer can create a `round-start-s` symlink in the gap, and bash `>` follows it, so the epoch can be written outside `DESIGN_TMPDIR`. The Python helper at `python/review_and_fix.py:1936-1944` is race-safe via `O_CREAT|O_EXCL|O_NOFOLLOW`; the new Bash path does not match that guarantee despite the plan’s symlink-hardening intent. **Suggested fix:** delegate the write to the same atomic helper used in Python (e.g. a small `python3` one-liner or shared CLI verb calling `os.open(..., O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW)`), or open via a helper that cannot follow symlinks; add a harness test that plants a `round-start-s` symlink between the existence check and write to lock the contract.

### FINDING_19: **risk-integration** `skills/design/scripts/test-design-step3-review.sh:157-175` — The sourced live-loop harness backgrounds `source-live-loop.sh` and then uses an **unbounded** `wait "$round_start_pid"` on the success path (line 174). Failure paths touch `release-body` and `wait ... || true`, but there is no `EXIT` trap after line 157 to release the stub and reap/kill the background PID if the parent exits unexpectedly, and the success-path wait has no wall-clock cap. If `run_design_step3_loop` regresses and hangs after `run_step3_round_body` returns (post-body continuation/timing/envelope path), the harness blocks forever and can wedge `bash skills/design/scripts/test-design-step3-review.sh` / CI. **Suggested fix:** Register an `EXIT` trap after capturing `round_start_pid` that always touches `release-body`, sends `TERM`/`KILL` to the background PID if still running, and waits with a bounded poll loop (mirror the 3s body-entered poll and the stub’s 5s release wait), failing fast instead of blocking on bare `wait`.
