### In-Scope Findings
- **correctness** `python/ci_cli.py:37-55,144-158` — The new `ci status` / `ci wait` entrypoints let invalid numeric and base-ref inputs through. The bash contracts rejected negative counters/timeouts/grace values and unsafe `--base-remote/--base-ref` labels before running git/gh; here `argparse` accepts values like `--empty-checks-grace -1`, `--iteration -100`, or a `--base-remote` beginning with option-like text and forwards them into `gather_status`/`poll_ci`. That can bypass safety-limit logic or change status from the old `CI_STATUS=error` / usage-exit path into a real poll. **Suggested fix:** After parsing, validate all numeric fields are non-negative integers and validate base labels with `git.validate_base_remote_ref`; preserve each command’s old failure mode (`ci status` emits the four KVs with `CI_STATUS=error` and exits 0, `ci wait` exits 1 before clearing/writing output files).

- **correctness** `python/config.py:140-151` — The Python `ci failed-jobs` classifier drops fixable CI jobs that the shell contract classified as fixable: `lint-local` and `bash32-check` are present in `scripts/ci-failed-jobs.sh` but absent from `CI_FIXABLE_JOBS`. Once callers use the Python path, failures in those jobs will be reported as unfixable and the CI-fix loop can skip local recovery that the legacy script allowed. **Suggested fix:** Add `lint-local` and `bash32-check` to `CI_FIXABLE_JOBS`, and add matching `per_job_command` mappings in `python/ci_monitor.py` so classified-fixable jobs can actually be replayed locally.

- **correctness** `python/git_cli.py:261-277` — The new `git check-phantom-dirty` CLI is not a drop-in replacement for `scripts/check-phantom-dirty.sh`: it rejects the documented `--phantom-paths-dir` argument and returns parser failure instead of the old always-0 `STATUS=unknown`/`REASON=<parse-error>` contract for malformed arguments. Any repointed harness or caller using the existing three-argument form will fail before emitting the status KVs consumers parse. **Suggested fix:** Accept `--phantom-paths-dir` with the old semantics, default it only where intentional, and convert argument errors into `STATUS=unknown` plus stable `REASON` tokens with exit 0 to preserve the shell contract.
