- **correctness** `python/migration_lint.py:47-54` — `_ship_pr_live_ref` ends each pattern with `(?=$|[\s;|&)>])`, so a retired script path quoted immediately before `]` is not treated as a live reference. That misses the common `[ -x "$SCRIPT_DIR/<script>.sh" ]` / `[[ -x "$SCRIPT_DIR/<script>.sh" ]]` shape already used in `scripts/ship-pr.sh` (e.g. lines 639, 645, 1612). Today’s deferred-to-E1 scripts in ship-pr are invoked directly (`"$SCRIPT_DIR/ci-wait.sh"`, etc.), so this does not bite yet, but the ship-pr carve-out is incomplete: a future change that only `-x`-guards a retained helper would stop blocking manifest retirement and could allow deleting a script still required under `LARCH_SHIP_PR_IMPL=bash`. **Suggested fix:** Extend the terminator class to include `]` (and other common closers such as `` ` `` if desired), add a positive pytest that `[ -x "$SCRIPT_DIR/resolve-repo.sh" ]` inside a synthetic `scripts/ship-pr.sh` blocks retirement, and add a negative case proving full-line `# …` comments still do not.

- **correctness** `python/migration_lint.py:59-66` — For non-`scripts/ship-pr.sh` files, `_line_references_retired` applies the `$SCRIPT_DIR/<basename>` substring rule only when `Path(rel).parent == Path(retired_path).parent`. A caller outside `scripts/` that references a retired helper solely as `$SCRIPT_DIR/<basename>.sh` (or `${SCRIPT_DIR}/<basename>.sh`) without ever embedding the manifest full path `scripts/<basename>.sh` would not be flagged.
