### In-Scope Findings
- **correctness** `python/pr_cli.py:26-42` — `pr create-branch --check` no longer matches the old `create-branch.sh` contract: the CLI now requires `--branch` even in check mode and emits `BRANCH`/`BASE`/`STATUS`, while the shell check mode emitted `CURRENT_BRANCH`, `IS_MAIN`, `IS_USER_BRANCH`, and `USER_PREFIX`. The backing validation in `python/pr.py:122-133` also hardcodes `sergey-zhupanov/`, so other users' valid branch prefixes are rejected. **Suggested fix:** Restore check mode as a no-`--branch` state probe with the original KV names, derive the user prefix from `git config user.name`, and validate create-mode branch names against that derived prefix.

- **correctness** `python/ci_cli.py:110-126` — `ci wait` drops multiple pieces of the shell contract: output order is changed, `ITERATION` and `ELAPSED` are omitted, `.done` is written empty instead of containing the numeric exit code, and any valid `ACTION=bail` decision exits 1 even though `ci-wait.sh` used exit 0 for valid decisions and exit 1 only for usage/argument errors. This will break consumers that wait on `.done` and parse the ordered KV payload. **Suggested fix:** Emit the exact old order (`ACTION`, `CI_STATUS`, `BEHIND_COUNT`, `CONFLICTED`, `FAILED_RUN_ID`, `BAIL_REASON`, `ITERATION`, `ELAPSED`), write the numeric exit status into `<output-file>.done`, and return 0 for all valid decisions including bail.

- **correctness** `python/pr.py:155-166` — `pr create` lost the pre-push clean-tree guard and maps plain push failure to exit 2. The old `create-pr.sh` failed with exit 1 for dirty worktree or push failure to prevent silently opening/updating a PR without uncommitted local changes. The new path calls `push.push_current_branch()` directly without checking `git status --porcelain`, so dirty worktrees can proceed until a push that excludes local changes. **Suggested fix:** Before any push, run the same clean-tree guard and return exit 1 on dirty worktree or push failure; reserve exit 2 for setup/PR-creation failures.

- **correctness** `python/git.py:298-318` — The git commit/stage port regresses argument shape: `--only` is emitted as `--only ""` instead of a bare `--only`, and `git.add()` omits `--` for exactly one path, so a single filename beginning with `-` is interpreted as a git option. Both differ from the shell wrappers, which used bare `--only` and `git add -- "$@"`. **Suggested fix:** Model `only` as a boolean and append only `--only`; always build `git add` as `["git", "add", "--", *paths]` when paths are present.

- **correctness** `python/ci_monitor.py:357-368` — The text fallback for `gh pr checks` sets `status = "fail"` but never extracts the failed run ID from the URL column. The shell fallback populated `FAILED_RUN_ID` from the first failing check URL, which downstream failure evaluation needs to fetch logs and rerun failed jobs. **Suggested fix:** When the text fallback detects a failure, parse the first URL containing `runs/<id>` and assign `failed_run_id` just like the JSON path.

- **correctness** `python/ci_cli.py:146-155` — `ci behind-count` now prints a raw integer, but `ci-behind-count.sh` emitted `BEHIND_COUNT=<N>`. The raw-stdout exception list does not include this helper, and callers that grep for `BEHIND_COUNT=` will parse an empty value and fail open incorrectly. **Suggested fix:** Emit `_emit_kv("BEHIND_COUNT", count)` while preserving fail-open exit 0 and usage exit 2.
