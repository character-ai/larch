### In-Scope Findings

- **risk-integration** `skills/implement/SKILL.md:1204-1206` — The new disposition-checkpoint fence uses bare `! grep -Fq …` on continuation lines inside an `if [ … ] && …` chain. Per `BASH_AUTHORING.md` §1 (and issue #3104), top-level `grep` in orchestrator Bash fences is the Claude Code wrapper, not `/usr/bin/grep`; a non-zero exit from that wrapper can abort the **entire** Bash tool block before the `if` branch is evaluated — the doc explicitly lists `if grep …; then` and `if ! grep …; then` as unsafe, and the same applies here. That bites on the common fallback path: when the checkpoint exits non-zero but `execution-issues.md` has no `step-8-oos-checkpoint*` row yet (126/127, append failure, or a fresh log), both probes no-match → wrapped `grep` exits 1 → the harness can terminate the block before `append-tool-failure.sh`, `printf 'OOS_CHECKPOINT_RC=…'`, or `[ "$_oos_chk_rc" -ne 0 ] && exit "$_oos_chk_rc"`. Step 8+ then sees a generic tool exit instead of the checkpoint’s 0/1/2 contract and may skip the 126/127 audit row the prose promises at line 1187. `scripts/lint-bare-grep-probe.sh` only flags lines that **start** with `if … grep`; it does not flag `&& ! grep` continuations, so this likely passed pre-commit. **Suggested fix:** Switch both probes to `command grep -Fq …` (preferred in `BASH_AUTHORING.md`), e.g. `&& ! command grep -Fq 'step-8-oos-checkpoint' "$IMPLEMENT_TMPDIR/execution-issues.md" 2>/dev/null` (and the validation-site line likewise). Optionally extend `lint-bare-grep-probe.sh` to flag any fence line matching `&& … grep` / `|| … grep` without a leading `command` or `(`.

- **risk-integration** `skills/implement/SKILL.md:1200` — `${DESIGN_TMPDIR:+--design-tmpdir "$DESIGN_TMPDIR"}` is expanded as an unquoted word on the `bash … checkpoint.sh` invocation line. If `DESIGN_TMPDIR` ever contains whitespace or glob characters, word-splitting can split one path into multiple argv tokens (`--design-tmpdir`, path fragment, …), mis-binding CLI args and breaking design-OOS resolution. Session tmpdirs are usually space-free, but this is still an orchestrator fence footgun on a load-bearing Step 8+ call. **Suggested fix:** Avoid bare parameter expansion on the argv line — e.g. build args with a small array (`_oos_args=(--implement-tmpdir "$IMPLEMENT_TMPDIR")`; `[ -n "${DESIGN_TMPDIR:-}" ] && _oos_args+=(--design-tmpdir "$DESIGN_TMPDIR")`; `bash … "${_oos_args[@]}"`) or use a conditional second line that passes `--design-tmpdir "$DESIGN_TMPDIR"` only when `[ -n "${DESIGN_TMPDIR:-}" ]`.
