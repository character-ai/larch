- **correctness** `skills/implement/scripts/test-oos-disposition-gate.sh:682-703` — The “merge-base absent” checkpoint case only asserts exit `0` against an `mkitmp()` fixture with empty accepted-OOS files, so `non_sec` is always zero and the gate returns success regardless of whether the checkpoint computed `origin/main..HEAD` or fell back to `HEAD`. A regression in the merge-base fallback chain in `oos-disposition-checkpoint.sh:94-100` would not be caught, despite the plan/harness doc claiming this case validates FINDING_1 range behavior. **Suggested fix:** Seed at least one non-security OOS block and craft `MB_TMP` so `origin/main..HEAD` and `HEAD` would produce different `git log` / inline-triage counts (or capture gate stderr and assert the range string appears, e.g. via a small wrapper or by expecting exit `1` vs `0` under a fixture where only `origin/main..HEAD` includes triage commits).

- **correctness** `skills/implement/scripts/test-oos-disposition-gate.sh:706-744` — The `--design-tmpdir` and `design-export/` checkpoint cases put the only `### OOS_*` block and `Filed URL` in the design markdown while `mkitmp()` leaves `oos-accepted-main-agent.md` / `oos-accepted-review.md` empty, so `count_non_security_oos` stays `0` and the gate exits `0` even if design-path resolution is broken and `--filed-urls-strict-file` points at a missing file.
