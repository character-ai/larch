### In-Scope Findings

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-compute-counters.sh:160` / `.claude/skills/audit-runs/SKILL.md:241-297` — `NS_RETRIES_SKIPPED_RUNS` is emitted by `audit-compute-counters.sh` but is not wired through the operator-facing report contract: `SKILL.md` does not list it in the KV read set (line 241), the `cumulative_counters` YAML template (lines 291–297) has no `ns_retries_skipped_runs` key, and `audit-compute-counters.md` omits it from the documented stdout schema. The script also never reads a prior `ns_retries_skipped_runs` from frontmatter and prints a batch delta only (no `TOTAL_*` / `*_DELTA` pair), so skipped-run counts cannot chain across audits the way `ns_retries_cursor_specialist` does. Operators re-auditing mixed legacy/concise batches will see `NS_RETRIES_SKIPPED_RUNS` in script stdout with no persisted label in filed reports. **Suggested fix:** Add `NS_RETRIES_SKIPPED_DELTA` (batch) and optionally `NS_RETRIES_SKIPPED_RUNS_TOTAL` (cumulative with `parse_prior`), document both in `audit-compute-counters.md`, add `ns_retries_skipped_runs` to the `cumulative_counters` YAML template and `SKILL.md` scan/counter tables, and surface the batch delta in `## Delta from prior audit` prose when non-zero.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:438-447` — For pre-migration run logs with neither `reviewer_signals` nor `*-ns-retry*.txt` sidecars, `scan_ns_retry_sidecars` now emits `result:"skip"` instead of the previous `result:"pass","count":0`. That is intentional for “unmeasurable,” but every such clean legacy PR increments `NS_RETRIES_SKIPPED_RUNS` by 1 while leaving `NS_RETRIES_CURSOR_SPECIALIST` unchanged. Re-auditing a large historical batch therefore inflates the skipped counter and flips per-PR scan rows from pass to skip without changing the cumulative NS-retry total, which can misread as widespread new failure rather than a measurement gap. **Suggested fix:** Emit `pass` with `count:0` and a `detail` such as `legacy log without reviewer_signals or sidecars (unmeasurable)` when legacy glob finds zero files, reserving `result:"skip"` for true scan errors; or document in `SKILL.md` / `## Delta from prior audit` that post-migration re-audits of legacy logs will show elevated `NS_RETRIES_SKIPPED_RUNS` without implying new NS retries.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:438-444` / `.claude/skills/audit-runs/scripts/audit-scan-run.md:43` — The legacy-only fallback path counts `*-ns-retry*.txt` files but assigns every reason as `UNKNOWN`, even though `audit-scan-run.md` still documents reading `NS_RETRY_REASON=` from `*.meta` during legacy fallback (as the pre-migration path did). Sidecar-present legacy runs still feed `NS_RETRIES_DELTA` correctly, but the `reasons` histogram regresses and can skew operator triage when mixing legacy fail rows with new carrier-based rows in one batch. **Suggested fix:** Restore `.meta` parsing in the legacy-only branch (mirror the pre-migration loop: read `NS_RETRY_REASON=`, normalize, fall back to `UNKNOWN`) and add a harness case with a legacy sidecar + `.meta` asserting non-`UNKNOWN` reasons.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:560-591,661-671` — `codex-generalist-waste` and `trailing-content-no-issues-found` have no legacy file fallback (unlike `ns-retry-sidecars`, which still globs sidecars). Pre-migration committed logs that retain `codex-generalist-output.txt` or `*-first-pass.txt` but lack `reviewer_signals` now emit `skip` instead of pass/fail, changing per-PR scan tables and recurrence detection for historical batches even though they do not feed cumulative counters. **Suggested fix:** Add the same two-tier pattern as NS-retry (carrier first, then legacy file read with `detail` noting fallback), or explicitly gate `skip` behind a migration cutoff / `larch_version` check so historical logs remain measurable until the corpus is re-flushed.
