Inspecting `scan_ns_retry_sidecars` and its helper calls in the audit-scan script.
Checking how `jq -sc` behaves with mixed valid/invalid round-meta files and whether tests cover the hybrid path.
### In-Scope Findings

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:159-176,438-447` — `_audit_reviewer_signals_jq` gates on any round having a non-empty `reviewer_signals` array, but the actual extraction uses `jq -sc` over **all** `round-*/round-meta.json` files. If any round-meta is malformed, `jq -sc` fails, `signals_json` becomes empty, and the scan falls into the legacy/unavailable branch even when another round has valid `ns_retry_reason` carriers. With no legacy `*-ns-retry*.txt` files on disk this emits `result:"skip"` instead of `fail`, silently missing real NS-retry events (verified: valid `round-1` signal + corrupt `round-2/round-meta.json` → skip). **Suggested fix:** parse round-meta per-file (or skip only bad files) so valid rounds still contribute; when `signals_any=true` but aggregation fails, emit `result:"error"` (or per-round partial fail) rather than treating the run as fully unavailable.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:470-484` — Orphan sidecar dedup is guarded by `[ -n "$signaled_bases" ]` and a `jq -e … || true` membership check. If the second `_audit_reviewer_signals_jq` call fails and leaves `signaled_bases=""`, the membership branch is skipped entirely and every `*-ns-retry*.txt` file is counted as an orphan on top of whatever the first pass already counted from `reviewer_signals[].ns_retry_reason`. The duplicate helper invocation makes this failure mode easy to miss because there is no validation that `signaled_bases` is a JSON array before entering the orphan loop. **Suggested fix:** derive reasons and `signaled_bases` in a single `_audit_reviewer_signals_jq` call (or cache the first slurp), and if dedup inputs are missing/invalid after a non-empty reason pass, emit `error`/`skip` instead of unconditionally incrementing orphan counts.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:438-459,476-484` — The legacy/unavailable branch and the orphan sidecar branch always append `UNKNOWN` to `_reasons_list` and never read `NS_RETRY_REASON=` from `*.meta` sidecars, but `audit-scan-run.md` still documents meta-based reason tokens for legacy fallback. A run with sidecars present therefore fails with the right count but wrong reason histogram (e.g. `.meta` containing `OUTPUT_EMPTY` is reported as `UNKNOWN`). **Suggested fix:** restore meta parsing in the legacy and orphan paths (reusing `_audit_normalize_ns_retry_reason_token`) so file-only retries preserve reason fidelity documented in `audit-scan-run.md`.

### Out-of-Scope Observations

- **correctness** `.claude/skills/audit-runs/scripts/test-audit-runs.sh:1341-1438` — Tests cover signal-only (`Test 35`) and sidecar-only legacy fallback (`Test 35a2`), but not the hybrid case where `reviewer_signals` and a matching `*-ns-retry.txt` coexist (`LARCH_FLUSH_DEBUG=1`). Manual execution of that hybrid path dedupes correctly to `count:1`, so this is a coverage gap rather than a confirmed defect.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:438-460` — Legacy fallback correctly emits `result:"fail"` when sidecars exist and `result:"skip"` only when both the carrier and sidecars are absent (`Test 35a2`); the scout concern about “skip instead of fail” does not apply to that branch.
