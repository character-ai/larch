Reviewing artifact-gating changes and tracing consumers that may break.
### In-Scope Findings

- **risk-integration** `scripts/design-log-publish.sh:514-520` — Top-level `voting-tally.md` is listed in `design_artifact_excluded()` (line 332) but the top-level staging loop forces `_include_excluded=true` for that basename only, so run-root tally prose is still committed while per-round `plan-review/round-N/voting-tally.md` is excluded. That reintroduces bulky voting prose into concise design logs and splits the contract: analyzers reading only the four-file per-round set (`round-summary.env`, `findings-classification.tsv`, `prune-decision.env`, `prune-nit.env`) will not see tally data that is still present at run root. **Suggested fix:** Either drop the carve-out and rely on `findings-classification.tsv` + `round-summary.env` for post-analysis, or document and test root `voting-tally.md` as an explicit fifth consumer-core artifact (and add it to the byte-budget guard).

- **risk-integration** `scripts/lib-design-round-artifacts.md:21-31` — The allowlist doc was not updated with the code change in `scripts/lib-design-round-artifacts.sh:5-17`. It still lists `findings.md`, `voting-tally.md`, vote outputs, scout manifests, per-round `plan.txt`/`plan.diff`, etc., and its own “Edit-in-sync rule” requires updating this file in the same commit. Contributors following the doc will expect artifacts the publisher now excludes, and may reintroduce bloat or hit “unexpected file” errors when extending snapshot/publish logic. **Suggested fix:** Rewrite the allowlist section to match the four-file default contract, debug-gated families, and root `plan.txt` keep-set; align `scripts/design-log-publish.md` (lines 62–72 still claim per-round `findings.md`/`voting-tally.md` are canonical and that `plan.diff` is generated for rounds ≥2).

- **risk-integration** `docs/run-logs.md:410-438` and `scripts/larch-log.md:53-82` — Committed-log documentation still describes the pre-concise surface: per-round `findings.md`, 2 KB–capped `*-vote-output*`, included `*-output-first-pass.txt` / NS-retry sidecars, and a `collect_log` section in `round-meta.json`. The branch removes `collect_log` from the producer (`scripts/larch-log.sh` Python block), debug-gates vote outputs and raw reviewer transcripts, and relies on `reviewer_signals[]` instead. Operators and downstream tooling reading these docs will look for files/fields that new runs no longer commit. **Suggested fix:** Update both docs to the concise default contract, `reviewer_signals` schema, debug-gated families, and note that `collector` (not `collect_log`) remains when `collector-results.env` exists.

- **risk-integration** `.claude/skills/audit-runs/SKILL.md:70-75` — The scan reference table still points `ns-retry-sidecars`, `codex-generalist-waste`, and `trailing-content-no-issues-found` at raw `round-*/*` files, but `scans-implement.tsv` and `audit-scan-run.sh` now use `reviewer_signals[]` in `round-meta.json` (with `skip` when signals are unavailable). Audit operators following SKILL.md will inspect the wrong artifacts on concise logs and may treat `result:"skip"` as healthy when `reviewer_signals` was never populated. **Suggested fix:** Update the SKILL table and `audit-scan-run.md` to match the new scan types/locations; call out that `skip` means “concise carrier missing,” not “clean run.”

- **risk-integration** `scripts/larch-log.sh:124,136,436-441` — `code-voter-slots.ndjson` remains on the default include list while `*-vote-output*.txt` (and sidecars) are debug-gated. Committed slots still reference `…/codex-vote-output.txt` paths that are absent from default flushed logs, and the `aggregator-output.txt` byte-identical skip runs only after `round_artifact_included`—but `aggregator-output.txt` now matches the debug-gated `*-output.txt` arm, so the cmp guard is unreachable and unique aggregator output is never committed by default. **Suggested fix:** Either stop flushing `code-voter-slots.ndjson` on the concise path, rewrite slot `output` fields to committed carriers (`findings-classification.tsv` / `round-meta.json`), or document slots as pointers to session-only paths; move the aggregator dedup check before the broad `*-output.txt` deny or drop the dead cmp block.

- **risk-integration** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:158-176` — `_audit_reviewer_signals_jq()` treats the signal carrier as unavailable unless some round has `reviewer_signals` with `length > 0`. A concise run where `round-meta.json` exists but `reviewer_signals` is missing/empty (producer failure, partial flush, or sidecar-only meta) causes `ns-retry-sidecars` and `trailing-content-no-issues-found` to emit `skip` instead of `pass` or `fail`. That is safer than a false pass on sidecar absence, but it can hide regressions in the new producer because audit dashboards may not distinguish “skipped” from “clean.” **Suggested fix:** Emit a distinct `result` (e.g. `error` or `fail` with `detail:"reviewer_signals producer empty"`) when `round-meta.json` exists but no round has a non-empty `reviewer_signals` array on implement runs that recorded review rounds.
