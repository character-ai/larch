### In-Scope Findings
- **risk-integration** `scripts/design-log-publish.sh:606-616` — `*.failure-diag` is now debug-gated by `scripts/lib-design-round-artifacts.sh:10-12`, but default publish does not classify it as an excluded basename in `design_artifact_excluded`; a non-debug plan-review round containing a bounded failure carrier will therefore hit the “unexpected file under plan-review” branch and make publish fail. This is reachable because design voters/reviewers write per-round outputs and `scripts/run-external-agent.sh:170-184` creates `${OUTPUT}.failure-diag` on nonzero exits. **Suggested fix:** Either keep `*.failure-diag` included by default for design, or add a default exclusion arm for `*.failure-diag` in `design_artifact_excluded` that skips it silently when `LARCH_FLUSH_DEBUG!=1`, with a publish regression fixture containing `plan-review/round-1/*failure-diag`.

- **risk-integration** `scripts/larch-log.sh:136-138` — The branch excludes raw reviewer outputs, NS-retry transcripts, and first-pass files from default committed implement logs, but the audit scans still read those exact files and report pass/skip when they are absent: `.claude/skills/audit-runs/scripts/audit-scan-run.sh:406-448`, `.claude/skills/audit-runs/scripts/audit-scan-run.sh:501-525`, and `.claude/skills/audit-runs/scripts/audit-scan-run.sh:594-610`. This silently disables the anomaly checks that the new `round-meta.json` `reviewer_signals[]` was meant to preserve. **Suggested fix:** Migrate those scans to `round-meta.json.reviewer_signals[]` before excluding the raw artifacts, and make missing signals produce explicit `skip`/error rather than clean pass; add audit-runs tests over concise logs with no raw `*-output`, `*-ns-retry*`, or `*-first-pass` files.

- **risk-integration** `scripts/larch-log.sh:618-630` — The new `reviewer_signals[].ns_retry_reason` extractor probes names like `<output>.txt-ns-retry.meta` / `<output>.txt.ns-retry.meta`, but the collector writes the actual sidecar as `${ORIG_OUTPUT%.txt}-ns-retry.txt.meta` (`scripts/collect-agent-results.sh:1306-1308`, `scripts/collect-agent-results.sh:1349-1352`). As a result, concise logs lose the NS retry reason even when the retry happened and the sidecar exists in the source dir. **Suggested fix:** Derive the stem by removing `.txt` and read `${stem}-ns-retry.txt.meta` / `${stem}-ns-retry.txt.json`, parsing `NS_RETRY_REASON=...`; pin this with a `write-round` fixture asserting `reviewer_signals[].ns_retry_reason`.
