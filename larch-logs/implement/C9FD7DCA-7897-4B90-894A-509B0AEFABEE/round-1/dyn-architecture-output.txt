Reviewing the branch diff and key architecture surfaces from the scout notes.
### In-Scope Findings

- **architecture** `scripts/larch-log.sh:478-644` — `reviewer_signals[]` is only composed inside `if [ -s "$sidecar_paths" ]`, so `round-meta.json` (and the signals audit scans depend on) is skipped whenever a round has no tally/collector sidecars, even if reviewer `*-output.txt` files are still present in `SOURCE_DIR`. That couples the new audit contract to an unrelated sidecar precondition and can leave concise logs without `reviewer_signals` on early or minimal flush paths. **Suggested fix:** Split round-meta composition: always run the `reviewer_signals` scan against `SOURCE_DIR` when any reviewer output exists; keep sidecar-driven keys (`tally`, `collector`, etc.) gated on their own inputs.

- **architecture** `scripts/larch-log.sh:617-630` — `ns_retry_reason` is read from `name + suffix` (e.g. `cursor-specialist-X-output.txt.ns-retry.meta`), but `collect-agent-results.sh` writes meta to `${ORIG_OUTPUT%.txt}-ns-retry.txt.meta` (e.g. `cursor-specialist-X-output-ns-retry.txt.meta`). The producer also skips any basename containing `ns-retry`, so it never ingests the retry artifact directly. Committed concise logs will therefore almost always have empty `ns_retry_reason` in `reviewer_signals[]`, defeating the planned replacement for raw `*-ns-retry*.txt` audit data. **Suggested fix:** Resolve NS-retry meta via `os.path.splitext(name)[0] + '-ns-retry.txt.meta'` (and `.json` siblings), or join against the paired `-ns-retry.txt` basename; add a fixture with a real NS-retry sidecar layout in `test-larch-log-write-round.sh`.

- **architecture** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:406-611` — Plan item D15 required migrating `ns-retry-sidecars`, `codex-generalist-waste`, and `trailing-content-no-issues-found` to `round-meta.json` `reviewer_signals[]` (with explicit `skip` when signals are unavailable). The branch still scans raw `*-ns-retry*.txt`, `round-1/codex-generalist-output.txt`, and `*-first-pass.txt`, which default concise flush now excludes. On v≥49 logs this yields false `pass`/`skip` instead of signal-backed results — the same class of “measurement blind spot” this bug set is fixing. **Suggested fix:** Implement the planned `reviewer_signals` readers in `audit-scan-run.sh`, update `test-audit-runs.sh` fixtures to use concise `round-meta.json` only, and emit `result:"skip"` with `detail:"…signal unavailable"` when required keys are absent.

- **architecture** `scripts/larch-log.md:29-30` vs `scripts/larch-log.md:216-218` — The canonical contract at the top still states `*-ns-retry*.txt` “remain committed” for the `ns-retry-sidecars` scan, while `round_artifact_included()` and the appended concise-log section deny those files by default and point audits at `reviewer_signals[]`. Operators and downstream tooling reading only the primary doc will assume transcripts are still durable. **Suggested fix:** Rewrite the §write-round exclusion list at the top to match the debug-gated default and document the `reviewer_signals` schema as the sole default audit carrier; remove or relocate the stale NS-retry retention sentence.

- **architecture** `scripts/test-larch-log-write-round.sh:238-253` — Tests assert `collect_log` removal and sidecar sections but do not assert `reviewer_signals[]` presence, required keys, or enum values, despite the plan requiring golden coverage before transcript denial lands. A regression in the producer (wrong directory, gating, or meta join) can ship without failing CI. **Suggested fix:** Extend the round-meta Python assertion block to require `reviewer_signals` entries with `output_basename`, `slot_label`, `result_kind`, `ns_retry_reason`, and `first_pass_trailing_content` when fixture reviewer outputs exist.

### Out-of-Scope Observations

- **architecture** `scripts/lib-prune-decision.sh:36-44` — `normalize_prune_eligible` emits the integer via `_prune_nonneg_int` (no trailing newline) plus a separate `printf '\n'`. Command-substitution callers capture this correctly; no defect found, but the two-call stdout pattern is easy to misuse if a future caller pipes instead of assigns.

- **architecture** `scripts/lib-prune-decision.sh:54-74` — `write_prune_decision_env` uses `${dest}.tmp.$$` + `mv -f`; safe under the single-writer-per-`$REVIEW_TMPDIR` assumption. Parallel writers to the same `dest` could still race, but dispatch and `flush_round_log` paths are session-scoped.

- **architecture** `skills/review/scripts/dispatch-panel.sh:472-616` and `skills/review/scripts/review-core.sh:300-306` — `_write_prune_decision_env` runs after the prune filter on all dispatch exits (including `PANEL_PRUNED_EMPTY`), and `flush_round_log` calls `ensure_prune_decision_env` / `ensure_prune_nit_env` before `larch-log.sh write-round` at all seven flush sites (lines 380, 648, 735, 864, 952, 1108, 1146). The shared `lib-prune-decision.sh` derivation is wired as planned on the implement path.

- **architecture** `scripts/larch-log.sh:481-644` — The `reviewer_signals` Python block reads from `sys.argv[1]` (`SOURCE_DIR`), not the filtered destination tree, so transcript denial in the staging loop does not strip signals at source-scan time. The main gap is sidecar gating and NS-retry meta path resolution, not scanning the wrong directory.
