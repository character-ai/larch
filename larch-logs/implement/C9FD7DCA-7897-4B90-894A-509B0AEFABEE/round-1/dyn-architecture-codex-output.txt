### In-Scope Findings
- **architecture** `scripts/larch-log.sh:136-139` — Default implement round flushing now excludes the raw files that several audit-runs scans still use: `*-ns-retry*.txt`, `*-output-first-pass.txt`, and `*-output.txt`. But `.claude/skills/audit-runs/scripts/audit-scan-run.sh:406-448`, `501-525`, and `594-610` still inspect those raw files directly, and `.claude/skills/audit-runs/scans-implement.tsv:6-14` still declares those raw-file patterns as the scan contract. On concise logs this turns real NS-retry/trailing-content/generalist-waste anomalies into clean `pass` or `skip`, defeating the new `reviewer_signals` architecture. **Suggested fix:** migrate those scans and registry descriptions to read `round-meta.json` `reviewer_signals[]`, returning explicit `skip` only when the signal is absent, and update the audit-runs tests before default-excluding the raw transcript families.

- **architecture** `scripts/larch-log.sh:618-627` — The new `reviewer_signals[].ns_retry_reason` producer looks for sidecars named like `<output>.txt-ns-retry.meta` / `<output>.txt.ns-retry.meta`, but `scripts/collect-agent-results.sh:1308` and `1349-1352` actually write `<output-stem>-ns-retry.txt.meta` containing `NS_RETRY_REASON=<token>`. Even after audit consumers are migrated to `reviewer_signals`, NS-retry reasons will stay empty or incorrectly parsed, so the compact signal does not replace the removed sidecar data. **Suggested fix:** derive the sidecar as `${name%.txt}-ns-retry.txt.meta` / `.json` and parse the `NS_RETRY_REASON=` line into just the token before writing `ns_retry_reason`.

- **architecture** `skills/design/scripts/plan-review-loop.sh:1790-1802` — The design `main-agent-vote-required` terminal branch snapshots and exits without recording launched reviewer slots into `reviewer-prune-ledger.tsv`, while the normal settled path records at `skills/design/scripts/plan-review-loop.sh:1848-1851`. This leaves MAV rounds out of the pruning history, so later round-3/4 pruning can be based on incomplete history and the committed design ledger remains incomplete for exactly one of the terminal paths the concise audit schema is meant to cover. **Suggested fix:** initialize the design prune ledger with the header at run start, and call `plan_review_record_prune_round "${PANEL_MANIFEST:-$DESIGN_TMPDIR/plan-review-slots.ndjson}" "$_findings_classification_out"` in the MAV branch before `_snapshot_terminal_exit_preserving_status` when the classification TSV exists.
