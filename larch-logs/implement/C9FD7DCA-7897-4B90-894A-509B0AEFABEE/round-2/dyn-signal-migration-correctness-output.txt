Reviewing the audit-scan signal migration: reading the diff and comparing the new jq logic to the old file-based scans.
### In-Scope Findings

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:426-469` — `scan_ns_retry_sidecars` no longer glob-counts `round-*/*-ns-retry*.txt` files; it counts `reviewer_signals[]` entries with non-empty `ns_retry_reason`. The producer in `scripts/larch-log.sh:622-646` fills `ns_retry_reason` only from meta/json sidecars, not from sidecar **file** presence. Under the old scan, any `*-ns-retry*.txt` file was a fail (with `UNKNOWN` when meta was missing); under the new scan, a retry sidecar with missing/unreadable meta yields an empty `ns_retry_reason` and **passes** (`count=0`). Multiple sidecar files per output can also under-count versus the old per-file glob. **Suggested fix:** In the `larch-log.sh` producer, set `ns_retry_reason` to at least `UNKNOWN` when any matching `*-ns-retry*.txt` exists for the output even if meta is absent; or have the scan treat non-empty `ns_retry_reason` **or** a dedicated boolean (e.g. `ns_retry_artifact_present`) as fail, and add a fixture with sidecar-on-disk + empty meta to lock the old semantics.

- **correctness** `scripts/larch-log.sh:570-586`, `.claude/skills/audit-runs/scripts/audit-scan-run.sh:622-641` — `trailing_content()` (fed into `first_pass_trailing_content`) is not equivalent to the removed first-pass grep. The producer skips leading blank lines, accepts `NO_ISSUES_FOUND` via broad `result_kind()` (JSON / case variants), and flags the second **non-empty** line; the old scan required exact `NO_ISSUES_FOUND` on **physical line 1** and scanned physical lines 2+. A first-pass file like `\nNO_ISSUES_FOUND\n<trailing>` was **passed** by the old scan (line 1 not `NO_ISSUES_FOUND`) but is now **failed** when paired with an output signal; conversely, `no issues found` + trailing may fail now while the old exact match passed. **Suggested fix:** Align `trailing_content()` with the old predicate (exact first non-empty line equals `NO_ISSUES_FOUND`, then any non-whitespace on later physical lines), or document the intentional broadening and add round-trip fixtures that assert producer output matches the legacy grep on representative first-pass shapes.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:522-552` — `scan_codex_generalist_waste` gates on `result_kind == "NO_ISSUES_FOUND"` from `reviewer_signals`, but the old scan required the **exact** first line of `round-1/codex-generalist-output.txt` to equal `NO_ISSUES_FOUND` after strip. `result_kind()` in `scripts/larch-log.sh:547-568` also classifies JSON `no_issues_found`, lowercase prose, etc., so runs that previously passed can now enter the `>120s` fail path. **Suggested fix:** Either preserve exact-line semantics in the producer for the codex-generalist slot (store a dedicated `first_line_token` or narrow `result_kind` for that basename), or restrict the scan to an explicit exact-match field rather than the generalized `result_kind` enum.

- **correctness** `.claude/skills/audit-runs/scripts/audit-scan-run.sh:159-176` — `_audit_reviewer_signals_jq` treats “no round-meta with non-empty `reviewer_signals`” as `unavailable` → **skip**. That is not a silent pass, but it **drops detection** on pre-concise run logs that still have `*-ns-retry*.txt` or `*-first-pass.txt` on disk but no `reviewer_signals` carrier; the old scans would fail on those artifacts. Historical audits therefore lose signal unless logs are backfilled. **Suggested fix:** Add a legacy fallback in each migrated scan: when `reviewer_signals` is unavailable, run the previous file-based logic (or emit `result:"error"` with a loud “concise carrier missing” detail) so old corpus rows are not downgraded to skip.

- **correctness** `.claude/skills/audit-runs/scripts/test-audit-runs.sh:914-938,1333-1371` — Regression coverage does not exercise the migrated scan paths end-to-end. Test 24 still duplicates the **removed** first-pass grep and claims it matches `audit-scan-run.sh`; Test 35 only hand-builds `reviewer_signals` for `ns-retry-sidecars` and does **not** run `codex-generalist-waste` or `trailing-content-no-issues-found`, does not assert `skip` when `reviewer_signals` is absent, and does not assert multi-round trailing aggregation across `round-*/round-meta.json`. The ns-retry fixture uses a synthetic `output_basename` that the real producer would never emit (it skips `*-ns-retry*` names in `scripts/larch-log.sh:613-614`). **Suggested fix:** Extend Test 35 (or add sibling tests) to run all three scans via `audit-scan-run.sh` with fixtures produced by `larch-log.sh write-round` (or faithful mirrors), including unavailable→skip, multi-round trailing, codex-generalist timing fail/pass, and producer-shaped ns-retry on a parent output basename.
