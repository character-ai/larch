### In-Scope Findings

- **security** `skills/review-and-fix/scripts/review-and-fix.md:56` — The new contract says snapshots live “outside the Codex coder's `--add-dir "$round_dir"` grant” (true) but also states the invariant that `dirname "$round_dir")` must stay “outside every Codex `--add-dir` / workspace root.” Codex dispatch still passes `--add-dir "$PWD"` alongside `--add-dir "$round_dir"` (`skills/review-and-fix/scripts/review-and-fix.sh:273`). Snapshots land at `$IMPLEMENT_TMPDIR/.pre-coder-snapshots/round-N`, i.e. under `dirname("$round_dir")`. Whenever `--implement-tmpdir` (or any caller) places `$IMPLEMENT_TMPDIR` inside the repo—allowed by the API and used in tests (`skills/review-and-fix/scripts/test-review-and-fix.sh:287-289` keeps tmpdir under the work tree)—that snapshot tree remains inside the `--add-dir "$PWD"` grant, so a hostile Codex coder can still tamper with `pre-coder-head.txt`, `pre-coder-tracked-paths.txt`, and patches and bypass the #3272 carryover gate. Production `/implement` usually avoids this because `session-setup.sh` puts the session tmpdir under `~/.cache/larch/sessions/` or `/tmp`, but the branch does not document or enforce that precondition. **Suggested fix:** Qualify `review-and-fix.md` (and `pre_coder_snapshot_dir` call-site comments) so tamper-resistance requires `$IMPLEMENT_TMPDIR` to resolve outside `$PWD` for Codex rounds, not merely outside `$round_dir`; optionally add a pre-dispatch guard in `review-and-fix.sh` (~1321) that refuses coder dispatch when `pre_coder_snapshot_dir` is path-contained under `$PWD`, or relocate snapshots to a directory never covered by any `--add-dir` (e.g. a dedicated path outside both grants).

- **security** `skills/review-and-fix/scripts/test-review-and-fix.sh:512-514` — The new “coder-unreachability” regression only asserts `pre_coder_snapshot_dir` is not under `$round_dir/`, which matches the relocation helper but does not exercise the real Codex grant surface (`--add-dir "$PWD"`). A layout with `$work/implement/round-1` and `$work/implement/.pre-coder-snapshots/round-1` passes this test while snapshots remain Codex-writable via `--add-dir "$PWD"`, so the test can pass when the security property does not hold. **Suggested fix:** Extend the carryover cases (or add a dedicated case) to assert the snapshot dir is not under canonical `$PWD` when simulating production, or document that in-repo tmpdir layouts are unsupported for Codex carryover integrity and gate them explicitly in the harness.
