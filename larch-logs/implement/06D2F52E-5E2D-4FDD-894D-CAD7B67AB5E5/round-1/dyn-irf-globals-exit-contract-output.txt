### In-Scope Findings

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:911-956` — While `run_implement_loop` sets `IRF_SUPPRESS_EMIT_KV=1` and then calls `_implement_round_body` (`skills/review-and-fix/scripts/review-implement-step5-loop.sh:110-114`), the round body’s infrastructure guards still use bare `exit 2` (MODE/ROUND_NUM/`IMPLEMENT_TMPDIR`/`REVIEW_CORE_SH`/`RUN_EXTERNAL_AGENT_SH`/jq/`CONVERGENCE_THRESHOLD`/dynamic-archetypes validation). In Bash, `exit` from a function terminates the whole process, so `run_implement_loop` never reaches `step5_emit_final_envelope`, and stdout lacks the promised `STEP5_REVIEW_STATUS=…` KV block even for otherwise “valid” invocations that hit a broken install (missing `jq`, non-executable `review-core.sh`, bad forwarded `--convergence-threshold`, symlinked tmpdir, etc.). **Suggested fix:** Treat these as recoverable when `IRF_SUPPRESS_EMIT_KV` is set: either hoist the same checks to `run_implement_loop` before setting suppression and emit a stall envelope there, or replace those `exit 2` sites with `return 2` plus minimal `IRF_LAST_*` staging and have the loop translate `post_exit`/`IRF` into `step5_emit_final_envelope stall …` (reusing fixed `STALL_REASON` values) instead of letting the process die mid-loop.

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:209-214,1160-1166` — `mirror_oos_markdown` still ends with `exit 2` on `cp` failure, and `_implement_round_body` calls it from the skipped-findings/OOS path while suppression is active. That terminates the entire script before the `IRF_LAST_*` assignments and the `if [[ -n "${IRF_SUPPRESS_EMIT_KV:-}" ]]; then return "$exit_code"; fi` footer (`skills/review-and-fix/scripts/review-and-fix.sh:1426-1429`), so the loop never emits the final Step 5 envelope despite this being a mid-round, “should stall not explode” class of failure. **Suggested fix:** Change `mirror_oos_markdown` to `return 2` (or return 1) on failure, have the caller set `status`/`exit_code` (or a dedicated stall reason such as `env-write-failed`) and flow through the normal suppressed return path so `run_implement_loop` can emit `step5_emit_final_envelope` and `exit 2` per contract.

- **correctness** `skills/review-and-fix/scripts/review-implement-step5-loop.sh:65-71` — Invalid `--round-cap` or `--starting-round` values trigger `larch_err` + bare `exit 2` with no `step5_emit_final_envelope`, unlike the missing-prior-round artifact case at lines 73–76 which does emit a stall envelope before exiting. Any mis-parameterized launcher call therefore yields stderr + exit 2 but no parseable `STEP5_REVIEW_STATUS`, same contract gap as above (different layer). **Suggested fix:** For these validation failures, emit `step5_emit_final_envelope stall true …` with a dedicated `STALL_REASON` (for example `invalid-round-cap` / `invalid-starting-round` aligned with the documented enum) before `exit 2`, or reject arguments in `run-step5-review.sh` before invoking loop mode so the loop always sees normalized integers.
