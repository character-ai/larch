### In-Scope Findings

- **correctness** `skills/design/SKILL.md:527-530,754-757` — The `case "$_summary_threshold" in (''|0|*[!0-9]*)` guard only rejects empty, a lone `0`, or any string containing a non-digit. Strings that are **all digits but not valid “plain” positive integers in the sense documented** slip through: e.g. `00` does not match `0` (full-string match), does not match `*[!0-9]*`, and is then passed to `[ "$_plan_lines" -gt "$_summary_threshold" ]`, where Bash treats it as **octal 0**, so almost every plan incorrectly enters summary mode. Similarly, values like `0120` are not normalized to decimal `120`; `[ -gt ]` treats them as **octal** (`0120` → 80), so the effective threshold can diverge silently from the documented “positive integer / default 120” contract. **Suggested fix:** Extend the `case` list (e.g. add a `0[0-9]*)` arm that resets to `120`, ordered so it catches multi-digit all-zero and other leading-zero forms) and/or compare using an explicit decimal coercion such as `$((10#_summary_threshold))` inside a guarded assignment so operands are always base-10 integers; keep the existing empty/`0`/non-numeric fallbacks and document that leading-zero env values are normalized to the default.
