### In-Scope Findings

- **security** `scripts/launch-cursor-implement.sh:325-333` — After a failed agent run, the launcher always calls `write_failed_agent_stderr_tail "$_FAILURE_OUTPUT" "$TRANSCRIPT_PATH"` with `_FAILURE_OUTPUT` defaulting to `$SIDECAR_LOG` whenever that file is non-empty. That sidecar is the merged stdout+stderr of `run-external-agent` (`>"$SIDECAR_LOG" 2>&1`), not the `--capture-stdout-only` stderr channel in `${TRANSCRIPT_PATH}.diag`. `run-external-agent.sh` has usually already written a redacted `${TRANSCRIPT_PATH}.stderr-tail` from `.diag` (lines 321–323 in `run-external-agent.sh`). The launcher write unconditionally replaces that artifact with a tail taken from the broader wrapper stream, which can surface wrapper progress, duplicated tail fences, and transcript-adjacent material under the “failed agent stderr tail” banner while still bypassing the lane’s intended source order. **Suggested fix:** For `--capture-stdout-only`, skip the post-loop write when `${TRANSCRIPT_PATH}.stderr-tail` is already non-empty, or mirror `select_failed_agent_stderr_source` (prefer `.diag`, then sidecar only if `.diag` is empty) so producer writes cannot clobber the redacted `.diag`-based tail.

- **security** `scripts/lint-fix-loop.sh:302-308` — On `run_cursor` failure, if `${run_dir}/cursor.log.stderr-tail` is missing, the fallback calls `write_failed_agent_stderr_tail "$run_dir/cursor.log" "$run_dir/cursor.log"`. Under `--capture-stdout`, `cursor.log` is the agent’s captured stdout / last-message transcript, not stderr; when `.diag` is also empty this path labels agent output as a stderr tail and pushes it through chat surfacing (`STDERR_TAIL_PATH` → `ship-pr.sh` / Step 5). Redaction limits bytes/lines but does not change semantics, so implement chat can receive agent response text (paths, snippets, model output) misclassified as failure stderr. **Suggested fix:** Restrict fallback sources to `${run_dir}/cursor.log.diag`, then `cursor.preflight.log` / wrapper logs that are actually stderr; never use `$run_dir/cursor.log` as a tail source in `--capture-stdout` mode. If no stderr source exists, omit the write and leave `STDERR_TAIL_PATH` unset.

### Out-of-Scope Observations

- `skills/design/scripts/plan-review-loop.sh:758-763` still tees the collector subprocess’s raw stderr to FD 2/4; production redaction for panel failures lives in `scripts/collect-agent-results.sh` §3.8 (`render_failed_agent_stderr_tail` / `larch_err`), not in the tee itself. The branch adds a regression test that asserts unredacted stub stderr reaches FD 2, which documents existing behavior rather than introducing a new emit path.

- `emit_kv SIDECAR_LOG=…` on implement failure paths (unchanged contract) still exposes a filesystem path to the full, unredacted sidecar; operators can read that file directly. This branch adds redacted `.stderr-tail` surfacing but does not narrow that older KV surface.

- Producer/consumer wiring otherwise consistently routes chat emission through `emit_failed_agent_stderr_tail_larch_err` on `${stem}.stderr-tail` artifacts (not raw `cat` of wrapper logs), honors empty-stem guards in `ship-pr.sh` and Step 5, and adds harness checks that synthetic `sk-ant-*` tokens are redacted in codex/cursor implement tails.
