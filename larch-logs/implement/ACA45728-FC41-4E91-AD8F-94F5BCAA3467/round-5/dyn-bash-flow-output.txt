Reviewing the branch diff and commit history for bash correctness issues.
### In-Scope Findings

- **correctness** `scripts/launch-cursor-implement.sh:325-333` — On agent failure (`LAUNCHER_EXIT != 0`), the launcher always calls `write_failed_agent_stderr_tail` with `_FAILURE_OUTPUT` defaulting to `$SIDECAR_LOG` whenever that file is non-empty, and only falls back to `${TRANSCRIPT_PATH}.diag` when the sidecar is empty. With `--capture-stdout-only`, `run-external-agent.sh` already writes `${TRANSCRIPT_PATH}.stderr-tail` from `.diag` (real agent stderr); `$SIDECAR_LOG` only receives the wrapper’s merged `2>&1` chatter (`> "$SIDECAR_LOG" 2>&1` at lines 307–307). That ordering can replace a good agent tail with wrapper-only text and drop the actionable stderr the #3227 path is meant to surface (the same file’s manifest-`bailed` block at 354–361 correctly prefers `.diag` first). **Suggested fix:** Mirror the bailed-manifest source order (prefer `${TRANSCRIPT_PATH}.diag`, then `$SIDECAR_LOG`), or skip the post-loop write when `[[ -s "${TRANSCRIPT_PATH}.stderr-tail" ]]` after `run-external-agent` has already produced a tail—matching the plan’s “no additional producer on the agent path” rule for cursor-implement.

- **correctness** `skills/design/scripts/plan-review-loop.sh:757-766` — The new `set +e` / `_collect_rc=$?` / `set -e` around the collect `$(…)` substitution stops `set -e` from aborting when `collect-agent-results.sh` exits non-zero (needed so stderr can tee to FD 2/4 while stdout is still captured), but `_collect_rc` is never read anywhere in the repo. If a real collector run exits non-zero with empty stdout (crash before records), the loop now continues with empty `_collect_out` instead of failing closed as it would have under `set -e` inside the substitution; downstream may treat that like a vacuous collect rather than `panel-failed`. **Suggested fix:** After capture, branch on `_collect_rc` (e.g. treat non-zero with no parseable records as collect failure / `panel-failed`, while still allowing non-zero when stdout contains failure records or when `-s "$_collect_err"` shows actionable stderr—the harness case at `skills/design/scripts/test-plan-review-loop.sh:2892-2912` emits stdout then `exit 1`).
