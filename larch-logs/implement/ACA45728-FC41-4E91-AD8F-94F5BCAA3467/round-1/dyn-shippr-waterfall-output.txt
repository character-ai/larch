Reviewing the branch diff and `ship-pr.sh` integration points for architecture issues.
### In-Scope Findings

- **architecture** `scripts/ship-pr.sh:2774-2836` — Recovery waterfall now parses `LAUNCHER_EXIT` from `launcher_stdout` and calls `_surface_ci_stderr_tail "$output"` when `tier_rc -ne 0`, `launcher_exit -ne 0`, or `${output}.stderr-tail` is non-empty, but tier advancement still keys only on `tier_rc` at `2779-2781`. CI launchers (`launch-codex-ci.sh`, `launch-cursor-ci.sh`) always `exit 0` and encode agent failure in stdout (`LAUNCHER_EXIT`), so the common failure shape is `tier_rc=0` with `launcher_exit≠0`: the tail is surfaced, then the function still runs the phase verifier (checks/OOS/create-pr/rebase) before `recovery_waterfall_paths_delta_revert` + `continue` at `2834-2836`. That diverges from `run_ci_fix_vendor` (`2088-2102`), which rolls back and tries the next tier immediately after a failed launcher. Operators now see a failed-agent tail followed by unrelated verifier work on a tier that already failed at the agent layer. **Suggested fix:** After surfacing on `launcher_exit -ne 0` or a non-empty `${output}.stderr-tail` (with `tier_rc=0`), call `recovery_waterfall_paths_delta_revert` and `continue` before detached-head/verify—matching the `tier_rc -ne 0` branch—unless a documented exception requires verify on agent failure.

- **architecture** `scripts/ship-pr.sh:2753-2777`, `scripts/test-ship-pr.sh:5995-6037` — Recovery waterfall’s new stdout capture (`launcher_stdout` per tier) and tri-condition surfacing gate are not covered by an integration harness case (existing `#3227` tests only exercise `_surface_ci_stderr_tail` and `run_lint_fix_loop_capture` in isolation). A regression that drops `LAUNCHER_EXIT` parsing, reads the wrong file, or surfaces with the wrong `$output` stem would not be caught while `run_ci_fix_vendor` tier-order tests continue to pass. **Suggested fix:** Add a `test-ship-pr.sh` case stubbing `launch-cursor-ci.sh` with `exit 0` + `LAUNCHER_EXIT=1`, a pre-seeded `${output}.stderr-tail`, and `run_recovery_waterfall` (or a minimal sourced wrapper), asserting the probe reaches caller stderr and that the waterfall advances to the next tier without invoking the verifier on the failed tier.
