### In-Scope Findings

- **correctness** `scripts/ship-pr.sh:114-119` — `_surface_ci_stderr_tail` re-sources `lib-failed-agent-stderr-tail.sh` on every call. That library’s idempotency guard uses `return 0` when `LARCH_FAILED_AGENT_STDERR_TAIL_LOADED` is already set (see `scripts/lib-failed-agent-stderr-tail.sh:7-9`). When the helper is invoked from a function—as it is here—the `return` exits `_surface_ci_stderr_tail` before `emit_failed_agent_stderr_tail_larch_err` runs. The first surfacing call in a `ship-pr.sh` process works; the second and later calls in the same process are silent no-ops. That breaks multi-tier paths such as `run_ci_fix_vendor` (`scripts/ship-pr.sh:2089`, `2100`, repeated per waterfall iteration) and `run_recovery_waterfall` (`scripts/ship-pr.sh:2776-2777`, one call per failed tier). Only the first failed tier’s tail can reach chat; later failures leave `${stem}.stderr-tail` on disk but never emit it. **Suggested fix:** Source `lib-failed-agent-stderr-tail.sh` once at `ship-pr.sh` startup (with a caller-side `[[ -z "${LARCH_FAILED_AGENT_STDERR_TAIL_LOADED:-}" ]]` guard if needed), and have `_surface_ci_stderr_tail` only call `emit_failed_agent_stderr_tail_larch_err "$stem" || true` without re-sourcing. Alternatively, change the library guard to skip re-definition without `return` when already loaded (e.g. wrap the body in `if [[ -z "${LARCH_FAILED_AGENT_STDERR_TAIL_LOADED:-}" ]]; then …; LARCH_FAILED_AGENT_STDERR_TAIL_LOADED=1; fi`), which matches the plan’s “source once” intent.

- **correctness** `scripts/launch-cursor-implement.sh:265-275` — Cursor auth preflight failures append diagnostics to `$SIDECAR_LOG` and exit with `LAUNCHER_EXIT=$PREFLIGHT_RC`, but unlike the new `MODEL_ARGS_RC` branch (`scripts/launch-cursor-implement.sh:243`) they never call `write_failed_agent_stderr_tail "$SIDECAR_LOG" "$TRANSCRIPT_PATH"`. `run-external-agent` does not run on this path, so `${TRANSCRIPT_PATH}.stderr-tail` is usually absent. `step2-implement.sh` only surfaces via `emit_failed_agent_stderr_tail_larch_err` in `emit_bailed()` (`skills/implement/scripts/step2-implement.sh:276`), which reads the tail file—not raw sidecar content—so preflight failures still miss the #3202 fenced tail in chat unless the operator opens `SIDECAR_LOG` from the KV line. **Suggested fix:** Add the same `write_failed_agent_stderr_tail "$SIDECAR_LOG" "$TRANSCRIPT_PATH" || true` immediately before the preflight early `exit 0`, mirroring the model-args branch.
