### Out-of-Scope Observations

- **Depth-bound tradeoff (pre-existing, now documented):** Activity deeper than five levels does not protect a session directory from deletion (`skills/cleanup/scripts/cleanup.sh:18-20`, `deep-session-freshness-probe-bounded` in `test-cleanup.sh`). Docs and `SECURITY.md` state this explicitly; it is intentional conservative disk reclamation, not a branch regression.

- **Asymmetric `/tmp` vs cache enumeration (pre-existing):** The cache pass lists all non-symlink top-level entries with no age pre-filter; the `/tmp` pass only considers top-level entries with `-mtime +N`. A `/tmp` directory whose top-level mtime was recently touched but whose contents are stale will never enter the removal loop, while a cache directory with the same shape would still be evaluated via `should_remove_by_age`. The branch’s new `stale-tmp-toplevel-with-fresh-deep-child-kept` case covers the happy-path retention path but not this “fresh top, stale inside” blind spot.

- **Top-level cache non-directories (pre-existing):** `should_remove_by_age` returns immediately for non-directories (`cleanup.sh:25`), so loose files under `larch/sessions/` are never removed. Updated docs correctly describe directory-oriented removal; this is not introduced by the branch.

The improved `write_stub_find_failure` stub (fail only on `-maxdepth 5`, not on enumeration paths) is a real harness correctness improvement.
