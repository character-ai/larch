### In-Scope Findings
- **correctness** `scripts/lib-larch-log.sh:448-475` — The refactor sets `found_any=true` after every successful `larch_log_publish_breadcrumbs_stage_file` call (exit 0), but `stage_file` also returns 0 on no-op paths (`[ -e "$f" ] || return 0` at 360, `[ -f "$f" ] || return 0` at 366). On `main`, `found_any` was only set after a file passed `[ -f "$f" ]` and redaction wrote into `staging_dir`; here, a glob match that is not a regular file at stage time (e.g. a directory named `foo.ndjson`) or a source that disappears between the loop’s `[ -e "$f" ]` and the helper’s checks still flips `found_any` without writing anything. If that is the only “match,” `larch_log_publish_breadcrumbs_swap` runs against an empty `staging_dir` and atomically replaces committed `larch-logs/.../breadcrumbs/` with an empty directory, wiping prior forensics. **Suggested fix:** Only set `found_any=true` when a file was actually staged—e.g. return a distinct skip code from `stage_file` (and set `found_any` only on “staged”), or restore `[ -f "$f" ] || continue` in both loops before calling the helper and have `stage_file` return non-zero only on real errors; optionally assert `[ -n "$(find "$staging_dir" -mindepth 1 -print -quit)" ]` before swap.

### Out-of-Scope Observations
- Existing harness cases such as `scripts/test-larch-log.sh:610-632` (“empty breadcrumb source”) remove `*.ndjson` files rather than leaving a non-regular `*.ndjson` path, so they would not catch the `found_any`/empty-swap regression above.
- `scripts/test-larch-log.sh:586-608` (“missing breadcrumb source”) still passes on this branch because with no `breadcrumbs/` dir and no quiet logs, both loops leave `found_any=false` and skip swap; that does not exercise the false-positive `found_any` path.
