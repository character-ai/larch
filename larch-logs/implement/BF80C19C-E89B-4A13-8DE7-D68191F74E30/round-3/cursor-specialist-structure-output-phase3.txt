### In-Scope Findings

1. - **correctness** `skills/design/scripts/design-route.sh:264` — Archival reject message text is inaccurate. The regex `LARCH_TITLE_ARCHIVAL_REPORT_REGEX_BASH='^\[.*[Rr]eport\] '` in `lib-title-eligibility.sh` requires "Report" to be *inside* the brackets (e.g., `[Research Report] Foo`), but the new message says `` `[...] Report` `` which implies "Report" comes *after* the closing bracket. The old SKILL.md message `` `[... Report]` `` was accurate. Operators who see the new message and try to rename their title will be misled about which bracket structure to avoid. **Suggested fix:** Change the message back to `` `[... Report]` `` (closing bracket after Report, matching the regex pattern).

2. - **code-quality** `skills/design/scripts/design-route.sh:235,252` — `_render_rc` is declared in `render_cancel_summary` locals and immediately captured from `$?` (line 252), but the function always unconditionally `return 0` and never reads `_render_rc`. This is a dead variable (shellcheck SC2034). It obscures intent — a reader would reasonably assume the captured value influences some branch, but there is no such branch. **Suggested fix:** Remove the `_render_rc=0` from the `local` declaration and the `_render_rc=$?` assignment, replacing the capture with a comment like `# render failure tolerated; exit 0 regardless` to make the intent explicit.

3. - **code-quality** `skills/design/scripts/design-route.sh:191,221-227` — `ROUTE_KVS` is a script-global array that creates an implicit sequencing contract: `route_emit_stdout_and_exit` silently iterates over whatever `ROUTE_KVS` contains at call time, which is correct only when `route_write_result_env` (which calls `route_build_kvs`) was called first. The two wrappers `emit_route_result` and `emit_cancel_route_result` enforce this ordering, but `route_emit_stdout_and_exit` has no defensive guard and produces empty or stale output if called standalone. **Suggested fix:** Add a brief comment on `ROUTE_KVS` noting it is always populated by `route_write_result_env` before use, or assert `[[ ${#ROUTE_KVS[@]} -gt 0 ]]` at the top of `route_emit_stdout_and_exit` to make the precondition explicit.

4. - **code-quality** `skills/design/scripts/design-route.sh:257-278` — `route_emit_cancel_side_effects` has a silent no-op fallthrough for any `ROUTE` value that is not `cancel-title-filter` or `cancel-reentry-guard`. If a future cancel route calls `emit_cancel_route_result`, it receives no reject banner and no `render-final-summary.sh` invocation — silently. **Suggested fix:** Add a `*) fail "route_emit_cancel_side_effects: unexpected ROUTE=${ROUTE}"` arm to the `case` to fail loudly if called with an unhandled cancel route.
