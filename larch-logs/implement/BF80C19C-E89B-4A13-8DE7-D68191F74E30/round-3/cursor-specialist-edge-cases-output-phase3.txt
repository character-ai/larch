## Edge-Case / Failure-Recovery Review — Round II Phase 5

### Finding 1 — `_render_rc` is captured but never acted on in `render_cancel_summary` (nit / dead code)

**Location:** `skills/design/scripts/design-route.sh:234–254`

```bash
render_cancel_summary() {
    local outcome="$1" mode="$2" _render_rc=0
    set +e
    if [ ... ]; then
        ...render-final-summary.sh... >/dev/null 2>&4
    else
        ...render-final-summary.sh... >/dev/null
    fi
    _render_rc=$?       # <- captured
    set -e
    return 0            # <- but always 0; _render_rc is dead
}
```

`_render_rc` is declared `local`, receives the render exit code, and then the function unconditionally returns `0`. The captured value is never examined here or by the caller (`route_emit_cancel_side_effects` ignores the return). The intent — tolerate render failures — is sound and matches the plan, but the `_render_rc` variable is semantically dead. A reader may assume the code was meant to branch on it and adds a handler, inadvertently changing the "always tolerate" invariant. The function could be simplified to drop the capture entirely, or replaced with `render-final-summary.sh ... || true` if the `set +e`/`set -e` dance is not needed for other reasons.

### Finding 2 — `ROUTE_KVS` global-array state coupling between write and emit (latent / architecture)

**Location:** `skills/design/scripts/design-route.sh:191–280`

The old `emit_route_result` used a `local -a kvs=()` array. The refactor promotes `ROUTE_KVS` to a module-level global:

```bash
ROUTE_KVS=()          # line 191: module-scope init

route_build_kvs()  { ROUTE_KVS=(...) }          # populates
route_write_result_env() { route_build_kvs; phase_driver_write_result_env ... "${ROUTE_KVS[@]}" }
route_emit_stdout_and_exit() { for kv in "${ROUTE_KVS[@]}"; do emit_kv ...; done; exit 0 }

emit_cancel_route_result() {
    route_write_result_env           # sets ROUTE_KVS, writes result-env
    route_emit_cancel_side_effects   # runs between write and emit
    route_emit_stdout_and_exit       # reads ROUTE_KVS
}
```

The result-env (the durable file) and the stdout KV stream are derived from the **same** `ROUTE_KVS` snapshot taken by `route_build_kvs`. Correctness depends on `ROUTE_KVS` not being mutated between `route_write_result_env` and `route_emit_stdout_and_exit`. Currently this holds because `route_emit_cancel_side_effects` only calls `larch_err`/`larch_errf` (stderr) and `render_cancel_summary` (external process with `>/dev/null`). But the invariant is nowhere enforced — `ROUTE_KVS` is a writable global visible to any function called from `route_emit_cancel_side_effects`. A future contributor adding a diagnostic WARN line into that side-effects function (e.g., `ROUTE_KVS+=("WARN=render-failed")`) would push a KV into stdout that was never written to the result-env, causing silent file-vs-stdout divergence.

The original `local -a kvs` was safe by construction; the new shape requires a discipline that is not documented or guarded.

### Finding 3 — Reentry-guard KV parse uses word-splitting; sibling parse uses safe `while read` (correctness / edge-case)

**Location:** `skills/design/scripts/design-route.sh:400–407`

```bash
for _rkv in $_reentry_out; do          # word-split, unquoted
    case "$_rkv" in
        MARKER_HIT=*) ...
        MARKER_AGE=*) ...
        MARKER_TTL=*) ...
    esac
done
```

Compare with the pause-load KV parser at line 300:

```bash
while IFS= read -r _pline || [[ -n "$_pline" ]]; do
    _pkey="${_pline%%=*}"
    ...
done <<<"${_pause_out:-}"
```

The word-split form is fragile for two reasons:

1. **Embedded whitespace:** if `_reentry_out` ever contains a value with spaces (e.g., a path in a future `MARKER_PATH=...` KV), the `for` loop splits it into two tokens and the case match fails silently, leaving the variable at its default.
2. **Newline-embedded values:** word splitting on unquoted `$var` collapses embedded newlines to IFS whitespace. If `design_reentry_marker_hit` emits multi-word values, the parser silently truncates them.

In this change the three parsed KVs (`MARKER_HIT`, `MARKER_AGE`, `MARKER_TTL`) are all numeric or boolean single-words, so the current behavior is correct. But the inconsistency with the safe `while read` idiom used everywhere else in the file is a maintenance risk: if a future KV is added to `design_reentry_marker_hit`'s output with a string value (e.g., `MARKER_PATH=...`), it would silently fail to parse.

### Finding 4 — `bare_devnull_count >= 2` is a count floor, not a per-branch structural assertion (test coverage gap)

**Location:** `scripts/test-design-structure.sh:1299–1302`

```bash
bare_devnull_count=$(grep -cE '>/dev/null$' "$DESIGN_ROUTE_SH" || true)
if (( bare_devnull_count < 2 )); then
  fail "(FINDING_18) design-route.sh non-quiet resume/render branches must redirect stdout to /dev/null"
fi
```

The code currently has exactly two `>/dev/null$` lines — one in `render_cancel_summary`'s non-quiet branch and one in the resume path's non-quiet branch. The test catches a regression that removes both. However, the count-floor shape has a blind spot: if a future change adds a third `>/dev/null` line for an unrelated reason while accidentally deleting one of the two required ones, the count stays ≥ 2 and CI stays green while the quiet-bridge contract is violated for one of the two operations. The sister assertion for `>/dev/null 2>&4` (line 1298) is a plain presence check with the same weakness.

A tighter pin would be:
```bash
[[ $(grep -cE '>/dev/null$' "$DESIGN_ROUTE_SH") -eq 2 ]] || fail ...
```
This fails if the count moves in either direction without an explicit test update.

### Finding 5 — `DESIGN_REENTRY_MARKER_PATH` empty-path degradation in `larch_errf` (latent / pre-existing)

**Location:** `skills/design/scripts/design-route.sh:410, 269–270`

```bash
DESIGN_REENTRY_MARKER_PATH="$(design_reentry_marker_path "$ISSUE" "$CLAUDE_PID" 2>/dev/null || true)"
...
larch_errf '...delete %s to override.**\n' \
    "$ISSUE" "$CLAUDE_PID" "$MARKER_AGE" "$MARKER_TTL" "$MARKER_REMAINING" "$DESIGN_REENTRY_MARKER_PATH"
```

If `design_reentry_marker_path` fails, `|| true` silences it and `DESIGN_REENTRY_MARKER_PATH` is empty. The banner then reads "…delete  to override." — a blank where the path should be. This is pre-existing behavior (the old SKILL.md had the same `${DESIGN_REENTRY_MARKER_PATH}` reference without any guards), so the change does not introduce a regression. The move to `larch_errf` with `%s` at least makes the format-argument boundary explicit and avoids accidental format-string injection. Flagging it here because the move from SKILL.md to the driver makes the path less visible to future editors; a non-empty guard or fallback literal (e.g., `${DESIGN_REENTRY_MARKER_PATH:-<unknown-path>}`) would eliminate the blank.
