2. **architecture** `skills/design/scripts/design-route.sh:258-275` — `route_emit_cancel_side_effects` references `$MARKER_REMAINING` and `$SUMMARY_MODE_STRING` (used in the `cancel-reentry-guard` arm of its `case`) without any module-level initialisation. All other module-level routing state (`ROUTE`, `MARKER_AGE`, `MARKER_TTL`, `DESIGN_REENTRY_MARKER_PATH`, etc.) is declared at lines 173–187, but these two variables are not. Under `set -u`, a future caller that invokes `emit_cancel_route_result` with `ROUTE=cancel-reentry-guard` without having first entered the re-entry guard block gets an "unbound variable" crash rather than a diagnostic message. The current call sites are safe (the guard block always sets them first), but the invariant is implicit and fragile. **Suggested fix:** Add `MARKER_REMAINING=0` and `SUMMARY_MODE_STRING=N/A` to the module-level initialisation block at lines 173–187 so the function is self-contained regardless of call site.

The result-env-before-side-effects ordering is the key safety invariant in the design (the plan enumerates it as the "critical hazard" mitigation): writing the contract file must precede any GitHub upsert or reject banner. A reorder would pass all current harness checks while silently breaking the invariant. The plan explicitly states "tests pin order" for this relationship, but no line-number comparison was added. **Suggested fix:** Add an ordering check analogous to the existing `route_resume_line`/`route_title_line`/`route_reentry_line` comparisons — extract the line number of the first call-site occurrence of `route_write_result_env` and `route_emit_cancel_side_effects` (excluding their definition lines) and assert the write-env line is lower.
