### In-Scope Findings

1. - **code-quality** `skills/design/scripts/design-route.sh:252-254` — `render_cancel_summary` contains a dead no-op block: `if [[ "$_render_rc" -ne 0 ]]; then :; fi`. Since `render_cancel_summary` always returns 0 and the no-op branch does nothing, this block has no effect and could mislead readers into expecting a diagnostic or early-return on render failure. **Suggested fix:** Remove lines 252-254, or replace with a `larch_err`/`larch_warn` emit if silent render failure should be surfaced (consistent with the plan's "tolerate non-zero render rc" intent).

2. - **correctness** `skills/design/scripts/design-route.sh:271-272` — `MARKER_REMAINING` and `SUMMARY_MODE_STRING` are accessed inside `route_emit_cancel_side_effects()` for the `cancel-reentry-guard` branch but are not declared or initialized at script scope (only set locally in the `# 3. Re-entry guard` block before calling `emit_cancel_route_result`). Under `set -euo pipefail`, any future call path that invokes `emit_cancel_route_result` for `ROUTE=cancel-reentry-guard` without first setting these globals would fail with "unbound variable". Currently this is safe because the only call site (lines ~408-421) always sets both before the call. **Suggested fix:** Initialize `MARKER_REMAINING=""` and `SUMMARY_MODE_STRING=""` alongside the other top-level variable declarations (around line 180) to make the dependency explicit.

3. - **correctness** `scripts/test-design-structure.sh:380-381` — Check 26 pin was weakened from the old two-form check (`delete <DESIGN_REENTRY_MARKER_PATH> to override.` / `delete ${DESIGN_REENTRY_MARKER_PATH} to override.` in SKILL.md) to just `delete %s to override.**` in `design-route.sh`. The new pin verifies a format-string placeholder exists, but does **not** verify that `$DESIGN_REENTRY_MARKER_PATH` (or any equivalent) is actually passed as the corresponding positional argument to `larch_errf`. A future edit that reorders or drops an argument from the `larch_errf` call at line 271 would silently satisfy the pin while producing the wrong path in the operator message. Concrete failing scenario: if `"$DESIGN_REENTRY_MARKER_PATH"` at line 271 were accidentally replaced with `""`, the pin would still pass but the operator override instruction would show a blank path. **Suggested fix:** Extend the pin to also grep for `"$DESIGN_REENTRY_MARKER_PATH"` in proximity to the `larch_errf` call, e.g. `grep -Fq '"$DESIGN_REENTRY_MARKER_PATH"' "$DESIGN_ROUTE_SH"`.
