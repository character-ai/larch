### FINDING_8: `MARKER_AGE` / `MARKER_TTL` not validated as integers before arithmetic expansion
- **Reviewer(s)**: cursor-specialist-security-output.txt
- **Severity**: latent
- **Concern**: `skills/design/scripts/design-route.sh` lines ~1310-1312: `MARKER_AGE` and `MARKER_TTL` are default-guarded against empty strings (`[[ -n "$MARKER_AGE" ]] || MARKER_AGE=0`) but not against non-integer values before use in arithmetic expansion `$((MARKER_TTL - MARKER_AGE))`. Under `set -e`, a non-numeric value (e.g., `MARKER_AGE=stale` from an unexpected `design_reentry_marker_hit` output) would abort the driver with a cryptic bash error rather than a clean diagnostic. The data source is controlled (filesystem timestamps), but the existing guard covers only the empty-string case, not the type case.
- **Suggested revisions (informational for voters; coder decides)**:
  - From cursor-specialist-security-output.txt: Add `[[ "$MARKER_AGE" =~ ^[0-9]+$ ]] || MARKER_AGE=0` (and same for `MARKER_TTL`) to fully harden the guard against unexpected reentry-guard output.
