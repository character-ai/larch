### In-Scope Findings

1. **Latent** (`security`) [scripts/sessionstart-health.sh:31](scripts/sessionstart-health.sh): `INPUT=$(cat 2>/dev/null)` buffers the entire SessionStart stdin with no size cap. A buggy or hostile caller could supply an extremely large payload and grow the hook process memory during `SessionStart`. 2. **Latent** (`risk-integration`) [scripts/sessionstart-health.sh:129-131](scripts/sessionstart-health.sh): `LARCH_TOKEN_SESSION_ID` is exported when `session_id` is non-empty but is never explicitly unset when `session_id` is empty or missing. If the hook process inherits a stale `LARCH_TOKEN_SESSION_ID` from the parent environment, `resolve_implement_tmpdir` may apply the wrong session filter (wrong tmpdir or none), so boundary advisories can miss the real run or target the wrong session. At the start of the boundary block, `unset LARCH_TOKEN_SESSION_ID` (or export empty) when `SID` is empty, then export only when bound.
