### In-Scope Findings

1. **Latent** (`risk-integration`) — [`scripts/sessionstart-health.sh:129-131`](scripts/sessionstart-health.sh): The hook only runs `export LARCH_TOKEN_SESSION_ID="$SID"` when `SID` is non-empty; it never clears a **pre-existing** `LARCH_TOKEN_SESSION_ID` from the process environment when the SessionStart payload omits or nulls `session_id`. [`lib-resolve-implement-tmpdir.sh:54-67`](skills/implement/scripts/lib-resolve-implement-tmpdir.sh) then applies session binding whenever that variable is set, so a stale inherited value can force the resolver down the strict `SESSION_ID` match path and return **no** tmpdir even though a valid TTL-bound run exists—**boundary advisories fail open and disappear** while the tmpdir is still pending. **Suggested fix:** `unset LARCH_TOKEN_SESSION_ID` (or export empty) immediately before the conditional export so “missing `session_id` in JSON” reliably means TTL mode as documented.

2. **Nit** (`risk-integration`) — [`scripts/test-sessionstart-health.sh:375-445`](scripts/test-sessionstart-health.sh): The implementation plan’s own edge case calls out that **all three** boundary conditions can append in one advisory, but the harness never asserts a single run where `manifest.env`, `review-round-summary.md`, and `.bump-version-armed` (with appropriate sentinels absent) all fire together—so a future regression that drops concatenation, ordering, or `append_msg` spacing would not be caught. **Suggested fix:** Add one fixture tmpdir + `run_with_stdin` assertion that the decoded `additionalContext` contains all three “post-/…” substrings.
