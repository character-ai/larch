### In-Scope Findings

1. **Latent** (`risk-integration`, `plan`) [scripts/test-sessionstart-health.sh](scripts/test-sessionstart-health.sh) (new boundary cases): The implementation plan’s edge case “all three boundaries can fire simultaneously (MSG concatenated)” has no regression test. Only each boundary (and suppressions) is exercised in isolation, so a bad interaction (ordering, short-circuit, or truncation) in `append_msg` / single `jq --arg ctx` emission would not be caught. **Suggested fix:** Add one fixture tmpdir with `design-export/manifest.env`, `review-round-summary.md`, and `.bump-version-armed` (and no sentinels / no `postbump-state.sh`) and assert `additionalContext` contains all three “post-/design”, “post-/review”, and “post-/bump-version” substrings in one JSON payload.

2. **Latent** (`correctness`) [scripts/sessionstart-health.sh](scripts/sessionstart-health.sh) (boundary block after `resolve_implement_tmpdir` sourcing): The hook runs `[[ -n "$SID" ]] && export LARCH_TOKEN_SESSION_ID="$SID"` and never clears `LARCH_TOKEN_SESSION_ID` when `session_id` is absent from stdin. If the hook process inherits a stale `LARCH_TOKEN_SESSION_ID` from the parent environment while the SessionStart JSON omits `session_id`, `lib-resolve-implement-tmpdir.sh` applies session binding and may skip the real tmpdir or bind the wrong session—advisory fails open (no prompt) even though a pending boundary exists. **Suggested fix:** Before calling `resolve_implement_tmpdir`, `unset LARCH_TOKEN_SESSION_ID` (or `export LARCH_TOKEN_SESSION_ID="${SID:-}"` when you intend empty to mean “no session binding”) so absent `session_id` cannot pick up unrelated env.

3. **Nit** (`risk-integration`, doc/test matrix for merge side) [scripts/merge-pr.md:48](scripts/merge-pr.md): Step 4 still states that “local/remote OID mismatch” always “fail closed via `MERGE_RESULT=error`”, but the new flush-only OID recovery path can clear a local-ahead OID mismatch and continue. **Concrete scenario:** Someone uses step 4 as the exhaustive list of hard failures and misses that flush-only divergence is recoverable. **Suggested fix:** Qualify “OID mismatch” (e.g. non-recoverable / excluding flush-only recovery) or cross-reference the “Flush-commit OID recovery” subsection.
