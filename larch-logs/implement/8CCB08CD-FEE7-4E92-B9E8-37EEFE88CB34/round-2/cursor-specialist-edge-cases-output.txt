### In-Scope Findings

1. **Important** (`risk-integration`) — [`scripts/merge-pr.sh:166-180`](scripts/merge-pr.sh): Flush-only recovery treats every commit in `${PR_HEAD_OID}..HEAD` as safe when **only** `git log --format='%s'` lines match `^chore(larch-logs): flush `; it does not verify that those commits touch only `larch-logs/` (or are otherwise no-op). **Concrete scenario:** a local commit whose subject line matches that prefix but that still changes product code (mislabeled commit, joke subject, or deliberate spoof) satisfies `FLUSH_COUNT`, the `grep -qv` filter, and `merge-base --is-ancestor`, so `_flush_recoverable` becomes true and the script runs `git-force-push.sh`—widening the merge path beyond true log-only flushes. **Suggested fix:** tighten the predicate (e.g. require a fixed subject template from `larch-log-flush.sh`, and/or add a path-scoped diffstat guard so non-`larch-logs/**` changes keep the original OID refusal).

2. **Latent** (`risk-integration`) — [`scripts/sessionstart-health.sh:116-136`](scripts/sessionstart-health.sh): Boundary advisories depend on `resolve_implement_tmpdir` matching `CLONE_PATH` in `.larch-keepalive` to `HOOK_CWD` by **exact string equality** (see [`skills/implement/scripts/lib-resolve-implement-tmpdir.sh:45-50`](skills/implement/scripts/lib-resolve-implement-tmpdir.sh)). **Concrete scenario:** SessionStart `cwd` is normalized (symlink-resolved or different trailing slash) relative to what `/implement` wrote into keepalive; resolution returns empty and **no** boundary advisory is injected after a real halt—same class of miss as other hooks unless paths are aligned. **Suggested fix:** normalize both sides to a canonical form before compare (e.g. `pwd -P` policy documented and applied consistently when writing and reading `CLONE_PATH`), or document the requirement for operators.

3. **Nit** (`code-quality`) — [`scripts/sessionstart-health.sh:116-118`](scripts/sessionstart-health.sh): `HOOK_CWD` and `SID` are extracted with two separate `jq` passes over the same stdin payload. **Impact:** redundant work only; no functional bug. **Suggested fix:** single `jq -r '[.cwd,.session_id] | @tsv'` (or one object) and split once.
