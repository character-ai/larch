Reviewing KV-parse safety in the diff and related files.
### In-Scope Findings

- **correctness** `skills/design/SKILL.md:250-251,261-262` — WARN/ERROR de-duplication uses a substring test on a space-padded join of prior messages (`[[ " ${_route_warn_lines[*]} " != *" $_value "* ]]` and the same for `_route_error_lines`). That is not equality: any later `_value` that appears as a space-bounded substring of an earlier message is treated as already seen and is not printed. Example: after `ERROR=pause-load-invalid-step`, a distinct `ERROR=invalid-step` (or any shorter token contained in an earlier line) is suppressed even though the strings differ. Multi-word pause-load or driver messages make this easier. Operators can miss real ERROR/WARN breadcrumbs on `LOAD_OK=false` fallthrough and other paths where file-first and stdout merge both run. **Suggested fix:** De-dupe with exact membership only (e.g. loop `"${_route_warn_lines[@]}"` and `[[ "$_w" == "$_value" ]]`, or an associative array keyed by the full message). Keep `=${_line#*=}` splitting so values may contain `=`; do not use substring globbing on joined text.

### Out-of-Scope Observations

- **`printf -v "$_key"` / shell-internals overwrite:** Step 0b file-first and stdout-merge loops only call `printf -v` inside explicit `case` arms for routing keys (`ROUTE`, `INIT_STATUS`, etc.). A tampered `.design-route-result.env` line like `PATH=evil` or `BASH_ENV=evil` is ignored (no matching arm). This matches the Step 3 `run-step3-review.sh` handoff pattern and is not worsened by the branch.

- **`phase_driver_write_result_env` has no allowlist or newline checks on write** (`skills/design/scripts/lib-phase-driver.sh:40-56`): Only `phase_driver_read_result_env` filters keys/values; the orchestrator deliberately does not call it. Safety relies on the driver only writing known KVs and on the SKILL `case` filter at read time — same tradeoff as Step 3.

- **Values containing `=`:** `${_line#*=}` / `${_pline#*=}` preserve everything after the first `=` in SKILL.md, `design-route.sh:214-215`, and init handoff loops; no defect found there.

- **`design-route.sh:213-225` pause-load parse:** Uses a fixed `case` on `_pkey` (no dynamic `printf -v`); only allowlisted pause-load keys are applied. Driver-authored ERROR tokens are single-token strings today; the SKILL dedup logic is still the main correctness risk for surfaced breadcrumbs.

- **Init handoff (`skills/design/SKILL.md:385-399`):** WARN lines are printed without substring dedup; duplicate file+stdout WARNs may appear twice — inconsistent with route but lower severity and not part of the scout’s dedup concern.
