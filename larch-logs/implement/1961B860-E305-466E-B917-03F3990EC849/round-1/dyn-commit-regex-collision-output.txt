Reviewing branch changes for commit-regex collision risks: reading the diff and relevant scripts.
### In-Scope Findings

- **risk-integration** `scripts/ship-pr.sh:2856-2894` — The new pre-rebase fixup commit is inserted immediately before `drop-bump-commit.sh --max-depth 20`, which always consumes one walk slot from HEAD. `drop-bump-commit.sh` only inspects `HEAD~0` … `HEAD~19` (see `scripts/drop-bump-commit.sh:99-111`). If the real bump commit already sits at `HEAD~19` when the dirty-tree guard fires, the fixup lands at `HEAD~0` and pushes that bump to `HEAD~20`, outside the window. `drop-bump-commit.sh` then emits `WARN: no bump commit found within 20 commits` and `DROPPED=false`, and `drop_bump_no_matching_commit` treats that as a benign no-op (`scripts/ship-pr.sh:770-773`, `2885-2886`), so `run_rebase_rebump` continues without dropping the stale bump—the same silent stale-bump class the `DROPPED=false` stall was meant to prevent (#2852). Before this change, the same dirty-tree state would have hit Guard 1 and stalled instead. **Suggested fix:** After a successful fixup commit, call `drop-bump-commit.sh` with `--max-depth 21` (or bump the default for this call site only when a fixup was just created), or skip `HEAD` in the drop walk when its subject matches the known fixup pattern (`chore: pre-rebase working-tree fixup (#3209)`), so the bump search depth is not reduced by the fixup layer.

### Out-of-Scope Observations

**Commit-subject regex collision (scout checklist):** No false-positive risk found for the new messages against the drop helpers. `drop-bump-commit.sh` uses anchored `^Bump version to [0-9]+\.[0-9]+\.[0-9]+$` (`scripts/drop-bump-commit.sh:106`); `drop-changelog-commit.sh` uses exact equality to `Update CHANGELOG for $VERSION` (`scripts/drop-changelog-commit.sh:93-102`). Neither `chore: pre-rebase working-tree fixup (#3209)` nor `Address code review feedback (round N) — follow-up` matches those patterns. `classify-bump.sh` uses the same anchored bump regex and only treats `Update CHANGELOG for …` and `chore(larch-logs): …` as transparent (`classify-bump.sh:93-96`); the new subjects are not bump-shaped.

**`rebump_dirty_tracked_fixup` fixture:** `sentinel-fix.txt` is created and committed in `make_repo` (`scripts/test-ship-pr.sh:328-330`) before the test appends dirty residue (`2530`), so `git add -u` stages it and the case exercises the intended dirty-tracked path, not a no-op.

**Option B staging scope:** Option B’s follow-up uses `git add -A` while Option A uses `git add -u`; that can commit new untracked files in round mode but is outside the commit-regex / drop-integration focus here.
