### Out-of-Scope Observations

**`scripts/ship-pr.sh` error mode matches Option A `rc=$?` capture.** The script deliberately omits `set -e` (lines 4–7) and documents explicit `rc=$?` handling for helpers. The new pre-rebase block at `2856–2869` follows the same pattern as the CI-fix staging path at `1801–1813`: a failing `git add -u` leaves `rc` non-zero, records a Warning, skips the `elif ! git diff --cached --quiet` commit branch, and execution continues to `drop-bump-commit.sh` at `2877+`. With no errexit, `rc=$?` always runs after `git add -u`; `pipefail` does not apply because the redirect is not a pipeline.

**`skills/review-and-fix/scripts/review-and-fix.sh` Option B is safe under `set -euo pipefail`.** The follow-up at `461–472` uses `if git add -A … && git-commit.sh …; then … else … fi`. Commands in the `if`/`elif` test are exempt from errexit, so a failed add or commit takes the `else` path instead of aborting. That matches the guarded primary round commit at `438–459`. Both orchestrator call sites wrap the function with `set +e` / `coder_rc=$?` / `set -e` (`913–917`, `1135–1138`), so errexit is already off during `apply_findings_with_coder`; the condition list is still the right pattern if the function is ever called without that wrapper.

**Plan vs acceptance wording (not an rc-capture defect).** Acceptance text says round mode must not return `CODER_STATUS=applied` with uncommitted tracked changes, but failure mode 2 and the implementation warn and continue (still emitting `applied` with a possibly stale `CODER_COMMIT_SHA` when the one-shot follow-up fails). That is intentional defense-in-depth with Option A as backstop, not a silent break of the `rc=$?` / fall-through contract.
