### In-Scope Findings

- **correctness** `scripts/test-ship-pr.sh:2661` — `rebump_fixup_commit_fail_stalls` only checks that `ship-pr.sh` exits `4`, which matches `exit_stall`’s hard-coded `exit 4` in `scripts/ship-pr.sh:1039-1042`, but the same exit code is used for every stall in `ci-initial` (checks, vendor exhaustion, drop-false, detached-head, etc.). The fixture does not assert `STALL_STEP=10` (the step token used when `drop-bump-commit.sh` returns `DROPPED=false` and `drop_bump_no_matching_commit` is false at `scripts/ship-pr.sh:2892-2894`), `STALL_TRACKING=true`, or fail-log text such as Guard 1’s `uncommitted tracked changes` vs the generic `run_rebase_rebump: drop-bump-commit returned DROPPED=false` line. A regression that stalled earlier (or later) with another `exit_stall` could still satisfy this test. **Suggested fix:** After the run, add `assert_state_line` for `STALL_STEP=10` and `EXIT_CODE=4`, and grep `$tmp/stdout-rebump-fixup-fail` or a captured fail file for `uncommitted tracked changes` / `drop-bump-commit.sh DROPPED=false` so the case uniquely pins fixup failure → dirty tree → Guard 1 stall, not an unrelated stall.

### Out-of-Scope Observations

- **Exit code 4 vs Guard 1:** Confirmed aligned — `exit_stall` always exits `4`; the `DROPPED=false` + not-`drop_bump_no_matching_commit` path calls `exit_stall 10` for `ci-initial`, which is what a dirty tree after a failed pre-rebase fixup should hit.
- **`rebump_fixup_commit_fail_stalls` apply-bump path:** The stub `apply-bump.sh` uses plain `git commit`, not the failing `git-commit.sh` stub; only the pre-rebase fixup message is forced to fail. That avoids a false stall during re-bump and is appropriate for this scenario.
- **`work_hook_residue`:** Stamp-based one-shot hook (`scripts/test-review-and-fix.sh:372-377`) correctly models first-commit residue; `CODER_COMMIT_SHA=${follow_sha}` with `follow_sha=$(git rev-parse HEAD)` and `primary_sha=HEAD~1` correctly requires the follow-up SHA, not the primary round commit (`410`).
