### In-Scope Findings
- **correctness** `scripts/ship-pr.sh:2856-2869` — The new pre-rebase fixup block uses bare `git add -u` and `git-commit.sh` followed by `rc=$?`, but `ship-pr.sh` is not errexit-free for the whole run: after `run_pr_prep_phase` it does `set -e` at line 1503 and never turns it off before `run_rebase_rebump`. With errexit on, a non-zero `git add -u` or `git-commit.sh` exits the script immediately, so `rc=$?`, `record_failure`, and the intended fall-through to `drop-bump-commit.sh` never run. That breaks the documented best-effort behavior and can abort with an unexpected exit code instead of the existing `DROPPED=false` stall path; offline tests do not catch this because each `ship-pr.sh` invocation starts without `set -e`. **Suggested fix:** Use the same errexit-safe capture pattern as `git add -A` at line 1106 (`rc=0; git add -u >"$fail_file" 2>&1 || rc=$?` and the same for `git-commit.sh`), or wrap only this block with `set +e` / restore errexit around both git calls.
