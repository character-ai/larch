### In-Scope Findings

- **correctness** `scripts/test-ship-pr.sh:2663-2674` — The `rebump_fixup_commit_fail_stalls` case correctly expects exit **4** (`exit_stall` → `EXIT_CODE=4`, `STALL_STEP=10` at `scripts/ship-pr.sh:1039-1042`), and that exit is reachable with this fixture: after the fixup stub fails, the tree stays dirty, so `drop-bump-commit.sh` hits **Guard 1** before the bump walk (`scripts/drop-bump-commit.sh:85-94`, before `113-116`). `drop_bump_no_matching_commit` only matches `WARN: no bump commit found within` (`scripts/ship-pr.sh:770-772`), not the Guard-1 message, so the stall branch runs even though there is no bump commit on the branch. The follow-on grep block is weaker: it searches only stdout and the **first** `ship-pr-fail-rebase-*.log` (the `refresh-run-logs.sh` stub capture from `_install_rebump_dep_stubs`, `scripts/test-ship-pr.sh:488-490`), while `git-commit.sh (pre-rebase fixup)` is recorded via `record_failure` into `execution-issues.md` (stub at `207-229`), Guard-1 text sits in a later drop-bump capture, and the stall line is written when that later file is overwritten (`scripts/ship-pr.sh:2896-2898`). The case can fail the “pins fixup failure then dirty-tree Guard 1 stall” `ok` even when exit 4 and stall state are correct. **Suggested fix:** Drop the fragile dual-grep or scan all `$tmp/ship-pr-fail-rebase-*.log` (and/or `$tmp/execution-issues.md`); keep `assert_rc 4`, `STALL_STEP=10`, `EXIT_CODE=4`, and optionally stdout `⛔ ship-pr: stalled at step 10`.
