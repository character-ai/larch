### In-Scope Findings

- **correctness** `scripts/ship-pr.sh:2856-2868` — The pre-rebase fixup uses `if [ "$rc" -ne 0 ]; then … elif ! git diff --cached --quiet`, so a failed `git add -u` skips the commit attempt even when the index already holds staged tracked changes (the plan’s “index dirty, worktree clean” case). That weakens the intended best-effort behavior: a transient `git add -u` failure can leave staged-only dirt and still hit `drop-bump-commit.sh` Guard 1. **Suggested fix:** Match the CI-fix pattern at `scripts/ship-pr.sh:1875-1880` and the local `ship_pr_pre_rebase_fixup_pass` helper: record a warning on `git add -u` failure, then always try `git-commit.sh` when `git diff --cached` is non-empty.

- **correctness** `scripts/ship-pr.sh:2856-2868` — Option A stages with `git add -u` but never runs submodule-path revert before staging. The primary round commit in `review-and-fix.sh` reverts submodule violations first; if tracked porcelain at rebase time is a dirty submodule gitlink (or path under a submodule root), the fixup can commit that state into `chore: pre-rebase working-tree fixup (#3209)`. **Suggested fix:** Reuse the same submodule revert helper pattern as `post_dispatch_submodule_revert` / uncommitted `ship_pr_revert_submodule_dirty_paths` before `git add -u`.

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:461-472` — The follow-up path runs `git add -A` without calling `post_dispatch_submodule_revert` again. The primary commit runs revert-then-`git add -A`; if tracked residue is submodule-related (or a hook re-touches a submodule path), `git add -A` can re-stage content the revert step deliberately removed. **Suggested fix:** Call `post_dispatch_submodule_revert` before follow-up staging; on `revert_count > 0`, return `submodule-violation` as on the primary path (as in the uncommitted working-tree version at `461-495`).

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:469-472` — After the one-shot follow-up, tracked porcelain may remain dirty, but the function still emits `CODER_STATUS=applied` and returns `0`. That conflicts with the stated acceptance criterion that round mode must not return `applied` with uncommitted tracked changes, and it allows `ship-pr` to proceed with a dirty tree until Option A (if it works). **Suggested fix:** Fail closed: `CODER_STATUS=failed`, `return 2`, when `git status --porcelain --untracked-files=no` is still non-empty after follow-up (as in the uncommitted working-tree block at `498-508`).

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:462` — The residue trigger uses `--untracked-files=no` (tracked-only), but follow-up staging uses `git add -A`, which also stages untracked paths whenever both tracked residue and untracked files exist (e.g. coder artifacts plus hook-dirty tracked file). That is broader than Guard 1 / Option A’s tracked-only scope and can pull unrelated files into the round follow-up commit. **Suggested fix:** Use `git add -u` for the follow-up (aligned with Option A and the updated doc at `skills/review-and-fix/scripts/review-and-fix.md:56`).
