Reviewing the branch diff and key driver modules for state-machine architecture issues.
### In-Scope Findings

- **architecture** `python/ship.py:228-264` — The CI-monitor loop keeps `iteration`, `rebase_count`, `fix_attempts`, and `transient_retries` as locals initialized to zero on every `run_ship()` entry, while bash persists those counters in `ship-pr-state.sh` (`REBASE_COUNT`, `FIX_ATTEMPTS`, `ITERATION`, `TRANSIENT_RETRIES`; see `scripts/ship-pr.sh` around lines 536–538 and 3004). Each orchestrator re-invocation after exit **3** (`NEEDS_USER_INPUT`) or exit **6** (`TRANSIENT`) therefore resets the 50/20/10 caps in `ci_monitor.decide()`, allowing unbounded fix/rebase work across handbacks even though the SKILL promises bash-compatible routing without reading `ship-pr-state.sh`. **Suggested fix:** Persist loop counters to a tmpdir sentinel or manifest `steps_ran` at loop exit and hydrate them at loop entry (or derive from gh/git + run-log ground truth as the plan describes); add `test_ship.py` coverage that simulates two invocations and asserts caps are cumulative.

- **architecture** `python/finalize.py:115-126`, `python/ship.py:150-170` — `finalize.postmerge()` maps a verify-main title mismatch to `Outcome.STALLED`, and `run_postmerge_phase()` returns immediately without calling `write_finalize_state()` or `flush_logs_post()`. Bash `implement-finalize.sh postmerge` treats verify-main mismatch as a warning (`verify_status=unexpected`) and still exits successfully, and `scripts/ship-pr.sh` `run_postmerge_phase()` writes `finalize-state.sh` **before** postmerge and still advances to `done` (lines 3045–3129). On the Python path, a successful merge with a transient title skew therefore exits **4**, skips manifest `status=done`, and leaves Step 18 without required finalize keys. **Suggested fix:** Match bash semantics—record verify-main mismatch as a warning-only outcome, write `finalize-state.sh` before postmerge (as in `ship-pr.sh:3045`), and still run the gated post-merge flush when `pr_closed` is true.

- **architecture** `python/ship.py:173-226` — Re-entry is only partially ground-truth driven: `pr.ensure_pr()` reuses an open PR via `gh.pr_for_branch`, but every invocation still runs checks, postbump (`finalize.postbump()` including `flush_logs_pre` + rebase/force-push), and PR-prep before reaching CI. The plan calls for idempotent resume from gh/git + manifest without a state file, but there is no phase short-circuit when a PR already exists and OOS disposition is satisfied (contrast bash, which resumes from persisted `PHASE`). Re-invocation after `oos-filing` or mid-CI handback can repeat destructive postbump work. **Suggested fix:** Add ground-truth phase detection at driver entry (open PR number/state, merge state, manifest/OOS disposition) to skip completed stages while preserving the checks→postbump→… ordering for cold starts; cover with re-invocation tests in `python/test_ship.py`.

- **architecture** `python/ship.py:181-190` — `run_checks_phase()` is called with hardcoded `codex_present=True` and `cursor_present=True`, ignoring Step 0 session-env availability flags that bash reads for degraded-panel fixer routing (`checks.py:1110-1162`). On degraded `/implement` runs, the Python driver may dispatch Codex/Cursor fixers the session marked unavailable, breaking the Step 0 degraded-tools contract. **Suggested fix:** Extend `RunContext` (or read `$IMPLEMENT_TMPDIR/session-env.sh`) for `CODEX_PRESENT` / `CURSOR_PRESENT` and pass real values into `run_checks_phase`; wire through `build_parser` / `from_env` and test degraded routing.

- **architecture** `python/test_ship.py:71-203` — Plan acceptance requires end-to-end driver tests for PR-only, draft, forked, transient retry, each `needs_user_reason`, stall, GOTO-rebase, cap exhaustion, and re-entry invariants; the branch ships only five tests (happy-path order, OOS gate, exit-map, `failed_run_id` mapping, JSON emit). Critical state-machine paths—including counter persistence, postmerge verify-main mismatch, and multi-invocation resume—are unverified at the driver level despite being central to Phase 7 architecture. **Suggested fix:** Expand `test_ship.py` per the plan acceptance list so phase-order and idempotency regressions are caught before cutover soaks.

### Out-of-Scope Observations

- **architecture** `skills/implement/SKILL.md:955-983` — The Python selector replaces the `ship-pr.sh` invocation but the Step 8+ block still mandates writing `ship-pr-state.sh` and anchors prose to the bash invoke fence; an orchestrator following the bash block literally on the Python path will perform redundant state-file work. Clarifying that the Python branch skips state-file init/write would reduce integration ambiguity (pre-existing structural awkwardness amplified by this branch’s additive selector).
