Reviewing the branch diff and key driver modules for state-machine architecture issues.
### In-Scope Findings
- **architecture** `python/ship.py:199-321` — Every `run_ship()` call runs the full linear pipeline from `checks` through `postbump` with no gh/git-derived phase entry, so orchestrator re-invokes after exit **3** or **6** repeat checks, log refresh, and Step 8b rebase instead of resuming near PR-create or CI the way bash does via persisted `PHASE` in `ship-pr-state.sh`. That conflicts with the Phase 7 “single idempotent process” / ground-truth re-entry design and with `skills/implement/SKILL.md`’s claim that the Python path mirrors bash resume semantics without reading `ship-pr-state.sh`. **Suggested fix:** Add an entry resolver (open PR, merge state, OOS pending, manifest status) that jumps to the correct phase and skips postbump when an open PR already exists and the branch is current; persist or reload only the minimum resume inputs (phase + CI counters) under `$IMPLEMENT_TMPDIR` if state files stay forbidden.

- **architecture** `python/ship.py:267-270` — CI loop counters (`iteration`, `rebase_count`, `fix_attempts`, `transient_retries`) are locals reset on every process start, so orchestrator re-invokes after TRANSIENT or post–CI-fix handback cannot accumulate toward `ci_monitor.decide()` caps (50/20/10) the way bash does with `ITERATION`, `REBASE_COUNT`, `FIX_ATTEMPTS`, and `TRANSIENT_RETRIES` in `ship-pr-state.sh`. **Suggested fix:** Extend `RunContext` or a tmpdir sidecar to load/save these counters across invocations; have Step 8+ re-invokes restore them; add tests proving two sequential `run_ship` calls honor cap exhaustion.

- **architecture** `python/run_logs.py:576-606` — `flush_logs_post` calls `_write_final_report` and ledger renders before writing `manifest.status=done`, reversing the plan’s fail-closed manifest-before-report ordering (the pre-change path wrote `status=done` first). If report rendering fails after a partial manifest update, manifest and summary can diverge. **Suggested fix:** When `finalize` is true, write `MANIFEST_STATUS_DONE` and `pr_number` first, then run `_write_final_report`/ledger renders; add a unit test that `status=done` is set before the report subprocess runs.

- **risk-integration** `python/ship.py:182-188`, `python/finalize.py:48-86` — Because re-entry always reruns `finalize.postbump` (including `rebase.rebase_and_push`), orchestrator retries after OOS filing or CI-fix can force-push/rebase a branch that already has an open PR, increasing races with in-flight CI. **Suggested fix:** Skip or narrow postbump when `gh.pr_for_branch` shows an open PR and the branch is not behind base; align skip rules with bash’s idempotent Step 8b behavior.

### Out-of-Scope Observations
- **code-quality** `python/config.py:15-16` — Unused legacy aliases `EXIT_BAIL=4` and `EXIT_STALL=6` sit beside the bash-compatible `OUTCOME_EXIT_MAP`; they are easy to misuse despite the plan saying not to route Outcomes through them. **Suggested fix:** Remove the aliases or rename them with a `_LEGACY_DO_NOT_USE` suffix if something external still needs them.
