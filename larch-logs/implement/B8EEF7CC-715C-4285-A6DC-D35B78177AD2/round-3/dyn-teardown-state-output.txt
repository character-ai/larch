### In-Scope Findings

- **security** `python/finalize.py:300-326` — `_cleanup_target_ok` authorizes `shutil.rmtree` using a non-canonical string prefix check (`raw.startswith("/tmp/", ...)`) and basename/session-id heuristics, without resolving the path or proving it stays under an allowed session root. A value like `/tmp/../../$HOME/claude-implement-<repo>-<suffix>` satisfies the prefix and default basename prefix (when `expected_session_id` is empty), so `teardown()` can recursively delete a directory outside `/tmp` or the larch cache if `ctx.tmpdir` is attacker-influenced via `IMPLEMENT_TMPDIR` or `--tmpdir`. The repo already has a stricter canonical guard in `checks.validate_tmpdir()` (`python/checks.py:102-130`), but teardown does not use it. **Suggested fix:** Before any removal, resolve `tmpdir` with `Path.resolve(strict=True)`, reject symlink roots, require `is_relative_to` an allowlisted root (`/tmp`, `/private/tmp`, `XDG_CACHE_HOME/larch/sessions`, etc.), and reuse the same basename/session-id rules on the canonical path; add regression tests for `..` segments and symlink roots.

- **security** `python/ship.py:407-446` — The Python driver accepts `IMPLEMENT_TMPDIR` / `--tmpdir` without confinement and immediately writes session artifacts (`finalize-state.sh`, `post-merge-sentinel`, JSONL journal) under `Path(ctx.tmpdir)`. Unlike bash `implement-finalize.sh` (`validate_tmpdir_arg` at `scripts/implement-finalize.sh:121-123`), there is no upfront validation that the tmpdir is under an accepted session root. With `LARCH_SHIP_PR_IMPL=python`, a manipulated env can redirect durable state and post-merge sentinels outside the intended session tree (same-UID write primitive). **Suggested fix:** Validate `ctx.tmpdir` at `RunContext` construction / `_ctx_from_args` using the same canonical policy as `checks.validate_tmpdir()` (or a shared helper), fail closed before any writes, and test rejection of paths outside allowed roots.

- **security** `python/ship.py:181-182` — `run_postmerge_phase` writes `post-merge-sentinel` as `MERGE_RESULT={ctx.merge_result}\n` without rejecting embedded newlines, while `write_finalize_state()` (`python/finalize.py:355-358`) explicitly blocks newline injection in KV state. A crafted `merge_result` could add extra sentinel lines and weaken the mechanical post-merge commit refusal in `scripts/larch-log.sh` (which keys off file existence, not strict single-line parsing). **Suggested fix:** Reject `merge_result` values containing `\n`/`\r` before writing the sentinel (mirror `write_finalize_state`), or write through a small KV serializer shared by both paths.

### Out-of-Scope Observations

- Bash teardown uses the same string-prefix `is_tmp_path` / `verify_cleanup_target` pattern (`scripts/implement-finalize.sh:47-54`, `593-636`) without canonical resolution; the Python port inherits that weakness rather than inventing it, but `finalize.teardown()` adds a direct `shutil.rmtree` path not gated by `cleanup-tmpdir.sh`'s audit log.

- `python/finalize.py:302-308` omits `XDG_CACHE_HOME` in the cache allowlist (bash and `cleanup-tmpdir.sh` honor it). That is a fail-safe cleanup skip for non-default cache layouts, not an escalation path.

- `python/run_logs.py:586-606` writes the final report before setting manifest `status=done`; the plan calls for the opposite ordering. That is primarily audit/correctness integrity, not a direct confidentiality boundary.

- Positive: `write_finalize_state()` newline rejection, JSON stdout redaction in `emit_result()`, and `tracking_issue.rename()` title redaction are appropriate hardening for untrusted GitHub-derived fields.
