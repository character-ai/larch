Reviewing the branch diff and finalize flow for risk-integration issues.
### In-Scope Findings

- **risk-integration** `python/finalize.py:48-80` — `postbump` calls `rebase.rebase_and_rebump`, which runs the CI-fix conflict launcher (`_resolve_conflicts` / external agents) on rebase conflicts. Bash Step 8b uses `rebase-push.sh --no-push`, which aborts on conflict and stalls without auto-fix. On `LARCH_SHIP_PR_IMPL=python`, a post-review rebase conflict can trigger unplanned agent work and different push/stall behavior than the bash ship path. **Suggested fix:** Use a Step-8b-only path aligned with `rebase-push.sh --no-push` plus the `check-remote-branch` / force-push gate (no `rebase_and_rebump`); reserve `rebase_and_rebump` for CI `goto_rebase` in `ship.py` only.

- **risk-integration** `python/finalize.py:116-125` — `postmerge` does `git switch main`, `git pull --ff-only origin main`, and `git branch -D` only. Bash Step 14 uses `local-cleanup.sh`, which fetches `origin/main` with transient retry, drops orphan `chore(larch-logs): flush` commits ahead of `origin/main`, then pulls. The Python path can leave `main` stale, fail pull, or keep orphan log-flush commits that bash would reset before verify. **Suggested fix:** Port the `local-cleanup.sh` fetch/retry, orphan-flush detection, and `hard reset` logic into `postmerge` (or call equivalent helpers in `git.py`), then run verify-main-style checks.

- **risk-integration** `python/finalize.py:64-79` — Postbump push gating uses `git.try_rev_parse(runner, f"origin/{branch}")`; any non-zero result (absent branch **or** auth/network failure) sets `defer_push=True` and returns OK with `*-push-skipped`. Bash uses `check-remote-branch.sh` and stalls with `remote-check-failed` on transport errors while treating only confirmed absence as “no force-push”. A transient `origin/<branch>` lookup failure can skip the required force-push and still look successful. **Suggested fix:** Use an `ls-remote`/`check-remote-branch`-style trichotomy (`present` / `absent` / `error`); stall on `error`, skip push only on `absent`, force-push on `present`.

- **risk-integration** `python/finalize.py:145-179` — `_rename_issue` renames when `gh issue view` fails: the OPEN-state guard runs only on exit 0, so a failed view still calls `tracking_issue.rename`. Bash teardown renames only when `get-issue-info` reports `OPEN`. If `finalize.teardown` is wired later (or called from tests mirroring production), a flaky `gh` call could rename a closed tracking issue. **Suggested fix:** On non-zero `gh issue view`, return `failed`/`skipped` without renaming; require explicit `OPEN` before rename, matching `implement-finalize.sh`.

- **risk-integration** `python/finalize.py:182-199` — `auto_stash_stalled_changes` treats non-zero `git status` like a clean tree (returns `""` with no warning). Bash warns that silence does not mean a clean tree. Operators may assume a dirty worktree was stashed when status failed. **Suggested fix:** Mirror bash: warn on status failure, do not treat it as clean; only stash when porcelain is non-empty and stash succeeds.

### Out-of-Scope Observations

- **risk-integration** `python/finalize.py:231-287` — `teardown` omits bash Step 18 behaviors still in `implement-finalize.sh`: `kill_session_background_processes`, `flush_execution_issues_safety_net`, manifest recovery/`larch-log.sh commit`, and `cleanup-tmpdir.sh` instead of raw `shutil.rmtree`. Live `/implement` Step 18 still calls bash today, so this is latent until Step 18 is cut over; `test_finalize_bash_parity.py` only covers postmerge skip decisions, not full teardown parity.

- **architecture** `python/config.py:353-354` — `EXIT_BAIL` / `EXIT_STALL` (4/6) coexist with `EXIT_STALLED` / `EXIT_TRANSIENT` (4/6) for Outcome routing; confusing but not used by the new Outcome map on the ship path.
