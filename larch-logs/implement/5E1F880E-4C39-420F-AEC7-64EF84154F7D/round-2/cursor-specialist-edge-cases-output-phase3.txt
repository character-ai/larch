### In-Scope Findings

**Finding 1 — Important | correctness**
`skills/design/scripts/decompose-file-issues.sh:312-315`

**Sentinel write ordering in `close-original` creates a duplicate-comment window.** In `cmd_close_original`, `rm -f "$comment_sent"` executes *before* `: >"$DESIGN_TMPDIR/.decompose-original-closed"`. If the process is killed between these two lines (SIGKILL, OOM), the per-run comment guard is gone but the overall-success sentinel was never written. A subsequent retry invokes `close-original` again; the `[[ ! -f "$comment_sent" ]]` guard no longer exists, so the script re-posts the close comment on GitHub — accepted silently because GitHub allows comments on closed issues.

**Suggested fix:** Swap the two lines: write `.decompose-original-closed` first, then `rm -f "$comment_sent"`. Alternatively, omit the `rm` entirely — the tmpdir is session-scoped and cleanup is irrelevant to correctness.

---

**Finding 2 — Latent | architecture**
`skills/design/scripts/decompose-file-issues.sh` — `cmd_close_original` function

**`close-original` has no self-contained idempotency guard; it delegates entirely to orchestrator prose.** The `.decompose-original-closed` early-exit check lives only in `decompose-panel.md §0`, not in the script itself. Any caller that bypasses the orchestrator — a manual operator retry, a future partial-recovery path, a test harness — will re-execute unconditionally and post a duplicate comment with no warning.

**Suggested fix:** Add an early exit at the top of `cmd_close_original`:
```bash
[[ -f "${DESIGN_TMPDIR}/.decompose-original-closed" ]] && { emit_kv CLOSE_ORIGINAL_STATUS ok; exit 0; }
```
This mirrors the orchestrator prose guard but enforces it at the script boundary, making the function safe to call from any context.

---

**Finding 3 — Nit | code-quality**
`skills/design/scripts/decompose-panel-dispatch.sh:193-194`

**Dual prefix-strip for archetype name extraction is order-sensitive.** The pattern `_arch="${_slot#decomp-cursor-}"; _arch="${_arch#decomp-codex-}"` works for all current archetype names, but silently produces a wrong value if a future archetype slug begins with `cursor-` or `codex-`. For example, a hypothetical `cursor-aware` archetype in slot `decomp-cursor-cursor-aware` would yield `_arch=aware` rather than `cursor-aware`, silently corrupting the `archetype` field in panel-outputs NDJSON.

**Suggested fix:** Either add a comment documenting the naming constraint (no archetype slug may start with `cursor-` or `codex-`), or use a single robust sed pass: `_arch="$(sed 's/^decomp-[a-z]*-//' <<< "$_slot")"`.
