## Plan Fidelity Review

### In-Scope Findings

**1. [important / correctness] `scripts/test-design-structure.sh:690`**

Check 19's stub-absence assertion is semantically broken. The line:

```bash
grep -vq 'decomposition panel is in development' "$SKILL_MD" || fail "(19) SKILL.md must not retain the pre-panel stub string"
```

`grep -vq` exits 0 whenever *any* line in the file does not match the pattern. Since `SKILL.md` has hundreds of lines, this exits 0 unconditionally — regardless of whether the stub is present. The plan's acceptance criterion explicitly requires this check to work. Any future commit re-introducing the stub will silently pass.

**Fix:** Replace with `! grep -Fq 'decomposition panel is in development' "$SKILL_MD" || fail "(19) ..."`

---

**2. [latent / correctness] `skills/design/scripts/test-decompose-panel-dispatch.sh:108-131`**

`feature-only` mode is exercised only in the `panel-failed` path (`W_STUB_MODE=nop`). There is no successful `feature-only` run that verifies `{DISCUSSION_BLOCK}` substitution actually injects discussion file content into the rendered prompt. The plan states: "Prompt template substitution resolved correctly in **both** `plan` and `feature-only` modes." The plan-mode test (D1) verifies `"Plan body."` appears in the rendered output; no equivalent check exists for discussion content in feature-only mode.

**Fix:** Add a sub-case with `W_STUB_MODE=ok`, `--discussion-round1-file` pointing to a non-empty file, and an assertion that its content appears in the rendered prompt.

---

### Out-of-Scope Observations

**1. [nit / code-quality] `skills/design/scripts/dispatch-plan-review-panel.sh:85-118`**

File is not in the plan's files-to-modify list. It was refactored to replace `printf '{"slot":...}\n'` NDJSON emission with `jq -nc` calls, preventing JSON corruption when tmpdir paths contain special characters. `test-dispatch-plan-review-panel.sh` also received two unplanned tests (jq validity + quoted-path case D6). The change is correct and makes this file consistent with the new `decompose-panel-dispatch.sh` (which used `jq -nc` from the start), but it is unplanned scope creep.
