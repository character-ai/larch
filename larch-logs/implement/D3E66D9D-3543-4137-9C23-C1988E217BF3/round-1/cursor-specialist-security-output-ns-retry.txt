### FINDING_1: Regression test replaces EXIT trap and skips `$TMP` cleanup
- **severity:** Important  
- **focus:** `correctness`  
- **location:** [scripts/test-dispatch-code-voters.sh](scripts/test-dispatch-code-voters.sh) — `26:26` (initial trap), `385:386` (second trap)  
- **problem:** A second `trap ... EXIT` overwrites the first; after regression 3 runs, `EXIT` only runs `rm -rf "$prod_tmp"` and no longer removes `"$TMP"`.  
- **impact:** Successful runs leave the main harness directory (stubs, logs, voter fixtures) under `/tmp/test-dispatch-code-voters.*` on disk until external cleanup; repeated runs accumulate junk; any sensitive fixture content in `$TMP` outlives the process.  
- **fix:** Chain cleanup (e.g. `trap 'rm -rf "$prod_tmp" "$TMP"' EXIT`) or use a nested subshell for regression 3 so the outer `EXIT` trap stays intact.

### FINDING_2: Path-pattern guard can suppress parent execution-issues for non-test tmpdirs
- **severity:** Latent  
- **focus:** `risk-integration`  
- **location:** [scripts/dispatch-code-voters.sh](scripts/dispatch-code-voters.sh) — `161:165` (`case "$voter_path" in ...`)  
- **problem:** Suppression is keyed only on pathname globs (`*/test-collect-*`, `*/test-check-*`, `*/test-tally-*`, etc.), not on a dedicated test flag.  
- **impact:** If `--review-tmpdir` (or a resolved voter path) ever sits under a legitimate directory whose path matches these segments, parse-rate warnings would not be appended to `execution-issues.md`, weakening audit visibility for that run.  
- **fix:** Prefer an explicit opt-in/out (e.g. env sentinel) in addition to path heuristics, or document and enforce naming constraints for production tmp roots.
