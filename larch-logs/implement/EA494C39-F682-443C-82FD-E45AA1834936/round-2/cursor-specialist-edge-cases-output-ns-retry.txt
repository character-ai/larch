### In-Scope Findings

- **risk-integration** `skills/compress-skill/SKILL.md:10-65` — `/compress-skill` no longer chains through `/imaq` → `/implement --merge --auto --quick`; it now calls `/implement --merge --auto`, which pulls in full `/design` (when the normal Step 1 path runs) plus the unified hard Step 5 loop. Operators or automation that treated compression as a lightweight “prose-only / quick-implement” hop can see sharply higher wall-clock, token use, and `/design --subagent` / `SendMessage` failure modes than under the old shortcut. **Suggested fix:** Add an explicit operator-facing note in `CHANGELOG.md` (and optionally a NEVER/limitations callout in this skill) describing the heavier pipeline and any supported escape hatches (for example documenting when `--design-only` or `--inline` are appropriate if you intend a narrower path).

- **Latent** `CHANGELOG.md:12-14` — The `[29.8.64]` “Changed” section documents Step 5 unification, JSONL category strictness, and `QUICK_MODE` reporting, but does not call out other user-visible delegators whose argv shape changed in the same effort (`/alias` scaffolding, `/create-skill` → `/im --auto`, `/compress-skill` → direct `/implement --merge --auto`, removed `/imaq`/`/imq`). Someone upgrading from the changelog alone can miss that non-Step-5 workflows also moved off `/implement --quick`. **Suggested fix:** Extend the changelog bullets to name those skills and state plainly that former `--quick` shortcut semantics are gone outside `/design --quick`.

- **Nit** `scripts/persist-implement-run-flags.md:8-9` — The “Interface” fenced example still shows `--quick-mode true|false` on the required-looking argv line, while `persist-implement-run-flags.sh` now treats `--quick-mode` as optional and defaults `QUICK_MODE=false` when omitted. Readers following only the `.md` contract can believe `--quick-mode` is mandatory or always meaningful. **Suggested fix:** Update the fenced usage to mark `--quick-mode` optional (for example `[--quick-mode true|false]`) and mirror the shell header’s defaulting sentence.

- **Nit** `scripts/run-step5-review.sh:167` — The new stderr breadcrumb explaining the shared base cap runs only when `WORKFLOW_PATH` is `HARD` and `ROUND_NUM` is `1`; `SIMPLE` runs get no analogous breadcrumb even though they now share the same `--panel hard` / base cap behavior. **Suggested fix:** Emit the same informational line for both workflow paths (or drop the special case and log once whenever `ROUND_NUM==1`).

- **Latent** `skills/fix-issue/scripts/test-fix-issue-bail-detection.sh:133` — Assertion `(a6)` bans the substring ` --quick` anywhere in the extracted Step 5a block; any future prose that legitimately mentions a removed `/implement --quick` token (for example quoting a forbidden argv) would trip CI even when the forward is correct. **Suggested fix:** Anchor the guard to the Skill-tool `args:` template line (similar to the old `grep '/implement --merge'` approach) or match a stricter forbidden pattern such as `args:.*--quick` instead of a bare substring over the whole block.
