### In-Scope Findings

- **correctness** `scripts/lib-external-launcher-common.sh:541-560` — The stripper’s multiline tracking toggles on any line containing an odd count of `"""` or `'''`, including `#` comment lines, without respecting TOML comment rules. A comment such as `# docs use """ for multiline` can leave `in_dq_multiline` true so later top-level `model_provider = "openai-larch-env"` / `env_key = "OPENAI_API_KEY"` lines are not removed; login fallback can then symlink `auth.json` while the temp config still selects env-key auth. **Suggested fix:** Only run `update_multiline_state` on lines that are not TOML comments (e.g. skip state updates when the line matches `^[[:space:]]*#`), or strip comments before multiline detection; add a harness case with a `"""`-containing comment above larch keys.

- **correctness** `scripts/lib-external-launcher-common.sh:550-560` — Table and top-level removal use strict double-quoted, whitespace-sensitive regexes. Variants such as `model_provider = 'openai-larch-env'`, `model_provider="openai-larch-env"` (no spaces), or `[ model_providers.openai-larch-env]` / `[model_providers.openai-larch-env ]` do not match, so the login branch can leave larch env-key selectors in a copied `config.toml` and still symlink `auth.json`, reproducing the “login + env-key config” conflict this change is meant to remove. **Suggested fix:** Broaden patterns (optional spaces, single-quoted values) or normalize before strip; add fixtures for each variant.

- **correctness** `scripts/lib-external-launcher-common.sh:558-557` — While `skip_larch_provider` is set, every line is dropped until the next `[` header is seen *and* `!was_in_multiline`. If a `"""` or `'''` delimiter inside the larch provider table is never closed, `was_in_multiline` stays true, subsequent `[model_providers.other]` headers never reset `skip_larch_provider`, and the awk pass deletes the rest of the file (unrelated providers/profiles). **Suggested fix:** Reset `skip_larch_provider` when a new `[` header is seen even inside multiline (only suppress table-header detection inside strings), or cap skip mode at EOF with a post-pass sanity check that fails closed when output is empty/truncated vs input size.

- **correctness** `scripts/test-lib-external-launcher-common.sh:59-120` — The plan requires a strip-failure case (`external_prepare_codex_auth` nonzero, no `auth.json` symlink), but the harness only covers happy-path strip/login/env-key. There is no test for unwritable config, corrupt strip input, or `chmod -w` behavior, so fail-closed login behavior is unverified. **Suggested fix:** Add a test that copies the fixture config, `chmod -w` or points at a strip helper stub that returns 1, asserts `external_prepare_codex_auth` fails and `auth.json` is not created.

### Out-of-Scope Observations

- **correctness** `scripts/lib-external-launcher-common.sh:530` — Strip requires `-w` on `config.toml`. Launchers create writable temp homes today, so this is unlikely in production; a copied read-only file would fail auth prep entirely rather than partially strip.

- **architecture** `scripts/lib-external-launcher-common.sh:527-567` — The helper is intentionally not a full TOML parser (per plan). Residual risk remains for inline tables, dotted keys (`[model_providers.openai-larch-env]` as a key), or `env_key` under non-larch provider tables; those are outside the stated larch-owned artifact contract.
