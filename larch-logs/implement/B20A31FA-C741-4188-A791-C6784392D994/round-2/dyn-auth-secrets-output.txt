Reviewing the branch diff and auth-helper code for secret exposure risks.
### In-Scope Findings

- **security** `scripts/test-launch-review.sh` — The branch wires env-key auth into `launch-review.sh` via `external_codex_auth_config_args` and `run-external-agent.sh`, which serializes the full post-`--` argv into `${OUTPUT}.meta` as `CMD_JSON` (same contract as Cursor issue #3375). Helper and other launcher harnesses assert the sentinel key value never appears in argv, but **`test-launch-review.sh` has no Codex env-key regression** (no `OPENAI_API_KEY` / `sk-*` sentinel checks on `.meta`, `${OUTPUT}.events.jsonl`, or stderr). A future mistake that expands the env var into argv or config would not be caught on the highest-volume Codex review path. **Suggested fix:** Add launch-review cases mirroring `skills/implement/scripts/test-codex-implementer.sh` and `scripts/test-launch-codex-ci.sh`: stub `codex`, set `OPENAI_API_KEY=sk-larch-*-sentinel`, assert auth `-c` tokens contain only the var name, and grep `.meta`, sidecar, events, and stderr for absence of the sentinel value.

- **security** `skills/review-and-fix/scripts/test-review-and-fix.sh` — Step 5 direct Codex dispatch now copies `~/.codex/config.toml`, uses `external_prepare_codex_auth`, and passes auth `-c` overrides through `run-external-agent.sh` (`review-and-fix.sh:267-306`), but **there is no env-key leak harness** for `coder-codex.wrapper.log`, `coder-codex.events.jsonl`, `coder-codex.sidecar`, temp `config.toml`, or wrapper-produced `.meta`/`CMD_JSON`. The plan’s acceptance criteria explicitly require sentinel-absence checks here; they are missing. **Suggested fix:** Add an integration case with a PATH-stubbed `codex` and sentinel `OPENAI_API_KEY`, asserting auth `-c` argv shape, no `auth.json` on the env-key path, no provider block written to disk, and no sentinel substring in config, argv logs, wrapper/sidecar, or events JSONL before Cursor fallback.

- **security** `scripts/check-reviewers.sh:211-212`, `skills/review-and-fix/scripts/review-and-fix.sh:279-280` — New behavior **copies `~/.codex/config.toml` verbatim** into ephemeral `CODEX_HOME` directories under `/tmp`. `external_strip_codex_larch_env_provider` only removes larch-owned lines (`model_provider = "openai-larch-env"`, `env_key = "OPENAI_API_KEY"`, and the `openai-larch-env` table). If an operator previously stored a **literal API key** in `config.toml` (misconfiguration outside the legacy `env_key = "OPENAI_API_KEY"` pattern), that secret is duplicated at rest in probe/review-fix temp homes until cleanup. `mktemp -d` limits exposure to the same user, but session tmpdirs are still a documented sensitive surface (`SECURITY.md` session-scrubbing guidance). **Suggested fix:** Document that `~/.codex/config.toml` must not contain literal secrets; optionally extend strip or add a pre-copy scan/redaction for obvious `sk-*` literals in copied configs used for larch temp homes, or copy only a allowlisted subset of config keys instead of the full file.

- **security** `scripts/test-lib-external-launcher-common.sh` — The plan requires a harness proving that **strip failure is fail-closed** (`external_prepare_codex_auth` returns non-zero and does not symlink `auth.json`). That case is **not present** (only happy-path strip tests exist). Without it, regressions in the awk stripper could silently stop removing env-key selector lines and leave login fallback in a mixed auth state. **Suggested fix:** Add a fixture config that makes `external_strip_codex_larch_env_provider` fail (e.g., unreadable after copy, or a deliberate corrupt state), assert `external_prepare_codex_auth` exits non-zero and `auth.json` is not created.

### Out-of-Scope Observations

- **Core env-key design looks sound:** `external_codex_env_key_enabled` uses `${OPENAI_API_KEY+x}` and `${#OPENAI_API_KEY}` (no value expansion under `set -x`); `external_codex_auth_config_args` only appends fixed `-c` tokens naming `OPENAI_API_KEY`; env-key mode does not symlink `auth.json` or write provider auth into `config.toml`. Round 2 added probe `PROBE_DIRS` cleanup and review-fix `REVIEW_FIX_TMPDIRS` EXIT trap, which closes temp-home leak risks on those paths.

- **`/research` and other direct `codex exec` helpers** remain on the old auth model by explicit design; docs correctly narrow scope.

- **Login fallback** still symlinks `~/.codex/auth.json`, which may contain plaintext credentials from `codex login --with-api-key`; that predates this branch and is unchanged when `OPENAI_API_KEY` is unset/empty.

- **`SECURITY.md` still describes Cursor `--api-key` argv persistence** in the section above the new Codex env-key paragraph; that is stale relative to issue #3375 env-based Cursor auth and was not introduced by this Codex change.
