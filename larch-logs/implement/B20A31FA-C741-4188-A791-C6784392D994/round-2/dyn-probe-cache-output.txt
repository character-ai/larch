Reviewing Codex health-probe changes for cache semantics, auth retry, and temp-home cleanup. Reading the diff and relevant probe code.
Checking one more edge case: login-cache interaction after a recent env-key probe.
### In-Scope Findings

- **correctness** `scripts/check-reviewers.sh:317-321` — After a run with `OPENAI_API_KEY` set, probes write only to `codex-env-key` stamps and never refresh `codex-login`. If the operator later unsets the key while a fresh `codex-login` stamp still says `true` (within `LARCH_PROBE_TTL_SECONDS`), the cache fast-path can set `CODEX_PRESENT=true` without re-running the login probe, even though login may be invalid or stale. The env-key→login transition is only partially isolated (separate stamp files; env-key mode bypasses cache), not invalidated when switching back to login. **Suggested fix:** On the login cache-hit path (`! external_codex_env_key_enabled`), treat a fresh `codex-env-key` stamp as a cache miss (force re-probe), or clear/update `codex-login` whenever writing `codex-env-key` stamps so login availability reflects the last auth mode actually exercised.

- **correctness** `scripts/test-check-reviewers.sh:304-329` — The harness proves env-key mode bypasses a fresh `codex-env-key` `true` stamp when the stub fails, but it does not cover the symmetric acceptance case: a fresh `codex-login` `false` stamp plus `OPENAI_API_KEY` set and a succeeding stub should still probe and emit `CODEX_PRESENT=true`. That gap leaves the main regression (“stale login-mode failure must not suppress env-key probe”) unverified even though `scripts/check-reviewers.sh:319-320` implements it via `&& ! external_codex_env_key_enabled`. **Suggested fix:** Add a fixture with `larch-codex-login-present-*.stamp` containing `false`, `OPENAI_API_KEY` set, stub `exit 0`, and assert `CODEX_PRESENT=true` plus argv log presence; optionally add the env-key→login stale-`true` stamp scenario above.

### Out-of-Scope Observations

- **Temp `CODEX_HOME` lifecycle** in `larch_run_one_codex_probe` (`scripts/check-reviewers.sh:208-263`) and `PROBE_DIRS` + `larch_probe_exit_cleanup` (`scripts/check-reviewers.sh:62-70, 275-276`) look consistent: explicit `rm -rf` on success, auth-retry (`return 2`), failure, auth-prep failure, and serial-lock failure, with EXIT trap as a backstop. The branch diff does not add harness assertions that probe-home directories are gone after success/failure/auth-retry/helper-failure paths.

- **Env-key cache semantics** are stricter than `scripts/check-reviewers.md:29` prose (“cached `false` is treated as a miss”): `&& ! external_codex_env_key_enabled` bypasses **all** env-key stamps, including fresh `true`, so every env-key probe runs within TTL. That matches the plan’s “fail loud / retry rotated key” intent but is broader than the doc line.

- **Legacy stamp files** (`larch-codex-present-${USER}.stamp` from pre-branch installs) are no longer read; login mode now uses `codex-login`. That causes a one-time extra probe after upgrade, not incorrect availability signaling.
