Reviewing the branch diff and `review-and-fix.sh` Codex auth/fallback paths for observability and redaction.
### In-Scope Findings

- **risk-integration** `skills/review-and-fix/scripts/review-and-fix.sh:320-340` — When `OPENAI_API_KEY` is set and Codex fails but Cursor fallback succeeds, the branch only appends `codex-env-key-failure: …` to `$round_dir/coder-codex.wrapper.log` and `coder-codex.sidecar`. It does not call `larch_err`, does not append to `$IMPLEMENT_TMPDIR/execution-issues.md`, and the round result KVs still report `CODER_TOOL=cursor` with `CODER_LOG_FILE` pointing at the Cursor log. That contradicts the documented “fail loud” promise for bad/expired API keys: an operator watching the `/implement` Step 5 transcript can believe review fixes ran on Cursor without ever learning the enterprise key path failed. **Suggested fix:** Before entering the Cursor branch, emit a redacted operator-visible warning (for example `larch_err` or `append-execution-issue.sh` under `Warnings`) whenever `external_codex_env_key_enabled` and `codex_rc != 0`, optionally add a machine KV such as `CODER_CODEX_FAILED=true` / `CODER_FALLBACK_TOOL=cursor`, and extend `test-review-and-fix.sh` to assert the warning is present on env-key failure + Cursor success.

- **risk-integration** `skills/review-and-fix/scripts/test-review-and-fix.sh` — The branch updates `review-and-fix.sh` and documents env-key auth, but `test-review-and-fix.sh` has no diff vs `main` and contains no assertions for env-key argv wiring, `codex-env-key-failure` breadcrumbs, auth-setup failure, temp-`CODEX_HOME` cleanup, or sentinel leak checks. Acceptance criteria and the plan both require this harness extension; without it, regressions in fallback observability (silent waterfall, missing breadcrumbs, trap/cleanup ordering) will not be caught in CI. **Suggested fix:** Add the planned stubbed-`codex` cases (env-set / env-unset / env-empty, auth-helper failure, env-key exec failure with Cursor fallback, sentinel absence under `set -x`) to `skills/review-and-fix/scripts/test-review-and-fix.sh` per `.claude/rules/launcher-argv-test-coverage.md`.

- **risk-integration** `skills/review-and-fix/scripts/review-and-fix.sh:308-322` — Env-key failure telemetry is asymmetric: `codex-env-key-failure` is written only when `codex_auth_prepared=true` (post–`external_prepare_codex_auth` success), while earlier failures (temp dir creation, config copy, or auth prep) take the `codex-auth-setup` path and delete `coder-codex.events.jsonl` / `coder-codex.sidecar` before fallback. With `OPENAI_API_KEY` set, a setup failure therefore leaves only a generic `codex-auth-setup` line and no env-key-specific breadcrumb, even though the operator’s configured auth mode was API-key. **Suggested fix:** When `external_codex_env_key_enabled` and `codex_rc != 0`, always append the same redacted `codex-env-key-failure` line (or a distinct `codex-env-key-setup-failure` variant) before Cursor fallback, regardless of whether `codex_auth_prepared` was set.

### Out-of-Scope Observations

- **Pre-existing pattern (not introduced by this branch):** Codex→Cursor waterfall without env-key mode also hid Codex failure from stdout when Cursor succeeded; this change adds durable round artifacts but does not yet surface them on the orchestrator transcript except when both tools fail (`larch_err` at line 343).
