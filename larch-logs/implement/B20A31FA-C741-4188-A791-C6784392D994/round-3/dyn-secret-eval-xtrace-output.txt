Reviewing the branch diff and the security-sensitive Codex auth helpers.
### In-Scope Findings

- **security** `scripts/test-lib-external-launcher-common.sh:194-203` — The `set -x` regression test only exercises `external_codex_env_key_enabled`, not `external_codex_auth_config_args`, which is the other secret-sensitive surface (it uses `eval` to append argv). Runtime behavior looks safe: `${#OPENAI_API_KEY}` traces as a length only (e.g. `+ [[ 24 -gt 0 ]]`), and the helper never expands `$OPENAI_API_KEY` elsewhere in the repo. But if a future edit introduced value expansion inside the `eval` string, the current harness would not catch it under xtrace. **Suggested fix:** Extend the xtrace case to call `external_codex_auth_config_args` with a sentinel `OPENAI_API_KEY` set, capture stderr, and assert the sentinel value is absent while the literal `OPENAI_API_KEY` name in `-c` tokens may remain.

### Out-of-Scope Observations

- **`external_codex_env_key_enabled` (`scripts/lib-external-launcher-common.sh:522-525`)** — The `${OPENAI_API_KEY+x}` / `${#OPENAI_API_KEY}` pattern is appropriate for Bash 3.2 and safe under `set -x` (trace shows `x` and length, not the secret). This matches the plan’s rejection of `[[ -n "${OPENAI_API_KEY:-}" ]]`.

- **`external_codex_auth_config_args` eval (`scripts/lib-external-launcher-common.sh:603-617`)** — Array-name validation (`''|*[!A-Za-z0-9_]*`, no leading digit) is tight enough for the current static call sites (`CODEX_AUTH_ARGS`, `_codex_auth_args`, `args`); it blocks injection via names like `foo; rm`. `eval` is still a footgun if a future caller passes a dynamic name without going through this helper.

- **`.meta` / `CMD_JSON` vs `SECURITY.md`** — No contradiction with the new Codex bullet (`SECURITY.md` ~line 26). `run-external-agent.sh` still records full post-`--` argv in `CMD_JSON` via `jq` (`scripts/run-external-agent.sh:190-204`), so env-key launches persist the five `-c` overrides, including `model_providers.openai-larch-env.env_key="OPENAI_API_KEY"`. That is the **variable name**, not the key value—the same session-private argv tradeoff already documented for Cursor (`SECURITY.md` CURSOR section). Committed `larch-logs` still strip `CMD_JSON` on publish.

- **Argv vs environment** — Env-key mode avoids putting the secret on the process command line (unlike Cursor’s `--api-key "$CURSOR_API_KEY"` path). The child still inherits `OPENAI_API_KEY` from the environment, which is required for Codex to read the key at request time; same-user `ps`/environ visibility is inherent to env-based auth, not introduced by this branch’s argv design.
