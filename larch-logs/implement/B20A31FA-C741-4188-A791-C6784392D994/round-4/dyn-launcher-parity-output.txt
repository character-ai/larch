Reviewing Codex launcher argv parity across the changed call sites. Reading the diff and comparing each launcher's auth/trust argv spine.
Branch commits (since `main`): `f0cefe772` Prefer OPENAI_API_KEY for covered Codex paths, plus three review-feedback rounds and a design log flush.

Across the three launchers, the health probe, and `review-and-fix`, auth/trust wiring is mostly aligned: shared helpers, `model-args` → `-c` trusted-project → auth `-c` overrides → `--output-last-message` on implement/review/CI/probe. Gaps below are where that contract breaks or docs disagree with code.

### In-Scope Findings

- **architecture** `skills/review-and-fix/scripts/review-and-fix.sh:300-303` — The Step 5 Codex coder path passes `trust` and auth `-c` overrides but never calls `agent-model-args.sh --tool codex --with-effort`, unlike `launch-codex-implement.sh:399-401`, `launch-review.sh:574-576`, `launch-codex-ci.sh:215-217`, and `check-reviewers.sh:237-239`. Operators who set `LARCH_CODEX_MODEL` get launcher/probe model argv on covered paths but not on `/implement` Step 5 coder dispatch (only whatever is in copied `~/.codex/config.toml`). **Suggested fix:** Load model args the same way as the launchers and insert `${MODEL_ARGS[@]+"${MODEL_ARGS[@]}"}` immediately before `-c "$trust_config_arg"` in the `codex exec` argv spine; extend `skills/review-and-fix/scripts/test-review-and-fix.sh` to assert sentinel model forwarding.

- **architecture** `scripts/check-reviewers.md:29` vs `scripts/check-reviewers.sh:318-320` — The sibling contract says that in env-key mode, a cached `false` stamp is treated as a miss so a rotated key can retry within the TTL. `larch_try_read_fresh_stamp` still returns `0` for any fresh `true`/`false` line, so a fresh `larch-codex-env-key-present-*.stamp` with `false` skips the live probe until expiry. Only login vs env-key stamp *names* are split (`larch_codex_probe_stamp_key`); the “false is a miss” behavior is not implemented. **Suggested fix:** In the Codex stamp branch, when `external_codex_env_key_enabled` and cached value is `false`, fall through to a live probe (or delete the stale stamp) before setting `CODEX_PRESENT`; add a harness case mirroring `test-check-reviewers.sh` t6e but with a fresh env-key `false` stamp.

- **risk-integration** `docs/configuration-and-permissions.md:193` — The `LARCH_CODEX_MODEL` section still says the Codex health probe runs with “no model argv,” but this branch wires `agent-model-args.sh --tool codex --with-effort` into `larch_run_one_codex_probe` (`check-reviewers.sh:221-224`) and documents that in `scripts/check-reviewers.md:28`. Operator docs now disagree with probe behavior and with `scripts/test-check-reviewers.sh` (sentinel-model argv assertion). **Suggested fix:** Update the `LARCH_CODEX_MODEL` bullet to state that the probe forwards the same model argv as `launch-review.sh`, and that `LARCH_CODEX_MODEL` applies there too.

- **architecture** `scripts/launch-codex-ci.md:16-18` and `scripts/launch-review.md:37-45` — `launch-codex-implement.md` documents the full Codex argv spine (`MODEL_ARGS` → trusted-project `-c` → auth `-c` → `--output-last-message`), but the CI and review sibling contracts only describe auth mode, not argv ordering. That makes parity harder to audit and diverges from `.claude/rules/script-md-siblings.md` / launcher-argv expectations after this change. **Suggested fix:** Add an explicit argv-spine paragraph to `launch-review.md` (both Codex `codex exec` spines) and `launch-codex-ci.md`, matching `launch-codex-implement.md` (noting intentional `--sandbox read-only` / `--add-dir` / `--full-auto` differences).

### Out-of-Scope Observations

- **Intentional asymmetry (not a defect):** `launch-codex-implement.sh` uses `--full-auto` and dual `--add-dir`; `launch-review.sh` uses `--sandbox read-only` and a single scoped `--add-dir`; the probe omits `--json` and `--add-dir`; `launch-codex-ci.sh` stays config-file-free. Those differences match `.claude/rules/external-tool-launcher-parity.md` and the plan.
- **Auth-prep failure exit semantics** differ by launcher family (implement/CI emit KV and exit 0; review exits non-zero; review-and-fix falls through to Cursor). That predates this branch and is not a new argv-ordering regression.
- Among the five wired call sites, **trust → auth → `--output-last-message` ordering is consistent** where model args exist; the main argv-spine outlier is review-and-fix omitting the model-args block entirely.
