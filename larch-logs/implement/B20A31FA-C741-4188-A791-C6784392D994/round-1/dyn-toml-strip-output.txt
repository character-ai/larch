Reviewing the branch diff and TOML strip helper implementation for correctness issues.
### In-Scope Findings

- **correctness** `scripts/lib-external-launcher-common.sh:532-545` — `external_strip_codex_larch_env_provider` is a line-oriented awk filter, not a TOML parser. Any physical line that starts with `[model_providers.openai-larch-env]` is treated as a real table header and enters `skip_larch_provider`, so following lines are dropped until the next `[…]` header. That is wrong inside multiline string values (`'''…'''`, `"""…"""`, or other quoted blocks) in a copied `~/.codex/config.toml` (probe / `review-and-fix`) or in other user config that survives the instructions-only pre-filter in `launch-codex-implement.sh` / `launch-review.sh`. The result can be a corrupted `config.toml` (broken strings, missing keys) while the helper still exits 0, so login fallback may fail or behave unpredictably instead of failing closed. **Suggested fix:** Track multiline string state the same way the launchers already do for `instructions` (skip until closing delimiter), or strip larch artifacts from the user-config slice before prepending launcher `instructions`, and add harness fixtures with a bracket-like line inside a `'''` block to lock the behavior.

- **correctness** `scripts/lib-external-launcher-common.sh:532-545` — On the login branch, stripping runs on the fully merged temp `config.toml` after launchers prepend their own `instructions = '''…'''` block (`launch-codex-implement.sh:295-315`, `launch-review.sh:423-443`). That block is not excluded from the strip pass. If the agent / hardening prompt body contains a line exactly matching `[model_providers.openai-larch-env]` (e.g. documentation or examples), the awk pass deletes subsequent lines inside the instructions string until the next `[` header, corrupting the file Codex reads. **Suggested fix:** Run `external_strip_codex_larch_env_provider` only on the user-derived portion before writing launcher `instructions`, or teach the strip awk to ignore bracket-like lines inside active `instructions` / other multiline assignments.

- **correctness** `scripts/lib-external-launcher-common.sh:534-544` — Table removal only recognizes a standard header `[model_providers.openai-larch-env]`. TOML array-of-tables headers (`[[model_providers.openai-larch-env]]`) and non-matching spellings are left in place, so stale larch provider material can remain on the login path and keep forcing env-key routing when `auth.json` is also symlinked. **Suggested fix:** Extend the header matcher (and tests) to cover `[[model_providers.openai-larch-env]]`, or document and strip dotted-key remnants if Codex can emit them.

- **correctness** `scripts/lib-external-launcher-common.sh:543-544` — Top-level `model_provider` / `env_key` removal is gated on `!in_table`, where `in_table` is set on the first `[` header and never cleared. That matches valid TOML (root keys before any table), but it does not remove double-quoted assignments that appear after the first table header even when they are legacy larch lines copied from old docs, and it ignores single-quoted or unquoted forms (`model_provider='openai-larch-env'`, `env_key='OPENAI_API_KEY'`). Login fallback can then keep env-key selectors the plan intended to strip. **Suggested fix:** Either document that only pre-table, double-quoted, exact legacy lines are removed, or broaden patterns (with fixtures) if real user configs use other quoting.

### Out-of-Scope Observations

- The plan called for harness cases where strip failure makes `external_prepare_codex_auth` return non-zero without symlinking `auth.json`; `scripts/test-lib-external-launcher-common.sh` covers happy-path strip but not corrupting inputs, multiline strings, or `mktemp`/`mv` failure. The awk path also cannot detect a bad rewrite—it only fails on I/O—so “fail closed on unsafe rewrite” is not fully enforced in code.

- `launch-review.sh` / `launch-codex-implement.sh` already use the same line-based awk pattern for `instructions` stripping; that pre-existing approach shares the multiline-string blind spot, but the new strip helper expands exposure to full copied configs and post-merge files.
