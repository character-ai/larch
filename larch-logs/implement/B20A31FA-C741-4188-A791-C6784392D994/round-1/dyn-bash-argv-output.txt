Reviewing branch changes for Bash argv construction, traps, and secret-handling correctness. Reading the precomputed diff and commit history.
### In-Scope Findings

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:288-296` — The Step 5 Codex branch builds `trust_config_arg` and `_codex_auth_args` but never loads `scripts/agent-model-args.sh --tool codex` into the `codex exec` argv. Every other wired surface in this change (implement/review/CI launchers and the health probe) passes model/effort tokens before the trust/auth `-c` overrides. With the new isolated temp `CODEX_HOME`, operators who depend on `LARCH_CODEX_MODEL` (or the default `-m` from `agent-model-args.sh`) and do not have a `~/.codex/config.toml` to copy no longer inherit the same model selection as production launchers, so review-fix Codex can run a different model or fail differently than `/design`/`/review` paths. **Suggested fix:** Mirror the launcher spine: read `agent-model-args.sh --tool codex --with-effort` into a local array and expand it before `-c "$trust_config_arg"` and `${_codex_auth_args[@]}` (with the same empty-array guard used elsewhere).

- **correctness** `scripts/lib-external-launcher-common.sh:532-545` — `external_strip_codex_larch_env_provider` only removes top-level `model_provider = "openai-larch-env"` and `env_key = "OPENAI_API_KEY"` while `in_table` is false (i.e., before the first `[…]` header). On the login branch, if a copied `config.toml` places those larch selectors after any TOML table header, they are left on disk and `auth.json` is still symlinked, so Codex can see both login material and env-key selector lines. That contradicts the intended “strip larch env-key artifacts before login symlink” contract and can force the wrong auth path. **Suggested fix:** Track “top-level” explicitly (e.g., reset a `top_level=1` flag only for lines before the first `[` header, or re-scan only the preamble region), or run a second pass that removes the three larch-owned forms anywhere outside `[model_providers.openai-larch-env]…` without treating all post-header lines as in-table.

- **correctness** `scripts/check-reviewers.sh:196-256` — `larch_run_one_codex_probe` creates `codex_home` but only removes it on normal `return` paths. The directory is not added to `PROBE_TMPFILES`, and there is no `trap … RETURN` on the function, so if the parent script’s EXIT trap runs mid-probe (signal, timeout kill while polling, etc.) before an `rm -rf "$codex_home"` line runs, `/tmp/larch-codex-probe-home-*` directories can be orphaned. The plan called for trap-backed cleanup on every probe exit path. **Suggested fix:** Register cleanup with `trap 'rm -rf "$codex_home"' RETURN` (and clear the trap on success after `rm -rf`), or append `codex_home` to a list cleaned by `larch_probe_exit_cleanup`.

- **correctness** `skills/review-and-fix/scripts/review-and-fix.sh:267-302` — Same temp-home lifecycle gap as the probe: `codex_home` is removed only on the linear path through `run_coder_dispatch`, with no `RETURN`/`EXIT` trap if `run-external-agent.sh` / `codex exec` is interrupted before line 302. **Suggested fix:** Add a function-local `trap '[[ -n "${codex_home:-}" ]] && rm -rf "$codex_home"' RETURN` (or `EXIT` scoped to the Codex branch) immediately after `mktemp -d`, and clear it after successful cleanup.
