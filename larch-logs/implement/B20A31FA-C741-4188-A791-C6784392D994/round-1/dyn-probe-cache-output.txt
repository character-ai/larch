Reviewing the branch diff and probe-cache changes for risk-integration issues.
Checking one more edge case: whether probe cleanup can be skipped on script-level abort.
### In-Scope Findings

- **risk-integration** `scripts/check-reviewers.sh:204-258` — `larch_run_one_codex_probe` creates a temp `CODEX_HOME` with `mktemp -d` but never registers it in `PROBE_TMPFILES` or a `RETURN`/`EXIT` trap that removes directories. The global `larch_probe_exit_cleanup` handler only `rm -f`s probe output files and kills PIDs; it does not `rm -rf` probe homes. Explicit `rm -rf "$codex_home"` runs only on normal return paths. Under `set -euo pipefail`, an unexpected abort after `mktemp -d` (for example a failing `rm -rf`, or script termination while the background probe is still running) can leave orphaned `/tmp/larch-codex-probe-home-*` dirs containing copied `config.toml` and, on the login branch, a symlink to `~/.codex/auth.json`. That diverges from the plan’s “trap-backed cleanup on every exit path” requirement and is a temp-state leak under failure or timeout. **Suggested fix:** Register each probe home in a cleanup list (for example append to `PROBE_TMPFILES` with a dedicated `rm -rf` loop, or use `trap 'rm -rf "$codex_home"' RETURN` at function entry) so abnormal exits and the existing EXIT handler always tear down temp auth state.

- **risk-integration** `scripts/check-reviewers.sh:312-316` — Auth-mode-aware caching bypasses only env-key **false** stamps (`external_codex_env_key_enabled && [[ "$_CACHED_C" == "false" ]]`), not env-key **true** stamps. After a successful env-key probe, `larch-codex-env-key-present-*.stamp` can keep `CODEX_PRESENT=true` for the full TTL (default 60s) even if `OPENAI_API_KEY` is revoked, rotated, or emptied mid-session. `external_launch_health_gate` and Step 0 session setup will then treat Codex as available and skip a fresh probe, while real launches on the same env-key path fail until the stamp expires. The branch introduces this mode-specific cache without a symmetric invalidation path for stale success. **Suggested fix:** Treat env-key cached `true` as a miss when auth mode or key presence changes (for example compare a cheap non-secret fingerprint such as `${#OPENAI_API_KEY}` plus stamp key), shorten TTL for `codex-env-key`, or skip caching env-key successes entirely so availability is revalidated each run.

- **risk-integration** `scripts/test-check-reviewers.sh:28-33,296-323` — The plan and `scripts/check-reviewers.md:29` require harness coverage for env-key probe behavior (stale login-mode `false` not suppressing env-key probes, temp-home cleanup on success/failure/auth-retry/helper-failure, trusted-project `-c` and auth `-c` argv parity, auth-helper failure without aborting KV emission). The branch only renames stamps from `larch-codex-present-*` to `larch-codex-login-present-*` and adds `env -u OPENAI_API_KEY` to `run_cr`; there are no tests that set `OPENAI_API_KEY`, assert `larch-codex-env-key-present-*` bypass of cached `false`, verify `-c 'projects."…".trust_level="trusted"'` / `openai-larch-env` argv wiring, or count temp probe homes before/after failure paths. Regressions in the probe-cache logic the scout notes target could ship undetected. **Suggested fix:** Add the planned fixtures to `scripts/test-check-reviewers.sh`: env-key with fresh login-false stamp still re-probes; env-key cached-false bypass; post-run assertion that no `larch-codex-probe-home-*` dirs remain under `$TMPDIR`; stubbed `external_prepare_codex_auth` failure still emits `CODEX_PRESENT=false` KVs; argv log assertions for trust and auth `-c` overrides.
