- **risk-integration** `scripts/test-launch-codex-ci.sh:171-174` — After the new env-key success case explicitly sets `OPENAI_API_KEY=sk-larch-ci-sentinel` (lines 122–123), later runtime cases (`OUT_EMPTY`, `OUT_AUTH`, `OUT_QUOTA`, etc.) invoke the launcher without `env -u OPENAI_API_KEY`. In an environment where the operator already exports `OPENAI_API_KEY`, those cases exercise the env-key branch instead of the intended login/no-key branch, so regressions in login fallback or argv-only-vs-symlink behavior would not be caught. **Suggested fix:** Wrap every non-env-key runtime invocation in `env -u OPENAI_API_KEY` (mirror `scripts/test-check-reviewers.sh` `run_cr`), and add explicit login-path assertions (`auth.json` symlink present, env-key `-c` absent, config still file-free for CI).

- **risk-integration** `scripts/check-reviewers.sh:314-316` — Auth-mode-aware stamps bypass a fresh probe only when env-key mode is active and the cached value is `false`; a fresh `true` on the `codex-env-key` stamp is still honored until TTL expiry. After a key rotation or revocation, `CODEX_PRESENT=true` can therefore persist while every wired launcher/probe attempt on the env-key path fails, delaying waterfall/degraded-panel behavior until the stamp ages out. **Suggested fix:** Treat env-key cached `true` as a miss whenever a subsequent probe/exec fails with auth-classified output (mirror the false bypass), or shorten/invalidate the env-key stamp on auth failure while leaving login-mode caching unchanged.

- **risk-integration** `skills/implement/scripts/test-codex-implementer.sh:321-374` — The primary launcher contract test now always sets `OPENAI_API_KEY="<REDACTED-TOKEN>"` and only asserts the env-key argv path (`4e`); there is no companion case with `env -u OPENAI_API_KEY` plus a fixture `~/.codex/auth.json` to verify login fallback, config-strip-before-symlink, or auth-prep failure KV/cleanup. A regression that reintroduces unconditional `auth.json` symlinks on the env-key path would not fail this harness. **Suggested fix:** Add unset/empty/login fixture cases alongside the existing env-set case, including auth-prep failure and trap/`MODEL_ARGS_TMP` cleanup assertions called out in the plan.
