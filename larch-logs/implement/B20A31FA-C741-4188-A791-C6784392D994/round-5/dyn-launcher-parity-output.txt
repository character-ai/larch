### In-Scope Findings

- **architecture** `docs/installation-and-setup.md:159-160`, `docs/external-reviewers.md:12`, `scripts/launch-review.md:37-42`, `scripts/launch-codex-implement.md:15`, `scripts/launch-codex-ci.md:18` — Operator-facing docs describe env-key mode as “non-empty” / “unset or empty,” but `external_codex_env_key_enabled` in `scripts/lib-external-launcher-common.sh:522-527` treats whitespace-only values as login fallback (same as unset). - **architecture** `scripts/test-launch-review.sh:339-409`, `scripts/test-launch-codex-ci.sh:165-220`, `skills/implement/scripts/test-codex-implementer.sh` — Launcher harnesses cover env-set, env-unset, and `OPENAI_API_KEY=""`, but not whitespace-only (`OPENAI_API_KEY=$' \t'`). Whitespace fallback is only exercised in `scripts/test-lib-external-launcher-common.sh:202-211`, so a launcher-specific regression in config copy + strip + argv wiring could slip through despite parity rule coverage on the three launchers. **Suggested fix:** Add a whitespace-only case to each launcher harness (and implementer harness if missing), asserting login branch (auth `-c` absent, `auth.json` symlink when fixture exists, no sentinel leak).
