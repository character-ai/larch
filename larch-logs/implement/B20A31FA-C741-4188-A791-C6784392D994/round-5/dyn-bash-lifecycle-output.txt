Reviewing branch changes for Bash lifecycle issues: reading the diff and inspecting trap/cleanup patterns in the touched scripts.
Reviewed the branch diff (commits from `f0cefe772` through review rounds) with focus on temp `CODEX_HOME` lifecycle, traps, `set -u`, and cleanup guards.

### In-Scope Findings

- **code-quality** `scripts/launch-codex-ci.sh:156-158` — The EXIT trap uses bare `$MODEL_ARGS_TMP` while `launch-codex-implement.sh` (updated in this branch) installs the trap earlier with `MODEL_ARGS_TMP=""` and `rm -f "${MODEL_ARGS_TMP:-}"`. Both scripts use `set -u`. Today `MODEL_ARGS_TMP` is always assigned before the trap can run, so this is latent, but if a future edit unsets or skips that assignment, the trap body can hit an unbound variable and **skip** `rm -rf "$CODEX_HOME_DIR"`, leaking `/tmp/larch-codex-ci-home-*` dirs. **Suggested fix:** Match the implement launcher: initialize `MODEL_ARGS_TMP=""` before `trap`, and use `${MODEL_ARGS_TMP:-}` / `${CODEX_HOME_DIR:-}` in the trap string (or a small cleanup function).

- **code-quality** `scripts/check-reviewers.sh:208-263` — `larch_run_one_codex_probe` eagerly `rm -rf`s `codex_home` on success, auth-retry (`return 2`), and failure, but never removes that path from `PROBE_DIRS`; cleanup depends on a second `rm -rf` in `larch_probe_exit_cleanup` on EXIT. That is usually idempotent, yet auth-retry loops can leave several stale entries in `PROBE_DIRS`, and any future logic that reuses the array before EXIT would see deleted paths. **Suggested fix:** After a successful `rm -rf "$codex_home"`, drop the matching entry from `PROBE_DIRS` (or use a per-invocation `trap 'rm -rf "$codex_home"' RETURN` and only fall back to `PROBE_DIRS` on error paths where RETURN might not run).
