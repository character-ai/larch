Reviewing the branch diff and commit history for secret-handling security issues.
### In-Scope Findings

- **security** `scripts/lib-external-launcher-common.sh:608-655` — `external_strip_codex_literal_credentials` only drops single-line, top-level `api_key` / `openai_api_key` assignments when not inside an active multiline string. For `api_key = """` / `"""` blocks it removes the opening line but still prints continuation lines, so secret material can remain in ephemeral `$CODEX_HOME/config.toml`. Provider-table `env_key = "<literal-secret>"` (any value other than the legacy top-level `OPENAI_API_KEY` name) is never removed. That conflicts with `SECURITY.md` and the plan claim that copied temp configs are scrubbed of literal credentials before launch. **Suggested fix:** Extend the strip helper (or a dedicated pass) to delete full multiline `api_key` / `openai_api_key` values and provider-scoped literal `env_key` assignments, with harness fixtures for triple-quoted and `[model_providers.*]` cases; narrow the security docs to match what is actually stripped.

- **security** `scripts/lib-external-launcher-common.sh:658-666` — `external_prepare_codex_auth` always copies/merges `~/.codex/config.toml` (launchers, probe, Step 5) and then runs the partial strip above on every branch, including env-key mode. Residual secrets in that temp file remain on disk for the Codex run lifetime under session tmpdirs (`/tmp/larch-codex-*`, probe homes, review-fix homes), widening at-rest exposure versus argv-only auth. Same-UID local readers (backups, support tooling, accidental `cat`) can read them even though `-c` overrides only pass the var name. **Suggested fix:** After copy/merge, treat any remaining credential-shaped TOML as fatal in env-key mode (fail auth prep) or run a stricter sanitizer that rewrites provider tables to env-var references only; add leak checks in `test-check-reviewers.sh` and `test-review-and-fix.sh` for nested/multiline fixtures.

- **security** `scripts/lib-external-launcher-common.sh:522-527` — `external_codex_env_key_enabled` uses `case "$OPENAI_API_KEY" in …`, which expands the full key in the shell for pattern matching. `set -x` tests pass on current Bash, but `scripts/lib-external-launcher-common.md:8` claims a length-only check “without expanding the value,” which is inaccurate and weakens the stated xtrace contract if operators rely on it for audits. **Suggested fix:** Use a value-free whitespace check (e.g. `${#OPENAI_API_KEY}` plus a small loop or `awk` length scan on the variable without tracing the value), or document that `case` expansion is in-process only; align the `.md` text with the implementation.
