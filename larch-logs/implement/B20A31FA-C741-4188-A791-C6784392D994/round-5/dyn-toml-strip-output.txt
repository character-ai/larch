Reviewing the branch diff and TOML strip helpers for correctness.
### In-Scope Findings

- **correctness** `scripts/lib-external-launcher-common.sh:608-649` — `external_strip_codex_literal_credentials` drops any non-multiline line matching `api_key` / `openai_api_key`, but when the assignment opens a TOML multiline string (`api_key = """` or `api_key = '''`), it removes only the opener, toggles multiline state, and **prints every following body line** until the closing delimiter. Copied `~/.codex/config.toml` into probe/review-fix/launcher temp homes can therefore still contain secret material after “strip,” on both login and env-key paths (`external_prepare_codex_auth` always runs this helper when `config.toml` exists). Harnesses only cover single-line literals (`scripts/test-lib-external-launcher-common.sh:214-224`). **Suggested fix:** When stripping a credential key line, detect same-line `"""` / `'''` openers (or enter a skip-until-close mode like `skip_larch_provider`) and omit the entire multiline assignment; add a harness fixture with multiline `api_key` / `openai_api_key` and assert the sentinel never remains in the rewritten file.

- **correctness** `scripts/lib-external-launcher-common.sh:597-598` — `external_strip_codex_larch_env_provider` only removes `model_provider` / `env_key` lines whose values are **double- or single-quoted** `openai-larch-env` / `OPENAI_API_KEY`. Unquoted or alternate forms (e.g. `model_provider = openai-larch-env`, bare keys, different quoting) are left in copied temp config, so login fallback can still force env-key provider selection while `auth.json` is present—the opposite of the “strip larch-owned env-key artifacts before symlink” intent. **Suggested fix:** Either extend patterns (carefully, with fixtures) to cover unquoted/basic-string forms Codex actually accepts, or document that only the documented legacy quoted shapes are stripped and treat any other `openai-larch-env` selector as operator misconfiguration.

- **correctness** `scripts/lib-external-launcher-common.sh:530-605,608-655` — Both awk rewriters always exit 0 on successful I/O; “fail closed” is only enforced for missing/unwritable paths and `mv` failure, not for unsafe or incomplete rewrites. A pathological config can therefore pass `external_prepare_codex_auth` with a partially stripped or internally inconsistent `config.toml` (including the multiline-credential case above), and call sites will still symlink `auth.json` on the login branch. **Suggested fix:** Add post-rewrite validation (e.g. reject output that still matches credential-key openers outside multiline guards, or detect unclosed `"""`/`'''` state) and return non-zero so launcher/probe/review-and-fix cleanup paths run; extend `scripts/test-lib-external-launcher-common.sh` beyond the mocked-`mv` case.

### Out-of-Scope Observations

- **correctness** `scripts/lib-external-launcher-common.sh:547-548,1184-1185` (behavior unchanged in spirit across launchers) — Table-header detection is line-anchored and does not implement full TOML; edge cases such as CRLF-terminated lines (`\r` before `$`) may leave larch selectors or legacy `env_key` lines unstripped on Windows-saved configs. Worth a fixture only if you support that environment.

- **architecture** `scripts/lib-external-launcher-common.md:9-10` vs `scripts/lib-external-launcher-common.sh:597-598` — Docs describe removing “top-level” legacy keys; the implementation strips matching lines **globally** (including under `[model_providers.other]`). That is likely desirable for login safety but is broader than the documented contract.
