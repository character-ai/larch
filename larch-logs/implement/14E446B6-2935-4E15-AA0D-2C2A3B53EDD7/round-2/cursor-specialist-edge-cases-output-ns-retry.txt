### In-Scope Findings

### FINDING_1: Unrecognized top-level `###` headings in `oos.md` discard lines without failing the compose step
- **Severity**: **Latent**
- **focus-area**: correctness
- **location**: [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh):184-208
- **issue**: For `code-review-oos`, any `### ...` line that is not `### OOS_*:` or `### FINDING_*: [OUT_OF_SCOPE]` hits the shared branch that runs `flush_pending` and `continue`, so the heading line is never appended to `pending_body` and no new `pending_id` is opened.
- **concrete scenario**: An `oos.md` that uses another heading style between blocks (for example `### Notes` as a top-level section, or a mistyped `### FINDING_1: Out of scope` without the literal `[OUT_OF_SCOPE]` token) loses that heading and following non-`###` lines until the next recognized header, producing JSONL that looks complete but omits reviewer prose.
- **suggested fix**: Mirror the `code-review-rejected` path: while `pending_id` is set, treat any inner `^###[[:space:]]` as body continuation; only call the generic `###` flush when `pending_id` is empty, or extend the OOS header regexes to cover documented variants and fail loud on unknown top-level `###` when a block is open.

### FINDING_2: Reviewer attribution uses the first anchored `Reviewer` / `**Reviewer**:` line anywhere in the pending body
- **Severity**: **Latent**
- **focus-area**: risk-integration
- **location**: [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh):74-86,127-136
- **issue**: `extract_reviewer_from_body` scans the full `pending_body` and exits on the first line matching the anchored patterns, with no fence stripping or structural guard beyond line-start anchoring.
- **concrete scenario**: A finding body that quotes a template, includes a bullet such as `- **Reviewer**: use slot output file foo.txt` as guidance, or duplicates the metadata block can attribute `reviewer` to the wrong value while still emitting a valid JSONL record, which is worse than falling back to `panel` for downstream attribution or dedupe keyed on reviewer.
- **suggested fix**: Reuse or share the stricter `reviewer_for_block` contract from [scripts/lib-vote-tally.sh](scripts/lib-vote-tally.sh) (including any fence stripping if added there), or scan only a bounded prefix of the body after the synthetic `## title` line, or prefer the last canonical attribution line if duplicates appear.

### FINDING_3: `round_num` mirrors the directory suffix verbatim (`round-01` → `"01"`)
- **Severity**: **Nit**
- **focus-area**: risk-integration
- **location**: [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh):224-228
- **issue**: `round_num` is `basename` plus a single `s/^round-//` strip, so zero-padded or non-numeric suffixes propagate unchanged into JSONL; nothing normalizes to the integer round counter used elsewhere in review scripts.
- **suggested fix**: If the contract is numeric rounds only, normalize with `10#` arithmetic or reject non-`^[0-9]+$` suffixes in CI fixtures; if heterogeneous suffixes are allowed, document that explicitly next to `round_num` in [scripts/compose-review-findings.md](scripts/compose-review-findings.md).
