### In-Scope Findings

1. **security** `python/ship.py:398-399` — `extra_fields` is merged into `fields` via `dict.update(extra_fields)` **after** all base fields are set, so any caller can silently overwrite security-sensitive keys (`PHASE`, `REPO`, `MERGE`, `FORKED_TARGET`, etc.) without any key allowlist. The sole current caller passes `{"CONFLICT_FILES": exc.conflict_csv}` which is benign, but the surface is unconstrained. **Suggested fix:** add an explicit allowlist check — e.g., `ALLOWED_EXTRA_FIELDS = {"CONFLICT_FILES"}`, raising `ShipError` if a caller supplies a key outside it.

2. **security** `python/ship.py:1131` — `exc.conflict_csv` carries git conflict file paths written unquoted into `ship-pr-state.sh` as `CONFLICT_FILES=<value>`. The newline guard at line 400-402 blocks `\n`/`\r` injection, but a filename containing a space followed by `KEY=VALUE` (e.g., `CONFLICT_FILES=a.py MERGE=false`) would survive the check and inject a second variable assignment when the state file is sourced by downstream bash. A git conflict file named `a.py MERGE=false` would overwrite `MERGE` in any shell that sources this file. **Suggested fix:** shell-quote the `CONFLICT_FILES` value (e.g., wrap in single quotes, escaping internal single quotes) or validate that `conflict_csv` contains no characters outside `[A-Za-z0-9._/,-]` before writing.

3. **correctness** `python/run_logs.py:117-118` — When `FORKED_TARGET` is present in state but holds an invalid value (neither `true` nor `false`), `_state_bool_or_default` falls back to `ctx.forked_target`, but `forked` is then set to that fallback value (`forked_target if raw_forked_target.strip() else ctx.forked`) rather than to `ctx.forked`. For the scenario `ctx.forked=True, ctx.forked_target=False, FORKED_TARGET=<garbage>`, `forked` becomes `False` instead of `True`. This incorrectly activates the main/master guard and disables gh-skipping for forked repos with corrupt state. The `test_read_durable_flags_persisted_false_overrides_stale_ctx_forked` test covers the valid-false case but not the invalid-value case. **Suggested fix:** `forked = forked_target if raw_forked_target.strip() in {"true", "false"} else ctx.forked`.

4. **latent** `python/ship.py:569` — `state_repo`, read from the state file's `REPO` field, is now passed directly to `gh.pr_view(runner, pr_number, repo=state_repo, cwd=cwd)`. This is a new data flow introduced by this diff (`import gh` is new). The state file is validated to be within the tmpdir, but a tampered state file could supply a malicious `REPO` value that flows to an external CLI invocation. The impact depends on `gh.py`'s argument handling, but this adds a new attack surface where state-file-controlled data reaches an external process without additional validation. **Suggested fix:** validate `state_repo` against the same format constraints as `ctx.repo` (e.g., `^[A-Za-z0-9._-]+/[A-Za-z0-9._-]+$`) before using it as a `gh` CLI argument.

5. **nit** `python/ship.py:715` — `_state_file_under_tmpdir` returns `True` when `state_path == tmpdir`, i.e., when the state file path is the tmpdir directory itself. A directory cannot serve as a state file and the write would fail later, but the guard is logically incorrect for this degenerate case. **Suggested fix:** change the condition to `tmpdir in state_path.parents` (drop the `state_path == tmpdir` case).
