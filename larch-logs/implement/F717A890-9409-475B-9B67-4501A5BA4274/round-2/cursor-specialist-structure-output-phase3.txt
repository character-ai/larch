### In-Scope Findings

1. **code-quality** `python/ship.py:534` — `_resume_plan` compares `resume_phase == "ship-pr-rrr-phase14"` with a hardcoded literal. `config.SHIP_PR_RRR_RESUME_PHASE` is the canonical constant (used everywhere else — `PrePushConflictHandoff`, the rebase write, and the tests). If the constant is ever renamed, the write side changes but the detection side silently stops routing `blocked-rebase-continuation`, causing the handback marker to be ignored and re-entry to fall through to `fresh` or `open-pr`. **Suggested fix:** Replace the literal with `config.SHIP_PR_RRR_RESUME_PHASE`.

2. **code-quality** `python/ship.py:957` — The open-pr branch reads `OOS_PENDING` from the state file twice. `_hydrate_resume_context` (called to build `pr_context`) already populates `pr_context.oos_pending` from state via `_state_bool_text(run_logs.read_state_kv(ctx.state_file, "OOS_PENDING"))`, so the second `or _state_bool_text(run_logs.read_state_kv(pr_context.state_file, "OOS_PENDING"))` in the condition is always redundant. **Suggested fix:** Simplify to `elif pr_context.oos_pending:`.

3. **code-quality** `python/ship.py:379,382` — `_ = step` (line 382) is a dead, misleading assignment. `step` is already consumed three lines earlier as `stall_step=step` in the `finalize.write_finalize_state` call; the `_` assignment adds no semantics but signals to readers that `step` is intentionally discarded — which it isn't. **Suggested fix:** Remove `_ = step`.

4. **code-quality** `python/ship.py:407-412` — `_write_ship_state` reads `RESUME_PHASE` and `CALLER_KIND` from the state file on every invocation where those kwargs are absent (the common path). The CI loop calls `_write_ship_state` at least once per iteration, adding 2 conditional file reads each time (up to 100 reads in a 50-iteration run). **Suggested fix:** Read `RESUME_PHASE`/`CALLER_KIND` once in `_resume_plan` or at the top of `run_ship()`, store them on the context or pass them through, and remove the in-place reads from `_write_ship_state`.

5. **latent** `correctness` `python/run_logs.py:146` — `read_durable_flags` sets `forked = forked_target if raw_forked_target.strip() else ctx.forked`. When state `FORKED_TARGET` is non-empty but invalid (neither `"true"` nor `"false"`), `forked_target` correctly falls back to `ctx.forked_target`, but `forked` also takes `ctx.forked_target` rather than `ctx.forked` (its own corresponding ctx field). The plan states "absent/empty/invalid falls back to the **corresponding** ctx field." A state file with `FORKED_TARGET=garbage` combined with `ctx.forked=True, ctx.forked_target=False` would silently clear the `forked` flag, potentially causing normal-repo gh-skip to be skipped and a protected-branch guard to be bypassed. **Suggested fix:** Change line 146 to `forked = forked_target if raw_forked_target.strip() in ("true", "false") else ctx.forked` so invalid values fall back to `ctx.forked`.

6. **nit** `code-quality` `python/ship.py:513` / `python/run_logs.py:125` — `_state_bool_text(value)` in `ship.py` duplicates `run_logs._state_bool_or_default(raw, default=False)`. Both do the identical three-way `true`/`false`/default parse. Making `_state_bool_or_default` public (rename to `state_bool_or_default`) would let `ship.py` reuse it directly. **Suggested fix:** Export `state_bool_or_default` from `run_logs` and call it from `ship.py` instead of the local copy.

7. **nit** `code-quality` `python/ship.py:932` — The bare `else` branch (`pr_context = _hydrate_resume_context(ctx, resume)`) is only reachable when `resume.start == "open-pr"` — all other starts return early above. A bare `else` hides this invariant and makes a future reader wonder what other starts could arrive. **Suggested fix:** Replace `else:` with `elif resume.start == "open-pr":` (and optionally add a final `else: raise AssertionError(resume.start)` for safety).
