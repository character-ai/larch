Reviewing the branch diff and durable-flag hydration paths for risk-integration issues.
### In-Scope Findings

- **risk-integration** `python/run_logs.py:154` — `read_durable_flags()` sets `forked=ctx.forked or forked_target`, so an explicit persisted `FORKED_TARGET=false` does not clear a stale `ctx.forked` from argv/env. That can keep `gh_skipped` true in `python/ship.py:551`, skipping `gh.pr_view` and allowing state-only `open-pr` / `merged` / `done` routing while bash resume logic uses only `read_state FORKED_TARGET` (see `scripts/ship-pr.sh:1066`). **Suggested fix:** When a state file exists, derive `forked` solely from the hydrated `forked_target` value (or a dedicated persisted `FORKED` key if you add one); use `ctx.forked` only when `state_file` is absent, matching bash parity.

- **risk-integration** `python/ship.py:789-825` — On `resume.start == "fresh"` with an existing `ship-pr-state.sh`, `run_ship()` builds `fresh_context` from argv `ctx` and never applies `resume.durable` from state. A normal-repo handback where `gh.pr_view` fails (or head/identity checks fail) therefore re-enters with stale argv defaults (`merge=True` in typical `_ctx`) even when state has `MERGE=false`, `REPO_UNAVAILABLE=true`, or `DRAFT=true`, and can incorrectly enter the merge loop or skip intended PR-only exits. **Suggested fix:** For state-present `fresh` fallbacks, hydrate mode flags from `resume.durable` (at minimum `merge`, `draft`, `repo_unavailable`, `forked`, `forked_target`) before checks/postbump/PR-only gating while still zeroing CI counters per the plan.

- **risk-integration** `python/ship.py:807-812` — The `fresh` checks-failure path calls `_write_terminal_state(fresh_context, …)` without passing restored counters, so defaults write `ITERATION=0` / `REBASE_COUNT=0` / etc. into an existing state file. After a failed resume classification (e.g. transient `gh` failure) that fell through to `fresh`, a checks stall can wipe session-wide caps that were persisted for orchestrator handback. **Suggested fix:** When `ctx.state_file` exists, pass `run_logs.read_resume_counters(ctx.state_file)` into `_write_terminal_state` / `_write_ship_state` on terminal/failure writes, or skip counter fields in the state rewrite when `fresh` is a degraded fallback rather than a true no-state start.
