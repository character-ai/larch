Reviewing branch-guard and protected-branch refusal in the diff and implementation.
### In-Scope Findings

- **security** `python/run_logs.py:120-127` — `read_durable_flags()` sets `forked=ctx.forked or forked_target`, so a stale argv/env `forked=True` (e.g. `FORKED=1` without a matching state `FORKED_TARGET=true`) still satisfies the main/master carve-out in `_resume_plan()` (`python/ship.py:537-547`) and can mark `gh_skipped` (`python/ship.py:551`). That lets a state-present resume on `main`/`master` skip protected-branch refusal and GitHub `head_ref` checks, then take the open-pr path (checks/postbump/OOS skipped) and enter CI/merge work on the default branch. **Suggested fix:** Derive resume `forked` only from hydrated state (`FORKED_TARGET=true`), not `ctx.forked`; treat absent/invalid state `FORKED_TARGET` as false for the guard even if argv still says forked. Add a regression test: state `FORKED_TARGET=false`, `ctx.forked=True`, checkout `main`, expect `blocked-checkout-mismatch` / `checkout-mismatch`, not open-pr/CI.

- **security** `python/ship.py:673-733` — `run_ship()` validates `ctx.tmpdir` with `_tmpdir_under_allowed_root()` but never constrains `ctx.state_file`. Bash enforces `--state-file` under the implement tmpdir and the same allowlist (`scripts/ship-pr.sh:3207-3212`). This branch reads/writes resume counters and durable flags from `state_file` on every re-entry; a caller-controlled path outside the session tmpdir can redirect reads/writes (including symlink targets) and supply forged `FORKED_TARGET` / `REPO_UNAVAILABLE` / `BRANCH_NAME` to bypass branch and GitHub guards. **Suggested fix:** Add `_state_file_under_tmpdir(state_file, tmpdir)` (and allowlist parity with bash) before `_resume_plan()` and `_write_ship_state()`; refuse with `STALLED`/`NEEDS_USER_INPUT` when the path is outside the session tree.

- **risk-integration** `python/ship.py:551-637` — For `repo_unavailable`, `forked`, or `forked_target` (all state-hydrated), classification skips `gh.pr_view` and trusts local `PHASE` / `PR_CLOSED` / `MERGE_RESULT` after checkout/name checks only. That matches bash’s documented operator trust in `FORKED_TARGET`, but combined with state-first hydration it means a writable `ship-pr-state.sh` can route `merged` → `run_postmerge_phase()` or `open-pr` → CI without GitHub head verification. **Suggested fix:** Document the trust boundary in `python/ship.py` / `python/README.md`; optionally require `FORKED_TARGET=true` plus a non-empty `REPO`/`upstream` signal before skipping `gh` on protected-looking branches; keep path containment so only the session owner can write state.

### Out-of-Scope Observations

- **security** `python/ship.py:492-493` — With no state file, `_resume_plan()` returns `fresh` without probing the current branch; `run_ship()` then runs checks before `finalize.postbump()`’s main/master guard (`python/finalize.py:60-61`). Resume hardening does not add an entry-level protected-branch check on the no-state path (defense-in-depth gap, largely pre-existing).

- **correctness** `python/test_ship.py` — The plan calls for a non-forked `main`/`master` safe-refuse test; only `test_forked_target_main_resume_uses_pr_only_path` covers protected-branch behavior. Missing coverage increases regression risk for the guards above but is not itself a logic defect.
