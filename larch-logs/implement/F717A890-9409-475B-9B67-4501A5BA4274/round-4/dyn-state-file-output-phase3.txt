### In-Scope Findings

- **security** `python/ship.py:~480` — `_resume_plan()`'s `blocked-rebase-continuation` early return uses `pr_url = state_pr_url or ctx.pr_url` before the `_valid_pr_url(state_pr_url)` check that appears later in the function. A state file containing `RESUME_PHASE=<rrr-phase>` together with `PR_URL=file:///etc/passwd` (or any non-HTTP(S) scheme URL) will bypass scheme validation entirely and propagate the unvalidated URL into `ShipResult.pr_url`. Note that `_read_kv_file`'s line-by-line parser prevents embedded newlines, so newline injection is not the risk; the gap is scheme/allowlist validation specifically for the `blocked-rebase-continuation` path. The same pattern applies to `state_repo` on that path (bypasses `_valid_repo_slug`), though `repo` is not surfaced in the returned `ShipResult`. JSON serialization by `emit_result` escapes most downstream rendering risks, but callers relying on `ShipResult.pr_url` as a validated URL (e.g., to open in a browser or pass to a subprocess) receive an unvalidated value. **Suggested fix:** Move the `_valid_pr_url(state_pr_url)` guard to before the `blocked-rebase-continuation` return, or explicitly clear the URL when it fails: `pr_url = (state_pr_url if _valid_pr_url(state_pr_url) else "") or (ctx.pr_url if _valid_pr_url(ctx.pr_url) else "")`. Similarly add `if not _valid_repo_slug(state_repo): state_repo = ctx.repo` before the blocked-rebase-continuation return.

### Out-of-Scope Observations

- **security** `python/ship.py` (pre-existing) — `PR_TITLE`, `ISSUE_NUMBER`, `RUN_ID`, `IMPLEMENT_TMPDIR`, and `MANIFEST_PATH` fields written by `_write_ship_state` are validated only for embedded newlines via `_validate_ship_state_value`. If any of these fields contain shell metacharacters (`$`, backtick, single quote) and the state file `ship-pr-state.sh` is ever sourced with `. state.sh` by a bash consumer rather than read key-by-key, command injection could occur. `PR_TITLE` in particular may carry user-controlled content. The new per-field validation loop is an improvement over prior code (no validation at all), but `PR_TITLE` warrants an explicit allowlist or shell-safe quoting on the write path.
