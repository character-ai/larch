### In-Scope Findings

- **risk-integration** `python/ship.py:799-807` — `_resume_plan()` catches all `gh.pr_view` failures with a bare `except Exception` and routes to `fresh`, so `TransientNetworkError` is treated like a permanent classification failure instead of the driver's normal `Outcome.TRANSIENT` handback (`_error_to_result` at `python/ship.py:115-116`). On a transient GitHub read during resume, the run resets CI-loop counters via `_fresh_resume_plan()` (`python/ship.py:568-569`), reruns checks/postbump, clears hydrated PR identity in `_hydrate_fresh_context()` (`python/ship.py:938-914`), and may call `ensure_pr()` again against an already-open PR. That undermines the branch's session-wide cap persistence and can create redundant GitHub churn after orchestrator exit-3/exit-6 re-entry. **Suggested fix:** Catch `TransientNetworkError` separately and either re-raise it (so `run_ship()` returns `Outcome.TRANSIENT`) or return a dedicated resume start that preserves restored counters without entering the fresh pipeline; reserve the `fresh` fallback for non-transient `ShipError`/malformed PR responses only.

- **risk-integration** `python/ship.py:1036-1037` — After `_resume_plan()` has already validated state/GitHub PR identity and produced a clean `resume.pr_url`, `run_ship()` still hard-fails on stale argv `ctx.pr_url` newlines before honoring `done`, `merged`, or `open-pr` routes. Resume planning correctly ignores an invalid argv URL when state/`gh.pr_view` supply a valid one (`python/ship.py:673`, `python/ship.py:700-707`), but the post-plan guard only inspects `ctx.pr_url`, so a normal-repo resume with `PHASE=ci-initial`, valid state `PR_URL`, and matching `gh.pr_view` head can still stall even though GitHub authority already selected `open-pr`. `python/test_ship.py:996-1013` encodes this behavior, but it conflicts with the state-first hydration contract in the plan. **Suggested fix:** Validate the URL that will actually be written/used (`resume.pr_url`, or hydrated `working.pr_url` after `_hydrate_resume_context()`), or skip the newline guard when `resume.start` is a non-fresh resume with a validated `resume.pr_url`.
