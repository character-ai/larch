Reviewing the branch diff and commit history for shell-state serialization and validation security issues.
### In-Scope Findings

- **security** `python/run_logs.py:134-156`, `python/ship.py:759-847` — `read_durable_flags()` lets `ship-pr-state.sh` alone elevate `FORKED_TARGET=true` and `REPO_UNAVAILABLE=true` even when argv/context still say non-forked / repo-available (`test_forked_target_main_resume_uses_pr_only_path` resumes on `main` with only state `FORKED_TARGET=true`). That disables the non-forked `main`/`master` guard and forces `gh_skipped` routing, so a tmpdir writer can resume open-PR/CI without `gh.pr_view` head verification. With `MERGE=true` in state this can re-enter the merge loop on `main` using unverified `PR_NUMBER`/`BRANCH_NAME`. **Suggested fix:** Treat those flags as security-sensitive: only honor state values when context corroborates them (e.g. refuse resume if state sets `FORKED_TARGET=true` but `ctx.forked_target`/`ctx.forked` are false; likewise for `REPO_UNAVAILABLE`), or safe-refuse on any durable-flag elevation mismatch—mirror the existing `state_repo == ctx.repo` gate.

- **security** `python/ship.py:633-634`, `python/ship.py:464-472`, `python/ship.py:672-673` — `_PR_URL_RE` accepts URLs containing `$`, `(`, and `)`, so values like `https://example.com/$(id)` pass `_valid_pr_url()` and can be read from tampered state, carried through open-pr/gh-skipped resume, and rewritten into `ship-pr-state.sh`. Bash consumers use awk + quoting (not `source`), but the new validator still allows command-substitution-shaped payloads—a footgun for any future unquoted consumer. **Suggested fix:** Tighten validation (reject `$`, backticks, and unbalanced parentheses; or parse with `urllib.parse` and allow only `http`/`https` with a conservative host/path charset), and add a regression test that such URLs are stripped or trigger safe-refuse on resume.

### Out-of-Scope Observations

- **Pre-existing write-path gaps:** `_validate_ship_state_value()` still only bounds `BRANCH_NAME`, `PR_URL`, and `MERGE_RESULT` (plus newlines). `REPO`, `PR_TITLE`, `IMPLEMENT_TMPDIR`, and `MANIFEST_PATH` are written without format checks on the fresh path; bash’s contract (never `source`, awk reads, quoted expansion) mitigates execution risk, matching `scripts/test-implement-finalize.sh` injection-as-data behavior.

- **Intentional open-pr OOS skip:** Open-PR resume deliberately bypasses `_materialize_manifest_oos` / `_pending_oos_gate` per plan; that is a workflow-integrity trade-off under a trusted session tmpdir, not a new shell-injection surface.

- **Good hardening in this branch:** State file must stay under tmpdir; `REPO` slug + ctx agreement on resume; branch/PR/MERGE_RESULT validation; `CONFLICT_FILES` path traversal checks; blocked-rebase continuation sanitizes bad `PR_URL`; newline rejection on state writes.
