### In-Scope Findings

- **correctness** `python/ship.py:849-876` — In gh-skipped resume (`repo_unavailable` / `forked` / `forked_target`), `local_merged` treats manifest `status=done` as sufficient on its own (`manifest_status(ctx) == config.MANIFEST_STATUS_DONE and pr_number is not None`), so a run still at `PHASE=ci-initial` (or any non-`postmerge`/`done` phase) can be classified as `merged`, enter `run_postmerge_phase`, and—if postmerge returns OK—write `PHASE=done` even though CI/merge work was never finished. That contradicts the plan’s restricted manifest-DONE rule and the accepted round-2 finding that manifest DONE must agree with phase/`PR_CLOSED`/`MERGE_RESULT` before routing to postmerge; `python/test_ship.py:799-824` currently locks in this behavior. **Suggested fix:** Only count manifest DONE toward `local_merged` when at least one agreeing predicate is already present (`PHASE` in `postmerge`/`done`, `PR_CLOSED=true`, or `MERGE_RESULT` in `POST_MERGE_MERGE_RESULTS`); otherwise ignore manifest for merged routing and fall through to `open-pr`/`fresh`. Replace `test_gh_skipped_resume_uses_done_manifest_as_merged_signal` with a negative case (`PHASE=ci-initial` + manifest DONE → must not run postmerge/write done) plus a positive case where manifest DONE agrees with `PHASE=postmerge` or `PR_CLOSED=true`.

- **correctness** `python/ship.py:1046-1066` — The new `merged` resume path writes `PHASE=done` whenever `run_postmerge_phase` returns `Outcome.OK`, but `finalize.postmerge` returns OK for `merge=false` (`skipped-merge-false`) without running teardown or verifying main. Combined with the manifest-DONE routing above, a gh-skipped resume with `MERGE=false`, `PHASE=ci-initial`, and a premature manifest `done` can skip real postmerge yet still persist terminal `PHASE=done`, falsely marking an incomplete run complete on the next idempotent `done` resume. **Suggested fix:** Before writing `PHASE=done` on the merged-resume path (and symmetrically on the main CI success path if needed), require hydrated `working.merge` and a substantive postmerge completion signal (e.g., postmerge status not in the skip set, or presence of `post-merge-sentinel` after a real postmerge). If postmerge was skipped, preserve `PHASE=postmerge` (or the prior phase) and return a non-OK/handback outcome instead of `done`.

### Out-of-Scope Observations

- **correctness** `python/finalize.py:136-151` — `postmerge` reports `Outcome.OK` even when `verify_main_status` is `"unexpected"` or branch cleanup is only `"partial"`; that predates this branch and is not worsened by the resume work, but it can still let the new merged-resume and CI-success paths write `PHASE=done` while main verification failed.
