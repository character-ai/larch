Reviewing the branch diff and commit history for CI-loop counter correctness.
### In-Scope Findings

- **correctness** `python/ship.py:1336-1342` — The CI loop increments `iteration` whenever `monitor.did_fixing` or `monitor.transient_rerun_attempted` is set, but bash only bumps `ITERATION` on rebase paths (`scripts/ship-pr.sh` at the `run_rebase_rebump` / fork `rebase` handlers). Fix-only and transient-rerun cycles advance `FIX_ATTEMPTS` / `TRANSIENT_RETRIES` in bash without touching `ITERATION`. Because this branch now restores and persists counters across exit-3/exit-6 handbacks, those extra `iteration` bumps accumulate session-wide and can trigger `ci_monitor.decide()` timeout (`iteration >= 50`) or the ship merge-loop cap (`iteration > 50`) earlier than bash would. **Suggested fix:** Restrict `iteration += 1` to rebase-consuming paths only (i.e., after a successful `goto_rebase` / rebase action), matching bash. Keep `fix_attempts` / `transient_retries` updates separate, and do not increment `iteration` for fix-only or transient-rerun continuations.

- **correctness** `python/run_logs.py:171-175` — `manifest_status()` resolves the manifest path from `ctx.run_id` only, while the rest of the run-log stack (`effective_run_id()`, `_manifest_path()`) prefers `RUN_ID` from `ship-pr-state.sh` when present. On gh-skipped resumes (`repo_unavailable` / `forked` / `forked_target`), `_resume_plan()` uses `manifest_status(ctx)` as a merged signal; if the orchestrator’s `ctx.run_id` diverges from the persisted state `RUN_ID`, manifest `DONE` is missed and a post-merge run can be misclassified as `open-pr` instead of `merged`. **Suggested fix:** Build the manifest path with `effective_run_id(ctx)` (same contract as `_manifest_path()`), and add/adjust a test where state `RUN_ID` and `ctx.run_id` differ to prove gh-skipped merged routing still sees manifest `DONE`.

### Out-of-Scope Observations

- **correctness** `python/ship.py:927-941` — `_monitor_persisted_counters()` increments `fix_attempts` whenever `monitor.did_fixing` is true, including terminal handbacks like `first-fixer-non-health`. Bash exits 3 on that path without bumping `FIX_ATTEMPTS` (`scripts/ship-pr.sh` around the `first-fixer-non-health` bail). With persisted counters this can edge toward `fix-attempts-exhausted` sooner than bash, though `python/test_ship.py:1175-1217` currently encodes the Python behavior as intended.

- **correctness** `python/ship.py:1336-1341` — The `monitor.action == "wait"` branch in the iteration-increment guard is effectively dead on the real path because `poll_ci()` spins until a non-`wait` decision; only stubbed tests exercise `action="wait"`. Harmless but misleading for cap reasoning.
