Tracing artifact flow and checking for gaps: other launchers, collector paths, and test harness ordering.
Branch commits: `7bf8262b4` (fix), `4f03282db` (run log), `929867c22` (relevant-checks).

### In-Scope Findings

- **correctness** `scripts/test-lint-fix-loop.sh:9-10` — The new static `--stderr-sink` pin calls `fail` before `fail()` is defined at line 15. If `grep` fails (pin removed or typo), the harness exits with `fail: command not found` (127) instead of a clear assertion, so the regression guard is self-defeating when it matters most. **Suggested fix:** Move the `grep -F` block to after the `fail()` helper (same pattern as other assertions in the file), or use `printf 'FAIL: ...\n' >&2; exit 1` inline until helpers exist.

- **correctness** `skills/review-and-fix/scripts/test-review-and-fix.sh:14-15` — Same ordering bug: the `--stderr-sink` source pin invokes `fail` at line 14 while `fail()` is not defined until line 49. A failed `grep` produces a shell error rather than the intended test failure message. **Suggested fix:** Relocate the pin after the `fail()` / `pass()` helpers (e.g., immediately before the first section that exercises `run_coder_dispatch`), keeping the check early enough to fail fast without referencing undefined functions.

- **architecture** `scripts/run-external-agent.sh:79,464-467` — Artifact flow now depends on a dual contract: callers must both redirect fd2 to the custom sink *and* pass the same path via `--stderr-sink`; the wrapper validates path shape only, not that it matches the live fd2 target. A drifted launcher (wrong variable, stale path, or flag without `2>` redirect) silently reverts to `.sidecar` → `${output}` → `.diag` selection—the exact latent failure mode #3218 addresses— with no error at launch. **Suggested fix:** Treat this as a documented launcher invariant (already partly in `run-external-agent.md`); consider a dev-only assert (e.g., compare inode of `--stderr-sink` to `/proc/self/fd/2` on Linux) or extend static pins to every default-mode codex caller; at minimum add `lint-fix-loop` / `review-and-fix` to the “Call sites” section in `run-external-agent.md` so the obligation is discoverable without reading each launcher `.md`.

- **code-quality** `scripts/run-external-agent.sh:31-32` — The header `# Usage:` comment still omits `[--stderr-sink PATH]` while `usage()`, the `# Options:` block, and `run-external-agent.md` were updated. That splits the contract across layers and can mislead readers tracing artifact priority from the script header alone. **Suggested fix:** Align the header `# Usage:` line with `usage()` and the markdown contract.
