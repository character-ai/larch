### In-Scope Findings

- **risk-integration** `scripts/test-lint-fix-loop.sh:9-18` — The new static pin runs `grep … || fail "…"` before `fail()` is defined (lines 15–18). While the pin passes today, a regression that removes `--stderr-sink` from `run_codex` does not produce the intended `FAIL: lint-fix-loop.sh run_codex must forward …` message; Bash reports `fail: command not found` (exit 127) instead, so the harness fails opaquely exactly when the contract check matters. **Suggested fix:** Move the `grep -F` block to immediately after the `fail()` helper (or use an inline `|| { echo "FAIL: …" >&2; exit 1; }` like `test-codex-implementer.sh` does) so the pin’s failure path is self-contained and readable.

- **risk-integration** `skills/review-and-fix/scripts/test-review-and-fix.sh:14-52` — Same ordering bug: the `--stderr-sink "$codex_wrapper_log"` pin at lines 14–15 calls `fail` before `fail()` exists at lines 49–52. Sharded targets such as `test-review-and-fix-dispatch` always execute this grep first, so a forwarding regression surfaces as `command not found` rather than a labeled harness failure. **Suggested fix:** Relocate the grep pin below `fail()`/`pass()` definitions, or replace `|| fail …` with an explicit `if ! grep …; then echo …; exit 1; fi` block.

- **risk-integration** `scripts/test-run-external-agent.sh:429-442,465-489` — Case 19f proves the non-zero-exit `.stderr-tail` path with `--stderr-sink` plus `2>"$sink"`, but the only timeout `.stderr-tail` case (19c) still uses `--capture-stdout`, not default mode with `--stderr-sink`. Both production call sites in `scripts/run-external-agent.sh` pass `"$STDERR_SINK"` on timeout and failure; a timeout-only regression (e.g. dropping the 4th arg on the timeout branch) would not be caught by the new integration coverage. **Suggested fix:** Add a sibling case (e.g. 19h) mirroring 19f: default mode, `--stderr-sink` + outer `2>"$sink"`, short timeout, child writes a distinctive stderr marker to the sink, then assert `${output}.stderr-tail` contains that marker and not pre-seeded `.diag` boilerplate.
