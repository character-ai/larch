Reviewing branch changes for schema compatibility: reading the diff, commit history, and key token-report files.
### In-Scope Findings

- **architecture** `scripts/token-report.sh:482-486,731` — The new `--summary` JSON shape for `claude_sub` only carries `input`, `cache_read`, and `output`, while the main `claude` lane includes `cache_write_5m` / `cache_write_1h`; the shell rollup at line 731 sums those three fields only. Spawned-Claude ledger rows record `cache_create` (folded into `BUCKETS_claude_sub.cache_create_5m` in full JSON), so the per-lane `Claude (subprocess): …k` breadcrumb undercounts whenever cache-creation tokens are non-zero, even though `token_total` and `claude_sub_ledger_total` are correct. **Suggested fix:** Extend the summary `claude_sub` object with cache fields (e.g. `cache_write_5m`/`cache_write_1h` mirroring `claude`, sourced from ledger `cache_create`), include them in `cs_raw`, and add a harness case with non-zero `cache_create` that asserts the subprocess lane k-total matches `claude_sub_ledger_total`.

- **risk-integration** `skills/implement/scripts/write-final-report.sh:248-254` — The corrupt-zero guard still treats “all zeros” as corruption using only `claude`, `codex`, and `cursor`; it never consults `claude_sub` / `BUCKETS_claude_sub`. A run whose only non-zero spend is spawned-process Claude (`claude.totals.total == 0` but `claude_sub.totals.total > 0`) can be misclassified as corrupt and emit `Cost: N/A` whenever `.codex` or `.cursor` sibling objects exist with zero totals (common when externals were probed but subprocess Claude did the work). **Suggested fix:** Add a `claude_sub` presence/total term to the jq predicate (e.g. exempt corrupt-zero when `(.claude_sub.totals.total // 0) > 0` or `BUCKETS_claude_sub.total > 0`) and cover it in `test-write-final-report.sh` with a subprocess-only fixture.

- **architecture** `scripts/test-token-report.sh:59-75` — Full JSON now always emits `BUCKETS_claude_sub` (even all-zero) per `report_json`, but the baseline shape test still pins only the three legacy `BUCKETS_*` keys and never asserts `BUCKETS_claude_sub` presence or zero defaults. A regression that drops the fourth bucket from persisted `token-report.json` / `token-report-final.json` would not fail this harness, breaking downstream parsers (`write-final-report.sh`, `render-final-summary.sh`, `report_tokens_cost.py`) that rely on the key when present. **Suggested fix:** Extend the baseline jq assertion with `(.BUCKETS_claude_sub.total == 0)` (and optionally key-existence checks) so every full-json render is pinned to the four-bucket contract.

- **architecture** `scripts/test-token-report-summary-format.sh:26-28` — Documentation and `token-report.md` now require the `--summary` line to include `Claude (subprocess)`, but the format harness still only checks for `Claude` / `Codex` / `Cursor` substrings. The subprocess lane label and ordering are therefore unenforced despite being part of the persisted/display schema contract. **Suggested fix:** Require `Claude (subprocess):` in the summary line (matching the updated doc string) and add a fixture ledger row with `vendor":"claude_sub"` so the lane is non-zero in the assertion.
