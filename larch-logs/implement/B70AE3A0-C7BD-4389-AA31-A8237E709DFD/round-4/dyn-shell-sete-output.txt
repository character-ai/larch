### In-Scope Findings

NO_ISSUES_FOUND

The branch correctly fixes finding #1: `_inv_apply_routing_line_if_empty` used `[ -z "${KEY:-}" ] && KEY="$_inv_value"` inside `case` arms, so when file-first parsing had already set a key, the failed `[ -z … ]` test made the function return status 1. Under `set -e` (enabled in `skills/implement/SKILL.md` immediately before sourcing at lines 310–318 and 355–364), the stdout-fallback `while` loop then aborted a successful Step 0 with exit 1.

The fix adds trailing `return 0` to both helpers (`scripts/parse-bootstrap-routing-envelope.sh:70`, `107`), which normalizes success for “already populated, skip assignment” without weakening real failures (`unknown argument` still `return 1` at line 27). Early exits (`[ -z "$_inv_line" ]`, disallowed keys, empty `coder`/`coder_fallback`, `--preserve-coder` skips) were already `return 0`.

`scripts/test-parse-bootstrap-routing-envelope.sh` reproduces the soak scenario: `set -euo pipefail`, a regular `bootstrap-routing.env` pre-populating keys, then stdout lines for the same keys—default and `--preserve-coder`. That matches the only failure mode (duplicate stdout fallback after file-first), and Makefile registration closes the loop.
