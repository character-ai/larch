Reviewing the branch diff and Python 3.11 floor changes for risk-integration issues.
### In-Scope Findings

- **risk-integration** `docs/configuration-and-permissions.md:195-197` — The `LARCH_SHIP_PR_IMPL` section documents switching to `python/ship.py` but does not state the Python ≥3.11 runtime requirement that `skills/implement/SKILL.md` enforces in the Step 8+ bash fence (`sys.version_info >= (3, 11)`). Operators who enable `LARCH_SHIP_PR_IMPL=python` from configuration docs alone may use an unsupported `python3` and only hit a mid-ship failure at Step 8 instead of seeing the prerequisite up front. **Suggested fix:** Add an explicit bullet under `LARCH_SHIP_PR_IMPL` that the python driver requires `python3` ≥3.11 (same probe/error text as the skill), and point to `docs/installation-and-setup.md` for the runtime vs contributor-tooling split.

- **risk-integration** `skills/report-tokens/SKILL.md:1-34` and `skills/report-tokens/scripts/run-analysis.md:1-21` — `/report-tokens` prerequisites were updated in `docs/installation-and-setup.md:96` and enforced in `skills/report-tokens/scripts/run-analysis.sh:74-75`, but the user-facing skill and its script contract still omit any Python version requirement. That leaves a doc surface that points operators at `run-analysis.md` without stating the 3.11 floor, so skill-only readers can miss the requirement until the wrapper exits. **Suggested fix:** Add a short “Prerequisites” note to `skills/report-tokens/SKILL.md` (Python 3.11+, link to installation docs) and mirror the same requirement in `run-analysis.md` under Inputs/Prerequisites so the three surfaces stay aligned.

- **risk-integration** `Makefile:30-34`, `scripts/relevant-checks.sh:47-77` — CI now proves 3.11 compatibility via the `python-lint` / `python-tests` matrix, but local `make py-test` and relevant-checks’ direct `py-test` target still run `pytest` on whatever interpreter owns the tools on PATH, with no `python3 ≥ (3,11)` probe matching the runtime entrypoints. A host with `python3` 3.10 and a stray `pytest` on PATH can run tests locally (or during `/implement` relevant-checks) without the same floor guarantee CI provides, weakening the “3.11 compliance” story outside the matrix jobs. **Suggested fix:** Add a shared small probe (or Makefile guard) before `py-test` / relevant-checks `py-test` dispatch, or document that only CI matrix jobs are authoritative for 3.11 verification and local runs require an explicit 3.11+ `python3`.
