Reviewing the branch diff and `python/run_logs.py` porcelain/cleanup logic.
### In-Scope Findings

- **correctness** `python/run_logs.py:881-898` — `_cleanup_volatile_run_tree` uses `"A" in line[:2]` as a proxy for “index-added, use `git clean` not `git restore`”. That is a substring test on the two-character status field, not a check of the index column. Combined states such as `AM`, `AU`, and `AD` also contain `A`, so those lines are excluded from `tracked_paths` and sent to `clean_paths` instead. After `has_staged` runs `git reset HEAD -- <rel>`, an `AM` refresh sidecar often becomes a tracked worktree modification that `git clean -fd` does not clear; the final repo-wide `git status --porcelain` then fails the empty-porcelain assertion and raises `ShipError`, so volatile-only refresh churn can stall instead of taking the `larch-log-volatile-only` no-commit path. Tests only cover `??`, ` M`, and bare `A `, not `AM`. **Suggested fix:** Classify by porcelain status codes the way `version_bump.py` does with `line[:2]` (e.g. treat index-added as `line[0] == "A"` for clean-only routing, or explicitly enumerate `("A ", "AM", …)`), and/or re-read porcelain after `git reset` before choosing restore vs clean. Add a regression test with `AM …/token-report-refresh.json` that must end in a volatile-only skip with empty repo-wide porcelain.

- **correctness** `python/run_logs.py:816-822` — `_status_line_path` takes `line[3:].strip()` and handles renames via ` -> `, but never removes Git’s optional double-quotes around paths with spaces or other special characters (`git status --porcelain` quoting per `gitstatus(5)`). A line like `?? "larch-logs/implement/<run-id>/token-report-refresh.json"` yields a path that still includes `"`, so `path.startswith(f"{rel}/")` and allowlist checks in `_volatile_file_paths` fail, the function returns `None`, and `_larch_log_commit` falls through to `git add`/`git commit` instead of volatile-only cleanup—reintroducing flush-commit divergence when quoted paths appear. **Suggested fix:** After extracting the path, strip a single pair of surrounding `"` characters (and document that tab-quoted paths are out of scope if you do not implement full `gitstatus` unquoting). Add unit tests for quoted `??` and ` M` refresh-sidecar lines that must classify as volatile-only.

- **correctness** `python/run_logs.py:831-833` — `_volatile_file_paths` returns `None` whenever `_status_line_path` yields an empty path (including blank or malformed porcelain lines). That aborts the volatile-only fast path and forces a normal flush commit. That is conservative for “do not skip cleanup incorrectly,” but it is fail-open toward committing when parsing is brittle (quotes, unexpected rename shapes, stray blank lines in captured status output), which works against O1’s goal of skipping refresh-only churn. **Suggested fix:** Distinguish “definitely not volatile-only” (a non-allowlisted path under `rel/`) from “cannot classify” (return `None` only on empty `status_stdout` or invalid `rel`; for unparseable lines, either fail closed with `ShipError` before commit or skip the line if all other lines are allowlisted volatile paths). Add tests for blank-line and quoted-path inputs to pin the intended behavior.

### Out-of-Scope Observations

- No direct unit tests for `_status_line_path`, `_volatile_file_paths`, or rename (`R  old -> new`) porcelain lines; existing `python/test_run_logs.py` coverage stops at `??`, ` M`, `A `, and fail-closed dirty-repo/git-failure cases.
- `python/version_bump.py:363-371` already parses porcelain with explicit `line[:2]` status codes (`AU`, `UU`, etc.); the volatile cleanup path does not reuse that pattern, which contributed to the `"A" in line[:2]` bug above.
