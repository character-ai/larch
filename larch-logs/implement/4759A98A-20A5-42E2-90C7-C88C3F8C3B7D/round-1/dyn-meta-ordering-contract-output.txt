### In-Scope Findings
- **correctness** `scripts/test-collect-agent-retry.sh:896-898` — The new `assert_meta_stderr_sink_before … CMD_JSON` check on the CMD_JSON retry path is tautological, not a runtime forwarding contract. That retry path invokes real `scripts/run-external-agent.sh` directly (via `collect-agent-results.sh` `RETRY_ARGS` at `scripts/collect-agent-results.sh:687-744`) and never calls `*_launcher_append_outer_meta`, so the retry `.meta` is written only by `run-external-agent.sh` in a fixed block where `STDERR_SINK=` (lines 199–201 of `scripts/run-external-agent.sh`) always precedes `CMD_JSON=` (line 202). Whenever the preceding `grep -Fxq "STDERR_SINK=$SINK_CMD_JSON"` passes, the ordering assertion must also pass regardless of whether `RETRY_ARGS+=(--stderr-sink …)` forwarding regressed. It therefore adds no regression signal beyond the presence check and can read as validating wrapper ownership when no wrapper participates. **Suggested fix:** Drop the CMD_JSON ordering assertion, or replace it with a check that actually distinguishes forwarding paths—for example assert `^STDERR_SINK=` appears before the first `^OUTER_LAUNCHER=` on outer-launcher retry metas only (already done at `scripts/test-collect-agent-retry.sh:848-850` / `877-879`), or add a test-only `run-external-agent.sh` shim that logs argv and assert `--stderr-sink` is present on the CMD_JSON retry invocation.

### Out-of-Scope Observations
The outer-launcher ordering assertions in `scripts/test-launch-review.sh:99-109` / `1398-1400` and `scripts/test-collect-agent-retry.sh:75-87` / `848-850` are a reliable proxy for the intended contract, not vacuous. Runtime sequencing is guaranteed: `run-external-agent.sh` writes base meta (including optional `STDERR_SINK=`) with `>` at `scripts/run-external-agent.sh:193-203`, then `launch-review.sh` appends outer keys via `external_launcher_append_outer_meta` (`scripts/lib-external-launcher-common.sh:26-32`) after the agent run at `scripts/launch-review.sh:605` / `1030`. A regression where only the 6th append arg carried the sink (and `_RUN_EXTERNAL_SINK_ARGS` did not reach `run-external-agent.sh`) would leave the sole `STDERR_SINK=` after `OUTER_LAUNCHER=` and fail the ordering check, while the companion `grep -Fxq` presence check alone could still pass—so the outer-launcher pairing is doing real work.

The codex hand-assembled fixture at `scripts/test-collect-agent-retry.sh:858-868` (input `.meta` puts `OUTER_LAUNCHER=` before `STDERR_SINK=`) does not make the outer-retry ordering assertion tautological: the assertion targets `${OUT%.txt}-retry.txt.meta` produced by a live `launch-review.sh` retry, not the hand-built input sidecar. Input key order is immaterial because `collect-agent-results.sh` parses keys line-by-line (`scripts/collect-agent-results.sh:517-533`).
