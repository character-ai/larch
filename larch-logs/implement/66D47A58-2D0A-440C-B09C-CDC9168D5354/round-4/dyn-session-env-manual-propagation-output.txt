### In-Scope Findings

- **risk-integration** `scripts/write-design-current-env.sh:126` — The writer only emits `export MANUAL_REQUESTED=…` when `--manual-requested` is non-empty; an omitted flag rewrites the file without that line but never emits `unset MANUAL_REQUESTED`. In bash, `source` does not clear a variable that was already set in the **same** subshell, so a second `source` after true→omitted rewrite can leave `MANUAL_REQUESTED=true` even though the file no longer exports it. Case 12 only checks a **fresh** subshell (`test-write-design-current-env.sh:282-288`), so it validates on-disk shape, not same-shell re-source semantics. `/design` normally gets a new Bash subshell per tool call (`skills/design/SKILL.md:69`), which limits exposure, but any block that sources twice after rewriting session env (or hand-rolled harnesses) can hit sticky manual mode via `approval-gates.md:78`’s first precedence rule. **Suggested fix:** When `--manual-requested` is omitted, write `unset MANUAL_REQUESTED` into the generated env file (or document that omission is only safe across subshell boundaries and add a harness case that re-sources in the **same** subshell after true→omitted rewrite).

- **risk-integration** `SECURITY.md:39` vs `skills/design/references/approval-gates.md:78` — SECURITY says runs without a known `--manual` request “may fall back to auto-apply” when `run-params.json` or `jq` is unavailable; Gate B mode resolution instead fails closed to `manual_gate_b=true` whenever persisted `false` cannot be confirmed (warning + manual prompts).
