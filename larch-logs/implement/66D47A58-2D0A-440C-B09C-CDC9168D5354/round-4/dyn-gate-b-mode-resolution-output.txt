### In-Scope Findings

- **correctness** `skills/design/references/approval-gates.md:76-121` — Gate B’s normative execution order says mode resolution runs only after the zero-findings short-circuit (“below”), but the file layout places `#### Gate B mode`, `### Presentation`, and `### Prompt` (all of which assume `manual_gate_b` is already resolved) *before* `### Zero-findings short-circuit`. An executor that follows `approval-gates.md` top-to-bottom can run presentation/auto-apply logic (and even touch `run-params.json` via the jq read in step 3 of the precedence chain) before proving `accepted-plan-findings.md` is non-empty, violating the plan’s “short-circuit before mode branch” invariant and doing unnecessary work on the zero-findings path. `SKILL.md` Step 3.5 states the correct order, but `approval-gates.md` is the binding Gate B body and currently contradicts itself. **Suggested fix:** Move `### Zero-findings short-circuit` to the top of the Gate B section (immediately after the severity rubric), or add an explicit numbered “Gate B execution order” block (1. zero-findings check → 2. mode resolution → 3. presentation → 4. prompt/apply) and keep subsection order aligned with that list.

- **correctness** `skills/design/references/approval-gates.md:78` vs `SECURITY.md:39` — The fail-closed fallback says that when `run-params.json` cannot be read, `jq` is unavailable, or `manual_gate_b=false` cannot be proven, Gate B must **fail closed to `manual_gate_b=true`** (manual prompts). `SECURITY.md` states the opposite for runs without a known manual request: “only runs without a known manual request may **fall back to auto-apply**.” On a default (no `--manual`) run where `MANUAL_REQUESTED` was not stamped and `jq` is missing at Step 3.5, the precedence chain cannot prove `false`, so the fail-closed path forces manual mode — not auto-apply. That is reachable after the zero-findings short-circuit passes (findings exist, session env has no `MANUAL_REQUESTED=true`, in-memory `manual_requested` is unbound in a fresh Bash subshell). **Suggested fix:** Pick one degraded-mode contract and align both surfaces. If security intent is “don’t auto-apply untrusted findings without provable opt-in,” update `SECURITY.md` (and any operator-facing docs that still say “defaulting to auto-apply”) to document fail-closed-to-manual. If product intent is “default stays auto-apply when persistence is unreadable,” change the fail-closed branch in `approval-gates.md` to default `manual_gate_b=false` with the warning, while still honoring `MANUAL_REQUESTED=true` / in-memory `manual_requested=true` overrides.
