## Review summary

Branch `a2e2df06` (plus version bump `1b0742f8`) implements NOT_SUBSTANTIVE outer-launcher retry in [`scripts/collect-agent-results.sh`](scripts/collect-agent-results.sh), dead-slot scoreboard rows + banner wiring in [`skills/review/scripts/tally-code-votes.sh`](skills/review/scripts/tally-code-votes.sh) / [`skills/review/scripts/review-core.sh`](skills/review/scripts/review-core.sh), and explicit `NOT_SUBSTANTIVE_SLOTS` accounting in [`skills/review/scripts/check-reviewer-failure-threshold.sh`](skills/review/scripts/check-reviewer-failure-threshold.sh). Regression coverage was extended in the test harnesses. Several failure-mode and contract gaps stand out relative to the stated plan and downstream consumers.

### In-Scope Findings

1. **Important** — **architecture** — [`scripts/collect-agent-results.sh:892-1041`](scripts/collect-agent-results.sh) vs implementation plan Fix A: The plan called for a `CMD_JSON` / `run-external-agent.sh` retry when `OUTER_LAUNCHER` metadata is absent. Section 3.7 only retries when `.meta` has a real `OUTER_LAUNCHER` plus prompt/workdir. Slots that are substantive-valid but only have `CMD_JSON` (or missing `.meta`) stay `NOT_SUBSTANTIVE` with no recovery, so behavior diverges from the documented contract and leaves a class of failures unhandled.

2. **Important** — **correctness** — [`scripts/collect-agent-results.sh:857-890`](scripts/collect-agent-results.sh) then [`scripts/collect-agent-results.sh:1026-1035`](scripts/collect-agent-results.sh): When both substantive and structured validation run, an entry can become `NOT_SUBSTANTIVE` in section 3.6 for missing/invalid structured sidecars while the prose file still passes substantive checks. The NOT_SUBSTANTIVE retry only runs `validate-research-output.sh` without `--structured-reviewer-mode` / `--write-structured`. A retry that passes substantive validation rewrites the row to `STATUS=OK` pointing at `-ns-retry.txt` without re-running structured validation or restoring `STRUCTURED_SIDECAR`, so the pipeline can accept a row that downstream structured consumers still treat as incomplete.

3. **Important** — **risk-integration** — [`skills/review/scripts/tally-code-votes.sh:382-437`](skills/review/scripts/tally-code-votes.sh): Dead-slot rows default `STATUS=NOT_SUBSTANTIVE` whenever the manifest basename is absent from `score_rows` and missing from the collector-derived map (e.g. never-launched slot with no collector record, basename normalization mismatch, or `FAILED`/`timeout` without a mapped entry). The scoreboard and banner text then attribute narrative-only failure to slots that actually failed for other reasons, which misleads triage and can disagree with `check-reviewer-failure-threshold.sh` semantics.

4. **Important** — **risk-integration** — [`scripts/test-collect-agent-results.sh:258-290`](scripts/test-collect-agent-results.sh) and [`scripts/collect-agent-results.sh:1009-1011`](scripts/collect-agent-results.sh): `C_NS_RETRY` installs an executable fake `OUTER_LAUNCHER` that exits without writing `-ns-retry.txt` or its `.done` sentinel, so `wait-for-reviewers.sh` still runs until `--timeout` reaches `TIMEOUT+60` (here up to **120s** wall clock per harness invocation). The test always passes via the “sentinel absent” branch and does not assert retry success, validator interaction, or updated `REVIEWER_FILE`, so it does not pin the new behavior and can materially slow CI.

5. **Latent** — **risk-integration** — [`skills/review/scripts/tally-code-votes.sh:351-377`](skills/review/scripts/tally-code-votes.sh) vs appended dead rows: Live scoreboard rows end with a numeric `Score` column; appended dead rows replace that column with `STATUS=…`. Any consumer that assumes column 11 is always numeric (sorting, awk, spreadsheets) can mis-parse appended rows.

6. **Nit** — **code-quality** — [`scripts/test-collect-agent-results.sh:266-271`](scripts/test-collect-agent-results.sh): Comments claim a “non-executable” fake launcher to skip launch, but the script `chmod +x` the launcher — the comment no longer matches the mechanism (the skip is really “launcher exits without producing sentinels/output,” not non-executable metadata).

7. **Nit** — **code-quality** — [`skills/review/scripts/tally-code-votes.sh:16-18`](skills/review/scripts/tally-code-votes.sh): `usage()` was not updated to mention `--collector-results-file` or `--not-substantive-count`, so `--help` / error paths disagree with [`skills/review/scripts/tally-code-votes.md`](skills/review/scripts/tally-code-votes.md).

8. **Latent** — **correctness** — [`skills/review/scripts/tally-code-votes.sh:427-434`](skills/review/scripts/tally-code-votes.sh): Manifest `output` paths are extracted with fixed `gsub` patterns on NDJSON text rather than `jq`. Unusual JSON ordering, escaped quotes in paths, or future manifest shape changes could drop or mis-parse `output`, misclassifying live vs dead slots.

### Out-of-Scope Observations

None surfaced that are both clearly pre-existing and unrelated to the new retry/tally/threshold paths; the issues above stem from the added logic or the new test’s interaction with it.
