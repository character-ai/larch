### In-Scope Findings

1. **Important** (`correctness`) — **Implementation plan Fix A steps 4–5** ([`scripts/collect-agent-results.sh`](scripts/collect-agent-results.sh) new “3.7” NOT_SUBSTANTIVE retry block ~1790–1941): The plan requires that when `OUTER_LAUNCHER` metadata is **not** available but `CMD_JSON` is, the collector must re-launch once via `run-external-agent.sh` (same pattern as section 3). The implementation only retries when `.meta` has executable `OUTER_LAUNCHER` plus prompt/workdir; `CMD_JSON`-only reviewers that become `NOT_SUBSTANTIVE` never get the stronger-prompt retry. **Scenario:** A narrative-only `NOT_SUBSTANTIVE` slot written only with inner `CMD_JSON` metadata (no outer launcher) stays failed after one substantive pass despite the plan’s explicit fallback. **Fix:** Add the `CMD_JSON` → `run-external-agent.sh` retry branch mirroring the existing empty-output retry deserializer, with the same prepended structured-output header on the retry argv or temp prompt as appropriate.

2. **Important** (`correctness` / plan traceability) — **Implementation plan Fix C1** ([`skills/review/scripts/check-reviewer-failure-threshold.sh`](skills/review/scripts/check-reviewer-failure-threshold.sh) ~2249, [`skills/review/scripts/review-core.sh`](skills/review/scripts/review-core.sh) ~2277): The plan specifies an emitted key `NOT_SUBSTANTIVE_COUNT`; the branch emits and reads `NOT_SUBSTANTIVE_SLOTS` instead. **Scenario:** Any script or operator grepping `review-core-threshold.env` for the planned `NOT_SUBSTANTIVE_COUNT` name gets nothing while the tally banner still works via the renamed key. **Fix:** Emit `NOT_SUBSTANTIVE_COUNT` as specified (optionally keep `NOT_SUBSTANTIVE_SLOTS` as an alias for backward compatibility if needed).

3. **Important** (`architecture` / completeness) — **Implementation plan file list** ([`skills/review/scripts/review-core.md`](skills/review/scripts/review-core.md)): The plan calls for updating `review-core.md` alongside `review-core.sh`; that file is **not** in the merge-base..HEAD change set, so orchestration docs stay stale relative to new `NOT_SUBSTANTIVE_SLOTS` / `--collector-results-file` / `--not-substantive-count` wiring. **Fix:** Document the new threshold KV and tally arguments in `review-core.md`.

4. **Nit** (`correctness`) — **Implementation plan Fix A “section 3.6”** vs docs/code ([`scripts/collect-agent-results.md`](scripts/collect-agent-results.md), [`scripts/collect-agent-results.sh`](scripts/collect-agent-results.sh)): Retry is documented and commented as **section 3.7** because structured sidecar validation already occupies 3.6. **Impact:** Plan-to-code traceability only; behavior is internally consistent.

The comment also says the fake launcher is “non-executable” while `chmod +x` makes it executable. **Fix:** With a controlled stub launcher that always writes `*-ns-retry.txt` and `.done`, assert sentinel and/or upgraded `STATUS` deterministically.

7. **Latent** (`correctness`) — **Feature description “render all panel-manifest.ndjson slots”** ([`skills/review/scripts/tally-code-votes.sh`](skills/review/scripts/tally-code-votes.sh) dead-slot awk ~2567): Manifest lines whose normalized basename matches `^dyn-` are skipped, so a dead **dynamic** slot would not get a scoreboard row. **Scenario:** Rare panels where a scout slot is in the manifest but produces no ballot rows and should be visible as dead. **Fix:** Drop or narrow the `dyn-` skip if dynamic dead rows are required.
