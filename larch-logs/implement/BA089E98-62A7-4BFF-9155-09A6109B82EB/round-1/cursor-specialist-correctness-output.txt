1. **Important** (`correctness`, plan + both) — [`scripts/collect-agent-results.sh`](scripts/collect-agent-results.sh): Fix A in the implementation plan requires a second retry path: when `.meta` has **only** `CMD_JSON` (no `OUTER_LAUNCHER`), re-launch via `run-external-agent.sh` like section 3. Section 3.7 only handles `OUTER_LAUNCHER` and silently skips all other `NOT_SUBSTANTIVE` rows (lines ~913–947, ~980). **Scenario:** A reviewer slot written with inner `CMD_JSON` metadata (no outer launcher fields) is marked `NOT_SUBSTANTIVE` after validation; it never gets the one-shot stronger-prompt retry the plan calls for. **Fix:** Add the `CMD_JSON` branch mirroring section 3’s deserializer/launch path, or narrow the plan/docs to “outer-launcher slots only” if that is intentional.

2. **Important** (`correctness`, plan + both) — [`scripts/collect-agent-results.sh`](scripts/collect-agent-results.sh): NOT_SUBSTANTIVE retry is implemented as **section 3.7 after section 3.6 structured validation** (~857–1043). On success it only runs `validate-research-output.sh` without `--structured-reviewer-mode` (~1027–1035). **Scenario:** Caller passes both `--substantive-validation` and `--structured-reviewer-validation` (plan-review wiring in your own docs). A slot is `OK` after substantive, then downgraded to `NOT_SUBSTANTIVE` in 3.6 because TSV/JSONL sidecar validation fails. The NS retry passes substantive checks on `*-ns-retry.txt` but still has no valid structured sidecar; the row is upgraded to `STATUS=OK` and never re-validated structurally. Downstream consumers see `OK` for output that is still invalid under structured rules. **Fix:** Run NS retry before structured validation, or after a successful NS upgrade re-run the structured validator (and only emit `OK` if that passes too).

3. **Latent** (`correctness`, requirements) — [`skills/review/scripts/tally-code-votes.sh`](skills/review/scripts/tally-code-votes.sh): Dead-slot rows use `collector_status[normed]` when present; otherwise the last column defaults to `NOT_SUBSTANTIVE` (~434–437). **Scenario:** A manifest slot never produced a collector record (dispatch skipped, path mismatch, or collector file from an older run). The scoreboard still shows a row labeled `STATUS=NOT_SUBSTANTIVE`, which reads as “narrative-only” even when the true state was “never ran” or another failure. **Fix:** Default to a distinct label such as `UNKNOWN` or `NO_COLLECTOR_ROW` unless `STATUS` was read from the collector map.
