### In-Scope Findings

1. **Important** (`risk-integration`) — [.github/workflows/ci.yaml](.github/workflows/ci.yaml) `make lint-only` (line 63) and [.claude/skills/relevant-checks/scripts/run-checks.sh](.claude/skills/relevant-checks/scripts/run-checks.sh) (pre-commit + `agent-lint` only, lines 116–134): CI never runs repo-wide `make lint-bash32`, and `/relevant-checks` never invokes it either. `scripts/test-lint-bash32.sh` only proves the linter on synthetic fixtures under a temp root, so a PR can introduce Bash 4+ into tracked `*.sh` files, pass all CI jobs and `/relevant-checks`, and still ship macOS-incompatible shell. **Scenario:** A contributor adds `declare -A` to a new `scripts/foo.sh`, relies on CI green + `/relevant-checks`; `test-lint-bash32` stays green because it does not scan the real tree. **Fix:** Run `make lint-bash32` (or `bash scripts/lint-bash32.sh`) in the CI `lint` job and mirror it in `run-checks.sh` (or register an equivalent pre-commit hook) so the full tracked `*.sh` inventory is enforced the same way the feature text promises.

2. **Important** (`risk-integration`) — [scripts/launch-claude-review.sh:105-111](scripts/launch-claude-review.sh) (voter role skips `append_context_file` for diff/plan/scope/feature) plus the updated expectations in [scripts/test-dispatch-code-voters.sh](scripts/test-dispatch-code-voters.sh) / [scripts/test-launch-claude-review.sh](scripts/test-launch-claude-review.sh): Claude **voters** no longer receive inline diff/plan context that reviewers still get. **Scenario:** A ballot asks the voter to verify a cited hunk against the diff; the model only sees the ballot/prompt file while symlinked or oversized diff paths are accepted at the dispatcher. The voter can return `DISPATCH_OK=true` / plausible votes without ever touching the material under vote, which is a silent loss of cross-checking power relative to the old “forward diff to voter” path. **Fix:** If that cross-check is still required, keep a bounded excerpt or hash-attested summary on the voter path; if omission is intentional, document the degraded guarantee in the voter-facing contract (`dispatch-code-voters.md` / `launch-claude-review.md`) so operators do not assume diff-grounded voting.

3. **Latent** (`correctness`) — [scripts/collect-agent-results.sh:1140-1146](scripts/collect-agent-results.sh): Section 3.7 NOT_SUBSTANTIVE retries are wrapped in `if [[ "$SUBSTANTIVE_VALIDATION" == "true" ]]; then`, but `--structured-reviewer-validation` remains valid without `--substantive-validation` (see usage string at line 153). Section 3.6 can still emit `STATUS=NOT_SUBSTANTIVE` with `NS_RETRY_MODE=structured`, yet **no** NS retry block runs when substantive validation is off. **Scenario:** A future caller copies only `--structured-reviewer-validation` expecting the new retry path to recover structured slots; structured failures stay terminal despite `NS_RETRY_MODE` advertising a retry intent. **Fix:** Either require substantive validation whenever structured validation is enabled, extend section 3.7’s guard to `SUBSTANTIVE_VALIDATION || STRUCTURED_REVIEWER_VALIDATION`, or strip `NS_RETRY_MODE` when substantive validation is disabled so the record is not misleading.

4. **Latent** (`correctness`) — [scripts/lint-bash32.sh:66-85](scripts/lint-bash32.sh): The scanner skips symlinked regular files (`! -L`), never flags anonymous `coproc { ... }`, and treats any line containing the substring `lint-bash32: ok` as fully suppressed before comment stripping (lines 75–76). **Scenario:** A tracked symlink to a `.sh` file hides Bash 4+ in the target; anonymous coprocs slip past the named-coproc regex; a long line embeds the substring inside a quoted string and accidentally suppresses real code on the same line. **Fix:** Follow symlinks to real files (or lint targets), extend the coproc rule if Bash 4 coprocs are forbidden outright, and tighten suppression to a anchored end-of-line `# lint-bash32: ok` token.

5. **Nit** (`code-quality`) — [Makefile:15](Makefile): `lint` runs the entire `test-harnesses` fan-out before `lint-bash32`. **Scenario:** A simple Bash 4 typo fails only after a long local harness sequence, slowing the edit/verify loop. **Fix:** Optionally reorder to `lint-bash32` before `test-harnesses`, or document the ordering trade-off in `docs/linting.md`.
