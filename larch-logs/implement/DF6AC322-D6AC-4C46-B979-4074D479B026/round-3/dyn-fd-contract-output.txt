Reviewing the branch diff and commit history for architecture issues.
### In-Scope Findings

- **risk-integration** `python/ship.py:726-733` — After `quiet_init()` redirects FD 1/2 to the quiet log, `emit_result()`’s contract-stream failure fallback prints the degraded `INTERNAL_ERROR` JSON to `sys.stdout` instead of FD 3. The Bash ship driver consumes machine-readable output from the contract FD (mirroring `lib-quiet.sh`’s `emit`/`emit_kv` on FD 3), so a broken-pipe or write failure on the primary contract stream can leave the parent with no parseable envelope even though JSON lands in the quiet log. `test_emit_result_downgrades_zero_byte_contract_stream_failure` mocks `contract_stream` without enabling quiet mode, so this production path is untested. **Suggested fix:** On fallback, write the JSON directly to FD 3 (e.g. `os.write(3, …)` or a fresh `os.fdopen(os.dup(3), "w")`) whenever `_self_initialized_quiet` is true or FD 3 differs from the redirected stdout; keep `sys.stdout` fallback only when quiet routing was never established. Add a subprocess test that runs `quiet_init()` before forcing a broken contract stream and asserts FD 3 receives the fallback payload.

- **architecture** `python/logging_util.py:87-99` — `quiet_init()` mutates FD 4 via `os.dup2(2, 4)` before log redirection is guaranteed to succeed; if `os.open` or the subsequent `dup2` to FD 1/2 raises `OSError`, the handler clears quiet env vars and returns but does not restore FD 4 (or FD 3 when it was freshly duplicated). That leaves the process in a half-initialized quiet state where breadcrumbs may target a redirected FD 4 while `_self_initialized_quiet` remains false and `contract_stream()` falls back to redirected `sys.stdout`. Bash `larch_quiet_init` in `scripts/lib-quiet.sh` prepares the log file first and only then performs `exec 3>&1` / `exec 4>&2`, keeping init all-or-nothing. **Suggested fix:** Open the log FD and complete FD 1/2 redirection before touching FD 4, or capture pre-init FD targets and restore them in the `except OSError` path; mirror bash’s “prep log, then dup contract/stderr, then redirect” ordering.

### Out-of-Scope Observations

- **architecture** `scripts/larch-log.sh:89-102` — The new explicit dynamic-Codex allow clause is correctly ordered after prompt/telemetry/static-Codex denies and is well regression-pinned in `scripts/test-larch-log.sh`, but retention of shapes outside the narrow explicit list (e.g. a future `dyn-*-codex-output-retry*.txt` artifact) still relies on the broad `*-output.txt|*-output-*.txt` allow at line 102. The inline comment that dynamic retention “does not depend on catch-all transcript globs” overstates isolation; the clause documents and pins the boundary rather than making the broad allow redundant. No behavioral defect for the plan’s scoped shapes.

- **architecture** `python/logging_util.py:76-77` — Python quiet logs are opened append-only (`open(..., "a")`) whereas bash `larch_quiet_init` truncates with `: > "$log_file"`. Re-invocation or crash-retry within the same session can accumulate multiple ship runs in one quiet log file, which may complicate forensics compared with the shell contract.
