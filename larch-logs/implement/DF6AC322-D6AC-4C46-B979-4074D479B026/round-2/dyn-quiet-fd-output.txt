### In-Scope Findings

- **risk-integration** `python/ship.py:716-724` — `emit_result()` wraps the contract JSON `print`/`flush` in `suppress(BrokenPipeError, OSError)`, so any contract-stream write failure (broken orchestrator pipe, bad fd after quiet init, or other I/O error) completes without emitting JSON and without a breadcrumb or non-zero exit override. `/implement` Step 8 on the Python path treats stdout JSON plus the process exit code as the primary contract; a successful `run_ship()` paired with a swallowed write yields an empty or partial stdout capture while still returning the mapped outcome exit code, which can stall or mis-route the ship state machine. **Suggested fix:** Track whether any bytes were written to the contract stream; on failure, log via `BreadcrumbWriter` (mirroring the journal skip path at `730`) and either retry on fd 3 directly or downgrade to `Outcome.INTERNAL_ERROR` when zero contract bytes were emitted.

- **risk-integration** `python/logging_util.py:78-83,96-102` — `quiet_init()` always executes `os.dup2(1, 3)` before redirecting stdout to the quiet log, mirroring bash `lib-quiet.sh` child re-init but without checking whether fd 3 already carries an inherited contract stream from a quiet parent. If `ship.py` is ever launched from an already-quiet bash wrapper (stdout already on the log file, fd 3 already pointing at the caller pipe), the dup clobbers fd 3 with the log fd and `contract_stream()` no longer reaches the immediate caller; JSON and breadcrumbs can land only in the quiet log while the orchestrator reads a noisy stdout stream. **Suggested fix:** Before `dup2(1, 3)`, detect an open fd 3 that differs from fd 1 (e.g., `fcntl(F_GETFD)`/`stat` parity with bash’s preserved contract fd) and skip re-saving fd 3 when inheriting a valid parent contract stream; add a subprocess regression test that sets `LARCH_QUIET_ACTIVE=1` with a foreign `LARCH_QUIET_PID`, pre-seeds fd 3, and asserts JSON still reaches the capture pipe.

- **risk-integration** `python/logging_util.py:96-102` — When `_self_initialized_quiet` is true but `os.fdopen(os.dup(3), …)` fails, `contract_stream()` falls back to `sys.stdout`, which after quiet init is the quiet log, not fd 3. `emit_result()` then writes JSON into the diagnostic log with no warning, while the orchestrator’s stdout capture may contain only breadcrumbs rather than the single JSON line the Step 8 parser expects. **Suggested fix:** Treat fd-3 open failure as fatal for the contract path: log loudly and either write directly with `os.write(3, …)` as a last resort or surface `Outcome.INTERNAL_ERROR` instead of silently falling back to redirected stdout.
