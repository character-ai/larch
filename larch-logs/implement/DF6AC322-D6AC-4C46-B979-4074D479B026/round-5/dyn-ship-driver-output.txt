Reviewing the branch diff and commit history for risk-integration issues.
### In-Scope Findings

- **risk-integration** `python/ship.py:321-324` — `_oos_gate()` still hardcodes `origin/main` / `upstream/main` when building the OOS disposition commit range, but this branch wires `run_ship()` to `gh.default_branch()` for PR creation and CI monitoring (`python/ship.py:507-509`, `python/pr.py:76`). On repos whose default branch is not `main`, the Python driver will open/monitor PRs against the real default while OOS disposition scans the wrong commits for `Inline-triage rule N:` breadcrumbs, which can falsely re-trigger `NEEDS_USER_INPUT` after Step 9a.1 or pass disposition when breadcrumbs live only on feature-branch commits outside the scanned range. **Suggested fix:** Resolve `base_ref` once in `run_ship()` (with the same `gh.default_branch()` fallback) and pass it into `_oos_gate()` for both `git merge-base` and `git log --format=%B`; add a regression test mirroring `test_pr_create_uses_repo_default_branch` that asserts OOS disposition uses the non-`main` base.

- **risk-integration** `python/ship.py:827-833` — `_state_file_kv()` catches all `ShipError` from `read_finalize_state()` and returns `{}`, so merge-loop counters (`ITERATION`, `REBASE_COUNT`, `FIX_ATTEMPTS`, `TRANSIENT_RETRIES`) silently reset to zero whenever `ship-pr-state.sh` is unreadable or fails the new shell-quote parser. Because the Python path re-invokes the full driver without `--resume-phase` and relies on persisted counters to bound the merge loop (`python/ship.py:581-585`), a parse failure turns a resume into a fresh loop budget instead of a fail-closed stall, weakening the iteration-cap safety property across orchestrator re-invokes (OOS checkpoint, Exit 6 retries, stall-recovery `step8-shippr`). **Suggested fix:** On parse failure, emit a breadcrumb and return `Outcome.STALLED` (or preserve the last successfully read counters in `ship-pr-state.sh` rather than `{}`); add a test where a malformed `ship-pr-state.sh` must not restart `ITERATION` at 0.
