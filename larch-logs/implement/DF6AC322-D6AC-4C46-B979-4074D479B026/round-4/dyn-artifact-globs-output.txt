Reviewing the branch diff and commit history for security issues in the dynamic Codex log allowlist.
### In-Scope Findings

- **security** `scripts/larch-log.sh:93` — The explicit dynamic-Codex allow arm uses the forbidden catch-all `dyn-*-codex-output-*.txt` (and matching `*.meta` / `*.json` / `*.cap-hit` sidecar globs), while `scripts/larch-log.md:35-36` states the matcher “does not use a catch-all dynamic Codex suffix glob.” The plan and acceptance criteria forbid this pattern because it matches prompt-shaped basenames such as `dyn-api-contract-codex-output-vote-prompt.txt`. Today’s `*-vote-prompt.txt` deny at line 82 runs before the allow and the new negative tests pass, so there is no demonstrated active leak on this branch; the defect is contractual and ordering-fragile—any future reorder that places the dynamic allow before vote-prompt / telemetry denies would commit prompt- or telemetry-shaped dynamic Codex artifacts into public `larch-logs/` commits. **Suggested fix:** Replace `dyn-*-codex-output-*.txt` and its sidecar catch-alls with the narrow patterns from the plan (`dyn-*-codex-output-phase*.txt`, and `dyn-*-codex-output-retry*.txt` only if retry artifacts are confirmed in producers), align `scripts/larch-log.md` with the implementation, and add a CI guard that fails if `dyn-*-codex-output-*.txt` appears in `round_artifact_included()`.

- **security** `scripts/test-larch-log.sh:173-184` — The ordering regression pin is supposed to guard against catch-all regressions, but its `dyn_catchall` detector uses `/dyn-\*-\*-\*codex-output/` (three `*` segments), which does not match the actual forbidden substring `dyn-*-codex-output-*.txt` at `scripts/larch-log.sh:93`; `!dyn_catchall` therefore always passes. Worse, the same awk block sets `dyn_allow` via `index($0, "dyn-*-codex-output-*.txt")`, so the test requires the catch-all pattern to be present rather than absent. CI cannot detect reintroduction of the plan-forbidden glob or a reorder that would leak vote prompts. **Suggested fix:** Split the pin into (a) an absence check that `index($0, "dyn-*-codex-output-*.txt")` is zero and (b) a separate ordering check keyed on the narrow allowed patterns (`dyn-*-codex-output.txt`, `dyn-*-codex-output-phase*.txt`), plus negative `assert_round_artifact_included` cases for vote-prompt-shaped `.meta` / `.json` sidecars if those basenames are plausible.

### Out-of-Scope Observations

- **security** `scripts/larch-log.sh:102` — Pre-existing broad `*-output-*.txt.meta` (and related sidecar globs) can include sidecars for vote-prompt-shaped basenames (e.g. `dyn-api-contract-codex-output-vote-prompt.txt.meta`) because the `*-vote-prompt.txt` deny covers only the `.txt` basename, not `.meta` / `.json` siblings; this branch did not introduce that surface, and no fixture asserts those sidecar negatives today.
