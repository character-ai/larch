### In-Scope Findings

- **correctness** `scripts/larch-log.sh:93` — The new dynamic-Codex allow arm uses the catch-all pattern `dyn-*-codex-output-*.txt` (and matching `*.meta` / `*.json` / `*.cap-hit` sidecars), but the plan, acceptance criteria, and `scripts/larch-log.md` all require *narrow* shapes only (`dyn-*-codex-output.txt`, `dyn-*-codex-output-phase*.txt`, optional `dyn-*-codex-output-retry*.txt`) and explicitly forbid a catch-all suffix glob because it can admit prompt-shaped `.txt` names (e.g. anything matching `dyn-*-codex-output-<suffix>.txt` that is not caught by an earlier deny). Today `*-vote-prompt.txt` and `.prompt` negatives still pass only because earlier deny clauses win on ordering; the catch-all widens the committed surface beyond the documented contract and makes future reordering a silent telemetry/prompt leak risk. **Suggested fix:** Replace `dyn-*-codex-output-*.txt` and its sidecar twins with the plan’s narrow patterns (`dyn-*-codex-output-phase*.txt`, and `dyn-*-codex-output-retry*.txt` only if a real producer exists); drop the retry fixture/assertions if no runtime emits that basename.

- **correctness** `scripts/test-larch-log.sh:173-184` — The new ordering/regression `awk` pin is supposed to reject a catch-all dynamic-Codex glob (`!dyn_catchall`), but `dyn_catchall` is set only by `/dyn-\*-\*-\*codex-output/`, which does not match the actual substring `dyn-*-codex-output-*.txt` on the allow line; meanwhile `index($0, "dyn-*-codex-output-*.txt")` records that same catch-all as the *required* `dyn_allow` line. The harness therefore always passes with the forbidden glob present and cannot catch a revert to catch-all or a doc/code mismatch. **Suggested fix:** Set `dyn_catchall` when `index($0, "dyn-*-codex-output-*.txt")` (and the parallel sidecar catch-alls) is found *outside* an explicit comment, require `index($0, "dyn-*-codex-output-phase*.txt")` instead, and fail if any `dyn-*-codex-output-*.txt` catch-all remains.

- **correctness** `scripts/test-larch-log-write-round.sh:90,159` and `scripts/test-larch-log.sh:158` — Tests assert inclusion of `dyn-api-contract-codex-output-retry.txt` via the catch-all, but no review/dispatch code in this repo generates `dyn-*-codex-output-retry*.txt` (dynamic Codex slots are emitted as unphased `dyn-<name>-codex-output.txt` per `skills/review/scripts/dispatch-panel.sh`); the plan said to add retry support only if the implementation already produces retry-suffixed dynamic Codex artifacts. The tests therefore validate a filename shape the runtime does not create, masking whether the intended narrow matcher would work in production. **Suggested fix:** Either locate and cite the real retry basename producer and test that exact pattern, or remove the retry fixture/assertions and keep retry out of `round_artifact_included()` until a producer exists.
