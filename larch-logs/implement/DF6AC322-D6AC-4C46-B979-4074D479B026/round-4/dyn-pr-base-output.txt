Reviewing the branch diff and commit history against the plan, with emphasis on risk-integration.
### In-Scope Findings

- **risk-integration** `python/ship.py:488-537` — The Python ship driver now always passes `base="main"` into `pr.ensure_pr()` / `gh.pr_create()`, while the bash path still relies on `scripts/create-pr.sh` to detect the repo default branch via `gh repo view … defaultBranchRef` and only fall back to `main` when detection fails (`scripts/create-pr.sh:269-274`). Before this branch, the Python path omitted `--base` and inherited `gh`’s default-branch behavior; the new explicit `--base main` is a cross-driver regression for any consumer repo whose default branch is not `main` (PR targets the wrong base or `gh pr create` fails). **Suggested fix:** Mirror `create-pr.sh` in Python: resolve the target repo’s default branch (respecting `--repo` / fork context) and pass that to `ensure_pr`, falling back to `main` only when lookup fails; add a parity test that stubs a non-`main` default branch and asserts the create argv.

- **risk-integration** `scripts/larch-log.sh:93` — The new dynamic-Codex allow clause uses the forbidden catch-all pattern `dyn-*-codex-output-*.txt`, which the plan explicitly rejects because it can match prompt-shaped names such as `dyn-api-contract-codex-output-vote-prompt.txt`. Exclusion currently depends on the earlier `*-vote-prompt.txt` deny (`scripts/larch-log.sh:82-83`) winning the case order; a future reorder or broadening of the allow clause would commit vote prompts into public run logs without a matcher-level guard. **Suggested fix:** Replace the catch-all with the plan’s narrow shapes only (`dyn-*-codex-output.txt`, `dyn-*-codex-output-phase*.txt`, and retry suffix only if production artifacts exist), and add a negative assertion that the source no longer contains `dyn-*-codex-output-*.txt`.

- **risk-integration** `scripts/test-larch-log.sh:4486-4503` — The new “ordering/regression pin” awk block is supposed to reject catch-all dynamic-Codex globs (`!dyn_catchall`), but its detector `/dyn-\*-\*-\*codex-output/` does not match the actual source token `dyn-*-codex-output-*.txt`, so the harness passes even while the forbidden catch-all remains. That leaves the bash↔run-log integration boundary under-protected against the exact failure mode the plan calls out (prompt leakage on matcher regressions). **Suggested fix:** Pin the literal forbidden substring `dyn-*-codex-output-*.txt` (or enumerate allowed patterns) and fail if it appears in `round_artifact_included()`; keep the ordering checks separate.
