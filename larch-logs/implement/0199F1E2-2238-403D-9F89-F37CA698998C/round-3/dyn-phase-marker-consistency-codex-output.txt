### In-Scope Findings
- **architecture** `skills/design/scripts/review-design-step3-loop.sh:451-469` — The loop leaves `.step3-round-N.phase=awaiting-continuation` behind when continuation returns `PLAN_REVIEW_CONTINUE=false`, but `run-step3-review.sh:466-479` auto-selects any existing consumed-round phase marker on a later `--mode loop` invocation with no `--starting-round`. That makes a fresh Step 3 re-entry able to resume the stale final round instead of launching `count+1`, silently skipping a new review pass. **Suggested fix:** When continuation settles with `false`, remove the current round’s phase/snapshot/ready marker before emitting `complete`, or change no-`--starting-round` auto-resume to ignore phase markers for already completed Step 3 states.

- **architecture** `skills/design/scripts/review-design-step3-loop.sh:423-435` — `awaiting-post-apply` skips dedup whenever `.gate-b-postapply-ready-N` exists, but postplan operator bail-outs leave that marker in place, and `skills/design/SKILL.md:1264` says plan-changing Fix-and-retry/autofix should re-enter `awaiting-post-apply`. After such a plan change, the stale ready marker causes resume to bypass `gate-b-dedup-plan.sh`, so the modified plan is postplanned without re-validating the dedup/trailer guard. **Suggested fix:** On any plan-changing operator recovery, explicitly delete `.gate-b-postapply-ready-N` before writing/resuming `awaiting-post-apply`, or make the loop track plan hash/mtime and rerun dedup when the marker predates the plan change.
