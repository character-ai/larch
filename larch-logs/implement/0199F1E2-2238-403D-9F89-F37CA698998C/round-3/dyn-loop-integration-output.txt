### In-Scope Findings

- **risk-integration** `skills/design/scripts/test-step3-orchestrator-fence.sh:118-121` — The harness claims to mirror `skills/design/SKILL.md` Step 3 handoff, but its `STEP3_REVIEW_LOOP_STATUS` bridge diverges from SKILL on `postplan-failed`: SKILL maps it to `LOOP_STATUS=postplan-failed` (```1238:1241:skills/design/SKILL.md```), while the harness maps it to `LOOP_STATUS=complete`. The harness only asserts `STEP3_REVIEW_LOOP_STATUS` is preserved (```407:411:skills/design/scripts/test-step3-orchestrator-fence.sh```), so this regression would not be caught. Any caller that applies harness logic or reads only `LOOP_STATUS` from `.step3-review-result.env` can treat a hard postplan failure as a normal `complete` review round and route into Gate B / continuation. **Suggested fix:** Align the harness `case` arm with SKILL (map `postplan-failed` → `LOOP_STATUS=postplan-failed`), add an assertion that `LOOP_STATUS=postplan-failed` after handoff, and pin the full bridge table in `test-design-structure.sh` so SKILL and harness cannot drift again.

- **risk-integration** `skills/design/scripts/review-design-step3-loop.sh:54-66` — `step3_loop_persist_envelope` writes contradictory dual status into `.step3-review-result.env` for several loop outcomes. The `*)` branch sets `loop_status="${LOOP_STATUS:-complete}"`, so bail-outs/terminals like `postplan-failed`, `main-agent-apply-required`, and `per-round-approval-required` often persist `LOOP_STATUS=complete` (left over from the review pass) alongside `STEP3_REVIEW_LOOP_STATUS=postplan-failed` (or another bail-out). `plan-review-continuation.sh` reads only `LOOP_STATUS` from that file (```63:63:skills/design/scripts/plan-review-continuation.sh```, ```174:176:skills/design/scripts/plan-review-continuation.sh```) and treats `TALLY_PLAN_REVIEW_STATUS=ok` + `LOOP_STATUS=complete` as a healthy settled round. That creates a footgun for resume, pause, or any helper that reads the result env without re-running SKILL’s bridge. **Suggested fix:** Teach `step3_loop_persist_envelope` an explicit mapping table mirroring SKILL’s bridge (e.g. `postplan-failed` → `LOOP_STATUS=postplan-failed`, apply bail-outs → `LOOP_STATUS=complete`, `cap-hit` → `cap-reached`), and extend `test-review-design-step3-loop.sh` to assert persisted `LOOP_STATUS` for each terminal/bail-out envelope.

- **risk-integration** `skills/design/SKILL.md:1248-1265,1294-1339` — `STEP3_REVIEW_LOOP_STATUS=postplan-failed` is documented as a hard-fail that must not advance to Step 3b (```1265:1265:skills/design/SKILL.md```), but the procedural flow has no mechanical halt before Step 3.5/3b.
