Reviewing the diff and key files for LOOP_STATUS vs STEP3_REVIEW_LOOP_STATUS coexistence and related integration risks.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/review-design-step3-loop.sh:80-84` — `step3_loop_write_completed_step3()` writes both `.completed/step-3` and `.completed/step-3.5` on every terminal loop exit (`cap-hit`, `panel-failed`, `tally-error`, `degraded-empty-collector`, and `complete`), but `skills/design/SKILL.md:1263-1271` and `1283-1285` still require `design-step3-state.sh --gate-b-bypass` before Step 3b on those same paths. That helper refuses when `.completed/step-3.5` already exists (`skills/design/scripts/design-step3-state.sh:87-89`), yielding `STEP3_STATE=refused-partial-gate-b-bypass` and an orchestrator abort even though the loop already marked Gate B skipped. **Suggested fix:** Pick one owner: either have the loop write only `.completed/step-3` and leave `step-3.5` to `gate-b-bypass`/Step 3b, or teach `--gate-b-bypass` to succeed idempotently when both sentinels are already present (and update `skills/design/SKILL.md:1287` plus `scripts/test-design-step3-state.sh` accordingly). Add a loop-mode integration case that runs `--gate-b-bypass` after `STEP3_REVIEW_LOOP_STATUS=panel-failed|cap-hit`.

- **risk-integration** `skills/design/SKILL.md:1293-1307` — The Step 3.5 prelude unconditionally runs `: > "$DESIGN_TMPDIR/.completed/step-3"` before branching on `STEP3_REVIEW_LOOP_STATUS`, including mid-loop bail-outs (`main-agent-vote-required`, `per-round-approval-required`, `postplan-operator-required`) where the loop intentionally did not write that sentinel. That leaves `step-3` set without `step-3.5`, and `scripts/design-pause-save.sh:175-176` maps that pair to `STEP=3.5`, so a pause after a bail-out resumes at Gate B instead of the Step 3 loop resume handler (`--mode loop --starting-round N` + `.step3-round-N.phase`). **Suggested fix:** Move the `step-3` write out of the unconditional prelude; write it only for legacy `--mode single` Gate B paths and terminal loop envelopes that are actually proceeding to Step 3b, or clear `.completed/step-3` on bail-out branches before any pause boundary.

- **risk-integration** `skills/design/SKILL.md:1238-1241` — The `STEP3_REVIEW_LOOP_STATUS`→`LOOP_STATUS` bridge maps `main-agent-apply-required`, `per-round-approval-required`, `postplan-operator-required`, and `postplan-failed` to `LOOP_STATUS=complete`, while the legacy block at `1267` still says `LOOP_STATUS=complete` → proceed to Gate B. The post-loop matrix is supposed to win, but `1283-1285` key only on `LOOP_STATUS` (`cap-reached`, `tally-error`, etc.) with no `STEP3_REVIEW_LOOP_STATUS` guard, so an orchestrator that evaluates legacy prose after the bridge can mis-route bail-outs (especially `postplan-failed`, which becomes indistinguishable from a happy `complete` at the `LOOP_STATUS` layer). **Suggested fix:** Gate all legacy `LOOP_STATUS` branches on `[[ -z "${STEP3_REVIEW_LOOP_STATUS:-}" ]]` (mirror the Step 3.5 skip guard at `1289`), or stop remapping bail-outs/postplan-failed to `LOOP_STATUS=complete` and carry envelope-only routing.

- **risk-integration** `skills/design/scripts/test-step3-orchestrator-fence.sh:123-125` — The hermetic handoff mirror’s legacy `LOOP_STATUS` allowlist omits `main-agent-apply-required|per-round-approval-required|postplan-operator-required|postplan-failed`, which `skills/design/SKILL.md:1243` includes. The harness therefore does not pin production normalization for legacy `--mode single` callers or any path where `STEP3_REVIEW_LOOP_STATUS` is unset, giving false confidence that the dual-status contract is complete. **Suggested fix:** Align the fence harness regex with `SKILL.md:1243` and add cases for each `STEP3_REVIEW_LOOP_STATUS` bail-out proving `LOOP_STATUS` bridge output and that legacy blocks are not entered.

- **risk-integration** `skills/design/SKILL.md:95-96` — The Completion sentinels table still assigns `step-3` to the Step 3.5 prelude and `step-3.5` solely to Step 3b entry, contradicting the new loop ownership (`1287`, `review-design-step3-loop.sh:80-84`, and `scripts/test-design-multi-round-integration.sh:206-207` now expecting the loop to write both on terminal paths).
