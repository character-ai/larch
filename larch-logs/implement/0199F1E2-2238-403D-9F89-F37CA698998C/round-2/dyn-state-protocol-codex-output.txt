### In-Scope Findings
- **architecture** `skills/design/scripts/review-design-step3-loop.sh:384-403` — The `awaiting-post-apply` resume path skips dedup whenever `.gate-b-postapply-ready-N` exists, but postplan operator bail-outs leave the phase at `awaiting-post-apply` after the marker was already written. That makes non-plan-changing Override/Continue prone to re-running the same postplan brake unless the prompt-side handler manually advances the phase, and makes plan-changing Fix-and-retry/autofix resume without rerunning dedup because the marker still exists. **Suggested fix:** Add an explicit persisted postplan-operator decision transition: non-plan-changing decisions should atomically write `.step3-round-N.phase=awaiting-continuation`; plan-changing fixes should remove `.gate-b-postapply-ready-N` before resuming `awaiting-post-apply` so dedup runs again.

- **architecture** `skills/design/SKILL.md:1238-1242` — `STEP3_REVIEW_LOOP_STATUS=postplan-failed` is documented as a hard-fail terminal, but the handoff normalizes it to `LOOP_STATUS=complete`. Any downstream legacy branch or resume path that keys off `LOOP_STATUS` can treat a failed postplan/continuation as a successful review and continue into Gate B or Step 3b. **Suggested fix:** Do not map `postplan-failed` to `complete`; handle it as an immediate abort/hard-fail branch before any Gate B/Step 3b transition, and update the orchestrator-fence test to assert that no completion sentinel or Step 3b route is taken.

- **architecture** `skills/design/SKILL.md:1293-1296` — The Step 3.5 fence now writes `$DESIGN_TMPDIR/.completed/step-3` without first ensuring `$DESIGN_TMPDIR/.completed` exists; main removed the `mkdir -p` that used to precede this write. Loop terminal paths create the directory, but mid-loop bail-outs enter Step 3.5 before the loop writes completion sentinels, so older/corrupt/resumed tmpdirs without `.completed` can fail at the first Gate B recovery write. **Suggested fix:** Restore `mkdir -p "$DESIGN_TMPDIR/.completed"` immediately before touching `.completed/step-3`.
