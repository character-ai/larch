### In-Scope Findings

- **correctness** `python/tracking_issue.py:178-183` — Footer idempotency uses `(?m)^Closes #{issue_number}[ \t]*$` on the whole body, so any line that is exactly `Closes #N` at column 0 counts as “already linked,” including lines inside fenced code blocks or other non-footer contexts. After `compose_pr_body` started delegating to `link_pr_closes`, a summary (or other section) that documents the keyword on its own line can suppress the real trailing footer that the old `parts.extend([..., f"Closes #{issue_number}"])` always added after the Test plan section; auto-close can then depend on a match inside a fence that GitHub may not treat as a closing keyword. **Suggested fix:** Narrow idempotency to the document suffix (e.g., scan only the last non-empty line, or only lines after the Test plan block), or strip fenced regions before the guard; alternatively, have `compose_pr_body` append unconditionally and reserve `link_pr_closes` idempotency for `ensure_pr` updates only.
