### In-Scope Findings
- **risk-integration** `scripts/test-dispatch-with-waterfall.sh:537-572` — The new `--no-fallback` timing guards use wall-clock `date +%s` deltas with a hard `< 4` second ceiling while `--timeout` is 5. That checks elapsed real time, not whether `wait-for-reviewers.sh` was entered; under loaded CI, process startup, or a slow first `collect-agent-results.sh` retry path, a correct run can exceed 4s and fail flakily, while a regression that waits almost the full 5s may pass at 4–5s. The same file already asserts the meaningful invariant (`STATUS=SENTINEL_TIMEOUT` absent); the duration checks add fragility without matching how other harnesses pin timing (e.g. `WAIT_FOR_REVIEWERS_POLL_INTERVAL=0.05` plus structural status checks in `scripts/test-dispatch-code-voters.sh`). **Suggested fix:** Drop the `_elapsed` / `_collect_*_elapsed` comparisons and rely on structural assertions (no `SENTINEL_TIMEOUT`, empty vs non-empty paths-file, expected paths-file lines). If a duration guard is still desired, gate on `WAIT_FOR_REVIEWERS_POLL_INTERVAL` being unset or use a much looser bound, or stub/instrument `wait-for-reviewers.sh` to fail if invoked when the paths-file is empty.

- **risk-integration** `scripts/test-dispatch-with-waterfall.sh:493-577` — The harness exercises all-fail (`no-fallback-drop`), all-ok single-slot (`no-fallback-keep`), and tool-absent with an empty paths-file (`no-fallback-absent`), but not the production-critical partial case: multiple manifest slots with one phase-1 success and one phase-1 failure under `--no-fallback`. A regression that writes every manifest `output` path into `${manifest}.output-files` (including a failed slot with no `.done`) would reintroduce the original ~timeout-per-slot stall; only the partial case catches that. **Suggested fix:** Add a two-slot manifest where one stub succeeds and one fails, assert the paths-file has exactly one line (the OK path), run real `collect-agent-results.sh --paths-file` with a short `--timeout`, and assert no `STATUS=SENTINEL_TIMEOUT`.

### Out-of-Scope Observations
- Production integration for empty or compact paths-files looks sound: `scripts/dispatch-with-waterfall.sh:446-479` omits dropped slots under `--no-fallback`; `skills/design/scripts/plan-review-loop.sh:770-803` only calls `collect-agent-results.sh` when `PANEL_PATHS_FILE` is non-empty (`-s`), so an empty `${manifest}.output-files` skips collect instead of blocking; `scripts/collect-agent-results.sh:250-252` fail-closes immediately on an empty paths-file if mis-invoked. `skills/design/scripts/test-plan-review-loop.sh:846-861` covers the empty-paths loop path.
- Per-run isolation via `TMPROOT="$(mktemp -d ...)"` and distinct output basenames (`no-fallback-drop.txt`, `no-fallback-keep.txt`, `no-fallback-absent.txt`) makes cross-case stale `.done` contamination within a harness run unlikely; `wait-for-reviewers.sh` would still treat a pre-existing `.done` at a listed path as immediate completion, but that is pre-existing sentinel semantics, not introduced by this branch.
- The `no-fallback-absent` collect subtest (`scripts/test-dispatch-with-waterfall.sh:567-576`) validates direct `collect-agent-results.sh` behavior on an empty paths-file (fast exit 1), not the `plan-review-loop.sh` skip path; loop coverage lives in `test-plan-review-loop.sh`.
