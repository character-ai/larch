### In-Scope Findings
- **architecture** `scripts/dispatch-plan-voters.sh:169-183` — The branch stops parsing waterfall `ALL_OUTPUT_FILES` / `ALL_OUTPUT_TOOLS` and always treats the pre-declared manifest paths (`$DESIGN_TMPDIR/codex-vote-output.txt`, `$DESIGN_TMPDIR/cursor-vote-output.txt`) as the sole voter output locations, but `dispatch-with-waterfall.sh`’s `collect_phase` (via `collect-agent-results.sh` §3 empty-output retry) can mark a slot OK while leaving substantive output only at `<manifest>-retry.txt` (`final_outputs[$idx]="${rf:-$output}"` at `scripts/dispatch-with-waterfall.sh:318`; collector sets `REVIEWER_FILE=$RETRY_OUTPUT` at `scripts/collect-agent-results.sh:1187`). The pre–parse-rate gate `[[ -s "$VOTER_2_PATH" ]]` / `[[ -s "$VOTER_3_PATH" ]]` then marks the slot `failed` and skips `check_and_retry_voter_parse_rate`, even though the waterfall/collector succeeded on the retry sidecar—dropping a valid external judge and emitting a false degraded-panel warning. This is a regression versus `scripts/dispatch-code-voters.sh:194-206`, which still binds paths from `ALL_OUTPUT_FILES`. **Suggested fix:** After the waterfall call, parse `ALL_OUTPUT_FILES` paired with `ALL_OUTPUT_TOOLS` and map by tool (`codex` → `VOTER_2_PATH`, `cursor` → `VOTER_3_PATH`), not by positional index; use the manifest paths only as defaults when a tool has no waterfall entry. Keep the availability-gated manifest emission and run the `-s` / parse-rate checks on the resolved final path.
