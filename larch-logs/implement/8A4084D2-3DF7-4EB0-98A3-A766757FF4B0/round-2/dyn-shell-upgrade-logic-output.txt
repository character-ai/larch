### In-Scope Findings

- **correctness** `skills/upgrade-larch/scripts/upgrade-larch.sh:81-96` — In `refresh_larch_marketplace`, both the update-failure fallback (`remove_larch_marketplace || true` then `add_sparse_larch_marketplace`) and the legacy/stale-cone branch swallow a failed `claude plugin marketplace remove` and still call `add_sparse_larch_marketplace`. When the clone at `$MARKETPLACE_CLONE` remains (the scenario `warn_marketplace_remove_failure` at `skills/upgrade-larch/scripts/upgrade-larch.sh:64-67` describes), `marketplace add` often fails because the marketplace entry or tree already exists. With `set -euo pipefail`, that failure triggers the `ERR` trap (`skills/upgrade-larch/scripts/upgrade-larch.sh:32`) and `recover()` (`skills/upgrade-larch/scripts/upgrade-larch.sh:24-31`), which does document `rm -rf '$MARKETPLACE_CLONE'`—but only after a hard abort. On the full upgrade path (`skills/upgrade-larch/scripts/upgrade-larch.sh:328-337`), `claude plugin uninstall` has already run, so this failure mode can leave the operator with no installed plugin and a wedged marketplace until manual recovery. **`set -e` is not left in an inconsistent state** (`|| true` behaves correctly); the defect is proceeding to `add` without clearing a remove-failed clone. **Suggested fix:** Before `add_sparse_larch_marketplace` in both re-add branches, if `remove_larch_marketplace` fails (or unconditionally when `[ -d "$MARKETPLACE_CLONE" ]`), run `rm -rf -- "$MARKETPLACE_CLONE"` and log that automatic cleanup ran; then call `add_sparse_larch_marketplace`. Keep `recover()` as the backstop for add/network failures.

### Out-of-Scope Observations

- **`normalize_sparse_dirs` / `marketplace_sparse_cone_matches` (`skills/upgrade-larch/scripts/upgrade-larch.sh:48-62`)** — `LARCH_SPARSE_DIRS` is a single-space-separated constant; `tr ' ' '\n'` is sufficient today. Comparing sorted `git sparse-checkout list` output to sorted `normalize_sparse_dirs` is order-robust and treats future include-list growth as drift (re-add). In cone mode, `git sparse-checkout list` emits bare directory names (not `/*` / `!/*/` patterns), so the equality check is not inherently format-broken for current git behavior.

- **`recover()` ERR trap (`skills/upgrade-larch/scripts/upgrade-larch.sh:24-32`)** — `trap recover ERR` invokes `recover` as a function at failure time; `$MARKETPLACE_CLONE` and `$LARCH_SPARSE_DIRS` expand at call time, not at trap definition time. If `refresh_larch_marketplace` fails on the already-latest repair path (`skills/upgrade-larch/scripts/upgrade-larch.sh:311-314`), the script aborts before printing “Already at latest…” (`skills/upgrade-larch/scripts/upgrade-larch.sh:317-318`), so the operator sees recovery steps rather than a misleading success line.

- **Already-latest repair without reinstall (`skills/upgrade-larch/scripts/upgrade-larch.sh:309-319`)** — Documented in `skills/upgrade-larch/scripts/upgrade-larch.md:12`: marketplace-only repair on the idempotent path does not reinstall the plugin; that is contract-intentional and does not strand the user without an install the way the upgrade-path remove-then-failed-add sequence can.

- **Round-1 migration edge (first hop from pre-sparse release)** — Partially mitigated by the already-latest cone repair added in `9adf39b6a`; a single hop from an older *script* on an actual version bump may still use the previous marketplace logic until a second `/upgrade-larch` at latest stable—pre-existing class of migration risk, not introduced by the cone-matching helpers alone.
