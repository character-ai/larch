Reviewing the branch diff with a security focus on pause/resume state handling and validation.
### In-Scope Findings

- **security** `python/ship.py:508-517` — The new `_validate_ship_state_value` gate validates newlines and a few high-risk keys on write (`BRANCH_NAME`, `PR_URL`, `MERGE_RESULT`) but does not validate `REPO`, `ISSUE_NUMBER`, `RUN_ID`, or `PHASE` before persisting them into `ship-pr-state.sh`. Read-side resume logic does enforce repo slug shape (`_valid_repo_slug` at `python/ship.py:897-904`), so a partially corrupt or hand-edited state file can be written with a malformed `REPO=` and only fail later (or along paths that do not re-validate), which is inconsistent fail-closed hygiene for persisted ship identity. **Suggested fix:** Extend `_validate_ship_state_value` to reject non-empty `REPO` values that fail `_valid_repo_slug`, require digit-only `ISSUE_NUMBER`/`PR_NUMBER` when non-empty, keep `RUN_ID` on the existing slug rules, and allowlist `PHASE` to known ship phases before write.

- **risk-integration** `python/ship.py:905-943` — New gh-skipped resume logic treats `local_merged` as true when any two of four signals fire; `PR_CLOSED` and `MERGE_RESULT` are both read directly from the persisted state file, so a same-UID tamperer (or corrupt partial write) can satisfy the quorum without `post-merge-sentinel` or manifest evidence and be routed to `resume.start == "merged"` → `run_postmerge_phase`. That can advance post-merge finalization on a branch that was never actually merged in gh-skipped modes (`repo_unavailable` / forked). **Suggested fix:** Require at least one non-state-file corroboration for `local_merged` (e.g. `post-merge-sentinel` present, or manifest `status=done` plus sentinel), or raise the quorum so both `PR_CLOSED` and `MERGE_RESULT` alone are insufficient.

- **risk-integration** `python/ship.py:533-595` — `_write_ship_state` now round-trips `RESUME_PHASE` / `CALLER_KIND` from disk but always rewrites the full key set and only adds `CONFLICT_FILES` when the current call passes `extra_fields`; routine phase transitions therefore drop a previously persisted `CONFLICT_FILES=` line. That weakens the pre-push conflict handoff contract if any resume/rewrite happens before the orchestrator consumes conflict metadata from state. **Suggested fix:** On each write, read and preserve allowlisted handoff keys from the existing state file (at minimum `CONFLICT_FILES`) unless explicitly overridden in `extra_fields`, with `_validate_conflict_csv` applied before persistence.

- **security** `scripts/design-pause-load.sh:236-311` — The new `git ls-tree` + `git show` restore path checks `..` segments in `rel` but never verifies that each resolved `dest` remains under `$restore_tmp` before `git show >"$dest"` and the final `cp -R` into `$DESIGN_TMPDIR`; publish-side staging already uses ancestor/root containment, but restore does not mirror that invariant. A malicious or malformed tree path that slips past the prefix/`..` patterns could write outside the staging directory and then be copied into the validated design tmpdir. **Suggested fix:** After computing `dest`, reject unless its canonical path (`realpath` / `pwd -P` containment) stays under `$(cd "$restore_tmp" && pwd -P)`; optionally refuse non-regular files before `cp -R`.

### Out-of-Scope Observations

- **security** `SECURITY.md:40-53` — The pause/resume paragraph no longer claims post-extract symlink rejection; the old loader also did not implement symlink scanning (only `git archive | tar`). The new `git show > file` path is not a symlink-extraction regression, but the doc change correctly aligns stated guarantees with behavior.

- **risk-integration** `docs/issue-anchored-plan.md` / pause marker model — Collaborator-editable `larch:design-pause` markers can still redirect resume to another snapshot for the same issue; WI3 improves retryability but does not change that documented residual risk.

- **architecture** `python/ship.py:549-556` — Unknown `RESUME_PHASE` / `CALLER_KIND` values read from disk are silently cleared on write rather than failing closed; that is conservative for security but may mask corrupt state rather than surfacing it (pre-existing pattern extended by this branch).
