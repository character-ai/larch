Reviewing the branch diff and tracing pause-load contract consistency across loader, router, and docs.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/design-route.sh:294-384` — On `LOAD_OK=false`, the router still falls through to title-eligibility and the step-4 verdict instead of terminating pause recovery. For issues whose titles carry lifecycle brackets (typical paused `/design` state: `[DESIGNING]`, `[IMPLEMENTING]`), step 2 emits `ROUTE=cancel-title-filter` and the SKILL abort path (`skills/design/SKILL.md:402-404`, `434-439`) surfaces only the title-filter refusal, not the dedicated `cancel-pause-load` guidance at `skills/design/SKILL.md:399-401`. Loader `ERROR=` breadcrumbs may appear earlier in the KV stream but are easy to miss behind the title-filter banner. WI3’s keep-marker-on-failure improves retry on a later `/design`, but the same-run integration still reproduces the #3506 confusion pattern for any remaining restore failure (snapshot missing, extract error, jq-missing, etc.). **Suggested fix:** When `pause_marker_present` and parsed `LOAD_OK=false` (or non-zero loader rc), short-circuit before title-eligibility—emit `ROUTE=cancel-pause-load` (or a new `pause-load-retry` route) with loader `ERROR`/`WARN` preserved, and abort with the pause-load operator copy; add a `design-route.sh` harness case: pause marker + `[DESIGNING]` title + `LOAD_OK=false` must not land on `cancel-title-filter`.

- **risk-integration** `skills/design/scripts/design-route.sh:363-434` — The complementary fallthrough path is equally risky: when `LOAD_OK=false` and the title is *not* lifecycle-rejected and no `larch:plan` block is present, step 4 sets `ROUTE=proceed` while WI3 leaves the pause marker in the issue body. The orchestrator then starts a fresh design (`skills/design/SKILL.md:445-456`) with an active auto-resume pointer; the next `/design` re-enters pause load unconditionally. There is no behavioral test covering router verdict + marker retention together—only loader-level assertions in `skills/design/scripts/test-design-pause-resume.sh` and static SKILL grep pins in `scripts/test-design-structure.sh`. **Suggested fix:** Treat `pause_marker_present && LOAD_OK=false` as a hard gate (same as above) or require explicit operator acknowledgment before `proceed`/`already-planned`; add an integration fixture in `test-design-pause-resume.sh` or a small `design-route` smoke that stubs a failed load and asserts `ROUTE` is not `proceed`/`already-planned` and `.design-route-result.env` retains loader `ERROR=`.

- **risk-integration** `skills/design/SKILL.md:408-411` — `MARKER_CLEARED=false` plus `WARN=marker-delete-failed` are propagated through `design-route.sh:206-206,312-313` and printed as bare KV lines on `resume@*`, but the orchestrator never emits an operator-visible `**⚠**` explaining that the issue-body marker is stale and must be removed manually (as `SECURITY.md:103-106` and `scripts/design-pause-load.md:61-63` describe). A successful tmpdir restore with a failed `named-block-write.sh` delete therefore resumes the run while leaving a live pause marker that forces re-load on every subsequent `/design` until manual cleanup—exactly the nuisance called out in the feature description. **Suggested fix:** In the `resume@*` branch, when `MARKER_CLEARED=false`, print an explicit warning referencing manual marker deletion (and optionally log to `$DESIGN_TMPDIR/execution-issues.md`); extend the existing `GH_EDIT_FAIL=1` loader test with a `design-route.sh` invocation asserting the warning reaches stdout/result-env.
