Reviewing the branch diff and test stubs against production behavior.
### In-Scope Findings

- **code-quality** `skills/design/scripts/test-design-pause-resume.sh:99-124` — The `git` stub’s `ls-tree`/`show` arms ignore `archive_ref` entirely and always read from `$SNAPSHOT_ROOT` via `find`/`cat`, so every stubbed load (round-trip, recovery-branch fetch at ~672, local-recovery at ~700, `missing-restored-artifact`, etc.) passes even if real `git ls-tree FETCH_HEAD` / `git show origin/main:…` would return nothing or wrong blobs. That was the pre-fix failure mode for remote recovery and default-branch restore. **Suggested fix:** Teach the stub to honor the ref argument (e.g. map `FETCH_HEAD` / `origin/main` / `larch-log-design-recovery-*` to committed objects under `$TMP/repo` or a ref→tree fixture), or add real-git cases that commit the snapshot on a fetched remote branch and on `main` with `larch-logs/ export-ignore`, then load without using `$SNAPSHOT_ROOT` as a fake object database.

- **code-quality** `skills/design/scripts/test-design-pause-resume.sh:215-241` — The only real-git WI2 case exercises the local `larch-log-design-recovery-*` + `show-ref` path. Production also restores via `FETCH_HEAD` after `git fetch origin larch-log-design-<RUN_ID>` (~207-218 in `scripts/design-pause-load.sh`) and via `origin/<default>` when `LOG_RECOVERY_BRANCH` is absent (~219-228). Those ref-selection paths are still covered only by the filesystem-backed stub above, so a regression in fetch/ref binding or `git show "$archive_ref:…"` for non-local refs would not fail CI. **Suggested fix:** Add stub-free subshell fixtures: (a) snapshot committed only on `larch-log-design-<RUN>` with marker pointing at that branch (exercises `FETCH_HEAD`), and (b) snapshot committed on `main` with no `LOG_RECOVERY_BRANCH` (exercises `origin/main`), both in repos with `larch-logs/ export-ignore`.

- **code-quality** `skills/design/scripts/test-design-pause-resume.sh:115-124,849-858` — `GIT_STUB_SHOW_FAIL` is implemented for per-file `git show` failures, but the dedicated extract-failure fixture only sets `GIT_STUB_LS_TREE_FAIL=1`. A bug in the per-path `if ! git show …` loop in `scripts/design-pause-load.sh:245-247` would not be caught while ls-tree failure would. **Suggested fix:** Add a sibling case `GIT_STUB_SHOW_FAIL=1` (snapshot present, enumeration succeeds) expecting `ERROR=snapshot-extract-failed`, marker retained, and no `.resume-loaded`.

- **code-quality** `skills/design/scripts/test-design-pause-resume.sh:93-97` — `show-ref --verify` succeeds only for the hard-coded ref `refs/heads/larch-log-design-recovery-RUNPAUSE1`. The local-recovery load at ~700 and any future stubbed run-id would hit `snapshot-not-found` in production logic even when `$SNAPSHOT_ROOT` has data. **Suggested fix:** Derive the allowed ref from the marker’s `LOG_RECOVERY_BRANCH` / `RUN_ID` (or delegate `show-ref` to `$REAL_GIT` against `$TMP/repo` when that repo is populated).
