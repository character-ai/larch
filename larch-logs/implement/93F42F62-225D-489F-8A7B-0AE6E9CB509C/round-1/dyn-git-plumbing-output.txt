Reviewing the branch diff and git history for git-plumbing correctness issues.
### In-Scope Findings

- **correctness** `scripts/design-pause-load.sh:305-321` — Successful restore now copies the full snapshot tree with `cp -R "$restore_tmp"/. "$DESIGN_TMPDIR"/` but never clears a restored `.pause-requested`. For `--reason pause` publishes, `scripts/design-log-publish.sh:294-301` deliberately stages top-level `.pause-requested` when it exists at publish time (`design-pause-save.sh` publishes before its terminal `rm -f "$DESIGN_TMPDIR/.pause-requested"` at line 318), so deferred-pause paths (Bash-prelude / `design-postplan-emit.sh` / assessor exit 11) can commit that sentinel into `larch-logs/design/<RUN_ID>/`. WI2’s `git ls-tree`/`git show` extraction faithfully restores it; the next Bash prelude or postplan pause checkpoint then immediately re-executes `design-pause-save.sh`, producing a save loop instead of continuing at `STEP`. This was largely masked in the larch dev repo while `git archive` returned empty tarballs under `export-ignore`; it is amplified now that restore succeeds. **Suggested fix:** After a successful install (and before or after marker delete), unconditionally `rm -f "$DESIGN_TMPDIR/.pause-requested"` in `design-pause-load.sh`, or exclude `.pause-requested` from pause publishes in `design-log-publish.sh` even when `--reason pause`; add a harness case that seeds `.pause-requested` in the snapshot and asserts it is absent post-load.

- **correctness** `scripts/design-pause-load.sh:318-321` — When both `body-drift` and post-success marker deletion fail, the loader emits two separate `WARN=` lines but never combines them; callers that collapse duplicate keys to a single value (e.g. `awk … | tail -1`) will drop `body-drift` and only surface `marker-delete-failed`. `design-route.sh` accumulates all `WARN` lines into an array, but any downstream parser using last-wins semantics loses the drift signal that operators rely on to explain issue-body edits during resume. **Suggested fix:** Merge warnings into one comma-separated `WARN=body-drift,marker-delete-failed` value (or emit a single structured warning token) when both conditions apply, and extend the optional harness case to assert both tokens are visible on stdout.
