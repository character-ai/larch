Reviewing the branch diff and commit history against the pause/resume fix plan.
### In-Scope Findings

- **architecture** `scripts/design-pause-load.sh:321-324` — The success path can emit at most one `WARN=` line. When both `body-drift` and post-success marker deletion fail, line 321 emits `WARN=body-drift`, then lines 323–324 overwrite it with `WARN=marker-delete-failed`. That contradicts `scripts/design-pause-load.md` (“optional `WARN=body-drift` and/or `WARN=marker-delete-failed`”) and `design-route.sh`, which collects multiple `WARN` lines into an array. Operators lose the body-drift signal in the combined failure mode. **Suggested fix:** Emit both warnings (e.g. append `marker-delete-failed` to `WARN_VALUE` with a delimiter, or emit two `WARN=` lines) so `design-route.sh` can surface both.

- **architecture** `skills/design/scripts/design-route.sh:295-368` — On `LOAD_OK=false`, the route driver still falls through to title-eligibility (step 2) instead of stopping with `cancel-pause-load`. WI3 now keeps the pause marker on all restore/extract/content failures, so this path is hit more often on retry. On issues titled `[DESIGNING] …`, a retryable load failure (`missing-restored-artifact`, `snapshot-not-found`, etc.) can surface as `cancel-title-filter` rather than a pause-resume error — the failure mode seen in #3506 before WI2 landed. **Suggested fix:** When `pause_marker_present` is true and `LOAD_OK=false` (or the loader exits non-zero), set `ROUTE=cancel-pause-load` and emit the loader `ERROR=` token, without running title/re-entry routing; reserve fallthrough only for cases where the marker is absent or corrupt.

- **architecture** `python/ship.py:843-850,1270-1273` — `_resume_plan()` returns `_fresh_resume_plan(..., counters=counters)` when persisted `PR_NUMBER` is missing/invalid or `gh pr view` fails, preserving `ITERATION` / `REBASE_COUNT` / `FIX_ATTEMPTS` / `TRANSIENT_RETRIES` in the `ResumePlan`. `run_ship()` then takes the `fresh` branch (checks → postbump → pr-create) and, at merge-loop entry, zeroes all four counters because `resume.start != "open-pr"`. A mid-ship resume after transient `gh` failure or a blank `PR_NUMBER=` in state therefore reruns pre-ship phases and resets CI-merge budgets, which can repeat side effects and bypass iteration/fix caps that were already consumed. **Suggested fix:** Treat “fresh fallback with non-zero persisted counters and `PHASE` in `{ci-initial,rebase,merge}`” as a distinct resume class (or pass counters through on that path) so merge-loop entry preserves persisted counters and skips checks/postbump when PR identity is already known from state/context.

- **architecture** `scripts/design-pause-load.sh:203-204` — Snapshot restore binds `REPO_TOP` from the caller’s cwd (`git rev-parse --show-toplevel`), while `--repo` only threads `gh`. Running `/design` from a clone whose cwd is not the repo that holds the recovery branch can target the wrong worktree; the new export-ignore test documents `cd` into the init repo but the loader does not enforce or validate that binding.
