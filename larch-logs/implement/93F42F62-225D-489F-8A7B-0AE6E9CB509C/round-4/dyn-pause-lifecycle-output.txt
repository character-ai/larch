Reviewing the branch diff and pause/resume marker lifecycle changes.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/design-route.sh:294-368` — Pause resume is evaluated before title filtering and the `already-planned` verdict, so any issue body that still carries `larch:design-pause` will always take the `resume@<STEP>` path when `LOAD_OK=true`, even after design has finished and the issue holds a terminal `[DESIGNED]` title plus a composed `larch:plan`. With the branch’s delete-on-success lifecycle, a post-success `named-block-write.sh` failure (`MARKER_CLEARED=false`, `WARN=marker-delete-failed` in `scripts/design-pause-load.sh:322-327`) leaves that marker in place while the current run continues; a later `/design` on the same issue then restores the obsolete pause snapshot into a fresh tmpdir instead of routing to `already-planned` or refusing on the terminal title, which can roll back workspace state relative to the published plan. **Suggested fix:** After a successful load, treat `MARKER_CLEARED=false` as an operator-action-required condition (prominent `**⚠**` banner and/or `AskUserQuestion` before continuing), and add a terminal cleanup hook in `skills/design/scripts/design-publish.sh` (Step 5c) to retry pause-marker deletion; alternatively, gate resume in `design-route.sh` when a well-formed `larch:plan` is already present and the title is `[DESIGNED]`.

- **risk-integration** `skills/design/SKILL.md:408-411` — When resume succeeds but marker deletion fails, the orchestrator only prints machine lines (`MARKER_CLEARED=false`, `WARN=marker-delete-failed`) alongside `🔓 resumed from STEP=…` and immediately continues the design; there is no human-visible warning that the GitHub pause pointer is still live and will hijack the next `/design` invocation. Because `clear_pause_marker` in `scripts/design-pause-load.sh:31-39` still discards `named-block-write.sh` stderr, operators get no actionable signal about auth, permissions, or transient `gh` failures at the moment the stale-marker risk is created. **Suggested fix:** On `resume@*` when `MARKER_CLEARED=false`, emit a mandatory `**⚠ /design: pause marker could not be deleted — remove the larch:design-pause block manually before a future /design on this issue.**` line (and optionally surface `named-block-write.sh` failure text to `$DESIGN_TMPDIR/execution-issues.md`), matching the visibility standard used for other degraded-path notices in the skill.

### Out-of-Scope Observations

- Pre-existing architectural coupling: `design-route.sh` always prioritizes pause-marker detection over `already-planned`; this branch does not introduce that ordering, but it makes non-fatal marker-delete failure more explicit without adding a route-level guard.
- Round 3 correctly moved `.pause-requested` removal and `.resume-loaded` creation into `$restore_tmp` before `cp -R` (`scripts/design-pause-load.sh:306-311`), reducing partial-install risk on copy failure; remaining `cp -R` non-atomicity is a general shell limitation, not a regression specific to this change.
- WI1 (driver phase-sentinel allowlist in `scripts/design-log-publish.sh`) and WI2 (`git ls-tree`/`git show` restore with pinned `snapshot_sha`) align with the plan; marker keep-on-failure fixtures in `skills/design/scripts/test-design-pause-resume.sh` cover the intended WI3 polarity.
- Large unrelated diff hunks (`python/ship.py`, `python/run_logs.py`, etc.) are outside the pause/resume lifecycle scope for this review.
