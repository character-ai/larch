- **risk-integration** `skills/design/scripts/design-route.sh:294-368` — On `LOAD_OK=false`, the route driver intentionally falls through to title-eligibility (per `design-route.md`) rather than emitting `ROUTE=cancel-pause-load`. On a `[DESIGNING]` issue, a still-failing restore therefore surfaces as `cancel-title-filter` even though the loader already emitted a precise `ERROR=` token (e.g. `missing-restored-artifact`). This predates the restore rewrite; WI3’s keep-marker-on-failure makes retries more likely to hit it again, but the primary export-ignore failure mode is fixed by WI2 making `LOAD_OK=true` on the larch dev repo. **Suggested fix:** If misleading routing remains painful for remaining failure modes, add an explicit `LOAD_OK=false` branch in `design-route.sh` that emits `ROUTE=cancel-pause-load` (or a dedicated abort route) before title filtering, instead of relying on fallthrough.

Real-git export-ignore and origin/main cases compensate; this is a harness fidelity gap, not a production defect. **Suggested fix:** Extend the stub’s `rev-parse` handler to return a fixed OID (or delegate to `$REAL_GIT`) when `--verify` and `^{commit}` are present.
