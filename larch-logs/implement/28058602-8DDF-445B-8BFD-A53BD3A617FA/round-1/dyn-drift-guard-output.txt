### In-Scope Findings

- **correctness** `skills/design/SKILL.md:177-204,493` — Step 0-pre no longer binds `manual_requested`, but Step 0b still passes `--manual-requested "$manual_requested"` into `design-init-runparams.sh`, which requires `true`/`false` (`validate_bool_flag` at `skills/design/scripts/design-init-runparams.sh:130`). An unset variable expands to an empty string, so fresh `/design` runs should fail at Step 0b before plan-size or drift logic ever runs. **Suggested fix:** Remove `--manual-requested` from the Step 0b fence and finish removing `MANUAL_REQUESTED` / `manual_gate_b` from `design-init-runparams.sh` and `write-run-params.sh`, per the plan.

- **correctness** `skills/design/scripts/design-postplan-emit.sh:561-572` — Drift baseline is only written after `invoke-plan-validator.sh` succeeds (`exit 10` skips `_postplan_run_plan_size`). On the validator-defect Fix-and-retry path, the plan can grow across retries with no `drift-baseline.env`; the first successful `check-plan-size.sh` call then seeds the baseline from the already-expanded plan. That bypasses the guard for growth between initial Step 2b and first clean validation — the #3482 class of creep during iterative plan editing. **Suggested fix:** Snapshot baseline on the first successful plan-size parse after initial `plan.txt` write (even when validation later fails), or write baseline from the first validator-pass plan before accepting further edits, so later comparisons anchor to the original Step 2b size.

- **correctness** `skills/design/scripts/check-plan-size.sh:167-175` — If `drift-baseline.env` exists but `BASELINE_DIFF_LINES` is unreadable, the script warns and leaves `baseline_diff_lines` at the current `diff_lines` (initialized at lines 163–164). Diff-axis drift is then permanently disabled for that run while plan-axis drift may still fire. A corrupted/partial baseline file can silently disable half the OR rule. **Suggested fix:** On partial parse failure, treat the baseline as fully unreadable (warn once, skip drift for both axes) or fail closed on both keys; do not compare diff against current when the stored diff baseline could not be read.

- **correctness** `skills/design/scripts/design-postplan-emit.md:36-59` — The merged-mode contract documents exit codes through `13` only and omits `DRIFT_*` / `BASELINE_*` from the allowlisted result-env keys, even though `design-postplan-emit.sh` exits `14` and emits those keys (`skills/design/scripts/design-postplan-emit.sh:409-414`, `195-200`). Callers relying on the script contract can miss drift handling. **Suggested fix:** Add exit `14` (`PLAN_SIZE_STATUS=drift-trigger`), document FD3 `## Plan Size — Drift`, and list all drift KVs in the allowlist, matching `flags.md` and `SKILL.md`.

- **correctness** `skills/design/scripts/check-plan-size.md:38-59` — The `emit_kv` output table and exit-code section were not updated for drift (`DRIFT_TRIGGER_FIRED`, `DRIFT_MULTIPLE`, ratios, `BASELINE_*`, `drift-baseline.env`, seed-on-first-parse). The implementation emits these keys (`check-plan-size.sh:236-241`), but the normative contract doc still describes only hard/soft gates. **Suggested fix:** Extend `check-plan-size.md` with drift semantics (write-once baseline, zero-baseline rule, strict `>` OR combine, precedence under hard/partition) so standalone Step 2b.5 callers parse the full KV set.
