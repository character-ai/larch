Reviewing the drift-baseline guard: reading the diff and the key scripts.
### In-Scope Findings

- **correctness** `skills/design/scripts/design-postplan-emit.sh:560-570` — On the `VALIDATE_STATUS=defects-found` branch, the driver may run `_postplan_run_plan_size` (when `--snapshot-original` is set) and populate `DRIFT_TRIGGER_FIRED` / `HARD_TRIGGER_FIRED` in the result env, but it always flushes and exits **10** without calling `_postplan_finish_merged_plan_size`. That means Step 2b fix-and-retry loops that still have validator defects never surface drift (exit **14**) or hard/partition triggers (exits **12**/**13**), even when the plan has already grown past the write-once baseline. The orchestrator only handles exit **10** as a validator prompt, so cumulative drift can accrue silently during validator fix-and-retry — the same ratchet this feature is meant to stop. **Suggested fix:** After a successful plan-size parse on the defects-found path, route through the same precedence logic as `_postplan_finish_merged_plan_size` (hard → partition → drift) before returning exit **10**; or exit **14**/**12**/**13** when those triggers fire and reserve exit **10** for defect-only outcomes. Add a regression in `test-design-postplan-emit.sh` that seeds a baseline, re-enters with `defects-found` plus an over-threshold plan, and asserts exit **14** (not **10**).

- **correctness** `skills/design/scripts/check-plan-size.sh:199-216` — When `drift-baseline.env` is unreadable (partially corrupt keys, symlink, etc.), the helper re-seeds the baseline from the **current** plan size and forces `DRIFT_TRIGGER_FIRED=false` on that call. If the plan has already grown beyond the threshold (e.g. baseline `10/10`, current `21/10` at 2.1×), re-seeding to `21/10` permanently resets the anchor and suppresses the drift that should have fired (`test-check-plan-size.sh` case 36 encodes this). That creates a silent drift-guard bypass whenever the baseline file is damaged mid-run. **Suggested fix:** On unreadable baseline, either fail closed (treat as drift trigger / require operator Continue) or re-seed from the last known-good baseline if recoverable; do not re-anchor to an already-inflated current size without at least surfacing a drift prompt when the pre-reset comparison would have fired.
