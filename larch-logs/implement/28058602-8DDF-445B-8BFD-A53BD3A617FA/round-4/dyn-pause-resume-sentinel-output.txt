Reviewing the branch diff and tracing `.step3-reentry` through pause/resume and Gate-C re-entry.
### In-Scope Findings

- **architecture** `scripts/design-pause-save.sh:171-189` — The new `.step3-reentry` priority forces `STEP=3` whenever the marker exists, but pause publish stages the tmpdir as-is without running the sentinel hygiene that `skills/design/scripts/design-step3-state.sh:60-72` performs. After Gate A “Ready for review” or Gate C “Re-run review panel”, a pause in the window between marker write and Step 3 entry can snapshot **both** an unconsumed `.step3-reentry` **and** stale `.completed/step-3`…`step-4b` markers from the prior review pass. `scripts/design-pause-load.sh:321` strips only `.pause-requested` (documented in `scripts/design-pause-load.md:69-76`); it does not normalize `.step3-reentry` or downstream sentinels. Correct resume therefore depends entirely on `resume@3` always executing `design-step3-state.sh --direct-review-entry` before any other Step 3 work. If that fence is skipped (orchestrator regression), the marker is never consumed—every subsequent pause still emits `STEP=3`—while stale `step-3.5`/`step-3.6` markers can confuse Gate B / assessor routing (`design-step3-state.sh:50-54` refuses partial gate-b-bypass when those exist). That is a latent infinite Step 3 re-review loop. **Suggested fix:** Either (a) call `design-step3-state.sh --direct-review-entry` from `design-pause-save.sh` before `design-log-publish.sh` when `.step3-reentry` is present (producing a self-consistent snapshot and consuming the marker before publish), or (b) split the helper into “clear downstream + restore bypass package” vs “consume marker” and run the clear/restore half at save time while keeping the marker for `STEP=3` until Step 3 entry. Document the chosen contract in `design-pause-load.md` alongside the `.pause-requested` rule.

- **architecture** `skills/design/scripts/test-design-pause-resume.sh:1037-1058` — Direct-review pause coverage duplicates `design-step3-state.sh` logic inline and **consumes** `.step3-reentry` before `design-pause-save.sh` runs, so it never exercises the branch introduced at `scripts/design-pause-save.sh:171-172` (unconsumed marker + stale downstream markers coexisting in the published snapshot). A regression that stops writing the marker at Gate A/C, or that skips the Step 3 entry helper on `resume@3`, would not be caught by this harness. **Suggested fix:** Add a case that writes `.step3-reentry`, leaves prior `step-3`/`step-3.5` markers in place, pauses **without** consuming the marker, asserts `STEP=3` and that the published snapshot still contains `.step3-reentry`, then on load invokes `design-step3-state.sh --direct-review-entry` (not inline bash) and asserts downstream clears + marker consumption.

- **architecture** `skills/design/SKILL.md:103,638,1092` — The completion-sentinel table and Step 1e prose say `.completed/step-1e` is batch-written on every Step 3 entry, but the Step 3 fence only calls `design-step3-state.sh --direct-review-entry`, which is a no-op unless `.step3-reentry` is present (`skills/design/scripts/design-step3-state.sh:61-63`). Line 1092 correctly gates hygiene on the marker; lines 103 and 638 do not. Maintainers following the table may add an unconditional `step-1e` write to the Step 3 entry fence, which would mask backward-loop clears and shift `design-pause-save.sh` registry detection away from `STEP=1e` toward `STEP=3` even when Gate A discussion has not finished. **Suggested fix:** Align the sentinel table row and line 638 with line 1092: Step 3 entry writes `step-1e` and the bypass package only when `design-step3-state.sh --direct-review-entry` runs with the marker present; first-time Step 3 entry remains env + pause-check + timing only.
