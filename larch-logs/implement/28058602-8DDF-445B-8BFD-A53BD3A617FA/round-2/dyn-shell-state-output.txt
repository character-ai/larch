Reviewing the branch diff for Bash state-machine and shell robustness issues.
### In-Scope Findings

- **code-quality** `skills/design/scripts/design-postplan-emit.sh:318-330` — `_postplan_seed_initial_drift_baseline` calls `check-plan-size.sh` to write `drift-baseline.env`, but it discards both stdout and stderr, ignores `_seed_rc`, and always returns 0. If seeding fails (non-zero rc, unreadable tmpdir, or partial write), the failure is invisible to `execution-issues.md` and the later merged plan-size pass may still proceed with no durable baseline, disabling the drift guard without an operator-visible breadcrumb. **Suggested fix:** On non-zero `_seed_rc` or a missing `drift-baseline.env` after the call, append the captured stderr through `append-tool-failure.sh` (Warnings) and/or emit a `WARN=` KV; only return success when the baseline file exists and is a regular non-symlink file.

- **code-quality** `skills/design/scripts/design-postplan-emit.sh:305-316` — `_postplan_snapshot_drift_baseline` gates the write-once path with `[[ ! -e "$_baseline" ]]`, so a symlink at `drift-baseline.env` is treated as “already present” and the write is skipped silently. `check-plan-size.sh` explicitly rejects symlinks and emits a WARN, but `design-postplan-emit.sh` does not, leaving inconsistent machine state: post-plan emit believes baseline seeding is done while drift checks stay disabled. **Suggested fix:** Mirror `check-plan-size.sh` and require `[[ ! -e "$_baseline" ]]` for creation plus `[[ -f "$_baseline" && ! -L "$_baseline" ]]` before treating baseline as present; WARN and continue when only a symlink or unreadable file exists.

- **risk-integration** `skills/design/SKILL.md:1189-1207` — Gate-B-bypass sentinel handling is split across two mechanisms: the Step 3 branch matrix still instructs inline `mkdir` / `: > .completed/step-*` writes (lines 1189–1191), while later prose mandates `design-step3-state.sh --gate-b-bypass` (lines 1203–1207). That helper exits 1 with `STEP3_STATE=refused-partial-gate-b-bypass` when `step-3.5` or `step-3.6` already exists (`skills/design/scripts/design-step3-state.sh:51-54`), but the orchestrator fences redirect helper output to `/dev/null` and do not branch on exit code (e.g. `SKILL.md:1096`). A partial Step 3.5 resume can therefore leave bypass sentinels stale while the run continues toward Step 3b. **Suggested fix:** Make bypass paths use only `design-step3-state.sh --gate-b-bypass`, parse `STEP3_STATE=` from stdout, fail closed on `refused-partial-gate-b-bypass` or non-zero rc, and remove the duplicate inline sentinel prose from the branch matrix.

- **code-quality** `skills/design/scripts/check-plan-size.sh:132-151` — New drift ratio emission depends on `python3` inside `ratio_token` with no availability guard. Under `set -euo pipefail`, a missing or failing `python3` aborts `check-plan-size.sh` before any `DRIFT_*` / `PLAN_LINES` KVs are emitted, which can break Step 2b.5 and merged post-plan fences that assume exit 0 with a full KV contract. **Suggested fix:** Add a `command -v python3` guard that falls back to integer ceiling division in pure bash (or `awk`) for ratio tokens, emitting a WARN when degraded.
