Checking bypass scenarios and whether any unwired `codex exec` calls remain.
### In-Scope Findings

- **security** `scripts/lint-codex-exec-auth.sh:140-152` — `has_trailing_pragma()` matches `# lint-codex-exec-auth: ok` anywhere on the line (`line ~ /…/`), not only as a trailing shell comment. A same-line string such as `dummy=" # lint-codex-exec-auth: ok"; codex exec …` satisfies the pragma regex (space before `#` inside the quotes) and causes `scan()` to return before the `codex exec` check, so the linter passes while still dispatching unwired Codex. The harness only covers embedded pragmas where `#` is not preceded by whitespace (`test-lint-codex-exec-auth.sh:55-57`), so this bypass is untested. **Suggested fix:** Anchor suppression to a real trailing comment (e.g. require the match at `$` or after `;`/command terminators), or strip quoted strings before pragma detection; add a harness case for `VAR=" # lint-codex-exec-auth: ok"; codex exec …` that must fail.

- **security** `scripts/lint-codex-exec-auth.sh:143-152` — Detection is limited to the literal token sequence `codex[[:space:]]+exec`. Quoted or escaped command names evade it while remaining valid shell: `"codex" exec …`, `'codex' exec …`, and `\codex exec …` (backslash does not break the word at runtime). None of these appear in `test-lint-codex-exec-auth.sh`. **Suggested fix:** After env-prefix stripping, also flag lines matching `[\"'\\]?codex[\"'\\]?[[:space:]]+exec`, or normalize/remove quoted/`\\`-prefixed command tokens before matching; add harness fixtures for each evasion shape.

- **security** `scripts/lint-codex-exec-auth.sh:216-218` — Markdown scanning only enters a fence when the opener matches `^[[:space:]]*```[[:space:]]*(bash|sh|shell)[[:space:]]*$` (case-sensitive, nothing after the info string). Fences like ` ```Bash` / ` ```SH` are ignored, so a raw `codex exec` inside them is never scanned. The repo currently uses lowercase ` ```bash`, but the linter is meant to guard future skill/reference edits. **Suggested fix:** Case-fold the info string (e.g. `tolower()` on the capture) and/or accept common variants; add harness cases for ` ```Bash` and trailing-info openers.

- **risk-integration** `scripts/lint-codex-exec-auth.sh:33-40` — `review-and-fix.sh` is allowlisted by full path under `skills/review-and-fix/scripts/`, but every other `scripts/*.sh` file is exempted by basename alone. A new `scripts/review-and-fix.sh` (or any other allowlisted basename copied into `scripts/`) skips the entire file scan, not just the canonical launcher. The harness confirms a `skills/*/scripts/launch-codex-exec.sh` copy is not exempt (`test-lint-codex-exec-auth.sh:121-125`) but does not cover a misplaced `scripts/review-and-fix.sh`. **Suggested fix:** For `scripts/*`, allowlist only the known canonical paths (mirror the full-path rule used for `skills/review-and-fix/scripts/review-and-fix.sh`) instead of bare basenames; document the closed path set in `lint-codex-exec-auth.md`.

### Out-of-Scope Observations

- **Chained env prefixes (`FOO=bar CODEX_HOME=x codex exec`)** — The `sub()` on lines 150–151 correctly strips repeated `NAME=value` prefixes; harness cases at `test-lint-codex-exec-auth.sh:85-92` cover single and multi-prefix forms. No bypass found for that scenario.

- **Continuation-line join + pragma on the continuation line** — Backslash continuation merges lines before `scan()` (lines 156–172), so a pragma on the joined line correctly suppresses a multiline `codex exec` (intended). Pragma on a separate non-continued line does not suppress a prior `codex exec` line. Behavior matches the contract.

- **Non-git `find` fallback (`list_shell_files` / `list_markdown_files` lines 87–97, 111–121)** — `${path#./}` only removes a leading `./`; it does not create empty paths or skip allowlist checks in a way that would suppress violations. Duplicate entries would rescan the same file, not skip it.

- **`scripts/run-external-agent.sh`** — Still a generic passthrough with no auth logic; it only mentions `codex exec` in comments (line 55). Call sites that pass `codex exec` on the same line are still caught by the linter unless allowlisted. The original OOS about `/research` lanes calling Codex without shared auth is addressed in this branch by routing through `launch-codex-exec.sh`; residual risk is indirect dispatch shapes that avoid the literal `codex exec` substring (covered above).

- **Scan scope gaps (pre-existing by design)** — `hooks/`, `docs/`, `agents/`, and `test-*.sh` are outside the linter’s file globs; unwired `codex exec` there would not be caught. That matches the plan and is not introduced by this branch’s logic.
