I'll trace the codex-exec retry protocol across the launcher, metadata writer, and both collector parse sites.
### In-Scope Findings

- **architecture** `scripts/collect-agent-results.sh:504-1157` — The codex-exec retry contract is spread across three parallel copies: `parse_retry_meta` (lines 504–546), the inline empty-output meta parser (lines 965–1004), and two nearly identical launch builders in `launch_outer_retry_or_mark` (lines 671–718) and the main retry loop (lines 1113–1157). This branch added seven `OUTER_LAUNCHER_*` fields to each copy; rounds 1–2 already had to fix a jq-absent `--add-dir` fallback gap between the two launch sites, which is exactly the silent-breakage mode the scout notes warn about. Field coverage is symmetric today (launcher writes `OUTER_LAUNCHER`, `OUTER_LAUNCHER_PROMPT_FILE`, `OUTER_LAUNCHER_WORKDIR`, `OUTER_LAUNCHER_KIND`, `OUTER_LAUNCHER_SANDBOX`, `OUTER_LAUNCHER_WITH_EFFORT`, `OUTER_LAUNCHER_USAGE_LABEL`, `OUTER_LAUNCHER_TIMING_KIND`, `OUTER_LAUNCHER_ADD_DIRS_JSON`; both parse sites read them; both launch sites validate and replay them the same way, including `--with-effort` conditionality and the jq-absent workdir fallback), but nothing mechanically keeps those copies aligned. **Suggested fix:** Have the empty-output loop call `parse_retry_meta "$META"` instead of inlining the parser, and extract a shared `build_codex_exec_outer_retry_args` helper used by both `launch_outer_retry_or_mark` and the main loop so validation and argv reconstruction cannot diverge again.

### Out-of-Scope Observations

- **risk-integration** `scripts/collect-agent-results.sh:700-710,1139-1148` — When `jq` is absent at collector retry time, both sites intentionally fall back to a single `--add-dir "$META_OUTER_LAUNCHER_WORKDIR"`, even if `.meta` records multiple grants (e.g. `lint-fix-loop.sh`’s `run_dir` + `REPO_ROOT`). That matches `scripts/collect-agent-results.md` and is symmetric across both launch sites, but multi-dir callers can still lose sandbox grants on retry in jq-less environments.
