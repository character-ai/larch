Reviewing the linter implementation and its harness for the bypass scenarios described in the scout notes.
### In-Scope Findings

- **correctness** `scripts/lint-codex-exec-auth.sh:129-134` — The shell scanner matches `codex[[:space:]]+exec` only within a single physical line, so a backslash continuation splits the token and neither line matches: `codex \` on line N and `exec …` on line N+1 both pass. That is a practical bypass because continuations are already idiomatic in allowlisted launchers (e.g. `scripts/launch-codex-exec.sh:182-183`, `scripts/launch-review.sh:579`). A contributor can copy that shape into a non-allowlisted `scripts/*.sh` and satisfy `make lint-codex-exec-auth` while still dispatching raw `codex exec` without `external_prepare_codex_auth`. **Suggested fix:** Teach both scanners to join continuation lines before matching (track a trailing `\`, concatenate the next line), or reject any line ending in `codex[[:space:]]*\\` and any continuation line starting with `exec`. Add a harness fixture with a two-line `codex \` / `exec` dispatch in `scripts/test-lint-codex-exec-auth.sh`.

- **correctness** `scripts/lint-codex-exec-auth.sh:133-134` — The leading-env strip `sub(/^([[:space:]]*[A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*[[:space:]]*)+/, …)` treats `B=codex` as a complete `NAME=value` assignment (value `codex`), so `B=codex exec --full-auto …` is reduced to `exec --full-auto …` and no longer matches `codex[[:space:]]+exec`. That is a false negative introduced by this PR’s strip logic; it is distinct from legitimate `CODEX_HOME="$codex_home" codex exec` lines, which still contain an adjacent `codex exec` substring after partial stripping. **Suggested fix:** Only strip env prefixes when the value cannot be the command name `codex` (e.g. require `=` value not equal to `codex`, or strip only known launcher prefixes like `CODEX_HOME=`), or run the `codex exec` match on the original line as well as the stripped line. Pin `B=codex exec` (and `A=1 B=codex exec`) as failing fixtures in `scripts/test-lint-codex-exec-auth.sh`.

- **correctness** `scripts/lint-codex-exec-auth.sh:166-169` — The markdown fence scanner has the same per-line `codex[[:space:]]+exec` limitation as the shell scanner, so a two-line `codex \` / `exec` fence in `skills/**/*.md` is also invisible to the guard. Missing the shell scanner’s env-assignment strip does **not** let env-prefixed `CODEX_HOME=… codex exec` escape (those lines still match); the real markdown gap is continuation splitting, shared with the shell path. **Suggested fix:** Apply the same continuation-aware pre-pass in `scan_markdown_file` and add a markdown-fence bypass fixture to the harness (the plan and `docs/linting.md:508` claim a markdown-fence failure case, but `scripts/test-lint-codex-exec-auth.sh` has none).

- **correctness** `scripts/test-lint-codex-exec-auth.sh:34-58` — The harness is far narrower than the plan contract and acceptance criteria: it only covers a clean tree, a single-line unwired shell file, allowlisted basename, pragma suppression, and invalid `--root`. It does not exercise backslash continuation, `B=codex exec` stripping, markdown fences, `CODEX_HOME=… codex exec` outside the allowlist, helper-plus-raw-exec files, or comment/prose negatives promised in the plan (`scripts/lint-codex-exec-auth.md`, `docs/linting.md:20`). Those gaps let the bypasses above land without CI regression signal despite the linter being advertised as the mechanical enforcement layer for #3475. **Suggested fix:** Extend `scripts/test-lint-codex-exec-auth.sh` with explicit failing fixtures for each bypass shape and passing fixtures for the documented negative cases; update `scripts/test-lint-codex-exec-auth.md` to list them.

### Out-of-Scope Observations

- **correctness** `scripts/run-external-agent.sh` — Still a generic `codex exec` dispatcher with no auth wiring of its own; auth remains the caller’s responsibility. That predates this branch and is outside the six swept surfaces, though it remains reachable from non-allowlisted wrappers unless they hit the linter patterns above.
