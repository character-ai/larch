Tracing jq handling in the codex-exec retry path and reading the relevant code.
### In-Scope Findings

- **correctness** `scripts/launch-codex-exec.sh:221-224` — When `jq` is missing at metadata-write time, `_add_dirs_json` is forced to the literal `[]` even though `ADD_DIRS` was already normalized to at least one path at `97-99` and may contain multiple entries (e.g. `lint-fix-loop.sh` passes both `--add-dir "$run_dir"` and `--add-dir "$REPO_ROOT"` at `373-374`). That empty array is persisted as `OUTER_LAUNCHER_ADD_DIRS_JSON` in `scripts/lib-external-launcher-common.sh:63`, so a later retry cannot distinguish “no add-dirs” from “jq was absent when serializing.” **Suggested fix:** Do not silently write `[]` when `jq` is absent and `ADD_DIRS` is non-empty; either fail closed before launch, or persist add-dirs without `jq` (e.g. newline sidecar / repeated `OUTER_LAUNCHER_ADD_DIR_N=` keys) so retry metadata is faithful.

- **correctness** `scripts/collect-agent-results.sh:690-706` and `scripts/collect-agent-results.sh:1125-1141` — On empty-output retry, the new `launch-codex-exec.sh` path validates `META_OUTER_LAUNCHER_ADD_DIRS_JSON` with `jq -e 'type=="array"'` and rebuilds `--add-dir` via `jq -r '.[]?'`. If `jq` is absent at retry time, validation fails and `mark_retry_metadata_invalid` drops the retry entirely (`447-454`); the launcher’s workdir default (`launch-codex-exec.sh:97-99`) is never reached. When `jq` is present and metadata is `[]` (from the write-time fallback above), validation passes but no `--add-dir` flags are forwarded; retry then runs with only `--add-dir "$META_OUTER_LAUNCHER_WORKDIR"`, dropping extra grants such as `lint-fix-loop`’s session `run_dir` that may lie outside the repo root. The plan’s “default to workdir when no add-dir args” fallback applies only after jq validation/extraction, not when jq is missing or metadata was lossily written as `[]`. **Suggested fix:** Treat a missing/unparseable `jq` the same as an empty array for codex-exec retries (skip add-dir reconstruction and still launch the outer launcher so its workdir default applies), and/or reject launch at write time when add-dir metadata cannot be serialized; when metadata is `[]` but `WORKDIR` is known, explicitly pass `--add-dir "$META_OUTER_LAUNCHER_WORKDIR"` before launch so behavior matches the documented default even without relying on launcher internals.
