Reviewing `collect-agent-results.sh` retry-path parity: reading the diff and the function vs inline main-loop blocks.
### In-Scope Findings

- **correctness** `scripts/collect-agent-results.sh:1129-1145` — The empty-output retry main loop’s `launch-codex-exec.sh` branch always pipes `META_OUTER_LAUNCHER_ADD_DIRS_JSON` through `jq` (validation at 1129–1130, reconstruction at 1142–1145) with no `command -v jq` guard. `launch_outer_retry_or_mark` at 700–710 does guard: when `jq` is missing it skips JSON parsing and appends `--add-dir "$META_OUTER_LAUNCHER_WORKDIR"`. If `jq` is absent, the inline path treats the pipeline as malformed and marks retry metadata invalid instead of launching a degraded retry. That contradicts `scripts/collect-agent-results.md:38`, which documents missing-`jq` fallback for outer-launcher codex-exec retries (“Both parse sites”). `/research` and other `launch-codex-exec.sh` lanes use the inline empty-output path, not the NS-retry helper, so they are the ones affected. **Suggested fix:** Reuse the same `command -v jq` branch from `launch_outer_retry_or_mark` in the inline codex-exec block (or route empty-output outer-launcher retries through the helper with the original `${ORIG_OUTPUT}.prompt` sidecar), and add a harness case that runs empty-output retry with `PATH` excluding `jq` and asserts a launcher retry with `--add-dir "$WORKDIR"`.

- **architecture** `scripts/collect-agent-results.sh:671-718,1113-1154` — Codex-exec outer-launcher retry logic is duplicated between `launch_outer_retry_or_mark` and the inline main loop; this PR already diverged them (`jq` fallback, separate vs combined `OUTER_LAUNCHER_USAGE_LABEL`/`OUTER_LAUNCHER_TIMING_KIND` error strings, and `$prompt_file` vs `$META_OUTER_LAUNCHER_PROMPT_FILE` — the last is intentional for NS-retry). The duplication makes parity regressions likely on every metadata-field change. **Suggested fix:** Extract a shared helper (e.g. `build_codex_exec_outer_retry_args` + `launch_codex_exec_outer_retry`) used by both call sites; keep only the prompt-source difference (strengthened temp file vs `.prompt` sidecar) at the call site.

- **risk-integration** `scripts/test-collect-agent-results.sh` — The plan called for a `launch-codex-exec.sh` empty-output outer-retry fixture (assert launcher replay, preserved flags, no raw `codex exec`), but `test-collect-agent-results.sh` / `.md` were not changed on this branch. The `jq`-absent divergence above therefore has no regression coverage. **Suggested fix:** Add the planned fixture (including a no-`jq` variant) to `scripts/test-collect-agent-results.sh` per the plan’s acceptance criteria.
