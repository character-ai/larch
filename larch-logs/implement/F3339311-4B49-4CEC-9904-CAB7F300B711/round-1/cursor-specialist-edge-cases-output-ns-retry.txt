- **Severity:** **Important**
- **Focus area:** `correctness`
- **Location:** [`scripts/lib-vote-tally.sh:132-133`](scripts/lib-vote-tally.sh)
- **Issue:** The new guard `exonerate > yes` is false when `yes` and `exonerate` are both 1, so the exoneration branch no longer runs for the previously covered case `classify_result 1 0 1 2`.
- **Concrete scenario:** Degraded panel with `eligible_count` / `EFFECTIVE_VOTERS` == 2 (one voter casts `YES`, another `EXONERATE`, zero `NO`). Tallies pass `yes=1`, `no=0`, `exonerate=1`, `eligible=2` into `classify_result` ([`skills/review/scripts/tally-code-votes.sh:284-294`](skills/review/scripts/tally-code-votes.sh), [`skills/design/scripts/tally-plan-review.sh:209-219`](skills/design/scripts/tally-plan-review.sh)). **Before:** `yes > 0 && exonerate > 0 && no == 0` yielded `exonerated`. **After:** `exonerate > yes` is `1 > 1` → false → falls through to `rejected`, wrongly treating a mixed YES/EXON panel like a dismissal.
- **Suggested fix:** Keep the unanimous-EXON fix without breaking the YES+EXON, `no==0` path—for example combine disjuncts: `(( yes > 0 && exonerate > 0 && no == 0 ) || ( yes == 0 && exonerate > 0 && exonerate >= no ))`, or otherwise preserve the old branch for `yes > 0 && no == 0` while still mapping `0Y/0N/NE` to `exonerated`.
