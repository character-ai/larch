### FINDING_11: **architecture** `python/tracking_issue.py:706-717` — `read_main` emits shell-level `FAILED=true` / `ERROR=` envelopes from the pre-parse `_parse_read_argv` / `_validate_read_combination` path before `logging_util.quiet_init()` runs. Every other `*_main` calls `quiet_init` before envelope-producing work (or uses stderr-only argparse usage). Here, `_emit_failure()` → `emit_kv()` can run while `logging_util._quiet_active()` is already true from a parent `larch_quiet_init` subprocess, but the child has not yet snapshotted FD 1 onto FD 3. `contract_stream()` may then dup a stale FD 3 or fall back unpredictably, so stdout-captured callers (`implement-bootstrap.sh:911-957` `read_out=$(...)` + `kv_value_from_block FAILED`) can miss failures. Current bootstrap mitigates via `LARCH_QUIET_DISABLE=1`; quiet-active callers (`refresh-execution-issues.sh`, `design-publish.sh`, etc.) are not safe if they ever invoke `tracking-issue read`. **Suggested fix:** Call `logging_util.quiet_init(argv0="tracking-issue-read")` as the first line of `read_main`, before argv parsing that can emit contract output; keep parser-level missing-value failures stderr-only by catching them before any `_emit_failure` call.
