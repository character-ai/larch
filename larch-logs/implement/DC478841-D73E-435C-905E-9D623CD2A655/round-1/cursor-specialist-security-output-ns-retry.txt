1. **Latent** · **risk-integration** · [skills/review/scripts/tally-code-votes.sh:462-465](skills/review/scripts/tally-code-votes.sh)  
   Dead-slot rows use `st = (normed in collector_status) ? collector_status[normed] : "OK"`, so any manifest output basename absent from both the live score rows and the parsed collector map is labeled `STATUS=OK`.  
   **Issue:** The scoreboard can no longer distinguish “collector confirmed OK / zero findings” from “collector record missing or failed to parse for this basename” (crash, partial flush, path/key skew vs `norm_base`).  
   **Scenario:** Manifest lists `codex-generalist-output.txt`, collector env omits that `REVIEWER_FILE` block; the row still shows `STATUS=OK` ([skills/review/scripts/test-tally-code-votes.sh](skills/review/scripts/test-tally-code-votes.sh) case8 now asserts this). Operators or automation may treat the panel as fully healthy when one slot’s status was never verified.  
   **Suggested fix:** Keep `OK` only when policy is “assume success if absent,” but document that contract in [skills/review/scripts/tally-code-votes.md](skills/review/scripts/tally-code-votes.md) as an explicit trust limitation; or gate `OK` on evidence the collector file listed every manifest basename (else `UNKNOWN` / separate “absent” token).

2. **Nit** · **correctness** · [scripts/lib-vote-tally.sh:37-38](scripts/lib-vote-tally.sh)  
   The bold branch requires `\*\*Reviewers?\*\*:` immediately after optional leading list/space characters, with no `[[:space:]]*` before the colon.  
   **Issue:** A non-canonical but human-valid line like `- **Reviewer** : name` would not match and would fall through to `unknown` unless the unbolded fallback matches.  
   **Suggested fix:** Allow optional spaces before the colon in the first alternative, e.g. `\*\*Reviewers?\*\*[[:space:]]*:`, if voting-protocol allows that variant.
