### In-Scope Findings

- **correctness** `skills/review/scripts/collect-findings.sh:409-418` — **Important** (correctness; source both). `collect-findings.sh` writes `[OUT_OF_SCOPE]` items into the same `findings.md` ballot as in-scope rows (`### FINDING_N:` in both). The new `aggregate-findings.sh` pass (`skills/review/scripts/aggregate-findings.sh:72-75`, `190-260`) feeds that whole file to an LLM whose template only weakly guards OOS separation (`agents/orchestrator-aggregator.md:19-23`), and the Python validator only checks reviewer-slot coverage, not preservation of `[OUT_OF_SCOPE]` in the merged block heading. **Concrete scenario:** two in-scope `### FINDING_1` / `### FINDING_2` plus one `### FINDING_3: [OUT_OF_SCOPE] …` on the ballot; the aggregator emits a single merged `### FINDING_1: <new title>` whose first line no longer contains `[OUT_OF_SCOPE]`. `tally-code-votes.sh` classifies OOS via `head -n1 "$block" | grep -Fq '[OUT_OF_SCOPE]'` (`skills/review/scripts/tally-code-votes.sh:1611-1613`), so the OOS item is mis-classified as an in-scope finding for voting, accepted/rejected routing, and scoreboard `kind`. **Suggested fix:** exclude `[OUT_OF_SCOPE]` blocks from aggregation input (or split ballots), add validation that each merged output block’s first-line OOS state matches the union of merged inputs, or reject merges that would drop `[OUT_OF_SCOPE]` from any contributing source unless the model emits a dedicated OOS representation you explicitly parse.

- **correctness** `skills/review/scripts/aggregate-findings.sh:190-208` — **Latent** (correctness; source plan). `input_labels()` records each input block’s reviewer field as a single string and builds `input_set` from those strings, while merged output slots are split on commas (`skills/review/scripts/aggregate-findings.sh:226-228`). **Concrete scenario:** a single input block legitimately contains `- **Reviewer(s)**: slot-a-output.txt, slot-b-output.txt` (comma-separated on one line). `input_set` becomes `{ "slot-a-output.txt, slot-b-output.txt" }` but merged output lists `slot-a-output.txt` and `slot-b-output.txt` separately → validator flags `unknown reviewer slot` and aggregation always fails for that shape even though slots are valid. **Suggested fix:** split comma-separated input attribution the same way as output (or union tokenized slots from both sides) before building `input_set`.

The escape-hatch section claims `LARCH_AGGREGATOR_DISABLED=1` means the script “does not read or rewrite `findings.md`”, but `aggregate-findings.sh` runs `count_finding_blocks "$FINDINGS_FILE"` at lines 90–91 before the disabled branch at 106–109, so the disabled path still reads the ballot for `INPUT_COUNT`. **Suggested fix:** move the disabled check before any read of `--findings-file`, or revise the contract text to match behavior.
