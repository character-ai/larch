### In-Scope Findings

1. `- **risk-integration** `skills/review/scripts/review-core.sh:495-497` — **Important** — `review-core.sh` runs `aggregate-findings.sh` with stdout redirected to `review-core-aggregate.env` but stderr sent to `/dev/null`, so any unexpected `set -e` failure inside the aggregator (for example `jq` failing while writing `aggregator-slots.ndjson`, or other errors before `emit_result`), Python tracebacks from the inline validator, or `larch_err` diagnostics on mis-invocation are discarded while the shell still continues into voter dispatch on the existing ballot. **Suggested fix:** Stop discarding stderr (for example append `2>>"$REVIEW_TMPDIR/review-core-aggregate.stderr"` or inherit stderr), or at minimum tee/stderr-to-file and surface a single `emit_kv` breadcrumb when the aggregate exit status is non-zero so operators can correlate silent fallbacks with logs.

2. `- **architecture** `skills/review/scripts/aggregate-findings.sh:63-70` — **Latent** — `append_warning` returns 0 without logging when `append-execution-issue.sh` is missing or not executable (`[[ -x ... ]] || return 0`), and the downstream `append-execution-issue.sh` invocation also ignores failures (`2>/dev/null || true`). In broken installs, stripped-down checkouts, or permission regressions, aggregator failures that are supposed to produce an `execution-issues.md` Warning under **External Reviewer Issues** can vanish entirely while the run still proceeds with raw `findings.md`, which looks like a clean success. **Suggested fix:** On append helper absence or non-zero append status, fall back to `printf` into a well-known log under `REVIEW_TMPDIR` or stderr, or fail loud in CI contexts, so degradation remains observable.

3. `- **correctness** `skills/review/scripts/review-core.sh:484-497` — **Latent** — The aggregate step ignores exit status (`set +e` … `set -e` with no `if [[ $? -ne 0 ]]` branch), relying on `aggregate-findings.sh` to always exit 0 on intentional fallbacks. Any future refactor that reintroduces a non-zero exit for a recoverable class of errors (or an accidental `exit 1` path) would skip emitting `review-core-aggregate.env` KVs yet still advance to `dispatch-code-voters.sh` without an explicit branch, which is easy to misread when debugging partial tmpdir state. **Suggested fix:** Capture `$?` into a variable, append a structured `emit_kv AGGREGATE_EXIT_CODE "$rc"` (or assert `rc` is 0 / log when non-zero) before continuing, keeping the non-blocking contract explicit in `review-core` rather than implicit in the child script alone.

4. `- **code-quality** `skills/review/scripts/aggregate-findings.sh:118-123` — **Nit** — When `agents/orchestrator-aggregator.md` is absent, `REASON` is set to `validation-failed` and `AGGREGATED=false`, which overloads the same `REASON` used for post-dispatch Python validation failures; telemetry and `review-core-aggregate.env` consumers cannot distinguish a missing install artifact from bad LLM shape without reading the warning text. **Suggested fix:** Use a distinct `REASON` value (for example `missing-agent` or `template-missing`) while keeping exit status 0.
