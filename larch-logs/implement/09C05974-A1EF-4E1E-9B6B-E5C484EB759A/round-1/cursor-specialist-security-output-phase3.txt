### In-Scope Findings

- **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:29` — `missing_rp` is constructed with `${RANDOM}` (0–32767), a predictable Bash pseudo-random suffix. If a file with that exact name already exists in `$TMPDIR` from a prior harness run (including a leftover from a crashed run under the same PID), `read-design-review-budget.sh` may find a readable file rather than a missing one. Depending on that file's content, the `[[ == full ]]` assertion on line 30 could silently pass while actually testing the wrong code path (the file-parse path rather than the unreadable early-return). Since the path is never created or cleaned up by this harness, a stale leftover in `/tmp` across reruns is the primary risk vector. **Suggested fix:** Generate `missing_rp` with `mktemp --dry-run` (or construct it from a fresh `mktemp -d` subdirectory that is immediately `rmdir`'d) to guarantee non-existence without relying on `$RANDOM` uniqueness.

- **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:63-70` — The jq-path test prepends `$_jq_dir` before `$fakebin_pyonly` in PATH. On macOS Homebrew systems where both `jq` and `python3` live in `/usr/local/bin`, `_jq_dir=/usr/local/bin` resolves real `python3` before the fake stub in `$fakebin_pyonly`, so the test silently exercises the python3 branch rather than the jq branch. The assertion `[[ == quick ]]` passes either way, creating false coverage confidence for `read-design-review-budget.sh` lines 32–35. **Suggested fix:** After resolving `_jq_dir`, verify real `python3` is not also reachable from it (`[[ ! -x "$_jq_dir/python3" ]]`) and skip with a clear message if so, analogous to the missing-jq guard on line 68; or resolve the real jq binary to a symlink or wrapper that redirects only the `jq` executable into an isolated directory.
