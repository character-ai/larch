This confirms the PATH issue: `read-design-review-budget.sh` tries `python3` first (line 14), so if real `python3` is reachable via `_jq_dir` in PATH, jq is never reached.

### In-Scope Findings

1. - **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:63-70` — The `fakebin_pyonly` PATH places `$_jq_dir` **before** the stub directory: `PATH="$_jq_dir:$fakebin_pyonly:..."`. On every standard CI environment (Ubuntu `/usr/bin/jq` + `/usr/bin/python3` co-located; macOS Homebrew `/opt/homebrew/bin/jq` + `/opt/homebrew/bin/python3` co-located), real `python3` is in `_jq_dir` and is found before the stub. `read-design-review-budget.sh` calls `command -v python3` first (line 14 of that script), so real `python3` parses `{"review_budget":"quick"}` and returns `quick` — the jq branch (lines 32-35) is never reached. The test assertion `[[ "$_rdb_out" == quick ]]` passes via the wrong branch, giving false CI confidence that the jq path is covered. **Suggested fix:** Create a thin per-test wrapper directory containing only a symlink to the real `jq` binary (not the full `_jq_dir` directory), then use that wrapper in place of `_jq_dir`; this ensures jq is reachable while python3 falls through to the stub.

2. - **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:38-40` — `fakebin` is created on line 38 and `fakebin_pyonly` on line 39, but the EXIT trap covering both is not registered until line 40. Under `set -euo pipefail`, if the `mktemp -d` on line 39 fails after line 38 succeeds, the script exits with the prior trap (`rm -f "$tmp"` from line 18), leaking the `fakebin` directory. This is a new gap introduced by adding `fakebin_pyonly`; the prior harness had a single `mktemp` followed immediately by a trap update. **Suggested fix:** Update the trap immediately after each `mktemp -d`, or create both fakebins in a single atomic parent tmpdir.

3. - **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:72-76` — Four consecutive `mktemp -d` calls (lines 72–75) precede a single combined trap update on line 76. The prior harness had a two-directory gap (`dt`, `full_dt`) here — this PR amplifies it to four by adding `dt_norp` and `defects_dt`. Under `set -euo pipefail`, any failed `mktemp` between lines 72 and 75 leaves earlier successfully-created directories outside the active EXIT trap (which at that point still only covers `fakebin`, `fakebin_pyonly`, and `tmp`). **Suggested fix:** Update the trap incrementally after each `mktemp -d`, or create one parent tmpdir with four named subdirectories so a single `rm -rf` covers all four.
