### In-Scope Findings

1. **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh:63-70` — The jq-path test constructs `PATH="$_jq_dir:$fakebin_pyonly:..."` where `$_jq_dir` is the directory containing the real `jq`. On macOS with Homebrew, `jq` and `python3` are typically co-installed in the same directory (e.g., `/opt/homebrew/bin/`), so the real `python3` is found at `$_jq_dir/python3` *before* the stub in `$fakebin_pyonly`, causing the test to silently exercise the python3 branch rather than the jq branch. The assertion `[[ "$_rdb_out" == quick ]]` still passes because python3 also returns `quick` for `{"review_budget":"quick"}`, giving false CI confidence that the jq branch is covered. **Suggested fix:** After resolving `_jq_dir`, add `if [[ -x "$_jq_dir/python3" ]]; then echo "SKIP: python3 co-located with jq at $_jq_dir; jq-path branch untestable" >&2; else ...jq test...; fi` so false passes are never silently emitted.

2. **code-quality** `skills/design/scripts/test-read-design-review-budget-invoke.sh:38-40,72-76` — Four `mktemp -d` calls at lines 72-75 (`dt`, `full_dt`, `dt_norp`, `defects_dt`) run sequentially before the EXIT trap is updated at line 76; the trap registered at line 40 covers only `fakebin`/`fakebin_pyonly`/`tmp`. Under `set -e`, if any `mktemp -d` in lines 72-75 fails after earlier ones succeed, those earlier dirs (`dt`, `full_dt`) are orphaned on disk. A smaller window also exists between lines 38-39 where `fakebin` is untrapped if `fakebin_pyonly` creation aborts. **Suggested fix:** Update the trap immediately after each successful `mktemp -d`, or allocate a single parent tmpdir and use subdirectories so one `rm -rf` covers all paths.

3. **correctness** `skills/design/scripts/test-read-design-review-budget-invoke.sh`, `skills/design/scripts/test-read-design-review-budget-invoke.md`, `CHANGELOG.md` — The #2730 plan's acceptance criteria explicitly state "No script, validator, lint rule, harness, or `.tsv` registry is changed by this PR," yet the diff adds 64 lines of new test harness code and 9 lines of sibling-doc updates. These originate from bailed run `3D982BC8` for issue #2715 and are scope-divergent relative to the #2730 plan. Additionally, the `CHANGELOG.md` 42.4.5 entry (lines 27-29) documents only the #2715 harness expansion and contains no mention of the #2730 dedup-sweep feature — leaving the version bump changelog attribution incorrect for this PR's primary change. **Suggested fix:** Either move the #2715 harness changes to a separate PR tied to issue #2715 (and revert them here), or amend the 42.4.5 CHANGELOG entry to include the dedup-sweep feature alongside the harness expansion.
