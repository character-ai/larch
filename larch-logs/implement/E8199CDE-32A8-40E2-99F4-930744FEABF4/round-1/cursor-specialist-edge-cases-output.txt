### In-Scope Findings

1. **Important** (`correctness`) — [`skills/review-and-fix/scripts/review-and-fix.sh:704-719`](skills/review-and-fix/scripts/review-and-fix.sh): Resolution uses `elif [[ ${LARCH_DYNAMIC_ARCHETYPES_MAX+x} ]]` then assigns `DYNAMIC_ARCHETYPES="$LARCH_DYNAMIC_ARCHETYPES_MAX"`. If the variable is **set but empty** (common when a parent process exports `LARCH_DYNAMIC_ARCHETYPES_MAX=` to mean “unset”), the branch is taken, `DYNAMIC_ARCHETYPES` becomes empty, the `case` fails validation, and Step 5 exits `2` instead of falling through to session-env or the implement-mode default `4`. **Scenario:** wrapper or CI exports an empty value “for symmetry” with other `LARCH_*` vars. **Suggested fix:** treat empty like unset (e.g. only use the env branch when non-empty after trim, else fall through to `session_get` / defaults), matching the spirit of priority (2) vs (3)–(4).

2. **Latent** (`risk-integration`) — [`skills/implement/SKILL.md:1350-1352`](skills/implement/SKILL.md): Step 5 user-facing breadcrumbs hardcode `dynamic-archetypes cap=4` for both quick and hard modes. **Scenario:** operator passes `--dynamic-archetypes 0` or `--dynamic-archetypes 2`; logs still claim cap `4`, which misleads debugging and run forensics. **Suggested fix:** bind the printed cap to the resolved value (`dynamic_archetypes_value`, session-env, or explicit “default 4” only when that is what will run).

3. **Latent** (`architecture`) — [`skills/implement/SKILL.md:152-153`](skills/implement/SKILL.md): `--no-dynamic-archetypes` and `--dynamic-archetypes <N>` have no documented mutual-exclusivity or precedence rule (unlike `--draft` / `--merge`). **Scenario:** both appear in `$ARGUMENTS`; behavior depends on ad hoc parse order in the orchestrator. **Suggested fix:** document deterministic precedence (e.g. last wins) or abort with a warning like other mutex pairs.

4. **Latent** (`risk-integration`) — [`skills/implement/SKILL.md:153`](skills/implement/SKILL.md): Value-taking `--dynamic-archetypes <N>` is specified without the same mechanical “requires following token / validate numeric” guardrails used for flags like `--issue <N>`. **Scenario:** malformed argv can consume the feature description as `<N>` or leave `dynamic_archetypes_value` unset while the operator believed they set a cap. **Suggested fix:** add explicit parse rules (peek next token, reject non-`[0-4]`, do not strip past first non-flag).

5. **Nit** (`risk-integration`) — [`skills/implement/SKILL.md:4`](skills/implement/SKILL.md): YAML `argument-hint` omits `--dynamic-archetypes` / `--no-dynamic-archetypes`, reducing discoverability in UIs that surface the hint. **Suggested fix:** extend `argument-hint` to include the new flags.

6. **Nit** (`architecture`) — [`scripts/write-session-env.md:44-46`](scripts/write-session-env.md): “Edit-in-sync” requires updating [`skills/shared/subskill-invocation.md`](skills/shared/subskill-invocation.md) when adding session-env keys; this branch adds `LARCH_DYNAMIC_ARCHETYPES_MAX` but does not update that file. **Suggested fix:** add the key to the subskill handoff doc where session-env keys are enumerated.

7. **Important** (`risk-integration`) — [`scripts/write-session-env.md:44-46`](scripts/write-session-env.md) (doc) vs [`scripts/session-setup.sh:131-140`](scripts/session-setup.sh) and [`scripts/session-setup.sh:405-432`](scripts/session-setup.sh): The doc obligates updating `session-setup.sh` when adding session-env keys; `session-setup.sh`’s `--caller-env` parser still drops unknown keys and `WSE_ARGS` never forwards `--dynamic-archetypes` to `write-session-env.sh`. **Scenario:** any harness or skill that uses `session-setup.sh --caller-env … --write-session-env …` to **clone** a parent `session-env.sh` containing `LARCH_DYNAMIC_ARCHETYPES_MAX` silently strips the scout cap from the child file while the feature doc claims the key is part of the session contract. **Suggested fix:** add `LARCH_DYNAMIC_ARCHETYPES_MAX` to the caller-env `case`, validate `0`–`4`, and append `WSE_ARGS+=(--dynamic-archetypes "$CALLER_…")` when present (mirror `LARCH_TIMING_LEDGER` forwarding).
