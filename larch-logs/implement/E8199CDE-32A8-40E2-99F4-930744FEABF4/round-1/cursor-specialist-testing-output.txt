### In-Scope Findings

1. **Important** (`risk-integration`, `plan` / `requirements`): [`skills/fix-issue/SKILL.md`](skills/fix-issue/SKILL.md) never adds `--no-dynamic-archetypes` / `--dynamic-archetypes <N>` to the **Flags** list (lines 16–22) or the Step **5a** `/implement` invocation template (line 229), while [`<feature_description>`](.) calls out both `/implement` and `/fix-issue`. PR work delegated through `/fix-issue` still picks up the new default indirectly, but operators cannot turn the scout off or set a cap from `/fix-issue` the way they can for `--no-logs-commit` / `--auto`. Extend the Flags section and the documented `/implement ...` argv the same way as other pass-through flags.

2. **Important** (`correctness` + `risk-integration`): [`skills/implement/SKILL.md`](skills/implement/SKILL.md) line 153 tells operators that explicit `/implement` flags take precedence over `LARCH_DYNAMIC_ARCHETYPES_MAX` in the shell. In [`skills/review-and-fix/scripts/review-and-fix.sh`](skills/review-and-fix/scripts/review-and-fix.sh) lines 700–710, resolution is `CLI > process env (session_get branch skipped when unset) > session-env file > default`, so an **exported** `LARCH_DYNAMIC_ARCHETYPES_MAX` still wins over `LARCH_DYNAMIC_ARCHETYPES_MAX` written into `session-env.sh` from `--dynamic-archetypes`, because [`scripts/run-step5-review.sh`](scripts/run-step5-review.sh) does not pass `--dynamic-archetypes` on the CLI (lines 145–156). Concrete scenario: `export LARCH_DYNAMIC_ARCHETYPES_MAX=0` then `/implement --dynamic-archetypes 4` still runs with cap `0`. Fix by aligning docs with the script, or change precedence / have `run-step5-review.sh` forward the session value as `--dynamic-archetypes` so file and flags match operator expectations.

3. **Latent** (`risk-integration`, `plan`): The plan’s verification section leans on manual `grep` and `/relevant-checks`; the branch does not extend [`scripts/test-session-env-roundtrip.sh`](scripts/test-session-env-roundtrip.sh) (which already covers other `write-session-env.sh` flags in sections A–D, ending ~line 219) with cases for valid `0–4`, rejection outside that range, and `LARCH_DYNAMIC_ARCHETYPES_MAX` round-trip through `read-session-env-key.sh`. Nor does [`skills/implement/scripts/test-implement-review-token-propagation.sh`](skills/implement/scripts/test-implement-review-token-propagation.sh) assert that `review-and-fix.sh` passes `--dynamic-archetypes` into the stubbed `review-core` argv (the stub currently swallows unknown flags at lines 75–120). A future regression could drop the flag silently. Add focused assertions in those harnesses.

4. **Nit** (`architecture`): [`scripts/write-session-env.md`](scripts/write-session-env.md) lines 44–46 require updating `skills/shared/subskill-invocation.md` when adding session-env keys; that file is unchanged in the branch, so the documented “edit-in-sync” contract for the new `LARCH_DYNAMIC_ARCHETYPES_MAX` key is incomplete.
