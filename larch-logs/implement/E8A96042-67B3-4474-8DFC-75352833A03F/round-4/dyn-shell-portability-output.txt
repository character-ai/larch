### In-Scope Findings

- **correctness** `scripts/implement-bootstrap-invoke.sh:201-205` — On the success path, `set -euo pipefail` means any failure of `cat "$_inv_routing_buf" >"$_inv_routing_tmp"` or `mv -f "$_inv_routing_tmp" "$_inv_routing_file"` aborts the script before `cat "$_inv_routing_buf"` (stdout envelope) and before `rm -f "$_inv_routing_buf"`. Bootstrap has already completed, but the orchestrator’s `_inv_out=$(…implement-bootstrap-invoke.sh…)` gets a non-zero exit with empty or partial capture instead of routing keys, and `$IMPLEMENT_TMPDIR/bootstrap-routing.env.XXXXXX` / `${TMPDIR:-/tmp}/implement-bootstrap-routing.XXXXXX` can be left behind. Symlink/non-regular early exits (189–199) correctly `rm -f` the buffer; this happy-path block does not. **Suggested fix:** Wrap the write in a small cleanup handler (e.g. `trap 'rm -f "$_inv_routing_buf" "$_inv_routing_tmp"' EXIT` scoped to that block, or `mv` then emit stdout from the installed file and `rm -f` both temps in a single `|| { …; exit 1; }` branch) so temp files are always removed and, if `bootstrap-routing.env` was written, stdout still emits the envelope (or a documented non-zero exit after printing it).

- **correctness** `scripts/implement-bootstrap-invoke.sh:106-112,118-124` — In the `copy-plan` / `gh-issue-view` exit-2 arms, `_ib_redacted_err=$(mktemp …)` runs under `set -e`. If `mktemp` fails (full disk, bad permissions), the wrapper exits **1** before the arm’s operator `printf` and before the final `exit 2`, so callers expecting bootstrap’s exit **2** (and the SKILL `if [ "$_inv_rc" -eq 2 ]; then exit 2` path) see the wrong code and may miss the canonical stderr message. **Suggested fix:** Guard `mktemp` (e.g. `if _ib_redacted_err=$(mktemp … 2>/dev/null); then … redact …; rm -f "$_ib_redacted_err"; fi`) and always emit the existing operator string and `exit 2` even when redaction temp allocation fails.
