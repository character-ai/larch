### In-Scope Findings

- **architecture** `scripts/parse-bootstrap-routing-envelope.sh:67-104` — The handoff contract is split across two transports with different filtering rules. `implement-bootstrap-invoke.sh` omits empty `coder` / `coder_fallback` from `bootstrap-routing.env` on `--mode resume` (`scripts/implement-bootstrap-invoke.sh:163-168`, covered by `skills/implement/scripts/test-implement-bootstrap-invoke.sh:288-297`), but `parse-bootstrap-routing-envelope.sh` still scans the **unfiltered** wrapper capture `_inv_out`, which always includes `coder=` / `coder_fallback=` from `emit_final_tail` on plan-tail resume (`scripts/implement-bootstrap.sh:1362-1363`; resume path does not load coder from `session-env.sh`). File parse skips empty implementer keys (`scripts/parse-bootstrap-routing-envelope.sh:61-63`), but stdout fallback does not (`scripts/parse-bootstrap-routing-envelope.sh:77-78`). On dirty-tree resume with `--preserve-coder`, if the recovery bash fence does not re-export a non-empty `coder`/`coder_fallback` before sourcing the parser, `_inv_apply_routing_line_if_empty` can set them to `""` from those stdout lines and defeat the preserve-coder intent even though the filtered envelope file correctly omitted them. **Suggested fix:** In `_inv_apply_routing_line_if_empty`, skip `coder`/`coder_fallback` when `$_inv_value` is empty (matching file parse), and when `_preserve_coder=true` skip both keys entirely in the stdout-fallback loop; add a small offline harness (or extend `test-implement-bootstrap-invoke.sh`) that sources the parser with `--preserve-coder`, pre-set `coder=codex`, stub `_inv_out` containing `coder=`, and asserts `coder` stays `codex`.
