Reviewing harness wiring and integration: reading the diff, commit log, and key test/Makefile files.
### In-Scope Findings

- **risk-integration** `skills/implement/scripts/test-implement-bootstrap-invoke.sh:161-188` — Initial-mode success cases capture wrapper output with `out=$(run_wrapper …) || true` and never call `assert_rc` on exit status. If the wrapper or stub exits non-zero after logging argv to `stub-invoke.log`, argv assertions can still pass while stdout/envelope checks are skipped or weakened (the unset-`coder` block at 184–188 checks only `stub_log`, not `out` or `rc`). That lets a broken success path slip through CI. **Suggested fix:** Drop `|| true` on success paths (or capture `rc` explicitly) and add `assert_rc "$rc" 0` for each initial/resume success scenario before envelope assertions; keep `|| true` only where failure is the case under test.

- **risk-integration** `skills/implement/scripts/test-implement-bootstrap-invoke.sh:176` — The `bootstrap-routing.env` check is guarded with `[ -f "$STUB_TMPDIR/bootstrap-routing.env" ] && assert_contains …`, so a regression that stops writing the file produces no failure (only a skipped assertion). Acceptance and `scripts/implement-bootstrap-invoke.md` treat dual transport (stdout + file) as part of the contract. **Suggested fix:** Require the file unconditionally on success (`[ -f … ] || fail …`) and assert it matches stdout (or at least contains the same routing keys).

- **risk-integration** `skills/implement/scripts/test-implement-bootstrap-invoke.sh:191-206` — Resume-mode success coverage asserts argv/env pass-through and one stdout key but never checks that `bootstrap-routing.env` is written or populated. A resume-only regression in `_inv_emit_routing_kv` / file write would not be caught. **Suggested fix:** Mirror the initial success block: assert `rc=0`, file exists under `$RESUME_TMP`, and required keys (`REPO`, presence keys, `BRANCH_NAME`, etc.) appear in both stdout and the file.

- **risk-integration** `scripts/test-implement-structure.sh:534-539` — Structural “envelope key set” coverage only greps three substrings (`BRANCH_NAME`, `PLAN_FILE`, `coder_fallback`) in `scripts/implement-bootstrap-invoke.sh`. Those strings can match outside `_inv_routing_keys`, and the other ~17 contract keys (`REPO`, `IMPLEMENT_BAIL_REASON`, `STALL_TRACKING`, presence keys, etc.) have no pin. Dropping a key from `_inv_routing_keys` is exactly the failure mode called out in the plan and is unlikely to fail CI. **Suggested fix:** Pin the full `_inv_routing_keys='…'` literal (or diff it against `scripts/implement-bootstrap-invoke.md`) and extend `test-implement-bootstrap-invoke.sh` to assert every listed key appears in stdout and `bootstrap-routing.env` on success.

- **risk-integration** `scripts/test-implement-structure.sh:455-533` — The plan/acceptance require removing `_ib_handle_bootstrap_exit2` and `_ib_kv_scan` from `skills/implement/SKILL.md`, but structural pins only forbid specific `_ib_kv_scan` case-arm lines and named helpers like `_ib_run_bootstrap` / `_ib_parse_bootstrap_out`. Reintroducing `_ib_handle_bootstrap_exit2() {` or `_ib_kv_scan() {` would not fail `make test-implement-structure`. **Suggested fix:** Add inverted `grep -Fq` pins for `_ib_handle_bootstrap_exit2() {` and `_ib_kv_scan() {` (and optionally `_ib_handle_bootstrap_exit2` call sites) alongside the existing `_ib_run_bootstrap` / `_ib_parse_bootstrap_out` pins.

### Out-of-Scope Observations

- Makefile wiring looks correct: `test-implement-bootstrap-invoke` is in `.PHONY`, has a dedicated target via `harness-timer.sh`, and sits beside `test-implement-bootstrap` in `test-harnesses-15`. `make test-implement-bootstrap-invoke` currently reports PASS=60 FAIL=0.
- `docs/linting.md` documents `make test-implement-bootstrap` but not the new invoke harness target (and its shard note for bootstrap may already be stale vs `test-harnesses-15`); that is doc drift, not a functional harness bug.
- Exit-2 cases use substring `assert_contains` on operator messages rather than full literal pins; that predates this branch’s style in other harnesses but leaves room for silent message drift compared to the plan’s “byte-for-byte” goal.
