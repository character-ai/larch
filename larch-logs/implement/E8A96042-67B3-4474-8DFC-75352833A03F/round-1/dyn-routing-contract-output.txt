Reviewing the routing-envelope contract across the branch diff and key consumer files.
### In-Scope Findings

- **risk-integration** `skills/implement/SKILL.md:330-364` — Step 0 routing parse is **file-first with unconditional overwrite**, then stdout only via `_inv_apply_routing_line_if_empty`. Main only parsed bootstrap **stdout** (`_ib_parse_bootstrap_out` / `_ib_kv_scan`); this branch adds `bootstrap-routing.env` as the preferred source. If a prior invocation left a routing file (e.g. first pass with `IMPLEMENT_BAIL_REASON=dirty-tree`) and the current wrapper run does not replace it (crash between bootstrap success and `cat … > bootstrap-routing.env`, partial failure, or abnormal tmpdir reuse), file ingest can resurrect stale bail/branch/coder values while `_inv_out` has the fresh tail; stdout backfill will **not** override non-empty stale keys. That breaks dirty-tree recovery prose (“routing keys come from the resumed tail”) and can re-enter dirty-tree or stall routing. **Suggested fix:** Treat the current invocation’s stdout as authoritative: parse `_inv_out` into routing vars first, then overlay `bootstrap-routing.env` only for keys still empty; or have the wrapper atomically replace the file (write temp + `mv`) before printing stdout, and skip file read when `_inv_rc -ne 0`.

- **risk-integration** `skills/implement/SKILL.md:385-451` + `scripts/implement-bootstrap-invoke.sh:76-78` — Dirty-tree recovery uses `--mode resume` → `implement-bootstrap.sh --up-to-phase plan --resume-plan-tail`, which **does not run** `phase_coder_select` (see `implement-bootstrap.sh:1482-1501` vs `1491-1501`). `emit_final_tail` still emits `coder=` empty (`implement-bootstrap.sh:1362-1363`). The routing table’s continue row requires `coder` non-empty (`skills/implement/SKILL.md:372`), but plan-only resume cannot repopulate it; harness case B7-plan-dirty-tree resume does not assert `coder=`. This gap existed on main; the branch **amplifies** it by exporting `coder` from the filtered envelope in the recovery fence (`skills/implement/SKILL.md:451`) while the envelope cannot carry a real coder on plan-only resume—making an empty `coder` explicit in the shell environment. **Suggested fix:** Either map dirty-tree recovery to a resume path that reaches `phase_coder_select` (e.g. `--up-to-phase coder --resume-plan-tail`, matching `test-implement-bootstrap.sh` B7-coder-dirty-tree), or extend plan resume to rehydrate `coder` from durable session artifacts (manifest / run flags) and document that in `implement-bootstrap-invoke.md`; align SKILL routing prose with whichever contract you choose.
