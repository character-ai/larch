Reviewing exit-2 stream handling: reading the diff and key implementation files.
### In-Scope Findings

- **risk-integration** `skills/implement/scripts/test-implement-bootstrap-invoke.sh:157-189` — Exit-2 stream discipline is only regression-tested for `session-setup` (stderr message + empty stdout) and partially for `copy-plan` (stderr operator text only; stdout not captured). The plan and `scripts/implement-bootstrap-invoke.md` require every handled `STEP_FAILED` arm to emit operator text on **stderr** with **empty stdout**, including `gh-issue-view` redaction and redaction-failure fallbacks; arms `session-entry-gate`, `get-issue-state`, `issue-number-required-for-resume`, `gh-issue-view`, and `resume-plan-tail-sentinel` have no harness cases, so a future drift (e.g. dropping `>&2`, echoing bootstrap KV to stdout, or breaking the redaction pipe) would not fail CI. **Suggested fix:** Extend `test-implement-bootstrap-invoke.sh` with one stubbed `STUB_STEP_FAILED` case per wrapper `case` arm; for each, redirect stdout/stderr to temp files, `assert_rc 2`, assert the exact operator substring on stderr, `assert_not_contains` routing keys on stdout, and for `copy-plan`/`gh-issue-view` add subcases for successful redaction (assert raw secret absent from stderr) and redaction failure (assert the suppression message on stderr).

### Out-of-Scope Observations

- **Improvement (not a regression):** On `main`, `_ib_handle_bootstrap_exit2` used bare `printf`/`cat` (no `>&2`) inside `_ib_out=$(_ib_run_bootstrap)`, so operator messages were captured into `_ib_out` rather than reaching the terminal. The new wrapper (`scripts/implement-bootstrap-invoke.sh:86-132`) routes all formatted exit-2 text to stderr; `skills/implement/SKILL.md:313-318` and `399-404` correctly use `set +e` / `_inv_rc=$?` / `exit 2` without re-printing. Stream ownership matches the contract.

- **Pre-existing gap (unchanged):** `implement-bootstrap.sh` can exit `2` with `STEP_FAILED=create-branch`, `write-session-env`, or `emergency-bypass-log`, but the wrapper `case` (`scripts/implement-bootstrap-invoke.sh:91-130`) has no arms for those values—same as the old inline handler—so those failures still exit `2` with no formatted operator message.

- **Doc vs fence:** The “do not print `$_inv_out` on exit 2” rule lives in `scripts/implement-bootstrap-invoke.md:36-41`, not in the Step 0 fenced bash in `skills/implement/SKILL.md`; behavior is still enforced by the wrapper emitting only to stderr on exit `2`.
