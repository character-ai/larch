Auditing stdout/FD isolation on the branch diff and the cited scripts.
### In-Scope Findings
- **correctness** `scripts/test-collect-agent-results.sh:640-645` — The new dedup case is labeled “stdout unchanged contract” but only checks that `STATUS=FAILED` appears on stdout; it never asserts that stderr-tail body text (e.g. `fatal tool error line 100`) is absent from `DEDUP_STDOUT`. A regression that routed tails through `emit`/`printf` to stdout instead of `larch_err` would still pass. **Suggested fix:** Add explicit negative greps on the captured stdout file (e.g. `! grep -Fq 'fatal tool error' <<< "$DEDUP_STDOUT"` and `! grep -Fq 'agent stderr tail' <<< "$DEDUP_STDOUT"`) for dedup/distinct/launch-stderr cases, matching the plan acceptance line that stdout `KEY=value` bytes stay unchanged when `.stderr-tail` sidecars exist.

### Out-of-Scope Observations
Production paths audited for this focus look sound: `render_failed_agent_stderr_tail` is the only lib entry that intentionally writes tail bytes to **stdout**, and every in-tree caller either redirects that stream (`>"$_tmp_tail"` in `scripts/collect-agent-results.sh:1455`) or captures it in a subshell (`rendered=$(…)` in `scripts/lib-failed-agent-stderr-tail.sh:95`, `select_failed_agent_stderr_source` / `_resolve_collector_stderr_tail_file` via `$()`). Section 3.8 (`scripts/collect-agent-results.sh:1426-1508`) uses only `larch_err`, `printf` to the sig-map file, and `render … >"$_tmp_tail"`; it does not call `emit`, `emit_summary_result`, or mutate `RESULTS[]` toward stdout. `emit_failed_agent_stderr_tail_raw` (`scripts/lib-failed-agent-stderr-tail.sh:134-144`) and `run-external-agent.sh` failure/timeout paths (`scripts/run-external-agent.sh:268-312`) emit fences only with `>&2`. Wired callers (`plan-review-loop.sh:757-762`, `collect-findings.sh:212-213`) capture collector stdout separately from stderr (tee), so §3.8 diagnostics stay off the `KEY=value` plane.
