### In-Scope Findings

- **correctness** `scripts/hook-anti-read-poll.sh:106-133` — `bash_line_task_output_poll_token` splits on `;`, `&&`, and `||` without respecting shell quoting, so a single `echo`/`printf` argument that merely *mentions* `; cat tasks/<id>.output` (or `&&` / `||` with a task path) can be split into a synthetic segment that still contains a read verb plus a `tasks/…​.output` token on the unstripped segment text. That segment is treated as a real poll even though Bash never executed `cat`/`tail` on the task file (only the string inside quotes ran). **Suggested fix:** split only on metacharacters outside quotes (small quote-aware scanner), or run token detection on the full line first and require the match to lie outside quoted spans before incrementing task-output state.

- **correctness** `scripts/hook-anti-read-poll.sh:58-67` — `bash_has_read_verb` uses `grep -Eq '…(\-n\b|--quiet)'` for `sed -n` / `sed --quiet` reads. `\b` is not POSIX ERE; BSD/macOS `grep` often does not implement word boundaries, so `sed -n … tasks/<id>.output` polling may not be classified as a read verb on Darwin while the harness expects it (`scripts/test-hook-anti-read-poll.sh:237-241`). **Suggested fix:** replace `\-n\b` with a portable boundary such as `-[[:space:]]n([^[:alnum:]_]|$)` (and keep the existing `--quiet` branch), and add a harness case that asserts the pattern on the platform’s default `grep`.

### Out-of-Scope Observations

- **Documented `nosession` sharing:** When both `session_id` and `conversation_id` are absent, all callers hash to the same `nosession` bucket (`scripts/hook-anti-read-poll.sh:24-28`, `scripts/hook-anti-read-poll.md:24-29`). That can produce cross-conversation false positives for task-output polling; the contract already calls this out as accepted bleed.

- **Backward-compatible generic state:** `state-<cwd_hash>.tsv` remains `path\toffset\tcount\tfirst_ts`; new `state-taskout-<session_hash>-<cwd_hash>-<task_id>.tsv` files are additive and do not collide with the old format.

- **600s / 30s windows and thresholds:** Task-output uses threshold 2 / 600s with offset ignored on Read; generic Read stays threshold 3 / 30s with offset — consistent with the header comments and tests (including expiry at 601s → reset → fire on third read).

- **Quoted Bash paths:** Token extraction intentionally uses unstripped segment text (`scripts/hook-anti-read-poll.md:41-44`), so quoted `cat '…/tasks/…​.output'` works; the gap is quote-unaware splitting, not quote stripping before `extract_task_output_token`.

- **`--summary-only` collector:** `dispatch-with-waterfall.sh` phase collects skip the §3.8 stderr-tail emit by design (`scripts/collect-agent-results.sh:1426-1429`); plan-review’s foreground `collect-agent-results.sh` (no `--summary-only`) is where panel failure tails are meant to surface.

- **#3202 stderr-tail path:** Mode-aware source selection, pipefail-safe spool, collector dedup, Claude timeout clamp, and `collect-findings.sh` stderr tee align with the plan; no additional correctness defects identified in that surface beyond the hook parsing issues above.
