### In-Scope Findings

- **correctness** `scripts/hook-anti-read-poll.sh:53-61,77-85` — `bash_has_read_verb` treats `cat`, `head`, `tail`, etc. as word-bounded tokens anywhere in the full Bash command string, not only as shell commands. A jq/awk program or grep alternation that contains `"cat"` or `|cat|` (e.g. `jq 'select(.kind == "cat")' "$TASK_OUT"`) still matches while `extract_task_output_token` also finds `tasks/...output`, so the hook can increment the task-output poll counter and fire a reminder even though no read utility was invoked. **Suggested fix:** Gate on a stricter pattern (e.g. require a read verb only before the first `tasks/...output` match, or only in the segment after stripping single-quoted/double-quoted spans), and add harness cases for jq/grep literals that mention `cat` alongside a task-output path.

- **correctness** `scripts/hook-anti-read-poll.sh:87-115` — `bash_line_task_output_poll_token` splits on the first `;`, `&&`, or `||` in the line with no quote awareness, so metacharacters inside double-quoted strings or jq programs can produce garbage segments (false negatives for real polls) or, in edge cases, spurious segments that combine a read verb with a path. **Suggested fix:** Either document this as an intentional heuristic limit, or split only on unquoted operator boundaries (minimal state machine over `'`/`"`/`\"`), with harness cases for `";"` inside quotes and for pipelines where the task path appears only after a redirect on a later segment.

- **correctness** `scripts/hook-anti-read-poll.sh:64-66,117-127` — `bash_normalize_cmd` only joins backslash–newline continuations; a read verb on one physical line and `tasks/<id>.output` on the next line without `\` is evaluated as two lines, the first fails `extract_task_output_token`, and the second fails `bash_has_read_verb`, so multiline polls of that shape are never counted (false negative). **Suggested fix:** After normalization, if a line is only a read verb (or ends with one) and the next line yields a task-output token, treat them as one logical segment; add a harness case for `cat` newline `tasks/foo.output` without a trailing backslash.

- **correctness** `scripts/collect-agent-results.sh:1474-1476,1394-1410` — The §3.8 dedup emit pass skips only `OK`, `cap_hit`, and empty `STATUS`, but successful NS-retry paths that land on `CURSOR_EMPTY_RESPONSE` do not run the `rm -f "${ORIG_OUTPUT}.stderr-tail"` cleanup that the `STATUS=OK` branches do (`1157`, `1397`, `1412`). If an earlier attempt left `${ORIG_OUTPUT}.stderr-tail` and the final `REVIEWER_FILE` still resolves to that path (or retry resolution still sees a tail file), the collector can emit a failure stderr tail for a terminal degraded-success row. **Suggested fix:** Extend stale-tail removal to every NS-retry / transient-retry terminal success class you do not want treated as a hard failure (at minimum `CURSOR_EMPTY_RESPONSE`), or add those statuses to the dedup skip list when `EXIT_CODE=0`.
