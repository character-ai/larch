### In-Scope Findings

1. **Important** (`risk-integration`) [scripts/rebase-push.sh:253-269](scripts/rebase-push.sh): The force-push lease snapshot uses `git fetch "$BASE_REMOTE" "$CURRENT_BRANCH"` and `git rev-parse "$BASE_REMOTE/$CURRENT_BRANCH"` for the expected OID, but `BASE_REMOTE` is the **rebase base** remote (e.g. `upstream` when `ship-pr.sh` runs `rebase-push.sh --base-remote upstream --base-ref main` at [scripts/ship-pr.sh:1441-1443](scripts/ship-pr.sh)), while the topic branch is normally pushed to **`origin`** (the script even hardcodes `origin` for `--skip-if-pushed` at [scripts/rebase-push.sh:155](scripts/rebase-push.sh)). On a typical fork, `upstream/<feature>` often does not exist, so `EXPECTED_REMOTE_OID` can be empty or unrelated to the ref `git push` actually updates; recovery compares `HEAD` to the wrong remote-tracking ref. **Concrete scenario:** forked `ACTION=rebase` path succeeds at rebase then mis-handles lease / “already pushed” detection against `upstream/feature` instead of `origin/feature`, causing spurious push failures or a weakened/wrong lease versus the pre-change plain `git push --force-with-lease` behavior. **Suggested fix:** resolve the **push remote** for the current branch (e.g. `git config branch.<name>.remote` with fallback `origin`, or an explicit flag) and use *that* remote for fetch/rev-parse of `$CURRENT_BRANCH` and for the post-failure `REMOTE_HEAD` equality check; keep `BASE_REMOTE` only for the base ref used in `git rebase`.

2. **Nit** (`code-quality`) [scripts/git-push.sh:2769-2776](scripts/git-push.sh) and [scripts/rebase-push.sh:2873-2878](scripts/rebase-push.sh): Integer division makes `_base/4` zero for `_base=1`, so the documented “±25% jitter” does not match the first retry’s sleep math (docs in [scripts/git-push.md](scripts/git-push.md) / [scripts/rebase-push.md](scripts/rebase-push.md)). **Impact:** harmless timing skew vs documentation, not a trust-boundary issue. **Suggested fix:** align the comment/doc with the formula or adjust the formula to implement the stated jitter for all attempts.
