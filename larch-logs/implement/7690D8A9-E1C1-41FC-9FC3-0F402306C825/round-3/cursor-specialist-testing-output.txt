### In-Scope Findings

1. **`risk-integration` (Important)** — [scripts/ship-pr.md](scripts/ship-pr.md):72  
   The invariant bullet for `version_already_published` now says only that `run_rebase_rebump` enforces `REBASE_COUNT >= 5` before stalling, and no longer mentions the separate `ci-wait.sh` → `ci-decide.sh` decision matrix, which still applies `rebase_count >= 20` (`scripts/ci-decide.sh:118`, documented in `scripts/ci-decide.md`).  
   **Scenario:** An operator or doc reader assumes “all rebase storms are capped at five,” while the outer CI loop can still classify actions under the 20-rebase matrix until that path bails.  
   **Fix:** Restore explicit wording that there are two layers: the new `run_rebase_rebump` entry cap (5) and the existing `ci-decide.sh` rebase-count ceiling (20) for the polling loop.

2. **`risk-integration` / `correctness` (Latent)** — [scripts/rebase-push.sh](scripts/rebase-push.sh):253–262  
   `EXPECTED_REMOTE_OID` is built from `git rev-parse "$BASE_REMOTE/$CURRENT_BRANCH"`; when that ref does not exist yet, the OID is empty and the push becomes `git push --force-with-lease=refs/heads/<branch>:` with a bare colon.  
   **Scenario:** First push of a branch that has no `origin/<branch>` yet (or a transient fetch miss) may behave differently than the historical plain `--force-with-lease`, risking an unexpected hard failure instead of a normal create.  
   **Fix:** Define behavior for empty OID (e.g. fall back to `git push --force-with-lease` without an explicit expected OID, or document “remote branch must exist”) and add a harness or integration note for that branch-lifecycle edge.

3. **`risk-integration` (Nit)** — [scripts/test-ship-pr.sh](scripts/test-ship-pr.sh) (vendor exhaustion case ~3580–3625 in diff)  
   The harness was updated for five vendor attempts and check counts, but nothing asserts the new `STALL_STEP` tokens (`10-max-retries`, `12-max-retries`, `*-detached-head`) written to `ship-pr-state.sh`.  
   **Scenario:** A typo or regression could change stall labels without failing CI.  
   **Fix:** Add a narrow `grep`/assert on `STALL_STEP=` for the exhaustion fixture (and optionally one detached-head fixture if cheap).

4. **`risk-integration` (Important, `plan`)** — [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh), [scripts/compose-review-findings.md](scripts/compose-review-findings.md), [scripts/test-compose-review-findings.sh](scripts/test-compose-review-findings.sh)  
   These HTML-escape / fixture changes are not in the implementation plan’s file list for “ship-pr resilience,” yet they ship in the same branch and expand the regression surface (markdown output shape, redacted-token assertions).  
   **Scenario:** A failure in this path blocks `make lint` / shard 11 for a PR reviewers expect to be narrowly scoped to ship-pr / bump tooling.  
   **Fix:** Split into a separate PR or call out clearly in the PR body so reviewers bisect failures correctly.

5. **`risk-integration` (Nit)** — [.claude/skills/bump-version/scripts/apply-bump.sh](.claude/skills/bump-version/scripts/apply-bump.sh):106–107  
   The tolerated-artifact WARN list uses `awk '{print $2}'`, which only prints the second whitespace-delimited field; unusual `git status --porcelain` paths (e.g. embedded spaces with quoting) would produce a truncated WARN line.  
   **Scenario:** Operators chasing phantom files get an incomplete filename in the WARN line (filtering still uses full lines).  
   **Fix:** Print `$0` with the `?? ` prefix stripped, or use a more porcelain-aware path extractor.
