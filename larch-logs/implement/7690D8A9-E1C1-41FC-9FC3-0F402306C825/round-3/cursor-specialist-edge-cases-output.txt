### In-Scope Findings

1. **Important** (`architecture` / `risk-integration`) — [`scripts/ship-pr.sh`](scripts/ship-pr.sh) `run_rebase_rebump` still ends in [`scripts/git-force-push.sh`](scripts/git-force-push.sh) after [`scripts/rebase-push.sh`](scripts/rebase-push.sh) `--no-push` (see around `scripts/ship-pr.sh:1338-1345` in the current tree). The new snapshot lease + three jittered retries were added to the **force-push path inside** `rebase-push.sh` when push mode is enabled (`scripts/rebase-push.sh:244-284`), which **does not run** on that primary rebump flow. **Scenario:** the common `version_already_published` / `ACTION=rebase` storm on the default (non-fork) path still depends on `git-force-push.sh`’s older “push once, sleep 5s, push again” recovery, while fork mode’s direct `rebase-push.sh --base-remote upstream --base-ref main` **does** pick up the new loop—so resilience is uneven across modes. **Suggested fix:** align `git-force-push.sh` with the same lease snapshot + retry policy, or restructure `run_rebase_rebump` to perform the push via a single scripted path that already encapsulates the new behavior (without double-rebasing).

2. **Latent** (`risk-integration`) — [`scripts/git-push.sh`](scripts/git-push.sh) `38-52`: the loop retries on **any** non-zero `git push`, while [`scripts/git-push.md`](scripts/git-push.md) and header comments describe **transient non-fast-forward** races. **Scenario:** a stable auth/hook/permissions failure still incurs up to three attempts and up to several seconds of backoff before the operator sees the real error. **Suggested fix:** narrow retries to known transient signatures (e.g. non-fast-forward / ref lock text) or document that all push failures are retried.

3. **Latent** (`correctness` / `code-quality`) — [`scripts/rebase-push.sh`](scripts/rebase-push.sh) `262-283`: on exhaustion, `PUSH_OUTPUT` is only the **last** attempt’s stderr/stdout (`PUSH_OUTPUT=$(git push ...)` overwrites each loop). **Scenario:** intermittent failures with different messages lose earlier evidence in `PUSH_ERROR`, making postmortems harder. **Suggested fix:** append or log each attempt’s output to the fail file before sleeping.

4. **Nit** (`code-quality`) — [`.claude/skills/bump-version/scripts/apply-bump.sh`](.claude/skills/bump-version/scripts/apply-bump.sh) `106`: `_internal_list` uses `awk '{print $2}'`, which breaks if an untracked path contains spaces (possible with `core.quotePath` settings). **Suggested fix:** strip the `?? ` prefix from the full remainder of the line instead of taking field 2 only.

### Out-of-Scope Observations

1. **`scripts/ci-decide.sh`** still enforces `REBASE_COUNT -ge 20` (`scripts/ci-decide.sh:118-120`) while `ship-pr.sh` now stalls earlier at `REBASE_COUNT >= 5` in `run_rebase_rebump`. Not introduced as a contradiction by the new cap alone (ci-decide can still matter for other flows), but the outer “20 rebases” bail is largely **shadowed** for rebump storms handled entirely inside `ship-pr.sh`. **Why out of scope:** `ci-decide.sh` is not in the resilience-plan file list and was not changed by this feature diff.
