### In-Scope Findings

1. **Important** (`risk-integration`) [`scripts/ship-pr.sh:1110`](scripts/ship-pr.sh) vs [`scripts/ship-pr.sh:1143-1160`](scripts/ship-pr.sh): `run_evaluate_failure` still calls `exit_stall` with the legacy token `12c` when `FAILED_RUN_ID` is empty, while the same function now stalls with `10-max-retries` / `12-max-retries` and `10-detached-head` / `12-detached-head` for the new guard paths. A consumer that keys off `STALL_STEP` (or operators grepping logs) now sees two different naming schemes for the same phase family (`12c` vs `12-*`), which makes triage and automation brittle. Align the empty-`FAILED_RUN_ID` stall with the new `12-*` vocabulary (or document `12c` explicitly in [`scripts/ship-pr.md`](scripts/ship-pr.md) as the only legacy exception) so every exit from this function uses one coherent scheme.

2. **Important** (`architecture`) [`scripts/compose-review-findings.sh:57-72`](scripts/compose-review-findings.sh), [`scripts/compose-review-findings.md`](scripts/compose-review-findings.md), [`scripts/test-compose-review-findings.sh`](scripts/test-compose-review-findings.sh): The branch also ships HTML-escape behavior for composed findings plus fixture/assertion updates. That is unrelated to the stated ship-pr / apply-bump / retry resilience work, so review risk, rollback scope, and bisect clarity all suffer if this PR is reverted or cherry-picked. Split the compose escape work into its own PR (or at least its own commit series) so the resilience change stays reviewable in isolation.

3. **Latent** (`risk-integration`) [`scripts/git-push.sh:33-51`](scripts/git-push.sh): The retry loop treats any non-zero `git push` the same (auth/config errors, missing `origin`, branch deleted, etc.), sleeping 1s then up to ~3s more before surfacing the failure. Operators hit a hard misconfiguration and still wait through artificial backoff, which reads like a hung ship step. Narrow retries to signatures you classify as transient (e.g. non-fast-forward / lease text) and fail fast on obvious permanent errors, or gate retries behind an env flag.

4. **Latent** (`correctness`) [`.claude/skills/bump-version/scripts/apply-bump.sh:96-107`](.claude/skills/bump-version/scripts/apply-bump.sh): Tolerance relies on `grep` line anchors and `awk '{print $2}'` for the WARN list. Porcelain v1 can quote or escape unusual paths; anything with spaces or odd quoting will not match the `^?? …$` suffix patterns and can still fail the bump, while the WARN path can mis-list the path if `$2` is only the first token. Rare in practice but opposite to “tolerate launcher sidecars” if a tool ever drops a sidecar under a weird path. Prefer `git status --porcelain -z` + a NUL-safe filter, or match on `git ls-files -o --exclude-standard` output.

5. **Latent** (`risk-integration`) [`scripts/test-rebase-push-force-lease.sh`](scripts/test-rebase-push-force-lease.sh) (new harness): The stub forces `origin/feature` == `HEAD` after the first failed push, so the new multi-attempt push loop, real `sleep`, and “remote still diverges after fetch” behavior are never exercised. Regressions in the retry half of [`scripts/rebase-push.sh:2837-2875`](scripts/rebase-push.sh) could slip through. Add a second fixture that keeps remote ≠ local through at least two attempts, asserting push count and that `sleep` runs when expected.

6. **Nit** (`code-quality`) [`scripts/git-push.md`](scripts/git-push.md) vs [`scripts/git-push.sh:44-48`](scripts/git-push.sh): The contract text claims “~1s/~2s ±25%” for both sleeps, but the first post-failure sleep is effectively pinned at 1s because `_base/2` truncates to 0 when `_base=1`. Tighten the doc (or the formula) so operators are not mis-calibrating worst-case delay.
