### In-Scope Findings

1. **Important** (`risk-integration`) — [`scripts/ship-pr.sh:1143-1187`](scripts/ship-pr.sh) and [`scripts/ship-pr.sh:1155-1161`](scripts/ship-pr.sh): `run_evaluate_failure` and `run_rebase_rebump` now call `exit_stall` with new `STALL_STEP` values (`10-max-retries`, `12-max-retries`, `10-detached-head`, `12-detached-head`) where vendor-fix exhaustion and similar cases used to surface as `10` / `12c` (see still-present `exit_stall ... 12c` at [`scripts/ship-pr.sh:1110`](scripts/ship-pr.sh)). Any automation, dashboards, or operator playbooks that match exact strings like `STALL_STEP=12c` for “CI fix loop exhausted” will mis-handle the new stalls until updated. **Scenario:** a resume script treats `12c` as “open the failure log and re-run vendor fix” but never handles `12-max-retries`, so operators get a silent classification gap. **Fix:** document the new tokens everywhere `STALL_STEP` is interpreted, or emit a backward-compatible primary step plus a new diagnostic field (e.g. `STALL_REASON=`) so existing consumers keep working.

2. **Latent** (`security`) — [`scripts/compose-review-findings.sh:57-72`](scripts/compose-review-findings.sh): `escape_finding_body` only encodes `&`, `<`, and `>`. That matches the stated markdownlint/XML-token goal and is ordered correctly (`&` first). **Scenario:** if this markdown is later embedded in HTML/XML attributes or other contexts without further encoding, `"`, `'`, U+2028, or backtick-heavy payloads could still be problematic for that consumer. **Fix:** treat current escaping as sufficient for markdown-on-disk only; if a second consumer appears, centralize context-appropriate encoding (HTML entity set or a vetted library) rather than growing ad hoc `sed` rules.

3. **Nit** (`correctness`) — [`.claude/skills/bump-version/scripts/apply-bump.sh:96-107`](.claude/skills/bump-version/scripts/apply-bump.sh): Tolerance is implemented with fixed-string `grep -v` on porcelain lines plus `awk '{print $2}'` for the WARN list. **Scenario:** `git status` quoted or multi-field paths for `*.redacted.log` / `*.launcher-stderr` may not match the patterns, so the bump still fails closed (no integrity loss), or WARN may list an incomplete path. **Fix:** optional hardening with `git status --porcelain -z` and NUL-safe parsing if you need bulletproof coverage for odd paths.
