### In-Scope Findings

1. **Important** (`risk-integration`) [scripts/git-push.sh:26-49](scripts/git-push.sh): The retry loop runs `sleep` and retries after **any** `git push` non-zero exit, while comments and [scripts/git-push.md](scripts/git-push.md) describe transient **non-fast-forward** races only. **Scenario:** hook rejection, auth failure, or `remote: error:` still triggers up to two backoff sleeps before surfacing the real error, stretching CI time and suggesting a “transient” story when the root cause is permanent. **Fix:** gate retries on stderr/exit-signature (e.g. non-FF / “fetch first” patterns) or exit immediately on other classes of failures.

2. **Important** (`risk-integration`) [scripts/rebase-push.sh:244-269](scripts/rebase-push.sh): Same pattern: the force-push loop retries and sleeps for **every** failed `git push --force-with-lease`, not only lease / stale-remote races. **Scenario:** branch protection or credential failure still burns three attempts with jittered delay before the operator sees the true `PUSH_ERROR`. **Fix:** same selective retry classification as above.

3. **Important** (`correctness`) [scripts/ship-pr.sh:1131-1133](scripts/ship-pr.sh): The new comment claims a “cap at 5 **total FIX_ATTEMPTS across all evaluate-failure calls**,” but the implementation is a **`while` counter per `run_evaluate_failure` invocation**; `FIX_ATTEMPTS` in state is still incremented only after a **successful** `run_ci_fix_vendor` ([scripts/ship-pr.sh:1144-1146](scripts/ship-pr.sh)). **Scenario:** a maintainer “fixes” a perceived double-count bug or removes another guard believing this comment. **Fix:** rewrite the comment to match behavior (e.g. “up to five `run_ci_fix_vendor` attempts per invocation; backoff between failures”).

4. **Latent** (`correctness`) [scripts/test-apply-bump.sh:322-343](scripts/test-apply-bump.sh) vs [scripts/test-apply-bump.md:2684](scripts/test-apply-bump.md): Sub-test I and the contract doc say the tolerated path **emits WARN** to stderr, but the harness never asserts on `stderr.log`. **Scenario:** a regression deletes or routes the WARN and tests still pass. **Fix:** add an `assert_stderr_contains` (or equivalent) for the WARN prefix / substring.

5. **Latent** (`risk-integration`) [scripts/ship-pr.sh:1337-1343](scripts/ship-pr.sh) and [scripts/rebase-push.sh:244-269](scripts/rebase-push.sh): `run_rebase_rebump` finishes with `git-force-push.sh`, not the push segment of `rebase-push.sh`. The new triple retry + jitter lives on **`rebase-push.sh`’s own push path**, so **`ship-pr`’s Rebase + Re-bump “step 5” push still follows only `git-force-push.sh`’s existing single extra retry**, not this new loop. **Scenario:** heavy concurrent lease churn on the **rebump** force-push is not improved by this PR’s `rebase-push.sh` change. **Fix:** if rebump pushes are the motivation, extend `git-force-push.sh` (or call a shared retry helper) for parity.

6. **Nit** (`code-quality`) [scripts/rebase-push.sh:47-48](scripts/rebase-push.sh): The file header still says exit `2` means force-with-lease push failure only; detached HEAD before a push attempt also exits `2` with `PUSH_ERROR=…` ([scripts/rebase-push.sh:249-251](scripts/rebase-push.sh)). **Fix:** extend the exit-code block to mention the detached-HEAD push guard (sibling [scripts/rebase-push.md](scripts/rebase-push.md) already hints at this).

7. **Nit** (`correctness`) [scripts/git-push.sh:41-45](scripts/git-push.sh) / [scripts/rebase-push.sh:259-263](scripts/rebase-push.sh): For `_base=1`, `_jitter=$(( RANDOM % (_base / 2 + 1) ))` is `RANDOM % 1`, so jitter is always zero and the first backoff is a fixed **1s**, not “±25%” around 1s as documented. **Fix:** use a minimum jitter range (e.g. `max(1, _base/4)` as modulus) for the first backoff tier.

8. **Latent** (`architecture`) [scripts/compose-review-findings.sh:57-72](scripts/compose-review-findings.sh): HTML-escaping the full reviewer string and body after redaction changes the on-disk markdown (e.g. angle brackets in examples become entities). **Scenario:** human readers or tools that expected raw `<tag>` examples in markdown see escaped forms; likely acceptable for lint but it is a behavioral contract shift. **Fix:** document the rendered form in the contract doc or restrict escaping to contexts that trigger the linter.
