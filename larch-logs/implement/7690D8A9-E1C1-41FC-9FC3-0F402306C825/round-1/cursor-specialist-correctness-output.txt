### In-Scope Findings

1. **Important** `risk-integration` [scripts/ship-pr.sh](scripts/ship-pr.sh) (stall paths ~1159 and ~1176): `exit_stall` now uses `10-max-retries` / `12-max-retries` when `run_evaluate_failure` exhausts vendor retries; previously the merge-phase path used **`12c`** for that stall. **Scenario:** Any operator script, dashboard, or grep that branches on `STALL_STEP=12c` for “CI fix vendor gave up” will no longer match after this change, so recovery prompts stay generic or misclassified. **Suggested fix:** Document the rename in `skills/implement/SKILL.md` / operator-facing stall tables, keep backward-compatible aliases in `exit_stall`, or emit both old and new sentinel in `fail_file`.

2. **Important** `correctness` `plan` [scripts/ship-pr.sh](scripts/ship-pr.sh) (~1172–1178 vs ~1155–1159): **`STALL_STEP` is overloaded** — `10-max-retries` / `12-max-retries` is emitted both when `REBASE_COUNT >= 5` blocks `run_rebase_rebump` and when `run_evaluate_failure` exhausts five `run_ci_fix_vendor` attempts. **Scenario:** Telemetry or triage that only records `STALL_STEP` attributes “max retries” to the wrong root cause without opening the captured `fail_file`. **Suggested fix:** Use distinct steps (e.g. `12-rebump-cap` vs `12-vendor-cap`) or encode the branch in `fail_file` / state with a machine-stable `STALL_REASON=`.

3. **Nit** `correctness` `plan` [scripts/ship-pr.sh](scripts/ship-pr.sh) (~2581–2583): The new comment says the loop caps “**5 total FIX_ATTEMPTS across all evaluate-failure calls**,” but the implementation is a **per-invocation** `while` counter; `FIX_ATTEMPTS` is still incremented only on success as before. **Scenario:** A maintainer throttles unrelated global state or mis-tunes caps believing a cross-call aggregate. **Suggested fix:** Reword the comment to “up to five `run_ci_fix_vendor` attempts per `run_evaluate_failure` invocation.”

4. **Nit** `correctness` `plan` [scripts/test-apply-bump.sh](scripts/test-apply-bump.sh) (~2730–2745): Sub-test I matches the plan’s success criteria except it **never asserts** `stderr` contains the `WARN: larch-internal untracked artifacts` line required by the plan’s Testing bullet and by [scripts/test-apply-bump.md](scripts/test-apply-bump.md) (“emits a WARN line to stderr”). **Scenario:** WARN logging regresses to silence while the bump still succeeds; CI stays green. **Suggested fix:** Add `assert_stderr_contains` (or equivalent) for the WARN prefix.

5. **Latent** `correctness` `plan` [scripts/git-push.sh](scripts/git-push.sh) (~36–48): The retry loop backs off on **every** non-zero `git push`, not only transient non-fast-forward races described in [scripts/git-push.md](scripts/git-push.md). **Scenario:** Hard failures (auth, branch protection, missing upstream) still incur up to two sleeps (~1s then ~2–3s) before surfacing the same exit code. **Suggested fix:** Parse stderr / exit class and retry only on known transient patterns (similar to other net helpers), or document “all push failures retry.”

6. **Latent** `correctness` `both` [.claude/skills/bump-version/scripts/apply-bump.sh](.claude/skills/bump-version/scripts/apply-bump.sh) (~96–107): Tolerance only strips porcelain lines matching `^?? …`; **ignored** untracked files use `!!` in porcelain and **are not filtered**. **Scenario:** If `.launcher-stderr` / `*.redacted.log` are ever gitignored, `apply-bump.sh` still fails the dirty check despite the plan’s intent to ignore those artifacts. **Suggested fix:** Extend filtering for `!!` with the same basename rules, or document “must not be gitignored.”

7. **Latent** `correctness` `plan` [scripts/compose-review-findings.sh](scripts/compose-review-findings.sh) (~57–71): `escape_finding_body` runs `&` → `&amp;` **before** `<` / `>`, so text that already contains HTML entities (e.g. `&lt;tag&gt;`) gets **double-encoded** (`&amp;lt;…`). **Scenario:** A reviewer or fixture includes pre-escaped markup; composed markdown reads incorrectly (usually harmless for lint, wrong for humans). **Suggested fix:** Escape in an order or with heuristics that avoid double-encoding, or document “inputs must not contain pre-escaped entities.”

9. **Nit** `risk-integration` (scope: branch vs [implementation_plan](implementation_plan) file list): The branch diff also changes `scripts/compose-review-findings.{sh,md}`, `scripts/test-compose-review-findings.sh`, `.claude-plugin/plugin.json`, and large `larch-logs/…` trees — none are listed in the plan’s “Files to modify” for this resilience task. **Scenario:** Reviewers merge assuming a narrowly scoped PR; extra surface increases regression and review load. **Suggested fix:** Split commits/PRs or extend the plan/feature doc to list these follow-on changes.
