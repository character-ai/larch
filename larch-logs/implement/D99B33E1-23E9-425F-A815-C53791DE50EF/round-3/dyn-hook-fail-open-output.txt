### Out-of-Scope Observations

Reviewed `scripts/hook-anti-read-poll.sh` against the branch diff and the `hook-fail-open` checklist. The expanded script keeps the same contract as sibling hooks (`hook-post-bump-version.sh`, `hook-stop-fail-close.sh`): `set -uo pipefail` without `set -e`, explicit `exit 0` on parse/setup failures, and a final unconditional `exit 0`.

**Top-level and I/O paths** — `INPUT`/`jq`/`date`/`mkdir` failures are guarded with `|| exit 0`; invalid `HOOK_ANTI_READ_POLL_NOW` exits 0; `chmod` uses `|| true`.

**`emit_reminder`** — `jq` is wrapped in `2>/dev/null || true`, so a non-zero `jq` status cannot propagate.

**Helper return codes** — Parsers (`extract_*`, `bash_*`) use `return 1` only inside functions; callers use `|| exit 0`, `|| return 1`, or `if`/`&&`, and `set -e` is off, so a helper returning 1 does not terminate the hook. `handle_task_output_poll` / `handle_generic_read_poll` are invoked without `set -e`; their last commands are guarded `if` blocks or `… || true` writes, so they do not surface a non-zero status to the top level.

**`set -u`** — Globals (`now`, `state_dir`, `session_hash`, `cwd_hash`) are set before function definitions; branch locals use `local` or `${var:-}`; `tool_input` fields come from `jq` with `// ""` defaults. No unguarded `$1` at top level.

**`pipefail`** — Pipelines run inside functions or `if`/assignments with `||` fallbacks (`cksum|awk`, `grep|tail`, `task_id_from_token`). Failures downgrade to empty tokens or early `exit 0`, not hook abort.

**Callers** — Read/Bash branches call handlers then fall through to `exit 0` (Read task-output path uses an explicit `exit 0` after `handle_task_output_poll`).

The only realistic non-zero exits are `set -u` on a future unset reference or an external kill (e.g. the 5s `hooks.json` timeout on pathological multiline `Bash` payloads). Neither appears in the current diff as an unguarded execution path; timeout behavior is environmental, not a missing `|| exit 0` in-script.
