### Out-of-Scope Observations

I traced `handle_task_output_poll` (`scripts/hook-anti-read-poll.sh:100-140`) through all four entry states; the state machine behaves as intended:

| Entry state | Result after update | Reminder at threshold? |
|---|---|---|
| **(a)** absent file / `count=0` | `count=1`, `first_ts=now`, `age=0` | No (`count≠2`) |
| **(b)** `count=1`, within 600s window | `count=2`, `first_ts` unchanged, `age=now-first_ts` | Yes on 2nd read |
| **(c)** `count=1`, window expired (`age>600` or `age<0`) | reset to `count=1`, `first_ts=now`, `age=0` | No (new window start) |
| **(d)** `count≥2`, within window | increment (e.g. `2→3`) | No (`count≠2`; one-shot warn) |
| **(d)** `count≥2`, window expired | reset to `count=1` | No |

**Post-write age recalculation (`scripts/hook-anti-read-poll.sh:134-136`):** `age=0` with `count>1` occurs only on the within-window increment path (`1→2`) when `now==first_ts` (same-second second read). The block recomputes `age=$((now-first_ts))`, which remains `0`; the threshold check `count==2 && age<=600` still passes. It cannot cause a spurious reminder (increment only runs when `age≤600`) or a missed reminder (same-second reads still satisfy `age<=600`). The block is redundant for firing logic but harmless.

**Same-second handling:** two invocations at identical `now` correctly reach `count=2` and fire; a third same-second call reaches `count=3` and stays silent.

**State-file naming (`state-taskout-${session_hash}-${cwd_hash}-${task_id}.tsv`):** `task_id` comes from the normalized `tasks/<id>.output` token, so absolute/relative/wrapper variants share one counter (harness-covered). Different `cwd` values isolate concurrent projects even when `session_id` is absent (`session_hash=cksum("nosession")` is fixed). Generic Read state (`state-${cwd_hash}.tsv`) is never touched for task-output paths because the Read branch calls `handle_task_output_poll` then `exit 0` (`scripts/hook-anti-read-poll.sh:185-189`).

**Minor non-defect notes:**

- When `session_id` is absent, all sessions sharing the same `cwd`+`task_id` collapse to one counter; `scripts/hook-anti-read-poll.md:28` overclaims session isolation without qualifying the `nosession` fallback, and the harness never exercises distinct `session_id` values.
- After the one-shot reminder at `count==2`, continued polling within the 600s window (`count→3,4,…`) produces no further reminders; that matches the plan’s threshold-2 design.
- The Bash classifier requires read-verb and `tasks/<id>.output` on the same line (`scripts/hook-anti-read-poll.sh:65-82`), so variable-indirection patterns like `OUT=tasks/id.output` followed by `cat "$OUT"` are false negatives upstream of `handle_task_output_poll`; acceptable per plan edge-case notes.
