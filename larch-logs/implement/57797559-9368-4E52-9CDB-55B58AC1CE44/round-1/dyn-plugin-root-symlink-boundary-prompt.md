4. **Scout prompt override is plugin-root-only.** Even though Piece 1 doesn't yet use scope/session-root override paths, the narrow allowlist closes a latent injection surface (R3/F17, R4-validated).
5. **Reviewer attribution stamped from slot manifest** (R2/F15). Reviewer prompts no longer ask reviewers to write `**Reviewer**:` lines; the orchestrator stamps them post-collection. Cleaner separation of concerns; structured-validation contract unchanged.
6. **Scope-files derivation is best-effort fail-open**: parses plan's Files-to-modify headings via regex; on parse failure, falls back to a minimal stub so scout never fails-closed on missing scope.

## Edge cases

- **Scout subprocess fails** (timeout, parse-failed, claude-failed): wrapper emits `SCOUT_STATUS != ok` and writes an empty manifest. The dispatcher continues with just the 10 static reviewer slots; no degradation of single-round Step 3.
- **Reserved-slug collision**: wrapper drops violating archetypes with stderr WARN; remaining valid archetypes are kept up to the cap.
- **Aggregator fails severity-preservation validation**: same retry path as other aggregator validation failures (advance to next outer phase: Cursor → Codex → Claude); after all phases exhausted, the un-aggregated `findings.md` stays as the ballot.
- **Plan with no parseable Files-to-modify** (e.g., conversational plan): wrapper writes a minimal scope-files stub naming the plugin-root SKILL.md so scout has a valid input.
- **Plan-review prompt template missing or unreadable**: scout invocation falls back to its built-in `/review` prompt (current behavior); wrapper emits a stderr WARN. Acceptable degradation; doesn't break the single-round flow.
- **Both Cursor AND Codex unavailable**: `dispatch-with-waterfall.sh` waterfalls all slots (static + dynamic) to Phase 3 Claude per existing behavior.
- **`--trivial` tier**: unchanged. Trivial enters Step 3 via the existing `review_budget=quick` main-agent self-review path; no scout, no dynamic reviewers.

## Failure modes

2. **Aggregator severity validator over-rejects on partial-merge edge cases.** Adding a new validator rule risks rejecting historically-valid output shapes from /review or /implement runs. **Earliest signal**: post-PR `aggregator-validate.stderr` shows new failure rates. **Mitigation**: extensive fixture coverage in `test-aggregate-findings.sh` covering single-source-without-severity (existing legacy path) and multi-source-merge; preserve the existing `LARCH_AGGREGATOR_DISABLED=1` escape hatch.
