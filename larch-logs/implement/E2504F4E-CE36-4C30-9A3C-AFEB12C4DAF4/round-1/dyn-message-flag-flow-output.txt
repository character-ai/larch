### In-Scope Findings

Tracing `count` and `count_message_emitted` in `scripts/lint-readability-preamble.sh` (lines 64–113): both are reset at the start of every manifest iteration (`count=0`, `count_message_emitted=false` at 70–71), before `if [ -f "$file" ]`. A missing-file row therefore cannot inherit a prior iteration’s `count` or flag state under `set -u`.

Within an iteration:

| Path | `count` | `count_message_emitted` | Outer `ok != true` behavior |
|------|---------|-------------------------|----------------------------|
| File absent | Stays `0` | Stays `false` | Generic `missing …` only (case never entered) |
| `external-prompt`, file present, count wrong | Set in arm (76–86) | Never set | Generic `missing external-prompt` (unchanged) |
| `orchestrator-inline`, file present, count match | Set by `grep -Ec` (92) | Stays `false` | Skipped (`ok=true`) |
| `orchestrator-inline`, file present, count mismatch | Set by `grep -Ec` (92) | Set `true` in `else` (96–97) before outer block | Specific `expected … found …` only; generic suppressed (108–109) |

The `external-prompt` arm never assigns `count_message_emitted`. The orchestrator `else` always prints the count-mismatch line and sets the flag before the outer `if [ "$ok" != true ]` runs, so there is no double-print or silent suppression on the paths the harness exercises (`orchestrator-bad`, `orchestrator-partial`, `orchestrator-missing-file` in `scripts/test-lint-readability-preamble.sh` 143–145).
