Reviewing branch changes for `render-final-summary.sh` / `render-run-summary.sh` note-file integration.
### In-Scope Findings

- **risk-integration** `skills/design/scripts/render-final-summary.sh:350-381` — `compose_self_fallback` appends the `cancelled-outline` cancel-site line immediately after the sentinel (`printf '%s\n' '<!-- larch:run-summary v=1 -->'` then another `printf` for the note), while the primary `invoke_render` path delegates to `scripts/render-run-summary.sh:254-256`, which inserts a blank line (`printf '\n'`) before `cat` of the note file. On renderer failure (the degraded path documented in `render-final-summary.md`), outline-cancel summaries therefore differ by one newline from the happy path and from the implement analogue in `skills/implement/scripts/write-final-report.sh:457-461`. The `cmp` in `test-render-final-summary.sh:58` only checks stdout vs file on the success path, so this fallback divergence is untested. **Suggested fix:** In `compose_self_fallback`, stop inlining the cancel line; after the sentinel block, if `$DESIGN_TMPDIR/final-summary-notes.md` exists (or `OUTCOME=cancelled-outline` and the file was just written in `invoke_render`), append with the same `printf '\n'; cat "$note_file"` pattern as `write-final-report.sh` / `render-run-summary.sh`, and add a renderer-fail test for `--outcome cancelled-outline` that asserts byte parity with the primary path (including the blank line after the sentinel).

- **risk-integration** `skills/design/scripts/render-final-summary.sh:299-331` — For non-`cancelled-outline` outcomes, `invoke_render` always passes `--note-lines-file "$DESIGN_TMPDIR/final-summary-notes.md"` but only `rm -f`s that file in the `else` branch (`309`); if removal fails (permissions, immutable file, etc.), `render-run-summary.sh:254-256` will still append the prior run’s cancel-site text to a later outcome on the same `$DESIGN_TMPDIR`. `write-final-report.sh:397-399` avoids this by only adding `note_args` when the notes file exists. **Suggested fix:** Mirror implement: build `note_args` only when the notes file exists and is non-empty after the write/rm branch, using `${note_args[@]+"${note_args[@]}"}` at the `render-run-summary.sh` invocation; optionally fail closed (or overwrite/truncate) when `rm` of a stale notes file fails instead of `|| true`.

### Out-of-Scope Observations

- `--note-lines-file` is correctly declared in `scripts/render-run-summary.sh:93` and matches the name passed from `render-final-summary.sh:300`; missing or absent files are ignored at `254-256` (no error), which is safe for the common case where `rm -f` succeeds.
- `test-render-final-summary.sh:49-59` validates cancel-site content and sentinel ordering on the primary path only; it does not exercise fallback + `cancelled-outline` parity.
- `render-final-summary.sh` has no implement-style stage-1 `--cost-unavailable` re-invoke before `compose_self_fallback`; that asymmetry predates this branch and is outside the note-file integration scope.
