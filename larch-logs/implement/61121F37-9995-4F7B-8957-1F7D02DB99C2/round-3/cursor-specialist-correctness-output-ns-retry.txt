Reviewing the branch diff and commit history for correctness issues.
### In-Scope Findings

- **correctness** `skills/design/scripts/render-final-summary.sh:374-380` — **Plan-correctness / Important:** `render_or_fallback` treats `invoke_render` exit non-zero OR an empty `final-summary.md` as a signal to call `compose_self_fallback`, but on the Step 5c two-phase happy path `--pre-publish-only` can already have written a valid non-empty `final-summary.md`. If the later `--post-publish-only` render exits non-zero while the file is still non-empty, the self-fallback unconditionally overwrites the good pre-publish summary with `- **Cost**: N/A` and a reduced schema. **Concrete scenario:** pre-publish succeeds with a full `💰 TOTAL … Claude/Codex/Cursor` line; post-publish `render-run-summary.sh` fails once (transient error, bad arg, stub flake); chat and `larch:final-summary` upsert show the degraded N/A body instead of the pre-publish costs. **Suggested fix:** Only run `compose_self_fallback` when the render failed **and** `final-summary.md` is missing or empty; if render failed but the file is already non-empty (e.g. contains `<!-- larch:run-summary v=1 -->`), keep the existing file, still append the warning, and print that file.

- **correctness** `skills/design/scripts/render-final-summary.sh:136-150`, `skills/implement/scripts/write-final-report.sh:186-190` — **Plan-correctness / Important:** The plan’s FINDING_12 path was “all bucket counts zero **and** non-empty `token-report` stderr, OR `jq_ok=false`.” The branch now sets cost-unavailable whenever parsed totals and buckets are both zero, even when `token-report` succeeded cleanly. **Concrete scenario:** `token-report-final.json` is valid (`jq_ok=true`), stderr is empty, but all vendor totals and buckets are `0` (empty ledger / reporting glitch); an approved or merged run prints `- **Cost**: N/A` instead of the renderer’s `💰 TOTAL ~$0.00 — Claude $0.00, Codex $0.00, Cursor $0.00 | Tokens: …` breakdown, so the user still does not get the per-agent line the issue targets. **Suggested fix:** Restore the plan predicate: mark `_cost_unavailable` / `TOKEN_DATA_AVAILABLE=false` only when `jq_ok=false`, token JSON is missing, or (`sum_b=0` **and** `total_t=0` **and** stderr indicates token-report failure); otherwise pass zero token args and let `token-cost.sh` emit the $0.00 breakdown.

- **correctness** `skills/design/scripts/render-final-summary.sh:343` — **Completeness w.r.t. plan / Nit:** `compose_self_fallback` prints duration with `${DURATION:-N/A}`, which does **not** treat an empty string as N/A (only unset). `DURATION` is initialized to `""` and may stay empty when timing collection fails, while the primary `invoke_render` path normalizes via `render-run-summary.sh`’s `na()`. **Concrete scenario:** `render-run-summary.sh` fails and timing JSON is absent; the self-composed fallback emits `- **Duration**: ` with a blank value. **Suggested fix:** Use the same empty-to-N/A rule as the renderer, e.g. `[ -n "$DURATION" ] || DURATION=N/A` before printing, or call `na` logic inline.
