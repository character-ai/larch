Gathering implementation details for the disposition gate and URL-counting semantics.

Confirming gate logic: `filed > 0` short-circuit predates this change; the branch adds scanning of `oos-accepted-design.md`, which increases prose-URL exposure.

### In-Scope Findings
- **risk-integration** `scripts/oos-disposition-shared.inc.bash:20-37` + `skills/implement/scripts/oos-disposition-gate.sh:175-181` + `skills/implement/SKILL.md:1663-1668` — `count_filed_urls_union_files` counts every `https://…/issues/<digits>` substring via `grep -EhEo` across each `--filed-urls-file`, while the gate treats **`filed > 0`** as full disposition success (`exit 0`) whenever `non_security_oos > 0`. Passing `$_oos_design_path` (`oos-accepted-design.md`) as a second `--filed-urls-file` therefore lets **any** citation URL embedded in an OOS **Description** (or other prose) satisfy the gate even if **no** block has a real `- **Filed URL**:` from the filing pipeline and **not all** accepted design OOS were filed—this exposure is **amplified** relative to the old single sentinel file, because that markdown now deliberately carries long reviewer text. **Suggested fix:** For the design export path, count only structured filed markers (e.g. `grep` lines matching `^-[[:space:]]*\*\*Filed URL\*\*:` before URL extraction, or a dedicated sidecar URL list written by `/design`) so prose URLs cannot satisfy the gate; alternatively tighten the gate to compare counts or per-block linkage if you truly need “no silent drops.”

- **risk-integration** `skills/implement/scripts/test-oos-disposition-gate.sh:336-362` — The new multi-`--filed-urls-file` regression only unions two **URL-only** fixtures (`url-a.md`, `url-b.md`); there is **no** case where a `--filed-urls-file` is realistic `oos-accepted-design.md`-style markdown containing a stray `https://github.com/.../issues/<n>` in prose **without** matching `- **Filed URL**:` fields, so the false-pass integration called out above is **unguarded** and could regress silently. **Suggested fix:** After narrowing URL counting for design inputs (or emitting a URL-only sidecar), add a harness where accepted markdown lists **two** non-security OOS blocks but the design `--filed-urls-file` contains only a prose citation URL and assert the gate **fails** (exit **1**); until the product accepts that risk, a comment-only test locking in the permissive behavior would at least document intent but is weaker.

### Out-of-Scope Observations
- **risk-integration** `skills/implement/scripts/oos-disposition-gate.sh:175-189` — The coarse **`filed > 0`** short-circuit (not `filed >= non_security_oos`) and reliance on separate heuristics for `inline` / `rejected` already meant the gate was an aggregate “evidence of some filing/triage” check rather than a strict per-OOS pairing; that predates this branch but is worth noting next to `skills/implement/scripts/oos-disposition-gate.md:3` vs `:23` where the prose says “each” block must be accounted for while the exit table still allows `filed > 0` alone.

- **risk-integration** `CHANGELOG.md` / plan artifacts — The branch explicitly documents deferring stricter counting to a follow-up (OOS_1-style); that documents accepted risk rather than fixing it.
