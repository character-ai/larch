### In-Scope Findings

### FINDING_1: Entry `rm -f` can drop a prior first-pass sidecar on no-retry exits
- **focus-area**: correctness  
- **file:line**: [scripts/dispatch-code-voters.sh:236-246](scripts/dispatch-code-voters.sh) (`check_and_retry_voter_parse_rate`: `first_pass_sidecar` + `rm -f "$first_pass_sidecar"` before `status=…` / early `return 0` when status is not `NOT_SUBSTANTIVE`)  
- **issue**: The sidecar path is removed unconditionally at function entry. Any later early return on the “already OK” path deletes an existing `*-vote-output-first-pass.txt` (or `*-first-pass`) without recreating it. A second `dispatch-code-voters.sh` invocation against the same `--review-tmpdir` (manual re-run, harness reuse, or any workflow that re-dispatches without a fresh directory) can therefore erase a first-pass artifact from an earlier successful parse-retry, undermining the observability goal.  
- **suggested fix**: Only remove a stale sidecar when entering the parse-retry path (e.g. move `rm -f "$first_pass_sidecar"` to just after the `NOT_SUBSTANTIVE` gate, or replace with “remove only if we are about to overwrite after a successful retry” / use a uniquely named sidecar per attempt if cross-run retention is required).
