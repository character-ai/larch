Reviewing branch diff and Gate B / Step 3.6 routing in SKILL.md and approval-gates.md.
### In-Scope Findings

- **architecture** `skills/design/references/approval-gates.md:89-91` — Gate B **passive-summary mode** (`LOOP_STATUS=converged|cap-hit`) tells the orchestrator to offer **Continue to Gate C** and explicitly **not** run the shared post-apply pipeline (whose step 8 is the only place besides the zero-findings short-circuit that names Step 3.6). That path is the multi-round auto-revise lane—the main “death by 1000 cuts” scenario—yet it never runs `write-after`, never snapshots the round, and never invokes the assessor before approval. `assessor.md` and `SKILL.md` Step 3.5 prose also omit passive-summary from the settled-path list, so an LLM following Gate B can jump 3.5 → 4b while the anti-halt chain still says 3.5 → 3.6 → 3b. **Suggested fix:** Treat passive-summary “Continue to Gate C” as a settled path: run Step 3.6 (HARD, round ≥ 2) and `write-after` before Gate C, or document an explicit intentional exemption and add a forward-reference in passive-summary mode matching the zero-findings short-circuit wording.

- **architecture** `skills/design/SKILL.md:1136` — Step 3.5 tells the executor to proceed to Step 3.6 only after Gate B settles **and Step 2b.5 returns**, listing auto-apply / Apply all / go-through-each only. The zero-findings short-circuit in `approval-gates.md:76` routes to Step 3.6 **without** any `ACTION=EMIT_PLAN` or Step 2b.5. An orchestrator that treats the Step 3.5 sentence as authoritative can skip the assessor on the common “no accepted findings” path despite the Gate B reference doc saying otherwise. **Suggested fix:** Split the transition rule: paths that re-emit the plan require “Step 2b.5 returned, then 3.6”; zero-findings (and any other non-emit paths) say “proceed directly to Step 3.6” without the 2b.5 guard. Mirror the same split in `SKILL.md` Step 3.5 prose.

- **architecture** `skills/design/SKILL.md:1102` — The Step 3 post-loop matrix still says `LOOP_STATUS=zero-findings-degraded-panel` uses Gate B’s zero-findings short-circuit and **continues to Step 3b**, bypassing Step 3.6 entirely. This branch was not updated in the same change that added Step 3.6 to `approval-gates.md:76` and the new Step 3.6 block. Competing normative sources on the same Gate B exit create a silent assessor bypass. **Suggested fix:** Change line 1102 to `Step 3.6 → Step 3b` (HARD) to match `approval-gates.md`, or distinguish degraded-panel from empty-accepted-findings if they are meant to differ.

- **architecture** `skills/design/SKILL.md:1151-1161` — Step 3.6 uses `$ROUND_NUM` for `write-after --round "$ROUND_NUM"` but only re-reads the cursor when `ROUND_NUM` is **empty**. `ROUND_NUM` is set inside the Step 3 fenced Bash block and is not persisted to a `.env` file (unlike `.step3-review-cap.env`). Separate Bash invocations per step often do not share shell locals; when they do, a stale non-empty `ROUND_NUM` from an earlier cycle is worse than an empty one because the fallback never runs. **Suggested fix:** Always derive the round in Step 3.6 from `snapshot-plan-round.sh read-cursor` (or persist `ROUND_NUM` at the end of Step 3 to something like `$DESIGN_TMPDIR/.step3-round.env` and source it in 3.6). Do not gate the re-read on emptiness alone.

- **architecture** `skills/design/references/approval-gates.md:154` — Gate C’s “When” section still enumerates settled paths as `… → Step 3b → Step 4 → Step 4b`, including `zero-findings short-circuit → Step 3b`, with no Step 3.6 in the chain. That contradicts the updated zero-findings text at line 76 and omits passive-summary’s divergent routing. **Suggested fix:** Update every enumerated path to `Step 3.6 → Step 3b → Step 4 → Step 4b` on HARD runs (and add a passive-summary bullet if that path is meant to include the assessor).
