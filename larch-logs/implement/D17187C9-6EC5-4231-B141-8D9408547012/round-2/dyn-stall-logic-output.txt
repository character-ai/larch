### In-Scope Findings
- **correctness** `scripts/lib-cursor-launcher-common.sh:150-156` — While `--output` is still missing and `target_pid` is alive, the stdout branch treats every poll as progress (`has_prog=true`), which refreshes `last_prog_ts` on each iteration, so `elapsed` never grows and the stall monitor can fail to fire for hangs where the capture redirect never creates the file (or the file is deleted mid-run and never recreated). This is separate from the time-bounded zero-byte grace on lines 153–155, which cannot suppress stalls indefinitely once `now - monitor_start_ts >= stall_threshold` as long as the file exists at size 0. **Suggested fix:** Bound the “missing output file” case the same way as the zero-byte startup window (only treat a missing file as progress when `((now - monitor_start_ts < stall_threshold))`), or document and enforce an invariant that the capture file always exists before monitoring and drop the unbounded missing-file branch.

### Out-of-Scope Observations
- The scout concern about the third `stdout` branch (`cur_size==0` with `now - monitor_start_ts < stall_threshold`) **does not** permanently suppress stalls for a created-but-still-empty file: once the age since `monitor_start_ts` reaches `stall_threshold`, that branch stops matching, size remains 0 with no `last_size` change, `has_prog` stays false, and `elapsed` grows until the stall fires.
- The `tree` subshell’s `set +o pipefail` plus `find … | head -n 1 | grep -q .` makes the tested condition be **`grep`’s exit status**, so “match vs no match” behaves as intended; with `pipefail` off, a `SIGPIPE` from `head` after a match does not force a false non-zero pipeline status that would starve `last_prog_ts`.
- Using `date +%s` (1-second resolution) with a 3-second threshold and sub-second polling mostly adds **jitter and up-to ~1s quantization skew** versus true wall time; it does not systematically fire a full poll interval *before* a literal 3.000s wall-clock stall in the common case, and tends to be **late** when progress timestamps fall late within a second boundary.
