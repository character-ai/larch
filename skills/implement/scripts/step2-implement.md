# step2-implement.sh

**Orchestrator wait contract**: the orchestrator MUST NOT call `ScheduleWakeup` while waiting on this dispatcher — `step2-implement.sh` blocks foreground until the implementer returns, so no wakeup is needed, and a non-sentinel `prompt` would re-fire as a `/loop` input on wakeup. See `skills/implement/SKILL.md` NEVER #9.

**Purpose**: Single dispatcher entrypoint for `/implement` Step 2. Branches on `--coder` (canonical) or the legacy `--codex-available` alias; on the Codex/Cursor/Gemini paths, drives the external implementer loop end-to-end (spawn → manifest → mechanical validation → sanitization → final KV envelope) so SKILL.md Step 2 only needs to parse a deterministic key/value summary. Claude fallback occurs when `--coder=claude` (explicit opt-in to the pre-Codex main-agent path), when the legacy `--codex-available false` is passed in, when `--coder=cursor` is requested but `--cursor-healthy != true`, or when `--coder=gemini` is requested but `--gemini-healthy != true`.

**Invariants**:
- Coder selection: `--coder` is the canonical flag (`codex` default, `claude` opt-in, `cursor` opt-in, `gemini` opt-in). `--codex-available true|false` is accepted for one release as a deprecated alias mapping to `--coder codex|claude` with a stderr deprecation warning. Passing both `--coder` and `--codex-available` is mutual-exclusive (exit 2). Three places emit `STATUS=claude_fallback`: when the resolved `coder` value is `claude`, when `coder=cursor` with `--cursor-healthy != true`, and when `coder=gemini` with `--gemini-healthy != true`.
- Cursor health gate: `--cursor-healthy true|false|""` is accepted. Empty and missing values normalize to false. The gate runs after the `claude` early-return and before `REPO_ROOT` git-tree lookup, so `--coder=cursor --cursor-healthy false` emits `STATUS=claude_fallback` even outside a git work-tree and does not write baseline files. The orchestrator then runs the main-agent code-edit path the same way it would for `--coder=claude`.
- Gemini health gate: `--gemini-healthy true|false|""` is accepted. Non-empty values are validated regardless of coder; empty/missing values normalize to false on the Gemini path. The gate runs before `REPO_ROOT` git-tree lookup, so `--coder=gemini --gemini-healthy false` emits `STATUS=claude_fallback` even outside a git work-tree and does not write baseline files.
- Two distinct roots: `PLUGIN_ROOT` (resolved from `SCRIPT_DIR/../../..`) is the plugin tree this script ships in — used for sibling plugin assets (`agents/<tool>-implementer.md`, `scripts/launch-<tool>-implement.sh`, `scripts/redact-secrets.sh`). `REPO_ROOT` (resolved from `git rev-parse --show-toplevel` against cwd) is the consumer git repo this run targets — used for every `git -C "$REPO_ROOT"` call and the `.claude-plugin/plugin.json` reference. The split is load-bearing: when the plugin is installed, `PLUGIN_ROOT` points inside `~/.claude/plugins/cache/...` which has no `.git`, so reusing it for git ops would make the first `git -C "$REPO_ROOT" ...` (the baseline write) abort the script with a non-zero exit and no KV envelope under `set -euo pipefail` — the orchestrator would then have no `STATUS=` line to parse. If cwd is not inside a git working tree on an external path after that tool's health gate passes, the dispatcher exits 2 (caller / invocation error) rather than spawning an implementer against an undefined repo.
- Stdout is KV-only — `STATUS`, `TOOL`, `MANIFEST`, `QA_PENDING`, `REASON`, `TRANSCRIPT`, `SIDECAR_LOG`, `ORCHESTRATOR_EDIT_AUTHORITY`. The launcher's progress chatter is captured to the sidecar log; the implementer transcript is captured to disk; neither leaks to stdout. SKILL.md Step 2's parser is a fixed grammar.
- **Orchestrator-edit-authority gate**: `ORCHESTRATOR_EDIT_AUTHORITY=<allowed|forbidden>` is emitted on EVERY exit-0 outcome (no exceptions). `allowed` is emitted **iff** `STATUS=claude_fallback` — i.e., on `--coder=claude`, on the legacy `--codex-available false`, on the `--coder=cursor --cursor-healthy != true` fallback, and on the `--coder=gemini --gemini-healthy != true` fallback. `forbidden` is emitted on every external-implementer outcome (`complete`, `needs_qa`, `bailed`). The pair invariant `ORCHESTRATOR_EDIT_AUTHORITY=allowed ⇔ STATUS=claude_fallback` is the mechanical gate the orchestrator uses (`SKILL.md` Step 2 entry preconditions matrix + NEVER #10) to decide whether main-agent Edit/Write/Bash code edits are permitted at Step 2.4. Tests in `test-step2-dispatch.sh` pin both halves of the iff.
- Spawn-time baseline files are written ONCE on the first invocation under `$TMPDIR_ARG`: `step2-baseline.txt` (HEAD SHA), `step2-spawn-branch.txt` (branch name), `step2-plugin-json-baseline.txt` (`git hash-object` of `.claude-plugin/plugin.json`). All resume invocations reuse them. The baseline SHA anchors the launcher-retry "clean state" guard (post-failure HEAD must equal baseline). The baseline-vs-HEAD diff cross-check that previously enforced manifest path-set equality was removed when the dispatcher took over committing — there is no longer a committed Codex diff to compare against.
- Cross-coder tmpdir-reuse guard: `step2-spawn-coder.txt` records the resolved `--coder` value on the first external-implementer invocation (atomic `.tmp` + `mv` write). Every subsequent invocation reads the file; if its trimmed contents differ from the current `$CODER`, the dispatcher emits `STATUS=bailed REASON=coder-mismatch-tmpdir-reuse TOOL=<current-tool>` BEFORE writing or reading any of the shared baseline files (`step2-baseline.txt`, `step2-spawn-branch.txt`, `step2-plugin-json-baseline.txt`) and BEFORE incrementing or reading the per-tool `${TOOL_TAG}-resume-count.txt`. This closes the cross-coder tmpdir-reuse footgun where partial external runs with different tools share a tmpdir and desynchronize shared baselines and per-tool counters. The guard runs only on external paths: the `claude` early-return above does not touch the tmpdir, so a prior claude invocation leaves no sentinel and a subsequent external run is the first writer; conversely, a prior external run leaves the sentinel but a subsequent `--coder=claude` invocation early-returns before reading it.
- Per-tool files under `$TMPDIR_ARG` use `${TOOL_TAG}-...` names: `${TOOL_TAG}-resume-count.txt`, `${TOOL_TAG}-impl-transcript.txt`, `${TOOL_TAG}-impl.log`, `${TOOL_TAG}-commit-message.txt`, and `${TOOL_TAG}-commit-stderr.txt`. `TOOL_TAG=codex` preserves the historical Codex filenames byte-for-byte.
- Resume counter is incremented ONLY when `--answers PATH` is supplied. Cap is 5; the 6th `--answers` invocation emits `STATUS=bailed REASON=qa-loop-exceeded` without spawning the implementer.
- Single retry on transient launcher failure (no manifest written): retry only when post-failure state is fully clean (`git status --porcelain` empty, no `.git/index.lock`, HEAD == `BASELINE_SHA`). A dirty post-failure state emits `STATUS=bailed REASON=dirty-state-after-timeout`.
- The dispatcher does NOT `git reset`, NOT `git checkout`, NOT discard working-tree state. On `status=complete` it stages and commits implementer edits via `git add -A && git commit -F <commit-message-file>` — `commit_message` is taken from the manifest with no diff or subject cross-check, but IS piped through `scripts/redact-secrets.sh` immediately before `git commit -F` so the secrets-family scrubber that protects the canonical on-disk manifest also protects git history. On any other status, the dispatcher leaves the working tree untouched. On `commit-failed`, `git add -A` has already run and the index stays staged — operators inspect `git status` and `$IMPLEMENT_TMPDIR/${TOOL_TAG}-commit-stderr.txt` (where the failed `git commit` stderr is captured) before deciding whether to `git reset` or amend. Implementer hard guard #1 (no destructive git ops) is mirrored here as "the dispatcher never destroys operator work either."
- HEAD-unchanged guard: tools that set `REQUIRES_HEAD_UNCHANGED=true` (today: Cursor and Gemini) do not have Codex's `workspace-write` sandbox and can write `.git/`. Before the dispatcher commits on their behalf, allows a `needs_qa` resume cycle, or passes through an implementer-authored bail, it asserts current `HEAD` still equals `BASELINE_SHA`; if not, it emits `STATUS=bailed REASON=${TOOL_TAG}-modified-history TOOL=$TOOL_TAG` and preserves the branch for operator inspection. Cursor's token remains `cursor-modified-history`; Gemini's token is `gemini-modified-history`.
- Path validation rejects `..`, leading `/`, `.claude-plugin/plugin.json`, and any path under a submodule (per `git submodule status --recursive`). NUL bytes are rejected implicitly — bash variables cannot hold a NUL, so the `read -r` consuming the jq output terminates the field at any NUL upstream; an explicit `*$'\0'*` glob would expand to `**` (since `$'\0'` is empty in bash strings) and match every non-empty path, so the check must not be expressed that way. The reserved-file check is a defense-in-depth duplicate of `hooks/pre-commit-block-bump-version-edit.sh`'s contract.
- `bailed` manifests are NOT enforced against working-tree-clean / diff-cross-check / commit-count invariants. Two sub-classes share `STATUS=bailed` on stdout: (1) **Implementer-originated** bails (`status=bailed` in the manifest itself, e.g. `resume-incompatible`, `submodule-edit-required-out-of-scope`, free-form tokens) — the implementer deliberately did not produce a commit-ready working tree, and the orchestrator surfaces the reason token it chose; the manifest passes through verbatim modulo sanitization unless the HEAD-unchanged guard supersedes it. (2) **Dispatcher mechanical** bails (`branch-changed`, `protected-path-modified`, `submodule-dirty`, `commit-failed`, `manifest-schema-invalid`, `manifest-missing`, `qa-pending-missing`, `qa-loop-exceeded`, `redactor-not-executable`, `dirty-state-after-timeout`, `codex-runtime-failure`, `cursor-runtime-failure`, `cursor-modified-history`, `gemini-runtime-failure`, `gemini-modified-history`, `coder-mismatch-tmpdir-reuse`) — the dispatcher overrode an apparent `complete` (or never reached a manifest at all) because a check failed. On `commit-failed` specifically: the implementer declared `complete`, the dispatcher staged everything via `git add -A`, then `git commit -F …` failed (empty tree, pre-commit hook rejection, transient git error). The failed `git commit` leaves the index fully staged with NO new commit on HEAD; the dispatcher removes the un-sanitized `manifest.json` (and its raw copy) so raw text fields do not linger on disk, captures `git commit` stderr to `$IMPLEMENT_TMPDIR/${TOOL_TAG}-commit-stderr.txt`, and bails. Operator recovery surface: `git status` (staged index), the commit stderr file, the transcript, and the sidecar log.
- Exit code is 0 on every documented outcome (including `STATUS=bailed`). Exit 2 is reserved for caller-error (missing flag, bad path, bad enum value) before any Codex spawn.

**Stdout contract**:
```
STATUS=<complete|needs_qa|bailed|claude_fallback>
TOOL=<codex|cursor|gemini> # set on external implementer paths
MANIFEST=<path>          # set ONLY when STATUS=complete or needs_qa, or when STATUS=bailed
                         # came from an implementer-authored manifest (status=bailed in the manifest
                         # itself, e.g. resume-incompatible). Dispatcher mechanical bails
                         # (commit-failed, manifest-schema-invalid, manifest-missing,
                         # branch-changed, protected-path-modified, submodule-dirty,
                         # qa-pending-missing, qa-loop-exceeded, redactor-not-executable,
                         # dirty-state-after-timeout, codex-runtime-failure, cursor-runtime-failure,
                         # gemini-runtime-failure, cursor-modified-history, gemini-modified-history,
                         # coder-mismatch-tmpdir-reuse) DO NOT emit
                         # MANIFEST= — and on commit-failed the manifest files are deleted
                         # from $IMPLEMENT_TMPDIR before bail to avoid leaving un-sanitized
                         # text on disk.
QA_PENDING=<path>        # set ONLY when STATUS=needs_qa
REASON=<token>           # set ONLY when STATUS=bailed
TRANSCRIPT=<path>        # set when launcher actually ran
SIDECAR_LOG=<path>       # set when launcher actually ran
ORCHESTRATOR_EDIT_AUTHORITY=<allowed|forbidden>
                         # ALWAYS emitted (every exit-0 outcome). `allowed` iff STATUS=claude_fallback;
                         # `forbidden` on every external-implementer outcome (complete/needs_qa/bailed).
                         # Mechanical gate for SKILL.md Step 2.4 main-agent Edit/Write authority.
```

**Flags**:

| Flag | Required | Purpose |
|------|----------|---------|
| `--tmpdir PATH` | yes | `$IMPLEMENT_TMPDIR` (where baseline / counter / manifest / transcript / sidecar log live) |
| `--plan-file PATH` | yes | The plan to implement (passed through to Codex) |
| `--feature-file PATH` | yes | The original feature description (passed through to Codex) |
| `--auto-mode VALUE` | yes | `true` or `false`; forwarded as context for the agent prompt; the dispatcher itself does not branch on it |
| `--coder VALUE` | optional (default `codex`) | `codex` (Codex spawn path; default when the flag is omitted), `claude` (immediately emits `STATUS=claude_fallback` and exits — pre-Codex main-agent path), `cursor` (Cursor spawn path when healthy; falls back to `STATUS=claude_fallback` when `--cursor-healthy != true`), or `gemini` (Gemini spawn path when healthy; falls back to `STATUS=claude_fallback` when `--gemini-healthy != true`). |
| `--codex-available VALUE` | optional (deprecated) | `true` (maps to `--coder codex`) or `false` (maps to `--coder claude`). Emits a stderr deprecation warning. Mutually exclusive with `--coder`. |
| `--cursor-healthy VALUE` | optional | `true`, `false`, or empty. Empty/missing normalizes to false. Consulted only on `--coder=cursor`; non-`true` falls back to `STATUS=claude_fallback` before `REPO_ROOT` lookup. |
| `--gemini-healthy VALUE` | optional | `true`, `false`, or empty. Non-empty values are validated regardless of coder. Empty/missing normalizes to false on `--coder=gemini`; non-`true` falls back to `STATUS=claude_fallback` before `REPO_ROOT` lookup. |
| `--answers PATH` | optional | Operator answers to a prior `needs_qa` cycle; presence increments the resume counter |

**Outcomes** (`STATUS` values):
- `complete` — all post-implementer mechanical checks passed; the dispatcher committed the external implementer's working-tree edits using `manifest.commit_message` (redacted via `scripts/redact-secrets.sh` immediately before `git commit -F`); the canonical manifest is sanitized and emitted at `$TMPDIR/manifest.json`.
- `needs_qa` — the external implementer wrote `qa-pending.json` with operator questions; SKILL.md Step 2 collects answers and re-invokes the dispatcher with `--answers`.
- `bailed` — the external implementer itself emitted `status=bailed`, OR the dispatcher overrode `complete` because mechanical validation failed. `REASON` token list is in `skills/implement/references/codex-manifest-schema.md` (Bail-reason tokens section). When the dispatcher overrides the implementer, the dispatcher's reason wins.
- `claude_fallback` — When `--coder=claude`, the legacy `--codex-available false`, `--coder=cursor` with `--cursor-healthy != true`, or `--coder=gemini` with `--gemini-healthy != true`; the caller proceeds with the main-agent code-edit path.

**Bail-reason tokens emitted by the dispatcher** (set internally; full list in `codex-manifest-schema.md`):
`qa-loop-exceeded`, `qa-pending-missing`, `manifest-missing`, `manifest-schema-invalid`, `protected-path-modified`, `submodule-dirty`, `branch-changed`, `commit-failed`, `dirty-state-after-timeout`, `codex-runtime-failure`, `cursor-runtime-failure`, `cursor-bailed-no-reason`, `cursor-modified-history`, `gemini-runtime-failure`, `gemini-bailed-no-reason`, `gemini-modified-history`, `redactor-not-executable`, `coder-mismatch-tmpdir-reuse`. Implementer-authored bail tokens (e.g., `resume-incompatible`, free-form) pass through verbatim — they are sanitized only for KV-grammar safety (whitespace and control characters collapsed to single spaces; capped at ~200 characters) before being emitted on `REASON=`. (`cursor-unhealthy` and `gemini-unhealthy` are not emitted: unhealthy gates route through `STATUS=claude_fallback` so the orchestrator runs the main-agent code-edit path instead of bailing.)

Implementer-spawning paths (manifest schema validation, dispatcher-side commit, sanitization, single-retry on transient failure, post-implementer mechanical checks) are out of scope for this offline harness — see `skills/implement/scripts/test-step2-dispatch.md` for the full coverage list and rationale.

**Note on external implementer hook bypass**: Codex, Cursor, and Gemini do NOT route through Claude Code's `Edit`/`Write` PreToolUse hook chain (`hooks/block-submodule-edit.sh`, `hooks/pre-commit-block-bump-version-edit.sh` apply to Edit/Write only). The dispatcher's mechanical checks (`.claude-plugin/plugin.json` unchanged via `git hash-object`; submodule status clean; manifest path normalization; branch unchanged; Cursor/Gemini `HEAD == BASELINE_SHA`) ARE the trust boundary in the external-implementer paths. The dispatcher then commits working-tree edits via `git add -A && git commit -F …` (the pre-commit hook chain runs at `git commit` time, providing a second-line backstop on the same files). See `SECURITY.md` for the full trust model.
