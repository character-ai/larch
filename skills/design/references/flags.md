# Flag Reference

**Consumer**: `/design` argument parsing (loaded before Step 0 via the MANDATORY directive adjacent to the compact flag table in SKILL.md).

**Contract**: single normative source for every `/design` flag — validation rules, default values, fallback behaviors, the `::` delimiter encoding spec for `--step-prefix`, the 4-key requirement for `--branch-info`, the `--auto` / `--quick` / `--full` interaction rules, caller-forwarded `--design-classification`, and all backward-compat notes. The literal string `All 4 keys are required` is byte-pinned by `scripts/test-design-structure.sh`.

**When to load**: once at the top of `/design` invocation, before Step 0 executes, via the MANDATORY directive adjacent to the compact flag table. Do NOT load mid-flow; flag parsing runs once and the decisions are sticky.

**Binding convention**: This file is the single normative source for `/design` flag semantics. SKILL.md's compact flag table is a non-normative index — when a caller needs the authoritative validation rule, fallback behavior, or encoding spec for any flag, read this file.

---

- `--auto`: Set a mental flag `auto_mode=true`. Default: `auto_mode=false`. When `auto_mode=true`, all interactive question checkpoints (Steps 1c, 1d, and 3.5) are skipped — the skill runs fully autonomously without user interaction. Note: when `/implement --quick` is set, `/implement` skips `/design` entirely — `--auto` has no effect in that case because `/design` is never invoked. This is distinct from `/design --quick`, which runs `/design` with a 2-agent sketch phase and still respects `--auto`.
- `--quick`: Set a mental flag `quick_mode=true`. Default: `quick_mode=false`. When `quick_mode=true`, the Step 0 run-depth router caps `sketch_budget` at 2 (2 sketch agents, except when `--full` is also set) and Step 3 (plan review) uses `plan-review-quick.md` — a Claude-only self-review (no external agents, no voting panel) that writes the same artifact set as normal mode; all other steps run normally. Independent of `--auto` — both flags can be set simultaneously. **Not to be confused with `/implement --quick`**, which skips `/design` entirely and produces an inline plan.
- `--full`: Set a mental flag `full_mode=true`. Default: `full_mode=false`. Forces `sketch_budget=4` regardless of the router classification. When `--full` and `--quick` are both set, sketch fan-out uses 4 agents but plan review still uses `plan-review-quick.md`; `quick_mode` governs plan review, not sketch count, while `full_mode` governs the sketch budget.
- `--subagent`: Set a mental flag `subagent_mode=true`. Default: `subagent_mode=false`. When `subagent_mode=true` AND `quick_mode=false`, Step 2a's heavy non-interactive phase (sketches → plan synthesis → plan review → optionally Step 3b/4 when `auto_mode=true`) runs in an isolated Agent-tool subagent that consumes `${CLAUDE_PLUGIN_ROOT}/skills/design/references/heavy-worker.md` and writes raw artifacts to `$DESIGN_TMPDIR/`, returning only `DESIGN_HEAVY=complete` or `DESIGN_HEAVY=failed REASON=<token>`. When `subagent_mode=false`, Step 2a runs inline in the executing agent (full output visible). **Quick-mode interaction**: When `quick_mode=true`, `--subagent` is intentionally ignored — quick-mode `/design` runs the full design pipeline (2 sketches, plan synthesis, plan review, dialectic, Steps 3b/4/5) inline regardless of `--subagent`. The combination is allowed but `--subagent` has no effect. **Independent of `--session-env` / `SESSION_ENV_PATH`**: `--subagent` controls only execution topology (where the heavy work runs); `SESSION_ENV_PATH` continues to govern the nested I/O contract (verbosity suppression, manifest export, OOS routing to parent dir, health propagation). **Standalone /design --subagent (NEW capability)**: when `subagent_mode=true` AND `SESSION_ENV_PATH` is empty AND `DESIGN_HEAVY=complete`, parent /design replays the artifacts inline (reads and prints `plan.txt`, `voting-tally.md`, `accepted-plan-findings.md`, `oos.md`, and — when `auto_mode=true` — `architecture-diagram.md` under their standalone headers) before Step 5 cleanup, so the user sees the deliverables that would otherwise be lost when `cleanup-tmpdir.sh` removes `$DESIGN_TMPDIR`. **Migration note**: callers previously relying on `--session-env` alone to select subagent dispatch must now pass `--subagent` explicitly. **Forwarded by `/implement`** by default (omitted only when `/implement --inline` is set).
- `--session-env <path>`: Set `SESSION_ENV_PATH` to the given path. This file contains already-discovered session values from a caller skill (e.g., `/implement`) and will be forwarded to `session-setup.sh` via `--caller-env`. If not provided, `SESSION_ENV_PATH` is empty (standalone invocation — full discovery).
- `--step-prefix <prefix>`: Encodes numeric prefix, textual breadcrumb path, and optional parent skill path using `::` delimiter — see `${CLAUDE_PLUGIN_ROOT}/skills/shared/progress-reporting.md` for the full encoding spec. Examples: `"1.::design plan::/implement"` (numeric `1.`, path `design plan`, parent skill path `/implement`), `"1.::design plan"` (legacy numeric + path), `"1."` (numeric only, backward compat). Parse into `STEP_NUM_PREFIX` (before first `::`), `STEP_PATH_PREFIX` (between first and second `::`, or empty if absent), and `PARENT_SKILL_PATH` (after second `::`, or empty if absent). Default: empty. When the flag is absent (standalone run), step numbers use local numbering and the rendered `🔶` skill path is `/design`. This is an internal orchestration flag used when `/design` is invoked from `/implement`.
- `--branch-info <values>`: Set `branch_info_supplied=true` and parse `IS_MAIN`, `IS_USER_BRANCH`, `USER_PREFIX`, `CURRENT_BRANCH` from the space-separated `KEY=VALUE` pairs. All 4 keys are required. Values are safe for space-splitting (`USER_PREFIX` is sanitized by `create-branch.sh`'s `derive_user_prefix()`, `CURRENT_BRANCH` cannot contain spaces). **Validation**: If any of the 4 keys is missing, print `**⚠ --branch-info is incomplete. Falling back to create-branch.sh --check.**` and run the script as fallback. **Fallback**: When `--branch-info` is absent (standalone invocation), run `create-branch.sh --check` as usual. This is an internal orchestration flag used when `/design` is invoked from `/implement` to skip the redundant branch-state check. **Sharp edge — power-user / nested-call shape only**: standalone callers that supply complete `--branch-info` are trusted not to lie about `IS_MAIN`/`IS_USER_BRANCH`/`USER_PREFIX`/`CURRENT_BRANCH`; mismatched values silently bypass the standalone safety check.
- `--design-classification <value>`: Caller-forwarded `TRIVIAL_DOC_ONLY`, `SIMPLE`, or `HARD` classification from `/implement`. Default: empty. When present AND `branch_info_supplied=true`, the Step 0 router accepts it without re-classifying and writes `design_classification_source=caller-forwarded` to `run-params.json`. When present without trusted `--branch-info`, ignore it defensively and run the standalone classifier, writing `design_classification_source=router-pre-design`.
- `--run-id <ID>`: Optional run identifier. Default: empty (auto-generate). When set, used as the run ID for this invocation instead of the auto-generated one. Parse and save as `RUN_ID`; actual propagation to session state and `larch-logs/` is deferred to #1438. Independent of all other flags.
